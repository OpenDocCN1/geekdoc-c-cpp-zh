
为了确保传输队列稳定，应满足 $s_{tra}^j < 1$。因此，传输服务器的平均响应时间可以公式化为

```
$T_{prio}^{tot(t)} = \hat{A} (T_{tra}^{j(t)}^{j-1}) T_{prio}^{j(t)}$
```

根据上述推导，优先级服务的总响应时间是三个阶段响应时间的和，可以给出

```
$T_{prio}^{tot}(t) = T_{prio}^{ach(t)} + T_{prio}^{com(t)} + T_{prio}^{tra(t)} \quad (2.7)$
```

此外，我们可以得到类 $j$ 应用的服务响应时间如下：

```
$T_{prio}^{j(t)} = T_{prio}^{ach(j(t))} + T_{prio}^{com(j(t))} + T_{prio}^{tra(j(t))} \quad (2.8)$
```

优先级服务情况下的总资源成本公式化为

```
$Z_{prio}^{tot} = (aS^t + bC^t + g\mathcal{G}^t) \quad (2.9)$
```

### 服务响应时间最小化问题
在多媒体云中，许多应用使用了优先级服务规则。具有更严格延迟要求的应用应该获得较高优先的服务，而延迟敏感性较低的多媒体应用可以用较低优先级的服务。多媒体服务提供者必须支持不同的优先级并最小化平均响应时间。我们制定了优先级服务情况下的响应时间最小化问题，其表述如下：通过联合优化分配的调度资源、计算资源和带宽资源，在每个队列系统的队列稳定性约束和资源成本约束的情况下，最小化所有应用的平均服务响应时间。从数学上上看，响应时间最小化问题可以公式化为

```
$Minimize \quad T_{prio}^{(tot)}(S^t, F^t, B^t) \quad (2.10)$
```

约束条件为

```
$lambda^t < S^t\nsum_{j=1}^{n} \hat{A}_{ij}^t F_j < C^t\nsum_{j=1}^{n} \hat{A}_{ij}^t D_j < B^t$
```

```
$(S^t + bC^t + \mathcal{B}^t g \le z_{max})$
```

其中：

$T_{prio}^{(tot)}$ 在方程 2.7 中给出

$z_{max}$ 是资源成本的上限。

响应时间最小化问题（方程2.10）是一个凸优化问题，可以使用原对内点法 [34] 高效地求解。

在优先级响应情况下，最高优先级的请求具有获得服务的抢占权。因此，优先级的引入减少了高优先级请求的平均延迟并增加了低优先级请求的平均延迟。然而，引入优先级对所有请求整体响应时间的影响尚不确定。为了解决引入优先级如何影响整体响应时间的问题，Schrage 和 Miller [35] 提出了最短处理时间（SPT）规则，其描述如下：(1) 如果队列的目标是减少整体平均延迟，则较高的优先级应该是分配给具有更快服务速率的类。(2) 如果多媒体云的总体目标是减少某个特定应用的服务响应时间，则该应用应赋予最高优先级。

### 资源成本最小化问题
不同优先级的应用对服务时间有不同的要求。对于多媒体云提供者来说，以最小资源成本支持多个 QoS（服务质量）保障是具有挑战性的。因此，我们建立了优先级服务情况下的资源成本最小化问题，其表述如下：通过联合优化分配的调度资源、计算资源和带宽资源，在满足队列稳定性约束和每个应用的服务响应时间约束的情况下，最小化优先级服务情况下的总资源成本。从数学上看，资源成本最小化问题可以表示为：

```
$$\min_{S^t,C^t,B^t} 2^{wot(t)} = (aS^t + bC^t + gB^t)G \quad (2.11)$$
```

受限于

```
$$1^t < S^t$$
$$\hat{A}1^t F_j < C^t \quad j=1$$
$$\hat{A}1^t p_j < B^t \quad j=1$$
$$T_{prio}^{wot(j)(t)} < t_j, j=1, \mathcal{M}$$
```

其中：

$T_{prio}^{wot(j)(t)}$，见于公式 2.8，是 j 类应用的服务响应时间

$t_j$ 是 j 类应用服务响应时间的上界

资源成本最小化问题（公式 2.11）也可以使用原始对偶内点法 [34] 高效求解。

### 2.4 未来方向

尽管云计算已取得进展，但仍存在以下若干待解决问题：

- 资源需求预测：由于资源分配过程需要时间，如果仅在资源不足时才重新分配资源，对于防止性能下降将太晚。因此，需要根据之前的统计数据预测资源需求。
- 负载监控：云负载是实时变化的。为了满足动态负载，特别是突发请求，需要进行实时负载监控。此外，动态分配云资源以处理变化的负载是一个挑战。
- 负载调度：云计算有两个级别的调度。第一级是用户级调度，根据当前负载将请求分配到不同的虚拟机。通过在虚拟机之间平衡负载，用户级调度可以有效避免云拥塞。与用户级调度相比，任务级调度在更精细的粒度上运行。应用程序可以分解一组任务，每个任务都需要不同的资源。任务级调度是将不同的任务分配给不同的虚拟机以实现性能最大。
- 资源迁移：凭借现有技术，虚拟机和应用程序迁移已经在局域网（LAN）环境中实现。未来，云应该将虚拟机和服务迁移到其他云，这将极大提高云数据中心的鲁棒性。
- 联合资源优化：目前大多数资源优化方法只关注云端，忽略了传输路径和用户端。事实上，通过联合优化云端、客户端以及云与客户端之间传输路径上的资源来最小化或最大化端到端 QoS 指标是一项挑战。

### 3.2 背景

#### 3.2.1 专业社区

Wenger 等人 [4] 将“实践社区（Communities of Practice, CoP）定义为对某一主题具有共同关注、一组问题或热忱的人群体，他们通过持续的互动来加深在该领域的知识和专业技能”。CoP 中最重要的过程是集体学习以及共享意义和集体认同的产生。实践由显性知识、隐性知识和能力组成。CoP概念有助于理解和支持协作、知识管理和协作学习 [5]。CoP 可以被视为学习的共享历史 [6]。CoP 结合了社区的社会实践与其个体成员的身份。此外，“专业社区”指的是某些专业领域（例如医学或建筑）中的 CoP，在这些领域中，专业人士天生通过参与 CoP 来进行学习。在组织中，非正式的 CoP 想要分享关于他们职业的知识。
