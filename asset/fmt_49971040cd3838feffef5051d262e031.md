围绕它的工具链。它让你能够无需通过 `create-react-app` 就能搭建自己的项目。我建议遵循使用 Webpack 和 Babel¹⁵⁸ 的极简设置。之后，你可以根据需要应用更多工具。例如，你可以使用 `ESLint`¹⁵⁹ 来在应用程序中遵循统一的代码风格。

- **React 组件语法：** 实现 React 组件的可能性和最佳实践随着时间不断演变。你会在其他学习资源中发现许多编写 React 组件（尤其是 React 组件）的方法。你可以查看这个 GitHub 仓库¹⁶⁶，或者寻找编写类组件（Class components）的其他方法。通过使用类字段声明，你将来可以将它们写得更简洁。

- **其他项目：** 学习 React 之后，在学习新知识之前，将所学应用到自己的项目中总是好的。你可以尝试用 React 写一个井井游戏或一个简单的计算器。有许多教程仅使用 React 就能构建有趣的内容。查看关于构建分页列表和无限滚动列表¹⁶⁷，或者如何将你的 React 连接到 Stripe 进行收费¹⁶³。通过尝试这些微型应用来熟悉 React。

- **UI 组件：** 你不犯过过早在项目中引入 UI 库的错误。首先，你应该学习如何使用标准的 HTML 元素从零在 React 中实现并使用下拉菜单、复选框或对话框。这些组件大部分负责管理它们的状态。复选框必须知道自己是否选中。你应该将它们实现为受控组件（controlled components）。在你完成所有基础实现后，可以引入一个将复选框和对话框作为 React 组件的 UI 组件库。

- **代码组织：** 当你读这本书时，会遇到关于代码组织的章节。如果你还没有这样做，现在就可以应用这些方法。它将帮助你通过结构化的文件和文件夹（模块）来组织项目。此外，它还能帮助你理解和学习代码分割、可复用、可维护性和模块 API 设计的原则。最终你的应用程序规模会扩大，你需要对它进行模块化构建。所以最好现在就开始。

- **测试：** 我们对测试仅仅触及了皮毛。如果你不熟悉这个通用话题，可以在 React 应用的背景下深入研究单元测试和集成测试的概念。在实现层面，我建议坚持使用 `Enzyme` 和 `Jest`，以完善你在 React 中进行单元测试和快照测试的方法。

- **路由：** 你可以使用 `react-router`¹⁶⁴ 为你的应用程序实现路由。到目前，你的应用程序只有一个页面。React Router 帮助你跨多个 URL 拥有多个页面。当你为应用程序引入路由时，不需要向 Web 服务器请求下一个页面。路由器将在客户端为你完成一切。亲自动手操作，在你的应用程序中引入路由吧。

- **类型检查：** 在一个章节中，你使用了 React `PropTypes` 来定义组件接口。这是防止 Bug 的通用良好实践。但 `PropTypes` 仅在运行时检查。你可以更进一步，在编译时引入静态类型检查。`TypeScript`¹⁶⁵ 是一种流行的方法。但在 React 生态系统中，人们经常使用 `Flow`¹⁶⁶。如果你兴趣让你的应用程序更健壮，我建议尝试一下 Flow。

- **React Native：** `React Native`¹⁶⁷ 将你的应用程序带到移动设备上。你可以将从 React 中中学的应用于发布 iOS 和 Android 应用。一旦你学会了 React，React Native 的学习曲线不应该是陡峭的。两者共享相同的原理。你只会遇到移动组件的布局与 Web 应用不同。
