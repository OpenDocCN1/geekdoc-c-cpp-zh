
# 汇编代码分析与优化示例

## x86 汇编代码

```asm
a$ = 8          ; size = 4
b = 12         ; size = 4
f unsigned PROC
    push
    mov     ebp
    mov     eax, DWORD PTR a$[ebp]
    cmp     eax, DWORD PTR b$[ebp]
    jbe     SHORT LN3@of_unsigned
    call    OFFSET $52761      ; 'a>b'
    printf
    add     esp, 4
$LN3@of_unsigned:
    mov     edx, DWORD PTR a$[ebp]
    cmp     edx, DWORD PTR b$[ebp]
    jne     SHORT LN2@of_unsigned
    push
    call    OFFSET $52763      ; 'a=b'
    printf
    add     esp, 4
$LN2@of_unsigned:
    mov     edx, DWORD PTR a$[ebp]
    cmp     edx, DWORD PTR b$[ebp]
    jae     SHORT LN4@of_unsigned
    push
    call    OFFSET $52765      ; 'a<b'
    printf
    add     esp, 4
$LN4@of_unsigned:
    pop     ebp
    ret     0
f_unsigned ENDP
```

正如前面提到的，分支指令是不同的：`JBE`——小于或等于则跳转，以及 `JAE`——大于或等于则跳转。这些指令（`JA`/`JE`/`JB`/`JBE`）与 `JG`/`GE`/`JL`/`JL` 的区别在于它们处理的是无符号数。

这就是为什么我们使用 `JG`/`JL` 而不是 `JA`/`JB`，反之亦然，我们几乎可以确定变量是有符号或无符号的。这里是 `main()` 函数，其中我们没有新要做的：

### 列表 1.112: main()

```asm
main PROC
push ebp
mov ebp, esp
push 2
mov 1
push
call _f_signed
add esp, 8

push 2
push 1
call _f_unsigned
add esp, 8
xor eax, eax
pop ebp
ret
0
```

## x86 + MSVC + Hiew

我们可以尝试补丁执行文件，使得 `f_unsigned()` 函数始终打印 "a=="。在 Hiew 中它看起来如下：

![图 1.40: Hiew: f_unsigned() 函数](img/4590a0c34d3b5b6ca77b4202d4036d48_186_0.png)

基本上，我们必须完成三个任务：

- 强制第一个跳转始终触发；
- 强制第二个跳转永远触发；
- 强制第三个跳转始终触发。

这样我们可以引导代码始终通过并输出 "a=="。三个指令（或字节）需要补丁：

- 第一个跳转变为 `JMP`，但跳转偏移保持不变。
- 第二个跳转可能会触发，但在任何情况下它都会跳转到下一条指令，因为我们将跳转偏移设置为 0。

在这些指令中，跳转偏移是加在下一条指令地址上的。因此，如果偏移为 0，跳转将转移控制到下一条指令。

- 我们像处理第一个一样将第三个跳转替换为 `JMP`，所以它始终触发。

这是修改后的代码：

![图 1.41: Hiew: 修改 f_unsigned() 函数](img/4590a0c34d3b5b6ca77b4202d4036d48_188_0.png)

## 优化的 GCC

细心的读者可能会问，如果每次执行后标志位的值都相同，为什么要执行多次 `CMP`？也许优化的 MSVC 做不到，但优化的 GCC 4.8.1 可以更深层：

### 列表 1.113: GCC 4.8.1 f_signed()

```asm
f_signed:
mov     eax, DWORD PTR [esp+8]
cmp     DWORD PTR [esp+4], eax
jg      .L6
je      .L7
jge     .L1
mov     DWORD PTR [esp+4], OFFSET FLAT:.LC2 ; "a<b"
jmp     puts
.L6:
mov     DWORD PTR [esp+4], OFFSET FLAT:.LC0 ; "a>b"
jmp     puts
.L1:
ret
.L7:
mov     DWORD PTR [esp+4], OFFSET FLAT:.LC1 ; "a==b"
jmp     puts
```

我们在这里也使用 `JMP puts` 代替 `CALL puts` / `RETN`。这种技巧在后面会解释：第 197 页的 12.21.1。这种类型的 x86 代码相当稀见。看来 MSVC 2012 无法生成这样的代码。另一方面，汇编语言程序员完全清楚 `Jcc` 指令可以堆叠的事实。

如果你在某处添加了几个这样的跟踪，那么很有可能是代码是手写的。

`f_unsigned()` 函数并不短：

### 列表 1.114: GCC 4.8.1 f_unsigned()

```asm
f_unsigned:
push    esi
push    ebx
sub     esp, 20
mov     esi, DWORD PTR [esp+32]
mov     ebx, DWORD PTR [esp+36]
cmp     esi, ebx
ja      .L13
cmp     esi, ebx ; 这条指令可以被移除
je      .L14
jb      .L15
.L10:
add     esp, 20
pop     ebx
pop     esi
ret
.L15:
mov     DWORD PTR [esp+32], OFFSET FLAT:.LC2 ; "a<b"
add     esp, 20
pop     ebx
pop     esi
jmp     puts
.L13:
mov     DWORD PTR [esp], OFFSET FLAT:.LC0 ; "a>b"
call    puts
cmp     esi, ebx
jne     .L10
.L14:
mov     DWORD PTR [esp+32], OFFSET FLAT:.LC1 ; "a==b"
add     esp, 20
pop     ebx
pop     esi
jmp     puts
```

尽管如此，这里有两个 `CMP` 指令而不是三个。

因此 GCC 4.8.1 的优化算法可能还不够完美。

## ARM

### 32位 ARM

#### 优化 Keil 6/2013 (ARM 模式)

**列表 1.115: 优化 Keil 6/2013 (ARM 模式)**

```asm
.text:000000B0 EXPORT f_signed ; CODE XREF: main+C
.text:000000B0 f_signed
.text:000000B4 STMFD SP, {R4,R6,LR}
.text:000000B8 MOV R4, R1
.text:000000BC CMP R0, R4
.text:000000C0 MOV R5, R0
.text:000000C4 ADRGT R0, #a1
.text:000000C8 BLGT 2printf
.text:000000CC CMP R5, R4
.text:000000D0 ADREQ R0, #a0 ; "a==b"
.text:000000D4 BLEQ 2printf
.text:000000D8 LDMFD SP, {R4,R6,PC}
.text:000000DC LDMFD SP, {R4,R6,LR}
.text:000000E0 ADR R0, #a1 ; "a==b"
.text:000000E4 B 2printf
.text:000000E8 ; End of function f_signed
```

ARM 中的许多指令只有在设置了特定标志位时才能执行。这在比较数字时非常有用。

例如，`ADD` 指令在内部实际上命名为 `ADDAL`，`AL` 代表 Always（始终），其谓词编码在 32 位 ARM 指令的 4 位中（条件字段）。用于无条件跳转的 `B` 指令实际上也是有条件的，其编码方式与任何其他条件指令相同，只是条件字段中是 `AL`，它意味着始终执行，忽略标志位。

`ADRGT` 指令的工作方式与 `ADR` 相同，但仅在之前的 `CMP` 指令在比较两个数时发现一个数大于另一个（大于，Greater Than）的情况下才会执行。

下一个 `BLGT` 指令的行为与 `BL` 完全相同，并且仅在比较结果为大于（Greater Than）时被触发。`ADRGT` 将字符串 "a>b" 的指针写入 `R0`，而 `BLGT` 调用 `printf()`。因此，带有 `-GT` 后缀的指令仅在 `R0`（即 `a`）大于 `R4`（即 `b`）时执行。

在后续操作中，我们使用了 `ADREQ` 和 `BLEQ` 指令。这些指令仅在最后一次比较中操作数相等时才会执行。在它们之前还有另一个 `CMP`（`printf()` 的执行可能会篡改标志位）。

然后我们使用 `LDMFD`，该指令的工作方式与 `LDMIA` 相同，但当其中一个值大于或等于另一个值（大于或等于，Greater or Equal）时被触发。`LDMFD SP,{R4-R6}` 指令作为函数序言，但它仅在 `a>=b` 时才被触发，然后执行函数。

但如果不满足该条件，即 `a < b`，则控制流将继续到下一个：

`LDMFD SP!` 指令是另一个函数尾声。此指令恢复 `R4-R6` 寄存器的状态，但替换的是 `PC`，因此不会从函数返回。最后两次调用以字符串 "a<b" 作为唯一参数的 `printf()`。在 `<printf(带有多个参数)>` 部分中，我们使用了无条件跳转到 `printf()` 函数而不是返回（见第 71 页的 1.11.2）。

`f_unsigned` 是无符号的，在这里使用了这些谓词（`HI` = 无符号高位，`CS` = Carry Set 进位设置，即大于或等于），它们与之前的类似，但针对无符号值。

`main()` 函数中剩余值的操作不多了：

**列表 1.116: main()**

```asm
.text:00000128 EXPORT main
.text:00000128 main      STMFD SP, {R4,LR}
.text:0000012C      MOV R1, #2
.text:00000130      MOV R0, #1
.text:00000134      MOV R3, #2
.text:00000138      MOV R1, #2
.text:0000013C      MOV R0, #1
.text:00000140      BL f_unsigned
.text:00000144      MOV R0, #0
.text:00000148      LDMFD SP,{R4,PC}
```

这就是在 ARM 中消除条件跳转的方法。为什么这样做更好？参见第 57 页的 2.4。x86 中没有这样的指令，除了 `CMOV`（它与 `MOV` 相同，但仅在 `CMP` 设置了标志位时触发）。

#### 优化 Keil 6/2013 (Thumb 模式)

**列表 1.117: 优化 Keil 6/2013 (Thumb 模式)**

```asm
.text:00000072 f_signed CODE XREF:main+6
.text:00000072 PUSH {R4,R5,LR}
.text:00000074 MOVS R4,R1
.text:00000076 MOVS R5,R0
.text:00000078 CMP R0,R4
.text:0000007A BLE .B2
.text:0000007C ADR R0, #a ; "a>b"
.text:0000007E BL printf
.text:00000080 .B2 XREF:f_signed+8
.text:00000080 CMP R5,R4
.text:00000082 BNE .B8
.text:00000084 ADR R0, #a ; "a=b"
.text:00000086 BL printf
.text:00000088 .B8 XREF:f_signed+12
.text:00000088 CMP R5,R4
.text:0000008A BGE .96
.text:0000008C ADR R0, #a ; "a<b"
.text:0000008E BL printf
.text:00000090 .96 POP {R4,R6,PC}
```

Thumb 模式下的 `B` 指令可以使用条件码补充，因此 `BLE` 是小于等于跳转，`BNE` 是不等于，`BGE` 是大于等于。`f_unsigned` 类似，处理无符号值时仅使用其他指令：`BLS`（无符号低或等于）和 `BCS`（Carry Set，即大于或等于）。
