```java
public class ret {
```


这意味着 `return` 指令用于返回控制权而不返回实际值。
了解了这一切后，很容易从最后一条指令推断出函数（或方法）的返回类型。

## 4.1.5 栈操作

```java
public class stack {
    public static void main(String[] args) {
        int a = 10;
        int b = 20;
        int c = a + b;
        System.out.println(c);
    }
}
```

```java
public static void main(java.lang.String[]);
flags: ACC_PUBLIC, ACC_STATIC
Code:
stack=2, locals=4, args_size=1
  0: bipush 10
  1: istore_1
  2: bipush 20
  3: istore_2
  4: iload_1
  5: iload_2
  6: iadd
  7: istore_3
  8: getstatic #2 // Field java/lang/System.out:Ljava/io/PrintStream;
  11: iload_3
  12: invokevirtual #3 // Method java/io/PrintStream.println:(I)V
  13: return
```

`bipush 10` 将 10 推入栈。
`istore_1` 将栈顶值弹出并存入局部变量 1。
`bipush 20` 将 20 推入栈。
`istore_2` 将栈顶值弹出并存入局部变量 2。
`iload_1` 将局部变量 1 的值推入栈。
`iload_2` 将局部变量 2 的值推入栈。
`iadd` 将栈顶两个值相加并将结果留在栈顶。
`istore_3` 将结果弹出并存入局部变量 3（对应变量 `c`）。
`iload_3` 将局部变量 3 的值推入栈。
`getstatic #2` 获取 `System.out` 引用。
`invokevirtual #3` 调用 `println` 方法。

因此，在内部，`println` 方法接收两个参数作为输入：1) `this`，即指向对象的引用；2) 要打印的整数值。
事实上，`println()` 是在一个初始化的 `System.out` 对象内部作为方法调用的。
为了方便起见，`javap` 工具将所有这些信息写入了注释中。

## 4.1.6 调用 beep()

这是一个简单的无参数函数调用：

```java
public static void main(String[] args) {
    java.awt.Toolkit.getDefaultToolkit().beep();
}
```

```java
public static void main(java.lang.String[]);
flags: ACC_PUBLIC, ACC_STATIC
Code:
stack=1, locals=1, args_size=1
0: invokestatic #2 // Method java/awt/Toolkit.getDefaultToolkit()Ljava/awt/Toolkit;
1: invokevirtual #3 // Method java/awt/Toolkit.beep():V
2: return
```

位于偏移量 0 处的第一条 `invokestatic` 调用 `java.awt.Toolkit.getDefaultToolkit()`，它返回一个 `Toolkit` 类对象的引用。
位于偏移量 1 处的 `invokevirtual` 指令调用了该类的 `beep()` 方法。

## 4.1.7 线性同余 PRNG

让我们尝试一个简单的伪随机数生成器，我们在书中已经考虑过一次（第424页的1.29节）：

```java
public class LCG {
    public static int rand_state;
    public static int RNG = 1664525;
    public static int RNG_c = 1013904223;

    public static void my_srand(int init) {
        rand_state = init;
    }

    public static int my_rand() {
        rand_state = rand_state * RNG;
        rand_state = rand_state + RNG_c;
        return rand_state & 0x7fff;
    }
}
```

如果你发现任何拼写错误、错误或有任何建议，请随时给我留言：我的电子邮箱。谢谢！

有几个类字段在启动时被初始化。

但如何呢？在 `javap` 输出中我们可以找到类构造函数（`<clinit>`）：

```
static {};
flags: ACC_STATIC
Code:
stack=1, locals=0, args_size=0
0: ldc #5 // int 1664525
2: putstatic #3 // Field RNG:I
5: ldc #6 // int 1013904223
7: putstatic #4 // Field RNG_c:I
10: return
```

这就是变量被初始化的原因。

`RNG` 占据类中的第 3 个槽，`RNG_c` 占据第 4 个槽，`putstatic` 将常量存入那里。

`my_srand()` 函数将输入值存储在 `rand_state` 中：

```
public static void my_srand(int);
flags: ACC_PUBLIC, ACC_STATIC
Code:
stack=1, locals=1, args_size=1
0: iload_0
1: putstatic #2 // Field rand_state:I
2: return
```

`iload_0` 获取输入值并将其推入栈中。因为这是一个 `static` 方法，所以没有 `this` 引用，参数索引从 0 开始。

`rand_state` 字段占据类中的第 2 个槽，所以 `putstatic` 将栈顶（TOS）的值复制到第 2 个槽。

现在看 `my_rand()`：

```
public static int my_rand();
flags: ACC_PUBLIC, ACC_STATIC
Code:
stack=2, locals=0, args_size=0
0: getstatic #2 // Field rand_state:I
3: getstatic #3 // Field RNG:I
6: imul
7: putstatic #2 // Field rand_state:I
10: getstatic #2 // Field rand_state:I
13: getstatic #4 // Field RNG_c:I
16: iadd
17: putstatic #2 // Field rand_state:I
20: getstatic #2 // Field rand_state:I
23: bipush 127
25: iand
26: ireturn
```

它只是从类的字段中加载所有值，执行操作，并使用 `putstatic` 指令更新 `rand_state` 的值。

在偏移量 20 处，`rand_state` 再次加载（因为它已经被 `putstatic` 从栈中弹出）。

这看起来像是不高效的代码，但放心，JVM 通常足够好地优化此类内容。

## 4.1.8 条件跳转

```java
public class abs {
    public static int abs(int a) {
        if (a < 0)
            return -a;
        return a;
    }
}
```

```
public static int abs(int);
flags: ACC_PUBLIC, ACC_STATIC
Code:
stack=1, locals=1, args_size=1
0: iload_0
1: ifge 7
4: iload_0
5: ineg
6: ireturn
7: iload_0
8: ireturn
```

如果栈顶的值大于等于 0，则跳转到偏移量 7。

不要忘记，任何 `if` 指令都会从栈中弹出用于比较的值（即栈顶的值）。

另一个例子：

```java
public static int min(int a, int b) {
    if (a > b)
        return b;
    return a;
}
```
