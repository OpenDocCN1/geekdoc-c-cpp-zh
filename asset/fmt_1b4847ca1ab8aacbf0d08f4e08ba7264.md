
为共享内存选择正确尺寸：在内核中声明的共享内存大小直接影响应用的占用率（占据，定义为多处理器执行的 `warp` 数量）。较高的占用率可以更好地隐藏内存延迟，但每个块分配过大的共享内存会限制并发运行的块数量。因此，找到平衡是关键。每个块的共享内存大小通常是一个可调参数，可以根据特定的应用程序和底层 GPU 架构进行优化。

使用共享内存进行归约操作：归约操作（如累加数组元素）由于共享内存相比全局内存访问速度更快，从中受益匪浅。其核心思想是在最终结果写回全局内存之前，尽可能在共享内存内完成计算。通过仔细的设计，可以确保这些操作高效执行，并具有极少的银行冲突和高并行效率。

共享内存是 CUDA 编程中的一种强大工具，弥补了快速但受限的寄存器内存与缓慢但丰富的全局内存之间的差距。通过理解其特殊性并掌握有效利用它的策略，开发者可以解锁 CUDA 应用中显著的性能提升。仔细关注内存访问模式、避免银行冲突和优化内存尺寸分配，可以将共享内存转变为在 NVIDIA GPU 上实现高性能计算的关键资产。

### 6.9 常量内存与纹理内存优化

在 CUDA 的 GPU 计算领域，理解并有效利用不同类型的内存可以显著影响应用程序的性能和效率。其中，常量内存和纹理内存提供了独特的优势，如果利用得当，将带来巨大的性能提升。本节深入探讨常量内存和纹理内存优化的复杂性，旨在为开发者提供最大化 CUDA 应用速度和效率的知识。

#### 常量内存

CUDA 中的常量内存是设备上的只读内存空间，它是经过缓存的，并设计用于所有线程读取相同值的场景。当内核重复读取一小部分数据时，它最有效。这种内存类型相对较小；但由于其缓存机制，当线程间的访问均匀时，它可以显著减少内存延迟。

要在 CUDA 中利用常量内存，必须使用 `__constant__` 空间限定符声明全局常量变量。以下是在内核中定义和使用常量内存的示例：

```
__constant__ float constArray[256]; 
__global__ void array() { 
    int i = threadIdx.x; 
    float val = constArray[i]; 
    // 使用 val 执行操作 
}
```

从宿主机（host）将数据拷贝到常量内存需要使用特定的操作。方法如下：

```
float hostArray[256]; // 初始化 hostArray
memcpy(constantMemory, hostArray, sizeof(hostArray));
```

需要注意的是，常量内存有一个速度优势方面存在局限性：当束（warp）内的线程访问不同的位置时，缓存优势会降低，可能导致内存访问的序列化。

### 纹理内存

纹理内存的作用与常量内存类似，但提供了适用于图形纹理的专用缓存和寻址模式——这些模式也可以用于通用计算。对于呈现空间局部性的读取操作，纹理内存大有益，从而提高特定内存访问模式的读取效率。

要使用纹理内存，必须声明并定义纹理引用（texture reference）。CUDA提供了纹理引用和纹理对象。以下是使用纹理对象使用纹理内存的示例：

```
cudaTextureType1D, cudaReadModeElementType texRef; 
__global__ void output(int width) { 
    int x = blockIdx.x * blockDim.x + threadIdx.x; 
    if (x < width) { 
        float val = tex1DFetch(texRef, x); 
        output[x] = val; 
        // 进一步处理 
    }
}
```

设置纹理引用涉及将纹理绑定到 CUDA 数组或线性内存。重要的是，纹理获取返回的是缓存值，这可能无法反映全局内存中的最新写入，这凸显了纹理内存的只读特性。

以下是将线性内存绑定到纹理引用的简单示例：

```
cudaChannelFormatDesc channelDesc;
cuArrayCreate(&cuArray, &channelDesc, width, height, mem);
```

#### 实际考虑

在使用常量内存和纹理内存优化 CUDA 应用时，应记住以下几点实际考虑：

- 确定应用程序的数据访问模式是否能受益于常量或纹理内存提供的缓存机制。
- 记住常量内存的大小限制（通常为 64KB）并做出相应的计划。
- 对于可以从中受益的应用程序（例如图像处理），利用纹理内存的专用寻址和过滤能力。
- 当一个束中的所有线程访问同一位置时，常量内存性能最佳。发散访问可能会降低缓存的有效性。
- 评估内存访问模式并尝试两种类型的内存，以确定哪种内存对你的特定用例提供了最佳性能提升。

常量和纹理内存的优化可以显著提高 CUDA 应用的性能。然而，与许多优化方面一样，关键在于理解数据的特性和访问模式，从而选择最合适的内存类型进行利用。

## 6.10 流与并发优化

在 CUDA 编程中有效利用流（streams）是实现显著性能提升的基石策略。在 CUDA 上文中，流允许内核函数、内存操作和宿主机代码并发执行，从而更高效地利用 GPU 计算资源。本节深入探讨了在 CUDA 应用中优化并发和有效使用流的策略。

### 理解 CUDA 流

在 CUDA 术语中，流是在 GPU 上按顺序执行的一系列操作。不同流中的操作可以并发执行，但受硬件限制。通过使用多个流，CUDA 程序可以重叠内核的执行以及宿主机与设备之间的内存传输，从而带来巨大的性能收益。

### 流的创建与销毁

在 CUDA 程序中创建和管理流涉及特定的 API 调用。`cudaStreamCreate()` 函数用于创建新流，而 `cudaStreamDestroy()` 则在不再需要时用于清理。妥善管理流以避免资源泄漏并确保程序稳定性至关重要。

```
cudaStream_t stream1, stream2; // 使用流进行内核执行或内存传输
```

### 在流中执行内核

要让内核在特定流中执行，必须在内核启动时传递流参数。这是通过在内核调用后附加 `<<<blockDim, 0, stream>>>` 实现的，其中 `stream` 是内核要执行的流。

```cpp
__global__ void kernel(int *d_data) { 内核实现 } 
// 在流中执行内核 
int *d_data; 
kernel<<<256, 1, 0, stream1>>>(d_data);
```

### 数据传输与内核执行的重叠

使用流强大的能力之一是允许数据传输与内核执行重叠。对于计算能力为 2.0 及以上的设备，数据传输（从宿主机到设备或设备到宿主机）可以与另一个流中的内核执行并行。这对于隐藏数据传输的延迟特别有用，从而最大化 GPU 利用率。

要实现这种重叠，必须确保内存操作和内核执行正确分配在各个流中。通常，在流之间交替使用“计算”和“拷贝”操作模式，以保持执行和数据传输的连续流。

```
cudaMemcpyAsync(d_data, h_data, size, cudaMemcpyHostToDevice, stream1);
kernel<<<blockSize, blockSize, 0, stream2>>>(d_data);
cudaMemcpyAsync(h_data, d_data, size, cudaMemcpyDeviceToHost, stream1);
```

在上述示例中，在 `stream1` 中启动宿主机到设备的数据传输，随后在 `stream2` 中执行内核，最后在 `stream1` 中将结果拷贝回宿主机。如果执行正确，数据传输和内核执行可以并行进行，从而缩短总执行时间。

#### 优化流的使用

虽然流提供了显著增强性能的潜力，但盲目使用多个流会导致资源竞争，并可能导致性能下降。以下是优化流使用的一些指南：

- 仔细分析应用程序以识别并发执行的机会。
- 使用最少数量流来实现所需的并发性，同时不让 GPU 过载。
- 在需要时利用流同步流之间的操作，同时避免过度的序列化。
- 考虑对于操作之间复杂的依赖关系使用 CUDA Graph，因为它们提供了可能更高效的执行。

在 CUDA 应用中有效利用流和并发可以大幅增加 GPU 资源的利用率，并显著减少总执行时间。

## 6.11 为了性能编译 CUDA 代码

优化 CUDA 代码涉及全面理解如何有效地编译它以获得最大性能。编译过程会显著影响 CUDA 应用的执行速度和效率。本节探讨了优化编译 CUDA 代码的几个关键考虑因素和策略，包括选择正确的编译器标志、理解 PTX（并行线程执行）版本以及有效利用 NVCC（NVIDIA CUDA 编译器）。

### 理解编译器选项

在编译 CUDA 代码时，利用正确的编译器选项至关重要。这些选项会极大地影响生成的二进制文件的性能特性。以下是几个值得考虑的重要标志和策略：

- `-O2` 和 `-O3` 优化标志指示编译器为最大速度优化代码 (`-O2`)以及更激进的、可能涉及更长时间编译等待的优化 (`-O3`)。虽然这些优化可以显著提升性能，但进行彻底测试至关重要，因为它们在某些情况下可能会引入 Bug 或意外行为。
- `--gpu-architecture` 和相关标志允许开发者指定目标 GPU 架构（例如 `compute_50`）和即时编译的 PTX 版本。针对目标 GPU 的特性对应用程序进行调整可以释放巨大的性能提升。
- `-ffast-math` 标志将某些浮点数学运算替换为速度更快但可能不精确的版本。它对于计算速度优于数学精度的应用程序是有益的。

#### 深入理解 PTX 版本

PTX 充当 CUDA C 代码与 GPU 执行的二进制文件之间的中间表示。理解并管理由 NVCC 生成的 PTX 版本对于性能至关重要。PTX 版本影响着 CUDA 内核的编译方式，并可能影响生成的二进制文件的效率。在编译期间指定特定的 PTX 版本，需要使用 `--gpu-code` 标志并配合所需的计算能力（compute capability）。

#### 运用 NVCC

NVIDIA CUDA 编译器 (`NVCC`) 在编译 CUDA 代码中起着核心作用。它处理 CUDA C 文件 (`.cu`) 并调用主机编译器来处理 C/C++ 代码。为了获得最佳性能，理解并正确利用 NVCC 选项至关重要。以下是使用 NVCC 编译 CUDA 程序的示例：

```
nvcc -O3 --gpu-architecture=compute_75 --gpu-code=compute_75,sm_75 example.cu -o example
```

在此命令中，`-O3` 标志用于激进优化，而 `-gpu-architecture` 和 `-gpu-code` 分别指定了目标 GPU 架构和代码版本。

为了充分利用 CUDA 编译器提升性能，开发者应该采用以下实用策略：

- 迭代优化是一个迭代过程。从使用基础优化编译代码开始，逐渐引入更激进的编译器标志，同时测量其对性能和准确性的影响。使用 NVIDIA 性能分析器（profiler）识别热点和瓶颈。使用分析引导的优化选项进行编译可以进一步针对特定的工作负载特性定制二进制文件。
- 多目标开发：对于旨在运行在不同 GPU 架构上的应用程序，为多个目标进行编译是有益的。这确保了应用程序能够利用每个目标 GPU 的特定特性和优化。

总之，为了性能编译 CUDA 代码是一个微妙的过程，需要对可用编译器选项和策略有深入理解。通过根据应用程序的特定需求和目标 GPU 架构定制编译过程，开发者可以实现显著的性能提升。优化的迭代方法结合对 NVCC 选项的策略性使用以及彻底测试，构成了高效 CUDA 应用开发的基石。

### 7.1 CUDA 中的动态并行

CUDA 中的动态并行代表了 GPU 内核启动和管理方式的范式转变传统的 CUDA 编程模型要求 CPU 初始化所有内核启动。然而，通过动态并行，可以从 GPU 上运行的其他内核调用内核，从而实现层次化且可能高效的并行计算结构。

此功能随 CUDA 5.0 引入，专为计算能力 3.5 及以上的 GPU 设计，提供了一种更自适应和递归的解决问题方法。通过允许 GPU 线程直接启动其他内核，动态并行简化了复杂的嵌套计算和数据依赖的管理。

#### 理解动态并行

动态并行的核心思想非常直观：它允许正在运行的内核（kernel）调用另一个内核或一组内核。这些子内核反过来可以启动其他内核，从而创建一个完全由 GPU 管理的内核启动层次结构。这种能力对于得益于递归方法的算法来说特别有用，例如快速排序、n 体模拟或有限元分析中的自适应网格细化。

动态并行的优势包括：

- **减少 CPU-GPU 交互**：通过尽量减少 CPU 启动内核的需求，动态并行可以减少与 CPU-GPU 通信相关的开销，从而潜在地提高性能。
- **算法设计灵活性更高**：程序员可以直接在 GPU 上实现复杂的层次化算法，而不受扁平并行结构的限制。
- **简化复杂问题的代码**：动态并行允许对递归和自适应算法进行更自然的表达，使代码更易编写和理解。

然而，考虑从内核内部启动内核的开销是非常关重要的。如果不谨慎使用，过度使用动态并行可能会导致性能下降。

#### 示例：使用动态并行

让我们探索一个简单的示例，展示如何在 CUDA 中使用动态并行。在这里，父内核启动了一个子内核，并在它们之间传递数据。

```cpp
__global__ void childKernel(int *data) {
    int idx = threadIdx.x + blockIdx.x * blockDim.x;
    data[idx] += 1; // 对数据进行简单操作
} 

__global__ void parentKernel(int *data, int N) {
    int threadsPerBlock = 256;
    int blocksGrid = (N + threadsPerBlock - 1) / threadsPerBlock;
    childKernel<<<blocksGrid, threadsPerBlock>>>(data);
}
```

在这个示例中，`parentKernel` 由主机（CPU）启动，反过来启动 `childKernel` 以对传递给它的数据数组执行简单操作。这展示了在 CUDA 应用中使用动态并行的基本结构。
