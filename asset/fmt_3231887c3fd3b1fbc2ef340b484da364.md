并且最后此外，CLR 将编译 `catch` 和 `finally` 块中的所有代码，包括从这些块内部调用的所有方法。这将消除在执行恢复代码或清理代码时可能发生的一系列异常。

- 取决于状态存储的位置，你可以使用事务来确保所有状态都被修改，或者状态都不被修改。例如，如果数据在数据库中，事务的工作效果很好。Windows 还支持事务性注册表和文件操作，因此你可能可以使用这些功能；然而，目前 `.NET Framework` 并没有直接暴露此功能。你必须通过 `PInvoke` 调用原生代码才能查看。更多信息请参阅 `System.Transactions.TransactionScope`。

- 你可以设计你的方法使其更具显式。例如，`Monitor` 类通常用于如下所示的获取/释放线程同步：

```csharp
public static class SomeType {
    private static Object s_lockObject = new Object();
    public static void SomeMethod() {
        try {
            // 在此处执行线程安全操作...
        } finally {
            Monitor.Exit(s_lockObject);
        }
    }
}
```

由于上述显示的问题，上面使用的 `Monitor.Enter` 方法重载已被发现，建议你将代码重写如下：

```csharp
public static class SomeType {
    private static Object s_lockObject = new Object();
    public static void SomeMethod() {
        Boolean lockTaken = false;
        try {
            Monitor.Enter(s_lockObject, ref lockTaken);
            // 在此处执行线程安全操作...
        }
        finally {
            if (lockTaken) Monitor.Exit(s_lockObject);
        }
    }
}
```

如果在你的代码中，你已经确定状态已因修复而损坏，那么你应该销毁任何损坏的状态，以便其不会造成额外的伤害。然后，重启你的应用程序，使状态能够初始化到良好状态。

而且，如果你觉得状态已经糟糕到应该终止进程，那么你可以调用 `Environment` 的静态方法 `FailFast`：

```csharp
public static void FailFast(String message);
public static void FailFast(String message, Exception exception);
```

该方法会终止进程，而不运行任何活跃的 `try/finally` 块或 `Finalize` 方法。
