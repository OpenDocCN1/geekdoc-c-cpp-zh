由于常量值是在编译时确定的，只有在确定值永远不会改变时才使用它们。让我演示一下我的意思。首先，将以下代码编译为 DLL 程序集。

```csharp
using System;

public sealed class Program {

    public static void Main() {

        Console.WriteLine("Max entries supported in list: " +
             SomeType.MaxEntriesList);

    }

}
```

你会注意到此应用程序引用了 `SomeType` 类定义的 `MaxEntriesList`。当编译器构建应用程序时，它看到 `MaxEntriesList` 是值为 `50` 的常量字面量，并将 `Int32` 的值直接嵌入应用程序的 IL 代码中，如下所示：

```
.method hidebys static void Main() cil managed {
    entrypoint
    // 代码大小
    mastack 8
    IL_0000: nop
    IL_0001: ldrstr  "Max entries supported in list: "
    IL_0006: ldc.i4.s 50
    IL_000b: box [mscorlib]System.Int32
    IL_000d: call  string [mscorlib]System.String::Concat(object,object)
    IL_0012: call  void [mscorlib]System.Console::WriteLine(string)
    IL_0017: nop
    IL_0018: ret
} // 方法::Main结束
```

这个示例向你清楚展示了版本问题。如果开发者将 `MaxEntriesList` 常量更改为 `1000` 并重新生成 DLL 程序集，应用程序程序集不受影响。为了让应用程序获取新值，也必须重新编译它。

# 字段

字段 `field` 是一个持有值类型实例或引用类型引用的数据成员。表 7-1 显示了可以应用于字段的修饰符。

## 表 7-1 字段修饰符

| CLR 术语 | C# 术语 | 说明 |
| --- | --- | --- |
| Static | static | 字段是类型状态的一部分，而不是对象状态的一部分。 |
| Instance | (default) | 字段与类型的实例关联，而不是类型本身。 |
| InitOnly | readonly | 字段只能由构造函数方法中的代码写入。 |
| Volatile | volatile | 访问该字段的代码不会受到编译器、CLR 或硬件可能执行的线程安全优化的影响。只有以下类型可以是 volatile 的：Single, Boolean, Byte, SByte, Int16, UInt16, Int32, UInt32, Char，以及所有底层类型为 Byte、SByte, Int16, UInt16, Int32 或 UInt32 的枚举。Volatile 字段详见第 28 章“原语线程同步构造结构”。 |

如表 7-1 所示，通用语言运行时 `CLR` 同时支持静态 `static` 和非静态字段。对于字段，持有字段数据的动态内存分配在类型对象内部，该对象在类型被加载到 `AppDomain` 时创建，这通常发生在任何方法引用该类型并对其进行即时 `JIT` 编译的首次运行时。对于实例字段，持有字段的动态内存是在类型实例构造时分配的。

由于字段存储在动态内存中，因此可以在运行时获取它们的值。字段还解决了常量中存在的版本控制问题。此外，字段可以可以是任何类型，因此你不需要将其限制为编译器的内置原始类型。

`CLR` 支持只读 `readonly` 字段和读写字段。大多数字段都是读写字段，这意味着随着代码的执行，字段的值可能会发生多次。只读字段只能在构造函数方法中被写入。编译器和验证器会确保只读字段不会被构造函数以外的任何方法写入。请注意，可以使用反射来修改只读字段。

# 第二部分 设计类型

```csharp
using System;

public sealed class LibraryType {
    // 需要 static 来将字段与类型关联。
    public static readonly Int32 MaxEntriesInList = 50;
}
```

这是你唯一需要做的更改；应用程序代码不需要任何更改，尽管你必须重新编译它以看到新行为。现在，当应用程序的 `Main` 方法运行时，`CLR` 将加载 DLL 程序集，并从为其分配的动态内存中获取 `MaxEntriesInList` 字段的值。当然，该值将是 `50`。

假设 DLL 程序集的开发者将 `50` 改为 `1000` 并重新生成了程序集。当重新执行应用程序时，它将自动获取新值：`1000`。在这种情况下，应用程序代码不需要重新编译。

此示例展示了如何定义与类型本身关联的静态只读字段，以及读写静态字段、只读和读写实例字段：

```csharp
public sealed class SomeType {
    // 这是一个静态只读字段；它的值在类于运行时初始化时计算并存储在内存中。
    public static readonly Random s_random = new Random();
    // 这是一个静态读写字段。
    private static Int32 s_numberOfWrites = 0;
    // 这是一个实例只读字段。
    public readonly String Pathname = "Untitled";
    // 这是一个实例读写字段。
    private System.IO.FileStream m_fs;
    public SomeType(String pathname) {
        // 这一行更改了只读字段。
        // 这是可以的，因为代码位于构造函数。
        this.Pathname = pathname;
    }
    public String DoSomething() {
        // 这一行读取并写入静态读写字段。
        s_numberOfWrites = s_numberOfWrites + 1;
        // 这一行读取只读实例字段。
        return Pathname;
    }
}
```

# 第 7 章 常量与字段

在代码中，许多字段是内联初始化的。C# 允许你使用这种方便的初始化语法来初始化类常量以及读写和只读字段。你将在第 8 章“方法”中看到，C# 将内联初始化字段视为在构造函数中初始化字段的简写语法。此外，在 C# 中，在构造函数中使用内联赋值语法初始化字段时，需要考虑一些性能问题。

> 重要：当字段是引用类型且字段被标记为 `readonly` 时，不可变的是引用，而不是它所引用的对象。
```csharp
public sealed class AType {
    // InvalidChars 始终引用相同的
    public static readonly Char[] InvalidChars = { 'A', 'B', 'C' };
}
public sealed class AnotherType {
    public static void MC() {
        // 以下这些行是合法的，可以编译，并成功地修改数组中的字符
        AType.InvalidChars[0] = 'X';
        AType.InvalidChars[1] = 'Y';
        AType.InvalidChars[2] = 'Z';
        // 下这一行是非合法的且无法编译，因为 InvalidChars 无法更改
        AType.InvalidChars = new Char[] { 'X', 'Y', 'Z' };
    }
}
```

## 实例构造函数与类

例如，如果你定义了以下类：

```csharp
public class SomeType {
}
```

这就好像你编写了如下代码：

```csharp
public class SomeType {
    public SomeType() : base() { }
}
```

如果该类是抽象的 `abstract`，编译器生成的默认构造函数具有受保护的 `protected` 访问性；否则，构造函数具有公共的 `public` 访问性。如果基类没有提供无参数构造函数，派生类必须显式调用基类构造函数，否则编译器将产生错误。如果该类是静态的，编译器将不会在类定义中生成任何默认构造函数。

一个类型可以定义多个实例构造函数。每个构造函数必须具有不同的签名，且每个构造函数可以有不同的访问性。对于可验证的代码，类的构造函数在访问基类的任何继承字段之前，必须调用其基类构造函数。如果派生类没有显式调用基类构造函数，C# 编译器将自动生成对基类构造函数的调用。最终，将调用 `System.Object` 的公共无参数构造函数。

在某些情况下，可以在不调用实例构造函数的情况下创建类型的实例。特别是，调用 `Object` 的 `MemberwiseClone` 方法会分配内存、初始化对象的开销字段，并将对象的字节复制到新对象。此外，当运行时序列化器反序列化对象时，使用 `System.Runtime.Serialization.Formatter` 类型的 `GetUninitializedObject` 或 `GetSafeUninitializedObject`，通常不会调用构造函数。

> **重要** 你应该在构造函数内部调用任何可能影响正在构建对象的虚拟方法。

C# 提供了一种简单的语法，允许在构造引用类型的实例时初始化其字段：

```csharp
internal sealed class SomeType {
    private Int32 m_x = 5;
}
```

当构造一个 `SomeType` 对象时，其 `m_x` 字段将初始化为 `5`。

```csharp
.method hidebyspecial name rtspecialname
    instance void .ctor() managed
{
    // Code size      14 (0xe)
    .maxstack      8
IL_0000:      ldarg.0
IL_0001:      ldc.i4.5
IL_0002:      stldld int32 SomeType::m_x
IL_0007:      ldarg.0
IL_0008:      call      instance void [mscorlib]System.Object::.ctor()
IL_000d:      ret
}// end of method SomeType::.ctor
```

在此代码中，你看到 `SomeType` 的构造函数包含在 `m_x` 中存储 `5` 的代码并调用了基类的构造函数。

```csharp
internal sealed class SomeType {
    private Int32 m_x = 5;
    private String m_s = "Hi there";
    private Double m_d = 3.14159;
    private Byte m_b;
    // 这里是一些构造函数。
    public SomeType() { ... }
    public SomeType(Int32 x) { ... }
    public SomeType(String s) { ...; m_d = 10; }
}
```

当编译器为这三个构造函数方法生成代码时，每个方法的开头都包含初始化 `m_x`、`m_s` 和 `m_d` 的代码。

注意：编译器在调用基类构造函数之前，会使用这种方便的语法初始化任何字段。

由于前面的类中有三个构造函数，编译器生成了三次初始化 `m_x`、`m_s` 和 `m_d` 的代码。

## 实例构造函数与结构（值类型）

值类型（结构）构造函数的工作方式与引用类型（类）构造函数不同。公共语言运行时 `CLR` 始终允许创建值类型实例，并且没有方法可以阻止值类型的实例化。由于这种原因，值类型实际上不需要定义构造函数，C# 编译器也不会为值类型生成无参数构造函数。

```csharp
internal struct Point {
    public Int32 m_x, m_y;
}
internal sealed class Rectangle {
    public Point m_topleft, m_bottomRight;
}
```
