
`SqlMembershipProvider` 用于将用户凭据存储在 `SQL Server` 数据存储中。你需要先安装 `SQL Server` 成员资格数据存储，然后配置 `SqlMembershipProvider` 以在 `ASP.NET` 应用程序中使用 `SqlMembershipProvider`。`SQL Server` 成员资格数据存储是用于存储用户凭据的。我们将在后续主题中查看安装 `SQL Server` 成员资格数据存储和配置 `SqlMembershipProvider` 的详细信息。

## Installing the SQL Server Data Store

使用具有管理权限的帐户登录到计算机，例如管理员帐户，以在计算机上安装 `SQL Server` 成员资格数据存储。登录系统后，从 `Visual Studio 2010` 命令提示符运行 `aspnet_regsql` 实用程序并以管理员身份运行。`aspnet_regsql` 实用程序用于安装 `ASP.NET` 的各种功能的数据存储，例如配置文件、个性化和成员资格。你需要了解其各种选项，如下所示，以使用 `aspnet_regsql` 实用程序：

- `-E` — 使用当前登录用户的凭据进行身份验证。
- `-S` — 指定要安装 `SQL Server` 数据存储的计算机的名称。
- `-A m` — 生成 `SqlMembershipProvider` 所需的表和存储过程。

例如，你可以使用以下命令在计算机上安装 `SQL Server` 成员资格数据存储：

```text
aspnet_regsql.exe -E -S server -A m
```

在前一行代码中，计算机的名称是 `Server`。

## Configuring SqlMembershipProvider

默认情况下，`SqlMembershipProvider` 的一个实例 `AspNet.SqlMembershipProvider` 在你的 `ASP.NET` 应用程序的 `Machine.config` 文件中定义。此实例将你的 `ASP.NET` 应用程序连接到在本地计算机上运行的 `SQL Server` 数据存储实例。因此，如果 `SQL Server` 成员资格数据存储安装在本地计算机上，你无需显式配置 `SqlMembershipProvider`。

但是，如果你想将 `ASP.NET` 应用程序连接到在与 `ASP.NET` 应用程序运行的计算机不同的计算机上运行的 `SQL Server` 数据存储，则需要配置 `SqlMembershipProvider`。你可以通过在 `ASP.NET` 应用程序的 `web.config` 文件中定义连接字符串和 `SqlMembershipProvider` 的实例来配置 `SqlMembershipProvider`。

与 `ActiveDirectoryMembershipProvider` 类似，你需要定义 `<provider>` 元素来创建 `SqlMembershipProvider` 的实例。现在，让我们来看一下在为 `SqlMembershipProvider` 定义 `<provider>` 元素时你需要设置的一些常见 `<provider>` 元素属性，见表 36.20。

### Table 36.20: Attributes of the `<provider>` Element

| Attribute | Description |
|---|---|
| ApplicationName | 指定单个应用程序的用户的信息。你应该在使用 `applicationName` 属性的值限定用户信息时将其存储在 `SQL Server` 数据存储中。这可以防止在单个 `SQL Server` 数据存储中存储多个应用程序的信息时可能出现的相似用户名的冲突。`applicationName` 属性的默认值是 `/`。 |
| EnablePasswordReset | 指定用户是否可以修改其密码。默认情况下，`enablePasswordReset` 属性设置为 `false`。你只能在 `requiresQuestionAndAnswer` 属性设置为 `true` 时将此属性设置为 `true`。 |
| PasswordFormat | 指定在 `SQL Server` 数据存储中存储密码的格式。此属性可以取以下值：<br><br>- **Clear** – 以明文形式存储密码。以这种格式存储和检索密码很容易；然而，密码安全性受损。<br>- **Encrypted** – 以加密形式存储密码。需要解密才能检索以这种格式存储的密码。然而，以加密格式存储的密码的安全性很高。<br>- **Hashed** – 使用单向哈希算法对密码进行哈希处理后再存储。 这些密码的安全性很高；然而，你无法检索以哈希格式存储的密码。 |
| RequiresQuestionAndAnswer | 指定用户是否需要提供密码问题和答案来修改密码。此属性的默认值是 `false`。 |
| RequiresUniqueEmail | 指示 `ASP.NET` 应用程序的用户电子邮件地址是否需要唯一。 此属性的默认值是 `false`。 |

以下代码说明了使用上述属性配置 `SqlMembershipProvider`：

```xml
<configuration>
  <connectionStrings>
    <add name="SqlServices" connectionString="Data Source=localhost;Integrated Security=SSPI;Initial Catalog=aspnetdb;" />
  </connectionStrings>
  <system.web>
    <authentication mode="Forms">
      <forms loginUrl="login.aspx" name=".ASPXFORMSAUTH" />
```

</authentication>

<authorization>

    <deny users="?" />

</authorization>

<membership defaultProvider="SqlProvider" userIsOnlineTimeWindow="15">

    <providers>

        <add

            name="SqlProvider"

            type="System.Web.Security.SqlMembershipProvider"

            connectionStringName="SqlServices"

            applicationName="MyApplication"

            enablePasswordRetrieval="false"

            enablePasswordReset="true"

            requiresQuestionAndAnswer="true"

            requiresUniqueEmail="false"

            passwordFormat="Hashed"

            maxInvalidPasswordAttempts="5"

            passwordAttemptWindow="10" />

    </providers>

</membership>

</system.web>

</configuration>
```

## Membership 类

`Membership` 类允许你为 `ASP.NET` 应用程序创建用户并管理这些用户。使用 `Membership` 类为 `ASP.NET` 应用程序创建的用户可以作为经过身份验证的用户访问该 `ASP.NET` 应用程序。`Membership` 类的层次结构如下：

`System.Object`

`System.Web.Security.Membership`

表 36.21 列出了 `Membership` 类的值得注意的方法：

| 方法 | 说明 |
|---|---|
| `CreateUser()` | 为 `ASP.NET` 应用程序创建新用户。 |
| `DeleteUser()` | 删除指定用户名的用户。如果成功删除用户，则此方法返回 true；如果要删除的用户名不存在，则返回 false。 |

| `FindUsersByName()` | 返回用户名与传递给方法的用户名的任何部分匹配的用户。 |

## 即时解决方案

### 确定代码是否可验证为类型安全

正如你在本章的“深入探讨”部分所学到的，可能有一些代码无法通过验证过程。这可能是由于验证算法或所使用的语言编译器的限制。例如，`.NET Framework` 提供的 `Visual C++` 编译器无法生成可验证为类型安全的代码。另一方面，`C#` 编译器能够生成可验证为类型安全的代码。让我们看看使用 `Visual C++` 和 `C#` 开发的应用程序如何通过 `PEVerify` 工具进行验证。为此，让我们用 `C#` 创建一个名为 `CSharpTestApp` 的控制台应用程序，并将其存储在名为 `PEVerifyApps`（在 `CD-ROM` 上）的文件夹中。要创建 `CSharpTestApp` 应用程序，请执行以下步骤：

- 1. 通过选择“开始”→“所有程序”→`Microsoft Visual Studio 2010`→`Microsoft Visual Studio 2010` 打开 `Visual Studio 2010` IDE。
- 2. 选择“文件”→“新建”→“项目”，这将显示“新建项目”对话框。在“新建项目”对话框中，在“项目类型”窗格中选择 `Visual C#` 选项，在“模板”窗格中选择“控制台应用程序”选项。此外，将应用程序名称指定为 `CSharpTestApp`，将位置指定为 `PEVerifyApps` 文件夹，然后单击“确定”按钮。随即创建 `CSharpTestApp` 应用程序。
- 3. 打开 `CSharpTestApp` 中的 `Program.cs` 文件，并添加一个名为 `SimpleClass` 的自定义类的代码。`CSharpTestApp` 应用程序中 `SimpleClass` 类的代码见清单 36.1：

#### 清单 36.1：在 CSharpTestApp 应用程序中定义 SimpleClass 类

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;

namespace CSharpTestApp
{
    class Program
    {
        static void Main(string[] args)
        {
            SimpleClass simpleObject = new SimpleClass();
            simpleObject.simpleMethod();
        }
    }

    class SimpleClass
    {
        public void simpleMethod()
        {
            Console.WriteLine("A simple method");
        }
    }
}
```

- 4. 编译该应用程序。
- 5. 使用 `VC++` 创建一个名为 `VCTestApp` 的 `CLR` 控制台应用程序。
- 6. 在“解决方案资源管理器”中，展开“源文件”，然后双击 `VCTestApp.cpp` 文件将其打开。在 `VCTestApp.cpp` 文件中，定义一个名为 `SimpleClass` 的类，如清单 36.2 所示：

#### 清单 36.2：在 VCTestApp.cpp 文件中定义 SimpleClass 类

```cpp
// This is the main DLL file.
#include "stdafx.h"
using namespace System;

public class SimpleClass
{
public:
void simpleMethod()
{
    Console::WriteLine("A simple method");
}
};

int main(array<System::String ^> ^args)
{
    SimpleClass simpleObject;
    simpleObject.simpleMethod();

正如你在清单 36.1 和清单 36.2 中看到的，两个应用程序都包含相同的类和相同的功能。但是，当使用 `PEVerify` 工具验证时，这两个应用程序会给出不同的结果。

- 7. 编译 `VCTestApp` 应用程序。
- 8. 通过选择“开始”→“所有程序”→`Microsoft Visual Studio 2010`→`Visual Studio Tools`→`Visual Studio 2010` 命令提示符打开 `Visual Studio 2010` 命令提示符。现在，在命令提示符中转到 `CSharpTestApp.exe` 的位置（在本例中为 `PEVerifyApps\CSharpTestApp\CSharpTestApp\bin\Debug`），然后键入以下命令：

`peverify csharpTestApp.exe /md /il`

该命令的输出为：

```

Copyright (c) Microsoft Corporation. All rights reserved.

```

正如你在输出中看到的，`CSharpTestApp` 应用程序的元数据和 `MSIL` 代码已通过 `PEVerify` 工具执行的验证。这意味着 `CSharpTestApp` 具有可验证为类型安全的代码。

现在让我们看看 `VCTestApp` 应用程序测试会发生什么。在导航到 `VCTestApp` 应用程序的位置后，在 `Visual Studio 2010` 命令提示符中输入以下命令：

`peverify VCTestApp.exe /md /il`

Unverifiable assembly 'c:\users\umer\Desktop\Chapter 36\PEVerifyApps\VCTestApp\Debug\VCTestApp.exe' failed policy check.

请注意，这里只显示了 `VCTestApp` 应用程序验证输出的一小部分。正如你在输出中看到的，`VCTestApp` 未通过 `PEVerify` 工具执行的验证，因此不具有可验证为类型安全的代码。元数据验证和 `MSIL` 代码验证中都有大量错误。以 `[MD]` 开头的错误对应于元数据中的错误，而以 `[IL]` 开头的错误对应于 `MSIL` 代码。请注意，如果你没有指定 `peverify` 命令的 `/il` 开关，则仅验证元数据，并且如果元数据中有任何错误，则仅报告这些错误。此外，如果元数据中有错误，则不验证 `MSIL` 代码。例如，如果你在 `Visual Studio 2010` 命令提示符中键入以下命令：

`peverify VCTestApp.exe /md`

# 使用基于角色的安全性来验证和授权用户

如今，大多数现代操作系统都自带自己的安全系统，允许你验证用户。在许多情况下，底层操作系统的安全系统已足以满足你的 `.NET` 应用程序的安全需求。然而，在某些情况下，该安全系统可能无法为你的应用程序提供所需的安全级别。在这种情况下，你可以采用基于角色的安全性，为你的应用程序提供额外的安全保障。通过基于角色的安全性，你不仅可以保护整个应用程序，还可以保护应用程序中的各个类和方法。
