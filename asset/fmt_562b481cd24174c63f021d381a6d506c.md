
`NSMapTable`类型是`NSDictionary`的通用形式，可以将任何指针大小的类型作为键和值。通过垃圾回收，你还可以使用该类来存储与强或弱对象指针的映射。这对于像`NSNotificationCenter`这样的东西有用，这样对象在注册接收通知时仍然可以被收集，并在发生这种情况时自动从通知中心中移除。

本节开头的示例展示了 ARC 和 GC 模式之间的重要区别。如果你在启用垃圾回收的情况下编译并运行此示例，你可能会看到它打印出一个对象地址。这是因为垃圾回收器在扫描栈时仍然会看到过时的临时变量。

相比之下，这在 ARC 模式下将始终打印 0。与 GC 不同，ARC 是完全确定的。将 nil 赋值给强指针会减少对象的引用计数并触发释放。弱指针在释放开始之前就会被置零，并保证在到达`fprintf()`时其值为 0。

## 分配可扫描的内存

```
id *buffer = NSAAllocateCollectable(
  10 * sizeof(id),
  NSScannedOption);
```

源自：`gc.m`

如果你使用`malloc()`分配内存，它对垃圾回收器是不可见的。如果你想要实现诸如包含对象的 C 数组，这就是一个问题。我们已经看过了这种问题的一种解决方案。你可以对正要存储的对象调用`CFRetain`，对旧值调用`CFRlease()`，然后将它们交换。

这并不理想，尽管它行得通。另一种选择是从垃圾回收器处分配区域内存。`NSAAllocateCollectable()`函数类似于`malloc()`，但有两个重要的区别。

首先，它返回的内存会被垃圾回收。没有对应的`NSFreeCollectable()`函数。当指向`buffer`的最后一个指针消失时，`buffer`就会被收集。

**注意：** Apple 收集器不支持内部引用（interior references），因此你必须确保保留一个指向区域起始位置的指针。指向`buffer`中间某个指针不会阻止它被释放。

第二个区别是，该函数的第二个参数定义了你想要的内存类型。如果你将将`buffer`用于存储 C 类型，只需在此传递 0 即可。如果你传递`NSScannedOption`，返回的`buffer`将被扫描作为对象指针的可能位置，以及由`NSAllocateCollectable()`返回的其他内存区域的指针。

## Objective-C 模式

每种编程语言都鼓励一套不同的设计模式。理解整个 Foundation 框架中使用的常用模式，会让理解整个框架以及编写 Objective-C 代码变得简单得多。

本章概述了 Objective-C 中一些最常见的模式。如果你想阅读更多内容，可以在 Erik M. Buck 和 Donald A. Yacktman 编写的《Cocoa Design Patterns》（Addison-Wesley, 2009）中找到更详尽的概述。

## 支持两阶段创建

```
NSMutableString *buffer =
  [[MutableString alloc] init];
NSMutableArray *array =
  [[NSMutableArray alloc]
    initWithObject: buffer];
```

源自：`allocInit.m`

你可能已经见过的模式之一是两阶段创建模式。在传统的、NeXT 出现之前的 Objective-C 中，你通过向类发送`+new`消息来创建对象。当你实现一个新类时，你会重写`+new`来调用父类的实现，然后执行该类的初始化。

NeXT 改变了这一点，将对象创建和对象初始化分为两个不同的方法。`+new`方法仍然有效，但现在它会向类发送`+alloc`消息，向返回的对象发送`-init`消息。

`+alloc`方法本身默认调用`+allocZone:`。它接受一个`NSZone`作为参数。这是一个封装了分配区域的不透明类型。这在 NeXT 系统上被非常频繁使用，以有效地利用这些机器配备的少量内存。它在 OS X 上运行并不理想，而且并不是所有的类都支持它，因此在许多现代 Objective-C 代码中是一个遗留特性。

当你创建一个新类时，重写`-init`方法，或者提供一个新的指定的初始化方法。

**注意：** 你仍然可以在 GCC 中发现一些旧式创建方法的证据。当`+new`用于创建对象时，在类方法中访问实例变量。GCC 中有一些代码支持这种做法。这种功能在很久以前就被弃用了，所以现在当你尝试这样做时会收到警告。

重写`+alloc`非常罕见。偶尔，人们这样做是为了实现类池或强制单例，但这并不寻常。如果你正在实现一个单例类，可能会重写`+alloc`以返回一个已存在的实例。我们将在本章后续部分讨论。

## 拷贝对象

```
@interface Pair : NSObject <NSCopying>
@property (nonatomic, retain) id first, second;
@end
@implementation Pair
  @synthesize first, second;
  (id)copyWithZone:(NSZone*)aZone
  {
    Pair *new = [self-isa allocWithZone:aZone];
    new->first = first;
    new->second = second;
    return new;
  }
@end
```

源自：`copy.m`

Foundation 框架包含一个名为`CopyObject()`的函数。你可能会逻辑上地认为它会拷贝一个对象，你几乎是对的。它创建一个与原始对象相同类的新对象，然后使用类似`memcpy()`的方法拷贝实例变量。

这对于那些仅具有原始 C 类型作为实例变量的对象有效，但对于其他对象则没那么好。对象指针在拷贝时需要发送`-retain`消息。C 指针可能需要对其进行其他处理，特别是当它们是从其他库返回的不透明类型时。

在没有关于对象之间确切关系信息的情况下，拷贝函数无法自动创建真正的副本。某些对象甚至不应该支持拷贝。例如，你期望一个封装了 socket 的对象的拷贝语义是什么？你会希望得到两个封装了同一个 socket 的对象吗？

真正知道如何创建对象副本的只有对象本身。如果该对象实现了`NSCopying`协议，你可以向它发送一个`-copyWithZone:`消息来获取副本。该方法接受一个`NSZone`作为参数。大多数代码并不会理会`NSZone`。`NSObject`提供了一个`-copy`方法，它只是用默认区域作为参数调用`-copyWithZone:`。尽管你可能总是调用`-copy`，但你应该实现`-copyWithZone:`。

该方法通常从通过向接收者的`isa`指针发送一个`+allocWithZone:`消息开始，这会创建一个新实例。然后它可能会调用一个初始化方法，或者可能自己填充实例变量。

**注意：** 如果你继承自实现了`NSCopying`协议的父类，那么在你的`-copyWithZone:`实现中，你应该向`super`发送`-copyWithZone:`消息，然后只拷贝子类添加的实例变量。

由`-copy`（或`-copyWithZone:`）返回的对象应该被视为与`+alloc`（或`+allocWithZone:`）返回的对象相同。它的初始引用计数为一，所以你必须记住在某处向它发送`-release`或`-autorelease`消息，以避免内存泄漏。

## 对象归档

```
55 void roundTripWithArchiver(id object, Class coder
56      Class decoder)
57 {
58  NSData *data = [coder

67 string]

69}
```

来自：`archive.m`

通常，你需要程序状态的某些部分比单次调用更持久化。你可以像我们在第 7 章所示的那样，在属性列表中存储一些纯数据对象类型，但存储任意对象呢？

你可以以某种自定义（或公共）格式写数据，然后从这些数据重新创建对象。然而，仅仅为了让几个对象持久化就定义新的文件格式，比大多数程序员愿意付出的精力要多得多。

幸运的是，Foundation 通过`NSCoding`协议提供了答案。它定义了两个方法：`-initWithCoder`和`-encodeCoder:`：许多标准类都实现了这个协议，你自己实现它也相对容易。

作为参数传递给这些方法的对象是一个 coder。这是一个封装了某些数据表示的类。在旧的系统上，这通常是`NSArchiver`，但在较新的系统上，它通常是`NSKeyedArchiver`。旧的`NSArchiver`接口仅允许你写入流（带类型的）值。然而，键归档（Keyed archives）支持更像字典的东西。它们允许你存储键值对然后以不同的顺序读回它们。

支持归档有两个部分。你的对象必须能够将自己写到归档文件中，并且必须能够将自己读回来。在`-encodeCoder:`方法中，你必须将对象的所有状态写入 coder 中。

这并不意味着对象的所有实例变量。某些对象的实例变量仅用于缓存可以从其他地方重构的信息。通常，在唤醒（awake）后重构这些信息比存储它们要好。

```
- (void)encodeWithCoder:(NSCoder*)aCoder {
    if ([aCoder allowsKeyedCoding]) {
        [aCoder encodeInt:integer
forKey: @"integer"];
        [aCoder encodeObject:string
forKey: @"string"];
    }
    else {
        [aCoder encodeValueOfObjType:@encode(int)
at: &integer];
        [aCoder encodeObject:string];
    }
}
```

来自：`archive.m`

使用 coder 同时支持键归档器和非键归档器是一个好主意。通常，非键归档器用于瞬时编码（例如，通过网络传输），而键编码器用于持久化数据。

键归档器具有更方便的方法来归档原始 C 类型。你可以发送诸如`-encodeInt:forKey:`这样的消息。旧式风格的归档器只有一个方法来存储原始 C 类型，该方法接受 Objective-C 类型编码和指向变量的指针。

相应的加载方法可能会稍微复杂一些。归档器会存储它存储的每个对象的版本。当你更改对象的实例变量布局时，你应该在`+initialize`中通过向自己发送一个`+setVersion:`消息来设置它。

```objc
- (id)initWithCoder:(NSCoder*)aCoder
{
    if ([coder versionForClassName:[self className]] != 0)
    {
        [self release];
        return nil;
    }
    if ([coder allowsKeyedCoding])
    {
        integer = [coder decodeIntForKey:@"integer"];
        string = [coder decodeObjectForKey:@"string"];
    }
    else
    {
        [coder decodeValueOfObjCType:@encode(int) at: &integer];
        string = [coder decodeObject];
    }
    string = [string retain];
    return self;
}
```

来自：`archive.m`

`-initWithCoder:`方法可能需要从旧版本加载归档。如果父类遵循`NSCoding`协议，那么在你的`-initWithCoder:`实现中，你应该向`super`发送`-copyWithZone:`消息，然后只拷贝子类添加的实例变量。

如果父类有你希望持久化的状态，那么你负责归档这些状态以及子类的实例变量。记住调用父类的这些方法也很重要。

## 创建指定初始化方法

```objc
(id)initWithName:(NSString*)aSel arguments:(NSArray*)args {
    if (nil == (self = [super init])) {
        return nil;
    }
    selector = [aSel copy];
    arguments = [args mutableCopy];
    return self;
}
(id)initWithName:(NSString*)aSel {
    return [self initWithName:aSel arguments:nil];
}
(id)init {
    return [self initWithName:nil];
}
```

来自：`designatedInit.m`

我们为止看到的大多数类都是使用`-init`方法初始化的。该方法是`NSObject`的指定初始化方法。

### 创建指定初始化方法

如果你继承自`NSObject`，你通常会重写这个方法。当创建一个新的`NSObject`子类时，它的所有实例变量都被设置为零。你的初始化方法可能会将它们中的某些设置为其他值，并获取对象所需的任何资源。

**注意：** `NSObject`的`-init`方法什么都不做，它只是返回`self`。这意味着在`NSObject`的直接子类中很容易避免向父类发送`-init`消息。这通常被认为是一种坏习惯，因为`NSObject`的分类可能会将此方法替换为实际执行的方法。

并不是所有类都保留`-init`作为指定初始化方法。根据约定，参数最多的初始化方法是指定初始化方法。所有其他初始化方法都会调用它。

这种方法使得子类化变得容易得多。许多类提供了许多初始化便利方法。如果你在每个子类中都重写这些方法，你会产生很多没有价值的代码。

如果父类使用指定初始化方法模式，你只需要重写一个初始化方法。本节中的示例来自 LanguageKit 中的`LKMessageSend`类。这是一个表示消息发送操作的抽象语法树节点。父类的指定初始化方法是`-init`，因此该类从指定初始化方法调用它。该类重写了`-init`，但重写版本调用了该类的指定初始化方法。

如果你子类该类，你只需要重写`-initWithName:arguments:`方法，并且只有当你添加了需要初始化的实例变量时才需要这样做。向你的类发送`-init`消息的人将得到一个初始化的实例。

## 强制单例模式

```
implementation Singleton
static Singleton *sharedInstance;
+ (void)initialize {
  if ([Singleton class] == self) {
    sharedInstance = [self new];
  }
}
+ (Singleton*)sharedInstance {
  return sharedInstance;
}
+ (id)allocWithZone:(NSZone*)aZone {
  if (sharedInstance &&
    [Singleton class] == self) {
    [NSException raise:NSGenericException format:@@@"May not create more instance of singleton."];];
  }
  return [super allocWithZone:aZone];
}
```

源自 `singleton.m`

本节开头的示例是一个骨架类，它只允许创建自身的单个实例。这遵循了在响应 `+sharedInstance` 消息时返回单例实例的惯例。许多单例类会在该消息名称中使用类名来代替 Instance。

例如，在 AppKit 应用程序中获取共享应用程序对象，你将向 `NSApplication` 发送 `+sharedApplication` 消息。该类是单例的一个特例，因为它将其共享实例存储在全局变量 `NSApp` 中。如果应用程序已经启动，你可以直接使用该变量，从而避免发送获取应用程序对象的消息。

单例最常见的错误是在创建过程中引入竞态条件。这个特定的单例将自身的实例存储在一个私有变量中。在 `+sharedInstance` 方法中创建它是有很有吸引力的。这对于单线程应用程序运行良好，但对于多线程应用程序呢？

如果你同时从两个线程发送 `+sharedInstance` 消息，会发生什么？两者都可能测试变量，发现它尚未被创建，然后创建它。为了解决这个问题，你可以使用锁。

一个更简单的解决方案是在 `+initialize` 方法中创建实例。该方法在第一次向该类发送消息时由运行时调用。运行时的责任确保在其他线程向该类投递任何消息之前，该方法已经完成执行。¹¹
