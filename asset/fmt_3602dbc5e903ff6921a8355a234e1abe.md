
这段代码与优化后的 MSVC 和 GCC 生成的代码相同。显然，LLVM 使用相同的算法来生成常数。

细心的读者可能会问，正如我们所看到的，在 ARM 模式下 `MOV` 是如何向寄存器写入 32 位值的呢？这本是不可能的。但正如我们看到的，每个寄存器占用了 8 个字节而不是标准的 4 个字节，实际上这里有两个指令。

第一条指令将 `0xE3E9` 加载到寄存器的低 16 位，第二条指令是 `MOV`，它将 `0x38E3` 加载到寄存器的高 16 位。IDA 可以识别这种序列，并为了紧凑性将它们简化为单个伪指令。

`SMMUL`（符号最高位乘法）指令对数字进行乘法，将其视为符号数，并将结果的高 32 位保留在 R0 寄存器中，丢弃低 32 位结果。

`MOV R1,R0,ASR#1` 是算术右移一位。

`ADD R0, R1,LSR#31` 是 `R0 = R1 + R0 >> 31`。

在 ARM 模式下，没有独立的移位指令。相反，像 `MOV`、`ADD`、`SUB`、`LSRB` 这样的指令带有后缀，说明第二个操作数是否需要移位、移位方式以及数值。ASR 代表*算术右移*（Arithmetic Shift Right），LSR 代表*逻辑右移*（Logical Shift Right）。


在这里我们看到了一个新的指令：`BREAK`。它会抛出一个异常。

在这种情况下，如果除数为 0 则会抛出异常（传统方法无法除以零）。但 GCC 可能没有做好优化工作，没有发现 `$V0` 永远不会为 0。所以检查被留在了这里。如果 `$V0` 以某种方式为 0，将执行 `BREAK`，向操作系统报告异常。否则，执行 `MFLO`，它从 `LO` 寄存器中获取除法结果并将其复制到 `$V0`。

顺便提一下，正如我们所知，`MUL` 指令将结果的高 32 位留在 `HI` 寄存器中，低 32 位留在 `LO` 寄存器中。`DIV` 将结果留在 `LO` 寄存器中，余数留在 `HI` 寄存器中。如果我们将语句改为 `a % 9`，则将使用 `MFHI` 指令代替 `MFLO`。

## 3.13.1 简单示例

这是读取以 ASCII 编码表示的数字的最简单方法。它不容易出错：数字以外的字符都会导致错误的结果。

```c
#include <stdio.h>

int my_atoi(char *s)
{
    int rt=0;
    while (*s)
    {
        rt=rt*10 + (*s-'0');
        s++;
    }
    return rt;
}

int main()
{
    printf("%d\n", my_atoi("1234"));
    printf("%d\n", my_atoi("1234567890"));
}
```

所以算法是从左到右读取数字。字符 "0" 到 "9" 在 ASCII 表中是连续的。
