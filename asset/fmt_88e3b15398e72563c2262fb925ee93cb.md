
您已经在前几章中学习了 .NET 中的应用程序在称为 `CLR` 的硬件和软件抽象层上运行。为了执行应用程序，`CLR` 必须提供有关要执行的应用程序的一些基本信息。此信息由 .NET 程序集以元数据的形式提供给它。程序集的概念经常与命名空间的概念混淆；然而，程序集与命名空间完全不同。命名空间在源代码中导入；而程序集在部署应用程序时由编译器开关引用。一个程序集可以包含多个命名空间。

程序集的基本组件如下：

- 程序集清单
- `MSIL` 源代码
- 类型元数据
- 资源

让我们现在详细讨论这些组件。

## 程序集清单

## MSIL 源代码

在编译程序集时，编译器将源代码翻译成 `MSIL`。这是因为 `MSIL` 是一组与平台和 CPU 无关的指令，可以在支持 .NET Framework 的任何环境中执行。`MSIL` 包含加载、存储、初始化对象以及调用方法的信息，以及执行各种操作（如算术和逻辑操作、控制流、直接内存访问和异常处理）的指令。一旦源代码被执行，实时（`JIT`）编译器就会将 `MSIL` 转换为 CPU 特定的代码。

## 类型元数据

类型元数据描述了存储在程序集中的类型的格式。它还包含有关程序集引用的外部类型的信息。执行代码后，`CLR` 将此元数据加载到内存中并引用它以检索有关源代码的类、成员和继承的信息。

## 资源

.NET Framework 本地化模型由一个包含大量嵌入式资源的主程序集组成，例如应用程序图标、图像文件、声音剪辑和字符串表。由于主程序集包含嵌入式资源，如果在本地化卫星程序集中找不到资源，`ResourceManager` 类将以分层方式回退到主程序集中的资源。.Net Framework 还支持仅包含本地化资源的卫星程序集。卫星程序集在您希望根据特定文化为国际软件开发分区资源时很有用。

## 程序集类型

根据其位置和对客户端的可访问性，程序集可以大致分为共享或私有。存储在单台机器上的共享程序集的单个副本可以被多个应用程序使用。共享程序集不会部署在正在使用它的应用程序的目录中；相反，它部署在全局程序集缓存（`GAC`）中，`GAC` 是程序集的存储库。您也可以使程序集为私有。这意味着复制到应用程序目录中的程序集只能被指定的应用程序访问，而其他应用程序无法使用同一程序集。换句话说，如果只有少数应用程序需要使用您的库程序集，您可以将它们放在相关应用程序的目录中，而不是放在 `GAC` 中。由于私有程序集独立工作，因此与共享程序集相比，它们更容易管理和维护。私有程序集不需要强名称，并且可以在不担心影响其他应用程序的情况下安装和卸载。

## 程序集签名

在 .NET Framework 3.5 中，有两种方法可以签署程序集——使用强名称和使用 `SignTool.exe` 文件，也称为 `Sign Tool`。当您使用强名称签署程序集时，会将公钥加密添加到包含程序集清单的文件中。使用强名称签署程序集可为程序集提供身份，并验证程序集名称是否唯一。另一方面，使用 `Sign Tool` 签署程序集可为程序集提供强名称和数字签名。`Sign Tool` 要求发布者向第三方机构展示其身份并获取证书。然后将此证书嵌入到管理员用来确定是否信任代码真实性的文件中。使用 `Sign Tool` 签署的程序集通过数字签名和证书保证真实性和完整性。此外，`Sign Tool` 还执行各种功能，例如哈希验证、强名称和签名，以确保程序集未被篡改。

`Sign Tool` 提供了一个命令行工具，用于对文件进行数字签名并验证文件中的签名。您可以在命令提示符下使用以下命令签署程序集：

```
signtool [command] [options] [file_name]
```

`Sign Tool` 命令的参数描述如下：

- `command` – 提供一个命令标志，用于指定要对文件执行的操作，例如 `catdb`、`sign`、`signwizard`、`timestamp` 和 `verify`
- `options` – 提供一个选项标志，用于修改命令标志，例如 `catdb` 选项（`/d`、`/g`、`/u`）、`sign` 选项（`/a`、`/c`、`/d`、`/f`）、`timestamp` 选项（`/t`）、`verify` 选项（`/a`、`/ad`、`/r`、`/o`）以及全局选项（`/q`、`/v`）
- `file_name` – 提供要签名的文件的位置

#### 注意

> Windows NT、Windows Me、Windows 95 和 Windows 98 不支持 `Sign Tool`。

## 强名称

要理解强命名程序集的概念，你应该具备扎实的公钥加密知识。那么，让我们先通过一个例子来讨论公钥加密。想象一下，你有一对密钥，其中一把密钥锁上的东西只能用另一把密钥打开，反之亦然。两把密钥上都刻有你的名字。再想象一下，你的朋友也有一对类似的密钥，上面刻着他的名字。假设你们俩各自只复制了每对密钥中的一把，并互相交换。现在，如果你用他给你的那把密钥的副本锁住一条消息发送给你的朋友，除了他之外没有其他人能解开它，因为只有他拥有这对密钥中的解锁密钥。

在前面的例子中，被复制和分发的密钥称为公钥；而由自己妥善保管、不让他人知道的密钥则称为私钥。在这种锁定/解锁密钥对的安排下交换信息有两个目的——首先，它可以防止任何人窃听你的消息；其次，它让接收者确信该消息是由经过身份验证的一方发送的。

当你创建强名称密钥对文件时，`sn.exe` 实用工具会将唯一的公钥-私钥对写入生成的文件中。在 `AssemblyInfo.cs` 文件中提及该密钥文件，编译器会通过创建属于该程序集的所有文件的哈希来锁定程序集，防止其被进一步更改。然后编译器使用私钥对哈希进行签名。此私钥不会写入程序集，而只保存在密钥文件中。可以使用公钥对其进行验证，公钥会写入程序集，并且任何引用该程序集的应用程序都可以提取它。该公钥的初始部分（称为令牌）会写入引用它的客户端的程序集清单中。要对程序集进行任何更改，你需要提及包含私钥的密钥对文件，以便编译器能够更新哈希并再次签名。因此，你需要保护密钥对文件免受未经授权的访问。

强名称由以下组件组成：

- **简单名称** – 提供一个指定程序集名称的文本字符串。
- **公钥令牌** – 提供程序集的公钥值，并使用 `AssemblyKeyFile` 属性进行分配。
- **版本号** – 提供程序集的主版本号和次版本号，包括修订号和内部版本号。它使用 `AssemblyVersion` 属性进行分配。
- **区域性信息** – 提供有关区域性或语言的信息，用于本地化。你可以使用 `AssemblyCulture` 属性来分配程序集的区域性。
- **数字签名** – 使用程序集内容的哈希和私钥创建。

`GAC` 对其安装的所有程序集执行完整性检查。在将程序集放入 `GAC` 之前，你需要对程序集进行强命名。如果有未经授权的用户试图访问你的程序集，`GAC` 将检测到这种未经授权的访问，并且在缺少密钥对文件的情况下，不允许该用户更新哈希。

## 延迟签名

延迟签名是一种在程序集仍处于开发阶段时对其进行部分签名的技术。延迟签名可防止未经授权的用户篡改程序集。延迟签名的主要目的是保护和控制程序集的私钥，并且仅在开发过程中使用它。当你必须将程序集提供给其他内部开发人员或其他公司的开发人员以进行进一步增强时，此技术非常有用。这样，其他开发人员在没有密钥对文件的情况下将无法更改你的程序集。在这种情况下，开发人员可以使用延迟签名来更改程序集并对其进行测试。

## 程序集信息文件

你已经了解了程序集的清单，它是任何程序集最重要的组件。现在让我们看看清单从哪里获取大部分信息。每个使用 Visual C# 创建的项目都有一个 `AssemblyInfo.cs` 文件，其中包含大量配置属性和其他信息，例如公司名称、版本、商标信息和程序集名称。程序集信息文件使用这些配置属性为程序集分配强名称密钥并指定其他信息，例如公司名称、版本和程序集名称。
