
# 多线程约束编程：模型与方法

像 ILOG 这样的管理模型为执行基于应用程序的并行化提供了有效手段。然而，管理模型在实现并发执行方面引发了若干疑虑。这些问题源于线程与管理器之间建立的关系类型。存在两种可能性：

- 不同的线程共享一个公共管理器。
- 不同的线程使用不同的管理器。

为多个线程使用一个管理器会带来许多困难。这些困难源于一个管理器一次只能处理一个问题这一事实。这意味着尽管线程可以并发地共享管理器，但如果它们这样做，它们就无法并发地处理不同的子问题。此外，如果线程共享同一个管理器，它们无法并发地处理同一个问题：如果它们这样做，每个线程的操作都会覆盖另一个（因为线程共享相同的内存空间）。然而，为了保证数据完整性而所需的额外同步开销超过了并行化带来的性能收益。因此，为了从并行化中获得显著性能收益，并发执行的线程应该使用不同的管理器。然而，使用不同的管理器也会引发其自身的问题。这些问题源于不同的管理器不共享 CP 数据。那么，为了让管理器处理同一个问题，包括变量和目标在内的数据必须为每个管理器进行复制。实际上，这种复制允许每个管理器都拥有一个原始问题表述的副本。为了从并行化中获得性能收益，必须对每个管理器的问题副本进行修改，使得每个管理器包含原始问题的一个不同子问题。这允许线程使用不同的管理器，每个管理器对应一个不同的子问题。因此，每个线程将有不同的任务要执行，应用程序可能会从并行化中获得性能收益。

## 3.4 划分

划分 CP 问题通常有两种通用方法：基于约束的划分和基于变量的划分。

### 基于约束的划分

基于约束的划分通过约束划分问题来创建子问题。这可以通过将一个约束划分为两个或多个不相交的子集来实现。这些新子集可以分配给不同的管理器，使得每个管理器都有自己不相交的子集，从而创建两个或多个子问题。这在示例 3.1 中所示。

**示例 3.1** 我们给出两个线程场景，每个线程都有自己的管理器，决策变量 $x, y$ 和 $z$ 的域为 $\{0,...,120\}$ 并满足以下约束：

```
x + y = 120
```
(3.1)

```
y - z = 100
```
(3.2)

(3.3) $(x = 100 \text{ AND } y \ge 5) \text{ OR } (y \le 100 \text{ AND } x < 25)$

我们可以将约束 3.3 划分为两个不相交的子集，使得每个线程的管理器并将约束 3.4 添加到一个线程的管理器中，将约束 3.5 添加到另一个线程的管理器中。

(3.4) $(x = 100 \text{ AND } y \ge 5)$

(3.5) $(y \le 100 \text{ AND } x < 25)$

现在使用两个管理器将问题公式化为两个子问题。现在，如果每个子问题由不同的线程并行执行，就可以获得性能收益。

基于约束的划分并不总是如示例所示那样容易工作。大多数问题表述更为复杂，且通常没有具有明显不同属性的约束。这使得约束的划分变得不明显。

### 基于变量的划分

基于变量的划分通过决策变量划分问题来创建子问题。这可以通过几种方法实现。一种方法是将决策变量的域划分为不相交的子域。随后，可以给不同的管理器分配决策变量的不相交子域，从而创建子问题。在决策变量较小（例如布尔决策变量）的情况下，可以使用交替方法进行划分，例如显式设置变量。这些变量可以从原始问题表述中移除，并作为常量赋予不同的管理器。这在示例 3.2 中所示。

**示例 3.2** 我们给出两个线程场景，每个线程都有自己的管理器，决策变量 $x, y$ 和 $z$ 的域为 $[0,1]$ 以及一组未公开的发布约束。我们可以移除原始决策变量之一（例如 $x$），并为每个管理器创建两个常量。这两个常量可以是一个线程管理器的 `XM1=1` 和另一个线程管理器的 `XM2=0`。然后管理器可以使用各自的常量来代替原始决策变量 $x$。这使用两个线程创建了不相交的子问题，这些子问题最终可以并行运行。

基于变量划分的一个问题是应该划分哪个变量。如果错误地选择决策变量进行划分，那么来自并行性的加速效果可能微乎其微。在大多数情况下，最佳选择取决于划分及其实现方式。几种通用策略建议：

- 选择共享许多约束的变量。
- 选择具有较大域的变量。
- 选择具有较小域的变量。
- 选择对目标函数影响变量。

## 3.5 基本方法

我们现在讨论一种基于线程的回溯方法。这种方法建立在之前章节的基础上，并利用内置搜索。然而，在这里我们应用动态负载均衡方案。

该过程从创建一个线程开始。线程包含 CP 问题表述，即决策变量、约束和目标。线程的任务是使用管理器的内置搜索来解决问题。然而，在搜索的任何时候，如果达到了活动线程限制或界变量数量足够，将会创建一个线程。在这种情况下，将创建一个界变量并将域划分为子域。它将使用子域创建新线程并传递状态信息（见 3.7.2 节）。新创建的线程将应用状态信息并执行内置搜索。上述方法应用于新创建的线程，当它完成搜索时将终止。

## 3.6 优化回溯

在 CSOP 的情况下，可以对基本模型进行改进以提高性能。可能性包括实现分支边界法、迭代深度搜索或二分法。在这些情况下，可以使用存储在共享内存中的全局最优来帮助消除可能导致更好解的路径。例如，我们描述多线程回溯分支边界。

理想情况下，假设这是一个最小化问题。算法从将全局最优初始化为问题的界开始。在搜索的任何时候，如果出现局部最优，子问题的界大于全局最优，会导致管理器失败并回溯。此外，如果线程在任何时间找到比全局最优更好的解，它可以更新全局最优。所有线程使用最优界进行剪枝。

## 3.7 非回溯模型

尽管基本多线程回溯模型提供了实现并行的方法，但它可能并不适用于所有问题。由于不同的问题可能从不同的技术中获益，因此，应该寻找替代方案。然而，CP 研究社区主要关注基于回溯或可以用回溯模拟的搜索。这可能是因为使用非回溯方法需要程序员离开管理器的内置搜索功能。这把搜索管理的负担放在了程序员身上。在这种情况下，CP 工具主要作为传播引擎，程序员必须执行表示节点、创建节点以及遍历节点树的任务。接下来的章节将讨论这些问题以及创建非回溯搜索的基础。

### 3.7.1 节点表示

在经典回溯案例中，程序员并不关心节点的表示或存储。这是因为在管理模型中，表示和存储节点是管理器的任务。在这种情况下，一个管理器使用时间回溯来生成新节点，通过对当前节点赋值到新节点和撤销用于回溯到之前的节点。虽然这种模型非常高效，但它极大地限制了可以执行的搜索策略类型。这是因为管理器控制着问题的状态。因此，在任何一个时刻，一个管理器只允许一个节点的并发。因此，只有基于回溯的搜索是可用的；非回溯搜索（如最佳优先搜索）要求节点在队列中并发存在。我们可以通过使用不同的节点表示方法来克服这一局限性。

实现节点并发存在的一种方法是使用外部（对于求解引擎而言）的数据结构来存储状态信息，即**外部节点表示**。它将仅包含与给定问题状态相关的数据。例如，在具有二进制变量和整数目标函数的简单 CSOP 案例中，节点可以是一个由两个整数和一个整数数组组成的数据结构，用于存储目标函数的最小值和最大值，并表示决策变量的当前状态。下面使用 C++ 语法所示。

```cpp
class node {
public:
  int minObjective;
  int maxObjective;
  int decisionVariableStatus [NUMOFVARS];
};
```

由于这种表示是求解器外部的，因此可以实例化多个数据结构的实例来创建多个节点。当需要扩展节点时，我们可以使用一个线程将给定节点的数据拷贝到“宿主”CP 公式中，执行公式引擎，然后将生成的状态信息拷贝到新节点中。虽然外部节点表示实现起来并不难，但持续从 CP 公式中拷贝状态信息可能是低效的。当变量数量很大时，这一点尤为明显。

实现节点并发存在的另一种方法是使用**显式节点表示**。在这种情况下，我们利用内存通过维护相关信息来提高应用性能，这是硬件和软件缓存中的常用做法。对于约束编程，可以通过将节点定义为 CP 公式来实现。在这种情况下，一个节点由一个管理器以及给定问题的决策变量、约束、目标和任务组成。让我们重新考虑上面的示例，一个具有二进制变量和整数目标的 CSOP。下面使用 ILOG Solver 和 C++ 伪代码给出了示例的显式节点表示。

```cpp
class node {
public:
  node();
  IlcManager manager;
  IlcVar objective;
  IlcBoolArray decisionVariables;

  node::node() : manager(IlcNoEdit)
  {
      decisionVariables = IlcBoolArray(manager, NUMOFVARS);
      objective = IlcIntVar(manager, MINOBJ, MAXOBJ);
      manager.setObjMin(objective);
      manager.add(CONSTRAINTS);
      manager.add(GOALS);
  }
};
```

如我们所见，节点是一个显式定义的 CSOP。因此在这种情况下，节点在其自然结构中维护状态信息。这里的好处是，有用信息不需要像外部表示方法那样频繁地重新计算。然而，显式表示的效率低于外部表示，因为在后者只存储了极少的信息，而在这里，存储了整个问题结构。

两种节点表示方法都允许节点与其他节点并发存在。这种并发存在允许使用如最佳优先搜索等替代搜索策略。此外，由于节点是独立的实体，线程可以共享节点。例如，一个线程可以对节点执行部分搜索，然后将该路径传递给另一个线程，由后者继续搜索，以此类推。这创建了更大的灵活性，允许使用许多类型的并行策略。

### 3.7.2 高效的状态存储与检索

将节点作为实体要求程序员负责状态信息的存储和检索。具体来说，为了创建父节点的子节点，程序员必须创建父节点的子问题。这可以通过三个步骤完成：

1. 创建新的 CP 公式。
2. 在新公式中复制父节点的状态。
3. 使用划分从新公式中创建子问题。

创建子节点的第一步是创建初始状态 $CSP_0, \dots, CSP_n$，其中 $n$ 是要生成的节点数量，$CSP_0$ 是原始 CP 公式。如果使用显式节点表示，创建 CSP 实际上涉及为给定问题创建新的 CP 公式，即为每个 CSP 创建一个新的管理器、决策变量、约束和目标。如果使用外部节点表示，则需要“宿主”CP 公式。在这种情况下，我们不需要创建新的问题公式，而是必须确保宿主公式处于初始状态（考虑任何先前的状态）。

为了复制给定的状态 CSP，我们需要复制存储在 CSP 中的相关信息。给定初始状态 $CSP_0$ 和状态 CSP，$CSP_i$ 的相关数据是从 $CSP_0$ 到 $CSP_i$ 发生的变化。这些变化代表了已执行的操作，包括决策变量的域削减和约束的添加。为了复制 CSP 的状态；我们需要复制操作引起的变化。具体来说，如果我们给定初始状态 $CSP_0$ 的副本 $CSP_1, \dots, CSP_n$ 以及一个想要在 $CSP_{01\dots ij}$ 中复制状态的子问题 $CSP_i$，我们必须向 $CSP_{ij}$ 拷贝从 $CSP_0$ 到 $CSP_i$ 发生的所有变化。这可以通过重新计算利用约束传播的不动点语义来实现。

在某些情况下，从 $CSP_0$ 到 $CSP_i$ 的变化是具有副作用的操作引起的，仅拷贝操作的结果是不够的。操作具有副作用这一事实要求必须复制它们。如果为了作为节点生成的一部分添加新约束，就属于这种情况。在这种情况下，我们将新约束拷贝到 $CSP_{01\dots ij}$，然后对每个 $CSP_i$ 进行传播。注意，拷贝约束的顺序无关。约束传播的不动点语义保证了决策变量的域总是以相同的方式被削减。因此，将新约束拷贝到 $CSP_{01\dots ij}$ 将产生与 $CSP_i$ 相同的不动点。

状态拷贝后，$CSP_{01\dots ij}$ 代表父节点 $CSP_i$ 的功能副本。为了创建 $CSP_i$ 的子问题，我们在 $CSP_{01\dots ij}$ 上使用基于变量的划分。具体来说，我们从 $CSP_i$ 中选择一个未绑定的决策变量，并使用基于变量的划分分配子域的该变量传递给 $CSP_0, \dots, CSP_m$。随后，我们传播这些结果，从而创建 $CSP_i$ 的节点（子问题）。需要注意的是，在实践中，为了性能考虑，我们会一直等待到划分阶段才执行传播引擎。也就是说，我们不会在将父节点的状态复制到其子节点后立即执行传播引擎。相反，我们会等待问题被划分后再执行传播引擎。因此，传播只执行一次。

如果我们使用显式节点表示，就可以提高子问题生成的性能。这是因为通过显式节点表示，父节点可以转换为其子节点之一。在理论上，在一个节点被用于生成其子节点后，如果不再需要被考虑，就可以将其删除。使用显式节点表示时，父节点在其自然结构中仍然包含有用信息。通过额外的约束或赋值，父节点可以轻松地转换为其子节点。这节省了在回溯搜索中生成子问题所需的计算时间。此外，在分支因子较小的应用中（例如 0-1 问题），只需要一个新节点。因此，复制操作仅需创建一个子节点即可。

# 多线程编程：混合方法

## 4. 带回溯搜索的多线程最佳优先搜索

在许多问题中，全局优化具有吸引力。带回溯搜索的多线程最佳优先搜索（MT-FWBS）是解决此类问题的混合方法。具体而言，该算法使用线程执行并行带回溯搜索的最佳优先搜索。最佳特征背后的思想是扩展最可能导致最优解的节点。然而，这需要使用队列来存储节点，从而产生了相当大的局限性。MT-FWBS 通过使用回溯来控制队列的大小来考虑内存。具体来说，当队列增长到一定大小时，节点不再以最佳优先的方式扩展。相反，它们通过回溯进行扩展。随后，当队列大小减小时，MT-FWBS 会恢复到最佳优先搜索。这种设计的用处是，可以在控制搜索内存需求的同时，扩展许多最佳节点。

### 4.1 实现

MT-FWBS 使用一个用堆实现的并发优先级队列来存储节点。

通常情况下，节点的排列顺序取决于目标是最小化函数还是最大化函数。为了方便理解，我们假设问题是一个最小化问题。在这种情况下，节点根据给定的启发式评估函数按升序排列。使用队列存储节点需要节点的并发性。第 3.7.1 节提供了两种方法。然而，通过实验，我们发现使用显式节点表示可以获得 MT-FWBS 的最佳性能。我们将这种成功归功于 MT-FWBS 的两个关键因素。首先，全局优化需要大量的计算能力和效率，因此，创建和复制节点的执行时间必须降到最低。显然，在这方面，显式节点表示更好。其次，MT-FWBS 结合了回溯来控制优先级队列的大小。

因此，节点使用更多内存并不是问题。因此，通过使用更多内存来产生更快速结果的权衡对于 MT-FWBS 来说是理想的。

为了简单起见，我们首先讨论作为单线程应用程序的搜索。算法首先将根节点放入优先级队列中，然后创建一个线程。节点扩展的方法和对搜索的控制取决于队列的大小。如果队列的大小在给定限制内，线程以广度优先的方式扩展队列，创建节点的子节点。如果这些新创建的节点是可行的且不违反任何边界，它们会被插入优先级队列中。然而，如果队列的大小超过了给定限制，线程将不会通过正常手段扩展节点。相反，线程将使用时间回溯来完全扩展队列。一旦完全扩展并更新了边界（如果需要），就会减小队列的大小。队列不再被考虑为可控的大小，同时确保任何最佳节点都会被扩展。该过程在线程终止后结束。当队列为空或队列上的节点下界大于或等于当前最佳解时，线程终止。

要并行执行该算法，需要多个线程。动态线程创建方案可以很容易地用于此目的。并行版本的启动方式与顺序版本相同，只有一个线程。然而，在扩展队列期间，如果并发执行的线程数少于活动限制（见 3.2 节），线程将创建一个新线程，并使用基于变量的划分为其分配一半子节点的扩展任务。这对于两种节点扩展方法都适用。线程然后以相同的方式继续，从队列中移除最佳节点并扩展到队列的大小。此外，所有线程在功能上是等价的，因此当并发执行的线程数少于活动限制时，它们可以创建其他线程。当队列为空或队列中最佳节点的下界大于或等于当前最佳解时，线程终止。当所有线程都终止时，整个过程结束。

### 4.2 应用

MT-FWBS 适用于具有用于衡量边界的启发式的优化问题，因为这些边界将用于为优先级队列中的节点排序。启发式的准确性将直接影响整个算法的性能。显然，更准确的启发式将提供更好的性能。另一个考虑因素是在分支策略中使用 MT-FWBS，创建较少子节点（层级）的分支策略性能优于创建较多子节点的分支策略。实验表明，创建许多子节点的分支策略会导致优先级队列以更快速度增长。因此，优先级队列会填满，搜索将切换到回溯以减小队列的大小。然而，在队列大小缩小后，它会迅速填满，因为分支策略产生了许多节点。这使得整个搜索更像并行回溯搜索。

## 5.2 应用说明

SCP 采用协作求解器方法进行建模。它使用 `ILOG Solver` 和 `Planner` 实现，并维护了两个相同的公式，但每个公式有其特定的职责。`ILOG Solver` 用于管理局部搜索策略，而 `Planner` 负责管理线性约束。此外，变量边界的通信由引擎自动完成。每个求解器都能帮助对方解决自己的问题。这与 [DB] 中的协作求解器方法相似。

该应用根据 [Beasley1] 中定义的列支配主约规则进行了少量的约化。目标不是获得最大数量的约简，而是快速获得一个更易处理的问题。此外，在预处理期间，通过渐进舍入算法获得了全局上界。关于渐进舍入的更多信息请参阅 [MT2]。

该应用使用 MT-BFWS 实现。优先级队列根据节点的下界排序，下界仅为 `Planner` 给出的线性松弛值。不同的扩展方法使用了两种不同的分支策略。回溯扩展方法使用一个准则来选择最接近 0.50 的变量，即“分数最大的变量”。广度优先扩展使用了两个准则：首先，选择前 10% 分数最大的变量，并从成本最高中选择。如果成本相同，则从两个选中的变量中选择“分数最大的变量”。其他平局随机打破。这种分支策略背后的直觉是，最困难的决策是选择哪些成本较高的列等于 1，因为这些列将更剧烈地增加目标函数。因此，我们应该尝试先做最困难的决策。
