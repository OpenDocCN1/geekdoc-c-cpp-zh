## 27.1 什么是 Unicode?

过去，以美国中心的世界使用 7 位或 8 位编码处理内存中的字符。这意味着我们可以有 128 或 256 个字符（包括不可打印字符）。这很好，但变成了兼容性噩梦。中文有超过 50,000 个字符，而一个字节无法容纳。为了解决这个问题，Unicode 发明了。它扩展到了无限（实际上）。

## 27.2 代码点 (Code Points)

我想在这里讨论两个概念。这很困惑，因为它们都是为了同一件事。但大致定义，*代码点*是指表示字符的数值。每个代码点代表一个唯一的字符。每个字符都有关联的代码点。例如，在 Unicode 中，数值 66 代表“B”，960 代表“n”。其他字符映射使用不同的值，可能让我们忘记它们并专注于 Unicode，未来！所以有一件事：代表每个字符的数字。在 Unicode 中，这些数字从 0 到 100 万。明白了吗？我们要翻转。

## 27.3 编码

## 27.5 C 中的 Unicode

在介绍 C 语言中的编码之前，让我们从代码点的角度谈谈 Unicode。在 C 中有一种方法可以指定 Unicode 字符，这些字符会被编译器翻译成执行字符集。
那么我们怎么做呢？

例如欧元符号，代码点 0x20AC。（我用十六进制写它，因为在 C 中表示它的两种方式都需要十六进制。）我们如何把它放入 C 中呢？

使用 `\u` 将其放入字符串中，例如 `"\u20AC"`（十六进制的大小写不影响）。你必须在 `\u` 后面恰好放四个数字，必要时用前零填充。
这是一个示例：

```c
char *s = "\u20AC1";
```

```c
printf("%s\n", s); // €1.23
```

所以 `\u` 适用于 16 位 Unicode 代码点，但不适用于大于 16 位的？对于那些，我们需要大写字母：
例如：

```c
char *s = "\u0001D4D1";
```

```c
printf("%s\n", s); // 打印数学字母 "B"
```

这与 `\u` 相同，只是用了 32 位而不是 16 位。这些是等价的：
\u03C0
\u000B3C0

再次，这些在编译期间会被翻译成执行字符集。它们代表 Unicode 代码点，而不是任何特定的编码。此外，如果一个 Unicode 代码点在执行字符集中无法表示，编译器可能会纳闷为什么你不能这么做：

```c
char *s = "€1.23";
```

```c
printf("%s\n", s); // €1.23
```

而且如果你使用现代编译器，很可能是可以。编译器会为你将字符集翻译成执行字符集。如果编译器发现任何未包含在其扩展字符集中的字符，它可以自由地报错，而 € 符号显然不在基础字符集中。
注意：如果一个 Unicode 代码点在执行字符集中无法表示，编译器可能会纳闷为什么你不能这样做。

## 27.7.2 宽字符

如果你不是多字节字符，那么你就是宽字符。

宽字符是一个单一值，可以唯一表示当前区域（locale）中的任何字符。它类似于 Unicode 代码点。但它可能不是。或者它可能是。

基本上，多字节字符是字节数组，而宽字符字符串是字符数组。因此，你可以开始以逐字符为单位进行思考，而不是以字节为单位（当字符开始占用不同数量的字节时，后者会变得非常混乱）。

宽字符可以用多种类型表示，但最引人的是 `wchar_t`。它是主要的类型。它就像 `char`，只不过是宽的。

你可能在想它是否为 Unicode，以及 C 如何允许你在编写代码时拥有如此大的灵活性？`wchar_t` 开启了一些大门，因为有一组可以与 `wchar_t` 使用的丰富函数（如获取长度的字符串等），而无需关心编码。

## 27.8 使用宽字符和 wchar_t

该轮到新的一回合了：`wchar_t` 是这种主要的宽字符类型。记得 `char` 只有一个字节吗？而字节可能不足以表示所有可能的字符吗？嗯，这个类型就可以了。

要使用 `wchar_t`，请包含 `<wchar.h>`。

它是多少字节的？这并不完全清楚。它可能是 16 字节，也可能是 32 字节。

但等一下，你说——如果只有 16 字节，还不足以容纳所有的 Unicode 代码点，对吧？你是对的——确实不足。规范并没有要求。它只需要能够表示当前区域中的所有字符。

这在具有 16 位 `wchar_t` 的平台上（如 Windows）可能会导致 Unicode 出现麻烦。但这超出了本指南的范围。

你可以使用 `l` 前缀声明这种类型的字符串或字符：

```c
printf("%ls %lc\n", s, c);
```

更详细地说，宏中的值是一个 `yyym` 年份整数，让你知道可以依赖哪种 Unicode 标准——取决于该日期生效的是哪一个。
