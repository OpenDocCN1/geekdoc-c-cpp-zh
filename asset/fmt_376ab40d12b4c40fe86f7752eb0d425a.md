
当你现在使用带有输入字段的 `Search` 组件时，它将过滤列表。这发生在客户端。但你想在 `onClick()` 处理程序中显式地执行。作为替代方案，你可以对 `onChange()` 函数进行防抖处理并省去按钮，但这会增加复杂性，并不是预期的效果。让我们先保持简单，不使用防抖。

首先，在你的 `Search` 组件中添加一个额外的按钮。按钮必须显式地触发搜索请求。否则，你会在每次输入字段变化时从 Hacker News API 获取数据。但你想在 `onClick()` 处理程序中显式地执行。

其次，在你的 `Search` 组件中引入一个按钮。按钮具有 `type="submit"`，表单使用其 `onSubmit()` 属性传递 `onSubmit()` 方法。你可以复用 `children` 属性，但这次它将用用作按钮的内容。

```javascript
    .catch(error => error);
```

```javascript
setSearchTopStories(result) {
  const { result } = this.state;

    updatedHits = result.hits;
  } else {
    updatedHits = [...result.hits, ...this.state.result.hits];

  this.setState({
    result: {

      hits: updatedHits,
    },
  });
}
```

在每次发起请求之前，必须设置 `searchKey`。它反映了 `searchTerm`。你可能会问：为什么我们起初不直接使用 `searchTerm` 呢？这是继续进行实现之前理解的关键部分。`searchTerm` 是一个变动变量，因为每当你向搜索输入框中输入内容时，它都会改变。然而，最后你需要一个非变动变量。它决定了最近提交给 API 的词，并用于从结果映射中检索正确的结果。它是缓存中当前结果的指针，因此可以在你的 `render()` 方法中显示当前结果。

`src/App.js`

```javascript

  this.setState({ searchKey: searchTerm });
  this.fetchSearchTopStories(searchTerm);
}
```

```javascript
onSearchSubmit(event) {

  this.setState({ searchKey: searchTerm });
  this.fetchSearchTopStories(searchTerm);
  event.preventDefault();
}
```

现在，你必须调整功能，将结果存储到组件内部状态中。它应该根据 `searchKey` 存储每个结果。

`src/App.js`

```javascript
class App extends Component {
  ...
  setSearchTopStories(result) {
    const { hits, page } = result;
    const { searchKey, results } = this.state;

    const oldHits = results && results[searchKey]
      ? results[searchKey].hits
      : [];

    const updatedHits = [
      ...oldHits,
      ...hits
    ];

    this.setState({
      results: {
        ...results,
        [searchKey]: { hits: updatedHits, page }
      }
    });
  }
  ...
}
```

`searchKey` 将用作键在结果映射中保存更新后的 `hits` 和 `page`。首先，你必须从组件状态中获取 `searchKey`。记住 `searchKey` 是在 `componentDidMount()` 和 `onSubmitSubmit()` 中设置的。其次，旧的 `hits` 必须像以前一样与新的 `hits` 合并。但这次旧的 `hits` 是通过 `searchKey` 作为键从结果映射中检索的。第三，可以在状态的结果映射中设置一个新结果。让我们检查 `setState()` get `results` 对象。

### 结果映射结构

`src/App.js`

```javascript
results: {
  ...results,
  [searchKey]: { hits: updatedHits, page }
}
```

下半部分确保通过 `searchKey` 存储更新后的结果。该值是一个包含 `hits` 和 `page` 属性的对象。`searchKey` 是搜索词。你已经学习了 `[searchKey]: ...` 语法。这是一个 ES6 计算属性名语法。它可以帮助你在对象中动态地分配值。

上半部分需要使用扩展运算符展开状态中所有其他按 `searchKey` 分类的结果。否则，你将丢失之前存储的所有结果。

现在，你按搜索存储所有结果。这是启用缓存的第一步。在下一步中，你可以根据非变动的 `searchKey` 从你的结果映射中检索结果。这就是为什么你起初必须引入 `searchKey` 作为非变动变量的原因。否则，当你使用变动的 `searchTerm` 来检索当前结果时，检索将会失效，因为当你使用搜索组件时，这个值可能会改变。

## 错误处理

与 Hacker News API 的交互一切已就绪。你甚至引入了一种优雅的方法来缓存 API 结果，并利用其分页功能从 API 获取无限列表的故事子列表，但缺少了一项。遗憾的是，现在的开发应用程序时经常会忽略：错误处理。在本章节中，你将为应用程序引入一种高效解决方案来处理错误的 API 请求。你已经学习了在 React 中引入错误处理所需的构建块：本地状态和条件渲染。基本上，错误只是 React 中的另一个状态。当发生错误时，你将其存储在本地状态中，并通过组件的条件渲染显示出来。就是。让我们在 App 组件中实现它，因为它是从 Hacker News API 获取数据的组件。首先，你必须在本地状态中引入错误。它被初始化为 null，但在发生错误时将设置为错误对象。

```javascript
class App extends Component {
  constructor(props) {
    super(props);
    this.state = {
      results: null,
      searchKey: '',
      searchTerm: DEFAULT_QUERY,
      error: null,
    };
  }

  ...
}
```

其次，你可以使用原生 fetch 中的 `catch` 块通过 `setState()` 将错误对象存储在本地状态中。每当 API 请求未成功时，`catch` 块就会执行。
