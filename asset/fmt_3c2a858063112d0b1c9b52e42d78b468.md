
二进制数是一组二的幂的和，就像十进制数是十的幂的和一样。对于分数值，小数点后的数字表示二分之一、四分之一、八分之一等。如果你尝试通过相加二的幂来创建一个 `0.1` 的值，你永远不会成功，尽管你会越来越接近。当你尝试通过相加十的幂来创建一个三分时（三十分之一，加上百分分之一，再加上千分之一，等等），也会发生同样的情况。

一种解决方案是使用定点算术。与其存储美元，你可能存储分之百分。这时你必须记住归一化你的值，并且你受到整数类型范围的限制。Objective-C 提供了另一种选项：小数浮点类型。

`NSDecimal` 类型是一个表示小数值的 C 结构体。由于有点奇怪的是，没有用于创建这些类型的 C API。你必须创建一个 `NSNumber` 实例，然后向它发送一个 `-decimalValue` 消息。

然后你有两种进行算术运算的选择。`NSNumber` 实例是不可变的。你可以根据算术结果创建新实例——例如，向其中发送 `decimalNumberByAdding:` 消息。

或者，你可以使用 C API，它可以直接修改结构体的值。如果你只执行一次算术操作并将结果存储在对象中，第一种方案更简单。如果你正在执行多个步骤，那么使用 C API 会更快。因为它们修改了结构体，所以你不需要为每个中间步骤创建一个新对象。

**注意：** C11 标准包含了小数类型，某些编译器作为扩展支持这些类型。`NSDecimal` 类型与这些不兼容。在大多数平台上，这并不重要。如果你目标是像 IBM 的 POWER6 这种具有小数算术硬件的设备，那么直接使用小数类型更好。

这两者都不是特别快。小数表示为数字数组，在两个数字归一化后，对它们进行成对操作。你可以预期获得与软件浮点实现类似的性能——可能稍差一点，因为 `NSDecimal` 没有被广泛使用，因此它不是许多优化的重点。

`NSNumber` 是 `NSNumber` 的子类，因此我们在下一节中查看的所有将 `NSNumber` 转换为字符串的方法都能按预期工作。你也可以使用访问数字对象上的标准方法将它们转换为 C 原始类型，但这些方法可能会截断或近似小数值。

## 字符串与数字之间的转换

```
int answer = [@"42" intValue];
NSString *answerString = [NSString stringWithFormat:@"%d", answer];
NSNumber *boxedAnswer = [NSNumber numberWithInt:answer];
XCTAssert([answerString isEqualToString:[boxedAnswer stringValue]], @"两个字符串应该是相同的");
```

来自：`stratum.m`

在数字和字符串之间转换有多种方法。许多表示简单数据的对象都有如 `-intValue` 的方法，用于返回整数表示。`NSString` 有这一系列中的几个方法。如果你有一个包含数值的字符串，你可以向它发送 `-doubleValue`、`-floatValue`、`-intValue` 或 `-longValue` 消息来将其转换为这些类型中的任何一种。在 64 位安全的 Foundation 版本中，你还可以向它发送 `-integerValue` 消息。这将返回 `NSInteger`。

有几种方法反过来，即从整数获取字符串。我们在第 6 章中查看一种：`NSString` 的 `+stringFormat:` 方法可以让你从原始类型构造字符串，就像使用 `sprintf()` 一样。如果你已经有一个 `NSNumber` 实例中的数字，有两种获取字符串的方法，其中一种是另一种封装。`-descriptionWithLocale:` 方法根据指定的区域设置生成字符串。实际上，它本身并不执行翻译。它向新的 `NSString` 发送 `initWithFormat:locale:` 消息。格式字符串取决于数字类型：例如，双精度数字将使用 `%0.16g` 格式字符串。这使用最多 16 位有效数字和所需的指数。

小数点分隔符取决于区域设置。如果你向 `NSNumber` 发送 `-stringValue` 消息，这等同于将 `nil` 作为参数发送 `-descriptionWithLocale:` 消息。这使用规范区域设置，这意味着没有任何本地化，因此结果在任何平台上都是相同的。

## 从字符串读取数字

```
NSScanner *parser = [NSScanner scannerWithString:@"1 plus 2"];

int operands[2];
NSString *operation;

[parser setCharactersToBeSkipped:[CharacterSet whitespaceCharacterSet]];

[parser scanInt:operands[0]];
[parser scanCharactersFromSet:[CharacterSet letterCharacterSet] toString:&operation];
[parser scanInt:operands[1]];
```

来自：`scanner.m`

任何 C 程序员首先学习使用的两个函数是 `printf()` 和 `scanf()`。这两个函数非常非常相似——一个几乎是另一个的反面——它们让你能够构造格式化字符串并从中解析数据。我们已经见过 `NSString` 有一个 `sprintf()` 的粗略物，所以你可以从格式字符串和变量构造字符串，但 Objective-C 的 `sscanf` 等价物是什么？给定字符串如何解析值？答案在于 `NSScanner` 类。这个类是一个非常强大的分词器。你创建一个附加字符串的 `NSScanner` 实例，然后一个接一个从从中扫描值。

你发送给扫描器的消息都具有相同的格式。它们接收一个变量的指针并返回一个 `BOOL`，表示执行是否成功。扫描器在字符串中存储当前的扫描索引，只有在扫描成功时才会将其增加，因此你可以尝试用不同的方式解析后续字符。你还可以通过 `Scanner` 轻松地实现预读和回溯。如果你向它发送一个 `-scanLocation` 消息，它会返回字符串中的当前索引。然后你可以尝试扫描一些内容，遇到错误后，通过发送 `-setScanLocation:` 消息重置旧索引，从而回溯。

`NSScanner` 最强大的方法之一是 `-scanCharactersFromSet:into:`。它从当前扫描点开始读取字符串，直到遇到一个不在指定集合中的字符。正如我们在第 6 章中看到的，你可以使用任何任意字符集构造 `NSCharacterSet` 实例，也可以使用标准集合之一。

本节开头的示例从字符串中读取了一个数字、一个单词，然后是另一个数字。数字是使用内置的 `-scanInt:` 方法读取的，但单词要稍微复杂一些。它使用了 `NSCharacterSet`，在本例中是所有字母的集合。

这并不是示例中使用的唯一 `NSCharacterSet`。该扫描器还配置为跳过空白字符。发送给扫描器的 `setCharactersToBeSkipped:` 消息会告诉它忽略作为参数传递的集合中的任何字符。传递空白字符集会告诉它跳过调用之间发生的任何空白。如果当你发送扫描消息时，扫描器开始读取的位置存在该集合中的字符，它将跳过它们。在解析标记时，它不会跳过这些字符，因此在字符串中放入“1 2”会被读取为两个独立的数字，而不是 12。

# 字符串操作

Objective-C 提供了两种字符串：C 字符串和 Objective-C 字符串（也称为字符串对象）。作为编译器扩展，GCC 也允许你使用 Pascal 字符串，但这些非常罕见，且仅为了与 Pascal 库兼容而支持。

字符串是一种非常原始的数据类型。它是一个字符数组，以 NULL 字节终止。它没有字符编码的概念，可以存储任何不包含零字节的字节序列。UTF-8 专门为为了与 C 字符串配合而设计的：它是一种变宽编码，即使在多字节序列也不使用零字节。

Objective-C 字符串是一种更高层次的抽象。它被视为 UTF-16 字符序列进行访问，但其内部表示是私有的。如果你为 GNU 编译 Objective-C，常量字符串将由具有三个实例变量的类实例表示：`isa` 指针、指向 C 字符串的指针，以及一个包含 C 字符串长度的整数。运行时库会在模块加载时将 `isa` 指针设置为正确的类。

当你访问 Objective-C 字符串中的单个字符时，你使用 `unichar` 类型。这代表单个 UTF-16 字符。请注意，UTF-16 也是一种变长编码，单个 Unicode 字符可能超过一个 UTF-16 字符。更令人复杂的是，如重音之类的组合标记可能意味着使用多个 Unicode 字符来表示单个字形。

## 创建常量字符串

```
const char *cstring = "C string";
NSString *objcstring = @"Objective-C string";
CFNSStringRef cfstring = CFStringCreateWithCString(NULL, "Core Foundation string", kCFStringEncodingASCII);
```

来自：`constantStrings.m`

在 OS X 上，Objective-C 字符串与 Core Foundation `CF` 字符串之间存在无桥接转换（toll-free bridged）。常量 CF 字符串的表示方式与 GNU 运行时 Objective-C 字符串类似，但有几处不同。它们的 `isa` 指针存在 Core foundation 框架中，因此它们工作不需要链接 Objective-C 运行时或 Foundation 框架。它们还有一个 `flags` 字段，允许其内部表示为 UTF-8 或 UTF-16，具体取决于哪种对其内容更有效。

常量 Objective-C 字符串是通过在常量 C 字符串字面量前加上符号（如 "@"）创建的。你也可以在 C 和 Objective-C 代码中通过 `CFSTR` 宏创建常量 Core Foundation 字符串。该宏调用编译器内置函数来生成一个常量字符串对象。

## 比较字符串

```
NSString *twelve = @"12";
NSString *twelveFromInt = [NSString stringWithFormat:@"%d", 12];
NSNumber *numberTwelve = [NSNumber numberWithInt:12];

if ([twelve isEqualToString:twelveFromInt])
    NSLog(@"Both strings are equal");
if (twelve == twelveFromInt)
    NSLog(@"Both strings are identical");
if (twelve == @"12")
    NSLog(@"Constant strings are identical");
if ([twelve isEqual:numberTwelve])
    NSLog(@"String is equal to number");
```

来自：`CompareStrings.m`

比较字符串相等性最简单且直接的方法是 C 比较运算符 `==`。不幸的是，它有时确实有效，这可能导致一些微妙的 bug。它测试的是两个对象是否完全相同，而不是是否相等。它测试的是它们是否是同一个对象，而不是值相相等的对象。比较两个指针比比较两个字符串快得多，甚至比发送消息还要快。在某些情况下，先尝试指针比较可能会更快。指针比较的结果让你知道这两个字符串是相同的，或者它们可能相同。它永远不会告诉你它们绝对是不同的。如果你经常比较相同的字符串，这可以使代码更快，但通常是过早优化的例子。

## 逐个字符处理字符串

```objc
for (NSInteger i=0; i<[aString length]; i++) {
    char c = [aString characterAtIndex:i];
    // Process c.
}
```

来自：`stringIterateSlow.m`

`NSString` 类是一个类簇。它是一个抽象类，当你创建一个它的实例时，你得到的是某个私有子类的实例。任何 `NSString` 子类必须实现两个原始方法：`-length` 和 `-characterAtIndex:`。第一个返回长度，第二个返回字符串中特定索引处的字符。

如果你需要对字符串中的每个字符进行某些操作，可以使用一个简单的循环对其进行迭代，并反复调用此方法。这种方法非常低效，因为每个字符都需要发送一次消息。这比访问 C 字符串中的字符要昂贵得多。这个版本还为每个字符发送一次 `-length` 消息，只有当长度在迭代过程中可能会变化时，才需要这样做。

另一种方法是获取 C 字符串并对其进行处理。例如，你可以向字符串发送 `-UTF8String` 消息，然后处理返回的 C 字符串。尽管这听起来合理，但请记住字符串可能非常大，并且可能不是以 UTF-8 存储的，因此对象可能需要将其内部表示转换为 UTF-8，分配内存进行存储，稍后由自动释放池或垃圾回收器清理这些内存。

访问字符串字符最高效的方法是 `-getCharacters:range:`。Objective-C 中以 `get` 开头的方法通常接收一个指向调用者分配的空间的指针，并返回其中的数据。在这种情况下，第一个参数是一个指向 `unichar` 缓冲区的指针，该缓冲区必须足够大以存储请求数量的字符。

下一个示例使用了这种机制来统计源文件中分号的数量。首先，它将源代码加载到字符串中，然后每次获取十个字符。注意这种双重循环结构。外层循环获取字符块，然后内层循环遍历该块。当你使用快速枚举来遍历集合时，编译器也会生成相同的结构。

这每十个字符需要发送一次消息。你可以通过增加缓冲区的大小，用更多的空间来换取更快的速度。注意，这个缓冲区是分配在栈上的。这种方式很快，但你应该小心确保设置了范围。

```objc
int semicolons = 0;
NSUInteger length = [str length];
NSRange range = { 0, 10 };
while (range.location < length) {
    char buffer[10];
    if (range.location + range.length > length) {
        range.length = length - range.location;
    }
    [str getCharacters: buffer range: range];
    range.location += 10;
    for (unsigned i=0; i<range.length ; i++) {
        char c = buffer[i];
        if (c == ';') {
            semicolons++;
        }
    }
}
printf("Source file contained %d semicolons\n", semicolons);
```

来自：`StringIterate.m`

否则，你可能会为你的应用程序引入一些安全漏洞。记住，字符串对象隐藏了它们的编码。无论字符串内部如何存储，这段代码都能工作。如果它是 7 位 ASCII 或 UTF-8，将大多数字符转换为 UTF-16 会非常快。如果是像 Mac Roman 之编码，可能需要稍微一点时间，但仍然很快。

## 转换字符串编码

```objc
NSString *str =
[NSString stringWithWithUTF8String:
"some text in a C string"];
const char *utf16 =
[str cStringUsingEncoding:
UTF16StringEncoding];
const char *utf32 =
[str cStringUsingEncoding:
UTF32StringEncoding];
const char *macRoman =
[str cStringUsingEncoding:
NSMacRomanStringEncoding];
```

来自：`encodings.m`

在 OpenStep 中，`NSString` 上最常用的两个方法是 `-cString` 和 `+stringWithCString::`。它们在 C 字符串和 Objective-C 字符串之间进行转换。这些方法的问题在于 C 字符串是不感知编码的。

C 字符串是一个字节数组。你可以在其中存储你喜欢的任何类型的字符数据。对其进行所有操作都是外部定义的，因此对字符编码的知识是字符串之外的。这与 Objective-C 字符串的工作方式恰相反。

当你将 C 字符串转换为 Objective-C 字符串或反之时，它必须知道 C 字符串的编码是什么。C 标准库函数检查环境变量来确定这应该是什么。遗憾的是，这导致了各种问题。如果你从套接字或文件读取某些数据，然后用这些函数从其构建 Objective-C 字符串，你得到的是用户选择的文本编码，而不是创建文件的人所选择的编码。

这些方法现在已弃用，取而代之的是带有明确编码参数的方法。需要记住的一点是，任何多字节编码的默认值都是大端，这在 Objective-C 流行的 Motorola 68000 系列和 RISC 工作站是有意义的，但在小端 x86 处理器上就不那么合理了。
