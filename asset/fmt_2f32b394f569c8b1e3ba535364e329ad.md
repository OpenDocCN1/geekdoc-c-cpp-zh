在当前版本的 OS X 中，这种方法将使用 XML 属性列表格式。如你所见，这非常冗长。旧的 OpenStep 属性列表格式对数组使用括号，对字符串使用双引号，因此体积会小不到的一半。将其转换为二进制格式可以将文件大小从 294 字节减少到 82 字节。

对于如此小小的属性列表，这种的减少是无关紧道的。两种格式都可能放进磁盘上的单个分配单元中，因此它们将占据相同的磁盘空间。两者的解析时间都微乎其微。

然而，对于较大的属性列表，情况并非如此。例如，Safari 将你的历史记录存储在二进制属性列表中。目前，我的记录有 15MB。如果我将其转换为 XML 格式，它会变成 34MB。解析开销也会增加，无论是在 CPU 时间还是内存占用方面。

遗憾的是，集合类不会以默认（XML）格式以外的格式写入自身的属性列表版本。相反，你必须使用`NSSerialization`类，我们将在接下来的节中介绍它。

属性列表格式都是分级结构的。它们不支持写入循环数据结构。此示例中的第二个数组包含一个指向自身的指针。将此内容写入属性列表时的行为是未定义的。在 OS X 上，只有递归指针之前的元素会被存储在文件中。其后出现的任何对象都会被忽略。

读取属性列表有两种方法。第一种是使用集合类的方法，正如我们刚刚查看的写入方法的反向操作。这听起来很容易，但存在一些复杂性。最重要的一点是属性列表并没有存储关于可变性的信息。例如，`NSString`和`NSMutableString`以相同的方式存储的。

当你读取属性列表时，你应该得到哪种？如果你向`NSArray`类发送`arrayWithContentsOf:`消息，你会得到一个不可变数组。如果你向`NSMutableArray`发送相同的消息，你会得到一个可变数组。

如果你想读取可变对象，你需要使用`PropertyListSerialization`。该类处理读取和写入属性列表，并比各种集合类提供了更细粒度的控制。

> **注意：** 如果你阅读 Apple 最新文档，你会发现我们使用的方法被标记为弃用。这是因为它在引入 serialization 之前就已经存在。

当你使用该类读取属性列表时，可以将可变选项作为参数传递。三种可能的选项。默认情况下对象是不可变的。本节开始使用的选项走向极端，使所有内容可变。第三种选项介于之间：它使容器可变，但其他对象（字符串、数字等）不可变。当你通过这种方式读取属性列表时，属性列表序列化类会告诉你格式是什么。

在过去的几年里，另一种与旧式 OpenStep 属性列表非常的格式变得流行。*JavaScript 对象表示 (JSON)* 是序列化 JavaScript 对象的子集，它存储数据而不存储代码。

最新版本的 Cocoa 包含了基于 `PropertyListSerialization` 模型的类，用于加载和存储 JSON 数据。这比属性列表编码稍更多的限制。你只能在叶节点中存储数字或字符串，并且所有的集合必须是数组或字典。

通常情况下，你不会在纯 Objective-C 环境的应用程序中使用 JSON。JSON 主要对互操作性非常有用。大多数平台和语言都有可用的库来读写 JSON，它是大多数 Web 应用程序的默认格式。如果你编写了 JSON 数据，网页上的客户端 JavaScript 很容易将其进行转换。反之亦然：你可以在网页上生成 JSON，然后在 Objective-C 代码中使用它。

在这个示例中，我们对 JSON 进行了格式化打印。这主要用于调试。它会自动对输出进行缩进以提高可读性。这会多消耗一点 CPU 并可能占用更多的空间，因此如果数据要跨网络传输并被另一个程序使用，这是一个坏主意；但如果数据将由手动编辑，这就是一个好主意。

用户默认设置系统是属性列表最大的用户之一。如果你查看 `~/Library/Preferences` 目录，你会看到很多属性列表文件。这些文件存储了当前用户的偏好设置。在 `/Library/Preferences` 中有一个对应的全局目录。

默认系统被暴露为一个单一字典，并带有一些便利方法。通常，你可以假装用户默认对象确实是一个持久化字典。

**注意：** 默认系统与 Windows 注册表相当，但有几个重要的不同。两者都支持多层级键（用户、系统和网络），但默认系统向程序员隐藏了这一切。尽管两者看起来像树形结构，但默认系统是一个单一数据库，它为每个域在单独的文件中存储数据。这使得使用第三方工具修改默认设置变得简单，并意味着它的扩展性更好，因为你永远不需要一次向内存中读取这些文件中的一两个。缺点是对默认设置的操作不是事务性的。同时从两个程序修改同一个域是未定义的。

与字典不同，默认对象具有一些便利方法来访问非对象类型并对对象类型进行类型检查。在当前示例中，我们向它发送了一个 `-stringForKey:` 消息。它封装了 `-objectForKey` 值：一个方法，但它确保了返回值是一个字符串。

还有其他便利方法，例如 `-floatForKey:` 和 `-setFloat:ForKey:`，它们接收原始 C 类型，并在存储到默认设置系统之前将其封装在 `NSNumber` 实例中。

此示例中的代码在结束时向向默认对象发送了 `-synchronize` 消息。这通常不是必要的。默认对象会定期与磁盘上的存储进行同步。但在本示例中，我们没有使用运行循环（所以计时器将不起），并且在修改默认设置后立即退出，因此如果没有此操作，我们的更改将永远不会提交到磁盘。

运行此示例，你可以看到初始值是 nil，因为默认设置中没有存储任何内容。作为参数传递给短程序的值被存储在默认设置中，并在下次运行时自动检索。

这还演示了 `NSArgumentDomain` 的使用。默认设置有多个来源，它们按顺序加载并覆盖之前的内容。最后一个、因此也是优先级最高的默认设置是参数。指定 `-example` 命令行选项会将默认设置中的 `@"example"` 键设置为传递的任何任何值。这不会替换持久化值，它只是在特定的运行中覆盖它。

## 与环境交互

Objective-C 通常用于类 UNIX 平台，并从那里继承了“环境”的概念。这包括了工作目录、环境变量等概念。

在传统的 Objective-C 环境中，你被期望以从 C 程序中完全相同的方式获取这些值。通过 OpenStep，Sun 和 NeXT 引入了 `NSTProcessInfo` 类，它提供了更高层次的抽象。

此部分动机之一是，OpenStep 程序预计将运行在 OPENSTEP、Solaris 和 Windows NT 上。这些系统在环境概念上都有细微差别，因此需要一些抽象来隐藏这些差异。
