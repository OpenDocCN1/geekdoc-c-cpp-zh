## In Depth

In the previous versions of .NET Framework, Microsoft used numerous technologies, such as ASP.NET Web service (which has `.ASMx` as file extension), Web Service Enhancements (WSE), and .NET Remoting, to build distributed applications. Windows Communication Foundation (WCF) technology is a successor of these technologies, as it brings together the functionalities of all these technologies under a unified programming model; thereby, simplifying the process of developing a distributed application. WCF provides an application programming interface in the .NET Framework to develop distributed service-oriented applications, also known as WCF services. It implements various Web services standards such as addressing, reliable messaging, and security to build secure and reliable services. The advantage of WCF over the previous technologies is that it provides a common runtime environment for the services; thereby, providing interoperability between services.

A WCF service is made up of three parts: the service, one or more endpoints, and a hosting environment. A service is a class written in a .NET compliant language, for instance `C#`, and contains some methods that are exposed through the WCF service. A service may have one or more endpoints that enable communication from the service to a client. Finally, a hosting environment is used to host or contain the WCF service.

In this chapter, you learn about the new features of WCF 4.0, such as routing service, default configuration, discovery behavior, improved Representational State Transfer (REST) service, and Windows Workflow Foundation (WF) and WCF integration. Next, you learn about instancing model of WCF services, which includes per-call, per-session, sharable, and singleton instancing services. You also learn about the WCF architecture. Moreover, you learn about WCF endpoints. Let’s start by learning about WCF.

## What is New in WCF 4.0?

WCF 4.0 has introduced various new features to increase the productivity of developers working with WCF services. These new features of WCF allow you to implement more sophisticated service-oriented patterns in building smarter and more resilient services. For example, in WCF 4.0, you do not need to manually configure the endpoints, behaviors, and other settings; these are automatically configured by WCF. The new features of WCF 4.0 are listed as follows:

- The routing service feature
- Default configuration
- Support for discovery behaviors
- Improved REST service development
- Support for the integration of WCF with WF

Let’s discuss these features in detail, one by one.

### The Routing Service Feature

A routing service acts as a broker or gateway to the services and can be implemented as a centralized security boundary in applications so that all the incoming messages can pass through it. The purpose of the routing service is to handle the messages over the WCF-supported protocol. WCF 4.0 provides the `RoutingService` class to implement routing services in applications. The `RoutingService` class receives incoming messages and sends them to the appropriate downstream after determining the target service to be used for sending messages. It determines the target service by evaluating each incoming message.

### Default Configuration

In the previous versions of WCF, you had to configure the endpoints, behaviors, and other settings of WCF to use WCF services. Consequently, the previous versions of WCF required adequate knowledge of the configuration of WCF to define an endpoint. However, WCF 4.0 automatically adds one or more default endpoints in an application, so that you can use WCF services without any configuration. These configurations are added to the `Web.config` file of the application while creating the WCF service application. You can also change the default configuration in the application according to your requirements.

> NOTE
> Endpoints are used for the communication between a client and a WCF service; while behaviors are used to add custom extensions to services. You learn more about endpoints and behaviors later in this chapter.

### Support for Discovery Behaviors

WS-Discovery is an Organization for the Advancement of Structured Information Standards (OASIS), which is used to dynamically discover the location of the WCF service endpoints by defining SOAP-based protocol. SOAP allows clients to examine the WCF service endpoints based on certain criteria to retrieve a list of the suitable candidates offering WCF services. The client can then select an endpoint from the discovered list and use it as a current runtime location of the WCF service endpoints.

### Improved REST Service Development

WCF 4.0 provides new features for building the RESTful web services (now referred as WCF WebHttp services) using WCF. A RESTful web service is a service based on HTTP protocol and REST principles. The REST principles are defined by three categories with respect to a Web service. As per the REST principles, a service:

- Can be accessed with a simple URI
- Supports MIME types
- Uses different HTTP methods

With the use of MIME types, different data formats, such as JavaScript Object Notation (JSON) and Extensible Markup Langague (XML), can be returned from the WCF service.

The WCF WebHttp service includes the following features:

- Support for automatic help page – Helps a consumer to understand the RESTful web service
- Simplified HyperText Transfer Protocol (HTTP) caching – Allows you to cache the responses of messages from WCF Web HTTP service operations
- Message format selection – Allows services to handle or return the messages in either the XML or JSON format
- REST-friendly exceptions – Transmits HTTP errors back to consumers by using a new class, `WebFaultException<T>`
- New Visual Studio project templates – Allows you to implement new project, control, and tools into your Visual Studio 2010 applications by using Extension Manager.

### Support for the Integration of WCF with WF

WCF 4.0 integrates with WF, which allows you to build distributed service-oriented applications. With the help of this integration, the developers can extend the reach of their workflows by using them with WCF endpoints. This implies that you can create WCF services that can easily transfer and persist data in and out of a workflow.

Now, let’s learn about the instancing model of the WCF services.

## Instancing Model of WCF Services

Every WCF service has an instancing model that controls the number of instances of a WCF service that can run at a time. The instancing model of WCF service contains a set of techniques, which are used to bind messages to a WCF service instance. Instance management is required to develop scalable and consistent service-oriented applications because the applications widely differ in their requirement for scalability, performance, throughput, transactions, and queued calls. The instancing model of WCF services is a server-side implementation model that should not be visible on the client-side. To hide the details of instancing model from client-side, WCF has introduced the concept of behavior, which is a local attribute of a service that does not affect WCF communication pattern.
