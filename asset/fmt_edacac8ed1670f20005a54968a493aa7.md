
如提示所示，我们有几种可以通过`mtx_init()`创建的互斥锁类型。（这些类型中的某些是位或操作的结果，如表所示。）

| 类型 | 描述 |
| --- | --- |
| `mtx_plain` | 普通互斥锁 |
| `mtx_timed` | 支持超时的互斥锁 |
| `mtx_plain|mtx_recursive` | 递归互斥锁 |
| `mtx_timed|mtx_recursive` | 支持超时的递归互斥锁 |

“递归”意味着锁的持有者可以在同一个锁上多次调用`mtx_lock()`。在其他人可以获取互斥锁之前，他们必须进行相同次数的解锁。这可能会在某些情况下简化编码，特别是当你已经持有互斥锁时，调用了一个需要锁定该互斥锁的函数。

而超时机制允许线程尝试获取一段时间的锁，但如果在该时间范围内无法获取，则退出。

对于超时互斥锁，请务必使用`mtx_timed`创建它：

```
mtx_init(&serial_mtx, mtx_timed);
```

并且当你需要它时，必须指定一个解锁的 UTC 时间。

来自`<time.h>`的`times_get()`函数可以提供帮助。它会以`timespec`结构体获取当前的 UTC 时间，这正是我们需要的。事实上，它似乎仅仅是为了这个目的而存在的。

它有两个字段：`tv_sec`是从 epoch 开始的当前时间，`tv_nsec`是纳秒（一秒的十亿）作为“小数”部分。

所以你可以使用当前时间并将其加上以获得一个特定的超时时间。

然后调用`mtx_timedlock()`代替`mtx_lock()`。如果它返回值`thrd_timeout`，则表示超时了。

`struct timespec;`

```
times_get(&timeout, UTC);    // 获取当前时间
timeout.tv_sec += 1;                   // 现在 1 秒后超时
```

```
int result = mtx_timedlock(&serial_mtx, &timeout);

if (result == thrd_timeout) {
    printf("互斥锁锁定超时!\n");
}
```

除此之外，超时锁与普通锁是相同的。

> 你可能本以为它是“从现在开始计时”，但你只是想这么想而已吧，不是吗！

### 39.8 条件变量

条件变量是我们在构建高性能多线程应用程序和组合更复杂的多线程结构所需的最后一块拼图。

条件变量提供了一种方式，让线程进入睡眠，直到另一个线程上的某个事件发生。

换句话说，我们可能有很多线程在等待，但它们必须等待到某个事件为真，否则它们会被告知“请等待”，直到它们收到通知。

这与互斥锁是紧密配合的，因为等待依赖于某些数据的值，而这些数据通常需要由互斥锁来保护。

需要注意的是，从我们的角度来看，条件变量本身并不是任何特定数据的持有者。它是 C 语言用来跟踪特定线程等待/非等待状态的变量。

```c
printf("Thread: is awake\n");

 t = 0;

// 累加所有值
for (int i = 0; i < VALUE_COUNT_MAX; i++)
    t += value[i];

printf("Thread: total is %d\n", t);

// 为主线程重置输入索引
value_count = 0;

mtx_unlock(&value_mtx); // <-- 释放互斥锁
}

return 0;

int main(void)
{
    thrd_t t;

    // 创建新线程
thrd_create(&t, run, NULL);
thrd_detach(&t);

    // 设置互斥锁和条件变量

mtx_init(&value_mtx, mtx_plain);
cnd_init(&value_cnd);

for (;;) {
    int n;
    scanf("%d", &n);

    mtx_lock(&value_mtx); // <-- 加锁互斥锁
    value[value_count++] = n;

    if (value_count == VALUE_COUNT_MAX) {
        printf("Main: signaling thread\n");
cnd_signal(&value_cnd); // <-- 发送条件信号
    }

    mtx_unlock(&value_mtx); // <-- 释放互斥锁
}

// 清理（我知道上面是一个无限循环，但我至少
// 想假装得很有体面）；
mtx_destroy(&value_mtx);
cnd_destroy(&value_cnd);
}
```

#### 39.8.1 条件等待

`cnd_wait()`有一个变体允许你指定超时时间，以便停止等待。

由于子线程必须重新加载互斥锁，这并不意味着你一定会在超时发生的瞬间立即返回；你仍然必须等待其他线程释放互斥锁。

但这意味着你不需要一直等到`cnd_signal()`发生。

要使此功能起生效，请调用`cnd_timed_wait()`而不是`cnd_wait()`。如果它返回值`thrd_timed`，则表示超时了。

时间戳始终是 UTC 时间，而不是从现在开始的时间。坦率说，`<time.h>`中的`timespec_get()`函数似乎是专门为这种情况量身定制的。

```c
struct timeout timeout;
timespec_get(&current_time, TIME_UTC); // 获取当前时间
current_time.tv_sec += 1; // 在现在 1 秒后超时
```

```c
int result = cnd_timed_wait(&condition, &mutex, &timeout);

if (result == thrd_timedout) {
    printf("Condition variable timed out!\n");
}
```

#### 39.8.2 广播：唤醒等待的线程

`cnd_signal()`只唤醒一个线程来继续工作。根据你的逻辑实现，在条件满足后唤醒多个线程来继续执行可能是有意义的。

当然，只有一个线程可以获取互斥锁，但如果你遇到以下情况：

- *新被唤醒的线程负责唤醒下一个线程，而且——虚假唤醒（spurious-wakeup）的循环条件可能会阻止它这样做，那么——*

你将希望唤醒所有线程，以确保至少有一个线程跳出循环并启动下一个线程。

你问如何做到？

只需使用`cnd_broadcast()`代替`cnd_signal()`。用法完全相同，区别在于`cnd_broadcast()`会唤醒所有在条件变量上等待的线程。

### 39.9 运行一次函数

假设你有一个可以被许多线程运行的函数，但你不知道何时运行，而且尝试用逻辑来处理行不通。

有一个绕过这个问题的方法：使用`call_once()`。许多线程可以尝试运行该函数，但只有第一个算数¹²

为了实现这一点，你需要声明一个特殊的标志位变量来跟踪该操作是否已经运行过。你还需要一个包装器来运行该函数，该函数不接受参数也不返回结果。

`once_flag of = ONCE_FLAG_INIT;` // 这样初始化

```c
void run_once_function(void)
{
    printf("I'll only run once!\n");
}

int run(void *arg)
{
    call_once(&of, run_once_function);
    // ...
}
```

在这个示例中，无论有多少个线程到达`run()`函数，`run_once_function()`都只会被调用一次。

因为线程跨 y 进行了同步，因此 thread 1 中在写入 y 之前发生的所有写入在 thread 2 写入 y 之后（while 循环之后）都是可见的。

注意以下几点：

- 1. 没有任何线程在睡眠。同步不是阻塞操作。两个线程都会全速运行直到退出。即使是自旋循环中的那个线程也不会阻塞其他线程运行。

- 2. 同步发生在一个线程读取原子变量而另一个线程写入该变量时。当 thread 2 读取时，thread 1 中之前的所有内存写入（即设置 x）在 thread 2 中都是可见的。

- 3. 注意 x 不是原子的。那是**因为**我们没有在 x 上进行同步，而在 thread 1 中写入时对 y 的同步，意味着 thread 1 中之前的所有写入——包括 x——将对其他线程可见……如果这些线程通过读取 y 来同步的话。

强制同步效率低的，并且可能比使用普通变量慢得多。这就是为什么除非特定应用程序有需要，否则我们不使用原子变量。

## 40.4 获取 (Acquire) 与释放 (Release)

更多术语！现在学习它们是有回报的。

当一个线程读取原子变量时，被称为一次获取（acquire）操作。

当一个线程写入原子变量时，被称为一次释放（release）操作。

这些是什么？让我们将它们与你处理原子变量时熟悉的术语对应起来：

**读 = 加载 (Load)** —— 获取。当你比较原子变量或将其读取到另一个变量时。

**写 = 存储 (Store)** —— 释放。当你向原子变量赋值一个值时。

在使用这些获取/释放语义的原子变量时，C 定义了会发生什么。

获取/释放构成了我们讨论的同步的基础。

当一个线程读取原子变量时，它可以看到另一个线程释放该变量时设置的值。

换句话说：

当一个线程读取原子变量时，可以看到另一个线程写入该变量时设置的值。

同步发生在获取/释放对之间。

更多细节：

对于特定原子变量的读取/获取：

- 另一个线程在写入/存储该原子变量之前发生的所有写入（原子或非原子）现在对当前线程都是可见的。

- 另一个线程对原子变量的新值对当前线程也是可见的。

- 当前线程中任何变量的读取或写入都无法重排到获取操作之前。

- 在代码重排方面，获取是一道单向屏障；当前线程的读取和写入可以从获取之前移动到它之后。但对同步更重要的是，没有任何操作可以从获取之后移动到它之前。

对于特定原子变量的写入/存储/释放：

- 当前线程中在释放操作之前发生的所有写入（原子或非原子）对读取/加载或获取了同一原子变量的其他线程都是可见的。

- 当前线程写入该原子变量的值对其他线程可见的。

- 当前线程中任何变量的读取或写入都无法重排到释放操作之后。

- 在代码重排方面，释放是一道单向屏障；当前线程的读取和写入可以从释放之前移动到它之后。但对同步更重要的是，没有任何操作可以从释放之后移动到它之前。

```
call_once() thrd_create() thrd_join()
mtx_lock() mtx_timedlock()
mtx_timedlock() mtx_trylock()
malloc() calloc()
aligned_alloc() dealloc() realloc()
```

`call_once()`—与针对特定标志的所有后续`call_once()`调用同步。通过这种方式，后续的调用就可以确保，如果另一个线程设置了该标志，你将能够看到它。

`thrd_create()`—与新线程的开始执行同步。新线程可以确保它看到了`thrd_create()`之前父线程对所有共享内存的写入。

`thrd_join()`—当一个线程结束时，它与此操作同步。调用了`thrd_join()`的线程可以确保它看到了最新的线程共享写入。

`mtx_lock()`—对同一互斥锁执行的早先`mtx_unlock()`调用保持同步。这反映了我们已经讨论过的获取-释放（acquire-release）过程。`mtx_unlock()`对互斥变量执行释放（release），任何后续通过`mtx_lock()`执行获取（acquire）的线程都能看到临界区中的共享内存更改。

`mtx_timedlock()`和`mtx_trylock()`—与`mtx_lock()`的同步类似，如果执行成功，早先的`mtx_unlock()`调用将与此调用同步。

**动态内存函数**：如果你分配了内存，它将与该内存之前的释放操作同步。特定内存区域的所有分配和释放都处于一个所有线程都能一致的单一顺序（total order）中。我认为这里的想法是，释放操作将在它选择的区域发生，而我们想要确保随后的分配不会看到未清除的数据。如果有遗漏，请告诉我。
