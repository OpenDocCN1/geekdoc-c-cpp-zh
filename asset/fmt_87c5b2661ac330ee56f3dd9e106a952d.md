
注意，宏本身并没有特定的类型。实际上发生的是，它们被整体替换为它们被 `#define` 定义的任何内容。

你也可以定义一个没有值的宏：

```c
#define EXTRA_HAPPY
```

在这种情况下，宏是存在且已定义的，但被定义为空。因此它在文本中出现的地方会被替换为空。我们稍后会看到它的用途。

按照习惯，宏名称通常使用全大写（ALL_CAPS），尽管这在技术上并不是要求的。

总的来说，这提供了一种定义常量值的方法，这些值实际上是全局的，可以在任何地方使用。即使在常量变量不起作用的地方，例如在 `switch` 分和固定数组长度中。

尽管如此，网上一直争论在一般情况下，带类型的 `const` 变量是否比 `#define` 宏更好。

它还可以用于替换或修改关键字，这是一个对于 `const` 完全陌生的概念，尽管这种做法应该谨慎使用。

## 19.3 条件编译

可以引导预处理器决定是否向编译器呈现某些代码块，或者在编译之前直接将其完全删除。

我们基本上通过将代码封装在条件块中来实现此点，类似于 `if-else` 语句。

### 19.3.1 Defined, #ifdef 和 #endif

首先，让我们尝试根据宏是否被定义来编译代码。

```c
#include <stdio.h>
```

```c
#define EXTRA_HAPPY

int main(void)
{
    #ifdef EXTRA_HAPPY
        printf("Im extra happy!\n");
    #endif

    printf("OK!\n");
}
```

在示例中，我们定义了 `EXTRA_HAPPY`（为空，但它是被定义的），然后在第 8 行我们使用 `#ifdef` 指令检查它是否被定义。随后的代码会被包含，直到 `#endif`。

因为被定义了，代码将被纳入编译，输出将是：

I'm extra happy!

OK!

如果我们注释掉 `#define`，如下：

```c
//define EXTRA_HAPPY
```

那么它就不会被定义，代码也不会被包含。

## 19.4 内置宏

标准定义了许多内置宏，你可以对其进行测试并用于条件编译。让我们在这里来看看这些宏。

### 19.4.1 强制性宏

这些都是定义的：

| 宏 | 描述 |
| --- | --- |
| `__DATE__` | 编译日期——例如你编译此文件时的时间，格式为 M dd yyyy |
| `__TIME__` | 编译时间，格式为 hh:mm:ss |
| `__FILE__` | 包含此文件命名的字符串 |
| `__LINE__` | 该宏所在文件的行号 |
| `__func__` | 该宏所处函数的名称，字符串形式² |
| `__STDC__` | 如果是标准 C 编译器，则定义为 1 |
| `__STDC_HOSTED__` | 如果编译器是托管式实现（hosted implementation）³则为 1，否则为 0 |
| `__STDC_VERSION__` | C 的版本，格式为 yyyymmL 的常量长整型，例如 20171L |

让我们把这些放在一起。

```c
#include <stdio.h>

int main(void)
{}
```

> ²² 这并不是真正的宏——技术上它是一个标识符。它是唯一的预定义标识符，而且感觉非常像宏，所以我把它包含在这里。就像一个反叛者。

> ³ 托管式实现（hosted implementation）基本上意味着你正在运行完整的 C 标准，可能在某种操作系统上。你很可能是这样。如果你在某种嵌入系统的裸机上运行，你可能处于一个独立实现中（standalone implementation）。

```c
printf("This function: %s\n", __func__);
printf("This file: %s\n", __FILE__);
printf("This line: %d\n", __LINE__);
printf("Compiled on: %s %s\n", __DATE__, __TIME__);
printf("C Version: %ld\n", __STDC_VERSION__);
```

在我的系统上的输出是：

- This function: main

This file: foo.c

This line: 7

Compiled on: Nov 23 2020 17:16:27

C Version: 201710

`__FILE__`、`__func__` 和 `__LINE__` 在向开发者报告错误情况时特别有用。`<assert.h>` 中的 `assert(macro)` 使用这些宏来指出代码断言失败的位置。

#### 19.4.1 __STDC_VERSION__

如果你好奇，这里是 C 语言不同版本的版本号：

| 版本 | ISO/IEC 版本 | `__STDC_VERSION__` |
| --- | --- | --- |
| C89 | ISO/IEC 9899:1990 | 未定义 |
| C89 | ISO/IEC 9899/Amd.1:1995 | 19949L |
| C99 | ISO/IEC 9899:1999 | 19990L |
| C11 | ISO/IEC 2011/Amd.1:2012 | 20112L |

该标记最初在 C89 中并不存在。

另外注意，版本号会严格增加，因此你可以始终检查是否“至少是 C99”:

```c
#if __STDC_VERSION__ >= 19990L
```

## 19.5 带参数的宏

宏比简单的替换更强大。尽管你可以将它们设为接收传入的参数。经常出现的问题是该使用宏还是函数。短答案是：使用函数。但你会在野生和标准库中看到很多宏。人们倾向于将它们用于短小的数学运算，以及随平台变化的特性。

### 19.5.1 单参数宏

让我们从一个简单的平方数字的宏开始：

```c
#include <stdio.h>

#define SQR(x) x * x // 不完全对，但听我说

int main(void)
{
    printf("%d\n", SQR(3 + 4));
}
```

它的意思是“每当看到 `SQR` 跟着某个值，就将其替换为该值”。我们在这里犯了一个错误，一个我们需要避免的错误。如果我们想计算 `SQR(3 + 4)` 呢？$(3+4)^2 = 49$，但宏展开的结果是：

```c
printf("%d\n", 3 + 4 * 4);
```

哎！由于乘法的优先级，我们先执行了 $4 \times 3 = 12$，而不是我们想要的。这太常见了，你应该你应该每次都这样做。

修复方法很简单：加一些括号，

```c
#define SQR(x) (x) // 好多了……仍然不够好
```

现在我们的宏展开为：

```c
printf("%d\n", (3 + 4) * (3 + 4)); // 漂亮！
```

但如果附近有比 `(*)` 更更高的运算符，仍然会有一些问题。正确的方法是用额外的括号包裹内容，例如：

```c
#define SQR(x) ((x)) // 太棒了！
```

编写数学宏时养成这种习惯，你就永远不会出错。

### 19.5.2 多参数宏

你可以根据需要无限堆叠这些东西：

```c
#define TRIANGLE(w, h) (0.5 * (w) * (h))
```

让我们使用求根公式为 $x$ 编写一些宏。万一你脑子里没背过它，它说明对于方程：

```
ax^2 + bx + c = 0
```

你可以用求根公式求出 $x$：

```
x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}
```

这太不可思议了。此外，其中的正负号 ($\pm$) 表示实际上有两个解。让我们为这些编写一些宏：

```c
#define QUADP(a, b, c) (((-(b) + sqrt((b) * (b) - 4 * (a) * (c)))) / (2 * (a))
#define QUADM(a, b, c) (((-(b) - sqrt((b) * (b) - 4 * (a) * (c))) / (2 * (a)))
```

这样就解决了。如果该实现支持各种“安全的”替代标准函数，

| 宏 | 描述 |
| --- | --- |
| `_STDC_LIB_EXT_` | 1 如果该实现支持 `Atomic` 或 `<stdatomic.h>` |
| `_STDC_NO_ATOMICS_` | 1 如果该实现不支持 `Atomic` |
| `_STDC_NO_COMPLEX_` | 1 如果该实现不支持复数类型或 `<complex.h>` |
| `_STDC_NO_THREADS_` | 1 如果该实现不支持 `<threads.h>` |
| `_STDC_NO_VLA_` | 1 如果该实现不支持变长数组 |

## 19.6 多行宏

如果用反斜杠（`\`）转义换行符，就可以编写多行的宏。

让我们写一个多行宏，打印从 0 到传入的两个参数乘积的数字。

```c
#include <stdio.h>
```

```c
#define PRINT_NUMS_TO_PRODUCT(a, b) do {
    int product = (a) * (b); \
    for (int i = 0; i < product; i++) { \
        printf("%d\n", i); \
    }
} while(0)
```

```c
int main() {
    PRINT_NUMS_TO_PRODUCT(2, 4); // 输出 0 到 7 的数字
}
```

这里有几点需要注意：

- 最后一行外，每一行的结尾都有转义符，表示宏在继续。
- 内容包裹在一个带有大括号的 `do-while(0)` 循环中。

后一点可能有点奇怪，但它都是为了吸收程序员在宏后面丢掉的结尾分号 `;`。

## 第 19 章. C 预处理器

起初我认为仅仅用大括号就足够了，但如果程序员在宏后面放一个分号，就会出现失效的情况。这里就是这种情况：

### 19.7 示例：一个断言宏

在代码中添加断言是捕获你认为不应该发生的情况的好方法。C 提供了 `assert()` 功能。它检查一个条件，如果为假，程序将崩溃并告诉你断言失败的文件名和行号。

但这还不够完美。

- 1. 首先，你可以为断言指定任何额外的消息。
- 2. 其次，没有一个简单的开关可以关闭所有断言。

我们可以通过宏来解决第一个问题。

基本上，当我有这段代码时：

```c
ASSERT(x < 20, "x must be under the ASSERT");
```

我希望发生这样的事情（假设 `ASSERT()` 在 foo.c 的第 220 行）：

> 正在违反法律……正在违反法律……

```c
if (!(x < 20)) {
    fprintf(stderr, "foo.c:220: assertion x < 20 failed;");
    fprintf(stderr, "x must be under 20\n");
    exit(1);
}
```

我们可以获取 `__FILE__` 宏的文件名。消息已经是一个字符串，包含了 `x < 20`，所以我们必须通过 `#` 来处理它。我们可以通过在行尾使用反斜杠转义来创建一个多行宏。

```c
#define ASSERT(c, m) \
do {
    if ((c)) {\
        fprintf(stderr, "__FILE__:%d: assertion %s: %s\n", \
               __LINE__, #c, m); \
        exit(1); \
    }
} while(0)
```

（`__FILE__` 这样写看起来有点奇怪，但记住它是一个字符串字面量，相邻的字符串字面量会自动拼接。另一方面 `__LINE__` 是一个整数。）

它是有效的！如果我运行这个：

```c
int x = 30;
```

```c
ASSERT(x < 20, "x must be under 20")
```

我得到了这个输出：

```
foo.c:23: assertion x < 20 failed: x must be under 20
```

非常棒！

剩下的就是一种开启和关闭它的方法，我们可以通过条件编译来实现。这里是完整的示例：

```c
#include <stdio.h>
#include <stdlib.h>
```

```c
#define ASSERT_ENABLED
#if ASSERT_ENABLED
#define ASSERT(c, m) \
do {
    if (!(c)) {\
        fprintf(stderr, "__FILE__:%d: assertion %s: %s\n", \
               __LINE__, #c, m); \
        exit(1); \
    }
} while(0)
#else
#define ASSERT(c, m) ((void)0)
#endif

int main() {
    int x = 30;
    ASSERT(x < 20, "x must be under 20");
    return 0;
}
```
