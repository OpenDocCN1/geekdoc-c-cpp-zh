# MUTABLE VS. IMMUTABLE COLLECTION CLASSES

All Objective-C collection classes come in two versions, mutable and immutable. For arrays, these are NSMutableArray and NSArray. The main difference is that you can add and remove items from a mutable array. The content of an immutable array is set when the array is created, and it cannot change.

In general, it is cleaner and safer to pass around immutable copies of your data than to allow direct access to a mutable collection. After all, you don’t want to accidentally change the data out from under yourself.

Now let’s add our properties to the @interface block:

```
```objc
@interface WeightHistory : NSObject {
}

// This is a virtual property.
@property (nonatomic, readonly) NSArray* weights;
@property (nonatomic, assign, readwrite) WeightUnit defaultUnits;
@end
```
```

As the comment indicates, the weights array is a virtual property. Unlike most properties, weights will not simply provide accessors to an instance variable. Instead, the value returned by weights will be dynamically generated during runtime. As we will see, this requires some extra work on our part.

Now let’s add two instance methods to this class. Place these below the @property declarations.

+   - `(void)addWeight:(WeightEntry*)weight;`
+   - `(void)removeWeightAtIndex:(NSUInteger)index;`

This declares a method to add a new WeightEntry and a method to remove any specified weight entry. That’s it, the interface is done, at least for now. We’ll come back and add a few more methods in Chapter 6, when we start saving and loading the model.
