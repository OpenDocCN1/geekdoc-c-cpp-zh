
# CSS and HTML

When HTML was first created

Take the `<strong>` tag, for example. In HTML, this common tag does one and only one thing: It makes text "stronger," usually by making it bolder. However, using CSS, you can "redefine" the `<strong>` tag so that it not only makes text bolder, but also displays in all caps and in a particular font to add more emphasis. You could even make the `<strong>` tag not make text bold.

Although both HTML and CSS have evolved over the years, they have rarely evolved in tandem. Instead, each standard has pretty followed its own path. However, both CSS3 and HTML5 will be hitting primetime over the next few years, creating the new foundation and framework for modern Web sites.

The power of CSS comes from its ability to mix and match rules from different sources to tailor your Web pages' layout to your exact needs. In some ways, it resembles computer programming—which is not too surprising, because a lot of this stuff was created by programmers instead of designers. But once you get the hang of it, "speaking" CSS will become as natural as putting together a sentence.

# Types of CSS Rules

The best thing about cascading style sheets is that they are amazingly simple to set up. They don't require plug-ins or fancy software—just text files with rules in them. A CSS rule defines what the HTML should look like and how it should behave in the browser window.

CSS rules come in three types, each with specific uses:

- *HTML selector*. The text portion of an HTML tag is called the selector. For example, `h1` is the selector for the `<h1>` tag. The HTML selector is used in a CSS rule to redefine how the tag displays. (See "(re)Defining an HTML Tag" in Chapter 3). For example:

```css
h1 { color: red; }
```

will style:

```html
<h1>...</h1>
```

- *Class*. A `class` is a "free agent" rule that can be applied to any HTML tag at your discretion. You can name the class anything you want. Because a class can be applied to multiple HTML tags, it is the most versatile type of selector. (See "Defining Reusable Classes" in Chapter 3). For example:

```css
.myClass { font: bold 1.25em; }
```

will style:

```html
<h1 class="myClass">...</h1>
```

- *ID*. Much like class selectors, ID rules can be applied to any HTML tag. ID selectors should be applied only once to a particular HTML tag on a given page to create an object for use with a JavaScript function. For example:

```css
#myObject1 { position: absolute;
  top: '10px'; }
```

will style:

```html
<h1 id="myObject1"></h1>
```

# What Is the World Wide Web Consortium?

The World Wide Web Consortium (w.w3.org) is an organization that sets many of the standards browser developers eventually use to create their products, including HTML and CSS, with the notable exception of JavaScript.

The W3C comprises more than 400 member organizations around the world. These organizations include vendors of technology products and services, content providers, corporate users, research laboratories, standards bodies, and governments.

According to its Web site, the W3C has four goals:

- *Web for Everyone*. To make the Web accessible to all people by promoting technologies that take into account the vast differences in culture, education, ability, material resources, and physical limitations of us users on all continents.

- *Web on Everything*. To allow all devices easy access to the Web. Although most access is still through desktop or laptop computers, an increasing array of devices can access the Web.

- *Knowledge Base*. To develop an environment that permits each user to make the best use of the resources available on the Web.

- *Trust and Confidence*. To guide the Web's development with careful consideration of the novel legal, commercial, and social issues raised by this technology.

# The Parts of a CSS Rule

```css
selector { property: value; }
```

All rules, regardless of their locations or types, having the structural elements:

- Selectors are the alphanumeric characters that identify a rule. A selector can be an HTML tag selector, a class selector, an ID selector, a universal selector (described in Chapter 3) or a combination of those basic selectors to create context-based styles (discussed in Chapter 4).

- Properties identify what is being defined. Several dozen properties are available; each is responsible for an aspect of the page content's behavior and appearance.

- Values are assigned to a property to define its nature. A value can be a keyword such as "red", a number, or a percentage. The type of value used depends solely on the property to which it is assigned.

After the selector, properties and their values, which together are referred to as a declaration. A single CSS rule can have multiple declarations separated by a semicolon (;).

## Browser CSS extensions

In addition to the specified CSS properties set by the W3C, a browser developer will occasionally introduce browser-specific properties. This is often done for one of two reasons:

- A spec is still under development but the browser wants to start using it.

- The browser developer wants to try a new idea but doesn't want to wait.

The basic syntax of a CSS rule starts with a selector (HTML, Class, or ID). Then add a property, a value, and a semicolon, which together are referred to as a declaration. You can add as many definitions as you need long as they are separated by a semicolon.

Sometimes the exact syntax of the official specification will be slightly different from the "sandbox" version created for a specific browser.

To avoid confusion and ensure forward compatibility of CSS code, each rendering engine has adopted its own prefix to use CSS properties that are unique to that browser. The prefixes for each browser are shown in Table 1.2.

These CSS extensions sometimes overlap and conflict when different browsers promote their own solutions. The good news is that due to the nature of CSS, you can include versions of each the properties for individual browsers, so that the browser will use whichever version it suits

Throughout the book, I include browser extensions, when appropriate, that you can ensure the widest interoperability of your styles.

```css
selector { -moz-property: value;
-webkit-property: value;
-o-property: value;
-ms-property: value;
property: value; }
```

- Browser CSS extensions can all be included as available to ensure that the style is applied if available to a particular browser.

> Although you don't have to include a semicolon with last definition in a list, experience shows that adding this semicolon can prevent future headaches. For example, if you later decide to add a new definition to the rule and forget to put in the required semicolon before the addition, you may cause the rule to fail completely. What's worse, not only will that definition will fail, but all the definitions in the rule won't be used.

> Most browser manufacturers drop an extension of a style within two releases after they adopt the official version. This practice allows designers to catch up before their style sheets stop working.

> Don't confuse the selector of an HTML tag with its attributes. In the following tag, for example, img is the selector, and src is an attribute:

```html
<img src="picture.gif">
```
