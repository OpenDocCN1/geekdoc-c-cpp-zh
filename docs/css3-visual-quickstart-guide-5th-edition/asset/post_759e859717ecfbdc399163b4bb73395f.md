Not all CSS definitions can be applied to all HTML elements. Whether a particular CSS property can be applied (or not) depends on the nature of the element. For the most part, it's fairly obvious when a property can be applied.

For example, you wouldn't expect the text-indent property, which indents the first line of a paragraph, to apply to an inline tag such as `<b>`; in fact, it can't be applied. When you need help in this area, see Appendix A to determine the CSS properties that can be applied to specific HTML elements.

# The Evolution of HTML5

HTML5 is the next step in Web markup and will take over from XHTML. Although XHTML2 was in development for almost eight years, it was laid to rest in 2009 in favor of HTML5.

To understand how this happened, let's take a little trip back to the halcyon days of the Web at the end of the twentieth century—1997, to be precise. It was still a Web 1.0 world, although we didn't yet know to call it that. The dotcom bubble was starting to inflate, and everyone was surfing the Web with Netscape Navigator until the World Wide Web Consortium (W3C) introduced HTML 4.0 (HTML4).

HTML4 was a vast improvement, because for the first time it was created by a standards body that gave everyone a seat at the table and believed that Web pages should display the same across all browsers.

# And then came XHTML

XHTML1 (released in 2001) is a rewriting of HTML 4.0 using XML and was intended to bring the power of XML to Web development. XHTML uses the XML doctype. XHTML employs all the same tags as HTML, but the code will still work with a browser that does not understand XML.

But wait, it was quickly realized that even XHTML1 was not enough to evolve the Web for the twenty-first century, bringing about a golden age of semantic pages. XHTML2 was primarily meant to be a transitional technology to evolve the Web from its relatively static "page" nature into a truly interactive and universal environment. From its very beginning, something went wrong.

# And then was HTML5

In June 2003, HTML5 started life as the Web HyperText Application Group (WHATWG), an organization that was not associated with the W3C. Instead, this independent group, frustrated with the slow pace and direction that XHTML was taking, began working on an alternative standard that would be backward compatible, more suitable for writing applications, and would also address many practical issues.

For several years, both languages were developed simultaneously. But in 2007, seeing that HTML5 was further along than XHTML, the W3C adopted it as the starting point for a new HTML standard, publishing the "First Public Draft" of the specification on January 2008.

# What’s Not in HTML5?

HTML5 includes several changes. But if you want to start using it, you also need to know what is not available. The frame tags–frameset, frame, noframes–have been eliminated, but the iframe is still available. Most presentation tags have been eliminated–as basefont, big, center, font, s, strike, tt, u–and although b (bold) and i (italic) are still included, some debate continues over that decision.

Also, unlike XHTML, stand-alone tags such as <img> and `<br>` will not have to be self-closing. So, rather than using `<br />`, it’s back to just `<br>`. But really, isn’t that a lot simpler?

# What’s New in HTML?

HTML5 makes important structural changes to Web pages. For example, you can specify common elements such as headers, footers, and asides. In addition, HTML5 introduces features natively (that is, features built into the browser) that used to require plug-ins and/or scripting in the form of new elements and APIs:

- The Canvas element allows scriptable bitmap editing.
- Document editing permits users to edit content directly in Web pages.
- Web forms self validate and include more input types.
- Drag-and-drop allows the manipulation of elements without scripting.
- Audio and Videoed media playbacks enable native control of media files without plug-ins.
- New structural elements remove the burden of using <div> tags with classes and IDs to create common elements such as headers and footers.

HTML5 is where Web design and development happens. Many browsers have already started some of its features, even though it’s not a complete standard, yet. That said, one notable (and frequent) support curmudgeon is Internet Explorer. However, Microsoft has pledged to introduce HTML5 support in IE version 9.
