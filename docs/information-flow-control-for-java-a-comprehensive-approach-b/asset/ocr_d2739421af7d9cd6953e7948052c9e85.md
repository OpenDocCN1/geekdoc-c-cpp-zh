Finally blocks are executed in any case, and thus are incorporated into the control flow after all code in the try and catch blocks has been executed. If no appropriate exception handler is present, it is nevertheless before the procedure returns (throwing the exception to the caller) and must therefore be included just before the method's exit node.

Building PDGs without explicit exception handling renders it incomplete for the full Java semantics. In Java, bytecode instruction may throw an implicit exception (subtypes of RuntimeException) in case operands are operands. For example, every bytecode that manipulates objects may throw a NullPointer, those for arrays ArrayOutOfBoundsException. To get a sound analysis, control flow must be taken into account. In each case, each bytecode that throws an implicit exception is preceded by a predicate that checks code's precondition for normal execution, and if it is not satisfied, control flow branches to exception handling code or to code for abnormal termination [CPS99].

An exception without appropriate exception handler is passed to the caller of the causative method. If this caller has an appropriate handler installed at the invocation bytecode, this handler is branched in order to handle the exception; if not, then the caller method terminates abruptly as, "rethrowing" the causing exception. This schema is employed until an appropriate handler is found somewhere in the stack, or else this thread of execution terminates and the causing exception is printed to the user. Again, this is incorporated into the control flow graph by introducing an extra predicate with two successors for each possibly executing call instruction: one-successor models normal termination and one is for abrupt termination of the called method.

In case there multiple catch blocks for one try block, the control flow graph contains a so-called typeswitch statement, which is similar to a traditional switch statement. For each possible catch block with exception type e exists an edge labeled e to the corresponding catch code block.
