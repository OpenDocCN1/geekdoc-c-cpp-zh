## 4.5 分析信息流

非干扰准则阻止非法流，但在实践中人们希望获得关于个体状态的安全级别的更详细信息。因此，信息流控制的理论模型如 Bell-LaPadula [BL96] 或非干扰 [GMS84] 利用安全级别的格 $\mathcal{L} = (\mathcal{L}, \le, \sqcup, \sqcap, T)$，最简单的仅包含两个安全级别 *High* 和 *Low*。程序员需要指定一个格，以及定义某些（或全部）注释的安全级别的注释。在实践中，只有输入和输出通道需要此类注释。

### 4.5.1 基本流方程

对于正确的 IFC，必须计算每个语句的实际安全级别，并且该计算必须尊重程序员指定的级别以及沿程序构造的传播规则。PDG 为基础的 IFC 的巨大优势在于 PDG 已经定义了语句和表达式之间的边，流可能发生在其上；如所述，PDG 节点之间的显式和隐式流是不可能的。因此，只需沿 PDG 边提供传播规则即可。我们从过程内分析开始。

语句的安全级别，即 PDG 节点为 S(x)，其中 $S : N \rightarrow L^5$ 保密性要求信息接收者 $x$ 必须至少具有每个发送者 $y$ 的安全级别 [31.96]。在 PDG 中，其中 $pred$ 和 $succ$ 是由 → 诱导的前驱和后继函数，分别，基本属性很容易表述为

```
$$y \rightarrow x \in G \Rightarrow S(x) \geq S(y) \quad (4.4)$
```

并且由上确界的定义

```
$S(x) \geq \bigsqcup_{y \in pred(x)} S(y) \quad (4.5)$
```

> $^5$记住 $N$ 是 PDG 节点的集合。注意我们的 $S$ 在原始的 Goguen/Meseguer 非干扰定义中称为 *dom*，但我们需要 *dom* 用于偏函数。

该基本约束确保 $S(y) \rightarrow S(x).^6$ 记住保密性和完整性是相互对偶的 [Bib77]，因此完整性的对偶条件为

```
$S(x) \leq \prod_{y \in prod(x)} S(y) \quad (4.6)$
```

在下面，我们集中于保密性，因为所有完整性方程都可以通过对偶性获得。

方程 (4.5) 假设每个语句、节点都有指定的安全级别，这在现实中是不切实际的。在实际应用中，人们希望指定安全级别不是针对所有，而是针对某些选定的语句。^7 提供的 security level 指定语句以提供的 security level 发送信息，即代表输入通道。所需的 security level 只要求具有更小或相等 security level 的输入可以到达该语句，^8 它代表指定 security level 的输出通道。从这些值可以计算实际的安全级别。

提供的 security level 由偏函数 $P : N \rightarrow L$ 定义。所需的 security level 类似地定义为偏函数 $R : N \rightarrow L$。因此，$P(s)$ 指定 $s$ 处的 information 的 security level（也称为 $s$ 的 security level），而 $R(s)$ 指定 information 的最大允许 security level。

节点 $x$ 的实际 security level $S(x)$ 不得大于其前驱的级别，但必须大于其自身提供的 security level。该方程 (4.5) 精炼为

```
$S(x) \geq \begin{cases} P(x) \cup \bigcup_{y \in dom(P)} S(y), & \text{if } x \in dom(P) \ \bigcup_{y \in prod(x)} S(y), & \text{otherwise} \end{cases} \quad (4.7)$
```

注意 $R$ 在此不出现在 $S$ 中。我们需要一个额外的约束来指定 incoming 节点不得超过节点的 required 级别：

```
$$\forall x \in dom(R) : R(x) \geq S(x) \quad (4.8)$
```

我们现在可以正式定义保密性：

**定义 4.1。** *给定程序的 PDG，如果对所有 PD 节点方程 (4.7) 和 (4.8) 都得到满足，则程序保持保密性。*

如前所述，我们正在准备一个机器检查的程序 [qui 定义 4.1 定义了非干扰。暂时，定义 4.1 被视为公理，然而，如上所述，它是基于 PDG 的正确性属性和保密性的经典定义而建立的。
