# 5.3. STATIC PATH CONDITIONS FOR JAVA

```
// pre: B extends InstanceOfExample
public class InstanceOfExample {
    static boolean pred = true;
    public static void main(String[] args) {
        A a = pred ? new A() : new B();
        System.out.println(instanceOf(a));
    }
    public static int instanceOf(A sel) {
        int result = 0;
        if (sel instanceof B) {
            result = 42;
        }
        return result;
    }
}
```

Algorithm 10 presents how path conditions for instanceof are computed; the algorithm is based on the precise instanceof semantics. The differences between equations (5.4)-(5.6) and the algorithm stem from optimizations which are at compile time, the JLS [GJS05]. For example, Γint = (int); the type test is at compile time and no further runtime constraint is required for the test null.

Obviously, the more refined Γτ is determined, the more precise the condition for the instanceof expression becomes. As points-to-points is usually a prerequisite for precise slicing, points-to-points can be leveraged to increase precision of Γτ. The number of possible runtime types reduces to less than or equal to 1, the path condition can be immediately reduced to true if the remaining type is an instance of τ, provided that the expression can never be null or false. As usual, determining Γτ requires whole-program analysis either without reflection, or using conservative approximations (e.g. [LWL05].
