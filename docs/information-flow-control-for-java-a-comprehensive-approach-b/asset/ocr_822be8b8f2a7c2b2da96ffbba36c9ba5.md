# 4.7.3 Confidentiality check with declassification

The original SDG-based confidentiality criterion no longer works with declassification, as information flow with declassification is no longer transitive and slicing is on transitive information flow. Thus $P(x)$ in $BS(a)$ where $P(x) \leq R(a)$ is not necessarily an illegal flow, as $P(x)$ can be declassified under yesterday. Instead, the criterion must be modified as follows:

**Confidentiality Check With Declassification.** For every $x \in dom(R) \setminus D$, compute $S(x)$ by Algorithm 7, and check the following property:

$\forall x \in dom(P) \cap BS(a): P(x) \leq S(x)$

**Theorem 4.6** guarantees that the constraints generated by Algorithm 7 and the $S$ values (being their minimal covert) are correct. Here the criterion is satisfied Definition 4.3 if satisfied. If the criterion is not satisfied, (4.19) is violated and an illegal flow has been detected. As described in section 4.6.1, the S values are computed first, and the criterion (4.21) is checked in a second phase; this allows to generate diagnostics by computing flows.

Let us return to the example in Figures 4.3 and 4.8 and assume $R(14) = public$. As described in section 4.5.3, the analysis reveals an illegal flow $3 \rightarrow$ 14. We introduce a declassification: $14 \in D, R(14) = secret, P(14) = public$ (represented as two colors). Now $S(14) = secret \leq R(14)$, so the confidentiality check will no longer reveal an illegal flow. This might be desirable on the security policy, since only a small amount of information leaks from password checking.
