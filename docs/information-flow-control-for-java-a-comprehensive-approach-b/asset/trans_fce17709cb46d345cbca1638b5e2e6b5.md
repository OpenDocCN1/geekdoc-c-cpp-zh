## 5.4.3 动态路径条件

### 通过动态切分进行细化

在从一个语句构造到另一个语句的路径条件时，所有这些语句之间的路径都通过静态依赖图中的切分来确定。如第 5.2.1 节所述，如果使用动态切分代替，则可以提高对已执行程序的路径条件的准确性。动态依赖图通常只包含实际放置的边，因此这种动态切分会产生这两个语句之间数量更少的路径。

例如，考虑图 1。如果执行跟踪为 1,2,3,4,7,9，则 2 与 9 之间的切分为 2,3,4,7,9。语句 5 在此设置中从未执行，因此可以从动态切分中移除。静态切分则保守地必须添加它。通过动态切分，可以在 2 与 9 之间的路径条件中省略路径 2,3,4,5,7,9 和 2,3,4,5,7,9。

尽管我们的路径条件生成器重用部分信息，因此路径数量减半并不会使路径条件缩短 50%，但此示例也显示了这种细化的影响。

### 通过跟踪值进行细化

为了用运行时信息加强给定的路径条件 PC，对跟踪进行分析以检索变量赋值。由于分析的程序在运行时经历了一系列赋值，所有这些赋值都必须捕获在限制子句 R 中。该子句反过来可用于使路径条件更强。

首先，确定路径条件 PC 与跟踪 T 中使用的变量的交集 V：

```
V = {v | v \in var(T) \intercap var(PC)}
```

对于每个变量 $v$，提取其在跟踪期间携带的值，设 $\beta(v)$ 为 $v$ 所约束的 $w_i$ 的集合：

```
\beta(v) = (v = w_i) \vee (v = w_j) \vee \dots$
```

现在限制子句 R 可以描述为所有值集合的合取：

```
R = \bigwedge_{v_i \in V} \beta(v_i)
```

为了使路径条件 PC 更强，使用第 5.2.1 节的结果并将两个子句合取结合

```
PC' = PC \wedge R
```

得到更强、更精确的路径条件 PC'。

### 动态路径条件的正确性

有时由于“有缺陷的记录器”或为了节省内存，只能获得跟踪的片段。虽然片段跟踪对于动态切片通常无用（参见第 5.4.1 节），但它们仍然对加强路径条件具有有价值的信息。

```
$x = 0 \vee x = 1$$
```

而变量赋值状态实际上是

```
$x = 0 \vee x = 2$$
```

受限路径条件

```
$PC' = (x > 1) \wedge (x = 0 \vee x = 1) \equiv false$$
```

将与实际程序状态（x = 2）相矛盾，然后肯定会排除数据依赖，而实际上可能是可能的。

为了避免不健全的路径条件，保守地假设每个变量都有一个额外的未知值 $\perp$，表示由于某些内存而未被跟踪的发生赋值。这使得路径条件随着跟踪的碎片化而正确受限。对于我们的示例，结果路径条件为

```
$$(x > 1) \wedge (x = 0 \vee x = 1 \vee \perp) \\\equiv (x > 1 \wedge x = \perp) \equiv x > 1$$
```

只有在可以保证跟踪的完整性（至少某些变量，参见第 5.4.1 节）的情况下，才可以放弃这种保守措施（针对这些变量）。

乍一看，使用这种技巧似乎不会获得任何关于动态变量的额外信息。为了显示包含未知值的变量跟踪的优势，考虑图 5.1 的路径 PC(1,5)。使用形成限制子句的片段变量（x = 5 \vee x = \perp$）从 1 到 5 的改进路径条件将为：

```
$PC(1,5) \equiv (n > 0 \vee n > 0) \wedge (x = 5 \vee x = \perp) \wedge (n = 3 \vee n = \perp)$$$
```

很明显，被跟踪的变量 x = 5 和 n = 3 可能会触发从第 1 行到第 5 行的影响。

这个微小的例子表明，虽然限制子句不能用于将路径条件的一个子句求值为 false，但它们可能会揭示触发非法信息流的输入值。

## 5.4.4 相关工作

符号执行是一种用符号而不是参数的具体值执行程序的技术。在执行期间，谓词 Φ（初始为 true）绑定以约束值。当分支被采用时，谓词会更新以反映该分支的条件。由于它表示通过 CFG 的当前路径的条件，因此也常被称为 *路径条件*，因为它表示采用特定路径的条件，它比我们工作中的执行条件更进一步。今天的符号执行系统主要基于定理证明器或模型检查器。基于定理证明器的系统如 ESC/Java [FLL02] 中的系统需要手动注释来生成验证条件，而我们的方法可以完全自动地实现。其他系统依赖于模型检查器 [DRH07]，它们是半自动的但可以处理状态爆炸。大多数符号执行系统仅执行按方法分析，而我们的方法自动生成过程条件。

J 的最新工作使用了路径切片 [JM05] 作为 CFG 的输入，并消除了与目标位置无关的所有操作。结果是目标位置可达性的条件，其不足足以证明路径不可行。该技术不适用于 PD 而仅适用于 CFG。它已被证明对消除模型检查器 Blast 提供的反例有效。对于我们的应用，这种方法似乎没有益处，因为它单独检查每条路径，这为两个语句之间的所有路径产生必要条件并共享公共子集。

参数切片 [FRT95] 允许对程序输入指定约束。返回的系统生成满足这些约束的程序切片。条件程序切片 [CCL08] 是一种类似的技术，它基于输入变量的一阶逻辑公式进行切片。条件切片是在删除语句的同时保持程序行为。两者都与路径条件不同，因为它们不确定输入值而是将其作为输入。相比之下，路径条件提供必须满足的逻辑公式以使信息可行。约束求解器将此条件简化为满足公式的输入值。

本工作中提出的布尔路径以及 [Sne96, RS02, Bob05] 中的布尔路径无法表达时态属性。例如，它们无法表达循环条件必须成立然后不再成立以使循环终止是必要的。布尔条件在分析涉及循环变量的循环和条件时变得保守。Lochbiler 和 Snelting [LS09] 的最新方法将路径条件扩展为时态逻辑以规避这些不精确性。通过模型检查而不是约束求解器创建见证。
