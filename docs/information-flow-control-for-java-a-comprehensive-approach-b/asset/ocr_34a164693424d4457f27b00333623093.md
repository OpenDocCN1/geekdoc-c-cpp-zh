But like these, the programmer needs to annotate all data structures with type parameters when they are to be used in different security policies. # Object-Insensitivity

Similar to contexts, different objects might want to store data with different security labels. However, type systems label each field statically with a single security label. Again, some remedy can be achieved by polymorphism, with the same problems as before. Another way to achieve object-sensitivity is runtime-labels, but these require program instrumentation, which induces an additional execution time and space overhead.

# Differences to Java

Even though Jif compiles down to standard Java (but requires an additional runtime system provided as a ja library), there are differences between Jif and Java. Some of these limitations are standard in any kind of language-based interfaces:

Threads Like most, Jif does not prevent threads from communicating via the timing of modification of shared variables and synchronization. Such channels can only be controlled by possibilistic [SV98] and probabilistic [SS0a,Smi6] IFC. An implementation of a type system for these security policies has been reported. However, our slicing-based IFC can be extended to probabilistic noninterference [GL]. We are currently integrating a checker for this security policy in our system.

Finalizers run in a separate thread in Java and can exploit the shared covert channel. Therefore, Jif does not support finalizers. Most analyses ignore them, as they are rarely used in Java and their execution time is unknown. Java guarantees that execution happens when the garbage collector finds an object not reachable from the active state. There is no guarantee that a finalizer will run at all however, e.g. [LIF03].

Timing channels are extremely hard to counter if an adversary has access to a clock independent from the system. These physical side channels are not covered by language-based information flow control except for Agat's type system [Aga0] and Sabelfeld and Sand's strong security [SS0a].
