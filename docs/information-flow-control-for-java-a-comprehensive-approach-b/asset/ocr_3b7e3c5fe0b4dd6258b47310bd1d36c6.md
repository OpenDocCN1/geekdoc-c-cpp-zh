The threaded control flow graph (TCFG) consists of the ICFGs of each thread that are connected at fork and join nodes, respectively. Note that Krinkle [Kr03b] and Nanda [NR06] require threads to be disjoint, which is in general not the case for Java threads. However, one can always duplicate parts of the graph to achieve disjointness, which will be assumed in the sequel.

A interprocedural realizable path $P = n_1, \dots, n_k$ is an ordered sequence of nodes in the TCFG G that every projection of P to a thread $\theta$, created in $P$ is either empty or corresponds to an interprocedural realizable path in the thread.
The slice of a cSDG w.r.t. $c$, the criterion $p$, depends on $S(p)$, consists of all nodes on $q$ which painfully depends and there exists an interprocedural trace witness $W$ in the TCFG for each such $q$.

```
S(p) = \begin{cases} q = n_1, \dots, n_k, \ q = n_{d_1}, \dots, n_{d_{k-1}}, n_k, p = d_i, i \in \cd, dd, id\}, 1 \le i \le k, \ \text{P is an interprocedural realizable path in G} \ \text{where } n_i \text{ is a node in } P \text{ in the same order as } W \end{cases}
```

Krinkle's algorithm [Kr98] was the first to solve the transparency problem for programs without method calls. The effects of synchronization are ignored in this approach. The idea of his slicing algorithm is to keep track of control flow that is necessary for an execution to be valid. To end, each visited node is annotated with a state tuple $\Gamma$ containing many entries as threads. For each thread, the entry in state is its last node on the path from the slicing criterion to the currently visited node. Initially, the state tuple for the slicing criterion is empty except for that criterion's thread, which contains the slicing criterion. Empty slot in tuple are usually denoted $\perp$ and do not impose any restriction on that thread's control flow.

With each traversal of an dependence edge $m \to n, m$ is annotated with a clone of $m$'s state tuple, the entry is replaced by $m$. When boundaries are crossed via interference, one must check whether intra-thread control flow from the source of interference to the statement listed in this thread (i.e in $m$'s slot of the state tuple at $m$) is actually possible. Krinkle makes a feasible state tuple a threaded witness.
