It should be straightforward to prove such a model for context-insensitive slicing. However, this thesis shows the effectiveness of our object trees in comparison to method-spanning dependencies.

Note that data that cross method boundaries violate a precaution for two-phase slicing, for context-sensitive slicing in such a model needs extra recovery at method boundaries each time slice is computed. We did not include such complex' analysis. Instead, we compare our context-sensitive slicer to the context-insensitive slicer using SDG and to the relaxed notion of graphs described above.

Table 7.1 shows the benchmark programs for this experiment. We evaluated a benchmark of 8 programs with an average size of 1kLoc, and medium-sized Java apps. The student programs use very few API calls, and for nearly all (see section 6.1.1) to not miss essential dependencies. One JavaCard is called "Wallet", the "Purse" is called from the "Pacman" case [BCM+00]. Both affect SDGs contain the JavaCard API PDGs, native methods have been added above.

For every program, the LOC and SDG size (nodes and edges) is given. The time to construct these SDGs are split into two numbers: the column 'time' displays for building the SDG and the intermediate representation and pointer analysis. The next column shows the time to insert the summary edges. This number is given separately, as summary computation has complexity.
