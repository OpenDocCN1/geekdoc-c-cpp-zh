# Theorem 3.4. If

$\forall a \in \text{dom}(\mathcal{R}) : \forall x \in BS(a) \cap \text{dom}(P) : P(x) \leq R(a)$ (4.15)

then confidentiality is maintained for all $x \in N$.

That is, the backward slice from a node with a required security level $R(a)$ must not contain a node $x$ that has a higher security level $P(x)$.

**Proof.** $x \in N$. We need to show that (4.7) and (4.8) are valid for $x$. From the premise we know $\forall x \in BS(a) : P'(x) \leq R(a)$, as $P'(x) \leq P(x)$ for $x \in \text{dom}(P)$. Thus $R(a) \geq \text{fix}_{BS(a)}(P')$, where $R(a) \geq S(x)$ by theorem 4.2. Here (4.8) is satisfied. Furthermore, by definition of the fixpoint for, $S$, $S$ satisfies (4.13) and thus (4.11) and (4.7). $\square$

The theorem can be easily transformed into an algorithm that checks for confidentiality.

**PDG-Based Confidentiality Check.** For every node in the dependency graph that has a required security level specified, compute the backward slice, and check all nodes in the slice have lower or equal security levels specified.

Once the PDG has been computed, each backward slice and confidentiality check has worst complexity $O(|N|)$. Usually, the number of nodes that have a specific security level $R(a)$ is bounded and not related to $|N|$: typically just a few outputs have statements $R(a)$. Thus overall complexity can be expected to be $O(|N|)$ as well.

Checking each node allows a simple powerful insight in the case of a security violation: if the backward slice $BS(a)$ has a provided security level that is too large or incomparable ($P(x) \ngeq R(a)$), the responsible nodes can be computed by a so-called $CH(x,a) = FS(x) \cap BS(a)$. The1 chop computes all nodes that are on a path from $x$ to $a$, thus it contains all nodes that may be involved in the propagation from $x$'s security level to $a$.
