The reason is that a parameter from a specific call cannot influence the result of a different call, as all side-effects are represented as parameters. This fundamental to obtain context-sensitivity was introduced in [HRB90,RH94] and is called HRB slice. In the example, the path 3 → 3i → b → 40 → 5 is not realizable and not context-sensitive, as parameter 3 and return parameter 40 do not belong to the same call.

Interprocedural propagation of security levels is basically identical to intraprocedural propagation, but is based on the HRB backward slice which includes reachable paths. Equation (4.13) and Theorem 4.3 still hold.

Equations (4.3) and (4.8) can again be interpreted as a dataflow framework. For reasons of efficiency, we can generate all instances of these equations simultaneously while computing the HRB backward slice. This results in a set of constraints for S(x) which is solved by an affine point iteration; the after being based on the same parameter in dataflow frameworks.

The details of the HRB algorithm are shown in Algorithm 7.15. Remember that backward computation, and propagation of security levels is in two phases:

+   1. The first phase ignores interprocedural edges from a call into the procedure, and will only traverse to callees of the slicing criterion (i.e. is only ascending the call graph). Due to some entries, which model transitive dependence of parameters, all parameters that might influence the outcome of a returned value are traversed, if the corresponding path(s) through the called procedure were taken.
