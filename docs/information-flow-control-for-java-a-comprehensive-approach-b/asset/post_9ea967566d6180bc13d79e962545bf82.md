
## 2.1. INTROPROCEDURAL DATAFLOW ANALYSIS

Since the nodes and their corresponding statements are bijectively mapped, we will use both meanings interchangeably in the sequel.

**Reachability** One of the most fundamental properties of a program is the question if an execution of the program exists, where a given node is traversed and later in this execution another node is reached, i.e. whether a given statement is reachable in a program execution from another given statement. A path $p = (n_1, \dots, n_k)$ is called *realizable* if an execution exists, where the nodes are executed in the order induced by the path. This question, however, is undecidable in general and so conservatively assumes that all paths in the CFG correspond to a valid execution. This corresponds to treating conditionals like non-deterministic choice operators.

### 2.1.1 Monotone Dataflow Analysis Framework

Monotone dataflow analysis frameworks (MDFAF) are the most important class of dataflow analysis. Under a certain condition, they can compute the most precise solution in a finite number of steps, if no loops in the CFG may infinitely long paths. The basic structure of a MDFAF is a lattice of values:

**Definition 2.2** (Semi Lattice). A *join* semi lattice $\mathcal{L} = (L, \leq, \bot, \sqcup)$ consists of a set of values $L$ with a partial order $\leq$, and a binary operator supremum $(\sqcup)$ where the least element $\bot := \sqcup L$ in $L$ is called and the following properties hold:

- 1. $a \leq b := a \sqcup b = b$
- 2. $(a \sqcup b) \sqcup c = (a \sqcup c) \sqcup b$ (commutativity)
- 3. $a \sqcup b = b \sqcup a$ (commutativity)
- 4. $a \sqcup a = a$ (idempotence)

A *semi lattice* $\mathcal{L} = (L, \leq, \top, \sqcap)$ consists of a set of values $L$ with a partial order $\leq$, and a binary operator infimum $(\sqcap)$ where the greatest element $\top := \sqcap L$ in $L$ is called top and the following properties hold:

- 1. $a \geq b := a \sqcap b = a$
- 2. $(a \sqcap b) \sqcap c = (a \sqcap c) \sqcap b$ (associativity)
- 3. $a \sqcap b = b \sqcap a$ (commutativity)
- 4. $a \sqcap a = a$ (idempotence)

**Definition 2.3** (Complete Lattice). A complete lattice $\mathcal{L} = (L, \leq, \bot, \top, \sqcup, \sqcap)$ consists of a set of values $L$ with a partial order such that $\mathcal{L} = (L, \leq, \sqcup)$ is a join semi lattice and $\mathcal{L} = (L, \leq, \top, \sqcap)$ is a meet semi lattice. The least element in $L$ is $\bot$ (bottom), the greatest is $\top$ (top). The binary operators infimum $(\sqcap)$ and supremum $(\sqcup)$ have the additional properties:

> $^1$A partial order is a reflexive, antisymmetric and transitive relation

- 1. $a \cap (a \cup b) = a$
- 2. $a \cup (a \cap b) = a$ (absorption)
- 3. any subset $X \subseteq L$ has a supremum $\sqcup X$ in $L$.

It is straightforward to show that finite lattices are always complete, which suffices ours in this thesis.

**Definition 2.4** (Monotone Function Space). A set of functions $F$ defined on a join-lattice $L = (L, \subseteq, \cap)$ is a monotone function space, if

- 1. $id_L \in F : id_L(x) = x$ (identity function)
- 2. $\forall F \in F : \forall x, y : x \leq y \Rightarrow F(x) \leq F(y)$ (monotonicity)
- 3. $\forall F, G \in F : F \circ G \in F$ (closed under composition)
- 4. $\forall F, G \in F : F \cap G \in F$ (pointwise infimum)

**Definition 2.5** (Dataflow Analysis Framework). A monotone dataflow analysis framework (MDFAF) $A = (L, F)$ consists of

- 1. a complete semi-lattice $L = (L, \subseteq, \cap)$ with a supremum operator for the abstract values of the dataflow analysis, and
- 2. a monotone function space $F$ defined on $L$.

If all functions in $F$ are distributive over $\cap$, i.e. $(\forall F \in F : \forall x, y \in L : F(x \cap y) = F(x) \cap F(y))$, the desired solution of a monotone dataflow analysis framework is the meet-over-all-paths (MOP) solution of a monotone in the control flow graph. transfer for a path $p = (n_1, \dots, n_k)$ can be constructed with the recursive definition:

```
F_{n1,...,nk} : L → L : F_{n1,...,nk}(x) = F_nk (F_{n1,...,n_{k-1}}(x))
```

Since there are infinitely many paths in a control flow graph, there is no general algorithm to compute the MOP, which is $F_p$, directly. However, an efficient solution can be found using a different definition, which is equivalent or conservative to the MFP for monotone functions.

**Definition 2.6** (Fixed point). A fixed point of an operator $f$ on a semi-lattice $L$ is an element $x$ in $L$ such that $f(x) = x$. A fixed point for $x$ is called minimal (MFP) if $y \leq x : f(y) = y \leq x$.

The efficient algorithm for computing the MOP solution of a MDFAF, which has been invented by Kildall [KU77], can be seen as pseudocode in Algorithm 1. Kam and Ullman [KU77] have shown that the monotonicity of the function space always guarantees termination and if the MFP exists. The MFP solution is always a conservative solution but if the MDFAF is not distributive it is necessarily the most precise solution.

**Algorithm 1** Kildall's algorithm to compute the MFP

```
**Input:** CFG a control flow graph
$F_s$ transfer functions of a monotone dataflow analysis framework
**Output:** $A$ an array of elements computing the MFP
**foreach** $n \in$ CFG **do**
  $A[n] = \perp$
  **od**
  **foreach** $n \in$ CFG **do**
    $temp = \bigcap_{q} F_q(A[q])$
    **if** $temp \neq A[n]$
      $change = true$
      $A[n] = temp$
    **fi**
  **od**
**until** $\neg$ $change
```

### 2.1.2 Reaching Definitions

Reaching definitions is a traditional problem that answers whether a definition of a variable can reach a use. A definition $d$ of a variable reaches another statement if there is a path $p = (n_1, \dots, n_k)$ where a given node is traversed and later in this execution another node is reached.

### 2.1.3 Static Assignment Form

A very popular representation is called *static single-assignment (SSA)* form [CFR*91]. It separates several values from the program's variables and thus enables several more optimizations. A program is in static-assignment form if every variable is assigned at most once. It is called *static* because the variable may well be assigned multiple times during program execution, e.g. in a loop. To compute the static single-assignment form [CFR*91], usually introduces a subscript for each variable that is incremented at each assignment statement. At points in the control flow graph, new assignments with a $\phi$-operator need to be inserted to represent the choice of the variable according to the program's flow. Note that programs in SSA form are equivalent to the original program.
