

## 5.2. 路径条件的奠基

$PC(x, y)$ 是从 $x$ 流向 $y$ 的必要条件，而 $E(z)$ 是执行 $z$ 的必要条件。控制路径是由控制依赖边组成的路径。$E(x)$ 是根据与依赖边 $u \to \mu$ 关联的条件 $c(u \to \mu)$，沿着函数 $x$ 的 $Start$ 节点到所有控制路径计算得到的。对于控制依赖，$c(u \to \mu)$ 通常是来自 *while-* 或 *if-statement* 的条件。路径条件中的程序变量是（隐式地）存在量化的，它们是潜在信息流的必要条件。

由于准则节点之间的路径是基于 chops 的，我们将关注路径集合 $P_1, P_2, \dots \in CH(x, y)$，并且对路径条件有一个稍微放宽的关系为：

```
$PC(x, y) = \bigwedge_{z \in PC(x,y)} E(z)$
```

在 [[SRK06]] 中 Selting 等人解释了为什么该公式是正确且精确的，并且为什么它明显简化了计算。他们还表明，$CH(x, y)$ 中的循环在计算 $PC(x, y)$ 时可以安全地忽略，使得公式始终是有限的。对于图 5.1 中的示例，计算了以下等式和路径条件：

```
$c(2 \to 3) \equiv c(2 \to 4) \equiv (n > 0), \quad c(4 \to 5) \equiv (x > 0)$,
$c(4 \to 7) \equiv (x \le 0)$,
$E(1) = \text{true}, \quad E(3) \equiv (n > 0) \wedge E(5) \equiv (n > 0) \wedge (x > 0)$,
$PC(1, 5) \equiv E(1) \wedge E(5) \equiv (n > 0) \wedge (x > 0)$
```

在存在数组或指针等数据结构的情况下，会生成额外的约束。对于数据依赖，$\Phi(\nu \to \mu)$ 是约束通过数据类型的信息流的条件。作为示例我们考虑数组（完整介绍见 [[SRK06]]）数组元素 $a[E_1] = \dots$ 与使用 $a[E_2]$ 之间的数据依赖 $u \to \mu$ 生成 $\Phi(\nu \to \mu) = E_1 \wedge E_2$；所有其他依赖将生成 $\Phi(\nu \to \mu) = \text{true}$。计算路径条件的等式变为：

```
$PC(x, y) = \bigwedge_{z \in PC(x,y)} (\bigwedge_{z \in P} E(z) \wedge \bigwedge_{u \in P} \Phi(u \to v)) \quad (5.2)$
```

对于分类，以下程序片段及其路径条件：

- 1 a[i+3] = x;
- 2 if (i>10)
- 3 y = a[2*j-42];

```
$PC(1, 3) \equiv (i > 10) \wedge (i + 3 = 2j - 42)$
```

这除了执行条件之外，还包含一个要求两个索引表达式相等的项，

### 多个变量赋值

基于原始程序文本计算路径可能会使条件不可满足，即使影响是可能的。作为示例，考虑图 5.2（左）中的代码和（原始）路径条件

> PC(1,5) ≡ (x < 7) ∧ (x = 8)

在第 1 行的 a 与第 5 行的 x 之间。该条件不可满足，尽管第 1 行肯定有一种方式可以影响第 5 行。问题在于程序对变量 x 有多次赋值，而路径条件无法区分。对于静态路径条件，这通过使用程序的 SSA 形式 [CFR91] 的变体来解决。如何，不同变量被区分并最终使用 ϕ 运算符组合在一起，用单个赋值替换多次赋值。图 5.2（右）显示了原始程序（左）的 SSA 形式。

SSA 形式通过区分 x 的不同变量使我们的路径条件变得可解：

> PC(1,5) ≡ (x < 7) ∧ (x = 8)

将程序转换为 SSA 会修改代码表示，对于接近源代码结构的代码 ValSoft 中的依赖图来说是不希望的。为了保持代码结构，使用了类似于 SSA 形式的赋值形式：索引号表示依赖图中的节点号，从而可以精确地区分不同的变量出现。路径条件如

```
($e\puf[idx] = "" + $)
```

因此写成

```
($e\puf_{99}[idx_{98}]=97$ + ""_{101}$)
```

$\phi$ 运算符不会出现在代码结构中，但仅用于计算路径条件。

### 弱路径条件和强路径条件

对于两个语句 $x, y$ 之间的给定 chop，通常可以定义多个路径条件。尽管如此，每个实例都是沿着 chop 进行信息流的必要条件。为了论证质量，对对 $(x, y)$ 定义了一个偏序 $\le$

```
$PC(x,y) \le PC(x,y) \quad PC(x,y) \Rightarrow PC'(x,y)$
```

在这种情况下 $PC(x,y)$ 被称为比 $PC'(x,y)$ 更强。更强的条件通常更容易被约束求解器求解，因此更有利。

请注意，底层 chop 影响路径条件的强度：如果存在两个 chop，其中一个比另一个更精确 $CH(x,y) \subset CH'(x,y)$，那么较小 chop 中的每个路径 $P \in CH(x,y)$ 也是较大 chop 中的路径。因此，较小的 chop 生成更强的路径条件，因为路径中的除法运行在几个之上：

![](img/27c6595637bae6b27613772d7079f8a2_138_0.png)

这一事实构成了第 5.4.2 节的理论基础，因为动态 chop 比静态 chop 更小。

向路径条件添加另一个合取项 $R$ 是加强它的另一种方式。在第 5.4.3 节中，逻辑公式将从动态 trace 生成并与原始路径条件结合，产生更强（或相等）的路径条件：

```
$PC(x,y) \wedge R \ge PC(x,y)$
```
