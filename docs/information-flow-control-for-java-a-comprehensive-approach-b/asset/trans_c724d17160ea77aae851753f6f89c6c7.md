## Chapter 4
## 信息流控制

信息流控制（IFC）是一种确保软件系统相对于安全规范的安全性的技术。关于 IFC 的研究随着移动代码和安全相关应用的普遍性而兴起。信息流控制通常通过特殊的类型系统进行验证 [SM03]。然而，类型系统没有利用当代程序分析的全部工具，因此受限于语言的限制且注释负担高。本章将介绍一种基于程序切片和系统依赖图的新型信息流控制方法，系统依赖图在前几章中定义。与类型系统相反，所提出的算法由于底层切片技术而具有流敏感性、上下文敏感性和对象敏感性，从而减少了误报。程序分析的最新进展使得该技术即使对于 Java 字节码等现实语言也具有可行性和可扩展性。

该工作的先前成果已发表于 [HKS06, HKN06, HS08]。

### 4.1 计算机安全

从技术意义上讲，安全被定义为免受危险或损失的状况，重点在于防止来自外部的危险。就计算机科学而言，可以识别出三个主要的安全维度，通常以 CIA 三元组表示。

**保密性**是数据隐私的保证。只有预期且授权的接收者——个人、进程或设备——可以读取机密数据。

**完整性**是数据不被篡改的保证。数据完整性断言信息在从源到接收的传输过程中未被更改，并包括对不可信输入的有效性检查。

**可用性**是对授权用户及时可靠地访问数据服务的保证。它确保信息或资源在需要时可用。

*基于语言的安全*从源代码或中间代码推导出安全属性。为此，它利用编程语言技术，通常是编译器技术的一部分。由于基于语言的技术无法验证时序属性，因此它们仅针对保密性和/或完整性。

### 4.1.1 信息流

信息安全传统上仅考虑软件制品及其用户的身份和来源。一个例子是 Bell 和 LaPadula [BL73, BL96] 访问控制，它已成为所有主要操作系统中的强制性要求。其他“经典”手段包括加密、代码签名、病毒扫描程序、防火墙、自动更新。然而，所有这些手段都无法断言整个数据处理过程的安全性（端到端安全），而只能在计算的某一点检查违规行为。问题在于，经典手段只验证身份和来源，而忽略了软件片段的语义。例如，访问控制可能只验证用户是否有权访问某些公共或机密数据。在释放该数据后，它就无法再控制程序是否使数据公开，因为这需要用户希望软件片段不会恶意使用其数据，通常基于公司的身份和声誉。然而，过去已有若干案例公开，甚至知名软件生产商也收集用户数据并将其发送回其服务器。

作为补救措施，基于安全可以验证程序信息的 security policy。信息流策略定义了给定系统的安全要求，对数据在计算中如何使用施加权利和限制。最理想的属性是端到端安全，其中敏感数据在完整的处理路径中受到保护 [SRC84]，例如从文件系统（具有访问控制）开始，经过程序中的数据处理，直到最终向授权用户呈现。由于访问控制已集成在所有主要操作系统中，控制处理期间的信息流仍然是巨大的挑战。

### 4.1.2 通道与信息流

Lampson [Lam73] 识别出程序可以通过三种所谓的通道向其环境传输信息：合法通道是程序声明的正式输出，存储通道是程序非本地环境中的其他存储，而隐蔽通道是传输信息的任何其他手段（即不涉及系统中任何存储的值）。时序通道是隐蔽通道的一个例子，攻击者可以通过测量程序的执行时间来获取信息。时序通道已被成功利用，例如使用中国剩余定理对 RSA 进行攻击，以破解智能卡中的加密 [Scho00]。

当信息从源传输到通道时，存在两种主要的信息流方式：

**显式流**从 $x$ 到 $y$ 发生，当 $y$ 被赋值为包含对 $x$ 的引用时。$y = \mathbf{f}(x)$ 是显式流的例子。

**隐式流**从 $x$ 到 $y$ 源于控制流，其中执行取决于 $x$ 的值。例如 if $(x=0)$ $y=0$ else $y=1$; 包含从 $x$ 到 $y$ 的隐式流。历史上，一些作者将隐式流视为隐蔽通道，然而，今天这种分类已不再存在，因为隐式流可以用基于语言的技术轻松检查。

## 4.2 信息流控制

控制信息如何在程序的通道中流动的手段称为信息流控制（IFC）。在 CIA 三元组中描述的三个维度中，信息流控制保密性和/或完整性。完整性通常仅限于对偶性（基于 [Bib77] 的观察），人们通常只描述如何断言保密性。控制可以在在线（程序执行期间）或离线（通常为编译时）进行。两种方法各有不同的优缺点。

在线（动态）IFC 的主要优点是它不会虚假地保护程序执行，因此是精确的。它的分类可以是静态的（每个变量在整个执行过程中具有固定的安全级别）或动态的（安全级别在每次赋值时确定）。但与动态程序分析一样，它无法证明程序的一般安全性，并且会因运行时测试而减慢程序执行速度。此外，动态检查最能防止即将发生的非法流，但恶意对手可能会获得程序因违反安全策略而被终止的信息，因此程序至少会泄漏布尔信息。像 Fenton 的 Data Mark Machine [Fen74] 这样的一些系统采用特殊技术来避免这种泄漏，但在存在副作用的情况下可能无效。运行时 IFC 最具限制性的属性是控制结构，一个合成变量，称为 *程序计数器*（或在 [Ara83] 中称为 *敏感性标签*）跟踪控制流中的数据。然而，控制谓词 $p$ 的安全标签不会限制在给定程序执行中由该谓词控制的控制的安全级别，但也会限制在另一次执行中由于谓词 $p$ 而可能发生变化的变量的值。但动态分析的特征是只有一条执行路径，而不是所有可能的路径。检测所有可能的隐式流的一种方法是保持 PC（程序计数器）在 $p$ 的安全级别直到程序结束（并随着后续控制结构而增加，这种效应在 [SM03] 中称为 *标签蔓延*），使动态分析在实践中仅具有限制性。
