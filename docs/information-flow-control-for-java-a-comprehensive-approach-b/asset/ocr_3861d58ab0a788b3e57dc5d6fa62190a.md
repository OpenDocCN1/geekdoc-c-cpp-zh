For computing precise results for data dependence it is necessary to base intersection decision on the results of pointer and alias analysis. Tonella et al. [TAFM97] were the first to use points-to analysis [And94,Ste96,SS00b] for SDG generation OO programs.

# Field sensitive analysis

Several approaches for determining the type of intersection have been proposed in literature. Each approach has its strengths and weaknesses. A straightforward intersection computation by scalar replacement [Kri03a], where any access to a variable is (recursively) replaced by the contained fields, does not necessarily give the most precise data dependencies. Consider the program in Figure 2.10 where z is only dependent on the definition in line 6. The C-Framework of ValSoft [Kri03a] uses a듯 slicing of line 4 due to the loss of precision of its scalar replacement. CodeSurfer [AT01] employs a non-virtual scalar replacement strategy that blows up by replacing the assignment a = b with strategy that allows the computation of the slice. Such replacement may be appropriate for procedural languages like C, where nesting of structures is not too common, for object-oriented languages like Java with deeply nested objects, would require a large overhead, which can be avoided by using a definition of data dependence without explicit scalar replacement.

The definition of data dependences can be refined for the case of field access to a field f, which is referenced by its fully qualified name (including name and defining):

# Definition 2.18 (Data Dependence for Field Access), A PDG has a data edge from node n1 to node n2 due to field access iff all the following conditions hold:

+   * n1 is a node that defines the field f of variable x
* n2 is a node that uses the field f of variable y
* x and y are potential aliases (may-aliases)
