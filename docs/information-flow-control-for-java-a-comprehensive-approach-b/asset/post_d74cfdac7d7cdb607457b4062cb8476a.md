The side-effects for a method m are described by the following functions [Ban79].

- Ref(m) = set of locations that may be dereferenced by executing m
- Mod(m) = set of locations that may be modified by executing m

These are prefixed with letters to refer interprocedural versions (see next paragraph). By definition, Ref(m) ⊆ Mod(m) and the same relation holds for the prefix name.

The first step in side-effect is to determine which side-effects a method may produce without considering other methods called in that method. We call these IRef and IMod to indicate that they are intra-procedural.

### 2.5.1 Intraprocedural IRef and IMod Computation

Before getting into the details of the algorithm, the notation used in this is presented: For a method m, the Param(m) denotes all formal parameters of m. We use Sub(x) for the set of locations that are transitively reachable by dereferencing fields of x. This can be easily determined by Class Hierarchy Analysis [DGC95], which provides results of class analysis generally allow much more refined sets, as only fields of points-to-set x (and transitively reachable locations) need to be considered. The base(y,f) refers to the base object of a composite location y and is defined as base(y,f) = y.

The locations that may be referenced or modified by the method alone, without taking effects of method into account, are computed according to the following recursive definitions. Therefore, we are interested in their minimal fixed point:

```
IRef(m) = {loc.y | y ∈ Param(m) ⊉ IRef(m) : ∃ statement r ∈ m
loc.x ∈ Mod(m) ⊉ Ref(r): alias(x,y)} ⊉ IMod(m) ⊉ Subobject(x)
{loc.y | y ∈ IRef(m) : ∃ statement r ∈ m ⊉ Ref(r): alias(x,y)} (2.3)
```

The locations that may be directly referenced in a method consists of the parameters of the analyzed method m as well memory locations transitively reachable from them through access a field f whose base object x is a may alias of may location that may be referenced. Apart from that, all memory locations that may be written (IMod(m)) must be included into IRef by definition, as not paths in method must redefine these fields. In case, the original value will be synthetically referenced. Finally, the subobjects of all memory locations that may be used when writing another memory location need to be included. The reason is that, when an object is written, its subject structure changes due to changed field values, and these changes come from the field values of the used object.

The set of locations that may be modified in the method $m$ directly subsum locations that are directly or indirectly accessible via parameters and are used at a statement $r \in dom(m)$ with a possible aliasing of the base locations. Apart from that, the whole set that with the synthetic variables $ret, scx$ representing the return value or the thrown exception of method $m$, is transitively considered with respect to the subgraph relation.

Note that in the presence of recursive structures, $IRef$ and $IMod$ may contain an infinite number of locations with finite length. For example, a linked list contain {head, head.next, head.next, ...}. We will show that for computation purposes, it is sufficient to determine only a number representatives for an equivalence relation, these sets can be considered finite in the metric.
