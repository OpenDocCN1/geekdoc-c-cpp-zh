## 4.2.1 The Lattice Model of Information Flow

Usually, data is classified into a finite set of security domains (also called security levels) $\mathcal{L} = \{l_1, \dots, l_n\}$. A transitive, reflexive and antisymmetric metric interference relation (a partial order): $\preceq$ denotes $x \preceq y$ if information in class $x$ is permitted to flow to class $y$. The completion relation, called noninterference, defined by $x \perp y$ means that information flow between security levels must be prevented. Frequently, the security levels are arranged in a lattice $\mathcal{L}$ in which $\preceq$ is equivalent to $\le$. If the interference relation does not form a lattice, we assume a complete bounded lattice $\mathcal{L} = $(\mathcal{L}, \le, \top, \bot)$ of security levels in the sequel for convenience. The most trivial lattices are given by linear priorities that can be represented as a sequence $0 \dots, n$, like LOW $(\text{L}) \le$ HIGH $(\text{HIGH})$ which can also be represented as $0 \le 1$, or like the well-known classification levels Unclassified (0), Confidential (1), Secret (2) and Top (3). Many complex lattices contain incomparable elements where neither $x \preceq y$ nor $y \preceq x$ as shown in Figure 4.1. Lattices have been found to naturally represent the semantics of information flow [Den76]. When information is composed of pieces with different security levels, the supremum operator $\sqcup$ signifies security class for the combined information. The 'operands' security levels are joined using the supremum operator, e.g. if information of the security levels Confidential and Secret is merged, the result must at least be Secret.

The type system offers a formal specification that separates the security policy from the enforcement mechanism. Type-based IFC is efficient, compositional, and correctness proofs are not difficult. Thus, type-based IFC have been a success story, opening up the whole field of language-based IFC. For type-based IFC, the elements of security lattice become a set of additional types where the interference relation ≤ between security levels is represented by subtyping. A program does not interfere with variables of a lower type, which guarantees confidentiality. Typing rules regulate security levels through the expressions and statements of a program, guaranteeing to catch information leak.

## 4.3. DEPENDENCE GRAPHS AND NONINTERFACE

The soundness of PDG construction guarantees that a matching path from a to b in a PD implies there is no influence from a to b. This asserts that information flow is not caused by hidden side channels such as timing or termination leaves impossible. It is therefore not surprising that technical details for secure information flow as noninterference is related to PDGs.

Noninterference as defined by Goguen and Mesueger [GM82, GM84] is defined with respect to an abstract automaton M=(S, A, O, step, out) representing state transitions of a program. The generali contains an initial state s₀ S, the set of actions A can be thought of as the program's constructs, and the outputs O represent all possible outputs. step: S × A → S is the transition function, which in our case is induced by the program semantics, and out: S × A → O is the output function. We define the function run: S × A* as the natural extension of sequence of actions in A* in the standard manner: run(s,e)=s; run(s,a)=run(s,a),
