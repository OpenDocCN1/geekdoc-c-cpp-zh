**Summary Edges for Object Trees**

When summary edges with object trees, an optimization is crucial to avoid explosion: With the original algorithm for summary edges, if a child of an actual parameter has a summary edge to $n$, then the parent(s) would get an edge to $n$ as well. But these edges are redundant, one can always follow the child's summary edge and ascend to the parent, so slicing will yield the same with or without follow control dependences from parameters to their lines.

Previous work [RYS88, BHR89, PS91] has shown several dimension of slicing correct (in interprocedural slicing and heap objects, see page 36). As a combination of interprocedural slicing with heap objects has not been explicitly proven, we focus on the soundness of interprocedural data dependences for heap objects. Thus, to show the soundness of our algorithm, we need to prove that all dynamic data dependences are approximated by static data dependences, i.e. when a statement defines a field value in an execution and its value is later used at another statement, there must be a dependence chain between the corresponding nodes of the SDG. For a method call, we assume that in a dynamic execution, the successor of the last statement of the invoked method is call, assigning the returned value to the result variable. In the sequel, we detect the kind of dependence an SDG edge with label(e), e.g, label$(x->y) = correspondingCall(n)$ denotes the call that creates the stack frame of statement, $n$ is typically a return statement.
