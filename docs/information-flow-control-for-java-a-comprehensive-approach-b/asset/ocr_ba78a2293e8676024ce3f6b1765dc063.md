In the following, we concentrate on confidentiality, as all equations for integrity are obtained by duality.

Equation (4.5) assumes that every statement, node has a security level specified, which is not realistic. In practical applications, one wants to specify security levels not for all, but for certain selected statements.^7 The provided security level specifies that a statement sends information with the provided security level, i.e. represents an input channel. The required security level requires only that input with a smaller or equal security level may reach that statement,8 i it represents an output channel of the specified security level. From these values the actual security levels can be computed.

Provided security levels are defined by a partial function $P : N \rightarrow L$. The required security levels are defined similarly as a partial function $R : N \rightarrow L$. Thus, $P(s)$ specifies the security level of the information at $s$ (also called 'the security level of $s$), and $R(s)$ specifies the maximum allowed security level of the information.

The actual security level $S(x)$ for a node $x$ must not be greater than the level of its predecessors, but greater than its own provided security level. This equation (4.5) refines to

```
$S(x) \geq \begin{cases} P(x) \cup \bigcup_{y \in dom(P)} S(y), & \text{if } x \in dom(P) \ \bigcup_{y \in prod(x)} S(y), & \text{otherwise} \end{cases} \quad (4.7)$
```

Note that $R$ does not occur in this for $S$. We need an additional constraint to specify that incoming nodes must not exceed a node's required level:

```
$$\forall x \in dom(R) : R(x) \geq S(x) \quad (4.8)$
```

We can now formally define confidentiality:

**Definition 4.1.** *Let a program's PDG be given. The program maintains confidentiality, if for all PD nodes equations (4.7) and (4.8) are satisfied.*
