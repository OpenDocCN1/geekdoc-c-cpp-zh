

# 第4章 信息流控制

如果准则未满足，则最终语句 $a$ 的输出在实际的 $a$ 与移除了所有 supposedly 非影响语句的 $\alpha$ 之间会不同——因此存在从 $\alpha$ 中的语句 $s$ 到 $a$ 的影响，即使这被 $dom(s) \not\subseteq dom(a)$ 所禁止。我们看到，安全性的概念基于观察行为而非源代码。

基于类型的非干扰定义通常以更紧凑的格式定义。在其最简单的变体 $c_{Low}$ 中，假设只有安全级别 $Low - High$——它读作

```
$s \_{Low} s' \implies [c]_s \_{Low} [c]_{s'}$ (4.2)
```

其中 $c$ 是一个语句或程序，$s, s'$ 是两个初始程序状态，$[c]_s, [c]_{s'}$ 是执行 $c$ 后的最终状态。$s \_{Low} s'$ 意味着 $s$ 和 $s'$ 在等价：它们可能在具有 $Low$ 安全性的变量上一致。对高输入变量的变化不会影响输出，因此机密性得到保证。注意，初等非干扰的各种扩展，例如可能的或概率的非干扰；其中一些基于 PER 关系 [SS01]。Pistoia 等人 [PCFY07] 已经指出，Goguen/Mesueger 非干扰不仅仅是方程 4.2 的安全流准则及其后代，因为前者仅考虑观察行为并且不包含每个语句的隐式和显式流。随后提出的方法仅考虑行为，因此遵循原始的 Goguen-Mesueger 定义。

下面的定理将 PDG 与原始的 Goguen-Mesueger 定义联系起来，可用于检查非干扰。

## 定理 4.1. 若

```
$s \in BS(a) \implies dom(s) \not\subseteq dom(a)$ (4.3)
```

则非干扰准则对 $a$ 成立。

证明。参见 [SRK06]。
如果 $dom(s) \not\subseteq dom(a)$（$s$ 和 $a$ 具有非干扰安全级别），则必须不存在 PDG 路径 $s \to a$，否则已发现安全泄漏。
该定理的普遍性源于它独立于特定语言或切片算法；它只是利用了任何正确切片的基本属性。该定理即使对于不精确的 PDG 和切片也是有效的，只要它们是正确的。应用该定理可对所有 $s$ 实现线性时间测试。更精确的切片会导致更少的误报。然而，正如我们稍后会看到的那样，不可能在纯粹基于切片的方法中使用降分类，因此稍后我们将提出定理 4.1 的扩展版本。

```
class PasswordFile {

    private String[] passwords;

        } catch (IndexOutOfBoundsException e) {

}
```

*sec* 的值被写入 *set* 中 *this-pointer* 的字段 *x* 的副作用。摘要边使 SDG 中的上下文敏感切片在节点数上呈线性时间 [HRB90]

在程序中，变量 *sec* 假定包含秘密值，不得影响 printed。首先创建一个新的 *A* 对象，其中字段 *x* 初始化为零。然而，该对象之后不再使用，因为它被覆盖（'killed'）为一个新的对象，其字段 *x* 被设置为 pub。现在上下文敏感分析 of set 发现新对象的 *x* *不* 受 *sec* 影响。因此不存在从 *sec* 初始化到第一个语句（最左边的 print 节点）的 SDG 路径 (13) -- (19)。我们有从 *sec* 初始化到该输出节点的路径。*sec* 变量不影响输出。此示例表明两个 *A* 对象的 *x* 字段被区分（对象敏感性），对 set 的不同颜色的副作用未被合并（上下文敏感性），并且流敏感性杀死了 *sec* 变量对第一个 println 的任何影响。

接下来的语句显示了信息的不合法流：行 (21) 检查 *sec* 是否为零并在这种情况下创建类 *B* 的对象。*o.set* 的调用是动态分派的：如果目标对象是 *A* 的实例，则 *x* 被设置为零；如果它具有类型 *B*，x 接收该值。(21) - (23) 类似于以下隐式：

```
if (sec==0 && ...) o.x = 0 else o.x = 1;
```

在 PDG 中，我们有从 *sec* 到调用 *sec* 的谓词到 o.set() 及其目标对象的路径。沿着摘要边到达 x 字段和第二个输出节点。因此 PDG 发现第 24 行打印的值取决于 *sec* 的值。在下一节中，我们将正式引入安全级别并证明此示例包含不合法的流。
