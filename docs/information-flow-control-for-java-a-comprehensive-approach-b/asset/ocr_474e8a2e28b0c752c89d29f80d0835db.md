Definition 2.9 (Data Dependence). Let Ref($x$) denote the set of variables referenced at node $x$. Then a node $y$ is dependent on node $x$ ($x ightarrow y$) if

+   - exists a variable $v$ with $v \in \text{Def}(x)$ and $v \in \text{Ref}(y)$
- exists a path $P$ in the CFG from $x$ to $y$ where the definition of $v$ is not definitively killed (i.e. $x$ is a reaching definition of $y$).

As mentioned, the program dependence graph consists of the nodes of the CFG (sometimes the END node is omitted as it has no in- or outgoing edges) with control and data dependence edges replacing the control flow edges. Consider the program dependence graph of our example in Figure 2.4. The data dependences are depicted in green, control dependencies in blue. Since statement 1 defines a variable that is referenced at line 5 and not overwritten inbetween, there is a data dependence from 1 to 5. The condition in line 5 determines how often the loop is executed, so all the statements in the loop body are connected by control dependence to node 5. Note that dependence graphs may contain loops (see the data dependence at node 6) and multiple edges between two nodes, they are multigraphs.

Data dependence can be computed with reaching definitions analysis directly. But it is explicitly simpler for programs in SSA form, as each variable name is only defined once. Computing DD from SSA form is finding the definition of the referenced variable and if this is defined in a $\Phi$-function building the transitive hull of variables referenced in $\Phi$-functions.

As an example, consider Figure 2.4 again. The definition of $sum_3$ depends on the variable $sum_2$, which is defined in a $\Phi$-function. This function in turn references $sum_1$ and $sum$, none of which is defined in a $\Phi$-function. $sum_3$ is data dependent on itself and on the initialization. This can be seen in Figure 2.4 as data dependences from node 3 to node 6 and from 6 to 6.
