# 3.2.2 Dynamic Thread Creation

Threads in Java are in contrast to previous languages like Ada totally dynamic. In static detection of the number of threads running in a program's execution is undecidable. A thread can be created by any other object calling java.lang.Thread constructors, and a subsequent invocation of its start() method will create a new thread of execution in the operating system executing its run() method. All this may happen in loops or recursion, so there is no static bound on the number of threads.

When a language offers threads that can be created and destroyed dynamically, and when thread creation may occur in a control flow cycle gets another source of undecidability even if the language offers no precisely. In this case, the undecidability result from intraprocedural slicing causes another undecidability. One cannot determine, or how often, the cycle is executed and thus a new thread is created. For program analysis one has to conservatively assume that indefinite number of threads will be created. However, the question if there may exist two threads during program execution where one is at a given statement s1 and the other at a given statement s2 must be conservatively answered 'yes', for there may always be another thread that created at statement s2.

However, interference is possible to other instances of t. The graph on the right illustrates, that a feasible path can only be found if at least three instances of t have been created. However, since it is undecidable if the loop executes at least thrice, precise slicing is undecidable here as.
