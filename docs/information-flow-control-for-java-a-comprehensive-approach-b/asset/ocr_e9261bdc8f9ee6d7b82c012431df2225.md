+   - Attackers cannot control the execution of the JVM including its security settings.

# 4.5.1 Fundamental Flow equations

For a correct IFC, the actual security level of every statement must be computed, and this computation must respect the programmer-specified levels as well as propagation rules along program constructs. The huge advantage of PDG-base IFC is that the PDG already defines the edges between statements and expressions, where a flow can happen; as explained, explicit and implicit flow between PDG nodes is impossible. Thus it suffices to provide propagation rules along PDG edges. We begin with the intraprocedural analysis.

The security level of a statement resp., where the PDG node is S(x), where $S : N \rightarrow L^5$ Confidentiality requires that an information receiver $x$ must have at least the security level of every sender $y$ [31.96]. In a PDG, where $pred$ and $succ$ are the predecessor and successor functions induced by $ightarrow$, resp., the fundamental property is easily stated as

```
$$y \rightarrow x \in G \Rightarrow S(x) \geq S(y) \quad (4.4)$
```

and by the definition of a supremum

```
$S(x) \geq \bigsqcup_{y \in pred(x)} S(y) \quad (4.5)$
```

> $^5$Remember that $N$ is the set of PDG nodes. Note that our $S$ is called *dom* in the original Goguen/Meseguer noninterference definition, but we need *dom* for partial functions.
