One of the reasons, why slicing-based IPC needs less annotations than type is that side-effects of methods are explicit in dependence graphs, so no end-label (which models the impact of side-effects on the program counter) is required, another return-value or explicit labels. These are computed as summary information representing the dependences of called methods.
Apart from these, Jif requires annotations to verify any nontrivial property except control flow. In particular, preconditions like non-nullness must be included in the program text instead of its annotations, explicit tags for null pointers or clause, which are typically followed by empty handlers as in the example shown in Figure 4.6 on page 96. Preconditions are therefore included as runtime times to enable local reasoning. Such coding style is an ordeal for the software engineering perspective, as it implies source comprehension and may conceal violated conditions. What one really wants is verification that such cases cannot happen in any execution and thus not need to be included in the source code.
