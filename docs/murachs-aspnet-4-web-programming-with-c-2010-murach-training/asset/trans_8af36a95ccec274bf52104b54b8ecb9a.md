

## 静态网页的工作原理

互联网上的许多网页都是 *静态网页*，它们不会根据用户输入而改变。这些页面是 *HTML* 文档，由 *HTML*，即 *超文本标记语言* 定义。

图 1-3 显示了 Web 服务器如何处理静态网页。流程始于用户在 Web 浏览器中请求一个网页。当用户在浏览器的地址栏中输入一个称为 *URL（统一资源定位符）* 的网页地址，或当用户点击一个链接前往另一页面时，就会发生这种情况。

在任何一种情况下，Web 浏览器都使用 HTTP 向 Web 服务器发送 *HTTP 请求*。HTTP 请求包括诸如所请求网页的名称和地址、发出请求的浏览器的地址以及将处理请求的 Web 服务器的地址等信息。

当 Web 服务器从浏览器收到 HTTP 请求时，服务器从磁盘检索请求的 HTML 文件，并以 *HTTP 响应* 的形式将文件发送回浏览器。HTTP 响应包括用户请求的 HTML 文档以及浏览器和 Web 服务器的地址。

当浏览器收到 HTTP 响应时，它会格式化并显示 HTML 文档。然后，用户可以查看内容。如果用户通过点击链接或在浏览器地址栏中输入另一个网页地址来请求另一个页面，则流程重新开始。

图 1-3 还显示了 URL 的组成部分。第一个组成部分是协议，在本例中为 HTTP。在大多数情况下，您可以省略协议，默认使用 HTTP。

第二个组成部分是 *域名*，它标识您的网站。例如，此图中的 URL 包含我们网站的域名 www.murach.com。浏览器使用域名来识别托管网站的服务器。

域名之后，您指定文件在服务器上的路径。请注意，在 URL 中使用正斜杠来分隔路径的各个部分。路径之后，您指定要在浏览器中显示的文件名。在本例中，该文件是一个名为 *index.htm* 的静态网页。

### 描述

- *静态网页* 是每次查看时都相同的 HTML 文档。换句话说，静态网页不会根据用户输入而改变。查看静态网页的每个人看到的内容完全相同。
- 静态网页通常是存储在 Web 服务器上的简单 HTML 文件。当浏览器请求静态网页时，Web 服务器从磁盘检索该文件并将其发送回浏览器。静态网页通常具有 .htm 或 .html 的文件扩展名。
- Web 浏览器通过向服务器发送称为 *HTTP 请求* 的 HTTP 消息来向 Web 服务器请求页面。HTTP 请求包括，除其他内容外，所请求的 HTML 文件的名称以及浏览器和 Web 服务器的 Internet 地址。
- 使用浏览器的用户可以通过多种方式发起 HTTP 请求。一种方法是输入称为 *URL* 或 *统一资源定位符* 的网页地址到浏览器的地址栏，然后按 Enter 键。另一种方法是点击指向网页的链接。
- Web 服务器通过向浏览器发送称为 *HTTP 响应* 的消息来回复 HTTP 请求。HTTP 响应包含浏览器和服务器的地址以及正在返回的 HTML 文档。

## 动态网页的工作原理

Web 应用程序由一个或多个网页组成，这些网页不是静态的，而是在每次显示页面时可以以某种方式改变。它们不是以 HTML 文件的形式存储在磁盘上，而是由应用程序动态生成的。因此，生成的页面通常被称为 *动态网页*。

静态网页和动态网页之间的关键区别之一是，动态网页是包含一个或多个 *服务器控件* 的 Web 表单，例如标签、文本框和按钮。用户使用这些控件与应用程序进行交互。

图 1-4 显示了动态网页的基本处理过程。首先，浏览器向 Web 服务器 (**IIS**) 发送 **HTTP** 请求，其中包含所请求网页的地址以及用户输入到表单中的信息。当 IIS 收到此请求时，它通过在 *应用程序映射* 列表中查找所请求页面的扩展名来确定这是一个对 Web 表单的请求。这些映射指示文件扩展名与哪个程序相关联。因为 .aspx 文件与 ASP.NET 相关联，所以 Web 服务器将请求传递给 **ASP.NET 应用程序服务器** 进行处理。ASP.NET 反过来管理所请求 Web 表单的执行。

顺便说一下，您应该意识到，如果您使用的是 IIS 7，即使请求不是针对 .aspx 文件，HTTP 请求也可能被发送到 ASP.NET 进行处理。这是因为 IIS 7 提供了将 ASP.NET 与 IIS 服务器集成的模式。使用集成模式的一个优点是，它允许您使用您将在第 19 章中学到的 ASP.NET 身份验证和授权功能来限制对静态网页以及动态网页的访问。要确定 ASP.NET 应用程序是否使用集成模式，您可以使用 *应用程序池*。您可以在附录 B 中了解有关使用 IIS 7 的应用程序池的更多信息。

当 Web 表单执行时，它会处理用户输入的信息并生成 **HTML** 文档。例如，如果 Web 表单从数据库显示数据，它会查询数据库以获取所需信息。然后，它生成包含该信息的页面，该页面由 ASP.NET 返回给 Web 服务器。Web 服务器反过来以 **HTTP** 响应的形式将页面发送回浏览器，浏览器显示该页面。从浏览器请求网页开始到页面发送回客户端结束的整个过程称为 *往返*。

当用户点击控件以启动 **HTTP** 请求时，这被称为“向服务器回发”，称为 *回发*。例如，在图 1-1 中的订单表单中，用户通过在下拉列表中选择一个项目或点击“添加到购物车”按钮来启动回发。然后，使用用户输入到页面中的新值来处理订单页面的 Web 表单。

### 描述

- *动态网页* 是由 Web 表单生成的 HTML 文档。通常，网页会根据浏览器发送到 Web 表单的信息而改变。
- 当 Web 服务器收到对动态网页的请求时，它会在 *应用程序映射* 列表中查找所请求文件的扩展名，以确定哪个应用程序服务器应处理该请求。如果文件扩展名为 .aspx，则请求会传递给 ASP.NET 进行处理。
- 当 *应用程序服务器* 收到请求时，它运行指定的 Web 表单。然后，Web 表单生成 HTML 文档并将其返回给应用程序服务器，应用程序服务器将其传回 Web 服务器，然后传回浏览器。
- 浏览器不知道也不关心 HTML 是从静态 HTML 文件检索的还是由 Web 表单动态生成的。无论哪种方式，浏览器只是显示作为请求结果返回的 HTML。
- 页面显示后，用户可以使用其控件与之交互。其中一些控件允许用户将页面 *发* 回 *服务器*，这称为 *回发*。然后，使用用户输入的数据再次处理页面。
- 从用户请求网页开始到服务器将响应发送回客户端结束的过程称为 *往返*。
- 如果您使用浏览器请求页面时省略 URL 中的文件名，IIS 默认会按以下四个名称查找文件：Default.htm、Default.asp、index.htm 和 iisstart.asp。（如果您使用的是 IIS 7，它还会查找名为 index.html 或 default.aspx 的文件。）如果您希望默认显示另一个页面，您可以将该页面的名称添加到此列表中。有关更多信息，请参阅附录 B（Windows 7 和 Windows Vista）或附录 C（Windows XP）。
