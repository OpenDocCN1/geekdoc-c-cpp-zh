

## 如何编写重定向到自定义错误页面的方法

图20-9展示了在ASP.NET应用程序中发生异常时重定向到自定义错误页面的三种方式。第一个示例展示了如何从try-catch语句重定向到自定义错误页面。这里，对SQL数据源的Insert方法的调用被放置在try块中，因此任何数据库异常都可以在catch块中处理。如果发生异常，catch块将Exception对象添加到会话状态并重定向到错误页面。然后，错误页面可以使用Exception对象获取有关异常的信息。

第二个示例展示了如何使用Page_Error方法捕获页面所有未处理的异常并重定向到自定义错误页面。这里，使用GetLastError方法获取Exception对象。然后，该方法将Exception对象添加到会话状态并重定向到自定义错误页面。

第三个示例展示了如何在global.asax文件中使用Application_Error方法捕获整个应用程序所有未处理的异常。这里，使用GetLastError方法获取Exception对象，并使用Exception对象的InnerException属性获取导致错误的异常。然后，该方法将Exception对象添加到会话状态并重定向到自定义错误页面。

### 在数据库操作期间发生异常时重定向到自定义错误页面的try-catch语句

```
try
{
    SqlDataSource1.Insert();
}
catch (Exception ex)
{
    Session["Exception"] = ex;
    Response.Redirect("ErrorPage.aspx");
}
```

### 重定向到自定义错误页面的Page_Error方法

```
private void Page_Error(object sender, EventArgs e)
{
    Exception ex = Server.GetLastError();
    Session["Exception"] = ex;
    Response.Redirect("ErrorPage.aspx");
}
```

### 在global.asax文件中重定向到自定义错误页面的Application_Error方法

```
void Application_Error(object sender, EventArgs e)
{
    Exception ex = Server.GetLastError().InnerException;
    Session["Exception"] = ex;
    Response.Redirect("ErrorPage.aspx");
}
```

### 说明

-   你可以从try-catch语句、Page_Error方法或global.asax文件中的Application_Error方法重定向到自定义错误页面。
-   在重定向到自定义错误页面之前，应将Exception对象添加到会话状态，以便错误页面可以使用它。
-   如果你在调试模式下运行应用程序并发生未处理的异常，Visual Studio会进入中断模式并显示一个对话框，该对话框描述错误并提供可用于获取有关错误的附加信息的链接。要在显示此对话框时继续程序执行，请单击“继续”按钮。

## 如何使用web.config文件处理HTTP错误

并非所有不可恢复的错误都会导致ASP.NET抛出异常。如图20-11所示，某些错误情况会导致由Web服务器本身处理的HTTP错误。对于这些错误，你可以使用web.config文件中的customErrors元素来指定自定义错误页面。

虽然可能发生许多不同类型的HTTP错误，但此图中列出了常见类型。其中，最常见的是404错误。当用户尝试检索不存在的页面时会发生此错误。在某些情况下，404错误是由页面丢失或页面被重命名引起的。在其他情况下，404错误是由应用程序导航控件中的错误引起的，例如使用不正确URL的超链接。

如图所示，你在web.config文件中为每个想要重定向到自定义错误页面的HTTP错误包含一个error元素。在示例中，这是针对两种错误类型完成的。第一个error元素指定如果发生404错误，应显示名为E404.aspx的页面。第二个元素指定如果发生500错误，应显示名为E500.aspx的页面。

你还可以指定默认错误页面，当发生未在error元素中特别列出的HTTP错误时，将显示该页面。在此图的示例中，defaultRedirect属性指定如果发生404或500以外的HTTP错误，应显示名为DefaultError.aspx的页面。

### 在web.config文件中指定自定义错误页面的customErrors元素

```
<system.web>
  .
  .
  <customErrors mode="On" defaultRedirect="DefaultError.aspx">
    <error statusCode="404" redirect="E404.aspx" />
    <error statusCode="500" redirect="E500.aspx" />
  </customErrors>
  .
  .
</system.web>
```

### 常见的HTTP错误代码

| 代码 | 描述 |
|------|------|
| 401 | 未授权的请求。客户端必须获得授权才能访问该资源。 |
| 403 | 禁止的请求。不允许客户端访问该资源。 |
| 404 | 文件未找到。无法定位该资源。 |
| 500 | 内部服务器错误。这通常是未处理异常的结果。 |

### 说明

-   web.config文件中的customErrors元素允许你指定自定义错误页面，当发生不可恢复的HTTP错误时，这些页面会自动显示。你无需编写任何代码来重定向或转移到这些页面。
-   若要启用自定义错误页面，请将customErrors元素添加到web.config文件的system.web元素中。然后，将mode属性设置为On，并将defaultRedirect属性设置为通用错误页面的名称。
-   若要将自定义错误页面与HTTP错误关联，请添加一个error元素，该元素在statusCode属性中指定HTTP错误代码，并在redirect属性中指定自定义错误页面的名称。
-   你还可以使用网站管理工具将customErrors元素添加到web.config文件中。为此，选择“网站→ASP.NET配置”命令，显示“应用程序”选项卡，单击“定义默认错误页面”链接，然后选择适当的设置。

### 注意

-   如果使用Application_Error方法处理错误，则不应使用customErrors元素。如果这样做，customErrors元素将被忽略。

## 如何处理后退按钮问题

如果用户单击浏览器窗口中的“后退”按钮返回以前的ASP.NET表单，然后发布该表单，应用程序的会话状态可能与该表单不对应。在某些情况下，这可能导致我们称之为*后退按钮问题*的问题。以下主题将向你展示如何处理此问题。

### 后退按钮问题简介

图20-12演示了购物车应用程序中的后退按钮问题。此处，用户购物车的内容存储在会话状态中并显示在页面上。然后，用户删除了两个项目中的一个，这会更改会话状态中的数据。此时，用户改变了主意并单击“后退”按钮，这会再次显示两个项目，即使会话状态只包含一个项目。

如果用户现在继续结帐，订单可能会显示一个项目，而用户认为自己订购了两个项目。但这取决于应用程序的编码方式。在最糟糕的情况下，后退按钮问题可能导致应用程序崩溃。在最好的情况下，单击“后退”按钮根本不会造成问题。

一般来说，处理后退按钮问题有两种方法。第一种是尝试防止页面被保存在浏览器的缓存中。然后，当用户单击“后退”按钮时，无法检索旧页面，并向服务器发送对该页面的新请求。正如你将在下图中看到的，ASP.NET提供了四种方法来实现这一点，但如果用户的浏览器忽略随响应发送的页面缓存设置，这些方法将不起作用。

第二种方法是编写关键Web表单的代码，使其检测用户何时尝试发布不是当前页面的页面。为此，表单可以使用时间戳或随机数来跟踪页面的使用情况。由于没有可靠的方法来防止页面被缓存并通过“后退”按钮检索，因此只要有可能，你就应该使用第二种技术。
