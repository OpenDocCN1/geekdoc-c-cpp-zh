检查UALdict类（UAL代表“无序基于数组的列表”），我们可以很容易地看到insert是一个常数时间操作，因为它只是将新记录插入到列表末尾。然而，find和remove在平均和最坏情况下都需要Θ(n)时间，因为我们需要进行顺序搜索。特别是remove方法必须接触列表中的每条记录，因为一旦找到目标记录，剩余记录必须向下移动以填补空隙。removeAny方法删除列表中的最后一条记录，因此这是一个常数时间操作。

作为替代方案，我们可以使用链表来实现字典。实现方式与图4.32所示非常相似，各函数的渐近代价也应相同。

另一种替代方案是使用有序列表来实现字典。这种方法的好处是我们可能能够通过二分搜索来加快find操作。为此，我们首先必须定义List ADT的一个变体以支持有序列表。基于数组的有序列表的实现如图4.33所示。有序列表与无序列表有些不同，因为它不允许用户控制元素插入的位置。因此，

```
// Dictionary implemented with an unsorted array-based list
template <typename Key, typename E>
class UALdict : public Dictionary<Key, E> {
private:
    AList<KVpair<Key,E> >* list;
public:
    UALdict(int size=defaultSize)    // Constructor
    { list = new AList<KVpair<Key,E> >(size); }
    ~UALdict() { delete list; }        // Destructor
    void clear() { list->clear(); }    // Reinitialize

    // Insert an element: append to list
    void insert(const Key& k, const E& e) {
        KVpair<Key,E> temp(k, e);
        list->append(temp);
    }

    // Use sequential search to find the element to remove
    E remove(const Key& k) {
        E temp = find(k); // "find" will set list position
        if(temp != NULL) list->remove();
        return temp;
    }

    E removeAny() { // Remove the last element
        Assert(size() != 0, "Dictionary is empty");
        list->moveToEnd();
        list->prev();
        KVpair<Key,E> e = list->remove();
        return e.value();
    }

    // Find "k" using sequential search
    E find(const Key& k) const {
        for(list->moveToStart();
            list->currPos() < list->length(); list->next()) {
            KVpair<Key,E> temp = list->getValue();
            if (k == temp.key())
                return temp.value();
        }
        return NULL; // "k" does not appear in dictionary
    }

    int size() // Return list size
    { return list->length(); }
};
```

## 图4.33 有序基于数组的列表的实现

有序列表中的insert方法必须与无序列表中的非常不同。同样，用户不能被允许向列表追加元素。由于这些原因，有序列表不能通过直接从List ADT继承来实现。

SAList类（SAL代表“有序基于数组的列表”）确实继承自AList类；然而，它是将AList类作为受保护的基类来继承的。这意味着SAList可以使用AList的任何成员函数，但这些成员函数不一定对SAList的用户可用。不过，AList的许多成员函数对SAList用户是有用的。因此，AList的大部分成员函数会直接传递给SAList用户而不作更改。例如，代码行

```
AList<KVpair<Key,E> > :: remove;
```

这行代码为SAList的客户端提供了访问AList的remove方法的途径。然而，AList类原有的insert方法被替换了，而AList的append方法被隐藏起来。

字典ADT可以很容易地从SAList类实现，如图4.34所示。字典的insert方法只需调用有序列表的insert方法。find方法使用了第3.5节中最初展示的二分搜索函数的泛化形式。对于长度为n的列表，在有序列表中find的代价是Θ(log n)。这比无序列表中find的代价有了很大改进。不幸的是，insert的代价从无序列表中的常数时间变为有序列表中的Θ(n)时间。字典ADT的有序列表实现是否比无序列表实现更高效，取决于要执行的insert和find操作的相对数量。如果使用的find操作远多于insert操作，那么使用有序列表来实现字典可能是值得的。在两种情况下，remove在最坏和平均情况下都需要Θ(n)时间。即使我们使用二分搜索来减少移除前查找记录的时间，我们仍然需要将列表中的剩余记录向下移动以填补remove操作留下的空隙。

对于两个键，我们还没有妥善解决如何比较它们的问题。一种可能性是直接使用C++内置的基本==、<=和>=运算符。这是我们在图4.32和4.34中展示的字典实现所采用的方法。例如，如果键类型是int，这可以正常工作。然而，如果键是指向字符串或其他任何类型对象的指针，那么这将不会得到预期的结果。当我们比较两个字符串时，我们可能想知道它们在字母顺序上哪个在前，但从标准比较运算符中得到的是哪个对象在内存中先出现。不幸的是，代码可以正常编译，但结果很可能不正确。

在像C++这样支持运算符重载的语言中，我们可以要求字典的使用者为给定的键类型重载==、<=和>=运算符。这一要求就变成了字典类用户的义务。不幸的是，这种义务隐藏在字典代码内部（也可能在用户手册中），而不是暴露在字典的接口中。因此，一些字典用户可能会忽略实现重载，导致意外结果。同样，编译器不会捕获这个问题。
