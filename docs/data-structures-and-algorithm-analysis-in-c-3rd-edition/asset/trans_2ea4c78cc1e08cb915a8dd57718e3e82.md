数据库的每条记录通常都有一个唯一的标识符，称为主键。例如，一组人事记录的主键可能是个人的社会安全号码或身份证号码。不幸的是，ID 号码通常是不方便用于搜索的值，因为搜索者不太可能知道它。相反，搜索者可能知道所需员工的姓名。或者，搜索者可能有兴趣查找所有薪水在某一范围内的员工。如果这些是数据库的典型搜索请求，那么姓名和薪水字段就值得分别建立索引。然而，姓名和薪水索引中的键值可能不是唯一的。

像薪水这样的键字段，其中特定的键值可能在多条记录中重复，称为次要键。大多数搜索都是使用次要键执行的。次要键索引（或更简单地称为次要索引）会将次要键值与具有该次要键值的每条记录的主键关联起来。此时，可以直接搜索整个数据库以查找具有该主键的记录，或者可能存在主键索引（或主索引），它将每个主键值与磁盘上实际记录的指针关联起来。在后一种情况下，只有主索引提供磁盘上实际记录的位置，而次要索引则引用主索引。

索引是组织大型数据库的重要技术，并且已经开发出许多索引方法。第 9.4 节讨论了通过哈希的直接访问。按键值排序的简单列表也可以作为记录文件的索引。下一节将讨论按排序列表对磁盘文件进行索引。不幸的是，排序列表对于插入和删除操作并不理想。

索引的第三种方法是树索引。树通常用于组织必须支持记录插入、删除和键范围搜索的大型数据库。第 10.2 节简要描述了 ISAM，这是解决必须支持记录插入和删除的大型数据库存储问题的初步尝试。它的缺点有助于说明树索引技术的价值。第 10.3 节介绍了与树索引相关的基本问题。第 10.4 节介绍了 2-3 树，一种平衡树结构，是第 10.5 节中 B 树的简单形式。B 树是大型磁盘数据库和文件系统实现中最广泛使用的索引方法。由于它们具有如此大的实用意义，因此发明了许多变体。第 10.5 节首先讨论通常仅称为“B 树”的变体。第 10.5.1 节介绍了最广泛实现的变体，B⁺-树。

## 10.1 线性索引

线性索引是一个索引文件，按序列组织键/指针对，其中键按排序顺序排列，指针要么（1）指向磁盘上完整记录的位置，（2）指向主索引中主键的位置，或（3）实际上是主键的值。根据其大小，线性索引可能存储在主内存或磁盘中。线性索引提供了许多优点。它提供了对可变长度数据库记录的便捷访问，因为索引文件中的每个条目都包含一个定长键字段和一个指向（可变长度）记录开头的定长指针，如图 10.1 所示。线性索引还允许对数据库记录进行高效搜索和随机访问，因为它适合于二分搜索。

如果数据库包含足够多的记录，线性索引可能太大而无法存储在主内存中。这使得索引的二分搜索成本更高，因为搜索过程通常需要多次磁盘访问。解决此问题的一种方法是存储一个二级线性索引在主内存中，指示索引文件中哪个磁盘块存储所需的键。例如，磁盘上的线性索引可能驻留在一系列 1024 字节的块中。如果线性索引中的每个键/指针对需要 8 字节（4 字节键和 4 字节指针），则每个块存储 128 个键/指针对。存储在主内存中的二级索引由一个简单表组成，存储线性索引文件中每个块的第一位置的键值。这种安排如图 10.2 所示。如果线性索引需要 1024 个磁盘块（1MB），二级索引仅包含 1024 个条目，每个磁盘块一个。要找到包含所需搜索键值的磁盘块，首先搜索 1024 条目表以找到小于或等于搜索键的最大值。这将搜索引导到索引文件中的正确块，然后将其读入内存。此时，该块内的二分搜索将产生指向数据库中实际记录的指针。因为

图 10.2 一个简单的两级线性索引。线性索引存储在磁盘上。较小的二级索引存储在主内存中。二级索引中的每个元素存储索引文件对应磁盘块中的第一个键值。在此示例中，线性索引的第一个磁盘块存储 1 到 2001 范围内的键，第二个磁盘块存储 2003 到 5688 范围内的键。因此，二级索引的第一个条目是键值 1（线性索引第一个块中的第一个键），而二级索引的第二个条目是键值 2003。

二级索引存储在主内存中，通过此方法访问记录需要两次磁盘读取：一次从索引文件读取，一次从数据库文件读取实际记录。

每当向数据库插入或从数据库删除记录时，所有关联的次要索引都必须更新。对线性索引的更新成本很高，因为可能需要移动整个数组的内容。另一个问题是具有相同次要键的多个记录会在索引中重复该键值。当次要键字段有许多重复项时，例如当它具有有限范围时（例如，用于在少量可能的职位类别中指示职位类别的字段），这种重复可能会浪费大量空间。

对简单排序数组的一个改进是二维数组，其中每一行对应一个次要键值。一行包含其记录具有指示次要键值的主键。图 10.3 说明了这种方法。现在没有次要键值的重复，可能带来相当大的空间节省。插入和删除的成本降低了，因为只需要调整表的一行。注意，当添加新的次要键值时，会向数组添加新行。这可能导致移动许多记录，但在适合使用这种安排的应用中这种情况很少发生。

这种方法的缺点是数组必须具有固定大小，这对可能与特定次要键关联的主键数量施加了上限。此外，那些记录数少于数组宽度的次要键将浪费其行的剩余部分。更好的方法是有一个一维的次要键值数组，其中每个次要键都与一个链表关联。如果索引存储在主内存中，这效果很好，但在存储在磁盘上时效果不佳，因为给定键的链表可能分散在多个磁盘块中。
