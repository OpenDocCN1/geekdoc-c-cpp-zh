
“高效。”在这种意义上，上述所有因素都应在比较中抵消掉，因为它们对两种算法同样适用。

如果你真正希望了解一个算法的运行时间，那么除了机器速度、编程语言、编译器等因素之外，还有其他更合适的因素需要考虑。理想情况下，我们会在标准基准条件下测量算法的运行时间。然而，除了在某种计算机上运行该算法的实现之外，我们无法可靠地计算运行时间。唯一的选择是使用其他度量作为运行时间的替代指标。

在估计算法性能时，首要考虑的是算法处理特定规模输入所需的基本操作数量。“基本操作”和“规模”这两个术语都相当模糊，并且取决于所分析的算法。规模通常指处理输入的数量。例如，在比较排序算法时，问题规模通常由待排序的记录数量来衡量。基本操作必须具有这样的性质：其完成时间不依赖于操作数的特定值。在大多数编程语言中，两个整型变量的相加或比较就是基本操作的例子。而求一个包含 n 个整数的数组的元素和则不是，因为其代价依赖于 n 的值（即输入的规模）。

### 示例 3.1

考虑一个简单的算法，用于解决在 n 个整数的数组中查找最大值的问题。该算法依次查看每个整数，并保存迄今为止所见最大值的位置。该算法称为最大值顺序查找，由以下函数说明：

```cpp
// Return position of largest value in "A" of size "n"
int largest(int A[], int n) {
    int currlarge = 0; // Holds largest element position
    for (int i=1; i<n; i++) // For each array element
        if (A[currlarge] < A[i]) // if A[i] is larger
            currlarge = i; // remember its position
    return currlarge; // Return largest position
}
```

这里，问题的规模是 n，即数组 A 中存储的整数个数。基本操作是将一个整数的值与迄今为止所见最大值的值进行比较。可以合理地假设，进行一次这样的比较需要固定的时间，无论这两个整数的值或它们在数组中的位置如何。

由于影响运行时间的最重要因素通常是输入的规模，对于给定的输入规模 n，我们通常将运行算法的时间 T 表示为 n 的函数，记为 T(n)。我们始终假设 T(n) 是非负值。

设 c 为函数 largest 中比较两个整数所需的时间。我们现在并不关心 c 的具体值是多少。我们也不关心递增变量 i 所需的时间（因为对数组中的每个值都必须执行此操作），不关心找到更大值时实际赋值所需的时间，也不关心初始化 currlarge 所花费的一点额外时间。我们只希望对算法执行所需的时间有一个合理的近似。因此，运行 largest 的总时间大约为 cn，因为我们必须进行 n 次比较，每次比较耗费 c 时间。我们说函数 largest（以及推广而言，任何典型实现下的最大值顺序查找算法）的运行时间由以下方程表示：

T(n) = cn。

这个方程描述了最大值顺序查找算法运行时间的增长率。

### 示例 3.2

将一个整数数组的第一个值赋给一个变量的语句，其运行时间就是复制第一个数组值所需的时间。我们可以假设这个赋值操作花费的时间是恒定的，与值无关。设 c₁ 为复制一个整数所需的时间。在典型计算机上，无论数组多大（在合理的内存和数组大小条件下），从数组第一个位置复制值的时间始终是 c₁。因此，该算法的方程很简单：

T(n) = c₁，

这表明输入规模 n 对运行时间没有影响。这称为常数运行时间。

### 示例 3.3

考虑以下代码：

```cpp
sum = 0;
for (i=1; i<=n; i++)
    for (j=1; j<=n; j++)
        sum++;
```

这段代码片段的运行时间是多少？显然，当 n 较大时，运行时间会更长。此示例中的基本操作是对变量 sum 的递增操作。我们可以假设递增操作需要常数时间；设这个时间为 c₂。（我们可以忽略初始化 sum 所需的时间，以及递增循环计数器 i 和 j 所需的时间。在实践中，这些开销可以安全地合并到时间 c₂ 中。）递增操作的总次数是 n²。因此，我们说运行时间为 T(n) = c₂n²。

## 3.2 最佳、最差和平均情况

考虑求 n 的阶乘的问题。对于这个问题，给定“规模”只有一个输入（也就是说，每个规模 n 只有一个实例）。现在考虑示例 3.1 中的最大值顺序查找算法，该算法总是检查数组中的每一个值。这个算法处理给定规模 n 的许多输入。也就是说，任何给定规模都可能有许多不同的数组。然而，无论算法查看什么规模为 n 的数组，其代价总是相同的，因为它总是依次查看数组中的每个元素一次。

对于某些算法，给定规模的不同输入可能需要不同的时间。例如，考虑在一个包含 n 个整数的数组中搜索特定值 K 的问题（假设 K 在数组中恰好出现一次）。顺序查找算法从数组的第一个位置开始，依次查看每个值，直到找到 K。一旦找到 K，算法就停止。这与示例 3.1 中的最大值顺序查找算法不同，后者总是检查数组中的每个值。

顺序查找算法的可能运行时间范围很广。数组中的第一个整数可能是 K，因此只检查一个整数。在这种情况下，运行时间很短。这是该算法的最佳情况，因为顺序查找不可能检查少于一个值。或者，如果数组的最后一个位置包含 K，那么运行时间相对较长，因为算法必须检查 n 个值。这是该算法的最差情况，因为顺序查找永远不会检查超过 n 个值。如果我们把顺序查找实现为一个程序，并在许多不同的大小为 n 的数组上多次运行，或者在同一数组中搜索许多不同的 K 值，我们期望算法平均在找到所需值之前会检查数组的一半。平均而言，算法检查大约 n/2 个值。我们称之为该算法的平均情况。

在分析算法时，我们应该研究最佳、最差还是平均情况？通常我们对最佳情况不感兴趣，因为它可能很少发生，而且通常过于乐观，无法公平地描述算法的运行时间。换句话说，基于最佳情况的分析不太可能代表算法的行为。然而，在极少数情况下，最佳情况分析是有用的——特别是当最佳情况发生的概率很高时。在第 7 章中，你将看到一些例子，其中利用某种排序算法的最佳情况运行时间会使另一种算法更高效。
