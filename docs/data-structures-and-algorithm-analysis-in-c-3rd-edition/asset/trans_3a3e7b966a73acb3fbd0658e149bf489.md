

```
// Floyd’s all-pairs shortest paths algorithm
// Store the pair-wise distances in "D"
void Floyd(Graph* G) {
    for (int i=0; i<G->n(); i++) // Initialize D with weights
        for (int j=0; j<G->n(); j++)
            if (G->weight(i, j) != 0) D[i][j] = G->weight(i, j);
    for (int k=0; k<G->n(); k++) // Compute all k paths
        for (int i=0; i<G->n(); i++)
            for (int j=0; j<G->n(); j++)
                if (D[i][j] > (D[i][k] + D[k][j]))
                    D[i][j] = D[i][k] + D[k][j];
}
```

显然，该算法需要 Θ(|V|³) 的运行时间，并且它是稠密图的最佳选择，因为它（相对）快速且易于实现。

## 16.2 随机化算法

在本节中，我们将考虑向算法中引入随机性如何可能加速处理，尽管这或许会以准确性为代价。但通常我们可以在加速算法的同时，将出错的可能性降到任意低的水平。

### 16.2.1 用于查找较大值的随机化算法

在 15.1 节中，我们确定了在未排序列表中查找最大值所需的下界成本为 Ω(n)。这是确信已找到最大值所需的最少时间。但是，如果愿意放宽对确定性的要求呢？第一个问题是：我们指的是什么？“确定性”有很多方面，我们可以通过多种方式放宽要求。

对于一个算法输出 X 作为最大值而真实最大值为 Y 的情况，我们可以要求多种可能的保证。到目前为止，我们一直假设要求 X 等于 Y。这称为解决该问题的精确算法或确定性算法。我们可以放宽这一要求，只要求 X 的排名“接近”Y 的排名（也许在固定距离或百分比之内）。这称为近似算法。我们可以要求 X “通常”是 Y。这称为概率算法。最后，我们可以只要求 X 的排名“通常”“接近”Y 的排名。这称为启发式算法。

我们还可以选择以不同方式牺牲可靠性来换取速度。这类算法也有相应的名称。

- 1. 拉斯维加斯算法：我们总是能找到最大值，并且“通常”能很快找到。这类算法保证结果正确，但不保证运行时间快。
- 2. 蒙特卡洛算法：我们要么快速找到最大值，要么根本得不到答案（但很快）。这类算法虽然运行时间良好，但结果没有保证。

下面是一个查找较大值的算法示例，它放弃了获得最佳值的保证，以换取更快的运行时间。这是一个概率算法的例子，因为它包含受随机事件影响的步骤。随机选择 m 个元素，并从中选出最好的一个作为答案。对于较大的 n，如果 m ≈ log n，答案就相当不错。成本是 m − 1 次比较（因为我们必须在 m 个值中找出最大值）。但我们并不确定会得到什么。不过我们可以估计，其排名约为 mn/(m+1)。例如，如果 n = 1,000,000 且 m = log n = 20，那么我们预计这 20 个随机选择的值中的最大值会位于 n 个值中的前 5%。

接下来，考虑一个略有不同的问题，目标是选出 n 个值中上半部分的一个数。我们可以从前 (n+1)/2 个值中选出最大值，成本是 n/2 次比较。我们能做得更好吗？如果我们想保证得到正确答案，就不能。但如果我们愿意接受近乎确定而非绝对确定，我们就可以在速度上获得很大提升。

作为替代方案，考虑这个概率算法：随机挑选 2 个数并选择较大的那个。该数有 3/4 的概率位于上半部分（因为只有当两个数都恰好落在下半部分时，它才不在上半部分）。3/4 的概率还不够好吗？那我们只需挑选更多的数！对于 k 个数，最大值位于上半部分的概率是 1 − 1/2^k，这与我们从多少个 n 中选取无关，只要 n 远大于 k 即可（否则机会可能变得更大）。如果我们挑选 10 个数，那么失败的概率只有 2^10 = 1024 分之一。如果我们真的想确保万无一失，因为生命取决于能否从上半部分抽到一个数呢？如果我们挑选 30 个数，那么十亿次中只可能失败一次。如果我们挑选足够多的数，那么选到一个小数的概率比计算过程中电源失效的概率还要低。挑选 100 个数意味着失败概率只有 10^30 分之一，这比你能想象到的任何可能中断该过程的灾难的概率都要低。

### 16.2.2 跳跃表

本节介绍一种称为跳跃表（Skip List）的概率搜索结构。与二叉搜索树（BST）类似，跳跃表旨在克服基于数组和链表的基本限制：搜索或更新操作都需要线性时间。跳跃表是一种概率数据结构的例子，因为它的某些决策是随机做出的。

跳跃表为 BST 及相关树结构提供了一种替代方案。BST 的主要问题是它很容易变得不平衡。第 10 章的 2-3 树保证无论数据值以何种顺序插入都能保持平衡，但实现起来相当复杂。第 13 章介绍了 AVL 树和伸展树，它们也保证提供良好的性能，但与 BST 相比，代价是增加了复杂度。跳跃表比已知的平衡树结构更容易实现。跳跃表并不保证提供良好的性能（其中良好性能定义为 Θ(log n) 的搜索、插入和删除时间），但它会以极高的概率提供良好的性能（这与 BST 不同，BST 有相当大的概率表现不佳）。因此，它在实现难度和性能之间提供了一个很好的折衷。

图 16.2 说明了跳跃表背后的概念。图 16.2(a) 展示了一个简单的链表，其节点按键值排序。搜索有序链表需要沿着链表逐个节点移动，平均情况下访问 Θ(n) 个节点。如果我们每隔一个节点添加一个指针，从而可以跳过交替节点，如图 16.2(b) 所示，会怎样？将只有一个指针的节点定义为 0 级跳跃表节点，将有两个指针的节点定义为 1 级跳跃表节点。

搜索时，沿着 1 级指针前进，直到找到一个大于搜索键的值，然后回到前一个 1 级节点，如有必要，再使用 0 级指针前进一个节点。这实际上将工作量减半。我们可以继续以这种方式向选定的节点添加指针——每第四个节点给第三个指针，每第八个节点给第四个指针，依此类推——直到对于包含 n 个节点的链表，在第一个和中间节点达到 log n 个指针的极致，如图 16.2(c) 所示。搜索时，从最顶层的指针开始，尽可能前进，一次跳过许多节点。然后，按需要逐步切换到越来越短的步长。通过这种安排，最坏情况下的访问次数是 Θ(log n)。

我们将为每个跳跃表节点存储一个名为 forward 的数组，用于存储指针，如图 16.2(c) 所示。forward[0] 位置存储 0 级指针，forward[1] 存储 1 级指针，依此类推。跳跃表对象包含数据成员 level，用于存储当前跳跃表中任何节点的最高层级。跳跃表存储一个名为 head 的头节点，其中包含 level 个指针。查找函数如图 16.3 所示。

在图 16.2(c) 的跳跃表中查找值为 62 的节点时，从头节点开始。沿着头节点在 level 层的指针前进，在本例中该层是第 2 层。该指针指向值为 31 的节点。因为 31 小于 62，所以我们接着尝试从 31 号节点的 forward[2] 指针出发，到达 69。因为 69 大于 62，我们不能继续前进，而必须将当前层级计数器递减为 1。接着，我们尝试沿着 31 的 forward[1] 到达值为 58 的节点。因为 58 小于 62，我们沿着 58 的 forward[1] 指针到达 69。因为 69 太大，我们沿着 58 的 0 级指针到达 62。因为 62 不小于 62，我们退出 while 循环，向前移动一步到值为 62 的节点。
