图 12.15 使用句柄进行动态内存管理。内存管理器在收到内存请求时返回句柄的地址。句柄存储实际内存块的地址。这样，内存块可以被移动（句柄中的地址随之更新），而不会干扰应用程序。

对用户而言，这比让整个系统停滞要好。这里的假设是其他进程最终会终止，从而释放内存。

另一种选择可能是为内存管理器分配更多内存。在内存管理器作为更大系统的一部分的分段内存分配系统中，这可能是一个可行的选择。在用 C++ 编写的实现自身内存管理器的程序中，可能可以从系统级的 new 操作符获取更多内存，就像第 4.1.2 节中的空闲列表所做的那样。

我们将要考虑的最后一个失败策略是垃圾回收。考虑以下一系列语句。

```
int* p = new int[5];
int* q = new int[10];
p = q;
```

在 Java 中这不会有问题（由于自动垃圾回收），但在 C++ 等语言中，这被视为不良做法，因为第三次赋值导致原本分配给 p 的空间丢失。该空间无法再被程序使用。这种丢失的内存被称为垃圾，也称为内存泄漏。当没有任何程序变量指向一块空间时，就无法再访问该空间。当然，如果另一个变量先被赋值指向 p 的空间，然后再重新赋值 p，就不会产生垃圾。

某些编程语言对垃圾采取不同的看法。特别是 LISP 编程语言使用图 12.5 中的多链表表示形式，所有存储都以具有两个指针的内部节点或原子形式存在。图 12.16 显示了一个典型的 LISP 结构集合，由名为 A、B 和 C 的变量引领，并附带一个空闲列表。

![](img/7ea3c39173f146f675b63b146d1535f3_449_0.png)

图 12.16 LISP 列表变量示例，包括系统空闲列表。

正在使用哪些部分以及哪些部分是垃圾。特别是，会保留所有程序变量的列表，任何无法从这些变量之一到达的内存位置都被视为垃圾。当垃圾回收器执行时，所有未使用的内存位置都会被放入自由存储以供将来访问。这种方法的好处是它允许轻松收集垃圾。它的缺点是从用户角度来看，系统必须不时停顿以执行垃圾回收。例如，在 Emacs 文本编辑器中可以注意到垃圾回收，它通常用 LISP 实现。偶尔用户必须等待片刻，让内存管理系统执行垃圾回收。

Java 编程语言也使用垃圾回收。与 LISP 一样，在 Java 中通常的做法是根据需要分配动态内存，并在之后丢弃对该内存的所有引用。垃圾回收器负责在必要时回收此类未使用的空间。这可能需要在程序运行时花费额外时间，但它使程序员的生活变得相当容易。相比之下，许多用 C++ 编写的庞大应用程序（甚至是常用的商业软件）都包含内存泄漏，随着时间的推移会导致程序失败。

已经使用了几种垃圾回收算法。其中之一是引用计数算法。这里，每个动态分配的内存块都包含一个计数字段的空间。每当指针指向一个内存块时，引用计数就会增加。每当指针从一个内存块移开时，引用计数就会减少。如果计数变为零，则该内存块被视为垃圾并立即放入自由存储。这种方法的好处是它不需要显式的垃圾回收阶段，因为信息在变成垃圾时立即放入自由存储。

![](img/7ea3c39173f146f675b63b146d1535f3_450_0.png)

图 12.17 垃圾循环示例。

循环中的所有内存元素都有非零引用计数，因为每个元素都有一个指向它的指针，即使整个循环是垃圾（即程序中没有任何静态变量指向它）。

引用计数被 UNIX 文件系统使用。文件可以有多个名称，称为链接。文件系统会记录指向每个文件的链接数。每当文件被“删除”时，实际上只是将其链接字段减少一个。如果文件还有另一个链接，则文件系统不会回收空间。当链接数降为零时，文件的空间即可供重用。

引用计数有几个主要缺点。首先，每个内存对象都必须维护一个引用计数。当对象较大时，例如文件，这效果很好。然而，在 LISP 等系统中效果不佳，在该系统中内存对象通常由两个指针或一个值（原子）组成。另一个主要问题是当垃圾包含循环时出现。考虑图 12.17。这里每个内存对象都被指向一次，但对象集合仍然是垃圾，因为没有指针指向该集合。因此，引用计数仅在内存对象以无环方式链接时才有效，例如 UNIX 文件系统，其中文件只能组织成 DAG。

另一种垃圾回收方法是标记/清除策略。这里，每个内存对象只需要一个标记位，而不是引用计数字段。当自由存储耗尽时，会进行单独的垃圾回收阶段，步骤如下。

1. 清除所有标记位。
2. 从系统静态变量列表中的每个变量开始，沿着指针执行深度优先搜索（DFS）。DFS 过程中遇到的每个内存元素都会将其标记位置为开启。
3. 对内存池进行“清除”，访问所有元素。未标记的元素被视为垃圾并放入自由存储。

标记/清除方法的优点是它需要的空间比引用计数少，并且适用于循环。然而，有一个主要缺点。这是一种进行处理所需的“隐藏”空间需求。DFS 是一种递归算法：要么必须递归实现，在这种情况下编译器的运行时系统维护一个栈，要么内存管理器可以维护自己的栈。如果所有内存都包含在单个链表中会怎样？那么递归的深度（或栈的大小）就是内存单元的数量！不幸的是，DFS 栈的空间必须在最糟糕的可能时间可用，即当空闲内存耗尽时。

图 12.18 Deutsch-Schorr-Waite 垃圾回收算法示例。（a）初始多链表结构。（b）在垃圾回收算法处理链接节点 5 的瞬间，图（a）的多链表结构。从变量 prev 到结构头节点的指针链已被垃圾回收算法（临时）创建。

幸运的是，一个巧妙的技术允许在不需要额外栈空间的情况下执行 DFS。相反，被遍历的结构被用来保存栈。在每次向遍历更深处迈进时，我们不是将指针存储在栈上，而是“借用”正在跟随的指针。该指针被设置为指向我们在上一步中刚刚来的节点，如图 12.18 所示。每个被借用的指针存储一个额外的位，用来告诉我们是从链接节点指向的左分支还是右分支下来。在任何给定瞬间，我们只沿着从根开始的一条路径向下，并且可以沿着指针的轨迹返回。当我们返回时（相当于弹出递归栈），我们将指针设置回其原始位置，以便将结构恢复到原始状态。这被称为 Deutsch-Schorr-Waite 垃圾回收算法。
