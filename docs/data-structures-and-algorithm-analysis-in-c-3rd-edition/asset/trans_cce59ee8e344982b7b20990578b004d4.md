

T(n) = n p_n + Σ_{i=0}^{n-1} (i + 1) p_i.

如果我们假设所有 p_i 都相等（p_0 除外），这个方程会变成什么样？

T(n) = p_n n + Σ_{i=0}^{n-1} (i + 1) p
= p_n n + p Σ_{i=1}^{n} i
= p_n n + p n(n + 1)/2
= p_n n + (1 - p_n)/n * n(n + 1)/2
= [n + 1 + p_n (n - 1)] / 2

根据 p_n 的值，有 (n+1)/2 ≤ T(n) ≤ n。

对于会被反复搜索的大型记录集合，顺序搜索慢得令人无法接受。减少搜索时间的一种方法是对记录进行预处理，即先对它们排序。给定一个有序数组，相比简单的线性搜索，一个明显的改进是检查 L 中当前元素是否大于 K。如果是，那么我们就知道 K 不可能出现在数组后面的位置，于是可以提前退出搜索。但这仍然不能改善算法的最坏情况代价。

我们还可以观察到，如果先查看有序数组 L 中的位置 1，发现 K 更大，那么我们就排除了位置 0 和位置 1。因为“更多”通常更好，如果我们查看 L 中的位置 2，发现 K 还是更大呢？这样一来，一次比较就排除了位置 0、1 和 2。如果将这一做法推到极致，先查看 L 中的最后一个位置，发现 K 更大呢？那么一次比较就能让我们知道 K 不在 L 中。这个结果确实很有用，但“我们应当总是从最后一个位置开始查看”这一结论有什么问题呢？问题在于，虽然有时我们会学到很多（一次比较可能让我们知道 K 不在列表中），但通常我们只能学到一点点（最后一个元素不是 K）。

于是问题变成了：一次跳多少才是合适的？这引导我们得到一种称为“跳跃搜索”的算法。对于某个值 j，我们检查 L 中每第 j 个元素，即检查 L[j]、L[2j] 等等。只要 K 大于我们正在检查的值，就继续向前。当遇到 L 中大于 K 的值时，就对长度为 j − 1 的那一段进行线性搜索，因为如果 K 在列表中，我们知道这一段将 K 括在其中。

如果我们定义 m 使得 m j ≤ n < (m + 1) j，那么该算法的总代价至多为 m + j − 1 次三路比较。（它们是三路的，因为在每次将 K 与某个 L[i] 比较时，我们需要知道 K 是小于、等于还是大于 L[i]。）因此，对于 n 个元素、跳跃大小为 j 的运行代价为

T(n, j) = m + j − 1 = ⌊ n / j ⌋ + j − 1。

我们可以为 j 选择的最佳值是什么？我们要最小化代价：

min_{1 ≤ j ≤ n} { ⌊ n / j ⌋ + j − 1 }

求导数并令 f′(j) = 0 来找到最小值，即 j = √n。在这种情况下，最坏情况代价约为 2√n。

这个例子涉及算法设计的一个基本原则。我们要在“选择子列表”所需的工作与“搜索子列表”所需的工作之间取得平衡。一般来说，让各个子问题的工作量大致相等是一个好策略。这是一个分治算法的例子。

如果我们把这个想法扩展到三个层级会怎样？我们首先以某个大小 j 跳跃，找到一个长度为 j − 1 的子列表，其两端值将 K 括在中间。然后以某个更小的尺寸（比如 j1）在这个子列表中跳跃。最后，一旦找到长度为 j1 − 1 的括号式子列表，就进行顺序搜索来完成整个过程。

先做两层跳跃，然后进行顺序搜索，这听起来可能有些复杂。虽然做两层算法（即跳跃搜索先跳跃以找到子列表，再对该子列表进行顺序搜索）可能是合理的，但三层算法几乎从来都不合理。相反，当层数超过两层时，我们几乎总是通过递归来推广。这就引出了有序数组最常用的搜索算法——第 3.5 节描述的二分搜索。

我们现在证明这与以下表达式相同：

$$\sum_{i=1}^{\sqrt{n}} \P(\text{至少需要 } i \text{ 次探测})$$

= 1 + (1 - \P_1) + (1 - \P_1 - \P_2) + \cdots + \P_{\sqrt{n}}

= (\P_1 + \cdots + \P_{\sqrt{n}}) + (\P_2 + \cdots + \P_{\sqrt{n}}) + (\P_3 + \cdots + \P_{\sqrt{n}}) + \cdots 

= 1\P_1 + 2\P_2 + 3\P_3 + \cdots + \sqrt{n}\P_{\sqrt{n}}

我们需要至少两次探测来确定边界，所以代价为

$$2 + \sum_{i=3}^{\sqrt{n}} \P(\text{至少需要 } i \text{ 次探测}).$$

我们现在利用一个称为“切比雪夫不等式”的有用结论。切比雪夫不等式说明，P(恰好需要 i 次探测)（即 P_i）满足

$$\P_i \leq \frac{p(1 - p)n}{(i - 2)^2} \leq \frac{1}{4(i - 2)^2}$$

因为对于任意概率 p，有 p(1 - p) ≤ 1/4。这里假设数据是均匀分布的。因此，探测次数的期望值为

$$2 + \sum_{i=3}^{\sqrt{n}} \frac{1}{4(i - 2)^2} < 2 + \frac{1}{4} \sum_{i=1}^{\infty} \frac{1}{i^2} = 2 + \frac{1}{4} \frac{\pi^2}{6} \approx 2.4112$$

QBS 比二分搜索更好吗？理论上是这样，因为 O(log log n) 的增长比 O(log n) 慢。然而，这里的情况说明了渐近复杂度模型在某些实际场景中的局限。是的，c1 log n 确实比 c2 log log n 增长得快。事实上，它是指数级地更快！但即便如此，对于实际的输入规模，绝对代价差异相当小。因此，常数因子可能起作用。首先我们比较 lg lg n 和 lg n。

| n | lg n | lg lg n | 倍数差异 |
| --- | --- | --- | --- |
| 16 | 4 | 2 | 2 |
| 256 | 8 | 3 | 2.7 |
| 2^{16} | 16 | 4 | 4 |
| 2^{32} | 32 | 5 | 6.4 |

降低算法的增长率并不总是实际的。每个问题都有一个“实用性窗口”，因为我们对于想要解决的输入规模有一个实际限制。如果我们的问题规模永远不会增长得太大，那么即使能多减少一个 log 因子，也可能无关紧要，因为两个算法的常数因子差异可能超过输入规模的对数的对数。

对于我们的两个算法，让我们进一步查看实际使用的比较次数。二分搜索总共需要大约 log n − 1 次比较。二次二分搜索（QBS）需要大约 2.4 lg lg n 次比较。如果我们将这一观察纳入表中，就能得到关于相对差异的一幅不同图景。

| n | lg n − 1 | 2.4 lg lg n | 倍数差异 |
|---|---|---|---|
| 16 | 3 | 4.8 | 更差 |
| 256 | 7 | 7.2 | ≈相同 |
| 64K | 15 | 9.6 | 1.6 |
| 2³² | 31 | 12 | 2.6 |

但我们还没有结束。这只是原始比较次数的统计。二分搜索本质上比 QBS 简单得多，因为二分搜索在每次比较前只需计算数组的中点位置，而二次二分搜索必须计算一个插值点，这更昂贵。因此 QBS 的常数因子甚至更高。

不仅平均而言常数因子更差，而且 QBS 比二分搜索更依赖于良好的数据分布才能获得好的性能。例如，假设你在电话簿中查找名字“Young”。通常你会翻到书的后半部分。如果你找到一个以‘Z’开头的名字，你可能会往前翻一点点。如果你找到的下一个名字也是以‘Z’开头，你会再往前翻一点。如果这本电话簿很特别，其中一半条目都以‘Z’开头，那么你就需要多次往前翻，每次从搜索中排除的记录都相对较少。在极端情况下，如果键值的分布被估算得很差，插值搜索的性能可能并不比顺序搜索好多少。

虽然事实证明 QBS 并不是一种实用的算法，但这并不是典型情况。幸运的是，算法的增长率通常表现良好，因此渐近算法分析几乎总能为我们提供关于两种算法中哪一个更好的实际指示。
