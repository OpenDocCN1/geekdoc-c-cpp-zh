
```cpp
template <typename E, typename Comp>
void qsort(E A[], int i, int j) { // Quicksort
    if (j <= i) return; // Don't sort 0 or 1 element
    int pivotindex = findpivot(A, i, j);
    swap(A, pivotindex, j);     // Put pivot at end
    // k will be the first position in the right subarray
    int k = partition<E,Comp>(A, i-1, j, A[j]);
    swap(A, k, j);              // Put pivot in place
    qsort<E,Comp>(A, i, k-1);
    qsort<E,Comp>(A, k+1, j);
}
```

## 图7.11 快速排序的实现

基准值被放在数组的末尾（位置 j）。因此，partition 不能影响数组位置 j 的值。分区完成后，基准值被放在位置 k，这是它在最终有序数组中的正确位置。通过这种方式，我们保证了至少有一个值（基准值）不会在 qsort 的递归调用中被处理。即使选择了一个糟糕的基准值，导致基准值的一侧分区完全为空，较大的分区也至多包含 n−1 个元素。

选择基准值有很多方法。最简单的是使用第一个键值。然而，如果输入是有序的或逆序的，这会导致较差的分区，所有值都落在基准值的一侧。更好的做法是随机选择一个值，从而减少不良输入顺序影响排序的机会。不幸的是，使用随机数生成器的开销相对较大，而选择数组的中间位置也能达到几乎相同的效果。下面是一个简单的 findpivot 函数：

```cpp
template <typename E>
inline int findpivot(E A[], int i, int j)
{ return (i+j)/2; }
```

现在我们来讨论 partition 函数。如果我们事先知道有多少个键值小于基准值，partition 就可以简单地将键值小于基准值的元素复制到数组的低端，将键值较大的元素复制到高端。由于我们事先并不知道有多少个键值小于基准值，我们使用一种巧妙的算法：从子数组的两端向内移动索引，在必要时交换数值，直到两个索引相遇。图7.12 展示了 partition 步骤的 C++ 实现。

```cpp
template <typename E, typename Comp>
inline int partition(E A[], int l, int r, E& pivot) {
    do {                    // Move the bounds inward until they meet
        while (Comp::prior(A[++l], pivot));  // Move l right and
        while ((l < r) && Comp::prior(pivot, A[--r])); // r left
        swap(A, l, r);          // Swap out-of-place values
    } while (l < r);            // Stop when they cross
    return l;       // Return first position in right partition
}
```

快速排序的最佳情况发生在 findpivot 始终将数组分成相等的两半时。如图7.14所示，快速排序反复将数组分割成更小的分区。在最佳情况下，结果将是有 log n 层分区，顶层有一个大小为 n 的数组，第二层有两个大小为 n/2 的数组，下一层有四个大小为 n/4 的数组，依此类推。因此，在每一层，该层的所有分区步骤总工作量均为 n，当快速排序找到完美的基准值时，总成本为 n log n。

快速排序的平均情况行为介于最坏情况和最佳情况这两个极端之间。平均情况分析考虑所有可能的输入排列的成本，将这些成本求和后除以情况数量。我们做一个合理的简化假设：在每一次分区步骤中，基准值等可能地落在（有序）数组中的任意位置。换句话说，基准值等可能地将数组分成大小为 0 和 n−1、1 和 n−2 等等的分区。

根据这一假设，平均情况成本由以下方程计算：

```
T(n) = c n + 1/n Σ_{k=0}^{n-1} [T(k) + T(n - 1 - k)],   T(0) = T(1) = c.
```

这个方程是一个递推关系的形式。递推关系在第2章和第14章中讨论，本节中的这个递推关系在第14.2.4节中求解。这个方程说明：基准值将数组分成大小为 0 和 n−1 的子数组的概率为 1/n，分成大小为 1 和 n−2 的子数组的概率为 1/n，依此类推。表达式“T(k) + T(n − 1 − k)”是对大小分别为 k 和 n−1−k 的两个数组进行两次快速排序递归调用的成本。初始项 c n 是执行 findpivot 和 partition 步骤的成本，其中 c 为某个常数。这个递推关系的闭式解是 Θ(n log n)。因此，快速排序的平均情况成本为 Θ(n log n)。

这是一种不寻常的情况：平均情况成本和最坏情况成本在渐近意义下有不同的增长率。考虑一下“平均情况”到底是什么意思。我们通过对每一个大小为 n 的可能输入，计算该输入的运行时间成本与该输入发生概率的乘积并求和，来得到大小为 n 的输入的平均成本。为简化起见，我们假设每个排列发生的可能性相等。因此，求平均值意味着将每个排列的成本求和，然后除以输入数量（n!）。我们知道这些 n! 个输入中有些的成本为 O(n²)。但所有排列成本的总和必须是 (n!)(O(n log n))。鉴于最坏输入的代价极高，它们的数量一定非常少。事实上，成本为 O(n²) 的输入不可能占一个恒定比例。即使，比如说，有 1% 的输入成本为 O(n²)，也会导致
