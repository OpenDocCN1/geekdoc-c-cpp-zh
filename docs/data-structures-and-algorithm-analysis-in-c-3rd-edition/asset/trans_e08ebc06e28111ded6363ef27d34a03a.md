注意，zigzag 旋转往往会使树更加平衡，因为它们将子树 B 和 C 上移一层，同时将子树 D 下移一层。其结果是树的高度通常会减少一层。Zigzig 提升和单旋转通常不会降低树的高度；它们只是将新访问的记录移近根节点。

对节点 S 进行伸展（splaying）需要执行一系列双旋转，直到 S 到达根节点或根节点的子节点。然后，如有必要，再进行一次单旋转使 S 成为根节点。这个过程有助于重新平衡树。无论平衡与否，伸展操作都会使经常访问的节点保持在树的顶部附近，从而降低访问成本。关于伸展树满足 O(m log n) 保证的证明超出了本书的范围。此类证明可在第 13.4 节的参考文献中找到。

本节介绍两种用于存储二维或更高维度点数据的空间数据结构：k-d 树和 PR 四叉树。k-d 树是 BST 向多维空间的自然扩展。它是一种二叉树，其分裂决策在键维度之间交替进行。与 BST 类似，k-d 树使用对象空间分解。PR 四叉树使用键空间分解，因此是字典树（trie）的一种形式。它仅在处理一维键时才是二叉树（在这种情况下，它是一个使用二进制字母表的字典树）。对于 d 个维度，它有 2^d 个分支。因此，在二维情况下，PR 四叉树有四个分支（因此得名“四叉树”），在每个分支处将空间分割成四个大小相等的象限。第 13.3.3 节简要介绍了这些数据结构的另外两种变体：bintree 和点四叉树。这四种结构涵盖了对象空间分解与键空间分解、多级二叉树与 2^d 路分支的所有四种组合。第 13.3.4 节简要讨论了用于存储其他类型空间数据的空间数据结构。

### 13.3.1 K-D 树

k-d 树是对 BST 的一种修改，允许高效处理多维键。k-d 树与 BST 的不同之处在于，k-d 树的每一层都基于与该层相关联的特定搜索键（称为判别器）来做出分支决策。原则上，k-d 树可用于在任意键集合（如姓名和邮政编码）上统一键搜索。但在实践中，它几乎总是用于支持多维坐标搜索，例如二维或三维空间中的位置。我们定义第 i 层的判别器为 i mod k，其中 k 为维度数。例如，假设我们存储按 xy 坐标组织的数据。在这种情况下，k 为 2（有两个坐标），x 坐标字段被任意指定为键 0，y 坐标字段被指定为键 1。在每一层，判别器在 x 和 y 之间交替。因此，第 0 层（根节点）的节点 N，其左子树中只包含 x 值小于 N_x 的节点（因为 x 是搜索键 0，且 0 mod 2 = 0）。右子树则包含 x 值大于 N_x 的节点。第 1 层的节点 M，其左子树中只包含 y 值小于 M_y 的节点。M_x 与 M 的后代的 x 值之间没有限制，因为在 M 处做出的分支决策仅基于 y 坐标。图 13.11 展示了一个二维点集合如何在 k-d 树中存储的示例。

图 13.11 k-d 树示例。（a）包含七个数据点的 128 × 128 单位区域的 k-d 树分解。（b）区域（a）对应的 k-d 树。

![](img/7ea3c39173f146f675b63b146d1535f3_469_0.png)

在图 13.11 中，包含这些点的区域被（任意地）限制为一个 128 × 128 的正方形，每个内部节点都分割搜索空间。每次分割用一条线表示，x 判别器的节点对应垂直线，y 判别器的节点对应水平线。根节点将空间分成两部分；其子节点进一步将空间细分为更小的部分。子节点的分割线不会穿过根节点的分割线。因此，k-d 树中的每个节点都有助于将空间分解为矩形，这些矩形显示了节点在各个子树中可能出现的范围。

在 k-d 树中搜索具有指定 xy 坐标的记录，就像在 BST 中搜索一样，只是 k-d 树的每一层都与一个特定的判别器相关联。

**示例 13.5.** 考虑在 k-d 树中搜索位于 P = (69, 50) 的记录。首先将 P 与存储在根节点处的点（图 13.11 中的记录 A）进行比较。如果 P 与 A 的位置匹配，则搜索成功。

在这个例子中，二者的位置并不匹配（A 的位置 (40, 45) 与 (69, 50) 不同），因此搜索必须继续。将 A 的 x 值与 P 的 x 值进行比较，以确定向哪个方向分支。因为 A_x 的值 40 小于 P_x 的值 69，所以我们分支到右子树（所有 x 值大于或等于 40 的城市都在右子树中）。A_y 不影响这一层的分支决策。在第二层，P 与记录 C 的位置不匹配，因此必须进行另一个分支。然而，在这一层，我们根据点 P 和记录 C 的 y 值相对大小进行分支（因为 1 mod 2 = 1，对应于 y 坐标）。因为 C_y 的值 10 小于 P_y 的值 50，所以我们向右分支。此时，将 P 与 D 的位置进行比较，匹配成功，搜索成功。

如果搜索过程到达 NULL 指针，则说明该点不包含在树中。以下是 k-d 树的搜索实现，相当于 BST 类的 findhelp 函数。KD 类的私有成员 D 存储键的维度。

![](img/7ea3c39173f146f675b63b146d1535f3_469_0.png)

![](img/7ea3c39173f146f675b63b146d1535f3_469_1.png)

```cpp
// Find the record with the given coordinates
bool findhelp(BinNode<E>* root, int* coord,
    E& e, int discrim) const {
    // Member "coord" of a node is an integer array storing
    // the node's coordinates.
    if (root == NULL) return false;    // Empty tree
    int* currcoord = (root->val())->coord();
    if (EqualCoord(currcoord, coord)) { // Found it
        e = root->val();
        return true;
    }
    if (currcoord[discrim] < coord[discrim])
        return findhelp(root->left(), coord, e, (discrim+1)%D);
    else
        return findhelp(root->right(), coord, e, (discrim+1)%D);
}
```

**示例 13.6.** 在图 13.11 的 k-d 树中插入位于 (10, 50) 的记录，首先需要搜索到包含记录 B 的节点。此时，新记录被插入到 B 的左子树中。

从 k-d 树中删除节点与从 BST 中删除类似，但要稍难一些。与 BST 删除一样，第一步是找到要删除的节点（称为 N）。然后需要找到一个 N 的后代，用于在树中替换 N。如果 N 没有孩子，则用 NULL 指针替换 N。注意，如果 N 有一个孩子且该孩子又有孩子，我们不能像 BST 那样简单地将 N 的父节点指向 N 的孩子。这样做会改变子树中所有节点的层数，从而用于搜索的判别器也会改变。结果是该子树将不再是一棵 k-d 树，因为节点的子节点可能会违反该判别器的 BST 性质。

与 BST 删除类似，存储在 N 中的记录应被替换为 N 右子树中具有 N 的判别器最小值的记录，或 N 左子树中具有该判别器最大值的记录。假设 N 位于奇数层，因此判别器是 y。那么 N 可以被其右子树中具有最小 y 值的记录（称为 Y_min）替换。问题在于，Y_min 不一定是 BST 中那样的最左节点。相反，必须使用一个修改后的搜索过程来查找左子树中的最小 y 值，以找到它。然后对删除例程的递归调用会将 Y_min 从树中移除。最后，用 Y_min 的记录替换节点 N 中的记录。
