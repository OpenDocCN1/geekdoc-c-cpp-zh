

## 3.11 经验分析

本章一直聚焦于渐近分析。这是一种分析工具，我们通过对算法的关键方面进行建模来确定算法随输入规模增长的增长率。正如前面所指出的，这种方法存在许多局限性。这些局限包括小规模问题的影响、区分具有相同增长率的算法的更细微差别，以及对更复杂问题进行数学建模的固有困难。

分析的另一种方法是经验方法。最明显的经验方法是简单地运行两个竞争者，看看哪个性能更好。通过这种方式，我们可能会克服分析方法的不足。

请注意，对程序进行比较计时是一件困难的事情，通常会受到来自不可控因素的实验误差的影响（系统负载、使用的语言或编译器等）。最重要的一点是不要偏向其中一个程序。如果你有偏见，这一定会反映在计时结果中。看看竞争的软件或硬件厂商的广告就应该能让你信服这一点。编写两个程序比较其性能时最常见的陷阱是其中一个程序获得了比另一个更多的代码调优工作量。如第 3.10 节所述，代码调优通常可以将运行时间减少十倍。如果两个程序的运行时间相差一个常数因子而不论输入规模如何（即它们的增长率相同），那么代码调优的差异就可能解释运行时间的任何差异。在这种情况下，对经验比较要保持怀疑态度。

另一种分析方法是仿真。仿真的思想是用计算机程序对问题进行建模，然后运行它以获得结果。在算法分析的背景下，仿真与两个竞争者的经验比较不同，因为仿真的目的是执行可能 otherwise 过于困难的分析。图 9.10 中出现了一个很好的例子。该图显示了在哈希表中插入或删除记录的成本，在为在表中寻找空槽而使用的策略的两种不同假设下。y 轴是评估的哈希表槽数成本，x 轴是表中已满槽的百分比。这些曲线的数学方程可以确定，但这并不容易。一个合理的替代方案是编写哈希的简单变体。通过对各种加载条件下程序成本进行计时，不难构建出类似于图 9.10 的图。此分析的目的是不是为了确定哪种哈希方法最有效，因此我们没有对哈希替代方案进行经验比较。相反，目的是分析在高效哈希系统中将使用的适当加载因子，以平衡时间成本与哈希表大小（空间成本）。
