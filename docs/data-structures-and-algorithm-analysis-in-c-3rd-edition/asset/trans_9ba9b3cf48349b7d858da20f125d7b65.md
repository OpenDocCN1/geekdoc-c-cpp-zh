读取该磁道需要多少时间？平均而言，需要半圈旋转将磁道的第一个扇区带到I/O磁头下方，然后再一整圈旋转来读取整个磁道。

即接近4秒。这比文件在磁盘上连续存放所需的时间要长得多！

这个例子说明了为什么保持磁盘文件不碎片化很重要，以及为什么所谓的“磁盘碎片整理程序”能够加快文件处理时间。文件碎片化最常发生在磁盘几乎已满，并且文件管理器在创建或更改文件时必须搜索空闲空间的时候。

## 8.3 缓冲区和缓冲池

根据示例8.1中磁盘驱动器的规格，我们发现平均读取一条磁道的数据大约需要9.5+11.1×1.5 = 26.2毫秒。而平均读取单个扇区的数据大约需要9.5+11.1/2+(1/256)×11.1 = 15.1毫秒。这是一个可观的节省（略多于一半的时间），但读取的数据还不到磁道上数据的1%。如果我们只希望读取一个字节，与读取整个扇区所需的时间相比，实际上并不会节省时间。因此，几乎所有的磁盘驱动器在访问磁盘时都会自动读取或写入整整一个扇区的信息，即使只请求一个字节的信息也是如此。

一旦一个扇区被读取，其信息就存储在主内存中。这被称为缓冲或缓存信息。如果下一个磁盘请求指向同一个扇区，则不必再次从磁盘读取，因为信息已经存储在主内存中。缓冲是本章开头提到的减少磁盘访问次数的一种方法示例：从磁盘额外读取信息以满足未来请求。如果文件信息被随机访问，那么连续两个磁盘请求指向同一个扇区的概率会很低。然而，在实践中，大多数磁盘请求都靠近前一个请求的位置（至少在逻辑文件中如此）。这意味着下一个请求“命中缓存”的概率远高于随机概率所指示的。

这一原理解释了为什么新磁盘驱动器的平均访问时间比过去低的一个原因。不仅硬件更快了，而且现在信息存储也使用了更好的算法和更大的缓存，从而最大限度地减少了从磁盘获取信息的次数。同样的概念也用于在CPU内部的更快内存中存储部分程序，即现代微处理器中普遍存在的CPU缓存。

扇区级缓冲通常由操作系统提供，并且常常直接内置于磁盘驱动器控制器硬件中。大多数操作系统至少维护两个缓冲区，一个用于输入，一个用于输出。考虑在逐字节复制操作中只有一个缓冲区会发生什么。包含第一个字节的扇区会被读入I/O缓冲区。输出操作为了写入这个字节，需要销毁单个I/O缓冲区的内容。然后，缓冲区需要再次从磁盘填充第二个字节，

却在输出时再次被销毁。解决这个问题的简单方法是保留一个输入缓冲区和一个输出缓冲区。

大多数磁盘驱动器控制器在收到I/O请求后独立于CPU运行。这是有用的，因为CPU在单个I/O操作所需的时间内通常可以执行数百万条指令。一种充分利用这种微并行性的技术是双缓冲。想象一个文件正在被顺序处理。当第一个扇区正在被读取时，CPU无法处理该信息，因此必须等待或在此期间找其他事情做。一旦第一个扇区被读取，CPU就可以开始处理，同时磁盘驱动器（并行地）开始读取第二个扇区。如果CPU处理一个扇区所需的时间与磁盘控制器读取一个扇区所需的时间大致相同，那么就有可能让CPU持续获得来自文件的数据。同样的概念也可应用于输出，在CPU向内存中的第二个输出缓冲区写入数据的同时，将一个扇区写入磁盘。因此，在支持双缓冲的计算机中，至少配备两个输入缓冲区和两个输出缓冲区是值得的。

在内存中缓存信息是一个好主意，以至于通常将其扩展到多个缓冲区。操作系统或应用程序可能会存储许多来自某些后备存储（如磁盘文件）的信息缓冲区。这种使用缓冲区作为用户和磁盘文件之间中介的过程称为文件缓冲。存储在缓冲区中的信息通常称为页，而缓冲区的集合称为缓冲池。缓冲池的目标是增加存储在内存中的信息量，希望新的信息请求能够更多地由缓冲池满足，而不需要从磁盘读取新信息。

只要缓冲池中有未使用的缓冲区，就可以按需从磁盘读入新信息。当应用程序持续从磁盘读取新信息时，最终缓冲池中的所有缓冲区都会填满。一旦发生这种情况，就必须决定牺牲缓冲池中的哪些信息，以便为新请求的信息腾出空间。

当替换缓冲池中包含的信息时，目标是选择一个具有“不必要”信息的缓冲区，即最不可能再次被请求的信息。由于缓冲池无法确切知道未来请求的模式，必须基于某种启发式或最佳猜测来做出决策。有几种方法可以做出这种决策。
