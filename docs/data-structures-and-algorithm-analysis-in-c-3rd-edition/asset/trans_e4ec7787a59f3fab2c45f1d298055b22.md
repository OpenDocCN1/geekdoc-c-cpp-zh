

虽然以这种方式选择中位数可以保证消除一部分元素（最多剩下 ⌈(7n − 5)/10⌉ 个元素），但我们仍需确保递归能得到线性时间算法。我们用下面的递推式来建模该算法。

T(n) ≤ T(⌈n/5⌉) + T(⌈(7n − 5)/10⌉) + 6⌈n/5⌉ + n − 1.

T(⌈n/5⌉) 项来自计算中位数的中位数，6⌈n/5⌉ 项来自计算中位数的代价（每个由五个元素组成的小组恰好需要六次比较），而 T(⌈(7n−5)/10⌉) 项来自对剩余（最多）70% 元素的递归调用。

我们将证明该递推式是线性的，方法是假设它对某个常数 r 成立，然后证明当 n 大于某个界限时 T(n) ≤ rn。

T(n) ≤ T(⌈n/5⌉) + T(⌈(7n − 5)/10⌉) + 6⌈n/5⌉ + n − 1
≤ r(n/5 + 1) + r((7n − 5)/10 + 1) + 6(n/5 + 1) + n − 1
≤ (r/5 + 7r/10 + 11/5)n + 3r/2 + 5
≤ (9r + 22)/10 n + (3r + 10)/2.

当 r ≥ 23 且 n ≥ 380 时成立。这提供了一个基准情形，使我们能够用归纳法证明 ∀n ≥ 380, T(n) ≤ 23n。

实际上，该算法并不实用，因为其常数因子开销太高。为了保证线性时间性能而做的工作太多，平均而言依靠随机选择枢轴更有效，例如随机选取或选取当前子数组的中间值。

## 15.7 最优排序

我们用寻找比较次数绝对最少的排序算法来结束本节。结果很可能不适用于通用排序算法。但请回忆我们之前对体育锦标赛的类比。在体育中，两个队伍或个人之间的“比较”意味着让两者进行比赛。这相当昂贵（至少与计算机中的一些轻微簿记相比），为了减少需要进行的比赛次数，付出相当多的簿记也是值得的。如果我们想设计一个锦标赛，用最少的总比赛次数得出所有队伍的确切排名，该怎么办？当然，我们假设每场比赛的结果是“准确的”，即我们不仅假设 A 对阵 B 的结果在锦标赛期间始终相同，而且结果也具有传递性。实际上这些假设是不现实的，但许多锦标赛组织中隐含了这些假设。与大多数锦标赛组织者一样，我们可以简单地接受这些假设，并设计一个进行比赛的算法，根据获得的结果给出某种排名。

回忆插入排序，我们把第 i 个元素插入到前 i − 1 个元素的已排序子列表中。如果我们修改标准插入排序算法，使用二分查找来定位第 i 个元素在已排序子列表中的位置会怎样？该算法称为二分插入排序。作为通用排序算法，这并不实用，因为我们然后（平均）需要移动约 i/2 个元素来为新插入的元素腾出空间。但如果只计算比较次数，二分插入排序相当不错。我们可以利用二分插入排序的一些思想，更接近于使用排序所需的绝对最小比较次数的算法。

考虑对五个元素运行二分插入排序时会发生什么。我们需要做多少次比较？我们可以用一次比较插入第二个元素，用两次比较插入第三个元素，用两次比较插入第四个元素。当我们把第五个元素插入到由四个元素组成的已排序列表中时，最坏情况下需要三次比较。注意插入时到底发生了什么。我们将第五个元素与第二个元素比较。如果第五个更大，我们必须将其与第三个比较，如果它更大，我们必须将其与第四个比较。一般来说，二分查找何时最有效？当列表中有 2^i − 1 个元素时。它在列表中有 2^i 个元素时效率最低。因此，如果可能的话，我们可以通过安排插入来避免将元素插入到大小为 2^i 的列表中，从而做得更好。

图 15.6 说明了我们可能进行的比较的另一种组织方式。首先比较第一个和第二个元素，以及第三个和第四个元素。然后比较两个胜者，形成一棵二项式树。我们可以将其视为由三个元素组成的（已排序）链，元素 A 从根部悬挂下来。如果我们然后将元素 B 插入到由三个元素组成的已排序链中，我们将以图 15.6 右侧所示的两个偏序集之一结束，代价为 2 次比较。然后我们可以以两<|message|> 次比较的代价将 A 合并到链中（因为我们已经知道它小于其中一个或两个元素，我们实际上将其合并到大小为二或三个的列表中）。因此，对五个元素排序所需的比较次数最多为七次，而不是八次。

如果我们有十个元素要排序，我们可以先组成五个元素对（使用五次比较），然后使用刚刚描述的算法对五个胜者进行排序（再使用七次比较）。现在我们需要处理的只是原始的失败者。我们可以对任意数量的元素推广此过程：

我们使用二分插入来放置失败者。然而，我们可以自由选择插入的最佳顺序，同时记住二分查找对 2^i 到 2^{i+1} − 1 个项目具有相同的代价。例如，二分查找对大小为 4、5、6 或 7 的列表最坏情况下需要三次比较。因此我们选择插入顺序以优化二分查找，这意味着选择一个避免子列表大小增长从而跨越列表大小边界而需要额外比较的顺序。这种排序称为合并插入排序，也称为 Ford 和 Johnson 排序。

对于十个元素，给定图 15.7 所示的偏序集，我们按元素 3、元素 4、元素 1，最后元素 2 的顺序折叠最后四个元素（标记为 1 到 4）。元素 3 将被插入到大小为三的列表中，花费两次比较。根据元素 3 在列表中的最终位置，元素 4 现在将被插入到大小为 2 或 3 的列表中，在任何情况下花费两次比较。根据元素 3 和 4 在列表中的位置，元素 1 现在将被插入到大小为 5、6 或 7 的列表中，所有这些都需要三次比较才能放置在排序顺序中。最后，元素 2 将被插入到大小为 5、6 或 7 的列表中。

合并插入排序相当不错，但它是最佳的吗？请回忆第 7.9 节，没有排序算法可以快于 Ω(n log n)。准确地说，排序的信息论下界可以证明为 ⌈log n!⌉。也就是说，我们可以证明比较次数的下界恰好为 ⌈log n!⌉。合并插入排序给出的比较次数等于该信息论下界，对所有 n ≤ 12 的值都成立。在 n = 12 时，合并插入排序需要 30 次比较，而信息论下界仅为 29 次比较。然而，对于如此小的元素数量，可以对每一种可能的比较排列进行穷举研究。事实证明，当 n = 12 时，根本不存在使下界小于 30 次比较的比较排列。因此，在这种情况下信息论下界是低估的，因为 30 才是真正能做到的最好结果。
