在相应方向上没有子结点的内部结点。[^3] 将这个结点称为 R'。然后我们添加一个新结点，其中包含要插入的新记录，作为 R' 的子结点。图 5.15 演示了这一操作。值 35 被添加为值为 32 的结点的右子结点。以下是 inserthelp 的实现：

```cpp
template <typename Key, typename E>
BSTNode<Key, E>* BST<Key, E>::inserthelp(
    BSTNode<Key, E>* root, const Key& k, const E& it) {
    if (root == NULL)  // Empty tree: create node
        return new BSTNode<Key, E>(k, it, NULL, NULL);
    if (k < root->key())
        root->setLeft(inserthelp(root->left(), k, it));
    else root->setRight(inserthelp(root->right(), k, it));
    return root;      // Return tree with node inserted
}
```

你应该仔细注意 inserthelp 的实现。注意，inserthelp 返回一个指向 BSTNode 的指针。返回的是与旧子树相同的子树，只是经过修改，包含了要插入的新记录。从根结点到新添加结点的父结点的路径上，每个结点的相应子结点指针都会被赋值。除了路径上的最后一个结点，这些结点实际上都不会改变其子结点的指针值。从这个意义上说，许多赋值似乎是多余的。然而，为保持插入过程的简单性，付出这些额外赋值的代价是值得的。另一种办法是检查某个赋值是否有必要，这可能比赋值本身更耗时！

BST 的形状取决于元素插入的顺序。新元素作为新的叶结点被添加到 BST 中，这可能会增加树的深度。图 5.13 展示了同一组值的两个 BST。包含 n 个结点的 BST 有可能形成一个高度为 n 的结点链。例如，如果所有元素都按已排序的顺序插入，就会发生这种情况。一般来说，BST 越浅越好。这能保持 BST 操作的平均成本较低。

从 BST 中删除结点比插入结点要棘手一些，但如果逐一考虑所有可能的情况，也并不复杂。在着手处理通用的结点删除过程之前，我们先讨论如何从给定子树中删除键值最小的结点。这个例程稍后会被通用的结点删除函数使用。要从子树中删除键值最小的结点，首先要找到该结点：沿着左链接不断向下移动，直到没有可继续的左链接。称该结点为 S。要删除 S，只需让 S 的父结点改变其指针，使其指向 S 的右子结点。我们知道 S 没有左子结点（因为如果 S 有左子结点，S 就不是键值最小的结点了）。因此，按上述方式改变指针后，BST 依然保持，同时 S 被删除。名为 deletemin 的方法的代码如下：

```cpp
template <typename Key, typename E>
BSTNode<Key, E>* BST<Key, E>::deletemin(BSTNode<Key, E>* rt) {
    if (rt->left() == NULL) // Found min
        return rt->right();
    else { // Continue left
        rt->setLeft(deletemin(rt->left()));
        return rt;
    }
}
```

### 示例 5.6

图 5.16 演示了 deletemin 的过程。从值为 10 的根结点开始，deletemin 沿着左链接移动，直到没有更进一步的左链接为止，在此例中到达值为 5 的结点。值为 10 的结点被改为指向包含最小值的结点的右子结点。这一点在图 5.16 中用虚线表示。

指向包含最小值的结点的指针被存储在参数 S 中。deletemin 方法的返回值是当前结点的子树，只不过该子树中最小值的结点已被删除。与 inserthelp 方法一样，返回根结点的路径上的每个结点，其左子结点指针都会被重新赋值为调用 deletemin 方法后得到的子树。

一个有用的配套方法是 getmin，它返回指向子树中包含最小值的结点的指针。

![](img/7ea3c39173f146f675b63b146d1535f3_193_0.png)

**图 5.16.** 删除最小值的结点的示例。在此树中，最小值为 5 的结点是根结点的左子结点。因此，根结点的左指针被改为指向 5 的右子结点。

```cpp
template<typename Key, typename E>
BSTNode<Key, E>* BST<Key, E>::getmin(BSTNode<Key, E>* rt) {
    if (rt->left() == NULL)
        return rt;
    else return getmin(rt->left());
}
```

从 BST 中删除具有给定键值 R 的结点，需要先找到 R，然后将其从树中删除。因此，删除操作的第一部分是查找 R 的搜索。一旦找到 R，会有几种可能情况。如果 R 没有子结点，则将 R 的父结点的指针设为 NULL。如果 R 有一个子结点，则将 R 的父结点的指针设为 R 的子结点（类似于 deletemin）。问题在于 R 有两个子结点的情况。一种简单但代价较高的方法是让 R 的父结点指向 R 的其中一个子树，然后重新逐个插入另一个子树中的结点。更好的替代方案是在其中一个子树中找到可以替换 R 中值的值。

于是问题变为：哪个值可以替代被删除的值？它不能是任意值，因为我们必须在不显著改变树结构的情况下保持 BST 性质。哪个值与要删除的值最相似？答案是大于（或等于）被删除键值的最小键值，或者小于被删除键值的最大键值。用这两个值中的任意一个替换被删除的值后，BST 性质都得以保持。

### 示例 5.7

假设我们希望从图 5.13(a) 的 BST 中删除值 37。我们不删除根结点，而是删除右子树中值最小的结点（使用 deletemin 操作）。然后这个值可以替换根结点中的值。在此示例中，我们首先删除值为 40 的结点，因为它包含右子树中的最小值。然后我们用 40 作为根结点的新值。图 5.17 演示了这一过程。

**图 5.17.** 从 BST 中删除值 37 的示例。包含该值的结点有两个子结点。我们用该结点右子树中的最小值（本例中为 40）替换值 37。

当树中没有重复的结点值时，替换值是取左子树中的最大值还是右子树中的最小值并无区别。如果存储重复值，则必须从右子树中选择替换值。要理解原因，设左子树中的最大值为 G。如果左子树中有多个结点的值为 G，选择 G 作为子树根的替换值，会导致现在包含 G 的结点的左侧出现相等的值。如果我们将值 120 替换为图 5.13(b) 左子树中的最大值，恰恰会出现这种情况。从右子树中选择最小值则没有类似问题，因为相等值出现在右子树中并不违反二叉搜索树性质。

综上所述，如果要删除存储在有两个子结点的结点中的记录，我们只需对该结点的右子树调用 deletemin，并用返回的记录替换被删除的记录。图 5.18 展示了 removehelp 的一种实现。

findhelp 和 inserthelp 的成本是所找到或插入的结点的深度。removehelp 的成本是被删除结点的深度；如果该结点有两个子结点，则是其右子树中值最小的结点的深度。因此，在最坏情况下，这些操作中任意一个的成本都是树中最深结点的深度。这就是为什么希望保持 BST 平衡，也就是使其高度尽可能小。如果二叉树是平衡的，那么包含 n 个结点的树的高度约为 log n。然而，如果树完全不均衡，例如呈链表形状，那么包含 n 个结点的树的高度可能高达 n。因此，平衡的 BST 在平均情况下的操作成本为 Θ(log n)，而严重不平衡的 BST 在最坏情况下的操作成本可能为 Θ(n)。考虑下面这种情况：我们通过一次插入一条记录来构建包含 n 个结点的 BST。如果我们有幸让这些记录以能够形成平衡树的顺序到达（“随机”顺序就是
