## 图 6.6 具有两个连通分量的图

在图 6.6 中，节点 A、H 和 E 是等价的，但 J 不与任何其他节点等价。图中等价（连通）边的子集称为连通分量。目标是将对象快速分类为与连通分量对应的不相交集合。UNION/FIND 的另一个应用出现在 Kruskal 算法中，该算法用于计算图的最小代价生成树（11.5.2 节）。

UNION/FIND 算法的输入通常是一系列等价对。在连通分量的例子中，等价对就是图中的边集。一个等价对可能表示对象 C 与对象 A 等价。如果是这样，C 和 A 被放在同一个子集中。如果后面有一个等价关系关联 A 和 B，那么根据蕴含关系，C 也与 B 等价。因此，一个等价对可能导致两个子集合并，每个子集可能包含若干对象。

等价类可以使用 UNION/FIND 算法高效管理。最初，每个对象都是其自身树的根。处理一个等价对时，通过方法 **differ** 检查该对中的两个对象是否在同一棵树中。如果它们在同一个树中，则无需更改，因为这些对象已经在同一个等价类中。否则，应该通过 **UNION** 方法合并这两个等价类。

## 示例 6.2

作为求解等价类问题的一个示例，考虑图 6.6 中的图。最初，我们假设图中的每个节点都在一个不同的等价类中。这通过将每个节点存储为其自身树的根来表示。图 6.7(a) 使用父指针数组表示显示了这一初始配置。现在，考虑处理等价关系 (A, B) 时会发生什么。包含 A 的树的根是 A，包含 B 的树的根是 B。为了使它们等价，将这两个根之一设置为另一个的父节点。在这种情况下，谁指向谁并不重要，因此我们任意选择 B 的父字段（数组中位置 1 的节点）存储指向 A 的指针。等价对 (C, H)、(G, F) 和 (D, E) 以类似方式处理。当处理等价对 (I, F) 时，因为 I 和 F 都是各自的根，所以将 I 设置为指向 F。注意，这也使 G 与 I 等价。处理这五个等价关系的结果如图 6.7(b) 所示。

父指针表示对可以共享同一父节点的节点数量没有限制。为了使等价处理尽可能高效，每个节点到其各自树的根的距离应尽可能小。因此，在合并两个等价类时，我们希望保持树的高度较小。理想情况下，每棵树的所有节点都直接指向根。任何时候都实现这一目标需要过多额外处理，不值得付出这样的努力，因此我们必须满足于尽可能接近这一目标。

一种低成本降低高度的方法是在两棵树合并时采取明智的策略。一种简单的技术称为**加权合并规则**，它通过让较小树的根指向较大树的根，将节点较少的树合并到节点较多的树上。这将把树的总深度限制在 O(log n)，因为只有较小树中节点的深度会增加 1，而合并后树中最深节点的深度至多比合并前最深节点深 1。因此，合并后树中的总节点数至少是较小树节点数的两倍。

## 示例 6.3

在图 6.7(b) 中处理等价对 (I, F) 时，F 是包含两个节点的树的根，而 I 是只包含一个节点的树的根。因此，将 I 设置为指向 F，而不是反过来。图 6.7(c) 显示了再处理两个等价对 (H, A) 和 (E, G) 的结果。对于第一对，H 的根是 C，而 A 的根是 A 自身。两棵树都包含两个节点，因此将哪个节点设置为合并后树的根是任意决定。对于等价对 (E, G)，E 的根是 D，而 G 的根是 F。因为 F 是较大树的根，所以节点 D 被设置为指向 F。

并非所有等价关系都会合并两棵树。如果在表示处于图 6.7(c) 所示状态时处理等价关系 (F, G)，则不会进行任何更改，因为 F 已经是 G 的根。

加权合并规则有助于最小化树的深度，但我们可以做得更好。路径压缩是一种倾向于创建极浅树的方法。路径压缩在查找给定节点 X 的根时进行。调用这个根为 R。路径压缩将路径上从 X 到 R 的每个节点的父节点都重置为直接指向 R。这可以通过首先找到 R 来实现。然后沿着从 X 到 R 的路径进行第二遍遍历，将遇到的每个节点的父字段赋值为 R。或者，可以按如下方式实现递归算法。这个 FIND 版本不仅返回当前节点的根，还使当前节点的所有祖先都指向根。

```
// 带路径压缩的 FIND
int ParPtrTree::FIND(int curr) const {
    if (array[curr] == ROOT) return curr; // 到达根
    array[curr] = FIND(array[curr]);
    return array[curr];
}
```

路径压缩使每个 FIND 操作的成本非常接近常数。更精确地说明“非常接近常数”的含义：在 n 个节点上执行 n 次 FIND 操作时（结合加权合并规则用于合并集合），路径压缩的成本约为¹ Θ(n log* n)。记号“log* n”表示在 n ≤ 1 之前需要对 n 取对数的次数。例如，log* 65536 是 4，因为 log 65536 = 16，log 16 = 4，log 4 = 2，最后 log 2 = 1。因此，log* n 增长非常缓慢，所以 n 次 FIND 操作系列的成本非常接近 n。

注意，这并不意味着处理 n 个等价对得到的树必然具有 Θ(log* n) 的深度。可以设计一系列等价操作，使结果树的深度为 Θ(log n)。然而，这样一系列中的许多等价操作只查看被合并树的根，所需的处理时间很少。n 次操作所需的总处理时间为 Θ(n log* n)，使得每次等价操作几乎达到常数时间。这是摊销分析的一个示例，将在 14.3 节进一步讨论。
