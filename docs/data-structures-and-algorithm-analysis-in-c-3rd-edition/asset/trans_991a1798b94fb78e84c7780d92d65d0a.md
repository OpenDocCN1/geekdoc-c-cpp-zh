我们可以使用队列而不是递归来实现拓扑排序，如下所示。首先访问所有边，计算有多少条边通向每个顶点（即计算每个顶点的先决条件数量）。所有没有先决条件的顶点都放入队列。然后我们开始处理队列。当顶点 V 从队列中取出时，它将被打印，并且 V 的所有邻居（即所有以 V 为先决条件的顶点）的计数减一。任何计数变为零的邻居都放入队列。如果在打印所有顶点之前队列变空，则图包含一个环（即不存在不违反任何先决条件的任务排序）。使用队列版本的拓扑排序对图 11.14 中的顶点打印的顺序为 J1、J2、J3、J6、J4、J5、J7。图 11.15 显示了该算法的实现。

```
// Topological sort: Queue
void topsort(Graph* G, Queue<int>* Q) {
    int Count[G->n()];
    int v, w;
    for (v=0; v<G->n(); v++) Count[v] = 0; // Initialize
    for (v=0; v<G->n(); v++)    // Process every edge
        for (w=G->first(v); w<G->n(); w = G->next(v,w))
            Count[w]++;
                            // Add to v2's prereq count
    for (v=0; v<G->n(); v++)    // Initialize queue
        if (Count[v] == 0)      // Vertex has no prerequisites
            Q->enqueue(v);
    while (Q->length() != 0) { // Process the vertices
        v = Q->dequeue();
        printout(v);            // PreVisit for "v"
        for (w=G->first(v); w<G->n(); w = G->next(v,w)) {
            Count[w]--;
                            // One less prerequisite
            if (Count[w] == 0)      // This vertex is now free
                Q->enqueue(w);
        }
    }
}
```

## 11.4 最短路径问题

在道路地图上，连接两个城镇的道路通常标有其距离。我们可以将道路网络建模为有向图，其边标记为实数。这些数字表示两个顶点之间的距离（或其他成本度量，例如旅行时间）。这些标签根据应用可称为权重、成本或距离。给定这样的图，一个典型的问题是找到两个指定顶点之间的最短路径的总长度。这不是一个微不足道的问题，因为最短路径可能不沿着连接两个顶点的边（如果存在），而是可能沿着涉及一个或多个中间顶点的路径。例如，在图 11.16 中，从 A 到 B 到 D 的路径成本为 15。从 A 直接到 D 的边的成本为 20。从 A 到 C 到 B 到 D 的路径成本为 10。因此，从 A 到 D 的最短路径为 10（而不是沿着连接 A 到 D 的边）。我们用记号 d(A, D) = 10 表示从 A 到 D 的最短距离为 10。在图 11.16 中，从 E 到 B 没有路径，因此我们设 d(E, B) = ∞。我们定义 w(A, D) = 20 为边 (A, D) 的权重，即从 A 到 D 的直接连接的权重。因为从 E 到 B 没有边，w(E, B) = ∞。请注意 w(D, A) = ∞，因为图 11.16 是有向的。我们假设所有权重都是正数。

### 11.4.1 单源最短路径

本节介绍一种求解单源最短路径问题的算法。给定图 G 中的顶点 S，找到从 S 到 G 中每个其他顶点的最短路径。我们可能只想要 S 和 T 两个顶点之间的最短路径。然而在最坏情况下，在寻找从 S 到 T 的最短路径时，我们可能会找到从 S 到每个其他顶点的最短路径。因此，在最坏情况下，找到到单个顶点的最短路径没有比找到到所有顶点的最短路径更好的算法。这里描述的算法只会计算到每个此类顶点的距离，而不是记录实际路径。记录路径需要对算法进行修改，作为练习留给读者。

计算机网络为单源最短路径问题提供了一个应用。目标是找到一台计算机向网络上所有其他计算机广播消息的最便宜方式。网络可以用图建模，边权重表示向相邻计算机发送消息的时间或成本。

对于无权图（或所有边成本相同的情况），单源最短路径可以使用简单的广度优先搜索找到。当添加权重时，BFS 不会给出正确答案。

解决边权重不同时问题的另一种方法可能是按固定顺序处理顶点。将顶点标记为 v0 到 vn−1，其中 S = v0。处理顶点 v1 时，我们取连接 v0 和 v1 的边。处理 v2 时，我们考虑从 v0 到 v2 的最短距离并将其与从 v0 到 v1 到 v2 的最短距离进行比较。处理顶点 vi 时，我们考虑已经处理的顶点 v0 到 vi−1 的最短路径。不幸的是，到 vi 的真正最短路径可能经过顶点 vj，其中 j > i。此算法不会考虑此类路径。但是，如果我们按距离 S 的顺序处理顶点，问题就不会发生。假设我们已按距离 S 的顺序处理了最接近 S 的前 i − 1 个顶点；称此顶点集合为 S。我们现在即将处理第 i 个最近的顶点；称其为 X。

从 S 到 X 的最短路径的倒数第二个顶点必须在 S 中。因此，

d(S, X) = min_{U ∈ S} (d(S, U) + w(U, X)).

换句话说，从 S 到 X 的最短路径是从 S 到 U 的路径，然后从 U 到 X 的一条边，其中 U 是 S 中的某个顶点。

该解决方案通常称为 Dijkstra 算法。它通过为 V 中的所有顶点 X 维护距离估计 D(X) 来工作。D 的元素初始化为值 INFINITY。顶点按距离 S 的顺序处理。每当处理顶点 V 时，V 的每个邻居 X 的 D(X) 都会更新。图 11.17 显示了 Dijkstra 算法的实现。最后，数组 D 将包含最短距离值。

```
// Compute shortest path distances from "s".
// Return these distances in "D".
void Dijkstra(Graph* G, int* D, int s) {
    int i, v, w;
    for (i=0; i<G->n(); i++) {        // Process the vertices
        v = minVertex(G, D);
        if (D[v] == INFINITY) return; // Unreachable vertices
        G->setMark(v, VISITED);
        for (w=G->first(v); w<G->n(); w = G->next(v,w))
            if (D[w] > (D[v] + G->weight(v, w)))
                D[w] = D[v] + G->weight(v, w);
    }
}
```

**图 11.17** Dijkstra 算法的实现。

在主 for 循环的每次遍历中寻找未访问的最小距离值顶点这一关键问题有两个合理的解决方案。第一种方法只是扫描 |V| 个顶点的列表寻找最小值，如下所示：

```
int minVertex(Graph* G, int* D) { // Find min cost vertex
    int i, v = -1;
    // Initialize v to some unvisited vertex
    for (i=0; i<G->n(); i++)
        if (G->getMark(i) == UNVISITED) { v = i; break; }
    for (i++; i<G->n(); i++)   // Now find smallest D value
        if ((G->getMark(i) == UNVISITED) && (D[i] < D[v]))
            v = i;
    return v;
}
```

由于此扫描执行 |V| 次，并且由于每条边都需要对 D 进行常数时间更新，因此该方法的总成本为 Θ(|V|² + |E|) = Θ(|V|²)，因为 |E| 在 O(|V|²) 中。
