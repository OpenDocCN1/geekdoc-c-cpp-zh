
```cpp
// Linked stack implementation
template <typename E> class LStack: public Stack<E> {
private:
    Link<E>* top;                // Pointer to first element
    int size;                    // Number of elements

public:
    LStack(int sz = defaultSize) // Constructor
    { top = NULL; size = 0; }

    ~LStack() { clear(); }      // Destructor

    void clear() {              // Reinitialize
        while (top != NULL) {   // Delete link nodes
            Link<E>* temp = top;
            top = top->next;
            delete temp;
        }
        size = 0;
    }

    void push(const E& it) { // Put "it" on stack
        top = new Link<E>(it, top);
        size++;
    }

    E pop() {                 // Remove "it" from stack
        Assert(top != NULL, "Stack is empty");
        E it = top->element;
        Link<E>* ltemp = top->next;
        delete top;
        top = ltemp;
        size--;
        return it;
    }

    const E& topValue() const { // Return top value
        Assert(top != NULL, "Stack is empty");
        return top->element;
    }

    int length() const { return size; } // Return length
};
```

### 4.2.2 链式栈

链式栈的实现非常简单。第 4.1.2 节的自由链表就是链式栈的一个示例。元素仅从链表头部插入和删除。不使用头结点，因为对于零个或一个元素的链表，不需要编写特殊情况的代码。图 4.19 展示了完整的链式栈实现。唯一的数据成员是 top，即指向栈的第一个（顶部）链接结点的指针。push 方法首先修改新创建的链接结点的 next 字段，使其指向栈顶，然后将 top 设置为指向新的链接结点。pop 方法也非常简单。变量 temp 存储栈顶结点的值，而 ltemp 在栈顶结点被从栈中移除时指向该结点。通过将 top 设置为指向栈中的下一个链接结点来更新栈。然后将旧的栈顶结点归还给自由存储区（或自由链表），并返回元素值。

### 4.2.3 基于数组的栈与链式栈的比较

基于数组的栈和链式栈实现的所有操作都花费常数时间，因此从时间效率的角度来看，两者都没有显著优势。另一个比较基础是所需的总空间。该分析与链表实现的分析类似。基于数组的栈必须一开始就声明一个固定大小的数组，只要栈未满，就会有部分空间被浪费。链式栈可以缩小和增长，但每个元素都需要一个链接字段的开销。

当需要实现多个栈时，可以利用基于数组的栈单向增长的特点。这可以通过使用单个数组来存储两个栈实现。如图 4.20 所示，两个栈分别从两端向内增长，有望减少空间浪费。然而，只有当两个栈的空间需求呈负相关时，这种方法才能很好地发挥作用。换句话说，理想情况下，当一个栈增长时，另一个栈会缩小。当元素从一个栈取出并放入另一个栈时，这种方法尤其有效。反之，如果两个栈同时增长，那么数组中间的空闲空间将很快被耗尽。

### 4.2.4 实现递归

也许栈最常见的计算机应用对用户来说甚至并不可见。这就是大多数编程语言运行时环境中子程序调用的实现。子程序调用通常通过将子程序所需的信息（包括返回地址、参数和局部变量）压入栈来实现。这些信息称为活动记录。后续的子程序调用会继续向栈中添加活动记录。每次从子程序返回时，都会将栈顶的活动记录弹出。图 4.21 展示了

此时，我们已到达 fact 的基本情形，于是递归开始回归。每次从 fact 返回都需要从栈中弹出存储的 n 值，以及函数调用的返回地址。fact 的返回值与恢复后的 n 值相乘，并将结果返回。

由于每次子程序调用都必须创建活动记录并压入栈中，因此进行子程序调用是一种相对昂贵的操作。虽然递归常用于使实现简单清晰，但有时你可能希望消除递归函数调用带来的开销。在某些情况下，例如第 2.5 节的阶乘函数，递归很容易被迭代替代。

**示例 4.2** 作为用栈替代递归的一个简单示例，请考虑以下阶乘函数的非递归版本。

```cpp
long fact(int n, Stack<int>& S) { // Compute n!
    // To fit n! in a long variable, require n <= 12
    Assert((n >= 0) && (n <= 12), "Input out of range");
    while (n > 1) S.push(n--);  // Load up the stack
    long result = 1;           // Holds final result
    while (S.length() > 0)
        result = result * S.pop();  // Compute
    return result;
}
```

这里，我们只需将不断减小的 n 值依次压入栈中，直到达到基本情形，然后反复弹出存储的值并将它们乘入结果中。

阶乘函数的迭代形式比示例 4.2 中展示的版本更简单也更快。但并非总是可以用迭代替代递归。在实现需要多重分支的算法时（例如汉诺塔算法），或遍历二叉树时，递归或其某种模拟形式是必要的。第 7 章的归并排序和快速排序算法也是需要递归的示例。幸运的是，我们总是可以用栈来模拟递归。现在让我们转向汉诺塔函数的非递归版本，该函数无法用迭代方式实现。

**示例 4.3** 图 2.2 所示的 TOH 函数进行了两次递归调用：一次将 n − 1 个圆盘从底部圆盘上移开，另一次将这些 n − 1 个圆盘移回目标柱子。我们可以通过使用栈来存储 TOH 必须执行的三个操作的表示，从而消除递归：两次递归调用和一次移动操作。为此，我们必须首先设计出各种操作的表示，并将其实现为一个类，该类的对象将存储在栈中。

## 4.3 队列

与栈一样，队列是一种类似列表的结构，对其元素的访问受到限制。队列元素只能在后端插入（称为入队操作），并从前端移除（称为出队操作）。队列的操作方式就像在电影院售票柜台前排队一样。¹ 如果没有人插队，那么新来的人会排到队伍的末尾。队伍最前面的人是下一个得到服务的人。因此，队列按照到达顺序释放元素。早在计算机出现之前很久，会计人员就已经在使用队列了。他们称队列为“FIFO”列表，意为“先进先出”。图 4.23 展示了一个队列 ADT 的示例。本节介绍队列的两种实现：基于数组的队列和链式队列。

### 4.3.1 基于数组的队列

要有效地实现基于数组的队列有些棘手。简单转换基于数组的列表实现并不高效。

假设队列中有 n 个元素。与基于数组的列表实现类似，我们可以要求队列的所有元素存储在数组的前 n 个位置。如果我们选择队列的队尾元素位于位置 0，那么出队操作只需 Θ(1) 时间，因为队列的队首元素（即被移除的元素）是数组中的最后一个元素。然而，入队操作将需要 Θ(n) 时间，因为队列中当前的 n 个元素每个都必须在数组中移动一个位置。反之，如果我们选择队列的队尾元素位于位置 n − 1，那么入队操作就等同于对列表的追加操作。这只需要 Θ(1) 时间。但现在，出队操作需要 Θ(n) 时间，因为所有元素都必须向下移动一个位置，以保持剩余的 n − 1 个队列元素位于数组的前 n − 1 个位置这一性质。

¹ 在英国，人们排成的队伍被称为“queue”，而排队等候服务被称为“queuing up”。
