
平均成本为 O(n²)。因此，随着 n 的增大，具有高成本的输入所占比例必须趋向于零的极限。我们可以得出结论，如果能够避免那极少数坏的输入排列，快速排序将具有良好的行为。

快速排序的运行时间可以得到改进（常数因子），并且已经投入了大量研究来优化该算法。最明显改进的地方是 findpivot 函数。快速排序的最坏情况出现在 pivot 对数组分割成大小相等的子数组效果不佳时。如果我们愿意花费更多的工作来寻找更好的 pivot，就能减少甚至消除坏 pivot 的影响。一个不错的选择是使用“中位数三数”算法，它使用三个随机选择的值的中间值作为 pivot。使用随机数生成器来选择位置相对昂贵，因此一个常见的折中方案是查看当前子数组的第一个、中间和最后一个位置。然而，我们简单的取中间值作为 pivot 的 findpivot 函数的优点在于，它使得偶然得到坏输入的可能性极低，并且实现成本很低。这与选择第一个或最后一个元素作为 pivot 形成鲜明对比，后者对于许多接近已排序或接近逆序排列的排列会产生糟糕的性能。

通过认识到当 n 很小时快速排序相对较慢，可以获得显著的改进。如果我们大多数时间排序大数组，这可能似乎不相关，也不应在罕见的小数组排序时快速排序花费多长时间，因为它无论如何都会很快。但你应该注意到快速排序本身会排序很多很多个小数组！这是分而治之方法的自然副产品。

一个简单的改进可能是用更快的排序来替换小数量的快速排序，例如插入排序或选择排序。然而，还有一个更好——而且更简单——的优化。当快速排序的分区低于某个大小时，什么都不做！该分区内的值将是无序的。然而，我们确实知道分区左侧数组中的所有值都小于分区中的所有值。分区右侧数组中的所有值都大于分区中的所有值。因此，即使快速排序仅将值“近似”放到正确的位置，数组也将接近有序。这是利用插入排序最佳性能的理想情况。最后一步是对整个数组进行一次插入排序调用，将元素放入最终的有序状态。经验测试表明，当子数组减少到九个或更少元素时，应保持其无序。

最后要考虑的加速是减少递归调用的成本。快速排序本质上是递归的，因为每次快速排序操作都必须对两个子列表进行排序。因此，没有简单的方法可以将快速排序转换为迭代算法。然而，快速排序可以通过使用栈来模拟递归来实现，因为必须存储的信息量很小。我们不需要存储子数组的副本，只需存储子数组的边界即可。此外，如果仔细控制快速排序递归调用的执行顺序，栈深度可以保持很小。我们还可以将 findpivot 和 partition 的代码内联以消除剩余的函数调用。请注意，通过不按上述建议处理大小为九或更小的子列表，约四分之三的函数调用已经消除。因此，消除剩余的函数调用只会带来适度的加速。

## 7.6 堆排序

我们对快速排序的讨论始于考虑使用二叉搜索树进行排序的实用性。BST 需要的空间比其他排序方法更多，并且由于向树中插入值的相对开销，它会比快速排序或归并排序慢。BST 还有可能不平衡，导致 Θ(n²) 的最坏情况运行时间。BST 中的子树平衡与快速排序的分区步骤密切相关。快速排序的 pivot 在功能上与 BST 根值大致相同，因为左分区（子树）存储小于 pivot（根）的值，而右分区（子树）存储大于或等于 pivot（根）的值。

可以基于更适合此目的的树结构设计出一个良好的排序算法。特别是，我们希望树是平衡的、空间高效且快速的。该算法应利用排序是一个特殊用途应用这一事实，即所有要存储的值在开始时都可用。这意味着我们不一定需要一次插入一个值到树结构中。

堆排序基于第 5.5 节介绍的堆数据结构。堆排序具有上面列出的所有优点。完全二叉树是平衡的，其数组表示是空间高效的，并且我们可以一次性将所有值加载到树中，利用高效的 buildheap 函数。堆排序的渐近性能在最好、平均和最坏情况下均为 Θ(n log n)。它在平均情况下不如快速排序快（常数因子），但堆排序具有特殊属性，使其在排序无法放入主内存的数据集时特别有用，如第 8 章所述。

基于最大堆的排序算法相当直接。首先我们使用第 5.5 节的堆构建算法将数组转换为最大堆顺序。然后我们反复从堆中移除最大值，每次这样做时恢复堆属性，直到堆为空。请注意，每次我们从堆中移除最大元素时，它都会被放置在数组的末尾。假设 n 个元素存储在数组位置 0 到 n − 1。移除堆中的最大值并重新调整后，最大值现在将被放置在数组的 n − 1 位置。堆现在被认为是大小为 n − 1。移除新的最大值（根）值会将第二大值放在数组的 n − 2 位置。依次移除其余每个值后，数组将从小到大正确排序。这就是为什么堆排序使用最大堆而不是可能预期的最小堆的原因。图 7.15 说明了堆排序。完整的 C++ 实现如下：

```
template <typename E, typename Comp>
void heapsort(E A[], int n) { // Heapsort
    E maxval;
    heap<E,Comp> H(A, n, n);     // Build the heap
    for (int i=0; i<n; i++)     // Now sort
        maxval = H.removefirst();   // Place maxval at end
}
```

由于构建堆需要 Θ(n) 时间（参见第 5.5 节），并且 n 次删除最大元素每次都需要 Θ(log n) 时间，我们看到整个堆排序操作在最坏、平均和最好情况下都需要 Θ(n log n) 时间。虽然通常比快速排序慢一个常数因子，但堆排序相比迄今为止研究的其它排序有一个特殊的优势。构建堆相对便宜，需要 Θ(n) 时间。从堆中移除最大元素需要 Θ(log n) 时间。因此，如果我们想找到数组中 k 个最大的元素，我们可以在 Θ(n + k log n) 时间内完成。如果 k 很小，这比使用前面描述的其它排序方法之一找到 k 个最大元素所需的时间有了实质性改进（其中许多方法需要先对整个数组进行排序）。我们可以利用这一概念的一种情况是在第 11.5.2 节的 Kruskal 最小成本生成树（MST）算法的实现中。该算法要求按升序访问边（因此使用最小堆），但该过程在 MST 完成后立即停止。因此，只需要对相对较小的部分边进行排序。

## 7.7 桶排序和基数排序

想象一下，在过去的一年里，当你支付各种账单时，你只是简单地把所有文件堆在某个桌子上。现在一年结束了，是时候按账单类型（电话、电费、租金等）和日期对所有这些文件进行排序了。一个相当自然的方法是在地板上腾出一些空间，然后在翻阅文件堆时，把电话账单放到一个堆里，电费账单放到另一个堆里，依此类推。一旦完成将账单分配到堆的初始工作（一次遍历），就可以相对快速地按日期对每个堆进行排序，因为它们每个都相当小。这就是桶排序的基本思想。

```
for (i=0; i<n; i++)
    B[A[i]] = A[i];
```
