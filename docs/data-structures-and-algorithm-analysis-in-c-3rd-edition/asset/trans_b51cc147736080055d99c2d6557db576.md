// 与之关联的子树。此信息以 2-3 树节点的形式给出，
// 具有一个键和一个（可能为 NULL）通过
// 中心指针字段的子树。
template <typename Key, typename E>
TTNode<Key,E>* TTNode<Key, E>::add(TTNode<Key,E>* it) {
    if (rkey == EMPTYKEY) { // 只有一个键，在此处添加
        if (lkey < it->lkey) {
            rkey = it->lkey; rval = it->lval;
            right = center; center = it->center;
        }
        else {
            rkey = lkey; rval = lval; right = center;
            lkey = it->lkey; lval = it->lval;
            center = it->center;
        }
        return this;
    }
    else if (lkey >= it->lkey) { // 添加到左侧
        center = new TTNode<Key,E>(rkey, rval, EMPTYKEY, NULL,
                                    center, right, NULL);
        rkey = EMPTYKEY; rval = NULL; right = NULL;
        it->left = left; left = it;
        return this;
    }
    else if (rkey < it->lkey) { // 添加到中心
        it->center = new TTNode<Key,E>(rkey, rval, EMPTYKEY,
                                       NULL, it->center, right, NULL);
        it->left = this;
        rkey = EMPTYKEY; rval = NULL; right = NULL;
        return it;
    }
    else { // 添加到右侧
        TTNode<Key,E>* N1 = new TTNode<Key,E>(rkey, rval,
                                              EMPTYKEY, NULL, this, it, NULL);
        it->left = right;
        right = NULL; rkey = EMPTYKEY; rval = NULL;
        return N1;
    }
}

B 树是 2-3 树的推广。换句话说，2-3 树是三阶 B 树。通常，B 树中节点的尺寸选择以填满磁盘块。B 树节点实现通常允许 100 个或更多子节点。因此，B 树节点相当于一个磁盘块，而树中存储的“指针”值实际上是包含子节点的块的编号（通常解释为对应磁盘文件的起始偏移量）。在典型的应用中，B 树对磁盘文件的访问将使用缓冲池和诸如 LRU 之类的块替换方案进行管理（参见第 8.3 节）。

图 10.17 显示了一个四阶 B 树。每个节点包含最多三个键，内部节点最多有四个子节点。

B 树中的搜索是 2-3 树中搜索的推广。它是一个交替的双步过程，从 B 树的根节点开始。

- 1. 对当前节点中的记录进行二分搜索。如果找到具有搜索键的记录，则返回该记录。如果当前节点是叶子节点且未找到键，则报告搜索不成功。
- 2. 否则，沿正确的分支继续并重复该过程。

例如，考虑在图 10.17 的树中搜索键值为 47 的记录。检查根节点并取第二个（右侧）分支。检查完第 1 层的节点后，取第三个分支到下一层到达包含键值为 47 的记录的叶子节点。

B 树插入是 2-3 树插入的推广。第一步是找到应包含要插入键的叶子节点，空间允许的情况下。如果此节点有空间，则插入键。如果没有，则将节点拆分为两个并将中间键提升到父节点。如果父节点已满，则将其拆分，其中间键提升。

请注意，此插入过程保证所有节点至少半满。例如，当我们尝试向四阶 B 树的已满内部节点插入时，现在必须处理五个子节点。将节点拆分为

### 10.5.1 B⁺-树

上一节提到 B 树被普遍用于实现大规模磁盘系统。实际上，上一节描述的 B 树几乎从未被实现，2-3 树在第 10.4 节中描述的方式也几乎从未被实现。最常见实现的是 B 树的一个变体，称为 B⁺-树。当需要更高的效率时，使用更复杂的变体 B*-树。

当数据是静态的时，线性索引提供了一种极其高效的搜索方式。问题是如何处理那些讨厌的插入和删除。我们可以尝试保留存储基于数组的排序列表的核心思想，但通过将列表分解为更易于更新的可管理块使其更灵活。我们该如何做呢？首先，我们需要决定块的大小有多大。由于数据在磁盘上，存储一个块大小的块，或磁盘块大小的少量倍数似乎是合理的。如果要插入的下一条记录属于尚未填满其块的块，那么我们可以直接在那里插入。事实上，这可能会导致该块中的其他记录在数组中稍微移动一点，这并不重要，因为只要我们在该块内移动数据，就不会导致额外的磁盘访问。但如果块填满了包含它的整个块怎么办？我们可以将其一分为二。如果我们想删除一条记录怎么办？我们可以直接从块中取出被删除的记录，但我们可能不希望有很多近乎空的块。所以如果它们之间只有少量数据，我们可以将相邻块合并在一起。或者我们可以将相邻块之间的数据重新排列，使它们一起包含更多数据。大的问题将是如何在处理具有给定键的记录时找到所需的块。也许某种树状结构可以用来定位适当的块。这些想法正是 B⁺-树的动机。B⁺-树本质上是管理一个基于数组的排序列表的机制，其中列表被分解成块。

B⁺-树与 BST 或标准 B 树之间最显著的区别是 B⁺-树仅在叶子节点存储记录。内部节点存储键值，但这些键值仅用作引导搜索的占位符。这意味着内部节点在结构上与叶子节点显著不同。内部节点存储键以引导搜索，将每个键与指向子 B⁺-树节点的指针关联。叶子节点存储实际记录，或者如果 B⁺-树纯粹用作索引，则存储键和指向单独磁盘文件中实际记录的指针。根据记录大小与键大小的比较，B⁺-树阶为 m 的叶子节点可能有足够的空间存储多于或少于 m 条记录。要求很简单，即叶子节点存储足够的记录以保持至少半满。B⁺-树的叶子节点通常链接在一起

一个重要的实现细节需要注意的是，虽然图 10.17 显示内部节点包含三个键和四个指针，但类 BPNode 稍有不同，因为它存储键/指针对。图 10.17 按传统方式绘制 B⁺-树。为了简化实际实现，节点实际上确实将一个键与每个指针关联。每个内部节点应假定在最左侧位置保存一个额外键，该键小于或等于其最左侧子树中任何可能键值。B⁺-树实现通常在最左侧叶子节点中存储一个额外的虚拟记录，其键值小于任何合法键值。
