
我们下一个关于归约的例子涉及两个 n × n 矩阵的乘法。对于这个问题，我们假设矩阵中存储的值是简单整数，并且两个简单整数相乘需要常数时间（因为两个 int 变量的乘法需要固定数量的机器指令）。两个矩阵相乘的标准算法是：将第一个矩阵第一行的每个元素与第二个矩阵第一列的对应元素相乘，然后将这些数相加。这需要 Θ(n) 时间。解中的 n² 个元素都以类似方式计算，总共需要 Θ(n³) 时间。已知有更快的算法（参见 16.3.3 节对 Strassen 算法的讨论），但没有一个能快到 O(n²)。

现在，考虑两个对称矩阵相乘的情况。对称矩阵是指第 ij 个元素等于第 ji 个元素的矩阵；也就是说，矩阵的右上三角部分是左下三角部分的镜像。在这种受限情况下，是否存在某种特性允许我们比一般情况更快地相乘两个对称矩阵？答案是不能，这一点可以通过下面的归约看出。假设我们有两个 n × n 矩阵 A 和 B。我们可以按如下方式从任意矩阵 A 构造一个 2n × 2n 对称矩阵：

```
[ 0  A ]
[ Aᵀ 0 ]
```

这里 0 表示一个由零值组成的 n × n 矩阵，A 是原始矩阵，Aᵀ 表示矩阵 A 的转置。¹ 注意，得到的矩阵现在是对称的。我们可以用类似的方式将矩阵 B 转换为对称矩阵。如果对称矩阵可以“快速”相乘（特别是，如果它们可以在 Θ(n²) 时间内相乘），那么我们就可以利用下面的观察结果，在 Θ(n²) 时间内找到两个任意 n × n 矩阵相乘的结果：

```
[ 0  A ][ 0  Bᵀ ] = [ AB  0 ]
[ Aᵀ 0 ][ B  0 ]   [ 0  AᵀBᵀ ]
```

在上面的公式中，AB 是矩阵 A 和 B 相乘的结果。

## 17.2 困难问题

一个问题可能因多种原因而被认为是困难的。例如，我们可能难以理解问题本身的定义。在一个大型数据收集与分析项目开始时，开发人员和客户可能对他们的实际目标只有一个模糊的概念，需要随着时间推移逐步明确。对于其他类型的问题，我们可能难以找到或理解求解该问题的算法。理解英语口语并将其转换为书面文本就是这样一个例子：其目标易于定义，但解决方案却不易发现。不过，即使自然语言处理算法可能很难编写，程序的运行时间也可能相当快。当今有许多实用系统能够在合理的时间内解决该问题的某些方面。

这些都不是计算机理论家使用“困难”一词时的通常含义。在本节中，“困难”意味着该问题已知的最佳算法在运行时间上代价高昂。困难问题的一个例子是汉诺塔。这个问题及其解决方案很容易理解，编写程序来解决它也很容易。但是，对于任何“合理”大的 n 值，运行它都需要极长的时间。试着运行一个程序来解决仅 30 个圆盘的汉诺塔吧！

汉诺塔问题需要指数时间，即其运行时间为 Θ(2ⁿ)。这与需要 Θ(n log n) 时间或 Θ(n²) 时间的算法有着根本性的不同。它甚至与需要 Θ(n⁴) 时间的问题也有根本性不同。这些都是多项式运行时间的例子，因为这些方程所有项的指数都是常数。回忆一下第 3 章的内容：如果我们购买一台运行速度提高一倍的新计算机，那么在给定时间内能解决的复杂度为 Θ(n⁴) 的问题规模将增加 2 的四次方根倍。换句话说，存在一个乘法因子的增加，即使它是一个相当小的因子。对于任何运行时间可以用多项式表示的算法，这都是成立的。

考虑一下，如果你买了一台速度快一倍的计算机，并试图在给定时间内解决一个更大的汉诺塔问题，会发生什么。由于它的复杂度是 Θ(2ⁿ)，我们只能多解决一个圆盘！这里没有乘法因子，而且对于任何指数算法都是如此：处理能力增加一个常数因子，只能带来解题能力的一个固定加法增量。

多项式运行时间与指数运行时间之间还有许多其他根本性差异，这些差异支持将它们视为性质上不同的类别。多项式在复合和加法下是封闭的。因此，按顺序运行多项式时间程序，或者让一个多项式运行时间的程序调用另一个程序多项式次，所得到的总时间仍然是多项式时间。此外，所有已知的计算机在多项式意义上都是相关的。也就是说，任何在今天任何一台计算机上以多项式时间运行的程序，当移植到任何其他计算机上时，仍然会以多项式时间运行。

认识到这种区别有一个实际原因。在实践中，大多数多项式时间算法是“可行”的，因为它们能在合理的时间内处理相当大的输入。相比之下，大多数需要指数时间的算法即使对于相当小的输入规模也不实用。有人可能会说，一个高次多项式（如 n¹⁰⁰）的程序不实用，而一个代价为 1.001ⁿ 的指数时间程序却实用。但现实是，我们几乎不知道有任何问题的最佳多项式时间算法具有高次数（它们几乎都只有四次或更低），而几乎没有任何指数时间算法（其代价为 O(cⁿ)）的常数 c 接近 1。因此，在实践中，多项式时间算法与指数时间算法之间并没有多少灰色地带。

在本章余下部分，我们将困难算法定义为以指数时间运行的算法，即对于某个常数 c > 1，运行时间为 Ω(cⁿ)。下一节将给出困难问题的定义。

### 17.2.1 NP 完全性理论

想象一台神奇的计算机，它通过从问题的所有可能解中猜出正确解来工作。另一种看待这个问题的方式是，想象一台超级并行计算机能够同时测试所有可能的解。当然，这台神奇（或高度并行）的计算机能做普通计算机能做的任何事情。它也可能比普通计算机更快地解决某些问题。考虑某个问题，给定一个解的猜测，检查该解是否正确可以在多项式时间内完成。即使可能解的数量是指数级的，任何给定的猜测都可以在多项式时间内被检查（等价地，所有可能的解都在多项式时间内被同时检查），因此通过我们假设的神奇计算机，该问题可以在多项式时间内被解决。这个概念的另一种看法是：如果你不能通过猜出正确答案然后检查它来在多项式时间内获得问题的答案，那么你也无法以任何其他方式在多项式时间内做到这一点。

“猜测”问题的正确答案——或者并行检查所有可能解以确定哪个是正确的——这种想法被称为非确定性。以这种方式工作的算法称为非确定性算法，任何在非确定性机器上以多项式时间运行的算法所对应的问题都有一个特殊的名称：称该问题属于 NP。因此，NP 中的问题就是那些可以在非确定性机器上以多项式时间解决的问题。

并非所有在普通计算机上需要指数时间的问题都属于 NP。例如，汉诺塔就不属于 NP，因为它必须为 n 个圆盘打印出 O(2ⁿ) 步移动。非确定性机器无法在更短的时间内“猜出”并打印出正确答案。
