换个角度看，第二名的候选者只能是最终赢家的失败者，而我们的目标是让这类元素尽可能少。因此我们需要跟踪那些在直接比较中输给（最终）赢家的元素集合。我们还观察到，当两名竞争者已知都大于相同数量的其他值时，我们从一次比较中获得的信息最多。因此我们希望安排比较，使其对手是“实力相当”的竞争者。我们可以用二叉树来完成所有这些。高度为 m 的二叉树有 2^m 个节点。它要么是一个单节点（当 m = 0 时），要么是由两个高度为 m − 1 的二叉树组成，其中一棵树的根成为另一棵树的子节点。图 15.2 说明了如何构造一个具有八个节点的二叉树。

由此产生的算法在原则上很简单：为所有 n 个元素构建二叉树，然后比较根的 ⌈log n⌉ 个子节点以找到第二名。我们可以将二叉树存储为显式的树结构，并且很容易在线性于比较次数的时间内构建它，因为每次比较只需要添加一个链接。由于二叉树的形状受到严格限制，我们也可以像堆一样隐式地将其存储在数组中。假设两个树各有 2^k 个节点，都在数组中。第一棵树位于位置 1 到 2^k。第二棵树位于位置 2^k + 1 到 2^{k+1}。每个子树的根位于该子树在数组中的最后一个位置。

要合并两棵树，我们只需比较子树的根。如果必要，交换子树，使根元素较大的树成为第二棵子树。这用空间换取时间（我们只需要为数据值提供空间，无需节点指针），在最坏情况下，所有的数据交换可能花费 O(n log n)，但这并不影响所需的比较次数。请注意，对于某些应用，这是一个重要的观察，即数组的数据交换不需要比较。如果比较只是两个整数之间的检查，那么当然，在数组中移动一半的值代价太高。但如果比较需要让两支运动队进行比赛，那么一点（甚至很多）簿记的成本就变得无关紧要了。

由于二叉树的根有 ⌈log n⌉ 个子节点，而构建树需要 n − 1 次比较，该算法所需的比较次数为 n + ⌈log n⌉ − 2。这显然优于我们之前的算法。它是最优的吗？

我们现在回到尝试改进下界证明。为此，我们引入对手的概念。对手的任务是使算法的成本尽可能高。想象对手保存着所有可能输入的列表。我们把算法看作是向对手询问有关算法输入的信息。对手绝不能撒谎，其答案必须与之前的答案一致。但它被允许“重新排列”输入，以使其认为的方式来最大化算法的总成本。特别是，当算法提出一个问题时，对手必须以与至少一个剩余输入一致的方式回答。然后对手划掉所有与该答案不一致的剩余输入。请记住，计算机程序内部并没有真正存在一个对手实体，我们也不实际修改程序。对手仅仅作为一种分析工具，帮助我们推理程序。

作为对手概念的例子，考虑标准的 Hangman 游戏。玩家 A 选择一个单词并告诉玩家 B 该单词有多少个字母。玩家 B 猜测各种字母。如果 B 猜中了单词中的字母，则 A 会指出单词中该字母的位置。玩家 B 只能猜测有限次不在单词中的字母，否则就会输。

在 Hangman 游戏的例子中，对手被想象为持有某个选定长度的词典。每次玩家猜一个字母时，对手会查阅词典并决定是接受该字母（并指出其所在位置）还是说它不在单词中，从而消除更多的单词。对手可以做出任何选择，只要词典中至少有一个单词与所有决定一致。通过这种方式，对手希望让玩家猜测尽可能多的字母。

在解释对手如何在我们的下界证明中发挥作用之前，首先观察到至少有 n − 1 个值必须至少输一次。这至少需要 n − 1 次比较。此外，至少有 k − 1 个值必须输给第二大值。也就是说，赢家必须有 k 个直接失败者。必须至少有 n + k − 2 次比较。问题是：我们能让 k 有多低？

称元素 A[i] 的强度为 A[i] 已知大于的元素数量。如果 A[i] 的强度为 a，且 A[j] 的强度为 b，则赢家的强度为 a + b + 1。算法可以知道每个元素的（当前）强度，并且可以挑选接下来比较的两个元素。对手可以决定任何一次比较的赢家。对手的什么策略会使算法从任何一次比较中获得的信息最少？它应该最小化任何元素强度提高的速度。它可以通过让每次比较中强度更大的元素获胜来实现。这是对对手的一种“公平”使用，因为它代表了为给定算法提供最坏情况输入的结果。

为了最小化最坏情况行为的影响，算法的最佳策略是最大化强度最小的提升，通过平衡任何两个竞争者的强度。从算法的角度来看，最好的结果是元素的强度翻倍。这发生在 a = b 时，其中 a 和 b 是正在比较的两个元素的强度。所有强度都从零开始，因此赢家必须在 2^{k-1} < n ≤ 2^k 时至少进行 k 次比较。因此，至少必须有 n + ⌈log n⌉ − 2 次比较。所以我们的算法是最优的。

## 15.5 状态空间下界证明

我们现在考虑从一个（未排序的）值列表中同时找到最小值和最大值的问题。如果我们想知道一组值的范围以绘制图表的刻度，这可能很有用。当然我们可以独立地在 2n − 2 次比较中找到它们。稍作修改，可以在 n − 1 次比较中找到最大值，将其从列表中移除，然后再用 n − 2 次比较找到最小值，总共 2n − 3 次比较。我们能做得更好吗？

继续之前，先想一想，这个寻找最小值和最大值的问题与上一节的问题，即寻找第二大值（从而隐含最大值）相比如何？你认为这两个问题哪个更难？这可能对你来说并不明显，一个问题比另一个更难或更易。直觉可以为任一情况辩护。一方面，直觉可能认为寻找最大值的过程应该告诉你关于第二大值的一些信息，多于它告诉你关于最小值的信息。另一方面，任何一次比较都会告诉你哪一个可以成为最大值候选者，哪一个可以成为最小值候选者，从而在两个方向上取得进展。

我们将从一种简单的分治方法开始寻找最小值和最大值。将列表分成两部分并在每部分中找到最小值和最大值元素。然后用另外两次比较将两个最小值和最大值相互比较以得到最终结果。该算法如图 15.3 所示。

该算法的成本可以用以下递推式建模。

$$
T(n) = \begin{cases}
0 & n = 1 \\
1 & n = 2 \\
T(\lfloor n/2 \rfloor) + T(\lceil n/2 \rceil) + 2 & n > 2
\end{cases}
$$

这是一个相当有趣的递推式，其解在 3n/2 − 2（当 n = 2^i 或 n = 2^i ± 1 时）和 5n/3 − 2（当 n = 3 × 2^i 时）之间。我们可以从这种行为推断出，我们如何划分列表会影响算法的性能。
