## 图 13.17 PR 四叉树插入示例。

(a) 包含两个数据点的初始 PR 四叉树。(b) 插入点 C 的结果。包含 A 的块必须分解为四个子块。如果只进行一次细分，点 A 和点 C 仍会在同一块中，因此需要第二次分解才能将它们分开。

NE 象限包含 x 值在 64 到 127 范围内，且 y 值在 0 到 63 范围内的点。如果根的子节点是叶节点，则检查该子节点是否已找到 Q。如果子节点是另一个内部节点，则搜索过程会继续遍历树，直到找到叶节点。如果该叶节点存储的记录位置与 Q 匹配，则查询成功；否则 Q 不在树中。

将记录 P 插入 PR 四叉树时，首先定位包含 P 位置的叶节点。如果该叶节点为空，则将 P 存储在此叶节点中。如果叶节点已包含 P（或具有 P 坐标的记录），则应报告重复记录。如果叶节点已包含另一条记录，则必须反复分解该节点，直到现有记录和 P 落入不同的叶节点。图 13.17 显示了此类插入的示例。

删除记录 P 是首先定位包含 P 的 PR 四叉树节点 N。节点 N 然后被更改为空。下一步是查看 N 的三个兄弟节点。如果它们中仅包含一个点，则必须将 N 及其兄弟节点合并形成单个节点 N′。此合并过程会继续，直到达到某个层级，在该层级中，节点 N′ 及其兄弟节点所代表的子树中至少包含两个点。例如，如果要从图 13.17(b) 所示的 PR 四叉树中删除点 C，则 resulting 节点必须与其兄弟节点合并，并且该较大节点再次与其兄弟节点合并，以将 PR 四叉树恢复为图 13.17(a) 的分解。

区域搜索使用 PR 四叉树很容易实现。要找到查询点 Q 半径为 r 范围内的所有点，从根开始。如果根是空叶节点，则找不到任何数据点。如果根是包含数据记录的叶节点，则检查数据点的位置以确定其是否落在圆内。如果根是内部节点，则该过程会递归执行，但仅对包含搜索圆的某些部分的那些子树执行。

现在让我们考虑 PR 四叉树的结构如何影响其节点表示的设计。PR 四叉树实际上是一个 trie（定义见第 13.1 节）。分解在内部节点的中间点处进行，而与数据点实际落在哪里无关。数据点的放置决定了是否对节点进行分解，但不决定节点分解的位置。PR 四叉树的内部节点与叶节点非常不同，因为内部节点有子节点（叶节点没有），而叶节点有数据字段（内部节点没有）。因此，将内部节点与叶节点不同地表示可能是有益的。最后，大约一半的叶节点将不包含数据字段。

另一个需要考虑的问题是：遍历 PR 四叉树的例程如何获取当前 PR 四叉树节点所代表的正方形的坐标？一种可能性是为每个节点存储其空间描述（例如左上角和宽度）。然而，这会占用大量空间——可能与数据记录所需的空间一样多，具体取决于存储的信息。

另一种可能性是在进行递归调用时传入坐标。例如，考虑搜索过程。最初，搜索访问树的根节点，其原点在 (0, 0)，宽度为所覆盖空间的完整大小。当访问适当的子节点时，搜索例程很容易确定子节点的原点，正方形的宽度只是其父节点的一半。不仅传入节点的尺寸和位置信息可以节省大量空间，而且避免在节点中存储此类信息使得空叶节点的良好设计成为可能，如下所述。

我们应如何表示空叶节点？平均而言，PR 四叉树中一半的叶节点为空（即不存储数据点）。一种实现选项是在内部节点中使用 NULL 指针来表示空节点。这将解决过多的空间需求问题。使用 NULL 指针会产生一个不幸的副作用，即要求 PR 四叉树处理方法理解此约定。换句话说，你破坏了节点表示的封装，因为树现在必须知道有关节点如何实现的信息。对于此特定应用来说，这并不太糟糕，因为节点类可以被视为树类的私有，在这种情况下，节点实现对外部世界完全不可见。然而，如果有另一个合理的替代方案，则这是不可取的。

幸运的是，有一个很好的替代方案。它被称为享元设计模式。在 PR 四叉树中，享元是单个空叶节点，在需要空叶节点的所有位置重复使用。你只需让所有具有空叶子节点的内部节点都指向同一个节点对象即可。该节点对象在程序开始时创建一次，并且永远不会被删除。节点类通过指针值识别正在访问享元，并相应地处理。

请注意，使用享元设计模式时，你不能在节点中存储节点的坐标。这是内在状态与外在状态概念的一个例子。对象的内在状态是存储在对象中的状态信息。如果你将节点的坐标存储在节点对象中，则这些坐标将是内在状态。外在状态是存储在环境中（如全局变量）或传递给方法的对象状态信息。如果你的递归调用在处理树时传入当前节点的坐标，则坐标将是外在状态。享元在其内在状态中只能拥有对享元的所有实例都准确的信息。显然坐标不符合条件，因为每个空叶节点都有自己的位置。因此，如果你想使用享元，就必须传入坐标。

另一个设计选择是：谁控制工作，节点类还是树类？例如，在插入操作中，你可以让树类控制沿树的流程，查看（查询）节点以查看其类型并相应地做出反应。这是第 5.4 节中 BST 实现采用的方法。另一种方法是让节点类执行工作。也就是说，你为节点提供一个 insert 方法。如果节点是内部的，它会将城市记录传递给适当的子节点（递归）。如果节点是享元，它会用新的叶节点替换自身。如果节点已满，它会用子树替换自身。这是第 5.3.1 节中讨论的组合设计模式的示例。如果使用 NULL 指针表示空叶节点，使用组合设计会很困难。事实证明，使用组合设计时，PR 四叉树插入和删除方法更容易实现。

## 13.3.3 其他点数据结构

k-d 树与 PR 四叉树之间的差异说明了在创建空间数据结构时遇到的许多设计选择。k-d 树提供区域的对象空间分解，而 PR 四叉树提供键空间分解（因此，它是一个 trie）。k-d 树在所有节点存储记录，而 PR 四叉树仅在叶节点存储记录。最后，两棵树的结构不同。k-d 树是二叉树（且不必是满的），而 PR 四叉树是具有 2^d 个分支的满树（在二维情况下，2^2 = 4）。考虑将此概念扩展到三维。三维的 k-d 树会交替通过 x、y 和 z 维度进行区分。三维 PR 四叉树的等价物将是具有 2^3 或八个分支的树。这种树称为八叉树。
