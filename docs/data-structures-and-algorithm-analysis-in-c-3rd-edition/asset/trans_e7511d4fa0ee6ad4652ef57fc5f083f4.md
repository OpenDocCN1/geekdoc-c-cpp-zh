遍历例程自然地写成递归函数。其输入参数是指向节点的指针，我们将其称为 rt，因为每个节点都可以视为某个子树的根。初始调用遍历函数时传入指向树的根节点的指针。遍历函数以所需顺序访问 rt 及其子节点（如果有）。例如，先序遍历规定先访问 rt 再访问其子节点。这可以很容易地实现如下。

```
template <typename E>
void preorder(BinNode<E>* root) {
    if (root == NULL) return;  // Empty subtree, do nothing
    visit(root);               // Perform desired action
    preorder(root->left());
    preorder(root->right());
}
```

函数 preorder 首先检查树是否为空（如果是，则遍历完成，preorder 仅返回）。否则，preorder 会调用 visit，该函数处理根节点（即打印值或执行应用程序所需的任何计算）。函数 preorder 然后在左子树上递归调用自身，这将访问该子树中的所有节点。最后，preorder 在右子树上调用，访问右子树中的所有节点。中序遍历和后序遍历类似。它们只是改变节点及其子节点被访问的顺序，以满足需要。

在树上实现任何递归函数时，一个重要决策是何时检查空子树。函数 preorder 首先检查 root 的值是否为 NULL。如果不是，它将递归调用自身处理 root 的左子节点和右子节点。换句话说，preorder 并没有尝试避免对空子节点进行自身调用。一些程序员使用另一种设计，即检查当前节点的左右指针，以便仅在非空子节点上进行递归调用。这种设计通常如下所示：

```
template <typename E>
void preorder2(BinNode<E>* root) {
    visit(root);  // Perform whatever action is desired
    if (root->left() != NULL) preorder2(root->left());
    if (root->right() != NULL) preorder2(root->right());
}
```

乍一看，preorder2 可能比 preorder 更高效，因为它进行的递归调用只有一半。（为什么？）另一方面，

preorder2 必须访问左右子节点指针的次数是两倍。净结果是性能几乎没有改善或没有改善。

实际上，与 preorder 相比，preorder2 的设计在两个原因上是劣等的。首先，虽然在这个简单示例中不明显，但对于更复杂的遍历，将对 NULL 指针的检查放在调用代码中可能会变得笨拙。在这里我们不得不写两个 NULL 测试，而 preorder 只需要一个。更重要的是，preorder2 的问题在于它容易出错。虽然 preorder2 确保不会对空子树进行递归调用，但如果初始调用传入 NULL 指针，它就会失败。这会在原始树为空时发生。为了避免错误，要么 preorder2 需要在开头额外测试 NULL 指针（这样随后的测试就变得冗余了），要么 preorder2 的调用者有隐藏的义务传入非空树，这是一种不可靠的设计。净结果是许多程序员忘记测试遍历空树的可能性。通过使用显式支持空子树处理的第一个设计，可以避免这个问题。

设计遍历时要考虑的另一个问题是如何定义要在每个节点上执行的访问者函数。一个方法是为每种访问者函数按需编写遍历的新版本。这种方法的缺点是执行遍历的函数必须能够访问 BinNode 类。更好的设计可能是只允许树类访问 BinNode 类。

另一种方法是让树类提供一个通用遍历函数，该函数将访问者作为模板参数或函数参数传递。这被称为访问者设计模式。这种方法的一个主要限制是所有访问者函数的签名，即它们的返回类型和参数，必须提前固定。因此，通用遍历函数的设计者必须能够充分判断潜在的访问者函数可能需要的参数和返回类型。

处理程序各部分之间信息流可能是一个重大的设计挑战，尤其是在处理递归函数如树遍历时。一般来说，我们可能会遇到传递给函数以完成其工作所需的正确信息的问题，或者将信息返回给递归函数的调用者的问题。我们将在全书中看到许多示例，说明如何在递归函数遍历树结构时将信息传入和传出。以下是几个简单示例。

### 示例 5.4 我们希望计算二叉树中节点的数量。关键的见解是，任何（非空）子树的总计数为根的 1 加上左右子树的计数。左右子树的计数从何而来？对子树调用函数 count 将为我们计算出来。因此，我们可以按如下方式实现 count。

```
template <typename E>
int count(BinNode<E>* root) {
    if (root == NULL) return 0;  // Nothing to count
    return 1 + count(root->left())
           + count(root->right());
}
```

```
template <typename Key, typename E>
bool checkBST(BSTNode<Key,E>* root, Key low, Key high) {
    if (root == NULL) return true; // Empty subtree
    Key rootkey = root->key();
    if ((rootkey < low) || (rootkey > high))
        return false; // Out of range
    if (!checkBST<Key,E>(root->left(), low, rootkey))
        return false; // Left side failed
    return checkBST<Key,E>(root->right(), rootkey, high);
}
```

## 5.3 二叉树节点实现

在本节中，我们研究实现二叉树节点的方法。我们首先介绍基于指针的二叉树节点实现的选项。然后讨论确定给定实现空间需求的技术。本节以对完全二叉树的基于数组的实现介绍结束。

### 5.3.1 基于指针的节点实现

根据定义，所有二叉树节点都有两个子节点，尽管一个或两个子节点可以为空。二叉树节点通常包含一个值字段，其类型取决于应用程序。最常见的节点实现包括一个值字段和指向两个子节点的指针。

图 5.7 显示了 BinNode 抽象类的简单实现，我们将其命名为 BSTNode。类 BSTNode 包含一个类型为 E 的数据成员，（它是第二个模板参数）用于元素类型。为了支持诸如二叉搜索树之类的搜索结构，还包含一个额外的字段，以及相应的访问方法，用于存储键值（其用途在第 4.4 节中解释）。其类型由第一个模板参数 Key 决定。每个 BSTNode 对象还具有两个指针，一个指向其左子节点，另一个指向其右子节点。可以添加重载的 new 和 delete 运算符以支持自由列表，如第 4.1.2 节所述。图 5.8 说明了 BSTNode 实现。

一些程序员发现添加指向节点父节点的指针很方便，从而允许在树中轻松向上移动。使用父指针有点类似于在双向链表中添加指向前一个节点的链接。实际上，父指针几乎总是没有必要，并且会增加树实现的空间开销。这不仅仅是父指针占用空间的问题。更重要的是，许多对父指针的使用源于对递归的错误理解，因此表明编程不佳。如果你倾向于使用父指针，请考虑是否有更高效的实现可能。
