
比较次数为 n − 1，即外层 for 循环执行的次数。因此，插入排序在最好情况下的代价为 Θ(n)。

虽然最好情况比最坏情况快得多，但最坏情况通常是“典型”运行时间的更可靠指标。然而，存在我们期望输入已排序或接近排序的情况。一个例子是当一个已排序的列表因少量添加而略微失序时；如果我们知道失序程度很轻，使用插入排序来恢复排序顺序可能是一个好主意。利用插入排序接近最好情况运行时间的算法示例有第 7.3 节的 Shellsort 算法和第 7.5 节的 Quicksort 算法。

插入排序的平均情况代价是多少？当处理记录 i 时，内层 for 循环的执行次数取决于该记录“失序”的程度。特别是，内层 for 循环会为数组位置 0 到 i − 1 中大于记录 i 的键的每一个键执行一次。例如，在图 7.1 的最左侧列中，值 15 前面有五个大于 15 的值。每一次这样的出现称为一个逆序。逆序的数量（即在数组中出现在给定值之前的更大值数量）将决定必须进行的比较和交换次数。我们需要确定位置 i 的记录的平均逆序数是多少。我们期望平均而言，前 i − 1 个数组位置中的一半键的值大于位置 i 处的键的值。因此，平均情况应约为最坏情况代价的一半，或约为 n²/4，仍为 Θ(n²)。因此，在渐近复杂度上，平均情况并不比最坏情况更好。

计数比较或交换会得到类似的结果。每次内层 for 循环的执行都会产生一次比较和一次交换，除了最后一次（即不满足内层 for 循环测试的比较），它没有交换。因此，整个排序操作的交换次数比比较次数少 n − 1。在最好情况下为 0，在平均和最坏情况下为 Θ(n²)。

## 7.2.2 冒泡排序

我们下一个排序算法称为冒泡排序。冒泡排序通常在入门计算机科学课程中教授给初学者程序员。这是不幸的，因为冒泡排序没有任何 redeeming 特性。它是一个相对较慢的排序，它并不比插入排序更容易理解，它与“日常”使用中的任何直观对应物都不对应，而且它具有较差的最好情况运行时间。然而，冒泡排序可以作为第 7.2.3 节中将要介绍的更好排序算法的灵感。

```
template <typename E, typename Comp>
void bubsrt(E A[], int n) { // Bubble Sort
for (int i=0; i<n-1; i++)      // Bubble up i’th record
  for (int j=n-1; j>i; j--)
    if (Comp::prior(A[j], A[j-1]))
      swap(A, j, j-1);
}
```

确定冒泡排序的比较次数很容易。无论数组中值的排列如何，内层 for 循环进行的比较次数始终为 i，导致总代价为

∑_{i=1}^{n} i ≈ n²/2 = Θ(n²)。

冒泡排序在最好、平均和最坏情况下的运行时间大致相同。

所需的交换次数取决于值小于其在数组中紧邻前一个值的频率。我们期望在平均情况下这会发生在大约一半的比较中，导致期望交换次数为 Θ(n²)。冒泡排序实际执行的交换次数与插入排序执行的交换次数相同。

再次考虑过去一年电话账单堆的排序问题。另一种直观的方法可能是浏览堆，直到找到一月份的账单，然后将其取出。然后浏览剩余的堆，直到找到二月份的账单，并将其放在一月后面。继续浏览不断缩小的账单堆以选择下一个按顺序的账单，直到完成。这就是我们最后一个 Θ(n²) 排序的灵感，称为选择排序。选择排序的第 i 次遍历“选择”数组中第 i 小的键，将该记录放入位置 i。换句话说，选择排序首先找到未排序列表中的最小键，然后是第二小的，依此类推。其独特之处在于记录交换次数很少。要找到下一个最小键值需要搜索整个未排序的数组部分，但只需一次交换即可将记录就位。因此，所需的总交换次数为 n − 1（我们“免费”得到最后一个记录就位）。图 7.3 说明了选择排序。下面是 C++ 实现。

```
template <typename E, typename Comp>
void selsort(E A[], int n) { // Selection Sort
for (int i=0; i<n-1; i++) { // Select i'th record
int lowindex = i; // Remember its index
for (int j=n-1; j>i; j--) // Find the least value
if (Comp::prior(A[j], A[lowindex]))
lowindex = j; // Put it in place
swap(A, i, lowindex);
}
}
```

选择排序（按此处编写）本质上是一个冒泡排序，只是我们不是反复交换相邻值以将下一个最小记录就位，而是记住要选择的元素的<|message|>位置并在最后进行一次交换。因此，比较次数仍为 Θ(n²)，但交换次数远少于冒泡排序所需的次数。选择排序特别

当交换的代价很高时，交换记录的指针是有利的，例如当元素是长字符串或其他大型记录时。在大多数其他情况下，选择排序也比冒泡排序更有效（常数因子）。

还有另一种方法可以在记录很大时保持交换代价低。这是在数组的每个元素中存储指向记录的指针而不是存储记录本身。在这种实现中，交换操作只需交换指针值；记录本身不会移动。这种技术由图 7.4 说明。需要额外的空间来存储指针，但回报是更快的交换操作。

## 7.2.4 交换排序的代价

图 7.5 总结了插入、冒泡和选择排序在最好、平均和最坏情况下所需的比较次数和交换次数¹ 的代价。这三种排序在平均和最坏情况下的运行时间均为 Θ(n²)。

本章中介绍的剩余排序算法在典型条件下明显优于这三种算法。但在继续之前，研究是什么使这三种排序如此缓慢是有启发性的。关键瓶颈是仅比较相邻记录。因此，比较和移动（除选择排序外）都是单步进行的。交换相邻记录称为交换。因此，这些排序有时被称为交换排序。任何交换排序的代价最多为数组中记录移动的总步数。

> 选择排序存在一个轻微的异常。选择排序的 supposed 优势是其所需的交换次数少，然而选择排序的最好情况交换次数比插入排序或冒泡排序更差。这是因为给出的选择排序实现在记录 i 已在位置 i 的情况下不会避免交换。可以加入一个测试来避免这种情况的交换。但通常进行测试所需的时间比避免此类交换所节省的时间更多。
