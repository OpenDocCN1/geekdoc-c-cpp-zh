
// 查找与给定键值匹配的记录
template <typename Key, typename E>
E TTTree<Key, E>::
findhelp(TTNode<Key,E>* root, Key k) const {
    if (root == NULL) return NULL;    // value not found
    if (k == root->lkey) return root->lval;
    if (k == root->rkey) return root->rval;
    if (k < root->lkey)                 // Go left
        return findhelp(root->left, k);
    else if (root->rkey == EMPTYKEY)    // 2 child node
        return findhelp(root->center, k);   // Go center
    else if (k < root->rkey)
        return findhelp(root->center, k);   // Go center
    else return findhelp(root->right, k);   // Go right
}

2-3 树的插入和删除例程不会在树的底部添加新节点。相反，它们会导致叶节点分裂或合并，可能导致向上传播到根的连锁反应。如果需要，根将分裂，从而创建新的根节点并使树加深一层。在删除时，如果根的最后两个子节点合并，则根节点将被移除，树将失去一个层级。在任何一种情况下，所有叶节点始终处于同一层级。当所有叶节点处于同一层级时，我们称树是高度平衡的。因为 2-3 树是高度平衡的，并且每个内部节点至少有两个子节点，我们知道树的最大深度为 log n。因此，所有 2-3 树的插入、查找和删除操作都需要 Θ(log n) 时间。

    TTNode<Key,E>* retval;

            NULL, NULL, NULL));

    // Add to internal node
    if (k < rt->lkey) {
        retval = inserthelp(rt->left, k, e);
        if (retval == rt->left) return rt;
        else return rt->add(retval);
    }
    else if((rt->rkey == EMPTYKEY) || (k < rt->rkey)) {
        retval = inserthelp(rt->center, k, e);
        if (retval == rt->center) return rt;
        else return rt->add(retval);
    }
    else { // Insert right

        if (retval == rt->right) return rt;
        else return rt->add(retval);

取代了除哈希之外几乎所有的大文件访问方法。B-树或其变体是需要插入、删除和键范围搜索的应用的标准文件组织。它们用于实现大多数现代文件系统。B-树有效地解决了在实现基于磁盘的搜索树时遇到的几乎所有主要问题：

- 1. B-树始终是高度平衡的，所有叶节点都在同一层级。
- 2. 更新和搜索操作只影响少数磁盘块。受影响的磁盘块越少，需要的磁盘 I/O 越少。
- 3. B-树将相关记录（即具有相似键值的记录）保存在同一个磁盘块中，这有助于由于引用局部性而最小化搜索时的磁盘 I/O。
- 4. B-树保证树中每个节点至少填充到某个最小百分比。这提高了空间效率，同时减少了搜索或更新操作期间通常需要的磁盘取数。

阶为 m 的 B-树的形状属性定义如下：

- 根要么是叶节点，要么至少有两个子节点。
- 除根之外的每个内部节点，子节点数在 ⌈m/2⌉ 和 m 之间。
