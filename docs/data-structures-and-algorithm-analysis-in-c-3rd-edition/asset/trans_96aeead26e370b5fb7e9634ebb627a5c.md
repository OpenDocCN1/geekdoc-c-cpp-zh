

许多程序会反复使用某些关键信息，而这些信息的重要性与其首次被访问的时间早晚关系不大。通常，更重要的是知道该信息被访问了多少次，或者该信息最近一次被访问是什么时候。

另一种方法称为“最不经常使用”（LFU）。LFU 跟踪缓冲池中每个缓冲区被访问的次数。当必须重用某个缓冲区时，被访问次数最少的缓冲区被视为包含“最不重要”的信息，因此会被优先使用。尽管 LFU 在直觉上似乎合理，但它有许多缺点。首先，需要为每个缓冲区存储和更新访问计数。其次，过去被频繁引用的信息现在可能已无关紧要。因此，通常需要某种让计数“过期”的时间机制。这也能避免某些缓冲区因为偶尔被使用而逐渐积累很高的计数，从而免于被替换的问题。另一种做法是为所有曾读过的扇区维护计数，而不仅仅是当前在缓冲池中的扇区。这可以避免刚读入的缓冲区立刻被替换，因为刚读入的缓冲区还没来得及建立较高的访问计数。

第三种方法称为“最近最少使用”（LRU）。LRU 简单地将缓冲区保存在一个列表中。每当某个缓冲区中的信息被访问时，该缓冲区就被移到列表的前端。当必须读取新信息时，就取列表尾部的缓冲区（即最近最少使用的那个），并根据情况将其“旧”信息丢弃或写回磁盘。这是对 LFU 的一种易于实现的近似方法，通常也是管理缓冲池的首选方法，除非对某应用程序的信息访问模式有特殊了解，从而建议采用专门的缓冲池管理方案。

缓冲池的主要目的是尽量减少磁盘 I/O。当一个块的内容被修改时，我们可以立即将更新后的信息写回磁盘。但如果该块再次被修改呢？如果每次修改后都写回块的内容，可能会产生大量本可避免的磁盘写操作。更高效的做法是等到文件即将关闭，或者包含该块的缓冲区内容即将从缓冲池中刷新时再写回。

当缓冲池中某个缓冲区的内容要被替换时，我们只希望在必要时将其内容写回磁盘。只有在块自最初从文件读入以来内容发生了修改时，才需要写回。确保块在必要时且仅在必要时写回的方法是：为缓冲区维护一个布尔变量（通常称为“脏位”），当客户端修改了缓冲区内容时将该位设置为开。当块从缓冲池刷新时，当且仅当脏位已被打开时，才会将其写回磁盘。

现代操作系统支持虚拟内存。虚拟内存是一种技术，它允许程序员编写程序时，仿佛存在比实际更多的快速主内存（如 RAM）。虚拟内存利用缓冲池来存储从较慢的辅助内存（如磁盘驱动器）中的块读取的数据。磁盘保存着虚拟内存的完整内容。内存访问时，块被读入主内存。自然，使用虚拟内存技术的程序比数据完全存储在主内存中的程序要慢。其优点是减少了程序员的工作量，因为一个好的虚拟内存系统无需修改程序即可提供更大主内存的假象。

在实现缓冲池时，关于缓冲池用户与缓冲池类本身之间的信息传输，可以采用两种基本方法。第一种方法是在两者之间传递“消息”。以下抽象类展示了这种方法：

![](img/7ea3c39173f146f675b63b146d1535f3_304_0.png)

// 使用消息传递风格的缓冲池 ADT
class BufferPool {
public:
// 将“space”中的“sz”字节复制到缓冲存储中的位置“pos”。
virtual void insert(void* space, int sz, int pos) = 0;
// 将缓冲存储中位置“pos”的“sz”字节复制到“space”。
virtual void getbytes(void* space, int sz, int pos) = 0;
};

这个简单的类提供了一个包含两个成员函数 insert 和 getbytes 的接口。信息通过 space 参数在缓冲池用户和缓冲池之间传递。该存储空间由缓冲池客户端提供，长度至少为 sz 字节，缓冲池可以从中获取信息（insert 函数）或将信息放入其中（getbytes 函数）。参数 pos 指示信息在缓冲池逻辑存储空间中的放置位置。物理上，它实际上会被复制到缓冲池中某个缓冲区的适当字节位置。此 ADT 类似于第 8.4 节讨论的 RandomAccessFile 类的 read 和 write 方法。

## 示例 8.4

假设磁盘文件的每个扇区（以及缓冲池中的每个块）存储 1024 字节。假设缓冲池处于图 8.5 所示的状态。如果下一个请求是从文件的第 6000 字节位置开始复制 40 字节，这些字节应放入扇区 5（其字节范围从位置 5120 到位置 6143）。由于扇区 5 当前在缓冲池中，我们只需将 space 中的 40 字节复制到字节位置 880-919。然后，包含扇区 5 的缓冲区被移到缓冲池中扇区 1 缓冲区之前。

另一种接口是让缓冲池向用户提供指向包含所请求信息的缓冲区的直接指针。此类接口可能如下所示：

// 使用缓冲区传递风格的缓冲池 ADT
class BufferPool {
public:
    // 返回所请求块的指针
    virtual void* getblock(int block) = 0;

    // 为持有“block”的缓冲区设置脏位
    virtual void dirtyblock(int block) = 0;

    // 返回缓冲区的大小
    virtual int blocksize() = 0;
};

在这种方法中，缓冲池用户被告知存储空间被划分为给定大小的块，每个块的大小与一个缓冲区相同。用户向缓冲池请求特定的块，并返回指向持有该请求块的缓冲区的指针。用户随后可以读取或写入此空间。如果用户写入该空间，则必须将这一事实告知缓冲池。原因是，当给定块要从缓冲池中移除时，如果该块已被修改，则必须将其内容写回后备存储。如果该块未被修改，则无需将其写回。
