这种实现最初会带来一个新问题。假设队列的队首元素初始位于位置0，并且元素被依次添加到数组中编号更高的位置。当元素从队列中移除时，队首索引会增加。随着时间推移，整个队列将向数组中编号更高的位置漂移。一旦元素被插入到数组中编号最高的位置，队列就空间耗尽了。尽管数组的低端可能存在空闲位置（之前从队列中移除的元素所在的位置），这种情况仍会发生。

基于数组的队列实现还有一个更严重但更微妙的问题。我们如何识别队列何时为空或已满？假设front存储队列中队首元素的数组索引，rear存储队尾元素的数组索引。如果front和rear位置相同，那么在这种方案下队列中必然有一个元素。因此，空队列可以通过rear比front小1来识别（考虑到队列是环形的，所以位置size−1实际上被认为比位置0小1）。但如果队列完全满了呢？换句话说，当一个有n个数组位置的队列包含n个元素时是什么情况？在这种情况下，如果队首元素在位置0，那么队尾元素在位置size−1。但这意味着，考虑到队列的环形特性，rear的值比front的值小1。换句话说，满队列与空队列无法区分！

你可能会认为问题在于front和rear被定义为分别存储队首和队尾元素的数组索引，并且对这个定义稍作修改就能解决问题。不幸的是，这个问题不能通过简单改变front和rear的定义来补救，因为队列可能处于的条件或状态数量。忽略第一个元素的实际位置，也忽略队列中存储元素的实际值，有多少种不同的状态？队列中可以没有元素、有一个元素、两个元素，等等。如果有n个数组位置，队列中最多可以有n个元素。这意味着队列有n + 1种不同状态（可能有0到n个元素）。

如果front的值固定，那么需要n + 1个不同的rear值来区分这n + 1种状态。然而，除非我们为比如空队列发明一种特殊情况，否则rear只有n个可能值。这是练习2.30中定义的鸽巢原理的一个例子。鸽巢原理指出，给定n个鸽巢和n + 1只鸽子，当所有鸽子都进入鸽巢时，我们可以确定至少有一个鸽巢包含不止一只鸽子。类似地，我们可以确定n + 1种状态中有两种无法通过front和rear的n个相对值来区分。我们必须寻找其他方法来区分满队列和空队列。

一个明显的解决方案是显式记录队列中元素的数量，或者至少使用一个布尔变量来指示队列是否为空。另一种解决方案是使数组大小为n + 1，并且只允许存储n个元素。采用哪种解决方案纯粹是实现者个人偏好的问题。我的选择是使用大小为n + 1的数组。

图4.26展示了一个基于数组的队列实现。listArray保存队列元素，和往常一样，队列构造函数允许一个可选参数来设置队列的最大大小。实际创建的数组足够大，可以容纳比队列允许的多一个元素，以便将空队列与满队列区分开来。成员maxSize用于控制队列的环形运动（它是模运算符的基数）。成员rear被设置为当前队尾元素的位置，而front是当前队首元素的位置。

在这种实现中，队列的队首被定义为朝向数组中编号较低的位置（在图4.25中为逆时针方向），而队尾被定义为朝向编号较高的位置。因此，enqueue递增rear指针（模size），dequeue递增front指针。所有成员函数的实现都很直接。

## 4.3.2 链式队列

链式队列实现是链表的一种直接改编。图4.27展示了链式队列类声明。front和rear分别是指向队首和队尾元素的指针。我们将使用一个头链接节点，通过避免队列为空时的任何特殊情况，使enqueue操作的实现更简单。初始化时，front和rear指针将指向头节点，并且front始终指向头节点，而rear指向队列中真正的最后一个链接节点。方法enqueue将新元素放在链表末尾的链接节点中（即rear指向的节点），然后将rear推进到指向新的链接节点。方法dequeue移除并返回链表的第一个元素。

基于数组和链式队列实现的所有成员函数都需要常数时间。空间比较问题与等效的栈实现相同。与基于数组的栈实现不同，没有方便的方法将两个队列存储在同一数组中，除非元素总是直接从其中一个队列转移到另一个队列。

## 4.4 字典

计算机程序最常见的目的是存储和检索数据。本书大部分内容涉及高效组织数据记录集合的方法，以便能够快速存储和检索它们。在本节中，我们描述这种集合的一个简单接口，称为字典。字典ADT提供了存储记录、查找记录和从集合中移除记录的操作。这个ADT为我们比较各种数据结构提供了标准基础。

在讨论字典接口之前，我们必须首先定义键和可比较对象的概念。如果我们想在数据库中搜索给定记录，应该如何描述我们要找的内容？数据库记录可以只是一个数字，也可能相当复杂，例如具有许多不同类型字段的工资记录。我们不想通过详细描述和匹配记录的整个内容来描述我们要找的东西。如果我们已经知道记录的一切，可能就不需要寻找它了。相反，我们通常根据键值来定义我们想要的记录。例如，如果搜索工资记录，我们可能希望搜索与特定ID号匹配的记录。在这个例子中，ID号就是搜索键。
