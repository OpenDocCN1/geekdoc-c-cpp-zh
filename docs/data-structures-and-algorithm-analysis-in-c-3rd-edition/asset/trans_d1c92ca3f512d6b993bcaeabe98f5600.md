## 5.1.1 满二叉树定理

某些二叉树实现只在叶结点存储数据，而利用内部结点为树提供结构。更一般地，二叉树实现可能需要为内部结点分配一定空间，而为叶结点分配不同的空间。因此，要分析这类实现所需的空间，了解一棵包含 n 个内部结点的树中叶结点所占比例的最小值和最大值是很有用的。

不幸的是，这个比例并不固定。一棵有 n 个内部结点的二叉树可能只有一个叶结点。当内部结点排列成一条链，并以单个叶结点结尾时，就会出现这种情况，如图 5.4 所示。在这种情况下，叶结点数量很少，因为每个内部结点只有一个非空孩子。要找到一棵有 n 个内部结点的树的叶结点数量的上界，首先注意到上界

![](img/7ea3c39173f146f675b63b146d1535f3_172_0.png)

# 图 5.4 一棵包含许多内部结点但只有一个叶结点的树。

会在每个内部结点都有两个非空孩子时出现，即当树为满树时。然而，这一观察并不能说明什么样的树形会产生最高比例的非空叶结点。事实证明这并不重要，因为所有具有 n 个内部结点的满二叉树都有相同数量的叶结点。这一事实使我们能够计算满二叉树实现的空间需求，这种实现的叶结点与内部结点所需的空间量不同。

## 定理 5.1 满二叉树定理：非空满二叉树中的叶结点数比内部结点数多一。

证明：对内部结点数 n 进行数学归纳。这是归纳证明的一个例子：我们从规模为 n 的任意实例化归为规模为 n − 1 且满足归纳假设的实例。

- 基础情形：内部结点数为零的非空树有一个叶结点。一个内部结点的满二叉树有两个叶结点。因此，n = 0 和 n = 1 的基础情形符合定理。
- 归纳假设：假设任何包含 n − 1 个内部结点的满二叉树 T 都有 n 个叶结点。
- 归纳步骤：给定一棵有 n 个内部结点的树 T，选择一个两个孩子均为叶结点的内部结点 I。移除 I 的两个孩子，使 I 成为叶结点。称新树为 T'。T' 有 n − 1 个内部结点。根据归纳假设，T' 有 n 个叶结点。现在恢复 I 的两个孩子，我们再次得到有 n 个内部结点的树 T。T 有多少个叶结点？因为 T' 有 n 个叶结点，加上两个孩子得到 n + 2。然而，结点 I 在 T' 中被计为一个叶结点，而现在已经变成内部结点。因此，树 T 有 n + 1 个叶结点和 n 个内部结点。

由数学归纳法可知，该定理对所有 n ≥ 0 均成立。

在分析二叉树实现的空间需求时，了解一棵树包含多少个空子树是很有用的。满二叉树定理的一个简单推广可以精确告诉我们任何二叉树中有多少个空子树，无论它是否为满二叉树。下面给出证明该定理的两种方法，每种方法都提供了一种思考二叉树的有用方式。

## 定理 5.2 非空二叉树中空子树的数量比树中结点数多一。

证明 1：取任意二叉树 T，将每个空子树替换为一个叶结点，称新树为 T'。原先在 T 中的所有结点在 T' 中都成为内部结点（因为即使 T 的叶结点在 T' 中也有孩子）。T' 是一棵满二叉树，因为 T 中的每个内部结点现在在 T' 中都有两个孩子，而 T 中的每个叶结点在 T' 中也都有两个孩子（即刚刚添加的叶结点）。满二叉树定理告诉我们，满二叉树的叶结点数比内部结点数多一。因此，为构造 T' 而添加的新叶结点数比 T 中的结点数多一。T' 中的每个叶结点对应于 T 中的一个空子树。因此，T 中空子树的数量比 T 中的结点数多一。

证明 2：根据定义，二叉树 T 中的每个结点都有两个孩子，因此一棵有 n 个结点的树共有 2n 个孩子。除根结点外，每个结点都有一个父结点，因此共有 n − 1 个有父结点的结点。换句话说，有 n − 1 个非空孩子。由于孩子总数为 2n，其余 n + 1 个孩子必然为空。

## 5.1.2 二叉树结点 ADT

正如链表由一组链对象组成，树由一组结点对象组成。图 5.5 给出了一个二叉树结点 ADT，称为 BinNode。这个类将被后面介绍的一些二叉树结构使用。BinNode 类是一个以 E 为参数的模板，E 是存储在结点中的数据记录的类型。所提供的成员函数可以设置或返回元素值、设置或返回指向左孩子的指针、设置或返回指向右孩子的指针，或者指示该结点是否为叶结点。

```
// Binary tree node abstract class
template <typename E> class BinNode {
public:
    virtual ~BinNode() {} // Base destructor

    // Return the node’s value
    virtual E& element() = 0;

    // Set the node’s value
    virtual void setElement(const E&) = 0;

    // Return the node’s left child
    virtual BinNode* left() const = 0;

    // Set the node’s left child
    virtual void setLeft(BinNode*) = 0;

    // Return the node’s right child
    virtual BinNode* right() const = 0;

    // Set the node’s right child
    virtual void setRight(BinNode*) = 0;

    // Return true if the node is a leaf, false otherwise
    virtual bool isLeaf() = 0;
};
```

## 5.2 二叉树的遍历

通常我们希望“访问”二叉树的每个结点来处理该树，每次访问时执行特定操作，例如打印结点内容。按某种顺序访问所有结点的过程称为遍历。任何恰好列出树中每个结点一次的遍历称为树的枚举。有些应用不要求结点按任何特定顺序被访问，只要每个结点恰好被访问一次即可。另一些应用则要求结点按保持某种关系的顺序被访问。例如，我们可能希望确保先访问某个给定结点，再访问它的孩子。这称为先序遍历。

## 示例 5.1 图 5.1 中树的先序枚举为

ABDCEGFHI。

首先打印的是根结点。然后，在打印右子树中的任何结点之前，按先序打印左子树的所有结点。

或者，我们可能希望在访问某个结点的孩子（以及它们的子树）之后才访问该结点。例如，如果我们希望将树中的所有结点归还给自由存储区，就必须这样做。我们希望先删除一个结点的孩子，再删除结点本身。但要做到这一点，需要先删除孩子结点的孩子，依此类推。这称为后序遍历。

## 示例 5.2 图 5.1 中树的后序枚举为

DBGEHIFCA。

中序遍历首先访问左孩子（包括其整棵子树），然后访问该结点，最后访问右孩子（包括其整棵子树）。
