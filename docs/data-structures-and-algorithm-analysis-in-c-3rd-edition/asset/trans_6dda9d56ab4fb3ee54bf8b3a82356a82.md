

\[
\begin{aligned}
&= a^m T(1) + a^{m-1} c (n/b^{m-1})^k + \cdots + a c (n/b)^k + c n^k \\
&= a^m c + a^{m-1} c (n/b^{m-1})^k + \cdots + a c (n/b)^k + c n^k \\
&= c \sum_{i=0}^{m} a^{m-i} b^{ik} \\
&= c a^m \sum_{i=0}^{m} (b^k/a)^i.
\end{aligned}
\]

注意

\[
a^m = a^{\log_b n} = n^{\log_b a}. \tag{14.1}
\]

这个求和是一个几何级数，其和取决于比值 \(r = b^k / a\)。存在三种情况。

1. **\(r < 1\).** 由方程 2.4，\(\sum_{i=0}^{m} r^i < 1/(1-r)\)，这是一个常数。因此，
\[
T(n) = \Theta(a^m) = \Theta(n^{\log_b a}).
\]

2. **\(r = 1\).** 因为 \(r = b^k / a\)，我们知道 \(a = b^k\)。由对数的定义可以直接得到 \(k = \log_b a\)。我们还从方程 14.1 中注意到 \(m = \log_b n\)。因此，
\[
\sum_{i=0}^{m} r^i = m + 1 = \log_b n + 1.
\]
又因为 \(a^m = n^{\log_b a} = n^k\)，我们有
\[
T(n) = \Theta(n^{\log_b a} \log n) = \Theta(n^k \log n).
\]

3. **\(r > 1\).** 由方程 2.5，
\[
\sum_{i=0}^{m} r^i = \frac{r^{m+1} - 1}{r - 1} = \Theta(r^m).
\]
因此，
\[
T(n) = \Theta(a^m r^m) = \Theta(a^m (b^k / a)^m) = \Theta(b^{km}) = \Theta(n^k).
\]

我们可以将上述推导总结为以下定理，有时称为主定理。

### 定理 14.1（主定理）

对于形如 \(T(n) = a T(n/b) + c n^k\)、且 \(T(1) = c\) 的任何递推关系，以下关系成立。

\[
T(n) =
\begin{cases}
\Theta(n^{\log_b a}) & \text{if } a > b^k, \\
\Theta(n^k \log n) & \text{if } a = b^k, \\
\Theta(n^k) & \text{if } a < b^k.
\end{cases}
\]

该定理可在适当时直接应用，而无须重新推导递推式的解。

### 示例 14.10

应用主定理求解

\[
T(n) = 3 T(n/5) + 8 n^2.
\]

因为 \(a = 3\)，\(b = 5\)，\(c = 8\)，且 \(k = 2\)，我们得到 \(3 < 5^2\)。应用定理的情形 (3)，可得 \(T(n) = \Theta(n^2)\)。

### 示例 14.11

使用主定理求解归并排序的递推关系：

\[
T(n) = 2 T(n/2) + n; \quad T(1) = 1.
\]

因为 \(a = 2\)，\(b = 2\)，\(c = 1\)，且 \(k = 1\)，我们得到 \(2 = 2^1\)。应用定理的情形 (2)，\(T(n) = \Theta(n \log n)\)。

### 14.2.4 快速排序的平均情况分析

在第 7.5 节中，我们确定了快速排序的平均情况分析具有以下递推关系：

\[
T(n) = c n + \frac{1}{n} \sum_{k=0}^{n-1} [T(k) + T(n-1-k)], \quad T(0) = T(1) = c.
\]

\(c n\) 项是 findpivot 和 partition 步骤的上界。该方程来源于这样的假设：划分元素等可能出现在任意位置 \(k\)。注意到两个递推项 \(T(k)\) 和 \(T(n-1-k)\) 是等价的，因为其中一个只是从 \(T(0)\) 向上计数到 \(T(n-1)\)，而另一个从 \(T(n-1)\) 向下计数到 \(T(0)\)，因此可以简化。由此得到

\[
T(n) = c n + \frac{2}{n} \sum_{k=0}^{n-1} T(k).
\]

这种形式称为具有**完整历史**的递推。求解此类递推的关键是消去求和项。求和的移位方法提供了一种实现方式。将两边乘以 \(n\)，并从 \((n+1)T(n+1)\) 的式子中减去所得结果：

\[
n T(n) = c n^2 + 2 \sum_{k=0}^{n-1} T(k)
\]

\[
(n+1)T(n+1) = c(n+1)^2 + 2 \sum_{k=0}^{n} T(k).
\]

从两边减去 \(n T(n)\) 得到：

\[
(n+1)T(n+1) - n T(n) = c(n+1)^2 - c n^2 + 2 T(n)
\]

\[
(n+1)T(n+1) - n T(n) = c(2n + 1) + 2 T(n)
\]

\[
(n+1)T(n+1) = c(2n + 1) + (n+2)T(n)
\]

\[
T(n+1) = \frac{c(2n+1)}{n+1} + \frac{n+2}{n+1} T(n).
\]

至此，我们已消去求和项，现在可以用通常的方法求解递推，得到闭式解。注意 \(\frac{c(2n+1)}{n+1} < 2c\)，因此可以简化结果。展开递推，得到

\[
T(n+1) \le 2c + \frac{n+2}{n+1} T(n)
\]

\[
= 2c + \frac{n+2}{n+1} \left( 2c + \frac{n+1}{n} T(n-1) \right)
\]

\[
= 2c + \frac{n+2}{n+1} \left( 2c + \frac{n+1}{n} \left( 2c + \frac{n}{n-1} T(n-2) \right) \right)
\]

\[
= 2c + \frac{n+2}{n+1} \left( 2c + \cdots + \frac{4}{3} \left( 2c + \frac{3}{2} T(1) \right) \right)
\]

\[
= 2c \left( 1 + \frac{n+2}{n+1} + \frac{n+2}{n+1} \cdot \frac{n+1}{n} + \cdots + \frac{n+2}{n+1} \cdot \frac{n+1}{n} \cdots \frac{3}{2} \right)
\]

\[
= 2c \left( 1 + (n+2) \left( \frac{1}{n+1} + \frac{1}{n} + \cdots + \frac{1}{2} \right) \right)
\]

\[
= 2c + 2c(n+2)(\mathcal{H}_{n+1} - 1)
\]

其中 \(\mathcal{H}_{n+1}\) 是调和级数。由方程 2.10，\(\mathcal{H}_{n+1} = \Theta(\log n)\)，因此最终解为 \(\Theta(n \log n)\)。

## 14.3 摊还分析

本节介绍摊还分析的概念，它是对一系列操作整体进行的分析。具体来说，摊还分析使我们能够处理 \(n\) 次操作的最坏情况代价小于 \(n\) 乘以任何单次操作最坏情况代价的情形。摊还分析不独立地关注每个操作的单独代价并将它们相加，而是考察整个序列的代价，并为每个操作“分摊”总代价中的一份。

我们可以将摊还分析技术应用于在无序数组中进行一系列顺序查找的情况。对于 \(n\) 次随机查找，每次查找的平均情况代价为 \(n/2\)，因此该序列的期望总代价为 \(n^2/2\)。不幸的是，在最坏情况下，所有查找都会定位到数组中的最后一个元素。此时，每次查找的代价为 \(n\)，最坏情况总代价为 \(n^2\)。将此与一组 \(n\) 次查找（其中数组中的每个元素恰好被查找一次）的代价进行比较。在这种情况下，某些查找必然代价高昂，但某些查找也必然代价低廉。对于该问题，无论最好、平均还是最坏情况，总查找次数都必须是 \(\sum_{i=1}^{n} i \approx n^2/2\)。这比更悲观的分析（按最坏情况代价对序列中的每个操作计费）要便宜一半。

作为摊还分析的另一个例子，考虑递增二进制计数器的过程。算法从低位（最右）位向高位（最左）位移动，将 1 改为 0，直到遇到第一个 0。将该 0 改为 1，递增操作即完成。下面是实现该递增操作的 C++ 代码，假设长度为 \(n\) 的二进制数存储在长度为 \(n\) 的数组 \(A\) 中。

```cpp
for (i=0; ((i<n) && (A[i] == 1)); i++)
    A[i] = 0;
if (i < n)
    A[i] = 1;
```

如果我们从 0 计数到 \(2^n - 1\)（需要至少 \(n\) 位的计数器），以处理的位数来衡量，一次递增操作的平均代价是多少？朴素的坏情况分析认为，如果除高位以外的所有位均为 1，则需要处理 \(n\) 位。因此，若有 \(2^n\) 次递增，则代价为 \(n 2^n\)。然而，这过高了，因为处理如此多位的情况很少发生。事实上，有一半时间低位是 0，因此只需处理该位；四分之一的时间里，低两位是 01，因而只需处理低两位。另一种理解方式是：最低位总是被翻转，其左边一位有一半时间被翻转，再下一位有四分之一时间被翻转，依此类推。我们可以用以下求和来捕捉这一点（按从右到左将代价分摊给各位）

\[
\sum_{i=0}^{n-1} \frac{1}{2^i} < 2.
\]

换言之，每次递增平均翻转的位数为 2，因此 \(2^n\) 次递增序列的总代价仅为 \(2 \cdot 2^n\)。

一个有助于摊还分析的概念可以通过栈数据结构的简单变体来说明，其中 **pop** 函数被稍作修改，接受第二个参数 \(k\)，表示要执行 \(k\) 次弹出操作。这个修改后的 pop 函数称为 **multipop**，可能如下所示：

```cpp
// pop k elements from stack
void multipop(int k);
```

针对 **multipop** 的“局部”最坏情况分析为 \(\Theta(n)\)（栈中有 \(n\) 个元素时）。因此，如果有 \(m_1\) 次 **push** 调用和 \(m_2\) 次 **multipop** 调用，那么该操作序列的朴素最坏情况代价为 \(m_1 + m_2 \cdot n = m_1 + m_2 \cdot m_1\)。这种分析不合理地悲观。显然，每次调用 **multipop** 真的不可能都弹出 \(m_1\) 个元素。只关注单次操作的分析无法处理这种全局限制，因此我们转而使用摊还分析来对整个操作序列建模。

解决此问题摊还分析的关键在于**势能**的概念。在任意给定时刻，栈上可能有若干元素。**multipop** 的代价不可能超过这个元素数目。每次 **push** 调用都会向栈上放入一个元素，该元素只能由一次 **multipop** 操作移除。因此，每次 **push** 调用会使栈的势能增加一个元素。所有 **multipop** 调用的代价之和永远不会超过栈的总势能（除了每次 **multipop** 调用本身的常数时间开销）。

任意 **push** 与 **multipop** 操作序列的摊还代价是三项代价之和。第一，每次 **push** 操作花费常数时间。第二，每次 **multipop** 操作都有一个常数时间开销，与该次调用弹出的元素数目无关。最后，我们计入所有 **multipop** 操作所耗费的势能之和，它至多为 \(m_1\)，即 **push** 操作的次数。因此，总代价可以表示为

\[
m_1 + (m_2 + m_1) = \Theta(m_1 + m_2).
\]

类似的观点也用于我们对快速排序算法中 partition 函数的分析（第 7.5 节）。在 while 循环的任意一次遍历中，左指针或右指针可能会一直移动穿过剩余部分
