
// Insert e into hash table HT
template <typename Key, typename E>
void hashdict<Key, E>::
hashInsert(const Key& k, const E& e) {
    int home;                  // Home position for e
    int pos = home = h(k);     // Init probe sequence
    for (int i=1; EMPTYKEY != (HT[pos]).key(); i++) {
        pos = (home + p(k, i)) % M; // probe
        Assert(k != (HT[pos]).key(), "Duplicates not allowed");
    }
    KVpair<Key,E> temp(k, e);
    HT[pos] = temp;
}

## Figure 9.6 Insertion method for a dictionary implemented by a hash table.

可能容纳该记录的第一个槽位将是该键的家位置。如果家位置被占用，则冲突解决策略会转到序列中的下一个槽位。如果该槽位也被占用，则必须找到另一个槽位，依此类推。这一系列槽位被称为探测序列，它由我们称为 p 的某个探测函数生成。插入函数如 Figure 9.6 所示。

方法 hashInsert 首先检查键的家槽位是否为空。如果家槽位被占用，则我们使用探测函数 p(k, i) 来在表中定位一个空闲槽位。函数 p 有两个参数，键 k 和计数 i，表示我们希望在探测序列中的位置。也就是说，要获取键 K 的家槽位之后探测序列中的第一个位置，我们调用 p(K, 1)。对于探测序列中的下一个槽位，调用 p(K, 2)。请注意，探测函数返回的是相对于原始家位置的偏移量，而不是哈希表中的槽位。因此，hashInsert 中的 for 循环在每次迭代时通过将探测函数返回的值加到家位置上来计算表中的位置。第 i 次调用 p 返回第 i 个要使用的偏移量。

在哈希表中的搜索遵循插入记录时所遵循的相同探测序列。这样，即使记录不在其家位置也能被恢复。Figure 9.7 显示了搜索过程的 C++ 实现。

插入和搜索例程假定每个键的探测序列上至少有一个槽位为空。否则，在搜索不成功的情况下，它们将在无限循环中继续。因此，字典应保持存储的记录数量计数，并在仅剩一个空闲槽位的表上拒绝插入。

桶式哈希的讨论提出了一种简单的冲突解决办法。如果记录的家位置被占用，则沿桶向下移动直到找到空闲槽位。这是冲突解决技术的一种示例，称为线性探测。简单线性探测的探测函数为

p(K, i) = i.

// Search for the record with Key K
template <typename Key, typename E>
E hashdict<Key, E>::
hashSearch(const Key& k) const {
    int home;            // Home position for k
    int pos = home = h(k); // Initial position is home slot
    for (int i = 1; (k != (HT[pos]).key()) &&
        (EMPTYKEY != (HT[pos]).key()); i++)
        pos = (home + p(k, i)) % M; // Next on probe sequence
    if (k == (HT[pos]).key())      // Found it
        return (HT[pos]).value();
    else return NULL;          // k not in hash table
}

## Figure 9.7 Search method for a dictionary implemented by a hash table.

也就是说，探测序列上的第 i 个偏移量就是 i，意味着第 i 步只是简单地在表中向下移动 i 个槽位。

一旦到达表的底部，探测序列就会绕回到表的开头。线性探测的优点是，在探测序列返回到家位置之前，表中的所有槽位都将成为插入新记录的候选。

虽然线性探测可能是考虑冲突解决策略时首先想到的想法，但它并不是唯一可能的方法。探测函数 p 为我们提供了许多冲突解决的方法。事实上，线性探测是最差的冲突解决办法之一。主要问题如图 9.8 所示。这里，我们看到一个包含十个槽位的哈希表，用于存储四位数，哈希函数 h(K) = K mod 10。在图 9.8(a) 中，已有五个数字被放入表中，剩下五个槽位。

冲突解决机制的理想行为是，表中每个空槽位都有相同的概率接收下一个插入的记录（假设表中每个槽位被最初哈希到的概率相等）。在此示例中，假设哈希函数使每个槽位（大致）以相等概率成为下一个键的家位置。然而，考虑下一个记录如果其键的家位置在槽位 0 会发生什么。线性探测会将记录发送到槽位 2。对家位置在槽位 1 的记录也会发生同样的情况。家位置在槽位 2 的记录将保留在槽位 2。因此，下一个插入的记录最终落在槽位 2 的概率为 3/10。以类似的方式，哈希到槽位 7 或 8 的记录会最终落在槽位 9。然而，只有哈希到槽位 3 的记录才会被存储在槽位 3，发生这种情况的概率为十分之一一个。同理，下一个记录被存储在槽位 4 的概率只有十分之一一个，槽位 5 为十分之一一个，槽位 6 为十分之一一个。因此，所得概率并不相等。

更糟糕的是，如果下一个记录最终落在槽位 9（它本身已经有高于正常的发生概率），那么下一个记录将以 6/10 的概率落在槽位 2。这如图 9.8(b) 所示。线性探测将项目聚集成簇的这种倾向被称为初级聚簇。小簇倾向于合并成大簇，使问题更糟。对初级聚簇的反对意见是它会导致探测序列变长。

## Improved Collision Resolution Methods

我们如何避免初级聚簇？一种可能的改进可能是使用线性探测，但以常数 c 跳过槽位，而不是 1。这将使探测函数为

```
p(K, i) = c i
```

因此探测序列中的第 i 个槽位将为 (h(K) + i c) mod M。这样，具有相邻家位置的记录将不会遵循相同的探测序列。例如，如果我们跳过两个，则我们相对于家槽位的偏移量将为 2，然后为 4，然后为 6，依此类推。

一个好的探测序列的特性是，它将在返回到家位置之前遍历哈希表中的所有槽位。显然线性探测（每次“跳过”一个槽位）就是这样做的。不幸的是，并非所有 c 的值都会使这种情况发生。例如，如果 c = 2 且表包含偶数个槽位，则任何家位置在偶数槽位的键都将具有仅遍历偶数槽位的探测序列。同样，家位置在奇数槽位的键的探测序列将遍历奇数槽位。因此，这种表大小和线性探测常数的组合有效地将

记录分为存储在两个不相交的哈希表部分中的两组。只要表的两个部分包含相同数量的记录，这并不是很重要。然而，仅凭偶然，很可能一个部分会变得比另一个更满，导致更多冲突和较差的性能。而另一部分记录较少，性能更好。但整体系统性能会下降，因为更满一侧的额外成本超过了较少一侧的性能提升。

常数 c 必须与 M 互质，才能生成遍历表中所有槽位的线性探测序列（即 c 和 M 必须没有公因子）。对于哈希表大小 M = 10，如果 c 是 1、3、7 或 9 中的任意一个，则探测序列将对任何键访问所有槽位。当 M = 11 时，1 到 10 之间的任何 c 值都会生成对每个键都访问所有槽位的探测序列。

考虑 c = 2 且我们希望插入具有键 k₁ 的记录的情况，使得 h(k₁) = 3。k₁ 的探测序列为 3、5、7、9，等等。如果另一个键 k₂ 的家位置在槽位 5，则其探测序列将为 5、7、9，等等。k₁ 和 k₂ 的探测序列以一种有助于聚簇的方式相互链接。换句话说，c > 1 的线性探测并不能解决初级聚簇问题。我们希望找到一个探测函数，不会以这种方式将键链接在一起。我们更希望 k₁ 在序列第一步之后的探测序列不与 k₂ 的探测序列相同。相反，它们的探测序列应该分开。

理想的探测函数将从未访问过的槽位中随机选择探测序列上的下一个位置；也就是说，探测序列应为哈希表位置的随机排列。不幸的是，我们实际上不能随机选择探测序列上的下一个位置，因为那样我们就无法在搜索键时重复相同的探测序列。然而，我们可以做类似的事情，称为伪随机探测。在伪随机探测中，探测序列中的第 i 个槽位为 (h(K) + rᵢ) mod M，其中 rᵢ 是从 1 到 M − 1 的随机排列中的第 i 个值。所有插入和搜索操作都使用相同的随机排列。探测函数为 p(K, i) = Perm[i − 1]，其中 Perm 是一个长度为 M − 1 的数组，包含 1 到 M − 1 的随机排列。

## Example 9.9

考虑一个大小为 M = 101 的表，其中 Perm[1] = 5，Perm[2] = 2，Perm[3] = 32。假设我们有两个键 k₁ 和 k₂，其中 h(k₁) = 30 且 h(k₂) = 35。k₁ 的探测序列为 30，然后是 35，然后是 32，然后是 62。k₂ 的探测序列为 35，然后是 40，然后是 37，然后是 67。因此，虽然 k₂ 会探测到 k₁ 的家位置作为其第二个选择，但这两个键的探测序列随后立即分开。
