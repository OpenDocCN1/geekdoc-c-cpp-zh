

## 算法：

**算法**是用于解决问题的一种方法或过程。如果把问题看作一个函数，那么算法就是该函数的一种实现，它把输入转换为相应的输出。一个问题可以用许多不同的算法来解决。一个给定的算法只能解决一个问题（即计算一个特定的函数）。本书涵盖了许多问题，对于其中几个问题，我给出了不止一种算法。对于排序这一重要问题，我给出了将近十二种算法！

了解一个问题的多种解决方案的好处在于，对于该问题的特定变体，或针对该问题的特定输入类别，解决方案 A 可能比解决方案 B 更高效；而针对另一种变体或输入类别，解决方案 B 可能比 A 更高效。例如，某种排序算法可能最适合对少量整数进行排序（如果你需要多次执行此操作，这一点很重要）。另一种可能最适合对大量整数排序。第三种可能最适合对一组可变长度字符串进行排序。

根据定义，只有具备以下所有性质的事物才能称为算法。

- 1. 它必须是*正确*的。换句话说，它必须计算所需的函数，将每个输入转换为正确的输出。请注意，每个算法都实现了某个函数，因为每个算法都将每个输入映射到某个输出（即使该输出是程序崩溃）。这里的关键问题在于，给定算法是否实现了*预期*的函数。
- 2. 它由一系列*具体步骤*组成。具体意味着该步骤所描述的动作能被必须执行该算法的人或机器完全理解——并且能够做到。每一步还必须在有限时间内完成。因此，算法通过执行一系列步骤为我们提供了解决问题的“配方”，其中每一个步骤都在我们的执行能力范围内。执行某一步的能力可能取决于谁或什么意图执行该配方。例如，烹饪书中饼干配方的步骤可能被认为足以指导人类厨师，但不足以编程一个自动化的饼干制造工厂。
- 3. 接下来执行哪一步不能有*任何歧义*。通常它就是算法描述中的下一步。选择（例如 **C++** 中的 **if** 语句）通常是任何描述算法的语言的一部分。选择允许决定接下来执行哪一步，但在做出选择时，选择过程是明确的。
- 4. 它必须由*有限*数量的步骤组成。如果算法的描述由无限多的步骤组成，我们就不可能将其写下来，也不可能将其实现为计算机程序。大多数描述算法的语言（包括英语和“伪代码”）都提供了某种执行重复操作的方式，称为迭代。编程语言中迭代的示例包括 C++ 的 while 和 for 循环结构。迭代允许简短描述，实际执行的步骤数由输入控制。
- 5. 它必须终止。换句话说，它不能进入无限循环。

程序：我们通常认为计算机程序是算法在某种编程语言中的实例或具体表示。在本书中，几乎所有算法都以程序或程序的一部分的形式呈现。自然，同一个算法可以有多个程序实例，因为任何现代计算机编程语言都可以用来实现同一个算法集合（尽管有些编程语言可以让程序员的工作更轻松）。为简化表述，我经常互换使用“算法”和“程序”这两个术语，尽管它们实际上是不同的概念。根据定义，算法必须提供足够的细节，以便在需要时转换为程序。

算法必须终止这一要求意味着并非所有计算机程序都符合算法的技术定义。你的操作系统就是这样一个程序。但是，你可以将操作系统的各种任务（每个任务都有相关的输入和输出）视为单独的问题，每个问题都由操作系统程序的某一部分实现的具体算法解决，并且每个算法一旦产生输出就终止。

总结：问题是一个函数或输入到输出的映射。算法是解决问题的配方，其步骤具体且无歧义。算法必须正确、长度有限，并且必须对所有输入都终止。程序是算法在编程语言中的实例化。

## 1.5 进一步阅读

关于数据结构和算法的早期权威著作是 Donald E. Knuth 的系列丛书《计算机程序设计艺术》，其中第 1 卷和第 3 卷与数据结构的研究最相关 [Knu97, Knu98]。Robert Sedgewick 的《算法》[Sed11] 是一本以现代百科全书式方法介绍数据结构和算法的书，掌握本书后应易于理解。关于算法、算法设计和算法分析的优秀且极具可读性（但更高级）的教学入门书，请参阅 Udi Manber 的《算法引论：一种创造性方法》[Man89]。关于高级的、百科全书式的方法，请参阅 Cormen、Leiserson 和 Rivest 的《算法导论》[CLRS09]。Steven S. Skiena 的《算法设计手册》[Ski10] 提供了 Web 上可用的许多数据结构和算法实现的指引。

所有现代编程语言都能实现相同的算法这一论断（更精确地说，任何可由一种编程语言计算的函数，也可由任何具有某些标准能力的编程语言计算）是可计算性理论的一个关键结果。关于该领域的简单入门，请参阅 James L. Hein 的 *《离散结构、逻辑与可计算性》* [Hei09]。

计算机科学的很大一部分致力于解决问题。事实上，这正是吸引许多人进入该领域的原因。George Pólya 的 *《怎样解题》* [Pól57] 被认为是关于如何提高解决问题能力的经典著作。如果你想成为一名更好的学生（同时也是更好的问题解决者），请参阅 Folger 和 LeBlanc 的 *《创造性问题解决策略》* [FL95]、Marvin Levine 的 *《有效解决问题》* [Lev94]、Arthur Whimbey 和 Jack Lochhead 的 *《问题解决与理解》* [WL99]，以及 Zbigniew 和 Matthew Michalewicz 的 *《基于谜题的学习》* [MM08]。

关于人类如何运用隐喻概念来处理复杂性的精彩讨论，请参阅 Julian Jaynes 的 *《两院制心智崩溃中意识的起源》* [Jay90]。与计算机科学教育和编程更直接相关的是，参见 Dan Aharoni 的“我思故我在！学生处理数据结构时的认知过程” [Aha00]，其中讨论了如何从编程语境思维转向更高层次（且更面向设计）的脱离编程的思维。

在更实际的层面上，大多数人学习数据结构是为了编写更好的程序。如果你期望程序正确高效地运行，它首先必须让你自己和你的同事能够理解。Kernighan 和 Pike 的 *《程序设计实践》* [KP99] 讨论了与编程相关的一系列实际问题，包括良好的编码和文档风格。关于编写大型程序所涉及的困难，请阅读 Frederick P. Brooks 的经典著作 *《人月神话：软件工程论文集》* [Bro95]，这是一个出色（且有趣！）的介绍。

如果你想成为一名成功的 C++ 程序员，手头需要好的参考手册。C++ 的标准参考书是 Bjarne Stroustrup 的 *《C++ 程序设计语言》* [Str00]，Ellis 和 Stroustrup 的 *《带注释的 C++ 参考手册》* [ES90] 提供了进一步的信息。C++ 程序员不应缺少 Stroustrup 的书，因为它提供了对该语言的权威描述，还包含大量关于面向对象设计原则的信息。遗憾的是，它不是学习如何用 C++ 编程的好教材。Patrick Henry Winston 的 *《进入 C++》* [Win94] 是对该语言基础知识的温和介绍。Deitel 和 Deitel 的 *《C++ 大学教程》* [DD08] 是一本更广泛的 C++ 入门教学文本。

在熟练掌握了程序编写的技巧之后，下一步是熟练地进行程序设计。良好的设计在任何学科中都难以学习，而面向对象软件的良好设计是最困难的挑战之一。
