

另一种消除初级聚集的探测函数称为**二次探测**。这里探测函数是某个二次函数

\[
p(K, i) = c_1 i^2 + c_2 i + c_3
\]

对于某些常数 \(c_1\)、\(c_2\) 和 \(c_3\) 的选择。最简单的变体是 \(p(K, i) = i^2\)（即 \(c_1 = 1\)、\(c_2 = 0\) 且 \(c_3 = 0\)）。那么探测序列中的第 \(i\) 个值将为 \((h(K) + i^2) \bmod M\)。在二次探测下，具有不同初始位置的两个键将具有发散的探测序列。

### Example 9.10

给定一个大小为 \(M = 101\) 的哈希表，假设对于键 \(k_1\) 和 \(k_2\) 有 \(h(k_1) = 30\) 且 \(h(k_2) = 29\)。\(k_1\) 的探测序列为 30，然后是 31，然后是 34，然后是 39。\(k_2\) 的探测序列为 29，然后是 30，然后是 33，然后是 38。因此，虽然 \(k_2\) 会在其第二个选择时探测到 \(k_1\) 的初始位置，但此后两个键的探测序列立即发散。

不幸的是，二次探测的缺点是通常并非所有哈希表槽都会出现在探测序列中。使用 \(p(K, i) = i^2\) 会产生特别不一致的结果。对于许多哈希表大小，该探测函数会遍历相对较少数量的槽。如果该循环中的所有槽恰好都已满，则记录根本无法插入！例如，如果我们的哈希表有三个槽，则哈希到槽 0 的记录只能探测到槽 0 和 1（即探测序列永远不会访问表中的槽 2）。因此，如果槽 0 和 1 已满，则即使表未满，记录也无法插入。更现实的例子是一个有 105 个槽的表。从任意给定槽开始的探测序列只会在表中访问另外 23 个槽。如果这 24 个槽恰好都已满，即使表中的其他槽为空，记录也无法插入，因为探测序列将不断仅命中相同的 24 个槽。

幸运的是，可以以低成本从二次探测中获得良好的结果。探测函数和表大小的正确组合会在表中访问许多槽。特别是，如果哈希表大小为质数且探测函数为 \(p(K, i) = i^2\)，则至少会访问表中一半的槽。因此，如果表不满一半，我们可以确定会找到一个空槽。或者，如果哈希表大小为 2 的幂且探测函数为 \(p(K, i) = (i^2 + i)/2\)，则探测函数将访问表中的每个槽。

伪随机探测和二次探测都消除了初级聚集，即键共享探测序列的大量段的问题。然而，如果两个键哈希到相同的初始位置，则它们将始终遵循相同的探测序列，对于我们迄今为止看到的每一种冲突解决方法都是如此。伪随机和二次探测生成的探测序列完全是初始位置的函数，而不是原始键值。

这是因为对于这些冲突解决方法，函数 \(p\) 忽略了其输入参数 \(K\)。如果哈希函数在特定初始位置产生一个簇，则该簇在伪随机和二次探测下仍然存在。这个问题称为二级聚集。

为了避免二级聚集，我们需要使探测序列在其决策过程中使用原始键值。实现此目的的一种简单技术是返回线性探测以恒定步长进行探测，但该常数由第二个哈希函数 \(h_2\) 确定。因此，探测序列的形式将为 \(p(K, i) = i \cdot h_2(K)\)。该方法称为双重哈希。

### Example 9.11

假设哈希表大小为 \(M = 101\)，并且有三个键 \(k_1\)、\(k_2\) 和 \(k_3\)，其中 \(h(k_1) = 30\)、\(h(k_2) = 28\)、\(h(k_3) = 30\)、\(h_2(k_1) = 2\)、\(h_2(k_2) = 5\) 且 \(h_2(k_3) = 5\)。那么，\(k_1\) 的探测序列将为 30、32、34、36，等等。\(k_2\) 的探测序列将为 28、33、38、43，等等。\(k_3\) 的探测序列将为 30、35、40、45，等等。因此，没有任何键共享相同探测序列的大量部分。当然，如果第四个键 \(k_4\) 满足 \(h(k_4) = 28\) 且 \(h_2(k_4) = 2\)，则它将遵循与 \(k_1\) 相同的探测序列。伪随机或二次探测可以与双重哈希结合来解决此问题。

双重哈希的一个良好实现应确保探测序列中的所有常数都与表大小 \(M\) 互质。这可以很容易实现。一种方法是选择 \(M\) 为质数，并使 \(h_2\) 返回范围 \(1 \le h_2(K) \le M-1\) 的值。另一种方法是设 \(M = 2^m\) 对于某个值 \(m\)，并使 \(h_2\) 返回 1 和 \(2^m\) 之间的奇数值。

图 9.9 显示了通过哈希表实现的字典 ADT。最简单的哈希函数被使用，冲突解决采用线性探测，作为哈希表实现结构的基础。本章末尾建议的一个项目要求你使用其他哈希函数和冲突解决策略改进实现。

```cpp
// Dictionary implemented with a hash table
template <typename Key, typename E>
class hashdict : public Dictionary<Key,E> {
private:
    KVpair<Key,E>* HT;              // The hash table
    int M;                          // Size of HT
    int current;                    // The current number of elements in HT
    Key EMPTYKEY;                   // User-supplied key value for an empty slot

    int p(Key K, int i) const       // Probe using linear probing
    { return i; }

    int h(int x) const { return x % M; }  // Poor hash function

    int h(char* x) const {          // Hash function for character keys
        int i, sum;
        for (sum=0, i=0; x[i] != '\0'; i++) sum += (int) x[i];
        return sum % M;
    }

    void hashInsert(const Key&, const E&);
    E hashSearch(const Key&) const;

public:
    hashdict(int sz, Key k) {       // "k" defines an empty slot
        M = sz;
        EMPTYKEY = k;
        current = 0;
        HT = new KVpair<Key,E>[sz]; // Make HT of size sz
        for (int i=0; i<M; i++)
            (HT[i]).setKey(EMPTYKEY); // Initialize HT
    }

    ~hashdict() { delete [] HT; }

    // Find some record with key value "K"
    E find(const Key& k) const
    { return hashSearch(k); }

    int size() { return current; }  // Number stored in table

    // Insert element "it" with Key "k" into the dictionary.
    void insert(const Key& k, const E& it) {
        Assert(current < M, "Hash table is full");
        hashInsert(k, it);
        current++;
    }
};
```

### 9.4.4 Analysis of Closed Hashing

哈希的效率如何？我们可以通过执行操作时所需的记录访问次数来衡量哈希性能。需要关注的主要操作是插入、删除和搜索。区分成功和不成功搜索是有用的。在记录被删除之前，必须先找到它。因此，删除记录所需的访问次数等同于成功搜索它所需的访问次数。要插入记录，必须在其探测序列中找到一个空槽。这等同于对该记录的不成功搜索（请记住，在插入期间对该记录的成功搜索应生成错误，因为表中不允许存储具有相同键的两个记录）。

当哈希表为空时，插入的第一条记录将始终找到其初始位置为空。因此，找到一个空槽只需要一次记录访问。如果所有记录都存储在其初始位置，则成功搜索也只需要一次记录访问。随着表的开始填满，记录可以插入到其初始位置的概率会下降。如果记录哈希到一个已占用的槽，则冲突解决策略必须找到另一个槽来存储它。找到未存储在其初始位置的记录也需要随着沿其探测序列搜索记录而增加的记录访问次数。随着表的填满，越来越多的记录很可能位于远离其初始位置的地方。

从这段讨论中，我们看到哈希的预期成本是表填充程度的函数。定义表的负载因子为 \(\alpha = N/M\)，其中 \(N\) 是表中当前记录的数量。

在假设探测序列遵循哈希表中槽的随机排列的情况下，可以从分析上推导出插入（或不成功搜索）的预期成本作为 \(\alpha\) 的函数。假设表中每个槽都有相同的概率成为下一条记录的初始槽，找到初始位置被占用的概率为 \(\alpha\)。找到初始位置被占用且探测序列中的下一个槽被占用的概率为 \((N-1)/(M-1)\)。\(i\) 次冲突的概率为

\[
\frac{N(N-1)\cdots(N-i+1)}{M(M-1)\cdots(M-i+1)}.
\]

如果 \(N\) 和 \(M\) 很大，则这近似为 \((N/M)^i\)。预期的探测次数为一次加上 \(i \geq 1\) 时 \(i\) 次冲突概率的总和，近似为

\[
1 + \sum_{i=1}^{\infty} (N/M)^i = \frac{1}{1-\alpha}.
\]

成功搜索（或删除）的成本与最初插入该记录的成本相同。然而，插入成本的期望值取决于删除时的 \(\alpha\) 值，而不是原始插入时的 \(\alpha\) 值。我们可以通过从 0 积分到当前 \(\alpha\) 值来推导出该成本的估计值（本质上是对所有插入成本的平均），得到结果

\[
\frac{1}{\alpha}\int_0^\alpha \frac{1}{1-x}\,dx
= \frac{1}{\alpha}\log_e\left(\frac{1}{1-\alpha}\right).
\]
