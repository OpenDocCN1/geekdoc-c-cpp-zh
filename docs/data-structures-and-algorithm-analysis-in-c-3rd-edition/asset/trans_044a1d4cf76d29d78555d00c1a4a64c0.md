## 2.4 求和与递推

大多数程序都包含循环结构。在分析带循环程序的运行时间成本时，我们需要把循环每次执行时的成本加起来。这就是求和的一个例子。求和只是对应用于参数值范围的某个函数的成本之和。求和通常用以下“西格玛”记号书写：

∑_{i=1}^{n} f(i).

该记号表示我们要在某个（整数）值范围内对 f(i) 求和。表达式的参数及其初始值标在 ∑ 符号下方。这里，记号 i = 1 表示参数为 i 且从值 1 开始。在 ∑ 符号上方是表达式 n。这表示参数 i 的最大值。因此，该记号意味着对 i 在 1 到 n 的整数范围内对 f(i) 的值求和。这也可以写成 f(1) + f(2) + ⋯ + f(n − 1) + f(n)。在句子中，西格玛记号排版为 ∑_{i=1}^{n} f(i)。

给定一个求和式，你通常希望用一个与求和式值相同的代数方程来代替它。这称为闭式解，而把求和式替换为其闭式解的过程称为求解求和式。例如，求和式 ∑_{i=1}^{n} 1 只是表达式“1”被求和 n 次（记住 i 从 1 到 n）。因为 n 个 1 的和是 n，所以闭式解是 n。以下是一些有用的求和式及其闭式解的列表。

∑_{i=1}^{n} i = n(n + 1)/2. (2.1)

∑_{i=1}^{n} i² = (2n³ + 3n² + n)/6 = n(2n + 1)(n + 1)/6. (2.2)

∑_{i=1}^{n} n = n log n. (2.3)

∑_{i=0}^{∞} a^i = 1/(1 − a) for 0 < a < 1. (2.4)

∑_{i=0}^{n} a^i = (a^{n+1} − 1)/(a − 1) for a ≠ 1. (2.5)

作为方程 2.5 的特例，

∑_{i=1}^{n} 1/2^i = 1 − 1/2^n. (2.6)

以及

∑_{i=0}^{n} 2^i = 2^{n+1} − 1. (2.7)

作为方程 2.7 的推论，

∑_{i=0}^{log n} 2^i = 2^{log n +1} − 1 = 2n − 1. (2.8)

最后，

∑_{i=1}^{n} i/2^i = 2 − (n + 2)/2^n. (2.9)

从 1 到 n 的倒数之和，称为调和级数，写成 ℋ_n，其值介于 log_e n 与 log_e n + 1 之间。更精确地说，随着 n 的增长，求和更接近

H_n ≈ log_e n + γ + 1/(2n), (2.10)

其中 γ 是欧拉常数，其值为 0.5772...

这些等式中的大多数都可以用数学归纳法很容易证明（参见第 2.6.3 节）。不幸的是，归纳法并不能帮助我们推导出闭式解。它只能在提出闭式解是否正确时加以确认。推导闭式解的技术在第 14.1 节中讨论。

递归算法的运行时间最容易用递归表达式来表示，因为递归算法的总时间包括运行递归调用的时间。递推关系通过包含一个或多个自身（更小）的实例的表达式来定义函数。经典的例子是阶乘函数的递归定义：

```
n! = (n-1)! · n for n > 1; 1! = 0! = 1.
```

```
Fib(n) = Fib(n-1) + Fib(n-2) for n > 2; Fib(1) = Fib(2) = 1.
```

从该定义，斐波那契数列的前七个数为

- 1, 1, 2, 3, 5, 8, 和 13。

注意该定义包含两部分：Fib(n) 的一般定义以及 Fib(1) 和 Fib(2) 的基本情况。同样，阶乘的定义也包含递归部分和基本情况。

递推关系通常用于模拟递归函数的成本。例如，第 2.5 节中函数 fact 对于大小为 n 的输入所需的乘法次数在 n = 0 或 n = 1 时为零（基本情况），并且将为调用 fact 于值 n-1 的成本加一。这可以用以下递推式定义：

```
T(n) = T(n-1) + 1 for n > 1; T(0) = T(1) = 0.
```

与求和类似，我们通常希望用闭式解来代替递推关系。一种方法是展开递推式，将右边的 T 的出现替换为其定义。

### 示例 2.8 如果我们展开递推式 T(n) = T(n-1) + 1，我们得到

```
T(n) = T(n-1) + 1
= (T(n-2) + 1) + 1
```

我们可以按任意多步展开递推式，但目标是检测出某种模式，以便我们能够用求和式重写递推式。在此例中，我们可能会注意到

```
(T(n − 2) + 1) + 1 = T(n − 2) + 2
```

如果我们再次展开递推式，我们得到

```
T(n) = T(n − 2) + 2 = T(n − 3) + 1 + 2 = T(n − 3) + 3
```

这推广为模式 T(n) = T(n − i) + i。我们可能会得出结论

```
T(n) = T(n − (n − 1)) + (n − 1)
= T(1) + n − 1
= n − 1.
```

因为我们只是猜测了一个模式，并没有真正证明这是正确的闭式解，所以我们应该用归纳证明来完成该过程（参见示例 2.13）。

### 示例 2.9 一个稍微复杂一点的递推式是

```
T(n) = T(n − 1) + n;   T(1) = 1.
```

展开该递推式几步，我们得到

```
T(n) = T(n − 1) + n
= T(n − 2) + (n − 1) + n
= T(n − 3) + (n − 2) + (n − 1) + n.
```

我们应该注意到该递推式似乎具有导致

```
T(n) = T(n − (n − 1)) + (n − (n − 2)) + ⋯ + (n − 1) + n
= 1 + 2 + ⋯ + (n − 1) + n.
```

这等价于求和式 ∑_{i=1}^{n} i，我们已经知道其闭式解。

寻找递推关系闭式解的技术在第 14.2 节中讨论。在第 14 章之前，本书中很少使用递推关系，并且在使用的同时会提供相应的闭式解以及推导过程的解释。

## 2.5 递归

如果算法调用自身来完成其部分工作，则该算法是递归的。为了使这种方法成功，“调用自身”必须针对比最初尝试的问题更小的问题。一般来说，递归算法必须有两个部分：基本情况，它处理可以用不使用递归调用的方式解决的简单输入，以及递归部分，其中包含一个或多个对算法的递归调用，其中参数在某种意义上“更接近”基本情况而不是原始调用。这里有一个递归的 C++ 函数来计算 n 的阶乘。fact 对于较小 n 值的执行跟踪在第 4.2.4 节中给出。

```
long fact(int n) {          // Compute n! recursively
    // To fit n! into a long variable, we require n <= 12
    Assert((n >= 0) && (n <= 12), "Input out of range");
    if (n <= 1) return 1; // Base case: return base solution
    return n * fact(n-1);   // Recursive call for n > 1
}
```

函数的头两行构成基本情况。如果 n ≤ 1，则其中一个基本情况为问题计算出解。如果 n > 1，则 fact 调用一个知道如何求 n − 1 的阶乘的函数。当然，知道如何计算 n − 1 的阶乘的函数恰好是 fact 本身。但在编写算法时我们不应该对此想太多。递归算法的设计始终可以以这种方式进行。首先编写基本情况。然后思考通过组合一个或多个更小但相似的子问题的结果来解决问题。如果你编写的算法是正确的，那么你当然可以依赖它（递归地）来解决较小的子问题。成功的秘诀是：不要担心递归调用如何解决子问题。只需接受它会正确地解决它，并利用这个结果来正确地解决原始问题。有多简单？

递归在日常的物理世界问题解决中没有对应物。概念可能难以掌握，因为它要求你以新的方式思考问题。为了有效地使用递归，有必要训练自己在递归调用之外停止分析递归过程。子问题会自行解决。你只需担心基本情况以及如何重新组合子问题。

递归版本的阶乘函数可能对你来说似乎不必要地复杂，因为同样的效果可以通过使用 while 循环来实现。这里是另一个递归的例子，基于一个著名的谜题“汉诺塔”。解决这个问题的自然算法有多个递归调用。它不能很容易地用 while 循环重写。
