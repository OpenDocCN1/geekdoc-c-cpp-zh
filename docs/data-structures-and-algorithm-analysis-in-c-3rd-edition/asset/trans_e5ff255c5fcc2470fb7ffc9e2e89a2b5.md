## 预备知识

## 数据结构与算法

德克萨斯州达拉斯市500英里范围内有多少人口超过25万的城市？我的公司里有多少人年收入超过10万美元？我们能否用不到1000英里的电缆连接所有电话客户？要回答这类问题，仅有必要的信息是不够的。我们必须以一种能够在满足需求的时间内找到答案的方式来组织这些信息。

表示信息是计算机科学的基础。大多数计算机程序的主要目的不是执行计算，而是存储和检索信息——通常尽可能快地进行。正因如此，数据结构的研究以及操作它们的算法是计算机科学的核心。而这本书就是关于这个主题的——帮助你理解如何结构化信息以支持高效处理。

本书有三个主要目标。第一个是介绍常用的数据结构。这些构成了程序员的基本数据结构“工具箱”。对于许多问题，工具箱中的某个数据结构就能提供良好的解决方案。

第二个目标是介绍权衡的思想，并强化这样一个概念：每种数据结构都伴随着成本和收益。这是通过描述每种数据结构在典型操作上所需的时间和空间来实现的。

第三个目标是教授如何衡量数据结构或算法的有效性。只有通过这种衡量，你才能确定工具箱中哪种数据结构最适合新问题。所介绍的技术也使你能够评判你或其他人可能发明的新数据结构的优点。

解决一个问题的方法往往有很多。我们如何在它们之间做出选择？计算机程序设计的核心理念有两个有时相互冲突的目标：

- 1. 设计一个易于理解、编码和调试的算法。
- 2. 设计一个能高效利用计算机资源 的算法。

理想情况下， resulting 程序同时忠实于这两个目标。我们可以说这样的程序是“优雅的”。这里呈现的算法和程序代码示例在这种意义上力求优雅，但本书的目的并不是明确处理与目标(1)相关的问题。这些主要是软件工程学科的关注点。相反，本书主要关注与目标(2)相关的问题。

我们如何衡量效率？第3章描述了一种评估算法或计算机程序效率的方法，称为渐近分析。渐近分析还允许你衡量一个问题的固有难度。剩余的章节使用渐近分析技术来估计每个所呈现算法的时间成本。这使你能够从效率角度看到每个算法与其他解决同一问题的算法相比如何。

本章为后续内容奠定了基础，通过介绍与数据结构的选择和使用相关的一些高阶问题。我们首先考察设计者如何为手头的任务选择合适的 数据结构。然后我们考虑抽象在程序设计中的作用。我们简要考虑设计模式的概念并看一些例子。本章以对问题、算法和程序之间关系 的探讨结束。

### 1.1 数据结构的哲学

#### 1.1.1 数据结构的必要性

你可能会认为，随着计算机越来越强大，程序效率变得不那么重要了。毕竟，处理器速度和内存大小仍在不断提升。明天硬件难道不会解决我们今天可能遇到的任何效率问题吗？

随着我们开发出更强大的计算机，迄今为止的历史总是让我们利用额外的计算能力来解决更复杂的问题，无论是更复杂的用户界面、更大的问题规模，还是以前被认为在计算上不可行的新问题。更复杂的问题需要更多的计算，使得对高效程序的需求变得更大。更糟糕的是，随着任务变得更复杂，它们变得不像我们日常经验那样。 当今的计算机科学家必须接受训练，对高效程序设计的原理有透彻的理解，因为他们在设计计算机程序时，日常的生活经验往往不适用。

只要有足够的空间存储一组数据项，就总有可能在集合中搜索指定的项、以任何期望的顺序打印或以其他方式处理数据项，或修改任何特定数据项的值。因此，可以对任何数据结构执行所有必要的操作。然而，使用合适的数据结构可以使程序在几秒内运行，而使用不当则可能需要数天。

如果一个解决方案在所需的**资源约束**内解决了问题，则称其为**高效**的。资源约束的示例包括存储数据的总可用空间——可能分为独立的主内存和磁盘空间约束——以及执行每个子任务允许的时间。有时，如果一个解决方案所需的资源少于已知的替代方案，无论是否满足任何特定要求，也称其为高效。解决方案的成本是解决方案消耗的资源量。最常见的是，成本以一种关键资源如时间来衡量，同时隐含假设解决方案满足其他资源约束。

显而易见的是，人们编写程序来解决问题。然而，在为特定问题选择数据结构时，牢记这一真理至关重要。只有先分析问题以确定必须达到的性能目标，才有可能为工作选择合适的数据结构。糟糕的程序设计者忽略了这一步分析，并应用他们熟悉但不适合该问题的数据结构。结果通常是一个缓慢的程序。相反，如果一个程序使用更简单的设计就能满足其性能目标，就没有必要采用复杂的表示来“改进”它。

在选择数据结构来解决一个问题时，你应该遵循以下步骤。

- 1. 分析你的问题以确定必须支持的基本操作。基本操作的示例包括将数据项插入数据结构、从数据结构中删除数据项以及查找指定的数据项。
- 2. 量化每个操作的资源约束。
- 3. 选择最能满足这些要求的 数据结构。

这种三步选择数据结构的方法使设计过程数据中心化。首要关注的是数据及其上的操作，其次是这些数据的实现，最后是该表示的实现。

对某些关键操作的资源约束，例如搜索、插入数据记录和删除数据记录，通常驱动数据结构选择过程。以下三个问题涉及这些操作的相对重要性，你在必须选择数据结构时应自问：

- 所有数据项是否都在开始时插入到数据结构中，还是插入与其他操作交错进行？静态应用（数据在开始时加载且永不更改）通常只需要比动态应用更简单的数据结构即可获得高效实现。
- 数据项可以被删除吗？如果是，这很可能会使实现更复杂。
- 所有数据项是否按某种明确定义的顺序处理，还是允许搜索特定数据项？“随机访问”搜索通常需要更复杂的数据结构。

#### 1.1.2 成本与收益

每种数据结构都有相关的成本和收益。实际上，几乎从不真实存在一种数据结构在所有情况下都优于另一种。如果一种数据结构或算法在各方面都优于另一种，劣等的那个通常早已被遗忘。对于本书中介绍的几乎每种数据结构和算法，你都会看到它是最优选择 的示例。其中一些示例可能会让你感到惊讶。

数据结构为其存储的每个数据项需要一定量的空间、执行单个基本操作需要一定量的时间，以及一定的编程工作量。每个问题对可用空间和时间都有约束。每个问题的解决方案以某种相对比例使用基本操作，数据结构选择过程必须考虑这一点。只有在仔细分析了你的问题特征后，你才能确定该任务的最佳数据结构。

**示例 1.1** 银行必须支持与客户的许多类型交易，但我们将考察一个简单模型，其中客户希望开设账户、关闭账户，以及向账户存入或取款。我们可以从两个不同层面考虑这个问题：（1）银行与其客户交互时使用的物理基础设施和工作流程过程的要求，以及（2）管理账户的数据库系统的要求。

典型的客户开设和关闭账户的频率远低于访问账户的频率。客户愿意在创建或删除账户时等待许多分钟，但通常不愿意在存款或取款等单个账户交易上等待超过短暂的时间。这些观察可以被视为该问题时间约束的非正式规范。
