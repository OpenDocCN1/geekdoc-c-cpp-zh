## 3.8 多个参数

有时对算法的正确分析需要多个参数来描述成本。为了说明这一概念，考虑一个计算图片中所有像素值计数排名顺序的算法。图片通常由二维数组表示，像素是数组中的一个单元。像素的值要么是颜色的代码值，要么是该像素处图片强度的值。假设每个像素可以取 0 到 C − 1 范围内的任意整数值。问题是找到每种颜色值的像素数量，然后根据每个值在图片中出现的次数对颜色值进行排序。假设图片是一个矩形，共有 P 个像素。解决该问题的伪代码算法如下。

```
for (i=0; i<C; i++)    // Initialize count
    count[i] = 0;
for (i=0; i<P; i++)    // Look at all of the pixels
    count[value(i)]++; // Increment a pixel value count
sort(count, C);        // Sort pixel value counts
```

在此示例中，count 是一个大小为 C 的数组，存储每种颜色值的像素数量。函数 value(i) 返回像素 i 的颜色值。

第一个 for 循环（初始化 count）的时间基于颜色的数量 C。第二个循环（确定每种颜色的像素数量）的时间为 Θ(P)。最后一行，即对 sort 的调用，取决于所使用的排序算法的成本。根据第 3.6 节的讨论，我们可以假设如果对 P 个项目进行排序，排序算法的成本为 Θ(P log P)，从而得到 Θ(P log P) 作为总算法成本。

这是否是该算法成本的良好表示？实际排序的是什么？不是像素，而是颜色。如果 C 远小于 P，那么 Θ(P log P) 的估计就是悲观的，因为排序的项目远少于 P 个。相反，我们应该对查看每个像素的步骤使用 P 作为分析变量，对查看颜色的步骤使用 C 作为分析变量。然后我们得到初始化循环的 Θ(C)，像素计数循环的 Θ(P)，以及排序操作的 Θ(C log C)。这得出总成本为 Θ(P + C log C)。

为什么我们不能简单地使用 C 作为输入大小并说算法的成本是 Θ(C log C)？因为 C 通常远小于 P。例如，一张图片可能有 1000 × 1000 个像素，颜色范围为 256 种可能颜色。因此，P 为一百万，远大于 C log C。但如果 P 更小，或 C 更大（即使它仍然小于 P），那么 C log C 可能会成为更大的量。因此，不应忽略任一变量。

## 3.9 空间界限

除了时间之外，空间是程序员通常关心的另一个计算资源。就像计算机多年来变得更快一样，它们也获得了更大的内存分配。尽管如此，可用的磁盘空间或主内存量对于算法设计者来说可能仍然是重要的限制。

用于衡量空间需求的分析技术与用于衡量时间需求的技术相似。然而，虽然时间需求通常是针对操作特定数据结构的算法来衡量的，但空间需求通常是针对数据结构本身确定的。关于输入大小增长速率的渐近分析概念完全适用于衡量空间需求。

示例 3.16 一个 n 个整数的数组的空间需求是多少？如果每个整数需要 c 字节，则该数组需要 cn 字节，即 Θ(n)。

示例 3.17 想象我们想要跟踪 n 个人之间的友谊。我们可以用一个大小为 n × n 的数组来做到这一点。数组的每一行代表一个个体的朋友，列指示谁拥有该个体作为朋友。例如，如果人 j 是人 i 的朋友，那么我们在数组第 i 行第 j 列放置一个标记。同样，如果我们假设友谊是双向的，我们还应在第 j 行第 i 列放置一个标记。对于 n 个人，数组的总大小为 Θ(n²)。

数据结构的主要目的是以允许高效访问数据的方式存储数据。为了提供高效访问，可能需要在数据结构中存储有关数据所在位置的额外信息。例如，链表的每个节点必须存储指向列表中下一个值的指针。所有存储在实际数据值之外的此类信息被称为开销。理想情况下，在允许最大访问量的同时应将开销保持在最低限度。需要在这两个相互对立的目标之间保持平衡，这使得数据结构的研究如此有趣。

算法设计的一个重要方面被称为空间/时间权衡原则。空间/时间权衡原则指出，人们通常可以通过牺牲空间来减少时间，反之亦然。许多程序可以通过“打包”或编码信息来修改以减少存储需求。“解包”或解码信息需要额外的时间。因此，结果程序使用更少的空间但运行更慢。相反，许多程序可以通过预存储结果或重新组织信息来修改，以允许在更大的存储需求的代价下获得更快的运行时间。通常，这样的时间和空间变化都是常数因子。

空间/时间权衡的经典示例是查找表。查找表预先存储否则每次需要时都会计算的函数值。例如，12! 是可以存储在 32 位 int 变量中的阶乘函数的最大值。如果你编写一个经常计算阶乘的程序，那么简单地预先计算并将 12 个值存储在表中在时间上要高效得多。每当程序需要 n! 的值时，它只需检查查找表即可。（如果 n > 12，值就太大了，无法存储为 int 变量。）与计算阶乘所需的时间相比，存储查找表所需的一点额外空间可能是值得的。

查找表也可以存储诸如正弦或余弦等昂贵函数的近似值。如果你只为精确度计算该函数，或者愿意用最接近度的值来近似答案，那么存储精确度计算的查找表就可以用来代替重复计算正弦函数。请注意，最初构建查找表需要一定的时间。你的应用程序必须足够频繁地使用查找表，使这种初始化物有所值。

空间/时间权衡的另一个例子是程序员在尝试优化空间时可能遇到的典型情况。这里有一个对整数数组进行排序的简单代码片段。我们假设这是一个特殊情况，其中有 n 个整数，其值是 0 到 n − 1 的整数的排列。这是一个 Binsort 的例子，将在第 7.7 节讨论。Binsort 将每个值分配到与其值对应的数组位置。

```
for (i=0; i<n; i++)
    B[A[i]] = A[i];
```
