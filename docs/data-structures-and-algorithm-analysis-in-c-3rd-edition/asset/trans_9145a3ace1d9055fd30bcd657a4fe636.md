## Example 1.2

一家公司正在开发一个包含美国城市和城镇信息的数据库系统。城市和城镇有成千上万个，数据库程序应允许用户通过名称查找特定地点的信息（另一个精确匹配查询的例子）。用户还应能够找到与位置或人口规模等属性的特定值或值范围匹配的所有地点。这被称为范围查询。

合理的数据库系统必须足够快速地回答查询，以满足典型用户的耐心。对于精确匹配查询，几秒钟是令人满意的。如果数据库旨在支持可以返回许多与查询规范匹配的城市的范围查询，整个操作可能被允许花费更长时间，大约一分钟左右。为满足这一要求，有必要支持以批处理方式处理范围内的所有城市，而不是作为对单个城市的一系列操作来处理的操作。

前一示例中建议的哈希表不适合实现我们的城市数据库，因为它无法执行高效的范围查询。第 10.5.1 节的 B⁺-树支持大型数据库、数据记录的插入和删除以及范围查询。然而，如果数据库是一次性创建，然后永不更改，例如分发在 CD 上的地图集或从网站访问，则第 10.1 节中描述的简单线性索引会更合适。

## 1.2 Abstract Data Types and Data Structures

上一节在没有正确定义的情况下使用了“数据项”和“数据结构”这两个术语。本节介绍术语并说明了选择数据结构的三步方法所体现的设计过程的动机。这种动机源于管理计算机程序巨大复杂性的需要。

类型是一组值的集合。例如，布尔类型由值 true 和 false 组成。整数也构成一种类型。整数是简单类型，因为其值不包含子部分。银行账户记录通常包含姓名、地址、账户号码和账户余额等几条信息。这样的记录是聚合类型或复合类型的例子。数据项是一条信息或一条记录，其值取自一种类型。数据项被称为该类型的成员。

数据类型是一种类型加上操作该类型的操作的集合。例如，整数变量是整数数据类型的成员。加法是整数数据类型上的一个操作示例。

应该区分数据类型的逻辑概念及其在计算机程序中的物理实现。例如，列表数据类型的两种传统实现是链表和基于数组的列表。因此，列表数据类型可以用链表或数组实现。即使“数组”一词也是模糊的，因为它可以指数据类型或实现。“数组”在计算机编程中通常用于表示连续的内存位置块，其中每个内存位置存储一个固定长度的数据项。按此含义，数组是一种物理数据结构。然而，数组也可以指由一组（通常是同质的）数据项组成的逻辑数据类型，每个数据项由索引号标识。数组可以用许多不同方式实现。例如，第 12.2 节描述了用于实现稀疏矩阵的数据结构，稀疏矩阵是一个大型二维数组，仅存储相对较少的非零值。这种实现与数组作为连续内存位置的物理表示大不相同。

**抽象数据类型**（ADT）是将数据类型实现为软件组件。ADT 的接口以类型和该类型上的一组操作来定义。每个操作的行為由其输入和输出决定。ADT 不指定*如何*实现数据类型。这些实现细节对 ADT 的使用者隐藏并受保护免受外部访问，这一概念称为**封装**。

**数据结构**是 ADT 的实现。在诸如 **C++** 之类的面向对象语言中，ADT 及其实现共同构成一个**类**。与 ADT 关联的每个操作都由一个**成员函数**或**方法**实现。定义数据项所需空间的变量称为**数据成员**。**对象**是类的一个实例，即在计算机程序执行期间被创建并占用存储的东西。

术语“数据结构”通常指存储在计算机主内存中的数据。相关术语**文件结构**通常指在外围存储（如磁盘驱动器或 CD）上数据的组织。

## Example 1.3

整数的数学概念以及操作整数的操作构成了数据类型。**C++** **int** 变量类型是抽象整数的物理表示。**int** 变量类型以及作用于 **int** 变量的操作构成了 ADT。不幸的是，**int** 实现并不完全忠实于抽象整数，因为 **int** 变量可以存储的值范围存在限制。如果这些限制被证明不可接受，则必须设计出 ADT“整数”的另一种表示，并为相关操作使用新的实现。

## Example 1.4

整数列表的 ADT 可能指定以下操作：

- 在列表的特定位置插入一个新整数。
- 如果列表为空则返回 **true**。
- 重新初始化列表。
- 返回列表中当前整数的数量。
- 删除列表中特定位置的整数。

从此描述中，每个操作的输入和输出应该很清楚，但列表的实现尚未指定。
