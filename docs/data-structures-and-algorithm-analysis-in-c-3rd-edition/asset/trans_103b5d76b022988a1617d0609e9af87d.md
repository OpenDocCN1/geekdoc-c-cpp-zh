在我多年来教授数据结构的过程中，我发现设计问题在我课程中的作用越来越大。这可以通过本书各个版本的演变来追踪，设计模式和通用接口的覆盖范围不断增加。第一版中没有提到设计模式。第二版对少数示例模式的覆盖有限，并引入了字典 ADT 和比较器类。在第三版中，明确涵盖了一些在编程本书中涵盖的基本数据结构和算法时遇到的设计模式。

## 在课堂上使用本书：

数据结构和算法教材往往分为两类：教学用书或百科全书。试图兼顾两者的书籍通常两者都失败。本书旨在作为教学用书。我认为，对于从业者来说，理解选择或设计最能解决某个问题的最佳数据结构所需的原则，比死记硬背大量教科书实现更重要。因此，我将本书设计为一本教学用书，涵盖大多数标准数据结构，但并非全部。一些未被广泛采用的数据结构被包含在内，以说明重要原则。一些相对较新的、未来应被广泛使用的的数据结构也被包含在内。

在本科课程中，本教材可用于高级低年级（大二或大三水平）数据结构课程，或高年级算法课程。第三版中新增了材料，以支持其在算法课程中的使用。通常，本书会在标准大一水平的“CS2”课程之后使用，该课程通常作为数据结构的初步介绍。本书的读者通常应具有相当于两个学期的编程经验，包括至少一些 C++ 方面的接触。熟悉递归的读者将具有优势。数据结构的学生最好先完成一门良好的离散数学课程。尽管如此，第 2 章试图在理解本书中使用的程度水平上，对先修数学主题进行相当完整的概述。读者在遇到不熟悉的数学材料时，可能希望根据需要参考相应的章节。

对于仅具备少量基本数据结构或分析背景的学生（即相当于传统 CS2 课程的背景）的大二课程，可能会详细涵盖第 1-11 章，以及第 13 章的选定主题。这就是我自己大二课程中使用本书的方式。背景更丰富的学生可能会涵盖第 1 章，跳过第 2 章的大部分内容仅作参考，简要涵盖第 3 章和第 4 章，然后详细涵盖第 5-12 章。同样，第 13 章中仅会涵盖某些主题，具体取决于讲师选择的编程作业。高年级算法课程将重点放在第 11 章和第 14-17 章。

第 13 章部分旨在作为大型编程练习的来源。我建议所有学习数据结构课程的学生都应被要求实现某种高级树结构，或第 12 章中难度相当的另一种动态结构，例如跳表或稀疏矩阵表示。这些数据结构在实现上并不比二叉搜索树困难得多，完成第 5 章后，任何一个都应在本学生能力范围内。

虽然我已尝试按合理的顺序安排内容，但讲师应随意根据需要重新排列主题。书中写成一旦读者掌握了第 1-6 章，其余材料相互依赖较少。显然，外部排序依赖于理解内部排序和磁盘文件。第 6.2 节关于 UNION/FIND 算法的介绍用于 Kruskal 的最小成本生成树算法。第 9.2 节关于自组织列表提到了第 8.3 节中介绍的缓冲区替换方案。第 14 章借鉴了全书的示例。第 17.2 节依赖于对图的了解。否则，大多数主题仅依赖于同一章中之前介绍的材料。

大多数章节以“进一步阅读”部分结尾。这些部分并不是所介绍主题的全面参考列表。相反，我列出了在我看来可能对读者特别有启发性或有趣的书籍和文章。在某些情况下，我引用了任何全面计算机科学家都应熟悉的作品。

使用 C++：编程示例是用 C++ 编写的，但我并不想阻止不熟悉 C++ 的人阅读本书。我已尝试在保持 C++ 优势的同时，使示例尽可能清晰。这里使用 C++ 严格作为说明数据结构概念的工具。特别是，我利用 C++ 对隐藏实现细节的支持，包括类、私有类成员、构造函数和析构函数等特性。这些语言特性支持将抽象数据类型所体现的逻辑设计与数据结构所体现的物理实现分离这一关键概念。

为了使内容尽可能清晰，这里避免了一些 C++ 的重要特性。我刻意减少了经验丰富的 C++ 程序员常用的某些特性的使用，例如类层次结构、继承和虚函数。运算符和函数重载的使用非常谨慎。C 风格的初始化语法优先于 C++ 提供的一些替代方案。

虽然上述 C++ 特性在实际程序中具有合理的设计依据，但它们往往会掩盖而不是阐明本书所倡导的原则。例如，继承是帮助程序员避免重复、从而最大限度减少错误的重要工具。从教学角度来看，继承往往使代码示例更难理解，因为它倾向于将一个逻辑单元的描述分散到多个类中。因此，我的类定义仅在继承与所说明的要点明确相关时才使用继承（例如，第 5.3.1 节）。这并不意味着程序员也应如此。避免代码重复和最大限度减少错误是重要目标。将编程示例视为数据结构原则的说明，但不要直接复制到自己的程序中。

我必须做出的一个痛苦决定是代码示例中是否使用模板。在本书第一版中，决定不使用模板，因为其语法会使不熟悉 C++ 的人难以理解代码的含义。在此后的几年里，计算机科学课程中使用 C++ 的情况大大扩展。我现在假设本书的读者熟悉模板语法。因此，模板现在在代码示例中被广泛使用。

我的实现旨在作为数据结构原则的具体说明，以辅助文本阐述。代码示例不应脱离相关文本单独阅读或使用，因为每个示例的大部分文档都包含在文本中，而不是代码中。代码补充文本，而不是相反。它们并非旨在成为一系列商业质量的类实现。如果你正在寻找可在自己的代码中使用的标准数据结构的完整实现，最好在互联网上进行搜索。
