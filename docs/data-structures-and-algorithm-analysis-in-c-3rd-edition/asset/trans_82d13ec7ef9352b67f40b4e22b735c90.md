

本章对昂贵且不可能解决的问题的理论做一个简要介绍。第 17.1 节介绍了规约的概念，规约是用于分析问题难度（而不是分析算法成本）的核心工具。规约使我们能够关联各种问题的难度，这通常比从第一性原理对问题进行分析要容易得多。第 17.2 节讨论了“困难”问题，我们所说的困难问题是指需要、或至少看起来需要、随输入规模呈指数增长的时间的问题。最后，第 17.3 节考虑了各种问题，这些问题虽然通常定义和理解起来很简单，但实际上却无法用计算机程序解决。这样的经典例子是判断任意计算机程序在处理指定输入时会不会进入无限循环。这就是所谓的停机问题。

## 17.1 规约

我们从理解问题之间关系的一个重要概念开始，称为规约。规约允许我们用另一个问题来解决一个问题。同样重要的是，当我们希望理解一个问题的难度时，规约允许我们对问题的成本的上界和下界做出相对性陈述（而不是算法或程序的成本）。

由于本章对问题的概念进行了广泛讨论，我们希望有一种记号来简化问题的描述。在本章中，问题将以输入和输出之间的映射来定义，并且问题的名称将全部用大写字母表示。因此，对排序问题的完整定义可以如下所示：

```
SORTING:
  Input: A sequence of integers x0, x1, x2, ..., xn−1.
  Output: A permutation y0, y1, y2, ..., yn−1 of the sequence such that yi ≤ yj whenever i < j.
```

当你购买或编写一个程序来解决一个问题，例如排序时，你可能能够利用它来帮助解决另一个不同的问题。这在软件工程中被称为软件重用。为了说明这一点，让我们考虑另一个问题。

```
PAIRING:
  Input: Two sequences of integers X = (x0, x1, ..., xn−1) and Y = (y0, y1, ..., yn−1).
  Output: A pairing of the elements in the two sequences such that the least value in X is paired with the least value in Y, the next least value in X is paired with the next least value in Y, and so on.
```

除了将旧算法应用于解决新问题（从而为新问题建立上界）之外，规约还有另一种用途。那就是通过证明它可以用作具有已知下界的旧问题的解，从而证明新问题的成本下界。

假设我们可以反过来将 SORTING 转换为 PAIRING，并且转换“足够快”。这对 PAIRING 的最小成本说明了什么？我们从第 7.9 节知道，SORTING 在最坏情况和平均情况下的成本为 Ω(n log n)。换句话说，最好的排序算法至少需要 n log n 时间。

假设 PAIRING 可以在 O(n) 时间内完成。那么，构造一个排序算法的一种方法是，将 SORTING 转换为 PAIRING，运行 PAIRING 的算法，最后将答案转换回 SORTING 的答案。只要我们能“足够快”地在 SORTING 和 PAIRING 之间转换，这个过程就会产生一个 O(n) 的排序算法！由于这与我们对 SORTING 的下界的认知相矛盾，而推理中唯一的缺陷是最初假设 PAIRING 可以在 O(n) 时间内完成，我们可以得出结论：PAIRING 不存在 O(n) 时间算法。这种规约过程告诉我们，PAIRING 必须至少与 SORTING 一样昂贵，因此本身也必须具有 Ω(n log n) 的下界。

为了完成关于 PAIRING 下界的这个证明，我们现在需要找到一种将 SORTING 规约到 PAIRING 的方法。这很容易做到。取一个 SORTING 的实例（即包含 n 个元素的数组 A）。第二个数组 B 生成，其中在位置 i 简单地存储 i，满足 0 ≤ i < n。将这两个数组传递给 PAIRING。取得到的一组配对，并使用配对中 B 部分的值来指示 A 部分应在排序数组中的哪个位置；也就是说，我们现在可以使用 B 数组中对应的值作为排序键，并运行一个简单的 Θ(n) 桶排序来重新排序 A 数组中的记录。将 SORTING 转换为 PAIRING 可以在 O(n) 时间内完成，同样地，将 PAIRING 的输出转换为 SORTING 的正确输出也可以在 O(n) 时间内完成。因此，这个“排序算法”的成本主要由 PAIRING 的成本决定。

考虑任意两个问题，如果能找到从一个到另一个的合适规约。第一个问题取其输入的任意实例，我们称之为 I，并将其转换为解，我们称之为 SLN。第二个问题取其输入的任意实例，我们称之为 I′，并将其转换为解，我们称之为 SLN′。我们可以将规约更正式地定义为一个三步过程：

- 1. 将第一个问题的任意实例转换为第二个问题的实例。换句话说，必须存在一个从第一个问题的任意实例 I 到第二个问题的实例 I′ 的转换。
- 2. 将第二个问题的算法应用于实例 I′，得到解 SLN′。

需要注意的是，规约过程本身并没有为我们提供单独解决任一问题的算法。它只是给出了在我们已经有第二个问题的解的情况下解决第一个问题的方法。更重要的是，对于本章剩余部分要讨论的主题，规约为我们提供了一种以另一个问题的术语来理解一个问题的界限的方法。具体来说，在转换高效的情况下，第一个问题的上界最多为第二个问题的上界。相反，第二个问题的下界至少为第一个问题的下界。

作为规约的第二个例子，考虑将两个 n 位数字相乘的简单问题。标准的手算乘法方法是，将第一个数的最后一位数字乘以第二个数字（耗时 Θ(n)），将第一个数的第二位数字乘以第二个数字（再次耗时 Θ(n)），依此类推，对第一个数的每一位数字进行操作。最后，将中间结果相加。请注意，将长度为 M 和 N 的两个数字相加可以很容易地在 Θ(M+N) 时间内完成。因为第一个数的每一位数字都乘以第二个数的每一位数字，所以该算法需要 Θ(n²) 时间。已知存在渐近更快（但更复杂）的算法，但没有一种算法快到 O(n) 级别。

接下来我们问一个问题：对一个 n 位数字进行平方运算是否与将两个 n 位数字相乘一样困难？我们可能会希望这种特殊情况的某些特性能够允许比更一般的乘法问题所需的更快的算法。然而，一个简单的规约证明表明，平方运算“与”乘法一样困难。

规约的关键在于以下公式：

X × Y = (X + Y)² − (X − Y)² / 4

该公式的意义在于，它允许我们将乘法的任意实例转换为涉及三次加法/减法（每一步都可以在线性时间内完成）、两次平方运算以及除以 4 的一系列运算。请注意，除以 4 可以在线性时间内完成（只需转换为二进制，向右移动两位，然后转换回来）。

这个规约表明，如果能找到一个线性时间的平方算法，就可以用它构造一个线性时间的乘法算法。
