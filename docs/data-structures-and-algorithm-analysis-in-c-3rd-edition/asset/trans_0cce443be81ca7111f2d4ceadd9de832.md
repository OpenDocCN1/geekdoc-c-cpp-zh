## 图 7.8 归并排序的示意图。

归并排序的示意图。第一行显示了要排序的八个数。归并排序会递归地将列表细分为每个元素一个的子列表，然后重新合并子列表。第二行显示了第一次合并后创建的四个大小为 2 的子列表。第三行显示了对第 2 行子列表进行下一次合并后创建的两个大小为 4 的子列表。最后一行显示了通过合并第 3 行的两个子列表创建的最终已排序列表。

归并排序在概念上是最简单的排序算法之一，并且在渐近意义和实际运行时间方面都有良好的性能。令人惊讶的是，尽管它基于一个简单的概念，但在实践中实现起来相对困难。图 7.8 说明了归并排序。归并排序的伪代码草图如下：

```
List mergesort(List inlist) {
    if (inlist.length() <= 1) return inlist;;
    List L1 = half of the items from inlist;
    List L2 = other half of the items from inlist;
    return merge(mergesort(L1), mergesort(L2));
}
```

在讨论如何实现归并排序之前，我们将首先检查合并函数。合并两个已排序的子列表非常简单。函数 merge 检查每个子列表的第一个元素并选择较小的值作为整体上的最小元素。此较小值从其子列表中移除并放入输出列表中。合并以这种方式继续，比较子列表的前端元素并不断将较小者附加到输出列表，直到没有更多输入元素为止。

实现归并排序存在许多技术上的困难。第一个决定是如何表示列表。归并排序非常适合对单链表进行排序，因为合并不需要随机访问列表元素。因此，当输入以链表形式存在时，归并排序是首选方法。对链表实现 merge 很简单，因为我们只需要从输入列表的前端移除项目并将项目附加到输出列表。 将输入列表分成两个相等的两半会带来一些困难。理想情况下，我们只需将列表分成前后两半。但是，即使我们事先知道列表的长度，仍然需要遍历到链表的中间才能到达第二半的开头。一种更简单的方法，不依赖于事先知道列表的长度，将输入列表的元素交替分配给两个子列表。第一个元素分配给第一个子列表，第二个元素分配给第二个子列表，第三个元素分配给第一个子列表，第四个元素分配给第二个子列表，以此类推。这需要一次完整地遍历输入列表来构建子列表。

当归并排序的输入是一个数组时，如果我们知道数组边界，将输入拆分为两个子数组就很容易。如果我们将子数组合并到第二个数组中，合并也很容易。请注意，这种方法需要的空间是迄今为止介绍的任何排序方法的两倍，这对归并排序来说是一个严重的缺点。可以在不使用第二个数组的情况下合并子数组，但这样做效率极低且不实用。将两个子数组合并到第二个数组中，虽然实现简单，但会带来另一个困难。合并过程以已排序的列表结束于辅助数组。考虑归并排序的递归性质如何将原始数组分解为子数组，如图 7.8 所示。归并排序会递归调用，直到创建大小为 1 的子数组，需要 log n 层的递归。这些子数组被合并成大小为 2 的子数组，然后再合并成大小为 4 的子数组，依此类推。我们需要避免每次合并操作都需要一个新的数组。通过一定的难度，可以设计出一种在两个数组之间交替的算法。一种更简单的方法是先将已排序的子列表复制到辅助数组中，然后再将其合并回原始数组。图 7.9 显示了遵循此方法的归并排序的完整实现。

归并排序的优化实现如图 7.10 所示。它在初始复制期间反转第二个子数组的顺序。现在两个子数组的当前位置从末端向内工作，使得每个子数组的末端可以一步合并。

```
template <typename E, typename Comp>
void mergesort(E A[], E temp[], int left, int right) {
    if ((right-left) <= THRESHOLD) { // Small list
        inssort<E,Comp>(&A[left], right-left+1);
        return;
    }
    int i, j, k, mid = (left+right)/2;
    mergesort<E,Comp>(A, temp, left, mid);
    mergesort<E,Comp>(A, temp, mid+1, right);
    // Do the merge operation. First, copy 2 halves to temp.
    for (i=mid; i>=left; i--) temp[i] = A[i];
    for (j=1; j<=right-mid; j++) temp[right-j+1] = A[j+mid];
    // Merge sublists back to A
    for (i=left,j=right,k=left; k<=right; k++)
        if (Comp::prior(temp[i], temp[j])) A[k] = temp[i++];
        else A[k] = temp[j--];
}
```

归并排序的分析很直接，尽管它是一个递归算法。合并部分需要 Θ(i) 时间，其中 i 是正在合并的两个子数组的总长度。要排序的数组会反复分成两半，直到达到大小为 1 的子数组，然后它们被合并为大小为 2，再合并为大小为 4，依此类推，如图 7.8 所示。因此，递归的深度为 n 个元素的 log n（为简单起见，假设 n 是 2 的幂）。递归的第一层可以被认为是在大小为 n 的一个数组上工作，第二层在两个大小为 n/2 的数组上工作，下一层在四个大小为 n/4 的数组上工作，依此类推。递归的底部有 n 个大小为 1 的数组。因此，n 个大小为 1 的数组被合并（需要 Θ(n) 总步数），n/2 个大小为 2 的数组（同样需要 Θ(n) 总步数），n/4 个大小为 4 的数组，依此类推。在 log n 层的递归中，每层完成 Θ(n) 的工作，总成本为 Θ(n log n)。此成本不受排序值相对顺序的影响，因此此分析适用于最佳、平均和最坏情况。

## 7.5 快速排序

虽然归并排序使用最明显的分而治之形式（将列表分成两半然后对两半进行排序），但它并不是我们分解排序问题唯一的方式。而且我们看到，当使用数组实现时，对归并排序执行合并步骤并不容易。所以也许另一种分而治之的策略会更有效？

**快速排序** 名称恰当，因为在正确实现时，它是平均情况下最快的通用内存排序算法。它不需要归并排序所需的额外数组，因此在空间上也很高效。快速排序被广泛使用，并且通常是库排序例程中实现的算法，例如 UNIX `qsort` 函数。有趣的是，快速排序受制于极差的最坏情况性能，因此使其不适用于某些应用。

在进入快速排序之前，先考虑一下使用二叉搜索树进行排序的实用性。你可以将所有要排序的值一个一个插入到 BST 中，然后使用中序遍历遍历完成的树。输出将形成一个已排序的列表。这种方法有许多缺点，包括 BST 指针所需的额外空间以及将节点插入树所需的时间。然而，这种方法引入了一些有趣的想法。首先，BST 的根（即第一个插入的节点）将列表分成两个子列表：左子树包含小于根值的列表中的值，而右子树包含大于或等于根值的列表中的值。因此，BST 隐式地实现了对左右子树排序的“分而治之”方法。快速排序以更有效的方式实现了这一概念。

快速排序首先选择一个称为 **枢轴** 的值。 （这在概念上类似于 BST 中根节点的值。）假设输入数组包含 *k* 个小于枢轴的值。然后以这样的方式重新排列记录，使得 *k* 个小于枢轴的值被放置在数组中前 *k* 个位置，即最左边的 *k* 个位置，而大于或等于枢轴的值被放置在最后 *n − k* 个位置，即最右边的 *n − k* 个位置。这称为数组的 **分区**。放置在给定分区中的值不必（并且通常不会）相对于彼此排序。唯一的要求是所有值最终都位于正确的分区中。枢轴值本身被放置在位置 *k*。快速排序然后继续对枢轴两侧的 resulting 子数组进行排序，一个大小为 *k*，另一个大小为 *n − k − 1*。这些值是如何排序的？因为快速排序是一个很好的算法，所以在子数组上使用快速排序是合适的。

与本章前面看到的一些排序不同，快速排序可能看起来不太“自然”，因为它不是一个人用来对真实对象进行排序的方法。但对于计算机上大量抽象对象的真正高效排序与我们对相对较少物理对象进行排序的经验大不相同，这一点并不令人惊讶。
