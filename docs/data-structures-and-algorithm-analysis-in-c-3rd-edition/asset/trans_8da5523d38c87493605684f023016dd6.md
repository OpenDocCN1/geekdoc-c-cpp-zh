

## 6.5 顺序树实现

为了说明使用顺序树表示进行处理时所涉及的困难，考虑查找根节点的右子节点。我们必须首先顺序遍历左子树的节点列表。只有到这时，我们才到达根节点右子节点的值。显然，顺序表示在空间上是高效的，但在沿任意路径向下遍历树时，在时间上并不高效。

假设每个节点值占用固定大小的空间。例如，节点值为正整数，并且 NULL 用零表示。根据第 5.1.1 节的满二叉树定理，我们知道节点列表的大小约为节点数的两倍（即开销比例为 1/2）。额外空间是 NULL 指针所必需的。我们应该能够更紧凑地存储节点列表。然而，任何顺序实现都必须识别何时到达叶节点，也就是说，叶节点表示一个子树的结束。一种方法是在节点列表中显式标明每个节点是内部节点还是叶节点。如果节点 X 是内部节点，那么我们知道它的两个子节点（可能是子树）在节点列表中紧跟在 X 之后。如果 X 是叶节点，则列表中的下一个节点是 X 的某个祖先的右子节点，而不是 X 的右子节点。具体来说，下一个节点将是 X 的最近的、其右子节点尚未被访问过的那个祖先的子节点。然而，这假设每个内部节点实际上都有两个子节点，也就是说，这棵树是满的。空子节点必须在节点列表中显式标明。假设内部节点用撇号（′）标记，叶节点不加标记。内部节点的空子节点用‘/’表示，而叶节点的（空）子节点则完全不表示。注意，在这种实现下，满二叉树不会存储 NULL 值，因此开销更少。

**示例 6.6** 我们可以将图 6.17 中的树表示如下：

`A′B′/DC′E′G/F′HI` (6.2)

注意，由于这不是满二叉树，所以空子节点需要用斜杠表示。

存储 n 个额外比特位与存储 n 个 NULL 值相比，可以节省相当多的空间。在示例 6.6 中，每个内部节点都会带有一个标记，叶节点则不带标记。这要求每个节点值都有空间存储这个标记位。例如，如果节点值存储为 4 字节整数，而所存储值的范围足够小，以至于并非所有位都被使用，那么这一点可以满足。例如，如果所有节点值都必须是正数，那么整数值的高位（符号）位就可以用作标记位。

另一种方法是存储一个单独的位向量来表示每个节点的状态。在这种情况下，树中的每个节点对应位向量中的一位。值为‘1’表示内部节点，为‘0’表示叶节点。

**示例 6.7** 图 6.17 中树的位向量（包括节点 B 和 E 的空子节点的位置）为

```
11001100100
```

(6.3)

通过顺序实现存储一般树，需要在节点列表中包含更明确的结构信息。一般树实现不仅必须指明节点是叶节点还是内部节点，还必须指明该节点有多少个子节点。或者，实现可以指明节点的子节点列表何时结束。下一个示例不再使用内部节点或叶节点的标记，而是使用一个特殊标记（我们将使用“)”符号）来表示子节点列表的结束。所有叶节点后都跟一个“)”符号，因为它们没有子节点。如果叶节点同时也是其父节点的最后一个子节点，则通过两个或更多连续的“)”符号来表示。

**示例 6.8** 对于图 6.3 中的一般树，我们得到如下顺序表示：

```
RAC)D)E))BF)))
```

(6.4)

注意，F 后面跟了三个“)”标记，因为它是一个叶节点，是 B 的最右子树的最后一个节点，同时也是 R 的最右子树的最后一个节点。

注意，这种用于序列化一般树的表示不能用于二叉树。这是因为二叉树不仅仅是最多只有两个子节点的一般树的受限形式。每个二叉树节点都有一个左子节点和一个右子节点，尽管其中一个或两个都可能为空。例如，示例 6.8 的表示无法让我们区分图 6.17 中的节点 D 是节点 B 的左子节点还是右子节点。

## 6.6 延伸阅读

第 6.2 节中引用的表达式 log\* n 与阿克曼函数的反函数密切相关。关于阿克曼函数以及 UNION/FIND 路径压缩代价的更多信息，请参阅 Robert E. Tarjan 的论文《关于一种良好但非线性的集合合并算法的效率》[Tar75]。Galil 和 Italiano 的文章《不相交集合合并问题的数据结构与算法》[GI91] 涵盖了等价类问题的许多方面。

Hanan Samet 的《多维与度量数据结构基础》[Sam06] 在 K 叉树的背景下详细讨论了树结构的各种实现。Samet 既介绍了顺序实现，也介绍了链表和数组实现，例如本章和第 5 章中描述的那些实现。虽然这些书表面上关注空间数据结构，但其中讨论的许多概念对任何需要实现树结构的人都很有借鉴意义。
