## 第二部分

## 基本数据结构

## 列表、栈和队列

如果你的程序需要存储一些东西——例如数字、工资记录或工作描述——最简单且最有效的方法可能是将它们放在一个列表中。只有当你必须组织和搜索大量事物时，更复杂的数据结构通常才变得必要。（我们将在第 5 章、第 7 章和第 9 章研究如何组织和搜索中等数量的数据，并在第 8–10 章讨论如何处理大量数据。）许多应用程序不需要任何形式的搜索，并且不需要对存储的对象进行任何排序。对于所有这些情况，简单的列表结构都是合适的。

本章描述了列表的表示形式，以及称为栈和队列的两种重要的类列表结构。除了介绍这些基本数据结构外，本章的另一个目标是：

- (1) 给出将逻辑表示形式以 ADT 形式与数据结构的物理实现分离的示例。
- (2) 在你可能已经熟悉的一些简单操作的背景下说明渐近分析的使用。通过这种方式，你可以开始了解渐近分析的工作原理，而不会出现分析更复杂算法和数据结构时出现的复杂性。
- (3) 介绍字典的概念和使用。

我们首先在第 4.1 节中定义列表的 ADT。用于列表 ADT 的两种实现——基于数组的列表和链表——将得到详细讨论，并讨论它们的相对优点。第 4.2 节和第 4.3 节分别介绍栈和队列。每个数据结构都提供了示例实现。第 4.4 节介绍了用于存储和检索数据的字典 ADT，这为实现第 5.4 节的二叉搜索树等搜索结构提供了背景。

### 4.1 列表

我们对“列表”意味着什么有一个直观的理解。我们第一步是精确地定义其含义，以便这种直观理解最终可以转化为具体的结构及其操作。与列表相关的最重要的概念是位置。换句话说，我们认为列表中有一个第一个元素、第二个元素，等等。我们应该将列表视为体现第 2.1 节中定义的数学概念序列。

我们将列表定义为一组称为元素的数据项的有限、有序序列。定义中的“有序”意味着每个元素在列表中都有一个位置。（我们不会在此上下文中使用“有序”来表示列表元素按值排序。）每个列表元素都有一个数据类型。在本章讨论的简单列表实现中，列表的所有元素具有相同的数据类型，尽管在概念上如果应用程序需要，元素具有不同数据类型的列表也没有反对意见（参见第 12.1 节）。作为列表 ADT 的一部分定义的操作不依赖于元素数据类型。例如，列表 ADT 可用于整数列表、字符列表、工资记录列表，甚至列表的列表。

当列表不包含任何元素时，称其为空。当前存储的元素数量称为列表的长度。列表的开头称为头部，列表的末尾称为尾部。元素的值与其在列表中的位置之间可能存在也可能不存在某种关系。例如，排序列表中的元素按值升序排列，而未排序列表中元素值与其位置之间没有特定关系。本节仅考虑未排序列表。第 7 章和第 9 章处理如何高效地创建和搜索排序列表的问题。

在呈现列表的内容时，我们使用第 2.1 节中为序列引入的相同记号。为了与 C++ 数组索引保持一致，列表上的第一个位置表示为 0。因此，如果列表中有 n 个元素，它们的位置为 0 到 n − 1（a0, a1, ..., an−1）。下标表示元素在列表中的位置。使用此记号，空列表将显示为 ()。

在选择列表实现之前，程序设计者应首先考虑实现必须支持哪些基本操作。我们对列表的共同直觉告诉我们，列表应该能够随着插入和删除元素而在大小上增长和缩小。我们应该能够从列表的任何位置插入和删除元素。我们应该能够访问任何元素的值，以便读取或更改它。我们必须能够创建和清除（或重新初始化）列表。方便地从“当前”元素访问下一个或上一个元素也很方便。
