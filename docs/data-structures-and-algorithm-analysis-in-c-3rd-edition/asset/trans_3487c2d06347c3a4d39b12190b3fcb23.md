我们的最后一个例子使用摊还分析来证明第 9.2 节中 move-to-front 自组织列表启发式的成本与列表最优静态排序的成本之间的关系。

回想一下，对于一系列搜索操作，静态列表的最小成本是在列表按其记录访问频率排序时得到的。这是记录的最优排序，如果我们从不允许记录的位置发生变化，因为访问频率最高的记录排在最前面（因此成本最低），其次是访问频率次高的记录，依此类推。

### Theorem 14.2
使用 move-to-front 启发式在长度为 \(n\) 的自组织列表上对任意包含 \(n\) 次或更多搜索的序列 \(S\) 所需的比较次数总和，永远不会超过将序列 \(S\) 应用于存储在其最优静态顺序的列表时所需的比较次数总和的两倍。

**Proof:** 列表中搜索键与记录的每次比较都是成功的或不成功的。对于 \(m\) 次搜索，自组织列表和静态列表都必须恰好有 \(m\) 次成功比较。自组织列表中不成功比较的总数是所有不同键对的和，即该对之间所做的每次不成功比较的次数。

考虑一对特定的键 \(A\) 和 \(B\)。对于任意搜索序列 \(S\)，\(A\) 和 \(B\) 之间（不成功）比较的总数与仅由对 \(A\) 或 \(B\) 的搜索组成的 \(S\) 的子序列之间的比较次数相同。称此子序列为 \(S_{AB}\)。换句话说，包含其他键的搜索不会影响 \(A\) 和 \(B\) 的相对位置，因此也不会影响 \(A\) 和 \(B\) 之间不成功比较对总成本的相对贡献。

move-to-front 启发式在子序列 \(S_{AB}\) 上对 \(A\) 和 \(B\) 之间所做的不成功比较次数，至多是当 \(S_{AB}\) 应用于列表的最优静态排序时 \(A\) 和 \(B\) 之间所需的不成功比较次数的两倍。为此，假设 \(S_{AB}\) 包含 \(i\) 个 \(A\) 和 \(j\) 个 \(B\)，其中 \(i \le j\)。在最优静态排序下，需要 \(i\) 次不成功比较，因为 \(B\) 必须出现在列表中 \(A\) 之前（因为其访问频率更高）。move-to-front 会在请求序列从 \(A\) 变为 \(B\) 或从 \(B\) 变为 \(A\) 时产生不成功比较。可能发生的此类变化总数最多为 \(2i\)，因为每次变化都涉及一个 \(A\)，而每个 \(A\) 最多可以参与两次变化。由于两种方法所需的成功比较次数相同，因此 move-to-front 所需的比较次数总和至多是最佳静态排序所需比较次数的两倍。

## 14.4 Further Reading

关于求解递推关系的一个良好介绍见 Fred S. Roberts 所著的 *Applied Combinatorics* [Rob84]。更高级的论述见 Graham、Knuth 和 Patashnik 所著的 *Concrete Mathematics* [GKP94]。

Cormen、Leiserson 和 Rivest 在 *Introduction to Algorithms* [CLRS09] 中提供了关于执行摊还分析的各种方法的良好讨论。关于 splay tree 在对 \(n\) 个节点执行 \(m\) 次操作时需要 \(m \log n\) 时间的摊还分析，其中 \(m > n\)，见 Sleator 和 Tarjan 的 “Self-Adjusting Binary Search Trees” [ST85]。定理 14.2 的证明来自 Bentley 和 McGeoch 的 “Amortized Analysis of Self-Organizing Sequential Search Heuristics” [BM85]。

  ```
  void DFS_component(Graph* G, int v, int component) {
      G->setMark(v, component);
      for (int w=G->first(v); w<G->n(); w = G->next(v,w))
          if (G->getMark(w) == 0)
              DFS_component(G, w, component);
  }

  void concom(Graph* G) {
      int i;
      int component = 1;    // Counter for current component
      for (i=0; i<G->n(); i++) // For n vertices in graph
          G->setMark(i, 0); // Vertices start in no component
      for (i=0; i<G->n(); i++)
          if (G->getMark(i) == 0) // Start a new component
              DFS_component(G, i, component++);
  }
  ```

  使用摊还分析中的势的概念来解释为什么该算法的总成本为 \(\Theta(|V| + |E|)\)。 （注意，这将不是真正的摊还分析，因为该算法不允许任意的 DFS 操作序列，而是固定为从每个顶点进行一次 DFS 调用。）
