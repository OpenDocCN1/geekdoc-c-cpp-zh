稀疏矩阵所需的空间。稀疏矩阵的大小取决于非零元素的数量（我们称这个值为 NNZ），而标准矩阵表示的大小则不变。我们需要知道指针和数据值的（相对）大小。为简单起见，我们的计算将忽略行和列表头所占用的空间（该空间几乎不受稀疏数组中元素数量的影响）。

例如，假设数据值、行或列索引和指针各需要四个字节。n × m 矩阵需要 4nm 字节。稀疏矩阵每个非零元素需要 28 字节（四个指针、两个数组索引和一个数据值）。如果我们设 X 为非零元素的百分比，我们可以求解出 X 的值，使稀疏矩阵表示在此值以下更节省空间。使用方程

28X = 4mn

解得 X，我们发现使用这种实现的稀疏矩阵在 X < 1/7 时更节省空间，也就是说，当非零元素少于约 14% 时。数据值、指针或矩阵索引的相对大小取值不同，会导致这两种实现的盈亏平衡点不同。

理想情况下，处理稀疏矩阵所需的时间应取决于 NNZ。当搜索一个元素时，代价是该元素在其行或列列表中前面的元素个数。对于像两个矩阵相加这样的操作，最坏情况下的代价应为 Θ(n + m)，其中一个矩阵存储 n 个非零元素，另一个存储 m 个非零元素。

另一种稀疏矩阵表示有时称为耶鲁表示法。Matlab 使用一种类似的表示法，其主要区别在于 Matlab 表示法采用列主序。¹ Matlab 表示法使用三个列表存储稀疏矩阵。第一个列表只是按列主序排列的所有非零元素值。第二个列表存储每一列在第一个列表中的起始位置。第三个列表存储每个对应非零值的行位置。在耶鲁表示法中，图 12.7 的矩阵将显示为：

值：10 45 40 23 5 32 93 12 19 7
列起始位置：0 3 5 5 7 7 7 7
行位置：0 1 4 0 1 7 1 7 0 7

如果矩阵有 c 列，那么所需的总空间将与 c + 2NNZ 成正比。这在空间方面是好的。它允许相当快速地访问任何一列，并且便于沿列处理非零值。然而，它在访问一行的值方面效果不佳，并且在需要向表示中添加或移除值时表现糟糕。幸运的是，当进行两个稀疏矩阵相加或相乘等计算时，输入矩阵的处理和输出矩阵的构造可以相当高效地完成。

## 12.3 内存管理

大多数数据结构设计用于存储和访问统一大小的对象。一个典型的例子是存储在列表或队列中的整数。某些应用需要存储可变长度记录的能力，例如任意长度的字符串。一种解决方案是在列表或队列中存储指向这些可变长度字符串的定长指针。这对于存储在主内存中的数据结构来说是可以的。但如果字符串集合是打算存储在磁盘上，那么我们可能需要担心这些字符串究竟存储在哪里。即使存储在主内存中，也需要某种机制来确定哪里有空闲字节来容纳该字符串。我们可以很容易地在队列或堆栈中存储可变大小的记录，其中

```
// Memory Manager abstract class
class MemManager {
public:
    virtual ~MemManager() {} // Base destructor

    // Store a record and return a handle to it
    virtual MemHandle insert(void* info, int length) =0;

    // Get back a copy of a stored record
    virtual int get(void* info, MemHandle h) =0;

    // Release the space associated with a record
    virtual void release(MemHandle h) =0;
};
```

## 图 12.8 一个简单的内存管理器 ADT。

插入和删除的限制性顺序使这一点容易处理。但在像 C++ 或 Java 这样的语言中，程序员可以通过 new 以复杂的方式分配和释放空间。这些空间从哪里来？本节讨论处理可变大小空间请求这一普遍问题的内存管理技术。

内存管理的基本模型是，我们有一个（大）块连续的内存位置，我们称之为内存池。内存请求会周期性地针对池中的一定空间发出。内存管理器的工作是在内存池中找到至少满足请求大小的连续位置块。满足这样的请求称为内存分配。内存管理器通常会返回一些请求者可以保留的信息，以便之后它能够取回刚才由内存管理器存储的记录。这些信息称为句柄。在某个时刻，已请求的空间可能不再需要，这块空间可以归还给内存管理器以便复用。这称为内存释放。然后内存管理器应能够复用这块空间来满足后续的内存请求。我们可以如图 12.8 所示定义一个内存管理器的 ADT。

MemManager ADT 的用户提供一个指针（在参数 info 中），指向存储待保存或取回的记录或消息的空间。这类似于第 8.4 节介绍的 C++ 基本文件读写方法。基本思想是客户端将消息交给内存管理器保管。内存管理器以 MemHandle 对象的形式返回该消息的“收据”。当然，为了实用，MemHandle 必须比要存储的典型消息小得多。客户端持有 MemHandle 对象，直到它希望取回消息为止。

方法 insert 让客户端告诉内存管理器要存储消息的长度和内容。该 ADT 假定内存管理器会记住与给定句柄相关联的消息长度（也许就在句柄本身中），因此方法 get 不包含长度参数，而是返回实际存储的消息长度。方法 release 允许客户端告诉内存管理器释放存储给定消息的空间。

当所有插入和释放都遵循简单的模式时，例如后请求先释放（栈顺序），或先请求先释放（队列顺序），内存管理相当容易。我们这里关注的是更一般的情况，即任意大小的块可能以任意顺序被请求和释放。这称为动态存储分配。动态存储分配的一个示例是为编译器的运行时环境管理自由存储区，例如 C++ 中的系统级 new 和 delete 操作。另一个示例是在多任务操作系统中管理主内存。在这里，程序可能需要一定量的空间，内存管理器必须跟踪哪些程序正在使用主内存的哪些部分。再一个示例是磁盘驱动器的文件管理器。当磁盘文件被创建、扩展或删除时，文件管理器必须分配或释放磁盘空间。

以这种方式管理的一块内存或磁盘空间有时被称为堆（heap）。这里的术语“堆”与第 5.5 节讨论的堆数据结构的使用方式不同。这里的“堆”指的是由动态内存管理方案控制的内存。

在本节的其余部分，我们首先研究动态内存管理的技术。然后，我们处理当内存池中没有单个内存块足够大以满足给定请求时该怎么办的问题。

### 12.3.1 动态存储分配
