
列表ADT。抽象类是这样一种类：其成员函数都被声明为“纯虚函数”，如成员函数声明末尾的“=0”符号所示。类 `List` 定义了任何继承自它的列表实现都必须支持的成员函数，以及它们的参数和返回类型。我们通过将列表ADT写成C++模板来增加其灵活性。

与ADT的概念一致，抽象类并不指定操作如何实现。本节稍后将给出两个完整的实现，它们都使用相同的列表ADT来定义其操作，但在方法和空间/时间权衡上存在很大差异。

图4.1展示了我们的列表ADT。类 `List` 是一个单参数模板，参数名为 `E`，代表“元素”。`E` 充当用户希望存储在列表中的任何元素类型的占位符。图4.1中的注释精确描述了每个成员函数的功能。然而，对基本设计进行一些解释是必要的。鉴于我们希望支持序列的概念，并且能够访问列表中的任意位置，许多成员函数（如 `insert` 和 `moveToPos`）的必要性是显而易见的。该ADT体现的关键设计决策是对当前位置概念的支持。例如，成员 `moveToStart` 将当前位置设置为列表的第一个元素，而方法 `next` 和 `prev` 分别将当前位置移动到下一个和前一个元素。这个ADT的任何实现的意图都是支持当前位置的概念。当前位置是插入或删除等任何操作发生的位置。

由于插入操作发生在当前位置，并且我们希望能够在列表的前部、后部以及之间的任何位置插入，因此当列表中有 n 个元素时，实际上有 n + 1 个可能的“当前位置”。

为了显示当前位置，修改列表表示法将很有帮助。我将使用竖线，例如 ⟨20, 23 | 12, 15⟩ 来表示四个元素的列表，当前位置在竖线右侧的元素 12 处。在这种配置下，调用 `insert` 并传入值 10 会将列表更改为 ⟨20, 23 | 10, 12, 15⟩。

如果仔细检查图4.1，你会发现所提供的列表成员函数允许你以任意期望的顺序构建列表，并访问列表中的任意期望位置。你可能注意到 `clear` 方法并非必需，因为它可以通过其他成员函数在相同的渐近时间内实现。引入它只是为了方便。

方法 `getValue` 返回指向当前元素的指针。请求获取不存在元素的值（即竖线右侧必须有元素）被视为违反 `getValue` 的前置条件。在我们的具体列表实现中，使用断言来强制这些前置条件。在商业实现中，这种违反最好通过C++异常机制来处理。

```
template <typename E> class List { // List ADT
private:
    void operator =(const List&) {}        // Protect assignment
    List(const List&) {}                  // Protect copy constructor
public:
    List() {}                // Default constructor
    virtual ~List() {} // Base destructor

    // Clear contents from the list, to make it empty.
    virtual void clear() = 0;

    // Insert an element at the current location.
    // item: The element to be inserted
    virtual void insert(const E& item) = 0;

    // Append an element at the end of the list.
    // item: The element to be appended.
    virtual void append(const E& item) = 0;

    // Remove and return the current element.
    // Return: the element that was removed.
    virtual E remove() = 0;

    // Set the current position to the start of the list
    virtual void moveToStart() = 0;

    // Set the current position to the end of the list
    virtual void moveToEnd() = 0;

    // Move the current position one step left. No change
    // if already at beginning.
    virtual void prev() = 0;

    // Move the current position one step right. No change
    // if already at end.
    virtual void next() = 0;

    // Return: The number of elements in the list.
    virtual int length() const = 0;

    // Return: The position of the current element.
    virtual int currPos() const = 0;

    // Set current position.
    // pos: The position to make current.
    virtual void moveToPos(int pos) = 0;

    // Return: The current element.
    virtual const E& getValue() const = 0;
};
```

图4.1 列表的ADT。

列表可以通过以下代码片段进行迭代。

```
for (L.moveToStart(); L.currPos() < L.length(); L.next()) {
    it = L.getValue();
    doSomething(it);
}
```

在此示例中，列表的每个元素依次存储在 **it** 中，并传递给 **doSomething** 函数。当当前位置到达列表末尾时，循环终止。

抽象类 **List** 的声明还将类的复制构造函数和赋值运算符的重载设为私有。这保护该类免受意外复制。这样做部分是为了简化本书中使用的示例代码。一个完整功能的列表实现可能会支持复制和赋值列表对象。

这里展示的列表类声明只是列表众多可能解释之一。图4.1提供了人们自然期望在列表上执行的大部分操作，并有助于说明实现列表数据结构的相关问题。作为使用列表ADT的一个示例，我们可以创建一个函数，如果列表中出现给定的整数则返回 **true**，否则返回 **false**。**find** 方法不需要了解具体的列表实现，只需要了解列表ADT即可。

```
// Return true if "K" is in list "L", false otherwise
bool find(List<int>& L, int K) {
    int it;
    for (L.moveToStart(); L.currPos() < L.length(); L.next()) {
        it = L.getValue();
        if (K == it) return true;  // Found K
    }
    return false;                  // K not found
}
```

虽然这个 **find** 实现可以针对元素类型编写为模板，但它在处理列表中存储的不同数据类型的能力上仍然受限。特别是，它只适用于被搜索对象的描述（函数中的 **k**）与对象本身类型相同，并且在使用 == 比较运算符时可以有意义地进行比较的情况。更典型的情况是我们正在搜索一条记录，该记录包含一个键字段，其值与 **k** 匹配。可以使用列表实现来创建基于键值查找并返回复合元素的类似函数，但这需要列表ADT和 **find** 函数在键的概念以及键的比较方式上达成某种一致。这个话题将在第4.4节讨论。

## 4.1.1 基于数组的列表实现

实现列表有两种标准方法：基于数组的列表和链表。本节讨论基于数组的方法。链表将在第4.1.2节中介绍。两者的时间和空间效率比较将在第4.1.3节中讨论。

图4.2展示了基于数组的列表实现，名为 `AList`。`AList` 继承自抽象类 `List`，因此必须实现 `List` 的所有成员函数。

类 `AList` 的私有部分包含基于数组的列表的数据成员。其中包括 `listArray`，即保存列表元素的数组。由于 `listArray` 必须以某种固定大小分配，因此在创建列表对象时必须知道数组的大小。注意，`AList` 构造函数声明了一个可选参数。通过这个参数，用户可以指示列表允许的最大元素数量。短语“=defaultSize”表示该参数是可选的。如果没有给出参数，则采用 `defaultSize` 的值，该值被假定为适当定义的常量值。

由于每个列表可以有不同大小的数组，每个列表必须记住其允许的最大大小。数据成员 `maxSize` 用于此目的。在任何给定时间，列表实际保存的元素数量可以小于数组允许的最大值。该值存储在 `listSize` 中。数据成员 `curr` 存储当前位置。由于 `listArray`、`maxSize`、`listSize` 和 `curr` 都被声明为私有，它们只能由 `AList` 类的方法访问。

类 `AList` 将列表元素存储在前 `listSize` 个连续的数组位置中。数组位置对应于列表位置。换句话说，列表中位置 i 的元素存储在数组单元 i 中。列表的头部始终在位置 0。这使得对列表中任意元素的随机访问变得非常容易。给定列表中的某个位置，可以直接访问该位置的元素值。因此，使用 `moveToPos` 方法后跟 `getValue` 方法访问任意元素需要 Θ(1) 时间。

因为基于数组的列表实现被定义为将列表元素存储在数组的连续单元格中，所以 `insert`、`append` 和 `remove` 方法必须维护这一属性。在列表尾部插入或删除元素很容易，因此 `append` 操作需要 Θ(1) 时间。但如果我们希望在列表头部插入一个元素，当前列表中的所有元素都必须向尾部移动一个位置以腾出空间，如图4.3所示。如果列表中已有 n 个元素，此过程需要 Θ(n) 时间。如果我们希望在包含 n 个元素的列表中的位置 i 处插入，那么 n − i 个元素必须向尾部移动。从列表头部移除元素的情况类似，所有剩余元素必须向头部移动一个位置以填补空缺。要移除位于位置
