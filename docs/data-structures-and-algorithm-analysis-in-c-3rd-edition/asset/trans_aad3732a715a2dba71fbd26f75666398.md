

如果我们将存储在这两种结构中的全部记录看作是出现在表示键空间的一条数轴上的某个点，就能发现这两种结构的划分行为截然不同。BST 会根据沿树下行时遇到的键值来划分空间；而 trie 在键空间中的划分是预先确定的。键空间中划分点预先确定的搜索树结构被赋予一个专门的名称 trie，以区别于像 BST 这样划分点由数据决定的搜索树类型。第 13 章将更详细地讨论 trie。

## 5.7 延伸阅读

关于这样一种树实现示例——当子节点是叶节点时，内部节点的指针字段存储的是其子节点的值，而不是指向其子节点的指针——参见 Shaffer 和 Brown [SB93]。

面对不友好的插入和删除操作序列时，有许多技术可以维持合理平衡的 BST。一个例子是 Adelson-Velskii 和 Landis 提出的 AVL 树，Knuth [Knu98] 对此有讨论。AVL 树（见 13.2 节）实际上是一种 BST，其插入和删除例程会重组树结构，以保证以任一节点的孩子节点为根的两棵子树的高度最多相差 1。另一个例子是伸展树 [ST85]，也将在 13.2 节讨论。

关于堆数据结构及其用途的详细讨论，参见本特利《编程珠玑》中的专栏“Thanks, Heaps” [Ben85, Ben88]。

5.6.1 节关于哈夫曼编码树具有最小外部路径权重的证明来自 Knuth [Knu97]。更多关于数据压缩技术的信息，参见 Witten、Moffat 和 Bell 所著的《Managing Gigabytes》[WMB99]，以及 Dominic Welsh 的《Codes and Cryptography》[Wel88]。表 5.23 和表 5.24 源自 Welsh [Wel88]。
