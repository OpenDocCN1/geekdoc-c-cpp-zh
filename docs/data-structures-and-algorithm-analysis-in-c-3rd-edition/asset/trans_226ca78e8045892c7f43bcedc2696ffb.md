

这里是我们证明该定理的第一次尝试。

**证明 1：** 我们将尝试反证法。假设存在一个算法 A，它只需要 n − 1 次（或更少）将 K 与 L 的元素进行比较。因为 L 有 n 个元素，A 必须避免将 K 与某个值 i 的 L[i] 进行比较。我们可以向算法提供一个 K 位于位置 i 的输入。这种输入在我们的模型中是合法的，因此算法是错误的。

这个证明正确吗？很遗憾不是。首先，任何给定的算法不一定在它的 n − 1 次搜索中始终跳过任何给定的位置 i。例如，并非所有算法都必须从左到右搜索列表。甚至并非所有算法每次遍历列表时都必须先搜索相同的 n − 1 个位置。

**证明 2：** 在算法的任何一次运行中，如果将 n − 1 个元素与 K 进行比较，则某个元素位置（称为位置 i）会被跳过。K 此时可能在位置 i，并且找不到。因此，需要 n 次比较。

很遗憾，还有另一个需要修正的错误。并非解决该问题的所有算法都必须通过将 L 的元素与 K 进行比较来工作。算法可以通过比较 L 的元素彼此来取得有用的进展。例如，如果我们比较 L 的两个元素，然后将较大的一个与 K 进行比较并发现该元素小于 K，我们就知道另一个元素也小于 K。直观上似乎很明显，这样的比较不会真正导致更快的算法，但我们怎么能确定呢？我们 somehow 需要将证明推广以考虑这种方法。

我们现在将介绍一个有用的抽象来表达一组对象的值关系的状态。总序定义了集合中对象之间的关系，使得对于每对对象，其中一个大于另一个。偏序集或 poset 是一个仅定义了部分序的集合。也就是说，可能存在我们无法判断哪个“更大”的元素对。对于我们这里的目的，部分序是我们当前对对象之间关系的了解状态，使得零个或多个元素对之间的序关系是已知的。我们可以通过绘制有向无环图（DAGs）来表示这种知识，显示已知的关系，如图 15.1 所示。

**证明 3：** 最初，我们对 L 中元素的相对顺序或它们与 K 的关系一无所知。因此，最初，我们可以将 L 中的 n 个元素视为处于 n 个独立的偏序中。L 中两个元素之间的任何比较都可能影响偏序的结构。这有点类似于第 6.2 节中描述的、使用父指针树实现的 UNION/FIND 算法。

现在，L 中元素之间的每次比较最多只能将两个偏序合并在一起。K 与 L 中的某个元素，例如 A 之间的任何比较，最多只能消除包含 A 的偏序。因此，如果我们花费 m 次比较

## 15.2.2 在已排序列表中搜索

我们现在假设列表 L 已排序。在这种情况下，线性搜索是否仍然最优？显然不是，但为什么呢？因为我们有在列表未排序时所没有的额外信息。我们知道标准二分搜索算法的最坏情况成本为 O(log n)。我们能做得更好吗？我们可以用与证明排序下界时类似的证明证明这是最坏情况下的最佳可能。

我们再次使用决策树来模拟我们的算法。与在未排序列表中搜索不同，L 元素之间的比较不会告诉我们关于它们相对顺序的任何新信息，因此我们只考虑 K 与 L 中元素的比较。在决策树的根部，我们的知识排除了 L 中的任何位置，因此所有位置都是潜在候选。随着我们根据将 K 与 L 中元素比较的结果在决策树中分支，我们逐渐排除潜在候选。最终我们到达树中的一个叶节点，表示 L 中可能包含 K 的唯一位置。树中必须至少有 n + 1 个节点，因为 K 可以处于 n + 1 个不同的位置（L 中的任何位置，加上不在 L 中）。树中某条路径必须至少有 log n 层深，而树中最深的节点代表该算法的最坏情况。因此，任何在已排序数组上的算法在最坏情况下至少需要 Ω(log n) 次比较。

我们可以修改这个证明来找到平均成本下界。再次，我们使用决策树来模拟算法。不同的是，我们现在感兴趣的不是最深节点的深度（最坏情况）以及因此具有最浅最深节点的树。相反，我们感兴趣的是树中可能的最小值

**证明 1：** 获胜者必须与所有其他元素进行比较，因此必须有 n − 1 次比较。

这个证明显然是错误的，因为获胜者不需要显式地与所有其他元素进行比较才能被识别。例如，标准的单淘汰制体育锦标赛只需要 n − 1 次比较，而获胜者并不与每个对手比赛。所以让我们再试一次。

**证明 2：** 只有获胜者不会输。有 n − 1 个失败者。一次比较最多产生一个（新的）失败者。因此，必须有 n − 1 次比较。

这个证明是合理的。然而，为了以后使用，将其抽象化并引入我们在第 15.2.1 节中做过的 poset 概念是有用的。我们可以将求最大值问题视为从一个没有任何已知关系的 poset 开始，因此集合中的每个成员都在其自己的单元素 DAG 中。

**证明 2a：** 为了找到最大值，我们从包含 n 个 DAG 的 poset 开始，每个 DAG 有一个单元素，并且我们必须构建一个 poset，使所有元素都在一个 DAG 中，并且有一个最大值（并且由此推断出 n − 1 个失败者）。我们希望以最少的链接数将 poset 的元素连接到一个单一的 DAG。这至少需要 n − 1 个链接。一次比较最多提供一个新链接。因此，必须进行至少 n − 1 次比较。

最大值的平均成本是多少？因为它总是进行相同数量的比较，显然它必须花费 n − 1 次比较。我们也可以考虑 largest 必须执行的赋值次数。函数 largest 可能在 for 循环的任何一次迭代中执行赋值。

因为这个事件确实会发生，或不会发生，如果我们对分布没有任何信息，我们可能会猜测每次比较后都会进行赋值，概率为二分之一。但这显然是错误的。事实上，largest 在第 i 次迭代中进行赋值当且仅当 A[i] 是前 i 个元素中最大的。假设所有排列都等可能，这个为真的概率是 1/i。因此，执行的平均赋值次数为 1 + ∑_{i=2}^n 1/i = ∑_{i=1}^n 1/i ，即调和级数 H_n。H_n = Θ(log n)。更精确地说，H_n 接近 log_e n。

这个平均值有多“可靠”？也就是说，程序的一次运行与平均成本的偏差会有多大？根据切比雪夫不等式，一个观测值至少有 75% 的概率落在均值的两个标准差之内。

对于 Largest，方差为 H_n − π²/6 ≈ log_e n − π²/6。

因此标准差约为 √(log_e n)。因此，75% 的观测值介于 log_e n − 2√(log_e n) 和 log_e n + 2√(log_e n) 之间。这是一个狭窄的范围还是宽的范围？与均值相比，这个范围相当宽，意味着赋值次数在程序的每次运行中变化很大。

## 15.4 对抗性下界证明

我们下一个问题是在一组对象中寻找第二大值。考虑标准单淘汰锦标赛中发生的情况。即使我们假设每场比赛中“最好”的队伍获胜，第二最好的是在决赛中输掉的队伍吗？不一定。我们可能会期望第二最好必须输给最好，但他们可能在任何时候相遇。

让我们按照标准的“寻找算法的算法”流程，先提出一个算法，然后提出一个下界，看看它们是否匹配。与我们对大多数问题的分析不同，这次我们将计算涉及的确切比较次数并尝试最小化该计数。寻找第二大的一个简单算法是先找到最大值（进行 n − 1 次比较），丢弃它，然后找到剩余元素的最大值（进行 n − 2 次比较），总成本为 2n − 3 次比较。这是最优的吗？这似乎值得怀疑，但让我们现在继续进行证明下界的步骤。

**定理 15.2。** 寻找第二大值的下界为 2n − 3。

**证明：** 任何输给除最大值之外的任何东西的元素都不能是第二名。因此，第二名的候选者只有那些输给最大值的元素。函数 largest 可能将最大元素与 n − 1 个其他元素进行比较。因此，我们可能需要另外 n − 2 次比较来找到第二大值。

这个证明是错误的。它表现出必要性谬误：“我们的算法做了某事，因此所有解决该问题的算法都必须做同样的事。”

这让我们目前最好的下界论证是寻找第二大值至少要花费寻找最大值一样多，即 n − 1。让我们再尝试一次寻找更好的算法，采用分治策略。如果我们将列表分成两半，并在每一半上运行 largest？我们可以然后比较两个获胜者（我们现在总共使用了 n − 1 次比较），并从其半部分中移除获胜者。对获胜者半部分的另一次 largest 调用会产生其第二好者。最后一次与另一半获胜者的比较给我们真正的第二名。总成本为 ⌈3n/2⌉ − 2。这是最优的吗？如果我们将列表分成四块呢？最好的是 ⌈5n/4⌉。如果我们将列表分成八块呢？那么成本将约为 ⌈9n/8⌉。注意，随着我们将列表分成更多部分，部分获胜者之间的比较变得越来越重要。
