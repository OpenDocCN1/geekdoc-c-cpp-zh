不出所料，外部排序算法的主要目标是最大限度地减少信息必须从磁盘读取或写入磁盘的次数。可以在一定程度上用额外的 CPU 处理来换取减少磁盘访问。

在讨论外部排序技术之前，再次考虑从磁盘访问信息的基本模型。文件被程序员视为固定大小块的顺序序列。假设【为简化】每个块包含相同数量的固定大小数据记录。根据应用的不同，记录可能只有几个字节——仅由键组成或几乎仅由键组成——也可能有数百字节，而键字段相对较小。假设记录不会跨越块边界。这些假设可以为特殊用途的排序应用而放宽，但忽略此类复杂性可以使原理更清晰。

如第 8.2 节所述，扇区是 I/O 的基本单位。换句话说，所有磁盘读写都是针对一个或多个完整的扇区。扇区大小通常是 2 的幂，范围在 512 到 16K 字节之间，具体取决于操作系统和磁盘驱动器的大小和速度。外部排序算法使用的块大小应等于或为扇区大小的倍数。

在此模型下，排序算法将数据块读入主内存中的缓冲区，对其进行一些处理，并在未来的某个时间将其写回磁盘。根据第 8.1 节，读写磁盘块所需的时间大约是内存访问时间的百万倍。基于这一事实，我们可以合理地期望单个块中包含的记录可以通过 Quicksort 等内部排序算法进行排序，而所需时间少于读写该块所需的时间。

在良好条件下，按顺序从文件中读取比随机顺序读取块更有效。鉴于寻道时间对磁盘访问的显著影响，按顺序处理似乎明显更快。然而，重要的是要精确地理解在何种情况下顺序文件处理实际上比随机访问更快，因为这会影响我们设计外部排序算法的方法。

高效的顺序访问依赖于寻道时间保持在最小值。第一个要求是构成文件的块实际上按顺序存储在磁盘上并且彼此靠近，最好填充少量连续磁道。至少，构成文件的区段数应很少。用户通常无法控制其文件在磁盘上的布局，但一次性按顺序将文件写入磁盘驱动器，并且磁盘驱动器有很大比例的空闲空间，会增加这种安排的可能性。

第二个要求是磁盘驱动器的 I/O 读写头在整个顺序处理过程中保持位于文件上方。如果 I/O 读写头有任何竞争，这种情况就不会发生。例如，在多用户分时计算机上，排序进程可能会与其它用户的进程竞争 I/O 读写头。即使排序进程完全控制 I/O 读写头，顺序处理仍然可能效率不高。想象一下所有处理都在单个磁盘驱动器上完成的情况，采用典型的单组读写头一起在盘片堆上移动的布置。如果排序过程涉及从输入文件读取，交替写入输出文件，那么 I/O 读写头将不断在输入文件和输出文件之间寻道。同样，如果同时处理两个输入文件【例如在合并过程中】，那么 I/O 读写头将不断在这两个文件之间寻道。

其寓意是，使用单个磁盘驱动器时，通常不存在对数据文件的有效顺序处理。因此，排序算法如果执行较少的非顺序磁盘操作，而不是执行大量在逻辑上是顺序的磁盘操作而实际上需要大量寻道，可能更有效。

如前所述，记录大小可能相对于键的大小相当大。例如，大型企业的工资条目可能每个存储数百字节的信息，包括每个员工的姓名、ID、地址和职位。排序键可能是 ID 号，仅需几个字节。最简单的排序算法可能是将此类记录作为整体处理，每次处理时读取整个记录。然而，这将大大增加所需的 I/O 量，因为单个磁盘块中只能容纳相对较少的记录。另一种选择是进行 **key sort**。在此方法下，所有键都被读取并一起存储在 **index file** 中，每个键都存储有指向原始数据文件中相应记录位置的指针。键和指针的组合应明显小于原始记录的大小；因此，索引文件将远小于完整数据文件。然后对索引文件进行排序，因为索引记录小于完整记录，所以所需的 I/O 远少。

一旦索引文件排序完成，就有可能重新排列原始数据库文件中的记录。这通常不会做有两个原因。首先，按排序顺序从记录文件中读取记录需要对每条记录进行随机访问。这可能需要大量时间，并且只有在需要按排序顺序查看或处理完整的记录集合时才有价值【而不是搜索选定的记录】。其次，数据库系统通常允许在多个键上进行搜索。例如，今天的处理可能是按 ID 号的顺序进行。明天，老板可能希望按薪水排序的信息。因此，可能没有单一的“排序”顺序适用于完整记录。相反，通常会维护多个索引文件，每个排序键一个。这些思想在第 10 章中进一步探讨。

### 8.5.1 简单的外部排序方法

如果你的操作系统支持虚拟内存，最简单的“外部”排序方法是读取整个文件到虚拟内存并运行 Quicksort 等内部排序方法。这种方法允许虚拟内存管理器使用其正常的缓冲区池机制来控制磁盘访问。不幸的是，这可能并不总是可行的选择。一个潜在的缺点是虚拟内存的大小通常限制在远小于可用磁盘空间的范围内。因此，你的输入文件可能无法放入虚拟内存。可以通过调整内部排序方法以使用自己的缓冲区池来克服有限的虚拟内存。

将内部排序算法适配到外部排序的更普遍问题是，它可能不如专门设计用于最小化磁盘 I/O 的新算法高效。考虑将 Quicksort 简单适配以使用缓冲区池的情况。Quicksort 首先处理整个记录数组，第一步分区从两端向内移动索引。这可以使用缓冲区池有效地实现。然而，下一步是处理每个子数组，然后处理子子数组，依此类推。随着子数组变小，处理很快接近对磁盘驱动器的随机访问。即使最大限度地使用缓冲区池，Quicksort 在平均情况下仍必须读取和写入每条记录 log n 次。我们可以做得更好。最后，即使虚拟内存管理器可以使用标准 Quicksort 实现良好的性能，这也会以使用大量系统工作内存为代价，这意味着系统无法将此空间用于其它工作。更好的方法可以在使用更少内存的同时节省时间。

我们对外部排序的方法源自 Mergesort 算法。最简单的外部 Mergesort 形式对记录进行一系列顺序传递，每次传递合并越来越大的子列表。第一次传递将大小为 1 的子列表合并为大小为 2 的子列表；第二次传递将大小为 2 的子列表合并为大小为 4 的子列表；以此类推。已排序的子列表称为 run。因此，每次传递都是将成对的 run 合并成更长的 run。每次传递都会将文件的内容复制到另一个文件。下面是算法的草图，如图 8.6 所示。

- 1. 将原始文件拆分为两个大小相等的 run 文件。
- 2. 从每个 run 文件中读取一个块到输入缓冲区。
- 3. 取出每个输入缓冲区的第一条记录，并以排序顺序将长度为二的 run 写入输出缓冲区。
- 4. 取出每个输入缓冲区的下一条记录，并以排序顺序将长度为二的 run 写入第二个输出缓冲区。
- 5. 重复直到完成，在两个输出 run 缓冲区之间交替输出。每当到达输入块的末尾时，从适当的输入文件读取下一个块。当输出缓冲区满时，将其写入适当的输出文件。
