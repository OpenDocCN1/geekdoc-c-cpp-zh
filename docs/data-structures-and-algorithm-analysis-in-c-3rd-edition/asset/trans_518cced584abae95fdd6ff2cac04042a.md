## 排序与查找

## 内部排序

我们在日常生活中会排序很多东西：玩桥牌时一把牌；账单和其他纸堆；香料罐；等等。我们有许多直观的策略可以根据我们需要排序的对象数量以及它们移动的难度来使用。排序也是计算机中最频繁执行的计算任务之一。我们可能会对数据库中的记录进行排序，以便更有效地搜索集合。我们可能会按邮政编码对记录进行排序，以便更便宜地打印和邮寄。我们可能会将排序用作解决其他问题的算法的内在部分，例如在计算最小成本生成树时（参见第 11.5 节）。

由于排序如此重要，自然而然地它已被深入研究，并且已经设计出许多算法。其中一些算法是我们日常生活中使用的方案的直接改编。另一些则与人类做事的方式完全不同，是为对计算机上存储的数千甚至数百万条记录进行排序而发明的。经过多年的研究，排序相关的未解决问题仍然存在。新的算法仍在为特殊用途应用而开发和改进。

在介绍计算机科学中的这个核心问题时，本章的次要目的是说明算法设计和分析中的问题。例如，这个排序算法集合展示了使用分治法的多种方法。特别是，分治的方式有多种：归并排序将列表分成两半；快速排序将列表分为大值和小值；基数排序通过一次处理键的一个数字来划分问题。排序算法还可以说明各种各样的分析技术。我们会发现一个算法的平均情况的增长速率可能显著小于其最坏情况（快速排序）。我们将看到如何通过利用另一种算法的最佳情况行为来加速排序算法（希尔排序和快速排序都利用插入排序）。我们将看到如何调整算法以获得更好性能的几个例子。我们将看到某些算法的特殊情况行为使其成为特殊细分应用的良好解决方案（堆排序）。排序提供了分析问题下界的重要技术的例子。排序也将被用来推动第 8 章中介绍的文件处理的介绍。

本章介绍了一些适用于对适合计算机主内存中的记录集合进行排序的标准算法。它首先讨论了三种简单但相对较慢的算法，在平均和最坏情况下都需要 Θ(n²) 时间。然后介绍了性能明显更好的几种算法，其中一些最坏情况运行时间为 Θ(n log n)。最后介绍的排序方法在特殊条件下仅需要 Θ(n) 最坏情况时间。本章以排序在一般情况下最坏情况下需要 Ω(n log n) 时间的证明结束。

### 7.1 排序术语和符号

除非另有说明，本章介绍的排序算法的输入是存储在数组中的记录集合。记录通过比较器类相互比较，如第 4.4 节中介绍的那样。为了简化讨论，我们假设每个记录都有一个键字段，其值由比较器提取。比较器类的键方法是 prior，它在第一个参数应出现在排序列表中第二个参数之前时返回 true。我们还假设对于每种记录类型都存在一个 swap 函数，可以交换数组中两个记录的内容（参见附录）。

给定一组记录 r₁, r₂, ..., rₙ，其键值为 k₁, k₂, ..., kₙ，排序问题是将记录排列成任意顺序 s，使得记录 rₛ₁, rₛ₂, ..., rₛₙ 的键满足性质 kₛ₁ ≤ kₛ₂ ≤ ... ≤ kₛₙ。换句话说，排序问题是将一组记录排列成其键字段的值按非递减顺序排列。

按定义，排序问题允许输入包含两个或多个具有相同键值的记录。某些应用要求输入不包含重复的键值。本章和第 8 章中介绍的排序算法可以处理重复的键值，除非另有说明。

当允许重复键值时，重复项可能存在隐式顺序，通常基于它们在输入中的出现顺序。可能希望保持重复项之间的初始顺序。如果排序算法不改变具有相同键值的记录的相对顺序，则称该算法是稳定的。本章介绍的许多但不是全部排序算法是稳定的，或者可以通过小的修改使其稳定。

可能具有误导性，因为许多排序算法的运行时间取决于输入值的具体情况。特别是，记录的数量、键和记录的大小、键值的允许范围以及输入记录“无序”的程度都可能极大地影响排序算法的相对运行时间。

在分析排序算法时，传统上测量键之间进行的比较次数。该度量通常与算法的运行时间密切相关，并且具有机器和数据类型无关的优点。然而，在某些情况下，记录可能非常大，以至于它们的物理移动可能占用总运行时间的很大一部分。如果是这样，可能需要测量算法执行的交换操作次数。在大多数应用中，我们可以假设所有记录和键都是固定长度的，并且无论涉及哪些键，单次比较或单次交换操作都需要恒定时间。某些特殊情况“改变了”比较排序算法的规则。例如，具有长度差异很大的记录或键的应用（例如排序可变长度字符串序列）将受益于特殊用途的排序技术。某些应用要求对少量记录进行排序，但排序需要频繁执行。一个例子是反复对五个数进行排序的应用。在这种情况下，通常在渐近分析中忽略的运行时方程中的常数现在变得至关重要，某些情况要求排序算法尽可能少地使用内存。最后，我们将指出哪些排序算法需要超出输入数组的显著额外内存。

### 7.2 三个 Θ(n²) 排序算法

本节介绍三种简单的排序算法。虽然易于理解和实现，但我们很快就会看到，当有大量记录需要排序时，它们是不可接受的缓慢。尽管如此，在某些情况下，其中一种简单算法是最佳工具。

#### 7.2.1 插入排序

想象一下，你有一叠过去两年的电话账单，你希望按日期整理它们。一个相当自然的方法可能是先查看前两张账单并将它们排序。然后取第三张账单并将其与前两张一起放入正确顺序，依此类推。随着你取出每张账单，你会将其添加到已经制作好的已排序堆中。这个自然直观的过程是我们第一个排序算法的灵感，称为插入排序。插入排序遍历记录列表。每个记录依次插入到由已处理的那些记录组成的已排序列表中的正确位置。

以下是 C++ 实现。输入是存储在数组 A 中的 n 条记录。

```
template <typename E, typename Comp>
void inssort(E A[], int n) { // Insertion Sort
for (int i=1; i<n; i++) { // Insert i'th record
for (int j=i; (j>0) && (Comp::prior(A[j], A[j-1])); j--)
swap(A, j, j-1);
}
}
```

考虑 inssort 处理第 i 条记录的情况，其键值为 X。只要 X 小于它上面的键值，该记录就会在数组中向上移动。一旦遇到小于或等于 X 的键值，inssort 就完成了该记录的处理，因为数组中它上面的所有记录都必须具有更小的键。图 7.1 说明了插入排序的工作原理。

inssort 的主体由两个嵌套的 for 循环组成。外部 for 循环执行 n – 1 次。内部 for 循环更难分析，因为它执行的次数取决于位置 1 到 i – 1 中有多少个键的值小于位置 i 中的键。在最坏情况下，每条记录都必须到达数组顶部。这将发生在键最初从最高到最低排列时，即与排序顺序相反。在这种情况下，比较次数第一次循环时为一，第二次为二，依此类推。因此，总比较次数为 \sum_{i=2}^n i \approx n^2/2 = \Theta(n^2)。
