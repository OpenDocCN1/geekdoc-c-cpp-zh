

## 3.4 渐近分析

尽管图 3.1 中标记为 10n 的曲线的常数更大，2n² 在相对较小的 n = 5 处就与它相交。如果我们把线性方程前的常数加倍呢？如图所示，20n 在 n = 10 时就被 2n² 超过。线性增长率的额外因子 2 并没有多大影响。它只使交点的 x 坐标翻倍。一般来说，对任一方程中的常数因子进行改变，只会改变两条曲线相交的位置，而不会改变它们是否相交。

当你购买一台更快的计算机或使用一个更快的编译器时，在给定的时间内、对于给定的增长率，能够运行的新问题规模会按相同的因子变大，而与运行时间方程中的常数无关。具有不同增长率的两种算法的时间曲线仍然会相交，而与它们的运行时间方程常数无关。出于这些原因，当我们想要估计算法的运行时间或其他资源需求的增长率时，我们通常会忽略常数。这简化了分析，并使我们始终关注最重要的方面：增长率。这称为渐近算法分析。严格来说，渐近分析是指对算法在输入规模“变得很大”或达到极限时的研究（在微积分意义上）。然而，忽略所有常数因子被证明是如此有用，以至于渐近分析被用于大多数算法比较。

并非总是合理地忽略常数。当比较针对 n 的小值运行的算法时，常数可能会产生很大影响。例如，如果问题是对恰好五个记录的集合进行排序，那么为排序数千条记录而设计的算法可能就不合适，即使其渐近分析表明性能良好。在罕见的情况下，两种算法比较的常数可能相差 1000 倍或更多，使得增长率较低的那一个由于其较大的常数而在大多数用途上不切实际。渐近分析是一种算法资源消耗的“粗略估算”形式。它提供了算法运行时间或其他资源需求的简化模型。这种简化通常有助于你理解算法的行为。只是要意识到在常数很重要的罕见情况下，渐近分析的局限性。

### 3.4.1 上界

有几个术语用于描述算法的运行时间方程。这些术语——及其相关符号——精确地指出了算法行为的哪个方面。其中之一是算法运行时间增长的上界。它表示算法可能具有的最高增长率。

由于短语“其增长率的上界为 f(n)”很长，并且在讨论算法时经常使用，我们采用一种特殊的记号，称为大-O 记号。如果算法的增长率上界（例如最坏情况）为 f(n)，那么我们就写这个算法“在最坏情况下属于集合 O(f(n))”（或简写为“在最坏情况下属于 O(f(n))”）。例如，如果 n² 与 T(n)（我们算法的运行时间）在最坏输入情况下增长一样快，我们就说该算法“在最坏情况下属于 O(n²)”。

下面是上界的精确定义。T(n) 表示算法的真实运行时间。f(n) 是上界的某个表达式。

对于非负值函数 T(n)，T(n) 属于集合 O(f(n))，如果存在两个正常数 c 和 n₀，使得对于所有 n > n₀，T(n) ≤ c f(n)。

常数 n₀ 是上界声明成立的最小 n 值。通常 n₀ 很小，例如 1，但也不必如此。你还必须能够选取某个常数 c，但 c 的实际取值无关紧要。换句话说，该定义说明对于所讨论类型的全部输入（例如大小为 n 的所有输入的最坏情况），只要足够大（即 n > n₀），算法总是执行少于 c f(n) 步，其中 c 为某个常数。

**例 3.4.** 考虑在整数数组中查找指定值的顺序查找算法。如果访问并检查数组中的一个值需要 cₛ 步，其中 cₛ 为正数，并且我们要查找的值在数组中的任何位置出现的概率相等，则在平均情况下 T(n) = cₛ n/2。对于所有 n > 1 的值，cₛ n/2 ≤ cₛ n。因此，根据定义，T(n) 在 n₀ = 1 且 c = cₛ 时属于 O(n)。

**例 3.5.** 对于某个特定算法，在平均情况下 T(n) = c₁ n² + c₂ n，其中 c₁ 和 c₂ 为正数。则 c₁ n² + c₂ n ≤ c₁ n² + c₂ n² ≤ (c₁ + c₂) n² 对于所有 n > 1 成立。所以，T(n) ≤ c n² 对于 c = c₁ + c₂，且 n₀ = 1。因此，根据定义，T(n) 属于 O(n²)。

**例 3.6.** 将数组第一个位置的值赋给一个变量所需的时间与数组大小无关，为常数时间。因此，T(n) = c（对于最好、最坏和平均情况）。在这种情况下，我们可以说 T(n) 属于 O(c)。然而，传统上说运行时间具有常数上界的算法属于 O(1)。

如果你突然被问到“谁是最好的？”，你的自然反应应该是回答“最好做什么？”同样，如果有人问你“这个算法的增长率是什么”，你需要问“何时？最好情况？平均情况？还是最坏情况？”有些算法无论接收到什么输入实例，其行为都相同。例如在整数数组中寻找最大值。但对于许多算法，这会有很大区别，例如在未排序数组中搜索特定值。因此，关于算法上界的任何陈述都必须在大小为 n 的某类输入的上下文中。我们几乎总是对最好情况、平均情况或最坏情况输入测量这个上界。因此，我们不能说，“这个算法的增长率上界为 n²。”我们必须说类似，“这个算法在平均情况下的增长率上界为 n²。”

知道某物属于 O(f(n)) 只说明事情可能有多糟。也许实际情况并没有那么糟。由于顺序查找在最坏情况下属于 O(n)，因此说顺序查找属于 O(n²) 也是正确的。但顺序查找对于大的 n 来说是实用的，而这对于某些其他属于 O(n²) 的算法则不成立。我们总是寻求用最紧的（最低的）上界来定义算法的运行时间。因此，我们更愿意说顺序查找属于 O(n)。这也解释了为什么使用短语“属于 O(f(n))”或记号“∈ O(f(n))”，而不是“是 O(f(n))”或“= O(f(n))”。大-O 记号的使用没有严格的相等性。O(n) 属于 O(n²)，但 O(n²) 不属于 O(n)。

### 3.4.2 下界

大-O 记号描述上界。换句话说，大-O 记号断言了算法对于大小为 n 的某类输入（通常是最坏的此类输入、所有可能输入的平均值，或最好的此类输入）所需资源（通常是时间）的最大量。

类似的记号用于描述算法对某类输入所需资源的最小量。与大-O 记号一样，这也是算法增长率的度量。与大-O 记号一样，它适用于任何资源，但我们最常测量所需的最少时间。同样，与大-O 记号一样，我们测量的是对特定类输入所需的资源：大小为 n 的最坏、平均或最好情况输入。

算法（或问题，如后面解释）的下界用符号 Ω 表示，读作“大-Omega”或“Omega”。下面对 Ω 的定义与大-O 的定义是对称的。

对于非负值函数 T(n)，T(n) 属于集合 Ω(g(n))，如果存在两个正常数 c 和 n₀，使得对于所有 n > n₀，T(n) ≥ c g(n)。
