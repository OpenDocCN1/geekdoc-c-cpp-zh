每个磁头对应一个磁头。单个盘片上可由该盘片的磁头某一位置访问到的数据统称为一个磁道，即盘片上与主轴距离固定的所有数据，如图 8.2(b) 所示。与主轴距离固定的所有磁道的集合称为一个柱面。因此，柱面即为臂处于特定位置时可读取的所有数据。

每个磁道被细分为扇区。扇区之间存在扇区间隙，其中不存储任何数据。这些间隙使读头能够识别扇区的结束。请注意，每个扇区包含相同数量的数据。由于外层磁道长度更大，因此每英寸的位数比内层磁道少。因此，大约有一半的潜在存储空间被浪费，因为只有最内层的磁道以最高可能的数据密度存储。这种排列如图 8.3a 所示。如今的磁盘驱动器实际上将磁道分组为“区域”，使得最内层区域内的磁道在向外调整其数据密度以保持相同的径向数据密度，然后下一区域的磁道重置数据密度以更好地利用其存储能力，依此类推。这种排列如图 8.3b 所示。

与硬盘的物理布局相反，CD-ROM 由单一螺旋轨道组成。轨道上信息位的间距相等，因此内外轨道的信息密度相同。为了使螺旋上的信息流保持恒定速率，驱动器必须在 I/O 头向磁盘中心移动时加快磁盘旋转速率。这使得机制更复杂且更慢。

从硬盘读取特定字节或一系列字节数据时，会发生三个独立步骤。首先，I/O 头移动，使其位于包含数据的磁道上方。这种移动称为寻道。其次，包含数据的扇区旋转到头下方。使用时磁盘始终在旋转。截至本文撰写时，典型磁盘旋转速率为每分钟 7200 转 (rpm)。等待所需扇区转到 I/O 头下方所花费的时间称为旋转延迟或旋转等待时间。第三步是数据的实际传输（即读写）。一旦第一个字节位于 I/O 头下方，读取信息所需的时间相对较少，只需其全部移过头下方所需的时间。事实上，磁盘驱动器设计为每次请求读取整个扇区数据，而不是一个字节。因此，扇区是可一次读取或写入的最小数据量。

通常，希望将文件的全部扇区尽可能集中在最少的磁道上。这种期望源于两个假设：

- 寻道时间很慢（通常是 I/O 操作中最昂贵的部分），并且
- 如果读取了文件的一个扇区，下一个扇区很可能很快会被读取。

假设 (2) 称为局部性原理，这在计算机应用中经常出现。

连续扇区通常被分组形成簇。簇是文件分配的最小单位，因此所有文件都是簇大小的倍数。簇大小由操作系统确定。文件管理器跟踪构成每个文件的簇。

在 Microsoft Windows 系统中，磁盘上有一个指定部分称为文件分配表，用于存储哪些扇区属于哪个文件的信息。相比之下，UNIX 不使用簇。文件分配和可读写的最小编号单位是扇区，在 UNIX 术语中称为块。UNIX 在称为 i-node 的某些磁盘块中维护有关文件组织的信息。

来自同一文件的物理上连续的簇组称为区段。理想情况下，构成文件的全部簇在磁盘上是连续的（即文件由一个区段组成），以便最大限度地减少访问文件不同部分所需的寻道时间。如果磁盘在文件创建时几乎已满，可能没有足够大的区段可容纳新文件。此外，如果文件增长，可能没有物理上相邻的可用空间。因此，文件可能由磁盘上分散的几个区段组成。磁盘越满，磁盘上的文件变化越多，这种文件碎片（以及由此产生的寻道时间）就越糟糕。文件碎片会导致性能明显下降，因为访问数据需要额外的寻道。

另一种问题类型出现在文件的逻辑记录大小与扇区大小不匹配时。如果扇区大小不是记录大小的倍数（或反之），记录将无法均匀地分布在扇区内。例如，一个扇区可能长 2048 字节，而逻辑记录为 100 字节。这留有存储 20 条记录的空间，剩余 48 字节。额外的空间要么被浪费，要么允许记录跨越扇区边界。如果记录跨越扇区边界，则可能需要两次磁盘访问才能读取它。如果空间保持空置，则这种浪费的空间称为内部碎片。

内部碎片的第二个例子发生在簇边界。文件大小不是簇大小的偶数倍时，最后一个簇的末尾必须浪费一些空间。最坏的情况发生在文件大小模簇大小为一时（例如，文件为 4097 字节，簇为 4096 字节）。因此，簇大小是在顺序处理的较大文件（其中较大的簇大小有利于最小化寻道）和较小文件（其中较小的簇有利于最小化浪费存储）之间的一种权衡。

每个磁盘驱动器组织都需要使用一些磁盘空间来组织扇区、簇等。磁道内扇区的布局如图 8.4 所示。必须存储在磁盘本身上的典型信息包括文件分配表、包含地址标记和每个扇区状况（是否可用）信息的扇区头，以及扇区间隙。扇区头还包含错误检测码，以帮助验证数据未被损坏。这就是为什么大多数磁盘驱动器具有“标称”大小的原因。这大于驱动器上可存储的实际用户数据量。差额是组织磁盘上信息所需空间的数量。由于碎片，还会损失更多空间。

## 8.2.2 磁盘访问成本

当需要寻道时，通常是访问磁盘信息的主要成本。这当然假设寻道是必要的。当按顺序读取文件时（如果构成文件的扇区在磁盘上是连续的），几乎不需要寻道。然而，当访问随机磁盘扇区时，寻道时间成为数据访问的主要成本。虽然实际寻道时间因 I/O 头当前所在磁道与头移动到的磁道之间的距离而高度可变，但我们只考虑两个数字。一个是磁道到磁道成本，即从一个磁道移动到相邻磁道所需的最小时间。这适用于你想要分析磁盘上放置良好的文件的访问时间的情况。第二个数字是随机访问的平均寻道时间。这两个数字通常由磁盘制造商提供。一个典型例子是 Western Digital Caviar 串行 ATA 驱动器。制造商规格表明磁道到磁道时间为 2.0 ms，平均寻道时间为 9.0 ms。2008 年该系列的典型驱动器大小为 120GB。2011 年，同一系列驱动器的大小已达到 2 或 3TB。在这两年的广告中，磁道到磁道和平均寻道时间完全相同。

多年来，磁盘驱动器的典型旋转速度为 3600 rpm，即每转 16.7 ms。2011 年大多数磁盘驱动器的旋转速度为 7200 rpm，即每转 8.3 ms。随机读取扇区时，可以预期磁盘需要旋转半圈才能将所需扇区带到 I/O 头下方，即 7200 rpm 磁盘驱动器的 4.2 ms。

一旦位于 I/O 头下方，扇区数据可以随扇区在头下方旋转一样快地传输。如果要读取整个磁道，则需要一整圈旋转（7200 rpm 时为 8.3 ms）使整个磁道移过头下方。如果只读取磁道的一部分，则所需时间按比例减少。例如，如果磁道上有 16,000 个扇区且要读取一个扇区，则所需时间微不足道（为一圈的 1/16,000）。
