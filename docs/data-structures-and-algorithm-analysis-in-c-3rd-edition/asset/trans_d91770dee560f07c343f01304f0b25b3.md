
> 我们很容易看出
> 
> $$\lim_{n\to\infty} \frac{n^2}{2n \log n} = \infty$$
> 因为 n 的增长速度比 2 log n 快。因此，n^2 在 \Omega(2n log n) 中。

## Example 3.9 我们首先分析一个简单的整数变量赋值。

由于赋值语句花费恒定时间，因此它是 Θ(1)。

```
a = b;

## Example 3.10 考虑一个简单的 for 循环。

```
sum = 0;
for (i=1; i<=n; i++)
sum += n;
```

第一行是 Θ(1)。for 循环重复 n 次。第三行花费恒定时间，因此根据第 3.4.4 节的简化规则 (4)，执行构成 for 循环的两个语句的总成本为 Θ(n)。根据规则 (3)，整个代码片段的成本也是 Θ(n)。

## Example 3.11 我们现在分析一个包含若干 for 循环的代码片段，其中一些是嵌套的。

```
sum = 0;
for (i=1; i<=n; i++) // First for loop
for (j=1; j<=i; j++) // is a double loop
sum++;
for (k=0; k<n; k++) // Second for loop
A[k] = k;
```

该代码片段有三个独立的语句：第一个赋值语句和两个 for 循环。同样，赋值语句花费恒定时间；记为 c1。第二个 for 循环与 Example 3.10 中的循环类似，花费 c2n = Θ(n) 时间。

第一个 for 循环是一个双重循环，需要一种特殊技术。我们从循环内部向外工作。表达式 sum++ 需要恒定时间；记为 c3。因为内层 for 循环执行 i 次，根据简化规则 (4) 其成本为 c3i。外层 for 循环执行 n 次，但每次内层循环的成本都不同，因为它花费 c3i 而 i 每次都在变化。你应该能看出，外层循环第一次执行时，i 为 1。外层循环第二次执行时，i 为 2。每次经过外层循环，i 增加一，直到循环最后一次执行时 i = n。因此，循环的总成本为 c3 乘以从 1 到 n 的整数之和。根据公式 2.1，我们知道

∑_{i=1}^{n} i = n(n + 1)/2

其为 Θ(n²)。根据简化规则 (3)，Θ(c1 + c2n + c3n²) 简化为 Θ(n²)。

## Example 3.12 比较以下两个代码片段的渐近分析：

```
sum1 = 0;
for (i=1; i<=n; i++)      // First double loop
    for (j=1; j<=n; j++)    //   do n times
        sum1++;
```

```
sum2 = 0;
for (i=1; i<=n; i++)      // Second double loop
    for (j=1; j<=i; j++)    //   do i times
        sum2++;
```

在第一个双重循环中，内层 for 循环始终执行 n 次。因为外层循环执行 n 次，很明显语句 sum1++ 精确执行 n² 次。第二个循环与前一个示例中分析的循环类似，成本为 ∑_{j=1}^{n} j。这大约为 ½ n²。因此，两个双重循环的成本均为 Θ(n²)，尽管第二个循环所需时间约为第一个的一半。

本节算法分析的最后一个示例将比较两种在数组中执行搜索的算法。之前，我们确定了在搜索值 K 在数组中各位置出现的概率相等时，顺序搜索的运行时间为平均和最坏情况下均为 Θ(n)。我们希望将此运行时间与对按从低到高顺序存储值的数组执行二分搜索所需的运行时间进行比较。

二分搜索首先检查数组中间位置的值；称此位置为 mid，对应的值为 k_mid。如果 k_mid = K，则处理可以立即停止。然而这种情况不太可能发生。幸运的是，知道中间值提供了有用的信息，可以帮助指导搜索过程。特别是，如果 k_mid > K，则你知道值 K 不能出现在数组中任何大于 mid 的位置。因此，你可以消除对数组上半部分的后续搜索。相反，如果 k_mid < K，则你知道可以忽略数组中小于 mid 的所有位置。无论哪种情况，都有一半的位置被排除在进一步考虑之外。二分搜索接下来查看 K 可能存在的数组部分中的中间位置。此位置的值再次使我们能够将剩余位置的一半排除在考虑之外。此过程重复进行，直到找到所需的值，或者数组中可能包含值 K 的位置已全部用完。图 3.4 说明了二分搜索方法。图 3.5 显示了二分搜索的实现。

为了在最坏情况下找到该算法的成本，我们可以将运行时间建模为递推式，然后求出闭式解。每次对 binary 的递归调用大约将数组大小减半，因此我们可以将最坏情况成本建模如下，假设为简单起见 n 为 2 的幂。

T(n) = T(n/2) + 1 for n > 1;   T(1) = 1.

// Return the position of an element in sorted array "A" of
// size "n" with value "K".  If "K" is not in "A", return
// the value "n".
int binary(int A[], int n, int K) {
    int l = -1;
    int r = n;            // l and r are beyond array bounds
    while (l+1 != r) {  // Stop when l and r meet
        int i = (l+r)/2;  // Check middle of remaining subarray
        if (K < A[i]) r = i;      // In left half
        if (K == A[i]) return i; // Found it
        if (K > A[i]) l = i;      // In right half
    }
    return n; // Search value not in A
}
```

### Figure 3.5 Implementation for binary search.

如果我们展开递推式，我们会发现只能展开 log n 次才达到基本情况，每次展开都会增加一次成本。因此，递推式的闭式解为 T(n) = log n。

函数 binary 设计为找到 K 的（单个）出现并返回其位置。如果 K 不在数组中，则返回一个特殊值。该算法可以修改以实现诸如在允许多次出现时返回 K 的第一次出现的位置，以及在 K 不在数组中时返回小于 K 的最大值的变体。

将顺序搜索与二分搜索进行比较，我们看到随着 n 的增长，顺序搜索在平均和最坏情况下的 Θ(n) 运行时间很快变得远大于二分搜索的 Θ(log n) 运行时间。孤立来看，二分搜索似乎比顺序搜索高效得多。尽管二分搜索的常数因子大于顺序搜索的常数因子，因为二分搜索计算下一次搜索位置的成本高于顺序搜索仅递增当前位置的成本。

然而请注意，顺序搜索的运行时间无论数组值是否按顺序存储大致相同。相比之下，二分搜索要求数组值按从低到高排序。根据二分搜索的使用上下文，这一对已排序数组的要求可能对完整程序的运行时间产生不利影响，因为在向数组插入新元素时保持值有序需要更大的成本。这是一个在二分搜索在搜索时的优势与维持已排序数组相关的劣势之间的权衡。只有在完整问题的上下文中，我们才能知道优势是否超过劣势。
