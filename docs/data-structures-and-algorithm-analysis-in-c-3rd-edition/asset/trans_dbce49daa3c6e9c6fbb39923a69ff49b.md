## 图 8.6 一个简单的外部归并排序算法。

输入记录平均分成两个输入文件。每个输入文件的第一段运行被合并并放入第一个输出文件。每个输入文件的第二段运行被合并并放入第二个输出文件。合并在两个输出文件之间交替进行，直到输入文件为空。然后输入文件和输出文件的角色互换，使得每次遍历时运行长度可以加倍。

- 6. 重复步骤 2 到 5，使用原始输出文件作为输入文件。在第二次遍历时，每个输入运行文件的最初两条记录已经按排序顺序排列。因此，这两个运行可以合并并输出为包含四个元素的单个运行。
- 7. 每次遍历运行文件都会产生越来越大的运行，直到只剩下一个运行。

## 示例 8.6

使用图 8.6 的输入，我们首先在两个输入文件之间创建长度为一的运行。然后我们依次处理这两个输入文件，生成长度为二的运行。第一个运行的值为 20 和 36，输出到第一个输出文件。下一个运行为 13 和 17，输出到第二个文件。运行 14、28 发送到第一个文件，然后运行 15、23 发送到第二个文件，以此类推。一旦本次遍历完成，输入文件和输出文件的角色互换。下一轮遍历将把长度为二的运行合并为长度为四的运行。运行 20、36 和 13、17 合并后发送 13、17、20、36 到第一个输出文件。然后运行 14、28 和 15、23 合并后发送运行 14、15、23、28 到第二个输出文件。在最后一次遍历中，这些运行被合并形成最终运行 13、14、15、17、20、23、28、36。

该算法可以很容易地利用第 8.3 节中描述的双缓冲技术。注意各种遍历都顺序读取输入运行文件并顺序写入输出运行文件。然而，为了使顺序处理和双缓冲有效，需要为每个文件提供一个单独的 I/O 头。这通常意味着输入和输出文件中的每一个都必须位于单独的磁盘驱动器上，为了最大效率总共需要四个磁盘驱动器。

前面描述的外部归并排序算法要求对包含 n 条记录的文件进行 log n 次遍历进行排序。因此，每条记录必须从磁盘读取并写入磁盘 log n 次。可以通过观察到对小运行使用归并排序并非必要来显著减少遍历次数。一种简单的修改是读取一块数据，在内存中对其进行排序（也许使用快速排序），然后将其作为单个已排序运行输出。

## 示例 8.7

假设我们有大小为 4KB 的块，记录为八个字节，其中四个字节为数据和四个字节的键。因此，每个块包含 512 条记录。标准归并排序需要九次遍历来生成 512 条记录的运行，而将每个块作为一个单元处理则可以在一次遍历中完成内部排序。这些运行然后可以由归并排序合并。标准归并排序需要十八次遍历来处理 256K 条记录。使用内部排序创建初始运行长度为 512 条记录可将其减少为一次初始遍历来创建运行和九次合并遍历将它们全部合并在一起，大约减少一半的遍历次数。

我们可以扩展这一概念以进一步提高性能。可用主内存通常远不止一个块大小。如果我们处理更大的初始运行，则归并排序所需的遍历次数会进一步减少。例如，大多数现代计算机可以为排序程序提供数十兆甚至数百兆字节的 RAM。如果将所有这些内存（除少量用于缓冲区和局部变量外）都用于构建尽可能大的初始运行，那么相当大的文件可以在很少的遍历中处理。下一节介绍了一种产生大运行的技术，通常大小是直接放入主内存的两倍。

减少所需遍历次数的另一种方法是增加每次遍历期间合并在一起的运行数量。虽然标准归并排序算法一次合并两个运行，但合并并不需要如此限制。第 8.5.3 节讨论了多路合并技术。

多年来，已经提出了许多外部排序的变体，但所有都基于以下两个步骤：

- 1. 将文件分解为大的初始运行。
- 2. 将运行合并在一起形成单个已排序文件。

## 图 8.7 替换选择的概述。输入记录按顺序处理。最初 RAM 被 M 条记录填满。随着记录的处理，它们被写入输出缓冲区。当该缓冲区填满时，它会被写入磁盘。与此同时，随着替换选择需要记录，它从输入缓冲区读取它们。每当该缓冲区变空时，下一个记录块就会从磁盘读取。

为数组可用的内存大小为 M 条记录，则输入文件可以分解为长度为 M 的初始运行。更好的方法是使用一种称为替换选择算法，平均可以创建长度为 2M 条记录的运行。替换选择实际上是堆排序算法的轻微变体。堆排序比快速排序慢这一事实在此上下文中无关紧要，因为 I/O 时间将主导任何合理的外部排序算法的总运行时间。构建更长的初始运行将减少所需总 I/O 时间。

替换选择将 RAM 视为由大小为 M 的数组加上输入缓冲区和输出缓冲区组成。（如果操作系统支持双缓冲，则可能需要额外的 I/O 缓冲区，因为替换选择在其输入和输出上都进行顺序处理。）想象输入文件和输出文件是记录流。替换选择在需要时按顺序从输入流中取出下一条记录，并一次输出一条记录到输出流。缓冲用于使磁盘 I/O 一次按块执行。记录块最初被读取并保存在输入缓冲区中。替换选择一次从输入缓冲区中取出一条记录，直到缓冲区为空。此时读取下一个记录块。输出到缓冲区类似：一旦缓冲区填满，它作为一个整体写入磁盘。此过程由图 8.7 说明。

替换选择的工作方式如下。假设主要处理在大小为 M 条记录的数组中完成。

- 1. 从磁盘填充数组。设 LAST = M − 1。
- 2. 构建一个最小堆。（回想一下，最小堆定义为每个节点的记录键值小于其子节点的键值。）
- 3. 重复直到数组为空：
  - (a) 将具有最小键值（根）的记录发送到输出缓冲区。
  - (b) 设 R 为输入缓冲区中的下一条记录。如果 R 的键值大于刚刚输出的键值 ...
    - i. 则将 R 放在根部。
    - ii. 否则用数组位置 LAST 中的记录替换根，并将 R 放在位置 LAST。设 LAST = LAST − 1。
  - (c) 下沉根以重新排序堆。

当步骤 3(b) 中的测试成功时，一条新记录被添加到堆中，最终作为运行的一部分输出。只要从输入文件来的记录键值大于为本次运行输出的最后一个键值，它们就可以安全地添加到堆中。键值较小的记录不能作为当前运行的一部分输出，因为它们不会按排序顺序排列。这样的值必须存储在某处以供将来作为另一运行的一部分处理。然而，因为在这种情况下堆会缩小一个元素，现在有一个空闲空间，原来堆的最后一个元素所在的位置！因此，替换选择会慢慢缩小堆，同时利用被丢弃的堆空间来存储下一运行的记录。一旦第一个运行完成（即堆变空），数组将被填满记录，准备用于第二个运行的处理。图 8.8 说明了替换选择创建运行的一部分。

应该很清楚，运行的最小长度将为 M 条记录，如果堆的大小为 M，因为至少堆中最初的那些记录将是运行的一部分。在良好条件下（例如，如果输入已排序），则可以实现任意长的运行。实际上，整个文件可以作为一次运行处理。如果条件很差（例如，如果输入是逆序排序），则运行仅为大小 M。

替换选择生成的运行的预期长度是多少？可以从一个称为雪犁论证的类比中推断出来。想象一个雪犁在暴风雪中绕着圆形轨道行驶。犁至少绕行一次后，轨道上的雪情况如下。犁后面，轨道是空的，因为它刚刚被犁过。轨道上雪量最大的是犁前面，因为这是最近被犁过的地方。在任何瞬间，轨道上有一定量的雪 S。雪不断以稳定速率落在整个轨道上，部分雪落在犁“前面”，部分落在犁“后面”。（在圆形轨道上，一切实际上都在犁“前面”，但图 8.9 说明了这个想法。）在犁的下一次绕行中，轨道上所有的雪 S 都会被清除，外加一半新落的雪。因为一切都假设处于稳态，经过一次绕行后轨道上仍有 S 雪，所以在一次绕行期间必须落下 2S 雪，并且在一次绕行期间清除 2S 雪（留下 S 雪）。
