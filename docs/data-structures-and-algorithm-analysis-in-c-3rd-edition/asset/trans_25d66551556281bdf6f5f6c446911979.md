```
class DijkElem {
public:
    int vertex, distance;
    DijkElem() { vertex = -1; distance = -1; }
    DijkElem(int v, int d) { vertex = v; distance = d; }
};
```

## 11.5 最小代价生成树

最小代价生成树（MST）问题以一个连通、无向图 G 作为输入，其中每条边都附有一个距离或权重度量。MST 是包含 G 的顶点以及 G 的边子集的图，该子集（1）具有最小总代价（按子集中所有边的值求和来衡量），并且（2）保持顶点连通。该问题解决方案有用的应用包括焊接所需的最短导线组

```
// Dijkstra’s shortest paths algorithm with priority queue
void Dijkstra(Graph* G, int* D, int s) {
    int i, v, w;                // v is current vertex
    DijkElem temp;
    DijkElem E[G->e()];         // Heap array with lots of space
    temp.distance = 0; temp.vertex = s;
    E[0] = temp;                // Initialize heap array
    heap<DijkElem, DDComp> H(E, 1, G->e()); // Create heap
    for (i=0; i<G->n(); i++) {          // Now, get distances
        do {
            if (H.size() == 0) return; // Nothing to remove
            temp = H.removefirst();
            v = temp.vertex;
        } while (G->getMark(v) == VISITED);
        G->setMark(v, VISITED);
        if (D[v] == INFINITY) return;   // Unreachable vertices
        for (w=G->first(v); w<G->n(); w = G->next(v,w))
            if (D[w] > (D[v] + G->weight(v, w))) { // Update D
                D[w] = D[v] + G->weight(v, w);
                temp.distance = D[w]; temp.vertex = w;
                H.insert(temp);     // Insert new distance in heap
            }
    }
}
```

### 11.5.1 普里姆算法

我们用于查找 MST 的两个算法中的第一个通常被称为普里姆算法。普里姆算法非常简单。从图中的任意顶点 N 开始，最初将 MST 设置为 N。选择与 N 相连的代价最小的边。这条边将 N 连接到另一个顶点；称其为 M。将顶点 M 和边 (N, M) 添加到 MST。接下来，选择从 N 或 M 出发到达图中任何其他顶点的代价最小的边。将此边及其所到达的新顶点添加到 MST。此过程不断继续，每一步都通过选择从当前 MST 中的某个顶点到当前不在 MST 中的某个顶点的代价最小的边来扩展 MST。

普里姆算法与用于查找单源最短路径的 Dijkstra 算法非常相似。主要区别在于，我们寻找的不是离起始顶点最近的顶点，而是离当前 MST 中任何顶点最近的顶点。因此，我们将 Dijkstra 算法中的这几行

```
if (D[w] > (D[v] + G->weight(v, w)))
    D[w] = D[v] + G->weight(v, w);
```

替换为普里姆算法中的这几行

```
if (D[w] > G->weight(v, w))
    D[w] = G->weight(v, w);
```

图 11.21 展示了普里姆算法的一种实现，它搜索距离矩阵以寻找下一个最近的顶点。对于每个顶点 I，当 I 被普里姆算法处理时，一条指向 I 的边会被添加到我们正在构建的 MST 中。数组 V[I] 存储了离顶点 I 最近的、之前已访问过的顶点。这些信息让我们知道当顶点 I 被处理时哪条边应该进入 MST。

```
void Prim(Graph* G, int* D, int s) { // Prim’s MST algorithm
    int V[G->n()];                 // Store closest vertex
    int i, w;
    for (i=0; i<G->n(); i++) {     // Process the vertices
        int v = minVertex(G, D);
        G->setMark(v, VISITED);
        if (v != s)
            AddEdgetoMST(V[v], v);  // Add edge to MST
        if (D[v] == INFINITY) return; // Unreachable vertices
        for (w=G->first(v); w<G->n(); w = G->next(v,w))
            if (D[w] > G->weight(v,w)) {
                D[w] = G->weight(v,w);  // Update distance
                V[w] = v;               // Where it came from
            }
    }
}
```

普里姆算法是贪心算法的一个例子。在 for 循环的每一步中，我们选择连接某个已标记顶点与某个未标记顶点的代价最小的边。除此之外，该算法并不会检查 MST 是否真的应该包含这条代价最小的边。这引出了一个重要问题：普里姆算法是否正确？显然，它生成了一棵生成树（因为每次执行 for 循环都会向生成树中添加一条边和一个未标记的顶点，直到所有顶点都被添加），但这棵树是否具有最小代价？
