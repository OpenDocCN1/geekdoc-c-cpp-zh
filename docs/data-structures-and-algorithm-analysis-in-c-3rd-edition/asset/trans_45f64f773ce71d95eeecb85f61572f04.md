

## 14.1 求和技巧

考虑以下简单的求和。

$$\sum_{i=1}^{n} i.$$

在第 2.6.3 节中，已通过归纳法证明该求和具有众所周知的闭式 n(n + 1)/2。但归纳法虽然是证明所提出闭式表达式正确的好方法，我们如何才能首先找到一个待测试的候选闭式表达式呢？让我们试着从第一性原理出发思考这个问题，就好像我们从未见过它一样。

分析求和的一个好起点是对给定 n 的值进行估计。观察到该求和的最大项为 n，且有 n 项相加。因此总和必须小于 n²。实际上，大多数项远小于 n，且项的大小线性增长。如果我们为项的大小画出条形图，其高度将形成一条直线，我们可以将其包围在一个宽 n、高 n 的盒子中。从中很容易看出，求和的更接近的估计约为 (n²)/2。掌握这个估计有助于我们在尝试确定精确的闭式解时，因为我们希望能识别出所提出的解是否严重错误。

现在让我们考虑一些可能找到该求和闭式解的精确方程的方法。我们可以采取的一种特别巧妙的方法是观察我们可以将“配对”第一项和最后一项，第二项和第 (n − 1) 项，等等。每对的和为 n + 1。对数是 n/2。因此，解为 n(n + 1)/2。这很漂亮，而且毫无疑问是正确的。问题在于它并不是解决许多其他求和的有效技术。

现在让我们尝试做一些更一般的事情。我们已经认识到，因为最大项为 n 且有 n 项，求和小于 n²。如果我们幸运的话，闭式解是一个多项式。以此作为工作假设，我们可以调用一种称为猜测-检验的技术。我们将猜测该求和的闭式解是形式为 c₁n² + c₂n + c₃ 的多项式，其中 c₁、c₂ 和 c₃ 为常数。如果这是真的，那么我们可以将求和的小情况的答案代入以求解系数。对于此示例，将 0、1 和 2 代入 n 会得到三个联立方程。因为当 n = 0 时求和只是 0，c₃ 必须为 0。对于 n = 1 和 n = 2，我们得到两个方程

$$c₁ + c₂ = 1$$

$$4c₁ + 2c₂ = 3.$$

将 f(n) 同时除以 n 和 f(n − 1) 恰好给出了我们可以使用的有用模式。f(n)/n = (n + 1)/2，且 f(n)/f(n − 1) = (n + 1)/(n − 1)。当然，很多其他对函数 g 的猜测都不起作用。例如，f(n) − n = f(n − 1)。知道 f(n) = f(n − 1) + n 对于确定该求和的闭式解没有用处。或者考虑 f(n) − f(n − 1) = n。同样，知道 f(n) = f(n − 1) + n 没有用处。找到正确的方程组合可能就像在大海捞针一样。

在我们的第一个例子中，我们可以直接看出闭式解应该是什么。由于 f(n)/n = (n + 1)/2，显然 f(n) = n(n + 1)/2。

除以 f(n − 1) 并没有给出如此明显的结果，但它提供了另一个有用的说明。

```
f(n)/f(n − 1) = (n + 1)/(n − 1)
f(n)(n − 1) = (n + 1)f(n − 1)
f(n)(n − 1) = (n + 1)(f(n) − n)
nf(n) − f(n) = nf(n) + f(n) − n² − n
2f(n) = n² + n = n(n + 1)
f(n) = n(n + 1)/2
```

一次又一次，我们仍然没有证明 f(n) = n(n + 1)/2。为什么？因为我们没有证明 f(n)/n = (n + 1)/2 也没有证明 f(n)/f(n − 1) = (n + 1)/(n − 1)。我们只是通过观察几个项假设了模式。幸运的是，用归纳法检验我们的假设很容易。

### Example 14.2

求解求和

$$\sum_{i=1}^{n} \frac{1}{2^{i}}.$$

我们将通过列出求和的前几个值来开始，看看是否能检测到模式。

| n | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| f(n) | 1/2 | 3/4 | 7/8 | 15/16 | 31/32 | 63/64 |
| 1 − f(n) | 1/2 | 1/4 | 1/8 | 1/16 | 1/32 | 1/64 |

通过直接检查表格的第二行，我们可能会认识到模式 f(n) = (2^{n} − 1)/2^{n}。然后一个简单的归纳证明可以证明这始终成立。或者，考虑如果我们没有注意到 f(n) 形式的模式。我们可能会观察到 f(n) 似乎正在趋向于一的渐近线。在这种情况下，我们可能会考虑查看 f(n) 与预期渐近线之间的差异。该结果显示在表格的最后一行，其中有一个清晰的模式，因为第 i 项为 1/2^{i}。从中我们可以很容易地推断出猜测 f(n) = 1 − 1/2^{n}。同样，一个简单的归纳证明将验证该猜测。

### Example 14.3

求解求和

$$f(n) = \sum_{i=0}^{n} a r^{i} = a + ar + ar^{2} + \cdots + ar^{n}.$$

这称为几何级数。我们的目标是找到某个函数 g(n)，使得 f(n) 与 g(n) 之间的差给我们一个易于处理的方程。因为求和的连续项相差一个因子 r，所以如果我们将整个表达式乘以 r，我们就可以移动项：

$$r f(n) = r \sum_{i=0}^{n} a r^{i} = ar + ar^{2} + ar^{3} + \cdots + ar^{n+1}.$$

我们现在可以按如下方式从一个方程中减去另一个方程：

$$f(n) - r f(n) = a + ar + ar^{2} + ar^{3} + \cdots + ar^{n} - (ar + ar^{2} + ar^{3} + \cdots + ar^{n}) - ar^{n+1}.$$

结果只剩下端项：

$$f(n) - r f(n) = \sum_{i=0}^{n} a r^{i} - r \sum_{i=0}^{n} a r^{i}$$

$$(1 - r) f(n) = a - a r^{n+1}.$$

因此，我们得到结果

$$f(n) = \frac{a - a r^{n+1}}{1 - r}$$

其中 r ≠ 1。

### Example 14.4

对于移动方法的第二个例子，我们求解

$$f(n) = \sum_{i=1}^{n} i 2^{i} = 1 \cdot 2^{1} + 2 \cdot 2^{2} + 3 \cdot 2^{3} + \cdots + n \cdot 2^{n}.$$

如果我们乘以二，我们就可以实现我们的目标：

$$2f(n) = 2 \sum_{i=1}^{n} i 2^{i} = 1 \cdot 2^{2} + 2 \cdot 2^{3} + 3 \cdot 2^{4} + \cdots + (n - 1) \cdot 2^{n} + n \cdot 2^{n+1}.$$

2f(n) 的第 i 项为 i · 2^{i+1}，而 f(n) 的第 (i + 1) 项为 (i + 1) · 2^{i+1}。从一个表达式中减去另一个表达式会得到 2^{i} 的和以及一些未抵消的项：

$$2f(n) - f(n) = 2 \sum_{i=1}^{n} i 2^{i} - \sum_{i=1}^{n} i 2^{i} = \sum_{i=1}^{n} i 2^{i+1} - \sum_{i=1}^{n} i 2^{i}.$$

将 i 的值在第二个求和中平移，将 i + 1 代替 i：

$$= n 2^{n+1} + \sum_{i=0}^{n-1} i 2^{i+1} - \sum_{i=0}^{n-1} (i + 1) 2^{i+1}.$$

将第二个求和分为两部分：

$$= n 2^{n+1} + \sum_{i=0}^{n-1} i 2^{i+1} - \sum_{i=0}^{n-1} i 2^{i+1} - \sum_{i=0}^{n-1} 2^{i+1}.$$

抵消相似项：

$$= n 2^{n+1} - \sum_{i=0}^{n-1} 2^{i+1}.$$

再次将 i 的值在求和中平移，将 i 代替 (i + 1)：

$$= n 2^{n+1} - \sum_{i=1}^{n} 2^{i}.$$

用我们已知的解替换新的求和：

$$= n 2^{n+1} - (2^{n+1} - 2).$$

最后，重新整理方程：

$$= (n - 1) 2^{n+1} + 2.$$

## 14.2 递推关系

递推关系通常用于模拟递归函数的成本。例如，标准归并排序（第 7.4 节）将大小为 n 的列表分成两半，对每一半执行归并排序，最后以 n 步合并两个子列表。其成本可以建模为

$$T(n) = 2T(n/2) + n$$

换句话说，算法在大小为 n 的输入上的成本是大小为 n/2 的输入成本的两倍（由于对归并排序的两次递归调用）加上 n（合并子列表所需的时间）。

求解递推关系的方法有很多，这里我们简要考虑三种。第一种是估计技术：猜测递推的上界和下界，用归纳法证明界限，并在需要时收紧。第二种方法是展开递推，将其转换为求和，然后使用求和技术。第三种方法是当递推具有合适的形式时，利用已证明的定理。特别是，像归并排序这样的典型分治算法会产生一种适合我们已有现成解的模式的形式的递推。

### 14.2.1 估计上界和下界

求解递推的第一种方法是猜测答案然后尝试证明其正确。如果给出正确的上界或下界估计，一个简单的归纳证明将验证这一事实。如果证明成功，则尝试收紧界限。如果归纳证明失败，则放宽界限并重试。一旦上界和下界匹配，你就完成了。这是一种有用的技术，当你只寻找渐近复杂度时。当寻求精确的闭式解（即你寻求表达式的常数）时，这种方法可能工作量太大。
