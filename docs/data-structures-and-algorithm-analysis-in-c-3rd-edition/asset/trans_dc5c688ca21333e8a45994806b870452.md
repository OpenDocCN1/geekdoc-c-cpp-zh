F(I) = YES ⇔ L(I') = ACCEPT.

也就是说，如果判定问题 F 对输入 I 给出 YES，则存在一个包含字符串 I' 的语言 L，其中 I' 是输入 I 的某种合适变换。反之，如果 F 对输入 I 的答案为 NO，则 I 的变换版本 I' 不在语言 L 中。

图灵机是编写语言接受程序的计算的简单模型。存在一台“通用”图灵机，它可以将图灵机的描述和输入字符串作为输入，并返回该机器对该字符串的执行。该图灵机反过来可以被表述为一个布尔表达式，使得该表达式可满足当且仅当图灵机对该字符串给出 ACCEPT。Cook 在他的证明中使用图灵机，因为它们足够简单，他能够开发图灵机到布尔表达式的这种变换，但又足够强大，可以计算常规计算机可以计算的任何函数。这种变换的意义在于，任何可由图灵机执行的判定问题都可以变换为 SAT。因此，SAT 是 NP-难的。

如上所述，要证明判定问题 X 是 NP-完全的，我们证明 X 在 NP 中（通常很容易，通常通过给出合适的多项式时间、非确定性算法来完成），然后证明 X 是 NP-难的。要证明 X 是 NP-难的，我们选择一个已知的 NP-完全问题，比如 A。我们描述一个多项式时间变换，将 A 的任意实例 I 变换为 X 的实例 I'。我们然后描述一个从 SLN' 到 SLN 的多项式时间变换，使得 SLN 是 I 的解。下面的例子为如何进行 NP-完全性证明提供了一个模型。

B 可满足当且仅当 G 具有大小为 k 或更大的团。B 可满足意味着存在一个真值赋值使得对每个 i 至少有一个文字 y[i,jᵢ] 为真。如果是这样，则这些 m 个文字必须对应于大小为 k = m 的团中的 m 个顶点。反之，如果 G 具有大小为 k 或更大的团，则该团的大小必须恰好为 k（因为同一子句对应的两个顶点不能在团中），并且团中对每个 i 都有一个顶点 v[i,jᵢ]。存在一个使每个 y[i,jᵢ] 为真的真值赋值。该真值赋值满足 B。

我们得出结论 K-CLIQUE 是 NP-难的，因此是 NP-完全的。□

## 17.2.3 Coping with 𝒩𝒫-Complete Problems

发现你的问题是 𝒩𝒫-完全的并不意味着你就可以完全忘记它。旅行商需要找到合理的销售路线，无论问题的复杂性如何。当面对必须解决的 𝒩𝒫-完全问题时，你该怎么办？

有几种技术可以尝试。一个方法是只运行问题的少量实例。对于某些问题，这是不可以接受的。例如，TRAVELING SALESMAN 增长得如此之快，以至于在现代计算机上无法对超过 30 个城市的问题规模运行，这对于现实生活中的情况来说并不是不合理的问题规模。然而，𝒩𝒫 中的某些其他问题，虽然需要指数时间，但增长得足够慢，以至于允许对有用规模的问题求解。

考虑第 16.1.1 节中的 Knapsack 问题。我们有一个动态规划算法，其成本为 Θ(nK)，用于将 n 个物品装入大小为 K 的背包。但事实证明 Knapsack 是 𝒩𝒫-完全的。这不是矛盾吗？当我们考虑 n 和 K 之间的关系时，就不是了。K 有多大？输入大小通常为 O(n lg K)，因为物品大小小于 K。因此，Θ(nK) 在输入大小上是指数的。

该动态规划算法在数字“合理”时是可处理的。也就是说，当 nK 在数千范围内时，我们可以成功找到问题的解。这种算法称为伪多项式时间算法。这与 TRAVELING SALESMAN 不同，后者在 n = 100 时在当前算法下不可能被求解。

处理 𝒩𝒫-完全问题的第二种方法是求解问题的特殊实例，该实例并不那么困难。例如，许多图上的问题是 𝒩𝒫-完全的，但在某些受限类型的图上，相同问题并不那么困难。例如，虽然 VERTEX COVER 和 K-CLIQUE 问题在一般情况下是 𝒩𝒫-完全的，但在二分图（即其顶点可以分为两个子集，使得其中一个子集内的任意一对顶点之间没有边）上存在多项式时间解。2-SATISFIABILITY（其中布尔表达式中的每个子句最多包含两个文字）具有多项式时间解。几个几何问题在二维中只需要多项式时间，但在三维或更高维度中是 𝒩𝒫-完全的。KNAPSACK 被认为在数字（和 K）“很小”时运行在多项式时间内。这里的小是指它们关于物品数量 n 是多项式的。
