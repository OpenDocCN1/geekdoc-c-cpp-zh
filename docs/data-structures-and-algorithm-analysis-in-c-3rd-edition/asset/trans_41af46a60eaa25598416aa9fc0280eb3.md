

## 3.6 分析问题

你通常使用“算法”分析技术来分析一个算法，或者算法实例化为程序后的情况。你也可以用同样的技术来分析一个问题的代价。应该说，一个问题的上界不可能比我们所知的该问题最佳算法的上界更差，这是合理的。但给出一个问题的下界意味着什么呢？

考虑对于某个给定问题的某个算法，在所有规模为 n 的输入上的代价图。定义 A 为求解该问题的所有算法的集合（理论上，这样的算法有无穷多个）。现在，考虑 A 中所有（无穷多个）算法的所有图。最坏情况下的下界是所有图中所有最高点中的最小值。

证明一个算法（或程序）属于 Ω(f(n)) 比证明一个问题属于 Ω(f(n)) 要容易得多。一个问题属于 Ω(f(n)) 意味着所有求解该问题的算法都属于 Ω(f(n))，甚至包括那些我们尚未想到的算法！

到目前为止，我们所有的算法分析示例给出的都是“显而易见”的结果，大O总是与 Ω 匹配。要理解如何正确使用大O、Ω 和 Θ 记号来描述我们对问题或算法的理解，最好考虑一个你对该问题还不甚了解的示例。

让我们前瞻性地分析排序问题，看看这一过程是如何运作的。在最坏情况下，任何排序算法的最小可能代价是多少？算法至少必须检查输入中的每个元素，才能确定输入确实是有序的。因此，任何排序算法至少要花费 c n 的时间。对于许多问题，这种“每个 n 个输入都必须被检查”的观察结果会带来一个简单的 Ω(n) 下界。

在你之前学习计算机科学的过程中，你可能见过一个在最坏情况下运行时间为 O(n²) 的排序算法示例。通常在大一编程课程中作为示例的简单冒泡排序和插入排序算法，其最坏情况运行时间都在 O(n²)。因此，可以说排序问题的上界是 O(n²)。我们如何弥合 Ω(n) 和 O(n²) 之间的差距？有没有更好的排序算法？如果你想不出任何最坏情况增长率优于 O(n²) 的算法，并且你也找不到任何分析技术来证明排序问题在最坏情况下的最小代价大于 Ω(n)，那么你就无法确定是否存在更好的算法。

第 7 章介绍了一些在最坏情况下运行时间为 O(n log n) 的排序算法。这大大缩小了差距。有了这一新知识，我们现在有了 Ω(n) 的下界和 O(n log n) 的上界。我们是否应该寻找更快的算法？许多人尝试过，但都没有成功。幸运的是（或者也许是不幸的是？），第 7 章还包含一个证明，证明任何排序算法在最坏情况下的运行时间都必须在 Ω(n log n)。² 这个证明是算法分析领域最重要的成果之一，它意味着对于规模为 n 的最坏情况输入，任何排序算法都不可能比 c n log n 更快。因此，我们可以得出结论，排序问题在最坏情况下是 Θ(n log n)，因为上下界已经相遇。

知道一个问题的下界并不会给你一个好算法。但它确实能帮助你知道何时该停止寻找。如果问题的下界与算法的上界匹配（在常数因子内），那么我们就知道，我们所能找到的更好算法也仅仅是在常数因子上有所改进。

## 3.7 常见的误解

渐近分析是计算机科学专业本科生所面临的最具智力挑战性的主题之一。大多数人觉得增长率和渐近分析令人困惑，因此对概念或术语产生误解。了解这些常见的困惑点有助于避免它们。

区分上界和下界概念的一个问题是，对于你遇到的大多数算法，很容易识别该算法的真实增长率。如果对代价函数有完整的了解，那么该代价函数的上界和下界总是相同的。因此，上界和下界之间的区别只有在你对所测量的对象了解不完整时才有价值。如果这个区别仍然不清楚，请重新阅读第 3.6 节。我们使用 Θ 记号来表示我们所知道的上界和下界的增长率之间没有有意义的差异（对于简单算法通常如此）。

一个常见的错误是混淆上界或下界的概念与最坏情况或最好情况的概念。最好、最坏或平均情况各自给出了一个具体的输入实例（或具体的实例集合），我们可以将其应用于算法描述以获得代价度量。上界和下界描述的是我们对该代价度量增长率的理解。因此，要定义算法或问题的增长率，我们需要确定我们在测量什么（最好、最坏或平均情况），以及我们对该代价度量增长率的描述（大O、Ω 或 Θ）。

算法的上界并不等同于该算法在给定输入规模 n 下的最坏情况。被限定的并不是实际代价（你可以针对给定的 n 值确定它），而是代价的增长率。对于单个点（例如某个特定的 n 值）不存在增长率。增长率适用于代价随输入规模变化而发生的变化。同样，下界也不等同于给定规模 n 下的最好情况。

另一个常见的误解是认为算法的最好情况发生在输入规模尽可能小的时候，或者最坏情况发生在输入规模尽可能大的时候。正确的说法是，对于每一种可能的输入规模，都存在最好和最坏情况的实例。也就是说，对于给定规模（比如 i）的所有输入，规模为 i 的输入中有一个（或多个）是最好情况，有一个（或多个）是最坏情况。通常（但并非总是如此！），我们可以刻画任意规模下的最好输入情况和最坏输入情况。理想情况下，随着输入规模的增长，我们可以确定所刻画的最好、最坏和平均情况的增长率。

### 示例 3.14

顺序查找的最好情况增长率是多少？对于任何大小为 n 的数组，最好情况发生在我们查找的值出现在数组第一个位置的时候。无论数组大小如何，这都是成立的。因此，最好情况（对于任意规模 n）发生在目标值位于 n 个位置中的第一个位置时，其代价为 1。说最好情况发生在 n = 1 时是不正确的。
