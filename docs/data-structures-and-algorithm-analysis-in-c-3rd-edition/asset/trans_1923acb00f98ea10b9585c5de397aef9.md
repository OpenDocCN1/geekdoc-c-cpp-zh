### 图4.7 使用头结点时链表的初始状态。

链表类的大多数成员函数的实现都很直接。然而，`insert` 和 `remove` 需要仔细研究。

插入一个新元素是一个三步过程。首先，创建新的链表结点并将新元素存储其中。其次，将新链表结点的 `next` 字段设置为指向当前结点（即 `curr` 所指向的结点之后的那个结点）。第三，将 `curr` 所指向结点的 `next` 字段设置为指向新插入的结点。图4.8中 `insert` 方法中的一行代码完成了上述所有三个步骤。

```cpp
curr->next = new Link<E>(it, curr->next);
```

`new` 运算符创建新链表结点并调用 `Link` 类的构造函数，该构造函数有两个参数。第一个是元素，第二个是要放入链表结点 `next` 字段中的值，此处为 `curr->next`。图4.9展示了这一三步过程。一旦新结点被添加，如果新元素被添加到了链表末尾，`tail` 会向后移动。插入操作需要 Θ(1) 时间。

从链表中删除一个结点，只需要将相应的指针重新指向待删除结点的下一个结点。图4.8中 `remove` 方法中的以下几行正是这样做的。

```cpp
Link<E>* ltemp = curr->next;   // Remember link node
curr->next = curr->next->next; // Remove from list
```

我们必须小心不要“丢失”被删除链表结点的内存。因此，先将临时指针 `ltemp` 指向被删除的结点，随后调用 `delete` 将该旧结点归还给自由存储区。图4.10演示了 `remove` 方法。假设自由存储区的 `delete` 运算符需要常数时间，则删除一个元素需要 Θ(1) 时间。

`next` 方法只是将 `curr` 向链表尾部移动一个位置，耗时 Θ(1) 时间。`prev` 方法将 `curr` 向链表头部移动一个位置，但实现起来更加困难。在单向链表中，没有指向前一个结点的指针。因此，唯一的选择是从链表头开始向下遍历，直到到达当前结点（务必始终记住它前面的结点，因为那才是我们真正需要的）。平均和最坏情况下需要 Θ(n) 时间。`moveToPos` 方法的实现类似，因为查找第 i 个位置需要从链表头向下移动 i 个位置，耗时 Θ(i) 时间。

其余操作的实现各需 Θ(1) 时间。

### 图4.8 链表实现。

```cpp
// Linked list implementation
template <typename E> class LList: public List<E> {
private:
    Link<E>* head;        // Pointer to list header
    Link<E>* tail;        // Pointer to last element
    Link<E>* curr;        // Access to current element
    int cnt;              // Size of list

    void init() {         // Initialization helper method
        curr = tail = head = new Link<E>();
        cnt = 0;
    }

    void removeall() {    // Return link nodes to free store
        while(head != NULL) {
            curr = head;
            head = head->next;
            delete curr;
        }
    }

public:
    LList(int size=defaultSize) { init(); }      // Constructor
    ~LList() { removeall(); }                    // Destructor
    void print() const;                          // Print list contents
    void clear() { removeall(); init(); }        // Clear list

    // Insert "it" at current position
    void insert(const E& it) {
        curr->next = new Link<E>(it, curr->next);
        if (tail == curr) tail = curr->next;  // New tail
        cnt++;
    }

    void append(const E& it) { // Append "it" to list
        tail = tail->next = new Link<E>(it, NULL);
        cnt++;
    }

    // Remove and return current element
    E remove() {
        Assert(curr->next != NULL, "No element");
        E it = curr->next->element;      // Remember value
        Link<E>* ltemp = curr->next;     // Remember link node
        if (tail == curr->next) tail = curr; // Reset tail
        curr->next = curr->next->next;   // Remove from list
        delete ltemp;                    // Reclaim space
        cnt--;                           // Decrement the count
        return it;
    }

void moveToStart() // Place curr at list start
    { curr = head; }

void moveToEnd()    // Place curr at list end
    { curr = tail; }

// Move curr one step left; no change if already at front
void prev() {
    if (curr == head) return;        // No previous element
    Link<E>* temp = head;
    // March down list until we find the previous element
    while (temp->next!=curr) temp=temp->next;
    curr = temp;
}

// Move curr one step right; no change if already at end
void next()
    { if (curr != tail) curr = curr->next; }

int length() const { return cnt; } // Return length

// Return the position of the current element
int currPos() const {
    Link<E>* temp = head;
    int i;
    for (i=0; curr != temp; i++)
        temp = temp->next;
    return i;
}

// Move down list to "pos" position
void moveToPos(int pos) {
    Assert ((pos>=0)&&(pos<=cnt), "Position out of range");
    curr = head;
    for(int i=0; i<pos; i++) curr = curr->next;
}

const E& getValue() const { // Return current element
    Assert(curr->next != NULL, "No value");
    return curr->next->element;
}
};
```

## 空闲列表

C++ 的自由存储区管理运算符 `new` 和 `delete` 使用起来相对昂贵。12.3节讨论了通用内存管理器是如何实现的。这种开销源于以下事实：自由存储区例程必须能够处理无特定模式的自由存储区分配和释放请求，以及大小差异巨大的内存请求。这使得它们与为更受控制的内存访问模式而可能实现的例程相比效率较低。

链表实现中，链表结点被创建和删除的方式允许 `Link` 类的程序员提供简单而高效的内存管理例程。`Link` 类不必反复调用 `new` 和 `delete`，而是可以管理自己的空闲列表。空闲列表保存当前未被使用的链表结点。当一个结点从链表中删除时，它会被放到空闲列表的头部。当要向链表添加新元素时，会检查空闲列表，看是否有可用的链表结点。如果有，则从空闲列表中取出该结点。如果空闲列表为空，就必须调用标准的 `new` 运算符。

空闲列表对于周期性增长然后收缩的链表特别有用。空闲列表的大小永远不会超过链表迄今为止达到的最大规模。（链表收缩后）对新结点的请求可以由空闲列表来处理。另一个使用空闲列表的好时机是程序使用多个链表时。只要这些链表不是同时增长和收缩，空闲列表就可以让链表结点在链表之间移动。

实现空闲列表的一种方法是创建两个新运算符，用以替代标准的自由存储区例程 `new` 和 `delete`。这要求用户代码（例如图4.8中的链表类实现）被修改为调用这些空闲列表运算符。第二种方法是使用 C++ 运算符重载，在操作 `Link` 类对象时替换 `new` 和 `delete` 的含义。这样，使用 `LList` 类的程序完全不需要修改即可利用空闲列表。`Link` 类是使用空闲列表实现，还是依赖常规的自由存储区机制，对于列表类的用户来说完全是透明的。图4.11展示了用空闲列表方法重载标准自由存储区运算符后 `Link` 类的重新实现。注意它们多么简单，因为它们只需要分别从空闲列表头部删除元素和向空闲列表头部添加元素。`new` 和 `delete` 的空闲列表版本都在 Θ(1) 时间内运行，但在空闲列表耗尽而必须调用 `new` 操作的情况下除外。在我的计算机上，调用重载的 `new` 和 `delete` 运算符所需时间大约是对应系统自由存储区运算符所需时间的十分之一。
