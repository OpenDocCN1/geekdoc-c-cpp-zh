本节介绍计算机科学中最重要和最有用的证明之一：任何基于键比较的排序算法在最坏情况下都不可能比 Ω(n log n) 更快。该证明重要有三个原因。首先，知道广泛使用的排序算法在渐近意义上是最优的，这令人安心。特别是，这意味着你不必撞墙去寻找 O(n) 排序算法（或者至少不是以任何方式基于键比较的）。其次，该证明是我们对任何问题所拥有的少数非平凡下界证明之一；也就是说，该证明提供了相对较少的实例，其中我们的下界比仅仅测量输入和输出的大小更紧。作为这样，它为证明其他问题的下界提供了一个有用的模型。最后，知道排序的下界也为其他问题的下界提供了依据，这些问题的解决方案可用于排序算法的基础。从一个问题的渐近界导出另一个问题的渐近界的过程称为归约，这一概念在第 17 章中进一步探讨。

除了 Radix Sort 和 Binsort 之外，本章介绍的所有排序算法都基于对两个键值的直接比较做出决策。例如，Insertion Sort 依次比较要插入到已排序列表中的值，直到与列表中的下一个值的比较失败。在对比之下，Radix Sort 没有键值的直接比较。所有决策都基于键值中特定数字的值，因此可以采用不涉及键比较的排序方法。当然，Radix Sort 最终并没有提供比基于比较的排序更高效的排序算法。因此，经验证据表明基于比较的排序是一种良好的方法。³

任何比较排序都需要 Ω(n log n) 次比较在最坏情况下的证明结构如下。首先，基于比较的决策可以建模为树中的分支。这意味着任何基于记录之间比较的排序算法都可以视为一棵二叉树，其节点对应于比较，其分支对应于可能的结果。接下来，证明了所得树中叶子的最小数量为 n 的阶乘。最后，证明了具有 n! 个叶子的树的最小深度在 Ω(n log n) 中。

在给出排序 Ω(n log n) 下界的证明之前，我们首先必须定义决策树的概念。决策树是二叉树，可以对任何做出二进制决策的算法的处理进行建模。每个（二进制）决策由树中的一个分支表示。为了对排序算法建模，我们将所有键值的比较都计为决策。如果两个键进行比较且第一个小于第二个，则在决策树中建模为左分支。在第一个值大于第二个值的情况下，算法取右分支。

当 n = 3 时，Insertion Sort 做的第一次比较是在输入数组中第二个项（Y）和数组中第一个项（X）之间。有两种可能性：要么 Y 的值小于 X 的值，要么 Y 的值不小于 X 的值。该决策由树中的第一个分支建模。如果 Y 小于 X，则应取左分支，并且 Y 必须出现在最终输出中 X 之前。只有原始六个排列中的三个具有此属性，因此根的左子节点列出 Y 出现在 X 之前的三个排列：YXZ、YZX 和 ZYX。同样，如果 Y 不小于 X，则会取右分支，并且只有 Y 出现在 X 之后的三个排列才是可能的结果：XYZ、XZY 和 ZXY。这些列在根的右子节点中。

对于 $n$ 个值的任何基于比较的排序算法，决策树中必须有多少个叶子的最小数量？由于排序算法的任务是确定输入对应的唯一排列与已排序列表相对应，任何排序算法的决策树必须为每个可能的排列包含至少一个叶节点。对于 $n$ 个数字的集合，存在 $n!$ 个排列（参见第 2.2 节）。

由于树中至少有 $n!$ 个叶子，我们知道树必须具有 $\Omega(\log n!)$ 个层级。根据 Stirling 近似（第 2.2 节），我们知道 $\log n!$ 在 $\Omega(n \log n)$ 中。任何基于比较的排序算法的决策树必须具有 $\Omega(n \log n)$ 个层级。因此，在最坏情况下，任何此类排序算法必须需要 $\Omega(n \log n)$ 次比较。

任何在最坏情况下需要 $\Omega(n \log n)$ 次比较的排序算法在最坏情况下需要 $\Omega(n \log n)$ 运行时间。由于任何排序算法都需要 $\Omega(n \log n)$ 运行时间，排序问题也需要 $\Omega(n \log n)$ 时间。我们已经知道具有 $O(n \log n)$ 运行时间的排序算法，因此我们可以得出结论，排序问题需要 $\Theta(n \log n)$ 时间。作为推论，我们知道没有基于比较的排序算法可以比现有的 $\Theta(n \log n)$ 时间排序算法改进超过常数因子。

## 7.10 Further Reading

排序的权威参考是 Donald E. Knuth 的 *Sorting and Searching* [Knu98]。其中涵盖了大量细节，包括小规模 $n$ 的最优排序和专用排序网络。这是对排序的彻底（尽管有些过时）处理。关于 Quicksort 的分析及其优化的全面调查，请参阅 Robert Sedgewick 的 *Quicksort* [Sed80]。Sedgewick 的 *Algorithms* [Sed11] 讨论了这里描述的大多数排序算法，并特别关注高效实现。第 7.4 节的优化 Mergesort 版本来自 Sedgewick。

虽然 $\Omega(n \log n)$ 是排序在最坏情况下的理论下界，但很多时候输入足够有序，以至于某些算法可以利用这一事实来加快排序过程。一个简单的例子是 Insertion Sort 的最佳情况运行时间。运行时间基于输入无序程度的排序算法称为 **adaptive**。有关自适应排序算法的更多信息，请参阅 Estivill-Castro 和 Wood 的“A Survey of Adaptive Sorting Algorithms” [ECW92]。
