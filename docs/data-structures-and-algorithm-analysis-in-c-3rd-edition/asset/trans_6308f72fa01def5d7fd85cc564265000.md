## 3 算法分析

我们完成计划的合并后，处理公司工资单需要多长时间？我应该从 X 供应商还是 Y 供应商购买新的工资单程序？如果某个程序运行缓慢，是实现不当还是它在解决一个难题？诸如此类的问题要求我们考虑问题的难度，或解决同一问题的两种或多种方法的相对效率。

本章介绍算法分析的动机、基本符号和基本技术。我们重点关注一种称为渐近算法分析，或简称为渐近分析的方法。渐近分析试图估计算法的资源消耗。它使我们能够比较解决同一问题的两种或多种算法的相对成本。渐近分析还为算法设计者提供了一个工具，在他们实际实现程序之前，估计所提出的解决方案是否可能满足问题的资源限制。阅读本章后，你应该理解

- 增长率的概念，即算法的成本随输入规模增大而增长的速率；
- 增长率的上界和下界的概念，以及如何为简单程序、算法或问题估计这些界；以及
- 算法（或程序）的成本与问题的成本之间的区别。

本章最后简要讨论了在经验上测量程序成本时遇到的实际困难，以及改进程序效率的代码调优原则。

### 如何根据效率比较解决某个问题的两种算法？

我们可以将两种算法都实现为计算机程序，然后在合适的输入范围内运行它们，测量每个程序使用的问题资源的多少。这种方法通常不令人满意，有四个原因。首先，编程和测试两种算法的工作量很大，而最好时你只想保留其中一种。其次，在经验上比较两种算法时，总是存在一种程序“写得更好”而另一种不是的风险，因此底层算法的相对质量并不能真正由其实现所代表。当程序员对算法有偏见时，这很容易发生。第三，经验测试用例的选择可能会不公平地偏向一种算法。第四，你可能会发现即使是两种算法中较好的一种也不在你的资源预算之内。在这种情况下，你必须用另一个实现新算法的程序重新开始整个过程。但是，你如何知道任何算法能否满足资源预算？也许问题本身对任何实现来说都太困难而无法在预算内完成。

这些问题通常可以通过使用渐近分析来避免。渐近分析衡量算法的效率，或其作为程序的实现，随着输入规模变大。它实际上是一种估计技术，并不能告诉我们关于两种程序的相对优点，其中一个程序总是“稍微快一点”。然而，渐近分析已被计算机科学家证明是有用的，他们必须确定特定算法是否值得考虑实现。

程序的关键资源最常是其运行时间。然而，你不能只关注运行时间。你还必须关心诸如运行程序所需的空间（包括主内存和磁盘空间）等其他因素。通常你会分析算法（或算法在程序形式中的实例化）所需的时间，以及数据结构所需的空间。

许多因素影响程序的运行时间。有些与程序编译和运行的环境有关。此类因素包括计算机 CPU、总线和外围硬件的速度。与其他用户竞争计算机（或网络）的资源可能会使程序运行缓慢。编程语言和特定编译器生成的代码质量可能有显著影响。程序员将算法转换为程序的“编码效率”也可能产生巨大影响。
