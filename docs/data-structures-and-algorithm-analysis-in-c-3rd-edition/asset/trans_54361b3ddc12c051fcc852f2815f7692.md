
还有哪些观察方法可以进一步加速？即使我们确实找到了一种快速求值多个点的方法，我们仍然需要对这些 2n − 1 个值进行插值，以恢复 AB 的系数。

因此，如果能够找到一种快速的方法对 2n − 1 个点进行求值/插值，我们就可以用少于 Θ(n²) 次操作完成两个多项式的乘法。在进一步考虑如何实现这一点之前，首先再次观察多项式在取值 c 和 −c 处的求值关系。一般地，我们可以将 Pₐ(x) 写成 Pₐ(x) = Eₐ(x) + Oₐ(x)，其中 Eₐ 是偶次幂部分，Oₐ 是奇次幂部分。因此，

```
Pₐ(x) = Σᵢ₌₀^{n/2−1} a₂ᵢ x²ⁱ + Σᵢ₌₀^{n/2−1} a₂ᵢ₊₁ x²ⁱ⁺¹
```

其意义在于，当对 c 和 −c 这一对值进行求值时，我们有

```
Eₐ(c) + Oₐ(c) = Eₐ(c) − Oₐ(−c)
Oₐ(c) = −Oₐ(−c)
```

因此，我们只需计算 E 和 O 一次，而不是两次，就能得到两个求值结果。

快速多项式乘法的关键在于找到合适的求值/插值点，以使过程高效。特别地，我们希望利用对称性，比如求值 x 和 −x 时所见的那种。但如果想要做的不仅仅是减少一半工作量，我们就需要在点之间找到更多的对称性。我们不仅要找到值对之间的对称性，还要找到值对之值对之间的进一步对称性，然后是值对之值对之值对之间的对称性，依此类推。

回忆一下，复数 z 有实部和虚部。如果用 y 维度表示虚部，我们就可以在坐标平面上考虑 z 的位置。现在，我们将定义 z 为 n 次本原单位根，如果满足：

- 1. zⁿ = 1，且
- 2. 对于 0 < k < n，zᵏ ≠ 1。

z⁰, z¹, ..., zⁿ⁻¹ 被称为 n 次单位根。例如，当 n = 4 时，z = i 或 z = −i。一般地，我们有恒等式 e^{iπ} = −1 和 zʲ = e^{2πij/n} = (−1)^{2j/n}。其意义在于，我们可以在单位圆上找到任意所需数量的点（见图 16.6）。但这些点很特殊，因为它们使我们能够完成恰好所需的计算，以获得必要的对称性，从而加速同时求值多个点的整体过程。

下一步是定义计算的具体方式。定义一个 n × n 矩阵 A_z，其第 i 行第 j 列为

```
A_z = (z^{ij}).
```

![](img/7ea3c39173f146f675b63b146d1535f3_556_0.png)

图 16.6 4 次和 8 次单位根的示例。

其思想是，每个根对应一行（第 i 行对应 z^i），而列对应于多项式中 x 的指数幂。例如，当 n = 4 时，z = i。于是，A_z 数组如下所示。

```
A_z = 
1   1   1   1
1   i  -1  -i
1  -1   1  -1
1  -i  -1   i
```

令 a = [a0, a1, ..., a_{n-1}]^T 是一个存储待求值多项式系数的向量。然后，我们可以通过将 A_z 矩阵乘以系数向量，来计算多项式在 n 次单位根处的值。得到的向量 F_z 被称为该多项式的离散傅里叶变换。

```
F_z = A_z a = b.

b_i = sum_{k=0}^{n-1} a_k z^{i k}.
```

当 n = 8 时，z = sqrt(i)，因为 sqrt(i)^8 = 1。因此，相应的矩阵如下。

```
A_z = 
1   1   1   1   1   1   1   1
1   sqrt(i)   i   i sqrt(i)  -1  -sqrt(i)  -i  -i sqrt(i)
1   i  -1  -i   1   i  -1  -i
1   i sqrt(i)  -i   sqrt(i)  -1  -i sqrt(i)   i  -sqrt(i)
1  -1   1  -1   1  -1   1  -1
1  -sqrt(i)   i  -i sqrt(i)  -1   sqrt(i)  -i   i sqrt(i)
1  -i  -1   i   1  -i  -1   i
1  -i sqrt(i)  -i  -sqrt(i)  -1   i sqrt(i)   i   sqrt(i)
```

我们仍然有两个问题。我们需要能够比执行标准矩阵-向量乘法更快地完成这个矩阵与向量的乘法，

因此，使用傅里叶变换将多项式 A 和 B 相乘的完整过程如下。

- 将一个 n−1 次多项式表示为 2n−1 个系数：

  `[a0, a1, ..., a_{n−1}, 0, ..., 0]`

- 对 A 和 B 的表示执行傅里叶变换

- 将结果逐对相乘，得到 2n−1 个值。

## 计算的极限

本书描述了可用于各种各样问题的数据结构，以及许多高效算法的示例。一般来说，我们的查找算法力求在最坏情况下以 O(log n) 的时间找到一条记录，排序算法力求达到 O(n log n)。少数算法的渐近复杂度更高。Floyd 所有点对最短路径算法和标准矩阵乘法都有 Θ(n³) 的运行时间（尽管两者的处理数据量都是 Θ(n²)）。

我们能够高效地解决许多问题，是因为我们拥有（并且选择使用）高效的算法。对于任何你知道某种算法的问题，总是可以编写一个低效的算法来“解决”该问题。例如，考虑一种排序算法，它测试输入的每一种可能排列，直到找到能够给出有序列表的正确排列。该算法的运行时间将是不可接受地高，因为它与排列的数量成正比，对于 n 个输入，这个数量是 n!。在解决最小代价生成树问题时，如果我们测试边集的每一种可能子集以找出哪个构成最短的最小生成树，那么对于具有 |E| 条边的图，工作量将与 2^{|E|} 成正比。幸运的是，对于这两个问题，我们都有更巧妙的算法，可以在不显式测试每一种可能解的情况下（相对）快速地找到答案。

不幸的是，有许多计算问题的可能最优算法也需要很长的运行时间。一个简单的例子是汉诺塔问题，它需要移动 2ⁿ 次才能“解决”一个 n 个圆盘的塔。任何求解汉诺塔问题的计算机程序都不可能在少于 Ω(2ⁿ) 的时间内运行，因为必须打印出那么多移动步骤。

除了那些解决方案必须花费很长运行时间的问题之外，还有许多问题我们根本不知道是否存在高效算法。对于这类问题，我们所知道的最佳算法非常慢，但也许还有更好的算法等待我们去发现。当然，虽然问题运行时间高很糟糕，但问题完全无法解决则更糟糕！这类问题确实存在，将在第 17.3 节中讨论。
