
将之后的前 n + 1 个位置向上移动。为了实现这一点，插入例程首先将 V 放在数组的第 n 个位置。当然，V 不太可能处于正确的位置。为了将 V 移动到正确的位置，需要将其与父节点的值进行比较。如果 V 的值小于或等于其父节点的值，那么它就处于正确的位置，插入例程结束。如果 V 的值大于其父节点的值，则交换这两个元素的位置。此后，将 V 与其当前父节点进行比较的过程会一直持续，直到 V 到达正确的位置。

由于堆是完全二叉树，其高度保证为最小可能值。特别地，包含 n 个节点的堆的高度为 Θ(log n)。直观上，我们可以看出这是必然的，因为我们每增加一层，树中节点的数量就会略微增加一倍以上（第 i 层有 2^i 个节点，前 i 层的节点总数是 2^{i+1} − 1）。从 1 开始，我们只能倍增 log n 次才能达到 n。精确地说，包含 n 个节点的堆的高度为 ⌈log(n + 1)⌉。

每次调用 insert 在最坏情况下耗时 Θ(log n)，因为被插入的值最多可以从树的底部移动到树顶。因此，如果逐个将 n 个值插入堆中，最坏情况下将耗时 Θ(n log n)。

buildHeap 的代价是多少？显然，它是各次向下筛选调用代价的总和。每次向下筛选操作的开销至多等于被筛选节点到达树底所需的层数。在任何完全树中，大约一半的节点是叶子，因此完全不能向下移动。四分之一的节点位于叶子上方一层，因此它们的元素至多可以向下移动一层。每向树上走一步，节点数是上一层的一半，而高度额外增加一。因此，元素可以移动的总距离的最大和为

```
∑_{i=1}^{log n} (i - 1) n / 2^i = n/2 ∑_{i=1}^{log n} i - 1 / 2^{i-1}.
```

由公式 2.9 可知，这个求和有一个近似为 2 的闭式解，因此该算法在最坏情况下耗时 Θ(n)。这比逐个构建堆要好得多，后者在最坏情况下需花费 Θ(n log n)。它也快于构建 BST（二叉搜索树）所需的平均情况时间 Θ(n log n) 和最坏情况时间 Θ(n²)。

从包含 n 个元素的堆中移除最大值（根值）要求我们保持完全二叉树的形状，并让剩余的 n − 1 个节点值符合堆的性质。我们可以通过将堆中最后一个位置上的元素（数组中当前的最后一个元素）移动到根的位置来保持正确的形状。现在我们认为堆的大小减少了一个。不幸的是，新的根值很可能不是新堆中的最大值。这个问题很容易通过使用向下筛选来重新调整堆而解决。因为堆有 log n 层深，删除最大元素的代价在平均和最坏情况下都是 Θ(log n)。

堆是本节开头讨论的优先队列的一种自然实现。需要时可以将作业添加到堆中（使用其优先级值作为排序键）。每当要执行一个新作业时，就可以调用 removemax 方法。

优先队列的某些应用要求能够改变已存储在队列中的对象的优先级。这可能要求更新该对象在堆表示中的位置。不幸的是，最大堆在搜索任意值时并不高效；它只擅长寻找最大值。然而，如果我们已知堆中某个对象的索引，那么更新其优先级（包括改变其位置以维持堆的性质）或移除它都是简单的事情。remove 方法将待移除节点在堆中的位置作为输入。对于需要更新优先级的优先队列，典型实现需要使用一个支持高效搜索对象的辅助数据结构（如 BST）。辅助数据结构中的记录会存储对象的堆索引，以便将该对象从堆中删除，并以新的优先级重新插入（参见项目 5.5）。第 11.4.1 节和第 11.5.1 节介绍了需要更新优先级的优先队列的应用。

## 5.6 哈夫曼编码树

第 3.9 节中的空间/时间权衡原则指出，我们常常可以通过牺牲运行时间来换取空间需求的改善。在许多情况下，这种权衡是可取的。一个典型的例子是将文件存储在磁盘上。如果文件不经常使用，其所有者可能希望压缩文件以节省空间。之后，当需要使用文件时，可以将其解压缩，这虽然会花费一些时间，但只发生一次。

我们经常通过为每个项目分配唯一代码来表示计算机程序中的一组项目。例如，标准 ASCII 编码方案为每个字符分配一个唯一的八位值。要为每个字符提供唯一代码，需要一定的最小位数。例如，需要 ⌈log 128⌉ 即七位，才能为 ASCII 字符集的 128 个符号提供所需的 128 个唯一代码。⁵

用 ⌈log n⌉ 位表示 n 个唯一代码值的要求假设所有代码都等长，就像 ASCII 码一样。这被称为定长编码方案。如果所有字符的使用频率相同，那么定长编码方案是空间效率最高的方法。然而，你可能已经意识到，在许多应用中，并非所有字符的使用频率都相同。例如，英文文档中的各个字母在使用频率上差异很大。
