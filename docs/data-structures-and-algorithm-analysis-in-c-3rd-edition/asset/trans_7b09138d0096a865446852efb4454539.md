对于其他应用——特别是当我们希望汇总程序在许多不同的输入上多次运行的成本时——最坏情况分析可能不是算法性能的代表性度量。通常我们更希望知道平均情况下的运行时间。这意味着我们希望了解算法在大小为 n 的输入上的典型行为。不幸的是，平均情况分析并不总是可能的。平均情况分析首先要求我们了解程序的实际输入（及其成本）相对于程序所有可能输入的集合是如何分布的。例如，先前提到过，顺序搜索算法平均会检查数组值的一半。这只有在值为 K 的元素在数组中的任何位置出现的可能性相等时才成立。如果该假设不成立，则算法在平均情况下不一定会检查数组值的一半。有关数据分布对顺序搜索算法的影响的进一步讨论，请参阅第 9.2 节。

数据分布的特征对许多搜索算法有显著影响，例如基于哈希的算法（第 9.4 节）和搜索树（例如参见第 5.4 节）。对数据分布的错误假设会对程序的空间或时间性能造成灾难性后果。不寻常的数据分布也可以被利用，如第 9.2 节所示。

总之，对于实时应用，我们可能会更倾向于对算法进行最坏情况分析。否则，如果我们足够了解输入的分布以计算平均情况，我们通常希望进行平均情况分析。如果不是这样，则必须求助于最坏情况分析。

## 3.3 更快的计算机，还是更快的算法？

假设你有一个问题需要解决，并且你知道一种算法，其运行时间与 n² 成正比。不幸的是， resulting 程序运行时间长了十倍。如果你用一台快十倍的新计算机替换当前计算机，n² 算法会变得可以接受吗？如果问题规模保持不变，那么更快的计算机也许能让你即使使用增长速率较高的算法也能足够快地完成工作。但大多数人得到更快的计算机后会发生一件有趣的事情。他们不会更快地运行相同的问题。他们运行更大的问题！假设在你的旧计算机上，你满足于对 10,000 条记录进行排序，因为这可以在午餐休息时间内完成。在你的新计算机上，你可能希望在相同时间内对 100,000 条记录进行排序。你不会比以前更早回到午餐，所以你最好解决一个更大的问题。由于新机器快十倍，你希望排序的记录数是原来的十倍。

|---|---|---|---|---|
| 10n | 1000 | 10,000 | n' = 10n | 10 |
| 20n | 500 | 5000 | n' = 10n | 10 |
| 5n log n | 250 | 1842 | √10n < n' < 10n | 7.37 |
| 2n² | 70 | 223 | n' = √10n | 3.16 |

如果你的算法的增长率是线性的（即描述输入规模为 n 时运行时间的方程为 T(n) = cn，其中 c 为常数），那么在新机器上对 100,000 条记录的排序所需时间与在旧机器上对 10,000 条记录的排序所需时间相同。如果算法的增长率大于 cn，例如 c1n²，那么在快十倍的机器上，你将无法在相同时间内完成十倍规模的问题。

在给定时间内，更快的计算机能解决多大的问题？假设新机器比旧机器快十倍。假设旧机器一小时内可以解决规模为 n 的问题。新机器一小时内能解决的最大问题是什么？图 3.3 显示了在两台机器上对图 3.1 中的五个运行时间函数可以解决的问题有多大。

该表说明了许多重要点。前两个方程都是线性的；只有常数因子的值发生了变化。在这两种情况下，快十倍的机器使问题规模增加了十倍。换句话说，虽然常数的值会影响在固定时间内可以解决的问题的绝对规模，但它并不影响通过更快的计算机获得的问题规模改善（相对于原始规模的比例）。这种关系无论算法的增长率如何都成立：常数因子永远不会影响通过更快的计算机获得的相对改善。

时间方程为 T(n) = 2n² 的算法从更快的机器上获得的改善远不如线性增长率的算法那么大。改善不是十倍，而是其平方根：√10 ≈ 3.16。因此，增长率更高的算法不仅在给定时间内首先解决的问题更小，而且从更快的计算机中获得的速度提升也更少。随着计算机变得越来越快，问题规模之间的差距变得越来越大。

增长率 T(n) = 5n log n 的算法改善程度大于二次增长率的算法，但不如线性增长率的算法那么大。

请注意，在运行时间呈指数增长的算法的情况下会发生一些特殊情况。在图 3.1 中，时间与 2^n 成正比的算法的曲线上升得非常快。在图 3.3 中，在快十倍的机器上问题规模的增加显示约为 n + 3（准确地说，是 n + log₂ 10）。对于指数增长率的算法，问题规模的增加是以常数加法而不是乘法因子进行的。因为旧的 n 值为 13，所以新的问题规模为 16。如果明年你再买一台快十倍的计算机，那么这台新计算机（比原始计算机快 100 倍）只能运行规模为 19 的问题。如果你有第二个程序，其增长率也是 2^n，并且原始计算机一小时内可以运行规模为 1000 的问题，那么快十倍的机器一小时内只能运行规模为 1003 的问题！因此，指数增长率与图 3.3 中显示的其他增长率有根本的不同。这种差异的重要性将在第 17 章中探讨。

与其购买更快的计算机，不如考虑如果你用运行时间与 n² 成正比的算法替换为运行时间与 n log n 成正比的新算法会发生什么。在图 3.1 的图中，固定时间量将显示为一条水平线。如果用于解决问题的可用时间线位于所讨论的两个增长率曲线的交点之上，则运行时间增长较慢的算法更快。运行时间 T(n) = n² 的算法对于输入规模 n = 1024 需要 1024 × 1024 = 1,048,576 个时间步。运行时间 T(n) = n log n 的算法对于输入规模 n = 1024 需要 1024 × 10 = 10,240 个时间步，与运行时间 T(n) = n² 的算法相比，改善了远不止十倍。因为当 n > 58 时 n² > 10n log n，所以如果本例中典型问题规模大于 58，则你最好更换算法而不是购买一台快十倍的计算机。此外，当你购买更快的计算机时，增长率更慢的算法在可以在新计算机上在一定时间内运行的更大问题规模方面提供了更大的好处。
