void binsort(E A[], int n) {
    List<E> B[MaxKeyValue];
    E item;
    for (int i=0; i<n; i++) B[A[i]].append(getKey::key(A[i]));
    for (int i=0; i<MaxKeyValue; i++)
        for (B[i].setStart(); B[i].getValue(item); B[i].next())

}

## 图 7.16 扩展的 Binsort 算法。

这里键值用于确定记录在最终排序数组中的位置。这是 Binsort 的最基本示例，其中键值用于将记录分配到桶中。该算法极其高效，无论键的初始顺序如何，时间均为 Θ(n)。这比我们迄今为止看到的任何排序算法的性能都要好。唯一的问题是该算法用途有限，因为它仅适用于从 0 到 n − 1 的数字的排列。

我们可以将这个简单的 Binsort 算法扩展使其更有用。由于 Binsort 必须对键值进行直接计算（与我们之前的排序算法只是询问哪两个记录在前不同），我们将假设记录使用整数键类型。我们进一步假设它可以使用模板参数类 getKey 提供的 key 方法从记录中提取出来。

最简单的扩展是允许键值之间存在重复值。这可以通过将数组槽位变成任意长度的桶来实现，即将 B 变成链表数组。这样，所有键值为 i 的记录都可以放在桶 B[i] 中。第二个扩展允许键范围大于 n。例如，n 个记录的集合可能具有 1 到 2n 的键。唯一的要求是每个可能的键值在 B 中都有对应的桶。扩展的 Binsort 算法如图所示 7.16。

此版本的 Binsort 可以对键值落在 0 到 MaxKeyValue−1 范围内的任何记录集合进行排序。所需总工作量只是将每个记录放入适当桶中然后取出记录所需的工作量。因此，我们需要处理每个记录两次，工作量为 Θ(n)。

不幸的是，这一分析中存在一个关键的疏忽。Binsort 还必须查看每个桶以查看是否包含记录。算法必须处理 MaxKeyValue 个桶，而不管实际有多少桶包含记录。如果 MaxKeyValue 相对于 n 很小，则这不是很大的开销。假设 MaxKeyValue = n²。在这种情况下，完成的总工作量将为 Θ(n + n²) = Θ(n²)。这导致了一个糟糕的排序算法，并且随着 n 与 MaxKeyValue 之间差异的增大，算法会变得更糟。此外，

## 图 7.17 十二个十进制基数中两位数基数排序的示例。

需要两次遍历来对列表进行排序。

一个较大的键范围需要一个不可接受的大数组 B。因此，即使是扩展的 Binsort 也仅适用于有限的键范围。

对 Binsort 的进一步推广产生了桶排序。每个桶与不仅仅一个键值相关联，而是与一组键值相关联。桶排序将记录分配到桶中，然后依靠某种其他排序技术对每个桶内的记录进行排序。希望相对廉价的桶分配过程只会在每个桶中放置少量记录，然后在桶内的“清理排序”就会相对便宜。

有一种方法可以在保持桶的数量和相关处理很小的同时，使清理排序基于 Binsort。考虑键在 0 到 99 范围内的记录序列。如果我们有十个桶可用，我们可以首先通过取其键值模 10 来将记录分配到桶中。因此，每个键都将被分配到与其最右边的十进制数字匹配的桶中。然后我们可以按顺序从这些桶中取出这些记录，并根据其最左边的（十位）数字重新分配到桶中（将 0 到 9 范围内的值定义为最左边的数字为 0）。换句话说，使用公式 A[i]/10 将第 i 个记录从数组 A 分配到桶中。如果我们现在按顺序从桶中收集值，结果就是一个已排序的列表。图 7.17 说明了这一过程。

```
template <typename E, typename getKey>
void radix(E A[], E B[],
    int n, int k, int r, int cnt[]) {
    // cnt[i] stores number of records in bin[i]
    int j;

    for (int i=0, rtoi=1; i<k; i++, rtoi*=r) { // For k digits
        for (j=0; j<r; j++) cnt[j] = 0;            // Initialize cnt

        // Count the number of records for each bin on this pass
        for (j=0; j<n; j++) cnt[(getKey::key(A[j])/rtoi)%r]++;

        // Index B: cnt[j] will be index for last slot of bin j.
        for (j=1; j<r; j++) cnt[j] = cnt[j-1] + cnt[j];

        // Put records into bins, work from bottom of each bin.
        // Since bins fill from bottom, j counts downwards
        for (j=n-1; j>=0; j--)
            B[--cnt[(getKey::key(A[j])/rtoi)%r]] = A[j];

        for (j=0; j<n; j++) A[j] = B[j];    // Copy B back to A
    }
}
```

## 图 7.18 基数排序算法。

在此示例中，我们有 r = 10 个桶和 n = 12 个键，范围为 0 到 r² − 1。总计算量为 Θ(n)，因为我们以恒定次数查看每个记录和每个桶。这相对于简单的 Binsort 来说是一个巨大的改进，在简单的 Binsort 中，桶的数量必须与键范围一样大。请注意，示例使用 r = 10 以便使桶计算易于可视化：记录首先基于最右边的十进制数字，然后基于最左边的十进制数字放置到桶中。任何数量的桶都可以使用。这是一个基数排序的示例，因此得名，因为桶计算基于键值的基数或基数。该排序算法可以扩展到任何数量的键和任何键范围。我们只需根据键的数字值从最右边的数字到最左边的数字将记录分配到桶中。如果有 k 个数字，则需要 k 次将键分配到桶中。

与归并排序一样，基数排序的高效实现实现起来有些困难。特别是，我们希望对值数组进行排序，避免处理链表。如果我们知道每个桶中会有多少个值，则可以使用大小为 r 的辅助数组来保存桶。例如，如果在第一次遍历中，0 桶将接收三个记录，1 桶将接收五个记录，那么我们可以简单地为 0 桶预留前三个数组位置，为 1 桶预留接下来的五个数组位置。图 7.18 中的 C++ 实现正是采用了这种方法。在每次遍历结束时，记录会被复制回原始数组。
