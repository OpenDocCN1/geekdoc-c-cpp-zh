
```cpp
// Return the minimum and maximum values in A
// between positions l and r
template <typename E>
void MinMax(E A[], int l, int r, E& Min, E& Max) {
    if (l == r) {        // n=1
        Min = A[r];
        Max = A[r];
    }
    else if (l+1 == r) { // n=2
        Min = min(A[l], A[r]);
        Max = max(A[l], A[r]);
    }
    else {              // n>2
        int Min1, Min2, Max1, Max2;
        int mid = (l + r)/2;
        MinMax(A, l, mid, Min1, Max1);
        MinMax(A, mid+1, r, Min2, Max2);
        Min = min(Min1, Min2);
        Max = max(Max1, Max2);
    }
}
```

**图 15.3** 查找数组中最小值和最大值的递归算法。

例如，如果列表中有六个元素会怎样？如果我们将列表分成两个各含三个元素的子列表，代价为 8。如果将列表分成一个大小为 2 的子列表和另一个大小为 4 的子列表，则代价仅为 7。

采用分治法时，最好的算法是使工作量最小的算法，而不一定是平衡输入规模的算法。从这个例子中可以学到的一点是，关注 n 较小时的情况可能很重要，因为对列表的任意划分最终都会产生许多小列表。

我们可以用以下递推式来建模该问题的所有可能分治策略。

```
T(n) = { 0                     n = 1
         1                     n = 2
         min_{1 ≤ k ≤ n-1} { T(k) + T(n - k) } + 2   n > 2 }
```

也就是说，我们希望找到一种拆分列表的方法，使总工作量最小。如果我们考察拆分小列表的各种方式，最终会认识到，将列表拆分为一个大小为 2 的子列表和一个大小为 n − 2 的子列表，其结果总是不亚于任何其他拆分方式。这一策略产生了以下递推式。

```
T(n) = { 0          n = 1
         1          n = 2
         T(n - 2) + 3   n > 2 }
```

这个递推式（以及相应的算法）得到 T(n) = ⌈3n/2⌉ − 2 次比较。这是最优的吗？现在我们为下界证明技术库引入又一个工具：状态空间证明。

我们将通过定义算法在任意时刻必须处于的状态来对算法建模。然后我们可以定义起始状态、终止状态以及任何算法所能支持的状态之间的转换。由此，我们将推理算法从起始状态到终止状态必须经过的最少状态数，从而得到状态空间下界。

在任意给定时刻，我们可以跟踪以下四类元素：

- 未测试：尚未被测试的元素。
- 胜者：至少赢过一次且从未输过的元素。
- 败者：至少输过一次且从未赢过的元素。
- 中间者：既赢过也输过至少一次的元素。

我们将当前状态定义为一个四元组 (U, W, L, M)，分别表示未测试、胜者、败者和中间者的数量。对于包含 n 个元素的集合，算法的初始状态为 (n, 0, 0, 0)，终止状态为 (0, 1, 1, n − 2)。因此，任何算法的每次运行都必须从状态 (n, 0, 0, 0) 到达状态 (0, 1, 1, n − 2)。我们还注意到，一旦某个元素被识别为中间者，就可以忽略它，因为它既不可能是最小值也不可能是最大值。

考虑到有四类元素，共有 10 种比较类型。与中间者进行比较不可能比其他比较更高效，因此我们应该忽略这些，剩下六种值得关注的比较。我们可以枚举每种比较类型的效果如下。如果我们处于状态 (i, j, k, l) 并进行一次比较，状态变化如下。

| 比较 | 状态变化 (i, j, k, l) |
|---|---|
| U : U | (i − 2, j + 1, k + 1, l) |
| W : W | (i, j − 1, k, l + 1) |
| L : L | (i, j, k − 1, l + 1) |
| L : U | (i − 1, j + 1, k, l) 或 (i − 1, j, k, l + 1) |
| W : U | (i − 1, j, k + 1, l) 或 (i − 1, j, k, l + 1) |
| W : L | (i, j, k, l) 或 (i, j − 1, k − 1, l + 2) |

现在，让我们考虑对手会对各种比较采取什么行动。对手会确保每次比较在使算法接近目标状态方面所做的工作量尽可能少。例如，将胜者与败者进行比较没有价值，因为最坏情况下的结果总是学不到任何新东西（胜者仍然是胜者，败者仍然是败者）。因此，只有以下五种转换值得关注：

| 比较 | 状态变化 (i, j, k, l) |
|---|---|
| U : U | (i − 2, j + 1, k + 1, l) |
| L : U | (i − 1, j + 1, k, l) |
| W : U | (i − 1, j, k + 1, l) |
| W : W | (i, j − 1, k, l + 1) |
| L : L | (i, j, k − 1, l + 1) |

只有最后两种转换类型会增加中间者的数量，因此必须有 n − 2 次这样的转换。未测试元素的数量必须变为 0，而第一种转换是实现这一点的最有效方式。因此，需要 ⌈n/2⌉ 次这样的转换。我们的结论是，可能的最小转换（比较）次数为 n + ⌈n/2⌉ − 2。因此，我们的算法是最优的。

## 15.6 查找第 i 个最佳元素

我们现在着手解决在列表中查找第 i 个最佳元素的问题。如前所述，一种解决方案是对列表排序，然后直接查看第 i 个位置。然而，这个过程提供了比解决问题所需多得多的信息。我们实际需要知道的最少信息可以如图 15.4 所示。

![](img/7ea3c39173f146f675b63b146d1535f3_525_0.png)

**图 15.4** 表示确定列表中第 i 个元素所需最少信息的偏序集。我们需要知道哪个元素有 i − 1 个值小于它、n − i 个值大于它，但我们不需要知道小于或大于第 i 个元素的那些元素之间的关系。

也就是说，我们只需要知道小于目标值的 i − 1 个元素，以及大于目标值的 n − i 个元素。我们不关心上组和下组内部的相对顺序。那么，我们能否比先排序更快地找到所需信息？再看看下界，我们能否将其收紧到超越 n 次比较的平凡下界？我们将专注于查找中位数元素（即排名为 n/2 的元素）这一具体问题，因为所得算法可以很容易地修改为查找任意 i 的第 i 个最大值。

回顾快速排序算法可能会给我们解决中位数问题带来一些启发。回想一下，快速排序的工作原理是选择一个枢轴值，将数组划分为小于枢轴的元素和大于枢轴的元素，并将枢轴移动到数组中的适当位置。如果枢轴位于位置 i，那么我们就完成了。如果不是，我们可以只考虑其中一个子列表来递归地解决子问题。也就是说，如果枢轴最终位于位置 k > i，那么我们只需在左分区中查找第 i 个最佳元素即可解决。如果枢轴位于位置 k < i，那么我们希望查找右分区中的第 i − k 个元素。

这个算法的最坏情况代价是多少？与快速排序一样，如果枢轴是数组中的第一个或最后一个元素，我们会得到糟糕的性能。这可能导致 O(n²) 的性能。然而，如果枢轴总是能将数组对半切分，那么我们的代价可以用递推式 T(n) = T(n/2) + n = 2n 或 O(n) 来建模。

要计算平均代价，我们需要使用一个带完整历史的递推式，类似于我们用于建模快速排序代价的递推式。如果我们这样做，将会发现在平均情况下 T(n) 为 O(n)。

是否有可能修改我们的算法以获得最坏情况下的线性时间？要做到这一点，我们需要选择一个能保证丢弃固定比例元素的枢轴。我们不能仅仅随机选择枢轴，因为这样做无法满足这一保证。理想情况是每次都能选择中位数值作为枢轴。但这本质上正是我们一开始试图解决的问题。

然而，请注意，如果我们选择任意常数 c，然后从大小为 n/c 的样本中选取中位数，那么我们可以保证至少丢弃 n/2c 个元素。实际上，我们可以做得更好：选择一些大小恒定的小子集（这样我们可以在常数时间内找到每个子集的中位数），然后取这些中位数的中位数。图 15.5 说明了这一思想。

![](img/7ea3c39173f146f675b63b146d1535f3_526_0.png)

![](img/7ea3c39173f146f675b63b146d1535f3_526_1.png)

**图 15.5** 一种为列表分区寻找枢轴的方法，该方法保证每个分区中至少包含列表的一个固定比例。我们将列表分成每组五个元素的组，并找出每组的中位数。然后递归地找出这 n/5 个中位数的中位数。五个元素的中位数保证每个分区中至少有两个元素。从 15 个元素的集合中取三个中位数的中位数，保证每个分区中至少有五个元素。

这一观察直接引出以下算法。

- 从列表中选择每组五个元素的 n/5 个中位数。选择五个元素的中位数可以在常数时间内完成。
- 递归地选择 M，即 n/5 个五元素组中位数的中位数。
- 将列表分区为比 M 大和比 M 小的元素。
