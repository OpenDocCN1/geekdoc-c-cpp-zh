## 索引

许多大规模计算应用都围绕着无法全部装入主内存的数据集。经典的例子是一个包含多条搜索键的大型记录数据库，需要具备插入、删除和搜索记录的能力。对于这种情况，散列提供了出色的性能，但仅限于所有搜索都是“查找键值为K的记录”这种形式的有限情形。许多应用需要更通用的搜索能力。一个例子是范围查询，搜索所有键位于某个范围内的记录。其他查询可能涉及按键值顺序访问所有记录，或查找键值最大的记录。散列表的组织方式无法高效支持这些查询中的任何一种。

本章介绍用于组织存储在磁盘上的大量记录的文件结构。此类文件结构支持高效的插入、删除和搜索操作，适用于精确匹配查询、范围查询以及最大/最小键值搜索。

在讨论此类文件结构之前，我们必须熟悉一些基本的文件处理术语。按录入顺序存储的文件（entry-sequenced file）按照记录添加到文件的顺序存储记录。按录入顺序存储的文件相当于磁盘上的未排序列表，因此不支持高效搜索。自然的解决方案是按搜索键的顺序对记录进行排序。然而，一个典型的数据库，例如企业维护的员工或客户记录集合，可能包含多个搜索键。要回答关于某个特定客户的问题，可能需要按客户姓名进行搜索。企业通常希望按邮政编码顺序对记录进行排序并输出，以便批量邮寄。政府文书工作可能需要按社会安全号码进行搜索的能力。因此，可能不存在存储记录的单一“正确”顺序。

索引是将键与相应数据记录的位置关联起来的过程。第8.5节讨论了关键字排序的概念，其中创建了一个索引文件，其记录由键/指针对组成。在这里，每个键都与指向主数据库文件中一条完整记录的指针相关联。索引文件可能需要按社会安全号码进行搜索的能力。因此，可能不存在存储记录的单一“正确”顺序。
