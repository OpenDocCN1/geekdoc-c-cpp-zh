```
E find(const Key& k) const {
    SkipNode<Key,E> *x = head;            // Dummy header node
    for (int i=level; i>=0; i--)
        while ((x->forward[i] != NULL) &&
               (k > x->forward[i]->k))
            x = x->forward[i];
    x = x->forward[0]; // Move to actual record, if it exists
    if ((x != NULL) && (k == x->k)) return x->it;
    return NULL;
}
```

```
void insert(const Key& k, const E& it) {
    int i;
    SkipNode<Key,E> *x = head;      // Start at header node
    int newLevel = randomLevel(); // Select level for new node
    if (newLevel > level) {        // New node is deepest in list
        AdjustHead(newLevel);      // Add null pointers to header
        level = newLevel;
    }
    SkipNode<Key,E>* update[level+1]; // Track level ends
    for(i=level; i>=0; i--) {   // Search for insert position
        while((x->forward[i] != NULL) && (x->forward[i]->k < k))
            x = x->forward[i];
        update[i] = x;              // Keep track of end at level i
    }
    x = new SkipNode<Key,E>(k, it, newLevel);   // New node
    for (i=0; i<=newLevel; i++) {   // Splice into list
        x->forward[i] = update[i]->forward[i]; // Where x points
        update[i]->forward[i] = x;             // What points to x
    }
    recount++;
}
```

### 图 16.4 跳跃表插入函数的实现。

图 16.2(c) 中的理想跳跃表经过精心组织，使得（如果不计算第一个和最后一个节点）一半的节点只有一个指针，四分之一有 2 个指针，八分之一有 3 个指针，依此类推。指针间距相等；实际上这是一个“完美平衡”的跳跃表。在正常的插入和删除过程中维持这种平衡代价高昂。跳跃表的关键在于我们完全不必担心这些。每当插入一个节点时，我们为其分配一个层级（即一定数量的指针）。分配是随机的，采用几何分布：节点有 50% 的概率拥有一个指针，25% 的概率拥有两个指针，依此类推。下面的函数基于这种分布确定层级：

```
// Pick a level using an exponential distribution
int randomLevel(void) {
    int level = 0;
    while (Random(2) == 0) level++;
    return level;
}
```

一旦确定了节点的适当层级，下一步就是找到该节点应插入的位置，并在其所有层级上适当地将其链接进去。图 16.4 展示了向跳跃表插入一个新值的实现。

### 图 16.5 跳跃表插入的示意图。

(a) 在第 1 层插入初始值 10 后的跳跃表。(b) 在第 0 层插入值 20 后的跳跃表。(c) 在第 0 层插入值 5 后的跳跃表。(d) 在第 3 层插入值 2 后的跳跃表。(e) 在第 2 层插入值 30 后的最终跳跃表。

接下来，插入值 20。假设这次 `randomLevel` 返回 0。查找过程到达值为 10 的节点，新节点插入其后，如图 16.5(b) 所示。第三个插入的节点值为 5，同样假设 `randomLevel` 返回 0。这得到图 16.5(c) 中的跳跃表。第四个插入的节点值为 2，假设 `randomLevel` 返回 3。这意味着跳跃表的层级必须升高，导致头节点额外增加两个 (NULL) 指针。此时，新节点被添加到列表前端，如图 16.5(d) 所示。最后，在第 2 层插入一个值为 30 的节点。这次，让我们仔细看看 `update` 数组的用途。它在查找新节点正确位置的过程中，存储每一层所能到达的最远节点。查找过程从头节点的第 3 层开始，前进到存储值 2 的节点。由于该节点的 `forward[3]` 为 NULL，在这一层无法继续前进。因此，`update[3]` 存储指向值为 2 的节点的指针。同样，在第 2 层也无法继续前进，所以 `update[2]` 也存储指向值为 2 的节点的指针。在第 1 层，我们前进到值为 10 的节点。这是第 1 层能到达的最远位置，因此 `update[1]` 存储指向值为 10 的节点的指针。最后，在第 0 层我们到达值为 20 的节点。此时，可以将新节点（值为 30）插入。对于每个下标 i，新节点的 `forward[i]` 指针被设置为 `update[i]->forward[i]`，同时 `update[i]` 中下标 0 到 2 所指向的节点的 `forward[i]` 指针被改为指向新节点。这样就将新节点在所有层级上“拼接”到了跳跃表中。

删除函数留作练习。它与插入类似，区别在于查找待删除记录的过程中构建 `update` 数组。然后，由 `update` 数组指定的那些节点调整其 `forward` 指针，使其绕过被删除的节点。

新插入的节点可能由 `randomLevel` 生成一个较高的层级，也可能是一个较低层级。跳跃表中可能存在大量节点拥有多个指针，导致不必要的插入开销，并在查找时产生较差的（即 Θ(n)）性能，因为跳过的节点不多。反过来，也可能有太多节点的层级过低。在最坏情况下，所有节点都在第 0 层，相当于普通链表。如果是这样，查找同样需要 Θ(n) 时间。然而，性能较差的概率非常低。连续 10 个节点都在第 0 层的概率仅为 1/1024。像跳跃表这样的概率数据结构的口号是：“别担心，要开心。”我们只需接受 `randomLevel` 的结果，并相信概率最终会站在我们这一边。这种方法的优点是算法简单，同时平均情况下所有操作只需要 Θ(log n) 时间。

实际上，跳跃表的性能很可能优于二叉搜索树 (BST)。BST 可能因数据插入顺序而导致性能不佳。例如，如果 n 个节点按键值升序插入 BST，那么 BST 将看起来像一个链表，最深节点的深度为 n−1。跳跃表的性能不依赖于值插入列表的顺序。随着跳跃表中节点数量的增加，遇到最坏情况的概率呈几何级数下降。因此，跳跃表体现了理论最坏情况（在此例中跳跃表操作为 Θ(n)）与平均情况性能 Θ(log n) 的概率迅速增加之间的张力，这正是概率数据结构的特征。

## 16.3 数值算法

本节介绍与数值数学计算相关的多种算法。例如两个数相乘或对一个数求给定次幂。我们特别关注内置整数或浮点运算无法使用的情形，因为所操作的值太大。对多项式或矩阵进行运算时也会出现类似的考虑。

由于我们不能依赖硬件在常数时间内一次性处理输入，我们需要考虑如何最有效地实现运算以最小化时间成本。这引出一个问题：我们应该如何应用通常的以输入规模增长率衡量的渐近代价？首先，加法或乘法的实例是什么？操作数的每个值都构成一个不同的实例。两个数相乘时输入规模又是什么？如果我们将输入规模视为 2（因为输入了两个数），那么任何非常数时间算法的增长率相对于输入的增长都是无限高的。这没有意义，尤其考虑到我们从小学算术中就知道，随着所涉及数值的增大，加法或乘法确实会变得更困难。事实上，我们从标准的学校算法中知道，标准加法的代价与相加的位数成线性关系，而乘法的代价在 m 位数乘以 n 位数时为 n×m。

在执行对输入规模敏感的数值算法时，操作数的位数确实是一个关键因素。位数就是该值在适当底数下的对数。因此，为了计算算法的渐近增长率，我们将输入值的“规模”视为该值的对数。基于这一看法，这些运算有许多相关的特征。

-   大数值的算术运算并不廉价。
-   值为 n 的实例只有一个。
