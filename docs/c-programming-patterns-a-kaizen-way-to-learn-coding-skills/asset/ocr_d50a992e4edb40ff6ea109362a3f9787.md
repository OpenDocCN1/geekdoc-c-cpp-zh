If `malloc` function call is successful then pointer variable `intPtr` will hold the memory address location from the heap memory area. As an example, let us consider in this case where pointer variable `intPtr` contains memory address location **6014** and this memory address location exists on heap memory area where continuous block for **50 integers** will be get allocated. Similarly, `free(intPtr)` method call deallocates the memory.

**So, pointer variable can be made to point to memory location and in this case it is pointing to heap memory area to avail the facility of getting extra memory.** The demand for extra memory could be sufficient big and that might throw an **stackoverflow** error if requested from stack memory area. Some program may require a large piece of memory to hold a large set of data and this large data may be required to be available for a longer period of time during the execution of program. In such situations usually a continuous block of memory is allocated dynamically and also get released when it is not required. This freeing of memory gives chance to reuse the memory when requested by running program. The serious part in all these activities of allocation and freeing of memory is that it has to be done manually through programming. In case of local variables it is automated. As soon as function call ends, all local variables and function call are pop-out of the stack memory and get freed up the memory automatically.
