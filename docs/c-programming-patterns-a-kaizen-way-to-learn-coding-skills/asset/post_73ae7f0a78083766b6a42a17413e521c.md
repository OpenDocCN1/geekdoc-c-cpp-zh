
We know that a variable represents a memory location. The variables **row**, **col** and **totalRows** are local to the **main()** method. Whenever the program gets executed, it initializes these local variables and they are pushed into the **stack** memory area. These local variables which are on the **stack** are readily available to the machine code and are directly accessible. This machine code can't directly access the memory locations of a **heap** memory area. This shortcoming can be overcome by using a pointer variable which basically contains only one type of data and that is memory location. A pointer variable also resides in the stack memory area like other variables. The following programming instruction suggests that the pointer variable **intPtr** is not pointing to any memory location and a simple way to initialize any pointer variable before its actual usage.

```c
int *intPtr = NULL; // pointer variable initialized to NULL.
```

If `malloc` function call is successful then pointer variable `intPtr` will hold the memory address location from the heap memory area. As an example, let us consider in this case where pointer variable `intPtr` contains memory address location **6014** and this memory address location exists on heap memory area where a continuous block for **50 integers** will be allocated. **So, pointer variable can be made to point to memory location and in this case it is pointing to heap memory area to avail the facility of getting extra memory.** The demand for extra memory could be sufficiently big and that might throw a **stack overflow** error if requested from stack memory area. Some programs may require a large piece of memory to hold a large set of data and this large data may be required to be available for a longer period of time during the execution of program. In such situations usually a continuous block of memory is allocated dynamically and also gets released when it is not required. This freeing of memory gives a chance to reuse the memory when requested by a running program. The serious part in all these activities of allocation and freeing of memory is that it has to be done manually through programming. In case of local variables it is automated. As soon as a function call ends, all local variables and the function call are popped out of the stack memory and the memory gets freed automatically.

## Stack and function calls

Stack literally means arranging items on top of another. A pile of books as shown in the picture is an example of a stack. If we want a book from this stack, we need to start removing books from the top and then get the actual one. This is called last-in-first-out or in short LIFO method. Stack is a memory area in RAM where data are added and removed in LIFO style. When a method is called, data stored in a variable(s) is pushed onto the top of the stack and data pops out or gets removed when the execution of the called function ends.

When the swap() method's execution gets completed, the stack-frame of swap() method will pop-out or get removed from the stack memory area.

Finally, when the main() method's execution gets completed, the stack-frame of main() method will also pop-out or get removed from the stack memory area. Now, stack memory will have no stack-frames available for execution. The stack memory area is emptied and ready to be reused for the next program's execution.
