In the example, we overload the prefix ++ and postfix ++ for time increments as members of class Clock. The most important difference between the overload of the prefix operator and the postfix operator is the formal arguments of the overload functions. According to the syntax, the member function of a prefix unary operator has no formal argument, while for a postfix unary operator, an integer argument is required. The integer argument is not used in the function body. It is only for differentiating the prefix and postfix. Therefore the argument list can contain only the type name without the argument name. ## 8.2.3 Operator Overloaded as Friend Function

The operator can also be overloaded as a friend function of the class. Thus, it can freely access any data member of the class. Here, all operands need to be passed by a formal argument list. The argument order from left to right in the argument list is the order of operands.

For binary operator B, if it has an operand that is an object of class A, then B can be overloaded as a friend function of class A. The function has two formal arguments and the type of one argument is class A. After overloading, expression `oprd1 B oprd2` is equivalent to calling function `operator B(oprd1, oprd2)`.

For prefix unary operator U, e.g., "-", to realize operation `U oprd`, oprd is an object of class A, U can be overloaded as a function call of class A. The formal argument is the object `oprd` of class A. After overloading, the expression `U oprd` is equivalent to calling function `operator U(oprd)`.

For postfix ++ and --, to realize expression `oprd++` or `oprd--`, where oprd is an object of class A, the operators can be overloaded as friend functions of class A and there are two formal arguments: the second argument is to distinguish itself from prefix operators. After overloading, the expression `oprd++` and `oprd--` is equivalent to calling function `operator++(oprd, o)` and `operator--(oprd, o)`.

## 8.3 Virtual Function

In Section 7.7, we introduced a program for staff information management system. A problem remains unresolved from that example, i.e., how to utilize iteration to deal with different objects of the same. To do that, we change the main() in Example 7.10 into the following program and observe the outcome.

```cpp
#include<iostream>
#include"employee.h"
using namespace std;
int main()
{
  manager m1;
  technician t1;
  salesmanager sm1;
  salesman s1;
  employee *emp[4]={&m1,&t1,&sm1,&s1};
  // the addresses of the objects in pointer array

  int i;
  for(i=0;i<4; i++){
    emp[i]->pay();
    cout<<"employee number"<<emp[i]->GetindividualEmpNo()"current salary"<<emp[i]->GetAccumumPay()<<endl;

```

The execution result is:

| employee 1000 current salary 0 |
| employee number 1001 current salary 0 |
| employee number 1002 current salary 0 |
| employee number 1003 current salary 0 |

From the execution result, pay() in the derived classes is not executed. Readers can execute the program step-by-step and it will be clear that every time the base-class object pointer calls the derived-class member function, it actually calls the baseclass member function instead of the new function in the derived class. Function pay() in the base class does not work. To solve this problem, we can use a virtual function to implement polymorphism.

Virtual functions are the basis of dynamic binding. A virtual function must be a non-static member function. After being overloaded, the virtual function can implement the execution polymorphism in a class family.
