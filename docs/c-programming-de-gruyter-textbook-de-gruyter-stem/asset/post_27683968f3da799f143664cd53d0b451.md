The order of the catch handler is very important, because in a try block, exception handlers are checked by their appearance order. If a matched exception type is found in a catch clause, the subsequent catch clauses will be ignored. For example, the exception handling block below, catch (...) appears firstly and it can catch any exceptions. Other catch clauses will never be checked. Therefore, catch (...) should always be put last.

```cpp

{

}

{
  //handle all exceptions here
}
```

### 12.2.2 Exception Interface

To make the program readable, and to let the user know all possible exceptions that could be thrown by a function, we can list all possible exception types in the function declaration. For example,

```cpp
void func() throw(A, B, C, D);
```

indicates that func() can call and can only throw exceptions whose types are A, B, D, and their subtypes. If there is no exception declaration in the function declaration, we can throw exceptions of any type. For example,

```cpp
void func();
```

A function that doesn't throw exceptions of any type can declare as follows:

```cpp
void func() throw();
```

### 12.3 Destruction and Construction

The real capacity of exception handling in C++ lies not only its ability to handle exceptions of various types but also its ability to call destructors for all objects constructed before throwing exceptions. In a program, after a matched catch handler is found, if the exception declaration of the catch clause is a value parameter, its initialization mode is to copy the thrown object; if the exception declaration of the catch clause is a reference, its initialization mode is to make this reference point to the exception object.

After the exception type declaration are initialized, the unfolding process will begin. This contains the destruction of all automatic objects constructed (and not destroyed) from the start of the try block to the place where the exception is thrown. The order of destruction is opposite to that of construction. And the program will resume execution after the last catch handler.

### Example 12.2: Use C++ Exception Handling of Classes with Destructors

```cpp

public:
    Expt();
    ~Expt();
    const char *ShowReason() const
    {
        return "Expt is exceptional.";
    }
};
class Demo {
public:
    Demo();
    ~Demo();
};
Demo::Demo() {
    cout << "construct Demo." << endl;
}
Demo::~Demo() {
    cout << "destruct Demo." << endl;
}
void MyFunc() {
    Demo D;
    cout<<"throw exception of class in MyFunc().";
    throw Expt();
}

int main() {
  cout << "in the main function." << endl;
  try {
    cout << "call MyFunc() in the try block." << endl;
    MyFunc();
  }
  catch( Expt E ) {
    cout << "in the catch handler." << endl;
    cout << "caught exception of type: " << E << endl;
    cout << E.ShowReason() << endl;
  }
  catch( char *str) {
    cout << "caught other exceptions. " << str << endl;
  }
  cout << "return to the main function and resume execution from here" << endl;
  return 0;
}
```

The output of the program is as follows:

| in the main function. |
| call MyFunc() in the try block. |
| construct Demo. |
| throw exception of class in MyFunc(). |
| destruct Demo. |
| in the catch handler. |
| caught exception of type: Expt class is exceptional. |
| return to the main function and resume execution from here |

Note that in this example, the two catch handlers both specify exception parameters (parameters of the catch clause):

```cpp
catch( Expt E ) {
  //...
}
catch( char *str) {
  //...
}
```

In fact, we don't have to specify these parameters (E and str). In many cases, it is enough to notify the handler has an exception of a certain type. But we do need to specify parameters when accessing exception objects. Otherwise, we cannot access the object in the catch clause. For example,

```cpp
catch( Expt ) {
    //cannot access exception object here
}
```

We can throw the exception being handled currently by throw expression with operands. This expression can only appear in catch handler or the inner functions of the catch handler. The exception object being thrown is the original exception object (not a copy). For example,

```cpp
try
{
    throw SomeOtherException();
}catch(...) {
    //response to exceptions (maybe only a part)
    //...
    throw; //pass the exception to other handler
}
```
