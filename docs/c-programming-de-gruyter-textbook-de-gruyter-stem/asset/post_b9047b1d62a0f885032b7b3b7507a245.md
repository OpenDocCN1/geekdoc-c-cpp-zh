
## 128 — 4 Class & Object

```cpp
Point(Point &); //copy constructor
int GetX() { return X; }
int GetY() { return Y; }
private:
int X,Y;
```

Inline constructor and copy constructor are declared inside the class body. The copy constructor is implemented as follows:

```cpp
Point ::Point(Point &p)
{
    X=p.X;
    Y=p.Y;
    cout<<"call the copy constructor"<<endl;
}
```

Common constructors are called when the objects are created, while copy constructor would be called in any of the following three situations: 

- 1. When using an object to initialize another object of the same class. For example:

```cpp
int main() {
    Point A(1,2);
    Point B(A); //using object A to initialize object B,
    //copy constructor is called
    cout<<B.GetX()endl;
    return 0;
}
```

- 2. When calling the function and passing parameters, if the formal parameter of a function is an object of a class. For example:

```cpp
void f(Point p) {
    cout<<p.GetX()endl;
}
int main() {
    Point A(1,2);
    f(A); //parameter is an object, when calling the function,
    //constructor is called
}
```

- 3. When the function is finished and is going to return to its caller, if the return value of a function is an object of a class. For example:

```cpp
Point g() {
    Point A(1,2);
    return A; //return value is an object, when returning the value,
    //copy constructor is called
}
int main() {
    Point B;
    B=g();
}
```

In the example above, why is the copy constructor called when returning the function value? On the return, function g seems to return A to the main function. But A is a object of g() and will disappear when g terminates, and thus A cannot exist after the process returns to the main function (this will be further discussed in Chapter 5). So in this situation, the compiler will generate a temporary unnamed object in the main function, whose lifetime is only in the statement of the function call, i.e., statement 'B = g();' When executing 'return A;' the copy constructor is called to copy A as a temporary object. After function g terminates, A disappears while the temporary object exists in statement 'B = g().' After computing, this temporary object will also disappear.

**Example 4.2:** Complete program for point class.

In the main function, there are three sections that demonstrate three situations of calling a constructor, respectively.

```cpp
//4_2.cpp
#include <iostream>
using namespace std;
class Point                               //Definition of class Point
{
public:                               //external interface
    Point(int xx=0, int yy=0) : X(xx),Y(yy) {} //constructor
    Point(Point &p)                             //copy constructor
    int GetX() {return X;}
    int GetY() {return Y;}
private:
    int X,Y;                               //private data
};
//implementations of member functions
Point::Point(Point &p)
{
    X=p.X;
    Y=p.Y;
    cout<<"copy constructor is called"<<endl;
}
// function with an object of class Point as parameter
void fun1(Point p)
{ cout<<p.GetX()endl; }
// function with an object of class Point as return value
Point fun2()
{
    Point A(1,2);
    return A;
}
//main function
int main()
{
    Point A(4,5); //first object A
    Point B(A); //situation, use A to initialize B. First time to
    //call copy constructor
    cout<<B.GetX()endl;
    fun1(B); //situation, use object B as the formal parameter of
    //fun1. Second time to call copy constructor
    B=fun2(); //situation, the return value of the function is
    //an object. Call copy constructor when returning to
    //the main function
    cout<<B.GetX()endl;
}
```

Readers may wonder at how the copy constructor and default copy constructor in the example above do the same job: they both pass values in the old object directly to the new object. Why do we need to write our own copy constructor in this situation? Yes, if things always go like this, we don't have to write a copy constructor particularly; just using the default copy constructor is enough. However, remember that when we sometimes only want to copy part of a page, in which case we can use white paper to cover the unneeded part before the copying. There are many other situations, such as when we want to copy with zooming in or out, etc. Things are similar in object copying in programs, where we can copy an object according to our needs. Readers can try to modify the above example code to make the copy constructor construct a new point with a certain amount offset from the old point. Besides, when some of the data members are of pointer types, default copy constructor can only do shallow copying, which causes security problems. To achieve the correct copy, i.e., deep copy, we must write our own copy constructor. Details about pointer types and issues of deep copy will be introduced in Chapter 6. Examples in Chapter 9 will show more about deep copy.

## 4.3.3 Class Destructor

Besides is a good start, we also need a good finish. Programming also needs to consider the round-off work. In C++, when an object disappears, we often need to take care of the mop-up.

Will an object disappear? Sure! Like every thing in the world, objects in programs have their own lifetime. We already know that an object is created when it is defined, and when the object disappears involves the issues of the object's lifetime, which will be discussed in Chapter 5. Here we only consider one situation: if a local object is defined inside a function, then it will disappear when the function terminates.

What should be done when an object is going to disappear? The most classical situation is: when constructing an object, some resources are allocated by the constructor, such as dynamically allocating memory space. When the object disappears, these resources have to be released. This is reflected in Examples 7.10 in Chapter 7, in some examples in Chapter 9, and is detailed in Section 7.7 "Running Result and Analysis". Basically, a destructor does exactly the opposite of what constructor does. A destructor is called automatically when the lifetime of the object ends. Dynamic memory allocation is detailed in Chapter 6.

Generally speaking, if we want the program to do some work automatically before the object disappears (without manually calling a function), we can write the work into the destructor.

For example, we add an empty destructor to class Clock, which has the same function as the default destructor that the system generates.

```cpp
class Clock
{
public:
    Clock(); //constructor
    void SetTime(int newH, int newM, int newS);
    void ShowTime();
    ~Clock()
private:
    int Hour, Minute, Second;
};
```
