# 2. Diagram Symbols for Relationships

We have introduced the diagram representations of class and object in UML, although with these diagram symbols only, we can still describe relationships between class and class, object and object, and class and object in a large system. For example, there can inheritance relationships or calling relationships between classes, etc.

UML uses lines to represent relationships. Let's see how to use these symbols to describe the relationships in this book has mentioned, such as calling, combination of classes, inheritance, etc.

# a) Dependency

Dependency between classes or objects indicates that changes of one thing may affect another thing it uses, while it is not true for the opposite. When a class uses another class as a parameter of its function member, we use the dependency relationship. Generally, calling and friends (will be discussed in Chapter 5) between classes, and instantiation of all class belong to this kind of relationship. Simple, original dependency is sufficient in many of the situations when dependency relationship is needed.

To demonstrate the nuance of dependency meanings, UML also defined some stereotypes for dependency. The most commonly used stereotype is 'use'. When we need to represent the use of relationships between two classes, we use the stereotype <<use>>. Other stereotypes will not be detailed here, and other stereotypes will be used in latter chapters, which will be discussed then.
