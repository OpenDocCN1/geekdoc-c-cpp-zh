## 4.2.2 Access Control to Class Members

Class members include data members describing the attributes of the problem and function members describing the behaviors of the problem, which are two invisible aspects. In order to understand access control to class members, let's see the clock example again. Any clock records times and have a panel, a knob, or a button. As discussed in Section 4.1, we can abstract all these common attributes of clocks into a *Clock class*. In normal use, users can only look through the panel and adjust time using the knob or button. A fender can take the clock apart, while others have better not try. In this panel, the knob, and the button are the only ways for us to touch and use a clock. Thus we can design them as the external interfaces of the *Clock class*. The time recorded is the private member of the class, which users can only access through the external interfaces.

The access control to class members is realized by setting the access control attributes of class members. There are three kinds of access control: **public, private, and protected.**

**Public members define the external interfaces of the class.** Public members are declared by the keyword *public*. We can only access public members outside the

![](img/5618306d085ac1bac8275d6c4c5bbf2a_136_0.png)

class. For the class Clock, we can only use the public function members SetTime() and ShowTime() to adjust or display time.

Class members defined after the keyword private are private members of the class. If the private members immediately follow the class name, keyword private can be omitted. Private members can only be accessed by the member functions of the class, and any access to private members from outside of the class is illegal. Thus, protected members are completely hidden in the class, which protects the security of data. Hour, Minute, and Second in class Clock are all private members.

Protected members are like private members; the differences lie in their newly generated classes during the inheritance procedure. Chapter 7 will discuss this issue in detail.

Figure 4.1 describes the access attributes of class members visually: set the members needed to be hidden by private, make them an inaccessible black box from the outside; set interfaces provided for the outside to public, and then they are transparent to the outside; protected members are like a cage, which offer some special access attributes for derived classes.

Now imagine, if a class can neither tell the time nor adjust the time, would you like to buy it? You may say: ‘what is use it! This is like a class out of any external interface – cannot be used. So remember, designing a class is for usage, and we must design necessary external interfaces for its use.

In the definition of a class, members with different access attributes can appear in any order. The keywords to denote access attributes can also appear at any time. Each member can only have one access attribute. For example, the following definition of class Clock is also:

```
class Clock
{
public:
    void SetTime(int NewH, int NewM, int NewS);
private:
    int Hour,Minute, Second;
public:
    void ShowTime();
};
```

Generally we put public members in the front when writing a class definition. This is easy to read, because public members are what need to be known when the outside needs to access the class. In general, all the data members of a class should be declared as private, and thus the internal structure won't affect the outside of the class, and the mutual influences between program modules can be minimized.

## 4.2.3 Member Function of Class

Member functions of a class describe the behaviors of the class, such as the function members SetTime() and ShowTime() of class Clock. Member functions implement the program algorithm and are the methods used to process the encapsulated data.

## 1. Declaration and Implementation of Member Functions

The function prototype should be defined in the class body. A function prototype describes the parameter list and the return type of the function. The implementation of the function is written outside the class body. Different from ordinary functions, a member function should specify its class name when it is implemented. The implementation is:

```
Return Type _ ClassName::Member Function Name (parameters)
{
    Function body
}
```

## 2. Member Function with Default Formal Parameters

In Chapter 3 we introduced functions with default parameters. Member functions can also have default parameters, and its calling rules are the same as those of ordinary functions. Sometimes default parameters can bring great convenience. For example, Clock's member function SetTime() can have default parameters as:

```
void Clock::SetTime(int NewH=0, int NewM=0, int NewS=0)
{
    Hour=NewH;
    Minute=NewM;
    Second=NewS;
}
```

If this member function is called without actual parameters, the clock time will be to 0 AM according to the default values.

## 3. Inline Member Function

We know that calling a function costs some memory resources and CPU time to pass parameters, to return value, and to record the calling state in order to correctly return and after the call finished. If a member function needs to be called frequently, and the code is simple, such a function can also be defined as an inline function. Unlike the ordinary inline function inserted in Section 3, the body of an inline member function will be inserted wherever it is called at compiling time. By doing this, the cost of function call is reduced and the execution efficiency is improved, while the code length after compiling is increased. So we should carefully weigh the pros and cons, and only define simple member functions as inline functions.

Two ways can be define an inline function: implicit definition and explicit definition.

Implicit definition puts the function body directly into the class body. For example, to define the member function ShowTime() of class Clock as an inline function:

```
class Clock
{
public:
    void SetTime(int NewH, int NewM, int NewS);
    void ShowTime()
    {
        cout<<Hour<<":":"<<Minute<<":""<<Second<<endl;
    }
private:
    int Hour,Minute, Second;
};
```

Explicit definition: we commonly use the keyword inline before the function type. That is, we put the keyword inline before the function definition:

```
inline void Clock::ShowTime()
{
    cout<<Hour<<":"<<Minute<<":""<<Second<<endl;
}
```
