## 3. Conversions Between Binary, Octal, and Hexadecimal Numerical Systems

There are internal relationships between the weights of binary, octal, and decimal numerical systems, that each digit in an octal number can be represented by three binary numbers ($2^3 = 8$), and each digit in a hexadecimal number can be represented by four binary numbers ($2^4 = 16$). Let's see the following examples:

As a number, we start from the decimal point and group every three (or four) digits into one unit left and rightward. By converting each binary unit into an octal (or hexadecimal) number, we achieve the conversion from the binary number to its octal (or hexadecimal) form. Note that in conversion, the grouping centers on the decimal point and extends leftward and rightward, the 0's in the middle cannot be omitted. We need to fill some 0's if there are not on either end.

Every digit in an octal (or hexadecimal) number can be converted into three (or four) binary digits. Notice that except the leftmost significant bit, there should be exactly three (or four) binary digits for each octal (or hexadecimal) digit or we need to fill some 0's. For example:

- $(1000100)_2 = (1 000 100)_2 = (104)_8$
- $(1000100)_2 = (100 0100)_2 = (44)_{16}$
- $(1011010.10)_2 = (001 011 010.100)_2 = (132.4)_8$
- $(1011010.10)_2 = (0101 1010.100)_2 = (5A.8)_{16}$
- $(F)_{16} = (1111)_2$
- $(7)_{16} = (0111)_2$
- $(F7)_{16} = (1111 0111)_2$

## 1.4.3 Storage Units of Information

All information in the computer is stored in the binary-encoded form. Here we introduce the data storage units:
The data units we usually use are "bit", "byte", and "word".

- Bit: the smallest unit of measurement, representing a binary data.
- Byte: a byte consists of 8 bits, which is the conventional elementary unit of information storage.

Usually, memory capacity is represented by the number of bytes. Common units include:
- kilobytes: 1 K = 1024 byte
- M bytes: 1 M = 1024 K
- G bytes: 1 G = 1024 M

Word: a word is the combination of bits and is used as an independent data unit. A word is also called a "computer word", and its exact meaning depends on machine types, word length, and user requirements. Common word lengths can be 8 bits, 16 bits, or 32 bits.
A data unit is used to describe the computer's internal data form, i.e., the data arrangement inside the computer. For example, single-byte data and variable-length data (data forms of different length in bytes), etc. are kinds of data units.
Machine word length is another hardware-related data unit. Machine word length usually refers to the number of binary bits those registers are involved in arithmetic. It represents the precision of a machine and can be 32 bits, 64 bits, etc.

## 1.4.4 Binary-coded Representation

The representation of a number in a machine is called the "machine number" and its value is called the "true value" of the machine number.

As mentioned before, data information in computers is represented in binary code.
Since a number can be positive or negative, how does one signify the sign of a number in computers? Generally, the leftmost bit of the number indicates the sign of the value represented, where "0" indicates the positive sign and "1" indicates the negative sign.
For example:
An 8-bit number $A = (+1011011)$ and $B = (-1011011)$ can be represented in a computer as:

| A | 0 | 1 | 0 | 1 | 1 | 0 | 1 | 1 |
|---|---|---|---|---|---|---|---|---|
| B | 1 | 1 | 0 | 1 | 1 | 0 | 1 | 1 |

The leftmost bit is the sign; it forms the number together with the rest of the bits.
Once the data information has been digitized, it can be recognized and represented by a computer. In order to simplify the computation of signed numbers and make ALU simpler, people have invented binary-coding methods, whose substantial difference lies in the coding methods of **negative numbers**.
Now we will introduce some common coding methods: true code, ones-complement code, and complement code.

### 1. True Code

True code makes the separate bit 0 or 1 and combines the absolute value of the number with the other bits to achieve the coding. It is also called "sign-absolute value represented" coding.
Firstly we will show how to represent a signed integer in true code:
Suppose we use one bit in memory to store an integer, and its true code is this:

```
$X = +1011011 \quad [X]_{true} = 00101011$
$X = -1011011 \quad [X]_{true} = 10101011$
```

Here $[X]_{true}$ are the machine number, and $X$ is called its true value.
For decimal fraction, the sign bit in true code is the one to the left of the decimal point. For example:

```
$X = 0.10111 \quad [X]_{true} = 0.10111$
$X = -0.10111 \quad [X]_{true} = 1.10111$
```

True code is simple and intuitive. However, true code has several shortcomings:
Firstly, the representation for 0 is not unique, since:

```
$X = +0000000 \quad [X]_{true} = 0000000$
$X = -0000000 \quad [X]_{true} = 1000000$
```

The ambiguity of 0 can cause trouble in computer.
Secondly, when we use true code to do operations, the sign bit should be handled independently and the operation is complicated.

### 2. Ones-complement code

Ones-complement code is rarely used, but it may help us understand the meaning of complement code, so we introduce it.

The ones-complement code of a positive number is the same as true code.
The ones-complement code of a negative number is like this:

```
$X = +110110 \quad [X]_{ones} = 0110110$
$X = -110110 \quad [X]_{ones} = 1001001$
```

Like true code, in ones-complement code we have positive zero and negative zero.
The ones-complement code of a decimal fraction is as follows:

```
$X = 0.1011 \quad [X]_{ones} = 0.1011$
$X = -0.1011 \quad [X]_{ones} = 1.0100$
```
