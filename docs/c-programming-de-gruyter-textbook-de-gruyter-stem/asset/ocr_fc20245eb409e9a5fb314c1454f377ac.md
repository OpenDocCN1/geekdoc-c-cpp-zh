Pay attention to that using a static data member: if you want to access the static data through a nonstatic function, you should use a noninline function, and the definition of this noninline function should be in the same source file as the initialization of the static member. Why should we do so? It is because static data member must be initialized before being accessed, and the compiler can only make sure to initialize static data members of class before calling any nonstatic function defined in the same source file. We will introduce a multifile structure in Section 5.6, and we will see that one project can be made up of several source files. The definition of class, the initialization of static data members, and the definition of member functions can be in different source files. In this case, cause unexpected errors.

# 5.4 Friend of Class

The encapsulation of data and the function operating the data to form a class can achieve both great advantage of object-oriented program design. But encapsulation is not omnipotent. Now, consider a simple example of the Point class that we are familiar with, in which each object represents a “point”. If we want to calculate the distance between two arbitrary points, how do we design this function?

If we design the distance calculator function as a general function outside the class, we cannot reflect the relation between the function and “point”, and functions outside the class cannot refer to the coordinates of the “point” (private member) directly, which makes the calculation inconvenient.

When about designing the calculator function as a member function of class Point? It is hard to implement from a grammatical point of view, but it is hard to understand. This is because distance is a relation between two points, and it does not belong to any point, nor to the whole class. In other words, to design the function as a nonstatic member or as a static member, it will always affect the readability of the program.
