```
oos1 = "hello";        // OK: assign new value
ooc.emplace(std::in_place, 7.2, 8.3);
```

Due to the two levels of having no value, an optional of optional enables you to have “no value” on the outside or on the inside, which can have different semantic meanings:

```
*oos1 = std::nullopt;  // inner optional has no value
oos1 = std::nullopt;   // outer optional has no value
```

This means that you have to take special care to deal with the optional value:

```
if (!oos1) std::cout << "no value\n";
if (oos1 && !*oos1) std::cout << "no inner value\n";
if (oos1 && *oos1) std::cout << "value: " << **oos1 << '\n';
```

However, from a semantic perspective, this is a type with two different states that both represent having no value. Therefore, a std::variant<> with two Boolean or monostate alternatives might be more appropriate.
