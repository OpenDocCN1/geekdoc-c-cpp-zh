This example shows why you need Locale objects. You feed them to locale-aware methods that produce text that is presented to users in different locations. You will see many examples of this in the following sections.

> **CAUTION:** Even such mundane operations as turning a string into lowercase or uppercase can be locale-specific. For example, in the Turkish locale, the lowercase of the letter I is a dotless ı. Programs that tried to normalize strings by storing them in lowercase have mysteriously failed for Turkish customers where I and the dotted İ don't have the same lowercase version. It is a good idea to always use the variants of toUpperCase and toLowerCase that take a Locale argument. For example, try out:
> 
> ~~~java
> String cmd = "QUIT".toLowerCase(Locale.forLanguageTag("tr"));
> // "quıt" with a dotless ı
> ~~~
> 
> Of course, in Turkey, where Locale.getDefault() yields just that locale, "QUIT".toLowerCase() is not the same as "quit".
> 
> If you want to normalize English language strings to lowercase, you should pass an English locale to the toLowerCase method.

> **NOTE:** You can explicitly set the locale for input and output operations.
> 
> - When reading numbers from a `Scanner`, you can set its locale with the `useLocale` method.
> - The `String.format` and `PrintWriter.printf` methods optionally take a `Locale` argument.
