# ISO/IEC 14882:2017(E)

floating-literal: one of
f I F L

A floating literal consists of an optional prefix specifying a base, an integer part, a radix point, a fraction, an e, E, p or O optionally signed exponent, and an optional type suffix. The integer and fraction parts both consist of a sequence of decimal (base ten) digits if there is no prefix, or hexadecimal (base sixteen) digits if the prefix is 0x or O. The floating literal is a **decimal literal** in the former case and a **hexadecimal literal** in the latter case. Optional single quotes in a **digit-sequence** or **hexadecimal-digit-sequence** are allowed when determining its value. *Example*: The floating literals 1.678e-19 and 0x1.67bp-19 are equivalent. Either the integer part or the fraction part (not both) can be omitted. Either the radix point or the E and the exponent (not both) can be omitted from aecimal literal. The integer part, the radix point, and the fraction part (not both) form the **significand** of the floating literal. In a decimal floating literal, the exponent, if present, indicates the power of 10 by which the significand is scaled. In a hexadecimal floating literal, the exponent indicates the power of 2. The floating literals 0xC.6bp+2 have the same value. If the scaled value is in the range of representable values for its type, the larger or smaller representable value near the scaled value, chosen in an implementation-defined manner. The type of a float literal is **double** unless specified by a suffix. The suffixes L and F specify **long** and **float**, respectively. If the scaled value is not in the range of representable values for its type, the program is ill-formed.

3 Note: The characters ' and ) are permitted in a raw-string. Thus, R"delimiter) is equivalent to "delimiter)".


5 Example: The raw string R"a\n\"a" is equivalent to "\n\na\a". The raw string R(x = \"\")")

6 After translation phase 6, a string literal that does not begin with an encoding-prefix is an ordinary string literal, and initialized with the given characters.

7 A string-literal that begins with u8, as u8"abcd", is a UTF-8 string literal.

8 Ordinary string literals, such as UTF-8 string literals are also referred to as narrow string literals. A narrow string literal has type "array of n const char", where n is the size of the string and has static storage during the UTF-8 encoding of the string (7).

9 For a UTF-8 literal, each successive element of the code (9) has the value of the corresponding code unit. A char16_t literal has type "array of n const char", where n is the size of the string defined below; it is initialized with the given characters. A single char may produce more than one char16_t in the form of surrogate pairs.

10 A string-literal that begins with u, as u"abcd", is a wide string literal. A wide string literal has type "array of n const char_t", where n is the size of the string defined below; it is initialized with the given characters.

11 A string-literal that begins with L, as L"abcd", is a char32_t string literal. A char32_t string literal has type "array of n const char32_t", where n is the size of the string defined below; it is initialized with the given characters.

12 In translation phase 6 (5.2), adjacent string-literals are concatenated. If string-literals have encoding-prefix, the resulting literal has that encoding-prefix. If one string-literal has no encoding-prefix, it is treated as a string-literal of the same encoding-prefix as the other. If a UTF-8 string literal adapts to a wide string literal, the process is ill-formed. Any other concatenations are conditionally-supported with implementation-defined behavior. Note: concatenation is an interpretation, not a conversion. Because the interpretation happens in translation phase 6 (after each character from a string literal has been translated into a value from the appropriate character set), string-literal's initialness has no effect on the interpretation or well-formedness of the concatenation. Escape sequences and universal-character-names in raw-string literals have the same meaning as in character literals (5.13.3), except that the single quote '\'' is representable either by '\'' or the escape sequence \' preceded by a \, and except that a universal-character-name may contain more than one element due to multiple encoding. The size of a raw string literal is the total number of escape sequences and other characters, plus at least one for the multibyte encoding of each universal-character-name, plus one for the terminating '\0'.

Evaluating a string-literal result in a string object with static storage duration, initialized from the given characters as specified. Whether all string literals are distinct (that is, in nonoverlapping objects) and whether successive evaluations of a string-literal yield the same or a different object is unspecified.
