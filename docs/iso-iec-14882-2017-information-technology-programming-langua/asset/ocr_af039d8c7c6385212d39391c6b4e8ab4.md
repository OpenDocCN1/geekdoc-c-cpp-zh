# 26 Container requirements [container.requirements]

# 26.2.1 General container requirements [container.requirements.general]

+   1 Containers are objects that store other objects. They control allocation and deallocation of these objects through constructors, destructors, insert and erase operations.

+   2 All of the complexity in this Clause are stated in terms of the number of operations on the contained objects. [Example: The copy constructor of vector<vector<int>> has linear complexity, even though the complexity of copying each container vector<int> is linear. — example]

+   3 For the components that declare an allocator_type, objects stored in these components must be constructed using the function allocator_traits<allocator_type>::rebind_traits<U>::construct and destroy (23.10.8), where U is either the allocator_type::value_type or an internal type used by the container. These functions are called only for the container's element type, not for internal types used by the container. Note: This means, for example, that a node-based container might need to construct nodes and call construct to place the element into the buffer. — note

+   4 In Tables 83, 84, and 85 X denotes a container containing objects of type T, and n denotes values of type X, where x denotes an identifier, r denotes a non-const value of x, and rv denotes a non-const value of type X.
