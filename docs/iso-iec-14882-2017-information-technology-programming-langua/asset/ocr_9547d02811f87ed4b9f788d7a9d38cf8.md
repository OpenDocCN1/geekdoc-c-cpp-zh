# 8.1.4.2 Qualified names [expr.prim.id.qual]

+   1. The type denoted by a decltype-spec denotes a class, optionally followed by the keyword template (17.2), and then followed by the name of a member of that class (12.2) or one of its bases classes (Clause 13), is a qualified-id; 6.4.3.1 describes lookup for class members that appear in qualified-ids. The result is the type of the member. The type of the result is a value if the member is a member function or a data member and a prvalue otherwise; a class member can be referred to using a qualified-id at any point in the program (6.3.7., end note). When two class-name-specifiers are used, the two class-names refer to the same class: the destructor, but shall not be the unqualified-id in a qualified-id. [Note: A typedef-specifier denotes a name that is a class-name (12.1.) — end note]

+   2. The nested-name-specifier denotes the global name. A nested-name-specifier that names a namespace (10.3), optionally followed by the name of a member of that namespace (or the name of a namespace made visible by using a-directive), is a qualified-id; 6.4.2.2 describes lookup for namespace members that appear in qualified-ids. The result is the type of the member. The type of the result is a value if the member is an enumeration or a variable and a prvalue otherwise. The result is the enumerator. The type of the enumeration is a prvalue.

+   3. A qualified-specifier that denotes an enumeration (10.2), followed by the name of an enumerator of that enumeration, is a qualified-id that refers to the enumerator. The result is the the type of the enumeration. The result is a prvalue.

+   4. In a qualified-id, if the unqualified-id is a conversion-function-id, its conversion-type-id should denote the same type in the context in which the entire qualified-id occurs and in the context of the class denoted by the nested-name-specifier.
