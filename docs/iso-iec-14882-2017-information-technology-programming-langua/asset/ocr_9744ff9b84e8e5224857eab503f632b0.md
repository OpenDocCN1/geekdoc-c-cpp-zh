Effects: If the shared state contains a deferred function (33.6.9), otherwise blocks until the shared state is ready or the absolute timeout (33.2.4) is specified by abs_time has expired.

Returns:

+   - future_status::deferred if the shared state contains a deferred function.

+   - future_status::ready if the shared state is ready.

+   - future_status::timeout if it is returning because of the absolute timeout (33.2.4)
 by abs_time has expired.

Throws: timeout-related exceptions (33.2.4).

# 33.6.8 Class template shared_future

The class template shared_future defines a type for asynchronous returned objects which may share their shared state with other asynchronous result. A default-constructed shared_future object has no shared state. A shared_future object with shared state can be created by conversion from a future and shares its shared state with the original provider (33.6.5) of the shared state. The result (value or exception) of a shared_future object can be got by calling a respect on an object that shares the same shared state.

> Member functions of shared_future do not synchronize with themselves, but they synchronize with the shared state of the other future. — end note

The effect of calling any member function other than the destructor, the move-assignment operator, the copy-assignment operator, or valid() on a shared_future object for which valid() == false is undefined. It is illegal to copy or move from a shared_future object for which valid() is false. — end note
Implementations should detect this event and throw an exception of type future_error with an error condition of future_errc::no_state. — end note
