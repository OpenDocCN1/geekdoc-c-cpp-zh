# ISO/IEC 14882:2017(E)

# 17.2 Names of template specializations

+   A template specialization (17.7) can be referred to by a template-id:
- simple-template-id:
- template-name <template-argument-list-opt>
- template-id:
- simple-template-id:
- operator-function-id <template-argument-list-opt>
- literal-operator-id <template-argument-list-opt>
- template-name:
- template-argument-list:
- template-argument-list , template-argument ...opt
- template-argument:
- constant-expression
- id-expression

> Note: The name lookup (6.4) is used to associate the use of a name with a template declaration; that is, to identify a name as a template-name. — end note]

+   For a template-id to be explicitly qualified by the template arguments, the name must be known to refer to a template.

+   After name lookup (6.4) finds that a name is a template-name or an operator-function-id or a literal-operator-id refers to a set of overloaded functions any member of which is function, then if followed by a < is always taken as the delimiter of a template-argument-list and not as the operator. When parsing a template-argument-list, the first non-nested¹³⁶ is taken as the delimiter rather than a greater-than operator. Similarly, the first non-nested is treated as two consecutive but distinct tokens, the first of which is the end of the template-argument-list and completes the template-id. —Note: The second token produced by this replacement rule may terminate the template-id or may be part of a different construct (e.g. a cast). — end note] [Example:

```
template<int i> class Y { /* ... };
Xi<2> > x2;
Y<1> x3;
Y<X>>> x4;
Y<Y<1)>> x5;
// syntax error
```

The template name is said to appear at the top level in a qualified-id if it appears outside of a template-argument-list or decltype-spec. In a qualified-id formed by a class-name (Clause 12) or enum-name (10.3), the template shall not appear at the top level. In a used-type-name (17.6), elaborated-type-spec (10.7.3), using-declaration (10.3.3), or class-decltype (Clause 13), an optional keyword template appearing at the top level is ignored. In these contexts, a < is always used to introduce a template-argument-list. In all other contexts, when naming a template specialization of a member of an unknown specialization (17.6.2.1).

¹³⁶ that encompasses the type-id of a dynamic_cast, static_cast, reinterpret_cast or const_cast, or which encompasses the template-arguments of a subsequent template-id, is considered necessary for the purpose of this description.
