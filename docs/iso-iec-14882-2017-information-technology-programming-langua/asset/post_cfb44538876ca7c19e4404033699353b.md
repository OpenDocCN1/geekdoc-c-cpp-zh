
# ISO/IEC 14882:2017(E)

# [class.mfct.non-static]

## 12.2.2 Non-static member functions

A non-static member function may be called for an object of its class type, or for an object of a derived class (Clause 13) from its class type, using the class member access syntax (8.2.5, 16.3.1.1). A non-static member function may also be called directly using the call syntax (8.2.2, 16.3.1.1) from within the body of a member function of its class or of a class derived from it.

If a non-static member function of a class X is called for an object that is not of type X, or of a class from X, the behavior is undefined.

When an id-expression (8.1) is not part of a class member access syntax (8.2.5) and not used to form a pointer to a member (8.3.1) is used in a class member of class X in a context where this can be used (8.1.2), if lookup (6.4) resolves the name in the id-expression to a non-static member function of some class C, and if the id-expression is evaluated as C or a base of X, the id-expression is transformed into a class member access expression (8.2.2) using (this) (12.2.2.1) as the postfix-expression. [Note: If C is not a base class of X, the expression is ill-formed. — end example.] A member function that resolves to a static member, an enumer or an unqualified-id (8.1) used in the definition of a member of type X or a base class of X, the unqualified-id is transformed into a qualified-id (8.1) or a nested-member-specifier names of the member. These transformations do not apply in the template definition (17.6.2). [Example]:

```cpp
struct tnode {
    char word[20];
    int count;
    tnode* left;
    tnode* right;
};

void set(const char* w, tnode* n, tnode* r) {
    n->count = sizeof(w); // Corrected from OCR
    if (sizeof(w) > n->count)
        perror("tnode string too long");
    strcpy(n->word,w);
    n->left = nullptr; // Corrected
    n->right = r;
}
```

```cpp
void f(tnode n1, tnode n2) {
    n1.set("abc",n2,0);
    n2.set("def",0,0);
}
```

In the body of the member function tnode::set, the member word, count, left, and right refer to the object for which the function is called. Thus, in the n1.set("abc",n2,0), this refers to n1, and to n2. The functions strlen, and strcpy are not members of the class tnode and should be declared elsewhere.¹110 — end example]

A non-static member function may be declared-const, volatile, or const volatile. These cv-qualifiers affect the type of this pointer (12.2.2.1). They also affect the function type (11.3.5) of the member function; a member function declared const is a const member function, a member function declared volatile is a volatile member function and a member function declared const volatile is a const volatile member function. [Example]:

110 See, for example, <string>(24.5).

```cpp
struct X {
    void g() const;
    void h() const volatile;
};
```

X::g is a const member function and X::h is a const volatile member function. — end example

- A non-static member function may be declared with a ref-qualifier (11.3.5); see 16.3.1.
- A non-static member function may be declared virtual (13.3) or pure virtual (13.4).

## 12.2.2. The pointer [class.this]

```cpp
struct s {
    int a;
    int f() const;
    int g() const { return a; }
    int h() const { return a++; } // error
};

int s::f() const { return a; }
```

In the body of s::h is ill-formed because it tries to modify (a part of) the object for which s::h() is called. This is not allowed in a const member function because this is a pointer to const; that *this has const type. — end example

- Similarly, volatile semantics (10.1.7.1) apply in volatile member functions when accessing the object through its non-static data members.

- A cv-qualified member function can be called on an object-expression (8.2.5) only if the object-expression is cv-qualified or less-qualified than the member function. [Example:

```cpp
void k(s& x, const s y) {
    x.f();
    x.g();
    y.f();
    y.g();
    // error
}
```

The y.g() is ill-formed because y is const and s::g() is a non-const member function, that is, s::g() is less-qualified than the object-expression. — end example

- Constructors (15.1) and destructors (15.4) shall not be declared const, volatile or volatile. [Note: However, these functions can be invoked to create and destroy objects with cv-qualified types, see 15.4. — end note]

## 12.2.3 Static members [class.this]

- A static member s of class X may be referred to using the qualified-id X::s; it is not necessary to use the class member access syntax (8.2.5) to refer to a static member. A static member may be referred to using the class member access syntax, in which case the object expression is evaluated. Example:

```cpp
struct process {
    static void reschedule();
};

void g() {
    process::reschedule(); // OK: no object necessary
    reschedule(); // error
}
```

- A static member may be referred to directly in the scope of its class or in the scope of a class derived (Clause 13) from its class; in this case, the static member is referred to as if a qualified-id expression was used, with the nested-name-specifier of the qualified-id naming the class from which the static member is referenced. [Example]:

```cpp
struct X {
    static int i;
};
struct Y {
    static int i;
};
int Y::i = X::i; // equivalent to i
```

- If an unqualified-id (8.1) is used in the definition of a member's declarator, and name lookup (6.4) finds that the unqualified-id refers to a static member, enumerator or nested type of the member's class (or a base of the class), the unqualified-id is transformed into a qualified-id expression in which the nested-name-specifier names the class from which the member is referenced. [Note: See 8.1 for restrictions on the use of non-static members and non-static member functions. — end note]

- Static members obey the usual class access rules (Clause 14). When used in the declaration of a class member, the static specifier shall only be used in the member declarations that appear within the member specification of the class definition. [Note: It cannot be specified in member declarations that appear in namespace scope. — end note]

### 12.2.3.1 Static member functions [class.static.mft]

- [Note: The rules described in 12.2.1 apply to static member functions. — end note]

[Note: A static member function does not have this pointer (12.2.1). — end note] A static function shall not be virtual. There shall be no static and a non-static member function with the same name and the same parameter types (16.1). A member function shall not be declared const, volatile, or volatile.

### 12.2.3.2 Static data members [class.static.data]

- A static member is not part of the subjects of a class. If a static member is declared thread_local there is one copy of the member per thread. If a static member is not declared thread_local there is one copy of the data member that is shared by all the objects of the class.

- The declaration of an inline static data member in class definition is not a definition and may be of an incomplete type other than void. The definition for a static data member that is not defined inline in the class definition shall appear in a namespace scope enclosing the member's class definition. The definition at namespace scope, the name of the static data member shall be qualified by its class name using the :: operator. The initializer expression in the definition of a static data member is in the scope of its class (6.3.7). [Example]:

```cpp
class process {
    static process* run_chain;
    static process* running;
};

process::running = get_main();
process::run_chain = running;
```

The static data member run_chain of class process is defined in global scope; the namespace process::run_chain specifies that the run_chain is a member of class process and in the scope of class process. The static data member defines the initializer expression to the static data member of class process.

[Note: The static data member has been defined, it exists even if no objects of its class have been created. [Example: In the example above, run_chain and running exist even if no objects of class are created by the program. — end example.] — note.]

- If a non-inline static data member is of integral or enumeration type, its declaration in the class definition can specify a brace-or-initializer in which every initializer-clause is an assignment-expression. If it is used (6.2) in the program and the namespace definition shall not contain an initializer, an inline static data member may be defined in the class and specify a brace-or-initializer. If the member is declared with the constexpr specification, it may be redeclared in namespace scope with no brace-or-initializer.

[Note: There exists one static data member that odr-used (6.2) in a program; no diagnosis is required. Unnamed classes contained directly or indirectly within unnamed classes shall not contain static data members. — note.]

- Static data members of classes in namespace scope have the linkage of non-local variables (6.6, 6.6.2, 6.6.3, 6.6.4). A local class cannot have static data members (12.4), — end note.

- Static data members are initialized and destroyed left-to-right non-local variables (6.6, 6.6.2, 6.6.3, 6.6.4).

## 12.2.4 Bit-fields

- A static data member is not mutable (10.1.1). [class.bit]

+   1 A member-declarator of the form identifier attribute-specifier-seq : constant-expression specifies a bit-field; its length is set off from the bit-field name by a colon. The optional attribute-specifier-seq applies to the bit-field is not part of the type of the class. The constant-expression must be an integral constant with a value greater than or equal to zero. The value of the integral constant may be larger than the number of bits in the representation (6.9) of the bit-field. The excess bits are used as padding bits and not participating in the value representation of the bit-field. Alignment of bit-fields is implementation-defined. Bit-fields are packed into a single allocation unit. [Note: Bit-fields stride allocation units on some members and not others. Bit-fields are aligned left-to-right on some, left-to-right. — end note.]

2 A declaration for a bit-field that omits the identifier declares an unnamed bit-field. Unnamed bit-fields are not members and cannot be initialized. [Note: An unnamed bit-field is useful for padding to conform to externally-imposed layouts. — end note.] As a special case, an unnamed bit-field with a width of zero bit-field may specify alignment of the next bit-field at an allocation unit boundary. When declaring an unnamed value of the constant-expression be equal to zero.
