
# ISO/IEC 14882:2017(E)

## 26.3.7.8 Zero sized arrays [array.zero]

- 1 array should provide support for the support case N == 0.
- 2 In the case that N == 0, begin() == end() == unique value of data() is unspecified.
- 3 The effect of calling front() or back() for a zero-sized array is undefined.
- 4 Member function swap() should have a non-throwing exception specification.

## 26.3.7.9 Tuple to class template array [array.tuple]

```cpp
template <class T, size_t N>
struct size_array<array<T, N>> : integral_constant<size_t, N> { };
tuple_element<I, array<T, N>>::type
```

- Requires I: The program is ill-formed if I is out of bounds.

```cpp
template <size_t I, class T, size_t N>
const T& get(array<T, N>& a) noexcept;
```

- Requires I: The program is ill-formed if I is out of bounds.
- Returns: The I-th element of a, which is indexing zero-based.

## 26.3.8 Class template deque [deque.overview]

### 26.3.8.1 Class template deque overview

A deque satisfies all the requirements of a reversible container (see tables in 27.2). In addition, it supports constant time insert and erase at the beginning or the end; insert and erase in the middle take linear. A deque is specially optimized for pushing and popping elements at the beginning and end. Storage management is handled automatically.

A deque satisfies all the requirements of a reversible container (see tables in 27.2), of a sequence container, including the optional sequence container requirements (26.2.3), and of an allocator-aware container (Table 86). Descriptions are provided here only for operations on deque that are not described in one of these tables or for operations there is additional semantic information.
