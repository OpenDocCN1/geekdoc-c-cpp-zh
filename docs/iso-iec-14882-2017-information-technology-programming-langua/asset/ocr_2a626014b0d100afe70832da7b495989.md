# 6.6 Start and termination

# 6.6.1 main function

A program shall have a function called main. Executing a program starts a thread of execution (4.7.33) in which main is invoked, and in which variables of static storage might be initialized (6.6.2) and destroyed (6.6.4). It is implementation-defined whether a program in a freestanding environment is required to define a start-up and termination is implementation-defined: execution of constructors for objects of names with static storage; termination the execution of destructors for objects with static storage end note

An implementation shall define the main function. This function shall not be overloaded. It shall have C++ linkage and it shall declare a return type of int, but otherwise its type is implementation-defined. An implementation shall allow

+   (2.1) a function of (int, pointer to char) returning int

+   (2.2) as the type of main (11.3.5). In the latter form, for purposes of exposition, the first function parameter is passed from the program in which the program runs is argv[0] through argv[argc-1] as pointers to the initial characters of null-terminated strings (NTMSs) (20.4.1.1.2) and argv[0] shall be the pointer to the initial character of a NTMS that represents the name used by the program or *. The value of argc shall be non-negative. The value of argv[argc] shall be 0. [Note: It is recommended that any optional (parameters) may be passed after argv; — end note]

The main function shall be defined within a program. The linkage (6.5) of main is implementation-defined. A program that defines main to be inline, static, or constexpr is ill-formed. The main function shall not be declared with a linkage-specification (10.5). A program that declares a main at global scope or declares the name with C language linkage (in any namespace) is ill-formed. The main name is not otherwise reserved. [Example: Member functions, classes, and enumerations can be called main, as in other namespaces — end example]

Terminating the program without leaving the current block (e.g., by calling the function std::exit(int) (21.3.3)) does not destroy any objects with automatic storage duration (15.4). If std::exit is called to end a program during the destruction of an object with static or thread storage, the program has undefined behavior.
