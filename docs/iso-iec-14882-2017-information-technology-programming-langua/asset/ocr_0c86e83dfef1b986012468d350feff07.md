# 11.3.1 Pointers [dcl.ptr]

+   1 In a declaration T where D has the form
* `attribute-specifier-seq-opt` cv-qualifier-type-list-opt D1

and the type of the identifier in the declaration D1 is *derived-declarator-type-list T`*, then the type of the
identifier of D is *derived-declarator-type-list cv-qualifier pointer to T*. The *cv-qualifiers* apply to the
pointer and not to the pointed to. Similarly, the optional `attribute-specifier-seq` (10.6.1) pertains to
the pointer and not to the object pointed to.

+   2 [Example: the declaration

```
const int ci = 10, *pc = &ci; *const int *pc = pc, *ppc;
int i, *p, *const pc = &i;
```

declare ci, a constant integer; a pointer to a constant integer cpc; a constant pointer to a constant
integer; ppc, a pointer to a pointer to a constant integer; i, an integer; p, a pointer to integer; and cp, a constant
pointer to integer. The value of cpc, cp, and cpp cannot be changed after initialization. The value of
pc can be changed, and so the object pointed to by cp. Examples of some correct operations are

```
i = ci;
*pc = ci;
ppc++;
pc = pc;
p = p;
ppc = &pc;
```

Examples of ill-formed operations are

```
ci = 1; // error
ci++; // error
*pc = 2; // error
cp = &ci; // error
ppc++; // error
p = pc; // error
ppc = &pc; // error
```

Each is unacceptable because it either change the value of an object declared const or allow it to be
changed through a cv-unqualified pointer later, for example:

```
*ppc = &ci; // OK, but would make p point to ci because previous error
*p = 5; // clobber ci
```

— end example]
