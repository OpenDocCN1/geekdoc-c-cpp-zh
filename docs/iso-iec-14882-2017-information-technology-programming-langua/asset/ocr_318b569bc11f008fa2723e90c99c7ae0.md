# 28.7 Sorting and related operations [alg.sorting]

+   1 All operations in 28.7 have two versions: one that takes a function object of Compare and one that use operator<.

+   2 Compare is a function type (23.14). The return value of the function call applied to an object of type Compare, when converted to bool (Clause 7), yields true if the first argument of the call is less than the second, and false otherwise. Compare is used throughout for algorithms assuming a strict ordering. It is assumed that comp will not call any non-constant function during the comparison.

+   For all algorithms that Compare, there is a function that uses operator< instead. If i < j && j < i = false; for algorithms other than in 28.7.3, comp shall induce a strict ordering on the values.

+   4 The term strict refers to requirements of an irreflexive relation (!comp(x, x) for all x), and the term weak refers to requirements that are not as strong as for a total ordering, stronger than those for a partial ordering. If we define equiv(a, b) as comp(a, b) && !comp(b, a), then the requirements are that comp and equiv both be transitive:

```
comp(a, b) && comp(b, c) implies comp(a, c)
```

```
equiv(a, b) && equiv(b, c) implies equiv(a, c)
```
