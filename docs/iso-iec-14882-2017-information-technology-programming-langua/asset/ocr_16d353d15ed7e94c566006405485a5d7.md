# ISO/IEC 14882:2017(E)

```
try {
  f(2);
} catch(Overflow oo) {
  // handles exceptions of type overflow here
}
// end example;
```

+   When an exception is thrown, control is transferred to the nearest handler with a matching type (18.3); "nearest" means the handler for which the compound-statement or ctor-initializer following the try keyword was most recently entered by the thread of control and not yet exited.

+   Throwing an exception copy-initializes (11.6, 15.8) a temporary object, called the exception object, to the variable declared in the handler (18.3). If the exception object is an incomplete type or a pointer to an incomplete type then ever the program is ill-formed.

+   The memory for the exception object is located in an unspecified way, except in 6.7.4.1. If a handler exits by throwing, control is passed to another handler for the same exception object. The points of potential destruction for the exception object are:

+   - when a handler for the exception exits by any means other than throwing, immediately after the destruction of the object (if any) declared in the exception-declaration in the handler;

+   - when an object of type std::exception_ptr (21.8.6) refers to the exception object is destroyed, after the destructor of std::exception_ptr returns.

Among all points of potential destruction for the exception object, there is one listed where the exception object is destroyed. All other points except one (4.7.1). [Note: No other thread synchronization is implemented in exception handling unless caught, and restored] in an unspecified way. [Note: A exception does not propagate unless caught, and restored, using appropriate library functions;] 21.8.6 and 33.6 — end note]

When the exception is a class object, the constructor selected for the copy-initialization as well as the constructor selected for a copy-initialization the object as an value shall be non-deleted and accessible, even if the copy/move operation is enabled (15.8). The destructor is potentially invoked (15.4).

An exception is considered caught when a handler for which exception becomes active (18.3). [Note: An exception can have active handlers and still be considered uncaught if it is rethrown. — end note]

If the exception handling mechanism handling an uncaught exception (18.5.2) directly invokes a function that exists via std::terminate() Example:

```
struct C {
  C() {}
  C(C&) {
    if (std::uncaught_exceptions()) {
      throw 0;
      // through control of handler's exception-declaration (18.3)
    }
  }
};

int main() {
  try {
    throw C(); // calls std::terminate() if construction of the handler's
               exception-declaration is not elapsed (15.8)
  }
  catch (C) {}
}

```
