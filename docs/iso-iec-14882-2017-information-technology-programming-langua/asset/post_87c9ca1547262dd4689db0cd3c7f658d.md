## 30.3.2 Overview [iostream.forward.overview]

- The template specialization basic_ios<char, traits> serves as a base class for the class templates basic_istream, basic_ostream, and class derived from them. basic_iostream is a class template derived from both basic_istream<char, traits> and basic_ostream<char, traits>.

- The class specialization basic_ambuf<char, traits> serves as a base class for class templates basic_stringbuf and basic_filebuf.

- The class specialization basic_istream<char, traits> serves as a base class for class templates basic_string and basic_istream.

- The class specialization basic_ostream<char, traits> serves as a base class for class templates basic_ostream and basic_ofstream.

- The class specialization basic_iostream<char, traits> serves as a base class for class templates basic_string and basic_fstream.

- Other typedef-names define instances of class templates specialized for char or wchar_types.

- Specializations of the class template fpos are used for file position information.

- The types streams and wstreams are used for positioning streams specialized from char and wchar_types respectively.

> [Note: This synopsis provides a circularity between streams and char_traits<char>. An implementation can avoid this circularity by substituting equivalent types. One way to do this might be
template<class State> class fpos { ... }; // depends on nothing
using _STATE_ = ...; // private declaration of state
streams = fpos<STATE>;

template<> struct char_traits<char> {
    using pos_type = streams;
}
// end_note

- 1 In this Clause, the synchronization unit refers to the type declared in <cstdio> (30.11).
- 2 The header <iostream> (30.11) declares objects that associate with the standard C streams provided by the functions declared in <cstdio> and includes all headers necessary to use these objects.- 3 The objects are constructed and the associations are established at some time prior to or during the first object of ios_base::init, and in any case before the body of main (6.1). The objects are destroyed during program execution. The results of including <iostream> defines an instance of ios_base::init with static duration.
- 4 Mixing operations on wide-character and narrow-character streams has the same semantics as such operations on FILE, as specified in the C library.
- 5 Concurrent access to a synchronized (30.5.3) standard istream object's formatted and unformatted input (30.7.1) and output (30.7.5) by multiple threads shall not result in a data race (4.7). [Note: Users must still synchronize concurrent use of these objects by multiple threads if they wish to avoid interleaved characters.]

## 30.4.3 stream objects

istream:

- 1 The object cin controls input from a stream buffer associated with the object stdin, declared in <cstdio> (30.11).
- 2 After the object cin is initialized, cin.tie() returns &cout. Its state is otherwise the same as basic_ios<char>::init (30.5.2).

ostream:

- 3 The object cout controls output to a stream buffer associated with the object stdout, declared in <cstdio> (30.11).

iostream:

- 4 The object cerr controls output to a stream buffer associated with the object stderr, declared in <cstdio> (30.11).
- 5 After the object cerr is initialized, cerr.flags() & cerr.tie() returns &cout. Its state is otherwise the same as required for basic_ios<char>::init (30.5.2).
- 6 The object clog controls output to a stream buffer associated with the object stderr, declared in <cstdio> (30.11).

> If it is possible for them to do so, implementations should initialize the objects earlier than required.. Constructors and destructors for static objects can access these to read input from stdin or write to stdout or stderr.

## 30.4.4 Wide stream objects [wide.stream.objects]

wistream wcin;

- 1 The object wcin controls input from a stream buffer associated with the object stdin, declared in <stdio> (30.11.1).
- 2 After the object wcin is initialized, wcin.tie() returns &wcout. Its state is otherwise the same as the required for basic_ios<wchar_t>::init (30.5.2).

wstream wcout;

- 3 The object wcout controls output to a stream buffer associated with the object stdout, declared in <stdio> (30.11.1).
- 4 The object wcerr controls output to a stream buffer associated with the object stderr, declared in <stdio> (30.11.1).
- 5 After the object wcerr is initialized, wcerr.flags() & unitbuf returns &wcout. Its state is otherwise the same as required for basic_ios<wchar_t>::init (30.5.2).

wstream wcg;

- 6 The object wcg controls output to a stream buffer associated with the object stderr, declared in <stdio> (30.11.1).
