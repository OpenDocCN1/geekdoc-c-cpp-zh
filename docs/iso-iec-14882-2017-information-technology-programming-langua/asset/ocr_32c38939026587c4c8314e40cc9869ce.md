# ISO/IEC 14882:2017(E)

```
int& (*fpi)(int*) = [](auto* a) -> autok { return *a; }; // OK
// end example
```

The value returned by any generic specialization of this conversion template is the address of a function F that, invoked, has the same effect as invoking the generic lambda's corresponding function call operator template specialization. If a is constexpr if the specialization is a constexpr function. [Note: This will result in the implicit instantiation of the generic lambda's body. The instantiated pointer type shall match the return type and parameter types of the pointer. — end note] [Example:]

```
auto GL = [](auto a) { std::cout << a; return a; };
int (*GL_int)(int) = GL; // OK conversion function template
GL_int(3); // OK as GL(3)
// end example
```

The governs or conversion function template is public, constexpr, non-virtual, non-explicit, const, and has a non-throwing exception specification ([18.4).

```
auto F = [](int (*fp), auto a) { return fp(a); };
auto C = [](auto a) { return a; };
```

```
static_assert(Fwd(C, 3) == 3); // OK

// No specialization of the call operator template is constexpr (from the local static).
auto NC = [](auto a) { int ret; return a; };
static_assert(Fwd(NC, 3) == 3); // ill-formed
// end example
```

The lambda-expression-compound-statement determines the function-body of the call operator, but for purposes of lookup (6.4), determining the type and value of this (12.2.2.1) and transforming id-expressions referring to non-static members into class member accesses using (*this) (12.2.2), the compound-statement is considered in the context of the lambda-expression. [Example:]

```
struct S1 {
int x, y;
int operator()(int);
void f() {
()()-> int {
return operator()(this->x + y); // equivalent to :operator(this->x + *(this).y)
// this has type Si*
}
};
// end example] Further, a __func__, is implicitly defined at the body of the compound-statement of the lambda-expression, with semantics as described in 11.4.1.
```

The closure type associated with a lambda-expression has no default constructor and a deleted copy assignment operator. It has a copy constructor and a moved constructor (15.8). [Note: These special member functions are implicitly defined as usual, and might not be defined as deleted. — end note]

A member of a closure type shall not be implicitly instantiated (17.7.2), or explicitly specialized (17.7.3), or named in a friend declaration (14.3).
