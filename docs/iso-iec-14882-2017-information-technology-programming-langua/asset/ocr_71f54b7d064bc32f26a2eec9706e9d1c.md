# ISO/IEC 14882:2017(E)

storage-class-specifier:
static
thread_local
extern
mutable

At most one storage-class-specifier shall appear in a given decl-specifier-seq, except that thread_local may appear with static or extern. If thread_local appears in any declaration of a variable-seq it shall be present in all declarations of that entity. If a storage-class-specifier appears in a decl-specifier-seq, there can be no typedef specified in the same decl-specifier-seq and the init-declarator-list or member-declarator-list of the declaration shall not exempt any union declared in a namespace or in the global namespace, which shall be declared static (12.3.1). The storage-class-specifier applies to the name declared by each init-declarator and not to names declared by other specifiers. A storage-class-specifier other than thread_local shall not be specified in an explicit specialization (17.7.3) or

> Note: A declaration without a storage-class-specifier at block scope has automatic storage duration by (6.7), — end note

The thread_specifier indicates that the named entity has thread storage duration (6.7.2). It shall be applied only to the names of variables of namespace or block scope and the names of static data members. When thread_local is used in a declaration of a block scope the storage-class-specifier static is implied if no other storage-class-specifier appears in the decl-specifier-seq. There can be no static function declarations within a block to have static storage parameters. A static specifier used in the declaration of a variable declares the variable to have thread storage duration (6.7). A static specifier used for static class members (12.2.3) describes its interface. For the linkage of a name declared with a static specifier, see 6.

The extern specifier can be applied only to the names of variables and to anonymous unions (12.3.1). The extern specifier cannot be used in the declaration of class members or function parameters.

The linkages implied by successive declarations for a given entity shall agree. That, within a given scope, each declaration declaring the same variable name or the overloading of a function name shall imply the same linkage. Each function in a given set of overloaded functions can have a different linkage, however:

```
static char f();
char* f(); // has internal linkage
/* ... */ // external linkage
```

```
char* g;
static char g(); // error: inconsistent linkage
/* ... */
```

```
void h();
inline void h(); // external linkage
```

```
inline void o();
extern void o(); // external linkage
```

```
inline void m();
extern void m(); // external linkage
```
