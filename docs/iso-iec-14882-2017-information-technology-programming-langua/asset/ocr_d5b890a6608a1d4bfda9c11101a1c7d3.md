# 16.3.3.1 Ellipsis conversion sequences

+   1 An ellipsis conversion sequence occurs when an argument in a function call is matched with the ellipsis parameter specification of the function called (8.2.2).

# 16.3.4.1 Reference binding

+   1 When a parameter of reference type binds directly, the conversion sequence is the identity, unless the argument expression has a type that is a derived class of the type, in which case the conversion sequence is a derived-to-Base Conversion (16.3.3.1). [Example:

```
struct A {};
struct B : A { B(); };
int f();
int i = f(b); // an exact match, rather than f(&a), a conversion
```

> - If parameter binds directly to the result of applying a function to the argument, the implicit conversion is a user-defined conversion sequence (16.3.3.1.2), with the second standard conversion sequence either identity conversion or, if the function returns an entity of a type that is a derived class of the parameter type, a derived-to-Base conversion.

+   2 When a parameter of reference type is not bound directly to an argument expression, the conversion sequence is the one required to convert the argument expression to the referenced type according to 16.3.3.1. Conceptually, this conversion sequence corresponds to copy-initializing a temporary of the referenced type with the argument expression. An initialization is performed by the rules of the type and does not constitute a conversion.

+   3 Except for an implicit object parameter, for see 16.3.1, a standard conversion sequence cannot be formed if it requires binding an invaluable reference to a non-const type or binding an invaluable reference to anything other than a value. [Note: For example, that a candidate function cannot be a viable function if it has a non-const value-type reference parameter (other than the implicit object parameter) and the corresponding argument would require a temporary to be created to initialize the reference (16.3.3.3 — note).

+   Other cases of binding invaluable references, in particular, are not based on the types of the reference and the argument do not affect the formation of a standard conversion sequence, however. [Example: A function with an "reference to" parameter can be a viable candidate even if the argument is an int bit-field. The formation of implicit conversion sequences treats the bit-field as an int with the parameter. If the function is selected by overload resolution, the call will nonetheless be ill-formed because of the prohibition on binding a non-const invaluable reference to a bit-field (11.6.3 — end example].
