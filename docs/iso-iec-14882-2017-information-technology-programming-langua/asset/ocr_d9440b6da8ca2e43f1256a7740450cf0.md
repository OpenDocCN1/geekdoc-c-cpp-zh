If the function selected by overload resolution (16.3) can be determined without instantiating a class template, it is unspecified whether that instantiation actually takes place. [Example:

```
template <class T> struct S {
    operator int();
};

void f(int);
void f(S<int>);
void f(S<float>);

void g(S<int>& sr) {
    f(sr); // instantiation of S<int> allowed but not required
          // instantiation of S<float> allowed but not required
}
// end example
```

If a function template or a member template specialization is used in a way that involves overload resolution, a declaration of the specialization is implicitly instantiated (17.8.3).

An implementation may not implicitly instantiate a virtual function template, a member template, a non-virtual member function, a member class, a static data member of a class template, or a substatement of a constexpr (14.1), unless instantiation is required. It is unspecified whether an implementation implicitly instantiates a virtual function of a class template or the virtual member function would otherwise be instantiated. Use of a template specialization in a default argument shall cause the template to be instantiated except that a class template may be instantiated where the complete type is needed to determine the correctness of the argument. The use of a default argument in a function call causes specializations in the default argument to be implicitly instantiated.

Implicitly instantiated class, and variable template specializations are placed in a namespace where the template is defined. Implicitly instantiated specializations for members of a class template are placed in the namespace where the enclosing class template is defined. Implicitly instantiated member templates are placed in the namespace where the enclosing class or class template is defined. [Example:

    };

    void g(Map<const char*,int>& m) {
        int i = m.get("Nicholas");
