+   If T is the name of a class, then each of the following shall have a name different from T:
- every data member of class T;
- every member function of T [Note: This restriction does not apply to constructors, which do not have names (15.1) — end note];
- every class of T that is itself a type;
- every member template of T;
- every enumerator of every member of class T that is an unscoped enumerated type; and
- every member of anonymous union that is a class of T.

In addition, if T has a user-declared constructor (15.1), or non-static data member of class T shall have a name different from T:

The common sequence of two standard-layout struct (Clause 12) types is the longest sequence of non-static data members and bit-fields in declaration order, starting with the first entity in each of the structs, such that corresponding entities have layout-compatible types and neither entity is a bit-field or both are bit-fields with the same width. [Example]:

```
struct A { int a; char b; }
struct B { const int b; volatile char b2; }
struct C { unsigned c; char b; }
struct D { int d; char b; }
struct E { unsigned int e; char b; }
```

The common initial sequence of A and B contains all members of each class. The common initial sequence of A and C and A and D contains the first of each. The common initial sequence of A and E is empty. — end example.

Two standard-layout structs (Clause 12) types are layout-compatible classes if they have the same number of non-static data members and corresponding bit-fields of both classes (6.9).

In a standard-layout union with an active member (12.3) of struct type T1, it is permitted to read a non-static data member of another union of struct type T2 provided it is part of the common initial sequence of T1 and T2; the behavior is as if the active member of T1 was nominated. [Example]:

```
struct T1 { int a; char b; }
struct T2 { int c; double d; }
union { T1 t1; T2 t2; }
int f() {
u u { 1, 2; } // active member is t1
return u.t2.c; // OK, if u.t1 was nominated
}
```

— end example — [Note: Reading a volatile non-volatile gvalue has undefined behavior (10.7.1). — end note

If a standard-layout class object has any non-static data members, its address is the same as the address of its first base subobject (if any).
