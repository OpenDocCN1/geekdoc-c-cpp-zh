# ISO/IEC 14882:2017(E)

*Note: Even destructors for fully-constructed objects are invoked when an exception is thrown during the execution of a constructor (18.2), their exception specifications do not contribute to the exception specification of a constructor, because an exception thrown from a destructor would call std::terminate rather than escape the constructor (18.1, 18.5.1). — end note*

The exception specification for an implicitly-declared constructor, or a destructor with a noexcept-specifier, is potentially-throwing if and only if any of the destructors of its potentially constructed subobjects is potentially-throwing.

The exception specification for an implicitly-declared assignment operator, or an assignment-operator without a noexcept-specifier that is defined on its first declaration, is potentially-throwing if and only if the invocation of any assignment operator in the implicit definition is potentially-throwing.

A allocation function (6.7.4.2) with explicit noexcept-specifier has a non-throwing exception specification.

+   Example:

```
struct A {
A(int = (A(5)), 0)) noexcept;
A(const A&) noexcept;
A(A&) noexcept;
-A)();
};

struct B {
B();
B(const B&) = default; // implicit exception specification is noexcept(true)
B(B&, int) noexcept( // throw Y), O);
-(B&) noexcept(false);
};

struct D {
int n = 7;
int* p = new int[n];
// /D:D() potentially-throwing, as the new operator may throw_bad_alloc or array_bad_length
// /D:D(const D&) non-throwing
// /D:D(D&) potentially-throwing
};
```

Furthermore, if A::~() is virtual, the program would be ill-formed since a virtual function from a base class cannot have a potentially-throwing exception specification if the base class has a non-throwing exception specification. — end example

12 An exception specification is considered to be needed when:

+   (12.1) in an expression, the function is the unique lookup or the selected member of set overloaded functions (6.4, 16.3, 16.4);

+   (12.2) the function is odr-used (or, if it appears in an unevaluated operand, odr-used if the expression was evaluated);

+   (12.3) the exception specification is compared to that of another declaration (e.g., an explicit specialization or an overriding virtual function);

+   (12.4) the function is defined;

+   (12.5) the exception specification is needed for a default special member function that calls the function.
Note: A default declaration does not require the exception specification of a base member function to be evaluated until the implicit exception specification of the derived function is called, and the implicit noexcept-specifier needs the implicit exception specification to compare against. — end note
