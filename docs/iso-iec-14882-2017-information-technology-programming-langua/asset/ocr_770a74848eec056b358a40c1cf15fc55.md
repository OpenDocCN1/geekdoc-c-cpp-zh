# ISO/IEC 14882:2017(E)

# 26.3.8.4 deque modifiers

```
iterator insert(const_iterator_position, const T& x);
iterator insert(const_iterator_position, T&& x);
iterator insert(const_iterator_position, size_type n, const T& x);
template <class InputIterator>
iterator insert(const_iterator_position,
    InputIterator first, InputIterator last);
iterator insert(const_iterator_position, initializer_list<T>);

template <class Args...>\Args= replace_front(Args&... args);
template <class Args...>\Args= reference_back(Args&... args);
void& emplace_front(const_iterator_position, Args&... args);
void push_front(const T& x);
void push_front(T&& x);
void push_back(const T& x);
void push_back(T&& x);
```

*Effects:* An insertion in the middle of the deque invalidates all the iterators to the deque, but has no effect on the validity of elements of the deque.

2 *Exceptions:* If an insertion is thrown other than by the copy constructor, move constructor, assignment operator, or move assignment operator of T there are no. If an exception is thrown while inserting a single element at end, there are none. Otherwise, if an exception is thrown by the move constructor of a non-Copyable T, the effects are unspecified.

3 *Complexity:* The complexity is linear in the number of elements inserted plus the lesser of the beginning and end of the deque. Inserting a single element at the beginning or end of a deque always takes constant time and causes a call to a constructor of T.

```
iterator erase(const_iterator_position);
erator erase(const_iterator_first, const_iterator_last);
void pop_front();
void pop_back();
```

4 *Effects:* An erase operation that erases the last element of a deque invalidates only the past-the-end iterator and all iterators and references to the erased elements. An erase operation that erases neither the first element nor the last element of a deque invalidates all iterators and references to the erased elements the past-the-end iterator and all iterators and references to all elements of the deque.

> *Note:* pop_front and pop_back are erase operations.

5 *Complexity:* The number of calls to the destructor of T is the same as the number of elements erased, but the number of calls to the assignment operator of T is no less than the number of elements before the erased elements and the number of elements after the erased elements.

6 *Throws:* Unless an exception is thrown by the copy constructor, move constructor, assignment operator, or move assignment operator.

# 26.3.8.5 deque specialized algorithms

```
template <class T, class Allocator>
void swap(deque<T, Allocator>& x, deque<T, Allocator>& y)
noexcept(noexcept(swap(x, y)));
```

*Effects:* As if x.swap(y).
