7 If the value of the operand of the delete-expression is not a null pointer, then

+   (7.1) If the allocation for the new-expression for the object to be deleted was not omitted and the allocation was not extended (8.3.4), the delete-expression shall call a deallocation function (6.7.4.2). The value returned from the allocation of the new new-expression shall be passed as the first argument to the deallocation function.

+   (7.2) Otherwise, if the allocation was extended or provided by the allocation of another new-expression, the delete-expression for every pointer value produced by a new-expression has been evaluated, the delete-expression shall call a deallocation function. The value returned from the allocation of the extended new-expression shall be passed as the first argument to the deallocation function.

+   (7.3) Otherwise, the delete-expression shall not call a deallocation function.

> [Note: The deallocation function is called regardless of whether the delete for the object or some element of the array throws. — end note.] If the value of the operand of the delete-expression is a null pointer, it is specified whether a deallocation function shall be described as above.

9 When the delete in a delete-expression is preceded by the unary :: operator, the deallocation function is looked up in global scope. Otherwise, the class-specific deallocation function (15.5) is found. If no class-specific deallocation function is found, the deallocation function is looked up in global scope.
