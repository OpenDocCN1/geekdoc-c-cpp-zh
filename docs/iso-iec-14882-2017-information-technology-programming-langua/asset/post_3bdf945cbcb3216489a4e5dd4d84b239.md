
# ISO/IEC 14882:2017(E)

The potential scope of a function parameter name (including one appearing in a lambda-declaration) or of a function-local variable in a function definition (11.4) begins at its point of declaration. If the function has a function-try-block the potential scope of a parameter or of a function-local variable ends at the end of the last handler, otherwise it ends at the end of the outermost block of the function definition. A parameter name shall not be redeclared in the outermost block of the function definition not in the outermost block of any handler with a function-try-block.

The name declared in an exception-declaration is local to the handler and shall not be redeclared in the outermost block of the handler.

Names declared in the init-statement, the for-declaration, and in the condition of if, for, or switch statements (including the controlled statement), shall not be redeclared in a subsequent condition of that not in the outermost block (or, for the if statement, any of the blocks) of the controlled statement; see 9.4.

## 6.3.4 Function prototype scope [basic.scope.proto]

In a declaration, or in any declaration except the declarator of a function definition (11.4), names of parameters (if supplied) have function prototype scope, which terminates at the end of the nearest enclosing declaration.

## 6.3.5 Function scope [basic.scope.fscope]

- Labels (9.1) have function scope and may be used anywhere in the function in which they are declared. Only labels have function scope.

## 6.3.6 Namespace scope [basic.scope.namespace]

The declared region of a namespace-definition is its namespace-body. Entities declared in a namespace-body are said to be member names of the namespace, and names introduced by these declarations into the declaration region of the namespace. A member name has namespace scope. Its potential scope includes its namespace from the member's point of declaration (6.3.2) onwards; and for each using-directive (10.3.4) that nominates the member's namespace, the member's potential scope includes that of the potential scope of the using-directive that follows the member's point of declaration. Example:

```cpp
namespace N {
int i;
int g(int a) { return a; }
int j();
void q();
}
namespace N {
int i=1;
// the potential scope of i is from its point of declaration to the end of the translation unit
```

```cpp
namespace N {
int g(int a) { // error: duplicate definition
return a;
} // 1 is from unnamed namespace
}
```

```cpp
int i;
int j();
// OK: duplicate function declaration
```

```cpp
int j() {
return g();
// OK: definition of N::j
calls N::g(int)
} // error: different return type
```
-- end example |

- 3 The most therefore declaration of a translation unit is also a namespace, called the global namespace. A name declared in the global namespace has global namespace (also called global scope). The potential scope of such a name begins at its point of declaration (6.3.2) and ends at the end of the translation unit that its declaration. A name with global namespace is said to be a global name.

## 6.3.7 Class scope [basic.scope.class]

- 1 The potential scope of a name declared in a class consists not only of the declarative region following the name's point of declaration, but also of all function bodies, default arguments, noexcept-specifiers, and brace-or-initializers of non-static members (including such things in nested).

- 2 A N named in a class S shall refer to the same declaration in this context and when reevaluated in the complete scope of S. No diagnostic is required for a violation of this rule.

- 3 A name declared within a member function refers to the declaration of the same name whose scope extends to end of the member function's class.

- 4 The potential scope of a declaration that extends to past the end of a class definition also extends to the regions defined by its member definitions, even if the members are legally outside the class (which includes static member definitions, nested classes, and member functions, including the member function body and any portion of the declarator part of such definitions which follows the declarator-id, including a parameter-declaration-clause and any default arguments (11.3.6).

## 6.3.8 Enumeration scope [basic.scope.enum]

- 1 The name of the scoped enumerator (10.2) has enumeration scope. Its potential scope begins at points of declaration and terminates at the end of the enum-specifier.

## 6.3.9 Template parameter scope [basic.scope.temp]

- 1 The declarative region of the name of a template parameter is the smallest template-parameter-list in which the name was introduced.

- 2 The declarative region of the name of a template parameter is the smallest template-declaration in which the name was introduced. Only template parameter belongs to this declarative region; any other kind of name introduced by declaration of a template-declaration is introduced into the same declarative region or as a result of a non-template declaration of the same name.
Example:
```cpp
namespace N {
    template<class T> struct A {}; // #1
    template<class D> void F() {} // #2
    struct B {
        template<class V> int g(V* C); // #3
    };
}
```
The declarative regions of the template-declarations on T and U are #1, #2, and #3, respectively. The names A, F and C all belong to the same declarative region — namely, the namespace-body of N. (G is still declared to belong to this declarative region while being hidden during qualified and unqualified lookup.) — end example

The potential scope of a template parameter name begins at its point of declaration (6.3.2) and ends at the end of its declarative region. ## 6.3.10 Name hiding [basic.scope.hiding]

- 1 A name can be hidden by an explicit declaration of that name in a nested region or divided class (13.2).

- 2 A class name (12.1) or enumeration (10.2) can be hidden by the name of a variable, data member, function, or enumer declared in the same scope. If a class or enumeration name and a variable, data member, function, or enumerator are declared in the same scope (with the same name), then the class or enumeration is hidden where the variable, data member, function, or enumerator is visible.

- 3 In a member function, the declaration of a name at block scope hides the declaration of the class with the same name: 6.3.7. The declaration of a member hides the declaration of a member of a class of the same name: 13.2.

- 4 During the lookup of a name qualified by a namespace, declarations that would otherwise be made visible by a using-directive are hidden by declarations with the same name in the namespace containing the using-directive: 6.4.3.2.

- 5 If a name is in scope and it is not hidden it is to be visible.

## 6.4 Name lookup [basic.lookup]

- 1 The rule lookup applies to all names (including typedef-names (10.1.3), namespace-names (10.3), and class-names (12.1)) which the grammar allows in the contexts discussed by a particular rule. Rule lookup should find for each use of a name either the entire entity or all declarations (16.1). Overall resolution (16.3) takes place after name lookup has succeeded. The access rules (Clause 14) are considered only once name lookup and overload resolution have. After name lookup, function overload (if applicable) and access checking survived are the attributes introduced by the name's declaration used further in expression processing (Clause 8).

- 2 A name “looked up in the context of an expression” (Clause 12) is considered an unqualified name in the scope where the expression is found.

- 3 The injected-class-name of a (Clause 12) is also considered to be a member of that class for the purposes of name hiding and lookup.

[Note: 6.5 discusses issues. The notions of scope, point of declaration and name hiding are discussed in 6.3 — end note.]

## 6.4.1 Unqualified name lookup [basic.lookup.unqual]

- 1 In all cases listed in 6.4.1, the scopes are searched for a declaration in the order listed in the respective categories: name lookup ends as soon as a declaration is found. If no declaration is found, the program is ill-formed.

- 2 The declarations from the namespace nominated by a using-directive become visible in a namespace enclosing the using-directive: 10.3.4. For the purpose of the unqualified name lookup rules described in 6.4.1, the declarations from the namespace nominated by the using-directive are considered members of enclosing namespace.
