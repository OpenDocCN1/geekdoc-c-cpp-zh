The semantics of initializers are: otherwise, the type of the object or reference initialized and the *source* type is the type of the initializer. If the initializer is not a single (possibly parenthesized) expression, the source type is not defined.

- (17.1) If the initializer is a (non-parenthesized) braced-list or is, the object or reference is list-initialized (11.6.4).

- (17.2) If the destination is a reference type, see 11.6.3.

- (17.3) If the destination is any type of characters, an array of char16_t, an array of char32_t, or an array of wchar_t, and the initializer is a literal string, see 11.6.2.

- (17.4) If the initializer is (), the object is value-initialized.

- (17.5) Otherwise, if the destination is an array, it is program-initialized.

- (17.6) If the destination is a type (possibly cv-qualified) class:
    - If the initializer is an expression and the cv-unqualified version of the source type is the class as the class of the destination, the initializer expression is used to initialize the destination object. [Example: x = T(T(T())); calls the T default constructor to initialize x. — example]

- (16.2) Otherwise, if the destination is direct-initialization, or if it is copy-initialization where the cv-unqualified version of the source type is the same as, or a derived class of, the class, the constructors are chosen through overload resolution (16.3), and the best one is chosen to select and initialize the object, the initializer expression or braced-list is used as its argument. If no constructor applies, the overload resolution is ambiguous, the initialization is ill-formed.

- (17.3) Otherwise (i.e., for matching copy-initializations), user-defined conversion sequences that can convert the source to the destination type (or when a conversion function is used) a derived class thereof are enumerated as described in 16.3.4, and the best one is chosen through overload resolution (16.3). If the conversion cannot be done or is ambiguous, the initialization is ill-formed. The function selected with the initializer expression as its argument; if the function is a constructor, it is a value of the cv-unqualified version of the destination type whose result object is initialized by the constructor. The call is used to direct-initialize, to the rules above, which is the destination of the copy-initialization.

- (17.7) Otherwise, if the source type is a (possibly cv-qualified) class type, conversion functions are considered. The applicable conversion functions are enumerated ([16.3.1.5]), and the best one is chosen through overload resolution ([16.3]). The user-defined conversion so selected to convert the initializer expression into the object being initialized. If the conversion cannot be done or is ambiguous, the initialization is ill-formed.

- (17.8) Otherwise, the value of the object being initialized is the (possibly converted) value of the initializer expression. Standard conversions (Clause 7) will be used, if necessary, to convert the initializer expression to the cv-unqualified value of the destination type; no user-defined conversions are considered. If the conversion cannot be done, the initialization is ill-formed. When initializing a bitfield with a value that cannot represent, the resulting value of the bitfield is implementation-defined.

## 11.6.1 Aggregates

[dcl.init.aggr] An aggregate is an array or class (Clause 12)

- 1 — user-provided, explicit, or inherited constructors ([15.1).
    - (1.1) — private or protected non-static data members (Clause 14),
    - (1.2) — virtual functions
    - (1.4) — virtual, private, or protected base classes ([13.1).

> [Note: Aggregate initialization does not allow accessing and private class members' constructors. — end note].

- 2 The elements of the aggregate are:
    - (2.1) — for array, the array elements in the array,
    - (2.2) — for class, the data in order, followed by non-static data members ([12.2.2.3) that are not members of an anonymous union, or
    - 3 When an aggregate is initialized by an initializer list, the elements of the initializer list are taken as initializers for the elements of the aggregate, in order. If the initializer-clause is absent and a narrowing conversion (11.6.4) is required, the program is ill-formed. [Note: If an initializer-clause is itself an initializer list, the element is list-initialized, which will result in recursive application.

- 4. An aggregate that can also be initialized with a single expression not in braces, as described in [11.6](https://en.cppreference.com/w/cpp/language/class_initial_list).

- 5. An array of unknown bound initialized as a one-dimensional array that has three elements since no size was specified and there are three initializers. — [11.3.4]. [Example:
int x[] = { 1, 3, 5 };
declares and initializes x as an empty initializer list {} should not be used as the initializer-clause for an array of unknown bound.¹⁵ [Note: A default member initializer does not determine the bound for a member array of unknown bound. The default member initializer is ignored if a suitable member-initializer is present (15.6.2), the default member initializer is not considered to initialize the array of unknown bound.] [Example:

```cpp

    int x;
