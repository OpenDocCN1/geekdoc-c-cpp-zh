# 18.2 Constructors and destructors [except.ctor]

-   1 As control passes from the point where an exception is thrown to a handler, destructors are invoked by a process, specified in this section, called stack unwinding.
2 The destructor is invoked for each atomic object of class constructed, but not yet destroyed, since the block was exited. If an exception is thrown during the destruction of temporaries or local variables for a return statement (9.6.3), the destructor for the returned object (if any) is also invoked. The objects are destroyed in the reverse order of the completion of their construction. [Example:

```cpp
struct A {

struct Y : Y() noexcept { throw 0; }; };

A f() {
try {
  A;
  Y;
  B;
  return ();
} catch (...) { // 1
  return ();
} // 2 }
```

At #1, the returned object of type A is constructed. Then, the local variable b is destroyed (9.6). Next, the local variable y is destroyed, causing unwinding, resulting in the destruction of the returned object, followed by the destruction of the local variable a. Finally, the returned object is constructed again at #2.
— end example]

# 18.3 Handling an exception [except.handle]

-   1 The exception-declaration in a handler describes the type(s) of exceptions that can handler to be entered. The exception-declaration shall not denote an incomplete type, an abstract class type, or an value reference type. The exception-declaration shall not denote a pointer or reference to an incomplete type, other void*, const void*, volatile void*, or const volatile void*.
2 A handler of type "array of T" or function type T is adjusted to be type "pointer to T".
3 A handler is a match for an exception object of type E

(3.1) The handler is of type T or cv T& and E are the same type (ignore the top-level cv-qualifiers), or

(3.2) the handler is of type cv T or cv T& and T is an unambiguous public class of E, or

(3.3) the handler is of type cv T or const T& where T is a pointer or pointer to member type and E is a pointer or pointer to member type that can be converted to

    (3.3.1) a standard pointer conversion (7.11) not involving convolutions to pointers or protected or ambiguous classes

    (3.3.2) a function pointer conversion (7.13)

    (3.3.3) a qualification conversion (7.5), or

(3.4) the handler is of type T or const T& where T is a pointer or pointer to member type and E is nullptr_t.

> Note: A type-expression which is an integral with value zero does not match a handler of pointer or member type. A handler of reference to array or function is never a match for any exception object (8.17).—end note
