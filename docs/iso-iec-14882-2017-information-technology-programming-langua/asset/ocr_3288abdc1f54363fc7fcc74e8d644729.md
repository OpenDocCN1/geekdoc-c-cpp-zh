# 18.2 Constructors and destructors [except.ctor]

+   1 As control passes from the point where an exception is thrown to a handler, destructors are invoked by a
process, specified in this section, called stack unwinding.
2 The destructor is invoked for each atomic object of class constructed, but not yet destroyed, since
the block was exited. If an exception is thrown during the destruction of temporaries or local variables
for a return statement (9.6.3), the destructor for the returned object (if any) is also invoked. The objects
are destroyed in the reverse order of the completion of their construction. [Example:

```
struct A {

struct Y : Y() noexcept { throw 0; }; };

A f() {
try {
  A;
  Y;
  B;
  return ();
} catch (...) { // 1
  return ();
} // 2 }
```

At #1, the returned object of type A is constructed. Then, the local variable b is destroyed (9.6). Next, the
local variable y is destroyed, causing unwinding, resulting in the destruction of the returned object,
followed by the destruction of the local variable a. Finally, the returned object is constructed again at #2.
— end example]

+   3 If the initialization or destruction of an object other than by delegating constructor is terminated by
anexception, the destructor is invoked for each of the object's direct subjects, and for a complete object,
virtual base class subclasses, whose initialization has completed (11.6) and whose destructor has not
begun execution, in the case of destruction, the variant members of a union-like class are
destroyed. The destruction is sequenced before entering a handler of a function-block of the constructor or destructor,
if any.

+   4 If the compound-statement of the function-body of a delegating constructor for an object exits via an
exception, the destructor's object is invoked. Such destruction is sequenced before entering a handler of the
function-block of a delegating constructor for that object, if any.

+   5 [Note: If the object was allocated by a new-expression (8.3.4), the matching declaration function (6.7.4.2),
if, is safe to free the storage occupied by the object. — end note]

# 18.3 Handling an exception [except.handle]

+   1 The exception-declaration in a handler describes the type(s) of exceptions that can handler to be
entered. The exception-declaration shall not denote an incomplete type, an abstract class type, or an value
reference type. The exception-declaration shall not denote a pointer or reference to an incomplete type, other
void*, const void*, volatile void*, or const volatile void*.
2 A handler of type "array of T" or function type T is adjusted to be type "pointer to T".
