# ISO/IEC 14882:2017(E)

Identifiers that are keywords or operators in C++ shall not be defined as macros in C++ standard library headers.171

D.5, Standard library headers, describes the effects of using the name.h (C header) form in C++ program.172

Annex K of the standard describes a large number of functions, with associated types and macros, "promote safer, more secure programming" than many of the traditional C headers. The names of the functions have a suffix of _: most of them provide the same behavior as the C library with the unsigned name, if namely an additional argument which is the size of the result. If any C++ header is included, it is implementation-defined whether any of names are declared in the global namespace. (One of them is declared in std).

# 20.5.1.3 Freanding implementations [compliance]

Two implementations are defined: hosted and freestanding (4.1). For a hosted implementation, the document describes the set of available headers.

A freestanding implementation has an implementation-defined set of headers. This set shall include at least the headers shown in Table 19.

The supplied version of the header <stddef> shall declare at least the functions abort, atxit, quick_exit_, and quick_exit (21.5). The other headers in this table shall meet the same requirements as a hosted implementation.

# 20.5.2 Using the library [using.overview]

## 20.5.2.1 Overview

1 This describes how a C++ program gains access to the facilities of the C++ standard library. 20.5.2.2 describes effects during phase 4, 20.5.2.3 describes effects during phase 8 (5).

## 20.5.2.2 Headers [using.headers]

1 The entities in the C++ standard library are defined in headers, whose contents are available to a translation unit when it contains the include directive (2).
2 A translation unit may include library headers in any order (Clause 5). It may be included more than once, with no effect except that the effect of <cassert> or assert. depends each time on NDEBUG.
3 A translation unit should include a header only after any declaration or definition, and should include it lexically before the first reference in that translation unit to any of the entities. No diagnostic is required.

## 20.5.2.3 Linkage [using.linkage]

1 Entities in the C standard library have external linkage (6.5). Unless otherwise specified, objects and functions have the default "C" (10.5).
2 Whether a standard library entity declared with external linkage have "C" or "C++" linkage is implementation-defined. It is recommended that an implementation use "C++" linkage for this purpose.174
3 Objects and functions defined in the library and required by a C++ program are included in the program prior to startup.
4 See also replacement functions (20.5.4.6), runtime changes (20.5.4.7).

173) This is the same as
174) The only way to declare an object or function signature for the C standard is by including the header, notwithstanding the latitude granted in 7.1.4 the C Standard.

## 20.5.3.1 Template argument requirements [utility.arg.requirements]

The templates in the C++ standard library refer to various names whose details are set out in Tables 20–27. In these cases, T is an object or reference type to be supplied by a C++ program instantiating a template; a, b, and c are values of type (possibly) T; s and t are modifiable of type; t denotes an identifier; rv is an value of T; and v is an value of type (possibly) T or an value of T.
