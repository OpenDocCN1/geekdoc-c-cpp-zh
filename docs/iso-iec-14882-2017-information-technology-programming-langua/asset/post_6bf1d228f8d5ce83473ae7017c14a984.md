## 16.3.4.1 Reference binding

+ 1 When a parameter of reference type binds directly, the conversion sequence is the identity, unless the argument expression has a type that is a derived class of the type, in which case the conversion sequence is a derived-to-Base Conversion (16.3.3.1). [Example:

```cpp
struct A {};
struct B : A { B(); };
int f();
int i = f(b); // an exact match, rather than f(&a), a conversion
```

> - If parameter binds directly to the result of applying a function to the argument, the implicit conversion is a user-defined conversion sequence (16.3.3.1.2), with the second standard conversion sequence either identity conversion or, if the function returns an entity of a type that is a derived class of the parameter type, a derived-to-Base conversion.

+ 2 When a parameter of reference type is not bound directly to an argument expression, the conversion sequence is the one required to convert the argument expression to the referenced type according to 16.3.3.1. Conceptually, this conversion sequence corresponds to copy-initializing a temporary of the referenced type with the argument expression. An initialization is performed by the rules of the type and does not constitute a conversion.

+ 3 Except for an implicit object parameter, see 16.3.1, a standard conversion sequence cannot be formed if it requires binding an invaluable reference to a non-const type or binding an invaluable reference to anything other than a value. ## 16.3.3.1.5 List-initialization sequence

1 When an argument is an initializer list (11.6.4), it is not an expression and special rules for converting it to a parameter apply.

2 If the parameter type is an aggregate class X and the initializer list has a single element of type U, where U is X or a class derived from X, the implicit conversion sequence is the one required to convert the element to the parameter type.

3 Otherwise, if the parameter type is a string literal and the initializer list has a single element that is an appropriately-typed string (11.6.2), the implicit conversion sequence is the identity conversion.

4 Otherwise, if the parameter type is std::initializer_list<X> and all the elements of the initializer list can be converted to X, the implicit conversion sequence is the worst conversion necessary to convert an element of the list to X, or if the initializer list has no elements, this conversion can be a user-defined conversion in the context of a call to an initializer-list constructor. Example:

```cpp
void f(std::initializer_list<int> list){
  f(0); // OK: initializer_list<int> identity conversion
  f(1, 0); // OK: initializer_list<int> identity conversion
  f('a', 'b'); // OK: initializer_list<int> integral promotion
  f(1.0); // error: narrowing
}

struct A {
  A(std::initializer_list<double>); // #1
  A(std::initializer_list<complex<double>>); // #2
  A(std::initializer_list<std::string>); // #3
  A(1.0, 2.0 : 0); // OK, uses #1
};

void g(A) {
  g("bar"); // OK, uses #3
}

typedef IA[3];
void h(const IA){
  h(1, 2, 3); // OK: identity conversion
}
```

5 Otherwise, if the parameter is an array of X, if there exists an implicit conversion sequence for each element of the array from the corresponding element of the initializer list (or from {} if there is no such element), the implicit conversion sequence is the worst such implicit sequence.

6 Otherwise, if the parameter is a non-aggregate class X and overload resolution 16.3.1.7 chooses a best constructor C of X to perform the initialization of an object of X from the argument list:

> (6.1) If C is not an initializer-list constructor and the initializer list has a single element of type U, where U is X or a class derived from X, the implicit conversion sequence has Exact Match rank if U is X, or Conversion rank if U is derived from X.

+ Otherwise, the implicit sequence is a user-defined conversion with the second standard conversion sequence an identity conversion.

If multiple constructors are viable but none better than the others, the implicit conversion sequence is allowed for user-defined conversions to the initializer list constructor parameter types as noted in 16.3.3.1. Example:

```cpp
struct A {
  A(std::initializer_list<int>);
};
void f(A);
f('a', 'b'); 
    // OK: f(A(std::initializer_list<int>)) user-defined conversion

struct B {
    B(int, double);
};
void g(B);
g('a', 'b'); 
    // OK: g(B(int, double)) user-defined conversion
g(1.0, 1.0); 
// error: narrowing

void f(B);
f('a', 'b'); 
    // error: ambiguous f(A) or f(B)

struct C {
    C(std::string);
};
void h(C);
h("foo"); 
    // OK: h(C(std::string("foo")))

struct D {
    D(A);
};
void i(D);

```
