# ISO/IEC 14882:2017(E)

The potential scope of a function parameter name (including one appearing in a lambda-declaration) or of a function-local variable in a function definition (11.4) begins at its point of declaration. If the function has a function-try-block the potential scope of a parameter or of a function-local variable ends at the end of the last handler, otherwise it ends at the end of the outermost block of the function definition. A parameter name shall not be redeclared in the outermost block of the function definition not in the outermost block of any handler with a function-try-block.

The name declared in an exception-declaration is local to the handler and shall not be redeclared in the outermost block of the handler.

Names declared in the init-statement, the for-declaration, and in the condition of if, for, or switch statements (including the controlled statement), shall not be redeclared in a subsequent condition of that not in the outermost block (or, for the if statement, any of the blocks) of the controlled statement; see 9.4.

# 6.3.4 Function prototype scope [basic.scope.proto]

In a declaration, or in any declaration except the declarator of a function definition (11.4), names of parameters (if supplied) have function prototype scope, which terminates at the end of the nearest enclosing declaration.

# 6.3.5 Function scope [basic.scope.fscope]

+   Labels (9.1) have function scope and may be used anywhere in the function in which they are declared. Only labels have function scope.

# 6.3.6 Namespace scope [basic.scope.namespace]

The declared region of a namespace-definition is its namespace-body. Entities declared in a namespace-body are said to be member names of the namespace, and names introduced by these declarations into the declaration region of the namespace. A member name has namespace scope. Its potential scope includes its namespace from the member's point of declaration (6.3.2) onwards; and for each using-directive (10.3.4) that nominates the member's namespace, the member's potential scope includes that of the potential scope of the using-directive that follows the member's point of declaration. Example:

```
namespace N {
int i;
int g(int a) { return a; }
int j();
void q();
}
namespace N {
int i=1;
// the potential scope of i is from its point of declaration to the end of the translation unit
```

```
namespace N {
int g(int a) { // error: duplicate definition
return a;
}// 1 is from unnamed namespace
}
```

```
int i;
int j();
// OK: duplicate function declaration
```

```
int j() {
return g();
 OK: definition of N::j
calls N::g(int)
}// error: different return type
```
