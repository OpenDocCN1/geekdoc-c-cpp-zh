# 6.3.10 Name hiding [basic.scope.hiding]

+   1 A name can be hidden by an explicit declaration of that name in a nested region or divided class (13.2).

+   2 A class name (12.1) or enumeration (10.2) can be hidden by the name of a variable, data member, function, or enumer declared in the same scope. If a class or enumeration name and a variable, data member, function, or enumerator are declared in the same scope (with the same name), then the class or enumeration is hidden where the variable, data member, function, or enumerator is visible.

+   3 In a member function, the declaration of a name at block scope hides the declaration of the class with the same name: 6.3.7. The declaration of a member hides the declaration of a member of a class of the same name: 13.2.

+   4 During the lookup of a name qualified by a namespace, declarations that would otherwise be made visible by a using-directive are hidden by declarations with the same name in the namespace containing the using-directive: 6.4.3.2.

+   5 If a name is in scope and it is not hidden it is to be visible.

# 6.4 Name lookup [basic.lookup]

+   1 The rule lookup applies to all names (including typedef-names (10.1.3), namespace-names (10.3), and class-names (12.1)) which the grammar allows in the contexts discussed by a particular rule. Rule lookup should find for each use of a name either the entire entity or all declarations (16.1). Overall resolution (16.3) takes place after name lookup has succeeded. The access rules (Clause 14) are considered only once name lookup and overload resolution have. After name lookup, function overload (if applicable) and access checking survived are the attributes introduced by the name's declaration used further in expression processing (Clause 8).

+   2 A name “looked up in the context of an expression” (Clause 12) is considered an unqualified name in the scope where the expression is found.

+   3 The injected-class-name of a (Clause 12) is also considered to be a member of that class for the purposes of name hiding and lookup.

# 6.4.1 Unqualified name lookup [basic.lookup.unqual]

+   1 In all cases listed in 6.4.1, the scopes are searched for a declaration in the order listed in the respective categories: name lookup ends as soon as a declaration is found. If no declaration is found, the program is ill-formed.

+   2 The declarations from the namespace nominated by a using-directive become visible in a namespace enclosing the using-directive: 10.3.4. For the purpose of the unqualified name lookup rules described in 6.4.1, the declarations from the namespace nominated by the using-directive are considered members of enclosing namespace.
