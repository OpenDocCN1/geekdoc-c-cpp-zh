## 26.3.11 Class template vector [vector.overview]

### 26.3.11.1 Class template vector overview

- 1 A vector is a container that supports (amortized) constant time insert and erase operations at the end; insert and erase in the middle linear time. Storage management is handled automatically, though hints can be given to improve efficiency.
- 2 A vector satisfies all the requirements of a container and of a reversible container (given in tables in 26.2), of sequence container including most of the optimal sequence container requirements (26.2.3), of an allocator-aware container (Table 80), and for an element type other than bool, of a contiguous container (26.2.1). The operations are push_front, pop_front member functions, which are not provided. Descriptions are provided here only for operations on vector that are not described in one of these tables or for operations where additional semantic information.

```cpp
namespace std {
template <class T, class Allocator = allocator<T>>
class vector {
  // types:
  using value_type = T;
  using allocator_type = Allocator;
  using pointer = typename allocator_traits<Allocator>::pointer;
  using const_pointer = typename allocator_traits<Allocator>::const_pointer;
  using reference = value_type&;
  using const_reference = const value_type&;
  using difference_type = implementation_defined; // see 36.2
  using implementation_defined = implementation_defined; // see 36.2
  using iterator = implementation_defined; // see 36.2
  using const_iterator = implementation_defined; // see 36.2
  using reverse_iterator = std::reverse_iterator<iterator>;
  using const_reverse_iterator = std::reverse_iterator<const_iterator>;
```

### 26.3.11.2 vector constructors, copy and assignment

```cpp
vector(const Allocator&);
- 1 Effects: Constructs an empty vector, using the specified allocator.
- 2 Complexity: O(1). 
```

```cpp
explicit vector(size_type n, const Allocator& alloc = Allocator());
- 3 Effects: Constructs a vector with n default-inserted elements using the specified allocator.
- 4 Requires: T shall be DefaultInsertable into *this.
- 5 Complexity: Linear in n.
```

```cpp
vector(size_type n, const T value,
const Allocator& alloc = Allocator());
- 6 Effects: Constructs a vector with n copies of value, using the specified allocator.
- 7 Requires: T shall be CopyInsertable *this.
- 8 Complexity: Linear in n.
```

```cpp
template <class InputIterator>
vector(InputIterator first, InputIterator last,
       const Allocator& alloc = Allocator());
- 9 Effects: Constructs a vector equal to the range [first, last].
- 10 Complexity: Makes only N calls to the copy constructor of T (where N is the distance between first and last) and no reallocations if iterators first and last are of forward, bidirectional, or random access. It makes calls to the copy constructor of T and log N reallocations if they are just input iterators.
```

## 26.3.11.3 vector capacity [vector.capacity]

```cpp
size_type capacity() const;
- 1 Returns: The total number of elements that the vector can hold without requiring reallocation.
```

```cpp
void reserve(size_type n);
- 2 Effects: A directive that informs the vector of a planned size, so that it can manage the storage accordingly. After reserve(), capacity() is greater or equal to the argument of reserve if reallocation happens at this point or if the current capacity is less than the argument of reserve(). If an exception is thrown other than the move constructor of a non-Copyable type, there are no effects.
- 3 Complexity: It does not change the size of the sequence and takes at most linear time in the size of the sequence.
- 5 Throws: length_error if n > max_size().
- 6 Remarks: Reallocation invalidates the references, pointers, and iterators referring to the elements in the sequence. No reallocation shall take place during insertions that happen after a call to reserve() until the would make the size of the vector greater than the value of capacity().
```

```cpp
void shrink_to_fit();
- 7 Requires: T shall be MoveInsertable *this.
- 8 Effects: shrink_to_fit is a non-binding request to reduce capacity(). [Note: The request is non-binding to allow latitude for implementation-specific optimizations. [end note] It may increase capacity() by causing reallocation. If an exception is thrown other than the move constructor of a non-Copyable T there are no effects.
- 9 Complexity: Linear in the size of the sequence.
- 10 Remarks: Reallocation invalidates the references, pointers, and iterators referring to the elements in the sequence as well as the past-to-end iterator. If no reallocation happens, they remain valid.
```

> 260 reserve() uses Allocator::allocate() which may throw an appropriate exception.
