# 18.5 Special functions

The function std::terminate() (18.5.1) is used by the exception handling mechanism for coping with errors related to the exception handling mechanism itself. The function std::current_exception() (21.8.6) and the class std::nested_exception (21.8.7) can be used by a program to capture the currently handled exception.

# 18.5.1 The std::terminate() function

+   - In some situations the exception handling must be abandoned for subtle error handling transitions. [Note: These situations are:
- when the exception handling mechanism, after completing the initialization of the exception object before activation of a handler for the exception (18.1), calls a function that exits via an exception, or
- when the exception handling mechanism cannot find a handler for a thrown exception (18.3), or
- when the search for a handler (18.3) encounters the outermost block of a function with a non-throwing exception specification (18.4), or
- when the destruction of an object during stack unwinding (18.2) throws by an exception, or
- when initialization of a non-local variable with static or thread storage duration (6.6.3) exits via an exception, or
- when destruction of an object with static or thread duration exits via an exception (6.6.4), or
- when execution of a function registered with std::exit or std::quick_exit exits via an exception (21.5), or
- when a throw-expression (8.17) with no attempts to throw an exception and no exception is being handled (18.1), or
- when the function std::nested_exception::rethrow is called for an object that has captured no exception (21.8.7), or
- when the execution of a thread exits via an exception (33.3.2.2), or
- for a parallel algorithm whose ExecutionPolicy specifies such behavior (23.19.4, 23.19.5, 23.19.6), or when execution of an element access function (28.4.1) of the parallel algorithm exits, or
- when a call to wait(), wait_until(), or wait_for on a condition (33.5.3, 33.5.4) fails to meet a predicate.

In cases where, std::terminate() is called (21.8.4). In the situation where no handler is found, it is implementation-defined whether or not the stack is unbound before std::terminate() is called. In the situation where the search for a handler (18.3) encounters the outermost block of a function with a non-throwing exception specification (18.4), it is implementation-defined whether the stack is unwound partially, or not unwound at all before std::terminate() is called. In all other situations, the stack shall not be unbound before std::terminate(). An implementation is not permitted to prevent the stack unwinding prematurely based on a determination that the unwind process will inevitably cause a call to std::terminate().
