# 20.2 The C standard library [library.c]

The C++ standard library also makes available the facilities of the C standard library, suitably adjusted to ensure static type safety.

The descriptions of many library functions use the C standard library for the semantics of those functions. In some cases, the signatures specified in this document may be different from the signatures in the C standard library, and additional overloads may be declared in this document, but the behavior and the preconditions (including any preconditions implied by the use of an C restrict qualifier) are same unless otherwise stated.

# 20.3 Definitions [definitions]

> [Note: Clause 3 defines additional terms used everywhere in this document. — end note]

# 20.3.1 arbitrary-positional stream [defns.arbitrary.stream]

stream (described in Clause 30) can seek to any integer position within the length of the stream
[Note to entry 1]: Every arbitrary-positional stream is a repositional stream. — end note

# 20.3.2 character [defns.character]

(Clauses 24, 25, 30, and 31) object, when treated sequentially, can represent text
[Note to entry 1]: The term does not mean only char, char16_t, char32_t, and wchar_t, but any value that can be represented by a type that provides the definitions specified in these Clauses. — end note

# 20.3.3 character container type [defns.character.container]

class or a type used to represent a character
[Note to entry 1]: It is used for one of the template parameters of the string, iostream, and regular expression class types. A character container type is a POD (6.9) type. — end note

# 20.3.4 comparison function [defns.comparison]

operator function (16.5) for any of the equality (8.10) or relational (8.9) operators

# 20.3.5 component [defns.component]

a group of entity directly related as members, parameters, or return types
[Note to entry 1]: For example, the class template basic_string and the non-member function templates that operate on strings are referred to as the string component. — end note

# 20.3.12

templates, defined in Clause 30, that take two template arguments

> Note 1 entry: The arguments are named *char* and *traits*. # 20.3.18

referenceable type
type that is either an object type, a function type that does not have cv-qualifiers or a ref-qualifier, or a reference

> [Note 1 to entry: The term describes a type to which a reference can be created, including reference types. — end note]

# 20.3.19

replacement function
non-resolved function whose definition is provided by a C++ program

> [Note 1 to entry: Only one definition for such a function is in effect for the duration of the program's execution, as the result of clearing the program (5.2) and resolving the definitions of all translation units (6.5). — end note]

# 20.3.20

positional stream
stream (described in Clause 30) that can seek to a position that was previously encountered

# 20.3.21

required behavior
description of replacement function and handler function semantics apply to both the behavior by the implementation and the behavior of any such function in the program

> [Note 1 to entry: If such a function in a C++ program fails to meet the required behavior when it executes, the behavior is undefined. — end note]

# 20.3.22

reserved function
function, specified as part of the C++ standard library, that is defined by the implementation

> [Note 1 to entry: If a C++ program provides a definition for any reserved function, the results are undefined. — end note]

# 20.3.23

stable algorithm
algorithm preserves, as appropriate to the particular algorithm, the order of elements

> [Note 1 to entry: Requirements for stable algorithms are given in 20.5.5.7. — end note]

# 20.3.24

traits class
class that encapsulates a set of types and functions necessary for class templates and function templates to manipulate objects of types for which they are instantiated

# 20.3.25

valid but unspecified state
value of an object that is not specified except that the object's invariants are met and operations on the object

Example: If an object of std::vector<int> is in valid but unspecified state, x.empty() can be called unconditionally, and x.front() can be called only if x.empty() returns false.— end example

# 20.4 Method of description (Informative)

1 This clause describes the conventions used to specify the C++ standard library. 20.4.1 describes the structure of Clauses 21 through 33 and Annex D. 20.4.2 describes other editorial conventions.

# 20.4.1 Structure of each clause

# 20.4.1.1 Elements

1 Each clause contains the following elements, as applicable:

- Summary
- Requirements
- Detailed specifications
- References to C standard library

# 20.4.1.2 Summary

1 The Summary provides a synopsis of the clause, and introduces the first-level subclauses. Each clause also provides a summary, listing the headers specified in the subclause and the library entities provided in each header.

2 Paragraphs labeled "Note(s):" or "Example(s):" are informative, and other paragraphs are normative.

3 The contents of the summary and the detailed specifications include:

- macros
- values
- types
- classes and class templates
- functions and function templates
- objects

# 20.4.1.3 Requirements

1 Requirements describe constraints that shall be met by a C++ program that extends the standard library. Such extensions are generally one of the following:

- Template arguments
- Derived classes
- Containers, iterators, and algorithms that meet an interface convention
