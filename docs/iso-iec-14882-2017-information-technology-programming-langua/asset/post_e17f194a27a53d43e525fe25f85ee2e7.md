## 10.3.4 Using directive [namespace::udir]

```
using-directive:
    attribute-specifier-using namespace nested-name-specifier,namespace-name;
```

- 1 A using-directive does not appear in class scope, but may appear in namespace scope or in block scope.
[Note: When using a namespace-name in a namespace, only names are considered, see 6.4.6. -- end ] The optional attribute-specifier applies to the using-directive.

- 2 A using-directive specifies that the names in the nominated namespace are accessible after the using-directive appears. During unqualified name lookup (6.4.1), the names appear as if they were declared in the nearest enclosing namespace which contains both the using-directive and the nominated namespace. ## 10.4 The declaration

An declaration has the form

- asm-definition: attribute-specifier-seq asm ( string-literal );

The declaration is conditionally-supported; its meaning is implementation-defined. The optional attribute-specifier-seq in an asm-definition appears to the asm declaration.[Note: Typically it is used to pass information through the implementation to an assembler.—end note]

## 10.5 Linkage specifications

- All function types, names with external linkage, and variable names with external linkage have language linkage. [Note: Some of the properties associated with an entity with linkage are specific to each implementation and are not described here. For example, a particular linkage may be associated with a particular form of functions with external linkage, or with a particular calling convention.—end note] The default language linkage of all function types, functions, and variables is C++ linkage. Two function types with different language linkages are distinct if they are otherwise identical.

- C++ and non-C++ code fragments can be achieved using a linkage-specification:
linkage-specification: extern string-literal { declaration-seq_opt } extern string-literal declaration

The string-literals indicate the required linkage. This document specifies the semantics for the string-literals "C" and "C++". Use of a string-literal other than "C" or "C++" is conditionally-supported with implementation-defined semantics. [Note: Therefore, a linkage-specification with a string-literal that is unknown to the implementation requires a diagnostic. — end note] [Note: It is recommended that the spelling of the string-literal be taken from the document defining that linkage. For example, Ada (not ADA) and Fortran or FORTRAN, depending on the version. — end note]

- Every implementation should provide for linkage to functions written in the C programming language, "C", and linkage to C++, "C++". [Example:]

When linkage specifications nest, the innermost one determines the language linkage. A linkage specification does not establish a scope. A linkage-specification shall occur only in namespace scope (6.3). In a linkage-specification, the specified linkage applies to all function declarations, function names with external linkage, and variable names with external linkage declared within the linkage-specification.. [Example:
