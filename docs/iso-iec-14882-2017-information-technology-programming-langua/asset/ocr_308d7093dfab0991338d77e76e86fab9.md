# ISO/IEC 14882:2017(E)

# 14 Member access control [class.access]

+   A member of a class can be

+   (1.1) private: that is, its name can be used only by members and friends of the class in which it is declared.

+   (1.2) protected: that is, its name can be used only by members and friends of the class in which it is declared, by classes derived from that class, and by friends (see 14.4).

+   (1.3) public: that is, its name can be used anywhere without access restriction.

+   A member of a class can also access all the members to which it has access. A local class of a member function may access the member function itself may access. 113

+   Members of a class defined with the keyword class is private by default. Members of a class defined with the keywords struct or union are public by default. [Example]

```
class X {
    int a;
    // X::a is private by default
}
structstruct S {
    int a;
    // S::a is public by default
}
// example
```

Access control is applied uniformly to all names, whether the names are referred from declarations or expressions. [Note: Access control applies to names nominated by friend declarations (14.3) and using-declarations (10.3.3). -- note. In the case of overloaded function names, access control is applied to the function selected by overload. [Note: Access control applies to names, if access control is applied to a typedef name, only the accessibility of the typedef name is not considered. Accessibility of the entity referred to by the typedef is not considered. For example,

```
class A {
public:
    typedef B B;
}
void f() {
    A::B x; // OK, typedef name A::B is public
    A::B y; // access error, A::B is private
}
// end note
```

It should be noted that there is access to members and base classes that is controlled, not their visibility. Names of members are still visible, and implicit conversions to base classes are still considered, when those members and base classes are inaccessible. The interpretation of a given construct is established without regard to access control. If the interpretation established makes inaccessible member names or base classes, the construct is ill-formed.

All access controls in Clause 14 affect the ability to access a class name from the declaration of a particular entity, including parts of the declaration preceding the name of the entity being declared and,
