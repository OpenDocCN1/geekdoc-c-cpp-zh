# 33.4 Locks

1 A lock is an object that has a reference to a lockable object and may unlock the lockable object during its destruction (such as when leaving block scope). An execution agent may use a lock to manage ownership of a lockable object if it is currently managing ownership of that lockable for an execution agent. A lock does not manage the lifetime of the lockable object. [Note: Locks are intended to ease the burden of unlocking the lockable object under normal and exceptional circumstances.]

2 Some constructors take tag types which describe what should be done with the lockable object during its lock's construction.

```
namespace std {
struct defer_lock_t {};      // do not acquire ownership of the mutex
struct try_to_lock_t {};   // try to acquire ownership of the mutex
                             // without blocking
                             // assume the calling thread has already
struct adopt_lock_t {};     // obtained mutex ownership and manage it

inline constexpr defer_lock() { defer_lock {}; };
inline constexpr try_to_lock() { try_to_lock {}; };
inline constexpr adopt_lock() { adopt_lock {}; };
}
```
