## 29.6.3 Random number class templates [rand.eng]

- 1 Each type instantiated from a class template specified in this section 29.6.3 satisfies the requirements of a random number engine (29.6.4.1).
- 2 Except where specified otherwise, no function described in this section 29.6.3 throws an exception.
- 3 Except where specified otherwise, function described in this section 29.6.3 has a function parameter q of type Seeq for a template name Seeq is different from type seed_seq throws and when the invocation of q, generate throws.
- 4 Descriptions are provided in this section 29.6.3 only for operations that are not described in 29.6.4.1 or for operations where there is additional information. In particular, declarations for copy constructors, for copy assignment operators, for streaming operators, and for equality and inequality operators are not shown in the synopsis.
- 5 Each template specified in this section 29.6.3 requires one or more relationships, involving the value(s) of its non-type template parameter(s), to hold. A program instantiating any of these templates is ill-formed if any required relationship to hold.
- 6 For every random number engine and for every random number adaptor X defined in this subclause (29.6.3) and in subclause 29.6.4.4:
  — if the constructor

```
template<class Sseq> explicit X(Sseq q);
```

is called with a type Sseq that does not qualify as a seed sequence, then this constructor shall not participate in overload resolution.

if the member function

```
template<class Sseq> void seed(Sseq q);
```

is called with a type Sseq that does not qualify as a seed sequence, then this function shall not participate in overload resolution.

The extent to which an implementation defines a type cannot be a seed sequence is unspecified, except that as a minimum a type shall qualify as a seed sequence if it is implicitly convertible to X::result_type.

## 29.6.3.1 Class template linear_congruential_engine

A linear_congruential_engine random number produces integer random numbers. The state x, of size 1 and contains of a single integer. The transition algorithm is a modular linear function of the TA(x) = (a * x + c) mod m; the generation algorithm is GA(x)=x+1.

```
template<UINTType a, UINTType c, UintType m>
class linear_congruential_engine {
public:
    //
    using result_type = UINTType;
    // engine characteristics
    static const result_type multiplier = a;
    static const result_type increment = c;
    static const result_type modulus = m;
    static const result_type min() { return m == 0 ? 0 : 0; }
    static const result_type max() { return m - 1; }
    static const result_type default_seed = 1;
```

```
// constructors and seeding functions
explicit linear_congruential_engine(result_type s = default_seed);
template<class Sseq> explicit linear_congruential_engine(Sseq q);
void seed(result_type s = default_seed);
template<class Sseq> void seed(Sseq q);
```

```
// generating functions
result_type operator();
void discard(unsigned long x);
```

- 2 If the template m is 0, the modulus m used throughout this section 29.6.3.1 is numeric_limits<result_type>::max() plus 1. [Note: m is not representable as a value of type result_type.]
- 3 If the parameter m is not 0, the following rules hold: a < m and c < m.
- 4 The textual representation consists of the value of x,

```
linear_congruential_engine(result_type s = default_seed);
```

- 5 Effects: Constructs a linear_congruential_engine object. If c mod m is 0 and s mod m is 0, sets the engine's state to s mod m.
