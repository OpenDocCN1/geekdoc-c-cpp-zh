
# ISO/IEC 14882:2017(E)

8- If a substitution results in an invalid type or expression, type deduction fails. An invalid type or expression is one that will be ill-formed, with a diagnostic required, if using the substituted arguments. [Note: If no diagnostic is required, the program is ill-formed. Access checking is part of the substitution process.—end note] Only invalid types and expressions in the immediate context of the function and its template parameters can result in a deduction failure. [Note: The substitution into types and expressions can result in effects such as the instantiation of class template specializations and/or function template specializations, the generation of implicitly-defined functions, etc. Such effects are not in the immediate context and can result in the program being ill-formed.—end note]

[Example:
```cpp
struct X { };
struct {
    X(int);
};

template <class T> auto f(T t1, T t2) -> decltype(t1 + t2); // #1
X(Y, Y); // #2

X x1, x2;
X3 = f(x1, x2); // deduction fails on #1 (cannot add X*X), calls #2
```—end example]

[Note: Type deduction may fail for the following reasons:

- (8.1) Attempting to instantiate a pack expansion containing multiple parameter packs of different lengths.
- (8.2) Attempting to create an array with an element that is void, a function type, a reference type, or an abstract class type, or attempting to create an array with a size that is zero or negative. [Example:
```cpp
template <T> int f(T*);
i = f<int>(0);
int j = f<void>(0); // invalid array
```—end example]

- (8.3) Attempting to use a type that is not a class or enumeration in a qualified name. [Example:
```cpp
template <class T> int f(typename T::B*);
int i = f<int>(0);
```—end example]

- (8.4) Attempting to use a type in a nested-name-specifier of a qualified-id when that type does not contain the specified member, or

- (8.4.1) the specified member is not a type where a type is required,
- (8.4.2) the specified member is not a template where a template is required,
- (8.4.3) the specified member is not a non-type where a non-type is required.

[Example:
```cpp
template <int> struct X {};
template <class T> class Z { };
template <class T> void f(typename T::*)();
template <class T> void g(XCT::N*)();
template <class T> void h(ZCT::TT*)();
struct A {};
struct B { int Y; };
struct C {};

typedef int N;
struct D {
    typedef int TT;
};

int main() {
    // Deduction fails in each of these cases:
    f<A>(0);      // A does not contain a member Y
    f<B>(0);      // The Y member of B is not a type
    g<C>(0);      // The N member of C is not a non-type
    h<D>(0);      // The TT member of D is not a template

    // end example
}
```—end example

Attempting to create a reference to pointer type.

Attempting to create a reference to void.

Attempting to create "pointer to member of T" when T is not a class type. Example:
```cpp
template <class T> int f(T*);
int i = f<int>(0);
```—end example]

Attempting to give an invalid type to a non-type template parameter. Example:
```cpp
template <class T> struct S {};
template <class T> int f(T*);

```—end example]

Attempting to perform an invalid conversion in either a template argument expression, or an expression used in the function declaration. Example:
```cpp

```—end example]

Attempting to create a function in which a parameter has a type of void, or in which the return type is a type or array type.

Attempting to create a function in which a parameter type or the return type is an abstract class type (13.4).

```cpp

### 17.8.2. Deducing template parameters from a function call [temp.deduct.call]

Template deduction is done by comparing each function parameter type (call it P) that contains template-parameters that participate in template deduction of the type of the corresponding argument of the call (call it A) as described. If removing references and cv-qualifiers from P gives `initializer_list<P>` or `P[M]` for some `P` and `N` is a non-empty initializer list (11.6.4), deduction is performed for each element of the initializer list, taking `P'` as a function parameter type and `N` is deduced from the length of the initializer list. If `P` is a non-template type, an initializer list causes the parameter to be considered a non-deduced context (17.8.2.5). Example:

```cpp
template <class T> void f(std::initializer_list<T>);
f(1,"asmdf"); // error: T deduced to both int and const char
```

```cpp
template <class T> void g(const T[]);
g(1,2,3); // no argument deduction for T
```

```cpp
template <class T, int h(const T[N]);
h(1,2,3); // T deduced to N to 3
```

```cpp
template <class T, int j(const T[M]);
j(42); // T deduced to int, array bound out of context
```

```cpp
struct Aggr { int i; int j; };
template<int N> int M k(const Aggr[M]);
k(1,2,3),Aggr(); // error: deduction fails, no conversion from Aggr to Aggr
k((1),(2), (3)); // OK. N deduced to 3
```

```cpp
template<int M, int N> void l(const T[M][N]);
l((1,2), (3,4)); // M and N both deduced to 3
```

- For a function parameter pack that occurs at the end of the parameter-declaration-list, deduction is performed for each remaining argument of the call, taking the type P of the declarator-id of the function pack as the corresponding function parameter type. Each deduction template arguments expanded by the function parameter pack. When a function parameter pack appears in a non-deduced context (17.8.2.5), Example:

```cpp
template <class T, class ... Types> void f(Types ...);
template <class T, class T1, class ... Types> void g(T1, Types ...);
template <class T, class T1, class ... Types> void h(Types ..., T1);
```

```cpp
void h(int x, float &y);
const int x, y, z;
f(x, y); // T is deduced to float, const is int
g(x, y, z); // T1 is deduced to int; Types are deduced to float, int
g(x, y, z); // error: Types is not deduced
g<int, int, int>(x, y, z); // OK; no deduction occurs
```

- If P is not a reference type:

- (2.1) If A is an array type, the type produced by the array-to-pointer standard conversion (7.2) is used in place of A for type deduction; otherwise;

- (2.2) If A is a function type, the type produced by the function-to-pointer standard conversion (7.3) is used in place of A for type deduction; otherwise;

- (2.3) If A is a cv-qualified type, the top-level cv-qualifiers of P are ignored for type deduction. If P is a reference type, the type referred to by P is used for type deduction. [Example]:

```cpp
template <class T> int f(const T)
int n1 = f(0); // calls f<int>(const int)
int i = 0;
int n2 = f(i); // calls f<int>(const int)
template <class T> int g(volatile T)
int n3 = g(i); // calls g<int>(volatile int)
```

- example: If P is a reference type and the argument is A, the type "value reference to A" is used in place of type deduction. [Example]:

```cpp
template <class T> struct A {
template <class U>
A(T& U, int*); // #1: T& is not a forward reference.
U& is a forward reference.
A(T&, int*); // #2
};
```

```cpp
template <class T> A(T&, int*); // #3: T& is a forward reference.
```

```cpp
int* ip;
A(1, ip); // error: cannot deduce from #1
A(a0, ip); // uses #1 to deduce A<int> and #1 to initialize
A(a2, ip); // uses #3 to deduce A<int> and #2 to initialize
// example

4 In general, the deduction process attempts to find argument values that make the deduced A identical to A (after the type is transformed). However, there are three cases that allow a difference:

- If the original P is a reference type, the deduced A (i.e., the type referred to by reference) can be more cv-qualified than the transformed A

- The transformed A can be another pointer or member type that can be converted to the deduced A via a pointer conversion (7.13) and/or quality conversion (7.5)

- If P is a class and has the simple-template-id, the transformed A can be a derived class of the deduced A. Likewise, if P is a pointer to a class of the simple-template-id, the transformed A can be a pointer to a derived class to the deduced A.
