[Note: This evaluation holds regardless of the semantics of the initialization; for examples when the elements of the initializer-list are interpreted as arguments of a constructor call, even though there are no constraints on the arguments of a call — end note]

An object of type std::initializer_list<E> is constructed from an initializer if the implementation generated and materialized (7.4) a value of type "array of N E", where N is the number of elements in the initializer list. Each element of array is copy-initialized with the corresponding element of the initializer list and the initializer_list<E> object is constructed to reflect that array. [Note: A constructor or conversion function used for the copy shall be accessible (Clause 14) in the context of the initializer list — end note] If a conversion is required to initialize any of the elements, the program is ill-formed. [Example]:

```
struct X {
 X(std::initializer_list<double> v);
 X { 1, 2, 3 };n};
```

The initialization be performed in a way equivalent to this:
const double _a[3] = {double(1),double(2),double(3)};
 X(std::initializer_list<double>{_a, _a+3});

assuming that the constructor constructs an initializer_list object just like binding a reference. — end example

Array has the same lifetime as any other temporary object (15.2), except initializing an initializer_list object extends the lifetime of the array exactly like binding a reference to a pointer.
[Example]:

```
typedef std::complex<double> cmplx;
std::vector<complex> v = {1, 2, 3};
```

```
void f() {
 std::vector<cmplx> v2{1, 2, 3};
 std::initializer_list<int> i13 = {1, 2, 3};
};
```

```
struct A {
 std::initializer_list<int> i14;
 A() : i14{1, 2, 3}; // ill-formed, would create a dangling reference
```

For v1 and v2, the initializer_list object is a parameter in a function call, so the array created for {1, 2, 3} has full-expression lifetime. For i13, the initializer_list object is a variable, so the array persists for the lifetime of the variable. For i14, the initializer_list object is initialized in the constructor ctor as by binding a temporary reference to a reference member, the program is ill-formed (15.6.2) — end example — [Note: The implementation is free to allocate the array in read-only memory unless an explicit array with the same initializer could be allocated — end note]
