## 6.9.2 Compound types

[basic.compound]

- Compound types can be constructed in the following ways:
- arrays of a given type, 11.3.4;
- functions, which have parameters of given type and return void or references to objects of a given type, 11.3.5;
- pointers to void or objects or functions (including static members of classes) of a given type, 11.3.1;
- references to objects of a given type, 11.3.2. There are two types of references:
  - value reference
  - reference reference
  - classes containing a sequence of objects (Clause 12), a set of types, enumerations and functions for manipulating these objects (12.2),
- unions, which are capable of containing objects of different types at different times, 12.3;
- enumerations, which set constant values. Each distinct enumeration constitutes a different type, 10.2;
- pointers to non-static members, which identify members of a given type within objects of a class, 11.3.3.

These methods of construction can be applied recursively; restrictions are mentioned in 11.3.1, 11.3.4, 11.3.5. If the number of bytes in an object exceeds the maximum value in the type size_t (2.1) it is ill-formed.

The type of pointer to void or a pointer to object is called an object pointer. [Note: A pointer does not have a pointer-to-pointer, because a pointer to object is not an object type]. The type of pointer that can designate a function is called function pointer type. A pointer to object is referred to as pointer to class. [Example: A pointer to object of type X is referred to as "pointer to X", and a pointer to object is referred to as "pointer to void"]. For pointers to static members, also applies to members. Pointer to incomplete types are allowed although there are restrictions on what can be done with them (6.11). Every value of pointer type is one of the following:
- a pointer to an object or function (the pointer is said to point to the object or function),
- a pointer past the end of an object (8.7), or
- the null pointer (7.11) for that type, or
- an invalid pointer value.

A value of pointer to or past an object represents the address of the first byte in memory (4.1) occupied by the object or the first byte in memory after the end of the storage occupied by the object. [Note: A pointer past the end of an object (8.7) is not considered to point to an unaltered object of the object's type that might exist. A value becomes invalid when the storage reaches the end of its storage; see 6.7]. For pointers in arithmetic (7.8) or comparison (8.10), a pointer past the end of an array is allowed to point to an element of the same type or beyond. The value representation of pointer types is implementation-defined. Pointers to layout-compatible types have the same value representation and alignment requirements (6.11). [Note: Pointers to over-aligned types but their range of valid values is restricted by the extended alignment requirement.]

## 6.9.3 CV-qualifiers [basic.type-qualifier]

A mentioned in 6.9.1 and 6.2 is a cv-qualified type. Each type is a cv-qualified complete or incomplete object type (6.9) has three cv-qualified versions of its type: a cv-qualified, a volatile-qualified version, and a cv-volatile version. The type of an object (4.5) includes the cv-qualifiers specified in the decl-specifier (10.1), declarator (Clause 11), type-id (11.1), or new-type (8.3) when the object is created.

- (1.1) A const object is an object of type const $T$ or a non-mutable subobject of such object.
- (1.2) A volatile object is an object of type volatile $T$, a subobject of such object, or a mutable subobject of a const object.
- (1.3) A const volatile object is an object of type volatile $T$, a non-mutable subobject of such object, a const subobject of a volatile object, or a non-mutable volatile subobject of a const object.

The cv-qualified or cv-qualified versions of a type are different types; however, they shall have the same representation and alignment requirements (6.11).$^{55}$
