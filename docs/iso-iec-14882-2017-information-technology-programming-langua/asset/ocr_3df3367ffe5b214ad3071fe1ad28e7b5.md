2 An atomic operation A performs a release operation on an atomic object M synchronizes with an atomic operation B that performs an acquire operation on M and takes its value from any side sequenced by A.

3 There shall be a single order S on all memory_order_seq_cst operations, consistent with the “happens before” order and modification orders for all affected locations, such that each memory_order_seq_cst operation B loads a value from an atomic object M one of the following:

+   (3.1) the result of the last modification of M that precedes B in S, if it exists,

+   (3.2) if A exists, the result of modification of M that is not memory_order_seq_cst and does not happen before A, or

+   (3.3) if A does not exist, the result of modification of M that is memory_order_seq_cst.

> [Note: It is not required that S includes lock, it can always be extended to an order order, unless the ordering between those is already included in the “happens before” order.—end note]

4 For an atomic operation B reads the value of an atomic object M, if there is a memory_order_seq_cst fence X sequenced before B, then B observes the memory_order_seq_cst modification of M preceding X in S or a later modification of M in its modification order.

5 For atomic operations A and B on an atomic object M, where A modifies and B takes its value, if there are a memory_order_seq_cst fence X that A is sequenced before X and B follows X in S, then B observes either the effects of A or a later modification of M in its modification order. For atomic operations A and B of an atomic object M, where A occurs later than B in the modification order of M:

+   (7.1) there is a memory_order_seq_cst fence X that is sequenced before X, and precedes X in S, or

+   (7.2) there is a memory_order_seq_cst fence Y that is sequenced before B, and precedes Y in S, or

+   (7.3) there are memory_order_seq_cst fence X and Y that is sequenced before X, Y is sequenced before B, and X precedes Y in S.

8 [Note: memory_order_seq_cst ensures sequential consistency only for a program that is free of data races and uses exclusively memory_order_seq_cst. Any use of weaker ordering will invalidate the guarantee unless extreme care is used. In particular, memory_order_seq_cst fences ensure a total order for the fences. Fences cannot, in general, be used to restore sequential consistency for atomic operations with weaker ordering.—end note]

9 Implementations shall ensure that no “out-of-thin-air” values are computed that critically depend on their own computation.
