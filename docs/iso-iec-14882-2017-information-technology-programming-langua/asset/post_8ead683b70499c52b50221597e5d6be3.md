## 10.1 Specifiers [decl.spec]

+ 1 The specifiers that can be used in a declaration

```cpp
decl-specifier:
    storage-class-specifier
    defining-type-specifier
    function-specifier
    friend
    typedef
    constexpr
    inline

decl-specifier-seq:
    decl-specifier attribute-specifier-seq_opt
    decl-specifier decl-specifier-seq
```

The optional attribute-specifier-seq in a decl-specifier-seq pertains to the type determined by the preceding decl-specifiers (11.3). The attribute-specifier affects the type only for the declaration it appears in, not other declarations involving the same type.

+ 2 Each-specifier shall appear at most once in a complete decl-specifier-seq, except that long may appear twice.

+ 3 If a type-name is encountered while missing a decl-specifier-seq, it is interpreted as a decl-specifier-seq if and only if there is no previous defining-type-specifier other than a cv-qualifier in the decl-specifier-seq. The sequence shall be self-consistent as described below. [Example:

```cpp
typedef char Pc;
static Pc; // error: no name was specified for the static variable of type Pc.
To get a variable called Pc, a type-specifier (other than volatile) has to be present to indicate the typedef-name Pc is the name being (re)declared, rather than part of the decl-specifier sequence.
For example:

```cpp
void f(Pc)               // f(char*) (const char*)
void g(const int);      // g(const int)
// end-example
```

+ 4 [Note: Since signed, unsigned, long, and short by default int, a type-name appearing after one of those specifiers is treated as the name being (re)declared. [Example:

```cpp
void h(unsigned int);  // h(unsigned int)
void k(unsigned int);  // k(unsigned int)
// end-example]
```

## 10.1.1 Storage class specifiers [decl.stc]

+ 1 The storage class specifiers are

```cpp
storage-class-specifier:
    static
    thread_local
    extern
    mutable
```

At most one storage-class-specifier shall appear in a given decl-specifier-seq, except that thread_local may appear with static or extern. If thread_local appears in any declaration of a variable-seq it shall be present in all declarations of that entity. If a storage-class-specifier appears in a decl-specifier-seq, there can be no typedef specified in the same decl-specifier-seq and the init-declarator-list or member-declarator-list of the declaration shall not exempt any union declared in a namespace or in the global namespace, which shall be declared static (12.3.1). The storage-class-specifier applies to the name declared by each init-declarator and not to names declared by other specifiers. A storage-class-specifier other than thread_local shall not be specified in an explicit specialization (17.7.3) or

> Note: A declaration without a storage-class-specifier at block scope has automatic storage duration by (6.7), — end note

The thread_specifier indicates that the named entity has thread storage duration (6.7.2). It shall be applied only to the names of variables of namespace or block scope and the names of static data members. When thread_local is used in a declaration of a block scope the storage-class-specifier static is implied if no other storage-class-specifier appears in the decl-specifier-seq. There can be no static function declarations within a block to have static storage parameters. A static specifier used in the declaration of a variable declares the variable to have thread storage duration (6.7). A static specifier used for static class members (12.2.3) describes its interface. For the linkage of a name declared with a static specifier, see 6.

The extern specifier can be applied only to the names of variables and to anonymous unions (12.3.1). The extern specifier cannot be used in the declaration of class members or function parameters.

The linkages implied by successive declarations for a given entity shall agree. That, within a given scope, each declaration declaring the same variable name or the overloading of a function name shall imply the same linkage. Each function in a given set of overloaded functions can have a different linkage, however:

```cpp

/* ... */ // external linkage
```

```cpp

/* ... */
```

```cpp

```

```cpp

extern void o(); // external linkage
```

```cpp

```

```cpp

inline void n();

static int b;                  // b has internal linkage

+ The mutable specifier shall appear only in the declaration of a non-static data member (12.2) whose type is neither const-qualified nor a reference type. [Example:

## 10.1.2 Function specifiers [dcl.fct.spec]

+ Function-specifiers can be used only in function declarations.
```cpp
function-specifier:
  virtual
  explicit
```

+ The virtual specifier shall be used only in the declaration of a non-static data member; see 13.3.

+ The explicit specifier shall be used only in the declaration of a constructor or conversion function within its class; see 15.3.

## 10.1.3 The typedef specifier

Declarations containing the typedef specifier (6.9) can be used for naming (6.9) types. The typedef specifier shall not be combined in a decl-specifier-seq with any other except

```cpp
typedef-name:
    identifier
```

A name declared with the typedef specifier becomes a typedef-name. Within the scope of its declaration, a typedef-name is syntactically equivalent to a keyword and a typedef is a synonym for another type. A typedef-name does not introduce a new class (12.1) or enumeration declaration. [Example:

```cpp
typedef int MILES, KICKLES;
MILES distance,
extern int KICKLES metric;
```
are all correct declarations; the type of distance is int and of metric is "pointer to int". -- end example

+ 2 A typedef-name can be introduced by an alias-declaration. The identifier using the keyword becomes a typedef-name and the optional attribute-specifier-seq following the identifier appears to be typedef-name. Such has the same semantics as if it were introduced by the typedef specifier. In particular, it does not introduce a new type. [Example:
```cpp
void handler_t = void (*)(int);
extern void (*qsort)(int, void *cell); // ill-formed
```
-- end example The typedef-specifier-seg of the defining-type-id shall not define a class or enumeration if the alias-declaration is the declaration of a template-declaration.

+ 3 In a non-class scope, a typedef specifier can be used to rename the name of any type declared in that scope to struct s { /* ... */ / s }; [Example:
```cpp
typedef struct s {
  typef int I;
} I;
typef II I;
```


+ 4 In a given scope, a typedef specifier can be used to redefine any class-name declared in that scope that is not a typedef-specifier to refer to the type to it already refers. [Example:
```cpp
struct S {
  typef struct A {}; // OK
  typef struct B {}; // OK
  typef A {}; // error
};
```
-- end example

+ 5 If a typedef specifier is used to redefine in a given scope an entity that can be referenced by an elaborated-type-specifier, the entity name can be referenced by an elaborated-type-specifier or as an enumeration or class definition respectively.
