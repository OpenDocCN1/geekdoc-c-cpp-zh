
# ISO/IEC 14882:2017(Standard)

## Standard conversions

- Standard conversions are implicit conversions with built-in meaning. Clause 7 enumerates the full set of conversions. A standard conversion sequence is a sequence of standard conversions in the following order:

- (1.1) Zero or one conversion from the following set: value-to-rv conversion, array-to-pointer conversion, and function-to-pointer conversion.

- (1.2) Zero or one conversion from the following set: integral motions, floating-point promotion, integral conversions, floating-point conversions, floating-integral conversions, pointer conversions, pointer to member conversions, and boolean conversions.

- (1.3) Zero or one function conversion.

- (1.4) Zero or one qualification conversion.

> [Note: A standard conversion sequence can be empty, or consist of no conversions. A standard conversion sequence will be applied to an expression if necessary to convert it to a destination type.]

- 2 Expressions with a given type will be implicitly converted to other types in several contexts:

- (2.1) When used as operands. The operator's requirements for its operands dictate the destination type (Clause 8).

- (2.2) When used in the context of an if or iteration statement (9.4, 9.5). The destination type is bool.

- (2.3) When used in the expression of a switch statement. The destination type is integral (9.4).

- (2.4) When used as the source expression for an initialization (which includes used as an argument in a function call and as the result of a return statement). The type of the entity being initialized is (generally) the destination type. See 11.6, 11.6.3.

An expression can be implicitly converted to a type T if only if the condition t is well-formed, for some temporary variable t (11.6).

Certain language constructs require that an expression be contextually converted to a Boolean value. An expression appearing in such a context is contextually converted to bool and is well-formed if and only if the expression bool t (11.6).

Certain language constructs require conversion to a value having one of set of types appropriate to the context. An expression of type E appearing in such a context is contextually converted to a specified type T and is well-formed if and only if it can be implicitly converted to a type T that is defined as follows: for non-implicit conversion functions whose return type is cr or to cr t that T is allowed by the context. There shall be exactly one such.

The effect of any implicit conversion is the same as performing the corresponding declaration and initialization and then using the variable as the result of the conversion. The result is an value if T is an integral reference type or a value reference to function type (11.3.2), if an T is a value reference to object type, and a prvalue otherwise. The expression E is treated as a value if and only if the initialization uses it as a value.

> [Note: For class types, user-defined conversions are considered well as well; see 15.3. In general, an implicit conversion sequence (16.3.3.1) consists of a standard conversion sequence followed by a user-defined conversion followed by another standard conversion sequence. — end note. For example, the value-to-prvalue conversion is not done on the operand of the unary & operator. Specific exceptions are in the descriptions of those operators and contexts. — end note

## 7.1 Value-to-prvalue conversion

1 A value (6.10) of a non-function, non-array type T can be converted to a prvalue. If T is an incomplete type, a program that necessitates this conversion is ill-formed. If T is a non-class type, the type of the prvalue is the cv-unqualified version of T. Otherwise, the type of the prvalue is T.

2 When an value-to-prvalue conversion is applied to an expression e, and other

- (2.1) e is not potentially value,

- (2.2) the evaluation of e results in the evaluation of a member ex of the set of potential results of e, and ex variable x that is not used by ex (6.2). the value contained in the referenced object is not accessed. [Example]:

```cpp
struct S {
  int n;
}
auto f() {
  S x;
  constexpr y { 
    return [](bool b) { return b ? y : x.n; };
}
auto g = f();
int m = g(false);
// undefined behavior due to access of x.n outside its lifetime
int n = g(true);
// Ok, does not access y.n
// end example
```

3 The result of the conversion is determined by the following rules:

- (3.1) If T is std::ptr_t, the result is a null pointer conversion (7.11). [Note: Since no value is fetched from ptr, there is no side effect for a value access (4.6), and an inactive member of a union (12.3) may be accessed. — end note

- (3.2) Otherwise, if T has a class type, the conversion copy-initializes the result object from the glvalue.

- (3.3) Otherwise, the object to which the glvalue refers to an invalid pointer value (6.7.4), the behavior is implementation-defined.

- (3.4) Otherwise, the value contained in the glvalue is the prvalue. [Note: See 6.10. — end note

## 7.2 Array-to-pointer conversion

1 An array of type T can be converted to a pointer to its first element. The result is a pointer to T. If T is an incomplete type, a program that necessitates this conversion is ill-formed. If T is a non-class type, the type of the pointer is the cv-unqualified version of T. Otherwise, the type of the pointer is T.

2 When an array-to-pointer conversion is applied to an expression e, and other

- (2.1) e is not potentially value,

- (2.2) the evaluation of e results in the evaluation of a member ex of the set of potential results of e, and ex variable x that is not used by ex (6.2). the value contained in the referenced object is not accessed. [Example]:

```cpp
int a[] = {1, 2, 3};
int* p = a; // p is a pointer to a[0]
```

3 The result of the conversion is determined by the following rules:

- (3.1) If T is an array type, the result is a pointer to the first element of the array.

- (3.2) Otherwise, the result is a null pointer. [Note: This case should not happen for array types.]

## 7.3 Function-to-pointer conversion

1 A function of type T can be converted to a pointer to the function. The result is a pointer to a function of type T.

2 When a function-to-pointer conversion is applied to an expression e, and other

- (2.1) e is not potentially value,

- (2.2) the evaluation of e results in the evaluation of a member ex of the set of potential results of e, and ex variable x that is not used by ex (6.2). the value contained in the referenced object is not accessed.

3 The result of the conversion is determined by the following rules:

- (3.1) If T is a function type, the result is a pointer to a function of type T.

## 7.4 Temporaryization conversion

1 A value of type T can be converted to a prvalue. The result is a prvalue of type T. If T is a class type, a temporary object is initialized from the prvalue.

2 When a temporaryization conversion is applied to an expression e, and other

- (2.1) e is not potentially value,

- (2.2) the evaluation of e results in the evaluation of a member ex of the set of potential results of e, and ex variable x that is not used by ex (6.2). the value contained in the referenced object is not accessed.

3 The result of the conversion is determined by the following rules:

- (3.1) If T is a class type, the result is a prvalue of type T.

## 7.5 Qualification conversion

1 An expression of type T can be converted to a type T' with the same cv-qualifiers. The result is an expression of type T'.

2 When a qualification conversion is applied to an expression e, and other

- (2.1) e is not potentially value,

- (2.2) the evaluation of e results in the evaluation of a member ex of the set of potential results of e, and ex variable x that is not used by ex (6.2). the value contained in the referenced object is not accessed.

3 The result of the conversion is determined by the following rules:

- (3.1) For every i > 0, if const is in cv¹ then const is in cv², and similarly for volatile.
