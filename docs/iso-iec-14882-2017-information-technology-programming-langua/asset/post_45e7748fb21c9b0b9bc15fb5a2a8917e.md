### 10.1.7.4

**Change**: The auto keyword cannot be used as a storage class classifier.

```cpp
void f() {
    auto int x; // invalid C, invalid C++
}
```

**Rationale**: Allowing the use of auto to deduce the type of a variable from its initializer results in undesired interpretations of auto as a storage class in certain contexts.
**Effect on original feature**: Deletion of semantically well-defined feature.
**Difficulty of converting**: Syntactic transformation.
**How widely used**: Rare.

### 10.2

**Change**: In C++, objects of enumeration type can only be assigned values of the same enumeration type. In C, objects of enumeration type can be assigned values of any integral type.

Example:

```cpp
enum color { red, blue, green };
enum color c = 1; // valid C, invalid C++
```

**Rationale**: The type-safe nature of C++.
**Effect on original feature**: Deletion of semantically well-defined feature.
**Difficulty of converting**: Syntactic transformation. (The type error produced by the assignment can be automatically corrected by applying an explicit cast.)
**How widely used**: Common.

### 10.2

**Change**: In C++, the type of the enumerator is its enumeration. In C, the type of an enumerator is int.

Example:

```cpp
enum { A };
size_t sizeof(A) == sizeof(int) // in C
sizeof(A) == sizeof(int)      // in C++
/* and int is not necessarily equal to sizeof(A) */
```

**Rationale**: In C++, an enumerator is a distinct type.
**Effect on original feature**: Change to semantics of well-defined feature.
**Difficulty of converting**: Syntactic transformation.
**How widely used**: Seldom. The only time this affects existing C is when the size of the enumerator is int. Taking the size of an enumerator is not a common C coding practice.

# C.1.7 Clause 11: declarators

### 11.3.5

**Change**: In C++, a function declared with an empty parameter list takes no arguments. In C, an empty parameter list means that the number and type of the function arguments are unknown.

Example:

```cpp
int f();
// means int f(void) in C++
// int f (unknown) in C
```

**Rationale**: This is to avoid erroneous function calls (i.e., function calls with the wrong number or type of arguments).

**Effect on original feature**: Change of semantics of well-defined feature. This feature was marked as "obsolete" in C.
**Difficulty of converting**: Syntactic transformation. The function declarations in C incomplete style must be completed to become prototype declarations. A program may need to be updated if different calls to the same (non-prototype) function have different numbers of arguments or if the type arguments differ.
**How widely used**: Common.

### 11.3.5 [see 8.3.3]

**Change**: In C++, types may not be defined in return or parameter types. In C, these definitions are allowed.

Example:

```cpp
void f(struct int { a; } arg {}) // valid C, invalid C++
enum E { A, B, C } // valid C, invalid C++
```

**Rationale**: When comparing types in translation units, C++ relies on name equivalence when C relies on structural equivalence. Regarding parameter types: since the type defined in a parameter list would be from within the function itself.
**Effect on original feature**: Deletion of semantically well-defined feature.
**Difficulty of converting**: Semantic transformation. The type definitions must be moved to file scope, or in header files.
**How widely used**: Seldom. This type of definition is seen as poor coding style.

### 11.4

**Change**: In C++, the syntax for function declaration excludes the "old-style" function. In C, "old-style" syntax is allowed, but deprecated as "obsolete".
**Rationale**: Prototypes are essential to type safety.
**Effect on original feature**: Deletion of semantically well-defined feature.
**Difficulty of converting**: Syntactic transformation.
**How widely used**: Common in old programs, but known to be obsolete.

### 11.6.2

**Change**: In C++, when initializing an array with a string, the number of characters in the string (including the terminator "\0") must not exceed the number of elements in the array. In C, an array can be initialized with a string even if the array is not enough to contain the string-terminating "\0".

Example:

```cpp
char array[4] = "abcd"; // valid C, invalid C++
```

**Rationale**: When these non-terminated arrays are manipulated by string functions, there is potential for major catastrophe.
**Effect on original feature**: Deletion of semantically well-defined feature.
**Difficulty of converting**: Semantic transformation. The arrays must be declared one element bigger to contain the string terminating "\0".

### 12.2.6

A typedef name may not be redecl in a class definition after being used.
Example:

```cpp
typedef int I;
struct S {\int I; // valid C, invalid C++
};
```

**Rationale**: When classes become complicated, allowing such a redefinition after the type has been used can create confusion for C++ programmers as to what the meaning of I really is.
**Effect on original feature**: Deletion of semantically well-defined feature.
**Difficulty of converting**: Semantic transformation. Either the type or the struct member has to be renamed.
**How widely used**: Seldom.
