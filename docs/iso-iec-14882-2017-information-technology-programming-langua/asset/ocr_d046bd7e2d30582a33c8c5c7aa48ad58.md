+   11 Many operands that expect operations of arithmetic or enumeration cause type conversions and yield results in a similar manner. The purpose is to use a common type, which is also the type of the result. This pattern is called the usual arithmetic, which is defined as follows:

+   (11.1) If either operand is of enumeration expression (10.2), no conversions are performed; if the other operand does not have the same type, the expression is ill-formed.

+   (11.2) If either is of type long, the other shall be converted to long double.

+   (11.3) Otherwise, if either operand is double, the other shall be converted to double.

+   (11.4) Otherwise, if either operand is float, the other shall be converted to float.

+   (11.5) Otherwise, the integral operands (7.6) shall be performed on all operands. Then the following rules shall be applied to the promoted operands:

+   (11.5.1) If both operands have the same type, no conversion is needed.

+   (11.5.2) Otherwise, if one operand has signed integer types or both have unsigned integer types, the operand with the type of lesser integer rank shall be converted to the type of the other operand with greater rank.

+   (11.5.3) Otherwise, if the operand with unsigned integer type has greater rank than or equal to the rank of the other type, the operand with signed integer type shall be converted to the type of the operand with unsigned integer type.

+   (11.5.4) Otherwise, if the type of the operand with signed integer type can represent all the values of the operand with unsigned integer type, the operand with unsigned integer type shall be converted to the type of the operand with signed integer type.

+   (11.5.5) Otherwise, both operands shall be converted to the unsigned integer type corresponding to the type of the operand with signed integer type.
