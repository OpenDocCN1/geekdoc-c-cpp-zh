## 9.6.4 The goto statement [stmt.goto]

+   The goto statement unconditionally transfers control to the statement labeled by the identifier. The identifier shall be a label (9.1) located in the current function.

## 9.7 Declaration statement [stmt.dcl]

+   A declaration statement introduces one or more new identifiers into a block; it has the form
  `declaration-statement:block-declaration.`
  If an identifier introduced by a declaration was previously declared in an outer block, the outer declaration is hidden for the remainder of the block, after which it resumes its function.

+   Variables with automatic storage duration (6.7.3) are initialized each time their declaration-statement is executed. With automatic storage duration the block in which they are destroyed (9.6).

+   It is possible to transfer into a block, but not in a way that bypasses declarations with initialization. A program jumps from a point where a variable with automatic storage duration is not in scope to a point where it is in scope is ill-formed unless the variable has scalar class type with a default constructor and destructor, a cv-qualified version of these types, or any one of the preceding types and is declared without an initializer (11.6). Example:

```cpp
void f() {
  goto lx; // ill-formed: jump into scope of a
  ...
  ly:
  int a = 1;
  lx:
    goto ly; // OK, jumps destructor call for a followed by
    construction immediately following label ly
}
```
- end example

+   Dynamic initialization of a block with static storage duration (6.7.1) or storage duration (6.7.2) is performed the first time control passes through its declaration; such a variable is considered initialized upon the completion of its initialization. If the initialization exits by an exception, the initialization is not complete, so it will be tried again the next time control enters the declaration. If control enters the declaration concurrently while the variable is being initialized, the concurrent execution will wait for completion of the initialization. If re-enters the declaration recursively while the variable is being initialized, the behavior is undefined. Example:

```cpp
int foo(int i) {
  static int s = s + foo(2*i); // recursive call -
  return i+1;
}
```
- end example

> The transfer from the condition of a switch statement to a case label is considered a jump in this respect. The implementation must not introduce any deadlock after execution of the initializer. Deadlocks might be caused by the program logic; the implementation need only avoid deadlocks due to its own synchronization operations.
