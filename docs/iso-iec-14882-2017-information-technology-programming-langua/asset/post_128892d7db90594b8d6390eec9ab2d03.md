## 28.3 Algorithms requirements [algorithms.requirements]

All of the algorithms are separated from the practical implementations of data structures and parameterized by iterator types. Because of this, they can work with program-defined data structures, as long as these structures have iterators satisfying the assumptions on the algorithms.

For purposes of determining the existence of data ranges, algorithms shall not modify objects through an iterator unless the specification requires such modification.

Through this Clause, the names of template parameters are used to express type requirements.

- (3.1) If an algorithm parameter is named InputIterator, InputIterator2, the template argument shall satisfy the requirements of an input iterator (27.2.3).
- (3.2) If an algorithm parameter is named OutputIterator, OutputIterator, or OutputIterator2, the template argument shall satisfy the requirements of an output iterator (27.2.4).
- (3.3) If an algorithm parameter is named ForwardIterator, ForwardIterator, or ForwardIterator2, the template argument shall satisfy the requirements of a forward iterator (27.2.5).
- (3.4) If an algorithm parameter is named BidirectionalIterator, BidirectionalIterator, or Bidirectional2, the template argument shall satisfy the requirements of a bidirectional iterator (27.2.6).
- (3.5) If an algorithm parameter is named RandomAccessIterator, RandomAccessIterator, or RandomAccess2, the template argument shall satisfy the requirements of a random-access iterator (27.2.7).
- 4 If an algorithm effects: such a value that is pointed to by any iterator as an argument is modified, then that algorithm shall have an additional requirement: The type of argument shall satisfy the requirements of a mutable iterator (27.2). [Note: Which does not affect arguments that are named OutputIterator, OutputIterator1, or OutputIterator2 because output iterators must never be mutable. — end note]

In-place and copying versions are provided for certain algorithms<sup>262</sup>. When such a version is provided for an algorithm it takes predicates with the suffix _if (which follows the suffix _copy).

The Predicate parameter is used when an algorithm effects a function object applied to the result of dereferencing the corresponding iterator, returning a value as true. In other words, if an algorithm takes Predicate as its argument and as its first argument, it should work if the construct pred(*iterator) is converted to bool (Clause 7). The function object pred shall not affect any non-constant function the dereferenced iterator.

The BinaryPredicate parameter is used when an algorithm effects a function object applied to the result of dereferencing two corresponding iterators or dereferencing an iterator and T when T is first part of the signature returns a value as true. In other words, if an algorithm takes BinaryPredicate binary_pred as its argument and first2 as its arguments, it should work correctly in the construct binary_pred(*first1, *first2) contextually converted to bool (Clause 7). BinaryPredicate always takes the first iterator value_type as its first argument, that is, in cases when T is part of the signature, it should work correctly in the construct binary_pred(*first1, value) contextually converted to bool (Clause 7). binary_pred should not apply any non-constant function.

## 28.4.3 Effect of execution policies [algorithms.parallel.exec]

- The invocations of element access in parallel algorithms with an execution policy of type execution::sequenced occur in the calling thread.
- The invocations of element access in parallel algorithms with an execution policy of type execution::parallel are permitted to execute in either the calling thread or concurrently. If the threads of execution created by (23.2) provide concurrent progress guarantees, then the provided forward progress is implementation-defined. Any such executions in the same thread of execution are indeterminate with respect to each other. [Note: The caller's responsibility is to ensure that the invocation does not introduce data races or deadlocks. — end note]
