# ISO/IEC 14882:2017(E)

+   (7.3) from an integer type or unscaped enumeration type to a floating-point type, except where the source is a constant expression and the actual value after conversion will fit into the target type and will produce the original value when converted back to the original type, or

+   (7.4) from an integer type or unscaped enumeration type to an integer type that cannot represent all the values of the original type, except where the source is a constant expression value after integral promotions will fit into the target type,

[Note: As indicated above, such conversions are not allowed at the top level in list-initializations. — end note]

```
int x = 999;                   // x is not a constant expression
const int y = 999;                  // OK, though it might narrow (in this case, it does narrow)
const char x = 999;                     // error: narrow
char cl = x;                        // error: narrow (assuming char is 8 bits)
char c2(x);                         // OK: no narrowing needed
char c3(y);                         // OK: no narrowing needed
unsigned char uc1 = {5};           // error: narrow
unsigned char uc2 = {-1};          // error: narrow
unsigned int sil =                 // error: narrow
{ (unsigned int)-1 };              // error: narrow
int ii = (2.0);                     // error: might narrow
float f1 = { x };                   // OK: 7 can be exactly represented as a float
float f2 = { 7 };
int f3();
int a[] = 
{ 2, f(2), f(2.0) };               // OK: the double-to-int conversion is not at the top level
```
