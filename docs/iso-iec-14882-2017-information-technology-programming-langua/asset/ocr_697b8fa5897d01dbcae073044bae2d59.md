# ISO/IEC 14882:2017(Standard)

# Standard conversions

+   Standard conversions are implicit conversions with built-in meaning. Clause 7 enumerates the full set of conversions. A standard conversion sequence is a sequence of standard conversions in the following order:

+   (1.1) Zero or one conversion from the following set: value-to-rv conversion, array-to-pointer conversion, and function-to-pointer conversion.

+   (1.2) Zero or one conversion from the following set: integral motions, floating-point promotion, integral conversions, floating-point conversions, floating-integral conversions, pointer conversions, pointer to member conversions, and boolean conversions.

+   (1.3) Zero or one function conversion.

+   (1.4) Zero or one qualification conversion.

> [Note: A standard conversion sequence can be empty, or consist of no conversions. A standard conversion sequence will be applied to an expression if necessary to convert it to a destination type.]

+   2 Expressions with a given type will be implicitly converted to other types in several contexts:

+   (2.1) When used as operands. The operator's requirements for its operands dictate the destination type (Clause 8).

+   (2.2) When used in the context of an if or iteration statement (9.4, 9.5). The destination type is bool.

+   (2.3) When used in the expression of a switch statement. The destination type is integral (9.4).

+   (2.4) When used as the source expression for an initialization (which includes used as an argument in a function call and as the result of a return statement). The type of the entity being initialized is (generally) the destination type. See 11.6, 11.6.3.

An expression can be implicitly converted to a type T if only if the condition t is well-formed, for some temporary variable t (11.6).

Certain language constructs require that an expression be contextually converted to a Boolean value. An expression appearing in such a context is contextually converted to bool and is well-formed if and only if the expression bool t (11.6).

Certain language constructs require conversion to a value having one of set of types appropriate to the context. An expression of type E appearing in such a context is contextually converted to a specified type T and is well-formed if and only if it can be implicitly converted to a type T that is defined as follows: for non-implicit conversion functions whose return type is cr or to cr t that T is allowed by the context. There shall be exactly one such.

The effect of any implicit conversion is the same as performing the corresponding declaration and initialization and then using the variable as the result of the conversion. The result is an value if T is an integral reference type or a value reference to function type (11.3.2), if an T is a value reference to object type, and a prvalue otherwise. The expression E is treated as a value if and only the initialization uses it as a value.
