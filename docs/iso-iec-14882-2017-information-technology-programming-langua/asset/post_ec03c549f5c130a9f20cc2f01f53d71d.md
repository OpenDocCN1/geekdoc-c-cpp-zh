## 4.7 Multi-threaded execution and data races

- ¹ An execution (also known as a thread) is a single flow of control within a program, including the invocation of a specific type-level function, and every recurring invocation executed by that thread. [Note: When one creates another, the call to the top-level function of the new thread is executed by the new thread, not by the creator. — end note] Every thread can potentially access every object and function.³ Under a hosted implementation, a C++ program may have more than one thread running concurrently. The execution of each thread proceeds as if the remainder of the program were executing concurrently with respect to all of its threads. [Note: Usually the execution can be viewed as an interleaving of all its threads, some kinds of operations, for example, allow evaluation inconsistent with a single interleaving, as described below. — end note] Under a freestanding implementation, it is implementation-defined whether a program may have more than one thread of execution.

- ² For a signal handler that is not executed as a result of a call to the std::raise function, it is unspecified which thread of execution consumes the signal handler invocation.

- ⁰ In other words, functions do not interfere with each other.

- ¹¹ An object with atomic or thread storage duration (6.7) is associated with one specific thread, and can be accessed by a different thread indirectly through a pointer or reference (6.9.2).

A synchronization operation on one or more memory locations is either a consume operation, an acquire operation, a release operation, or both an acquire and release operation. In addition, there are relaxed atomic operations, where an associated memory location can be either an acquire fence, a release fence, or both release fence, which are not synchronization operations, and atomic-read-write operations, which have special characteristics.
