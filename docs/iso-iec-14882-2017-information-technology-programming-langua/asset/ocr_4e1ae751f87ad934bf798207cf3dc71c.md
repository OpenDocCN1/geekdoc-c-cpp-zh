# 30.4.2 Overview

+   1 In this Clause, the synchronization unit refers to the type FILE declared in <cstdio> (30.11.1).
2 The header <iostream> (30.11) declares objects that associate objects with the standard C streams provided by the functions declared in <cstdio> and includes all headers necessary to use these objects.
3 The objects are constructed and the associations are established at some time prior to or during the first object of class ios_base::init is constructed, and in any case before the body of main (6.6.1). The objects are not destroyed during program execution. The results of including <iostream> defines an instance of ios_base::init with static storage duration.
4 Mixing operations on wide-character and narrow-character streams has the same semantics as such operations on FILES, as specified in the C standard library.
5 Concurrent access to a synchronized (30.5.3.4) standard istream object's formatted and unformatted input (30.7.1) and output (30.7.5) standard C by multiple threads shall not result in a data race (4.7). [Note: Users must still synchronize concurrent use of these objects and by multiple threads if they wish to avoid interleaved characters. — end note]
SEE ALSO: ISO C 7.2.11

# 30.4.3 stream objects

istream:

+   1 The object cin controls input from a stream buffer associated with the object stdin, declared in <cstdio> (30.11.1).
2 After the object cin is initialized, cin.tie() returns &cout. Its state is otherwise the same as required for basic_ios<char>::init (30.5.5.2).

ostream:

+   3 The object cout controls output to a stream buffer associated with the object stdout, declared in <cstdio> (30.11.1).

iostream:

+   4 The object cerr controls output to a stream buffer associated with the object stderr, declared in <cstdio> (30.11.1).
5 After the object cerr is initialized, cerr.flags() & cerr.tie() returns &cout. Its state is otherwise the same as required for basic_ios<char>::init (30.5.5.2).

+   6 The object clog controls output to a stream buffer associated with the object sterr, declared in <cstdio> (30.11.1).

> 288 If it is possible for them to do so, implementations should initialize the objects earlier than required.
289 Constructors and destructors for static objects can access these to read input from stdin or write to stdout or stderr.
