## 8.1.6 Fold expressions

1 A fold expression performs a fold of a template parameter (17.5.3) over a binary operator.

```
fold-expression:
  ( expression fold-operator ...)
  (.. fold-operator cast-expression ..)
  (cast-expression fold-operator cast-expression ..)
```

```
fold-order: one of
  * / % & | << >> =
  += -= *= /= &= &= <= <= &&=
  != | < > (.. op >=) && || | -*
```

2 An expression of the form (op ...) where op is a fold-operator is called a unary left fold. Unary left and unary right folds are collectively called unary folds. In a unary fold, the cast-expression shall contain an unexpanded parameter pack (17.5.3).

3 An expression of the form (op1 op2) where op1 and op2 are fold-operators is called a binary fold. In a binary fold, op1 and op2 should be the same fold-operator, and either e1 shall contain an unexpanded parameter pack, or e2 shall contain an unexpanded parameter pack, but not. If e2 contains an unexpanded parameter pack, the expression is called a binary left fold. If e1 contains an unexpanded parameter pack, the expression is called a binary right fold. [Example:

```cpp
template<typename Args>
bool f(Args... args) {
    return (true && .. args);
}

template<typename Args>
bool f(Args... args) {
    return (args + ... + args); // error: both operands contain unexpanded parameter packs
}
// end example
```

## 8.2 Postfix expressions [expr.post]

+ Postfix expressions group left-to-right.

```
postfix-expression:
primary-expression
postfix-expression < expr-or-braced-list >
postfix-expression < expression-list-opt >
simple-type-spec < expression-list-opt >
typename-spec < expression-list-opt >
simple-type-spec < braced-list
typename-spec < braced-list
postfix-expression . template_opt id-expression
postfix-expression > template_opt id-expression
postfix-expression . pseudo-destructor-name
postfix-expression - pseudo-destructor-name
postfix-expression ++
postfix-expression --
dynamic_cast < type-id > ( expression )
static_cast < type-id > ( expression )
reinterpret_cast < type-id > ( expression )
const_cast < type-id > ( expression )
typeid ( expression )
typeid ( type-id )
expr-list:
initializer-list
pseudo-destructor-name:
nested-name-specifier_opt type-name :: :: type-name
nested-name-specifier simple-template :: :: type-name
type-specifier
```

> [Note: The > following the type-id in a dynamic_cast, static_cast, reinterpret_cast, or const_ may be the result of replacing a >> by two consecutive > tokens (17.2). — end note]

## 8.2.1 Supervising [expr.sub]

+ A postfix expression followed by expression in square brackets is a postfix expression. One of the expressions shall be a glance of array of T or a pointer to T and the other shall be a value of unescaped enumeration or integral type. The result is of type "T". The type "T" shall be a completely-defined object type. The expression E1[E2] is identical (by definition) to *(E1)(E2) [Note: see 8.3 and 8.7 for details of * and + 11.3.4 for details.]. — end note], except that in the case of an array operand, the result is an inline if operand is an xvalue. The expression E1 shall be followed before the expression E2.
A braced-list should not be used with the built-in subscript.

## 8.2.2 Function call [expr.call]

+ A function call is a postfix expression followed by parentheses containing possibly empty, comma-separated initializer-list constructs the arguments to the function. The postfix expression shall have function type or function pointer type. For a call to a non-member function or to a static member, the postfix expression shall be either an lvalue that refers to a function (in which the function-to-pointer standard conversion (7.3) is suppressed on the postfix expression), or it shall have function pointer type. Calling a function through an expression function type is different from the function type of the called function definition results in undefined behavior (10.5). For a call to a non-static member function, the postfix expression shall be an implicit (12.2.2, 12.2.3) or explicit class member access (8.2.5) whose id-expression is a function name, or a pointer-to-member (8.5) selecting a function member; the call is as a member of the class referred to by the expression. In the case of an implicit class member access, the object is the one pointed to by this expression. [Note: A member function call of the class is interpreted as (*) (12.2.2) or explicit call — end note] If a function name is used, it may be converted (Clause 10), in which case the appropriate function shall be selected according to the rules in 10.3. If the non-static member function in the expression is qualified, then it is called. Such a call is referred to as a virtual call. [Note: The type is the type of the object referred to the current value of the object expression. 15.7 describes the behavior of virtual functions when called. — end note]

> [Note: If a function member name is used, and name lookup (6.4) does not find a declaration of that name the program is ill-formed. No function is implied by such a call. — end note]

If the postfix expression designates a destructor (15.4), the type of the function call is void; otherwise, the type of the function call is the return type of the statically chosen function (i.e., ignoring the keyword), even if the type of function is actually defined. This return type shall be an object, reference or void.

When a function is called, each parameter (11.3.5) shall be initialized (11.6, 8.5, 15.1) with its corresponding argument type. If the function is a non-static member, this parameter of the function (12.2.1) shall be initialized with a pointer to the object called, converted as by an explicit call (8.4).
