# 17.8.2.2 Deducing template arguments taking the address of a function template
[temp.deduct.funccaddr]

+   1 Template arguments can be deduced from the type when taking the address of an overloaded function (16.4). The function's type and the specified type are used as types of P and A, the deduction is described in 17.8.2.5.

+   2 A placeholder type (10.1.7.4) in the return type of a function template is a non-deduced type. If argument deduction succeeds for such a function, the return type is determined by instantiation of the function body.

# 17.8.2.3 Deducing conversion function template arguments
[temp.deduct.conv]

+   1 Argument deduction is done by comparing the return type of the conversion function (call it) with the type that is deduced as the result of the conversion (call it; see 11, 16.3.1.5, and 16.3.1.6) for the determination of that type as described in 17.8.2.5.

+   2 If P is a reference type, the type referred to by P is used in place of P for deduction and for any references to or from P in the manner described in this section.

+   3 If A is not a reference type:

+   (3.1) If P is a pointer type, the type produced by the array-to-pointer standard conversion (7.2) is used in place of P for type deduction; otherwise.

+   (3.2) If P is a cv-qualified type, the type produced by the function-to-pointer standard conversion (7.3) is used in place of P for type deduction; otherwise;

+   (3.3) If P is a cv-qualified type, the top-level cv-qualifiers of P are ignored for type deduction.

+   4 If A is a cv-qualified type, the top-level cv-qualifiers of P's type are ignored for type deduction. If A is a reference type, the type referred to by A is used for type deduction.

+   5 In general, the deduction process proceeds to find argument values that will make the deduced A identical to A. However, there are four cases that allow a difference:

+   (5.1) If the original A is a reference type, A can be cv-qualified than the deduced A (i.e., the type referred to by the)

+   (5.2) If the original A is a function pointer type, A can be "pointer to function" even if the deduced A is "pointer to noexcept function".

+   (5.3) If the original A is a member function type, A can be "pointer to member of type function" even if the deduced A is "pointer to member of type noexcept function".

+   (5.4) The deduced A can be another pointer or pointer to member that can be converted to A via a qualification conversion.

+   6 These alternatives are considered only if type deduction would otherwise fail. If they yield more than one possible A, the type deduction fails.

+   7 When the deduction process requires a qualification conversion for a pointer or member type as described above, the following process is used to determine the deduced template argument values:

+If A is a type

```
cv_{1,0} "pointer to ..." cv_{1,n-1} "pointer to" cv_{1,n} T1
```

and P is a type

```
cv2,n "pointer to ..." cv2,n-1 "pointer to" cv2,n T2,
```

then the cv-unqualified T1 and T2 are used as the types of A and P respectively for type deduction.
[Example:
```

    template<class T> operator T***();
};
A;
const int * const = const * p = a; // T is deduced as int, not const int
// end example
```

# 17.8.2.4 Deducing template arguments during partial ordering [temp.deduct.partial]

+   1 Template argument deduction is done by comparing types associated with the two function templates being compared.
2 Two sets of types are used to determine the partial ordering. [Note: if the templates used is t original function type and the transformed function type is described in 17.5.2.— end note] The deduction process uses the transformed as the argument and the original type of the other template as the parameter template. This process is twice each type involved in the partial ordering: once using the transformed-1 as the argument template and template-2 as parameter template and again using the transformed-2 as argument template and template-1 as parameter template.
3 The types used to determine the ordering depend on the context in which the partial ordering is:
(3.1) In the context of a function, the types used are function parameters for which the function has arguments.
(3.2) In the context of a call to a conversion function, the types of the conversion templates used. In other contexts (17.5.2) the function type is used.
4 Each type nominated above the parameter template and the corresponding type from the argument template are the types of P and A. If a particular contains no template-parameters that participate in template deduction, P is not used to determine the ordering.
5 Before the partial ordering is done, certain transformations are performed on the types used for partialordering:
(5.1) If P is a reference type, P is replaced by the type referred to.
(5.2) If A is a reference type, A is replaced by the type referred to.
6 If P and A were reference types (before being replaced with the type referred to), determine which of the two types (if any) is more cv-qualified than the other; otherwise the types considered to be equally cv-qualified for partial ordering purposes. The result of this determination will be used below.
7 Remove top-level cv-qualifiers:
(7.1) If P is a cv-qualified type, P is replaced by the cv-unqualified version of P.
(7.2) If A is a cv-qualified type, A is replaced by the cv-unqualified version of A.

+   8 Using the resulting types P and A, the deduction is then as described in 17.8.2.5. If P is a function parameter pack, the type A of each remaining parameter type of the argument template is compared with. Default arguments are not considered to be arguments in this context; they only become arguments after a function has selected.
