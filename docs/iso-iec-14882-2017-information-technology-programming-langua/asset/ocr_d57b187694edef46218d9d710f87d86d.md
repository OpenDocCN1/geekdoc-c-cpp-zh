# ISO/IEC 14882:2017(E)

1 A character literal is one or more characters enclosed in single quotes, as in 'x', optionally preceded by u8, u, U, or L as in 'u8x', 'u\'x', or 'Lx'.

2 A character literal that does not begin with u8, u, U, or L is an ordinary character literal. An ordinary character literal that contains a single c-char representable in the execution character set has type char, with value equal to the numerical value of the encoding of the c-char in the execution character set. An ordinary character literal containing more than one c-char is a multichar literal. A multichar literal, or an ordinary character literal containing a single c-char not representable in the execution character set, is conditionally-supported, has type int and an implementation-defined value.

3 A character literal that begins with u8 as in u8x is a character literal of type char. The value of a U-8 character literal is equal to its ISO 1046 code point value, provided that the code point is a valid UTF-8 code point; otherwise, if it is not in the Basic Latin One Unicode block, the program is ill-formed. A U-8 character literal containing multiple c-chars is ill-formed.

4 A character literal that begins with the letter u, as in ux', is a character literal of type char16_t. The value of a char16_t character literal containing a single c-char is equal to its ISO 1046 code point value, provided that the code point is representable in a 16-bit code unit (it is provided that it is a multi-plane code point). If the value is not representable within 16 bits, the program is ill-formed. A char16_t character literal containing multiple c-chars is ill-formed.

A character literal that begins with the letter U, as in U'', is a character literal of type char32_t. The value of a char32_t character literal containing a single c-char is equal to its ISO 1046 code point value. A wide-character literal of type char32_t is implementation-defined.

A character literal that begins with the letter L, as in L'', is a wide-character literal. A wide-character literal has type wchar_t. The value of a wide-character literal containing a single c-char has value equal to the numerical value of the encoding of the execution-character set, unless the c-char has no representation in the execution-character set (see 6.9.1).

> [Note: The wide-character literal containing the single quote '\', the double quote '', the question mark '?', and the backslash '\' can be represented by the sequences '\', '\\', '\?', and '\\', respectively. The double quote ''' and the question mark '?' are not listed in Table 8. The backslash following the backslash not listed in Table 8 are conditionally-supported, with implementation-defined semantics. The backslash following the backslash shall be represented by the sequences '\\' and '\\\\' respectively. Each escape sequence follows a single character.

> — The value of a wide-character literal containing multiple c-chars is implementation-defined.
