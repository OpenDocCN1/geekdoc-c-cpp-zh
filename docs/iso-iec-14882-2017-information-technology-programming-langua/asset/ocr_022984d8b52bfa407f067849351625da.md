# 17.6 Name resolution [temp.res]

+   1 Three kinds of names are used within a template definition:
(1.1) The name of the template itself, and names declared within the template itself.
(1.2) Names declared on a template-parameter (17.6.2).
(1.3) Names from scopes which are visible within the template definition.

+   2 A name used in a template declaration or definition that is dependent on a template-parameter is assumed not to be a type unless the applicable lookup finds a type name or the name is qualified by the keyword typename. [Example:
// no B here

```
class X;
template<class T> class Y {
class Z;

void f() {
type* a1; // declare pointer to X

multiplier of T::A by a7; ill-formed, no visible declaration of a7
```

+   3 When a qualified-id is intended to refer to a type that is not a member of the current instantiation (17.6.2.1) and its nested-name specifier refers to a dependent type, it shall be prefixed by the keyword typename, forming a typename-name specifier. If the qualified-id does not denote a type or a class template, the program is ill-formed.

```
typename-specifier:
typename-name specifier identifier
typename-name specifier_template_opt simple-template
```

+   4 If a specialization of a template is instantiated for a set of template-arguments such that the qualified-id prefixed by typename does not denote a type or class template, the specialization is ill-formed. The usual qualified name lookup (6.4.3) is used to find the qualified-id even in the presence of typename. [Example:
