
# ISO/IEC 14882:2017(E)

## 14 Member access control [class.access]

- A member of a class can be
  - (1.1) private: that is, its name can be used only by members and friends of the class in which it is declared.
  - (1.2) protected: that is, its name can be used only by members and friends of the class in which it is declared, by classes derived from that class, and by friends (see 14.4).
  - (1.3) public: that is, its name can be used anywhere without access restriction.

- A member of a class can also access all the members to which it has access. A local class of a member function may access the member function itself may access. 113

- Members of a class defined with the keyword class is private by default. Members of a class defined with the keywords struct or union are public by default. [Example]

```cpp
class X {
    int a;
    // X::a is private by default
}
struct S {
    int a;
    // S::a is public by default
}
// example
```

Access control is applied uniformly to all names, whether the names are referred from declarations or expressions. [Note: Access control applies to names nominated by friend declarations (14.3) and using-declarations (10.3.3). -- note. In the case of overloaded function names, access control is applied to the function selected by overload. [Note: Access control applies to names, if access control is applied to a typedef name, only the accessibility of the typedef name is not considered. Accessibility of the entity referred to by the typedef is not considered. For example,

```cpp
class A {
public:
    typedef B B;
}
void f() {
    A::B x; // OK, typedef name A::B is public
    A::B y; // access error, A::B is private
}
// end note
```

It should be noted that there is access to members and base classes that is controlled, not their visibility. Names of members are still visible, and implicit conversions to base classes are still considered, when those members and base classes are inaccessible. The interpretation of a given construct is established without regard to access control. If the interpretation established makes inaccessible member names or base classes, the construct is ill-formed.

All access controls in Clause 14 affect the ability to access a class name from the declaration of a particular entity, including parts of the declaration preceding the name of the entity being declared and, the entity is a class, the definitions of the class appearing outside the class's *member-specification*.

## 14.1 Access specifiers

[class.access.spec]

- 1 Member declarations can be declared by an *access-specifier* (Clause 13):

```
access-specifier : member-specification_opt*
```

An *access-specifier* specifies the access rules for members following it until the end of the class or until another *access-specifier* is encountered. *Example:*

```cpp
class X {
    int a;
    // X::a is private by default: class used
public:
    int b;
    // X::b is public
    int c;
    // X::c is public
};
// end example
```

- 2 Any number of access specifiers is allowed and no particular order is required. [Example:
```cpp
struct S {
    int a;
    // S::a is public by default: struct used
protected:
    int b;
    // S::b is protected
private:
    int c;
    // S::c is private
public:
    int d;
    // S::d is public
};
// end example
```

- 3 [Note: The effect of access control on the order of allocation of data members is described in 12.2. — end note];

- 4 When a member is redeclared within its class definition, the access specified at this redeclaration shall be the same as its initial declaration. [Example:
```cpp
struct S {
    class A;
    enum E : int;
private:
    class A {}; // error: cannot change access
    enum E : int {}; // error
};
```

- 5 [Note: In a derived class, the lookup of a base class will find the name in the scope where it was declared. end note];
Example:
```cpp
class A {};
class B : private A {
    A a; // error: A is inaccessible
};
class C : public B {
    B b; // OK
};
```

## 14.2 Accessibility of base classes and base members

A base class of N is accessible in R, if:

- (4.1) an invented public member of B would be a public member of N, or
- (4.2) R occurs in a base or friend of class N, and an invented public member of B would be a private or protected member of N, or
- (4.3) R occurs in a base or friend of class N, and an invented public member of B would be

If a class is declared to be a base (Clause 13) for another class using the public access specifier, the public and protected members of the base class are accessible in the derived class. If a class is declared to be a base using the protected access specifier, the public and protected members of the base class are accessible in the derived class. If a class is declared to be a base using the private access specifier, in a derived class, the lookup of a base class will find the injected-class-name instead of the name in the scope where it was declared. Note: A member of a private base is accessible as an inherited name, but inaccessible directly. Because of the rules on pointer conversions (7.11) and explicit casts (8.4), a conversion from a pointer to a derived class to a pointer to an inaccessible base class might be ill-formed if an implicit conversion is used, well-formed if an explicit cast is used. Example.

```cpp
class B {
public:
 int mi;
 static int si;
};
class D : private B {
class DD : public D {
 void f();
};
```

```cpp
void DD::f() {
nmi = 3;

}
```
