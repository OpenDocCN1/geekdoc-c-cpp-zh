## 10.1.7.4.1 Placeholder type deduction [dcl.type.auto.deduct]

- Placeholder type deduction is the process by which a type containing a placeholder is replaced by a deduced type.

- A type T containing a placeholder, and a corresponding initializer e, are determined as follows:
    - for a declared-return statement that occurs in a function with a return type that contains a placeholder type, T is the deduced return type and e is the operand of the return statement. If the return statement has no operand, then e is void())
    - for a variable declaration that contains a placeholder type, T is the deduced type of the variable and e is the initializer. If the initialization is list-initialization, the initializer shall be a braced-init-list containing only a single-expression or e the assignment-expression; T
    - for a non-type parameter declaration with a type that contains a placeholder type, T is the deduced type of the non-type parameter and e is the corresponding argument.
In the case of a return statement with no operand or with an operand of type T, T shall be decltype(auto) or ce auto.

If the deduction is a return statement and is a braced-init-list (11.6.4), the program is ill-formed.

If the placeholder is the auto type-specifier, the deduced type T replacing T is using the rules for type argument deduction. Obtain P from T replacing the occurrence of auto with a new initializer e with std: std::initializer_list<U>. Deduce a value U using the rules of template argument deduction from a function call (17.8.2.1), where P is a function parameter type and the corresponding argument. If the deduction fails, the declaration is ill-formed. Otherwise, T is substituted by the deduced U into P.

```cpp
auto x = { 2 }; // decltype(x) is std::initializer_list<int>
auto x2 = { 1, 0 }; // error: multiple element type
auto x3 = { 3 };
auto x4 = {}; // decltype(x4) is std::initializer_list<int>
auto x5 = { 3 }; // decltype(x5) is int
```

## 10.1.7 Deduced class types

- A placeholder for a deduced class type is a decl-specifier in the decl-class-seq of an initializing declaration [11.6] of a variable, the placeholder is replaced by the return type of the function by overload resolution [16.3.1]. If the decl-class-seq is followed by initializer-list or member-list containing more than one declarator, the type that replaces the placeholder shall be the same in each deduction.
- A placeholder for a deduced class type can also be used in the new-type-id or type-id [8.3.4], or as the simple-type-specifier in an explicit type conversion [8.2.3]. A placeholder for a deduced class type shall not appear in any other context.
Example:

```cpp
template<T> struct container {
    container(T) {}
    template<class Iter>
    container(Iter beg, Iter end);
};
template<class Iter> container(Iter b, Iter e) : container<typename std::iterator_traits<Iter>::value_type>{
std::vector<double> v = { /* */ };
};

container c(); // OK, deduces int for T
auto d = container(v.begin(), v.end()); // error, int is not an iterator
container e(5, 6);

## 10.2 Enumeration declarations

- An enumeration is a distinct type [6.9.2] with named constants. Its name becomes an enum-name within its scope.

enum-name:
    identifier

enum-specifier:
    enum-head { enumerator-list-opt }
    enum-head { enumerator-list , }

enum-head:
    enum-key attribute-specifier-seqopt enum-name-opt enum-base-opt

enum-head-name:
    named-name-specifier-seqopt identifier

opaque-enum-declaration:
    enum-key attribute-specifier-seqopt named-name-specifier-seqopt identifier enum-base-opt;

```cpp
enum-key:
  enum
  enum class
  enum struct

enum-base:
  : type-specifier-seq
enumerator-list:
  enumerator-definition
  enumerator-list, enumerator-definition

enumerator-definition:
  enumerator
  enumerator = constant-expression

enumerator:
  identifier attribute-specifier-seq
```

The optional attribute-specifier-seq in the enum-head and the opaque-enum-declaration pertains to the enumeration; the attributes in that attribute-specifier-seq are thereafter considered attributes of the enumeration whenever it is named. A "enum nested-name-specifier identifier" within the enumerator-seq reveals a potential ambiguity between the declaration of an enumeration with an enum-base and the declaration of an unnamed bit-field of enumeration type. [Example]:

```cpp
struct S {
  enum E : int {};
  enum E : int {};
}
```

-- end note | If an enumeration-declaration contains a nested-name-specifier, the declaration shall be an explicit specialization (17.7.3).

The enumeration declaration with an enum-key of only enum and its enumerators are unscoped enumerators. The enum-keys class and enum struct are semantically equivalent; an enumeration declaration with one of these is a scoped enumeration, and its enumerators are scoped enumerators. The optional identifier for an enum-base shall not be omitted for an integral type; any cv-validation is ignored. If an enumeration-declaration has an enum-base, then the enumerators in an enumerator-list are declared as constants, and may appear wherever constants are required. An enumerator-definition with the associated enumerator value indicated by the constant-expression. If the first enumerator-definition has an initializer, the value of the corresponding constant is zero. An enumerator-definition without an initializer increases the value of the preceding enumerator by one. [Example]:

```cpp
enum a { b, c=2 };
enum d { e, f=2 };
```

defines a and d to be zero, and b to be one, and f to be three. -- end example | The optional attribute-specifier-seq in an enumeration pertains to that enumerator.

An enumeration declaration is either a declaration of an enumeration in the current scope or of a new enumeration. Note: An enumeration declaration with an enum-base-declaration has fixed the underlying type is a complete type. The list of enumerators may be provided in a later declaration with an enum-specifier. -- end note | A scoped enumeration shall not be later redecl as unscoped or with a different type. An unscoped enumeration shall not be later redecl as scoped and each redeclaration shall include an enum-base specifying the same type as in the original declaration.
