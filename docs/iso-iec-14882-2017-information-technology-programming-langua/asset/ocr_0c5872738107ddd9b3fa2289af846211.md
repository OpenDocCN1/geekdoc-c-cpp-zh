# 33.4.3 Mutex [thread.mutex.requirements]

# 33.4.1 In general [thread.mutex.requirements.general]

A mutex facilitates protection against data races and allows safe synchronization of data between execution agents (33.2.5). An execution agent owns a mutex from the time it successfully calls one of the lock functions until it unlocks. Mutex can be recursive or non-recursive, and can grant simultaneous ownership to one or more execution agents. Both recursive and non-recursive mutexes are supplied.

The mutex types are the standard library mutex, recursive_mutex, timed_mutex, recursive_timed_mutex, shared_mutex, and shared_timed_mutex. They shall meet the requirements set out in this section. In this description, m denotes an object of a mutex.

+   - The mutex types must be Lockable (33.2.5.3).

+   - The mutex types shall be Constructible and Destructible. If initialization of an object of a mutex type fails, an exception of type system_error shall be thrown. The mutex types shall not be copyable or movable.

The error conditions codes, if reported by member functions of the mutex type shall be:

+   - (4.1) resource_unavailable_try_again — if any native handler type mapped is not available.

+   - (4.2) operation_not_permitted — if the thread does not have the privilege to perform the operation.

+   - (4.3) invalid_argument — if any native type mapped as part of mutex construction is incorrect.

The implementation shall provide lock and unlock operations, as described below. For purposes of determining the existence of a data race, both atomic operations shall occur in a single order. (4.7). The lock and unlock operations on a single mutex shall occur in a total order. [Note: Construction and destruction of an object of a mutex type need not be thread-safe; other synchronization should be used to ensure that mutex objects are initialized and visible to other threads. — end note]

The expression m.lock() shall be well-formed and have the following semantics:

+   - If m is of type mutex, timed_mutex, shared_mutex, or shared_timed_mutex, the calling thread does not own the mutex.

+   - Effects: The calling blocks until ownership of the mutex can be obtained for the calling thread.

+   - Postconditions: The calling thread owns the mutex.

+   - Return type: void.

+   - Synchronization: Prior unlock() operations on the same object shall synchronize with (4.7)

+   - Throws: system_error when an exception is required (33.2.2).

+   - Error conditions:

+   - operation_not_permitted — if the thread does not have the privilege to perform the operation.
