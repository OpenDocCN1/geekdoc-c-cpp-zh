Two unordered containers a and b compare equal if a.size() == b.size(), and for every-container group [Ea, Ea] obtained from a.equal_range(a), there exists an equivalent-container group [Eb1, Eb2] obtained from b.equal_range(b), such that ispermutation(Ea, Eb1, Eb2) returns true. For unordered_value_type, the complexity of operator== (the number of calls to the operator== of value returned by a(), and the hash function returned by a()) is proportional to N in the average case and to N² in the worst case, where N is a.size(). For unordered_map and unordered_multimap, the complexity of operator== is proportional to Σ Ei in the average case and to N², where Ei is the size of the ith-container group in a. If the respective elements of each corresponding pair of equivalent-container groups Ea and Eb are in the same order (as is commonly the case, e.g., if a set and b are unordered copies of the same container), then the average-case complexity is O(N), but unordered_set and unordered_multimap becomes proportional to O(N²), except for a meticulously bad hash function.

The behavior of a program that uses operator== or operator!= on unordered containers is undefined unless the Hash and Pred objects respectively have the same behavior for both containers and the equality
