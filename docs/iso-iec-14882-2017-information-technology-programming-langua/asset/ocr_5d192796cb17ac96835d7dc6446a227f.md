# ISO/IEC 14882:2017(E)

+   4 If L is a user-defined-floating-literal, f be the literal without its ud-suffix. S contains a literal operator with parameter type long double, the literal L is treated as a call of the form

```
operator ** X(f)
```

Otherwise, S shall contain a literal operator or a literal operator template (16.5.8) but not both. If S contains a raw literal, the literal L is treated as a call of the form

```
operator ** X(f*)
```

Otherwise (S contains a literal template), L is treated as a call of the form

```
operator ** X(c1, c2, ..., ck)
```

where f is the source character set c1,c2,...,ck. [Note: c1,c2,...,ck can only contain characters from the basic source character set.] — end note

+   5 If L is a user-defined-string-literal, str be the literal without its ud-suffix and len be the number of units in str (i.e., excluding the terminating null). The L is treated as a call of the form

```
operator ** X(str, len)
```

If L is a user-defined-character-literal, ch be the literal without its ud-suffix. S shall contain a literal operator (16.5.8) but only the parameter type of ch and the literal L is treated as a call of the form

```
operator ** X(ch)
```

+   7 Example:

long double operator "(long double);

+   8 In translation phase 6 (5.2), adjacent string literals are concatenated and user-defined-string-literals are considered string literals for that purpose. During concatenation, ud-suffixes are removed and ignored and the concatenation occurs as described in 5.13.5. At the end of phase 6, if a string literal is the result of concatenation involving at least one user-defined-string-literal, the participating user-defined-string-literals have the same suffix which is applied to the concatenation.

— end example
