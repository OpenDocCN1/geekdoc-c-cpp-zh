# ISO/IEC 14882:2017(E)

# 15.6.3 Initialization by inherited constructor [class.inhor.init]

When a constructor for type B is invoked to initialize an object of a different type D (that is, when the constructor was initialized (10.3.3)), initialization proceeds as if a default constructor was used to initialize the D object and base class subclass from which the constructor was inherited, except that the B object is initialized by the invocation of the inherited constructor. The complete initialization is considered to be a single function call; in particular, the initialization of the inherited constructor's parameters is sequenced before the initialization of any part of the D object. {Example:

```
struct B1 {
B1(int, ...) {}
};
```

```
struct B2 {
B2(double) {}
};
```

```
int get();
```

```
struct D1 : B1 {
using B1::int;
int x;
int y = get();
};
```

```
void test() {
D1(2, 3, 4);
// OK: B1 is initialized by calling B1(2, 3, 4),
// d.x is default-initialized (no initialization is performed),
// d.y is initialized by calling get()
// error: D has a deleted default constructor
```

```
D1 e;

using B2::B1;
B1 b;
```


Class Log wraps any class and for all of its constructors, writing a message to the standard log whenever an object of class Log is destroyed. — end example

If the constructor was inherited from multiple base class subobjects of type B, the program is ill-formed. [Example:
