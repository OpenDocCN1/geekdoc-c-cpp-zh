# 26.2.6.1 Exception safety guarantees [associative.reqmts.excerpt]

+   For associative containers, no clear() throws an exception. erase(k) does not throw an exception unless it is thrown by the Compare object (if any).

+   For associative containers, if an exception is thrown by any operation from within an insert or replace function inserting an element, the insertion has no effect.

+   For associative containers, no swap function throws an exception unless it is thrown by the swap of the container's Compare object (if any).

# 26.2.7 Unordered associative containers [unordered.req]

+   Unordered associative containers provide ability for fast retrieval of data based on keys. The worst-case complexity for operations is linear, but the average case is much faster. The library provides four associative containers: unordered_set, unordered_map, unordered_multiset, and unordered_multimap.

+   Unordered associative containers conform to the requirements of Containers (26.2), except that the expressions a == b have different semantics for the other containers.

+   Each unordered container is parameterized by Key, by a function type Hash that has the Hash requirements (20.5.3.4) and as a hash function for values of Key, and by a binary predicate that defines equivalence relation on values of Key. unordered_map and unordered_multimap take an additional template type Key_compare.

+   The container's type of object — deduced by hash — is the hash function of the container. The container's type of predicate — deduced by pred — is the equality predicate of the container.

+   Two values k1 and k2 of type Key are equal if the container's equality predicate returns true when those are compared. If k1 and k2 are equal, the container's hash function returns the same value for both. (Note: when an associative container is initialized with a non-default Pred it usually needs a non-default Hash as parameter.— end) For any two keys k1 and k2 in the same container, calling pred(k1, k2) shall always return the same value. For any k in a container, hash(k) shall always return the same value.

+   An unordered associative container supports unique keys. It may contain at most one element for each key. However, unordered_set and unordered_map, unordered_multiset and unordered_multimap support duplicate keys. In containers that contain elements, equivalent keys are adjacent to each other in the order of the container. Although the absolute order of elements in an unordered container is not specified, elements are grouped into equivalent-key groups where all elements of group have equivalent values. Mutating operations on unordered containers shall preserve the relative order of elements within each equivalent-key group unless otherwise specified.

+   For unordered_set and unordered_multiset the value type is the same as the key type. For unordered_map and unordered_multimap it is pair<Key, To>.

+   For unordered containers the value type is the same as the key type, both iterator and const_iterator are constant iterators. It is specified whether or not iterator and const_iterator are the same type. Note: iterator and const_iterator have identical semantics in case, and iterator is convertible
