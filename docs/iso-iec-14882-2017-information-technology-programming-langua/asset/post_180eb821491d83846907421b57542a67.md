
# ISO/IEC 14882:2017(E)

## 9.5 Iteration statements

Iteration statements specify looping.

```
iteration-statement:
    while ( condition ) statement
    do statement while ( expression );
    for ( init-condition_opt, expression_opt ) statement
    for ( for-range-declaration : for-range-initializer ) statement
```

```
for-range-declaration:
    attribute-specifier-seq_opt decl-specifier-seq declarator
    attribute-specifier-seq_opt decl-specifier-seq ref-qualifier_opt { identifier-list }
    for-range-initializer:
        expr-or-braced-init-list
```

See 11.3 for the optional attribute-specifier-seq in a for-range-declaration. [Note: An init-statement ends with a semicolon.] — end note

The substatement in an iteration-statement implicitly defines a block (6.3) which is entered and exited each time through the loop.

If the statement in an iteration-statement is a single statement and not a compound-statement, it is as if it was rewritten to a compound-statement containing the original statement. [Example:]

```
while (-x > 0)
    int++;
can be rewritten as
while (-x > 0) {
    int++;
}
```

After the while statement, i is no longer in scope. — end example

If a name introduced in an init-statement or for-range-declaration is redeclared in the outermost block of the substatement it is ill-formed. [Example:]

```
void func() {
    for (int i = 0; i < 10; ++i) {
        int i = 0; // redeclaration
        for (int i : { 1, 2, 3 }) // redeclaration
    }
}
// end example
```

## 9.5.1 The while statement

In the while statement the substatement is executed repeatedly until the value of the condition (9.4) becomes false. The test takes place before each execution of the substatement.

When the substatement of a while statement is a declaration, the scope of the variable that is declared extends from its point of declaration (6.3.2) to the end of the while statement. A while statement of the form is equivalent to that

```
label:
{
    T = x;
    if (t) { // start of condition scope
statement
goto label;
} // end of condition scope
```

The variable created in a condition is destroyed and created with each iteration of the loop. [Example:
struct A {
    int val;
    A(int i) : val(i) {}
    ~A() {}
    operator bool() const { return val != 0; }
};
int i = 1;
while (A = i) {
    // ...
    i = 0;
}
end example
```

In the while-loop, the constructor and destructor are each called twice, once for the condition that succeeds and once for the condition that fails.

## 9.5.2 The statement

1. The expression is contextually converted to bool (Clause 7); if conversion is ill-formed, the program is ill-formed.
2. In the statement is executed repeatedly until the value of the expression becomes false. The test takes place after each execution of the statement.

## 9.5.4 The range-based for statement

The range-based for statement for-range-declaration : for-range-initializer statement is equivalent to

```
for (for-range-initializer) {
    auto &&__range = for-range-initializer;
    auto __begin = begin-expr;
    auto __end = end-expr;
    for (; __begin != __end; ++__begin) {
        for-range-declaration = __begin;
        statement
    }
}
```

where

- (1.1) if the for-range-initializer is an expression, it is regarded as if it were surrounded by parentheses unless a comma cannot reinterpret it delimiting two declarators);
- (1.2) __range and __end are variables defined for expression only; and
- (1.3) begin-expr and end-expr are determined as follows:
    - (1.3.1) if the for-range-initializer is an expression of array type R, begin-expr and end-expr are __range and __range bound. If R is an array of unknown bound or an array of incomplete type, the program is ill-formed;
    - (1.3.2) if the for-range-initializer is an expression of class type C, the unqualified-ids begin and end are looked up in the scope of C if class member lookup (6.4.5), and if either (or both) finds at least one declaration, begin-expr and end-expr are __range.begin() and __range.end(), respectively;
    - (1.3.3) otherwise, begin-expr and end-expr are __range.begin() and __range.end(), respectively.

## 9.6 Jump statements

1. Jump statements conditionally transfer control.

### 9.6.1 The break statement

The break statement shall only occur in an iteration-statement or switch statement of the smallest iteration-statement or switch statement; control passes to the statement following the terminated statement, if any.

### 9.6.2 The continue statement

The continue statement shall only occur in an iteration-statement or switch statement to pass to the loop continuation of the smallest iteration-statement, which is to the end of the loop.

```
while (foo) {
    do {
        for (;;) {
            // ...
            // ...
        }
        continue;
    } while (foo);
}
```

a continue not contained in an enclosed statement is evaluated as convert goto.

### 9.6.3 The return statement

The copy-or-braced-init-list of a return statement is called. A return statement with no operand shall be used only in a function whose return type is void; (15.1)—a constructor or a destructor (15.4)—void. A return statement with any other type of void shall be used only in a function whose return type is cv void; the return statement initializes the value or result of the object (explicit or implicit) function by copy-initialization (11.6) from the operand. [Note: A return statement may invoke an invocation of a constructor to perform a copy or move of the operand if it is not a value or if its types differ from the return type of the function. An object associated with a return statement may be moved or converted to a value—end note] [Example:

```
std::string result=f(const char* p, int x) {
    return (p);
}
```

—flowing off the end of a constructor, a destructor, or a function with a cv void return type is equivalent to a return with no operand. Otherwise, flowing off the end of a function other than main (6.6.1) results in undefined behavior.
