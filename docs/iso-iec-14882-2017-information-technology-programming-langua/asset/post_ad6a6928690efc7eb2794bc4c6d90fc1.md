(7.1) If value_type is wchar_t, it converts the value to native encoding (30.10.4) using the codecvt<wchar_t, mbstate_t> facet of loc.
(7.2) Otherwise a conversion is performed using the codecvt<char_t, mbstate_t> facet of loc, and then a direct conversion to the current native encoding.

- 8 Finds the detected-format from a database (30.10.8.2.1) and constructs an object of class path for which the pathname in format is

[Example: A string is to be read from a database that is encoded in ISO/IEC 8859-1, and used to create a directory.]

```cpp
namespace fs = std::filesystem;
std::string latin_string = latin_data();
codecvt_8859_1<wchar_t, char, char> latin_facet;
std::locale locale_locale("latin_facet");

```

For POSIX-based operating systems, the path is constructed by using latin_facet to convert ISO/IEC 8859-1 encoded latin_string to a wide character string in the native encoding (30.10.4). The resulting string is then converted to a narrow character pathname string in the current native encoding. If the native encoding is UTF-16 or UTF-32, or UTF-8 encoding, all of the characters in the ISO/IEC 8859-1 character set will be converted to their Unicode representation, but for other native encodings some may have no representation.

For Windows-based operating systems, the path is constructed by using latin_facet to convert ISO/IEC 8859-1 encoded latin_string to a UTF-16 wide character pathname string. All of the characters in the ISO/IEC 8859-1 character set will be converted to their Unicode representation.

# 30.10.8.4.3 path append

The operations use operator=/ to denote their semantic effect of preferred-separator when needed.

```cpp
path operator=(const path& p);
```

Effects: If p.is_absolute() && p.has_root_name() && p.root_name() != root_name(), operator(p).

Otherwise, modifies *this as by these steps:

- - If p.has_root_directory(), removes any root directory and path from the generic format pathname. If has_root_directory() or is_absolute() is true or if has_filename() is true, then append::preferred_separator to the generic format pathname.
- - Then appends the native pathname of p, omitting any root-name from its generic format pathname, to the native pathname.

Example: Even if /host is interpreted as a root-name, both of the paths path("//host"/"foo") and path("//host"/"/foo") equal to /host/foo.

Expression examples:

```cpp
// On Posix,
path("foo") / ""; yields "foo/"
path("foo") / "bar"; yields "foo/bar"
// On Windows, backslashes replace slashes in the above yields

// On Windows,
path("foo") / "c:/bar"; yields "c:\bar"
path("foo") / "c:/c"; yields "c:\c"
path("foo") / ":*"; yields "c:*"
path("foo") / "c:/bar"; yields "c:\bar"
path("foo") / "c:bar"; yields "c:\bar"
// end example
```

Returns: *this.

# 30.10.8.4.7 path generic format observers [fs.path.generic]

- 1 Generic object function returns strings formatted to the generic format (30.10.8.1). A single slash ('/') is used as the directory-separator.
- 2 Example: On an operating system uses backslashes as its preferred-separator, path("home\bar").generic_string() returns "home/bar".

```cpp

class Allocator = allocator<EChar>>

generic_string(const Allocator& a = Allocator()) const;
```

- 3 Returns: The pathname in the generic format.
- 4 Remarks: All memory allocation, including for the return value, shall be performed by a. Conversion, if any, is specified by 30.10.8.2.
