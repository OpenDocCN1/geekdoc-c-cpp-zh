# 8.2.9 Static_cast

1 The expression static_cast<T>(v) is the result of converting expression v to type T. If T is an lvalue reference or rvalue reference type, the result is an lvalue; if T is a reference to object type, the result is an xvalue; the static_cast operator must not cast away (8.2.1).

2 An instance of type "cv B", where B is a class, can be cast to type "reference D", where D is a class derived from B (Clause 13). If it is the same cv-qualification as B, or greater-qualified than. If B is a virtual base of D or a base of a virtual base, and if no standard conversion from "pointer to B" to "pointer to B" exists (7.11), the program is ill-formed. An instance of type "cv B" can be cast to type "reference D" with the same constraints as for an lvalue of type "cv B". If the object of "cv B" is actually a subclass of an object of D, the result refers to the enclosing object of type D. Otherwise, the behavior is undefined. [Example]:

```cpp
struct B {};
```

3 The recommended name for such a class is extended_type_info. If p is an expression of type cv B, then *p, *(p), *(*p), and so on, all meet this requirement.

```cpp
struct D : public B {
  B &kr =
};
static_cast<D&>(d); // produces lvalue to the original
```

4 A value of type `T1` can be cast to type-value `cvT2` if `cvT2` is reference-compatible with `cvT1`. If T is not a bit-field, the lvalue-to-value conversion (7.1) is applied to the bit-field and the resulting value is used as the expression of `static_cast` for the remainder of this section. If T is an inaccessible (Clause 14) or ambiguous (13.2) base class of T, a program that necessitates such a cast is ill-formed.

5 An expression can be explicitly converted to a type T if there is an implicit conversion from e to T, or if overload resolution for de-initialization ([11.6]) of an object or reference of type T would find at least one viable function (16.3.2). If T is a reference type, the effect is the same as performing the declaration and initialization of some variable t (11.6) and then using the temporary variable as the result of the conversion. [Note: The conversion is ill-formed when attempting to convert an expression of class to an inaccessible or ambiguous.]

6 Otherwise, the static_cast shall perform one of the conversions listed below. No other conversion shall be performed explicitly using a static_cast. Any expression can be explicitly converted to type `void`, if it becomes a discard-value expression (Clause 8). [Note: However, if the value is in an object (15.2), the destructor for that object is not accessed until the statement ends, and the value of the object is preserved for the purpose of executing the destructor. — end note]

7 The inverse of any conversion sequence (Clause 7) not containing lvalue-to-value (7.1), array-to-pointer, pointer-to-pointer (7.3), null pointer (7.11), member pointer (7.12), union (7.14), or function pointer (7.13) can be performed explicitly using `static_cast`. A program is ill-formed if it uses `static_cast` to perform an ill-formed standard conversion sequence. Example:

```cpp
struct B {
 private: B {};
void f() {
 static_cast<B*>(int(0)); // error: B is a private base of D
 static_cast<B&>(int(0)); // error: B is a private base of D
}
// end example
```

8 The lvalue-to-pointer (7.2), array-to-pointer, and function-to-pointer (7.3) conversions are applied to the object-type. A `static_cast` is subject to the restriction that the explicit conversion does not cast away const (8.2.1), and the following rules apply for special cases:

- A value of an enumeration type (10.2) can be explicitly converted to an integer type. When the value is bool, the resulting value is false if true for all other values. For the remaining integral types, the value is unchanged if the original value can be represented by the specified type. Otherwise, the resulting value is unspecified. A value of scoped enumeration type can be explicitly converted to a floating-point type; the result is the same as converting from the original value to the floating-point type.

- A value of integral or enumeration type can be converted to a complete enumeration type. The value is unchanged if the original value is within the range of the enumeration values (10.2). Otherwise, the behavior is undefined. A floating-point type can convert the original value to the underlying enumeration type. The resulting value is also the same as converting the original value to the underlying enumeration (7.10), and subsequently to that enumeration type.

11 A value of type "cv B", where B is a class type, can be cast to type "reference D", where D is a class derived from B (Clause 13). If it is the same cv-qualification as B, or greater-qualified than. If B is a virtual base of D or a base of a virtual base, and if no standard conversion from "pointer to B" to "pointer to B" exists (7.11), the program is ill-formed. An instance of type "cv B" can be cast to type "reference D" with the same constraints as for an lvalue of type "cv B". If the object of "cv B" is actually a subclass of an object of D, the result refers to the enclosing object of type D. Otherwise, the behavior is undefined.

12 A value of type `T1` can be cast to type-value `cvT2` if `cvT2` is reference-compatible with `cvT1` the same cv-qualification as, or greater-than. The recommended name for such a class is extended_type_info. [Example]:

```cpp
struct B {};
struct D : public B {
  B &kr =
};
static_cast<D&>(d); // produces lvalue to the original
```

13 A value of type `pointer to void` can be explicitly converted to any integral type large enough to hold it. The mapping function is implementation-defined. [Note: it is to be unprising to those who know the structure of the underlying machine. — end note.] A value of type `uintptr_t` is converted to an integral type; the conversion has the same meaning and validity as a conversion of `(void*)0` to the integral type. If the pointer value represents the address of A, and there is an object of type T (ignoring cv-qualification) that is pointer-interconvertible (6.9.2) with a, then the pointer value is unchanged by the conversion. If A does not satisfy the requirement of T, the behavior is undefined.

# 8.2.10 Reinterpreter cast

1 The result of the expression `reinterpret_cast<T>(v)` is the result of converting a reference to type T. If T is an value reference or a value reference to object, the result is alone; otherwise, the result is a value and value-to-reference (7.1), array-to-pointer (7.2), and function-to-pointer (7.3) standard conversions are performed on the expression v. Conversions can be performed explicitly using `reinterpret_cast`.

2 The `reinterpret_cast` operator shall not cast away (8.2.11). An expression of integral, enumeration, or pointer-to-pointer may be converted explicitly to such type; a class yields the value of its operands.

> Note: The mapping performed by `reinterpret_cast` might not, or produce a representation from the original value — end note.
