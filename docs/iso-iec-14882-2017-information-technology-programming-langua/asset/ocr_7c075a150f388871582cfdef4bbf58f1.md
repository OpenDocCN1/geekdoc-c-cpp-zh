# 10.1.1

Change: In C++, register is not a storage class specifier.

Rationale: The storage class specifier has no effect in C++.

Effect on original feature: Deletion of semantically well-defined feature.

Difficulty of converting: Syntactic transformation.

How widely used: Seldom.

# 10.1.3

Change: A++ typedef name must be different from any type name declared in the same scope (except if it is a synonym of the class name with the same name). In C, a typedef and a struct tag name declared in the same scope can have the same name (because they have different namespaces).

Example:

```
typedef struct name { /* ... */ name }; // valid C and C++
struct name { /* ... */ };
typedef int; // valid invalid C
```

Rationale: For ease of use, C++ doesn't require that a type name be prefixed with the keywords struct or union when used in object declarations or type cases.

Example:

```
class name { /* ... */ };
name; // it has type class
```

Effect on original feature: Deletion of semantically well-defined feature.

Difficulty of converting: Semantic transformation. One of the 2 types has to be renamed.

How widely used: Seldom.

# 10.1.7 see also 6.31

Change: const objects must be initialized in C++ but can be uninitialized in C.

Rationale: A const object cannot be assigned to unless it must be initialized to hold a useful value.

Effect on original feature: Deletion of semantically well-defined feature.

Difficulty of converting: Semantic transformation.

How widely used: Seldom.

# 10.1.7 Banning implicit int.

In C++ a decl-specifier must contain a type-specifier, unless it is followed by a declarator for a constructor, a destructor, or a conversion function. In the following example, the left-hand column presents valid C; the right-hand column presents invalid C:

```
void f(const int param);      void f(const int param);
const n = 3;                      const int n = 3;
main()                             int main()
  /* ... */                          /* ... */ /
```
