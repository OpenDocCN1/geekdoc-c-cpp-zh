## 33.4.4.4 Class template shared_lock

template <class Mutex>
class shared_lock {
public:
  using mutex_type = Mutex;

An object of shared_lock controls the shared ownership of a lockable object within a scope. Shared ownership of the lockable object may be acquired or after construction, and may be transferred, after acquisition, to another shared_lock object. Objects of type shared_lock are not copyable but are movable. The behavior of a program is undefined if the contained pointer pm is not null and the lockable object pointed to by pm does not exist for the remaining lifetime (6.8) of the shared_lock object. The supplied mutex type shall meet the shared mutex requirements (33.4.3.5).

> [Note: shared_lock meets the Timedlock requirements (33.2.5.4). — end note]

## 33.4.5 Generic locking algorithms

```
template <class L1, class L2, class L3...> int try_lock(L1&, L2&, L3&...);
```

Requires: Each template parameter type shall meet the Lockable requirements. [Note: The Unique_lock class template meets these requirements when instantiated. — end note]

Effects: Calls try_lock() for each argument beginning with the first until all arguments have been processed or a call to try_lock() fails, either by returning false or throwing an exception. If a call to try_lock() fails, unlock() shall be called for all prior arguments and there should be no further calls to try_lock().

Returns: -1 if all calls to try_lock() returned true, otherwise a zero-based index value that indicates the argument for which try_lock() returned false.
