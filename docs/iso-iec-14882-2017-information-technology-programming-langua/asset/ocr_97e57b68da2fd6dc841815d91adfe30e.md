# ISO/IEC 14882:2017(E)

# 20.5.5.10 Protection within classes [protection.within.classes]

1 It is unspecified whether any function signature or class described in Clauses 21 through 33 and Annex D is a friend of any class in the C++ standard library.

# 20.5.5.11 Derived classes [derivation]

1 An implementation may derive any class in the C++ standard library from a class with a name reserved to the implementation.

2 Classes defined in the C++ standard library are required to be derived from other classes in the C++ standard library. An implementation may derive such a class directly from the base or indirectly through a hierarchy of base classes with names reserved to the implementation.

3 In any case:

+   (3.1) Every class described as virtual shall be virtual;

+   (3.2) Every class not described as virtual shall not be virtual;

+   (3.3) Unless explicitly stated otherwise, types with distinct names shall be distinct.¹182

4 All types in the C++ standard library shall be non-final types unless otherwise specified.

# 20.5.5.12 Restrictions on exception handling [res.exception.handling]

1 Any of the functions in the C++ standard library can report a failure by throwing an exception of their type described in their Paragraph; or by throwing an exception of a type named in the Paragraph that would be caught by an handler for the base type.

2 Functions from the C++ standard library shall not throw exceptions¹183 except when such a function calls a program-specified function that throws exception.¹84

3 Destructor operations in the C++ standard library shall not throw exceptions. Every destructor in the C++ standard library shall have a non-throwing exception specification.

4 Functions in the C++ standard library that do not have a Paragraph but have a potentially-throwing exception specification may throw implementation-defined exceptions.¹185 Implementations should report errors by throwing exceptions of or from the standard exception classes (21.6.3.1, 21.8, 22.2).

5 An implementation may strengthen the exception specification for a non-virtual function by adding a non-throwing exception specification.

# 20.5.5.13 Restrictions on storage of pointers [res.pointer.storage]

1 Objects constructed by the standard library that may hold a smart-pointer value or an integer of type::intptr_t shall store values in a traceable pointer location (6.7.4.3). [Note: Others are strongly encouraged to use the same, since doing so may result in accidental use of pointers that are not safely defined. Libraries that store pointers outside the user's address space should make it apparent that they are stored and returned from a traceable pointer location. — end note]
