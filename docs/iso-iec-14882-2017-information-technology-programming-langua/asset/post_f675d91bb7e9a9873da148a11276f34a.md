# 15.6 Initialization [class.init]

- 1 When not initialized for an object of (possibly cv-qualified) class type (or array thereof), or the initializer has no form {}, the object is initialized in 11.6.

- 2 An object of class type (or array) may be explicitly initialized [either explicitly or implicitly] and the elements are initialized by constructor, the constructor shall be called for each element of the array, following the subscript order; see 15.6.1 and 15.6.2. 11.4. [Note: Destructors for the array elements are called in reverse order of their construction. — end note]

# 15.6.1 Explicit initialization [class.explicit]

- 1 An object of class type may be initialized with a parenthesized expression-list, where the expression-list is constructed as an argument list for a constructor that initializes the object. Alternatively, a single assignment-expression can be specified as an initializer using the = of initialization. Either direct-initialization semantics or copy-initialization semantics apply; see 11.6. [Example:

```
struct complex {
    complex();
    complex(double);
    complex(double,double);
};
```

```
complex sqrt(complex,complex);
complex(a); // initialize by a call of complex(double)
complex b = a; // construct complex(1) using complex(double,double).
complex c = complex(1,2); // copy/move it
complex d = sqrt(b,c); // call by a call of complex(complex,complex) and copy/move the result into d
complex e; // initialize by a call of complex(double)
complex f = 3; // construct complex(3) using complex(double), copy/move it into f
complex g = { 1, 2 }; // initialize by a call of complex(double,double)
```

end note [Note: Overloading of the assignment operator (16.5.3) has no effect on initialization.

- 2 An object of class type may be initialized by a braced-init-list. List-initialization semantics apply; see 11.6 and 11.6.4. [Example:

```
complex v[6] = { 1, complex(1,2), complex(0), 2 };
```

Here, complex::complex(double) is called for the initialization of v[0] and v[3]; complex::complex(double,double) is called for the initialization of v[1]; complex::complex() is called for the initialization of v[2], v[4]. For another example,

```
struct X {
    int f;
    complex c;
}
x = { 9, 8.8, 7.7 };
```

Here, x is initialized with 9, f is initialized with 8.8, and complex::complex(double) is called for the initialization of c. [Note: Braces are elided in the initializer-list for any aggregate, if the aggregate has members of a class with user-defined type; see 16.6.] [Note: If T is a class with no default constructor, any declaration of an object of T (or array) is ill-formed if initialization is specified (see 15.6.2).] [Note: The order in which storage duration initialization is described in 6.6.3 and 9.7.]

# 15.6.2 Initializing bases and members [class.init]

In the definition of a constructor for a class, initializers for direct and virtual class subobjects and non-static data members can be specified by a constructor-initializer, which has the form

```
ctor-initializer:
  : mem-initializer-list
  initializer-list:
    mem-initializer ...opt
    mem-initializer-list, mem-initializer ...opt
mem-initializer:
  mem-initializer(expression-list)
  mem-initializer(braced-init)
  class-identifier:
    identifier
class-or-type
```

In a member initializer an unqualified identifier is looked up in the scope of the constructor's class, and not found in such class, it is looked up in the scope containing the constructor. [Note: If the class contains a member with the same name as a direct or virtual base of the class, a member-initializer naming the member or base of a single identifier refers to the constructor's class, a non-static data member of the class. A member-initializer for the hidden base may be specified using a qualified name.—end note] Unless the member-initializer names the data member of the constructor's class, a direct or virtual base of that class, the member-initializer is ill-formed.

A member-initializer can initialize a base class using any class-or-type that denotes that base class. [Example:

```
struct A {
  A global_A;
};
struct B {
};
struct C : public A, public B {
  C() : A(global_A) {} // member-initializer for base A
};
```

A member-initializer is ambiguous because it denotes a direct base class and an inherited base class, the member-initializer is ill-formed. [Example:

```
struct A {
  A();
};
struct B : virtual A {
};
struct C : public A, public B {
  C() : A() {} // ill-formed: which A?
};
```

A constructor-initializer may initialize a variant of the constructor's class. If a constructor-initializer specifies more than one member-initializer for the same member or for the same base class, the constructor-initializer is ill-formed.

- 6 A member-initializer can delegate to another of the constructor's class using any class-or-type that denotes the constructor's class itself. If a member-initializer designates the constructor's class, it shall be the only member-initializer; the constructor is a delegating constructor, and the constructor selected by the member-initializer is the target constructor. The target body of the delegating constructor is executed. If a constructor delegates to itself directly or indirectly, the program is ill-formed, no diagnostic required. Example:

```
struct C {
    C() {} //: non-delegating constructor
    C(int) : C(42) //: delegates to #1
    C(char c) : C(C(42)) //: ill-formed due to recursion with #4
    C(double d) : C('a') //: ill-formed due to recursion with #3
};
```

- 7 The initialization-list or braced-init-list is used to initialize the designated subobject (or, in the case of a delegating constructor, the complete object) according to the initialization rules of 11.6 for direct-initialization. Example:

```
struct B {
    B(int) : /* ... */ {};
    B(int) : /* ... */ {};
};
struct D {
    B b1, b2;
    D(int);
    const int c;
};
D(int a) : b2(a), b1(a+2), c(a+3), b(a+4) { /* ... */ }
D(10);
```

> Note: The initialization by each member-initializer constitutes a full-expression (1.6). Any expression in a member-initializer is evaluated as part of the full-expression that performs the initialization.
- note A member-initializer where the member-initializer denotes a virtual base class is ignored during execution of a constructor of any class that is not the most derived class.

- 8 A temporary expression bound to a reference in a member-initializer is ill-formed. Example:

```
struct A {
    A() : v(42) // error
    const int v;
};
```

- 9 In a non-delegating constructor, if a potentially constructed subobject is not designated by a member-initializer (including the case where there is no member-initializer-list because the constructor has no constructor-initializer), then

— if the entity is a non-static data member that has a default member initializer (12.2) and either
    — the constructor's class is a union (12.3), and no other variant member of that union is designated by a member-initializer-or-decl
    — the constructor's class is not a union, and if the entity is a member of an anonymous union, no other member of that union is designated by a member-initializer-id,
— the entity is initialized from its default member initializer as specified in 11.6;

—otherwise, if the entity is an anonymous union or a variant member (12.3.1), no initialization is performed;
