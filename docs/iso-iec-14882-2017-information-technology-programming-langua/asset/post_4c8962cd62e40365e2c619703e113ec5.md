
# ISO/IEC 14882:2017(E)

## 23.19.5 Parallel execution policy [exececpol.par]

```cpp
class execution::parallel_policy { unspecified };
```

- 1 The class execution::parallel_policy is an execution policy type used as a unique type to disambiguate parallel algorithm overloading and indicate that a parallel algorithm's execution may be parallelized and vectorized.
- 2 During the execution of a parallel algorithm with the execution::parallel_policy policy, if the invocation of an element access function exists via an uncaught exception, terminate() shall be called.

## 23.19.6 Parallel and unsequenced execution policy [execpolunseq]

```cpp
class execution::parallel_unsequenced_policy { unspecified };
```

- 1 The class execution::parallel_unsequenced_policy is an execution policy type used as a unique type to disambiguate parallel algorithm overloading and indicate that a parallel algorithm's execution may be parallelized and vectorized.
- 2 During the execution of a parallel algorithm with the execution::parallel_unsequenced_policy policy, if the invocation of an element access function exists via an uncaught exception, terminate() shall be called.

## 24 Character traits

[char.traits]

- 1 This subclause defines requirements on representing character traits, and defines four specializations, char_traits<char>, char_traits<char16_t>, char_traits<char32_t>, and char_traits<wchar_t>, that satisfy those requirements.
- 2 Most specified in Clauses 24.3 and 30 need a set of related types and functions to complete the definition of their semantics. These types and functions are provided as a member of typedef-name and in the template parameter traits used by each template. This subclause defines the semantics of these members.
- 3 To specialize these templates to generate a string or iostream class for a particular character trait Type, and its related character traits Traits are passed as a pair of parameters to the string or iostream template as parameters Traits:char should be the same as Char.
- 4 This subclause specifies a template, char_traits<char>, and explicit specializations of, char_traits<char>, char_traits<char16_t>, char_traits<char32_t>, and char_traits<wchar_t>, of which appears in the header <string> and satisfies requirements below.

### 24.2.2 Types [char.traits.typedefs]

- 1 The type char_type, a related container type INT_T shall be a type or class that can represent all the valid characters converted from the corresponding char_type values, as well as an end-of-file value, EOF represents a container type which can hold end-of-file to be used as a return type of the lostream class functions.
- 2 using int_type = INT_T;
- 3 Requires Requirements for off_type and pos_type are described in 30.2.2 and 30.3.
- 4 using off_type = implementation-defined; using pos_type = implementation-defined;
- 5 using state_type = STATE_T;
- 6 Requires: state_type shall meet the requirements of CopyAssignable (Table 26), CopyConstructible (Table 24), and DefaultConstructible types.
- 7 If EOF can be held in char_type then some lostream operations may give surprising results.
