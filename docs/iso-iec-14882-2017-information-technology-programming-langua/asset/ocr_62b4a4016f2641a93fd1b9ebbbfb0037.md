# ISO/IEC 14882:2017(E)

# 16.3.1.3 Initialization by constructor

[over.match.ctor]

1 When objects of class type are direct-initialized (11.6), copy-initialized from expression of the same or a derived class type (31.6), or default-initialized (11.6), overload resolution selects the constructor. For direct-initialization or default-initialization that is not in the context of copy-initialization, the candidate functions are all the constructors of the class being initialized. For copy-initialization, the candidate functions are all the converting constructors (15.3.1) of that. The argument list is the *expression-list or assignment-expression of the initializer*.

# 16.3.1.4 Copy-initialization by user-defined conversion

[over.match.copy]

1 Under the conditions specified in 11.6, as part of an copy-initialization of an object of class type, a user-defined conversion can be invoked to convert an initializer expression to the type of the object being initialized. Overload resolution is used to select the user-defined conversion to invoked. [Note: The conversion for indirect binding to a reference to a possibly cv-qualified type is determined in terms of a corresponding non-reference copy-initialization. *end note*] Assuming that *cv T* is the type of the object being initialized, with T class type, candidate functions are selected as follows:

+   (1.1) The converting functions (15.3.1) of T are candidate functions

When the type of the initializer is class T or *cv T*, the non-explicit conversion functions of T are considered. When initializing a temporary to be the first parameter of a constructor where the parameter is type *reference to possibly cv-qualified T* and it is called with a single argument in the context of direct-initialization of an object of type *cv T*, then explicit conversion functions are also considered. Those that are not hidden within S and yield a type whose un-qualified version is valid. Conversion functions that return *reference to X* return values or xvalues, depending on the type of reference, of type X and are considered to yield X for this process of selecting candidate functions.

2 In both cases, the argument list has one argument, which is the initializer expression. [Note: This argument will be compared against the first parameter of the constructors and against the implicit object parameter of the conversion functions. *end note*]

# 16.3.1.5 Initialization by conversion function

[over.match.conv]

1 Under the conditions specified in 11.6, as part of an initialization of an object of class type to the type of the object being initialized. Overload resolution is used to select the conversion function to be invoked. Assuming that *cv T* is the type of the object being initialized, and *cv S* is the type of the initializer expression, with S class type, candidate functions are selected as follows:

+   (1.1) The conversion functions of S and its base classes are considered. Those non-explicit conversion functions that are not hidden within S and yield a type T or one that can be converted to T via a standard conversion (16.3.1.1) are candidate functions. For direct-initialization, explicit conversion functions that are not hidden within S and yield a type T or one that can be converted to with a qualification conversion (7.5) are also candidate functions. Conversion functions that return a cv-qualified type are considered to yield the un-qualified version of that for this process of selecting candidate functions. Conversion functions that return *reference to cv2* return values or xvalues, depending on the type of reference, of type *cv2* and are therefore considered to yield X for this process of selecting candidate functions.

2 The argument list has one argument, which is the initializer expression. [Note: This argument will be compared against the implicit object parameter of the conversion functions. *end note*]
