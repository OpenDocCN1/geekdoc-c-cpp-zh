## 29.2 Definitions [numerics.defns]

+ Define GENERALIZED_NONCOMMUTATIVE_SUM(op, a1, ..., aN) as follows:

+ (1.1) all when N is not 1, otherwise
(1.2) op(GENERALIZED_NONCOMMUTATIVE_SUM(op, a1, ..., aN), aK), GENERALIZED_NONCOMMUTATIVE_SUM(op, a1, ..., aK) for any K where 1 < K+1 = M ≤ N.

2 Define GENERALIZED_SUM(op, a1, ..., aN) as GENERALIZED_COMMUTATIVE_SUM(op, b1, ..., bN), where b1, ..., bN be any permutation of a1, ..., aN.

## 29.3 Numeric type requirements [numerics.requirements]

1 The complex and array components are parameterized by the type of information they contain and maintain a C++ program shall instantiate these components with only a type T that satisfies the following requirements,²267

+ (1.1) T is not an abstract class (it has no virtual member functions);
(1.2) T is not a reference type;
(1.3) T is not cv-qualified;
(1.4) If T is a class, it has a default constructor;
(1.5) If T is a class, it has a public copy constructor with the signature T::(const Tk)
(1.6) If T is a class, it has a public destructor;

> ²267 In other words, value types. These include arithmetic types, pointers, the library class complex, and instantiations of vararray for value types.

(1.7) If T is a class, it has a public assignment operator whose signature is either T& T::operator=(const T&) or T& T::operator=(T)

(1.8) If T is a class, its assignment operator, copy and default constructors, and destructor shall correspond to each in the following line:

+ (1.8.1) Initialization of raw storage using the copy constructor on the value of T(), however obtained, is semantically equivalent to value-initialization of the raw storage

+ (1.8.2) Initialization of raw storage using the default constructor, followed by assignment, is semantically equivalent to initialization of raw storage using the copy constructor.

+ (1.8.3) Destruction of an object, followed by initialization of raw storage using the copy constructor, is semantically equivalent to the original object.

> [Note: This rule, in places, is that there shall not be any differences in the semantics of initialization versus assignment. This gives an implementation considerable clarity in how arrays are initialized.

> [Example: An implementation is allowed to initialize a varray by allocating storage using the new operator (which implies a call to the default constructor for each element) and then assigning each element its value. Or implementation can allocate raw storage and use the copy constructor to initialize each. — end example]

If the difference between initialization and assignment is important for a class, or if it fails to satisfy any of the other conditions listed above, the programmer should use vector (26.3).

(1.9) If it is a operation on T does not overload the exception.

2 In addition, many member and related functions of varray<T> can be successfully instantiated and exhibit well-defined behavior only if T satisfies additional requirements for each member or related function.

> [Example: It is valid to instantiate varray<complex>, but operator() will not be successfully instantiated for varray<complex>, since complex does not have any operators. — end example]

+ 3 A separate floating-point environment shall be maintained for each thread. Each function accesses the environment through its calling.

## 29.5 Complex numbers [complex-numbers]

+ 1 The header <complex> defines a template, and numerous functions for representing and manipulating complex numbers.

+ 2 The effect of instantiating the template complex for any type other than float, double, or long double is unspecified. The specializations complex<float>, complex<double>, and complex<long double> are literal types (6.9).

+ 3 If the result is not mathematically defined or not in the range of representable values for its type, the behavior is undefined.

4 If there is an expression value of type complex<T> then:

+ (4.1) the expression reinterpret_cast<cu> T[2](z) shall be well-formed,

+ (4.2) reinterpret_cast<cv> T[2](z)[0] shall designate the real part of z

+ (4.3) reinterpret_cast<cv> T[2](z)[1] shall designate the imaginary part of z.

Moreover, if there is an expression of type complex<T*> and the expression a[i] is well-defined for an integer expression i, then:

+ (4.4) reinterpret_cast<cu> T*(a)[2*i] shall designate the real part of a[i]
