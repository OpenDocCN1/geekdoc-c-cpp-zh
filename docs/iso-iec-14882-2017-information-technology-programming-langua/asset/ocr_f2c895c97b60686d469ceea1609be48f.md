# ISO/IEC 14882:2017(E)

# 23.7.7 Visitation [variant.visit]

```
template <class Visitor, class... Variants&&... vars;
constexpr see below(Visitor&, Variants&&...);
```

+   1 Requires: The effect in the Effects: element shall be a valid expression of the same type and value for all combinations of alternative types of all variants. Otherwise, the program is ill-formed.
2 Effects: Let is... vars.index(). Returns INVOOKE(forward<Visitor>(vis), get<forward<Variants&&>(vars)..>)(23.4.3).
3 Returns: The return type is the common type of all possible INVOOKE expressions of the Effects: element.
4 Throws: bad_variant_access if any variant in vars is valueless_callback exception.
5 Complexity: If sizeof...(Variants) <= 1, the invocation of the callback is implemented in constant time, it does not depend on sizeof...(Types). The invocation of the object has no complexity requirements.

# 23.7.8 Class monostate [variant.monostate]

struct monostate;
nThe monostate class can serve as a first alternative for a variant to make the variant type constructible.

# 23.7.9 monostate relational operators [variant.monostate.relops]

```
constexpr bool operator==(monostate, monostate) noexcept { return false; }
constexpr bool operator==(monostate, monostate) noexcept { return false; }
constexpr bool operator<(monostate, monostate) noexcept { return true; }
constexpr bool operator>(monostate, monostate) noexcept { return true; }
constexpr bool operator<=(monostate, monostate) noexcept { return true; }
constexpr bool operator>=(monostate, monostate) noexcept { return false; }
```

> Note: Monostate objects have only a single state; they always compare equal.

# 23.7.10 Specialized algorithms [variant.specalg]

```
template <class Types...>
void swap(variant<Types...>& v, variant<Types...>& w) noexcept(see below);
```

+   1 Effects: This function shall not participate in overload resolution unless is_move_constructible_<vT> && is_swappable_<vT> is true for all i. The expression inside noexcept is equivalent to noexcept(swap(v, w)).

# 23.7.11 Class bad_variant_access [variant.bad.access]

```
class bad_variant_access : public exception {
public:
    bad_variant_access() noexcept;
    const char* what() const noexcept override;
};
```

+   1 Objects of type bad_variant_access are thrown to report invalid accesses to the value of a variant.
