## 5.13.8 User-defined literals [lex.ext]

```
user-defined-literal:
user-defined-integer-literal
user-defined-floating-literal
user-defined-string-literal
user-defined-character-literal
user-defined-integer-literal:
  decimal-literal-ud-suffix
  octal-literal-ud-suffix
  hexadecimal-literal-ud-suffix
  binary-literal-ud-suffix
user-defined-floating-literal:
  fractional-constant-exponent-part_opt ud-suffix
  digit-sequence-exponent-part-ud-suffix
  hexadecimal-prefix-hexadecimal-fraction-constant-binary-exponent-ud-suffix
  hexadecimal-prefix-hexadecimal-digit-sequence-binary-exponent-part-ud-suffix
user-defined-string-literal:
  string-ud-suffix
user-defined-character-literal:
  character-literal-ud-suffix
ud-suffix:
```

- 1 If a token matches both user-defined-literal and another kind, it is treated as the latter. [Example: 12km is a user-defined-literal, 12LL is an integer. — end example] The syntactic non-terminal preceding the form of a ud in a user-defined-literal is taken to be the longest sequence of characters that match that non-terminal.
- 2 A user-defined literal is treated as a literal operator or literal operator template (16.5.8). To determine the form of this for a given user-defined-literal L with ud-suffix X, the literal-operator-whose literal suffix is X is looked up in the context of L using the rules for unqualified lookup (6.4.1). Let S be the set of declarations for this lookup. S shall not be empty.
- 3 If L is a user-defined-integer-literal, let it be the literal without ud-suffix. If S contains a literal suffix with parameter type unsigned long long, the literal L is treated as a form of the operator "" ('*) Otherwise, S contains a raw literal or a literal operator template (16.5.8) but not both. If S contains a raw literal, the literal L is treated as a form of the operator "" ("* Otherwise (If S contains a literal operator template), L is treated as a form of the operator "" <c1', c2', ... ck'> > where n is the source character sequence c1,c2...ck. [Note: the sequence c1,c2...ck can only contain characters from the basic source character set. — end note]
- 4 If L is a user-defined-floating-literal, f be the literal without its ud-suffix. S contains a literal operator with parameter type long double, the literal L is treated as a call of the form

```
operator "" X(f)
```

Otherwise, S shall contain a literal operator or a literal operator template (16.5.8) but not both. If S contains a raw literal, the literal L is treated as a call of the form

```
operator "" X(f*)
```

Otherwise (S contains a literal template), L is treated as a call of the form

```
operator "" X(c1, c2, ..., ck)
```

where f is the source character set c1,c2,...,ck. [Note: c1,c2,...,ck can only contain characters from the basic source character set.] — end note
- 5 If L is a user-defined-string-literal, str be the literal without its ud-suffix and len be the number of units in str (i.e., excluding the terminating null). The L is treated as a call of the form

```
operator "" X(str, len)
```

If L is a user-defined-character-literal, ch be the literal without its ud-suffix. S shall contain a literal operator (16.5.8) but only the parameter type of ch and the literal L is treated as a call of the form

```
operator "" X(ch)
```
- 7 Example:
```cpp
long double operator ""(long double);
std::string operator ""(const char16*, std::size_t);
unsigned operator ""(const char*);
int main() {
    1.2_w; // calls operator ""u"1.2")
    one_w; // calls operator ""u"one")
    12_w; // calls operator ""u"12")
    "two_w"; // no applicable literal operator
}
```
— end example
- 8 In translation phase 6 (5.2), adjacent string literals are concatenated and user-defined-string-literals are considered string literals for that purpose. During concatenation, ud-suffixes are removed and ignored and the concatenation occurs as described in 5.13.5. At the end of phase 6, if a string literal is the result of concatenation involving at least one user-defined-string-literal, the participating user-defined-string-literals have the same suffix which is applied to the concatenation.
- 9 Example:
```cpp
int main() {
    L"A" "B" "C_x"; // OK: same as L"ABC_x"
    "P_x" "Q" "R"; // error: two different-suffixes
}
```
— end example

## 6 Basic concepts

- 1 [Note: This Clause presents the basic concepts of the C++ language. It explains the difference between an object and how they relate to the value for expressions. It introduces the concepts of a declaration and a definition and presents C++'s notion of type, scope, linkage, and storage duration. The mechanisms for starting and terminating a program are described. Finally, this Clause presents the fundamental types of the language and the ways of constructing types. — end note.]
- 2 [Note: This Clause does not cover concepts that affect only non-static data type. Language concepts are introduced in the relevant Clauses. — end note]
- 3 An entity is a value, object, reference, function, enumerator, type, class member, bit-field, template, namespace, or parameter pack.
- 4 A name is a use of an entity introduced by an identifier(5.10.2), operator-function(16.5), literal-operator(16.5.8), conversion-function(15.3.2), or template-id(17.2) that denotes an entity or label(9.6.4, 9.1).
- 5 Every name that denotes an entity is introduced by a non-static data member or every label is introduced by a goto statement(9.6.4) or a labeled-statement(9.1).
- 6 A variable is introduced by the declaration of a reference or any non-static data member or an object. The variable's name is called name lookup(6.4).
- 7 Some names denote types or templates. In general, whenever a name is encountered it is necessary to determine whether name denotes one of these entities before continuing to process the program that it contains. The process that determines this is called name lookup(6.4).
- 8 Two names are the same
  - (8.1) they are composed of a single part of the character sequence,
  - (8.2) they are operator-function-ids with the same operator,
  - (8.3) they are conversion-function-ids with the same type, or
  - (8.4) they are names of literal operators that refer to the same class, function, or variable, or
  - (8.5) they are the names of literal operators(16.5.8) formed with the same literal identifier.
- 9 A name used in more than one translation unit can potentially refer to the same entity in these translation units upon the linkage(6.5) of the name in each translation unit.

## 6.1 Declarations and definitions [basic.def]

- 1 A declaration(Clause 10) may introduce one or more names into a translation unit or rename names introduced by previous declarations. If the declaration specifies the interpretation and attributes of these names. A declaration may also have effects:
  - (1.1) — static assertion(Clause 10),
  - (1.2) controlling template instantiation(17.7.2),
  - (1.3) guiding argument deduction for constructors(17.9),
  - (1.4) use of attributes(Clause 10), and
  - (1.5) nothing (in the case of an empty-declaration).
- 2 A declaration is a definition unless
  - (2.1) — it declares a function without specifying the function's body (11.4),
  - (2.2) — it contains the extern specifier (10.1.1) or a linkage-specification(10.5) and neither an initializer nor a function-body,
  - (2.3) — it declares a non-inline static data member in a class definition (12.2, 12.2.3),
  - (2.4) — it declares a static data member outside a class definition and the variable was defined with the constexpr specifier (this usage is deprecated; see D,1)
  - (2.5) — it is a class declaration (12.1),
  - (2.6) — it is an opaque-declaration (10.2),
  - (2.7) — it is a template-parameter (17.1),
  - (2.8) — it is a parameter-declaration (11.3.5) in a class definition that is not the declarator of a function-definition,
  - (2.9) — it is a typedef declaration (10.1.3),
  - (2.10) — it is an alias-declaration (10.1.3),
  - (2.11) — it is a using-declaration (10.3.3),
  - (2.12) — it is a deduction-declaration (17.9),
  - (2.13) — it is a static_assert-declaration (Clause 10),
  - (2.14) — it is an attribute-declaration (Clause 10),
  - (2.15) — it is an empty-declaration (Clause 10),
  - (2.16) — it is a using-directive (10.3.4),
  - (2.17) — it is an explicit-declaration (17.7.2), or

> 20) Appearing inside the braced-enclosed declaration-seq in a linkage-specification does not affect whether a declaration is a definition.
