## 20.5.3.3 NullPointer requirements [nullablepointerrequirements]

A NullPointer type is a pointer-like type that supports null values. A type P meets the requirements of NullPointer if:

- (1.1) P satisfies the requirements of EqualityComparable, DefaultConstructible, CopyConstructible, Copyassignable, and Destructible.
- (1.2) Values of P are parsable (20.5.3.2).
- (1.3) the expressions shown in Table 28 are valid and have the semantics, and
- (1.4) P satisfies all the other requirements

A value-initialized object of type P produces the null value of the type. The null value should be equivalent only to itself. A default-initialized object of type P may have an indeterminate value. [Note: Operations involving indeterminate value may cause undefined behavior.] end note

An object of type P can be contextually converted to bool (Clause 7). The effect will be if p!=nullptr has been evaluated in place of p.

No operation is part of the NullPointer requirements shall exit via an exception.

## 20.5.3.4 Hash requirements [hash.requirements]

A type H has the Hash requirements:

- (1.1) it is a function object type (23.14),
- (1.2) it satisfies the requirements of CopyConstructible and Destructible (20.5.3.1), and
- (1.3) the expressions shown in Table 29 are valid and have the semantics.

Given Key is an argument type for function objects of type H, in Table 29 h is a value of type (possibly const) H. u is a value of Key, and k is a value of type convertible to (possibly const) Key.

## 20.5.3.5 Allocator requirements [allocator.requirements]

The library describes a standard set of requirements for allocators, which are class-type objects that encapsulate the information about an allocation model. This information includes the knowledge of pointer types, the type of size of allocators in this allocation model, as well as the memory and deletion delimitations for. All of the types (Clause 24), containers (Clause 26) (except array), string buffers and streams (Clause 30), and match_results (Clause 31) are parameterized in terms of allocators.
