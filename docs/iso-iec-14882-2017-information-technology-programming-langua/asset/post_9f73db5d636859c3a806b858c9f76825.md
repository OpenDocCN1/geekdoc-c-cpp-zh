## 30.10.13 Class directory_iterator

An object of type directory_iterator provides an iterator for a sequence of directory_entry. For exposition, class recursive_directory_iterator should see 30.10.14.

```cpp
namespace std::filesystem {
class directory_iterator {
public:
    using iterator_category = input_iterator_tag;
    using value_type = directory_entry;
    using difference_type = ptrdiff_t;
    using pointer = const directory_entry*;
    using reference = const directory_entry&;

    directory_iterator();
    directory_iterator(const path& p, directory_options options);
    directory_iterator(const path& p, error_code& ec) noexcept;
    directory_iterator(const path& p, directory_options options, error_code& ec) noexcept;
    directory_iterator(const directory_iterator& rhs);
    directory_iterator(directory_iterator&& rhs) noexcept;

    directory_iterator& operator=(const directory_iterator& rhs);
    directory_iterator& operator=(directory_iterator&& rhs) noexcept;

    const directory_entry& operator() const;
    const directory_entry* operator->() const;
    directory_iterator& operator++();
    directory_iterator& operator++(error_code& ec) noexcept;
};
```

- The directory_iterator satisfies the requirements of an input iterator (27.2.3).
- The directory_iterator default constructor should create an iterator equal to the end iterator.
- For the directory that resolves to p, constructs an iterator for the first element in a sequence of directory_entry representing the files in the directory; if any, otherwise the end iterator.
- However, if (options & directory_options::skip_permission_denied) != directory_options::none and construction encounters an error indicating that permission to access p is denied, constructs the iterator does not report an error.
- Two iterators are always equal.
- The order of entries yielded by incrementing a directory_iterator is unspecified.
- directory_iterator member functions shall not directly or indirectly call any refresh function. [Note: Mechanism for caching values is shown in 30.10.12]
- Performing directory iteration may wish to test if the path obtained by dereferencing a directory iterator actually exists. A symbolic link to a non-existent file exists. Programs recursively walking trees for purposes of removing and renaming entries may wish to avoid symbolic links.
- If an entry is removed or added to a directory after the construction of a directory_iterator referencing it, unspecified or not subsequently incrementing the iterator will result in an iterator referencing the removed or added entry.
