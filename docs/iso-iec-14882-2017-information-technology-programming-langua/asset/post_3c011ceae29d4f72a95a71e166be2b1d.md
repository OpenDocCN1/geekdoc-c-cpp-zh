The parent directory of a directory is the directory that contains an entry for the given directory and is represented by the dot-dot in the file. The parent directory of other types of files is a directory containing a directory entry for the file under discussion.

A sequence of elements that identify the location of a file within a filesystem. The elements are the root-name, directory-separator, and an optional sequence of filenames. The maximum number of elements in the sequence is operating system dependent.

A pathname is a character string that represents the name of a path. Pathnames are formatted according to the generic pathname grammar (30.10.8.1) or an operating system dependent native pathname format.

Pathname resolution is the operating system dependent mechanism for resolving a pathname to a file in a hierarchy. There may be multiple paths that resolve to the same file. [Example: POSIX specifies the mechanism in section 4.1, Pathname resolution.] — end example

A relative path is a path that is not absolute, and so, uniquely identifies the location of a file when resolved relative to an implied starting location. The elements of a path that determine if it is operating system dependent. [Note: Pathnames "/" and "../" are relative paths. — end note]

A symbolic link is a type of file with the property that the file is encountered during pathname resolution, a string stored by the file is used to identify the pathname resolution. [Note: Symbolic links are often called symlinks. A symbolic link can be thought of as a pointer to a file. ## 30.10.5 Requirements [fs.req]

- 1. Through this subclass, char, wchar_t, char16_t, and char32_t are collectively encoded character types.
- 2. Functions with template parameters named ECharT shall not participate in overload resolution; ECharT is one of the encoded character types.
- 3. Template parameters named InputIterator shall meet the input requirements (27.2.3) and shall have a value that is one of the encoded character types. [Note: Use of an encoded character type implies an associated character set and encoding. Since signed and unsigned char have no character set and encoding, they are not permitted types. — end note]
- 4. Template parameters named Allocator shall meet the Allocator requirements (20.5.3.5).
