
# ISO/IEC 14882:2017(E)

(4.6) a pointer to an object of derived class type or an *ivalue* or *rvalue* of derived class type may be explicitly converted to a pointer or reference to an unambiguous base class type, respectively;

(4.7) a pointer to member of derived class type may be explicitly converted to a pointer to member of an unambiguous non-virtual base class type;

(4.8) a pointer to an object of unambiguous non-virtual base class type, a *gvalue* of an unambiguous non-virtual base class type, or a pointer to member of an unambiguous non-virtual base class type may be explicitly converted to a pointer, a reference, or a pointer to member of a derived class type, respectively.

If a conversion be interpreted in more than one of the ways listed, the interpretation that appears in the first list is used, even if a cast resulting from that interpretation is ill-formed. If a conversion is interpreted in more than one way as a *static_cast*, performed by *const_cast*, the conversion is ill-formed.
Example:

```
struct T {};
struct I1 : A {};
struct I2 : A {};
struct D : I1, I2 {};
void foo(D* p) {
  // ill-formed static_cast interpretation
  return (A*)p;
}
```

The operand of a cast using the cast notation can be a prvalue of "pointer to incomplete type". The destination type and operand types are class types and one or both; if one is incomplete, it is unspecified whether the *static_cast* or the *reinterpret_cast* interpretation is used, even if there is an inheritance relationship between the two. [Note: For example, if classes defined in the translation unit, a multi-pass compiler would be permitted to interpret a cast between pointers to the classes if it were complete at the point of the cast.]

# 8.5 Pointer-to-member operators [expr.mptr.oper]

1 The pointer-to-member operators *->* and *.* group left-to-right.

```
pm-expression:
pm-expression * cast-expression
pm-expression -> cast-expression
```

2 The binary operator *.* binds its second operand, which shall be of type "pointer to member of T" to its operand, which shall be a class of which T is unambiguous and accessible base class. The result is an object or a pointer of the type specified by the second operand.

3 The binary operator *-> binds its second operand, which shall be of type "pointer to member of T" to its first operand, which shall be of type "pointer to U" where U is T or class of which T is unambiguous and accessible base class. The expression E1->E2 is converted into the function expression (*E1).*E2.

4 Abbreviating *pm-expression*, *cast-expression* on E1.*E2, E1 is the *object expression*. If the type of E1 does not contain the member to which E2 refers, the behavior is undefined. Otherwise, the expression E1 is sequenced before the expression E2.

5 The restrictions on *ce-qualification*, and the manner in which the ce-qualifiers of the operands are ordered to produce the ce-qualifiers of the result, are the same as the rules for E1.E2 given in 8.2.5. [Note: It is not possible to use a pointer to member that refers to modify a *const* class object. For example.

```
struct S {
  S() : i(0) {}

void f() {

  int S::pm = &i; // pm refers to mutable member S::i
  cs.pm = 88; // ill-formed: cs is a const object

```


# 8.6 Multiplicative operators

1. The multiplicative operators *, /, and % group left-to-right.
```
multiplicative-expression:
  multiplicative-expression
  multiplicative-expression * multiplicative-expression
  multiplicative-expression / multiplicative-expression
  multiplicative-expression % multiplicative-expression
```

2. The operands of * and / shall have arithmetic or unscoped enumeration type; the operands of % shall have integral or unscoped enumeration type. The usual arithmetic operations are performed on the operands and determine the type of the result.

3. The binary * operator indicates multiplication.

4 The / operator yields the quotient, and the binary % operator yields the remainder from the division of the first expression. If the second operand of / % is zero the behavior is undefined. If integral operands / operator yields the algebraic quotient with functional part discarded; if the quotient (a/b)*b + a%b is equal to a; the behavior of both a/b and a%b is undefined.

# 8.7 Additive operators

1. The additive operators + and group left-to-right. The usual arithmetic operations are performed for operands of arithmetic or enumeration type.
```
additive-expression:
  multiplicative-expression
  additive-expression + multiplicative-expression
  additive-expression - multiplicative-expression
```

(85) This is often called truncation zero.

For addition, either operand shall have arithmetic or unsccaped enumeration type, or one operand shall be a pointer to a completely-defined object type and the other shall have integral or unsccaped enumeration type,

2 For subtraction, one of the following shall hold:

- (2.1) both operands have arithmetic or unsccaped enumeration type; or;
- (2.2) both operands are pointers to the same completely-defined object type; or
- (2.3) the left operand is a pointer to a completely-defined object type and the right operand has integral or unsccaped enumeration type.

3 The result of the binary + operator is the sum of the operands. The result of the binary − is the difference resulting from the subtraction of the second operand from the first.

4 When at least one operand is added to or subtracted from a pointer, the result has the type of the promoted left. If the expression P[i] of an object x with n elements points to i + j if 0 ≤ i + j < n; otherwise, the behavior is undefined. When two pointers are added or subtracted, the result is of type undefined or an implementation-defined integer type. If the expressions P and Q point to, respectively, elements[i] and x[j] of the same object, Q has the value i - j; otherwise, the behavior is undefined.

6 For subtraction, if the expressions P or Q have type "pointer to c", where T and the element type are not small (7). In particular, a pointer to base class be used for pointer arithmetic when the result is the value 0 converted to the type std:ptiff_t. — end note

7 If the value 0 is added to or subtracted from a null pointer, the result is a null pointer. If two pinter values are equal, the result compares equal to the value 0 converted to the type std:ptiff_t.

# 8.8 Shift operators

1 The shift operators << >> group left-to-right.

```
shift-expression:
additive-expression:
shift-expression << additive-expression
shift-expression >> additive-expression
```

The operands shall be integral or unscaped enumeration type and integral promotions are performed. The result is that type of the promoted left. The behavior is undefined if the right operand is greater or equal to the length in bits of the promoted left.

3 The value of E1 << E2 is E E2 bit-position bits are zero-filled. If E1 has an unsigned type, the result of E1 is E1 × 2^E2, modulo one greater than the maximum value representable in the result type; otherwise, if E1 has a signed type and non-negative value, and E1 × 2^E2 is representable in the corresponding value type of the result type, then value, converted to the result type, is the result

The value of E1 >> E2 is E1 right-shifted E2 bit positions. If E1 has an unsigned type or if E1 has a signed type and non-negative value, the result is E1 divided by 2^E2; otherwise if E1 has a signed type and negative value, the result is implementation-defined.
