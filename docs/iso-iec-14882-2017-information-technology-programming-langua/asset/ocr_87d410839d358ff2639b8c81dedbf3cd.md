All the containers defined in this Clause and in 24.3.2 except array meet the identical requirements of an allocator-aware container, as described in Table 86.

Given an allocator T and a given type X having a value identical to T and an allocator_traits<T>::rebind_alloc(T) returns an value of type A, a pointer of type T*, and an value of type v (possibly const) T and an value rv of type T, the following terms are defined. If X is not allocator-aware, the following terms are defined as If allocator object needs to be created and specializations of allocator are not instantiated:

(15.1) T is Insertable into X means that the following expression is well-formed:
allocator_traits<T>::construct(m, p)

(15.2) An element of X is default-inserted if it is initialized by evaluation of the expression
allocator_traits<T>::construct(m, p)
where p is the address of the unitialized storage for the element allocated X.

(15.3) T is Moveable into X means that the following expression is well-formed:
allocator_traits<T>::construct(m, p, rv)
and its evaluation carries the following postcondition to hold: The value of vp is equivalent to the value of rv before evaluation. [Note: rv remains a valid object. — end note]

(15.4) T is Copyable into X means that, in addition to T being MoveInsertable into X, the following expression is well-formed:
allocator_traits<T>::construct(m, p, v)
and its evaluation carries the following postcondition to hold: The value of v is unchanged and equivalent to vp.

(15.5) T is Constructable into X from args, for zero or more arguments args, means that the following expression is well-formed:
allocator_traits<T>::construct(m, args)

(15.6) T is Erasable from X means that the following expression is well-formed:
allocator_traits<T>::destroy(m, p)
