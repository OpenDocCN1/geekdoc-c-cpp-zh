
# ISO/IEC 14882:2017(E)

## 8.16 Conditional operand [expr.cond]

conditional-expression: assignment=czexpression
logical-or-expression: czexpression : assignment=czexpression

- 1 Conditional expressions right-to-left. The first expression is contextually verified to bool (Clause 7). It is evaluated and if it is true, the result of the conditional expression is the value of the second expression, otherwise that of the third expression. Only the second and third expressions are evaluated. Every value computation and side effect with the first expression is sequenced before every value computation and side effect with the second or third operand.

- 2 If the second or third operand have type value, one of the following should hold:
  (2.1) The second or third operand (but not both) is (possibly parentheses) three-expression (8.17); the result is of the type and value category of the other. The conditional-expression is a bit-field if that is a bit-field.
  (2.2) Both the second and third operands have type void; the result is of type void and void [Note: This includes the case where both operands occur].

- 3 Otherwise, if the second and third operand are bit-fields of the same value category and of type cv1 and cv2, respectively, the operands are considered to be of type (possibly-qualified) class for the remainder of this section, where cv is the union of cv1 and cv2.

- 4 Otherwise, if the second and third operand have different types and either is possibly-qualified class, or if both are bit-fields of the same value category and type except for conversion, an attempt is made to form an implicit conversion sequence (16.3.3) from each of operands to the type of the other. [Note: Properties such as, whether an operand is a bit-field, or whether conversion sequence is formed from an operand expression E1 to a target type related to T2 of the operands.
  (4.1) If E2 is an xvalue, the type is "value reference to T2", subject to the constraint that the conversion reference must bind directly (11.6.3) to an.
  (4.2) If E2 is a value the type is "value reference to T2", subject to the constraint that the reference must bind directly.
  (4.3) If E2 is a prvalue or neither of the conversion sequences above can be formed and at least one of the operands has (possibly-qualified) class:
  (4.3.1) if T1 and T2 are the same class type (ignoring cv-qualification), or one is a base class of the other, and T2 is at least as cv-qualified as T1, the target type is T2,
  (4.3.2) otherwise, the target type is the type that E2 would have after applying the lvalue-to-reference (7.1), array-to-pointer (7.2), and function-pointer (7.3) standard conversions.

Using this, determines whether an implicit conversion sequence can be formed from the second operand to the target type for the third, and vice versa. If both sequences can be formed, or one but is the ambiguous conversion sequence, the program is ill-formed. If no conversion can be formed, the operands are left unchanged and further checking is performed as described below. If exactly one conversion sequence is formed, conversion is applied to the chosen operand and the converted operand is in place of the original operand for the remainder of this section. Note: The conversion may be ill-formed even if an implicit conversion sequence could be formed.

- 5 If the second and third operand are gvalues of the same value category and have the same type, the result is of that type and value category and it is a bit-field if the second or third operand is a bit-field, or both are bit fields.

Otherwise, the result is a value. If the second and third operands do not have the same type, and either has (cv-qualified) class type, overload resolution is used to determine the conversions (if any) be applied to the operands (16.3.1.2, 16.6). If the overload resolution fails, the program is ill-formed. Otherwise, the conversions determined are applied, and the converted operands are used in place of the original operands for the remainder of the expression.

Lvalue-to-pointer (7.1), array-to-pointer (7.2), and function-to-pointer (7.3) standard conversions are performed on the second and third operands. After those conversions, one of the following should hold:

- The second and third operands have the same type; the result is of that type and the result object is initialized using the selected operand.
- The second and third operands have arithmetic or enumeration type; the usual arithmetic conversions are performed to bring them to a common type, and the result is of that type.
- One of the second or third operands have pointer conversions; pointer conversions (7.11), function conversions (7.13) and qualification conversions (7.5) are performed to bring them to their composite type (Clause 8). The result is the composite pointer type.
- One of the second or third operands have member pointers; pointer to member conversions (7.12) and qualification conversions (7.5) are performed to bring them to their composite type (Clause 8). The result is the composite pointer type.
- Both the second and third operands have type std::nullptr_t; the result is of std::nullptr_t.

## 8.17 Assignment and compound operator

assignment-expression:
conditional-expression
logical-or-expression
throw-expression
assignment-operator: one of
+= -= *= <= >= >>= ^= ==



- 1 The assignment (=) replaces that of the left operand.
- 2 If the left operand is of class type, the assignment is complete.
- 3 [Note: For class objects, assignment is not general in same as initialization (11.6, 15.8).]
- 6 When the operand of an assignment operator is a bit-field that cannot represent the value of the expression, the resulting value of the bit-field is implementation-defined.
- 7 The behavior of an expression E1 op E2 is either equal to E1 = E2 except that E1 is evaluated only once. In all cases, E1 shall have arithmetic type.
- 8 If the value stored in an object is reached via another object that overlaps in storage of the first, the object shall be the same and both have the same type, otherwise the behavior is undefined.
- 9 A braced-init-list may appear on the right-hand side of
  (9.1) an assignment to a scalar, in which case the initializer list shall have at most one element. The meaning of x = {v}, where T is the scalar type of the expression x, is that of x = T(v). The meaning of x = {} is T().
  (9.2) an assignment to an object of class type, in which case the initializer list is passed as the argument to the assignment operator function by overload resolution [16.5.3, 16.3].

```
[Example:
complex<double> z; // meaning z.operator=({1,2})
z = {1, 2};
z += {1, 2}; // meaning z.operator+=({1,2})
int a, b;
a = b = {1}; // meaning a=b+1
a = {1} = b; // syntax error
— end example]
```
