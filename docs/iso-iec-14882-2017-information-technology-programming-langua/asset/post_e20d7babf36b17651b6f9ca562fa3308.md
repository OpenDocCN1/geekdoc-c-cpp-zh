## 17.6.2 Dependent names

Inside a template, some constructs have semantics that may differ from instantiation to another. Such a construct depends on the template parameters. In particular, expressions may depend on the type and/or value of template parameters (as determined by the template arguments) and this determines the context for name lookup for certain names. Expressions may be type-dependent (that, is, may depend on a template parameter) or value-dependent (that, is, when evaluated as a constant expression (8.20) may depend on a template parameter) as described in this section. In an expression of the form:

```
postfix-expression ( expression-list )
```

where the postfix-expression is unqualified, the unqualified-id denotes a dependent name if
- any of the expressions in the expression-list is a pack expansion (17.5.3),
- any of the expressions or braced-init-lists in the expression-list is type-dependent (17.6.2.2),
- or the unqualified-id is a template-id in which any of the template arguments depends on a template parameter.

If an operand of an operator is a type-dependent expression, the operator also denotes a dependent name. Such names are unbound and are looked up at the point of template instantiation (17.6.4.1) in the context of the template definition and the context of instantiation. [Example:

```cpp
template<class T> struct X : B<T> {
    typedef T::A a;
    void f(T* p) {
        static int i = B<T>::i;
        p->j++;
    }
};
the base class name B<T>, the type T::A, the name B<T>::i and p->j explicitly depend on the template-parameter.

In the definition of a class or template, the scope of a dependent class (17.6.2.1) is not examined during unqualified lookup either at the point of definition or an instantiation of the class template or member. [Example:

```cpp
typedef struct A;
template<class T> class B {
    typedef int A;
};

struct A {
    struct B { /* ... */ };
    int a;
    int Y;
};
template<class T> struct X : B<T> {
    A a;
    // has type
};
The type A in the definition of X<T> binds to the typedef name defined in the global namespace, not to the typedef name defined in the base class B<T>. [Example:

```cpp
int a;
template<class T> struct Y : T {
    struct B { /* ... */ };
    B b; // The B defined in Y
    void f(int i) { a = i; } // ::a
    Y* p; // ::Y<T>
```

The members A::B, A::a and A::Y of the template argument do not affect the binding of names in Y<A>.

## 17.6.2.1 Dependent types

A name refers to the current instantiation if it

- (1.1) in the definition of a class template, a nested class of a class template, a member of a class template, a member of a nested class of class template, the injected-class-name (Clause 12) of the class template or nested class.
- (1.2) in the definition of a primary class template or a member of a primary class template, the name of the class template followed by the template argument of the primary template enclosed in <> (or an equivalent alias specialization).
- (1.3) in the definition of a nested class of a class template, the name of the nested class referenced as a member of the current instantiation, or
- (1.4) in the definition of a partial specialization or a member of a partial specialization, the name of the class template followed by the template argument of the partial specialization enclosed in <> (or an equivalent alias specialization). If the nth template parameter is a template pack, the nth template argument is a pack expansion (17.5.3) which is the pattern of the template pack.
2 The template argument of a primary template is a template argument where the nth template parameter has the value of the nth template parameter of the class template. If the nth template parameter is a template pack, the nth template argument is a pack expansion (17.5.3) which is the name of the template pack.
3 A template argument that is equivalent to a template parameter (i.e., has the same constant value as the type-template-parameter) may be used in place of that template parameter in a reference to the current instantiation. In the case of a non-type template argument, this only applies if the argument was given the value of the template parameter and not an expression in which the template parameter appears as a subexpression. — Example:

```cpp
template <class T> class A {
    A* p1; // A is the current instantiation
    <A>* p2; // <A> is the current instantiation
    <A>* p3; // <A> is not the current instantiation
    ::<A>* p4; // ::<A> is the current instantiation
    class B {
        B* p1; // B is the current instantiation
        <A>::B* p2; // <A>::B is the current instantiation
        typename A<T>::B* p3; // A<T>::B is not the current instantiation
    };
};

template <class T> class A<T> {
    A* p1; // <A> is the current instantiation
    <A>* p2; // <A> is not the current instantiation
};

template <class T1, class T2, int> struct B {
    T1, I* B1; // refers to the current instantiation
    T2, I* B2; // not the current instantiation
    typedef int my_I;
    static const int my_I = 0;
    static const int my_I2 = 0;
    static const int my_I3 = my_I;
    T1, T2, my2 = B3; // refers to the current instantiation
    T1, T2, my2 = B4; // not the current instantiation
    T1, T2, my13 = B5; // refers to the current instantiation
};
```

- (5.1) An unqualified name that, when looked up, refers to at least one member of a class that is the current instantiation or a non-dependent base class. [Note: This can only occur when looking up a name in a scope defined by the definition of a class template. -- end note]
