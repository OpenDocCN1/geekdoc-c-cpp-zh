# 29.5.9 Additional overloads [complex.overloads]

1 The following function templates shall have additional overloads:
```
arg          norm
conj         proj
imag         real
```

2 The additional overloads shall be sufficient to ensure:
1. If the argument has type double, then it is effectively cast to complex<double>.
2. Otherwise, if the argument has type double or an integer type, then it is effectively cast to complex<double>.
3. Otherwise, if the argument has type float, then it is effectively cast to complex<float>.

3 Function pow shall have additional overloads to ensure, for a call with at least one argument of type complex<T>:
1. If either argument has complex<double> or long double, then both arguments are effectively cast to complex<double>.
2. Otherwise, if either argument has type complex<double>, double, or an integer, then both arguments are effectively cast to complex<double>.
3. Otherwise, if either argument has type complex<float> or float, then both arguments are effectively cast to complex<float>.

# 29.6 Random number generation

1 This subclause defines a facility for generating (pseudo)-random numbers.
2 In addition to utilities, four categories of entities are defined: uniform random bit generators, random number engines, random number engine adapters, and random number distributions. These categorizations are applicable to types that satisfy the corresponding requirements, objects instantiated from such types, and templates when instantiated. [Note: These entities are specified in such a way as to permit the binding of any random bit generator object as the argument to any random distribution object d, which produces a zero-argument function object such as bind(d,e). -- end note.
3 Each of the entities specified via this subclause has an arithmetic type (6.9.1) identified as result_type. With T as the result_type associated with such an entity, T is characterized:
    a) as boolean or equal-boolean, if T is bool;
    b) as integral or equal-integer-valued, if numeric_limits<T>::is_integer is true;
    c) as floating point or equal-real-valued.
If integer, it may also be further characterized as signed or unsigned, according to numeric_limits<T>::is_signed.
4 Unless otherwise specified, all descriptions of calculations in this subclause use mathematical rules.
5 Throughout this subclause, the operators bitand, bitor, and xnor denote the conventional bitwise operations. Further
    a) the operator shiftleft denotes a bitwise shift with zero-valued bits appearing in the high bits of the result, and
    b) the operator shiftright denotes a bitwise shift with zero-valued bits appearing in the low bits of the result, and whose result is always taken 2^m.
