+   4 The `typeid` (8.2.7) can be used during construction or destruction (15.6.2). When `typeid` is used in a constructor (including the mem-initializer (12.2) for a non-static data member) or in a destructor, or in a function called (directly or indirectly) from a constructor or destructor, if the operand of `typeid` refers to the object under construction or destruction then the `std::type_info` object representing the constructor or destructor's static type of the operand is neither the constructor nor destructor's class nor one of its bases, the behavior is undefined.

+   5 `dynamic_cast` (8.2.7) can be used during construction or destruction (15.6.2). When `dynamic_cast` is used in a constructor (including the mem-initializer or default member initializer for a non-static data member) or in a destructor, or in a function called (directly or indirectly) from a constructor or destructor, if the operand of `dynamic_cast` refers to the object under construction or destruction, this object is considered to be a most derived object that has the type of the constructor or destructor's class. If the operand of `dynamic_cast` refers to the object under construction or destruction and the static type of the operand is not a pointer to or object of the constructor or destructor's class or one of its bases, the `dynamic_cast` results in undefined behavior. | Example:

```
struct V {
    virtual void f();
};

struct A : virtual V {

struct B : virtual V {
    B(V*, A*);
};

struct D : A, B {
    D() : B(A*this), this) { }
}
```

```
B(V* v, A* a) {
    typeid(*this); // type_info for B
    typeid(*v); // well-defined: v has type V, a base of B yields type_info for B
    typeid(a); // undefined behavior: type A is not a base of B
    dynamic_cast<B*>(v); // well-defined: v of type V*, v base of B results in B*
    dynamic_cast<B*>(a); // undefined behavior, a has type A*, not a base of B
}
```
