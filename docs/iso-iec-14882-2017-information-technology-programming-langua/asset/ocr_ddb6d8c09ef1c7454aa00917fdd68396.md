# 30.10.7 Error reporting [fs.report]

+   Filesystem library functions have two overloads, one that throws an exception to report file system errors, and others that set an error_code. [Note: this supports two common use cases:

+   (1.1) Uses where file system errors are truly exceptional and not necessarily represent failure. Returning an error code is the most appropriate response. This application specific error handling, including simply ignoring the error.

> - end note)

+   2 Functions not having an argument of type error_code handles errors as follows, unless otherwise specified:

+   (2.1) When a call by the implementation to an operating system or other underlying API results in an error that prevents the function from meeting its specifications, an exception of type filesystem_error shall be thrown. For functions with a single argument, that argument shall be passed to the filesystem_error constructor with a single argument. For functions with two arguments, the first of these arguments should be the path1 argument, and the second should be passed as the path2 argument. The filesystem_error constructor's error_code argument is as appropriate for the specific operating system dependent error.

+   (2.2) Failure to allocate storage is reported by throwing an exception as described in 20.5.12.

+   (2.3) Destructors throw nothing.
