
# ISO/IEC 14882:2017(E)

- (4.2) otherwise, if e is an unparenthesized id-expression or an unparenthesized class member access (8.5), decltype(e) is the type of entity named by e. If there is no such entity, or if e names a set of overloaded functions, the program is ill-formed
- (4.3) otherwise, if e is an xvalue, decltype(e) is T&, where T is the type of e;
- (4.4) otherwise, if e is an lvalue, decltype(e) is T&& where T is the type of e;

Example:
```cpp
const int& foo() {int i;
struct A { double x; };
A* a = new A();
decltype(foo()) x1; // type is const int&
decltype(x2); // type is int
decltype(x3); // type is double
decltype((a->x)) x4; // type is const double
```
Note: The rules for types involving decltype(auto) are specified in 10.7.4. If the operand of decltype-specifier is a prvalue, the temporary conversion is not applied (7.4) and no result is produced for the primal. As a result, storage is not allocated and it is not destroyed. A class is not instantiated as result of being the type of a function call in this context. The purpose of writing a decltype-specifier is analogue to that of a value, so the same reasons for requiring a conversion do not apply. In particular, it is not necessary to allocate a temporary object or to enforce the semantic constraints associated with invoking the type's destructor. Unlike the prvalue, parentheses have no special meaning.

Example:
```cpp
template<class T> class A { ~A() = default; };
template<class T> auto i(T) -> A<T>; // #1
template<class T> auto f(T) -> T; // #2
decltype(f<T>())); // #3 forces completion of A<T> and implicitly uses A<T>::~A() for the temporary introduced by the use of i. // #4
template<class T> auto f(T) -> void;
auto g() -> void { f(42); } // #5 calls #2. #1 is not a valid candidate: type deduction fails (17.8.2) because A<int>::~A() is implicitly used in its decltype-specifier
template<class T> auto q(T) -> decltype(f<T>())); // #6 does not force completion of A<T>; A<T>::~A() is not implicitly used within the context of this decltype-specifier
void r() { q(42); } // #7 error: deduction against q succeeds, so overload resolution selects the specialization "q(T) -> decltype(f<T>())) [with int]"; the return type is an int, so a temporary is introduced and its destructor is used, so the program is ill-formed
//;
```

# 10.1.7.3 Elaborated type specifiers

```
elaborated-type-specifier:
    class attribute-specifier-seq_opt nested-name-specifier_opt identifier
    class simple-template-id
    class nested-name-specifier_opt simple-template-id
    enum nested-name-specifier_opt identifier
```

- 1 An attribute-specifier-seq shall not appear in an elaborated-type-specifier unless the latter is constituent of a declaration. If an elaborated-type is the constituent of a declaration, the declaration is ill-formed unless it is an explicit instantiation (17.7.3) or it has one of the following (17.7.2):

```cpp
class attribute-specifier-seq_opt identifier;
friend class ::simple-template-id;
friend class nested-name-specifier_opt identifier;
friend class nested-name-specifier_opt simple-template-id;
```

In the first case, the attribute-specifier-seq, if any, pertains to the class being declared; the attributes in the attribute-specifier-seq are thereafter attributes of the class which is named. If the identifier resolves to a class-name or enum-name, the elaborated-type-specifier introduces it into the declaration as a simple type-specifier introduces its type. If the identifier resolves to a typedef-name or the simple-template-id resolves to a template-parameter T, the declaration is ill-formed [Note: This implies, with a class with a template T, the declaration `friend T;` is ill-formed. however, the declaration is (14.3).]

- 3 The class or enum keyword present in the elaborated-type-specifier shall be in kind with the declaration to which the name in the elaborated-type-specifier refers. This rule also applies to the form of elaborated-type-specifier that declares a class or friend class which can be constructed as referring to the definition. In this context, the purpose of writing a decltype-specifier is analogue to that of a value, so the same reasons for requiring a conversion do not apply. In particular, it is not necessary to allocate a temporary object or to enforce the semantic constraints associated with invoking the type's destructor. Unlike the prvalue, parentheses have no special meaning.

Example:
```cpp
enum class;
```

# 10.1.7.4 auto

- 1 The auto or decltype(auto) specifier is used to refer to a type. If the operand of decltype-specifier is an undevaluated operand (8), decltype(e) is the type of entity named by e. If there is no such entity, or if e names a set of overloaded functions, the program is ill-formed
- 2 If the operand of decltype-specifier is a prvalue, the temporary conversion is not applied (7.4) and no result is produced for the primal. As a result, storage is not allocated and it is not destroyed. A class is not instantiated as result of being the type of a function call in this context. The purpose of writing a decltype-specifier is analogue to that of a value, so the same reasons for requiring a conversion do not apply.
- 3 If the return type is an int, so a temporary is introduced and its destructor is used, so the program is ill-formed.

Example:
```cpp
template<class T> class A { ~A() = default; };
template<class T> auto i(T) -> A<T>; // #1
template<class T> auto f(T) -> T; // #2
decltype(f<T>())); // #3 forces completion of A<T> and implicitly uses A<T>::~A() // #4
template<class T> auto f(T) -> void;
auto g() -> void { f(42); } // #5 calls #2. #1 is not a valid candidate: type deduction fails (17.8.2) because A<int>::~A() is implicitly used in its decltype-specifier
template<class T> auto q(T) -> decltype(f<T>())); // #6 does not force completion of A<T>; A<T>::~A() is not implicitly used within the context of this decltype-specifier
void r() { q(42); } // #7 error: deduction against q succeeds, so overload resolution selects the specialization "q(T) -> decltype(f<T>())) [with int]";

- 4 If e is an xvalue, decltype(e) is T&, where T is the type of e;
- 5 If e is an lvalue, decltype(e) is T&& where T is the type of e;
- 6 Otherwise, decltype(e) is the type of e.

Example:
```cpp
const int& foo() {int i;
struct A { double x; };
A* a = new A();
decltype(foo()) x1; // type is const int&
decltype(x2); // type is int
decltype(x3); // type is double
decltype((a->x)) x4; // type is const double
```
