The optional attribute-specifier-seq in the enum-head and the epoch-enum-declaration pertains to the enumeration; the attributes in that attribute-specifier-seq are thereafter considered attributes of the enumeration whenever it is named. A : "enum nested-name-specifier identifier" within the enumerator-seq reveals a potential ambiguity between the declaration of an enumeration with an enum-base and the declaration of an unnamed bit-field of enumeration type. [Example]:

```
struct S {
  enum E : int {};
  enum E : int {};
}
```

-- end note | If an enumeration-declaration contains a nested-name-specifier, the declaration shall be an explicit specialization (17.7.3).

The enumeration declaration with an enum-key of only enum and its enumerators are unscoped enumerators. The enum-keys class and enum struct are semantically equivalent; an enumeration declaration with one of these is a scoped enumeration, and its enumerators are scoped enumerators. The optional identifier for an enum-base shall not be omitted for an integral type; any cv-validation is ignored. If an enumeration-declaration has an enum-base, then the enumerators in an enumerator-list are declared as constants, and may appear wherever constants are required. An enumerator-definition with the associated enumerator value indicated by the constant-expression. If the first enumerator-definition has an initializer, the value of the corresponding constant is zero. An enumerator-definition without an initializer increases the value of the preceding enumerator by one. [Example]:

```
enum a { b, c=2 };
enum d { e, f=2 };
```

defines a and d to be zero, and b to be one, and f to be three. -- end example | The optional attribute-specifier-seq in an enumeration pertains to that enumerator.

An enumeration declaration is either a declaration of an enumeration in the current scope or of a new enumeration.
