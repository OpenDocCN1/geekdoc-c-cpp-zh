The header valarray defines five classes (valarray, slice_array, gslice_array, mask_array, and indirect_array), and a series of return templates for representing and manipulating arrays of values.

The array classes are defined to be free of certain forms of aliasing, allowing operations on these classes to be optimized.

Any function returning a valarray is permitted to return an object of another type, provided all the const member functions of valarray are also applicable to this type. This return type should not add more than two levels of template nesting over the deeply nested argument type.²⁷⁵

Implementations using such replacement types should provide additional functions and operators as:

+   (4.1) for every taking a const valarray<T>& other than begin and end (29.7.10), identical functions taking the replacement types should be added;

+   (4.2) for every taking two const valarray<T>&, identical functions taking every combination of const valarray<T>& and replacement types should be added.

5 In particular, an assignment should allow a valarray<T> to be constructed from such replacement types and allow assignments and compound assignments of type valarray<T>, slice<T>, gslice<T>, mask_array<T>, and indirect<T> objects.

6 These library functions are permitted to throw a bad_alloc (21.6.3.1) exception if there are not sufficient resources to carry out the operation. The exception is not mandated.

> ²⁷⁵ Annex B recommends a minimum number of recursively nested template instances. This requirement directly suggests a minimum allowable complexity for valarray expressions.
