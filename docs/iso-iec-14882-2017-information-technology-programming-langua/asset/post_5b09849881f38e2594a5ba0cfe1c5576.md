# 31.5 Namespace std::regex_constants [re.const]

The `std::regex_constants` holds symbolic constants used by the regular expression library. This namespace provides types, syntax_option_type, match_flag_type, and error_type, all several of these.

## 31.5.1 Bitmask type syntax_option_type [re.opt]

```cpp
namespace std::regex_constants {
    using syntax_option_type = T;
    inline constexpr syntax_option_type icase = unspecified;
    inline constexpr syntax_option_type not = unspecified;
    inline constexpr syntax_option_type optimize = unspecified;
    inline constexpr syntax_option_type collate = unspecified;
    inline constexpr syntax_option_type ECMcript = unspecified;
    inline constexpr syntax_option_type basic = unspecified;
    inline constexpr syntax_option_type extended = unspecified;
    inline constexpr syntax_option_type awk = unspecified;
    inline constexpr syntax_option_type grep = unspecified;
    inline constexpr syntax_option_type multiline = unspecified;
}
```

The `syntax_option_type` is an implementation-defined bitmask type (20.4.2.1). Setting its elements has effects listed in Table 130. A valid value of `syntax_option_type` shall have one of grammar elements: ECMAScript, basic, extended, awk, grep, egrep. If no element is set, the default grammar is ECMAScript.

Table 130 — syntax_option_type effects

| Element | Effect(s) if set |
| :--- | :--- |
| icase | Specifies that matching of regular expressions against a character sequence shall be performed without regard to case. |
| nosub | Specifies that no sub-expressions shall be considered, so that when a regular expression is matched against a character sequence, no sub-expression matches shall be in the supplied match_results structure |
| optimize | Specifies that the regular expression engine should pay more attention to the speed with which regular expressions are matched, and less to the speed with which regular expression objects are constructed. |
| collate | Specifies that characters of the form "a-b" shall be locale sensitive. |
| ECMAScript | Specifies that the grammar recognized by the regular expression engine shall be used by ECMAScript, as modified in 31.13 |
| basic | Specifies that the grammar recognized by the regular expression engine shall be used by basic expressions in POSIX, Base Definitions and Regular Expressions. |
| extended | Specifies that the grammar recognized by the regular expression engine shall be used by extended expressions in POSIX, Base Definitions and Regular Expressions. Specifies that the grammar recognized by the regular expression engine shall be used by the utility awk in POSIX. |
| grep | Specifies that the grammar recognized by the regular expression engine shall be used by the utility grep in POSIX. |
| egrep | Specifies that the grammar recognized by the regular expression engine shall be used by the utility egrep given the -E option in POSIX. |
| multiline | Specifies that "^" shall match the beginning of a line and shall match the end of a line, if the ECMAScript engine is selected. |

## 31.5.2 Bitmask type match_flag [re.matchflag]

```cpp
namespace std::regex_constants {
  using match_flag_type = T;
  inline constexpr match_flag_type match_default = {};
  inline constexpr match_flag_type not_bool = unspecified;
  inline constexpr match_flag_type not_eol = unspecified;
  inline constexpr match_flag_type match_not_bow = specified;
  inline constexpr match_flag_type match_not_eow = specified;
  inline constexpr match_flag_type match_any = specified;
  inline constexpr match_flag_type match_not_null = specified;
  inline constexpr match_flag_type match_continuous = specified;
  inline constexpr match_flag_type match_prev_avail = specified;
  inline constexpr match_flag_type format_default = {};
  inline constexpr match_flag_type format_sed = specified;
  inline constexpr match_flag_type format_not_copy = specified;
  inline constexpr match_flag_type format_first_only = specified;
}
```

The *match_type* is an implementation-defined bitmask (20.4.2.1). The constants of that type, except `match_default` and `format_default`, are bit elements. The `match_default` and `format_default` constants are empty bitmaps. Matching a regular expression against a sequence of characters `[first, last)` follows the rules of the grammar for the regular expression, modified by the effects in Table 131 for any bit elements set.

Table 131 regex_types: match_flag_type effects when obtaining a match against a character sequence [first, last)

| Element | Effect(s) |
| :--- | :--- |
| match_not_bol | The first character in `[first, last)` should be treated though it is not at the beginning of a line, so the ^ in the regular expression shall not match `[first, last)`. |
| match_not_eow | The last character in `[first, last)` should be treated though it is not at the end of a line, so the $ in the regular expression shall not match `[first, last)`. |
| match_not_bow | The expression `\b` shall not match the sub-sequence `(first, first)`. |
| match_any | If more than one match exists then any is an acceptable result. |
| match_not_null | The expression shall not match an empty sequence. |
| match_continuous | The expression shall only match a sub-sequence that begins at first. |
| match_prev_avail | `--first` is a valid position. When this flag sets the match_not_bol, it is ignored by the regular expression algorithms (31.11) and iterators (31.12). |
| format_default | When a regular expression is to be replaced by a new string, the new string shall be constructed using the rules used by the ECMAScript replace function in ECMMA-202, part 15.5.4. In addition, during search and replace operations all non-overlapping occurrences of the regular expression shall be replaced and sections of the input that did not match the expression shall be copied unchanged to the output string. |
| format_sed | When a regular expression is to be replaced by a new string, the new string shall be constructed using rules sed utility in POSIX. |
| format_no_copy | During search and replace operation, sections of the character sequence being searched that do not match the regular expression shall not be copied to the output string |
| format_first_only | When specified during search and replace operation, only the first occurrence of the regular expression shall be replaced. |
