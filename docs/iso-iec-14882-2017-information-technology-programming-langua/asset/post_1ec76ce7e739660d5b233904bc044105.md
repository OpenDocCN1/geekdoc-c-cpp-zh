## 26 Container requirements [container.requirements]

### 26.2.1 General [container.requirements]

- 1 Containers are objects that store other objects. They control allocation and deallocation of these objects through constructors, destructors, insert and erase operations.
- 2 All of complexity in this Clause are stated in terms of the number of operations on the contained objects. Example: The copy constructor of vector<int> has linear complexity, though the complexity of copying each vector<int> is linear.
- 3 For components that declare an allocator_type, objects stored in these components must be constructed using the function allocator_traits<U>::construct and allocator_traits<U>::destroy (23.10), where U is either the allocator_type or an internal type used by the container. These functions are called only for the container's element type, not for internal types used by the container. Note: This means, for example, a node-based container might need to construct nodes and call construct to place the element into the buffer.
- 4 In Tables 83, 84, and 85 X denotes a container containing objects of type T, n denotes values of type X, x denotes an identifier, r denotes a non-const value, and rv denotes a non-const value of type X.

- 5 The member function size() returns the number of elements in the container. The number of elements is defined by the rules of constructors, iterators, and erases.
- 6 begin() returns an iterator to the first element in the container. end() returns an iterator which is moved. Such move constructs the past-the-end value for the container. If the container is empty, begin() == end().
- 7 In the expressions

```cpp
i == j
i != j
i < j
i <= j
i >= j
i > j
```

where i and j denote objects of a container's iterator, either or both be replaced by an object of the container.

- 8 Unless otherwise specified, all containers defined in this clause obtain memory using an allocator (see 20.5.3). Note: In particular, if the container is of type_traits<P>::pointer, where P is allocator_traits<Allocator>, then Copy constructors of these types obtain an allocator by move construction from the allocator being copied. Such move construction of the allocator shall not fail via an exception. All other constructors for these types use an optional allocator argument. Note: If an invocation of the constructor only uses the default value of an allocator, then the allocation is performed by copy, move assignment, or swapping of the allocator. The allocator may be replaced only via assignment or swap(). Allocation is performed by copy, move assignment, or swapping of the allocator, during the lifetime of each container until the allocator is replaced. In all container types defined in this Clause, the get_allocator() returns a copy of the allocator used to construct the container.
