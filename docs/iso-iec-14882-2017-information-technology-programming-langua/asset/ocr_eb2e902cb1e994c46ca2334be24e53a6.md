# C.1.8 Clause 12: classes [diff.class]

12.1 [see also 10.1.3]

**Change:** In C++, a class declaration introduces the name into the scope where it is declared and hides any object, function or declaration of an enclosing scope. In C, an inner scope declaration of a struct tag name hides the name of an object or function in an outer scope.

Example:

```
int x[99];
void f() {
  struct x { int a; };n  sizeof(x); // size of the array in C/
  // size of the struct in C++/
}
```

**Rationale:** One of the few inconsistencies between C and C++ that can be attributed to the new C++ name space definition where a name can be declared as a type and as a non-type in a single scope causing the non-type to hide the type name and when or refer to the type. This new name space provides important conveniences to C++ programmers and helps to make the use of user-defined types as similar as possible to the use of fundamental types. The advantages of the new name space definition were justified by far by the inconsistency as described above.

**Original feature:** Change to semantics of well-defined feature.

**Difficulty of converting:** Semantic transformation. If the hidden name needs to be accessed at global scope, the C++ operator can be used. If the hidden name is at block scope, either the type or struct tag has to be renamed.

**How widely used:** Seldom.

# 12.2.1

**Change:** In C++, the name of a nested class is local to its enclosing class. In C the name of the nested class belongs to the same scope as the name of the outermost enclosing class.

**Rationale:** Leaving the choice of something to implementations could lead to inconsistent definitions of template specializations. For consistency, the implementation freedom was eliminated for non-dependent types, too.

**Effect on original feature:** The choice is implementation-defined in C, but not so in C++.

**Difficulty of converting:** Syntactic transformation.

**How widely used:** Seldom.

Example:

```
struct X {
  struct Y { /* ... */ y; };
};\struct Y y; // valid C, invalid C++
```

**Rationale:** C++ classes have member functions which require that classes establish scopes. The rule would leave classes as an incomplete scope which would prevent C++ programmers from maintaining locality within a class.
