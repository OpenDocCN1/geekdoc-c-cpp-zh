# 30.10.2 Operating system dependent behavior [fs.conorm.os]

+   1 Some behavior is specified as being operating system (30.10.4). The operating system is implementation implementation-defined.

+   2 It is permissible for an implementation to be dependent on an operating system emulator rather than the actually underlying operating system.

# 30.10.3 File system race [fs.race.behavior]

+   1 Behavior is undefined if functions provided by this subclause introduce a file system race (30.10.4).

# 30.10.4 Terminology [fs.definitions]

+   1 An *path* is a path that unambiguously identifies the location of a file without reference to an additional starting location. The elements of a path that determine if it is absolute are operating system dependent.

+   2 A *directory* is an object within a file system that holds as a container of directory entries that contain information about other files, possibly including other directories.

+   3 A *file* is an object within a file system that holds user or system data. Files can be written to, read from, or both. A file has certain attributes, including type. File types include regular files and directories. Other types of files, such as symbolic links, may be supported by the implementation.

+   4 A *file system* is a collection of files and their attributes.

+   5 *File system access* is the condition that occurs when multiple threads, processes, or computers interfere with modification of the same object within a file system.

+   6 A *filename* is the name of a file. Filenames consisting of one and two characters respectively, have special meaning. The following characteristics of filenames are operating system dependent:
(6.1) The permitted characters. [Example: Some operating systems prohibit the ASCII control characters (0x00–0x1F) in filenames. — end example]
(6.2) The maximum permitted length.
(6.3) Filenames that are not permitted.
