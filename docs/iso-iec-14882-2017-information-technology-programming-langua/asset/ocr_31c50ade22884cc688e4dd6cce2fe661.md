# 33.2 Requirements [thread.req.paramname]

# 33.2.1 Template parameter names

Throughout this Clause, the name of templates are used to express type requirements. If a template is named Predicate, operator() of the template argument should return a value that is convertible to bool.

# 33.2.2 Exceptions [thread.req.exception]

Some functions in this Clause are specified to throw exceptions of type system_error (22.5.7). Such exceptions shall be thrown if any of the function's error conditions is detected or a call to an operating system or other underlying API returns an error that prevents the function from meeting its specifications. Failure to allocate storage should be reported in 20.5.5.12.

> Example: Consider a function in this clause that is specified to throw exceptions of operation_not_permitted that does not have the privilege to perform the operation. That, during the execution of this function, an errno of EPERM is reported by a POSIX API call by the implementation. Since POSIX specifies an errno of EPERM when the "caller does not have the privilege to perform the operation," the implementation maps errno to an error_condition_operation_not_permitted (22.5) and an exception of type system_error is thrown.

The error code reported by an exception's code() member function shall have value equal to one of the conditions specified in the function's error condition element.

# 33.2.3 Native names [thread.req.native]

Several classes described in this Clause have members native_handle_type and native_handle. The presence of these members and their semantics is implementation-defined. [Note: These members allow implementations to provide access to implementation details. Their names are specified to facilitate portable code compile-time detection. Actual use of these members is inherently non-portable.
