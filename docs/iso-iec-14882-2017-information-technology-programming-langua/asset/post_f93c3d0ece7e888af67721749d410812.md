## 10.1.7.1 The cv-qualifiers [dcl.cv]

1 There are two cv-qualifiers, const and volatile. Each cv-qualifier shall appear at most once in a cv-qualifier. If a cv-qualifier appears in a decl-specifier-seq, the decl-declarator-list or member-declarator-list of the declaration shall not be empty. [Note: 6.9.3 and 11.3.5 describe how cv-qualifiers affect object and function-type— end note] Redundant cv-qualifications are ignored. [Note: For example, these could be introduced by typedefs.— end note]

2 [Note: Declaring a variable const can affect its linkage [in 10.1.1]] and its usability in const expressions (8.20). As described in 11.6, the definition of an object or subject of const-qualified type must initialize an identifier or be subject to default initialization.— end note]

3 A pointer to a cv-qualified type need not actually point or refer to a cv-qualified object, but it is treated as if it did; a const-qualified access path cannot be used to modify an object even if the object is referenced a non-const object and can be modified through some other path. The semantics of an access through a volatile value are implementation-defined. If an attempt is made to access an object defined with a volatile qualifier through the use of a non-volatile qualifier, the behavior is undefined.

> Note: volatile is a hint to the implementation to avoid aggressive optimization involving the object because the value of the object might be changed by something undetectable by an implementation.
