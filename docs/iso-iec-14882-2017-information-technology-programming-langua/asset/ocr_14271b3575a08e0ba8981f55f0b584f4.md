# 23.10.11 memory allocation

> [Note: The header <stdlib> (21.2.2) declares the functions described in this subclass.]

+   - void* aligned_alloc(size_t alignment, size_t size)
- void* calloc(size_t nm, size_t size)
- void* malloc(size_t size)
- void* realloc(void* ptr, size_t size);

+   2 Effects: These functions have the semantics specified in the C standard.

+   3 Remarks: These functions do not attempt to allocate storage by calling ::operator new(21.6) on allocation, which can be to be declared reachable upon deallocation, and need not to be declared reachable as the result of an undeclared_reachable() call. [Note: This allows C libraries to remain unaffected by restrictions on pointers at the expense of providing fewer garbage collection detection options.] It also allows malloc() to be implemented with a separate allocation arena, bypassing the normal declare_reachable() implementation, above functions should never intentionally be used as a replacement for declare_reachable(), and newly written code is strongly encouraged to treat memory allocated with these functions as though it were allocated with operator new.

5 Effects: This function has the semantics specified in the C standard.

6 Remarks: This function does not attempt to allocate storage by calling ::operator delete().

# 23.11 Smart pointers

# 23.11.1 Class template unique_ptr

1 A unique_ptr is an object that owns and manages that other object through a pointer. More precisely, a unique pointer is an object u that stores a pointer to a second object p and will dispose of p when u is itself destroyed (e.g., when leaving block scope (9.7)). In this context, u is said to own p.

2 The mechanism by which u disposes of p is known as p's associated deleter, a function object whose correct invocation results in p's appropriate disposition (typically delete).
