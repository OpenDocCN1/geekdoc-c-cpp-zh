# ISO/IEC 14882:2017(E)

Note: If a new object is created in storage occupied by an existing object of the same type, a pointer to the original object can be used to refer to the object unless the type contains const or reference members; in the latter cases, this function can be used to obtain a pointer to the new object.
See 6.8. — end note

Example:

```
struct X { const int n; }
X *p = new X(3);
const int a = p->n; // p does not point to object (6.8) because X::n is const
const int b = p->n; // undefined behavior
const int c = std::lander(p)-n; // OK
```

# 21.6.5 Hardware interference size

```
inline size_t hardware_destructive_interference_size = implementation-defined;
```

This number is the minimum recommended offset between two concurrently-accessed objects to avoid additional performance degradation due to contention introduced by the implementation. It should be at least alignof(max_align_t).

Example:

```
struct keep_apart {
alignas(hardware_destructive_interference_size) atomic<int> cat;
alignas(hardware_destructive_interference_size) atomic<int> dog;
};
```

— end example

```
inline size_t hardware_constructive_interference_size = implementation-defined;
```

This number is the minimum recommended size of contiguous memory occupied by two objects accessed with temporal locality by concurrent threads. It should be at least alignof(max_align_t).

Example:

```
struct together {
atomic<int> int;
p puppy;
};
struct kernel {
// Other data members...
alignas(sizeof(together)) together pack;
// Other data members...
};
static_assert(sizeof(together) <= hardware_constructive_interference_size);
```

— end example
