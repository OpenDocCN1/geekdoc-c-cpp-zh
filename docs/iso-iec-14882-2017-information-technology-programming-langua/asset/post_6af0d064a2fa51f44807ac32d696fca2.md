
# ISO/IEC 14882:2017(E)

Example:

```
typedef void *p;
typedef const int *q;
typedef int **pi;
typedef const int **pci;
```

The composite type of p and q is "pointer to const void"; the composite type of pi and pci is "pointer to const pointer to const int". — end example

## 8.1 Primary expressions

- primary-expression:
  - literal
  - this
  - ( expression )
  - id-expression
  - lambda-expression
  - fold-expression

### 8.1.1 Literals

A literal is a primary expression. Its type depends on its form (5.13). A string literal is an lvalue; all literals are prvalues.

### 8.1.2

The keyword `this` names a pointer to the object for a non-static member template of a class X, or a static-data member initializer (12.2) is evaluated.

If a declaration declares a member function or member template, this expression is a prvalue of "pointer to co-qualifier-seq X" between the optional co-qualifier-seq and the end of the function-declarator, member-initializer. It should not appear before the optional co-qualifier-seq and will not appear within the declaration of a static member function (although its type and value category are defined within a static member function as they are within a static member function). [Note: This declaration matching does not occur until the complete declarator is known. — end note] Unlike the expression in other contexts, *this is not required to be of complete type for purposes of class member body. [Note: Only class members declared prior to the declaration are visible. — end note] [Example:

```
struct A {
  char *ptr;
  template<class T> f(T t) -> decltype(g(t)) {
    return t;
  }
};
template auto A::f(int t) -> decltype(g(t));
```

Otherwise, if a member-declarator declares a non-static member (12.2) of a class X, the expression is a prvalue of "pointer to X" within the optional default member initializer (12.2). It should not appear in the member-declarator.

The expression this shall not appear in any other context. [Example:

```
class Outer {
  int a(sizeof(*this)); // error: not inside a member function
  unsigned int sz = sizeof(*this); // OK: in default member initializer

  void f() {}

  int b[sizeof(*this)];    // OK
  struct Inner {
      int c[sizeof(*this)];    // error: not inside a member function of Inner
  };
};
// end example
```

### 8.1.3 Parentheses

A parenthesized expression (E) is a primary expression whose type, value, and category are identical to those of E. The parenthesized expression can be used in exactly the same contexts as where E can be used, and with the same meaning, except as otherwise indicated.

### 8.1.4 Names

```
id-expression:
    unqualified-id
    qualified-id
```

An id-expression is a restricted form of a primary-expression. [Note: An id-expression can appear after and -> operators (8.2.5)]. — end note

An id-expression denotes a non-static data member or non-static function of a class can only be used:

- (2.1) -- part of a class member (8.2.5) in which the object expression refers to the member's class65 or a class derived from that class, or

- (2.2) -- to form a pointer to member (8.3.1), or

- (2.3) -- if id-expression denotes a non-static data member and it appears in an unevaluated operand. Example:

```
struct S {
    int m;
    int i = sizeof(S::m);    // OK
    int j = sizeof(S::m + 42); // OK
}
// end example
```

### 8.1.4.1 Unqualified names

```
unqualified-id:
    operator-function-id
    conversion-function-id
    literal-operator-id
    class-specifier
    decltype-specifier
    template-id
```

An id-expression is provided if it has been declared (Clause 10). [Note: For operator-function-ids, see 16.5; for conversion-function-ids, see 15.3; for literal-operator-ids, see 16.5; for template-ids, see 17.2. A class-name or decltype-specifier prefixed by a destructor; see 15.4. Within the definition of a non-static member function, an identifier that names a non-static member expression is transformed to the unqualified-id65. This also applies when the object expression is implicit (++this) (12.2).]

### 8.1.4.2 Qualified names

- 1. The type denoted by a decltype denotes a class, optionally followed by the keyword template (17.2), and then followed by the name of a member of that class (12.2) or one of its bases (Clause 13), is a qualified-id; 6.4.3.1 describes lookup for class members that appear in qualified-ids. The result is the type of the member. The type of the result is a value if the member is a function or data member and a prvalue otherwise; The result is the enumerator. The type of the enumeration is prvalue.

- 2. The nested-name-specifier denotes the global name. A nested-name-specifier that names a namespace (10.3), optionally followed by the name of a member of that namespace (or the name of a namespace made visible by using a directive), is a qualified-id; 6.4.2.2 describes lookup for namespace members that appear in qualified-ids. The result is the type of the member. The type of the result is a value if the member is an enumeration or a variable and a prvalue otherwise.

- 3. A qualified-specifier that denotes an enumeration (10.2), followed by the name of an enumerator of that enumeration, is a qualified-id that refers to the enumerator. The result is the type of the enumeration. The result is prvalue.

- 4. In a qualified-id, if the unqualified-id is a conversion-function-id, its conversion-type-id should denote the same type in the context in which the entire qualified-id occurs and in the context of the class denoted by the nested-name-specifier.

### 8.1.5 Lambda expressions

```
lambda-expression:
  lambda-introducer lambda-declarator_opt compound-statement
  lambda-introducer:
    { lambda-capture_opt }
  lambda-declarator:
    { parameter-declaration-clause } decl-specifier-seq_opt
    nested-specifier_opt attribute-specifier-seq_opt trailing-return-type_opt
```

- 1 Lambda expressions provide a concise way to create simple function objects. [Example:
#include <algorithm>
#include <cmath>
void absorb(float* x, unsigned n) {
  std::sort(x, x + n, [](float a, float b) { return std::abs(a) < std::abs(b); });
}
```

- 2 Lambda-expression is a value whose result is the closure object. Lambda-expression shall not appear in an unvaluated expression (Clause 8), in a template-argument, in an alias-declaration, in a typedef declaration, or in the declaration of a function or function template outside its function and default arguments. [Note: The intention is to prevent lambdas from appearing in a signature. — end note] [Note: A closure behaves like a function object (23.14). — end note]

- 3 In the decl-specifier-seq of the lambda-declarator, each decl-specifier shall either be mutable or constexpr.

- 4 If a lambda-expression does not include a lambda-declarator, it is as if it is replaced by the type specifier (). The lambda return type is auto, which is replaced by the trailing-type provided or deduced from return statements as described in 10.1.7.4. Example:

```
auto x1 = [](int i) { return i; }; // OK return type is int
auto x2 = []() { return {1, 2}; }; // deduced return type from braced-init-list
int j;
auto x3 = []() { return j; }; // OK return type is int&
```

### 8.1.5 Closure

1 The type of a lambda-expression (which is the type of the closure object) is unique, non-union type class, the closure type, properties are described below

The closure type is declared by the smallest scope, class, or namespace that contains the corresponding lambda-expression. [Note: This determines the sets of namespaces and classes associated with the closure. (6.4.2)] The closure type is not an aggregate type (11.6.1). An implementation may define the closure type differently from what is described below does not allow the observable behavior of the program other changing by:

- (2.1) the size and alignment of the closure type,
- (2.2) whether the closure type is trivially copyable (Clause 12)
- (2.3) whether the closure type is a standard-layout class (Clause 12),
- (2.4) whether the closure type is a POD class to the closure type.

An implementation shall not add members of reference type to the closure type.

The type for a non-generic lambda-expression has a public inline call operator (16.5.4) whose parameters and return type are described by the lambda-expression's parameter-declaration-clause and trailing-return-type. For a generic lambda, the closure type has a public inline call operator template (17.5.2) whose template-parameter-list consists of one invented template-parameter for each auto in the lambda's parameter-declaration-clause, in appearance. The invented template-parameter is a parameter pack if the corresponding parameter-declaration-clause returns from the function operator derived from the expression's trailing-return-type and parameter-declaration-clause by replacing each auto in the decl-specifiers of the parameter-declaration-clause with the name of the corresponding invented template-parameter.
