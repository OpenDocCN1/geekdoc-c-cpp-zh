## 23.17.2 Steady_clock [time.clock]

Objects class steady_clock represent clocks for values of time_point never decrease as time advances and for values of time_point advance a rate relative to real time. The class may not be modified.

```cpp
class steady_clock {
public:
    using rep = unspecified;
    using period = ratio<unspecified, unspecified>;
    using duration = chrono::duration<rep, period>;
    using time_point = chrono::time_point<rep, duration>;
    static const bool is_steady = true;

    static time_point now();
};
```

## 23.17.3 Class high_resolution_clock [time.clock]

Objects class high_resolution_clock represent clocks with the shortest period. high_resolution_clock may be a synonym for system_clock or steady_clock.

```cpp
class high_resolution_clock {
public:
    using rep = unspecified;
    using period = ratio<unspecified, unspecified>;
    using duration = chrono::duration<rep, period>;
    using time_point = chrono::time_point<unspecified, duration>;
    static const bool is_steady = unspecified;

    static time_point now();
};
```

### 23.18.2 type_index overview [type.index.overview]

```cpp
namespace std {
class type_index {
public:
    type_index&=(const type_index& rhs) const noexcept;
    operator!=(const type_index& rhs) const noexcept;
    operator<(const type_index& rhs) const noexcept;
    operator>(const type_index& rhs) const noexcept;
    operator>=(const type_index& rhs) const noexcept;
    operator<=(const type_index& rhs) const noexcept;

    size_t hash_code() const noexcept;
    const char* name() const noexcept;
private:
    const type_info* info;
// Note that the value of a pointer here, rather than a reference,
    // means that the default copy/move constructor and assignment
    // operators will be provided and work as expected.

```

- 1. The class type_index provides a simple wrapper for type_info which can be used as an index type in associative containers (26.4) and in unordered associative containers (26.5).
- 2. strftime supports the C conversion specials C, D, e, f, g, h, r, t, u, v, w, and z, and the modifiers E and O.

## 23.19 Execution policies

### 23.19.1 In general

- 1. This subclause describes execution policies. An object of an execution policy indicates the kind of parallelism allowed in the algorithm. Example:

```cpp
using namespace std;
vector<int> v;

// standard sort
sort(v.begin(), v.end());

// explicitly sequential
sort(execution::seq, v.begin(), v.end());

// permitting parallel
sort(execution::par, v.begin(), v.end());

// permitting vectorization as well
sort(execution::par_unseq, v.begin(), v.end());
```
[Note: Because parallel architectures may require idiosyncratic parameters, implementations may provide additional execution policies to those described in this standard.] — end note

### 23.19.2 Header <execution> synopsis [execution.syn]

```cpp
namespace std { 
// 23.19.3, execution policy type trait

```

### 23.19.3 Execution policy type trait [ecpol.type]

- template<class> struct is_execution_policy { see below };
is_execution_policy can be used to detect execution policies for the purpose of excluding signatures from others overload resolution.
is_execution_policy<T> shall be a UnaryTypeTrait with a base characteristic of true_type if T is the type of a standard or implementation-defined execution policy, otherwise false_type.
[Note: This provision reserves the privilege of creating non-standard execution policies to the library implementation.] — end note
The behavior of a program that adds specializations for is_execution_policy is undefined.

### 23.19.4 Sequenced execution policy [ecpol.seq]

- class execution::sequenced_policy { unspecified };
class execution::sequenced_policy is an execution policy used as a unique type to disambiguate parallel algorithm overload requiring and that a parallel algorithm's execution may not be parallelized.
During the execution of a parallel algorithm with the execution::sequenced_policy, if the invocation of an element access entry exits via an uncaught exception, terminate() shall be called.
