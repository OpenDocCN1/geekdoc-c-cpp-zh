## 20.4.1.4 Detailed specifications [structure.specifications]

- 1 The detailed specifications each contain the following elements:
  (1.1) name and description
  (1.2) synopsis (class definition or function declaration, as appropriate)
  (1.3) restrictions on template arguments, if any
  (1.4) description of class invariants
  (1.5) description of function semantics

- 2 The descriptions of class member functions follow the order (as appropriate).157
  (2.1) constructor(s) and destructor
  (2.2) copying, moving & assignment functions
  (2.3) comparison functions
  (2.4) modifier functions
  (2.5) observer functions
  (2.6) operators and non-member functions

- 3 The descriptions of function semantics contain the following elements (as appropriate):158
  (3.1) Requires: the preconditions for calling the function
  (3.2) Effects: the actions performed by the function
  (3.3) Synchronization: the synchronization operations (4.7) applicable to the function
  (3.4) Postconditions: the observable results established by the function
  (3.5) Returns: a description of the value(s) returned by the function
  (3.6) Throws: any exceptions thrown by the function, and the conditions that would cause the exception
  (3.7) Complexity: the time and/or complexity of the function
  (3.8) Remarks: additional semantic constraints on the function
  (3.9) Error conditions: the error codes reported by the function

## 20.4.2 Other conventions [conventions]

- 1 This subclause describes several editorial conventions to describe the contents of the C++ standard library. These conventions are based on implementation-defined types (20.4.2.1), and member functions (20.4.2.2).

## 20.4.2.1 Type descriptions [types.descriptions]

### 20.4.2.1.1 [types.general]

- 1 The subclauses defined in Clause 30 are used to describe names that are used to specify constraints on template arguments.¹⁵¹ These names are used in library classes to describe the types that may be supplied as arguments by a C++ when instantiating templates from the library.

- 2 Certain types defined in Clause 21 through 33 are used as function parameter or return types. They are based on other types, but built by constructs.

## 20.4.2.1 Exposition-only types [exposure.only.types]

- 1 Several types defined in Clause 21 through 33 and Annex D that are used as function parameter or return types are for the purpose of exposition only in order to capture their language linkage. The declarations of such types are followed by a comment ending in exposition only. [Example:

```
namespace std {
extern " some-handler = int(int, void*, double); // exposition only
}
```

The placeholder some-handler can be used to specify a function that takes a callback parameter with C language linkage. — end example]
