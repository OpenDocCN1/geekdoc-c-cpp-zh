
# ISO/IEC 14882:2017(E)

## 5.12 Operators and punctuators

The lexical representation of C++ programs includes a number of preprocessing tokens which are used in the syntax of the preprocessor or are converted into tokens for operators and punctuators:

```
preprocessing-or-op-punc: one of
(      )      #       ##      ()
<       :>      %       %%      :      :
new delete ?      :      ;      *
+       *      /       &       /      %
!       |      <       ,      ===     !
<=      &=      <<     ++      >>     <=     ->
and     and_eq  bitand compl  not     not_eq
or     or_eq    xor     or_eq
```

Each preprocessing-or-op-punc is converted to a single token in translation phase 7 (5.2).

+ 1. An [italic]integer literal[/ is a sequence of digits that has no period or exponent part, with optional separating quotes that are ignored when determining its value. The lexically first digit of the sequence of digits is the most significant. An integer literal may have a prefix that specifies its base and a suffix that specifies its type. A binary literal (base two) begins with 0B or 0b and consists of a sequence of binary digits. A decimal literal (base ten) begins with a digit other than 0 and consists of a sequence of decimal digits. A hexadecimal literal (base sixteen) begins with 0X or 0x and consists of a sequence of hexadecimal digits, which include the decimal digits A through F. *Example:* The number twelve can be written 12, 0xC, or 0b1100. The integer literals 1048576, '1'048576, 0x10000, '0'10000, and 0'000000 all have the same value. — *example*

+ 2. The type of an integer literal is the first of the corresponding list in table 7 in which its value is represented.

+ 3. If all of the types in the list are unsigned, the extended integer type shall be unsigned. If the list contains both signed and unsigned types, the extended integer type may be signed or unsigned. A program is ill-formed if one of its translation units contains an integer literal that cannot be represented by any of the allowed types.

### 5.13.3 Character literals

```
character-literal:
  encoding-prefix c-sequence '
  encoding-prefix: one of
    u8 U L
  c-sequence:
    c-char
    c-sequence c-char
c-char:
    the single character or new-line character
    any member of the source character set except
    escape-sequence, universal-character-name
escape-sequence:
  simple-escape-sequence
  octal-escape-sequence
  hexadecimal-escape-sequence
simple-escape-sequence: one of
  \'a \b \f \r \v
octal-escape-sequence:
  \octal-digit
  \octal-digit octal-digit
  \octal-digit octal-digit
hexadecimal-escape-sequence:
  \hexadecimal-digit
  hexadecimal-escape
```

1 A character literal is one or more characters enclosed in single quotes, as in 'x', optionally preceded by u8, U, or L as in 'u8x', 'ux', or 'Lx'.

2 A character literal that does not begin with u8, U, or L is an ordinary character literal. An ordinary character literal containing a single c-char representable in the execution character set has type char, with value equal to the numerical value of the encoding of the c-char in the execution character set. An ordinary character literal containing more than one c-char is a multichar literal. A multichar literal, or an ordinary character literal containing a single c-char not representable in the execution character set, is conditionally-supported, has type int and an implementation-defined value.

3 A character literal that begins with u8 as in u8x is a character literal of type char. The value of a u8 character literal is equal to its ISO code point value, provided that the code point is a valid UTF-8 code point; otherwise, if it is not in the Basic Latin block, the program is ill-formed. A u8 character literal containing multiple-chars is ill-formed.

4 A character literal that begins with the letter u, as in ux', is a character literal of type char16_t. The value of a char16_t character literal containing a single c-char is equal to its ISO code point value, provided that the code point is representable in a 16-bit code unit (it is provided that it is a multipoint code point). If the value is not representable within 16 bits, the program is ill-formed. A char16_t character literal containing multiple-chars is ill-formed.

A character literal that begins with the letter U, as in U'', is a character literal of type char32_t. The value of a char32_t character literal containing a single c-char is equal to its ISO code point value. A wide-character literal of type char32_t is implementation-defined.

A character literal that begins with the letter L, as in L'', is a wide-character literal. A wide-character literal has type wchar_t. The value of a wide-character literal containing a single c-char has value equal to the numerical value of the encoding of the execution-character set, unless the c-char has no representation in the execution-character set (see 6.9.1).

> [Note: The wide-character literal containing the single quote '\', the double quote '"', the question mark '?', and the backslash '\' can be represented by the sequences '\', '\\', '\?', and '\\', respectively. The double quote '"' and the question mark '?' are not listed in Table 8. The backslash following the backslash not listed in Table 8 are conditionally-supported, with implementation-defined semantics. The backslash following the backslash shall be represented by the sequences '\\' and '\\\\' respectively. Each escape sequence follows a single character.]
