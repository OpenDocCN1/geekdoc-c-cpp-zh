Just as a range is empty when there is no pointer pointing past the last element of it, for any iterator type there is an iterator that points the past-end values. The values of an iterator for which the sequence is defined are dereferenceable. The library never ensures that past-end values are dereferenceable. Iterators can also have values that are not associated with any sequence. [Note: The guarantee is not offered for de-initialization, the distinction only matters for types with trivial destruct — end note] In these cases the value is returned the same way as any other iterator. Dereferenceable values are always non-singular.

An iterator j is reachable from i if and only if there is a sequence of operations from expression +1 that makes i j. If j is reachable from i, they refer to elements of the same sequence.

Most of the library iterators operate on data structures that have interfaces using ranges. A range of iterators is denoted by composition. [i, i) is an empty range; in general, a range [i, j) refers to the elements in the data structure starting with i to j. Range [i, j) is valid if and only j is reachable from i. The result of the application of functions in the library to invalidate ranges is undefined.

All the iterators require only those functions that are reliable for a given category in constant time (amortized). Therefore, require tables for the iterators to have no complexity complexity.

An invalid iterator may invalidate pointers and references previously obtained from that iterator.
