## 17.5.6.2 Partial ordering of function templates [temp.func.order]

1 If a function template is overloaded, the use of a function template specialization may be ambiguous because template argument deduction (17.8.2) may associate the function template specialization with more than one function template declaration. Partial ordering of overloaded function template declarations is used in the following contexts to select the function template to which a function template refers:
(1.1) during overload resolution for a call to a function template specialization (16.3.3);
(1.2) when the address of a function template specialization is taken;
(1.3) when a placement operator delete is a function template specialization is selected to match a placement operator new (6.4.2, 8.3.4); or an explicit instantiation
(1.4) when a friend function declaration (17.5.4), an explicit specialization (17.7.2) (17.7.3) refers to a function template specialization.

2 Partial ordering occurs when two functions are more specialized than the other by transforming each template term (in each turn; except of template argument deduction using the function deduction). The process determines whether one of the templates is more specialized than the other. If so, the more specialized template is chosen by the partial ordering process.

3 To produce the transformed template, for each type, non-type, or template parameter deduction using the function template parameters (in 17.5.3) synthesizes a unique value, type, or class template respectively (including [Note: The type replacing the placeholder in the type of value synthesized for a non-type template parameter is also a synthesized type — end note]) If only one of the function templates M is a non-static member of class A, M is considered to have a new first parameter in its function list. Given as the case the member of A or if M has no ref-qualifier and the reference to c of the other template has ref-qualifier and the first parameter of the other template has reference type. Otherwise, the new parameter is of type “value reference to c A”. [Note: This allows for a non-static member to refer to a non-member function and the results to be equivalent to the ordered non-members.— end note] [Example:

## 17.5.7 Alias templates [temp.alias]

1. A template-declaration in the declaration is an alias-declaration (Clause 10) declares the identifier to be an alias template. An alias template is a name for a family of types. The name of the alias template is a template-name.

2 When a template-id refers to the specialization of an alias template, it is equivalent to the associated type obtained substitution of its template-arguments for the template-parameters in the type-id of the alias. [Note: An alias template is never deduced. -- end note]; [Example:
template<class T> struct Alloc { /* ... */ };
template<class T> Vec = vector<T, Alloc<T>>;
Vec<int> v; // same as vector<int, Alloc<int>> v;

void process(Vec<T>& v) {
    /* ... */
}

## 17.6 Name resolution [temp.res]

1 Three kinds of names are used within a template definition:
(1.1) The name of the template itself, and names declared within the template.
(1.2) Names declared on a template-parameter.
(1.3) Names from scopes which are visible within the template.

2 A name used in a template declaration or definition that is dependent on a template-parameter is assumed not to be a type unless the applicable lookup finds a type name or the name is qualified by the keyword typename. [Example:
// no B here

```cpp
class X;
template<class T> class Y {
class Z;

void f() {
    type* a1; // declare pointer to X
    type* a2; // declare pointer to T
    type* a3; // declare pointer to Y<T>
    type* a4; // declare pointer to Z
    typename T::TA;
TA* a5; // declare pointer to T's A
    typename T::* a6; // declare pointer to T's A
    T::* a7; // T::A is not a type name:
multiplier of T::A by a7; ill-formed, no visible declaration of a7
* a8; // B is not a name:
multiplier of B by a8; ill-formed, no visible declarations of B and a8

};

// end example
```

3 When a qualified-id is intended to refer to a type that is not a member of the current instantiation (17.6.2.1) and its nested-name specifier refers to a dependent type, it shall be prefixed by the keyword typename, forming a typename-name specifier. If the qualified-id does not denote a type or a class template, the program is ill-formed.

```cpp
typename-specifier:
typename-name specifier identifier
typename-name specifier_template_opt simple-template
```

4 If a specialization of a template is instantiated for a set of template-arguments such that the qualified-id prefixed by typename does not denote a type or class template, the specialization is ill-formed. The usual qualified name lookup (6.4.3) is used to find the qualified-id even in the presence of typename. [Example:
