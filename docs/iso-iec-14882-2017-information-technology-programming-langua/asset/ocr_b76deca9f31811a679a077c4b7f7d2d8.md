An enumeration type is incomplete from its point of declaration (6.3.2) to immediately after its *enum-base* (if any), at which point it becomes a complete type. An enumeration whose underlying type is not fixed is incomplete from its point of declaration to immediately after the closing of its *enum-specifier*, at which point it becomes a complete type.

An enumeration whose underlying type is not fixed is implementation-defined—which integral type is used to represent. If no integral type can represent all the enumerator values, defined in the enumeration, it is ill-formed. The underlying type shall not be larger than the value of an enumerator cannot fit in an *int* or *unsigned*. If the *enum-list* is empty, the underlying type is an enumeration with a single value of 0.

For an enumeration whose underlying type is fixed, the values of the underlying type are the smallest *enumerator* and the largest *enumerator*, where the smallest and largest correspond to the range [b<sub>min</sub>, b<sub>max]] defined as follows: Let *K* be the number for two's complement representation and 0 for a one's complement or sign-magnitude representation and 2<sup>M</sup> - 1, where *M* is the smallest value greater than or equal to max(b<sub>min</sub>, -b<sub>max</sub>) and is also a non-negative integer. *M* is zero if b<sub>min</sub> is non-negative and (b<sub>max</sub> - b<sub>min</sub> + 1). The size of the smallest bit-field required to hold all values of the underlying type is *M* if *M* is zero and M+1 otherwise. It is possible to define an enumeration that has values not defined by any of its enumerators. If the *enum-list* is empty, the values of the enumeration are as if the enumeration had a single value of 0.

The value of an enumerator or an object of an unscoped enumeration type is converted to an integer by integral promotion (7.6). Example:

color col = red;
