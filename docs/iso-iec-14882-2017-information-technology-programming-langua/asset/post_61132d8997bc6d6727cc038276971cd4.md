## 10.3.1.1 Unnamed namespaces

An unnamed-namespace-definition behaves as if it were replaced by
```cpp
inline namespace unnamed { /* empty body */
using namespace unnamed;
```
where `inline` appears and only if it appears in the unnamed-namespace-definition and all occurrences of `inline` in the translation unit are replaced by the same identifier, and this identifier differs from all other identifiers in the translation unit. Example:

```cpp
namespace A {
  int i; // unnamed::i
  void f() { i++; }; // unnamed::i
}
namespace A {
  namespace {
    int i; // unnamed::i
    int j; // unnamed::j
  }
  void g() { i++; }; // unnamed::i
}
using namespace A;
void h() {
  i++; // error: unnamed::i
  A::i++; // unnamed::i
  j++; // unnamed::j
}
```

## 10.3.1.2 Namespace member definitions

+ A declaration in a namespace M (excluding declarations in nested scopes) whose declarator-id is an unqualified-id (11.3), whose class-name (1.2) or enum-name (10.2) is an identifier, or whose elaborated-type-specifier is of the form class-specifier-seq identifier (10.7.3), declares (or redecl) its unqualified-id as a member of M. [Note: An explicit instantiation (17.7.2) or explicit specification (17.7.3) of a template does not introduce a name and thus may use an unqualified-id if the primary template is declared in an unnamed namespace. — end note] Example:

```cpp
namespace X {
  void f() { /* ... */ }; // OK introduces X::f()
```

```cpp
namespace M {
  void g() {
    using M::g(); // OK introduces X::M::g()
    void g();
  } // error: conflicts with X::M::g()
}
```

+ Members of a named namespace can also be defined outside that namespace by explicit qualification (6.4.3.2) of the name being defined, provided that the entity defined was already declared in the namespace and the definition appears after the point of declaration in a namespace that encloses the declaration's namespace. Example:

```cpp
namespace Q {
    namespace V {
        void f();
        void V::f() { /* ... */ } // OK
        void V::g() { /* ... */ } // error: g() is not yet a member of V
        namespace V {
            void g();
        }
    }
}
namespace R {
void V::g() { /* ... */ } // error: g doesn't enclose Q
}
```

If a friend in a non-local class declares a class, function, class template or function template, the friend is a member of the innermost enclosing namespace. The friend declaration does not by make the name invisible to lookup (6.4.1) [Note: If a matching declaration is provided at namespace scope (either before or after the class definition grant friendship). — end note] If a function or function template is called, it may be found by the name the lookup considers from namespaces and classes associated with the point of call (6.4.3). ## 10.3.2 Namespace aliases

+ 1 A namespace-alias-definition declares an alternate name for a namespace according to the following grammar:
namespace-alias:
  identifier
namespace-alias-definition:
  namespace-alias identifier = qualified-namespace-specifier;
qualified-namespace-specifier:
  nested-name-specifier namespace-name

+ 2 The identifier in a namespace-alias-definition is a synonym for the name of the namespace denoted by the qualified-namespace-specifier and becomes a namespace-alias. [Note: When looking up a namespace-name in a namespace-definition, only namespace names are considered, see 6.4.6.]

+ 3 In a declarative region, a namespace-alias can be used to redefine a namespace-alias declared in that declarative region to refer to the namespace to which it refers. [Example: The following declarations are well-formed:
namespace Company_with_long_name { /* ... */
namespace CWLN = Company_with_long_name;
namespace CWLN = Company_with_long_name; // OK duplicate
namespace CWLN = CWLN;}]

## 10.3.3 The using declaration

+ using-declaration:
  using-declaration-list:
    using-declarator ...
    using-declarator ... opt
using-declarator:
  typename_opt nested-name-specifier unqualified-id

+ 1 Each using-declaration in a using-declaration introduces a set of declarations into the declarative region where the using-declaration appears. The set of declarations introduced is found by performing name lookup in the using-declaration, excluding functions that are hidden described below (6.6.3, 13.2) If the using-declaration does not name a constructor, the unqualified-id is declared in the declarative region as a synonym for each declaration introduced by the using-declaration. [Note: Only the specified name is so declared; if declaring an enumeration name in a using-declaration does not declare its enumerators in the using-declaration’s declarative region. — end note] If the using-declaration names a constructor, it declares that the class inherits the set of constructor declarations introduced by the using-declaration from the nominated base.

> (98) A using-declaration with more than one using-declaration is equivalent to a corresponding sequence of using-declaration each.
