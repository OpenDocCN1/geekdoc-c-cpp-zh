# ISO/IEC 14882:2017(E)

# 33.2.4 Timing specifications

1 Several functions described in this Clause take an argument to specify a timeout. These timeouts are specified either as a duration or a time_point type as specified in 23.17.

2 Implementations necessarily have some delay in returning from a timeout. Overhead in interrupt response, function return, and scheduling includes “quality of implementation” delay, expressed as duration $D_i$. Ideally, this delay would be zero. Further, contention for processor and memory resources reduces “quality of management” delay, expressed as duration $D_m$. The delays may vary from timeout, but in all cases it is shorter.

3 The member functions use end_in take an argument to specify a duration. These functions produce relative times. Implementations should use a steady clock to measure time for these functions. Given a duration $D_t$, the real-time of that duration is $D_t + D_i + D_m$.

4 The member functions use end_until take an argument to specify a timeout. These functions produce absolute times. Implementations should use the steady clock in the timeout to measure time for these functions. The clock, the clock point of the return from them should be $C_t + D_i + D_m$ during the execution. If the clock is adjusted to $C_n$ during the timeout, the behavior should be as follows:

+   (4.1) If $C_n < C_t$, the waiting function should be as soon as possible, i.e. $C_n + D_i + D_m$, since the timeout is specified already. This specification may result in the total duration of the wait measured against a steady clock. — end note

+   (4.2) If $C_n > C_t$, the waiting function should not time out Clock: now() returns a $C_n$ i.e. waking at $C_t + D_i + D_m$. When the clock is adjusted, this specification may result in the total duration of the wait increasing when measured against a steady clock. When the clock is adjusted, this specification may result in the total duration of the wait decreasing when measured against a steady clock. — end note

An implementation should return from a timeout from the time specified above to the time it would return from a steady-clock relative amount of the difference between $C_t$ and the time point of the clock adjusted to until. [Note: Implementations should decrease the duration of the wait when the clock is adjusted. — end note]

+   5 If the clock is not synchronized with a steady clock, e.g., a CPU clock time, these timeouts might not provide usefulness. — end note

+   6 The resolution of timing provided by an implementation depends on both operating system and hardware. The finest resolution provided by an implementation is called the native resolution.

+   7 Implementation-provided clocks that are used for these functions must meet a timeout if, during its execution, a clock point, or duration throws an exception. Such exceptions are referred to as timeout-related exceptions. [Note: Instances of clock, time point and duration types supplied by the implementation as specified in 23.17.7 do not throw exceptions. — end note]

+   8 A function that takes an argument which will timeout if, during its execution, a clock point, or duration throws an exception.
