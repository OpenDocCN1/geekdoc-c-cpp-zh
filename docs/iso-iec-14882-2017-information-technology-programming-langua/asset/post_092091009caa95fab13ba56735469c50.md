Within the initializer-list of a braced-init-list, the initializer-clauses, including any that result from pack expansions (17.5.3), are evaluated in the order in which they appear. That is, every computation and side effect associated with a given initializer-class is sequenced before every computation and side effect in the comma-separated list of the initializer-list.
[Note: This evaluation holds regardless of the semantics of the initialization; for examples when the elements of the initializer-list are interpreted as arguments of a constructor call, even though there are no constraints on the arguments of a call — end note]

An object of type std::initializer_list<E> is constructed from an initializer if the implementation generated and materialized (7.4) a value of type "array of N E", where N is the number of elements in the initializer list. Each element of array is copy-initialized with the corresponding element of the initializer list and the initializer_list<E> object is constructed to reflect that array. [Note: A constructor or conversion function used for the copy shall be accessible (Clause 14) in the context of the initializer list — end note] If a conversion is required to initialize any of the elements, the program is ill-formed. [Example]:

```
struct X {
 X(std::initializer_list<double> v);
 X { 1, 2, 3 };
};
```

The initialization be performed in a way equivalent to this:
const double _a[3] = {double(1),double(2),double(3)};
 X(std::initializer_list<double>{_a, _a+3});

assuming that the constructor constructs an initializer_list object just like binding a reference. — end example

Array has the same lifetime as any other temporary object (15.2), except initializing an initializer_list object extends the lifetime of the array exactly like binding a reference to a pointer.
[Example]:

```
typedef std::complex<double> cmplx;
std::vector<complex> v = {1, 2};
```

```
void f() {
std::vector<cmplx> v2{1, 2};
std::initializer_list<int> i13 = {1, 2};
};
```

```
struct A {
std::initializer_list<int> i14;
 A() : i14{1, 2}; // ill-formed, would create a dangling reference
```

For v1 and v2, the initializer_list object is a parameter in a function call, so the array created for {1, 2} has full lifetime. For i13, the initializer_list object is a variable, so the array persists for the lifetime of the variable. For i14, the initializer_list object is initialized in the constructor as by binding a temporary reference to a member, the program is ill-formed (15.6) — [Note: The implementation is free to allocate the array in read-only memory unless an explicit array with the same initializer could be allocated — end note]

A narrowing conversion is an implicit conversion
from a floating-point type to an integer type,
from long double to double or from double to float, where the source is a constant expression and the actual value after conversion is within the range of values that can be represented (even if it cannot be represented),
(7.3) from an integer type or enumeration type to a floating-point type, except where the source is a constant expression and the actual value after conversion will fit into the target type and will produce the original value when converted back to the original type, or
(7.4) from an integer type or enumeration type to an integer type that cannot represent all the values of the original type, except where the source is a constant expression value after integral promotions will fit into the target type, [Note: As indicated above, such conversions are not allowed at the top level in list-initializations — end note]

```
int x = 999; // x is not a constant expression
const int y = 999; // OK, though it might narrow (in this case)
const char x = 999; // error: narrow
char cl = x; // error: narrow (assuming char is 8 bits)
char c2(x); // OK: no narrowing
char c3(y); // OK: no needed
unsigned char uc1 = {5}; // error: narrow
unsigned char uc2 = {-1}; // error: narrow
unsigned int sil = // error: narrow
{ (unsigned int)-1 }; // error: narrow
int ii = (2.0); // error: might narrow
float f1 = { x }; // OK: 7 can be exactly represented as a float
float f2 = {7 };
int f3();
int a[] = { 2, f(2), f(2.0) }; // OK: the double-to-int conversion is not at the top level
```

# Classes [class]

1 A class is a type. Its name becomes a class-name (12.1) within its scope.

```
class-name:
    identifier
    simple-template-id
```

Class-specifiers and elaborated-type-specifiers (10.1.7.3) are used to make class-names. An object of a class consists of a (possibly empty) sequence of members and base class objects.

```
class-specifier:
    class-head { member-specification_opt }
    class-head:
        class-key attribute-specifier-seq_opt class-name class-specifier_opt class-virt-specifier_opt base-clause_opt
        class-key attribute-specifier-seq_opt base-clause_opt
```

```
class-name:
    nested-name-specifier_opt class-name
```

```
class-virt-specifier:
    final
    class-key:
        struct
        union
```

A class-specifier whose class-head omits the class-name defines an unnamed class. [Note: An unnamed class's name can't be final. — end note]

2 A class-name is inserted into the scope in which it is declared immediately after the class-name. The class-name is also inserted into the scope of itself; this is known as the injected-class-name. For purposes of access checking, the injected-class-name is treated as if it were a public member name. A brace of its class-specifier has been opened but member functions in general are not yet defined. The attribute-specifier-seq applies to the class in the attribute-specifier-seq attributes which are thereafter considered attributes of the class whenever it is named.

3 If a class is marked with the class-virt-specifier final and it appears as a class-or decltype in a base-clause (Clause 13), the program is ill-formed. Whenever a class-key is followed by a class-name, the identifier final, or a colon or left brace, final is interpreted as a class-virt-specifier. [Example: 

```
struct A;
struct A() {}; // definition of struct A.
    // non-initialization of variable final

struct X {
    struct C { constexpr operator int() { return 5; } };
    struct B : C {}; // declaration of nested class B.
    // declaration of a bit-field member final
};

// end example]
```
