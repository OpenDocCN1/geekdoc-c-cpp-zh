## 23.10.8.2 Allocator traits member functions [allocator.traits.members]

```cpp
static pointer allocate(Alloc& a, size_type n);

Returns: a.allocate(n).
static pointer allocate(Alloc& a, size_type n, const void_pointer hint);

Returns: a.allocate(n, hint) if that expression is well-formed; otherwise, a.allocate(n).
static deallocate(Alloc& a, pointer p, size_type n);

Effects: a.deallocate(p, n).
nrows: Nothing.
```

```cpp
template <class T, class... Args>
static void construct(Alloc& a, Args&&... args) : std::forward<Args>(args)... if that call is well-formed; otherwise, invokes :: new (static_cast<void*>(a.get())) T(std::forward<Args>(args)...);

template <class T>
static void destroy(Alloc& a, T* p) : noexcept;

Effects: a.destroy(p) if that call is well-formed; otherwise, invokes ~T(p).
```

```cpp
size_type max_size(const Alloc& a);

Returns: a.max_size() if that expression is well-formed; otherwise, numeric_limits<size_type>::max()/sizeof(value_type).
```

```cpp
static Alloc select_on_container_copy_construction(const Alloc& rhs) const noexcept;

Returns: rhs.select_on_container_copy_construction(construction) if that expression is well-formed; otherwise, rhs.
```

## 23.10.9.1 allocator members

- Except for the destructor, member functions of the default allocator shall not introduce data races (4.7) as a result of calls to them member functions from different threads. Calls to these functions allocate or deallocate a particular unit of size occurs in a single total order, and each such deallocation shall happen before the next allocation (if any) in this order.

```cpp
T* allocate(size_t n);
```

- Returns: A pointer to the initial element of an array of size n * sizeof(T), aligned appropriately for objects of type T.
- Remarks: the storage is allocated by calling ::operator new (21.6.2), but it is unspecified or when how often this is called.
- Throws: bad_alloc if the storage cannot be obtained.

```cpp
void deallocate(T* p, size_t n);
```

- Requires: a pointer value obtained from allocate(). n shall equal the value passed as the first argument to the allocation of which returned p.
- Effects: Deallocates the storage referenced by p.
- Remarks: ::operator delete (21.6.2), but it is unspecified when this function is called.

## 23.10.10 Specialized algorithms [specialized.algorithms]

Throughout this subclass, the name of template parameters are used to express type requirements.

- If an allocator template is named InputIterator, the template argument shall satisfy the requirements of an input iterator (27.2.3).
- If an allocator template is named ForwardIterator, the template argument shall satisfy the requirements of a forward iterator (27.2.5), and is required to have the property that no exceptions are thrown from increment, assignment, comparison, or direction through valid iterators.

Unless otherwise specified, if an exception is thrown in the following algorithms there are no effects.

## 23.10.10.1 addressof [specialized.addressof]

```cpp
template <class T> constexpr T* addressof(T& r) noexcept;
```

- Returns: The actual address of the object or function referenced by r, even in the presence of an overloaded operator.
- Remarks: An expression address(E) is a constant subexpression (20.3.6) if E is an lvalue constant.

## 23.10.10.2 uninitialized_default_construct [uninitialized.construct.default]

```cpp
template <class ForwardIterator>
void uninitialized_default_construct(ForwardIterator first, ForwardIterator last);
```

- 1 Effects: Equivalent to:

```cpp
for (; first != last; ++(void)address(*first))
    ::new (static_cast<void>(address(*first)))
    typename iterator_traits<ForwardIterator>::value_type;
```

```cpp
template <class ForwardIterator, class Size>
ForwardIterator uninitialized_construct_n(ForwardIterator first, Size n);
```

- 2 Effects: Equivalent to:

```cpp
for (; n!=0; (void)++address(*first))
    ::new (static_cast<void>(address(*first)))
    typename iterator_traits<ForwardIterator>::value_type;
```
