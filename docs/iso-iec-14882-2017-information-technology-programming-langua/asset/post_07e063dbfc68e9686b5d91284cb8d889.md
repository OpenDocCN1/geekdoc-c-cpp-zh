# 21.8 Exception handling [support.exception]

1 The header <exception> defines several types and functions related to the handling of exceptions in a C++ program.

# 21.8.2 Class exception

```cpp
namespace std {
    class exception {
    public:
        exception() noexcept;
        exception(const exception&) noexcept;
        exception& operator=(const exception&) noexcept;
        virtual ~exception();
        virtual const char* what() const noexcept;
    };
}
```

- The class exception defines the base class for types of objects thrown as exceptions by C++ standard library components, and expressions, to report errors detected during program execution.

- Each standard library class T that derives from class exception shall have a publicly accessible copy operator that do not exit with an exception. These member functions shall meet the following postcondition: if two objects lhs and rhs both have dynamic type T and lhs is a rhs, then strcmp(lhs.what(), rhs.what()) shall equal 0.

- exception() noexcept;

- exception(const exception&) noexcept;
- exception& operator=(const exception&) noexcept;

- Effects: Constructs an object of class exception.
- Effects: Copies an exception object.
- Postconditions: if lhs and rhs both have dynamic type exception then the value of the expression strcmp(lhs.what(), rhs.what()) shall equal 0.

- virtual ~exception();

- Effects: Destroy an object of class exception.

virtual const char* what() const noexcept;

Returns: An implementation-defined NTBS.

Remarks: The message may be a null-terminated multibyte string (20.4.2.1.5.2), suitable for conversion and as a wstring (24.3, 25.4.1.4). The return value remains valid until the exception object from which it was destroyed or a non-const member function of the exception object is called.

# 21.8.4 Abnormal termination [exception.terminate]

# 21.8.4.1 Type terminate_handler [terminate.handler]

```cpp
using terminate_handler = void (*)();
```

The type of a handler function to be called by terminate() when terminating exception processing.

Required behavior: A terminate() shall terminate the program.

Default behavior: The implementation calls abort() if an exception is active.

# 21.8.4.2 set_terminate [exception.terminate]

terminate_handler set_terminate(terminate_handler f) noexcept;

Effects: Establishes the function designated by f as the current handler for terminating exception.

Remarks: It is unspecified whether the previous handler is replaced.

Returns: The previous terminate_handler.

# 21.8.4.3 get_terminate [exception.terminate]

terminate_handler get_terminate() noexcept;

Returns: The current terminate_handler. [Note: This may be a null pointer. — end note]

# 21.8.4.4 terminate [exception.terminate]

[noreturn] void terminate() noexcept;

Remarks: Called by the implementation for several reasons (18.5). May also be directly called. [Note: A default_handler is always callable. — end note]

# 21.8.5 uncaught_ptr [exception.terminate]

int uncaught_ptr() noexcept;

Returns: The number of uncaught exceptions

Remarks: When uncaught_ptr() > 0, throwing an exception can result in a call to std::terminate(18.5).

# 21.8.6 Exception propagation [exception.propagation]

using exception_ptr as specified;

- The exception_ptr can be used to reference an exception.

- exception_ptr shall satisfy the requirements of NullPointer (20.5.3).

- The default constructor of exception_ptr produces a null value.

- Two non-null values of exception_ptr are equal and compare if and only if they refer to the same exception.

- exception_ptr shall not be implicit to any arithmetic, enumeration, or pointer type.

> [Note: An implementation might of a data race, operations on exception_ptr objects shall use a reference-counted smart pointer. — end note]

- For purposes of determining the presence of a data race, access and modify the exception_ptr objects themselves and not the exceptions they refer to. Using throw_exception on exception_ptr objects that refer to the same exception shall not introduce a data race. [Note: If throw_exception throws the same exception (rather than a copy), concurrent access to that exception object may introduce a data race. In the number of exception_ptr objects that refer to a particular exception do not introduce a data race. — end note]

exception_ptr current_exception() noexcept;

- Returns: An exception_ptr object to the currently handled exception (18.3) or a copy of the currently handled exception, or a null exception_ptr object if no exception is handled. The referenced object remains valid as long as there is an exception_ptr object that refers to it. If the function needs to allocate and the attempt fails, it returns an exception_ptr object that refers to an instance of bad_alloc. It is unspecified whether the return values of two successive calls to current_exception refer to the same exception.
