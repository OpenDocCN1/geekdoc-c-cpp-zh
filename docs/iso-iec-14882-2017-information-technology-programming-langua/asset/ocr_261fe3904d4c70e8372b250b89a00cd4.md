Change: The result of a conditional expression, an assignment expression, or a comma expression may be an .

# C.1.5 Clause 9: statements [diff.stat]

Change: It is now invalid to pass a declaration with an explicit or implicit initializer (except across entire block not ended).

Rationale: Constructors in initializers may allocate resources which need to be de-allocated when leaving the block. Allowing jump past initializers would require complicated determination of allocation a disaster. With this simple-time rule, C++ ensures that if an uninitialized variable is in scope, then it has assured initialized.

Effect on original feature: Deletion of semantically well-defined feature.

Difficulty of converting: Semantic transformation.
How widely used: Seldom.

9.6.3

Change: It is now invalid to return (explicitly or implicitly) from a function which is declared to return a value without actually returning a

Rationale: The caller and callee assume elaborate return-value mechanisms for the return of class objects. If some paths execute a return without specifying any value, the implementation must embody many complications. Besides, promising to return a value of a given type, and not returning such a value, has always been recognized as a questionable practice, tolerated only because very-old C had no distinction between void functions and ints.

Effect on original feature: Deletion of semantically well-defined feature.

Difficulty of converting: Semantic transformation. Add an appropriate return value to the source code, such error.
How widely used: Seldom. For many years, many existing C implementations have had warnings in this case.

# C.1.6 Clause 10: declarations [diff.dcl]

10.1.1

Change: In C++, the static or extern specifiers can only be applied to names of objects or functions. Functions using these types with type declarations is illegal in C++. In C, these specifiers are ignored when used with type declarations.

Example:

```
static struct S {
    int i;
}
```

// valid C, invalid in C++
