> Note: The above definitions for comparison functions do not require t_tail (or u_tail) to be constructed. It may not be possible, as t and u are not required to be copyable. Also, all comparison functions are short-circuited; they do not perform elements beyond what is required to determine the result of the comparison. — end note

# 23.5.3.9 Tuple traits [tuple.traits]

```
template <class... Ttypes, class... Alloc>
struct uses_allocator<tuple<Ttypes...>, Alloc> : true_type { };
```

+   1 Requires: Alloc shall be an Allocator (20.5.3.5).

> Note: Specialization of this trait informs other libraries that tuple can be constructed with an allocator, though it does not have a nested allocator_type. — end note

# 23.5.3.10 Tuple specialized algorithms [tuple.special]

```
template <class... Ttypes>
void swap(tuple<Ttypes...>& x, tuple<Ttypes...>& y) noexcept(see below);
```

Remarks: This function shall not participate in overload resolution unless is_swappable_v<T, T> is true for all i, where 0 <= i < sizeof...(Ttypes). The expression inside noexcept is equivalent to:
except(swap(y))

Effects: As if by x.swap(y).
