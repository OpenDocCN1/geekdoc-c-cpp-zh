# ISO/IEC 14882:2017(E)

(4.6) a pointer to an object of derived class type or an *ivalue* or *rvalue* of derived class type may be explicitly converted to a pointer or reference to an unambiguous base class type, respectively;

(4.7) a pointer to member of derived class type may be explicitly converted to a pointer to member of an unambiguous non-virtual base class type;

(4.8) a pointer to an object of unambiguous non-virtual base class type, a *gvalue* of an unambiguous non-virtual base class type, or a pointer to member of an unambiguous non-virtual base class type may be explicitly converted to a pointer, a reference, or a pointer to member of a derived class type, respectively.

If a conversion be interpreted in more than one of the ways listed, the interpretation that appears in the first list is used, even if a cast resulting from that interpretation is ill-formed. If a conversion is interpreted in more than one way as a *static_cast*, performed by *const_cast*, the conversion is ill-formed.
Example:

```
struct T {};nstruct I1 : A {};nstruct I2 : A {};nstruct D : I1, I2 {};
* foo(D* p) {
// ill-formed static_cast interpretation
  return (A*)p;
}
```

The operand of a cast using the cast notation can be a prvalue of "pointer to incomplete type". The destination type and operand types are class types and one or both; if one is incomplete, it is unspecified whether the *static_cast* or the *reinterpret_cast* interpretation is used, even if there is an inheritance relationship between the two. [Note: For example, if classes defined in the translation unit, a multi-pass compiler would be permitted to interpret a cast between pointers to the classes if it were complete at the point of the cast.]

# 8.5 Pointer-to-member operators [expr.mptr.oper]

1 The pointer-to-member operators *->* and *.* group left-to-right.

```
pm-expression:
pm-expression * cast-expression
pm-expression -> cast-expression
```

2 The binary operator *.* binds its second operand, which shall be of type "pointer to member of T" to its operand, which shall be a class of which T is unambiguous and accessible base class. The result is an object or a pointer of the type specified by the second operand.

3 The binary operator *-> binds its second operand, which shall be of type "pointer to member of T" to its first operand, which shall be of type "pointer to U" where U is T or class of which T is unambiguous and accessible base class. The expression E1->E2 is converted into the function expression (*E1).*E2.

4 Abbreviating *pm-expression*, *cast-expression* on E1.*E2, E1 is the *object expression*. If the type of E1 does not contain the member to which E2 refers, the behavior is undefined. Otherwise, the expression E1 is sequenced before the expression E2.

5 The restrictions on *ce-qualification*, and the manner in which the ce-qualifiers of the operands are ordered to produce the ce-qualifiers of the result, are the same as the rules for E1.E2 given in 8.2.5.
