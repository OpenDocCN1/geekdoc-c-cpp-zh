## 17.5.3 Variadic templates [temp::variadic]

- 1 A template pack is a template that accepts zero or more template arguments. [Example:

```cpp
template<class Types> struct Tuple {

Tuple<void> t0; // Type contains no arguments
Tuple<int> t1; // Type contains one argument: int
Tuple<int, float> t2; // Type contains two arguments: int and float
Tuple<0> error; // error: 0 is not a type
// end example];
```

- 2 A function pack is a function that accepts zero or more function arguments. [Example:
template<class Types> void f(Types args);

```cpp
f();
f(1); // OK: args contains one argument: int
f(1, 2.0); // OK: args contains two arguments: int and double
// end example];
```

- 3 A pack expansion consists of a pattern and an ellipsis, the instantiation of which produces zero or more instantiations of the pattern in a list (described below). The form of the pattern depends on the context in which the expansion occurs. Pack expansions can occur in the following contexts:

- (4.1) In a function pack (11.3.5); the pattern is the parameter-declaration without ellipsis

- (4.2) In a using-declaration (10.3.3); the pattern is a using-declaration.

- (4.3) In a template pack that is an ellipsis:

- (4.3.1) if the template pack is a pack-declaration; the pattern is the pack-declaration without the ellipsis;

- (4.3.2) if the template pack is a type-parameter with a type-parameter-list; the pattern is the corresponding type-parameter without the ellipsis.

- (4.4) In an initializer-list (11.6); the pattern is an initializer-clause.

- (4.5) In a base-specifier-list (Clause 13); the pattern is a base-specifier.

- (4.6) In a member-initializer-list (15.6.2) for a member-initializer whose member-initializer-id denotes a base class; the pattern is the member-initializer.

- (4.7) — In a template-argument-list (17.3); the pattern is a template-argument.

- (4.8) — In an attribute-list (10.6:1); the pattern is an attribute.

- (4.9) — In an alignment-specifier (10.6:2); the pattern is the alignment-specifier without the ellipsis.

- (4.10) — In a capture-list (8.1:5); the pattern is a capture.

- (4.11) — In a sizeof… expression (8.3:3); the pattern is an identifier.

- (4.12) — In a fold-expression (8.1:6); the pattern is the pack-expansion that contains an unpacked parameter pack.

```cpp
[Example:
template<Class Types> void f(Types... rest);
template<Class ...> void f(Types... rest) {
    f(rest...);
    // "rest" is a pack expansion; "rest" is its pattern
}
//end example]
```

For the determination of whether a parameter pack satisfies a rule other than parameter packs, the parameter pack is to be the entity that arises from an instantiation of the pattern in which it appears. A pack parameter whose names appear within a pattern of pack expansion is expanded by that pack expansion. An appearance of a name of a pack is expanded by the innermost pack expansion. The pattern of pack expansion contains one or more parameter packs that are not expanded; such packs are called unpacked packs. All parameter packs expanded by a pack expansion will have the same number of arguments specified. An appearance of a name of a pack that is not expanded is ill-formed. [Example:

```cpp
template<typename... T1, typename T2> struct Pair {};
template<class ... Args1> struct zip {
    typedef Tuple<Args1, Args2...> type;
};
```

```cpp
typedef zip<short, int::with<unsigned, short>>::type T1; // T1 is Pair<short, unsigned>
// T2; // error: different number of arguments specified for Args1 and Args2
```

```cpp
template<class ... Args>
void g(Args... args) {
    f(const Args&...(args...)); // OK: Args is expanded by the function pack args
    f(S...); // OK: pattern does not contain any parameter packs
    f(args); // error: pattern "args" is not expanded
    f(h(args...)); // OK: first "args" expanded within h, second "args" expanded within f
}
//end example]
```

The instantiation of a pack expansion that is not a sizeof expression nor a fold-expression produces a list $E_1, ..., E_N$, where $N$ is the number of elements in the pack expansion. Each $E_i$ is generated by instantiating the pattern and replacing each pack parameter with its ith element. Such an element in the context of the template, is interpreted as follows:

- (7.2) if the pack is a function pack, the element is an id-expression designating the function parameter resulted from the instantiation of the pattern where the pack is declared.

All of the $E_i$ becomes the following list [Note: The variety of lists with expression-list, base-specifier-list, template-argument-list, etc.—end note]. When $N$ is zero, the instantiation of the expansion produces an empty list. Such instantiation does not alter the syntactic interpretation of the enclosing construct, even in cases where omitting the list would be ill-formed or would result in an ambiguity in the grammar. [Example:

```cpp
template<class... T struct X { T... };
template<class... T void f(T... values) {
  X(values...);
}
```

```cpp
template void f(); // OK: X has no base classes
// x is a variable of type X that is value-initialized
```
end example

The instantiation of sizeof... expression (8.3.3) produces an integral count containing the number of elements in the pack parameters. The instantiation of a fold-expression produces:

- (9.1) — $(E_1 \ op E_2) \dots \ op E_N$ for a unary left fold,

- (9.2) — $(E_N \ op E_{N-1}) \dots \ op E_1$ for a unary right fold, and

- (9.3) — $((E_1 \ op E_2) \op E_3) \dots \ op E_N$ for a binary left fold, and

- (9.4) — $(E_1 \ op (\dots \op (E_N \ op E_1)))$ for a binary right fold.

In each case, $op$ is the fold-operator, $N$ is the number of elements in the pack expansion parameters, and each $E_i$ is generated by instantiating the pattern and replacing each pack expansion parameter with its ith element. For a binary fold-expression, $E$ is generated by the cast-expression that did not contain an unexpanded pack parameter. [Example]:

```cpp
template<typename... Args>
bool all(Args... args) { return ... && args; };
```

```cpp
bool b = all(true, true, true, false);
```

Within the instantiation of all, the returned expression expands to ((true && true) && true) && false, which evaluates to false. — end example. If N is zero for a unary fold-expression, the value of the expression is shown in Table 14; if the operator is not specified the instantiation is ill-formed.

Table 14 — Value of folding empty sequences

| Operator | Value when parameter pack is empty |
| :--- | :--- |
| \|\| | true |
| && | false |
| | void() |

## 17.5.4 Friends [temp.friend]

A friend of a class or class template can be a function template or class template, a specialization of a function template or class, or a non-function template or class. For friend declaration that is not a template:

- if the name of the friend is qualified or unqualified template-id, the friend declaration refers to a specialization of that function template, otherwise,

- if the name of the friend is a qualified-id and a matching non-function is found in the specified class or namespace, the friend declaration refers to that function, otherwise,

- if the name of the friend is a qualified-id and a matching function template is found in the specified class or namespace, the friend declaration refers to the specialization of that template (17.8.2), otherwise,

- the name shall be an unqualified-id that declares (redeclares) a non-function template.

```cpp
[Example:

template<class T> class;
template<class T> task<T>* preempt(task<T>*);

template<class T> class task {
    friend void next_time();
    friend void process(task<T>*);
    friend task<T>* preempt(task<T>*);
    template<class C> friend func(C);
};

friend class int; {
    friend class frd;
};
```

Here, each specialization of the task template has the function next_time as a friend; because process does not explicit template-arguments, each specialization of the task template has an appropriately typed function as a friend, and this is not a function template specialization; because the friend preempt has an explicit template-argument as a friend; and each specialization of the task template has the class template specialization task<int> as a friend, and all specializations of the task template has all specializations of the function template func as friends. Similarly, each specialization of the class template frd as friends.— end example

A friend may be declared within a class or class template. A friend function may be defined within a class or class template, but a friend template may not be defined in a class or class template. In these cases, all specializations of the friend class or function template are friends of the class or template granting friendship. [Example:

```cpp
class A {
template<class T> friend class B; // OK
template<class T> friend void f() { /* ... */ } // OK
};
end example]

A template friend declaration specifies that all specializations of that template, whether they are implicitly instantiated (17.7.1), partially specialized (17.5.5) or explicitly specialized (17.7.3), are friends of the class containing the friend declaration. [Example:

```cpp
class T {
template<class T> friend struct A;
class Y { };
```
