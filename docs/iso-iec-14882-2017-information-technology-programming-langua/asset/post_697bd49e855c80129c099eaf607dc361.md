## 30.10.7 Error reporting [fs.report]

- Filesystem library functions have two overloads, one that throws an exception to report file system errors, and others that set an error_code. [Note: this supports two common use cases:
- (1.1) Uses where file system errors are truly exceptional and not necessarily represent failure. Returning an error code is the most appropriate response. This application specific error handling, including simply ignoring the error. - end note)
- 2 Functions not having an argument of type error_code handles errors as follows, unless otherwise specified:
- (2.1) When a call by the implementation to an operating system or other underlying API results in an error that prevents the function from meeting its specifications, an exception of type filesystem_error is thrown. For functions with a single argument, that argument shall be passed to filesystem_error constructor with a single argument. For functions with two arguments, the first of these arguments should be the path1, and the second should be passed as the path2. The filesystem_error constructor's error_code argument is appropriate for the operating system error.
- (2.2) Failure to allocate storage is reported by throwing an exception as described in 20.5.12.
- (2.3) Destructors throw nothing. Functions having an argument of type error_code handle errors as follows, unless otherwise specified:
- (3.1) If a call by the implementation to an operating system or other underlying API results in an error that prevents the function from meeting its specifications, the error_code argument is set as appropriate for the operating system error. Otherwise, clear() is called on the error_code argument.

## 30.10.8 Class path

An object of class path represents a path and contains a pathname (30.10.4). Such an object is concerned only with the lexical and syntactic aspects of a path. The path does not necessarily exist in external storage, and the pathname is not necessarily valid for the file system. Note: Class path is used to show the differences between string types used by different systems to represent pathnames, and to perform conversions between encodings when necessary.

```cpp
namespace std::filesystem {
class path {
public:
    using value_type = see below;
    using string_type = basic_string<value_type>;
    static const value_type preferred_separator = see below;

    // 30.10.4.1, enumeration format
    enum format;
    // 30.10.4.2, constructors and destructor
    path() noexcept;
    path(const path& p) noexcept;
    path(string_type&& source, format = auto_format);
    template <class Source>
    path(const Source& source, format = auto_format);
    template <class InputIterator>
    path(InputIterator first, InputIterator last, format = auto_format);
    template <class Source>
    path(const Source& source, const locale& loc, format = auto_format);
    template <class InputIterator>
    path(InputIterator first, InputIterator last, const locale& loc, format = auto_format);
    ~path();

    // 30.10.4.3, assignments
    path operator=(const path& p);
    path operator=(path&& p) noexcept;
    path operator=(string_type&& source);
    path assign(string_type&& source);
    template <class Source>
    path operator=(const Source& source);
    template <class Source>
    path assign(const Source& source);
    template <class InputIterator>
    path assign(InputIterator first, InputIterator last);

    // 30.10.4.4, appends
    path operator/=(const path& p);
};
```
