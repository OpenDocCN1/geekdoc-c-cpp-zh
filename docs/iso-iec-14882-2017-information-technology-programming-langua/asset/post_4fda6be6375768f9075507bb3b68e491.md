## C.1.2 Clause 6: basic concepts

[diff.basic]

## 6.1

Change: C++ does not have “tentative definitions” as in C.
Eg., at file scope,

```cpp
int i;
int i;
```

is valid in C++. This makes it impossible to define mutually referential file-local static objects, initializers restricted to the syntactic forms of C. For example,

```cpp
struct X { int i; struct X *next; };

static struct X;
static struct X b={0, ah};
static struct X c={1, bh};
```

Rationale: This avoids different initialization rules for fundamental types and user-defined types.
Effect on original feature: Deletion of semantically well-defined feature.
Difficulty of converting: Semantic transformation. In C++, the initializer for one of a mutually-referential file-local static objects must invoke a function call to achieve the initialization.
How widely used: Seldom.

## 6.3

Change: A name of scope that is explicitly declared const, and not explicitly declared extern, has internal linkage, while in C++ it would have external linkage.
Rationale: Class scope is crucial to C++, and a struct is a class.
Effect on original feature: Change to semantics of well-defined feature.
Difficulty of converting: Semantic transformation.
How widely used: C programs use extern frequently, but the change is only noticeable when struct, enumerator, or names are referred to outside the struct. The latter is rare.
[also 10.1|7](10.1.10|7)

Because const objects may be used as values during translation in C++, this feature urges programmers to provide an explicit initializer for each const object. This feature allows the user to put const objects in source files where they are included in more than one translation unit.
Effect on original feature: Change to semantics of well-defined feature.
Difficulty of converting: Semantic transformation.
How widely used: Seldom.

## 6.6.1

Change: The main function cannot be called recursively and cannot have its address taken.
Rationale: The main function may require special actions.
Effect on original feature: Deletion of semantically well-defined feature.
Difficulty of converting: Trivial: an intermediary function such as mymain(argc, argv).
How widely used: Seldom.

## 6.9

Change: C allows “compatible types” in several places, C++ does not.

For example, otherwise-identical types with different tag names are "compatible" in C but are distinctly different types in C++.
Rationale: Stricter typing is essential for C++.
Effect on original feature: Deletion of semantically well-defined feature.
Difficulty of converting: Semantic transformation. The "typesafe linkage" mechanism will find many, but not all, of problems. These problems not found by typesafe linkage will continue to function properly, according to the "layout compatibility rules" of this document.
How widely used: Common.

## C.1.3 Clause 7: standard conversions [diff:conv]

### 7.11
Change: Converting void* to a pointer-to-object requires casting.

```cpp
char a[10];
void* b;
void foo() {
    char* c;
}
```

ISO C will accept the use of void for being assigned to a pointer to object type. C++ will not.
Rationale: C++ harder than C to enforce compile-time type safety.
Effect on original feature: Deletion of semantically well-defined feature.
Difficulty of converting: Could be automated. Violations will be diagnosed by the C++ translator.
The fix is to cast it: For example:
```cpp
char* c = (char*)b;
```

How widely used: This is widely used but it is good practice to add the cast when assigning pointer-to-void to pointer-to-object. Some C compilers will give a warning if the cast is not used.

## C.1.4 Clause 8: expressions [diff:expr]

### 8.2.2
Change: Implicit declaration of functions is not allowed.
Rationale: The type-safe nature of C++.
Effect on original feature: Deletion of semantically well-defined feature. Note: the original feature was labeled as "obsolete" in ISO C.
Difficulty of converting: Syntactic transformation. Facilities for producing explicit function declarations are fairly widespread commercially.
How widely used: Common.

### 8.2.6, 8.3.2
Change: Decrement operator is not allowed with bool operand.
Rationale: With surprising semantics.
Effect on original feature: A ISO C expression or cast expression the decrement operator on a bool value (for instance, via the C typed in <stdbool.h>) is ill-formed in this International Standard.

### 8.3.3, 8.4
Change: Types must be defined in declarations, not in expressions.
In C, a sizeof expression or cast expression may define a new type. For example,
```cpp
pp = (void*)(struct x { int i; }) * 0;
```
defines a new type, struct x.
Rationale: This prohibition helps to clarify the location of definitions in the source code.

Effect on original feature: Deletion of semantically well-defined feature.
Difficulty of converting: Semantic transformation.
How widely used: Common.

## C.1.6 Clause 10: declarations [diff:dcl]

### 10.1
Change: In C++ a decl-specifier must contain a type-specifier, unless it is followed by a declarator for a
Rationale: Class scope is crucial to C++, and a struct is a class.
Effect on original feature: Change to semantics of well-defined feature.
Difficulty of converting: Semantic transformation.
How widely used: C programs use extern frequently, but the change is only noticeable when struct, enumerator, or names are referred to outside the struct. The latter is rare.

### 10.1.1
Change: Banning implicit int.
In C++ a decl-specifier must contain a type-specifier, unless it is followed by a declarator for a
constructor, destructor, or a conversion function. In the following example, the left-hand column presents valid C; the right-hand column presents invalid C:

```cpp
void f(const int param);      void f(const int param);
const n = 3;                      const int n = 3;
main()                             int main()
  /* ... */                          /* ... */ /
```
