## 6.4.3.2 Namespace members

- 1 If the nested-name-specifier of a qualified-id nominates a namespace (including the case where the nested-name-specifier is :: i.e., nominating the global namespace), the name after the nested-name-specifier is looked up the scope of the namespace. The names in a template-argument of a template-id are looked up in the context in which the entire postfix-expression occurs.

- 2 For a namespace X and name m, the namespace-qualified lookup set S(X,m) is defined as follows: Let S'(X,m) be the set of all declarations of m in X and the inline namespace set of X (10.3.1). If S'(X,m) is not empty, S(X,m) is S'(X,m); otherwise, it is the union of S(Ni, m) for all namespaces Ni nominated by using--directives in X and its inline namespace set.

- 3 Given X:: (where X is a user-declared namespace), or given ::m (where X is the global namespace), if S(X,m) has exactly one member, or if the context of the reference is a well-formed the program is ill-formed. Otherwise, if the use of m is a using-declaration (10.3.3), S(X,m) is the required set of declarations of m. Otherwise if the use of m is not one that allows a unique declaration to be chosen from S(X,m), the program is ill-formed. [Example:

```cpp

  int b;

  B::a++; // OK: both A and B searched (once), S is {A::a}

During the lookup of a qualified namespace name, the lookup finds more than one declaration of the member, and if one declaration introduces a class name or enumeration name and the other declarations either introduce the same variable, the same enumerator or a set of functions, the non-type name hides the class or enumeration name if and only if the declarations are from the same namespace; otherwise (the declarations are from different namespaces), the program is ill-formed. Example:
```cpp
namespace A {
  struct x { };
  int x;
  int y;
}

namespace B {
  struct y { };
}

namespace C {
  using namespace A;
  using namespace B;
  int i = C::x; // OK, A::x (of type int)
  int j = C::y; // ambiguous, A::y or B::y
} // end example;
```

## 6.4.4 Elaborated type

- 1 An elaborated-specifier (10.7) may be used to refer to a class name or enum-name
the nested-name-specifier is the initial part of the nested-name-specifier.

- 2 If the elaborated-specifier is a declaration with the following form:
```cpp
nested-name-specifier unqualified-id
```
the unqualified-id shall name a member of the namespace designated by the nested-name-specifier or of
element of the namespace set (10.3.1). [Example:
```cpp
namespace A {
    namespace B {
        void f1(int);
    }
    using namespace B;
    void A1::f1(int) // ill-formed, f1 is not a member of A
} -- example] However, in such namespace member declarations, the nested-name-specifier may rely on
using-directives to implicitly provide the initial part of the nested-name-specifier. [Example:
```cpp
namespace A {
    namespace B {
        void f1(int);
    }
}
namespace C {
    namespace D {
        void f1(int);
    }
}
using namespace A;
using namespace C::D;
void B::f1(int) {} // OK, defines A::f1
} // example
```

- 3 If the elaborated-specifier is a using-declaration (10.3.3), the elaborated-specifier is the required set
of declarations of the name. Otherwise if the use of the name is not one that allows a unique declaration to be
chosen from the lookup set, the program is ill-formed.

## 6.4.5 Class member access

- 1 In a class member access (8.2.5), if the . or -> is immediately followed by an identifier followed by a list, the identifier is looked up to determine whether the < is the beginning of a template argument list (17.2) or a less-than operator. The identifier is looked up in the context of the class of the object. If the identifier is not found, it is then looked up in the context of the entire postfix-expression and shall claim a class name.

- 2 If the id-expression in a class member (8.2.5) is an unqualified-id, and the type of the object expression is of a class C, the unqualified-id is looked up in the scope of class C. For a pseudo-destructor call (8.2.4), the unqualified-id is looked up in the context of the entire postfix-expression.
If the id-expression is a -type, the name is looked up in the context of the entire postfix-expression. If the type T of the object expression is of a class C, the type-name is also looked up in the scope of class C. At least one of the lookups shall find a name that refers to cv T. Example:

```cpp
struct B {
    struct A;
    void f(::A* a);
};

void B::f(::A* a) {
    a->A();
} // OK: lookup in *a finds the injected-class-name
```

- end example
