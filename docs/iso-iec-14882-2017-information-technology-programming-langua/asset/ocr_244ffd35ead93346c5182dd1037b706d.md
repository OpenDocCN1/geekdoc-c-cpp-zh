# 6.4.3.1 Class members

+   1 If the nested-name-specifier of a qualified-id nominates a class, the name specified by the nested-name-specifier is looked up in the scope of the class (13.2), except for the cases listed below. The name shall represent one or more members of class or one of its classes (Clause 13. Note: A class member can be referred to as a qualified-id at any potential scope (6.3.7). The exceptions to the name lookup rule are as follows:

+   (1.1) the lookup for a destructor is described in 6.4.3;
(1.2) a conversion-type of a conversion-function is looked up in the same manner as a conversion-type in a class member access (see 6.4.5);
(1.3) the lookup for a name specified in a template-argument (10.3.3) also finds class or enumeration names hidden within the same scope (6.3.10);
(1.4) the lookup for a name specified in a using-declaration (10.3.3) that is a member-declaration, also finds class or enumeration names

+   2 In a lookup which function names are not ignored 84 and the nested-name-specifier nominates a class C:
(2.1) if the same name-specifier, when looked up in C, is the injected-class-name of C (Clause 12),
(2.2) in a using-declaration-of using (10.3.3) that is a member-declaration, if the name specified after the nested-name-specifier is the same as the identifier or the simple-template-id's template-name in the last component of the nested-name-specifier, the name is considered to be constructor of class C. Note: For example, the name is not an acceptable result in an elaborated-type-specifier the constructor would not be used in place of the injected-class — end note). Such a constructor shall be used only in the declarator-id of a constructor or in a using-declaration. Example:
