# 15.2 Temporary objects [class.temporary]

+ 1 Temporary objects created
    - when a value is materialized so that it can be used as a value (7.4),
    - when needed by the implementation to pass or return an object of trivially-copyable type (see below),
    - when throwing an exception (18.1). [Note: The lifetime of exception objects is described in 18.1. — end note]

Even when the creation of the temporary object is unevaluated (Clause 8), all the semantic restrictions shall be respected if the object had been created and destroyed. [Note: This includes accessibility (Clause 14) and whether it is deleted, for the constructor selected and for the destructor. However, in the special case of the operand of a delete-specifier (8.2.2), no temporary is introduced, the following does not apply to a prvalue. — end note]

+ 2 The materialization of a temporary object is generally deferred as long as possible in order to avoid unnecessary temporary objects. [Note: Temporary objects are materialized:

    - when performing member access on a class prvalue (8.2.5, 8.5),
    - when performing an array-to-pointer conversion or subscribing on an array prvalue (7.2, 8.2.1),
    - for initializing an object of type std::initializer_list<T> from a braced-init-list (11.6.4),
    - for certain unevaluated operands appears as a discarded-value expression (Clause 8).

+ 3 When an object of type X is passed or returned from a function, if X is deleted or if at least one non-deleted copy or move constructor exists, implementations are permitted to create a copy to hold the function argument or result. The temporary to which the reference is bound persists for the lifetime of the reference — note

+ 4 When an implementation introduces an object of a class that has a non-trivial constructor (15.1, 15.8), temporary objects are destroyed in the full-expression (4.6) that contains the points where they are created. This is true even if evaluation ends throwing an exception. There are three contexts in which a temporary is destroyed before the end of the full-expression. The first context is when a temporary is called to initialize an element of an array (11.6). The second context is when a copy constructor is called to copy an element of an array (15.2, 15.8). In either case, if the constructor has one or more default arguments, the destruction of every temporary created in a default argument is sequenced before the construction of next element, if any.

+ 6 The third context is when a reference is bound to a temporary.¹¹⁶ The temporary to which the reference is bound is not extended except

    (6.1) A temporary object bound to a reference parameter in a function call (8.2.2) persists until the completion of the full-expression containing the call.
    (6.2) The lifetime of a temporary bound to the returned value in a function return statement (9.6.3) is not extended; the temporary is destroyed at the end of the full-expression in the return statement.
    (6.3) A temporary bound to a reference in a new-initializer (8.3.4) persists until the completion of the full-expression containing the new-initializer. [Example]:

```cpp
struct S { int mi; const std::pair<int,int>& m; };
S a {1, {2, 3}};
S* p = new S(1, 2); // dangling reference
```
