## 12.2.5 Nested class declarations [class.next]

1 A class can be declared within another class. A class declared within another is called a nested class. The name of the nested class is local to its enclosing class. [Note: See 8.1] for restrictions on the use of non-static data members and non-static member functions. — end note

Example:

```cpp
int x;
int y;

struct enclose {
  int x;
  static int s;

  struct inner {
    void f(int i) {
      int a = sizeof(x); // OK: operand of sizeof is an unvaluated operand
      x = i; // error: assign to enclose::x
      s = i; // OK: assign to enclose::s
      y = i; // OK: assign to global x
      // OK: assign to global y
    }

  void g(enclose* p, int i) {
    p->x = i; // OK: assign to enclose::x
  }
};

inner* p = 0; // error: inner not in scope
```
end example

2 Member functions and static data members of a nested class can be defined in a namespace scope enclosing the definition of their class. [Example:]

```cpp
struct enclose {
    struct inner {
        static int x;
        void f(int i);
    };
};
int enclose::inner::x = 1;

void enclose::inner::f(int i) { /* ... */ }
```
end example

3 If X is defined in a namespace scope, a nested class Y may be declared in namespace X and later defined in the definition of class X or later defined the definition of class X. [Example:]

```cpp
class E { // declaration of nested class
    class I;
    class II;
    class III { }; // definition of nested class
};
class E::II { : I }; // definition of nested class
```
end example

4 Like a member function, a friend function [14.3] defined within a nested class is in the lexical scope of class; it obeys the same rules for binding as a static member function of class [12.2.3], but it has no special access to members of an enclosing class.

## 12.2.6 Nested type names [class.nested.type]

1 Type names obey the same scope as other names. In particular, type names defined within a class definition cannot be used without class qualification. [Example:]

```cpp
struct X {
    typedef int I;
    class Y { /* ... */ };
    I a;
};

b; // error
Y c; // error
X::Y d; // OK
X::I e; // OK
```
end example

## 12.3 Unions [class.union]

1 In a union, a static data member is active if its name refers to an object whose lifetime has begun and has not ended (6.8). At most one of the non-static data members of an object of union type can be active at any time, that is, at most one of the non-static data members can be stored in a union at any time. [Note: One special guarantee is made in order to simplify the use of unions: if a standard-layout union contains several standard-layout structs that share a common initial sequence (12.2), and if a non-static member of an object of this standard-layout union type is active and is one of the standard-layout structs, it is permitted to inspect the initial sequence of any standard-layout struct members; see 12.2— end note]

The size of a union is sufficient to contain the largest of its non-static data members. Each non-static data member is allocated as if it were the sole member of a struct. [Note: A standard-layout union and its non-static data members are pointer-interconvertible (6.9.2, 8.2.9)]. As a consequence, all non-static data members of such a union have the same address.—end note]

A union can have member functions (including constructors and destructors), but it should not have virtual (13.3) functions. A union shall not have base classes. A union shall not be used as a base class. If a union contains a non-static data member of reference type the program is ill; [Note: Absent member initializes (12.2), if any non-static data member of a union has a non-trivial default constructor (15.1), copy constructor (15.8), move constructor (15.8), copy assignment operator (15.8), move assignment operator (15.8), or destructor (15.8), the corresponding function of the union must be user-provided—or it will be implicitly defined (11.4.3) for the union.—end note]

## 12.3.1 Anonymous unions [class.union.anon]

1 A union of the form

```cpp
union { int a; const char* p; };
```

is called an anonymous union; it defines an unnamed type and an unnamed object of that type. Each member-declaration in the member-specification of an anonymous union shall either define non-static data member or be a static *assert-declaration*. [Note: Nested types, anonymous functions cannot be declared within an anonymous union. — end note] The names of members of anonymous union shall be distinct from the names of any other entity in the scope in which the anonymous union is declared. For the purpose of name lookup, after the anonymous union definition, the members of the union are considered to have been defined in the scope in which the anonymous union is declared. [Example:

```cpp
void f() {
    union { int a; const char* p; };
    a = 1;
    p = "*";
}
```
Here a and p are used like ordinary (non-member) variables, but since they are members they have the same address. — end example

2 Anonymous unions declared in a named namespace or in the global namespace shall be static. Anonymous unions declared at block scope shall be declared with any storage class for a block-scope variable, or with no storage. A storage class is not allowed in a declaration of an anonymous union in a block scope. An anonymous union shall not have private or protected members (Clause 14). An anonymous union should not have member functions.

3 A union for which objects, pointers, or references are declared is not an anonymous union. [Example:

```cpp
void f() {
    union { int a; char* p; } *ptr = &obj;
    a = 1;                        // error
    ptr->a = 1;                               // OK
}
```
