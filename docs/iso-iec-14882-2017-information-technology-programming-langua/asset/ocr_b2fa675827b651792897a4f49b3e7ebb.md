The carries dependency on function f means that the return value carries a dependency out of f, so that the implementation need not constrain ordering upon f. Implementations of f and its caller may preserve dependencies instead of emitting hardware memory order instructions (a.k.a. fences). Function g's second parameter has a carries_dependency attribute, but its first parameter does not. Furthermore, f's first call to g carries a dependency into g, but its second call does not. # 10.6.5 Fallthrough attribute

+   1 attribute-token fallthrough may be applied to a null statement (9.2); such statement is a fallthrough statement. The statement shall appear at most once in each attribute-list and no attribute-argument-clause shall be. A fallthrough statement may only appear within an switching statement whose label is a case or default label for the same switch statement. The program may be ill-formed if there is no such statement.

+   2 [Note: The use of a fallthrough statement is intended to suppress a warning that an implementation might otherwise issue for a case or default label that is reachable from another case or default label along path of execution. Implementations should issue a warning if a fallthrough statement is not dynamically. — end note]
