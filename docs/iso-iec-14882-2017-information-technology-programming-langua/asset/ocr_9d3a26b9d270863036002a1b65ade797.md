Names not covered by these rules have no linkage. Moreover, except as noted, a name declared at scope (6.3.3) has no linkage. A type is said to have linkage if and only if

+   (8.1) it is a class or enumeration type that is named (or has a name for linkage purposes (10.1.3)) and has its name linkage; or

+   (8.2) it is an unnamed class or enumeration that is a member of a class with linkage; or

+   (8.3) it is a specialization of a class template (Clause 17)5; or

+   (8.4) it is a fundamental type (6.9.1); or

+   (8.5) it is a compound type (6.9.2) other than a class or enumeration, compounded exclusive types that have linkage; or

+   (8.6) it is a cv-qualified (6.9.3) version of a type that has linkage.

A type without linkage is not used as the type of a variable or function with external linkage unless

+   (8.7) the entity is not od-used (10.5), or

+   (8.8) the entity is declared within an unnamed namespace (10.3.1), or

+   (8.9) the entity is not od-used or defined in the translation unit.

> [Note: A type without linkage contains a class or enumeration that cannot be named outside its translation unit. An entity with external linkage declared using such a type could correspond to any other entity in another translation unit of the program and must be defined in the translation unit if it is od-used. Note that classes with linkage may contain members whose types do not have linkage, and typedef names are ignored in the determination of whether a type has linkage. — end note]

[Example:

```
template <Class T> struct B {
    void gT();
    void hT();
    friend void i(B, T) {}
};
void f() {
    struct A { int x; }; // no linkage
    A a = { 1 };
    B<A> ba; // declares B<A>::g(A) and B<A>::h(A)
    // OK
    ba.ga(a); // error: B<A>::h(A) not defined in the translation unit
    i(ba, a); // OK
}
// end example]

```
