# ISO/IEC 14882:2017(E)

# 16.5.8 User-defined literals

literal-operator-id:
operator user-defined-string-literal

+   1 The *string-literal* or *user-defined-string-literal* in a *literal-operator-id* shall have no encoding-prefix and shall contain no characters other than the terminating '\0'. The *ud-suffix* of the user-defined-string-literal or the identifier in a literal-operator-id is called a *literal suffix*. Some literal suffixes are reserved for future standardization; see 20.5.4.3.5. A function declared with a literal-operator-id uses such literal suffix is ill-formed, no diagnostic required.

+   2 A declaration whose literal-operator-id shall be a declaration of a namespace-scope function or function template (which can be a friend function [14.3]), an explicit instantiation or specialization of a function template, or a using-declaration [10.3.3]). A function declared with a literal-operator-id is a literal function. A function template declared with a literal-operator-id is a literal operator template.

+   3 The declaration of a literal operator shall have a *parameter-declaration-clause* equivalent to one of the following:

```
const char*
unsigned long int
double
char
wchar_t
char16_t
char32_t
const char*, std::size_t
const wchar*, std::size_t
const char16_t*, std::size_t
const char32_t*, std::size_t
```

If a parameter has a default argument [11.3.6], the program is ill-formed.

+   4 A literal operator shall have a single parameter with type is *const char*.

+   5 The declaration of a literal template shall have an empty *parameter-declaration-clause* and the *template-parameter-list* shall have a single template-parameter that is a non-type template parameter pack [17.5.3] with element type char.

+   6 Literal operators and literal operator templates are implicitly invoked through user-defined literals (5.13.8).

+   7 [Note: However, for the constraints described above, they are ordinary namespaces-scope functions and templates. In particular, they are looked up like ordinary functions and templates they follow the same overload resolution rules. Also, they can be declared inline or constexpr, and have internal or external linkage, they can be called explicitly, their addresses can be taken, — end note]

+   8 [Example]:

```
void operator **= *long(double);
// OK
string operator ** = *int18(const char*, std::size_t);
// OK
template<char _> operator ** = ('\u0330');
// OK: UCN for lowercase pi
// OK
float operator * = (const char);
// error: reserved literal suffix (50.5.4.3.5, 5.13.8)
double operator**= _Bq(long double);
// OK: does not use the reserved identifier _Bq (5.10)
double operator**= _Bq(long double);
// uses the reserved identifier _Bq (5.10)
float operator * = _B(const char);
// error: non-empty-string literal
string operator ** = SX(const char*, std::size_t);
// error: invalid literal suffix identifier
```
