# ISO/IEC 14882:2017(E)

# 8 Expressions [expr]

+   1 [Note: Clause 8 defines the syntax, order of evaluation, and meaning of expressions. An expression is a sequence of operators and operands that performs a computation. An expression can result in a value and cause side effects. — end note]

+   2 [Note: Operators can be overloaded, that is when applied to expressions of class type (Clause 12) or enumeration type (10.2). Use of overloaded operators are transformed into function calls as described in 16.5. Overloaded operators follow the rules and evaluation order specified in Clause 8, but relations between operands of different type as += are not guaranteed for overloaded operators — end note]

Clause 8 defines the effects of operators when applied to types which have not been overloaded. Operator overloading does not modify the built-in operators, that is, for operators applied to types for which built-in operators operate in resolution, and if by part of process user-defined conversions will be considered necessary to convert the operands to their type, the behavior is undefined. If a built-in operator is selected, such conversions will be applied to the operands before the operation is considered further according to the rules in Clause 8; 16.3.1, 16.2.6.

If the evaluation of an expression result is not mathematically defined or not in the range of representative values for its type [Note: Treatment of division by zero, forming a remainder value using a divisor, and all floating-point exceptions vary much, and is sometimes adjustable by a library function. — end note]

5 If an expression has a type “reference to T” (11.3.2, 11.6.3), the type is adjusted to T prior to any further analysis. The expression designates the object or function denoted by the reference, and the expression is an lvalue or xvalue, depending on the type.[Note: Before the lifetime of the reference has started or after it has ended, the behavior is undefined (see 6.8). — end note]

6 If a prvalue initially has type “const T”, where T is a cv-unqualified non-class, non-array type, the type of the expression is adjusted to T prior to any analysis.

+   7 [Note: An expression is an xvalue if it is:

+   (7.1) the result of calling a reference to object type,

+   (7.2) a cast to an rvalue reference to object type,

+   (7.3) a member access expression designating a non-static data member of non-reference type in which the expression is an xvalue, or

+   (7.4) a .pointer-member expression in which the first operand is an xvalue and the second operand is a pointer to data member.

In general, the effect of this rule is named that rvalue references are treated as lvalues and unnamed rvalue references to functions are treated as xvalues whether they are named or not. — end note]
