# 26.5.4.2 unordered_map constructors

```
unordered_map() : unordered_map(size_type n see below) {
explicit unordered_map(size_type n,
    const hasher& h = hasher(),
    const key_eq& eq = key_equal(),
    const allocator& a = allocator());
```

+   1 Effects: Creates an unordered_map using the specified hash function, key equality predicate, and allocator, and using at n buckets. For the default, the constructor of buckets is implementation-defined. max_load_factor() returns 1.

+   2 Complexity: Constant.

```
template <class InputIterator>
unordered_map(InputIterator first, InputIterator last,
    size_type n = see below,
    const hasher& h = hasher(),
    const key_eq& eq = key_equal(),
    const allocator& a = allocator());
unordered_map(initializer_list<value_type> it, int il,
    size_type n = see below,
    const hasher& h = hasher(),
    const key_eq& eq = key_equal(),
    const allocator& a = allocator());
```

+   3 Effects: Creates an unordered_map using the specified hash function, key equality predicate, and allocator, and using at n buckets. If is not provided, the number of buckets is implementation-defined. It inserts elements from the range [f, r) for the first, or from the range [il.begin(), il.end()) for the second for. max_load_factor() returns 1.

+   4 Complexity: Average linear, worst case quadratic.

# 26.5.4.3 unordered_map element access

```
mapped_type& operator[] (const key_type& k);
```

+   1 Effects: Equivalent to: return_emplace(k).first->second;

```
mapped_type& operator[] (key_type&& k);
```

+   2 Effects: Equivalent to: return_emplace(move(k)).first->second;
