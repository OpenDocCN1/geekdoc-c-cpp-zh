# C.2.2 Clause 7: standard conversions

[diff.cpp03.conv]

7.11

Change: Only literals are integer null pointers.
Rationale: Removing surprising interactions with templates and constant expressions.

Effect on original feature: Valid C++ 2003 code may fail to compile or produce different results in this International Standard, as the following example illustrates:

```
void f(void); // #1
void f(...); // #2
template<int T> void g() {
    f(0); // calls #2; to be called as #1
}
```

# C.2.3 Clause 8: expressions

[diff.cpp03.expr]

8.6

Change: Specify rounding for results of integer / %.
Rationale: Increase portability, C99 compatibility.

Effect on original feature: Valid C++ 2003 code that uses integer division rounds the result towards 0 or negative infinity, whereas this International Standard always rounds the result towards 0.

8.14

Change: && is valid in a type-name.
Rationale: Required for new features.

Effect on original feature: Valid C++ 2003 code may fail to compile or produce different results in this International Standard, as the following example illustrates:

```cppbool b1 = int && false; // previously false, ill-formed
struct S { operator int(); };
bool b2 = &S::operator&& false; // previously false, ill-formed
```

# C.2.4 Clause 10: declarations

[diff.cpp03.dcl]

10.1

Change: Remove auto as a storage class specifier.
Rationale: New features.

Effect on original feature: Valid C++ 2003 code that uses the keyword auto as a storage class specifier may be invalid in this International Standard. In this International Standard, auto indicates that the type of a variable is to be deduced from its initializer expression.

# C.2.5 Clause 11: declarators

[diff.cpp03.dcl]

11.6.4

Change: Narrowing restrictions in aggregate initializers.
Rationale: Catches bugs.

Effect on original feature: Valid C++ 2003 code may fail to compile in this International Standard. For example, the following code is valid in C++ 2003 but invalid in this International Standard because double is to be an int:

```cppint x = { 2.0 };
```

# C.2.6 Clause 15: special member functions

[diff.cpp03.special]

15.1, 15.4, 15.8

Change: Implicit-declared special member functions are defined as deleted when the implicit definition would have been ill-formed.

Rationale: Improves template argument deduction failure.

Effect on original feature: A valid C++ 2003 program that uses one of these special member functions in a context where the definition is not required (e.g., in an expression that is not potentially evaluated) becomes ill-formed.

# 15.4 (destructors)

Change: User-declared destructors have an implicit exception specification.

Rationale: Clarification of destructor requirements.

Effect on original feature: Valid C++ 2003 code may execute differently in this International Standard. In particular, those that throw exceptions call `std::terminate` (without calling `std::unexpected`) if their exception specification is not-throwing.

# C.2.7 Clause 17: templates [diff.cpp03.temp]

# 17.1

Change: Remove export.

Rationale: No implementation consensus.

Effect on original feature: A valid C++ 2003 declaration containing `export` is ill-formed in this International Standard.

# 17.2

Change: Remove whitespace for nested template template angle brackets.

Rationale: Considered a persistent but minor annoyance. Templates representing non-class types would exacerbate whitespace issues.

Effect on original feature: Change to semantics of well-defined. A valid C++ 2003 expression containing a right angle bracket (`>`) followed by another right angle bracket may be treated as two templates. For example, the code in C++ 2003 because `>>` is the right shift operator, invalid in this International Standard because `>>` closes templates.

```cpp
template <class T> struct Y {
  int<class B> y;
  X V y = 1 >> 2;
};
```

# 17.6.4.2

Change: Allow default of templates with internal linkage.

Rationale: Over constrained, simplify overload rules.

Effect on original feature: A valid C++ 2003 program could get a different result than this International Standard.

# C.2.12 Clause 24: strings [diff.cpp03.strings]

24.3

Change: basic string requirements no longer allow reference-counted strings.
Rationale: Invalidation is costly with reference-counted strings. This change regularizes behavior in this International Standard.
Effect on original feature: Valid C++ 2003 code may execute efficiently in this International Standard.

24.3.2.1
Change: Loose basic_string invalidation rules.
Rationale: Allow small-string optimization.
Effect on original feature: Valid C++ 2003 code may execute differently in this International Standard. Some constant members, such as data and c_str, no longer invalidate iterators.

# C.2.13 Clause 26: containers [diff.cpp03.containers]

26.2
Change: Complexity of size() member function remains constant.
Rationale: Lack of specification of size() resulted in divergent implementations with inconsistent performance characteristics.
Effect on original feature: Some container implementations that conform to C++ 2003 may not conform to the specified size() requirements in this International Standard. Adjusting containers such as std::list may require incompatible changes.

26.2
Change: Requirements change: relaxation.
Rationale: Clarification.
Effect on original feature: Valid C++ 2003 code that attempts to meet the specified container requirements may now be over-specified.
