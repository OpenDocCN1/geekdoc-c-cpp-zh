# 20.5.2 Using the library [using.overview]

# 20.5.2.1 Overview

+   1 This describes how a C++ program gains access to the facilities of the C++ standard library. 20.5.2.2 describes effects during phase 4, 20.5.2.3 describes effects during phase 8 (5.2).

# 20.5.2.2 Headers [using.headers]

+   1 The entities in the C++ standard library are defined in headers, whose contents are available to a translation unit when it contains the include processing directive (19.2).
2 A translation unit may include library headers in any order (Clause 5). It may be included more than once, with no effect from being included exactly once, except that the effect of either <cassert> or assert.h depends each time on the current definition of NDEBUG.¹173
3 A translation unit should include a header only after any declaration or definition, and should include the header lexically before the first reference in that translation unit to any of the entities declared in that header. No diagnostic is required.

# 20.5.2.3 Linkage [using.linkage]

+   1 Entities in the C++ standard library have external linkage (6.5). Unless otherwise specified, objects and functions have the default external "C" (10.5).
2 Whether a C standard library entity declared with external linkage have extern "C" or extern "C++" linkage is implementation-defined. It is recommended that an implementation use "C++" linkage for this purpose.¹174

+   3 Objects and functions defined in the library and required by a C++ program are included in the program prior to startup.

+   4 See also replacement functions (20.5.4.6), runtime changes (20.5.4.7).

173) This is the same as that

174) The only way to declare an object or function signature for the C standard library is by including the header that declares it, notwithstanding the latitude granted in 7.1.4 of the C Standard.
