# 8.1.5 Closure

1 The type of a lambda-expression (which is the type of the closure object) is unique, non-union type class, the closure type, properties are described below

2 The closure type is declared by the smallest scope, class, or namespace that contains the corresponding lambda-expression. [Note: This determines the sets of namespaces and classes associated with the closure. (6.4.2)] The closure type is not an aggregate type (11.6.1). An implementation may define the closure type differently from what is described below this does not allow the observable behavior of the program other changing by:

+   (2.1) the size and alignment of the closure type,
(2.2) whether the closure type is trivially copyable (Clause 12)
(2.3) whether the closure type is a standard-layout class (Clause 12),
(2.4) whether the closure type is a POD class to the closure type.

An implementation shall not add members of reference type to the closure type.

3 The type for a non-generic lambda-expression has a public inline call operator (16.5.4) whose parameters and return type are described by the lambda-expression's parameter-declaration-clause and trailing-return-type. For a generic lambda, the closure type has a public inline call operator template (17.5.2) whose template-parameter-list consists of one invented template-parameter for each auto in the lambda's parameter-declaration-clause, in appearance. The invented template-parameter is a parameter pack if the corresponding parameter-declaration-clause returns from the function operator derived from the expression's trailing-return-type and parameter-declaration-clause by replacing each auto in the decl-specifiers of the parameter-declaration-clause with the name of the corresponding invented template-parameter. Example:

```
auto lambda = [](auto a, auto b) { return a < b; }; // OK
bool b = lambda(3, 3.14)
```
