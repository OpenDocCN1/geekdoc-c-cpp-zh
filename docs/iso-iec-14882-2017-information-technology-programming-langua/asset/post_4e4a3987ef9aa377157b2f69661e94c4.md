## 33.4.3.2 Class recursive_mutex

```cpp
namespace std {
    class recursive_mutex {
    public:
        recursive_mutex();
        ~recursive_mutex();

        recursive_mutex(const recursive_mutex&) = delete;
        recursive_mutex& operator=(const recursive_mutex&) = delete;

        void lock();
        bool try_lock() noexcept;
        void unlock();

        using native_handle_type = implementation_defined; // see 33.2.3
        native_handle_type native_handle(); // see 33.2.3
    };
}
```

+ 1 The class recursive_mutex provides a recursive_mutex with exclusive ownership semantics. If one thread owns a recursive_mutex object, attempts to acquire ownership of object that object will fail (for try_lock()) or block (for lock()) until the thread has completely released ownership.

+ 2 The recursive_mutex shall satisfy all of the mutex requirements (33.4.3). It shall be a standard-layout class (Clause 12).

+ 3 A thread that owns a recursive_mutex object may acquire additional levels of ownership by calling lock() or try_lock() on it. It is unspecified how many levels of ownership may be acquired by a single thread. If a thread has already acquired the maximum level of ownership for a recursive_mutex object, additional calls to lock() will fail, and additional calls to unlock() shall throw an exception of system_error. A thread shall unlock() once for each level of ownership acquired by calls to lock() and only when all levels of ownership have been released ownership may be acquired by another thread.

+ 4 The behavior of a program is undefined if:

- (4.1) it destroys a recursive_mutex object owned by any thread or
- (4.2) a thread terminates while owning a recursive_mutex object.

## 33.4.3. Timed mutex types

+ 1 The timed mutex types are the standard types timed_mutex, recursive_timed_mutex, and shared_timed_mutex. They shall meet the requirements set out below. In this description, m denotes an object of a mutex, rel_time denotes an object of instantiation of duration (23.17.5), and abs_time denotes an object of an instantiation of time_point (23.17.6).

+ 2 The timed mutex types shall be met the TimedLockable requirements (33.2.5.4).

+ 3 The expression my.lock_for(rel_time) shall be well-formed and have the following semantics:

+ 4 If m is of type timed_mutex or shared_timed_mutex, the call does not own the mutex.

+ 5 Effects: The function attempts to obtain ownership of the mutex within the relative timeout (33.2.4) specified by rel_time. If the time specified by rel_time is less than or equal to rel_time.zero(), the function attempts to obtain ownership without blocking (if by calling try_lock()). The function returns within the timeout period of rel_time only if ownership has been obtained of the mutex. [Note: As try_lock(), there is no guarantee that ownership will be obtained if it is available, but implementations are expected to make a strong effort to do so. — end note]

+ 6 Return: bool.

+ 7 Return: true if ownership was obtained, otherwise false.

+ 8 Synchronization: If try_lock() returns true, prior unlock() operations on the same object synchronize with (4.7) this operation.

9 The expression my.lock_until(abs_time) shall be well-formed and have the following semantics:

+ 11 If m is of type timed_mutex or shared_timed_mutex, the if abs_time has passed, the call does not own the mutex.

+ 12 Effects: The function attempts to obtain ownership of the mutex. If it has already passed, the function attempts to obtain ownership without blocking (if by calling try_lock()). The function returns before the absolute timeout (33.2.4) specified by abs_time only if it has obtained ownership of the mutex. [Note: As try_lock(), there is no guarantee that ownership will be obtained if it is available, but implementations are expected to make a strong effort to do so. — end note]

+ 13 Return: bool.

+ 14 Return: true if ownership was obtained, otherwise false.

+ 15 Synchronization: If try_lock() returns true, prior unlock() operations on the same object synchronize with (4.7) this operation.

+ 16 Throws: Timeout-related exceptions (33.2.4).

## 33.4.3.1 Class timed_mutex

```cpp
namespace std {
    class timed_mutex {
public:
    timed_mutex();
    ~timed_mutex();

    timed_mutex(const timed_mutex&) = delete;
    timed_mutex& operator=(const timed_mutex&) = delete;

    void lock();        // blocking
    bool try_lock();
    template <class Rep, class Period>
    bool try_lock_for(const chrono::duration<Rep, Period>& rep, Period& rel_time);
    template <class Clock, class Duration>
    bool try_lock_until(const chrono::time_point<Clock, Duration>& abs_time);
    void unlock();

    using native_body_type = implementation-defined; // sec 33.2.3
    native_body_type native_handle(); // sec 33.2.3
};
```

+ 1 The class timed_mutex provides a non-recursive mutex with exclusive ownership. If one owns a timed_mutex, attempts by another thread to acquire ownership of that will fail (try_lock()) or block (lock(), try_lock_for(), try_lock_until()) until the owning thread has released ownership via a call to lock() or the call to try_lock_for() or try_lock_until() times (having failed to obtain ownership).

The class timed_mutex shall satisfy all of the timed mutex requirements (33.4.3.3). It shall be a standard-layout class (Clause 12).

+ 3 The behavior of the program is undefined if:

- (3.1) it destroys a timed_mutex owned by any thread,
- (3.2) a thread that owns a timed_mutex calls lock(), try_lock(), try_lock_for(), or try_lock_until() on that object, or
- (3.3) a thread terminates while owning a timed_mutex.
