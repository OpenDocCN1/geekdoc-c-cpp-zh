# 19.3.1 Argument substitution [cpp.subst]

+   1. After the arguments for the invocation of a function-like macro have been identified, argument substitution takes place. A parameter in the replacement list, unless preceded by a # or followed by a ## preprocessing token (see below), is replaced by the corresponding argument after all macros have been replaced. Before being substituted, each argument's preprocessing tokens are completely remapped if they match the rest of the replacement: no preprocessing tokens are available.

+   2. An identifier __VA_ARGS__ that occurs in the replacement list should be treated as if it were a parameter, and the variable arguments should form the preprocessing tokens used for.

# 19.3.2 The # operator [cpp.string]

+   1. Each # preprocessing in the replacement list for a function-like macro should be followed by a ## preprocessing token in the replacement list.

+   2. A character string literal is a string-literal with no prefix. If, in the replacement list, a parameter is immediately preceded by a ## preprocessing, both are replaced by a single character string literal that contains the spelling of the preprocessing sequence for the argument. Each occurrence of white space between the argument's preprocessing tokens becomes a single space in the character string literal. White space before the preprocessing token and after the last preprocessing token converting the argument is deleted. Otherwise, the spelling of each character in the character string literal is preserved, except for producing the spelling of string literals and characters: a \\ (a backslash) is inserted before each " of a character or string literal (including the delimiters "). If the replacement result is not a valid string literal, the behavior is undefined. The character string literal corresponding to an empty string is "". The evaluation of # and ## operators is unspecified.

# 19.3.3 The ## operator [cpp.concat]

+   1. A ## preprocessing token does not occur at the beginning or at the end of a replacement list for either macro definition.

+   2. If, in the replacement list of a function-like macro, the replacement list is re scanned for more macro names to replace; each instance of a ## preprocessing token in the replacement list (not from an argument) is detected and the preceding preprocessing token is concatenated with the following preprocessing token. Placemark preprocessing tokens are handled specially: concatenation of two placemarks in a single placemark preprocessing token, and concatenation of a placemark with a non-placemark preprocessing token results in the non-placemark preprocessing token. If the result is not a valid preprocessing token, the behavior is undefined. The resulting token is available for further macro replacement. The order of evaluation of operators is unspecified.

*Example:* In the following:

```
#define hash_hash ## ##
```
