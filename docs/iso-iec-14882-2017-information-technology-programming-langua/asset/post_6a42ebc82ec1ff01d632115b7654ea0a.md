## 10.6.3 dependency [dcl.attr.dep]

+ 1 The attribute-carries-dependency specifies propagation into and out of functions. It may appear at most once in each attribute-list and no attribute-argument-clause shall be present. The attribute may be applied to the declarator-id of parameter-declaration in a function declaration or lambda, in which case it specifies the initialization of the parameter carries a dependency to (4.7) each value-to-value conversion (7.1) of that object. The attribute may also be applied to the declarator-id of a function declaration, in which case it specifies the return value, if any, carries a dependency to the evaluation of the function expression.

+ 2 The first declaration of a function specifies the carries-dependency attribute for its declarator-id if any declaration of the function specifies the carries-dependency attribute. Furthermore, the first declaration of a function specifies the carries-dependency attribute for a parameter if any declaration of function specifies the carries-dependency attribute in its first declaration in one translation unit and one of its parameters is declared with the carries-dependency attribute in its first declaration in the same function or one of its parameters is declared without the carries-dependency attribute in its first declaration in another translation unit, the program is ill-formed, no diagnostic required.

+ 3 [Note: The carries_dependency attribute does not change the meaning of the program, but may result in generation of more efficient code. — end note]

+ 4 [Example:
/* Translation unit A. */

```
struct foo { int *a; int *b; };
::atomic<struct foo*> foo_head[10];
foo_array[10][10];

[[carries_dependency]] struct foo f(int i) {
    return foo_head[i].load(memory_order_consume);
}

int g(int* x, int* y [[carries_dependency]]) {
    return kill_dependency(foo_array[x][y]);
}
```

/* Translation unit B. */

```
[[carries_dependency]] struct foo f(int i);
int g(int* x, int* y [[carries_dependency]]);
```

```
int c = 3;
void h(int i) {
    struct foo *p;
p = f(i);
do_something_with(g(&c));
```

The carries dependency on function f means that the return value carries a dependency out of f, so that the implementation need not constrain ordering upon f. Implementations of f and its caller may preserve dependencies instead of emitting hardware memory order instructions (a.k.a. fences). Function g's second parameter has a carries_dependency attribute, but its first parameter does not. Furthermore, f's first call to g carries a dependency into g, but its second call does not. The implementation might insert a fence prior to the second call to g. — end example]

## 10.6.5 Fallthrough attribute

+ 1 The attribute-token fallthrough may be applied to a null statement (9.2); such statement is a fallthrough statement. The statement shall appear at most once in each attribute-list and no attribute-argument-clause shall be. A fallthrough statement may only appear within a switching statement whose label is a case or default label for the same switch statement. The program may be ill-formed if there is no such statement.

+ 2 [Note: The use of a fallthrough statement is intended to suppress a warning that an implementation might otherwise issue for a case or default label that is reachable from another path of execution. — end note]

```
void f(int n) {
void g(int i);
switch (n) {
case 1:
case 2:
case 3:
case 4:
    i();
    [[fallthrough]];
}
```

## 10.6.6 Maybe unused attribute

The attribute-token `maybe_unused` indicates that a name or entity is intentionally unused. It shall appear at most once in each attribute-list and no attribute-argument-clause shall be present.

The attribute may be applied to the declaration of a class, a typedef-name, a variable, a non-static data member, a function, an enumeration, or an enumerator.

[Note: For an entity marked `maybe_unused`, implementations should not emit a warning that the entity is unused, or that the attribute is used despite the presence of the attribute. — end note]

A name or entity declared without the `maybe_unused` attribute can be redeclared with the attribute and vice versa. An entity is considered after the first declaration that marks it.

[Example]:

```
[[maybe_unused]] void func([[maybe_unused]] bool thing1,
    [[maybe_unused]] bool thing2 {
    [[maybe_unused]] bool b = thing1 && thing2;
    assert(b);
};
```

Implementations should work when b is unused, whether or not DEBUG is defined. — end example

## 10.6.7 Nodiscard attribute

The attribute-token `nodiscard` may be applied to the *declarator-id* in a function declaration or to the declaration of a class or enumeration. It shall appear at most once in each attribute-list and no attribute-argument-clause shall be present.

[Note: A nodiscard is a function expression that calls a function previously declared `nodiscard`, or whose return type is a possibly-evaluated class or enumeration marked `nodiscard`. Appearance of a nodiscard as a possibly-evaluated expression (class S is discouraged unless explicitly cast to. Implementations should issue a warning in such cases. This is typically because discarding the return value of a nodiscard has surprising consequences. — end note]

[Example]:

```
struct { error_info { /* ... */ };
error_info enable_missile_safety_mode();
void launch_missiles();
void test_missiles();
missile_safety_mode(); // warning encouraged
launch_missiles();
er_info foo(); // warning not encouraged: a nodiscard call, because neither
the (reference) return type nor the function is declared nodiscard
```
