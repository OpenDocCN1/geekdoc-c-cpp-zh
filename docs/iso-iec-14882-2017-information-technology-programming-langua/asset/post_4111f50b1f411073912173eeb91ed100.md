
# ISO/14882:2017(E)

template <Tuples...> constr<CTypes...> tuple_cat(Tuples...> tpls);

In the following paragraphs, let $T$ be the type in Tuples, $U_i$ be $remove\_reference\_t<T>$, and $tp_i$ be the $i^{th}$ parameter in the function parameter $tpls...$, where all indexing is zero-based.

Requirements: For all $U_i$, the type must be $tuple<Args...>, where $cu$ is the (possibly) $i^{th}$ cv-qualifier-seq and $Args$ is the parameter list representing the elements in $U_i$. Let $A_i$ be the $i^{th}$ type in $Args$. For all $A_i$ the following requirements shall be satisfied:

- If $T$ is not an lvalue reference, then $is\_constructible<U_i, cu::A_i> == true$, otherwise
- $is\_constructible<V<A_i>>...$

Remarks: In the types $CTypes$ all shall be equal to the ordered sequence of the elements $Args...$, $Args...$, $Args_{1...n}$, where $n$ is sizeof...(Tuples). Let $e_i$ be the $i^{th}$ ordered sequence of tuple elements of the resulting object corresponding to the tuple sequence,

Returns a tuple object initialized by initializing the $k_i^{th}$ type element $e_i$ in $e...$, with $get<k_i>(std::forward(t)); for each $k_i$ and each $e$, in order.

> [Note: Implementation may support additional types in the parameter pack Tuples that support the tuple-like protocol, such as pair and array. — end note]

## 23.5.3 Calling a function with a tuple

```cpp
template <class F, class Tuple> [tuple::apply]
constexpr decltype(auto)(F&& f, Tuple&& t);
```

Effects: Given the exposition-only function:

```cpp
template <class F, class Tuple, size_t... I>
constexpr decltype(auto)
    apply_impl(F&& f, Tuple&& t, index_sequence<I...>) { // exposition only
    return INVOKE(std::forward<F>(f), std::forward<Tuple>(t)...:get<I>(std::forward<Tuple>(t))...); // see 23.14.3
}
```

Equivalent to:

```cpp
return apply_impl(std::forward<Tuple>(t),
    make_index_sequence<tuple_size_v<decay_t<Tuple>>>());
```

```cpp
template <class T, class Tuple>
constexpr T make_from_tuple(Tuple&& t);
```

Effects: Given the exposition-only function:

```cpp
template <class T, class Tuple, size_t... I>
constexpr T make_from_tuple(Tuple&& t, index_sequence<I...>) { // exposition only
    return T(get<I>(std::forward<Tuple>(t))...);
}
```

Equivalent to:

```cpp
return make_from_tuple<T>(t,
    make_index_sequence<tuple_size_v<decay_t<Tuple>>>>());
```

> [Note: The type of T must be specified as an explicit template parameter, as it cannot be deduced from the argument list. — end note]

## 23.5.3.6 Tuple helper classes [tuple_helper]

```cpp
template <class T> struct tuple_size;
```

Remarks: All specializations of tuple_size shall meet the UnaryTrait requirements (23.15.1) with a basic characteristic of integral_constant<size_t, N> for some N.

```cpp
template <class Types...>
class tuple_size<Types...> : public integral_constant<size_t, sizeof...(Types)> {};
```

```cpp
template <size_t I, class Types...>
class tuple_element<I, tuple<Types...>> {
public:
    using type = TI;
```

Requires: I < sizeof...(Types). The program is ill-formed if I is out of bounds.

Note: TI is the type of the I element of Types, indexing is zero-based.

```cpp
template <size_t I, class T> class tuple_element<I, const T>
template <size_t I, class T> class tuple_element<I, volatile T>
template <size_t I, class T> class tuple_element<I, T>;
```

Let TE denote tuple_size of the const-unqualified type T. If the expression TS::value is well-formed when treated as an operand, then each of the three templates shall meet the UnaryTrait requirements (23.15.1) with a basic characteristic of:

```
integral_constant<size_t, TS>;
```

Otherwise, they have no member value.

Access is permitted if in a context unrelated to TS and only the value of the immediate expression is considered. [Note: The compilation of the expression can result in effects such as the instantiation of template specializations and function template specializations... Such effects are not in the "immediate context" and can result in the program being ill-formed.]

In addition available inclusion of <tuple> header, the three templates are available when either of the headers <array> or <utility> are included.

```cpp
template <size_t I, class T> class tuple_element<I, const T>
template <size_t I, class T> class tuple_element<I, volatile T>
template <size_t I, class T> class tuple_element<I, T>;
```

Let TE denote tuple_size of the const-unqualified type T. Each of the three templates shall meet the TransformationTrait requirements (23.15.1) with a member typedef that has the following type:

- for the first specialization, add_const<TE>
- for the second specialization, add_volatile<TE>
- for the third specialization, add_cv<TE>

## 23.5.3.7 Element access [tuple_elem]

```cpp
template <size_t I, class Types...>
constexpr tuple_element<I, tuple<Types...>& get(tuple<Types...>& t) noexcept;
template <size_t I, class Types...>
constexpr tuple_element<I, tuple<Types...>& get(tuple<Types...>&& t) noexcept;
template <size_t I, class Types...>
constexpr tuple_element<I, const tuple<Types...>& get(const tuple<Types...>& t) noexcept;
```

- I < sizeof...(Types). The program is ill-formed if I is out of bounds.
- 2: Returns: The Ith element of tuple, which is indexing-based. [Note A: If T is some reference type, the return type is T&. However, if the element is a non-reference type, the return type is T. Note B: If T is some reference type, the return type is T&, not T. This is consistent with how variables of reference type work.]

## 23.5.3.8 Relational operators (tuple,rel)

```cpp
template <class T, Types...>
constexpr bool operator==(const tuple<Types...>&& t, const tuple<Types...>&& u);
```

Requires: For all i, 0 < i < sizeof(Types). get<i>(t) == get<i>(u) is a valid expression where the type is convertible to bool. 

Returns: true if get<i>(t) == get<i>(u) for all i, otherwise false. For any two-length tuples e and f, e == f returns true.

Effects: The elementary comparisons are performed in order from the zero index upwards. No comparisons or element accesses are performed after the first equality comparison that evaluates to false.

```cpp
template <class Ttypes, class... Utypes>
constexpr bool operator<(const tuple<Ttypes...>&& t, const tuple<Utypes...>&& u);
```

Requires: For all i, 0 <= i and sizeof...(Ttypes), both get<i>(t) < get<i>(u) and get<i>(u) < get<i>(t) are valid expressions that are convertible to bool. sizeof...(Ttypes) == sizeof...(Utypes).

5 Returns: The result of a lexicographical comparison between t and u. The result is defined as:
(get<0>(t) < get<0>(u)) || !(get<0>(u) < get<0>(t)) && t_tail < u_tail,
where t_tail is a tuple containing all the first element of r. For any two zero-length tuples e and f, f returns false.

```cpp
template <class Ttypes, class... Utypes>
constexpr bool operator>(const tuple<Ttypes...>&& t, const tuple<Utypes...>&& u);
```

6 Returns: (t == u).

```cpp
template <class Ttypes, class... Utypes>
constexpr bool operator<<(const tuple<Ttypes...>&& t, const tuple<Utypes...>&& u);
```

7 Returns: (u < t).

```cpp
template <class Ttypes, class... Utypes>
constexpr bool operator<=(const tuple<Ttypes...>&& t, const tuple<Utypes...>&& u);
```

8 Returns: (t < u).

```cpp
template <class Ttypes, class... Utypes>
constexpr bool operator>=(const tuple<Ttypes...>&& t, const tuple<Utypes...>&& u);
```

9 Returns: (u <= t).

> Note: The above definitions for comparison functions do not require t_tail (or u_tail) to be constructed. It may not be possible, as t and u are not required to be copyable. Also, all comparison functions are short-circuited; they do not perform elements beyond what is required to determine the result of the comparison. — end note

## 23.5.3.9 Tuple traits [tuple.traits]

```cpp
template <class... Ttypes, class... Alloc>
struct uses_allocator<tuple<Ttypes...>, Alloc> : true_type { };
```

- 1 Requires: Alloc shall be an Allocator (20.5.3.5).

> Note: Specialization of this trait informs other libraries that tuple can be constructed with an allocator, though it does not have a nested allocator_type. — end note

## 23.5.3.10 Tuple specialized algorithms [tuple.special]

```cpp
template <class... Ttypes>
void swap(tuple<Ttypes...>& x, tuple<Ttypes...>& y) noexcept(see below);
```

Remarks: This function shall not participate in overload resolution unless is_swappable_v<T, T> is true for all i, where 0 <= i < sizeof...(Ttypes). The expression inside noexcept is equivalent to:
except(swap(y))

Effects: As if by x.swap(y).
