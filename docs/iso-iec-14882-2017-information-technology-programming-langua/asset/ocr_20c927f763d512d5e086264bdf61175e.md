# 30.10.8.4.3 path append

The operations use operator=/ to denote their semantic effect of preferred-separator when needed.

```
path operator=(const path& p);
```

Effects: If p.is_absolute() && p.has_root_name() && p.root_name() != root_name(), operator(p).

Otherwise, modifies *this as by these steps:

+   - If p.has_root_directory(), removes any root directory and path from the generic format pathname. If has_root_directory() or is_absolute() is true or if has_filename() is true, then append::preferred_separator to the generic format pathname.

+   - Then appends the native pathname of p, omitting any root-name from its generic format pathname, to the native pathname.

Example: Even if /host is interpreted as a root-name, both of the paths path("//host"/"foo") and path("//host"/"/foo") equal to /host/foo.

Expression examples:

```
// On Posix,
path("foo") / """; yields "foo/"
path("foo") / "bar"; yields "foo/bar"
// On Windows, backslashes replace slashes in the above yields

// On Windows,
path("foo") / "c:/bar"; yields "c:\bar"
path("foo") / "c:/c"; yields "c:\c"
path("foo") / ":*"; yields "c:\*"
path("foo") / "c:/bar"; yields "c:\bar"
path("foo") / "c:bar"; yields "c:\bar"

// end example
```

Returns: *this.
