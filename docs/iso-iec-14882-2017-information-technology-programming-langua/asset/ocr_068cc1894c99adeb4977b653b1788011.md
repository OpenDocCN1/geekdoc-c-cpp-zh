# 11.5 Structured binding declarations

+   A structured binding declaration introduces the identifiers v0, v1, v2 ... of the identifier-list as names (6.3.1),
structured bindings. Let cv denote the cv-qualifiers in the decl-spec-seq. A variable with
unique name e is introduced. If the assignment-expression in the initializer has type A and
ref-qualified e, it has type A and each element is copy-initialized or direct-initialized from the
corresponding element of the assignment-expression as specified by the initializer. Otherwise, e
defined as with

```
attribute-spec-seq-04 decl-spec-seq ref-qualified T e = initializer;
where the declaration is interpreted as a function declaration and of the declaration other
nde the declarator is taken from the corresponding structured binding declaration. The type of the
id-expression e is called E. [Note: E is no reference type (Clause 8). — end note]
```

+   If E is an array with element type T, the number of elements in the identifier-list shall be equal
the elements of E. Each name of i refers to the element of the array and
who T is the referenced type T. [Note: The top-level cv-qualifiers of T are cv. — end note]
Example:

```
auto f() -> auto[2](int);
auto [x, y] = f(); // x and y refer to the elements in the array return value
xr and yr refer to elements in the array returned by f's return value
```

+   Otherwise, if the unqualified-id std::tuple_size<N> names a type, the expression std::tuple-\size<>:: shall be a well-formed integral constant expression and the number of elements in the
identifier-list shall be equal to the value of that expression. The unqualified-id get is looked up in the scope of
 by class member lookup (6.4.5), and if it finds at least one declaration, the initializer is e.get<I>().
Otherwise, the initializer is get<i>(e), where get is looked up in the associated namespaces (6.4.2). In it
case, get<<i> is interpreted as a template. [Note: Ordinary unqualified lookup (6.4.1) is not performed.
