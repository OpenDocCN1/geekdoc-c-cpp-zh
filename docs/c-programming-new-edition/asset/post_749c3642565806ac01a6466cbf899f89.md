## 3.1. WHY CONTROL STATEMENTS?

Well that’s an interesting query. One may ask that when C is such an omnipotent language with so many features and disciplines where does the need arise for incorporating separate control statements. Well that’s a tough one, but as mentioned in the earlier session with so many different functions being carried out by C it needs some kind of a managerial system which instructs the computer what function has to be performed at which time. The control statements act as a manager. You will be amazed at the amount of functions the different control statements handle.

For example in a program you may have a statement in which a multiplication operation is to be performed and in the next an addition operation and after the next line there may be a statement which may want itself to be repeated 8 times and another statement may like itself to be skipped and attended to at a later stage.

All these conditions are managed by the control statements. You have had a glimpse of the different types of control statements in the previous session and now is the time to get into the thick of the things. You have seen the broad classification of the control statements in the earlier session, here is the various subdivisions that they possess represented diagrammatically.

The sequence control structure is one of the basic uncomplicated control statements. The idea is very simple. In the sequence control instructions the statements to be executed are done so in a serial manner one after the other.

The C compiler first executes the opening line and then moves on to the next and so on in a serial fashion and the entire program is executed in this manner. For example if the first statement requires the computer to perform a mathematical operation then when the compiler comes across this statement it computes the operation and stores the answer in the memory and only then advances to the next line. ## 3.2. THE IF STATEMENT

The if statement reacts on a particular condition that follows the if. Unless the condition after the if is satisfied the statements following it will not be executed. It is like a person says “ if I am paid Rs.100 then the work will be done by me.”

In the above example it is noticed that if the person is paid Rs. 100 (i.e., the condition becomes true) only then the work will be done by him otherwise the work will not be done by him (condition becomes false). Here the condition is the payment of Rs. 100 and the statement to be executed if the condition is true is, the work being done. Since the computer cannot decipher if we write it in normal English we have to write it in a form which is understandable by the computer. The general format is specified as below:

if (this condition is true)

execute this statement; now one may ask why only the word if why not any other word. Well what the keyword if does is that it intimates the compiler that a decision control instruction follows it and if the condition in the parentheses turns out to be true then the following statements are to be executed but if the condition is not satisfied then none of the statements are to be executed.

The conditions are to be specified within the parentheses. Why? because once a statement is written the parentheses and it follows the if the compiler recognizes that it is a condition and its truth or falsity is to be checked. This is done by means of the relational operators of C (<, >, <=, >=, ==, !=).
