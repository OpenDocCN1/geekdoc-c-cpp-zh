
Several types of documentation are kept during the course of the program development process. Here are a few:

- Program specifications;
- Program description;
- Program design charts (flowcharts, pseudocode, etc.);
- Description of testing done and errors found;
- An operator’s manual (user’s guide);
- Maintenance documentation.

Program specifications describe what the program is intended to accomplish: they help the programmer design the program. The program description details what the completed program actually does. Program design charts outline the specific steps used in the program to produce the desired results. The types of testing done, the data used, as well as the errors found are typically recorded in separate documentation. Details on how to operate a program are presented in an operator’s manual. Maintenance documentation is record of the changes made to the program and a detailed explanation of those changes.

The type of documentations kept depends on each programming department’s various requirements.

Why this is preferred to the machine language is that a single statement in the high level is equivalent to a number of instructions in machine level. ### 1.4. COMPILING A C PROGRAM

Coding, compiling, and executing a C program consists of different steps that will be discussed below. Before embarking on that endeavor, one must be advised that C is compatible to different operating systems like the DOS and UNIX.

Executing a program in each of these environments consists of different steps. The different steps needed for both the platforms are discussed below.

Steps involved in Turbo C:

- 1. **Step 1:** Opening a C program Once the system is ready and a screen opened (text editor), from the main menu you select file (ALT + F) and choose NEW. Once this is done a new screen is presented. Whenever you enter the turbo C text editor for the first time, by default a new file is opened and you can start coding your program.
- 2. **Step 2:** Compiling a C program Once the program is coded and is ready for execution it is compiled to check for any errors. (ALT + C) The compilation is done by a compiler, which translates the program instruction to machine language. If there are any errors in the program the compilation stops immediately.
- 3. **Step 3:** Error inspection This step comes into picture only if there are any errors in the coding. The errors, which may be in the syntax or semantics of the language, may vary. The line where the error lies and the type of error are displayed. Once the errors are rectified the program is once again compiled. This process continues until the program is error free.
- 4. **Step 4:** Running the program Once the program is declared error free you must run the program (CTRL + F9) to get a display of the result.
- 5. **Step 5:** Display the output The display of a program (ALT + F5) is done only when the program is compiled and executed.

### 1.5. COMPILER AND INTERPRETERS

Can you imagine the commotion that is caused when two people from different countries who don’t know each other’s dialect start talking to each other? Then how does the computer, a machine, understand, react, and execute the instructions that you dictate? Using Compilers and Interpreters

The compilers and interpreters, to keep it simple, act as translators between the user and the computer. What some people are not aware of is that the computer understands only the machine language, i.e., 0s and 1s.

The compilers or the interpreters translate the programming language to the machine language, do the necessary computation in the machine language and once the result is obtained, translate it back into the programming language.

A compiler or the interpreter is itself a program and every computer must have its own compiler or interpreter. It is just that the approaches of translating programs in both of them are different. A compiler while translating takes the whole program, translates it, and displays it back.

An interpreter on the other hand, breaks the program into sentences and translates the sentences one by one. It is preferable to develop a new program using an interpreter rather than a compiler though it is mandatory for every computer to have its own compiler or interpreter for a particular high-level language.

### 1.6. BUILDING LOGIC THROUGH PSEUDOCODES

As they say, a good plan is half the battle. In a similar way in C before embarking on writing the program it is essential that you plan the strategy that you intend to use.

In short, a skeletal program or framework of the code must be organized so that the entire concentration is on the logic of the program. Once the program strategy is decided, emphasis can be given to the details associated with the individual statements. This line of attack is generally referred to as top-down approach. With large programs this entire process might recur numerous times.

Top-down approach can be accomplished by evolving an informal outline containing sentences that are partly in English and partly in C. In the infant stages of the program development, the exigency for C is minimal restricting it to only major program components. Auxiliary detail is then provided in English. The resulting detail is called pseudocode.

In your example you will come across a pseudocode that is written for computing simple interest on a given Principle. The formula will be SI = p*n*r/100 and the values for p, n, and r should be requested from the user. Here ‘p’ stands for the principal ‘n’ stands for the number of years ‘r’ stands for the rate of interest.
