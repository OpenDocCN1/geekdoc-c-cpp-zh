## 5.2. ADVANTAGES OF FUNCTIONS

What you have skimmed through above, is just a general idea of the functions and the kind of operations they perform. Listed below are a few of the merits the functions offer to the programmer and more often than not the programmers comply with the functions and find that the pains of programming if any, are alleviated. A programmer can exploit the below mentioned advantages to the fullest and reap the rich rewards of implementing functions.

A programmer can identify whatever actions are performed repeatedly in various parts of the program, write them as a function and call the function from various parts of the program, wherever needed. This approach avoids code duplication. Instead of duplicating the same code in different parts of the program, you just write the function once and call it from different parts of the program, thus reducing the executable file size and redundancy of code, making the maintenance of code easy.

In multitasking systems like Unix, there is a direct relationship between the amount of memory a program consumes and the speed with which it runs. You will, in general find that large programs which demand a lot of memory, are sluggish.

Breaking down your program into subroutines lends your program a structure. You can divide your task into multiple sub-tasks, develop a function for each sub-task, and integrate them into a single program. Once a function is written and completely tested, a programmer can expect it to smoothly fit in with the rest of the program modules.

Once a function is written, tested, and found to be working as per the expectations, the function can be loaded into a library, and can be used in an altogether different application. This approach encourages code reusability.

## 5.3. DECLARING A FUNCTION

After reading the prologue about functions you must be waiting anxiously and expectantly to kick start and get into the thick of things. You will no longer be kept on hold and will now start by declaring a function which is one of the basic bricks in the structure of a function.

still a cloud of doubts they dispelled will be blown away with the help of this example. To maintain simplicity no arguments are included.

```c
#include<stdio.h>
main()
{
    tips();
    /* caller */
    printf("\n Success is about hanging on after others have let go");
}
tips()
/* called */
{
    printf("\nWhen you reach the end of the rope tie a knot & hang on");
}
```

The above program is a simple example which will help you take a whiff of the actual happenings. In this program soon after the main function the function called tips is invoked or called. As soon as this happens the control is passed on to the place where the function tips is defined.

Once the control reaches the called function it executes the statements within that function and returns to the caller function and executes the statements after it. So, the output of the above program would be:

When you come to the end of the rope tie a knot & hang on. Success is about hanging on when others have let go.

## 5.4. CALLING A FUNCTION

The intricacies of declaring a function were just explained in detail but what use is it if you just declare a function and don’t call it. Hence you will now deal with the process of calling a C function. You have defined the function but how do you summon the compiler to execute the code in the function definition? Well, you just call it. Calling in the sense you give some kind of indication or to put it clearly a kind of arrow sign which requests the compiler to take diversion and carry on further execution from the place specified.

these issues you should be aware of the different kinds of variables that exist in C’s arsenal. The types of variables being the: Local Variables and Global Variables.

### Local Variables

You are aware of the fact that main is a function and you can declare any number of variables within it. So, if a rule holds good for one function why can’t it for other functions? It definitely can.

You can declare a variable inside any function belonging to any size and type. Thus, variables declared inside a function are called local variables and are valid and can be used within that function. The life of these variables exists until they are within the function. It is the same as the value of a particular variable in a program cannot exist for all the programs.

Any attempt to break the rules will result in an error. But sometimes you might need to access the variable from another function, well C takes care of this too. The values can be imported from other functions by passing them in parameters. But with passing parameters care should be taken that the same number of variables and the same type are being passed. Thus, a copy of the actual parameters is made and passed to the formal parameters. All this is an extra burden and is cumbersome for the programmer. Beside this, several functions are required to share information, which results in transmission and re-transmission of parameters, which affect the performance of the program. The value in the variables if altered in a sub-function does not affect the value in the main function.

### Global Variables

Before you can accuse C of being inefficient in certain areas it pops up with an alternative. The alternative for reducing the aforementioned problem is declaring the variables globally. You were given an example of the global declarations in the first session. The global variables are otherwise called external variables and unlike the local variables which are confined only to the function which has them, the global variables can be used anywhere in the program. The global variables are declared outside the main, i.e., before beginning the program and the values hold good throughout the program. The storage for global variables is in a fixed region of memory set aside for this specific purpose by the C compiler.

The effectiveness of declaring globally can be felt when many functions in a program use the same data. Defining a variable as global is particularly advantageous because its value is made available to all other functions. But the only risk factor involved in this is that if any function manipulates or alters the global variable then any other function using the same variable at the same time gets the altered value. So, the choice of using global variables has to be made judiciously considering the above implication.
