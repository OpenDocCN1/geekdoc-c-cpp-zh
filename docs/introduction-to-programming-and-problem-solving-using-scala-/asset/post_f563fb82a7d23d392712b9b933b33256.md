The alternative sort we will learn about is the SHELL SORT, also called the diminishing gap sort. This was proposed in 1959 by Donald Shell, and was one of the first general sort algorithms that are faster than $O(n^2)$, though some changes had to be made in order to get performance for the worst case. The basic idea of this sort is one that might seem a bit counter. It performs an insertion sort repeatedly on different subsets of the array. To start, the subsets are to groups of elements are widely spaced.

The spacing between the elements in each subset is called the “gap”. As the alternate name implies, the gap is decreased in size for each run through the sort.

The intuitive aspect of this sort is that performing insertion sort multiple times sort the array faster than doing it outright. This work can sort with a smaller gap size maintains order at the larger gap size so work is not undone, and the insertion sort is very efficient on partially ordered data. The sorts with large gaps do very little compared to the smaller gaps because they do not contain many elements, but once you get to the smaller gaps the data is mostly sorted so you get close to the best-case performance of the insertion sort. The sort always ends with a gap size of 1, which is doing a normal insertion sort, so you know that the result is fully sorted.

The only trick to the Shell sort is figuring out what to do about the gap. The initial suggestion was to start at the size of the Array and decrease it by factors of 2. It works well, but spacings that are factors of 2 apart will keep even and odd subsets until you get down to a gap of 1 and in certain cases can actually lead to O(n²) behavior. For this reason, we use a slightly different factor where we divide by 2.2

```scala
def shellSort(a:Array[Double]):Unit = {
  var gap = a.length/2
  while (gap > 0) {
    for (j in gap until a.length) {
      var i = j-gap
      var tmp = a(j)
      while (i >= 0 && a(i) > tmp) {
        a(i+gap) = a(i)
        i -= gap
      }
      a(i+gap) = tmp
    }
    gap = (gap/2.2).round.toInt
  }
}
```

## 13.2 Searching

While sorting data is something we do a bit with computers, searching for data is a far more common task. A lot of the things you do on regular basis involve searching for information either to retrieve it or modify information. This makes sense, as running through data is something that computers do particularly and efficiently.

### 13.2.1 Sequential Search (Linear Search)

The most basic form of search is the own or LINEAR SEARCH. This involves running through data element at a time and checking each one to see if it matches what you are looking for. If it finds what you are looking for, it returns the index where it can be found. If it gets to the end without finding, it will return something to indicate that the data was not there. The following code is a linear search through an Array of Ints.

```scala
def linearSearch(a:Array[Int], value:Int):Int = {
  var i = 0
  while (i < a.length && a(i) != value) {
    i += 1
  }
  if (i >= a.length) -1 else i
}
```

The statement is needed because the common idiom when returning an index is -1 when the value is not found. We can get rid of this conditional at the end if we count backwards.

```scala
def linearSearchForLast(a:Array[Int], value:Int):Int = {
  var i = a.length-1
  while (i > 0 && a(i) != value) {
    i -= 1
  }
  i
}
```

This modified version of the code starts at the end and goes backwards. It is a bit simpler, but it fundamentally alters the description of the function as we now find the last occurrence instead of the first.

There are quite a few different methods on the Scala collections that do searching. For the collections that we have learned about, these are all performing linear searches. They include the following, as they are defined in Seq[A]:

-   def find(p: (A) => Boolean): Option[A]
-   def indexOf(e: E, from: Int): Int
