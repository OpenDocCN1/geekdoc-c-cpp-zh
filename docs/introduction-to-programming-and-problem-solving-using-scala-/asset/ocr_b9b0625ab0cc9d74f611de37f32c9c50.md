# Getting to Know the Tools

```
tar cf assign1.tar header.txt Assign1/
t tf assign1.tar
tar xf assign1.tar
```

The first command is what you might execute to create a tarball called assign1.tar contains a header file and all the contents of the directory Assign1. The second command might be used to verify that everything you want is in the file or to check what is before it is extracted. The last command would extract the contents.

The counterpart to tar is gzip. This command will compress one or more files. Follow the gzip command with a set of files to compress. This will create a new set of compressed files with the extension .gz The gzip command will unzip a file to give you the original file. You can use the -r option to recursively descend into a directory.

The combination of tar and gzip is so common that you can get tar to automatically zip or unzip files using gzip. Simply put the z flag in the options and either gzip or gunzip will be invoked. Files created are typically given a .tgz extension. Both tar and gzip are specific to Unix/Linux world. If you want to deal with compressed files going to or from other systems, you might want to use the more broadly used zip format. The zip command can be followed by the name of a zip file and the set of file names to zip up into the specified file. If you want to zip up a whole directory structure you will need to use the -r option. An unzip command will extract the contents of a zip file.

# A.1.1.6 Remote

One of the strengths of Unix/Linux is the true multi-user capabilities that have multiple people to be logged in at once. A computer could be in full even if no one is sitting at it. In fact, this is a part of why you should be familiar with the command line. Running graphical interfaces on across long distance Internet connections can be very unpleasant. However, the plain text of a command line will be quite responsive over slow networks.

So do you log into one computer from another? If you are on a Unix/Linux box and want to log into another there are several commands that you could use to make a connection. The most basic, and likely useful, is telnet. Simply type in telnet followed by the name or IP address of the machine that you want to connect to. This opens a very simple connection between the machines. Telnet connections are not secure and, in a way, too flexible, you will probably find this approach blocked by the security settings on most machines.

Next the scale is ssh. This stands for remote shell and can be invoked in the same way as telnet. The rsh connection is not secure and as such, it is blocked on many systems. However, it might be allowed if you are logged into a trusted machine inside of the local firewall.

The connection type that you probably use is default ssh. This stands for secure and implies across an ssh connection is encrypted using public key cryptography. If a system is getting to let log in remotely, this is the method that most system administrators are likely to leave open for.

When you connect to a machine you will be asked for your password, and assuming you get it, you will be dropped at a command prompt on that machine.
