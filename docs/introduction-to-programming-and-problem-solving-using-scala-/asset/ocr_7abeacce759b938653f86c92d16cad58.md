A reduce method on a sequence of Strings will only give us a String, but the fold methods can give us another type. Here we show that both the fold literal syntax as well as the shorter version.

```
scala var list=List("How", "many", "characters", "do", "we", "have")
wordlist: List[String] = List(How, many, characters, do, we)
```

```
scala wordlist.foldLeft((count,word) => count + word.length)
res98 = 25
```

# 6.5.4 Combinatorial/Iterator Methods

There are other methods on sequences that, for reasons of efficiency and memory limitations, work a bit differently. These methods get us an object that provides access to multiple collections that are created from the original collection. The object that they give us is an Iterator, and specifically they give us an Iterator[List[A]] or an Iterator[Array]. The Iterator type is more primitive than the List or Array. You can only go through it because it is consumed as you go through it. The reason for using an Iterator on these methods is generally for performance and memory benefits. The fact that the Iterator consumes as it goes means that it does not have to store all the contents at once. In fact, one only needs to exist at any given time. When it moves from one to the next, it can forget the last and make the next one.

The methods in this category are listed here. To show the values of the outputs a call to foreach(println) is used. Without this, all that would be shown is Iterator[List[Int]] = empty-iterator.

+   * combinations(n:int) – Generates all combinations of the elements of this sequence length n.

```
scala list.combinations(3).foreach(println)
List(7, 4, 6)
```

> The foldRight method needs a function of type (A,B) => B. There is also a basic fold method, because the order it runs through the collection is not specified, it cannot work with any type B.
