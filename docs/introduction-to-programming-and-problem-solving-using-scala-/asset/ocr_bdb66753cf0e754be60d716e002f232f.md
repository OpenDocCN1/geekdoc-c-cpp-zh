multiple different types. The simplest example of a PARAMETRIC FUNCTION is the identity method shown here.

```
scala def ident[A](a:A)=a
ident: [A] (a: A) A
```

This method takes an argument of any type and returns a tuple passed in. While there are not many situations where you would want to do this, it demonstrates the syntax of parametric functions. You simply place a type parameter name in square brackets between the function name and the normal argument list. It also demonstrates the power of parametric functions, especially if we were to use it as we do here.

```
scala ident(3)
res1: Int = 3
```

```
scala ident("3.3")
res2: Double = 3.3
```

First, this function works fine with an Int, a Double, and a String. That is pretty good. Even better, it works with all those types without telling it the types. Parametric functions can almost infer the types of the parameters.

Here is a more complex example that it really does not do much, a function that takes two arguments and returns a tuple with two values in it.

```
scala def makeTuple[A,B](a:A,b:B) = (a,b)
makeTuple: [A,B] (a:A, b:B) (A, B)
```

This demonstrates how a function can have many parameters. They appear as a comma separated list in the square brackets. A simple example would be a function with three elements

```
scala def threeList[A](a1:A,a2:A,a3:A) = List(a1,a2,a3)
threeList: [A] (a1:A, a2:A, a3:A) List[A]
```

The main reason for introducing this is that it us understand something we saw in the last chapter, the fold methods. We said that fold was much like one of the recursive functions we wrote in the last chapter where we pass in a base value and a function. However, the fold works on sequences of any type and what is more, they can return a different type. With the type of parameters we can write a function with this same capability.

```
def ourFold[A,B](list:List[A],base:B)(f:(A,B)=>B):B = {
  if (list.isEmpty) base
  else f(list.head,ourFold(list.tail, base))
}
```

Like in the API, this method is curried, a topic we will discuss in detail section 7.8. It turns out that doing helps with type inference and allows us to not have to specify types on the function. We can see this working with lst using two different processing functions.

```
scala ourFold(List(1,0), _+)
res0: Int = 30
```
