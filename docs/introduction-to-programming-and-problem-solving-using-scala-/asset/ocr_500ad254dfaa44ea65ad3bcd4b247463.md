# 15.6 Mazes

Another class of problems that works with recursion is involving mazes. This might also seem to be more for recreation, but mazes are a simplified case of something called graphs which are very important in computer science and mathematics and are used to represent all types of different problems. The same approaches that we will use here for mazes apply to graphs as well. There are also many applications where doing like finding the optimal route through restricted path maze is significant.

To keep things simple, we are going to use a basic approach to building our mazes. Instead of having a grid with walls between cells, we will have a grid where squares can be empty or occupied by values that tell us if there is a wall or not. In theory we could use a 2-D Array[Boolean] for this purpose, but in practice we will have use of being able to put numeric values with the code like the following.
Array Array[Int] will be more practical.

We will define maze=Array(Array(0, 0, 0, 0, 0, 0, 0),

```
Array(-0, -1, -1, -0, -1, -1, -1, -1),
Array(0, 0, -0, -1, 0, 0, -1, 0),
Array(0, -1, 0, -1, -1, -1, 0, 0),
Array(0, -1, -1, -0, 0, -1, -1, 0),
Array(0, -1, -1, -1, 0, 0, 0, 0),
Array(0, -1, 0, -1, 0, -1, -1, 0),

Array(0, -1, 0, -1, -1, 0, -1, -1),
Array(0, -1, 0, 0, -1, 0, 0, 0));
```

This builds a 2-D Array of Ints that uses 0 to represent an open square and a -1 to represent a wall. The use of -1 for a wall is intentional so that positive numbers can be used to represent other things later. This particular maze is 10x10 in size. This is a good size to start off for our purposes that most people would probably want to do with a maze.

Our first task is the thing that most people would probably want to do with a maze. To start, we want to know how to get through it in the shortest path of steps. The shortest path has this significant advantage over just returning a path. If it is only a simple numeric value, it is also unique. There can be multiple paths with the same length. That produces ambiguity. It also happens that having a function to find the length of the shortest path is sufficient to find it, as such function can be used to construct the optimal path even though such construction is less than optimal.

You can write a function to find the length of the shortest path using loops, but it is fairly complex code. We can write a simpler solution using recursion, and the recursive approach will easily adapt to solving other problems as well. As with recursive functions, we can break the solution down into two parts, base cases and recursive cases. The base cases are two good base cases for the maze problem. One base case is if you reach the exit. If you are at the exit it takes zero steps to get out. Another base case is if you are checking a location which is out of the maze or in a wall. For we want to return a value that could not possibly be a solution. We will come back to specifically what that value should be after discussing the recursive cases.
