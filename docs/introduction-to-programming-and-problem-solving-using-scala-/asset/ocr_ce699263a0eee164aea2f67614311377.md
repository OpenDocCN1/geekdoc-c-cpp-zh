# 8.4 Testing

We have now gotten to the point where you can write programs of reasonable complexity. You know most of the constructs that exist in the Scala programming language. As soon as you start larger programs, there are some new elements of the programming process that becomes more significant such as testing and debugging.

Just because you have written the code and it compiles and runs does not mean that it is correct. To determine if it actually does what you want it to, you need to test it. This means you need to run the code with a variety of inputs to make sure that they all work, and then fix the problems when they do.

The first part of this, running the program with different inputs is testing. The challenge in testing is trying to figure out what inputs make good tests. When you are testing you are looking for inputs that will break what you have written. You want to give it some things that you think might break it, and in addition, a good set of tests will go through all of the functionality of the code.

Things that will break the code involves looking for boundary conditions. Things that are right at the edge of valid input. For example, if you have a function that takes an Array or a List, what happens if the List or Array you pass is empty? You want to check different small input sets as well as large ones. If the code takes numeric values, does it work for both positive and negative? What about zero? Giving back answers that are wrong or do not make sense can be worse than crashing. If it is a String, what happens when the String is?

There are some situations where you will be certain that the input is coming from a user who might give you something that is not what you expect. Even when the input is coming from another part of the program and something that you think will have the right format, there can be cases that you have not considered. Good testing will help you find these situations.
