In this way, functions allow us to organize code and give useful names to things that we might want to do.
This code also does something else that we have never seen before, it declares variables inside of a function. When we do this the variables are LOCAL VARIABLES, and they can only be accessed inside the function. If after typing this function, you try to use sec, or any of the other variables, outside the function, you will get an error message.

```
scala> sec
<console>:6: error: not found: value sec
```

The part of the code over which a name can be accessed is called the SCOPE of that name.
When you declare a variable or a function in a script outside any block of code, it has a scope that goes through the rest of the script. If you declare it in a block of code, it has a scope that goes from the point of the declaration to the end of the block it is declared in.
A block is denoted with curly braces, so you can use the name until you get to the right curly brace that closes off the block name declared. As a general rule, you want to minimize the scope of variables so they can only be accessed when they are needed. This reduces the amount of code you have to look through if something goes wrong with that variable. This is particularly true of var declarations.

> Trap: New programmers are often tempted to have functions a var that declared outside of the function. The majority of time, this is a bad idea as it is very error prone, and makes the functions harder to use or less reusable.
