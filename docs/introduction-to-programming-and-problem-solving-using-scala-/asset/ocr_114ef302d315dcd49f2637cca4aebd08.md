# 2.7 Naming Values and Variables

We have seen enough that you can solve some simple problems. For, if you were given a number of different grades and asked to find the average, you could type in an expression to add them all up and divide by the number of them to get the average. We basically have the ability to use Scala to solve anything we could solve with a calculator as well doing some fairly string manipulation. We will develop a lot over time, but we have to start somewhere. As it stands we are not just limited to solving problems we can do with a calculator; we are solving the way we would with a calculator. Type in mathematical expressions the way we would write them on paper and get back an answer. Real programming involves tying together multiple lines of instructions to solve larger problems. In order to do this, we need to have a way to give names to values so we can use those values later.

There are two ways in Scala that give names to values: val and var. To begin, let us look at the full syntax of val and var in two samples. We then pull them apart, talk about what they do, see how they are different, and discuss which parts of them are optional.

```
scala val:Int = 2015-1996
age: Int = 19
```

```
scala var average:Int = (2+3+4)/5
average: Int = 3
```

Syntactically the only difference between these two is that one says val and the other says var. That is followed by a name with a colon and a type after. The rules for names in Scala are that they need to start with a letter or an underscore followed by zero or more letters, numbers, and underscores.¹10 abc,abc123, and Team250 are all valid Scala names while 2points is not. You also cannot use keywords as variable names. The only keywords that have been introduced are for val and var, but there will be others, and you cannot use those for names as they are reserved by the language.

Scala is also case sensitive. Names AGE, age, and ageE are all different. In general, it is considered very poor to use names that differ only in capitalization as it can quickly lead to confusion. Most names will not involve underscores, and numbers only appear when they make sense. Scala borrows a standard naming convention from Java called camel case. Names of values begin with a lower case and the first letter of subsequent words are capitalized. For example, theClassAverage is a name that is capitalized. This is not the same convention except that the first letter is capitalized. We use camel case because the capital looks like it.

The types in these examples are followed by an equal sign and an expression. Unlike many programming languages, this is not optional in Scala. In Scala, when you declare a val or var, you must get an initial value.¹¹¹
