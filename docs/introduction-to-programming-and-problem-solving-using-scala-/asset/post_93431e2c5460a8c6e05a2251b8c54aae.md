- less - Display out the contents of one or more files with the ability to move forward and backward, search, etc. (Less is more than more).
- ls - List the contents of a directory.
- mkdir - Make a directory.
- more - Display the contents of one or more files with the ability to page through or search.
- pwd - Stands for ‘print working directory’. This prints out the directory you are currently working in.
- rm - Remove a file.
- rmdir - Remove a directory if it is empty.

The advantage of the command line is that each command can be followed by arguments. Just entering a command is double clicking on a program icon. It is the arguments that let you specify additional information. Most of these commands do not do anything unless you give them one or more file/directory names to work on.

To see how you go about using these commands we will begin with pwd. It is a very simple command and can come handy if you have lost track of where you are in the directory structure. At the command prompt simply type in pwd and hit Enter. Exactly what you get will depend on many things, but it should print out one line of output showing the current directory. It could look something like this.

```
mlewis@mlewis-laptop:~$ pwd
/home/mlewis
mlewis@mlewis-laptop:~$ 
```

In this case, the directory is /home/mlewis. After printing the output we get a new prompt to enter the next command.

> Aside
> In Unix and Linux systems, the base of the entire file system is /. That is why it appears at the beginning of the /home/mlewis directory. A directory that begins with / is an absolute directory.

The next command we want to enter is the ls command. Type in ls, followed by an argument and you will get a listing of all the files in your current directory. This is the most basic usage of the command. You can also use it to see the contents of any other directory by following the ls command with a directory name. Here we see a listing of the contents of the root directory.

```
mlewis@mlewis-laptop:~$ ls /
bin dev initrd list-found opt sbin tmp vminuz
boot initrd.img lib32 media proc srv usr vminuz
cdrom home initrd.img lib64 mnt root sys var
```

If you list a directory and it does not start with / then it will be a relative directory which means the location of that directory is relative to (within) the current working directory. The directory you list will be appended to the end of the current directory. For example, you might have a directory called Desktop in the current directory. Typing in ls Desktop will list the contents of the Desktop directory under the current directory.

```
mlewis@mlewis-laptop:~$ ls Desktop
AdobeReader.desktop QtCreator.desktop
```

You can also specify multiple files or directories, and they will all be listed as seen here.

```
mlewis@mlewis-laptop:~$ ls Desktop /
bin dev initrd list-found opt sbin tmp vminuz
boot initrd.img lib32 media proc srv usr vminuz
cdrom home initrd.img lib64 mnt root sys var
```

Desktop:
AdobeReader.desktop QtCreator.desktop

As you can see, the contents of the current directory are listed on the lines below / : and the contents of Desktop are listed below Desktop:

You might not think that you would normally use all the time with wild characters. At once, it is a feature of the shell. If you put a * into a name, the system will replace it with all the files or directories that match if the * is replaced with zero or more characters. Here is an example of that usage.

```
mlewis@mlewis-laptop:~$ ls /home/mle*
/home/mlewis
```

For the first line, * is replaced with nothing. For the second it is replaced with “old”. You can also use ? to represent any one character. These wild cards are not seen by the ls command it replaces them with all matching file names passed to the command.

The ls has a lot of other options. The options are all preceded by a hyphen. The most commonly used option is -l, which tells ls to use long format. This is an example of that:

```
mlewis@mlewis-laptop:~$ ls -l Desktop
total 8
drwxr-xr-x 2 root root 4096 Oct 27 12:21 AdobeReader.desktop
rw-r--r-- 1 mlewis mlewis 256 Oct 27 12:23 QtCreator.desktop
```

The long format puts each file or directory on a line. In addition to the files, it shows a number of links there are to this file. The first characters show permissions (discussed in section A.1). After that are the user and the owner of the file it belongs to. The last pieces of information are the size of the file, measured in bytes, and the date and time of last modification.

The next commonly used option is -a. This tells ls to list all files, including hidden files. Hidden files in Unix and Linux are files whose names begin with a period. We see here a usage of this combined with long format. Only one hyphen is needed when options are combined:

```
mlewis@mlewis-laptop:~$ ls -al Desktop
total 16
drwxr-xr-x 2 root root 4096 Oct 27 12:22 ..
drwxr-xr-x 2 mlewis mlewis 4096 Oct 27 12:21 AdobeReader.desktop
rw-r--r-- 1 mlewis mlewis 256 Oct 27 12:23 QtCreator.desktop
```

This adds two additional lines. The letter d at the left tells us that these are actually directories. The . is the name for the current directory. .. is the name of the directory in which the current directory sits. We might also refer to it as the parent directory. By default, commands work in the current directory. For this reason, one of the commands you use the most is cd that changes the current directory. The cd is followed by a single directory name. The directory will be the current directory. As we just saw, each directory has . and .. names inside it. If you want to move up a directory, simply execute cd .. at any time to change back to your home directory. The following command changes our current directory to the Desktop directory.

```
mlewis@mlewis-laptop:~$ cd Desktop
mlewis@mlewis-laptop:~/Desktop$
```

The prompt used in this example shows that we can see we are in this new directory. Other tasks that you frequently do when you are manipulating files in a GUI are to copy, move, or delete. The commands for these are cp, mv, and rm. The cp and mv commands are used in the same way. One way to use them is to enter one or more file names and end with a directory name. In that usage all files listed are copied or moved to the directory at the end. If you include a name that has a wild card in it, it will be expanded to all the file names. You can see this in use here:

```
mlewis@mlewis-laptop:~/Desktop$ mv *.txt .
```

Here we move all the files from our home directory that end with .txt into the current directory. This line with mv uses .. to refer to the directory above the current one and . to refer to current. Another way to use these commands is to enter two file names, where the first file will be copied to the second name with cp or renamed to the second name by mv. Assume that one of the files in the Desktop directory was named text.txt. After executing the following command we have copied file into a new file named test2.txt.

```
mlewis@mlewis-laptop:~/Desktop$ cp text.txt test2.txt
```

If you want to remove a file, use the rm command. The rm command can be followed by one or more files. Again, wild cards can be used to match multiple files. Here we are getting rid of all the files that end with .txt.

Use caution when removing files on Linux systems with the command line, it is not forgiving and you cannot easily "undo" what was done. This is true whether you are using rm or if you use mv or cp to a file name when you already had a file of that name. Most of the GUIs that you have used to move files delete to the store of trash can, really just a different delete and then allow you to clear that out; doing rm on a file deletes it at that moment. You cannot dig in the trash to find it. When you delete a file with rm on these systems, it is your only chance of getting it back is if you have a backup.^1

This can be especially dangerous with the way the command line deals with wilds and the dot. Take the rm command above. If you accidentally insert a space between the asterisk and you will delete every file in the current directory. This is because the * alone matches everything.^2 Be careful when you are using rm and look over the command before you enter to make sure you did not mistake anything or insert unwanted spaces.
