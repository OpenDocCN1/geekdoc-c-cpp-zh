An interesting question comes now which of these is better, the Array or the List? Is it better to use an Array which can be mutated or a List which can mutate the data? The answer is it depends on whether you want a function to be able to mutate the data. If the function is supposed to be mutable When you pass mutable data then there could be a benefit to passing something mutable. However, if you do not want the data mutated then passing mutable data you have no control over whether it is mutated. In situations where you do not want your data mutated, you must make a DEFENSIVE COPY. To protect your version of the data, you make a copy of it and pass the copy into the function.

For reason, the question of whether you want to use a mutable or immutable structure depends on the way in which you use that data. If it is going to be mutated frequently then it might make sense for it to be mutable. However, if it is not going to be mutated frequently then immutably likely makes sense so you do not have to be defensive copies. Even in situations where there might be a bit of mutation, you need to consider how much defensive copying will be needed if you choose mutable data.

# 7.8 Currying

In chapter 6 we come across a number of methods that used something called currying, where arguments could be separated into different argument lists. This is a common feature of functional programming languages. In case you are wondering, the name has nothing to do with spices. It comes from the name of Haskell Curry, a mathematician and logician. In this section we want to show you not just how to call functions/methods using currying, but how to write your own methods and how you would want to.

Let's try writing our own curried functions. This first example shows how we can make a curried function using the normal Scala function type and function literal syntax.

```scala
scala> def add(x:Int):(Int)=>Int = (y:Int)=>x+y
add: (x:Int)(Int) => Int
```

```scala
scala> add(5)
res0: Int = 11
```

```scala
scala> val plus5 = add(5)
plus5: (Int)=>Int = <function1>
```

```scala
scala> plus5(6)
res1: Int = 11
```

The first input defines a function add that takes an integer and returns a function that takes an integer and returns an integer. The add function is a higher-order function because it returns a function. The second input to the REPL shows that we can use add as a curried

This example shows what it means to curry a function. There can be times when this approach is quite useful. For that reason, Scala provides a shortcut for doing it. If you define a function and follow it with more than one argument list, the function is curried. So, the code above could be entered like this:
