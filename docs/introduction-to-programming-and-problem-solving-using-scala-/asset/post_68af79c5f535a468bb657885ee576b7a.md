
# Type Basics and Argument Passing

The print statement is to help us keep track of what is happening. Now we will write the same function again, but this time the argument by name instead.

```scala
scala def incrByName(n => Int):Int = {
  println("About to increment.")
  n*1
}
```

incrByName: (n => Int) Int

The syntax for passing an argument by name is to put a rocket before the type of the argument. This is the same used in function literals. If we were to put parentheses in front of it to get () we would have the type of a function that takes arguments and returns an Int. The by-name argument is much the same only when you call the function you do not have to explicitly make a function for the argument, any collection of code will work. To start off, we will call this function in the simplest way we possibly could.

```scala
scala incr(5)
About to increment.
res0: Int = 6
```

```scala
scala incrByName(5)
About to increment.
res1: Int = 6
```

No difference here. They appear to both do the same thing. Both print the statement and give back 6. However, the two are not really doing the same thing. To make clear, we will call them again and the argument be a block that includes a print.

```scala
scala incr {println("Eval"); 5}
Eval
About to increment.
res2: Int = 6
```

```scala
scala incrByName {println("Eval"); 5}
Eval
About to increment.
res3: Int = 6
```

Now it is clear that they are not doing the same thing. When you pass an argument by value, it is evaluated before the function starts so you can have the value to pass through. When you pass by name, the evaluation happens when the parameter is used. That is why the line "Eval" printed out "About to increment." in the second case. The println in the function happens before the value of n is ever accessed.

Using pass-by-name gives you the ability to do more interesting things when mutations of values comes into play. To see that, we can write a slightly different function.

```scala
scala def thriceMultiplied(n => Int):Int = n*n*n
thriceMultiplied: (n => Int) Int
```

It might seem that this method could be called cubed, but as we will see, that name might not always apply for it it uses pass-by-name. Note that we are making use of the fact that an argument list with a single argument can skip the parentheses when a block of code is passed. 

To start with, let us call it with an expression that gives a simple value, but prints something first.

```scala
scala> thriceMultiplied(println("Get value."); 5)
Get value.
Get value.
Get value.
res4: Int = 125
```

Note that the println statement happened three times. This is because the value n was used three times in the function. The parameter been passed-by-value, that would not have happened. It would have printed once, when the function was called.

This particular case still gave us a valid cube though. Why was the function not called cube? The reason is if the code in the argument does the right thing, the result will not be a cube. Here is an example.

```scala
scala> var i=5
i: Int = 5
scala> thriceMultiplied(i+=1); i)
res5: Int = 336
```

336 is not a perfect cube. So how did we get this value? In this example we introduced a var. The code pass-by-name argument alters this var. As, every time that n is used, the value given by n is different. The first time we use n value is 6 because the original 5 was incremented and returned. The next time it is 7 because the 6 that was set to the previous time is increased again. The last time it is 8. So the answer is 6 * 7 * 8 = 336.

# 7.10 Multidimensional Arrays

When we first introduced Arrays and Lists back in chapter 6, we saw that these types are parametric. That means the type requires a type argument to be fully defined. You cannot have just an Array or List. Instead you find Array[Int] or List[String]. Each of these is a type in Scala. The parameter for these parametric types can be any type. If you put these together you can build things like Array[Array[Double]], List[List[String]], or List[Array[Int]]. You do not have to store though. Scala will be perfectly fine with a List[Array[List[Array[Int]]]] . It is not clear what would want such a type, but if you do, Scala will support it.

In the case of Arrays types, we find a special term for them: multidimensional arrays. This is because of how you might picture them in your head. You picture a normal Array as a row with multiple bins that each store a value. An Array[Array[Int]] could be pictured as a table of integers that has rows and columns. Such a table could be said to be two dimensional. If you had Array[Array[Int]]... In general all these things can be applied to Lists just well as Arrays, the term multidimensional is not nearly common, and the fact that it is difficult to do indexing Lists that most applications that have multidimensional data structures will not create with Lists.

> There are restrictions on parametric types, the collections generally allow any type to be used.

So, how you create and use multidimensional arrays? The most basic syntax mirrors what we used to originally create normal arrays.

```scala
scala tda = Array(1,2,3),Array(4,5,6)
tda1: Array[Int] = Array(1, 2, 3), Array(4, 5, 6)
```

In this use the number of elements in each sub-array does not have to be the same. When the lengths are different, they are ragged arrays. When they are all the same, they are rectangular arrays.

If you are interested in making large rectangular arrays, you should use either the fill method or the tabulated method. For fill, all you have to pass in multiple arguments in the first parameter list.
