
## Object-Orientation

With that in place, we can start our implementation of the Bank class giving it collection for the accounts. We also add methods to add and find the accounts. The method to find an account is the apply method.

```scala
class Bank {
  private var accounts:List[Account] = Nil

  def addAccount(account:Account):Unit = accounts ::= account

  def apply(accountID:String):Option[Account] = accounts.find(._id == accountID)
}
```

The apply method returns an Option[Account] because it is possible that there is no account with the provided ID. In that situation, it would return None. After setting up an instance of Bank and some accounts, you could search for one by ID using bank("01234567"), which would give back an Option[Account] for an account with ID "01234567".

## 16.2.3 this Keyword

By default, when you write code in a class that calls a method or uses a member of the class, the call is made on the current object or the value from the current object is used. All calls are implicitly made on the current instance. That is exactly what you want most of the time and the scoping of variables feels very natural. This implicit specification of an object prevents from having to specify which. Consider the code deposit method for adding money to the bank. We wrote

```scala
_balance += amount
```

which is really short

```scala
this._balance += amount
```

Scala simply added this for you.

That is fine in general, but occasionally you will have a need to be able to put a new to the current object. you might need to call a function/method that needs an instance of the object as an argument and you want to use the code that is currently executing. When situation arises you will use the keyword. this is a name that always refers to the current instance in a class. In the bank example, we will use this in two ways when creating an account. We will use this to pass the current account to the Customer who owns it to set things up. We will also use this in the Customer to check if an account belongs to the current Customer as it would be an error to have a Customer taking ownership of an account for someone else.

## 16.2.4 object Declarations

In order to complete our examples, we need to introduce another style of declaration that exists in Scala, the object declaration. We said earlier that you should think of a class as a blueprint for making objects. These objects are called instances, and the process of making them new is called instantiation. On the other hand, the object declaration specifies how to build what is called a singleton. As the name implies, this is an object where there is only a single instance. The syntax is very much like that of a class other than you cannot pass in arguments. This makes sense as you pass the arguments to a class when you use new, and you never call new with a singleton object, because the declaration creates it in the current scope. Any data members or methods you want can be declared in the object declaration.

Even though an object declaration does not create a new type, you use a capital letter as the first letter in it to distinguish it from normal instantiated objects. To use the members of an object, use the object name and call it like you would for an instance of a class. object declarations can be used in any scope where you want an object, but only one object of that type. At the top level they are typically used as a place to organize functions, which have far more versatility than this one.

### 16.2.4.1 Applications

The fact that you can use an object without instantiation is very significant. The objects effectively exist as soon as the program starts. You do not have to have a line that makes a new one. This is most significant when we move beyond REPL and scripts into applications. A top level object declaration defines an entry point to an APPLICATION it contains a method that takes an argument of type Array[String] and results in Unit. Here is a simple example

```scala
object Firstapp
def main(args:Array[String]):Unit = {
  println("My first application.")
}
```

The scripts we have been using can be converted to applications by doing nothing more than pasting the code of a main that is an object. If you use the variable name args for the command-line arguments, then references to them in a script will work fine.

The difference between a script and an application is how you organize the code in files and when you run them. By definition, a script is supposed to be a small program. All of the code for a script goes into one file. When the amount of code that requires gets larger, it needs to be split.
