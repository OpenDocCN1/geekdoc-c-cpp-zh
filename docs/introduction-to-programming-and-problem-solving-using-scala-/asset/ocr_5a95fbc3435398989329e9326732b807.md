The reason the BufferedSource is just an iterator is not hard to understand. Remember, reading files is extremely slow. You should do it once and get the information that you want that time. Reading it over and over again would be inefficient. To force yourself forward toward efficiency, you would have to explicitly reset the file or open it up to iterate through it again. In addition, files can be very large. The advantage of the Iterator is that it only needs to keep the current contents in memory, not the entire file. In contrast, the Array and List need to use memory for everything they store.

With the List and Array types, you are parametric. You can make a List [Int] or a List [String]. This is also true of Iterators. The Source and BufferedSource types are typically Iterator (Char). This means they operate on individual characters. The call to next above illustrated. Also, if you call functions like map or filter, or if you convert the Iterator to a List or Array, the result will be a bunch of characters. We can see this explicitly here.

```
scala newSource.toList
res4: List[Char]
```

Note the character 'T' is because it was consumed by the call to next. Converting an Iterator to an Array or List only takes the elements that have not yet been iterated through. It also consumes the Iterator in the process.

While all the data you want is in form of characters, it can be a bit difficult to do what you really want to do with it in format. For reason, there is a method getLines[String] that will give you a different Iterator. This new Iterator is of the type Iterator [String] and each element is a full line in the file without the newline character at the end.

```
scala val lines = fileSource.reset.getLines
lines: Iterator[String] = non-empty iterator
```

```
scala lines.next
```
