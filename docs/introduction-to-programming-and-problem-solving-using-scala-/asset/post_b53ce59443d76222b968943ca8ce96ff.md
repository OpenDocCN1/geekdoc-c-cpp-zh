## 9.3.4 Other Options (Java Based)

The advantage of using a scala.io.Source is that you get a Scala Iterator that has all the methods you have gotten used to working with the List and Array types. However, that does not mean that Source is your best option. For some situations, you might find that the java.util.Scanner class is better.

The java.util.Scanner has methods for reading specific types of data as well as checking if there are specific types of data available. Here is a sampling of the methods that are available in java.util.Scanner.

- * hasNext():Boolean - Check to see if there is another "word"
- *hasNextDouble():Boolean - Check to see if there is a Double to read.
- *hasNextInt():Boolean - Check to see if there is an Int to read.
- *hasNextLine():Boolean - Check to see if there is a line of text ready to read.
- * next():String - Read the next "word".
- * nextDouble():Double - Read the next Double.
- * nextInt():Int - Read the next Int.
- * nextLine():String - Read the next line of text.
- * useDelimiter(pattern:String) - Change the pattern used for the delimiter.

This list be fairly self-explanatory. The only thing one might wonder about is why "word" is in quotes. The reason for this is reflected in the last method listed. When you want to read a "word" with a Scanner, it will read up to the next delimiter, whatever happens to be. By default it is any grouping of white space.

In order to use a Scanner, you first have to make one. To do this you would probably want to import java.util.Scanner and use the following expression.

```
new Scanner(file)
```

The file needs to be an expression that the type java.io.File which we will also make with a new expression. Putting this together, you could put something like this into a program to read and print a bunch of Ints if you have a file with integers separated by space. Note that this would not work on our file called "numbers.txt" because of the commas and the fact that the values in that file are Doubles.

```
import java.util.Scanner
import java.io.File
```

```
val sc = new Scanner(new File("numbers.txt"))
while (sc.hasNextInt()) {
  println(sc.nextInt())
}
sc.close()
```

## 9.4 Writing to File

Scala does not provide any functionality for writing to files in its own libraries. That is something that is already supported by Java and Adding Scala libraries has not been seen as a significant benefit. There are many ways to set up a file to write in Java. The easiest approach, and the one that we will use, is the java.io.PrintWriter. We can make a new PrintWriter with new and telling the name of the file we want to write to. So we can get a PrintWriter that we can use for doing output with this code.

```
import java.io.PrintWriter
val pw = new PrintWriter("output.txt")
```

Now we could call on pw which will cause things to be written to that file. You can use print and println methods to print the file in the same way that you have done using those functions in Scala to print standard output.

Using this we could write the code to print 100 random points with x and y values between 0 and 1.

```
for (i <- 1 to 100) {
  pw.println(math.random() + " "+math.random())
}
pw.close()
```

The last line is critical because the PrintWriter is also used as a file resource with buffering, just like the BufferedSource. However, it holds things in memory until there is enough to make it write to the disk. If you do not close the file, the file in the buffer will not have been written out. If you are not done with the file, but you want to make sure that you have written into the file, you can use the flush method.

flush

When you call this, anything in the buffer will be written out. This way the computer crashes, loses power, or something goes wrong, that information will be out of the volatile memory.

## 9.4.1 Appending to File

Creating a PrintWriter in the way just described has the side effect that it will either create a new file or delete an existing one and write over it. If there is an existing file and you want to append to the end instead of overwriting, there is one more step that needs to be added. Instead of simply telling the PrintWriter file name to use, tell it a java.io.FileWriter to use. When we create a FileWriter we can tell it the file name and give it a Boolean value... If the value is true, the contents of the existing file will be left in place and anything written will go to the end of the file. If it is false it will behave like what we had before. So if you wanted to append to the output.txt file you can do the following.

```
import java.io.FileWriter,PrintWriter;
var pw = new PrintWriter(new FileWriter("output.txt",true));
```
