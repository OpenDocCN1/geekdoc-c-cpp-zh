## 15.6 Mazes

Another class of problems that works with recursion is involving mazes. This might also seem to be more for recreation, but mazes are a simplified case of something called graphs which are very important in computer science and mathematics and are used to represent all types of different problems. The same approaches that we will use here for mazes apply to graphs as well. There are also many applications where doing like finding the optimal route through restricted path maze is significant.

To keep things simple, we are going to use a basic approach to building our mazes. Instead of having a grid with walls between cells, we will have a grid where squares can be empty or occupied by values that tell us if there is a wall or not. In theory we could use a 2-D Array[Boolean] for this purpose, but in practice we will have use of being able to put numeric values with the code like the following. Array Array[Int] will be more practical.

This builds a 2-D Array of Ints that uses 0 to represent an open square and a -1 to represent a wall. The use of -1 for a wall is intentional so that positive numbers can be used to represent other things later. This particular maze is 10x10 in size. This is a good size to start off for our purposes that most people would probably want to do with a maze.

Our first task is the thing that most people would probably want to do with a maze. To start, we want to know how to get through it in the shortest path of steps. The shortest path has this significant advantage over just returning a path. If it is only a simple numeric value, it is also unique. There can be multiple paths with the same length. That produces ambiguity. It also happens that having a function to find the length of the shortest path is sufficient to find it, as such function can be used to construct the optimal path even though such construction is less than optimal.

You can write a function to find the length of the shortest path using loops, but it is fairly complex code. We can write a simpler solution using recursion, and the recursive approach will easily adapt to solving other problems as well. As with recursive functions, we can break the solution down into two parts, base cases and recursive cases. The base cases are two good base cases for the maze problem. One base case is if you reach the exit. If you are at the exit it takes zero steps to get out. Another base case is if you are checking a location which is out of the maze or in a wall. For we want to return a value that could not possibly be a solution. We will come back to specifically what that value should be after discussing the recursive cases.

Picture standing at a location somewhere in the maze, and you want to know how many steps it takes to get from your current location to the exit on the shortest path.

The recursive way to do this is to imagine that you have an oracle that could tell you the answer from any of the neighboring squares and figure out how you would combine values to determine the distance from where you are. As we said earlier in the chapter, we write a recursive function by assuming we have one works, and we base on that assumption. Once we are done, assuming we have handled the cases properly, it will work. The oracle is our assumed working function. If you are in a maze and you can ask the oracle to tell how many steps it takes to get out of the path to the north, south, east, and west, how would you use that information to determine the shortest distance from where you are?

To make this more concrete, picture yourself at a four intersection. You ask the oracle about each direction and get values of 7, 13, 4, and 19. The shortest path lies in the direction that you give back 4. However, that is the distance from one step in that direction. The minimum distance from where you are one greater than, or 5 steps. It is the minimum of four, one step to get to that location. The solution of taking the minimum also points in the proper direction for the base case of hitting a wall or going out of bounds. If the best solution is minimum, we return a number that cannot possibly be for a bad path. A large number such as one billion will suffice for any maze. You might be tempted to use Int. MaxValue, but remember that we are adding 1 to it. Try Int.MaxValue+1 in the REPL and you will see that this is not an ideal choice.

The whole function is built if expressions. The first option is going out of bounds, hitting a wall, or coming one of our breadcrumbs, and it returns one billion, a number so large it cannot possibly be a valid path, but one small enough that we will not overflow it by adding 1 for other steps through the maze. The second case is where we have reached the end. These two can be reversed and would need to be if the exit were outside of the bounds or marked by a special value in the array. The last case is the recursive case which drops a breadcrumb and returns. This code uses four recursive calls and combines them with min, then picks up the breadcrumb and returns. This code could be invoked with this call.

```scala
def shortestPath(maze:Array[Array[Int]], x:Int, y:Int, endX:Int, endY:Int): Int = {
  if (x < 0 || y < 0 || x >= maze(y).length || y >= maze.length || maze(y)(x) != 0) {
    1000000000
  } else if (x == endX && y == endY) {
    0
  } else {
    var dist = shortestPath(maze, x + 1, y, endX, endY) min
    dist = shortestPath(maze, x - 1, y, endX, endY) min
    dist = shortestPath(maze, x, y + 1, endX, endY) min
    dist = shortestPath(maze, x, y - 1, endX, endY) + 1
    dist
  }
}
```

```scala
println(shortestPath(maze, 0, 0, 9, 9))
```

This function literally tests every single path through the maze and gives us the shortest. There are strengths and weaknesses to this approach. The weakness is that if there are a lot of paths this could take a while. We explore that more and consider ways to address it in Object-Orientation, Abstraction, and Data Structures Using Scala[1]. The strength of trying every path is that it takes only very minor modifications of this code to produce other functions as one to find the longest path or to count how many paths there are. These particular problems are left as exercises for the student, but we will tell you now that the only real changes are to alter the return values of the base cases and the way in which the recursive calls are combined.
