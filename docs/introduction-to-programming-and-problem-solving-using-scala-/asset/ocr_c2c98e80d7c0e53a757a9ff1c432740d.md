# 15.3 Fibonacci Recursion

The classic example of recursion is Fibonacci numbers. This is a sequence of numbers
where each number is defined as the sum of the previous two. In mathematical notation
this is written as $f(n) = f(n-1) + f(n-2)$. This is not a complete definition, however,
because we need to know how the sequence starts. That is to say that we need a base case
for the recursion. It is customary to have the first two elements be 1. So, the sequence then
is 1, 2, 3, 5, 8, 13, ...

We can write this function in Scala with short function definition.

```
def fib(n):Int = if (n<=2) 1 else fib(n-1)+fib(n-2)
```

For n=1 and n=2 we get 1. For n=3 we get 1. For larger numbers, the process
is more complex, and it is instructive to visualize it. We do this by considering what
happens on the call stack in a manner similar to figure 15.1. Unlike the code for figure 15.1,
this function calls itself twice and that makes things a bit more complex.

For example, a call to fib(4). This is equal to fib(3)+fib(2). In order to know
what is true, recursive calls have to be made to each of those functions. By convention, we
imimagine that the calls are processed from left to right. Unlike examples we
have seen before, when fib(3) returns, there is another call to fib(2) still waiting. We
immediately a new stack frame appears where the one for fib(3) had just been. This
process of stack frames being removed to be replaced with new ones happens a lot in this
calculation of the Fibonacci numbers as well as other recursive functions that themselves\more than once. Instead of drawing it as a vertical stack as was done in figure 15.1, it
is customary to draw it in a branching structure called a tree as is drawn in figure 15.2.
Each new stack frame is still below the one it called, but different stack frames at the
same depth in the stack are drawn to next horizontally. Arrows are used to
keep track of things.

In this representation, boxes represent the stack frames. We have dispensed with the
function names and left only the argument value. The straight arrows show function
calls. The curved arrows show and are labeled with result values. These types of
diagrams can be very helpful when you are trying to see what happens in a
complex recursive function. When you draw them yourself can dispense with the boxes
arrows. Arrows with lines between them typically suffice.
