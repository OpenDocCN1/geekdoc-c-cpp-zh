There are a few things in this code that are worth taking note of. Lines 37-49 include a companion object. This serves two main purposes in this code. The first is a place to store the three constants that tell us the account type. If these values were put in the class, then every instance of the class would get their own copy. As they would all have the same values, this would be wasteful. The object is a singleton though, putting them in the companion object means we get a single copy of each. In the class we refer to these two locations. One line is a check to make sure that the accountType that is passed matches one of the allowed values. The other reference is in monthlyAdjustment. Note that in both of these locations, the references to the account are prefixed with the name of the object.

The other use of the companion object is to ensure that all instances of the Account have unique IDs. The private keyword appears in front of the argument list. This has is some syntax that we have not previously introduced before. This has the effect of making instantiation private that nothing outside this file can call new(...). If we did not have this, code could create new account instances with the same ID. Instead, we have added an apply method into the companion object and must use this method to make accounts with the syntax apply(...). Note that the apply method does not take an ID as an argument. Instead, there is a private var declared in the companion object that keeps track of the next account number to. Inside of apply, this unique prefix is used to make a string long characters, and that is used as the ID in a call to new. The apply method also increments the value of nextAccount so that subsequent accounts will have a different ID. The combination of apply and making instantiation private means that outside can never create two accounts with the same ID.

Line 3 of Account.scala shows our first usage of this. The Account and Customer classes have a mutual dependence. Instances of Account have be constructed with a reference to a Customer, and the Customer instances keep track of the accounts they have. To deal with this, we have added line 3 to the Account that will automatically add the new Account instance to the customer it refers to.
