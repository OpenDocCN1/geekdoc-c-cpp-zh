```
def getAndClear(lst:List[Int],index:Int):(Int,List[Int]) = {
  lst(index), lst.zipWithIndex.map( tuple => {
    val (n,i) = tup
    if (i == index) 0 else n
  })
}
```

There is only one exception in this function, the tuple to return. The first element in the tuple is (index). It looks up the proper value and uses the value there. Remember that looking things this way on a List is not efficient, but we have to do so to give a List and an index. The second part of the tuple is a bit more complex. It calls the method zipWithIndex on lst. The first line is a List that pulls the two parts out of the tuple. We need the index in order to decide if it is the one to be cleared or not. If we were clearing based on value instead of position this would not be needed.
The map is immediately called on the List of tuples, and it is given a function called tup, short for tuple. This function literal uses curly braces and has two lines. The number from the List is called n and the index is called i. The function returns with an expression that gives the value of 0 or n based on i is the same as index.

Substituting for a value in a List is a common enough that the API calls a method to do it for us. So we can create a simpler version of getAndClear for a List that uses the updated. This method takes an index and returns a modified list.

```
def getAndClear(lst:List[Int],index:Int):(Int,List[Int]) = {
  lst(index), lst.updated(index,0)
}
```

Another approach would be to pull off the elements before and after the index and then stick them together with a 0 between them.

```
def getAndClear(lst:List[Int],index:Int):(Int,List[Int]) = {
  lst(index), lst.take(index)::lst.drop(index+1)
}
```
