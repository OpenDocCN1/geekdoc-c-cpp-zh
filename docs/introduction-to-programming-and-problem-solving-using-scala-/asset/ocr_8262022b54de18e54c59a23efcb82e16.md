# Recursion 15.3: mergeSort.scala

```
def merge(lst1:List[Int], lst2:List[Int]):List[Int] = (lst1,lst2) match {
  case (Nil, _) => lst2
  case (_, h1) => h1
  case (h1::t1, h2::t2) =>
    if (h1<h2) h1 :: merge(t1, lst2)
    else h2 :: merge(lst1, t2)
}
```

```
def mergeSort(lst:List[Int]):List[Int] = lst match {
  case h::Nil => lst
  case _ =>=>
    val (l1, l2) = lst.splitAt(lst.length/2)
    merge(mergeSort(l1), mergeSort(l2))
}
```

Both of the functions use pattern matching for the different cases in the recursion. This makes them nice, short, and easy to read. Unfortunately, the recursive version of merge has to allocate a new stack for every element that is merged. That means that this version of the code cannot scale to large sizes.

To get around this limitation we need to use a more imperative merge that works with a while loop. Such a version might look like the following.

```
def merge(lst1:List[Int], lst2:List[Int]):List[Int] = {
  var lst1 = lst1
  var lst2 = lst2
  var ret = List[Int]()
  while (lst1.isNotEmpty && lst2.isNotEmpty) {
    if (lst1.head<lst2.head) {
      ret += lst1.head
      lst1 = lst1.tail
    } else {
      ret += lst2.head
      lst2 = lst2.tail
    }
  }
  if (lst1.isNotEmpty) ret += lst1.reverse
  else ret += lst2.reverse
  return ret
}
```

This version is not as pretty and is about twice as long. However, it handles significantly larger Lists making it useful if you actually have a large set of data.

One thing to note about merge sort is the way in which it works. As the recursive calls go down the stack, very little happens. The Input gets split in half and those two halves get passed down. This repeats until a single element remains. The real work happens as the recursion pops back up the stack. Before a function can return, it calls merge, which does the work. So if you picture in your head like 15.1, the downs are not associated with much work.
