To make it work with different sorts, we need to pass the sort function as an argument. The following function does this for us.

```
def timeFunc(sortFunc:(Array[Double])=>Unit, a:Array[Double]):Unit = {
    val copy = Array.tabulate(a.length)(i => a(i))
    val start = System.nanoTime()
    sortFunc(copy)
    val end = System.nanoTime()
    println("Time:" + (end-start)/1e9)
    assert(isSorted(copy))
}
```

The print statement divides the difference by 1e9. This gives us a back in seconds instead of nanoseconds which is much easier for us to read and deal with. We invoke by putting the code at the end of our script.

```
val nums = Array.fill(args(0).toInt)(math.random)
args(1) match {
    case "bubble" => timeFunc(bubbleSort, nums)
    case "flagged" => timeFunc(flaggedBubbleSort, nums)
    case "min" => timeFunc(minSort, nums)
    case "insert" => timeFunc(insertionSort, nums)
    case "shell" => timeFunc(shellSort, nums)
}
```

Make sure to use the function that do not have calls to the rendering core when you put this there.

If you play around with this some you will notice a few things. First, you have to get up to at 10000 numbers in the Array before the timing means. If the Array is too small, the sort will be so fast that the resolution of the machine's clock will become a problem. Second, the amount of time spent doing the sort can vary on different invocations. For this reason, any true attempt to measure performance will run the code multiple times and take an average of the different values.

# # Radix Sort (Advanced)

The sorts discussed earlier in this chapter require nothing than the ability to compare elements. There are situations where you have more information about the values, and you can use them to sort more efficiently. Examples of such non-general sorts include BUCKET SORT and RADIX SORT. Both use knowledge of the data being sorted to break them into groups.

To understand this work, consider the situation where you are in a large room of letters to sort and you are in a name. Many people would start off by going through the stack and breaking it into different piles. The piles would be for different parts of the alphabet. If the original stack were really large and you had a really big room, you might make one sort for each starting letter.
