The indices in Strings begin with zero, so 'a' is at index 0, 'b' is at index 1, 'c' is at index 2. Calling substring with an argument of 2 gives back everything from the 'c' syntax to the end.

The version of substring takes two arguments allows us to demonstrate a different syntax where we leave out the dot. In this case, the first argument is the first to take and the second one is one after the last index to take. In math terms, the bounds are inclusive on the low end and exclusive on the high end. The fact that there are two arguments mean that we have to parentheses group together the two arguments, However, we are not required to put the dot, and the method name can just be between the object and the arguments. Here are examples using the normal syntax and the version without the dot.

```scala
scala "abcd".substring(1,3)
res21: String = bc
```

```scala
scala "abcd" substring (1,3)
res22: String = bc
```

The space between the method and the parentheses is not required. Remember that in general Scala does not care about spaces as long as they do not break up a token. In this book, we will typically use the standard method calling notation, but you should be aware that variations exist.

There are other types that worth noting before we move on. One is the type Unit. The Unit type represents a value that carries no information. There is a single object of type Unit. It is written in code and prints out (). We have actually seen an example of code that uses Unit. Another significant type in Scala is the TUPLE. A tuple is a sequence of a specified number of specific types. a collection of values that is strict about what type of values it has. We can make tuples by simply putting values in parentheses and separating them with commas as seen in the following examples.

```scala
scala (5,6,7)
res23: (Int, Int, Int) = (5,6,7)
```

```scala
scala "book",200
res24: (String, Int) = ("book",200)
```

```scala
scala (5.7,8,'f,'a string')
res25: (Double, Int, Char, String) = (5.7,8,f,"a string")
```

The tuples in Scala provide a simple way of dealing with multiple values in a single package, and they will come occasionally through the book. Note that we express a tuple type in Scala is to put the type of values of the tuple in parentheses with commas them them, just like we do with the values to make a tuple object.

Tuples with only two elements can have special meanings in some parts of Scala. For that reason, there is an alternate syntax you can use to define these. If you put the tuple -> between two values, it will produce a 2-tuple with those values. Consider the following

> The equivalent in other languages is called void.

```scala
scala 3 -> "three"
res26: (Int, String) = (3,"three")
```

The -> will only produce tuples with two elements. If you try using with more than two elements you can get interesting results.

```scala
scala 4 -> 6
res27: ((Int, Int), Int) = ((4,5),6)
```

So if you want tuples more than two elements, stick with the parentheses and comma notation.
Once you have a tuple, there are two ways to get things out of it. The first is to use methods named _1, _2, _3, etc. So using res21 from above we can do the following.

```scala
scala res25._1
res28: Double = 5
```

```scala
scala res25._3
res29: Char = f
```

The challenge with this method is that method names like _1 are not very informative and make code difficult to read. We will see an alternative approach in section 2.7 that requires a bit more typing, but can produce more readable code.

## 2.5.1 Binary Arithmetic

Now that you know how to go from binary to decimal and decimal to binary, just like decimal, let's take a minute to do some arithmetic with binary numbers. It is certainly possible to do this by converting binary to decimal, doing the arithmetic in decimal, converting back to binary. However, this is quite inefficient and not worth it because really not hard to work in binary. Instead, it is easier to work in binary than in decimal. Let us begin with the operation of addition. We want to add the bits one column, from right to left. Just as you would do exactly what you would with long addition in decimal. As with decimal numbers, you start by adding the bits one column at a time; when the sum in one column is a two-bit number, the least significant part is written down as part of the total and the most significant part is "carried" to the next left column. The biggest difference between decimal and binary addition is that in binary there is a lot more carrying. Here is a problem solved without showing the carries.

```
110101
+ 101110
------
1100011
```

Here is the same problem, but with numbers written above to show when there is a carry.

```
 111
+101101
------
1100011
```
