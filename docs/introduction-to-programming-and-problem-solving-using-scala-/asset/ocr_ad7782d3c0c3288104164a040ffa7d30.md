# 15.4 Towers of Hanoi

Our next example of this more powerful recursive functions is somewhat playful. You have likely seen and perhaps played Towers of Hanoi. It is a “game” played with three pegs and a number of disks of different sizes that have holes in them; so, they can be put on the pegs. Your goal in playing is to move the disks from one peg to another following two rules:

+   1. You can move one disk at a time.

+   2. No disk can be placed on a smaller disk than it.

We want to write a program that can solve this. To do so, we need to first analyze the problem bit more.
If you start picturing a peg with 7 disks on stacked from largest to the bottom to the smallest and to pick the solution, you will probably have a hard time. The first step is to clear the top disk to one of the other pegs, but which one? It gets more complex from there. Instead of trying to solve a hard problem, we should start with an easy problem and try to build up from there.

The easiest setup to solve is when you have only one disk. Move the disk from where it started to the peg you want to finish on. This was bit trivial, so how are two disks? If you want to move the top disk to the peg you do not want to end on, then you move the second to the end peg and move the smaller one on top of it. It might not clear at this point, but points towards a general solution. To see this, think of the situation with three disks. We could run through every single move, but we just saw how to move two disks so we know how to do that. Using that, we move two disks to the middle peg. Note that we use the approach we developed to move two disks in three separate moves. Then the largest is moved to the end peg and the two disks are moved on top of it.

This points to a general solution. If we make the assumption that we know how to move N - 1 disks, we can move N disks by first moving the N - 1 disks to the off peg, moving the largest one to the destination, then the N - 1 disks back on top of the largest one. This is a recursive definition. A function for N disks relies on the solution to N - 1 disks. The base case is one where we move a single disk across.

We now have an approach to solving this problem. Next we need to figure out how we want to represent the problem in the memory of the computer. We can use a way to represent pegs and disks. For the disks, all we really care is the size of the disk. This can be represented by an Int or a List of Ints. To decide which, we should consider how they are used. The number of disks on a peg changes over time, but they are always added or removed at one location, the top of the stack. By using a List where the head of the List is the top disk. We can use :: to add a disk to a peg and the tail to what is left when a disk is removed. The script below shows code that implements the three pegs as an Array[List[Int]]. A check to make sure we are not breaking the rule.

Listing 15.1: hanoiText.scala

```
val num = if (args.length>0) args(0).toInt else 7
val pegs = Array(List.tabulate(num)(i => i=+2), List[Int](), List[Int]())
```
