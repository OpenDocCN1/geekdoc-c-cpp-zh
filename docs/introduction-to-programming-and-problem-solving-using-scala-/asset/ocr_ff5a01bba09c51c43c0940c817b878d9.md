# Object-Orientation

With that in place, we can start our implementation of the Bank class giving it collection for the accounts. We also add methods to add and find the accounts. The method to find an account is the apply method.

```
class Bank {
  private var accounts:List[Account] = Nil

  def addAccount(account:Account):Unit = accounts ::= account

  def apply(accountID:String):Option[Account] = accounts.find(._id == accountID)
}
```

The apply method returns an Option[Account] because it is possible that there is no account with the provided ID. In that situation, it would return None. After setting up an instance of Bank and some accounts, you could search for one by ID using bank("01234567"), which would give back an Option[Account] for an account with ID "01234567".

# 16.2.3 this Keyword

By default, when you write code in a class that calls a method or uses a member of the class, the call is made on the current object or the value from the current object is used. All calls are implicitly made on the current instance. That is exactly what you want most of the time and the scoping of variables feels very natural. This implicit specification of an object prevents from having to specify which. Consider the code deposit method for adding money to the bank. We wrote

```
_balance += amount
```

which is really short

```
this._balance += amount
```

Scala simply added this for you.
That is fine in general, but occasionally you will have a need to be able to put a new to the current object. you might need to call a function/method that needs an instance of the object as an argument and you want to use the code that is currently executing. When situation arises you will use the keyword. this is a name that always refers to the current instance in a class. In the bank example, we will use this in two ways when creating an account. We will use this to pass the current account to the Customer who owns it to set things up. We will also use this in the Customer to check if an account belongs to the current Customer as it would be an error to have a Customer taking ownership of an account for someone else.
