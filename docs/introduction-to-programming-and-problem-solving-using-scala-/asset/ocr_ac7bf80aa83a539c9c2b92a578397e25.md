# Nature of Programming

Every piece of software, from the BIOS of each device to the OS, and the multitude
applications they run, is a program that was written by a programmer. So what is this
thing we call programming, and how do we do it? How do we give a computer instructions
will make it do things for us? In one sense, programming is just the act of giving the
computer instructions in a format that it can work with. At a fundamental level, computers
do nothing more than with numbers. Remember the model in figure 1.2. Each cycle
the computer loads and executes it. There was a time when programming
done by the specific, low level instructions that the computer understands. We refer
to the language of these instructions as machine language. While machine language is
the only language that the computer understands, it is not a very good language for humans
to work in. The numbers of machine language do not hold meaning for humans,
it it is very easy to make mistakes. To understand this, consider the following code that
calculates a wage using the math wage = rate * hours with MIPS machine language.

```
100011 00000 00100 0000000000000 # Load rate into register 2
100011 00001 00111 0000000000000 # Load hours into register 3
000000 0010 0011 01100 00000 01100 # Multiplies 2 and 3,
and store in 4

101011 00100 00101 0000000000000 # Store result from register 4
```

This shows the instructions in binary; we will discuss binary in chapter 2. Spaces
have been inserted to it easier to see the parts of the instructions, and comments are
put in to explain each command, made of 32 bits and ls is doing. Real machine
code does not have spaces, comments, or even separate lines. The commands are generally
written/virtual in hexadecimal instead of assembly. So this code would look like

```
8c200008c23000432018ac850000
```

Even without knowing anything about programming, you can probably tell that this would
very hard to work with. For this reason, people have developed better ways to program
computers to write out machine language instructions.
The first step up from machine language is assembly language. Assembly language is
basically the same as machine language in that there is an assembly instruction for each
machine language. However, the assembly instructions are expressed as words,
known as mnemon, that describe what they do. The assembly language also helps to keep
track of how things are laid out in memory so that programmers do not have to actively
consider such issues the way they do with machine language. The machine language above
can be written as the following assembly instructions.

```
lw $s0, $s2, 0
lw $s1, $s3, 0
mult $s2, $s3, $s4
sw $s4, $s5, 0
```

The first group of six numbers in the binary machine code corresponds to an instruction.
For example, you can see that 100011 is \u033, which is short for 'load word'. To get the
computer to understand assembly language, we employ a program that does a translation
from assembly language to machine language. This program is called an assembler.
