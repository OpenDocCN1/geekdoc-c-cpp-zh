```
mlewis@mlewis-laptop:~/Desktop$ mv *.txt
```

Here we move all the files from our home directory that end with .txt into the current directory. This line with mv uses .. to refer to the directory above the current one and . to refer to current. Another way to use these commands is to enter two file names, where the first file will be copied to the second name with cp or renamed to the second name by mv. Assume that one of the files in the Desktop directory was named text.txt. After executing the following command we have copied file into a new file named test2.txt.

```
mlewis@mlewis-laptop:~/Desktop$ cp.txt test2.txt
```

If you want to remove a file, use the rm command. The rm command can be followed by one or more files. Again, wild cards can be used to match multiple files. Here we are getting rid of all the files that end with .txt.

Use caution when removing files on Linux systems with the command line, it is not forgiving and you cannot easily "undo" what was done. This is true whether you are using rm or if you use mv or cp to a file name when you already had a file of that name. Most of the GULs that you have used to move files delete to the store of trash can, really just a different delete and then allow you to clear that out, doing rm on a file deletes it at that moment. You cannot dig in the trash to find it. When you delete a file with rm on these systems, it is your only chance of getting it back is if you have a backup.^1

This can be especially dangerous with the way the command line deals with wilds and the dot. Take the rm command above. If you accidentally insert a space between the asterisk and you will delete every file in the current directory. This is because the * alone matches everything.2 Be careful when you are using rm and look over the command before you enter to make sure you did not mistake anything or insert unwanted spaces.

Directories exist to keep files organized. For this reason, you should probably create directories for each major grouping of work that you do. You might also need these to refine your organization scheme. You can make a new directory with the mkdir command. Simply follow the command with the names of one or more directories you want to create. For example, it is probably a good idea to make a directory to store all of the work for this project assignments/projects or the code you write. You might make sub-directories for different assignments/projects so that we do not clutter our Desktop directory, make a sub-directory projects in which we can store all of your assignment and project files.

```
mlewis@mlewis-laptop:~/Desktop$ mkdir projects
```

> ^1There is a i -option for rm, mv and cp that will cause the prompt to prompt you before any file is removed. It is not practical if you want to remove a lot of files, but it could be considered a good default for what you do.

> ^2There is one minor safety in place. The * alone does not match files that start with a ., hidden files would not be deleted in that. That will not make you feel better though if you have erased five different multi-hour coding projects.
