The code begins by creating a scene that has a Polyline that goes around the scene as well as a Circle that begins in the top left corner. Note that the perimeter line is added to a Var List called walls. This is used to keep track of all the shapes that the circle cannot go through.

The keyPressed handler is set to move the ball. To do this, it remembers the current location of the ball, then moves two pixels in the proper direction. It then uses a call to forall walls to see if this location would overlap any walls. This is done using a call to Shape.intersect. The result of that is a new Shape object that represents the intersection. To tell if this shape is empty, we call boundsInLocal, which gives us a Property. To get the actual bounds from the property we call value, then finally ask the bounds if it is empty. If the new position does intersect, the circle is set back to its initial position.

The three mouse handlers are all rather simple. When the mouse is pressed, a new Polyline is prepended to the front of walls using cons. This new shape is added to the contents of the scene, and the current point of mouse is added onto its set of points. The handlers for dragging and releasing the mouse simply append the mouse location to the Polyline at the head of walls, adding the most recent segment to line.

## 12.3 Images

Most applications that do graphics cannot do what they need just with shapes. Most of these types are provided by scalafax.scene.image. The most fundamental of these types is the Image type, which represents an image. These can be created using one of the:

- Image(url: String, requestedWidth: Double, requestedHeight: Double, preserveRatio: Boolean, smooth: Boolean, backgroundLoading: Boolean)
- Image(url: String, requestedWidth: Double, requestedHeight: Double, preserveRatio: Boolean, smooth: Boolean)
- Image(url: String, backgroundLoading: Boolean)
- Image(url: String)

The url argument specifies the source of the image data. These can start with "file": to pull the information from the local disk. The requestedWidth and requestedHeight arguments allow you to specify the size of the image if you want one that is different from the natural size of the image. The preserveRatio argument, if true, will cause the aspect ratio to be preserved. The smooth argument allows ScalaFX whether you want a higher quality filtering algorithm or a faster one. Lastly, the backgroundLoading argument allows you to let the program continue execute while image loads in the background.

The Image has height and width properties. The most significant method on the Image type is probably pixelReader: Option[PixelReader]. This will provide a PixelReader that allows the image in question for reading pixels. The details of the PixelReader are discussed later.

If your goal is to get an image to display in your GUI, the ImageView is a subtype of Node that serves this purpose. You can create one of these with new ImageView(url: String) or new ImageView(image: Image). After you have created it, you can set the fit to align the bounding box that the image is inside.

For many applications, it will be able to find out the color of individual pixels in an image. For purposes there is the PixelReader type, which allows you to get the type of information. At this point, two are significant are getRGB(x: Int, y: Int): Int and getColor(x: Int, y: Int): Color. Given the x and y coordinates of a pixel, these methods return the native ARGB value for the color or a Color value for it.

There is a subtype of Image called WritableImage. As the names imply, this type allows you to write to it. Specifically, you can create a PixelWriter, the counterpart to the PixelReader and set the value of individual pixels. To create a WritableImage, use one of the following:

- WritableImage(reader: PixelReader, x: Int, y: Int, width: Int, height: Int)
- WritableImage(reader: PixelReader, width: Int, height: Int)
- WritableImage(width: Int, height: Int)
