# 4.9 Putting Together

In the last chapter we also wrote conditional code for calculating the admission cost to the theme park. This makes a good example of a function as well. Here is that converted to a function.

Listing 4.6: EntryCost.scala

```scala
def entryCost(age:Int, cooler:Boolean, waterPark:Double): Double = {
  if (age<13 || age>=65) 20 else 35 +
  if (cooler) 5 else 0 +
  if (waterPark) 10 else 0
}
```

The information needed for the calculation is passed in and this function only does a calculation with the data, giving back a number.

Now we can put things together and write a script that will calculate the cost of a group of people with four members and the purchase of meals. We will assume that the whole group either brings a cooler or does not, that all either would go to the water park or not, and that they all order some size of combo meal. The following code could be put in a script with the entryCost and itemCost functions from earlier in the chapter.

Listing 4.7: ThemeParkBook.scala

```scala
def individualCost(cooler:Boolean, waterPark:Double): Double = {
  println("What is the person's age?")
  val age = readInt()
  println("What size combo are they ordering?")
  val size = readLine()
  entryCost(age,cooler,waterPark) + itemCost("Combo",size)
}
```

# Ways to run a Scala Program (Aside)

One that students occasionally struggle with is figuring out how they should run their Scala programs. There are three ways you can run Scala. Two of these you have seen: REPL and scripts. A third, compiling to applications, will be dealt with later. To use the REPL you enter scala on the command line with no file to execute. To run a script, give it a file name ends with .scala. At first it might seem that these two approaches are completely distinct. However, the REPL has a :load command that you can use to load code from a Scala file. Using this, it is possible to load a script into the REPL. There are times when this can be handy, but you need to understand the difference between these two approaches.
When you run a script, the only thing that the user sees is the values are printed out. If your file does not contain a print statement, nothing will be shown on screen and it will appear to the user that it did not work. If the file has val declarations, statements beginning with val, var, or def (there are other types of declarations that we will learn about later, but these three cover what we know at this point), the script does not really do anything. You have to have statements that use the declarations for them to matter in the script.

This is not the case when you load a file into the REPL. In that usage, feedback is shown for every declaration in the form of a line that is printed with the type and

value of the declaration. If you declared functions in the file, you can call them in the REPL after the file has been loaded. For this reason, files you load into the REPL do not always need statements at the end that call functions, and they often do not print statements to display output.

Basically, the REPL gives you the ability to "play around" with the code. Using a script simply runs it and does what it says. You should ask your instructor about this, but odds are good that any code you submit for grading should be in the form of a script that includes calls that demonstrate the functionality of the script and prompt users for input. In this case, you can use the :load option in the REPL when you are working on the program, before you turn it in, make sure it runs properly and does what you want used as a script.

## 4.10.1 Problem Solving

The material covered in chapter adds flexibility. Functions in programming are similar to those from math. We also learned in this chapter about functions that are called only for side effects. We now know these can be general. Functions help break problems into smaller pieces.

The value of the parameters is determined at the time the function is called. Information is passed through formal parameters.

Functions are declared in Scala using def. This is followed by the function name, an argument list, a result type, and then an equal sign with the expression. Result type can be left off and inferred, but it is recommended you include it anyway.

- 1. Call functions for side effects.
    - A variable with `var`.
    - A function with `def`.
- 2. Declare something:
    - A function with `type`.
    - A function with `def`. To give something meaningful name.
- 3. Assign a value to a variable.
- 4. Write an if statement.
