# Introduction to Programming and Problem-Solving Using Scala

```
scala> val h=compose(plus5,square)
h: Double => Double = <function1>

scala> val j=compose(square,plus5)
j: Double => Double = <function1>

scala> h(3)
res0: Double = 14.0

scala> j(3)
res1: Double = 64.0
```

The function $h(x) = x^2 + 5$ while $j(x) = (x + 5)^2$. You can see that when we call these with an argument of 3, we get values of 14 and 64 respectively, just as would be expected.

We define the same $h$ and $j$ using function literals as.

```
scala> val h = compose(+5, x => x*x)
h: Double => Double = <function1>

scala> val j = compose(x => x*x, +5)
j: Double => Double = <function1>

scala> h(3)
res5: Double = 14.0

scala> j(3)
res6: Double = 64.0
```

If you had no real need for the functions plus5 or square, you would likely use this latter format. They would be defined with `def` if you had a need to refer to multiple times.

# 4.8 type Declarations

Scala provides a mechanism that allows you to provide alternate names for types. This can provide significant power when combined with concepts like abstraction that are beyond the scope of a first-semester course. However, for now, it can be used to help you short meaningful names for tuple types that you use commonly.

The syntax of a `type` declaration begins with the keyword `type`. This is followed by the name you want to give the type. With other names, you should pick something that is meaningful to you so that when you are reading through code, having this name helps it to make more sense. Unlike `var`, `val`, and `def`, it is the general style for type names to being with capital letters.
