
# Introduction to Programming and Problem-Solving Using Scala

The scala.xml package contains the types related to XML. We will run through some of the most significant ones here.

- Elem - Represents a single element. This is a subtype of Node.
- Node - Represents a more general node in the XML document. This is a subtype of NodeSeq.
- NodeSeq - Represents a sequence of Nodes.
- XML - A helper object that has methods for reading and writing XML files.

There are quite few other types that you can see in the API, but we will focus on these as they give us the functionality we need for our purposes.

## 14.2.2 Parsing XML

Once we have this Elem object stored in res4, the question becomes how you get the information out of it. The NodeSeq type, and the Node and Elem types which are subtypes of it, declare operators \ and \. These operators are used to search inside XML the contents of an object. Both operators take a second argument of a String that gives the name of what you want to look for. The difference is how they search. The \ operator looks for things at the top level, either Nodes in the sequence if we have a NodeSeq, or children of this node if we have a Node or Elem. The \ on the other hand, finds anything that matches at the current level. To illustrate this, we will do three examples.

```scala
scala res4 \ "student"
res5: scala.xml.NodeSeq =
NodeSeq(<student name="Bender" name="Quinn">
  <quiz grade="88"></quiz>
  <quiz grade="100"></quiz>
  <quiz grade="90"></quiz>
  <test grade="94"></test>
  <assignment grade="100">
    Code compiled and runs free.
  </assignment>
</student><student name="Hughes" name="Jason">
  <quiz grade="85"></quiz>
  <quiz grade="78"></quiz>
  <test grade="67"></test>
  <assignment grade="20">
    Code did not compile.
  </assignment>
</student>)
```

```scala
scala res4 \ "test"
res6: scala.xml.NodeSeq = NodeSeq()
```

```scala
scala res4 \ "test"
res7: scala.xml.NodeSeq = NodeSeq(<test grade="94"></test>, <test grade="67"></test>)
```

The two searches use the \ operator. The first one searches for elements that have the name "test". The second search looks for tags that have the name "test" and gives back a NodeSeq with them. This search returns an empty NodeSeq. This is because there are tags with the name "test" in res4, they are nested deeply inside of the "student" elements as such, are not found by the \ operator. The last example searches for the "test" tag name again, so so with \, which searches deeply, and gives back a NodeSeq with two Nodes inside of it.

The \. operators can also be used to get attributes from elements. To get an attribute index of a tag, simply put "@" at the beginning of the string you are searching for. Here are three examples to illustrate this.

```scala
scala res4 \ "name"
res8: scala.xml.NodeSeq = CSCI 1320
```

```scala
scala res4 \ "grade"
res9: scala.xml.NodeSeq = NodeSeq()
```

```scala
scala res4 \ "grade"
res10: scala.xml.NodeSeq = NodeSeq(98, 100, 90, 94, 100, 85, 78, 67, 20)
```

## 14.2.3 Building XML

So now you know how to get the contents of an XML file into one Scala. What about going the other way? Assume that the code we just wrote was used in the menu based application from chapter 10 and that changes were made and now we want to write the results back out file. The first step in this would be to build the Node represents the data.

We saw above that can put XML directly into a Scala program or the REPL and it will be parsed and understood. However alone does not give the ability to put values from the program back into the XML file. Fortunately, is not hard to do either. Inside of XML that is embedded in a Scala program can enable Scala expressions using curly braces. We will start with a simple example.

```scala
scala:<tag>4+5 is (4+5)</tag>
res19: scala.elem = <tag>4+5 is 9</tag>
```

Here the expression 4+5 has been put in curly braces, and as you can see it evaluates to value 9 as it should. The code you put inside the curly braces can be far more complex build additional XML content or.

We will use this to write a function that parses a Student object into an XML node. This code looks like the following:

```scala
def studentToXML(student:Student):xml.Node = {
val nameParts = student.nameParts(" + ")
<student name=${nameParts(0)} name=${nameParts(1)}>
${student.quizzes.map(q => <quiz grade=${q.toString()}>)}
${student.tests.map(t => <test grade=${t.toString()}>)}
${student.assignments.map(a => <assignment grade=${a.toString()}>)}
</student>
}
```

The first line splits the student name into pieces around spaces. It is assumed that the first element is the first name, and the second element is the last name. These are used as attribute in the student tag. Inside of that are three lines of code, each of quizzes, tests, and assignments. Each of these maps the corresponding List to a of elements with grade attributes.

It is worth noting things about using code for the attribute values. First, the quotes are not written anywhere. They are automatically provided when the value is Scala code. Second, the type of the Scala for the value has to be String. This is apparent with the grade values. They are Doubles and have to be explicitly converted to Strings.
