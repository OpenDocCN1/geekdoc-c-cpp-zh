def recurByDay(daysLeft:List[String], workerAvail:List[WorkerDays],
  schedule:List[WorkerAssignments]) {
  if (daysLeft.isEmpty) {
    printSchedule(schedule)
  } else {
    val day = daysLeft.head
    val thisDay = daysLeft.filter(_.dayOfWeek==day)
    val rides = thisDay.flatMap(_.ride).distinct
    val operatorRides = rides.flatMap(ride=>{
      val nums = thisDay.filter(_.ride==ride).map(_.numRiders)
      val avg = nums.sum/nums.length
      val rideData = rideInfo.find(_.name==ride).get
      Array(if(avg>rideData.rowCount) avg else 0)(ride)
    })
    recurByWorker(daysLeft.tail, workerAvail, WorkerAssignments(day, Nil)::schedule,
      workerAvail.map(_.name), operatorRides)
  }

This is a significantly more complex recursive function than what we looked at previously. It is worth taking some time to study what is going on. The recursion is broken into two separate functions that are nested in the primary function. The primary function does more than pull together the information on the days and then make a call to recurByDay.

As the name implies, the recurByDay function uses days as the recursive argument. Each level of the call stack has five elements on the daysLeft List. The base case is when daysLeft is empty. This function borrows code from the earlier version to build a full schedule for the week, and we are ready to print it. Use a List of rides with multiple names for the number of operators needed.

All of the information that comes from recurByDay, as well as other information that it figures out is passed into recurByWorker. This function recurs again meant to give us an image of what is going on. On each call, the base is when there are no more rides that need operators. The recursive case runs through all the riders that are trained to operate, and if any of them still need operators, one recursive branch is taken with that worker assigned to that ride. There is also a recursive branch at the end where the current worker is not assigned to work that day.

Note that the case of recurByWorker contains a call back to recurByDay so these are MUTALLY RECURSIVE FUNCTIONS. It is reasonably common in complex situations, when the recursion needs to run through a space that has several independent parameters, to break the problem up like this into different functions that handle cases in different options and depend on one another to get a complete solution.
