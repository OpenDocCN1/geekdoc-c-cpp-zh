## 5.7 Putting Together

Back to the theme park. Let's take some of the functions we wrote previously, and put them to use in a recursive function that is part of a script we could use at the front of the park where we sell admission tickets. The recursion will let us handle multiple groups paying for admission with any number of people. It will add up all the admissions costs so we can make a daily total. In addition, it will keep track of the number of groups and people that come in. The code for this makes the same assumptions we made before about groups in regards to coolers and the water park.

Listing 5.1: EntryGate.scala

```scala
def entryCost(age:Int, cooler:Boolean, waterPark:Boolean) = {
  if (age < 13 || age > 25) 20 else 35 +
  if (cooler) 5 else 0 +
  if (waterPark) 10 else 0
}
def individualAdding(num:Int, cooler:Boolean, waterPark:Boolean) = {
  if (num > 0) {
    println("What is the person's age?")
    val age = readInt()
    entryCost(cooler, waterPark) + individualAdding(num-1, false, waterPark)
  } else 0.0
}
def groupSizeCost():(Int, Double) = {
  println("How many people are in your group?")
  val numPeople = readInt()
  println("Is the group bringing a cooler? (Y/N)")
  val cooler = readLine() == "Y"
  println("Will they be going to the water park? (Y/N)")
  val waterPark = readLine() == "Y"
  (numPeople, individualAdding(numPeople, cooler, waterPark))
}
def doAdmission():(Int, Double) = {
  println("Is there another group for the day? (Y/N)")
  val another = readLine()
  if (another == "Y") {
    val (people, cost) = groupSizeCost()
    val (morePeople,moreGroups,moreCost) = doAdmission()
    (+morePeople, 1+moreGroups, cost+moreCost)
  } else (0,0,0)
}

val (totalPeople, totalGroups, totalCost) = doAdmission()
println("There were " +totalPeople + " people in " + totalGroups + " groups who joined a total of " + totalCost)
```

This code has two recursive functions, one for groups and one for people. The doAdmission function returns full groups. It asks each time if there is another group and if it uses groupSizeCost to get the number of people and cost for the next group, then adds those to the return of the recursive call. The group uses the recursive individualAdding function to run through the proper number of people, their age, and add them all.

An interesting point to notice about individualAdding is that the function takes a Boolean for whether or not there is a cooler, but when it recursively calls itself, it passes false for that argument. This is a simple way to enforce our rule that each group only brings in one cooler. If the initial call uses true for cooler, that will be used for the first person. Following calls will use a value of false, regardless of the value for the initial call.

## 5.8 Looking Ahead

This will not be our last look at recursion in this book. Indeed, we have just scratched the surface. We have only used recursion in this chapter to repeat tasks, as a model for repetition. The real power of recursion comes from the fact that it can do a lot more than just repetition. Recursive calls have memory. They do not know what they are doing, they just remember what they have done. This really comes into play when a recursive function calls itself more than once. That is a topic for later, but before we leave this first encounter with recursion here is a little bit of a teaser for you to think about.

Below is a little bit of code. You will notice that it is nearly identical to the countDown function that we wrote near the beginning of this chapter. Other than changing the name of the method, the only difference is that the two lines inside it have been swapped. Put this function into Scala. What does it do? More importantly, why does it do that?

```scala
def count(n:Int):Unit = {
  if (n>=0) {
    count(n-1)
    println(n)
  }
}
```

### 5.9.1 Problem Solving Approach

While recursion gives us much greater flexibility than what we learned before to repeat code an arbitrary number of times, it used the same constructs we had learned before, and for reason, it does not increase the list of options for any given line. It also adds new ways to think about and use options we had before. This chapter did include one new type of statement/expression.

- 1. Call a function with side effects.
- 2. Declare something:
    - A variable with val or var.
    - A function with def.
- 3. Assign a value to a variable.
- 4. Write a conditional:
    - An if statement.
    - A match statement.

### 5.9.2 Summary of Concepts

- The concept of recursion comes from mathematics where it is used in terms of itself.
- All recursive functions must have at least one case that does not call itself.
- Lack of base case leads to infinite recursion.
- In programming context, a recursive function is one that calls itself.
- Recursion is used to provide repetition.
