It assumes the input List is sorted, and returns a new List with the specified value at the proper location. If sorted is empty, it returns a List with the value as the only element. Otherwise, it checks if the insert is less than the head of sorted. If so, it cons to sorted and if not does he cons the head of sorted to the result of inserting the new element on the tail. Unlike the others, it has a second helper function that we have called helper. It builds up a sorted list, taking values at a time from the unsorted list. The base case is when everything has moved to the sorted list, which is returned.

# 13.5 Performance and Timing

This chapter has introduced a number of different sorting and searching algorithms. We have discussed the performance of these algorithms in terms of order. This tells us how they scale as the number of inputs is changed and quite often is what we really care about. You might not know or care about details the hardware or the data sets you will be running on, or you know that such details will change over time. There are times when you need to do exactly how fast an algorithm is on a particular machine, and you need to compare it to other algorithms on that same machine. When you do this, you need to do timing on the tests.

There are a number of different ways to get timing information on a program. Linux has a command that will tell you how much time a program consumes when it is running. For some algorithms this is ideal. For our purposes we only want to measure how long a part of the program takes. We do not want to measure the time taken to start things up or initialize the Array. When sorting the Array you can get detailed information like from a PROFILER but that is overkill for what we want to do. For our purposes, we need the ability to determine a start time and a stop time and the difference between the two. We can do this by calling System.nanoTime(). This is also in the Java libraries that returns a Long measuring the current time in nanoseconds.
