
## 14.1 Description of XML

Everything in an XML file can be classified as either markup or content. Markup in XML is found between the symbols '<' and '>' or between '&' and ';'. The content is anything that is not markup. To help you understand XML we will look at an example XML file. This example is built on the idea of calculating grades for a course.

```xml
<course name="CSCI 1320">
  <student fname="Quinn" lname="Bender">
    <quiz grade="98"/>
    <quiz grade="100"/>
    <quiz grade="90"/>
    <test grade="94"/>
    <assignment grade="100">
      <!-- Feedback -->
      Code compiled and runs fine.
    </assignment>
  </student>
  <student fname="Jason" lname="Hughes">
    <quiz grade="85"/>
    <quiz grade="78"/>
    <test grade="67"/>
    <assignment grade="20">
      Code didn't compile.
    </assignment>
  </student>
</course>
```

Just reading this should tell you what information it contains. That is one of the benefits of XML, the markup can be informative. Now we want to go through the different pieces of XML to see how this was built.

### 14.1.1 Tags

Between '<' and '>' characters are called TAGS. Nearly everything in our sample XML file is inside of a tag. The first word in the tag is the name of the tag, and it is the only thing that is required in the tag. There are three types of tags that can appear in an XML file.

- Start tag - Begins with '<' and ends with '>'
- End tag - Begins with '</' and ends with '>'
- Empty-element tag - Begins with '<' and ends with '/>'

Tags can also include attributes, which come after the name and before the close of the tag. These are discussed in section 14.1.3.

### 14.1.2 Elements

The tags are used to define ELEMENTS which give structure to the XML document. An element is either a start tag and an end tag with everything in between or else it is an empty element tag. The empty element tag is simply a shorter version of a start tag followed by an end tag with nothing in between.

Elements can be nested inside one another. In our sample file, there is a course element that encompasses everything else. This is required for XML, there needs to be one element that goes around all the other. There are student elements inside of the course element. Each of those includes elements for the different grades. Most of these are empty elements, the assignments are not empty and have contents in them.

Any time there is a start tag, there should be a matching end tag. When elements are nested, they must be properly nested. That is to say that if element2 begins inside element1, element2 must also end before the end of element1. In addition to other elements, you can place general text inside of elements.

### 14.1.3 Attributes

Additional information can be attached to both start tag and empty element tags in the form of ATT. An attribute is a name value pair where the value is in quotes and the two are separated by an equal sign. The example XML contains quite a few attributes. In fact, every start or empty element tag in the example has an attribute. It is not required that these tags have an attribute, but it is a good way to associate simple data with a tag. Some of the tags in the example show that you also have multiple attributes associated with them.

### 14.1.4 Content

Between a start tag and an end tag you cannot put other tags, you can put plain text. In the example XML, the assignment element has text in it that serves as a comment on the grade. The text that you put inside of an element is not formatted and can include anything you want, as long as it does not conflict with the XML syntax. Unlike the markup part of the XML document, there is no special formatting on content.

### 14.1.5 Special Characters

While the content does not have any special formatting, it is still embedded in an XML document. There are certain characters that are special in XML that you cannot include directly in the content. For example, if you put a '<' in the text it will be interpreted as the beginning of a tag. For this reason, there is a special syntax that you can use to include certain symbols by starting with & and ending with ; There are five standard values defined for XML.

- &amp; = &
- &apos; = '
- &gt; = >
- &lt; = <
- &quot; = "

There are many more defined for other specific markup languages. For example, if you ever looked at HTML you have probably seen &nbsp; used to represent spaces.

### 14.1.6 Comments

Just like code, it is helpful to occasionally put comments in your XML. A comment begins with '<!--' and ends with '-->'. You can put whatever text you want between them as long as it does not include the sequence to end the comment.

### 14.1.7 Overall Format

There are two other rules that are significant for XML. First, the entire XML document must be inside of a single element. In the example above, everything was the course element. If we wanted to have more than one course element, we would have had to create some higher level element to hold them.

In addition, most XML files will begin with an XML declaration that comes right before the element containing the XML document. The declaration has a slightly different syntax and looks like:

`<?xml version="1.0" encoding="UTF-8"?>`

## 14.1.8 Comparison to Flat File

To better understand the benefit of XML, we will compare XML to flat file. Here is a representation of the same information using attributes:

```xml
<course name="CSCI 1320">
  <student fname="Quinn" lname="Bender">
    <quiz grade="98"/>
    <quiz grade="100"/>
    <quiz grade="90"/>
    <test grade="94"/>
    <assignment grade="100">
      <!-- Feedback -->
      Code compiled and runs fine.
    </assignment>
  </student>
  <student fname="Jason" lname="Hughes">
    <quiz grade="85"/>
    <quiz grade="78"/>
    <test grade="67"/>
    <assignment grade="20">
      Code didn't compile.
    </assignment>
  </student>
</course>
```

An alternate approach would be to not use attributes at all and store all information in sub-elements.

```xml
<course>
  <name>CSCI 1320</name>
  <student>
    <fname>Quinn</fname>
    <lname>Bender</lname>
    <quiz><grade>98</grade></quiz>
    <quiz><grade>100</grade></quiz>
    <quiz><grade>90</grade></quiz>
    <test><grade>94</grade></test>
    <assignment>
      <grade>100</grade>
      <comment>Code compiled and runs fine.</comment>
    </assignment>
  </student>
  <student>
    <fname>Jason</fname>
    <lname>Hughes</lname>
    <quiz><grade>85</grade></quiz>
    <quiz><grade>78</grade></quiz>
    <test><grade>67</grade></test>
    <assignment>
      <grade>20</grade>
      <comment>Code didn't compile.</comment>
    </assignment>
  </student>
</course>
```

There is no definitive answer for which of these two styles you should use. What can be said definitively that attributes must be unique and generally have short text. You should not try to use attributes for things that would span multiple lines or need multiple values that would be challenging to break apart. A possible rule of thumb to follow is that anywhere you only have a single value that is, you should represent as an attribute. Anything that has multiple values or is long should be in sub-elements.

## 14.2 XML in Scala

XML is not part of the normal first semester in computer science, but Scala makes it so easy that there is no reason not to. To see this, simply go to the REPL and type in valid XML.

```scala
scala <tag>Some XML.</tag>
res0: scala.xml.Elem = <tag>Some XML.</tag>
```

The Scala language has a built-in XML parser that allows you to write XML directly into your code. You can see that the type of this expression is scala.xml.Elem.
