In the last case, we used recursion to do things as calculate the sum or the product of a bunch of numbers entered by the user. What if we wanted to do both? We could have done both a sum and a product if the user wanted the numbers twice, but the user did not want to do that. We had one significant problem with what we were doing. We took the numbers from the user and performed operations on them, but we did not really store them so we could use them again. The reason for this was that the type we have so far is a single value or in the case of a tuple, fixed number of values. We do not really have a good way to store a variable of numbers so that we can work with them and do multiple operations on them. That exactly what collections allow us to do. To really understand this, it helps to look at some examples.

We will start by making some Arrays that have values in them.

```
scalaArray(1,2,3,4)
res0[Int] = Array(1, 2, 3, 4)
```

```
scalaArray(1.0,0.2,3.0,4.0)
res1[Double] = Array(1.0, 2.0, 3.0, 4.0)
```

```
scalaArray('c','a','t')
res2[Char] = Array(c, a, t)
```

```
scalaArray("This","is","test")
res3[String] = Array(This, is, test)
```

Here we have four Arrays of different types. The syntax for making an Array with values in it is to follow the word "Array" with a list of parameters for the values we want in the Array. As always, each expression the REPL tells us the name used for this, the type of the expression, and the value of the expression. The type of the expression shows something that we have never seen before. The type is not just Array. Array name is followed by square brackets that have another type in them. This is called PARAMETERIZED TYPE. All the collections in Scala are parameterized. We will talk about this more later in this chapter, but the meaning should be clear. The Array [Int] is an Array that can hold integer values in it. As usual, we did not have to tell Scala's type inference and specifically tell it the type you want. The example below makes Array [Double] even though all the values in it are integers. This is perfectly valid all values in Int are also valid of Double.

```
scalaArray[Double](1,2,3,4)
res4[Double] = Array(1.0, 2.0, 3.0, 4.0)
```

Such for has to match what you pass in Scala. Scala will not allow you to do this for an invalid conversion.
