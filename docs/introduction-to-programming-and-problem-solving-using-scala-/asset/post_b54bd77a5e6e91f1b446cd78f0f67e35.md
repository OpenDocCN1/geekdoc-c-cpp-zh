## 13.1.1 Bubble Sort

The first sort we will describe is something of a classic in computer science. It is not efficient. In fact, you would be hard pressed to convince anyone to use this method when sorting things by hand. For for computers they will do whatever you tell them, even if it is extremely repetitive. It is only taught broadly because it is so simple to describe and code.

The basic idea of the BUBBLE SORT is that you want to run through the array and look at items that are next to one another. If two items are out of order, you swap them. One pass through the array will not get sorted unless it was very close to sorted to begin with. However, if you repeat this process and over, the array will eventually get to a situation where it is sorted. Using this description, there are a few ways in which the bubble sort can be written.

```scala
for (i <- 0; i < a.length-1; i++) {
  if (a(i) > a(i+1)) {
    val tmp = a(i)
    a(i) = a(i+1)
    a(i+1) = tmp
  }
}
```

The end index of this loop can change over iterations to make it more efficient, but the idea is i runs through the array comparing each element to the one after it. If the first is larger than the second, then they would swap a.

# Sorting and Searching

The swap code is the three lines inside of it. To picture what this is doing, imagine the analogy of cars in a parking lot. The tmp variable is an extra space where you can move by moving the first car to the empty space. After you move the second car into the space the first had been in. To finish it, you pull the car from the extra space into the second spot. The car analogy is not perfect. When we move a car from one spot to another, the space that is vacated is left empty. When we do an assignment, the variable or Array location we are getting the value from does not lose the value. Instead, we have memory locations that both have references to the value. That would be like having a second version of the car. Much of the time it is only a technical, but there are times when it can be significant as these extra references can hold onto memory that you are not using much.

In order to do a full sort, this loop needs to be repeated over and over. How many times must it be repeated? To answer we can observe each time, the largest unsorted value is pushed all to where it belongs. If there are n elements in the Array, then after n-1 everything will certainly be in place.¹ Using this logic, we can write the following code:

```scala
def bubbleSort(a:Array[Double]):Unit = {
  for (j <- 0 until a.length-1) {
    for (i <- 0 until a.length-j) {
      if (a(i) > a(i+1)) {
        val tmp = a(i)
        a(i) = a(i+1)
        a(i+1) = tmp
      }
    }
  }
}
```

In this code, the outer loop executes n-1 times the value j counts up from 0 to n-2. You will notice one other change in the inner loop. The end value for i has been changed from a length-1 to a length-j. This is based on the observation that after each pass, the largest element is in the correct location at the end. After two passes, the second largest is also in the correct place and so on. For this reason, the inner loop can stop earlier each time because there is no need to check those values that are already known. The sort would still work without subtracting j, but it would do twice as much work.

Other thing that this full sort includes that was not apparent from the inner loop is that this function has been written to sort an Array of Doubles. As written, this will not work if you pass anything other than Array[Double]. If you need to sort something else, you have to use generics. There are many ways to do this, but for now, we will stick to Doubles. If you need to sort something else, you would need to rewrite the function for that specific type or use a generic type.

The fact that we can stop the inner loop early is a simple optimization. In the worst case, the array is sorted in reverse order and we still need many passes. But in the best case, where the array is already sorted, we can finish in just one pass. This is why we use a flag in the version of bubble below.

# Flagged Bubble Sort

Another variation of bubble sort is to stop if the array becomes sorted before all passes are complete. We use a flag to track whether any swaps were made during a pass. If no swaps were made, we know the array is sorted and we can stop early.

```scala
def flaggedBubbleSort(a:Array[Double]):Unit = {
  var flip = true
  var j = 0
  while (flip && j < a.length-1) {
    flip = false
    for (i <- 0 until a.length-1-j) {
      if (a(i) > a(i+1)) {
        val tmp = a(i)
        a(i) = a(i+1)
        a(i+1) = tmp
        flip = true
      }
    }
    j += 1
  }
}
```

This code adds a few lines to deal with the flag and the fact that we have to do the counting ourselves with a while loop. The flag is flip, and it starts off as true. However, the inner loop is always set to false and only gets back to true when a swap is done. This is more efficient than the standard bubble sort when the array is already partially sorted.

## 13.1.2 Selection Sort (Min/Max Sort)

The next sort we want to consider is that humans are far more like to employ, especially in a situation like sorting cars where moving cars around takes a significant amount of effort. The sort is SELECTION SORT, and it is called because it runs through the values and selects one element and places it where it belongs. In order for this to work you have to know where the value should go. This is easy if the value is either the largest or smallest in the collection. As well as either a minimum sort (MIN SORT) or a maximum sort (MAX SORT). In theory one can also write a min-max sort that picks and moves them to where they belong.

We will write a min sort. It is fairly trivial to convert this to max sort. The inner loop of the min sort will run through the currently unsorted part of the collection and find the minimum element. If that element is not already where it should be, it is swapped into place. For an Array, the fact that this is a swap is significant. To understand this, think about the order. Shifting all the cars over one is hard. Swapping two is much easier Array is like the parking lot with fixed locations. Certain other data structures could act more similarly to folders, which slide around and allow slight shifting. If you use an Array and a shift instead of swap, the code will be both longer and significantly slower.

```scala
def minSort(a:Array[Double]):Unit = {
  for (j <- 0 until a.length-1) {
    var min = j
    for (i <- j+1 until a.length) {
      if (a(i) < a(min)) min = i
    }
    if (min != j) {
      val tmp = a(j)
      a(j) = a(min)
      a(min) = tmp
    }
  }
}
```
