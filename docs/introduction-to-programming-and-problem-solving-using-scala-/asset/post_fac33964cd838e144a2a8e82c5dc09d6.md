# Short Circuit Operators

One significant factor about the Boolean && and || operators is that they are short circuit operators. This means that if the value they give is known after the first argument is evaluated, the second argument will not be evaluated. For &&, happens if the first argument is false because no matter what the second argument is, the value will be false. Similarly, if the first argument of || is true, the final value will be true there is no spending time to evaluate second argument. This will be significant to us later when we get expressions that cause errors. The only thing we could do now that would cause an error during a run is to divide by zero. # 3.5 Precedence

So far all of expressions have been small. Other factors can come into play when they get large. One factor that becomes significant is precedence. This is the order in which operations are done. You know from math that multiplication happens before addition, and Scala follows that same order of operation. Now you need to know where these new operators fit into the precedence list. All of the comparison and Boolean operators perform *after* all mathematical operators. This allows a=5 < b*2 without parentheses. Similarly, comparisons have higher precedence than the Boolean operators. The expressions for `overlap` and `overlapY` used both of these facts as they combined addition, and &&.

As mentioned earlier, operators are just methods in Scala. The ones we have talked about so far are simple methods that are defined in the Scala libraries or the appropriate types. So && and || are defined on the *Boolean* type. The comparison operators are defined on numeric types, etc. When you use operator notation with a method, the precedence is determined by the *first character* in the operator.
