Using combinations, you can run through all possible options of some type and find the one that was the best in some way. For example, if I wanted to find subgroups of numbers that have a small sum, but a large product, I could do something like the following, which finds any groups of 3 from 1st that have a sum less than 15, but a product greater than 30.

```
scala List.combinations(3).filter(s => s.sum<15 && s.product>30).foreach(println)
List(7, 4, 3)

```

# 6.6 Complete Grades Script/Software Development

In chapter 4 we spent some writing functions to calculate averages in a class. We now have the ability to put together everything that we have learned and write a script that will keep track of the grades for a single student and be able to calculate student's average. This could be extended to multiple students, but we will not do that here.

When we solve a large problem, there are certain steps that must be taken. The first is to get a clear description of the problem you are solving. This is called ANALYSIS. The analysis step does not involve any coding or thinking about it. We just want a description that has enough detail to know what we are supposed to create. Once we have that, we can go to the next step, which is called DESIGN. In the design step we figure out how we are going to be solving the problem in the analysis. The design step does not involve coding either, but it specifies what we will do when we get to the code. The design phase is where we do our decomposition. We think about how to break the problem down and what pieces we will need to put together to get a single, whole solution to the problem. After we have a design, we get to the IMPLEMENTATION phase.

9These phases are part of the Software Development Life Cycle (SDLC).
