# 3.3 Comparisons

The first statement shown in the previous sections >= to do a comparison between two values. You likely had no problem figuring out that this can be read as greater than or equal to. Your keyboard does not have a > key, so instead we use two characters in a row. All of the normal comparisons that you are used to in Scala, but some, the greater than or equal to, differ from how you are used to writing on paper.

The simplest comparison you can do is check if two things are the same or different. You read this as saying that two things are equal or not to one another. In Scala we represent these with == and != respectively. Note that the check for equality uses two equal signs. A single equal in Scala stands for assignment, which we have already stores a value into a variable. The double equal sign checks if two expressions have the same value and produces a Boolean value with the result of the comparison. Here are a few examples of the use of this in the REPL.

```
scala 2 == 3
res1: Boolean = false
```

```
scala > 7 == 7
res2: Boolean = true
```

```
scala 'a' == 'a'
res3: Boolean = true
```

```
scala "hi" == "there"
res4: Boolean = false
```

```
scala "mom".length == "dad".length
res5: Boolean = true
```

The ! operator is basically the opposite of ==. It tells us if things are different and should be read as not equal. As we will see, the exclamation pronounced "bang" in many computing contexts, "not" in Scala. Any of the examples above could use != instead of == and the result would be the opposite of what is shown.

In addition to equality and inequality, there are also comparisons of magnitude like the age >= 13 that we used above. The comparisons of magnitude in Scala are done with <, >, and >=. These also give back a value of the Boolean type so it will be either true or false. These comparison operators are also known as relational operators. The order of the characters in < and >= is significant. They are in the same order that you say, "less than or equal to" and "greater than equal to"; so, it will not be hard to remember. If you reverse the order, Scala will not be able to figure out what you mean and return an error.

```
scala 5<6: error: value <= is not a member of Int
<console> 5<9
```
