# 16.1.2 Analysis and Design of Pac-Man™

A very different example for us to break down in an object-oriented way is the classic arcade game, Pac-Man™. One reason for picking this game is that it is assumed that anyone is already familiar with this game, or can easily find information on the basic game-play. For that reason, we will not explicitly describe the analysis of the problem, and instead go straight into design.

There are many different types of things that are significant in the Pac-Man game. The ghosts, and fruit. Other elements are less obvious. We definitely need a type that represents the overall playing area, we might call the maze. How just the maze stores impact what other types we will use. For example, we should have a separate type for a pellet, or the grid cells in the maze values that tell if the cell contains a pellet in addition to whether the cell is a wall or open space? There are pros and cons to each of these approaches. For this design, we are going to make it so that the grid stores information about whether or not pellets are present. It could also be useful to have something that represents the full game for things like score and the number of lives left. This gives us a reasonable list of types to start off with.

We will start with the Pac-Man type.
