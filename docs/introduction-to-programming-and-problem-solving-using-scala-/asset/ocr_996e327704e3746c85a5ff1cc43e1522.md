# 7.4 Subtyping

So we have generally talked about types as if they are completely independent and unrelated. We have written functions that might work with an Int or a String or a Tuple. The exception to this was in section 7.2, where it was clear that Option, Some and None are somewhat related. By adding parameters we were able to make functions that work with any type, but this still did not imply any relationship between types. In reality, Scala, like most object-oriented languages, supports SUBTYPING. A type B is a subtype of type A if any place where we want to use an object of type A we can use an object of type B instead.

The concept of subtyping is dealt with detail in Object-Orientation, Abstraction, and Data Structures Using Scala [1] in the chapter on inheritance, but for now you should be aware of the term because there will be times when it comes up. Our first example. If we wrote a function that takes Option[Int] as its argument, we could have passed in a Some[Int] or a None and it work because Some and None are subtypes of Option.

Some of the general subtype relationships in Scala are shown in figure 7.3. This is a UML^3 diagram. The arrows point from a subtype to a supertype.

At the top of there is the ultimate subtype called Any. Every object in Scala is an instance of Any. All values in Scala, everything is an instance of Any, either directly or indirectly. The types Int and Double that we learned back in chapter 2 are on the left side of figure 7.3 under a type AnyVal is a subtype of Any. On the right side there is another type called AnyRef that has a bunch of unspecified types below it. All the other types we will or talk about in this book somewhere under AnyRef.

> The Unified Modeling Language (UML) is a general purpose modeling language used in object-oriented software development.
