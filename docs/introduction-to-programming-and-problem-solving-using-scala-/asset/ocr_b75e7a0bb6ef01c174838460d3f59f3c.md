# 16.2.2.2 The apply Method

Another method that Scala treats a treat as a shortcut is the apply method. This method, and how it is handled, a major part of what makes Scala as a functional language while remaining very object-oriented. You write apply like any other method that might put in a class. You can call it any other method as well. However, Scala will allow you to call the apply method without using a dot or the name apply. When you remove it, it makes like you are treating the object as a function. Indeed, this is how functions work in Scala. As was said early on, everything in Scala is an object. That includes functions. A function is just an object of type that has an apply method that takes the appropriate arguments.

The intelligent use of apply is how you are indexing into all of the collection types. Consider the following code that you could write in the REPL.

```
scala val arr = Array(5,7,4,6,3,2,8)
arr: [Int] = Array(5, 7, 4, 6, 3, 2, 8)
```

```
scala arr(3)
res0: Int = 6
```

```
scala apply(3)
res1: Int = 6
```

The call to arr(3) is actually just the shortcut for arr.apply(3). Scala is doing nothing more than assuming the presence of the call to apply.

How can we use this in our code? In our design for the bank program, we mentioned having a Bank class that stores all the accounts and customers of a bank, and includes methods for looking them up. We could put apply method in the Bank class that takes an account number and produces an Option[Account]. To do this, we first need to get the Account ID. This is easily done by modifying the declaration to take a val argument.
