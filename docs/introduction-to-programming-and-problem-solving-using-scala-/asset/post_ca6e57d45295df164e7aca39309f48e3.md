# 16.4 Implementing the Bank Example

We now know enough about the syntax of object-oriented programming in Scala that
we can implement the bank example. This is being written as an application, so each class
is in its own file. Note that this code does not do anything related to logging as that
is beyond the scope of this text, but the code has been written such that you could add
appropriate code in the methods to easily get logging in all the places it is needed. Since
we have done the most with the Account class now, let's look at first.

Listing 16.1: Account.scala

```
class Account private(val id:String, val customer:Customer, accountType:Int) {
  require(accountType == Account.Checking // accountType == Account.Savings ||
  accountType == Account.CD)
  private var _balance = 0
  customer.addAccount(this)
  def deposit(amount:Int):Boolean {
    if (amount > 0) {
      _balance += amount
      true
    } else false
  }
  def withdraw(amount:Int):Boolean {
    if (amount > 0 && amount <= _balance) {
      _balance -= amount
      true
    } else false
  }
  def monthlyAdjustment():Unit {
    accountType match {
      case Account.Checking => _balance = (_balance * 1.01).toInt
      case Account.Savings => _balance = (_balance * 1.03).toInt
      case Account.CD => _balance = (_balance * 1.05).toInt
    }
  }
  def balance = _balance
  def balance_=(b:Int):Unit {
    if (b >= 0) {
      if (b < _balance) withdraw(_balance - b) else deposit(b - _balance)
    }
  }
}
```

There are a few things in this code that are worth taking note of. Lines 37-49 include a companion object. This serves two main purposes in this code. The first is a place to store the three constants that tell us the account type. If these values were put in the class, then every instance of the class would get their own copy. As they would all have the same values, this would be wasteful. The object is a singleton though, putting them in the companion object means we get a single copy of each. In the class we refer to these two locations. One line is a check to make sure that the accountType that is passed matches one of the allowed values. The other reference is in monthlyAdjustment. Note that in both of these locations, the references to the account are prefixed with the name of the object.

The other use of the companion object is to ensure that all instances of the Account have unique IDs. The private keyword appears in front of the argument list. This is some syntax that we have not previously introduced before. This has the effect of making instantiation private so nothing outside this file can call new(...). If we did not have this, code could create new account instances with the same ID. Instead, we have added an apply method into the companion object and must use this method to make accounts with the syntax apply(...). Note that the apply method does not take an ID as an argument. Instead, there is a private var declared in the companion object that keeps track of the next account number. Inside of apply, this unique prefix is used to make a string of long characters, and that is used as the ID in a call to new. The apply method also increments the value of nextAccount so that subsequent accounts will have a different ID. The combination of apply and making instantiation private means that outside can never create two accounts with the same ID.

Line 3 of Account.scala shows our first usage of this. The Account and Customer classes have a mutual dependence. Instances of Account have been constructed with a reference to a Customer, and the Customer instances keep track of the accounts they have. To deal with this, we have added line 3 to the Account that will automatically add the new Account instance to the customer it refers to. This requires passing the current account, which we need to use for this.

Now we come at the Customer class. Like Account, this file includes a companion object with an apply method that helps to create unique IDs. Unlike the Account, it is possible for outside code to make instances of Customer.

> As has been mentioned before, there are better ways of dealing with account types that go beyond what we have learned. Methods would make it impossible to pass in bad values. This approach at least makes a runtime error that happens immediately upon creation of an Account with a bad type.
> This example is simplified in many ways, but the contents of monthlyAdjustment are probably the most extreme simplification. Interest rates should not be hard coded here. Also, there should inevitably be code that makes sure this does not happen more than once each month.

```scala
class Customer(
  val id:String,
  val firstName:String,
  val address:List[String],
  phone: String
) {
  private var accounts: List[Account] = Nil

  def addAccount(account:Account):Unit {
    accounts = account :: accounts
  }

  def removeAccount(id:String): Boolean {
    val index = accounts.findIndexIndex(_.id == id)
    if (index != -1) {
      accounts = accounts.removeAt(index)
      true
    } else {
      false
    }
  }

  def accounts = accounts
}

object Customer {
  private var nextID = 1

  def apply(firstName:String, address: List[String], phone: String):Customer = {
    val id = nextID.toString
    nextID += 1
    new Customer(id, firstName, address, phone)
  }
}
```

The Customer class takes quite few arguments. The reason for this design is in part to show you it can be done, and in part to preserve the identity of the customer.

Listing 16.3: Bank.scala

```scala
class Bank {
  private var accounts: List[Account] = Nil
  private var customers: List[Customer] = Nil

  def addAccount(account:Account):Unit = accounts :: account
  def removeAccount(id:String): Boolean {
    val index = accounts.findIndexIndex(_.id == id)
    if (index != -1) {
      accounts = accounts.removeAt(index)
      true
    } else {
      false
    }
  }

  def addCustomer(customer:Customer):Unit {
    customers = customer :: customers
  }

  def removeCustomer(customerID:String): Boolean {
    val index = customers.findIndexIndex(_.id == customerID)
    if (index != -1) {
      customers = customers.removeAt(index)
      true
    } else {
      false
    }
  }

  def accounts = accounts
  def customers = customers

  def findAccount(accountID:String):Option[Account] = accounts.find(_.id == accountID)
  def findCustomer(customerID:String):Option[Customer] = customers.find(_.id == customerID)
}
```

```scala
object BankApp {
  def main(args:Array[String]):Unit = {
    val bank = Bank
    val customer = Customer("Bob", List("123 Broadway"), "(123) 456-7890")
    bank.addCustomer(customer)
    val account = Account(customer, Account.Checking)
    bank.addAccount(account)
  }
}
```
