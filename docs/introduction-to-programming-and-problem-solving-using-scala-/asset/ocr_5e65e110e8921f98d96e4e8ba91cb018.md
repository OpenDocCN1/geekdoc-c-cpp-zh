Earlier in the book we made the statement that programming was all about problem solving. It is the art of giving a computer set of instructions to solve a problem in terms that the computer can understand. One of the fundamental elements of programming is problem decomposition. The idea of problem decomposition is that good solutions of large, complex problems are built out of smaller, more manageable problems. This is especially important in programming because the problems can be arbitrarily complex; at the base, we have to break them down to the level where we can communicate them to the computer, which is fundamentally simplistic.

A function is a collection of statements to solve a specific problem that we can call as needed. You can think of it as a little, self-contained program that performs a task that we can run over and over again. The scripts we have built to point share some characteristics with functions. They are collections of statements we put together to do something repeatedly without repeating it. We have also looked at a few built-in methods that can be viewed as functions. Do you remember some of the math methods such as min and max? You know enough about programming in Scala to be write code to find the minimum or maximum of two numbers, but it is certainly useful to not have to type that code over every time we would want to find an answer. Functions are very beneficial to a programmer.
