After you have an implementation you have to make sure it works and fix any problems. This is called the TESTING and DEBUGGING phase because it is where you test the code to find all the bugs and fix them. Real software, after all the bugs are fixed and the software has rolled out, or deployed, you worry about MAINTENANCE. This is where you continue to make analyses to the software to improve it or address customer requests.

At the level you are now, you do not do analysis because your instructor or book will give you a complete description of what you are doing. You do not need analysis because you have a customer base that is using the software. A little of these can still creep into your work when you make sure you fully understand the description of a problem and then if you are given a layer that someone has done previously.

You should spend a significant amount of time working on design and debugging. In fact, the implementation phase is the shortest phase of the software creation process.¹¹ If done properly, most of the things going into the design phase so implementation is simply typing in what you had designed. Testing and debugging is extremely variable in time. It is possible to write your program and have everything perfectly the first time. That gets less as programmers get and is especially for novice programmers, though the static type checking in Scala will help to make that if everything is working in your program checks out it has a better chance of winning. When things do not work, debugging can take arbitrarily long periods of time and is often the longest phase of software development, and they are rarely in sequential order.

In real development, these phases are not always distinct, and it is common in one phase of development you realize something was missed in an earlier phase. Some approaches to software development mix the phases so that the developer is involved in more than one at any given time.
