
# Nature of Programming

Every piece of software, from the BIOS of each device to the OS, and the multitude applications they run, is a program that was written by a programmer. So what is this thing we call programming, and how do we do it? How do we give a computer instructions will make it do things for us? In one sense, programming is just the act of giving the computer instructions in a format that it can work with. At a fundamental level, computers do nothing more than with numbers. Remember the model in figure 1.2. Each cycle the computer loads and executes it. There was a time when programming was done by the specific, low level instructions that the computer understands. We refer to the language of these instructions as machine language. While machine language is the only language that the computer understands, it is not a very good language for humans to work in. The numbers of machine language do not hold meaning for humans, so it is very easy to make mistakes. To understand this, consider the following code that calculates a wage using the math wage = rate * hours with MIPS machine language.

```
100011 00000 00100 0000000000000 # Load rate into register 2
100011 00001 00111 0000000000000 # Load hours into register 3
000000 0010 0011 01100 00000 01100 # Multiplies 2 and 3, and store in 4

101011 00100 00101 0000000000000 # Store result from register 4
```

This shows the instructions in binary; we will discuss binary in chapter 2. Spaces have been inserted to make it easier to see the parts of the instructions, and comments are put in to explain what each command made of 32 bits and is doing. Real machine code does not have spaces, comments, or even separate lines. The commands are generally written in hexadecimal instead of assembly. So this code would look like

```
8c200008c23000432018ac850000
```

Even without knowing anything about programming, you can probably tell that this would be very hard to work with. For this reason, people have developed better ways to program computers to write out machine language instructions.

The first step up from machine language is assembly language. Assembly language is basically the same as machine language in that there is an assembly instruction for each machine language. However, the assembly instructions are expressed as words, known as mnemonics, that describe what they do. The assembly language also helps to keep track of how things are laid out in memory so that programmers do not have to actively consider such issues the way they do with machine language. The machine language above can be written as the following assembly instructions.

```
lw $s0, $s2, 0
lw $s1, $s3, 0
mult $s2, $s3, $s4
sw $s4, $s5, 0
```

The first group of six numbers in the binary machine code corresponds to an instruction. For example, you can see that 100011 is lw, which is short for 'load word'. To get the computer to understand assembly language, we employ a program that does a translation from assembly language to machine language. This program is called an assembler.

# Basics of Computers, Computing, and Programming

Even assembly language is less ideal for expressing the ideas that we want to put into programs. For this reason, other languages have been created. These higher languages use more words and allow a more complex organization of ideas so that more powerful programs can be written more easily. Our earlier pieces of code would be written as age = rate*hours in most modern languages. The computer does not understand these languages either, so they employ compilers to translate the higher level languages assemble them into machine language or interpreters that execute the instructions one at a time without ever turning them into machine language.

There are literally hundreds of programming languages. Each one was created to address some deficiency in what others were or address a specific need. This book uses the Scala programming language, for someone who has not programmed before. We will say that Scala is a very high-level language that allows you to communicate with the computer in a concise way, and gives you access to a large number of libraries to help you write programs that are free, interesting, and/or useful.

Early in your process of learning to program, you will likely struggle with figuring how to express your ideas in a programming language instead of the natural language. Part of this is because programming languages are fundamentally different than natural languages in that they do not allow ambiguity. In addition, they typically require you to express ideas at a lower level than you are used to natural language. Both of these are a big part of the reason why everyone should learn how to program. The true benefits of programming are not in the ability to tell a computer how to do something. The real benefits come from how to break problems down.

At a fundamental level, the computer is a stupid machine. It does not understand or analyze things. The computer does it; it is both a blessing and a curse for the programmer. Ambiguity is bad when you are describing how to do things and it is particularly problematic when the instructions do not have the ability to evaluate the different possible meanings and pick the one that makes the most sense. That means programs have to be rigorous and take into account small details. On the other hand, the computer tells us to do things that humans would find incredibly tedious, and the computer will do it for as long as you ask it to. This is a big part of what makes computers so useful. They can sift through huge amounts of data and do calculations without fatigue induced errors.

In the end, you will find that converting your thoughts into a language the computer can understand is the easy part. It will take time to learn your new language and to get to the nuances of it, but the real challenge is figuring out exactly what steps are required to solve a problem. As humans, we tend to overlook many of the details in the processes we go when we are solving problems. We describe things at a high level and ignore the lower levels, assuming that they will be implicitly understood. Programming forces us to clarify these implicit steps and, in doing so, forces us to think more clearly about how we solve problems. This becomes very important as problems get bigger and the things we want to have implicitly assumed become sufficiently complex that they need to be spelled out.

One of the main skills that you will develop when you learn how to program is the ability to break problems down into pieces. All problems can be broken into smaller pieces, and it is possible that the pieces can be reused. If you have solved a particular problem once, you do not want to solve it again. Some ways of breaking up a problem are very free and likely to be useful in other contexts. Other ways will give you elements that are very specific to a given problem and will not be useful to you again.

The fact that there are many ways to break up problems or work with problems has not only led to many programming languages, it led to families of different approaches that are called paradigms. There are four main paradigms of programming. It is possible others could come into existence in the future, but what appears to be happening now is Scala merging the existing paradigms. Scala is one of the languages that is blurring the lines between paradigms. To help you understand this we will run through the different paradigms.
