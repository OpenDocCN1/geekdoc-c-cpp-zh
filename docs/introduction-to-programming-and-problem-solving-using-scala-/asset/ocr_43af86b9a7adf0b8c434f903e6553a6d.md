Unlike merge sort, quicksort can be done in-place. However, that is more complex and is not covered in this book. For now we will make the quicksort like our merge sort and work on a List, for which the idea of being in-place does not make sense.

The quality of a quicksort is largely depending on the selection of a pivot. A good pivot would be in the middle of the collection to cut in half. A really bad pivot would be the minimum or maximum element which does nothing to split the data and only pulls out the next level of recursion. Keeping with the idea of simplicity for the implementations in this chapter, we will use the first element as the pivot. This is not a good way to do this in general and can lead to very bad behavior on sequences that are already sorted.

With these simplifications we can write a version of quicksort with the following code.

# Listing 15.4: quicksort.scala

```
def quicksort(lst:List[Double]):List = lst match {
  case Nil => Nil
  case h::Nil => Nil
  case pivot => lst.head
    val (less, greater) = lst.partition(<pivot)
    quicksort(less) ::: (pivot :: quicksort(greater))
}
```

The pivot is set to the head of the List. We use partition to split the rest of the elements that are less than the pivot and those that are not. Finally, the quicksort on those two subsets and pull the whole together into a result. The result is a short and simple sort function that actually works well on random data.

It is worth asking what order of this sort really. Unlike the merge sort, the performance of our quicksort can vary dramatically depending on the input. Like the merge sort, each level of the recursion leads to O(n) work. This case is when the pivot is partition and sticking Lists together. If the pivot is in the middle of the values, each level is cut in half and we get O(log(n)) levels for recursion and O(log(n)) overall performance. For random data, this is the expected behavior. However, our simple pivot selection can lead to very poor behavior and this sort is O(n²) when it is already sorted.

The last thing to note about quicksort is unlike merge sort, it does most of its work going down the call stack. The call to partition is where all the comparisons happen. List version does have to merge Lists on the back up the call stack. A version written to work in-place with Arrays will not have to do that.
