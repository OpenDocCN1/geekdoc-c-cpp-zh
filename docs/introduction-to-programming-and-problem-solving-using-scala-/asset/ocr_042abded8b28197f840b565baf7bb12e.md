# 9.3.1 Iterators

When the value of the BufferedSource is printed all it shows "non-empty iterator". This is because the BufferedSource, and the normal Source, are both subsets of a more general type called Iterator. An Iterator is much like the Array and List types that we previously saw. In fact, all the methods that we can call on the Array and the List are available on an Iterator. The difference is that a basic Iterator is consumed as you go through it, so it can only be used once. The Array and List are said to be Iterable which means they can give multiple Iterators to call those methods over and over again. In the case of Iterator, once you call a method that runs through the whole thing, it is spent and you cannot use it again.

```
scala fileSource.mkString
res0: String =
"This is a sample text file that I have written to use for the files chapter.
There is really not all much to this file. It is simply supposed to be used to illustrate how we can read from files.
```

```
scala fileSource.mkString
res1: String ="
```

```
scala fileSource
res2: scala.io.BufferedSource = empty iterator
```

The first call to mkString gives us a string that has the contents of the file. The second call gives us nothing. The reason for this is clear if we look at the value of fileSource. After reading the first time, it has gone from a non-empty iterator to an empty iterator. There is nothing left for us to read. The Source type provides a method called reset which you do not get in most Iterators. The reset method gives you a new Source that is set back to the beginning for you to read again. Note that it is a new Source, it does not make the original Source non-empty again.
