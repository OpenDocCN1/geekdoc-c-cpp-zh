## 2.5.2 Negative Numbers in Binary

We have not addressed the question of how we represent negative numbers on a computer. The description that we have given so far only deals with positive values. Numbers that are interpreted this way we call UNSIGNED. All the numeric types in Scala are SIGNED, so we should figure out how that works. To this, there are two things that should be kept in mind. The first is that our values have limited precision. That is to say they only store a certain number of bits. Anything beyond is lost. The second is that negative numbers are defined as the additive inverses of their positive counterparts. In other words, $x + (-x) = 0$ for any $x$.

To demonstrate how we get negative numbers, let's work with the number 1101101 (53 in decimal). Unlike before, we will now limit ourselves to a single byte. So, we have 8 digits to work with, and the top digits are zeros. Our number stored in a byte is really 00110101. The question of what should be the negative is answered by figuring out what value we add to this to get zero.

```
00110101
+ ????????
000000000
```

Of course, there is nothing that we can put into the question to make this work. (i.e. values have limited precision) we can see what we must do. Note that our total below has 9 digits. We do not need the total to be zero, we need eight digits of zero. In reality, what we are looking for is the following.

This problem is solvable and the most significant 1, the one on the far left, will be thrown away because we can only store 8 bits in a byte. The answer is given here.

```
00110101
+ 11001011
100000000
```

Note that the top bit is "on" in the negative value. The top bit is not exactly a sign, but if a number is signed, the top bit will tell us whether the number is positive or negative. This style of making negatives early-options were tried, such as adding a sign-bit or a method called ones' complement where the bits are simply flipped. However, two's complement is used in machines today to allow numeric operations to be done with negative numbers using the same circuitry as is used for positive numbers.

This process gives us the correct answer and is based on the proper definition of what a negative number is. Finding values using the definition of a negative value works and can be a fallback, but there is a simpler method. To get the two's complement negative of a binary number, simply flip the bits and add one. You can verify that this approach works for our example above. It is left as an exercise for the student to figure out why this works.

## 2.5.3 Other Integer Types

There are larger groups than the 8-bit types that have meaning in Scala. In fact, if you go back to section 2.3 and look at the different methods on an Int, you will find that Double and toChar are not the only conversions we can do. Scala has larger integer types called Byte, Short, and Long. A Byte in Scala is an 8-bit number. A Short is a 16-bit number. The Int we have been using is a 32-bit number. The Long type is a 64-bit number. The reason for the odd behavior that was demonstrated at the beginning of section 2.5 is that we added two numbers together whose sum is bigger than what can store (the OVERFLOW, as it is called, wrapped around to a negative value). Table 2.1 shows the minimum and maximum values for each of the different integer types.

Occasionally you will need to use literals that are bigger than what an Int store. You can do this with a Long. Making a numeric literal into a Long is by simply adding an L to the end. You can see this here.

```
scala> 5000000000L
```

res31: Long = 5000000000

The value binary is not a valid Int. If you leave the L here you get an error. The L can be lower case, but then it looks a a the number so it is better to use the upper case.

We talked about binary, and Scala has a method that will let you see the binary form of a number. This method works on the four numeric types and Char. Here we use it to see the binary representation for 83 and -83 for the values as both Int and Long types.

```
scala = 83.toBinaryString
res32: String = 10100111
```

```
scala = -83.toBinaryString
res33: String = 1111111111111111111111110101
```

```
scala = 83L.toBinaryString
res34: String = 1010011
```

```
scala = -83L.toBinaryString
res35: String = 11111111111111111111111111111010101
```

The toBinary method does not display leading zeros, so the positive values only show seven digits in both formats. However, the negative format has many leading ones and all of these are printed.
