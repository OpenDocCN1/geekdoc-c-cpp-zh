# Introduction to Programming and Problem-Solving Using Scala

+   - Scripts are good for small programs, but larger programs are written and run as applications. The entry point to an application is defined by a main method in an object. Top level declarations are split to different files. Code is compiled with scalac and using scala.

+   - An object with the same name as a class can be declared in the same file, and it becomes a companion object. Companions have access to private declarations.

# 16.6.2 Exercises

+   1. Alter the Ghost class that it makes more intelligent direction choices to head toward or away from the player. Note that they can always make the best choice or the game becomes impossible.

+   2. Alter the Ghost class so that they move faster than the player when they are not scared and slower when they are.

+   3. You can turn any script that you wrote previously into an application by embedding everything into an object in the main method. The results of this should compile with scalac and run with scala.³

The result of this simple conversion is not generally ideal. Any method or case declarations should generally be pulled out of main. The methods likely go inside of object, but outside of main. If these methods are not generally useful, they should be private. The classes could be inside of the object where they might or not be private, depending on how generally they are. If they truly stand on their own and have meaning, they should go outside the object and into a separate file bearing their name.

The results of modification might not compile. That will depend on the quality of the original code and whether you variables declared outside of methods in the methods. If you use variables outside of the methods in the body, you have one of two choices. Generally your first choice should be to pass these variables by adding extra parameters to the method. If a variable is a data member/property of the object, it can be moved to a level up so it too is in object, but not in main⁵

Your goal for this is to run through this process on a number of scripts that you wrote in the book. When you do this, it is recommended that you use a subdirectory for each script you are converting, copy files into there. This way you not only preserve the original script, but make it easier to compile that single application. Doing this on a number of scripts will really help to build your feel for how this new approach differs from what we done previously.

4. Another thing you can do to help you get to use some aspects of the oriented model is to convert case classes over to normal classes. This is generally a less significant modification, but it will require some changes in other parts of the code such as forcing to use new when instantiating an object. You will also lose the code method.

> ³Remember that when you run an application with scalac you give only the name of the object, not the name of the file. Most of the time file name should start with the object name so you are just leaving off .scala.

> ⁵Note that if a variable is set by user input, it almost certainly needs to stay in main. Having singleton objects that request users to enter input will lead to very odd and unexpected behaviors in larger programs.
