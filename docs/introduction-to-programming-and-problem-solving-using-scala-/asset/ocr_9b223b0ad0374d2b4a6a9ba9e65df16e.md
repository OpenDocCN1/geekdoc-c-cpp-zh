```
while (!after.isEmpty) {
  val perm = after.head :: p
  permute(before :: after.tail,f,perm)
  before = after.head
  after = after.tail
}
```

When the List is empty, we have a full permutation, we call the function on it. Otherwise, we have a loop that runs all the elements we want to permit and makes recursive calls assuming each one has been added to the head of the permutation. This is done using two Lists and a while loop. To start off with, one List is empty and the other is all the elements in the input List. In the loop we not only make the recursive call, but also move elements from one to the other. We can to check if this function works by calling it.

```
permute(List(1,2,3), print, Nil)
```

When we make this call, we get the six different permutations of the list with three elements and then simply print them out. The first call should use Nil for the last argument. This function displays an interesting feature that is generally true of recursive functions. Because it is defined in terms of itself, we write assuming that it is true. When we do writing it, it will work. This logic seems circular, but it is actually using a method called induction. First we make the function work for the simple base case. Every case above is defined in terms of a smaller one. Eventually this gets down to the base case, which generally works in a trivial way. If the base cases work, the case right above work. When the one above the base cases work, the one above that should work. This logic progresses upwards to solve problems of arbitrary size.

We mentioned earlier that we do not return List of the permutations because there be a lot of them and would require a lot of memory. It is worth taking a slightly better understanding of what "a" means. Specifically, we would like to know the order of the number of permutations. This will not only tell us how long a list if we build one, will give us a measure of how long this function will take to run for any task that we might give us as it will be the number of times that the function parameter, n, gets called.
As is normal the case for our analysis, we will think in terms of the size of our input. In this case, that is the size of the input List which we will call. The first call to permit makes n calls to itself, each one is passed a List with n-1 elements. Those then make n-1 calls with Lists of size n-2. This process continues until we get down to 0 elements in the List. If you picture this as a tree similar to that in figure 15.2, we have a box with n branches off. These lead to boxes that have n-1 branches off. So at the third level we have n * (n-1) boxes. At the next level we continue down to 1 we get the factorial function that we played with in chapter 5. Indeed, if you recall from our earlier discussion, the factorial function grows very quickly. So quickly in fact, that we had to use the Long or BigInt types if we wanted to use even large inputs. Clearly do not want to get all the permutations of Lists with much more than 10 elements in them. Depending on what you are doing, even lists of 10 elements might take a while.
