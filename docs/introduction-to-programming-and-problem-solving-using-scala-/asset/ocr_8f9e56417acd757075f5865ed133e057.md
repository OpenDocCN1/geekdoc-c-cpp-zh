One of the things that you have noticed by this point is that there are times when it can be helpful to group pieces of data together. If all the data is the same type, you could use something like an Array or a List. The down side of this is that the simpler compiler cannot make to sure that you have the right number of elements. For example, if you have a point in 3-D with $x$, $y$, and $z$ coordinates having more or less could cause the code to break and Scala would not be able to check that until the program was running. The alternative, which also works if the types of values are different is to use a tuple. Some 3-D point could be represented as a (Double, Double, Double). While this works reasonably well for a 3-D point, it too has significant limitations.

To illustrate this, consider different things that could be represented as three Doubles. One is a point in 3-D. Another related one is a vector in 3-D. The vector or the point could be represented in Cartesian coordinates, cylindrical coordinates, or polar coordinates and the tuple would not tell you which is which. The three Doubles also represent the high temperature, low temperature and average temperature for a day; or the regular price, sale price, and cost of a sweater; or three sub-averages for a students grade in a class. For example, the tuple does not tell you which type of data is in the tuple and this does not help you all with keeping things straight.

What is more, the tuple lacks some flexibility and the syntax for getting out of them is less ideal. Calling the _1 and _2 methods all through your code can make it difficult to read. Imagine if you wanted to represent a full student in a class. Then the tuple might have a String and a large number of grades, all of the same type. Keeping track what numbers are associated with what would very quickly become problematic. To get around these limitations, we will consider the use of case classes for grouping data.
