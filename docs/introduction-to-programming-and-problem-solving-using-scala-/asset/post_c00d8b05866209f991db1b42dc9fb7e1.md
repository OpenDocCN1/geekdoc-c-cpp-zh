Earlier in the book we made the statement that programming was all about problem solving. It is the art of giving a computer set of instructions to solve a problem in terms that the computer can understand. One of the fundamental elements of programming is problem decomposition. The idea of problem decomposition is that good solutions of large, complex problems are built out of smaller, manageable problems. This is especially important in programming because the problems can be arbitrarily complex; at the base, we have to break them down to the level where we can communicate them to the computer, which is fundamentally simplistic.

A function is a collection of statements to solve a specific problem that we can call as needed. You can think of it as a little, self-contained program that performs a task that we can run over and over again. The scripts we have built to point share some characteristics with functions. They are collections of statements we put together to do something repeatedly without repeating it.

### 4.1 Motivating Example

Imagine a function that takes a number as input and returns its square. In Python, it might look like this:

```python
def square(x):
    return x * x
```

We can call this function with different arguments to get different results:

```python
print(square(3)) # Output: 9
print(square(5)) # Output: 25
```

This approach allows us to reuse the code for squaring numbers without rewriting the logic each time. It makes the program more organized and easier to maintain.

### 4.2 Function Refresher

In a general sense, a function is a mapping that associates inputs with output values. In your math classes you have likely focused on functions that map numbers into numbers. We have seen that our programs can work with numbers, but there are other types that we can work with. Some simple examples of this include the following:

- A function that takes a String and returns how many vowels are in it.
- A function that takes a String and returns the first uppercase letter in it.
- A function that takes two points as $(x,y)$ pairs and returns the distance between them.

All of these have parameters that are not simple numbers. In terms you used in algebra, we would say that their domain is not just the real numbers. They also give back values from different types. In algebra this would be the range.
