# 9.1 I/O Redirection

In a certain way, you have already had the ability to make your program deal with files through I/O redirection. When you run the program from the command line as a script, you can have standard input from a file using `<`. You can also make the standard output to a file using `>`. This works nicely if you are going to be entering the same values multiple times or want to preserve the output so you can look at it.

The down side of using I/O redirection is that it is rather limited. You only get to read from one file or write to one. What is, if you decide to read from a file, you cannot also have the user input from the keyboard, or if you decide to have the output to a file, the user will not see anything that is printed on the screen. These limitations make this approach impractical for most applications. As such, it is important for us to learn other ways to get data into a program.

Almost everything that we have used so far is available in Scala without having to specify where to look for it. The basic parts of the language are simply available by default. One exception to this was the various read methods. To those without using long names, you can import `io.stdin` at all of the scripts and in the REPL. The Scala language uses packages to organize code. To understand the reason for packages, consider the `List` type that we learned to use in chapter 6. This type is defined by a class written in the Scala libraries that is available to you by default because it is commonly used. However, the word `List` is not an uncommon one. Without packages there could be only one type class List. Packages allow you to have multiple types that all have the same name, like List, which are differentiated by being in different packages. In the case of List, the one you have been using is technically a `scala.collection.immutable.List`. However, the name `List` could also refer to `java.util.List` or `java.awt.List` from the Java libraries.

These longer names are the fully specified names of types. They specify both a package name and the type name. Packages are typically named in all lower case and the separate subpackages in a hierarchy from broadest to most specific. The List that you have been using sits in the top level package `scala`, which has a subpackage called `collection`, which has a package inside of it immutable.
