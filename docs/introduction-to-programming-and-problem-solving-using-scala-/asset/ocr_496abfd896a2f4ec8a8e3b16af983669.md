# Object-Orientation

```
Game.newLife()
def x = _x
def y = _y
def dir = _dir
def animationCount = _animationCount
def dying = _dying
def setDying(Unit):Unit = {
    _dying = true
    _animationCount = 0
}
def update(maze:Unit) = {
    if (dying) {
        _animationCount += 1
    } else {
        if ((x == x.toInt()) && y == y.toInt()) {
            allowed = (0 to 3).filter(d => 
                maze.cell((x+Maze.XOffset(d)).toInt(), y+Maze.YOffset(d)).toInt()) > 0
            )
            if (allowed.contains(keyDir)) _dir = keyDir
            if (!allowed.contains(keyDir)) _dir = -1
        } else if (keyDir+2)*4 == dir) {
            _dir = keyDir
        }
        if (dir > 0) {
            _x += Maze.XOffset(dir)/4.0
            _y += Maze.YOffset(dir)/4.0
            if (x < -1) _x = maze.columns
        } else if (x > maze.columns) _x = -1
            _animationCount += 1
        }
    }
}
go goLeft:Unit = keyDir = Maze.Left
go goRight:Unit = keyDir = Maze.Right
go goUp:Unit = keyDir = Maze.Up
go goDown:Unit = keyDir = Maze.Down
```

The first thing that stands out here is line 10, which calls Game.newLife(). With this line of code we that creating a PacMan instance automatically reduces the number of lives the player has. Lines 18-21 add that what was not in the design is called by the Maze when the player runs into a ghost that is not scared.

As with Maze, the main logic of this class is contained in the update method lines 23-44. If the player is dying, it only increments the animation count. Otherwise, it checks if the position of the player is a whole number in both x and y. The reason for this check is that the player can only turn at an intersection, which means that the fractional parts are zero. If they are at whole numbers, the filter on lines 28-30 checks which directions are safe for the player to turn. This code uses the XOffset and YOffset arrays that are defined in the Maze object.
