# 4.3 Making and ways Using Functions

There are a number of ways to make functions in Scala. We will begin with the standard definition format. In chapter 2 we saw that we can use the keywords val and var to declare variables. In a similar way, we use the keyword def to define a function. We will start with the simple mathematical examples that were used in the previous section and Scala functions that match in the REPL.

```scala
scala def square(x:Double):Double = x*x
square: (x:Double)Double
```

In math, functions are given names f and g. This works for a limited context, but it does not scale up well if you are using a lot of different functions. We use the name square because it describes what the function does. The name is written the def and after we have a set of parentheses that contain a name and a type separated by a colon: like a val declaration that is called, it does not include an initial value¹ and the type is required. The value is specified when this function is called, just like for the math mathematical function, the type is Double. The contents of the parentheses are the formal parameters of the function.

After the parentheses is another colon and the type that this function gives back, or returns. In Scala we refer to this as the RESULT TYPE. In this case, because we are mirroring the mathematical function, the type is Double. After the result there is an equal sign and the expression x*x. Once this has been entered, the REPL tells us that we have created something like square with the type (x:Double)Double. This is Scala's way of telling us that we have a function that takes a Double and returns a Double.

Now that have defined square we can use it. In the last section we used our function with f(3). The syntax in Scala is the.

```scala
scala square(3)
res0: Double = 9.0
```

We give the name of the function followed by parentheses with the value we want to use for x. When we do this with the value 3, Scala gives back a value of 9.0 as a Double. This particular value could also be represented as an Int, but the function works with type Double and the Int that we passed in was converted to a Double and the result is also a Double.

> ¹Allows you to provide a value here, a default value. That is something you will not often; so, it is not counted until chapter 10.

Let us now look at the second example math function. In this case we will use the short name g and make it with the Int type instead of Double.

```scala
scala def g(x:Int,y:Int):Int = x+y*y
g: (x:Int,y:Int):Int
```

Note that both of the parameters are put in the variables and separated by a comma. In general, you can have an arbitrary number of parameters. They can have different types, and they will be separated by commas. The function is called by giving the function name with values separated by commas,

```scala
scala g(3,5)
res1: Int = 28
```

In this example we used simple literals for the arguments to the function, but the arguments can be any expression with the proper type. For example, we could do the following:

```scala
scala val a = 5
a: Int = 5

scala g(a+2,square(3).toInt)
res2: Int = 88
```

Here we show that the arguments to g can include a reference to a val or a call to the square function. The call to square needs to be followed by a conversion to an Int because g is declared to take Int and the result type of square is Double. If you leave that out, you will figure them out for us: an error like:

```scala
scala g(a+2,square(3))
<console>: 9: error: type mismatch;
found : Double
required: Int
g(a+2,square(3))
```

With the val and var declarations, we say that we could typically leave off the types and Scala would figure them for us. With functions, the types on the parameters are required. The result type is not required as it can be inferred, but it is considered better style to specify it. The reason this is preferred is if you call a function and make a mistake in the function that causes it to result in a different type, Scala can tell you that something has gone wrong.

The block, itself, is either a statement or an expression. When used as an expression, the value you get from it is the value of the last expression in the block. The part of the code over which name can be accessed is called the SCOPE of that name. When you declare a variable or function in script outside of code, it has a scope that goes through the rest of the script. If you declare it in block, it has a scope that goes from the point of declaration to the end of the block. A block is denoted with curly braces, so you can use the name until you get to the right curly brace. As a general rule, you want to minimize the scope of variables so they are only accessed when needed. This is particularly true of var.

> Trap: New programmers are often tempted to have functions declared outside of the function. The majority of time, this is a bad idea as it is very error prone and less reusable.
