From the beginning we have said that Scala is a completely object-oriented language. You have been using objects and calling methods referred to back in chapter 2 when we were taking our first steps in the language. Despite this, we have actually done very little with object-orientation. This has been intentional. So far we have been building your logic skills and teaching you to break problems into different functional units. Now that your problem solving skills have reached a sufficient level we will take the next step to do full object-oriented decomposition of problems. We finish this book by giving you a brief introduction to object-orientation and how to do it in Scala.

# ##16.1 Basics of Object-Orientation

The basic idea of an object is that it contains both data and the functionality that operates on that data. This combining of data and the functionality is commonly referred to ENCAPSULATION. We grouped data originally with tuples and then in chapter 10 we started using case classes to group data together in a more meaningful way. What we did not do with either of these methods was to bind any functionality to them directly. We wrote functions that could operate on them, but was independent of the data itself. In the case of tuples, we cannot bind the functionality into objects. case classes allow us to do this; however, we simply did not keep things simple.
