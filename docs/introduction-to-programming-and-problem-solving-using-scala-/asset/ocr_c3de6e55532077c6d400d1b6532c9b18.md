The setup of the GUI is fairly standard, based on what we have seen previously. The interesting part is that the bindings are at the bottom. All of these bindings are for numeric values. In particular, they have the type `DoubleProperty` as well in the code, we are able to do math with these values, and the result is another `DoubleProperty`.

If you have played much with the previous GUIs, you probably noticed one significant shortcoming, not to allow the user to change the size of the window. In all of the GUIs so far, we have manually set the values of `layoutX` and `layoutY` as `prefetch` and `preheight` when needed. This approach is simple, but it is not really flexible. We could have added the line `resizable = false` to the stage in any of these GUIs to make it that the user is not allowed to change the size of the window, but that does not really fix the underlying problem. The proper way to do with this is to use layouts and panes, which are results described in section 11.7. When you want to do something that an existing layout or pane will not do.

In this example, the `label` is always displayed in the center of the window, even when we resize the window. This behavior is produced by binding the label values to calculations based on the width and height of the full scene and the label. You can use this type of binding to put things in arbitrary locations that are based on the size of the window, but it is less effective than using layouts and panes when they work.

The last binding uses the `<<` operator to link the values of the `ScrollBar` and the `Slider` that is bound to the y-value of the rectangle. If you move one, the other also moves, and the rectangle's vertical position also shifts. In figure 11.13 you can see that the `ScrollBar` and the `Slider` above it are in the same position.
