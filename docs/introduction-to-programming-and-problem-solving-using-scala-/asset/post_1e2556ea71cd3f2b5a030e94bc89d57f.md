# The Option Type

If you start digging through the API much you will find that the type Option, which is in the top level scala package, comes up a fair bit. The idea of an Option type is that they should be used when you are not certain if you have a value or not. An Option[A] can either be Some[A] or None. If it is Some, it will have a value that can be retrieved with get. If there was no value, then you get None and know that it does not have a value. An example of a method that does this is the find method. You can call find on either a List or Array and pass a function that takes an element and returns a Boolean. The find method is supposed to return the first element for which the function returns true. That sounds simple enough, but what if there is not one? What happens if find runs through the whole sequence and nothing makes the function return true? For that reason, the find method returns Option[A] where A is the type contained in the sequence. If nothing works, it can return None.

Let us run through two examples to see how this works using the declaration val lst = List(7, 4, 6, 9, 3, 1).

```scala
scala lst.find(_ < 4)
res0: Option[Int] = Some(3)
scala lst.find(_ < 1)
res1: Option[Int] = None
```

The list contains elements that are less than 4. The first of these is 3 so we get Some(3). However, it does not contain anything less than 1 so that returns None. You might wonder how you could use this type of result. There are actually a few different approaches that can be employed. It depends on what you want to do with the result or based on the result.

The simplest thing to do is to use the getOrElse of the Option type. As the name of this method implies, it will get the value that is stored if is called on a Some or give back some default value if it is called on a None. Here we can see how this might be done using our two previous examples with find.

```scala
scala lst.find(_ < 4).getOrElse(0)
res2: Int = 3
```

```scala
scala lst.find(_ < 1).getOrElse(0)
res3: Int = 0
```

This approach works if you have a good default value in the case where nothing was found. It is also good idiomatic Scala. However, this approach does not work well if you want to perform additional logic in the situation where there is a value or when you want to do different things based on whether or not there is a value. In the situation where you have more processing that was supposed to happen in the case where you have a Some, you can use the map or flatMap methods of Option. Calling map on a Some applies the function to the stored value and results in a Some with the result of that function. Calling map on a None does nothing and results in None. The behavior is exactly what you would expect if Some was a List with one element and None were Nil.

# Type Basics and Argument Passing

Imagine we wanted to square the value we found, but only if we found it. Then map would be a good fit.

```scala
scala lst.find(_ < 4).map(_ * _)
res4: Option[Int] = Some(9)
```

```scala
scala lst.find(_ < 1).map(_ * _)
res5: Option[Int] = None
```

AsAs you can see, the challenge with map, or flatMap, is that you get back another object of type Option. You can go through many maps, even filters, but at some point you will likely need to use one of the other approaches to unwrap it. If you actually want to do something in the case you have a None, the more idiomatic way to do this in Scala is using match. This takes the result of find and tells us what was found.

```scala
scala lst.find(_ < 4) match {
  case Some(i) => "Found "+i
  case None => "Nothing found"
}
res6: String = "Found 3"
```

Note that this is using pattern matching capabilities to get the value of the Option. The Option type also has isEmpty that is true for None and false for Some as well as a get method that will return the value in a Some or crash if None. This is the least idiomatic method of dealing with Option and is generally frowned upon. Code that does the same thing as match look like this.

```scala
val result = lst.find(_ < 4)
res7: Option[Int] = Some(3)
if(result.isEmpty) "Nothing found" else "Found " + result.get
```

Note that the result of the call to find needs to be given a name, because pattern matching is used twice in the code, and calling it twice would be inefficient.

# 7.3 Parametric Functions

Types like List, Array, and Option are not the only things that can have parameters. Functions can have parameters as well. This is something that is not used much in this book as it is more important in later courses, but it can help you to read the API if you are introduced to the syntax. We would make a parametric function if we want to work with different types. You would use flatMap instead of map if the function you were applying was going to result in an Option[Option[A]], so flatMap flattens it to only a single Option.

# Introduction to Programming and Problem-Solving Using Scala

The simplest example of a PARAMETRIC FUNCTION is the identity method shown here.

```scala
def ident[A](a:A)=a
ident: A
```

This method takes an argument of any type and returns it passed in. While there are not many situations where you would want to do this, it demonstrates the syntax of parametric functions. You simply place a type parameter name in square brackets between the function name and the normal argument list. It also demonstrates the power of parametric functions, especially if we were to use it as we do here.

```scala
scala ident(3)
res1: Int = 3
```

```scala
scala ident("3.3")
res2: Double = 3.3
```

First, this function works fine with an Int, a Double, and a String. That is pretty good. Even better, it works with all those types without telling it the types. Parametric functions can almost infer the types of the parameters.

Here is a more complex example that it really does not do much, a function that takes two arguments and returns a tuple with two values in it.

```scala
def makeTuple[A,B](a:A,b:B) = (a,b)
makeTuple: (a:A, b:B) => (A, B)
```

This demonstrates how a function can have many parameters. They appear as a comma-separated list in the square brackets. A simple example would be a function with three elements.

```scala
def threeList[A](a1:A,a2:A,a3:A) = List(a1,a2,a3)
threeList: (a1:A, a2:A, a3:A) => List[A]
```

The main reason for introducing this is that it helps us understand something we saw in the last chapter, the fold methods. We said that fold was much like one of the recursive functions we wrote in the last chapter where we pass in a base value and a function. However, the fold works on sequences of any type and what is more, they can return a different type. With the type of parameters we can write a function with this same capability.

```scala
def ourFold[A,B](list:List[A],base:B)(f:(A,B)=>B):B = {
  if (list.isEmpty) base
  else f(list.head,ourFold(list.tail, base))
}
```

Like in the API, this method is curried, a topic we will discuss in detail section 7.8. It turns out that doing this helps with type inference and allows us to not have to specify types on the function. We can see this working with lst using two different processing functions.

```scala
scala ourFold(List(1,0), _+)
res0: Int = 30
```
