# 1.5.3 Object-Oriented Programming

Object-oriented programming is a relative newcomer to the list of programming paradigms. The basic idea of object-oriented programming first appeared in SIMULA67 programming language. As the name implies, it dates back to the 1960s. However, it did not gain much momentum until the 1980s when the Smalltalk language took the ideas further. In the 1990s, object-oriented reality hit it and virtually any new language that is created and expects to use object-oriented features.

The basic idea of orientation is quite simple. It is that data and functions that operate on the data should be bundled together into objects. This idea is encapsulation, and we will discuss it at the end of this book. This might seem like a simple idea, but it enables us of significant extras that do not become apparent until you have worked with it a while.

Object-orientation is not really independent of the imperative and functional paradigms. Instead, object-oriented programs can be done in either a functional or an imperative style. The early object-oriented languages tended to be imperative and most of the ones in use today still are. However, there are a number of functional languages that now include object-oriented features.

Scala is a purely object-oriented language, statement that is not true of many languages. What this means and the implications of it are discussed in detail in later chapters. For most of this book, the fact that Scala is object-oriented will not even be significant to us, but it will always be under the surface.

# 1.5.4 Logic Programming

The fourth paradigm is logic programming. The prime example language is Prolog. Logic programming is completely declarative. As the name implies, programs are written by writing logical statements. It is up to the language/computer to figure out a solution. This is the least used of the paradigms. This is in large part because of significant performance problems. The main use is in artificial intelligence applications. There is indication that logic programming could reappear in languages where it is combined with other paradigms, but these efforts are still in the early stages.

# 1.5.5 Nature of Scala

As indicated in the sections below, Scala provides a mix of different paradigms. It is a truly hybrid language, as the programmer, the ability to solve problems in the way that makes the most sense to you or that best suits the problem at hand. The Scala language directly includes imperative, functional, and object-oriented elements. The name Scala stands for Scalable Language; so, it is not completely out of the question to add them to a library in the future that could support logic programming to some extent if a benefit doing so was found.
