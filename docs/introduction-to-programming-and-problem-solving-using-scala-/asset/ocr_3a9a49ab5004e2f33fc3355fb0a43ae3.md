It is worth noting that while we are presenting one complete file at a time, this is not how it was written. Real development moves from one file to another and back again, iterating as features are added. This approach does not just help with logic, but it helps with getting things done. You should stop coding and run your program so often to make sure it works. You also debug each feature as you add. Do not try to go on to the next feature until you have the current state working. Focusing on a single task can be challenging, but it helps tremendously with the development process.

Next is Maze, which is declared as a class. This is where lot of the logic of the game actually takes place. The Maze class does not take any arguments as it always sets up in a default configuration. Lines 4-9 declare a number of private vars, setting them all to default values. This can be dangerous, especially the null, except that lines 11-12 declare the initMap and initContents methods that get those values. Earlier iterations of the code set those values at the point of declaration, but it is useful to be able to tell them.
