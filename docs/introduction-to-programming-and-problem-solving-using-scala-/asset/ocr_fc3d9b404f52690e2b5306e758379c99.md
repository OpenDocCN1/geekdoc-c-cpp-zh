What does all of this have to do with NaN? NaN stands for "Not-a-Number", and it is the result of an operation when it is not what the result should be. One way to get this is to add Infinity and -Infinity or other operations with Infinity or -Infinity that the computer cannot know the result of. Consider this example.

```
scala 1e150*1e200-1.0/0.0
res105: Double = NaN
```

In general the computer cannot know if this would be out of range or negative so it goes to NaN because it gives up. There is one other way to get to NaN: divide by zero

```
scala 0.0/0.0
res106: Double = NaN
```

This is what is happening to cause our error, and it happens when zero test or assignment grades or only one grade have been entered.
If have no test or assignment grade, the normal average will return 0.0/0.0, as the sum is Double 0.0 and the length is the Int. If the list of grades has only one element, then one is the median. The function returns (x-x)/(x-1) where x is the grade as Double. How do we fix this? We need to make the average and the averageDropMin function a smaller bit so that we have special cases in the instances they should not do division. We can do this by putting expressions in both.

```
def average(nums:List[Double]):Double = =
if (nums.isEmpty) 0 else nums.sum/nums.length

def averageDropMin(nums:List[Double]):Double = =
if (nums.isEmpty || nums.tail.isEmpty) 0 else
(nums.sum-nums.min)/(nums.length-1)
```

If you use these versions of the functions things work well.
Now to the functional alternative. The imperative version uses var declarations outside of the function. These declarations can be seen by anything in the script that follows them. We properly refer to this as the GLOBAL SCOPE. For small scripts this might not be a problem, but do not want to get into the head of making things global, especially if it is a var or mutable. That is global in a large program can be messed up by any line of code, making it very hard to track certain types of errors. It is better to have our variables declared a LOCAL SCOPE, inside of a function.
