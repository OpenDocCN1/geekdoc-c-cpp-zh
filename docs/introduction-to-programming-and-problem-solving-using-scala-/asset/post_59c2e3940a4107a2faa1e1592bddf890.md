## 12.2 Basic Keyboard, Mouse, and Touch Input

In chapter 11 how we could add in code to interact with the various GUI elements. It is also possible to interact with the user at a lower level by getting individual actions from the keyboard and mouse as well as touch. This can be done using many different properties that begin with on, each of which is a function that is called when something happens. We will look at these separately for the different types of interactions.

For the keyboard there are only three properties of significance: keyPressed, keyReleased, and onType. The keyPressed function is called when a key goes down. The keyReleased is called when a key is held up. The onType is called for the full typing of a character and is only for keys that wind binding up. This means that onType does not register things like arrow keys, Shift, or Ctrl when keyPressed and keyReleased.

These handlers all take an argument of scalafx.scene.KeyEvent. This provides you with information about how key was part of the event as well as other things that you may need to know. The KeyEvent object contains members such as character for typed values, keyCode (including non-printable keys), as well as altDown, controlDown, metaDown, and shiftDown. The code member has type such as scalafx.scene.keyCode. You can compare those values in KeyCode such as KeyCode.A, KeyCode.F1, KeyCode.Left, or many others that represent whatever keys might be on your keyboard.

In section 11.5.1 we discussed the concept of focus as it relates to text controls.

> Note that keyboards have a "repeat" rate so that if you press a key and hold it, multiple events will wind up.

The Mouse handler is just one of several event handlers that you can register for dealing with user interactions using mouse. The following list shows the different options, when these handlers are called, and the type of event that gets passed into them.

- onDragDetected - Takes aMouseEvent and is called when a drag is detected.

- onDragDone - Takes a DragEvent and is called when a drag-and-drop event ends after the release and the current Node is the source of the drag.

- onDragDropped - Takes a DragEvent and is called when a mouse button is released at the end of a drag-and-drop on the current Node.

- onDragEntered - Takes a DragEvent and is called when a drag-and-drop motion enters this Node.

- onDragExited - Takes a DragEvent and is called when a drag-and-drop event exits the current Node.

- onDragOver - Takes a DragEvent and is called when a drag-and-drop event moved over the current Node.

- onMouseClicked - Takes a MouseEvent when the mouse is clicked over this Node.

- mouseDragEntered - Takes a MouseDragEvent and is called when the mouse enters the Node while the mouse button is down.

- mouseDragExited - Takes a MouseDragEvent and is called when the mouse leaves the Node while the mouse button is down.

- mouseDragOver - Takes a MouseDragEvent and is called when a full mouse-drag-release gesture happens on this Node.

- mouseDragReleased - Takes a MouseDragEvent and is called when a mouse press-drag-release ends on this Node.

- mouseDragged - Takes a MouseDragEvent and is called when the mouse is pressed on this Node dragged.

- mouseEntered - Takes a MouseEvent when the mouse enters this Node.

- mouseExited - Takes a MouseEvent when the mouse exits this Node.

- mouseMoved - Takes a MouseEvent when the mouse moves within this Node and no buttons are pressed.

- mousePressed - Takes a MouseEvent when a mouse button goes down over this Node.

- mouseReleased - Takes a MouseEvent when a mouse buttons is released over this Node.

- onScroll - Takes a ScrollEvent and when the user performs a scroll action.

- onScrollFilled - Takes a ScrollEvent and when the user finises a scroll action.

- onScrollStarted - Takes a ScrollEvent and when the user begins a scroll action.

The MouseEvent object has all the information you need to know about the state of the mouse and all other information for the particular event. The following list shows significant members of the MouseEvent type that you might need to use to interpret what to do with that action.

- altDown: Boolean - Tells if the Alt key was down during this.

- button: MouseButton - Gives a value that can be compared to MouseButton.Middle, MouseButton.None, MouseButton.Primary, or MouseButton.Secondary.

- clickCount: Int - Tells you how many times the mouse has been clicked in a row so the program can respond to double clicks, triple clicks, etc.

- controlDown: Boolean - Tells you if the Control key was down during this event.

- metaDown: Boolean - Tells you if the Meta key was down during this event.

- middleButtonDown: Boolean - Tells you if the mouse button was down for this event.

- pickResult: PickResult - Used for 3D graphics discussed in section 12.11.

- primaryButtonDown: Boolean - Tells you if the primary mouse button was down during this event.

- sceneX: Double - Tells you the x-coordinate of the mouse in the Scene.

- sceneY: Double - Tells you the y-coordinate of the mouse on the full scene.

- screenX: Double - Tells you the x-coordinate of the mouse on the full screen.

- screenY: Double - Tells you the y-coordinate of the mouse on the full screen.

- secondaryButtonDown: Boolean - Tells you if the secondary mouse button was down during this event.

- shiftDown: Boolean - Tells you if the Shift buttons was down during this event.

- shortcutDown: Boolean - Tells you if the shortcut modifier for your platform was down during this event.

- source: AnyRef - Tells you the object on which the event initially occurred.

- stillSincePress: Boolean - Tells you if the pointer has stayed in the same location since the last pressed event occurred.

- x: Double - Tells you the x-coordinate of the mouse in the Scene.

- y: Double - Tells you the y-coordinate of the mouse on the full scene.

- z: Double - Tells you the z-coordinate (depth) of the mouse relative to the source.

The DragEvent is a subtype of MouseEvent which can be used to determine the object that the drag started with. DragEvent removed the members that tell you about buttons and instead has a method called drag which returns an object of type Drag. The ScrollEvent has many of the same methods as MouseEvent related to keyboard keys and position, it adds others specific to scrolling.

Mouse and keyboard interactions are demonstrated in the following program which allows the user to draw paths with the mouse then use the arrow keys to move a little circle. The circle is not allowed to cross lines.

# Listing 12.4: DrawMaze.scala

```
import scalafx.Imports._
import scalafx.application.JFXApp
import scalafx.scene.Scene
import scalafx.scene.paint.Color
import scalafx.scene.shape._
import scalafx.scene.input.MouseEvent
import scalafx.scene.input.KeyCode
val app = new JFXApp {
  stage = new JFXApp.PrimaryStage {
    title = "Draw Maze"
    scene = new Scene(500,500) {
      val polyline = Polyline(0, 0, 500, 0, 500, 500, 0, 500, 0, 0, 0)
      var walls = List(polyline)

      val ball = Circle(21, 21, 20)

      content = List(ball) = (e:MouseEvent) => {
        println("Pressed")
        val oldX = ball.centerX.value
        val oldY = ball.centerY.value
        if (e.code == KeyCode.Up) ball.centerY = ball.centerY.value - 2
        if (e.code == KeyCode.Down) ball.centerY = ball.centerY.value + 2
        if (e.code == KeyCode.Left) ball.centerX = ball.centerX.value - 2
        if (e.code == KeyCode.Right) ball.centerX = ball.centerX.value + 2

        // Collision detection with walls
        val clear = walls.forall(shape =>
          Shape.intersect(ball,shape).boundsInLocal.value.isEmpty
        )
      }
    }
  }
}
```
