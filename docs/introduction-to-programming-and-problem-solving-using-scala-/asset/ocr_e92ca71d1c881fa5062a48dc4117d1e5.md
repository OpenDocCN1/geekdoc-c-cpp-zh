Adding numbers in binary is best done in pairs. The reason is that as soon as you add together 3 or more numbers in binary you have the capability to have to do something you are not accustomed to doing in decimal: carry a value up two digits. In decimal you would have a column sum up to one or hundred for this to happen. However, in binary you only have to get to four (which is written as 100 in binary). That happens in this particular instance the 6th digit. To reduce the odds of an error, it is better to add the two values at a time as we have shown here.

```
1101010
+ 1010100

100111110
+ 10101100

1011100110
+1010100000

10010000110
```

# 2.5.2 Negative Numbers in Binary

We have not addressed the question of how we represent negative numbers on a computer. The description that we have given so far only deals with positive values. Numbers that are interpreted this way we call UNSIGNED. All the numeric types in Scala are SIGNED, so we should figure out how that works. To this, there are two things that should be kept in mind. The first is that our values have limited precision. That is to say they only store a certain number of bits. Anything beyond is lost. The second is that negative numbers are defined as the additive inverses of their positive counterparts. In other words, $x + (-x) = 0$ for any $x$.

To demonstrate how we get negative numbers, let's work with the number 1101101 (53 in decimal). Unlike before, we will now limit ourselves to a single byte.
