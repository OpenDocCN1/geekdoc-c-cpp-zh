Everything that is discussed in this section will work on the remote machine as well as the local one, no matter how away the machine is. When you are done entering commands and you want to come back to the current machine, type logout or exit to terminate the remote session.

# Aside

If your username on the remote machine is different from that the current machine you can use "ssh username@machine" to specify the remote username. Also, the ssh command has one argument that will be particularly helpful once you get past chapter 11. The -Y option allows the remote machine to send windows back to the current machine. use "ssh -Y machine" to activate this.

What if you are on a Windows machine? How can you connect? Your windows machine should likely have telnet if it bring up the command prompt. As mentioned above, this type of connection will be likely blocked for security reasons. Frankly, there are free ssh programs that you can get for Windows. One of these is putty and it will allow you to ssh into a remote machine and use it from a Windows. If you like the Unix/Linux command prompt you can also install Cygwin under Windows and getsh. ssh, and all the other commands we will talk about on your Windows machine.

# Aside

You can get windows sent back to your machine through Putty using Xforwarding. This is a bit more complex so you should look at the help for Putty to see how to do it.

An better approach if you have a Windows machine is create dual boot so you can run Linux on the machine. There are versions of Linux such as Ubuntu@ Linux Mint which are specifically targeted at novice users or people who want to just get things running without much difficulty. You can download them from their websites at http://www.ubuntu.com and http://linuxmint.com respectively. If you do not want to dual boot your machine, you can run Linux in a window using free virtualization software such as VirtualBox@(http://www.virtualbox.org) or VMwarePlayer@(http://www.vmware.com/products/).

telnet, r and ssh all give you ways to log into a remote machine and execute commands on that machine. Some times you want to move files from one to another. For this you should probably use sc or sftp. The sc command stands for secure copy. You use it like you would the normal cp command. The only difference is that your file names can be prepended with a machine name and a colon to say that they come from or are going to a different machine. 

```
scp cs.trinity.edu:Desktop/fileInet.txt
```
