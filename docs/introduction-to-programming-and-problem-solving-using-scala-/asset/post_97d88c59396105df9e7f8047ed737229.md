Now we need to perform an operation on the contents of the Array. We will skip the step of making a special function for just adding or multiplication and jump straight to the more abstract and flexible method where we pass a function to operate on the contents. In addition to doing the operation, we also need an Array and an integer for the current index. Unlike what we did in the previous chapter, we do not need to pass in a base case because we know when we are at the beginning or end of the Array. The function could look like this.

```scala
def operateOnArray(arr:Array[Int],index:Int, func:(Int,Int)->Int):Int = {
  if (index < arr.length-1) {
    func(arr(index), operateOnArray(arr, index+1, func))
  } else {
    arr(arr.length-1)
  }
}
```

If an index at or beyond the last element of the Array is passed in, this function results in the last element of the array. Otherwise, it applies the function to the current element and the result of the recursive function on subsequent elements. We can see this this in action on the previously defined Array, arr, in these commands.

```scala
scala val arr = Array(7,4,6,3,9,1)
res13: Array[Int] = Array(7, 4, 6, 3, 9, 1)
```

```scala
scala operateOnArray(arr, 0, _*)
res13: Int = 30
```

```scala
scala operateOnArray(arr, 0, _*)
res14: Int = 4536
```

Already this allows us to use the added power we get from using an Array. Having the values stored gives us the ability to operate on them multiple times without having to input them multiple times.

# Arrays and Lists in Scala

## 6.3 Lists

Arrays are built in collection of choice in most non-functional languages. An Array is typically stored as a single block of memory. This makes them fast and efficient for a lot of operations. As we saw, Arrays are mutable. Functional languages tend to lean away from mutation and other side effects. If you do not allow mutation, Arrays becomes much efficient. If you want to change a single value in an immutable Array, you have to make a complete copy of the Array. For this reason, functional languages prefer to use lists. Technically the List type in Scala is an immutable singly linked lists, a data structure that you should become familiar with in a later course. You do not have to understand the structure in how to use it.

We can build a List using the syntax to build an Array with initial values.

```scala
scala List(7,4,6,3,9,1)
res15:List[Int] = List(7, 4, 6, 9, 1)
```

Like the Array, the List type is parametric and Scala will figure out the best type if you use this syntax.

Unlike Arrays, Lists do not have a fixed length determined at the time it is created. Then there is another way to put Lists together when we do not know initially all of the values that will be stored. We can easily build Lists one element at a time if we add to the front of the List. To add elements to a List we use the "cons" operator, :: Here is an example of adding a single element to an existing List.

```scala
scala val lst = List(2,3,4)
lst:List[Int] = List(2, 3, 4)
```

We begin by creating a List that contains 2, 3, and 4, then cons 1 to the beginning of the list. This operation did not alter the original List. It gave us a new list with an extra element at the beginning. Because of the way that Lists works, it is efficient. It did not have to copy the List to make it work. We can look at lst again to see that it has not changed.

```scala
scala lst
res17:List[Int] = List(2, 3, 4)
```

If you build a List with the cons operator, it is common to start with an empty List. There are two ways to represent an empty List in Scala. One is to not put arguments in the parentheses. The other is to use Nil. So we can build the same list we had before way.

```scala
scala 1::2::3::4::Nil
res18:List[Int] = List(1, 2, 3, 4)
```

You have to place the Nil at the end because the :: operator needs to have a List on the right hand side. Notice that for this to work, the :: operator is right associative.

> This was something we first discussed with the difference between val and var. As a general rule, programs are easier to reason about when they do not include mutation. Including mutation makes things more complex by introducing errors. So 1::2::the same as 2::1 is the opposite of the normal mathematical operators which are left associative. In Scala, any operator that ends with :: will be right associative. We can use the cons operator to write a function that builds a List of numbers from user input. Going until "quit" works well for Lists because we can easily add new elements to a List. It was not the case for Arrays where we had to halve the size. The method for this is quite simple.

```scala
def inputList():List[Int] = {
  val in = readLine()
  if (in == "quit") Nil else in.toInt::inputList()
}
```

We can see this work as we run it with 3, 4, 5, and "quit" on separate lines.

```scala
scala> inputList()
res19: List[Int] 
```

It is possible to access the elements of a List the same way you do an Array by putting index. However, for a List this is generally inefficient. The preferred method, especially for large lists, is to use the methods head and tail. The head method will give back the first element of the List. The tail method gives you a List of all the elements after the first.

```scala
> lst.head
res20: Int = 2
```

```scala
> lst.tail
res21: List[Int] = List(3, 4)
```

Using these methods we can write an operateList function that mirrors the operateOnArray function.

```scala
def operateList(lst:List[Int], func:(Int,Int)->Int): Int = {
  if (lst == Nil) Nil else func(lst.head, operateList(lst.tail, func))
}
```

Note that we do not require an index to be passed. We do not have + or -1 in this function. That type of behavior comes from the fact that we recurse, we pass in lst.tail. We can see this function in action here:

```scala
> val lst=List(7,4,6,3,9,1)
lst: List[Int] = List(7, 4, 6, 3, 9, 1)
```

```scala
> operateList(lst, _*)
res22: Int = 30
```

```scala
> operateList(lst, _*)
res23: Int = 4536
```

This function was written using an if statement. When working with lists, it is also common to pattern matching. The :: can be used in a pattern to indicate a list with different parts. This particular function List2 can be rewritten as shown here.

```scala
def operateList2(lst:List[Int], func:(Int)=>Int):Int = lst match {
  case h::Nil => 0
  case h::t => func(h, operateList2(t, func))
  case _ => 0
}
```

You might wonder about the last case. This is not required, but if we leave it out we will get a warning telling us that the match is not exhaustive. This is not just the compiler being overly picky. It turns out that the original method that uses an if expression is safe. Try calling it with an empty List and you will see why.

## 6.4 Bigger Arrays and Lists with Fill and Tabulate

The simple syntax for creating Arrays and Lists work well for short sequences. In Case of Lists, you can build a large List using :: and a recursive function, but there are even easier ways to do so with the fill and populate methods. To use the fill method you specify how many elements you want, and the object value to fill each element with. Some examples of fill might look like the following.

```scala
scala Array.fill(10)(4)
res24:Array[Int] = Array(4, 4, 4, 4, 4, 4, 4, 4)
```

```scala
scala List.fill(6)(23)
res25:List[Int] = List(23, 23, 23, 23, 23, 23)
```

```scala
scala List.fill(6)("hi")
res26:List[String] = List("hi", "hi", "hi", "hi", "hi", "hi")
```

Array and List here refer to what are called "companion objects", and like all objects, they can have methods. You can see the various methods using tab completion in the REPL. You might notice something about how the fill is called. It takes two arguments, but instead of being passed in one parameter list with a comma between, they are passed in two parameter lists. This is called CURRYING. We will discuss fully in section 7.8. The first argument is how many values we want in the resulting sequence, and the second that gives the values is.

The other thing to note about fill is that the second argument is passed in a special way "pass-by-name". This is a very powerful feature of Scala that will be covered in the next section 7.9. For now, we will simply show why it matters. Consider the following two examples.

```scala
> List.fill(5)(math.random)
res27:List[Double] = List(0.34276326027921, 0.8128658516345523, 0.6149601139661, 0.53806172408777, 0.705727808692085)
```

```scala
> Array.fill(3)(readInt)
res28:Array[Int] = Array(1, 2, 3)
```
