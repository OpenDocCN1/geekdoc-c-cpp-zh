```
$a_x(i) = -\sum_{j} \frac{(x_j - x_i) m_j}{d_{ij}^2}$
```

There is a similar formula for y. The $d_{ij}$ is the distance between particle i and particle j. Also note that given a value, the best way to cube it is `c*c*c` math.

When you write your formula in the code, think about it. This formula causes a problem if we use d because particles can get too close to one another. It is suggested that you want to make $d = \sqrt{d_x^2 + d_y^2 + epsilon}$, where epsilon is a small value. You can play with how small you want it to be because that depends on the scale of your problem. It is also recommended that you have your integrator not use the normal Euler method which calculates accelerations, then updates positions, then velocities. Make sure that it does the accelerations on velocities before applying the velocities to the positions. Keep in mind that you want to break this up into functions that fit together nicely and are helpful. It will hurt your brain if you do not.

- 3. This is the first installment for you building your own text adventure. Your program will read in a map file that you will write and let the user run around that map by using commands like "north" to move from one room to another. The map file will have a fairly simple format right now and you can create your own map file. Make sure when you turn in this program you turn in both the script and the map file so it can be tested with your map.

The format of the map file should start with a line telling the number of rooms then has something like this. You can change this if you want to use a slightly different format:

```
room_number
room_name
long line of room description
number_of_links
direction1
destination1
direction2
destination2
...
```

This is repeated over and over. (The number of rooms helps for storing things in an Array that you know big to make it.) Each room should have a unique room number, and they should start at 0. The reason is that you will be putting all the room information into Arrays. There is a link on the book's website to a sample map file, but you do not have to stick exactly to that format if you do not want to. Use it if you are thinking about other options you might want in later. Odds are good if you will be refactoring your code for later projects.

The interface for your program is quite simple. When you run the program it should read in the map file and keep all the map information stored in an Array[Room] where Room is a case class you have made to keep the significant information for each room. You will start the user in room 0 and print the description of that room.

> ⁴Many implementations also make a case class to represent an Exit from a room and the different directions they can go as well as those exits lead to, then follow that a prompt.
