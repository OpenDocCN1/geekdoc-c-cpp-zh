(Note that you can also call the par method on a List, but it is not efficient because it has to convert the List into a different structure that is efficient to work in parallel.) Many calls to parallel collections will get split up multiple threads, as will be for loops. To see the impact of this, consider the following.

scala def fact(n:BigInt):BigInt = if (n<2) 1 else n*fact(n-1)

The factorial of BigInt is used in part because it is fairly slow. The first version everything runs in that you expect and the values of 30! to 15! are printed in order. With the addition of par, the values are no longer in order. Instead, work is broken up into different threads and each value prints after it has been calculated. The biggest values take longer to calculate; so, they are not the first to print.
