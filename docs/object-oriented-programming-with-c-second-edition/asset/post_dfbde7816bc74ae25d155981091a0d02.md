
## 2.2.2 Default Values for Formal Arguments of Member Functions

We already know that default values can be assigned to arguments of non-member functions. Default values can be specified for formal arguments of member functions also. An illustrative example follows in Listing 2.17.

**Listing 2.17** Giving default values to arguments of member functions

```cpp
/*Beginning of memFuncDefault.cpp*/
#include<iostream.h>
class A {
public:
    void show(int p=1);
};
void A::show(int p) {
    for(int i=0;i<p;i++)
        cout<<"Hello\n";
}
void main() {
    A A1;
    A1.show();                   //default value taken
    A1.show(3);                  //default value overridden
}
/*End of memFuncDefault.cpp*/
```

Output

Hello
Hello
Hello
Hello

Again, it has to be kept in mind that a member function should be overloaded with care if default values are specified for some or all of its formal arguments. For example, the compiler will report an *ambiguity error* when it finds the second prototype of the show() function of class A in Listing 2.18.

**Listing 2.18** Giving default values to arguments of overloaded member functions lead to ambiguity errors

```cpp
class A {
public:
    void show();
    void show(int p=0);             //ambiguity error
};
```

Reasons for such ambiguity errors have already been explained in the section on overloading in Chapter 1. As the case of non-member functions, if default values are specified for more than one formal argument, they must be specified from the right to the left. Similarly, default values must be specified in the function prototypes and not in function definitions. Further, default values can be specified for a formal argument of any type.

## 2.2.3 Inline Member Functions

Member functions are made inline by either of the following two methods.

- By defining the function within the class itself (as in Listing 2.5)
- By only prototyping and not defining the function within the class. The function is defined outside the class by using the scope resolution operator. The definition is prefixed by the inline keyword. In non-member functions, the definition of the inline function must appear before it is called. Hence, the function should be defined in the same header file in which its class is defined. Listing 2.19 illustrates this.

### Listing 2.19 Inline member functions

```cpp
/*Beginning of memInline.cpp*/
class A {
  public:
    void show();
}
inline void A::show() //definition in header file
{ // //definition of A::show() function
}
/*End of memInline.cpp*/
```

## 2.2.4 Constant Member Functions

Let us consider this situation. The library programmer desires that one of the member functions of his/her class should not be able to change the value of member data. This function should be able to read the values contained in the data members, but not change them. However, he/she fears while defining the function he/she might accidentally write the code to do so. In order to prevent this, he/she seeks the compiler's help. If he/she declares the function as a constant, and therefore prevents change to the value of a data member through function, the compiler throws an error.

Let us consider the class Distance. The Distance::get(), Distance::inches(), and the Distance::add() functions should obviously be constant functions. They should not change the values of members of the invoking object by accident.

Member functions are specified as constants by suffixing the prototype and the function definition header with the const keyword. The modified prototypes and definitions of the member functions of the class Distance are illustrated in Listing 2.20.

### Listing 2.20 Constant member functions

```cpp
/*Beginning of Distance.h*/
/*Header file containing the definition of the Distance
class*/
class Distance
{
    int iFeet;
    float fInches;
public:
    void setFeet(int);
    int getFeet() const;
    void setInches(float) const;
    float getInches() const;
    Distance add(Distance) const;
};
//End of Distlib.h*/

/*Beginning of Distlib.cpp*/
/*Implementation file for the class Distance*/
#include"Distance.h"

void Distance::setFeet(int x)
{
    iFeet=x;
}
int Distance::getFeet() const
{
    iFeet++;
    //ERROR!!
    return iFeet;
}

void Distance::setInches(float y)
{
    fInches=y;
}

float Distance::getInches() const
{
    fInches=0.0;
    //ERROR!!
    return fInches;
}

Distance Distance::add(Distance dd) const
{
    Distance temp;
    temp.iFeet=iFeet+dd.iFeet;
    temp.setInches(fInches+dd.fInches);
    iFeet++;
    //ERROR!!
    return temp;
}/*End of Distlib.cpp*/
```

For constant member functions, the memory occupied by the invoking object is readonly memory. How does the compiler manage this? This pointer becomes 'a constant pointer to a constant' instead of 'a constant pointer'. For example, this pointer is of type Distance* const for the Distance::get(), Distance::inches(), and the Distance::add(Distance). Clearly, constant member functions cannot be called with respect to an object.

## 2.2.5 Mutable Members

A mutable data member can be modified even inside a constant function. This is because the data member is declared with the mutable keyword. Listing 2.21 illustrates this.

### Listing 2.21 Mutable members

```cpp
/*Beginning of mutable.h*/
class A
{
    int x;
    mutable int y;
public:
    void abc() const
    {
        y++;
    }
    void def() const
    {
        y++;
    }
};
/*End of mutable.h*/
```

## 2.2.6 Friends

A class can have non-member functions and member functions of other classes as friends. Such functions can access private members.

### Non-member functions

A friend function is a non-member function that has special rights to access private members of class. In this section, we will only study those functions that are not member functions. A friend function is prototyped within the definition of the class which it is intended to be friend. The prototype is prefixed with the keyword friend. An illustrative example is shown in Listing 2.22.

### Listing 2.22 Friend functions

```cpp
/*Beginning of friend.cpp*/
class A
{
    int x;
public:
    friend void abc(A); //prototype of the friend function
};
void abc(A& Aobj) //definition of the friend function
{
    Aobj.x++; //access private members of the object
}
void main()
{
    A A1;
    abc(A1);
}/*End of friend.cpp*/
```

A few points about the friend functions that we must keep in mind are:

- friend keyword should appear in the prototype and not in the definition.
- Since it is a non-member function of the class of which it is friend, it can be prototyped in either the private or the public section of the class.
- A friend function takes one extra parameter as compared to a member function that performs the same task. This is because it cannot be called with respect to any object. Instead, the object itself appears as an explicit parameter in the friend call.
- We need not and should not use the scope resolution operator while defining a friend function.

### Friend classes

A class can be a friend of another class. Member functions of a friend class can access private data members of objects of the class of which it is friend. If class B is to be made a friend of class A, then the statement should be written within the definition of class A.
