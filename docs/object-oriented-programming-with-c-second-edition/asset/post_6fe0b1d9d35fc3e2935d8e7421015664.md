## 11.3.5 Throwing Parameterized Objects of a Nested Exception

Let us have a look at Listing 11.11.

Listing 11.11 Nested exception class

```cpp
#include<iostream.h>
#include<string.h>

template<class T>
class vector
{
    T * v;
    int size;
public:
    class RangeError
    {
        char Error[30];
        int errorPos;
        public:
        RangeError(char * str,int p)
        {
            strcpy(Error,str);
            errorPos=p;
        }
        char * getError()
        {
            return Error;
        }
        int getPos()
        {
            return errorPos;
        }
    };
    vector(int s)
    {
        v=new T[s];
        size=s;
    }
    ~vector()
{
        delete[] v;
    }
    void setElement(T val,int p)
    {
        if(p>size-1 || p<0)
            throw RangeError("Out of range exception - could not write",p);
        v[p]=val;
    }
    T& getElement(int p)
    {
        if(p>size-1 || p<0)
            throw RangeError("Out of range exception - could not read",p);
        return v[p];
    }
};
```

We can define the exception class as a nested class of the class that throws it. This indicates the class originating an exception. It also prevents pollution of the global namespace. In the example in Listing 11.11, the class RangeError has been declared within the vector class. If the setElement() function or the getElement() function finds a bad subscript value, it throws an exception of type RangeError. The handler for this exception looks like

```cpp

```

it may be noted that the nested exception class is public. This allows the catch block to have access to the type.

## 11.3.6 Catch Caught Exceptions

The C++ language supports a feature to catch exceptions that were raised in a try block but not caught by any of the catch blocks. The syntax of the catch construct to handle exceptions is follows.

```cpp
catch(...)
{
  //action for handling an exception
}
```

The three dots in catch(...) indicate that it catches all types of exceptions. Listing 11.12 illustrates the use of this catch block.

Listing 11.12 Catch uncaught exceptions

```cpp
#include<iostream.h>
class Sugar{};
class Spice{};
class Tasteless{};
void abc(int);

void main() {
    try {
        abc(-1);
    } catch(Sugar) {
        cout<<"Caught Sugar\n";
    } catch(Spice) {
        cout<<"Caught Spice\n";
    } catch(...) {
        cout<<"Unidentified object caught\n";
    }
}

void abc(int p) {
    if(p<0)
        throw Tasteless();
}
```

## 11.3.7 Re-throwing Exceptions

Suppose you are defining a function, which calls another function and the called function throws an exception. You will therefore have a try/catch mechanism in your function for handling the exception that the called function throws. Suppose that the name of your function is test_hmean() and the name of the called function is hmean(). The overall structure of your function would look like:

```cpp
double test_hmean(double p, double q)
{
    //Variable declaration statements.
    try {
        r=hmean(p,q);
    } catch {
        //Catch handler
    }
}
```

Now, suppose that you know only a part of what your function needs to do if it catches the exception or you do not have any idea of what your function needs to do if it catches the exception. In both cases, you would like the function that calls your function to do something about it. For this, you would like your function to re-throw the exception to the function that has called it. Listing 11.13 shows how functions can re-throw exceptions. In this case, the main() function has called your function. Note how the throw keyword has been used below in the test_hmean() function.

# Listing 11.13 Re-throwing exceptions

```cpp
/*Beginning of Rethrowing1.cpp*/
/*
Program to illustrate re-throwing of exceptions.
*/
#include <iostream>
#include <string.h>

double test_hmean(double p, double);
double hmean(double, double);

class hmeanexception
{
    char cError[30];
public:
    hmeanexception(char * s)
    {
        strcpy(cError, s);
    }
    char * getError()
    {
        return cError;
    }
};

void main()
{
    double x, y, z;
    x = 10;
    y = -10;
    try {
        z = test_hmean(x, y);
    } catch(hmeanexception& e)
    {
        cout << "Inside the catch block of main()\n";
    }
}

double test_hmean(double p, double q)
{
    double r;
    try {
        r = hmean(p, q);
    } catch(hmeanexception& e)
    {
      cout << "Inside the catch block of test_hmean()\n"
      throw;
    }
    return r;
}

double hmean(double a, double b)
{
  if(a==b)
    throw hmeanexception("Exception error - a*b not allowed")
  return 2.0*a/(a+b);
}
/*/End of Rethrowing1.cpp*/
```

# Output

Inside the catch block of test_hmean()
Inside the catch block of main()

Let us follow the execution of the main() function. The main() function calls the test_hmean() function from inside the try block. The test_hmean() function in turn calls the hmean() function from inside the try block. The hmean function throws an error because the values passed to it are opposite to each other (10 and -10). The type of exception is hexexception. The test_hmean() has a catch block that handles exceptions of this type. Therefore, the catch block of the test_hmean() executes. The first statement of the catch block displays "Inside the catch block of test_hmean()". The second statement of the catch block throws the same exception. Thus, the exception is not consumed by the test_hmean() function. Inside, it gets upwards to the calling function, which is main().

main() in turn has a catch block that handles exceptions of the thrown type. Therefore, the catch block of the main() function executes. The single statement in this displays the error "Inside the catch block of main()".

Naturally, if the throw statement is removed from the catch block of the test_hmean() function, then the catch handler of the main() function would not receive any exception for it to handle. execute(the test_hmean() function would not be throwing anything).
