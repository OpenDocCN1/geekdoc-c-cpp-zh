# Listing 2.1 Undesirable manipulation of structures not prevented in C

```
struct Date d1;
setDate(&d1); //assign system date to d1.
printf("%d", d1.month);
d1.month = 13; //undesirable but unpreventable!!
```

The bug arising out the last line of the main() function is easily detected even by a visual inspection. Nevertheless, the same will not be the case if the code is around 25,000 lines long. Lines similar to the last line of the main() function may be scattered over all the code. Then, it will be difficult to hunt down.

Notice that the absence of a facility to bind the data and the code that can have the exclusive rights to manipulate the data can lead to difficult-to-detect run-bugs. C provides not the library programmer with the facilities to encapsulate data, to hide data, and abstract data.

The C++ compiler provides a solution to this problem. Structures (the struct keyword) have been redefined to allow member functions also. Listing 2.2 illustrates this.

# Listing 2.2 C++ allows member functions in structures

```

#include <iostream.h>

struct Distance
{
    int feet;
    float inches;

        feet=x;

        return feet;
    }
    void setInches(float y)
{
        inches=y;
    }
    float getInches()
{
        return inches;
    }

void main(){
    Distance d1,d2;
```
