# Object-Oriented Programming with C++

As the user adding characters to the string, the allocated memory keeps getting stretched in a manner that is transparent to the programmer. Such an effect is simply unthinkable with character arrays.

We would also like to add a function that will replace the string associated with an object with the string that we pass to. We let this function

```
void String::setString(const char * const);
```

Suppose the following statements are executed:

```
String s1("abc"); //replace "abc" by "def"
s1.setString("def");
```

Then the following events take place when the second statement executes ('s1.cStr' is already pointing to a memory block that contains the string and is NULL).

+   * A block of four bytes should be dynamically allocated to accommodate the string "def".
* The string def should be written in that memory block with the null character appended.
* s1.cStr should be made to point to this new block of memory.
* The block of memory at s1.cStr was previously pointing should be deallocated to prevent memory leak.

The formal argument of the String::setString() is a const char * const. The reasons for this have already been discussed under the section on parameterized constructor. We may think that the definition of this function will be the same as that of the constructor. This is not so. When the constructor starts executing, cStr may or not be NULL (it may contain junk value). But if it is not NULL, does not mean that it is pointing at a dynamically allocated block of memory. When the String::setString() function starts executing, cStr is not NULL, then it is definitely pointing at a dynamically allocated block of memory. Statements to check this condition and deallocate the memory block and nullify cStr and set 'len' to zero should be inserted at the beginning of the String::setString() function. Otherwise a memory leak will occur. Defining the String::addChar() and String::setString() functions is like an exercise.

Let us think of more relevant functions that can be added to the class String. There can be a function that will change the value of a character at a particular position in the string at which the pointer of the invoking object points. Moreover, there can be a function that reads the value from a particular position in the string at which the pointer of the invoking object points. These functions can have built-in checks to prevent values from being written or read from by that beyond the memory block allocated. Also, such a check is not built into character arrays. The application programmer has to put in extra efforts on/her to prevent the program from exceeding the bounds of the array.

After we added all functions to the class String, we will get a new data type that will be safe, efficient, and convenient to use.

Suitably defined constructors and destructors have a vital role to play in the creation of such data types. They ensure that

+   * There are no memory leaks (the destructor frees unwanted memory).
* There are no run-time errors (no two calls to the destructor to free up the same block of memory).
* Data is never in an invalid state and domain constraints on the values of data members are never violated.
