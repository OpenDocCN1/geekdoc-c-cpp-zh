
# Object-Oriented Programming with C++

First of all the value of the VPTR of the object is read. The address of the called function from the corresponding VTBL is obtained. Finally, the function is called through the address thus obtained.

Now it is obvious how the virtual functions work. If a base class pointer points at (or a base class reference refers to) an object of the derived class and a virtual function is called with respect to it, then the derived class function will be called if it overrides the base class virtual function. If the base class virtual function is not overridden, then it will be called.

Note that it is the table size that varies from class to class (for each class there is only one VTBL). The size of the object does not vary. The size of the objects with virtual functions increases by four bytes due to the presence of the additional pointer (VPTR).

We might wonder as to why C++ supports two types of binding—static and dynamic. Why does it not support dynamic binding? In other words, why does it not declare all functions virtual by default? The reason is that virtual functions entail a runtime-cost in the form of shape that is wasted for creating the VTBL and embedding the VPTR in each and every object of the base/derived class. Time is also lost in searching the VTBL for the address. If none of the member functions of a class will be overridden, then making them virtual will unnecessarily increase the above cost. Therefore, C++ allows the programmer to decide whether the member function has be declared as virtual or not.

## 6.4 Pure Virtual Functions

From Section 6.3, we already know that it is optional to override virtual functions. A library programmer declares a member function virtual if he/she expects overriding and wants to make the override effective.

But there are cases where the library programmer would like to enforce an override of the base class virtual functions. Such a case is now described. A call to a base class virtual function has been embedded somewhere in the code with respect to a pointer or reference of base class type. For example, a class A has a virtual function abc() that is called from class xyz() of class X. See Listing 6.12.

> Listing 6.12 Using virtual functions

```cpp
/* Beginning of X.cpp */
#include "X.h"
void X::xyz(A * p)
{
  // some lines of (complicated) code
  p->abc();
  // some lines of (complicated) code
}
/* End of X.cpp */
```

Now, A::abc() function may satisfy either of the following descriptions.

- It has no meaningful definition with respect to the base class. For example, a function to rotate the shape cannot be defined in the class Shape itself. The algorithm to rotate the shape is not known since the shape itself is not known. See Listing 6.13.

# Listing 6.13 Giving blank definition to undefinable virtual function

```cpp
class Shape {
  public:
    virtual void rotate();
};

void Shape::rotate() {
  // null definition!
}
```

- It has only a few lines of code, which do not really give it a complete definition. The function is such that it cannot be called in isolation. It can only be called indirectly through the derived class’s overriding function that has the necessary code to complete the definition. C++ should provide some mechanism to the library programmer to enforce the desired result. Pure virtual functions provide this mechanism. If one more function is declared as a pure virtual, then the corresponding class becomes an Abstract Base Class (ABC in short). A function is declared as a pure virtual function by prefixing its prototype with the virtual keyword as before suffixing it with an ‘equal to’ sign and then by declaring a pure virtual function

```cpp
virtual <return type><function name>(formal arguments)=0;
```

Listing 6.14 illustrates this.

# Listing 6.14 Defining pure virtual function

```cpp
/* Beginning of A.h */
class A {
public:
    virtual void abc() = 0;
};
/* End of A.h */
```

An abstract class cannot be instantiated. However, it can be used as a base class for other classes. The derived class must implement all pure virtual functions of the base class to be a concrete class. If it does not, it also becomes an abstract class.

The utility of an ABC is to define an interface that all derived classes must follow. This allows the library programmer to work with the base class without knowing the implementation of derived classes.

# Listing 6.15 An abstract class

```cpp
/* Beginning of Shape.h */
class Shape {
public:
    int x1, y1, x2, y2;
    virtual void rotate() = 0;
    virtual void shrink() = 0;
    virtual void grow() = 0;
    virtual void hflip() = 0;
    virtual void vflip() = 0;
    virtual void draw() = 0;
};
/* End of Shape.h */
```

The advantage of an ABC is that it provides a common interface for derived classes. This allows the programmer to write code that works with the base class, which will also work for any derived class. This is the essence of dynamic polymorphism.

An example of using ABC is given in Listing 6.16.

# Listing 6.16 Client code to use

```cpp
/* Beginning of MyWindow.cpp */
#include "X.h"
void MyWindow::xyz(A * p)
{
    // some lines of (complicated) code
    p->abc();
    // some lines of (complicated) code
}
/* End of MyWindow.cpp */
```
