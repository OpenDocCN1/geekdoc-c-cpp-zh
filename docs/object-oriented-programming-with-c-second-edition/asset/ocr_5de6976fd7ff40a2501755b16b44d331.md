Qualifying the name of the class with that of the namespace can be cumbersome.
using the directive enables to make the class definition inside a namespace so that the
qualifying the name of the referred class by the name of the namespace is no longer required.
Listing 2.45 shows how this is done.

**Listing 2.45** The using directive makes qualifying of referred class names by names of
enclosing namespaces unnecessary

```
/*Beginning of using.cpp*/
#include "A1.h"
#include "A2.h"
void main() {
    using namespace A1;           //OK: A0bj1 is an object of the class
    A A0bj;                        //defined in A1.h
    A2::A0bj2;                   //OK: A0bj2 is an object of the class
                                 //defined in A2.h
}
/*Beginning of using.cpp*/
```

However, we must note that the using directive brings back the global namespace pollution
that the namespace mechanism was supposed to remove in the first place! The last line in
the above listing compiles only because the class name was qualified by the name of the
namespace.
Some namespaces have long names. Qualifying the name of a class that is enclosed within
such a namespace, with the name of the namespace, is cumbersome. See Listing 2.46.

**Listing 2.46** Cumbesome long names for namespace

```
/*Beginning of longName01.cpp*/
namespace a_very_very_long_name {
    class A {
    };
}
void main() {
    a_very_very_long_name::A A1;   //cumbersome long name
}
/*End of longName01.cpp*/
```

Assigning a suitably short alias to such a long namespace solves the problem as
illustrated in Listing 2.47.

**Listing 2.47** Providing an alias for a namespace

```
/*Beginning of longName02.cpp*/
namespace a_very_very_long_name {
    class A {
    };
}
```
