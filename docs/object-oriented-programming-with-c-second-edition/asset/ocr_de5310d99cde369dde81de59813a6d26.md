# Listing 8.71 The const_cast operator

```
/*Beginning of const_cast.h*/
class A {
int x; //non-mutable data member
int y; //non-mutable data member
public:
void abc(const int) const { //a constant member function
x++; //ERROR: cannot modify a non-constant data
//member in a constant member function

const_cast<A*>(this)->y++; //OK: can modify a non-mutable data member
//in a constant member function by casting
//away the constness of this pointer

void def() {
nx++; //OK: can modify a non-mutable data member
//in a non-constant member function
yy++; //OK: can modify a mutable data member in a
//-non-constant member function
}
};
/*End of const_cast.h*/
```

The compiler treats this pointer as a constant pointer inside non-constant functions. However, it treats this pointer as a constant pointer to a constant instance functions. In the A: :abc() function in Listing 8.71, the constness of this pointer is cast away. This enables us to modify a non-mutable data member in a constant function.

We note that passing '*' to the const_cast operator in the A::abc() function in Listing 8.71, the pointer was made an ordinary pointer that is neither constant nor supposed to be a constant object. We could have well passed 'A *' instead and still ensured a successful compilation of the statement. This is because 'A *' const' to the const_cast operator would have rendered this pointer a constant pointer that points at a non-constant object.

The motive for using the const_cast operator is the same as the motive for using the mutable keyword.
As in the case of the new style cast operators, using the const_cast operator indicates the programmer's awareness and acceptance of the possible negative consequences of its use.
