But why the compiler create the formal argument of the default copy constructor as a reference? And when the compiler defines a copy constructor in the expected way, then why should we define one on our own? Both questions are answered now.

First, let us find out which objects are passed by reference to the copy constructor. Suppose formal argument ('AObj') of the copy constructor is not a reference. Now, suppose the following statement executes.

```
A2=A1;
```

The copy constructor will be called for 'A2' and 'A1' will be passed as a parameter to it. Then the copy constructor will be called for 'AObj' and 'A1' will be passed as a parameter to it. This is because 'AObj' is a non-reference formal argument of the copy constructor. Thus, an endless chain of calls to the copy constructor will be initiated.
