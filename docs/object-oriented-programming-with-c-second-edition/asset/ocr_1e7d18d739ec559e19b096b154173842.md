# Operator Overloading, Type Conversion, New Style Casts, and RTTI 26

```
void main()
{
    B* Bptr01 = new B;
    B* Bptr02 = new B;
    Bptr02->set(20);
    cout<<Bptr02->get()<<endl;
    Bptr01->set(10)<<endl;
    cout<<Bptr02->get()<<endl;
}
/*End of Main.cpp*/
```

# Output
2
10

After the first two statements in Listing 8.52 execute, 'Bptr01' will point at the first byte of the memory pool and 'Bptr02' will point at the fifth. The third statement writes 20 into the block of bytes from the fifth byte to the eighth byte. However, the fifth statement writes '10' into the same memory block!

In order to neutralize this effect of inheritance, the size of memory block being targeted for allocation or deallocation should be compared with the size of the class for which the operator is overloaded. If these two do not match, the global new or the global delete operator should be called (see Listing 8.53).

+   **Listing 8.53** Preventing the ill effects of the new and delete operators getting inherited

```
void* A::operator new(const size_t size)
{
    if(size != sizeof(class A)) //true if derived class type
        //passed as parameter
    return ::operator new(size);
    //rest of the code
}

void A::operator delete(void* p, const size_t size)
{
    if(size != sizeof(class A)) //true if derived class type
        //passed as parameter
        ::operator delete(p);
        return;
    //rest of the code
}
```
