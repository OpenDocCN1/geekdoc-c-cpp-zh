An interesting point to be noted is that a pointer of the base class points at a dynamically created object of the derived class and then deletes the memory occupied by the object, the entire block of memory is deleted. In other words, if the total size of the static data members of the base class is 'x' and the total size of the non-static data members of the derived class is 'y', then the block of size 'x+y' is deleted. It is irrespective of whether the base class is virtual or not.

# 6.5.2 Virtual Constructors

First, let us understand that constructors cannot be virtual. Declaring a constructor as virtual results in a compile-time error. Why? Consider a class A, and a class B that is derived from A. If the constructor of class A is virtual, then in the following statement

```
* p = new B;
```

the constructor of class B alone will be called. The constructor of class A will not be called. This can lead to trouble. What will happen if class A has a pointer that the class constructor correctly initializes? Since the constructor is not called, a rogue pointer will result.

However, the need to construct virtually arises very frequently while programming in C++. Let us consider the function in the following lines of code.

```
void abc(A * p)           //A is a class
{
    //deletion of abc() function
}
```

This means that another object has the same values as the object at which 'p' points needs to be created within the 'abc()' function.
