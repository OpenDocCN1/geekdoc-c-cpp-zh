For understanding the second circumstance where operator overloading is mandatory, let imagine that there is a class whose objects do not share even copies of dynamically allocated resources. This means that statements such as the following should not compile at.

```
o1 = o2; //o1, o2 objects of the said class
```

Here is the solution simple. We just define the function to overload the assignment operator in the private section of the class. Any use of the assignment operator within a non-member function will call this to the operator-overloading function. The function is private, such a call will throw a compile-time error. As desired, the use of the assignment operator will be prevented. However, what would happen if we inadvertently used the assignment operator within a member function or friend function? The private nature of the function will not be enough to prevent such a call by not defining the function to overload the assignment operator. This trick will make the linker throw an error.

Now, let us understand the fourth circumstance. The new operator does a number of things by default, or some of which might be undesirable for the class being designed.

By default, the new operator throws an exception if it fails to allocate the amount of memory requested (exceptions are dealt with in of the later chapters). However, this default action of the new operator may be unsuitable for the class being designed. the class designer might need to call one of the member functions of the class. Only overloading the new operator can fulfill this.

Also by default, the new operator not only allocates the amount of memory requested, it also stores the amount of memory allocated in the memory itself. This enables the delete operator (if it is called) to deallocate the same amount of memory (Chapter 3). However, in memory applications, if the class designer knows that the same amount of memory will be allocated when the new operator is called, he/she can prevent this wastage of memory. Again, only overloading the new operator can do this.

Further, by default, the new operator simply allocates memory for the object whose type is passed as an operand to. However, the class designer would not want that the class have more than one object. He/she may want that an object be created only when the new operator is called for the first time. Subsequent calls to the new operator should not create more objects. Instead, subsequent calls should merely return the address of the object that was created in response to the first call to the new operator.
