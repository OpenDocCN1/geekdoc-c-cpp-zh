```cpp
// generic sum function
long int genSum(unsigned int a, unsigned int b,
    long int (*p)())
{
    int i;
    long sum=0;
    for(i=0;i<b;i++)
    sum+=(*p)(i);
    return sum;
}
```

Next, we can call the function by passing the function whose returned values to be summed up as the last parameter to this generic function. The following lines of code demonstrate this:

```cpp
x=genSum(1,5,factorial);
x=genSum(3,8,cube);
```

Now, any kind of summation can be carried out by this single generic function, provided the function whose returned values are being summed returns a long int or a value of compatible type. A very important point to be noted is the generic sum function is capable of similarly summing the returned values from a function that may be created well into the future! The function call:

```cpp

```

exhibits polymorphic behaviour, while compiling it, it is not known which function will actually be executed. This becomes known only later when the client program calls the genSum() function is compiled.

We would greatly like the show() function of that class to be called object' address is passed as its parameter. In other words, we would like to extend the class library as described in the previous section.

If the library programmer is defining the class, expects and respects overriding of a member function and wants to make such an override meaningful, he/she declare the function as virtual. For declaring the function as virtual, the prototype of the function within the class should be prefixed with the virtual keyword. The virtual keyword may appear either before or after the keyword specifying the type of function. If the function is defined outside the class, then only the prototype should have the virtual keyword.
The syntax for declaring a virtual function as follows:

```cpp
virtual <return type> <function name>(formal arguments);
```

The following lines of code illustrate how virtual functions are declared:

```cpp
class A
{
    public:
    virtual void show();        // A::show() is virtual
};
```

If no such occurring occurs, the base class function will be called.

in the X::abc() function in Listing 6.4 exhibits polymorphic behaviour. Against this call, the show() function of the base class or the overriding show() function of any of its derived classes will be called. However, this polymorphic behaviour is also dynamic in nature. Which function will be called is not known when the X::abc() function is compiled and put in a library. This is decided only when the client program that calls the function is compiled. We can therefore see that compile time for the client is run time for the library. Therefore, the polymorphic behaviour exhibited by virtual functions is also termed dynamic polymorphism.

It is worthwhile to note that functions in the base class usually contain only statements that are relevant to the base class. It is not always possible to provide a complete definition of them, as the base classes are sometimes abstract in the Vehicle class. The overriding functions of the derived class first call the overridden base class and then add the extra statements that complete the definitions with respect to the derived class itself. Having such base functions as virtual ensures that the client is able to call both the functions in sequence as desired.

# 6.3 Mechanism of Virtual Functions

Now, let us understand the mechanism of virtual functions. For every base class that has one or more virtual functions, a table of function addresses is created during run time. This table of function addresses is called the virtual table or VTBL in. The VTBL contains the address of each and every virtual function that has been defined in the corresponding class. Addresses of non-virtual functions do not appear in such tables.

Suppose a class has two virtual functions—abc() and def() (Listing 6.10).

Listing 6.10 A class with two virtual functions

```cpp
/*Beginning of A.h*/
class A
{
public:
    virtual void abc();
    virtual void def();
}
/*End of A.h*/
```

Similarly, a table of addresses of virtual functions will be created for the derived class also. If the derived class does not redefine a center base class member, then the table will contain the address of the inherited base class virtual function itself. But if a base class virtual function is redefined in the derived class, this table will contain the address of the overriding function. Finally, if the derived class defines a new virtual function, then its address will also be contained in the table.
