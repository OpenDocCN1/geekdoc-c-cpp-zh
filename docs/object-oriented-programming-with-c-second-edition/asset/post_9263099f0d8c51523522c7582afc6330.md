In most cases, this default assignment operator is sufficient. However, there are cases where this default behaviour causes problems. We recollect the section on copy constructors from Chapter 4. We discussed the ill effects of the default copy constructor for classes that acquire resources dynamically. Exactly the same problems arise due to the effect of the default assignment operator. The problems caused by the code

```cpp
String s1, s2;
s1.setString("abcd");
s2 = s1;
```

if the assignment operator is not defined then the same as the problems that arise out of the code

```cpp
String s1("abcd");
s2 = s1;
```

if the copy constructor is not defined. As a result of the preceding assignment operation, the pointers of both 's1' and 's2' will end pointing at the same memory block (see Figure 8.1). From the study of the copy constructor, we are already conversant with the havoc in such cases. The conclusion is that the assignment operator must be defined for a class for whom the copy constructor has been defined. A suitable definition of the assignment operator for the class given is in Listing 8.30.

### Listing 8.30 A practical example of overloading the assignment operator

```cpp
/*Beginning of String.h*/
class String {

    String& operator = (const String&);
    // rest of the class String

/*End of String.h*/
```

Understanding why the outermost 'if' (if (this != &ss)) has been inserted at the top of the function and why the function returns the calling object by reference, we must appreciate the definition of the assignment operator in Listing 8.30 which handles all possible cases as follows:

- LHS.cStr = NULL AND RHS.cStr = NULL
  If LHS.cStr = NULL then the first inner 'if' (if cStr != NULL) fails and the corresponding 'if' block does not execute. If RHS.cStr = NULL then the second inner 'if' (if (ss.cStr != 0)) fails and the corresponding 'if' block does not execute. The entire function does not do anything unchanged that it returns the calling object by reference. As expected desired, the value of the left-hand side operand remains unchanged (as cStr = NULL and len = 0) because the corresponding values in the right-hand side object are NULL and 0.
- LHS.cStr = NULL AND RHS.cStr != NULL
  If LHS.cStr = NULL then the first inner 'if' (if cStr != NULL) fails and the corresponding 'if' block does not execute. If RHS.cStr != NULL then the second inner 'if' (if (ss.cStr != 0)) succeeds and the corresponding 'if' block executes:
    - correctly sets the value of the 'len' member of the class to be equal to the length of the string that will hold a copy of the string at 'cStr' member of the right-hand side object pointing;
    - allocates enough memory to hold a copy of the string at which the cStr member object is pointing and makes the 'cStr' member of the left-hand side point at it, and
    - copies the string at which the 'cStr' member of the right-hand side is pointing into the memory block at which the 'cStr' member of the left-hand side object is pointing.
- LHS.cStr != NULL AND RHS.cStr = NULL
  If LHS.cStr != NULL then the first inner 'if' (if cStr != NULL) succeeds and the corresponding 'if' block executes. It deallocates the memory block at which the 'cStr' member of the left-hand side object points out, sets its value to NULL and the value of 'len' member of the left-hand side object set to 0. If RHS.cStr = NULL then the second inner 'if' (if (ss.cStr != 0)) fails and the 'if' block does not execute. As expected desired, if it was not already so, the value of the left-hand side operand gets nullified (cStr = NULL and len = 0) because the right-hand side is NULL.
- LHS.cStr != NULL AND RHS.cStr != NULL
  If LHS.cStr != NULL then the first inner 'if' (if cStr != NULL) succeeds and the corresponding 'if' block executes. It deallocates the memory block at which the 'cStr' member of the left-hand side object points, sets its value to NULL, and sets the value of 'len' member of the left-hand side object to 0. If rhs.cStr != NULL then the second inner 'if' (if (ss.cStr != 0)) succeeds and the corresponding 'if' block executes:
    - correctly sets the value of the 'len' member of the class to be equal to the length of the string that will hold a copy of the string at 'cStr' member of the right-hand side object pointing;
    - allocates enough memory to hold a copy of the string at which the cStr member object is pointing and makes the 'cStr' member of the left-hand side point at it, and
    - copies the string at which the 'cStr' member of the right-hand side is pointing into the memory block at which the 'cStr' member of the left-hand side object is pointing.
