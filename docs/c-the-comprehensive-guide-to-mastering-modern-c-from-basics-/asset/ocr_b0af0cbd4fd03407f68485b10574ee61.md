You can access the elements of the vector randomly in O(1)—that is, with optimal speed.

# ### Tip: Locality

For the CPU, it is better to access registers than cache. Cache is better than main memory, and main memory is faster than the hard drive. The more compact the memory areas needed for a computation are, the more likely it is that the computer can use fast memory for it. Even better for locality is if the memory is mainly in one direction rather than back and forth. Often, the same computation using a strategy with better locality is many times faster: factors of x10 or x100 are possible!

A vector has better locality than, for example, a set, if no specific allocators are taken. You can also use a vector in ascending order, then that is even better for locality. To do this, the iterator only move forward in the vector or increment the index for access only.

If you want to keep all data sorted, you usually use a set. However, that is not good for memory. If this is important to you, you take a look at the flat_set adapter for a vector, which has been available since C++23.

You can pack almost anything into a vector that is possible in C++ types. It depends on the operations you will use and whether the type is loaded or not. The element type must either be copyable or movable; the standard library will choose the appropriate operation. However, there must be a destructor for E, either one generated by the compiler or one you wrote yourself—so you cannot mark the destructor = delete.

In practice, it is recommended that the element type be movable and guaranteed not to throw exceptions when moved—that is, marked with noexcept move operations or generated by the compiler. If you can, stick to the rule of zero for the element type; see Chapter 17, Section 17.1 as a reminder.
