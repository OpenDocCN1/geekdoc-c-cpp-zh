If you want a coarser time unit that you cannot implicitly convert due to loss of precision, then you have two already explained options:

```
// https://godbolt.org/rz/z3b8h1lcx
auto res = fib(45);
//
std::cout << "Time: " << duration_cast<seconds>(t1).count() << "\n";
// Output: Time: 7 (e.g.)
std::cout << "Time: " << duration_cast<double>(t1).count() << "\n";
// Output: 7.35035 (e.g)
```

With duration_cast<>, you can accept loss of precision in the output. If you convert to a floating-point duration, the compiler allows the loss of precision—with floating-point numbers is not actually a loss.

If you don't need a stopwatch but a wall clock, then use system_clock. The point in time describes results from the elapsed duration since the epoch. Epoch is the implicit start of this clock. You get the duration since the epoch with time_since_epoch():

```
// https://godbolt.org/rz/1xbhhTdEV
#include <iostream>
#include <chrono>
int main() {
    using namespace std::chrono;
    auto tp = time_point_cast<seconds>(system_clock::now());
    auto d = tp.time_since_epoch();
    std::cout << d.count() << "\n":ratio<86400>(d).count() << " days\n";
    std::cout << duration<double,ratio:86400>(d).count() << "\n";
}
```

On all systems known to me, the epoch corresponds to 1970-01-01 00:00:00.[ [78] time_since_epoch() returns a duration here, based on seconds, which you can manipulate as usual.
