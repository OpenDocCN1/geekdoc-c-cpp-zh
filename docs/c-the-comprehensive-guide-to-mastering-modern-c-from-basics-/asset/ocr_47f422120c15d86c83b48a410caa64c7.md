ios::out), where the content of the file is deleted
ios::trunc). If this file does not yet exist, it will be
created.

Confusion often arises about when and how to combine
which flags. It can definitely be said that you should
always use at least the ios::in or ios::out flag, which is
also the default setting of the classes. For ios::in, the
file must already exist. If you do not use ios::in, the file
will be newly created if it does not exist. Table 27.10
provides an overview of various combinations of flags
and what they do.

# Close File

When you are done with the file, you should return the
resources to the system and close the file. First, you do
not have an infinite number of file streams available,
and second, you ensure that data still in the buffer is
finally processed. To close a file, the close() method is
used. The following listing demonstrates close().

```
// https://qndbolt.org/z/TMdWhE51
#include <fstream>
#include <iostream>
int main() {
    std::ofstream file01("data.db");
    if(file01.fail()) {
        std::cout << "Could not open data.db\n";
    } else {
        std::cout << "ok.\n";
    }
    file01 << "Text for the file\n";
    if(file01.is_open(){
        file01.close();
    }
    file01.open("data001.db");

n}
```
