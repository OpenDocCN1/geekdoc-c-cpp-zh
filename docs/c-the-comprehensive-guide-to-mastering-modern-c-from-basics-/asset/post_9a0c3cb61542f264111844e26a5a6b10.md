
# Flags for Opening a File

| Flag | Short | Description |
| --- | --- | --- |
| ios::in | Input | Open for reading (default for ifstream) |
| ios::out | Output | Open for writing (default for ofstream) |
| ios::app | Append | Always add something at the end when writing |
| ios::trunc | Truncate | The file length is set to 0, and existing content is deleted |
| ios::ate | At end | Positions the read or write position at the end of the file immediately after opening. Without this flag, the read and/or write position is usually at the beginning of the file after opening |

| Flag | Short | Description |
| --- | --- | --- |
| ios::binary | Binary | Opens the file in raw binary mode. For example, line-end conversions are not performed, and raw bytes are transferred. Without this mode, a file is opened in a formatted text mode. |

**Table 27.9** Various flags for opening a file.

## Default Values of "ifstream", "ostream", and "fstream"

The default value of ifstream is essentially ios::in, that of ostream is ios::out | ios::trunc, and that of fstream is ios::in | ios::out.

You can write the flags either directly in the constructor after the file name or in the method after the file name. The following listing shows two simple examples.

```cpp
// https://godbolt.org/z/GoPdTQw6
#include <fstream>
#include <iostream>
using std::cout;
int main() {
    std::ofstream file01("testfile.txt", ios::out|std::ios::app);
    if(file01.fail()) {
        cout << "Could not open testfile.txt\n";
    } else {
        cout << "ok.\n";
    }
    std::fstream file02;
    file02.open("database.db", ios::out|std::ios::trunc);
    if(!file02) {
        cout << "Could not open database.db\n";
    } else {
        cout << "ok.\n";
    }
}
```

**Listing 27.16** Additional flags when opening files.

| Flags from ios | Meaning |
| --- | --- |
| in | Read; file must exist. |
| out | Truncate and write; file will be created if necessary |
| out | trunc | Truncate and write; file will be created if necessary |
| out | app | Append data; file will be created if necessary |
| app | Append data; file will be created if necessary |
| in | out | Read and write; file must exist; file position at the beginning |
| in | out | trunc | Truncate, read, and write; file will be created if necessary |
| in | out | app | Read and write; append data; file will be created if necessary |

**Table 27.10** Meanings of different combinations for opening a file. ios::out with "testfile.txt"

First, I open a file for writing (ios::out) with testfile.txt and append the new content to the end of the file (ios::app). I also open the file "database.db" for writing ios::out, where the content of the file is deleted ios::trunc. If this file does not yet exist, it will be created.

Confusion often arises about when and how to combine which flags. It can definitely be said that you should always use at least the ios::in or ios::out flag, which is also the default setting of the classes. For ios::in, the file must already exist. If you do not use ios::in, the file will be newly created if it does not exist. Table 27.10 provides an overview of various combinations of flags and what they do.

# Close File

When you are done with the file, you should return the resources to the system and close the file. First, you do not have an infinite number of file streams available, and second, you ensure that data still in the buffer is finally processed. To close a file, the close() method is used. The following listing demonstrates close().

```cpp
// https://qndbolt.org/z/TMdWhE51
#include <fstream>
#include <iostream>
int main() {
    std::ofstream file01("data.db");
    if(file01.fail()) {
        std::cout << "Could not open data.db\n";
    } else {
        std::cout << "ok.\n";
    }
    file01 << "Text for the file\n";
    if(file01.is_open()){
        file01.close();
    }
    file01.open("data001.db");
    std::ofstream file02("data002.db");
} // here file02 is closed
// here file01 is also closed
}
```

**Listing 27.17** Explicitly closing a file stream.

With `close()`, you cut the connection to the file. To avoid accidentally closing a file that is not (or is no longer) open, I use the `is_open()` method here, which checks whether the stream object `file01` is actually connected.

You will find an overview of the methods for opening and closing.

| Method | Description |
| --- | --- |
| open(filename) | Opens the file with default mode. |
| open(filename, flags) | Opens the file with specified flags. |
| close() | Closes the file. |
| is_open() | Returns true if the stream is open, otherwise false. |

**Table 27.11** Methods for opening and closing.

# You Cannot Copy Streams by Value

You cannot copy stream objects, only move them. This means that you cannot pass a stream by value to a function; you must pass it by reference.

In practice, however, formatted writing and reading with the << and >> operators is rarely used. It is more efficient to read from and write to files in blocks. I will go into more detail on the individual possibilities (character-wise, line-wise, and block-wise) in the next sections.
