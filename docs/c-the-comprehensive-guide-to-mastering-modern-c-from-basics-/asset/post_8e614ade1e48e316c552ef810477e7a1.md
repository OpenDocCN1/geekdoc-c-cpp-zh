    for (auto i = 0; i < m3.extent(0); ++i) {
        cout << "Level " << i << "\n";
        for (auto j = 0; j < m3.extent(1); ++j) {
            for (auto k = 0; k < m3.extent(2); ++k) {
                cout << m3[i, j, k] << " ";
            }
        }
        cout << "\n";
    }
}

You provide the mdspan with the raw data, here via v.data(). You also set the dimensions when creating it. With extent(), you get the size in one dimension. You access the elements of a 3D mdspan m3[i, j, k].

Previously, you worked with C-arrays and then wrote mx[y][x]. The problem with it was that the layout of the data was confusing. You should ideally iterate over the last dimension in the innermost loop to avoid cache misses. In addition, boundary checking is difficult. Overall, mdspan greatly simplifies working with multidimensional data. Perhaps vararray will be obsolete?

Since C++20, you can only use the sequence operator in operator[] if you accept a warning, because starting from C++23, the meaning changes! From then on, multidimensional indices are possible.

# Inserting into a "vector"

It's not very interesting to put things into a container only during construction; you also want to add things at runtime. The following member functions serve this purpose:

- **Efficient appending at the end**
push back and emplace back a single element to the end of the vector. With push back, the passed value is copied into the vector, while emplace back constructor arguments of the new element as parameters and creates it directly in place. On average, appending at the end is optimally fast, in O(1). Starting from C++23, you can also append a range with append_range.

- **Insert somewhere**
You can insert an element at any position in the vector. With insert, you copy it in; with emplace, you create it in place with its constructor arguments. The insert_range method is available from C++23. These methods use only in exceptional cases, as vector is slow when inserting at positions other than the.

With each insertion operation, it may happen that space for the new element has to be created in a way that all previous elements have to be moved (or copied) to a new (twice as large) location. For this reason, iterators, spans and ranges (see data) in the container should be considered invalid after any insertion operation—unless you have previously ensured with reserve or capacity that such a reallocation will not occur. As far as time is consumed, you don't need to worry; even if a single insertion operation takes O(n) time, the algorithm is clever enough to guarantee O(1) on average.

There is erase as a method for all containers except array, and in forward_list there is erase. In vector, you can either pass an iterator to remove a single element or a pair to remove an entire range:

- **All elements**
clear(erase) removes all elements from the vector. Its size is then zero.

- **Last element**
pop_back() is the best method to remove a single element from a vector. It is the counterpart to push_back. It takes O(1).

- **Single arbitrary element**
erase(const_iterator) deletes a single element. All elements with a larger position than the deleted one are shifted (or copied) one position to fill the gap. This takes O(n) time for vector and should therefore not be done repeatedly.

- **Range**
erase(const_iterator from, const_iterator to) deletes all elements between from and to, exclusive of to—mathematically noted as a half-open interval [from,to). For clarification, erase(begin(), end()) is equivalent to clear(). Here two elements shift left to fill the gap. This takes O(n) time for vector or by the distance between the two iterators. The return value is an iterator pointing to the first shifted element.

# Only Container Methods
As a rule of thumb: Only methods like erase delete elements from a container, changing its size. Free functions like remove from <algorithm> do not delete, but merely rearrange elements—for example, moving them to the end where they can be deleted. This also applies to ranges—that is, the std::ranges namespace. You can delete all elements effectively with a simple call to clear():

```cpp
vector<int> v{1, 2, 3};
v.clear(); // v is empty
```

You could delete a single element with erase:

```cpp
// https://godbolt.org/r/68bd
vector<int> v{1, 2, 3, 4, 5, 6};
for(auto it=v.begin(); it!=v.end(); ++it) {
    it = v.erase(it);
}
// Here v is: {2, 4, 6} deletes every second element.

If you want to delete a range, also use erase, but specify the range with two iterators.

```cpp
// https://godbolt.org/r/febe99
vector<int> v{1, 2, 3, 4, 5, 6};
v.erase(v.begin(), v.begin()+5); // v is now {1, 2, 6}
v.erase(v.begin(), v.end()); // deletes the rest
```

# Listing 24.31 "erase" with two parameters deletes an entire range.

The first parameter is the element to deleted; the second parameter is the first element that should remain after the range to be deleted, so it points to an element after the last element to deleted.

To delete the end of a vector, pop_back is more suitable:

```cpp
vector<int> v{1, 2, 3};
v.pop_back(); // v becomes {1, 2}
```

When you combine erase with free functions like remove or remove_if from <algorithm>, you have many flexible, elegant, and efficient options to remove elements from a vector—or indeed any container. You can find examples in Chapter 25.

# Specialty: Size and Capacity

In **Listing 24.32**, you can see few operations for the size and capacity of a vector. Understanding these metrics is fundamental for the efficient use of vector.

```cpp
// https://cppbolt.org/YzGkMIwaE
#include <vector>
#include <iostream>
#include <format> // C++20
using namespace std;

ostream& operator<<(ostream& os, const vector<int>& vec) {
    for(auto const& v : os) os << v << " ";
    return os;
}

int main() {
    vector<int> data; // creates an empty vector
    data.reserve(3); // Space for 3 elements
    cout << format("{}\n", data.size(), data.capacity()); // 0/3
    data.push_back(11); // add an element
    data.resize(3); // Resize, it appends new elements
    data.push_back(99); // add another element
    cout << format("{}\n", data.size(), data.capacity()); // 4/6
    data.push_back(33); // add another element
    cout << format("{}\n", data.size(), data.capacity()); // 111, 0, 999
    data.resize(1); // nothing happens, because capacity() > 1
    cout << data << "\n"; // shrink, elements are removed
    cout << format("{}\n", data.size(), data.capacity()); // 3/6
    data.resize(44); // resize again, fill with 44s
    cout << data << "\n"; // 111, 0, 44, 44 ...
}
```

### 24.6.4 array
an array is an exception among containers in that it is the only container that cannot change its size. You determine at compile time duration of existence, it maintains that size. You cannot add elements or remove elements—only replacing elements.

Therefore, you also specify the size of this container as a template parameter within angle brackets—for example, array<int,5> for array with five elements. The array<int,5> type is different from the array<int,4> type because that is the nature of templates. Consequently, you need write a single function that can handle different array sizes as parameters.
