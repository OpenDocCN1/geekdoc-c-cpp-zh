
```
// https://godbolt.org/z/5z4s6WMXG
#include <iostream>
#include <string>
#include <algorithm> // min, max
#include <tuple>
using std::tuple; using std::get; std::cout;
using std::string;
tuple<int,int,int> arrange(int a, int b, int c) {
    using std::min; using std::max;
    auto x = min(a,b,c);
    auto y = max(min(a,b), max(a,b,c));
    auto z = max(a,b,c);
    return make_tuple(x, y, z);
}
tuple<string, string, string, int> president(int year) {
    using namespace std::literals;
    if(year >= 2021)
        return std::make_tuple("Joseph", "Biden", "Democratic"s, 1942);
    if(year >= 2017)
        return std::make_tuple("Donald", "Trump", "Republican"s, 1946);
    if(year >= 2009)
        return std::make_tuple("Barack", "Obama", "Democratic"s, 1961);
    // Add more presidents as needed...
    return std::make_tuple("s", "s", "s", 0); // Default case
}
int main() {
    tuple<int,int,int> zs = arrange(23, 42, 7);
    cout << get<0>(zs) << ' ' << get<1>(zs) << ' ' << get<2>(zs) << '\n';
    // Output: 7 23 42
    auto ps = president(2015);
    cout << get<1>(ps) << ' '\n'; // Output: Obama
}
```

# Listing 28.2 "with tuple", you can return any number of elements.

You combine multiple values of different types into a tuple using auto, as with arrange and zs, feel free to write out the tuple type. However, I recommend working with auto, as shown with president and ps. Here it is actually a tuple<string, string,int>, but you can save yourself the typing with auto.

Instead of accessing the elements with first and second, you now use get<0> and get<1>. For further elements, logically use larger numbers. Note that you can only specify fixed values (constexpr) as an index here. This does not work with variables.

You can even pass a type instead of a number, the type that you want.

```
// https://godbolt.org/z/TE1EcEYPv
// ... as before ...
int main() {
    tuple<string, string, string, int> ps = president(2015);
    cout << get<int>(ps) << '\n'; // Output: 1940
    cout << get<string>(ps) << '\n'; // not unique
}
```

# Listing 28.3 "array" works with a type as an index.

Because it appears only once in tuple<tuple, string, string, int>, you can use get<int> to access the corresponding element. get<string> does not work because that would not be unique.

> "array" as "tuple"
The real array container (see Chapter 24, Section 24.6.4) for a fixed number of elements of the same type also offers the possibility to access elements with get<...>. You can almost use an array<int,3> like a tuple<int,int,int>.

If accessing elements in this way is too cumbersome for you, then bind the return value of a function to variables with tie.

```
// https://godbolt.org/z/zG7yGF3K
// ... as before ...
int main() {
    using std::tie; using std::ignore;
    string lastName();
    int birthYear;
    tie(ignore, lastName, birthYear) = president(2015);
    cout << lastName << '\n'; // Output: Obama 1961
}
```

**Listing 28.4** Decomposing tuples with "tie" and "ignore".

When you use tie on the left side of an assignment as shown here, you can directly assign the individual parts of tuple and pair returns to previously declared variables. If you are only interested in parts of the return, then use ignore at the positions you are not interested in.

# Structured Binding with "auto"

With C++17, it has become even easier to directly assign the returns of tuple or array to variables. This feature is structured binding. This makes it possible to declare variables simultaneously:

```cpp
auto [a, lastname, c, birthyear] = president(2015);
```

Here, four variables are automatically declared with the correct types and initialized with the corresponding parts of the returned tuple. For this, the expression on the right side needs a "tuple-like interface"; that is, it must support get<> and tuplesize<>, which is the case for array, tuple, and pair.

# A C-array or a struct can also be on the right side.

tuple has overloaded operators for comparisons, particularly < and ==, which are necessary for algorithms like sort and the standard containers. If the first elements of a tuple are equal, then the second elements are compared, and so on. This is called lexicographical order, because it works like sorting in a dictionary.

```cpp
// https://godbolt.org/z/sG4E6YW
#include <iostream>
#include <string>
#include <tuple>
#include <vector>
#include <algorithm>
using std::tuple; using std::get; using std::cout; using std::string;
int main() {
    std::vector<tuple<string,string,int>> armstrongs = {
        {"Armstrong", "Louis", 1901},
        {"Armstrong", "Lance", 1971},
        {"Armstrong", "Neil", 1930}
    };
    sort(armstrongs.begin(), armstrongs.end());
    for(const auto& a : armstrongs) {
        cout << get<0>(a) << " " << get<1>(a) << " " << get<2>(a) << "\n";
    }
}
```

**28.5** Tuples implement lexicographical order.

First, you can see that it is easy to initialize a tuple when the type is given. This is the case here with vector<tuple<string,string,int>> When sort is performed, the tuples are compared with each other. The first elements are always the same, and the second element is considered—for example, "Armstrong" and "Louis". Just as you can sort a vector<tuple<string,string,int>>, the only thing needed to compare tuples is the comparability of the individual elements.

```cpp
// https://godbolt.org/z/9ghMoZb
#include <iostream>
#include <string>
#include <tuple>
#include <map>
#include <unordered_set>
using std::tuple; using std::get; using std::cout; using std::string;

int main() {
  std::map<tuple<int,string>, double> m = {{{ {12,"x"}, 3.14}};
  cout << m[{12,"x"}] << "\n"; // Output: 3.14

  std::unordered_set<tuple<int,string>> s; // no
}
```

# Listing 28.6 Tuples as keys.

In an associative container like unordered_set, you cannot use tuple without further precautions, as std::hash(tuple<...>) does not exist. However, this can be retrofitted if necessary.

The fact that tuple supports comparisons can also be used to simplify your code. If you have your own data structure with multiple elements for which you want to implement lexicographical order, you can rely on tuple. The tie function helps you. It breaks down any tuple into its individual parts, which you can then associate with your own variables. The result is very compact code for lexicographical comparisons.

```cpp
// https://godbolt.org/vd7TTjWK
#include <iostream>
#include <string>
#include <tuple>
#include <map>
#include <unordered_set>
using std::tuple; using std::tie; using std::cout; using std::string;
struct Point {
    int x,y,z;
    bool operator<(const Point &b) {
        return tie(x,y,z) < tie(b.x, b.y, b.z);
    }
};
int main() {
    Point a{11, 22, 33};
    Point b{11, 33, 0};
    cout << (a < b) << "\n"; // Output: true
}
```

# **Listing 28.7** Forming tuples in-place using tie.

It is not difficult to implement lexicographical order yourself. However, this is a tedious task into which errors often creep. When you use tuple with tie, the code is compact, clear, and correct. Remember that you should not use make_tuple here as it would create copies of your data. tie works with references, so your data elements are compared without an additional copy.

The superlative of tie is forward_as_tuple, which you need when writing a function template that should assemble a tuple from multiple arguments while preserving rvalue references. This is a very advanced topic, which you will notice the first time you use it. You should not use forward_as_tuple until you have worked with std::forward at least once. The last way to create a tuple is by using tuple_cat. You give tuple_cat a list of tuples and receive a single large tuple as a return, with all elements concatenated.

```cpp
// https://godbolt.org/z/e1dgdWbe9
#include <iostream>
#include <string>
#include <tuple>
using std::tuple; using std::cout; using std::string;

int main() {
    tuple<int,string> a {12, "gnorf" };
    tuple b { 666 };
    tuple<double,double,string> c { 77.77, 33.33, "frong" };
    tuple<int,string,int,double,string> r = std::tuple_cat(a, b, c);
    cout << std::get<2>(r) << "\n"; // Output: 666
}
```

# Listing 28.8 Combining several small tuples into one large tuple.

Just as well—probably better—you could have written r = ... and let the compiler determine the correct type. Instead of tuple, you can also give tuple_cat a pair as an argument. In most cases, the types are compatible.
