
## 24.6 The Sequential Container Classes

Let's walk through the sequential container classes (see Table 24.4):

- `array<ElementType,Size>`
A fixed number of elements is stored here. Adding and removing is only possible by overwriting. The elements are stored directly next to each other in memory. Therefore, `array` is suitable for both few huge and many tiny element types, as it has virtually no memory overhead.

![](img/290cf954dfcaad53865de6b98cca8e6f_1125_0.png)

**Figure 24.2** An "array" can grow nor shrink, but it is compact.

- `vector<ElementType>`
This all-rounder grows automatically. You can insert any where, but efficiently only at the back end.

![](img/290cf954dfcaad53865de6b98cca8e6f_1125_1.png)

**Figure 24.3** Schematic representation of a "vector".

Reading the elements is done sequentially forwards, backward, or randomly by index. Also, `vector` stores its elements directly next to each other in memory, making it practical for both few large and many tiny elements. Optimally used, it has virtually no memory overhead; in suboptimal cases, it is still acceptable as it does not fragment memory.

- `deque<ElementType>`
You easily add elements to the end of a vector, but less easily to the beginning, as all existing elements are shifted one place to the right. The double-ended queue `deque` is suitable for quickly adding elements at both ends. As a disadvantage, it does not store its elements directly next to each other, but still usually more compactly than list. If possible, prefer vector.

![](img/290cf954dfcaad53865de6b98cca8e6f_1125_2.png)

**Figure 24.4** A "deque" can be extended at both ends, but the elements are not contiguous in memory.

- `list<ElementType>`
The list is simpler than a vector and is very well suited for frequent insertions in the middle. However, the elements are not contiguous in memory but are internally linked. You do not have index access available. If you want to iterate over ranges, it is fast.

![](img/290cf954dfcaad53865de6b98cca8e6f_1126_0.png)

**Figure 24.5** A "list" that can be traversed forwards and backward. Insertion is easy.

- `forward_list<ElementType>`
The exotic type mimics the fundamental structure of a linked list from C and requires minimal additional resources. However, it has a slightly different interface than all other containers. Every insertion works somewhat differently. Both list and `forward_list` are specialists in *splicing*—that is, transferring some consecutive or all elements from one list to another.

![](img/290cf954dfcaad53865de6b98cca8e6f_1126_1.png)

**Figure 24.6** Elements of the "forward_list" only know their successor.

| Container | Description |
| --- | --- |
| array | Fixed size; similar to C-array ElementType[Size] |
| vector | All-rounder; similar to new ElementType[Size], but dynamically growing; inserting and removing at the back is very efficient |
| deque | Inserting and removing from the front and back is very efficient |
| list | Inserting everywhere is efficient; no [i]; forward and backward iterable |
| forward_list | Efficient insertion everywhere; low memory overhead; no [i]; no size(); only forward iterable |

**Table 24.4** Profiles of the sequence containers.

> Among the sequence-based container classes in C++, vector and array are the ubiquitous all-rounders.

## 24.6.1 Commonities and Differences

If you are considering using a sequence container, one of these two should always be your first choice.

| Property | array | vector | deque | list | forward_list |
|---|---|---|---|---|---|
| Dynamic size | - | Yes | Yes | Yes | Yes |
| Key type* | size_t | size_t | size_t | - | - |
| Iterate forward | Yes | Yes | Yes | Yes | Yes |
| Iterate backward | Yes | Yes | Yes | Yes | - |
| Overhead per element | None | Special* | Very Little | Everywhere | Special* |
| Efficient insertion | Not all | Back | Front/back | Everywhere | Everywhere |
| Where to insert | - | Everywhere | Everywhere | Everywhere | Everywhere |
| Splicing | - | - | - | Yes | Yes |
| Memory layout | Stack | Contiguous | Open | Fragm. | Fragm. |
| Iterators/ranges | Contiguous | Contiguous | Random access | Bidirectional | Forward |
| Algorithms | All | All | All | Special* | Special* |

**Table 24.5** Properties of sequence containers. For the *entries, see the explanation ahead.

You may use when you know at compile time how many elements the container should hold. vector, on the other hand, has a dynamic size: you can add elements to it or remove them.

Table 24.5 lists the main properties that distinguish the sequence-based containers from each other. The following notes apply to the entries marked with an asterisk *:

- **Key type**
You can only use a size_t for `operator[]` and `at`. Key is not quite the right term here, shifting elements changes the association of the keys to the container elements. However, I include this property to compare it with associative containers.

- **Overhead per element of vector**
In the optimal case, vector has virtually no additional memory consumption than that of the base elements it manages. If you know in advance you will store 1,000 elements, you can prepare the vector to exactly this size with `reserve(1000)` and then add elements. You will achieve optimal performance in terms of time and memory consumption. If you do not know in advance, the vector may reallocate and copy elements, which is a costly operation. However, in suboptimal cases, it is still acceptable as it does not fragment memory.

- **Efficient insertion into forward_list**
Unlike other containers, `forward_list` does not have a `size()` method, so finding the number of elements is $O(n)$. However, insertion is efficient if you already have the iterator to the position. This is because you can only move forward.

- **Splicing of list and forward_list**
Both list and `forward_list` are specialists in *splicing*—that is, transferring some consecutive or all elements from one list to another. This is a very efficient operation as it only involves relinking pointers rather than copying elements.

- **Memory layout**
`array` is stored on the stack. `vector` and `deque` use contiguous memory (though `deque` is a sequence of contiguous blocks). `list` and `forward_list` use fragmented memory as they are linked structures.

- **Algorithms**
Most algorithms work with all sequence containers. However, `list` and `forward_list` have specialized versions of some algorithms because they do not support random access.

## 24.6.2 Methods of Sequence Containers

In this section, `cont` or `c` stands for instance of container. For element type, use `E`, and for iterator types, use `It`. `Rg` stands for range.

- **Constructors**: `C()`, `C(size_t)`, `C(size_t, E)`, `C(It, It)`, `C(from_range, rg)`
The default constructor creates an empty container. With `C(size_t)`, you can create a container of a predetermined size filled with default elements, as `vector<int>(5)`, which creates a vector with five elements. If you do not like the default value, specify your own: `vector<int>(5,42)` will contain 42 five times. With a pair of iterators from any other container, you can copy its contents. Since C++23, you can also use `from_range` to initialize a range. You can specify an initializer list that your container should contain.

- **Copy and Move**: `C(const C&)`, `operator=(const C&)`, `assign`, `assign_range`, `C(C&&)`, `operator=(C&&)`, `swap`
You can pass a different container as an argument to the copy and move constructors and operators. There is an `assign` method in several variants to reinitialize the container similarly to one of the constructors, with `assign_range()` existing since C++23. All containers implement `swap(Cont& other)` efficiently (in constant time, independent of the number of elements), which allows for great performance tricks when used skillfully; swap takes linear time for array.

- **Destructor**: `~Cont()`
All containers have destructors that remove the contained elements. Note that this does not apply if you pack pointers into containers. Use smart pointers for, or managing the dynamic objects elements.

- **Iterate forward**: `begin()`, `end()` and backward: `rbegin()`, `rend()`
Get an iterator with `begin()` that points to the first element, and with `end()` one points the last element; you can use these iterators for a loop to iterate forward. For the backward loop, use `rbegin()`, which points to the last element, and `rend()`, which points the first element. In sequence containers, you always iterate over the elements in the order in which you inserted them or where you inserted them.
