## 27.6.5 Synchronized Streams for Threads

## 27.7 Streams for Strings

If you look at the simplified hierarchy of the stream class in Figure 27.1, starting from ios, you will find three streams for strings: istringstream, ostringstream, and stringstream. This means that you are reading or writing a string rather than outputting to console or file. For all three classes, you need to include <sstream> header. These streams are well-suited for converting different data types to and from strings—again, with all the advantages of preceding streams and their methods and manipulators. Table 27.13 lists the various streams.

| Stream | Meaning |
| --- |---|
| istream | Creates a string stream that can be read from. The stream is opened in ios::in mode. |
| ostringstream | Creates a string stream for writing. By default, this stream is used with ios::out mode. |
| stringstream | Creates a string stream for reading and writing. The default modes are ios::in and ios::out |

**Table 27.13** String streams of the standard library.

For all three constructors, you can use an empty constructor as argument; the open mode, as with file streams (see Table 27.9); a string (std::string) with which the stream should be initialized immediately; or a combination of the string (first argument) and the open mode (second argument). This should be added to the open modes for string streams, ios::in, and ios::out make the most sense. The other values of type ios::openmode are also implemented, but whether they actually have effect on stringstream object depends on the implementation.

### Old stringstream

In the old C++98 standard, a stream class was still implemented with char*. Today, basic_string type is used for this purpose. The old stream classes istream, ostream, and string are therefore only present for backward compatibility and should no longer be used in new projects; they are deprecated, meaning that they are obsolete. Because string streams inherit all public methods from the base classes derived from them, all previously known and introduced methods are also available to you here. However, the main for string streams are provided by the class itself with str() method (see Table 27.14).

| Method | Description |
| --- | --- |
| string str() const | Returns the string buffer as a string |
| void str(const string& s) | Resets the content of the string buffer |

**Table 27.14** "str()" is the centerpiece of the string stream.

This way, you can convert simple data types like double or int into a string, in the following listing.

```
// https://godbolt.org/z/TT13E3sz
#include <sstream> // ostringstream
#include <iostream>
int main() {
    std::ostringstream ostr;
    double dval = 3.1415;
    int ival = 4321;
    ostr << dval << " : " << ival.str();
    std::cout << ostr.str() << std::endl; // Output: 3.1415 : 4321
}
```

**Listing 27.25** Writing to a "stringstream".

First, I create the string stream for writing, which we need for the conversion. Then I simply write the double value and the int value separated by a colon into the string stream using <<. With the str() method, I copy the entire content of the string stream buffer into the string and then output it.

The same works in the other direction. The following listing shows how you can extract individual types from a string.

```
// https://godbolt.org/z/1EMMox3hW5
#include <sstream> // istringstream
#include <iostream>
int main() {
    std::istringstream str("3.1415 : 4321");
    std::string none;
    double dval=0.0;
    int ival=0;
    str.str(""); // initialize
    str >> dval >> none; // read
    if (!str.eof()) {
        std::cout << "Error converting\n";
        return 1;
    }
    std::cout << dval << " = " << none << " = " << ival << "\n";
    // Output: 3.1415 = : none = 4321
}
```

# Listing 27.26 Reading from a "stringstream".

First, initialize an empty istream in str, from content which I will later extract values. I then set the content with str(...). You could also pass the content directly to the constructor.

Extraction is done as with any other istream using >>. This means that for double, characters are consumed as long as they could be part of a floating-point number. Extraction stops at a whitespace. The colon ends up in none, because when reading into a string, >> also stops at the next whitespace. Finally, it reads into an int so long as there are 0 to 9 or + - in the string stream.

With eof, I check if any errors occurred during the conversion. If the string stream is not at the end, that would be the case.
