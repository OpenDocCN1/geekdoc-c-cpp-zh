
It is also possible to leave the update part empty. Then you will have to take care of the update within the loop block. But this is rather rare, because then you almost have a while loop. In extreme—and particularly rare—cases, you can also omit the condition. Then you must be able to end the loop in some other way. How to do this without Ctrl+C is something you will learn when I explain break in this chapter.

A frequently used way to execute something “forever” is to omit all three parts.

```cpp
int main() {
    for(;;) { // no it, no condition, no update - so forever
        /* ... User input */
        /* ... if user chooses Quit, end program */
        /* ... otherwise, perform calculation and output */
    }
}
```

**Listing 8.16** Loops without conditions must be terminated in some other way.

Of course, lot of program code is missing. But using a loop that runs forever as last resort should make the use case clear to you.

## 8.9 The Range-Based "for" Loop

When I explain the for loop, I must also cover its new variant, the range-based for loop (or ranged for). Especially with standard containers, it is very useful. To examine the contents of primes, I use for loop with colon notation : I refer to the following excerpt from Listing 8.1:

```cpp
// Excerpt
std::vector<int> primes(2); // vector is a container, ready for
// primes must be sorted in ascending order
void isPrime(int n) {
    for(int factor : primes) { // range-based for
        if(factor > n)
            return true;
        if(n%factor==0)
            return false;
    }
}
void outputPrimes() {
    for(int i=1; int prime : primes) { // range-based for
        std::cout << i << " Prime: " << prime << " ";
    }
    std::cout << " ";
}
```

**Listing 8.17** You can recognize range-based “for” loop by the colon. primes collects the overall result so that it appears on the screen in outputPrimes. On the other hand, it is used in isPrime to perform only the necessary divisibility tests.

You read for(int factor : primes) this way: Select an element from the primes container one one, assign it to factor, execute the loop statement, and repeat this process for all elements of the container. That is:

```cpp
for(Destination : Container )
```

allows quite a lot. You can even equip your own data types to be used in these for loops like container. All you need to do is appropriately define begin and end methods. When outputting with int prime : primes, it is the same, but here we also have initialization part with int i;. This has been possible since C++20. Before that, you had to define such a counter before the loop. Normally, you apply range-based for to containers, which you get to know in Chapter 24. If you write container-like classes, you can make them fit range-based for.

## 8.10 The “switch” Statement

You have already seen that you can use if-else cascades to check multiple cases in succession. The switch statement is a specialized form of the case where you always test the same expression, and the expression has int-like type—or enum, as you will see in Chapter 16, Section 16.12.2:

```cpp
switch( Expression ) { Cases }
```

Since C++17, it works analogously to if as well:

```cpp
switch( Initialization ; Expression ) { Cases }
```

Where Cases consist of a sequence of cases of the following form:

```cpp
case Constant: Statements
```

From the list of Cases, those Statements are executed whose Constant matches the result of the Expression. There are still some things to consider:

- Cases must not contain duplicate Constants, but they do not need to follow a specific order.
- Instead of case, you can also use default to catch everything else. Normally, this is the last or first case, but it doesn't have to be.
- You can also write multiple case instructions directly in a row without statements between if you want to combine multiple cases.
- Statements of a case should always end with break. Exceptions to this rule are very rare and should be clearly highlighted with a comment. If you forget this break, the statements of the next case will be executed, regardless of what its constant is. This is called fall-through.

In Figure 8.6, you can see the flowchart of the switch construct. Although the break statements do not strictly belong to the switch flowchart, I have included them here as an option because they are so common and important. The very simple calculator from Listing 8.18 places digits in a stack. An arithmetic operation takes the top elements of the stack and places the result back on top.

```cpp
// https://godbolt.org/z/Y4W1loW8b
#include <string>
#include <vector>
#include <iostream> // cout

void calculator(std::ostream& out, std::string input) {
    std::vector<int> stack {};
    for(char c : input) {
        if(c=='0' && c<='9') {
            stack.push_back(c-'0'); // numeric value of the character
            continue;
            // next loop iteration
        }
        int top = 0;
        int second = 0;
        switch(c) {
            case '+':
                top = stack.back(); stack.pop_back();
                second = stack.back(); stack.pop_back();
                stack.push_back(second + top);
                break;
            case '-':
                top = stack.back(); stack.pop_back();
                second = stack.back(); stack.pop_back();
                stack.push_back(second - top);
                break;
            case '*':
                top = stack.back(); stack.pop_back();
                second = stack.back(); stack.pop_back();
                stack.push_back(second * top);
                break;
            case '=':
                for(int elem : stack) { out << elem; }
                out << " ";
                break;
            case ':':
                break;
            default:
                out << " " << c << " ";
                break;
        }
    }
}

int main(int argc, const char* argv[]) {
    if(argc==1) {
        calculator(std::cout, argv[1]);
    } else {
        calculator(std::cout, "345*6=");
    }
}
```

**Listing 8.18** Each "case" covers one scenario, and nowhere was the "break" forgotten.
