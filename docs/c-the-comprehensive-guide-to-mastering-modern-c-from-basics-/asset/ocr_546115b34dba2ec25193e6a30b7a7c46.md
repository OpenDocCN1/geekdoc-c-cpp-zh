Proceed slightly differently for the decimal part, .45. Multiply the number repeatedly by 2 and note the 0 or 1 before the decimal point. Ignore the part before the decimal point for the next step. Continue until you have already carried out a multiplication operation once:

```
.45 x 2 = 0.9
.9 x 2 = 1.8
.8 x 2 = 1.6
.6 x 2 = 1.2
.2 x 2 = 0.4
.4 x 2 = 0.8
.8 x 2 = ... we already had -+-
```

You could continue endlessly, but it is more practical to note this period somehow—example, with a line above the repeating part: 0.1100. If the repeating part were a zero, the result would be exact and the number would have no period in binary notation.

The parts before the decimal point and after the decimal point add up to the following in binary notation: $z_{101101.011100}$.

You can determine the exponent from the exponent from this representation. To do this, move the decimal point after the first 1 and count how many positions you have moved—five positions in this case. In scientific notation in the decimal system, you could write “e5” after the scaled number. In this case, you could first convert the integer 5 into a binary number and obtain $z_{1.01101011100e01}$.

You now have the exponent for the machine representation. So that exponents smaller than zero can also be saved, you only need to add 127 (for float) the exponent—that is, 132 for 5, or binary $z_{2.1000010}$.

There are eight bits, just as much space in the exponent for a float. If there were fewer, you would pad with zeros in front; if there were more, you would have an overflow and the number could only be stored as stored as infinity. If the result for the exponent were negative, this would be an underflow—a number so close to zero that it can only be stored as zero.
