But what information does typeid return? Well, mainly const& to a type_info instance; let's call it ti. The following things can be done with ti:

+   - size_t ti.hash_code()
Returns a hash value, for example, to quickly test for inequality.

+   - const char* ti.name()
Returns a textual representation of the type. However, this does not have a standardized format, nor must it be different for all types in a program, nor is it guaranteed that this text will always be the same for a given type. So, it is not very reliable, although informative, and is therefore mainly used for diagnostics.

+   - type_index(ti)
This important function from the <typeindex> header is the way to check the equality of two types based on their type_info references.

More important than what works is perhaps what does not work: You cannot create or copy a type_info, and you should not compare them with ==. It is not guaranteed that two calls til1 and ti2 of typeid(A) will return the same type_info—in fact, even til == ti2 is not guaranteed, although operator== is overloaded for type_info.

If you want to find out whether til1 and ti2 represent the same type, do it like this: type_index(til1) ====
