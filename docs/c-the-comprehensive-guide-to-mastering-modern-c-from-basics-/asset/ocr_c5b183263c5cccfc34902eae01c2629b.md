# The Elements and Their Properties

As with set, the elements in the multiset are the keys by which the container is kept sorted. Here too, you can overload operator<= or operator> for your element type, or provide your own comparator as an optional template argument.

To make it clear, so that there are no misunderstandings, especially not in comparison to the unordered multiset: all elements in the multiset are stored in a sorted tree, including duplicates. You can see this exemplified in Figure 24.12. It is not the case that duplicates are stored in a linked list or something similar. This means that even with a multimap having many or duplicate entries, the performance does not degrade. The multimap is just as fast with n identical elements as it is with n different ones. The key property of multiset is that its efficiency is guaranteed and unlike the unordered_ variants if they have poor hash functions. In Listing 24.75, you can see how set, multiset, and unordered multiset perform in different scenarios. One conclusion is that many identical elements do not degrade the performance of an unordered_multiset, but many different ones do with a poor hash function.
