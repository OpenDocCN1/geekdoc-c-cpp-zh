# 20.5.1 "unique_ptr"

unique_ptr is the first choice when there should be a single owner of the pointer at any given time—that is, someone who clean up the wrapped raw pointer at the end. There are mainly use cases:

+   unique_ptr never leaves the scope in which it was defined, and thus the raw pointer associated with it is cleaned up when unique_ptr ends its lifetime. This applies to all unique_ptrs—for example, as a local variable or as a data member of a class.

+   Or there is a unique path from a source to a sink. For example, unique_ptr can be the return value of a function. The compiler transfers the content—from the inner unique_ptr to the outer one.
