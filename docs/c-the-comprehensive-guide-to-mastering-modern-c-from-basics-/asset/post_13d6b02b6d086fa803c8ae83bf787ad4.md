# Specialty: List Operations

Just like list, forward_list has a set of methods that serve as replacements for some free functions from <algorithm>, but always operate on the entire list instead of just a range between two iterators. Fortunately, merge is also available for merging two presorted lists.

The specialty of efficiently merging lists or ranges works again with a special case in forward_list compared to list—namely, splice_after, as shown in Listing 24.44.

```cpp// https://github.com/godbolt/z9qFY4Mve
#include <forward_list>
#include <iostream>

using std::cout; using std::forward_list; using std::ostream;

std::ostream& operator<<(ostream& os, const forward_list<int>& data) {
    for (auto i : data) { os << i << '\n'; }
    return os;
}

int main() {
    forward_list<int> fw1 {10, 20, 30, 48};
    forward_list<int> fw2 {5, 6, 7};
    fw1.splice_after(fw1.begin(), fw2); // transfers everything
    cout << fw1; // Output: 10 5 6 7 20 40

    forward_list<int> fw1 {10, 20, 30, 48};
    forward_list<int> fw2 {5, 6, 7};
    fw1.splice_after(fw1.begin(), fw2, fw2.end()); // one element left
    cout << fw1; // Output: 10 6 7 20 30
    cout << fw2; // Output: 5
}
```

**Listing 24.44** "splice_after" can efficiently merge lists.

splice comes in several variants to merge entire forward_list containers or just ranges of them. Note that the nature of the forward_list interface is once a bit tricky. As you can see in Listing 24.44, the two similar calls to splice after yield different results: The first variant only takes source list as a parameter and transfers the entire content of the source. However, if you pass two iterators as the source, the list is not spliced at the first iterator; that is, the "after" rule applies. Because I pass begin() here, the splice happens after the begin. As a result, element remains in the source.

# 24.7 Associative and Ordered

In this section, Cont stands for one of the container types like set<int> or map<int,string>, and cont is for an instance of a container, such as set<int>. For key type, I use K or, for target type or T, and the value type pair<K, T> is V. Iterator types are abbreviated as It.

- *set<Key>*
This "set" contains elements where the stored values are also elements, in contrast to the map. For example, simply put all elements into set<Person>. Because the keys are always well-ordered, the elements are always sorted, allowing fast retrieval in guaranteed time.

- *map<Key,T>*
Use to translate values of one type to another. map finds a corresponding target value based on a key. For example, map translates string into your own type. In this container, the elements are always well-ordered, and the search is guaranteed.

- *multimap<Key,T> and multiset<Key>*
For each Key, the non-multi variants can only store one element. With these variants, multiple elements can also be hidden behind a key. Therefore, duplicate insertion is possible.

| Container | Description |
| :--- | :--- |
| set | Sorted and duplicate-free collection of elements |
| map | Unique keys refer to a target value |
| multiset | Sorted collection of elements that can occur multiple times |
| multimap | Sorted keys can each occur multiple times |
