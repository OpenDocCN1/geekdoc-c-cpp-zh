Unlike with thread, you are not forced to handle exceptions within the thread function; you can do that in the calling thread. This increases the chance that you can keep exception handling centralized and avoid catch blocks.

But, you might ask, what happens if the exception is thrown in a thread started by async with the launch::async policy? The answer is: it is caught and stored by the framework. It is thrown in the calling thread when you query the result with get().

```
// https://godbolt.com/z/rYM9xqsGa
#include <future>
#include <vector>
#include <algorithm> // max
#include <iostream>

int getHeight(int count, int maxCount, int scale) {
    if(maxCount == 0)
        throw std::logic_error("All heights 0");
    return (count * scale) / maxCount;
}

void bar(const std::vector<int> &counts) {
    // Start calculation
    auto maxCount = std::max_element(counts.begin(), counts.end());
    std::vector<int> futs;
    for(int count : counts) {
        futs.push_back(std::async(launch::async, count, maxCount, 200));
    }

    // Collect results
    for(auto &fut : futs) {
        std::cout << fut.get() << " "; // triggers exception
    }
    std::cout << "\n";
}

    try {
        bar(std::vector<int>{10,23,13,0,33,4}); // Output: 60 139 78 0 200 24
```
