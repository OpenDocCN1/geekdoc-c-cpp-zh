Each function is introduced with extern "C" so that as a C++ author, when you include that header, you can distinguish C++ functions from C functions. This is necessary because C++ uses different mechanisms when searching for the appropriate function; this is important for overloading and the like. So, coming from C++, every function signature you want to use must be marked with extern "C". If this is missing in a header, you can alternatively include it in your source code in a slightly cumbersome way:

```
extern "C" {
#include <zlib.h>
}
```

After you wrap the entire #include in a large extern "C".

After you have the header, you continue with the rest of the program. In addition to <zlib.h>, you also need some of the usual C++ headers from the standard library. For error handling with zlib, the <errno> and <cstring> C headers are necessary. The former allows querying the global error code variable, errno, which zlib uses; this is stated in the documentation. The latter provides strerror to convert an error code into a readable text message. Both headers are part of the C standard library. Therefore, each header exists in two variants: In C++, you use <errno> when <errno.h> is specified in the C documentation. Similarly, the C include <strings.h> becomes <cstring> for C++ programs.
