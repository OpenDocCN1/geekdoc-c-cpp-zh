w.setNumber(100); // w is non-const, changing is okay
}

# Listing 13.9 Although the return type is marked with "const" here, it has no effect because it is always copied.

Although the return type is const Widget, the const never have an effect because the return is always copied as a value—and the caller can have control over where it is copied. Here it is copied again into Widget w (non-const), and thus the caller can do whatever they want with their copy.

It is quite different with references (and pointers): a reference means "no copy."

nI can't say it often enough: if you return a reference, you must ensure that the object reference points exists for as long as you use it externally.
