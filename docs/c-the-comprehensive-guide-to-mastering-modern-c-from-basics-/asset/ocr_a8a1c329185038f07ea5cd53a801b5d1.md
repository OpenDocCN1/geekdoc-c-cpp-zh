# **Listing 14.3** In the “fib.cpp” file, there is a free function that you want to test.

This should be the entire content of fib.cpp. You write the tests in a separate module, separate from the production code—for example, in a separate directory like test/, or with a clear naming scheme such as test_fib.cpp.

To test the fib in another module, you need to call it—and that requires that it is known to the test code. Either you need a header that exports the function and that you include in the test code, or you use your internal developer knowledge about the function and declare it the tests without #include. It depends on your test rules whether you allow this as an exception and for unit tests, because in productive code such opaque of functions is not good style. One might argue that unit tests are an exception here, because the naming scheme of the filenames indicates where the actual function is located.
