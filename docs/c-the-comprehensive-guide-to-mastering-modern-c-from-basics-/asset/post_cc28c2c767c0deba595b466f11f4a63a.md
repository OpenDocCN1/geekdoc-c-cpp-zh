
I let the compiler define the method operator=> for Point = default, which then lexicographically compares the fields x_ and y_. The compiler generates operator< from it. If you don't have C++20 available, define operator< as a friend with tie(a.x, a.y) < tie(b.x, b.y);

```cpp
// https://godbolt.org/z8njj7vfeba
template<typename IT>
ostream& operator<< (ostream& os, const pair<IT, bool>& wh) {
    return os << (wh.second ? "yes" : "no");
}
struct Point {
    double x, y;
    Point(double x, double y) : x(x), y(y) {}
    friend ostream operator<<(ostream& os, const Point& a) {
        return os << "(" << a.x << ", " << a.y << ")";
    }
};
int main() {
    set<int> data{10, 20, 30, 40, 50, 60, 70}; // inserts between 30 and 40
    auto wh = data.insert(35); // Output: yes
    cout << "new?" << '\n';
    wh = data.insert(40); // already exists, so does not insert
    cout << "new?" << '\n'; // Output: no
    set<Point> points;
    points.insert(Point(3.5, 7.25)); // temporary value
    points.emplace(1.25, 2.00); // constructor arguments
    cout << points; // Output: (1.25,2) (3.5,7.25)
}
```

# Listing 24.52 To insert a single element, use "insert" or "emplace".

One variant of insert works to extract. The return type of extract, which is only known internally, is a parameter of insert. This allows you to efficiently transfer elements between similar containers.

## Inserting a Single Element with a Position Hint

You can achieve a slight speedup by providing an iterator as an additional parameter for insert. For place, use place_hint so that the iterator is not confused with a forwarded constructor argument. As a return, you get an iterator to the insertion position. If your position hint is correct, the insertion takes constant time on average—that is, O(1). If the hint is incorrect, the insertion occurs at the correct position regarding sorting, but the time consumption falls back to that of a manual insertion.

```cpp
// https://godbolt.org/z/gzaI79bor
set<int> data[] = {10, 20, 30, 40, 50, 60, 70};
set<int> target(data);
auto hint = target.begin();
for(auto &e : data) {
    // insertion position in the next range
    hint = target.insert(hint, e); // Hint helps because data is sorted
}
```

# Listing 24.53 You can return the value when inserting sorted ranges.

The return value of the insert method with a position hint returns an iterator for associative containers as well as for sequence containers. This allows you to write functions that work with both container types.

```cpp
// https://godbolt.org/z/h1Gv86jv
#include <set>
#include <vector>
#include <iostream>
using std::cout; using std::ostream; using std::set; using std::vector;

template<typename Container>
void insertFive(Container& c, int a, int b, int c, int d, int e) {
    auto it = c.end();
    for(int x : { a, b, c, d, e }) {
        it = c.insert(it, x); // works with vector, set etc.
    }
}

int main() {
    vector<int> dataVec;
    insertFive(dataVec, 0, 2, 2, 0, 4);
    for(auto e : dataVec) cout << e << " ";
    cout << "\n"; // Output: 4 0 2 2 0
    set<int> dataSet;
    insertFive(dataSet, 9, 4, 2, 2, 0);
    for(auto e : dataSet) cout << e << " ";
    cout << "\n"; // Output: 0 2 4 9
}
```

## Access via Iterators

The iterators of set are bidirectional; see Table 24.2. Because associative containers are ordered at all times (hence the name), you always iterate over the elements in a given order. With `begin()/end()`, this order is ascending; with `rbegin()/rend()`, it is descending.

## Access via Search

The most important search function is find. It takes a search element and returns an iterator. If the element is found, it points to it; if not, it points to end(). lower_bound behaves differently: it finds the first element that is not less than the search element. That means if it is present, it points to it; if not, it points to the next element. With upper_bound, you get the first element that is greater than the search element. Both equal_range you get a pair of two iterators that mark the search element (so, a range). With count, you find the number of matching keys; in a set, this is either zero or one. Since C++20, there is also contains, which returns a bool. All searches are guaranteed to take at most log steps.

```cpp
// https://godbolt.org/z/M74f77
#include <set>
#include <iostream>
using std::ostream; using std::set;
void search(const set<int>&data, int what, ostream& os) {
  // contains
  auto inside = contains(what); // C++20
  os << "inside: " << (inside ? "yes." : "no."); // check contains
  auto where = data.find(what);
  if (where != data.end()) {
    os << "found: " << *where;
  } else {
    os << "not found.";
  }
  auto lo = data.lower_bound(what);
  if (lo != data.end()) {
    os << "lo: " << *lo;
  } else {
    os << "lo: end";
  }
  auto up = data.upper_bound(what);
  if (up != data.end()) {
    os << "up: " << *up;
  } else {
    os << "up: end";
  }
  // [lo,up) is the same as what equal_range would returned
  os << "Range:";
  for(auto i=lo; i!=up; ++i) {
    os << *i << ",";
  }
  os << ")";
  // count
  os << "count: " << data.count(what) // count hits
  os << "\n";
}
set<int> data={10, 20, 30, 40, 50, 60};
search(data, 20); // 20 in:yes. found:20 up:30 range:{20} C:1
search(data, 25); // 25 in:no. lo:30 up:30 range{} C:0
search(data, 10); // 10 in:yes. found:10 up:20 range:{10} C:1
search(data, 60); // 60 in:yes. found:60 up:range:{60} C:1
search(data, 5); // 5 in:no. lo:10 up:10 range{} C:0
search(data, 99); // 99 in: no. lo:end up:end range{} C:0
```

# Listing 24.56 These are the "set" search functions.

If the combination of return values seems strange to you, you might remember them by their typical use cases:

- lower bound finds the search element or—if not present—its best insertion position.
- equal_range returns the range of all found elements, which is particularly useful for the mult variants of the containers. If no element fits, the range is empty.
- upper_bound returns the first element that no longer fits.

It helps me to imagine that the found boundaries lie between the elements, not on the elements themselves. Figure 24.11, I have drawn the returned iterators at the beginning of the element. If you imagine it that way, the terms upper_bound and lower_bound suddenly fit perfectly.

I mostly use lower_bound myself, and sometimes equal_range with multiset. upper_bound is used less frequently, but you can find an example in Listing 24.58.

The search functions are also available in the <algorithms> header for all compatible containers, especially for sequence containers. However, they must be sorted beforehand. Chapter 25.
