One example is the ranges::sized_range concept. It requires that it be possible to calculate the size of a range in O(1). A container that offers size() usually fulfils this—at least. However, if you write a Pile container yourself that has a size() method which does not work in O(1), then the sized_range concept should not be fulfilled for this container. This is a semantic constraint.

The ranges::sized_range concept therefore also checks whether the disable_sized_range<Pile>=true expression is defined—or, more precisely:

```
constexpr bool std::ranges::disable_sized_range<Pile> = true;
```

So you can use your own definition to communicate the semantics of your container, and the sized_range semantic concept will notice it.
