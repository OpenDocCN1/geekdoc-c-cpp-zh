The simple and composite requirements should each end with a semicolon;.

# 23.4.3 How to Write Concepts tedious to repeat the entire list of

requirements every time you write a function. Therefore, you can define recurring concepts with the concept keyword.

```
// https://godbolt.org/Txcnr6jTM
template<typename T>
concept dbl_quotable = copyable<T> &&
requires(T t) { mk_string(t) + mk_string(t); }
requires(T t){ mk_string(t) -> same_as<string>; };
string dbl_quotable auto& val) {
    auto val2(val);// Create a copy (for demonstration purposes only)
    return '*' + mk_string(val) + mk_string(val2) + '*';
}
```

**List 23.27** Define requirements using concept.

What you previously wrote directly in front of the function with && chain of requires, you now define with concept and give it a name. You can use this name in later templates. In the example, I implemented this with the auto of an abbreviated template.
