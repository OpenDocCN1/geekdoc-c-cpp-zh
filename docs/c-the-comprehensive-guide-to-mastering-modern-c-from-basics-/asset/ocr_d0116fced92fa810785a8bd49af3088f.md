+   • Explicitly from an iterator or a size

+   • Explicitly from two iterators

Note that the std::span<int> area parameter is not passed by reference, but by value, because it is just a small object.

Other ways to create a span include from a C-array, from a range, and of course from another span. But it is also the useful other way: say that you have a C++ object and want to pass it to a C API. In the earlier Listing 24.24 with fwrite, it have looked like this:

```
auto write(span<int> what, FILE* where) { // C++20: span
    return fwrite(what.data(), sizeof(int), what.size(), where);
}
```

A span has an optional template argument Extent that specifies the size of the span at compile time. If you omit it, span is dynamic as shown in Listing 24.26. You cannot change the size of the extent directly, but only in relation to the underlying content:

```
span sp(vec.data(), 3); // the first three elements
sp = span(vec.end(), vec.end()); // Assignment, now the last five elements
```

You created fixed-size extents, for example, in the next listing.

```
//://godbolt.org/z/aqqrYPM
int arr[] = {1, 2, 3, 4, 5}; // directly from a C-array
span<int> arr2 = {1, 2, 3, 4, 5};
span span2(arr); // directly from a std::array
vector vec = {1, 2, 3, 4, 5}; // with 'Extent' from a std::vector
span<int> sp3 = span 3(vec);
```

# Listing 24.27 These are spans when you want to take advantage of the compiler

You can use fixed-size spans when you want to take advantage of the compiler performing certain size checks at compile time for you:

```
std::array arr{1, 2, 3, 4, 5, 6}; // size 6
std::span<int, 3> sp3(vec); // size 3
sp3 = arr; // does not compile
```

The as bytes(span) and as_writable_bytes(span) functions are also very exciting. With these you can convert a span into span<const byte> or span<const byte>. You could also use these here for fwrite() or even change the underlying memory location.
