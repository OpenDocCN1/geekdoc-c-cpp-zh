+   - Element access: E operator[](), E& at(size_t), E front(), E back()
With const(), you can access the l-th element unchecked. The method first checks whether the container contains the element and throws an out_range exception if it does not. c.front() is equivalent to *(c.begin()), and c.back() is equivalent to *(prev(c.end())). Exceptions: list and forward_list have neither at nor(), and forward_list has no back.

+   - Size: size(), empty(), resize(size_t), max_size()
With size(), you get the current number of elements in the container; empty() is true if this is zero. When you call resize, the container shrinks or grows and may remove or create elements accordingly. With max_size(), you get the theoretical maximum size of the container. That does not consider the current state of the program or the machine but is a library-dependent constant. Exceptions: forward has no size(), and array has no resize.

+   - Capacity: capacity(), reserve(size_t), shrink to fit()
Only vector has a capacity different from that you can increase.
capacity() returns the number of elements that vector can hold without needing to request new dynamic memory. If you pack more into it, this capacity automatically increases. Internally, this results in all elements being copied or moved. Sounds worse than it is, but if you know in advance how many elements you will pack into a vector, it is worth requesting this capacity once with reserve(). If you do not know this in advance but can estimate when you are adding elements, you can get rid of excess capacity with a shrink_to_fit(). However, this approach can also trigger an internal copy or move, and vector does not have to comply with the request. Exceptions: deque is usually based on vector, it also has a shrink_to_fit().
