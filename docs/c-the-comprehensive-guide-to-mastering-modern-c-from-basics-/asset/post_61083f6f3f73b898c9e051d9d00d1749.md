
# Searching without a Specific Key

The parameters of find and find-related functions naturally require a key as a parameter for the search. But what if generating a key is very costly or even impossible? Or the search keys are slightly different in form from the stored keys? In that case, you can use a different type as a parameter for the search. It is important that the keys are equivalent (with respect to the search).

```cpp
// https://cppbolt.org/z/zEsdBe7g
#include <string>
#include <set>
#include <iostream>
#include <tuple>
using std::string; using std::set; using std::count; using std::tie;
struct Hobbit {
    string firstName;
    string lastName;
    Hobbit(const string v, const string n) : firstName(v), lastName(n) {}
};
struct CompLastName {
    bool operator()(Hobbit x, const Hobbit& y) const { // normal <
        return tie(x.lastName, x.firstName) < tie(y.lastName, y.firstName);
    }
    using is_transparent = std::true_type; // allowed for find
    bool operator()(Hobbit x, const string& y) const { // for find etc.
        return x.lastName < y;
    }
    bool operator()(const string& x, const Hobbit& y) const { // for find end.
        return x < y.lastName;
    }
};
int main() {
    using namespace std::literals; // allow ""
    set<Hobbit, CompLastName> hobbits = {"Frodo", "Baggins" };
    hobbits.emplace("Sam", "Gamgee");
    auto f1 = hobbits.find(Hobbit("Frodo", "Baggins")); // whole key
    if(f1 != hobbits.end()) {
        cout << "found: " << f1->firstName << '\n'; // Frodo
    }
    auto f2 = hobbits.find("Gamgee"); // equivalent key
    if(f2 != hobbits.end()) {
        cout << "found: " << f2->firstName << '\n'; // Sam
    }
}
```

You can search with non-identical keys if they are equivalent.

In Listing 24.57, to search for "Gamgee"s, you do not need to create a whole search element of Hobbit. For this, the configured comparator CompLastName must have certain properties. For the normal comparisons that set uses internally, and the search for find(Hobbit{"Frodo", "Baggins"}), the first operator() is defined, which takes two Hobbit arguments. For the search for "Gamgee", the other two overloads are there, which take a Hobbit and a string. However, with the line

```cpp
using is_transparent = std::true_type;
```

it should also be indicated that these overloads can be used for search functions. Thus a string can be used directly for the search, and no entire Hobbit is created.

Note in this way you can only search if the alternative comparison functions do not imply a different order than the main comparison operator. You cannot expect the set to be kept sorted in one order, but then search with a comparison operator that would sort differently. This is what is meant by an equivalent comparison function.

# Deleting

For deletion, you have erase and clear available. With extract, you remove an element, which you usually transfer to another set with insert:

- Deleting all elements
  You delete all elements with the clear() method.

- Deleting a single element
  If you pass an iterator to the erase method, the element at that position will be deleted. Alternatively, you can also specify an element as a parameter, which will be deleted if it exists. Both log n time. The return value is the number of deleted elements.

- Transferring an element
  With extract, you remove a single element from the set. The return value is a "handle" for the removed node, which you can use for other purposes, such as transferring it to another similar set using insert.

- Deleting multiple elements
  With a pair of iterators algorithms erase can delete the elements between them.

All iterators of nondeleted elements retain their validity.

```cpp
// https://cppreference.org/w/cpp/set/erase
set<int> data = {10, 20, 30, 40, 50, 60, 70};
auto lo = data.lower_bound(35);
auto up = data.upper_bound(55); // deletes all numbers between 35 and 55
data.erase(lo, up);
cout << data; // Output: 20 30 60 70
lo = data.lower_bound(20);
up = data.upper_bound(60);
data.erase(lo, up); // deletes 60, because up to 70
cout << data;
int n = data.erase(69); // deletes nothing
cout << "Number of removed elements: " << n << "\n"; // Output: 0
n = data.erase(70); // deletes one element
cout << "Number of removed elements: " << n << "\n"; // Output: 1
cout << data; // Output: 10
```

# Listing 24.58 erase deletes one or more elements.

A map is used to quickly find values using keys.
Each key (Key) in a map is associated with exactly one target (Target). The map is related to the set in that the rules for the elements of set also apply the keys of map:

- Keys in a map are always sorted.
- No key appears more than once in a map.
- Searching for a key is guaranteed to take at most n steps.

Much of applies to set also applies to map, so Section 24.7.3 can provide additional information.

However, there is a big difference from set: the individual elements in the map are a pair, specifically a pair<const Key, Target>. When I refer to this pair, I use the term Element or elem in the context of map.

# Value Is Ambiguous in "map"

Sometimes the key and target pair is also called the value. Elsewhere, value refers to what I named target. To avoid this misunderstanding, I strive to avoid the term value in the context of map.

If you come from another language like Python or Perl, I want to immediately draw your attention to a pitfall you might stumble over, because the C++ map behaves differently than the Python dictionary or the Perl hash. If you access the map with [] and the key does not exist, a new entry is created with its default constructor. This is a side effect. If you want to determine whether it exists, use find or contains.

```cpp
// https://cppreference.org/w/cpp/map/at
#include <map>
#include <iostream>
#include <string>
using std::map; using std::cout;

int main() {
    map<char, int> alpha;
    alpha['a'] = 1;
    cout << alpha.at('a') << '\n';
}
```

If you do not like this implicit behavior of [], use insert_or_assign instead of inserting into a map.

# The Elements and Their Properties

The elements of map are pair<const Key, Target>—that is, a pair consisting of a key and target. For the key, the rules of the elements as set apply, as well as the associated rules for comparison and sorting. By default, the compiler uses a less-than to internally arrange the keys in a tree and keep them constantly sorted.

If you don't like <, you can specify your own comparison function as an additional template parameter.

This also works for custom data types, but you can simply overload operator<.

```cpp
// https://godbolt.org/z/W0MnfxJl
#include <cctype> // toupper, lower
// /
auto comp = [](char a, char b) { return toupper(a) < toupper(b); };
map<char,int,decltype(comp)> lets(comp); // as template parameter and argument
lets['a'] = 1; lets['b'] = 2; lets['c'] = 3;
lets['A'] = 4; // overwrites position 'a'
```
