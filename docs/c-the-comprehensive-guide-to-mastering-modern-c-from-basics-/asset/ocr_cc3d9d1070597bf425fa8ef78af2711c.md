I have timeStuff exemplarily provided with C++20 concepts. For Gen it is required gen must be a functor that can be called with a size_t and whose return must be an int. For Cont, the value_type must be an int.

You can make the following observations:

+   - The multiset almost doesn't care whether the elements are same Or scattered.

+   - set is nearly ultrafast with same because it ignores duplicates and thus constantly holds one element.

+   - With a reasonable hash function, it doesn't matter to unordered_multiset whether the values are the same or scattered.

+   - Only with a poor hash function like badHash the performance catastrophically degrade when different elements are sorted into the same bucket.

Performance also heavily depends on the implementation of the compiler and the associated standard library. Here is the program on the same machine, compiled with a different compiler (Clang+ 9.0):[59]


Note that the performance of an unordered associative container can also degrade if you have a not-so-bad hash function but unfavorable data. Only the ordered variants provide guarantees, though the unordered ones are faster in the optimal case.
