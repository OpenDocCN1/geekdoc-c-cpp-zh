parameter of print_ref8 is declared with the & as a reference—namely, int& n. Therefore, when calling print_ref8(x) in main(), the compiler does not copy the value of x into the function, but passes the x itself as a reference; within the function, it is then addressed with the parameter name n. This way, you can call print_ref8 from completely different program locations and pass completely different variables; within print_ref8, they are always called n.

There is another difference: you cannot use print_ref8(42). Can you see why? Within print_ref8, the 42 would be referred to by the name n—and later an assignment is made in print_ref8 with n = 8. This means it would be 42 = 8, and obviously is not possible. However, the compiler prevents this not only at the assignment n = 8, but at the call print_ref8(42): the parameter type is int& (read: “reference to int”) and not int, and the compiler cannot refer to 42 in this way; 42 is not compatible with int&, and the compiler will complain.
