
To offer some damage control here, the constructors and methods of the flat containers that add entire ranges have an optional `sorted_unique` or `sorted_equivalent` marker parameter, which can then work more efficiently if the elements are already sorted.

Use these adapters consciously and not just always!

A special feature of the flat containers is that you can access the internal containers for keys and values with the `extract` method. The container for the keys is even sorted.

## 24.10 Special Cases: "string", "basic_string", and "vector<char>"

| Container | Description |
| --- | --- |
| basic_string | Specialized container for texts, similar to vector |
| string | Template specialization: `basic_string<char>` |

**Table 24.11** Profile: "string".

Almost everything you can do with a `vector`, you can also do with a `basic_string`. The relationship goes so far that `basic_string` even has a `push_back` method for appending individual characters. And `string`, in turn, is just a template specialization of `basic_string<char>`.

Although `vector<char>` is very similar to `string`, you should use `string` when it semantically fits better. `string` is better suited for texts and text manipulations, while `vector<char>` is better when the characters are to be considered individually and not necessarily form a text together. For example, some implementations have special optimizations for short strings that you wouldn't need.

However, there is at least one advantage of `string` over `vector<char>`: you can initialize `string` directly from a string literal—that is, `const char[]`—which is not possible with `vector<char>`. Also, `vector<char>` does not have overloaded `operator<<` for output.

Since C++20, the string class has undergone a lot of modernization to feel more like strings from other languages. Some special features have been added that set it apart from other containers: are now `starts_with` and `ends_with` methods. Since C++23, there are also `contains`, `insert_range`, `append_range`, and `replace_with`. For working with APIs, `resize` has been added, allowing you to overwrite string of predefined size. Strings work excellently with ranges, just like other containers. Starting from C++17, we also have `span` extensions:

- span: A span roughly replaces `begin()` and `end()`. You typically use `span` with vector and array, but it also works with string.
- string_view: This provides a read-only span to a string or `const char*`. Typically you use it as a parameter where you previously passed `const string&`.
- sv as suffix: The standard library also provides the user-defined suffix to create a `string_view`. The advantage over `string` is that it does not create a new string, but only a view—almost nothing needs to be copied or created.

```cpp
// https://godbolt.org/z/7zbrld
#include <vector>
#include <string>
#include <iostream>
#include <string_view>

using std::string; 
using::string_view; 
using std::vector; 
using std::cout;

int get_len(string_view str) { return str.size(); }

int main() {
    string s1 = "Hello"; // simple with string literal
    string s2{'H','e','l','l','o'}; // or list of char
    using namespace std::literals;
    auto s3 = "Hello"sv; // even simpler with string literal
    vector<char> v1("Hello"); // no vector with
    vector<char> v2{'H','e','l','l','o'}; // list of char is okay
    cout << s1 << s2 << s3 << '\n'; // Output of string works
    cout << v1 << v2 << '\n'; // vector has no output

    const auto str = "String"; // String literal
    const auto strv = "String"sv; // StringView literal
    cout << "Length of str is " << get_len(str) << '\n'; // Output:
    cout << "Length of strv is " << get_len(strv) << '\n'; // Output: 
}
```

**Listing 24.89** "string" is more suitable for texts than "vector<char>".

## 24.11 Special Cases: “vector<bool>”, “array<bool,n>”, and “bitset<n>”

For an array of truth values, the standard library offers several specialized solutions from which you can choose the right one depending on the application.

| Container | Description |
| vector<bool> | Specialized container; stores bool compactly |
| array<bool,n> | Regular container; stores bool values separately |
| bitset<n> | Compact, but not a standard container; rather like a large unsigned with bit operations |

**Table 24.12** Profile: The bool containers.

### 24.11.1 Dynamic and Compact: “vector<bool>”

Assume that `vector<bool>` wastes a lot of space: a bool normally as large as an int for performance reasons, even though a single bit would suffice to store true or false.

In the case of `vector<bool>`, the standard library has a specialization where bits are compacted. Multiple true/false values share a memory space. This means that a container `vector<bool>(100)` takes up much less memory than `bool[100]`.

Externally, `vector<bool>` behaves like a normal sequence container for bool—with one exception: the access methods cannot provide a `bool&` for in-place modification. A reference into the vector would always hit multiple bits at once. Instead of a `bool&` you get back a proxy object.

### 24.11.2 Static: “array<bool,n>”

`array<bool,n>` is a fixed-size array. Unlike `vector<bool>`, it does not use dynamic memory and each element occupies one byte.

### 24.11.3: “bitset<n>”

`bitset<n>` is a compact representation of a fixed number of bits. It is useful for bitwise operations and when the number of bits is known at compile time.
