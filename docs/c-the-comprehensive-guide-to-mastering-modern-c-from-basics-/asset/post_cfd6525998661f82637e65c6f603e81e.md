
## 24.8 Only Associative and Not Guaranteed

In this section, Cont stands for one of the container types and cont for an instance of it. As key type use Key or K, as target type Target or T, and the value type pair<K, T> is Value or V. Iterator types are abbreviated as It.

| Container | Description |
|---|--|
| unordered_set | Contains a unique set of elements |
| unordered_map | Unique keys refer to a target value |
| unordered_multiset | Is a set of elements that can occur multiple times |
| unordered_multimap | Keys can occur multiple times |

These containers do not store their keys sorted, but hash them. This has two effects: first, the elements are not in a specific order when you iterate; and second, hashing is often faster than sorting.

### 24.8.1 Hash Tables

While map, set, and their multi_ variants store their elements in a permanently sorted tree, the unordered variants use lookup tables called hash tables.

By using the tree, map and set guarantee an upper bound on the time consumed during searches. Hashing is usually faster, but it cannot provide this guarantee. It is important to know that in extreme cases it can be much slower. hashing works well depends on many factors; for example, you might have an inefficient hash function (without realizing it) or receive unfriendly data (which is beyond your control).

### Hashing, Tables, Buckets, and Collisions

When an element is to be inserted or searched, the container first calculates a hash value for the element. This is a numerical value from a very large range—between zero and UINT MAX. This hash value determines the position of the element in the hash table. However, because this table cannot have UINT entries, it is much smaller; let's say it has 1,024 entries. The position in the hash table is determined by the hash value modulo 1024, which is the remainder of the division. Elements whose values are, for example, 7, 831, or 2055 are stored under the same table entry. Typically, these elements are stored as a list.

The table entries are also called buckets. When checking if a generic element is in the container, the hash value quickly leads to its bucket. The elements in this bucket have the same hash value (modulo table size), but they may differ in terms of equality ==, which is called collision. Therefore, further searching within the bucket is necessary, and this can take a long time if there are many elements in buckets. This is why the container makes a great effort to keep the number of collisions low. For example, the table size is adjusted repeatedly as the number of elements in the container grows. Everything runs normally, most buckets should contain only one element. Another important factor in keeping the number of collisions low is the quality of the hash function.

Use the unordered variants only if you need first that extra bit of speed and second control over the keys of the container—ensuring they do not become “unfriendly” in terms of frequency and hash. The ordered associative containers are more robust in this regard.

You must exercise great care when selecting the hash function. Although unfavorable input data can be disastrous, a poorly chosen hash function leads to performance catastrophes more quickly. ### Providing Your Own Hash Function

Whenever the standard library needs a hash function for the T data type, it uses the `std::hash<T>` functor. This is defined for all built-in types. For custom data types, you must provide a specialization. This is discussed further ahead in the context of Listing 24.78.

Unordered associative containers also use these functors. Alternatively, you can provide them with your own functor as a constructor argument. This is significant after injecting a functor into the std namespace.

```cpp
// https://cppbolt.org/IMYhvb7ra
#include <set> // set, multiset
#include <unordered_set> // unordered_set, unordered_multiset
#include <iostream>
#include <string>
#include <chrono> // Time measurement
using std::chrono;
using namespace std::chrono;

long milliSince(steady_clock::time_point start) {
    return duration_cast<milliseconds>(steady_clock::now()-start).count();
}

const size_t ITERATIONS = 108000;
template <typename Gen, typename Type>
requires(Gen gen, size_t n) -> std::same_as<int> &&
requires(Gen gen, size_t n) { { gen(n); } -> std::same_as<int>;
std::size_t as(typename Type::value_type int);

void timeFunc(std::string name, Type data, Gen gen) {
    auto start = steady_clock::now();
    for (size_t i=0; i<ITERATIONS; ++i) {
        data.insert(gen(i));
    }
    cout << name << " : " << milliSince(start) << " ms" << std::endl;
} // always generates the same
struct SameHash {
    size_t operator()(int) const { return 0; }
};

int main() {
    std::set<int> s;
    std::multiset<int> ms;
    std::unordered_set<int> us;
    std::unordered_multiset<int> ums;
    std::unordered_multiset<int, BadHash> umsh;

    timeFunc("set", s, [](int n) { return n; });
    timeFunc("multiset", ms, [](int n) { return n; });
    timeFunc("unordered_set", us, [](int n) { return n; });
    timeFunc("unordered_multiset", ums, [](int n) { return n; });
    timeFunc("unordered_multiset (bad hash)", umsh, [](int n) { return n; });

    return 0;
}
```
