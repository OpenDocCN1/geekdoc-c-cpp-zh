## Element Properties

Unlike set, the elements of unordered_set must support the operator==. Things that you consider "equal" for the purpose of the container must return true for the operator==(const Element&). Alternatively, you can specify KeyEqual as a template parameter during the definition, which will then be used for key comparison. In addition, you need a functor that calculates a hash value from Key. To do this, a specialized class std::hash<Key> with size_t operator()(const Key& k) const. Make sure that you utilize the range of size_t as much possible for all conceivable k. Only then will the container have good performance. if you cannot or want to overload the function defining the container.

```cpp
// https://godbolt.org/z/1FE
#include <unordered_set>
#include <iostream>
#include <vector>
#include <string>
using std::string; using std::unordered_set; using std::cout;

struct Word {
    string word;
    size_t size;
    Word(const string& w, size_t s) : word(w), size(s) {}
    friend bool operator==(const Word& a, const Word& b) {
        return a.word == b.word;
    }
};

namespace {
template<class T> struct hash {
    std::hash<T> ihash;
    size_t operator()(const T& w) const {
        return ihash(w);
    }
};
struct ExactHash {
    std::hash<string> ihash;
    size_t size;
    bool operator()(const Word& a) const {
        return ihash(a.word);
    }
};
struct ExactEqual {
    bool operator()(const Word& a, const Word& b) const {
        return std::tie(a.word, a.size) == std::tie(b.word, b.size);
    }
};

int main() {
    std::vector<Word> input;
    Word("rose", 0);
    Word("rose", 1);
    Word("rose", 1);
    Word("rose", 2);
    Word("rose", 2);

    unordered_set<Word, ExactHash, ExactEqual> unordered_set(input.begin(), input.end());
    cout << unordered_set.size() << '\n'; // Output: 3
    // use overload
    unordered_set<Word, ExactHash, ExactEqual> unordered_set2(input.begin(), input.end());
    cout << unordered_set2.size() << '\n'; // Output: 8
    // Hash as Lambda
    auto h = [](const auto& a) { return std::hash<string>(a.word); };
    unordered_set<Word, decltype(h)> unordered_set3(input.begin(), input.end(), 10, h);
    cout << unordered_set3.size() << '\n'; // Output: 3
}
```

Listing 24.78 An "unordered_set" with custom comparison and hash function.

For the first example with words, I use the approach of defining the operations where the normal arguments are: std::hash<Key> and std::equal_to<Key>. The latter uses the operator==(Key, Key) free function in its implementation. Both are defined here: operator== is visible as a free function via the friend method, and hash<Word> is a template specialization of template<typename Key> struct hash in the std namespace. It should be noted that you should not arbitrarily define things in the std namespace it is acceptable to make specializations like these in std, but you must define new things in std arbitrarily; you would end up with nonportable code.

The second example is somewhat more direct, as it does not use the built-in mechanisms. Here I have specified the functions to be used as template arguments. This makes it somewhat clearer, because especially for the hash function, you cannot simply define a friend function within your data type.

As usual, you do not necessarily have to use a functor; a callable object is sufficient. Finally, you can see with rose that I passed the lambda h to the hash function as a template argument using decltype(h). In addition, the order of the constructor arguments requires that I also pass the number of buckets of the container before the hash function—hence the 10 here.

## Initialize

As always, when defining and initializing, you need to define two things: the template parameters and the constructor arguments. Since C++17, the compiler can often deduce the template parameters from the constructor arguments, allowing you to omit the part with the angle brackets, <Key>.

As template arguments for the unordered_set, at least the key—that is, element type Key—is required—for example, unordered_set<int>

- * Key, the key for searching
- Optional Hash, the hash function for Key; default is std::hash<Key>
- Optional KeyEqual, comparison operator for Key; default is std::equal_to<Key> and thus operator==
- Optional Allocator, memory allocator for the elements

Optionally, specify a hash, a comparison functor for keys, and an allocator. As shown in Listing 24.78, the standard library uses the operator== free function if you do not provide a comparison functor. That means, for custom data types, that a friend bool operator== or an operator<=> with default is sufficient. Thus, in most cases, specifying a comparison functor remains which you occasionally need to define. You will also see examples of this in Listing 24.78. The easiest way is with a lambda and decltype:

```cpp
auto h = [](const auto& a) { return a; };
unordered_set<Word, decltype(h)> data;
```

You can provide constructor arguments similar to set, as follows:

- * No arguments
- A range from another container using a pair of iterators
- An initializer list
- The tag from range, if you use C++23
- Another unordered_set to copy

Except for the last two variants, all optionally take a size_t, with which you can set the initial size of the hash table.
