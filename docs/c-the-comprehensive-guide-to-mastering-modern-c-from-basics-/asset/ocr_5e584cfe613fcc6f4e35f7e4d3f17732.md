way to obtain the result. The return type of get() is that as
of the thread function—in this case, long.

You don't need an explicit join(). Why would you? You
don't have a thread or jthread object. This role is taken
over by get. Unlike with thread, it does not harm if the
scope of future exists before the result is retrieved.
Here, it is, the destructor waits until the
computation is finally completed, similar to jthread.

```
// https://ggbolt.org/z/7Me1Y3Mn
#include <iostream>
#include <future> // async
using std::cout = std::endl;
long fib(long n) { return n<=1 ? n : fib(n-1)+fib(n-2); };

int main() {
auto f40 = std::async(fib, 40);
auto f41 = std::async(fib, 41);
auto f42 = std::async(fib, 42);
auto f43 = std::async(fib, 43);
cout << "fib(40): " << f40.get() << endl; // Output: fib(40):
102334155
} // also waits for f41, f42, and f43.
```

# 29.6.1 Launch Policies

By using get, it should feel
to you as if the value has
always been there for you
very similar to a
unique_ptr. If that is the case, then it doesn't really
matter whether the computation took place in the
background and you just need to pick it up with get, or
nothing has happened yet and the computation only
starts with get. You wouldn't notice the difference from
the outside (except perhaps in the elapsed time).
