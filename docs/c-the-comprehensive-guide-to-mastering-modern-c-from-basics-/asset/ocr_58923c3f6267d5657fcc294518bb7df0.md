```
protected: void print() {
  cout << data; // 'data' is inherited privately here
}
class Ultimately : public Middle {
  public: void go() {
    print(); // 'data' is not visible; 'print' is protected
  }
};
int main() {
  Ultimately u {};
  u.go(); // output: 5
}
```

**Listing 18.6** In practice, child classes use privately inherited members indirectly.

In main, I instantiate Ultimately and call its only public method, go. In it, I have access to the print() method inherited from Middle. The data field is invisible, the inherited print method naturally uses the field.

# 18.2.2 Nonpublic Inheritance in Practice

wild, public inheritance is by far the most common. You should follow this practice and leave protected and private inheritance for extreme special cases.

In languages like Java, all inheritance is public.

Sometimes you see private inheritance when there is not an is-a relationship but a has-a relationship. Because the interface of the inherited class b does not become part of the interface of the inheriting class D, class D does not appear externally as a b and thus is not actually a.
