# Enough theory, let's just try it out.

```
// https://goddbbolt.org/GhY9Ssrd7
#include <iostream>
#include <future>
using std::cout; using std::endl;
long fib(long n) { return n<=1 ? fib(n-1)+fib(n-2) : n; }

int main() {
    auto f40 = std::async(fib, 40);
    auto f41 = std::async(fib, 41);
    auto f42 = std::async(fib, 42);
    auto f43 = std::async(fib, 43);
    /* at this point, further calculations can be made */
    cout << "fib40: " << f40.get() << endl; // Output: fib(40):102334155
    cout << "fib41: " << f41.get() << endl; // Output: fib(41):165580141
    cout << "fib42: " << f42.get() << endl; // Output: fib(42):267914296
    cout << "fib43: " << f43.get() << endl; // Output: fib(43):43344437
}
```

**Listing 29.30** "async" you can easily initiate asynchronous computations.

As you can see, you start a thread using async in the same way you would with jthread: the first argument is a callable object (function pointer, lambda, functor, etc.), and the rest are parameters that are passed as copies to the thread function at startup.

The difference is here you do not receive a jthread or a plain thread as a return, but a future<...>, specifically a future<long>. Because there is rarely a reason to write this type out on the left side, you will mostly see auto there, as shown here.
