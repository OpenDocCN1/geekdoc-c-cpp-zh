Both calling methods are equivalent. In the real world, you should not use different calls in associated call_once as it only confuses your readers and is also prone to errors.

You can now use the same Sender instance in multiple threads without issues (provided it is acceptable for multiple threads to send and receive data from a Connection simultaneously). Even in the presence of multiple threads, conn_ is only initialized once. Thus, call_once combines the functionality of a mutex with that of a Boolean flag.

# 29.3.2 Locking with "recursive_mutex"

that tries to lock a mutex that it has already locked will fail due to undefined behavior. In rare cases where you need to lock a mutex multiple times, use a recursive_mutex.

You can call the recursive_mutex lock() method multiple times within a thread. Another thread must wait until its lock() succeeds, which means you have to call unlock() as many times as you have used lock().
