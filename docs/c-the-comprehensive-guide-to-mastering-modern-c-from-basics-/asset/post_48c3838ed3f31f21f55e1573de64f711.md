## 23.4.2 How to Use Concepts

In the previous section, you saw some examples of self-written functions that work with existing concepts. When you write functions and classes with concepts yourself, you have a few more tools at your disposal.

The easiest way is to write a concept name instead of typename in the template header or before the angle of an abbreviated function template:

```cpp
// https://godbolt.org/z/eaGre4bqr
auto min2(const std::integral auto a, const std::integral auto &b) {
    return a < b ? a : b;
}

auto min3 = []<std::integral T>(const T &a, const T &b, const T &c) {
    return min2(a, min2(b,c));
}
```

```cpp
int main() {
  cout << min3(3, 7, 2) << '\n';
  cout << min3(8.11, 113.2, -3.1) << '\n'; // Error: not an integral type
}
```

Here we have restricted the arguments with integral so that min3(8.11...) no longer compiles. This works with functions like min2() as well as with lambdas like min3().

But you have even more options. First, you have already learned about the requires keyword. With it, you can not only specify a single concept but also combine multiple ones to add further conditions.

```cpp
// https://godbolt.org/z/fxoo4h9Gj
#include <concepts>
#include <iostream>
#include <string>
using namespace std; using std::literals;

string mk_string(integral auto val) { return to_string(val); };
template<typename T>
string mk_string(string val) { return '+'+val+';'; };
requires copyable<T> // Type requirement
requires (T t) { mk_string(t) + mk_string(t); } // simple requirement
requires (T t) { // composite requirement
  mk_string(t) -> same_as<string>; // valid expression must meet condition
}
string dbl_quote(const T val) { // Create a copy (for demonstration purposes only)
  return '*' + mk_string(val) + '*';
}

int main() {
  cout << dbl_quote(10) << '\n'; // Output: "10"
  cout << dbl_quote("ab") << '\n'; // Output: "[ab]"
  cout << dbl_quote(3.14) << '\n'; // Error: no suitable overload
}
```

## 23.2 Specify additional conditions

Assume there are overloads for mk_string defined only on integral but not on float. Now we want to write a function dbl_quote() that copies a value and then converts it to a string using mk_string(). We express this by first introducing the template with template<typename T>, thus defining the placeholder T. For this T, we then specify some requires, which combine with &&. The first requires is the introduction of the entire requires clause. The subsequent requires expressions within the clause. OR combinations with || are also possible, but rarer. The AND combination consists of the individual requirements that must be met. There are three types:

- Type requirement: In the example, copyable<T>. The type T is used in another concept that must be true.
- Simple requirement: The example states that mk_string(t) + mk_string(t) expression must be valid for t of type T. The expression is not executed; it is only checked whether the expression compiles.
- Composite requirement: Beyond the simple requirement, the arrow -> indicates a type requirement for the expression. The simple and composite requirements should each end with a semicolon.

To repeat the entire list of requirements every time you write a function is tedious. Therefore you can define recurring concepts with the concept keyword. What you previously wrote directly in front of the function with && chain of requires, you now define with concept and give it a name. You can use this name in later templates. Finally, I want to mention that you can also use concepts together with using. This way, you can also restrict a type alias with a concept:

```cpp
// https://godbolt.org/9agsGW6MB
template<std::ranges::range T> // a range over type T
using ValueTypeOfRange = std::ranges::range_value_t<T>;
// or
```

```cpp
template<typename T> // a range over type T
requires std::ranges::range<T>
using ValueTypeOfRange = std::ranges::range_value<T>;
// results in:
ValueTypeOfRange<std::vector<int>> x;                             // x is int
ValueTypeOfRange<std::string> y;                                       // y is char
ValueTypeOfRange<std::list<double>> z;                                 // z is double
ValueTypeOfRange<int> w;                                              // int is not a range
```

Even within constexpr you can use concepts. The following listing shows a minimal example of it:

```cpp
if constexpr (std::integral<T>) {
  // T is an integral type
} else if constexpr (std::floating_point<T>) {
  // T is a floating-point type
} else {
  // T is neither
}
```

**Listing 23.28** This is how you use constexpr<T> checks whether T is an if constexpr (std::integral<T>) is an integral type, and then if constexpr (std::floating_point<T>) checks T is a floating-point type. A different example can be found in Chapter 25, Listing 25.6, where also two if constexpr check for concept requirements.

So far, I have mainly shown you how to constrain templates using concepts that work based on syntactic errors Semantic Constraints. This means that if something would not compile (or would result in nonsense, as in the case of pointer comparisons), you constrain it with a concept. However, the standard library also uses concepts to check the semantics of templates. This means that even if it would technically work, you can use traits or other agreements to change the semantics so that concepts notice this and enforce a constraint. One example is the ranges::sized_range concept. It requires that it be possible to calculate the size of a range in O(1). A container that offers size() usually fulfils this—at least. However, if you write a Pile container yourself that has a size() method which does not work in O(1), then the sized_range concept should not be fulfilled for this container. This is a semantic constraint.

The ranges::sized_range concept therefore also checks whether the disable_sized_range<Pile>=true expression is defined—or, more precisely:

```cpp
constexpr bool std::ranges::disable_sized_range<Pile> = true;
```

So you can use your own definition to communicate the semantics of your container, and the sized_range semantic concept will notice it.
