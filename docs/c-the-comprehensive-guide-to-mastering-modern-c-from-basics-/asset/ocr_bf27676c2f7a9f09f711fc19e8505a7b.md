When the compiler has type information, it converts pointers accordingly and adds the offsets so that you don't have to worry about it. However, if you intervene with void* or reinterpret_cast to prevent the compiler from applying its knowledge, you suppress the corrective offset of pointer values.

In all implementations I know, this address correction only happens with multiple inheritance. Theoretically, the compiler could find it necessary in other situations as well. In that case, it must guarantee that it makes the corrections for you covertly and that everything resolves itself in the case of casts and comparisons. The real culprits would be void* and reinterpret_cast, which you should avoid anyway, right?
