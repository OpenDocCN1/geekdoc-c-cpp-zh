<chrono> also prevents someone from trying to specify 10ms as a time span. If you define sleep to take seconds as a parameter, there must be a reason for that. sleep will not be able to work in the millisecond range. So by choosing the parameter type for sleep, you are also making a statement about the granularity with which your sleep operates—and you do without extra comments or documentation.

And if you find that you need to refine your granularity to nanoseconds? Then you do not need to go through the source code and modify all sleep calls, or do you need to introduce a sleepNanoseconds function.

```
void sleep(std::chrono::nanoseconds ns) { // takes nanoseconds as duration
    /* ... */
}
```

<chrono> automatically handles the conversion at all calling sites at compile time.

# “chrono::seconds”

chrono::duration stands for duration, a time span. This can be something like seconds, three minutes, three hours, and so on.

The basis of <chrono> is the seconds in the form of std::chrono::seconds. At runtime, an instance of this type is no different from an int64_t or long long; both occupy (trivially) move, copy, and construct it, and it costs the computer almost no time.

At its core, seconds are a very simple type, and you can roughly treat it like this:

```
//://godbolt.org/z/h8yijsME
#include <cintypes> // int64_t
namespace std { namespace chrono {
    class seconds {
        int64_t sec;
        public:
            seconds() = default;
        // _ etc ~
    }
}
```
