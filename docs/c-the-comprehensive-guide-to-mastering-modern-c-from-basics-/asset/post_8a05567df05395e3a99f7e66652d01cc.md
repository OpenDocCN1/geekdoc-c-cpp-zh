
```cpp
std::cout << noleap << "\t" << noleap.day() << "\n"; // Output: 2021-02-28
)
```

You can create a date using the year_month day constructor. To prevent dangerous mix-up errors, not simply pass three integers to the constructor. For example, year_month_day(10, 11, 12) should not work: What is the day, what is the month, and what is the year? Instead, you create instances of the types year, month, and day, which you then pass to the constructor:

```cpp
year_month_day ymd(year(2024), month{11}, day{14});
```

It looks nicer with the predefined suffixes like "y", constants like November, and the / operator, which combines the individual elements into a date:

```cpp
// https://godbolt.org/z/4s697od3
auto a = 2024y/11/14;
auto b = 2024y/11/14;
auto c = 14d/11/2024;
auto d = November/2024;
```

The following orders are possible: month/day/year, day/month/year, and year/month/day. One of the first two elements must be a calendar type—so, for example, not 14/10/2024y, because 14/18 would be recognized as integer division. The / operator cleverly creates "incomplete" types as intermediate values until you reach the complete date.

You can also generate the last day of a month:

```cpp
auto ymd = last/February/2024; // last day in February 2024: 2024-02-29
```

Isn't that useful? This also makes the somewhat-looking "last" and "unspecified" types from Table 28.7 make sense. These are generated as intermediate results when you create a date with the / operator. However, they are also useful in further operations, as you will see, because you can even perform calculations with these intermediate results.

```cpp
// https://godbolt.org/z/Md38bzvf
#include <chrono>
#include <iostream>
```

```cpp
#include <format>
using namespace std::chrono;
int main() {
    auto ymd = last/February/2024; // last day in February 2024: 2024-02-29
    std::cout << ymd << "\n"; // the output with << is simple
    std::cout << format("{:%Y-%m-%d\n", ymd); // format is more flexible
    std::cout << format("{:%B %d, %Y\n", ymd); // much more flexible!
}
```

**Listing 28.28** Output of date and time with format.

The stream outputs 2024/Feb/last—which is correct, but not helpful. With format, you can output 2024-02-29 and 29. February 24, and so on.

To parse strings into a data type from <chrono>, since C++20 there are chrono::from_stream and chrono::parse.

# Invalid Dates and Error Handling

The calendars from <chrono> leave it up to you how to handle invalid dates. For example, you can create November 31, which is an invalid date. It is neither automatically clamped to November 30 nor rolled into December, nor is an exception thrown. It is up to you to handle the invalid intermediate result:

```cpp
auto ymd = 31d/October/2024;
ymd += months(i);
```

ymd is now 2024/November/31d. If you want this to automatically be limited to November 30, then use last:

```cpp
if (!ymd.ok()) {
    ymd = ymd.year()/ymd.month()/last;
}
```

If you want to round into into December, convert to sys_days. The data type ensures the wraparound at the month's boundary:

```cpp
if (!ymd.ok()) {
    ymd = sys_days(ymd);
}
```

Here you can see how to use last and the classes to handle invalid dates.

So you can generate a specific day of a month or the last day of a month. But what about, for example, the second Tuesday of a month—the day you always expect Windows updates? Use the [] notation for that.[ 7 ]

```cpp
// https://github.org/z/19vf9iFTM
#include <chrono>
#include <iostream>
using namespace std::chrono;
int main() {
  for (int mo = 1; mo <= 12; ++mo) {
    year_month_weekday patch_tues(mo/Tuesday[2]/2024);
    year_month_day ymd(days(patch_tues));
    std::cout << ymd.month() << " " << ymd.day() << "\n";
  }
}
```

28.29 Always the second Tuesday of the month.

Note how Tuesday[2] refers to the second Tuesday of the month. First, we create a year_month_weekday object, then we convert it to the universal sys_days, and finally to a year_month_day calendar for output.

# Time Zones

Since C++20, the standard library can also handle time zones. This is a very complex topic that we can only touch. The most important types involved are as follows:

- time_zone
- zoned_time
- tzdb
- tzdb_list
- ambiguous_local_time
- nonexistent_local_time

For a time zone and a time within it, there are the types:

- time_zone represents the time zone of a specific geographic region consists of the name, the UTC offset, any daylight saving rules, and so on—for example, Europe/Berlin or America/New York.
- zoned_time combines time_zone and time_point to represent a point in time in a specific time zone. Provides local_time and sys_time.

To convert, use the constructor of zoned_time with local_time:

```cpp
auto autumn = local_days(26/June/2024) + 16h + 33min;
std::cout << zoned_time("Europe/Berlin", autumn) << '\n';
```

Conversions to and from sys_time and local_time are usually straightforward. However, there are edge cases that always cause trouble. What is blame? Daylight saving. There are local times that do not exist at all, and exist twice. In Europe/Berlin, the time 02:01 on March 31, 2024, does not exist. Instead, on October 27, 2024, you have the opportunity to interpret the time 02:01 as daylight saving time and 00:01 UTC, or as standard time and 01:01 UTC. The C++ standard allows you to handle these cases. When you convert local_time to sys_time, two types of exceptions can be thrown:

- nonexistent_local_time The local time does not exist.
- ambiguous_local_time The local time exists twice. You can decide with choose::earliest or choose::latest one you need.

```cpp
// https://godbolt.org/z/ezn68
#include <chrono>
#include <iostream>
using namespace std::chrono;
int main() {
    auto spring = local_days(31/March/2024) + 2h + 1min;
    try {
        auto zt = zoned_time("Europe/Berlin", spring);
    } catch (const nonexistent_local_time& e) {
        std::cout << e.what() << '\n'; // Exception thrown: does not exist
    }
    auto autumn = local_days(27/October/2024) + 2h + 1min;
    try {
        auto zt = zoned_time("Europe/Berlin", autumn);
    } catch (const ambiguous_local_time& e) {
        std::cout << e.what() << '\n'; // Exception exists
    }
    std::cout << zoned_time("Europe/Berlin", autumn, choose::earliest) << '\n';
}
```

```cpp
// Output: 2024-10-27 02:01:00 CEST
std::cout << zoned_time('Europe/Berlin', autumn, choose::latest) << '\n';
// Output: 2024-10-27 02:01:00 CET
}
```

If you are dealing with multiple time zones, the time zone database enters into play:

- tzdb

- tzdb_list
You can use the tzdb_list() method to get a list of all time zones, and multiple versions may be stored.

- time_zone_link
This represents an alternative designation of a time zone.
