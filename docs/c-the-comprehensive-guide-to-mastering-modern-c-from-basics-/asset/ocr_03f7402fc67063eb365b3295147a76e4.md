hand. If necessary, I would rather recommend the move operations. On the one hand, it helps that you can move mutex, and on the other hand, you can then return MxStack from a function, for example.

# 29.2.6 Locks Can Lead to Deadlock

Multiple locks on a mutex potentially lead to a deadlock. For example, if a method of MxStack calls another method and both try to lock the mutex, the second call will wait forever. In pseudocode, it looks something like this:

```
class MxStack {
  bool isEmpty() const {
    std::lock_guard<std::mutex> g(mx);
    return data_.empty();
  }
  void top() {
    std::lock_guard<std::mutex> g(mx);
    if(!data_.isEmpty()) // lock inside a lock
  }
};
```

A similar situation can arise when two operations a and b in two different threads need to lock two mutexes mx and my. Once again in pseudocode:

```
Thread 1:
  operation a():
    mx.lock();
    my.lock();
    /* Work a... */

Thread 2:
  operation b():
    my.lock();
    mx.lock();
    /* Work b... */
```
