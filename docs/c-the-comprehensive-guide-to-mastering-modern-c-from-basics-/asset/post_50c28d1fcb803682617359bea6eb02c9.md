# Other Time Spans: “std::chrono::duration”

However, you not only have seconds as a time unit available, but also other time units as mentioned at the beginning. The standard specifies at least those in Table 28.6. The implementation may offer more. The types from days to years were newly added in C++20, but they do not have suffixes. **Table 28.6** Various "duration" types of the standard library.

By using ratio as the basis of these time units, <chrono> allows the automatic conversion of all these time units into each other.

```cpp
// https://cppbolt.org/z/ars63vdzl1
#include <chrono>
#include <iostream>

int main() {
    using namespace std::chrono;
    seconds mySecs = 121s;
    std::cout << mySecs << "\n"; // Allow suffixes
    milliseconds milliseconds = mySecs; // seconds(121)
    std::cout << milliseconds << "\n"; // Output: 121000ms
    // // automatically converted
    nanoseconds nanoseconds = mySecs;
    std::cout << nanoseconds << "\n"; // Output: 121000000000ns
    minutes minutesErr = duration_cast<minutes>(mySecs); // Error: Conversion with loss
    minutes minutes = mySecs; // explicit works
    std::cout << minutes << "\n"; // Output: 2min
}
```

**Listing 28.4** Automatic conversion between time units.

As you can see, then the converted size in count(). So long as the conversion can take place without loss, the transformation works automatically. It would also work implicitly for parameters and returns, as you have already seen in the introductory example with sleep(...).

It is different when information is lost during the conversion. This would be the case, for example, if you converted mySecs to minutes. Then, 121 seconds would become 2 minutes, and the remaining 1 second would be lost. Here, the compiler complains if you want to do it implicitly.

If you know what you're doing, you can force exactly this conversion with duration_cast<>. The result is a rounding toward zero (decimal places are simply truncated). You get other rounding approaches with the floor, round, and ceil functions.

To be clear, duration_cast<> is not built-in like static_cast<> and its kin, but is a function template that is fully named std::chrono::duration_cast<> and is part of <chrono>.

All this works because <chrono> knows the relationships between different time units and knows whether and how to convert them each other.

# Do Not Convert Yourself

When you start working with <chrono>, let the library handle the conversions. Do not convert yourself, like in the following listing.

```cpp
// https://godbolt.org/z/Y3dnsMYCs
#include <chrono>
#include <iostream>
int main() {
    using namespace std::chrono;
    milliseconds myMs = 4000ms;
    std::cout << myMs.count()/1000 << "\n"; // Where here lose thousands
    std::cout << myMs.count()/1000 << "\n"; // Where here lose thousands
    std::cout << duration_seconds(myMs).count() << "\n"; // explicit
    std::cout << microseconds(myMs).count() << "\n"; // like implicit
}
```

**Listing 28.25** Do not make your calculations using "count()".

It is much less error-prone to use <chrono> to do the work in one place. The performance is also not worse than if you programmed yourself by hand.

If the compiler tells you somewhere that it cannot convert something, believe it. Do not bypass its warning by using count() and your own calculation. The probability is high that you have made a logical error somewhere.

You can also mix conversions and arithmetic. An expression can contain different units. So long as no information is lost during the conversions, it works seamlessly.

```cpp
// https://godbolt.org/z/vTx4cdqza
#include <chrono>
#include <iostream>
void showDuration(std::chrono::milliseconds dur) {
    std::cout << dur.count() << "ms\n";
}
int main() {
    using namespace std::chrono;
    auto x = 2s;
    auto y = 3ms;
    showDuration(x + y); // Output: 2003ms
    showDuration(x - y); // Output: 1997ms
}
```

**Listing 28.26** You can mix units.

Here, x is automatically converted to milliseconds before + or - is performed.

# Custom duration Types

If you need other time units (Femtoseconds? Ten-day spans?) or if the 64 bits of second consume too much memory, you can easily create a new type that works seamlessly with the others.

```cpp
// https://cppbolt.org/z/ars63vdzl1
#include <chrono>
#include <iostream>

using namespace std;
using days = duration<int>;
using ten_day = duration<int,ratio<86400>>; // other time unit
using fseconds = duration<double>; // Floating point representation

int main() {
    days s(5);
    cout << milliseconds(s).count() << "ms\n";
    hours h = s; // Conversion
    cout << "day has " << h.count() << "hours\n";
    fseconds fs(2.75);
    cout << fs.count() << "s\n";
    auto printDuration = [](fseconds f) { cout << f.count() << "s\n"; }; // Function
    printDuration(45ms); // Conversion to fseconds
    // Output: 0.045
}
```

Conversions between days and week types to the normal types work easily.

You will receive special treatment if you choose a floating-point representation for your own type, in which case <chrono> assumes that no precision is lost during conversions. The expression 45ms + us is implicitly converted to microseconds. The printDuration function takes fseconds as parameter. This would not work with integer-based seconds because the compiler would protect against loss of precision. If you use a float type, the compiler allows the conversion. An explicit conversion with duration_cast<> is then necessary.

# But What Is a Calendar?

A calendar is a collection of dates, each of which has a specific name. In `<chrono>` sense, `sys_date` is the canonical calendar. A calendar that can be converted to and from `sys_date` can be converted to any other calendar.

The standard currently supports only the Gregorian calendar and `sys_days`. However, other calendars can be easily added. You might need an ISO week-numbering calendar, the Julian calendar, or the Islamic calendar, for example. In the C++ standard, the Gregorian calendar is referred to as the civil calendar as it is the most widely used.

You will find some type aliases, suffixes, and constants that refer to the civil calendar. The constant November is part of the civil calendar, although of course there is a November in other calendars.

The class for the civil calendar is year, month, and day. Note that year does not denote a duration, but rather the "name" of a year in the calendar sense. However, you can subtract two years from instances of each other to get a day. It is important that an int is not implicitly converted to a year. This prevents careless mistakes. A year is literal with y, so 2024:

```cpp
// https://codbolt.org/z/zMojoMeav
#include <chrono>
#include <iostream>
using namespace std::chrono;
int main() {
    year y{2023};
    std::cout << y << "\n";
    month m(October);
    auto result = m + months(3); // 'months', not 'month': 3 months later
    std::cout << result << "\n"; // overflowed to January
    weekday wd = wd + days(4);   // 'days', not 'day': 4 days later
    std::cout << wd << "\n"; // overflowed to Monday
    weekday sun(0); // 0 is Sunday
    weekday sunday(7); // 7 is also Sunday
    std::cout << sun << "\t" << sunday;
    weekday indexed(wd, 4); // unspecified 4th Thursday
    std::cout << indexed << "\n"; // as given by chrono
    // unspecified values
}
```

And when you put the pieces together, you get:

```cpp
// https://codbolt.org/z/6z48xvvM
#include <chrono>
#include <iostream>
using namespace std::chrono;
int main() {
    year year{2023};
    year last{2020};
    year month day ymd{year, October, 28};
    std::cout << ymd << "\n"; // in an unspecified year
    month_weekday m_ymwd{ymd, Thursday[4]}; // Output: Nov/Thu[4]
    std::cout << m_ymwd << "\n";
    month day mdlast(February); // last day of an unspecified February
    year month day leap(year, mdlast); // Add year
    year_month_day last_nleap(this, year, mdlast); // Add year
    std::cout << leap << "\t" << leap.day() << "\n"; // Output: 2020-02-29
}
```
