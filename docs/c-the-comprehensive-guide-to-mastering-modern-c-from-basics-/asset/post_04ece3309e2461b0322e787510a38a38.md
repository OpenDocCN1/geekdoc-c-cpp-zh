
## 20.11 The Exception: When Cleanup Is Not Necessary

There are indeed cases where you do not want to clean up objects you have created. If you know that the program is about to end anyway, cleaning up the data unnecessarily consumes time, and the only resource being occupied is memory, so you can use heap objects to save time.

Every stack object and every global object normally would be removed upon exiting main. But maybe you have created an enormous neural network or a super large search tree. If, for example, it consists of a million small nodes, cleaning it up can take a few seconds. At the end of the program, the operating system releases all memory en bloc anyway. So you can save yourself the trouble of releasing just before the program ends.

And this is the case where you are allowed to use new and delete. If the program is going to terminate soon anyway, you can save yourself the trouble of cleaning up memory-only resources.

```cpp
// https://godbolt.org/z/xE1TwXve
#include <map>
#include <memory> // unique_ptr
#include <string>
#include <iostream>
#include <chrono> // time measurement
using std::map; using std::cout; using std::endl; using namespace std::chrono;

struct Node {
    std::unique_ptr<int> d;
    Node() : d{new int} { *d = d; } // allow some memory
    explicit Node(int d) : d{new int} { *d = d; };
    friend bool operator<(const Node& a, const Node& b) { return *a.d < b.d; }
    friend bool operator==(const Node& a, const Node& b) { return *a.d == b.d; }
};

long milliSince(steady_clock::time_point start) { // Helper for measurement
    return duration<milliseconds>(steady_clock::now() - start).count();
}

int main() {
    std::unique_ptr<std::map<int,Node>> huge = new map<int,Node>();
    cout << "Building..." << endl;
    steady_clock::time_point start = steady_clock::now();
    for(int idx = 0; idx < 100 * 100 * 1000; ++idx) { // massive amount in the map
        huge[idx] = Node();
    }
    cout << ": " << milliSince(start) << " ms" << endl; // timing here
    start = steady_clock::now();
    huge.reset(); // cleanup
    cout << "End: " << milliSince(start) << " ms" << endl; // timing here
}
```

# **Listing 20.16** Is it worth saving the release of memory?

To measure how long something takes after exiting main(), you would need timing outside the program. Here, I simulate the cleanup of the map by telling unique_ptr to clean up its charge. You would have done the same without smart pointers with the following:

```cpp
map<int,Node> *huge = new map<int,Node>();
// delete huge;
```

But here you want to avoid raw pointers. In both cases, the rule is this: if you omit `delete huge;` or write `huge.release()` instead of `reset()`, you save the time needed to clean up the many Node objects. You can find out how much time you save at "End":

At "Done", milliSince determines the time in milliseconds required to build the data structure. I chose the number 100*100*1000 (i.e., 100 million) so that my computer can just handle it:

- Building it takes my computer about 52,000 milliseconds with nine gigabytes of memory. [ 51 ]
- Tearing it down takes 6,700 milliseconds.

It's not really much—but on other computers and different conditions, it might take more time. Whether you need this time-saving feature when exiting is up to you. However, do not let the program design suffer because of it.

In the `millisSince()` helper function, I use `steady_clock` from `<chrono>` for precise measurement.

## 21.1 The Preprocessor

Preprocessor directives always begin with the hash # at the start of a line. They have own syntax and are processed before the actual compilation takes place. The preprocessor is a powerful tool, but it must be used carefully.

- **Preprocessor**: A program that processes the source code before the compiler.
- **Include guard**: A mechanism that prevents a header file from being included multiple times.
- **Define**: A macro that replaces an identifier with text.
- **Conditional compilation**: Using `#ifdef`, `#ifndef`, etc., to include or exclude code blocks.

In C++, there are many alternatives to macros now. However, the preprocessor is still widely used for things like:

```cpp
// https://godbolt.org/z/GrM4f
// Filename: my-macros.hpp
#ifndef MY_MACROS_HPP
#define MY_MACROS_HPP

#include <iostream>
#include <vector>

#ifdef OUTPUT_TO_STANDARD
#define OUT std::cout
#else
#define OUT std::cerr
#endif

#define MESSAGE(text) { OUT) << text << "\n"; }

#endif // MY_MACROS_HPP
```
