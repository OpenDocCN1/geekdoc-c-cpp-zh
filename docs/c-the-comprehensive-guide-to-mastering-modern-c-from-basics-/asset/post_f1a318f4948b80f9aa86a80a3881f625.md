# Do Not Compare Floating-Point Numbers with ==

Because none of the floating-point types, float, double, and long double, can store all numbers exactly, you should never test for equality using `==`. Instead, calculate the difference and check whether the result is close to zero. For example, if you want to know whether the two double values a and b are "almost equal," you can check this in this way:

```cpp
if (fabs(b-a) < 0.0001)
```

The `fabs()` function returns the absolute value (makes it positive) and is located in the `<cmath>` header. For 0.0001, use an epsilon that suits your application.

# Floating-Point Literals

Similar to integers, you can write floating-point numbers naturally in the source text. However, you must use the dot `.` as a separator; the continental comma does not work. In the literal 124.258, the compiler recognizes from the dot that that it is not an integer.

```cpp
// https://cppbolt.org/qx8h7a4i9n
#include <iostream>
#include <iomanip>
using std::cout;
int main() {
    cout << std::setprecision(2) << std::fixed;
    cout << "1/4:" << 0.25 << "\n";
    // Output: 1/4: 0.25

    cout << "2/4:" << 0.5 << "\n";
    // Output: 2/4: 0.50
    cout << "3/4:" << 0.75 << "\n";
    // Output: 3/4: 0.75
}
```

```cpp
cout << "4/4: " << 1 << "\n"; // recognizes 1 as int
// Output 4/4: 1 1.0
cout << "1e0: " << 10 << "\n"; // scientific notation
// Output: 1e0: 1.0
cout << "0x10.1p: " << 0x10.1p << "\n"; // hexadecimal notation
```

**Listing 4.33** Several ways to make "double" literals.

If, with `<< 1`, the floating-point number happens to have no decimal places, then write at least the dot to distinguish it from the integer literal—and zeros if you want: 1., 1.0, 1.000, and so on. A 1 without a dot is an `int` for the compiler. This still works in many cases, because if the compiler knows that you actually mean a double, it converts the `int` 1 into a `double` 1 without loss. However, in cases where both would be possible, you should (or must) indicate the floating-point number. The output operator for `<<` does not know which you mean an int, so it outputs the 1 as such. The compiler recognizes the 1.0 as a floating-point number and the output is correct.

Since C++17, you can also use hexadecimal notation for floating-point literals, as you can see in the example at 0x10.1p0. This is close to the internal representation, which we will discuss a later in this section. Short, these are the building blocks of the literal:

- *0x*, the hexadecimal prefix
- *10.1*, the significifier in hexadecimal notation (here, decimal 1.125)
- *p*, the separator
- *0*, the exponent in hexadecimal notation

The significand or parts of a floating-point literal is `double`. In most cases today, it makes sense to use this data type as the first choice when calculating with floating-point numbers. Today’s hardware is designed for calculating with it. If you need to save space, want to use a third-party API, or have other reasons, make a floating-point literal `float` by appending an `f` or `F` to it. Adding an `l` or `L` indicates a long double. As of C++23, there are extended floating-point types that have suffixes such as `f128` and the like (see Table 4.9).

```cpp
// https://cppbolt.org/z6gf4oYnr
#include <iostream>
#include <iomanip, setprecision>
int main() {
    using std::cout;
    cout << std::setprecision(30) << "\n"; // always output 30 digits
    // Output: 1.11222333445556667788896708731250000000
    cout << 1.11222333445556667788899d << "\n"; // double is default
    // Output: 1.11222333445556667788899d6607023997349
    cout << 1.11222333445556667788899dd << "\n"; // double literal
    // Output: 1.112223334455566677888992397349
    cout << 1.11222333445556667788899ll << "\n"; // long double
    // Output: 1.112223334455566677888991227731
}
```

- *to_string(number)* This is only possible for numbers.
