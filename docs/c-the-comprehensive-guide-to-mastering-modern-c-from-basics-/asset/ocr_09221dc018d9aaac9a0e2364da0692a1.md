# Listing 17.8 C API in C++ code.

Here, the database resource is acquired with sqlite3_open(), released with sqlite3_close(), and operated on with sqlite3_exec() in between. It is, of course, not a good idea to exit the function with exception:

+   - The first exception is correct because sqlite3_open() was not successful, sqlite3_close() does not need to be called.[ 45 ]

+   - However, the second exception prevents sqlite3_close() from being called, and the resource would be blocked—or at least released—which can have different impacts depending on the type of resource.

One could, convert the entire SQLite API into a C++ API, but that is certainly a large undertaking. Besides, someone has surely done this work for a popular API like SQLite. Hopefully, they will also maintain it when something changes in the C API.

Rightly, one does not want to incur another dependency. A smaller solution might also suffice. A simple standard method to transform such code into RAII code is to wrap the resource in a wrapper class.
