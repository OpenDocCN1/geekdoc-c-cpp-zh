In Listing 29.18, I show you the public part and method declarations, not their definitions. You should notice that this class will have difficulties when used in parallel and is not inherently safe. The problem here is that you cannot rely on the result of isEmpty() in parallel operation. Although the function safely returns a correct result at the moment of the call, as soon as it exits, other threads are free to call push() or pop().

```
// https://godbolt.org/z/4j7njd763
#include <vector>

template<class T>
class MxStack {
public:
    bool isEmpty() const;
    void push(const T&);
    void pop();
    const T& top() const;
};
```

**Listing 29.18.** The interface to a multithreaded stack.

If the thread that evaluates isEmpty() acts on its result, it may be that this is no longer correct. The same is true for top() and pop(): the element that top() returns does not necessarily have to be the one that pop() removes in parallel operation.
