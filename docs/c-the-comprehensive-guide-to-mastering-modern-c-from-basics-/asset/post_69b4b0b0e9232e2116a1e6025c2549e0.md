### 6.2.5 The "endl" Manipulator

Not all manipulators actually change. The most important is endl. Because it acts like newline, it also flushes the buffer. If you use it many times, there is a delay. If you want to avoid the flush, use \n. This is a common mistake.

## 6.3 Container and Pointer

Containers are a fundamental part of the standard library. Because they play a central role, I will go into them later. Here I will give you a brief overview.

### 6.3.1 Container

So far, you have encountered types that can hold a single piece of data. For example, if you have needed two values (such as int, y). With array<int>, you already had a taste of, and I will explain now.

What do you do if you want to store a lot of values? Do you maybe want to iterate over all values? Or perhaps you don't know how many values there will? For this, the C++ standard library provides containers. Remember that containers are a fundamental idea in C++. 

### 6.3.2 Parameterized Types

All containers have in common that they are parameterized types.

They consist of a main type—the actual container—and the type or types that are put into the container. The main type is followed by parameters in angle brackets, for example, vector<int>, map<string,Car>, Or array<double,10>. It is extremely important that you consider the entire construct as a single type. A vector<int> is different from a vector<long>, just as an int is different from a long. This is crucial for function overloading and for operator resolution. For example, you can write two functions like this:

```cpp
long sum(vector<int> arg);
long sum(vector<long> arg);
```

This works because the argument types are different. You are writing a normal overload (see Chapter 7, Section 7.8).

This also applies to (constant) values as parameters; for example, array<int,10> is a different type than array<int,11>.

There are many containers in the standard library, and depending on the purpose of the application, one or the other is the sensible choice. In this chapter, I will focus on two particular containers because they are fundamentally different from each other. The respective interfaces of all containers are the same, and you can apply what you know about one to all—provided you follow some rules. There are exceptions, and quite a few of them, but once you understand the idea, you will master all.
