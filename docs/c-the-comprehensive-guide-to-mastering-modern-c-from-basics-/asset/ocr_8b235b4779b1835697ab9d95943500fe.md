In practice, you write your productive code in a certain way to make it easily testable—but the test itself is elsewhere. A data access object (DAO), which would normally be private and const, might be friend or protected for testability purposes and give up its write protection. It is better for the production code to get by as few of these compromises as possible, but designing and writing the code to be testable is more important.
