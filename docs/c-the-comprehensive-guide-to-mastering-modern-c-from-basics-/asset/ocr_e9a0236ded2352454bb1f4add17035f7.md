At file.open(filename), I no longer check if opening the file was successful, because now something else happens: file.open() triggers an exception if there was an error. This means the program is immediately interrupted and the current function—here, ifstream::open—is exited. However, this does not happen in the normal way via return, but rather on the fly. Also, countWords() and process() are “unwound” in this manner—until the try-catch block in main() is reached, which contains the call to process(). There it is stated what needs to be done with catch(std::exception) in this case. Here I output an error, and, as in the previous example, main() returns a 1.
