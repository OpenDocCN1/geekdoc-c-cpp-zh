
Thus, you can not move all elements of another container but also those of a range.

**Listing 24.15** For values, the container can also move.

The move_iterator created by make_iterator ensures that every a = b the element-wise initialization of target a = std::move(b). This means for string that b will contain the empty string afterward. Moving from source to target a move operation element-wise—meaning that the content of the elements is moved, not the element itself.

All containers support initialization with an initializer list and can usually deduce the template parameter for you since C++17. However, avoid the pitfalls of putting strings into the initializer list. In such a case, explicitly write vector<string> to force a conversion or use the ""s suffix for string (or even ""sv for string view).

```cpp
// https://github.com/rz/rCKG3393Ma5
#include <iostream>
vector<int> in(2,3,5,7,11);
vector<int> evens(2,4,6,8);
vector<unsigned> notLikeThis("a", 3.1, 1); // "Narrowing" double not okay
vector<string> name("are"); // converts arguments
vector<const char*> sound("move","tune"); // dangerous: vector<const char[]>
vector<string> set("rain","water"); // vector<string>
vector<string_view> cold("ice","pole sv"); // string_string view
```

**Listing 24.16** Using in initializer list to fill a vector.

## Narrowing and Initialization Lists

Narrowing is the implicit conversion of a numeric type A into another type B, where B is not capable of holding the entity range of values of A, as int to char OR to int.

In an initialization list, the compiler does not allow such conversions to protect you from typical and hard-to-find errors.

In Listing_24.15, the compiler complains that you are trying to convert the double value 4.3 into an int. The long value 8l, it does not complain because it is smart enough to realize that an int is sufficient for this. 8000000000L will allow it for a 32-bit int but not otherwise.

All standard containers can copy data from any other container when fed with iterators.

```cpp
// https://godbolt.org/z/h8Pze7ME
#include <deque>
#include <ranges>
#include <iostream>
std::deque<int> v{1,2,34,35,99};
vector<int> thirty(v.begin()+2, v.begin()+5);
for(auto e : thirty) {
    cout << e;
}

cout << "\n"; // C++20
namespace vs = std::ranges::views;
auto v = in | vs::drop(2) | vs::take(3);
vector<int> os2(v.begin(), v.end());
vector<int> trente(std::from_range, in); // C++23
```

Listing 24.17 Copy values from any other container or C-array during initialization.

Since C++20, this is also possible with the iterators of ranges and views, and from C++23 even without iterators, if you additionally pass the from_range marker to the constructor.

Specifically for vector, there are constructors that preinitialize a vector with a number of elements.

```cpp
// https://godbolt.org/z/rzdobifSk
vector<int> zeros(10); // 10 zeros
vector<int> sizes(10, 6); // 10 sizes
vector<int> ten(10); // Attention! Only one 10
vector<int> tenSix(10,6); // Attention! Two elements 10 and 6
```

Listing 24.18 Preinitializing with a fixed number of values is (almost) only available with "vector".

In these cases, you must use the round brackets () during initialization; otherwise the elements will be interpreted as an initializer list.

## Assignment

Like containers (except array), vector has overloaded the assignment operator= for copying and moving. With the help of assign, you can usually apply all initializations to a container even after construction that you can apply during the "first" initialization. Starting from C++23, you can also use assign_range.

```cpp
// https://cppbolt.org/z/Yb4jEdaki
vector<int> from{2, 3, 4};
vector<int> to=from; // Assignment with move operator, now both are the same
vector<int> drain(){
    int sink=std::move(from); // Move, 'from' is empty
    vector<int> v(100); // v is now (100, 100, ..., 100)
    v.assign(to.begin(), to.end()); // v is now (2,3,4)
    int z[] = { 10, 20, 30, 40 }; v.assign(z, z+4); // v is now (20, 30, 40)
}
```

**Listing 24.19** You can assign to "vector" or reinitialize it later with "assign".

Somehow you need to get to the data that is in the vector. There are mainly these possibilities:

- *Iterator*: You use an indirection, mainly an iterator. Because the elements are contiguous, pointers all work.
- *Beginning and end*: front and back refers to the first and last element. As the result is undefined for empty container, you must check with empty().
- *Span*: A span is easier to handle than two separate iterators or an iterator. This class has been available since C++20, and since C++23 is also the span variant. For more, see the "Access via Spans" section.

The vector container has several member functions that return an iterator, primarily begin() and end(), Just like all containers, you deference the iterator to get a reference to the actual element, as shown in Listing 24.20.

```cpp
// https://cppbolt.org/z/freak
vector<char> vowels {'a', 'e', 'i', 'o', 'u'};
const vector<char> even {'0', '2', '4', '8'}; // vector<char>::iterator
auto it1 = vowels.begin(); // *it1 = 'a';

auto it2 = even.begin(); // vector<char>::iterator
auto it3 = vowels.begin(); // const_iterator
*it2 = '5'; // error: const* is not modifiable
for(auto it1=vowels.begin(); it1!=vowels.end(); ++it1) {
    cout << *it1 << ' ';
}
for(auto it1=vowels.rbegin(); it1!=vowels.rend(); ++it1) { // despite reverse!
    cout << *it1 << ' ';
}
```

**Listing 24.20** With "begin", "end", and their relatives, you get iterators. With begin and end, you get const_iterator, which does not allow you to modify the element upon dereferencing. variants of these functions allow reverse iteration through the vector. Note that you need to increment reverse_iterator with ++ to actually iterate backward.

## Notation for "begin()", "cbegin()", "rbegin()", and "crbegin()"

To be concise, I write

- *cbegin()* for begin() and cbegin();
- *rbegin()* for rbegin() and rbegin();
- *crbegin()* for begin(), cbegin(), and crbegin().

The same applies to variants of end.

Access via iterator is universal for all containers. vector has random access—that is, via random_access_tag. In practice, you can add a positive or negative offset to a vector, as you in Listing 24.21.

```cpp
// https://cppbolt.org/z/src73
#include <vector>
#include <iostream>
#include <algorithm>
using std::vector; using std::cout; // ranges: sort
vector<int> data(data); // copied
sort(data); // C++20, otherwise std::sort(data);
auto it = data.begin();
it += data.size() / 2;
if(it == data.end()) return 0; // special case
int median = *it; // approximately the middle
if(data.size()%2 != 0) { // odd number of elements
    return median;
} else {
    return double(*it + *(it+1)) / 2; // even number of elements
}

int main() {
    vector<int> data {12, 22, 34, 10, 1, 99, 33 };
    cout << median(data) << '\n';
    vector<int> data2 {30, 2, 80, 99, 31, 3 };
    cout << median(data2) << '\n'; // 30.5
}
```

**Listing 24.21** With "vector" iterators, you can perform random access.

it points to the beginning of the vector. With m = it+sz/2, you move forward by half the vector, and m points approximately to the middle. For an odd number of elements like 7, sz/2 naturally results in 3, and it3 corresponds to data[3], which is the middle of 7 elements. If the number is even like 6, the middle lies between the elements data[2] and data[3]. m points to data[3], and (m + *(m-1)) / 2 calculates the average of the surrounding values. To ensure that the division occurs with floating-point numbers, I convert the intermediate result beforehand with double().

While every container works with iterators, only vector, array, and deque allow access to the position in the container using operator[]. (Of course, that's aside from the fact that you can also use an associative container with integers as keys.)

The foremost element always has the index zero, and the last in the container has the index size(-1).

- *Checked access*: When you access a vector with operator[](size_t idx), you immediately get back the element at the stored position—that is, in O(1). It is not allowed to access an element by size(-1) of the vector. That would be a programming error and would lead to undefined behavior. You must ensure that this does not happen in your program.
- *Checked access*: Element&at(size_t idx) is very fast, in O(1), but the library checks at runtime whether you are using an index within the allowed range of the container. If not, then it is not a programming error, but it throws an exception of type std::out_of_range.

You can use [] for both reading and on the left side of an assignment for writing the element.

In a loop, it is smart to avoid and use [], because typically the loop condition includes a check.

```cpp
// https://nppcpp.org/doc/cpp/md375
vector<int> data={1, 2, 4, -1, 2, -2};
for(size_t idx=0; idx < data.size(); ++idx) { // checks vector boundary
    cout << data[idx] << ' '; // additional check with at not necessary
    idx--; // same here
}
cout << '\n';
// Output: 1 2 -4 -1 2 -2
```

**Listing 24.22** Normally you use access with [], because you already check the boundaries elsewhere.
