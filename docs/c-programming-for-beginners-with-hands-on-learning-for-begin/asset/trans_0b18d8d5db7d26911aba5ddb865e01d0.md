## 第 7 章 最佳实践与技巧

### 7.1 编写高效且可读的代码

任何想要成功的 C 程序都必须具有可理解且高效的代码。提升可维护性和协作性可能会带来更好的性能。本节将讨论构建可理解且有效 C 代码的最佳实践和要点。

### 7.1.1 代码结构与组织

- 模块化：将代码划分为独立的函数，每个函数负责特定任务。这提高了可读性，并使维护和调试更简单。编写经过优化以有效完成单一任务的函数，而不是过于冗长的函数。
- 文件结构：逻辑地安排源文件，将实现文件和头文件分开。确保所有文件和文件夹具有一致的命名。因此，查找和理解各个项目组件的功能变得更简单。

### 7.1.2 命名特征

- 为变量使用描述性且有意义的名称，使其含义明确。不要使用晦涩或单字母名称。这使代码更易阅读和理解，从而使你和他人将来更容易理解。
- 函数命名清晰：选择能很好表达其用途的函数名。命名良好的函数消除了用冗长注释描述函数用途的必要性。当函数返回值或对象时，使用名词；对于执行操作的函数，使用动词。

### 7.1.3 一致的格式与缩进

- 一致的缩进可提高代码可读性。无论使用制表符还是空格进行缩进，都要遵循一致的风格。这有助于看清代码结构。
- 花括号位置：确保花括号位置保持一致。选择一种并在整个代码库中遵循：K&R 风格（左花括号在同一行）或 Allman 风格（左花括号另起一行）。
- 行长度：为防止水平滚动，保持行长度可控（通常在 80 到 120 个字符之间）。这增强了可读性，尤其是在并排比较代码时。

### 7.1.4 注释与记录

- 编写有洞察力的注释，阐明“为什么”而不是“是什么”。注释可以澄清设计选择或为代码提供上下文，而代码本身应当是不言自明的。
- 编写公共接口文档：为函数和库的公共接口提供清晰的文档。这包括任何副作用、返回值、输入参数和函数原型。
- 注释更新：持续更新注释以考虑代码更改。过时的注释可能会损害代码理解，并可能具有误导性。

### 7.1.5 避免魔法数字和硬编码

- 使用常量：在代码中定义具有有意义名称的常量，而不是直接使用魔法数字。这使代码更易于理解，并便于将来修改。
- 配置选项：避免将软件可能具有的任何配置选项直接硬编码到代码中。为了提高软件的灵活性，请使用配置文件或命令行选项。

### 7.1.6 处理错误

- 验证返回值：在使用任何可能失败的函数之前，务必验证其返回值。实施适当的错误处理流程，例如 errno、全局错误变量和返回的错误码。
- 在开发应用程序时考虑优雅降级以管理错误。尽可能避免突然终止程序；相反，提供描述性错误消息以便于故障排除。

### 7.1.7 应用 DRY 原则与代码复用

- DRY（不要重复自己）：避免冗余代码。相反，使用函数或宏来包含通用功能。这简化了代码维护并消除重复。
- 关注点分离：代码应划分为多个模块或层次，每个模块或层次处理特定任务。这便于扩展或修改单个组件，并鼓励代码复用。

### 7.1.8 谨慎优化

- 先分析性能：为了精确识别性能瓶颈，在优化之前对代码进行性能分析。过早优化可能不会带来任何速度优势，反而导致代码复杂且难以理解。
- 采用高效技术：针对你的问题领域，选择有效的算法。有时，算法改进比微优化产生更大的效果。

### 7.1.9 有意义的提交与版本控制

- 利用版本控制：使用 Git 等版本控制系统跟踪代码修改。为了跟踪软件的开发，定期使用有洞察力的提交说明提交更改。
- 将分支用于实验性或特定功能开发是分支和标记代码的好方法。为了标识程序的可靠版本，请为发布打标签。

### 7.1.10 测试驱动开发（TDD）与测试

- 创建单元测试：实施单元测试以确认各个组件或函数是有效的。自动化测试有助于在开发过程中及早发现回归。
