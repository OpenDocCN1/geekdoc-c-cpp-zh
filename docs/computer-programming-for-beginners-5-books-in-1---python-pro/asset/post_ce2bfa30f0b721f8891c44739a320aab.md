
The intended callback function is called when the promise resolves and provides a value. You can attach several callbacks to an individual promise, and they will all be called, even if they were attached when the promise has been completed. The then method also sends back another promise that resolves to the value that the handler function returns. It is important to see promises as a device to turn values into an asynchronous reality. A promised value is a value that could be there or could appear at a certain point in the future. Computations described in terms of promises work on enclosed values and are performed asynchronously as the values become available. To build a promise, use the Promise constructor. It contains an odd layout, and the constructor expects a function as an argument, which it calls instantly, passing it a function that can be used to resolve the promise.

It is how to build a promise-based layout for the readStorage function:

```
function storage(nest, name) {
  return new Promise(resolve => {
    nest.readStorage(name, result => resolve(result));
  });
}
storage(bigOak, "enemies")
  .then(value => console.log("Got", value));
```

This asynchronous function returns a meaningful value.

## Failure

JavaScript computations can fail by throwing an exception. A network request could fail, or some asynchronous code computation could throw an exception. The most consistent issue with asynchronous programming in callback style is that it makes it very hard to ensure failures are revealed correctly to the callbacks. A widely used convention is that the first argument to the callback is used to indicate failure, and the second has the value provided by the action when it completes. Such callback functions always check whether they received an exception and ensure that any arising problems, including exceptions thrown by functions they call, are given to the correct callback. They can resolve when it completes successfully or be rejected when it fails. Resolve handlers (as registered with then) are called only when the task completes successfully, and rejections automatically propagate to the returned new promise. And when a handler throws an exception, this automatically causes the promise produced by its call to be rejected. When an element in a chain of asynchronous actions fails, the outcome of the whole chain is rejected and no success handlers are called past the failing point. Much like resolving a promise produces a value, rejecting one also provides one, often called the rejection reason. If an exception in a handler function creates the rejection, the exception value is used as the reason. Similarly, when a handler returns a rejected promise, that rejection goes into the next promise. There’s a Promise.reject function that creates a new, immediately rejected promise.

If a catch handler throws an error, the new promise is likewise rejected. As a shorthand, then also takes a rejection handler as a second argument, so you can install the two types of handlers in a single method call. A function sent to the Promise constructor receives a second argument, along with the resolve function, which it can use to reject the new promise. The chains of promise values created by calls to then and catch can be seen as a pipeline through which asynchronous values or failures move. Because those chains are built by registering handlers, every link consists of either a success handler or a rejection handler related to it. Handlers that do not match the type of outcome are ignored. But those that match are called, and their output decides what type of value comes next: success when it returns a non-promise value, rejection when it throws an exception, and the result of a promise when it returns one of those.

```
new Promise((_, reject) => reject(new Error("Fail")))
.then(value => console.log("Handler 1"))
.catch(reason => {
console.log("Caught failure " + reason);
return "nothing";
})
.then(value => console.log("Handler 2", value));
// → Caught failure Error: Fail
// → Handler 2 nothing
```

## Networks are hard

Periodically, there’s very little light for the crows’ mirror systems to convey a signal, or something is obstructing the way of the signal. It is possible for a signal to be transmitted but get lost. Often, transmission failures are random accidents, like a car’s headlights obstructing the light signals, and resending the request could make it succeed. So, let’s define our request function, and consequently retry sending the request a few times before giving up. And, since we have established that promises are good, we’ll also ensure our request function sends back a promise. When it comes to what they can express, promises and callbacks are equivalent. Callback-based functions can be wrapped to expose a promise-based interface and vice versa. Even when a request and its reply are transmitted successfully, the reply could indicate failure, for instance, if the request tries to use a request type that has not been defined or the handler throws an error. To aid this, send and defineRequestType follow the convention declared earlier, where the first argument sent to callbacks is the reason for failure, if any, and the second is the definite result. They are translated to promise resolution and rejection by our wrapper.

```
class Timeout extends Error {}
function request(nest, target, type, content) {
  return new Promise((resolve, reject) => {
    let done = false;
    function attempt(n) {
      nest.send(target, type, content, (failed, value) => {
        done = true;
        if (failed) reject(failed);
        else resolve(value);
      });
      setTimeout(() => {
        if (done) return;
        else if (n < 3) attempt(n + 1);
        else reject(new Timeout("Timed out"));
      }, 250);
    }
    attempt(1);
  });
}
```

Because promises can be resolved or rejected only once, it will work. The first call to resolve or reject decides the result of the promise, and any other calls are disregarded. To create an asynchronous loop for the retries, use a recursive function; an ordinary loop does not allow us to stop and wait for an asynchronous action. The attempt function makes a single attempt to transfer a request. It also sets a timeout that, if there is no response after 250 milliseconds, begins the next attempt or, if it is the fourth try, rejects the promise with an instance of Timeout as the reason. Retrying each quarter-second and stopping when there is no response after a second is certainly arbitrary. If the request does come through, but the handler takes longer, the request may be transferred several times. Create your handlers with that problem in mind; duplicate messages are not harmful. To isolate ourselves from callbacks totally, define a wrapper for defineRequestType that enables the handler function to return a promise or simple value and wires up the callback for us.

```
function requestType(name, handler) {
  defineRequestType(name, (nest, content, source, callback) => {
    try {
      Promise.resolve(handler(nest, content, source))
        .then(response => callback(null, response),
              failure => callback(failure));
    } catch (exception) {
      callback(exception);
    }
  });
}
```

Promise.resolve is used to transform the value returned by the handler into a promise if it is not already one.

## Collections of promises

Every nest computer stores an array of other nests within transmission distance in its neighbors property. To examine which are reachable, write a function that tries to transfer a "ping" request (a request that demands a response) to all of them and checks which ones come back. If you're working with a group of promises running at once, the Promise.all function is very important. It sends back a promise that waits for all of the promises in the array to resolve and then settles to an array of the values that these promises provided. If any promise is rejected, the result of Promise.all is also rejected.

```
requestType("ping", () => "pong");
function availableNeighbors(nest) {
  let requests = nest.neighbors.map(neighbor => {
    return request(nest, neighbor, "ping")
      .then(() => true, () => false);
  });
  return Promise.all(requests).then(result => {
    return nest.neighbors.filter((_, i) => result[i]);
  });
}
```
