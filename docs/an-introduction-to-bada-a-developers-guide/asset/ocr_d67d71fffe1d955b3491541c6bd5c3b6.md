# The Recipe

The following configuration is required for this recipe:

**Namespaces used:**
Osp::Social, Osp::Social::Services

**Header files to #include:**
FSocial.h

**Required libraries:**
FSocial, FSocialServices

**Required privilege level:**
System

**Required privilege groups:**
BUDDY_SERVICE

This recipe uses the Osp::Social and Osp::Social::Services namespaces to provide access to the social features of bada. It is a more detailed implementation of the request for a buddy presented in Chapter 5. There are some prerequisites to using this feature in your application. First, your application profile has to be registered with System-level privilege on the bada developer web site. Second, you have to have a valid Samsung account, which you get for free, and sign in.

There are two steps to adding a buddy:

+   1. Search the profile by passing a name, email address or login ID using the ProfileService class.
+   2. Send the buddy request to that particular user using the BuddyService class. To use these two classes, you have to implement the listener interface class to handle the results received from the bada Server.

Let's first implement our own listener class called MyListener. In a concrete project, you would probably use one of your UI classes, in which you want to display the results from the server, as your listener. This would mean that your UI class would inherit from the IProfileServiceListener and IBuddyServiceListener interfaces. But you can also have your own class to handle the results, as we show below.

```
//MyListener class implementation
class MyListener :
    public Osp::Social::Services::IProfileServiceListener,
    public Osp::Social::Services::IBuddyServiceListener
{
public:
    MyListener();
};
```
