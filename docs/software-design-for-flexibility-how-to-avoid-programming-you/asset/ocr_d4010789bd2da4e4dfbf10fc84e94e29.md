# A Language of (?) Patterns

The first job is to make up our language of patterns. We will start with something simple. We will make our patterns out of Lisp (Scheme) lists. Unlike the mathematical example above, we will not have reserved symbols, such as and +, so we will have to distinguish pattern variables from pattern constants. A pattern variable can be represented by a query symbol, ?. This is a traditional choice. So in this language the patterns that make up the distributive law may be represented as follows, assuming that we are manipulating Lisp prefix mathematical expressions:

```
* (* ? a) (? b) (? c))
(+ (* ? a) (? b)) (* ? a) (? c))
```

You might complain that we could have distinguished symbols, such as a instead of the long-wind (? That would be fine, but that choice would make it a bit harder to extend, say if we want a variable that is restricted to only numbers. Of course, we can add syntax later if it is helpful, remember Alan Perlis's maxim: "Syntactic sugar causes cancer of the semicolon." With our simple list representation we are able to restrict the pattern variable (??) to match only numbers by adding the predicate describing the restriction to its list representation: (? a ,number?).

One constraint on our design of the matcher is the second pattern above match

```
+ (* (cos x) (exp y)) (* (cos x) (sin z))
```

where a=(cos x),b=(exp y), and c=(sin z).
But it should not match

```
+ (* (cos x) (exp y)) (* (+ x y) (sin z))
```

because there is no consistent assignment possible for (? a), unless, somehow, x=(+ x y).We will learn about that sort of situation when we use unification matching in section 4.4; here we will decide that there is no match possible.
