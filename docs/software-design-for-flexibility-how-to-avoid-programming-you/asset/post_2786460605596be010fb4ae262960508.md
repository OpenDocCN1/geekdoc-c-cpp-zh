One to write restrict-arity and get-arity is as follows:

```scheme
(define (restrict-arity proc nargs)
  (hash-table-set! arity-table proc nargs)
  proc)
```

```scheme
(define (get-arity proc)
  (or (hash-table-ref/default arity-table proc #f)
      (let ((a (procedure-arity proc)); arity not in table
        (assert eqv? (procedure-arity-min a)
          (procedure-arity-max a))
        (procedure-arity-min a))))
  arity-table (make-key-eqv-hash-table))
```

We are using a hash table to attach a "sticky note" to the procedure. This is a simple trick for adding information to an existing object, but it depends on the uniqueness of the object being annotated, so it should be used carefully.

If the procedure get-arity is unable to find an explicit value in arity-table, it computes using primitives from the MIT/GNU Scheme system. This involves some hair, because those primitives support a more general idea of arity: that a procedure requires a minimum number of arguments, and may have an optional maximum number of arguments. Our code expects an arity to be a fixed number of arguments, and so get-arity cannot work with any other kind of procedure. Unfortunately, this excludes procedures like + that take any number of arguments.

Changing the arity code to use a more general notion of arity would complicate it, and our goal here is to have a clear exposition rather than a general solution (see exercise 2.2).

## Multiple values

Notice that parallel-combine and spread-combine are similar in that each is the application of a combiner h to the results of f and g. But we did not use compose to construct these combinators. To abstract this pattern we need to be able to return multiple values from the combination of f and g and then use those values as arguments for h. We could do this by returning a compound data structure, but a better way is to use the Scheme multiple-value return mechanism. Given multiple values we can define spread-combine as a composition of two parts, h and it of f and g;⁵

```scheme
(define (spread-apply f g)
  (let ((n (get-arity f)) (m (get-arity g))
    (let ((t (+ n m)))
      (define (the-combination args)
        (assert (= (length args) t))
        (values (apply f (list-head args n))
              (apply g (list-tail args n))))
      (restrict-arity the-combination t))))))
```

The first part, *spread-apply*, is the combination of the functions f and g with the correct arguments routed to them. The second part is the combiner h, which is just composed with the first part. The Scheme procedure values returns the results of applying both f and g.^6

Now we can generalize even further. We can allow all of the functions we are combining to return multiple values. If f and g both return multiple values we can combine those values into multiple values that the-combination can return:

```scheme
(define (spread-apply f g)
  let (n (get-arity f)) (m (get-arity g))
    (let (t (+ n m))
      (define (the-combination args)
        (assert (= (length args) t))
        (let-values (fv f (list-head n))
          (gv apply g (list-tail args))
            (apply values (append fv gv)))
      (restrict-arity the-combination t))))

  (lambda (x y) (values x y))
  (lambda (u v w) (values u v w)))

(a b d c)
```

## A small library

Many common patterns of usage can be captured as combinators, and very pretty programs are often constructed using such techniques. It is to our advantage to expose and abstract such patterns. Here are a few more to think about.

Often we have an interface that is more general than necessary in a particular situation. In such a case we may want to preserve the interface, but call some more specialized procedure that does not need all of the parameters we supply in the general case; so we choose to make a version of our specialized procedure that ignores some arguments.

The procedure discard-argument takes the index, i, of the argument to be discarded and returns a combinator. The combinator takes a function, f, of n arguments and returns a new function the-combination of $n+1$ arguments that applies f to $n$ given resulting from deleting the ith argument from the $n+1 arguments.
