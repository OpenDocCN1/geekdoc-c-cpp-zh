### 4.5 Pattern matching on graphs

The pattern matching we developed so far is for matching list structures. Such structures are excellent for representing expressions, such as algebraic expressions or abstract syntax trees. However, pattern matching can be used to make systems that operate on a wider range of data. If the structure of interest can be characterized by an accessibility relation, it may be appropriate to describe the structure as a graph of “places” and edges representing how the places are interconnected. A circuit is an example of such structure, where parts are places and the accessibility relation is just the description. A board game like chess or checkers is another, where squares may be represented by nodes in a graph.

We implement a graph as a collection of nodes and edges. Our graphs are immutable in the sense that once a node or edge is added, it cannot be modified; the graph can be changed only by adding more nodes and edges. This will have consequences that we will see in section 4.5. A node contains a collection of edges, and an edge is a combination of label and value. The label of an edge is a unique object, usually a symbol or a number. The value of an edge is another node or a promise. This implementation will work with concrete graphs (where all of the nodes and edges are available at the time we build the graph) and lazy graphs (where the graph is extended as necessary at the time of access). We will first look at a simple example to see how graphs work. We will then use an extended example to explore complex uses of graphs and pattern matching on graphs.

### 4.5.1 Lists as graphs

We start with the simple but familiar world of lists. Cons cells are the nodes, which will be made with `g:cons` and whose car and cdr will be implemented as edges labeled with car and cdr.

```scheme
(define (g:cons car cdr)
  (let ((pair make-graph-node 'pair))
    (pair connect! car)
    (pair connect! cdr)))
```

```
(define (g:car pair) (pair 'edge-value 'car))
(define (g:cdr pair) (pair 'edge-value 'cdr))
```

To represent lists as graphs we need a special marker for lists:

```scheme
(define nil (make-graph-node 'nil))
(define (g:null) nil)
(define (g:null? object) (eqv? object nil))
```

The conversion of a list to a graph is:

```scheme
(define (list->graph list)
  (if (pair? list)
    (g:cons (car list) (list->graph (cdr list)))
    (g:null)))
```

And a simple example works as expected:

```scheme
(define g (list->graph '(a b c)))
(and eqv? 'a (g:car g))
    (eqv? 'b (g:car (g:cdr g)))
    (eqv? 'c (g:car (g:cdr (g:cdr g))))
    (g:null? (g:cdr (g:cdr g)))))
```

We can modify the `list-graph` constructor to allow lazy graphs, nodes that are created as edges traversed:

```scheme
(define (list->lazy-graph list)
  (if (pair? list)
    (g:cons delay (car list))
    (delay (list->lazy-graph (cdr list))))
  (g:null)))
```

Here we use the Scheme `delay` to construct a promise that will evaluate the (postponed) expression when the promise is forced. Streams lazy lists are usually constructed using `delay` and `force`.

### 4.5.2 Implementing graphs nodes

We have to be able to make graph nodes and connect them to other nodes by edges. We will represent a graph node as a bundle procedure: a collection of delegate procedures that can be called by name.

```scheme
(define make-graph-node name)
  (let ((edges '()))
    (define (get-name) name)
    (define (all-edges) (list-copy edges))
    (define (%find-edge label)
      (find (lambda (edge)
        (eqv? label (edge 'get-label)))
      edges))
    (define (has-edge? label)
      (and (%find-edge label) #t)) ; boolean value
    (define (get-edge label)
      (let ((edge (%find-edge label)))
        (if not edge)
          (error "No edge with this label:" label)
          edge))
    (define (edge-value label)
      ((get-label) 'get-value))
    (define (connect! label value)
      (if (has-edge? label)
        (error "Two edges with same label:" label))
        (set! edges (cons (make-graph-edge label value) edges)))
    (define (maybe-connect! value)
      (if (not (default-object? value))
        (connect! label value))))
  (bundle graph-node? get-name all-edges has-edge?
    (make-graph-edge label value) connect! edge-value maybe-connect!)))
```

The argument to `make-graph-node` is the name of the new node; this is shown when printing a node object. The first argument to the bundle macro is a predicate that the generated bundle will satisfy. In this case, it is defined as

```scheme
(define graph-node? (make-bundle-predicate 'graph-node))
```

We will not show the definitions of other bundle predicates since they are similar.

Edges are also represented as bundle procedures. An edge may have a concrete value or the value may be a promise (constructed by delay) to produce the value when asked. The latter provides for lazy graph structures.

```scheme
(define (make-graph-edge label value)
  (define (get-label) label)
  (define (get-value))
```
