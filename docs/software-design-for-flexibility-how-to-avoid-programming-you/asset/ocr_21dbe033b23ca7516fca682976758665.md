We want the players to have different views of the board graph: we want the meanings of the edge labels to be relative to the player. If the player playing White sees a north edge from (the node representing) square to square B we want the player playing Black to see a north edge from square B to square A.

To make this work we introduce graph views. A graph view is a reversible mapping from one edge to another. When a graph view is applied to a node, it returns a copy of that node in which the edges are renamed.

In the case of chess relevant view it is with the board rotated 180 degrees:

```
(define rotate-180-view
(make-graph-view inverse rotate-180 rotate-180))
```

where make-graph-view makes a graph view. The procedure graph-node-view applies a a node to:

```
(graph-node-view node view)
```

White will see a node directly and Black will see the same node projected through the rotate-180-view. Given this map, all operations look to the same to both White and Black.

Using a graph view takes care of relative addressing, where we are looking at neighbors of a given node. We also need to do absolute addressing, where the node to find is specified by a row and column.
