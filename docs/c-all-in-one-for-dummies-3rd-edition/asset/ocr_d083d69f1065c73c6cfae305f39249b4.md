This line would appear after you're finished using a pointer that you allocated by using new. (Like the new operator, delete is also an operator and does not require parentheses around the parameter.)

The FreePointer example, shown in Listing 7-10, provides a complete demonstration of allocating a pointer, using it, and then freeing it.

# Listing 7-10: Using delete to Clean Up Your Pointers

```
```cpp
#include <iostream>

using namespace std;

int main()
{
    string *phrase = new string("All presidents are cool!!!");
    cout << *phrase << endl;

    (*phrase)[20] = 'r';
    phrase->replace(22, 4, "oked");
    cout << *phrase << endl;

    delete phrase;
    return 0;
}
```
```

When you run this application, you see the following output:

```
```text
All presidents are cool!!!
All presidents are crooked
```
```

In this code, we first allocated a new string and initialized it, saving its address in the pointer variable called phrase. Then we wrote the phrase, manipulated it (providing some editorial content), and then wrote it again. Finally, we freed the memory used by the pointer.

![](bbox=[0.156, 0.677, 0.229, 0.752])

Although people usually say that you’re deleting the pointer or freeing the pointer, really you’re freeing the memory that the pointer points to. The pointer can still be used for subsequent new operations. Nevertheless, we will abide by tradition and use these phrases.

![](bbox=[0.156, 0.761, 0.229, 0.834])

You can actually get away with not freeing your pointers because the computer frees all the memory used by your application when it ends. That way, your memory is available to all the other cool applications you want to run. However, getting into the habit of freeing your pointers when you are finished using them is a good practice; otherwise, you may use all the memory allotted for the heap while your application is running. And some big software systems at big companies run on and on, shutting down maybe once a week or every two weeks. If one part of the application continues to refuse to free its data, eventually the heap probably fills and the whole application shuts down.
