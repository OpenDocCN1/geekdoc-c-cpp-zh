# Understanding main()

All applications so far in this chapter have had a `main()`. This `main()` is actually a function. Notice its header, which is followed by code inside braces:

```
int main()
```

You can see that this is definitely a function header: It starts out with a return type and then the function name, `main()`. This is just one form of the `main()` function — the form that Code::Blocks uses by default. However, you may decide that you want to give users the ability to provide input when they type the name of your application at the console. In this case, you use this alternative form of the `main()` function that includes two parameters:

```
int main(int argc, char *argv[])
```

# Who, what, where, and why return?

The `main()` function header starts with the type `int`. This means that the function `main()` returns something. But what? And to whom? And why when and all those words?

The result of `main()` is sometimes used by the computer to return error messages if the application, for some reason, didn’t work or didn’t do what it was supposed to do. But here’s the inside scoop: *Outputting a return value just doesn’t work* — at least, not in the graphical environment that most people use.

It’s true. For many computers, particularly Windows computers, the return value is of little use to anybody. The return type is specifically designed to work with batch files (files with a BAT extension that originally appeared as part of DOS, or Disk Operating System). Consequently, unless you plan to work with batch files (and many people still do), just return `0`.
