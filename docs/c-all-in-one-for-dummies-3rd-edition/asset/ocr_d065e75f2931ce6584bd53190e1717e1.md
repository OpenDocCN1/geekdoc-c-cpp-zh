The previous chapters in this book focus on the Unified Modeling Language (UML) and how you use it to better model applications. Chapter 6 moves on to design patterns, which actually help you implement a model. This chapter takes the process one step further by looking at lambda expressions — an elegant method of turning a model into a math expression. Let’s say that you need to calculate the number of widgets produced in an hour before you can print out the value. Adding the equation directly to the existing code might look bulky, but adding it as a separate function makes the code hard to read. Lambda expressions provide a middle ground where you can define the calculation in an easy-to-read manner without creating a separate function.

Unlike many of the odd terms you’ve encountered so far in the book, we programmers have nothing to do with the term lambda expression — you can blame it on the mathematicians, for once! It’s actually a kind of calculus that was introduced by Alonzo Church in the 1930s and it’s used as short-hand for complex equations. The equations are anonymous — that is, they aren’t given a name.

For once, the programming version of something found in math is actually easier to understand and use than what Alonzo Church created. We’ll show you how to use lambda expressions to define simple functions that you only need to use in one place. They don’t need a name because you won’t use them again. It’s sort of a disposable function and they come in really handy for those times when you need to do something simple, but you want to separate it from the main function. Think of lambda expressions as a kind of function within a function (a nested function).

Lambda expressions aren’t usable as part of earlier versions of C++. In order to work with most of the examples in this chapter, you must configure the project to use C++ 11. If you don’t perform the required configuration, you see an error message when you attempt to compile the example.
