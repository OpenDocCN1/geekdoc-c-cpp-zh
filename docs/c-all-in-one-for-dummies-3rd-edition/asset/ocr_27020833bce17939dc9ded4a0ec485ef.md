# Obtaining Standard Library UDL support

Adding UDLs to the Standard Library is a new feature for C++ 14. In order to actually see this feature at work, your compiler must support all of the C++ 14 additions. Because some of these features require time to implement, your C++ compiler may not provide all of the standardized features, even if it purports to provide C++ 14 support.

The GCC 4.7.1 compiler used throughout most of this book doesn’t provide the required UDL support. However, one approach shows how to simulate such support if you need it immediately. The GCC 4.8.1 compiler, which is currently unstable, provides some C++ 14 support.

Support, however, in order to obtain full support, you must wait for the upcoming GCC 4.9 compiler.

Other compiler vendors are also creating the support required to fully implement C++ 14. For example, you can find the required support in the upcoming Clang 3.4 distribution. Visual C++ 2013 also includes some level of C++ 14 support, but Microsoft is currently working to implement C++ 14 fully. The bottom line is that you must ensure that your compiler actually provides the C++ 14 language support you need before these new UDL features will work.

In C++ 14, the Standard Library includes built-in literal support for basic_string. All you need to do is add the suffix s to a string to create one. However, it’s important to get an idea of how all this works behind the scenes. The BasicString example in Listing 2-3 demonstrates three techniques for creating a basic_string object.

```cpp
#include <iostream>
#include <typeinfo>

using namespace std;

string operator""_s(const char * str, unsigned len)
{
    return string(str, len);
}

int main()
{
    basic_string<char> StdString = "This is a standard string.";
    auto AutoString = "This is an auto string."_s;

    // Remove comment when your compiler supports C++ 14.
    //auto UDLString = "This is a UDL string."_s;

    cout << StdString << endl << typeid(StdString).name() << endl;
    cout << AutoString << endl << typeid(AutoString).name() << endl;
}
