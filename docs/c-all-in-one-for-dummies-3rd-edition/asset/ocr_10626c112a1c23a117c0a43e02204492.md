And newer versions of most operating systems understand laptop computers: When the battery is just about to be completely drained, the operating system saves the entire state of the machine to a giant file on the hard drive and shuts down. This is called *hibernation*. So these aren’t bugs, after all. We guess we can close up that bug report we just sent to the vendor.

Now consider this: Suppose that you’re using an application that we won’t name here, and in the middle of it, you get a message box that says something like `Exception Error`, and the application simply closes. All your work is lost. So you call tech support, and the helpful friend on the other end says, “You must have typed something it didn’t like. This application has a built-in protection scheme whereby if you type something you’re not supposed to, it shuts down.”

Oh, yeah. We get it. That’s when the guy says, “It’s a *feature*, not a bug!” Tell me another one. But sometimes situations walk the fine line between bug and feature. We don’t think that an application crashing could be considered a feature, but consider this instead: When your browser messes up, a message asks whether you want it to send the vendor a trouble report. *That’s* a feature that handles bugs.

But the unnamed application that shut down definitely has a bug. And other applications have bugs. For example, we have been quickly switching between browser windows, typing, resizing, doing things quickly as we go back and forth between the windows (too much caffeine, perhaps), when suddenly the thing crashes and we see the trouble-report message. *That really was a bug:* The application choked when we, the user, *did something that the programmers did not anticipate.*

Now, why did the application choke? Well, in addition to what we did that the programmers hadn’t expected, it’s possible that the programmers simply messed up. Either they didn’t include code to handle a rough situation (rapidly switching, resizing — that sort of thing), or perhaps they wrote code that did something wrong, such as free a pointer but then continue to use the memory address.

Here’s an example of programmers not expecting something. Suppose that we’re writing an application that reads a number from the console. You should type a single character for your first choice and then type another character for your second choice. The code might look like this:

```
char x, y;
cout << "Enter your first choice" << endl;
cin >> x;
cout << "Enter your second choice" << endl;
cout << x << endl;
cin >> y;
cout << y << endl;
```
