
Because `Exclude` appears within the square brackets, the lambda expression can use it to perform the comparison. When you run this example, you see the following output:

```
1
2
4
```

![](img/6ba99460b0feb3585671a4612ff5fabb_627_0.png)

Notice that the value of 3 is excluded from the output because this is the value passed as part of the call to `ProcessVector()`. When you provide a different value, a different number is removed from the output. The main purpose of the capture clause is to provide a means of passing additional information to the lambda expression to aid in processing the data it receives.

### Sorting data using a lambda expression

One of the most common tasks that applications must perform before presenting data to the user is placing it in some sort of sorted order. Although a computer can easily locate a specific value in a long list of values, even if that list isn’t sorted, users are quite different. The longer the list, the more important it becomes to present the information in a particular order.

![](img/6ba99460b0feb3585671a4612ff5fabb_627_1.png)

At one time, developers had to create their own sorting algorithms for every need; the topic of sorting received more than a little emphasis in computer science classes. Today, however, a developer only needs to worry about sorting algorithms when a specific kind of sort is needed. The `sort()` algorithm used by itself will perform most generic sorting tasks. However, you still need a custom sorting method to perform specialized sorts, such as when you’re working with a structure or complex data.

For the sake of simplicity, it’s easiest to review sorting using a simple vector. The `Sorting` example in Listing 7-8 performs both a standard sort and a custom sort on the same vector.

### Listing 7-8: Sorting Data Using a Lambda Expression

```cpp
#include <iostream>
#include <algorithm>
#include <vector>

using namespace std;

void StandardSort(vector<int>& vect)
{
    sort(vect.begin(), vect.end());
    cout << "Using the Standard Sort" << endl;
    for_each(vect.begin(), vect.end(), [](int x){ cout << x << endl;});
}

void ProcessVector(vector<int>& vect)
{
    sort(vect.begin(), vect.end(), [](int S1, int S2){return S1 < S2;});
    cout << "Using a Custom Sort" << endl;
    for_each(vect.begin(), vect.end(), [](int x){cout << x << endl;});
}

int main()
{
    vector<int> MyVector;
    MyVector.push_back(11);
    MyVector.push_back(2);
    MyVector.push_back(33);
    MyVector.push_back(4);

    StandardSort(MyVector);
    ProcessVector(MyVector);
}
```

![](img/6ba99460b0feb3585671a4612ff5fabb_628_0.png)

Look at the StandardSort() function first. When an application calls sort(), it places the resulting data in the same object that it received. At first, vect contains unsorted data. However, after the call to sort(), the data is sorted using a generic sorting method. Notice that you don't need a lambda expression to perform a generic sort.

The ProcessVector() function looks almost the same as StandardSort(). The difference is that this function relies on a lambda expression to perform a custom sort. Sorting is a process of comparing one value to another, so the lambda expression receives two inputs, S1 and S2. By knowing which value is greater, sort() can determine where to place the two values in the list.

The result is the same in both cases. Here is what you can expect to see from the example as written.

```
Using the Standard Sort
2
4
11
33
Using a Custom Sort
2
4
11
33
```

Of course, this might lead you to believe that vect remains sorted. As an experiment, change return S1 < S2 to read return S1 > S2. Try the example again and you see that the lambda expression approach lets you present the data in reverse order.

```
Using the Standard Sort
2
4
11
33
Using a Custom Sort
33
11
4
2
```

### Specifying that the lambda expression throws exceptions

An exception is an indicator of an unexpected occurrence within an application. The occurrence could be due to an error, such as someone sending a function an incorrect value. However, the occurrence could just as easily be due to a loss of a network connection or a full disk drive. The important consideration here is that the occurrence is unexpected — that the application couldn’t automatically check for the potential problem and proactively compensate for it.

The process of indicating the unexpected occurrence is called *throwing an exception*. Lambda expressions can throw any sort of exception required to indicate an error condition. However, there are methods of indicating the precise sort of exception that a lambda expression might throw. By indicating the kind of exception, you make it possible for the compiler to optimize the lambda expression and make it faster — more efficient.

![](img/6ba99460b0feb3585671a4612ff5fabb_629_0.png)

In some cases, a lambda expression never throws an exception. Perhaps the functionality it provides is quite simple and there literally isn’t anything that can go wrong in the sense of generating an exceptional condition. When this is the case, you add the `throw()` clause to the lambda expression as shown here.

```cpp
auto myLambda = []() throw() { return true; };
```

It’s far more likely that your lambda expression will throw a specific exception. For example, the input may be outside the range the lambda expression expects and there isn’t any good way to compensate for this condition. Even in this situation, telling the compiler specifically which exception the lambda expression will throw allows the compiler to better optimize the code — making it faster. The Exceptions example in Listing 7-9 shows just such a situation.

First things first. We've all heard of rivers and lakes and streams, and it's interesting just how many common words are used in computer programming. That's handy, because it lets us use words we already know with similar meaning, but it's also a bummer because it's harder to impress strangers. While we don't have gluggerbumbles and picklershops in computer programming — words most people have never even heard of, mainly because we made them up — we do have *streams*!

Most programmers think of a stream as the same thing as a file. You know — a file that's stored on your hard drive or maybe on a Universal Serial Bus (USB) flash drive or Secure Digital (SD) card. But streams go beyond just files. A *stream* is any type of data structure that you *stream* (that is, flow) your data into and out of in a sequence of bytes.

For example, if we open an Internet connection to a top-secret computer that stores all our top-secret data (oooh), and we start putting our data on the remote computer, we might use a stream-based data structure. By that we mean we write the data in sequence, one byte after another, as the data goes over the Internet like a stream of water, reaching the remote computer. The data we wrote first gets there first and so on.

You can use the same approach for storing data into a file. Rather than just filling a huge 500MB data structure and then dropping it onto the hard drive, you write your data piece after piece; the information goes into the file.

In this chapter, we talk about different kinds of streams available to you, the C++ programmer.
