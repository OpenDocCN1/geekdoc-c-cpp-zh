Regardless of whether the code uses the "Parse" or "TryParse" approach, the key caution about converting from a string to an enum is such that a cast is not localizable. Therefore, developers should use this type of cast only for messages that are not exposed to users (assuming localization is a requirement).

# Guidelines

+   AVOID direct enum/string conversions where the string must be localized into the user's language.

Many times, developers not only want enum values to be unique but also want to be able to represent a combination of values. For example, consider System.IO FileAttributes. This enum, shown in Listing 9.35, indicates various attributes of a file: read-only, hidden, and so on. Unlike the ConnectionState attribute, where each enum's values were mutually exclusive, the FileAttributes enum values can be, and are, intended for combination: A file can be both read-only and hidden. To support this behavior, each enum member's value is a unique bit.

Listing 9.35: Using Enums as Flags

```
[Flags]
public enum {
    None = 0,                          // 000000000000
    ReadOnly = 1 << 0,                 // 000000000001
    Hidden = 1 << 1,                   // 000000000010
    System = 1 << 2,                  // 000000000100
    Directory = 1 << 4,               // 000000010000
    Archive = 1 << 5,                // 000000100000
    Device = 1 << 6,                  // 000010000000
    Normal = 1 << 7,                  // 000100000000
    Temporary = 1 << 8,              // 001000000000
    SparseFile = 1 << 9,             // 010000000000
    ReparsePoint = 1 << 10,          // 100000000000
    Compressed = 1 << 11,            // 110000000000
    Offline = 1 << 12,               // 100000000000
```
