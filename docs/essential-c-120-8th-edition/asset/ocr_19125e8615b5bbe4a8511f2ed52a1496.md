# Chapter 1: Introducing C#

There was a period in programming history when a prolific set of comments implied a disciplined and experienced programmer. This is no longer the case. Instead, code that is readable without comments is more valuable than that which requires comments to clarify what it does. If developers find it necessary to enter comments to clarify what a block of code is doing, they favor rewriting the code more clearly over commenting it. Writing comments that simply repeat the code clearly serves only to clutter the code, decrease its readability, and increase the likelihood of the comments going out of date because the code changes without the comments updating.

> Guidelines
DO NOT use comments unless they describe something that is not obvious to someone other than the developer who wrote the code.
DO favor writing clearer code over entering comments to clarify a complicated algorithm.
