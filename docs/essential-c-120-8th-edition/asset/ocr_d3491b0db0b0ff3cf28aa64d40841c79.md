A common pattern enabled by concurrent collections is support for thread-safe access by producers and consumers. Classes that implement IProducerConsumerCollection<> (identified by an asterisk in Table 22.4) are specifically designed to provide such support. This enables one or more classes to pump data into the collection while a different set of classes reads it, removing the data. The order in which data is added and removed is determined by the individual collection classes that implement the IProducerConsumerCollection<> interface.

Although it is not built into the out-of-the-box .NET Core Frameworks, an additional immutable collection library is available as a NuGet package reference, called System.Collections.Immutable. The advantage of the immutable collection is that it can be passed freely between threads without concern for either deadlocks or interim updates. As immutable collections cannot be modified, interim updates won't occur; such collections are automatically thread safe (so there is no need to lock access).
