There are two basing formats for an identifier. Pascal case (hence PascalCase), the .NET framework creators refer to because of its popularity in the Pascal programming language, capitalizes the first letter of each word in an identifier name; examples include ComponentModel, Configuration, and HttpClientCollection. As HttpClientCollection demonstrates with HTTP, when using acronyms that are more than two letters, only the first letter is capitalized. The second format, camel case (hence camelCase) follows the same convention except that the first letter is lowercase; examples include quotient, firstName, HttpClientCollection, ioStream, and theDreadPirateRoberts.

# Guidelines

+   - DO favor clarity over brevity when naming identifiers.

+   - DO NOT use abbreviations or contractions within identifier names.

+   - DO NOT use any acronyms unless they are widely accepted, in which case you use them consistently.

Notice that although underscores are legal, generally there are no underscores, hyphens, or other nonalphanumeric characters in identifier names. Furthermore, C# doesn't follow its predecessors in Hungarian notation (prefixing a name with a data type abbreviation) is not used. This convention avoids the variable rename that is necessary when data types change, or the inconsistency introduced by failure to adjust the data type prefix using Hungarian notation.

In rare cases, some identifiers, such as Main, can have a special meaning in C# language.

While naming guidelines may seem relatively trivial, especially when coming from other languages where such guidelines are ambiguous or missing entirely, violations of these guidelines will be glaring to an experienced C#.NET programmer and indicate poor quality or inexperience. To avoid this, learn the guidelines, and follow them religiously.
