## Constant Patterns (C# 7.0)

In Chapter 4, we demonstrated constant patterns when using the is operator to check for null (i.e., data is null) and not in explaining the basic switch statement (https://essentialcsharp.com/the-basic-switch-statement). The principle is that you can compare the input operand against any constant. You could, for example, compare data.Day with the value 21. Listing 7.23 provides both is and switch expression examples.

LISTING 7.23: Constant Pattern Matching with is Operator

```csharp
using System.Diagnostics.CodeAnalysis;
public static class SolsticeHelper
{
    public static bool IsSolstice(DateTime date)
    {
        if (date.Day is 21)
        {
            if (date.Month is 12)
            {
                return true;
            }
            if (date.Month is 6)
            {
                return true;
            }
        }
        return false;
    }

    public static bool TryGetSolstice(DateTime date, [NullException(true)] out string? solstice)
    {
        if (date.Day is 21)
        {
            if ((solstice = date.Month switch)
            {
                12 => "Winter Solstice",
                6 => "Summer Solstice",
                _ => null
            }) is not null) return true;
            solstice = null;
            return false;
    }
}
```

Constants can be any literal including strings, defined constants, and, of course, null. Note that the comparison of a string to the literal string "*" will work, but comparing it to string.Empty will fail because string.Empty is not declared as a constant.

## Relational Patterns (C# 9.0)

With relational patterns you can compare to a constant relatively using the operators <, >, <=, and >=. Listing 7.24 provides both operator and switch expression versions of relational patterns. (Note that == is not one of the operators since this functionality is already available in the constant pattern matching.)

Listing 7.24: Relational Pattern Matching Examples

```csharp
public static bool IsDeveloperWorkHours(
  int hourOfTheDay) =>
  hourOfTheDay > 10 && hourOfTheDay < 24;

public static string GetPeriodOfDay(int hourOfTheDay) =>
{
    return hourOfTheDay switch
    {
        6 => "Dawn",
        12 => "Morning",
        18 => "Afternoon",
        24 => "Evening",
        _ => throw new ArgumentOutOfRangeException(
            "The hour of the day specified is invalid" + nameof(hourOfTheDay))
    };
};
```

It is important to note that starting in C# 7.0, match expressions are no longer necessarily mutually exclusive. For example, we could have a match expression of > 0 and another with < 24 and both would be true regardless of the hour. Order will make the final determination of which path the code execution follows. For this reason, use caution ordering the match expressions in switch statements and expressions (in the same way you would be careful about ordering a series of if statements).

## Logical Patterns (C# 9.0)

With logical patterns we can combine relational match expressions with a single variable and the operators not, and, or, providing negated, conjunctive, and disjunctive patterns respectively. Therefore, rather than using logical operators like == or || (see the IsDeveloperWorkHours() method in Listing 7.24 example) you can specify the input operand once and then have multiple match expressions as shown in Listing 7.25.

LISTING 7.25: Logical Pattern Matching Examples

```csharp
public bool IsStandardWorkHours(
    int hour) =>
    hour is
    >= 8
    and < 17
    and not 12; // lunch

static bool TryGetPhoneButton(
    char character,
    [NullWhen(true)] out char button)
{
    return (char.ToLower(character)) switch 
    {
        '1' => '1',
        '2' or (>= 'a' and <= 'c') => '2',
        // operator and parenthesis example (C# 10)
        '3' or not < 'd' => '3',
        '4' or >= 'g' and <= 'i' => '4',
        '5' or >= 'j' and <= 'l' => '5',
        '6' or >= 'm' and <= 'o' => '6',
        '7' or >= 'p' and <= 's' => '7',
        '8' or >= 't' and <= 'v' => '8',
        '9' or >= 'w' and <= 'z' => '9',
        '0' or _ => '0',
        _ => default // Set the button to indicate invalid value
    };
```

The order of precedence is not and or; the first two examples don't need parentheses. Parentheses, however, are allowed to change the order of precedence arbitrarily as demonstrated by match expressions in the switch expression.

Be aware that using or and not operators cannot also declare a variable. For instance:

```csharp
if (input is "data" or string text)
{
    // ...
}
```
will result in error: CS8780: A variable may not be declared within 'not' or 'or' pattern.

## Parenthesized Patterns (C# 9.0)

To override the order of precedence of logical operators you can group them together using parentheses (see Listing 7.26).

Listing 7.26: Parenthesized Patterns

```csharp
public bool IsOutsideOfWorkHours(
    Time time) =>
    time.Hour is not (8 and < 17 and not 12); // Parenthesized - C# 9
```

Parenthesizing is available with both operators and switch syntax.

## Tuple Patterns (C# 8.0)

With tuple pattern matching, you can check for constant values within the tuple or assign tuple items to a variable (see Listing 7.27).

Listing 7.27: Tuple Matching with is Operator

```csharp
public static void Main(params string[] args)
{
    const int command = 0;
    const int fileName = 1;
    const string dataFile = "data.dat";

    // ...
    if ((args.Length, args[command].ToLower()) is (1, "cat"))
    {
        Console.WriteLine(File.ReadAllText(dataFile));
    }
    else if ((args.Length, args[command].ToLower()) is (2, "encrypt"))
    {
        string data = File.ReadAllText(dataFile);
        File.WriteAllText(args[fileName], data.ToString());
    }
}
```

As expected, the same is possible with the switch expression or statement syntax see Listing 7.28.

Listing 7.28: Tuple Matching with the switch Statement

```csharp
public static void Main(params string[] args)
{
    const int action = 0;
    const int fileName = 1;
    const string dataFile = "data.dat";

    // ...
    switch ((args.Length, args[action].ToLower())
    {
        case (1, "cat"):
            Console.WriteLine(File.ReadAllText(dataFile));
            break;
        case (2, "encrypt"):
            {
                string data = File.ReadAllText(dataFile);
                File.WriteAllText(args[fileName], data.ToString());
            }
            break;
        default:
            Console.WriteLine("Arguments are invalid.");
            break;
    }
}
```

In both Listing 7.27 and Listing 7.28, we pattern match against a tuple that is populated with the length and the elements of args. In the first match expression, we check for one argument and the action "cat". In the second match expression, we evaluate whether the first item in the array is equal to "encrypt". In addition, Listing 7.27 assigns the third element in the tuple to the variable FileName if the initial match expression evaluates to true. The switch statement in Listing 7.28 doesn't make the variable assignment since the input operand of the switch statement is the same for match expressions.

Each element can be a constant or a variable. Since the tuple is instantiated before the operator executes, we can't use the "encrypt" scenario first because args[FileName] would not be a valid index if the "cat" action was requested.

## Positional Patterns (C# 8.0)

Building on the deconstructor construct introduced in C# 7.0 (see Chapter 6), C# 8.0 enables positional pattern matching with a syntax that closely matches pattern matching (see Listing 7.29).

Listing 7.29: Positional Pattern Matching with the is Operator

```csharp
using System.Drawing;

public static class PointHelper
{
    public static void Deconstruct(
        Point point, out int x, out int y) =>
        (x, y) = (point.X, point.Y);

    public static bool IsVisibleOnGAScreen(Point point) =>
        point is (>=0 && <=1920, >=0 && <=1080);

    public static string GetQuadrant(Point point) => switch
    {
        (>=0, >=0) => "Quadrant I", // II | I
        (<=0, >=0) => "Quadrant II", // ----|_
        (<=0, <0) => "Quadrant III", // --/
        (>=0, <=0) => "Quadrant IV" // III | IV
    };
}
```
