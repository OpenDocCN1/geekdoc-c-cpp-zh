Although this pattern is both common and legal, there are better ways to achieve that aim. For example, if you are considering returning two or more values from a method and C# 7.0 is available, it is likely preferable to use C# 7.0 tuple syntax. Prior to that, consider writing two methods, one for each value, or still using the System.ValueTuple type without C# 7.0 syntax.

Each and every normal code path must result in the assignment of all out parameters.

# Read-Only Pass by Reference (in)

In C# 7.2, support was added for passing a value type by reference that was read only. Rather than passing the value type to a function so that it could be changed, read-only pass by reference was added: It allows the value type to be passed by reference so that not only copy of the value type occurs but, in addition, the invoked method cannot change the value. In other words, the purpose of the feature is to reduce the memory copied when passing a value while still identifying it as read only, thus the performance. This syntax is to add an in modifier to the parameter. For example:

```
int Method(in int number) { ... }
```

With the in modifier, any attempts to reassign number (number++, for example) results in a compile error indicating that number is read only.
