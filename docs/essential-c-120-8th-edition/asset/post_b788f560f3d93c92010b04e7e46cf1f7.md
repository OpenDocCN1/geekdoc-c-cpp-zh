Since the output from the IEnumerable<T>.Where() method is a new IEnumerable<T> collection, it is possible to again call a standard query operator on the same collection. For example, rather than just filtering the data from the original collection, we could transform the data (see Listing 15.11).

Listing 15.11: Projection with System.Linq.Enumerable.Select()

```
using System;
using System.Collections.Generic;
using System.Linq;

{

    {

            patient => patient.ToString());
```

# Running LINQ Queries in Parallel

With the widespread availability of computers having multiple processors and multiple cores within those processors, the ability to easily take advantage of the additional processing power becomes more important. To do so, programs need to support threads so that what can happen simultaneously on different CPUs within the computer. Listing 15.14 demonstrates one way to do this using Parallel LINQ (PLINQ).

Listing 15.14: Executing LINQ Queries in Parallel

```c
//...
IEnumerable<string> fileList = Directory.EnumerateFiles(rootDirectory, searchPattern);
var items = fileList.AsParallel().Select(
file => {
    FileInfo fileInfo = new File(file);
    return new {
        FileName = fileInfo.Name,
        Size = fileInfo.Length
    };
});
//...
```

As Listing 15.14 shows, only a minimal change in code is needed to enable parallel support. All that this example uses a Microsoft .NET Framework 4-introduced standard query operator, AsParallel(), on the static class System.Linq.ParallelEnumerable. Using this simple extension method, the runtime begins executing over the items within the fileList and returning the resultant objects in parallel. Each parallel operation in this case is not particularly expensive (although it is relative to the other execution taking), consider the burden imposed by CPU-intensive operations such as encryption or compression. Running the query in parallel across multiple CPUs can decrease execution time by a factor corresponding to the number of CPU cores.

An important caveat to be aware of (and the reason AsParallel() appears as Advanced Topic rather than in the standard text) is that parallel execution can introduce race conditions, such that an operation on one thread can intermingled with an operation on different thread, causing data corruption. To avoid this, synchronization mechanisms are required on data with shared access. Synchronization itself, however, can introduce deadlocks.

More details on this and additional multithreading are provided in Chapters 19 through 22.

# Counting Elements with Count()

Another query frequently performed on a collection is to retrieve the count. To support this type of query, LINQ includes the Count() method. Listing 15.15 demonstrates that Count() is overloaded to count all elements (no parameters) or to take a predicate that counts only items identified by the predicate.

Listing 15.15: Counting Items with Count()

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

public class Program
{
    public static void Main()
    {
        IEnumerable<Patient> patients = PatientData.Patents;
        Console.WriteLine($"Patient Count: {patients.Count()}");
        Console.WriteLine($"Patient Count in 1800s: {patients.Count(patient => patient.YearOfPublication.StartsWith(\"18\"))}");
    }
}
```

In the apparent simplicity of the Count() statement, IEnumerable<T> has not changed, the executed code still iterates over all the items in the collection. Whenever a Count property is directly available on the collection, it is preferable to use that rather than calling LINQ's Count() method (a subtle difference). Fortunately, ICollection<T> includes the Count property, so that calls the Count() method on a collection that supports ICollection<T> casts the collection and call Count directly. However, if ICollection<T> is not supported, Enumerable.Count() proceeds to enumerate all the items in the collection rather than the built-in Count mechanism. If the purpose of checking the count is just to see whether it is greater than zero (if(patients.Count() > 0){...), the preferred approach would be to use the Any() operator (if(patients.Any())){ Any() attempts to iterate over only one of the items in the collection to return a true result, rather than iterating over the entire sequence.

> Guidelines
DO use System.Linq.Enumerable.Any() rather than calling patients.Count() when checking whether there are more than zero items.
DO use a collection's Count property (if available) instead of calling the System.Linq.Enumerable.Count() method.
