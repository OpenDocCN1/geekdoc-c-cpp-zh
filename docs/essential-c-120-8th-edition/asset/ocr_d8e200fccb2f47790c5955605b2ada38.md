For example, creating a hash that doesn't consider the distribution of a string in Latin-based languages primarily centered on the initial 122 ASCII characters would result in a uneven distribution of string values and to rely on a strong GetHashCode() algorithm.

GetHashCode() is generally used in Equals() implementations to short-circuit a full equals comparison if the hash codes are different. As a result, it is frequently called when the type is used as a key type in dictionary collections.

+   - Performance: Small differences between two objects should result in large differences between hash code values—ideally, a 1-bit difference in the object should result in approximately 16 bits of the hash code changing, or average. This helps ensure that the hash table remains balanced no matter how it is "bucketing" the hash values.
