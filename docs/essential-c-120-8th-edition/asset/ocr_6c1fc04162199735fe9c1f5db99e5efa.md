# LISTING 6.41: Using NullWhen and NullIfIfNotNull Attributes

```
using System.Diagnostics.CodeAnalysis;
// ...
 static bool TryGetDigitAsText(
    char number, [NotNullWhen(true)]out string text) =
    (text = number switch
    {
        '1' => "one",
        '2' => "two",
        '3' => "three",
        '4' => "four",
        // ...
        'g' => "nine",
        => null
    }) is not null;
```

```
// nameof(text) on parameters is not supported prior to C# 11/.NET 7.0
[return: NullIfIfNotNull(nameof(text))]
static public string TryGetDigitsAsText(string text)
{
    if (text == null) return null;

    string result = ""
    foreach (char character in text)
    {
        if (TryGetDigitAsText(character, out string digitText))
        {
            if (result != "") result += '-';
            result += digitText.ToLower();
        }
    }
    return result;
```

Notice that the call to digitText.ToLower() from TryGetDigitAsText() without a coalescing operator does not issue a warning even though text is declared as nullable. This is possible because the text parameter in TryGetDigitAs() is decorated with the NullWhen(true) attribute, which informs the compiler that, if the method returns true (the value specified by the NullWhen attribute), then your intent is that digitText will not be null. The NullWhen attribute is a post-condition declaration, informing the caller that output(text) is not null if the method returns true.
