Notice there are relatively small differences between Listing 20.1 and Listing 20.3. Furthermore, the number of periods will vary between executions, the output should match that from Listing 20.2. This is one of the key points about the async/await pattern: It lets you write code with only minor modifications from the way you wrote it synchronously.

To understand the pattern, focus first on the CountOccurrencesAsync() method and the differences from Listing 20.1. First, we change the signature of the CountOccurrences() method declaration by adding the new contextual async keyword as a modifier on the signature. The async keyword must return a **valid async return type**. This can be a void, Task<T>, ValueTask<T>, or IAsyncEnumerable<T>/AsyncEnumerator<T> (as of C# 8.0). In this case, since the body of the method does not return any value we still be able to return information about the asynchronous activity to the caller, CountOccurrencesAsync() returns Task. By returning a Task, the caller has access to the state of the asynchronous invocation and the result (int) when it completes.
