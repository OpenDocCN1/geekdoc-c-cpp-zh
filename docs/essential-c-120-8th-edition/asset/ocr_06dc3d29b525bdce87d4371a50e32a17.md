You can also use the ParallelOptions object's TaskScheduler property to specify a custom task scheduler when scheduling the tasks associated with each iteration. For example, you might have an asynchronous event handler that responds to the user's click of a Next button. If the user clicks the button times, you might want to use a custom task scheduler that prioritizes the most recently created task that has waited the longest. The task scheduler provides a mechanism of specifying how the tasks will execute in relation to one another.

The ParallelOptions object also has a Cancellation property that provides a mechanism to communicate to the loop that no further iterations should start. Additionally, the body of an iteration can watch the cancellation token to determine if an early exit from the iteration is in order.

# Breaking a Parallel Loop

Like a standard for loop, the Parallel.For() loop supports the concept of “breaking” to exit the loop and canceling any further iterations. In the context of parallel for execution, however, a break signifies that new iterations following the breaking iteration should start. All currently executing iterations, however, will run to completion.
