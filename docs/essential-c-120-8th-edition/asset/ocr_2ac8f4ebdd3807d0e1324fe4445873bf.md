# State Is Shared

The problem with an implementation as Listing 15.5 is that if two loops interleaved each other—foreach inside another, both using the same collection—the collection must maintain a state indicator of the current element so that when MoveNext() is called, the next element can be determined. In such a case, interleaving loop can affect the other. The same is true of loops executed by multiple threads.

To overcome this problem, the collection classes do not support IEnumerator<T> and IEnumerator interfaces. Instead, as shown in Figure 15.1, there is a second interface, called IEnumerable<>, whose only method is GetEnumerator(). The purpose of this is to return an object that supports IEnumerator<T>. Instead of the collection class maintaining the state, a different class—usually a nested class, so that it access to the internals of the collection—will support IEnumerator< > interface and will keep the state of the iteration loop. The enumerator is like a “cursor” or a “bookmark” in the sequence. You can have multiple bookmarks, and moving each of them enumerates over the collection independently of the others.
