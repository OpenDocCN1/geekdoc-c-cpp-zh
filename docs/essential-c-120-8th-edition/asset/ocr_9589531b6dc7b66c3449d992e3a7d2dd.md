when you don't know whether the operand is null, but you know the number of elements, or at least a particular element exists.

What makes the null-conditional operator especially convenient is that it can be chained (with and without more null-coalescing operators). For example, in the following code, both ToLower() and StartWith() will be invoked only if both segments and segments[0] are not null:

```
segments[0]?.ToLower().StartsWith("file:");
```

In this example, of course, we assume that the elements in segments potentially be null, so the declaration (assuming C# 8.0) would more accurately have

string[][]? segments;
Thements array is null, in other words, and each of its elements is a null string.

Null-conditional expressions are chained, if the first operand is null, the expression evaluation is short-circited, and no further invocation within the expression chain will occur. You can also chain a null-coalescing operator at the end of the expression so that if the operand is null, you can specify which default value to use:

```
string uriString = segments[0]?.ToLower().StartsWith("file:")??"intellect.com";
```

Note that the data type resulting from the null-coalescing operator is not null (assuming the right-hand side of the operator ("intellect.com" in this example) is not null—which would make little sense.

Be careful, however, that you don't unintentionally neglect additional null values. Consider, for example, what would happen if ToLower() (hypothetically, in this case) returned null. In this scenario, a NullReferenceException would occur upon invocation of StartWith(). This doesn't mean you must use a chain of null-conditional operators, but rather that you should be intentional about the logic. In this example, because ToLower() can never be null, no additional null-conditional operator is necessary.
