with additional parameters. Consider using optional parameters in favor of overloading so that the default values for “defaulted” properties are visible in the API. For example, a constructor signature of Person(string FirstName, string LastName, int? age = null) provides signature documentation that if the Age of a Person is not specified, it will default to null.

Notice also that it is possible to have expression bodied member implementations of constructors,⁹ as

```
// FirstNameLastName inside Id property setter.
#pragma warning disabling CS0618
public Employee(int id) => id = id;
```

In this case, invoke the Id property to assign FirstName and LastName. Unfortunately, the compiler won't detect the assignment and, starting with C# 8.0, issues a warning to consider those properties as nullable. Since we are, in fact, setting them, the warning is disabled.

# Guidelines

+   DO use the same name for constructor parameters (camelCase) and properties (PascalCase) if the constructor parameters are used to simply set the property.

DO provide constructor optional parameters or constructor overloads to initialize properties with good defaults.
