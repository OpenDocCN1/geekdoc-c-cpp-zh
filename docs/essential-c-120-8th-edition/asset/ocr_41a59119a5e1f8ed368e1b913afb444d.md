# TABLE 8.2: Comparing Abstract Classes and Interfaces (continued)

| Abstract Classes | Interfaces |
|---|---|
| Derived classes either be abstract themselves or must implement all abstract members. | Implementing types must implement all abstract members. |
| Can add additional non-abstract members that all derived classes can inherit without breaking cross-version compatibility. | Can add additional default interface members in C# 8.0/NET Core 3.0 that derived classes can inherit without breaking version compatibility. |
| Can declare methods, properties, and fields (along with all other member types, including constructors and finalizers). | Instance members are limited to methods and properties, not fields, constructors, or finalizers. All static members are possible, including static constructors, static events, and static fields. |
| Members may be instance or static, or optionally abstract, and provide implementations for non-abstract members that can be used by derived classes. | Starting with C# 8.0/NET Core 3.0, members may be instance, abstract, or static, and may provide implementations for non-abstract members that can be used by derived classes. |
| Members may be declared as virtual or not. Members that should not be overridden (see Listing 8.13) will not be declared as virtual. | All (non-sealed) members are virtual, whether explicitly designated as such or not; there is no way for an interface to prevent overriding behavior. |
| A derived class may derive from only a single base class. | An implementing type may arbitrarily implement many interfaces. |
| Static abstract members are not supported. | C# 11 introduced static abstract members.|

# Guidelines

CONSIDER defining an interface if you need to support its functionality on types that already inherit from some other type.

In summary, assuming a .NET Core 3.0 framework is acceptable, C# 8.0 (or later) defined interfaces have all the capabilities of abstract classes except the ability to declare an instance field.
