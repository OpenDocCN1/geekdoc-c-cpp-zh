| Enum | Description |
| --- | --- |
| NotOnFailed* | This specifies that the continuation task should not be scheduled if its antecedent had an unhandled exception. This option is not valid for multitask continuations. |
| OnlyOnCanceled* | This specifies that the continuation task should be scheduled only if its antecedent was canceled. This option is not valid for multitask continuations. |
| NotCanceled* | This specifies that the continuation task should not be scheduled if its antecedent was canceled. This option is not valid for multitask continuations. |
| OnlyOnFaulted* | This specifies that the continuation task should be scheduled only if its antecedent had an unhandled exception. This option is not valid for multitask continuations. |
| OnlyRanToCompletion | This specifies that the continuation task should be scheduled only if its antecedent ran to completion. This option is not valid for multitask continuations. |
| ExecuteSynchronously | This specifies that the continuation task should be executed synchronously. With this option, the continuation will attempt to execute the work on the same thread that causes the antecedent task to transition into its final state. If the antecedent is already complete when creating the continuation it will run on the thread creating the continuation. |
| HideScheduler (.NET 4.5) | This prevents the created task from being seen by the current scheduler. This means that operations Run/StartNew and ContinueWith performed in the created task will see TaskScheduler.Default(null) as the current scheduler. This is useful when continuation should run on a particular scheduler, but the continuation is calling out to additional code that should not schedule work on the same scheduler. |
| LazyCancellation (.NET 4.5) | This causes the continuation to delay monitoring the cancellation token for a cancellation request until the antecedent has completed. Consider tasks t1, t2, and t3, where the latter is a continuation of the former. If t2 is canceled before t1 completes, it is possible that t3 could start before t1 completes. Setting LazyCancellation avoids this.
