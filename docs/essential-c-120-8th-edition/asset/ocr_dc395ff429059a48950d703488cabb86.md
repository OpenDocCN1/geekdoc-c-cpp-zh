The bulk of the logic appears in the GetData() method. The purpose of this method is to always return an instance of the data—whether from the cache or reloading it. GetData() begins by checking whether the Data property is null. If it is, the data is loaded and assigned to a local variable called target. It creates a reference to the data so that the garbage collector will not clear it. Next, we instantiate a WeakReference and pass a reference to the loaded data so that the WeakReference object has a handle to the data (its target); then, if requested, an instance can be returned. Do not pass an instance that does not have a local reference to WeakReference, because it might get cleaned before you have a chance to return it (i.e., do not call new WeakReference<byte[]>(LoadData())).

If the data already has an instance of WeakReference, then the code calls TryTarget() and, if there is an instance, assigns target, creating a reference so the garbage collector will no longer clean up the data.

Lastly, if WeakReference’s TryTarget() method returns false, we load the data, assign the reference with a call to SetTarget(), and return the newly instantiated object.

# Resource Cleanup

Garbage collection is a key responsibility of the runtime. Nevertheless, it is important to recognize that the garbage collection process centers on the code’s memory utilization. It is not about the cleaning up of file handles, database connection strings, ports, or other limited resources.

# Finalizers

Finalizers allow developers to write code that will clean up a class’s resources. Unlike constructors that are called explicitly using the new operator, finalizers cannot be called explicitly from the code. There is no equivalent such as a delete operator.
