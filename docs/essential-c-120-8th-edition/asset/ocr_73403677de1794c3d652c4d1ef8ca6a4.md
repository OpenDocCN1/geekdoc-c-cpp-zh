The ValueTuple<...> set of classes was designed for the same purpose as the Pair<T> and Pair<TFirst, TSecond> classes, except that together can handle every type arguments. In fact, using the last ValueTuple in Listing 12.16, TRest can be used to store another ValueTuple, making the number of elements of the tuple practically unlimited.

Another interesting member of the tuple family of classes is the nongeric ValueTuple class. This class has static factory methods for instantiating the various generic type types. Although each generic type can be instantiated directly using its constructor, the ValueTuple type's factory methods allow for inference of the type arguments using the Create() method. Listing 12.17 demonstrates using the Create() method in combination with type inference.

Listing 12.17: Comparing System.ValueTuple Instantiation Approaches

```
#if !PRESHARP7
(string, Contact) keyValuePair;
keyValuePair =
    ("55-55-5555", new Contact("Inigo Montoya"));
#else // Use System.ValueTuple<string,Contact> prior to C# 7.0
ValueTuple<string, Contact> keyValuePair;
keyValuePair =
    ValueTuple.Create(
    ("55-55-5555", new Contact("Inigo Montoya"));
new ValueTuple<string, Contact>(
    ("55-55-5555", new Contact("Inigo Montoya"));
#endif // !PRESHARP
```

Obviously, when the ValueTuple gets large, the number of type parameters to specify could be cumbersome without the Create() factory methods.
