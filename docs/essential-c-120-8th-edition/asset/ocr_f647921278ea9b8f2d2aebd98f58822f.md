# Type Member Accessibility Modifiers

The full list of access modifiers appears in Table 10.1.

TABLE 10.1: Accessibility Modifiers

| Modifier | Description |
| --- | --- |
| public | The member is accessible anywhere the type is accessible. |
| internal | The member is accessible from within the assembly. |
| private | The member is accessible from within the containing type but inaccessible otherwise. |
| protected | The member is accessible within the containing type and any subtypes derived from it, regardless of the assembly. |
| protected internal | The member is accessible from anywhere within the containing type, even if the derived types are within a different assembly. |
| private protected | The member is accessible from any types derived from the containing type that are also in the same assembly.4 |
| file | The member is accessible only from the same file. |

# Defining Namespaces

As mentioned in Chapter 2, all data types are identified by the combination of namespace and their name. However, in the CLR, there is no such as a “namespace.” The type’s name actually is the fully qualified type name, including the namespace. For the classes you defined earlier, there was no explicit namespace
