appropriate for the Windows UI, it is single-threaded; thus, the return will always be
to the same thread—the UI thread. In other words, rather than immediately
executing the continuation task, the TPL consults the synchronization context, which
instead posts a message regarding the continuation work to the message pump. Next,
because the UI thread monitors the message pump, upon picking the continuation
work message, it invokes the code following the await call. (As a result, the
inocation of the continuation code is on the same thread as the caller that processed
the message pump.)

A key readability feature is built into the TAP language pattern. Notice in
Listing 20.15 that the code to return pingReply.Status appears to follow naturally
after the await statement, providing a clear indication that it will execute
immediately following the previous line. However, writing what really happens from
scratch would be far less understandable for multiple reasons.
