# Boxing

We know that variables of value types directly contain their data, whereas variables of reference types contain a reference to another storage location. What happens when a value type is converted to one of its implemented interfaces or to its root class, object? The result of the conversion must be a reference to a storage location that contains something that looks like an instance of a reference type, but the variable contains a value of value type. Such a conversion, which is known as boxing, has special behavior. Converting a value of value type that directly refers to its data to a reference type that refers to a location on the garbage-collected heap involves several steps.

+   Memory is allocated on the heap that will contain the value type’s data and the other overhead necessary to make the object look like every instance of a managed object of the reference type (namely, a SyncBlockIndex and method table pointer).

+   The value of the value type is copied from its current storage location into the newly allocated location on the heap.

+   The result of the conversion is a reference to the new storage location on the heap.

The reverse operation is called unboxing. The unboxing conversion first checks the type of the boxed value is the same as the type to which the value is unboxed, and results in a copy of the value stored in the heap location.
