# Defining Custom Exceptions

Once throwing an exception becomes the best course of action, it is preferable to framework exceptions because they are well established and understood. Instead of throwing a invalid argument exception, for example, it is preferable to use the System.ArgumentException type. However, if the developers using a particular API a mapping API receives an address for which the ZIP code exception-handling logic will vary to handle a custom exception type, for instance—it is appropriate to define a custom exception. For example, if a mapping API receives an address for which the ZIP code is invalid, instead of throwing System.ArgumentException, it may be better to throw a custom InvalidAddressException. The key is whether the caller is likely to write a specific InvalidAddressException catch block with special handling rather than a generic System.ArgumentException catch block.
