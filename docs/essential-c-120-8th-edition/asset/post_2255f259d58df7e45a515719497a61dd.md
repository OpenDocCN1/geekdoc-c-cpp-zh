You can also add a suffix to a value to explicitly declare the literal as float or double using the F (or f) and D (or d) suffixes respectively. For integer types, the suffixes are U, LU, and UL. The type of integer literal can be determined as follows:

### Fundamental Numeric Types

- Numeric literals with no suffix resolve to the first data type that can store the value, in order: int, uint, long.
- Numeric literals with the suffix U resolve to the first data type that can store the value, in order: uint and ulong.
- Numeric literals with the suffix L resolve to the first data type that can store the value, in order: long and ulong.
- If the numeric literal has the suffix UL or LU, it is of type ulong.

Note that for literals are case insensitive. However, uppercase is generally preferred to avoid any ambiguity between the lowercase l and digit 1.618033988749895.

On occasion, numbers can get large and difficult to read. To overcome the readability problem, C# 7.0 added support for a digit separator, an underscore (_), when expressing a numeric literal, as shown in Listing 2.4. You can use the digit separator to create whatever grouping you like as long as the underscore occurs between the first and last digits. In fact, you can even have multiple underscores by side—with no digit between them.

# Listing 2.4: Specifying Separator

```csharp
Console.WriteLine(9_814_072_356);
```

In addition, you may wish to use exponential notation instead of writing out several zeros before the decimal point (using a digit separator or not). To use exponential notation, supply the e or E infix, follow the infix character with a positive or negative integer number, and complete the literal with the appropriate data type suffix. For example, you could print Avogadro's number as a float, as shown in Listing 2.5 and Output 2.4.

### Hexadecimal Notation

Usually, you work with numbers that are represented with a base of 10, meaning there are 10 symbols (0–9) for each place value in the number. If a number is displayed with hexadecimal notation, it is displayed with a base of 16, meaning 16 symbols are used: 0–9, A–F (in lowercase). Therefore, 0x00A corresponds to the decimal value 10 and 0x02A corresponds to the decimal value 42, being 2 × 16 + 10. The actual number is the same. Switching from hexadecimal to decimal, or vice versa, does not change the number itself—just the representation of the number.

Each hex digit is four bits, so a byte can represent two digits.

In all discussions of literal values so far, we have covered only base 10 type. C# also supports the ability to specify hexadecimal values. To specify a hexadecimal value, prefix the value with 0x and then use any hexadecimal series of digits, as shown in Listing 2.6.

# LISTING 2.6: Hexadecimal Literal Value

```csharp
//Display the value 42 using a hexadecimal literal
Console.WriteLine(0x02A);
```

Output 2.5 shows the results of Listing 2.6. Note that this code still displays 42 (0x02A). Starting with C# 7.0, you can also represent numbers as binary values (see Listing 2.7).

# OUTPUT 2.5
```
42
```

# LISTING 2.7: Binary Literal Value

```csharp
// Display the value 42 using a binary literal
Console.WriteLine(0b101010);
```

The syntax is like the hexadecimal syntax except with 0b as the prefix (uppercase B is also allowed). See "Beginner Topic: Bits and Bytes" in Chapter 4 for an explanation of binary notation and the conversion between binary and decimal. Note that with C# 7.2, you can place the digit separator after the x for a hexadecimal literal or the b for a binary literal.

### Formatting Numbers as Hexadecimal

To display a numeric value in its hexadecimal format, it is necessary to use the x or X formatting specifier. The casing determines whether the hexadecimal letters appear in lowercase or uppercase. Listing 2.8 with Output 2.6 shows an example of how to do this.

# LISTING 2.8: Example of a Hexadecimal Format Specifier

```csharp
//Displays "0x2A"
Console.WriteLine($"0x{42:X}");
```

# OUTPUT 2.6
```
0x2A
```

Note that the numeric literal (42) can be in decimal or hexadecimal form. The result will be the same. Also, to achieve the hexadecimal formatting, we rely on the formatting specifier, separated from the string interpolation expression with a colon.

### Round-Trip Formatting

By default, Console.WriteLine(1.618033988749895); displays 1.618033988749895. To accurately identify the string representation of the double, use the round-trip format specifier, R (or r). The round-trip format specifier returns the original value. Listing 2.9 with Output 2.7 shows the numbers are equal.

# LISTING 2.9: Formatting Using the R Specifier

```csharp
// ...
const double number = 1.618033988749895;
double result;
string text;

text = $"{number:R}";
result = double.Parse(text);
Console.WriteLine($"result = {number}:{result}");
```

# OUTPUT 2.7
```
False: result == number
True: result == number
```

When assigning the first time, there is no round-trip specifier; as a result, the value returned by double.Parse(text) is not the same as the original number. In contrast, the round-trip format specifier is used, double.Parse(text) returns the original value.

The fundamental types discussed so far are numeric types. C# includes some additional types as well: bool, char, and string.

### Boolean Type (bool)

Another C primitive is a Boolean or conditional type, bool, which represents true or false in conditional statements and expressions. Allowable values are the keywords true and false. The BCL name for bool is System.Boolean. For example, to compare two strings in a case-insensitive manner, you call the string.Compare() method and pass a bool literal true (see Listing 2.10).

LISTING 2.10: A Case-Insensitive Comparison of Two Strings

```csharp
bool ignoreCase = true;
string option = "/help";
//...
int comparison = string.Compare(option, "/Help", ignoreCase);
bool isRequested = (comparison == 0);
// Displays: Help Requested: True
Console.WriteLine($"Help Requested: {isRequested}");
```

In this case, you case-insensitive comparison of the contents of the variable option with the literal text /Help and assign the result to comparison.

Although theoretically a single bit could hold the value of a Boolean, the size of bool is 1 byte.
