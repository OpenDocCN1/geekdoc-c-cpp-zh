

# 类型的封装

程序集必须标记为 `public`。因此，在编译 Coordinates.dll 程序集之前，有必要确保类型声明是 `public`（参见列表 10.8）。

## 列表 10.8：在程序集外部使类型可用

```csharp
public struct Coordinate
{
    // ...
}
public struct Latitude
{
    // ...
}
public struct Longitude
{
    // ...
}
public struct Arc
{
    // ...
}
```

同样，`class`（类）和 `enum`（枚举）等声明既可以是 `public` 也可以是 `internal`。`internal` 访问修饰符不仅限于类型声明；也就是说，它也可以存在类型成员上。因此，你可以将一个类型指定为 `public`，但将类型内的特定方法标记为 `internal`，以便这些成员仅在程序集内部可用。成员的访问权限不能高于其类型。如果类被声明为 `internal`，则该类型上的 `public` 成员将只能从程序集内部访问。

2. 你可以使用其他类成员可用的任何访问修饰符（例如 `private`）来装饰嵌套类。然而，在类作用范围之外，可用的访问修饰符只有 `public` 和 `internal`。

## `protected internal` 类型修饰符

另一个类型成员访问修饰符是 `protected internal`。具有 `protected internal` 访问修饰符的成员可以从包含程序集内的所有位置以及从派生该类型的类访问，即使派生类不在同一个程序集内。默认成员修饰符是 `private`，因此当你添加访问修饰符（`public` 除外）时，该成员会变得稍微可见。

> 注意：具有 `protected internal` 访问修饰符的成员可以从包含程序集内的所有位置以及从派生该类型的类访问，即使派生类不在同一个程序集内。

## `file` 类型修饰符

C# 11 引入了一种了一种新的访问修饰符：`file` 修饰符。使用 `file` 修饰符装饰类型将将其可见性限制在文件内部。定义在一个文件中的 `file class Thing{}` 在该文件外部是不可见的。事实上，你可以在同一个项目中的多个文件中都定义为 `file class Thing{}`，而不会发生冲突，因为它们彼此之间是不可见的。`file` 修饰符主要用于代码生成，以便专门为内部目的生成的类型不会影响现有代码；事实上，多个文件中的相同代码生成将局部封装在每个文件中。

3. `file` 不能用于嵌套类型定义——仅用于顶层定义。

更重要的是，CLI 框架中有成千上万种类型，而在框架之外还有数个数量级不同的类型。因此，为特定问题寻找正确的类型可能是一个重大的挑战。

解决这两个问题的办法是组织所有类型，将它们分组到命名为命名空间的的逻辑类别中。例如，`System` 命名空间之外的类通常被放在与公司、产品或名称对应的命名空间中。例如，来自 Addison-Wesley 的类被放在 `Awl` 或 `AddisonWesley` 命名空间中，而来自 Microsoft 的类（System 类）位于 `Microsoft` 命名空间中。命名空间名称可以包含点，这样做提供了类的层次结构。例如，所有与网络 API 相关的 `System` 类都在 `System.Net` 中，与 Web 相关的在 `System.Web` 中。命名空间的第二层应该是稳定的产品名称，不会随版本发生变化。事实上，稳定性在所有级别都是如此的。更改命名空间名称是不兼容版本的更改，应该避免。由于此原因，你应该避免使用不稳定的名称（组织层次结构、转瞬即逝的品牌）。使用 `file` 修饰符装饰类型将将其可见性限制在文件内部。`file` 修饰符主要用于代码生成，以便专门为内部目的生成的类型不会影响现有代码；事实上，多个文件中的相同代码生成将局部封装在文件中。
