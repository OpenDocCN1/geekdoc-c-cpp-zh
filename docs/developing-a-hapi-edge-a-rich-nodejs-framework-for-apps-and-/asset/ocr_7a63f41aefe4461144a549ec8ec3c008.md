# CHAPTER 4: The handler

The path is where the actual data is we'd like to retrieve and display. There's a num-ber of options that can be set here as well.

We're first and foremost setting index to false. There shouldn't be any need to serve up any index.html in a CSS folder.

The options for directory are as follows:

+   - path - See handler for an explanation of the various ways of setting this.
- index - Can be true, false, or a string representing the name of the index file to look for the default index file is index.html and it is set to true.
- listing - Determines whether a directory should show in the absence of an index. Defaults to false.
- showHidden - Determines if hidden files should be displayed by the listing. Defaults to false.
- redirectToSlash - if there's a trailing slash, this will be redirected to the path without the slash.
- lookupCompressed - If true, it for the same filename with the '.gz' suffix for a pre-compressed version of the file to serve if the request supports content en-coding. Defaults to false.
- defaultExtension - A string that is appended to file requests if the requested file is not found. Defaults to empty string.

# VIEWS HANDLER

The views handler displays information using templates. In practice, this option isn't very commonly used. The more common approach is configuring the server with the views op-tion, and then using the regular handler for reply.views().

Because hapi supports both, we'll take a look at the views handler, and focus more on how to configure the server to directly support views with reply.views().

For our hapi-plugins project, we're not using a views handler, but it should be men-tioned how it can use. This may serve as a case for whatever reason, the regular views.views to be overridden.

In both cases, the server is configured with a views manager.

```
plugin.views({
  engines: {
    module: require('handlebars')
  },
  path: __dirname + '/views'
});
```
