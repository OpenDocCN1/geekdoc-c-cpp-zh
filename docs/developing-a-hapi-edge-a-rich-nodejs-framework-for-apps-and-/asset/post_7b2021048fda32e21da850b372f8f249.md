## Decorating the server

Using server.decorate, you can add functions directly to the server. This is different from method where you add methods to access via server. In addition to decorating the server object, you can also decorate reply object, and we'll cover that in Chapter 4.

```
server.decorate('server', 'success', function () {
    return this.response({ success: true });
});
```

## Configuring for caching

We can use server.cache to setup cache. hapi has a built-in server cache facility and relies on memory but other types of engines are supported like redis, memcached and others. Please refer to the cache documentation for details. Here is a simple example of how to use server.cache.

```
var cache = server.cache({
    segment: 'plugins',
    expiresIn: 60 * 60 * 1000
});

cache.set('pluginName', { author: 'hapi' }, null, function (err) {
    cache.get('pluginName', function (err, value, log) {
        // value === { author: 'hapi' };
    });
});
```

We have setup cache with segment of plugins. Segments are used to isolate cached items within the cache. When you call this within plugin, it defaults to name.

## Request lifecycle

Understanding how handles an HTTP request is fundamental in developing secure, efficient applications. Node.js doesn't provide much in this regard, although creating a server is fairly simple:

```javascript
var server = require('http');

server.on('request', function (request, response) {
  // do something
});

server.listen(80);
```

That's just it, the request has all information from the origin of the request, and the reply is a writable stream that needs to have headers set, information written to it, and then the connection closed. At first this can be exciting for those who haven't dealt with it. The way in which hapi deals with the requests is by having a reliable series of events each time a request is received by the server. Here's the full lifecycle:

- 'onRequest' extension point: always called. The request object passed to extension functions is decorated with request.URL() and request.getMethod(). Calls to these methods will impact how the request is routed and can be used for these rules. request.route is not yet populated at this point.

JSON configuration is ignored for any response returned from the extension point since no route is matched yet and JSON configuration is unavailable.

- Lookup route using path
- Parse cookies
- 'onPreAuth' extension point: Authenticate request
- Read and parse payload
- Authenticate request payload
- 'onPostAuth' extension point
- Validate path parameters
- Process query (e.g. JSON)
- Validate query
- Validate payload
- 'onPreHandler' extension point: Route prerequisites - configured in the Handler
- Route handler
- 'onPostHandler' extension point

> The response object contained in request.response may be modified (but not assigned a new value). To return a different response type (for example, replace an error with an HTML response), return a new response via reply(response).

## Extension points

Now that we've discussed the lifecycle, we can utilize 'extension points' in hapi. These extension points expose streams in the lifecycle where other functions can be inserted. They can easily be tied to a server to augment the existing hapi lifecycle. We use the server.ext functionality to accomplish this. Let's look at a couple of examples. These next examples are also shown in Chapter 9 around how to do shared context. It's important to know what this means now, but let's take a look at how server.ext is used. There's first the onResponse event:

```javascript
server.ext('onResponse', function (request, reply) {
  var response = request.response;
  if (!response.isBoom) {
    if (response.source && response.source.context) {
      response.source.context.title = "hapi-plugins";
    }
  }
  return reply();
})
```
