Feature-wise, hapi was designed to prevent recurring problems experienced by other frameworks at the time. That included problems like middleware ordering problems, lack of isolation, slot path matching, testability, and lack of commonly used built-features. Middleware ordering problems are solved by the hapi Lifecycle, which provides controlled, dependency-mapped hook throughout the life of a request when it hits the server, after a response is returned to the user. The lack of isolation was solved by domains and last replaced with an even better service. Path matching in hapi is built for speed and flexibility. hapi code is testable from finish (and is well-tested, itself!). Finally, via the hapi universe (https://github.com/hapi), there are dozens of official plugins that are as robust, well-tested, and flexible as hapi itself. This is addition to the hundreds of community modules available on NPM.

Designed and built entirely in open-source, hapi has also set a very high bar for source projects. From the thoroughly complete code coverage (a process ingrained from the beginning thanks to Wyatt Preault) to incredibly detailed release notes and well-organization, using hapi and related modules can trust that it works reliably and behaves as expected.

hapi has an incredibly long list of satisfied users - not least of which is WalmartLabs itself, who has prided itself on having the Node.js deployment in the world thanks to Black Friday.

There are a lot of reasons to use hapi. Try it and you will see what a pleasant developing web applications in Node.js can be.
