We also have an expiresIn setting, which is set to expire the cached item in one hour.
There is an interesting setting called staleIn where you can mark the item stored in cache as stale. This setting must be less than expiresIn. Using this feature, you can have the cache ready by the time expiresIn comes along. If staleIn doesn't have sufficient time before expiresIn hits, it will work like the usual expiresIn. This is like warming up your cache.

# Request lifecycle

Understanding how a technology handles an HTTP request is fundamental in developing secure, efficient applications using that technology. Node.js itself doesn't provide much in this regard, although creating a server is fairly simple in Node.js:

```
var server = require('http');

server.on('request', function (request, response) {
  // do something
});

server.listen(80);
```

That's just it, the request has all information from the origin of the request, and the reply is a writeable stream that needs to have headers set, information written to it, and then have the connection closed. At first this can be exciting, especially for those who haven't dealt with it in past. Once an application needs routing table however, it becomes a lot taxing to deal with.

The way in whichhapi deals with the requests is by having a reliable series of events each time a request is received by the server. Here's the full lifecycle:

+   * 'onRequest' extension point
  * always called
  * the request object passed to the extension functions is decorated with the request.URL() and request.getMethod() methods. Calls to these methods will impact how the request is routed and can be used for these rules.
  * request.route is not yet populated at this point.
