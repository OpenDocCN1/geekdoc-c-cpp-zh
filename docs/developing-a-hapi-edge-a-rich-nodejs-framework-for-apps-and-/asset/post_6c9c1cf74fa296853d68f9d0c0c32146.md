
directs says that we should only redirect five times as a max. The pass-Through setting specifies whether or not to preserve headers on the original request. Finally, the xforward setting tells hapi to add (or append) an 'x-forwarded-for' header to the request.

You can do other powerful things with the proxy handler. You can rewrite the request using mapUri, pass local-state from the handler instance using localStatePassThrough, reject unauthorized requests with rejectUnauthorized, and you can even use a custom function with onResponse to do whatever you want. Refer to documentation for more details.

Instead of proxying Google, you can proxy your own service here. Proxying is an easy way to get started with something simple. As time permits, you can add routes to your application to take over that downstream functionality. This approach leads to easier troubleshooting due to the smaller change sets.

## Tails

Certain actions do not require immediate completion. The type of calls may be a background of some sort, which is not necessary for the return of the page served to the
client. It may be a database call for some update, or it may be any number of things. When
not necessary to capture this, we are still likely to capture this for logging purposes.
When the tails are completed for the request, the server emits a tail event.

server.route({

  path: '/',

## Defining the handler using server.handler

The handler can be defined directly on the server object. In practice, this is not a way we define handlers in our own code, it's included here as a possible alternative. After all, a lot of code depends on preference.

```javascript
var DB = new Database(options);
server.handler('pluginLike', function (route, options) {
  return function (request, reply) {
    options.DB.getPlugin(request.path.id, function (err, plugin) {
      if (err) {
        return Boom.internal(err);
      }

      plugin.like(function (err) {
        if (err) {
          return reply.fail();
        }

        return reply.success();
      });
    });
  };
});
server.route({
  method: 'GET',
  path: '/plugins/like/{id}',
  handler: { pluginLike: db: DB }
});
```

## Liking a plugin example

As a large example, we're going to take a look at what is happening behind the scenes when we use a plugin on the site. Below is the example.

```javascript
module.exports.like = {
  auth: 'session',
  handler: function (request, reply) {
    var pluginName = request.params.name;
    var username = request.auth.credentials.username;

    if (!username) {
      return reply.unauthorized();
    }

    var getPlugin = function (user) {
      DB.get(pluginName, function (err, plugin) {
        if (err || !plugin) {
          var msg = 'plugin not found';
          return reply.fail(msg);
        }

        plugin.like(user, function (err) {
          if (err) {
            return reply.fail();
          }

          return reply.success();
        });
      });
    };

    var addLike = function (plugin, next) {
      user.like(plugin, function (err) {
        if (err) {
          return next(err);
        }
        next();
      });
    };

    Async.waterfall([
      getPlugin,
      addLike
    ], function (err, result) {
      if (err) {
        return reply.fail(err);
      }
      return reply.success(result);
    });
  }
};
```

## Uploading files

Because we're receiving a file, we have chosen to create readStream so that we can pipe the output directly to a file, database, or whatever storage method that's preferred. By moving the file's contents in chunks from the request into the readstream as we receive them, avoiding needing to store the entire file in our memory before storing it somewhere. This saves precious time and memory.

In the payload section of this chapter, we can utilize the request.payload object for methods such as POST. Notice that we're giving specific options on how to handle. A default payload is limited to 1mb. This is to prevent malicious or incompetent users from bringing down your app. Although the default for parsing is raw, we have chosen to include it here. This field tells whether the data will need to be processed gunzipped (decompressed) or raw. true gunzip means the file will be processed.

A few mime-types are supported and looking at the "encrypt" at our form above, we can see that we're using "multipart/form-data". hapi supports the following:

- * application/json
- * application/x-www-form-urlencoded
- * application/octet-stream
- * text/*
- * multipart/form-data

In the handler, we create a writeStream for the file and piping the data to it. Done.

```javascript
module.exports.postUpload = {
  description: 'Post a file',
  payload:{
    maxBytes: 209715200,
    output: 'stream',
    parse: true
  },
  handler: function (request, reply) {
    request.payload.datafile.pipe(FS.createWriteStream("out"));
    reply('yeah, so done.');
  }
};
```
