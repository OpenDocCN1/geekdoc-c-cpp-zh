good-file that logs your output to a file, which can later be processed by a log aggregator (see discussion in Chapter 11). To generate the prod config file, you do the same command as before change the filter to --filter.env=prod. Many times it's convenient during a deploy to generate this on the fly and ensure you have the same valid output before you start up your server. Invalid JSON will result in errors. Also you will see that the optsinterval in $Base get merged for both filters. Confidence can do even more, this should empower you to have one configuration for your hapi server you can easily maintain your environments. Using confidence in combination with rejoice (which uses glue) will keep your ever-changing environments manageable.

# Server methods

You may want to register methods that are available everywhere on the server for access. Doing this is very easy as shown.

```
server.method('spumko', function (next) {
  console.log('the hapijs project was');
  console.log('originally called spumko');
  return next(null, 'called');
}
```

The server methods are then accessed via the server.methods object.

```
server.methods.spumko(function (err, result) {
  console.log(result); // prints "called"
}
```

You may not want to your method to provide a callback. If so, you can toggle this behavior in one of the options.

The additional options that are available are bind, cache and generateKey.
