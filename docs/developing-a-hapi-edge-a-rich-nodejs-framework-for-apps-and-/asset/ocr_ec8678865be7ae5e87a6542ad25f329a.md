Joyent has made an effort to improve the debugging node.js on SmartOS by adding commands to mdb that can be loaded after a Node core is loaded. In Node 0.12.0 and later there are also commands, such as dcms, which include nodebuffer, jfunctions, jsource, jsource and v8internal. This is part of the great list which are findobjects, jstack, and jsprint among others.

You can use mdb by attaching to a process or by passing a file in the core argument. Generally, you will find that you are looking at an existing core file. If you are attaching to a process you need to pass the p argument to mdb. If you are attached or a core is loaded you should load the v8 support into mdb by typing :load v8. If you need to load a specific v8.so you can point to the full file path. Here is what this process looks like:

```
# mdb corefile
Loading modules: [ libumem.so.1 libc.so.1 ld.so.1 ]
> :load v8
V8 version:3.14.5.9
Autoconfigured V8 support from target
C++ support demangling enabled
```

Generally, the next step is to investigate the stack at the time core was. To do this you use the dcmd jsstack to the stack. To get extra information for the stack you should pass in the -v argument for verbose mode. This will print the stack trace with related addresses for the stack. These items in memory can be inspected further by passing the address to the : :jsprint dcmd. The next example demonstrates taking a jsstack and passing it into jsprint and displaying the result.

```
> ::jsstack -v
d7fff8bc0 0x4a1afaca2c8 <anonymous> (as Agent.addRequest)
(61ef064b3aal)
file: http.js
arg1:67d992c1fd1 (JSONObject)
arg2:67d992c2041 (SeqAsciiString)
arg3:3b0000000 (SMI: value = 443)
arg4:60bc59304121 (Odball: "undefined")
...
> 61ef064b3aal::jsprint
function <anonymous> (as Agent.addRequest)
```
