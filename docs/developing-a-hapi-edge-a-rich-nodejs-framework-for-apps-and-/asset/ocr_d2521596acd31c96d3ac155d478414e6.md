You will notice that there is validation on the response. A schema is provided for what each of these values should be. We have chosen not to separate it out since it is small and easier to read together.

For hapi-plugins.com, once the results are returned from the database, they are converted to an output format where extraneous data is removed and converted to only what is needed. This data is validated through this response schema, which is making sure each item in the array is the expected results.

We can sleep peacefully at night.

# Generic data validation with joi

Not only do we use joi for validating inputs and outputs, we also use it internally for verifying all kinds of data. Let's say we're making a call to an external service, or just to the database. While our data is hopefully not polluted with partial data that gives errors, it never hurts to be careful and validate the data if you're relying on some-where downstream.

So we're covering all the cases with our validation with hapi-plugins.com and there is a lot more joi than what we've seen so far. We'll dedicate some time here to look at what else joi has to offer.

One property that should be remembered is joi is chainable, which means that you can create shortcuts for yourself.

So imagine you are validating a specific string, maybe an email Joi.string().email().email() or something more complicated that's a longer string. You could, instance, assign email to a shorter variable:

```
var email = Joi.string().email() and use this everywhere instead of the longer version.
```

The author was working on lists: lists, wedding registries, bakery registries, etc., and had to make sure a proper list type was being sent each time. This is the validation which was used:

```
Joi.string().insensitive().required().valid(['BR', 'SFL', 'WR', 'WL']),
```

In this case we're not caring about the case but we did care that the string needs to be one of the different list types. Otherwise it was invalid.
