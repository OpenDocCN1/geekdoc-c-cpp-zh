We begin with a convenience function called load(). The purpose of load is to go through all the files in a given directory and require those files. In addition, we're exposing the required handler files under the handler name. These then are used in lib/handlers.js to access the handlers for the routers.

The plugin object that's sent to the register function is nothing else than the object itself. The context of it is referred to as plugin here.

plugin.expose is a function to make the plugin available to the server object via server.plugins[name]. In this particular case it's not likely needed since we're going to use the handlers in the routes file, however it's good practice to expose the plugins so they can be used in the application.

The plugin is also getting some attributes set to it. Typically this can be set to the package.json, but if you want to keep it minimal, or for some reason don't want to use the package.json, then you can just set it with an object that has the name and version properties:

```
exports.register.attributes = {
name: 'handlers',
version: '1.0.0'
};
```

This is all there is to most of the plugins. There are a few more things to say about plugins that we use, however.

In addition to expose, we also tend to use plugin.dependency as well as plugin.bind.

Let's for example say that you're relying on other third-party plugin for some setup that you're doing in your own plugin. This plugin.dependency comes into play. The dependencies are checked on a per-connection basis. So even if you have the dependencies loaded for one connection, if you don't have it on the other connection where it's used, hapi will throw an error: Plugin *api* missing dependency controllers in connection: http://0.0.0.0:8088.
