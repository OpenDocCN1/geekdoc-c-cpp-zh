# path

Paths are divided into segments by the / character. That means that anything not part of is a segment.
It's important to note early that parameters per segment are not allowed. Because of the hapi rule to always have the routes in a predictable order, hapi does not support any sort of regular expression syntax because it becomes difficult to tell when paths overlap. But what hapi allows is using both optional parameters, wildcard parameters and match multiple segments of a path.

The named parameterized by parts of the path are identified using curly brackets as shown: /fixed/:name. In the handler, the request object will have a params object. You should use the name parameter in the handler with request.params.name. We will cover more details on the request object in Chapter 4.
