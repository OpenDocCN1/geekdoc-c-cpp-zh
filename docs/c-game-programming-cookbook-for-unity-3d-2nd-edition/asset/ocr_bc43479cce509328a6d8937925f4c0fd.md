Above, several hashtables are used to store and access the data this script needs to use. Hashtables have a key and a value, which makes them ideal for storing player related info or objects. Instead of using an index number, as you do with an array, you can provide a key and get access to its associated value. In this case, each player's unique ID is used to store data about the state of each player, and we can use a player ID to quickly get data back out again.

In this class, we use hashtables for:

Race positions – Each player's race position is stored as an integer.

Race laps – Each player's current lap number is stored as an integer.

Race finished – When a player crosses the finish line after completing the set number of laps (held in the variable totalLaps), an entry into the raceFinished Hashtable will be set to true. Otherwise, it will be false.

Race controllers – Here, we store references to a RaceController Component attached to each player.

All the above hashtables use the player ID as a key.
