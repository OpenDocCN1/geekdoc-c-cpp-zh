As an illustration, let’s reimplement the trampoline in Java, a language with no tail-call optimization at all (yet):⁴

```
interface Computation<A> {
  A result();

  static <T> Computation<T> done(T value) {
    return new Done<>(value);
  }

  static <T> Computation<T> call(Supplier<Computation<T>> thunk) {
    return new Call<>(thunk);
  }
}

record Done<A>(A value) implements Computation<A> {
  public A result() {
    return value;
  }
}

record Call<A>(Supplier<Computation<A>> thunk) implements Computation<A> {
  public A result() {
    Computation<A> calc = this;
    while (calc instanceof Call<A> call)
      calc = call.thunk().get();
    return calc.result();
  }
}
```

Listing 14.4: Trampoline for tail-call optimization in Java.

The approach is the same as Listing 14.2. The Java type Supplier<T> corresponds to a function with no argument and return type T. To help build trampolines, two helper functions, done and call, are defined as before. Because Java does not support any tail recursion optimization, the evaluation of the trampoline in method result uses a regular while-loop. It performs the same computation as the Scala variant.

The even–odd example can now be rewritten in Java:

```
Computation<Boolean> isEven(int n) {
  if (n == 0) return done(true);
  else return call(() -> isOdd(n - 1));
}
```
