By contrast, code that relies on the Java or Kotlin standard libraries requires a full copy of the set, either when adding or when returning the entire collection. In the following Java and Kotlin variants, for instance, you need to copy the entire set—with the lock owned—inside method all:

```
Java
public class SafeSet<A> {
    private final Set<A> elements = new java.util.HashSet<>();

    public synchronized int add(A elem) {
        elements.add(elem);
        return elements.size();
    }

    public synchronized Set<A> all() {
        return Set.copyOf(elements); // full copy here
    }
}
```

```
Kotlin
class SafeSet<A> {
    private val elements = mutableSetOf<A>()

    @Synchronized fun add(elem: A): Int {
        elements += elem
        return elements.size
    }

    @Synchronized fun all(): Set<A> = elements.toSet() // full copy here
}
```

These implementations of all would be incorrect:

```
Java
// DON'T DO THIS!
public synchronized Set<A> all() {
    return Collections.unmodifiableSet(elements);
}
```

```
Kotlin
// DON'T DO THIS!
@Synchronized fun all(): Set<A> = elements
```
