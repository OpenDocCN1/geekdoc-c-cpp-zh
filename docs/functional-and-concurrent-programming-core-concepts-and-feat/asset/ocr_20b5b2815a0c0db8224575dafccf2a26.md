Because the set being returned is (or contains) a reference to the internal set, these implementations would potentially result in unsafe interactions between a writing thread (with the lock owned) and a reading thread (without the lock).

In contrast, if you use Kotlin’s immutable sets, you can make all efficient—but now add requires a full copy of the entire set:

```
class SafeSet<A> {
    private var elements = setOf<A>() // an immutable set

    @Synchronized fun add(elem: A): Int {
        elements += elem // full copy here
        return elements.size
    }

    @Synchronized fun all(): Set<A> = elements
}
```

Scala’s variant uses an efficient “+” method on immutable sets—the sets elements and elements + elem share data—that is not available in Kotlin’s standard library.

# A.12 Thread Pools

JVM thread pools, defined in java.util.concurrent, can be used directly in all three languages. For instance, the Scala code in Listing 21.4 uses a thread pool in a server:

```
exec.execute(() => handleConnection(socket))
```

It could be written in Java as

```
exec.execute(() -> handleConnection(socket));
```

or in Kotlin as

```
exec.execute {
    handleConnection(socket)
}
```
