The answer to the question is that we overwrote the actual oldest sample, x (n-D), when we wrote in x (n). This is one of the reasons for our rule about always performing reads before writes in our algorithms. This means that to get the oldest sample in the delay, you must first read out pBuffer[i] before writing into it. In other words, before the write access, the buffer looks like Figure 7.6; you can see the oldest value x (n-D) is actually the location of the current write operation.

The steps for creating the delay line in your plug-in are as follows:

+   1. Decide on the maximum amount of delay you need to provide.
+   2. Declare read and write index values.
+   3. Declare a float buffer for each channel, right and left: for very long delay lines this is traditionally done with the new operator in the constructor of the plug-in.
+   4. Initialize the buffers with 0.0 using the memset() function.
