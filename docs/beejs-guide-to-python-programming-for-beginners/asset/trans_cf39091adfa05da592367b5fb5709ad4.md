```python
s = 'Bears, beets, Battlestar Galactica'

```

那里的返回值 7 是“好”的数据。我们要求一个东西，我们得到了它。但如果出了问题怎么办？

```python
s = 'Bears, beets, Battlestar Galactica'

x = s.find('Dwight')

print(x)  # -1, because the substring isn't found
```

这里的 -1 是我们用来告诉我们是否有错误的哨兵值。

我们可以在此基础上做出决定。这就是我所说的“经典”错误处理。这就是人们在建造巨石阵时处理错误的方式。而且，就像巨石阵一样，这种错误处理方法至今仍在使用。如果它没有坏，就不要修它。

好吧，是的，我承认巨石阵坏了。让我说我的比喻！

```python
s = 'Bears, beets, Battlestar Galactica'

x = s.find(substring)

if x == -1:
    print(f"Couldn't find {substring}")
else:
    print(f"Found {substring} at index {x}")
```

好了！我们以经典的方式成功处理了错误。

## 14.5 使用异常进行错误处理

问题解决步骤：理解问题

异常是表示出了问题另一种方式。

我们已经见过一些这些。例如，如果我们运行执行以下操作的代码：

```python
int("Hello!")  # Convert Hello! to integer
```

Python 会不高兴。“Hello!”不是它听说过的数字。当我们运行它时，我们会得到这条消息，程序退出：

```text
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: invalid literal for int() with base 10: 'Hello!'
```

这就是异常的实际作用。我们尝试了一些代码，它引发了异常来告诉我们我们正在做的事情根本行不通。

异常因 Python 中的各种原因而被引发（有时也称为抛出）。

尝试打开一个不存在的文件进行读取：

```text
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
FileNotFoundError: [Errno 2] No such file or directory: 'keyser_soze.txt'
```

尝试将一个数字除以零：

```text
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ZeroDivisionError: division by zero
```

你看到的异常最后一行的那些第一个缩写词？那就是发生的异常的名称。

```text
ValueError
FileNotFoundError
ZeroDivisionError
```

因此，就像使用返回值来指示错误一样，异常也指示发生了错误。

现在——我们如何检测它并做些什么？

## 14.6 捕获异常

问题解决步骤：理解问题

请耐心，因为这段代码在执行方式上有点不同。

我们将结合使用两个新语句：`try` 和 `except`。让我们直接用一个可以剖析的例子开始：

```python
try:
    x = input("Enter a number: ")
    x = int(x)  # Convert to integer
    print(x * 1000)
except ValueError:
    print(f'error converting "{x}" to integer')
```

那里发生了什么？先看大块。我们有一个 `try` 块和一个 `except` 块。

把 `try` 块想象成在用户每次都输入正确信息的那种光鲜梦幻世界中你想要执行的代码。

就像用户输入 3490，然后它顺利转换为整数，然后你打印出 3490000。

完美。

但如果用户输入 beans 而不是数字呢？`int()` 会大发雷霆并引发 `ValueError`，就像我们之前看到的那样。

这里的魔力是，如果发生了这种情况，`try` 块的执行会立即停止，Python 将控制权转移到匹配的 `except` 块（如果存在）。

例如，这里是一个成功的运行：

```text
Enter a number: 3490
3490000
```

这里是一个引发异常的运行：

```text
Enter a number: beans
error converting "beans" to integer
```

你看它如何直接转移控制到 `except` 块中？

这就是我们处理异常的方式！
