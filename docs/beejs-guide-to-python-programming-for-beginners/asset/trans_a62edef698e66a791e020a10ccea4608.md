|---|---|

```

换句话说，内存中只有一个值为 [1, 2, 3] 的列表。它同时被 x 和 z[0] 引用。两个变量引用同一个列表。

在那个例子中，我们如何访问列表中的列表元素？

我们将再次使用方括号表示法，而且会更多。

```
x = [1, 2, 3]
y = [4, 5, 6]
z = [x, y]

print(z[0]) # z[0] refers to x, so this prints [1, 2, 3]
print(z[1]) # z[1] refers to y, so this prints [4, 5, 6]
```

到目前为止还不错？

这里需要注意的是：由于 z[0] 和 z[1] 是列表，你可以通过再次使用方括号表示法来访问这些列表中的元素。

让我们尝试从第二个列表中取出数字 6。

```
print(z[1][2]) # prints 6
```

拆解这行代码。发生了什么？

首先 Python 评估它遇到的第一个方括号。它知道 z 是一个列表，因此它评估 z[1] 得到列表 [4, 5, 6]。然后它取该列表并用 [2] 评估它，从而取出 6。

另一种思考方式是想象使用括号：

```
(z[1])[2] # first evaluate z[1], then evaluate [2] on the result
z[1][2]   # this is equivalent to the previous line
```

（虽然 Python 不介意你这样使用括号，但程序员不会这样做，因为它会让代码看起来很混乱。）

但这给了我们什么？列表的列表很令人兴奋之类的。（对吧？）它们有什么用？

拥有列表的列表实际上为你能表示的数据增加了第二个维度。单个列表可以表示一行数据，而列表的列表可以表示多行或数据网格。

在计算中，网格或多行数据用在哪些地方？

```

另一种技术，分解子问题，是我们一直在做的变体的。

让我们从高层次的伪代码开始，然后在需要的地方进行分解。

```
while not quit:
    print map and player indicator
    get input
    make sure input is valid
    make sure we're not moving through walls
```

我们如何知道分解子问题对这个伪代码有用？第一个线索是有些步骤是实质性的，例如“print map and player indicator”立刻会让人想到问题，“我们到底怎么做到这一点？”

如果任何步骤过于复杂或不明确，就意味着你必须进一步分解它们。让我们对所有不明确的部分都这样做：

```
while not quit:
    print map and player indicator
    for each row of the map:
        for each column of the map:
            if this is where the player is:
                print @
            else:
                print the map character

    get input
    make sure input is valid

    if input invalid:
        print error message

    elif input is "q":
        quit

    else:
        figure out the new row and column of the player

    if the map at the new player position is "#":
        print "You can't go that way."
    else:
        set the current position to the new position
```

这好多了。翻译成 Python 会容易得多。
