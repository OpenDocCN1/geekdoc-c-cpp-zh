
我们希望编写一个应用，能够打印出任意指定之人父母的出生日期。

示例：

```
Enter a name (or q to quit): Beej Jorgensen
Parents:
    Mom Jorgensen (1970)
    Dad Jorgensen (1965)
```

因此，我们需要某种方式来存储这些数据，并且需要某种方式来查找数据中引用的其他人的信息。

是的，我们可以使用人员列表并直接搜索，但有一种不那么笨拙的方式可以做到这一点。

本章主要讨论如何存储这类数据。

## 9.3 什么是字典？

问题解决步骤：理解问题。

还记得对于列表，我们可以用索引编号作为键来从列表中获取值，也可以用相同的索引编号将内容存储到那个“槽位”中吗？

对于存储按编号索引的信息集合来说，这确实很方便，对吧？

那么，如果你想用一个不是数字的东西来引用某个槽位呢？如果你想使用，比如说，一个字符串，如下所示？

```
x = [1, 2, 3]
x["beej"] = 3490  # Not going to work with a list
```

这会让 Python 不高兴，因为 "beej" 不是整数。而列表需要的是整数。

但我们可以用字典（简称 dict）来绕过这个限制。

声明字典的方式稍有不同，但这里有一个简单的入门示例：

```
d = {}  # Squiggly braces, not square brackets!
d["beej"] = 3490
print(d["beej"])  # 3490
```

用法上非常相似，尽管变量的初始声明方式与列表不同。

对于字典，方括号中的值称为键，存储在那里的值称为值。

```
# key      value
# |         |
# ---      -----
d["goats"] = "awesome"
```

你使用键来查找字典中的值，或者在字典中设置值。

键可以是任何不可变类型（例如整数、浮点数、字符串）。值可以是任何类型。

## 9.4 初始化字典

问题解决步骤：理解问题。

如上所述，你可以像这样初始化一个空字典：

```
d = {}
```

但你也可以用多个键和值来预初始化字典：

```
d = {
    "name": "Bee",
    "age": 29,  # ish
    "favorite OS": "windows",
    "no really, favorite OS": "linux"
}
```

这相当于手动设置它们，尽管简洁一些：

```
d = {}
d["name"] = "Bee"
d["age"] = 29  # ish
# etc.
```

如果你有 Web 开发背景，你可能遇到过 JSON 格式的数据。Python 字典在格式上与其非常相似，但并不完全相同。

## 9.5 速度狂魔

问题解决步骤：理解问题。

与列表一样，字典在查找信息方面非常快速。事实上，平均而言，从字典中获取一个值所需的时间是相同的，无论字典中有多少项。

请记住这一点。接下来我们会遇到更复杂的问题，可以利用这一特性让你的程序保持快速运行。轰！

## 9.6 这个字典有这个键吗？

问题解决步骤：理解问题。

如果你有一个字典，能够检查某个键是否存在是很有用的。

实现这一点的秘诀是 in 语句，它会返回一个布尔值，指示某个键是否在字典中。

```
d = {
    "a": 10,
    "b": 20
}

if "a" in d:
    print(f"key a\'s value is: {d[\"a\"]}")

if "x" not in d:
    print("There is no key \"x\" in d")
```

还有一种使用 .get() 方法从字典中获取条目的方法。如果键不存在，该方法会返回默认值 None。

```
val = d.get("x")

if val is None:  # Note: use "is", not "==" with "None"!
    print("Key x does not exist")
else:
    print(f"Value of key x is {d[x]}")
```

```

如果你有一组键/值对列表，你也可以很容易地将它们读入字典。

```
a = [["alice", 20], ["beej", 30], ["chris", 40]]
d = { k: v for k, v in a }
print(d) # {'alice': 20, 'beej': 30, 'chris': 40}
```

## 9.10 字典的字典

问题解决步骤：理解问题。

是这样的：你为给定键存储的值可以是任何东西！

嗯，不是鲸鱼或火星，而是任何数据类型。所以，你可以将字符串、整数、浮点数、列表，甚至其他字典存储为字典键的值！

看看这个嵌套声明，以及我们如何逐层深入字典层来获取数据：

```
d = {
  "a": {
    "b": "Mars! Ha!"
  }
}
print(d)      # {'a': {'b': 'Mars! Ha!'}}
print(d["a"])   # {'b': 'Mars! Ha!'}
print(d["a"]["b"]) # Mars! Ha!
```

像这样嵌套字典可能是一种非常强大的数据存储方法。

## 9.11 字典是可变的

问题解决步骤：理解问题。

当你对一个字典进行赋值复制时，复制的是对同一个字典的引用，而不是创建一个新字典。就像列表和其他任何东西一样。

这一点很重要，因为字典和列表一样，都是可变的。

```
d = { "beej": 3490 }
e = d  # both e and d refer to the same dict!
e["beej"] = 3491  # modify it
print(d["beej"])  # 3491
```

如果你想复制一个字典，可以使用以下任一方法：

```
d = { "beej": 3490 }
e = d.copy() # make a copy, the preferred way
e = dict(d)  # make a copy
```

第一种方式是首选，因为它更容易阅读，而易于阅读的代码就是快乐代码™。

此时正确的做法是回到规范的创建者那里，确切地问清楚在这种情况下应该发生什么。

问题解决步骤：再次理解问题

答案：打印出这样的错误信息：

```

问题解决步骤：再次制定计划

我们使用以下代码来获取一个人的记录：

```python
record = tree[name]  # Look up the record in the outer dict
```

但正如我们所见，如果 name 不是字典中的有效键，这会抛出异常。

我们如何处理这种情况？有几种方法。其中一种涉及捕获异常，但我们将在后面的章节中详细讨论。

我们在本章前面讨论过的做法是对字典使用 .get() 方法。它会返回记录；如果键在字典中不存在，则返回 None。然后我们可以对此进行测试，并打印一些错误信息。

问题解决步骤：再次执行计划

```python
record = tree.get(name)  # Look up the record in the outer dict

if record is None:  # Use "is" when comparing against "None"
    print(f'No record for "{name}"')
    continue

mother_name = record["mother"]  # Extract parent names from inner dict
father_name = record["father"]

print("Parents:")
print(f'    {mother_name}')
print(f'    {father_name}')
```

现在我们很接近了。但我们仍然缺少一大块：父母的出生年份。

获取他们的名字是小菜一碟：它就在我们要查找之人的记录中。但他们的出生年份不在那里。

我们如何获取它们？

问题解决步骤：再次制定计划

我们有父母的名字。仅此而已。

我们如何从名字得到出生年份？

看起来 “Beej Jorgensen” 的记录中列出了出生年份……

```
if mother_record is not None:
    mother_born_date = mother_record["born"]
else:
    mother_born_date = "missing record"

# Get the birth year of the father; note if missing
if father_record is not None:
    father_born_date = father_record["born"]
else:
    father_born_date = "missing record"

print("Parents:")
print(f'    {mother_name} ({mother_born_date})')
print(f'    {father_name} ({father_born_date})')
```

就这样！

问题解决步骤：回顾

我们还能做得更好吗？这个应用有哪些缺点？

看看我们用来存储数据的字典结构。怎么能更好？想想家谱中存在的所有情况。当然，我们覆盖了常见情况，但被收养的孩子呢？我们如何建模？离婚呢？再婚呢？事实证明，为家谱建模远比你可能最初预期的要复杂得多。

如果两个人同名怎么办？在真实的族谱中，完全有可能出现多个 Tom Jones⁸。但既然我们使用名字作为字典的键，而键必须是唯一的，因此，名字不能作为键——必须用唯一的东西。

一种选择是使用 UUID⁹ 作为键，并以某种方式将该 UUID 映射到名字。也许你有另一个字典，对于给定的名字，存储代表同名人员的一组 UUID。然后，如果存在多个 Beej Jorgensen，我们可以问用户：“您是指 1971 年、1982 年、1997 年还是 2003 年出生的 Beej Jorgensen？”（你可以通过导入 uuid 包并运行 uuid.uuid4() 来创建随机 UUID。）

这里有很多改进的选择！
