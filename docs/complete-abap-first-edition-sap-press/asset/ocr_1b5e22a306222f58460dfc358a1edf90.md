+   - **Trace Overview** — This option provides various database access statistics, such as time spent on `SELECT`, `INSERT`, or `COMMIT` or the number of times these statements were executed. It also provides suggestions to address any unnecessary database access.
+   - **Sizing Information** — This view provides information about the data volume, such as the number of records inserted, modified, or deleted per table and the size of the tables.

Along with ABAP Trace, the SQL trace is an important tool that can provide great insight into database access. We recommend that you start your analysis from the tables that take up a long runtime and branch out to other views.

# 21.8.3 RFC Trace

The *RFC trace* allows you to check the RFCs that are executed between instances. This trace records both incoming and outgoing RFC calls. Using this trace, you can identify the time the programming is spending with RFC calls and therefore identify bottlenecks.

Among other things, using the RFC trace helps to analyze the following:

+   - Different function modules called remotely by the program
+   - Execution status of the RFC (i.e., if the RFC was executed successfully)
+   - The total time taken for processing the RFC call
+   - The size of the data sent and received during the RFC call
+   - Information about the instance for which the RFC call was executed
+   - The technical parameters of the instance

The RFC trace display view is similar to the SQL trace view and allows you to check information about each action. The important details are the duration it took to execute the RFC, the program that executed the RFC, and details about the client and the server.

The system differentiates between client and server RFCs. The client calls the RFC, and the server executes the RFC.
