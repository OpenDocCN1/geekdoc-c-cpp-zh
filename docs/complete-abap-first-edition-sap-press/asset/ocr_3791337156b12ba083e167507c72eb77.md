Certain naming conventions are followed when creating packages. Table 2.7 lists the naming conventions used for packages.

| Package Naming Convention | Explanation |
|---|---|
| Names beginning with a letter from A to S or from U to X. | ▸ Package names beginning with these letters are reserved for standard SAP objects; customer objects cannot be created in these packages.<br>▸ The objects in these packages can be transported as the Transport Organizer records changes to the objects in these packages. As shown in Figure 2.10, these packages belong to the SAP transport layer and are assigned to an SAP software component (e.g., SAP_BASIS, SAP_APPL, etc.). |
| Names beginning with Y or Z | ▸ Customer objects are created in these packages; the objects in these packages can be transported as the Transport Organizer records changes to the objects in these packages.<br>▸ These packages are assigned to the software component HOME. |
| Packages belonging to a prefix namespace | ▸ The objects in the prefix namespace begin with a forward slash (/). Like other repository objects (such as programs, tables, etc.), packages can also belong to a prefix namespace.<br>▸ Customer objects are created in these packages; the objects in these packages can be transported as the Transport Organizer records changes to the objects in these packages. |
| Names beginning with T (private test packages) | ▸ These packages allow you to create objects in a customer namespace (Y or Z) or objects from the prefix namespace (objects starting with /).<br>▸ This package doesn't belong to a transport layer, so the objects in this package can’t be transported using the Transport Organizer. However, if the package is linked to the Transport Organizer, the objects are recorded in nontransportable local requests. |
