
If you do not supply a select-expression, each WHEN statement is evaluated to determine if the when-expression is true or false. As an example, here is Program 7.5, rewritten with a SELECT statement:

# Program 7.5: Demonstrating a SELECT Statement When a Select-Expression is Missing

```sas
data Conditional;
  length Gender $ 1;
  Quiz $ 2;
  input Age Gender Midterm Quiz FinalExam;
select;
  when (missing(Age)) AgeGroup = ;
  when (Age lt 20) AgeGroup = 1;
  when (Age lt 40) AgeGroup = 2;
  when (Age lt 60) AgeGroup = 3;
  when (Age ge 60) AgeGroup = 4;
  otherwise;
datalines;
```

Note that there is no select-expression in this SELECT statement. Each when-expression is evaluated, if true, the statement following the expression is executed.

## 7.6 Using Boolean Logic (AND, OR, and NOT Operators)

You can combine logical operators (also known as Boolean operators) to form fairly complex statements. As example, the data set contains information on clinic, diagnosis (DX), and weight. A program to list all patients who were seen at the HMC clinic and had either a diagnosis of 7 or 9 weighted over 180 pounds demonstrates how to combine various Boolean operators:

# Program 7.6: Combining Various Boolean Operators

```sas
title "Example of Boolean Expressions";
proc print data=Learn.Medical;
  where clinic = 'HMC' and
  (DX in ('7','9') or
  Weight gt 180);
  id Patno;
  var Patno Clinic DX Weight VisitDate;
run;
```

Note the parentheses around the two statements separated by OR. The AND operator has precedence before the OR operator. That is, a statement such as the:

if X and Y or Z;

is the same as this:

if (X and Y) or Z;

If you want to perform the OR operation before the AND operation, use parentheses, like this:

if X and (Y or Z);

In Program 7.6, you want the clinic to be HMC and you want either the diagnosis to be one of two values or the weight to be 180 pounds. You need the parentheses to first decide either the diagnosis or weight condition is true before performing the AND operation. Even in cases whereas they are not needed, it is fine to include them so that statements are easier to read and understand. The NOT operator has the highest precedence, so it is performed before AND. For example, the statement:

if X and not y or z;

is equivalent to:

if (X and not y) or z;

Here is the output:

# Figure 7.2: Output from Program 7.6

| Patno | Patno | Clinic | DX | Weight | VisitDate |
|---|---|---|---|---|---|
| 004 | 004 | HMC | 9 | 288 | 11/01/2006 |
| 050 | 050 | HMC | 7 | 199 | 07/06/2006 |

## 7.7 A Caution Using OR Operators

Look at the short program here: # Program 7.7: A Caution on the Use of OR Operators

```sas
data Believe_or_Not;
input X;
if X = 3 or X = 4 then Match = 'Yes';
else Match = 'No';
datalines;
3
7;
title "Listing of Believe_or_Not";
proc print data=Believe_or_Not noobs;
run;
```

The programmer probably wanted to say:

if X = 3 or X = 4 then Match = 'Yes';

What happens when you run this program? Many folks would expect to see an error message in the log and would expect the program to terminate. Not so. Here is the output from this program:

# Figure 7.3: Output from Program 7.7

| X | Match |
|---|---|
| 3 | Yes |
| 7 | Yes |

In Program 7.7, there is one condition on either side of the OR operator—one is x = 3, the other is 4. In SAS, any value other than 0 or missing is true. Therefore, X = 4 is evaluated as true always true.

> Note: This bears repeating: Any numeric value in SAS that is not zero or missing is considered TRUE.

## 7.8 The WHERE Statement

If you are reading data from a SAS data set, use a WHERE statement to subset your data. For example, if you started with the data set Conditional (Program 7.3), you could create a data set of all females with the following program:

# Program 7.8: Using a WHERE Statement to Subset a Data Set

```sas
data Females;
set Conditional;
where Gender eq 'F';
run;
```

In this example you could use either a WHERE or a subsetting IF statement. There are sometimes advantages to using a WHERE statement instead of a subsetting IF statement. You have a larger choice of operators that can be used with a WHERE statement (to be discussed next) and, if the input data set is indexed, the WHERE statement might be more efficient. You may also use a WHERE statement in a SAS procedure to subset the data being processed. You cannot use a subsetting IF statement with a SAS procedure.

> Note: IF statements are not allowed inside SAS procedures.

## 7.9 Some Useful WHERE Operators

The table below lists some of the useful operators that you can use with a WHERE statement.

| Operator | Description | Example |
|---|---|---|
| IS MISSING | Matches a missing value | where Subj is missing |
| IS NULL | Equivalent to MISSING | where Subj is null |
| BETWEEN | An inclusive range | where age between 20 and 40 |
| CONTAINS | Matches a substring | where Name contains Mac |
| LIKE | Matching with wildcards | where Name like R_% |
| *= | Phonetic matching | where Name *= Nick |

> **Note:** When using the LIKE operator, the underscore character (_) takes the place of a single character, while the percent sign (%) can be substituted for a string of any length (including a null string).

Here are some examples.

| Expression | Matches |
|---|---|
| where Gender is null | A missing character value |
| where Age is null | A missing numeric value |
| where Age is missing | A missing numeric value |
| where Age between 20 and 40 | All values between 20 and 40 |
| where Name contains 'mac' | mac immaculate |
| where Name like 'R*Nick' | Ron Ronald Run Running |
| where Name *= Nick' | Nick Nack Nicki |

Notes:

- The NULL OR IS MISSING expression matches a character or a numeric missing value.
- The AND expression matches all the values greater than or equal to the first value.
- The CONTAINS expression matches any character value.
- The LIKE expression uses two underscores.
- The percent (%) matches a string of length.
