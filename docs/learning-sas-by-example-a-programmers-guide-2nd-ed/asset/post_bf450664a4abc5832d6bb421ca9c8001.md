## 26.8 An Example of Fuzzy Matching

One of the strengths of PROC SQL is its ability to create a Cartesian product. As mentioned earlier in this chapter, a Cartesian product is a pairing of every row in one table with every row in another table. Here are two tables: Demographic (used in many of the other examples in this chapter) and Insurance.

Figure 26.16: Listing of Data Sets Demographic and Insurance

| Subj | DOB | Gender | Name | Name | Type |
|---|---|---|---|---|---|
| 001 | 10/15/1960 | M | Friedman | Friedman | F |
| 002 | 08/01/1995 | M | Stern | Goldman | P |
| 003 | 12/25/1988 | | McGold | Chein | F |
| 005 | 05/28/1949 | | Chien | Stern | P |

You want to join (merge) these tables by Name, allowing for slight misspellings of the names. Here is an SQL query that does just that:

Program 26.13: Using PROC SQL to Perform a Fuzzy Match

```
title "Example of a Fuzzy Match";
proc sql;
select Subj,
Demographic.Name,
Insurance.Name
from Demographic,
Learn.Insurance
where sperdist(Demographic.Name,Insurance.Name) <= 25;
quit;
```

The SPEDIT (spelling distance) function allows for misspellings (see Chapter 12). The WHERE clause operates on every combination of names from the two tables and selects names that are within a spelling distance of 25. In practice, you would want to compare other variables such as Gender and DOB between two files to increase the likelihood that a valid match is being made. Take a look at the listing that follows to see which names were matched by this program:

Figure 26.17: Output from Program 26.13

Example of a Fuzzy Match

| Subj | Name | Name |
|---|---|---|
| 001 | Friedman | Friedman |
| 005 | Chien | Chein |
| 002 | Stern | Stern |

You could easily modify this program so that the output would not include names that match exactly.

We have only touched the surface of what you can do with SQL. Hopefully, this introduction to SQL will encourage you to learn more.
