## 22.5 Reading Character and Numeric Data in One Step

There is a little-known feature in user-defined informats—the ability to create an informat that reads character and numeric data and creates a numeric variable. The examples that follow show ways that you can take advantage of this feature.

For this example, you have temperatures on hospital patients. Because many of the patients have a normal temperature (98.6 degrees Fahrenheit), it is convenient to convert normal temperatures by entering an N as a data value. Some sample lines of data are as follows:

```
101 N 97.3 n N 104.5
```

Notice that some of the N are in uppercase and others in lowercase. Before we look at the elegant enhanced solution, let's look at a traditional approach:

Program 22.5: A Traditional Approach to Reading a Combination of Character and Numeric Data

```
data Temperatures;
  input Dummy (Dummy) = 'N' then Temp = 98.6;
  else Temp = input(Dummy, 8);
  drop Dummy;
datalines;
101 N 97.3 n N 104.5
```

Each data is read as character data. A check is made to see whether this value is equal to an upper- or lowercase N. If so, Temp is set to 98.6—if not, the INPUT function performs the character-to-numeric conversion. This works fine, but programmers (who, me?) are always looking for a more elegant solution. Program 22.6 uses an enhanced numeric informat:

# Chapter 22: Using Advanced Features of User-Defined Formats and Informats 383

```
proc format;
  invalue Readtemp (upcase)
    96 - 106 = same_
    'N' = 98.6
    other = .;

run;

data Temperatures;
  input Temp : Readtemp5. @@;
  datelines;
  101 97.3 n N 67 104.5
  ;
```

The UPCASE option converts any character to uppercase. The keyword _SAME_ in this format leaves any numeric values in the range 96 to 106 unchanged. Values of N are converted to the numeric value of 98.6 and any values that are not in the range of 96 to 106 or N are set to a numeric missing value. The technique of using the keyword _SAME_ for valid values and setting other values is missing one way to screen unwanted extreme values as they are being read. ## 22.6 Using Formats (and Inormats) to Perform Table Lookup

Table lookup is a process where one or more data values are used to retrieve a value for another variable. For example, given an item number from catalog, you might want to retrieve a product name and a price.

SAS provides you with a variety of ways to perform a table lookup, such as a data merge, a key value from an index, an array, a format hash, or an informat. Because SAS formats are stored in memory, they are fast and efficient. Program 22.8 uses an item number (ItemNumber) to look up a product name and its price. Here is the program:

# Chapter 22: Using Advanced Features of User-Defined Formats and Informats 385

# Program 22.8: Using Formats and Informs to Perform Table Lookup

```
proc format;
  value NameLookup
  122 = 'Salt'
  188 = 'Sugar'
  101 = 'Cereal'
  755 = 'Eggs'
  other = ' ';
invalue PriceLookup
'Salt' = 3.76
'Sugar' = 6.99
'Cereal' = 5.97
'Eggs' = 2.65
  other = .;

run;

data Grocery;
  input ItemNumber @@;
  Name = put(ItemNumber,NameLookup);
  Price = input(Price,PriceLookup);
datalines;
101 755 122 188
```

A user-defined format is used, along with a PUT function, to retrieve a product name from the item number. An informat relating product names, is used with INPUT function to retrieve the price. An informat used for the price because the INPUT function can return a numeric value. Remember that the PUT function always returns a character value. (If you used a format, would have to perform character-to-numeric conversion to obtain a numeric value for the price.)

Both the format and informat use the keyword OTHER to assign a missing value to invalid item code. A listing of data set follows:

## 22.7 Using a SAS Data Set to Create a Format

The example in the last section used only small number of item codes. If you have a large number of values, writing a format statement by hand is tedious. SAS allows you to use a specially constructed data set to create a SAS format. The PROC FORMAT option CNTLIN=(control) allows you to use the SAS data set (or data view) that you want to use.

Control sets require a minimum of three variables, FMTNAME, START, and LABEL. FMTNAME is a variable that specifies the format or informat name; START is either a single value or, if END is also, the beginning of a range. You should include a $ as the first character of FMTNAME if you are creating a character format. Optionally, you can include a variable TYPE that is either c for character formats or N for numeric formats.

Note: There are other values of TYPE for formats and picture formats: I specifies a numeric informat; J a character informat; P specifies a picture format.

If you have data values and labels already stored in a data set, you can use that data set as input to a DATA step (with variables renamed) to create your control set.

This sounds complicated, but an example will make it clear. If you have a permanent SAS data set (Codes) that contains ICD-10 code values (International Classification of Diseases, Version 10) and descriptions. You want to create a format that provides labels for each of the ICD-10 codes. So that you can try this yourself, you create a permanent SAS data set called Codes.

# Program 22.9: Creating a Test Data Set That Will be Used to Make a CNTLIN Data Set

```
data Learn.Codes;
  input ICD10 : $5. Description & $21;
datalines;
020 Plague
022 Anthrax
390 Rheumatic fever
410 Myocardial infarction
493 Asthma
540 Appendicitis
;
```

# Program 22.10: Creating a CNTLIN Data Set from an Existing SAS Data Set

```
data Control;
  set Learn.Codes(rename=
    (ICD10 = Start
    Description = Label));
  retain Fmtname=$ICDFMT
  Type = 'C');

run;

title "Demonstrating an Input Control Data Set";
proc format cntlin=Control fmtlib;
run;
```

Using a RETAIN statement is more efficient than an assignment statement, these values are set at compile time—an assignment statement executes for each iteration of the DATA step.
