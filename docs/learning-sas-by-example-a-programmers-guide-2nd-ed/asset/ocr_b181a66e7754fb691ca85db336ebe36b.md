# 9.3 Reading Values from Text Data

As you saw in Chapter 3, formatted input (or list input with an appropriate informat) allows SAS to read nonstandard numeric data. SAS has built-in date formats that allow you to read dates in any of the forms in the table in Section 9.2 (and) and automatically convert these dates into SAS dates. Let's look at an

You have a data file: C:\\learning\Dates.txt, as shown here:

```
1 2 3
12345678901234567890123456789 Columns
001 10/21/1950 0522203 08/10/65 23Dec2005
002 01/03/1960 1112209 09/13/02 02Jan1960
```

The first three (starting in columns 5, 16, and 25) are in the month-day-year format; the last (starting in column 3) starts with the day of the month, a three-letter month abbreviation, and a four-digit year. Notice that some of the dates include separators between the values, while others do not. Also, the third value is also a two-digit year. Here is a program to read these dates:

# Program 9.1: Program to Read Dates from Text Data

```
Data Dates;
infile 'C:\\learning\Dates.txt' truncate;
input @Subject $3;
  $DOB
  @16 VisitDate mmDDYY8;
  @26 TwoDigit mmDDYY;
  @34 LastDate date;
run;
```

The TRUNCATE option is added to the INFILE statement. You typically need to use the TRUNCOR or PAD option when reading data files with fixed columns (see Chapter 21). Both of these options prevent errors when you have a short report.

Each of the dates is read with an appropriate informat. The first three dates are all in month-day-year format so they use the MMDYY10 informat. The date of birth (DOB) takes up 10 columns, MMDDYY10 is the proper informat to use. The second date (VisitDate) uses a format similar to the DOB, except that there are no separators between the month, day, and year. Therefore, the number of columns occupied by these dates is 8. The third date uses separators between the values but has only two-digit year values (this is illustration purposes only—always use four-digit years). Therefore, these dates also take up 8 columns.
