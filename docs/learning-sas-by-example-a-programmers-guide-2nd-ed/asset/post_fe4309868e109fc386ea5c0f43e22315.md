## 10.13 Merging Two Data Sets with Different BY Variable Types

A slightly more complicated situation occurs when the variable you want to use as the BY variable in a merge is a different data type in the two data sets. SAS performs a merge only when the BY variables in both data sets are the same type—either character or numeric.

As example, two divisions of your company store Social Security numbers differently (they do this to make your life interesting). Division 1 stores the Social Security number as a numeric variable and Division 2 stores the Social Security number as a character variable. This is not an unusual situation. Here are listings of two data sets to demonstrate this:

Figure 10.18: Listings of Data Set Division1 and Listing of Data Set Division2

| SS | DOB | Gender | SS | JobCode | Salary |
|---|---|---|---|---|---|
| 11123333 | 11/14/1956 | M | 111-22-3333 | A10 | 45123 |
| 12345678 | 05/17/1946 | F | 123-45-6789 | B5 | 35400 |
| 98765432 | 04/01/1977 | F | 98-65-4321 | A20 | 87900 |

In this example, not only are the data types different, but one of the data sets (Division2) dashes in the SS values. Luckily, SAS can handle this easily.

You can create a character variable based on the numeric value of SS in the Division1 data set or you can create a numeric variable based on the character variable in the Division2 data set. The following solution uses the first approach:

# Chapter 10: Subsetting and Combining SAS Sets When the BY Variables Are Different Data Types 153

```sas
data Division1C;
set Division1(rename=(SS = NumSS));
SS = put(NumSS,ssn1);
drop NumSS;
run;

data Both_Divisions;
***Note: Both data sets already in order
of BY variable;
merge Division1C Division2;
by SS;
run;
```

Because the two data sets use the same name for the BY variable, first you have to rename this variable and then create a new character variable with the name of SS. The PUT function takes the variable named in the first argument, applies the format in the second argument, and returns the formatted value (see Chapter 11 for details on this function). SSN1 is a built-in SAS format that prints leading zeros and adds dashes as required for Social Security numbers. Thus, the variable in data set Division1 is identical to SS in variable Division2. You can now proceed with the merge in the standard manner. Here is a listing of the resulting data set:

Data Sets Divisions

| DOB | Gender | SS | JobCode | Salary |
|---|---|---|---|---|
| 11/14/1956 | M | 111-22-3333 | A10 | 45123 |
| 05/17/1946 | F | 123-45-6789 | B5 | 35400 |
| 04/01/1977 | F | 987-65-4321 | A20 | 87900 |

You may choose to convert a numeric value from the character value of SS in data set Division2 instead. The choice of method depends on what data type you want in the merged data set. Here is the alternative approach—creating a numeric variable for the merge:

# Program 10.15: An Alternative to Program 10.14

```sas
data Division2N;
set Division2(rename=(SS = CharSS));
SS = input(compress(CharSS,'kd'),9);
***Alternative:
SS = input(CharSS,comma1.);
drop CharSS;
run;
```

Because the character value of SS contains dashes, you first need to use the COMPRESS function to remove the dashes, and then use the INPUT function to perform the character-to-numeric conversion. (You can read about the COMPRESS function in Chapter 12—all you need to know is that this function with the 'k' and 'd' modifiers, takes a character string and "keeps the digits", removing all other characters.) The INPUT function takes the first argument (a character variable), and applies the informat in the second argument, resulting in a numeric variable.

A clever alternative (inspired by a good friend, Mike Zdeb) is to use the comma directly in the INPUT function. It is not commonly known that this informat not removes commas and dollar signs when reading a value, it also removes dashes. You can therefore use the COMMA11, informat in the INPUT function directly without having to remove the dashes. You can now merge data sets Division1 and Division2N as before. We will not bother to show you a listing of the result—it contains a numeric variable called SS.

This is referred to as a one-to-many merge. As an example, suppose you want to merge data set Bert with a data set with multiple values of ID. To demonstrate this, take a look at the following two data sets:

Figure 10.20: Listing of Data Sets Bert and Oscar

| Listing of Data Set Bert | Listing of Data Set Oscar |
| ID | X | ID | Y |
| 123 | 90 | 123 | 200 |
| 222 | 95 | 123 | 250 |
| 333 | 100 | 222 | 205 |
| | | 333 | 317 |
| | | 333 | 400 |
| | | 333 | 500 |

Notice that data set Oscar has multiple observations with the same ID. What happens when you perform a merge? The resulting data set is shown next:

| 123 | 90 | 250 |
