## 9.3 Reading Values from Text Data

As you saw in Chapter 3, formatted input (or list input with an appropriate informat) allows SAS to read nonstandard numeric data. SAS has built-in date formats that allow you to read dates in any of the forms in the table in Section 9.2 (and) and automatically convert these dates into SAS dates. Let's look at an

You have a data file: C:\learning\Dates.txt, as shown here:

```
1 2 3
12345678901234567890123456789 Columns
001 10/21/1950 0522203 08/10/65 23Dec2005
002 01/03/1960 1112209 09/13/02 02Jan1960
```

The first three (starting in columns 5, 16, and 25) are in the month-day-year format; the last (starting in column 3) starts with the day of the month, a three-letter month abbreviation, and a four-digit year. Notice that some of the dates include separators between the values, while others do not. Also, the third value is also a two-digit year. Here is a program to read these dates:

## Program 9.1: Program to Read Dates from Text Data

```
Data Dates;
infile 'C:\learning\Dates.txt' truncate;
input @Subject $3;
  @5 DOB
  @16 VisitDate mmDDYY8;
  @26 TwoDigit mmDDYY;
  @34 LastDate date;
run;
```

The TRUNCATE option is added to the INFILE statement. You typically need to use the TRUNCATE or PAD option when reading data files with fixed columns (see Chapter 21). Both of these options prevent errors when you have a short report.

Each of the dates is read with an appropriate informat. The first three dates are all in month-day-year format so they use the MMDYY10 informat. The date of birth (DOB) takes up 10 columns, MMDDYY10 is the proper informat to use. The second date (VisitDate) uses a format similar to the DOB, except that there are no separators between the month, day, and year. Therefore, the number of columns occupied by these dates is 8. The third date uses separators between the values but has only two-digit year values (this is illustration purposes only—always use four-digit years). Therefore, these dates also take up 8 columns. Finally, the last date uses the day of the month, a three-letter month abbreviation, and a four-digit year. The number of columns used for these dates is 9, and the informat is DATE.

Each of these dates is read with an appropriate SAS informat. As these dates are read, SAS converts all of the dates to their corresponding numerical value. To see this, there is a listing, produced by PROC PRINT:

## Figure 9.1: Listing of Data Set Four_Dates

| Subject | DOB | VisitDate | TwoDigit | LastDate |
| --- | --- | --- | --- | --- |
| 001 | -3359 | 15837 | 2048 | 16793 |
| 002 | | 18213 | 15596 | 1 |

The numbers in this listing represent the internally stored values for the four dates that SAS read the raw data and converted. These values are stored the same way SAS stores numeric values.

You can choose any SAS format to display these dates—they do not have to match the informat that used to read the dates. To demonstrate this, the next program adds a FORMAT statement in the DATA step, as follows:

## Program 9.2: Adding a FORMAT Statement to Each of the Dates

```
data Four_Dates;
infile 'C:\learning\Dates.txt' truncate; @1 Subject $;
  @5 DOB mmDDYY10;
  @16 VisitDate mmDDYY8;
  @26 TwoDigit mmDDYY8;
  @34 LastDate date;
  format DOB date;
  TwoDigit LastDate mmDDYY10.
run;
```

Again, it is important to separate the way dates are read from the way you choose to display them. Here is the listing, formatted values:

## Figure 9.2: Listing of Four_Dates with Formatted Dates

| Subject | DOB | VisitDate | TwoDigit | LastDate |
| --- | --- | --- | --- | --- |
| 001 | 21OCT1950 | 12MAY2003 | 08/10/1965 | 12/23/2005 |
| 002 | 01JAN1960 | 12NOV2009 | 09/13/2002 | 01/02/1960 |

There are several things to notice how SAS reads these date values. First, two of the dates (VisitDate and TwoDate) used the same informat (MMDDYY8) because both dates occupied 8 columns. SAS was clever enough to realize that VisitDate did not use delimiters, so the year must have four digits. The values for TwoDate did include delimiters; the year must have two digits. All of these would have been read correctly if the day of the month did not include zero.

Next, notice the values for TwoDigit in this listing. The first observation shows the year as 1965, while the second observation shows the year as 2002. How did SAS figure out whether to make the first two digits 19 or 20? Whenever you use a two-digit year, it is impossible to know if the date is from 1900 to 1999 or from 2000 to 2999 (or some other century). There is a system option called YEAROFF that enables SAS to compute these values. The default value for this option was 1920 in SAS 8 and is 1926 in SAS 9.4. This value determines the start of a 100-year interval that SAS uses when it encounters a two-digit year. With a YEAROFF of 1926, all two-digit years are in the interval from 1926 to 2025. That is why the first date (8/10/1965) is given the value 8/10/1965 and the second date 9/13/2002.

> Note: If you use four-digit years in your data, the YEAROFF option has no effect. Always use four-digit years.

## 9.4 Computing the Number of Years between Two Dates

Suppose you want to compute a person's age, given his or her date of birth. The following program uses the Four_Dates data as input and computes the subject's Age as of the visit date (VisitDate):

## Program 9.3: Compute a Person's Age in Years

```
data Ages;
    set Four_dates;
    Age = yrdif(DOB,VisitDate);
run;
title "Listing of Ages"
proc print data=Ages noobs;
run;
```

Program 9.3 uses a SAS function, YRDIF, to compute the difference in years between the date of birth and the visit date. Here is the listing:

## Figure 9.3: Output from Program 9.3

Listing of Ages
| DOB | VisitDate | Age |
|---|---|---|
| 21OCT1950 | 12MAY2003 | 52.5562 |
| 01JAN1960 | 12NOV2009 | 49.8630 |

If you want the Age as the person's last birthday (dropping any fractional part of a year), you can use the INT (integer) function:

```
Age = int (yrdf (DOB,Visit));
```

If you want to round the Age to the nearest year, you can use the ROUND function:

```
Age = round(yrdf (DOB, VisitDate));
```

You may see the following expression in some older programs:

```
Age = (VisitDate - DOB) / 365.25;
```

This expression gives an approximate value for the number of years between two dates (the .25 accounts for a leap year every four years). Because the YRDIF function has the ability to return an exact value, you should use it rather than this expression.

## 9.5 Demonstrating a Date Constant

How do you compute a person's age as of certain date, January 1, 2017, for example? You need to be able to enter this date constant. The general form of a date constant is day of the month, a three-letter abbreviation, and a four-digit year, in single or double quotation marks, followed by a d. This is the only form allowed as a date constant: '01Jan2017'.

Rewriting Program 9.3 to compute Age as of January 1, 2017, you have the following program:

## Program 9.4: Demonstrating a Date Constant

```
data Ages;
    set Four_Dates;
    Age = yrdif(DOB,'01Jan2017');
run;

title "Listing of Ages";
proc print data=Ages;
    format Age 5.1;
run;
```

In this program, a date constant represents the date January 1, 2017. This program also formats Age so that it prints the value to the nearest 1th.

## 9.6 Computing the Current Date

Suppose you want to compute a quantity based on the current date. The TODAY function returns the value of the current date. Here is an example where the current date is substituted for January 1, 2017, in Program 9.4:

## Program 9.5: Using the TODAY Function to Return the Current Date

```
data Ages;
    set Four_Dates;
    Age = yrdif(DOB,today());
run;
```

Even though you do not pass any arguments to the TODAY function, the parentheses, function name are required (so that SAS can tell you want to use the function rather than a variable Today). The DATE function performs an identical task as the TODAY function. Feel free to use either name.
