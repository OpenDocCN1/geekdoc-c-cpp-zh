# 3.11 Using a FORMAT Statement in a DATA Step versus in a Procedure

Program 3.8 and 3.9 demonstrated using a FORMAT statement in a procedure. Placing a FORMAT statement here associates the formats and variables only for that procedure. It is usually useful to place your FORMAT statement in the DATA step. When you do this, there is a permanent association of the formats and variables in the data set. You can override any permanent format by placing a FORMAT statement in a particular procedure where you would like a different format. You will usually want to place all your dates in a DATA step because no one wants to see untreated SAS dates. You can also remove a format from a variable by issuing a FORMAT statement for one or more variables and not specify a format. For example, if a variable Age was formatted in a DATA step and you wanted to see untreated values in a listing, you could write the following FORMAT:

format Age;

# 3.12 Using Informats with List Input

Suppose you have a blank- or comma-delimited file containing data and character values longer than 8 bytes (or other values that require an informat). One way to provide informats with list input is to feed each variable in your INPUT statement with a colon, following the appropriate informat. To see how this works, suppose you want to read the CSV file List.csv.

```
"001", "Christopher Mullens",11/12/1955,"$45,200"
"002", "Michelle Kwo",9/12/1955,"$78,123"
"003", "Roger W. McDonald",1/1/1960,"$107,200"
```

Variables in this file represent a subject number (Subj), Name, date of birth (DOB), and yearly salary (Salary). You need to supply informs for Name (length is greater than 8 bytes), DOB (you need a data informat here), and Salary (this is a nonstandard numeric value—with a dollar sign and commas). 3.10 shows one way to supply the appropriate formats for variables.

```
data List_Example;
infile C:\books\List.csv dsd;
input Subj : $3;
  Name   : $20;
  DOB    : mmddyy10;
  Salary  : dollar8.
format date date9. Salary dollar8;
run;
```

You see there there is a colon preceding each informat. This colon (called an informat modifier) tells SAS to use the informat to stop reading the value for this variable when a delimiter is encountered. Do not forget the colons without them SAS may read past a delimiter to satisfy the width specified in the informat.

This would also work if the informat for Subj were omitted and the variable name was followed by a dollar sign (to signify that Subj is a character variable). However, the Subj variable would then be stored in 8 bytes (the default length for character variables with list input). By providing the $3. informat, you tell SAS to use 3 bytes to this variable.
