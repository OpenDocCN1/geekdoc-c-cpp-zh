Create a policy map to assign actions to traffic configured in Layer 3/4 class maps:

| Command | Description |
| --- | --- |
| `ciscoasa(config)# policy-map`<br>`p-map-name` | Specify a name for this policy map (up to 40 characters in length).<br><br>**NOTE:** Another variation of the command is `policy-map type inspect p-map-name` command. The command is beyond the scope of this chapter. |

Identify the class map:

| Command | Description |
| --- | --- |
| `ciscoasa(config-pmap)# class`<br>`class-map-name` | Assign a class map to a policy map where you can assign actions to the class map traffic and enter config policy map class mode.<br><br>**NOTE:** The class name `class-default` is a reserved name. |

**NOTE:** The `description` keyword could be used to document the policy map.

Assign one of the following actions:

| Command | Description |
| --- | --- |
| `ciscoasa(config-pmap-c)# set connection` | Configure connection parameters. |
| `ciscoasa(config-pmap-c)# police {input &#124; output} rate-bps` | Rate-limit traffic for this class. |
| `ciscoasa(config-pmap-c)# inspect protocol` | Configure protocol inspection services.<br><br>**NOTE:** There are many different protocol keywords, including `dns`, `ftp`, `http`, `icmp`, `ipv6`, and more. All are beyond the scope of this chapter. |

**NOTE:** Other configurable policy map actions that are beyond the scope of this chapter include `priority`, `service-policy`, `shape`, `ips`, `flow-export`, and more.

The service policy enables the policy map globally on all interfaces or on a specific interface:

| Command | Description |
| --- | --- |
| `ciscoasa(config)# service-policy`<br>`p-map-name {global &#124; interface intf}` | Enable a set of policies globally or apply them on an interface. |
