## Spanning Tree Protocol Attacks

Redundant Layer 2 topologies eliminate single points of failure, but they are more susceptible to broadcast storms, topology flaps, and MAC address table instability problems.

Spanning Tree Protocol (STP) is a Layer 2 protocol that provides a loop-free redundant network topology by placing certain ports in the blocking state. A hacker could manipulate STP to conduct an attack by changing the topology of a network (for example, by connecting a rogue switch in an attempt to take over as the root and have all traffic for the immediate switched domain flow through it).

> **NOTE:** Configure the STP enhancement features PortFast, BPDU guard, and root guard to mitigate STP manipulation attacks.

## STP Enhancement Features

| Feature | Description |
|---|---|
| **PortFast** | ▪ Feature minimizes the time an access port must wait for spanning tree to converge.<br>▪ The Layer 2 access port immediately transitions from the blocking to the forwarding state, bypassing the listening and learning states.<br>▪ It should be enabled on user-facing access ports. |
| **BPDU guard** | ▪ Feature protects the switched network from the potential problems caused by the receipt of bridge protocol data units (BPDUs) on user-facing ports.<br>▪ If a BPDU is received, the port transitions to error-disabled mode and blocks all traffic.<br>▪ The port must be reset manually and therefore provides a secure response to invalid configurations.<br>▪ It should be enabled on user-facing access ports to prevent rogue switch installations. |
| **Root guard** | ▪ Feature enforces the placement of root bridges and limits the switch ports out of which the root bridge may be negotiated.<br>▪ If an incoming BPDU advertises a lower bridge ID than the current bridge, the port transitions to a root-inconsistent state (blocked).<br>▪ The port recovers as soon as the offending BPDUs cease.<br>▪ It should be configured on user-facing ports and switch ports that connect to switches (but which should not be the root bridge). |

> **NOTE:** Another STP enhancement is the BPDU filter feature, which stops the sending and receiving of BPDUs on a port. However, you should not configure this if BPDU guard is enabled.

> **NOTE:** BPDU guard and root guard are similar, but their impact is different. BPDU guard disables the port, and it must be enabled manually. Root guard disables the port but recovers once the offending device ceases to send superior BPDUs.

## Configuring STP Enhancement Features

You can enable PortFast globally or individually on an access port:

| Command | Description |
|---|---|
| `Switch(config)#spanning-tree portfast default` | Globally enable the PortFast feature on all ports.<br><br>**NOTE:** You must explicitly disable PortFast on switched ports leading to switches because they may create Layer 2 loops. |
| `Switch(config-if)#spanning-tree portfast` | Enable PortFast on the specified port. |

> **NOTE:** Use the `show running-config [interface interface-id]` command to verify that PortFast is enabled.

You can enable BPDU guard globally or individually on an access port:

| Command | Description |
|---|---|
| `Switch(config)#spanning-tree portfast bpduguard default` | Globally enable BPDU guard on all PortFast-enabled ports. |
| `Switch(config-if)#spanning-tree bpduguard enable` | Enable BPDU guard on the specified port. |

> **NOTE:** Use the `show spanning-tree summary` and the `show spanning-tree summary totals` commands to display STP state information.

You can enable root guard on either an access port or a switch port that connects to another switch (but which should never be the root bridge).

| Command | Description |
|---|---|
| `Switch(config-if)#spanning-tree guard root` | Enable root guard on the specified port. |

> **NOTE:** To verify, use the `show spanning-tree inconsistentports` command.

You can also configure a switch to auto-recover BPDU guard error-disabled ports after a specified amount of time:

| Command | Description |
|---|---|
| `Switch(config)#errdisable recovery cause bpduguard` | Enable the timer to recover from the BPDU guard error-disabled state. |

> **NOTE:** Use the `show errdisable recovery` command to display the error-disabled recovery timer information.

## Configuring STP Enhancements Example

Figure 8-2 shows the topology for the configuring STP enhancements example.

![](img/0d9540c65a85f4cb1c32cee46038d8ab_130_0.png)

Figure 8-2 — Network Topology for the Configuring STP Enhancements Example

```
switch(config)#storm-control
{[broadcast | multicast | unicast]
[level {level | level-low} | bps bps
[bps-low] | pps pps [pps-low]] |
[action {shutdown | trap}]}
```

Enable storm control on Layer 2 ports and EtherChannels to monitor the rate of received traffic. Broadcast, multicast, and unicast traffic can be monitored.

`level {level | level-low}` specifies the rising and falling suppression levels as a percentage (to two decimal places) of total bandwidth of the port.

`level bps {bps [bps-low]}` specifies the rising and falling levels in bits per seconds.

`level pps {pps [pps-low]}` specifies the rising and falling levels in packets per second.

The action taken can be

- **shutdown:** Disables the port during the storm
- **trap:** Sends an SNMP trap during a storm

> **NOTE:** By default, unicast, broadcast, and multicast storm control are disabled on the switch interfaces; that is, the suppression level is 100 percent.

## Configuring Storm Control Example

This example shows how to enable broadcast address storm control on a port to a level of 25 percent. When the broadcast traffic exceeds 25 percent of the total available bandwidth, the switch drops all broadcast traffic until the end of the traffic storm control interval:

```
S1(config-if)#storm-control broadcast level 25
```

Enable storm control on Layer 2 interfaces to monitor the rate of received traffic.

## VLAN Hopping Attacks

### Spoofing DTP messages

Attacker sends spoofed Dynamic Trunking Protocol (DTP) messages in an attempt to establish a trunk link with the switch. If successful, the attacker can send traffic tagged with the target VLAN and have the switch deliver the packets to the destination.

![](img/0d9540c65a85f4cb1c32cee46038d8ab_134_0.png)

- On all trunk links:
  - Enable trunking.
  - Disable DTP.
  - Use unique native VLAN.
- On all unused ports:
  - Disable trunking.
  - Assign all unused ports to a dedicated VLAN.
  - Disable the port.
- On an access port:
  - Disable trunking.

Figure 8-3 Network Topology for the Mitigating VLAN Attacks Example

| Command | Description |
| :--- | :--- |
| `S3(config)#interface range Fa0/1 - 2` | Configure the two trunking ports, Fa0/1 and Fa0/2. |
| `S3(config-if-range)#switchport mode trunk` | Explicitly enable trunking. |
| `S3(config-if-range)#switchport nonegotiate` | Disable DTP. |
| `S3(config-if-range)#switchport trunk native vlan 88` | Assign the native VLAN to VLAN 88. VLAN 88 is not used for any other traffic. |
| `S3(config-if-range)#interface Fa0/3` | Change to interface Fa0/3. |
| `S3(config-if)#switchport mode access` | Disable trunking. |
| `S3(config)#interface range Fa0/4 - 24` | Configure all other unused ports. |
| `S3(config-if-range)#switchport mode access` | Disable trunking on all unused ports. |
| `S3(config-if-range)#shutdown` | Disable all unused ports. |
