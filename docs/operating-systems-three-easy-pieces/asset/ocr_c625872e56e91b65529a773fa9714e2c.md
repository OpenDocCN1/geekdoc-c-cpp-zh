# 19.1 TLB Basic Algorithm

19.1 shows a rough sketch of how hardware might handle a virtual address translation, (i.e., the page table is an array) and a hardware-managed TLB (i.e., the hardware handles of much the responsibility of page table accesses; we'll explain more about this below).

The algorithm follows works like this: extract the page number (VPN) from the virtual address (Line 1 in Figure 19.1), and check if the TLB holds the translation for this VPN (Line 2). If it does, we have a TLB hit, which means the TLB holds the translation. Success! we can now extract the frame number (PFN) from the relevant TLB entry; concatenate it with the offset from the original virtual address, and form the desired physical address (PA), and access memory (Lines 5-7), assuming protection checks do not fail (Line 4).

If the CPU does not find the translation in the TLB (a TLB miss), we have some more to work in. In this example, the hardware accesses the page table to find the translation (Lines 11–12), and assuming that the virtual memory generated by the process is valid and accessible (Lines 13, 15), updates the TLB with the translation (Line 18). The set of actions are costly, primarily because of the extra memory reference needed to access the page table (Line 12). Finally, the TLB is updated, the hardware retries the instruction; this time, the translation is found in the TLB, and the memory reference is processed quickly.
