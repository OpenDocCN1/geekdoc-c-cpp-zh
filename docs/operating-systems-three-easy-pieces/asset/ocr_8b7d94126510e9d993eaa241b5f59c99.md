# 21.2 The Present Bit

Now that we have some space on the disk, we need to add machinery up in the system to support swapping pages to and from the disk. Let us assume, for simplicity, that we have a system with a hardware-managed TLB.

Recall what happens on a memory reference. The running process generates virtual memory references (for instruction fetches, or data accesses), and, in this case, the hardware translates them into physical addresses, and, if a hit, produces the address before fetching the data from memory.

Remember that the hardware extracts the VPN from the virtual address, checks the TLB for a match (**a TLB hit**), and, if a hit, produces the physical address and fetches it from memory. This is hopefully the common case, and it is fast (requiring no additional memory).

If the VPN is not found in the TLB (i.e., **a TLB miss**), the hardware locates the page in memory (using the **page table register**) and looks up the **page entry (PTE)** for this page using the VPN as an index. If the page is valid and present in physical memory, the hardware extracts the VPN from the PTE, inserts it into the TLB, and retrieves the translation, this time as a TLB hit; so, so good.

If we allow pages to be swapped to disk, however, we must add more machinery. Specifically, when the hardware learns that the PTE is **not present** in physical memory. The way the hardware (or the OS, in a software-managed TLB approach) determines this is through a new piece of information in each page-table-entry, known as the **present bit**. If the present bit is set to one, it means the page is present in physical memory and everything proceeds as above; if it is set to zero, the page is **not in memory** but rather on disk somewhere.
