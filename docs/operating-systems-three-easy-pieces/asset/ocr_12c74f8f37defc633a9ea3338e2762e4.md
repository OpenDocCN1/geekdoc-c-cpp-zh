# INTERLUDE: FILES AND DIRECTORIES

The declaration below shows the information available within each directory entry in the struct direkt data structure:

```
struct direkt {
    char            d_name[256]; // filename
    ino_t           d_ino;      // inode number
    off_t           d_off;      // offset to the next diret
    unsigned short d_recl;    // length of this record
    unsigned char  d_type;     // type of file
};
```

Because direktories are light on information (basically, just mapping the name to the inode number, with a few other details), a program may want to stat() on each file to get more information on, such as its length or other detailed information. Indeed, this is exactly ls is when you pass it the -1 flag; try trace on ls and without that flag to see for yourself.

# 39.13 Deleting Directories

Finally, you can delete a directory with a call to rmdir() (which is used by the program of the same name, rmdir). Unlike file deletion, however removing directories is more dangerous, as you could potentially delete a large amount of data with a single command. Thus, rmdir() has the requirement that the directory be non-empty (i.e., only has "." and " entries) before it is deleted. If you try to delete a directory, the call to rmdir() will simply fail.

# 39.14 Hard Links

We now come back to the mystery of removing a file is performed via link(), by understanding how to make an entry in the file system tree, through a system known as link(). The link() system takes two arguments, an old pathname and a new one; when you "link" a new name to an old one, you essentially create another way to refer to the same file. The command-line program ln is used to do this, as we see in this example:

```
prompt> echo hello > file
prompt> cat file
hello
prompt> ln file file2
prompt> cat file2
hello
```
