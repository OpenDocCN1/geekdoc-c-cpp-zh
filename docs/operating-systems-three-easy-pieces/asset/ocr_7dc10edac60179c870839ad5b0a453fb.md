# PAGING: FASTER TRANSLATIONS (TLBs)

The TLB, like all caches, is built on the premise that the common case, translations are found in the cache (i.e., hits). If so, little overhead is added, as the TLB is found near the processing core and designed to be quite fast. When a miss occurs, the high cost of paging is incurred; the page table must be accessed to find the translation, and an extra memory reference (or more, with more complex page tables) results. If this happens, the program will likely run noticeably slower; memory accesses, relative to more CPU instructions, are costly, and TLB misses lead to more memory accesses. Thus, it is our hope to avoid TLB misses as much as we can.

# 19.2 Example: Accessing An Array

To clear the operation of a TLB, let's examine a simple virtual address trace and see how a TLB can improve its performance. In example, let's assume we have an array of 10 4-byte integers in memory, starting at virtual address 100. Assume further that we have a small 8-bit virtual space, with 16 pages; thus, a virtual address down into a 4-bit VPN (there are 16 virtual pages) and a 4-bit offset (there are 16 bytes on each of those pages).

Figure 19.2 (page 26) shows the array laid out on the 16-byte pages of the system. As you can see, the array's first entry ([0]) begins on VPN=06, offset=04); only four-byte integers fit into that page. The array continues onto the next page (VPN=07), where the next four entries (a[3] ... a[6]) are found. Finally, the last three entries of the 10-entry array (a[7] ... a[9]) are located on the next page of the address space (VPN=08).

Now let's consider a simple loop that accesses each array element, something that would look like:

```
int sum = 0;
for (i = 0; i < 10; i++) {
  sum += a[i];
}
```

For the sake of simplicity, we will pretend that the only memory accesses the loop generates are i and sum, as well as the instructions themselves. When the first element ([0]) is accessed, the CPU will use to load a virtual address 100. The hardware extracts the VPN from (VPN=06), and uses that to check the TLB for a valid translation. Assuming this is the first time the program accesses the array, the result will be a TLB miss.

The next access is to a[1], and there is some news here: a TLB hit! Because the second element of the array is packed next to the first, it lives on the same page; we've already accessed this page when accessing the first element of the array, the translation is already loaded
