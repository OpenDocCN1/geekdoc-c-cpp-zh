> ASIDE: THE SUPERUSER (ROOT)
A system generally needs a user who can administer the system, and is not limited in the way most users are. Such a user should be able to kill an arbitrary process (e.g., if it is abusing the system in any way), even though that process was not started by this user. Such a user should also be able to run powerful commands such as shut down (usually, shuts down the system). In UNIX-systems, these special abilities are given to the superuser (sometimes called root). Most users cannot kill other processes. Being root is like Spider-Man: with great power comes great responsibility [QI5]. Thus, to increase security (avoid costly mistakes), it's usually better to be a regular user; if you need to be root, read carefully, all of the destructive powers of the computing are now at your fingertips.

## 5.7 Summary

We have introduced some of the APIs dealing with UNIX creation: fork(), exec(), and wait(). However, we have just skimmed the surface. For more detail, read Stevens and Rago [SR05], of course, particularly the chapters on Process Control, Process Relationships, and Signals; there is much more to extract from the wisdom therein.

While our passion for the UNIX process API remains strong, we should also note that this positivity is not uniform. For example, a recent paper by systems researchers from Microsoft, Boston University, and ETH in Switzerland details some problems with process creation APIs such as spawn() [B+19]. Read it, and the related work it refers to, to understand this different vantage point. While it's generally good to trust this book, remember too that the authors have opinions, those opinions may not (always) be as widely shared as you might think.

## ASIDE: KEY PROCESS API TERMS

- Each has a name; in many systems, that name is a number known as a process ID (PID).
- The fork() system call is used in UNIX systems to create a new process. The creator is called the parent; the newly created process is called the child. As sometimes occurs in real life [J16], the child process is a nearly identical copy of its parent.
- The wait() system call allows a parent to wait for its child to completion.
- The exec() family of system calls allows a child to break free from its similarity to its parent and execute an entirely new program.
- A UNIX shell commonly uses fork(), wait(), and exec() to launch user commands; the separation of fork and exec enables features, all without changing anything about the programs running.
- Process control is available in the form of signals, which can cause jobs to stop, continue, or even terminate.
- Which processes can be controlled by a particular person encapsulated in the notion of a user; the operating system allows multiple users onto the system, and ensures users can only control their own processes.
- A superuser can control all processes (and indeed do many other things); this role should be assumed infrequently and with caution for security reasons.

## ASIDE: CODING HOMEKS

Coding homeworks are small exercises where you write code on a real machine to get some experience with basic system APIs. After all, you are (probably) a computer scientist, and therefore would like to code, right? If you don't, there is always CS theory, but that's pretty hard.

## Homework (Code)

In this homework, you are to gain some familiarity with the process management APIs about which you just read. Don't worry – much fun than it sounds! You'll in general be better off if you find much time as you can write code, why not start?

## Questions

- 1. Write a program that calls fork(), have the main process accept a variable (e.g., x) and set its value to something (e.g., 100). What value is the variable in the child process? What happens to the variable when both the child and parent change the value of x?
- 2. Write a program that opens a file (with the open() system call) and then calls fork() to create a new process. Can both the child and parent access the file descriptor returned by open()? What happens when they writing to the file concurrently, i.e., at the same time?
- 3. Write another program using fork(). The child process should print "hello"; the parent process should print "goodbye". You should ensure that the child always prints first; can you do this without wait() in the parent?
- 4. Write a program that calls fork() and then calls some of exec() /bin/ls to run the program. See if you can try all of the variants of exec(), including (on Linux) exec(), exec(), execclp(), execv(), and execve(). Why do you think there are so many variants of the same basic call?
- 5. Write a program that uses wait() to wait for the child process to finish in the parent. What does wait() return? What happens if you wait() in the child?
