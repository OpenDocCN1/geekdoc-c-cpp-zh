# ## 37.5 Disk Scheduling

Because of the cost of I/O, the OS has historically played a role in deciding the order of I/Os to the disk. More specifically, given a set of I/O requests, the **disk scheduler** examines the requests and decides which one to schedule next [SCL90, JW91].

Unlike job scheduling, where the length of each job is usually unknown, with disk scheduling, we can make a good guess at how long a "job" (i.e., request) will take. By estimating the possible rotational delay of a request, the disk scheduler can know how long each request will take, and thus (greedily) pick the one that will take the least time to service first. Thus, the disk scheduler will try to follow the principle of SJF (shortest job first) in its operation.

# ### SSTF: Shortest Seek Time First

One early disk scheduling approach is known as **shortest-seek-time-first (SSTF)** (also called *shortest-seek-first* or SSF). SSTF services the queue of I/O requests by track, picking requests on the nearest track to complete. For example, assuming the current position of the head is over the inner track, track and 22 (outer track), we would then issue the request to 21 first, wait for it to complete, and then issue the request to 2 (Figure 37.7).

SSTF works well in this example, however, SSTF is not a panacea, for the following reasons. First, the drive geometry is not available to the host OS; rather, it sees an array of blocks. Fortunately, this problem is easily fixed. Instead of SSTF, an OS can implement **nearest-block-first (NBF)**, which schedules the request with the nearest block address next.
