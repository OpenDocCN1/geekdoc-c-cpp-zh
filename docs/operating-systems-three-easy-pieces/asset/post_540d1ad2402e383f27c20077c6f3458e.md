TIP: INTERPOSITION IS POWERFUL
Interposition is a generic and powerful technique that is often used to great effect in computer systems. In virtualizing memory, the hardware will intercept each memory access, and translate the virtual address issued by the process to a physical address where the desired information is actually stored. However, the general technique of interposition is much more broadly applicable; almost any well-defined interface can be interposed, to add new functionality or improve some aspect of the system. One of the usual benefits of an approach is transparency, the interposition often done without changing the client of the interface, requiring no changes to said.

```c
void func() {
  int x = 3000; // thanks, Perry.
  x = x + 3; // line of code we are interested in
  ..
}
```

The compiler turns this line of code into assembly, which might look like this (in x86 assembly). Use objdump on Linux or a Mac to disassemble it

```assembly
128: mov 0(%ebx), %eax      ;load 0+ebx into eax
132: add $0x03, eax             ;add 3 to eax register
135: mov %eax, 0(%ebx)          ;store eax back to mem
```

This snippet is relatively straightforward; it presumes the address of x has been placed in the register eax, and then loads the value at that address into the general-purpose register eax using mov instruction (for "longword" move). The next instruction adds 3 to eax, and the final instruction stores the value in eax back into memory at that same location.

In Figure 15.1 (page 154), observe how both the code and data are located in the process's address space; the three-instruction code sequence is located at address 128 (in the section near the top), and the value of the variable x is at address 15 KB (in the stack near the bottom). In the initial state, the value of x is 3000, as shown in its location on the stack.

When these instructions run, from the perspective of the process, the following accesses take place:

- Fetch instruction at address 128
- Execute this instruction (load from address 15 KB)
- Fetch instruction at address 132
- Execute this instruction (no memory reference)
- Fetch the instruction at address 135
- Execute this instruction (store to address 15 KB)

From the program's perspective, its address space starts at 0 and grows to a maximum of 16 KB; all memory references it generates should be within these bounds. However, to virtualize memory, the OS wants to place the process somewhere in physical memory, not necessarily at address 0. Thus, we have the problem: how can we relocate this process in a way that is transparent to the process? How can we provide the illusion of a virtual address space starting at 0, when in reality the address space is located at some other physical address?

## 15.3 Dynamic (Hardware-based) Relocation

To gain some understanding of hardware-based address translation, we will first discuss the base and bounds approach. Specifically, we need two registers: one for the base and the other for the limit. The base register holds the physical address where the process starts, and the limit register holds the size of the address space. This ensures that the process cannot access memory outside its bounds. Because we can move the process even after it has started, this technique is often referred to as dynamic relocation.

### SIDE: SOFTWARE-BASED RELOCATION

In the early days, before hardware support, relocation was a crude form of software. For example, if you wanted to move a program, the OS would have to find all the memory references in the code and update them. This was slow and inefficient. A better way was to use a translation table, which maps virtual addresses to physical addresses. This is the basis for paging and segmentation.

The point of the base and bounds is to make sure all addresses generated by the process are legal. Specifically, the processor will first check that the memory reference is within bounds before adding the base. In the simple example above, the bounds register will always be set to 16 KB. If a process generates an address that is greater than the bounds, the CPU will raise an exception.

Transforming a virtual address into a physical address is exactly what we refer to as address translation; that is, the hardware takes a virtual address and transforms it into a physical address where the data actually resides. Because this relocation happens at runtime, we can move the process. If a process generates an address that is greater than the bounds, or that is negative, the CPU will raise an exception, and the process will be terminated. The point of the bounds is to make sure all addresses generated by the process are legal. We should note that the base and bounds registers are hardware structures kept on the chip (one pair per CPU). As we develop more sophisticated memory-management techniques, we will be adding more circuitry to the MMU.
