# Homework (Simulation)

This section introduces raid.py, a simple RAID simulator you can use to shore up your knowledge of how RAID systems works. See the README for details.

# Questions

+   Use the simulator to perform some basic RAID mapping tests. Run with different levels (0, 1, 4, 5) and if you can figure out the mappings of a raid-5, see if you can figure out the difference between left-symmetric and left-asymmetric layouts. Use some different random seeds to generate different problems above.
Do the same as the first problem, but time vary the chunk with -C. How does chunk size change the mappings?
Do the same as above, use the -r flag to reverse the nature of each problem.
Use the reverse flag but increase the size of each request with the -S flag. Try specifying sizes of 8k, 12k, and 16k, while varying the underlying I/O pattern when the sequential workload too (-W sequential); for what request sizes are RAID-4 and RAID-5 more efficient?
Use the timing mode of the simulator (-t) to estimate the performance of each RAID level, varying the RAID levels, using 4 disks.
Do 100 random reads (-w 100) instead of reads.
Do the same as above, but increase the number of disks. How does the performance of each RAID level scale as the number of disks increases?
Do the same as above, but use all writes (-w 100) instead of reads. How does the performance of each RAID level scale now? Can you do a rough estimate of the time it will take to complete the workload of 100 writes?
Run the timing mode one last time, but this time with a sequential workload (-W sequential). How does the performance vary with RAID level, and when reads versus writes? How about varying the size of each request? What size should you write to a RAID when using RAID-4 or RAID-5?
