> ASIDE: THE SUPERUSER (ROOT)
A system generally needs a user who can administer the system, and is not limited in the way most users are. Such a user should be able to kill an arbitrary process (e.g., if it is abusing the system in any way), even though that process was not started by this user. Such a user should also be able to run powerful commands such as shut down (usually, shuts down the system). In UNIX-systems, these special abilities are given to the superuser (sometimes called root). Most users cannot kill other processes. Being root is like Spider-Man: with great power comes great responsibility [QI5]. Thus, to increase security (avoid costly mistakes), it's usually better to be a regular user; if you need to be root, read carefully, all of the destructive powers of the computing are now at your fingertips.

# 5.7 Summary

We have introduced some of the APIs dealing with UNIX creation: fork(), exec(), and wait(). However, we have just skimmed the surface. For more detail, read Stevens and Rago [SR05], of course, particularly the chapters on Process Control, Process Relationships, and Signals; there is much more to extract from the wisdom therein.

While our passion for the UNIX process API remains strong, we should also note that this positivity is not uniform. For example, a recent paper by systems researchers from Microsoft, Boston University, and ETH in Switzerland details some problems with process creation APIs such as spawn() [B+19]. Read it, and the related work it refers to, to understand this different vantage point. While it's generally good to trust this book, remember too that the authors have opinions, those opinions may not (always) be as widely shared as you might think.
