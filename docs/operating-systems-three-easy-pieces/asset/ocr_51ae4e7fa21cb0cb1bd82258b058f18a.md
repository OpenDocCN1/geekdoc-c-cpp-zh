The lock and unlock routines are not the only routines within the threads library to interact with locks. Two other routines of interest:

```
int pthread_mutex_try_lock(pthread_mutex_t *mutex);
int pthread_mutex_timedlock(pthread_mutex_t *mutex, struct timespec *abs_timeout);
```

These two are used in lock acquisition. The trylock version fails if the lock is already held; the timedlock version of acquiring a lock returns after a timeout or acquiring the lock, whichever happens first. Thus, the timedlock with a timeout of 0 degenerates to the trylock case. Both of these versions should be avoided; however, there are a few cases where avoiding getting stuck (perhaps definitely) in a lock acquisition routine can be useful, as we will see in future chapters (e.g., when we study deadlock).

# 27.4 Condition Variables

The other major component of any threads library, and certainly the case with POSIX threads, is the presence of a condition variable. Condition variables are useful when some kind of signaling must take place between threads, if one is waiting for another to do something before it can continue. Two primary routines are used by programs to interact with this variable:

```
int pthread_cond_wait(pthread_cond_t *cond, pthread_mutex_t *mutex);
int pthread_cond_signal(pthread_cond_t *cond);
```

To use a condition variable, one has have in addition a lock that is associated with this condition. When having to call either of the above routines, this lock should be held.

The first routine, pthread_cond_wait(), puts the calling thread to sleep, and waits for some other thread to signal it, usually when something in the program has changed that the now-sleeping thread might care. A typical use case looks like this:

```
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
```

```
pthread_mutex_lock(&lock);
while (ready == 0)
  pthread_cond_wait(&cond, &lock);
pthread_mutex_unlock(&lock);
```
