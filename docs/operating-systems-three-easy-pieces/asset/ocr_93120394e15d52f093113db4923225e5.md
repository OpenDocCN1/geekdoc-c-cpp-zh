# References

[AD09]Multilevel Feedback Scheduling in Solaris by Andrea Arpaci-Dousseau. Available: http://www.ostep.org/Citations/notes-solaris.pdf. A great set of notes by one of the authors of the Solaris scheduler. OK, we are probably biased in this description, but the notes are pretty damn good.

[B86]The Design of the UNIX Operating System by M.J. Bach. Prentice-Hall. One of the classic old books on how a UNIX operating system works: a must-read for kernel handlers.

[C62]"Experimental Time-Sharing System" by J. F. Corberto, M. D. Daggett, R. C. Daley. IFPRS 1962. A hard read, but the source of many of the first ideas in multi-level feedback scheduling. Memory went late into Unix, which one could argue was the most influential operating system of all.

[CS97]"Inside NT" by Helen Cutler and David A. Microsoft Press, 1997. If you would like to learn something other than Unix. Of course, why would you OK?, we'd be kidding; you might actually work for Microsoft some day you know.

[ES95]"An Analysis of Decay-Scheduling in Multiprocessors" by D.H.J. Epema. SIG-METTER 1995. A nice paper that looks back at the mid 1990s, including a good overview of the basic approach decay-usage scheduling.

[LM89]"The Design and Implementation of the 4.3BSD Unix Operating System" by S.J. Leifer, M.K. McKus, M.J. Kernels, J.S. Quar. Addison-Wesley, 1989. Another OS classic, written by four of the main people behind BSD. The other versions of this book, while more up to date, don't match the beauty of the original.

[O11]"John Orouster's Home Page" by John Orouster. www.stanford.edu/bouncer/. The home page of the famous Professor Orouster. The two-authors of this book of taking graduate operating systems from Orouster in graduate school; this, is where the two came to get home out of school, marriage, and even this book. Thus, you really can blame Orouster for this mess you're in.

[P95]"Informed Prefetching and Caching" by R.H. Preetch, G.A. Gibson, E. Gint, D. Stodolsky, J. Zelenka. SOSP 95, Copper Mountain, Colorado, October 1995. A paper about some very cool ideas in file systems, including how applications can give the OS advice about what files it is accessing and how to plan it.

[Y18]"Principled Scalability Analysis for Distributed Storage Systems using Thread Architecture Models" by Suli Yang, Jing Liu, Andrea C. Arpaci-Dusseau, Remzi H. Arpaci-Dusseau. OSDI '18, San Diego, California. A recent work of our group demonstrates the difficulty of scheduling I/O requests in modern distributed storage systems like Hive/HDFS, Cassandra, MongoDB, and Risk. Without care, a single user might be able to monopolize system resources.
