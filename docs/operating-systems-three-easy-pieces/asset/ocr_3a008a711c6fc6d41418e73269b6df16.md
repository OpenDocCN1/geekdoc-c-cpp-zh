# INTERLUDE: FILES AND DIRECTORIES

The first thing that cat does is open the file for reading. A couple of things we should note about this; first, the file is only opened for reading (not writing), as indicated by the O_RDONLY flag; second, the 64-bit offset opened by O_LARGEFILE; third, that the call to open() succeeds and returns a file descriptor, which has the value of 3.

Why does the first call to open() return 3, 0 or -1 as you might expect? As it turns out, each process already has three files open, standard input (which the process can read to get input), standard output (which the process can write to dump information to the screen), and standard error (which the process can write error messages to). These are represented by file descriptors 0, 1, and 2, respectively; until you open another file (as cat does), it will almost certainly be a file descriptor.

After open succeeds, we use read() system call to read some bytes from a file. The first argument to read() is the file descriptor, thus filling the file we read; a process of have multiple files open at once, and the descriptor enables the operating system to know which file a particular reader refers to. The second argument to a buffer where the result of the read() will be placed; the system-call trace shows the results of the read in this spot ("hello"). The third argument is the size of the buffer, which in this case is 4 KB. The call to read() returns successfully as well, here returning the number of bytes it read (6, includes 5 for the letters in the word "hello" and one for an end-of-line marker).

At this point, you see another interesting result of the trace: a call to write() system call to file descriptor 1. As we mentioned above, this descriptor is known as the standard output, and thus is used to write the word "hello" to the screen the program cat is meant to do. But does it call write() directly? Maybe (if it is highly optimized). If not, what cat might do is the library routine printf(); internally, printf() formats all the formatting details passed to it, and eventually writes to standard output to print the results to the screen.

The cat program then tries to read more from the file, but since there are no bytes left in the file, the read() returns 0 and the program knows it has read the entire file. Thus, the program close() to indicate that it is done with the file "", passing in the corresponding file descriptor. The file is thus closed, and the reading of it complete.
