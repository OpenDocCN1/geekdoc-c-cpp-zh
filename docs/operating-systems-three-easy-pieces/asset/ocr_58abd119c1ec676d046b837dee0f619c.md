# 2.4 Persistence

The third major theme of the course is persistence. In system memory, data can be easily lost, devices such as DRAM values in a volatile memory; when power goes away or the system crashes, any data in memory is lost. We need hardware and software to be able to store data persistently; such storage is crucial to any system as users care a great deal about their data.

The hardware comes in some form of kind as input/output or I/O device; in modern systems, a hard drive is a common repository for longterm information, although solid-state drives (SSDs) are making headway in this area.

The operating system that usually manages the disk is called the file system; it is responsible for storing any files the user creates in a reliable and efficient manner on the disks of the system.

Unlike the abstractions provided by the OS for the CPU and memory, the OS does not create a private, virtualized disk for each application. Rather, it is assumed that often times, users want to share information files. When writing a C program, you might use an editor (emacs) to create and edit the file (emacs -nw main.c). Once done, you run the compiler to turn the source code into an executable (gcc -o main.c). When you're finished, you run the new executable ./main). Thus, you can see how files are shared across different processes. First, Emacs creates a file that serves as input to the compiler; the compiler uses that input to create a new executable file (in many steps—take a compiler course for details); finally, the new executable is then run. And thus a new program is born!
