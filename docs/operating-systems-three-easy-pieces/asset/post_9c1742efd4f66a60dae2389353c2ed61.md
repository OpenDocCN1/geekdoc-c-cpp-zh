
# 45.9 Summary

We have discussed data protection in modern storage systems, focusing on checksum implementation and usage. Different checksums protect against different types of faults; as storage devices evolve, new failure modes will undoubtedly arise. Perhaps such change will force the re-search community and industry to revisit some of these basic approaches, or invent entirely new approaches altogether. Time will tell. Or it won't. Time is funny that way.

# Homework (Simulation)

In this homework, you'll use checksum.py to investigate various aspects of checksums.

- 1. First just run checksum.py. Compute the additive, XOR and Fletcher checksums.
- 2. Now do the same, but vary the input.
- 3. Sometimes the additive and XOR produce the same, even though the data is different. Start with a 4-byte value (e.g., 0,1,2,3) and see if you can replace one of those numbers but end up with the same checksum.
- 4. Now pass in a 4-byte value that you know will produce the same additive and XOR. In general, when does this occur?
- 5. Now do the same for Fletcher checksum.
- 6. Now do the same for XOR checksum.
- 7. Now let's look at a specific set of data. The first is 1,2,3,4. What do you notice about these checksums (additive, XOR, Fletcher)? How does Fletcher compare to the simple additive?
- 8. No checksum is perfect. Given a particular input of your choosing, can you find other values that lead to the Fletcher checksum? When, in general, does this occur? As always, use -c to check your answers.

# Homework (Code)

In this part of the homework, you'll write some of your own code to implement checksums.

- 1. Write a short C program (called check-xor.c) that computes an XOR-based checksum over an input file, and prints the checksum as output. Use a 8-bit unsigned char to store the (one byte) checksum. Make some test files to see if it works.
- 2. Now write a short C program (called check-fletcher.c) that computes the Fletcher checksum over an input file. Once again, test your program to see if it works.
- 3. Now compare the performance of both: is one faster than the other? How does performance change as the size of the input file changes? Use internal calls to gettimeday to time the programs. Which should you use if you care about performance? About checking ability?
- 4. Read about 16-bit CRC and then implement it. Test it on a number of different inputs to ensure it works. How is its performance as compared to the simple XOR and Fletcher? How about its checking ability?
- 5. Build a tool (create-csum.c) that computes a single-byte checksum for every 4 KB block of a file, and records the results in an output file (specified on the command line). Build a related tool (check-csum.c) that reads a file, computes the checksums over each block, and compares the results to the stored checksums stored in another file. If there is a problem, the program should print that the file has been corrupted. Test the program by manually corrupting the file.
