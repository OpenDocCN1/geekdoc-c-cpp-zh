The problem occurs when consumers run first (Tc1 and Tc2) and both go to sleep (c3). Then, the producer, puts a value in the buffer, and wakes one of the consumers (say Tc1). The producer then loops (releasing and requiring the lock along the way) and tries to put more data in the buffer; because the buffer is full, the producer waits on the consumer (then sleeping). Now one consumer is ready to run (Tc1), and two threads are sleeping on a condition (Tc2 and Tp). We are about to cause a problem: getting exclusive

The consumer Tc1 then wakes up by wait (c3), re-checks the condition (c2), and finding the buffer, consumes the value (c4). This consumer then, critically, signals on the condition (c5), waking only one thread that is sleeping. However, which would it wake?
Because the producer has emptied the buffer, it clearly should wake the producer. However, if it wakes the consumer Tc2 (which is definitely possible, depending on how the we is managed), we have a problem.
