en a process (Process A) starts; note how its memory transla-
 are handled by the hardware with no OS intervention. At some\point (middle of second process), a timer interrupt occurs, and the OS

address); at that point, the OS must get involved, terminating the process
and cleaning by freeing B’s memory and removing its entry from the
process table. As you see from the figures, we are still following the
basic approach of limited direct execution. In most cases, the OS just
sets up the hardware appropriately and lets the process run directly on

involved.

# 15.6 Summary

In this chapter, we have extended the concept of limited direct ex-
c with a specific mechanism used in virtual memory, known as ad-ess translation. With address translation, the OS can control each
every access from a process, ensuring the accesses stay within
bounds of the address space. To the efficiency of this technique
hardware support, performs the translation quickly for each ac-
turning virtual addresses (the process’s view of memory) to phys-
ical (the actual). All of this is performed in a way that trans-
p to the process has been relocated; the process has no idea its
memory references are being translated, making for a wonderful illusion.
