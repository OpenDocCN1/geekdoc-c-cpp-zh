# 33.6 A Solution: Asynchronous I/O

To overcome this limit, many modern operating systems have introduced new ways to issue I/O requests to the disk system, referred to generically as asynchronous I/O. These interfaces enable an application to issue an I/O request and return control immediately to the caller, before the I/O has completed; additional interfaces enable an application to determine whether various I/Os have completed.

For example, let examine the interface provided on a Mac (other systems have simple APIs). The APIs revolve around a basic structure, the struct aiocb or IO control block in common terminology. A simplified version of the structure looks like this (see the manual pages for more information):

```
struct aiocb {
    aio_fildes;      // File descriptor
    off_t   aio_offset;
    volatile void *aio_buf;  // Location of buffer
    size_t  aio_bytes;    // Length of transfer
};
```

To issue an asynchronous read to a file, an application should first fill this structure with the relevant information: the file descriptor of the file to be read (aio.fildes), the offset in the file (aio.offset) as well as the length of the request (aio.bytes), and finally the memory location into which the results of the read should be copied (aio.buf).

After this structure is filled, in application application must issue the asynchronous read API: on a Mac, this API is simply the asynchronous read API:

```
int aio_read(struct aiocb *aiocbp);
```

This calls to issue the I/O; if successful, it simply returns right away and the application (i.e., the event-based server) can continue with its work.

There is one last piece of the puzzle we must solve: however. How can we tell an I/O is complete, and that the buffer (pointed to by aio_buf) has the data we requested?

One last API is needed. On a Mac, it is referred to (somewhat confusingly) as aio_error(). The API looks like this:

```
int aio_error(const struct aiocb *aiocbp);
```

This system checks whether the requested request by aiocb has completed. If it has, the returns status (indicated by a zero); if not, EINPROGRESS is returned. Thus, for every outstanding I/O, an application can periodically poll the I/O system via to aio_error() to determine whether said I/O has yet completed.
