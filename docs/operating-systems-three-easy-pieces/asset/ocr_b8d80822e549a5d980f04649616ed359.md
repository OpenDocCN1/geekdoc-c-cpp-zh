# Interlude: Files and Directories

Thus far we have seen the development of two key operating system abstractions: the process, which is a virtualization of the CPU, and the address space, which is a virtualization of memory. In tandem, these two abstractions allow a program to run as if it is in its own private, isolated world; as if it has its own processor (or processors); as if it has its own world. This illusion makes programming the system much easier and is thus prevalent today not only on desktops and servers but increasingly on all programmable platforms including mobile phones and the like.

In this section, we add one more critical piece to the virtualization puzzle: persistent storage. A persistent-storage device, such as a classic hard drive or a more modern solid-state storage device, stores information permanently (or at least for a long time). Unlike memory, whose contents are lost when there is power loss, a persistent-storage device keeps data intact. Thus, the OS must take extra care with such a device: this is where users keep data that they really care about.

> Crux: How To Manage a Persistent Device
How should the OS manage a persistent device? What are the APIs? What are the important aspects of the implementation?

Thus, in the next chapters, we will explore critical techniques for managing persistent data, focusing on methods to improve performance and reliability. We begin, however, with an overview of the API: the interfaces you'll expect to see when interacting with a UNIX file system.
