# Questions

+   1. The first Linux tool you should check out is the very simple tool free. type man free and read its entire manual page; it's short, don't worry!
2. Run free, perhaps using some of the arguments that might be useful (e.g., -m, to display memory totals in megabytes). How much memory is in your system? How much is free? Do these numbers match your intuition?
3. Next, create a little program that uses a certain amount of memory, called memory-user.c. This program should take one command line argument: the number of megabytes of memory it will use. When it run, it should allocate an array, and constantly stream through the array, touching each entry. The program should do this indefinitely, or perhaps, for a certain amount of time specified by the command line.
4. While running your memory-user program, also (in a different terminal window, but on the same machine) run the free tool. How does the memory usage change when your program is running? How happens when you kill the memory-user program? Do the numbers match your expectations? Try this for different amounts of memory usage. What happens when you use large amounts of memory?
5. Let's try one more tool, pmap. Spend some time, and read the pmap manual page in detail.
6. Use pmap, you know the process ID of the process you're interested in. Then, first run ps auxw to see a list of all processes; then, pick an interesting one, such as a browser. You can also use your memory-user program in this case (indeed, you can have that program getpid() and print out its PID for convenience).
7. Run pmap on these processes, using various flags (like -X) to reveal many details about the process. What do you see? How many different entities make up a modern address space, as opposed to our simple conception of code/stack/heap?
