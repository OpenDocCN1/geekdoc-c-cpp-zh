# Why Do Deadlocks Occur?

As you may be thinking, simple deadlocks such as the one seem readily avoidable. For example, if Thread 1 and 2 both made to grab locks in the same order, the deadlock would never arise. Why do deadlocks happen?

One reason is in large code bases, complex dependencies arise between components. Take the operating system, for example. The virtual memory system might need to access the file system in order to page a block from disk, the file system might subsequently read a page of memory to read the block into and thus contact the virtual memory system. Thus, the design of locking strategies in large systems must be carefully done to avoid deadlock in circular dependencies that may occur naturally in the code.

Another reason is due to the nature of encapsulation. As software developers, we are taught to hide details of implementations and thus make software easier to build in a modular way. Unfortunately, this modular does not mesh well with locking. As Jula at point out [J+08], seemingly innocuous interfaces invite you to deadlock.
