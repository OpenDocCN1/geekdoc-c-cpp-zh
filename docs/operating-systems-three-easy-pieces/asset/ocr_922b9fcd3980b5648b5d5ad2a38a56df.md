# FILE SYSTEM IMPLEMENTATION

> ASIDE: DATA STRUCTURE — THE INODE

The inode is the generic name used in many file systems to describe the structure that holds the metadata for a given file, such as its length, permissions, and location of its constituent parts. The name goes back at least far as UNIX (and probably further back to Multics if not earlier systems); it is for index node, as the inode is used to index into an on-disk index to find the file of that number. We'll see, design of the inode is one key part of file system design. Most modern systems have some kind of structure that links it to every file they track, but perhaps call different things (such as nodes, inodes, etc.).

Each inode is implicitly referred to by a number (the i-number), which we either call the low-level name of. In vfs and other file systems, given an i-number, you can directly be calculate where the corresponding inode is located. For example, the inode table of vfs as follows: 20-KB in size (4-KB blocks) and consisting of 80 inodes (assuming each inode is 256 bytes); further assume that the inode range starts at 2KB (the superblock starts at 0KB, the inode bitmap is at address 4KB, the data bitmap at 8KB, and thus the inode comes from address). To read inode number 32, the file system would first calculate offset into the inode range (32 - sizeof(inode) or 8192), and add it to the start address of the inode disk (inodeStartAddr = 12KB), and thus arrive upon the correct address of the desired inode. Recall that disks are not byte addressable, but rather consist of a large number of addressable sectors, usually 512 bytes. Thus, to fetch the block that contains inode 32, the file system would issue a read to sector 51, or 40, to fetch the desired inode. Generally, the sector of the inode block can be calculated as follows:

```
blk = (inumber(inode_t)) / blockSize;
sector = ((blk * blockSize) + inodeStartAddr) / sectorSize;
```
