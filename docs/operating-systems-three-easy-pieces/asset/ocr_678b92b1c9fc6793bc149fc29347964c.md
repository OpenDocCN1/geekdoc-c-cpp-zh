The second abstraction is that of a directory. A directory, like a file, has a low-level name (i.e., an inode number), but its contents are quite specific: it contains a list of (user-readable name, low-level name) pairs. For example, let's say there is a file with the low-level name “10”, and it is referred to the user-readable name “foo”. The directory that “foo” resides in would have an entry (“foo”, “10”) that maps to other files or directories. By placing directories within other directories, systems are able to build an arbitrary directory tree (or hierarchy), under which all files and directories are stored.
The hierarchy starts at the directory (in Unix-like systems, the root directory is referred to as / and uses some kind of separator to make subsequent sub-directories visible. For example, if a user created a directory foo in the root directory /, and then created a file bar.txt in the directory foo, we could refer to the file by its absolute pathname, which in this case would be /foo/bar.txt.
