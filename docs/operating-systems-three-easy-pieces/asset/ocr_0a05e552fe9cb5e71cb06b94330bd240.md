# Homework (Code)

In this homework, we'll familiarize ourselves with how the APIs
described in the chapter work. To do so, you'll just write a few
programs, mostly based on various UNIX utilities.

+   1. **Stat**: Write your version of the command line program *stat*, which simply calls the `stat()` system call on a given file or di-
irect. Print out file size, number of blocks allocated, reference
(link) count, and so forth. What is the link count of a directory, as
the number of entries in the directory changes? Useful interfaces:
stat()`, naturally.
2. **Files**: Write a program that lists files in the given directory.
When called without any arguments, the program should print
the filenames. When invoked with the `-l` flag, the program should
out information about each file, such as the owner, group, per-
missions, and other information obtained from the `stat()` system
call. The program should take one additional argument, which is
t directory to read, e.g., `mys -l directory`. If no directory is
given, the program should use the current working directory.
Useful interfaces: `stat()`, `opendir()`, `readdir()`, `getcwd()`.
3. **Tail**: Write a program that prints out the last few lines of a file.
The program should be efficient, in that it seeks to near the end of the
file, reads in a block of data, and then goes backwards until it
the requested number of lines; at point, it should print out those
lines from beginning to the end of the file. To invoke the program,
one should type: `mytail -n file`, where n is the number of lines
at the end of the file to print. Useful interfaces: `stat()`, `lseek()`,
open()`, `readdir()`, `close()`.

+   4. **Recursive**: Write a program that prints the names of\each file and directory in the file system tree, starting at a given
point in the tree. For example, when without arguments, the
program should start with the current working directory and print
it contents, as well as the contents of any sub-directories, etc., until
the entire tree, root at the CWD, is printed. If a single argu-
mentof a directory name), use that as the root of the tree instead.
Refine your recursive search with more function options, similar to the
powerful `find` command line tool. Useful interfaces: figure it out.
