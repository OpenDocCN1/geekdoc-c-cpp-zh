# LOCK-BASED CONCURRENT DATA STRUCTURES

> TIP: AVOID PREMATURE OPTIMIZATION (KNUTH'S LAW)
When building a concurrent data structure, start with the most basic approach, which is to add a single big lock to provide synchronized access. By doing so, you are likely to build a correct lock; if you then find that it suffers from performance problems, you can refine it, thus only making it fast if needed. As Knuth famously stated, "Premature optimization is the root of all evil."

Many operating systems utilized a single lock when first transitioning to multiprocessors, including Sun OS and Linux. In the latter, this lock even had a name, the big kernel lock (BKL). For many years, this simple approach was good enough, until a single active thread in the kernel at a time became a bottleneck. Thus, it was finally time to add the optimization of improved concurrency to these systems. Within Linux, the more straightforward approach was taken: replace one lock with many. Within Sun, a more radical decision was made: build a brand new operating system, known as Solaris, that incorporates concurrency fundamentally from day one. Read the Linux and Solaris kernel books for more information about these fascinating systems [BC05, MM00].
