# 21.6 When Replacements Actually Occur

Thus for the way we described how replacements occur assumes that the OS waits until memory is entirely full, and then only replaces (evicts) a page to make room for other page. As you can imagine, this is a little unrealistic, and there are many reasons for the OS to keep a small portion of memory free proactively.

To keep a small amount of memory free, most operating systems have some kind of high watermark (HW) and low watermark (LW) to help when decide to start evaging pages from memory. This works is as follows: the OS notices that there are fewer than LW pages available, a background thread that is responsible for freeing memory runs. The thread evicts pages until there are HW pages available. The background, sometimes called the swap daemon or page daemon, then goes to sleep, happy that it has free some memory for running processes and the OS to use.
