# TIP: TURN FLAWS INTO VIRTUES

Whenever your system has a fundamental flaw, see if you can turn it around into a feature or something useful. NetApp's WAFL does this with old files; by making old versions available, WAFL no longer has to worry about cleaning quite so often (though it deletes old versions eventually, in the background) and provides a cool feature and removes much of the LFS cleaning problem all in one wonderful twist. Are there other examples of this in systems? Undoubtedly, but you will have to think of them yourself, because this chapter is over with a capital “O”. Over. Done. Kaput. We're out. Peace!

The large writes that LFS generates are excellent for performance on many different devices. On hard drives, large writes ensure that positioning is minimized; on parity-based RAIDs, as RAID-4 and RAID-5, they avoid the small-write problem entirely. Recent research on Flash-based SSDs [H+17]; thus, perhaps surprisingly, LFS-style file systems may be an excellent choice even for these new mediums.

The downside to this approach is that it generates garbage; old copies of the data are scattered throughout the disk, and if one wants to claim space for subsequent usage, one must clean old segments periodically. Cleaning became the focus of much controversy in LFS, including NetApp's WAFL [HLM94], Sun's ZFS [B07], and even modern flash-based SSDs [AD14], adopt a similar copy-on-write approach to disk, and thus the intellectual legacy of LFS lives on these modern file systems. In particular, WAFL got around cleaning problems by turning them into a feature; by providing old versions of the file system via snapshots, users could access old files whenever deleted current orders accidentally.
