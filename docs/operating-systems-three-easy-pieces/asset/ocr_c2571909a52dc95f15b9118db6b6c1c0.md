# Redundant Arrays of Inexpensive Disks
(RAIDs)

When we use a disk, we sometimes wish it to be faster; I/O operations
are slow and thus can be the bottleneck for the entire system. When we
 a disk, we sometimes wish it to be larger; more and more data is being
put online and thus our disks are getting fuller and fuller. When we use
a disk, we sometimes wish for it to be more reliable; when a disk fails, if
our data is not backed up, all that valuable data is gone.

> CRUX: How To Make A Large, Fast, Reliable DISK
How can we make a large, fast, reliable storage system? What are
the key techniques? What are trade-offs between different approaches?

In this chapter, we introduce the Redundant Arrays of Inexpensive
Disks better known as RAID [P-88], a technique to use multiple disks in
concert to build a faster, bigger, and more reliable disk system. The term
was introduced in the late 1980s by a group of researchers at U.C. Berke-
ley led by Professors David Patterson and Randy Katz and then student
Girth Gibson; it was around this time that many researchers misi-
narily arrived around the basic idea of using multiple disks to build
better storage system [BC88, K86, P86, SC86].

Externally, a RAID looks like a group of blocks one can read
internally, the RAID is a complex backend, consisting of multiple
disks, memory (volatile and non,), one or more processors to
manage the system. A hardware RAID is very much like a computer
specialized for the task of managing a group of disks.

RAIDs offer a number of advantages over a single disk. One adv-
tage is performance. Using multiple disks in parallel can greatly speed
u I/O times. Another benefit is capacity. Data sets demand large
disks. Finally, RAIDS can improve reliability; spreading data across mul-
tiple disks (without RAID techniques) makes the data vulnerable to
the loss of a single disk; with some form of redundancy, RAIDS can tolerate
t loss of a disk and keep operating as if nothing were wrong.
