Thus, our hybrid approach: instead of having a single page table for
t entire address space of the process, why not have one per logical seg
ment? In this example, we might have three page tables, one for the
code, heap, and stack parts of the address space.

Now, remember with segmentation, we had a base register that told
us where each segment lived in physical memory, and a *bound* or *limit
register that told the size of said segment. In our hybrid, we have
t structures in the MMU; here, we use the base not to point to the
segment but rather to hold the *physical address of the page table* of
segment. The bounds register beside to indicate the end of the page table
(ie., how many pages it has).

Let's do some example to clarify. Assume a 32-bit virtual address
 with 4KB pages, and an address space split into four segments.
We'll use three segments for this example: one for code, one for
heap, and stack.

To determine what an address refers to, we'll use the
two bits of the address space. Let's assume 0 is the unused segment,
with 01 for code, 10 for heap, and 11 for the stack. Thus, a virtual
address looks like this:

On a TLB miss (assuming a hardware-managed TLB, i.e., where the
hander responsible for handling TLB misses), the hardware uses the
segment bits (SN) to determine which base and bounds pair to use. The
h takes the physical address therein and combines it with
t VPN as follows to form the address of the page table entry (PTE):

```
SN = (Virtual Address & SEG_MASK) >> SN_SHIFT
VPN = (Virtual Address & VPN_MASK) >> VPN_SHIFT
AddressOfPTE = Base[SN] + (VPN * size(PTE))
```

This sequence should look familiar; it is virtually identical to what
saw before with linear page tables. The only difference, of course, is the
use of three segment base registers instead of the single page table
base register.
