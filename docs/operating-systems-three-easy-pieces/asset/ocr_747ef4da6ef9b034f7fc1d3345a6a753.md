# Tracking The Size Of Allocated Regions

You might have noticed that the interface to free(void *ptr) does not take a size parameter; thus it is assumed that when given a pointer, the malloc library can quickly determine the size of the region of memory being freed and thus incorporate the space back into the free list.

To accomplish this task, allocators store a little bit of information in a header block which is kept in memory, usually just before the handed-out chunk of memory. Let's look at again (Figure 17.1). In this example, we are examining an allocated block of 20 bytes, pointed to by ptr; imagine the called malloc() and stored the results in ptr;ptr = malloc(20);
The header minimally contains the size of the region (in this case, 20); it may also contain additional fields to speed up deallocation, a magic number to provide additional integrity checking, and other information. Let's assume a simple header which contains the size of the region and a magic number, like this:

```
typedef struct {
  int size;
  int magic;
} header_t;
```
