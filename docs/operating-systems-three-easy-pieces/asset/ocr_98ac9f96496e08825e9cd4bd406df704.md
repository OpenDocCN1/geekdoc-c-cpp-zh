# CRASH CONSISTENCY: FSCK AND JOURNALING

# References

[B07] "ZFS: The Last Word in File Systems" by Jeff Bonwick and Bill Moore. Available online: http://www.ostp.org/citations/zfs_last.pdf ZFS uses copy-on-write and journaling, actually, in some cases, logging writes to disk perform better.

[C-12] "Consistency Without Ordering" by Vijay Chidambaram, Tushar Sharma, Andrea C. Arpeau-Dusseau, Remzi H. Arpeau-Dusseau. FAST 12, San Jose. A recent paper of our new form of crash consistency based on points. Read it for the exciting details!

[C-13] "Optimistic Crash Consistency" by Vijay Chidambaram, Thanu S. Pillai, Andrea C. Arpeau-Dusseau, Remzi H. Arpeau-Dusseau. SOSP '13, Meckanim Woodlands Resort, PA, November 2013. Our work offers a much better journaling protocol. For workloads that call sync(), performance can be greatly improved.

[GP94] "Metadata Update Performance in File Systems" by Gregory R. Gray and Yale N. Kent. OSD 94. A paper about careful ordering of writes as the main way to achieve consistency. Implemented in LFS-based systems.

[GO08] "A Declarative File System Checker" by Harwadi S. Gunawi, Abhishek Raj-Jimenez, Andrea C. Arpeau-Dusseau, Remzi H. Arpeau-Dusseau. OSD 08, San Diego, California. Our paper on a new and better way to build a file system checker using SQL queries. We show some problems with the consistency check, finding numerous bugs and adds behaviors, a result of the complexity of fsck.

[H87] "Implementing the Cedar File System Checker using Logging and Group Commit" by Robert Haight, Austin, Texas, November 1987. The first work (that we know of) that applied write-ahead logging (a.k.a journal).

[M13] "The File System Checker" by Ao Ma, Christopher Dragga, Andrea C.-Arpeau-Dusseau, Remzi H. Arpeau-Dusseau. FAST 13, San Jose, February 2013. A recent paper of ours detailing how to make on crash on order of magnitude faster. Some of the ideas have been implemented in Linux and are now deployed today.

[M96] "The UNIX File System Checker" by Mark Marshall Kent and T. J. Kowalski. In 1996. Describes the first comprehensive file-system checking tool, the infamous fsck. Written by some of the people who wrote UFS.

[MJ84] "All File Systems Are Not Created Equal" by Marshall K. Chidambaram, William N. Joy, Sam J. Lee, Robert S. Ferry. ACM Transactions on Computing Systems, Volume 2-3, August 1984. Our paper discusses enough about FFS, so to to re-ference important papers.

[P14] "Crash Consistency Applications" by Thumulukkannarayanan Pillai, Vijay Chidambaram, Ramnathan Alagan, Al-Swayid, October 2014. Andrea C. Arpeau-Dusseau, Remzi H. Arpeau-Dusseau. OSD 14, Bloomfield, Colorado. A paper in which we study what file systems guarantee and what applications expect different, leading to to all sorts of interests problem.

[P05] "IFSN File System" by Vijay Prabhakaran, Lakshmi K. Bairavasitaram, Nitin Agrawal, Harwadi S. Gunawi, Andrea C. Arpeau-Dusseau, Remzi H. Arpeau-Dusseau. OOSP 05, Berlin, October 2005. A paper focused on studying how file systems report to failures. We report the experimental results and how fsync can speed to up, which was greatly adopted into Linux.

[PA05] "Analysis and Evaluation of Journaling Systems" by Vijay Prabhakaran, Andrea C. Arpeau-Dusseau, Remzi H. Arpeau-Dusseau. An early paper about evaluating journaling file systems. USENIX '05, Anaheheim, April 2005.

[R11] "Cache Eviction and Direct-Mode Journaling" by Abhishek Rajwale, Vijay Chidambaram, Ramesh Ramamurthi, Andrea C. Arpeau-Dusseau, Remzi H. Arpeau-Dusseau. DSN '11, Hong Kong, China, June 2011. Our paper on the problem of disks that buffer writes in a memory cache instead of forcing them to disk, even when not told to do that! Our solution to overcome this problem: if you want A to be written before B, first write A, then send a lot of "dummy" writes to A to be forced to make room for them in the cache. A need impact analysis.
