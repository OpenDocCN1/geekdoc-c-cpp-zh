#  44.5 From Raw Flash to Flash-Based SSDs

Given our basic understanding of flash chips, we now face our next task: how to turn a basic set of flash chips into something that looks like a typical storage device. The standard storage interface is a simple block-based, where blocks (sectors) of size 512 bytes (or larger) can be read or written, given a block address. The flash-based SSD is to provide that block interface atop the flash chips inside.

Internally, an SSD consists of some number of flash chips (for persistent storage). An SSD also contains some amount of volatile (i.e., non-persistent) memory (e.g., SRAM); which is useful for caching and buffering... as well as control logic to orchestrate device operation. See Agarwal et al for details [A08]; a simplified block diagram is seen in Figure 44.3 (page 595).

One of the essential functions of this control logic is to satisfy reads and writes, turning them into internal flash operations as needed. The flash translation layer, or FTL, provides this functionality. The FTL takes read and write requests on logical blocks (that comprise the device interface) and turns them into low-level read, erase, and program operations on the underlying physical blocks and pages (that capture the actual flash device). The FTL should accomplish this task with the goal of delivering excellent performance and high reliability.

Excellent performance, as we'll see, can be realized through combination of techniques. One key will be to utilize multiple flash chips in parallel; although we won't discuss this technique further, sufficient to say that all modern SSDs use multiple chips internally to obtain higher performance.
