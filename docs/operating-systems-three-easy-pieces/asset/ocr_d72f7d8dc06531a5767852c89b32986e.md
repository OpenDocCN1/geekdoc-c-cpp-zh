# 31.2 Binary Semaphores (Locks)

We are now to use a semaphore. Our first use will be one with which we are already familiar: using a semaphore as a lock. See Figure 31.3 for a code snippet; therein, we will simply surround the critical section of interest with a sem_wait()/sem_post(). Critical to making this work, however, is the initial value of the semaphore m (initialized to X). What should X be?

(Try thinking about it going on)

Looking back at definition of the sem_wait() and sem_post() routines, we can see that the initial value should be 1. To make this clear, let's imagine a scenario with two threads. The first thread (Thread 0) calls sem_wait(); it will first decrement the value of the semaphore, changing it to 0. Then, it will wait only if the value is not greater than 0. Because the value is 0, sem_wait() will simply return and the thread will acquire the lock while no other thread tries to acquire the lock while Thread 0 is free to enter the critical section. If no other thread is inside the critical section, it calls sem_post(), it will simply restore the value of the semaphore to 1 (and not wait a waking thread, because there is none). Figure 31.4 shows a trace of this scenario.
