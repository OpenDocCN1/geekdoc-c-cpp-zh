One question we will answer in this book is quite simple: how does the operating system visualize resources? This is the crux of our problem. Why the OS does not the main question, as the answer should be obvious: it makes the system easy to use. Thus, we focus on the *how*: what mechanisms and policies are implemented by the OS to attain virtualization? How does the OS do so efficiently? What hardware support is needed?

The primary way the OS does is through a general technique that we call **virtualization**. Thus, the OS takes a **physical resource** (such as the processor, memory, or a disk) and transforms it into a more generic, powerful, and easy-to-use **virtual form** of itself. Thus, we sometimes refer to the operating system as a **virtual machine**

In order, to allow users to tell the OS what to do and thus make use of the features of the virtual machine (such as running a program, allocating memory, or accessing a file), the OS also exports some interfaces (**APIs**) that you can call. A typical OS, in fact, exports a few hundred system calls that are available to applications. Because the OS provides these to run programs, access memory and devices, and other related actions, we sometimes say that the OS provides a **standard library** to applications.

Finally, because virtualization allows many programs to run (thus including the CPU), and many programs to concurrently access their own structures and data (thus sharing memory), and many programs to access devices (thus sharing disks and forth), the OS is sometimes known as a **resource manager**. Each of the CPU, memory, and disk is a **resource** of the system; it is thus the operating system's role to **manage these resources**, doing so efficiently or fairly or indeed with many possible goals in mind. To understand the role of the OS a little better, let's take a look at some examples.
