# CONCURRENCY: AN INTRODUCTION

```
#include <stdio.h>
#include <assert.h>
#include <pthread.h>
#include "common.h"
#include "common_threads.h"

void mythread(void *arg) {
    printf("%s\n", (char *)arg);
    return NULL;
}

int
main(int argc, char *argv[]) {
    pthread_t p1, p2;
    int rc;
    printf("main: begin\n");
    // join threads for the threads to finish
    Pthread_create(&p1, NULL, mythread, "A");
    Pthread_create(&p2, NULL, mythread, "B");
    Pthread_join(p1, NULL);
    Pthread_join(p2, NULL);
    printf("main: end\n");
    return 0;
```

Figure 2.6: Simple Thread Creation (t0.c)

After creating the two threads (let's call them T1 and T2), the main thread calls pthread_join(), waits for a particular thread to complete. It does so, ensuring T1 and T2 will run and run again; when it does, it will print "main exit" and exit. Overall, three threads were employed during this run: the main thread, T1 and T2.

Let us examine the possible ordering of execution of this little program. In the execution diagram (Figure 26.3, page 307), time increases in the downwards direction, and each column shows when a different thread (the main one, or Thread 1, or Thread 2) is running.

Note, however, this is not the only possible ordering. In fact, given a sequence of instructions, there are quite a few, depending on which thread the scheduler decides to run at a given point. For example, once a thread is created, it may run immediately, which would lead to the execution shown in Figure 26.4 (page 307).

We also could see "B" printed before "A", if, say, the scheduler decided to run Thread 2 before even Thread 1 was created earlier; there is no reason to assume that a thread that was created first will run first. Figure 26.5 (page 308) shows this final ordering, with Thread 2 getting to its stuff before Thread 1.
