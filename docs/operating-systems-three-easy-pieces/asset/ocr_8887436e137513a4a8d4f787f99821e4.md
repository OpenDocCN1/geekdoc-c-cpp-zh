# INTERLUDE: Thread API

```
#include <stdio.h>
#include <pthread.h>
typed struct {
 int a;
 int b;
} myarg_t;

void *mythread(void *arg) {
 myarg_t *args = (myarg_t *) arg;
 printf("%d %d\n", args->a, args->b);
 return;
}

int main(int argc, char *argv[]) {
 myarg_t args = { 10, 20 };

 int rc = pthread_create(&p, NULL, mythread, &args);
}
```

This routine takes arguments. The first is of type pthread_t, and is used to specify which thread to wait for. This variable is initialized by the thread creation routine (when you pass a pointer to it as an argument to pthread_create()); if you keep it around, you can use it to wait for that to terminate.

The second argument is a pointer to the return value you expect to get back. Because the routine can return anything, it is defined to return a pointer to void; because the pthread_join() routine changes the value of the argument in passed, you do not need to pass in a value to that, not just the value itself.

Let's look at another example (Figure 27.2, page 322). In the code, a single thread is again created, and passed a couple of arguments via the myarg_t structure. To return values, the main thread, which has been waiting inside of the pthread_join() routine¹, then returns, and we can access the values returned from the thread, whatever is in myret_t..

A few things to note about this example. First, often times we don't have to do all of this painful packing and unpacking of arguments. For example, if we create a thread with no arguments, we can pass NULL in as an argument when the thread is created. Similarly, if we pass NULL into pthread_join() if we don't care about the return value.
