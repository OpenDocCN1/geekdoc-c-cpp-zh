# 43.4 Problem: Finding Inodes

To understand how we find an inode in LFS, let us briefly review how to find an inode in a typical Unix file system such as FS, or even the old Unix file system, finding inodes is easy, because they are organized in an array and placed at fixed locations.

The old Unix file system keeps all inodes at a fixed position of the disk. Thus, given an inode number and the start address, to find a particular inode, you can calculate its disk address simply by multiplying the inode number by the size of an inode, and adding the start address of the on-disk array; array-based indexing, given an inode number, is fast and straightforward.

Finding an inode number in FFS is only slightly more complicated, because FFS splits up the inode table into chunks and grows inodes within each chunk group. Thus, one must know how each chunk of inodes is and what the start addresses of each. After that, the calculations are also simple.

In LFS, life is more difficult. Why? Well, we’ve managed to scatter the inodes throughout the disk! Worse, we never overwrite in place, and the latest version of an inode (i.e., the one we want) keeps moving.
