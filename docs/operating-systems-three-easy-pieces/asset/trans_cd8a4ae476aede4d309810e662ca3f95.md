> 提示：编译通过或运行通过 ≠ 它是正确的
仅仅因为一个程序编译了(!) 甚至正确地运行了一次或多次，并不意味着该程序是正确的。很多事件可能会让你处于认为它能正常运行的程度，但随后情况发生了变化，它就停止了。学生常见的反应是说（或大喊）“但它之前还好好好的！”并将其归咎于编译器、操作系统、硬件，甚至（我们敢说吗）问题本身。问题通常就在你认为它所在的地方，在你的代码里。为了让它工作并进行调试，你却把归咎放在其他组件上。

当你运行这段代码时，它可能会导致段错误（segmentation fault），这是一个华丽的术语，意思是“你对内存上做了某些错误的事情，程序员，我非常生气”。在这种情况下，正确的代码可能像这样：

```c
char *src = "hello";
char *dst = (char *) malloc(strlen(src) + 1);
strcpy(dst, src); // 正常工作
```

或者，你可以使用 `strdup()` 让你的生活变得更轻松。阅读 `strdup` 的手册页以获取更多信息。

# 分配内存不足

另一个相关的错误是没有分配足够的内存，有时被称为缓冲区溢出（buffer overflow）。在上面的示例中，常见的错误是为目标缓冲区只留了几乎足够的空间。

```c
char *src = "hello";
char *dst = (char *) malloc(strlen(src)); // 太小了！
strcpy(dst, src); // 正常工作
```

奇怪的是，取决于内存的实现方式以及许多其他细节，这个程序运行似乎是正确的。在某些情况下，当字符串拷贝执行时，它会向分配空间的末尾多写一个字节，但在某些情况下，这种溢出是无害的，可能覆盖了一个未使用的变量。在某些情况下，这些溢出可能是极其有害的，事实上，它们是许多安全漏洞的根源。如果内存库在任何地方分配了一点额外的空间，那么你的程序实际上并没有涂改其他变量的值，并且运行得很好。在其他其他情况下，程序确实会失败并崩溃。因此，我们学到了另一个宝贵的教训：即使它运行过一次，也不意味着它是正确的。

虽然听起来相似，但你很快就会学会为什么这种非法的内存访问被称为段错误；如果这不能激励你读下去，还有什么能？

# 忘记初始化已分配的内存

在这种错误中，你正确地调用了 `malloc()`，但忘记了在你新分配的数据类型中填入一些值。不要这样做！如果你忘记了，你的程序最终会遇到未初始化读取（uninitialized read），即它从一个具有未知值的堆数据中读取内容。谁知道那里会有什么？如果你足够幸运，可能是一个程序仍能工作的值（例如，零）。如果你不幸运，可能是一些随机且有害的东西。

# 忘记释放内存

另一个常见错误被称为内存泄漏（memory leak），它在你忘记释放（free）内存时发生。在长时间运行的应用程序或系统（例如操作系统本身）中，这是一个巨大的问题，因为缓慢的泄漏会导致内存耗尽，之后需要重启。因此，通常情况下，当你完成一块内存的使用后，你应该确保释放它。请注意，使用垃圾回收的语言在这里并没有帮助，如果你仍然对某块内存有引用，任何垃圾回收器永远不会释放它，即使在更现代的语言中内存泄漏仍然是一个问题。

在某些情况下，不调用 `free()` 似乎是合理的。例如，你的程序很短，很快就会退出；在这种情况下，当进程死亡时，操作系统将清理它所有的分配页，本质上不会发生内存泄漏。虽然这“有效”（参见第 145 页的旁注），但这可能是一个不好的习惯，所以要警惕选择这种策略。作为程序员，你的目标之一是养成良好的习惯；习惯之一就是理解你是如何管理内存的以及（在 C 等语言中）你所分配的块。即使你不这样做也能逃过，养成释放每一个显式分配的字节的习惯可能也是好事。

# 在完成工作之前释放内存

有时程序会在完成使用之前释放内存；这种错误被称为悬空指针（dangling pointer），正如你所知，这是坏事。随后的使用会导致程序崩溃，或覆盖内存（例如，你调用了 `free()`，然后又调用了 `malloc()` 来分配其他东西，这回收了已经释放的内存）。

# 重复释放内存

程序有时也会多次释放内存；这被称为双释放（double free）。这样做的结果是未定义的。正如你可以想象的，内存分配库可能会陷入困惑并发生各种奇怪的事情；崩溃是常见的结果。

14.5 底层 OS 支持

你可能注意到，我们在讨论 `malloc()` 和 `free()` 时没有谈到系统调用。原因很简单：它们不是系统调用，而是库调用。因此，库通过系统调用来请求更多内存或释放回系统。最后，当前的系统调用 `brk` 用于更改堆的边界。它接受一个参数（新边界地址），并根据新边界变大还是小来增加堆的大小。额外的调用 `sbrk` 通过增量传递，但具有类似的作用。注意，你不应该直接使用 `brk` 或 `sbrk`。它们是被内存库使用的；如果你尝试使用它们，可能会做出（极其）错误的事情。坚持使用 `malloc()` 和 `free()`。最后，你还可以通过 `mmap()` 调用从操作系统获取内存。通过传递正确的参数，`mmap()` 可以在程序内部创建一个内存区域——一个与特定文件无关但与交换空间相关的区域，我们稍后会在虚拟内存中详细讨论。这种内存可以被视为堆并对其进行管理。阅读 `mmap()` 的手册页获取详情。

14.6 其他调用

内存分配库还支持其他几个调用。例如，`calloc()` 分配内存并在返回之前将其零；这防止了假设内存已清零而忘记初始化的错误（参见“未初始化读取”段落）。`realloc()` 例程也有用，如果你为某些东西分配了空间（例如数组），然后需要向其添加某些内容：`realloc()` 创建一个新的内存区域，将旧区域复制到其中，并返回新区域的指针。

14.7 总结

我们介绍了一些处理内存分配的 API。由于我们刚刚涵盖了基础；更多细节可以在其他地方找到。当你习惯了使用这些强大的工具，你将会疑惑没有它们是如何生存的。
