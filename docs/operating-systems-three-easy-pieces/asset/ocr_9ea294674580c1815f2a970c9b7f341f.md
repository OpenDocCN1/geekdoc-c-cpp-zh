ASIDE: STORAGE TECHNOLOGIES
We'll delve much deeply into how I/O devices actually work later (see the chapter on I/O devices). So be patient! And of course the slower device need not be a hard disk, but could seem more modern such as a Flash-based SSD. We'll talk about those things too. For, just assume we have a big and relatively-slow device which we can use to help us build the illusion of a large virtual memory, even bigger than physical memory itself.

Beyond just a single process, the addition of swap space allows the OS to support the illusion of a large virtual memory for multiple concurrently-running processes. The invention of multiprogramming (running multiple programs "at once", to better utilize the machine) demanded the ability to swap out pages, as early machines clearly not hold all the pages needed by all processes at once, the combination of multiprogramming and ease-of-use loads we want to support by using more memory than is physically available. It is something that all modern VM systems do; it is now something we will learn about.

# 21.1 Swap Space

The first thing we will need is to reserve some space on the disk for moving pages back and forth. In operating systems, we generally refer to such space as swap space, because we swap pages out of memory to and swap pages into memory from it. Thus, we will simply assume that the OS can read from and write to the swap space, in page-sized units. To do so, the OS will need to remember the disk address of a given page.

The size of the swap space is important, as ultimately determines the maximum number of pages that can be used in a system at a given time. We use for simplicity that it is very large for now.

In the tiny example (Figure 21.1), we can see a little of a 4-page physical memory and an 8-page swap space. In the example processes (Proc 0, Proc 1, and Proc 2) are actively sharing physical memory; each of the three, however, all of their values in memory, with the rest located in swap space on disk. A fourth process (Proc 3) has all of its pages swapped out to disk, which clearly isn't currently running. One block of swap memory free. Even from this tiny example, hopefully you can see how swap space allows the system to pretend that memory is larger than it is actually.
