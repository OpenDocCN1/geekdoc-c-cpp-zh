```
#include <stdio.h>
#include <unistd.h>
#include <assert.h>
#include <fcntl.h>
#include <sys/types.h>

int main(int argc, char *argv[]) {
    int fd = open("/tmp/file", O_WRONLY|O_CREATE|O_TRUNC,
                                     S_IRWXU);
    assert(fd > -1);
    int rc = write(fd, "hello world\n", 13);
    assert(rc == 13);
    close(fd);
    return 0;
}
```

Figure 2.6: A Program That has some code. I/O (io.c)

To understand this error, let's create a file (/tmp/file) that contains the string "hello world".
To accomplish this task, the program makes three calls to the operating system. The first, a call to open(), opens the file and creates it; the second, write(), writes some data to the file; the third, close(), closes the file indicating that the program isn't writing any more data to it. These system calls are routed to the operating system and return some kind of error code to the user.
You might be wondering what the OS does in order to accurately write to disk. We could show you but you'd have to close your eyes first; it is quite unpleasant. The file system has to do a bit of work: first figuring out where this new data will reside, and keeping track of it in various structures the file system maintains. Doing so requires I/O requests to the underlying storage device, to either read existing structures or update (write). Anyone who has written a driver knows, getting a device to do something on your behalf is an intricate and detailed process. It requires a deep knowledge of the low-level device interface and its semantics. Frankly, the OS provides a standard and simple way to access devices through its system calls. The OS is sometimes seen as a standard library.
Of course, there are many more details in how devices are accessed, and how file systems manage data persistently for performance reasons, most file systems delay writes for a while, hoping to batch into larger groups.
