# Reading A File From Disk

In this simple example, let us assume that you want to simply open a file (e.g., /foo/bar), read it, and then close it. For this example, let's assume the file system is 12KB in size (i., 3 blocks).

When you issue an open ("foo/bar") call, the file system first needs to find the inode for the file bar, to obtain some basic information about the file system (permissions, file size, etc.). To do so, the file system must be able to find the inode, but all it has right now is the full name. The file system must traverse the pathname and thus locate the desired.

All traversals begin at the root of the file system, in the root directory which is simply called /. Thus, the first thing the FS will read from disk is the inode of the root directory. But where is the inode? To find an inode, we must know its i-number. Usually we find it in its directory; the root has no parent (by definition). Thus the root inode number must be known; the FS must know when the file system is mounted. In Unix file systems, the root inode number is 2. Thus, to begin the process, the FS reads in the block that contains inode number 2 (the first block).

Once the inode is read, the FS can look inside it to find pointers to data blocks, which contain the contents of the root directory. The FS will use these on-pointers to read the directory, in which case its looking for an entry for foo. By reading in one or more directory blocks, it will find foo for foo; once found, the FS will also have the inode number of foo (say it is 44) which it will need next.
