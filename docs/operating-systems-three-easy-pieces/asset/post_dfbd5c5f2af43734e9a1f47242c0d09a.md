# 42.4 Solution #3: Other Approaches

We've described two options in keeping file system metadata consistent: a lazy approach based on *fsck*, and a more active approach known as journaling. However, these are not the only approaches. One approach, as Soft Updates [GP94], was introduced by Ganger and Patti. This approach carefully orders all writes to the file system to ensure that the on-disk structures are never left in an inconsistent state. For example, by writing a pointed-to data block *before* the inode that it points to, we can ensure that the inode never points to garbage; similar rules can be derived for all the structures of the file system. Implementing Soft Updates can be a challenge; however, the journaling described above can be implemented with relatively little knowledge of each file system structure and Soft Updates requires intricate knowledge which adds fair amount complexity. Another approach is known as *copy-on-write* (COW), and is used in a number of popular file systems, using Sun's ZFS [B07]. This technique never overwrites files or directories in place; rather places new updates to previously unused locations on disk. After a number of updates are completed, COW systems flip the root structure of the file system to include pointers to the newly updated structures. Doing so makes the file system consistent straightforward. We'll learn-ing about this technique when we discuss the log-structured file system (LFS) in a future chapter; LFS is it an example of COW.

Another approach is just developed here at Wisconsin. With this technique, entitled backpointer-based consistency (or BBC), no ordering is enforced between writes. To achieve consistency, an additional back pointer is added to every block in the system; for example, each data block has a reference to the inode to which it belongs. When accessing a file, the file system can determine if the file is consistent by checking the forward pointer (e.g., the address in the inode or direct block) a block that refers back to it. If so, everything must have safely reached disk and if not, the file is inconsistent, and an error is returned. By adding back pointers to the file system, a new form of lazy consistency can be attained [C+12].

Finally, we have also explored techniques to reduce the number of times a journal has to wait for disk writes to complete. optimistic crash consistency [C+13], this new approach issues as many writes as possible by using a generalized form of the transaction checksum [P+05], and includes a few other techniques to detect inconsistencies as they arise. For some workloads, these optimistic techniques can improve performance by an order of magnitude. To function well, a slightly different disk interface is required [C+13].

# 42.5 Summary

We have introduced the problem of crash consistency, and discussed various approaches to attacking this problem. The older approach of building a file system crash works but is likely too slow to recover on modern systems. Thus, many file systems now use journaling. Journaling reduces recovery time from O(size-of-the-volume) to O(size-of-the-log), speeding recovery substantially after a crash and restart. For reason, modern file systems use journaling. We have also seen that journaling can come in many different forms; the most commonly used is ordered metadata journaling, which reduces the amount of traffic to the journal while preserving reasonable consistency guarantees for both file system metadata and user data. In the end, strong guarantees on user data are probably one of the most important things to provide; oddly enough, as recent research has shown, this area remains a work in progress [P+14].
