# VIRTUAL MEMORY SYSTEMS

The general weakness exploited in each of these attacks is that the CPUs found in modern systems perform all sorts of crazy behind scenes tricks to improve performance. One class of technique that lies at the core of the problem is called speculative execution, the CPU guesses instructions will be executed in the future, and starts them ahead of time. If the guesses are correct, the program runs faster; if not, the CPU undoes their effects on architectural state (e.g., registers) tries again, this time going down the right path.

The problem with speculation is that it tends to leave traces of its execution in various parts of the system, such as processor caches, branch predictors, and thus. As the authors of the attacks show, such state can be vulnerable to the contents of memory, even memory that was protected by the MMU.

One avenue to increasing kernel protection was to remove much of the kernel address space from each user process and have a separate kernel page table for most kernel data (called kernel page isolation, or KPTI) [G+17]. Thus, instead of mapping the kernel's code and data structures into each process, only the bare minimum is kept; when switching into the kernel, then, switch to the kernel page table is needed. Doing so improves security and avoids attack vectors, but at a cost: Switching page tables is costly. Ah, the cost of: convenience and performance.

Unfortunately, KPTI doesn't solve all the security problems laid above, just most of them. Simple solutions, such as turning off speculation, would make little sense, because systems would run thousands of times slower. Thus, it is an interesting time to be alive, if systems security is yours.

To truly understand these attacks, you (likely) have to learn a more first. By beginning modern computer architecture, as found in advanced books on the topic, focusing on speculation and all the mechanisms needed to implement it. Definitely read about the Meltdown and Spectre attacks, at the websites mentioned above; they actually also include a useful primer on speculation, so perhaps are not a bad place to start. And study the operating system for further vulnerabilities. Who knows what problems remain?
