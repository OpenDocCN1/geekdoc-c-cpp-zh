```
// counter: used to track if we've found the winner
int counter = 0;

// winner: use some call to a random number generator to
get a value, between 0 and the total # of tickets
int winner = getrandom(0, totaltickets);

// current: use this to walk through the list of jobs
node_t *current = head;
while (current) {
    counter += current->tickets;
    if (counter > winner) {
        break; // found the winner
    }
    current = current->next;
}
// 'current' is the winner: schedule it
```

# 9.3 Implementation

Probably the most amazing about lottery scheduling is the simplicity of its implementation. All you need a random number generator to pick the winning ticket, a data structure to track the processes of the system (e.g., list), and the total number of tickets.
Let's keep the processes in a list. Here is an example of three processes, A, B, and C, each with some number of tickets.

![](bbox=[0.196, 0.549, 0.802, 0.587])

To make a scheduling decision, we first have to pick a random number (the winner) from the total number of tickets (400) Let's say we pick the number 300, then we traverse the list, with a simple counter used to help find the winner (Figure 9.1).
The code walks the list of processes, adding each ticket value to counter until the value exceeds winner. If that is the case, the current is the winner. With our example of the winning ticket being 300, the following takes place. First, counter is incremented to 100 for A's tickets; because 100 is less than 300, the loop continues. Then counter would be updated to 150 (B's tickets), still less than 300 and again we continue. Finally, counter is updated to 400 (clearly greater than 300), and thus we break out of the loop with current pointing at C (the winner).

> Surprisingly, as pointed out by Björn Lindberg, this can be challenging to do correctly; for more details, see https://stackoverflow.com/questions/2509679/how-to-generate-a-random-number-from-within-a-range.
