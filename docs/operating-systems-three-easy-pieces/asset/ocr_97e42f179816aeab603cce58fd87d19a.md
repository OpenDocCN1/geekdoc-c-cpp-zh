TIP: INTERPOSITION IS POWERFUL
Interposition is a generic and powerful technique that is often used to great effect in computer systems. In virtualizing memory, the hardware will intercept each memory access, and translate the virtual address issued by the process to a physical address where the desired information is actually stored. However, the general technique of interposition is much more broadly applicable; almost any well-defined interface can be interposed, to add new functionality or improve some aspect of the system. One of the usual benefits of an approach is transparency, the interposition often done without changing the client of the interface, requiring no changes to said.

```
void func() {
  int x = 3000; // thanks, Perry.
  x = x + 3; // line of code we are interested in
  ..
```

The compiler turns this line of code into assembly, which might look like this (in x86 assembly). Use objdump on Linux or a Mac to disassemble it

```
128: mov 0x(%ebx), %eax      ;load 0+ebx into eax
132: add $0x03, eax             ;add 3 to eax register
135: mov %eax, 0(%ebx)          ;store eax back to mem
```

This snippet is relatively straightforward; it presumes the address of x has been placed in the register eax, and then loads the value at that address into the general-purpose register eax using mov instruction (for "longword" move). The next instruction adds 3 to eax, and the final instruction stores the value in eax back into memory at that same location.

In Figure 15.1 (page 154), observe how both the code and data are located in the process's address space; the three-instruction code sequence is located at address128 (in the section near the top), and the value of the variable x is at address 15 KB (in the stack near the bottom). In the initial state, the value of x is 3000, as shown in its location on the stack.

When these instructions run, from the perspective of the process, the following accesses take place:

+   - Fetch instruction at address 128
- Execute this instruction (load from address 15 KB)
- Fetch instruction at address 132
- Execute this instruction (no memory reference)
- Fetch the instruction at address 135
- Execute this instruction (store to address 15 KB)
