# INTERLUDE: PROCESS API

```
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(int argc, char *argv[]) {
    printf("hello world (pid:%d)\n", (int) getpid());
    int rc;
    rc = fork();
    if (rc < 0) { // fork failed; exit
        fprintf(stderr, "fork failed\n");
        exit(1);
    } else if (rc == 0) { // child (new process)
        printf("hello, I am child (pid:%d)\n", (int) getpid());
    } else {
        int rc_wait = wait(NULL);
        printf("hello, I am parent of %d (rc_wait:%d) (pid:%d)\n", rc_wait, (int) getpid());
    }
    return 0;
}
```

Figure 5.2: Calling fork() And Wait() (p2.c)

You might have noticed: the child isn't an exact copy. Specifically, although it has its own address space (i.e., its private memory), it has its own registers, usually the PC, and so the value it returns to the caller of fork() is different. Specifically, while the parent receives the PID of the newly-created child, the child receives a return code of zero. This differentiation is useful, because it is simple to write the code that handles the two different cases (as above).

You might also notice: the output (output of pl.c) is not deterministic. When the child process is created, there are now two active processes in the system that we call: the parent and the child. Assuming we are running on a system with a single CPU (for simplicity), either the child or the parent might run at that point. In our example (above), the parent did and printed its message first. In other cases, the opposite might happen, as we show in this output trace:

```
prompt> ./pl
hello world (pid:29146)
hello, I am child (pid:29147)
hello, I am parent of 29147 (pid:29146)
prompt>
```
