# Multiprocessor Scheduling (Advanced)

This chapter will introduce the basics of **multiprocessor scheduling**. As this topic is relatively advanced

After years of existence only in the high-end of the computing spectrum, **multiprocessor** systems are increasingly commonplace, and have found their way into desktop machines, laptops, and even mobile devices. The rise of the **multicore** processor, in which multiple CPU cores are packed into a single chip, is the source of this proliferation; these computer architects have had a difficult time making a single CPU faster without using (way) too much power. And we now have a few CPUs available to use, which is a good thing, right?

Of course, there are many difficulties that arise with the arrival of more than a CPU. A primary one is that a typical application (i.e., some C program you wrote) uses only a single CPU; adding more CPUs does not make that application run faster. To remedy this problem, you'll have to rewrite your application to run in **parallel**, perhaps using **threads** (as discussed in great detail in the second piece of this book). Multi-threaded applications can spread across multiple CPUs and thus run faster when given more CPU resources.
