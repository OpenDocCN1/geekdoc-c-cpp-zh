# 378 CONDITION VARIABLES

```
int loops;
cond_t cond;
mutex_t mutex;
```

```
void *producer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex); // p1
        while (count == 1) { // p2
            Pthread_cond_wait(&cond, &mutex); // p3
            put(i); // p4
        }
        Pthread_cond_signal(&cond); // p5
        Pthread_mutex_unlock(&mutex); // p6
    }
}
```

```
void *consumer(void *arg) {
    int i;
    for (i = 0; i < loops; i++) {
        Pthread_mutex_lock(&mutex); // c1
        while (count == 0) { // c2
            int temp = get(); // c3
            Pthread_cond_wait(&cond, &mutex); // c4
        }
        Pthread_cond_signal(&cond); // c5
        Pthread_mutex_unlock(&mutex); // c6
        printf("%d\n", temp);
    }
}
```

**Hoare semantics**, is harder to build but provides a stronger guarantee that the thread will run immediately upon being woken [H74]. Virtually every system employs Mesa semantics.

# **Better, But Still Broken: While, Not If**

Fortunately, this fix is easy (Figure 30.10): change the if to a **while**. Think about how this works: now T1 wakes up and (with the lock held) re-checks the state of the shared variable (c2). If the buffer is empty at that point, the consumer simply goes back to sleep (c3). The corollary (c1) is also changed a in the producer (p2).

Thanks to Mesa semantics, a simple rule to remember with condition variables is to **always use loops**. Sometimes you don't have to check the condition, but it is always safe to do so; just do it and be be happy.
