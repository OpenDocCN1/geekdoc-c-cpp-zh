Using trace, we can see that mv uses the system call rename (char *old, char *new), which precisely takes two arguments: the original name of the file (old) and the new name (new).

One interesting guarantee provided by the rename (call) is that it (usually implemented as an atomic call with respect to system crashes; if the system crashes during renaming, the file will either be named the old name or the new name, and no in-between state can arise. rename() is critical for supporting certain kinds of applications that require an atomic update to file state.

Let's be a more specific here. Imagine that you are using an editor (e.g., emacs), and you insert a line into the middle of a file. The file's name is the same as the example. The editor might update the file to guarantee that the new file has the original contents the line is inserted as follows (ignoring error-checking for simplicity):

```
int fd = open("foo.txt.tmp", O_WRONLY|O_CREAT|O_TRUNC, S_IRUSR|S_IWUSR);
write(fd, buffer, size); // write out new version of filesync(fd);
close(fd);
rename("foo.txt.tmp", "foo.txt");
```

What the editor do in this example is: write out the new version of the file under a temporary name (foo.txt.tmp), force it to disk with fsync(), and then, when the application is certain the new file metadata and contents are on disk, rename the temporary file to the original file's name. This last step atomically swaps the new file into place, while concurrently deleting the old version of the file, and thus an atomic file update is achieved.

# 39.9 Getting Information About Files

Beyond file, we expect the file system to keep a fair amount of information about each file it is storing. We generally call this about metadata. To see the metadata for a certain file, we can use the stat() system calls. These calls take a pathname (or descriptor) to a file and fill in a struct as seen in Figure 9.1.

You can see that there is a lot of information about each file, including its size (in bytes), a low-level name (i.e., inode number), some ownership information, and some information about when the file was accessed or modified, among other things.
