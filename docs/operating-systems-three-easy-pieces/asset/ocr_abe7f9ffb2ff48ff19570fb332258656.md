The behavior of a clock algorithm variant is shown in Figure 22.9. This variant randomly scans pages when doing a replacement; when it encounters a page with a reference bit set to 1, it clears the bit (set to 0); when it finds a page with the reference bit set to 0, it chooses it as its victim. As you can see, it doesn't quite as well as perfect LRU, it does better than approaches that don't consider history at all.

# 22.9 Considering Dirty Pages

One small modification to the clock algorithm (also originally suggested by Corbato [C69]) is bit set by the additional consideration of whether a page has been modified or not in memory. The reason for this: if a page has been modified and is thus dirty, it must be written back to evict it, which is expensive. If it has not been modified (and thus clean), the eviction is free; the physical frame can simply be reused for other purposes without additional I/O. Some systems prevent it to evict dirty pages over pages.

To support this behavior, the hardware should include a modified bit (a.k.a. dirty bit). This bit is set any time a page is written, and thus can be incorporated into the page-replacement algorithm. The clock algorithm, for example, could be changed to scan for pages that are both unused and clean to evict first; failing to find those, then for unused pages that are dirty, and so forth.
