Unfortunately, things get a little more interesting when little memory is free. the memory pressure forces us to start out pages to make room for actively-used pages. Deciding which page (or pages) to evict is the replacement policy of the OS; historically, it was one of the most important decisions the early virtual memory systems made, as older systems had little physical memory. Minimally, it is an set of policies worth knowing a little more about. And thus our problem:

> The Crux: How to Decide Which Page to Evict
How the OS decide which page (or pages) to evict from memory? This decision is made by the replacement policy of the system, which usually follows some general principles (discussed below) but also includes certain tweaks to avoid corner-case behaviors.

# 22.1 Cache Management

Before diving into policies, we describe the problem we are trying to solve in more detail. Given that main memory holds some subset of all the pages in the system, it can rightly be viewed as a cache for virtual memory pages in the system. Our goal in picking a replacement policy for this cache is to minimize the number of cache misses, i.e., to minimize the number of times that we have to fetch a page from disk. The number of cache hits let us calculate the average memory access time (AMAT) for a program (metric computer architects compute for hardware caches [HP06]). Specifically, given these values, we can compute the AMAT of a program as:

```
AMAT = T_M + (P_{Miss} \cdot T_D)
```
