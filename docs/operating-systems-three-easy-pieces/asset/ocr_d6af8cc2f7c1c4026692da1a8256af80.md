# Data Integrity and Protection

Beyond the basic advances found in the file systems we have studied thus far, a number of features are worth studying. In this chapter, we focus on reliability once again (having previously studied storage system reliability-in the RAID chapter). Specifically, how should a file system or storage system ensure that data is safe, given the unreliable nature of modern storage devices?

This general area is referred to as data integrity or data protection. Thus, we will now investigate techniques used to ensure that the data you put into storage is the same when the storage system returns it to you.

# 45.1 Disk Failure Modes

As you learned in the chapter about RAID, disks are not perfect, and can fail (on). In early RAID systems, the model of failure was quite simple: either the disk is working, or it fails completely, and the detection of such a failure is straightforward. This fail-stop model of disk failure makes RAID relatively simple [S90].

What you didn't learn is all about of the other types of failure modes modern disks exhibit. Specifically, as Bairavasandas et al. studied in great detail [B07, B08], modern disks will occasionally seem to be mostly working but have trouble successfully accessing one or more blocks. Specifically, two types of single-block failures are common and worthy of consideration: latent-sector errors (LSEs) and block corruption. We'll discuss each in more detail.
