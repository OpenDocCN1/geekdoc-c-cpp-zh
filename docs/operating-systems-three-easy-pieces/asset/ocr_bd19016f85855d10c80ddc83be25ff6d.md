I/O Devices

For example, on x86, the in and out instructions can be used to communicate with devices. For example, to send data to a device, the caller specifies a register with the data in it, and a specific port names the device. Executing the instruction leads to the desired behavior.

Such instructions are usually privileged. The OS thus is the only entity allowed to directly communicate with them. If any program could read or write the disk, for example: total chaos (as always), as any program could use a loophole to gain complete control over the machine.

The second method to interact with devices is known as memory-mapped I/O. With this approach, the hardware makes registers available as if they were memory locations. To access a particular register, the OS issues a load (to read) or store (to write) the address; the hardware then routes the load/store to device instead of main memory.

There is not some great advantage to one approach or the other. The memory-mapped approach is nice in that no new instructions are needed to support it, but both approaches are still in use.

# 36.7 Fitting Into OS: The Device Driver

One problem we will discuss: how to fit devices, each of which have very specific interfaces, into the OS, which we would like to keep as general as possible. For example, consider a file system. We'd like to build a file system that worked on top of SCSI devices, IDE disks, USB keychain drivers, and so forth, and we'd like the file system to be oblivious to all of the details of how to issue a read or write request to these types of devices. Thus, our problem:

How can we keep most of the OS device-neutral, hiding the details of device interactions from OS subsystems?

The problem is solved through the old-age technique of abstraction. At the lowest level, a piece of software the OS must know in detail how a device works. We call this piece of software device driver, and any specifics of device interaction are encapsulated within.

Let us see how this abstraction might help OS design and implementation by examining the Linux file system stack software.
