# SEMAPHORES

# ASIDE: SETTING THE VALUE OF A SEMAPHORE

We've now seen two examples of initializing a semaphore. In the first case, we set the value to 1 to use the semaphore as a lock; in the second, to 0, to use the semaphore for ordering. So what's the general rule for semaphore initialization?

One simple way to think about it, thanks Perry Kivolowitz, is to consider the number of resources you are willing to give away after initialization. With the lock, it was 1, because you are willing to have the lock locked (given away) immediately after initialization. With the ordering case, it was 0, because there is nothing to give away at the start, when the child thread is done created, at which point, the value is incremented to 1. Try this line of thinking on future semaphore problems, and if it helps.
