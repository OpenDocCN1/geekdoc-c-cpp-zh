# Homework (Measurement)

This homework introduces you to a new tool, **vmstat**, and how it can be used to understand memory, CPU, and I/O usage. Read the associated README and examine the code in `mem.c` before proceeding to the exercises and questions below.

# Questions

+   1. First, open two separate terminal connections to the **same machine**, so that you can easily run something in one window and the other.
Now, in window, run `vmstat 1`, which shows statistics about machine usage every second. Read the man page, the associated README, and any other information you need so that you can understand its output. Leave this window running `vmstat` for the rest of the exercises.
Now we will run the program `mem.c` but with very little memory usage. This can be accomplished by typing `./mem 1` (which uses 1 MB of memory). How do the CPU usage statistics change when running `mem`? Do the numbers in the `user` column make sense? How does this change when running more than one instance of `mem` at once?

+   2. Let's now looking at the memory statistics running two columns: `swpd` (the amount of virtual memory) and `free` (the amount of idle memory). `./mem 1024` (which allocates 1024 MB) and watch how these values change. In particular, how does the **free** column change when the program exits? Does the amount of free memory increase? Then kill the running program (by typing ctrl-c) and watch again how the values change. What do you notice about the values? How does the free column change when the program exits?

+   3. We'll look at the `swap` columns (**si and so**), which indicate how much swapping is taking place to and from the disk. Of course, to activate this, you will need to run `mem` with large amounts of memory in your Linux system (for example, by typing `/proc/meminfo`; type man proc for the `/proc` file system and the information you can find there). One of the entries in `/proc/meminfo` is the total amount of memory in your system. Let's assume it's something 8 GB of memory; if so, start by running `mem 4000` (about 4 GB) and watching the swap in/out columns. Which columns give non-zero values? Then, try with `5000`, `6000`, etc. What happens to these values as the program enters the second loop (and beyond), as compared to the first loop? How much data (total) are swapped in and out during the second, third, and subsequent loops? (do the numbers make sense?)
