# PAGING: SMALLER TABLES

> TIP: BE WARY OF COMPLEXITY
System designers should be wary of adding complexity to their system. What a good systems builder does implement the least complex system that achieves the task at hand. For example, if disk space is abundant, don't design a file system that works to use as few bytes as possible; similarly, if processors are fast, it is better to write a clean and understandable module within the OS than CPU-optimized, hand-assembled code for the task at hand. Beware of needless complexity; optimizing code or other approaches makes systems harder to understand, maintain and debug. Antoine de Saint-Exupery wrote: "Perfection is attained when there is no longer anything to add, but when there is no longer anything to take away." What he wrote: "It's a lot easier to say about perfection than to actually achieve it"

The other page of the page table is found PFN 101. This page contains mappings for the last 16 VPNs of the address space; see Figure 20.5 for details.

In the example, VPNs 254 and 255 (the stack) have valid mappings. Hopefully, we can see from this how much space savings are possible with a multi-level index structure. In this example, instead of allocating all sixteen pages for a linear page table, we allocate only three: one for the page directory, and two for the chunks of the page table that have valid mappings. The savings for large (32-bit or 64-bit) address spaces could be much greater.

Finally, let's use this information in order to perform a translation. Here is an address that refers to the 0th byte of VPN 254: 0x3F80, or 0011 1111 0000 0000.

Recall that we use the top 4 bits of the VPN to index into the page directory. Thus, 1111 will choose the last (15, if you start at the 0th) entry of the page directory. This points to a valid page at address 101. We then use the next 4 bits of the VPN (1110) to index into that page table and find the PTE. 1110 is the next-to-last (14th) entry on the page, and tells us that the physical address is 55. By concatenating PFN=55 (or 0x37) with offset=0x0000, we can form our physical address and issue the request to the memory system: PhysAddr = (PTE << SHIFT) + offset
