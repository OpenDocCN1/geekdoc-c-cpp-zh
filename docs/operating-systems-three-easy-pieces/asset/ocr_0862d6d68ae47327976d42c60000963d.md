# INTERLUDE: PROCESS API

In the example above, the output of the program wc is redirected into the output file newfile.txt (the greater-sign is how said redirection is indicated). The way the shell accomplishes this task is quite simple: when the child is created, before calling exec(), the shell closes standard output and opens the file newfile.txt. By doing so, any output from the soon-to-running program wc are sent to the file instead of the screen.

Figure 5.4 (page 48) shows a program that does exactly this. The reason for this redirection is due to an assumption about how the operating systems manage file descriptors. Specifically, UNIX systems start looking for file descriptors at zero. In this case, STDOUT.FILENO will be the first available one and then get assigned when open() is called. Subsequent writes by the child process to the standard output file descriptor, for example by routines as print(), will then be routed transparently to the newly-opened file instead of the screen.

Here is the output of running the p4.c program:

```
prompt> /p4
prompt> cat p4.output
      32  109      846 p4.c
prompt>
```

You'll notice (at least two) tidbits about this output. First, when p4 is running, it looks as if nothing has happened; the shell just prints the command and is immediately ready for your next. However, that is not the case; the program p4 did indeed call fork() to create a new child, and then run the wc program via a call to execvp(). You don't see any output to the screen because it has been redirected to the file p4.output, you can see when we call the output file, all the output from running wc is found. Cool?

Pipes are implemented in a similar way, but with the pipe system. In this case, the output of one process is connected to an input pipe, and the input of another process is connected to that same pipe; thus, the output of one process seamlessly is used as input to the next, and long chains of commands can be strung together. As an example, considering how many times said word occurs; with a word in a file, and the utilities grep and wc, it is easy; just grep -o foo file | wc -1 into the command prompt and marvel at the result.

Finally, we have just sketched out the process API at a high level, there is a lot more detail about these calls out to be learned and digested; we'll learn more, for example, about file descriptors when we talk about file systems in the third part of the book. Now, suffice it to say that the fork()/exec() combination is a powerful way to create and manipulate processes.
