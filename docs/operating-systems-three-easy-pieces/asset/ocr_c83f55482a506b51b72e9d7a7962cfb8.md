# 28.4 Evaluating Locks

Before building any locks, we should first understand what our goals are, and thus how to evaluate the efficacy of a particular lock implementation. To evaluate whether a lock works (and works well), we should establish some criteria. The first is whether the lock does its basic task, which is to provide **exclusion**. Basically, does the lock do its work, preventing multiple threads from entering a critical section?

The second is **fairness**. Does each thread contending for the lock get a fair shot at acquiring or is it free? Another way to look at this is by examining the more extreme case: does any thread contending for the lock **starve** while doing so, unless other than?

The final is **performance**, specifically the time added by using the lock. There are a few cases that are worth considering here. One is the case of no contention; when a single thread is running and releases the lock, what is the overhead of doing so? Another is the case where multiple threads are contending for the lock on a single CPU; in this case, are there performance concerns? Finally, how does the lock perform when there are multiple CPUs involved, and threads on each contending for the lock? By comparing these scenarios, we can better understand the performance impact of using various locking techniques, as described below.
