# CONCURRENCY: AN INTRODUCTION

As it turns out, there are at least two major reasons you should use threads. The first is simple: parallelism. Imagine you are writing a program that performs operations on large arrays, for example, adding two large arrays together, or incrementing the value of each element in the array by some amount. If you are running on just a single processor, the task is straightforward: perform each operation and be done. However, if you are executing the program on a system with multiple processors, you have the potential of speeding up this process by using the processors to perform each portion of the work. The task of transforming your single-threaded program into a program that does this sort of work on multiple CPUs is called parallelization, using a thread per CPU to do what is a natural and typical way to make programs run on modern hardware.

The second reason is a subtle way to avoid blocking program due to slow I/O. If you are writing a program that performs different types of I/O: either waiting to send or receive a message, for an explicit (or implicitly) to complete, or for a page to finish. Instead of waiting, your program may wish to do something else, utilizing the CPU for computation, or even issuing further I/O requests. Using threads is a natural way to avoid getting stuck; while one thread in your program waits (i.e., is blocked) the scheduler can switch to other threads, which are ready to do something else. Thread enables overlap of I/O with other activities within a single program, which makes multiprogramming for processes across programs; as a result, modern server-based applications (web servers, database management systems, and the like) make use of threads in their implementations.

Of course, in the cases mentioned above, you could use multiple processes instead of threads. However, threads share an address space and thus make it easy to share data, hence are a natural choice when constructing these types of programs. Processes are a more sound choice for logically separate tasks where little sharing of data structures is needed.
