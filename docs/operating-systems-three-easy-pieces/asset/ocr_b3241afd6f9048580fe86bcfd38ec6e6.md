# INTERLUDE: FILES AND DIRECTORIES

# References

[BD96]"Checking for Race Conditions in File Access" by Matt Bishop, Michael Dilger. Computing Systems 9-2, 1996. A great description of the TOCTOU problem and its presence in file systems.

[CK-08]"The xv Operating System" by Russ Cox, Frans Kaashek, Robert Morris, Nickolai Zeldovich. From: http://github.com/mit-pdos/xv-base. As mentioned before, a cool and simple Unix implementation. We have used an older version (2012-01-30-1-c41342) and hence some examples in the book may not be the latest in source.

[HT-18]"Fastly later File System Crash Consistency to Produce ACID Transactions" by Y. Hu, J. Lee, Y. Kwon, T. Cheng, Y. Chidambaram, E. Witchel. USENIX AT’18, 2018. The first fast file system at UNIX AT’18, and a great place to start learn about transactional file systems.

[Processes-84]"Processes as Files" by Maurice Uman. The paper that introduced the Unix file system, where each process was created as a file within a simple file system. A clever idea that still holds in modern UNIX systems.

[Cap-84]"Capability-Based User Systems" by Henry M. Levy. 1984. Available: http://homes.washington.edu/levy/capabook. An excellent overiew of capability-based systems

[MLF-94]"All File Systems in the Linux" by Marshall K. McKusick, William N. Joy, Sam J. Levy, Robert S. Fabry. ACM TOCS, 2, August 1984. We’ll talk about the Fast File System (FFS) later on. Here, we refer to all of the other from things it turned it into, like file names and symbolic links. Sometimes, when you are building a new system to improve one, you might a lot of other things along the way.

[P-13]"Event Ordering, Application-Level Consistency" by Thamunalian S. Pillai, Vija Chidambaram, Joshua Young, Andreas A. Arpacci-Dusseau, and Remzi H. Arpacci-Dusseau. HotDep ’13, November 2013. Our work shows how readily applications can make mistakes in committing data to disk; in particular, assumptions about the file system create inconsistencies and thus the applications works correctly only if they are running on a specific file system.

[P-14]"All File Systems Are Not Equal: on the Complexity of Crafting Crash-Consistency" by Thamunalian S. Pillai, Al-Kiswany, Vija Chidambaram, Ramnathan Alagakaran, Samfield, Colorado, October 2014. The full conference paper on this topic – with many more details and interesting insights from the first of work paper after.

[MK-99]"Complexity of Computer Systems" by Henry H. Saltzer and Frans. Kahn. Morgan-Kaufman. This tour of force is a must-read for anyone interested in the field. It is how they teach systems at MIT. Read it once, and then read it a few more times to let it soak in.

[SR05]"Advanced Programming in the Unix Environment" by W. Richard Stevens and Stephen A. Rago. Addison-Wesley, 2005. We have highly referenced this book a hundredfold times. It is that useful to you, if you care to become an awesome systems programmer.

[T-08]"Portably Solving File TOCTOU Races with Hardness Amplification" by D. Tsafrir, T. Hertz, D. Wagner, D. Silva. FAST ’08, San Jose, California. The paper that introduced TOCTOU, is a recent-ish and well-done description of the problem and a way to solve the problem in a portable manner.
