# Homework

Most (and eventually, all) chapters of this book have homework sections at the end. Doing these homeworks is important, as it lets you, the reader, gain more experience with the concepts presented within the chapter.

There are two types of homeworks. The first is based on **simulation**. A simulation of a computer system is just a simple program that pretends to do some of the interests of what a real system does, and then return output metrics to show how the system behaves. For example, a hard drive simulation might take a series of requests, simulate how long they would take to get serviced by a hard drive with certain performance characteristics, and then report the average latency of the requests.

The cool thing about simulations is they let you easily explore how systems behave without the difficulty of running a real system. Even let you create systems that cannot exist in the real world (for example, a hard drive with unimaginably fast performance), and thus see the potential impact of future technologies.

Of course, simulations are not just approximations of how a real system. If an important aspect of real-world behavior is omitted, the simulation will report bad results with suspicion. In the end, how a system behaves in the real world is what matters.

The second type of homework requires interaction with **real-world code**. Some of these homeworks are measurement focused, whereas others just require some small-scale development and experimentation. Both are just small forays into the larger world you would be getting into, which is how to write systems in C on UNIX-based systems. Indeed, larger-scale projects, which go beyond these homeworks, are needed to push you in this direction; thus, beyond doing homeworks, we strongly recommend you to solidify your skills. See this page (github.com/remzi-arpusseau/ostep-projects) for some projects. To do these homeworks, you likely have to be on a UNIX-based machine, running either Linux, macOS, or similar system. It should also have a C compiler (e., gcc) as well as Python. You should also know how to edit code in a real editor of some kind.

### A Dialogue on Virtualization

**Professor:** And thus we reach the first of three pieces on operating systems: **virtualization.**

**Student:** *But what is virtualization, oh noble professor?*

**Professor:** *Imagine we have a peach.*

**Student:** *A peach? (incredulous)*

**Professor:** Yes, Let us call the *physical* peach. But we have many eaters who would like to eat this peach. What we would like to present to each is their own peach, so that they can be happy. We call the peach we create **virtual peaches**; we somehow create many of these virtual peaches out of one physical peach. And the important thing: in this illusion, it looks to each eater like they have a physical peach, but in reality they don't.

**Student:** So you are sharing the peach, but you don't even know it?

**Professor:** Right!

**Student:** Well, if I was sharing a peach with somebody else, I think I would notice.

**Professor:** Ah! Good! But that is the thing with many eaters; most of the time they are napping or doing something, and thus, we can snatch that peach away and give it to someone else for a while. And we create the illusion of many virtual peaches, one peach for each person!

**Student:** Sounds like a bad campaign slogan. You are talking about computers, right Professor?
