Then, we compare the old data and the new data; if they are the same (e.g., $C_{new} = C_{old}$), then we know the parity will also remain the same (i.e., $P_{new} = P_{old}$). If, they are different, then we must flip the old parity bit to its current state, that is, if ($P_{old} == 1$), $P_{new}$ will be set to 0; if ($P_{old} == 0$), $P_{new}$ will be set to 1. We can express this whole process nearly with XOR (where $\oplus$ is the XOR operator):

```
$P_{new} = (C_{old} \oplus C_{new}) \oplus P_{old} \quad (38.1)$
```

Because we are using blocks, not bits, we perform calculation over all the bits in the block (e.g., 4096 bytes in each multiplied by 8 bits per byte). In most cases, the new block will be different from the old block and thus the new parity block will too.

For this performance analysis, let assume we are using the subtractive method. Thus, for each case, the RAID will perform 4 physical I/Os (two reads and two writes). Imagine there are lots of writes submitted to the RAID; how can RAID4 perform in parallel? To understand, let us look at the RAID-4 layout (Figure 38.6).

| Disk 0 | Disk 1 | Disk 2 | Disk 3 | Disk 4 |
|---|---|---|---|--|
| 0 | 1 | 2 | 3 | P0 |
| *P4 | 5 | 6 | 7 | *P1 |
| 8 | 9 | 10 | 11 | P2 |
| 12 | *13 | 14 | 15 | *P3 |

**Figure 38.6: Writes To 4, 13, and Even Parity Blocks**

Now imagine there 2 small writes submitted to the RAID-4 at the same time, blocks 4 and 13 (marked with * in the diagram). The data for these disks is on disks 0 and 1, and thus the read and write to happen in parallel, which is good. The problem that arises with the parity disk; both the requests have to read the related parity blocks for 4 and 13, parity (marked with *). Hopefully, the issue is now clear: the parity is a bottleneck under this type of workload; sometimes we call this the **small-write problem** for parity-based RAIDs. Thus, even though the disks could be accessed in parallel, the parity prevents any parallelism from initializing; all writes to the system will be serialized because of the parity disk.
