# PAGING: SMALLER TABLES

TIP: USE HYBRIDS
When you have two good and seemingly opposing ideas, you should always see if you can combine them into a hybrid that manages to achieve the best of both worlds. Hybrid corn species, for example, are known to be more robust than any naturally-occurring species. Of, not all hybrids are a good idea; the Zeebok (or Zonkey), is a cross of a Zebra and a Donkey. If you don't believe such a creature exists, look it up, and prepare to be amazed.

The critical difference in our hybrid scheme is the presence of a bounds register per segment; each bounds register holds the value of the maximum page in the segment. For example, if the code segment only uses its first three (0, 1, and 2), the code segment table will have three entries allocated to it and the bounds register will be set to 3; memory accesses beyond the end of the segment will generate an exception and lead to the termination of the process. In this manner, our hybrid approach realizes a significant memory savings compared to the linear page table; unallocated pages between the stack and the heap no longer take up space in a page table (just to mark them as not valid).

However, as you might notice, this approach is not without problems. First, it requires us to use segmentation; because segmentation is not as flexible as we would like, as it assumes a certain usage of the address space; if we have a large but sparsely-used heap, for example, we can end up with a lot of page table waste. This hybrid approach is managed in page-sized units, page tables can now be of arbitrary size (in PTEs). Thus, finding free space for memory is more complicated. For these reasons, people continued to look for better ways to implement smaller page tables.

# 20.3 Multi-level Page Tables

A different approach doesn't rely on segmentation but get rid of all invalid regions in the page table by keeping them all in memory? We call this approach a multi-level page table, as it turns the linear page table into something like a tree. This approach is so effective that many modern systems employ it (e.g., x86 [BOH101]). We describe this approach in detail.

The basic idea behind a multi-level page table is simple. First, chop up the page table into page-sized units; then, if an entire page of page-table entries (PTEs) is invalid, don't allocate that page of the table at all. To track whether a page of the page table is valid (and if valid, where it is in memory), use a new structure, called the page directory. The page directory thus either can be used to tell you where a page of the page table is, or that the entire page of the page table contains no valid pages.
