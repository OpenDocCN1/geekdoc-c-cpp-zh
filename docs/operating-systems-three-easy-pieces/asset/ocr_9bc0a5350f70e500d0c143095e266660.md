# INTERLUDE: MEMORY API

> TIP: IT COMPILED OR RAN ≠ IT IS CORRECT
Just because a program compiled(!) or even ran once or many times correctly does not mean the program is correct. Many events may have you to a point where you believe it works, but then changes and it stops. A common student reaction is to say (or yell) "But it worked before!" and blame the compiler, operating system, hardware, or even (dare we say it) The problem is usually all right where you think it would be, in your code. To work and debug it you blame those other components.

When you run this code, it will likely lead to a segmentation fault, which is a fancy term for YOU DID SOMETHING WRONG WITH MEMORY PROGRAMMER AND I AM ANGRY. In this case, the proper code might look like this:

```
char *src = "hello";nchar *dst = ( *) malloc(strlen(src) + 1);
strcpy(dst, src); // work properly
```

Alternately, you could use strdup() and make your life even easier. Read the strdup man page for more information.

# Not Allocating Enough Memory

A related error is not allocating memory, sometimes called a buffer overflow. In the example above, a common error is to make almost enough room for the destination buffer.

```
char *src = "hello";nchar *dst = ( *) malloc(strlen(src)); // too small!
strcpy(dst, src); // work properly
```

Oddly, depending on how memory is implemented and many other details, this program will run seemingly correctly. In some cases, when the string copy executes, it writes one byte too far the end of the allocated space, but in some cases this is harmless, perhaps overwriting a variable that isn't used. In some cases, these overflows can be incredibly harmful, and in fact they are the source of many security vulnerabilities. If the memory library allocated a little extra space anywhere, and thus your program actually doesn't scribble on other variable's value and works quite fine. In even other cases, the program will indeed fail and crash. And thus we learn another valuable lesson: even though it ran once, doesn't it's correct.
