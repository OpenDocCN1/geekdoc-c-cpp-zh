> TIP: WHEN IN DOUBT, TRY IT OUT

If you aren't sure how some routine or operator you are using behaves, there is no substitute for simply trying it out and making sure it behaves as expect. While reading the manual pages or other documentation is useful, it works in practice is what matters. Write some code and test! It is not the best way to make sure your code behaves as you desire. double *d = (double) malloc(sizeof(double));

Woy, that's lot of double-ing! This invocation of malloc() uses the sizeof() operator to request the right amount of space; in C, this is generally thought of as a compile-time operator, meaning that the actual size is known at compile time and a number (in this case, 8, for double) is substituted as the argument to malloc(). For this reason, sizeof() is correctly thought of an operator and not a function call (a function would take place at run).

You can also pass the name of a variable (and not just a type) to sizeof(), but in some cases you may not get the results you desire, so be careful. For example, let's look at the following code snippet:

```
int *x = malloc(10 * sizeof(int));
printf("%d\n", sizeof(x));
```

In the first line, we've declared space for an array of 10 integers, which is fine and daddy. However, when we use sizeof() in the next line, it returns a small value, such as 4 (on 32-bit machines) or 8 (on 64-bit machines). The reason is that in this case, sizeof() thinks we are simpel how big a pointer to an integer is, not how much memory we have dynamically allocated. However, sometimes sizeof() does work as you might expect:

```
int x[10];
printf("%d\n", sizeof(x));
```

In this case, there is enough static information for the compiler to know that 40 bytes have been allocated.

Another place to be careful with strings. When declaring space for a string, using the following idiom: malloc(strlen(s) + 1), gets the length of the string using the function strlen(), and adds 1 to it in order to make room for the end-of-string character. Using sizeof() may lead to trouble.
