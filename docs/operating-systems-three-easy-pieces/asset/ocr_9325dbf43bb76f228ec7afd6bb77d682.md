More intriguing is the case of write buffering. NFS servers absolutely may not return success on a WRITE protocol until the write has been forced to stable storage (e.g., to disk or some other persistent device). While they can place a copy of the data in server memory, returning success to the client on a WRITE protocol could result in incorrect behavior; can you figure out why?

The answer lies in our assumptions about how clients handle server failure. Imagine the following sequence of writes issued by a client:

```
write(fd, a_buffer, size); // fill 1st block with a’s
write(fd, b_buffer, size); // fill 2nd block with b’s
write(fd, c_buffer, size); // fill 3rd block with c’s
```

These overwrites the three blocks of a file with a’s, then b’s, and c’s. Thus, if the file initially looked like this:

```
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy
zzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzz
```

We might expect the final result after these writes to be like this, with x’s, y’s and z’s, would be overwritten with a’s, b’s, and c’s.

```
aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbcccccccccccccccccccccccccccccccccc
```

Now let’s assume for the sake of the example that these three clients were issued to the server first WRITE protocol and issued to the disk, and the client informed of its success. Now assume the second write is just in memory, and the server also reports it to the client before forcing to disk; unfortunately, the server crashes before writing to it. The server quickly restarts and recovers the third write request, which all succeeds.

Thus, to the client, all the requests requested, but we are surprised that the file contents like this:

```
aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy <--- oops
cccccccccccccccccccccccccccccccccccccccccccccc
```

Yikes! Because the server told the client the second write was successful before committing to it, an old chunk is left in the file, which, depending on the application, may be catastrophic.
