# ASIDE: EMULATING REFERENCE BITS

As it turns out, you don't need a hardware reference bit in order to get some notion of which pages are in use in a system. In the early 1980's, Babuoglu and Joy showed that protection bits on the VAX can be used to emulate reference bits [BJ81]. The basic idea: if you want to get some understanding of which pages are being used in a system, mark all of the pages as inaccessible; (keep around the information as to which pages are really accessible by the process, perhaps in the "reserved" OS field of the page table) if a process accesses it, it will generate a trap into the OS; the OS will then check if the page should be accessible, and if so, revert the page to its normal protections (e.g., read-only, or read-write). At the time of a replacement, the OS can check which pages remain inaccessible, and thus give an idea of which pages have not been used. The key to this "emulation" of reference bits is reducing overhead while still obtaining a good idea of page usage. The OS must not be too aggressive in marking pages inaccessible, or overhead would be too high. The OS also not be too passive in such marking, or all pages will end up referenced; the OS will again have no idea of which page to evict.

To address these two problems, the developers can use the segmented FIFO replacement [Rl81]. The idea is simple: each process has a maximum number of pages it can keep in memory, known as its resident set (RSS). Each of the pages is kept on a FIFO list; when a process exceeds the RSS, the "first-in" page is evicted. FIFO clearly does not need any support from the hardware, and is easy to implement.

Of course, pure FIFO does not perform particularly well, as saw earlier. To improve FIFO's performance, VMS introduced two second-chance lists where pages are placed before being evicted from memory, specifically a global clean free list and dirty page list. When a page P exceeds its RSS, it is removed from its per-process FIFO; if clean (not modified), it is placed on the end of the clean page list; if dirty (modified), it is placed on the end of the dirty page list. If another process Q seeks, it takes the first free page of the global list.
