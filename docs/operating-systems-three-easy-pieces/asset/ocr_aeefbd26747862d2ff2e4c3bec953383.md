Pretty simple, the put() routine assumes the buffer is empty (and checks this with an assertion), and then puts a value into the shared buffer and marks it full by setting count to 1. The get() routine does the opposite, when the buffer is empty (i.e., setting count to 0) and returning the value. Don't worry that this shared buffer has a single entry; we'll generalize it to a queue that can handle multiple entries, which will be more fun than it sounds.

Now we need to write some routines to know when it is OK to access the buffer to put data into or get data out of it. The conditions for this would be obvious: only put data into the buffer when count is zero (when the buffer is empty), and only get data from the buffer when count is one (i.e., when the buffer is full). If we write the synchronization code that a producer puts a full buffer, or a consumer gets data from an empty one, we have done something wrong (and in this code, an assertion will fail).

This work is to be done by two types of threads, one set of which we'll call producer threads, and the other which we'll call consumer threads. Figure 30.7 shows the code for a producer that puts an integer into the shared buffer number of times, and a consumer gets the data out of that shared buffer (forever), each time printing the data item it from the shared buffer.
