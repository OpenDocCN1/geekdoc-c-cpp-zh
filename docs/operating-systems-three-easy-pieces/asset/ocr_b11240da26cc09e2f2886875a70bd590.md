> TIP: THERE'S NO FREE LUNCH
There's No Such Thing As A Free Lunch, or TNSTAAFL for short, is an old American idiom that implies when you are seemingly getting something for free, in fact you are likely paying some cost for it. It comes from the days when diners advertised a free lunch for customers, hoping to draw them in; only when you went in, did you realize that to acquire the “free” lunch, you had to purchase one or more beverages. Of course, this may not actually be a problem, particularly if you are an aspiring alcoholic (or typical undergraduate student).

# Common Checksum Functions

A number of functions are used to compute checksums, and vary in strength (i.e., how good they are protecting data integrity) and speed (i.e., how quickly they can be computed). A trade-off that common in systems arises: usually, the more protection you get, the costlier it is. There is no such thing as a free lunch.

One simple checksum that is based on exclusive or (XOR). With XOR-based checksums, the checksum is computed by XORing each of the data block being checksummed, producing a single value that represents the XOR of the entire block.
To make this more concrete, imagine we are computing a 4-byte checksum over a block of 16 bytes (this block is of course too small to really be a disk sector, but it will serve for the example). The 16 data bytes, in hex, look like:

```
365e c4cd ba14 892ec 2c3a 40be f666
```

If we view them in binary, we get the following:

```
0011 0110 0101 1110  1100 0100 1100 1101
1011 1010 0001 0100  1000 1010 1001 0010
1110 1110 1111 1111  0010 0011 0011 1010
0100 0000 1011 1110  1111 0110 0110 0110
```

Because we've lined up the data in groups of 4 bytes per row, it is to see what the resulting checksum will be: perform an XOR over each column to get the final checksum value:

```
0010 0000 0001 1011  1001 0100 0000 0110
```

The result in hex, is 0x201b9403.
XOR is a reasonable checksum but has its limitations. If, for example, two bits in the same position within each checksum unit change, the checksum will not detect the corruption. For this reason, people have investigated other checksum functions.
