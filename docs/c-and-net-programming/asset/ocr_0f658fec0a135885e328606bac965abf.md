# 26.3 Custom Hosting with CLR Objects

+   - While executing various applications there are multiple ways by which Windows understand that a binary is a .NET application. These techniques depend on versions of Windows. Normally .exe files are executed by Windows by looking at the PE-Header (Portable-Executable). This PE-Header says how it should be loaded into memory, what dependencies it has, and where the entry point is. To know the entry-point of a .NET application Windows uses certain technique. Actually, the application is in some IL-code. Executing that directly will clearly lead to a crash. It is not the IL-code that should start executing, but the .NET runtime, which eventually should load the IL-code and execute it.

+   - In newer versions of Windows, .NET comes preinstalled, and Windows has built-in support for recognizing a .NET application. This can be done by simply looking in the PE-Header present in all executables and DLLs. In older versions of Windows, execution is passed to an entry point where boot-strap code is located. The boot-strap, which is native code, uses an unmanaged CLR Hosting API, to start the .NET runtime inside the current process and launch the real program which is the IL-code.
