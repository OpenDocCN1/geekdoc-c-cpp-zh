# 17.9.3 DOM vs SAX

| Sr. No. | DOM | SAX |
|---|---|---|
| 1. | Stores the entire XML document into memory before processing. | Parses node by node. |
| 2. | Nodes can be inserted or deleted. | Nodes can not be inserted or deleted. |
| 3. | Stores entire document in the memory before processing, Occupies more memory, The entire xml tree must be in memory before the parser begins to parse. | Does not store XML in memory, It is no compulsory for the entire xml tree to be loaded before the parser begins to parse, it can work with the maximum depth of the given xml tree. |
| 4. | Traversing can be done in any direction. | Traversing can be done top to bottom. |
| 5. | There are formal specifications for the DOM. | There aren't formal specifications within SAX. |
| 6. | Streamed reading from the disk is impossible. | Streamed reading from the disk is possible. |
| 7. | Less problems during the XML validation. | More problems during the XML validation. |
| 8. | It is not event triggered parser. | It is event triggered parser. |
