
## Differences between Private and Shared Assembly
- Private assembly can be used by only one application.
- Shared assembly can be used by multiple applications
- Private assembly will be stored in the specific application's directory or sub-directory.
- Shared assembly is stored in GAC (Global Assembly Cache).
- There is no other name for private assembly.
- Shared assembly is also termed as shared assembly
- Strong name is not required for private assembly.
- Strong name has to be created for shared assembly.
- Private assembly doesn't have any version constraint.
- Shared assembly should strictly enforce version constraint.

## 27.1 XAML
- XAML is Extensible Application Markup Language and pronounced "zammel" is a markup language used to instantiate .NET objects. It's a simple and declarative language based on XML.

### 27.1.1 XAML Applications
- Although XAML is a technology that can be applied to many different problem domains, its primary role in life is to construct WPF user interfaces.
- XAML is the language to build user interfaces for Windows and Mobile applications that use Windows Presentation Foundation (WPF), UWP, and Xamarin Forms. The purpose of XAML is simple, to create user interfaces using a markup language that looks like XML. Most of the time, designer is to create XAML but XAML can also be directly manipulated by hand.

### 27.1.2 XAML Types
- The way XAML is being used currently, the XAML program looks as the XML-based syntax for representing a tree of .NET objects and these objects can be button in a window or a custom class. However XAML could be used on the other platform to represent non .NET objects.
- Below are subsets of XAML that are also used in web world,
1. **WPF XAML** - encompasses the elements that describe WPF content, such as vector graphics, controls, and documents.
2. **XPS XAML** - is the part of WPF XAML that defines an XML representation for formatted electronic documents.
3. **Silverlight XAML** - is a subset of WPF XAML that's intended for Silverlight applications. Silverlight is a cross-platform browser plug-in that allows us to create rich web content.
4. **WF XAML** - encompasses the elements that describe Windows Workflow Foundation.

### 27.1.3 XAML Working and XAML Compilation
### XAML Compilation
- XAML compilation is fast and XAML achieves this with BAML (binary application markup language), which is binary representation of XAML.
- While XAML compiles in Visual Studio, all XAML is converted into BAML and that BAML is then embedded as resource inside the final DLL or EXE assembly. BAML is tokenized, which means lengthier bits of XAML are replaced with shorter tokens. Not only is BAML significantly smaller, it's also optimized in a way that makes it faster to parse at runtime.

### Working of XAML
XAML is a **declarative language** in the sense it defines the **WHAT** and **HOW** to do the specified things. XAML processor is responsible for the **HOW** part to find out. Fig. 27.1.1 illustrates the XAML side of application.

![](img/3005a4307e6d8f3bb7e76eea28a92357_868_0.png)

- 1. **Step 1:** The XAML file is interpreted by a platform-specific XAML processor.
- 2. **Step 2:** The XAML processor transforms the XAML to internal code that describes the UI element.
- 3. **Step 3:** The internal code and the C# code are linked together through partial classes definitions and then the .NET compiler builds the app.

### 27.1.5 XAML Program Skeleton and Syntax
### Basic
- Every element in a XAML document maps to an instance of a .NET class. The name of the element matches the name of the class exactly. For example, the element `<Button>` instructs WPF to create a Button object.
- As with any XML document, one element can be nested inside another. A button element inside a Grid element means a Grid that contains a button inside. However, Nesting is usually a way to express containment.
- The properties of each class can be set through attributes.

### Programming Example
Create a blank WPF page, Visual Studio adds up few lines of code by default as shown below,

```
    <Window x:Class="TireControl.Window1"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        Title="Window1" Height="300" Width="300">
    <Grid>
    </Grid>
    </Window>
```

- 1. This XAML includes only two elements-the top-level Window element, which represents the entire window, and the Grid, in which all controls will be placed. Although any top-level element can be used, WPF applications rely on just a few, that is,
  **Window Page (which is similar to Window, but used for navigable applications) and**
  **Application (which defines application resources and startup settings)**
- 2. In all XML documents, there can only be one top-level element. In the current example, that means as soon as the Window element is closed with the </Window> tag, the document ends. No more content can follow.

### 27.1.6 XAML Namespaces
It's not enough to supply just the name of any class being used, the XAML parser also needs to know the .Net namespace where this class is located. As in window can exist in several places, it might refer to system.windows.window class or it could refer to a window class in a third party component. To figure out which class is really required, the XAML parser examines the XML namespace that's applied to the element.

Below code lines declare XAML namespace,

```
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
```

**XMLNS** - The xmlns attribute is a specialized attribute in XML that is reserved for declaring namespaces. This snippet of markup declares two namespaces that one can find in every WPF XAML document created,

```
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation" ,
```
