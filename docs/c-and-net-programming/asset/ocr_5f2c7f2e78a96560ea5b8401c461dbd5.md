# 28.3.2 .NET Compact Framework - Application Testing

+   - Visual Studio .NET offers two methods for testing applications that target the .NET Compact Framework namely, through an emulator and on a device. With either the emulator or a device, Visual Studio .NET handles **deploying** both the application and all of the components required by the application, including the .NET Compact Framework and SQL Server CE.
+   - All this is handled when a .NET Compact Framework application is tested from within Visual Studio .NET 2003. A check of the target platform is made to confirm that the .NET Compact Framework is installed. If Visual Studio .NET determines that the .NET Compact Framework is missing, it will automatically copy and install the .NET Compact Framework before attempting to run the application. This installation process will occur the first time a device or the emulator tested and if the device or emulator is hard reset.
+   - A similar process is used if the application uses SQL Server CE. Visual Studio .NET will check the target platform to confirm that the SQL Server CE components are installed. If Visual Studio .NET does not find them, it will automatically copy and install the required SQL Server CE components before running the application.
+   - After it has been determined that all of the components required by the application are present, the application will be copied to the target platform and placed in the specified directory in project configurations and finally application is launched.

# Running a Test

There are several ways to run a test of the application,

+   1. From the Visual Studio .NET toolbar, click the Start button.
+   2. From the Debug menu, select Start or Start without Debugging.
+   3. Press the F5 key (start with debugging) or Ctrl+F5 (start without debugging).
+   4. Testing in the Emulator

+   - Microsoft provides an emulator program that comes with VS.NET to allow developers to emulate Pocket PC 2002 and Windows CE WebPad. The emulator provides an environment within the desktop PC that mimics the functionality and operation of the device platform being targeted with the application. The emulator is useful in situations where the device is not available for testing. It should be noted that **testing in the emulator has its shortcomings**. First problem is that the emulator runs on a desktop PC, which has far more processing resources than the target device. This can give a false sense of how well the application performs.
