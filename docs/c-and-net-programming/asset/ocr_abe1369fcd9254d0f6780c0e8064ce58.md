+   - The runtime initializes ASP.NET with Shadow Copy enabled for the bin directory. The AppDomain will copy any 'dll' file it needs from the bin directory to a temporary location before locking and loading the 'dll' file into memory. Shadow Copy allows developers to overwrite any 'dll' file in the bin directory during an update without taking the web application offline.

# 26.2.5 Obtaining AppDomain Properties in Application

Application domains replace the OS process as the unit of isolation for .NET code. An understanding of application domains provides an idea of the work taking place behind the scenes of an ASP.NET application. Using the CurrentDomain property of the AppDomain class developer can inspect properties about the AppDomain and the code executing in the AppDomain, including the Shadow Copy settings.

# 26.2.6 AppDomain Advantages

+   - A single CLR operating system process can contain multiple application domains. There are advantages to having application domains within a single process.

+   1. It lowers the system cost as many application domains can be contained within a single system process.
+   2. Each application domain can have different security access levels assigned to them, all within a single process.
+   3. Code in one AppDomain cannot directly access code in another AppDomain.
+   4. The application in an AppDomain can be stopped without affecting the state of another AppDomain running in the same process.
+   5. An Exception in one AppDomain will not affect other AppDomains or do not crash the entire process that hosts the AppDomains.

# 26.2.7 AppDomains Tracker for Profiling ASP .NET Applications

+   - The AppDomains tracker can be used to associate instances with the AppDomain they were created in. The AppDomains tracker is particularly useful when profiling ASP.NET applications, or other applications that rely on AppDomains for separation.
