# 11. Invalid catch blocks

+   1. programmer needs to take care while writing multiple catch blocks. A catch block having no parameter (that is Parameterless catch block) and a catch block with an Exception parameter are **not allowed in the same try-catch statements**, because they both do the same thing.
+   
+   2. Parameterless catch block catch{ } or general catch block catch(Exception ex){ } must be the last block. The compiler will **give an error** any other catch blocks after a catch{ } or catch(Exception ex) block.

# Example

```
```csharp
//illustrating Invalid catch blocks… it generates compile time error.

try
{
    //code that may raise an exception
}
catch //parameterless catch block
{
    Console.WriteLine("Exception raised");
}
catch(Exception ex) //catch with Exception class object as parameter.
                    //Cannot have both catch and catch(Exception ex)
{
    Console.WriteLine("Exception raised");
}
```
