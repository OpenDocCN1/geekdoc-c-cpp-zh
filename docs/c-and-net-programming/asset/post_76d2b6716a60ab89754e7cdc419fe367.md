
### 1. Application configuration file

For deploying and installing the application there is no need for any pre-configuration files on the device to be used. The desktop Framework includes a ConfigurationSettings class in the System.Configuration namespace. This class is used to read application settings from an XML file associated with the application and called appname.exe.config. The Compact Framework does not support this class, but developers can write their own using the classes in the System.Xml namespace.

### 2. Method overloads

Overloading a method provides alternative ways to call that method. It also increases the size of the Framework. Because of this, the .NET Compact Framework has cut off the overloads from almost all methods. What this means is two-fold. First, there is a good chance that a particular overloaded method used with a desktop application will not be available when developing .NET Compact Framework-based applications. Second, when the documentation is referred, developers pay close attention to whether or not a method is supported by the .NET Compact Framework.

### 3. Missing controls

A number of .NET Framework controls are not supported in the .NET Compact Framework. The absence of most of these controls is insignificant to mobile developers. Since printing has such a limited role in mobile applications, removing the whole family of print-related controls is not an issue. That takes care of the CrystalReportViewer, PageSetupDialog, PrintDialog, PrintDocument, PrintPreviewControl and PrintPreviewDialog controls. One can replace many of the missing dialogs with own dialogs or by accessing system dialogs directly using the Windows CE API. Third-party controls are already becoming available to fill in for the controls that were left out of the .NET Compact Framework.

### 4. XML functionality

As much as the .NET Compact Framework offers in the way of XML, an equal amount of functionality was removed. The key missing XML-related component is the System.Xml.XPath namespace. The XPath namespace made XML parsing far easier than the methods offered under the .NET Compact Framework. In its absence, one can use a combination of recursive and iterative searches against the Document Object Model (DOM).

The .NET Compact Framework is missing another key XML component, Extensible Stylesheet Language Transformation, or XSLT. With XSLT, one can convert an XML document into different formats. Also, .NET Compact Framework does not currently provide support for developing device-based XML Web services.

### 5. Database support

The Compact Framework omits the System.Data.OleDb namespace and so does not support the ability to make calls directly to a database using the OleDb .NET Data Provider. However, the remote data access (RDA) features of SQL Server CE do support pulling data down from a SQL Server that can act as a repository for data from other data sources. The .NET Compact Framework offers a robust set of data-related tools. Local database support is provided for SQL Server CE. On the server side, the .NET Compact Framework provides support for SQL Server. It should be noted that there is a third party who provides a .NET Compact Framework component for working with Pocket Access databases.

### 6. Binary serialization

Due to size and performance considerations both the BinaryFormatter and SoapFormatter classes have been omitted from the .NET Compact Framework.

### 7. Access to the Windows registry

The .NET Framework has the Microsoft.Win32.Registry namespace, which makes it easy to work with the Windows registry from an application. Obviously, this namespace was not included in the .NET Compact Framework, because it relates to Win32, not Windows CE. Windows CE registry can be accessed by invoking the relevant Windows APIs.

### 8. Leveraging COM components and interoperability

Incorporating COM objects into a .NET Compact Framework-based application is a two-step process. First step is, to write an unmanaged code - that is to say eMbedded Visual C++ - DLL wrapper that exposes the COM object. Depending upon the complexity of the COM object, this may be anything from simple to extremely complicated. Second step, by using PInvoke access the DLL wrapper. Currently, big development community has already begun work on accessing the more commonly used COM components that is really helpful all the developers working in this area.

### 9. Security

The .NET Compact Framework does not provide secure access to unmanaged code. Any application can call any system or non-system API. There is currently no role-based security with the .NET Compact Framework. The principal object has no understanding of known identity or known role.

### 10. XML web services and System.Web namespace

The most notable exclusion from the .NET Compact Framework XML Web service capabilities is the ability to use cookies. Cookies are widely used to maintain state on the server between calls from a client. While the use of cookies in Web services is not as prevalent as their use on Web sites, they are still in use. The .NET Compact Framework offers limited cryptographic abilities with respect to Web services. There is no support for the System.Web namespace.

### 11. Printing

The .NET Compact Framework provides no support for printing. There is no easy way to interact with either network printers or external printers via IR. The workaround for accessing network printers is to build a server-based application, which accepts and prints jobs submitted by any mobile application. One can send output through the IR port directly to IR-enabled printers. The System.Net.IrDA namespace can be used to access the IR port of the device.

### 12. GDI+

Windows CE does not natively support GDI+, so GDI+ related functionality was removed from .NET Compact Framework.

### 13. Remote programming

The first release of the .NET Compact Framework does not support remote programming.

## 28.1.7 Windows Compact Edition - Project Types

- As shown in Fig. 28.1.3, four project types target the Windows CE platform. These are Windows Application, Class Library, Console Application and Empty Project.

![](img/3005a4307e6d8f3bb7e76eea28a92357_892_0.png)

Fig. 28.1.3 Windows CE project types

- **1. Windows application** - A Windows Forms-based project including Windows CE .NET-specific controls. This is the most commonly used template because it generates Windows-based applications.
- **2. Class library** - Class libraries allow to package related components in a single file. They can be used to develop other applications or as a base for inheritance for other components. This project type is best suited for creating modules of code that will be reused with multiple applications.
- **3. Console application** - Used to create executables that will run within the console window. Best used for background and maintenance applications, which may or may not require user interaction. Unlike the Pocket PC, Windows CE natively supports console applications.
- **4. Empty project** - Defines a project with no predefined components, allowing to custom-build everything from the ground up.

## 28.1.9 .NET Compact Framework - Supported Languages

- The .NET Compact Framework supports two development languages, C# .NET and Visual Basic .NET. While previous versions of Windows CE development tools favored C-based languages - namely eMbedded Visual C++ - with the .NET Compact Framework it makes little difference which of the languages to choose, because both are equally powerful and functional.
- As a late addition to the Visual Studio .NET development environment, J# is not supported by the .NET Compact Framework.
- Developer should also be aware that there is another language limitation under the .NET Compact Framework that does not exist under the .NET Framework. Under the .NET Framework mixed-language components can be used within a single project. In comparison, .NET Compact Framework projects are restricted to a single language, either C# .NET or Visual Basic .NET. The workaround to this single-language project limitation imposed by .NET Compact Framework is to create additional projects using the Class template. Alternate language code needs to be added to the template, and then simply add references to these classes in the application project.

## 28.1.10 .NET Compact Framework - Online Documentation

The documentation included with Visual Studio .NET provides information relating to the .NET Compact Framework. There are both .NET Compact Framework-specific topics, such as "Creating Custom Controls with the .NET Compact Framework", and line item identification of features supported under the .NET Compact Framework.

## 28.1.11 .NET Compact Framework IDE - Additional Features

In addition to all of the features found natively in Visual Studio .NET, there are the following device-specific features supported in .NET compact framework,

- **1. Templates** - Predefined configurations for common project types. Templates are provided for both Pocket PC and Windows CE devices.
- **2. Device-specific controls** - Controls specifically designed for use with the Pocket PC and Windows CE. The interface, resource consumption and functionality have been tailored for these environments.
- **3. Device emulators** - Testing environments that simulate specific devices. Emulators run on the developer's PC, allowing for testing without the presence of a device.
- **4. Automatic deployment of applications** - Allows easy testing for either an emulator or a device, providing developers with a seamless testing environment.
