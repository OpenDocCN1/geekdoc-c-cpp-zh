# 5. Database support :

The Compact Framework omits the System.Data.OleDb namespace and so does not support the ability to make calls directly to a database using the OleDb .NET Data Provider. However, the remote data access (RDA) features of SQL Server CE do support pulling data down from a SQL Server that can act as a repository for data from other data sources. The .NET Compact Framework offers a robust set of data-related tools. Local database support is provided for SQL Server CE. On the server side, the .NET Compact Framework provides support for SQL Server. It should be noted that there is a third party who provides a .NET Compact Framework component for working with Pocket Access databases.

# 6. Binary serialization :

Due to size and performance considerations both the BinaryFormatter and SoapFormatter classes have been omitted from the .NET Compact Framework.

# 7. Access to the windows registry :

The .NET Framework has the Microsoft.Win32.Registry namespace, which makes it easy to work with the Windows registry from an application. Obviously, this namespace was not included in the .NET Compact Framework, because it relates to Win32, not Windows CE. Windows CE registry can be accessed by invoking the relevant Windows APIs.

# 8. Leveraging COM components and interoperability :

Incorporating COM objects into a .NET Compact Framework-based application is a two-step process. First step is, to write an unmanaged code - that is to say eMbedded Visual C++ - DLL wrapper that exposes the COM object. Depending upon the complexity of the COM object, this may be anything from simple to extremely complicated. Second step, by using PInvoke access the DLL wrapper. Currently, big development community has already begun work on accessing the more commonly used COM components that is really helpful all the developers working in this area.

# 9. Security :

The .NET Compact Framework does not provide secure access to unmanaged code. Any application can call any system or non-system API. There is currently no role-based security with the .NET Compact Framework. The principal object has no understanding of known identity or known role.
