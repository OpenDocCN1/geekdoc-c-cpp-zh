+   - While XAML compiles in visual studio, all XAML is converted into BAML and that BAML is then embedded as resource inside the final DLL or EXE assembly. BAML is tokenized, which means lengthier bits of XAML are replaced with shorter tokens. Not only is BAML significantly smaller, it's also optimized in a way that makes it faster to parse at runtime.

# Working of XAML

XAML is a **declarative language** in the sense it defines the **WHAT** and **HOW** to do the specified things. XAML processor is responsible for the **HOW** part to find out. Fig. 27.1.1 illustrates the XAML side of application.

![](bbox=[0.09, 0.316, 0.914, 0.479])

+   1. **Step 1:** The XAML file is interpreted by a platform-specific XAML processor.
+   2. **Step 2:** The XAML processor transforms the XAML to internal code that describes the UI element.
+   3. **Step 3:** The internal code and the C# code are linked together through partial classes definitions and then the .NET compiler builds the app.
