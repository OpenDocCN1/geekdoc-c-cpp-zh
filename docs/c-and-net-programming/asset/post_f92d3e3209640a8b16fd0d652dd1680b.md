## 13.2 Errors and Exceptions

### 13.2.1 Errors and their Classification

**Concept**

- Computer programs have to deal with errors and so does the programmer. Errors are unexpected conditions that are not part of the normal operation of a program, say for example running out of memory.

**Explanation**

- Errors can be classified based on their time of occurrence or based on the damage they could make to the running process or the way they should be tackled.
- There are several kinds of errors.
  - 1. Based on damage they cause — fatal errors, non-fatal errors.
  - 2. Based on where the damage is caused — system errors, application errors.
  - 3. Based on what made them to occur — arithmetic errors, IO errors, logical errors, hardware errors.

- **Techniques for detecting errors (debugging)**：If the testing phase signals the presence of logical errors or if one cannot detect the cause for a runtime error, it is necessary to debug the program.

  - 1. by inserting output statements in the code;
  - 2. by executing the program by means of a **debugger**.

### 13.2.2 Exceptions

**Concept**

- 1. When a programmer anticipates situations but does not deal with them “in normal ways”, then it leads to an exception. The situation could be recoverable through an exception handling mechanism or else can be left unhandled, leading to program crash. Exception handling makes an application robust, that is, tough against all types of unexpected situations.

**Explanation**

- 2. An exception is a problem that arises during the execution of a program. A C# exception is a response to an exceptional circumstance that arises while a program is running, such as an attempt to divide by zero.
- 3. C# provides a structured solution to the exception handling in the form of try and catch blocks. Using these blocks, the core program statements are separated from the exception-prone and exception-handling statements.

**These error handling blocks are implemented using the try, catch, and finally keywords.**

- 4. **Exception handling**
  - 1. Exceptions provide a way to transfer control from one part of a program to another. C# exception handling is built upon four keywords: **try**, **catch**, **finally**, and **throw**.

**Syntax**

```csharp
try
{
    // code that may raise exceptions
}
catch (Exception ex)
{
    // handle exception
}
finally
{
    // final cleanup code
}
```

- 2. The program code is put in the try block that may raise an exception, followed by a catch and/or finally block. A try-catch block is placed around the code that might generate an exception. Code within a try-catch block is referred to as protected code.
- 3. Variable declarations are generally kept out of the try block so that they can be accessed in the catch and finally blocks.
- 4. The try block must be followed by catch or finally or both blocks. The try block without a catch or finally block will result in a compile-time error.
- 5. Multiple catch blocks can also be specified with different exception types; this is called exception filters. Multiple catch blocks are useful when one wants to handle different exceptions in different ways.
- **6. 'try' is a block of code**：A try block identifies a block of code for which a particular exception is activated or wherein the exception is anticipated. In the nomenclature of exception handling, an exception is said to be “raised by” the code. The try block is followed by one or more catch blocks.
- **7. 'catch' is a block of code**：The catch block contains the code for handling the exception. That is, it is an exception handling routine which would be invoked only when the exception is raised. In the nomenclature of exception handling, the catch block is said to be “catching the exception” and then it runs its own code.
- **8. 'Finally' is a block of code**：
  - The finally block is used to execute a given set of statements, in either of the circumstances, whether an exception is raised or not raised.
  - The finally block is generally used for cleaning-up code, e.g., for disposing of unmanaged objects, etc.
  - The finally block must come after a try or catch block.
  - Finally block is optional.
  - Multiple finally blocks are not allowed.
  - The finally block cannot have the return, continue, or break keywords. It doesn't allow control to leave the finally block.
- **9. 'Throw' is a statement**：Throw is a programming statement used for throwing the exception when the exceptional situation occurs in the program. A program is said to be “throwing an exception” when a problematic case occurs in the try block, upon which the catch block catches it and executes its own code. 'throw' is the keyword used for throwing the exception.

**Example**

```csharp
//illustration of exception handling using try catch
using System;
namespace Exceptionhandling
{
    class ArrayOps
    {
        int[] nums = new int[3];
        public void Show()
        {
            try
            {
                nums[0] = 128;
                nums[1] = 64;
                nums[2] = 16;
                nums[3] = 2;

                foreach(int cnt in nums)
                    Console.WriteLine(nums[cnt]);
            }
            catch
            {
                Console.WriteLine("Exceptional situation occurred. Stopping Application.");
            }
        }
        static void Main(string[] args)
        {
            ArrayOps ops = new ArrayOps();
            ops.Show();
        }
    }
}
```

Input: Nil

**Output**

Exceptional situation occurred. Stopping Application.

- **10. Multiple catch blocks**
  - It is quite possible that a block of code raises multiple exceptions and hence there is a need for multiple catch blocks.
  - Multiple catch blocks would help to segregate the exceptions and handle them in different ways individually.
  - Multiple catch blocks with different exception types would help to display the appropriate message to the user, depending upon the error, so that the user does not repeat the same mistake again.
  - Multiple catch blocks with the same exception type are not allowed. It generates a compile-time error.
  - **A strong suggestion**: Place more specific catch statements first and move down with more generalized exceptions.

**Syntax**

```csharp
try
{
    // statements causing exception, that may raise multiple exceptions.
}
catch (ExceptionName e1)
{
    // Exception handling code
}
catch (ExceptionName e2)
{
    // Exception handling code
}
catch (ExceptionName eN)
```

**Output**

Not a valid number

- **11. Invalid catch blocks**
  - 1. Programmer needs to take care while writing multiple catch blocks. A catch block having no parameter (that is, a parameterless catch block) and a catch block with an Exception parameter are **not allowed in the same try-catch statements**, because they both do the same thing.
  - 2. Parameterless catch block `catch { }` or general catch block `catch (Exception ex) { }` must be the last block. The compiler will **give an error** for any other catch blocks after a `catch { }` or `catch (Exception ex)` block.

**Example**

```csharp
//illustrating Invalid catch blocks… it generates compile-time error.

try
{
    //code that may raise an exception
}
catch //parameterless catch block
{
    Console.WriteLine("Exception raised");
}
catch(Exception ex) //catch with Exception class object as parameter.
                    //Cannot have both catch and catch(Exception ex)
{
    Console.WriteLine("Exception raised");
}
```

**Example**

```csharp
//illustrating Invalid catch blocks… it generates compile-time error.

try
{
    //code that may raise an exception
}
catch
{
    // this parameterless catch block must be last catch block
}
catch (NullReferenceException nullEx)
{
    Console.WriteLine(nullEx.Message);
}
```
