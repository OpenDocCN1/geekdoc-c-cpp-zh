## 26.1 Assemblies and Shared Assemblies

### 26.1.1 .NET Assembly

**Concept**

- 1. Assembly is a **logical collection of smallest unit in .NET Framework.** Example: .DLL File contains the application code, the .aspx file, .ascx user controls, resource files like .gif, .bmp, .ico file etc. Assemblies are basic fundamental unit of application development and deployment in the .NET Framework.

**Explanation**

- 2. The .NET assembly is the standard for components developed with the Microsoft.NET. Dot NET assemblies may or may not be executable, i.e., they might exist as the executable (.exe) file or dynamic link library (DLL) file. All the .NET assemblies contain the definition of types, versioning information for the type, meta-data, and manifest. The designers of .NET have worked a lot on the component (assembly) resolution.
- 3. An assembly contains the **MSIL code**, which the common language runtime executes, and the type metadata.
- 4. An assembly also contains an assembly manifest that contains the assembly metadata. This metadata contains information about the assembly version, its security identity, the resources required by the assembly, and the scope of the assembly.
- 5. Assemblies are the smallest units to which the .NET Framework grants permissions. They provide security boundaries within the .NET Framework. One can specify the permission required by application while building assemblies. When the assembly is loaded into the runtime, the assembly sends a request to the runtime to grant the permission.

### 26.1.2 Types of Assemblies

### 26.1.2.1 Static and Dynamic Assemblies

- 1. **Static Assemblies**
  - A static assembly is generated when program is compiled using any of the .NET language compilers.
  - A static assembly contains the types, interfaces, and various resources required by the assembly.
  - A static assembly is stored on the hard disk in the form of a portable executable that is **PE (.exe or .dll) file.**
- 2. **Dynamic Assemblies**
  - Dynamic assemblies are generated and executed on the fly.
  - Dynamic assemblies are created through **System.Reflection.Emit** namespace.

### 26.1.2.2 Single-File and MultiFile Assemblies

- 1. **Single-File Assemblies**
  - A single-file assembly consists of a **single .exe or .dll** file.
- 2. **Multifile Assemblies**
  - A multifile assembly is an assembly that can include multiple file, but it should contain at least one **.dll or .exe** file.
  - Assembly manifest in multifile assembly can be attached to any assembly file or can be created separately as just the manifest.

### 26.1.2.3 Private and Shared Assemblies and GAC

- 1. **Private assemblies**
  - **Private assemblies** are simple and copied with each calling assemblies in the calling assemblies folder.
  - When an assembly deployed which can be use by single application, such assembly is called a private assembly.
  - Private assemblies can be used by only one application they are deployed with.
  - Private assemblies are deployed in the directory where the main application is installed.
- 2. **Shared assemblies (Strong Assemblies)**
  - When deployed assembly can be used by several applications, then this assembly is called shared assembly.
  - **Shared assemblies** are copied and stored in a single location, a special folder called **Global Assembly Cache (GAC)**, which can be accessed by all applications. For all calling assemblies within the same application, the same copy of the shared assembly is used from its original location. Hence, shared assemblies are not copied in the private folders of each calling assembly.
  - **Strong names for strong security**
    - 1. **Shared assemblies** must have a **strong name**. A strong name is a .NET assembly name combined with its version number and other information to uniquely identify the assembly. This allows multiple versions of the same assembly to peacefully co-exist in the global assembly cache, where shared assemblies are typically stored.
    - A strong name consists five parts namely, assembly name, a version number, a culture, a public key (RSA cryptographic public key that helps verify the assembly's authenticity) and an optional digital signature. Each shared assembly has a four part name including its file name, version, public key token and culture information. The

public key token and version information makes it almost impossible for two different assemblies with the same name or for two similar assemblies with different version to mix with each other.

- 2. Strong names are highly useful in Versioning and Authentication process. Signed assemblies are unique and strong name solves problem with namespace collisions (developers can distribute their assemblies even with the same file names). Assemblies signed with strong names are uniquely identified and are protected and stored in different spaces.

### 3. GAC

- 1. GAC is capable of maintaining multiple copies of an assembly with the same name but different versions.
- 2. Each computer on which the Common Language Runtime is installed has a machine-wide code cache called the 'Global Assembly Cache'. The Global Assembly Cache (GAC) enables to share assemblies across numerous applications.
- 3. The GAC is automatically installed with the .NET runtime. The global assembly cache is located in 'Windows/WinNT' directory and inherits the directory's access control list that administrators have used to protect the folder.

- 4. The approach of having a specially controlled central repository addresses the shared library concept and helps to avoid pitfalls of other solutions that lead to drawbacks like DLL hell.

- 5. The Global Assembly Cache Tool (Gacutil.exe), allows to view and manipulate the contents of the Global Assembly Cache.

- 6. To view content of GAC one can open explorer and follow path c:\Windows\assembly.

### 26.1.2.4 Resource-only and Satellite Assemblies

- 1. Resource-only assemblies
  - These are assemblies that store only resource and no code. For example, Image, audio.
- 2. Satellite assemblies
  - Resource-only assemblies that store the culture-specific information are known as satellite assemblies.

### 26.1.3 Benefits of Assemblies

- 1. It is used in Versioning.
- 2. Assemblies are useful for Type Identification
- 3. Assemblies provide Security for applications.
- 4. Application deployment becomes easy because of assemblies.
- 5. Assemblies are used for Referencing.
- 6. Assemblies improve the application performance.
  - CLR compiles .NET Application codes.
  - Whenever a request is made to ASP.NET page, the page gets compiled first and then is transferred to the user. The compilation process is also completed in two steps.
    1. An IL (Intermediate Language) is generated and then this is handed over for JIT
    2. JIT (Just In Time) compilation which produces the machine code and the pages get displayed with their dynamic content.

The performance of web application can be improved by creating pre-compiled libraries of IL which are further handed over to JIT directly without having the inclusion of an extra process to make the conversion. This method is called componentization. Components are pre-compiled set of classes that have been developed in the form of DLL files and can then be included within the projects. This is also known as an assembly.
