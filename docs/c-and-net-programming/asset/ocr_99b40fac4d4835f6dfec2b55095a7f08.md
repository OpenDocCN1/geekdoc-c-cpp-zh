+   - Dynamic assemblies are created through **System.Reflection.Emit** namespace.

# **26.1.2.2 Single-File and MultiFile Assemblies**

+   1. **Single-File Assemblies**
+      - A single-file assembly consists of a **single .exe or .dll** file.
+   2. **Multifile Assemblies**
+      - A multifile assembly is an assembly that can include multiple file, but it should contain atleast one **.dll or .exe** file.
+      - Assembly manifest in multifile assembly can be attached to any assembly file or can be created seperately as just the manifest.

# **26.1.2.3 Private and Shared Assemblies and GAC**

+   1. **Private assemblies**
+      - **Private assemblies** are simple and copied with each calling assemblies in the calling assemblies folder.
+      - When an assembly deployed which can be use by single application, such assembly is called a private assembly.
+      - Private assemblies can be used by only one application they are deployed with.
+      - Private assemblies are deployed in the directory where the main application is installed.
+   2. **Shared assemblies (Strong Assemblies)**
+      - When deployed assembly can be used by several applications, then this assembly is called shared assembly.
+      - **Shared assemblies** are copied and stored in a single location, a special folder called **Global Assembly Cache (GAC)**, which can be accessed by all applications. For all calling assemblies within the same application, the same copy of the shared assembly is used from its original location. Hence, shared assemblies are not copied in the private folders of each calling assembly.
+      - **Strong names for strong security**
+        1. **Shared assemblies** must have a **strong name**. A strong name is a .NET assembly name combined with its version number and other information to uniquely identify the assembly. This allows multiple versions of the same assembly to peacefully co-exist in the global assembly cache, where shared assemblies are typically stored.
+   
+           **A strong name consists five parts namely, assembly name, a version number, a culture, a public key (RSA cryptographic public key that helps verify the assembly's authenticity) and an optional digital signature.** Each shared assembly has a four part name including its face name, version, public key token and culture information.
