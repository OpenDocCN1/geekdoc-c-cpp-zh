
## 28.3.2 .NET Compact Framework - Application Testing

- Visual Studio .NET offers two methods for testing applications that target the .NET Compact Framework namely, through an emulator and on a device. With either the emulator or a device, Visual Studio .NET handles deploying both the application and all of the components required by the application, including the .NET Compact Framework and SQL Server CE.
- All this is handled when a .NET Compact Framework application is tested from within Visual Studio .NET 2003. A check of the target platform is made to confirm that the .NET Compact Framework is installed. If Visual Studio .NET determines that the .NET Compact Framework is missing, it will automatically copy and install the .NET Compact Framework before attempting to run the application. This installation process will occur the first time a device or the emulator is tested and if the device or emulator is hard reset.
- A similar process is used if the application uses SQL Server CE. Visual Studio .NET will check the target platform to confirm that the SQL Server CE components are installed. If Visual Studio .NET does not find them, it will automatically copy and install the required SQL Server CE components before running the application.
- After it has been determined that all of the components required by the application are present, the application will be copied to the target platform and placed in the specified directory in project configurations and finally the application is launched.

### Running a Test

There are several ways to run a test of the application,

- 1. From the Visual Studio .NET toolbar, click the Start button.
- 2. From the Debug menu, select Start or Start without Debugging.
- 3. Press the F5 key (start with debugging) or Ctrl+F5 (start without debugging).
- 4. Testing in the Emulator

- Microsoft provides an emulator program that comes with VS.NET to allow developers to emulate Pocket PC 2002 and Windows CE WebPad. The emulator provides an environment within the desktop PC that mimics the functionality and operation of the device platform being targeted with the application. The emulator is useful in situations where the device is not available for testing. It should be noted that testing in the emulator has its shortcomings. First problem is that the emulator runs on a desktop PC, which has far more processing resources than the target device. This can give a false sense of how well the application performs. In addition, input for the emulator is provided through a keyboard and a mouse rather than the stylus the end user will use. If the developer is not consciously aware of this difference, the developer can create an application that is easy to use in the emulator and painful to use on the device. Finally, the emulator offers a close representation of a device, not an exact match. There are subtle differences in all emulators.

### Emulator Requirements

- The emulators provided with Visual Studio .NET will not operate unless the development PC on which it is running has a network connection. If the PC does not have a network connection, the emulator can still be used by installing the Microsoft Loopback Network Adapter. This adapter simulates a network connection and effectively fools the emulator into running.

### Testing on a Device

- Testing on a device allows the developer to get a first-hand experience with how applications perform. With Visual Studio .NET the developer can test on devices connected to development PC via USB, serial or Ethernet. It should be noted that Ethernet can be used to connect the device to the development PC. This is by far the quickest and easiest method for testing and debugging.

## 28.3.3 .NET Compact Framework - Application Debugging

- The debugging environment provided through the Visual Studio .NET IDE is robust. Debugging environment allows to pause the application, see its inner workings, modify code, examine the values and step through the application in a systematic manner.
- The core of the debugging functionality can be found on the Debug menu in the Visual Studio .NET IDE. From this menu, a debugging session can be started or stopped, breakpoints can be set, and the application can be navigated while in a debug mode. It should be noted that breakpoints identify a line of code within the application where one wants to pause or interrupt the execution of the application when breakpoint is encountered.
- Visual Studio .NET enables developer to remotely debug applications that are running on a device or in an emulator from the comfort of the development PC. The Command window can be used to enter statements, query and set variables, execute lines of code and other similar tasks. For the optimal debugging environment, Ethernet should be used to connect to the device and PC.

## 28.4 .NET Compact Framework - Optimizing Application Performance

In web-based server applications, performance optimization is considered a very necessary part of the software development lifecycle - after all, the code is written to service hundreds of users at the same time. However, in a single user environment, such as the mobile device, one might wonder if this is necessary. The truth is, sometimes mobile users may not need applications that run faster, but applications that respond faster. A mobile device has hardware limitations that will always place it behind the PC in terms of power and speed, so it will never be expected to number crunch or load data as fast as the PC can. By designing mobile application such a way that it will be constantly and highly responsive to user input, it can make up for its limitations by providing a more fluent user experience.

### 28.4.1 Best Practices for Better Performance

While developing application usability of the application is important to consider. Size of device being a key constraint, usability becomes a key factor to be considered while developing applications for smart devices. Below are other practices one should follow while developing application,

- Keep the UI simple and easy to work with.
- Avoid multiple data entries.
- Avoid new forms, try using tab controls.
- Use hardware functions.
- Keep the functionality simple, avoid complexities.
- Use disconnected datasets.
- Reduce data joins.
- Use multithreading.
- Create threads for long jobs.
- Use asynchronous calls.
- Mostly, making a call to unmanaged code will be costly from a performance point of view.

### Optimizing database performance

There are a few things that can be done to optimize database performance as listed below,

- Data caching should be used to cache frequently used data lists.
- Database indexes should be used to boost search performance.
- GZIP compression can be used to compress textual data.
- Faster code should be developed to manipulate strings, WinForms, XML, and files in the .NET Compact Framework
- Below are two widely used approaches for enhancing database performance,
- Caching data lists to improve loading performance.
- Using database indexes to improve search performance.

### Data caching

- When the data is cached in memory, there is no need to retrieve the same data from the database each time it is used. This can lead to considerably better performance as it cuts down the database round trip required to retrieve that data. Also, it is not necessary to cache everything being accessed. The following are general guidelines to follow in selecting suitable candidates for data caching,
  - Short lists of data (< 100 records)
  - Data that is not expected to change frequently
  - Data that is used repeatedly throughout the application (for example, data in drop-down list).

### Optimizing data transfer performance

- Microsoft offers data compression functionality via the System.IO.Compression namespace. The GZipStream class allows to compress a byte array based on the GZIP standard. After compressing data, the GZipStream class does not store the original size of the uncompressed data. Therefore, developer should implement own method to "remember" and store this original size somewhere so that it can be used later during decompression. A common approach is to store this size as the first four bytes of the compressed stream.
