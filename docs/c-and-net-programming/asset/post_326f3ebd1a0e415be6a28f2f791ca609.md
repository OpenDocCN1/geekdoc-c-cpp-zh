
## 28.4.3 Managing Better Strings

String manipulation is a common operation in any application. The String class is immutable. This means that each time one concatenates strings in the preceding fashion it creates a new string object. This can lead to inefficient memory utilization (and more work for the garbage collector). Memory utilization of strings can be improved in the application using the StringBuilder class.

## 28.4.5 .NET Compact Framework - Code Optimization and Measuring Code Performance

- Before the code is optimized for performance, it is necessary to know if it is really underperforming. The performance can be measured at two basic levels - at the code level and at the application level.
- At the code level, developers can typically use timers in order to time sections of code and to then display the time taken for the piece of code to execute. At the application level, the developer might need to know, for instance, how much memory an application has been consuming or how many times garbage was collected during its lifetime.

### Measuring .NET compact framework code performance

The most basic way to measure the performance of a piece of code is to:

- 1. Capture the start time.
- 2. Perform the action.
- 3. Capture the end time.
- 4. Calculate the difference (delta).

There are various techniques used to capture time, like the Environment.TickCount.

## 28.5 .NET Compact Framework - Application Packaging and Deployment

### 28.5.1 .NET Compact Environment - Packaging

- Before an application can be deployed to a device or set of devices, it must be packaged.
- Much of the work involved with packaging an application is taken care of by the functionality in Visual Studio. Once packaged, the application and the Compact Framework itself can be deployed in a variety of ways, some of which may require custom code development, depending on the location and connectivity of the device.

#### 28.5.1.1 Packaging Step 1 - Setting Application Properties

- **Perhaps the most fundamental aspect of deployment that developers should know before packaging the application is setting the project and file properties in VS .NET.**
- **The first property**, at the project level, that VS .NET supports is the **Output File Folder property** in the Properties window. This property specifies the deployment directory on the device that the project will be installed in. This property is consulted by the Deploy menu options in VS .NET, as well as the CAB file creation. It defaults to the \\Program Files\\projectname folder, but this setting can be changed easily.
- **The second property** is the Build Action property shown in the Properties window for each file included in the project. This option can be set to one of four values shown in the table below.

| Build action | Purpose |
|---|---|
| None | Performs no action for the specified file. This can be used when the file is to be included in the project but not compiled or deployed to the device. This is useful for documentation, such as Visio diagrams. |
| Compile | Compiles the file into the project. This is the setting used for all code files and forms. |
| Content | Deploys the file along with the project. This is useful for deploying SQLCE databases, XML files, and other supplementary files that the application may use. |
| Embedded resource | Includes the file in the assembly as a resource. This is useful for adding images and text files to the assembly and later retrieving them. |

- Additionally, an icon can be associated with the application in the Project Properties dialog box accessed by right-clicking on the project name in VS .NET and selecting properties.
- Finally, the build configuration can be set from within VS .NET by selecting the Build/Configuration. It is important to remember to change the solution or project configuration from Debug to Release before deploying the application because the Debug build slows performance and creates larger assemblies. The build mode for the current project can also be changed via the Solution Configuration option in the toolbar in VS .NET.

#### 28.5.1.2 Packaging Step 2 - Creating Cabinet Files (CAB Files)

- Creating setups for a .NET Compact Framework application is similar to the approach used for other Windows applications. Application setups are delivered using cabinet files, more commonly referred to as "CAB" files, after their .cab file extension. CAB files serve two purposes namely,
  - 1) They compress and store files so that they may be easily distributed;
  - 2) They make sure that all of the files and settings required by an application are correctly handled.
- Once the project options are set, a CAB file can be created to deploy the application. VS .NET makes this easy by including a Build Cab File menu, accessible by right-clicking the project. Note that this process is different from that in the desktop Framework, where a deployment project that uses the Windows Installer can be added to the solution to package the application.
- When this option is invoked, VS .NET silently creates a .cab directory under the project directory on the developer's workstation. In this directory, and within a directory identifying the build mode (Debug or Release), are placed a series of .cab files, each targeting a specific processor type, including ARM, ARM4, MIPS, SH3, and X86, and named accordingly, such as MyApplication_PPC_ARM.cab. To install the application on a device, the .cab file simply needs to be copied to the device and executed.

##### Steps to create CAB file

The easiest way to create a CAB file for the application is to let Visual Studio .NET do all of the work. One of the features offered through Visual Studio .NET is a menu item within the IDE for generating CAB files.

##### To build a CAB file for an application

- 1. Open the project of the application within Visual Studio .NET.
- 2. Select Release from the Solution Configuration dropdown combo box.
- 3. On the Build menu, click Build CAB File.

Several command windows will be displayed briefly as the application is being built. When these windows are cleared, then the CAB file is complete. It should be noted that there is no message or acknowledgement that is displayed to inform that the CAB file has been generated. After the last of the command windows is closed down, the user is taken back to the Visual Studio .NET interface indicating that CAB file work is done.

##### CAB File Output

Output from this CAB-building process is stored in a directory located under the application's directory. The individual CAB file can be found under the subdirectory \bin\release. At this point, the appropriate CAB file can be copied to the target device, open up File Explorer on the device, tap on the CAB file and the application would be installed. It should be noted that, for the application to be able to run, the .NET Compact Framework and, if required, SQL Server CE have to be installed on the device.

### 28.5.2 .NET Compact Environment - Application Deployment

After a Compact Framework application has been packaged into a .cab file, it must be deployed and installed on the device.

#### 28.5.2.1 Techniques for Deploying Application

There are several techniques for deploying an application, including using ActiveSync, a Web site, a storage card, a file share, and even creating an auto-updating application.

- 1. Using ActiveSync: The most obvious option for deploying a Compact Framework application is to allow the application to be installed when the device is cradled using the ActiveSync software typically used to synchronize files and e-mail. To do so, the application must be registered with the ActiveSync Application Manager installed on the desktop machine. This process is relatively simple; it requires creating a custom setup executable that invokes the Application Manager on the workstation with ActiveSync installed and passing it an .ini file that contains information about the application to install.
- 2. Using a Web Site: The second option for deploying and installing a Compact Framework application is to use a Web site. Using this option, an organization could create an Internet or intranet site that contains links to the various .cab files created for the application. This option has the benefit of not requiring the device to be cradled in order to install software. When a user navigates to the Web page using Pocket Internet Explorer, the user can tap on the required .cab file. The resulting dialog allows the file to be downloaded and opened. Opening the file after download is equivalent to executing the .cab file on the device and will cause the application to be installed. It should be noted that, regardless of how the .cab file reaches the device, the installation software on the device automatically deletes the .cab file once the installation is complete. To prevent this from happening, the .cab file can be marked as read-only.
