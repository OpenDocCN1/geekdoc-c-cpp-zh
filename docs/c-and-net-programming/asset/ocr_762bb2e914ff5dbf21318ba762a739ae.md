# Emulator Requirements

+   - The emulators provided with Visual Studio .NET will not operate **unless the development PC on which it is running has a network connection**. If the PC does not have a network connection, the emulator can be still used by installing the Microsoft Loopback Network Adapter. This adapter simulates a network connection and effectively fools the emulator into running.

# Testing on a Device

+   - Testing on a device allows the developer to get a first-hand experience with how applications perform. With Visual Studio .NET developer can test on devices connected to development PC via USB, serial or Ethernet. **It should be noted that Ethernet can be used** to connect the device to the development PC. This is by far the quickest and easiest method for testing and debugging.

# 28.3.3 .NET Compact Framework - Application Debugging

+   - The debugging environment provided through the Visual Studio .NET IDE is robust. Debugging environment allows to pause the application, see its inner workings, modify code, examine the values and step through the application in a systematic manner.

+   - The core of the debugging functionality can be found on the **Debug** menu in the Visual Studio .NET IDE. From this menu, a debugging session can be started or stopped, breakpoints can be set, and application can be navigated while in a debug mode. **It should be noted that breakpoints identify a line of code** within the application where one wants to pause or interrupt the execution of the application when breakpoint is encountered.

+   - Visual Studio .NET enables developer to remotely debug applications that are running on a device or in an emulator from the comfort of the development PC. The Command window can be used to enter statements, query and set variables, execute lines of code and other similar tasks. For the optimal debugging environment, Ethernet should be used to connect to the device and PC.
