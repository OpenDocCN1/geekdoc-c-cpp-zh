+   1. **Application configuration file :**
+   
+       For deploying and installing the application there is no need for any pre-configuration files on the device to be used. The desktop Framework includes a ConfigurationSettings class in the System.Configuration namespace. This class is used to read application settings from an XML file associated with the application and called appname.exe.config. The Compact Framework does not support this class, but developers can write their own using the classes in the System.Xml namespace.

+   2. **Method overloads :**
+   
+       Overloading a method provides alternative ways to call that method. It also increases the size of the Framework. Because of this, the .NET Compact Framework has cut off the overloads from almost all methods. What this means is two-fold. First, there is a good chance that a particular overloaded method used with a desktop application will not be available when developing .NET Compact Framework-based applications. Second, when the documentation is referred, developers pay close attention to whether or not a method is supported by the .NET Compact Framework.

+   3. **Missing controls :**
+   
+       A number of .NET Framework controls are not been supported into the .NET Compact Framework. The absence of most of these controls is insignificant to mobile developers. Since printing has such a limited role in mobile applications, removing the whole family of print-related controls is not an issue. That takes care of the CrystalReportViewer, PageSetupDialog, PrintDialog, PrintDocument, PrintPreviewControl and PrintPreviewDialog controls. One can replace many of the missing dialogs with own dialogs or by accessing system dialogs directly using the Windows CE API. Third-party controls are already becoming available to fill in for the controls that were left out of the .NET Compact Framework.

+   4. **XML functionality :**
+   
+       As much as the .NET Compact Framework offers in the way of XML, an equal amount of functionality was removed. The key missing XML-related component is the System.Xml.XPath namespace. The XPath namespace made XML parsing far easier than the methods offered under the .NET Compact Framework. In its absence, one can use a combination of recursive and iterative searches against the Document Object Model (DOM).
