# Chapter 8 ■ Hash Tables 173

Another strategy to implement hash tables is open addressing. In open addressing values are stored in an array, and some sort of calculation serves as the hashing function, mapping values into positions in the array. For example, if a hash table uses an array with M entries, a simple hashing function might map the key K into array position K mod M.

Different variants of open addressing use different hashing functions and collision-resolution policies. In all cases, the collision-resolution policy produces a sequence of locations in the array for a value. If a value maps to a location that is already in use, the algorithm tries another location. If that location is also in use, the algorithm continues trying new locations until it finds an empty location or concludes that it cannot find one.

The sequence of locations that the algorithm tries is called its probe sequence. The average length of probe sequences for values that may or not be in the hash table gives a good estimate of how efficient the hash table is. Ideally the average probe sequence length should be only 1 or 2. If the table becomes too full, the average probe sequence may become fairly long.

Depending on the collision-resolution policy, a probe sequence might be unable to find an item for an empty slot even if there are empty slots in the hash table's array. If the probe sequence repeats itself before visiting every entry, some entries remain unused.

To locate an item in the hash table, the algorithm follows the value's probe sequence until one of three things happens. First, if the probe sequence finds the item, the job is done. Second, if the probe sequence finds an empty entry in the array, the item is not present.

The third possibility is that the probe sequence could visit M entries, where M is the size of the array. In this case, the algorithm can conclude that the value is not present. The probe sequence might not visit every entry in the array, but it is unlikely to find the target value. The probe sequence may be following a loop, visiting the same positions repeatedly. In any case, the value must not be present because, if it were, it would have been added to the array using the same probe sequence.

At a reasonable percentage, open addressing is very fast. The average probe sequence is only 1 or 2, adding and locating items has runtime O(1).

Open addressing is fast, but it has some disadvantages. The most obvious problem is that the hash table's performance degrades if its array becomes too full. In the worst case, if the array contains N items and is completely full, it takes O(N) time to conclude that an item is not present in the array. Even finding items that are present can be very slow.

If the array becomes too full, you can resize it to make it bigger and give the hash table a smaller percentage. To do that, create a new array and rehash the items into it. If the new array is reasonably large, it should take O(1) time to reach each item, for a total runtime of O(N).
