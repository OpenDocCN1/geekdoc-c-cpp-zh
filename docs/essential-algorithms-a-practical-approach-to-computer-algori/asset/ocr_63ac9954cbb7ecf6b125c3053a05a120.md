# Cryptographically Secure PRNGs

Any linear congruential generator has a period over which it repeats, and that makes it unusable for cryptographic purposes.
For example, you encrypt a message by using a PRNG to generate a value for each letter in the message and then decrypt that value to the letter. For the letter A 3 would be D, because there are three letters after A in the alphabet. If you get to Z, you wrap around to A. So, for example, Y + 3 = B.
This technique works quite well as long as the sequence of numbers is random, but a linear congruential generator has a limited number of seed values. All you need to do to crack is to try decrypting the message with every possible seed value. For each decryption, the program can look the distribution of letters to see if the result looks like real text. If you picked the wrong seed, every letter should appear with roughly equal frequency. If you guessed the right seed, letters such as E and T will appear much more than other letters, such as J and X. The letters are unevenly distributed, you probably guessed the seed.
This may seem like a lot of work, but on a modern computer it's not hard. If the seed value is a 32-bit integer, only 4 billion seed values are possible. A modern computer can check every possible seed in just a few seconds or, most, minutes.
A crypt secure pseudorandom number generator (CSPNG) uses more complicated algorithms to generate numbers that are harder to predict and produce much longer sequences without entering a loop. They typically have much larger seed values. A simple PRNG might use a 32-bit seed. A CSPNG might use keys that are 1,000 bits long to initialize its algorithm.
