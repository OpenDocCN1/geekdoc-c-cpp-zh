

# 第 18 章 分布式算法

- 有效性（Validity）——如果所有进程最初提议的值为 V，它们最终都对值 V 决定。
- 完整性（Integrity）——如果一个有效进程决定了一个值 V，那么 V 必须是由某个有效进程提议的。
- 一致性（Agreement）——所有进程最终必须对同一个值达成一致。

“阶段之王”（phase king）算法在最多有 $F$ 个进程故障且总数至少为 $4 + F + 1$ 个进程的情况下，可以解决共识问题。例如，为了容忍一次故障，该算法至少需要五个进程。

假设有 $N$ 个进程且最多有 $F$ 个故障。最初，每个进程都对它认为最终值应该是什么进行猜测。令 $V_i$ 为进程 $P_i$ 的猜测。

为了容忍最多 $F$ 个故障，算法使用了一系列 $F + 1$ 个阶段。在每个阶段中，其中一个进程被指定为“阶段之王”。你可以根据进程 ID 或其他任意值来分配阶段之王，只要每个阶段 own不同的阶段之王即可。

$F+1$ 个阶段中的每个阶段都包含两轮。在第一轮中，每个进程告诉其他所有进程它对认为应该是值的当前猜测。

每个进程检查它收到的猜测加上它当前的猜测，并找到多数决值。如果没有多数决值，它将使用某个预定义的默认值。令 $M_i$ 为进程 $P_i$ 的多数决值。

在第二轮中，阶段之王 $P_k$ 将自己的多数决值广播给所有其他进程，作为平局依据。每个进程（包括阶段之王在内）检查其多数决值 $M_i$。如果 $M$ 出现的次数大于 $N/2+F$，则进程通过 $V_i=M$ 更新其猜测。如果 $M$ 出现的次数不大于 $N/2+F$，则进程将 $V_i$ 设置为阶段之王的平局值。

例如，看看这在简单情况下是如何运作的：假设有五个进程，可能有一个无效进程，但实际上所有进程都在正常工作。令阶段 $i$ 的阶段之王为进程 $P_i$，并假设进程的初始猜测分别是：attack、retreat、retreat、attack、attack。

- 阶段 1，第 1 轮——进程诚实地相互广播它们的值，因此每个进程认为有三个 attack 和两个 retreat。
- 阶段 1，第 2 轮——阶段之王将其多数决值 attack 广播给其他进程。每个进程比较多数决值（attack）出现的次数。数值 $N/2+F=5/2+1=3.5$。因为多数决值的出现次数没有超过3.5 次，进程将它们的所有猜测设置为平局值 attack。
- 阶段 2，第 1 轮——进程再次诚实地相互广播它们的值。现在他们都 attack。
- 阶段 2，第 2 轮——阶段之王将它的多数决 attack 广播给其他进程。这次每个进程看到多数决值出现了五次。数值 5 大于 3.5，每个进程接受这作为自己的猜测。

由于这个例子容忍最多一次故障，它只在两个阶段后才结束。在这个例子中，每个进程都投票选择 *attack*，而这恰好是真实值。

# 领导选举

有时一组进程需要一个中央领导来协调行动。如果领导崩溃或网络故障，该组必须选出一个新领导。*霸权算法* 使用 ID 来选举新领导。尽管描述看起来简单，但霸权算法并没有你想象的那么简单。

以下步骤描述了霸权算法：

- 如果进程 P 检测到当前领导故障了（因为超时），它向所有较高 ID 的进程广播“你还在吗？”
- 如果 P 没有收到来自任何较高 ID 进程的“我还在”消息，它通过向所有进程发送“我是领导”来成为领导。
- 如果 P 收到来自较高 ID 进程的“我还在”消息，它会等待消息。如果 P 在超时时间内没有收到该消息，它假设领导故障并开始新选举。
- 如果 P 收到来自较低 ID 进程的“你还在吗？”，它回复“我还在”并开始新选举。
- 如果 P 收到来自较低 ID 进程的“我是领导”消息，它开始新选举。

在步骤 5 中，当一个较低 ID 的进程说它是领导时，较高 ID 的进程基本上说：“不不是，”推开较低 ID 的进程并接管。这种行为是霸权算法名称的由来。
