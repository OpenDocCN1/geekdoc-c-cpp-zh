In this example, the pieces of the brick represent 001, 010, 011, 100, 101, and 111 in binary, tell you which pieces to give to the contractor on each day. 1 means you should give the corresponding piece, and 0 means you should keep that piece.

For example, 6 is 110 in binary. This means on day 6 you give the contractor 4/7th piece (for the initial 1) and 2/7ths piece (for the second 1) but not the final (0).

This problem is easy if you've seen it before and can be confusing if you haven't, although you can probably come with a solution if you work through it starting day 1. Being aware of numbers can help you.

Whenever you have a tool such as a balance that divides a collection into sets, you should think about subdivision. If you divide a set of objects into two groups and eliminate one at each step, you can use binary subdivision to find whatever you're looking for.

In this problem, that doesn't work. If you put four eggs on each side of the balance, you can eliminate half of the eggs from consideration in one weighing. Then you can place the remaining four eggs, two on each side of the balance, and eliminate two more. At that point, you're still left with two, and you've used two weighings.

The balance lets you eliminate two of the three groups. After one weighing, the set of eggs under consideration must include only three eggs. That means the groups you weigh in the first weighing should contain three eggs (or fewer). 

The key to this problem is noticing the balance doesn't define only two sets containing eggs in the left pan and the right pan. It defines a third set containing eggs that are not in either pan. Instead of using binary to divide the eggs into two groups and eliminating one, you can use ternary to divide the eggs into three groups and eliminate two.

Suppose you have only three eggs. If you put one in the left pan, one in the right, you know the third egg is gold-plated. If the pans don't balance, you know the egg in the lighter pan is gold-plated.

That explains you perform the second weighing to finalize your choice. You still need to figure out how to use the first weighing to reduce the number of remaining eggs to three (or fewer).

Here's the final solution:

1. Place three eggs in the left pan, three in the right, and omit two.
2. If the pans balance:
   a. The gold-plated egg is one of the two eggs that were not weighed the first time. Place one of them in each pan.
   b. The lighter pan contains gold-plated egg.
3. If the pans don't balance:
   a. Exclude the eggs in the heavier pan and the eggs that were not weighed the first time.
   b. From the remaining three eggs, place one egg in the left pan and one egg in the right.
   c. If the pans balance, the egg that has not been weighed is gold-plated.
   d. If the pans don't balance, the lighter pan contains the gold-plated egg.

(Note, if the pans balance in the first weighing, you have narrowed the number of possibilities to two eggs. The second weighing can find the gold-plated egg in a set of three eggs, so it would work even if you had only narrowed the possibilities to three eggs. That means you can use the same technique if you start with nine eggs instead of eight.)

## Glossary

- **2-node** — In a 2-3 tree, a node that has two children.
- **3-node** — In a 2-3 tree, a node that has three children.
- **adaptive quadrature** — A technique in which a program detects areas where its approximation method may produce large errors and refines its method in those areas.
- **adjacent** — In a network, if two nodes are connected by a link, they are adjacent.
- **adversary** — In cryptography, a person trying to intercept a message.
- **algorithm** — A recipe for getting something done.
- **ancestor** — In a tree, a node's parent, its parent, and so on.
- **array** — A chunk of contiguous memory that program can access using indices.
- **associative** — Hash table.
- **asymptotic** — The limit of an algorithm's performance as the size grows.
- **attacker** — In cryptography, a person trying to intercept.
- **augmenting path** — A path through residual capacity that improves maximal flow.
- **AVL tree** — A sorted binary tree in which the heights of two subtrees at given node differ by at most 1.
- **B-tree** — A balanced tree in which internal nodes (called buckets) hold several values.
- **B+tree** — Similar to a B-tree, except that the tree's nodes store only key pointers to the data.
- **backtracking** — A recursive algorithm that considers partial solutions. If it finds a partial solution that cannot be extended to a full solution, the algorithm discards it, backtracks to the previous state, and continues searching.
- **balanced tree** — A tree that rearranges its nodes as necessary to guarantee it doesn't become too tall and thin.
- **Big Omega notation** — An algorithm's run time is Ω(g(N)) if the function g(N) is a lower bound.
- **Big O notation** — An algorithm's O time is O(g(N)) if the function g(N) is an upper bound.
- **Big Theta notation** — An algorithm's big theta run is Θ(g(N)) if the function g(N) is both lower and upper bound.
- **binary search** — A strategy that repeatedly divides the search space into two halves and searches the halves that contain the target item.
- **binary tree** — A tree with degree 2.
- **bipartite matching** — The process of matching the nodes in one group of a bipartite network with the nodes in the other group.
- **bipartite network** — A network in which the nodes can be divided into two groups, A and B, and every link connects a node in group A with a node in group B.
- **block cipher** — A cipher in which the plaintext is broken into blocks of the same size, each encrypted, and the blocks are combined to give the ciphertext.
- **bottom-up B-tree** — A B-tree that performs burst splits as recursive calls end and move up to the root.
- **branch** — Connects a parent and child node in the tree.
- **branch and bound** — A tree search algorithm in which the program moves down a branch then decides whether it is possible to improve its current solution enough to be better than the best solution so far. If the current solution does not improve on the best solution so far, the algorithm stops exploring that part of the tree.
- **breadth-first traversal** — In a tree or network, a traversal that visits all of a node's children before visiting any other nodes. This makes the traversal visit nodes close to the starting node before visiting nodes farther away.
