## Testing for Primality

The algorithm described in the earlier section “Finding Prime Factors” factors numbers. One way to determine whether a number is prime is to use an algorithm to factor it. If the algorithm doesn't find any factors, the number is prime.

As that section mentioned, that algorithm works well for relatively small numbers. But if the number has 100 digits, the number of steps the program must execute is a 50-digit number. Not even the fastest computers can perform that operations in a reasonable amount of time. (A computing 1 trillion steps per second would need more than 3 × 10^{30} years.)

Some cryptographic algorithms need to use large primes, so this method of testing whether a prime is wont works not. Frankly, there are other methods. The Fermat test is one of the simpler.

Fermat’s “little theorem” states that if p is prime and 1 ≤ n ≤ p, $n^{p-1} \pmod p = 1$. In other words, if you raise n to the p-1 power and take the result mod p, the result is 1.

For example, suppose p = 11 and n = 12. Then $n^{p-1} \pmod p = 2^{10} \pmod{11} = 1,024 \pmod{11}$. The value $1,024 = 11 \times 93 + 1$, so $1,024 \pmod{11} = 1$ as desired.

Note that it is possible for $n^{p-1} \pmod p = 1$ even if p is not prime. In that case the value n is called a Fermat liar because it incorrectly implies that p is prime.

If $n^{p-1} \pmod p \neq 1$, n is called a Fermat witness; it proves that p is not prime.

It can be shown that, for a natural number p, at least half of the numbers n between 1 and p are Fermat witnesses. In other words, if p is prime and you pick a random n between 1 and p, and there is a 0.5 probability that n is a Fermat witness, so $n^{p-1} \pmod p \neq 1$.

Of course, there is also a chance you'll get unlucky and randomly pick a Fermat liar for n. If you repeat the tests many times, you can increase the chances that you pick a witness if one exists.

It can be shown that at each test there is a 50 percent chance that you'll pick a Fermat witness. So if p passes k tests, there is a 1/2 chance you got unlucky and picked Fermat liars every time. In other words, there is a 1/2^k that p is actually a composite number pretending to be prime.

For example, if p passes the 10 tests, there is a 1/2^10 ≈ 0.00098 probability that p is not prime. If you want to test even more, repeat the test 100 times. If p passes all 100 tests, there is only a 1/2^{100} ≈ 7.8 × 10^{-31} probability that p is not prime.

The following pseudocode is an algorithm that uses this method to decide whether a number is probably prime:

```
// Return true if the number is (probably) prime.
Boolean: IsPrime(Integer: p, Integer: max_tests)
// Perform the test up to max_tests times.
For test = 1 To max_tests
  <Pick a pseudorandom number n between 1 and p (exclusive)>
  If (n^{p-1} Mod p != 1) Then Return false
Next
// The number is probably prime.
// There is a 1/2^{max_tests} chance that it is not prime.
Return true
```

> NOTE: This is an example of a probabilistic algorithm—one that produces a correct result with a certain probability. There's still a slim chance that the algorithm is wrong, but you can repeat the tests until whatever level of certainty you want.

If the number p is very large—which is the only time when this issue is interesting—using multiplication could take quite a while. Fortunately, you know how to do this quickly by using the fast exponentiation described in the earlier section “Performing Exponentiation."

Once you know how to determine whether a number is (probably) prime, you can write an algorithm to pick prime numbers:

// Return a (probable) prime with max_digits digits.
Integer: FindPrime(Integer: num_digits, Integer: max_tests)

  <Pick a pseudorandom number p with num_digits>

## Performing Numerical Integration

Numerical integration, which is sometimes called quadrature or numeric quadrature, is the process of using numerical techniques to approximate the area under a curve defined by a function. When the function is a function of one variable y = F(x) so the result is a two-dimensional area, but some applications might need to calculate the three-dimensional area under a surface defined by a function z = F(x,y). If the function is easy to understand, you may be able to use calculus to find the exact area. For example, perhaps the function's equation is complex, or you have data generated by physical process, so you don't use calculus, but you can use numerical integration.

There are several ways to perform numerical integration. The most straightforward for us are Newton-Cotes formulas, which use a series of polynomials to approximate the function. The two most basic kinds of Newton-Cotes formulas are the rectangle rule and the trapezoid rule.

It can be shown that at each test there is a 50 percent chance that you'll pick a Fermat witness. So if p passes k tests, there is a 1/2 chance you got unlucky and picked Fermat liars every time. In other words, there is a 1/2^k that p is actually a composite number pretending to be prime.

For example, if p passes the 10 tests, there is a 1/2^10 ≈ 0.00098 probability that p is not prime. If you want to test even more, repeat the test 100 times. If p passes all 100 tests, there is only a 1/2^{100} ≈ 7.8 × 10^{-31} probability that p is not prime.

The following pseudocode is an algorithm that uses this method to decide whether a number is probably prime:

```
// Return true if the number is (probably) prime.
Boolean: IsPrime(Integer: p, Integer: max_tests)
// Perform the test up to max_tests times.
For test = 1 To max_tests
  <Pick a pseudorandom number n between 1 and p (exclusive)>
  If (n^{p-1} Mod p != 1) Then Return false
Next
// The number is probably prime.
// There is a 1/2^{max_tests} chance that it is not prime.
Return true
```

### IsPrime

> NOTE: This is an example of a probabilistic algorithm—one that produces a correct result with a certain probability. There's still a slim chance that the algorithm is wrong, but you can repeat the tests until whatever level of certainty you want.

If the number p is very large—which is the only time when this issue is interesting—using multiplication could take quite a while. Fortunately, you know how to do this quickly by using the fast exponentiation described in the earlier section “Performing Exponentiation."

Once you know how to determine whether a number is (probably) prime, you can write an algorithm to pick prime numbers:

```
// Return a (probable) prime with max_digits digits.
Integer: FindPrime(Integer: num_digits, Integer: max_tests)
Repeat
  <Pick a pseudorandom number p with num_digits>
  If (IsPrime(p, max_tests)) Then Return p
```

## Performing Numerical Integration

Numerical integration, which is sometimes called quadrature or numeric quadrature, is the process of using numerical techniques to approximate the area under a curve defined by a function. When the function is a function of one variable y = F(x) so the result is a two-dimensional area, but some applications might need to calculate the three-dimensional area under a surface defined by a function z = F(x,y). You could calculate areas defined by higher-dimensional functions.

If the function is easy to understand, you may be able to use calculus to find the exact area. For example, perhaps the function's equation is complex, or you have data generated by physical process, so you don't use calculus, but you can use numerical integration.

There are several ways to perform numerical integration. The most straightforward for us are Newton-Cotes formulas, which use a series of polynomials to approximate the function. The two most basic kinds of Newton-Cotes formulas are the rectangle rule and the trapezoid rule.
