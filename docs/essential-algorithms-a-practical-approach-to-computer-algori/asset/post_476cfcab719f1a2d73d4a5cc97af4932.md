The algorithm starts by checking its depth of recursion. If it has exceeded its maximum allowed depth of recursion, the algorithm cannot determine the game's eventual outcome from this board position; it sets best_value to Unknown and returns.

To find the best move for player1, the algorithm must find the move that gives player2 the worst board value. The algorithm creates a variable to keep track of the lowest board value found so far for player2. It sets lowest_value equal to Infinity so that any board value it finds replaces the initial value of Infinity.

Next the algorithm loops through all the moves player1 could make. The Minimax algorithm makes a move and then recursively calls itself to find the best move player2 could make after player1 makes that move.

After the recursive call, the algorithm compares the best result player2 could obtain with the value saved in lowest_value. If the test value is lower, the algorithm updates lowest_value and lowest_move, so it knows that this move is preferable to player1.

After it finishes all the possible tests, the algorithm knows which move player1 should make to give player2 the worst possible position. It saves and converts the value of the board for player2 into the value for player1. For example, if the best board position makes player2 lose, it makes player1 win, and vice versa.

In cases player2 doesn't win or lose, it's a little less clear how to convert from a player2 value to a player1 value. For tic-tac-toe, the Unknown and Draw are the same for both players. For example, if a board position gives player2 a draw, it gives player1 a draw as well.

For a more complicated game such as chess, a board position's value might be a number between -100 and +100, where +100 represents a win and -100 represents a loss. In that case, player1's value for a board position might simply be the negative of player2's value for the same board position.

One side of a simple minimax strategy that can sometimes be a problem is that the program considers all solutions that have the board value equally desirable. To see why that could be a problem, suppose a game is close enough to the end for the program to realize that it will lose no matter what it does. In case, it selects the first move it considers searching the game tree, because all moves give the same result. That move may seem random or even foolish. For example, the program might pick a move that gives its opponent a win in the next move where a different move might have delayed the inevitable for two or three more moves. In contrast, a human would probably last longer, hoping the opponent will make a mistake or not realize that the game is as good as over.

Conversely, the program might find a way to win in six moves and pick that other strategy to win in only two moves.

You can address these problems by favoring longer sequences of moves that lead to losses or shorter sequences of moves that lead to wins, but for more complicated games a program cannot search the entire game tree. The following sections describe some strategies you can use to search larger game trees.

# Initial Moves and Responses

One way to reduce the size of the tree is to use precomputed initial moves and responses. Instead of searching the tree, you can use a table to look up the best move. For example, in chess, the openings are well-known, and you can use a table of the first few moves. This will significantly reduce the number of moves the program needs to search.

In tic-tac-toe, the openings are even simpler, and you can use a table of all possible opening moves. This will allow the program to find the best move instantly.

However, for more complicated games, the openings are not always well known. In these cases, you can use a heuristic to guide the search. A heuristic is a rule of thumb that helps you estimate the value of a position. For example, in chess, you might give more value to positions that control the center. This will help the program find moves that are likely to be beneficial.

The algorithm can also use pruning to prune the search tree. Pruning is the process of removing branches of the tree that are unlikely to affect the final result. This can significantly reduce the number of moves the program needs to search. One common technique for pruning is alpha-beta pruning.

Another way to search larger game trees is to use a depth-limited search. This limits the depth of the search tree and uses a heuristic to estimate the value of the positions at the depth limit. This is useful for games where the search tree is too large to search completely.
