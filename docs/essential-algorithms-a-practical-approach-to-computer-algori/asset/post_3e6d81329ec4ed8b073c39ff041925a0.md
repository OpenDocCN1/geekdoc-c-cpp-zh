For example, suppose you want to calculate $7^6$. First the algorithm calculates $7^1$, $7^2$, and $7^4$. It stops because the next power, 8, is greater than the desired power, 6:

$7^1 = 7$

$7^2 = (7^1)^2 = 7^2 = 49$

$7^4 = (7^2)^2 = 49^2 = 2401$

Next the algorithm uses the second fact to build 6 from a sum of powers of 2 that are already created. If you think of 6 as being because of $2 = 2 + 4$. Using the second fact, you know that $7^6 = 7^2 \times 7^4 = 49 \times 2401 = 117,649$.

Performing this calculation took two multiplications to calculate $7^2$ and $7^4$ plus one more multiplication to find the final result, for a total of three multiplications. That's fewer multiplications than multiplying $7 \times 7 \times 7 \times 7 \times 7$, but it's a small difference in this example.

More generally, for the exponent P, the algorithm calculates log(P) powers of A. It then searches the binary digits of A to see which of those powers it must multiply to get the final result. (If a binary digit of P is 1, then the result should include the corresponding power of 2. For the previous example, the binary representation of 6 is 110 so the second and third powers of 2 are included: $2^2$ and $2^1$).

In binary, the value P has log(P) digits, so the total time is O(log P) + O(log P). If P is 100, log(P) is about 20, so this algorithm uses about 20 steps (up to 40 multiplications), which is less than 1 million.

One limitation of this algorithm is that values raised to large powers grow extremely large. Even a "small" value as $7^{300}$ has 254 decimal digits. This means that multiplying the huge numbers needed to calculate large powers grows slow and takes up quite a bit of space.

Fortunately, the most common applications for these kinds of huge powers are cryptographic algorithms that perform all operations in modulus. The modulus is large, but it still limits the numbers' size. For example, if the modulus has 100 digits, the product of two 100-digit numbers can have more than 200 digits. You then reduce the result with the modulus to again get a number with no more 100 digits. Reducing each number with the modulus each step slightly smaller, but it means you can calculate values of practically unlimited size.

# Working with Prime Numbers

As you probably know, a prime number is a counting number (an integer greater than 1) whose only factors are 1 and itself. A composite number is a counting number greater than 1 that is not prime.

Prime numbers play important roles in some applications where their special properties make certain operations easier or more difficult. For example, some kinds of cryptography use the product of two large primes to provide security. The fact that it is hard to factor a number that is the product of two large primes is what makes the algorithm secure.

The following sections discuss common algorithms that deal with prime numbers.

# Finding Prime Factors

The most obvious way to find a number's prime factors is to try dividing the number by all the numbers between 2 and 1 less than the number. When a possible factor divides the number even more, save the factor, divide the number by it, and continue trying more possible factors. Note that you need to try the same factor again before moving on in the case number contains more than one copy of the factor.

For example, to find the prime factors of 127, you would try to divide 127 by 2, 3, 4, 5, and so on until you reach 126.

The following pseudocode shows this algorithm:

```
List Of FindFactors(Integer: number)
List Of Integer: factors
Integer: i = 2
While (i < number)
  // Pull out factors of i.
  While (Mod i == 0)
    // i is a factor. Add it to the list.
    factors.Add(i)
  // Divide the number by i.
  number = number / i
End While
  // Check the next possible factor.
  i = i + 1
End While

// If there's anything left of the number, it is a factor, too.
If (number > 1) Then factors.Add(number)

Return factors
End FindFactors
```

If the number is N, this algorithm runs in time O(N).
You can improve this method considerably with three key observations:

- You do not need to test whether the number is divisible by any even number other than 2 because, if it is divisible by any even number, it is divisible by 2. This means that you only need to check divisibility by 2 and then add odd numbers instead of all possible factors. Doing so cuts the run time in half.

- You only need to check for factors up to the square root of the number. If n = p × q, either p or q must be less than or equal to sqrt(n). (If both are greater than sqrt(n), their product is greater than n). If you check up to sqrt(n), you will find the smaller factor, which reduces the run time to O(sqrt(n)).

- Every time you divide the number, you can update the bound. These observations lead to the following improved algorithm:

```
List Of FindFactors(Integer: number)
List Of Integer: factors
// Pull out factors of 2.
While (Mod number == 0)
    factors.Add(2)
    number = number / 2
End While

// Look for odd factors.
Integer: i = 3
Integer: max_factor = Sqrt(number)
While (i <= max_factor)
    // Pull out factors of i.
    While (Mod i == 0)
        // i is a factor. Add it to the list.
        factors.Add(i)
        // Divide the number by i.
        number = number / i
    // Check the next possible factor.
    i = i + 2
    max_factor = Sqrt(number)
End While

// If there's anything left of the number, it is a factor, too.
If (number > 1) Then factors.Add(number)

Return factors
```
