
## OCTTREES

An octree is similar to a quadtree, except that it stores objects in three dimensions. An octree node represents a three-dimensional volume. When an octree node contains too many items, its volume is divided into eight octants that are represented by eight child nodes, and the items are distributed among the child subtrees.

## Tries

A Trie (the word comes from "retrieval" but is pronounced "try") is a tree that holds strings. Each internal node represents a single letter. Leaf nodes may represent more than one letter. A path from the root to a leaf node corresponds to a string, some are sometimes called prefix trees. A partial path from the root to an internal node represents a prefix for longer paths, whether it ends at an internal node or a leaf node, has an associated value. In this example, the node represents WISP and has value 72. To add a new key to the trie, you use the key's letters to follow the appropriate path through the trie. If you reach a leaf node and the key has more letters that are not represented by the current path, you add a new node to represent the rest of the key. For example, suppose you want to add the key WANTED to the trie. Follow the path through the nodes W, A, and N. The key still has letters, so you add a new node to hold them. Instead of storing a letter in each internal node, you can figure out the node's letter by keeping track of the path you took from the root to get there. For example, you could store a node's children in an array where Children[0] is the branch for the letter A, Children[1] is the branch for the letter B, and so forth. Figure 10-23 shows the trie from Figure 10-22 with internal nodes moved to the branches. Notice that the node with value 29 doesn't need any extra information because the key it represents is fully specified by the path to the node. In contrast, the path to the node with value 10 specifies only the letters W, A, and T, so the node needs to store the final D.

![](img/fefa42765c0b41af670511aea7c0cb_291_0.png)

Figure 10-23: Instead of storing an internal node's letter in the node, you can figure out the node from the path to the node.

The phrase "remaining node key" means part of a key stored in a leaf node, such as D and SP in Figure 10-23. The following pseudocode shows how you can add an item to a trie:

```
AddValue(string new_key, string new_value)
  If new_key is not blank and matches the remaining node key,
    place the value in this node and return.
  If new_key is blank and the remaining node key is too,
    place the value here and return.
  If new_key is blank and the node's remaining key isn't blank,
    move the node's remaining key (minus the first letter) into
    child, place the value here, and return.

  // If we get to this point, we need a child node.
  If (Children array is null) Then
    // Make the Children array.
    Children = New TrieNode[26]
    If the node's remaining key is not blank,
      move it into the appropriate child.
  End If
```

```
// Convert the letter into an integer by "subtracting" A.
Integer: index = new_key[0] - 'A'

// Search the appropriate subtrie.
If (Children[index] == null)
  // This child doesn't exist. Make it and
  // let it represent the rest of the new key.
  Children[index] = new TrieNode(
    Children[index].RemainingKey = new_key.Substring(1)
    Children[index].Value = new_value
  )
  Return
```

```
// Search the appropriate subtrie.
Children[index].AddValue(new_key.Substring(1), new_value)
```

This is a fairly confusing algorithm. It may be easier to understand if you draw a tree and walk through the algorithm, updating in various ways. As the algorithm moves through the trie, it removes the letters from the new key corresponding to the branches. First, if the new key is not blank and matches the remaining node key, the algorithm returns the value in this node. This happens if the trie contains WANTED and the algorithm crosses the T branch. If the new key is blank and the remaining node key is too, the algorithm returns the value here. This occurs if the trie contains WAN and the algorithm crosses the N branch. If the new key is blank but the node's remaining key isn't blank, the algorithm moves the remaining key (minus the first letter) into a child and returns the value here. This happens if the trie contains ED and the algorithm crosses the E branch.

If the algorithm gets to this point, it needs a child node. If the Children array is null, the algorithm creates the Children array. If the node's remaining key is not blank, it moves it into the appropriate child. This happens if the trie contains ISP and the algorithm crosses the I branch. If the child does not exist, the algorithm creates it and stores the rest of the key. If the child does exist, the algorithm calls itself to add the new key (minus its first letter).
