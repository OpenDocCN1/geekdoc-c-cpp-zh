This chapter describes different kinds of decision trees. It explains techniques you can use to search these trees efficiently so that you can find solutions to larger problems than you could find by using a brute-force approach. It explores heuristic methods you can use to find approximate solutions to some problems when searching a tree isn't feasible.

The following sections start the discussion of decision tree search algorithms by covering a very specific kind of search: game trees.

# Searching Game Trees

You can model games such as chess, checkers, Go, and tic-tac-toe (naughts and crosses) with a game tree where each branch represents a move by one of the players. At some point in the game player has 10 possible moves, the tree at point 10 possible branches. A complete path through the tree responds to a complete game.

Like all decision trees, game trees grow extremely quickly. For example, suppose a game lasts 40 moves (each player moves 20 times) and has an average of 30 possible moves per turn. The total number of paths through the game tree is $30^{40} \approx 1 	imes 10^{59}$. Exhaustively searching a tree with a computer that could examine 1 billion paths per second would take roughly $2.3 	imes 10^{44}$ (See http://en.wikipedia.org/wiki/Shannon_number for a discussion of the Shannon number, an estimate of the complexity of chess).

Tic-tac-toe is a more tractable problem, although the game tree is still huge. In the first move, the X player initially has nine squares. In the second move, player O has eight choices. At each move, the current player has one fewer choice than the other player in the previous move, so a total of $9 	imes 8 	imes 7 	imes ... 	imes 1 = 9! = 362,880$ paths through the game tree.

Some of the paths are illegal. For example, if X takes the first three squares with X taking squares the tree doesn't go all way to the ninth level of the tree.

If you remove all the paths that end early, the game tree still contains roughly a million leaf nodes, so the tree is still fairly.
