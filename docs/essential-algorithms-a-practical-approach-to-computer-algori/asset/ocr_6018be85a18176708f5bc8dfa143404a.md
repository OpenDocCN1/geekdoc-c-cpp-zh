Trying to solve the puzzle with a grand plan can be confusing, but there is a simple recursive solution. Instead of trying to think of solving the problem as a whole, you can reduce the problem size and recursively solve for the problem. The following pseudocode uses this approach to provide a simple recursive solution:

```
// Move the top n disks from peg_peg to to_peg
// using other_peg to hold disks temporarily as needed.
TowerOfHanoi(Peg: from_peg, Peg: to_peg, Peg: other_peg, Integer: n)
// Move the top n - 1 disks from from_peg to other_peg
If (n > 1) Then TowerOfHanoi(from_peg, other_peg, to_peg, n - 1)

// Move the top disk from from_peg to to_peg
<Move the top disk from from_peg to to_peg>

// Move the top n - 1 disks back from other_peg to to_peg
If (n > 1) Then TowerOfHanoi(other_peg, to_peg, from_peg, n - 1)
TowerOfHanoi
```

It does this by recursively calling the TowerOfHanoi algorithm. At this point, can you know how the algorithm works and handle the smaller problem?

The answer is that the method recursively calls itself repeatedly if needed to move smaller and smaller stacks of disks. At some point in the sequence of recursive calls, the algorithm is called to move only a single disk. Then the algorithm doesn't call itself recursively. It moves the disk and returns.

The key is that each recursive call is used to solve a smaller problem. Eventually the problem size is so small that the algorithm can solve it without calling itself recursively.
