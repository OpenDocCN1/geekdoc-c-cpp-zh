# Numerical Algorithms

Numerical algorithms calculate numbers. They perform such tasks as randomizing values, breaking numbers into their prime factors, finding greatest common divisors, and computing geometric areas.

All these algorithms are useful occasionally, but they also demonstrate useful algorithmic techniques such as adaptive algorithms, Monte Carlo simulation, and using tables to store intermediate results.

# Randomizing Data

Randomization plays an important role in many applications. It lets a program simulate random processes, test algorithms to see how they behave with random inputs, and search for solutions to difficult problems. Monte Carlo integration, which is described in the later section “Performing Numerical Integration,” uses randomly selected points to estimate the size of a complex geometric area. The first step in any randomized algorithm is generating random numbers.

# Generating Random Values

Even though many programmers talk about “random” number generators, any algorithm used by a computer to produce numbers is not truly random. knew the details of the algorithm and its internal state, you could correctly predict the "random" numbers it generates.

To get truly unpredictable randomness, you need to use a source other than a computer program. For example, you could use a radiation detector that measures particles coming out of a radioactive sample to generate random numbers.

Other sources of true randomness include dice rolls, atmospheric noise, and Brownian motion. Unfortunately, these methods are slow and complicated, so most applications use pseudorandom number generators (PRNGs).

One feature of PRNGs is an advantage that you can use a particular seed to generate the same sequence of "random" values repeatedly. That may also be a disadvantage, because it means that the numbers are more predictable, being able to use the same numbers can make some programs much easier to debug.

Being able to repeat sequences of numbers also lets some applications store complex data in a compact format. For example, suppose a program needs to perform a long and complicated pseudorandom walk on a map. The program could generate and save all its coordinates so that it can redraw the route. Alternatively, it could just save the seed. Then, whenever it needs to draw the route, it can use the seed to reinitialize a PRNG so that produces the same walk each time.

A simple example of creating numbers is a linear congruential generator, which uses the following relationship $X_{n+1} = (A \times X_n + B) \pmod M$, where A and B are constants. 

```
  X_0 = 0
  X_1 = (7 × 0 + 5) mod 11 = 5
  X_2 = (7 × 5 + 5) mod 11 = 7
  X_3 = (7 × 7 + 5) mod 11 = 4
  X_4 = (7 × 4 + 5) mod 11 = 10
  X_5 = (7 × 10 + 5) mod 11 = 9
  X_6 = (7 × 9 + 5) mod 11 = 2
  X_7 = (7 × 2 + 5) mod 11 = 8
  X_8 = (7 × 8 + 5) mod 11 = 6
  X_9 = (7 × 6 + 5) mod 11 = 3
  X_10 = (7 × 3 + 5) mod 11 = 0
```

Because $X_{10} = X_0$, the sequence repeats. The values $0, 5, 7, 4, 10, 9, 2, 8, 6, 3$ look fairly random. But now that you know the method that the program uses, if someone tells you the current number, you can correctly predict that.
