The mergesort algorithm, however, doesn't need to load that memory all at once. The algorithm doesn't even need to look at any of the items in the array after its recursive calls have returned.

At that point, the algorithm walks through the two sorted halves in a linear fashion and merges them. Moving through the items linearly reduces the computer's page memory to from disk. When quicksort moves items into the two halves of a section paging, it jumps from one location in the array to another, increasing paging and slowly down the algorithm.

Mergesort was more useful in the days when large data sets were stored on tape drives, which most efficiently moved forward with a few rewinds. (Sorting that cannot fit in memory is external sorting). Specialized versions of mergesort were even more efficient for tape drives. They're interesting but not commonly used anymore, so they aren't described here.

A common approach to sorting enormous sets is to sort only the items' keys. For example, a customer record might occupy 1 MB, but the customer's name might occupy only 100 bytes. A program can make a separate index that matches to record numbers and then sort the names. Then, if you have 1 million customers, sorting them requires only about 100 MB of memory, and an amount that could reasonably hold. (Chapter 11 describes B-trees and B+ trees, which are often used by database systems to store and sort record keys in this manner.)

# STABLE SORTING

> A stable sorting algorithm is one that maintains the original positioning of equivalent values. For example, suppose a program is sorting Car objects by their Cost and Car objects A and B have the same Cost values. If object A initially comes before B in the array, then in a stable sorting algorithm, A still stays before B in the sorted array.

If the items are sorting value types such as integers, dates, or strings, then two entries with the same values are equivalent, so it doesn't matter if the sort is stable. For example, if the array contains two entries have value 47, it doesn't match 47 comes first in the sorted array.

In contrast, if Car objects are rearranged unnecessarily, a stable sort lets you sort the array times to get a result that is sorted on multiple keys (such as Maker and Cost for the Car example).

Mergesort is easy to implement as a stable sort (the algorithm described earlier-is stable), so it is used by Java's Arrays.sort library method.

Mergesort is also easy to parallelize, so may be useful on computers that have more than one CPU. See Chapter 18 for information on implementing merge-sort on multiple CPUs.

Quicksort may be faster, but mergesort still has some advantages.
