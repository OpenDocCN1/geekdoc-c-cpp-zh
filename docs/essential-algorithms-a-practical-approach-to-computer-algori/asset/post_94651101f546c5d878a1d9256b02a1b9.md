The next step, mapping row and column to a position in the one-dimensional array, is a bit more confusing. Recall how the preceding mapped row and column to an index in the values array. First the code defined how complete rows belongs in the array and multiplied by the number of items in a row. The code added 1 for each position in the item's row that was before the item.

Moving to three dimensions isn't much harder. Figure 4-3 shows a 4x4x3 three-dimensional array with dimensions labeled height, row, and column. entry with coordinates (1, 1, 3) is highlighted in gray.

To map the item's coordinates (1, 1, 3) to an index in the values array, first determine how many complete "slices" come before it. Because the item's height coordinate is 1, there is one complete slice before the item in the array. The size of a slice is <row size> x <column size>. If the item has coordinates (h, r, c), the number of items that come before this one to slices is given by the following:

```
index = h x <row size> x <column size>
```

Next you need to determine how many items come before this one due to rows. In this example, the item's row is 1, so one row comes before the item in the values array. If the item has row r, you need to add r times the size of a row to the index:

```
index = index + r x <row size>
```

Finally, you need to add 1 for each item that comes before this one in its column. If the item has column c, this is simply c:

```
index = index + c
```

You can extend this technique to work in even higher dimensions. To make calculating indices in the values array easier, you can make a slice_size array that holds the size of the “slice” at each of the dimensions. In the three-dimensional case, these values are <row size> x <column size>, <Column size>, and 1.

To move to higher dimensions, you can find a slice by multiplying the next slice by the size of the current dimension. For example, four dimensional array, the next slice size would be <height size> x <row size> x <column size>.

With all this background, you are ready to see the complete algorithm. Suppose the bounds array alternates lower and upper bounds for the N-dimensional array. The following pseudocode initializes the array:

```
// Initialize LowerBound and Slice.
Integer: slice_size = 1
For i = NumDimensions - 1 To 0 Step -1
SliceSize[i] = slice_size
```

```
LowerBound[i] = bounds[2 * i]
Integer: upper_bound = bounds[2 * i + 1]
Integer: bound_size = upper_bound - LowerBound[i]
slice_size *= bound_size
```

```
// Allocate room for all of the items.
Double: Values[slice_size]
InitializeArray
```

This code calculates the number of dimensions by dividing the values in the bounds array by 2. It creates a LowerBound array to hold the lower bounds and a SliceSize array to hold the sizes of slices at different dimensions.
The next code sets slice_size to 1. This is the size of the slice at the highest dimension

The code loops through the dimensions, starting at the highest and looping toward 0. (This corresponds to looping from column to row to height in the preceding example). It sets the current slice size to slice_size and saves the dimension's lower bound. It multiplies slice_size by the current dimension to get the slice size for the next-smaller dimension.

After it finishes looping over all the dimensions, slice_size holds the sizes of all the array's dimensions multiplied together. That is the total number of items in the array, so the code uses to allocate the Values array, where it will store the array's values.

The following deceptively simple pseudocode uses the LowerBound and SliceSize array to map the indices array to an index in the Values array:

```
Integer: MapToIndex(Integer: indices[])
Integer: index = 0
For i = 0 to indices.Length - 1
  index = index +
    (indices[i] - LowerBound[i]) * SliceSize[i]
Next i
  Return index
End MapToIndex
```

The code initializes index to 0. It then loops over the array's dimensions. For each dimension, it multiplies the number of slices at dimension by the size of a slice at dimension and adds the result to index.

After it has looped over all the dimensions, index holds the item's index in the Values array.

You can make the algorithm easier by encapsulating it in a class. The constructor can tell the object what dimensions to use. Depending on your programming language, you will be able to make get and set methods that are used as access so that a program can treat an object as if it were an array.

## Triangular Arrays

Some applications can save space by using triangular arrays instead of normal rectangular arrays. In a triangular array, the values above the diagonal (where the column's index is greater than its row) have some default value, such as 0, null, or blank. Figure 4-4 shows an upper triangular array.

For example, a connectivity matrix represents the connections between points in some sort of network. The network might be an airline's flight network that indicates airports are connected to other airports. The array's entry connected[i, j] is set to 1 if there is a flight from airport i to airport j. if you assume there is a flight from airport i to airport j whenever there is a flight from airport i to airport j.

Figure 4-4: In a triangular array, values above the diagonal

Building a triangular array isn't too hard. Simply pack the array's values into one-dimensional array, skipping the entries that should not be. The challenges are to figure out how big the one-dimensional array must be and to figure out how to map rows and columns to the one-dimensional array.

Table 4-1: Entries in Triangular Arrays

| NUMBER OF ROWS | NUMBER OF ENTRIES |
|---|---|
| 1 | 1 |
| 2 | 3 |
| 3 | 6 |
| 4 | 10 |
| 5 | 15 |
| 6 | 21 |
| 7 | 28 |

If you study Table 4-1, you'll see a pattern. The number of cells needed for N rows equals the number needed for N-1 rows plus N. If you think about triangular arrays for a while, you'll realize that they contain roughly half the number of entries in a square array with $N^2$ entries, so it seems likely that the number of entries in the corresponding triangular array would involve $N^2$. If you start with a general quadratic equation $A \times N^2 + B \times N + C$ and plug in the values from Table 4-1, you can solve for A, B, and C to find that the equation is $(N^2+N)/2$.
That solves the first challenge. To build a triangular array with N rows, allocate a one-dimensional array containing $(N^2+N)/2$ items.
The second challenge is to figure out how to map rows and columns to the one-dimensional array. To find the index of an entry with row r and column c, you need to figure out how many entries come before that one in the one-dimensional array.
