If the array holds N items and at least one item reaches its final position each pass through the array, the algorithm can perform, at most, N passes. (If the array is initially sorted in reverse order, the algorithm needs all N passes.) Each pass takes N, so the total time is O(N²).

Like insertionsort and bubblesort is fairly slow for small lists (fewer than 1000 or items). It is also sometimes faster than more complicated algorithms for very small lists (five or items).

You can make several improvements to bubblesort. In Figure 6-3, the item with value 3 started out before its final position, but consider what happens if an item starts after its final position. In that case the algorithm finds the item out of position and swaps it with the following item. It then considers the next item in the array and finds it again. If it is still out of position, the algorithm swaps it again. The algorithm continues to swap it down the list until it reaches its final position in a single pass through the array. You can use this fact to speed up the algorithm by alternating downward and upward passes through the array. Downward passes quickly move items that are too high in the array, and upward passes quickly move items that are too low in the array.

To make a second improvement, notice that some items move through several swaps in a downward pass, a large item (call it K) be swapped several times before it reaches a larger item, and it stops for that. Pass, you can save a little time if you don't put K back in the array for every swap. Instead, you can store K in a temporary variable and move other items in the array until you find the spot where K stops. You then put K in position and continue the pass through the array.

To make a final improvement, consider the last item (call L) that is not in its final position. During a downward pass, the algorithm reaches that item and swaps it down the list until it reaches its final position. The next pass through cannot swap L unless it is in its final position. That means the algorithm can end its pass through the array when it reaches item L.

More generally, the algorithm can end its pass through the array when it reaches the position of the last swap it made during the previous pass. If you keep track of the last swap made during downward and upward passes through the array, you can shorten each pass.
