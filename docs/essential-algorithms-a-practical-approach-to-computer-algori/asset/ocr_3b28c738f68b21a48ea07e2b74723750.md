To attack a column cipher, an attacker would write the message in an array, with the number of columns given by the length of the keyword. The attacker would swap columns to guess the proper ordering. If the array has C columns, there are C possible orderings of the columns, which could require looking at a lot of combinations. For example, 10 columns would result in 3,628,800 possible arrangements of columns.

It seems like a lot of possibilities, particularly if the attacker is using a computer, but the attacker may be decrypt the message incrementally. The attacker could start by trying to find the first five columns in the plaintext. If the first five columns are correct, the first row will show five characters of valid words. It may show a complete word or at least a prefix of a word. The other rows may begin with partial words, but after that they will contain words or prefixes. There are only 10³⁹⁸8⁷7⁶ = 30,240 possible arrangements of five columns chosen from 10, so this is a few combinations to check, although it would be a daunting task.

# Route Ciphers

In a route cipher, the plaintext is written into an array or some arrangement and is then read in an order determined by a route through the array. For example, Figure 16-4 shows a plaintext message written into an array by rows. The ciphertext is read by following the array's diagonals, starting with the left diagonal, so the ciphertext is SRSSE ATATG HSMEI EECSI.

![](bbox=[0.19, 0.663, 0.383, 0.787])

Figure 16-4: In a route cipher, you write the plaintext into an array by rows and then read the ciphertext in some other order.

In the theory, the number of possible routes through the array is enormous. If the array holds N entries, N! possible routes exist. The example shown in Figure 16-4 has 20! ≈ 2.4 10¹⁸ possible routes.
