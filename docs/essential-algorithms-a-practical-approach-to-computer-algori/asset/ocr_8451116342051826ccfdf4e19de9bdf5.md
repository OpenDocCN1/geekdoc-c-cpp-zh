+   11. It is easy to write down, but it's not easy to look up transitions when you need them. For example, suppose the DFA is in state 17, and it sees the input H. The program would need to search the table to find the appropriate entry before moving to the state. If the table is large, this could take a while. To speed things up, you could store the transitions in a tree, hash table, or some other data structure to make transitions easier. That would take more memory and complicate the program.

In contrast, suppose you use objects to represent the states, similar to how you can use node objects to represent locations in a network. Each state object could have a list giving the new state object for various inputs. In each case, state transitions would be relatively quick and simple. If some states can read many inputs (in other words, there are many links leaving them in the state diagram), you might spend some time looking up new states. In case you might want to use a tree, hash table, or some other data structure to make finding new states faster, at least you won't have to search the whole transition table.
