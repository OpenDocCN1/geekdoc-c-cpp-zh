
## Sub O(N log N) Algorithms

Earlier this chapter said the fastest possible algorithm that uses comparisons to sort N items uses at least O(N log N) time. Heapsort and mergesort achieve that bound, and so do quicksort in the expected case, you might think that it's the end of the sorting story. The loophole is in the phrase “that uses comparisons.” If you use a method other than comparisons to sort, you can beat the O(N log N) bound. The following sections describe two algorithms that sort in less than O(N log N) time.

### Countsort

Countsort works if the values you are sorting are integers that lie in a relatively small range. For example, if you need to sort a million integers between 0 and 1000, countsort provides amazingly performance. The basic idea behind countsort is to count the number of items in the array that have each value. It is relatively easy to copy each value, in order, the required number of times back to the array. Then the following pseudocode shows the algorithm:

```
Countsort(Integer: values[], Integer: max_value)
  // Make an array to hold the counts.
  Integer: counts[0 To max_value]
  // Initialize the array to 0. (This is not necessary in all programming languages.)
  For i = 0 To max_value
    counts[i] = 0

  // Count the items with each value.
  For i = 0 To length of values - 1
    // Add 1 to the count for this value.
    counts[values[i]] = counts[values[i]] + 1

  // Copy the values back into the array.
  Integer: index = 0
  For i = 0 To max_value
    // Copy the value i into the array counts[i] times.
    For j = 1 To counts[i]
      values[index] = i
      index = index + 1
```

The `max_value` parameter gives the largest value in the array. If you don't pass it as a parameter, the algorithm can figure it out by looking through the array. Let M be the number of items in counts array (so M = max_value + 1) and N be the number of items in values array. If your programming language does not automatically initialize counts so that it contains 0s, the algorithm spends M steps initializing the array. It then takes N steps to count the values in the array. The algorithm finishes by copying the values back into the original array. If any of the entries in counts array is still 0, the program spends some time skipping over that. In the worst case, if all values are the same so that the counts array contains mostly 0s, it takes M steps.

That makes the total run time O(N+M). If M is relatively small compared to N, this is much smaller than the O(N log N) performance given by heapsort and the other algorithms. In one test, quicksort took 4.29 seconds to sort a million items between 0 and 1000, but countsort took only 0.03 seconds. Countsort handles lots of duplication well.

### Bucketsort

The bucketsort (also called bin sort) works by dividing items into buckets. It sorts the buckets either by recursively calling bucketsort or by some other algorithm and concatenates the buckets back into the original array. The following pseudocode shows the algorithm at a high level:

```
Bucketsort(Data: values[])
  Make buckets.
  Distribute the items into the buckets.
  Sort the buckets.
  Gather the bucket back into the original array.
```

If the values in an array holding N items are uniformly distributed, if you use M buckets and the buckets divide the range of values evenly, you should expect N / M items per bucket. For example, consider the array at the top of Figure 6-12, which contains 10 items between 0 and 99. In the distribution step, the algorithm moves the items into the buckets. In this example, each bucket represents 10 values: 0 to 9, 10 to 19, and so on. In the sorting step, the algorithm sorts each bucket. The gathering step concatenates the values in the buckets to build the sorted result.

The buckets can be stacks, linked lists, queues, arrays, or any other data structure you find convenient. If the array contains N evenly distributed items, distributing them into buckets requires N times whatever it takes to place an item in a bucket. Normally this mapping can be done in constant time. For example, suppose the items are integers between 0 and 99, as in the example shown in Figure 6-12. You would place item with value v in bucket number ⌊v/2⌋. You can calculate this in constant time, distributing the items takes O(N) steps. If you use M buckets, sorting each bucket requires an expected F(N / M) steps, where F is the run time function of the sorting algorithm that you use to sort the buckets. Multiplying this by the number of buckets M, the total time to sort all the buckets is O(M × F(N / M)). After you have sorted the buckets, gathering their values back into the array requires N steps to move all the values. It could require an additional O(M) steps to skip empty buckets if many of the buckets are empty, but if M < N, the whole operation requires O(N) steps.

Adding the times needed for the three stages gives a total run time of O(N) + O(M × F(N / M)) = O(N + M × F(N / M)). If M is a fixed fraction of N, M is a constant, so F(N / M) is also a constant, and this simplifies to O(N).

In practice, M is a relatively large fraction of N for the algorithm to perform well.

## Summary

The sorting algorithms described in this chapter demonstrate an assortment of techniques and have different characteristics. Table 6-1 summarizes the algorithms.

**Table 6-1 Algorithm:**

| ALGORITHM | RUN TIME | TECHNIQUES | WHAT IS USEFUL FOR |
| :--- | :--- | :--- | :--- |
| Insertort | O(N²) | Insertion | Very small arrays |
| Selectort | O(N²) | Selection | Very small arrays |
| Bubblesort | O(N²) | Two-way passes | Mostly sorted arrays |
| Heapsort | O(N log N) | Heaps, storing complete trees in an array | Large arrays |
| Quicksort | O(N log N) expected, O(N²) worst case | Divide-and-conquer, swapping items into position, randomization to avoid worst-case | Large arrays without many duplicates |
| Mergesort | O(N log N) | Divide-and-conquer, merging, external sorting | Large arrays with unknown distribution, huge amounts of data |
| Countsort | O(N + M) | Counting | Range of values |
| Bucketsort | O(N + M) | Buckets | Large arrays with uniform value distribution |

**Table 6-1 (continued):**

| ALGORITHM | RUN TIME | TECHNIQUES | WHAT IS USEFUL FOR |
| :--- | :--- | :--- | :--- |
| Countsort | O(N + M) | Counting | Large arrays of integers with a limited range of values |
| Bucketsort | O(N + M) | Buckets | Large arrays with reasonably value distribution |
