**Figure 4-8:** To remove a target entry, the algorithm sets the preceding's NextColumn reference to the entry after the target entry.

The algorithm does not change the target entry's NextColumn reference. That reference still refers to the following entry, but the algorithm no longer has a reference that can refer to the target entry, so it is essentially lost to the program.

> **NOTE** When this algorithm deletes a row or column object, that's memory must be freed. Depending on the programming language you use, that may require more action. For example, a C++ program must explicitly call the free function for the removed object that may memory available for reuse. Other languages take other approaches. For example, C# and Visual Basic use garbage collection, the next time the garbage collector runs, it automatically frees any objects that the program can no longer access.

After it has removed the target entry from the row's linked list, the program examines the row's ArrayRow sentinel. If that object's NextColumn reference is not null, the row still holds other column entries, so the algorithm is finished, and returns.

If the target no longer contains any entries, the algorithm removes it from the linked list of ArrayRow objects, as it removed the target column entry. The DeleteEntry algorithm calls FindBefore and FindColumnBefore. If the array has N rows that contain nondefault values and the row with most M of those values, the run time for the DeleteEntry method is O(N + M).
