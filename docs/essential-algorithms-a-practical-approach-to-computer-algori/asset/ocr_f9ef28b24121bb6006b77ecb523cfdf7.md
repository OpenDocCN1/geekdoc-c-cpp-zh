AddValue

This is a fairly confusing algorithm. It may be easier to understand if you draw a tree and walk through the algorithm, updating in various ways. As the algorithm moves through the trie, it removes the letters from the new key corresponding to the branches it crosses. The body of the algorithm then considers the current value of the new key.

First, if the new key is not blank and matches the remaining node key, the algorithm places the new value in the current node. This would happen in Figure 10-23 if you set the value for WANTED. When the algorithm reaches the needed node D, the new key value will be D and the node's remaining key is D.

Next, if the new key is blank and the remaining key is too too, the algorithm places the value in this node. This occurs if you set the value of WAN in Figure 10-23. When the algorithm crosses the N branch, the new key is reduced to an empty string. The node at the end of that branch doesn't have any remaining key (only leaf nodes can have remaining key values), so this is where the value for WAN belongs.

Next, if the new key is blank but the node's remaining key isn't, the algorithm moves the remaining key into it. This would happen if the trie contains WANTED and not WANTED. In that case, the path for WANTED will be W, A, N, T, ED. When you add WANTED and crosses the T branch, the new key value moves the ED down to a child, creating a new E branch and a new node D with its remaining key.

If the algorithm gets past all the previous steps, the algorithm must move into a child subtrie. Before it tries to do that, it determines whether the node's Children array has been initialized. If it has not, the algorithm creates the Children array. If the remaining key isn't blank, the algorithm also moves the remaining key (minus its first letter) into the appropriate child.
