# Sub O(N log N) Algorithms

Earlier this chapter said the fastest possible algorithm that uses comparisons to sort N items uses at least O(N log N) time. Heapsort and mergesort achieve that bound, and so do quicksort in the expected case, you might think that it's the end of the sorting story. The loophole is in the phrase “that uses comparisons.” If you use a method other than comparisons to sort, you can beat the O(N log N) bound.

The following sections describe two algorithms that sort in less than O(N) log time.

# Countsort

Countsort works if the values you are sorting are integers that lie in a relatively small range. For example, if you need to sort 1 million integers with values between 0 and 1,000, countsort can provide amazingly fast performance.

The basic idea behind countsort is to count the number of items in the array that have each value. It is relatively easy to copy each value, in order, the required number of times back to the array.

Then the following pseudocode shows the countsort algorithm:

```
Countsort(Integer: values[], Integer: max_value)
  // Make an array to hold the counts.
  Integer: counts[0 To max_value]

  // Initialize the array to hold the counts.
  // (This is not necessary in all programming languages.)
  For i = 0 To max_value
    counts[i] = 0
  Next i

// Count the items with each value.
  For i = 0 To <length of values> - i
    // Add 1 to the count for this value.
    counts[values[i]] = counts[values[i]] + 1
  Next i

// Copy the values back into the array.
  Integer: index = 0
  For i = 0 To max_value
    // Copy the value i into the array counts[i] times.
    For j = 1 To counts[i]
      values[index] = i
      index = index + 1
    Next j
  Next i
End Countsort
```
