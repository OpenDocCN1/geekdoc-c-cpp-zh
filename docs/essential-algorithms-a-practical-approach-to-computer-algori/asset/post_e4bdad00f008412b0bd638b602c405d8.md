## Searching

The preceding chapter explained how you can sort data. Algorithms such as quicksort and heapsort let you sort fairly large amounts of data quickly. Algorithms such as countsort and bucketsort let you sort data almost as quickly as a program can examine it but only under certain special circumstances.

One of the advantages of sorted data is that it lets you find specific items relatively quickly. For example, you can locate a particular person in a telephone directory containing tens of thousands of names in just a minute or because all the names are arranged in sorted order. (Imagine trying to find a name if the directory wasn't sorted!)

This chapter explains algorithms that you can use to find a particular piece of data in a sorted array.

> NOTE The algorithms described in this chapter work with simple arrays, not more specialized data structures. Specialized data structures such as trees also let you quickly find an item with a specific value. Algorithms for working with trees are discussed in Chapter 10.

> NOTE Some programming libraries include searching tools that locate items in a sorted array. For example, the .NET Framework's Array class provides a BinarySearch method. These methods are generally fast, so in practice you may use those tools to save time writing and debugging the sorting code.

It's still important to understand searching algorithms work, however, because sometimes you can do even better than the tools. For example, interpolation search is much faster than binary search when it is applicable.

## Linear Search

As you may be aware, a linear or exhaustive search simply loops through the items in the array, looking for the target item. Figure 7-1 shows a linear search for the value 77.

![](img/fefa42765c0b410af6705110aea7c0cb_187_0.png)

Figure 7-1: a linear search examines every item in the array until it finds the target.

Unlike binary search and interpolation search, linear search works on linked lists, where you cannot easily jump from one part of the list to another, as you can in an array.

Linear search also works on unsorted lists. But if the items are sorted, the algorithm can stop if it comes to an item with a value greater than the target value. That lets the algorithm stop early and save a little time if the target isn't in the list.

The following pseudocode shows the linear search algorithm for an array:

```
// Find the target item's index in the sorted array.
// If the item isn't in the array, return -1.
Integer: LinearSearch(Data values[], Data target)
For i = 0 To <length of values>
  // If the item is found, return the index.
  If (values[i] == target) Then Return i
  // If we have passed the target, stop.
  If (values[i] > target) Then Break
Next i
// If the item is not in the array
Return -1
```

This algorithm is much slower than binary search, but it has the advantage that it works on linked lists and unsorted lists. In the worst case, it may need to loop through the entire array, so its runtime is O(N). Even in the average case, you get O(N).

## Binary Search

In binary search, the algorithm keeps track of the smallest and largest indices that might contain the item. Initially, these bounds are 0 and <length of values> - 1. At each step, the algorithm divides the number of items in half. If the array contains N items, with O(log N) steps, the section of the array that might hold the target contains only one item, so the algorithm either finds the item or concludes it isn't.

The following pseudocode shows the algorithm:

```
// Find the target item's index in the sorted array.
// If the item isn't in the array, return -1.
Integer: BinarySearch(Data values[], Data target)
Integer: min = 0
Integer: max = <length of values> - 1
While (min <= max)
  // Find the dividing item.
  Integer: mid = (min + max) / 2
  // If the item is found, return the index.
  If (values[mid] == target) Then Return mid
  // If we need to search the left half.
  If (target < values[mid]) Then max = mid - 1
  // If we need to search the right half.
  Else min = mid + 1
End While
// If the item is not in the array
Return -1
```

## Interpolation Search

At every step, binary search examines the item in the middle of the section of the array that it is considering. In contrast, interpolation search uses the value of the target item to guess where in the array it lie and achieve much faster times. For example, suppose the array contains 1000 items with values between 1 and 100. If the target is 30, it lies about 30 percent of the way from the smallest to the largest value so you can guess that the item be near index 30. Depending on the distribution of the numbers in the array, this may not be exactly correct, but it should get you fairly close to the target item's position.

Figure 7-3 shows an interpolation search for the value 77.

| 16 | 21 | 22 | 39 | 41 | 47 | 49 | 52 | 57 | 60 | 65 | 71 | 77 | 90 | 91 |

Figure 7-3: interpolation search uses the target item's value to calculate where it should be in the remaining part of the array.

The following pseudocode shows the algorithm at a high level:

```
Integer: InterpolationSearch(Data values[], Data target)
Integer: min = 0
Integer: max = <length of values> - 1
While (min < max)
  // Find the dividing item.
  Integer: mid = min + (max - min) *
    (target - values[min]) / (values[max] - values[mid])
  If (values[mid] == target) Then Return mid
  // Set min or max to search the left or right half.
End While
```
