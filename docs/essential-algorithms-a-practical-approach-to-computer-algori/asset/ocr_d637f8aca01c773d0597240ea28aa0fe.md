# 512 Appendix B Solutions to Exercises

+   c. 1,000 names—Heapsort, quicksort, and mergesort would work well. Quicksort would be fastest if the values do not contain too many duplicates and are initially sorted or if you use a randomized method for selecting items. Countingsort doesn't work. Making bucketsort might be difficult. (The trie described in Chapter 10 is similar to a bucketsort, and it would work.)

+   d. 100,000 integers with values between 0 and 1,000—Countingsort would work very well. Bucketsort would also work, but not as well as countingsort. Heapsort, quicksort, and mergesort would be slower.

+   e. 100,000 integers with values between 0 and 1 billion—Countingsort would not work well, because it would need to allocate an array with 1 billion entries to hold value counts. Bucketsort would work well. Heapsort, quicksort, and mergesort would be slower.

+   f. 100,000 names—Countingsort doesn't work with strings. Making bucketsort might be difficult. (Again, the trie described in Chapter 10 would work.) Heapsort, quicksort, and mergesort would work well, with quicksort being the fastest in the expected case.

+   g. 1 million floating-point values—Countingsort doesn't work with strings. Bucketsort would work well. Quicksort, and mergesort would work but be much slower.

+   h. 1 million names—This is a hard for the algorithms described in this chapter. Countingsort doesn't work with strings. Making bucketsort with strings could be hard, but it would work. Heapsort, quicksort, and mergesort would work but would be slow. The trees described in Chapter 10 can also handle this case.

+   i. 1 million integers with uniform distribution—Countingsort might work if the range of values is limited. Otherwise, bucketsort would probably be the best choice. Heapsort, quicksort, and mergesort would work but would be slow.

+   j. 1 million integers with nonuniform distribution—Countingsort might work if the range of values is limited. Bucketsort might have trouble because the distribution is nonuniform. Heapsort, quicksort, and mergesort would work but would be slow.

# Chapter 7: Searching

+   1. Example program LinearSearch implements the linear search algorithm.

+   2. Example program RecursiveLinearSearch implements the linear search algorithm recursively. If the array holds N items, this method might require N levels of recursion. Some programming languages may be unable to handle depth of recursion, so the nonrecursive version is safer.

+   3. Example program LinkedLinkedList implements the linear search algorithm for a linked list.
