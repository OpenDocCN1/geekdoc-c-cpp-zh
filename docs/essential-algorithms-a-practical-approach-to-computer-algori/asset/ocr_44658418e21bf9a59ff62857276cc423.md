Special-purpose libraries may also be available that can help you with tasks. For example, you may be able to use a network analysis library instead of writing your own network tools. Similarly, database tools may save you a lot of work building trees and sorting times. You may get better performance building your own balanced trees, but using a database is a less work.

If your programming tools include functions that perform the task of one of these algorithms, by means use them. You may get better performance than you could achieve on your own, and you'll have less debugging to do.

Finally, the best algorithm isn't always the fastest for very large problems. If you're sorting a large list of numbers, quicksort usually provides good performance. If you're sorting only three numbers, a simple series of if statements will probably give better performance and will be a lot simpler. Even if quicksort does better performance, does it matter whether the program finishes in 1 millisecond or 2 second? Unless you need to perform the many times, you may be better off with the simpler algorithm that's easier to debug and maintain better than the complicated one to save 1 millisecond.

If you use libraries such as described in the preceding paragraphs, you may not need to code all these algorithms, but it's useful to understand how the algorithms work. You can take better advantage of the tools that implement them if you don't write them. For example, if you know that relational databases use B-trees (or similar trees) to store their indices, you'll have a better understanding of how important pre-allocation and fill factors are. # Summary

To get the most out of an algorithm, you not only need to understand how it works, but you also need to understand its performance characteristics. This chapter explained Big O notation, which you can use to study an algorithm's performance. If you know an algorithm's Big O runtime behavior, you can estimate how much the runtime will change if you change the problem size.
