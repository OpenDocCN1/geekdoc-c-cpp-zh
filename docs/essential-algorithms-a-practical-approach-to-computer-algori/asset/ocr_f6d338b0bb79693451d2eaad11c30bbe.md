# Chapter 5: Stacks and Queues

+   1. When one of the stacks is full, NextIndex1 > NextIndex2. At that point stacks are full, NextIndex1 is the index of the top item in the second stack, and NextIndex2 is the index of the top item in the first stack.

+   2. Simply push each of the items from the original stack to a new one. The following pseudocode shows this algorithm:

Stack: ReverseStack(Stack: values)
Stack: new_stack
While (<values is not empty>)
_stack.Push(values.Pop())
End

Return new_stack
EndReverseStack

+   3. The StackInsertionsort example, which is available for download on the book's website, demonstrates insertionsort with stacks.

+   4. The algorithm doesn't need to move all the unsorted items back onto the original stack, because all it will do with those items is the next one to insert sorted position. Instead, the algorithm could just move the sorted items onto the original stack and use the next unsorted item as the item to insert. This would save some time, but the run time would still be O(N²).

+   5. The fact that stack insertionsort algorithm works means you can train cars with only one holding track the plus output track. You can use the holding track as the second stack, and you can use the output track to store the car that you are currently sorting (or vice versa). This would require more steps than you would if you have more than one holding track, however. Because moving train cars is a lot slower than moving items between stacks on a computer, it would be better to use more holding tracks if possible.

+   6. The StackSelectionsort example program, which is available for download on the book's website, demonstrates selectionsort with stacks.
