# Chapter 6 Sorting

```
values[i] = scratch[i]
Next i
End Mergesort
```

In addition to the array to sort the start and end indices to sort, the algorithm also takes as a parameter scratch array that it uses to merge the sorted halves.

This algorithm starts checking whether the section of the array contains one or fewer items. If it does, it is trivially sorted, the algorithm returns.

If the section of the array contains at least two items, the algorithm calculates the index of the item in the middle of the section of the array and recursively calls itself to sort the two halves.

Next the algorithm merges the sorted halves. It loops through the halves, copying the smaller item from whichever half holds it into the scratch array. When one half is empty, the algorithm copies the remaining items from the other half.

Finally, the algorithm copies the merged items from the scratch array back into the original array.

> NOTE It is possible to merge sorted halves without using a scratch array, but it's more complicated and slower, so most programmers use a scratch array.

The “call tree” shown in Figure 6-11 shows to quicksort when the array are perfectly balanced, so the algorithm divides the items into equal halves at every step. The mergesort algorithm does divide the items into equal halves at every step, so Figure 6-11 applies more to the mergesort algorithm than it does to quicksort.

The run time analysis shown earlier for quicksort also works for mergesort, so this algorithm has O(N log N) run time. Like heapsort, mergesort’s run time does not depend on the initial arrangement of the items, so it always has O(N log N) run time and doesn't have a disastrous worst case like quicksort.

Like quicksort, mergesort is parallelizable. When a call to mergesort calls itself recursively, one can make one of calls on another processor. This requires some coordination, however, because the original call must wait until recursive calls finish before it can merge their results. In contrast, quicksort can simply tell its recursive calls to sort a particular part of the array, and it doesn't need to wait until calls return.

Mergesort is particularly useful when all the data to be sorted isn't in memory once. For example, suppose a program needs to sort 1 million customer records, each of which occupies 1 MB. Loading all that data into memory once would require 10^18 bytes of memory, or 1000 TB, which is much more than most computers have.
