## Queues

A queue is a data structure where items are added and removed in first-in-first-out order. Because of this first-in-first-out (FIFO), usually pronounced "ife-oh" behavior, stacks are sometimes called FIFO lists or FIFOs.

A queue is similar to a store's checkout. You join the end of the line and wait your turn. When you go to the front of the line, the cashier gives you a receipt.

Usually the method that adds an item to a queue is called Enqueue, and the item that removes an item from a queue is called Dequeue.

The following sections describe few of the more common methods for implementing a queue.

## Linked-List Queues

Implementing a queue is easy using a linked list. To make removing the last item from the queue easy, the queue should use a doubly linked list.

The Enqueue method simply adds a new cell to the top of the list, and the Dequeue method removes the bottom cell from the list.

The following pseudocode shows the algorithm for enqueuing an item in a linked-list:

```
Enqueue(Cell: top_sentinel, Data: new_value)
  // Make a cell to hold the new value.
  Cell: new_cell = New Cell
```

```
new_cell.Value = new_value
```

```
// Add the new cell to the linked list.
new_cell.Next = top_sentinel.Next
top_sentinel.Next = new_cell
new_cell.Prev = top_sentinel
```

```
End Enqueue
```

The following pseudocode shows the algorithm for dequeuing an item from a linked-stack:

```
Data: Dequeue(Cell: bottom_sentinel)
// Make sure there is an item to dequeue.
If (bottom_sentinel.Prev == top_sentinel) Then <throw an exception>

// Get the bottom cell's value.
Data: result = bottom_sentinel.Prev.Value

// Remove the bottom cell from the linked list.
bottom_sentinel.Prev = bottom_sentinel.Prev.Prev
bottom_sentinel.Prev.Next = bottom_sentinel

// Return the result.
Return result
```

```
End Dequeue
```

> NOTE See Chapter 3 for more details about using linked lists.

With a linked list, enqueueing and dequeuing items have O(1) run times, both operations are quite fast. The list requires no extra aside from the links between cells, so linked lists are space-efficient.

## Array Queues

Implementing a queue in an array is a bit trickier than implementing one with a linked list. To keep track of the array positions that are used, you can use two variables: Next, to mark the next open position, and Last, to mark the position that has been in the longest. If you simply store items at one end of an array and remove them from the other, however, the occupied spaces move down through the array.

For example, suppose a queue is implemented in an array with eight entries. Consider the following series of enqueue and dequeue operations:

```
Enqueue(M)
Enqueue(O)
Enqueue(V)
Dequeue() // Remove M.
Dequeue() // Remove O.
Enqueue(I)
Enqueue(N)
Enqueue(Q)
Dequeue() // Remove V.
Dequeue() // Remove I.
```

Figure 5-9 shows this sequence of operations. Initially Next and Last refer to the same entry. This indicates that the queue is empty. After the series of Enqueue and Dequeue operations, only two empty spaces are available for adding new items. After that it will be impossible to add new items to the queue.

One approach to solving this problem is to enlarge the array when Next falls off the end of the array. Unfortunately, that would make the array grow bigger over time, and all the space before the Last will be unused.

Another approach would be to move the array's entries to the beginning of the array whenever Last falls off the array. That would work but would be relatively slow.

![](img/fefa42765c0b410af6705110aea7c0cb_148_0.png)

**Figure 5-9:** As you enqueue and dequeue items in an array-based queue, the occupied spaces move down through the array.

A more effective approach is to build a circular array, in which you treat the last item as it was immediately before the first item. When Next falls off the array, it wraps around.

## Specialized Queues

Queues are fairly specialized, but some applications use more specialized queues. Two of these kinds of queues are priority queues and deques.

## Priority Queues

In a priority queue, each item has a priority, and the dequeue method removes the item that has the highest priority. Basically, high-priority items are handled first.

One way to implement a priority queue is to keep the items in the queue sorted by priority. For example, you can use the main concept behind insertionsort to keep the items sorted. When you add a new item to the queue, you search through the queue until you find the position where it belongs, and place it there. To dequeue an item, you simply remove the top from the queue. With this approach, enqueueing an item takes O(N) time, and dequeuing an item takes O(1).

Another approach is to store the items in whatever order they are added to the queue and then have the dequeue method search for the highest-priority item. With this approach, enqueueing an item takes O(1) time, and dequeuing an item takes O(N).

Both of these approaches are reasonably straightforward if you use linked lists. The heap data structure described in the “Heapsort” section of Chapter 6 provides a more efficient way of implementing a priority queue. A heap-based priority queue can enqueue and dequeue items in O(log N) time.

## Deques

Deque, which is usually pronounced “deck,” stands for “double-ended queue.” A deque is a queue that allows you to add items to and remove items from either end of the queue.
