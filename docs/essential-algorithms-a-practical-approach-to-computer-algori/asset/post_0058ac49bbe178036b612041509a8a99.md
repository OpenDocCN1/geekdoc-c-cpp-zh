## Connectivity Testing

The traversal algorithms described in the previous two sections lead to couple other algorithms with only minor modifications. For example, a traversal algorithm visits all the nodes that are reachable from the start node. For an undirected network, that means it visits every node in the network if the network is connected. This leads to the following simple algorithm to determine whether an undirected network is connected:

```
Boolean:IsConnected(Node: start_node)
// Traverse the network starting from start_node.
Traverse(start_node)
```

```
// See if any node has been visited.
For each node In <all nodes>
If (Not.Visited) Then Return False
Next node
```

```
// All nodes were visited, so the network is connected.
Return True
IsConnected
```

This algorithm uses the previous traversal algorithm and then checks node’s Visited property to see if it was visited.
You can extend this algorithm to find all the network’s connected components. Simply use the traversal algorithm repeatedly until you visit all the nodes. The following pseudocode shows an algorithm that uses a depth-first traversal to find the network’s connected components:

```
List(Of List(Of Node)):GetConnectedComponents
// Keep track of the number of nodes visited.
Integer: num_visited = 0;

// Make the result list of lists.
List(Of(Of Node)): components

// Repeat until all nodes are in a connected component.
While (num_visited < <number of nodes>)
// Find a node that hasn't been visited.
Node: start_node = <first node not visited>

// Add the node to the stack.
Stack(Of Node): stack
stack.Push(start_node)
start_node.Visited = True
num_visited = num_visited + 1

// Add the node to a new connected component.
List(Of Node): component
components.Add(component)
component.Add(start_node)

// Process the stack until it's empty.
While (stack isn't empty)
// Get the next node from the stack.
Node: node = stack.Pop()

// Process the node's links.
For Each Link in node.Links
// Use the link only if the destination
// node hasn't been visited.
If (Not link.Nodes[1].Visited) Then
// Mark the node as visited.
link.Nodes[1].Visited = True

// Mark the link as part of the tree.
link.Visited = True
num_visited = num_visited + 1

// Add the node to the current connected component.
component.Add(link.Nodes[1])

// Push the nodes onto the stack.
stack.Push(link.Nodes[1])
End If

Next link
End // While (stack isn't empty)
Loop While (num_visited < <number of nodes>)

// Return the components.
Return components

End GetConnectedComponents
```

This algorithm returns a list of lists, each holding the nodes in a connected component. It starts by making the variable num_visited to keep track of how many nodes have visited. It then makes the list of lists it will return. The algorithm then enters a loop that continues as long as it has not visited every node. Inside the loop the program finds a node that has not been visited, adds it to a stack, and also adds to a new list of nodes. The algorithm then enters a loop similar to the one traversal algorithm used to process the stack until it is empty. The only real difference is that this algorithm adds the nodes it visits to the list it is currently building in addition to adding them to the stack. When the stack is empty, the algorithm has visited all the nodes that connected to the start node.

## Spanning Trees

If undirected network is connected, you can make a tree rooted at any node, showing a path from the root node to every other node. This tree is called a spanning tree because it spans all the nodes in the network. For example, Figure 13-5 shows a spanning tree rooted at node H. If you use the links, you can trace a path from the root node to any other node. For example, the path to node M visits nodes H, C, A, F, K, L, and M.

Figure 13-5: A spanning tree connects all the nodes in a network

The traversal algorithms described earlier actually find spanning trees but they don't record which were used. To modify the previous algorithms to record the links, simply add the following lines after the statement that makes a new node visited:

```
// Mark the link as part of the spanning tree.
link.Visited = True
```

Basically the algorithm starts with the root node in the spanning tree. At each step, it picks another node that is adjacent to the tree and adds it to the tree. The new algorithm records which links were used to connect the nodes to the spanning tree.

## Minimal Spanning Trees

The spanning tree algorithm described in the preceding section lets you use any node in the network as root of spanning tree, so many spanning trees are possible. A spanning tree that has the least possible cost is called a spanning tree. Note that a network may have more than one minimal tree. In fact, if all the links in the network have the same cost, every spanning tree is a minimal tree.

The following steps describe a simple high-level algorithm for finding a minimal tree with root R:

1. Add the root node R to the initial spanning tree.
2. Repeat until every node is in the spanning tree:
   a. Find a least-cost link that connects a node in the spanning tree that is not yet in the tree.
   b. Add that link's destination node to the spanning tree.

The algorithm is greedy because at each step it selects a link that has the least cost. By making the best choices locally, it achieves the best solution globally.

For example, consider the network shown on the left in Figure 13-6, and suppose the links and nodes are part of a growing spanning tree rooted at node A. In step 2a, you examine the links that connect nodes in the tree that are not yet in the tree. In this example, those links have costs 15, 10, 12, and 11. Using the greedy algorithm, you add the least-cost link, which has cost 10, to get the tree on the right.

The most time-consuming step in this algorithm is step 2a, finding the next link to add to the tree. How much this step depends on the approach you use.

![](img/fefa42765c0b410af6705110aea7cb_362_0.png)

**Figure 13-6:** At each step, you add to the spanning tree the least-cost link that connects a node to a tree that is not in the tree.

One way to find a least-cost link is to loop through the tree's nodes, examining links to find one that connects to a node outside the tree and that has minimum cost. This is fairly time-consuming, because the algorithm must examine the links of the tree's nodes many times, even if they lead to nodes that are already in the tree.

A better approach is to keep a list of candidate links. When the algorithm adds a node to the growing spanning tree, it also adds any links from node to a node outside the tree to the candidate list. To find a minimal link, the algorithm looks through the list for the smallest link. As it searches the list, if it finds a link that leads to another node that is already in the tree (because node was added to the tree after the link was added to the candidate list), the algorithm removes it from the list. That way, the algorithm doesn't need to consider the link again later. When the candidate list is empty, the algorithm is done.
