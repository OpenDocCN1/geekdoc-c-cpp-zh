Circular linked lists can be useful when you need to loop through a sequence of items indefinitely. For example, an operating system might repeatedly loop through a list of processes to give each a chance to execute. If a new process started, it could be added anywhere in the list, right after the sentinel so that it would have a chance to execute right away.

As another example, a game might loop indefinitely through a list of objects, allowing each to move on the screen. Again, new objects could be added anywhere to the list.

The kind of linked list shown in Figure 3-10 is interesting mostly because it presents you with two interesting problems. First, how can you tell whether a linked list contains such a loop? Second, if a linked list contains such a loop, how can you find where the loop starts and break it to “fix” the list? This is roughly the same question as asking where “bottom” of the list is. In Figure 3-10, you might define the bottom of the list to be cell I because it is the last cell visit while traversing the list before cells repeating.

The following sections describe some of the most interesting algorithms that answer these questions.

# Marking Cells

Probably the easiest way to tell if a linked list has a loop is to traverse its cells, marking each as you visit. If you come to a cell that is already marked, you know that the list has a loop and it starts at that point.
