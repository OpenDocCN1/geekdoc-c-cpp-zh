# Optimization ≤ Reporting

The final step is showing that the three kinds of problems have the same complexity is showing that Optimization ₘ Reporting. Suppose you have a reporting algorithm Report(k). Then the algorithm can call Report(k), Report(k+1), Report(k+2), and so on until it finds a solution. (If the problem also allows solutions of the form Report(k-1), try those.)

For a specific example, suppose ReportSum(k) returns a subset with total value k if one exists. The following steps describe an algorithm for OptimizeSum(k):

+   1. For 0 To N, where N is the number of items in the set:
   a. If ReportSum(k + i) returns a subset, OptimizeSum should return that.
   b. If ReportSum(k - i) returns a subset, OptimizeSum should return that subset.
   c. Continue the loop in Step 1.

These reductions show Detection ₘ Reporting ₘ Optimization and Optimization ₘ Reporting ₘ Detection, so the problems all have the same complexity.

# NP-Complete Problems

More than 3,000 NP-complete problems have been discovered, so the following list is only a very small subset of them. They are listed here to give you an idea of some kinds of problems that are NP-complete.

Remember that NP-complete problems have no known polynomial time solution, these are all considered very hard problems. Many can only be solved for very small sizes.

Because these problems are all NP-complete, there is a way to reduce each of them to another problem:

+   * Art gallery problem—Given an arrangement of rooms and hallways in an art gallery, find the minimum number of guards needed to watch the entire gallery.
* Bin-packing—Given a set of objects and a series of bins, find a way to pack the objects into the bins to use the finest bins possible.
* Bottleneck traveling salesman problem—Find a Hamiltonian path through a weighted network that has the minimum possible largest weight.
* Chinese postman problem (or route inspection problem)—Given a network, find the shortest cut that visits every link.
