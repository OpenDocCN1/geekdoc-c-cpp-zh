# An RSA Example

First, consider an example of picking the public and private keys:

+   1. Pick two large prime numbers p and q.
For this example, let p = 17 and q = 29. In a real application, these values should be much larger, such as 128-bit numbers written in binary, so they would have an order of magnitude about $1\times10^{38}$.
2. Compute n = p \cdot q. Release this as the public modulus.
The public modulus n is $p \cdot q = 493$.
3. Compute $\phi(n)$ where $\phi$ is Euler's function.
The value $\phi(n) = (p-1)(q-1) = 16 \cdot 28 = 448$.
4. Pick an integer e where $1 \le e \le \phi(n)$ and e are relatively prime.
For this example, you need to pick e where $1 \le e \le 448$ and 448 are relatively prime. The prime factorization of 448 is $2^6 \cdot 7$, so it cannot include the factors 2 or 7. For this example, let $e = 3 \cdot 5 \cdot 11 = 165$.
5. Find d, the multiplicative inverse of e modulo $\phi(n)$. In other words, $d-1 \equiv e \pmod{\phi(n)}$.
For this example, you find the multiplicative inverse of 165 modulo 448. In this example, find d that $d \cdot 165 \equiv 1 \pmod{448}$. (Example program MultiplicativeInverse, which is included in the 29-downloads for this chapter, exhaustively finds inverses such as this. It tried values until it discovered 429.)

So the exponent e = 165, the modulus n = 493, and the secret d = 429.
Suppose you want to encrypt the message value 321. The encrypted value $C = M^e \pmod{n}$ The ExponentiateMod program, which is available for download on the book's website as part of Chapter 2'sExercise1, calculates large exponentials quickly. That program calculates $321^{165} \equiv 359 \pmod{493}$, so the encrypted value is 359.
To decrypt $359^{429}$, the receiver calculates $C^d \pmod{n}$. For this example, that's $359^{429} \equiv 321 \pmod{493}$. The ExponentiateMod program from Chapter 2 calculates $359^{429} \equiv 321 \pmod{493}$, so the decrypted message is 321 as it should be.

# Practical Considerations

Generating good keys and calculating big exponents can take some time if you use fast modular exponentiation. Remember that p and q are large numbers, so using private-key cryptography to encrypt a long message in blocks small enough to be represented as numbers could take quite a while.
