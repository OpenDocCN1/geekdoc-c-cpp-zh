The user moves next, so the computer doesn't need to make again until two moves have been made. The size of the game tree at that point depends on the particular moves made, but the tree will be much smaller than the original game tree. For example, the entire tic-tac-toe game tree contains 255,168 possible games. If X picks the upper-left square and O picks the upper-middle square, the remaining game tree contains only 3,668 possible games. That may still be too many to enumerate by hand, but it's a very small tree for a computer to search.

If the user moves first, the first game also shrinks dramatically. If the user picks the upper-left square for the first move, the remaining game tree contains only 27,732 possible games. This is a lot more than the number of games after the second move, but it's a lot smaller than the entire game tree. With one additional change, you can make that even smaller.

X has only nine choices for a first move. If you precalculate all those moves, you can make the program look up the appropriate response. Instead of searching a game tree containing 27,732 possible games, the program only needs to look up a response.

The user moves again, so the program doesn't need to search the game tree until three moves have been made—one by the user, a precalculated response, and by the user. At that point the game tree is much smaller. For example, if X takes the upper-left square, O takes the upper-middle square, and X takes the upper-right square, the remaining game tree contains only 592 possible games. That's actually small enough that could search the tree if you wanted to.

In a more complicated game like chess, the game tree is infinitely large for practical purposes, trimming the top few levels of the tree won't help as much. Skipping three moves might reduce the number of possible games from around $1.2 \times 10^9$ to roughly $4.5 \times 10^{54}$, that's still too much to big search completely.

Using precalculated moves and responses does let chess program make its first few moves quickly, however. It also lets you spend lots of studying openings where you can invest extra in planning those moves. It lets the program avoid openings that would give it a bit initial disadvantage.

# Game Tree Heuristics

The game trees for all but the simplest games are too big to search completely, so in general there's no way to know if a particular move will lead to a better solution than another. Although you can't always know for certain that a particular move will be beneficial, sometimes you can use a heuristic to indicate a move's value.
