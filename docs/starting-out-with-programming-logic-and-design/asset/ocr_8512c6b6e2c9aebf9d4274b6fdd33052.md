The flowchart in Figure 7-1 reads input in two places: first just before the loop and inside the loop. The first input operation—just before the loop—is called a priming read, and its purpose is to get the first value that will be tested by the validation loop. If value is invalid, the loop will perform subsequent input operations.

Let's consider an example. Suppose you are designing a program that reads a test score and want to make sure the user does not enter a value less than 0. The following pseudocode shows how you can use an input validation loop to reject any input value that is less than 0.

```
// Get a test score.
Display "Enter a test score."
Input score

// Make sure it is not less than 0.
While score < 0
  Display "ERROR: The score cannot be less than 0."
  Display "Enter the correct score."
  Input score
End
```

This pseudocode primes the user to enter a test score (this is the priming read), and then the loop executes. Recall from Chapter 5 that the While is a test loop, which means it tests the expression score < 0 before performing an iteration. If the user enters a valid test score, the expression is false, however, the expression will be true and the statements in the body of the loop will execute. The loop displays an error message and prompts the user to enter the correct test score. The loop will continue to iterate until the user enters a valid score.
