If you are developing software in an operating system that uses a GUI, such as Windows, Mac OS X, or Linux, you can also use the GUI in the programs that you write. This allows you to incorporate standard GUI elements such as dialog boxes with icons, buttons, and so on into your programs.

# GUI Programs Are Event-Driven

In a text-based environment, as a command line interface, programs determine the order in which things happen. For example, consider a program that calculates the area of a rectangle. The first program prompts the user to enter the rectangle's width. The user enters the width and the program prompts the user to enter the rectangle's length. The user enters the length and then the program calculates the area. The user has no choice but to enter the data in the order that is requested.

In a GUI environment, however, the user determines the order in which things happen. For example, 15-3 shows a GUI program that calculates the area of a rectangle. The user can enter the width and length in any order he or she wishes. If a mistake is made, the user can erase the data that was entered and retry it. When the user is ready to calculate the area, he or she clicks Calculate Area and the program performs the calculation. Because GUI programs must respond to the actions of the user, it is said that they are *event-driven*. The user causes events to take place, such as the clicking of a button, the program must respond to the events.

# Creating a GUI Program

Many of the steps in creating a GUI program are the same as those you have used to create text-based programs throughout this book. For example, you must understand the task that the program is to perform and determine the steps that must be taken to perform the task.

In addition, you must design the on-screen GUI elements that make up each window in the program's interface.
