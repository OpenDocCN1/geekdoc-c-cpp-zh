# Avoiding Stale Data

In the ServiceQuote class, the getPartsCharges and getLaborCharges methods return the values stored in fields, but the getSalesTax and getTotalCharges methods return the results of calculations. You might be wondering why the sales tax and the total charges are not stored in fields, like the parts and labor charges. These values are not stored in fields because they could become stale. The value of an item is dependent on other data and that item is not updated when the other data is changed, so that the item would become stale. If the sales tax and total charges were stored in fields, the values of those fields would become incorrect as soon as the partsCharges or laborCharges changed.

When designing a class, you should take care not to store in a field any calculated data that can potentially become stale. Instead, provide a method that returns the result of the calculation.

# Generalization and Specialization

In the real world, you can find many objects that are specialized versions of other more general objects. For example, the term *insect* describes a very general type of creature with numerous characteristics. Because grasshoppers and bumblebees are insects, they all have the general characteristics of an insect. In addition, they have special characteristics of their own.
