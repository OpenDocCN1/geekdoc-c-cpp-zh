Program 2-13 shows another example. This program declares a total of four variables: three to hold test scores and another to hold the average of those test scores.

# Program 2-13

```
1 Declare Real test1
2 Declare Real test2
3 Declare Real test3
4 Declare Real average
5
6 Set test1 = 88.0
7 Set test2 = 92.5
8 Set test3 = 97.0
9 Set average = (test1 + test2 + test3) / 3
10 Display Your test score is , average
```

# Program Output

Your average test score is 92.5

This program shows a common technique for declaring variables: they are all declared at the beginning of the program, before any other statements. This is one way of making that all variables are declared before they are used.

Note that line 5 in this program is blank. This blank line does not affect the program works because most compilers and interpreters ignore blank lines. For the human reader, this blank line visually separates the variable declarations from the other statements. This makes the program more organized and easier for people to read.

Programmers commonly use blank lines and indentations in their code to create a sense of organization. This is similar to the way that authors arrange the text on the pages of a book. Instead of writing each chapter as one long series of sentences, they break it into paragraphs. This does not change the information in the book; it only makes it easier to read.

Although you are generally free to place blank lines and indentations in your code, you should not do so haphazardly. Programmers follow certain conventions when it comes to this. For example, you have just learned that one convention is to use a blank line to separate a group of variable declaration statements from the rest of the statements in a program. These conventions are known as programming style. As you progress through this book you will see many other programming style conventions.
