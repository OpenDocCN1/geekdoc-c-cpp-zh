## Programming Style and Nested Decision Structures

For debugging, it's important to use proper alignment and indentation in a nested decision structure. This makes it easier to see which actions are performed by each part of the structure. For example, in most languages the following pseudocode is functionally equivalent to lines 14 through 24 in Program 4-5. Although this pseudocode is logically correct, it would be very difficult to debug if it is not properly indented.

```
If salary >= 30000 Then
  If yearsOnJob >= 2 Then
    Display You qualify for the loan.
  Else
    Display "You must have been on your current"
    Display "job for at least two years to qualify."
  End
```

> Don't write pseudocode like this!

## The If-Then-Else If

Even though Program 4-6 is a simple example, the logic of the nested decision structure is fairly complex. Most languages provide a special version of the decision structure known as the If-Then-Else statement, which makes this type of logic simpler. In pseudocode we will write the If-Then-Else statement using the following format:

```
If condition_1 Then
    statement
    etc.
Else condition_2 Then
    statement
    etc.
Insert as many Else If as necessary
Else
    statement
    etc.
End If
```

When the statement executes, condition_1 is true. If condition_1 is true, the statements immediately follow are executed, up to the Else If. The rest of the structure is ignored. If condition_1 is false, however, the program jumps to the next Else If and tests condition_2. If it is, the statements immediately follow are executed, up to the Else clause. The rest of the structure is ignored. This process continues until a condition is found to be true, or no more Else clauses are left. If none of the conditions are true, the statements following the Else clause are executed.

The pseudocode in Program 4-7 shows an example of the If-Then-Else statement. This program works the same as Program 4-6. Instead of using a nested decision structure, this program uses the If-Then-Else statement in lines 9 through 19.

## Program 4-7

```
// Variable to hold the test score
Declare Real score

// Get the test score.
Display "Enter your test score."
Input score

// Determine the grade.
If score < 60 Then
    Display "Your grade is F."
Else If score < 70 Then
    Display "Your grade is D."
Else If score < 80 Then
    Display "Your grade is C."
Else If score < 90 Then
    Display "Your grade is B."
Else
    Display "Your grade is A."
End If
```

> Notice the alignment and indentation that are used with the If-Then-Else If statement: The If, Else If, Else, and End If are all aligned, and the conditionally executed statements are indented.

> You have to use the If-Then-Else If statement because its logic can be coded with nested If-Then-Else statements. However, a long series of nested If-Then-Else statements has two particular disadvantages when you are debugging code:

- The code can grow complex and become difficult to understand.
- Because indenting is important in nested statements, a long series of nested If-Else statements can become too long to be displayed on the computer screen without horizontal scrolling. Also, statements tend to "wrap around" on paper, making the code even difficult to read.

The logic of an If-Then-Else statement is usually easier to follow than a long series of nested If-Then-Else statements. And, because all of the clauses are aligned in an If-Then-Else statement, the length of the lines in the statement tend to be shorter.

## The Case Structure

**CONCEPT:** the case structure lets the value of a variable or an expression determine which path of execution the program will take.

The case structure is a multiple alternative decision structure. It allows you to test the value of a variable or an expression and then use value to determine which statement or set of statements executes. In many situations, case structures accomplish the same thing as nested If-Then statements, but with simpler and more straightforward code. Figure 4-18 shows an example of how a case structure looks in a flowchart.

In the flowchart, the diamond symbol contains the name of a variable. If the variable contains the value 1 the statement Display "January" is executed. If the variable contains the value 2 the statement Display "February" is executed. If the variable contains the value 3 the statement Display "March" is executed. If the variable contains none of these values, the statement labeled Default is executed. In this case, the statement Display "Error: Invalid month" is executed.
