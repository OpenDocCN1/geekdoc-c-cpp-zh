The flowchart in Figure 7-1 reads input in two places: first just before the loop and inside the loop. The first input operation—just before the loop—is called a priming read, and its purpose is to get the first value that will be tested by the validation loop. If value is invalid, the loop will perform subsequent input operations.

Let's consider an example. Suppose you are designing a program that reads a test score and want to make sure the user does not enter a value less than 0. The following pseudocode shows how you can use an input validation loop to reject any input value that is less than 0.

```
// Get a test score.
Display "Enter a test score."
Input score

// Make sure it is not less than 0.
While score < 0
  Display "ERROR: The score cannot be less than 0."
  Display "Enter the correct score."
  Input score
End
```

This pseudocode primes the user to enter a test score (this is the priming read), and then the loop executes. Recall from Chapter 5 that the While is a test loop, which means it tests the expression score < 0 before performing an iteration. If the user enters a valid test score, the expression is false, however, the expression will be true and the statements in the body of the loop will execute. The loop displays an error message and prompts the user to enter the correct test score. The loop will continue to iterate until the user enters a valid score.

The loop in this pseudocode determines whether score is less than 0 or greater than 100. If either is true, an error message is displayed and the program is prompted to enter a correct score.

> NOTE: This pseudocode used the OR operator to determine whether score was outside the range. Think about what would happen if the Boolean expression used instead
score < 0 AND score > 100

This expression would never be true because it is impossible for a number to be less than 0 AND greater than 100!

# Validation Functions

Validation functions are used to encapsulate the validation logic into a reusable function. This makes the main program cleaner and easier to maintain. A validation function typically returns a Boolean value: true if the input is valid, and false if it is not.

The following example shows a function that validates whether a test score is between 0 and 100.

```
Function Boolean isValid(Integer score)
  // Local variable to hold True or False
  Declare Boolean status

  If score >= 0 AND score <= 100
    Set status = true
  Else
    Set status = false
  End If

  // Return the status
  Return status
End Function
```

To use this function in a loop, the code would look like this:

```
Display "Enter a test score."
Input score
While NOT isValid(score)
  Display "ERROR: The score must be between 0 and 100."
  Display "Enter the correct score."
  Input score
End While
```

By using validation functions, you can handle complex validation logic without cluttering the main loop.

# Validating String Input

Validating strings can be more complex than validating numbers because you may need to check for specific patterns, lengths, or even allowed characters. The following example shows a validation function that takes a string as an argument and returns whether it is valid.

```
Function Boolean isValidString(String answer)
  // Local variable to hold True or False
  Declare Boolean status

  If answer = "yes" OR answer = "no"
    Set status = true
  Else
    Set status = false
  End If

  // Return the status
  Return status
End Function
```

To use this function in a loop, the code would look like this:

```
Display "Do you have another item? (yes or no) "
Input answer
While NOT isValidString(answer)
  Display "ERROR: Please enter yes or no."
  Input answer
End While
```
