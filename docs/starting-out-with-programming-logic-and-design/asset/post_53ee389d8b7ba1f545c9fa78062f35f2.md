## Refining the List of Nouns

The nouns in the problem description are merely candidates to become classes. It might not be necessary to make classes for all of them. The next step is to refine the list only the classes that are necessary to solve the particular problem at hand. We will look at the common reasons that a noun can be eliminated from the list of potential classes.

1. Some of the nouns really mean the same thing:

In this example, the following sets of nouns refer to the same thing:

TIP: Some object-oriented designers note whether a noun is plural or singular. Sometimes a plural noun will indicate a class and a singular noun will indicate an object.

4. Some of the nouns represent simple values that can be stored in a variable and do not require a class. Remember, a class contains fields and methods. Fields are items that are stored within an object and define its state. Methods are actions or behaviors that may be performed. If a noun has any fields or methods, it can probably be eliminated from the list. To help determine whether a noun has fields and methods, ask the following:

- Would you use a group of related values to represent the item's state?
- Are there any obvious actions to be performed by the item?

If the answers to both of these questions are no, then the noun represents a value that can be stored in a variable. If we apply this test to each of the nouns in our list, we can conclude that the following are not classes: *address, estimated labor charges, estimated parts charges, make, model, name, sales tax, telephone number, total charges, and year*. ### Determining Class Responsibilities

In the Spotlight section, we examined the problem domain description for the Joe's Automotive Shop program. We also identified the classes that we need, which are *Car, Customer,* and *ServiceQuote*. The next step is to determine those classes' responsibilities. A class' responsibilities are as follows:

- The things that a class is responsible for knowing
- The actions that a class is responsible for doing

When you have identified the things that a class is responsible for knowing, then you have identified the values that will be stored in fields. Likewise, when you have identified the actions that a class is responsible for doing, you have identified its methods.
