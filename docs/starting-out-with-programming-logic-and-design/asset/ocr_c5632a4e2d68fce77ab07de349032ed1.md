So, a class is not an object, but it can be a description of an object. When the program is running, it can use the class to create, in memory, as many objects of a specific type as needed. Each object that is created from a class is called an instance of the class.

For example, Jessica is an entomologist (someone who studies insects) and also enjoys writing computer programs. She designs a program to catalog different types of insects. As part of the program, she creates a class named Insect, which specifies fields and methods for handling and manipulating data common to all types of insects. The Insect class is not an object, but a specification that may create a firstly object, which is an instance of the Insect class. The firstly object occupies computer memory and stores data about a household. It has the fields and methods specified by the Insect class. Then she writes a mosquito object. The mosquito object is also an instance of the Insect class. Although the firstly and mosquito objects are separate entities in the computer, they were both created from the Insect class. This means that each of the objects has the fields and methods described by the Insect class. This is illustrated in Figure 14-5.
