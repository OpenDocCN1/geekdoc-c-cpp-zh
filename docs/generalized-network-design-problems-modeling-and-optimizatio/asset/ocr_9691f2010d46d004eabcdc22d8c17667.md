In this model, the constraints (7.1) ensure that two commodities k of flow f are produced in the root cluster V1, preserved in any other cluster they are not assigned and consumed by cluster Vk. In order to achieve the edge-biconnectivity, the constraints (7.2) forbid the transportation of two commodities assigned for the same cluster over the same connection. Constraints (7.3) guarantee that from each cluster we select exactly one node, restrictions (7.4) force us to select only edges between nodes belonging to the clusters which are connected in the global structure, and the inequalities (7.5) ensure that only edges incident to selected nodes are chosen. The valid global structure is obtained by inequalities (7.6), which ensure global connections to be included in the solution if a flow is active on it. Finally, the restrictions (7.7) and (7.8) are the integrality constraints.

# 7.3 Solving the GMEBCNP

Despite the importance of the GMEBCNP in the real world, especially in applications to the design of backbones in large communication networks, not much research on the problem has been done. Huygens [84] provided integer programming formulations of the problem, along with facet defining inequalities and as far as we know, only one specific algorithm has been developed for solving the GMEBCNP, namely, the improved Variable Neighborhood Search (VNS) approach [82], in which several variants are proposed, which we will describe in this section.

The variable neighborhood search (VNS) is a metaheuristic, introduced by Mladenovic [124] for solving combinatorial and global optimization problems. Its basic idea is to systematically change the neighborhood within the local search. The VNS had a very rapid development, with a dozen of papers being published on this topic. For a survey on VNS, and its extensions and applications, we refer to [70, 71, 125].

Hu et al. [82] proposed four types of neighborhoods, focusing on different aspects of the GMEBCNP. In order to create an initial solution of good quality, they considered an adaptation of the Christofides heuristic. It starts with building a solution of the generalized minimum spanning tree problem (GMSTP), using an Kruskal based heuristic. Next, the generalized spanning tree is augmented until it becomes a feasible solution of the GMEBCNP.
