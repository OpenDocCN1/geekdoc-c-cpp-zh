
The observations presented so far lead to our final formulation, called the *local-global formulation* of the GFCND problem as an 0-1 mixed integer programming problem:

```
min \sum_{e \in E} c_e x_e + \sum_{d \in D, a \in A} g_a b_d f_a^d
s.t.
z(V_k) = 1, \quad \forall k \in \{1, \dots, m\},
\sum_{a_s \in \delta^+(i)} F_{a_s}^d - \sum_{a_s \in \delta^-(i)} F_{a_s}^d = \left\{\begin{array}{ c c }
1, & i \in s_{gd} \\
-1, & i \in t_{gd} \\
0 & \text{otherwise}
\end{array}\right. \quad \forall d \in D, i \in V_g
F_{ij}^d + F_{ji}^d \le y_{eg}, \quad \forall e_g = (i, j) \in E_g, d \in D
F_{a_s}^d = \sum_{\{a \in (i, j) \in A | i \in V_k, j \in V_l\}} f_a^d, \quad \forall a_g = (k, l) \in A_g
x(V_l, V_r) = y_{lr}, \quad \forall l, r \in K = \{1, \dots, m\}, l \neq r \tag{6.13}
x(i, V_r) \le z_i, \quad \forall r \in K, \forall i \in V \backslash V_r \tag{6.14}
f_a^d \ge 0, \quad \forall a = (i, j) \in A, d \in D
x, z, y \in \{0, 1\}.
```

The integrality restriction on the decision variables z can be relaxed and replaced by the restrictions z_i \ge 0, i \in V. Obviously, if the decision variables x, y \in \{0, 1\} then restrictions (6.13) and (6.14) imply that z \in \{0, 1\}.

We observe as well that the local-global model of the GFCND problem has a polynomial number of restrictions and variables, and the number of integer decision variables is less compared to the other MIP models of the problem.

## 6.3 Solving the GFCNDP

Despite the importance of the GFCND problem in network design not much research on the problem has been done. As far as we know, only two approaches have been developed in order to solve the GFCND problem, a branch-cut-and-price algorithm proposed by Thomadsen and Stidsen [200] and a solution procedure based on the local-global formulation of the problem developed by Pop and Pop Sitar [160].

Due to the substantial number of decision variables and constraints that occur in the bidirectional flow formulation of the GFCNDP, Thomadsen and Stidsen [200] described a branch-cut-and-price algorithm that takes advantage of the fact that only few non-zero variables and few binding constraints exist.

The most widely used method for solving MIPs, however, is the branch-and-cut algorithm, employed by most state-of-the-art MIP solvers. Although the user can extend the existing branch-and-cut solvers by adding problem specific plugins, these solvers feature very effective generic algorithms, which can be used to solve many general MIPs without further problem knowledge.

Nowadays, branch-and-price is a well-established method to solve huge and extremely difficult combinatorial optimization problems. Its success relies on exploiting structures contained in the problem with use of a decomposition and being able to solve the occurring pricing problems rather efficiently with problem specific algorithms. Several general acceleration strategies for the branch-and-price process were proposed [22, 116].

Branch-cut-and-price is a combination of branch-and-price and branch-and-cut. The variables are given implicitly and added to the problem only when needed. Additionally, cutting planes are added to the problem during the solving process, in order to strengthen the LP relaxation. Variables and cutting planes are created alternately.

The branch-and-cut-and-price algorithm proposed by Thomadsen and Stidsen [200] is specified next.

```
**Algorithm 6.2** (The branch-cut-and-price algorithm for solving the GFCNDP (Thomadsen and Stidsen [200])).
1 VARS = initial set of variables
2 CONS = initial set of constraints
3 BRANCHES = set consisting of an initial branch
4 INCUMBENT = +∞
5 do
6   Select and remove BRANCH ∈ BRANCHES
7   do
8     LP-lowerbound = SOLVE LP (CONS, VARS, BRANCH)
9     Add variables with negative reduced cost to VARS
10    Add violated constraints to CONS
11  while variables or constraints added
12  if LP solution is integer and LP-lowerbound < INCUMBENT:
13    Update incumbent: INCUMBENT = LP-lowerbound
14    Fathom
15  else if LP-lowerbound ≥ INCUMBENT:
16    Fathom
17  else
18    Select branching variable v
19    Add the two branchings v = 1 and v = 0 to BRANCHES
20 while BRANCHES ≠ ∅
```

## 6.4 Computational results

In order to solve the GFCND problem with the branch-cut-and-price algorithm, Thomadsen and Stidsen [200] generated test instances with 50–300 nodes, in steps of 25 nodes and with 10–30 clusters, in steps of 10 clusters.

Each test instance consists of a number of nodes located randomly in the unit square [0, 1] × [0, 1]. The clusters were created in the same way as in [43], using the procedure called CLUSTERING, and is described in the following. This procedure sets the number of clusters m = [k/4], identifies the m farthest nodes from each other, and assigns each remaining node to its nearest center. Obviously, some real-world problems may have different cluster structures. However, the solution proposed in this paper is able to handle any cluster structure.

The costs of the edges ce, e = (i, j) ∈ E were set equal to the Euclidean distance between the nodes i and j and for each pair of clusters Vk and Vl, k, l ∈ {1, ..., m} a demand d is defined. The value of the communication demand, bd, is set equal to a uniformly distributed random variable between 0 and 20 times the product of the number of nodes in each of the two clusters.
