## Transformation of the RTSP to the symmetric TSP

Since the previous transformation results in an asymmetric TSP, Hu et al. [78] proposed an alternative procedure for generating a symmetric TSP, defined on the graph $G' = (V', E')$. Their approach follows the same basic ideas as the previous transformation with the observation that the number of nodes must be doubled during the process.

Let $a'_1, ..., a'_k \in \sigma'$ again be exact copies of the arrival-nodes $a_1, ..., a_k \in \sigma$, ordered according to their arrival times. These nodes are duplicated once more, thus producing the nodes $a''_1, ..., a''_k$. Then, these nodes are connected to a cycle by edges $(a'_2, a''_1), (a'_3, a''_2), ..., (a'_k, a''_{k-1}), (a'_1, a''_k)$ with zero costs and the edges $(a'_i, a''_i), i = 1, ..., k$ with high costs $M$. High costs on edges $(a'_i, a''_i)$ cause few of them as possible to be present in the solution.

For example, in Figure 4.6, when a travel-edge leads to $a_1$ there are two possible routes to go through $(a'_1, a'_2, a'_3) \cup \{a''_1, a''_2, a''_3\}$, one ending in $a''_3$ and one ending at $a'_1$. The latter one is cheaper, since the edge $(a'_1, a''_1)$ with high costs is ignored.

The same procedure is applied to the nodes $d'_1, ..., d'_l$ and their duplicates $d''_1, ..., d''_l$. Then, all nodes $a''_i, i = 1, ..., k$ are connected to nodes $d''_j, j = 1, ..., l$ and the cost of the edges $(a''_i, d''_j)$ are set to

$c(a''_i, d''_j) = [1440 + t_{d'_j} - t_{a''_i} - f_B(\sigma)] \mod 1440 + f_B(\sigma)$.

Similar to the previous transformation, the costs of the original stay-edges are implicitly included in these edges.

Finally, for each original travel-edge $(d_j, v)$ a new edge $(d''_j, v)$ is added, with the cost given by

$c(d''_j, v) = c(d_j, v) + M'$.

Since \(M\) was already used by edges \((a'_i, a''_i)\) and \((d'_j, d''_j)\) inside \(\sigma'\), an even larger value for \(M'\) was chosen, to ensure that only one travel-edge is included in the solution on \(G'\), namely \(M' = M \cdot |B|\).

### Computational results

In order to test the proposed TSP transformation schemes, the authors used instances based on two railway timetables, containing real-world data of train schedules in the Netherlands. The instance \(nd\_loc\) contains 23 cities and represent trains in a local region and the instance \(nd\_ic\) contains 21 larger cities in the Netherlands, which are connected by Intercity trains.

The requirements for the traveling salesman were generated at random. They were created by letting the salesman visit either 5 or 10 cities, and staying times were chosen between 10 and 240 minutes at each location. Since [46, 92] also used randomly generated data for the salesman with the same number of cities to be visited, the results should be at least roughly comparable. However, the staying times were not mentioned.

The time-expanded digraph, based on both timetables, contains more than 2000 nodes and around 4000 edges (depending on the traveling person). After reducing the graph, the transformation procedure for generating a symmetric TSP instance was carried out, and it was solved with the branch-and-cut (B&C) algorithm from the Concorde library.

## 4.3.4 An ant-based heuristic for solving the RTSP

Due to the complexity of the RTSP, the problem cannot be solved by means of exact methods, within polynomially bounded computation times. Nevertheless, sub-optimal solutions are sometimes easy to find. Consequently, it seems reasonable to focus on metaheuristic algorithms, that can find near optimal solutions within a reasonable running time. Such an approach, based on ant colony optimization, was described by Pop et al. [156].

### The ant colony algorithm for solving the RTSP

In [137], Pineo et al. proposed a new algorithm, based on the Ant Colony System, called the Reinforcing Ant Colony System (RACS), in order to solve the Generalized Traveling Salesman Problem.

For solving the RTSP, the RACS algorithm must be changed, following the characteristics of the railway problem. The salesman starts from a specific station (cluster), has to visit a given number of stations (cities), spends a minimum amount of time in each station, and must finally return to the starting station.
