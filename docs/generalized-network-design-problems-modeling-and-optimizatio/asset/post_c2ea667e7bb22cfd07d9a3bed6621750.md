

In this model, the constraints (7.1) ensure that two commodities k of flow f are produced in the root cluster V1, preserved in any other cluster they are not assigned and consumed by cluster Vk. In order to achieve the edge-biconnectivity, the constraints (7.2) forbid the transportation of two commodities assigned for the same cluster over the same connection. Constraints (7.3) guarantee that from each cluster we select exactly one node, restrictions (7.4) force us to select only edges between nodes belonging to the clusters which are connected in the global structure, and the inequalities (7.5) ensure that only edges incident to selected nodes are chosen. The valid global structure is obtained by inequalities (7.6), which ensure global connections to be included in the solution if a flow is active on it. Finally, the restrictions (7.7) and (7.8) are the integrality constraints.

## 7.3 Solving the GMEBCNP

Despite the importance of the GMEBCNP in the real world, especially in applications to the design of backbones in large communication networks, not much research on the problem has been done. Huygens [84] provided integer programming formulations of the problem, along with facet defining inequalities and as far as we know, only one specific algorithm has been developed for solving the GMEBCNP, namely, the improved Variable Neighborhood Search (VNS) approach [82], in which several variants are proposed, which we will describe in this section.

The variable neighborhood search (VNS) is a metaheuristic, introduced by Mladenovic [124] for solving combinatorial and global optimization problems. Its basic idea is to systematically change the neighborhood within the local search. The VNS had a very rapid development, with a dozen of papers being published on this topic. For a survey on VNS, and its extensions and applications, we refer to [70, 71, 125].

Hu et al. [82] proposed four types of neighborhoods, focusing on different aspects of the GMEBCNP. In order to create an initial solution of good quality, they considered an adaptation of the Christofides heuristic. It starts with building a solution of the generalized minimum spanning tree problem (GMSTP), using a Kruskal based heuristic. Next, the generalized spanning tree is augmented until it becomes a feasible solution of the GMEBCNP.

### 7.3.1 Simple Node Optimization Neighborhood (SON)

The simple node optimization neighborhood consists of all solutions that differ from a current solution by exactly one spanned node. A move within this neighborhood is realized by exchanging a node within a cluster with another one, also removing the connections of the initial node, and adding the corresponding edges to the new node. The node exchange neighborhood is a combination of the simple node optimization neighborhood and edge augmentation neighborhood, and addresses modifications of the spanned nodes as well as the edges connected them. ### 7.3.5 Variable Neighborhood Descent

In their proposed VNS scheme, Hu et al. [82] used the variable neighborhood descent (VND) as local improvement. They provided three VND variants. The first one, denoted VND1, applies the previously described neighborhood structures. The second one, denoted VND2, applies the above mentioned neighborhoods and in addition two neighborhoods, based on the graph reduction technique [82]. Finally, the last variant called the self-adapted variable neighborhood descent (SAVND), applies the same neighborhood structures as VND2, but instead of a given static order, the neighborhoods are rearranged automatically during the search process. The pseudocode of the general VNS is presented in Algorithm 7.1.

### Algorithm 7.1 (VNS algorithm for solving the GMEBCNP).

```
1 Create initial solution S
2 repeat
3   k = 0
4   repeat
5     S' = S
6     if k > 0 then
7       Shaking(S', k): add k randomly chosen edges from E \ T
8       remove the redundant edges
9       VND1 (S') or VND2 (S') or SAVND (S')
10      if solution S' is better than S then
11        S = S'
12        k = 1
13      else
14        k = k + 1
15    until k = k_max
16  until a termination criterion is met
17  return solution S
```

## 7.4 Computational results

Hu et al. [82] have tested their VNS variants for solving the GMEBCNP on two types of instances, namely, Euclidean TSPlib instances with geographical center clustering according to [43] and random instances introduced by Ghosh [49], originally in the case of the GMSTP. For more information on these instances, we refer to Section 2.6 or [82].

The experiments were performed on a Pentium 4, 2.6 GHz PC with 1 GB RAM and, in order to compute the average values and standard deviations, Hu et al. performed 30 independent runs for each instance and algorithm variant.

After analyzing the computational results presented in Tables 7.1 and 7.2, we observe that, in the case of TSPlib instances, from among the tested VNS variants SAVNS performs best, whereas for the random instances, the results are ambiguous. For the group Euclidean and non-Euclidean instances SAVNS performs best and in the case of random Euclidean the VNS2 variant performs best.

## 7.5 Notes

The generalized minimum edge-biconnected network problem (GMEBCNP) is an extension of the edge-biconnectivity augmentation problem and consists of finding the minimum cost subgraph containing exactly one node from each cluster and connecting in an edge-biconnected way. The GMEBCNP was introduced by Huygens [84] and arises in the design of backbones in large communication networks.

Within this chapter, we have presented an integer programming model of the problem and an improved Variable Neighborhood Search (VNS) approach, in which several variants were proposed.

The material presented in this chapter is based on the results published by Hu et al. [82].
