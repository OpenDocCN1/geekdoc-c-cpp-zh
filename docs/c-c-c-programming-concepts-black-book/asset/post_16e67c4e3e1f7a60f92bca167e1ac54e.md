If the key < middle element, then it considers the left-hand side array of the middle element, as the key may exist in the left-hand side sub-array; otherwise, it searches in the right-hand side sub-array of the middle element. Again, the middle element is selected from the sub-array and that element is matched with the key value. Listing 24.45 shows the implementation of the iterative binary search:

### Listing 24.45: Showing the Code for the Iterative Binary Search

```c
#include <stdio.h>

int Binary_Search(int a[],int key,int n)
{
    int mid;
    int first = 0;
    int last = n-1;
    while(first < last)
    {
        mid = (first + last)/2;
        if(a[mid] == key)
        {
            return mid;
        }
        if(key < a[mid])
        {
            last = mid - 1;
        }
        if(key > a[mid])
        {
            first = mid + 1;
        }
    }
    return -1;
}

void main()
{
    int a[50];
    int key,n,x,result;
    printf("Enter the number of array elements. . .\n");
    scanf("%d",&n);
    printf("Enter the array elements. . .\n");

    for(x=0;x<n;x++)
        scanf("%d",&a[x]);

    printf("Enter the number to be searched : ");
    scanf("%d",&key);
    result = Binary_Search(a,key,n);
    if(result == -1)
        printf("Element not found");
    else
        printf("%d is found in the list, at position %d\n",key,result);
}
```

```text
function Binary_Search_Recursive(A[n], key, first, last):integer
begin
  if(first > last)
  begin
    return -1
  end
  mid <- (first + last)/2
  if(A[mid] == key)
  begin
    return mid
  end
  if(A[mid] < key)
  begin
    Binary_Search_Recursive(A[n], key, first, mid-1)
  else
    Binary_Search_Recursive(A[n], key, mid+1, last)
  end
  return -1
end
```

## Algorithm Analysis

Let’s assume an input array of length 64. When we apply the binary search mechanism, it executes in the following way:

- 1. At step 1, when n = 64, Binary_Search is called to reduce the size to n = 32
- 2. At step 2, when n = 32, Binary_Search is called to reduce the size to n = 16
- 3. At step 3, when n = 16, Binary_Search is called to reduce the size to n = 8
- 4. At step 4, when n = 8, Binary_Search is called to reduce the size to n = 4
- 5. At step 5, when n = 4, Binary_Search is called to reduce the size to n = 2
- 6. At step 6, when n = 2, Binary_Search is called to reduce the size to n = 1

Therefore, the number of steps required to search an array of length 64 is 6, where 64 = 2⁶. Similarly, the number of steps required to search an array of length 32 is 5, where 32 = 2⁵. This emphasizes that to sort a list of n numbers, if k steps are required, then n = 2ᵏ.

If we take log on both sides of the equation, n = 2ᵏ, then the result would be as follows:

Log n ≈ k.

Therefore, the time complexity of the binary search algorithm is O(log n).

In the best case, the key element lies at the middle of the list. Therefore, only a single step is required to execute the operation. In this case, the time complexity is O(1). In the worst case, the list needs to be divided until the divided section contains 1 element. In this case, therefore, the time complexity is O(log n). In the average case, the number of steps required to complete the operation is (log n)/2. Therefore, the time complexity is O((log n)/2), which is nothing but O(log n).

## Hashing

Hashing uses a hash table, which is a data structure that accesses data from the memory without any help of indexing. Its main feature is to search a data based on a key, which in turn is calculated based on a hash function. This mechanism is widely used, as it provides a smart way to access or search the data stored in the memory. The two elements that are required for hashing are as follows:

- **Hash key** — Maps the table index with the stored records
- **Hash function** — Finds the table index that is mapped to the hash key
