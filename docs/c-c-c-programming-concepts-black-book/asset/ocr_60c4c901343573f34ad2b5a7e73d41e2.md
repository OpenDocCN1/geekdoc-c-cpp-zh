# Dependency

Dependency is used when one class is fully dependent on another class. For example, when we apply for a loan, the loan amount is fully dependent on the currency that we want. Therefore, there exist a dependency relationship between the loan amount and the currency. Figure 13.24 shows the symbolic relationship of dependency:

![](bbox=[0.319, 0.444, 0.705, 0.493])

As shown in Figure 13.24, we use a unidirectional arrow (➔) to symbolize the dependency relationship.

# Aggregation

Aggregation is used when a class is a part of another class. For example, members are the part of a club. Therefore, there exists an aggregation relationship between the members and the club. Aggregation relation is shown in Figure 13.25:

![](bbox=[0.319, 0.589, 0.705, 0.638])

As shown in Figure 13.25, we use a clear diamond to symbolize the aggregation relationship.

An aggregation is a stronger form of association. It is a structural relationship and specifies that a class represents a larger thing, which constitutes of smaller things. Aggregation represents a has-a” relationship. In UML, aggregation can be represented, as shown in Figure 13.26:

![](bbox=[0.319, 0.704, 0.705, 0.751])

In UML, a link is placed between the whole and part classes with a diamond head attached to the whole class to indicate that this association is an aggregation.

Aggregation is a concept that is used to express “part of” types of associations between objects. One aggregate may contain multiple whole-part structures each viewable as a distinct aggregate.
