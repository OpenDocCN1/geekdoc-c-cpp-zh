# ## AVL Tree

A binary search tree with a balance condition is known as an AVL (Adelson Velskii and Landis) tree. A balance condition insists that every node should have left and right sub-trees of the same height. If the height of an empty sub-tree is defined to be -1, then only perfectly balanced trees of 2^n - 1 nodes will satisfy this criterion.

Although the time complexity of searching an element in a binary search tree is O(log N) in the average case, it is O(N) in the worst case. Suppose we have a binary search tree with elements in the decreasing order. In this case, the root will have the maximum value, and the tree will only grow in the left side with each left side having a NULL right sub-tree pointer and a valid left tree pointer. This type of tree is known as the degenerating tree, where the searching time is in the order of N, for N elements in the tree. AVL, on the other hand, is always balanced and the search time is guaranteed as O(log N) in the average case as well the worst case. The balance condition of making an AVL tree does not allow it to grow on one side and result in a degenerating tree.

An AVL tree is identical to a binary search tree except that for every node in the tree, the height of the left and right sub-trees can differ by at most 1 (the height of an empty tree is defined to be -1). The height of an AVL tree is defined as the maximum level of its leaves. Therefore, an AVL tree can be defined as a binary search tree, where the heights of the two sub-trees of every node never differ by more than 1. The balance of every node in such a tree is defined as the height of its left sub-tree minus the height of its right sub-tree. Each node in an AVL tree has a balance factor of -1, 0, or 1, depending on whether the height of its left sub-tree is less than, equal to, or greater than the height of its right sub-tree. The tree can become unbalanced only if the newly inserted node is a left descendant of a node that previously had a balance of 1 or if it is a right descendant of a node that previously had a balance of -1.

Now, let’s consider the cases where a tree can become unbalanced after an insertion. Following are the four cases where a tree can become unbalanced:

+   1. An insertion into the left sub-tree of the left child of a balanced node
+   2. An insertion into the right sub-tree of the left child of a balanced node
+   3. An insertion into the left sub-tree of a right child of a balanced node
+   4. An insertion into the right sub-tree of the right child of a balanced node
