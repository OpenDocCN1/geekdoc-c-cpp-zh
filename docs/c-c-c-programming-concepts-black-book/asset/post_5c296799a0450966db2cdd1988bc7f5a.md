## The Unzip Operation

In the unzip operation, we use the object of the ZipFile class, which is a collection of ZipEntry objects, create a separate directory of the same name in the folder where the zipped file has been selected, and copy each compressed file in that location. The constraint that we imposed on this operation is that it does not process any directory inside a zipped file. The stepwise execution of the unzip operation is as follows:

- 1. When the UnZip Files button is clicked, the Open dialog box appears prompting a user to select a zipped file from it. Figure 21.18 shows the Open dialog box:
  
  ![](img/43c5f409f9b17790a628c4b4df854b61_752_1.png)
  
  After selecting a zipped file from the dialog box, the file information is extracted and the `UnzipFiles()` method is called, which is defined in the `ZipSource` class library. The `UnzipFiles()` method takes two arguments: the file path information and the output location. In our case, the output folder is created at the same path from where the user selects the zip file. At first, it opens the zip file for read and returns a `FileStream` object.
- 2. An object of the `ZipFile` class is created that contains the collection of zipped files.
- 3. The unzip file operation creates an output directory in the output location. Using a fixed-size buffer, it uses the `Copy()` method of the `StreamUtils` class to copy the file from the zipped folder to the created output directory.
- 4. At the end of the process, the resources held by the `ZipFile` class are released.

The C# code for the unzip operation is shown in Listing 21:18:

**Listing 21:18: Showing the `UnzipFiles()` Method**

```csharp
public static void UnzipFiles(string fileName, string outputLocation)
{
    //Opening the zip files that is to be decompressed
    FileStream fs = File.OpenRead(fileName);

    //Creating the ZipFile object that contains all the ZipEntry objects
    ZipFile zipFile = new ZipFile(fs);

    foreach (ZipEntry zipEntry in zipFile)
    {
        //Ignoring the directories
        if (zipEntry.IsFile)
        {
            continue;
        }
        byte[] buffer = new byte[4096]; //Choosing the optimum storage
        Stream zipStream = zipFile.GetInputStream(zipEntry);
        //Creating the output file directory
        string outputDirectory = fileName.Substring(0, fileName.LastIndexOf("\\"));
        string outputFileName = outputDirectory + "\\" + zipEntry.Name;
        if (!Directory.Exists(outputDirectory))
        {
            Directory.CreateDirectory(outputDirectory);
        }
        //Copying the zipped file content to the unzipped file content using the buffer storage
        using (FileStream streamWriter = File.Create(outputFileName))
        {
            StreamUtils.Copy(zipStream, streamWriter, buffer);
        }
    }
    //Releasing the resources held by zipfile object
    zipFile.Close();
}
```

## Describing the Isolated Storage

Sometimes when we try to save a file in a registry or disk, the operation fails due to an access issue or storage issue. Moreover, if the location is known to other users, then they can access the file easily and damage the data in it. Therefore, Microsoft provides a better way to handle the application-specific user data known as isolated storage.

Isolated storage creates a virtual store for an application. Whenever a file is created through the application, it is saved in the isolated storage area. Only the application and the .NET assembly have the access to this isolated storage. In other words, any other application cannot access this isolated storage area assigned to the application; thereby, providing a secret, application-specific storage. Therefore, isolated storage provides a trusted way to store any application-specific user data, as the data is configured and controlled by an administrator only. The .NET runtime environment uses a user-friendly mechanism of the operating system to support this concept. An application can utilize the isolated storage in the following two ways:

- Isolated storage can be accessed by the application and the assembly. For multiple instances of the application, the same storage area can be accessed.
- Isolated storage can be accessed by the application, each instance of it, and the assembly. It implies that the application can be written in such a way that each instance can access different isolated storage area. This refines the access procedure, and reduces the possibility of errors due to concurrent execution.
