Table 22.1: Describing the data types for the sockaddr_in structure

| Datatype | Description | Header |
|---|---|---|
| int8_t | signed 8-bit integer | `<sys/types.h>` |
| uint8_t | unsigned 8-bit integer | `<sys/types.h>` |
| int16_t | signed 16-bit integer | `<sys/types.h>` |
| int32_t | signed 32-bit integer | `<sys/types.h>` |
| uint32_t | unsigned 32-bit integer | `<sys/types.h>` |
| sa_family_t | address family of socket address structure | `<sys/socket.h>` |
| socklen_t | length of socket address structure normally uint32_t | `<sys/socket.h>` |
| in_addr_t | IPv4 address, normally uint32_t | `<netinet/in.h>` |
| in_port_t | TCP or UDP port, normally uint16_t | `<netinet/in.h>` |

+   - The storing of the IPv4 addresses and the TCP or UDP ports is always in network byte order.
+   - The IPv4 address stored inside the sockaddr_in structure can be used in two different ways. Let us assume that the server is a variable of Internet socket address structure type. Then we can refer to the IPv4 address of the socket address structure as server.sin_addr. The syntax server.sin_addr refers to the 32-bit IPv4 address as the in_addr structure, whereas the same IPv4 address can be referenced to as server.sin_addr.s_addr. In the second scenario, we refer to a 32-bit unsigned integer. We should be referencing the IPv4 address correctly while passing the sockaddr_in structure to functions.
+   - The sin_zero field of the structure remains unused. By convention, the field is always set to zero.
+   - The socket address structures are only used on a single host.

# Generic Socket Address Structures

Socket address structures are always passed as a reference to socket functions. The socket functions take pointers to one of the socket structure passed to them as an argument. They must be compatible to socket address structures belonging to any protocol family, which means that we would require a generic address structure which can be used across all protocol family. The generic socket address structure is defined inside the <sys/socket.h> header. Listing 22.2 defines a generic socket address structure:

Listing 22.2: Describing a generic socket address structure

```
    struct sockaddr {
        uint8_t        sa_len;
        sa_family_t    sa_family;    /* Address family */
        char           sa_data[14];  /* Protocol specific address */
    };
```

The socket functions that we would be discussing in this chapter take pointer to the generic socket address structure. Before passing the argument, explicit type casting is required. Let us take an example of a function called bind whose signature is:

```
    int bind(int , struct sockaddr *, socklen_t);
```

Any call made to the function requires the socket address structures to be casted from a protocol specific to a generic one. For instance:

```
    struct sockaddr_in serverAddress;

    bind(sockfd, (struct sockaddr*)&serverAddress, sizeof(serverAddress));
```
