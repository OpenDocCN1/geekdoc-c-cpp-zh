# # IPv6 Socket Address Structure

The IPv6 socket address structure is defined inside the header <netinet/in.h> and appears as follows:

```
struct in6_addr {
    uint8_t              s6_addr[16];    /* 128 bit IPv6 address network byte ordered */
};

struct sockaddr_in6 {
    uint8_t              sin6_len;       /* length of the structure */
    sa_family_t           sin6_family;    /* AF_INET6 */
    in_port_t             sin6_port;      /* IPv6 port network byte ordered */
    uint32_t              sin6_flowinfo; /* priority and flow label */
    struct in6_addr       sin6_addr;      /* IPv6 address Network Byte Ordered */
};
```

Some important remarks of the IPv6 socket address structure are as follows:

+   - The sin6_len should be defined if the length member of the socket address structure is supported by the system.
+   - The IPv6 family is AF_INET6.
+   - The sin6_flowinfo member is divided into the following three fields:
+     - The lower order 24 bits are called flow label.
+     - The next 4 bits are priority.
+     - The next 4 bits are reserved.

# ## Byte Ordering Functions

Before going into the depth of socket APIs, we need to understand the byte ordering of variables that takes place in network programming. Let us consider a 16-bit integer which is made up of two bytes. We have two ways of storing the number in memory. In the first method, we store the lower byte at the starting address, which is known as little endian method. The second method is to store the higher order byte at the starting address, which is known as big endian method. The two methods are explained in Figure 22.1:
