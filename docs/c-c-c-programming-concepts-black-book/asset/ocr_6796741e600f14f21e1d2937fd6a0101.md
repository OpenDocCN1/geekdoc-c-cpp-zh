# # Deadlocks

Deadlocks can arise if two or more threads share a common set of resources and try to lock the resources in some order and wait for them indefinitely. This kind of deadlock situation happen when two or more competing threads are waiting for each other to finish; and therefore, they keep on waiting for each other indefinitely. Deadlocks are very common in multithreading systems, where both the software and hardware locks are used to handle shared resources and implement synchronization. Consider the following example, which will lead to a deadlock:

```
    Thread 1                                   Thread 2
    Lock (A)                                   Lock(B)
    Lock (B)                                   Lock(A)
    ...
```

In the preceding example, we have defined two threads – Thread 1 and Thread 2. Note that both the threads are sharing the same data space. Now, we have two variables, A and B, which are common to both the threads. In the execution path, Thread 1 locks the variable A and waits to lock the variable B. On the other hand, Thread 2 executing in parallel, locks the variable B first and then intends to lock the variable A, which is currently locked by Thread 1. This implies that both Thread 1 and Thread 2 wait for the resources A and B, which are currently locked by the other thread; therefore, both the threads are in a deadlock situation. In other words, both Thread 1 and Thread 2 wait for an event, unlock(), which is never going to happen.

Therefore, while writing the codes for multithreading-enabled programs, we should ensure that all the threads acquire the locks in the same order. That is, if Thread 1 locks A first and then locks B, then all the other threads performing the similar operation should also lock A before locking B.
