## Register Storage Class

In previous versions of C, the register storage class specification was only applicable to variables of type int, char, or pointer but later the definition of register storage class has been modified to include all types of variables. The register specifier tells the compiler to keep the value of the variable in a CPU register rather than in memory. The main motive behind this is to speed up the operations taking place over that variable. Repeated memory access is much slower while accessing CPU. Register storage classes are introduced to achieve better performance, as registers reside inside the CPU itself.

Some basic features of register storage class are as follows:

- **Storage**—The value of a variable having register storage class specifier is always stored inside a CPU register
- **Initialization**—A register specifier type variable will be initialized with garbage value when it's declared.
- **Scope**—The scope of such variables are always within the block where the variable is defined.
- **Life**—The lifetime of a variable having register storage class specification will remain till the control remains within the block inside which the variable is defined

Characters and integer variables are generally declared as register variables and get stored inside CPU registers. Variables as big as arrays and large strings are avoided as CPU registers have limited storage capacity. It is always a good idea to store variables like loop counters inside registers as access to them is relatively high compared to any other variables in a program. Compiler takes the decision of associating a CPU register with a register variable. When a compiler fails to find an empty register for storage, it simply associates an auto storage class specifier with it.

Register storage class specifiers can only be associated with variables that are local to a function or block. Global register variables are not allowed.

Listing 2.25 describes register storage class specification:

### Listing 2.25: Register Storage Class Specification in C

```c
#include<stdio.h>

int main()
{
    int sum = 0;
    register int count;

    for(count=1; count <= 100; count++)
    {
        sum += count;
    }
    printf("\n Sum is [%d] ",sum);
    getch();
    return 0;
}
```

The output of Listing 2.25 is given as follows:

```text
Sum is [5050]
```

In Listing 2.25, the count variable is declared as a register variable, as it acts like a loop control variable and gets most frequently used in a program. It is better to declare frequently accessed variables as registers. Any number of variables can be declared as register variables. A compiler can convert a variable to auto if it fails to find a CPU register for it. Address of a register variable cannot be obtained in C using the & operator. This is mainly due to the fact that it cannot figure out beforehand that a variable declared with a register storage class specification resides inside a register or not.

Listing 2.26 shows an example of accessing the address of register variables:

### Listing 2.26: Accessing Address of Register Variables

```c
#include<stdio.h>

int main()
{
    int *ptr;
    register int vara;

    ptr = &vara;

    printf("\n The address of vara is [%d]",ptr);
    getch();
    return 0;
}
```

The preceding code will give the following warning during compilation:

```text
[warning] address of register variable `vara' requested
```

The warning mentioned in the preceding output shows that accessing memory address of a register variable is prohibited in C, so it is not a good practice to request address of a register variable.

## Extern Storage Class

Variables declared as extern are not confined within a function or block. The scope of extern variables ranges from the point they are declared till the scope of the program ends. Extern variables are sometimes called global variables as well. Understanding the extern storage class specification requires a brief understanding of the C linkage. C generally defines three linkages— external, internal, and none. Functions and extern variables are said to have an external linkage, which means that they are accessible to all the files that make up the program. Objects declared as static are said to have an internal linkage, which means that they are only known to that file where they are declared (this is also regarded as file scope). Since extern variables are accessible throughout the program, they retain their values that are assigned to them within a scope. It means that an extern variable can be assigned values inside a function, which can be later accessed by other functions as well. This helps the user to transfer information from one place of the program to another. This is useful in cases where we want to return multiple items from a function. A simple way of achieving this is to make the variables extern so that they can be used to transfer values.

While working with external variables, it is important to understand the difference between their declaration and definition. Declaration of extern variables is similar to that of any other variables like auto or register. The only difference is that they should be declared outside all functions accessing them. Definition of variables links a storage class specifier with it. It is not mandatory to use the keyword "extern" while defining an extern variable. The compiler will itself link the extern storage class with the variable depending on the location of its declaration. A variable defined as extern can be assigned a value from the point of its definition.

Listing 2.27 shows how to declare extern variables:

### Listing 2.27: Extern Storage Class Specification

```c
#include<stdio.h>

int global_var = 10;

int main()
{
    printf("\n The value of the variable is [%d] ",global_var);
    getch();
    return 0;
}
```

The output of Listing 2.27 is given as follows:

```text
The value of the variable is [10]
```

The global_var variable is declared before any functions in the program, so the compiler has assigned an extern storage class to the variable. This makes the global_var variable accessible from any function inside the program.

Listing 2.28 shows how to modify values of an extern variable:

### Listing 2.28: Modifying Values of an Extern Variable

```c
#include<stdio.h>

int global_var = 10;

void myFunction();
int main()
{
    printf("\n The value of the variable is [%d] ",global_var);
    myFunction();
    printf("\n The value of the variable is [%d] ",global_var);
    getch();
    return 0;
}
void myFunction()
{
    global_var++;
}
```

The output of Listing 2.28 is given as follows:

```text
The value of the variable is [10]
The value of the variable is [11]
```

The output shows that the variable retains the values assigned to it from any function and the same value is displayed when the variable is next time displayed from the main function. One fact about extern variables is that for majority of variables, declaration also means the definition of variables. However, for extern variables, we can actually declare the variable without defining it. When we need to refer to the same variable, we can associate the name of the variable with the extern keyword that automatically links the declaration of the variable with the definition.
