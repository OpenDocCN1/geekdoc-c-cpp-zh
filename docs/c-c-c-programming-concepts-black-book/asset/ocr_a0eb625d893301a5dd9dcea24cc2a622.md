# Chapter 8

A library is a collection of functions. A library file stores the functions individually. It is similar to an object file but there is a difference as well. When an object file is linked, the entire content of the object is becomes the part of the executable file. However, when a program uses a library function, only the function is added to the program and not the entire content of the library.

The American National Standards Institute/International Organization for Standardization (ANSI/ISO) standard has defined various sets of functions that must be supported by all the C compilers. These sets of functions are known as standard library functions. With the help of these functions, complex and cumbersome C programs can be simplified to a great extent. C programs can use the standard library functions irrespective of the architecture and platform on which they are compiled and executed.

In this chapter, we learn about mathematical functions, time functions, dynamic allocation functions, utility functions, and string functions.

Let’s begin the chapter with the mathematical functions.

# Mathematical Functions

The C89 compiler used to support only 22 mathematical functions, which have comparatively tripled in size with the advent of C99 compiler. To use these functions in a program, we first need to include the <math.h> header in the program, as the prototype for the functions are defined within it. The <math.h> header also contains some macros that are linked with these functions. The C89 compiler used to define only one macro called HUGE_VAL, which is a double value indicating that an overflow has occurred. On the other hand, C99 defines a number of macros, which are given as follows:

```
HUGE_VAL          - A float version of HUGE_VAL
HUGE_VALL         - A long double version of HUGE_VAL
math_errhandling  - Contains MATH_ERRNO and/or MATH_ERREXCEPT
MATH_ERRNO        - Error number is used to report errors
MATH_ERREXCEPT    - Floating-point exception is raised to report errors
NAN               - Not a number
```

C99 also defines the following macros, which are used to classify a value:

```
int isfinite(val)    - Returns non-zero if val is finite
int isin f(val)      - Returns non-zero if val is infinite
int isnormal(val)    - Returns non-zero if val is a normal value
int isnan(val)       - Returns non-zero if val is not a number
```

In addition, C99 defines the following set of comparison macros for floating-point values:

```
int isgreater(a, b) - Returns non-zero if a is greater than b
int isgreaterequal(a,b) - Returns non zero if a is greater than or equal to b
int isless(a, b) - Returns non-zero if a is less than b
int islessequal(a,b) - Returns non-zero if a is less than or equal to b
int islessequal(a, b) - Returns non-zero if a is greater than or less than b
int isunordered(a, b)- Returns 1 if a and b are unordered relative to each other;
else, returns 0 if a and b are ordered
```

In the C89 and C99 compilers, error handling related to the mathematical functions is somewhat different in nature. In the C89 compiler, if an argument to a mathematical function is not present in the domain for which it is defined, then an implementation-dependent value is returned by the function and the global integer errno variable is set to EDOM. For the C99 compiler, however, an implementation-specific value is returned. If the returned value contains MATH_ERRNO, then the errno variable is set to EDOM. However, if the returned value equals to MATH_ERREXCEPT, then a floating-point exception is raised.

In the C89 compiler, if a mathematical function creates a result, which is too huge to be represented, then an overflow occurs. In such a situation, the function returns HUGE_VAL and the errno variable is set to ERANGE, which indicates a range overflow. For an underflow, the function returns 0 and the errno variable would be same as ERANGE. For the C99 compiler, overflow and underflow work in a similar manner.
