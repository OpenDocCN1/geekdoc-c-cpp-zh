Similar to UNIX, Linux has a monolithic kernel. This implies that Linux is implemented as a single process running entirely in the kernel space. However, Linux also borrows some of the features from microkernels. Linux adds to itself the capability of loading small kernel modules dynamically that enhances its functionality at runtime without restarting the operating system. Let’s consolidate the characteristics of Linux kernel that makes it different from UNIX variants:

+   1. Linux supports dynamic loading of kernel modules. Although the Linux kernel is monolithic, it is capable of dynamically loading and unloading the kernel code on demand.
+   2. Linux has Symmetric Multiprocessor support. Symmetric multiprocessing is a computer architecture where two or more processors are connected by a single shared memory and the entire system is controlled by a single operating system instance.
+   3. The Linux kernel is preemptive, that is, it can be interrupted to perform another task. Unlike traditional UNIX variants, the Linux kernel is capable of preempting a task even if it is running in the kernel. UNIX implementations, such as SOLARIS and IRIX, have preemptive kernels, but most traditional UNIX kernels are non-preemptive.
+   4. Linux takes an interesting approach towards thread support, that is, it does not differentiate between normal threads and processes. This implies that they are all the same to the kernel.
+   5. Linux provides an object-oriented device model with device classes, hot pluggable events, and a user-space device filesystem (sysfs).
+   6. Linux ignores some common UNIX features that are thought to be poorly designed, such as STREAMS.
+   7. Linux is free in every sense of the word, that is, its source code is freely distributable and can be modified and enhanced by anyone.

# ## Linux Kernel Modules

Linux kernel modules are smaller modules having a specific functionality that can be loaded and unloaded into the kernel dynamically. Similar to microkernels, kernel modules extend the functionality of the kernel without the need to reboot the system. However, we should be careful while running the kernel modules from the systems, as even a small mistake in the code can wipe out the entire file system or may result in a core dump followed by a reboot. Examples of Linux kernel modules are device drivers that allow the kernel to access hardware connected to the system. Without kernel modules, we would have to build monolithic kernels and add the new module directly into the kernel image to add a small functionality or utility into the Linux kernel. Moreover, one of the biggest disadvantages of having larger kernels is that it requires us to rebuild the entire kernel and reboot it every time to add a new functionality.

To see the kernel modules that are already loaded into the kernel, we need to run the lsmod command and view its output. The lsmod command displays this information by reading the /proc/modules file. A kernel module has its extension as ko.
