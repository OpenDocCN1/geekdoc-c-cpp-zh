
Output of the preceding program is as follows:

The result after shifting 5 bits to the right [-1]

We can notice in the output that even after shifting the number 5 bits to its right, the value stays as -1. This happens as the compiler fills the blank positions with 1 instead of 0. However, this handling may vary from compiler to compiler.

## Left Shift Operator

Left shift operator is similar to a right shift operator; however, the difference is that the bits are shifted to the left. For every bit being shifted, a 0 is added to the right of the number. The left shift operator is denoted by a << sign. Let’s consider the following expression:

abc << 5

Assume that abc contains a bit pattern, 10101110. If the number gets shifted 5 places to its left, then the resultant value becomes 11000000. Figure 5.5 shows the working of left shift operation:

```c
#include<stdio.h>

{
    int varA = 174;
    varA = varA << 5;
```

The decimal representation of 10101110 becomes 174. After shifting the number 5 places to its left, the result becomes 5568 in the 32-bit decimal representation.

Let’s take a look at the code that converts a given decimal number to its 16-bit binary notation, as shown in Listing 5.38:

### Listing 5.38: Showing the Binary Representation of Variables

```c
#include<stdio.h>
int main()
{
    int varA, i, mask, bitPos;
    printf("\nEnter any decimal number -> ");
    scanf("%d",&varA);
    printf("\n The Binary equivalent of %d is ",varA);
    for(i=15;i >= 0;i--)
    {
        mask = 1 << i;
        bitPos = varA & mask;
        bitPos == 0 ? printf("0"):printf("1");
    }
    getch();
    return 0;
}
```

Output of the preceding program is as follows:

```
Enter any decimal number -> 276
The Binary equivalent of 276 is 0000000100010100
Enter any decimal number -> 139
The Binary equivalent of 139 is 0000000010001011
```

When the loop is executed for the first time, the content of mask is 1000000000000000. With this mask, the most significant bit is masked off. If the bit is 0, then 0 will be displayed; else, 1 is displayed. Now, i gets decremented and the next most significant bit is masked off; the process continues till all the 16 bits are covered.

## Type Qualifiers

Type qualifiers control the way variables are accessed or modified. The C89 compiler defines two types of qualifier: const and volatile. The C99 compiler defines a new type of qualifier called restrict. According to the C89 compiler, all the variables are considered unqualified if no qualifier is used in their definition. A type qualifier must precede the type names that they qualify. Type qualifiers change the properties of a variable only for the scope in which the variable is declared. For example, a variable declared as const remains a constant only within the current scope of that variable.

Let's consider calling the memcpy() function, which has the following prototype:

```c
void *memcpy(void * restrict dest, const void * restrict src, size_t len);
```

The preceding function could be called with a pointer pointing to a regular (non-read-only) part of the memory. We assume that the implementation will not write into the area pointed to by the src pointer. By using the restrict qualifier, it is ensured that no overlap takes place between the two pointers when the function is called.

Let's learn about const, volatile, and restrict.

### const

Variables declared as const are not allowed to be changed in a program. A const variable can be initialized when it is declared. A compiler generally places these sorts of variables in the read-only part of the memory. Consider the following statement:

```c
const int varA = 20;
```

The preceding statement creates a variable called varA and assigns a value 20 to it. However, this value cannot be altered by any program, which works on the variable. Const variables are generally used to prevent the object pointed to by an argument to a function from being modified by that function. When a pointer is passed to a function, the function can modify the object pointed to by the pointer. If the pointer is mentioned as const in the parameter declaration, then the function will not be able to modify it.

Listing 5.39 shows the code that would not compile, as we are trying to modify the content of a const variable inside the checkFunc() function:

### Listing 5.39: Showing the Const Parameter in C

```c
#include<stdio.h>
void checkFunc(const int varA);
int main()
{
    const int varA = 10;
    checkFunc(10);
    getch();
    return 0;
}
void checkFunc(const int varA)
{
    printf("\n variable passed [%d] ",varA);
    varA++;
}
```

Compilation error is shown as follows:

```
In function 'checkFunc': increment of read-only location
```

Many standard library functions, such as strlen() and strchr(), have a const type qualifier for the string arguments that are passed to them. It indicates that the functions would not modify the content of the string passed to them.

A general form for declaring const variables is as follows:

```c
const int varA = 10;
```

The following alternative form is also acceptable, since the order of type specifiers and qualifiers does not matter:

```c
int const varA = 5;
```

Order becomes important when composite types with pointers are used, shown as follows:

```c
int * const ptr = &i; /* const pointer to int */
const int * ptr_1; /* pointer to const int */
int const * ptr_1; /* pointer to const int */
```

The pointer ptr is itself a const, that is, the pointer cannot be modified. However, the integer variable it points to can be modified. In contrast, pointer ptr_1 can be modified, but the variable it points to cannot.

Casting away the const-ness (type casting a const variable into a non-const one) is possible, but considered dangerous. Modifying a const-qualified variable is not only dangerous, but may even lead to runtime errors, if the values are placed in the read-only storage, shown as follows:

```c
const int * ptci;
int *pti, i;
const int ci;
ptci = pti = &i;
*ptci = 5; /* Compiler error */
*pti = 5; /* OK, but dangerous */
pti = &ci; /* Compiler error */
pti = ptci; /* Compiler error */
pti = (int *)&ci; /* OK, but dangerous */
*pti = 5; /* OK, dangerous and potential runtime error */
```

### volatile

The volatile type qualifier tells the compiler that the value of the variable can be changed outside its current scope. Consider a scenario where the address of a global variable is passed to the operating system's clock routine and is used to hold the system time. In such a situation, the content of the variable will be altered without any explicit assignment statements in the code. The C compiler automatically optimizes certain portions of the code assuming that a variable’s content remains unchanged if it does not occur in the left side of any assignment statement. Therefore, this situation can give rise to a number of misleading errors. The volatile type qualifier prevents this sort of changes where a compiler optimizes the code based on certain assumptions. The volatile type qualifier has extensive usage in the multi-threading environment where content of any variable is shared across multiple processes or threads. It should be kept in mind that frequent usage of volatile type qualifier can make the code slower.

### restrict

The meaning of a restrict-qualified pointer is that there is no other method to access the object, which is pointed to by a pointer. This property indicates that aliasing is not an issue for a so-qualified pointer. The restrict type qualifier may only be used for pointers.

The restrict type qualifier is mainly used for optimization. The optimizations enabled by using the restrict qualification have been present in most compilers. However, the profit that can be observed by using a restrict type qualifier is not as large as it seems; therefore, the usage of restrict type qualifiers is minimal. However, only on a global basis (compiler options), the extra gain to be expected is not quite as large; therefore, the necessity of using this qualifier can be considered minimal. Leaving out the keyword shall not change the behavior of a program.

## Memory Segmentation in C

After compilation, a C program creates four logically distinct regions of memory. The first region is often referred to as the text segment. This is the area in which the executable instructions reside. Only one copy of the instructions for the same program resides in the memory at any time. The portion of the executable file containing the text segment is the text section.

The second region of memory is where the global variables are stored. This region is divided into two parts. The first part is called the data segment where the global and statically allocated variables are initialized with non-zero. Each process running the same program has its own data segment. The portion of the executable file containing the data segment is the data section. The second part is the uninitialized data segment or the Block Started by Symbol (BSS) segment. Global and statically allocated data, which are initialized to 0 by default, are kept in this region of memory. Each process running the same program has its own BSS area. While running a program, the BSS data are placed in the data segment; however, in the executable file, they are stored in the BSS section.

The next region is the stack, which is used to hold the return addresses of function calls, arguments to functions, and local variables. The stack region also saves the current state of the CPU. The data is popped from or pushed into the stack following the Last In First Out (LIFO) rule. When a function is called, a stack frame (or a procedure activation record) is created and pushed onto the top of the stack. This stack frame contains information, such as the address from which the function was called and where to jump back when the function is finished (return address), parameters, local variables, and any other information needed by the invoked function. A stack typically grows downwards so the items, which are deeper inside the stack, are closer to the heap segment.

The last segment is known as a heap. This is a free memory region, which is used by programs through dynamic memory allocation functions of C. Everything on a heap is anonymous; therefore, we only access parts of it through a pointer. As memory is allocated on a heap, the process’s address space grows. Although it is possible to give memory back to the system and shrink a process’s address space, this is almost never done because the memory might be allocated to some other process. Items that are added to a heap are numerically greater than the ones added to the previous regions. This happens as a heap grows upwards. A pointer, known as break, marks the end of heap.
