
Similarly, a socket becomes ready for writing when one of the following conditions holds:

- The number of bytes of the available space in the socket send buffer is greater than or equal to the current size of the low water mark for the socket send buffer.
- The write half of the connection is closed. Any write operation on that socket will generate a SIGPIPE.
- A socket error is pending. The write operation on the socket will not block and continue; it will return an error(-1) with the errno flag set to a specific value.

A socket has an exception condition pending if there exists out-of-band data for the socket or the socket still happens to be in out-of-band mark. When an error occurs, the socket is considered both readable and writable by the select function call. ### recv and recvfrom Functions

The signatures of the recv and recvfrom functions are as follows:

```c
ssize_t recv(int s, void *buf, size_t len, int flags);

ssize_t recvfrom(int s, void *buf, size_t len,
                int flags, struct sockaddr *from,
                socklen_t *fromlen);
```

We need to include the headers <sys/types.h> and <sys/socket.h> in order to use these two functions. The functions are used to read data from the socket once they are connected. The recv() function is used for connecting TCP sockets and the recvfrom() function is used for reading information from a UDP socket. Both the functions contain some arguments in common; both includes a socket descriptor, which is denoted by the integer value “s.” A pointer to a buffer denoted by “buf,” which will contain the information that is being read. Another argument happens to be the size in bytes, which is denoted by the argument “len,” The argument “flags” controls different functionalities of the functions. Apart from all these arguments, the recvfrom function takes some additional arguments and the “from” argument tells from where the information came. The function call also gives the socket address structure of the source from where the data is coming. The “fromlen” field contains the length of the socket address structure. Table 22.3 presents the different values that can be provided to the “flags” field:

| Type | Description |
|---|---|
| **MSG_OOB** | This flag denotes “receive out-of-band data”. When the MSG_OOB flag is set, it signifies that the out-of-band information should be read instead of the normal information. |
| **MSG_PEEK** | This flag helps us to look at the data that is available to be read without having the system discard the information. |
| **MSG_WAITALL** | This flag tells the kernel not to return from a read operation until the requested number of bytes have been read. |

Both the functions return the number of bytes actually received. The value returned might be less than the length that is passed as a parameter. If the remote side closes its end of the connection, then the recv() function returns zero.

### send and sendto Functions

The signatures of the send and sendto functions are as follows:

```c
ssize_t send(int s, const void *buf, size_t len, int flags);

ssize_t sendto(int s, const void *buf, size_t len,
              int flags, const struct sockaddr *to,
              socklen_t tolen);
```

The send function is mostly used for TCP connections, whereas the sendto function is meant for UDP unconnected datagram sockets. For unconnected, we need to specify the destination address each time we are sending a packet. To specify the destination address, we need the last two parameters of the sendto function call. The argument “s” denotes the socket, “buf” is a pointer to the buffer which contains the data that needs to be sent, and “len” is the number of bytes that needs to be sent. The “flags” parameter tells us how the data needs to be sent from the client. If the flag is set to zero, then it signals normal data. Let us take a look at some of the values of these flags, as presented in Table 22.4:

Table 22.4: Different flags used in I/O functions

| **Type** | **Description** |
|---|---|
| MSG_OOB | For the send function, this flag signifies that the out-of-band data is being sent. It’s a way of telling the receiving end that this data has a higher priority than the normal data. |
| MSG_DONTROUTE | This flag tells the kernel that the destination is on a locally attached network and we need not perform lookup of the routing table. Additional support has been added to this feature as a setsockopt option of SO_DONTROUTE. |
| MSG_DONTWAIT | This block signifies a non-blocking I/O without having to turn on the non-blocking flag for the socket. This option performs the I/O operation and turns off the non-blocking flag. It’s like enabling a non-blocking option just for this send. |
| MSG_NOSIGNAL | This flag is required when we are sending to remote host which is no longer receiving. In such scenarios, we generally get a SIGPIPE signal. This flag prevents such signals from getting raised. |

The functions return the number of bytes actually sent. It might happen that the number of bytes that we have sent is less than the number of bytes that we wanted to send. If the connection is closed, then the process calling send() will get a SIGPIPE signal.

### readv and writev Functions

The signatures of the readv and writev functions are as follows:

```c
int readv(int filedes, const struct iovec *iov, size_t count);

int writev(int filedes, const struct iovec *iov, size_t count);
```

We need to include the header file <sys/uio.h> in order to use the readv and writev functions. The two functions are almost similar to the parameter to the read() and write(), but these functions allow us to read from or write into multiple different buffers with a single function call. These functions are often referred to as scattered read (because the input data gets scattered into multiple application buffers) and gathered write operations (since multiple buffers are gathered together for a single output operation). The first argument is the file descriptor that is required to make the function call. The second argument to both the functions is a pointer to an array of “iovec” structures. This is defined inside the header <sys/uio.h> as follows:

```c
struct iovec {
    void  *iov_base;    /* starting address of the buffer */
    size_t  iov_len;    /* size of the buffer */
};
```

There are some limits to the number of elements in the array of the iovec structures that an implementation allows. If we take the example of 4.4BSD, then it allows up to 1024 elements in the iovec structure, whereas Solaris 2.5 has upper limit of 16. The readv and writev functions can be used for any sort of descriptors; they are not restricted to only sockets. All the buffers mentioned in the functions are filled in the array order. It means that the readv() function first fills vector[0] before proceeding to vector[1]. Similarly, the writev() function writes vector[0] first before moving to vector[1].

### recvmsg and sendmsg Functions

Another pair of read and write functions are present, which are most general of all the I/O functions. Any form of read and write operations can be replaced with the two functions. The signatures of the recvmsg and sendmsg functions are as follows:

```c
ssize_t recvmsg(int socket, struct msghdr *message, int flags);
ssize_t sendmsg(int socket, struct msghdr *message, int flags);
```
