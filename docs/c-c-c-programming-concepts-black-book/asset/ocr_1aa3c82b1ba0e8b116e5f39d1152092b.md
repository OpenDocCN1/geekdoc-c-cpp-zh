# Registering a Device

Character devices are accessed through the device files, which are located in /dev. Each character device file has two numbers: a major number and a minor number. The major number helps in locating the file that handles the device. On the other hand, the minor number is used by the driver to differentiate between the devices it is working on, in case the driver handles more than one device. Whenever we add a device to the system, we need to first register it with the kernel. The major number of a device is generated during the initialization of a module. The function called to register a device with the kernel is register_chrdev(), which is defined in the linux/fs.h header file. The signature of register_chrdev() is given as follows:

```
int register_chrdev(unsigned int major, const char *name, struct file_operations *fops);
```

In the preceding signature, the first argument is the major number that we want to request; the second argument is the name of the device as it appears in /proc/devices; and the third argument is a pointer to the file_operations table for the driver. If the major number is passed as 0, then register_chrdev() tries to dynamically allocate a major number and returns its value. If the major number is passed as some positive non-zero value, then register_chrdev() attempts to register the device with the given major number and returns 0 on success. The register_chrdev() function returns a negative value on failure.

While registering character devices, we mostly pass the major number as 0 to the register_chrdev() function. This ensures that there is no conflict with the major number of the existing registered devices. However, this approach has one disadvantage that we cannot make a device file in advance, as we do not know which major number it is going to take. There are a couple of methods to make a device file. First, the driver can print its own newly assigned major number and using this, we can make the device file. Second, the newly registered device can make the entry in /proc/devices, and from there, we can generate the device file easily. Third, we can make the driver create the device file using the mknod system call after a successful registration and rm during the call to cleanup_module.

Note that we do not pass the minor number of a device explicitly to the kernel during a registration, as only the device uses it. This implies that the Linux kernel has nothing to do with the minor number of a device.

# Unregistering a Device

After a character device serves its purpose, we need to unregister it from the kernel. The following function can be used to unregister a character device file from the kernel:

```
int unregister_chrdev(unsigned int major, const char *name);
```

In the preceding function, the first argument is the device major number and the second argument is the device name. The unregister_chrdev() function is called during module_cleanup to remove the driver from the kernel. It returns 0 on success and -EINVAL if the major number is not registered with the matching name.

# Device Drivers

Whenever we plug-in a new device into a system, a special program is loaded into it during its start-up. This special program is known as the device driver routine. Without a device driver, the system would not be able to use the device. For example, when we plug-in a TV tuner card or a graphics card into a system, we need to install the driver into the system to make it recognize the new hardware and support its execution and operation. In UNIX, each piece of hardware is represented by a file located in /dev, which provides the communication with the underlying hardware.

As most of the devices are used in both the input mode and the output mode, a mechanism should be there for a driver to receive an input and send an output to the device. To send an output to the device, we need to open the device file in the input mode and write the required data to it.
