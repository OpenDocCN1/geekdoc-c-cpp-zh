socket address structure should contain a valid IP address and a port number of the server. For a TCP socket, the connect call initiates a three-way handshake and establishes the connection. The function returns only when the connection is established or an error has occurred. The following error scenarios occur in a connect call:

+   * It might happen that the client is not getting any response from the SYN that it has sent to the server. ETIMEDOUT is returned in such scenario.
+   * It can happen that the server sends a RST in response to the SYN sent from the client. This response indicates that no process is waiting for that host on the server side. The server process is not running on the port that is mentioned in the SYN sent from the client. These sorts of errors are known as hard errors, and ECONNREFUSED is returned to the client when the RST is received. A RST is also known a reset; this sort of segment is sent by TCP when something goes wrong. Generally, there are three conditions that can give rise to a RST. Firstly, when a SYN arrives on the port at the server side and no process is listening on that port. Secondly, when the TCP wants to abort an existing connection, and lastly, when the TCP receives a segment for a connection which does not exist.
+   * A connect error can occur when a SYN sent from a client meets an ICMP destination unreachable error from some intermediate router. These sorts of error are also called soft errors.

We would be discussing about all types of TCP connect errors later in this chapter.

The bind function is used for assigning a local protocol address to a socket. The IP address is combination of a 32-bit IPv4 or 128-bit IPv6 address along with a 16-bit TCP or User Datagram Protocol (UDP) port. Listing 22.10 shows the signature of a bind function call:

The signature mentioned in Listing 22.10 is defined inside the <sys/socket.h> header. The first argument is the socket descriptor which is returned by the socket call. The second argument is the pointer to the protocol-specific address and the third argument is the size of this structure. Some characteristics of the bind call are as follows:

+   * A server generally binds to their well-known ports when they start. A TCP client or server is assigned ephemeral ports by kernel if it chooses not to use well-known ports. It is normal for a TCP client to let the kernel choose an ephemeral port for it to use. But a server must bind to a well-known port as servers are generally known for their well-known ports.

The kernel chooses an IP for the socket whenever the socket is connected. The selection of the IP address is based on the route required to reach to the server. If a TCP server doesn't bind an IP address to its socket, the kernel checks the SYN packet that has reached the server from the client. The kernel uses the destination IP address of the SYN as the server's source IP address.
