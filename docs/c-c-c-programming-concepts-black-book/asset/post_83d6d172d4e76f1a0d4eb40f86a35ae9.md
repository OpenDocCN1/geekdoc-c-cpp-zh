## Introduction to Programming Languages

A programming language can be defined as an artificial language that is used to deliver instructions to a machine to control its behavior. It is generally a set of notations provided to a user to perform a particular task. A programming language consists of two parts—syntax and semantics. With time, programming languages have evolved from their primitive forms and become much more user friendly. Programming languages are generally categorized into four groups:

- First generation programming languages
- Second generation programming languages
- Third generation programming languages
- Fourth generation programming languages

### First Generation Programming Languages

First generation programming languages (1GLs) were used to write code in a machine understandable form. That’s why they are also known as machine level languages. Machine level languages were purely written in the binary format by specifying the memory addresses in the code itself. Machine level languages are not in a human-understandable format and therefore difficult to work with. However, assembly level language happens to be more symbolic in nature. It implements a symbolic representation of the machine codes and other constants needed to program a given CPU architecture. The assembly language needs to be converted into the machine readable format, such as the binary format, to run it on a computer. This language was not made generic to all types of machines but can only run on some particular target machines or family of machines. This language was entirely dependent on the characteristics of the machine on which it is run.

An assembly level language is more flexible than a machine level language. In a machine level language, if at any point of instruction, you need to jump to some later instructions in the memory, then the exact memory address has to be specified. However, if the program is modified in such a way that the destination jump address changes due to the insertion of some instructions in between, then the entire program has to be changed accordingly. However, in case of the assembly level language, instead of specifying the destination address, the corresponding mnemonics can be used, such as jump to label 4. This mnemonic would enable a programmer to label the line where to jump and hence changing the code would not involve a complete change in all the instructions that call a jump instruction. The assembler will compile and load the program with all the jump statements correctly placed. The main benefit of programming in a first generation programming language is that the code written by a programmer runs very fast and efficiently, since it is directly executed by the CPU and a translator is not required to compile and assemble the program.

### Second Generation Programming Languages

Second generation languages or 2GLs are more English-like and capable of expressing the normal logic used by the programmers. These languages were introduced in late 1950s with FORTRAN. Second generation languages are used to employ a static storage model where data storage was allocated only once, i.e. when the program is loaded. This resulted in making recursions difficult. Algol, another second generation programming language, was used to provide block-structured naming constructs and expanded the set of features available to programmers, like concurrency management. The symbolic representation of machine instructions, registers, and memory addresses allows programmers to produce a human-readable program. An assembler is needed to convert the English-like language to mnemonics and then through one-to-one mapping technique, this mnemonic is translated to the corresponding machine-readable format. This language generates a machine-optimized assembly language version of a particular function. Second-generation languages are sometimes used in kernels and device drivers.

### Third Generation Programming Languages

Third generation programming languages (3GLs) were mainly introduced to overcome the limitations of 2GLs. 3GLs were developed in a way that they remain independent of the architecture of the computer on which the algorithm is run. Therefore, we can say that 3GLs were hardware-independent. The code written in a 3GL is first converted to the assembly language by a compiler and then the assembler translates the code from assembly language into the machine-readable form (binary form). While the steps to interpret 3GL were similar to those of 2GLs, there was no need for one-to-one mapping between codes, segments, and machine codes. 3GL compilers could target different hardware and produce different translations of the same source code commands.

Structured programming was practiced in 3GLs where a program model was seen as a hierarchy of nested blocks rather than a list of instructions. A particular set of instructions that is meant for repeated executions is kept under a block. This block is run the number of times the statements need to be repeated through the programming language itself. It did not use jump statements to move backward to execute some instructions again and again. Structured programming is used to expand many higher-level commands into a number of lower-level commands. The entire code was divided into many individual blocks, subroutines, and functions that can be run independently of other blocks of the same program, making it easier for many programmers to work on the same code at the same time. Once this coding style was introduced, it was retrofitted in all the languages, such as ALGOL and FORTRAN, which did not have it originally. The block structure style of programming allows less use of global variables. In this programming style, local variables are used to occupy memory locations only when their container block of code gets executed and not the entire time the program is running. 2GLs were used to concentrate more on the logical structure while 3GLs emphasized the usability of the same language, making them more user-friendly.

### Fourth Generation Programming Languages

The fourth generation programming languages or 4GLs were introduced with some specific purposes in mind, such as the development of commercial business software. 4GLs surpassed the 3GLs in terms of higher abstraction and statement power. 3GLs were structured languages but slow and prone to errors. 4GLs were developed by adding higher-level programming and methods to generate a language which was equivalent to 3GLs in respect to complexity but involved fewer errors. PL/SQL is an example of 4GL.
