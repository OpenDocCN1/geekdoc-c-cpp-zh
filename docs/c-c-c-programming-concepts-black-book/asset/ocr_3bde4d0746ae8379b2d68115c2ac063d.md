As the set() and showBase() functions are private members of the Derived class, accessing them in the main() function will cause compilation error. This is because when the access specifier of a base class is private or protected, the members of the base class become private members of the derived class. It implies that they are still accessible by the members of the derived class but cannot be accessed by parts of the program that are not the members of either the base class or the derived class. Therefore, to generalize the access specifier related problems as to which one to use and when, one thing can be done is to make every member's scope public rather than putting some of the members in public definition and others in private. However, in that case, if all the members of the class are made public, the data is going to be exposed to the outside world and security will be breached. Moreover, it is also not aligned with object-oriented programming principles of encapsulation. Therefore, C++ provides the solution for this problem in the form of **protected** access specifier. Let's learn more about it in the next section.

# ## Protected Access Specifier

Class members can always be accessed by functions of the same class, irrespective of the members being public or private. However, objects of a class defined outside of the class, such as in the main() function, can only access the public members of the class. The following program illustrates this concept:

    int b;

    object.a = 10; /* Error - 'a' is not a public member of Base */
    object.b = 9; /* Valid Access - as 'b' is a public member */
