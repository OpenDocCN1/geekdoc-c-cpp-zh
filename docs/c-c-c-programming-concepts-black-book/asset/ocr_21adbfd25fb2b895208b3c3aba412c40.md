In the preceding program, we have made a call to pthread_create() by using a pointer to a thread. In the pthread_create() call, the thread attribute is sent as NULL, the start function pointer is set to thread_function(), and thread_params is passed as an argument to pthread_create(). On the successful execution of pthread_create(), the main and child threads run in an overlapped manner giving the essence of parallelism. From the main() function, the main thread prints "In main" for 1000 times and the child thread prints "I'm thread" for 10000 times.

As the main thread loops for 1000 times and the child thread loops for 10000 times, the main thread will complete its execution before the child thread. This may lead to a critical issue in the preceding program. The child thread, which completes later than the main thread, remains in the system as a zombie thread. Zombie threads are a special kind of threads that have completed their execution but are still present in the table of active threads. They have nothing to do, but as they did not exit normally, they still hold the resources that they were using in their lifetime. The solution of this issue is the use of pthread_join(), which properly cleans the zombie threads; otherwise, the situation cannot be handled.

A call to pthread_join() from the main thread will make it wait for the child thread to finish first. Only then, the main thread can exit. The syntax of pthread_join() is as follows:

```
```c
int pthread_join (pthread_t thread_id,
                  void **retval);
```
```

The pthread_join() API waits for the thread identified by thread_id to terminate. Generally, a thread can terminate under the following circumstances:

+   * The thread calls pthread_exit().
+   * The thread returns from the thread function.
+   * The thread is cancelled.
+   * The thread in the process calls the exit() function or the main thread performs a return from the main() function. This terminates all the threads created by the process.

The retVal argument collects the return value from the terminated thread. If there is nothing to return, then NULL can be passed. In a multithreading environment, all the threads in a process are peers; therefore, during the execution cycle, any thread can join another thread in the process.
