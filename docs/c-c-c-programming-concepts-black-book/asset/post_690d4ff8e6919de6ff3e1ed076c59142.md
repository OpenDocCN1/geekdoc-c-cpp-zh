
```text
B[parentIndex] <- B[childIndex]
B[childIndex] <- temp
else
    do nothing
end
end
end
return B[0...k]
end
```

In the preceding algorithm, first, the Heap_Sort function is defined, where we build the heap using the Form_Heap function for the given array A[n]. After getting the initial heap, the root element is stored in the array A[n], which is used to hold the sorted elements. Then, the root element of the tree is replaced by the last element of the heap H[n]. After executing this function, the Form_Heap function is recursively called to rebuild the heap. This function continues until all the elements are sorted. On the other hand, the Form_Heap function traversed through the binary tree comparing the key value of the parent and the child nodes. If the key value of any child node is greater than its parent node, then the parent key value is replaced with the maximum key value of its child node. This way the heap is formed.

Now, let’s analyze the heap sort algorithm. In the heap sort, the complexity analysis is based on two procedures:

- 1. Building the heap each time after an element is removed from its last position
- 2. The initial for loop that executes to sort the array by removing the root element and placing the last element at the root position

The former procedure requires O(log n) time and the latter procedure requires O(n) time to execute. Therefore, the best case and the worst case complexities are same, that is, O(n log n). The Heap sort algorithm is more efficient than the merge sort algorithm, as it requires the memory only to store the heap. However, the stability issue is still there with the heap sort algorithm, as the order of equal elements may change during its execution. This counts as one of the disadvantages of heap sort along with the fact that this sorting technique is found somewhat difficult to understand for a beginner. However, as it implements the concepts of both heap and complete tree, its study is very effective and necessary to understand the data structure concept.

### Listing 24.40: Showing the Algorithm for Graph Sort

```text
function Topological_Sort(Graph G with n nodes)
begin
    Q <- Initialize the array to null to store the
         output topological ordering
    n <- Count of nodes in graph
    inDegree[n] <- Initialize this array to null to
                   store the in-degree of the node
    v <- Initialize an integer that holds the intermediate node.
    H <- G

    while H is not empty do
    begin
        //Step 1
        inDegree[n] <- Store the indegree count of the particular node
        //Step 2
        if(inDegree[n] == 0)
        begin
            //Step 3
            v <- nodes[n]
            n <- n - 1
            remove v and all its outgoing edges from H
            Insert v to Q
        end
    end
end
```

The preceding algorithm implements the graph sort based on the in-degrees count. At the beginning of the algorithm, an array inDegree[] is declared to hold the in-degree values of each node in the graph. An array Q acts as the output array and the array H holds the graph G, which consists of the array nodes[]. For each node in the graph, first, the in-degree values of the nodes are calculated and then they are stored in the array inDegree[]. If the in-degree value for any node is zero, then that node and its outgoing edges are removed from the graph H and that graph node is then inserted in the output array Q. This process decrements the node count of the graph by 1 and is repeated until graph H is empty. At the end of this process, Q holds the graph nodes in a sorted order that forms a path to reach the destination from the source that passes through each node.

The complexity of the algorithm depends on the number of nodes and the number of edges the graph contains. For a graph with N nodes and E edges, the complexity of the graph sort is calculated as O(E + V). Therefore, the best case, the worst case, and the average case complexities are the same for this sorting technique.
