# Object-Oriented Analysis

The object model has influenced even earlier phases of the software development life cycle. The conventional structured analysis emphasizes the flow of data within a system, whereas Object-Oriented Analysis (OOA) focus on real-world models using object-oriented view of the real world. Grady Booch defined OOA as:

> *Object-oriented analysis is a method of analysis that examines requirements from the perspective of the classes and objects found in the vocabulary of the problem domain.*

Precisely, how are OOA, OOD, along with OOP related? Essentially, the products associated with OOA functions as models from which we might start an object-oriented style; the products associated with object-oriented design may then be used like blueprints for completely implementing something using object-oriented encoding methods.

In an object-oriented approach, in the analysis phase, the emphasis is on discovering and describing objects in the problem domain.

In OOA, we focus on doing the right thing. OOA includes:

+   - **Use Case Model** – It captures the functionality the system should provide from the user’s perspective. It does not specify how the system actually implements the system. In essence, it helps to systematically identify the system’s responsibilities from the user requirements perspective.
+   - **Use Cases** – It includes stories or scenarios of how people use the system.
+   - **Use Case Diagram** – It gives a high-level view of how different users interact with the system through use cases.

Thus, Use Case Model = Use Cases + Use Case Diagrams.

In OOA, we have two types of model to define any scenario: one is Use Case Model and the other is Domain Model. The use case model consists of use case templates and use case diagram. We can define use cases of a scenario as the goals set for the system to achieve and/or it must produce. It mainly describes the interaction between the user and the system. Textual descriptions use in use cases generally express several scenarios. In a single sentence, we can define use case as a set of goals performed by the system, which is of value for one or more actors and other stakeholders of the system. The use case model, on the other hand, can be defined as below:

+   - Use Case Model captures the functionality of the system that should be provided from the user’s perspective.
+   - It does not specify how the system actually implements the system
+   - In essence, it helps to identify responsibility of the system in user requirement perspective

In the use case model, users are defined either as an actor or as a stakeholder, where actors of the system are bound to achieve some goals, whereas the stakeholders do not always need to achieve any goals. We will mainly deal with actors while documenting or diagrammatically representing use case model.
