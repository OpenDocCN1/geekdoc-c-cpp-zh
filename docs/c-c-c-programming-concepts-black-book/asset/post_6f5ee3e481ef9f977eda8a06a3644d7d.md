
```cpp
int F2(int value)
{
    if (value < 0)
        throw E1();
    else if (value > 100)
        throw E2();
}
int F1(int value)
{
    .....
    myvalue = F2(value);
    return 2*myvalue;
}

int main()
{
    int a;
    try {
        a = F1(-9);
    }
    catch (E1) {
        cout << "E1" << endl;
        .....
    }
    return 0;
}
```

In the preceding example, main() calls F1(), which calls F2(). As F2() is passed a value less than zero, an exception of type E1 is thrown. Moreover, since no exceptions are caught in F2(), execution jumps out of F2() and goes back to F1(). The variables of F2() are removed from the stack and any destructor for local objects is called. This is called **unwinding the stack**. Again, the F1() function does not catch any exception; therefore, its variables are removed from the program stack. Any destructor for local objects is called. The stack is further unwound. Now, we have reached main(). In this case, the exception is caught and handled.

Exactly what would happen in case main() did not capture the exception? This is actually the case with E2. The variables of main() function will be removed from the stack and any destructor will be called. As no handler is located, the **terminate()** system function is called and the program aborts, but this is undesirable. Attempts should be made to capture and handle all the exceptions.

Next, let's discuss how uncaught exceptions are handled.

## Uncaught Exceptions

If we do not have any catch declaration for the exception that is thrown, then the program terminates abnormally. Throwing an unhandled exception causes the conventional library function **terminate()** to be invoked. By default, **terminate()** calls **abort()** to prevent a program from unexpected terminations. Consider the following example:

```cpp
#include <math.h>
using namespace std;
double FSQRT(double X)
{
    // if the user entered a negative number, this is an error condition
```

As there is no specific exception handler for type int, the exception is caught by the catch-all handler. The output of the preceding program is as follows:

```text
we have caught an exception of an undetermined type
```

## Restricting Exception

The throw clause in a function definition specifies the type of exceptions the function is expected to throw. Using the throw clause, we can restrict the type of exceptions that a function can throw by specifying a comma-separated list of exception types within the throw clause. Throwing any other exception will cause abnormal program termination.

The generic declaration of the exception consists of using the throw keyword followed by a list of all the possible types of exceptions. Therefore, we can declare a function as:

```cpp
void f() throw(VeryBig, VerySmall, divideByZero);
```

The function declaration f() signifies that any possible type of exception can be thrown from the function and void f() throw() signifies that there is no exception to be thrown from the f() function.

We should always use an exception specification while writing a function that throws an exception. This ensures good coding standards and good documentation. It also makes easier for us to use the function caller.

There might be situations within a program where we throw something than what appears as the exception specification. In such cases, a special function unexpected() is called. By default, unexpected() causes abort() to be called, which causes abnormal program termination. Presence of throw() with empty parenthesis indicates that the function within which it is defined, is not expected to throw any exception.

The general form of the throw clause is:

```cpp
return_type function_name (argument_list) throw(type_list)
{
    //-
}
```

Consider the following piece of code where we have considered the RestrictHandler() function that can only throw an int, char, and double:

```cpp
#include <iostream>
void RestrictHandler(int test) throw(int, char, double)
{
    if (verify==0) throw verify;  // throw int
    if (verify ==1) throw 't';    // throw char
    if (verify ==2) throw 346.47; // throw double
}
int main()
{
    cout<< "Start\n";
    try
    {
        RestrictHandler(0); // also, try passing 1 and 2 to
                            // RestrictHandler()
    }
    catch (int i)
    {
        cout<< "Caught int\n";
    }
    catch (char c)
    {
        cout<< "Caught char\n";
    }
    catch (double d)
    {
        cout<<"Caught double\n";
    }
        cout<<"end";
        return 0;
}
```

In the preceding program, the RestrictHandler() function can only throw the integer, character, and double exceptions. If it attempts to throw any other type of exception, then an abnormal program termination will occur.

Let's now learn how to catch an exception.

## Catching any Exception

The catch block is used to catch the exceptions in a program whenever such exceptions occurred within the program. This block generally follows the try block. We can specify the type of exception that we wish to catch in the catch block. This is determined by the exception declaration, which is mentioned within the set of parenthesis that follows the catch keyword.

The generic syntax of the catch block is as follows:

```cpp
try
{
    // Code ...
} catch (NameofException e)
{
    // code snippet that handles NameofException exception
}
```

If a function has zero exception specification, then any sort of exception can always be thrown. One solution to the present problem is to generate a handler that catches any sort of exception. This is done by using the ellipses in the argument list of catch(), shown as follows:

```cpp
catch(...)
{
    cout<<"An exception was thrown" << endl;
}
```

In the next section, let's learn how to re-throw an exception.

## Re-throwing an Exception

To re-throw an expression from within an exception handler, we can write a code block in such a way that we can call the throw statement with no exception in it. This will result in passing the current exception on to an outer try/catch sequence. Consider the following code:

```cpp
catch(...)
{
    cout<<"Let us throw this exception" << endl;
    throw;
}
```

Re-throwing an exception is mainly done to give multiple handlers access to the exception. We can only re-throw an exception from within a catch block or from any function called from within that block. In such cases, it will not be re-caught by the same catch statement; rather, it will propagate outward to the next catch statement. Consider the following example to illustrate the concept of re-throwing an exception:

```cpp
#include <iostream.h>
using namespace std;
void Rhandler()
{
    try
    {
        throw "Hi! I am in try";                 // throw a char *
    }
    catch (char *)
    {
        // catch a char *
        cout << "Hi! Caught char * inside Rhandler\n";
        throw;                                   // rethrow char * out of function
    }
}
int main()
{
    cout << "Starting the demo.\n";

    try
    {
        Rhandler();
    }
    catch (char *)
    {
        cout << "Hi! Caught char * inside the main() function\n";
    }
    cout << "Ending Demo...";
    return 0;
}
```

The output of the preceding program is as follows:

```text
Starting the demo...
Hi! Caught char * inside Rhandler
Hi! Caught char * inside the main() function
Ending Demo...
```

## Handling Derived Class Exceptions

As the argument type of catch applies to the objects of base classes as well as to the classes derived from the base classes, the order of declaring the catch handlers is important. Handlers from the specific derived objects must appear prior to the handlers of base classes. It is also possible to create handlers that would not execute; for example, by placing a handler for any derived class after a handler for its corresponding base class. The following code demonstrates how an exception handler does not execute, as its base class exception handler catches every exception:

```cpp
catch(CBaseException& ex)
{
    // Handle a base type of exception
}

catch(CDerivedException& ex)
{
    // This handler would never ‘run’ because its base would catch everything
    // it can
}
```
