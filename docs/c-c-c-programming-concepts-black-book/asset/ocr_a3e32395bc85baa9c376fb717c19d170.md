As the comment in the preceding code snippet indicates, the statement does not raise any error because C++ automatically converts the character ‘a’ into its double equivalent. Although automatic type conversions are convenient, they are the prime source of ambiguity. Let’s consider an example of two functions that have the same name and both of them takes one argument each. Suppose one of them takes a floating point variable as an argument and the other takes a double variable as an argument. Now, due to C++ automatic type conversion mechanism, when a call to the function will be made with a fractional argument, the compiler will not be able to decide which one to call; thereby, giving rise to an ambiguous situation. Let’s understand more about this concept from the following program:

In the preceding program, the example() function is overloaded so that it can take arguments of either float type or double type. In line number 10, the call to example (10.32) function is unambiguous because unless otherwise specified as float, all the floating point constants in C++ are automatically of the double type. However, when example() is called using an integer value in line number 11, ambiguity is introduced because the compiler has no way of knowing whether the parameter should be converted into a float type or a double type. Therefore, in this situation, the compiler causes an error message to be displayed failing the compilation process, and leaving the ambiguity resolution to the programmer.
