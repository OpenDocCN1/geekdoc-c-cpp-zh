This chapter mainly focuses on network sockets. A network socket is described as an endpoint of an inter-process communication taking place over a network. A socket is identified with the help of a socket address. A socket address for a Transmission Control Protocol (TCP) connection is defined as the grouping of an Internet Protocol (IP) address and a port. It uniquely identifies every TCP connection on the Internet. This chapter mainly provides the description of different sockets Application Programming Interface (API) that uses network sockets. Before describing the socket APIs, let us take a look at the socket structures that are passed to each and every sockets API.

# Socket Address Structure

As an argument, a pointer to a socket address structure is required by most socket functions. The socket address structures of the different protocol suites are defined by themselves. The naming convention of these structures starts with sockaddr_ and concludes with a distinct suffix for every protocol suite.

IPv4 sockets address structures are identified by the naming convention sockaddr_in, where in stands for Internet socket address. The structure is defined inside the header file <netinet/in.h>. Listing 22.1 shows a detailed description of the structure:

**Listing 22.1:** Describing the sockaddr_in structure

```
```c
struct in_addr {
    in_addr_t   s_addr;                 /* 32-bit IPv4 address network byte ordered */
};

struct sockaddr_in {
    uint8_t     sin_length;             /* length of the structure */
    sa_family_t sin_family;             /* AF_INET */
    in_port_t   sin_port;               /*16bit UDP or TCP port number */
    struct in_addr sin_addr;            /* 32 bit IPv4 address network byte ordered */
    char        sin_zero[8];            /* unused */
};
```
```

With the help of the preceding listing, some important points that are worth mentioning about socket address structures are as follows:

+   - The socket address structure mentioned in Listing 22.1 conforms to the POSIX.1g standards. The first member of this structure, that is, sin_length, was introduced during the release of 4.3BSD-Reno with the support for Open Systems Interconnection (OSI) protocols. Prior to the release of 4.3BSD-Reno, sin_family was the first member of this structure. The length field is not widely supported across all vendors for socket address structure, although the inclusion of the sin_length field helps in handling variable-socket address structures.
+   - Although the sin_length field is present in the structure, it is never set or examined. The field is used within the kernel when routing sockets are used.
+   - Only the three members, that is, sin_family, sin_addr, and sin_port, of the sockaddr_in structure are required by the POSIX.1g standards. Any POSIX compliant implementation is free to add its own structure members. For example, most of the implementations add the sin_zero field to their sockaddr_in address structure.
