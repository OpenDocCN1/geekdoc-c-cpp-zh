The specific floating-point precision determines the number of digits written upon the insertion operations to convey the floating-point values. How that is interpreted depends upon the floatfield structure flag defined to some specific notation (each fixed or scientific) or it truly is unset (while using particular default notation, which is neither fixed nor scientific). Consider the following program:

```
```cpp
#include <iostream>
using namespace std;

int main ()
{
double f = 8.68768;
cout.setf(0,ios::floatfield);        // floatfield not set
cout.precision(5);
cout<< f << endl;
cout.precision(12);
cout<< f << endl;
cout.setf(ios::fixed,ios::floatfield);   // floatfield set to fixed
cout<< f << endl;
return 0;
}
```
```

The output of the preceding program is given as follows:

```
```
8.68767
8.687680
8.687680000000
```
```

Notice that the first number written is just five digits lengthy, while the second number is six digits lengthy, but not much more, even though the actual stream’s precision should be 12. This happens because precision with the whole default float area only specifies the most number of digits being displayed, although not the particular minimal. The third quantity displays the 12 digits following the decimal point, as the float field structure flag is in this case set to fixed.

> > **NOTE**
> >
> > With the exception of the field width, all the format parameter settings are permanent. The field width parameter is reset after each use.
