# Blocking I/O Model

The most basic I/O model used in networking is called blocking I/O model. All the sockets are blocking by default. Let us take an example of a UDP message exchange which becomes easier to discuss, as in case of UDP, we can easily conclude whether a datagram has been received or not. Let us take an example of a system call "recvfrom," which expects data from a UDP socket and tries to read it. Figure 22.6 shows a blocking I/O model:

![](bbox=[0.28, 0.26, 0.75, 0.405])

The preceding figure shows that a system call made to "recvfrom" gets blocked until the kernel finds that information has arrived on that socket. The moment information arrives on the socket, the function call is returned to the process.

# Non-Blocking I/O Model

We can set a socket to a non-blocking I/O model. Setting the socket to non-blocking means that we are signaling the kernel when an I/O operation requested by the process that fails to complete the process should not be put to sleep, but an error should be returned in return.
