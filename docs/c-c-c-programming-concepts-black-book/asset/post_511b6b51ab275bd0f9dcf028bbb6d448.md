Also, in ATM, to withdraw money, the machine needs to verify the card identity. Thus, withdrawing money from the ATM includes card verification process. In UML, a link is placed between the “whole” and “part” classes with a diamond head attached to the whole class to indicate that this association is an aggregation.

Aggregation is a concept that is used to express “part of” types of associations between objects. An aggregate is conceptually an extended view of a unit by some operations, but it can actually be composed of multiple objects. One aggregate may contain multiple **whole-part** structures, each viewable as a distinct aggregate. Components may or may not exist in their own right and they may or may not appear in multiple aggregates.

Since aggregation is a special kind of association, it adds additional meaning in some cases. Two objects form an aggregate if connected tightly by a **whole-part** relationship. But how to identify whether it is aggregation? Grady Booch had put forward some valuable questions to test whether a relation is an aggregation or not:

- Would you use the phrase “part of” to describe it?
- Are some operations on the whole automatically applied to its parts?
- Are some attribute values propagated from the whole to all or some parts?
- Is there an intrinsic asymmetry to the association, whether one object class is subordinate to the others?

If the answer to all the preceding questions is yes, then the relation is an aggregation.

Let us think of the Java language. A relation between class A and class B is aggregation if class A maintains an ArrayList of class B and the constructor of class A does not create an object of class B. Also, if class B is freely floating, then it is called aggregation. Figure 23.17 shows the aggregation relation:

## Object Allocation

Objects in Java are usually dynamically allocated (produced). It is also feasible for an object to dynamically reallocate memory employed for its own variables. The origin of the word "class" is to consider a collection of items with related behaviors like a class, a mathematical notion much like a set of individual objects. Rather than defining the behavior for every object individually, a class definition gives the behaviors that'll be possessed by all objects within the class. The objects themselves are occasionally called members of the actual class, again alluding to the set-like qualities of the class. It is also sometimes said that the particular object is an instance of the class.

### Name

Each class has a name, a Java identifier. The name effectively becomes a **type name**, so is usable anywhere a type would be usable.

### Constructor

The actual *constructor* identifies the guidelines and code for initializing a new object. Syntactically, it appears like a procedure and uses the name from the class as the constructor name. The constructor is called when an object is created dynamically or automatically. The constructor doesn't return a value within its syntactic structure. A constructor is always called using the *new* operator.

### Methods

Methods are like procedures that provide an interface between the object and the program using the object. As with ordinary procedures, each method has an explicit return type or specifies the return type void.

### Variables

Every time an object is created, like a "member" of a class, the system allocates another set of variables internal to it. These variables are accessible to each one of the methods associated with the object without explicit declaration within the method. *In other words, the variables local to the object look as if global to the methods, without necessitating re-declaration.*

The reason behind the preceding emphasis is that utilization of objects can provide a convenience when the amount of variables would otherwise become too large to be treated because procedure parameters and utilization of global variables might be considered a temptation.

## Static versus Instance Variables

An exception to using a separate copy of the variable for each object occurs with the idea of *static variable*. When a variable inside a class is declared static, there's only one copy shared by all objects within the class. For example, a static variable can keep a counter of the number of objects allocated in the actual class if that had been desired. For that matter, a static variable could maintain a summary of references to all objects created inside the class.

When it is essential to distinguish a variable from the static variable, the term *instance variable* is usually used in accordance with the variable being of a particular object instance. Occasionally, static variables are known as *class variables*.

Similarly, a *static method* is one that does not depend on instance parameters, and the state of the object. A static method may rely on static variables, however. Static methods are thus analogous to procedures or possibly functions in ordinary languages.

A final note on classes raises a thread in program development. It has become common to provide algorithms using *Abstract Data Types (ADTs)* that are viewed as mathematical structures associated with procedures and functions for dealing expressly with these structures. For example, a typical ADT might be a collection accompanied by functions with regard to constructing sets, testing membership, forming unions, etc. Such structures are seen as the behavioral interaction of these functions rather than through the internal representation used in order to implement the structure.

Classes seem to be a very appropriate tool for defining ADTs and enforcing the disciplined use of their functions and procedures.
