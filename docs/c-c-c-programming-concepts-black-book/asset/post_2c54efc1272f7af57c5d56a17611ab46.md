### IPv6 Socket Address Structure

The IPv6 socket address structure is defined inside the header <netinet/in.h> and appears as follows:

```c
struct in6_addr {
    uint8_t              s6_addr[16];    /* 128 bit IPv6 address network byte ordered */
};

struct sockaddr_in6 {
    uint8_t              sin6_len;       /* length of the structure */
    sa_family_t           sin6_family;    /* AF_INET6 */
    in_port_t             sin6_port;      /* IPv6 port network byte ordered */
    uint32_t              sin6_flowinfo; /* priority and flow label */
    struct in6_addr       sin6_addr;      /* IPv6 address Network Byte Ordered */
};
```

Some important remarks of the IPv6 socket address structure are as follows:

- The sin6_len should be defined if the length member of the socket address structure is supported by the system.
- The IPv6 family is AF_INET6.
- The sin6_flowinfo member is divided into the following three fields:
  - The lower order 24 bits are called flow label.
  - The next 4 bits are priority.
  - The next 4 bits are reserved.

### Byte Ordering Functions

Before going into the depth of socket APIs, we need to understand the byte ordering of variables that takes place in network programming. Let us consider a 16-bit integer which is made up of two bytes. We have two ways of storing the number in memory. In the first method, we store the lower byte at the starting address, which is known as little endian method. The second method is to store the higher order byte at the starting address, which is known as big endian method. The two methods are explained in Figure 22.1:

![](img/43c5f409f9b17790a628c4b4df854b61_767_0.png)

**Figure 22.1: Explaining the Little Endian Method and Big Endian Method**

It can be seen in the preceding figure that for little endian byte order, the memory is getting increased from right to left fashion. For big endian, the memory increases from left to right fashion. Byte ordering used by a system is known as host byte order. Listing 22.3 displays a host byte order:

**Listing 22.3: Illustrating a host byte order**

```c
#include <stdio.h>

int main()
{
    unsigned short lower, varA = 0x0201;

    lower = varA&0x0003;

    if(lower == 1)
    {
            printf("\n Little Endian System");
    }
    else
    {
            if(lower == 2)
                    printf("\n Big Endian System");
            else
                    printf("\n unknown  System");
    }

    getch();

    return 0;
}
```

In the listing, we store a 2 byte value 0x0102 inside a short integer; then, we mask the higher order byte off and only take the lower order byte into account. If the lower order byte comes out to be 2, then we can say that the host is little endian. If the lower order byte happens to be 1, then the host is big endian. Byte ordering of a 16-bit integer is same as byte ordering of a 32-bit integer. Different hosts can have different byte orders, but all of them must agree upon a unique byte ordering for communicating over a network. This is called network byte order. The IPs use big endian byte ordering for transmitting multi-byte integers. A typical client or server implementation could have taken the overhead of converting to and from network byte order. But the problem occurs for those fields which need to be kept in network byte order. To have inter-conversion between two byte orders, we have certain APIs, which are described in Listing 22.4:

Listing 22.4: Showing prototypes of different byte ordering functions

```c
uint16_t htons(uint16_t host16bit);

uint32_t htonl(uint32_t host32bit);    /* Both the API's return the value in Network
                                          Byte Order */

uint16_t ntohs(uint16_t net16bit);

uint32_t ntohl(uint16_t net32bit);     /* Both the API's return the value in Host
                                          Byte Order */
```

In Listing 22.4, the letter n stands for network, h stands for host, s stands for short, and l stands for long. The functions are used independent of the endianness of a system. If a system happens to be big endian, then the functions have no effect on the conversion. All the functions mentioned in Listing 22.4 are defined in the <netinet/in.h> header.

### Byte Manipulation Functions

Before starting to understand network programming, one needs to understand multi-byte operations taking place on data coming over network. Generally, we have two groups of functions that deal with multi-byte fields; these functions do not assume the data to be null-terminated string, as illustrated in Listing 22.5:

Listing 22.5: Showing prototype of functions dealing with multi-byte fields

```c
void bzero(void *dest, size_t nbytes);

void bcopy(const void *src, void *dst, size_t nbytes);

int bcmp(const void *ptr1, const void *ptr2, size_t nbytes);
```

The functions stated in Listing 22.5 are defined inside the `<strings.h>` header. The function bzero sets specified number of bytes to 0 in the destination. The number of bytes is denoted by the argument nbytes and the destination is denoted by the void *dest pointer. The specified number of bytes from source to destination is moved by bcopy and the comparison of two arbitrary byte strings is done by bcmp. If both the strings are identical, then bcmp returns zero; else, it returns a nonzero value. There are some more functions as well which are used for memory-related operations, as shown in Listing 22.6:

**Listing 22.6:** Showing functions used for memory-related operations

```c
void *memset(void *dest, int c, size_t nbytes);

void *memcpy(void *dest, const void *src, size_t nbytes);

int memcmp(const void *ptr1, const void *ptr2, size_t nbytes);
```

All the functions mentioned in Listing 22.6 are defined inside the <string.h> header. The function memset is used for setting specified number of bytes in a variable to c. The number of bytes is mentioned by the parameter nbytes. The function memcpy is used for copying nbytes from the variable src to the variable dest. The comparison of two variables for a length of nbytes is done by the function memcmp. The function returns zero if two variables are identical; else, a non-zero value is returned.

### Address Conversion Functions

IP address used in network programming can be represented in two ways, they can be in either American Standard Code for Information Interchange (ASCII) strings, which are preferable for programmers, or network byte ordered binary values. The network byte ordered binary values are stored inside the socket address structures. In this section we are going to discuss about two groups of functions, one which converts ASCII strings to network byte ordered binary and vice versa. Listing 22.7 describes a group of functions which performs such interconversions:

**Listing 22.7:** Showing functions that perform address interconversion

```c
char *inet_ntoa(struct in_addr in);
    /* Returns pointer to dotted decimal string */

int inet_aton(const char *cp, struct in_addr *inp);
    /* Returns 1 if string was valid, 0 on error */

in_addr_t inet_addr(const char *cp);
    /* Returns 32 bit binary network byte ordered
                         IPv4 address */
```

In the listing, the function inet_ntoa function is used for converting a 32-bit binary network byte ordered IPv4 address to its corresponding dotted decimal string format. The function returns a dot and a number string inside a static buffer which gets overwritten every time the function gets called.

The function inet_aton which is used for converting the string pointed by cp to a 32-bit binary network byte ordered value which is stored inside the pointer inp. The function returns non-zero if the address is a valid one; else, the function returns zero.
