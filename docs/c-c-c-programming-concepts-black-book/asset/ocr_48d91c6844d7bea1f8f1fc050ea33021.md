# Static versus Instance Variables

An exception for using a separate copy of the variable for each object occurs with the idea of *static variable*. When a variable inside a class is declared static, there's only one copy discussed by all objects within the class. For example, a static variable can keep a counter of the amount of objects allocated in the actual class if that had been desired. For that issue, a static variable could maintain a summary of references to all objects created inside the class.

When it is essential to distinguish a variable from the static variable, the term *instance variable* is usually used in accordance with the variable being of a particular object instance. Occasionally, static variables are known as *class variables*.

Similarly, a *static method* is one that does not depend on instance parameters, and the state of the item. A static method may rely on static variables, however. Static techniques are thus analogous in order to procedures or possibly feature in ordinary languages.

Your final note on classes issues a thread in formula development. It has become common to provide algorithms using *Abstract Information Types (ADTs)* that are viewed as mathematical structures associated with procedures and functions for dealing expressly with one of these structures. For example, an average ADT might be a collection accompanied by functions with regard to constructing sets, testing regular membership, forming unions, etc. Such structures are seen as the behavioral interaction of these functions rather than through the internal representation used in order to implement the structure.

Classes seem to be a very appropriate tool for defining ADTs and enforcing the disciplined use of their functions and procedures.
