# Interrupt Service Routine

Interrupt Service Routines or interrupt handlers are callback functions that are triggered by an interrupt. In several operating systems, Interrupt Service Routines are often divided into two parts: First-Level Interrupt Handler (also called hard interrupt handler) and Second-Level Interrupt Handler (also called soft interrupt handler).

The main job of a First-Level Interrupt Handler is to quickly serve an interrupt. This happens by switching to Interrupt Service Routine and executing it. First-Level Interrupt Handlers are also used for masking interrupts.

Second-Level Interrupt Handlers complete a long interrupt processing task similar to that of an independent process. In Linux, each Second-Level Interrupt Handler has an independent kernel thread associated to it for its execution.

When Interrupt Service Routines are executed for devices, they are known as device drivers; whereas, when they are executed by software, they are known as exceptions, signals, or trap handlers. A hardware interrupt is generated by a device or port when it is ready to perform an action or it has completed its assigned action. It generates a call to an Interrupt Service Routine. An interrupt caused due to runtime exception, such as divide by zero, is called a trap. When a runtime exception occurs, it generates a software interrupt, which is regarded as a signal or an exception that invokes an Interrupt Service Routine.

# Case Study on ARM Architecture

ARM stands for Advanced RISC Machine. It is the most widely used 32-bit Reduced Instruction Set Computer (RISC) Instruction Set Architecture (ISA). The ARM architecture includes several features of RISC, such as support for using register file load/store architecture. Using this feature, data processing operations are only made on registers and their contents; thereby, reducing the direct operations on memory. All the load/store instructions are determined from registers, as addressing modes used for this purpose are much simpler.

The ARM processor is also known as an A32 processor because it has a fixed length (32-bit) instruction set. ARM instructions are generally 32-bit wide and aligned on 4-byte boundaries. ARM processors are used in smart phones and personal digital assistants.
