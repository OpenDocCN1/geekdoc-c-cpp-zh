The type of mutex determines what happens when a thread tries to lock a mutex on which it has already acquired a lock. Following are the three types of mutex available in Linux:

+   - **Fast Mutex (default)**—Mutex of this type cannot detect a deadlock. A thread will deadlock if it tries to relock this mutex without first unlocking the mutex. This type of mutex is implemented using `PTHREAD_MUTEX_FAST_NP`.
+   - **Error Checking Mutex**—Mutex of this type provides error checking. A thread will return an error if it tries to relock this mutex without first unlocking the mutex. This type of mutex is implemented using `PTHREAD_MUTEX_ERRORCHECK_NP`.
+   - **Recursive Mutex**—A thread will succeed in locking this mutex if it tries to relock this mutex without first unlocking the mutex. Multiple locks of this mutex will require the same number of unlocks to release the mutex before another thread can acquire the mutex. This type of mutex is implemented using `PTHREAD_MUTEX_RECURSIVE_NP`.

To initialize, destroy, lock, and unlock a mutex, we can use the following statements:

+   - The following API is used for the initialization operation:
+     ~~~c
+     int pthread_mutex_init (pthread_mutex_t * restrict mutex, const pthread_mutexattr_t
+     *restrict attr);
+     ~~~
+   - The following statement declares a static mutex with default attributes:
+     ~~~c
+     static pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
+     ~~~
+   - The following statement initializes a mutex attribute:
+     ~~~c
+     int pthread_mutexattr_init(pthread_mutexattr_t *attr);
+     ~~~
+   - The following statement destroys a mutex attribute:
+     ~~~c
+     int pthread_mutexattr_destroy(pthread_mutexattr_t *attr);
