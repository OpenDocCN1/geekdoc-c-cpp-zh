## Overview of OOP Principles

In this world, we can find ourselves surrounded by objects, such as computers, refrigerators, coffee machines, and books. Some of these objects operate on their own, whereas, some objects interact with each other. Objects have two inherent properties – *state* and *behavior*. Many objects are similar in behavior, but they may differ in purpose. Similarly, a same action can cause an object to do various things.

Object-oriented concepts encompass three main principles – *encapsulation*, *inheritance*, and *polymorphism*.

Let’s look closely at these terms and find out what they really mean.

### Encapsulation

**Grady Booch** defined encapsulation as “the process of compartmentalizing the elements of an abstraction that constitute its structure and behavior; encapsulation serves to separate the contractual interface of an abstraction and its implementation.”

Encapsulation is defined as the process of hiding those details of an object that do not contribute to the significant characteristics of that object. It hides the implementation details of the object and only exposes the interface of the object, that is, the group of all the messages to which the object can respond. Encapsulation assists in separating an object’s execution from its behavior to restrict the use of its internal information. It also helps in retaining the integrity of the object; thereby, restricting the external users to set the internal implementation of the object to an invalid or inconsistent state. Therefore, encapsulation reduces the complexity by restricting the interdependencies between objects.

Encapsulation and abstraction are two concepts in OOP that are closely linked to each other, but in many cases, they are used synonymously by mistake. This is because abstraction is a process and the act of determining the relevant characteristics and behaviors that an object should possess. On the contrary, encapsulation is the mechanism through which the abstraction is actually implemented. Therefore, the two terms should not be confused.

### Inheritance

The generalization hierarchy associates with it the idea of the process of inheritance. Two major types of inheritance are structural and behavioral. In the structural inheritance, a subclass inherits the attributes of its superclass. Suppose an employee class has name, address, and salary as its attributes. Then, a subclass, say engineer, can also be defined by using these attributes. In the behavioral inheritance, a subclass is said to inherit the methods of its superclass. Suppose the employee class has a method, calculatePay(). Then, a subclass, say manager, can also be characterized using this method.

A subclass also participates in the relationship sets in which its superclass participates. If a subclass has some subclasses specified on it, then it forms a hierarchy or a lattice. The class-subclass relationship is represented by a Directed Acyclic Graph (DAG). This is particularly useful when objects can be classified in more than one way, which are independent of each other.

If in a hierarchy, a given entity set is involved as a lower-level entity set in only one ISA relationship, then the entity set has **single inheritance**. Figure 13.9 shows the concept of single inheritance:

In a lattice or hierarchy, a subclass inherits the attributes not only of its direct superclass but also of all its predecessors. A subclass with more than one superclass is called a shared subclass. A shared subclass is a subclass in more than one distinct superclass–subclass relationship, where each relationship has a single superclass. Figure 13.10 shows the concept of multiple inheritance:

### Polymorphism

In OOP, polymorphism implies a language’s capability to handle an object differently depending on its runtime. Objects can communicate with each other by sending and receiving messages. The advantage associated with polymorphism is that the sender of a message need not know about the class of the receiver. It only needs to know that the actual receiving object is capable of doing a particular conduct.

Polymorphism refers to the ability of two or more objects that belong to different classes to respond in different class-specific ways towards the same message. Figure 13.11 provides a better understanding of polymorphism:

## Genesis of C++

C++ is a superset of C, and therefore, it is backward compatible with C. C++ finds its application over a vast spectrum comprising application programs, system programs, embedded systems, high performance client/server applications, and entertainment software.

Factors that led to the evolution of C++ are as follows:

- Increasing complexity of the problem domain
- Difficulty in capturing the complexity of the problem domain through procedural languages, such as C, Fortran, and Pascal
- Difficulty in modeling real-world objects through procedural languages

## OOP, Objects, and Classes

OOP is an approach that provides a way of modularizing applications by creating partitioned storage area with each data and function used as templates with regard to creating copies associated with the modules on demand. Salient features of OOP are shown in Figure 13.13:

![](img/43c5f409f9b17790a628c4b4df854b61_377_0.png)

The advantages of OOP may be enumerated as follows:

- [ ] Provides better understanding of the system, which is achieved by **modularity**
- [ ] Combines data and behavior into one package, which is known as an **object**. The advantage of this combination is as follows:
  - Separate development teams can work independently
  - An object class can be developed, reused, or purchased
  - Update operation may affect a limited number of object classes
- [ ] Avoids duplication of common behavior with the use of **hierarchy** or **inheritance**. The reasons of such avoidance are as follows:
  - Behavior depends on the individual object
  - New kinds of objects can be added later without any harm
- [ ] Changes the implementation of an object without affecting its behavior
- [ ] Reduces the risk of building complex software systems

An object is defined as something that can perform a set of related activities. The set of activities performed by an object defines the behavior of the object. For example, the Employee object can give a name or address. Object has state and exhibits some well-defined behavior. The state of an object includes all the properties of the object, which are static. The values of these properties are dynamic in nature. Identity of an object distinguishes it from all the other objects. In C++, an object is a region of storage with associated semantics and can be declared as follows:

```cpp
int a;
```

The preceding declaration specifies that a is an object of type int.

Within the context of the object model of C++, the word object refers to an instance of the class. A class defines the actual behavior of several objects. Objects are often referred through references, which are aliases to an object. Bjarne Stroustrup in his book, *The C++ Programming Language (Second Edition, Addison-Wesley, 1992)*, said that *the obvious implementation of a reference is as a (constant) pointer that is de-referenced each time it is used.*
