
- Postfix Notation—In this type of notation, operators are written after their operands. The operators are evaluated from right to left and they act on the two nearest values on the left. In the postfix notation, the addition expression between A and B would be as follows:

  AB +

The postfix notation is also known as Reverse Polish notation.

Now, let's learn about various asymptotic notations that are used to describe the complexities of algorithms.

## Complexity of an Algorithm

An algorithm is a sequence of instructions that takes data as input and transforms it into output. Therefore, it is a well-defined set of instructions to manipulate the data given by a user or machine. Complexity of an algorithm is defined as a function that calculates the time required to complete the set of instructions (time complexity) and the space required to store the intermediate data (space complexity). Therefore, we can say that complexity is the time and space used by an algorithm.

Complexity of an algorithm is expressed using certain notations known as asymptotic notations. These asymptotic notations help in comparing the complexities of two algorithms. Following are different types of asymptotic notations:

- Big "Oh" notation
- Big "Omega" notation
- Big Theta notation
- Small "Oh" notation
- Small "Omega" notation

Let's start the discussion with the Big "Oh" notation.

### Big “Oh” Notation

Big “Oh” or Big-O notation is used to express the upper bound of runtime of an algorithm. Generally, it can be defined as follows:

For function g(n), Big-O of n (O(g(n))) is defined as,

\[
O(g(n)) = \{ f(n) : \text{there exist positive constants } c \text{ and } n_0 \text{ such that } 0 \leq f(n) \leq cg(n)\ \forall n \geq n_0 \}
\]

The running time O(n²) means that there is a function f(n) which is equal to O(n²) such that for any value of n, no matter what particular input of size n is chosen, the running time of that input is bounded from above by the value f(n).

### Big “Omega” Notation

Big “Omega” or Big-Ω notation is used to express the lower bound of runtime of an algorithm. Generally, it can be defined as follows:

For function g(n), Big-Ω of n (Ω(g(n))) is defined as:

\[
\Omega(g(n)) = \{ f(n) : \text{there exist positive constants } c \text{ and } n_0 \text{ such that } 0 \leq cg(n) \leq f(n)\ \forall n \geq n_0 \}
\]

The running time Ω(n²) means that there is a function f(n) which is equal to Ω(n²) such that for any value of n, no matter what particular input of size n is chosen, the running time of that input is tightly bounded from below by the value f(n).

### Big Theta Notation

For two non-negative functions, f(n) and g(n), f(n) is theta of g(n) iff (if and only if) f(n) = O(g(n)) and f(n) = Ω(g(n)). This is written as “f(n) = Θ(g(n))”. Formally, it can be defined as follows:

For function g(n), Big-theta or Big-Θ of n (Θ(g(n))) is defined as:

\[
\Theta(g(n)) = \{ f(n) : \text{there exist constants } c_1, c_2 \text{ and } n_0 \text{ such that } 0 \leq c_1g(n) \leq f(n) \leq c_2g(n)\ \forall n \geq n_0 \}
\]

The running time Θ(n²) means that there is a function f(n) which is equal to Θ(n²) such that for any value of n, no matter what particular input of size n is chosen, the running time of that input is tightly bounded by the value f(n).

### Small “Oh” Notation

For two non-negative functions, f(n) and g(n), f(n) is small-oh or small-o of g(n) iff f(n) = O(g(n)) and f(n) ≠ Ω(g(n)). This is written as “f(n) = o(g(n))”. Formally, it can be defined as follows:

For function g(n), small-o of n (o(g(n))) is defined as,

\[
o(g(n)) = \{ f(n) : \text{for any positive constant } c > 0, \text{ there exists a constant } n_0 > 0 \text{ such that } 0 \leq f(n) < cg(n)\ \forall n \geq n_0 \}
\]

\[
\lim_{n\to\infty}\frac{f(n)}{g(n)} = 0
\]

### Small “Omega” Notation

For two non-negative functions, f(n) and g(n), f(n) is small-omega or small-ω of g(n) iff f(n) = Ω(g(n)) and f(n) ≠ O(g(n)). This is written as “f(n) = ω(g(n))”. Formally, it can be defined as follows:

For function g(n), small-ω of n (ω(g(n))) is defined as,

\[
\omega(g(n)) = \{ f(n) : \text{for any positive constant } c > 0, \text{ there exists a constant } n_0 > 0 \text{ such that } 0 \leq cg(n) < f(n)\ \forall n \geq n_0 \}
\]

\[
\lim_{n\to\infty}\frac{f(n)}{g(n)} = \infty
\]

## Algorithm Case Analysis

Depending on the input sequence given to an algorithm, we can evaluate how much time and space are required to execute an operation. Based on this, following three types of cases are possible for an algorithm:

- **Worst Case**—Results in the worst possible running time to execute an algorithm. It depends on the input sequence and deals with the worst input case possible. Therefore, we can say that it represents the upper bound of the running time of an algorithm for any input. To describe this situation, let's take an example of sequential search, where the key is matched with every single element of a sequence until the match is found. Therefore, if the input sequence is such that the key value does not exist or the key value lies at the end of the sequence, then it is considered as the worst case behavior because the search operation needs to search every single element of the sequence.
- **Best Case**—Results in the best possible running time to execute an algorithm. It deals with the best input case possible. Therefore, we can say that it is the lower bound of the running time of an algorithm for any input. If we consider the example of sequential search again, then in the best case behavior, the key value lies at the first position of the sequence so that after one comparison, the match will be found and the search process will be over.
- **Average Case**—Results in the average running time to execute an algorithm. In this case, the input sequence is drawn randomly from a given distribution of elements. Its behavior lies between the best case behavior and the worst case behavior of an algorithm. In case of sequential search, average case is considered to be the one, where the key value lies in the middle of the sequence. Therefore, in the average case, it is often assumed that all the inputs in a given sequence are equally likely.

## Linked List

A linked list is a data structure that can change during execution. It is similar to an array because they both store collections of data. However, there are certain disadvantages of arrays:

- The size of the array is fixed.
- Due to the fixed size, programmers allocate a huge size in advance, but most of the time it is wasted.
- Insertion of new elements at the front of an array is a potential problem.

To compensate for the disadvantages of an array, linked lists were introduced. In a linked list, successive elements are connected by pointers. The last element in a linked list points to NULL. Linked lists can grow and shrink in size during the execution of a program and can be made as long as possible.
