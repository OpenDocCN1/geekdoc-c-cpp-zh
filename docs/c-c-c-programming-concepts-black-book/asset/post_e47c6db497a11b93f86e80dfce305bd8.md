C++ is compatible with two Input/Output (I/O) systems – the one inherited from C and the other one defined by C++ itself, which is called I/O streams. Although the I/O system inherited from C is extremely rich, flexible, and powerful, the question arises why we need another I/O system in C++. The answer to this question is that C's I/O system does not know anything about objects. Therefore, to provide complete support for object-oriented programming in C++, it was necessary to create an I/O stream that could operate on user-defined objects as well. Apart from this, there are several benefits of using C++'s I/O stream even in programs that do not make extensive (or any) use of user-defined objects.

Exception handling allows us to handle runtime errors in a systematic manner. With the help of exception handling, a program can invoke an error-handling routine when an error occurs without any human intervention. The primary advantage of exception handling is that it automates much of the error-handling code that previously had to be coded "by hand" in any particular program.

This chapter extensively discusses C++ I/O streams, binary I/O, open mode bits, disk I/O using member functions, stream status bits, member functions for accessing stream status bits, random access, formatted I/O, and manipulators. Apart from this it also deals with another very important aspect in C++ programming: the exception handling mechanism. Further, we learn about the mechanics of exception handling using try, catch, and throw. In addition, it discusses exceptions-stack, catching any exception, and re-throwing exceptions. Toward the end, the chapter discusses about handling derived class exceptions and the use of standard library exception hierarchy.

Let’s start the chapter by discussing I/O streams.

### I/O Streams

Generally, an I/O stream is a source or destination for a collection of characters or a flow of data. Output streams allow us to store or write the characters that are read or fetched from the input streams. The main purpose of the I/O stream is to act as a tool for the input and output of texts. Usually, input and output are the transfer of data between a program and any kind of external device. Figure 15.1 shows how I/O stream supports the transfer of data between a program and external devices:

![](img/43c5f409f9b17790a628c4b4df854b61_463_0.png)

The inner representation of the transferred data is supposed to be hassle-free for the processing of data in a program. On the other hand, the external representation can vary a lot; it might be described as either a display in individually readable form or a portable data swap format. The intent of representation, such as conserving storage space, can also affect the external representation.

Stream classes form a powerful set of classes that can be modified, extended, or expanded to include the support for user-defined data types or objects. The benefits of stream classes are given as follows:

- Encapsulates the internal working of classes from a programmer. As a result, the programmer need not specify the type of data that is to be used as input or output; rather, the stream class automatically determines it.
- Offers a rich set of error handling facilities.

In the next section, let’s discuss the stream class hierarchy.

### The Stream Class Hierarchy

Similar to the C-based I/O method, the C++ I/O method also operates by the means of streams. A stream can be a logical device, which either produces or consumes information. It is connected to a logical device from the I/O system. Almost all the streams behave in the same manner even though the specific physical devices, with which they are connected to, may vary substantially. As all the streams behave identically, the same I/O capabilities can operate on virtually almost any physical device. The benefit of this approach is that we need to learn about a single I/O system only.

Standard C++ provides support for streams through the `<iostream>` header. With this header, a rather complicated group of class hierarchies is described that supports the I/O procedures. The I/O classes start with a system of template classes. A template class defines the shape of a class without fully specifying the information upon which it may operate. Once a template class is defined, specific instances of it may be created. As the template classes pertain to the I/O library, standard C++ creates two specializations for them—one for 8-bit characters and another for wide characters. The I/O system is made up of two related but different template class hierarchies. The foremost is derived from the low-level I/O class called *basic_streambuf*. This class supplies the fundamental, low-level input and output operations, as well as provides the underlying support for the whole I/O system. Note that *basic_streambuf* is used only during advanced I/O programming. Most commonly used class hierarchy is *basic_ios*, which is a high-level I/O class that provides formatting, error checking, and status information associated with an I/O stream. A base class for *basic_ios* is known as *ios_base*, which defines several non-template traits utilized by *basic_ios*. *basic_ios* can be used as a base for several derived classes, such as *basic_istream*, *basic_ostream*, and *basic_iostream*. These classes are utilized to create streams at input, output, and input/output, respectively.

Let’s now discuss the stream class hierarchy. The *ios* class defines the basic formatting and error control capabilities. It is a virtual base class for the *istream* and *ostream* classes. The *iostream* class inherits from both the *istream* and the *ostream* classes. These classes are used to take input from the keyboard and send output to the screen. The definitions for these classes are contained in the *iostream* file. The stream class hierarchy is shown in Figure 15.2.
