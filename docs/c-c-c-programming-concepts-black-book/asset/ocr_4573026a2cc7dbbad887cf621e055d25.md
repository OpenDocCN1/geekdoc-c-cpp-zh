Sequence diagram follows the MVC architecture where the user interacts with the user interface (controller). The controller informs the model and then the view to refresh the model to accommodate the changes. In this architecture, the model works independent of the view.

We need different types of arrows, which are explained in Table 13.1, to help design a sequence diagram:

**Table 13.1: Different Types of Arrows in Sequence Diagrams**

| Symbol | Meaning |
|---|---|
| → | To call a method |
| ⟶ | To send any information that is utilized by a method |
| - · - · - · ⟶ | To return any value |
| `<<create>>` → | To create an object |
| `<<destroy>>` → | To destroy an object |

To design a sequence diagram, we need to first choose a use case from the use-case diagram and then find all the necessary interactions between the actor and the use case. Thus, the main success scenario reveals us about the necessary transaction of message between two objects or between an actor and an object. We start with the success scenario of the use case UC1, i.e., “Request for Room.”

The main success scenarios for the UC1 are as follows:

+   1. Customer visits at the Hotel user interface and provides his/her choice of room
+   2. System checks the availability of the room
+   3. System notifies the customer regarding the availability of room
+   4. Customer places a request for the room and his/her personal details
+   5. System verifies the customer details and checks whether he/she has a membership of the hotel
+   6. If the customer is a member, then the system modifies the change of the tariff and saves the record
+   7. System sends customer confirmation message for successful completion of the room booking process
+   8. At the end, the customer is provided with a “Booking ID”
