
The catch clause for a base class will match any class derived from the base class. Therefore, if we want to catch exceptions of both a base type and a derived class type, then we need to put the derived class first in the catch sequence. Otherwise, the catch clause of the base class will always catch the derived class exception, and the catch clause specifying the derived class as its argument type will never execute. Consider the following program:

```cpp
#include <iostream>
using namespace std;
class Base
{
};
class Derived: public Base
{
};

int main()
{
    Derived d;
    try
    {
        throw d;
    }
    catch(Base b)
    {
        cout<< "Caught a base class.\n";
    }
    catch(Derived d)
    {
        cout<< "This will never execute.\n";
    }
    return 0;
}
```

In the preceding program, since d is an object that has Base as a base class, it will be caught by the first catch clause. However, the second clause will never execute. Some compilers will highlight this condition with a warning message, while some compilers may issue an error. To fix this condition, the order of the catch clauses needs to be reversed.

In the last section, let’s discuss some standard library exception hierarchy.

## Standard Library Exception Hierarchy

The C++ standard library consists of a hierarchy of exception classes. This hierarchy is headed by the base class exception. It contains a virtual function **what**, which the derived classes can override to trigger the appropriate error messages. The C++ standard library exceptions declare the following standard exception objects:

- **bad_alloc**—It is thrown when **new** fails
- **bad_cast**—It is thrown when **dynamic_cast** fails
- **bad_typeid**—It is thrown if **dynamic_cast** is applied to a **NULL** pointer
- **bad_exception**—It is thrown when an unexpected or non-specified exception is thrown

Let's now discuss each of the exception classes, in detail.

### bad_alloc()

When the new and new[] operators are unable to allocate the requested storage space, the bad_alloc() exception is thrown. A null-terminated character sequence identifying the exception is returned by its what() member function. Consider the following example:

```cpp
#include <iostream>
#include <new>
using namespace std;
int main ()
{
    try
    {
        int* myarray= new int[100000];
    }
    catch (bad_alloc&BA)
    {
        cerr<< "Exception caught - " << BA.what() << endl;
    }
    return 0;
}
```

The output of the preceding program is given as follows:

```text
Exception caught - bad allocation.
```

### bad_cast()

When dynamic_cast fails the runtime check performed on references to polymorphic class types, the bad_cast() exception is thrown. Similar to the case of bad_alloc, a null-terminated character sequence identifying the exception is returned by the what() member function of bad_cast().

### bad_exception()

This sort of exception is a unique kind of exception created specifically to be listed in its exception specifier. If a function together with bad_exception is listed within its exception-specification throws an exception not listed inside and unexpectedly re-throws this exception (or throws almost every other exception, which is also not inside the exception-specification), then a bad_exception is automatically thrown. The what() function results in a null-terminated character series identifying the actual exception. Consider the following example:

```cpp
#include <iostream>
#include <exception>
using namespace std;

void myunexpected ()
{
    cerr<< "Unexpected handler is called!\n";
    throw;
}
void testFunction () throw (int,bad_exception)
{
    throw 'x'; // throws char (not in exception-specification)
}
int main (void)
{
    set_unexpected (myunexpected);
    try
    {
        testFunction();
    }
    catch (int)
    {
        cerr<<"Caught int\n";
    }
    catch (bad_exception be)
    {
        cerr<<"Caught bad Exception\n";
    }
    catch (...)
    {
        cerr<<"Caught other exception\n";
    }
    return 0;
}
```

The output of the preceding program is as follows:

```text
Unexpected handler is called!
Caught bad Exception
```

### domain_error()

```cpp
class domain_error : public logic_error
{
public:
    explicit domain_error (const string& what_arg);
};
```

The constructor takes a regular string object as a parameter, which is used to generate the C-string that is returned by its inherited member function what(). The value of the string object is stored in the object.

### invalid_argument()

This class defines the type of objects thrown as exceptions to report an invalid argument. It is designed to ensure that any program, not only the elements from the standard library, can throw it as an exception. The constructor associated with bitset (bitset::bitset) may throw the exception. We can define this particular class as:

```cpp
class invalid_argument : public logic_error
{
public:
    explicit invalid_argument (const string& what_arg);
};
```

The constructor takes a regular string object as a parameter, which is used to generate the C-string that is returned by its inherited member function what(). The value of the string object is stored in the object.

Consider the following code:

```cpp
#include <iostream>
#include <bitset>
#include <stdexcept>
using namespace std;
int main (void)
{
    try
    {
        bitset<5> mybitset (string("0ABDF1"));
    }
    catch (invalid_argument& ia)
    {
        cerr << "Invalid argument Exception has been thrown: " << ia.what() << endl;
    }
    return 0;
}
```

In the preceding program, the bitset constructor throws an invalid_argument if initialized with a string containing the characters other than 0 and 1.

The output of the preceding program is given as follows:

```text
Invalid argument Exception has been thrown: bitset::_M_copy_from_string
```

### length_error()

This class defines the type of objects thrown as exceptions to emphasize a length error. It is designed in such a way that apart from the elements of the standard library, any program can throw it as an exception. When attempted to resize to an excessive length, some member functions belonging to a vector and string throw this type of error.

Consider the following example:

```cpp
#include <iostream>
#include <vector>
#include <stdexcept>
using namespace std;
int main (void)
{
    try
    {
        // The vector throws a length_error if resized above max_size
        vector<int> Exvector;
        Exvector.resize(Exvector.max_size()+1);
    }
    catch (length_error& LE)
    {
        cerr << "Length error Exception: " << LE.what() << endl;
    }
    return 0;
}
```

The constructor requires a standard string object as a parameter. This value is stored within the object, and is used to generate the C-string returned through its inherited fellow member function what().

The output of the preceding program is given as follows:

```text
Length error Exception: vector::_M_fill_insert
```

### runtime_error()

Some errors can only be determined during runtime. The runtime_error() class defines the type of objects thrown as exceptions to highlight such errors.

Its subclass logic_error is required as a base for exceptions exposing an error, which might be prevented before runtime. The constructor uses a standard string object as a parameter. This value is stored within the object, and is required to generate the C-string returned by means of its inherited function what().

### range_error()

This class defines the kind of objects thrown as exceptions to emphasize the range errors within internal computations. It is designed in such a way that apart from the elements of the standard library, any program can throw it as an exception. The class can be defined as follows:

```cpp
class range_error : public runtime_error
{
public:
    explicit range_error (const string& what_arg);
};
```

### overflow_error()

The overflow_error() class defines the type of objects thrown as exceptions to emphasize the arithmetic overflow errors. We may define this class as follows:

```cpp
class overflow_error : public runtime_error
{
public:
    explicit overflow_error (const string& what_arg);
};
```
