In UML, five types of views are available, which are given as follows:

+   - **User View**—Illustrates how an end user views a system
+   - **Structural View**—Illustrates the static feature of a model that includes classes, attributes, behaviors, and the relationships between classes
+   - **Behavioral View**—Shows the interaction between the objects and the way a group of objects collaborates in same behavior
+   - **Component View**—Illustrates the organizations and dependencies among software components, including source code, runtime, and executable components
+   - **Deployment View**—Displays the physical layers of a system by revealing the software-hardware dependencies in it

Let’s now learn about the basic concepts of diagrammatic representation of classes and their components.

# ### Attribute

An attribute is a named property of a class that describes the value of the property. In UML, we list the attributes just below the class name.

# ### Operation

An operation is the implementation of a service that can be requested from any object of a class. In UML, we list the operations just below the class attributes, as shown in Figure 13.16:

# ### Signal

A signal is the specification of an asynchronous stimulus communicated between instances.
