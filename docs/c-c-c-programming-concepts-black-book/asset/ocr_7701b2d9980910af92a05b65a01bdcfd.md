# # Global Assembly Cache

The machine-wide code cache that is installed with the CLR is known as Global Assembly Cache (GAC). It acts as a central repository for an assembly. Therefore, we need to install an assembly into the GAC to share it with other applications. However, during the installation of assemblies into the GAC, the following points need to be taken care of:

+   - Assembly dependency should be declared private
+   - Assembly should be strongly named which means that an assembly name should contain a public key token that makes it strong
+   - We need to locate the assembly in the application directory

To install an assembly into the GAC, we need to use the Global Assembly Cache Tool or GacUtil.exe. In addition, we should have the administrative rights to install the assembly. For example, to install the Example.dll assembly, we need to open the Visual Studio 2008 Command Prompt window and type the following command:

```
```
gacutil /i <assembly name>
```
```

After the successful execution of the preceding command, the DLL or the assembly file will be stored in the C:\Windows\assembly location.

In .NET, DLL Hell refers to a problem that occurs when multiple programs in an application attempt to share the same DLL. This problem occurs if the version information about different DLLs of an application is not recorded into the system. Therefore, the use of GAC helps in avoiding DLL Hell that arises due to the incompatible versioning problem of the DLL files and leads to improper execution of an application.

# # Memory Management in C# Programming

CLR requires all its resources to be allocated in a managed heap, which represents an array of memory addresses that is used to allocate objects. This heap has a pointer, which at the beginning points to the base address of the heap. While allocating the objects, this pointer always points to the next available address of the managed heap. Whenever an object is created using the new keyword, that object is usually allocated to a 16 KB memory space (may vary from system to system) in the managed heap. Therefore, when the pointer in the managed heap points to a memory address, which no longer belongs to the managed heap, garbage collection procedure is called.

In this section, we mainly discuss the garbage collection procedure with the help of an algorithm.

The garbage collection procedure checks if there are any objects in the managed heap that are no longer in use. If there are such objects, then the memory spaces allocated to those objects are reclaimed for the newly created objects. Garbage collection procedure runs based on the following three assumptions:

+   - **Assumption 1**—We can easily maintain a part of the heap as compared to the entire heap. Therefore, the managed heap is divided into three sections, which are known as *generations*.
