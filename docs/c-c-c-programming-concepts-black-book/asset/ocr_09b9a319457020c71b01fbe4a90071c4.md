+   - In the second step, the query is defined using the query syntaxes. These syntaxes have similarities with the SQL syntaxes. In LINQ, a .NET application always treats the source data either as IEnumerable<T> or IQueryable<T> regardless of the actual type of the data source. For an XML data source, LINQ treats the source data as IEnumerable<XElement> type; for an ADO.NET dataset, it treats the source data as IEnumerable<DataRow> type; and for LINQ to SQL, it treats the source data as IEnumerable<T> or IQueryable<T>, where T is the custom object type defined to represent the data in the SQL database. Therefore, for simplicity, we use the anonymous type var to represent the type of the data source.
+   - In the last step, the query using the foreach loop is executed.

Let’s take a small example to understand the comprehensive query. Listing 19.5 lists out the odd numbers from a set of numbers using a LINQ query:

# Listing 19.5: Showing an Example of LINQ Query

```

using System.Collections;

using System.Linq;

class Program
{
    public static void Main()

        //Initializing data source
        int[] List = { 1, 2, 3, 4, 5, 6, 7, 8, 9 };

        //type IEnumerable<int>
        IEnumerable<int> query = from num in list
                                 where num % 2 != 0
                                 select num;

        }
    }
}

After that, the LINQ query is used, which returns the dataset of type IEnumerable<int>, as the actual data source is of type int. At last, the query is executed using foreach, which loops through each element of the collection type IEnumerable<int> and prints the output on the console.
