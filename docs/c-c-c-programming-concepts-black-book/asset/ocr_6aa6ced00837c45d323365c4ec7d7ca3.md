# Some Useful Signals

When we try to kill a program from a task manager (for Windows) or terminal (for Linux), the operating system sends a SIGTERM signal to the program. In Linux, the kill command is used to send a SIGTERM signal to the program. Listing 6.3 shows the working of SIGTERM signal:

**Listing 6.3:** Showing the Working of SIGTERM Signal

```
```c
#include<stdio.h>
#include<signal.h>

void writeToFile(char *sigDec)
{
        FILE *fp = fopen("D:\\signalgtest.txt","a");
        fprintf(fp,"\n SIGNT Received ");
        fclose(fp);
}

void sigIntHandler(int signum)
{
        writeToFile("SIGINT RECEIVED");
}

void sigTermHandler(int signum)
{
        writeToFile("SIGTERM RECEIVED");
}

int main()
{
        signal(SIGINT, (void*)sigIntHandler);
        signal(SIGTERM, (void*)sigTermHandler);

        while(1)
        {
                printf("\n Infinite Loop");
        }

        return 0;
}
```
```

In Listing 6.3, we have registered a signal handler called sigTermHandler() to handle the SIGTERM signal. While executing the infinite loop, if a user presses CTRL + C, sigIntHandler() is called because CTRL + C generates an interrupt. For this, sigTermHandler() will be called to kill the program. After the code inside the sigTermHandler() signal handler is executed, the program again starts executing.

Another useful signal is SIGKILL, which terminates the program. One can try to handle a SIGKILL signal by registering a handler but the default handler is always called.

In the Linux environment, a process can be suspended by using the SIGCONT signal. This is done when the CTRL + Z key combination is sent against a running process.
