**Figure 9.1: Displaying the Architecture of a Linux Operating System**

As shown in Figure 9.1, the architecture is broken down into three levels - user space, System Call Interface (SCI), and kernel. On the top level, user applications are running and at the bottom level, kernel is running. The intermediate level is SCI, which connects various user applications to get the services from the kernel. This layer is important as both the kernel space and the user space reside in two different protected address spaces. In other words, the SCI layer serves as the only communication medium between them. Communication between the applications in user space and the kernel space is done mainly through the calls to the library functions, which in turn issue a system call to perform the job. To understand the communication between the user space and the kernel space, let’s take an example of the printf() function in the C language that helps in the formatting and buffering of data. Issuing a call to printf() eventually calls the write() system call, which instructs the kernel to write the data on the console. It is interesting to note that when an application executes a system call, the kernel executes on behalf of the application and runs in a process context.

The kernel also manages hardware resources by means of interrupts. When any hardware wants to communicate with the system, it issues an interrupt that asynchronously interrupts the kernel. Generally, interrupts are identified by a number. The kernel uses this number to execute a specific interrupt handler to process and respond to the interrupt. For example, as you type, the keyboard controller issues an interrupt to let the system know that there is a new data in the keyboard buffer. Kernel handles this by enabling and disabling the interrupts to interact with the outside environment. In the Linux kernel, it interrupts do not execute in process context; instead, they run in a special context called the interrupt context.

# Monolithic or Microkernels – What Linux Chooses?

Kernels can be classified into two main design patterns: monolithic kernel and microkernel. Monolithic kernel is an operating system architecture that is implemented as a single large process running as a supervisor, entirely in the kernel mode. Communication within the monolithic kernel is comparatively simple as everything runs in the kernel mode in the same address space. On the other hand, microkernels are not implemented as a single large process. For designing microkernels, the entire functionality of the kernel is broken down into the smaller kernel modules that can be configured easily and flexibly.
