### Sequential Search

Sequential search is one of the simplest searching techniques that searches all the elements against a key value. It works correctly regardless of the ordering of the elements in a list. Let’s consider the following list of elements, where we search for the number 5:

- {1, 2, 4, 10, 9, 8, 5, 6, 7, 3}

Sequential search loops through all the elements in the list until it finds the right match. The moment it finds the right match, it breaks out from the loop.

Listing 24.42 shows the algorithm for sequential search:

### Listing 24.42: Showing the Algorithm for Sequential Search

```text
function Sequential_Search(A[n], key): integer
begin
    found <- false
    k <- 0
    item <- A[k]
    while A[k] is not null and found == false do
    begin
        if(A[k] != key)
        begin
            found <- false
            k <- k +1
        else
            found <- true
            break;
        end
    end
    return k
end
```

The Sequential_Search() function returns the index of a list and compares each single list element with the key value until the match is found. In the algorithm, A[] is the input array and key represents the element to be searched. The function loops through each element of the array A[] until it finds an element that matches to the element key. If it finds the match, then it breaks the loop; otherwise, the loop continues to execute.

In the sequential search, the best case is the one where the key value is the first element in the list. In this case, only one comparison is required. On the other hand, the worst case is the one where the key value is the last list element or the key does not exist in the list. In this case, each list element needs to be compared with the key value. Therefore, in the best case, the time required to perform the search is O(1); whereas, in the worst case, the time required to perform the search operation is O(n), where n is the length of the array element. Similarly, in the average case, the key element will be at the middle of the list. Therefore, the time required to perform the search operation is O(n/2), which is nothing but O(n), where n is the length of the list. The case analysis of the sequential search is as follows:

- **Best Case:** O(1)
- **Worst Case:** O(n)
- **Average Case:** O(n/2) ≈ O(n)

In the sequential search, as the list is unsorted, all the elements are compared in case of searching against a key value. However, this situation might completely change if the list is already sorted. Therefore, binary search is used to implement the searching technique on a sorted list.

Let’s learn about binary search, in detail.

### Binary Search

In the binary search, to find a key element, first the middle element of a list is found, which is then matched with the key value. If the key value is less than the middle element of the list, then the searching continues with the left-hand side set of elements recursively. However, if the key value is greater than the middle element of the list, then this technique is applied to the right-hand side of list elements recursively. This process continues until the key value is found. If a list contains millions of records, then it will take log2(1000000) ≈ 20 steps to perform the search. Therefore, this technique is much more efficient than the sequential search.

Let’s consider the following list of elements:

(-1, 1, 5, 10, 50, 60, 70, 80, 90, 100, 200, 300)

Now, suppose the key value is 80. If we apply the binary search technique, then it would be as follows:

| Step | Array / Elements | Comparison |
|---|---|---|
| Step 1 | -1, 1, 5, 10, 50, **60**, 70, 80, 90, 100, 200, 300 | Middle element = 60; 60 < 80 |
| Step 2 | 70, 80, **90**, 100, 200, 300 | Middle element = 90; 90 > 80 |
| Step 3 | 70, **80** | Middle element = 80; 80 == 80 |

In step 1, the middle element is selected, which is 60. As 80 is greater than 60, the process looks into the right-hand side list of 60. The technique is again applied to the right-hand side list, where the middle element is selected as 90. As 80 is less than 90, the binary search technique is again applied to the left-hand side list of 90, where the middle element is selected as 80. In this case, 80 matches with the key value.
