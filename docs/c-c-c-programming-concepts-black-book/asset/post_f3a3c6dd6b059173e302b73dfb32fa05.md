## NOTE

The compound statement following a try clause is the guarded area of code. The throw-expression punches an exception. The compound statement following a catch clause is the particular exception handler and draws the exception thrown from the throw-expression. The exception declaration statement following a catch clause indicates the sort of exception the clause addresses. This type can be valid data type, including a C++ class.

Note that C++ does not catch a divide by zero exception by default. The code will crash when a divide by zero situation occurs. As a result, the only option is to write a class or method to handle divide by zero case. The following example shows how to handle the divide by zero situation and how to construct an exception:

```cpp
#include<iostream>
using namespace std;
class Division
{
    public:
        double quotient(int numerator, int denominator);
    private:
};

double Division::quotient(int numerator, int denominator)
{
    if(!denominator)
    {
        exception e("divide by 0 exception");
        throw(e);
    }
    return (static_cast< double >( numerator ))/denominator;
}
int main()
{
    Division d;
    try
    {
        cout<<"1. (500/10) = "<<d.quotient(500, 10)<<endl;
        cout<<"2. (15/6) = "<<d.quotient(15, 6)<<endl;
        cout<<"3. (10/0) = "<<d.quotient(10, 0)<<endl;
        cout<<"4. (30/9) = "<<d.quotient(30, 9)<<endl;
    }
    catch(exception& e)
    {
        cout<<"Exception caught with cause :"<<e.what()<<endl;
    }
    return 0;
}
```

The output of the preceding program is as follows:

```text

2. (15/6) = 2.5
```

Let’s now discuss the mechanics of exception handling.

## Exception Handling – Mechanics

Whenever an exception is thrown, it is caught by the corresponding catch declaration, which processes the exception. There can be several catch statements for a try; which catch statement can be used will be determined by the kind of exception. That is, if the data type specified within a catch matches with that of the exception, then all the other catch statements are bypassed. When an exception is captured, the argument specified within the catch clause will have the exception. Any kind of data may end up being caught, including the classes that are created. If absolutely no exception is thrown, then no catch statement is executed. If a match is found, the catch handler’s code is executed and control resumes at the point after the catch handlers.

If the control reaches the try statement by normal sequential setup, then the guarded section from the try block is accomplished. In case there is no exception to be thrown in the guarded section, the catch clauses that will follow the try block are certainly not executed. Execution continues at the statement following last catch clause pursuing the try block that exception was expected. If an exception is thrown in the execution of the guarded section, or in just about any routine, the guarded segment calls either directly as well as indirectly. An exception object is made from the object manufactured by the throw operand. This means that a copy constructor could possibly be involved. At this place, the compiler looks for the catch clause in a higher exception context, which could handle an exception in the type thrown, or a new catch handler that can handle any sort of exception. The catch handlers are examined as a way of their appearance pursuing the try block. If no appropriate handler can be found, the next dynamically attaching try block is looked at. This process continues prior to the outermost enclosing try is examined. If a matching handler is not found, or if an exception occurs during unwinding, but before the handler gets control, the pre-defined runtime function terminate() is called.

The throw statement usually accepts a single parameter and it is passed as an argument to the exception handler. The general format of the throw statement is as follows:

```cpp
throw ex;
```

Throw generates the exception specified by ex. If the exception is to be caught, then throw must be executed from either within try block or from any function called from within the try block.

## Exceptions – Stack

Data is pushed upon a stack and popped off. A stack can have the following constraints:

- Stack will be of fixed size
- Stack will throw a stack overflow exception if an attempt is made to push data onto a full stack
- Stack will throw a stack empty exception if an attempt is made to pop data off an empty stack

Consider the following program to implement the stack class:

```cpp
#include <iostream>
#include <string>
using namespace std;
class DivideByZero {
public:
    DivideByZero(int N, int D) : numerator(N), denominator(D), errorMessage("Divide by zero exception because of occur!!!") {}
    ~DivideByZero() {}
    void getMessage()
    {
        cout << "An exception has occurred in the program. " << endl;
        cout << errorMessage << endl;
        cout << "The Numerator is: " << numerator << endl;
        cout << "The Denominator is: " << denominator << endl;
    }

    // private declarations
private:
    int numerator;
    int denominator;
    string errorMessage;
};

// defining Stack overflow exception
class StackOverflowException {
public:
    StackOverflowException() {}
    ~StackOverflowException() {}
    void getMessage()
    {
        cout<< "An exception has occurred. "<< endl;
        cout<< "Exception: Stack is Full." << endl;
    }
};

// Defining empty stack exception
class StackEmptyException {
public:
    StackEmptyException() {}
    ~StackEmptyException() {}
    void getMessage()
    {
        cout<< "An exception has occurred..." << endl;
        cout<< "Exception: Stack is Empty." << endl;
    }
};

// Implementing a very crude stack class that is intended only to illustrate
// exceptions.

class CrudeStack {
public:
    CrudeStack() : index(-1) {}
    ~CrudeStack() {}
    void push(int value)
    {
        index++;
        if (index >= 25)
        {
            throw StackOverflowException();
        }
        data[index] = value;
    }

    int pop()
    {
        if (index < 0)
        {
            throw StackEmptyException();
        }
        int value = data[index];
        index--;
        return value;
    }

//Private declarations
private:
    int data[20];
    int index;
};

int divide(int numer, int denom)
{
    if (denom == 0)
    {
        throw DivideByZero(numer,denom);
    }
    return numer/denom;
}
int main()
{
    CrudeStack stack;
    int numer;
    int denom;
    int value;
    cout<< "Starting implementation of crude stack..." << endl;
    cout<< "Enter the numerator: ";
    cin>> numer;
    cout<< "Enter the denominator: ";
    cin>> denom;
    try {
        stack.push(numer);
        stack.push(denom);
        divide(numer, denom);
        value = stack.pop();
        cout<< "An starting popping of values..." << endl;
        cout<< "The following is popped " << value<< endl;
        value = stack.pop();
        cout<< "The following is popped " << value<< endl;
        value = stack.pop();
        cout<< "The following is popped " << value<< endl;
    }
    catch (StackOverflowException e) {
        e.getMessage();
    }
    catch (StackEmptyException e) {
        e.getMessage();
    }
    catch (DivideByZero e) {
        e.getMessage();
    }
    catch (...) {
        cout<< "An exception has occurred..." << endl;
        cout<< "An exception of unknown type occurred" << endl;
    }
    cout<< "Exiting the program..." << endl;
    return 0;
}
```

In the preceding program, whenever we divide by zero error occurs, it is wisely handled by an exception. Similarly, when the stack overflows or is empty, an exception is thrown.
