### Defining Destructors

Destructors are meant to destroy the instance of a class. They are invoked automatically by the garbage collector, which decides when the destructor method will be called. Generally, if an instance of a class has not been used for a long time, the garbage collector calls the destructor method to destroy that instance. For destructors, we need to take care of the following points:

- Destructors cannot be called from the member methods. They are invoked automatically.
- Only class definition holds the destructor method.
- They cannot be overloaded or inherited.
- They do not have any parameters. We can only distinguish a destructor and a constructor by the sign "~", which comes before the name of the destructor.

Note that a destructor has the same name of the class. Listing 18.9 shows an example of the destructor.

### Defining Shared Members

Shared members are the class members for which we do not need to create an instance of a class. These members are static in nature. For example, when we use the Math class, we do not need to create an object of the Math class to access the Abs() method, which calculates the absolute value of a given number. Code snippet for this operation is given as follows:

```csharp
long result = Math.Abs(10000.9090);
```

However, when we refer the non-static class DateTime, we need to create an object of that class, as follows:

### Defining Indexers

Similar to the operator array in C++, C# provides an indexer that allows a class to be used as an array. This indexer is mainly applied when a class contains a collection.

Let's consider an example of Employee class that contains the details of an employee in an array of string. Now, we cannot fetch the individual array elements by just creating an instance of the Employee class. In this case, indexers can be used to fetch the individual array elements by using the class as an array. Listing 18.12 shows the implementation of this example by using indexers:
