+   - Aggregation—An aggregation is a stronger form of association. It is a structural relationship that specifies that one class represents a large thing which constitutes of smaller things. Aggregation represents a “has-a” relationship. In UML, it is shown as in Figure 23.16:

![](bbox=[0.41, 0.617, 0.702, 0.642])

**Figure 23.16: Showing the Aggregation Relationship**

In UML, a link is placed between the “whole” and “part” classes with a diamond head attached to the whole class to indicate that this association is an aggregation.

Aggregation is a concept that is used to express “part of” types of associations between objects. An aggregate is conceptually an extended view of a unit by some operations, but it can actually be composed of multiple objects. One aggregate may contain multiple **whole-part** structures, each viewable as a distinct aggregate. Components may or may not exist in their own right and they may or may not appear in multiple aggregates.

Since aggregation is a special kind of association, it adds additional meaning in some cases. Two objects form an aggregate if connected tightly by a **whole-part** relationship. But how to identify whether it is aggregation? Grady Booch had put forward some valuable questions to test whether a relation is an aggregation or not:

+   - Would you use the phrase “part of” to describe it?
+   - Are some operations on the whole automatically applied to its parts?
+   - Are some attribute values propagated from the whole to all or some parts?
+   - Is there an intrinsic asymmetry to the association, whether one object class is subordinate to the others?

If the answer to all the preceding questions is yes, then the relation is an aggregation.
