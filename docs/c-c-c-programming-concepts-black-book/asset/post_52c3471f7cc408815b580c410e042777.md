## Aggregation

Aggregation is used when a class is a part of another class. For example, members are part of a club. Therefore, there exists an aggregation relationship between the members and the club. Aggregation relation is shown in Figure 13.25:

![](img/43c5f409f9b17790a628c4b4df854b61_392_1.png)

As shown in Figure 13.25, we use a clear diamond to symbolize the aggregation relationship.

An aggregation is a stronger form of association. It is a structural relationship and specifies that a class represents a larger thing, which consists of smaller things. Aggregation represents a “has-a” relationship. In UML, aggregation can be represented, as shown in Figure 13.26:

![](img/43c5f409f9b17790a628c4b4df854b61_392_2.png)

In UML, a link is placed between the whole and part classes with a diamond head attached to the whole class to indicate that this association is an aggregation.

Aggregation is a concept that is used to express “part of” types of associations between objects. One aggregate may contain multiple whole-part structures each viewable as a distinct aggregate.

As aggregation is a special kind of association, it adds additional meaning in some cases. Two objects form an aggregate if connected tightly by a whole-part relationship. Now, the question arises: how can we identify whether a relationship is an aggregation. Grady Booch had put forward some valuable questions to test whether a relation is an aggregation, which are as follows:

- Would you use the phrase "part of" to describe it?
- Are some operations on the whole automatically applied to its parts?
- Are some attribute values propagated from the whole to all or some parts?
- Is there an intrinsic asymmetry to the association, whether one object class is subordinate to the others?

If the answer to all the above is yes, then the relation is an aggregation.

Therefore, a relationship between class A and class B is of aggregation type, if class A maintains a list of class B and the constructor of class A does not create an object of class B. In addition, if class B is freely floating, then it is called aggregation, as shown in Figure 13.27:

![](img/43c5f409f9b17790a628c4b4df854b61_393_0.png)
