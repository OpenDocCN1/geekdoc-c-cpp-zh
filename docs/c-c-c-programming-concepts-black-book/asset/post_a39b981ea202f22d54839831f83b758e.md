Let's now learn about the function overriding in inheritance.

## Overriding Member Functions

We can use member functions in a derived class having the same name as in a base class. Generally, a derived class inherits all the member data variables and functions of its base class. Now, if the derived class also has a member function sharing the same name as that of the one in the base class, then the member function in the derived class overrides the one in the base class. Therefore, when an object of the base class calls the member function, the base class copy of the member function is executed; whereas, when the object of the derived class calls the member function, the member function of the derived class is called. This typical phenomenon is known as function overriding.

The following program shows the concept of overriding member functions:

```cpp
1:/* Inheritance Example Program 5 */
2:#include <iostream.h>
3:using namespace std;
4:
5:class Base {
6:public:
7:    void show()
8:    {
9:        cout<<"Calling Base Class Show"<<endl;
10:    }
11:};
12:
13:class Derived : public Base {
14:public:
15:    void show()
16:    {
17:        cout<<"Calling Derived Class Show"<<endl;
18:    }
19:};
20:
21:int main()
22:{
23:    Base BaseObj;
24:    Derived derivObj;
25:
26:    BaseObj.show();
27:
28:    derivObj.show();
29:
30:    return 0;
31:}
```

In the preceding program, we have declared two classes, Base and Derived, where both of them have a same function, show(). Now, in line number 13, we have derived the Base class to the Derived class. Therefore, as per the definition of inheritance, the class Derived got the two copies of the show() function, that is, one its own copy and the another one derived from the Base class. Now, in the main() function, we have defined two different objects, one for each class. When line number 26 executes, the show() function of the Base class is called; and when line number 27 executes, the show() function of the Derived class is called. Let's first see the output of the program:

```text
Calling Base Class Show
Calling Derived Class Show
```

From the output, it is clear that when the object of the base class makes a call to show(), the function of the base class is executed. However, when the object of the derived class makes a call to show(), how does the compiler knows which version of show() to call, as the derived class has two versions of show() in it - a base class copy and its own function. The compiler follows this rule when the same function exists in both the base class and the derived class, the function in the derived class is executed. This is true for the objects of the derived class. On the other hand, objects of the base class do not have any knowledge of the derived class and always use the functions of the base class.

Now, what happens if the object of the derived class wants to call the base class version of the function before it executes its own version? C++ provides the solution in the form of using scope resolution with overridden functions. Let's write the following program where we discuss how to resolve the conflict using the scope resolution operator:

```cpp
1:/* Inheritance Example Program 5 */
2:#include <iostream.h>
3:#include <stdlib.h>
4:using namespace std;
5:#define MAX 100
6:
7:class StackBase {
8:protected:
9:    int arr[MAX];    /* Limiting the capacity of the stack */
10:    int top;
11:public:
12:    StackBase()
13:    {
14:        top = -1;            /* Initialize stack top to invalid loc */
15:    }
16:    void push(int val)/* Pushing values onto stack */
17:    {
18:        arr[++top] = val;
19:    }
20:    int pop()            /* Popping values from stack */
21:    {
22:        return (arr[top--]);
23:    }
24:};
25:
26:class Stack : public StackBase {
27:public:
28:    void push(int val)      /* Validates input and call base class fn */
29:    {
30:        if (top >= MAX - 1) {
31:            cout<<"Error - Stack Overflow"<<endl;
32:            exit(1);
33:        }
34:        StackBase::push(val); /* Call the base class function */
35:    }
36:    int pop()                /* Validates input and call base class fn */
37:    {
38:        if (top < 0) {
39:            cout<<"Error - Stack Underflow"<<endl;
40:            exit(1);
41:        }
42:        return StackBase::pop();     /* Call the base class function */
43:    }
44:};
45:
46:int main()
47:{
48:    Stack Stackobj;
49:
50:    Stackobj.push(1);
51:    Stackobj.push(2);
52:    Stackobj.push(3);
53:    Stackobj.push(4);

55:    cout<<"Popped value is "<<Stackobj.pop()<<endl;
56:    cout<<"Popped value is "<<Stackobj.pop()<<endl;
57:    cout<<"Popped value is "<<Stackobj.pop()<<endl;
58:    cout<<"Popped value is "<<Stackobj.pop()<<endl;
59:
60:    return 0;
61:}
62:
```

In the preceding program, the StackBase class implements the basic stack in C++ with push() and pop() functions. In addition, it has a constructor for initializing the stack to point at an invalid location at the beginning of the program when the stack is empty. Now, we have another class Stack that derives from StackBase; however, it does not define any other data members, rather overrides the push() and pop() functions of StackBase to handle the error conditions while the stack is operating. Notice the line number 34, where after handling the error in the push() function of the derived class, we are making a call to the push() function of the base class. The line number 34 is as follows:

```cpp
StackBase::push(val);
```

This is how scope resolution is used to call a function of the base class from within the derived class, when both have a function with the same name. Without the scope resolution operator, the compiler will call the derived class version of the same function by default. To call the base class version of the function, we use the base class name followed by the scope resolution operator (::), which is again followed by the function name with argument list, if required. Similar syntax is used in line number 42 while making a call to the base class version of the pop() function. Following is the output of the program:

```text
Popped Value is 4
Popped Value is 3
Popped Value is 2
Popped Value is 1
Error - Stack Underflow
```

Let's now learn about multi-level inheritance.

## Multi-Level Inheritance

Till now, we have discussed mostly about the base class and derived class involving only single level of inheritance. However, classes can be derived from classes that are themselves derived; this phenomenon is called multi-level inheritance. In real world scenario, we need multi-level inheritance to model scenarios, such as hierarchical relationships for maintenance of company data. Consider the following code snippet:

```cpp
class Base
{
    ..........
};
class Derv1 : public Base
{
    ..........
};
class Derv2 : public Derv1
{
    ..........
};
```

In the preceding code snippet, the Derv1 class is derived from the Base class. Similarly, the Derv2 class is derived from the Derv1 class. This process can be repeated for arbitrary number of levels; for example, Derv3 can be derived from Derv2 and Derv4 can be derived from Derv3.

When a derived class is used as a base class for another derived class, any protected member of the initial base class that is inherited (as public) by the first derived class may also be inherited as protected again by a second derived class. Let's write the following program to understand more about the concept.
