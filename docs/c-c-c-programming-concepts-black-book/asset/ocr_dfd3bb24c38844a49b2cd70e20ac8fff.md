# # Differences between OOP and Procedural Programming

Procedural programming is a way of encoding by identifying a group of steps to solve a particular problem and executing this group of steps in a precise order to reach the required outcome or condition. Suppose we wish to calculate the month-end closing balance for a bank account. The very first step in calculating the balance is to acquire the starting balance from the account and then reducing all the debit amounts occurred throughout the month. After that, we need to add all the credit amounts occurred during the month. At the end of this procedure, we get the month-end closing balance from the account.

One of the main concepts associated with procedural programming is procedure call. A procedure, also called a subroutine, method, or perhaps a function, contains an ordered listing of instructions to be completed. A procedure could be called anytime during the execution of any other procedure or alone. Examples of procedural languages are C and Pascal.

Within OOP, the focus is on taking into consideration the problem to be solved when it comes to real-world elements as well as representing the problem when it comes to objects and their own behavior.

The key distinction between OOP and procedural programming is that the focus of procedural programming would be to break down the actual programming task into an accumulation of variables and subroutines; whereas, the focus of OOP would be to break down the actual programming task into objects, which encapsulate information and methods. Another difference is that the procedural encoding uses procedures to directly work on data structures; whereas, OOP bundles the information and methods together to ensure that an object will operate on data.
