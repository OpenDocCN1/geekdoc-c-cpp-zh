
```csharp
int sum = df(2, 3);
Console.WriteLine("The addition is {0}", sum);
}
}
```

In Listing 19.3, we have put the lambda operator => in between the list of arguments and the actual expression. The left side of the lambda operator indicates the arguments that we will pass to the method and the right side of the lambda operator represents the actual expression. In the preceding code, we have calculated the summation of the two variables, i and j.

We can also write a lambda expression that contains multiple expressions, as shown in Listing 19.4:

**Listing 19.4: Showing a Lambda Expression Containing Multiple Expressions**

```csharp
using System;
using System.Linq;
class Program
{
    delegate int DelFunc(int i, int j);
    public static void Main()
    {
        DelFunc df = (i, j) => {
            i = i * 2;
            j = j * i;
            return (i + j);
        };
        int sum = df(2, 3);
        Console.WriteLine("The addition is {0}", sum);
    }
}
```

The preceding code shows the method of adding multiple expressions in a lambda expression that adds the content of two variables i and j. The output of the code is given as follows:

```text
The addition is 16
```

Let’s now learn about LINQ queries, in detail.

## LINQ Queries

A query is a way to fetch the desired set of data from a data source. It is a set of instructions that describes which data to be fetched and what would be the format of the data. To fetch data from different data sources, we need to learn different query languages that have been developed for the data sources. For example, to work with SQL or Extensible Markup Language (XML), we need to learn SQL or XQuery. On the other hand, LINQ provides a consistent model using which we can work with different data sources without learning different query languages. Therefore, whether we query an XML database, SQL database, ADO.NET dataset, or .NET collection object, the basic structure of a LINQ query remains the same.

Following are the two different types of LINQ queries:

- Comprehensive queries
- Lambda queries

Let’s start our discussion with the comprehensive query type.

### Comprehensive Queries

Comprehensive queries are normal LINQ queries, which are syntactically similar to the SQL queries. A program that contains the comprehensive query executes in three steps, which are given as follows:

- In the first step, the data source is defined.
- In the second step, the query is defined using the query syntaxes. These syntaxes have similarities with the SQL syntaxes. In LINQ, a .NET application always treats the source data either as `IEnumerable<T>` or `IQueryable<T>` regardless of the actual type of the data source. For an XML data source, LINQ treats the source data as `IEnumerable<XElement>` type; for an ADO.NET dataset, it treats the source data as `IEnumerable<DataRow>` type; and for LINQ to SQL, it treats the source data as `IEnumerable<T>` or `IQueryable<T>`, where T is the custom object type defined to represent the data in the SQL database. Therefore, for simplicity, we use the anonymous type var to represent the type of the data source.
- In the last step, the query using the foreach loop is executed.

Let’s take a small example to understand the comprehensive query. Listing 19.5 lists out the odd numbers from a set of numbers using a LINQ query:

**Listing 19.5: Showing an Example of LINQ Query**

```csharp
using System;
using System.Collections;
using System.Collections.Generic;
using System.Linq;

class Program
{
    public static void Main()
    {
        //Initializing data source
        int[] list = { 1, 2, 3, 4, 5, 6, 7, 8, 9 };

        //Writing the LINQ query which returns a set of object of
        //type IEnumerable<int>
        IEnumerable<int> query = from num in list
                                 where num % 2 != 0
                                 select num;

        Console.WriteLine("The odd numbers are...");
        //Executing the query
        foreach (int nums in query)
        {
            Console.WriteLine(nums);
        }
    }
}
```

In the preceding code, we have retrieved a list of odd numbers from a set of integers. To carry out this operation, an array of integers is first declared. After that, the LINQ query is used, which returns the dataset of type `IEnumerable<int>`, as the actual data source is of type int. At last, the query is executed using foreach, which loops through each element of the collection type `IEnumerable<int>` and prints the output on the console. This example shows the exact data type of the dataset that the LINQ query returns. However, the same result can also be produced if we use the anonymous type var instead of the specific generic type. Listing 19.6 shows the use of anonymous type to declare the dataset returned by a LINQ query.

**Listing 19.6: Showing an Example of LINQ Query using Anonymous Type**

```csharp
using System;
using System.Linq;
class Program
{
    public static void Main()
    {
        //Initializing data source
        int[] list = { 1, 2, 3, 4, 5, 6, 7, 8, 9 };

        //Anonymous type "var"

                    where num % 2 != 0
                    select num;
        Console.WriteLine("The odd numbers are...");
        //Executing the query
        foreach (int nums in query)
        {
            Console.WriteLine(nums);
        }
    }

```

The preceding program is the modification of the code given in Listing 19.5 with the only difference that the anonymous type variable is used to store the LINQ query. For both the programs, the output will be same as follows:

```text

1
3
5
7
9
```

Let’s now learn about lambda queries.

### Lambda Queries

Lambda query constitutes a query that contains a lambda expression. While writing a lambda query, we need to follow certain rules, which are given as follows:

- Lambda expression should contain the equal number of arguments as that of the delegate type
- Each argument type of the lambda expression must be implicitly convertible to the type of the delegate parameter
- The return type of the lambda expression must be implicitly convertible to the return type of the delegate

Let’s modify the preceding code to incorporate the lambda expression in place of the LINQ query, as shown in Listing 19.7.

**Listing 19.7: Showing the Code for the Lambda Query**

```csharp
using System;
using System.Linq;

class Program
{
    public static void Main()
    {
        //Initializing data source
        int[] list = { 1, 2, 3, 4, 5, 6, 7, 8, 9 };

        //Writing the lambda query which returns a set of object of
        //Anonymous type "var"
        var query = list.Where(n => n % 2 != 0);

        Console.WriteLine("The list of odd numbers are...");
        //Executing the query
        foreach (int nums in query)
        {
            Console.WriteLine(nums);
        }
    }
}
```

In Listing 19.7, instead of a LINQ query, we have used a delegate that accepts a lambda expression. By using the foreach loop, the lambda query gives all the odd numbers from a list of given numbers. The output of the preceding code is same as that of Listing 19.6.

Next, let's understand the two execution methods of a LINQ query.

### Deferred and Immediate Executions

While writing a LINQ query, we first store the actual query in a query variable, which is of type `IEnumerable<T>` or `IQueryable<T>`. This query variable stores only the command of the query but not the result of the query. The result of the query will be retrieved only when the query will be iterated by using the foreach loop. Therefore, we can postpone or defer the execution of the query as long as we want. This type of query execution is referred to as deferred execution.

In Listing 19.7, the anonymous type variable, query, holds the actual command of the query. As the query retrieves the integer values, the integer variable num in the foreach loop holds the resultant data in each step of the iterated query execution. The code snippet responsible for the deferred execution is shown in Listing 19.8:

**Listing 19.8: Showing the Code Snippet for Deferred Execution**

```csharp
foreach (int nums in query)
{
    Console.WriteLine(nums);
}
```

Now, consider a case where we immediately require the result of the query. For this, LINQ provides some methods, which can be used to force the immediate execution of the query. When an aggregation operation method, such as count, min, or max, needs to be executed in the LINQ query, it forces an immediate execution of the foreach loop. For this, we do not need to write the foreach loop explicitly. The aggregation operation methods iterate over the result of the query and get the value. Listing 19.9 shows an example of the immediate execution:

**Listing 19.9: Showing an Example of Immediate Execution**

```csharp
using System;
using System.Linq;

class Program
{
    public static void Main()
    {
        //Initializing data source
        int[] list = { 1, 2, 3, 4, 5, 6, 7, 8, 9 };

        var query = list.Where(n => n % 2 != 0);

        int max = query.Max();
        Console.WriteLine("The maximum odd number is {0}", max);
    }
}
```
