
```c
printf("\n This code is always compiled");
getch();
return 0;
}
```

In Listing 7.8, we have defined the __DEBUG__ compilation flag using the #define directive, which makes the code inside the #ifdef and #endif block to be compiled.

The output of the preceding program is given as follows:

```text
This code is skipped
This code is always compiled
```

Similarly, we can use the #undef directive to turn the __DEBUG__ flag off so that the same code would not compile. Listing 7.9 shows the working of #undef directive:

**Listing 7.9: Showing the Working of #undef Directive**

```c
#include<stdio.h>
#undef __DEBUG__
int main()
{
    #ifdef __DEBUG__
        printf("\n This code is skipped ");
    #endif
    printf("\n This code is always compiled");
    getch();
    return 0;
}
```

The output of the preceding program is given as follows:

```text
This code is always compiled
```

The #ifdef and #else directives work in the same way as the if and else conditional statements, but these directives are specifically used in the macros. Listing 7.10 shows the use of #ifdef and #else directives:

**Listing 7.10: Using the #ifdef and #else Directives**

```c
#include<stdio.h>
#define __DEBUG__
int main()
{
    #ifdef __DEBUG__
        printf("\n Disabling flag");
        #undef __DEBUG__
    #else
        printf("\n Enabling flag");
        #define __DEBUG__
    #endif

    #ifndef __DEBUG__
        printf("\n Enabling the flag once again");
        #define __DEBUG__
    #else
        printf("\n Disabling the flag once again");
        #undef __DEBUG__
    #endif

    getch();
    return 0;
}
```

The output of the preceding program is given as follows:

```text
Disabling flag
Enabling the flag once again
```

In Listing 7.10, we have first checked whether the __DEBUG__ macro is defined or not. If the macro is already defined, then it will be undefined in the #ifdef block. However, if the macro is not defined, then it will be defined in the #else block. Note that if we do not define the macro, then we get the reverse output.

Now, consider a scenario where the utilityFunc() function is defined in the header1.h file, which is included in another header file called header2.h. Suppose that a program includes both these header files. In this case, the compiler will throw an error message - Multiple declaration of utilityFunc(). This is because an instance of the header1.h file is already included in the header2.h file. If we include both the header files in a program, then multiple instances of the same function will be included in it. To solve this problem, we need to avoid including the same header file multiple times. The following code snippet shows the solution to avoid multiple inclusions of a function in a program:

```c
#ifndef __myheader_h
#define __myheader_h
utilityFunc()
{
}
#endif
```

When the __myHeader.h file is included in the program for the first time, the preprocessor checks for the flag and finds it undefined. Therefore, the preprocessor sets the flag and includes the body of the utilityFunc() function in the program. However, if the same header file is included in the program for the second time, then the preprocessor finds the defined flag; and therefore, skips this portion of code.

Let's now learn about some miscellaneous directives.

## Miscellaneous Directives

Some preprocessor directives cannot be categorized into any specific type, as they are used for different purposes. Following are such miscellaneous directives:

- #undef
- #pragma
- #error
- #line

Let's learn about them in detail, one by one.

### #undef

The #undef directive removes a previously defined definition of a macro that follows it. In other words, it undefines a macro. The general syntax of the #undef directive is given as follows:

```c
#undef macro_name
```

**Listing 7.11: Showing the Working of #undef Directive**

```c
#include<stdio.h>
#define VARIABLE 50
int main()
{
    #undef VARIABLE
    printf("\n The value is %d ",VARIABLE);
    getch();
}
```

When we compile the preceding program, it generates the following compilation error:

```text
'VARIABLE' undeclared (first use in this function)
```

### #pragma

The #pragma directive is an implementation-driven directive that is used to provide various instructions to the compiler. Pragma varies from one compiler to another. Certain pragmas, such as startup and exit, are used for inserting comments in a source code. Listing 7.12 shows the working of pragmas:

**Listing 7.12: Showing the Working of Pragmas**

```c
void fun1( ) ;

void fun2( ) ;

#pragma startup fun1

#pragma exit fun2

main( )
{
    printf ( "\ninside main" ) ;
}
void fun1( )
{
    printf ( "\ninside fun1" ) ;
}
void fun2( )
{
    printf ( "\ninside fun2" ) ;
}
```

In Listing 7.12, the #pragma startup and #pragma exit directives allow a user to specify functions that should be called before and after the execution of the main() function, respectively.

The output of Listing 7.12 is given as follows:

```text
Inside fun1
Inside main
Inside fun2
```

### #line

The #line directive changes the content of __LINE__ and __FILE__, which are two predefined identifiers in the compiler. The __LINE__ identifier holds the line number of the currently compiled line of code. The __FILE__ identifier holds a string that contains the name of the source file being compiled. Listing 7.13 shows the code written without the #line directive:

**Listing 7.13: Showing the Code Without Using the #line Directive**

```c
#include<stdio.h>

int main()
{
    printf("\n In Line [%d] File name [%s] ",__LINE__,__FILE__);
    getch();
}
```

The output of the preceding program is given as follows:

```text
In Line [5] File name [D:\Tanuman\Progs\conditional.c]
```

Now, if the code in Listing 7.13 is rewritten using the #line directive, then it appears, as shown in Listing 7.14:

**Listing 7.14: Showing the Code Written with the #line Directive**

```c
#include<stdio.h>
#line 500 "Tanuman"
int main()
{
    printf("\n In Line [%d] File name [%s] ",__LINE__,__FILE__);
    getch();
}
```

The output of the preceding program is given as follows:

```text
In Line [503] File name [Tanuman]
```

As the output suggests, the #line directive has not only changed the line number and reset it to 500, but it has also changed the file name of the program.

### #error

The #error directive stops the compiler from compilation. It is primarily used for debugging. The general form of #error directive is as follows:

```c
#error error-message
```

Note that the error-message should not be given inside the double quotes. Whenever the #error directive is encountered, the error-message is displayed. Listing 7.15 shows the usage of #error directive:

**Listing 7.15: Showing the Working of #error Directive**

```c
#include<stdio.h>
int main()
{
    #error Stop here
    printf("\n This is Test");
    getch();
}
```

The output of Listing 7.15 is given as follows:

```text
#error Stop here
```

As the output suggests, the compilation of the code stops by giving the error message.
