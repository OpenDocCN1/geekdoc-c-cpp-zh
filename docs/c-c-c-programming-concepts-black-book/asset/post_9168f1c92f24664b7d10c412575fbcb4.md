
### Some Useful Signals

When we try to kill a program from a task manager (for Windows) or terminal (for Linux), the operating system sends a SIGTERM signal to the program. In Linux, the kill command is used to send a SIGTERM signal to the program. Listing 6.3 shows the working of SIGTERM signal:

**Listing 6.3:** Showing the Working of SIGTERM Signal

```c
#include<stdio.h>
#include<signal.h>

void writeToFile(char *sigDec)
{
        FILE *fp = fopen("D:\\signalgtest.txt","a");
        fprintf(fp,"\n SIGNT Received ");
        fclose(fp);
}

void sigIntHandler(int signum)
{
        writeToFile("SIGINT RECEIVED");
}

void sigTermHandler(int signum)
{
        writeToFile("SIGTERM RECEIVED");
}

int main()
{
        signal(SIGINT, (void*)sigIntHandler);
        signal(SIGTERM, (void*)sigTermHandler);

        while(1)
        {
                printf("\n Infinite Loop");
        }

        return 0;
}
```

In Listing 6.3, we have registered a signal handler called sigTermHandler() to handle the SIGTERM signal. While executing the infinite loop, if a user presses CTRL + C, sigIntHandler() is called because CTRL + C generates an interrupt. For this, sigTermHandler() will be called to kill the program. After the code inside the sigTermHandler() signal handler is executed, the program again starts executing.

Another useful signal is SIGKILL, which terminates the program. One can try to handle a SIGKILL signal by registering a handler but the default handler is always called.

In the Linux environment, a process can be suspended by using the SIGCONT signal. This is done when the CTRL + Z key combination is sent against a running process.

### Registering a Common Handler

Instead of registering different signal handlers for each signal, we register a single signal handler for all sorts of signals. Listing 6.4 shows how to register a common handler:

**Listing 6.4: Registering a Common Handler**

```c
#include<stdio.h>
#include<signal.h>

void writeToFile(char *sigDec)
{
    FILE *fp = fopen("D:\\SignalTest.txt", "a");
    fprintf(fp,"\n %s Received ",sigDec);
    fclose(fp);
}

void sigHandler(int signum)
{
    switch(signum)
    {
        case SIGINT:writeToFile("SIGINT RECEIVED");
            break;
        case SIGTERM:writeToFile("SIGTERM RECEIVED");
            break;
        case SIGCONT:writeToFile("SIGCONT RECEIVED");
            break;
    }
}

int main()
{
    signal(SIGINT, (void*)sigHandler);
    signal(SIGTERM, (void*)sigHandler);
    signal(SIGCONT, (void*)sigHandler);

    while(1)
    {
        printf("\n Infinite Loop");
    }

    return 0;
}
```

In Listing 6.4, we have used a single signal handler while registering sigHandler() with the signal() function. When a signal is sent to the program, the registered signal handler will be called. If the program has registered the signal along with the signal handler, then the call to the signal handler will be made. Instead of keeping multiple signal handlers, the program keeps the same signal handler for all the signals registered. Depending on the type of signal, a specific task is carried out.

### Interrupt Service Routine

Interrupt Service Routines or interrupt handlers are callback functions that are triggered by an interrupt. In several operating systems, Interrupt Service Routines are often divided into two parts: First-Level Interrupt Handler (also called hard interrupt handler) and Second-Level Interrupt Handler (also called soft interrupt handler).

The main job of a First-Level Interrupt Handler is to quickly serve an interrupt. This happens by switching to Interrupt Service Routine and executing it. First-Level Interrupt Handlers are also used for masking interrupts.

Second-Level Interrupt Handlers complete a long interrupt processing task similar to that of an independent process. In Linux, each Second-Level Interrupt Handler has an independent kernel thread associated to it for its execution.

When Interrupt Service Routines are executed for devices, they are known as device drivers; whereas, when they are executed by software, they are known as exceptions, signals, or trap handlers. A hardware interrupt is generated by a device or port when it is ready to perform an action or it has completed its assigned action. It generates a call to an Interrupt Service Routine. An interrupt caused due to runtime exception, such as divide by zero, is called a trap. When a runtime exception occurs, it generates a software interrupt, which is regarded as a signal or an exception that invokes an Interrupt Service Routine.

### Case Study on ARM Architecture

ARM stands for Advanced RISC Machine. It is the most widely used 32-bit Reduced Instruction Set Computer (RISC) Instruction Set Architecture (ISA). The ARM architecture includes several features of RISC, such as support for using register file load/store architecture. Using this feature, data processing operations are only made on registers and their contents; thereby, reducing the direct operations on memory. All the load/store instructions are determined from registers, as addressing modes used for this purpose are much simpler.

The ARM processor is also known as an A32 processor because it has a fixed length (32-bit) instruction set. ARM instructions are generally 32-bit wide and aligned on 4-byte boundaries. ARM processors are used in smart phones and personal digital assistants.

### Installing Exception Handlers

A new exception handler must be installed inside a vector table. After the installation, the new exception handler executes when the corresponding exception occurs. An exception handler is installed by using either the branch instruction or the load pc instruction. By using the branch instruction, each entry inside the vector table contains a branch entry, which points to the required exception handler routine. However, this scheme has a limitation, as it has a range of 32 MB. By using the load pc instruction, the program counter is forced to point to the handler address directly by storing the absolute address of the handler.

### Interrupt Handlers

The ARM processor has two levels of external interrupt: FIQ and IRQ. For an interrupt to be executed, the appropriate disable bit in the CPSR must be clear. FIQ interrupts have a higher priority as compared to IRQ interrupts. Both the external interrupts differ in the following two ways:

- FIQs are serviced first when multiple interrupt occurs.
- Servicing of FIQs causes IRQs to be disabled. They remain disabled until the FIQs are finished executing and then turned back once again.

Interrupt handlers can be written in C by using the __irq keyword, which cannot be used for the re-entrant interrupt handlers because it does not store all the required states. The irq keyword preserves all other registers (excluding the floating-point registers) used by the interrupt handler function. It exits the function by setting the program counter to the value stored in the link register and restoring the CPSR to its original value. If the function calls a subroutine, __irq preserves the link register for the interrupt mode.

### Reset Handlers

The job performed by a reset handler depends on the operating system platform and the system for which the software is developed. A reset handler might be used for setting up exception vectors. It can be used for initializing stacks and registers as well as the memory system, if it is a Memory Management Unit (MMU). Reset handlers are used for initializing I/O devices and enabling interrupts. They play a major role in changing the mode or state of a processor.
