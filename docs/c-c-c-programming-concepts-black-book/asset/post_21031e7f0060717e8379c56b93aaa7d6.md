
As the comment in the preceding code snippet indicates, the statement does not raise any error because C++ automatically converts the character ‘a’ into its double equivalent. Although automatic type conversions are convenient, they are the prime source of ambiguity. Let’s consider an example of two functions that have the same name and both of them take one argument each. Suppose one of them takes a floating point variable as an argument and the other takes a double variable as an argument. Now, due to C++ automatic type conversion mechanism, when a call to the function will be made with a fractional argument, the compiler will not be able to decide which one to call; thereby, giving rise to an ambiguous situation. Let’s understand more about this concept from the following program:

```cpp
1:/* Function Overloading Example Program 3 */
2:#include <iostream.h>
3:using namespace std;
4:
5:float example(float i);
6:double example(double n);
7:
8:int main()
9:{
10:    cout<< example(10.32)<<endl;    //Unambiguous, calls example(double)
11:    cout<< example(12)<<endl;       //Ambiguous
12:
13:    return 0;
14:}
15:
16:float example(float i)
17:{
18:    return i;
19:}
20:
21:double example(double n)
22:{
23:    return n;
24:}
```

In the preceding program, the example() function is overloaded so that it can take arguments of either float type or double type. In line number 10, the call to example(10.32) function is unambiguous because unless otherwise specified as float, all the floating point constants in C++ are automatically of the double type. However, when example() is called using an integer value in line number 11, ambiguity is introduced because the compiler has no way of knowing whether the parameter should be converted into a float type or a double type. Therefore, in this situation, the compiler causes an error message to be displayed failing the compilation process, and leaving the ambiguity resolution to the programmer.


In C++, char and unsigned char are not inherently ambiguous. However, when example() is called using the integer value 88 in line number 11, the compiler does not know which version of example() to call.

Similarly, an ambiguity can be caused unknowingly by using the default arguments in overloaded functions. Consider the following example that shows how using default arguments along with function overloading can cause ambiguity:

```cpp
1:/* Function Overloading Example Program 5 */
2:#include <iostream.h>
3:using namespace std;
4:

6:int example(int a, int b=1);

19:}
```

In line number 10, two arguments are specified in example(); therefore, no ambiguity is introduced in this case and the call is made to example(int a, int b). However, when the second call to example() is made in line number 11, ambiguity occurs and the compiler cannot decide which function call to process. That is, whether to call the function with a single argument or to call the function (which has one of the arguments as default value) with two arguments. In this case, the compiler issues an error and fails the compilation process.

Let’s now learn about the basic steps for function overloading in C++.

## Steps for Function Overloading

A function call first tries to find a match with the prototype having the same number and type of arguments and then makes a call to the appropriate function for execution. A best match must be unique. The function selection involves the following steps:

- 1. The compiler first tries to find an exact match in which the type of the actual arguments is same as that of the formal arguments and then uses that function.
- 2. If an exact match is not found, then the compiler uses the automatic type promotions to the actual arguments, such as char to int or float to double, to find a match.
- 3. When either of the preceding steps fails, the compiler tries to use the built-in conversion for the actual arguments and then uses the function whose match is unique. If the conversion matches with more than one function definition, then the compiler generates an error message and fails the compilation process. Suppose we are using the following two function definitions:
  - `long square(long n);`
  - `double square(double x);`

  In this case, a function call, such as square(19), will cause an error because the int argument can be converted to either long or double; thereby, creating an ambiguity so as to which version of square should the compiler use.
- 4. If all the preceding steps fail, then the compiler will try the user-defined conversions to find a unique match. User-defined conversions are often used in handling class objects.

Let's now learn why overloading is useful in defining constructors and member functions of a class.

### Overloading Constructor Functions

A constructor function is a special type of function that is present inside a class definition and invoked every time an object is instantiated in a program. The primary benefit of constructor function is that it frees a programmer from explicitly initializing each object after it is created in the program. The programmer can write a constructor in the class definition that initializes the data members of an object and whenever the object is instantiated, the constructor for that class is fired automatically and it executes the block of code within the constructor function. Now, in this section, we learn how to overload constructor functions of a class and what benefits it gives us. In real life programming, it is very common to find overloaded constructor functions. Let's create a class that holds the time in hour:mins:sec format, shown as follows:

```cpp
1:/* Constructor Function Overloading Example Program 6 */
2:#include <iostream.h>
3:using namespace std;
4:
5:class Time {
6:    int hour;
7:    int mins;
8:    int secs;
9:public:
10:    Time()
11:    {
12:        hour=mins=secs=0;
13:    }
14:    Time(int hr, int min, int sec)
15:    {
16:        hour = hr;
17:        mins = min;
18:        secs = sec;
19:    }
20:    void show_time()
21:    {
22:        cout<<"Time: "<<hour<<":"<<mins<<":"<<secs<<endl;
23:    }
24:};
25:
26:int main()
27:{
28:    Time time_obj1;
29:    Time time_obj2 (12, 30, 52);
30:
31:    time_obj1.show_time ();
32:    time_obj2.show_time ();
33:
34:    return 0;
35:}
```

In the preceding program, we can initialize an object of type Time either by specifying the values of hours, minutes, and seconds explicitly into the constructor function or by using the default constructor to set the values to zero for the three member variables of type Time. The basic advantage of overloading the constructor is that it frees us from doing object specific initialization every time an object is created. In situations where we just want to define an object of type Time and set its value later in the program, we can initialize it using the default constructor by setting the values of each member to zero. On the other hand, when we want to create a Time object and initialize it using a particular value, say system time, we can use the parameterized constructors by setting the values of the member variables entered by a user. This gives ample flexibility to the programmer by handling housekeeping related tasks, such as garbage initialization of variables at the time of instantiation. In addition, overloading constructors provide ease of use while creating class libraries, which can be used by other users without worrying about the allocation and deallocation of members of the object.

Let’s now learn about operator overloading in C++.

## Operator Overloading

Now, as we have almost covered what function overloading is and how it is implemented in C++, let’s introduce another form of polymorphism in C++. Closely related to function overloading is operator overloading in C++, where different operators exhibit different behavior based on their arguments, with which they are called. We can overload most of the operators so that they can perform special operations relative to classes that we create. For example, we generally use the addition operator ‘+’ to add two integer or real values in C++, but we can also use it to concatenate two character strings. Let’s consider another example of a class that maintains a stack. The class might overload the addition operator ‘+’ to push the values into the stack and the operator ‘-’ to pop the values from the stack. Note that when an operator is overloaded, none of its original meaning is lost. This implies that when the ‘+’ operator is used to concatenate two character strings in a program, it does not stop us from using the ‘+’ operator for arithmetic addition in the same program. Instead, the type of objects, to which it can be applied to, gets broader with overloading.

We can overload operators in C++ by creating **operator** functions. An **operator function** defines the specific operation that the overloaded operator will perform relative to the class it is designed to work on. Operator functions can be either member functions or non-member functions of the class that they will operate on. For non-member functions, it has to be the **friend** function of that class. The benefit of operator overloading is the capability to transform obscure programs into obvious ones. For example, consider the following two statements:

```cpp
obj3.addObject (obj1, obj2);
obj3 = obj1.addObject (obj2);
```

The preceding two statements can be changed to a much more readable format using the same operation, as follows:

```cpp
obj3 = obj1 + obj2;
```
