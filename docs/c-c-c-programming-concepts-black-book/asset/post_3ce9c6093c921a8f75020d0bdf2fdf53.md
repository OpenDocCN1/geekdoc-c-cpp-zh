In the preceding code snippet, type casting is necessary because the syntaxes of the read() and write() functions are as follows:

```cpp
write(char * addr, int size);
read(char * addr, int size);
```

The preceding syntaxes imply that the compiler assumes that the buffer is of character type. Therefore, the address of the object should be typecasted as a character pointer. Now, consider the following program.

```cpp
#include <fstream>
using namespace std;
int main ()
{
  char * buffer;
  long size;
  ifstream infile ("EXAMPLE.txt",ifstream::binary);
  ofstream outfile ("new.txt",ofstream::binary);

  // get size of file
  infile.seekg(0,ifstream::end);
  size=infile.tellg();
  infile.seekg(0);

  // allocate memory for file content
  buffer = new char [size];

  // read content of infile
  infile.read (buffer,size);

  // write to outfile
  outfile.write (buffer,size);

  // release dynamically-allocated memory
  delete[] buffer;
  outfile.close();
  infile.close();
  return 0;
}
```

> **NOTE**
>
> *The typecast inside the calls to read() and write() are required when operating on a buffer that is not defined as a character array. Due to C++'s strong type checking, a pointer of one type cannot be automatically converted into a pointer of another type.*

Next, let’s learn about explicit file opening and closing.

## Explicit File Opening and Closing

Explicitly, a file can be opened by using the **open()** and **close()** functions. The use of these two functions can be explained with the help of the following code:

```cpp
#include <iostream>
#include <fstream>
using namespace std;

int main ()
{
   ofstream file1;
   file1.open ("SAMPLE.txt");
   file1<<"Example of open and close function.\n";
   file1.close();
   return 0;
}
```

The preceding code creates a file SAMPLE.txt and writes a sentence to that file.

To open a file having a stream object, we need to use the open() function as follows:

```
open (filename, mode);
```

In the preceding syntax, filename is a null-terminated character series of type **const char *** symbolizing the name of the file to be opened, and mode is an optional parameter with a mix of the following flags:

| Flag | Description |
|---|---|
| ios::in | Used in streams open for input operations. |
| ios::out | Used in streams open for output operations. |
| ios::binary | Used in streams open in binary mode. |
| ios::app | Used in streams open for output-only operations. All the output operations are performed at the end of the file, appending the content to the current content of the file. |
| ios::ate | Used to set the initial position at the end of the file. If this flag is not set to any value, the initial position is the beginning of the file. |
| ios::trunc | Used to delete the content of a file and replace it with the new one, if it is opened for output operations and already exists. |

Each stream contains a series of bits or flags associated with its operators. These bits are defined in the **ios** class. Some of these bits are used for formatting input and output, while some are used for error handling. By the virtue of inheritance, these are available in the **fstream** classes. Some of these bits are also associated with the opening of files. Associated with every stream is a series of bits called the open mode bits. These open mode bits represent the mode in which the file is opened. Collectively, these bits state the mode in which the file is to be opened. For example, consider the following statement:

```cpp
fstream file("IOFILE",ios::in|ios::out);
```

When a program encounters the preceding statement, the two bits in the statement are set for the stream. Therefore, the file is available for both input and output. Table 15.1 lists the open modes with their explanation:

Table 15.1: Open Modes

| Mode | Explanation |
|---|---|
| app | All data written out is appended to the stream. |
| ate | The file pointer starts at the end of the stream, that is, it causes seek at the end of the file. The I/O operations can still occur anywhere within the file. |
| in | The stream is opened for input. |
| out | The stream is opened for output. |
| binary | Binary file, if not present, is opened as the American Standard Code for Information Interchange (ASCII) file by default. |
| trunc | If the file exists, it is truncated and all data is erased before writing or reading. |
| nocreate | If the file we are opening does not already exist, then the operation fails. |
| noreplace | Operation fails when opening for output, if the file already exists, unless the app or ate mode is set. |

In the next section, let’s discuss disk I/O in detail.

### Disk I/O Using Member Functions

Let’s understand this concept with the help of a sample C++ program. Consider the Medicine class defined as follows:

```cpp
class Medicine
{
    private:
        char MedicineCode[5];
        unsigned int BatchNo;
        char Category;
        char units;
        float producedQty;

    public:
        void getdata()
        {
            cout<< "Enter the BatchNo:";
            cin>> BatchNo;
            cout<< "Enter the Medicine Code:";
            cin>> MedicineCode;
            cout<< "Enter Category:";
            cin>> Category;
            cout<< "Enter the unit of measurement:";
            cin>> units;
            cout<< "Enter the quantity produced:";
            cin>> producedQty;
        }
        void showdata()
        {
            cout<< "Displaying the desired Data:";
            cout<< "The Batch Number is:" << BatchNo;
            cout<< "The Medicine Code is:" << MedicineCode;
            cout<< "The Category is:" << Category;
            cout<< "the unit of measurement is:" << units;
            cout<< "The quantity produced is:" << producedQty;
        }
};
```

The aim of the preceding code snippet is to include disk I/O operations into the class definition. However, it can be seen that if we include I/O operations within the class, we may compromise with the reusability of the class to some extent because the class will be associated with the disk file. To keep the variable disk file name, we could include the file name as an attribute of the class. However, in this case, file name is not an attribute of Medicine class. Moreover, if we want to reuse the Medicine class to create a list of Medicines, we cannot do so, as file I/O is not a property of a generalized Medicine class. Now, consider the code for Medicine_File class:

```cpp
class Medicine_File
{
   private:
      Medicine buffer;
   public:
      void diskout(void);
      void diskin(void);
};
```

To separate the file I/O from the generalized Medicine class, we have declared a separate class called **Medicine_File**, which produces an output file called MEDICINE.TXT associated with this class. The only attribute of this class is a contained object called buffer of type Medicine into which values can first be written, and then flushed on to a disk file, or an object can be read from the file into this object. This class also contains two public functions: one for writing records to the file and another to read records from the file. The member functions of the class are as follows:

- **diskout()**—Gets data from a user and writes the record on to the file
- **diskin()**—Reads the records from the file and displays them on the screen

Now, consider the following code:

```cpp
void Medicine_File::diskout(void)
{
   ofstream ofile("MEDICINE.TXT", ios::app);
   char loop;
   do
   {
      buffer.getdata();
      ofile.write((char *) &buffer, sizeof(buffer));
      cout<<"Any more records (y/N)?";
      cin>>loop;
   } while (loop == 'y');
}
void Medicine_File::diskin(void)
{
   ifstream ifile("MEDICINE.TXT");
   ifile.read((char *) &buffer, sizeof(buffer));
   while (ifile)
   {
      buffer.showdata();
      ifile.read((char *) &buffer, sizeof(buffer));
   }
}
```

We have a self-contained class called Medicine_File for file I/O; therefore, we can implement the main() function in a very simple way, as follows:

```cpp
void main()
{
   Medicine_File fileobj;
   fileobj.diskout();
   fileobj.diskin();
}
```
