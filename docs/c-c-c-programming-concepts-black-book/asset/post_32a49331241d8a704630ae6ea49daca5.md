
```
num1 <= num2
num2 <= temp
end
```

The preceding algorithm sorts a list of elements in the ascending order. At first, it calculates the minimum and maximum indexes of the list. After that, the Partition_List function is called to partition the list in two parts against the selected pivot value. The left partition contains the elements whose values are smaller than the pivot value and the right partition contains the elements whose values are greater than the pivot value. Again, the quick sort technique is applied recursively to these two partitions. At the end, all the elements of the list are sorted in the ascending order.

In the Partition_List function, the first element of the list is selected as pivot. Based on this pivot value, the comparisons take place. In this function, two variables i and j holds the minimum and maximum indexes of the list, respectively. The value i is incremented if the pivot value is greater than the ith element in the list. In addition, the value of j is decremented if the pivot value is less than the jth element in the list. If at any point, one of these two conditions is not satisfied, then the ith and jth elements interchange their positions, as the jth element is smaller than the ith element. These two processes continue until i is less than j. If at any point, the value of i is greater than j, then the ith element is interchanged with the pivot value, as the ith element has a greater value than the pivot. This process partitions the list against the pivot value.

Now, let's analyze the quick sort algorithm. While analyzing the algorithm for quick sort, let's first concentrate on its best case behavior. The behavior of quick sort depends on the selection of the pivot. In the best case behavior, the pivot is selected in such a way that each partition results in the sub-lists of same length. Therefore, the recursive call required is log n. While partitioning the list, this operation loops over the array elements, which is of the order O(n). Therefore, in the best case behavior, the quick sort takes O(n log n) time. The average case behavior is also same as the best case behavior in quick sort, which is O(n log n).

In the worst case behavior, the pivot is chosen in such a way that the partition results in two sub-lists of length 1 and n-1, respectively. Therefore, the behavior will be same as that of the bubble sort. In this case, the ith element is sorted in O(n-i). The order of execution can be calculated as follows:

1 + 2 + 3 + ... + (n - 1) + n = n(n - 1)/2 = O(n^2)

## Merge Sort

Merge sort is another sorting technique that is based on the divide and conquer strategy. In the divide step, it divides the array into two halves of the same size. In the conquer step, the two sub-arrays are conquered by recursively applying the sorting technique. At the end of the process, the already sorted sub-arrays are merged until they get back to the original size of the initial array. In this way, the sorted array is achieved.

As the merge sort follows the three steps of divide and conquer paradigm, we can represent the merge sort technique as follows:

- 1. Divide the array A[n] into two halves.
- 2. Continue division until there is a single element left, which is sorted by its own.
- 3. Merge already sorted sub-arrays into one and continue merging until the actual length of the array is reached. This process will result in a sorted array.

In the preceding algorithm, first, the list is partitioned in such a way that at the end of the partition, there are a number of partitions, which is equal to the number of the list elements. By calling the MergeSort_Partition() function recursively, the list is partitioned. After the list is partitioned into single elements, the Merge() function is executed. In this function, we remove the smaller elements from L1 and L2 and place them immediately to the right of the earlier element in the resultant array. If this removal makes one list empty, then the remaining elements from the other lists are appended to the resultant list. This process is repeated until the entire list is sorted.

Now, let's analyze the merge sort algorithm. Among the family of divide and conquer sorting techniques, merge sort is the most efficient sorting algorithm, as its complexity even in the worst case is O(n log n). The reason behind this is that if a list is sorted in a reverse order, then

- O(log n) time is required to partition the list
- O(n) time is required to merge the two partitions

Therefore, the total complexity of the algorithm is O(n log n). In the best case, as the partitioning and merging will take place regardless of the order of the element, the complexity is O(n log n). Therefore, we can say that merge sort is useful, as it is fast regardless of the order of the elements as well as easy to understand and implement.
