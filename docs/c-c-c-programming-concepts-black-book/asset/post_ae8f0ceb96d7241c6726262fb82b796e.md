A thread created in a joinable state can be made detachable by calling pthread_detach() with the thread ID, as follows:

```c
int pthread_detach (pthread_t thread);
```

Note that once a thread is made detachable, it cannot be made joinable again.

One of the most interesting attribute state of a thread is the detach state. The following statement sets the value of the detach state for the current thread, for which it is called:

```c
int pthread_attr_setdetachstate (pthread_attr_t * attr, int detachstate);
```

In the preceding statement, we have placed the detach state as the second argument.

The detach state can take the following two values:

- PTHREAD_CREATE_DETACHED
- PTHREAD_CREATE_JOINABLE

Let’s consider the following program to explore the detachstate thread attribute and show how a child thread can be cleaned up without calling pthread_join():

```c
/* thread4.c – Demonstrating pthread_attribute handling for detachstate */
#include <stdio.h>
#include <pthread.h>

void* thread_function (void* thread_arg)
{
    /* Do work here... */
    printf("\nI am a new thread. I am detached\n");
    sleep(20);
    printf("\nI am a new thread. I am exiting\n");
}

int main ()
{
    pthread_attr_t attr;
    pthread_t thread;
    pthread_attr_init (&attr);
    pthread_attr_setdetachstate (&attr, PTHREAD_CREATE_DETACHED);
    pthread_create (&thread, &attr, &thread_function, NULL);
    pthread_attr_destroy (&attr);

    printf("\nThis is main thread. I am not waiting for the other thread\n");
    /* No need to join the thread. */
    sleep(30);
    printf("\nThis is main thread. I am exiting\n");
    return 0;
}
```

In the preceding program, we have defined an object of the pthread attribute type and set the detach state as PTHREAD_CREATE_DETACHED. We have also passed this attribute object as an argument to the pthread_create() API. The newly created thread has the detach state set as CREATE_DETACHED. This implies that whenever a child thread terminates, it will be automatically cleaned up; and thereby, there is no need to call pthread_join() explicitly for the thread.

Next, let’s learn about thread cancellation and modes.

### Thread Cancellation and Modes

Suppose we are running the threads in a multithreading environment and depending on a particular condition, we want to cancel some threads and terminate their execution. Moreover, a thread can request another thread to terminate during the execution of a program. This can be done by using the concept called thread cancellation. By sending a cancellation request to a thread, we can only request the thread for termination; whether the thread will end its execution or not, solely depends on its cancellation state. Moreover, only sending the cancellation request might not be sufficient for terminating or cancelling a thread during its execution. Cancellation also depends on the two factors of the target thread – cancel state and type. To cancel a thread, we can use the following statement:

```c
int pthread_cancel (pthread_t  thread_id);
```

In the preceding statement, thread_id is the ID of the thread to be cancelled. The pthread_cancel() API sends a cancellation request to the thread with the given thread_id.

A cancelled thread can be joined later using pthread_join() unless it is detached. The return value of the cancelled thread is PTHREAD_CANCELED.

Cancellation can be risky if a thread is doing a complex job, such as updating a critical pool of resources. In this case, cancelling that thread might hamper the criticality of the job in execution along with all its dependencies. To resolve such situations, pthreads are empowered with cancellation modes. Following are the three modes with regard to thread cancellation:

- 1. **Asynchronously Cancellable** – A thread can be cancelled at any point of its execution.
- 2. **Synchronously Cancellable** – A thread can be cancelled, but not at any point of its execution. Instead, cancellation requests are queued and the thread is cancelled only when it reaches some specific points, known as cancellation points, in its execution path. This is the default mode for a newly created thread.
- 3. **Uncancellable** – Any attempt to cancel a thread is silently ignored.

A thread can be in any one of the preceding three modes by setting its cancel state and type, which are explained as follows:

- **Cancel State** – PTHREAD_CANCEL_ENABLE or PTHREAD_CANCEL_DISABLE is used to cancel the state. This checks whether the cancellation is enabled on a particular thread or not. Setting the cancel state of a thread to PTHREAD_CANCEL_ENABLE makes the thread react to the pthread_cancel() request. Whereas, setting the cancel state of a thread to PTHREAD_CANCEL_DISABLE makes the thread indifferent to the pthread_cancel() request.
- **Cancel Type** – The cancel state can affect type PTHREAD_CANCEL_ASYNCHRONOUS can be cancelled at any point of its execution. Whereas, a thread with cancel type PTHREAD_CANCEL_SYNCHRONOUS implies that the thread can only be cancelled when it reaches some special points in its execution path, known as cancellation points. The synchronous cancellation type handles a situation where a cancellable thread executing a critical task can only be cancelled once the task is finished. This is done when a cancellation point is inserted just after the thread completes its task.

Following is the mapping of the cancellation modes with the cancel state and type:

- Asynchronously Cancellable
  - **State** – PTHREAD_CANCEL_ENABLE
  - **Type** – PTHREAD_CANCEL_ASYNCHRONOUS
- Synchronously Cancellable
  - **State** – PTHREAD_CANCEL_ENABLE
  - **Type** – PTHREAD_CANCEL_SYNCHRONOUS
- Uncancellable
  - **State** – PTHREAD_CANCEL_DISABLE

To set the cancel state of a thread, we can use the following API:

```c
int pthread_setcancelstate (int state, int *oldstate);
```

The preceding API sets the new cancel state and returns the old cancel state. Similarly, for setting the cancel type of a thread, we can use the following API:

```c
int pthread_setcanceltype (int type, int *oldType);
```

The preceding API sets the new cancel type and returns the old cancel type.

Now, to set a cancellation point in a synchronously cancellable thread, we need to call pthread_testcancel(). The cancellation point will process a pending cancellation request. The syntax for setting a cancellation point in a synchronously cancellable thread is as follows:

```c
void pthread_testcancel (void);
```

Let’s consider the following program to handle thread cancellation:

```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <pthread.h>

void *thread_function(void *arg);

int main()
{
    int             res;
    pthread_t       a_thread;
    void            *thread_result;

    res = pthread_create(&a_thread, NULL, thread_function, NULL);
    if (res != 0) {
        fprintf(stderr, "\nThread creation failed.\n");
        return 1;
    }

    sleep (1);
    fprintf(stdout, "Cancelling thread ...\n");
    res = pthread_cancel(a_thread);
    if (res != 0) {
        fprintf(stderr, "\nThread cancellation failed\n");
        return 1;
    }

    fprintf(stdout, "\nWaiting for thread to finish ...\n");
    res = pthread_join(a_thread, &thread_result);
    if (res != 0) {
        fprintf(stderr, "\nThread join failed\n");
        return 1;
    }
    fprintf(stdout, "\nThread joined\n");

    return 0;
}

void *thread_function(void *arg)
{
    int     i;
    int     res;

    res = pthread_setcancelstate(PTHREAD_CANCEL_ENABLE, NULL);
    if (res != 0) {
        fprintf(stderr, "\nThread pthread_setcancelstate failed\n");
        return 0;
    }

    res = pthread_setcanceltype(PTHREAD_CANCEL_DEFERRED, NULL);
    if (res != 0) {
        fprintf(stderr, "\nThread pthread_setcanceltype failed\n");
        return 0;
    }
    fprintf(stdout, "\nthread_function is running\n");
    for (i = 0; i < 500; i++) {
        fprintf(stdout, "\nI am still running (%d) ...\n", i);
    }
    pthread_testcancel();
    pthread_exit(0);
}
```

In the preceding program, we have created a new thread in the main() function and issued a pthread_cancel() request on it. On the other hand, we have manipulated the state and type of the thread in thread_function().

Note that the pthread_cancel() API should be used only in unusual circumstances; for example, when a thread might leave some incomplete tasks affecting the result of a program. In this case, better approach is to communicate to the thread that it should end and then wait for the thread to exit on its own.

Now, let’s learn about cleanup handlers.

### Cleanup Handlers

A cleanup handler is a function that is called automatically when a thread is cancelled. This is typically used for freeing up the resources and locks that might be held by a thread. When a thread is cancelled, the cleanup handlers, which were registered at the beginning of the program, are called in the reverse order from the stack. By registering a cleanup handler, we mean pushing it in the stack; whereas, by de-registering a cleanup handler, we mean removing it from the stack.

We can register a cleanup handler, as follows:

```c
void pthread_cleanup_push (void (*routine) (void *), void *arg);
```

When a thread is cancelled, routine is called with arg as its argument.

We can de-register a cleanup handler, as follows:

```c
void    pthread_cleanup_pop (int execute);
```

If the execute argument is non-zero, then the cleanup handler at the top of the stack is executed once. The preceding two APIs can also be used as macro with matching braces. They should be used in pair within the same function and at the same lexical nesting level.
