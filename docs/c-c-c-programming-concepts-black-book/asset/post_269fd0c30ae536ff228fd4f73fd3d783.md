
- 1. The virtual functions in a base class must be defined, even though it may not be used.
- 2. Virtual functions cannot be static members.
- 3. Virtual functions should be accessed by using object pointers.
- 4. A virtual function can be a friend of another class.
- 5. The prototypes of the base class version of a virtual function and all the derived class versions must be identical. In case the prototypes are different, the virtual function mechanism is lost.
- 6. We cannot have virtual constructors, but we can have virtual destructors.
- 7. When a base pointer points to the object of a derived class, incrementing or decrementing the base pointer will not make it point to the next object of the derived class. Therefore, we should not use this method to move the pointer to the next object.
- 8. If a virtual function is defined in a base class, it need not be necessarily redefined in the derived class. In such cases, calls will invoke the base version.

In the next section, let’s discuss about pure virtual functions.

## Pure Virtual Functions

In normal practice, a virtual function is declared in the base class and redefined in the derived classes. In addition, the virtual function inside the base class is rarely used for performing any task, that is, it only serves as a placeholder. Therefore, let’s now introduce the concept of pure virtual functions. A pure virtual function is a virtual function that has no definition within the base class. The following syntax is used to declare a pure virtual function:

```cpp
virtual type functionName (arg-list) = 0;
```

When a virtual function is made pure, every derived class that inherits it must provide its own definition by overriding it. If the derived class fails to override the pure virtual function, the compiler raises a compile-time error. The actual syntax in the definition of pure virtual function has nothing to do with the assignment; the value 0 is not assigned to anything. The syntax only tells the compiler that this function will be pure. Let’s write the following program on pure virtual functions:

```cpp
1:/* Virtual Function Example Program 6 */
2:#include <iostream.h>
3:using namespace std;
4:
5:class Base {
6:public:
7:    virtual void show () = 0;          /* Pure Virtual Function */
8:};
9:
10:class Derived1 : public Base {
11:public:
12:    void show ()
13:    {
14:        cout<<"Inside class Derived1"<<endl;
15:    }
16:};
17:
18:class Derived2 : public Base {
19:public:
20:    void show ()
21:    {
22:        cout<<"Inside class Derived2"<<endl;
23:    }
24: };
25:
26: int main()
27: {
28:     //Base             BaseObj;        /* Will generate compiler error - Illegal */
29:     Base *ptr[2];                     /* Pointer to Base class - Legal */
30:     Derived1        derv1_obj;       /* Object of Derived1 */
31:     Derived2        derv2_obj;       /* Object of Derived2 */
32:
33:     ptr[0] = &derv1_obj;              /* Putting addr of derv1_obj in ptr */
34:     ptr[1] = &derv2_obj;              /* Putting addr of derv2_obj in ptr */
35:
36:     ptr[0]->show();
37:     ptr[1]->show();
38:
39:     return 0;
40: }
```

In line number 7, the base class declares a pure virtual function. Now, both the derived classes, Derived1 and Derived2, inherit the Base class and override the virtual function show(); otherwise, the compiler will generate an error for not overriding a pure virtual function. One more important thing to note is the only commented line in the main() function. This line tries to declare an object of the base class, but on declaring it, the compiler will generate an error saying a class with a pure virtual function in it cannot be instantiated. We learn more about this while discussing abstract classes. Following is the output of the preceding program:

```text
Inside class Derived1
Inside class Derived2
```

Let’s now learn about abstract classes.

## Abstract Classes

A class that contains at least one pure virtual function is said to be abstract. As an abstract class contains one or more pure virtual functions, no object can be created for an abstract class. An attempt to instantiate an object of an abstract class will generate a compiler error. Instead, an abstract class constitutes an incomplete type that is used as a foundation for derived classes.

Although we cannot create objects of abstract classes, we can create pointers and references to an abstract class. This allows an abstract class to support runtime polymorphism. In the preceding program, the Base class was an abstract class; and therefore, an attempt to create an object of the Base class in the main() function would have resulted in an error. That is why we have commented line number 28 in the preceding program.

Till now, we have covered almost all the concepts of virtual functions; however, one last thing is left to cover, that is virtual destructors. Let’s discuss about virtual destructors with the help of some programs.

## Virtual Destructors

Base class destructors should always be virtual. Suppose we use delete with a base class pointer to a derived class object to destroy it. If the base class destructor is not virtual, then delete, similar to a normal member function, calls the destructor for the base class and not the destructor for the derived class. This will cause the base part of the object to be destroyed only. Let’s illustrate the concept by writing the following program:

```cpp
1: /* Non-Virtual Destructor Example Program */
2: #include <iostream>
3: using namespace std;
4:
5: class Base {
6: public:
7:     ~Base() {
8:         cout << "Base Destroyed" << endl;
9:     }
10: };
11:
12: class Derived : public Base {
13: public:
14:     ~Derived()
15:     {
16:         cout << "Derived Destroyed" << endl;
17:     }
18: };
19:
20: int main()
21: {
22:     Base *ptr = new Derived;
23:
24:     delete ptr;
25:
26:     return 0;
27: }
```

The output of the preceding program is as follows:

```text
Base Destroyed
```

Therefore, we can observe that only the base part of the object is destroyed. Let’s modify the preceding program using a virtual destructor in the Base class and see the changes in the output:

```cpp
1: /* Virtual Destructor Example Program 7 */
2: #include <iostream.h>
3: using namespace std;
4:
5: class Base {
6: public:
7:     virtual ~Base() {
8:         cout << "Base Destroyed" << endl;
9:     }
10: };
11:
12: class Derived : public Base {
13: public:
14:     ~Derived()
15:     {
16:         cout << "Derived Destroyed" << endl;
17:     }
18: };
19:
20: int main()
21: {
22:     Base *ptr = new Derived;
23:
24:     delete ptr;
25:
26:     return 0;
27: }
```

The output of the preceding program is as follows:

```text
Derived Destroyed
Base Destroyed
```

As shown in the output, both the parts of the derived class object are destroyed. Therefore, we should declare the virtual destructors in all the base classes to ensure that the derived class objects are destroyed properly.
