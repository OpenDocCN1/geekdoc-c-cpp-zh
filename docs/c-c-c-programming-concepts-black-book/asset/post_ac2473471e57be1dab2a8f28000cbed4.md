
The preprocessor contains the following directives:

- #if
- #ifdef
- #ifndef
- #else
- #elif
- #endif
- #include
- #define
- #undef
- #line
- #error
- #pragma

As we can see, all the preprocessor directives begin with a # sign. In addition, each preprocessor directive extends only across a single line of code. As soon as a newline character is found, the preprocessor directive is considered to end. No semicolon (;) is expected at the end of a preprocessor directive. For example, the following statement would not work:

```cpp
#include <iostream>     #include <string>
```

In this section, we cover only two of the preprocessor directives (#include and #define), as the other preprocessor directives are already covered in detail in the section on C Programming in this book. Let’s start the discussion on #include.

### #include

The #include directive instructs the compiler to read another source file in addition to the one that contains the #include directive. The name of the additional source file must be enclosed between double quotes or angle brackets. For example, consider the following two statements:

```cpp
#include <iostream>
#include <string>
```

Both the preceding statements instruct the compiler to read and compile the header for the file system library functions. These can be both standard C++ include files and custom header files written by users. Both types of header files can also have #include directives in them. Such directives are referred to as nested includes. The number of levels of nesting varies from compiler to compiler. However, the ANSI C standard supports at least eight nested inclusions. Let’s say, that our program takes a header file myFile.hpp as one standard include file, and now when we check inside myFile.hpp, it might contain other include statements, such as #include <iostream>. Therefore, typically, our program, while being compiled, not only includes myFile.hpp, but also includes iostream before compilation.

The proposed ANSI C++ standard recommends that at least 256 levels of nested inclusions should be supported. The filename enclosed within quotes or angle brackets determines how the search for the specific file should be conducted. If the filename is enclosed in angle brackets, the file is searched for in a manner defined by the creator of the compiler. Often, this means searching some special directory set aside for include files. If the filename is enclosed in quotes, the file is looked for in another implementation-defined manner. For many compilers, this means searching the current working directory. If the file is not found, then the search is repeated as if the filename has been enclosed in angle brackets.

### #define

The #define directive defines an identifier and a character sequence that will be substituted for the identifier each time the identifier is encountered in the source file. The identifier is referred to as macro name and the replacement process as macro replacement. The general form of the directive is as follows:

```cpp
#define MACRO_NAME    char-sequence
```

Notice that there is no semicolon in this statement. There can be any number of spaces between the identifier and the character sequence, but once the character sequence begins, it is terminated only by a newline. Consider the following popular example we use in programming:

```cpp
#define TRUE    1
#define FALSE   0
```

The preceding statements cause the compiler to substitute a 1 or 0 each time TRUE or FALSE is encountered in the program. Macro substitution is simply the replacement of an identifier by the character sequence associated with it. We can even use prepared error messages in macros, as follows:

```cpp
#define ERROR_MSG  "Error Occurred in program\n"
```

Now, whenever the macro ERROR_MSG is encountered, the value will be substituted in its place. One more important thing to mention about macros is that no text substitution occurs if the identifier is within a quoted string. For example, the following statement does not print “Error Occurred in program”:

```cpp
cout << "ERROR_MSG";
```

We can also write multi-line macros as follows:

```cpp
#define ERROR  "This program has \
              encountered an error"
```

C and C++ programmers generally use upper case letters for defined identifiers. This convention helps the reader to understand that a macro replacement will take place. At times, as a typical usage of macros, we define the size of arrays or lists in a macro, and operate on those data structures using the macro definition of size or max length, as a change in size of max limit only costs changing its value in the macro definition and not in all the places where it is used.

### Predefined Macro Names

A macro is a fragment of code, which has been given a name. Whenever the name is used, it is replaced by the content of the macro. We may define any valid identifier as a macro. The main benefit of using a macro is to group a common part of code, which are used multiple times in the entire program; thereby, increasing the readability of the source code. In addition, if something needs to be changed in the common code, then we need to change its related macros only. In such a case, we do not need to change the common code. This makes macros very popular among programmers. C++ contains five built-in predefined macro names, which are given as follows:

- `__LINE__`
- `__FILE__`
- `__DATE__`
- `__TIME__`
- `__STDC__`

The __LINE__ and __FILE__ are the frequently used macros provided by C++. They help a lot during debugging a source program. The __LINE__ macro gives an integer value representing the current line in the source code file being compiled and the __FILE__ macro is a string literal containing the name of the source file being compiled. The __DATE__ macro contains a string of the form month/day/year. This string represents the date of the translation of the source file into object code. Similarly, the __TIME__ macro translates to hour:minute:second. The macro __STDC__ contains the decimal constant 1 and is used for ANSI C standards.

## Chapter 12

It is a good practice to make use of these macros when we are writing a program. It helps in debugging the program. Consider the following program:

```cpp
//Demonstrating the usage of predefined macros in C++
#include <stdio.h>
int main ()
{
    printf("We are in File:[%s] on Line No:[%d] at %s",__FILE__,__LINE__,
           __DATE__,__TIME__);
    return 0;
}
```

After executing the preceding program, we get the following output:

```text
We are in File:[debugging.c] on Line No:[5] at Mar 16 2012 14:27:54
```

The preceding information can help us in debugging large projects consisting of multiple files.
