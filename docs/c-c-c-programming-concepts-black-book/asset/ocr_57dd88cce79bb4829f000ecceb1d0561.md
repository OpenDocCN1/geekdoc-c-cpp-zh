# ## Overview of OOP Principles

In this world, we can find ourselves surrounded by objects, such as computers, refrigerators, coffee machines, and books. Some of these objects operate on their own, whereas, some objects interact with each other. Objects have two inherent properties – *state* and *behavior*. Many objects are similar in behavior, but they may differ in purpose. Similarly, a same action can cause an object to do various things.

Object-oriented concepts encompass three main principles – *encapsulation*, *inheritance*, and *polymorphism*.

Let’s look closely at these terms and find out what they really mean.

# ### Encapsulation

**Grady Booch** defined encapsulation as “the process of compartmentalizing the elements of an abstraction that constitute its structure and behavior; encapsulation serves to separate the contractual interface of an abstraction and its implementation.”

Encapsulation is defined as the process of hiding those details of an object that do not contribute to the significant characteristics of that object. It hides the implementation details of the object and only exposes the interface of the object, that is, the group of all the messages to which the object can respond. Encapsulation assists in separating an object’s execution from its behavior to restrict the use of its internal information. It also helps in retaining the integrity of the object; thereby, restricting the external users to set the internal implementation of the object to an invalid or inconsistent state. Therefore, encapsulation reduces the complexity by restricting the interdependencies between objects.

Encapsulation and abstraction are two concepts in OOP that are closely linked to each other, but in many cases, they are used synonymously by mistake. This is because abstraction is a process and the act of determining the relevant characteristics and behaviors that an object should possess. On the contrary, encapsulation is the mechanism through which the abstraction is actually implemented. Therefore, the two terms should not be confused.
