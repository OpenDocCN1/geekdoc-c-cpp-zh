## CLR

As one of the main components of the .NET Framework, CLR provides portability and security for the programs as well as manages the execution of the programs. In addition, it provides mixed language programming using CTS.

Before going into the details of CLR, let’s learn about the two different types of codes, which are given as follows:

- **Managed code** — CLR executes managed code which accesses both the managed data (refers to the memory location that is allocated and de-allocated by the CLR using the garbage collection technique) and the unmanaged data. Managed code helps the CLR:
  - To locate the method encoded in the assembly module with the help of the metadata information provided by the managed code

The CLR uses the JIT compiler to convert the MSIL code into the managed native code on the demand basis as and when each part of the code is required. In addition, it optimizes the invoked module for the first time during compilation. The C# program executes the native code even if the code is initially compiled into MSIL. Therefore, the program will run nearly as fast as it can if it is compiled into the native code at the first place. However, in .NET environment, the JIT compiler gains more portability due to MSIL. Therefore, the JIT compiler dynamically converts the CIL or MSIL to a managed native code that is optimized for execution on an operating system. Moreover, JIT compilation takes place only when any method is invoked for the first time to provide the optimized code.

There are three different types of JIT compilers, which are as follows:

- **Pre-JIT compiler** → Compiles the entire code into the native code completely
- **Econo JIT compiler** → Compiles the code part by part as and when required
- **Normal JIT compiler** → Compiles only that part of the code when it is called for compilation and places the code in cache

When we compile the C# program, metadata also results as an output along with the MSIL. It contains the following:

- Information of the data used by the program
- The versioning information
- The reference information

The same file contains both the metadata and MSIL. The existence of the metadata eases the execution method and enables a code to interact with other code. Using metadata, the .NET application has the following benefits:

- Application does not require any header files.
- Metadata holds the requirement to execute .exe or .dll files.
- Using metadata, components do not need to register in the registry.
- An object's field can be automatically serialized/deserialized.
- Using metadata at runtime, an application can determine the kind of types the application holds and get the information of the members that type defines. This is also known as late binding.
- Components can be made reusable using metadata. They can be used by different languages.

CLR provides the following services:

- Memory management
- Threads
- Garbage collection
- Exception handling
- Security
- Application isolation
- Data interaction
- Encryption services
- Deployment

In this chapter, we will mainly look into the memory management and the garbage collection technique used in .NET. Other services are out of scope of this chapter.

## Class Library

Generally, the .NET class library is referred to as the .NET Framework Class Library (FCL), whose subset is Base Class Library (BCL). FCL contains a huge set of reusable classes and interfaces as well as value types that provide prefabricated functionalities from reading an XML file to designing a graphic interface. In addition, FCL helps the developers to optimize their development process and provide access to the system functionality. Those who are already familiar with Java may know about the class library. However, .NET class library provides a much broader set of functionalities than any other language can provide. Languages that are supported by .NET architecture can refer to these defined in FCL.

FCL is organized in a hierarchical manner using namespaces, which represent a collection of functionalities that specify a single logical task. Consistent base types provided by FCL are used by all the .NET-supported languages. The namespaces access these base type classes and the assemblies in turn hold these namespace references.

The System namespace is the root namespace that contains the Object base types from which all the other value and reference types are derived. The namespace also provides the main types, such as integer, string, and character, which are mostly used in an application. Other than this, it provides functionalities, such as exception handling, console I/O operations, and math operations, as well as utility types that convert different data types safely. However, to use the utility classes, we need to know which namespace to refer. Therefore, developers can create their own customized namespaces that refer the FCL or they can directly refer to the FCL namespaces into their application. ## CTS

One of the advantages of .NET Framework is that it provides cross-language interoperability. This is possible with the help of CTS provided by Microsoft that concentrates on the type conversion. CTS specifies the rules which include how the types can be declared, used, and managed at runtime that helps in integrating different languages. To summarize, CTS provides the following functionalities:

- Cross-language integration and type safety
- High performance code execution
- An object-oriented platform where codes from different languages can be integrated
- Rules that a language must follow to achieve cross-language interoperability

Types defined by CTS can be classified into the following two categories:

- **Value type** – Refers to a type that contains data. The instance of the value type is allocated either in a stack or in a structure itself. Following are the three kinds of value types:
  - Built-in types
  - User-defined types
  - Enumeration
- **Reference type** – Refers to a type that is allocated in a managed heap. Reference type in OOP language refers to object of classes. In addition, pointers and interfaces can also be classified as reference types.
