# *Library Functions for Modules*

While writing C user-space programs, we can use different library functions that we do not want to define all the time. The most common example is the printf() function. Similar library functions are also available for kernel modules, such as printk().

In the hello.c program, discussed earlier in this chapter, note that we have used the printf() function without including any standard I/O library. This is because kernel modules are object files, whose symbols are resolved during insmod'ing. The definitions for the symbols generally come from the kernel itself. The /proc/kallsyms file provides the list of all the symbols that are exported by the kernel.

Before going further, let's understand the difference between library functions and system calls. Library functions are higher level Application Programming Interfaces (APIs) that run completely in a user space and provide a more convenient interface to the functions. On the other hand, system calls run in a kernel mode on the user's behalf. For example, to format the data passed as an argument to printf(), the system call write() is used that sends the data to the standard output.

Consider the following program:

```
```c
#include <stdio.h>
int main(void)
{
    printf("hello");
    return 0;
}
```
```

Now, compile the preceding program with gcc -Wall -o hello hello.c and run the executable with strace ./hello. The strace tool gives every detail about the system calls a program is using including which call is made, what its arguments are, and what it returns. The output of running the executable with strace ./hello shows that the actual operation behind the printf() function is write(1, "hello", 5).

# Character Device Files

The file_operations structure in the linux/fs.h header file holds the pointers to the functions that the driver registers with the kernel to perform various operations on a device. Every field of the structure corresponds to a function that handles a requested operation; however, not all the entries are mandatory in the structure. An instance of file_operations is commonly known as fops or file ops. The structure assignment is given as follows:

```
```c
struct file_operations file_ops = {
    read: read_my_device,
    write: write_my_device,
    open: open_my_device,
    release: release_my_device
};
```
```

Note that any member of the structure that is not explicitly assigned will be automatically initialized as NULL by the gcc compiler.

# *Exploring the File Structure*

In Linux, a file is a kernel level structure and should not be confused with user-space files. It is not the same file as defined by glibc and it would never appear in the kernel space function. Moreover, the file in context is a Linux open file and not the file on disk; therefore, it should not be confused with an inode, which is used to store the entire information specific to a file in Linux systems.
