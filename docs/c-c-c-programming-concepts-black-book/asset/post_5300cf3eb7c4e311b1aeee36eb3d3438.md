## Resource File

Resource files in .NET are used to store the resources, such as bitmaps, icons, and local-specific strings. These files are created with an extension resx. When we compile the code in the .NET platform, the compiler compiles these files into the binary files with the .resource extension and then the linker put these files into the assembly. Therefore, the final .exe, which will be executed, contains the information about the resources as well. The resource files ease the job of the processor in managing the resources.

## Global Assembly Cache

The machine-wide code cache that is installed with the CLR is known as Global Assembly Cache (GAC). It acts as a central repository for an assembly. Therefore, we need to install an assembly into the GAC to share it with other applications. However, during the installation of assemblies into the GAC, the following points need to be taken care of:

- Assembly dependency should be declared private
- Assembly should be strongly named which means that an assembly name should contain a public key token that makes it strong
- We need to locate the assembly in the application directory

To install an assembly into the GAC, we need to use the Global Assembly Cache Tool or GacUtil.exe. In addition, we should have the administrative rights to install the assembly. For example, to install the Example.dll assembly, we need to open the Visual Studio 2008 Command Prompt window and type the following command:

```
gacutil /i <assembly name>
```

After the successful execution of the preceding command, the DLL or the assembly file will be stored in the C:\Windows\assembly location.

In .NET, DLL Hell refers to a problem that occurs when multiple programs in an application attempt to share the same DLL. This problem occurs if the version information about different DLLs of an application is not recorded into the system. Therefore, the use of GAC helps in avoiding DLL Hell that arises due to the incompatible versioning problem of the DLL files and leads to improper execution of an application.

## Memory Management in C# Programming

CLR requires all its resources to be allocated in a managed heap, which represents an array of memory addresses that is used to allocate objects. This heap has a pointer, which at the beginning points to the base address of the heap. While allocating the objects, this pointer always points to the next available address of the managed heap. Figure 16.15 shows the structure of the managed heap:

![](img/43c5f409f9b17790a628c4b4df854b61_517_0.png)

Whenever an object is created using the new keyword, that object is usually allocated to a 16 KB memory space (may vary from system to system) in the managed heap. Therefore, when the pointer in the managed heap points to a memory address, which no longer belongs to the managed heap, garbage collection procedure is called.

In this section, we mainly discuss the garbage collection procedure with the help of an algorithm.

The garbage collection procedure checks if there are any objects in the managed heap that are no longer in use. If there are such objects, then the memory spaces allocated to those objects are reclaimed for the newly created objects. Garbage collection procedure runs based on the following three assumptions:

- **Assumption 1**—We can easily maintain a part of the heap as compared to the entire heap. Therefore, the managed heap is divided into three sections, which are known as *generations*. These three generations are *Generation 0* or *G0*, *Generation 1* or *G1*, and *Generation 2* or *G2*, as shown in Figure 16.16:

![](img/43c5f409f9b17790a628c4b4df854b61_518_0.png)

**Figure 16.16: Displaying the Generations in a Managed Heap**

Initially, whenever an object is created, it is placed in G0 by default and the garbage collector always starts its processing from G0.

- **Assumption 2**—Objects that are still in use are always shifted to the next generation. For example, we have initially created three objects, which are placed in G0. After some time, if they are still in use, then they are shifted to the next generation G1. This whole process is explained in Figure 16.17.

![](img/43c5f409f9b17790a628c4b4df854b61_518_1.png)

**Figure 16.17: Displaying the Shifting of Objects**

Note that if the object has to shift the location, then the garbage collector has to be run. Moreover, the garbage collector will run whenever G0 is full.

- **Assumption 3**—Newly created objects have a shorter life span.

Let's now explain the garbage collector procedure with the help of the following example:

```csharp
using System;
using System.Collections.Generic;
public class Program
{
    public static void Main()
    {
        List<object> myList = new List<object>();

        for (int i = 0; i < 10000; i++)
        {
            myList.Add(new object());
        }
        Console.WriteLine("Total object created is {0}", myList.Count);
    }
}
```

According to the preceding example, 10000 objects of the Object class are added to the List object. Therefore, these objects are first placed in G0. However, as the managed heap gets full, the garbage collection procedure is run.

During the processing of the garbage collector procedure, it first detects the objects that are still in use as well as those that are not in use. The objects that are still in use are moved to G1 and the spaces of unused objects are reclaimed using the garbage collection procedure. **Figure 16.18: Displaying the Garbage Collection Procedure**
