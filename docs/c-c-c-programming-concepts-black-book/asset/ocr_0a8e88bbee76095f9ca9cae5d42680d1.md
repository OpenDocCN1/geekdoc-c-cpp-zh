# Describing the Isolated Storage

Sometimes when we try to save a file in a registry or disk, the operation fails due to an access issue or storage issue. Moreover, if the location is known to other users, then they can access the file easily and damage the data in it. Therefore, Microsoft provides a better way to handle the application-specific user data known as isolated storage.

Isolated storage creates a virtual store for an application. Whenever a file is created through the application, it is saved in the isolated storage area. Only the application and the .NET assembly have the access to this isolated storage. In other words, any other application cannot access this isolated storage area assigned to the application; thereby, providing a secret, application-specific storage. Therefore, isolated storage provides a trusted way to store any application-specific user data, as the data is configured and controlled by an administrator only. The .NET runtime environment uses a user-friendly mechanism of the operating system to support this concept. An application can utilize the isolated storage in the following two ways:

+   - Isolated storage can be accessed by the application and the assembly. For multiple instances of the application, the same storage area can be accessed.
+   - Isolated storage can be accessed by the application, each instance of it, and the assembly. It implies that the application can be written in such a way that each instance can access different isolated storage area. This refines the access procedure, and reduces the possibility of errors due to concurrent execution.
