Now, let’s learn about destructors.

### Destructors

A member function of class A, named ~A, is called the destructor of class. A destructor is called implicitly when an object is destroyed. If no destructor is provided, then the compiler provides a default destructor. Destructors cannot take any argument, cannot be overloaded, and cannot return any value. Consider the code given in Listing 13.6.

**Listing 13.6:** Showing the Code for Destructor

```cpp
class A
{
    public:
    int *x;
    A(int);
    ~A();
};

A::A(int y)
{
    x = new int[y];
}

A::~A()
{
    delete[] x;
}
```

### Class Members

Data members and functions are the members of a class that must be declared within the class definition. Consider the code snippet given in Listing 13.7:

**Listing 13.7:** Showing an Example of Class Members

```cpp
class A
{
    int a;             // a is a data member of class A
    int b;             // b is a data member of class A
    int a;             // Error redefinition of a
};
```

Note that we cannot declare a member twice within a function. Moreover, no member can be added elsewhere other than the class definition.

Listing 13.8 shows func_1 and func_2 as the member functions of class B:

**Listing 13.8:** Showing Another Example of Class Members

```cpp
class B
{
        int a;
        float b;
        void func_1(int, float);
        int func_2();
};
```

In the preceding example, both the member functions determine the behavior of the objects of class B.

### Definition of Member Functions and Access controls

Member functions have access to all the data members of a class. A member function can be defined, as shown in Listing 13.9:

**Listing 13.9:** Showing the Definition of Member Functions

```cpp
void Y :: func_1 ( int a, int b)
{
    x = a;                    // a is the data member of class Y
    y = b;                    // b is also a data member of class Y
}
int Y :: func_2 ()
{
    return a;
}
```

Moreover, one member function can use other member functions of a class, as shown in Listing 13.10:

**Listing 13.10:** Illustrating the Access Control of Member Functions

```cpp
void Y :: func_1 (int a , int b)
{
    x = a;
    y = b;
    printf ( "%d", func_2() ) ; // Y :: func_1 () calls Y :: func_2()
}
```

### Messages to Objects

Member functions of a class are invoked by the messages to objects. Messages to objects access the data members of the objects through the member functions. Listing 13.11 shows how to pass messages to objects:

**Listing 13.11:** Passing Messages to Objects

```cpp
1: class A;
2: void func()
3: {
4:     A obj_A;
5:     obj_A.func (10, 10);
6: }
```

In the class A, obj_A is an object of type A. Line 5 of the code denotes the message to the object obj_A, where func() is the function to be invoked by the message.

### Objects

An object is an instance of a class. According to Grady Booch,“an object has state, behavior, and identity; the structure and behavior of similar objects are defined in their common class; the term instance and object are interchangeable.” Listing 13.12 shows how to declare objects as the instances of a class:

**Listing 13.12:** Declaring Objects as the Instances of a Class

```cpp
class A;
A a ;                       // a is an object of type A.
Circle c1, c2;              // c1 and c2 are objects of type Circle.
Circle c3 = c2;             // c3 is a copy of c2
class Date
{
    int day, month, year;
    .....
};
Date todays_date;
Date my_birthday = todays_date ; // my birthday is a copy of todays_date
```

Similar to any variable, storage modifiers can also be used while declaring the objects. We can declare the objects as static, auto, register, and const.

In the next section, let’s revisit the concept of encapsulation to illustrate the access control level of the members of a class and external users.

### Encapsulation - Access Control to the Members and External Users

Members of a class can be declared as *private*, *protected*, or *public*. A *private* member of a class can only be used by the member functions of the class within which it is declared. A *protected* member of a class can be accessed only by the member functions of the class within which it is defined and by the member functions of the classes that are derived from that class. On the contrary, *public* members of a class can be used by any function and the access control level is applied uniformly to all the member functions and data members.

Classes that have all the public data members are more susceptible to be misused by the users, as there is no protection for those members. This is strictly not in harmony with the object-oriented principles, as the implementation details are not isolated from the users. The concept of data or information hiding fails to prevail over these classes.

Listing 13.13 shows the GEN class to understand the concept of access controls:

**Listing 13.13:** Showing the Code for GEN Class

```cpp
class GEN
{
private :
    int a;
    int b;
protected :
    func_1();
    int c;
public :
    func_2();
    func_3();
};
```

Now, consider the OBJ_FUNC() function, given in Listing 13.14:

**Listing 13.14:** Showing the Code for OBJ_FUNC() Function

```cpp
1: void OBJ_FUNC()
2: {
3: GEN obj_GEN;
4: obj_GEN.a = 5;
5: obj_GEN.func_2();
6: obj_GEN.func_3();
7: obj_GEN.func_1();
8: obj_GEN.c = 3;
9: }
```

Line 3 of the function denotes that obj_GEN is an object of the GEN class. The declaration at line 4 will give an error, as a is a private member of the GEN class. Both the lines 5 and 6 are correct, as func_2() and func_3() are the public members of the GEN class. Again, line 7 gives an error, as func_1() is a protected member of GEN and not accessible to a function, which is neither its member function nor its derived class. Similar is the case for line 8.

In UML, five types of views are available, which are given as follows:

- **User View**—Illustrates how an end user views a system
- **Structural View**—Illustrates the static feature of a model that includes classes, attributes, behaviors, and the relationships between classes
- **Behavioral View**—Shows the interaction between the objects and the way a group of objects collaborates in same behavior
- **Component View**—Illustrates the organizations and dependencies among software components, including source code, runtime, and executable components
- **Deployment View**—Displays the physical layers of a system by revealing the software-hardware dependencies in it
