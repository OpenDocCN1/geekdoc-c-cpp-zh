
Each parameter of the API is explained as follows:

- The thread parameter is the ID of the new thread
- The attr parameter specifies the attributes of the new thread (which will be discussed later in this chapter)
- The new thread starts its execution by invoking start_routine with arg as an argument

Let's compile and run the program. For compilation, we should link the program to the pthread library during the compilation, as follows:

```
gcc thread1.c -o thread1 -lpthread
```

Now, to run the program, execute the following command in the UNIX prompt:

```
./thread1
```

In the preceding program, we have made a call to pthread_create() by using a pointer to a thread. In the pthread_create() call, the thread attribute is sent as NULL, the start function pointer is set to thread_function(), and thread_params is passed as an argument to pthread_create(). On the successful execution of pthread_create(), the main and child threads run in an overlapped manner giving the essence of parallelism. From the main() function, the main thread prints "In main" for 1000 times and the child thread prints "I'm thread" for 10000 times.

As the main thread loops for 1000 times and the child thread loops for 10000 times, the main thread will complete its execution before the child thread. This may lead to a critical issue in the preceding program. The child thread, which completes later than the main thread, remains in the system as a zombie thread. Zombie threads are a special kind of threads that have completed their execution but are still present in the table of active threads. They have nothing to do, but as they did not exit normally, they still hold the resources that they were using in their lifetime. The solution of this issue is the use of pthread_join(), which properly cleans the zombie threads; otherwise, the situation cannot be handled.

A call to pthread_join() from the main thread will make it wait for the child thread to finish first. Only then, the main thread can exit. The syntax of pthread_join() is as follows:

```c
int pthread_join (pthread_t thread_id,
                  void **retval);
```

The pthread_join() API waits for the thread identified by thread_id to terminate. Generally, a thread can terminate under the following circumstances:

- The thread calls pthread_exit().
- The thread returns from the thread function.
- The thread is cancelled.
- The thread in the process calls the exit() function or the main thread performs a return from the main() function. This terminates all the threads created by the process.

The retVal argument collects the return value from the terminated thread. If there is nothing to return, then NULL can be passed. In a multithreading environment, all the threads in a process are peers; therefore, during the execution cycle, any thread can join another thread in the process.

Now, consider the thread2.c program to understand the working of pthread_join():

```c
/* thread2.c - demonstrating the usage of pthread_join */
#include <stdio.h>
#include <pthread.h>

struct thread_args {
    char    name[20];
    int     count;
};

void *thread_function(void *arg);

int
main ()
{
    int             local_counter = 100;
    int             ret         = 0;
    pthread_t       thread;
    struct thread_args  params;

    strcpy (params.name, "I'm thread");
    params.count = 10000;

    ret = pthread_create(&thread, NULL, thread_function, (void*)&params);
    if (ret != 0) {
        fprintf(stderr, "\nthread creation failed\n");
        return 1;
    }

    printf("Output:\n");
    while (local_counter) {
        printf("in main\n");
        local_counter--;
    }

    printf("\nwaiting for thread to finish...\n");
    ret = pthread_join(thread, NULL);
    if (ret != 0) {
        fprintf(stderr, "\nthread join failed\n");
        return 0;
    }
    printf("\nthread joined\n");

    return 0;
}

void *thread_function(void *arg)
{
    struct thread_args  *params = (struct thread_args*)arg;

    while (params->count) {
        printf("%s\n", params->name);
        params->count--;
    }
}
```

In the preceding program, the main thread completes its execution and waits for the child thread to finish, before it can exit. A call to pthread_join() is performed with retVal, which is set to NULL.

Now, let's consider a situation where a child thread returns something to the main thread before it exits. To do this, we use the second argument of the pthread_join() API, as shown in the following program:

```c
/* thread3.c - demonstrating returning of args from child thread by pthread_join */
#include <stdio.h>
#include <pthread.h>
#include <stdlib.h>

struct thread_args {
    int        num1;
    int        num2;
};
void *thread_function_sum(void *arg);
void *thread_function_product(void *arg);

int
main ()
{
    int         count  = 1000;
    int         ret    = 0;
    pthread_t   thread1;
    pthread_t   thread2;
    struct thread_args params;
    void        *thread_result = NULL;

    params.num1 = 5;
    params.num2 = 15;

    ret = pthread_create(&thread1, NULL, thread_function_sum, (void*)&params);
    if (ret != 0) {
        fprintf(stderr, "\nThread creation failed\n");
        return 1;
    }

    ret = pthread_create(&thread2, NULL, thread_function_product, (void*)&params);
    if (ret != 0) {
        fprintf(stderr, "\nThread creation failed\n");
        return 1;
    }

    printf("OUTPUT:\n");

    printf("\nWaiting for threads to finish...\n");
    ret = pthread_join(thread1, &thread_result);
    if (ret != 0) {
        fprintf(stderr, "\nThread join failed\n");
        return 0;
    }
    printf("\nThread1 joined. sum=[%d]\n", *((int*)(thread_result)));

    ret = pthread_join(thread2, &thread_result);
    if (ret != 0) {
        fprintf(stderr, "\nThread join failed\n");
        return 0;
    }
    printf("\nThread2 joined. product=[%d]\n", *((int*)(thread_result)));

    return 0;
}

void *thread_function_sum(void *arg)
{
    struct thread_args  *params = (struct thread_args*)arg;
    int                 *result = (int*)malloc(sizeof(int));

    *result = params->num1 + params->num2;
    return result;
}

void *thread_function_product(void *arg)
{
    struct thread_args  *params = (struct thread_args*)arg;
    int                 *result = (int*)malloc(sizeof(int));

    *result = params->num1 * params->num2;
    return result;
}
```

In the preceding program, we have created one main thread and two child threads from the main() function. After they are created, all the three threads start execution in an overlapped manner. Now, both the child threads have different start_routine as their argument in the pthread_create() API. The child thread1 calls thread_function_sum() and the child thread2 calls thread_function_product(). Both the functions do some amount of processing in their respective start_routine and return a value while exiting. The preceding program is a bit different from the thread2.c program, as the pthread_join() call has a non-null argument of type void pointer. Both the thread functions return their output through the second argument in the pthread_join() call. The main thread, after completing its execution, waits for the child threads to finish their work. After the child threads exit, the main thread takes the return values of the child threads and processes them accordingly.

Let's now learn about thread attributes, in detail.

## Thread Attributes

In the previous program of pthread_create() API, we have intentionally passed its second argument as NULL to simplify the program. While calling the pthread_create() API, if we pass NULL in place of the thread attribute, then the thread will be created with the default attributes, that is, it will be a joinable thread. However, if we want to specify custom thread attributes, then we need to handle the call explicitly as follows:

- Create a pthread_attr_t object by declaring an automatic variable
- Call pthread_attr_init() on an object to initialize it with the default values
- Modify the pthread attribute object as per the requirements and set the necessary attributes
- Pass the pointer to the pthread attribute object as an argument into pthread_create()
- Call pthread_attr_destroy() to release the attribute object

Following different types of custom thread attributes can be passed to the pthread_create() API:

- Joinable Thread (Default)—When a thread terminates, it will not be cleaned up automatically. This implies that the thread becomes zombie until pthread_join() is called on it.
- Detached Thread—When a thread terminates, it will be cleaned up automatically, and therefore, pthread_join() need not be called.
- Scheduling Policy for a Thread (Real Time? PTHREAD_INHERIT_SCHED, PTHREAD_EXPLICIT_SCHED, SCHED_OTHER)—This specifies the type of scheduling policy a thread should use. It is used primarily for real time threads to differentiate them from other threads.
- Scheduling Parameter—This sets the scheduling parameters in the thread attribute object. By using this, the priority of a thread is set.
- InheritSched Attribute (Default: PTHREAD_EXPLICIT_SCHED Inherit from parent thread: PTHREAD_INHERIT_SCHED)—This is primarily used while creating new threads.
- Scope (Kernel threads: PTHREAD_SCOPE_SYSTEM, user thread—PTHREAD_SCOPE_PROCESS pick one or the other, but not both). This helps us to work in two different modes – kernel space and user space.
