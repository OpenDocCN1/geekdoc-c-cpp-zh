
The Floyd’s algorithm compares all the possible paths between every pair of vertices in a graph and selects the shortest path. It is used in several real-time transportation and routing management systems due to its optimum cost factor association. However, the complexity of this algorithm is little higher, that is, for V number of vertices, the average complexity is O(V³).

Let’s consider a graph G with V vertices and E edges. We formulate a function called shortestPath(i,j,k) that returns the shortest possible path between the vertices i and j, but only using the edges from the set {1 through k} as the intermediate points. Now, if the weight of an edge is W(i,j) between the vertex i and the vertex j, then we can have shortest path as:

```text
shortestPath(i, j, 0) = W(i, j)
```

Similarly, the recursive formula will be as follows:

```text
shortestPath (i, j, k) = min (shortestPath(i, j, k-1), shortestPath(i, k, k-1) +
shortestPath(k, j, k-1));
```

The preceding process continues in an iterative manner to determine the shortest paths between every pair of nodes for a directed graph. Generally, for this algorithm, the cost associated between every pair of nodes is non-negative. However, during computation, if there is no path between a pair of vertices, then we represent it as infinity or a very big number, as this is never going to affect the calculation for shortest path.

## Chapter A: Some Important Concepts of C++

### The this Pointer

Whenever a member function is called by an object, we can always access the object using an invisible pointer named the “this” pointer. The member functions of an object have access to the “this” pointer, which is a magical pointer that points to the object itself. In C++, the “this” pointer is a very useful tool that helps in accessing the object from within its member functions. This concept is illustrated through the following code snippet:

```cpp
#include <iostream>
using namespace std;

class example {
    int memberData;
public:
    example() {
        this->memberData = 1;
    }

    ~example() {
        this->memberData = 0;
    }

    void set_n_show (int var) {
        this->memberData = var;
        cout <<memberData<<endl;
    }
};

int main ()
{
    example obj1, obj2;

    obj1.set_n_show (99);
    obj2.set_n_show (88);
    return 0;
}
```

Output:

```text
99
88
```

It can be seen in the output of the preceding program that in the method “set_n_show()” of the class example, we are accessing the memberData of the calling object with the help of the this pointer. The preceding program can be performed without using the “this” pointer in the method “set_n_show(),” but using the “this” pointer enhances the readability of the source code.

The “this” pointer finds its main application in cases of operator or function overloading when different types of objects can call a single overloaded operator or function for execution. Note that the “this” pointer is not accessible in static member functions and also in case of friend functions.

### Inline Specifier

C++ provides an interesting feature known as inline function, which has the feature of both a function and a MACRO. An inline function not only prevents duplication of code like a common C++ function but also saves the function calling overhead by expanding inline like a MACRO.

We all know that function saves space in the memory because every call to the function, during the program execution, causes the same memory chunk to get executed. However, this feature does not come for free. Any call to a function does a lot of background job during any function call. Whenever the compiler finds a function call in the source code, it immediately takes the program control to the calling function from the caller function. However, in between the generation of a jump to the function, a lot of instruction execution takes place, such as instruction for saving register content for the previous execution instruction, instruction for pushing arguments onto stack, instruction for restoring registers, and lots more.

Imagine a scenario where a function has a very small body, such as a utility function for calculating the power of an integer member or a function to check whether a flag is enabled or not. For such cases, we cannot afford to spend so much overhead in saving registers and doing all other instruction execution like we do for any normal function call. As a solution to this, the inline function is introduced, which resembles exactly like a function but ignores the overhead associated with the function call mechanism by expanding the function call inline.

C++ implements the inline function with the help of an “inline specifier.” Let us illustrate the concept of an inline function by writing a small program:

```cpp
#include <iostream>
using namespace std;

class example {
    bool privateFlag;
public:
    void set (bool flag) {
        this->privateFlag = flag;
    }
    inline bool isFlagSet () {
        return this->privateFlag ? true : false;
    }
};

int main ()
{
    example obj;
    obj.set(true);
    cout << "The status of the flag is " << obj.isFlagSet() << endl;
    return 0;
}
```
