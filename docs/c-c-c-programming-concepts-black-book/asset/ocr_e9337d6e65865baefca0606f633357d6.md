As a successor of UNIX, Linus Torvalds developed the Linux operating system in the year 1991 for the computers using the Intel 80386 microprocessor. Although Linux is designed over the foundations of UNIX, it has applied its own intelligence and optimization to deviate from the path shown by UNIX. However, Linux has neither broken the application interfaces of UNIX nor compromised with the general design goals of UNIX.

One of the most fascinating features of the Linux operating system is that it is not a commercial product; instead, it is an open source project, developed collaboratively over the Internet. Although Linus Torvalds remains the creator and maintainer of the Linux, progress continues as programmers across the world are contributing to make it richer in features. As the Linux kernel, along with much of its system, is free and open source software; therefore, anyone willing to contribute can take part in this project. The Linux kernel is licensed under the GNU General Public License (GPL). Therefore, anyone willing to make modifications can download the source code over the Internet and work on it.

# ## Overview of the Linux Operating System

Linux operating system comprises the kernel, device drivers, boot loader, command shells, and other user interfaces along with the basic files and system utilities. Kernel is the innermost and important part of the Linux operating system. It can be defined as system software that provides basic services to all the other parts of the system, manages hardware, and distributes system resources. Typical components of a kernel include interrupt handlers for servicing the interrupt requests, a scheduler to share the processor time among competing processes, a memory management unit managing the process address space, and a set of system services, such as inter-process communication and networking.

Nowadays, with the protected memory management units, kernel resides in a higher level of system state as compared to the normal user applications. This includes protected memory space and a full access to hardware. The system state and memory space collectively referred to as *kernel space*. On the other hand, user applications execute in *user space*. Unlike the kernel space, applications in the user space view only a subset of system's available resources and are unable to perform certain functions, such as directly accessing or communicating with hardware. Applications running in the user space use the *system calls* to communicate with the kernel. A system call is a program that requests a service from the kernel. Generally, system calls are invoked by the processes, which are running in a user space.
