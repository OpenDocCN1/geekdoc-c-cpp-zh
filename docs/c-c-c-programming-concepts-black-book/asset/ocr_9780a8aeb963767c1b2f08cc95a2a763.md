As shown in Figure 24.17, the keys for two consecutive records are two widely separated numeric values. For Record 0, the key value is 4800 and for Record 1, the key value is 0001. On the other hand, for two distant records, such as Record 50 and Record 99, the key values are relatively closer to one another. Therefore, it is important to establish a mapping between the index and the key value by using a hash function.

Hash function finds the index value of the array using the key id. Therefore, if K is the key value for Record R, then the hash function H can be written as H(K). In our case, as the last two digits represent the index value, the hash function would be K%100.

It is the main task of a developer to select a good hash function. However, as there is a huge range of keys of four digits, it may happen that a hash function may result in the same index for two different keys. For example, if we construct the hash function in such a way that it picks up 4800 and 6700 as keys for Record 0, then it will hash to the same value, that is, 00, which results in a collision. To avoid such collision, we can use the following two techniques to resolve it:

+   - Separate chaining
+   - Open addressing

Let’s learn about these techniques in the next sections.

# ### *Separate Chaining*

The separate chaining technique uses an array of linked lists to resolve the collision when the two key values hash to the same value. Bucket hashing is one of those techniques that implement the separate chaining methodology to prevent the collision. In bucket hashing, hash table is implemented in the form of buckets. A bucket is an array that can hold a number of records. In bucket hashing, the hash function hashes the key to find the bucket number. If the hash function hashes a key to store the record that already exists in the bucket, then we do not store that record. In this way, we can avoid having collision between the key values.
