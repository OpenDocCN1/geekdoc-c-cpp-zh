The Floyd’s algorithm compares all the possible paths between every pair of vertices in a graph and selects the shortest path. It is used in several real-time transportation and routing management systems due to its optimum cost factor association. However, the complexity of this algorithm is little higher, that is, for V number of vertices, the average complexity is O(V³).

Let’s consider a graph G with V vertices and E edges. We formulate a function called shortestPath(i,j,k) that returns the shortest possible path between the vertices i and j, but only using the edges from the set {1 through k} as the intermediate points. Now, if the weight of an edge is W(i,j) between the vertex i and the vertex x, then we can have shortest path as:

```
shortestPath(i, j, 0) = W(i, j)
```

Similarly, the recursive formula will be as follows:

```
shortestPath (i, j, k) = min (shortestPath(i, j, k-1), shortestPath(i, k, k-1) +
shortestPath(k, j, k-1));
```

The preceding process continues in an iterative manner to determine the shortest paths between every pair of nodes for a directed graph. Generally, for this algorithm, the cost associated between every pair of node is non-negative. However, during computation, if there is no path between a pair of vertices, then we represent it as infinity or a very big number, as this is never going to affect the calculation for shortest path.
