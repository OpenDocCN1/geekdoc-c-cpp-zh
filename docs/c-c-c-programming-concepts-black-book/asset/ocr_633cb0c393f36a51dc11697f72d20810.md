# Data Abstraction and Information Hiding

Information hiding is a very important term used in OOP, where a class tries to hide its implementation details from its users. For example, we can implement a stack using the concept of arrays or linked lists. This, however, does not affect the functionality of the stack. A user bothers only about how the stack performs and what functionality it provides, but not about how it is implemented. This concept is called data abstraction.

Consider the EmployeeSal class to calculate the salary of an employee. Listing 13.22 shows the code of the EmployeeSal class:

**Listing 13.22:** Showing the Code to illustrate Information Hiding

```
class EmployeeSal
{
    public:
        void setSalary(double sal);
        {
            salary = sal;
        }
    private:
        double salary;
}
```

People may confuse encapsulation with information hiding. Encapsulation enables us to draw a boundary around something that we want to encapsulate. It enables us to communicate about the inner and outer worlds of that boundary. Information hiding, on the other hand, is a design, which limits the direct exposure of data and implementation flow to prevent unwanted coupling. Information hiding is a design principle; whereas, encapsulation is merely a feature of programming languages.

> > According to John Wilkinson, “Information hiding or the opposite, information leakage may span multiple objects, or it may involve other forms of coupling between client code and implementation code. For example can all order dependency will expose some information that normally should be hidden. Another example might be default values that are used by the client code. There are examples of perfectly encapsulated code that still exhibits information hiding problems.” Therefore, encapsulation is not synonymous to information hiding, but in some ways, it requires some degree of information hiding.

Abstraction, encapsulation, and information hiding can be implemented using Abstract Data Types (ADTs). An ADT is a class that is designed to be served as an interface for derived classes.
