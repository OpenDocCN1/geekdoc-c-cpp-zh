## Listing 19.15: Showing a Different Approach of Implementing LINQ to XML

```csharp
using System;
using System.Linq;
using System.Xml.Linq;
using System.Collections;
using System.Collections.Generic;

class Program
{
    public static void Main()
    {
        // Load the XML document
        XDocument doc = XDocument.Load(@"C:\Employee.xml");

        // LINQ Query to get XML elements
        var query = from child
                    in doc.Element("Organization").Descendants("Employee")
                    where child.Element("LastName").Value.Equals("Scott")
                    select new {
                        empID = child.Element("EmpID").Value,
                        firstName = child.Element("FirstName").Value,
                        lastName = child.Element("LastName").Value
                    };

        // Get the result
        foreach (var ele in query)
        {
            Console.WriteLine("Employee ID : {0} Employee Name : {1}", ele.empID,
                ele.firstName + " " + ele.lastName);
        }
    }
}
```

## LINQ to ADO.NET

LINQ to ADO.NET uses the relational database as a data source. The usage of disconnected architecture in terms of ADO.NET is one of the attractive features of .NET architecture. In this section, let's discuss the following three categories of data source in the context of ADO.NET:

- LINQ to Dataset
- LINQ to SQL
- LINQ to Entities

Let's start our discussion with LINQ to Dataset.

### LINQ to Dataset

A dataset stores a database in a disconnected representation. Using LINQ, a dataset can also be queried using the instance of DataTable. Listing 19.16 shows how to query a DataTable using LINQ.

**Listing 19.16: Showing the Implementation of LINQ to Dataset**

```csharp
using System;
using System.Data;
using System.Linq;

class Program
{
    public static void Main()
    {
        DataTable employeeList = new DataTable();
        // Adding the columns
        employeeList.Columns.Add("Employee_ID", typeof(Int32));
        employeeList.Columns.Add("First_Name", typeof(string));
        employeeList.Columns.Add("Last_Name", typeof(string));
        // Adding rows
        employeeList.Rows.Add("100", "James", "Scott");
        employeeList.Rows.Add("200", "Jonathan", "Jackson");
        employeeList.Rows.Add("300", "Keith", "Scott");
        employeeList.Rows.Add("400", "Johny", "Lee");
        employeeList.Rows.Add("500", "Amy", "John");
        employeeList.Rows.Add("600", "Leonardo", "Scott");

        // LINQ statement
        var query = from emp in employeeList.AsEnumerable()
                    where emp["Last_Name"].Equals("Scott")
                    select emp;

        // Printing the Employee information in the console
        foreach (var emp in query)
        {
            Console.WriteLine("Employee ID : {0} Employee Name : {1}",
                emp["Employee_ID"].ToString(),
                emp["First_Name"] + " " + emp["Last_Name"]);
        }
    }
}
```

In the preceding program, we have stored the data in the DataTable instance instead of storing it in a collection object or an XML file. The output of the program is same as that of Listing 19.15.

### LINQ to Entities

LINQ to Entities uses the Entity Data Model (EDM) to query the data in a relational database. EDM converts a query into a command tree query, executes the query, and returns the objects that can be used by both EDM and LINQ. Moreover, instead of using the data layer, LINQ to Entities uses Object Service Layer to establish the connection between a .NET application and a relational database.

Let’s perform the following steps to understand the execution of LINQ to Entities by using the LINQ project:

- 1. Modify the relational database schema of the project by adding some more tables in the schema. In our case, we have added two more tables: Product and Department. The schema structure of the two tables is given as follows:

```text
Product {Product_ID, Product_Name, Dept_ID}
Department {Dept_ID, Dept_Name}
```

- 2. Modify the Employee table of the relational database schema to include Product_ID as a foreign key in the table. Therefore, the new schema structure of the Employee table will be as follows:

```text
Employee {Employee_ID, First_Name, Last_Name, Designation, Product_ID*}
```
