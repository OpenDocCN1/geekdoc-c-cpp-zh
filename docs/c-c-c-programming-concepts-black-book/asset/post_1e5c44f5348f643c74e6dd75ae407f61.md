
In Listing 7.2, the macro is replaced with an entire conditional statement. During the preprocessing, the macro is expanded and the following line,

```c
if (CONDITION)
```

becomes,

```c
if(((varA < 10) AND (varB > 20)) OR ((varA > 50) AND (varB > 50)))
```

The output of the preceding program is given as follows:

```text
inside the if block
```

Now, suppose there is a constant value in a source code that appears quite a number of times in the code. If the constant value needs to be changed, then we need to manually go through the code and change every occurrence of the constant value. However, if we replace the constant value with a macro, then we need to just change the expansion value and all the occurrences will be automatically replaced with the expanded value. We can achieve the same objective with the help of a variable; however, it would make the compiler slower. Therefore, macros produce more efficient and easily comprehensible codes.

We can also use a macro to perform certain calculations, which could otherwise be done with the help of a function. However, there is a significant difference between a macro and a function. A macro is replaced by the preprocessor blindly without performing any check for errors, whereas, a function is far more secured in terms of syntax errors. A major advantage of a macro is that it is less time consuming than a function. This is because multiple context switching takes place for each call made to a function. In addition, registers and program counters need to be saved and a jump is made to the first instruction followed by the function name. In case of a macro, all this overhead is not required, as it only replaces the code block instead of any context switching. However, one disadvantage of using a macro is that it increases the size of a source code. If a macro is called multiple times in a program, then the same code will be replaced multiple times. Therefore, macros should be used as a shorthand notation, but for large-scale codes, we should still rely on functions.

## Macro with Arguments

Similar to functions, arguments can also be passed to a macro. Listing 7.3 shows how to pass arguments to a macro.

**Listing 7.3:** Passing Arguments to a Macro

```c
#include<stdio.h>
#define SQUARE(num) (num*num)
int main()
{
    int varA;
    printf("\n Enter any number -> ");
    scanf("%d", &varA);
    printf("\n The square root of %d is %d ", varA, SQUARE(varA));
    getch();
    return 0;
}
```

The preprocessor will expand the SQUARE(num) macro to (num*num) during the preprocessing. In the main() function, varA is passed as an argument to the macro that substitutes for num. The output of the preceding program is given as follows:

```text
Enter any number -> 11
The square root of 11 is 121
```

Note that no blank spaces should be present in between a macro and its arguments; otherwise, the compiler will throw an error. Listing 7.4 shows the code with an error in a macro definition:

**Listing 7.4:** Showing an Error in a Macro Definition

```c
#include<stdio.h>
#define SQUARE (num) (num*num)/* error due to blank space between SQUARE and (num) */
int main()
```

When the preceding code is compiled, the compiler would generate the following error:

```text
In function 'main'
'num' undeclared (first use in this function)
```

This is because the preprocessor fails to expand the macro due to the blank space present in between the macro and its argument. In this case, the statement becomes,

```c
(num) (num*num)
```

Another important point to be considered is that when a macro takes arguments, the macro expansion should be enclosed within the parenthesis. Listing 7.5 shows the result of not enclosing a macro expansion within the parenthesis:

**Listing 7.5:** Showing the Result of not Enclosing Macro Expansion within Parenthesis

```c
#include<stdio.h>

int main()
```

Now, let's learn about multi-line macro.

## Multi-Line Macro

Till now, we have used single-line macros in our programs; however, there might be situations where we need to use multiple lines in a macro. For this purpose, C provides multi-line macros, which allow us to provide multiple lines in them. In a multi-line macro, each line should be followed by a backslash (\) character. In case we do not provide a backslash character after each line, the compiler would generate an error. Note that the last line of a multi-line macro should not end with a backslash character. Moreover, the curly braces should surround the body of a multi-line macro. Listing 7.6 shows a multi-line macro:

**Listing 7.6:** Showing a Multi-Line Macro

```c
#include<stdio.h>
#define FINDSUM(num) { \
    int i= 0; \
    while(i <= 10) \
    { \
        num = num + i; \
        i++; \
    } \
}

int main()
{
    int varA;

    printf("\n Enter any number -> ");
    scanf("%d",&varA);
    FINDSUM(varA);
    printf("\n The result is %d ",varA);
    getch();
    return 0;
}
```

In Listing 7.6, you can observe that the last line of the macro does not end with a backslash character. The output of the preceding program is given as follows:

```text
Enter any number -> 100

The result is 155
```

## Nested Macro

A macro body inside another macro definition is referred to as a nested macro. Note that the enclosing macro should be expanded and must be called before the nested macro is called. Listing 7.7 shows a nested macro:

```c
#include<stdio.h>
#define SQUARE(num) (num*num)
```

Now, let’s learn about file inclusion.

## File Inclusion

Consider a scenario where a source code is divided into multiple files and each file contains multiple functions that are interlinked with each other. In addition to this, multiple utility functions and macros are used in multiple files. In this case, it does not make any sense of writing the same piece of code every time. As a better solution, we can write such functions and macros in a common file and then include the file wherever required. This concept is known as file inclusion, which allows the entire content of a file to be inserted in some source code. The syntax for using the file inclusion is given as follows:

```c
#include "file"
```

As a common practice, we provide ".h" extension to the files that are to be included in a source code. The ".h" extension stands for header files. The function prototypes for all the standard library functions are present in different header files. There are two ways of including a header file in a source code. One way is to use the following statement:

```c
#include <stdio.h>
```

The preceding statement would look for the stdio.h file in a specific list of directories. Different C compilers have different search paths for header files. Another way is to use the following statement:

```c
#include "myfile.c"
```

The preceding statement would look for the myfile.c file in the current directory as well as in the specific list of directories mentioned in the include search path.

Let’s now learn about conditional compilation.

## Conditional Compilation

We can make the compiler skip a certain portion of the source code based on some preprocessor directives. This concept is known as conditional compilation. In C, the directives used for conditional compilation are #ifdef, #endif, #undef, #else, and #ifndef.

The #ifdef directive marks the beginning of a conditional compilation block; whereas, the #endif directive marks the end of the block. A general syntax of #ifdef and #endif is given as follows:

```c
#ifdef macro
    statement 1;
    statement 2;
    -----------------
    statement n;
#endif
```

In the preceding syntax, the block of code between #ifdef and #endif will be processed only if the macro name is defined; otherwise, it will not be processed.

One of the major uses of conditional compilation is to comment certain portions of the source code based on some condition. Listing 7.8 shows how the code can be conditionally compiled:

**Listing 7.8:** Showing how to Conditionally Compile the Code

```c
#include<stdio.h>
#define _DEBUG_
int main()
{
    #ifdef __DEBUG__
        printf("\n This code is skipped ");
    #endif
```
