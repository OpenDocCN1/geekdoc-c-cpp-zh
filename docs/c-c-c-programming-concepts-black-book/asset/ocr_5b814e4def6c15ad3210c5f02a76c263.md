Listing 2.22 shows some examples regarding auto variables:

# Listing 2.22: Auto Storage Class Specification

```
~~~c
#include<stdio.h>

int main()
{
    int varA;

    printf("\n Default value of varA is [%d] ",varA);
    getch();
    return 0;
}
~~~
```

The output of Listing 2.22 is given as follows:

```
~~~text
Default value of varA is [1972870708]
~~~
```

The output suggests that auto variables are always initialized with garbage values so they need to be explicitly initialized every time they are declared. Listing 2.23 shows how variables can be accessed beyond their scope:

# Listing 2.23: Accessing Variables Beyond their Scope

```
~~~c
#include<stdio.h>

int main()
{
    {
        int varA = 10;
        printf("\n Default value of varA is [%d] ",varA);
    }
    printf("\n Default value of varA is [%d] ",varA);
    getch();
    return 0;
}
~~~
```

The output of Listing 2.23 is given as follows:

```
~~~text
`varA` undeclared (first use in this function)
~~~
```

The code in Listing 2.23 fails to compile because the variable is getting accessed beyond its scope. An auto variable is only visible inside its scope and does not have any existence, if the control is outside its scope. In this case, the varA variable is declared as an auto variable but within a block scope inside the main function. When the control comes out of a block, any variable declared inside the block gets destroyed. If the same variable gets accessed beyond the scope of the block, the compiler throws an error.
