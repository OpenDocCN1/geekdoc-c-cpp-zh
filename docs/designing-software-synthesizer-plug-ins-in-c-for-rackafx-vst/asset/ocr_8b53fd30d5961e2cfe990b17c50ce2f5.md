The object is responsible for initializing and maintaining the underlying line member objects. It also implements methods that the GUI uses to update these underlying objects. The delay ratio is interesting. This allows you to set the left and right delay times like the K Wavestation's. In these products, the user selects from a list of pre-defined ratios to set up the scaling of the delay time. One channel gets the full delay time, while the other gets a fraction of it. The delay ratio controls this fraction. Rather then implement and decode a table of ratios, we implement a continuous control adjustable from -0.9 to +0.9 as follows for the normal and ping-pong delays:

If ratio is negative:

+   - left delay is abs(ratio)*(total delay time)
- right delay is total delay time

If ratio is positive:

+   - left delay is total delay time
- right delay is ratio*(total delay time)

If ratio is zero:

+   - ratio is 1:1, so left and right delays are both the total delay time (identical)

For the multi-tap variations, the control behaves slightly differently, adjusting the time of the secondary tap as a ratio of the primary tap.

If ratio is negative:

+   - left secondary tap is abs(ratio)*(total delay time)
- right secondary tap is total delay time (1.0 – abs(ratio))*(total delay time)

If ratio is positive:

+   - left secondary tap is total delay time (1.0 – abs(ratio))*(total delay time)
- right secondary tap is abs(ratio)*(total delay time)

If ratio is zero:

+   - left secondary tap = 0 mSec
- right secondary tap = 0 mSec
