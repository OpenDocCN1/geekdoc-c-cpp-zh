Your constructor is where all your variables are initialized. The very first line of the constructor has been written for you; it calls initUI() which is a method that handles the control and setup of your GUI controls. You never modify the initUI() method; RackAFX maintains this code for you.

# Destruction

When users use the DLL either manually or by loading another plug-in, the client first deletes the plug-in from memory, which calls the destructor. Any dynamically declared variables or buffers need to be deleted here. After destruction, the client deletes the DLL from the process space.

# The GUI

RackAFX uses a two-phase approach to GUI design. The first phase is prototyping—here, you create a set of controls using the main interface consisting of slider controls, buttons and a low LCD control (more than one in a moment). You don't need to be careful about the ordering of the controls. The user-interface is not flashy; it's a set of rows and buttons, but it allows you to rapidly prototype your plug-in. When you set up elements on the Prototype Panel, RackAFX adds members to the .h file of your derived plug-in. Each slider or button-group controls one variable in you. You setup each control with minimum, maximum and initial values as well as the name and data type. RackAFX calculates the variable's value and delivers it to your plug-in, automatically updating it in real-time. In some cases, this is all you will need and there is nothing left to write. In other cases, you will need to perform more calculations or logic processing in order to changing the control.

After your plug-in is completed and tested, you move to the second phase by switching to the GUI Designer Panel. Here, you drag and drop controls onto a blank surface, and you link them to the variables you set up in the prototyping phase. You can also customize the controls to a reasonable extent, changing the sizes, bitmaps, colors, fonts and other attributes. You can re-arrange the controls however you wish. It is not uncommon to provide the user with a more limited final GUI than you implemented in the prototyping phase—you decide you do not want the user to have control over some voicing aspects of your plug-in. Many companies go out of their way to prevent the user from making really horrible sounds by limiting the controls and the ranges on them.

# Building and Testing

Finally, you will build the DLL then and fix any issues. After the build succeeds, you can load it into the RackAFX Client. You can use the built-in MIDI piano control (limited) or any Windows compatible MIDI input device (recommended) to generate the MIDI messages needed to test the plug-in.

# Creating and Saving Presets

The presets are created and maintained on the main RackAFX UI. After you load your plug-in you can move the controls like you and then save them as a preset. Use the Save Preset button on the toolbar. The presets will be saved inside a file until the next time you compile your plug-in; after that, the presets will be built into the DLL. You can add, modify, or delete the presets when your plug-in is loaded.

# 2.7 Setting Up RackAFX

Start the RackAFX software. You will start in Prototype View where you will see a blank control surface shown in Figure 2.2. Your GUI may look slightly different or have different background images.

The control surface is what you use to create your user interface. It is full of assignable controls you can connect to your plug-in's variables. The surface consists of:

- 1. 40 assignable sliders (continuous controls)
- 2. universal LCD control with 1024 more continuous controls inside
- 3. project controls (open, load, edit, rebuild, debug, jump-to-C++)
- 4. 4 on-off 2-state switches
- 5. mini-analyzer with scope and spectrum analyzer and joystick control (for vector synths)
- 6. assignable buttons
- 7. 10 assignable LED meters
- 8. input/output controls
- 9. prototype tab: the main GUI
- 10. GUI Designer tab: opens the designer for editing; you must have GUI controls declared first

# Setup Preferences

Before starting projects, take some time to configure the preferences. This is where you will choose your C++ compiler and set your default directories. Choose View->Preferences to get the interface.

In the preferences you need to:

- Choose your default folders for projects, WAV files and default WAV file. You can use whatever directory for your project folder, and you can also open projects from any other folder at any time; the default is simply for conveniently grouping your projects together. You can also set the default folders for porting your projects to AU and VST.
- Choose a Visual C++ compiler.
- Set the C++ options—Enable C++ Control/Switching should be left on all but for the most advanced users. C++ Control/Switching allows RackAFX to control Visual Studio, save files, launch the debugger, etc.
- Set the edit options when entering information in the GUI slider/dialog boxes.

Notice the last checkbox in area (3) that automatically names your object with a “C” to match the Hungarian notation in this book explained in the Forward—see http://www.willpirkle.com/synthbook/ for an explanation of Hungarian notation.
