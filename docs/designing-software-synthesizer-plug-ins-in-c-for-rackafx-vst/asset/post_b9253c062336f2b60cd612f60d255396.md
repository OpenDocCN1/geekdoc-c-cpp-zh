We get the count from the IParameter interface packaged inside the processData struct loop through the queues. If the user has not changed any controls, there is nothing to process. The IQueue interface is used to access each queue. The getPoint() method is called, passing the value ->getPoint()-1 as the parameter for the point in question; this represents the last point in the queue. Case, the messages are updated every 10ms. The other arguments return: a sampleOffset value that we ignore for simplicity since we only need the last control value and the normalized (raw) value of the control on the range of [0..1]. In order to convert this value into meaningful information for our synth, this is done with a helper function we have written in synthfunctions called coolVSTGUIVariable(); It returns the data as a float based on the arguments. That value may be cast to int, UINT or other datatypes as a bool. In example, you can see the OCTAVE control change being processed. So, these control ID values are all identical to the you set up in the Controller's initialize() method for each you write a long switch/case statement to decode and handle each individual control, saving it to our Processor control variables. At the end of the statement, you call the update() method to set the new variables on our voice objects after count that is greater than zero. This code is extracted from the doControlEvents() function.

// loop through the parameters
int32 count = data.inputParameterChanges->getParameterCount();
for (int32 i = 0; i < count; i++)
{
    // get the message queue for ith parameter
    ParamValueQueue* queue = data.inputParameterChanges->getParameterData(i);

    if(queue)
    {
        int32 sampleoffset;
        ParamValue value;

        // queue->getPointCount()-1

        if(queue->getPoint(queue->getPointCount()-1, /* last point */

## Accessing the Audio Buffers

Remember that the audio travels through buses. In our case, we have declared one stereo output bus. The processData structure has a member named outputs that is of the AudioBuffers* type. We use this variable to write to the output buffers. Each channel has its output buffer; they are not interleaved. There are separate buffers for 32 and 64 audio samples since they are different data-types. So we have one bus (0) with 32-bit output.
