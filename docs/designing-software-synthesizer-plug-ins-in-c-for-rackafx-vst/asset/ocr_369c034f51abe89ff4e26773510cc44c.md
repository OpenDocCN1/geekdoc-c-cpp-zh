# 2.30 Implementing a VST3 Plug-in: GUI Design

You don't really need to design a custom GUI if you don't want to it is only window-dressing for your plug-in. GUI design is the subject of many other textbooks and outside the scope of this book, but most of us know the difference between a cluttered, confusing GUI and a clean one. VST is very flexible when it comes to custom GUI design and there are many options. We decided to use the GUI designer called VSTUI for a variety of plug-APIs. This is maintained by a third party and can be used to design GUIs. In the fact, the most recent version of RackAF uses VSTUI for its custom controls. Details are found at http://sourceforge.org/projects/vstui/, and if you decide to really dig into this product, join the mailing list there. VSTUI is powerful and can be used on any platform and any plug-in API including Apple's AU and Avid's AAX.

VSTUI is a C++ class that encapsulate and implement GUI control behavior. Most controls also have associated graphics resources like a bitmap, JPEG or PNG files that are used to skin them and change their look and feel. All of our resources will be PNG files. You can implement a VSTUI in two ways: programmatically or using the drag-and-drop editor. When you implement the VSTUI programmatically, you usually start out with a graph paper and you decide the locations and types of controls within an outer container (or window). You use a GUI coordinate system to codify your control's size and position in the container, identifies the resources for skinning, and you programmers actually prefer this method, and once you practice for a while, it's not intimidating.

However, we live in a drag-and-drop world and we have chosen to use that route for the VST3 plug-ins in this book.
