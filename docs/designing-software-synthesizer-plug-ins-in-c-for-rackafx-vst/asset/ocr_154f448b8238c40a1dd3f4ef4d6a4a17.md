# Inline doublesquare(double dModule, double dInc)

The frequency of the oscillator may be modulated and constantly changing. We need a function to figure out which table to use at any time. We also need a pointer to the currently selected table, even if it the sine table, because we will use pointer to call the functions. Another DC offset arises from the sum-of-sawtooth method to generate square waves with PWM; as the tables become more and more sparse, they deviate more and more from a true ramp slope even when using the Lanczos sigma smoothing. This necessitates a per-correction factor to be applied before output scaling. These factors will be stored in a nine-slot array and are found empirically.

```
// sum-of-saws method
// pretend to be SAWL type
m_uWaveForm = SAWL;

// get first sawtooth output
double dSaw1 = dasawtooth(dModule, dInc);
// phase shift on second oscillator
if(dInc > 0)
dModule += m_dPulseWidth/100.0;
dModule -= m_dPulseWidth/100.0;
```

The harmonic limits of the nine tables are calculated using the him equation. Table 5.4 lists the fundamental frequency and the upper harmonic limit (number of harmonics) for each octave.

Anything above A8 will simply use the table, as there will be only one harmonic. Each table is 512 samples in length, and you can control this with a defined constant that is at the top of the wavetable's .h file.

```
#define WT_LENGTH
```

Also, remember that one way to minimize aliasing is to force the tables to become shorter and shorter as the number of harmonics drops off(you can see that they approximately halve on each octave transition), with the last octave covered by 32 or 64 samples table. You may experiment with this approach, but you will need to keep track of the length to properly calculate the phase increment value.
