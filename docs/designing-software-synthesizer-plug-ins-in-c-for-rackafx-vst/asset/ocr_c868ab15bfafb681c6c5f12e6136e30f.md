One of the most important that COM does is that it completely separates the components and plug-in from one another
a a safe way. It does this by using the concepts of components and interfaces. A long time ago, soft was written
in a monolithic way with a set of variable declarations and a run-loop all packed inside of one executable. As the
alocations got larger, soft were meant teams of programmers could work on separate components. A special
problem with this approach involves making sure that the components fit together and communicate properly, and
most importantly that they do ultimately break the application—also known as a crash. This is where the interface
concepts come into play.

Suppose that for some reason, you are determined to pull a big-Chevy V8 engine in your Honda automobile. You will
rip out the Honda motor and drag in the BV. The V8 needs to be connected to a Chevy transmission. The
Honda transmission mounting plate is the right size and the housing are all metric! What you need is an
interface that lets you connect to a robust and safe way. With this Chevy-interface in place, the Honda
transmission doesn't know it's connected to a Chevy—as far it is concerned, it's connected to a Honda engine.
Likewise, the BV thinks it's connected to a Chevy transmission. Interfaces are portable, so you could take the Chevy-
interface and connect it to the side of your house so that now a Chevy motor can be attached to it one side
 and Honda transmission on the other. With the interface established, the two do not need to know about each other,
or do they care about each other's implementation details. They also don't care about the language used to design
e other.

deplementation of the plug and vice-versa. And, as long as the plug implements the required set of
functions, it is guaranteed to be a proper plug-in and loaded into the client's address space. If you've used
RackAFX to make a VST2/3 compatible DLL, then you have already seen this. The single RackAFXL file works as
 both RackAFX plug-in, VST2 plug-in, and a VST3 plug-in. This is because it implements three sets of interfaces—it
an "dock" to either platform.
