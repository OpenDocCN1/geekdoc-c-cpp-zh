# Sharing the Global Matrix

You saw how the monophonic NanoSynth shared its one and only matrix in the plug-in so that the plug-in could make changes when MIDI events occurred or when the user wanted to reconfigure it. With polyphony, each NanoSynth will need its own modulation matrix because the voice sources and destinations are different; each voice needs its own source and destination array. However, the modulation matrix core is the same set for all voices. When the user wants to reconfigure the matrix, we don't want to update each voice's matrix.

So, the voice modulation needs to share the same core as the plug-in—in other words, there is one and only core. One way of handling this is with a singleton object, which in theory can be constructed once and is useful as a shared resource. In IOS programming, it is a common paradigm. However, a singleton actually increases the complexity somewhat, so we are going to
