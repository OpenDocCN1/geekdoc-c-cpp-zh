The first calls will your GetPropertyInfo() function to see what extra properties you support. We are going to respond by replying noErr for the following property:

```
kAudioUnitProperty_CocoaUI
```

Since we support a Cocoa GUI we need to answer noErr to your query.

After GetPropertyInfo(), the host will call GetProperty() for the items we replied with noErr. In this function you must reply with information the host can retrieve your GUI and save/maintain it. It is critical to implement this function perfectly or your GUI will not appear, even if your code compiles fine.

# Functions to Handle MIDI Events:

Like RackAF's Plugin base class, AUInstrumentBase is set up to automatically call a set of MIDI message for the most common messages. We will implement each of these, and we will be interested in all of them. These are all overrides of AUInstrumentBase or one of its base classes, AUMIDIBase.

```
virtual OSStatus
StartNote()
```

```
virtual OSStatus
StopNote()
```

```
virtual OSStatus
HandlePitchWheel()
```

```
virtual OSStatus
HandleControlChange()
```

```
OSStatus
HandleMidiEvent()
```

The first four are reasonably self-explanatory; these handle the MIDI note on, note off, pitch bend and continuous controller change. The fifth function is where you handle anything else. We will use this for handling program change and aftertouch messages.
