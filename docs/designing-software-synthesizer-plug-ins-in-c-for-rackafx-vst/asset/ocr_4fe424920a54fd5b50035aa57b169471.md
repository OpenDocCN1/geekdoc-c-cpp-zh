# MIDI Note On and Off

These are the two most important MIDI messages we will deal with. We will get into the exact details of these methods in Chapter 8; however, you need to know how RackAFX simplifies some of the work for you, depending on the MIDI message. For the note on messages, RackAFX converts the MIDI byte data into manageable UINT types. The three arguments are:

+   * UINT uChannel: 0–15 for 16 total channels
* UINT uMIDINote: the MIDI note number 0->127 for the note event
* UINT uMIDIVelocity: the note ON velocity 0->127 for the note event

The first step is to check midiNote and bail out if it is not a channel we are playing or supporting. More details will show in the next chapter when we look more closely at the MIDI messages. After, we do the necessary event stuff.

```
bool __stdcall CMiniSynth::midiNoteOn(UINT uChannel, UINT uMIDINote, UINT uVelocity)
```

For note misses, RackAFX converts the MIDI byte data into more manageable UINT types. The three arguments are:

+   * UINT uChannel: 0–15 for 16 total channels
* UINT uMIDINote: the MIDI note number 0->127 for the note event
* UINT uMIDIVelocity: the note offvelocity 0->127 for the note event (most MIDI keyboards do not transmit this value)
* bool bAllNotesOff: a MIDI panic message to turn every note off

# MIDI Mod Wheel

The mod wheel is the standard on most MIDI keyboard controllers. It is typically managed separately from the continuous controller (CC) messages unlike VST3 and AU, RackAFX decodes and sends this message separately simply because it is common on such products. The mod wheel value is 0 to 127. As with note on and off, RackAFX converts the bytes into UINTs for you.

+   * UINT uChannel: 0–15 for 16 total channels
* UINT uModValue: the wheel position from 0->127
