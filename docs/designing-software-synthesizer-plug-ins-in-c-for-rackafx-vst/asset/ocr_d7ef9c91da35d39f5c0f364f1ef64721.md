# doVoice()

This is the most important function of all since it implements the rendering, and it is nearly identical to NanoSynth's rendering code. The modulation layers are the same, the only difference is in the wiring of the audio engine. Notice the call to the base class and the scale-before-summing on the pitched oscillators in the audio engine. The articulation block is nearly identical to NanoSynth because the programming is done in the modulation matrix. The only difference is the call to voice object's update after modulation Layer 1, but before updating the rest of the components.

Notice how the MiniSynth object does most of the work that had previously been done in the plug-in object. Next, we will deal with polyphony and setup a scheme that will make the code nearly identical on all three of our platforms.

# 9.6 Polyphony Part Two

NanoSynth used a simple and easy to fool voice stealing heuristic on just two voices that were implemented structures. MiniSynth uses a different heuristics and the C++ MiniSynth object instead. To set up the plug-ins for polyphony, we will switch to storing an array of voice object pointers. Voice objects are created dynamically at startup and destroyed during down. There are three functions that are the same for all synths in one API that allows searching the array for voices certain criteria. MiniSynth uses a voice stealing heuristic called "the oldest note," which means that it needs to keep track of the order of the note events. We need a timestamp to know which voice is playing the oldest note. The other heuristics listed in Chapter 8 provide all information we have in the form of note number or velocity.
