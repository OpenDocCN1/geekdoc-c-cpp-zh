For our synths, we only care about the parameter changes, so we set the event type using a constant and call AUEventListenerAddEventType to register it.

```
void addParamEventListener(AUEventListenerRef listener,
    void* refCon, AudioUnitEvent *inevent)
```

```
// set the event type to kAudioUnitEvent_ParameterValueChange
inevent->mEventType = kAudioUnitEvent_ParameterValueChange;
```

```
// register it
verify_noerr(AUEventListenerAddEventType(listener, refCon,
inevent));

The next step is to create the

AUEventListener passes it a selector to a callback function that you implement. Then you tell the AUEventListener about all your parameters, and it sets up a private Listener for each. You also define a private Listener function that responds by telling the controls to update their positions. The Event Listener callback is named AUEventListenerDispatcher but you may name it whatever you wish. Look at the function call that creates the AUEventListener:

The two arguments you need to understand are the first one that names the callback method and the second one that is a pointer to your self. This pointer will be passed to the callback function cloaked as a void*, which is a standard trick in callback functions since the function stands alone, outside any other object definition. If this is new to you, see the website for more information about callbacks. The callback function is declared at the top of the View.cpp file, outside the object implementation:

```
verify_noerr(AUEventListenerCreate(AUEventListenerDispatcher,
self,
CFRunLoopGetCurrent(),
CFRunLoopDefaultMode, 0.05, 0.05,
&AUEventListener));
