## 0xC—Program Change

The Program Change message transmits a single value between 0 and 127, which selects a patch numerically 1 to 128 on a synth. We will trap and identify this message in our synths but not use it until you forge ahead and build your own multi-program synth.

## 0xD—Channel Aftertouch

Channel Aftertouch is similar to Aftertouch but is not transmitted separately for each note. Instead, it is transmitted globally and to all notes on a particular channel. Since it is a less expensive option, many more controllers implement it instead of Polyphonic Key Pressure.

## 0xE—Pitch Bend

The Pitch Bend Message is a special kind of Voice Message because of the way it is decoded. It is usually generated with a joystick or wheel. Pitch bend decoded uses two data bytes to encode a bipolar value with 0 in the center (no pitch bend). Positive pitch bend values indicate an increase in pitch (sharp) while negative values indicate a drop in pitch (flat). Most synthesizers feature a pitch bend range of at least one octave to +/- 4 octaves. If only one data byte was used to transmit the value, your ear would hear the bend as a series of discrete bumps in pitch rather than smooth and continuous change. Smooth transitions are accomplished using two data bytes, each contributing 7 bits to a 14-bit value resulting in 16,384 values—enough to produce smooth bends.

MIDI 1.0 specifies pitch bend as a bipolar range of values with:

- 0x00 00 = most negative (flat) pitch bend
- 0x00 64 = center (0)
- 0x7F 7F = most positive (sharp) pitch bend

For calculations it is easier to convert this into a bipolar value, so that 0 applies no pitch change. The 16,384 values are then spread across a bipolar range of -8192 to +8191 or -1.0 to +0.999.

## 3.4 Project: NanoSynth

NanoSynth is going to be the basis for the MIDI portion of every other synth, as well as act as a testbed for your C++ objects. You will build NanoSynth over the next five chapters. In this chapter you will learn how your platform deals with MIDI messages and configure the fundamental messaging system. There are no controls to deal with, as this is a simple project that you should get running quickly. You will need a MIDI controller to provide as many of the controller messages in Section 3.2 as possible. You will trap MIDI events and log them to an output window to make a basic MIDI monitor. In the next chapter, you will use the note on off events to turn your oscillators on and for testing. This plug-in won't make any noise, but it will ease you into coding on the platform you choose. Take a look at Table 3.3 from the last chapter showing the differences in the MIDI function implementation for each API. In this project, we'll be working in those functions.

### Common Files

All platforms will use some common functions that are identical and included in every synth:

- synthfunctions.h—a collection of constants, structures and functions used widely in every project
- pluginconstants.h—originally a RackAFX file, this includes more constants, functions, and objects such as GUI controls.
- pluginobjects.cpp—the implementation file for objects declared in pluginconstants.h

VST and AU plug-ins need one additional file. Note that this file is slightly different for each synth since it is based on the synth's properties.
- synthparameters.h—enumerations and defines for zero-based parameter index values, as well as the parameter limits (min, max, default) that match your GUI.
