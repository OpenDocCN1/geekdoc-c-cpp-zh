You are modifying the Controller when you add, remove or change any of the user GUI underpinnings. There is a simple four step process for setting up the controls for use; as long as you follow this sequence properly, your GUI should just work fine.

The Controller object is defining your plug-in's GUI controls, and our custom GUI depends on this as well. Objects called Parameters represent the GUI controls, and the Controller stores a set of these Parameter objects inside a Container. You can access the center and Parameters out of it if needed. The Controller sends and receives values from the GUI by a zero-based index. When the user moves a control, the GUI sends a normalized value from 0.0 to 1.0 a called value, and an index or ID a a tag, which identifies the control. When the Controller wants to change the position of the controls during start-up or automation, it sends indexed, normalized values out to the GUI. So it is important to understand that each Parameter (GUI control) has an index. Controls may share the same index in case they move together, but we will not have any shared controls-each of our index values must be unique.

On the Processor side, each GUI will be utilized to control an underlying variable. That variable will change when the user moves a control, and the audio rendering will be modified accordingly. All of the synth projects in this book will use these types of variables:

- double
- int
- enumerated UINT aka enum

Controls that connect to a double variable will ultimately generate continuous double floating point values. The int controls will generate integer-based values. The enumerated UINT controls will generate unsigned integer values (UInts) that will map to strings in an enumerated list. In VST3 you don't have to implement the enumerations like you do in RackAFX, you will be responsible for knowing which strings map to values.

The fundamental variable types are float, int and enumerated UINT. The Octave and Octave controls generally generate numerical values that the user uses in the GUI, and they have minimum or Lo Limit, maximum or Hi Limit and default (Def) values. The Fc (Filter cutoff) control has the "volt/octave" which means that this control is logarithmic. The Filter control displays strings that define the current value. An unsigned integer (UINT) keeps track of the current setting. The Enum String gives you the comma-separated values that will map to the UINT. In example is:

- LPF: 0
- HPF: 1
- BPF: 2

Each control is called a "parameter," and there is a Parameter object that handles the details. The controls are referenced with an index. It is up to you to keep track and maintain this system. If you change the index values, your controls might not map correctly. The easiest way to keep track of the index values is with enumeration. The VST3 limits, default values, and enumerations are all contained in the file SynthParamLimits.h, which is different for each synth. There are three fundamental types of parameter objects we will use plus container to hold them.

### RangeParameter

The RangeParameter represents a continuous control that has a minimum, maximum and default value. An easy example is volume control in dB where the minimum is -96, maximum is +24 and default is 0. The control moves smoothly across this range.

### StringListParameter

The StringListParameter defines a control with a fixed set of states defined by strings. An example might be "Filter Type" control where the user chooses from list of strings like LPF, HPF, etc. We will also use this as on/off control by limiting the strings to ON and OFF.

### LogScaleParameter

The LogScaleParameter is similar to the RangeParameter but the control moves logarithmically. We will use this exclusively for filter cutoff control, which we want to move in a logarithmic manner.

### Parameter Container

The Controller class declares a Container to hold all your controls. This is essentially a linked list. You declare your Parameters and add them to the Container and evaluate the control's current value if needed. The Container's name is parameters, and it is declared in vstedcontainer.h

ParameterContainer parameters;`

### Normalized and Plain Parameters

An important concept in VST is GUI controls transmit parameters. In my previous book (and in earlier versions of VST), these are called "raw" values. Sometimes a parameter may have a range of 0.0 to 1.0, but most of the time the controls will not. For example the filter cutoff control for all filters will have a range of 80.0 Hz to 18 kHz—on the UI you will see these values, but when the user moves a control, the GUI transmits the normalized or raw value. It is up to you to write the code to figure out what mapped value will be. VST3 calls the mapped value "plain" value, whereas in VST2 and RackFX it is called the "coded" value, and the function that converts normalized/raw value to the plain/coded value is the "cooking function." We have already supplied you with functions that will cook and un-cook your variables in synthfunctions.h; you supply the minimum, maximum and raw/cooked values. In all our synth projects, the Container will handle the job of making the UI have the properly cooked values as the user moves the controls. It does this by making a linear (or logarithmic if you use LogScaleParameter) mapping to the normalized value. This poses a slight issue in the case of control automation where the user wants to recall his control movements in real-time, along with the song information. If your control does not map in a linear or logarithmic way, you will need to provide some translation code that converts from plain to normalized and back. We won't need this in our projects since we will provide all the functions and keep track of your own variables and their raw and cooked mappings.

In order to implement your Controller object, follow these steps:

- every control will have an index so lay out as an enumeration in the SynthParamLimits.h file
- decide on a UI and establish min, max and default values for each control
- write the code that declares the UI parameters in the VSynthController.cpp file and add them to the parameters container; this will also setup the default UI own- write the code that performs the read-side serialization
- implement the MIDI Controller Mapping (the controller exposes IMIDapping)
