Of these folders, you will spend the majority of time in AU Source. Its files include:

- AUStructures.h and AUSynthVersion.h: helper to struct definitions and version information

- AUSynth_Prefix.pch: the header that you can safely ignore

In the CocoaUI group, you can see Objective-C files (.h and .m) for the GUI as well as custom controls prefixed with AU: objects are all named according to the synth project, directly with:

- Factory: .NIB File Owner that loads the View
- View: custom view
- RotaryKnob: custom rotary knob control
- EditBox: custom edit control
- OptionGroup: custom option menu control (aka pop up button)
- PopUpToggleButton: custom pop up button

The reason these files are named after the synth project is that Cocoa has a flat namespace and each object must have a unique name. For example, if all synths use RotaryKnob as the name of these controls, and you customized the knob in project to look different from others, the names would collide and you would lose the uniqueness of the object; for example, if you load the plugin with the unique knob first, subsequent plugins will load the same knob even though they were compiled with different resources. RULE: rename all objects in a potentially unique way—Apple recommends using your initials as the first letters of any object.

## 2.36 The Info.plist File

The Info.plist file contains some items that are critical in declaring your plugin to the client. You must ensure that this file is correct, or your plugin may not appear in the client. The Info.plist file contains information about your .component that the client needs to properly recognize and load your GUI.

Your plugin is ultimately and uniquely identified by two four-character values. One four-character value represents your company name (“WILL” for mine). The other represents MiniSynth “MS0x” where “x” is a revision number (currently it is three, so the code is “MS03”).

The name that will be displayed in a client is based on a string setting of the ID; so for example “Will Pirkle MiniSynth” would cause Logic to create a new AU Menu Item named “Will Pirkle” and a new sub-item named “MiniSynth”, whereas Ableton would create a Folder named “Will Pirkle” with a content item “MiniSynth.”

AU plugins are differentiated by a special character code: music synthesizers use the code “aumu”.

Your AU plugin is part of a bundle and has a bundle identifier. This identifier is needed to access Cocoa GUI finding your folder (we do this when sampling WAV files that must be in specific locations relative to .components). Each synth has its own bundle identifier. The projects are set up with the default identifier: developer.audiounit.yourname.yourname

So for the MiniSynth, we would specify our identifier as:

developer.audiounit.willpikle.MiniSynth

Open the Info.plist file in the MiniSynth’s Resources group. You will need to modify this file each time you make a new synth plugin. First, open the Dictionary:

- Type: synth
- Subtype: aumu
- Manufacturer: WILL
- Version: MS03
- Name: Will Pirkle MiniSynth
- Description: A custom synthesizer by Will Pirkle

The Type and Subtype are critical for the host to recognize the plugin. The Manufacturer and Version are for identification. The Name and Description are what the user sees in the UI.

The Info.plist file also contains the dictionary for the GUI.

The Volume and Octave controls ultimately generate numerical values that the user sees on the GUI, and they have minimum or Lo Limit, maximum or Hi Limit and default (Def) values. The control may also have Units (" or empty string). The Fc (Filter Cutoff) control has the note "volt/octave" which means this control is logarithmic.

The Filter control displays strings that define the current value. An unsigned integer (UINT) keeps track of the current setting. The enum String column gives you the comma-separated values that will map to the UINT variable. In this example is:

- LPF: 0
- HPF: 1
