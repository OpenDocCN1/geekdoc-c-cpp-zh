# 8.20 Global polyphony Parameterization

Handling polyphony by replicating structures (or objects) is fairly straightforward; you saw the use of the for() loop to iterate through the voices and deal with them. We have a shared modulation matrix core, so when the user changes or enables/disabling routes, we only need to change the matrix core once. But if you look at the update() function for the Poly NanoSynth plug-in, you will see wasted code. We are looping through the objects and repeatedly setting the same variable once. And, we are setting variables on objects that might not even be active. Imagine a synth with 16 voices of polyphony and 40-50 GUI controls, which will have in the rest of the projects.
