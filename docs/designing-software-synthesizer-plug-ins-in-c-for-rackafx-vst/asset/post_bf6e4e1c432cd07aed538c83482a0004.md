## prepareForPlay()

This is the one-time-initialization function for the object. The plug-in calls it during its own one-time-initialization function and passes the current sample rate. This function passes that sample rate to the member objects and then calls the init() function to request the allocation of two seconds worth of buffers.

```
// --- one time init
void CStereoDelayFX::prepareForPlay(double sampleRate) {
    // --- set sample rate first
    m_LeftDelay.setSampleRate((int)dSampleRate);
    m_RightDelay.setSampleRate((int)dSampleRate);

    // --- initialize to 2 sec max delay
    m_LeftDelay.init(2.0*sampleRate);
    m_RightDelay.init(2.0*sampleRate);

    reset();

## update()

update() function takes the delay ratio and calculates the individual delay times on the left and right delay lines using the logic at the beginning of the section. For negative ratios, notice the negation operation, which is the equivalent of calling an absolute value function here.

```
void CStereoDelayFX::update()
{
    if(m_uMode == tap1 || m_uMode == tap2)
    {
        // if (-) bias to left
        // if (+) bias to right
        // if 0.0 ratio is 1:1
        if(m_dDelayRatio < 0)
        {
            // -- note negation of ratio!
            m_dTap2LDelayTime_msec = -m_dDelayRatio*m_dDelayTime_mSec;
            m_dTap2RDelayTime_msec = (1.0 + m_dDelayRatio)*m_dDelayTime_msec;
        } else if (m_dDelayRatio > 0)
        {
            m_dTap2LDelayTime_msec = (1.0 - m_dDelayRatio)*m_dDelayTime_msec;
            m_dTap2RDelayTime_msec = m_dDelayRatio*m_dDelayTime_msec;
        } else
        {
            m_dTap2LDelayTime_msec = 0.0;
            m_dTap2RDelayTime_msec = 0.0;
        }

        // normal times
        m_LeftDelay.setDelay(m_dDelayTime_mSec);
        m_RightDelay.setDelay(m_dDelayTime_mSec);

        return;
    } else // else
    m_dTap2LDelayTime_msec = 0.0;
    m_dTap2RDelayTime_msec = 0.0;

// --- set the delay times based on the control
// if (-) bias to left
// if (+) bias to right
// if 0.0 ratio is 1:1
if(m_dDelayRatio < 0)
{
    // --- note negation of ratio!
    m_LeftDelay.setDelay(-m_dDelayRatio*m_dDelayTime_mSec);
    m_RightDelay.setDelay(m_dDelayTime_mSec);
} else if (m_dDelayRatio > 0)
{
    m_LeftDelay.setDelay(m_dDelayTime_mSec);
    m_RightDelay.setDelay(m_dDelayRatio*m_dDelayTime_mSec);
} else
{
    m_LeftDelay.setDelay(m_dDelayTime_mSec);
    m_RightDelay.setDelay(m_dDelayTime_mSec);
}
```

## processAudio()

This is the main function that implements the stereo delay. It follows the basic logic:

- get the left and right delay outputs
- form the input to the delay; this is based on the mode of operation
- call processAudio() functions to process the delay inputs
- mix the dry inputs with the wet outputs according to user control

```cpp
bool CStereoFX::processAudio(double* pInputL, double* pInputR, double* pOutputL, double* pOutputR)
{
    // --- do the delays
    // common components:
    double dLeftOut = m_LeftDelay.readDelay();
    double dRightOut = m_RightDelay.readDelay();

    // --- inputs to delays: default is norm
    double dLeftIn = *pInputL + dLeftOut*(m_dFeedback_Pct/100.0);
    double dRightIn = *pInputR + dRightOut*(m_dFeedback_Pct/100.0);

    double dLeftTap2out = 0.0;
    double dRightTap2out = 0.0;

    // --- do the other modes:
    // NOTE: cross mode sounds identical to ping-pong if the input is mono (same signal to both)
    case cross:
        dLeftTap2out = m_LeftDelay.readDelayAt(m_dTap2LDelayTime_mSec);
        dRightTap2out = m_RightDelay.readDelayAt(m_dTap2RDelayTime_mSec);
        break;

    // Left Input -> Left Delay; Left Feedback -> Right Delay
    // Right Input -> Right Delay; Right Feedback -> Left Delay
    case ping:
        dLeftTap2out = m_LeftDelay.readDelayAt(m_dTap2LDelayTime_mSec);
        dRightTap2out = m_RightDelay.readDelayAt(m_dTap2RDelayTime_mSec);
        dLeftIn = *pInputL + (0.5*dLeftOut + 0.5*dLeftTap2out)*(m_dFeedback_Pct/100.0);
        dRightIn = *pInputR + (0.5*dRightOut + 0.5*dRightTap2out)*(m_dFeedback_Pct/100.0);
        break;

    case pong:
        // Left Input -> Right Delay; Left Feedback -> Right Delay
        // Right Input -> Left Delay; Right Feedback -> Left Delay
        dLeftIn = *pInputR + dRightOut*(m_dFeedback_Pct/100.0);
        dRightIn = *pInputL + dLeftOut*(m_dFeedback_Pct/100.0);
        break;
}

    // --- intermediate variables
    double dLeftOut = 0.0;
    double dRightOut = 0.0;

    // --- do delay lines
    m_LeftDelay.processAudio(&dLeftIn, &dLeftOut);
    m_RightDelay.processAudio(&dRightIn, &dRightOut);

    // --- form outputs
    *pOutputL = *pInputL*(1.0 - m_dWetMix) + dLeftOut*m_dWetMix;
    *pOutputR = *pInputR*(1.0 - m_dWetMix) + dRightOut*m_dWetMix;

```
    // --- return All
    return true;
```

Using the delay object is refreshing. Of course for interfacing, but after that there are only a few functions called for operation. This delay object is not a member of voice—as master effect, it lies outside the stack of voices. For ease of implementation, we are going to make the delay object member of the plug-in. The plug-in object will form the current sample output then it processes through the delay plug-in before writing to its output locations. Remember that this happens on a per-sample basis and not a per-voiceradius basis. Figure 13.11 shows the MiniSynth with the delay added after the DCA. We are not adding the modulation routines but if desired a Chapter Challenge. Remember the plug-in shares its modulation core with the voices and that it receives the MIDI control inputs, so we can add them to the FX section if desired.
