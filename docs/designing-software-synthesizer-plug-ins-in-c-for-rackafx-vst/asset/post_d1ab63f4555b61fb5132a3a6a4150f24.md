The note on logic is based on what we use in NanoSynth, plus the portamento. The logic also handles voice stealing. Figure 9.8 shows the flowchart. A note is considered to be available if no note is playing and note is pending. In this case you set the event flag, calculate start pitch (if using portamento), and start up the oscillators, EGs and LFOs. If the voice is stolen, you first store all the pending note information and set the pending flag. An issue arises if the voice being stolen is currently in the middle of a portamento glide. In this case, the increment value is calculated from the semitones between the current oscillator pitch and the target pitch. Lastly, you shut down the EGs for the steal stage. # doVoice() Logic

The CVoice class handles the low level rendering operations common to all synths. You will always override this in your derived synth objects, and you will always call this function first; if it returns false, there is no note to render, which can happen if the note has just ended. Note that it only returns true if a note is currently playing or stole a voice. Compare the code to the flowchart to make sure you understand the implementation. Notice the way portamento works. If portamento is enabled when a note is transferred, the portamento start pitch is the current portamento value. The portamento event ends and the pitch has reached the target. If not, it calculates the new pitch for the current sample. Your derived class will add voice-specific parameters.

# 9.4 MiniSynth Specifications

The MiniSynth derived class won't make sense until you understand the deeper specifications for MiniSynth. Specifically, we need to address the voice modes of MiniSynth. You will remember from the block diagram in Figure 9.1 there are four oscillators. One oscillator always plays the sub-octave (OSC3) while another is a noise oscillator (OSC4). However, there are multiple waveform modes of operation. This idea was taken from Virtual Keys; it cleverly uses UI controls by presenting the user with a preset of waveform combinations. The MiniSynth's voice modes also determine the LFO modulation that is applied to the oscillators.

Sawtooth and triangle waves have their pitch modulated. Square waves have their width modulated. For voice modes that are combinations of square and others, both pitch and pulse-width are modulated.

These combinations yield an interesting and wide palette. Saw2Sqr is quite interesting; with the square wave at 50% duty cycle, the sub-oscillator is cancelled. Moving the pulse width in either direction causes the pulse-width to produce interesting effects as the sub-octave component mixes in.

Detuning creates a thicker sound. Table 9.3 shows the MiniSynth voice modes and abbreviations in the enumeration. Figure 9.13 shows the detailed connection diagram; compare with NanoSynth.

# Table 9.3: MiniSynth Voice Modes are combinations of oscillators and modulations.

| Voice Mode | Details | LFO -> Mod |
| :--- | :--- | :--- |
| Saw | Three sawtooth oscillators | pitch |
| Sqr3 | Three square wave oscillators | pulse width |
| Saw2Sqr | Two sawtooth and one square wave oscillator | pitch and pulse width |
| Tri2Saw | Two triangle and one sawtooth oscillator | pitch |
| Tri2Sqr | Two triangle and one square wave oscillator | pitch and pulse width |
