Even with all differences, the AU API follows the same pattern as discussed in the beginning of the chapter and the same paradigm that RackAFX and VST3 follow—in this respect it is just as ordinary as the others. The plug-ins are derived from a special class. You override and implement the necessary functions to handle GUI changes and audio processing/rendering. If you make a custom GUI, you need to add the code for that well. If you have the basic MacOS and Objective-C skills, AU is even and more straightforward than VST3. For synthesizer plug-ins, AU resembles RackAFX in how it handles MIDI messages, going from RackAFX to AU is actually conceptually easier than going to VST3.

In order to develop the plug-ins in this book, you will need to:

+   - a Mac with MacOS 10.7 or greater
- the Xcode version that is best/most recent for your OS
- the AU project files from the website
- an AU client like Logic or Ableton Live

There is no SDK per se. The support files you need are usually included with Xcode, or as an additional download. As of writing, the latest update to these files was done in November 2013, and you can get the latest updates at developer.apple.com by searching for the following string: "Audio Unit Examples (AudioUnit, Generator, Instrument, and Offline.\ In addition to the support files, you will find the latest sample code. These files are all contained in a set of folders in a specific hierarchy. If you want to play with the Apple sample code, it will be accessing files in other folders in that hierarchy, like VST3.

However, unlike VST3, the additional files do not reference each other in specific locations. So, to make the projects easier to manage and stand-alone like RackAFX, we created self-contained project folders that have all the necessary files included. If you download the sample projects, you won't really need the stuff from Apple, unless they make an update to the code. And, each of your synth projects is independent of the others. With the projects contained, this means you can put them in any wish, so there are no restrictions you have with VST3.

An plug-in is also a dynamically linked library. The file extension is .component in MacOS, so you will ultimately building a component project. The Cocoa GUI is packaged in a resource file with the extension .bundle. The .component file must be placed in the:

~Library/Audio/Plug-Ins/Components
nThe bundle file must be placed in a Resources folder relative to the project. To facilitate this, we set up Build Phases in Xcode to copy the two files to their destinations.

I/O buses may be mono or multi-channel. For a synth plug-in, there is no input bus and one output bus. AU plug-ins can also accept MIDI messages either as synth plug-ins or as MIDI controlled effects.

In Figure 2.43 you can see the scene of operation between the AU plug-in and the host. The host initializes the plug-in and queries it for special behaviors. MIDI is routed through the host to the plug-in via message handlers. Audio is rendered into buffers that are shipped out to the Core Audio subsystem. The Cocoa view maintains the GUI.
