## readSampleBuffer()

This function reads and interpolates samples from a wave data buffer. It handles both mono and stereo file buffers and uses the same technique you saw in the CWaveTable object. It is nearly identical in core operation. For mono, it writes the left channel to the right output. You will see that this function mainly deals with indexing and bookkeeping and treats the buffer like a wave table.

## doOscillate()

The render function makes use of the helper function above, which handles the details of reading and interpolating the audio data. The doOscillate() function primarily handles wrapping and looping of the read index value. It uses the start and end loop values for the sustain loop mode. For one-shot mode, the once samples through a single time, the read index is set to -1; this is the flag to exit the function and return the 0.0 samples we cleared. In sustain mode, loop mode is treated like one-shot.

## 10.7 Audio File Location

Our sample-based synths require either single samples or folders, and the plugin needs to know where these files are located. Some options are hardcoding the location, using an installer to write the location in the registry, or using some other method of letting the DLL know the file location. An easy way to solve this problem without the need of registering the files is to place the files in the same directory as the DLL (or component) or in a sub-directory of this folder. This reason is in both Windows and MacOS, you can query the OS for the location of the application using it. All sample-based synths will use the DLL or component factor to store samples. The samples themselves be in sub-directories called /Samples and /MultiSamples. Finding the DLL/Component factor is so, open the software and use Folders to place:

- RackAFX;
- VST3;
- AU: ~Library/Audio/Plug-Ins/Components
