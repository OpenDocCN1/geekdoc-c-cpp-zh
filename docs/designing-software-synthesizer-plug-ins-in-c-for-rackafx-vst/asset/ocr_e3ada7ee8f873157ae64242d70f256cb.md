class ASynth : public AUInstrumentBase
Next, the functions for calculating the attack and decay times. Optionally, you may alter the function that calculates the release time in a similar manner using the decay time scalar. All you need to do is to scale the attack or decay time in milliseconds by the scalar value.

Back in the .h file, the update() function to rescale the attack and decay times. The calculation of the attack and decay time is intensive, however, so we only need to call this once the note is struck. Notice how the attack and decay time are handled as inversions—this is a 0 in the destination array named "no modification," and we need to invert it for two rows. The code to check for the sustain pedal and call the sustain override as needed.

Take a minute to look at the calculation functions so you can see how the times are scaled. You can see that when the scalar value is 0, the attack or decay time is 0 (fastest) and when the value is 1.0, the attack or decay time is the normal value in the GUI. Here you could alter this scaling if desired.

The news is that the modulation matrix makes it easy to add these new routines. Once again, there are two steps: add the new modMatrixRows (there are six new row pairs in Table 8.4, so there will be six corresponding rows in the matrix) and then set up the objects with new source and destination index values. When you add new rows to the matrix, the order doesn't really matter. Notice also that the velocity to attack and note number to decay mappings are disabled by default.
