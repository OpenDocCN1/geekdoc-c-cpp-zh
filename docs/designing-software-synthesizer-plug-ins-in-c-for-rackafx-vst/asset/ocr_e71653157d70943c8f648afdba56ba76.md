have become accustomed to naming your C++ classes with a capital "C", for example CSyn or CRever. The capital "I" indicates that a C object is a COM interface. Your VST Processor object utterly inherits from AudioProcessor, and your Controller object inherits from IEditController. Since all objects must expose a common interface that the client will use to connect to others, what should that interface be named? Microsoft chooses to call it IUknown. Steinberg's version is called Funknown. Funky, either way, the name of an "unknown" interface is something that has turned off more than a few programmers from exploring COM; it seems confusing. We do not have a better name for it.

Let's wrap this section on COM by learning how the creation function knows what kind of COM object to instantiate. This is done by uniquely identifying each COM object. Your Processor needs one and your Controller COM objects. When the client creates a VST plug-in, it will use one of these unique identifiers to specify which plugin it wants. It is important that every VST plug-component has a unique identifier. Two developers might accidentally name their plugin the same way—GoldenFlanger. As long as you have unique identifiers, the VST host can instantiate both GoldenFlangers without conflicts. If you create a new VST plug-in that has the same identifier as one is already loaded in the client, the client will ignore its existence or return the object when asked.

Microsoft calls these Globally Identifiers or GUIDs (pronounced "good-idz”). Steinberg's version names them FUIDs—“foo-idz”. A FUID or GUID is a 128-bit value. The easiest way to generate one is with Microsoft's COM generator, which is called uuidgen.exe. You can find it in your Visual Studio project folder. Launch this executable, and a window will pop up with a button that says "GUID”—that button and you hit the button to copy it to the clipboard. Then, you can paste it into your VST code with a bit of formatting manual. The uuidgen program generates a GUID from a unique timestamp based on the number of 100 nanosecond intervals that has elapsed since midnight of October 1582. This guarantees that no duplicate GUIDs will be generated until 3400A.D. Microsoft calls GUIDs here:

```
GUID({846EB93F-3247-4B8F-A901-10E8ED4ACC34})
```

Steinberg FUIDs are declared like this (here is the FUID for a Controller object):

```
FUID Controller::cid(0xB561D747, 0xBA004597, 0xA3BF911A, 0x5DA2AFA4)
```

Both Microsoft and Steinberg's IDs are 128-bit, so you just have to format the numbers. For example, to use the above Microsoft GUID as a VST FUID for this Controller you would duplicate the digits as follows, removing the dashes and consolidating:

```
GUID({846EB93F-3247-4B8F-A901-10E8ED4ACC34})
```

becomes:

```
FUID Controller::cid(0x846EB93F, 0x32474B8F, 0xA90110E8, 0xED4ACC34)
```
