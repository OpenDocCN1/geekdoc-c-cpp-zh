To to set up this kind of continuous control, right click inside one of the bounding boxes for a slider control. The bounding box is a thin grey frame around each slider as shown in Figure 2.2. Right-starting the Slider Designer, a simple way to use it by filling in to create the control. As an example, right-click on the first slider in the upper left. It produces the form you have shown in Figure 2.9.

You need to fill the Slider Properties with the proper values. You will notice that uControlID is 0 for this slider. This is the ID that will link the slider to a variable. You cannot edit this cell. Start with the Control Name and "Volume" (no quotes). Hit advance to the next cell, then set the Units to "dB". The next cell is one of the most important—it is the data type for the variable that will be linked; with choices from a drop-down list. You can select the data type with the mouse, or you just type the first letter (e.g. "d" for double) while the box is highlighted. Compare this figure with the first row of Table 2.6 and you can see how to translate table rows into control configurations. You can ignore the MIDI stuff now—see my website on how to connect MIDI controllers to any of the GUI components to use this option. However, on the left is an important set of

+   * Linear Slider
* Log Slider
* One/octave Slider

The linear and log (arithmetic) sliders move with these offsets, and you could use a log control for volume if needed. However, for some synth frequency controls as the cutsofffrequency for a filter, you want to choose the volt/octave option. This will make the control in a 2N fashion (i.e. in octaves), which is how synth work when using this taper (NOTE: in VST3/AU this volt/octave is called "Logarithmic Scale"). If you realize a mistake or left something out, just right-click in the slider box and fix the problem. You can also remove the slider by clicking the button on the Properties Window, and you can copy the settings of another slider with the Copy Existing Slider Control drop-down list.

As you add, edit or remove controls from the main UI, you will notice that RackAFX will flash to the compiler and as it writes the code for you. You might use this flashing as a signal that the code update is synchronized. If you don't like it, minimize the compiler and the flashing will not occur. There is a special check-box in View->Preferences to start the compiler for this reason (Visual Studio 2008 only; Microsoft removed the ability later).

Your plugin-code will use the index value 0 (uControlID in the Properties dialog) to map the slider named Volume on the UI to the m_dB variable. After setting up the Volume control, switch to the Visual Studio compiler (hint: use the -> C++ prompt to save the .sln file, always say YES and see my website for information on getting rid of most of these pop-ups) and open your project's .h file.
