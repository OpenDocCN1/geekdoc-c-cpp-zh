Multidimensional arrays can be tricky in C/C++ when you want to pass a pointer to an array as a function argument. Therefore CVectorPathGenerator uses a classic programming trick where we flatten the array as a single dimensional chunk of memory, arranged as concatenated table rows (this is how the compiler usually does too). A macro is defined that allows you to find cells in array. The macro is JS_PROG_INDEX:

```
#define JS_PROG_INDEX(x,y) (x)+(MAX_PROGRAM_STEPS*(y))
```

For example, the array is named m_pVPGProgramTable, you would find the cell at row 2, column 5 as:
AC_Mix = m_pVPGProgramTable[JS_PROG_INDEX(2,5)];

You don't have to worry about unless you want to modify the object.

# Programming

Both in this chapter use the now familiar objects to handle the voice. Both declare a static member of type CVectorPathGenerator named m_VPG. Programming requires a set of function calls to one named setProgramStep.

```
void CVectorPathGenerator::setProgramStep(int nIndex, float fX, float fY, float fTimeToStep_mSec, bool bJoystick)
```

The arguments are:
- nIndex: the zero-based index of the step (path vertex)
- fX and fY: the (x,y) coordinate of the new vertex
- fTimeToStep_mSec: the segment time to the next vertex
- bJoystick: true if you are using rotated coordinates, if you are using rotated version

For example, let's program the following path in non-joystick coordinates shown in Figure 11.29. This path starts at the center then moves through all vertices so that the sound starts at an equal mix then morphs between 100% versions of each sound source coordinates for each step are:

- 0: (0.0, 0.0) = 25% A, 25% B, 25% C, 25% D
- 1: (-1.0, 1.0) = 100% A
- 2: (1.0, 1.0) = 100% B
- 3: (1.0, -1.0) = 100% C
- 4: (-1.0, -1.0) = 100% D

# Starting/Stopping

You start the program during an event with startProgram(). If the joystick is in sustain mode, it will pause itself once the vertex is hit (it's the second to last one in the program). When the note off occurs, you resume operation with resumeProgram(), which takes the path through the last segment. If the program is not in sustain mode, then there is nothing to do here.

# Incrementing the Program

You have to increment the program on each sample interval to update the new vector mix. After incrementing the program, you can query it for the new vector mix values. These two steps always go together.

```
// --- some variables to hold the mix values 
float f, fB, fC, fD, fAC, fBD;
m_VPG.incTimer();
// uses pass-by-reference to set ours with
m_VPG.getMixValues(f, fB, fC, fD);
m_VPG.getVectorABCDMixes(fAC, fBD);
```

# Oscillators

- four CSampleOscators with four sets of stereo multi-samples

# Filters

- two ThreeFiveFilters (one for left, one for right), LPF mode, NLP engaged

# LFOs

- two CLFOs, one general purpose and one for the rotor

# Voice Mode

- manual: you use the vector joystick to mix your oscillators in realtime
- program: you run a vector path program

# Vector Path Mode

- once: one time through path
- loop: loop over complete path
- sustain: stop at second to last vertex during sustain, resume after note off
- backfrth: move back and forth complete path

# VST3 and AU
