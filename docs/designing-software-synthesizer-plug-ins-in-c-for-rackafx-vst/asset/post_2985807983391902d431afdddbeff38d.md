# CDiodeLadderFilter: the diode ladder fourth LPF

All filters are derived from an abstract base class CFilter. The base class object will handle the cutoff frequency modulating since it is the same for all filters. All filters except the first order LPF and HPF can optionally feature nonlinear processing. The CFilter object will define the user interface variables and controls. An Aux Control will be assigned to the variable BSF control in the SEM filter to pass passband compensation in the ladder filters. You may utilize it for whatever you wish in the other models. We will design and code all filters first. Then we will add the Moog ladder filter to NanoSynth. You can then test all other filters. They are simplified since all filters are derived from the same object and have the same core functions.

![](img/b42d0dca53f4a889d8162d55f7c8c05d_414_0.png)

As with many synths, our filters will use an exponential cutoff frequency Q control, known as "vol/octave" control. As we move the control, the cutoff frequency varies by the octave, producing a more musical result. In addition, modulating the cutoff frequency will also be exponential in nature. The filter synthfunctions.hs has the necessary functions to assist in the exponential control and modulation. All filters operate over a full range of cutoff frequencies from 20 Hz to 20,480 Hz. In our synth designs, however, we limit the range of operation 80 Hz to 18 kHz, which you may certainly change if you like. As with many synths, the Q will be labeled from 1 to 10, and we will map this according to the filter type. For the SEM filter, this will become a value for Q 0.5 (critically damped) and 25 (highly resonant), for the others it will be converted to a value for the filter feedback gain K. All filters will use the same nonlinear processing block consisting of the tanh() function and a saturation control. The saturation control will range from 1 (none) to 2 (+6dB) providing amplitude distortion.

## 7.13 The CFilter Base Class

The CFilter base class exposes the filter interface. It stores all variables that are common to all models as provides mutators (set()) methods for modulation input. Virtual functions are provided so the derived filters may override them and implement their own special functionality. Table 7.2 lists the CFilter member variables and methods.

- - in the detailed block diagram, the NLP block shown inline after the filter; this is not accurate as the NLP block exists within the filter structure in different locations on filter model

The easiest way to understand the object is to step through the functions and discuss them. Open the Filter.h and .cpp files and examine the functions. At the top of the Filter.h, you will find the default and constant declarations used for setting limits, clamping values the modulation variable. Here is where you may adjust the range of the filter's cutoff frequency if you wish. You must calculate the number of semitones between the lower and upper cutoff limit and divide by two. The semitoneBetweenFrequencies() function is provided for you and we will use it in other places later on.

# reset() and setQControl()

These functions must be overridden in the derived class. They have empty (blank) implementations in the base class. They are coded in case you need to add anything.

# doFilter()

This is the only pure virtual function on the object. This has two ramifications: derived classes must override this method, and the CFilter object is pure abstract, so it cannot be instantiated on its own. The function takes an input xn and produces the filtered output.

```cpp
virtual double doFilter(double xn) { return 0; }
```

# update()

The update() function will be called once per sample. It performs the calculation for cutoff frequency modulation in exponential form using the pitchShiftMultiplier() function that we also use when modulating pitch. The setQControl() function is called in case you are modulating the Q value (this is a Chapter Challenge since it would need to be re-calculated on each sample interval).

The CFilter object is fairly short and simple. Now let's use it as a base class and design all the rest of the filters in the chapter starting with the one-pole filters.

```cpp
inline virtual void update() {
  // --- update Q (filter-dependent)
  setQControl(mdQ);

  // --- do the modulation shift
  mdFc = mdFcMod * pitchShiftMultiplier(mdFcMod);

  // --- bound the final frequency
  if(mdFc > FILTER_FC_MAX) {
    mdFc = FILTER_FC_MAX;
  }
  if(mdFc < FILTER_FC_MIN) {
    mdFc = FILTER_FC_MIN;
  }
}
```
