# 2.3 Implementing a VST Plug-in: Debugging

Debugging your synth-plugin is crucial for your success. As soon as you start experimenting with your own code and
the Challenges, you will likely have problems as well when implementing new code or ideas. To debug
 test your plug-in, you will need a VST client as developed. To debug with it, you will need to tell Visual Studio
where it is located. Open the Project Properties and select Configuration Properties -> Debugging. In the Command
field, find the executable from the list. Now, in the Attach field, choose Yes. Place your VST file in the
proper for your folder and launch the client. You can't start the debugger until the client is running. With the client
running, start the Studio debugger and set breakpoints. When you instantiate your plug-in, the breakpoints will
come active and you can step through code and debug as you will. You will be flipping back and forth between
Visual Studio and the plug-in—this is normal for development on any platform.

# 2.4 Writing Audio Unit (AU) Plug-ins

Apple's Audio format is different from RackAFX and VST3, which are built in "straight"
C++ and require no additional libraries outside of ANSI C++. AU plug-ins are written in C++ using Apple's Xcode
compiler. There are many MacOS-specific features that require the programmer to know more than just
C++. To write AU plug-ins, you need already to be familiar with macOS programming, specifically the CoreServices
AppKit frameworks. Additionally, the Apple-preferred way of creating a GUI for your plug-in is with the Cocoa framework, which is done in another programming language:\Objective-C. The AU plug-ins in all use Cocoa, so you will need to understand the Objective-C language as
well as concepts like IBActions, IBOutlets, target-actions, and referencing outlets. We developed our own custom
controls for the Cocoa GUI, all in Objective-C, and you don't to understand how they work on the inside
to the projects in this book, if you want to modify the code and feel or behavior. And what means you will
to be competent in Objective-C. If you don't know Objective-C but you are already good with C++ then the good news
is that you can learn it easily.

AU provides two mechanisms for implementing a GUI. The AU client provides a default GUI in the plug-in does
ot implement one. There is also an option for a custom GUI. We will implement both: need to define the default
UI first and then connect the custom GUI to its parameters. You can alternate back and forth between the two GUIs
in the AU Client.
