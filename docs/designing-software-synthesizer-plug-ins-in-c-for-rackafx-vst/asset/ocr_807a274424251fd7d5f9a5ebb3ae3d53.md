# Redeclaration of Datatypes

Like VST3, AU redeclares datatypes such as Int32, UInt32, Float32 etc., so be aware of this. You can always use your familiar datatypes, int, float, double, etc.; however, on occasion you can get burned if you try to override a base class function that uses the redeclared type but you substitute a standard type. The compiler will not recognize your function as an override.

# Scopes and Elements

You will see the argument datatypes AudioUnitScope and AudioUnitElement in several of the AU functions we override. Scopes are used to identify a "major attribute" of an audio unit. Typically you will see input, output and global (both input and output). For example, output bus #2 would use Scope = output and Element = 2 while input bus #1 would use Scope = input and Element = 1.

# 2.39 AUSynth and the AUInstrumentBase

The base for AU synth plug-ins is named AUInstrument. It is derived from another object called MusicDevice, which is derived from AUBase and AUMIDBase. In the application document, you may run across AUMonitimbralInstrumentBase and AUMultimbralInstrumentBase, which are also derived from AUInstrument. These objects were added later in the development of the Audio Units API and are supposed to make your life easier; we do not find this to the case and were quite perplexed that the definition for AUMultimbralInstrumentBase in the AUInstrument.h file says "this is a work in progress."

We decided to bypass these objects and design a straight-up synth plug-in template that you can easily modify. As a bonus, the operation of the synth voices very much parallels the way that RackAFX and VST3 operate, making it easy to move from one API to the next. Additionally, you can easily modify your voice while stealing heuristic (Chapter 8), which is not straightforward when using the AUXXxtimbralInstrumentBase classes.

The AUInstrumentBase functions need to override and implement can be loosely categorized as follows:

+   - standard plug-ins initialization and destruction
- function for rendering/processing audio
- functions to declare user interface controls ("Parameters")
- functions to handle presets and saved states
- functions to declare custom GUI and MIDI capabilities
- functions to handle MIDI events

We implement all of these on one single synth object AUSynth; remember, all projects use the same AUSynth object. The AUInstrumentBase base class handles the rest of the instrument function (and there is a lot of it). You don't have to worry about the implementation details, but it wouldn't hurt for you to examine the AUInstrumentBase object in the CoreAudio group's AUInstrumentBase.h.

Download the MiniSynth project, open the AUSynth.h file and look at the functions.
