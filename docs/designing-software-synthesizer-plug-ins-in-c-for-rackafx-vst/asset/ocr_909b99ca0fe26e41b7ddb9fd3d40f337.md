# 3.4 Project: NanoSynth

NanoSynth is going to be the basis for the MIDI portion of every other synth, as well as act as a testbed for your C++ objects. You will build NanoSynth over the next five chapters. In this chapter you will learn how your platform deals with MIDI messages and configure the fundamental messaging system. There are no controls to deal with, as this is a simple project that you should get running quickly You will need a MIDI controller to provide as many of the controller messages in Section 3.2 as possible. You will trap MIDI events and log them to an output window to make a basic MIDI monitor. In the next chapter, you will use the note on off events to turn your oscillators on and for testing. This plug-in won't make any noise, but it will ease you into coding on the platform you choose. Take a look at Table 3.3 from the last chapter showing the differences in the MIDI function implementation for each API. In this project, we'll be working in those functions.

Table 3.3: MIDI functions for RackAFX, VST3 and AU.

| Functions | RackAFX | VST3 | AU |
| --- | --- | --- | --- |
| MIDI Message(s) | | | |
| Note On | midiNoteOn() | process() | StartNote() |
| Note Off | midiNoteOff() | process() | StopNote() |
| Pitch Bend | midiPitchBend() | process() | HandlePitchWheel() |
| Mod Wheel | midiModWheel() | process() | HandleControlChmge() |
| All other MIDI Messages | midiMessage() | process() | HandleControl()HandleMouseEvent() |

For VST3, you will create a sub-function processEvents() to handle the decoding, but the information arrives during the process() function; we will call processEvents() from process()

# Common Files

All platforms will use some common functions that are identical and included in every synth project:

+   - synthfunctions.h—a collection of constants, structures and functions used widely in every project
- pluginconstants.h—originally a RackAFX file, this includes more constants, functions, and objects such as the CWData object that opens and reads wave flows
- pluginobjects.cpp—the implementation file for objects declared in pluginconstants.h

VST and AU plug-ins need one additional file. Note that this file is slightly different for each synth since it is based on the synth's parameters—the GUI controls. This file is not needed in RackAFX because of the way the controls are created and declared—with a properties format rather than in code.

+   - synthparameters.h—enumerations and #defines for the zero-based parameter index values, as well as the parameter limits (min, max, default) that will match your GUI tables
