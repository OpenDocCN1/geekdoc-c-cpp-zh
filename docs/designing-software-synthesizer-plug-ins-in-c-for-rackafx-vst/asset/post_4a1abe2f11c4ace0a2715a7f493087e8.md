# 8.20 Global polyphony Parameterization

Handling polyphony by replicating structures (or objects) is fairly straightforward; you saw the use of the for() loop to iterate through the voices and deal with them. We have a shared modulation matrix core, so when the user changes or enables/disabling routes, we only need to change the matrix core once. But if you look at the update() function for the Poly NanoSynth plug-in, you will see wasted code. We are looping through the objects and repeatedly setting the same variable once. And, we are setting variables on objects that might not even be active. Imagine a synth with 16 voices of polyphony and 40-50 GUI controls, which will have in the rest of the projects. Updating all the voices at once will result in lots of wasted function calls. Since the voices' all share the same GUI controls (i.e. changing the filter cutoff changes the cutoff in all the voices), why not have a way to share common or global parameters? We will use the same strategy again for the global parameters; we will augment rather than replace code. This allows you to use the objects in other projects and plug-ins outside the scope of our synth projects.

Each of our synth objects requires the same modification for global parameters:

- declare a global parameter structure pointer; when NULL, global parameters are not used own- implement a init(GlobalParameters()) function in which you save your new global parameter pointer (thus enabling the functionality), and you initialize your synth variables
- use the global parameters in your update() function, where the object's parameters are updated based in (in part) on GUI control values
