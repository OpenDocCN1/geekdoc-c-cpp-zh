After deciding on impulse response, the next step is to choose how much of the edge you want to adjust. In general, the more points you adjust, the better the aliasing reduction, however it comes at the cost of processing time and storage. You usually select the pulses symmetrically around the discontinuity. In our simplest BLEP oscillators, we will apply correction to just one point on each side of the discontinuity, for a total of two points. We implement a four-point correction in the next section. The reduction in aliasing is dramatic, though not 100% complete. This is potentially an area for experimentation in your own designs. Since we will implement completely alias-free wavetable waveforms as we have something to come with. Some of your window listing tests the quasi bandlimited and wavetable oscillators and judge for yourself.

**Figure 5.10:** (a) The window sinc() selects only the central pulse (b) the resulting BLEP edge after integration and bipolar correction (c) the BLEP residual for the rising and falling edge cases.

Knowing the width of the adjustment zone, you can then window the impulse response (that, is, only a portion of it). This is another area for experimentation—you may choose different window functions such as Hann, Hamming, Blackman, or even scale the impulse response values. The value of the window and size factor determines the aliasing is reduced. In our simplest BLEP oscillators, we use a rectangular window on the original sinc() function to limit the pulse to its zero crossings, as seen in Figure 5.9(a), which gives a correction width of two samples. This is also the choice used to demonstrate the Legacy/Bright patent if you are following along in that. However, Krog and other know may use different correction windows and widths; this is another secret trade. Figure 5.9 (b) shows the use of a non-rectangular window around a wider piece of impulse.

With the window size and type selected, we can generate the BLEP residual. BLEP residual is precalculated in a 4096 element array in synthfunctions.h for you to use called dBLETable[4096]. You may download the C/C++ code from this chapter we generate the residuals from this chapter for your own experiments. You may also use MATLAB or other tools to generate and window an impulse. The residual is stored in this relatively large 4096-point sampled array. We can then use lookup techniques to find the residual value to apply to a given waveform sample.

There are a multitude of ways of implementing a BLEP oscillator. The residual is stored in a relatively large finely sampled array. Other manifestations are less memory intensive, and there are different table lookup techniques that can be applied. For example, if you were to go eight points into the discontinuity (or four), then you might create eight-point tables for different increment values from the module controller and interpolate between them. Our implementation is hardware-less; BLEP is a function that returns the residual correction value or 0.0 if you are outside the discontinuity transition region. You can use simple table lookup techniques to fetch the residual value according to the current phase of the oscillator. You may enable or disable interpolation of the BLEP table (it is disabled to save processing time), and of course you are encouraged to experiment with other forms of interpolation.
