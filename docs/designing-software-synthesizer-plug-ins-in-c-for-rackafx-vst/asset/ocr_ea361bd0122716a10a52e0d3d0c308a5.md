Each of your synthesizer plugins becomes a C++ object named NanoSynth, CMiniSynth, CDigiSynth, CVectorSynth, CAiSynth and CDSynth. These are all derived from the CPLugin base class. The RackAFX plug-in will help you write your plug-in. When you create a RackAFX project, it will set up a Visual C++ Project for you and populate your project with all the files it needs. It will automatically create a new derived class based on the name of your project. When you setup GUI controls like sliders and buttons, it will write and maintain the code for you. You will be switching back and forth between RackAFX and your C++ compiler. There are buttons on the RackAFX GUI that will let you jump to the compiler as well as launch functions like rebuilding and debugging. Use RackAFX to maintain your GUI and your compiler to write the signal processing code. RackAFX also handles MIDI messages and is really MIDI-ready. It delivers MIDI messages to your plug-in and interfaces with your MIDI controllers: if you have a built-in piano-controller; however you need hardware MIDI controller to execute all the controller options like continuous and sustain pedal.

# Building the DLL

RackAFX sets up your compiler to develop your freshly built DLL in the /Plugins folder in the RackAFX Application Directory. If you want to see, move or delete a DLL, you can find this folder by using the menu item Plugin->Open Plugins or Menu->All Programs->RackAFX->Plugins Folder . After a successful build, you use RackAFX to test and debug your plug-in. You call and create your plug-in. The client needs to handle four basic operations during the lifecycle of your component:

+   * creation of the plug-in
* maintaining the UI
* rendering audio from the plug-in
* sending MIDI messages to the plug-in
* destruction of the plug-in

# Creation

When you load a plug-in in RackAFX, you are actually setting the system path to the DLL you've created. RackAFX uses an OS function to load the DLL into its process space. Once the DLL is loaded, RackAFX first runs a compatibility test, then requests a pointer to the constructor called createObject(). It uses this pointer to call the method, and the DLL returns a newly created instance of your plug-in cast as the CPLugin * base class type.
