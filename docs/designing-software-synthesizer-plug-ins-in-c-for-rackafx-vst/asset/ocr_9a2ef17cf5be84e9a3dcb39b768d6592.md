The Filter type control displays strings that define the current setting. An unsigned integer (UINT) keeps track of the current setting. The enum String gives you comma-separated values that will map to the UINT variable. In this example the mapping is:

+   * LPF: 0
* HPF: 1
* BPF: 2

For the enumerated UINT type, the default value is always the first value in the enum string-list or LPF here.

In the prototype phase, you assign the controls in any order you wish, meaning you can pick the sliders, buttons or LCD controls as you choose. The main thing to understand is that the RackFX controls are already indexed for (which you can ignore the last column in Table 2.6). Once your plug-in is complete, you can use the GUI Designer to craft the final GUI and just as in the prototype phase, the controls do not have to specify any ordering. RackFX indexes the controls as shown in Table 2.7.

One of the fundamental differences between RackFX and VST3/AU is that in later APIs, it is up to you to define and maintain proper indexing of controls. This is done with a giant enumeration. In RackFX the indexing is preset. You do not need to define or maintain a list and the order can be arbitrary. However, you have to know what the index is for a given control, so RackFX automatically creates a comment-block identifying the index/control pairs whenever you add or remove controls. We will look at this shortly.
