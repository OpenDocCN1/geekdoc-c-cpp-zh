## 3.8 MIDI Controllers in VST3

Interestingly (and confusingly), a VST host will not deliver MIDI control changes directly to your plug-in. Steinberg tries to justify this by noting that delivering MIDI data directly to a plug-in that uses the data to alter its parameters and GUI can interfere with the host's automation. To make things even more interesting, VST3 groups of Channel Pressure and Pitch Bend messages with control index values. These are MIDI messages, not controller indexes! And it creates a condition that requires index values greater than 127, which may confuse verification routines.

If you receive these messages, VST3 requires the use of a MIDI Map. The idea is that you create a GUI with controls for parameters, and you map a CC—say, Expression—to one of your parameters, such as Filteroff Frequency. The mod wheel is always mapped to LFO by default. And the volume control is usually mapped to the output level.

A simple solution is to create dummy parameters for the MIDI messages you want to receive. You don't intend for the user to see them on the final GUI. Then, you map these controller messages to your dummy parameters. During the process() function, these parameters are extracted as if they were coming from the GUI. A fundamental drawback is that the Parameter value is normalized between 0 and 1. The channel information is lost, so you can't know the original CC channel. A helper function called doUIControl() handles parameter changes. It gets called in the process() function, which receives the events in its argument.

### Defining Parameter Index Values

With all GUI parameters, these dummy parameters are identified with an index value. We use the same index to initialize the parameter as we decode it later during doUIControl() function. For all the VST3 synth, these parameter index values are implemented with an enumeration found at the top of SynthParamLimits.h:

```cpp
enum {
    MIDI_PITCHBEND,
    MIDI_MODWHEEL,
    MIDI_VOLUME_CC7,
    MIDI_PAN_CC10,
    MIDI_EXPRESSION_CC11,
    MIDI_SUSTAIN_PEDAL,
    MIDI_CHANNEL_PRESSURE,
    MIDI_ALL_NOTES_OFF,
    NUMBER_OF_SYNTH_PARAMETERS // always last
};
```

### Initializing the MIDI Parameters

The GUI parameters are always created and initialized in the Controller::initialize function. Initializing the Parameter objects involves linking them to the enumerated parameter indices, as well as establishing the min, max and default values. Our parameter values get delivered to the Processor as a normalized value anyway, so the simplest thing is to set them up unipolar. The SynthParamLimits.h file has constant declarations for the min, max and default values of all parameters in all the synths and includes unipolar and bipolar limits as well. Open the SynthController.cpp file and set the dummy variables (refer to Chapter 2 if you need to), use the indexes and limits in the SynthParamLimits file:
