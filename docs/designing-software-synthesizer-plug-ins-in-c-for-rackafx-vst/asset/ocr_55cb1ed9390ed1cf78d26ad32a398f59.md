# Audio Units (AU): MacOS

I chose not to implement the VST3/MacOS versions due to space limitations. Frankly, the code is nearly identical to the Windows version and the VST3 SDK contains sample code on platforms. You may also notice that Avid's AAX API is messy. You must be a registered plug-in developer to develop. This is not a simple process, as you must first prove that you can write and sell plug-ins. In this way, the AAXAPI is closed and not openly documented like RackFAX, VST3 and AU so I can write the SDK implementation details.

If you read my first, then you know that RackFAX packages itself as a VST2 plug-in by using a C++ wrapper. This obscures the actual implementation details. This body does not work that—each plug-in is implemented in its native language using the SDK tools; there are no third-party libraries, frameworks or other helpers. You see all the details with nothing obscured. This has the impact on the Audio Units plugins. Their GUIs must be implemented with Cocoa, which is written in Objective C. If you are targeting AU, then you need to know Objective C to understand the programming GUI. We are on that subject, so you should be happy to know all the VST3 and AU plug-ins come with complete pre-built GUIs in the same. In RackFAX, you can use the drag-and-drop editor to create a GUI with, but VST3 and AU are different. In VST3 you use the VSTUI design editors. These ship with the SDK. In this body, you use the drag-and-drop editor that VSTUGI offers but is still code for setting up and managing the GUI. In AU plug-ins, you use InterfaceBuilder (IB) that is built into Xcode. If you have created several custom controls for Cocoa so you can create impressive user interfaces. Of course you may use the SDK objects as well.

Another area of improvement in this book came as a suggestion from the first readers. Requested homework assignments. These appear in the form of "Challenges" at the end of not, but not all chapters. This is directly taken from Joe Conway and Aaron Riley in their excellent iOS—The Big North Guide book, which is the text I use for my iOS programming class at the University of Miami. The "Challenges" are usually programming assignments and categorized as Bronze, Silver, Gold, Platinum and Diamond from the least to most challenging. Solutions are not given, but they should show up at my forum as students and readers implement them and show their variations (most are open-ended and a very difficult for).

In the early phases of preparing a book proposal, I needed to make a decision about the synth projects themselves. They could be really simple with plenty of room for expansion or grossly complex with every type of synthesis algorithm modulation routing possible.
The first thing I decided not to feature physical modeling algorithms. The reason is that this could easily turn into a whole book out itself and would be much more of a theory book than a programming book. I decided to feature six polyphonic synthesizers using a variety of synthesis techniques. The synths respond to common MIDI controller messages and a modulation matrix that allows you to spin off countless variations on their architectures. I also needed to make sure that there was not overlap of the theory and this book features all oscillators and filter designs. The theory are also different with slightly more examples on analog synthesis.

Chapter 1 is a brief introduction to synthesizer components and basic signal processing in both analog and digital domains. Chapter 2 is the most lengthy in the book; it details how to write plug-ins in all APIs as well as comparing side-by-side and showing the pros and cons of each. The real fun starts in Chapter 3 where you begin your first "training synth" NanoSynth and MIDI messages on your platform. With the MIDI in place, we can move on to the theoretical meat of the book in Chapters 4– Chapter 4 includes the analog and digital signal processing you need to understand the filters and oscillators. Chapter 5 explains the oscillators, and you will add them to NanoSynth project. Next you add the Envelope Generator (EG) and Digital Controlled Amplifier (DCA) in Chapter 6. Chapter 7 introduces the virtual filter models (you will test with different filters); here you add the Mono Ladder Filter for NanoSynth and then you are on your to test the other filters.
