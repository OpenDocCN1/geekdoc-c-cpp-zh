# 2.25 VST3 Controller MIDI Mapping

# Step Five: MIDI Mapping

VST implements an interesting and somewhat confusing strategy for dealing with MIDI messages. The note and off messages are handled in the Processor. MIDI controller messages, as those sent from the pitch-bend, joystick or slider continuous controllers, are handled in the Controller. Specifically, each MIDI controller control a Parameter object such as the pitch bend wheel, which changes the value of the underlying Parameter object and alters the appearance of the control on the GUI. In some cases this makes sense; for example you map MIDI Continuous Controller (CC) Message 0x07 (volume) to the master volume control on your synth. When the user turns this controller on a MIDI device, the volume control automatically moves on the GUI. Note that the Processor will actually deal with the MIDI control and apply it to the synth rendering. However, we want to design that that are configurable during operation that might change the mapping. For example, in our synth the wheel control (CC 0x01) will be mapped to the LFO depth parameter by default. But we want make sure our synths allow the user to change this mapping to some other destination. You will get into the details of this when you learn about the modulation map—a component that greatly extends the flexibility of our synths.

The Processor will receive the MIDI controller events disguised as synth parameters and issue changes to the underlying synth objects. We have chosen to map each MIDI Controller to a dummy Parameter on the Controller. These Parameters will appear as controls in the GUI only; our custom GUI will hide them. In this way, we can re-map MIDI Controllers on-the-fly.

The Controller exposes the IMIDIMapping interface and must implement one and only pure abstract getMIDIControllerAssignment().
