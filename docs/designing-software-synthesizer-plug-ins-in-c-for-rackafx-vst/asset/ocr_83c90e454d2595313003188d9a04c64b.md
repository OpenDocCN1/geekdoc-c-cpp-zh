+   - WPOptionMenuGroupMS: a custom option menu group control (aka pop up button control)
- WPPopUpToggleButtonMS: a custom pop up button cell

The reason these files are named after the synth project is that Cocoa has a flat namespace and each object must have a unique name. For example, if all the synths use WPRotaryKnob as the name of these controls, and you customized the knob in project to look different from others, the names would collide, and you would lose the uniqueness of the object; for example, if you load the plug-in with the unique knob first, all subsequent plug-ins will load the same knob, even though they were compiled with different resources.

RULE: rename all GUI objects in a potentially unique way—Apple recommends using your initials as the first three letters of any GUI object.

In Xcode, select the MiniSynth target and examine its Build Phases. Let's go over each one:

+   - Target Dependencies: the synth projects require that their GUI also be built without errors, so you see Cocoa listed here
- Copy Headers: all of the .h files that are required to support the plug-in
- Copy Bundle Resources: the info.plist file
- Compile Sources: all of the .cpp files that are required to support the plug-in
- Link Binaries with Libraries: the five frameworks required for the synth portion of the plug-in
- Build Carbon Resources: AUSynth; this is only for compatibility with Logic 9
- Copy Files (1 Item): copies your CocoaSynth.bundle to the /Resources folder
- Copy Files (1 Item): copies your synth.component file to the /Components folder

Select the CocoaUI target and examine its Build Phases you will see basically the same thing, though there is no copying of files. When you select and build the MiniSynth project, it will first build the CocoaUI, then build the Synth, and then copy the two files to their destinations.

Re-select the MiniSynth target and examine its Build Settings. The most important things to note are:

+   - uses an exported symbol with the .exp extension
- Info.plist is named Info.plist
- product name is MiniSynth
- wrapper extension is component

The .exp file contains the symbols that define the entry points into the component. These entry points do not change from one project to the next so you don't need to worry about that. The two symbols are named as follows and should never be changed for our projects:

```
_AUSynthEntry
_AUSynthFactory
```
