## GUI Designer Rules and Paradigms

- when you run out of continuous controls (sliders) you can't drag any more knobs/sliders
- each time you drag a knob or slider, you must set it up before dragging any other knobs or sliders
- you can add any continuous control (slider) to the LCD group; it is a separate entity from the one on your main RackAFX

when you add radio button controls, RackAFX starts with the topmost bank on the main GUI and automatically links your variable. It moves from top to bottom as you drag the buttons. If you need to skip button banks, all of them at first, then reorder the ones you don't. The buttons are highly customizable. The RackAFX GUI is constantly being designed so the control images are steadily improved which means that your version of the software may not exactly resemble the figures here. Be sure to check the website http://www.willpark.com/synthbook/ for updates and how to use the most recent version of the GUI.

For the synths in this book, we will not use the meter or assignable button controls. If you want to learn how to use these, see Designing Audio Effects in C++, which several projects will feature these controls.

## Compiling as VST2/VST3 Plug-in

Once your plug-in is compiled, and you've added a GUI with the GUI Designer, you can go back to the project setup using File->Edit Project or the Edit button on the right. Here you can select "Make VST2 Compatible" and "Use RackAFX Custom GUI". When you say OK, it will take some time, as RackAFX copies over some files and reconfigures your Visual Studio files. Once complete, rebuild the project. The DLL can be found by using the menu Item->Open Plugins the VST folder of any VST2 client and used as other plug-in. You can also copy this DLL and change the extension to .vst and place it in the VST3 folder of any VST2 client to use the DLL as a VST3 plug-in. The GUI you designed will appear as the custom GUI in the VST2 and VST3 clients.

### _stdcall

In the RackAFX code you will see the qualifier _stdcall preceding each function prototype as implementation. The _stdcall calling convention is for future compatibility with other compilers as well as any 3rd party software. The _stdcall is a directive that tells the compiler how the stack is cleaned up after method calls; it has no effect on the math or audio processing thread.
