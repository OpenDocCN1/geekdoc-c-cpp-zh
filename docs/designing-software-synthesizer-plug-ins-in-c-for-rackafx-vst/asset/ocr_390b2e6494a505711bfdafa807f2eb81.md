# 2.35 AU XCode Projects

The XCode projects we have created for all follow the same paradigms for file naming, GUI naming and groups. All synths have a Cocoa GUI included, though you may choose to use the projects marked "Empty", if you want to design your own GUI. The "NO GUI" versions have empty Cocoa files and an Interface Builder.NIB file that has no controls. So each XCode project consists of two targets, one for the synth and one for the UI. The UI target is always the same (CocoUI), while the synth's name changes for each project. The synth will be the same name as the Project: NanoSynth, MiniSynth, DigiSynth, VectorSynth, AniSynth and DXSynth.

# Starting a New Project

You have two options for starting a new AU project: start from scratch or modify an existing project. Modifying an existing project is far and simpler the option. An existing project can be converted to a new one in less than ten easy steps (the Appendix).

There are multiple projects you may download, and design the GUI—for each synth project:

+   - Empty everything you write and design the GUI—if you are already an advanced programmer, this might be a good option
- GUI—the code and GUI is already there so you can focus on the synth components and processing; in each Chapter you'll have to go in and modify the GUI at a time, and after a few projects, you might want to take the complete GUI design. NOTE: this is the recommended option!
- Full—the whole project inclusive; we don't recommend compiling someone else's code as a learning method, however having the full code allows you to not only check your work but also step through the code in debug mode, so you can see how the client interacts—in short, the full projects are excellent for you debug and understand your own projects-in-progress
