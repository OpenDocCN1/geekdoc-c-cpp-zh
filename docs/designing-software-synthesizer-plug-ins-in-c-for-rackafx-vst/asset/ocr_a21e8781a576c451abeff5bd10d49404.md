The index offset is +5, so the pointer moves in steps of five buffer locations, skipping through. When it skips the end boundary, it wraps back to the top and offsets the same number of buffer locations.

Suppose we have using the pointer to write audio samples into this buffer and that has been going for some time that the pointer has wrapped around the top a few times. If we freeze during a write-event and think about the contents of the buffer, we can see how the samples line up in time. Let's assume we are using an index value m_nwrite to keep track of the write location in the buffer, incrementing it by each sample period. We are going to use another index m_nread to read values from the array. In Figure 13.3(a) you can see that the oldest sample in the buffer is the one we are writing. The youngest sample is one location before the write location. The other values are between the oldest and youngest. If we want to delay the signal by 100 samples, we offset the read index 100 samples before the write index; this might mean that the index wrap around the top of the buffer. As Figure 13.3(b) shows, the difference between the read and write index determines the delay time.

So, by implementing a circular buffer and reading/writing audio samples from/to, we can create a basic delay. This delay time is set in samples, not seconds or milliseconds. And as it turns out, we need more precision than the sample period has to offer. For example,
