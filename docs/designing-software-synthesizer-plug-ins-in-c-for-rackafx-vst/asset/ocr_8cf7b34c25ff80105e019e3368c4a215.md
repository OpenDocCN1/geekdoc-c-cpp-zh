Before wrapping Event Listening, we take a look at the two handlers, one for the knob and the other for the option menu group. Action handlers are usually in the form (:sender), so the control passes it as an argument. When we set up the knobs and menus, we give each index of the parameter it will control—these index values are called "controlIDs". So, we can just retrieve this index and use it to call ASetParameterSet() with the new value. These two methods are essentially identical except the knob value is accessed with controlValue and the menu's with getSelectedIndex. The important thing to understand is that a user control change results in a ASetParameterSet().

To put this in perspective, here is the sequence of operations that occur when the user moves a knob:

+   - moves the knob
- the iAction WPRotaryKnobChanged is triggered
- this calls ASetParameterSet()
- the new parameter value is set in the Audio Unit's "cloud" (parameter container)
- the Audio Unit notifies all listeners of this control that it has changed by using the callback function EventListenerDispatcher
