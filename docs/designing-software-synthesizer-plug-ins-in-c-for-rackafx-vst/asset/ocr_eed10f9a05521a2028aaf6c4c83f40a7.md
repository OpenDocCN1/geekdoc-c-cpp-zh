This poses a slight issue in the case of control automation where the user wants to recall or his control movements in real-time, along with the song information. If your control does not map in a linear or logarithmic way, you will need to provide some translation code that converts from plain to normalized and back. We won't need this in our projects since we will provide all the functions and keep track of your own variables and their raw and cooked mappings.

In order to implement your Controller object, follow these steps:

+   - every control will have an index so lay out as an enumeration in the SynthParamLimits.h file
- decide on a UI and establish min, max and default values for each control
- write the code that declares the UI parameters in the VSynthController.cpp file and add them to the parameters container; this will also setup the default UI
- write the code that performs the read-side serialization
- implement the MIDI Controller Mapping (the controller exposes IMIDIMapping)

# Step One: Enumerate Some Constants for Indexing the Controls

You can choose whatever order you want. The order that you add the parameters to the control list will ultimately dictate their order in the default GUI, but in the custom GUI you can place them anywhere. Even though this is an arbitrary assignment, it is important not to re-arrange these, otherwise you may need to change some connections in the custom GUI.
