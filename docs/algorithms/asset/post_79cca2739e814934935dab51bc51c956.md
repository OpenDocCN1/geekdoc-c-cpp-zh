
## Common subproblems

Finding the right problem takes creativity and experimentation. But there are a few standard choices that seem to arise repeatedly in dynamic programming.

- i. The input is $x_1, x_2, \dots, x_n$ and a subproblem is $x_1, x_2, \dots, x_i$.

```
$x_1\quad x_2\quad x_3\quad x_4\quad x_5\quad x_6\quad x_7\quad x_8\quad x_9\quad x_{10}$
```

The number of subproblems is therefore linear.

- ii. The input is $x_1, \dots, x_n$ and $y_1, \dots, y_m$. A subproblem is $x_1, \dots, x_i$ and $y_1, \dots, y_j$.

```
$x_1\quad x_2\quad x_3\quad x_4\quad x_5\quad x_6\quad x_7\quad x_8\quad x_9\quad x_{10}$
```

```
$y_1\quad y_2\quad y_3\quad y_4\quad y_5\quad y_6\quad y_7\quad y_8$
```

The number of subproblems is $O(mn)$.

- iii. The input is $x_1, \dots, x_n$ and a subproblem is $x_i, x_{i+1}, \dots, x_j$.

```
$x_1\quad x_2\quad x_3\quad x_4\quad x_5\quad x_6\quad x_7\quad x_8\quad x_9\quad x_{10}$
```

The number of subproblems is $O(n^2)$.

- iv. The input is a rooted tree. A subproblem is a rooted subtree.

## Of mice and men

Our bodies are extraordinary machines: flexible in function, adaptive to new environments, and able to interact and reproduce. All these capabilities are specified by a program unique to each of us, a string that is 3 billion characters long the alphabet [A, C, G, T].DNA sequences of any two people differ by only about 0.1%, however this still leaves 3 million positions which vary, more than enough to explain the vast range of human diversity. These differences are of great scientific and medical interest—for instance, they might help predict prone to certain diseases. DNA is vast and seemingly inscrutable, but it can be broken down into smaller units that are precise, like subroutines. Computers have a crucial tool in understanding the genes of humans and other organisms, to the extent that genomics is now a field in its own right. Here are examples of typical questions that arise:

1. When a new gene is discovered, one way to gain insight into its function is to find genes that match closely. This is particularly helpful in transferring knowledge from well-studied species, such as mice, to human beings. A basic primitive in this search is to define an efficiently computable match of strings suggests a generalization of edit distance, and dynamic programming can be used to compute it. The current method of searching through the vast GenBank database of algorithmic tricks and biological intuitions has made it the most widely used software in computational biology.

2. Methods for sequencing DNA (that is determining the string of characters that constitute it) typically take 500-700 characters. Billions of scattered fragments can be generated, but how can they be assembled into a coherent DNA sequence? For one, the position of any fragment in the draft of human DNA is unknown and may be inferred by two groups: the publicly funded Human Genome Consortium and Celera.

3. When a particular gene has been sequenced in several places, can this information be used to reconstruct the evolutionary history of these species? We explore these problems at the end of this chapter. Dynamic programming has turned out to be an invaluable tool for some of them and for computational biology in general.

On the other hand, there is one of each item (the broker has broken into a gallery, say, items 1 and two (total: ...)). However, using dynamic programming they can be solved in $O(nW)$ time, which is reasonable when $W$ is small, but not when the input size is proportional to $W$.

## Knapsack with repetition

Let's start with the version that allows repetition. As always, the main question in dynamic programming is, what are the subproblems? Can we shrink the original problem into smaller capacities? It usually takes little experimentation to figure out what we need. Accordingly, define

$K(w) = \text{maximum value achievable with a knapsack of capacity } w$

Can we express this in terms of smaller subproblems? Well, if the optimal solution to $K(w)$ includes item $i$, then removing this from the knapsack leaves an optimal solution to $K(w - w_i)$. In other words, $K(w)$ is simply $K(w - w_i) + v_i$, for some $i$. We don't know which $i$, so we need to try all possibilities: what is the maximum over an empty set is 0. We're done! The algorithm now writes itself, and it is characteristically simple and elegant.

```
$K(0) = 0
for $w = 1$ to $W:$
  $K(w) = \max[K(w - w_i) + v_i; w_i \le w]$
return K(W)
```

This algorithm fills in a one-dimensional table of length $W+1$. As always, there is an underlying dag. By constructing it, you will be rewarded with a startling insight: this variant of knapsack boils down to finding the longest path in a dag!

## Knapsack without repetition

On the second variant: what if repetitions become completely useless? For instance, knowing that the value $K(w - w_i)$ is high doesn't help us, because we don't know whether or not item $i$ already got used up in this partial solution. We must refine our concept of a subproblem to carry additional information about the items being used. We add a second parameter, $0 \le j \le n$:

$K(w, j)$ = maximum value achievable using a knapsack of capacity $w$ and items $1, \dots, j$.

The answer we seek is $K(W, n)$.

How can we express a subproblem $K(w, j)$ in terms of smaller subproblems? Quite simple: either $j$ is needed to achieve the optimal value, or it isn't:

```
$K(w, j) = \max(K(w-w_j, j-1) + v_j, K(w, j-1)).
```

(The first case is invoked only if $w_j \le w$. In other words, we can express $K(w, j)$ in terms of subproblems $K(\cdot, j-1)$. The algorithm then consists of filling a two-dimensional table, with $W+1$ rows and $n+1$ columns. Each table entry takes constant time, so even though the table is much larger than in the previous case, the running time remains the same, $O(nW)$. Here's the code.

```
Initialize $K(0, j) = 0$ and all $K(w, 0) = 0$
for $j = 1$ to $n:$
  for $w = 1$ to $W:$
    if $w_j \le w$:
      K(w, j) = \max(K(w-w_j, j-1) + v_j, K(w, j-1))$
    else:
      K(w, j) = K(w, j-1)
return K(W, n)
```

## 6.5 Chain matrix multiplication

Suppose that we want to multiply four matrices, $A \times B \times C \times D$, of dimensions $50 \times 20$, $20 \times 10$, and $10 \times 100$, respectively. Matrix multiplication is not commutative (in general, $A \times B \neq B \times A$), but it is associative, which means for instance $A \times (B \times C) = (A \times B) \times C$. We can compute the product of matrices in many different ways, depending on how we parenthesize it. Are there some of these others?

Multiplying an $m \times n$ matrix by an $n \times p$ matrix takes $mpn$, to a good approximation. Using this formula, compare different ways of evaluating $A \times B \times C$:

## Memoization

In dynamic programming, we write a table to store values of subproblems. What about a more intelligent recursive implementation, one that remembers its previous invocations and avoids repeating them? This is called memoization. A hash table, initially empty, holds values of $K(w)$ indexed by $w$.

```
function knapsack(w)
  if w in hash: return K(w)
  K(w) = max(knapsack(w - wi) + vi : wi ≤ w)
  insert K(w) into hash, with key w
  return K(w)
```

Since this algorithm never repeats a subproblem, its running time is $O(nw)$, just like the dynamic programming. The constant factor in this O notation is significantly larger because of the overhead of recursion.

In some cases, though, memoization pays off. Here's why: dynamic programming automatically solves every subproblem that could be needed, while memoization only solves the ones that actually used. For instance, if $W$ and all the weights $w_i$ are multiples of 100. A subproblem $K$ is useless unless 100 does divide $w$. The memoized recursive algorithm will never look at these extraneous entries.
