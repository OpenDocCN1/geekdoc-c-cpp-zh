# Algorithms 145

Input: a Horn formula
Output: a satisfying assignment, if one exists

set all variables to false

while there is an implication that is not satisfied:
set the right-hand variable of the implication to true

if pure negative clauses are satisfied:
return the assignment
else: return “formula is not satisfiable”

For instance, the formula is

(w ∧ y ∧ z) ⇒ x, (x ∧ z) ⇒ w, x ⇒ y, (x ∧ y) ⇒ w, (w ∨ (¬x ∧ ¬y ∨ z)), (2).

We start with everything false and notice that x must be true on account of the singleton implication ⇒ x. We see that y is also true, because of x ⇒ y. And so on.

To see why the algorithm is correct, notice that if it returns an assignment, this assignment satisfies both the implications and the negative clauses, and so it is indeed a satisfying true assignment of the Horn formula. We only have to convince ourselves that if the algorithm finds no satisfying assignment, then there is really none. This is because our “stingy” rule maintains the following invariant:

> If a set of variables is set to true, then they must be true in any assignment.

Hence, if the truth assignment found after the while loop does not satisfy the negative clauses, then there be no satisfying true assignment.

Horn formulas lie at the heart of Prolog (“programming by logic”), a language in which you program by specifying desired properties of logical expressions. The workhorse of Prolog interpreters is our greedy satisfiability algorithm. Conveniently, it can be implemented in time linear in the length of the formula; do you see how (Exercise 5.33)?
