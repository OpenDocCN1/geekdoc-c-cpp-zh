
# Hey, that was group theory!

For any integer $N$, the set of all numbers $N$ that are relatively prime to $N$ constitute what mathematicians call a *group*:

- There is a multiplication operation defined on this set.
- The set contains a neutral element (namely 1: any number multiplied by this remains unchanged).
- All elements have a well-defined inverse.

This particular group is called the *multiplicative group of $N$*, usually denoted $\mathbb{Z}_N^*$.
Group theory is a very well developed branch of mathematics. One of its key concepts is that a group can contain a *subgroup*—a subset that is in group and itself. An important fact about a subgroup is that its size must divide the size of the whole group.

Consider the set $B = \{b : b^{N-1} \equiv 1 \pmod N\}$. It is not hard to see that it is a subgroup of $\mathbb{Z}_N^*$ (just check that $B$ is closed under multiplication and inverses). The size of $B$ must divide that of $Z_N^*$. Which means if $B$ does not contain all of the next largest size it can have $|Z_N^*|/2$.

We can reduce this *one-sided error* by repeating the procedure many times, randomly picking several values of $a$ and testing them all (Figure 1.8).

> Pr(Algorithm 1.8 returns yes when $N$ is not prime) $\le \frac{1}{2^k}$

This probability of error drops exponentially, and can be driven arbitrarily low by choosing $k$ large enough. Testing $k=100$ values of $a$ makes the probability of failure at most $2^{-100}$, which is minuscule: for instance, the probability that a random cosmic ray will sabotage the computer during the computation!

**Figure 1.8** An algorithm for testing primality, with low error probability.

```
function primality2(N)
Input: Positive integer N
Output: yes/no
Pick positive integers $a_1, a_2, \dots, a_k < N$ at random
if $a_i^{N-1} = 1 (mod N)$ for all $i = 1, 2, \dots, k:
  return yes
else:
  return no
```

# Carmichael numbers

The smallest Carmichael number is 561. It is not a prime: $561 = 3 \cdot 11 \cdot 17$; yet it fools the Fermat test, as $a^{560} \equiv 1 \pmod{561}$ for all values of $a$ relatively prime to 561. For a long time it was thought that there might be finitely many numbers of this type; now we know they are, but exceedingly rarely.

There is a way around Carmichael numbers, using a slightly more refined primality test like Rabin and Miller. Write $N-1=2^s u$. If we choose a random base $a$ and check the value of $a^u \mod N$. We perform this computation by determining $a^*=\mod N$ and then repeatedly squaring, to get the sequence:

```
$a^* \mod N, (a^*)^2 \mod N, \dots, (a^*)^{2^s} = a^{N-1} \mod N$
```

If $a^{N-1} \not\equiv 1 \mod N$, then $N$ is composite by Fermat's theorem, and we are done. If $a^{N-1} \equiv 1 \mod N$, we conduct a little follow-test: somewhere in the preceding sequence, we run into a for for the first time. If this happened after the first position (that is, if $a^* \not\equiv 1 \mod N$), and the preceding value in the list is $-1 \mod N$, then we declare $N$ composite.

In the latter case, we have found a nontrivial square root of $1 \mod N$: a number that is not $\pm1 \mod N$ but when squared is equal to $1 \mod N$. Such a number can only exist if $N$ is composite (Exercise 1.40). It turns out that if we combine this square-root check with our earlier Fermat test, then at least three-fourths of the possible values between $1$ and $N-1$ will reveal a composite $N$, even if it is a Carmichael number.

# Randomized algorithms: virtual

Surprisingly—almost paradoxically—some of the fastest and most clever algorithms rely on chance; these proceed according to the outcomes of random tosses. These randomized algorithms are often very simple and elegant, and their output is allowed to be incorrect with small probability. This bound on failure holds for every input; it only depends on the random choices made by the algorithm itself, and can easily be as small as one likes.

Instead of devoting a special chapter to this topic, in this book we interspersed randomized algorithms where they arise naturally. Furthermore, no knowledge of probability is necessary to follow what is happening. You just need to be familiar with the concept of probability, expected value, the expected number of times we must flip a coin before getting heads, and the property known “linearity of expectation.”

# 1.4 Cryptography

Our next topic, the Rivest-Shamir-Adleman (RSA) cryptystem, uses all the ideas we have introduced in this chapter! It derives very strong guarantees of security by ingeniously exploiting the wide gulf between the polynomial-time computability of certain number-theoretic aspects (modular exponentiation, greatest common divisor, primality testing) and the intractability of others (factoring).

The typical setting for cryptography can be described via a cast of three characters: Alice and Bob, who wish to communicate in private, and Eve, an eavesdropper who will go to lengths to find out what they are saying. For concreteness, let's say Alice wants to send a specific message $x$, written in binary (why not), to her friend Bob. Bob encodes it $e(x)$, sends it over, and then applies his decryption function $d(\cdot)$ to decrypt it: $d(e(x))=x$. Here $e(x)$ and $d(\cdot)$ are appropriate transformations of the messages.
