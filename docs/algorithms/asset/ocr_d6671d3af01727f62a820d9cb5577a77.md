Thus, using $k$ gives us a shorter path from $i$ to $j$ if and only if

```
dist(i, k, k-1) + dist(k, j, k-1) < dist(i, j, k-1)
```

in which case $dist(i, j)$ should be updated accordingly.

Here is the Floyd-Warshall algorithm—and as you can see, it takes $O(|V|^3)$ time.

```
for i = 1 to n:
  for j = 1 to n:
    dist(i, j, 0) = ∞
for all (i, j) ∈ E:
  dist(i, j) = ℓ(i, j)
for k = 1 to n:
  for i = 1 to n:
    dist(i, j) = min[dist(i, k, k-1) + dist(k, j, k-1)]
```

# The traveling salesman problem

A traveling salesman is getting ready for a sales tour. Starting at hometown, in case, he will conduct a journey in which each of his cities is visited once before he returns home. Given the pairwise distances between cities, what is the best order in to visit them, so to minimize the distance traveled?

Denote the cities by $1,...,n$, the hometown being 1, and let $D = (d_l)$ be the matrix of intercity distances. The goal is to design a tour that starts and ends at 1, includes all other cities exactly once, and has minimum total length. Figure 6.9 shows an example involving five cities. Can you spot the optimal tour? In this tiny example, it is tricky for a human to solve the solution; what happens when hundreds of cities are involved.

It turns out this problem is also difficult for computers. In fact, the traveling salesman problem (TSP) is one of the most notorious computational tasks.
