More generally, at any given moment the breadth-first search is advancing along certain edges of G, and there is an alarm for every endpoint toward which it is moving, set off the estimated time of arrival at that node. Some of these might be overestimates because BFS may find shortcuts, as a result of arrivals elsewhere. In the preceding example, a quicker route to B was revealed upon arrival at A. However, nothing interesting can possibly happen before an alarm goes off. The sounding of the next alarm must signal the arrival of the wavefront to a real node u ∈ V by BFS. At that point, BFS might also start advancing along some new edges of u, and alarms need to be set for their endpoints.

The following "alarm clock algorithm" faithfully fulfills the execution of BFS on G'.

+   - Set an alarm clock for node s at time 0.
- Repeat until there are no more alarms:
- Say the next alarm goes off at T, for node u. Then:
  - The distance from s to u is T.
  - For each neighbor v u in G:
    - If there is no alarm for v, set one for T + l(u, v).
    - If v's alarm is set for later than T + l(u, v), then edit it to this earlier time.

# Dijkstra's algorithm

The alarm clock algorithm computes distances in any graph with positive integral lengths. It is almost ready for use, except that we need to implement the system of alarms. The right data structure for this job is a priority queue (usually implemented via a heap), which maintains a set of elements (nodes) with associated numeric key values (alarm times) and supports the following operations:

+   - Insert a new element to the set.
- Decrease-key. Accommodate the decrease in key value of a particular element.
