## 5.2 Huffman encoding

In the MP3 audio compression scheme, a sound signal is encoded in three steps.

- 1. It is digitized at regular intervals, yielding a sequence of real numbers $s_1, s_2, \dots, s_T$. For instance, a value of 44,100 samples per second, a 50-minute symphony would round to $T = 50 \times 60 \times 44 \approx 130$ million measurements.
- 2. Each real-valued sample $s_i$ is *quantized*: approximated by a nearby number from a finite set $\Gamma$. This is carefully chosen to exploit human perceptual limitations, with the intention that the approximating sequence is indistinguishable from $s_1, s_2, \dots, s_T$ by the human ear.
- 3. The resulting length of $T$ over alphabet $\Gamma$ is encoded in binary.

It is in the last step that Huffman encoding is used. To understand its role, let’s look at a toy example in which $T$ is 130 million and the alphabet $\Gamma$ consists of just four values, denoted by the symbols A, B, C, D.

Figure 5.9 Top: Prim's minimum spanning tree algorithm. Below: An illustration of Prim's algorithm, starting at node A. Also shown are a table of cost/prev values, and the final MST.

```
procedure prim (G, w)
Input: A connected undirected graph G = (V,E) with edge weights w
output: A minimum spanning tree defined by the array prev
for all u∈V:
  cost(u) = ∞
  prev(u) = nil
  pick any initial node u₀
  cost(u₀) = 0
H = makequeue(V) (priority queue, using cost-values as keys)
while H is not empty:
  v = deletion(H)
  for each [v, z] ∈ E:
    if cost(z) > w(v, z):
      cost(z) = w(v, z)
      prev(z) = v
```

## A randomized algorithm for minimum cut

We have already seen that spanning trees and cuts are intimately related. There is another connection: remove the last edge that Kruskal's algorithm adds to the spanning tree; this breaks the tree into two components, defining a cut $(S, V-S)$. What can we say about this? Suppose the graph were unweighted and its edges were ordered uniformly at random for Kruskal's algorithm to process them. Here is a remarkable fact: with probability at least $2/n$, $(S, V-S)$ is the minimum cut in the graph, where size of a cut $(S, V-S)$ is the number of edges crossing between $S$ and $V-S$. This means that repeating the process $n^2$ times outputs the smallest cut with high probability: an $O(n^2 \log n)$ minimum cut algorithm, invented by David Karger, is the fastest known algorithm for this problem.

So let us see why in each iteration of Kruskal's algorithm, the vertex $V$ is partitioned into connected components. The only edges eligible to be added to the tree have their endpoints in distinct components. So if there are $k$ components in the graph, the number of edges out of it is at least $C/2$ (and we need to compensate for double-counting each edge). Since the edges were randomly ordered, the chance that the next edge in the list is from the minimum cut is at most $C/(k/2)$. Thus, with probability at least $1-2/k=(k-2)/k$, the choice leaves the minimum cut intact. But now that the choice of the last spanning tree is

$$\frac{n-2}{n} \cdot \frac{n-3}{n-1} \cdot \frac{n-4}{n-2} \cdots \frac{2}{n-4} \cdot \frac{1}{n-3} = \frac{1}{n(n-1)}$$

Is there some sort of variable-length encoding, in which just one bit is used for the frequently occurring symbol A, at the expense of needing three or more bits for less common symbols? A danger with having codewords of different lengths is that the resulting encoding may not be decipherable. For instance, if the codewords are [0, 01, 11, 001], the decoding of strings like 001 is ambiguous. We will avoid this problem by insisting on the prefix-free property: no codeword can be a prefix of another.

Any prefix-free encoding can be represented by a full binary tree—that in which each node has either zero or two children—where the symbols are at the leaves, and where each codeword is generated by a path from root to leaf, interpreting left as 0 and right as 1 (Exercise 5.29). Figure 5.10 shows an example of such encoding for the four symbols A, B, C, D. Decoding is unique: a string of bits is decrypted by starting at the root, reading the string from left to right to move downward, and whenever a leaf is reached, outputting the corresponding symbol and returning to the root. It is a simple scheme and pays nicely for our toy example (under the codes of Figure 5.10) the total size of the binary string drops to 21 megabits, a 17% improvement.

In general, how do we find the optimal coding tree, given the frequencies $f_1, f_2, \dots, f_n$ of $n$ symbols? To make the problem precise, we want a tree whose leaves correspond to a symbol and minimizes the overall length of the encoding,

```
$cost\text{ tree} = \sum_{i=1}^{d} f_i \cdot (depth\text{ of } i^{th}\text{ symbol in tree})$
```

(the number of bits required for a symbol is exactly its depth in the tree).

There is another way to write this cost function that is very helpful. Although we are only given frequencies for the leaves, we can define the frequency of any internal node to be the sum of the frequencies of its descendants; this is, after all, the number of times the internal node is visited during encoding or decoding. During the encoding process, each time we move down the tree, one gets bit output for every node through which we pass. cost—the total number of bits which are output—can also be expressed as:

The cost of a tree is the sum of the frequencies of all leaves and internal nodes, except the root.

The first formulation of the cost function tells us that the two symbols with the smallest frequencies must be at the bottom of the optimal tree, as children of the lowest node (since the tree is full). Otherwise, swapping these two symbols with whatever is lowest in the tree would improve the encoding. This suggests that we start constructing the tree greed: find the two symbols with smallest frequencies, say $i$ and $j$, and make them children of a new node, which then has $f_i + f_j$. To keep the notation simple, let's assume these are $f_1$ and $f_2$. By the second formulation of the cost function, any tree in which $f_1$ and $f_2$ are sibling-leaves has the cost for a tree with $n-1$ leaves of frequencies $(f_1 + f_2), f_3, \dots, f_n$;

![](img/3dd1f1364df8f87b80683fc32a15b999_152_0.png)

The latter problem is just a smaller version of the one we started with. So we pull $f_1$ and $f_2$ off the list of frequencies, insert $(f_1 + f_2)$, and loop. The resulting algorithm can be described in terms of priority queue operations (defined on page 109) and takes $O(n \log n)$ time if a binary tree is used.

```
procedure Huffman(f)
Input: An array $f[1\dots n]$ of frequencies
Output: $H$: An encoding tree with $n$ leaves
```

```
let $H$ be a priority queue of integers, ordered by $f$
for $i = 1$ to $n$: insert$(H,i)$
for $k = n+1$ to $2n-1$:
  $i = deletemin(H)$, $j = deletemin(H)$
  create a node $k$ with children $i, j$
  $f[k] = f[i] + f[j]$
  insert$(H,k)$
```
