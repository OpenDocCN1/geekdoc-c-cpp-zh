Such constraints are conveniently represented by a directed graph in which each task is a node, and there is an edge from $u$ to $v$ if $u$ is a precondition for $v$. In other words, before performing a task, all the tasks pointing to it must be completed. If the other graph has a cycle, there is no hope; no ordering can possibly work. If the other graph is a dag, we would like if possible to linearize (or topologically sort) it, to order the vertices one after the other such that each edge goes from an earlier vertex to a later vertex, so that precedence constraints are satisfied. In Figure 3.8, for instance, one valid ordering suggests B, A, D, C, E, F. (Can you spot the other three?)

What types of dags can be linearized? Simple: All of them. And again depth-first search tells us exactly how to do it: simply perform tasks in decreasing order of their post numbers. After all, the only edges $(u, v)$ in a graph for which post(u) < post(v) are back edges—and we have seen that a dag cannot have back edges. Therefore:

+   * In a dag, every edge leads to a vertex with a larger post number.

This gives us a linear-algorithm for ordering the nodes of a dag. And, together with our early observations, it tells us that three different-sounding properties—acyclicity, linearizability, and the absence of back edges during a depth-first search—are in fact one and the same.

Since a dag is linearized by decreasing post numbers, the vertex with the smallest post number comes last in this linearization, and it is a sink—no outgoing edges. Symmetrically, the one with the highest post number, a node with no incoming edges.

Every dag has at least one source and at least one sink.
