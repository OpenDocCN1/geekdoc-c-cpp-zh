Now, go through this sorted list, and for each point, compute its distance to subsequent points in list. Let $p_M, q_M$ be the closest pair found. ## 3. Decompositions of graphs

### 3.1 Why graphs?

A wide range of problems can be expressed with clarity and precision in the concise pictorial language of graphs. For instance, consider the task of coloring a political map. What is the minimum number of colors needed, with the obvious restriction that neighboring countries should have different colors? One of the difficulties in attacking this problem is that the map itself, even a stripped-down version like Figure 3.1(a), is usually cluttered with irrelevant information: intricate boundaries, border posts where three or more countries meet, open seas, and meandering rivers. Such distractions are absent from the mathematical map of Figure 3.1(b), a graph with vertex for each country (1 is Brazil, 2 is Argentina) and edges between neighbors. More precise goal is now to assign a color to each vertex so that no edge has endpoints of the same color.

Graph coloring is not the exclusive domain of map designers. Suppose a university needs to schedule examinations for all its classes and wants to use the fewest time slots. The only constraint is that two exams cannot be scheduled concurrently if one student will be both of them. To express this problem as a graph, use one vertex for each exam and put an edge between two vertices if there is a conflict, that if there is somebody taking both exam endpoints. Each time slot has its own color. Then, assigning time slots is exactly the same as coloring this graph!

Some basic operations on graphs arise with such frequency, and in such a diversity of contexts, that lot of effort has gone into finding efficient procedures for them. This chapter is devoted to some fundamental properties of graphs. Formally, a graph is specified by a set of vertices $V$ and edges $E$. When the graph is undirected, this has a symmetry: $(u, v)$ is an edge if and only if $(v, u)$ is an edge. When the graph is directed, an edge is an ordered pair $(u, v)$, and we say there is an edge from $u$ to $v$.

How big is your graph?

One way to represent a graph is the adjacency matrix, an $n \times n$ array whose
$a_{ij} = \begin{cases} 1 & \text{if there is an edge from } i \text{ to } j \\ 0 & \text{otherwise} \end{cases}$
For undirected graphs, this matrix is symmetric. The biggest convenience of this format is that a particular edge can be checked in constant time, with one memory access. On the other hand the matrix takes up $O(n^2)$ space, which is wasteful if the graph does not have many edges.

An alternative representation, with size proportional to the number of edges, is the adjacency list. It consists of $|V|$ linked lists, one per vertex. The linked list for vertex $u$ holds the names of vertices to $u$ has an outgoing edge—that is, vertices $v$ for $(u, v) \in E$. Therefore, each edge appears in one of the linked lists if the graph is directed or two if the graph is undirected. Either way, the total size of data is $O(E)$. Checking for a edge $(u, v)$ is no constant time, because it requires sitting through $u$'s adjacency list. But it is easy to iterate through all neighbors of $v$ (by running down the corresponding linked list), and, as we shall soon see, this turns out to be a very useful operation in graph algorithms. Again, for undirected graphs, this representation has a symmetry of lists: $v$ is in $u$'s adjacency list if and only if $u$ is in $v$'s adjacency list.
