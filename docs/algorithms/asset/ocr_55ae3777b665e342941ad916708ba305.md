# Which heap is best?

The running time of Dijkstra's algorithm depends heavily on the priority queue implementation. Here are the typical choices.

| Implementation | delete | insert/ decreasekey | |V| × delete + (|V| + |E|) × insert |
|---|---|---|---|
| Array | O(|V|) | O(1) | O(|V|^2) |
| Binary heap | O(log |V|) | O(log |V|) | O((|V| + |E|) log |V|)|
| d-array heap | O(log |V| / log d) | O(log |V| / log d) | O((|V| - d + |E|) log |d)|
| Fibonacci heap | O(log |V|) | O(1) (amortized) | O(log |V| + |E|)|

For instance, a naive array heap gives a respectable time complexity of O(|V|^2), whereas a binary heap gets O(|V| + |E|). Which is preferable?

This depends on whether the graph is sparse (has few edges) or dense (lots of them). For all graphs, |E| is less than |V|^2. If it is Ω(|V|^2), then the array implementation is the faster. On the other hand, the binary heap becomes preferable as |E| dips below |V|^2/|V|.

The d-ary heap is a generalization of the binary heap (which corresponds to d=2) and leads to a running time that is a function of d. The optimal choice is d ≈ |E|/|V|; in other graphs, to optimize we must set the degree of the heap to be equal to the average degree of the graph. This works well for both sparse and dense graphs. For very sparse graphs, where |E| = O(|V|), the running time is O(|V|log|V|), as good as with a binary heap. For dense graphs, |E| = Ω(|V|^2) and the running time is O(|V|^2), as good with a linked list. Finally, for heaps with intermediate degree |E| = |V|^(1+k), the running time is O(|E|), linear.

The last line in date gives times using a sophisticated data structure called a Fibonacci heap. Although its efficiency is impressive, this data structure requires considerably more work to implement than the others, and this tends to dampen its appeal in practice. We will say little about it except to mention a curious feature of its bounds. Its insert operations taking amount of time are guaranteed to O(1) over the course of the algorithm. In such situations (one of which we will encounter in Chapter 5) we say the amortized cost of insert is O(1).

An insert or decreasekey is fast, because it involves adjusting a key value, an O(1) operation. To deletemin, on the other hand, requires a linear-time scan of the list.
