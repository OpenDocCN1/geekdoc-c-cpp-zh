# Efficiency analysis

Naturally, the running time of our algorithm depends on the random choices of v. It is possible that due to persistent bad luck we picking v to be the largest of the array (the smallest element), and thereby shrink the array by only one element time. In the earlier example, we first pick v = 36, and so on. This worst-case scenario would force our selection to perform

```
$n + (n-1) + (n-2) + \dots + \frac{n}{2} = \Theta(n^2)$
```

operations (when computing the median), but it is extremely unlikely to occur. Only when each randomly chosen v happens to split the array perfectly in half, resulting in a running time of O(n). Where, in this spectrum from O(n) to Θ(n²), does the average running time lie? Fortunately, it lies close to the best-case time.

To distinguish between lucky and unlucky choices of v, we will call v good if it lies within the 25th to 75th percentile of the array that it is. We like these choices of v because they ensure that the subsets $S_L$ and $S_R$ have size three-fourths of $S$ (do you see why?), that the array shrinks substantially. Fortunately, random v's are abundant: half the elements of any list must fall between the 25th to 75th percentile!

Given that a randomly chosen v has a 50% chance of being good, how may v's do we need to pick on average before getting a good one? Here's a more familiar reformulation (see also Exercise 1.34):

**Lemma** On a fair coin needs to be tossed twice before a "heads" is seen.

Proof. Let E be the expected number of tosses before a heads is seen. We certainly need at least one toss, and if it's heads, we're done. If it's tails (which occurs with probability 1/2), we need to repeat. $E = 1 + \frac{1}{2}E$, which works out to $E = 2$.

Therefore, after two split operations on average, the array will shrink to at most three-fourths of its size. Letting $T(n)$ be the expected time on an array of size n, we get

```
$T(n) \leq T(3n/4) + O(n)$.
```

This follows by taking expected values of both of the following statement:

Time taken on an array of size n

$\leq$ (time taken on an array of size $3n/4$) + (time to reduce array size to $\leq 3n/4$),

and, for the right-hand side, using the familiar property that the expectation of the sum is the sum of the expectations.
