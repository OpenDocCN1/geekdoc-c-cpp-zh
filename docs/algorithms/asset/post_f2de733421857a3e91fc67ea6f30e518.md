## More careful analysis

In discussion so far, we have been counting the number of basic computer steps executed by each algorithm and thinking of these basic steps as taking a constant amount of time. This is a very useful simplification. After all, a processor's instruction set has variety of basic primitives—branching, memory access, comparing numbers, simple arithmetic, and so on—rather than distinguishing between these operations, it is far more convenient to lump them together into one.

But looking back at our treatment of Fibonacci algorithms, we have been too liberal with what we consider a basic step. It is reasonable to treat addition as a single step if small numbers are being added, say 32-bit numbers. The $n$th Fibonacci number is about $n$ bits long, and this can exceed 32 as $n$ grows. To better appreciate the importance of this dichotomy between exponential and polynomial algorithms, the reader may want to peek ahead to the story in Chapter 8. Arithmetic operations on arbitrarily large numbers cannot possibly be performed in a constant-time step. We need to audit our earlier running time estimates and make them honest.

## 0.3 Big-O notation

We've just seen how looseness in analysis can lead to an unacceptable level of inaccuracy. Saying $f=O(g)$ is a very loose analog of $f \le g$. It differs from the constant $c$, so for instance $10n=O(n)$. This also allows us to disregard what happens for small values of $n$. For example, suppose we are choosing between two algorithms for a particular computational task. One takes $f_1(n)=n^2$ steps, while the other takes $f_2(n)=2n+20$ steps (Figure 0.2). Which is better? Well, this depends on the value of $n$. For $n \le 5$, $n^2$ is smaller; and thereafter, $2n+20$ is the clearer winner. In this case, $f_2$ scales much better than $n$, and therefore it is superior.

This superiority is captured by the big-O notation: $f_2 = O(f_1)$, because

$$\frac{f_2(n)}{f_1(n)} = \frac{2n+20}{n^2} \le 2$$

for all $n$; on the other hand, $f_1 \neq O(f_2)$, since the ratio $f_1(n)/f_2(n) = n^2/(2n+20)$ can be arbitrarily large, and no constant $c$ will make the definition work.

An insightful analysis is based on this. In what follows, think of $f(n)$ and $g(n)$ as the running times of two algorithms on inputs of size $n$. It is time to define this notation precisely. Let $f(n)$ and $g(n)$ be functions from positive integers to positive reals. We say $f=O(g)$ (which means that "$f$ grows faster than $g$") if there is a constant $c > 0$ such that $f(n) \le c \cdot g(n)$. Another algorithm comes along, one that uses $f_3(n) = n+1$ steps. Is this better than $f_2$? Certainly, but only by a constant factor. The discrepancy between $2n+20$ and $n+1$ is tiny compared to the huge gap between $n^2$ and $2n+20$. In order to stay focused on the big picture, we treat functions as if they differ only by multiplicative constants.

Returning to definition of big-O, we see that $f_2 = O(f_3)$:

$$\frac{f_2(n)}{f_3(n)} = \frac{2n+20}{n+1} \le 22$$

and of course $f_3 = O(f_2)$, this time with $c = 1$.

As $O()$ is an analog of $\le$, we can also define analogs of $\ge$ and $\Theta$ as follows: In the preceding example $f_2 = \Theta(f_1)$ and $f_1 = \Omega(f_3)$. Big-O notation lets us focus on the picture. With a complicated function like $n^2 + 4n + 5$, we just replace it with $O(n^2)$, because the quadratic portion dominates the rest. Here are some rules that help simplify functions by omitting terms:

- Multiplicative constants can be omitted.
- $n^a$ dominates $n^b$ if $a > b$.
- Any exponential dominates any polynomial.
- Likewise, any polynomial dominates any logarithmic.

Don't misunderstand this attitude. Programmers and developers are very interested in what would gladly make an algorithm faster by a factor of 2. But understanding algorithms would be impossible without big-O notation.

0.2. Show that, if $c$ is a positive number, then $g(n) = 1 + c + c^2 + \dots + c^n$ is:

- (a) $\Theta(1)$ if $c < 1$.
- (b) $\Theta(n)$ if $c = 1$.
- (c) $\Theta(c^n)$ if $c > 1$.

The moral: in big-terms, the sum of a geometric series is simply the first term if the series is strictly decreasing, the last term if the series is strictly increasing, and the number of terms if the series is unchanging.

0.4. Is there a faster way to compute the $n$th Fibonacci number than by fib2 (page 4)? One idea involves matrices. We start by writing the equations $F_1 = F_1$ and $F_2 = F_0 + F_1$ in matrix notation:

$$\begin{pmatrix} F_1 \\ F_2 \end{pmatrix} = \begin{pmatrix} 0 & 1 \\ 1 & 1 \end{pmatrix} \begin{pmatrix} F_0 \\ F_1 \end{pmatrix}$$

Similarly,

$$\begin{pmatrix} F_s \\ F_{s+1} \end{pmatrix} = \begin{pmatrix} 0 & 1 \\ 1 & 1 \end{pmatrix} \begin{pmatrix} F_{s-1} \\ F_s \end{pmatrix} = \begin{pmatrix} 0 & 1 \\ 1 & 1 \end{pmatrix}^2 \begin{pmatrix} F_{s-2} \\ F_{s-1} \end{pmatrix}$$

and in general

$$\begin{pmatrix} F_n \\ F_{n+1} \end{pmatrix} = \begin{pmatrix} 0 & 1 \\ 1 & 1 \end{pmatrix}^n \begin{pmatrix} F_0 \\ F_1 \end{pmatrix}$$

So, in order to compute $F_n$, it suffices to raise this $2 \times 2$ matrix, call $X$, to the $n$th power.

- (a) Show that two $2 \times 2$ matrices can be multiplied using 4 additions and 8 multiplications.
