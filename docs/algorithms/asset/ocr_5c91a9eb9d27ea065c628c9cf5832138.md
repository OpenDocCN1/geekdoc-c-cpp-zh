# 3.2 Finding all nodes reachable in undirected graphs

# Figure 3.3 Finding nodes reachable from a particular node.

```
procedure explore(G, v)
Input: G = (V, E) is a graph; v ∈ V
Output: visited(u) is set to true for all nodes u reachable
from v

visited(v) = true
previsit(v)
for each edge (v, u) ∈ E:
    if not visited(u): explore(u)
postvisit(v)
```

is shown in Figure 3.3.1. The revisit and postvisit procedures are optional, meant for performing operations on a vertex when it is first discovered and also when it is being for the last time. We will see some creative uses for them.

More, we need to confirm that explore always works correctly. It does not venture too far, because it moves from nodes to its neighbors and can never jump to a node that is not reachable from v. Does it find all vertices reachable from v? Well, if there is some u that it misses, choose any path from v to u, and the last vertex on that path the procedure actually visits. Call this node z, and let u be the node immediately after it on the same path.

So z was visited but w was not. This was a contradiction: while the explore was at node z, it would have moved to w and moved on to.

Incidentally, this pattern of reasoning arises often in the study of graphs and is in essence a streamlined induction. A more formal inductive proof would start by framing a hypothesis, such as "for any k ≥ 0, all nodes within k hops from v visited." The base case is as usual trivial, since v is visited anyway. The general case—if all nodes k hops away are visited, then so are all nodes k+1 hops away—is precisely the point we just argued.

Figure 3.4 shows the result of running explore on our example graph, starting at node A, and breaking ties in alphabetical order whenever there is a choice of nodes to visit. The solid edges are those that were actually traversed, each of which was visited by a call to explore and led to the discovery of a new vertex.

> *With many of our graph algorithms, this applies to both undirected and directed graphs. In such cases, we adopt the directed notation for edges, (x, y). If the graph is undirected, each of its edges should be thought of as existing in both directions: (x, y) and (y, x).
