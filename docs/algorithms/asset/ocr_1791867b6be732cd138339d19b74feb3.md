piece of bad news about the TSP, which we will better understand in Chapter 8, is that it is highly unlikely to be solvable in polynomial time.

How long does it take, then? Well, the brute-force approach is to evaluate every possible tour and return the best one. Since there are $(n-1)!$ possibilities, this strategy takes $O(n!)$ time. We will see that dynamic programming yields a much faster solution, though not a polynomial one.

What is the appropriate subproblem for the TSP? Subproblems refer to partial tours, and the most obvious partial partial is the initial portion of a tour. Suppose we have started at $i$ as required, have visited a few cities, and are now in $j$. What information do we need in order to extend this particular? We certainly know $j$, since this will determine which cities are most convenient to visit next. And we need to know all the cities visited so far, so that we do not repeat any of them. Here, then, is an appropriate subproblem.

For a subset of cities $S \subseteq \{1, 2, \dots, n\}$ that includes $1$, and $j \in S$, let $C(S, j)$ be the length of the shortest path visiting each node in $S$ exactly, starting at 1 and ending at $j$.

When $|S| > 1$, we define $C(S, 1) = \infty$ since the path cannot start and end at 1.

Now, let's express $C(S, j)$ in terms of smaller subproblems. We need to start at 1 and end at $j$; what should we pick as the second-to-last city? It has to be some $i \in S$, so the overall path length is the distance from 1 to $i$, $C(S - \{j\}, i)$, plus the length of the final edge, $d_{ij}$. We must pick the best $i$:

```
$C(S, j) = \min_{i \in S \neq j} C(S - \{j\}, i) + d_{ij}$.
```
