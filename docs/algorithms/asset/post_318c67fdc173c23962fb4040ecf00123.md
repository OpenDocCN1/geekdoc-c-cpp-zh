
## Recursion? No, thanks.

Returning to our discussion of longest increasing subsequences: the formula for $L(j)$ also suggests an alternative, recursive algorithm. Wouldn't that be even simpler?

Actually, recursion is a very bad idea: the resulting procedure would require exponential time! To see why, suppose the dag contains edges $(i, j)$ for all $i < j$—that is, the given sequence of numbers $a_1, a_2, \dots, a_n$ is sorted. In that case, the formula for subproblem $L(j)$ becomes

```
$L(j) = 1 + \max\{L(1), L(2), \dots, L(j-1)\}$
```

The following figure unveils the recursion for $L(5)$. Notice that the same subproblems are solved over and over again!

![](img/3dd1f1364df8f87b80683fc32a15b999_170_0.png)

For $L(n)$ this tree has exponentially many nodes (you can bound it?), and so a recursive solution is disastrous.

Then did recursion work so well with divide-and-conquer? The key point is that in divide-and-conquer, a problem is expressed in terms of subproblems that are substantially smaller, half the size. For instance, mergesort sorts an array of size $n$ by recursively sorting two subarrays of size $n/2$. Because of this sharp drop in problem size, the recursion tree has only logarithmic depth and a polynomial number of nodes.

In contrast, in a typical dynamic programming problem, a problem is reduced to subproblems that are only slightly smaller—for instance, $L(j)$ relies on $L(j-1)$. Thus the full recursion tree generally has polynomial depth and an exponential number of nodes. However, it turns out that most of these nodes are repeats, that there are not too many distinct subproblems among them. Efficiency is therefore obtained by explicitly enumerating the distinct subproblems and solving them in the right order.

## Programming?

The origin of the term dynamic programming has very little to do with writing code. It was first coined by Richard Bellman in the 1950s, a time when computer programming was an esoteric activity practiced by so few people as to even merit a name. Back then programming “planning,” and “dynamic programming” were conceived to optimally multistage processes. The dag of Figure 6.2 can be thought of as describing the possible ways in which such a process can evolve: each node denotes a state, the leftmost node is the starting point, and the edges leaving a state represent possible actions, leading to different states in the next unit of time.

## 6.3 Edit distance

three smaller subproblems $E(i-1, j), E(i, j-1), E(i-1, j-1)$. We have no idea which of them is the right, so need to try all and pick the best:

```
$E(i, j) = \min\{1+E(i-1, j), 1+E(i, j-1), \text{diff}(i, j)+E(i-1, j-1)\}$
```

where $\text{diff}(i, j)$ is defined to be 0 if $x[i]=y[j]$ and 1 otherwise.

For instance, computing the edit distance between EXPONENTIAL and YOMIAL, $E(4,3)$ must be one of three:

$E(4,3) = \min\{1+E(3,3), 1+E(4,2), \text{diff}(4,3)+E(3,2)\}$

where $E(4,3)$ corresponds to the rightmost column. Thus, $E(i, j)$ form a two-dimensional table, as in Figure 6.4. In what order should these subproblems be solved? Any order is fine, as long as $E(i-1, j), E(i, j-1)$ are handled before $E(i, j)$. Both methods fill the table row by row, left to right. Alternatively, we could fill it by column. By the time we get around each row, all the subproblems are already solved.

## The underlying dag

Every program has an underlying dag structure: think of each node representing a subproblem. In our edit distance, the nodes of the underlying dag correspond to positions $(i, j)$. Its edges are the precedence constraints, of the form $(i-1, j) \to (i, j)$, $(i, j-1) \to (i, j)$, and $(i-1, j-1) \to (i, j)$ (Figure 6.5). To see this, set all edge lengths to 1 so that the edit distances match 0. The final answer is then simply the distance between nodes $s=(0,0)$ and $t=(m, n)$.

By altering the weights on this dag, we can also generalize forms of edit distance, in which insertions, deletions, and substitutions have different costs.

## 6.4 Knapsack

During a robbery, a burglar finds much more than he had expected and decides what to take. The bag (or "knapsack") will hold a total weight of at most W. There are n items to pick from, of weight $w_1, \dots, w_n$ and dollar value $v_1, \dots, v_n$. What's the most valuable combination of items he can fit into his bag?
