Any oil transmitted must pass from L to R. Therefore, no flow can possibly exceed the total capacity of the edges from L to R, which is 7. This means that the flow we found earlier, of size 7, must be optimal!

More generally, an (s, t)-cut partitions the vertices into two disjoint groups L and R that s is in L and t is in R. Its capacity is the total capacity of the edges from L to R, and as argued previously, is an upper bound on any flow:

Pick any flow f and any (s, t)-cut (L, R). Then size (f) $\le$ capacity(L, R).

Some cuts are large and give looser upper bounds—cut{s, b, c}, {a, d, e, t} has a capacity of 9. But there is also a cut of 7, which is effectively a certificate of optimality of the maximum flow.

# Max-flow min-cut theorem:

The size of the maximum flow in a network equals the capacity of the smallest (s, t)-cut. Moreover, our algorithm automatically finds this cut as a byproduct!

Let's see why this is true. Suppose f is the final flow when the algorithm terminates. We know that t is no longer reachable from s in the residual network $G^f$. Let L the nodes that are reachable from s in $G^f$, and R = $V - L$ be rest of the nodes. Then (L, R) is a cut in the graph G:

![](img/3dd1f1364df8f87b80683fc32a15b999_214_0.png)

We claim that size(f) = capacity(L, R). To see this, observe by the way L is defined, any edge going from L to R must be at capacity (in the current flow), and any edge from R to L must have zero flow. (So, in the figure, $f_e = c_e$ and $f_e = 0$.) Therefore the net flow across (L, R) is exactly the capacity of the cut.

## 7.2.5 Efficiency

Each iteration of our maximum-flow algorithm is efficient, running $O(|E|)$ time if a depth-first or breadth-first search is used to find an s-t path. But how many iterations are there?

Suppose all edges in the original network have integer capacities $\le C$. Then an inductive argument shows that on each iteration of the algorithm, the flow is always an integer and increases by an integer. Therefore, if the maximum flow is at most $C$, it follows that the number of iterations is at most $C$. This is hardly a rewarding bound: what if C is in the millions?

We examine this issue further in Exercise 7.3. It turns out that it is possible to construct bad examples in the way the number of iterations is proportional to $C$, if s-t paths are not carefully chosen. If paths are chosen in a sensible manner—in particular, by a breadth-first search, which finds the path with the fewest edges—the number of iterations is at $O(|V| \cdot |E|)$ no matter what the capacities are.

## 7.3 Bipartite matching

Figure 7.7 shows a graph with four nodes on the left representing boys and four nodes on the right representing girls. There is an edge between a boy and girl if they like each other (for instance, Al likes all the girls). Is it possible to choose couples so that everyone has exactly one partner, and is it someone? In graph-theoretic jargon, is there a perfect matching?

| BOYS | GIRLS |
| :--- | :--- |
| Al | Alice |
| Bob | Beatrice |
| Chet | Carol |
| Dan | Danielle |

This matching can be reduced to the maximum-flow problem, and thereby to linear programming. Create a new source node, s, with outgoing edges to all the boys; a new sink node, t, with incoming edges from all the girls; and direct all the edges in the original bipartite graph from boy to girl (Figure 7.8). Finally, give every edge a capacity of 1. Then there is a perfect matching if and only if this network has a flow whose size equals the number of couples. Can you find such a flow in the example?

Actually, the situation is slightly more complicated than just stated: it is easy to see that the optimum-valued flow corresponds to the optimum matching.

> This kind of graph, in which the nodes can be partitioned into two groups such that all edges are between the groups, is called bipartite.

We would be at a bit of a loss interpreting a flow that shifts 0.7 units along the edge Al-Carol, for instance! Unfortunately, the maximum-flow problem has the following **Property:** if all edge capacities are integers, the optimal flow found by our algorithm is integral. We can see this directly from the algorithm, which in such cases would increase the flow by an integer amount on each iteration.

Integrality comes free in the maximum-flow problem. Unfortunately, this is the exception rather than the rule: as we will see in Chapter 8, it is a very difficult problem to find the optimum solution (or for matter, any solution) of a general linear program, if we also demand that the variables are integers.

## 7.4 Duality

We have seen that in networks, flows are smaller than cuts, but the maximum flow and min cut coincide and is therefore a certificate of the other's optimality. Remarkable as this phenomenon is, we generalize it from maximum flow to *any* problem that can be solved by linear programming! It turns out that every linear maximization problem has a *dual minimization* problem, and they relate to each other in the same way as flows and cuts.
