Its running time is linear in the sizes of these numbers, in other words $O(n)$, where $n=\lceil\log N\rceil$ is the size of $N$; as a reminder, we choose to use the letter $n$ to denote input size.

To multiply two $N$ numbers $x$ and $y$, we again start with rough multiplication and then reduce the answer modulo $N$. The product can be as large as $(N-1)^2$, but this is at most $2n$ bits since $\log(N-1)^2=2\log(N-1) \le 2n$. To reduce the answer modulo $N$, we compute the remainder by dividing it by $N$, using our quadratic division algorithm. Multiplication then remains a quadratic.

Division is not quite so. In ordinary arithmetic there is just one tricky case—division by zero. It turns out that in modular arithmetic there are potentially other such cases as well, which we will characterize at the end of this section. Whenever division is legal, it can be managed in cubic time, $O(n^3)$.

To complete the result we need next turn to modular exponentiation, and then to the greatest common divisor, which is the key to division. For both tasks, the most obvious procedures take exponentially long, but with ingenuity polynomial-time solutions can be found. A careful choice of algorithm makes all the difference.

### 1.2.2 Modular exponentiation

In the cryptosystem we are working at, it is necessary to compute $x^y$ mod $N$ for values of $x, y$, and $N$ that are several hundred bits long. Can this be done quickly?

The result is some number modulo $N$ and is itself a few hundred bits long. however, the value of $x^y$ can be much, much longer than that. Even when $x$ and $y$ are 20-bit numbers, $x^y$ is at least $2^{(20^{20})}=2^{(10485760000)}$, about 10 million bits long! What happens if $y$ is a 500-bit number?

To make sure we are dealing with numbers not too large, we need to perform all intermediate computations modulo $N$. So here's an idea: calculate $x^y$ mod $N$ by repeatedly multiplying $x$ modulo $N$. The resulting sequence of intermediate products,

```
$x \mod N \rightarrow x^2 \mod N \rightarrow x^3 \mod N \rightarrow \dots \rightarrow x^y \mod N$.
```

consists of numbers that are smaller than $N$, and the individual multiplications do not take too long. But there's a problem: if $y$ is 500 bits long, we need to perform $y-1 \approx 2^{500}$ multiplications! This algorithm is exponentially slow in the size of $y$.

Luckily, we can do better: starting with $x$ and squaring repeatedly modulo $N$, we get

```
$x \mod N \rightarrow x^2 \mod N \rightarrow x^4 \mod N \rightarrow x^8 \mod N \rightarrow \dots \rightarrow x^{2^{(\log y)}} \mod N$.
$.```

Each takes $O(\log^2 N)$ time to compute, and in this case there are only $y$ multiplications. To determine $x^y \mod N$, we simply multiply an appropriate subset of these powers, those corresponding to 1's in the binary representation of $y$. For instance,

```
$x^{25} = x^{1000} \cdot x^{1002} \cdot x^1 = x^{16} \cdot x^8 \cdot x^1$.
```

A polynomial-time algorithm is finally within reach!

**Figure 1.4** Modular exponentiation.

```
function modexp(x, y, N)
Input: Two $n$-bit integers $x$ and $N$, an integer exponent $y$
Output: $x^y \mod N$

if y = 0: return 1
z = modexp(x, y/2, N)
if y is even:
	return $z^2 \mod N$
else:
	return $x \cdot z \mod N$
```

We package this idea in a particularly simple form: the recursive algorithm of Figure 1.4, which works by executing, the self-evident rule

```
$x^y = \begin{cases} (x^{(y/2)})^2 & \text{if } y \text{ is even} \\ x \cdot (x^{(y/2)})^2 & \text{if } y \text{ is odd.} \end{cases}$
```

In so, it closely parallels the recursive multiplication algorithm (Figure 1.1). For instance, that algorithm would compute the product $x \cdot 25$ by an analogous decomposition to the one we just saw: $x \cdot 25 = x \cdot 16 + x \cdot 8 + x \cdot 1$. Whereas for multiplication the terms $x \cdot 2'$ come from repeated doubling, for exponentiation the corresponding terms $x^{2'}$ are generated by repeated squaring.

Let $n$ be the size in bits of $x$, $y$, and $N$ (whichever is largest of them). As with multiplication, the algorithm will halt after $n$ recursive calls, and during each call it multiplies $n$-bit numbers (computing modulo $N$ saves us here), for a running time of $O(n^2)$.

### 1.2.3 Euclid's algorithm for greatest common divisor

Our next was discovered well over 2000 years ago by the mathematician Euclid, in ancient Greece. Given two integers $a$ and $b$, it finds the largest integer that divides both of them, known as their greatest common divisor (gcd).

The most obvious approach is to first factor $a$ and $b$, and then multiply together their common factors. For instance, $1035 = 3^2 \cdot 5 \cdot 23$ and $759 = 3 \cdot 11 \cdot 23$, that

gcd = $3 \cdot 23 = 69$. However, we have no efficient algorithm for factoring. Is there some other way to compute greatest common divisors?

Euclid's algorithm uses the following simple formula.

Euclid's rule If $x$ and $y$ are positive integers with $x \geq y$, then gcd(x, y) = gcd(x \mod y).

Proof. It is enough to show the slightly simpler rule gcd(x, y) = gcd(x - y), from which the one stated can be derived by repeatedly subtracting $y$ from $x$.

Here goes. Any integer that divides both $x$ and $y$ must also divide $x - y$, so gcd(x, y) \leq gcd(x - y)$. Likewise, any integer that divides both $x - y$ and $y$ must divide both $x$ and $y$, so gcd(x, y) \geq gcd(x - y, y).

Figure 1.5 Euclid's algorithm for finding the greatest common divisor of two numbers.

```
function Euclid(a,b)
Input: Two integers $a$ and $b$ with a $a \geq b \geq 0$
Output: gcd(a,b)
```

```
if b = 0: return a
return Euclid(b, a mod b)
```

Euclid's rule allows us to write down its correctness. In order to figure out its running time, we need to understand how quickly (a, b) decrease with each recursive call. If they are initially n-bit integers, the base case will be reached within $n$ calls. And each call invokes a quadratic-time division, the total time is $O(n^2)$.
