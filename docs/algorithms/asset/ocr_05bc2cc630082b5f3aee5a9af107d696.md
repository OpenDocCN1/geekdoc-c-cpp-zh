# Unsolvable problems (Continued )

Notice what paradox does: it terminates if and only if program does not terminate given its own code as input.

You should smell trouble. What if we put this program in a file named paradox and we executed paradox(paradox)? This execution would error? Or? Neither answer is possible. Since we arrived at this contradiction by assuming there is an algorithm for telling we programs, we must conclude that this problem cannot be solved by any algorithm.

By this way, all it tells us important about programming: It will never be automated, it will forever depend on discipline, ingenuity, and hackery. We now know that you can't tell whether a program has an infinite loop. But can you tell if it has a buffer overrun? Do you see how to use the unsolvability of the “halting problem” to show that this, too, is unsolvable?

# Exercises

+   8.1. Optimization vertex search. Recall the traveling salesman problem:

+   TSP
Input: A matrix of distances; a budget b
Output: A tour which passes through all the cities and has length ≤ b, such a tour exists.

The optimization version of this problem asks directly for the shortest tour.

+   TSP-OPT
Input: A matrix of distances
Output: The shortest tour which passes through all cities.

Show that if TSP can be solved in polynomial time, then so TSP-OPT.
