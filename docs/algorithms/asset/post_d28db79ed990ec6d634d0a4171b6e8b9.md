
## The unix Sort command

Comparing the algorithms for sorting and median-finding we notice that, beyond the common divide-and-conquer philosophy and structure, they are exact opposites. Mergesort splits the array in the most convenient way (first half, second half), without any regard to the magnitudes of the elements in each half; but then it works until the subarrays are sorted. In contrast, the median algorithm is careful about its splitting (smaller numbers first, then the larger ones), but its work ends with the recursive call.

Quicksort is a sorting algorithm that splits the array in exactly the same way as the median algorithm; and once the subarrays are sorted, by two recursive calls, there is nothing more to do. Its worst-case performance is $\Theta(n^2)$, like that of median-finding. But it can be proved (Exercise 2.24) that its average case is $O(n \log n)$; furthermore, empirically it outperforms other sorting algorithms. This has made quicksort a favorite in many applications—instance, it is the basis of the code by which enormous files are sorted.

From this recurrence we conclude that $T(n) = O(n)$: on any input, our algorithm returns the correct answer after a linear number of steps, on the average.

## 2.5 Matrix multiplication

The product of two $n \times n$ matrices $X$ and $Y$ is a third $n \times n$ matrix $Z = XY$, with $(i, j)$th entry

$Z_{ij} = \sum_{k=1}^{n} X_{ik}Y_{kj}$

To make it more visual, $Z_{ij}$ is the dot product of the $i$th row of $X$ with the $j$th column of $Y$:

![](img/3dd1f1364df8f87b80683fc32a15b999_66_0.png)

In general, $XY$ is not the same as $YX$; matrix multiplication is not commutative. The preceding formula implies an $O(n^3)$ algorithm for matrix multiplication: there are $n^2$ entries to be computed, and each takes $O(n)$ time. For a while, this was widely believed to be the best running time possible, and it even proved that in certain models of computation no algorithm could do better. It was therefore a source of great excitement when in 1969, the German mathematician Volker Strassen announced a significantly more efficient algorithm, based upon divide-and-conquer.

Matrix multiplication is particularly easy to break into subproblems, because it can be performed blockwise. To see what this means, carve X into $n/2 \times n/2$ blocks, and also Y:

```
$X = \begin{bmatrix} A & B \\ C & D \end{bmatrix}, \quad Y = \begin{bmatrix} E & F \\ G & H \end{bmatrix}$
```

Then their product can be expressed in terms of these blocks and is exactly as if the blocks were single elements (Example 2.11).

```
$XY = \begin{bmatrix} A & B \\ C & D \end{bmatrix} \begin{bmatrix} E & F \\ G & H \end{bmatrix} = \begin{bmatrix} AE+BG & AF+BH \\ CE+DG & CF+DH \end{bmatrix}$
```

We have a divide-and-conquer strategy: to recursively compute eight $n/2$ products $AE, BG, AF, BH, CE, DG, CF, DH$, and then do a $O(n^2)$-time additions. The total running time is described by the recurrence relation

```
$T(n) = 8T(n/2) + O(n^2)$
```

This comes out to an unimpressive $O(n^2)$, the same as for the default algorithm. But if the efficiency can be further improved, and as with integer multiplication, the key is some clever algebra. It turns out $XY$ can be decomposed from seven $n/2 \times n/2$ subproblems, by a decomposition strategy that is intricate and that Strassen was able to discover it!

```
$XY = \begin{bmatrix} P_3+P_4-P_2+P_6 & P_1+P_3 \\ P_3+P_4 & P_1+P_5-P_3 \end{bmatrix}$
```

where

```
$P_1 = A(F-H) \quad P_5 = (A+D)(E+H)$
$P_2 = (A+B)H \quad P_6 = (B-D)(G+H)$
$P_3 = (C+D)E \quad P_7 = (A-C)(E+F)$
$P_4 = D(G-E)$
```

The new running time is

```
$T(n) = 7T(n/2) + O(n^2)$
```

which by the master theorem works out to $O(n^{\log_2 7}) \approx O(n^{2.81})$.

## 2.6 The fast Fourier transform

We have seen so far divide-and-conquer gives fast algorithms for multiplying integers and matrices; our next target is polynomials. The product of two degree-d polynomials is a polynomial of degree $2d$, for example:

```
$(1+2x+3x^2) \cdot (2+x+4x^2) = 2+5x+12x^2+11x^3+12x^4$
```

More generally, if $A(x) = a_0 + a_1x + \dots + a_dx^d$ and $B(x) = b_0 + b_1x + \dots + b_dx^d$, their product $C(x) = c_0 + c_1x + \dots + c_{2d}x^{2d}$ has coefficients

```
$c_k = \sum_{i+j=k} a_ib_j$
```

(for $0 \le k \le 2d$).

To compute the coefficients of $C(x)$, we could use $O(d^2)$ time. But can we do better? The answer is to evaluate $A(x)$ and $B(x)$ at $2d+1$ points, multiply the values at each point, and then interpolate to find $C(x)$. However, evaluation and interpolation generally take $O(d^2)$ time. If we choose the points wisely, we can achieve much better complexity. The key is to use the roots of unity.

The $n$-th roots of unity are the solutions to $x^n = 1$, given by

$\omega^k = e^{2\pi i k / n}$ for $k=0, 1, \dots, n-1$.

These points have several properties:
- $(\omega^k)^n = 1$
- $\omega^{k+n/2} = -\omega^k$ (if $n$ is even)
- $\omega^j \cdot \omega^k = \omega^{j+k \pmod n}$

If we evaluate $A(x)$ at $\omega^k$, we get

$A(\omega^k) = \sum_{j=0}^{n-1} a_j (\omega^k)^j = \sum_{j=0}^{n-1} a_j \omega^{kj}$

By splitting the sum into even and odd indices,

$A(\omega^k) = \sum_{j=0}^{n/2-1} a_{2j} \omega^{2jk} + \sum_{j=0}^{n/2-1} a_{2j+1} \omega^{(2j+1)k}$

Let $E(y) = \sum_{j=0}^{n/2-1} a_{2j} y^j$ and $O(y) = \sum_{j=0}^{n/2-1} a_{2j+1} y^j$. Then

$A(\omega^k) = E(\omega^{2k}) + \omega^k O(\omega^{2k})$

For $0 \le k < n/2$, $\omega^{2k}$ are the $n/2$-th roots of unity. Thus we only need to evaluate $E$ and $O$ at $n/2$ points. For $n/2 \le k < n$, $\omega^{2k}$ are the same $n/2$-th roots of unity but in reverse order. This leads to the recurrence $T(n) = 2T(n/2) + O(n)$, which solves to $O(n \log n)$. This is the fast Fourier transform (FFT).

## Why multiply polynomials?

For one thing, it turns out that the fastest algorithms we have for multiplying integers after all, polynomials and binary integers are quite similar. But perhaps more importantly, multiplying polynomials is crucial for signal processing. A signal is any quantity that is a function of time (as in Figure (a)) or position. It might, for instance, capture a human voice by measuring fluctuations in air pressure close to the speaker' mouth, or alternatively, the pattern of stars in the night sky, measuring brightness as a function of angle.

In order to extract information from a signal, we will need to digitize it by sampling (Figure (b)—and, then, to put it through a system that will transform it in some way. The output is called the *response* of the system:

signal $\longrightarrow$ response.

An important class of systems are those that are linear—the response to the sum of signals is just the sum of their individual responses—and time invariant—shifting the input by time $t$ produces the same output, also shifted by $t$. Any system with these properties is characterized by its response to the simplest possible input: the unit impulse $\delta(t)$. To see this, consider the close $\delta(t-i)$, a shifted impulse in which the jerk occurs at time $i$. Any signal $a(t)$ can be expressed as a linear combination of these, letting $\delta(t-i)$ pick out its behavior at time $i$.

| Coefficient representation | Interpolation | Value representation |
|---|---|---|
| $a_0, a_1, \dots, a_d$ | | $A(0), A(1), \dots, A(d)$ |
| $a_0, a_1, \dots, a_d$ | | $A(0), A(1), \dots, A(d)$ |

The output of the system at time $k$ is

$c(k) = \sum_{i=0}^{k} a(i)b(k-i)$,

exactly the formula for polynomial multiplication!
