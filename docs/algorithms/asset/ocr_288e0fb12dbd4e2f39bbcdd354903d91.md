The shortest-path problem is ill-posed in graphs with negative cycles. As might be expected, our algorithm from Section 4.6.1 works only in the absence of such cycles. But where did this assumption appear in the derivation of the algorithm? Well, if we asserted the existence of a shortest path from s to t.

Fortunately, it is easy to automatically detect negative cycles and issue a warning. Such a cycle would allow us to endlessly apply rounds of update operations, reducing dist every time. So instead of stopping after |V| - 1 iterations, perform one extra round. There is a negative cycle if and only some dist value is reduced during this final round.

# 4.7 Shortest paths in dags
