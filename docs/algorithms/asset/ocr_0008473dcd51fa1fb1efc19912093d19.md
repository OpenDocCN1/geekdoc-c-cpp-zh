# 4.4.2 An alternative derivation

Here's a plan for computing shortest paths: expand outward from the starting point
s, steadily growing the region of the graph to which distances and shortest paths are
known. This growth should be orderly, first incorporating the closest nodes and then
moving on to those further away. More precisely, when the "known region" is some
subset of R includes s, the next addition to it should be the node outside
R that is closest to s. Let us call this v; the question is: how do we identify it?

To answer, consider u, the node just before v in the shortest path from s to v

```
s --- u --- V
```

Since we are assuming that all edge lengths are positive, u must be closer to s than v
is means that u is in R—otherwise it would contradict v's status as the closest
node to outside R. So the shortest path from s to v is simply a known shortest
path extended by a single edge.

Figure 4.10 Single-edge extensions of known shortest paths.

![](bbox=[0.1485, 0.4735, 0.6145, 0.6635])

But will typically be many single-edge extensions of the currently known
shortest paths (Figure 4.10); of these identifies v! The answer is, the shortest of
these extended paths. Because, if an even shorter single-edge-extended path existed,
this would more contradict v's status as the node outside R closest to s.
So, it's easy to find v: it is the node outside R for which the smallest value of
distance(s, u) - (u, v) is attained, as u ranges over R. In other words, try any single-
edge of the currently known shortest paths, find the shortest extended
path, and proclaim its endpoint to be the next node of R.
