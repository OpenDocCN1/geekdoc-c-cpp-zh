NP-complete problems

## 8.1 Search problems

Over the past seven chapters we have developed algorithms for finding shortest paths and minimum spanning trees in graphs, matchings in bipartite graphs, maximum increasing subsequences, maximum flows in networks, and so on. All these algorithms are efficient, because in each case their time requirement grows as a polynomial function (such as $n$, $n^2$, or $n!$) of the size of the input.

To better appreciate efficient algorithms, consider the alternative: In all problems we are searching for a solution (path, tree, matching, etc.) from among an exponential population of possibilities. Indeed, $n$ boys can be matched with $n$ girls in $n!$ different ways, a graph with $n$ vertices has $n-2$ spanning trees, and a typical graph has an exponential number of paths from $s$ to $t$. All these could in principle be solved in exponential time by checking all candidate solutions, one by one. But an algorithm whose runtime is $2^n$, or worse, is all useless in practice (see the next book). The quest for efficient algorithms is about finding clever ways to bypass this exhaustive search, using clues from the input in order to dramatically narrow the search space.

So in this book we have seen the most brilliant successes of this quest, algorithmic techniques that defeat the specter of efficiency: greedy algorithms, dynamic programming, linear programming (while divide-and-conquer typically yields faster algorithms for problems we can reliably solve in polynomial time). Now the time has to meet the quest's most embarrassing and persistent failures. We shall see other "search problems," in which we are seeking a solution with particular properties among an exponential chaos of alternatives. But for these new problems no shortcut seems possible. The fastest algorithms we know for them are all efficient—not substantially better than an exhaustive search. We now introduce important examples.

## The story of Sissa and Moore

According to the legend, the game of chess was invented by the Brahmin Sissa to teach him his king. Asked by the grateful monarch what he wanted in return, he requested the king place one grain of rice in the first square of the chessboard, two in the second, four in the third, and so on, and as a result doubling the amount of rice up to the 64th square. The king agreed on the spot, and as a result he the first person to learn the valuable—albeit humbling—lesson of exponential growth. Sissa's request amounted to $2^{64}-1 = 18,446,744,073,709,551$ grains of rice, enough to pave all of India several times over!

All nature, from colonies of bacteria to cells in a fetus, we see systems that grow exponentially—for a while. In 1798, the philosopher T. Robert Maths published an essay in which he predicted that the exponential growth (he called "geometric growth") of the human population would soon deplete growing resources, an argument that influenced Charles Darwin deeply. It would appear that Moore's law provides a disincentive for developing polynomial algorithms. After all if an algorithm is exponential, why not wait until Moore's law makes it feasible? As Sissa and Malthus knew very well, exponential expansion cannot be sustained indefinitely. Bacterial colonies ran out of food; chips hit the atomic scale. Moore’s law will stop the progress of computers within a decade or two. Here an instance of SAT looks like:

```
(x ∨ y) (x ∨ y) (y ∨ z) (z ∨ x) (x ∨ y ∨ z)
```

This is a Boolean formula in conjunctive normal form (CNF). It is a collection of clauses, each consisting of the disjunction of literals, where each literal is either a Boolean variable or its negation. A satisfying assignment is an assignment of false or true to each variable so that every clause contains a literal whose value is true. The sat is the following: given a Boolean formula in conjunctive normal form, either find a satisfying assignment or report that none exists.

In the instance previously mentioned, setting variables to true, for example, satisfies every clause except the last. Is there a truth assignment that satisfies all clauses?

With a little thought

SAT is a typical search problem. We are given an instance I (that is, some input specifying the problem at hand, in this case a Boolean formula in conjunctive normal form), and we are asked to find a solution S (an object that meets a particular specification, in this case an assignment that satisfies each clause). If no such solution exists, we must say so.

More specifically, a search problem has the property that any proposed solution to I can be quickly checked for correctness. Does this entail? For one thing, S must be at least quick to read, with length polynomially bounded by that of I. This is clearly true in the case of sat, for which S is an assignment to the variables. To formalize the notion of quick checking, we will say that there is a polynomial-time algorithm that takes as input I and S decides whether or not S is a solution of I. For sat, this is as easy as it involves checking the assignment specified by S satisfies every clause in I.

Later in this chapter it will be useful to shift your vantage point and think of this efficient algorithm for checking proposed solutions as defining the search problem.
