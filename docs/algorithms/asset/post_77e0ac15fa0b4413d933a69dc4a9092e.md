If $c_i \le 0$, then considering the constraints $x \ge 0$, we can't hope for a better objective value. Conversely, if some $c_i > 0$, the origin is not optimal, since we can increase the objective function by raising $x_i$.

Thus, for task 2, we can move by increasing some $x_i$ for which $c_i > 0$. How much can we increase it? Until we hit some other constraint. That is, we release the constraint $x_i \ge 0$ and increase $x_i$ until some other inequality, relatively loose, becomes tight. At that point, we again have exactly $n$ tight inequalities, so we are at a new vertex.

For instance, suppose we're dealing with the following linear program:

```
$2x_1 + 5x_2 \le 25$
$2x_1 - x_2 \le 4$
$x_1 + 2x_2 \le 9$
$-x_1 + x_2 \le 3$
$x_1 \ge 0$
$x_2 \ge 0$
```

Simplex can be started at the origin, which is specified by constraints (④) and (⑤). To move, we release the tight constraint $x_2 \ge 0$. As $x_2$ is gradually increased, the first constraint runs into $-x_1 + x_2 \le 3$, and thus it has to stop at $x_2 = 3$, at which point this new inequality is tight. The new vertex is given by (③) and (④).

So we know what to do if we are at the origin. But if our current **u** is elsewhere? The trick is to transform **u** into the origin, by shifting the coordinate system from the usual $(x_1, \dots, x_n)$ to the "local view" from **u**. These local coordinates consist of (appropriately scaled) distances $y_1, \dots, y_n$ to the $n$ hyperplanes (inequalities) that define and enclose **u:**

![](img/3dd1f1364df8f87b80683fc32a15b999_225_0.png)

Specifically, if one of these enclosing inequalities is $a_i \cdot x \le b_i$, then the distance from a point **x** to that particular "wall" is

```
$y_i = b_i - a_i \cdot x$.
```

The $n$ equations of this type, one per wall, and this relationship can be inverted to express the $x_i$'s as a linear function of the $y_i$'s. This doesn't fundamentally change it, we can rewrite the LP in terms of $y_i$ without totally change it (for instance, the optimal value stays the same), but it expresses it in a different coordinate frame. The revised "local" LP has the following three properties:

### 7.6 The simplex algorithm

- 1. It includes the inequalities $y \ge 0$, which are simply the transformed versions of the inequalities defining $u$.
- 2. $u$ itself is the origin in $y$-space.
- 3. The cost function $\max c_u + c^Ty$, where $c_u$ is the value of the objective function at $u$ and $c$ is a transformed vector.

In short, we are back to the situation we know how handle! Figure 7.13 shows this algorithm in action, continuing with our earlier example.

The simplex algorithm is now fully defined. It moves from vertex to neighboring vertex, stopping when the objective is locally optimal, that is, when the coordinates of the local cost vector are all zero or negative. As we've seen, a vertex with this property must also be globally optimal. On the other hand, if the current vertex is not locally optimal, its local coordinate system includes some dimension along which the objective function can be improved, we move along this edge of the polyhedron—until we reach a neighboring vertex. By the nondegeneracy assumption (see footnote 3 in Section 7.6.1), this edge has nonzero length, and so strictly improve the objective value. The process must eventually halt.

### 7.6.3 Loose ends

There are important issues in the simplex algorithm that we haven't mentioned.

#### The starting vertex:

How do we find a vertex at start simplex? In our 2D and 3D examples we always started at the origin, which the linear programs happened to have inequalities with positive right-hand sides. In a general LP we won't always be fortunate. However turns out that finding a starting vertex can be reduced to an LP and solved by simplex!

To see this is done, with any linear program in standard form (recall Section 7.1.4), we know that LPs can always be rewritten this way.

```
min cᵀTx such that Ax = b and x ≥ 0.
```

We first make that the right-hand sides of the equations are nonnegative: if $b_i < 0$, just multiply both sides of the $i$-th equation by -1.

Then we create a new LP as follows:

- Create new artificial variables $z_1, \dots, z_m \ge 0$, where $m$ is the number of equations.
- Add $z_i$ to the left-hand side of the $i$-th equation.
- Let the objective, to be minimized, be $z_1 + z_2 + \dots + z_m$.

For this new LP, it's easy to come up with a starting vertex, namely the one with $z_i = b_i$ for all $i$ and all other variables. Therefore we can solve it by simplex, to obtain the optimum.

### 7.6 The simplex algorithm

There are cases. If the optimum value of $z_1 + \dots + z_m$ is zero, then all $z_i$'s are zero, and hence from the optimum vertex of the new LP we get a starting vertex of the original LP, just by ignoring the $z_i$'s. We can start simplex!

But what if the optimum objective turns out positive? Let us think. We tried to minimize the $z_i$'s, but simplex decided that it cannot be zero. But this means that the linear region is infeasible: it needs nonzero $z_i$ to become feasible. This is how simplex reports that an LP is infeasible.

#### Degeneracy:

In the polyhedron of 7.12 vertex $B$ is degenerate. Geometrically, this means that it is the intersection of more than $n = 3$ Faces of the polyhedron (in this case, ②, ③, ④, ⑤). Algebraically, it means if we choose any one of four sets of inequalities (②, ③, ④), (②, ③, ⑤), and (③, ④, ⑤) and solve the corresponding system of three linear equations in three unknowns, we get the same solution in all cases: (0, 0, 0). This is a serious problem: simplex may return a suboptimal degenerate vertex because all its neighbors are identical to it and thus has no better objective. And if we modify the simplex so that it detects degeneracy and continues to hop from vertex to vertex despite any improvement in the cost, it may end looping.

One way to fix this is by a *perturbation*: change $b$ by any tiny amount that doesn't change the element of the LP since the $\epsilon_i$'s are tiny, but it has the effect of differentiating the solutions of the linear systems. We can see why geometrically, that the four planes ②, ③, ④, ⑤ were jolted a little. Wouldn't vertex $B$ split into two vertices, very close to one another?

#### Unboundedness:

In cases an LP is unbounded, in its objective function can be made arbitrarily large (or small, in minimization problem). If this is the case, simplex will discover: in exploring the neighborhood of a vertex, it will notice that adding an inequality leads to an underdetermined system of equations that has infinity of solutions. And in fact (this is an easy test) the space of solutions contains a whole line across which the objective become larger and larger, all the way to $\infty$. In this case simplex halts and completes.

### 7.6.4 Running time of simplex

What is the running time of simplex, for a generic linear program

```
max $c^T x$ such that $Ax \le 0$ and $x \ge 0$.
```

where there are $n$ variables and $A$ contains $m$ inequality constraints; Since it is an iterative algorithm that proceeds from vertex to vertex, let's start by counting the time for a single iteration. The current vertex is $\mathbf{u}$. By definition, it is the unique point at which $n$ inequality constraints are satisfied with equality. Each of its neighbors shares $n-1$ of these inequalities, so $\mathbf{u}$ can have at most $n \cdot m$ neighbors: choose which inequality to drop and which new to add.

A naive way to perform an iteration would be to check each potential neighbor to see whether it is really a vertex of the polyhedron and to determine its cost.
