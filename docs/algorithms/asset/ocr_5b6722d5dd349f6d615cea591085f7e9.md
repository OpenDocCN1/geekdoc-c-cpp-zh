# On time and memory

The amount of time it takes to run a dynamic programming algorithm is easy to discern from the dag of subproblems; in many cases it is just the total number of edges in the dag! All we are really doing is visiting the nodes in linearized order, examining each node's inges, and, most, doing a constant amount of work per edge. By the end, each edge of the dag has been examined.

But how much memory is required? There is no simple method of the dag characterizing this. It is certainly possible to do the job with an amount of memory proportional to the number of vertices (subproblems), but we can get away with much less. The reason is that the value of a particular problem needs only to be remembered until the larger subproblems depending on it have been solved. Therefore, it takes memory until it can be released for reuse.

For example, the Floyd-Warshall algorithm value of dist(i, j, k) is not needed once the dist(., ., k+1) values have been computed. Therefore, we only need two |V| arrays to store the dist values, one for odd values of k and one for even: when computing dist(i, j, k), we overwrite dist(i, j, k-2).

And let us not forget, as always in dynamic programming, we also need one more prev(i, j), storing the last vertex in the current shortest path from i to j, a value that must be updated with dist(i, j, k). We omit this crucial bookkeeping step from our dynamic programming algorithms.

Can you see how the edit distance in Figure 6.5 only needs memory proportional to the length of the shorter string?

The subproblems are ordered by [S]. Here's the code:

```
C([1, 1]) = 0
for s = 2 to n:
  for subsets S ⊆ {1, 2, ..., n} of size s and containing 1:
    C(S, 1) = ∞
    for j ∈ S, j ≠ 1:
      C(S, i) = min(C(S - {j}), i) + d_{j,i}; i ∈ S, i ≠ j)
return min, C({1, ..., n}, j) + d_{j1}
```

There are at most 2ⁿ - n subproblems, and each takes linear time to solve. The total running time is O(n²ⁿ).
