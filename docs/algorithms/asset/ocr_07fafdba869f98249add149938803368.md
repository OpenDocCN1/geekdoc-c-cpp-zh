Suppose $x$ and $y$ are each $n$ bits long; in this chapter we consistently use the letter $n$ for the sizes of numbers. Then the sum of $x$ and $y$ is $n+1$ bits at, and each individual of this sum computed in a fixed amount of time. The running time for the addition algorithm is therefore of the form $c_0 + c_1n$, where $c_0$ and $c_1$ are some constants; in other words, it is *linear*. Instead of worrying about the precise values of $c_0$ and $c_1$, we will focus on the big picture and denote the running time as $O(n)$.

Now that we have a working algorithm whose running time we know, others wander inevitably to the question of whether there is something better.

**Is there a faster algorithm?** (This is another numbers question.) For addition, the answer is: in order to add two $n$-bit numbers we must least read and write down the answer, and that requires $n$ operations. So addition algorithm is optimal, up to multiplicative constants! Why $O(n)$ operations? Isn't binary addition something that computers perform by just one instruction? There are two answers. First, it is truly true that in a single instruction we can add integers whose size is within the word length of today's computers–32 perhaps. But, as will appear later in this chapter, it is often useful and necessary to handle numbers larger than this, perhaps several thousand bits long. Adding and multiplying large numbers on real computers is very much like by performing the operations by bit. Second, when we want to understand algorithms, it makes sense to study the basic algorithms that are encoded in the hardware of today's computers. In doing so, we shall focus on the *bit complexity* of the algorithm, the number of elementary operations on individual bits—because this reflects the amount of hardware, transistors and wires, necessary for implementing the algorithm.

# 1.1.2 Multiplication and division

Onward to multiplication! The grade-school algorithm for multiplying two numbers $x$ and $y$ is to create an array of intermediate sums, each representing the product of $x$ by a single digit of $y$. These values are appropriately left-shifted and then added up. Suppose for instance that we want to multiply $13 	imes 11$, or in binary notation, $x = 1101$ and $y = 1011$. The multiplication would proceed thus.

| 1 0 1 1 (1101 times 1, shifted once) |
|0 0 0 0 (1101 times 0, shifted twice) |
|+ 1 1 0 1 (1101 times 1, shifted thrice) |
| 0 0 0 0 1 1 1 1 (binary 143)|
