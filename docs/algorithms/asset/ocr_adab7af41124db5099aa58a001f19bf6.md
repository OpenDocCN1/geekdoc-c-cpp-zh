At this point, the algorithm for edit distance basically writes itself.

```
for i = 0, 1, 2, ..., m:
  E(i, 0) = i
  for j = 1, 2, ..., n:
    E(0, j) = j
  for i = 1, 2, ..., n:
    for j = 1, 2, ..., m:
      E(i, j) = min(E(i-1, j) + 1, E(i, j-1) + 1, E(i-1, j-1) + diff(i, j))
  return E(m, n)
```

This procedure fills the table row by row, and left to right within each row. Each
entry entry takes constant time to fill in, so the overall running time is just the size of the
table, O(mn).

# The underlying dag

Every dynamic program has an underlying dag structure: think of each node asnrepresenting a subproblem

In our present edit distance application, the nodes of the underlying dag
correspond to subproblems, or equivalently, to positions (i, j) in the table. Its edges
are the precedence constraints, of the form (i-1, j) → (i, j), (i, j-1) → (i, j),
and (i-1, j-1) → (i, j) (Figure 6.5). In this, we can take a little fur
per weight on the edges so that the edit distances match 1, except for
shortest paths in the dag. To see this, set all edge lengths to 1, except
{(i, j-1) → (i, j): x[i, j]} (shown dotted in the figure), which length
is 0. The final answer is then simply the distance between nodes s = (0,0)
and t = (m, n). One shortest path is shown, the one that yields the
alignment we found earlier. On this path, each move down is a deletion, each
move right is an insertion, and each diagonal move is a match or a
substitution.

By altering the weights on this dag, we can also generalize forms of edit dis-
tance, in which insertions, deletions, and substitutions have different associated
costs.
