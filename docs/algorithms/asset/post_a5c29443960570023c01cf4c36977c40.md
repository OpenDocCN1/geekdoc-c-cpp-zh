
# Figure 8.13 An instance of CIRCUIT SAT.

![](img/3dd1f1364df8f87b80683fc32a15b999_271_0.png)

- Known input gates have no incoming edges and are labeled false or true.
- Unknown input gates have no incoming edges and are labeled "?".

One of the sinks of the dag is designated as the output gate.

Given an assignment of values to the unknown inputs, we can evaluate the gates of the circuit in topological order, using the rules of Boolean logic (such as false ∨ true = true), until we obtain the value at the output gate. This is the value of the circuit for the particular assignment to the inputs. For instance, the circuit in Figure 8.13 evaluates to false under the assignment true, false, true (from left to right).

Circuit SAT is then the following search problem: Given a circuit, find a truth assignment for the unknown inputs that the output gate evaluates to true, or report that no such assignment exists. For example, if presented with the circuit in Figure 8.13 we could have returned the assignment (false, true, true) because we substitute these values to the unknown inputs (from left to right), the output becomes true.

Circuit SAT is a generalization of SAT. To see why, notice that SAT asks for a satisfying truth assignment for a circuit that has this simple structure: a bunch of AND gates at the top join the clauses, and the result of this big AND is the output. Each clause is the OR of its literals. Each literal is either an unknown input gate or the NOT of one. There are no known input gates.

## 8.3 The reductions

Going in the other direction, CIRCUIT SAT can also be reduced to SAT. Here is how we can rewrite any circuit in conjunctive normal form (the AND of clauses): for each gate g in the circuit we create a variable g, and we model the effect of the gate using a few clauses:

![](img/3dd1f1364df8f87b80683fc32a15b999_272_0.png)

Do you see that these clauses do, in fact, exactly the desired effect? And to finish up, if g is the output gate, we force it to be true by adding clause (g). The resulting instance of SAT is equivalent to the instance of CIRCUIT SAT: the satisfying assignments of this conjunctive normal form are in one-to-one correspondence with those of the circuit.

Now we know CIRCUIT SAT reduces to SAT, we turn to our main job, showing that all search problems reduce to CIRCUIT SAT. So, suppose that A is a problem in NP. We must discover a reduction from A to CIRCUIT SAT. This sounds very difficult, because we know nothing about A!

We all know about A is that it is a search problem, so we must put this knowledge to be checked: the main feature of a search problem is any solution to put it quickly: there is an algorithm C that checks, given an instance I and a proposed solution S, whether or not S is a solution of I. Moreover, C makes this decision in time polynomial in the length of I (we assume that S is itself encoded as a binary string, and we know that the length of this string is polynomial in the length of I).

Recall our argument in Section 7.7 that any polynomial algorithm can be rendered as a circuit, however input gates encode the input to the algorithm. Naturally, for any input length (number of input bits) the circuit will be scaled to the appropriate number of inputs, but the total number of gates of the circuit will be polynomial in the number of inputs. If the polynomial algorithm in question solves a problem that requires a yes or no answer (as is the situation with C: "Does S encode a solution to the instance encoded by I"), this answer is given at the output gate.

We conclude that, given any instance $I$ of problem A, we can construct a polynomial time circuit whose known inputs are the bits of $I$, and whose unknown inputs are the bits of $S$, such that the output is $true$ if and only if the unknown inputs spell a solution $S$ of $I$. In other words, the satisfying truth assignments of the circuit are in one-to-one correspondence with the solutions of instance $I$ of A. The reduction is complete.

## Unsolvable problems

At least an NP-complete problem can be solved by some algorithm—the trouble is that this algorithm will be exponential. But it turns out there are difficult computational problems for which no algorithm exists! One famous problem of this sort is an arithmetic version of SAT. Given an equation in many variables, perhaps

```
x^3y+2y^3-7xy^5=0
```

are integer values of $x, y, z$ that satisfy it? There is no algorithm that solves this problem. Polynomial, exponential, or recursive problems are unsolvable. The first unsolvable problem was discovered in 1936 by Alan M. Turing, a student of mathematics at Cambridge, England. When Turing came up with it, there were no computers or programming languages (in fact, it can be argued that these things came later). But today we can see it in familiar terms. Suppose that are given a program in your favorite language, along with a particular input. Will the program terminate, once started on this input? This is a very reasonable question. Many of us would be ecstatic if we had an algorithm, call it terminates(p,x), that takes as input a file containing program $p$, and a file of data $x$, and finally tells us whether or not $p$ would ever stop. But you can't. Such an algorithm does not exist! And here is the proof: Suppose we actually had such a program terminates(p,x). Then we could use it as a subroutine of the following program:

```
function paradox(z:file)
1: if terminates(z,z) goto 1
```

Notice what paradox does: it terminates if and only if program does not terminate given its own code as input. What if we put this program in a file named paradox and executed paradox(paradox)? This execution would error? Neither is possible. Since we arrived at this contradiction by assuming there is an algorithm for telling programs, we must conclude that this problem cannot be solved by any algorithm. By this way, it tells us important about programming: it will never be automated, it will forever depend on discipline, ingenuity, and hackery. We now know that you can't tell whether a program has an infinite loop. Do you see how to use the unsolability of the “halting problem” to show that this, too, is unsolvable?

8.4. Consider the CLIQUE restricted to graphs in which every vertex has degree at most 3. Call this problem CLIQUE-3.
(a) Prove that CLIQUE-3 is in NP.
(b) What is wrong with the following proof of NP-completeness? We know that the CLIQUE problem in general graphs is NP-complete, so it is enough to present a reduction from CLIQUE-3 to CLIQUE. Given a graph with vertices of degree $\le 3$, and a parameter $g$, the reduction leaves the graph and the parameter unchanged: clearly the output of the reduction is a possible input for the CLIQUE problem. Furthermore, the answer to both problems is identical. This proves the correctness of the reduction, and therefore, the NP-completeness of CLIQUE-3.
(c) It is true that the VERTEX cover problem remains NP-complete when restricted to graphs in which every vertex has degree at most 3. Call this problem VC-3. What is wrong with the following proof of NP-completeness for clique-3? We present a reduction from vc-3 to clique-3. Given a graph $G = (V, E)$ with node degrees bounded by 3, and a parameter $b$, we create an instance of CLIQUE-3 by leaving the graph unchanged and switching the parameter to $|V|-b$. Now, a subset $C \subseteq V$ is a vertex cover in $G$ if and only if the complement set $V - C$ is a clique in $G$. Therefore $G$ has a vertex cover of size $\le b$ if and only if it has a clique of size $\ge |V|-b$. This proves the correctness of the reduction, and consequently, the NP-completeness of clique-3.
