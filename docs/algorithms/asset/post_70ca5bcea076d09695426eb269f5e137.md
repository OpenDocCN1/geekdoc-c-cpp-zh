In many graphs, such as the one in Figure 8.3, the smallest cut joins a singleton vertex on one side—it consists of all edges adjacent to this vertex. Far more interesting are small cuts that partition the vertices of the graph into nearly equal sets. More precisely, the BALANCED CUT problem is this: given a graph with $n$ vertices and a budget $b$, partition the vertices into two sets $S$ and $T$ such that $|S|, |T| \geq n/3$ and that there are at most $b$ edges between $S$ and $T$. Other hard problem

Balanced cuts arise in a variety of important applications, such as clustering. Consider the problem of segmenting an image into its constituent components (say, an elephant standing in a grassy plain with a clear blue sky). A good way of doing this is to create a graph with a node for each pixel of the image and to put an edge between nodes whose pixels are spatially close together and are also similar in color. A single object in the image (like the elephant) then corresponds to a set of highly connected vertices in the graph. A balanced cut is therefore likely to divide the pixels into two clusters without breaking any of the primary constituents of the image. The first cut, for instance, separate the elephant on one hand from the sky and grass from the other. A further cut would then be needed to separate the sky from the grass.

# Integer linear programming

Even though the simplex algorithm is not polynomial time, we mentioned in Chapter 7 that there is a different, polynomial algorithm for linear programming. Therefore, linear programming is efficiently solvable both in practice and in theory. The situation changes completely if, in addition to specifying a linear objective function and linear inequalities, we also constrain the solution (the values for the variables) to be integer. This latter method is called INTEGER LINEAR PROGRAMMING (ILP). Let's see how we formulate it as a search problem. We are given a set of linear inequalities $Ax \leq b$, where $A$ is an $n \times m$ matrix and $b$ is an $n$-vector; an objective function specified by an $n$-vector $c$, and a goal $g$ (the counterpart of a budget in maximization problems). We want to find a nonnegative integer $n$-vector $x$ such that $Ax \leq b$ and $c \cdot x \geq g$.

But there is a redundancy here; the last constraint $c \cdot x \geq g$ is itself a linear inequality and can be absorbed into $Ax \leq b$. So, we define ILP to be the following search problem: given $A$ and $b$, find a nonnegative integer $x$ satisfying the inequalities $Ax \leq b$, or report that none exists. Despite the crucial applications of this problem, and intense interest by researchers, no efficient algorithm is known for it.

There is a particularly special case of ILP that is hard in and of itself: the goal is to find a vector $x$ of 0s and 1s satisfying $Ax = i$, where $A$ is an $n \times m$ matrix with 0–1 entries and $i$ is the $m$-vector of all 1s. It should be apparent that the reductions in Section 7.1.4 this is a special case of ILP. We call it ZERO-ONE EQUATIONS (ZOE).

We have now introduced a number of important search problems, some of which are familiar from earlier chapters and for which there are efficient algorithms, and others are different in small but crucial ways that make them very hard computational problems. To complete our story we will introduce a few more problems, which will play a role later in the chapter, when we relate the computational difficulty of all these problems. # Three-dimensional matching

Recall the problem: bipartite matching with $n$ nodes on each side (the boys and the girls), find a set of $n$ disjoint edges, or decide that no such set exists. In Section 7.3, we saw how to efficiently solve this problem by a reduction to maximum flow. However, there is an interesting generalization, called 3D MATCHING, for which no polynomial algorithm is known. In this new setting, there are $n$ boys and $n$ girls, but also $n$ pets, and the compatibilities among them are specified by a set of triples, each containing a boy, a girl, and a pet. Intuitively, a triple $(b, g, p)$ means that boy $b$, girl $g$, and pet $p$ all get well together. We want to find $n$ disjoint triples and create $n$ harmonious households.

# Longest path

We know the shortest-path problem can be solved very efficiently, but how about the longest PATH problem? We are given a graph $G$ with nonnegative edge weights and two distinguished vertices $s$ and $t$, along with a goal $g$. We are asked to find a path from $s$ to $t$ with total weight at least $g$. Naturally, to avoid trivial solutions we require that the path be simple, containing no repeated vertices.

No efficient algorithm is known for this problem (which sometimes also goes by the name of TAXICAB RIP-OFF).

# Knapsack and subset sum

Recall the KNAPSACK problem (Section 6.4): we are given integers $w_1, \dots, w_n$ and values $v_1, \dots, v_n$ for $n$ items. We are also given a weight capacity $W$ and a goal $g$ (the former is present in the original optimization problem, the latter is added to make it a search problem). We seek a set items whose total weight is at most $W$ and total value is at least $g$. as if no such set exists, we would say no.

In Section 6.4, we developed a dynamic programming scheme for KNAPSACK with running time $O(nW)$, which is now exponential in the input size, since it involves $W$ rather than $\log W$. And we have the usual exhaustive algorithm as well, which looks at all subsets of items—$2^n$ of them. Is there a polynomial algorithm for KNAPSACK? Nobody knows one.

But suppose we are interested in the variant of the knapsack problem in the integers are in unary—for instance, by writing IIIIIIIIII for 12. This is an expediently wasteful way to represent integers, but it defines a legitimate problem, which we could call UNARY KNAPSACK. It follows from our discussion that somewhat somewhat arithmetic problem has a polynomial algorithm.

A different variation: suppose that each item's value is equal to its weight (as given in binary), and to top it off, the goal $g$ is the same as the capacity $W$. (To adapt the silly story, whereby we first introduced the knapsack problem, the items are all gold nuggets, and the burglar wants to fill his knapsack to the hit.) This special case is tantamount to finding a subset of a given set of integers that adds up to exactly $W$. Since it is a special case of KNAPSACK, it cannot be any harder. Could it be polynomial? As it turns out, this problem, called SUBSET SUM, is also very very hard.
