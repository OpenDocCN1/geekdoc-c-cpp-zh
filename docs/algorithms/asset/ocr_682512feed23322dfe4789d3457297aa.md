# 3.1 Why graphs?

# How big is your graph?

Which of the two representations, adjacency matrix or adjacency list, is better? Well, depends on the relationship between $|V|$, the number of nodes in the graph, and $|E|$, the number of edges. $|E|$ can be as small as $|V|$ (if it gets much smaller, the graph degenerates—for example, isolated vertices), or as large as $|V|^2$ (when all possible edges are present). When $|E|$ is close to the upper limit of range, we call the graph dense. At the other extreme, if $|E|$ is close to $|V|$, the graph is sparse. As we shall see in this chapter and the next two chapters, where $|E|$ lies in this range is usually a crucial factor in selecting the right graph algorithm.

Or, for matter, selecting the graph representation. If it is the World Web graph that we wish to store in memory, search engines know of about eight billion vertices of the graph, hence the adjacency matrix would take up dozens of terabits. Again at the time we write these lines, it is not clear that there is enough computer memory in the whole world to achieve this. (And waiting a few years until there is enough memory is unlike: the Web will grow and probably grow faster.)

With adjacency lists, representing the World Web becomes feasible: there are only a few billion hyperlinks in the web, and each will carry a few bytes in the adjacency list. You can carry a device that stores the result, a terabyte or two, in your pocket (it may soon be in your earning, but by the time the Web will have grown).

The reason why adjacency lists are so much more effective in the case of the World Web is that the Web has hyperlinks to only half a dozen pages, out of the billions of possibilities.

The biggest convenience of this format is that a particular edge can can be checked in time, with one memory access. On the other hand the matrix takes up $O(n^2)$ space, which is wasteful if the graph does not have many edges.

An alternative representation, with size proportional to the number of edges, is the adjacency list. It consists of $|V|$ linked lists, one per vertex. The linked list for vertex $u$ holds the names of vertices to $u$ has an outgoing edge—that is, vertices $v$ for $(u, v) \in E$. Therefore, each edge appears in one of the linked lists if the graph is directed or two if the graph is undirected. Either way, the total size of the data is $O(E)$. Checking for a edge $(u, v)$ is no constant time, because it requires sitting through $u$'s adjacency list. But it is easy to iterate through all neighbors of $v$ (by running down the corresponding linked list), and, as we shall soon see, this turns out to be a very useful operation in graph algorithms. Again, for undirected graphs, this representation has a symmetry of lists: $v$ is in $u$'s adjacency list if and only if $u$ is in $v$'s adjacency list.
