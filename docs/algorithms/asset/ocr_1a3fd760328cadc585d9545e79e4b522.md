# RUDRATA CYCLE→TSP

Given a graph G = (V, E), we construct the instance of the TSP: the set of cities is given by V, and the distance between cities u and v is 1 if [u, v] is an edge of G and 1+α otherwise, for α > 1 to be determined. The budget of the TSP is equal to the number of nodes, |V|.

It is easy to see that if G has a Rudrata cycle, the same cycle is also a tour within the budget of the TSP; and conversely, if G has no Rudrata cycle, there is no solution: the cheapest TSP tour has cost n+α (it is at least n-1). Thus RUDRATA CYCLE REDUCES TO TSP.

In this reduction, we introduced the parameter α by varying it, we can obtain two interesting results. If α = 1, then all distances are either 1 or 2, and so this instance of the TSP satisfies the triangle inequality: if i, j, k are cities, d_ij + d_jk ≥ d_ik (proof: a + b ≥ c holds for any numbers 1 ≤ a,b,c ≤ 2). This is a special case of TSP which is of practical importance and, which we will see in Chapter 9, in a certain sense easier, because it can be efficiently approximated.

On the other hand α is large, the resulting instance of TSP may not satisfy the triangle inequality, but has another important property: it has a solution of cost n or less, or all its solutions have cost n+α (which now can be arbitrarily larger than n). There can be nothing in between! As we see in Chapter 9, this gap property implies that, unless P = NP, no approximation algorithm is possible.
