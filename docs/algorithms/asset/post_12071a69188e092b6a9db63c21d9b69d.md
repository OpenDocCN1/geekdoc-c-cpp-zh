
## 6.5 Chain matrix multiplication

As you can see, the order of multiplications makes a big difference in the final time! Moreover, the natural greedy approach, to always perform the cheapest matrix multiplication available, leads to the second parenthesization shown here and is therefore a failure.

How do we determine the optimal, if we want to compute $A_1 \times A_2 \times \dots \times A_n$ where $A_i$'s have dimensions $m_0 \times m_1, m_1 \times m_2, \dots, m_{n-1} \times m_n$, respectively? The first thing to notice is that a particular parenthesization can be represented very naturally by a binary tree in which the individual nodes are leaves, the root is the final product, and interior nodes are intermediate products (Figure 6.7). The possible orders in which to do the multiplication are the various full binary trees with $n$ leaves, whose number is exponential in $n$ (Exercise 2.13). We certainly cannot try each tree, and with brute force ruled out, we turn to dynamic programming.

The binary trees of Figure 6.7 suggest: for a tree to be optimal, its subtrees must also be optimal. What are the subproblems corresponding to the subtrees? They are the product of $A_i \times A_{i+1} \times \dots \times A_j$. Let's see if this works for: $1 \le i \le j$, define

```
$C(i, j) = \text{cost of multiplying } A_i \times A_{i+1} \times \dots \times A_j.$
```

The size of this subproblem is the number of matrix multiplications, $|j - i|$. The smallest subproblem is when $i = j$, in which case there's nothing to multiply, $C(i, i) = 0$. For $j > i$, consider the optimal subtree for $C(i, j)$. The first branch in this subtree, the one at the top, will split the product in two pieces, of the form $A_i \times \dots \times A_k$ and $A_{k+1} \times \dots \times A_j$, for some $k$ between $i$ and $j$. The cost of the subtree is then the cost of these two products, plus the cost of combining $C(i, k) + C(k, j) + m_{i-1}m_k m_j$. And we need to find the splitting point $k$ for which this is smallest:

**Figure 6.7** (a) $((A \times B) \times C) \times D$; (b) $A \times ((B \times C) \times D)$; (c) $(A \times (B \times C)) \times D$.

![](img/3dd1f1364df8f87b80683fc32a15b999_180_0.png)

```
C(i, j) = \min_{i<k<j} [C(i, k) + C(k+1, j) + m_{i-1} \cdot m_k \cdot m_j]
```

We are ready to code! In the following, the $s$ denotes subproblem size.

```
for i = 1 to n: C(i, i) = 0
for s = 1 to n-1:
  for i = 1 to n-s:
    j = i + s
      C(i, j) = min(C(i, k) + C(k+1, j) + m_{i-1} \cdot m_j : i \le k < j)
return C(1, n)
```

The subproblems constitute a two-dimensional table, each of whose entries takes $O(n)$ time to compute. The overall running time is thus $O(n^2)$.

## 6.6 Shortest paths

We started this chapter with a dynamic programming algorithm for the elementary task of finding the shortest path in a dag. We now turn to more sophisticated shortest-path problems and see how these two can be accommodated by our powerful algorithmic technique.

### shortest reliable paths

Life is complicated, and abstractions as graphs, edge lengths, and shortest paths rarely capture the whole truth. In a communications network, for example, if edge lengths reflect transmission delays, there may be other considerations involved in choosing a path. For instance, each edge in the path may be an "hop" fraught with uncertainties and dangers of packet loss. In such cases, we would like to avoid paths with too many edges. Figure 6.8 illustrates this problem with a graph where the shortest path from S to T has four edges, while there is another path that is a little longer but uses only two. If four edges translate to prohibitive unreliability, we may have to choose the latter path.

Figure 6.8: We want a path from s to t that is both shortest and has few edges.

![](img/3dd1f1364df8f87b80683fc32a15b999_181_0.png)

Suppose that we have a graph $G$ with lengths on the edges, along with two nodes $s$ and $t$ and an integer $k$, and we want the shortest path from $s$ to $t$ that uses at most $k$ edges.

Is there a quick way to adapt Dijkstra's algorithm to this new task? Not quite: that algorithm focuses on the length of each shortest path without “remembering” the number of hops in the path, which is now a crucial piece of information.

In dynamic programming, the trick is to choose subproblems so that vital information is remembered and carried forward. In this case, let us define, for each vertex $v$ and each integer $i \le k$, $dist(v, i)$ to be the length of the shortest path from $s$ to $v$ that uses $i$ edges. The starting values $dist(v, 0) = \infty$ for all vertices except $s$, for which it is 0. And the general update equation is, naturally enough,

```
dist(v, i) = \min_{u,v\in E} [dist(u, i-1) + l(u, v)]
```

And we need more?

### All-pairs shortest paths

What if we want to find the shortest path not just between $s$ and $t$ but all pairs of vertices? One approach would be to execute our general shortest-path algorithm from Section 4.6.1 (since there may be negative edges) $|V|$ times, for each starting node. The total running time would then be $O(|V|^2|E|)$. We'll need a better alternative, the Floyd-Warshall algorithm.
