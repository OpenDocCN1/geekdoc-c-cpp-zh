Note the name of the test above indicates the name of the method being tested by a short description of the test being performed and a description of the expected output. Test names like this, long, are important. By reading a long list of test names we can work out parts of our system have been adequately tested and which parts have been missed.

In addition to the tests described we should also try to add a client with the same ID twice. Our system should of course not allow this to happen. The test succeeds if the code prevents a client being added twice.

Conversely if the system does not generate an exception after adding the same client for the second time then the test should indicate that the code has failed. For this test is given below...

```
[TestMethod]
public void AddClient_TestAddExistingClient()
{
    BankManager.Client c = new BankManager.Client("Simon", "Room
1234", "x200", 10);
    try
    {
        Bof.AddClient(1, c);
        Bof.AddClient(1, c);
        Assert.Fail("ClientAlreadyExists exception should be thrown\n        if client added twice");
    }
    catch (BankManager.ClientAlreadyExistsException)
    {
    }
}
```

An alternative way of writing the test above is to indicate that the test expects an exception to be generated by the [ExpectedException(...)] attribute. If this exception is generated and interrupts the test then the test has passed. See an alternative version of the test code below...

```
[TestMethod]
[ExpectedException(typeof(BankManager.ClientAlreadyExistsException))]
public void AddClient_TestAddExistingClient()
{
    BankManager.Client c = new BankManager.Client("Simon", "Room
1234", "x200", 10);
    Bof.AddClient(1, c);
    Bof.AddClient(1, c);
    Assert.Fail("ClientAlreadyExists exception should be thrown\n        client added twice");
}
```
