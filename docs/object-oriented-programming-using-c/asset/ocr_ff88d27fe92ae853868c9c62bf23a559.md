# Object Oriented Software Analysis and Design

How do we get from a 'need' for some software to an object oriented software design that will meet this?

Some software engineers specialise in the task of Requirement Analysis is the task of clarifying exactly what is required of the software. This is often done by iteratively performing the following tasks :-

+   1) interviewing clients and potential users of the system to find out what they say about the system needed
2) documenting the results of these conversations,
3) identifying the essential features of the required system
4) producing preliminary designs (and possibly prototypes of the system)
5) evaluating these initial plans with the client and potential users
6) repeating the steps above until a finished design has evolved.

Performing requirements is a analysed skill that is outside the scope of this task but here we will focus on steps three and above ie. giving a description of how we convert this into a potential OO design.

While we can hope to develop design skills experience is a significant factor in this task. Producing simple and elegant designs is important if we want the software to work well and be easy to develop identifying good designs from weaker mechanisms is not simple and experience is a key factor.
