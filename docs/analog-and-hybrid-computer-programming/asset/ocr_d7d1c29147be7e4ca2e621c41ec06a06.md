If the output N of the inverter reads 0.4 after some time, this would correspond to 0.4 · 0.12 = 0.048 mols.

So, it is necessary to distinguish between so-called *problem variables* which are the variables appearing in the mathematical representation of the problem and *machine variables* which are the corresponding scaled variables as they occur in a given scaled computer setup. Machine variable are often denoted by a hat:

$\hat{N} = \alpha N$ with $\alpha = \frac{1}{\max(N)}$

where $\alpha$ is the scale factor for this variable. In the example above it is

$\alpha = \frac{1}{0.12} \approx 8.333.$

This amplitude scaling of variables is only one side of the coin. It is also necessary to distinguish between *problem time*, i. e. the time in which the actual problem runs, and *machine time*, the time at which the current simulation runs. The process of transforming problem time to machine time is called *time scaling*. To distinguish between both times the symbols $t$ and $\tau$ are commonly used, representing problem and machine time; these are coupled by a scale factor $\beta$ yielding $\tau = \beta t$. $\beta$ is determined as the product of $k_0$ of the integrators in a given setup and their respective input weights.

Machine time is running faster than problem time, if $\beta > 1$. This is suitable for simulating processes which change too slowly with time for direct observation. Radioactive decay of some long-lived isotope is a typical example of such a process. In other cases where the problem time is too short to make useful observations, choosing $\beta < 1$ suitably will slow down machine time accordingly.

In the case of $^{234}_{90}$Th having a half-life of $T_{1/2} = 24.1$ days, a substantial speedup of machine time as compared to problem time is desirable. To get a flicker-free display on an oscilloscope, machine time will be scaled so that 2.41 ms will correspond to the half-life $T_{1/2} = 24.1$ d with $0 \le \tau \le 20$ ms. This results in

$\lambda = \frac{\ln(2)}{2.41} \approx 0.287$
