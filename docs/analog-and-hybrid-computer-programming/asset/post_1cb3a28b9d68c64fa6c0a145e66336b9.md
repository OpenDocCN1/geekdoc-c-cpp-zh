The following examples give a basic overview of the general capabilities of a hybrid computer. More information on hybrid computing with many applications can be found in [BEKEY et al. 1968], [KORN et al. 1964], [SCHÖNEFELD 1977], and other classic text books.

### 7.2 Basic operation

The Model-1's hybrid controller used in these examples is connected to the digital computer by means of a USB interface which emulates a serial line.¹³² To facilitate programming the digital computer a Perl¹³³ module (IO::HyCon) has been implemented; it provides an object oriented interface to the hybrid controller.¹³⁴

IO::HyCon requires a configuration file in YAML-format¹³⁵ which describes the actual setup of the analog computer, i.e. the addresses of the various computing elements, the serial line parameters, etc. A typical minimum example is shown in the following listing:¹³⁶

```yaml
serial:
  port: /dev/cu.usbserial-DN05OL10
  bits: 8
  baud: 115200
  parity: none
  stopbits: 1
  poll_interval: 10
  poll_attempts: 20000
types:
  0: PS
  1: SUM8
  2: INT4
  3: PT8
  4: CU
  5: MLT8
  6: MDS2
  7: CMP4
  8: HC
manual_potentiometers:
elements:
  INT-0: 0x0030
  INT-1: 0x0031
  INT-2: 0x0032
  INT-3: 0x0033
```

It consists of the following sections:

**serial:** This section describes the communication setup. port defines the serial device. Its name depends on the operating system and the USB-serial-adapter being used. The remaining parameters are defaults and can be adopted unchanged in most cases.

**types:** Each computing element in an Analog Paradigm Model-1 returns an eight bit value on the data bus when selected for readout. This section contains the mapping between these codes and the actual computing element types.

**manual_potentiometers:** This section allows the definition of manual potentiometers which can be read by the hybrid controller. This is useful, if a simulation requires user input by means of coefficient potentiometers whose values are of interest during or after an analog computer run.

**elements:** All elements which are to be read out by the hybrid controller have to be defined in this section. Names like INT-0 should be avoided in favour of meaningful variable names such as phi-dot or the like.

A typical hybrid computer program starts like this:

```perl
use strict;
use warnings;
use IO::HyCon;

my $ac = IO::HyCon->new();
```

The scalar variable `$ac` is an object with access to all the methods implemented in `IO::HyCon` to control the operation and setup of the analog computer. The call `$ac->ic()` will set the analog computer to IC mode, `$ac->op()` will initiate an OP phase, and so on.

### 7.3 Shell trajectory

This first example is based on the ballistic trajectory simulation described in section 6.6 and is an example of the digital and analog computers working in an alternating fashion. The analog computer setup shown in figure 6.21 is used in this hybrid computer setup. The only difference here is that the coefficient potentiometers for

$\dot{x}_0 = \cos(\varphi)$

$\dot{y}_0 = \sin(\varphi)$

are two of the hybrid controller’s eight digital potentiometers. $\dot{x}_0$ corresponds to DPT0 and $\dot{y}_0$ to DPT1.

The aim of this simulation is to determine the elevation angle of the cannon in this two-dimensional setup in order to hit a target at a user defined $x$-coordinate. The digital computer sets an elevation angle $\varphi$, and thus $\dot{x}_0$ and $\dot{y}_0$, then starts a simulation run and reads the $x$ component where the shell hit the ground. Based on δ = x − x_target, the distance between the target and this point, a new φ is determined and so on until δ is sufficiently small.

![](img/91599d88757ed8c75960eb83f4f85a12_212_0.png)

Fig. 7.2. HALT detection and target input

It is assumed that the y component of the cannon's position satisfies y_cannon > 0 while the target's y component is y_target = 0. Using a comparator as shown in figure 7.2, an external halt signal is generated when the shell hits the ground. This signal is connected to the EXTHALT input of the hybrid controller. x_target can be set manually by the potentiometer shown below the comparator. Its output is not connected to anything as it is only read out by the digital computer after a run to determine the miss distance δ.

The configuration file for this hybrid simulation is shown below - the sections serial and types have been omitted as these are identical to those in the listing shown on page 197. The two computing elements yielding the values required by the digital portion of the hybrid computer setup are defined in the elements section and labelled X and TARGET, representing x_shell and x_target.

```yaml
elements:
  X:     0x0221
  TARGET: 0x0051
```

The corresponding Perl program for this hybrid simulation is shown below and is straightforward.

```perl
use strict;
use warnings;
use IO::HyCon;

my $ac = IO::HyCon->new();

$ac->set_ro_group('X', 'TARGET');

$ac->set_ic_time(1);

$ac->enable_ext_halt();

my $phi = 3.1415 / 4;  # Start with 45 degrees of elevation
while (1) {
    $ac->set_pt(0, cos($phi));
    $ac->set_pt(1, sin($phi));

    $ac->single_run_sync();
    my $result = $ac->read_ro_group();
    my $delta = $result->{X} - $result->{TARGET};
    $phi -= $delta / 10;
    printf("%0.4f\t%0.4f\t%0.4f\n",
        $result->{X}, $result->{TARGET}, $delta);
}
```

After instantiating an IO::HyCon object $ac in line 6 a readout group is defined in line 8. All elements of such a readout group can be read by the hybrid controller with minimal clock skew – something which is not necessary in this particular case as the analog computer has been halted when the simulated shell hit ground and thus all variables are static. A single run, consisting of an IC-period of 1 ms and an OP-phase of 2 ms, is initiated by calling single_run_sync in line 19. This method blocks until either the defined OP-time has been reached or an external halt signal has occurred. In this simulation, the latter event will always precede a timeout since the shell will hit ground in less than 2 ms with k0 = 10³.

After such a single run x_shell and x_target are read by invoking read_ro_group. This returns a hash containing one key-value-pair for each element defined in the readout group. Based on these values δ is determined in line 22. This value is then used to determine a new elevation angle φ in line 23.¹³⁸ Before the next single run with this angle is started, the current values of x_shell, x_target, and δ are printed on screen.

### 7.4 Data gathering

Using a hybrid controller it is also possible to gather data either during HALT periods in a lengthy computer run or continuously during an OP period as shown in the following example.¹³⁹ The goal is to solve the one-dimensional wave equation

$\frac{1}{c}\ddot{u} - \frac{\partial^2 u}{\partial x^2}=0.$

As before, the derivatives with respect to $x$ are approximated by a difference quotient yielding

$\frac{1}{c}\ddot{u} - \frac{u_{i-1}-2u_i+u_{i+1}}{(\Delta x)^2}=0$

with $\Delta x = \frac{x}{n}$ and $n \in \mathbb{N}$. Defining

$\lambda := \frac{c}{(\Delta x)^2} = \frac{c n^2}{x^2}$

results in a form suitable to derive an analog computer setup:

$\ddot{u}_i = \lambda (u_{i-1}-2u_i+u_{i+1})$

To simplify things further it is assumed that $n=4$ and $\lambda=1$ finally yielding the following set of coupled ordinary differential equations:

- $\ddot{u}_0 = \delta(t)$
- $\ddot{u}_1 = u_0 -2u_1 + u_2$
- $\ddot{u}_2 = u_1 -2u_2 + u_3$
- $\ddot{u}_3 = u_2 -2u_3 + u_4$
- $\ddot{u}_4 = u_3 -2u_4 + u_5$
- $u_5 = 0$

$\delta(t)$ represents an impulse occurring at the start of a simulation run, i.e. at $t=0$. Figure 7.3 shows the resulting computer setup consisting of four basically identical cells, each containing two integrators, an inverting summer and a coefficient potentiometer. Using the hybrid controller as a data logger it is now possible to gather the variables $u_1,\dots,u_4$ during a simulation run.¹⁴⁰
