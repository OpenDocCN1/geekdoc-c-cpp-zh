## ## Using Comments

While comments may seem like a minor element in the many lines of code to combine and make a game, application or even an entire operating system, in fact they're probably one of the most important factors.

### THE IMPORTANCE OF COMMENTING

Comments inside code are basically human readable descriptions of what the code is doing at that particular point. They don't sound especially important but code without comments is one of the frustrating areas of programming unless you're a professional or just starting out.

In short, code should be commented in a manner to effectively describe the purpose of a section, or individual elements. You should get in the habit of commenting as much as possible so that someone who doesn't know anything about programming can pick up your code.

In a professional environment, comments are vital to the success of the code. In an organisation, managers work alongside engineers, other developers, hardware analysts and on. If you're part of the team that's working on code, comments help a lot of others follow in the shoes of someone whose job is to find in excess of 800,000 lines of code spread across different modules. The best comments are concise and link the code, detailing what happens when the program hits a section. You don't need to comment every line. However, if something is that drastically changes the program for the user, as you've run out of lines, it certainly needs to be commented. Even if you write comments sharing with others this way you can return and always understand what went wrong. Comments practice and once you understand how to add a comment, so soon it becomes your nature.
