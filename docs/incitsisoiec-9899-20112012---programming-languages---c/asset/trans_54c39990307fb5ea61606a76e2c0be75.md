## 6.10.3.1 参数替换

在识别出函数型宏调用的参数后，将进行参数替换。替换列表中的参数，除非其在面紧跟有 `#` 或 `##` 预处理令牌，或者后面紧跟有 `##` 预处理令牌（见下文），否则它将被其中包含的所有宏展开后的相应参数所替换。在被替换之前，如果每个参数的预处理令牌构成了预处理文件的剩余部分，则它们将被完全进行宏替换；此时没有其他可用的预处理令牌。

在替换列表中出现的标识符 `__VA_ARGS__` 应被视为一个参数，且可变参数将形成用于替换它的预处理令牌。

## 6.10.3.2 # 运算符

### 限制条件

在函数型宏的替换列表中，每个 `#` 预处理令牌后面必须是替换列表中的下一个预处理令牌（参数）。

### 语义

如果在替换列表中，一个参数前面紧跟一个 `#` 预处理令牌，则两者都被替换为单个字符字符串字面量预处理令牌，该令牌包含对应参数的预处理令牌序列的拼写。参数预处理令牌之间的每个空白将变为字符字符串字面量中的单个空格字符。构成参数的第一个预处理令牌之前的空白和最后一个预处理令牌之后的空白将被删除。否则，参数中每个预处理令牌的原始拼写保留在字符字符串字面量中，但对生成字符串字面量和字符常量拼写有特殊处理：在每个常量或字符串字面量的 `"` 和 `\` 字符之前都会插入一个 `\` 字符，无论在通用字符名称起始的 `\` 之前是否插入了 `\`。如果替换结果不是有效的字符串字面量，则行为未定义。对应空参数的字符字符串字面量为 `""`。`#` 和 `##` 运算符的评估顺序未指定。

## 6.10.3.3 ## 运算符

### 限制条件

##` 预处理令牌不应出现在任何形式宏定义的替换列表的开头或结尾。

### 语义

如果在函数型宏的替换列表中，一个参数前面紧跟或后面紧跟一个 `##` 预处理令牌，则该参数被相应参数的预处理令牌替换；然而，如果参数不包含任何预处理令牌，则该参数被占位符（placemark）预处理令牌替换。

对于对象型和函数型宏调用，都会对替换列表中的每个 `##` 预处理令牌重新检查替换列表，删除该令牌（并非来自参数），并将前面的预处理令牌与后面的预处理令牌拼接。占位符预处理令牌有特殊处理：两个占位符的拼接产生单个占位符预处理令牌，占位符与非占位符预处理令牌的拼接产生非占位符预处理令牌。如果结果不是有效的预处理令牌，则行为未定义。`##` 运算符的评估顺序用于进一步的宏替换。

示例 在以下片段中：

```
#define hash_hash # ##
#define mkstr(a) # a
#define in_between(a) mkstr(a)
#define join(c, d) in_between(c hash_hash d)

char p[] = join(x, y); // 等同于
      // p[] = "x ## ## y";
```

展开在不同阶段产生：

```
join(x, y)
in_between(x hash_y)
in_between(x ## y)
mkstr(x ## y)
"x ## ## y"
```

换句话说，展开 `hash_hash` 会产生一个新的令牌，由两个相邻的井号组成，但这个新令牌不是 `##` 运算符。

173) 占位符预处理令牌不在语法中，因为它们是仅存在翻译阶段4的临时实体。

## 6.10.3.4 重新扫描和进一步替换

在替换列表中的所有参数都被替换且完成了 `# ##` 处理后，所有的占位符预处理令牌将被移除。然后对生成的预处理序列以及源文件中所有后续预处理令牌进行重新扫描，以寻找更多待替换的宏名。

如果在扫描替换列表期间（不包括源文件的其余预处理令牌）发现了正在被替换的宏名，则不进行替换。此外，如果任何嵌套替换遇到了正在被替换的宏名，则不进行替换。这些未被替换的宏名预处理令牌，如果稍后在（重新）检查中本该被替换宏名预处理令牌的上下文，将不再用于进一步替换。

生成的完全经过宏替换的预处理令牌序列如果类似于预处理指令，则不会被作为预处理指令处理，但其中所有的 `pr unary` 一元运算符表达式将按照 6.10.9 的规定进行处理。

示例 在某些情况下，不清楚替换是否是嵌套。例如，以下宏定义：

```
#define f(a) a*g
#define g(a) f(a)
invocation

f(2)
```
可能展开为：

```
f(9)
```

或者

```
2*g
```

严格遵守的程序被允许依赖这种行为。
