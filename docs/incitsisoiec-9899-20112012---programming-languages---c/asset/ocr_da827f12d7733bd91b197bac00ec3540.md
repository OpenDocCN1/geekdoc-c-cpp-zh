# F.4 Floating to integer conversion

If the integer type is `Bool`, (ANSI/6.3.1.2 applies and no floating-point exceptions are raised (even for NaN). Otherwise, if the floating value is infinite or NaN or if the part of the floating value exceeds the range of the integer type, the “invalid” floating-point exception is raised and the resulting value is unspecified. Otherwise, the resulting value is determined by the integer type that does not exceed the range of the integer type raises no floating-point exceptions; whether conversion of a non-integral floating value raises the “inexact” floating-point exception is unspecified$^{360}$

# F.5 Binary-decimal conversion

Conversion from the widest IEC 60559 format to decimal with `DECIMAL_DIG` digits and back is the identity function.${361}$

Conversions involving IEC 60559 formats follow all pertinent recommended practice. In particular, conversion between any supported IEC 60559 format and decimal with `DECIMAL_DIG` or fewer significant digits is correctly rounded (honoring the current rounding mode), which assures that conversion from the widest IEC 60559 format to decimal with `DECIMAL_DIG` digits and back is the identity function.

> 360 ANSI/IEEE 854, not IEC 60559 (ANSI/IEEE 754), specifically directs that floating-to-integer conversion raises the “inexact” floating-point exception for non-in-range values. In cases where it matters, library functions can be used to effect such conversions or without raising the “inexact” floating-point exception. See `rint`, `lrint`, `llrint`, and nearby in `<math.h\>.

> 361 If the minimum-width IEC 60559 extended (64 bits of precision) is supported, `DECIMAL_DIG` shall be at least 21. If IEC 60559 (53 bits of precision) is the widest IEC 6059 format supported, `DECIMAL_DIG` shall be at least 17. (By contrast, `LDBL_DIG` and `DB_DIG` are 18 and 15, respectively, for these formats.)
