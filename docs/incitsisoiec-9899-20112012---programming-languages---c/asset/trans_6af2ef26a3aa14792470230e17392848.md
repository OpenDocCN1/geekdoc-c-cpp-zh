

### 6.7.2.4 原子类型限定符

#### 语法

```
atomic-type-specifier:
_Atomic ( type-name )
```

#### 约束

如果实现不支持原子类型，则不应使用原子类型限定符（参见 6.10.8.3）。

原子类型限定符中的类型名不应引用数组类型、函数类型、原子类型或限定类型（qualified type）。

#### 语义

与原子类型相关的属性仅对左值（lvalues）表达式有意义。如果 _Atomic_ 关键字后紧跟一个左括号，则它被解释为类型限定符（带有类型名），而不是类型修饰符。

### 6.7.3 类型限定符

#### 语法

```
type-qualifier:
const
restrict
volatile
_Atomic
```

#### 约束

除了引用的类型为对象类型的指针类型外，都不应带有 *restrict* 限定符。

被 _Atomic_ 限定符修饰的类型不应该是数组类型或函数类型。

#### 语义

与限定类型相关的属性仅对左值（lvalues）表达式有意义。^{132}

如果同一个限定符在同一个限定符-限定符列表中出现多次（直接出现或通过一个或多个 typedef 出现），其行为与出现一次相同。如果限定符-限定符列表中与 _Atomic_ 限定符同时出现其他限定符，则结果类型为该经限定限定的原子类型。

如果尝试使用非 *const-* 限定类型的左值来修改由 *const-* 限定类型定义的对象，则其行为是未定义的。如果尝试使用非 *volatile-* 限定类型的左值来引用一个由 *volatile-* 限定类型定义的对象，则其行为是未定义的.¹133)

具有 *volatile-* 限定类型的对象可能会以实现所所未知的方式被修改，或产生其他未知的副作用。因此，任何引用此类对象的表达式都应严格按照 5.1.2.3 的抽象机器规则进行求值。此外，在每个序列点（sequence point），对象中存储的值应与抽象机器规定的值一致，但前述未知因素的修改除外.¹134 对具有 *volatile-* 限定类型的对象的访问是由实现定义的。

通过 *restrict-* 限定的指针访问的对象与该指针有特殊的关联。这种关联在下文 6.7.3.1 中定义，要求对该对象的所有访问都必须直接或间接地使用该特定指针的值.¹135 使用 *restrict* 限定符的意图（类似于 register 存储类）是为了促进优化，并且从组成合规程序的所有预处理单元中删除该限定符的所有实例不会改变其含义（即可观察的行为）。

如果数组类型的规范包含任何类型限定符，则元素类型是经此类限定的，而不是数组类型。如果函数类型的规范包含任何类型限定符，则其行为是未定义的.¹136)

为了使限定类型相互兼容，两者都应具有兼容类型的完全相同的限定版本；在限定符-限定符-列表列表中，类型限定符的顺序不影响指定的类型。

示例 1 一个声明的对象

```
extern const volatile int real_time_clock;
```

> 133 这适用于那些行为上类似于使用限定类型定义的对象，即使它们在程序中从未被实际定义为对象（例如内存映射输入/输出地址处的对象）。

> 134 一个 *volatile* 声明可用于描述对应内存映射输入/输出端口的对象，或由异步中断函数访问的对象。对对象的的操作不应被实现“优化掉”或重新排序，除非符合求值规则的允许。

> 135 例如，一个通过 `malloc` 分配值赋值给单个指针的语句确立了分配对象与指针之间的这种关联。

> 136 这两种情况都可以通过使用 typedef 实现。

示例 2 声明和表达式说明了类型限定符修饰聚合类型时的行为：

```
const struct s { int mem }; cs = { 1 };
struct ncs // 对象 ncs 是可修改的
typedef int A[2];
const A a = {{4, 5, 6}, {7, 8, 9}}; // const int 数组数组
int *pi;
const int *pci;

ncs = cs; // 有效
cs = ncs; // 违反 = 的可修改左值约束
pi = &ncs.mem; // 有效
pi = &cs.mem; // 违反 = 的类型约束
pci = &cs.mem; // 有效
pi = a[0]; // 无效：a[0] 的类型为 "const int *"
```

示例 3 声明

```
_Atomic volatile *p;
```

指定 p 的类型为“指向 volatile 原子 int 的指针”，即一个指向 *volatile-* 限定的原子类型的指针。

## 6.7.3.1 restrict 的形式化定义

令 D 为普通标识符的声明，该声明提供了一种将对象 P 指定为类型 T 的 *restrict-* 限定的指针的方法。

如果 D 出现在块内部且不具有存储类 *extern*，则令 B 表示该块。如果 D 出现在函数定义的参数声明列表中列表中，令 B 表示相关的块。否则，令 B 表示 `main` 块（或在无标准环境中，程序启动时调用的任何函数的块）。

在下文中，如果指针表达式 E 被认为是“基于”对象 P 的，如果（在求值 E 之前 B 执行的某个序列点）将 P 修改为其以前指向的数组对象的副本会改变 E 的值。(137) 注意，“基于”仅对指针类型的表达式有定义。

在 B 的每次执行期间，令 L 表示 L 已绑定（bound）到 P。如果使用 L 来访问它指向的对象 X 的值，且 X 也被修改（通过某种方式），则适用以下要求：T 不应是 *const-* 限定的。每个其他左值的地址也应绑定到 P。出于此类子类的目的，任何修改 X 的访问都应被视为修改了 P。如果 P 被赋值为基于另一个受限制指针 P2（与块 B2 关联）的指针表达式 E 的值，则 B2 的执行要在 B 的执行之前开始，或者在赋值之前结束。如果未满足这些要求，则行为是未定义的。

> 137 换句话说，E 依赖于 P 的值，而不是通过 P 间接引用的对象的值。例如，如果标识符类型为 (**restrict**)，那么指针表达式 p 和 p+1 基于 p 指定的受限制对象，但指针表达式 *p 和 p[1] 不是。

5 B 的执行意味着程序执行中对应于标量类型具有自动存储期的对象的部分。

6 翻译器可以忽略 *restrict* 使用的所有别名影响。

7 示例 1 文件作用域声明

```
int * restrict a;
int * restrict b;
extern int c[];
```

断言如果使用 a、b 或 c 访问了某个对象，且该对象在程序的任何地方被修改，则从未被另外两个访问。

8 示例 2 此示例中的函数声明

```
void f(int n, int * restrict p, int * restrict q)
{
    while (n-- > 0)
        *p++ = *q++;
}
```

断言在函数的每次执行期间，如果通过一个指针参数访问对象，则不通过另一个访问。

9 *restrict* 限定符的好处是它们允许翻译器在不检查程序中任何 f 调用的情况下对 f 进行有效的依赖分析。代价是程序员必须检查所有的调用以确保没有给定的未定义行为。例如，f g 的第二次调用具有未定义行为，因为 d[1] 到 d[49] 的每个元素都被通过 p 和 q 访问。

```
void g(void)
{
    extern int d[100];
    f(50, d + 50, d); // 有效
    f(50, d + 1, d); // 未定义行为
}
```

10 示例 3 函数参数声明

```
void h(int n, int * restrict p, int * restrict q, int * restrict r)
{
    int i;
    for (int i = 0; i < n; i++)
        p[i] = q[i] + r[i];
}
```

说明了未修改的对象如何可以通过两个受限制指针产生别名。特别是，如果 a 和 b 是不交的数组，则形式为 h(100, a, b, b) 的调用具有定义行为，因为数组 b 在函数 h 中没有被修改。
