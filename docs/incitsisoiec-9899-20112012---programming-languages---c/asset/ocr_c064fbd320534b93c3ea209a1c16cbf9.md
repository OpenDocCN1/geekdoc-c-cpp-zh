4 Likewise, a error occurs if the mathematical result of the function cannot be represented in an object of the specified type, due to extreme magnitude.

5 A floating point overflows if the magnitude of the mathematical result is finite but so large that the mathematical result cannot be represented without extraordinary roundoff error in an object of the specified type. If a floating point overflows and default rounding error is in effect, the function returns the value of the macro HUGE_VAL, HUGE_VALF, or HUGE_VALL according to the return type, with the same sign as the correct value of the function; if the expression math_errhandling & MATH_ERRNO is nonzero, the integer expression errno acquires the value ERANGE; if the expression math_errhandling & MATH_ERREXCEPT is nonzero, the “overflow” floating-point exception is raised.

6 The result underflows if the magnitude of the mathematical result is so small that the mathematical result cannot be represented, without extraordinary roundoff error, in an object of the specified type.(232) If the result underflows, the function returns an implementation-defined value whose magnitude is no greater than the smallest normalized positive number in the specified type; if the expression math_errhandling & MATH_ERRNO is nonzero, whether errno acquires the value ERANGE is implementation-defined; if the expression math_errhandling & MATH_ERREXCEPT is nonzero, whether the “underflow” floating-point exception is raised implementation-defined.

7 If a domain, pole, or range error occurs and the expression math_errhandling & MATH_ERRNO is zero,(233) then errno shall either be set to the value corresponding to the error or left unmodified. If no such error occurs, errno shall be left unmodified regardless of the setting of math_errhandling.

232) The term underflow here is intended to encompass both “gradual underflow” as in IEC 60559 and also “flush-to-zero” underflow.

233) Math errors are being indicated by the floating-point exception flags rather than by errno.
