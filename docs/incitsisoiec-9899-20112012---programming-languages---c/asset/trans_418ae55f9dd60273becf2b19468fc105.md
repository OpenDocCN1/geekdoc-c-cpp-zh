

## H.3 通知 (Notification)

通知是告知用户或程序发生了异常算术操作的过程。C 语言的操作与 LIA–1 兼容，这是因为 C 允许实现在当任何算术运算返回 LIA–1 第 5 节定义的异常值时，创建一个发生触发的通知。

### H.3.1 通知的替代方案

- LIA–1 要求至少提供以下两种处理通知的替代方案：设置指示器（indicators）或陷获并终止（trap-and-terminate）。LIA–1 允许第三种替代方案：陷获并恢复（trap-and-resume）。

- 实现仅需对整个程序支持给定的通知替代方案。实现可以支持在执行期间切换不同通知替代方案的能力，但并不要求这样做。实现可以为每种类型的通知提供单独的选择，但这并非强制要求。

- C 允许实现提供通知。C 的 SIGFPE（针对陷阱）以及 FE_INVALID、FE_DIVBYZERO、FE_OVERFLOW、FE_UNDERFLOW（针对指示器）可以提供 LIA–1 通知。

- C 的信号处理程序与 LIA–1 兼容。SIGFPE 的默认处理可以提供陷获并终止的行为，但通过数学库函数调用实现的 LIA–1 操作除外。用户提供的 SIGFPE 信号处理程序允许在相同约束下实现陷获并恢复的行为。

### H.3.1.1 指示器 (Indicators)

- C 的 <fenv.h> 状态标志与 LIA–1 指示器兼容。

以下映射适用于浮点类型：

| 类型 | 指示器 |
| :--- | :--- |
| undefined | FE_INVALID, FE_DIVBYZERO |
| floating_overflow | FE_OVERFLOW |
| underflow | FE_UNDERFLOW |

- 浮点指示器的查询和处理操作为：

`set_indicators feraisecept(i)`
`clear_indicators flecleareexcept(i)`
`test_indicators fetestexcept(i)`
`current_indicators fetestexcept(FE_ALL_EXCEPT)`

其中 i 是一个 int 类型的表达式，表示 LIA–1 指示器的子集。

C 允许实现提供以下 LIA–1 要求的行为：如果设置了任何指示器，实现应发送一条含义明确且“难以忽视”的消息（见 LIA–1 子节 6.1.2）。

LIA–1 未区分“undefined”（未定义）是浮点还是整数。本文对此进行了这种区分，是因为 <fenv.h> 仅涵盖了浮点指示器。

### H.3.1.2 陷阱 (Traps)

- C 与 LIA–1 算术运算的陷阱要求兼容，但对于数学库函数例外（这些函数不允许调用用户的 SIGFPE 信号处理程序）。实现可以提供一种带有“难以忽视”消息的通知终止的替代方案（见 LIA–1 子节 6.1.3）。

- LIA–1 不要求陷阱是精确的（precise）。

- C 要求如果为 LIA–1 算术异常提高了任何信号，则 SIGFPE 必须是相应的信号。

- C 支持 SIGFPE 的信号处理程序并允许对 LIA–1 算术异常进行陷获。当 LIA–1 算术异常触发陷阱时，C 的信号处理机制允许根据程序员的选择执行陷获并终止（默认实现行为或用户的替换）或陷获并恢复。

## 常见警告

实现在许多情况下可能会生成警告，其中任何一种均未被列为本国际标准的一部分。以下是几种较为常见的情况。

- 在函数原型中出现了新的结构体（struct）或联合体（union）类型（6.2.1, 6.7.2.3）。
- 跳入一个具有自动存储生存期的对象的初始化块（6.2.4）。
- 遇到隐式收缩转换，例如将 long int 或 double 赋值给 int，或将 void * 指针赋值给除字符类型以外的任何类型的指针（6.3）。
- 十进制浮点常数无法在它的求值格式中精确表示（6.4.2）。
- 整数常量包含一个或多个字符，或宽字符常量（wide character constant）包含一个或多个多字节字符内容（6.4.4.4）。
- 在注释中发现了字符 `/*` `（6.4.7）。
- “无序”二运算符（逗号、&& 或 || 除外）对一个操作数中的值产生副作用，并对另一个操作数中的相同值产生副作用或访问该值（6.5）。
- 调用了函数但未提供原型（6.5.2.2）。
- 函数调用中的参数在数量和类型上与非原型型函数定义中的参数不符（6.5.2.2）。
- 定义了对象但未使用使用（6.7）。
- 给枚举类型对象赋值，但不是通过赋值该枚举的成员的枚举常量，或具有相同类型的枚举对象，或返回相同类型的枚举函数（6.7.2）。
- 聚合体的部分括号初始化（6.7.8）。
- 无法到达的语句（6.8）。
- 遇到无效果语句（6.8）。
- 常量表达式作为选择语句的控制表达式（6.8.4）。
- 跳过预处理组时遇到格式错误的预处理组（6.10.1）。
- 遇到无法识别的 # 指令（6.10.6）。

## 移植性问题

本录收集了一些关于移植性的信息。以下内容未规定：

- 字符串字面量是否产生不同的数组（6.4.5）。
- 副作用发生的顺序，函数调用、&&、||、逗号运算符除外（6.5注：根据执行流对齐）
- 函数调用中函数名、参数以及参数内部子表达式的求值顺序（6.5）。
- 复合字面量初始化中的副作用顺序（6.5.2.5）。
- 赋值运算符的操作数的求值顺序（6.16）。
- 用于位域的存储单元对齐（6.7.2.1）。
- 调用内联函数使用的是内联定义还是外部定义（6.7.4）。
- 当尺寸表达式是 `sizeof` 运算符的一部分且改变其值不会影响结果时，是否进行求值（6.7.6.2）。
- 初始化列表中副作用的顺序（6.7.9）。
- 函数参数的布局（6.9.1）。
- 当完全展开宏替换列表包含函数宏名称作为最后一个标记，且源文件的下一个预处理标记为 `(`，而该宏的完全展开以第一个宏的名字结尾且源文件的下一个预处理标记再次为 `(` 时，这是否被视为嵌套替换（6.10.3）。
- 宏替换期间 # 和 ## 运算的评估顺序（6.10.3.2, 6.10.3.3）。
- 执行从翻译为 `FENV_ACCESS "off"` 的部分传递到翻译为 `FENV_ACCESS "on"` 的部分时，浮点状态标志的状态（7.6.1）。
- `feraiseexcept` 产生浮点异常的顺序，如 F.8.6 所示（7.6.2.3）。
- `frexp` 函数在指定值不是浮点数时的结果（7.12.6.4）。
