## K.3.4 Integer types <stdint.h>

The header <stdint.h> defines a macro.

The macro is

```
RSIZE_MAX
```

which expands to a value.³386) of type size_t. Functions that have parameters of type rsize_t consider it a runtime-constraint violation if the values of those parameters are greater than RSIZE_MAX.

## Recommended practice

Extremely large object sizes are a frequent sign that an object's size was calculated incorrectly. For example, negative numbers appear as very large positive numbers when converted to an unsigned type size_t. Also, some implementations do not support objects as large as the maximum value that can be represented by size_t.

For those reasons, it is sometimes beneficial to restrict the range of object sizes to prevent programming errors. For implementations targeting machines with large address spaces, it is recommended that RSIZE_MAX be defined as the smaller of the largest object supported or (SIZE_MAX >> 1), if this limit is smaller than the size of some legitimate, but very large, Implementations targeting small address spaces may use RSIZE_MAX as SIZE_MAX, which means that is no size that is considered a runtime-constraint violation.

384) As a matter of programming, errno may be used as something that deals only with the values that might be found in errno. For example, a function that returns the value of errno might be declared as having the return type errno_t.

## K.3.5 Input/output <stdio.h>

The header <stdio.h> defines several macros and two types.

The macros are

- L__tmpnam_s which expands to an integer constant expression that is the size needed for an array of char large enough to hold a temporary name string generated by the tmpnam_s function;
- TMP_MAX_S which expands to an integer constant expression that is the maximum number of unique file names that can be generated by the tmpnam_s function.

The types are

- errno_t which is type int; and
- rsize_t which is the type size_t.

## K.3.5.1 Operations on file

### K.3.5.1.1 The tmpfile_s function

#### Synopsis

```
#define __STDC_WANT_LIB_EXT1__ 1
#include <stdio.h>
errno_t tmpfile_s(FILE * restrict * restrict streamptr);
```

#### Runtime-constraints

- streamptr shall not be a null pointer.

If there is a runtime-constraint violation, tmpfile_s does not attempt to create a file.

#### Description

The tmpfile_s function creates a temporary binary file that is different from any other existing file and will automatically be removed when it is closed or at program termination. If the program terminates abnormally, whether an open temporary file is removed is implementation-defined. The file is opened for update with "wb" mode with the meaning that mode has in the fopen_s function (including the mode's effect on exclusive access and file permissions).

If the file was created successfully, the pointer to FILE pointed by streamptr will be to the object controlling the opened file. Otherwise, the pointer to FILE pointed by streamptr will be set to a null pointer.

#### Recommended practice

It should be possible to open at TMP_MAX_S temporary files during the lifetime of the program and there should be no limit on the number simultaneously open other than this limit and any limit on the number of open files (FOPEN_MAX).

#### Returns

+ The tmpnam_s function returns zero if it created the file. If it did not create the file or there was a runtime-compliance violation, tmpfile_s returns a nonzero value.

## K.3.5.1.2 The tmpnam_s function 

#### Synopsis

```
#define __STDC_WANT_LIB_EXT1__ 1
#include <stdio.h>
errno_t tmpnam_s(char *s, rsize_t maxsize);
```

#### Runtime-constraints

+ s shall not be a null pointer. maxsize shall be less than or equal to RSIZE_MAX maxsize shall be greater than the length of the generated file name string.

#### Description

+ The tmpnam_s function generates a string that is a valid file name and is not the same as the name of an existing file. The function is potentially capable of generating TMP_MAX_S different strings, but any or all of them may already be in existing files and thus not be suitable return values. The lengths of these strings shall be less than the value of the L_tmpnam_s macro.

+ The tmpnam_s function generates a different string each time it is called.

+ It is assumed that s points to an array of let maxsize characters. This array will be set to generated string, as specified below.

> 387) Files created using strings by the tmpnam_s function are temporary only in the sense that their names do not collide with those generated by conventional naming rules for the implementation. It is still necessary to use remove to delete such files.

#### Recommended practice

After a program obtains a filename using tmpnam_s and before the program creates a file, the possibility exists that someone else creates a file with that name. To avoid this race condition, tmpfile_s should be used instead.

#### Returns

If no suitable string can be generated, or if there is a runtime-constraint violation, tmpnam_s function writes a null character to s[0] and returns a nonzero value.

Otherwise, tmpnam_s function writes the string to s and returns zero.

#### Environmental limits

The value of the macro TMP_MAX_S shall be at least 2.

## K.3.5.2 File access

### K.3.5.2.1 The fopen_s function

#### Synopsis

```
#define __STDC_WANT_LIB_EXT1__ 1
#include <stdio.h>
errno_t fopen_s(FILE * restrict * restrict streamptr,
               const char * restrict filename,
               const char * restrict mode);
```

#### Runtime-constraints

None of streamptr, filename, or mode shall be a null pointer.

If there is a runtime-constraint violation, fopen_s does not attempt to open a file. Furthermore, if streamptr is not a null pointer, fopen_s sets *streamptr to the null pointer.

> 388) An implementation may have tmpnam for temporary files, but this is not required.

#### Description

The fopen_s function opens the file whose name is the string pointed to filename, and associates a stream as described for fopen, with the addition that modes starting with 'w' or 'a' may be preceded by the character 'u', see below:

- uw truncate to zero length or create text file for writing, default permissions
- uwx create text file for writing, default permissions
- ua append; open or create text file for writing at end-offile, default permissions
- uwb truncate to zero length or create binary file for writing, default permissions
- ubwx create binary file for writing, default permissions
- uab append; open or create binary file for writing at end-offile, default permissions
- uw+ truncate to zero length or create text file for update, default permissions
- uw+x create text file for update, default permissions
- ua+ append; open or create text file for update, writing at end-offile, default permissions
- uw+b or uw+b truncate to zero length or create binary file for update, default permissions
- uw+bx or uw+bx create binary file for update, default permissions
- ua+ or uab+ append; open or create binary file for update, writing at end-offile, default permissions

To the extent that the underlying system supports the concepts, files opened for writing shall be opened with exclusive (also known as non-shared) access.
