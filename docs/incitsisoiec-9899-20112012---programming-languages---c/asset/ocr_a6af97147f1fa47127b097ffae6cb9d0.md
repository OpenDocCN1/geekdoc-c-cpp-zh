# F.8.6 Changing the environment

Operations defined in 6.5 and macros defined for the standard libraries change floating-point status flags and control modes just as indicated by their modes (including conformance to IEC 60559). They do not change flags or modes (as to be detectable by the user) in any other cases.

If the feraiseexcept in <fenv.h> represents IEC 60559 valid coincident floating-point exceptions for atomic operations (namely "overflow" and "inexact"), or "underflow" and "inexact", then "overflow" or "underflow" is raised before "inexact".

# F.9 Optimization

This section identifies code transformations that might subvert IEC 60559-specified behavior, and others that do not.

# F.9.1 Global transformations

Floating-point arithmetic operations and external function calls may entail side effects which optimization might fail honor, at least where the state of the FENV_ACCESS pragma is "on". The flags and modes in the floating-point environment may be regarded as global variables; floating-point operations (+, *, etc.) implicitly read the modes and write the flags.

Concern about side effects may inhibit code motion and removal of seemingly useless code. For example,

```
#include <fenv.h>
#pragma STDC FENV_ACCESS ON
void f(double x)
{
    /* ... */
    for (i = 0; i < n; i++) x = x + 1;
    /* ... */
}
```

x + 1 might raise floating-point exceptions, so cannot be removed. And since the loop body might not execute (maybe 0 ≥ n), x + 1 cannot be moved out of the loop. (Of these optimizations are valid if the implementation can rule out the nettlesome cases.)

This specification does not require support for trap handlers that maintain information about the order or count of floating-point exceptions.
