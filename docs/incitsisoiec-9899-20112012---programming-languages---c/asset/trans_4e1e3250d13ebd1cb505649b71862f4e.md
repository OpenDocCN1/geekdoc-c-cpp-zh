

```c
extern int max(a, b)
int a, b;
{
    return a > b ? a : b;
}
```

这里的 `a, b` 是参数的声明列表。这两种定义的区别在于：第一种是原型声明，它会强制对后续函数调用的参数进行转换；而第二种则不会。

示例 2 将一个函数传递给另一个函数，可以说：

```c
int f(void);
/* ... */
g(f);
```

那么 `g` 的定义可能是：

```c
void g(int (*funcp)(void))
{
    /* ... */
    (*funcp)(); /* * or funcnp ((); ... * */
}
```

或者，等价地：

```c
void g(int func(void))
{
    /* ... */
    func(); /* * or (*func) ((); ... * */
}
```

## 6.9.2 外部对象定义

## 语义

如果对象的标识符声明具有文件作用域且有一个初始化，则该声明是该标识符的外部定义。

如果具有文件作用域的对象的标识符声明没有初始化，且没有存储类限定符，或具有存储类限定符 `static`，则构成尝试定义。如果一个翻译单元包含一个或多个针对同一标识符的尝试定义，且该翻译单元不包含该标识符的外部定义，则其行为恰如该翻译单元包含该标识符的文件作用域声明，其复合类型作为翻译单元的结束，初始化值为 0。

如果对象的标识符声明是一个尝试定义且具有内部链接，则所声明的类型不应是不完全类型。

## 示例 1

```c
int i1 = 1;               // 定义，外部链接
static int i2 = 2;   // 定义，内部链接
extern int i3 = 3;   // 定义，外部链接
int i4;                // 尝试定义，外部链接
static int i5;          // 尝试定义，内部链接

int i1;                 // 有效尝试定义，引用上一个
int i2;                 // 6.2.2 指未定义，链接冲突
int i3;                 // 有效尝试定义，引用上一个
int i4;                 // 有效尝试定义，引用上一个
int i5;                 // 6.2.2 指未定义，链接冲突

extern int i1;         // 引用上一个，链接为外部
extern int i2;         // 引用上一个，链接为外部
extern int i3;         // 引用上一个，链接为外部
extern int i4;         // 引用上一个，链接为外部
extern int i5;         // 引用上一个，链接为内部
```

## 示例 2 如果在翻译单元末尾包含

```c
int i[];
```

数组 `i` 仍然是不完全类型，则隐式初始化会导致它拥有一个元素，该元素在程序启动时被设置为零。

## 描述

预处理器指令由一系列预处理器标记组成，这些标记满足以下约束：序列中的第一个标记是 `#` 预处理器标记，它（在翻译阶段 4 刚时）要么是源文件的第一个字符（可选地跟在不包含换行符的空白之后），要么紧跟在包含至少一个换行符的空白之后。序列中的最后一个标记是紧随序列中第一个标记的换行符。¹65) 换行符会结束预处理器指令，即使它出现在本应是另一行的内容内部。

因此，预处理器指令通常被称为“行”。这些“行”没有语法意义，因为在预处理期间的某些情况下（例如参见 6.10.32 中的 `#` 字符串字面量创建运算符），所有的空白都是等价的。

> 165) **类函数宏的调用。**

文本行不应以 `#` 预处理器标记开头。非指令项不应以语法中出现的任何指令名称开头。

当一个组被跳过时（6.10.1），指令语法会被放宽，允许在指令名称和随后的换行符之间出现任何预处理器标记。

## 约束

在预处理器指令内部，预处理器标记之间允许出现的空白字符（从引言的 `#` 预处理器标记之后到直到结束的换行符之前）仅限于空格和水平制表符（包括在翻译阶段 3 中替换了注释或可能的其他空白字符的空格）。

## 语义 

实现可以根据条件条件处理和跳过源文件的某些部分，包含其他源文件，并替换宏。这些能力被称为预处理，因为从概念上讲，它们发生在生成的翻译单元进行翻译之前。

预处理器指令内的预处理器标记除非另有说明，否则不受宏展开的影响。

示例 输入：

```c
#define EMPTY
EMPTY # include <file.h>
```

第二行上的预处理器标记序列不是预处理器指令，因为它在翻译阶段 4 刚开始时不是以 `#` 开头的，尽管在宏 `EMPTY` 被替换后它会变成。

在求值之前，位于控制表达式中的预处理器标记列表中的宏调用将被替换（除了由 `defined` 元运算符命名的宏），就像在普通文本中一样。在此替换过程中生成了标记，或者在使用 `defined` 元运算符之前不符合指定的格式之一，则行为是未定义的。在宏展开和 `defined` 元运算符的操作后，所有剩余的标识符（包括词法上与关键字相同的标识符）都被替换为 `pp-0`，然后每个预处理器标记转换为标记。生成的标记构成了控制表达式，并根据 6.6 的规则进行求值。为了这些标记转换和求值，所有符号整数类型和无符号整数类型都像头文件中定义的 `intmax_t` 和 `uintmax_t` 类型一样解释字符常量，这可能涉及将转义序列转换为字符集成员。这些字符常量的数值与在表达式（除 `#if` 或 `#elif` 指令之外）中相同字符的值匹配是实现定义的¹⁶⁸。此外，单字符常量是否可以负值是实现定义的。

> 167) 因此，在一种 `INT_MAX` 为 0x7FFF 且 `UINT_MAX` 为 0xFFFF 的实现上，0x8000 在 `#if` 表达式内部是符号正正的，尽管它在翻译阶段 7 中是无符号的。
