# H.2.4 Type conversions

The LIA–1 type conversions are the following casts:

```
cvtI -> I    (int) i, (long int) i, (long long int) i,
               (unsigned int) i, (unsigned long int) i,
               (unsigned long long int) i
ccvtF -> I    (int)x, (long int)x, (long long int)x,
               (unsigned int)x, (unsigned long int)x,
               (unsigned long long int)x
ccvtI -> F    (float) i, (double) i, (long double) i
ccvtF -> F    (float)x, (double)x, (long double)x
```

In the above conversions (casts) to floating, the use of (cast) x can be replaced with (cast) round(x), (cast) rist(x), (cast) nearbyint(x), (cast) trunc(x), (cast) ceil(x), or (cast) floor(x). In addition, C’s floating-point to integer conversion functions, lrint(x), llrint(x), lround(x), and llround(x), can be used. They all meet LIA–1’s requirements on floating-point to integer rounding for in-range values. For out-of-range values, the conversions shall silently wrap for the modulo types.

The fmod(x) function is useful for doing signed wrap to unsigned integer types, e.g., fmod(fabs(x), 65536.0) or (0.0 <= (y = fmod(rint(x), 65536.0)) ? y : 65536.0 + y) will compute an integer value in the range 0 to 65535.0 which can be cast to unsigned short int. But, the remainder(x) function is not useful for doing signed wrap to signed integer types, e.g., remainder(rint(x), 65536.0) will compute an integer value in the range -32767.0 to +32768.0 which is not, in general, in the range of signed short int.

C’s conversions (casts) from floating-point to floating-point can meet LIA–1 requirements if an implementation uses round-to-nearest (IEC 60559 default).

C’s conversions (casts) from integer to floating-point can meet LIA–1 requirements if an implementation uses round-to-nearest.
