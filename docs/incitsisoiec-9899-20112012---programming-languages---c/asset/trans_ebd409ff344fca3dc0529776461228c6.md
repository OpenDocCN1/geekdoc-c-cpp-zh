

# 各种形式的预处理指令

```
# ifdef identifier new-line group_opt
# ifndef identifier new-line group_opt
```

检查标识符当前是否未定义为宏名。它们的条件分别等于 **#if defined identifier** 和 **#if !defined identifier**。

每个指令的条件按顺序进行检查。如果其结果为假（零），则其控制的组将被跳过；指令仅通过确定该指令的名称进行处理，以跟踪嵌套指令的层级；其他指令的预处理标记将被忽略，该组中的其他预处理标记也也会被忽略。只有第一个控制条件求值为为真（非零）的组会被处理。如果存在 **#else** 指令，则处理由 **#else** 控制的组；缺少 **#else** 指令，则直到 **#endif** 之前的所有组都被跳过.¹169)

## 6.10.2 源文件包含

### 约束

一个 **#include** 指令应当标识一个可以由处理的头文件或源文件。

### 语义

形式如下的预处理指令

```
# include <h-char-sequence> new-line
```

在实现定义的系列位置中搜索由 **<** 和 **>** 分隔符之间的指定序列唯一标识的头文件，并将该指令替换为该头文件的全部内容。这些位置如何指定或头文件如何标识，是由实现定义的。

形式如下的预处理指令

```
# include "q-char-sequence" new-line
```

将该指令替换为由 " " 分隔符之间的指定序列所标识的源文件的全部内容。以实现的方式搜索命名的源文件。如果不支持这种搜索，或者搜索失败，则当该指令被读取时，将重新处理该指令：

```
# include <h-char-sequence> new-line
```

使用原始指令中相同的包含序列（包括 > 字符，如果有）。

> 169) 正如语法所示，在终止换行符之前，预处理标记不应跟在 **#else 或 #endif** 指令之后。然而，注释可以出现在源文件的任何位置，包括预处理指令内部。

4 形式如下的预处理指令

```
# include pp-tokens new-line
```

（不符合上述两种形式之一的）是被允许的。指令中 include 之后的预处理标记像普通文本一样被处理。（每个被明确定义为宏的标识符都被替换为其替换预处理标记列表。）所有替换后生成的指令应匹配上述两种形式之一.¹17⁰) 将 < 和 > 预处理标记对之间或一对 " 字符之间的预处理标记序列组合为单个头文件名称预处理标记的方法是由实现定义的。

5 实现应当为由一个或多个非数字或数字（6.4.2.1）后跟一个点（.）和一个单个非数字组成的序列提供唯一映射。第一个字符不应是数字。实现可以忽略字母的大小写，并将映射限制在点之前的八个有效字符内。

6 一个 #include 预处理指令可能出现在由于另一个文件中的 #include 指令而被读取的源文件中，其深度取决于实现定义的嵌套限制（见 5.2.4.1）。

7 示例 1 #include 预处理指令最常见的用法如下：

```
#include <stdio.h>
#include "myprog.h"
```

#elif VERSION = 2

#else
  #define INCFILE "versN.h"

## 6.10.3 宏替换

### 约束

- 如果两个替换列表相同当且仅当两者的预处理标记在数量、顺序、拼写和空白分隔上相同，其中所有空白分隔均被视为相同。
- 当前定义为对象类宏的标识符不应被另一个 #define 预处理指令重新定义，除非第二个定义是对象类宏定义，且两个替换列表相同。同样，当前定义为函数类宏的标识符不应被另一个 #define 预处理指令重新定义，除非第二个定义是具有相同参数数量和拼写的函数类宏定义，且两个替换列表相同。
- 在对象类宏的定义中，标识符和替换列表之间应当存在空白。
- 如果宏定义中的标识符列表不以省略号（...）结尾，则函数类宏调用中的参数数量（包括那些不包含预处理标记的参数）应等于宏定义中的参数数量。否则，调用中的参数数量多于宏定义中的参数数量（不包括 ...）。必须存在一个 ) 预处理标记来结束调用。
- 标识符 `__VA_ARGS__` 仅应出现在在参数中使用中使用省略号表示法的函数类宏的替换列表中。
- 函数类宏中的参数标识符应当在其作用域内唯一地声明。

### 语义

- 紧接在 define 之后的标识符称为宏名。宏名有一个命名空间。替换列表之前或之后的任何空白字符都不被视为替换的一部分。

8 如果一个预处理标记后跟一个标识符，在词法上出现在预处理指令可能开始的位置时，则该标识符不参与宏替换。

9 形式如下的预处理指令

```
# define identifier replacement-list new-line
```

定义了一个对象类宏，该宏导致后续每个宏名¹¹ 被替换为构成指令剩余部分的预处理标记列表。然后按照下述对替换列表进行重新扫描以查找更多宏名。

10 形式如下的预处理指令

```
# define identifier lparen identifier-list-opt ) replacement-list new-line
# define identifier Lparen ... ) replacement-list new-line
# define identifier lparen identifier-list , ... ) replacement-list new-line
```

定义了一个带有参数的函数类宏，其语法上与函数调用类似。参数由可选的标识符列表指定，其作用域从声明开始，直到换行符终止 #preprocessing 指令，随后跟随作为下一个预处理标记的 a 引入了被定义中替换列表所替换的预处理标记序列（宏调用）。被替换的预处理标记序列由匹配的 ) 预处理标记终止，跳过中间的左括号和右括号标记对。

11 由最外层匹配括号界定的预处理标记序列构成了函数类宏的参数列表。列表内部的个体通过预处理标记分隔，但匹配内括号之间的逗号预处理标记并不分隔参数。如果存在预处理指令序列¹² 行为是未定义的。
