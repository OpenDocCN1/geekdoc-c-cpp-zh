13 The storage-class specifier in the declaration specifiers for a parameter declaration, if present, is ignored unless the declared parameter is one of the members of the parameter type list for a function definition.

14 An identifier list declares only the identifiers of the parameters of the function. An empty list in a function declarator that is part of a definition of that function specifies that the function has no parameters. 15 For two function types to be compatible, both shall specify compatible return types. Moreover, the parameter type list, if both are present, shall agree in the number of parameters and in use of the ellipsis terminator; corresponding parameters shall have compatible types. If one type has a parameter type list and the other is specified by a function declarator that is not part of a function definition and contains an empty identifier list, the parameter list shall not have an ellipsis terminator and the type of each parameter shall be compatible with the type that results from the application of the default argument promotions. If one type has a parameter type list and the other type is specified by a function definition that contains a (possibly empty) identifier list, both shall agree in the number of parameters, and the type of each prototype parameter shall be compatible with the type that results from the application of the default argument promotions to the type of the corresponding identifier. In the determination of type compatibility and of composite type, each parameter declared with function or array type is taken as the adjusted type and each parameter declared with qualified type is taken as the unqualified version of its declared type.

16 EXAMPLE 1 The declaration

```
int f(void), *fip(), (*pfi);
```

declares a function f with no parameters returning an int, and a pointer pfi to a function with no parameter specification returning a pointer to an int. It is especially useful to compare the two. The binding of *fip is *(f()), so that the declaration suggests, and the same construction in an expression requires, the calling of a function fip, and then indirection through the pointer to yield an int. In the declarator (*pfi)(), the extra parentheses are necessary to indicate that indirection to a pointer yields a function; returns an int. See “future language” (6.1.6). If both function types are “old style”, parameter types are not compared. If the declarator occurs outside of any function, the identifiers have file scope and external link. If the declaration occurs inside a function, the identifiers of f and fip have file scope or external link depending on what file scope declarations for these identifiers are visible, and the identifier of pfi has file scope and no linkage.

EXAMPLE 2 The declaration

```
int (*pfi[3]) (int *x, int *y);
```

declares an array pfi of three pointers to functions returning int. Each of the functions has two parameters that are pointers to int. The identifiers x and y are declared for descriptive only and go out of scope at the end of the declaration of pfi.

EXAMPLE 3 The declaration

```
int (*pfi) (*long), int), ...);
```

declares a function fpfi that returns a pointer to a function returning int. The function fpfi has two parameters: a pointer to a function returning int (with one parameter type long), and an int. The pointer returned by fpfi points to a function that has one parameter and accepts zero or more arguments of any type.

void addscalar(int n, int m, double a[n][m], double x);

## 6.7.7 Type names

### Syntax

```
type-name:
  specifier-qualifier-list abstract-declarator-declarator_opt
abstract-declarator:
  pointer
    pointer_opt direct-abstract-declarator
direct-declarator:
  ( abstract-declarator )
  direct-abstract-declarator_opt [ type-qualifier-list_opt
    assignment-expression_opt ]
  direct-abstract-declarator_opt [ static type-qualifier-list_opt
    assignment-expression ]
  direct-abstract-declarator_opt [ type-qualifier-list static
    assignment-expression ]
  direct-abstract-declarator_opt [ * ] ( parameter-type-list_opt )
```

### Semantics

In several contexts, it is necessary to specify a type. This is accomplished using a type name, which is syntactically, empty declaration for a function or an object of that type that omits the identifier.¹

### EXAMPLE The constructions

- (a) int
- (b) int *
- (c) int *[3]
- (d) int (*) [3]
- (e) int (*) [*]
- (f) int *
- (g) int (*) (void)
- (h) int (*const [1]) (unsigned int, ...)

respectively the types (a) int, (b) pointer to int, (c) array of three pointers to int, (d) pointer to array of three ints, (e) pointer to variable length of unspecified number of ints, (f) function with no parameter specification returning a pointer to int. (g) pointer to function with no returning an int, and array of an unspecified number of constant pointers to functions, each with one parameter that has type unsigned int and an unspecified number of other parameters, returning an int.

> ¹147 As indicated by, empty parentheses in a name are interpreted as “function with no parameter specification”, rather than redundant parentheses around the omitted identifier.

## 6.7.8 Type definitions

### Syntax

```
typedef-name:
    identifier
```

### Constraints

If a typedef name specifies a variably modified type then it shall have block scope.

### Semantics

In a declaration whose storage-class specifier is typedef, each declarator defines an identifier to be a typedef name that denotes the type for the identifier in the way described in 6.7.6. Any array size expressions associated with variable length declarators are evaluated each time the typedef name is reached. A typedef declaration does not introduce a new type, only a synonym for the type specified. That is, in the following declarations:

```
typedef T type_ident;
type_ident D;
```

type_ident is defined as a typedef name with the type specified by the declaration specifiers in T (known as T), and the identifier in D has the type “derived-declarator-type-list” where the derived-declarator-type-list is specified by the declarators of D.

typedef struct s1 { int x; } t1, *tp1;
