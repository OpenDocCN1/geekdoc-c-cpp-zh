If the expression P points to an element of an array object and the expression Q points to the last element of the same array object, the pointer expression Q+1 compares greater than P. ## 6.5.9 Equality operators

### Syntax

```
equality-expression:
relational-expression == relational-expression
equality-expression != relational-expression
```

### Constraints

One of the following shall hold:

- both operands have arithmetic type;
- both operands are pointers to qualified or unqualified versions of compatible types;
- one operand is a pointer to an object and the other is a pointer to a qualified or unqualified version of void; or
- one operand is a pointer and the other is a null pointer constant.

### Semantics

The == (equal to) and != (not equal to) operators are analogous to the relational operators except for their lower precedence. (108) Each of the operators yields 1 if the specified relation is true and 0 if it is false. The result has type int. For any pair of operands, exactly one of the relations is true.

If both of the operands have arithmetic type, the usual arithmetic conversions are performed. Values of complex types are equal if and only if their real parts are equal and also their imaginary parts are equal. Any two of arithmetic types from different types are equal if and only if the results of their conversions to the (complex) result type determined by the usual arithmetic conversions are equal.

> 107 The expression a<b<c is not interpreted in mathematics. As the syntax indicates, it means (a<b)<c; in other words, "if a is less than b, compare 1 to c; otherwise, compare 0 to c".

> 108 Because of the precedence, a<b == c<d is whenever a<b and c<d have the same truth-value.

Otherwise, at least one operand is a pointer. If one operand is a pointer and the other is a null constant, the null constant is converted to the type of the pointer. If one operand is a pointer to an object type and the other is a pointer to a qualified or unqualified version of void, the former is converted to the type of the latter.

Two pointers compare equal if and only if both are null pointers, both are pointers to the same object (including a pointer to an object and a subobject of its beginning) or function, both are pointers to one past the last element of the same array object, or one is a pointer to past the end of any array object and the other is a pointer to the start of a different array object that happens to immediately follow the first array object in the address space.

For the purposes of these operators, a pointer to an object that is not an element of an array behaves the same as the first element of an array of length one with the type of the object as its element type.

## 6.5.10 Bitwise AND operator

### Syntax

```
AND-expression:
  equality-expression
  AND-expression & equality-expression
```

### Constraints

Each of the operands shall have integer type.

### Semantics

The usual arithmetic conversions are performed on the operands.

The result of the binary & operator is the bitwise AND of the operands (that is, each bit in the result is set if and only if each of the operands is set).

> 109 Two objects may be adjacent in memory because they are adjacent elements of a larger array or members of a structure, even though they are unrelated. If prior operations (such as accesses outside array bounds) produce undefined behavior, subsequent comparisons also produce undefined.

Otherwise, at least one operand is a pointer. If one operand is a pointer and the other is a null constant, the null constant is converted to the type of the pointer. The usual arithmetic conversions are performed on the operands. The result of the binary & operator is the bitwise AND of the operands (that is, each bit in the result is set if and only if each of the operands is set).

## Bitwise exclusive OR operator

### Syntax

```
exclusive-expression:
  equality-expression
  exclusive-expression ^ equality-expression
```

### Constraints

Each of the operands shall have integer type.

### Semantics

The usual arithmetic conversions are performed on the operands.

The result of the binary ^ operator is the bitwise XOR of the operands (that is, each bit in the result is set if and only if exactly one of the operands is set).

## Bitwise inclusive OR operator

### Syntax

```
inclusive-expression:
  equality-expression
  inclusive-expression | equality-expression
```

### Constraints

Each of the operands shall have integer type.

### Semantics

The usual arithmetic conversions are performed on the operands.

The result of the binary | operator is the bitwise OR of the operands (that is, each bit in the result is set if and only if at least one of the operands is set).

## Logical AND operator

### Syntax

```
and-expression:
  or-expression
  and-expression && or-expression
```

### Constraints

Each of the operands shall have scalar type.

### Semantics

The usual arithmetic conversions are performed on the operands.

The result of the binary && operator yields 1 if both of the operands are unequal; otherwise, it yields 0. The result has type int.

## Logical OR operator

### Syntax

```
or-expression:
  and-expression
  or-expression || and-expression
```

### Constraints

Each of the operands shall have scalar type.

### Semantics

The usual arithmetic conversions are performed on the operands.

The result of the binary || operator yields 1 if either of the operands are unequal; otherwise, it yields 0. The result has type int.

## Conditional operator

### Syntax

```
conditional-expression:
  or-expression
  or-expression : conditional-expression
```

### Constraints

The first operand shall have scalar type.

One of the following shall hold for the second and third operands:

- both operands have arithmetic type;
- both operands have the same structure or union type;
- both operands have void type;
- both operands are pointers to qualified or unqualified versions of compatible types;
- one operand is a pointer and the other is a null pointer constant;
- one operand is a pointer to an object type and the other is a pointer to a qualified or unqualified version of void.

### Semantics

The first operand is evaluated; there is a sequence point between its evaluation and the evaluation of the second or third operand (whichever is evaluated). The second operand is evaluated only if the first compares equal to 0; the third operand is evaluated only if the first compares non-zero. The result is the value of the second or third operand (whichever is evaluated), converted to the type below.

If the second and third operands have arithmetic type, the result type that would be determined by the usual arithmetic conversions, were they applied to those two operands, is the type of the result. If both operands have structure or union type, the result has that type. If both operands have void type, the result has void type.
If the second and third operands are pointers or a null pointer constant and the other is a pointer, the result type is a pointer to a type qualified with all the qualifiers of the types referenced by both operands. Furthermore, if both operands are pointers to compatible types or to differently qualified versions of compatible types, the result type is a pointer to an appropriately qualified version of the composite type; if one operand is a null pointer constant, the result has type of the other operand; otherwise, one operand is a pointer to void or a qualified version of void, in which case the result type is a pointer to an appropriately qualified version of void.

> ¹ A conditional expression does not yield an Ivalue.
