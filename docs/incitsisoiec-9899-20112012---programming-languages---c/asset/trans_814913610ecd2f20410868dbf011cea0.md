## 7.1.3 保留标识符

每个头文件声明或定义了其相关子句中列出的所有标识符，并可选地声明或定义与其相关的未来库方向子句列出的标识符，以及始终保留用于任何用途或作为文件范围标识符的标识符。

- 所有以下划线开头且紧跟大写字母或另一个下划线的标识符均始终保留用于任何用途。
- 所有以下划线开头的标识符在普通命名空间和标签命名空间中均始终保留用于作为文件范围标识符。
- 下述任何子句（包括未来库方向）中的每个宏名称，如果包含了其相关的任何头文件，则按指定方式保留使用；除非另有明确说明（参见 7.1.4）。
- 下述任何子句（包括未来库方向）中的所有具有外部链接的标识符和 `errno` 始终保留用于具有外部链接的标识符¹184)
- 下述任何子句（包括未来库方向）中列出的每个文件范围标识符，如果包含了其相关的任何头文件，则保留在同一命名空间中作为宏名称和文件范围标识符使用。

没有其他标识符被保留。如果程序在保留标识符的范围内（7.1.4 允许之外）声明或定义了标识符，或将保留的标识符定义为宏名称，则行为是未定义的。

如果程序删除了（通过 `#undef`）上述第一组列表中标识符的任何宏定义，则行为是未定义的。

¹184) 具有外部链接的保留标识符列表包括 `math_errhandling`、`setjmp`、`va_copy` 和 `va_end`。

## 7.2 诊断 <assert.h>

头文件 `<assert.h>` 定义了 `assert` 和 `static_assert` 宏，并引用了另一个宏：

```
NDEBUG
```

该宏并非由 `<assert.h>` 定义。如果在包含 `<assert.h>` 的源文件点 `NDEBUG` 被定义为宏名，则 `assert` 宏简单地定义为：

```
#define assert (ignore) ((void) 0)
```

每次包含 `<assert.h>` 时，`assert` 宏都会根据 `NDEBUG` 的当前状态重新定义。

`assert` 宏应实现为宏，而不是实际函数。为了访问实际函数而抑制了宏定义，则行为是未定义的。

宏

```
static_assert
```

展开为 `_Static_assert`。

## 7.2.1 程序诊断

## 7.2.1.1 assert 宏

概要

```
#include <assert.h>
void assert (scalar expression);
```

描述

`assert` 宏将诊断测试放入程序中；它展开为一个 `void` 类型的表达式。当它被执行时，如果 `expression`（其类型应为标量类型）为假（即等于 0），`assert` 宏将向标准错误流以由实现定义的格式写入有关特定调用失败的信息（包括参数文本、源文件名、行号和闭包函数名称——后者分别是预处理宏 `__FILE__`、`__LINE__` 和标识符 `__func__` 的值¹191），然后调用 `abort` 函数。

写入的消息的形式可能是：

```
Assertion failed: expression, function abc, file xyz, line nnn.
```
