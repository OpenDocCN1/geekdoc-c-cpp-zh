If the input stream is parsed into preprocessing tokens up to a given character, the next preprocessing token is the longest sequence of characters that could constitute a preprocessing token. There is one exception to this rule: header name preprocessing tokens are recognized only within #include preprocessing directives and in implementation-defined locations within #pragma directives. In contexts, a sequence of characters that could be either a header name or a string literal is recognized as the former

EXAMPLE 1 The program 1Ex is parsed as a preprocessing token (one that is not a valid floating or integer token), even though a as the pair of preprocessing tokens 1 and Ex might produce a valid expression (for example, if Ex was a macro defined as +1). Similarly, the program E1Ex is parsed as a preprocessing token (one that is a valid constant token), when not E is a macro.

EXAMPLE 2 The program x++++yy is parsed as x ++ ++ +, which violates a constraint on increment operators, even though the x ++ ++ y may yield a correct expression.
