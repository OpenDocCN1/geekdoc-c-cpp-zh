
选择语句或迭代语句的表达式；

一元运算符 `!` 的操作数，其结果表达式为选择语句或迭代语句的整个控制表达式；或

表达式语句的整个表达式（可能强制转换为 void）。

如果该调用出现在任何其他上下文中，其行为是未定义的。

## 7.13.2 恢复调用环境

### 7.13.2.1 longjmp 函数

### 概要

```
#include <setjmp.h>
__noreturn void longjmp(jmp_buf env, int val);
```

### 描述

longjmp 函数恢复由程序在同一次调用中，最近一次对 `setjmp` 宏的调用所保存的环境，该调用通过相应的 `jmp_buf` 参数进行对应。如果没有发生过调用，或者该调用来自另一个执行线程，或者包含 `setjmp` 宏调用的函数在此期间已经终止了执行（² 248），或者 `setjmp` 宏的调用位于一个具有广义修改类型的标识符的作用域内，且执行在此期间已离开了该作用域，则其行为是未定义的。

所有可访问的对象都有值，且抽象机器的所有其他组件（² 249）在 `longjmp` 函数被调用时都有状态，但对于包含相应 `setjmp` 宏调用的函数中的局部自动存储生存期的对象，如果它们不具有 `volatile` 修饰类型，且在 `setjmp` 调用和 `longjmp` 调用之间发生了变化，则其值是不确定的。

### 返回

在 `longjmp` 完成后，线程执行继续，就像相应的 `setjmp` 宏调用刚刚返回了由 `val` 指定的值一样。longjmp 函数无法导致 `setjmp` 宏返回值 0；如果 `val` 为 0，则 `setjmp` 宏返回值 1。

示例 longjmp 函数将控制权交回 `setjmp` 调用点可能会导致与变长数组对象相关的内存被压缩。

> 248) 例如，执行 `return` 语句或另一个 `longjmp` 导致跳转到嵌套调用集中较早函数中的 `setjmp` 调用。

> 249) 这包括但不限于浮点状态标志和已打开文件的状态。

```
#include <setjmp.h>
jmp_buf buf;
void g(int n);
void h(int n);
int n = 6;

void f(void) {
    int x[n]; // 有效: f 未终止
    setjmp(buf);
    g(n);
}

void g(int n) {
    int a[n]; // a 可能会保持分配状态
    h(n);
}

void h(int n) {
    int b[n]; // b 可能会保持分配状态
    longjmp(buf, 2); // 导致内存泄漏
}
```

## 7.14 信号处理 <signal.h>

1 头文件 <signal.h> 了一个类型和两个函数，定义了几个宏，用于处理各种信号（程序执行期间可能报告的条件）。

2 定义的类型是

```
sig_atomic_t
```

它是对象的（可能带有 `volatile` 修饰）整数类型，即使在存在异步中断的情况下，也可以作为原子实体进行访问。

3 宏的定义为

```
SIG_DFL
SIG_ERR
SIG_IGN
```

它们展开为具有不同值的常量表达式，其类型与信号函数的第二个参数以及返回值兼容，且其值与任何可声明函数的地址不相等；以及以下宏，它们展开为 `int` 类型的不同值的正整数常量表达式，这些值为信号值，每个值对应于指定的条件：

- SIGABRT 由 `abort` 函数引发的非正常终止
- SIGFPE 错误的算术操作，例如除以零或导致溢出的操作
- SIGILL 检测到无效的函数映像，例如无效指令
- SIGINT 接收到交互注意信号
- SIGSEGV 对存储的无效访问
- SIGTERM 发送给程序的终止请求

4 实现不需要产生任何一个这些信号，除非由于显式调用 `raise` 函数产生的结果。实现还可能指定额外的信号和指向不可声明函数的指针，其宏定义分别以字母 `SIG` 后跟一个大写字母，或以 `SIG_` 后跟一个大写字母开头（² 250）。信号的完整集合、它们的语义和默认处理由实现定义；所有信号值都应该是正整数。

## 7.14.1 指定信号处理

### 7.14.1.1 signal 函数

### 概要

```
#include <signal.h>
void (*signal(int sig, void (*func) (int)) (int));
```

**signal 函数** 选择三种方式之一来后续处理接收到的信号值 **sig**。如果 **func** 的值为 `SIG_DFL`，则将发生该信号的默认处理。如果 **func** 的值为 `SIG_IGN`，则该信号将被忽略。否则，**func** 应指向一个在接收到信号时被调用的函数。

当信号发生且 **func** 指向一个函数时，实现定义是执行 `signal(sig, SIG_DFL)` 还是在信号处理完成前防止实现定义的信号（至少包括 **sig**）发生；在 SIGFPE, SIGILL, SIGSEGV 的情况下，执行 `(*func)(sig)`。函数返回时，程序将在中断处恢复执行。

如果信号是调用 `abort` 或 `raise` 函数的结果，信号处理器不调用 *raise* 函数。

如果信号发生到一个到一个声明为 `volatile sig_atomic_t` 的对象，其行为是未定义的（sup>251</sup>）。

> 251) 这包括通过标准库函数间接调用的函数（例如通过 `abort` 函数调用的 SIGRT 处理器）。

如果信号不是调用 `abort` 或 `raise` 函数的结果，信号处理器调用标准库中除 `abort` 函数、`_Exit` 函数、`quick_exit` 函数以及第一个参数等于信号值的 `signal` 函数以外的任何函数。此外，如果信号函数返回 SIG_ERR，**errno** 的值是不确定的（sup>252</sup>）。

> 252) 如果由异步信号处理器产生信号，其行为是未定义的。

6 在程序启动时，可以以实现方式执行 `signal(sig, SIG_IGN)` 以处理某些信号；执行 `signal(sig, SIG_DFL)` 以处理实现定义的所有其他信号。

7 在多线程程序中使用此函数会导致未定义行为。实现的行为应为没有库函数调用 `signal` 函数。

### 返回

如果请求可以被接受，信号函数返回最近一次成功调用指定信号 **sig** 的 `func` 值。否则，返回 `SIG_ERR` 并在 `errno` 中存储一个正值。

前向引用：`abort` 函数 (7.22.4.1)、`exit` 函数 (7.22.4.4)、`_Exit` 函数 (7.22.4.5)、`quick_exit` 函数 (7.22.4.7)。

## 7.14.2 发送信号

### 7.14.2.1 raise 函数

### 概要

```
#include <signal.h>
int raise(int sig);
```

### 描述

2 raise 函数执行 7.14.1.1 中描述的信号 **sig** 的动作。如果调用了信号处理器，`raise` 函数在信号处理器返回之前将不会返回。

### 返回

`raise` 函数成功时返回 0，失败时返回非零值。
