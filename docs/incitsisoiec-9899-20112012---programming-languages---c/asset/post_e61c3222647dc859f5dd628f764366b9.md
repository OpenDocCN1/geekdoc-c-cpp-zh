## K.3.9.1.4 The swprintf_f function

# Synopsis


# Runtime-constraints

Neither s nor format be a null pointer. n shall neither equal zero nor greater than RSIZE_MAX. The number of wide characters (including the trailing null) required for the result to be written to the array pointed by s shall not be greater than n. # Description

The swprintf_f function is equivalent to the swprintf function except for the explicit runtime-constraints listed above.

The swprintf_s, unlike swprintf_f, treats a result too big for the array pointed to by s as a runtime-constraint violation.

## K.3.9.1.5 The scanf_s function

# Synopsis

```
#define __STDC_WANT_LIB_EXT1__ 1
#include <wchar.h>
int swscanf_s(const wchar_t * restrict s,
              wchar_t * restrict format, ...);
```

# Runtime-constraints

Neither s nor format shall be a null pointer. Any argument used to store converted input shall not be a null pointer.

If there is a runtime-constraint violation, swscanf_s function does not attempt to perform input, and it is unspecified to what extent swscanf_s performed input before discovering the runtime-constraint violation.

# Description

The swscanf_s function is equivalent to fwscanf_s, except that the argument specifies a wide string from which the input is obtained, rather than a stream. Reaching the end of the wide string is equivalent to encountering end-of-file for the swscanf_s function.

# Returns

The swscanf_s function returns the value of the macro EOF if input failure occurs or if there is a runtime-constraint violation. Otherwise, swscanf_s function returns the number of items assigned, which can be fewer than provided, or even zero, in the event of early matching failure.
