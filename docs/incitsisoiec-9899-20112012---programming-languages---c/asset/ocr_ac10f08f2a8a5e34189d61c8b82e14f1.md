As discussed in 6.2.5, a structure is a type consisting of a sequence of members, whose storage is allocated in an ordered sequence, and a union is a type consisting of a sequence of members whose storage overlap.

Structure and union specifiers have the same form. The keywords struct and union indicate that the type being signed is, respectively, a structure type or a union type.

The presence of a struct-declaration-list in a struct-or-union-specifier declares a new type, within a translation unit. The struct-declaration-list is a sequence of declarations for the members of the structure or union. If the struct-declaration-list does not contain any named members, either directly or via an anonymous struct or anonymous union, the behavior is undefined. The type is incomplete until immediately after the } that terminates the list, and complete thereafter.

A member of a structure or union may have any object type other than a modified type.¹123} In addition, a member may be declared to consist of a specified number of bits (including a sign bit, if any). Such a member is called a bit-field;124} its width is defined by a colon.

A bit-field is interpreted as having a signed or unsigned integer type consisting of the specified number of bits.¹125} If the value 0 or 1 is stored into a non-zero bit-field of type _Bool, the value of the bit-field shall compare equal to the value stored; a _Bool has the semantics of a _Bool.

An implementation may allocate any addressable storage unit large enough to hold a bitfield. If enough space remains, a bit-field that immediately follows another bit-field in a structure shall be packed into adjacent bits of the same unit. If insufficient space remains, whether a bit-field that does not fit is put into the next unit or overlaps adjacent units is implementation-defined. The order of allocation of bitfields within a unit (high-to-low-order or low-order to high-order) is implementation-defined. The alignment of the addressable storage unit is unspecified.
