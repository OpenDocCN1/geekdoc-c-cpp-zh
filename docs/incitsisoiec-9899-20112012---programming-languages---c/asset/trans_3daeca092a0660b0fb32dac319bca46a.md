
在程序启动时，文本流是预定义的并且显式打开的标准输入（用于常规输入）、标准输出（用于常规输出）以及标准错误（用于诊断输出）。初始打开后，标准错误不是全缓冲的；标准输入和输出流只有当它们被确定为交互式设备时才是全缓冲的。

8 打开文件需要一个文件名，这是一个字符串。构造有效文件名的规则是实现定义的。同一个文件是否可以同时打开多次也是实现定义的。

9 虽然文本流和二进制定向流在概念上都是宽字符序列，关联宽定向流的文件是多字节字符序列，如下：

- 文件中的多字节编码可能包含空字节（与程序的多字节编码不同）
- 文件不需要在初始状态开始或结束^{268}

10 此外，用于多字节字符的编码可能不同。这种编码的选择是实现定义的。

11 宽字符输入函数从流读取多字节字符并转换为宽字符，就像连续调用 `fgetwc` 函数一样。每次转换都由 `mbstate_t` 对象描述的状态进行。字节函数从流返回字符，就像连续调用 `fc` 函数一样。

12 宽字符输出函数将宽字符转换为多字节字符并将其写入流，就像连续调用 `fputc` 函数一样。每次转换都由流自身的 `mbstate_t` 对象描述的状态通过 `wctow` 函数进行。字节输出向流写入字符，就像连续调用 `fc` 函数一样。

13 在某些情况下，某些字节输入输出函数还会执行多字节字符和宽字符之间的转换。这些转换也通过调用 `mbrtowc` 和 `wctow` 函数发生。

14 如果呈现底层 `mbrtowc` 函数的字符序列没有形成有效的多字节字符，或者传递给底层 `wctow` 代码不对应有效的多字节字符，则发生编码错误。

> 268 将文件指针设置为文件末尾（如 `fseek(file, 0, SEEK_END)`），对于二进制流（由于可能的尾空字符）或任何不确保在初始状态的状态依赖编码的流，具有未定义行为。

宽字符输入输出函数和字节输入输出函数仅在发生编码错误时才会存储宏 `EISSEQ` 的值。

## 环境限制

`FOPEN_MAX` 的值至少为八，即三个标准文本流。

前向引用：`exit` 函数 (7.22.4.4)、`getc` 函数 (7.21.7.1)、`fopen` 函数 (7.21.5.3)、`fputc` 函数 (7.21.7.3)、`setbuf` 函数 (7.21.5.5)、`setvbuf` 函数 (7.21.5.6)、`fgetwc` 函数 (7.29.3.1)、`fputwc` 函数 (7.29.3.3)、转换状态 (7.29.6)、`mbrtowc` 函数和 `wrtomb` 函数 (7.29.6.3)。

## 7.21.4 文件操作

### 7.21.4.1 remove 函数

#### 摘要

```
#include <stdio.h>
int remove(const char *filename);
```

#### 描述

`remove` 函数导致名为 `filename` 指向字符串的文件不再再通过名称访问。后续使用该名称打开该文件的尝试将失败，除非重新创建它。如果文件处于打开状态，`remove` 函数的行为是实现定义的。

#### 返回

`remove` 函数在操作成功时返回 0，失败时返回非 0。

### 7.21.4.2 rename 函数

### 摘要

```
#include <stdio.h>
int rename(const char *old, const char *new);
```

### 描述

`rename` 函数导致名为 `old` 指向字符串的文件从现在起由 `new` 指向字符串给出的名称识别。名为 `old` 的文件不再再通过名称访问。如果在调用 `rename` 函数之前已存在名为 `new` 指向字符串的文件，其行为是实现定义的。

`rename` 函数在操作成功时返回 0，失败时返回非 0^{269}，在这种情况下，如果文件之前存在，它仍然以其原始名称识别。

> 269) 在某些情况下，使用 `rename` 函数生成的字符串创建的文件仍需要使用 `remove` 函数来删除重命名。

### 7.21.4.3 tmpfile 函数

#### 摘要

```
#include <stdio.h>
FILE *tmpfile(void);
```

#### 描述 

`tmpfile` 函数创建一个临时二进制文件，它与任何现有文件都不同，并且在关闭或程序终止时会自动删除。该文件以 "wb+" 模式打开。

#### 建议做法

在程序生命周期内，至少可以打开 `TMP_MAX` 个文件（该限制与 `tmpnam` 共享），并且除了此限制外，没有打开文件的限制（FOPEN_MAX）。

#### 返回

`tmpfile` 函数返回指向所创建流的指针。如果无法创建文件，`tmpfile` 返回空指针。

前向引用：`fopen` 函数 (7.21.5.3)。

### 7.21.4.4 tmpnam 函数

#### 摘要

```
#include <stdio.h>
char *tmpnam(char *s);
```

#### 描述 

`tmpnam` 函数生成一个有效的文件名，且与现有文件的名称不相同^{270} 该函数可能能够生成 `TMP_MAX` 个不同的字符串，但其中某些或全部可能已被现有文件占用因此无法使用。

> 270) 使用 `tmpnam` 生成的字符串创建的文件仅在与常规命名规则冲突的意义上是临时的。在使用结束且程序终止之前，仍需要使用 `remove` 函数来删除此类文件。

`tmpnam` 函数每次调用时都会生成不同的字符串。带有空指针参数调用 `tmpnam` 函数可能会彼此之间引入数据竞态。实现应表现为没有库函数调用 `tmpnam` 函数。

#### 返回

如果无法生成合适的字符串，`tmpnam` 返回空指针。否则，如果参数是空指针，`tmpnam` 函数将其结果留在内部状态并返回指向该对象的指针（后续调用 `tmpnam` 函数可能会修改该对象）。如果参数不是空指针，假设它指向一个至少有 `L_tmpnam` 个字符的数组；`tmpnam` 函数将其结果写入该数组并返回参数作为值。

#### 环境限制

`TMP_MAX` 的值至少为 25。

## 7.21.5 文件访问函数

### 7.21.5.1 fclose 函数

#### 摘要

```
#include <stdio.h>
int fclose(FILE *stream);
```

#### 描述 

成功调用 `fclose` 函数会导致 `stream` 指向的流被刷新并关联的文件被关闭。流的任何未缓冲数据都会交付给主机环境以写入文件；任何未读取的缓冲数据都会被丢弃。无论调用是否成功，流都会与文件分离，且通过 `setbuf` 或 `setvbuf` 函数设置的任何缓冲区都会与流分离（如果是自动分配的，则会被释放）。

#### 返回

`fclose` 函数在流成功关闭时返回 0，如果检测到任何错误则返回 `EOF`。
