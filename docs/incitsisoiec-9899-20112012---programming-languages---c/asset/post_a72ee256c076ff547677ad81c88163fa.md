## 6.10.4 Line control

Constraints

- 1 The string literal of a #line directive, if present, shall be a character string literal.
- 2 The line number of the current source line is greater than the number of new-line characters read or introduced in translation phase 1 (5.1.1.2) while processing the source file to the current token.

Semantics

- 3 A preprocessing directive of the form

`# line digit-sequence new-line`
causes the implementation to behave as if the following sequence of source lines begins with a source line that has a line number as specified by the digit sequence (interpreted as a decimal integer). The digit sequence shall not specify zero, nor a number greater than 2147483647.

- 4 A preprocessing directive of the form

`# line digit-sequence "s-char-sequence_opt" new-line`
sets the presumed line similarly and changes the presumed number of the source file to be the contents of the character string literal.

- 5 A preprocessing directive of the form

`# line pp-tokens new-line`
(that does not match one of the two previous forms) is permitted. The preprocessing tokens after line on the directive are processed just as in normal text (each identifier currently defined as a macro name is replaced by its replacement list of preprocessor tokens). The directive resulting after all replacements shall match one of the two previous forms and is then processed as appropriate.

## 6.10.5 Error directive

Semantics

A preprocessing directive of the form

```c
# error pp-tokensopt new-line
```

causes the implementation to produce a diagnostic message that includes the specified sequence of preprocessing tokens.

## 6.10.6 Pragma directive

Semantics

A preprocessing directive of the form

```c
# pragma pp-tokensopt new-line
```

where the preprocessing token STDC does not immediately follow pragma in the directive (prior to any macro replacement)¹⁴ causes the implementation to behave in an implementation-defined manner. The behavior might cause translation to fail or cause the translator or the resulting program to behave in a non-conforming manner. Any such pragma that is not recognized by the implementation is ignored.

If the preprocessing STDC immediately follow pragma in the directive (prior to any macro replacement), then no macro replacement is performed on the directive, and the directive should have one of the following forms¹¹⁵ which means are described elsewhere:

```c
#pragma STDC FP_CONTRACT on-off-switch
#pragma STDC FENV_ACCESS on-off-switch
#pragma STDC CX_LIMITED_RANGE on-off-switch
```

on-off-switch: one of

```
ON DEFAULT
```

Forward references: the FP_CONTRACT pragma (7.12.2), the FENV_ACCESS pragma (7.6.1), the CX_LIMITED_RANGE pragma (7.3.4).

¹⁴) An implementation is not required to perform macro replacement in pragmas, but it is permitted except for standard pragmas (where STDC immediately follows pragma). If the result of macro replacement in a non-standard pragma has the same form as a standard pragma, the behavior is implementation-defined; an implementation is permitted to behave as if it were the standard pragma, but is not required to.

¹⁷⁵ The presumed source file name and line number can be changed by the #line directive.

## 6.10.7 Null directive

Semantics

A preprocessing directive of the form

```c
# new-line
```

has no effect.

## 6.10.8 Predefined macros

The values of the predefined macros, except for __FILE__ and __LINE__, remain constant throughout the translation unit.

None of these macros, nor the identifier, shall begin with a leading underscore followed by an uppercase letter.

## 6.10.8.1 Mandatory macros

The following macros shall be defined by the implementation:

- __DATE__ The date of translation: a character string literal of the form "mm dd yyyy". If the date is not available, an implementation-valid date shall be supplied.
- __FILE__ The presumed source file (a character string),¹⁶
- __LINE__ The presumed line number (an integer).¹⁷
- __STDC__ The integer constant 1, intended to indicate a conforming implementation.
- __STDC_HOSTED__ The integer constant 1 if the implementation is hosted or 0 if it is not.

## 6.10.8.2 Environment macros

The following macros are conditionally defined by the implementation:

- __STDC_ISO_10646__ An integer constant of the form yyyymmL (for example, 19972L). If this symbol is defined, then every character in the required set, when stored in an object of char_t, has the same value as its store identifier of that character. The Unicode required set consists of all the characters defined by ISO/IEC 10646, along with all amendments and technical corrigenda, as of the specified year and month. If some other encoding is used, the macro shall not be defined and the actual encoding used is implementation-defined.
- __STDC_MB_MIGHT_NEO_WC__ The constant 1, intended to indicate that in the encoding for char_t, a member of the basic character set need not have a code value equal to its value when used as the lone character in an integer constant.
- __STDC_UTF_16__ The integer constant 1, intended to indicate that values of char16_t are UTF–16.
- __STDC_UTF_32__ The integer constant 1, intended to indicate that values of char32_t are UTF–32.

¹⁶ See “future directions” (6.11).
¹⁷ The presumed source file name and line number can be changed by the #line directive.
¹⁸ STDC_VERSION__ The integer constant yymmL

__TIME__ The translation of the unit: a character string literal of the form "hh:mm:ss" as in the time generated by the asctime function. If the time is not available, an implementation-defined valid time shall be supplied.
