

## 3.7.2

多字节字符（multibyte character）
一个或多个字节的序列，表示源或执行环境扩展字符集中的成员

注意 扩展字符集是基本字符集的超集。

## 3.7.3

宽字符（wide character）
`wchar_t` 类型对象可以表示的值，能够表示当前区域（locale）中的任何字符

## 3.8

约束（constraint）
一种语法或语义上的限制，用于对语言元素的阐述进行解释

## 3.9

精确舍入结果（correctly rounded result）
在结果格式中的表示，在当前舍入模式下，其数值最接近于该结果在具有无限范围和精度的时的值

## 3.10

诊断消息（diagnostic message）
属于实现定义的实现消息输出子集的消息

## 3.11

前向引用（forward reference）
对本国际标准中后续子句的引用，该子句包含与本子句相关的附加信息

## 3.12

实现（implementation）
一组特定的软件，在特定的控制选项下运行于特定的翻译环境中，用于对特定环境中的程序进行翻译并支持在该执行环境中的函数执行

## 3.13

实现限制（implementation limit）
实现对程序施加的限制

## 3.14

内存位置（memory location）
标量类型的对象，或者一组均具有非零宽度的相邻位域的最大序列

注意 1 两个执行线程更新并访问不同的内存位置，且互不产生干扰。

注意 2 位域与相邻的非位域成员位于不同的内存位置。位域之间也适用此规则：如果其中一个位域声明在嵌套结构声明内部而另一个不是，或者如果它们被一个零长度的位域声明隔开，或者它们被一个非位域成员声明隔开。在同一个结构体中，如果它们之间声明的所有成员都是（非零长度的）位域，并发更新两个非原子位域是不安全的，无论中间的位域大小如何。

示例 一个如代码所示通过 `struct` 声明的结构体：

```c
struct {
    char a;
    int b:5, c:11, :0, d:8;
    struct { int ee:8; } e;
}
```

包含四个独立的内存位置：成员 `a`，以及位域 `d` 和 `e.ee`。它们各是独立的内存位置，可以并发修改而互不产生干扰。位域 `b` 和 `c` 构成了第四个内存位置。位域 `b` 和 `c` 不能被并发修改，但例如 `b` 和 `a` 可以修改。

## 3.15

对象（object）
执行环境中存储存储区域，其内容可以表示值

注意 当引用时，对象可能被解释为具有特定类型；参见 6.3.2.1。

## 3.16

参数（parameter）

形式参数（formal parameter）形式参数（formal argument，已废弃）作为函数声明或定义一部分声明的对象，在进入函数时获取值；或函数形式宏定义中紧跟在宏名后的括号边界的逗号分隔列表中的标识符

## 3.17

推荐做法（recommended practice）
被强烈推荐符合标准意图的规范，但该规范对某些实现来说可能是不可行的

## 3.18

运行时约束（runtime-constraint）
调用库函数时对程序的要求

注意 1 尽管术语相似，但运行时约束不属于 3.8 定义的约束类型，且不需要在翻译时证明。

注意 2 支持附录 K 中扩展的实现需要验证程序是否违反了库函数的运行时约束；参见 K.3.1.4。

## 3.19

值（value）
当对象的内容被解释为具有特定值时，其精确的含义

## 3.19.1 实现定义的值（implementation-defined value）

未指定的值（unspecified value），每个实现都记录了如何进行该选择

## 3.19.2 不确定值（indeterminate value）
或是未指定的值或实现表示

## 3.19.3 未指定的值（unspecified value）
当解释为具有特定值时，国际标准未对其施加要求的值

注意 未指定的值不能是实现表示。

## 3.19.4 实现表示（trap representation）
一种不符合对象要求的对象表示

## 3.19.5 陷阱（perform a trap）
中断程序的执行

注意 在国际标准中，当“trap”后面没有紧跟“representation”时，它表示中断执行。
