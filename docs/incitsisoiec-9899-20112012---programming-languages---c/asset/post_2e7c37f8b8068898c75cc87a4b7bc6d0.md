## 7.1.3 Reserved identifiers

Each header declares or defines all identifiers listed in its associated subclause, and optionally declares or defines identifiers listed in its associated future library directions subclause and identifiers which are always reserved for any use or as file scope identifiers.

- All identifiers that begin with an underscore and either an uppercase letter or another underscore are always reserved for any use.
- All identifiers that begin with an underscore are always reserved for use as identifiers with file scope in both the ordinary and tag name spaces.
- Each macro name in any of the following subclauses (including the future library directions) are reserved for use as specified if any of its associated headers is included; unless explicitly stated otherwise (see 7.1.4).
- All identifiers with external linkage in any of the following subclauses (including the future library directions) and `errno` are always reserved for use as identifiers with external linkage.¹184)
- Each identifier with file scope listed in any of the following subclauses (including the future library directions) are reserved for use as a macro name and as an identifier with file scope in the same name space if any of its associated headers is included.

No other identifiers are reserved. If the program declares or defines an identifier in a context in which it is reserved (other than as allowed by 7.1.4), or defines a reserved identifier as a macro name, the behavior is undefined.

If the program removes (with `#undef`) any macro definition of an identifier in the first group listed above, the behavior is undefined.

¹184) The list of reserved identifiers with external linkage includes `math_errhandling`, `setjmp`, `va_copy`, and `va_end`.

## 7.2 Diagnostics <assert.h>

The header <assert.h> defines the assert and static_assert macros and refers to another macro,

```
NDEBUG
```

which is not defined by <assert.h>. If NDEBUG is defined as a macro name at the point in the source file where <assert.h> is included, the assert macro is defined simply as

```
#define assert (ignore) ((void) 0)
```

The assert macro is redefined according to the current state of NDEBUG each time <assert.h> is included.

The assert macro shall be implemented as a macro, not as an actual function. If the macro definition is suppressed in order to access an actual function, the behavior is undefined.

The macro

```
static_assert
```

expands to _Static_assert.

## 7.2.1 Program diagnostics

## 7.2.1.1 The assert macro

Synopsis

```
#include <assert.h>
void assert (scalar expression);
```

Description

The assert macro puts diagnostics tests into programs; it expands to a void expression. When it is executed, if expression (which shall have a scalar type) is false (that is, compares equal to 0), the assert macro writes information about the particular call failed (including the text of the argument, the name of the source file, the line number, and the name of the enclosing function — the latter are respectively the values of the preprocessing macros __FILE__ and __LINE__ and of the identifier __func__ on the standard error stream in an implementation-defined format.¹191) then calls the abort function.

The message written might be of the form:

```
Assertion failed: expression, function abc, file xyz, line nnn.
```
