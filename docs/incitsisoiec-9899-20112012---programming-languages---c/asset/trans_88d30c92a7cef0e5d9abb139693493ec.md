
根据 order 的值。这些操作是原子-修改-写操作（5.1.2.4）。对于有符号整数类型，算术运算定义为使用补码表示，并在溢出时静默回绕；没有未定义的结果。对于地址类型，结果可能是未定义的地址，但在其他情况下这些操作没有未定义行为。

## 返回

原子性地返回在影响发生之前，对象所指向的值。

注意 `atomic_fetch` 和 `modify` 通用函数的操作与相应的 `op=` 赋值运算符的操作几乎等。唯一的区别在于，复合赋值运算符不保证以原子方式操作，且复合赋值运算符产生的值是对象更新后的值，而 `atomic_fetch` 和 `modify` 通用函数返回的值是原子对象的值。

## 7.17.8 atomic_flag 类型和操作

`atomic_flag` 类型提供了经典的测试并设置（test-and-set）功能。它有两个状态：设置（set）和清除（clear）。

对 `atomic_flag` 类型对象的操作应当是无锁的（lock free）。

注意 因此，这些操作也应该是无地址的（address-free）。没有其他类型需要锁操作，因此 `atomic_flag` 类型是符合此国际标准所需的最小硬件实现类型。其余的类型可以用 `atomic_flag` 模拟，尽管其属性并不理想。

宏 `ATOMIC_FLAG_INIT` 可用于将 `atomic_flag` 初始化为清除状态。未用 `ATOMIC_FLAG_INIT` 显式初始化的 `atomic_flag` 初始处于不确定状态。

示例

```
atomic_flag guard = ATOMIC_FLAG_INIT;
```

## 7.17.8.1 atomic_flag_test_and_set 函数

### 概览

```
#include <stdatomic.h>
Bool atomic_flag_test_and_set(
volatile atomic_flag *object);
Bool atomic_flag_test_and_set_explicit(
volatile atomic_flag *object, memory_order order);
```

### 描述

原子性地将对象所指向的值设置为 true。内存根据 order 的值受到影响。这些操作是原子的读-修改-写操作（5.1.2.4）。

## 返回

3 原子性地返回在影响发生之前，对象的值。

## 7.17.8.2 atomic_flag_clear 函数

### 概览

```
#include <atomic.h>
void atomic_flag_clear(volatile atomic_flag *object);
void atomic_flag_clear_explicit(volatile atomic_flag *object, memory_order order);
```

### 描述

2 `order` 参数不应为 `memory_order_acquire` 或 `memory_order_acq_rel`。原子性地将对象所指向的值设置为 false。内存根据 order 的值受到影响。

## 返回

3 `atomic_flag_clear` 函数没有返回值。

## 7.20 整数类型 <stdint.h>

1 头文件 `<stdint.h>` 声明了具有指定宽度的整数类型组，并定义了一组宏。²260 它还定义了指定其他标准头文件中定义的类型对应的整数类型限制的宏。

2 类型定义在以下类别中：

- 具有特定宽度的整数类型；
- 具有至少某些指定宽度的整数类型；
- 具有至少某些指定宽度的最快整数类型；
- 足够大以容对象指针的整数类型；
- 具有最大宽度的整数类型。

（这些类型中的某些表示相同的类型。）

3 相应的宏指定了声明类型的限制并构造了合适的常量。

4 对于实现提供的此处描述的每个类型，²261) `<stdint.h>` 应当声明该 `typedef` 名称并定义关联宏。相反，对于实现未提供的此处描述的每个类型`<stdint.h>` 不应声明该 `typedef` 名称，也不应定义关联宏。实现应当提供描述为“强制的”（required）的类型，但不需要提供其他任何类型（描述为“可选的”，optional）。

## 7.20.1 整数类型

1 对于仅在开头是否存在 `u` 而区别的 `typedef` 名称，它们应当表示 6.2.5 中描述对应的有符号和无符号类型；提供这些对应类型之一的实现也应提供另一个。

2 在下面的描述中，符号 `N` 代表一个没有前导零的无符号十进制整数（例如 8 或 24）。

> 260) 见“未来方向”（7.31.10）。

> 261 某些类型可能表示实现定义的整数类型。

## 7.20.1.1 精确宽度整数类型

`intN_t` 指定一个宽度为 `N`、无填充位且具有补码表示的有符号整数类型。因此，`int8_t` 是宽度为 8 位的有符号整数类型。

`uintN_t` 指定一个宽度为 `N` 无填充位的无符号整数类型。因此，`uint24_t` 是宽度为 24 位的无符号整数类型。

这些是可选的。然而，如果提供了宽度为 8、16、32 或 64 位、无填充位且（对于有符号类型）具有补码表示的整数类型，应当定义相应的 `typedef` 名称。

## 7.20.1.2 最小宽度整数类型

`int_leastN_t` 指定一个宽度至少为 `N` 的有符号整数类型，使得没有更小的有符号整数类型具有指定的宽度。因此，`int_least32_t` 是宽度至少为 32 位的有符号整数类型。

`uint_leastN_t` 指定一个宽度至少为 `N` 的无符号整数类型，使得没有更小的无符号整数类型具有指定的宽度。因此，`uint_least16_t` 是宽度至少为 16 位的无符号整数类型。

以下类型是强制的：

```
int_least8_t           uint_least8_t
int_least16_t          uint_least16_t
int_least32_t          uint_least32_t
int_least64_t          uint_least64_t
```

所有其他形式的类型都是可选的。

## 7.20.1.3 最快最小宽度整数类型

以下每个类型指定在所有具有至少指定宽度的整数类型中通常操作最快²的 的类型。

`int_fastN_t` 指定宽度至少为 `N` 的最快有符号整数类型。`uint_fastN_t` 指定宽度至少为 `N` 的最快无符号整数类型。

> 262) 指定类型并不保证在所有用途下都是最快的；如果实现没有明确理由选择一种类型而非另一种类型，它将简单选择满足符号和宽度要求的某种整数类型。
