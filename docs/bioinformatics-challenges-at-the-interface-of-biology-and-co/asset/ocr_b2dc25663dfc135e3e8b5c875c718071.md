The other resource an algorithm uses very efficiently is space: during execution, an algorithm must have free access to a certain amount of physical memory. The amount of space required depends on how much data must be manipulated, and how that manipulation takes place. How the required amount of space changes with the size of input is the space complexity of an algorithm, and also described using the big O notation, as a measure of memory usage rather than of time. Even our naïve bubble sort actually does well when measured this way: aside from the space required to store the original list (which doesn't feature in our calculation of memory usage), only one more value in memory is required – the temporary value used during swap. If each item takes one binary unit, then this algorithm uses one extra n to perform its sorting function on a list of size n. This constant gives bubble sort a best-in-show space complexity of O(1); it will always use the same amount of space, regardless of input size.

From here, it is easy to see that an algorithm may be efficient in terms of one resource, but terribly inefficient in terms of another. Indeed, choosing (or designing) the right algorithm for a given task will inevitably involve a compromise between different resources, a compromise that must be made in the context of the specific problem at hand and of its limits.

# 6.4.3 Choices, choices

The example we've been using in this chapter is of a very simple problem (sorting list of numbers) and a very simple solution (the bubble sort algorithm). If this were the only available solution, our jobs would be much straightforward. However, there are many sorting algorithms, each with their own qualities, quirks and complexities in space and time: some work in place, others rely on the fact that their arrays arrive by item; some work better with already partially ordered lists, others rely on specific data. Some of the most used sorting algorithms and their related complexities are shown in Table 6.2, which illustrates the worst-, average-, and best-case complexities and the space complexity, in big O notation.

# Table 6.2
Complexities of some common sorting algorithms.

| Algorithm | Worst-case | Average-case | Best-case | Space complexity |
|---|---|---|---||
| Bubble sort* | O(n²) | O(n²) | O(n) | O(1) |
| Quicksort | O(n²) | O(n log n) | O(n log n) | O(log n) |
| Insertion sort | O(n²) | O(n²) | O(n) | O(1) |
| Merge sort | O(n log n) | O(n log n) | O(n log n) | O(n) |
| Heapsort* | O(n log n) | O(n log n) | O(n log n) | O(1) |

*Although, superbly, the heapsort algorithm would seem to be the best of all worlds, it requires a very specific data structure (a heap) on which to work that limits its applicability (see Section 6.5).
