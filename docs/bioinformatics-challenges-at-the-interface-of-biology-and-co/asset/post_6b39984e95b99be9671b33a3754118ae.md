# 5.6 Problems with database entries

Some of the issues we've been discussing in the previous sections are bound up with the constant state of flux of database entries. Our next example is no exception. Consider the following: when we refer to the database entry for the protein designated by AC# Q23293, which are we referring? In 1996, the sequence entered the first release of TreMBL with the description, 'Similarity to mammalian μ- and κ-type opioid receptors'. In the years that followed, there were 107 versions of this entry, amongst which the description of the protein changed more than a dozen times. By March 2012, the UnProtKB/TreMBL description line read, 'Protein DMRSR-1', and its sequence had changed in length from 320 to 355 amino acids – a summary of these changes is given in Table 5.3.

A few aspects of the changes shown in Table 5.3 deserve special mention. The first description of the protein was reasonably definitive, asserting that it remained an opioid receptor (a GPCR); over the years, the force of this assertion diminished, changing to 'hypothetical 36.4 kDa protein', then to 'putative uncharacterized protein', and more recently to 'protein ZC404.11' and 'protein DMRSR-1'. But the initial claim that the sequence was an opioid remained in the database for years; during this time, it's possible that any subsequent analyses based on that led to inappropriate conclusions.
