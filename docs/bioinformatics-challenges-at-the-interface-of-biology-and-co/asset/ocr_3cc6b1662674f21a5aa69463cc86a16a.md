# 7.8 Summary

This chapter introduced some of the basic ideas involved in identifying, representing and giving meaning to bioinformatics data. Specifically we saw that:

+   1. Computers need explicit machine-readable content in order to identify or interpret anything; humans can deal with assumptions, machines can't.
2. The best identifiers are often opaque, these don't go stale or become inconsistent when the they identify.
3. Sometimes, the convenience of having non-opaque identifiers, as for Web pages, outweighs the benefits of opacity (but this is rare).
4. Things in the world inevitably change, so we need to build systems that take account of this.
5. But 'cool' identifiers don't change; there's no good technical reason why identifiers should be avoided.
6. There is no one-size-fits-all way of representing data; it depends on what we want to do with our data; applying principles (like building in provenance and versioning) from day one can prevent trouble later.
7. Paradigms such as XML, RDF and JSON can help us avoid new file formats from scratch.

+   8. Knowledge can be captured in machine-readable form using technologies like SKOS, OWL and OBOF; we can get machines to help us reason about our data and what they make sense.

+   9. The various technologies that underpin the machine-readable Web can also be used to create Linked Data and Web services that make data easy for machines to explore and interpret.
