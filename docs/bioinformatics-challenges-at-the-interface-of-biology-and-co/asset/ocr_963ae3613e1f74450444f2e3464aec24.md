gives a human-readable version of the UniProtKB with accession number
PO02699, whereas:

http://www.uniprot.org/uniprot/P02699.xml

returns an XML representation of the same resource, but one that can more easily
be processed programmatically. This approach of delivering machine-readable content
in XML, RDF or JSON over HTTP makes it very easy to build simple tools that
access online content programmatically. The simplicity of accessing a service in this
however, comes with an important limitation: all the responsibility for interpreting
the retrieved resource lies with the client. Here, means that the client software
has understand UniProtKB's XML schema in order to extract the variousproperties of the protein's record and doing meaningful with them. For
ample, inspecting the XML in a little detail, we can find that says:

```
<dbreference type="PDB" id="1F88">
<property type="method" value="X-ray"/>
<property type="resolution" value="2.80"/>
<property type="chains" value="/A:1-348"/>
</dbreference>
```

which we can interpret as being a link of sorts to the crystal structure of protein,
created through X-ray crystallography at a resolution of 2.80Å (and, assuming that the
values for 'method', 'X-ray' and 'resolution' are available in some ontology, a
computer could make some decision; but there's nothing in the UniProtKB XML
record that tells us how then fetch the XML record for PDB's 1F88 (or whether
ch a representation exists)

At this stage, the responsibility falls back to the human programmer of the client
software to read the PDB web service documentation to determine – at least as
time of writing – a URL of the:

http://www.rcsg.org/pdb/download/download/File.do?fileFormat=xml&structureId=1F88

This somewhat fragile step, where the logic for linking between records has to be
interpreted by humans and explicitly written in executable code, could have
avoided by simply recording the 'outgoing' URL to the PDB record in UniProtKB's
XML to create what's known as 'Linked Data'.

# 7.7.3 Linked Data

The term Linked Data was coined by Tim Berners-Lee in 2006 in a W3C design
relating to the era of the 'semantic Web' – a web of data accessible to machines as well
humans. In this, he outlined four simple rules for creating Linked Data – para-
phased slightly, these states:

+   1 Use URIs as names for things.
2 Use HTTP URIs so that people and machines can look up those names.
