One of the most simple, and hence successful, flat-file formats that devised to store nucleotide sequences in the EMBL database provided the basis for a number of databases that are still in wide use (e.g., Swiss-Prot, TrEMBL, PROSITE).

The EMBL uses series of two-letter tags to describe the data stored on each line of the file, as shown in the inset of Figure 4.9. To illustrate change features this works for our $\alpha$-globin sequence, let's take a look at its EMBL entry, shown in Figure 4.10.

The file begins with an identifying (ID) code (HSAGLI1) and an accession (AC) number (V00488); the AC number is designed to be read by computers; the ID code is intended to convey slightly more meaning to a human reader – here, with expectation, we judge that HSAGLI was Homo sapiens $\alpha$-globin 1, which is certainly not detectable by V00488. The ID and AC codes are intended to uniquely specify any entry in a given database, but of the two, only the AC number (in principle) is invariant. If for any reason, database entries are merged, the AC numbers are retained, maintaining older numbers to be tracked. AC numbers are crucial to tracking, maintaining and merging data. IDs can change if entries are modified. For all operational purposes, the AC number should be used rather than the ID.

This line following the AC number provides the sequence version (SV). Here, V00488.1 informs us that this is version 1 of the nucleotide sequence. Sequence versioning is useful, if it flags to users when changes have been made to the sequence rather than the annotation; nevertheless, it took more than ten years to introduce sequence databases, and even longer to introduce the concept to sequence databases.

Another important piece of information for tracking changes is the date (DT) of accession of a sequence to the database, and the date on which changes were last made to that database. This helps to ‘future proof’, it should change in subsequent HSAGLI standard; genomic DNA; HM; 1138 BP. it also allows us to ascertain the currency of a given entry and determine whether it's out-of-date.

To its simplicity, this format was adopted by many other biological databases. Given that AC and ID codes can be difficult to read (with the eye!), the file includes a descriptive (DE) title indicating what the entry contains – the title in the entry confirms that this is the human-globin gene (to facilitate swift parsing of the file, many of these terms are also included as keywords (KW)). Although the title shows that we're dealing with a human gene, the file also specifies species more precisely (i.e., Homo sapiens) and its biological classification (OC) here, Eukaryota, Metazoa... In addition, we might want to know, say, when the sequence was published and other relevant information (e.g., relating to structure and functional studies), the file includes a number of bibliographic citations – these are stored on the RN lines (RN is the reference number; RP gives the source; RX the PubMed cross-reference; RA the author; RT the RL (location of publication).

Cross-links to other information in databases are provided by the DR lines, here links to EPD (the Eukaryotic Promoter Database), GDB (the Human Genome Database) and TRANSFAC (the TransFactor database).

Another potentially rich source of annotation is the comment (CC). In this, little further information is provided, but in databases, the comment provides a field of useful annotation: e.g., in UniProt/Swiss-Prot, the CC file is semi-structured, with different headings to indicate details of function, structure, disease associations, family relationships, etc. (this is one of the features that made Swiss-Prot such a popular resource)

To make more informative, characteristics or features of the sequence itself are stored in the Feature Table (FT). As mentioned in Section 3.5, the databases of the INSDC have adopted common data standards and protocols, to streamline data-annotation practices. In particular, they use a common FT format, to help data consistency and reliability, and to facilitate database interaction. Many different features and regions of a sequence may be described, including those that perform functions; affect the expression of function or the replication of a sequence; interact with other molecules; have secondary or tertiary structure; so on. Regulating the content, vocabulary and syntax of feature descriptions ensures that the data are released in a format that is easily understood and readily accessible to analysis software. In this example, the FT indicates that the source of the entry is human DNA; within the 1,358 bases of its sequence, the primary sequence resides between 38 and 92, where the first exon runs from 98 to 230, and from 692 to 929. To create the coding sequence from these exons, it's necessary to join the coding sequences, from bases from 135 to 230, 340 to 551 and 692 to 920.

The nucleotide sequence is stored in the SQ field using the single-letter code, together with its attributes such as length and base composition (here, Sequence 1138 BP; 183 A; 412 C; 350 G; 193 T; 0 other). The entry is completed with the terminator symbol.
