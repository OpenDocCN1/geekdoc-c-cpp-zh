We see examples of disparate alignments produced by tools such ClustalW, T-Coffee, MUSCLE and so on; we get first hints that not all alignments are equal. Crucially, however, it isn't just a question of the alignment order or parameters – the conceptual framework that motivates and the basis for alignment is also important. Let's now consider some of the reasons why. Normally, when we align sequences, we do so by creating a 2D grid or matrix, which we populate row by row, with the one-letter codes that represent the constituent amino acids (or bases, if we're aligning DNA or RNA) of the sequences we want to compare. When sequences have different lengths, we simply accommodate the discrepancy by adding gap characters, in order that equivalent residues can be brought into register – the operative word here is equivalent. When we stack one residue beneath another in an alignment grid, we're making some sort of assertion about their relationship: e.g., we believe they are structurally equivalent (have similar structural contexts), or we don't think they're equivalent at all, but just wish (or need) to represent them in this way for convenience. Different analysis tools, different alignment algorithms, assume different kinds of equivalence – and we need to understand this if we're be able to interpret their outputs meaningfully.
