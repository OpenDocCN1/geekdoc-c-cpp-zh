Although the idea of Linked Data is simple in principle, its implications are profound, it implies a different paradigm for consuming services and data on the Web. Whereas SOAP/XSD, and to some extent, the *ad hoc* use of HTTP as an API (Application Programming Interface), imply a traditional programming model (call a function; make a decision; call another function), where behaviour is reliable and predictable, Linked Data allows machines to ‘browse the web of data’ in a similar way to which humans browse the Web. Thus, using the same stack of robust and readily available tools that allow a browser to fetch and interpret HTML for human consumption, a program can request machine-readable content, and by inspecting the results and comparing with ontologies, makes decisions about further bits of data to retrieve. This ‘browsing’ paradigm is much in line with the nature of the Web’s underlying infrastructure.

It may appear, at least, that by looking at *linked data* on the Web, we've stayed somewhat from the original topic of *Web services*; however, in most cases, and entirely the distinction between ‘a service that produces some data’ and ‘some data that were produced by a service’ is largely meaningless.

The real strength of Linked Data is that there are very few technological barriers to making content available in this style; the software for doing so is well understood and reliable, and, in fact, only relatively minor changes would have to be made in the way when using XML, RDF or JSON are produced. There’s also little conceptual complexity; the principles can be explained in four simple sentences. The barriers to moving from arbitrary ‘XML over HTTP’ style services are largely to the inertia associated with evolving any legacy system. Nevertheless, institutions such as the EBI are beginning to expose their services and data-sets as Linked Data (e.g., March 2014 saw the first release of the ChEMBL database in linked RDF).

In the absence of primary databases creating Linked Data versions of the content, various initiatives, such as bio2rdf (a community-based, open-source project) and Linked Life Data (a commercial venture by Bulgarian software company, Ontoday), have created Linked Data versions of many databases (Figure 7.9), enabling programs to integrate and ‘browse’ what would otherwise be independent stores.

The so-called ‘Linked Data Cloud’ contains RDF triples from all manner of domains, ranging from governmental data (e.g., the UK railway stations, stops and postcodes), geospatial information (e.g., places of interest that are geographically close to one another, or information about continents and their countries, capitals and currencies), to items of more niche interest. Even in its currently emerging and somewhat anarchic state, the Linked Data Cloud provides a resource of astonishing scale and richness, which ultimately best the potential to create a Web of Knowledge readable by machines and humans.

## Bioinformatics challenges at the interface of biology and computer science

## 7.8 Summary

This chapter introduced some of the basic ideas involved in identifying, representing and giving meaning to bioinformatics data. Specifically we saw that:

- 1. Computers need explicit machine-readable content in order to identify or interpret anything; humans can deal with assumptions, machines can't.
- 2. The best identifiers are often opaque, these don't go stale or become inconsistent when the they identify.
- 3. Sometimes, the convenience of having non-opaque identifiers, as for Web pages, outweighs the benefits of opacity (but this is rare).
- 4. Things in the world inevitably change, so we need to build systems that take account of this.
- 5. But 'cool' identifiers don't change; there's no good technical reason why identifiers should be avoided.
- 6. There is no one-size-fits-all way of representing data; it depends on what we want to do with our data; applying principles (like building in provenance and versioning) from day one can prevent trouble later.
- 7. Paradigms such as XML, RDF and JSON can help us avoid new file formats from scratch.
- 8. Knowledge can be captured in machine-readable form using technologies like SKOS, OWL and OBOF; we can get machines to help us reason about our data and what they make sense.
- 9. The various technologies that underpin the machine-readable Web can also be used to create Linked Data and Web services that make data easy for machines to explore and interpret.
