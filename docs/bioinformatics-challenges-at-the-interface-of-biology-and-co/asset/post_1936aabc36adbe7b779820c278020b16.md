
## Chapter 7 Representation and meaning

### SKOS: The Simple Knowledge Organisation System
SKOS provides a way to create controlled vocabularies, taxonomies and thesauri. It's designed primarily for indexing-searching applications: e.g., a user searching a database for 'rhopsin' may also be interested in the broader category of GPCRs – it's straightforward to capture such relationships in SKOS.

SKOS is intentionally restrictive (hence the 'simple' in name), providing a small, controlled set of relationships between concepts. The SKOS Primer describes concepts as:

- units of thought – ideas, meanings, or (categories of) objects and events...[that]exist in the mind as abstract entities which are defined by the terms used to label them.

Consider the following:

```turtle
ex:Leucine rdf:type skos:Concept;
skos:prefLabel "Leucine"@en;
skos:prefLabel "Leucina"@es;
skos:prefLabel "Leucinium"@ia;
skos:prefLabel "Leucin"@de;
skos:narrower ex:Aliphatic.
```

The first line defines Leucine in the ‘example’ namespace ‘ex’ as having the RDF type of SKOS Concept. Lines 2, 3, and 5 associate a ‘preferred’ label with the concept in English, Spanish, Latin and German, respectively (there can be, at most, one). The final line defines ex:Leucine as being a ‘narrower’ concept than the ex:Aliphatic (i.e., defines it as a subclass of Aliphatic). SKOS allows any synonym of ‘alternative labels’ to be defined using skos:altLabel. For example, we might add:

```turtle
skos:altLabel "4-Methyl-L-norvaline";
skos:altLabel "H Leu OH";
skos:altLabel "L Leucine";
```

to indicate that 4-Methyl-L-norvaline and H-Leu-OH are ‘(human) language independent synonyms for Leucine.

### OWL: The Web Ontology
At the other extreme of expressiveness sits the family of knowledge-representation languages OWL (a short acronym of Web Ontology Language). Whereas creating taxonomies and thesauri with SKOS is primarily about capturing concepts and simple relationships, an OWL ontology seeks to emphasise objects in a way that makes it possible to practise which category or class of objects they belong. This defining step – to recognise an object’s class – that’s the main intentional difference. OWL does this using a logic-based language in which statements or axioms have a strict interpretation, such that a computer can draw conclusions from them. For example, we could say that in order to be an amino acid, a molecule must have amine and carboxylic acid functional groups and side-chains: i.e., these are necessary conditions. We can also say that, to recognise an object as belonging to the class of hydrophilic amino acids, it is enough that the amino acid has a hydrophilic side-chain (sufficient condition). It is easy to imagine more complex combinations of conditions that will result in a tangled web of amino acid classes, each of which is defined in its properties: this would be an ontology of amino acids.

Using OWL, it's possible to define classes, properties, instances and operations, such as union, intersection and disjointness. #### Box 7.7 Automated Reasoning and the Open World Assumptions

The Open and Closed World Assumptions in the world of formal logic and ontologies there are two ways of looking at systems of knowledge. The Closed World Assumption, anything that isn't known to be true is false; the Open World Assumption, on the other hand, says that anything that isn't known to be true is simply unknown. For example, the assertion 'valine is hydrophobic' if we ask the question 'Is valine hydrophilic?' in a Closed World context, the answer would be 'no'; because we don't have either a statement saying it is true or means by which it can be inferred; in an Open World, the answer would be 'I have no idea'.

In a Closed World, the assumption is that we have all there is about a domain contained within a system; for example, a database of all the students enrolled at a particular university can easily answer the question 'Is this student enrolled?' yet if the person is not recorded in the database as in the world. The Open World Assumption is useful when a system is trying to describe something using incomplete information. A database of sequences is an example of data that could be interpreted under an Open World Assumption. You can ask, 'Is there a human gene with diabetes', the only sensible answers are 'yes' or 'we haven't found one yet'.
