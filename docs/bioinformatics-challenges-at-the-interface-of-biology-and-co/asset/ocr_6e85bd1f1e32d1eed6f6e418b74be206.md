Another good candidate for this is the declaration of any temporary variables used inside the loop. Even though their values might be different from one iteration to the next (such as v above), let the memory that they aren't being continually deallocated and allocated each time stay around. When a function is a macro When writing, we're likely to make use of functions by someone in order to provide the intended functionality. This kind of re-use is perfectly normal, for a good deal of the code of any software system, is a Good Thing. Sometimes though, not knowing the details of how such functions are written can present problems to those trying to use them (something we touched on Section 6.3), especially if the function isn't a function at all, but a macro. Macros, short for macroinstructions (not to be confused with macros in popular word-processing software), specifically how certain input can be mapped to replacement output code. The difference between using a function and a macro is a question of when the parameters are evaluated. A function's parameters are evaluated before that function is called, while a macro is inserted into the surrounding code and the parameters are replaced before evaluation. Simple examples can be seen in Figure 6.14 and Figure 6.15, where a function and a macro are defined, both attempting to ascertain the maximum of two values. In each case, we use them to find the maximum of the square roots of two arbitrary numbers (m and n). For the function max(a,b) of Figure 6.14, the parameters are evaluated before the function is called, so the two auxiliary calls to sqrt(a) and sqrt(b) are executed only once.
