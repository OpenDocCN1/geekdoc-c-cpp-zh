
# Not all problems are effectively computable

Some problems, while technically computable, aren't effectively computable. In this case, an effectively computable problem is one that can be solved in a reasonable amount of time. This suggests that some problems, by their nature, take an unreasonable amount of time to solve.

This is sometimes a good thing—it's precisely this quality that makes current encryption techniques work: using brute force to break an encryption without the required key would take so long as make it impractical. Taking a 128-bit encryption key as an example, given that there are $2^{128}$ different keys, and employing a billion computers that test a billion keys per second, it would still require a period of execution equivalent to times the age of the universe to test each key:

```
$2^{128} = \frac{3.4 \times 10^{18}}{3.1 \times 10^{22}} \times 10^9 \times 60 \times 60 \times 24 \times 365.25 \approx 10^{13}$ years
```

For most practical purposes, of course, taking unreasonable amounts of time to solve problems usually isn't a good thing; knowing whether the problem we're trying to solve is effectively computable can never be employed. Often, we test our algorithms on relatively small input data—with small data, almost any algorithm will finish quickly. Knowing how an algorithm will behave when evaluated on realistic amounts of data is crucial, especially in a world where data are being produced at an ever-increasing rate. Barely do we have the chance to appreciate the quantities of data currently available, before new technologies appear that threaten to bury us. An example of the extreme nature of the problem can be seen in the work of Puckelwartz et al. with their supercomputer-powered whole-genome analysis system, which is capable of aligning and analysing 240 genomes in ~50 hours. Systems like this will only exacerbate the data-handling problems we're struggling to solve.

# Accuracy is sometimes negotiable

Sometimes approximate answers are as useful as accurate answers, or, at least, aren't useless. This is a concession worth considering, because there are many situations where approximate solutions can be effectively computed, but accurate solutions can't, and a lot of time can be saved by knowingly opting for the faster, approximate, solution.

A pertinent example is that of the Travelling Salesman Problem (TSP), named after the problem faced by a travelling salesman who wishes to visit each of a cities. If cities are nodes in a network, with roads between them the edges, then the TSP becomes a graph-based problem that asks for the quickest route around a graph, such that it be guaranteed that all nodes are visited. This problem has been known for a long time, and many complete (accurate) solutions exist; however, for very large graphs, none are effectively computable. Nevertheless, there are effectively computable solutions that use heuristics to reach approximate answers that reach 99 percent accuracy in realistic time frames.

# Easily verifiable ≠ effectively computable

The P versus NP problem is an unsolved problem in computability theory. Here, the P represents the class of problems that can be effectively computed (the 'P' is short for polynomial time, a concept introduced later in Section 6.4.2), while NP represents the class of problems, the solutions to which can be effectively verified. To illustrate the difference between these two classes, take the following list of numbers:

- -7, 5, 1, -4, 15, 26, -14, 66

Our task is to out whether there exists a subset of these numbers, when added together, equal zero. Feel free to make a try to do that just. The larger the list, the longer it would take - exponentially longer in fact: this problem is not computable. However, given an answer, as the following, we can verify it very quickly indeed, simply by adding the numbers together and checking that they sum to:

```
5 + 1 + 15 - 7 - 14 = 0
```

This distinction is important because it can lead us to overestimate our chances of solving a problem. It cannot be assumed that easily verifiable answers can be produced; it might be impossible to do so.
