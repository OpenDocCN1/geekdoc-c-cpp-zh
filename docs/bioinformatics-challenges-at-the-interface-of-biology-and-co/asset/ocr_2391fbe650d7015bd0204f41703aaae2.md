# Box 7.1 Scheme names

There are more than 150 'official' scheme names registered with the Internet Assigned Names Authority (IANA), and a small handful of unofficial but commonly used names. In bioinformatics, we frequently encounter:

+   * http, the HyperText Transport Protocol, and its Secure equivalent, used for interactions between Web servers and clients;
* ftp, ftps: the File Transfer Protocol, and its Secure equivalent, still quite often for moving large files around the Internet.
* ssh: Secure Shell, a protocol for allowing encrypted remote login between machines;
* git: a distributed version control system designed by Linus Torvalds, original creator of the Linux operating system;
* imap: Internet Message Access Protocol, a protocol for email retrieval and storage. Largely used POP (the Post Office Protocol), although the scheme remains unchanged;
* smtp: the Simple Mail Transfer Protocol, used for sending email (as opposed to IMAP, which is used for retrieving it);
* dor: the Digital Object Identifier (see Section 7.3), widely used in scholarly publishing, but not an IANA scheme at the time of writing.

Notice that this URI carries the idea of a namespace within it, as each successive narrowing of the domain places within the context of the primitive element of the URI (i.e., 'protein' is in the namespace of 'example.com', 'get' is within the namespace of 'protein', and so on). Note that, although, in this example, we've used path components that mean something to a human (and so make the URI highly-opaque), there is nothing in the specification of the URI standard or http: scheme that forces this to be true; the same resource could well be identified by an opaque URI such as:

```
http://example.com/101127123875x7nfi4
```

which is utterly nothing for humans, but has all the advantages of opaque identifiers discussed previously. It's worth noting that even an unmemorable URI like this isn't actually opaque, because URIs such as those with the scheme inherently contain some information about where the resource exists (in this case, at example.com); to this extent, a URI that contains a location can't be completely opaque.
