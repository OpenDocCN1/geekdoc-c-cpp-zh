An example of a SIMD operation is vector addition: the simultaneous pair-wise addition of two identically sized arrays of values. Without SIMD instructions, the kind of addition seen below must be performed as four separate calculations, each row being calculated separately and in sequence:

SIMD extensions, can be performed as one operation on the four rows simultaneously, providing a roughly four-fold increase in speed relative to the SIMD formulation. Some compilers can automatically take advantage of SIMD extensions, but can only do so if code happens to fulfil certain requirements. In many circumstances, to make use of such vector arithmetic (or any of the other SIMD operations that may be available), we must explicitly write assembly to define that part of the algorithm. This is not a trivial task, but can improve the efficiency of any code that is amenable to optimisations.

It can be seen, then, that many strategies can be employed to implement better algorithms, from taking advantage of language quirks (or avoiding their pitfalls), by writing code that's more amenable to modern compiler optimisations, or making use of processor-set extensions.

Taking a step back from these low-level concerns, let's now turn to a less subtle concern of optimisation.

# 6.6.4 Parallelisation

Many algorithms are sequential by nature: they're made of a sequence of steps that must be carried out, in the correct order, to solve a particular problem. Some algorithms exhibit parallel qualities: i.e., some steps are independent of each other, and can be done in any order, or crucially, at the same time. In our world of multi-core and multi-processor machines, server clusters and distributed systems, the ability to execute parts of an algorithm simultaneously (in parallel) allows us to dramatically reduce the time to solve some problems. So what kinds of algorithm can be parallelised?

# Divide and conquer

The bubble sort algorithm discussed in Section 6.4.1 is a good example of a sequential algorithm: each iteration through the loop assumes that previous iterations have already completed, as it relies on the previous iteration's result to work properly. If the steps were done in any other order, the algorithm would fail to function properly; it can't be parallelised.

However, there's an algorithm called Quicksort that takes a divide-and-conquer approach to sorting.
