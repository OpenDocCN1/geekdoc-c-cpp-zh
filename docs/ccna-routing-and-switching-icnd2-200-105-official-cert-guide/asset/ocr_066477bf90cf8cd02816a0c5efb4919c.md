The configuration and use of the native VLAN on the trunk requires a little extra thought.
The native VLAN can be configured on a subinterface, or on the physical interface, or ignored as in Example 19-1. Each 802.1Q trunk has one native VLAN, and if the router needs to route packets for a subnet that exists in the native VLAN, then the router needs some configuration to support that subnet. The two options to define a router interface for the native VLAN are

+   - Configure the `ip address` command on the physical interface, but without an encapsulation command; the router considers this physical interface to be using the native VLAN.
+   - Configure the `ip address` command on a subinterface, and use the `encapsulation dot1q vlan-id native` subcommand to tell the router both the VLAN ID and the fact that it is the native VLAN.
