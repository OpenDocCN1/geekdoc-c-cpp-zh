```
R> c(mob.fac,new.values)
[1] 4 1 12 9 11 7 7 10 2 2
```

Clearly, this has not done what you want it to. Combining the two factor objects resulted in a numeric vector. This is because the function interprets factors as integers. Comparing this with the defined levels, you can see that the numbers refer to the index of each month within the ordered levels.

```
R> levels(mob.fac)
[1] "Jan" "Feb" "Mar" "Apr" "May" "Jun" "Jul" "Aug" "Sep" "Oct" "Nov" "Dec"
```

This means you can use these integers with levels to retrieve a character vector of the complete observed data—the original eight plus the additional three.

```
R> levels(mob.fac)(c(mob.fac,new.values))
[1] "Apr" "Dec" "Sep" "Nov" "Jul" "Jun" "Oct" "Feb" "Feb"
```

Now you have all the observations stored in a vector, but they are currently stored as strings, not values. The final step is to turn this vector into a factor object.

```
R> mob.new <- levels(mob.fac)(c(mob.fac,new.values))
R> mob.new.fac <- factor(x=mob.new,levels=levels(mob.fac),ordered=TRUE)
R> mob.new.fac
[1] Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < Oct < Nov < Dec
```

As this example shows, factoring requires two objects to deconstruct the numeric positions of each entry with respect to the factor levels, and then rebuild them together. This ensures that the levels are consistent and the observations are valid in the final product.
