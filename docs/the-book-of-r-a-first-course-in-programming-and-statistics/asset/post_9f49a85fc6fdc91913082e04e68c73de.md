
### 4.3.2 Defining Ordering Levels

The sex factor from the previous section represents the simplest kind of factor variable—there are only two possible levels with no ordering, in that one level is not intuitively considered "higher than" or "following" the other. Here you'll look at factors with levels that can be logically ordered; for example, month of birth (MOB), there are 12 levels that have a natural order. Let's store the observed MOB from earlier as a character vector.

```
R mob <- c("Apr", "Jan", "Dec", "Sep", "Nov", "Jul", "Jun")
```

There are two problems with the data in this vector. First, not possible categories are represented since mob contains only seven unique months. Second, this vector doesn't reflect the natural order of the months. If you compare January and December to which is greater, you get:

```
R mob[2]
[1] "Jan"
R mob[3]
[1] "Dec"
R mob[2]<mob[3]
[1] FALSE
```

Alphabetically, this result is of course correct—J doesn't occur D. But in terms of the calendar months, which is what we're interested in, the FALSE result is incorrect.

If you create a factor object from these values, you can deal with both of problems by supplying additional arguments to the factor function. You can define additional levels by supplying a character vector of all possible values to the levels argument and then instruct R to order the values precisely as they appear in levels by setting the ordered argument TRUE.

```
R ms <- c("Jan", "Feb", "Mar", "Apr", "May", "Jun", "Jul", "Aug", "Sep", "Oct", "Nov", "Dec")
R mob.fac <- factor(x=mob,levels=ms,ordered=TRUE)
R mob.fac
[1] Apr Jan Dec Sep Nov Jul
Levels: Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < Oct < Nov < Dec
```

Here, the mob.fac contains the same individual entries at the same index positions as the mob vector from earlier. Notice that this variable has 12 levels, even though you have not made any observations for the levels "Feb", "Mar", "Oct" (Note that if your console window is too narrow to print all the levels to the screen, you may see a ..., indicating there's output has been hidden. Just widen your window and reprint the object to see the hidden levels). Also, the strict order of these levels is shown by the < symbol in the object output. Using this new factor object, you can perform the relational comparison from earlier and get the result you might expect.

```
R mob.fac[2]
[1] Jan
Levels: Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < Oct < Nov < Dec
R> mob.fac[3]
[1] Dec
Levels: Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < Oct < Nov < Dec
R> mob.fac[2]<mob.fac[3]
[1] TRUE
```

These improvements are far from just cosmetic. There's a big difference, for example, between a data set with zero observations in some of the categories and the same data set defined with fewer categories to begin. The choice of whether to instruct R to formally order a factor can also have important consequences in the implementation of various statistical methods, such as regression and other types of modeling.

### 4.3.3 Combining and Cutting

As you've seen, it's usually simple to combine multiple vectors of the same kind (whether numeric, logical, or character) with the c function. Here is an example:

```
R foo <- c(5.1,3.3,3.1,4)
R bar <- c(4.5,1.2)
R c <- c(foo,bar)
[1] 5.1 3.3 4.0 4.5 1.2
```

This combines the two numeric vectors the same way with factor-valued vectors. However, the c function doesn't work well. Let's see what happens when you use it on the data in Table 4-4 and the MOB factor mob.fac, from Section 4.3.2. Suppose you now observe three more individuals with MOB values "Oct", "Feb", and "Feb", which are stored as a factor object, as follows.

```
R new_values <- factor(c("Oct"
```

```
[1] Oct Feb Feb
Levels: Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < Oct < Nov < Dec
```

Now you have mob.fac with the original observations and new.values with an additional three. Both are factor objects, defined with identical, ordered levels. You might expect that you can just use c to combine the two as follows.

```
R> c(mob.fac,new.values)
[1] 4 1 12 9 11 7 7 10 2 2
```

Clearly, this has not done what you want it to. Combining the two factor objects resulted in a numeric vector. This is because the function interprets factors as integers. Comparing this with the defined levels, you can see that the numbers refer to the index of each month within the ordered levels.

```
R> levels(mob.fac)
[1] "Jan" "Feb" "Mar" "Apr" "May" "Jun" "Jul" "Aug" "Sep" "Oct" "Nov" "Dec"
```

This means you can use these integers with levels to retrieve a character vector of the complete observed data—the original eight plus the additional three.

```
R> levels(mob.fac)[c(mob.fac,new.values)]
[1] "Apr" "Dec" "Sep" "Nov" "Jul" "Jun" "Oct" "Feb" "Feb"
```

Now you have all the observations stored in a vector, but they are currently stored as strings, not values. The final step is to turn this vector into a factor object.

```
R> mob.new <- levels(mob.fac)[c(mob.fac,new.values)]
R> mob.new.fac <- factor(x=mob.new,levels=levels(mob.fac),ordered=TRUE)
R> mob.new.fac
[1] Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < Oct < Nov < Dec
```

As this example shows, factoring requires two objects to deconstruct the numeric positions of each entry with respect to the factor levels, and then rebuild them together. This ensures that the levels are consistent and the observations are valid in the final product.

Factors are also created from data that was originally measured on a continuum, for example the weight of a set of adults or the amount of a drug given to a patient. Sometimes you'll need to group (or bin) these types of observations into categories, like Small/Medium/Large or Low/High. In R, you can map this kind of data into discrete factor categories using the cut function. Consider the following numeric vector of 10:

```
R> Y <- c(0.53,5.4,1.5,3.3,33.0,0.45,0.1,2.4,1.9,1.0)
```

Suppose you want to bin the data as follows: Small refers to observations in the interval [0,2), Medium refers to [2,4), and Large refers to [4,6]. A square bracket refers to *inclusion* of its nearest value, and a parenthesis indicates *exclusion*, so an observation $y$ will fall in the Small interval if $0 \le y < 2$, in Medium if $2 \le y < 4$, or in Large if $4 \le y \le 6$. For this you'd use cut and supply your desired breaks to the breaks argument:

```
R br <- c(0,2,4,6)
R cut(x=Y,breaks=br)
[0,2] [4,6] [2,4] [0,2] [0,2] [2,4] [4,6] [0,2]
Levels: (0,2] (2,4] (4,6)
```

This gives you a factor, with each observation now assigned an interval. However, notice that your boundary intervals are back-to-front—you want the boundary levels on the left like [0,2], rather than the right as they appear by default, (0,2]. You can fix this by setting the logical argument to FALSE.

```
R cut(x=Y,breaks=br,right=F)
[0,2] [4,6] [2,4] [0,2] [0,2] [2,4] [4,6] [0,2]
Levels: (0,2] (2,4] (4,6]
```

Now you've swapped boundaries which are inclusive and exclusive. This is important because it changes which categories fall into. Notice that the seventh observation has changed categories. But there's still a problem: the final interval *excludes* 6, and you want this maximum value to be *included* in the highest level. You can fix this with another logical argument: include.lowest. Even though it's called "include.lowest", this argument can also be used to include the *highest* value if right is FALSE, as indicated in the help file ?cut.

```
R cut(x=Y,breaks=br,right=F,include.lowest=T)
[0,2] [4,6] [2,4] [0,2] [0,2] [2,4] [4,6] [0,2]
Levels: (0,2] (2,4] (4,6]
```

The intervals are now defined how you want. Finally, you want to add better labels to the categories, rather than using the levels that R provides by default, passing a character string vector to the labels argument. The order of labels must match the order of the levels in the factor object.

```
R lab <- c("Small","Medium","Large")
R cut(x=Y,breaks=br,right=F,include.lowest=T,labels=lab)
[1] Small Large Small Medium Small Small Large Small Small
Levels: Small Medium Large
```
