## 25.1.2 Built-in Palettes

Being able to implement your own RGB colors is most useful when you need many colors, the collection of which is referred to as a palette. You'll typically need a palette when color is used to describe something on a continuum, like the various shades of blue for the height measurements in Figure 24-6

There are a number of color palettes built into the base R installation. These are defined by the functions rainbow, heat.colors, terrain.colors, topo.colors, cm.colors, gray.colors, and gray. With the exception of gray, you directly specify the number of colors you want, and they'll be returned as a character vector of codes representing an equally spaced sequence over the entire range of that particular palette.

It's easiest to see this in action with a visualization. The following code generates exactly 600 colors from each palette:

```
R N <- 600
R rainbow <- rainbow(N)
R heat <- heat.colors(N)
R terr <- terrain.colors(N)
R topo <- topo.colors(N)
R cm <- cm.colors(N)
R gray1 <- gray.colors(N)
R gray2 <- gray(level=seq(0,1,length=N))
```

Note that single gray expects a numeric vector of values between 0 (total black) and 1 (total white) to provide a grayscale. Its counterpart, gray.colors, works the same as the other built-in palettes but defaults to a slightly narrower visual range between the extremes of black and white. These can be reset using the optional arguments start and end, which you'll see shortly.

The next chunk uses skills from Chapter 23 to initialize a new plot and uses vector repetition to place 600 points for each palette in a single call to coloring them appropriately as per the vectors of color.

```
dev.new(width=8,height=3)
R par(mar=c(1,1,1,1))
plot(1:N,ylim=c(0,0.5,7),type="n",xax="n",yax="n",ann=FALSE)
points(rep(1:N,7),rep(7,each=N),pch=19,cex=3)
col=c(rep("rainbow",heat,terrain,topo,cm,gray1,gray2))
axis(2,at=1:7,labels=c("rainbow","heat.colors","terrain.colors","topo.colors","cm.colors","gray.colors","gray"),family="mono",las=1)
```

## 25.1.3 Custom Palettes

You're not restricted to the ready-to-use color designs. The function colorRampPalette allows you to create your own palettes; you supply two or more desired color keys to an argument of the same name, and it creates a palette that transitions between them. The result of a call to colorRampPalette is itself a function—one that behaves exactly like the built-in palette functions noted earlier.

Let's say you'd like to be able to generate colors on a scale between purple and yellow. You specify the color keys to be interpolated, in the desired order, as a character vector of names from the collection that R recognizes. The following line creates this palette function:

```
R puryl.colors <- colorRampPalette(colors=c("purple","yellow"))
```

Let's create another one, this time picking one will show up a little clearer in a color plot that ends up you are using it in grayscale (in which case switching to monochromatic palettes is a good idea).

```
R blues <- colorRampPalette(colors=c("navyblue","lightblue"))
```

Here are a couple more, using more than two colors for this time:

```
R fours <- colorRampPalette(colors=c("black","hotpink","seagreen4","tomato"))
R patriot.colors <- colorRampPalette(colors=c("red","white","blue"))
```

## 25.1.4 Using Color Palettes to Index a Continuum

You've now seen a few times how color can be used to identify groups based on a categorical variable (the data corresponding to a certain level are simply a distinct color from the others), which is pretty easy to do. However, assigning colors appropriately to values on a continuum requires a little more. There are two methods for this: categorization or normalization of your continuous values. Let's look first at the former approach.

### Via Categorization

One way to color values according to a continuous variable is to turn it into the familiar problem of coloring points of a categorical variable. You can do this by binning your continuous values into a fixed number of k categories, generating k colors from your palette, and matching each observation to the appropriate color it falls into.

In Section 20.1, you plotted height against handspan for the survey data from the MASS package. Let's use color to additionally identify the nonwriting handspan variable. Load the package and execute the following line:

```
R surv <- na.omit(survey[c("Wr.Hnd","NW.Hnd","Height")])
```

This creates the data object surv

Now, the first thing to do is decide on your color palette.

```
R NW.pal <- colorRampPalette(colors=c("red","yellow2"))
```

This will generate colors that go from a dark, dull red at the lower end of the scale to a slightly faded yellow at the higher end (similar to the built-in heat palette; see Figure 25-2). Next, you need to decide how many bins, k, you're going to construct for the continuous values. This determines how many distinct colors to generate from NW.pal. For this data, set k=5.

```
R k <- 5
R ryc <- NW.pal(k)
R ryc
[1] "#B80000"#A33B00"#BC7700"#D5B200"#EEEE00"
```

Your five NW.pal colors as, are available. Next, you need to actually bin the continuous values, which you can do cut. First you need to set k+1 break points for the bins (refer to Section 4.3.3 for a refresher), seq.

```
R NW.breaks <- seq(min(surv$NW.Hnd),max(surv$NW.Hnd),length=k+1)
R NW.breaks
[1] 12.5 14.7 16.9 19.1 21.3 23.5
```

The six equally spaced values span the range of the students' nonwriting handspans, delineating your five intended bins. Then cut factorizes the nonwriting handspans with respect to those bins. You can use numeric to specifically retain the indices for extracting the appropriate color for each observation from your five ordered codes in ryc (full output is suppressed here for reasons of print).

```
R NW.fac <- cut(surv$NW.Hnd,breaks=NW.breaks,include.lowest=TRUE)
R as.numeric(NW.fac)
[1] 3 4 3 3 3 4 3 2 3 4 4 4 5 4 4 4 3 4 4 3 3 4 4 2 3 5
[32] 3 2 3 4 3 1 5 5 3 5 5 3 4 5 3 2 3 4 5 3 4 4 3 3 3 3 4 2 3
[63] 2 3 3 3 3 3 5 3 3 3 --snap--
R NW.cols <- ryc[as.numeric(NW.fac)]
R NW.cols
[1] "#BC7700"#D5B200"#BC7700"#D5B200"#BC7700"#BC7700"
[7] "#BC7700"#D5B200"#BC7700"#BC7700" --snap--
```

### Via Normalization

Using categorization to index a continuum with color is a little unsophisticated. There are plenty of ways you can bin your observations, for example, so your plot might look very different from the same plot designed by someone else. In a computational sense, it's more accurate (not to mention elegant)
to leave your continuous data as is.

Recall the built-in gray palette mentioned in Section 25.1.2. This function behaved a little differently from the others. Instead of simply asking for a number of colors from the specified palette, you're required to provide a numeric value of values to tell R, on a continuous scale from 0 through 1, "how far" along the palette to go. This type of behavior suits the current task perfectly, since your raw data are also on a continuous scale. To implement it, you need two ways: a to create a palette that will behave like a normalized version of your continuous values that fall within the acceptable range of 0 to 1 inclusive.

The colorRamp function allows you to create a palette and is used in the same way as colorRampPalette, but the result is a color palette function that expects a numeric value as stated. You'll see in a moment. To transform a collection of $n$ original values ($x_1, \dots, x_n$) to say, ($z_1, \dots, z_n$), where $0 \le z_i \le 1$; $i = 1, \dots, n$, you can employ the following equation:

```
$z_i = \frac{x_i - \min x_i}{\max x_i - \min x_i} (25.1)$
```
