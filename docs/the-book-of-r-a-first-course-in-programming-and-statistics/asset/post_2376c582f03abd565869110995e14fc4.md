
Let's make that an R function by writing the following in the R editor:

```
normalize <- function(datavec){
  lo <- min(datavec, na.rm=TRUE)
  up <- max(datavec, na.rm=TRUE)
  datanorm <- (datavec-lo)/(up-lo)
  return(datanorm)
}
```

Based on a vector as its only argument, normalize implements Equation (25.1), using the optional na.rm argument to ensure any missing values in datavec don't contaminate the calculation of the minimum and maximum values (see Section 13.2.1).

## 25.15 Including a Color Legend

Now that you use color to significant effect in your plots, you need a legend to reference the color scale. It's possible to create a legend using R tools alone, but it can be simpler to use contributed functionality in R instead.

One useful function for this is colorlegend command. This is found in the shape package (Sohorter, 2014), so first download and install shape from CRAN. The following code loads the package, reproduces the most recent plot (based on the surv object created earlier and shown on the right of Figure 25-4) with some better titles, and draws the color strip legend:

```
R library("shape")
R plot(surv$Nw.Hnd,surv$Height,col=Nw.cols2,pch=19)
xlab="Writing handspan (cm)",ylab="Height (cm)"
R colorlegend(Nw.pal(200),range=surv$Nw.Hnd),zval=seq(13,23,by=2),
posx=c(0.3,0.33),posy=c(0.5,0.9),main="Nonwriting handspan")
```

This result is given on the left of Figure 25-5.

The colorlegend assumes that you already have a plot present in an active graphics device, so you need to have one created. The first thing you supply to colorlegend is the span of the values you want to reference. This is easiest with a color palette function like those listed in the help file ?rainbow or using colorPalette--in other words, a function that takes an integer value telling how many colors to generate. Doing so with a large number of colors gives you a smooth color strip so use Nw.pal(200). Next, provide colorlegend with the range of the values that will be referenced by the legend using lim, in this case, range(surv$Nw.Hnd). The zval argument takes in the values you want to mark off on the legend. The values between 13 and 23, in steps of 2, are marked off.

![](img/b2cf85bb129f60fe59a2bae07)

**Figure 25-5:** Two examples of implementing a color legend using the colorlegend function from the shape package

The positioning and sizing of the legend are done using the posx and posY arguments. Each of these must be a vector of length 2 describing relative coordinates, horizontal (posx) and vertical (posy) lengths of the strip. In this example, posx=c(0.3,0.33) tells the function to draw the width of the legend from 30 percent of the left of the device to 53 percent so that the width is 33 percent of the overall device and positioned to the left of the center. posY=c(0.5,0.9) says you want the strip to span 40 percent of the device from the bottom to 90 percent and up. Lastly, you can add the title to the legend by supplying a character string to main. The device-specific nature of posx and posY means that if you resize your device, you might need to reevaluate the values of these arguments. If you wanted the legend to appear outside the plot region, you could easily use the xlim argument in the initial call to plot; alternatively, change the outer margin to give enough room to plot the legend, taking up only 2 percent of the device width on the right with posx=c(0.89,0.91). With no specification of posy, colorlegend has used the default c(0.05,0.9), giving a color strip that spans almost the entire height of the device. This next chunk of code does just by widening the right margin, replotting the scatterplot, and inserting a color legend into that extra space.

```
R par(mar=c(5,4,4,6))
R plot(surv$Nw.Hnd,surv$Height,col=Nw.cols2,pch=19,
xlab="Writing handspan (cm)",ylab="Height (cm)")
R colorlegend(Nw.pal(200),range=surv$Nw.Hnd,zval=13.5:22.5,digit=1,
posx=c(0.89,0.91),main="Nonwriting handspan")
```

The Result is given on the right of Figure 25-5. The legend is narrower, taking up only 2 percent of the device width on the right with posx=c(0.89,0.91). With no specification of posy, colorlegend has used the default c(0.05,0.9), giving a color strip that spans almost the entire height of the device. The tick marks and labeling of the new legend are now placed in increments of 1 from 13.5 to 22.5; note that to display decimal places in other words, significant digits, you need to increase the digit argument from its default, 0 to reveal them. digit+1 prints the tick labels to one decimal.

There are properties that you can control with these, including labeling style and tick positioning; see ?colorlegend help file for details. You may also like to investigate the similarly named function color.legend in the contributed plotrix package (Lemon, 2006) for a slightly different take on drawing color legends on R plots.

## 25.1.6 Opacity

Another useful is the ability to specify the opacity of any of the colors and color palettes discussed far. All functions that provide the user with hex codes have an optional argument alpha, the value range which depends on the function (a quick check of the corresponding documentation will tell you). For example, the rgb function uses maxColor to set the upper bound on opacity, and palette functions like rainbow all use the normalized range from 0 through 1 (just like in the ggplot2 plots throughout Chapter 24).

By assuming opacity when you are creating colors, hex codes change slightly when opacity is explicitly set using alpha. Rather than six characters after the #, eight will appear, with the last containing the additional opacity information. Consider the following lines of code, which generate four different versions of: default, zero opacity, 40 percent opacity (0.4 x 255 = 102), and full opacity, respectively:

```
R> rgb(cbind(255,0,0),maxColorValue=255)
[1] "#FF0000"
R> rgb(cbind(255,0,0),maxColorValue=255,alpha=0)
[1] "#FF0000"
R> rgb(cbind(255,0,0),maxColorValue=255,alpha=102)
[1] "#FF0006"
R> rgb(cbind(255,0,0),maxColorValue=255,alpha=255)
[1] "#FF00FF"
```

Note that the first and last colors are identical; it's just that the last hex code specifies full opacity. You can always adjust the opacity of any color you've already got with the alpha.f argument (which takes values in the range 0 through 1) of the ready-to-use adjustcolor function.
