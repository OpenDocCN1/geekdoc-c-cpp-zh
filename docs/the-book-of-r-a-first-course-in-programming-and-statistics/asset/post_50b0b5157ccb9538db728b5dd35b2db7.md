
The result of these two lines is given on the bottom left of Figure 25-17. Unfortunately, the original density estimate is still defined in terms of the original x and y-ranges of the raw data, which gives you a border of empty pixels; in addition, the aforementioned density areas still fall outside the observation window.

All this emphasizes the important fact that a z-matrix is specific to a predefined evaluation grid. The only way to get your density estimate to span the geographical study region for the Chorley-Ribble data is to revise your kernel estimate so that it's produced on an evaluation grid that spans the limits of the region. Fortunately, the kde2 function allows you to set optional x-limits of the evaluation grid with the lims argument. This expects a numeric vector of length 4, with the x-axis lower and upper values followed by the y-axis and upper values, in that. The following code reestimates the density using the study region limits and plots. The result is given on the bottom of Figure 25-17.

```R
R> chor.dens(chor$x,chor$y,n=256,lims=c(WIN$xr,WIN$yr))
R> image(chor.dens.WIN$x,chor.dens.WIN$y,chor.dens.WIN$z,col=rbw)
R> plot(chor.WIN,add=TRUE)
```

With this, you've solved the problem of ensuring your surface spans the desired area. However, this definitely highlights the second problem—the data that were actually observed strictly within the defined polygon, you can see plotted pixels outside the geographical region, which doesn't make sense. You can control precisely which pixels are plotted in any given image by setting the relevant entries in your z-matrix to be NA if you don't want them drawn.

You'll need a mechanism that can decide whether a cell enters inside or outside the polygon (the object chor.WIN). If it falls outside the polygon (object chor.WIN$z), you'll want to force it to be NA. In general, this type of decision making requires you to test each element of the matrix with respect to its coordinate value on the evaluation grid, possibly using your own R function. Frankly, in this case, the inside.win function of spatstat does exactly that, but the principle remains the same whenever you need to control over which pixels are plotted and which not.

One or more two-dimensional (x,y) coordinates and an object of class 'win', the inside.win function returns a logical vector with TRUE for those coordinates inside the defined region and a FALSE for any other coordinate. As a quick demonstration, observe the following

```R
R> inside.win(x=c(355,345),y=c(420,415),w=chor.WIN)
[1] TRUE FALSE
```

This confirms what you can see from Figure 25-17—that the coordinate (355,420) lies well within the polygon and that coordinate (345,415) doesn't.

Now, you need to use the inside.owin function on every coordinate in the evaluation grid that z-matrix chor.dens.WIN$ sits on. First, create the full set of grid coordinates using expand.grid, in the same way as illustrated in Section 25.3.1.

```R
R> chor.xy <- expand.grid(chor.dens.WIN$x,chor.dens.WIN$y)
R> nrow(chor.xy)
```
+ [1] 65536

Calling nrow on the resulting data frame of coordinates confirms you exactly $256^2=$ 65536 grid points as defined in the chor.dens.WIN KDE object. The following call takes the two columns of chor.xy and makes use of logical negation (using !) to produce a logical vector that flags grid coordinates that are outside the defined region.

```R
R> chor.outside <- !inside.owin(x=chor.xy[,1],y=chor.xy[,2],w=chor.WIN)
```

The final step is now

```R
R> chor.out.mat <- matrix(chor.outside,nrow=256,ncol=256)
R> chor.dens.WIN$Z[chor.out.mat] <- NA
```

First, for clarity, recast the long chor.outside vector as a $256 \times 256$ matrix to emphasize that it corresponds exactly to the z-matrix of interest. This logical flag matrix allows us to directly overwrite the “outside” entries in the z-matrix to be NA.

All that's left now is to plot the newly manipulated z-matrix. Make sure you have the shape package loaded for the finishing touch of a color. The following code creates the KDE surface pixel image with points restricted to the geographical region defined by Window only:

```R
R> dev.new(width=7.5,height=7)
R> par(mar=c(5,4,4,7))
R> image(chor.dens.WINZ,col=row,xlab="Eastings",ylab="Northings",bty="1",asp=1)
R> plot(chor.WIN,lwd=2,add=TRUE)
R> colorleg(col=row,zlim=chor.dens.WIN$z,na.rm=TRUE),zval=seq(0,0.2,0.0025),main="KDE")
```

First you open a new graphics device and the right margin to incorporate the color legend. Next you invoke image to plot, specifically using an L-shaped box and a one-to-one y aspect ratio, and then add the region with thicker lines. Finally you execute colorleg to obtain an appropriately positioned legend referencing the color values (which were found after a little trial and error) (the specific positioning and tick marks).
