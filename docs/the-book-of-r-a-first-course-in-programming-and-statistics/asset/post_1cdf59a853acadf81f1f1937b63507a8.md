
# Isosurface Level Selection

The selection of the level to display depends on the range of values that make up the result of the trivariate function itself. When you choose compute.count=TRUE in the call to kde, you're automatically provided with a collection of appropriate levels. These are returned in the component $count as a numeric vector with a length of exactly 99, representing each integer between 1 and 99 percent.

Internally, these levels are calculated by taking the result of the trivariate function at the location of each of the originally observed data points and then using quantile to obtain all the integer-valued percentiles (from 99 to 1 percent) of these density values (for a refresher on quantiles, refer to Section 13.2.5). They are returned in decreasing order; in other words, $quak.dens3count[1]$ corresponds to the 99th percentile, and $quak.dens3count[99]$ is the 1st percentile.

Though these values are obtained in a different way from the $\alpha$-levels you experimented with when plotting the trivariate normal density, you essentially end up with same interpretation when visualizing the result—density at level of estimated observed "denseness" that you want. For example, the lower quartile (aka the 25th percentile) is extracted from the following:

```
$quak.dens3count[75]
25.00274e-05
```

This provides the value of KDE trivariate function that is estimated to separate the most spatially diffuse 25 percent of the observations from the rest (in other, so that the result diffuse blobs encapsulate the most spatially dense 75 percent of the data).

> At the time of writing, both the rgl and misc3d packages are dependencies of ks. This means they are loaded automatically when you load ks, so you don't need to call library("rgl") or library("misc3d") explicitly in this case, and plot3d and contour3d are already available to you. This may change as the developers update their packages over time.

When you execute the code, it first replots the quak data that the density estimate is based on and adds the corresponding isurface using the lower point-wise density quartile as the desired level. You can see the result on the left of Figure 26-14.

```
plot3d(x=quaklong,y=quaklat,z=quakdepth,
xlab="x.latt",ylab="Latitude",zlab="Depth")
contour3d(x=x.latt,y=y.latt,z=z.latt,f=quak.dens3count[75],add=TRUE)
```

### 2D Circle

Let's start with a simple example. One of the most immediately recognizable shapes defined this way is a 2D circle. To find any point on a circle, you need to know the center and its radius, and provide the angle $\theta$:

$x = a + r\cos(\theta)\quad\text{and}\quad y = b + r\sin(\theta)$

If you're working in degrees, then technically 0 ≤ θ ≤ 360; to convert to radians, you must multiply by π/180 such that 0 ≤ θ < 2π. Draw a circle based on the equations in (26.1), first decide on a radius, then decide on a center, and generate the corresponding values of x and y. Consider the following code:

```
R radius <- 3
R a <- -1
R b <- -4.4
R angle <- 0.360*(pi/180)
R x <- a+radius*cos(angle)
R y <- b+radius*sin(angle)
R plot(x,y,ann=FALSE)
R abline(v=a)
R abline(h=b)
```

The circle will have a radius of 3 and be centered at (1,-4.4). Given the sequence defined as angle, note the plot will place a point at each integer angle from 0 to 360 degrees—I allowed the upper limit to be equal to 360 to fully complete the rotation—after which you convert to radians (with multiplication by π/180) in order to use the built-in R functions cos and sin. The geometric value of pi (π=3.1415...) is held within the ready-to-use R object pi (see the help file ?Constants). The last three lines execute the plot, shown in Figure 26-16.
