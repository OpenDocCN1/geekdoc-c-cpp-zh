
# 24.3 Multiple Plots and Variable-Mapped Facets

In Section 23.1.4, you saw different ways in which several traditional R plots can be viewed or laid out in a single graphics device. The same methods, as setting nrow in a call to par or compartmentalizing the device using layout, can't be used for ggplot2 graphics. There are other functions, though, that allow independent ggplot2 plots to populate a single device. True to form, ggplot2 also offers a convenient way to consider multiple-plot graphics using facets, where the images are all drawn in one.

## 24.3.1 Independent Plots

First, let's say you have several ggplot2 plots that you've created independently of one another and you'd like to arrange them as a single. A quick way to do this is to use the grid.arrange function provided in the gridExtra package (Augie, 2012). Install the package by running install.packages("gridExtra") at the prompt (you'll need an Internet connection).

To illustrate the use of grid.arrange, continue with the object—the copy of air data you created in Section 24.2 with the Month factor column. Now, consider the following three ggplot2 objects, which I'll explain in a moment:

```
gg1 <- ggplot(air,aes(x=1:nrow(air),y=Temp)) +
  geom_line(aes(col=Month)) +
  geom_point(aes(col=Month,size=Wind)) +
  geom_smooth(method="loess",col="black") + 
  labs(x="Time (days)",y="Temperature (F)")
gg2 <- ggplot(air,aes(x=Solar.R,fill=Month)) +
  geom_density(alpha=0.4) +
  labs(expression=paste("Solar radiation ",ring(A),")) +
  y="Kernel estimate"
gg3 <- ggplot(air,aes(x=Wind,y=Temp,color=Month)) +
  geom_point(aes(size=Ozone)) +
  geom_smooth(method="lm",level=0.9,fullrange=FALSE,alpha=0.2) + 
  labs(x="Wind speed",y="Temperature (F)")
```

Execute library("gridExtra") to load the required package. To view gg1, gg2, and gg3 in one window, simply call the following, which produces Figure 24-4:

```
grid.arrange(gg1,gg2,gg3)
```

And you'll likely see some warning messages telling you there are missing values in the air data frame and recommending to resize the plots.

As you can see, grid.arrange is easy to use—you simply create your ggplot2 images first and store them as objects, then provide them directly to the arrangement function. grid.arrange decides how to produce the final layout based on the number of objects you give (in this case, it's a column of the three plots). You can control the order of the plots by changing the order in which the objects are supplied. There are more optional arguments, which you can read in the documentation file grid.arrange.

The plots gg1, gg2, and gg3 also provide an opportunity to discuss more ggplot2 capabilities. Since there's a lot going on, especially in gg1 and gg3, I'll discuss the code for each object separately.

gg1 The first plot is of the daily temperature. Create a sequence of integers matching the number of rows in aes, to be paired with geom_line and geom_point all interconnecting lines and the raw observations themselves, to be added to the default aesthetic mapping. The interconnecting lines are set to change color according to Month, The raw observations also change color according to Month, and the point sizes are proportional to the wind speed regressions. I include an overall LOESS with its default color changed to “black”. I remain with the default mapping—I don't want to separate trends for each month. The final addition of labs merely clears the axis titles you've already seen.

gg2 The second plot is a variant of the plot on the right of Figure 24-3. This time, it shows the densities of the solar radiation readings (in amounts). The opacity is set, as you saw earlier, using alpha in geom_density. It's also worth noting that I used expression in labs to approximate the angst unit symbol, Å, using ring(A).

gg3 The last is a scatterplot of temperature by wind speed, where you can see a negative relationship. The color, again to be assigned each month, is also set as the default aesthetic mapping in ggplot. In the call to geom_point, the aesthetic enhancement is instructed to plot size proportional to the ozone reading (this is to ensure correct formatting of the corresponding legend, light is a different kind of use for geom_smooth. In setting method="lm", I want superimposed correspond to simple linear model fits to the x and y aesthetic mappings as predictor and response, respectively. Additionally including the factor Month in the default mapping ensures separate simple linear models are fitted for the temperature on wind speed for each month and colored appropriately (it’s important to note that the plotted lines do not reflect a multiple linear model that includes all the variables in the plot). Light, transparent 90 percent CI are included with each regression (level=0.9 and alpha=0.2), and setting fullrange=FALSE restricts each regression only to the width of the observed data for each month.

## 24.3.2 Facets Mapped to a Categorical Variable

If you independently created ggplot2 graphics to appear in the same window, grid.arrange is arguably the best way to deal with them. However, the ggplot2 package offers a flexible alternative to quickly view multiple plots. Often, when exploring a data set, you'll want to create several plots of the same variables based on the levels of one or more categorical variables. This behavior, referred to as faceting, familiar territory for ggplot2 using either the facet_wrap or the facet_grid command.

Let's focus on the simplest case where you have one categorical variable. Remaining with the air data frame object, the following line creates a ggplot2 object of the density plots of the New York temperatures on the right of Figure 24-3:

```
ggp <- ggplot(data=air,aes(x=Temp,fill=Month)) + geom_density(alpha=0.4) + 
  ggtitle("Monthly temperature probability densities") +
  labs(x="Temp (F)",y="Kernel estimate")
```

Rather than view all densities together, you can create a plot of each one separately, displaying them in the same device, with the following three uses of facet_wrap, the results are at the top left, top right, and bottom of Figure 24-5:

```
ggp + facet_wrap("Month")
ggp + facet_wrap("Month",scales="free",nscale="free")
ggp + facet_wrap("Month",nrow=1)
```

![](img/b2cfc85cbb129f60fe595a2bae074fe4_652_0.png)

Figure 24-5: Three examples using facet_wrap to display kernel density estimates of the temperature data, split by month

The facet_wrap function automates the layout of the multiple plots; a formula specifying the faceting variable. In all the previous plots, this is set to “Month, to be read as “by Month”. The code for the first visualization, given at the top left, offers no additional arguments, and without arguments the x and y axes of each facet are fixed, so you can compare the plots on the same scale. If you don't want that, you can instruct the axes to be “free", means each plot is produced on scales specific to its contents. You can see this in the second plot, at the right in Figure 24-4, the line of code which specifies scales="free". You can also opt to free only the horizontal or vertical axes with scales="free x" or scales="free y", respectively. Note that facet placement can be tailored by using nrow and ncol arguments. In the third plot, setting nrow=1 instructs R to place the plots in one row, giving the horizontal arrangement on the bottom of Figure 24-5. For further details on placement, you can find the documentation for this command at facet_wrap.

The alternative to facet_wrap, facet_grid, does much the same thing but isn't to wrap the plots if you're faceting by only one categorical variable. The formula var1~var2 is interpreted as “facet var1 as rows and var2 as columns”. If you are interested in faceting by only one variable in columns or rows, then simply replace var1 or var2 with a dot (.). The third image in Figure 24-5, for example, can just be achieved via facet_grid as follows:

```
R> ggp + facet_grid(. ~ Month)
```

The next example, however, shows facet_grid in action with two variables. Turn your attention again to the diabetes data frame in the faraway package. After loading the package, the following code creates the object with the data frame of interest and with missing-value rows deleted, producing Figure 24-6:

```
R> diab <- na.omit(diabetes[c("chol","weight","gender","frame","age",
"height","location")]) + 
R> ggplot(diab, aes(x=age,y=chol)) + 
geom_point(aes(shape=location,size=weight,col=height)) + 
facet_grid(group="frame") + geom_smooth(method="lm") + 
labs(y="cholesterol")
```

The initial call to ggplot R to use diab and plot total cholesterol again. An addition of geom point sets changes the shape, size, and color of each plotted point to change according to the county location, the weight, and the height of the individuals, respectively (as you've already seen for point size based on a continuous variable, point color is also automatically changed to vary if the continuous mapped aesthetic variable isn't a factor).
