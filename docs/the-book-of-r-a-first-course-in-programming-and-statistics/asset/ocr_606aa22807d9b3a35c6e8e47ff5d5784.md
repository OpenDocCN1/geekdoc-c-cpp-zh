makes sense to internally define a helper function when (a) it's used only by a single parent function, and (b) it's called multiple times within the parent function. (Of course, multiples satisfies only (a), and it's provided here just for the sake of illustration.)

# 13.2 Disposable Functions

Often, you may need a function that performs a simple, one-task for. For example, when you use apply, you'll typically just want to pass in a short, simple function as an argument. That is where disposable (or anonymous) functions come in—allow you to define a function intended for use in a single instance without explicitly creating a new object in your global environment.

Say you have a numeric matrix whose columns you want to repeat twice and then sort.

```
R foo <- matrix(c(2,3,3,4,2,4,7,3,3,6,7,2),3,4)
R foo
,[1],[2] [3] [4]
[1] 2 4 7 6
[2] 3 2 3 7
[3] 3 4 3 2
```

This is a perfect task for apply, which can apply a function to each column of the matrix. This simply has to take in a vector, repeat it, and sort the result. Rather than define sort function separately, you can define a disposable function right in the argument of apply using the function command.

```
R apply(foo,MARGIN=2,FUN=function(x){sort(rep(x,2))})
,[1],[2] [3] [4]
[1] 2 2 3 2
[2] 2 2 3 2
[3] 3 4 3 6
[4] 3 4 3 6
[5] 3 4 7 7
[6] 3 4 7 7
```

The function is defined in the standard format directly in the call to apply. This function is defined, called, and immediately forgotten once apply is complete. It is disposable in the sense that it exists only for the one instance where it is actually used.

Using the function command this way is a shortcut more than anything else; plus, it avoids the unnecessary creation and storage of a function object in the global environment.
