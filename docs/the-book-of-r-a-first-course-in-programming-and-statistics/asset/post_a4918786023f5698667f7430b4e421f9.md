## 2.3.4 Vector-Oriented Behavior

Vectors are so useful because they allow R to carry out operations on multiple elements simultaneously with speed and efficiency. This vector-oriented, vectorized, or element-wise behavior is a key feature of the language, one that you will briefly examine here with some examples of rescaling measurements.

Let's start with this example:

```R
> foo <- 5.5:0.5
> foo
[1] 5.5 4.5 3.5 2.5 1.5 0.5
> foo-c(2,4,6,8,10,12)
[1] 3.5 0.5 -2.5 -5.5 -8.5 -11.5
```

This code creates a sequence of six values between 5.5 and 0.5, in increments of 1. From this vector, you subtract another vector containing 2, 4, 6, 8, 10, and 12. What does this do? Well, simply, R matches the elements according to their respective positions and performs the operation on each corresponding pair of elements. The resulting vector is obtained by subtracting the first element of c(2,4,6,8,10,12) (5.5 – 2 = 3.5), by subtracting the second element of c(2,4,6,8,10,12) from the second element of foo (4.5 – 4 = 0.5), and so on. Thus, rather inelegantly cycling through each element (as you could do by hand or explicitly using a loop), R permits a fast and efficient alternative using vector-oriented behavior. Figure 2-1 illustrates how you can understand this type of and highlights the fact that the positions of the elements are crucial in the final result; elements in differing positions have no effect on.

The situation is made complicated when using vectors of different lengths, which can happen in two ways. The first is when the length of the longer vector can be evenly divided by the length of the shorter vector. The second is when the length of the longer vector cannot be divided by the length of the shorter vector—this is unintentional on the user's part. In both of these situations, R essentially attempts to replicate, or recycle, the shorter vector by many times as needed to match the length of the longer vector before completing the operation. As an example, suppose you wanted to alternate the elements of foo earlier as positive. ![b2cf85bb129f60fe595a074fe4_67]

Figure 2-1: A conceptual diagram of element-wise behavior carried out on two vectors of equal length. Note that the operation is performed by matching up the positions. You could explicitly multiply foo by c(1,-1,-1), but don't need to write out the latter vector. Instead, you can write the following:

```R
R bar <- c(1,-1)
R foo+=bar
[1] 5.5 -4.5 3.5 -2.5 1.5 -0.5
```

has been applied repeatedly throughout the length of foo. The left plot of Figure 2-2 illustrates this particular example. Let's see what happens when the vectors are not evenly divisible.

```R
R baz <- c(1,-1,-0.5)
R foo+=baz
[1] 5.50 -4.50 1.75 -1.25 1.50
Warning message: foo + baz : longer object length is not a multiple of shorter object
```

You see that R has matched the first four elements of foo with the entirety of baz, which is not able to fully repeat. The repetition has been attempted, with the first two elements of baz matching with the last two of foo, though without protest from R which notifies the user of uneven lengths (you'll look at warnings more detail in Section 2.1). The plot on the right in Figure 2-2 illustrates this example.

As noted in Section 2.3.3, you can consider single values as vectors of length 1, so you can use a single value to repeat an operation on all the values of a vector of any length. Here's an example, using the same vector foo:

```R
R qux <- 3
R foo+qux
[1] 8.5 7.5 6.5 5.5 4.5 3.5
```

This is easier than executing foo+c(3,3,3,3,3,3) or the more general foo+rep(x=3,times=length(x=foo)). Operating on vectors using a single value in this fashion is quite common, such as if you want to rescale or translate a set of measurements by some constant amount.

Another benefit of vector-oriented behavior is that you can use vectorized functions to complete potentially laborious tasks. For example, if you want to sum or multiply all the entries in a numeric vector, you can just use built-in function.

Recall foo, shown earlier:

```R
> foo
[1] 5.5 4.5 3.5 2.5 1.5 0.5
```

You can find the sum of these six elements with

```R
> sum(foo)
[1] 18
```

and their product with

```R
> prod(foo)
[1] 162.4219
```

Far from being just convenient, vectorized functions are faster and more efficient than an explicitly coded iterative approach like a loop. The main takeaway from these examples is that much of R's functionality is designed specifically for certain data structures, ensuring neatness of code as well as optimization of performance.

Lastly, as mentioned earlier, this vector-oriented behavior applies in the same way to overwriting multiple elements. Again using foo, examine the following:

```R
R foo
[1] 5.5 4.5 3.5 2.5 1.5 0.5
R foo[c(1,3,5,6)] <- c(-99,99)
R foo
[1] -99.0 4.5 99.0 2.5 -99.0 99.0
```

You see four specific elements being overwritten by a vector of length 2, which is cycled in the same fashion you are familiar with. Again, the length of the vector being overwritten, or else divide the number of elements being overwritten, or a warning similar to the one shown earlier will be issued when R cannot complete a full-length recycle.
