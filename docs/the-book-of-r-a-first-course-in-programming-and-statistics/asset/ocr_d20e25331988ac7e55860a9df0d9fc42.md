One handy feature of drop1 that its scope argument is optional. If you don't include code, it defaults to the intercept-only model which is the "most-reduced" model, which is usually a reasonable choice.

Before diving into the deletion process, remind yourself of the interpretation of what you're doing. Just as adding any will improve the goodness-of-fit in forward selection, deleting any term in backward selection will always worsen the goodness-of-fit. The real question is the perceived significance of these changes in fit. In the same way as earlier, when you wanted to add only those that offer a statistically significant improvement in goodness-of-fit, when dropping terms, you only want to remove those that do not result in a statistically significant detriment to goodness-of-fit. As such, backward selection is the complete reverse of forward selection in the way it's carried out.

So, from the output of drop1, you want to choose the term to remove from the model that has the least significant effect of reducing the goodness of fit. In your words, you're looking for the term with the largest, nonsignificant p-value for its partial F-test—because dropping a term with a significantly small p-value would significantly worsen the predictive capacity of the regression model.

In the current example, it seems the predictor bs has the least significant effect on reducing the goodness-of-fit, so let's start the update by removing that term from nuc.

```
R nuc.1 <- update(nuc.0,"-bw")
```

Use of in this selection algorithm is the same as before; though, you use -a to signify the deletion of a term following the standard "what's already there".---
The process is then repeated using the latest model nuc:1.

R drop1(nuc.1,test="F")
