```
R> bar
[1] NA
```

Note that bar, the NA object, is printed with an index position [1]. This suggests you have a vector with a single element. In contrast, you explicitly foo to be empty with NULL. Printing this object doesn't provide a position index because there is no position to.

This interpretation of NULL also applies to vectors that have other well-defined items. Consider the following two lines of code:

```
R> c(2,4,NA,8)
[1] 2 4 NA 8
R> c(2,4,NULL,8)
[1] 2 4 8
```

The first line creates a vector of length 4, with the third position coded as NA. The second line creates a similar vector using NULL instead of NA. The result is a vector with a length of only 3. That's NULL cannot take a position in the vector. As, it makes sense to assign NULL to multi-ple positions in a vector (or any other structure). Again, here's an example:

```
R> c(NA,NA,NA)
[1] NA NA NA
R> c(NULL,NULL,NULL)
NULL
```

The first line can be interpreted as "three possible slots for unrecorded observations. The second line simply provides "emptiness three times", which is interpreted as one single, unsettable, empty object.
At this point, you might wonder why there is even a need for NULL. If something is empty and dont, why define it in the first place? The answer lies in the able to explicitly state or check whether a cer-tain object has been defined. This occurs when calling functions in R. For example, when a function contains optional arguments, internally the function has to check which of those arguments have been supplied and which are missing or empty. The NULL value is a valuable and flexible tool that the author of a function can use to facilitate such checks. You'll see examples of this on Chapter 11.
