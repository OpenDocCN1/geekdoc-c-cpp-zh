
## 2.1.1 Arithmetic

In R, standard mathematical rules apply throughout and follow the usual left-to-right order of operations: parentheses, exponents, multiplication, division, addition, subtraction, PEMDAS. Here's an example in the console:

```
R> 2+3
[1] 5
R> 14/6
[1] 2.333333
R> 14/6+5
[1] 7.333333
R> 14/(6+5)
[1] 1.272727
R> 3*2
[1] 9
R> 2*3
[1] 8
```

You can find the square root of any non-negative number with the sqrt function. You simply provide the desired number to x as shown here:

```
R> sqrt(x=9)
[1] 3
R> sqrt(x=5.311)
[1] 2.304561
```

When using R, you'll often find that you need to translate a complicated arithmetic formula into code for evaluation (for example, when replicating a calculation from a textbook or research paper). The next examples provide a mathematically expressed calculation, by its execution in R:

```
R> 10^2+3*60/8-3
[1] 119.5
```

$10^2 + \frac{3 \times 60}{8} - 3$

```
R> 5^3+(6-2)/(61-4)
[1] 8.064516
```

$5^3 \frac{(6-2)}{61-4}$

```
R> 2^(2+1)-4+64^{((-2)^(2.25-1/4))
[1] 16777220
```

$2^{2+1} - 4 + 64^{2.25-\frac{1}{4}}}$

```
R> (0.44*(1-0.44)/34)^(1/2)
[1] 0.08512966
```

$\frac{0.44 \times (1-0.44)}{34}$

Note some R expressions require extra parentheses that aren't present in the mathematical expressions. Missing or misplaced parentheses are common causes of arithmetic errors in R, especially when dealing with exponents. If the exponent is itself an arithmetic calculation, it must always appear in parentheses. For example, in the third expression, if you need parentheses around 2.25-1/4. You also need to use parentheses if the number being raised to some power is a calculation, such as the expression 9^2+1 in the third example. Note that R considers a negative calculation because it interprets, for example, -2 as -1^2. This is why you need parentheses around -2 in that same expression. It's important to highlight these issues early because they can easily be overlooked in large chunks of code.

## 2.1.2 Logarithms and Exponentials

You'll see or read about researchers performing a log transformation on certain data. This refers to rescaling numbers using a value referred to as base, the logarithm. When supplied a given number x and a value referred to a base, the log calculates the power to which you must raise the base to get x. For example, the log of x=243 to base 3 (mathematically as log₃243) is 5, because 3^5 = 243. In R, the log transformation is achieved with the log function. You supply the number to the transform, assigned to the value x, and the base, assigned to base, as follows:

```
R> log(x=243,base=3)
[1] 5
```

Here are some things to consider:

- Both x and the base must be positive.
- The log of any number x when the base is equal to x is 1.
- The log of x = 1 is always 0, regardless of the base.

There's a particular kind of log transformation often used in mathematics called the natural log, which fixes the base at a special mathematical number—Euler's number. This is conventionally written as e and approximately to 2.718.

Euler's number gives rise to the exponential function, defined as e raised to the power of x, where x can be any number (negative, zero, or positive). The exponential function, f(x) = e^x, is often written as exp(x) and represents the inverse of the natural log such that exp(log_e x) = log_e exp(x) = x. The R command for the exponential function is:

```
R> exp(x=3)
[1] 20.08554
```

The default behavior of log is to assume the natural log:

```
R log(x=20.08554)
[1] 3
```

You must provide the value of base yourself if you want to use a value other than $e$. The logarithm and exponential functions are mentioned here because they become important later on in the book—many methods they use because of their various helpful mathematical properties.

## 2.1.3 E-Notation

When R prints large or small numbers below a certain threshold of significant figures, set at 7 by default, the numbers are displayed using the classic scientific e-notation. The e-notation is typical to most programming languages—and many desktop calculators—to allow easier interpretation of extreme values. In e-notation, any number $x \times 10^y$, which represents exactly $x$ times $10^y$. Consider the number $2,342,151,012,900$. It could, for example, be represented as:

- $-2.3421510129e12$, which is equivalent to writing $2.3421510129 \times 10^{12}$
- $2.3421510129e10$, which is equivalent to writing $2.3421510129 \times 10^{10}$

You could use any value for the power of $y$, but standard e-notation uses the places that a decimal just after the first significant digit. Simply, for a positive power $+y$, the e-notation can be interpreted as "move the decimal point y positions to the right." For a negative power $-y$, the interpretation is "move the decimal point y positions to the left."

```
R> 2342151012900
[1] 2.3421510129e12
R> 2342151012900
[1] 2.3421510129e10
```

In the first example, R shows the first seven digits and hides the rest.

## 2.2 Assigning Objects

So far you've used only numeric values, but note that the procedure for assignment is universal for all types and classes of objects, which you'll examine in the coming chapters. If you want to save something, store it under a given name so it can be accessed later. You can specify an assignment in R in two ways: using arrow (<-) and using equal sign (=). Both methods are shown here:

```
R> x <- -5
[1] -5
```

```
R> x = x + 1 # this overwrites the previous value
R> x
[1] -4
```

```
R> mynumber = 4
R> y <- mynumber+x
[1] 0
```

```
R> ls()
[1] "mynumber" "x" "y"
```

As you can see from these examples, R will display the value assigned to an object when you enter the name of the object. When you use the object in subsequent operations, R will substitute the value assigned to. Finally, if you use the ls command (in Section 1.3.1) to examine the contents of the current workspace, it will reveal the names of the objects in alphabetical order.

Although = and <- do the same thing, it is wise (for the neatness of code) to be consistent. Many users choose to stick with the <-, however because of the potential for confusion (for example, I didn't mean that x is mathematically equal to x + 1). In this book, I'll do the same and reserve = for setting function arguments, which begin in Section 2.3.2. So far you've used only numeric values, but note that the procedure for assignment is universal for all types and classes of objects, which you'll examine in the coming chapters.

Objects can be named anything long as the name begins with a letter (in other words, not a number), avoids symbols (though underscores and periods are fine), and avoids the handful of "reserved" words such as those used for defining special values (see Section 6.1) or for controlling code flow (see Chapter 10). You can find a useful summary of these naming rules in Section 9.1.2.
