### ### Example 3: Nonparametric Bivariate Density Estimate (Earthquake Data)

Another useful role fulfilled by contour plots and the other plots in this chapter is to visualize bivariate density functions.

In 24.2.2, you looked at the idea of kernel density estimation (KDE) as a method by which to smooth estimates of the probability density functions of your data—essentially, sophisticated histograms. KDE extends to higher dimensions quite naturally that you can also estimate the density of bivariate observations in the x-y plane. This again involves a z-matrix over a fixed grid of coordinates. For theoretical details on multivariate KDE, see Wand and Jones (1995).

Turn attention back to the built-in quake data frame and recall the plots of the spatial coordinates of the 1,000 seismic events (for example, Figure 13-1 on page 265 and Figure 23-1 on page 578). To estimate the probability density function of these points, you can use the kde2d package. Load kde2d and execute the following line to produce the kernel estimate of the two-dimensional data:

```R
R> quake$kde2d(x=quake$long,y=quake$lat,n=100)
```

Supply the bivariate data as the x and y arguments for the horizontal and vertical axes. The optional argument n is used to specify the number of evaluation coordinates (along each of the two) at which actually return the estimated density surface. This defines the size of the matrix returned by a call kde2d. Here, you've asked for KDE to be performed on a 100 x 100 evenly spaced grid over the range of the observed data.

The resulting object is simply a list with three members. The components accessed through $sx$ and $sy$ contain the evenly spaced evaluation coordinates in the corresponding axis directions, and $sz$ provides you with the corresponding z-matrix. You can confirm by entering either $quad.dens$sx$ or $quad.dens$sy$ at the prompt that they are indeed sequences spanning the ranges of the observed data. Entering the following confirms the size of the matrix:

```R
R> dim(quake.dens$sz)
[1] 100 100
```

With that, you have all the ingredients to display contours of KDE surface. The next line produces the default contour plot, on the top left of Figure 25-12.

```R
R> contour(quake.dens$sx,quake.dens$sy,quake.dens$sz)
```

There are many more optional arguments available to contour for displaying your continuous surface. It can also be helpful to simultaneously view other data or observations (if they've been used in some way to create the surface, as is the case with bivariate KDE). The following code replots the quakes kernel estimate with unpadded axes, different contour levels to the defaults, and the observations; you can see the result on the right of Figure 25-12.

```R
R> contour(quake.dens$sx,quake.dens$sy,quake.dens$sz,levels=50,drawlabels=FALSE,xaxis="1",yaxes="1",xlab="Longitude",ylab="Latitude")
R> points(quakes$long,quakes$lat,cex=0.7)
```

Rather than using levels to determine the exact levels at which to draw the contours (as you did with Example 2), you can use the levels argument to specify the number of levels to display, and the function will choose the levels to display. This numeric value must be on the same scale as the resulting bivariate function of interest; here, I asked for contours at all integer levels from 32 through 8. I also employ familylty and lwd to control the appearance of the contours themselves, which are set here as dashed and slightly thicker than usual.

Furthermore, for contour plots in particular, you'll want to deviate from the default axis limit style, the small amount of additional "padding" space that's included in the default plot region (refer to Section 23.4.1) can be prominent—take another look at the volcano contour plot in Figure 25-10. As previously shown, setting xaxs and yaxs to "i" restricts all plotting to the exact limits imposed by x and y.

### 25.4.2 Color-Filled Contours

For a straightforward variation on the contour plot, you can use color to fill the gaps between the levels that are drawn. Combined with a color legend, this removes the need to label the contour lines and in certain cases can make it easier to visually interpret fluctuations in the plotted-matrix surface.

The filled.contour function does this for you. You need to supply the increasing of grid coordinates in both the x-axis and y-axis directions, as well as the corresponding -matrix, to the x, y, and z in the same way as contour. The easiest way to specify the colors is to supply a color palette to the color.palette argument (which defaults to the built-in cm.colors palette), and R does the rest.
