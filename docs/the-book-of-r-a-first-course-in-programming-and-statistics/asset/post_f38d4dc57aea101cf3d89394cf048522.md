
```R
R> xyz <- expand.grid(vals,vals,vals)
R> nrow(xyz)
[1] 125000
```

Then you use dmvnorm to get the numeric value of the standard trivariate normal just as you do in the bivariate setting. The function automatically knows you're requesting the trivariate density because your data argument has three columns.

```R
w <- array(dmvnorm(xyz),c(50,50,50))
```

Note that the result is stored properly as a 50 × 50 × 50 3D array—refer to Section 3.4 for details on array. Look at the conceptual diagram of a 3D array (Figure 3-3 on page 53) and compare it to the 3D lattice on the right of Figure 26-10. The trivariate normal values are represented by a 3D block of numbers sitting at each evaluation coordinate in the defined 3D space.

An isosurface can be produced using the contour3 function, of the misc3d package (Feng and Tierney, 2008), which works closely with rgl. To use it, you need to decide on the level (or levels) at which to plot the surface. For contours; for more details, see the authoritative text on the α-level theory of trivariate densities by Scott (1992). In brief, for some density f, these delineate the (1 - α) × 100 percent “most dense” observations by setting the isosurface to be drawn at positions in the multivariate evaluation lattice that corresponds to the density value by α × max(f).

For the trivariate normal, the maximum value of the density is located at the coordinate (0,0,0).

```R
R max3d.norm <- dmvnorm(c(0,0,0),mean=c((0,0,0))
R max3d.norm
[1] 0.634964
```

You'll need this producing the next couple of plots. Install misc3d, load it with library("misc3d"), and then call contour3.

```R
R contour3(x=vals,y=vals,z=vals,f=0.05+max3d.norm)
```

This produces an isosurface in an RGL that can rotate and zoom as you desire; you can see the result on the left of Figure 26-11. You supply contour with the arguments x, y, and z as equally sequences in the x-, y-, and z-coordinates, respectively. You supply the 3D array, defining the entire result of the trivariate function to f, and pass the level (or levels) at which you want to draw the isosurface itself to level. Here, I've chosen the α-level to leave only 5 percent of the probability in the tails of the distribution, meaning that 95 percent of the total mass is held within the “blob”.

The plot matches what you might expect—the shape of the trivariate density is relatively clear based on the plot of the randomly generated data you produced. However, without scale, it's little more than a statistical golf ball. It's often more helpful to view the data alongside the density from which it came, which is also easy to do. The following code repeats the data in rand3d.norm using plot3 and contours3d to draw at the α level of 0.05.

```R
R> plot3(rand3d.norm,xlab="x",ylab="y",zlab="z")
R> contour3d(x=vals,y=vals,z=vals,f=w,level=0.05*max3d.norm,add=TRUE,alpha=0.5)
```

Just as with the R contour function, if you want contour3d to add to an existing rgl plot (as is the case here), you need to explicitly specify add=TRUE. You can also use the optional alpha argument to adjust opacity, reduced to 50 percent in this example, to “see inside” the density isosurface.

## Controlling Multiple Levels with Color and Opacity

Playing with color is especially useful when you want to plot the isosurface at multiple α levels at once. Color is also useful in this way, as a variable that can represent a fourth dimension without adding an additional axis to the graph.

To view the trivariate normal density at multiple levels, consider the plot produced by executing the following code:

```R
R> plot3(rand3d.norm,xlab="x",ylab="y",zlab="z")
R> contour3d(x=vals,y=vals,z=vals,f=w,
level=c(0.05,0.2,0.6,0.95)*max3d.norm,
color=c("pink", "green", "blue", "red"), alpha=(0.1,0.2,0.4,0.9),add=TRUE)
```

Figure 26-12 shows the result. Here, you replot the 500 randomly generated observations, and another call to contour3d now draws contours at four α-levels of the trivariate density—0.05, 0.2, 0.6, and 0.95. You use the optional color argument to render these in pink, green, blue, respectively, and progressively increase the opacity of each level with the alpha argument.

## 26.3.3 Example: Nonparametric Trivariate Density

For an extended example using real data, the quakes data frame includes the spatial location and depth of 1000 events. In Section 26.3, you constructed bivariate kernel estimates of the 2D longitude-latitude coordinates using the kde function. Our goal now, as noted there, is to calculate and visualize a density estimate of the same spatial data, but this time based on the trivariate coordinates of longitude, latitude, and depth in 3D space.

### Raw Data

First, let's look at the raw observations. The following code creates a copy of the quakes data, extracting three variables and rendering depth as negative. I do this so that, when plotted, depth moving down the vertical axis gives the impression of depth below sea level.

```R
R quake <- quakes[c("long","lat","depth")]
R quake$depth <- -quake$depth
```

In usual rgl fashion, you create a point cloud of the raw data with the following:

```R
R plot3d(x=quake$long,y=quake$lat,z=quake$depth,xlab="Longitude",ylab="Latitude",zlab="Depth")
```

If you spin the plot directly from the top with a bird's eye view, you will recognize the 2D spatial patterning you've plotted already; see, for example, Figure 13-1 (page 265), Figure 23-1 (page 578), or Figure 25-12 (page 662).

![](img/b2cfc85cbb129f60fe595a2bae074fe4_749_0.png)

Figure 26-13: Viewing the 3D dispersion of the earthquake occurrences—latitude, longitude, and depth.

### Calculating the 3D Estimate

The evaluation lattice for which the longitude-latitude-depth data reside exactly as illustrated in Section 26.3.2. Actually calculate the 3D KDE surface for the quake data, you'll use the impressive functionality of the ks package (Duong, 2007). Install the package and load it with a call to library("ks"). The kde function within the ks package allows you to use kernel smoothing to estimate the probability density of data.

The first argument you supply to kde is your data, in the form of a matrix or data frame; the order of the columns in your data object matters when using kde. When called as follows with quake, and taking into account the extraction of the three variables in the earlier code that created quake, the x, y, and z coordinate in the resulting 3D kernel estimate will correspond to longitude, latitude, and depth, respectively.

```R
R> dens3 <- kde(x=quake,gridsize=c(64,64,64),compute.cont=TRUE)
```

This matches the way the data are displayed in Figure 26-13. The gridsize specifies the lattice resolution in each axis. For example, I've settled on a 64 x 64 x 64 lattice; by default, kde chooses the range of evaluation in coordinate direction so that it's wider than the observed data. Finally, to plot the result, it's useful to specify the argument compute.cont=TRUE.

The returned object has several components. The 3D estimate is provided as an appropriately sized array as $estimate; if you want to check, execution of the following line confirms it matches the desired lattice resolution:

```R
R> dim(dens3$estimate)
```
[1] 64 64 64

The $eval.points component holds a list whose members are the specific evaluation coordinates, which are equally spaced sequences in each of the three axes. The number of members reflects the dimension of the problem, and their order corresponds to the specific axis. You can extract them with the following lines:

```R
R> x.latt <- dens3$eval.points[[1]]
R> y.latt <- dens3$eval.points[[2]]
R> z.latt <- dens3$eval.points[[3]]
```

If you print these vectors to your console screen, you'll see that each is a vector of length 64, with x.latt, y.latt, and z.latt corresponding to the variables matching the order of the columns in the data frame quake.
