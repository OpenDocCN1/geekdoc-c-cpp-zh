The result of these two lines is given on the bottom left of Figure 25-17. Unfortunately, the original density estimate is still defined in terms of the original x and y-ranges of the raw data, which gives you a border of empty pixels; in addition, the aforementioned density areas still fall outside the observation window.

All this emphasizes the important fact that a z-matrix is specific to a predefined evaluation grid. The only way to get your density estimate to span the geographical study region for the Chorley-Ribble data is to revise your kernel estimate that it's produced on an evaluation grid that spans the limits of the region. Fortunately, the kde2 function allows you to set optional x-limits of the evaluation grid with the lims argument. This expects a numeric vector of length 4, with the x-axis lower and upper values followed by the y-axis and upper values, in that. The following code reestimates the density using the study region limits and plots. The result is given on the bottom of Figure 25-17.

```
R> chor.dens(chor$x,chor$y,n=256,lims=c(WIN$xr,WIN$yr))
R> image(chor.dens.WIN$x,chor.dens.WIN$y,chor.dens.WIN$z,col=rbw)
R> plot(chor.WIN,add=TRUE)
```

With, you've solved the problem of ensuring your surface spans the desired area. However, this definitely highlights the second problem—the data that were actually observed strictly within the defined polygon, you can see plotted pixels outside the geographical region, which doesn't make sense. You can control precisely which pixels are plotted in any given image by setting the relevant entries in your z-matrix to be NA if you don't want them drawn.

You'll need a mechanism that can decide whether a cell enters inside or outside the polygon (the object chor.WIN). If it falls outside the polygon (object chor.WIN$z), you'll want to force it to be NA. In general, this type of decision making requires you to test each element of the matrix with respect to its coordinate value on the evaluation grid, possibly using your own R function. Frankly, in this case, the inside.win function of spatstat does exactly that, but the principle remains the same whenever you need to control over which pixels are plotted and which not.

One or more two-dimensional (x,y) coordinates and an object of class 'win', the inside.win function returns a logical vector with TRUE for those coordinates inside the defined region and a FALSE for any other coordinate. As a quick demonstration, observe the following

```
R> inside.win(x=c(355,345),y=c(420,415),w=chor.WIN)
[1] TRUE FALSE
```

This confirms what you can see from Figure 25—17—that the coordinate (355,420) lies well within the polygon and that coordinate (345,415) doesn't.
