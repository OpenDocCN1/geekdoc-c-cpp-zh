

## R > baz

```R
[,1] [2] [3]
[1,] 1 NA NA
[2,] 2 5 8
[3,] 6 NA Nan
```

对象 `foo` 是一个字符向量，缺少条目 2、3 和 6；`bar` 是一个长度为 11 的因子向量，缺少元素 2, 3, 7 和 10；`baz` 是一个数值矩阵，缺失第 1 行、第 2 和 3 列以及第 3 行的元素。在因子向量中，注意 NAs 显示为 `<NA>`。这是为了区分因子的真实值与缺失观测值，防止缺失值被误解释为某个水平（level）。

与其他特殊值一样，你可以使用 `is.na` 函数来识别 NA 元素。这对于删除或替换 NA 值非常有用。考虑以下数值向量：

```R
qux <- c(NA,5.89,Inf,NA,9.43,-2.35,NaN,2.10,-8.53,NA,-4.58,2.01,NaN)
qux
[1] NA 5.89 Inf NA 9.43 NaN 2.10 -8.53 NA -4.58
[13] 2.01 NaN
```

该向量总共有 14 个条目，包括 NA、NaN 和 Inf。

```R
is.na(x=qux)
[1] TRUE FALSE FALSE TRUE FALSE FALSE TRUE FALSE TRUE TRUE
[13] TRUE FALSE
```

如你所见，`is.na` 将 `qux` 中对应的 NA 条目标记为 `TRUE`。但并非全部——注意它也标记了元素 7 和 14，而这两个元素是 NaN 而不是 NA。严格来说，NA 和 NaN 是不同的实体，但在实践中它们是相同的，因为你对这两个值几乎都无法进行任何操作。`is.na` 将它们标记为 `TRUE`，允许用户同时进行删除或重新编码。

如果你想分别识别 NA 和 NaN 条目，可以使用 `is.nan` 结合逻辑运算符。这里有一个例子：

```R
which(x=is.nan(x=qux))
[1] 7 14
```

这识别出了元素特定为 NaN 的索引。如果你只想识别 NA 条目，请尝试以下操作：

```R
which(x=(is.na(x=qux))&is.nan(x=qux))
[1] 4 11
```

这只识别出 NA 条目（通过检查 `is.na` 为 `TRUE` 且 `is.nan` 不为 `TRUE` 的条目）。

在定位有问题的元素后，你可以使用方括号中的负索引来删除它们，尽管 R 提供了一个更直接的选项。`na.omit` 函数将接收一个结构并删除其中所有的 NA；如果元素是数值型的，`na.omit` 也适用于 NA。

```R
quux <- na.omit(object=qux)
quux
[1] 5 Inf 9.43 -2.35 2.10 -8.53 -7.58 -4.58 2.01
attr(,"na.action")
[1] 1 4 7 14
attr(,"class")
[1] omit
```

注意，传递 `na.omit` 的结构作为参数提供的，并且在打印返回的对象时会显示额外输出。这些额外信息是为了告知用户原始向量中的元素已被删除（在 `na.action` 中）。属性将在 6.2.1 节详细讨论。

与 NaN 类似，对 NA 进行算术计算会导致 NA。对 NaN 或 NA 使用关系运算符也会导致 NA。

```R
3+2.1*NA
[1] NA
3*c(1,2,NA,NaN,6)
[1] 3 6 NA NaN
```

你可以通过输入找到更多关于 NA 值用法和细微区别的细节。最后，查看空值，写作 `NULL`。这个值通常用于显式定义一个“空”实体，这与 `NA` 指定的“缺失”实体不同。`NULL` 实例表示一个存在的位置，可以被访问并在需要时覆盖——而不是针对 NULL 本身。如果你比较 NA 的赋值与 NULL 的赋值，就可以看到这一点。

```R
foo <- NULL
foo
NULL
bar <- NA
bar
[1] NA
```

注意，NA 对象 `bar` 带有索引 `[1]` 打印。这表明你有一个单元素的向量。相比之下，NULL 不提供索引，因为没有位置。这种对 `NULL` 的解释也适用于具有定义项的向量。考虑以下两行：

```R
c(2,4,NA,8)
[1] 2 4 NA 8
c(2,4,NULL,8)
[1] 2 4 8
```

第一行创建了一个长度为 4 的向量，第三个被编码为 NA。第二行使用 `NULL` 代替 NA 创建了类似的向量。结果是一个长度仅为 3 的向量。在向量（或其他结构）的多个位置分配 `NULL` 是合理的。再次，这里有一个例子：

```R
c(NA,NA,NA)
[1] NA NA NA
c(NULL,NULL,NULL)
NULL
```

第一行可以解释为三个可能的观测值。第二行仅提供了空性，这被解释为一个空对象。此时，你可能会想为什么甚至需要 `NULL`。如果某东西是空的，起初为什么要定义它呢？答案在于在 R 中调用函数。当一个函数包含可选参数时，函数内部必须检查哪些参数已被提供，哪些是的。`NULL` 值是函数作者用来方便此类检查的有用且灵活的工具。你将在第一章看到这些示例。`is.null` 函数用于检查某个内容是否显式为 `NULL`。假设你有一个带有名为 `opt_arg` 的可选参数的函数，如果提供，`opt_arg` 应该是一个长度为 3 的字符向量。

```R
opt_arg <- c("string1","string2","string3")
```

现在如果你使用 NA 检查是否提供了该参数，可能会调用：

```R
is.na(x=opt_arg)
[1] FALSE FALSE FALSE
```

NA 的位置特定性意味着这是逐元素的，并为 `opt_arg` 中的每个值返回一个答案。这出了问题，因为你只需要一个答案——它是空的还是被提供的？这时 `NULL` 派上用场了。

```R
is.null(x=opt_arg)
[1] FALSE
```

很显然 `opt_arg` 不是空的，函数可以继续。如果参数是空的，对于这些目的，使用 `NULL` 替代 `NA` 更好。

```R
opt_arg <- c(NA,NA,NA)
is.na(x=opt_arg)
[1] TRUE TRUE TRUE
```

```R
opt_arg <- c(NULL,NULL,NULL)
is.null(x=opt_arg)
[1] TRUE
```

如前所述，向向量填充 `NULL` 并不是通常做法；在这里只是为了说明。但 `NULL` 的用法远不止于此。它常用于 R 中现有的功能和用户贡献的功能。空 `NULL` 在参与算术或关系比较时会产生有趣的影响。

```R
NULL+53
numeric(0)
53<=NULL
logical(0)
```

结果并不是你预期的 `NULL`，而是由尝试的操作决定的“空”向量。`NULL` 通常主导任何算术，即使包含了其他特殊值。

```R
NaN/Inf
numeric(0)
```

`NULL` 也在检查列表和数据框时自然出现。例如，定义一个新列表 `foo`。

```R
foo <- list(member1=c(33,1,5,2,7),member2="NA or NULL?")
foo
$member1
[1] 33  1  5  2  7
$member2
[1] "NA or NULL?",
```

这个列表显然没有包含名为 `member3` 的成员。看看尝试通过该名称访问 `foo` 中的成员会发生什么：

```R
foo$member3
NULL
```

`NULL` 的结果表示 `foo` 中不存在名为 `member3` 的成员，或者在 R 的术语中为空。因此，它可以填充你想要的内容。

```R
foo$member3 <- NA
foo
$member1
[1] 33  1  5  2  7
$member2
[1] "NA or NULL?",
$member3
[1] NA
```
