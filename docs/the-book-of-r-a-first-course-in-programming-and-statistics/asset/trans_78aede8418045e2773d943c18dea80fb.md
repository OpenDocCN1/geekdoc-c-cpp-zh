
你可以看到这里 `oma=c(0, 0, 0)`——默认没有设置外边距。默认的图形边距空间为 `mar=c(5.1, 4.1, 4.1, 2.1)`——换句话说，底部有 5.1 行文本，左上方有 4.1 行，右侧有 2.1 行。

为了说明这些区域，请看图 23-4 左侧的图像，它是在一个新的图形设备中通过以下代码创建的：

```
R> plot(1:10)
R> box(which="figure", lty=2)
```

**图 23-4：** 展示了传统 [base] R 图形处理的图形设备区域；实线框显示绘图区域（plot region），虚线框显示图形区域（figure region），点线框显示外区域（outer region）。左侧：默认设置。右侧：通过 `par` 对外区域和图形边距区域的用户指定。

如果你使用 `box` 函数并并将可选参数 `which` 设置为 `"figure"`，它会向你显示图形区域（额外的 `lty=2` 参数会绘制出虚线）。

如果你在屏幕图形设备中查看此图，你应该会注意到虚线紧贴着窗口边缘。通过检查 `mar` 中的默认值，你可以发现相对来说，它们对应于绘图区域四侧的间距（由默认实线框给出）。最宽的图形边距（平行于绘图区域的底部）为 5.1 行；最窄的图形边距（平行于绘图区域的右侧）为 2.1 行。

### 23.2.2 自定义间距

让我们通过定制外边距来生成相同的图表，使得底部、左侧和右侧的区域分别为一、四、三和二行，而图形边距分别为四、五、六和七行。以下代码的结果如图 23-4 右侧所示。

```
R par(oma=c(1,4,3,2),mar=4:7)
R plot(1:10)
R box("figure",lty=2)
R box("outer",lty=3)
```

注意，不规则的边距在默认的正方形设备中压缩了绘图区域，以适应边缘定义的间距。如果你设置的图形参数将绘图区域压缩到不存在，R 将抛出错误，提示“图形边距过大”（figure margins too large）。

由于你通常需要保留边距空间以适应绘图的特定注释，让我们来看 `mtext` 函数，它专门用于在图形或外边距区域中写入文本。默认情况下，`outer` 为 `FALSE`，这意味着文本将写入图形区域中。设置 `outer=TRUE` 则将文本置于外区域。如果你保留了最近一次的绘图顺序，以下几行代码为图 23-4 所示区域提供了额外的边距注释：

```
R mtext("Figure margins/mar[ . ]",line=2)
R text("Outer region margins/noma[ . ]",line=0.5,outer=TRUE)
```

你将写入字符字符串的文本作为第一个参数，而 `line` 参数指示文本距离内边界多少行空间。`mtext` 中还有一个可选参数，用于决定文本出现的位置。它的默认值为 3，将文本设置在顶部，但你可以设置 `side=1` 将文本放置在底部，使用 `side=2` 将其设置在左侧，使用 `side=4` 将其设置在右侧。请查看 `?mtext` 获取更多用于边距文本的参数。

你可能还想研究现成的函数 `title`，它是 `mtext` 的专门实现，通常当主要关注是为图表的四个轴提供图形边距注释（超出指定 `main`、`xlab` 或 `ylab` 等基本功能）时使用。

### 23.2.3 裁剪（Clipping）

控制裁剪允许你根据图形自身的用户坐标在边距中绘制或向边距中添加元素。例如，你可能想将图例放在绘图区域之外，或者你可能想画一个超出绘图区域的箭头来装饰特定的观察结果。

图形参数 `xpd` 控制基础图形中的裁剪。默认情况下，`xpd` 为 `FALSE`，因此所有绘制内容仅限制在可用的绘图区域（`mtext` 等特殊的添加边距的函数除外）。将 `xpd` 设置为 `TRUE` 允许你在正式绘图区域之外绘制到图形边距内，但不会进入任何外区域。

将 `xpd` 设置为 `MA` 将允许在所有三个区域进行绘制——绘图区域、图形边距和外区域。

例如，看看图 23-5 中的图像，它显示了按气缸数量划分的箱线图，是通过以下代码创建的：

```
R dev(new)
par(oma=c(1,1,5,1),mar=c(2,4,5,4))
boxplot(mtcars$mpg,mtcars$cyl,xat="n",ylab="MPC")
box("figure",lty=2)
box("outer",lty=3)
arrows(x=c(2,2.5,3),y=c(44,37,27),x1=c(1.25,2.25,2.5),y1=c(31,22,20),xpd=FALSE)
```
（注：此处原文代码中 `dev(new)` 似为 `dev.new()` 的笔误，且 `arrows` 函数结尾未闭合括号，翻译保持原意逻辑）
