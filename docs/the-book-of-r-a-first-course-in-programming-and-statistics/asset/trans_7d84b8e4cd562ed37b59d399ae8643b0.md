

### 4.3.2 定义排序级别

上一节中的性别因子（sex factor）代表了最简单的因子变量——只有两个可能的水平，且没有顺序之分，其中一个水平在直觉上并不被认为“高于”或“后续”另一个水平。在这里，你将看到具有可以逻辑排序水平的因子；例如，出生月份（MOB），有 12 个具有自然顺序的水平。让我们之前观察到的 MOB 存储为字符向量。

```R
R mob <- c("Apr", "Jan", "Dec", "Sep", "Nov", "Jul", "Jun")
```

这个向量中的数据存在两个问题。首先，没有表示所有可能的类别，因为 `mob` 只包含七个唯一的月份。其次，这个向量没有反映月份的自然顺序。如果你比较 1 月和 12 月哪个更大，你会得到：

```R
R mob[2]
[1] "Jan"
R mob[3]
[1] "Dec"
R mob[2]<mob[3]
[1] FALSE
```

从字母顺序上来说，这个结果显然是正确的——J 的出现不在 D 之后。但在日历月份方面（这正是在我们感兴趣的），`FALSE` 结果是错误的。

如果你从这些值创建一个因子对象，可以通过向 `factor` 函数提供额外的参数来解决这两个问题。你可以通过向 `levels` 参数提供包含所有可能值的字符向量来定义额外的水平，然后通过将 `ordered` 参数设置为 `TRUE` 来指示 R 按照它们在 `levels` 中出现的顺序对值进行排序。

```R
R ms <- c("Jan", "Feb", "Mar", "Apr", "May", "Jun", "Jul", "Aug", "Sep", "Oct", "Nov", "Dec")
R mob.fac <- factor(x=mob,levels=ms,ordered=TRUE)
R mob.fac
[1] Apr Jan Dec Sep Nov Jul
Levels: Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < Oct < Dec
```

在这里，`mob.fac` 包含了与之前的 `mob` 向量索引位置相同的个体条目。注意该变量有 12 个水平，尽管你没有对“Feb”、“Mar”、“Oct”这些水平进行任何观测（注意，如果你的控制台窗口太窄，无法在屏幕上打印所有水平，你可能会看到 ...，表示某些输出被隐藏了。只需放大窗口并重新打印对象即可查看隐藏的水平）。此外，这些水平的严格顺序通过对象输出中的 `<` 符号显示。使用这个新因子对象，你可以执行之前的关系比较并得到你可能预期的结果。

```R
R mob.fac[2]
[1] Jan
Levels: Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < Oct < Nov < Dec
R> mob.fac[3]
[1] Dec
Levels: Jan < Feb < Mar < Apr < May < Jun < Jul < Aug < Sep < Oct < Nov < Dec
R> mob.fac[2]<mob.fac[3]
[1] TRUE
```

这些改进不仅仅是外观上的。这存在巨大的差异，例如，在某些类别中观测值为零的数据集，与从一开始就定义了较少类的相同数据集是不同的。是否指示 R 对因子进行正式排序，在各种统计方法（如回归和其他类型的建模）的实现中也可能产生重要影响。

### 4.3.3 合并与切割

正如你所看到的，通常使用 `c` 函数合并相同类型的多个向量（无论是数值、逻辑还是字符）是简单的。这里有一个示例：

```R
R foo <- c(5.1,3.3,3.1,4)
R bar <- c(4.5,1.2)
R c <- c(foo,bar)
[1] 5.1 3.3 3.1 4.5 1.2
```
