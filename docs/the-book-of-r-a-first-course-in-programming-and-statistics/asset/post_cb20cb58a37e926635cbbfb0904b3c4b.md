## READING AND WRITING FILES

Now I'll cover one fundamental aspect of working with R: loading and saving data in an active workspace by reading and writing files. Typically to work with a large dataset, you'll need to read the data from an external file, whether it's stored as plain text, in a spreadsheet, or on a website. R provides functions you can use to import these data, usually as a data frame object. You can also export data frames by writing to a new file, plus you can save any plots you create as image files. In this chapter, I'll go over some useful read- and write operations for importing and exporting data.

## 8.2 Reading External Data Files

R has a variety of functions for reading files and making sense of them. You'll look at how to read table-format files, which are among the easiest for R to read and import.

### 8.2.1 The Table Format

Table-format files are thought of as plain-text files with three key features that define how R reads the data:

- Header: If a header is present, it's always the first line of the file. This optional feature is used to provide names for each column. When importing a file into R, you need to tell the software whether a header is present so it knows to treat the first line as variable names.
- Delimiter: The all-important delimiter is a character used to separate the entries in each file. The delimiter cannot be used for anything else and tells R when a specific entry begins and ends.
- Missing value: This is another unique string used exclusively to denote a missing value. When reading the file, R will turn these entries into the format it recognizes: NA.

Typically, these files have a .txt extension or .csv (for comma-separated values). Figure 8-2 shows an appropriate table-format file called datafile.txt, which has that data frame with few values marked as missing. This data can be found on the book's website at https://www.nostarch.com/book/, or you can create it yourself from Figure 8-2 using a text editor.

![](img/b2cfc85cbb129f60fe95a2bae074fe183_0.png)

Figure 8-2: A plain-text table-format file

Note that the first line is the header, the values are delimited with a single space, and missing values are denoted with an asterisk (*). Also, each new record is required to start on a new line. Suppose you've handed this plain-text file for data analysis in R. The ready-to-use command read.table imports table-format files, producing a data frame object, as follows:

```
R mydatafile <- read.table(file="/Users/tdavies/mydatafile.txt", header=TRUE,sep=" ",na.strings="*", stringsAsFactors=FALSE)

R mydatafile
person age sex
1 Peter NA M High 504
2 Lois 40 F NA 480
3 Meg 17 F Low 204
4 Chris 14 M Med 168
5 Stevie 1 M High NA
6 Brian NA M Med NA
```

In a call to read.table, file takes a string with the filename and folder location (using forward slashes), header is a logical value telling R whether file has a header (TRUE in this case), sep takes a character string representing the delimiter (a single space, " "), na.strings requests the characters used to denote missing values ("*" in this case).

If you are reading multiple files and don't want to type the entire folder location each time, it's possible to first set your working directory using setwd (Section 1.2.3) and then simply use the filename and its extension as the character string supplied to the file argument. However, both approaches require you to know exactly where your file is located when you're working at the R prompt. Frankly, R possesses useful tools that should forget your file's precise location.
