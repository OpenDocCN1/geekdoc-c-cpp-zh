The col argument needs to specify the (m – 1) × (n – 1) facet colors (assuming an m × n z-matrix passed to z). The typical way to find this in R if you are intending to color the facets according to the z-value is to calculate each facet's z-value, which will be the average of the four adjacent z-matrix entries. Only then can you deploy one of the color assignment approaches from Section 25.1.4.

Let's recreate the pixel image of the Chorley-Ribble kernel density estimate (Example 4: Figure 25-18), complete with z-axis-specific coloring, as a perspective plot. First, make sure you have the packages spat and MASS already loaded. Then repeat the code from earlier to obtain the kernel grid, truncated to the geographical region.

```R
R> col.WIN <- chorley$window
R> dens.WIN <- kded(chorley,n=256, lim=c(chorley$x,chorley$y))
R> cor.xy <- expand.grid(dens.WIN$x,dens.WIN$y)
R> out.mat <- matrix(NA, x=cor.xy[,1],y=cor.xy[,2], w=256,256)
R> dens.WIN$z[out.mat] <- NA
```

Next, you need to calculate all the zf values; this can be done en masse with the following code:

```R
R> zm <- dens.WIN$z
R> nr <- nrow(zm)
R> nc <- ncol(zm)
R> zf <- (zm[-1,-1]+zm[-1,nc]+zm[-nr,-1]+zm[-nr,nc])/4
R> dim <- dim(zf)
[1] 255 255
```

The three lines simply store the z-matrix as the object zm and its rows and columns (both 256 in this case) as nr and nc, respectively. The fourth line is the relevant calculations, giving a matrix of zf values. It does this systematically by element-wise summation of four versions of the original[-1,-1] (first row, first column), zm[-1,nc] (first row, last column), and zm[-nr,-nc] (last row, last column). When the four are summed this is divided by 4 at the end, the result is a matrix zf, each element of which is the four-point average of four adjacent entries in the original-matrix. The final call to dim zf confirms the size of the result. Since there are a total of 256 × 256 lines in the defined z-matrix, these encapsulate a total of 255 facets.

The hard work is done, and all you need to do now is assign the colors from your palette to the calculated facet values. You can do this using either the categorization or normalization approach noted in Section 25.4; for simplicity, let's stick to categorization. Consider the following code:

```R
R> rainbow <- rainbow(200,start=0,end=5/6)
R> zf.breaks <- seq(min(zf,na.rm=TRUE),max(zf,na.rm=TRUE),length=201)
R> zf.colors <- cut(zf,breaks=zf.breaks,include.lowest=TRUE)
```

The first line is repeated from Section 25.2 to generate the same 200 colors from the built-in palette used in the pixel images. The second line sets up an evenly spaced sequence spanning the range of the calculated z values to form the category break points required by the categorization approach. Note the use of na.rm=TRUE in the calls to min and max to avoid all the NA entries in zf (remember, the surface has been truncated to the irregular polygon representing the geographical region). The sequence is one longer than the generated colors—again, refer to Section 25.1.4 for this necessary feature of the categorization approach. Lastly, assign each of the zf facet value entries an appropriate rank with respect to 200 ordered bins. As you learned, the zf.colors ranks are subsequently used to index the vector of 200 colors stored in with plotting.

With that, you can enjoy the fruits of your labor! ## 25.6.3 Rotating with Loops

There's one last bit of fun you can have with perspective plots if you want to get an overall impression of the rotating surface. Using a simple for loop (Section 10.2.1) to increment theta or phi, you can perform an animation—essentially a cartoon—of all sides. Consider the following basic function in the editor:

```R
prosp <- function(skip=1,...){
  for(i in seq(90,360,by=skip)){
    persp(phi=i,theta=0,...)
  }
  for(i in seq(0,360,by=skip)){
    persp(phi=20,theta=i,...)
  }
}
```

Using an ellipsis (see Section 11.2.4), prosprot simply takes all the arguments you usually supply to a call to persp, barring theta and phi. Then comes a for loop alters the vertical viewing angle, starting with phi=90 (birds-eye view) and moving down to a mildly elevated phi=20. A second loop then completes a full 360-degree horizontal rotation.

The only formally tagged argument is skip, which determines the amount phi and theta increment by each iteration. Increasing skip will reduce the time it takes to complete the rotation, though it makes for a more jagged animation.

Depending on the type of graphics devices you're using, you may want to experiment with skip. Note that not all graphics devices are well suited to the animation effect by this rough function (for example, it's not appropriate if you're using RStudio—see Appendix B). That said, when running the base GUI applications on OS X or Windows, I find persp works well under default graphics settings.
