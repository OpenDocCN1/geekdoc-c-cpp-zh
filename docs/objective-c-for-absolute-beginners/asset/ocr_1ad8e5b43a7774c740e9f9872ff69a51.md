# Using Getter and Setter Methods

Here is the Book's object header (.h) file, which contains the Book's interface definition.

**Listing 8–12.** Defining a getter and setter for the Book object.

```
#import <Foundation/Foundation.h>

@interface NSObject {
    NSString *title;
    NSString *author;
    NSString *description;
}

(NSString)*title;
(void)setTitle:(NSString *)newString;

@end
```

The two methods defined on lines 9 and 10 are the getter and setter methods, respectively. Conventionally, the getter method is named the same as the instance variable. In order we are fetching the title of a book object so our getter method is simply title. It is defined to return an NSString object to the caller.

The setter object is named by convention to setVariableName. For our example, the setter method is named setTitle. Notice that the instance variable's first character uses an uppercase letter; this is also part of the standard convention.

> NOTE: A naming convention called camel case (or CamelCase) uses an uppercase letter to distinguish words in a method, variable, or class name. The text is suggestive of a camel, since the uppercase letters tend to focus forms. It makes the label easier to read. For example, stringWithContentsOfURL is much easier to read than stringWithcontentsofURL.

Now, the word "convention" has been mentioned several times. Objective-C does not require that a method named anything specific. Since most applications follow the guidelines we discussed, the becomes becomes de facto standard. Knowing this becomes very important when the topic of properties is discussed later. For now, however, we are going to manually write a getter and a setter method so that they can be better understood.

First, the getter—this is the simplest of the methods to implement:

+   - (NSString)*title
{
    return title;
}

In the preceding example, the method simply returns the instance variable called title. To access the method, the syntax [object title] is used.
