# Working with Implied Retain Messages and Autorelease

How do we know which objects need to be released and which don't? The answer basically falls under the rule of object ownership. If an object is created that has alloc, copy, or new you own the object, and it, therefore, needs to be released once the program is finished it. There are other examples, but no hard and fast rules unfortunately. Deallocating memory takes an understanding of the objects and what messages result in an explicit retain.

While an object can be sent an explicit retain message, in the examples so far, there isn't one case where there are automatic or implied retain messages. For example, whenever the message setObject:forKey: is sent to the dictionary object, the object we add is automatically sent a retain message. As mentioned previously, whenever we are allocating a retain is implied:

```
NSMutableDictionary *dict = [[NSMutableDictionary alloc] init];
```

Other calls are not so obvious, as seen in the following example:

```
NSDate* today = [NSDate date];
```

In the case above, the object has allocated but has in implied release—called autorelease. As mentioned above, anything with an alloc, copy, new requires that the program manually releases the object. For anything else, the object is released automatically.

The key is that the return value is a new date object. Because it's a new object, it receives a sort of implied retain message. But more importantly, it will automatically released since the object wasn't created with an alloc/copy/new method. The program could just have been written as follows:

```
NSDate* today = [[NSDate alloc] init] autorelease];
```

This code would yield the exact same results. The difference is that, in the second example, we are explicitly allocating the memory marking it as autorelease. The Objective-C run-time system will automatically release the memory. While autorelease seems like the best way to handle releasing memory, it may not be what is needed. Variables that are marked autoreleased don't stick around very. iOS and some Mac applications have a run-loop. Basically, an application for the most part just waits for input. If you touch the screen, the application will perform some function and then eventually go back to waiting for input. When the application goes back to wait for more input, all autorelease variables are released; this could easily be as short as 1/60th of a second. So, autorelease should be used with caution and only in an area where the need for a variable is within the span of the current run-loop. If the program needs to have an autorelease variable stick around for a while, then either don't use autorelease (use the standard alloc and init) or simply send a retain message to the object.
