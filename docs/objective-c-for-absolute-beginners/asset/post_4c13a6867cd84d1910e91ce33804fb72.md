## NSDictionary

The NSDictionary class is also a very useful type of collection class. It allows the storage of objects, just like the NSSet and NSArray, but the NSDictionary is different in that it allows a key to be associated with the entry. For example, NSDictionary could be created that stores a list of Animal objects. Instead of accessing the Animal objects by an index like an NSArray, the NSDictionary could use an NSString like "monkey".

However, all keys must be unique—that is, "monkey" cannot exist more than once. Depending on your program, finding unique names is not normally a problem.

Using the "monkey" example—if there are 5 monkeys, the NSDictionary would contain one entry for "monkey". However, that entry could be in another NSDictionary that contains five unique monkey names:

"monkey" -> NSDictionary object

The NSDictionary object contains:

- "Spider" -> Animal Object
- "Capuchin" -> Animal Object
- "Tamarin" -> Animal Object
- "Mandril" -> Animal Object
- "Orangutan" -> Animal Object

Of course, an NSDictionary could be organized in many different ways, depending on how the keys are defined. In most cases, there aren't NSDictionary entries of Dictionaries—the example was just provided to show how flexible the NSDictionary, or collections in general, can be.

Let's see how the example would look in code. For example, assume that a list of Animal objects already another another NSDictionary and we're just assigning it to the dictionary:

## Determining Class Type in a Collection

When iterating through a collection, we generally use the id class type to indicate that we't know what class is in the collection. Each Objective-C object has two nifty methods to help us use. Let's take a look at them now.

Using the code in Listing 8–3 as an example, consider the following code fragment:

### Listing 8-6. Handling different classes within a collection.

```
11 for (id element in [zoo allValues]) {
12 if ([element isKindOfClass:[Animal class]]) {
13 NSLog("@%@", element); }
14 }
15 if ([element isKindOfClass:[NSDictionary class]]) {
16   ... // Process the monkey edition.
17 }
```

In Listing 8-6, we use enumeration to go through your NSDictionary. Since there are only two possibilities: the Animal class or an NSDictionary of animals, the code needs to check for two different class types. As previously mentioned, Objective-C object has two handy methods.

- The first is the kindOfClass: method. This method returns a Boolean value if the current class, our element variable, is a type of class.
- The second handy method is the class method. This method simply returns the class of the object; line #12 is the Animal class. Line #15 is the NSDictionary class.

Using a combination of the kindOfClass: and the class methods makes it fairly simple to process different types of classes within a collection.

## Using the Mutable Classes

Up to this point, we've only discussed collection objects that are initialized once and can never change. While there are definitely places this is useful, what's even more useful is a collection class that can be modified. Each of the collection classes has a mutable version—we've only talked about the non-mutable classes. The classes are fundamentally the same except that elements can be added and removed from the mutable versions.

## NSMutableSet

This can be initialized as the NSSet or can be initialized without any values and then values added. Consider the code in Listing 8-7:

**Listing 8-7. Adding objects to an NSMutableSet.**

```
1 NSMutableSet *mySet = [[NSMutableSet alloc] init];
2
3 [mySet addObject:@"One"];
4 [mySet addObject:@"Two"];
5 [mySet addObject:@"Three"];
6
7   for (id val in mySet) {
8     NSLog("%%s@", val);
9   }
```

The nice thing about any of the mutable classes is that elements can be added and removed instead of having to declare the class with all the values at once. All objects in a set can be removed with the following line:

```
[mySet removeAllObjects];
```

A specific object can also be removed as long as we have a reference to that object:

**Listing 8–8. Removing a specific object in an NSMutableSet.**

```
NSString *testString = "Zero";
[mySet removeObject:testString];

for (id val in mySet) {
  NSLog("%@", val);
}
```

## NSMutableArray

As the NSMutableSet, the NSMutableArray is similar to its parent, the NSArray. However, the NSMutableArray can add elements. Take a look at Listing 8–9.

**Listing 8–9. Adding and inserting values into NSMutableArray.**

```
NSMutableArray *myArray = [[NSMutableArray alloc] init];
[myArray addObject:@"One"];
[myArray addObject:@"Two"];
[myArray addObject:@"Three"];

for (id val in myArray) {
  NSLog("%@", val);
}

[myArray insertObject:@"One and Half" atIndex:1];

for (id val in myArray) {
  NSLog("%@", val);
}
```

In Listing 8–9 a new array is created similarly to the NSMutableSet. However, on line #11 new element is being inserted into the array at position 1. Remember, position 0 is the first element. The contents of the array would look like:

| Index | Value |
|---|---|
| 0 | One |
| 1 | One and Half |
| 2 | Two |
| 3 | Three |

Line #11 inserted a new element–the remaining elements were moved up in the array.

With the NSMutableArray, there are several ways to remove an object. Following are a few of the more commonly used methods:

- removeAllObjects – This method does as advertised. It removes all objects from a given NSMutableArray.
- removeLastObject – This method removes the last object at the end of the array. The array size is reduced by one.
- removeObjectAtIndex(index) – This methods removes an object at a given index. The value is from 0 to length of the array–1.
