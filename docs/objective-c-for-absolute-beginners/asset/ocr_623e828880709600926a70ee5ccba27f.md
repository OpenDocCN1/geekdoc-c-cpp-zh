# Listing 13–8. A Retain Count.

```
1 NSMutableDictionary *dict = [[NSMutableDictionary alloc] init]; dict retainCount = 1
2 NSObject *today = [[NSDate alloc] init];      today retainCount = 1
3 [dict setObject:today forKey:@"TODAY"];
4                                              retainCount = 2
5 [dict release];                                 retainCount = 1
6 today = nil;
7 [dict removeObjectForKey:@"TODAY"];      today deallocated
8 [dict release];                             dict deallocated
```

Looking at Listing 13-8, the retain counts of the dict and today objects are shown. The dict object has a retain count of 1 whenever the object is created. The same is true for the today object on line 2.

In line 4, things looks a little odd. For some reason, the retain count is 2. What happened? Well, if we look closely at the NSMutableDictionary documentation for the setObject:forKey: method, we see, in the documentation for the setObject: part of the message that "the object receives a retain message before being added to the receiver."

According to the documentation, before an object is added to the dictionary, the object is sent a retain message. This is why the dictionary has a retain count of 2.

Why does the dictionary do this? The answer is quite simple. If we add an object to the dictionary, the dictionary should be responsible for it; we basically hand it over to that class. We can release any local variables to objects we add to the dictionary. To ensure this, the dictionary becomes the owner of the objects. NSMutableDictionary class sends all the data it stores a retain message so that the system knows someone is using that object.

Since dict is managing the object, line 5 is used to release our object. The dictionary still has the same message that the today object has: we've just told the system that we're finished with it. Had the dictionary not sent a retain message, line 5 would have actually deallocated the memory by way of a release. The rule is plenty simple: Once the retain count of an object reaches zero, the object is sent a dealloc message, and the memory to that object is actually deallocated.

Line 7 removes the object by way of the key TODAY. When an object is removed from a dictionary, the object is automatically sent a release message. At this point, the today that used to point to it is sent a release message. Since this now makes the retain count of the object zero, the object is also sent a dealloc message to deallocate its memory.

Line 8 sends a release message to the dict object. This will deallocate the memory of the object, since nowhere else is the object retained.
