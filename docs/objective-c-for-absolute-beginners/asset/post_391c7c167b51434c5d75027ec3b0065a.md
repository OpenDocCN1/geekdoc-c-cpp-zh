# Introducing Instance Variables

Our object is simply called Book and is a subclass of NSObject. True, we have an object, but it doesn't store anything at this point. In order for this class to be useful, it needs to be able to hold some information, which done with instance variables. When an object is used, it has to be instantiated. Once the object is instantiated, it has access to its instance variables. These variables are available to the object as long as the object stays in scope. We know from Chapter 7, scope defines the context in which an object exists. In some cases, an object's scope might be the life of the program. In other cases, the scope might be just a function or method. It all depends on where the object is declared and how it will be used. For more later, let's add some instance variables to our Book class to make it more useful.

# Accessing Instance Variables

Now that we have some instance variables, how can we use them? How are they accessed? As you learned in previous chapters, Objective-C objects respond to messages. Unfortunately, simply declaring an instance variable doesn't give you access to it. There are two ways to access these variables.

- One way is, of course, within our Book object.
- The second way is outside of the object—that is, another part of the program that uses the Book object.

If we are writing the code for a method within our Book object, accessing an instance variable is quite simple. For example, you could simply write the following:
title = @"Test";

The preceding line is written within the Book class. Outside of it, the instance variable is not visible at all. To accomplish this, you need to create two types of methods: a getter and a setter.

- getter is a method that returns the value of something in the object, typically an instance variable like the author.
- A setter is a method that updates instance variable.

Let's take a look at the traditional getter and setter methods that were common before the introduction of Objective-C 2.0.

> TIP: Sometimes instance variables are referred to as ivars. Ivar is just the short form of instance variable.

# Using Getter and Setter Methods

Here is the Book's object header (.h) file, which contains the Book's interface.

**Listing 8–12. Defining a getter and setter for the Book object.**

```objc
#import <Foundation/Foundation.h>

@interface NSObject {
    NSString *title;
    NSString *author;
    NSString *description;
}

(NSString)*title;
(void)setTitle:(NSString *)newString;

@end
```

The two methods defined on lines 9 and 10 are the getter and setter methods, respectively. Conventionally, the getter method is named the same as the instance variable. In order we are fetching the title of a book object so our getter method is simply title. It is defined to return an NSString object to the caller.

The setter object is named by convention to set. For our example, the setter method is named setTitle. Notice that the instance variable's first character uses an uppercase letter; this is also part of the standard convention.

> NOTE: A naming convention called camel case (or CamelCase) uses an uppercase letter to distinguish words in a method, variable, or class name. The text is suggestive of a camel, since the uppercase letters tend to focus forms. It makes the label easier to read. For example, stringWithContentsOfURL is much easier to read than stringWithcontentsofURL.

Now, the word "convention" has been mentioned several times. Objective-C does not require that a method named anything specific. Since most applications follow the guidelines we discussed, the becomes de facto standard. Knowing this becomes very important when the topic of properties is discussed later. For now, however, we are going to manually write a getter and setter method so that they can be better understood.

First, the getter—this is the simplest of the methods to implement:

```objc
(NSString)*title
{
    return title;
}
```

In the preceding example, the method simply returns the instance variable called title. To access the method, the syntax [object title] is used.
