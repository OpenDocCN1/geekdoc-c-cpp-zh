Class methods have limitations. One of their biggest limitations is that none of the instance variables can be used. Well, technically, Xcode allows instance variables to be coded in a class method. The code will compile with a warning, but accessing or using the instance variable sense does nothing—just don't do it. Being unable to use instance variables makes sense since we haven't instantiated. A class method can have its own local variables within the method itself, but can't use any of the variables defined as instance variables.

A call to a class method would look like this:

```
[RadioStation minFrequency];
```

Notice that the call is very similar to how a message is passed to an instantiated object. The big difference is that instead of an instance variable, the class name is used. Class methods are used extensively in the Mac OS and iOS frameworks. They are mostly used for returning some fixed or well-known type of value, or to return a new instance of object. These types of classes are sometimes referred to as factory methods, like factories, they create something new; in this case, a new instance of a class. Here's a factory method example:

+   1. [NSDate intervalSinceDate]; // Returns a number
2. [NSString stringWithFormat:@%d", 1000]; // Returns a new NSString object
3. [NSDictionary alloc]; // Returns a new uninitialized NSDictionaryObject.

All of the preceding values that class methods are called.

Line 1 returns a value that represents the number of seconds since January 1, 2001, which is the reference date.

Line 2 returns a new NSString object that has been formatted and has a value of 1000.

Line 3 is a form that is very commonly used because it allocates a new object. Typically, the line is not used by itself, but in a line, like:

```
myDict = [NSDictionary alloc init];
```

The preceding call is a compound method. The [NSDictionary alloc] class method returns a new NSDictionary Object. The init message is sent to the NSDictionary, which is used within a class to initialize it (e.g., setting up instance variables). The function returns the new object back to the caller.

So when would you use a class method? As a general rule, if the method returns information that is NOT specific to any particular instance of the class, make the a class method. For example, the minFrequency in the preceding example would be the same for ALL instances of RadioStation object—this is a great candidate for a class method. However, the station's name or its assigned frequency would be different for each instance of the class. This should not (and indeed could not) be methods. The reason for this is that class methods cannot use any of the instance variables defined by the class.
