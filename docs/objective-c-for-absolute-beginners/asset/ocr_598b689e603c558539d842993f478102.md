Dealing with the retain/release model will take some time to get to used but overall is a fairly straightforward system of managing memory. Here's a word of caution though: even though our examples talked about the retainCount method of an object, do not rely on this value. Since you have no idea what parts of the framework have an interest in your objects, the retain count could be higher than you expect. However, knowing about the retainCount is beneficial in troubleshooting a potential memory leak. Continue to practice working with the retain/release model, and make sure that you read the developer documentation when sending or receiving objects so that you know how the object in question is being handled.

# If Things Go Wrong

Allocating memory through the standard C mechanisms or the Objective-C allocation methods works most of the time. However, the programmer cannot assume that allocating an object or allocating memory works all time. When memory allocation fails, it's generally a sign that bigger problems are at hand, and the program may not be too much longer (it will crash because of memory issues).
