# ## Range adaptors in C++20

| View | Description |
| --- | --- |
| `std::ranges::lazy_split_view`<br>`std::views::lazy_split` | Splits a view by using a delimiter. |
| `std::views::counted` | Creates a view from a begin iterator and a count. |
| `std::ranges::common_view`<br>`std::views::common` | Converts a view into a `std::ranges::common_range`. |
| `std::ranges::reverse_view`<br>`std::views::reverse` | Iterates in reverse order. |
| `std::ranges::elements_view`<br>`std::views::elements` | Creates a view on the n-th element of tuples. |
| `std::ranges::keys_view`<br>`std::views::keys` | Creates a view on the first element of pair-like values. |
| `std::ranges::values_view`<br>`std::views::values` | Creates a view on the second element of pair-like values. |

Strictly speaking, the functions in the namespace `std::views` like `std::views::values` are range adaptors, and the types in the namespace `std::ranges` like `std::ranges::values_view` are views. A range adaptor range | `std::views::values` operates on a range and returns a view but a view gets a range as argument: `std::ranges::values_view{range}`.

`std::ranges_view` stores a reference to the underlying range. It is a borrowed range and can refer to the underlying range as long as it is valid. Reallocation of the underlying range does not invalidate the `std::ranges_view`.

`std::ranges::owning_view` takes ownership of the elements of another range. It can only be constructed from an rvalue and cannot be copied.

`std::owning_view`

```
~~~cpp
1 std::vector<int> vec{1, 2, 3, 4, 5};
2
3 std::ranges::owning_view vec2{vec};       // ERROR
4 std::ranges::owning_view vec3{std::move(vec)}; // OK
5
6 std::ranges::owning_view vec4{vec2};      // ERROR
7 std::ranges::owning_view vec5{std::move(v2)}; // OK
~~~
```
