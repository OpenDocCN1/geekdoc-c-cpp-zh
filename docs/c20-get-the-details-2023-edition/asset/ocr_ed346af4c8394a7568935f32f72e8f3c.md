# Optimized == and != Operators

There is an optimization potential for string-like or vector-like types. In this case, a == and != may be faster than the compiler-generated comparison operator. The == and != operators can stop if the two values compared have different lengths. Otherwise, if one value were a prefix of the other, lexicographical comparison would compare all elements until the end of the shorter value. Consequently, the compiler-generated == and != operators compare, in the case of a string-like or a vector-like type, first their lengths and then their content if necessary. The standardization committee was aware of this performance issue and fixed it with the paper [P1185R2](http://www.open-std.org/jtc1/sc22/wg21/docs/papers/2019/p1185r2.html).
