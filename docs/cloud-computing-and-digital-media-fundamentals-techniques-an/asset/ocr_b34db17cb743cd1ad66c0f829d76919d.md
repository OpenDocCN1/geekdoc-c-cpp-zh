**DEFINITION 12:** An execution graph P is a directed graph with form P(V,E) = |v| is an MRJ, E = |e| = {MRJ_i, MRJ_j}, MRJ_j, MRJ_i ∈ V}.

Given we say MRJ depends on MRJ, and only if MRJ_j's output is a direct input of MRJ. A directed edge is added from MRJ to MRJ, in P to specify the execution order. On the contrary, two MRJs are considered independent if they do not connect to the same edge in P. According to P, independent MRJs can be executed in parallel as long as their direct inputs are ready. MRJ that has a predecessor(s) must wait until its predecessor(s) are finished.

We summarize the general framework of our solution. We map a SPARQL query to MRJs, each of which is either a Join or an Mjoin, and execute the MRJs according to the corresponding P. Since there could be many P generated to different selections of Join over G, we want to find such a P that guarantees a minimum query processing time. Formally, we define the problem as follows:

**Problem definition:** Given a platform configuration Δ, RDF data statistics S, and a query pattern G obtained from a SPARQL query Q, find a function F:(Δ,S,G) → P(V,E) such that

+   1. MRJ's execution time be t_i. Let (i,j) denote a path from MRJ to MRJ, in P, and the weight of this path be W_{i,j} = \sum_{k∈i,j} t_k.
2. The Max{W_{i,j}} is minimized.

In the problem definition, W_{i,j} indicates the possible minimal execution time from MRJ to MRJ_j. Therefore, by minimizing the maximum W_{i,j}, the overall minimum execution time of P is achieved.
