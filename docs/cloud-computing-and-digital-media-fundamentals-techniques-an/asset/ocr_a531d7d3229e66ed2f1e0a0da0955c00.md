To model a set of operators with shared computation, RUMOR proposes an abstraction called physical multiuser (m-op). The state of m-op is a vector conceptually, which mainly executes all its operators from input stream and writes the output produced by the relevant operators to the corresponding output streams. Meanwhile, transformation on m-ops can be extended as multiple query transformation rules or m-rules for short, which consist of a pair of condition and action functions. The condition of an m-rule is a Boolean side effect-free function from the power set of all possible m-ops to true and false set. The action of an m-rule maps a set of m-ops to a single m-op, which is referred to as the target m-op. Therefore, a query plan is composed of m-ops, and the representative m-rules can be used to express the existing and new MQO techniques. Considering the sharing in the case where “similar” streams are processed by identical operators, RUMOR also defines channels to them, which have compatible schemas. A channel is defined as the union of its streams, and each stream has an additional attribute called membership component to label the source with a bit vector. When identical tuples from different streams are encoded as a single channel, their space can be shared. When multiple streams are encoded into the same channel, the computation of operators can be shared. For example, considering a case that an m-op $p_{(i...j)}$ implements $n$ projections on different input streams $(S_{i...})$, input streams are encoded by channel C, and $n$ output streams are encoded by channel D. Then $p_{(i...j)}$ can perform projection only once channel $t$ from $C$ and produce only one output channel tuple in $D$, keeping the membership component of $t$ intact in the output $D$ tuple. RUMOR builds the similar query plans encoded by channels, and proposes a heuristic algorithm based on a set of criteria.
