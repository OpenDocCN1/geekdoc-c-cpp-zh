PN search is a kind of best-first algorithm that was successfully used to prove or solve the theoretical values of game positions for many games [9,10], as Connect Four, Gomoku, Renju, Checkers, Lines of Action, Go, and Shogi. PN search is based on an AND/OR search tree, where each node is associated with PN/disproof number that indicates the minimum number of node expansions (or evaluations) to prove/disprove the node. During each round, the search chooses one node, named the most proving node (MPN), expands it, and then reevaluates the PN/disproof number of the node and its ancestors. An important property about MPN is as follows: If the MPN is proved/disproved, the PN/disproof number of root decreases by one. Thus, if the root is to proved/disproved, the PN search will use the MPNs to lead to proving/disproving the root.

The most best-first PN search has a well-known disadvantage: the requirement of maintaining the whole search tree in the memory. Therefore, many variations [9,10] were proposed to solve this problem, as two-level PNS (PN^2), Depth-First-Number Search (Df-PN, Proof-Number* (PN*), and Proof-number and Disproof-Number Search (PDS). With the JL-PN search, it becomes possible to maintain the JL-PN search tree inside the client memory without much problem according to our experiences for Connect6.

In JL-PN search for Connect6 (described in more detail in Reference 9), NCTU is used to expand OR nodes (or generate nodes from OR nodes), whereas Verifier is used to expand AND nodes. In our experiences, the search tree usually contains no more than 1 million nodes, which can fit process (client) memory. Assume that it takes 1 minute (60 seconds) to run NCTU6. A volunteering system with 60 processors takes about 11 days to build a tree up to 1 million nodes. In such cases, we can manually split one JL-PN search into two.

For the former, prompt interaction, the users want to read the returning messages such as the best moves and all possible defensive moves promptly. As for the latter, highly dynamic job scheduling, in case that some node is proved, all the subtree nodes should be aborted immediately.
