## 2.3.1.2 Queuing Model

The proposed queuing model is shown in Figure 2.2. The model consists of three concatenated queuing systems: the scheduling queue, the computation queue, and the transmission queue. The master server maintains the scheduling queue. Since two consecutive arriving requests may be from different users, the inter-arrival time is a random variable, which can be modeled as an exponential random variable [30]. Therefore, the arrivals of requests follow a Poisson process. The average arrival rate is denoted by $\lambda^i$. The requests are scheduled to the computing servers at the rate $S^i$. Each computing server has a corresponding computation queue to process requests. The service results are sent back to the users at the rate $B^i$ the transmission server. ## 2.3.2 Problem Formulation

Based on the proposed system models, we study the resource optimization problems in the FCFS service case and the priority service case. In each case, we optimize cloud resources to minimize the service response time and the resource cost, respectively.

## 2.3.2.1 FCFS Service Case

In the FCFS service case, the requests of users are served in the order that they arrived at the data center. All requests are processed with the same priority. Suppose there are $M$ classes of applications provided in multimedia cloud. Applications have different processing procedures, task sizes, result sizes, as well as different requirements on service response time. The mean arrival rates of the requests at time slot $t$ are denoted as $\lambda_1^t, \lambda_2^t, ..., \lambda_M^t$, respectively. According to the composition property of Poisson process [31], the total arrivals of requests follow the Poisson process with an average arrival rate $\lambda^t = \hat{\lambda}^t\mathbf{1}^t$. Thus, the

scheduling queue can be modeled as an $M/M/1$ queuing system [30] with the mean service rate $S^s$ at the master server. To maintain a stable queue, $\lambda^s < S^s$ is required. The response time of the scheduling queue is given

```
$T_{FCFS}^{com(s)} = \frac{1/S^s}{1-\lambda^s/S^s}$
```

Each application requires a different service procedure. $M$ computing servers are employed to process $M$ classes of applications, in which computing server $i$ is dedicated to service requests for class $i$ application. Since the VMS can be dynamically provisioned and released in the cloud, the number of computing servers can be dynamically changed according to the number of applications. For class-$i$ application, the average task size is denoted by $F_i$ and the execution time is a random variable, which is assumed to follow exponential distribution with average $F_i/C_i$ [32,33]. To maintain a stable queue, the constraint $\lambda^i < C_i/F_i$ must be satisfied. The response time at computing server $i$ is given

```
$T_{FCFS}^{com(i)(t)} = \frac{F_i/C_i}{1-\lambda^i/C_i}$
```

Therefore, the average response time in computation phase can be formulated as

```
$T_{FCFS}^{com(t)} = \mathbf{\hat{A}}(1/\lambda^i \cdot T_{FCFS}^{com(i)(t)}) = \mathbf{\hat{A}} \frac{F_i/C_i}{\lambda^i(1-\lambda^i/C_i)}$
```

After processing, all service results are sent to the transmission queue. Since a result is requested for each and the service is a closed system, the average arrival rate of the results at the transmission queue is $\lambda^$. For class-$i$ application, the average result size is denoted by $D_i$. Different applications have different result sizes, leading to different transmission time. The transmission time for the class-$i$ service is exponentially distributed with mean service time $D_i/B$, where $B$ is the bandwidth resource at the transmission server. Therefore, the transmission queue can be viewed as a queuing system in which service results are grouped into a single arrival stream and the service distribution is a mixture of $M$ exponential distributions. In fact, the service time follows hyperexponential distribution [30]. The transmission queue is actually an $M/H_M$ queuing system, where $H_M$ represents a hyperexponential $M$ distribution.
