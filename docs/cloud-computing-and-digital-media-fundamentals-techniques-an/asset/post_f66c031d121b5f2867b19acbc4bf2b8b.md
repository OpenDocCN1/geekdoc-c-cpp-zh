Resource cost minimization problem. Different priority applications have different requirements on service time. It is challenging for multimedia cloud providers to support multiple QoS provisioning at the minimal resource cost. Therefore, we formulate the resource cost minimization problem in the priority service case, which can be stated as follows: to minimize the total resource cost in the priority service case by jointly optimizing the allocated scheduling resource, the computation resource, and the bandwidth resource, subject to the queuing stability constraints and the service response time constraint for each application. Mathematically, the resource cost minimization problem can be formulated as follows:

```
$$\min_{S^t,C^t,B^t} 2^{wot(t)} = (aS^t + bC^t + gB^t)G \quad (2.11)$$
```

subject to

```
$$1^t < S^t$$
$$\hat{A}1^t F_j < C^t \quad j=1$$
$$\hat{A}1^t p_j < B^t \quad j=1$$
$$T_{prio}^{wot(j)(t)} < t_j, j=1, \mathcal{M}$$
```

where:
$T_{prio}^{wot(j)(t)}$, given in Equation 2.8, is the service response time for class-j application
$t_j$ is the upper bound of the service response time for class-j application

The resource cost minimization problem (Equation 2.11) can also be solved efficiently using the primal-dual interior-point methods [34].

# 2.4 FUTURE DIRECTIONS

In spite of the progress made in cloud computing, there remain a number of open issues as follows:

- 1. Resource demand prediction: Since the process of resource allocation takes time to complete, it will be too late to prevent QoS degradation if resource reallocation is only carried out when resources become insufficient. Therefore, an accurate resource demand model is required to forecast the resource demand in the near-term future based on the previous statistics.
- 2. Workload monitoring: The workload in cloud is changing in real time. To allocate resources to satisfy the dynamic workload, especially the burst of requests, a live workload monitoring is needed for cloud providers. In addition, it is a challenge to dynamically allocate the cloud resources to handle the time-varying workload.
- 3. Workload scheduling: There are two levels of scheduling in cloud computing. The first level is user-level scheduling, in which the requests for one application are distributed to different VMs according to the current workload. By balancing workload among the VMs, the user-level scheduling can effectively avoid congestions in the cloud. Compared to the user-level scheduling, the task-level scheduling performs in a finer granularity. An application can be decomposed into a set of tasks, each of which requires different resources. The task-level scheduling is to assign different tasks to different VMs so that the performance can be maximized.
- 4. Resource migration: With current techniques, VMs and application migrations have been implemented in the local area network (LAN) environment. In the future, cloud should be able to migrate VMs and services to other clouds, which can greatly improve the robustness of cloud data center.
- 5. Joint resource optimization: Currently, most of the resource optimization methods focus only on the cloud side, ignoring the transmission path and the user side. In fact, it is a challenging task to minimize or maximize an end-to-end QoS metric by jointly optimizing the resources in the cloud, at the client, and along the transmission path between the cloud and the client.
