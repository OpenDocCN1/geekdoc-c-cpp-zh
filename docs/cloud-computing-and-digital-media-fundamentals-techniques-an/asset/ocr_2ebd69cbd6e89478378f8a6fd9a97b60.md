# 9.4.2 SPARQL Evaluation Using MapReduce

We summarize the essential ideas of current solutions to this problem. As explained in Figure 9.7, conceptually the SPARQL query evaluation can be considered as a subgraph matching problem. However, to leverage the massive parallelism and scalability of the MapReduce framework, SPARQL queries are usually evaluated in a multipoint join. To be specific, considering variables as the join keys, Map first scan the dataset to find all the data that satisfy the given BQPs, and then shuffle the data of the same key by the Reduce task to examine all the possible join results. +   1. Reducing the volume of file scan. Solutions such as “Predicate split” [36,37] and precomputed query forwarding [38] try to evaluate queries only on the computing nodes that hold the desired data. Shared scan [11] is also widely adopted as an effective tool to reduce the file cost.
