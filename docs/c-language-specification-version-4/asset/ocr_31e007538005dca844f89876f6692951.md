When an expression contains multiple operators, the precedence of the operators controls the order in which the individual operators are evaluated. For example, the expression x + y * z is evaluated as x + (y * z) because the * operator has higher precedence than the + operator.

Most operators can be overloaded. Operator overloading permits user-defined operator implementations to be specified for operations where one or both of the operands are of a user-defined class or struct type.

The following table summarizes C#'s operators, listing the operator categories in order of precedence from highest to lowest. Operators in the same category have equal precedence.

| Category | Expression | Description |
|---|---|---|
| Primary | x.m | Member access |
| Primary | x(...) | Method and delegate invocation |
| Primary | x[...] | Array and indexer access |
| Primary | x++ | Post-increment |
| Primary | x-- | Post-decrement |
| Primary | new T(...) | Object and delegate creation |
| Primary | new T(...) {...} | Object creation with initializer |
| Primary | new {...} | Anonymous object initializer |
| Primary | new T[...] | Array creation |
| Primary | typeof(T) | Obtain System.Type object for T |
| Primary | checked(x) | Evaluate expression in checked context |
| Primary | unchecked(x) | Evaluate expression in unchecked context |
| Primary | default(T) | Obtain default value of type T |
| Primary | delegate {...} | Anonymous function (anonymous method) |
| Unary | +x | Identity |
| Unary | -x | Negation |
| Unary | !x | Logical negation |
| Unary | ~x | Bitwise negation |
| Unary | ++x | Pre-increment |
| Unary | --x | Pre-decrement |
| Unary | (T)x | Explicitly convert x to type T |
| Multiplicative | x * y | Multiplication |
| Multiplicative | x / y | Division |
| Multiplicative | x % y | Remainder |
| Additive | x + y | Addition, string concatenation, delegate combination |
| Additive | x - y | Subtraction, delegate removal |
