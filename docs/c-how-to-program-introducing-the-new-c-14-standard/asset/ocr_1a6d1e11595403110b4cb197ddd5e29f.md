# # `CommissionEmployee` Constructor

The `CommissionEmployee` constructor definition *purposefully does not use member-initializer syntax* in the first several examples of this section. This will enable us to demonstrate how `private` and `protected` specifiers affect member access in derived classes. As shown in **Fig. 11.5**, lines 12–14, we assign values to data members `firstName`, `lastName` and `socialSecurityNumber` in the constructor body. Later in this section, we’ll return to using member-initializer lists in the constructors.

We do not validate the values of the constructor’s arguments `first`, `last` and `ssn` before assigning them to the corresponding data members. We certainly could validate the first and last names—perhaps by ensuring that they’re of a reasonable length. Similarly, a social security number could be validated to ensure that it contains nine digits, with or without dashes (e.g., `123-45-6789` or `123456789`).
