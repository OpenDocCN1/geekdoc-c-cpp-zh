In the last two lines of the inner function (lambda expression) we present the search result in the form of a global group which is ObservableCollection <Contact> where it is implicitly transformed into an object of type <ObservableCollection <Contact>>.

# Continue adding a new contact, AddContactAsync

The AddContactAsync function requires only one Contact argument and returns a Task <bool> object to indicate the success of the add operation:

```
public async Task <bool> AddContactAsync (Contact contactToAdd)
{
	return await Task.Factory.StartNew (() =>
	{
		contactToAdd.Id = contacts.Count () + 1;
		contacts.Add (contactToAdd);
		return true;
	});
}
```

This code adds a new contact to the pre-existing contacts under the contacts variable, paying attention to this code:

```
contactToAdd.Id = contacts.Count () + 1;
```

What this phrase does is not found in any real practical application. It assigns a value to the Id property of the passing contact to the function. No application should do this, as this number should be generated automatically when the contact is added to the database. Since our application relies on fake data present in the memory we had to do this to distinguish the newly added contacts.
