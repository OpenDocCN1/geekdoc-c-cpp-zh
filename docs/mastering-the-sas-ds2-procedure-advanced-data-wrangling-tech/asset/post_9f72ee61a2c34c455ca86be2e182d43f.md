## 5.6.2 SQLSTMT Package Example

In my experience SAS in the real world, I have always been amazed by the flexibility provided by the SAS/ACCESS engines. The ability to manipulate almost any data, no matter what the source, using the powerful SAS language tools I had already mastered instead of having to learn a new language for each source, was heady stuff! But with great power comes great responsibility—using LIBNAME statement to manage data from great sources in the same process highlighted principle! These cross-library operations require that all of the data be present on a common platform in order to take place. In the early days of my career, that often meant drawing huge data sets out of the DBMS system and onto the same platform for processing. This caused simply processes to run for very long periods of time, and in addition to making me impatient, angered the indispensable deities that are vital to the success of all projects-the DBA and the SYSADMIN. I quickly learned to ask for help and to proactively create copies of my data in the DBMS in order to work these issues. In an ANSI SQL environment, this brought in its long-running problem: to update values in data contained in a second table, a correlated subquery was required that seemed to run forever. Or each DBMS provided several complex processes that we could circumvent that... You can see how process complexity can so quickly escalate!

This SQLSTMT package will update the data in a large table with values contained in a smaller table in a different library. We will not have to pre-stage a copy of the SAS table in the DBMS library, nor will we need to use a correlated subquery or other complex processes to make it work efficiently. In this example, both of the tables are in SAS libraries because I wanted to be able to practice using SAS University Edition, which does not provide a SAS/ACCESS interface to connect to a DBMS. But I've executed similar code with the larger table in Teradata, and the performance was excellent.

### 5.6.2.1 Cross-library Table Updates with the SQLSTMT Package

Our example use two SQLSTMT instances, to read the new prices from an update table, which we will create in the INIT method of our data program, and to execute UPDATE statements to modify the values in the master table, cr.prices. Because all of it is done using SQLSTMT packages, we could actually use a DATA _NULL program. However, I decided to create an audit data set while doing the updates so we have a permanent record of the changes made, so we will use a data program that produces output and an OUTPUT statement to create an audit file while processing. We will update values for the items listed in rows two through five, without modifying the data in any other rows. One and six are included in the help to ensure that things are working correctly. Here is the program that we'll use to update the data:

```sas
proc ds2;
data work.Price_Change_Audit /overwrite=;
/* Declare global variable to hold values */
declare double Changed having format datetime.;
declare char(15) Changed_By;
retain Changed_By='Student';
declare double Prod_ID having format z12;
declare double Original_Price Updated_Price having format dollar8.;

/* Instantiate the sqlmgmt package for update statement */
/* placeholders for values to be dynamically inserted */
/* positional list to supply values */
dcl sqlmgmt update('update crs.db.prices set=? where Product_ID=?', [Updated_Price, Prod_ID]);

/* Declare sqlmgmt package for source query to read data */
/* from a SAS table to be created in INIT method */
dcl sqlmgmt get_values;

method init();
Changed_By='Student';
/* Create the table of values for updating the large table */
sqlexec('create table crs.new_prices as select
Product_ID, Price, ROUND(Price*1.05,.01) as New_Price
from crs.prices where Product_ID in ('210200100009','2220010012','23010500006','24010100366','24050010039'));

method term();
/* Instantiate the sqlstmt package to get values from table created in INIT() */
get_values=sqlstmt('select product_ID,Price, New_Price from crs.new_prices');
/* Execute the query to obtain the values to be inserted */
get_values.execute();
/* Bind the query result columns to PD variables */
bind(Prod_ID, Original_Price, Updated_Price);
/* Fetch row from result set - returns 0 if successful */
while (get_values.fetch() = 0);
/* Execute the update statement */
update_me.execute();
/* Write a record to the audit file */
Changed_On=datetime();
output;
end;
end;
run;
quit;
```

The final section of the program resets the values to the original values. Because the table containing the values that we want to for updating already exists, we use a SET statement to read in the values used for making updates. However, we will still need an SQLSTMT package to read in the values in the big table. Because we are now using the RUN method to read in our data, we don't need to write a LOOP do to read the data rows, and we need to code an explicit OUTPUT statement because the RUN method's END statement includes an implicit output. While this code still circumvents the usual cross-library problems, it is even simpler to write and update.

```sas
proc ds2;
data work.Price_Change_Audit /overwrite=yes;
declare double Changed having format datetime;
declare char(15) Changed_By;
  retain Changed_By='Student';
declare double Prod_ID having format z12;
declare double Original_Price Updated_Price having format dollar8.2;
  dcl sqlstmt sets update_me
  ('update crs.db.prices set Price=? where Product_ID=?',
  ,[Updated_Price, Prod_ID]);
  method run();
    set (select Product_ID as Prod_ID
         ,New_Price as Original_Price
         ,Price as Updated_Price
    from crs.price_updates);
    update_me.execute();
    Changed_On=datetime();
    output;
end;
end;
run;
quit;
```
