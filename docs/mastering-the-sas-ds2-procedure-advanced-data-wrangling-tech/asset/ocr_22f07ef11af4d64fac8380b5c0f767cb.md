# 4.3 User-Defined Packages

# 4.3.1 General Considerations

If you want to use a standard, user-defined method in several programs across SAS sessions, you can build a collection of methods and store it in a SAS library. In DS2, we call these packages, and you create them using a DS2 package program. DS2 packages can be used in subsequent DS2 programs, making their methods easily and safely reusable.

But packages can be so much more than just a storage mechanism for user-defined methods! Packages are the objects of the DS2 language. Just as ALL programs contain three systems (INIT, RUN and TERM), all packages include a constructor method which has the same name as the package, and a destructor method DELETE. You can explicitly define a package's constructor and destructors to set up an initialization process for the package when it is instantiated and cleanup routines to be executed when the package goes out of scope.

When you do not write a constructor or destructor method, a null method is provided by the compiler. A package can also contain private, global variables that we can use to keep track of state within a package instance. You will reap the benefits of an object-oriented approach to application development and show examples of using DS2 packages as objects in Section 4.3.3.
