Figure 1.1: Traditional DATA Step versus DS2 Data Program Processing

| Base SAS DATA step | DS2 data program in Base SAS |
| --- | --- |
| SAS | SAS -> DS2 |
| PDV | PDV |
| ID Name Salary | ID Name Salary |
| Num Char Num | Bigint VarChar Decimal |

| SAS/ACCESS LIBNAME engine | DS2 driver |
| --- | --- |
| DBMS Table | DBMS Table |
| ID Name Salary | BIGINT VarChar Decimal |

We can see in Figure 1.1, when the traditional SAS DATA accesses DBMS data via the SAS/ACCESS engine using a LIBENAME statement, DBMS data types are automatically converted to fixed-width character or double-precision, floating-point numeric. In contrast, the DS2 data program accesses the RDBMS data via a special driver associated with the SAS/ACCESS product and can therefore process the data in its native data.

The SAS DATA step is essentially a data-driven loop: reading, manipulating, and writing out one observation at a time. If the process is computationally complex, it can easily become CPU bound; that, data can be read into memory faster than it can be processed. If the DATA step elapsed (clock) time in the SAS log is the same as the CPU time, your process is most likely CPU bound. DS2 can accelerate CPU-bound processing by processing data rows in parallel using DS2 threads.
