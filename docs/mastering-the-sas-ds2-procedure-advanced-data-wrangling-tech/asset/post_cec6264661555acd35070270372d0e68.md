Here is an example that shows similar processing, loads data from a data table, moving the data from a matrix to a VARARRAY with method, and writing the results out to the DS2 program result set:

```sas
proc ds2;
data;
  dcl varchar(7) Timing;
  dcl package matrix m(2,2);
  vararray double a[2] vl2;
  vararray double v[2, 2] w x y z;
  dcl double b[2,2];
  drop v1 v2;
  method run();
  /* Read data, load each row of matrix from vararray*/
    set x;
    m.in(a, n);
    m.tovarray(b);
  end;
  method term();
  Timing='Before:';
    m.tovarray(v);
    output;
  Timing='Trans:';
    m=m.trans();
    m.tovarray(v);
    output;
  Timing='SQRT:';
    m=m.sqrt();
    m.tovarray(v);
    output;
  end;
ata;
run;
quit;
```

To start, we create a matrix with six rows and four columns that represents the fluid capacities of all vehicles and a second matrix with one row and six columns that represents the inventory of each type of vehicle. The next step is to multiply these two matrices. The result is a matrix of one row and four columns containing the total volume of each fluid required for this year's maintenance.

### 5.5.2.1 Getting data into out of Matrices

Because it is easier to transfer data into and out of matrix package using arrays, for each matrix we create, we create a corresponding array or variable. We'll use the RUN method to load the capacity matrix and the vehicle inventory. Then, in the TERM method, we'll load the vehicle inventory into the unit's matrix, do the multiplication, and transfer the results out all values to the volume's array, round up to the nearest whole unit, and output the result set.

```sas
proc ds2;
title1 'Fluids required for this year''s maintenance:';
title2 'All volumes in gallons:';
data;
* The Matrices *
* Six vehicle types, 4 capacities each */
dcl package matrix m_caps(6,4);
* How many of each type get maintenance */
dcl package matrix m_units(1,6);
* Total amount of each fluid to buy */
dcl package matrix m_fluid_reg(1,4);
* The Arrays /
* 4 capacities each vehicle */
vararray double a[4] Oil Cooling Transmission Differential;
* How many of each type get maintenance */
dcl double a_units[1] Inventory;
* Total amount of each fluid to buy */
vararray double a_vals[4] Oil Cooling Transmission Differential;
keep Oil Cooling Transmission Differential;
```

```sas
method run();
  set curs.out_fleet;
/* Load capacities matrix from vararray, row by row*/
  m_caps.in(a_caps, n);
/* Load unit array with inventory values */
  a_units[n]=Inventory;
end;
method term();
  dcl int i;
/* Load units matrix from units array */
  m_units.in(a_units);
  /* With all matrices loaded, do the math */
  m_vols_reg=units.mlt(m_caps);
/* Load results to volumes vararray */
  m_vols_req.toarray(a_vols);
/* Each vech get 4 oil changes this year */
/* Cooling and transmission are in quarts- convert to gallons */
/* Because each vehicle gets 4 oil changes, oil is already in gallons */
do
  i=2 to dim(a_vols)-
    a_vols[i]=a_vols[i]/4;
end
/* Convert points to gallons */
Differential=Differential/8;
/* Round volumes up to nearest whole unit */
do i=1 to dim(a_vols)
  a_vols[i]=cell(a_vols[i]);
end
output;
end;
endata;
run;
quit;

```

## 5.6 The SQLMT Package

### 5.6.1 General

The SQLMT package provides a way to pass FedSQL statements to a database for execution. A FedSQL statement selects rows from a table, the SQLMT package provides methods for interrogating the rows returned by the query. Because the SQLSTMT instance prepares and stores the FedSQL statement in the database, the instance can efficiently execute the statement multiple times.

### 5.6.1.1 Declaring, Instantiating, and Using an SQLSTMT Package

At instantiation, the SQLSTMT package can accept either one or two parameters. The first parameter is required and defines the query that the package will execute.

```sas
dcl package sqlstmt drop ('drop crs.new_prices');
```

The SQLSTMT query may be dynamic by inserting question marks (?) as placeholders indicating where PDV variables will be inserted when the query is executed. Dynamic queries require a second parameter that provides the ordered list of PDV variables that will supply the placeholders when the query is executed. The SQL statement will be built and customized dynamically when the DS2 program calls the EXECUTE command.

```sas
dcl package sqlstmt upd
('update crs_db.prices set Price=? where Product_ID=?'
, [Price Product_ID]);
```

The code in the first SQLSTMT package parameter is checked for correct syntax when the package is instantiated. You might want to create a table inside a data program and query that with the SQLSTMT later in the same data program. Because the table does not exist at compile time, syntax of the SQLSTMT package at compile time would produce errors. You can circumvent this by declaring the SQLSTMT package at compile time, as discussed in the previous section with the matrix package.

```sas
dcl package sqlstmt make;
dcl package sqlstmt apnd;
method init() (
make=NEW_sqlstmt (
'create table work.dates (DTM double, DT double,T double)')
make.execute();
apnd=NEW_sqlstmt (
'insert into work.dates(DTM,T) VALUES (?,?)'
,[SAS_Datetime SAS_Time]);
end;
```

To execute the SQL statement using SQLMT package, we use the EXECUTE method.

```sas
proc ds2;
data _null;
dcl package sqlstmt qry{
  'select * from crs.dates';
  decl double DTM having format datetime;
  decl double DT having format mmddyy10;
  decl double T having format timeampm.
  method init();
    query.execute();
  query.bindresults({DT T});
    do while (qry.fetch(dt) = 0);
      put dt= dt= t=;
    end
end;
enddata;
run;
quit;
```
