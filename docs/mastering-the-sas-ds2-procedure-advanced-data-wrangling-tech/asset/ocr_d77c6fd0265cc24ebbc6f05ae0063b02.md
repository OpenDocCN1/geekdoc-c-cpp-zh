# 5.6.2 SQLSTMT Package Example

In my experience SAS in the real world, I have always been amazed by the flexibility provided by the SAS/ACCESS engines. The ability to manipulate almost any data, no matter what the source, using the powerful SAS language tools I had already mastered instead of having to learn a new language for each source, was heady stuff! But with great power comes great responsibility—using LIBNAME statement to manage data from great sources in the same process highlighted principle! These cross-library operations require that all of the data be present on a common platform in order to take place. In the early days of my career, that often meant drawing huge data sets out of the DBMS system and onto the same platform for processing. This caused simply processes to run for very long periods of time, and in addition to making me impatient, angered the indispensable deities that are vital to the success of all projects-the DBA and the SYSADMIN. I quickly learned to ask for help and to proactively create copies of my data in the DBMS in order to work these issues. In an ANSI SQL environment, this brought in its long-running problem: to update values in data contained in a second table, a correlated subquery was required that seemed to run forever. Or each DBMS provided several complex processes that we could circumvent that... You can see how process complexity can so quickly escalate!

This SQLSTMT package will update the data in a large table with values contained in a smaller table in a different library. We will not have to pre-stage a copy of the SAS table in the DBMS library, nor will we need to use a correlated subquery or other complex processes to make it work efficiently. In this example, both of the tables are in SAS libraries because I wanted to be able to practice using SAS University Edition, which does not provide a SAS/ACCESS interface to connect to a DBMS. But I've executed similar code with the larger table in Teradata, and the performance was excellent.
