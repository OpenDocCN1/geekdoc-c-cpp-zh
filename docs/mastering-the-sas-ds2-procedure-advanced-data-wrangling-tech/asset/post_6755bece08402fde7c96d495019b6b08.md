### 1.1 Introduction

Today's data scientists deal with ever larger data from a widening variety of sources, and the computations required to process them are continually becoming complex. The SAS DATA step, with its sequential observation-by-observation approach, has remained stubbornly single. In the summer of 2013, SAS released SAS 9.4, which included a revolutionary new language named DS2.

Here is what DS2 can do:

- natively process American Standards Institute (ANSI) data types
- provide modern programming constructs, making it simple to extend
- tightly integrate with SQL
- provide simple, safe multi-threaded processing to accelerate CPU-intensive tasks

I like to think of DS2 as a language that retains the power and control of the Base SAS DATA step with just enough object-oriented features. If you have a SAS/ACCESS license for a supported database management system (DBMS), the traditional DATA step accesses DBMS data via the LIBNAME engine, but data types are first translated to fixed-width character or double-precision floating-point numeric. This causes a loss of precision when dealing with higher-precision data types, such as BIG or DECIMAL. DS2 is capable of directly manipulating ANSI data types—including multi-byte character types—even when processing on the SAS compute platform.

### 1.2 Accessing SAS and Setting Up for SAS

The SAS DATA step is essentially a data-driven loop: reading, manipulating, and writing out one observation at a time. If the process is computationally complex, it can easily become CPU bound; that, data can be read into memory faster than it can be processed. If the DATA step elapsed (clock) time in the SAS log is the same as the CPU time, your process is most likely CPU bound. DS2 can accelerate CPU-bound processing by processing data rows in parallel using DS2 threads.

We can see in Figure 1.1, when the traditional SAS DATA accesses DBMS data via the SAS/ACCESS engine using a LIBENAME statement, DBMS data types are automatically converted to fixed-width character or double-precision, floating-point numeric. In contrast, the DS2 data program accesses the RDBMS data via a special driver associated with the SAS/ACCESS product and can therefore process the data in its native data.
