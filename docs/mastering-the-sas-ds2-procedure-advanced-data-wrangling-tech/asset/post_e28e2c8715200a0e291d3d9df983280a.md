
## Chapter 7: Performance Tuning in DS2

## 7.3.2 Analyzing Performance Statistics

One of the first comparisons to make is real CPU time. If your task is performing real-time and real time and CPU time are consistently within 10 to 15% of each other, the limiting factor is probably CPU time, and your task is CPU bound. If there is a large difference between real time and CPU time, the limiting factor is probably I/O, and your process is probably I/O bound. Other valuable information from FULLSTIMER can be gained by analyzing the remaining statistics. A search of support.sas.com for “FULLSTIMER SAS option” will provide more in-depth guidance on how to proceed.

## 7.3.3 Tuning Your Code

As a general rule, if your task reads from a table in a DBMS that has the SAS In-Database Accelerator installed, it will run much faster if you rewrite the data program and execute the thread from a data program using the SET statement. Performance will be even better if the data program output is also a database table and your database is capable of running both the thread and data programs in-database. As of this writing, only Teradata and Hadoop have that capability. If your task sources its data from a DBMS, using DS2_OPTIONS TRADE or OPTIONS SASTRACE or both can identify how much processing is happening in the database and how much movement to the SAS platform for processing was necessary.

In summary, the following:

- If your task is I/O bound, threading on the SAS platform will likely exacerbate the problem. However, if your task sources its data from a DBMS that has the SAS Database Code Accelerator installed, you can probably significantly improve performance by running the process in-database as a DS2 THREAD program.
- If your task is CPU bound, it can benefit from parallel processing using DS2 threads, even if you do not have in-database processing capability available. Try writing the data program as a thread program, and executing it in parallel from a data program using the SET statement, experimenting with THREADS+ option values.
- Another technique I've found (when my DS2 program uses an SQL query as input to the SET statement) is to create a temporary table using the query and then use the temporary table as input to the DS2 program while troubleshooting. This can help isolate performance degradation to the DS2 or SQL portion of the program.

### 7.4.2 SAS Support Communities

My favorite destination for seeking (and sometimes providing) answers is the SAS Support website at http://communities.sas.com. There are many sub-communities available, but most of the DS2 activity appears in the SAS Programming and General SAS Programming communities (under SAS Programming). The SAS Support forums are very active with seasoned users, newcomers, and SAS staff all eager to help each other.

Another excellent community resource is the Wiki at http://www.sascommunity.org. Contributors come from all the world and all walks of life. The "saspedia" portion is a unique source of information about a wide array of SAS techniques.

When posing a question to an online community, you can get help more quickly if you prepare properly. Post your question clearly and succinctly. Provide a program that demonstrates your problem as simply as possible. And if you want a quicker response, include a sample data set. The best way to provide sample data is to include a LITTLE DATA step that produces the sample data, so the folks on the can can run your code for themselves, using the same data, and be able to quickly reproduce your results. I wrote a blog about this "Jedi SAS Tricks: The DATA to STEP Macro" which included code for the data2datastep macro. This macro can create a DATA step to reproduce a data set that you specify. I've included the code for this macro in the ZIP file containing the data for this book. Look for the program file named data2datastep. The macro is self-documenting, but you can read more about how the macro works at http://go.gl/spQojuc. Please note that these shortened URLs are sensitive, make sure you use a capital Q.

### 7.4.3 SAS Technical Support

Any licensed user can contact SAS Technical Support with his or her SAS questions. There is a guide to help you optimize your interactions with SAS Technical Support.

- What can I expect from SAS Technical Support?
  See http://support.sas.com/techsup/support.html
- How can I contact SAS Technical Support?
  a. Use the telephone for business-critical issues: +1 (919) 677-8008.
  b. Use the web form for all other issues: http://support.sas.com/ctx/supportform/createForm
- What information will I need when contacting SAS Technical Support?
  * If you are using a commercial version of SAS, your company name.
  * The country in which your SAS software is licensed.
  * Your name, email address, and phone number.
- Site number, operating system, and software release. You can obtain this information from the top of a fresh SAS log, or you can execute this macro to print the information that you need in the SAS log:

```
%macro siteinfo;
%PUT NOTE: Site ID is &SYSITE;
%PUT NOTE- SAS Version is &SYSLONG;
%PUT NOTE- Operating System is &SYSSCP (&SYSSCPL);
%end;

%siteinfo
```
- SAS product involved (Base SAS is the product for DS2 questions).
- Succinct, one-line description of the issue for the subject line of your technical support track.
- Detailed problem description, including error or warning messages.
- A clear, concise description of any troubleshooting or research that you've already done.
- Copies of your SAS program, SAS log, and any other pertinent files. If at possible, supply some mock-up input data for your program to add the Technical Support folks in troubleshooting your problem. You can use the data2dataset macro discussed in Section 7.4.2 to provide the data. To include attachments, wait for the first automatic email response to arrive after you post your problem, and then reply to that email with the requisite attachments.

## 7.5 Review of Key Concepts

- The SAS system option FULLSTIM can provide significantly more detailed performance information in the SAS log than is usually available. own- The DS2_OPTIONS statement with the TRACE option can provide extra insight into how-database processing is accomplished by DS2 programs running in database.
- For benchmarking, it is necessary to code several approaches to the same problem, run them on realistically sized and located data, and compare performance statistics in order to best tune your DS2 programs.
- There is a lot of help available online for SAS users, including free e-learning courses, how-videos, SAS community forums, and SAS Technical Support.
- Proper preparation before contacting SAS Technical Support will make the engagement smoother and result in faster answers to your questions.
