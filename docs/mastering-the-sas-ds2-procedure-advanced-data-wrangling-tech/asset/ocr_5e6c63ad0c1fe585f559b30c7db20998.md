To execute the thread, we must first declare an instance in a data program. Because the thread requires a parameter, we will call the SETPARMS method to parameter before we use a SET statement to execute the thread. The THREADS=3 option will cause three copies of the thread program to execute in parallel

```
data null;
  decl thread work.myThread;
  method init();
    t.setparms(1);
  end;
  method run();
    set from t threads=3;
  end;
  method term();
    put 'DATA Program: ';
    put _all_;
    put;
  end;
enddata;
```

SAS Log:

| ThreadNo=0 Count=3
ThreadNo=1 Count=0
ThreadNo=2 Count=0
DATA Program:
NAME-National Savings and Trust Count=3 ThreadNo= N=4 RATE=0.0328

The log reveals that the thread program variable flag is available for processing in the thread program, but not in the data program. The thread's globally declared ThreadNoCount appear in the data program's PDV, and this can be confusing. Count was created with a SUM statement, its value is retained in the PDV. So, by the time data program TERM method is executed, Count is still there, but ThreadNo has been reinitialized to missing-even though _n_ is 4! In this case, it might have been a better idea to drop ThreadNo and Count in the thread program, as we really have no use for them in the output result set.
