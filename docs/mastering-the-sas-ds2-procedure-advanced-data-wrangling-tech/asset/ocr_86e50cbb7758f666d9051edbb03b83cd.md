```
data _null;
dcl char(25) "Character";
method run();
"Character"="&msg";nput "Character";
end;

```

SAS Log:

> WARNING: Line nnn: No DECLARE for referenced variable "this is the message."; creating it as a global variable of type double.
NOTE: Execution succeeded. No rows affected.

As we can see from the log, DS2 interpreted "This is the message." as a variable name. Because there was no indication of what type of variable to create, DS2 created a double-precision, floating-point numeric (SAS numeric) variable name "this is the message". The value of this new variable was assigned to the "Character" variable, which is a text variable. The automatic conversion from numeric to message produced the ':' that we then see in the log. We can tell what happened because of the warning message produced by the use of an undeclared variable.

To facilitate macro-generated text in DS2 literals, SAS provides the autocall macro %TSLIT allows all macros to resolve, and then takes the resulting text and applies a real single quote mark character to the beginning and end of the text. Finally, SAS sends the resulting text back to the word scanner. This makes macro variable resolution as expected in DS2:

```
%let msg=This is the message;
proc ds2;
data _null;
dcl char(25) "Character";
method run();
"Character"="%tslit(&msg);
put "Character";
end;
enddata;
run;
quit;
```

SAS Log:

> This is the message.
NOTE: Execution succeeded. No rows affected.
