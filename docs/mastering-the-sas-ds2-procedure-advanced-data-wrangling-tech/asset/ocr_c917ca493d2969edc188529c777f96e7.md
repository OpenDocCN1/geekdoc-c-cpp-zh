# Chapter 2: Introduction to the DS2 Language

Figure 2.4: DS2 Data Program Variable Scope

| Global identifiers can be referenced anywhere in the data program. | proc ds2;
data null;
-dcl varchar(6) var1 var2;
-retain var2 'Global';
-method init();
-dcl varchar(5) var1;
-put var1='Local';
-put 'INIT method ' var1=;
-put 'INIT method ' var2=;
-end;
method run();
-put var1=;
-put 'RUN method ' var1=;
-put 'RUN method ' var2=;
-end;
method term();
-put var1=;
-put 'TERM method ' var2=;
-end;
endata;
run;
quit; |
 Local identifiers can only be referenced within the method in which they were defined.

| INIT method var1=Local

Variable identifiers are also in scope if the variable is undeclared or introduced to the program via a statement. In DS2, an undeclared variable is created whenever a variable is first referenced in a program statement other than a SET or DECLARE statement, such as an assignment statement. The use of undeclared variables in DS2 is discouraged; doing so will produce warnings in the SAS log. Although this might at first seem strange to a SAS data programmer, if you ever executed a long-running SAS program only to be greeted by the dreaded NOTE: Variable var is uninitialized in the SAS log, you will understand the benefit of this behavior. Generally, that means you've misspelled a variable name somewhere in your code, and the processing time for that run of the step has been wasted.

You can control DS2 behavior for undeclared variables with the system option DS2COND or SCOND=option in the PROC DS2 statement. The default is WARNING, but NONE, NOTE, and ERROR are all valid values. When writing, prototyping, or coding, I prefer to have this option to ERROR, so that DS2 programs containing undeclared variables will fail to compile, will not execute, and will produce this message in the SAS log:

| ERROR: Compilation error.
ERROR: Line nn: No DECLARE for referenced variable var; creating as a global variable of type double. |
