You can think of a package as a "class": The package serves as the template from which an instance of object is created, and contains the necessary methods to create and destroy that instance, provide the object's behaviors (methods), and keep track of the object's current state (private global variables). For example, a household lamp. A lamp has functions (methods), such as operating its switch and it states—either on or off. In a DS2 package created to emulate a lamp, we would write methods to provide the lamp's function and create package variables to keep track of the lamp's status.

Although packages cannot include the automatically executed system methods INIT, RUN, and TERM, each package includes two special methods called the constructor and destructor. Constructor and destructor methods do not return types and cannot return values.

The destructor method is always DELETE and is automatically generated by the DS2 package program. It performs cleanup and releases packages back to the system whenever a package is terminated (destroyed). You can write your own DELETE method to add custom routines. The DELETE method executes automatically whenever a package instance goes out of scope and destroyed.

The constructor method has the same name as the package itself. For example, if your package was stored in work, the constructor method is TEST. If you don't explicitly define the constructor method, a null constructor is automatically generated by the DS2 package program. However, instead of calling the default null, you can write a user-defined constructor method instead. The method can be overloaded, if desired. A package instance is constructed in these circumstances: when a DECLARE PACKAGE statement is executed with constructor arguments, or in an assignment statement using a _NEW_ operator. A package's constructor method automatically executes when the instance is constructed.

Packages can also include global variables. These variables have package scope—that is, they are globally available to all methods within the package but are private to the package itself that they do not populate the PDV. You can use these variables to keep track of an instance's status.

In the following example, we will define a package that creates a lamp object. Each lamp has global variables lampName and lampOn to keep track of the status of the lamp, an overloaded constructor method, and other methods to allow us to query and control the status of the lamp.

```
proc ds2;
  package.lamp /overwrite=yes;
  /*Global variables instance name and lamp status*/
  dcl varchar(15) lampName;
  dcl tinyint lampOn;
/* Constructor method is overloaded */
  method lamp();
    lampOn=;
    put '**** Instantiating a lamp ****';
    lampName='lamp status not set. It is off (default).';
    put;
end;
```
