## 3.3.3. TO DOUBLE Function

The DOUBLE function accepts a single ANSI TIME, DATE, or TIMESTAMP value as an argument and returns the corresponding DOUBLE SAS TIME, DATE, or DATETIME value.

```
proc ds2;
data;
  dcl timestamp ANSI_Timestamp;
  dcl date ANSI_Date;
  dcl time ANSI_Time;
  dcl SAS_Datetime having format datetime25.6;
  dcl SAS_date having format yymmdd10.;
  dcl SAS_Time having format tod15.6;
 method();
  ANSI_Timestamp=timestamp='2017-09-07 07:09:17.090717';
  ANSI_Date=date='2017-09-07';
  ANSI_Time=time='07:09:17';
  SAS_Datetime=to_double(ANSI_Timestamp);
  SAS_Date=to_double(ANSI_Date);
  SAS_Time=to_double(ANSI_Time);
  put 'ANSI: ' ANSI_Timestamp ANSI_Date ANSI_Time;
  put 'SAS: ' SAS_Datetime SAS_Date SAS_Time;
 end;
enddata;
run;
quit;
```

## 3.3.4 Processing SAS Missing and ANSI Null Values

SAS missing values and ANSI null values are two very different representations of unknown values in a data store. ANSI null values are actually no value: zeros of data are stored when the actual value for a variable is not known. As a result, nothing can be determined about the unknown value. So a null value is an unknown value.

SAS takes a different approach to missing data. It stores special codes for missing values in each variable where the actual value is unknown. Although the actual value for this variable is not known, MISSING itself is a known value of sorts. There are three types of missing in SAS:

- character missing, represented by a blank (' ') when displayed in reports
- numeric missing, represented by a period ('.') when displayed in reports
- special numeric values (7 levels), represented by '_' and 'A' through 'Z'

### 3.3.4.1 SAS Missing versus Null: The Rest of the Story

If the idea of special missing values is news to you, SAS might seem a bit obsessive. However, there is good reason for all this focus. Consider a scenario where you are tasked with collecting data in a neighborhood. Here is a copy of your questionnaire:

| House # | Question | Response |

With your clipboard in hand, you valiantly set forth on your mission to collect data. You knock on the first door and ask your questions. When asked about household income, the first respondent answers, "How should I know? My spouse stays home and drinks beer all day!" Well, it seems off to a very start! At house number 3, you are still rattled from the encounter at house number one that you forgot to ask the income question all, and just to make the day more "interesting" the respondent at house number 5 becomes indignant when asked about household income and slams the door in your face! The rest of your day goes reasonably well, with respondents answering all the questions. When the survey is complete, there are several data points for which we don't have a value, but we know the reasons why the data is missing: some refused to answer, others were clueless, and at times we forgot to ask the household income.

If we store data in SAS, we can check each of the missing values to know why the data is missing. .R could indicate the respondent refused to answer, .C that the respondent was reluctant, .F that I forgot to ask for the salary value. The concepts of null and missing are so fundamental to how data is processed and so radically different from each other, PROC DS2 actually has two separate operating modes on which concept for handling nonexistent data is given: SAS mode and ANSI mode. But before I launch into a detailed description of missing and null, I want to make clear that, in DS2, only those data types that are available in Base SAS DATA step and DS2 programs (DOUBLE and CHAR) are capable of containing missing values. Variables of any other data type are strictly ANSI in their behavior. They will always contain null when assigned a nonexistent value.

## 3.3.4.2 PROC DS2 SAS Mode

SAS mode is the default mode for PROC DS2, and thus it is never specified in the PROC DS2 statement. In SAS mode, expressions resolving to an unknown value produce SAS missing values as an intermediate result. When those are assigned to CHAR or DOUBLE variables, those variables will contain a SAS missing value.
