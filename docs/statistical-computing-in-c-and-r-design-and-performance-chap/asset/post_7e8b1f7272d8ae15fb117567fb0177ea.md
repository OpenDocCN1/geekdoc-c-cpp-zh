This class Functor used is probably the most direct approach and overloads the () operator with two arguments. The first corresponds to the optimization variable, as, while the second is an integer that is combined with if statements to determine which of the functions $f'$ or $f''$ will be evaluated. Our previous one-argument version of () can live in harmony with the two-argument version and suffices for access to the function itself. An overloaded constructor that takes one function pointer has been provided to handle cases where no derivative information is available. The fact that the one-argument version of () can be used with objects created from either class makes the Listing 8.11 function useful for derivative and derivative based methods without changing our previous code that was created for the latter methods.

The prototype for the Newton method now takes the form

```cpp
double newton(double& f, double a, double b, double start, int* i const);
```

The arguments for newton are a Newton object, the lower and upper terminals (a and b) of the interval that should contain the minimizer and a value to be used as an initial "guess" for the minimizer's location. For a convex function, specification of a and b would be extraneous to the algorithm. But, when dealing with functions that have multiple minima the inclusion of a and b provides means to check that the Newton method does not take you beyond the region of interest. In general, there is no risk that the Newton step $f'(k)$ should produce a new value $(k+1)$ in the region of interest and that this derivative $f''(k)$ can also produce a floating-point 0. Both of these problems are met taking into account and that is the purpose of the i pointer argument for newton. This variable will return an error code that indicates either of the two problems has been encountered.

The definition for newton method

```cpp
double opt::newton(const Functor& f, double a, double b, double start, int* ier const) {
  *ier = 0;
  double minTemp = start, minTempLast = b;
  while(fabs(minTemp - minTempLast) > delta*fabs(minTemp) && *ier < maxIter){
    minTemp = minTempLast;
    if(f(minTempLast, 2) != 0)
        minTemp = minTempLast - (minTempLast - 1)/f(minTempLast, 2);
    else {
        *ier = 1;
        break;
    }
    if(minTemp > b || minTemp < a) {
        *ier = 2;
        break;
    }
    niter++;
  }
  return minTemp;
}
```

The code in the method mimics the pseudo-code object development in Algorithm 8.2. The actual Newton steps are computed using a Functor with the second argument to evaluate both the first and second derivatives of f. Additional if blocks have been included to guard against cases where $f'$ might be 0 or the Newton update takes us outside the interval over which f is minimized. Such occurrences return values of 1 and 2, respectively, for the integer corresponding to ier. When error occurs there rather than to proceed further and the most expedient solution is likely to try a new value. Rather than stopping execution with the exit function, a break statement (e.g., Section 3.4) has been used. The current loop is terminated when break is encountered but the program will continue to run and end gracefully. In particular, this allows the value of ier to be returned to the calling program for use in diagnosing the source of the difficulty.

The driver program in Listing 8.12 was written to apply the Newton method to the function $f(\theta)=-\theta(1-\theta)$ from Section 3.

> Listing 8.12 optDriver.cpp

```cpp
//optDriver.cpp
#include <iostream>
#include <cstdlib>
#include "optim.h"
#include "functor.h"

double fun(double theta){
    return (-theta*(1.- theta));
}

double fun1(double theta){
    return (-1. + 2.*theta);
}

double fun2(double theta){
    return 2;
}

int main(int argc, char** argv){

    int iMax = atoi(argv[1]);
    double delta = atof(argv[2]);
    double start = atof(argv[3]);

    Functor f(&fun, &fun1, &fun2);
    Optim Opt = Optim(iMax, delta);
    int ier = 0;
    double fMin = Opt.approx(f, 0., 1., start, &ier);
    std::cout << "The approximate minimizer is " << fMin << std::endl;
    std::cout << "The error code is " << ier << std::endl;
```

The functions fun, fun1 and fun2 are f and its first two derivatives. The addresses of these three functions are used to obtain the Functor object. Optim class object is created using new values for delta and itMax that are provided through the command line. The resulting approximate value are then written to standard output.

It seems like every check for the starting value works. A little checking reveals that iterations are always terminated when the Newton method reaches the solution. Of course, this is no surprise for this choice of an objective function and a bit of luck has occurred. A value of start=.1 allows the method to travel the gentle downhill with increasingly smaller steps towards $\theta=0$.
