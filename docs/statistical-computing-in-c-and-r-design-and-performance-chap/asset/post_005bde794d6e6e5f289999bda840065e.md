
# PARALLEL RANDOM NUMBER GENERATION

```cpp
//runOpenMP.cpp
#include <omp.h>
#include "RngStream.h"
#include <iostream>

using std::cout; using std::endl; using std::cin;

int main() {
    int nP = omp_get_num_procs();
    omp_set_num_threads(nP);//set number of threads

    unsigned long seed[6]={1,2,3,4,5,6};
    RngStream::SetPackageSeed(seed);
    RngStream RngArray[nP];//array of RngStream objects

    int myRank;
    #pragma omp parallel private(myRank)
    {
        myRank = omp_get_thread_num();
        #pragma omp critical
        cout << "For thread " << myRank << endl;
        RngArray[myRank].WriteState();
        cout << "The random number is " 
             << RngArray[myRank].RandU01() << endl;
    }

    return 0;
}
```

The first step is to include the RngStream class header file RngStream.h via an include directive. The SetPackageSeed function is then used to set the six integers of unsigned long, as the array is created with nP being the number of processors. The default behavior is for the seed of each array element to be $2^{31}$ states from the initial state of its predecessor and their states are produced to standard output to allow for comparison with our parallel treatments. Independent streams will be produced if each thread uses a different entry from RngArray when generating numbers. To accomplish this we simply use the number assigned to each thread by the OpenMP API as it indexes for accessing the array of RngStream objects. To avoid garbled output the segment from the parallel region is wrapped in a critical region.

Let us consider how to construct an of our OpenMP program that can use MPI. There are various ways to accomplish this. Perhaps the simplest is to have all processors create an array of Rngstream objects and then the object that carries their rank. This approach is left as an exercise (Exercise 11.1). Our particular solution is more involved and involves use of some features that are provided in RngStreams package.
As noted at the beginning of this section, seeds/states of Rngstream objects are advanced by multiplication using matrices $A_1$ and $A_2$. A function that can be used to carry out these multiplications mod $2^{32}-09$ and mod $2^{32}-83$ is contained in the RngStream.cpp file. An anonymous namespace is created using syntax as

```cpp
namespace
{
```

This creates a namespace that is available only to functions in the same file. In this respect, it provides an alternative to the creation of global static functions and variables. Appendix E provides another illustration of how anonymous namespace can provide useful. The anonymous namespace in RngStream.cpp holds the $A_1$ and $A_2$ matrices as $3 \times 3$ unsigned long integers. It also includes the `matVecMod` prototype:

```cpp
void MatVecMod(const double A[3], const double s[3], double v[3], double m)
```

This function perform multiplication of $3 \times 3$ three-element arrays $s$ modulo $A$ and return the result in the three-element array $v$, by taking $A$ to be $A_1$ or $A_2$ and $m$ to be $m_1$ or $m_2$, a given seed can be advanced to obtain a seed for the next random stream. With this in mind and then appended

```cpp
static void AdvanceSeed(unsigned long seedIn[6], unsigned long seedOut[6]);
```

to the header file RngStream.h and then:

```cpp
void RngStream::AdvanceSeed(unsigned long seedIn[6], unsigned long seedOut[6]) {
    unsigned long tempIn[6]; double tempOut[6];
    for(int i = 0; i < 6; i++)
        tempIn[i] = seedIn[i];
    MatVecMod(A1, tempIn, tempOut, m1);
    MatVecMod(A2, tempIn, tempOut, m2);
    for(int i = 0; i < 6; i++)
        seedOut[i] = tempOut[i];
}
```

to RngStream.cpp file. By declaring `AdvanceSeed` as static it can be used directly without a RngStream object which is precisely what is needed for the application that we have in mind. Our implementation of RngStream now takes the form

Listing 11.5 ranMPI.cpp

```cpp
//ranMPI.cpp
#include <iostream>
#include <#include <mpi.h>
#include "RngStream.h"

using std::cout; using std::endl;

int main(){
    unsigned long seed[6] = {1,2,3,4,5,6};

    MPI_Init();
    int myRank = MPI_COMM_WORLD.Get_rank();
    int nP = MPI_COMM_WORLD.Get_size();

    if(myRank == 0) {
        unsigned long tempSeed[6];
        double ranValue = 0;
        //start with the 0 processor
        RngStream::SetPackageSeed(seed);
        RngStream Rng;

        double myNumber = Rng.RandU01();
        cout << "For processor 0 the state is" << endl;
        for(int j = 0; j < 6; j++)
            cout << seed[j] << endl;
        cout << endl;

        // create and send the seeds to the other processors
        for(int i = 1; i < nP; i++){
            RngStream::AdvanceSeed(seed, tempSeed);
            MPI_COMM_WORLD.Send(seed, 6, MPI_UNSIGNED_LONG, i, 0);
            cout << "For processor " << i << " the state is" << endl;
            for(int j = 0; j < 6; j++)
                cout << tempSeed[j] << endl;
        }
        cout << endl;

        // collect the results
        for(int i = 1; i < nP; i++){
            MPI_COMM_WORLD.Recv(&ranValue, 1, MPI_DOUBLE, i, 0);
            cout << " The random number for process " << i
                << " is " << ranValue << endl;
        }
        cout << " The random number for process 0 is " << myNumber
            << endl;
    }
    else{
        unsigned long mySeed[6];
        //get my seed
        MPI_COMM_WORLD.Recv(mySeed, 6, MPI_UNSIGNED_LONG, 0, 0);

        // create the rngstream object
        RngStream::SetPackageSeed(mySeed);
        RngStream Rng;

        //generate my number and send it back to the 0 processor
        double myNumber = Rng.RandU01();
        MPI_COMM_WORLD.Send(&myNumber, 1, MPI_DOUBLE, 0, 0);
    }

    MPI_Finalize();

    return 0;
}
```

The idea behind Listing 11.5 is straightforward. The master (or rank 0) processor uses our AdvanceSeed function along with an initial seed to determine seeds that will produce "independent" random number streams for the other processors. These seeds are communicated to the processors using the Send and Recv functions. The processors then use these to initialize their individual RngStream objects. After finishing their tasks, the processors produce the uniform value they generated to the master process for output.
