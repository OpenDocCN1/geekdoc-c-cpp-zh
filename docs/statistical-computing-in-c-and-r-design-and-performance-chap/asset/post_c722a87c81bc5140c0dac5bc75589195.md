## 9.2 Linked lists and mergesort

Linked lists provide another approach to implementation of a dictionary. They arise, for example, in applications such as storage of sparse matrices and polynomial arithmetic (Exercises 10.26-10.27). Like dynamic arrays, they also provide a foundation from which other useful data structures such as hash tables, queues and stacks can be built.

As we saw in the previous section, insertion of new elements or resizing operations is computationally expensive for array types. Linked lists provide one means of overcoming such problems. For these data types resizing is actually costly, while insertion can be performed in constant time. With these compromises, there is a downside which, in this case, comes in the form of slow performance for each of list elements.

A list data structure consists of a collection of objects that have both key and data components, as well as a member next which designates (e.g., by a pointer) the next element in the list. The components of the list are generally nodes with the first node having the head and the last node referred to as the tail. The value of next for a list is the NULL value (e.g., a null pointer) indicating it has no successor. Lists of this particular type are called singly linked because the connection between nodes goes only in one direction; i.e., it is only possible to move toward the tail of the list by "stepping" through the next members of the node objects in the list. A simple extension is the doubly linked list, where nodes have an additional member that points to the preceding entry thereby making both forward and reverse movements possible.

Let us now take a look at the operations required to implement a linked list. A linked list can be built by "pushing" new nodes onto the front of the list as in

### Algorithm 9.3 push(a): Add a new node to a linked list

```
a.next = head
head = a
```

Here and subsequently the . notation represents a generic member selection operator; e.g., a.next is the "value" of next for an object. So, the value of next for the new node a is assigned the address of the current head. Then, a becomes the head and the list has grown by one object. Note that two simple steps are needed to add a node. The operation can therefore be accomplished in constant time.

The lookup operation for a linked list is described in Algorithm 9.4.

### Algorithm 9.4 lookUp(key): Look-up in a linked list

```
a := NULL
while a != NULL then
  if a.key == key then
    return a
  end
  a := a.next
end
return NULL
```

## ABSTRACT DATA STRUCTURES

The implementation is quite simple that one iteratively steps through the list by moving from each node to its next member until the end of the list is encountered or the designated key value is found. The algorithm returns the node that has the desired value or NULL if no node exists with that key. Note that potentially every node in the list must be examined to find the one with the targeted key value. Thus, this operation can require order n operations in an n-element list.

To insert a node to the right of (i.e., immediately after) a node with given key value, we first look up the key to find where the new node should be placed. This also allows us to check if an element with the same key is already present which should trigger an error report. The idea is implemented in Algorithm 9.5.

### Algorithm 9.5 insert(a, key): Find the location and insert a node into a linked list

```
if lookup(p,key) == NULL then
  b := Up(key)
  a.next := b.next
  b.next = a
else
  return Error: duplicate key!
```

There is nothing special about insertion to the right. In fact, the insertion to the left or between two specified keys may be of more interest in some applications (Exercise 9.12).

As true for dynamic arrays, it is also of interest to be able to sort the elements in a list. The method of choice in this case is called mergesort. Like quicksort, it uses a divide-and-conquer strategy although mergesort handles the details in how that is accomplished.

To illustrate the mergesort, let us again consider sorting the integer array:

+ 15 1 18 28 27 19 38 6 2 40

that was used in Section 9.2.1. To divide, this array into the subarrays (15, 1, 18, 28, 27) and (19, 49, 38, 6, 40). Let us focus on the second array which we split into two more component arrays (19, 49, 38) and (6, 2, 40). Again, working with the second subarray, we arrive at a singleton 6 and (2, 40) the latter which is already sorted. The next step is to merge these two "arrays". To accomplish this the larger array. The pair (6, 2) is sorted and appended to 40 to give (2, 6, 40). By the same process (19, 49, 38) we get (19, 38, 49). Then we merge (19, 38, 49) and (2, 6, 40) to get (2, 6, 19, 38, 40, 49). The final result is (2, 6, 19, 38, 40, 49).
