The Node in our linkedList class will be stored on the free-store. Thus, an explicit destructor is needed such as

```cpp
linkedList::~linkedList() {
  Node* temp;
  while (Head != 0) {
    temp = Head->Next;
    delete Head;
    Head = temp;
  }
}
```

The definition of the method is

```cpp
void linkedList::push(int newData, int newKey) {
  Node* newNode = new Node(newData, newKey, Head);
  Head = newNode;
  Size++;
}
```

This uses the nondefault constructor to initialize a Node object with its Next member given the address of the current head node. The new node that is pushed onto the list becomes the head node, its Next member points to the former head node and the Size is incremented.

The lookup method for the linkedList structure looks like

```cpp
Node* linkedList::lookup(int key) const {
  Node* iter = Head;
  while (iter != 0) {
    if (iter->keyValue == key) {
      return iter;
    }
    iter = iter->Next;
  }
  return 0;
}
```

This follows verbatim from Algorithm 9.4 and provides an example of the general way to iterate through a list using while, rather than for, loop.
The insert method takes the form

```cpp
void linkedList::insert(int newData, int newKey, int key) {
  if (lookup(newKey) != 0) {
    Node* iter = lookup(key);
    if (iter != 0) { // target exist
      Node* newNode = new Node(newData, newKey);
      newNode->Next = iter->Next;
      iter->Next = newNode;
      Size++;
    } else {
      std::cout << "Key not found!" << std::endl;
    }
  } else {
    std::cout << "Duplicate key!" << std::endl;
  }
}
```

In line with Algorithm 9.7, our code for the application of mergesort to our simple linkedList class

```cpp
void linkedlist::mergeSort(Node** pHead) {
    Node* head = *pHead;
    Node* midNode;

    if (head == 0 || head->Next == 0) // nothing to do
        return;

    split(head, &midNode);

    // recursion
    mergeSort(&head);
    mergeSort(&midNode);

    // now merge
    *pHead = merge(head, midNode);
}
```

An oddity of sorts is that this arising in the Node** method argument. The reason for this is that mergeSort will actually rearrange the pointers that connects the nodes in the list. In particular, this requires it to be able to change the value of the Head member of a linkedList object. If we simply passed head to the function, only a copy of the pointer would be available and changing it would not actually alter the value of Head. Unlike the array setting, we do not know how to partition the list into substrings of roughly equal length. The split method accomplishes this; it takes the head node pointer as its first argument and returns the "middle" node pointer in its Node* second argument. The mergeSort method is then applied to references to head and "middle" pointers thereby setting off the recursion. The final step is an application of the merge method that produces the new head node pointer.
Our code for the split function below follows a standard approach for finding the "middle" node in a linked list.

```cpp
void linkedlist::split(Node* head, Node** midNode) {
    Node* fast;
    Node* slow;
    if (head == 0 || head->Next == 0)
        *midNode = 0;
    else {
        slow = head;
        fast = head->Next;

        while (fast != 0) {
            fast = fast->Next->Next;
            if (fast != 0)
                slow = slow->Next;
            fast = fast->Next;
        }
        midNode = slow->Next; // new list has slow->Next as head node
        slow->Next = 0; // terminate the other list at slow
    }
}
```

A pair of pointers are defined that move down the list (i.e., toward the tail node) with the fast pointer progressing as fast as its slow counterpart. When the fast pointer reaches the end of the list, signaled by its Next being the null pointer, the slow->Next pointer will be pointing to be viewed as a "middle" node. There is more than here it may seem. The "middle" node that has been located with the algorithm is returned in the function's argument and will then serve as the head of the resulting list. The original list that begins at the head argument split until its current tail and this must be rebuilt before there will actually be two separate lists. Making slow->Next = 0 terminate the other list at slow.
