
# BASIC MPI COMMANDS FOR C++

## 11.3 Basic MPI commands for C++

The dominant API for distributed memory computing is the Message Passing Interface and it is precisely what MPI functions are created to accomplish. Messages are passed between processors through the creation of communicators which are capable of communicating with each other. In C++ the communicator concept is implemented through the COMM class. In particular, the COMM_WORLD object that connects all the processors used by a program will always exist. This is the only communicator object that will be discussed here.

To use MPI in C++ programs we need to include the header file mpi.h which provides all the MPI prototypes. The MPI classes and functions then reside in the MPI namespace and can be accessed via the scope resolution operator. The MPI part of our code must be placed between the two commands

- MPI::Init()
- MPI::Finalize()

The Init here stands for "initialize" while Finalize terminates inter-processor communication. Accordingly, MPI calls are illegal before or after Finalize.

Associated with the COMM_WORLD object are a number of methods for communication and related purposes. Of particular interest are

- MPI::COMM_WORLD.Get_rank()
- MPI::COMM_WORLD.Get_size()

The MPI versions of the omp_get_thread_num and omp_get_num_procs functions that are used with OpenMP. The two functions return integers the unique rank that has been assigned to each processor and the number of processors being managed by the COMM_WORLD object.

The code list below provides a more formal version of our standard "Hello world! application using the four functions we have learned for

```cpp
//mpiEx1.cpp
#include <iostream>
#include <mpi.h>

int main() {
    MPI::Init();

    int myRank = MPI::COMM_WORLD.Get_rank();
    int np = MPI::COMM_WORLD.Get_size();

    std::cout << " Hello y'all from processor " << myRank << " ";
    std::cout << " of " << np << std::endl;

    MPI::Finalize();
    return 0;
}
```

To execute this code is issued to the operating system that will result in the placement of an executable version of the program in RAM on each processor. At this point the individual processors work autonomously to carry out their tasks of printing out the greeting. The processor's rank can be used to specialize the computation on each processor as we see here and in later examples.

The syntax mpic++ (on the cluster where this code was compiled) invokes a C++ compiler for MPI programs. The executable mpiEx that is run using mpiex command with the -np 5 option requesting five processors are used to perform the computations. Notice the processors do not finish in order this is not surprising as they are working independently.

In practice the set of commands that were used here to compile and run mpiEx.cpp may or not be appropriate for a given system using MPI. In some cases a single node can be obtained on a cluster that will allow for an interactive session and it is not difficult to install one of the MPI implementations such as Open MPI on a desktop machine for interactive use. But, both of these options enable MPI in shared memory environments which is not really its purpose. The power and utility of MPI is best in distributed-memory, high-performance computing systems. In such systems job submission will generally take place in batch mode using job scripts that can take various forms depending on the software that is being used to manage job scheduling. The details involved can usually be obtained from the computing center that manages the cluster.

Our mpiEx.cpp program is not necessarily interesting for several reasons. With a parallel perspective it is short in that there is no interaction between processors. Inter-processor communication is useful for those frequently employed for parallel programming. The simplest way to communicate between processors is through the Send and Recv (an abbreviation for receive) methods. The methods of these functions are

```cpp
void MPI::COMM_WORLD.Send(void* buf, int count, MPI_Datatype datatype, int dest, int tag, MPI_Comm comm)
```

```cpp
void MPI::COMM_WORLD.Recv(void* buf, int count, MPI_Datatype datatype, int source, int tag, MPI_Comm comm)
```

The first argument for both functions is a pointer to value. This is just a way of passing generic data in and out of the functions. The count buff appears in both the Send and Recv functions. The data is what is being sent by Send and received by Recv. The (third) datatype argument is used to describe the contents of buff as in some C++ data type that is recognized by MPI. Such data types include all the common ones in C++ as well as those that are defined. The latter option will not be offered. For our purposes it is enough to know that, for example, MPI::CHAR, MPI::INT, MPI::LONG, MPI::UNSIGNED_LONG, MPI::FLOAT, MPI::DOUBLE, MPI::LONG_DOUBLE and MPI::BOOL correspond to C++ primitive data types, int, unsigned long, float, double and bool, respectively.

The (second) count argument to the Send and Recv specifies how many of datatype values are being sent or received. The count arguments do not need to match for a send and receive. But, the receive count must be at least as large as what has been seen in order to avoid an error. The comm argument is the communicator object that is managing the inter-node communication and will always be COMM_WORLD for our applications.

The dest and source arguments in Send and Recv represent the rank of the node for which the message is intended and the rank of the node from which a message is to be received, respectively. The remaining tag argument is a parameter that provides some sorting facility for incoming and outgoing messages. It comes handy if one is sending, for example, two doubles to another processor. Using a different tag for each will make certain they are identified correctly and then stored in a suitable variable by the receiving processor.

With the above preliminaries we are now ready to write our second MPI program. It uses inter-node communication to create the “Hello world!” application.

```cpp
//mpiEx2.cpp
#include <iostream>
#include <mpi.h>
#include <cstring>

int main() {
    MPI::Init();
    int myRank = MPI::COMM_WORLD.Get_rank();
    int np = MPI::COMM_WORLD.Get_size();

    char msg[20];
    if(myRank == 0) {
        strcpy(msg, "Hello ya'll");
        for(int i = 1; i < np; i++)
            MPI::COMM_WORLD.Send(msg, 20, MPI_CHAR, i, 0);
    }
    else {
        MPI::COMM_WORLD.Recv(msg, 20, MPI_CHAR, 0, 0);
        std::cout << msg << " from processor " << myRank << std::endl;
    }

    MPI::Finalize();
    return 0;
}
```

The idea behind mpiEx2.cpp is that a portion of our greeting message will now be relayed from the "master" or rank 0 to the other processors using the Send and Recv functions. This illustrates how branching statements can be used to determine the action of each of the processors; in this case, the processor 0 is told to tell all the others are to receive via use of if/else block.

The message segment "Hello ya'll" will be stored in the char array msg which has been chosen to length 20. The choice of 20 is arbitrary. It can be any value large enough to provide storage for the portion of the greeting it meets. To place in msg the rank 0 processor uses the strcpy function whose purpose is to copy strings into characters. An array of (at most) 20 elements of type MPI_CHAR is sent and received. Processor 0 sends the array to each of the other processors using the Send function in a loop with the dest argument being the receiving processor’s rank and the value of tag arbitrarily to 0. The other processors receive the message by using 0 as the source argument for the Recv function. In this lancer the value of tag must agree with the value used in the Send function.
