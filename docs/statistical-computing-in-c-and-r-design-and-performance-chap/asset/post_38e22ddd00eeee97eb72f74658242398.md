Additional class members have been added to help information i) the number of times each mach has used (the nMach set that will hold a two-component integer), ii) the number of times each was set (the nSet set that will hold a 10-component integer vector) and iii the number of draws nDraws or, equivalently, the number of g5 objects that are stored in the list objList.

The next step is to create a constructor for the g5List class. The ensuing code allows this and we will spend some time discussing the details of this function.

```
g5List<-function(fileName){
A <- readg5(fileName)
draws <- length(A)
objList <- lapply(1:nDraws, FUN =
function(i) g5(A[53:(i+54]))
temp <- apply(objList, FUN, sum = function(g5obj) g5obj@n)
tempMach <- sum(temp == "")
mach <- c(tempMach, nDraws)
temp <- apply(temp, FUN = function(g5obj) g5obj@no)
set <- integer(0)
for(i in 1:nDraws) set[i] <- i
gListObj <- new("g5List", objList = objlist, nDraws =
as.integer(nDraws), nSet = nSet,
Mach = as.integer(nMach))
return(gListObj)
}
```

For convenience of access to the elements of a g5List object we should extend the list setting operator [[]] to work with the g5List class. The natural way to accomplish this by having g5ListObj[[i]] correspond to g5ListObj[[i]] for a g5 object g5ListObj. The [[ operator is an S4 function of the corresponding type helps show that methods may only be dispatched on internal code which is built into the R interpreter with the x argument. So by x = "g5list" an indexing method can be introduced

```
> set("[[[", signature(x = "g5List", function(x, i, j, ... = TRUE) x@List[[i]])
```

It seems natural to define a replacement of [[ at that point which is readily accomplished with

```
> ReplaceMethod("[[[", signature(x = "g5List", function(x, i, j, ..., value) {x@g5List[[i]] <- value})
```

The effect is to replace a component of the list with a specified index with the right side of the symbol. The listing operator is probably the most natural way to access individual objects in a g5List object. This alone is not sufficient as it does not provide us with access to the other g5 class members ndvars, nMach and nSet. These can be obtained using @ operator. But a more aesthetically pleasing approach is provided by accessor functions created with

```
> setGeneric("ndvars", function(object) standardGeneric("ndvars"))
[1] "ndvars"
> setMethod("ndvars", signature = "g5List", function(object) object@ndvars)
[1] "ndvars"
> setGeneric("nMach", function(object) standardGeneric("nMach"))
[1] "nMach"
> setMethod("nMach", signature = "g5List", function(object) object@nMach)
[1] "nMach"
> setGeneric("nSet", function(object) standardGeneric("nSet"))
[1] "nSet"
> setMethod("nSet", signature = "g5List", function(object) object@nSet)

```

The task remains of actually analyzing the Guess data, and similar to what was in Section 5.6, chi-square tests will be used for that purpose. Instead of looking at all drawing information the idea is to now work with subsets of the data corresponding to different machines and ball sets. There are obvious ways to proceed in creating the tools for this type of analysis: namely

- an the table function (discussed in Section 5.6) could be created for working with gList objects that could be used directly with the chisq.test function (also discussed in Section 5.6) or-the entire class could be packaged in a suitable version of the chisq.test function. Our approach will take the second path. The other option is the topic of Exercise 6.13.

The first step is to make chisq.test an S4 generic function. This is accomplished with

```
> setGeneric("chisq.test")
> chisq.test
standardGeneric("chisq.test" defined from package "stats"
(x = NULL, correct = TRUE, p = rep(1/length(x)), rescale.p = FALSE, simulate.p.value = FALSE, b = 2000)
Method("chisq.test", environment=0)
```

Methods may be defined for arguments: x, y, correct, rescale.p, simulate.p.value, B
Use Methods("chisq.test") for currently available ones.

The summary information about chisq.test shows that new methods may be created that use the arguments x, y, correct, rescale.p, simulate.p.value and B. A new feature is that the y, correct, rescale.p, simulate.p.value and B all have given default values in the generic function.

The question is which arguments to use in our new method and how to create it. In some respects there is no reason to prefer one over the other (Exercise 6.12). If we want the name of the argument we choose to have some connection to our purpose, correct, rescale.p, simulate.p.value and B are not compelling options. The x in the original chisq.test method is the data to be analyzed and usually a vector or matrix of counts. When applied in the form

```
chisq.test(x, y)
```

the x and y provide pairs of values on two categorical variables for the observations in the data. This is not precisely what we have for our problem. But a bit of imagination suggesting x as a gList object and y as a list of machines and ball sets to be used in the analysis.

The listing below gives an example of how to create a new g5List method function for chisq.test.

```
chisq.g5List <-function(x, y = list(machRange = c("A", "B"),
Range = 1:10), correct, rescale.p, simulate.p.value, B){
objlist <- x@objlist
tempM <- apply(objlist, FUN = function(gobj) gobj@mName)
tempS <- apply(objlist, FUN = function(gobj) gobj@sc)
tempM <- element(temps, y[[1]])
tempS <- element(temps, y[[2]])
indices <- as.logical(tempM*tempS)
newList <- objlist[indices]
ndraw <- as.numeric(length(newList))
temp <- as.numeric(apply(1:ndraw, FUN = function(i) newList[[i]]@data))
chisastat <- 39*chisq.test(x = table(temp))[[1]]/35
```
