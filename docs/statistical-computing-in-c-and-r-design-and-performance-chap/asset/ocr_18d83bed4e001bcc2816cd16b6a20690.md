which goes through the elements in the Server object decrementing the remaining time to serve their current Customer object/or changing their Busy member to false if they have finished their current assignment.

The next task for update is to generate the number of new Customer arrivals. This is accomplished with the method

```
int MMNQueue::rPoisson(){
double sum = rExp(1./lambdaC);
int numberNew = 0;
while (sum < 1){
    numberNew++;
    sum += rExp(1./lambdaC);
}

return numberNew;
}
```

that, in turn, calls

```
double MMNQueue::rExp(double lambda){
double u = 0;
Rng.randif(1, &u);
return (-lambda*log(1. u));
}
```

The latter method uses the ranGen to generate a stream of random numbers from an exponential distribution with its mean lambda. As it is used both to generate the service times for arrivals in the Server objects as well as the number of arrivals from the Poisson distribution. The latter application stems from Algorithm 4.5 which derives from the fact that the waiting times for arrivals in a Poisson process with mean λ are independent and exponentially distributed with mean 1/λ. As a result, generating values from this exponential distribution until their sum exceeds some fixed time t, we have realized a set of arrivals from a Poisson process over the interval [0,t]. The corresponding value for the Poisson random is the penultimate number in the sum.

Once the number of Customer objects is set, there are two possibilities: either the queue is empty or not. If it is empty (determined by the empty method for the priority.queue class), the new customer objects will be assigned to Server objects with Busy value false as long as they are available. The availability or lack of availability is determined by

```
int MMNQueue::freeServer(){
int serverIndex = 0;
while(pS[serverIndex].Busy && serverIndex < nServers)
    serverIndex++;

if(pS[serverIndex].Busy)
    return -1;
else
    return serverIndex;
}
```
