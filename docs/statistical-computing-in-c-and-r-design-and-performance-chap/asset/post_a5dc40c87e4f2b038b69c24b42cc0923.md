Listing 3.4 shows a 2x3 matrix of double precision variables. This does by obtaining a pointer that can hold (i.e., take on) the memory location of a pointer to double. The first loop carries out the allocation of memory to each of the two rows of the matrix. The resulting output from our program confirms what was indicated in the diagram above: that is, pM points to (i.e., holds the address of) the pointer M[0] which, in turn, points to M[0], etc. Specifically, the second for loop demonstrates that memory is laid out contiguous row to row. In general, there is no (or guarantee) that memory locations will be contiguous in our array due to the presence of a gap between the memory blocks for row to row. In fact, there appears to be a gap between the memory and the block for pM[0] and the one that begins at pM[1]. Actually, this is a feature of C++ where an "one-pass-to-the-end" block of memory is always provided for pointer. This additional block of memory can be pointed to but cannot be deferred. Listing 3.4 demonstrates that data stored in pointer-to-pointer format can be manipulated in the same manner as any other array. To assign values to the (i, j)th memory location for the pointer pM use pM[i][j] syntax. The final loop in listing demonstrates how to release the memory for pointer-to-pointer storage. This case is technically unnecessary as all of the memory released automatically when the program terminates. But, in general, many may exist outside of other functions called from main.

The C++ language would be very restrictive if it only allowed for source code to be put in the body of main. We know from Chapter 2 that this is not the case and it is possible to include other functions in our programs. To accomplish this, a prototype or definition of function must be provided prior to the code for main. This can be accomplished by placing the prototype in the same file as main or through use of an #include directive. We will direct attention to the first option for the moment. The general structure of a function has this:

```cpp
returnType functionName(arguments){
    body of function
    return statement
}
```

Here the returnType can be any of the primitive data types. The quantity in the return statement must be of the same type as returnType. The code listing below is for a simple program that can call a square function in the body of main to square the value of some number that is provided as input through the shell interface using the input stream cin introduced in Section 2.3.

Listing 3.5 square.cpp

```cpp
//square.cpp
#include <iostream>

using namespace std;

double square(double x);

int main() {
    double x;
    cout << "Enter a number ";
    cin >> x;
    cout << square(x) << endl;
    return 0;
}

double square(double x) {
    return x*x;
}
```

Notice the prototype that was provided for square prior to its use in main. If this had not been done and the definition of square was also not given prior to main a compiler error would have been generated like something:

```
square.cpp: In function int main() {
square.cpp:10: error: 'square' was not declared in this scope
```

Compilation and -Wall square.cpp produces, e.g.,

```bash
$ g++ -Wall square.cpp -o square
./square
Enter a number 4
16
./square
Enter a number 1.278
1.63328
```

In C/C++ arguments to functions are passed by value. This means that a copy of each argument is created for the function. The function works with the copies with the consequence that the actual values of the arguments cannot be altered. The copying process incurs memory and time. Among others, passing by value restricts what functions can accomplish. References provide objects that behave in most ways as if they were just aliases for the variable.
