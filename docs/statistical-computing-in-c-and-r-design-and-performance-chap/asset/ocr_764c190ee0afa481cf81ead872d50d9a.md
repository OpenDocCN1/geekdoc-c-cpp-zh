Both a warning and error object are generated by our spelling error. The TryCatch function can be used to reduce this by "catching" either of the two conditions and instituting an appropriate fix. A function that does this is given below:

```
readFile <- function(fileName)
  out <- tryCatch(suppressWarnings(fileName),
    error = function(e) {
      print(e)
      print("Please enter a file name followed by a return")
      newName <- scan(, what = character(0), quiet = TRUE)
      readFile(newName))
})
```

Here the use of scan is encapsulated inside tryCatch. The suppressWarnings function has used so that only error (and not warning) objects will be generated when problems are encountered. These will be handled by a function that prints the error object, which asks for and then scan to acquire a new valid name and then iii) attempts to retry using the new name with a recursive call to readFile. The quiet argument for scan is set to TRUE when reading the new file name to suppress the output it would otherwise have given. In the context of the grop.txt this gives the result: named:

Let us consider again the dimnames of the previous section. The dimnames function was apparently used on a matrix A in two forms: to:

> > dimnames (A)

and

> > dimnames (A) <- list(c("C1", "C2"), c("R1", "R2", "R3"))

The first merely returns the list object that contains the dimnames for A without altering the matrix. In contrast, the second actually modifies A by changing the dimnames to the value on the right-hand side of <- operator. This raises two questions: how can one perform two different operations and how a function that supposedly passes values by value, as be expected in a functional language, alters its argument. The answer is that appearances has (possibly) fooled us. First, there are two functions at work: the dimnames function that returns the dimnames list and a replacement function dimnames<- assigns values to the list. The replacement "version" of dimnames then reformulates its operation so that the altered matrix is the output, without input, of a function that thereby preserving the functional language paradigm. The underlying syntax for replacement is the functional form of dimnames that we used

```
A <- "dimnames<-"(A, value = list(c("C1", "C2")
+ c("R1", "R2", "R3"))
```
