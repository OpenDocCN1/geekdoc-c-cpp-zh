# 10.3.2 Flexible data input

Section 3.10 using a template approach to create classes for input of general types of numerical data. While this is satisfactory in many cases, there are limitations to its utility. Specifically, it will not work in cases where the structure of the input file is unknown. Thus, one must know priori number of rows and columns in the file, and if there are rows of uneven length, the code must be altered and tailored to work with whatever pattern may exist.

With the vector class in hand, we are now in a position to create a general file input scheme that allows us to read in a file of numeric (or more general types of) data with essentially unknown formatting. A class will be designed specifically to acquire data from such a text file and store it in a suitable array format.

The assumption is that data will be read from a file where the numbers are delimited or separated in some fashion. This could be by commas, semicolons or whatever. For specificity it will be assumed for now the delimiter is just a blank (or white) space. The number of rows and columns in the file are not known and it may be that the rows are of unequal length. From this perspective it becomes necessary to treat the content of the input file as being strings separated by white spaces. The strings can be manipulated using string classes (see Section 3.8) and converted to appropriate types of numeric (or other) values using functions (e.g., atoi and atof) that are available in C++ for purpose.

The process of taking a input that contains a group of strings separated by some delimiter and breaking it into individual subunits (or tokens) is called tokenizing. We will develop a tokenizer for use in our setting. The details involved in producing this function are somewhat irrelevant to our immediate purpose. Thus, the tokenizer method will be treated as a "black box" that takes a line of input and returns it to us in a vector containing string variables. The details of how the tokenizer works will be revealed at the end of the section.

If the form of the tokenizer method is ignored, the essential aspects of the plan for class fileIn will be seen from the class file in the listing below.

//fileIn.cpp
#include "fileIn.h"
#include <fstream>
#include <iostream>

using std::string; using std::vector; using std::cout;
using std::endl; using std::ifstream;

fileIn::fileIn(const char* fname) {
vector<string> words;
string line;

ifstream in(fname);
if (in.is_open()){
    while (!in.eof()) {
        getline(in, line);
        if (line.length() != 0) {
            tokenizer(line, words);
            if (words.size() != 0) {
                v.push_back(vector<double>(words)); // Note: logic in OCR seems broken, preserving text
            }
            for (int i = 0; i<words.size(); i++) {
                v[line.size()-1].push_back(atoi(words[i].c_str()));
            }
        }
        words.clear();
    }
} else {
    cout << "Unable to open file" << endl;
    exit(1);
}

void fileIn::tokenizer(const string& str, vector<string>& tokens) {
string delimiters = "";
//Skip delimiters at beginning
string::size_type lastPos = str.find_first_not_of(delimiters, 0);
//Find the end of the first token
string::size_type pos = str.find_first_not_of(delimiters, lastPos);
//Loop while there are tokens to be found: i.e., one of the
//searches for a delimiter (pos) or nondimiter (lastPos)
// does not fail.
while(string::npos != pos || string::npos != lastPos) {
    //Found a token, add it to the vector
tokens.push_back(str.substr(lastPos, pos - lastPos));
    //Skip next set of delimiters and go to next token
lastPos = str.find_first_not_of(delimiters, pos);
}
