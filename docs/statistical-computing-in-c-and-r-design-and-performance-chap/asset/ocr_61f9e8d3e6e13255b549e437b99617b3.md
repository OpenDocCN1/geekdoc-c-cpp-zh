The remainder of this section will be focused on illustrating the priority.queue container in the context of a discrete event simulation wherein the activity in some physical system is modeled through a sequence of events that occur, sequentially, over a specified period of time. The setting we will use is that of M/M/n queue i.e., a queue with n servers where there are Poisson customers arriving with rate parameter λ and independent exponential service times with mean λ. The servers and customers are also assumed to operate independently. A similar development using the queue class will be explored in Exercise 10.15.

The basic elements of the model are the customers and servers, and, each will need to be developed in the form of a class. The customer class will be treated first. The declaration is

```
struct Customer{
 int Arrive;
 bool Gold;
Customer(int t = 0, bool gold = 0) : Arrive(t), Gold(gold) {}

 bool operator<(const Customer& x) const;
};
```

There are two members: the customer's arrival Arrival and a Boolean variable Gold. The Arrival class is the member that the Customer object enters the simulation. To simplify matters, time will evolve in discrete (i.e., one minute) intervals and, Arrival will take only on integer values. The Gold class represents the presence or absence of "gold" in the sense associated with car rentals, airlines, etc., where frequent passage can lead to a customer receiving a preferential "gold" level of service. The way that Gold is used is in the definition of a < operator which takes the

```
bool Customer::operator<(const Customer& x) const {
 if (Gold == 0 && x.Gold == 0 ||
 Gold == 1 && x.Gold == 1)
 if (Arrive < x.Arrive));// earlier arrival higher priority
 return false;
 else
 return true;
}

if (Gold == 0 && x.Gold == 1)
 return true;
if (Gold == 1 && x.Gold == 0)
 return false;
}
```

The STL queue is a max queue i.e., elements are partially sorted in descending order determined by the < operator. All things being equal, our overloaded version of this operator has the effect that earlier arrivals get higher priority and, conversely, later arrivals leads to lower priority. On the other hand, a customer with a Gold value is always preferred (i.e., >=) to a customer with Gold equal to false.
