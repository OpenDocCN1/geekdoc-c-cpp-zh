A pair of pointers are defined that move down the list (i.e., toward the tail node) with the fast pointer progressing as fast as its slow counterpart. When the fast pointer reaches the end of the list, signaled by its Next being the null pointer, the slow->Next pointer will be pointing to be viewed as a "middle" node. There is more than here it may seem. The "middle" node that has been located with the algorithm is returned in the function's argument and will then serve as the head of the resulting list. The original list that begins at the head argument split until its current tail and this must be rebuilt before there will actually be two separate lists. Making slow->Next a null pointer merges the original list at a tail node that immediately precedes the "middle" node located by the algorithm.

With arrays the merging process requires the use of temporary storage. However, with linked lists, all that requires is a rearrangement of the next pointers which can be done "in place". For our linkedList class this rearrangement can accomplish with

```
Node linkedList::merge(Node* a, Node* b){

if(a == 0)
  return(b);
else if (b == 0)
  return(a);

if (a->keyValue > b->keyValue){//a is new head node
  head = a;
  head->Next = merge(a->Next, b);
}else{// b is new head node
  head = b;
  head->Next = merge(a, b->Next);
return head;
}
```

The method is in the same spirit as Algorithm 9.6 and the motivating example. The Head pointer for the head node with the larger key becomes the Head pointer for a combined list. The algorithm is then applied again except one of the two lists will be shorter by an element.
