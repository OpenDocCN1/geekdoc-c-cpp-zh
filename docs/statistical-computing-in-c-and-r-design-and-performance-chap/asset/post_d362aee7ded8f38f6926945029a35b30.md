Apart from the template parameters, this is just the push method for the linkedList. It makes no use of iterators as there is no need to perform actions inside the class. In contrast, the Lookup iterator is derived as from

```cpp
template <class Key, class Data> typename LTC<Key, Data>::iterator
    LTC<Key, Data>::lookup(const Key& key) {
    iterator iter(*this);
    while (iter != end()) {
        if (iter->keyValue == key)
            return iter;
        iter++;
    }
    return 0;
    }
```

This has the basic form as the lookup method for the list class. Except now the details explicitly using a pointer to Node to iterate through the list have been encapsulated in an iterator object. The iterator is created with the constructor that takes an LTC object as its argument with the consequence that its current member points to the head node. It is moved through the list via the increment operator until the desired key is located or the end is reached. The keys compared to the target are obtained by dereferencing the iter object.

The insert method for the LTC struct was

```cpp
template <class Key, class Data> typename LTC<Key, Data>::iterator
    LTC<Key, Data>::insert(const Data& data, const Key& key) {
    const Key& key = key;
    if (lookup(key) == end()) //key does not exist
    iterator iter = lookup(key);
    if (iter != end()) {
        Node<Key, Data>* newNode = new Node<Key, Data>(data, key, iter->Next);
        newNode->Next = iter->Next;
        iter->Next = newNode;
    }
    Size++;
}
```

Now let us return to the other iterator: const_iterator. As the name suggests, this class provides iterators that can be used for read-only access to LTC objects. To appreciate the need for this type of iterator consider the nonoperative implementation below of the LTC class constructor.


The solution is to create another iterator class that can access but not alter nodes. Motivated by the analogous STL concept, the class has been named const_iterator.

The basic iterator class methods for comparing and incrementing will work perfectly for our new class. Hence, const_iterator has been made a derived class from class iterator. The changes occur for the dereferencing operators which now take the form

```cpp
template <class Key, class Data> const Node<Key, Data>&
TCKey, Data>::const_iterator::operator*(){
    if(iterator::current != 0)
        return *iterator::current;
}
```

```cpp
template <class Key, class Data> const Node<Key, Data*>
TCKey, Data>::const_iterator::operator->(){
    if(iterator::current != 0)
        return iterator::current;
    else return;
}
```

Both methods have been specified to have const return types which forbids alteration of the data in the underlying object. In addition to these two methods, overloaded versions of the begin and end methods will return const_iterator, rather than iterator, objects namely:

```cpp
template <class Key, class Data> typename LTC<Key, Data>::const_iterator
TCKey, Data>::begin() const {
    return const_iterator(*this);
}
```

```cpp
template <class Key, class Data> typename LTC<Key, Data>::const_iterator
TCKey, Data>::end() const {
    return const_iterator();
}
```
