The basic premise of the previous example is readily extended to produce something useful. For, suppose that the goal is to fill an n-element array held in a pointer pu to double with independent pseudo-random uniforms. A code segment that accomplishes this

```
#pragma omp parallel private(myRank)
{
  myRank = omp_get_thread_num();
  #pragma omp
  for(int i = 0; i < n; i++)
    pu[i] = RArray[myRank].RandU01();
}
```

The computing effort is distributed across np threads with each producing values from a different Rngstream object.
The basic idea behind the previous listing was used to do some performance comparisons that are shown in Table 11.1. The values in the table are the (machine dependent) times that were needed to generate approximately a billion random numbers using one, two, four, and sixteen processors in OpenMP.

Table 11.1 Time required to generate 1 billion random uniforms

| Number of Processors | Time (in seconds) | speedup |
|---|---|--|
| 1 | 130.74750 | 1 |
| 2 | 111.25400 | 1.175261 |
| 4 | 62.95395 | 2.076875 |
| 8 | 37.63115 | 3.476111 |
| 16 | 22.05340 | 5.928678 |

The use of four processors cuts the computation time in half while sixteen processors carry out the work in a sixth of the serial time.
