The present chapter gives a high level overview of ADTs. Our perspective is here much the same as for creating a class declaration in C++. As a case in point, the listing below is the declaration for a pared down version of our Vector class from Chapter 3 and Appendix D.

```
class Vector{
  double* pA;
  int nRows;

public:
  Vector(int nRows, double const* pa);
  Vector(const Vector& v);
  Vector();
  Vector& operator=(const Vector& v);
  double operator[](int i) const {return pA[i];}
};
```

This declaration can be viewed as a contract that guarantees i) Vector objects can be created, ii) a Vector may be assigned to another Vector object and iii) random access using operator[] will be provided to the elements of the underlying array of doubles that is encapsulated by a Vector object.

There is nothing special about using doubles for array elements, as in Exercise 3.31, a template approach can be used to allow them both of int or char, for example. Taking this one step further leads to Vector objects that serves as containers in the sense of being able to hold arbitrary, user-defined types. But, even in this generic form the operations laid out in the Vector declaration make sense and represent at least the minimum one would want from something that provides a generalization of a numeric array; i.e., a generic Vector container class should include functions that

+   a) create a new object,
b) create a copy of an existing Vector object,
c) assign a Vector object to another
d) allow (random) access to the objects in the container.

This list of operations represents a public interface for a Vector class in the same sense as a class declaration.

Our treatment of ADTs in this chapter will be geared towards describing their public interfaces through abstract, somewhat axiomatic "statements" that indicate how the data will be stored and the operations will be expected from the structure. This will be supplemented by pseudo-code implementations of the operations. In this case, specific examples of simple C++ implementations will be provided to illustrate the concept with a (relative) minimum of technical clutter. The R language has certain AD capabilities that will be explored here.
