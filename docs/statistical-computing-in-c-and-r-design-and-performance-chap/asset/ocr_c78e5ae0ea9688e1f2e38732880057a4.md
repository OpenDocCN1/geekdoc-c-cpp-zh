The specifics of our program are system-dependent. An illustration of how this might be accomplished in an interactive mode

```
$ mpixx mpiEx1.cpp -o mpiEx1
$ mpiex -np 5 mpiEx1
Hello ya'll from processor 4 of 5
Hello ya'll from processor 2 of 5
Hello ya'll from processor 0 of 5
Hello ya'll from processor 1 of 5
Hello ya'll from processor 3 of 5
```

The syntax mpixx (on the cluster where this code was compiled) invokes a C++ compiler for MPI programs. The executable mpiEx that is run using mpiex command with the -np 5 option requesting five processors are used to perform the computations. Notice the processors do not finish in order is not surprising as they are working independently.

In practice the set of commands that were used here to compile and run mpiEx.cpp may or not be appropriate for a given system using MPI. In some cases a single node can be obtained on a cluster that will allow for an interactive session and it is not difficult to install one of the MPI implementations such as Open MPI on a desktop machine for interactive use. But, both of these options enable MPI in shared memory environments which is not really its purpose. The power and utility of MPI is best in distributed-memory, high-performance computing systems. In such systems job submission will generally take place in batch mode using job scripts that can take various forms depending on the software that is being used to manage job scheduling. The details involved can usually be obtained from the computing center that manages the cluster of.

Our mpiEx.cpp program is not necessarily interesting for several reasons. With a parallel perspective it is short in that that there is no interaction between processors. Inter-processor communication is useful for those frequently employed for parallel programming. The simplest way to communicate between processors is through the Send and Recv (an abbreviation for receive) methods. The methods of these functions are

```
void MPI::COMM_WORLD.Send(void* buf, int count, MPI_Datatype datatype,
int dest, int tag, MPI_Comm comm)
```

```
void MPI::COMM_WORLD.Recv(void* buf, int count, MPI_Datatype datatype,
int source, int tag, MPI_Comm comm)
```

The first argument for both of functions is a pointer to value. This is just a way of passing generic data in and out of the functions. The count buff appears in both the Send and Recv functions. The data is what is being sent by Send and received by Recv. The (third) datatype argument is used to describe the contents of buff as in some C++ data type that is recognized by MPI. Such data types include all the common ones in C++ as well as those that are defined. The latter option will not be offered. For our purposes it is enough to know that, for example, MPI::CHAR, MPI::INT, MPI::LONG, MPI::UNSIGNED_LONG, MPI::FLOAT, MPI::DOUBLE, MPI::LONG_DOUBLE and MPI::BOOL correspond to C++ primitive data types, int, unsigned long, float, double and bool, respectively.

The (second) count argument to the Send and Recv specifies how many of datatype values are being sent or received. The count arguments do not need to match for a send and receive. But, the receive count must be at least as large as what has been seen in order to avoid an error. The comm argument is the communicator object that is managing the inter-node communication and will always be COMM_WORLD for our applications.
