A comparison of this with the while loop of our pointer arithmetic reveals a certain similarity. They are, in fact, conceptually the same. null pointer representing and iter = iter->Next performing the function of traversing and accessing a collection of objects; both pointer arithmetic example and lookup function solutions to the more general problem of traversing and accessing objects of type. The iterator (sometimes called cursor) has developed as a standardized approach to navigation of ADTs. An iterator is an abstract, generic analog of a pointer. The generic part of this design manifests as a "guaranteed" set of operations provided by any iterator class:

- a postfix increment operator that advances the iterator to the next object
- a dereferencing operator that returns the current object being pointed to
- a logical operator that allows for comparison of two iterator objects

The details behind the implementation of iterators for various ADTs will, of course, be different. Nonetheless, the user can expect these basic operations to be provided and, in sense, familiar with the structure of the underlying ADT in order to explore its contents. In many cases iterators possess other pointer-like operations such as -- (to move the iterator to the previous object) or -> to access an object. For a singly list the decrement operator becomes problematic since nodes only move from the head to the tail of the list. However, both ++ and -- are options if the list is doubly linked so that connections to both the next and preceding node exist.

## 9.5.2 A linked list class

Iterators require close connection to the ADT. In particular, there are two ways to create such a connection: a friend relationship between the iterator and ADT class or having the iterator nested within the ADT class. We will take the latter approach here since it allows us to touch on new topic (i.e., nested classes) and coincides with the way C++ container classes treated in the next chapter. To illustrate the construction of a nested iterator class we will again work with a singly list class. The first step is to give the Node class structure. This is accomplished in the listing below

```cpp
template <class Key, class Data>
struct Node {
    Data dataValue;
    Key keyValue;
    Node* Next;

    Node() {}
    Node(Data data, Key key, Node* next = 0)
        : dataValue(data), keyValue(key), Next(next) {};
};
```

This is very similar to the definition of the Node struct from Section 9.2.2. The only change is that the int types for the key and data have been replaced by generic template parameters Key and Data. The declaration for our linked list class LTC is given in Listing 9.7.

Listing 9.7 LTC.h
```cpp
template <class Key, class Data>
struct LTC {

    Node<Key, Data>* Head;
    int Size;

    LTC(){Head = 0};
    LTC(const LTC<Key, Data>& L);
    ~LTC();
    LTC<Key, Data>& operator=(const LTC<Key, Data>& L);

    //nested iterator class
    struct iterator {

        Node<Key, Data>* current = 0;
        iterator(const LTC<Key, Data>& L) : current (L.Head) {}

        Node<Key, Data>* operator*();
        Node<Key, Data>* operator->();
        iterator& operator=(const iterator& iter);
        bool operator==(const iterator& iter) const;
        bool operator!=(const iterator& iter) const;
        iterator operator++();
        iterator operator++(int){return operator++(int);}
    };

    struct const_iterator : public iterator{
        const_iterator(Node<Key, Data>* node = 0) : iterator(node) {}
        const_iterator(const LTC<Key, Data>& L) : iterator(L) {}

        const Node<Key, Data>& operator*();
        const Node<Key, Data>* operator->() const;
        const_iterator& operator=(const const_iterator& iter);
    };

    iterator begin();
    iterator end();
    const_iterator begin() const;
    const_iterator end() const;

    void push(const Data& newData, const Key& newKey);
    iterator lookUp(const Key& key);
    iterator insert(const Data& newData, const Key& newKey, const Key& key);
};
```

It looks like there are many new features here and that is certainly the case. But, a comparison between 9.7 and 9.2 reveals that this new class is not far removed conceptually from the linkedList of Section 9.2. To be more specific, if the internal iterators and the begin and end methods are ignored, the two classes have the same basic elements and methods with the same number (if not type) of arguments. As with the Node struct, the changes required to adapt the LTC class from linked template parameters to allow for indexing and storing objects of general types.

Let us begin the discussion of 9.7 by examining the internal iterators. The fact that iterator is nested in the class means the scope resolution operator must be used twice; e.g., LTC::iterator. Note that the typename keyword indicates that the return type is an iterator object where the identity is contained in the class. In such cases the typename keyword tells the compiler that LTC<Key, Data> is, in fact, a class (e.g., Vandervoorde and Josutti 2003). The same consideration applies to the assignment operator whose definition is

```cpp
template <class Key, class Data>
typename LTC<Key, Data>::iterator& operator=(const iterator& iter) {
    current = iter.current;
    return *this;
}
```

The == operator invokes a straightforward comparison of the current member pointers of two iterator objects. Seeing that != is the logical complement of ==, the latter operator can be obtained directly from the former. Note that the typename keyword does not appear in either return type because bool is already a recognized data type. Finally, the dereferencing operators are defined as

```cpp
template <class Key, class Data>
Node< Data>& LTC<Key, Data>::iterator::operator*() {
    if (current != 0)
    return *current;
}
```

```cpp
template <class Key, class Data>
Node<Key, Data>* LTC<Key, Data>::iterator::operator->() {
    if(current != 0)
    return current;
    else return 0;
}
```

If the "cursor" is not at the end of the list, the object pointed to by the current pointer is returned as either a pointer or reference to Node.
