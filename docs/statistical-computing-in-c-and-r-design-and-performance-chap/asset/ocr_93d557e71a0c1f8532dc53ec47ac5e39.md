Eventually we will create a function that can sort a collection of g5 objects. The critical ingredient in accomplishing this is having order relationships that allow us to compare g5 object to another. For our purposes the result will be in terms of drawDate slot that will produce a chronologically sorted arrangement. Rather define ==, <=, etc., individually is possible to define all operators simultaneously with a slight modification of our previous approach for defining methods. The difference is that now the method functions will be defined for a group or collection of functions named Compare in this. Other group generics include those with Arith, Logic, Math and Summary as described on the R page for S4groupGeneric. For Compare the help page describes the functions in the group having the basic form

```
Compare(e1, e2)
```

Thus, they are all functions with two arguments e1 and e2. All of them can be extended to the g5 class using

```
> setMethod("Compare", e1 = "g5", e2 = "g5")
+ function(e1, e2) callGeneric(e1@drawDate, e2@drawDate)
[1] "Compare"
```

The callGeneric that appears here is for method dispatch; it will call the current generic function that is appropriate for the Date class objects e1@drawDate and e2@drawDate in instance. This will be sufficient because all the functions in the Compare generic have methods that apply to the Date class as indicated in the R help page gives results as

```
> g50bj1 > g50bj2
[1] FALSE
> g50bj1 < g50bj2
[1] TRUE
> g50bj1 == g50bj2
[1] FALSE
> g50bj1 <= g50bj2
[1] TRUE
```

The fact that for g50bj1 (i.e., 1952-01-17) is earlier than the date for g50bj2 (i.e., 1952-01-21) shows that the comparator operators are working correctly.
