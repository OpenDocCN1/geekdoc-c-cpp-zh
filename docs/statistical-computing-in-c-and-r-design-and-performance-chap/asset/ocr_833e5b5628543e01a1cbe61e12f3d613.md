In such a case, the syntax `algorithm(beginName` will look like

These latter differ from the previous two only in terms of the addition of a function object or functor (e.g., Section 8.2) that provides the tool to be used in processing the elements of the source container. Not function object will do and, as was the case for iterators, functions need to inherit from an STL class. The possibilities in this case are `unary_function` and `binary_function`.

To illustrate some of the basic ideas, we will use the g5Array class of Section 10.3.3. Our goal will be to create three methods for the class that are all implemented using methodology from the library algorithm. The methods that we will create are one that will look up results for a specified date, the g5 objects in the container by the date of their drawings and compute a chi-square statistic.

```
std::vector<g5> g5Array::sort() {
std::vector<g5> sort(ndArray);
std::copy(this->begin(), this->end(), sort.begin());
g5Less f;
std::sort(sort.begin(), sort.end(), f);

return sort;
}
```

This method uses two algorithms: `sort` and `copy`. There are three main sorting methods in the algorithm library: `sort`, `partial_sort` and `stable_sort`. The sort method is akin to quicksort while partial and stable are merges. All of these require random access iterators which means we must first transfer the elements of the g5Array object to, e.g., a vector object. This object will need to have `ndArray` slots. Once it is created, the `begin()` and `end()` iterators of the g5 iterator for the vector object gives the beginning of the range where the data is to be replicated.

Once all the g5 objects on the g5Array object are in the vector format, they are ready for sorting. But, sorting requires specifying a method for comparison. This can be done by overloading the comparison operator `<` (as in Section 10.5) or by providing an explicit function object to be used in comparisons. We will take the latter route.
