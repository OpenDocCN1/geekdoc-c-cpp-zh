# 10.3.1 Streaming data

In applications that require the analysis of huge data sets it may be impractical to store
the data in memory or even any portion of it multiple times. The streaming model
of computation assumes that data arrive in a stream of observations. Depending on the
particular application, each observation may consist of several attributes. The program
 perform any computation on each individual observation immediately. The standard
assumptions are that

+   - the size of the data set is too large to store and
- the diversity of the attributes or keys precludes the use of counters to tabulate the
frequencies of their individual values.

Muthukrishnan (2005) gives an introduction to data streaming models, applications and
results from an algorithmic standpoint. Aggrawal (2007) contains a collection of surveys
that are oriented toward data mining applications.
Cormode and Muthrishnan (2005) propose a simple but effective ADT called count-min
sketch can be used to answer questions about the distribution of variables in a streaming
data structure. This structure contains $d \times w$ array $B$ of nonnegative integers $B[i,j]$, with probability $1 \leq i \leq d, 1 \leq w$ that hold estimates of the frequency of the occurrence of the
variable. The row and column dimensions of $B$ correspond to $d$ hash functions $h_1, \dots, h_d
that map $\{1, \dots, m\}$ into $\{1, \dots, w\}$. The integers represent the set of attributes,
discretized or grouped values; for example, when a key/attribute is continuous and round into a finite number of
groups with some desired precision. In practice, the discretization need not produce integer
values; but, there is no loss in assuming that to be the case. The $d$ hash functions are
chosen uniformly from a random independent hash family.

The elements of $B$ are all initialized to zero and then updated as the data arrive.
Specifically, if a key value $k$ is found to occur in the stream, $B[h_j(k)]$, $j = 1, \dots, d$ will
be incremented by one. At any point in time, an estimate of the frequency of that key

```
$\tilde{n}_k = \min B[h_j(k)].$
```

Let $n_k$ denote the number of observations with the key $k$ that have been observed in
t first N elements from a data stream. An indication of the performance of the count-min
sketch data structure is proven by Theorem 10.1.

**Theorem 10.1.** For $\epsilon, \delta > 0$ let $w = [\e/\epsilon]$ and $d = [\ln(1/\delta)]$. Then, $n_k \leq \tilde{n}_k$ and
Prob(${n_k \leq n_k + \epsilon N$) $\geq 1 - \delta$.

The sketch overestimates its target, and with probability at least
$1 - \delta$, exceeds it by no more than $\epsilon N$. While the parameters $\delta$ and $\epsilon$ in Theorem 10.1
can be arbitrary, they will have fundamental consequences for the size of the
uring data structure.
