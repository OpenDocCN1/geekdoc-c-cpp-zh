With and without a certain term have been obtained. To determine whether is preferable the regr class could be expanded to include measures of lack-of-fit (Exercise 6.2). It is usually good practice to provide checks that an object has been constructed in the proper way. This will be taken care of automatically for slots that from specified classes like matrix. So, in the case of the regr class, a matrix must be supplied for the X slot when calling new or an error will occur. But, there are no further checks carried out to ensure any form of consistency or that the calculations be carried out inside the constructor are actually possible.

One feature that would be expected for an object of type regr is that both the X and y arrays have the same number of rows. The nrow function for class allows us to carry out comparisons of this nature. Also, in order to work, the matrix X (or X augmented by a unit column vector) must have full rank. To check this condition the R function qr can be used. This function returns a list with a named rank the rank of the matrix supplied with the argument. We well to use the qr function in Section 7.5.

To make sure that the input data is appropriate for an object from a user-created class one can use the setValidity function. The code below employs this function to check the row length of the X and y slots as well as the appropriate

```
setValidity("regr", object){
  if(nrow(object@) != length(object)){n    return("The number of rows for X and y differ")
  }
  if(object@intercept{
    if(qr(bind(1,object@))$rank < (ncol(object@) + 1)){
      return("The matrix of predictors is singular")
    }
  } else{
    if(qr(object@)$rank < ncol(object@)){
      return("The matrix of predictors is singular")
    }
  }
  return(TRUE)
}
```
