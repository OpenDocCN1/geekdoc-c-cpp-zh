Flaming (1995) describes a good hash function for strings as

> "a magic formula that hashes, mixes, and slices the input character string, using just a few statements".

There are numerous hash functions that can be categorized in this way of which some have been found to perform well in practice. One of those that has received good reviews in the public domain Fowler/No or FNV hash function that will be used as the base for our hash function family. The resulting method for the CMS class is defined in the next listing.

```
int CMS::fnvHash(int i, string key){
ununsigned int h = 2166136261;
for (unsigned int j = 0; j < key.length(); j++) {
  h = (h*16777619) ^ key[j];
}
return (a[i]*h + W) % W;
```

The method argues two things: the string variable key that is to be hashed and an integer that specifies one of the D hash functions to use for hashing the key.
The body of the method is an implementation of FNV which is straightforward; it produces a hash value that is combined with the appropriate coefficients from the a and b arrays (as determined by the in argument) to create the actual hash value that is returned by the method. The FNV method performs on a key as straightforward (e.g., Exercise 2.4) a hash value (2166136261) is sequentially multiplied by a constant (16777619) with a exclusive XOR operation (or addition) used to create the result with each element of the key value. The process of breaking the key into parts (i.e., key[0], ..., key.length() - 1) in this case and then combining the values via exclusive OR operations (or addition, multiplication, etc.) is called folding and is one of the standard methods used in creating hash functions for strings (see, e.g., Chapter 13 of Budd 1994 or Chapter 10 of Drozdek 2005).

When the compiler encounters another long (any integer like 2166136261 (prior to assigning it to h)) in the fnvHash function, it must decide on a storage type. There are differences between how compilers (from different versions of a standard) handle this and many warnings may be generated as a result. One way is to give the compiler a hand by stating what the storage size should be. This is accomplished by adding a suffix to the numeric value. For integers the U and L for unsigned and long, respectively. In combination (as used in the fnvHash function) signify that the content is of unsigned long.
