The iterator (sometimes called a cursor) has developed as a standardized approach to navigation of ADTs. An iterator is an abstract, generic analog of a pointer. The generic part of this design manifests as a "guaranteed" set of operations provided by any iterator class::

+   * a postfix increment operator that advances the iterator to the next object in the ADT,
* a dereferencing operator that returns the current object being "pointed to" by the iterator and
* != a logical operator that allows for the comparison of two iterator objects.

The details behind the implementation of iterators for various ADTs will, of course, (possibly very) different. Nonetheless, the user can expect these three basic operations to be provided and, in sense, not be familiar with the structure of the underlying ADT in order to explore and access its contents.

In many cases iterators possess other pointer-like operations such as -- (to move the iterator to the previous object) or -> to access an object or aspect of an. Because iterators are ADT specific, the operations they will and can are determined by their ADT. For example, in a singly linked list the decrement operator becomes problematic since nodes only moves from the head to the tail of the list. However, both ++ and -- are options if the list is doubly linked so that connections to both the next and preceding node in the list.
