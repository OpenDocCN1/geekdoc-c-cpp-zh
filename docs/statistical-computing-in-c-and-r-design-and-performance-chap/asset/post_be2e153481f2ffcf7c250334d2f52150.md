To illustrate the use of mle, consider the function

```r
lfunc <- function(theta, xbar, n) -n*log(theta) + n*xbar*theta)
```

This evaluates the negative log-likelihood for an exponential distribution given the sample size n and the sample mean xbar. For optimization purposes, the values of n and xbar must be fixed and the fixed argument for mle can be used to handle this. The listing below demonstrates this with the same data that was used with our like class.

```r
> set.seed(123)
> x0 <- rep(100, 1)
> library("stats")
> mle(lfunc, start = list(theta = .5), fixed = list(xbar = mean(x0),
+ n = length(x0)))
```

# 8.6 Random search

Deterministic optimization methods such as the golden section and Newton's method provide practical alternatives to a global search strategy for finding the global minimizer of a function f. However, they are limited by their requirement of a good initial search location. The use of random number generators to find such locations can be quite effective. This raises the question of why use deterministic methods at all? Not simply search the entire optimization region with a sequence of random numbers? There are many methods that do precisely this. An overview of this area is provided by Spall (2003).

The simplest strategy is a blind search method where one simulates in the region of interest until, e.g., a suitable approximation to the minimizer has found. Spall (2003) shows that, under weak restrictions on f, the resulting sequence of approximate minimizers converge to the global minimizer with probability one. The approach is summarized formally in Algorithm 8.3 that requires a choice for the iteration counter parameters maxit.

# Algorithm 8.3 Blind random search

```r
iter <- 0
Generate minTemp uniformly distributed on [a, b]
while iter < maxit do
  Generate U uniformly distributed on [a, b]
  if f(U) < f(minTemp) then
    minTemp = U
  end if
  iter <- iter + 1
end while
return minTemp
```

The ranSearch method below was added to Listing 8.8 directly implements Algorithm 8.3 using a ranGen object from Appendix E.

# RANDOM SEARCH

```cpp
double Optim::ranSearch(Functor& f, double a, double b,
  unsigned long seed) const {
  double minTemp, U;
  int niter = 0;
  ranGen RNG;
  RNG.setSeed(seed);
  double* pu = new double;
  RNG.ranUnif(1, pu);
  minTemp = a + (b - a)*(pu);
  while(niter < itMax) {
    RNG.ranUnif(1, pu);
    U = a + (b - a)**(pu);
    if (f(U) < f(minTemp))
      minTemp = U;
    niter++;
  }
  delete pu;
  return minTemp;
}
```

Simulated annealing is a blind search that attempts to move more quickly toward the minimum using an accept-reject strategy. Values that decrease the objective function are always accepted; the kth step value $\theta$ that increases the objective function will be accepted with probability $p = \exp\{(f(\theta^{(k-1)}) - f(\theta))/T_k\}$, where $\theta^{(k-1)}$ is the value from the previous iteration and $T_k$ is a decreasing sequence of values that increase the objective function will occur with decreasing probability while the accept-reject scheme allows movements to escape local minima in the early stages of the search. Simulated annealing produces a sequence that will converge with probability one to the global minimizer assuming, continuity of the objective function (e.g., Béisle 1992 and Spall 2003).

Simulated annealing relies on user choices for the cooling schedule, the maximum number of iterations (itMax) and a parameter $d$ that governs the size of the step to take away from the current approximation to the minimizer. A pseudo-code summary of the method is provided in Algorithm 8.4.

# Algorithm 8.4 Simulated annealing

```r
niter = 0, generate minTemp uniformly on [a, b]
while niter < itMax do
  Generate U uniformly on [max(minTemp - d), min(minTemp + d)]
  if f(U) < f(minTemp)
    minTemp = U
  else
    p = exp((f(minTemp) - f(U))/Titer)
    Generate V uniformly distributed on [0, 1]
    if V < p then
      minTemp = U
  end
  niter = niter + 1
end
return minTemp
```

A "class view" on the type of outcome would be to conclude that all methods are capable of producing solutions that in the neighborhood of the global optimizer. Further experience with this particular example suggests that simulated annealing is the most sensitive to the choice of its tuning parameters, and in respect, the other methods are more reliable. Part of this is undetected due to the details of our implementation. However, in a general sense, it should be pointed out that simulated annealing is really more relevant for high-dimensional solutions with possibly nonsmooth objective functions. In contrast, blind search is not a viable option and the golden section becomes intractable. In Section 8.4 the R function has simulated annealing that comes available through the method of "SANN". The cooling schedule is used by optim is $T_k = inf/(k-1)$ where temp is the starting temperature for the cooling schedule (which defaults to 10) and max is the number of function evaluations that are allowed at each temperature (and also defaults to 10). The values of temp and max are set by the control argument for optim that must be given as a list that lists the parameter values by name. Another parameter for optim is maxit that sets the maximum number of iterations. It is also set using the control argument and defaults to 100 for the derivative-based methods and 10,000 for SANN.
