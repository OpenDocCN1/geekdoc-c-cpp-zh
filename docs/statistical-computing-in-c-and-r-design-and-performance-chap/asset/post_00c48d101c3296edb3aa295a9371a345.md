Thus, (random) access to the contents of a known memory location can be obtained in constant time. The same is true of appending a new entry to the end of a dArray object, except for the case when the object is already full. Specifically, our definition for the append method is:

```
void dArray::append(int value){
  if (Size < containerSize){
    p[Size] = value;
    Size++;
  }
  else{
    resize();
    p[Size] = value;
    Size++;
  }
}
```

The location of the last object in the array is always available through the value of the member variable `Size`; i.e., it has index `Size - 1`. Provided an open memory location exists, the append operation requires constant time. Otherwise, the resize function must be called before the new int object can be created.

While arrays are good for accessing and appending new elements, the insertion operation can be quite slow depending on where a new data object must be placed. Algorithm 9.1 describes the process for inserting a new entry into the kth slot of an n-element array with existing entries $A[1],....A[m]$ for $m < n$.

# Algorithm 9.1 insert(k, a): Insert a new array entry

```
tempLow = A[k]
A[k] = a
for j = k to m - 1 do
  tempUp = A[j+1]
  A[j+1] = tempLow
  tempLow = tempUp
end
A[m+1] = tempLow
```

The time needed to accomplish insertion is therefore dependent on the location where insertion is to take place, with the average time complexity being proportional to the number of elements in storage.

Our insert method for class dArray below uses a variation of Algorithm 9.1.

```
void dArray::insert(int k, int value){
  if (k > Size){
    std::cout << "This is not a valid index!" << std::endl;
    exit(1);
  }

  if (Size == containerSize){
    resize();
    Size++;
  }
  for (int j = Size; j > k; j--)
    p[j] = p[j-1];
  }
  p[k] = value;
}
```

# ADT DICTIONARY

The modification of Algorithm 9.1 is that resize is called when the array becomes full to accommodate another stored entry. The other is the way the start elements of the array are shifted. The first value of Size is augmented. This allows us to start at the slot with index `Size - 1` and work our backward while shifting each entry by one array. An advantage of this approach is that it avoids the temporary storage.

The other side of insertion is deletion. It may be of interest to remove elements from a dArray object and, if Size becomes sufficiently small after a number of deletions, resizing may be of value as a means of conserving memory. It is necessary to sort the elements in a numeric method to obtain, e.g., statistics of interest. We have seen examples of a sorting method in the bubblesort Algorithm 3.1 and the selection sort method of Section 6.4. These sorting schemes are slow and require an order of $n^2$ operations on average to sort an n-element array. A better option is the quicksort algorithm that requires an average of $O(n \log n)$ operations to order the elements.

The idea behind quicksort is simple: recursively split the unsorted array into two parts; the easiest way to achieve this is to ensure that each value in the first part is no greater than in the second part. This is perhaps illustrated with our example as a guideline, Algorithm 9.2 provides a formulation of the procedure.

# Algorithm 9.2 quickSort(A, left, right): Sort array elements A[left],...,A[right]

```
low = left, pivotIndex = (left + right)/2, pivot = A[pivotIndex], high = right
while low <= high
  while pivot > A[low]
    low = low + 1
  while A[high] > pivot
    high = high - 1
  if low <= high
    temp = A[low], A[low] = A[high], A[high] = temp
    low = low + 1, high = high - 1
  if low < right
    quickSort(A, left, right)
  if left < low - 1
    quickSort(A, left, low - 1)
```

The algorithm starts with low and high as the left-most and right-most indices, respectively, and takes the pivot to be the value of the entry in the "middle" array. It then moves the low index across the array until it encounters an element whose value is greater than or equal to the pivot; otherwise, the array elements are swapped. A recursive call can then be made using this subarray as the argument. Similarly, the values in the subarray constructed from elements less than low will be smaller than the pivot and the quickSort function can be applied. The average running time for quicksort is proportional to $n \log n$ for an n-element array. To assume $n=2^k$ for some integer $k$ and the pivot falls at the center of the array in each step of the recursion, the first partitioning will produce two arrays of size $2^{k-1}$. These two arrays, in turn, each need $O(2^{k-1})$ operations to produce subarrays of size $2^{k-2}$, which will require a total of $n$ operations to advance to the next stage of the recursion. This remains true at every step in the recursion which means the overall effort is on the order of $n \log n$. It may be proved that, assuming the initial order of elements in the array is random (regardless of what the elements are), the expected number of comparisons in quicksort is $O(n \log n)$.

On the other hand, the worst case in running time for quicksort occurs when the partitioning always produces a subarray of size one. If this happens, this gives $n(n+1)/2$ operations; i.e., the method requires $O(n^2)$ operations. Note that this is an impossible event; it is exactly what happens if the pivot is selected from the beginning (or the end) of a sorted array. Somewhat paradoxically, we see that the hard cases for quicksort are those where the array elements are already ordered or partially ordered.

The methods swap and quicksort provide an implementation of the quicksort algorithm for our dArray class. The swap method is a utility that is used by the quickSort method. Thus, we made it a member of the dArray class while quickSort was made public. The int variables in swap designate the elements that are to be swapped in the dArray object while the left and right arguments for quickSort specify the index subrange on which the algorithm will be applied.

The definition of swap method is:

```cpp
void dArray::swap(int i, int j){
  int temp = pa[i]; pa[i] = pa[j]; pa[j] = temp;
}
```

Temporary storage is used to hold the value of one array element while it is written after which the remaining component is replaced with the stored value. The implementation of the quicksort algorithm then takes the form:

```cpp
void dArray::quicksort(int left, int right){
  int pivotIndex = floor((left + right)/2);
  int pivot = pa[pivotIndex];
  int low = left, high = right;
  while(low >= high){
    while(pivot > pa[low])
      low++;
    while(pa[high] > pivot)
      high--;
    if(low <= high){
      swap(low, high);
      low++; high--;
    }
  }
  if(left < low - 1)
    quicksort(left, low - 1);
  if(low < right)
    quicksort(low, right);
}
```
