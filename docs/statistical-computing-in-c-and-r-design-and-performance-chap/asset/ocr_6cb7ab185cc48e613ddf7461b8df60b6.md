# # Creating classes and methods in R

# ## 6.1 Introduction

The previous chapter focused on developing applications that worked with existing R classes. This chapter describes how new R classes and methods can be created for dealing with data analysis problems that require a more customized approach.

It is possible to create classes in R with member elements that in most ways are consistent with the C++ paradigm. However, the primary focus in R is on functions rather than classes. To expand on this last statement, `ObjA` is an object from a C++ class `A`. A method `func` for class `A` would be invoked via syntax resembling `ObjA$func` apart from any arguments that would be needed for the method. If `ObjB` is an object from another class `B`, the expression of the form `ObjB$func` need not have any meaning, and if so, there is no need for the method `func` to perform similar or related operations for objects from class `A` or `B`. The R version of OOP reverses the role of function and object compared to the C++ treatment. Classes do not have member elements. Instead, functions are a class in their own right and specific functions have "methods" that provide implementation of the function for different types of objects. Thus, if `func` is an R function, it may have methods with exactly the same name that would be applicable to perform properly on the objects `ObjA` and `ObjB` from classes `A` and `B`, respectively. The correct version or method function of `func` for an object (or objects) supplied as an argument (or arguments) is determined by the class of the argument (or arguments) through a process `method dispatch`.

The functions in R can (and often are) generic in a sense that is analogous to the use of template function in C++. A template function is not tied to any particular class, and at least in terms of syntax, expressions of the form `func(ObjA)` and `func(ObjB)` for `ObjA` and `ObjB` from entirely different classes `A` and `B` are conceptually valid, if not not necessarily meaningful from a practical perspective. When means are called to call `func(ObjA)` and `func(ObjB)`, the generic spirit that underlies template function creation would lead us to expect that the specializations of `func` to class `A` and `B` will perform similar operations on the objects of each class. For example, template functions `print` or `plot` would be expected to perform analogous procedures across objects from different classes. With this in mind, generic functions in R might be viewed as a collection of template functions that carry out similar operations on a variety of R classes.

There are two class systems in R that are referred to as S3 (or "old style") classes (e.g., Chapter 4 of Venables and Ripley 2000 and Chapter 3 of Gentleman) and S4 (or "new style") classes (e.g., Chapters 7-8 of Chambers 1998, Chapter 5 of Venables and Ripley 2000 and Chapter 3 of Gentleman). The S3 class concept is essentially a naming convention that is employed, for example, in method dispatch. In contrast, the S4 class system allows for the creation of objects with member elements and other features that would be expected from an object-oriented language. Accordingly, our attention will be focused on the S4 framework which represents the subject of the next section.
