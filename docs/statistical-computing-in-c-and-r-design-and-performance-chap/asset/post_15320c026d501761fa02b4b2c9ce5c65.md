A similar outcome will be obtained from naive use of the assignment = operator in

```cpp//equalEx.cpp
#include "simpleMatrix.h"
#include <iostream>

using std::cout; using std::endl;

    Matrix m1(1., 2, 2);
    Matrix m2;

}
```

Specifically, either of these two programs produces run-time errors that output a statement such as

```
The destructor will now be called
equalEx(17): malloc: error for object 0x10009
pointer being freed was not allocated
breakpoint in debug
```

This message is about a problem related to memory allocation that lies under the hood of the C++ new operator. The problem may arise from an attempt to delete a pointer (using the C function free) that has not actually been allocated. That is precisely what occurred.

To understand what has transpired we need to think about when a destructor occurs when an object goes out of scope: i.e., when the end of a block of code is reached. For the first program a copy of the Matrix object is created to pass by value to function g. It then goes out of scope when control passes back to main and the destructor deletes the memory associated with the class. But, since the copy was made element-by-element, the memory pointed to by pa (i.e., the pa in main) is what is actually deleted. When m goes out of scope at the end of main the destructor is called again and deletes the memory that no longer points to.

A similar problem arises for the second driver equalEx.cpp. In this latter the behavior is to make an element-by-element copy m2 of the Matrix object when m2 is equal to m1. At the end of main the destructor for m2 is created also by deleting the memory allocated to m1. When an attempt is made to delete this memory, for the object m1, an error occurs.

The above discussion makes explicitly: namely, when dynamic memory is involved two things must be a copy constructor and an overloaded version of assignment operator. Let us first deal with the issue of creating a copy constructor.

To handle the problem using assignment in class Matrix the solution is to define an overloaded version of the = operator along the lines of definitions in Section 3.8.3. An overloaded = operator for our matrix class will have the form Matrix& operator=(const Matrix& A);

Here, more or general, assignment operators need to return a reference to allow for composite expressions that use assignment in other function calls. The definition for the assignment operator might look something like

```cpp
Matrix::operator=(const Matrix& A){
    if(this == &A) // avoid self assignment
        return *this;
    // if dimensions match we can copy overwrite, otherwise...
    if(nRows != A.nRows||nCols != A.nCols){
        if(pA != nullptr) // check first before releasing memory
            ~Matrix();

        // redefine object's members
        nRows = A.nRows;
        Cols = A.nCols;
        pA = new(std::nothrow) double*[nRows];
        pointerCheck();

        for(int i = 0; i < nRows; i++) {
            pA[i] = new(std::nothrow) double[nCols];
            pointerCheck(i);
        }
    }
}
```

If memory has already been allocated for that object's pa there are two possibilities: either the dimensions of the matrices are the same or are not We can simply overwrite the existing memory. A final possibility that can arise in this instance is that the left-hand side object was created with the default constructor in which case there is no memory to release.
