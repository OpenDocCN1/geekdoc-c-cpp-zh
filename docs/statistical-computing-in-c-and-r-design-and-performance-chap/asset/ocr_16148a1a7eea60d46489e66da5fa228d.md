To effectively handle problems of practical interest an output class should be constructed. An object from the class could then be used to write an to a specified file. The methods that might be created or object construction would depend on the data type for the array. This would require different methods to handle integer and floating-point data, for that would be done conveniently if we could create a generic data type that would allow arrays constructed from, e.g., any of the primitive types to be written to files with only a single method. This can be accomplished using a class template and that the solution will be developed.\nThe syntax for creating a template class looks like

```
template<class T> class className{\n    member declarations and method prototypes
};
```

Here T represents a "word of card" for sorts that must be specified by the calling program. In the general context of template classes T could be any data type including one that was created. For statistical purposes T will most be one of the primitive types such as char, int, float, etc., and there is no harm in viewing it from that perspective throughout this section.\nThe declarations for methods and well as specification of public and private class templates are exactly the same as for the non-template case. To specify method definitions outside the class declaration

```
template<class T> returnType className<T>::methodName(arguments{
    body of method
};
```

There is a caveat here; the method definitions must reside in the same file as the class declaration.\Previously class declarations have been physically separated from the method definitions in header and cpp files. The cpp files were then compiled into object files that were linked at the end to produce an executable. The problem with this approach for templates is the generic T is used as a place holder for the actual data type that will be substituted for T to produce a specific object. The class has no way to allocate storage for when an object file is created without an actual data type being specified. This is done only when a specific choice is made for T when the compiler essentially goes through both the source (i.e., cpp file) code and definitions for the class (that resides in the header) and substitutes in the "value" for T. However, if the cpp file compiled separately the compiler does not have it assumes that for all the methods with the necessary "values" for T will exist as in precompiled object files.
