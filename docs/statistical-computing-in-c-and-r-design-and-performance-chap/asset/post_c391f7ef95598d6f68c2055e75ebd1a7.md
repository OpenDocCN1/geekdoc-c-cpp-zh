include directives. Header files were discussed in Chapter 2 as a means of making various aspects of the C++ standard library. We will expand on that in the sense of creating our header files to facilitate access by other programs to code that we have created for various purposes.

Basically, a header file for a class should consist of the class prototype or declaration. So, for the Power class, the header file would be constructed using essentially lines 6-12 of the listing for Power.cpp. There is a slight caveat here concerning include guards and we need to deal with this first before giving the exact listing for the header.

Header files provide the connective medium between classes and other programs that use them to be included in any program that uses a member of a class. As a result, when multiple programs are being combined it is possible that a particular header file be included more than once in the final compilation process. This would be viewed by the compiler as a redefinition of the class and tagged as an error. Include guards provide a way to avoid this type of problem. The procedure is to use the preprocessor to conditionally define a variable the first time the header is encountered. Once defined, it is then used by the preprocessor to ignore the header file if it is encountered through an include directive from any other program.

A listing of the header file for class Power complete with an include guard is given below. The first time the header is encountered by the preprocessor, the variable POWER_H is defined and the code in the file is processed. Any other requests to include the header will have #ifndef POWER_H evaluate to false and the remainder of the file will be ignored.

```cpp
//Class.h
#ifndef POWER_H
#define POWER_H

class Power{
    int K;//integer power

public:
    Power() : K(1);//default constructor
    Power(int k) : K(k); 
    double xToTheK(double x);
};
#endif
```

In addition to the include guard, a default constructor has been placed inline by giving its definition (rather than just declaration) in the header file. Any function defined within a class declaration is automatically inline with the effect that it will be expanded in place by the compiler (i.e., the body of the function will be used directly) in lieu of a function call. For small functions this can improve the speed of a program.

The definitions for the member functions for class Power are now placed in a separate file powerClass.cpp which looks like:

```cpp
//powerClass.cpp
#include <iostream>
#include "PowerClass.h"

using namespace std;

Power::Power(int k){
    if(k != 1)
        K = k;
    else
        cout << "The power must be an integer >= 1!" << endl;
}
```

```cpp
double Power::xToTheK(double x){
  double y = 1;
  for(int i = 1; i <= K; i++)
    y = x*y;
  return y;

Note that an include directive has been used to bring in the Power class prototype contained in Class.h. The use of quotation marks instead of < > tells the preprocessor to begin looking for the header file in the current directory.

Finally, a program that actually uses class Power:

```cpp
//powerClassDriver.cpp
#include <iostream>
#include "powerClass.h"

using namespace std;

int main(){
  int k;
  double x;
  cout << "Enter an integer power ";
  cin >> k;
  Power powObj(k);
  cout << "Enter a number to raise to this power ";
  cin >> x;
  cout << powObj.xToTheK(x) << endl;
  return 0;
}
```

Observe that the header file for class Power has been included in this driver program and that a Power object is now being used to call the xToTheK method.

In looking back at the header file and associated cpp file for class Power, one will see that the namespace directive was only employed in the cpp file. This was done for purpose and it is, in general, not to place namespace directives in header files. The reason for this is that the preprocessor inserts the content of a header file into any source file (which could be another header file) that imports it via #include statement. This means that a namespace designation in a header file can propagate unintentionally if the header is being used several times in a multiple source code project. The result can be name clashes that are hard to diagnose. Therefore, it is best to use explicit namespace qualifiers via the scope resolution operator in header files and restrict the use of namespace directives to the cpp files for a class. We will demonstrate this in the next section.

The only thing remains is showing how to create an executable program using three separate files for the code. This can be accomplished directly via:

```bash
$ g++ -Wall powerClass.cpp powerClassDriver.cpp -o powerClass
./powerClass
Enter an integer power 3
Enter a number to raise to this power 1.2
1.728
```

which is a direct extension to use the -c option of the GNU compiler to create intermediate object files of our previous approach to compilation. Alternatively, one can use files from the two cpp files. These files have a extension and can be linked to produce the executable. For our specific example this takes the form:

```bash
$ g++ -c Wall powerClass.cpp
$ g++ -c Wall powerClassDriver.cpp
$ g++ -Wall powerClass.o powerClassDriver.o -o powerClass
./powerClass
Enter an integer power 3
Enter a number to raise to this power 1.2
```

The first two invocations of g++ with the -c option produce the g++ files powerClass.o and powerClassDriver.o. These are then linked by the final call to g++ that produces the executable named powerClass. Further discussion of the use and options for g++ can be found in Gough (2005).

Linking objects to compile multiple source files can become tiresome if many source files and/or the process has to be repeated. A program that allows us to efficiently automate the compilation of each code in a project is the make utility. Other features, this program checks to see if any files in the project have changed since the last compilation and recompiles only the ones that have been altered. To use it is necessary to have a myfile in the directory that contains the code to be compiled. An illustration of such a file, named powerClass.mk in this case, that was written to compile our power class example is shown below.

Listing 3.7 powerClass.mk

```make
powerClass : powerClassDriver.o powerClass.o
	g++ -Wall powerClass.o powerClassDriver.o -o powerClass

powerClass.o : powerClass.cpp powerClass.h
	g++ -c Wall powerClass.cpp

powerClassDriver.o : powerClassDriver.cpp powerClass.h
	g++ -c Wall powerClassDriver.cpp
``` (Note: The OCR for the Makefile was heavily fragmented in the source; I have reconstructed the logical make structure based on the context of the commands provided in the text).
