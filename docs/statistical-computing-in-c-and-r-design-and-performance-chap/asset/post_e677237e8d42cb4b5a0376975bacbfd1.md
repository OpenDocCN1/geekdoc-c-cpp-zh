As a more complicated let us consider a regression variable selection method. The artificial data set that will be used for this purpose is generated with

+   > set.seed(123)
> n <- 1000
> p <- sample(1:p, size = 1)
> indicesToDelete <- sample(1:p, nDelete)
> beta <- rnorm(p, sd = 2)
> beta[indicesToDelete] <- 0
> beta

| 3.1174166 | 0.1410168 | 0.2585755 | 0.000000 | 0.9218324 | -2.5302125 |
| [7] | -1.3737055 | 0.0000000 | 2.4481636 | 0.0000000 |

+   > X <- matrix(rnorm(p*n), n, p)
> y <- X*%beta + rnorm(n)

The data consists of 1000 observations on a response (stored in the vector y) and 10 "predictors" (stored in the matrix object X). The response and predictor variables are related through a linear model with standard random errors. The coefficient vector for the predictors is constructed in two steps. First, an integer between 1 and 10 is chosen to determine the indices for these variables are randomly selected. Next, the coefficient vector is generated from a zero mean normal distribution with standard deviation two and the selected coefficients are set to zero. We now point out that in this particular instance, the eighth and tenth "predictors" will be independent of the response variable.

We will now treat our simulated data as if its properties are unknown to and attempt to determine which variables should be used in a fit of a linear model involving the 10 predictors. To accomplish all $2^{10} = 1024$ possible variables (including a constant term) will be fit to the data. The criterion that will be used to rank the fit is the Bayesian Information Criterion (see, e.., Chapter 2 of Eubank)

> BIC(i) = log(RSS(bi)) + log(n)*#(i)

where RSS(bi) is the residual sum of squares for the i-th model and #(i) is the number of variables in this model. A “best” fitting model is one that provides a minimum value for the criterion.

The R function can be used to evaluate BIC extractAIC with (simplified) proto-

```r
extractAIC(fit, k)
```

The fit argument can be an lm object returned from the R lm function (discussed, for example, in Section 3 of Appendix B). The extractAIC function returns a two-component vector storing the number of variables in the fitted model and (from apart an additive constant) the value of

```
log(RSS(bi)) + k#(i),
```

for a constant k that defaults to 2. For our purpose we will use extractAIC in the

```r
extractAIC(fit, k = log(n))
```

to produce values that are equivalent to BIC.

Our plan is a simple divide-and-conquer scheme; a group of the possible model subsets will be assigned to each processor. The individual processors will evaluate the BIC criterion over their model subsets and return the best-fitting model back to the master processor. For our purpose we will use the R send and receive commands. We have

```r
mpi.send.Robj(object, destination, tag)
mpi.recv.Robj(mpi.any.source(), mpi.any.tag())
```

In the mpi.send.Robj function, destination and tag represent the R object to be sent, the rank of the slave that should receive the object, analogous to the MPI case, an integer tag that can be used to differentiate messages when more than one is being sent. A simplified version of the function is implemented here where “wild cards” mpi.any.source() and mpi.any.tag() are used to allow a processor to receive an object from any source with tag. This will suffice because only the master processor will send and receive only one object.

The variable subsets are constructed and sent to the processors using

+   - nSubsets <- 2^p - 2
- subsets <- expand.grid(rep(list(0:1), p))
- indexList <- lapply(1:4, FUN = function(i)
- subsets + c((i - 1)*nSubsets, subsets)
- for(i in 1:3) mpi.send.Robj(indexList[[i]], i, 0)
- mySubsets <- mpi.recv.Robj(mpi.any.source(), mpi.any.tag())

Four processors are used in the analysis. Thus, each processor will receive $2^p/4 = 2^{10}/4 = 256$ subsets to analyze. The entire collection of subsets is enumerated in the data frame using the rep and expand.grid function. The latter function creates a data frame using all combinations of subsets; i.e., a data frame with $2^{10}$ rows having elements are all zeros and ones. The code excerpt illustrates the idea for $p=3$.

The zeros and ones in the array indicate which variable subsets should be in the fitted model: 0 signifies that the variable should be excluded and 1 means it should be included in the fit. The first row consists of all zeros. It has the effect of producing a fit with only the constant term: the function is used to create blocks of 256 rows from the subsets data frame. These are then distributed to the processors via a for loop. The processors then call mpi.recv.Robj to receive their data using the mpi.bcast.cmd function. This latter function is a version of mpi.remote.exec which produces no output. The function that will be used to create subsets

```r
myRegTask <- function(mySubsets) {
  n <- length(y)
  aicVec <- apply(mySubsets, MARGIN = 1, function(a) {
    ind <- as.vector(a, mode = "logical")
    if(sum(a) == 0)
      k <- log(n)
    else
      extractAIC(lm(y ~ ind), k = log(n))
  location <- which.min(aicVec[, 2])
  list(mySubsets[location, ], aicVec[location])
}
```

The argument mySubsets will contain a subset of the subsets data frame held by the master processor. There is a minor problem of determining how to translate the rows of this object into the subset that will be used in the regression. The solution is to translate each row into a logical vector using the vector constructor set to logical. An if statement is also needed to make certain that the case of fitting the constant is handled correctly; the sum of the ind vector will evaluate to 0 when all the predictors are excluded from the fit and is to determine if it is the case. The second component of the vector returned from extractAIC is the value of the criterion. The best fit for a given processor will be the one whose index corresponds to the column of aicVec contains the smallest BIC. This index is found by using the which.min function to the second row of aicVec. The processor then returns its optimal subset along with the corresponding value of BIC to the master processor.

Finally, the data and the myRegTask function are sent to the processors which are ordered to carry out their calculations

```r
> mpi.bcast.Robj2slave(y)
> mpi.bcast.Robj2slave(X)
> mpi.bcast.Robj2slave(myRegTask)
> mpi.remote.exec(myRegTask(mySubsets))
```
