Both of these functions perform minimization over quasi-Newton type algorithms that use fine difference approximations for the first and second derivatives that appear in the Newton updating setting. The optim function provides access to several other minimization techniques including simulated annealing that can be found in Section 8.6. It also allows for enforces range constraints while nlm does not have that option. As a result, our focus will be on the use of optim.

A simplified version of the prototype for optim is

```
optim(par, fn, method = "L-BFGS-B", lower, upper)
```

The par argument is the starting value to initiate the recursion, fn is the function to be minimized and lower and upper are the bounds to define the entire real line in the univariate case. The method L-BFGS-B is a limited memory, quasi-Newton algorithm that employs the Broyden-Goldfar-Shanno or BFGS updating scheme for second derivative approximations and allows for constraints in the form of bounds (see, e.g., Byrd et al. 1995 and Zhu et al. 1997). The limited memory aspect is not particularly relevant for our one-dimensional setting. In general, the optim function can be used for optimization in higher dimensions where such issues become more important.

An application of the optim function for minimization of f(θ) = sin(4πθ²) resulted in

```
optim(.5, func, method = "L-BFGS-B", lower = 0, upper = 1)
```

```
$value
[1] -0.61574799
```

```
$counts
function gradient
17 17
```

```
$convergence
[1] 0
```

```
$message
[1] "CONVERGENCE: REL_REDUCTION_OF_F <= FACTR*EPSMCH"
```

A component list is returned by optim whose first components are the approximate minimizer (par) and the corresponding value of the objective function (value). The counts component includes the number of evaluations that were required for the function (i.e., in this case) and the number of iterations that were computed for the function's derivatives both of which are 17 in this instance. The value of convergence returns an error message 0 indicating successful convergence. The last message is a report of any additional information returned by the optimizer. In this instance, the optimizer identified that the algorithm terminated when the change in the objective function fell below a constant multifact of the machine epsilon or minimum detectable absolute rounding error that was discussed in Section 2.5. The value of fractr can be specified as an argument to optim and defaults to 10^{-7} otherwise. The derivative of the objective function can also be supplied to optim as its gr argument.
