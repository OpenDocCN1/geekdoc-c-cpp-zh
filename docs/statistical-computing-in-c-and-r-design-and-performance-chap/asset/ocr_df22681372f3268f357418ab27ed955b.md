# INTEGERS

The results obtained from the storageSize will be machine-dependent. For the C++ implementation on the computer that was used to produce this output, a small integer with no attached sign represented in unsigned short will be stored in two bytes or 16 bits of memory. The long int and unsigned long int types provide eight bytes of storage while the values for an int variable can take up more than four bytes of memory.

One of the reasons for machine dependence is the flexibility that was written into the C++ Standard. Only minimum and maximum values are specified for the different data types. For, in the case of the requirement is that long int need only as much as int. The values that we just satisfy this guideline since long int provides twice the storage capacity of int.

The float and double types are the irrational analog of the int and long int storage for integers. Another phrase that is used for float is single precision and double is for double precision. This terminology becomes meaningful from the output of the storageSize program: a double is allocated 64 bits of memory or twice that is allowed for a float. A long double is stored in 128 bits of memory or twice that provided for a double.

# 2.3 Integers

Computer arithmetic is basically conducted with integers and floating-point values that are used to approximate the values of integers. Although floating-point storage has a complex structure, it is not dissimilar from what is employed for integers. In the every number must be translated into a sequence of bits and the devil is in the details of how this is done. Integers are a good place to think about such concepts and, accurately, that is why this section begins.

To explore how integers are stored in some specific cases of interest it would be helpful to have a program that returns the binary representation of a number. To accomplish this let us first define the unsigned int or simply unsigned short data type. As the names suggest, these are small negative integers. As seen in the previous section, they occupy 2 bytes of storage with values ranging from 0 to 2^16 - 1 = 65535. This makes ideal for our current purpose where we want to extract the binary representation of numbers in a simple setting. A program that accomplishes this is provided by Listing 2.2.
