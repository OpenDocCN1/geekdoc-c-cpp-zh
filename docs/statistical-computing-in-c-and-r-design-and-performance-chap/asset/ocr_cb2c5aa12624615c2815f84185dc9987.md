Let us now assume that the drawing results from the Guess5 game data all be stored in the format shown above. If regular analysis is to be conducted on this data, time and energy can be conserved by creating a data analysis structure that is tailored to dealing with data of this type. A natural way to accomplish this is by building Guess5 related classes and functions and that is the approach that will be taken.

The first step in the design process is to consider what classes would be useful and suitable for Guess5 data. In representing the smallest data “unit” might be viewed as the results of a particular draw. It is important to be able to access the information about each individual draw for historical purposes as well as diagnostic analysis related to unusual draws that occur at various points in time. This suggests each draw has its own “identity”, and in mind a natural starting point would be the creation of a Guess5 class to hold the information about a single Guess5 draw.

In creating a Guess5 class we need to consider what information to retain about the draw results. The results can exhibit structural problems from wear and tear and machines malfunction. Thus, it may be necessary to look at subsets of the data that correspond to different sets and machines. Also, the date of the draw provides a unique identifier that can aid in sorting and locating data in a file suggesting that information of this nature should be included. These considerations lead to a “wish list” for properties that might be built into Guess5 class objects:

+   a) Guess5 object should contain the results of a single night’s draw.

+   b) Class members should include identifiers for the drawing machine and ball set that were used to carry out the draw. Other possible class members might represent information on the date and the day of the week for the draw.

+   c) The actual drawing results (i.e., the numbers for all the balls that are drawn in the Guess5 draw and pretend experiments) should be available in a form that is easy to manipulate for data analysis purposes; e.g., as a matrix.

An R class that adheres to our design guidelines for Guess5 drawing results might be established with something like

```
> setClass("g5", representation = "Date",
+ mName = "character", sNo = "integer", Day = "character",
+ data="matrix")
[1] "g5"
```

This creates a base class g5 with class members for the date of the draw (drawDate), the machine name (mName), ball set number (sNo) and the day of the week (Day). All members derive from the R classes. We worked with the Date class previously in Section 5.6. The actual drawing results will be stored in the slot as a matrix object.
