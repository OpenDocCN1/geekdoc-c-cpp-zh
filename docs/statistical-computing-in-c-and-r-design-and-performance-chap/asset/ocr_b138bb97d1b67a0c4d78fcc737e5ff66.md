The errors incurred from floating-point division can be bounded similarly to the case of multiplication (Exercise 2.5). However, this is not true for floating-point addition and subtraction. In fact, as noted by Wilkinson (1963, page 17), it is not possible to obtain a bound for the relative errors associated with such calculations as the floating-point sum/difference can be zero when the sum is zero.

An indication of how problems can arise from subtraction is provided by taking $x$ and $y$ to floating-point numbers with $m$ digits significands $x=1.0\dots0^v$ and $y=b_0b_1\dots b_{m-1}.2^v$ with $b_0=\dots=b_{m-1}=1$. In this instance the difference between $x$ and $y$ is $2^{v-m}$. This difference is amplified by $2^m$ for chopping and 0 under rounding to the closest value. The absolute relative error for approximating $x-y$ is one in either case because $(2^{-(v-m)})/2^{v-m}=1$ and $(0-2^{-(v-m)})/2^{v-m}=-1$. This implies that the absolute error in subtracting $x$ from $y$ using floating-point calculations can be as large as the quantity $x-y$. Put, there may be no digits of accuracy in the output steps unless taken to provide additional accuracy in the calculation.

Suppose that the floating-point addition operator produces exactly rounded results and let $\hat{x}_1,\dots,\hat{x}_n$ be floating-point approximations of numbers $x_1,\dots,x_n$. To compute an approximation $\hat{S}_n$ to $S_n=\sum_{j=1}^n\hat{x}_j$ use the recursion that starts with $\hat{S}_1=\hat{x}_1$ and has the general step

```
$\hat{S}_j = \hat{x}_j+\hat{S}_{j-1}$
```

for $j=2,\dots,n$. At the $j$th step of the recursion

```
$\hat{S}_j = (\hat{x}_j+\hat{S}_{j-1})(1+E)$
```
