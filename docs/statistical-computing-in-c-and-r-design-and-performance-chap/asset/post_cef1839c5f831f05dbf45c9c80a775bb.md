
# MAXIMUM LELIHOOD

To provide some variation in the development, we will have our likelihood class Like to manage the input of data using a template class fileIn is similar to the one created in Exercise 3.33. The calling program will simply supply the name of the file that contains the data and finish the functions that are to be used in the optimization process. For the Newton method, the logarithm of the density and its first derivatives will need to be passed to a Like class object. The Functor class will be used for this.

Listing 8.13 functorIn.h

```cpp
//functorIn.h
#ifndef FUNCTIONOR_H
#define FUNCTIONOR_H

struct FunctorIn{
    double (*PF)(double x, double theta);
    double (*PF1)(double x, double theta);
    double (*PF2)(double x, double theta);

    FunctorIn() {}
    FunctorIn(double (*pf)(double x, double theta),
              double (*pf1)(double x, double theta),
              double (*pf2)(double x, double theta)){
        PF = pf; PF1 = pf1; PF2 = pf2;
    }

    double operator()(double x, double theta, int i) const {
        if (i == 0) return PF(x, theta);
        if (i == 1) return PF1(x, theta);
        return PF2(x, theta);
    }
};
#endif
```

The primary difference between Listing 8.13 and Listing 8.11 is that operator() has three arguments rather than two: the variable to be used in optimization, theta, the index i that determines which function to evaluate, and an x variable that corresponds to the observed sample values. This header file for our likelihood class is given in Listing 8.14 below.

# NUMERICAL OPTIMIZATION

The Like class has three members: the sample size n, a Functor object, and a pointer to double that will hold the data values. The class constructor takes the sample size and a Functor object as arguments as well as a C-style string (i.e., a null-terminated "\0" character array or pointer to char) that contains the name of the file where the data is stored. The class mle manages the optimization work requiring specification of the lower and upper bounds a and b for the parameter space interval and a starting value to use in initialization of Newton's method. The remaining two arguments itMax and delta set the stopping criteria for the Newton iteration; recall that once an argument is given a default value all subsequent arguments in the function's signature have defaults as well. This is why itMax and delta appear at the end of the argument list for the mle method.

The content of the file that contains the class Like method definitions is shown in the next listing.

Listing 8.15: like.cpp

```cpp
//like.cpp
#include "like.h"
#include "functor.h"
#include "optim.h"
#include "fileIn.h"

Like::Like(int N, char* fname, FunctorIn& F) {
    n = N; f = F;
    px0 = new double[n];
    fileIn<double> inObj(fname);
    inObj.read(n, px0);
}

double Like::l(double theta) const {
    double logL = 0;
    for(int i = 0; i < n; i++)
        logL += f(px0[i], theta, 0);
    return (-logL);
}

double Like::lp(double theta) const {
    double logL = 0;
    for(int i = 0; i < n; i++)
        logL += f(px0[i], theta, 1);
    return (-logL);
}

double Like::lpp(double theta) const {
    double logLpp = 0;
    for(int i = 0; i < n; i++)
        logLpp += f(px0[i], theta, 2);
    return (-logLpp);
}

double Like::mle(double a, double b, double start, int itMax,
                 double delta) const {
    int ier = 0;
    Functor<const Like> logL(this, &Like::l, &Like::lp, &Like::lpp);
    Optim<const Like> Opt(itMax, delta);
    double thetaHat = Opt::newton(logL, b, start, ier);
    return thetaHat;
}
```

The class constructor allocates sufficient memory to hold the data array and then uses the input name to create a file object that is suitable for reading floating-point data in double precision. The read method for this particular incarnation of class fileIn looks like

```cpp
template<class T> void fileIn(int n, T* pData) {
    std::ifstream inFile(fileName);
    if(!inFile.is_open()) {
        std::cout << "Error opening file!" << std::endl;
        exit(1);
    }
    for(int i = 0; i < n; i++)
        inFile >> pData[i];
    inFile.close();
}
```

This method uses an ifstream (cf. Section 3.1) to open the input file, reads the data while placing in memory and then closes the connection. The functions lp and lpp calculate the negative log-likelihood and its derivatives at a given theta for the parameter. For this purpose they use the Functor which was supplied to the class constructor to sum the observed values and directly evaluate f'. These functions were designated as private in the class header because they are internal for this particular instance. The form of the mle method in Listing 8.15 is perhaps deceptive in its seeming simplicity. The idea is straightforward: a function object encapsulates the lp and lpp methods (i.e., a Functor object from Listing 8.1) is constructed and then passed to an optimization object to find the mle. However, similar to the example of Section 8.3, the fact that the mle class parameter must be set as const. Also, the functions lp and lpp must all be const functions in order to be invoked by this pointer that is passed to the Optim object. The function objects in Listing 8.1 derive from functor.h (template with derivatives)

```cpp
//functor.h
#ifndef FUNCTOR_H
#define FUNCTOR_H

template<class T>
class Functor{
    double (T::*pf)(double) const;
    double (T::*pf1)(double) const;
    double (T::*pf2)(double) const;

public:
    Functor() : pf(nullptr), pf1(nullptr), pf2(nullptr) {}
    Functor(double (T::*pf)(double) const, double (T::*pf1)(double) const,
            double (T::*pf2)(double) const){
        pf = pf; pf1 = pf1; pf2 = pf2;
    }
    double operator()(double u) const {
        return pf(u);
    }
    double operator()(double u, int i) const {
        if (i == 1) return pf1(u);
        if (i == 2) return pf2(u);
        return pf(u);
    }
};
#endif
```

This is a template version of the functor class in Listing 8.1 as it is a template class, our optimization class should be structured similarly. The template version of Optim in Section 8.3 was adapted for the job by adding a template version of the Newton prototype

```cpp
template <class T> double Optim<T>::newton(Functor<T>& f, double a,
                                         double b, double start, int ier)
```

The Like class will be used to obtain the mle for the exponential distribution with density

```
f(x) = { theta exp(-theta x), x > 0, 0, otherwise}
```

for theta > 0. This is a trivial case in the sense that the mle has a closed form and is found to be the reciprocal of the sample mean sum_{n=1}^n xi/n. Its utility lies in the fact that it gives a test case where the answer is known. The driver program for the exponential scenario is

```cpp
//likeDriver.cpp
#include <cmath>
#include <iostream>
#include <cstdlib>
#include <limits>
#include "like.h"
#include "functor.h"

double f(double x, double theta){
  return (log(theta) - theta*x);
}

double fp(double x, double theta){
  return ((1./theta) - x);
}

double fpp(double x, double theta){
    return (-1./(theta*theta));
}

int main(int argc, char* argv[]){
    int n = atoi(argv[1]);
    FunctorIn F(&f, &fp, &fpp);
    Like obj(n, argv[2], F);
    double up = std::numeric_limits<double>::infinity();
    double mle = obj.mle(0, up, atof(argv[3]));
    std::cout << mle << std::endl;
    return 0;
}
```

The functions f, fp and fpp are the logarithm of the exponential density and its two derivatives that are used to create the Functor object. The sample size, file name (for the data) and a starting value for the recursion are obtained from command line arguments. However, for the exponential distribution the parameter space is the real line. Thus, a lower limit of a=0 is specified while the upper limit is set to the machine definition of infinity using the numeric_limits template.
