# NUMERICAL OPTIMIZATION

This version of func agrees with the original on [0, 1] and evaluates at the R representation
of positive infinity otherwise. Thus, values outside of [0, 1] are effectively excluded from
consideration. With this new version of func goes much more smoothly with optim
returning

```
set.seed(123)
optim(par) = .5, fn = func, method = "SANN")[1:2]
$par
[1] 0.9373296
```

```
$value
[1] -0.9363776
```

The default choices were used here and worked reasonably well in this instance.
To see how sensitive is to the choices of temp, tmax and maxit a few other
were considered giving results like

```
set.seed(123)
optim(par) = .2, fn = func, method = "SANN"
+ control = list(maxit = 5, temp = 2, tmax = 1))[1]
$par
[1] 0.1829546
```

```
set.seed(123)
optim(par) = .2, fn = func, method = "SANN"
+ control = list(maxit = 10, temp = 2, tmax = 1))[1]
$par
[1] 0.9542554
```

```
set.seed(123)
optim(par) = .2, fn = func, method = "SANN"
+ control = list(maxit = 100, temp = 2,0 = 250))[1]
$par
[1] 0.9651814
```

At least in the context of this example, the algorithm appears to behave robustly with
respect to the choice of the tuning parameters. It placed us in the right area for locating
global minimizer when the number of iterations, for example, has been set to be
quite small.
