While there has been some debate about the relative merits of the two approaches, in practice it appears that both packages are effective and provide solutions to the problem of obtaining something that can be viewed as independent streams. Practical difficulties that arise in SPRNG stem from its ties to MPI and a complex implementation that necessitates the creation of a compiled library. In contrast, the source code for the RngStreams package is compact and easy to incorporate into C/C++ programs using either OpenMP or MPI through simple include directives. This property extends its applications from clusters to desktop environments, and accordingly, it is the parallel pseudo-random number generator that will be used here.

"backbone" generator for RngStreams is the multiple recursive generator Merg32kda in (4.11)-(4.12). The period of the generator exceeds $2^{191}$. For use in a parallel context this length is divided into 264 nonoverlapping streams of length 2127.

The key to accessing different streams from (4.11)-(4.12) is the technique described in L'ucyer (1990) that allows movement between streams through linear transformations of the initial seeds using known matrices. If $\tilde{x}_1, \tilde{x}_2$ are the initial seeds/seeds for the stream, then at the $n$th step of the generator for stream $i$ is $x_{i,n} = (A_i^n m_i \pmod{m_i})$, $i=1,2$, for $3 \times 3$ matrices $A_1$ and $A_2$ with $m_1 = 4294967087$ and $m_2 = 429444443$. The powers of the matrices $A_1$ and $A_2$ can be computed explicitly, and it is the $A_1^{27}$ and $A_2^{27}$ that are needed for movement between the different streams of the generator are found to

> $A_1^{27} = \begin{pmatrix} 242970618 & 358015074 & 949970784 \ 226153695 & 1230515664 & 358015074 \ 198883501 & 996791581 & 1230515664 \end{pmatrix}$ (11.1)

and

> $A_2^{27} = \begin{pmatrix} 146441153 & 277697599 & 1610723613 \ 32183930 & 146441153 & 1022807787 \ 282425495 & 32183930 & 2093834863 \endend{pmatrix}$ (11.2)

Section 4.5 demonstrated how to use the SetPackageSeed function to set the initial state for RngStream objects. This requires the user to supply initial integers to serve as the beginning seed for the generator. The first RngStream object that is created will use this initial seed. Subsequent objects will be started on the next stream; i.e., they will have initial "seeds" that are $2^{27}$ states removed from the initial state of the previous object's generator.

Our first objective is to perform some experiments that will illustrate how the seeds are changed (and how to guarantee that they are changed) for different processors. For this purpose the GetState function will be needed. It has prototype

```
void GetState(unsigned long seed[]) const
```

This function provides a means to return the current state of an RngStream object at any point during random number production. In particular, it allows us to determine an object's initial seed and how it will be used in our examination of the behavior of the RngStream class constructor.
