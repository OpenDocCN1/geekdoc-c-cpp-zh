This code is similar to what was used for our copy constructor. The main difference is that it now allows for the possibility that we are working with an existing object. In that case it must be taken into account that the Matrix on the left-hand side of = is to be overwritten with the contents of the Matrix A in the operator's argument which corresponds to the quantity on the right-hand side of the = operator. If memory has already been allocated for that object's pa member there are two possibilities: either the dimensions of the matrices are the same or they are not We can simply overwrite the existing memory. A final possibility that can arise in this instance is that the left-hand side object was created with the default constructor in which case there is no memory to release. This is checked first before proceeding with memory release. One may check that inclusion of our overloaded= operator in the Matrix class resolves our prior difficulties and assignment no longer produce a run-time error.

The definition of overloaded= also represents our first use of the hidden pointer that was discussed in Section 3.8.2. The Matrix& has return-type Matrix& which means it must return the address of a matrix object: namely, the address of the calling matrix that resides on the left-hand side of the = operator. This latter object needs to actually "know" its own address for us to be able to return the reference and it keeps information in the value of this.

Operators overloading can be used to produce operators for all the standard matrix operations for members of a class Matrix. With that in mind, a somewhat complete development of a class that incorporates addition, multiplication and other new features has the header in Listing 3.15.
