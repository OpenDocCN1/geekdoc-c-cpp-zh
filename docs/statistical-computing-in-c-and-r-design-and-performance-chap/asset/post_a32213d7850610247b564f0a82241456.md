## 2.4 Floating-point representation

Storage types with fixed positional representation work for integers. This basic idea could be used to represent rational numbers or fractions as $k/m$ with $k$ and $m$ integers. However, the utility of the fixed point framework leaves the unresolved problem of storing and working with irrational numbers, which comprise the bulk of the number system.

At this point we must realize that a general number cannot be stored in its entirety and, as a result the stored value remains only an approximation to the truth. Errors are created in computer arithmetic with real numbers due to the rounding of the numbers for storage as well as further manipulations. These issues will be discussed in the next section. The present suffices it to recognize that there is a limit to the precision that can be achieved from any computer representation that might be employed for irrational numbers. We will express the precision by the number of significant digits of agreement between the true value of a number and its floating-point representation. A good storage system is one that attempts to minimize losses in precision subject to the constraints that have been imposed by the allowed amount of storage.

Roughly speaking, significant digits are obtained by removing leading and trailing zeros from a number would take place for scientific notation. For example, this is an act that for the developments in this and the next section. To effectively scale irrational numbers on a computer the decimal point must be allowed. By we mean that the decimal is placed after the first significant digit. To recover the actual value of a number this decimal relocation is accompanied by multiplication by the base (e.g., 2 or 10) to an appropriate power. This is an adaptive representation for numbers that allow considerable storage flexibility to the integer case.

To be more specific, let us return to the base 10 scenario where the floating decimal concept is already familiar in the form of E-notation. For example, under this format the values 21.237 and .01237 would be retained as 2.1237E+1 and 2.1237E-2. The use of "E" in this context stands for the exponent of 10 and what is really being stated is that $21.237 = 2.1237 \times 10^1$ and $.021237 = 2.1237 \times 10^{-2}$. This idea works generally in that $m+1$ significant figures can be retained for a real number $x$ by writing it as:

$x = \pm a_0.a_1 a_2 \dots a_m 10^p$,

The idea behind (2.6) is that any real number can be written as

There is no special about base 10 and the analog of (2.6) for base 2 looks like:

```
$x = \pm b_0.b_1 b_2 \dots b_m 2^p \quad (2.8)$
```

with $b_0, \dots, b_m$ all having values of 0 or 1 and $p$, being a signed integer. As for the case of (2.6), (2.8) derives from

```
$x = \pm \sum_{j=0}^{\infty} b_j 2^{p-j}$
```

and then keeping the $m+1$ terms from the series. It is only necessary to deal with cases where $b_0=1$ means that a binary representation can always be written in form:

```
$x = \pm 1.b_1 b_2 \dots b_m 2^p \quad (2.9)$
```

This has the practical consequence that the value of $b_0$ need not actually be stored. Numbers represented in (2.9) are said to be normalized. The remaining part $b_1 b_2 \dots b_m$ is called the mantissa or significand. Let us see how an expression as (2.9) might be translated into a specific storage scheme. We will begin with a simple, realistic illustration and describe what can be expected on a typical machine. Suppose that a number $x$ is to be stored in floating-point representation that allocates one byte. There are essentially four things that must be accounted for: the sign of the number, the value of the exponent in (2.9) as well as its sign, and the values for $b_1, \dots, b_m$. To account for the sign of $x$, take the least-most bit to be value 0 for a positive number and 1 for a negative value. The next three bits can be used to hold the two's complement representation of the exponent (that can range from -4 to 3). This leaves four bits (i.e., $m=4$) to hold the significand. To signify this idea, e.g., the number -12.5, first observe:

```
$12.5 = 1.1001 \times 2^3.$
```

Hence, -12.5 would be represented as the leading 1 in the significand is dropped because it is assumed *a priori* to be 1, and the remaining part, 1001, represents coefficients for $2^{-1}, 2^{-2}, 2^{-3}$ and $2^{-4}$, respectively. Now adding .25 to -12.5, we can represent .25 (exactly) in our storage plan:

```
$.25 = 2^{-2}$
$= 1.0000 \times 2^{-2}$
```

But, to add it to -12.5 a common denominator is needed, which in this case, viewing 12.5 as:

```
$.25 = .0001 \times 2^3$.
```

However, in this format it cannot be stored exactly in four bits and instead must be rounded to a significand of $.000$ if we chop off the last digit or to $.001$ if we round up. As a result, addition returns the sum of -12.5 and .25 under truncation and -12 if the answer is rounded up. This is illustration of the types of problems that can occur when performing basic arithmetic operations using numbers with different magnitudes. In fact, in this case the addition of a number to -12.5 leaves it unchanged for any $|a| \le 2^{-3}$.

Finally, let us see what happens when we try to store $1/5$ using our simple system. This fraction cannot be stored exactly, and instead, the best that can be obtained is an approximate representation

```
$\frac{1}{5} = 2^{-3} + 2^{-4} + 2^{-7} - 2^{-8}=.191875$.
```

The sign for .191875 will have value 0 and the two's complement representation for its exponent (namely, $-3$) is 101. The significand be stored in its entry and rounding is required to make it fit into four bits of memory. The value is rounded up to 1010 and what is retained. The final result is that

There is a slight problem with our simple storage scheme. Since the lead of the significand was not the natural value to represent 0 has been lost. To account for this 0 simply be replaced by some value as 01000000 which would have the effect of eliminating $2^{-4}$ as a possible value.

In the real world storage for floating-point numbers can be expected by the IEEE 754 standard, for example, in Stevenson (1981) and Goldberg (1991). In the case of, e.g., float types the 754 standard specifies four bytes of data. The first of the 32 available bits is a sign bit with the next eight bits being allocated for storage of the exponent. The significand is stored in the remaining 23 bits.

In contrast to the value was handled in our simple storage scheme, the 754 standard employs a biased exponent. With eight bits there are only 256 possible integers (e.g., 0 to 255 or -128 to 127) that can be stored whether they are signed or unsigned. Biasing those with the unsigned integers 0 to 255 that can be stored in eight bits transforms or biases the values by subtracting 127 to produce exponents (base 2) that range from $-127=(0 - 127)$ to $128=(255 - 127)$.
