
```cpp
//no empty buckets were found
Index = -1; current = pCH->Table[0].end();
}
```

The basic premise here is that the nextBucket method will be called when the end of a list has been reached necessary to find the nonempty bucket in the table. Value of Index is the current slot for the iterator object which means that the next place to look for more elements is in the next bucket to the right or Table[Index + 1]. Since this is a list, the associated method empty that can be used to check if the list contains elements. The search for a nonempty bucket continues until one is found or there are no further slots in Table. In this instance, the end of the table has been reached and we need some way to indicate this. The approach employed here is to return nonoperative values for Index and current. We will say a bit more about this choice.

An alternative to our implementation of nextBucket is offered in Exercise 10.6. For instance, the hash table has a similar list that links the elements inserted into the table. This list directly provides iterators for moving between buckets in the order in which they were populated. The only overhead is space (instead of time) due to the additional data that must be stored besides the hash table's array. This approach has a precedent, for example, the Python data structure ordered dictionary.

ChainHash class provides the STL type methods begin and end that return iterators to the first and one past the elements in a container. We are now in a position that allows us to define these two methods. Specifically, the definition for the begin method in the next listing.

```cpp
template<class Key, class Data>
typename chainHash<Key, Data>::iterator
chainHash<Key, Data>::begin(){
    iterator iter;
    iter.pCH = this;
    //start the search in a bucket with index 0
    iter.Index = -1;
    // set Index and current
    iter.nextBucket();
    return iter;
}
```

The "beginning" of the hash table should be the first element in the nonempty bucket and returns an iterator to that object if it exists. For this purpose iterator object is created with its chainHash object pointer to point at the chainHash object that will be the first call to the nextBucket method. Its index is set to -1 before calling the nextBucket method. The first step in nextBucket is to advance the index to the Vector container. The remainder of the work is carried out by nextBucket which sets a final value for the Index and current class members.

The final entry in a chainHash object is the last in the list (i.e., right-hand) nonempty bucket. One can use an alternative strategy employed by, e.g., Gray and Todd (2002) to simply define an object that cannot actually be realized and return this whenever an attempt is to go past the end of the container. Our choice here needs to agree with the object returned from nextBucket when no further empty buckets are found. This last consideration leads to the choice of the end method given in the next listing.

All the pieces are now in place that allow us to give the definition for a prefix increment operator.

```cpp
template <class Key, class Data>
    typename chainHash<Key, Data>::iterator
    chainHash<Key, Data>::iterator::operator++(){
    if(*this == pCH->end())
        return *this;

    current++;
    if(current == pCH->Table[index].end())
        nextBucket();
    return *this;
}
```

The first step is to check if the table has been reached. In that case, an application of ++ will have no effect. Otherwise, the location of the iterator is advanced inside its current bucket. A check is made to see if one past the end of the current first list has been reached. In that event, the next bucket or pCH->end() is found via nextBucket.

The insert and lookup methods for chainHash given below involve operations similar to the ones that were used to define our iterator increment operator.

```cpp
template<class Key, class Data>
    typename chainHash<Key, Data>::iterator
    chainHash<Key, Data>::insert(pair<Key, Data> a){
    int index = hash(a);
    Table[index].push_front(a);
    iterator iter(this, index, Table[index].begin());
    Size++;
    return iter;
}
```

```cpp
template<class Key, class Data>
    typename chainHash<Key, Data>::iterator
    chainHash<Key, Data>::lookup(Key a) {
    int index = hash(a);
    typename chainHash<Key, Data>::iterator
    iter(this, index, Table[index].begin());
    while(iter->first != a && iter.current != Table[index].end())
        iter++;
    return iter;
}
```

The methods return iterators to the locations of pair objects that have either been inserted or found. These iterator objects are created using the nondefault constructor that takes a pointer to chainHash, a bucket index and a list container iterator as its arguments.

bucket index is obtained by hashing a key provided in the method's argument while the list iterator is the one returned by the begin method of the chosen bucket's list object. For insert, the new pair is added to the list object using its push_front method and the number of elements in the table is also incremented. In contrast, Lookup does not alter the table but searches for the pair object with the designated key found. This is presumed to exist and no mechanism has been provided to handle a misspecified key value.
