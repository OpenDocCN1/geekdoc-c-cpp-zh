# ADT DICTIONARY

```
> library(hash)
hash-2.1.0 provided by Decision Patterns

> hT <- list(1, 2, 3, 4), list(1, matrix(rnorm(16), 4, 4),
+ expression(1 + pi), 1:5))
> class(hT)
[1] "hash"
> attr("package")
[1] "hash"
> eval(hT[["3\]])
[1] 4.141593
```

The first package is loaded into the current environment. Then, a hash table object is formed using a group of R objects. A check reveals the new hash table is an object of the hash class. Evaluation of the expression object demonstrates that the entries in a hash object can be accessed with the indexing operator ]] using the object's key as the value.

The functions delete and has.key provide the same utility for hash objects as we obtained with rm and for environments. There is also a clear function that empties the table. The use of these functions in terms of our example produces

```
> delete("3", "4")
> has.key("4", hT)
4
FALSE
> clear(hT)
> hT
<hash containing 0 key-value pair(s).
NA NULL
```

The third and fourth entry are removed from the table with delete and has.key is employed to check that removal actually occurred. The clear function is applied to the hash object and an application of show indicates the table is empty.

Hash tables created (and, hence, produced with the hash package) store both the keys and their corresponding data objects in memory. For large data sets this can become problematic. One solution to problems of this nature can be obtained by using the file package from Section 9.3 where the key values are retained in memory while the corresponding data is stored on disk and accessed as needed.

The list below demonstrates the steps in creation of a filehash object.

The filehash library is loaded and an empty database called myData is created on disk using the dbCreate function. The myData file is "linked" to a filehash object hT with the dbInit function using the database filename (myData in case) as its argument. An application of the class function reveals that the filehash object has been created. The DB1 that appears in the class name corresponds to the default storage options where keys and data are stored in a single file.
