# 9.2 Linked lists and mergesort

Linked lists provide another approach to implementation of a dictionary. They arise, for example, in applications such as storage of sparse matrices and polynomial arithmetic (Exercises 10.26-10.27). Like dynamic arrays, they also provide a foundation from which other useful data structures such as hash tables, queues and stacks can be built.

As we saw in the previous section, insertion of new elements or resizing operations is computationally expensive for array types. Linked lists provide one means of overcoming such problems. For these data types resizing is actually costly, while insertion can be performed in constant time. With as compromises, there is a downside which, in this case, comes in the form of slow performance for each of list elements.

A list data structure consists of a collection of objects that have both key and data components, as well as a member next which designates (e.g., by a pointer) the next element in the list. The components of the list are generally nodes with the first node having the head and the last node referred to as the tail. The value of next for a list is the NULL value (e.g., a null pointer) indicating it has no successor. Lists of this particular type are called singly linked because the connection between nodes goes only in one direction; i.e., it is only possible to move toward the tail of the list by “stepping” through the next members of the node objects in the list. A simple extension is the doubly linked list, where nodes have an additional member that points to the preceding entry thereby making both forward and reverse movements possible.

Let us now take a look at the operations required to implement a linked list. A linked list can be built by “pushing” new nodes onto the front of the list as in

# Algorithm 9.3 push(a): Add a new node to a linked list

```
a.next = head
head = a
```

Here and subsequently the . notation represents a generic member selection operators; e.g., a.next is the “value” of next for a object. So, the value of next for the new node a is assigned the address of the current head. Then, a becomes the head and the list has grown by one object. Note that two simple steps are needed to add a node. The operation can therefore be accomplished in constant time.

The lookup operation for a linked list is described in Algorithm 9.4.

# Algorithm 9.4 lookUp(key): Look-up in a linked list

```
a := NULL
while a != NULL then
  if a.key == key then
    return a
  end
  a := a.next
end
return NULL
```
