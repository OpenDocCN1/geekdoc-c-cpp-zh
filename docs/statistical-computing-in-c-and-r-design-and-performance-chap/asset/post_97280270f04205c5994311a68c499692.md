## 9.2.4. Hash tables in R

Hash tables are present in the internals of most programming languages, either inside the compiler in the case of compiled languages such as C++ or inside the interpreter in interpreted languages such as R or Python. An interpreter must be able to retrieve information about any object previously defined and, from perspective, it is easy to imagine that a hash table may be useful only as a means to obtain information about an object given its name. Both R and Python use a general hash table mechanism to store the information about objects defined by the user, as well as for internal use by the interpreter. A good portion of time is used in both R and Python arrays (another synonym for a hash table) a prominent feature in Python, R's hash tables are much less efficient to a casual user. Nonetheless, its internal hash table mechanism is available and easy to use for storage purposes. There are at least two ways to make use of this feature: directly, using environments, or through the hash package. Another is provided by the file package that creates an external (from R) hash database. All approaches will be discussed in this section.

The key to creating hash tables in R is the environment concept. An environment consists of a set of symbol-value pairs (called a frame), and a pointer to another environment (called the enclosure). The details of the implementation or internal usage of environments are not of interest for us here; instead, want to examine how to use them to create hash tables for objects in R.

The constructor for the environment has class type

```
new.env(hash = FALSE, size)
```

The first argument in the constructor gives the option of having the environment be a chaining hash table. The second argument parent is the environment that is to contain the object created by the constructor. As no role in the R help page, it is the "ultimate enclosure of any environment [...] which to nothing may be assigned". The size argument is the number of buckets to be used in the hash table and defaults to 29.

The insert and look-up operations for environment are carried out using the assign function and either the get or mget functions; get access to one object which returns (as a list) the objects whose names/keys are specified in its list argument. An abbreviated prototype for assign is

```
assign(x, value, pos)
```

The x is a character string that represents the name that will be given to the object by the value argument. The pos argument specifies the environment where the assignment is to take place. Similarly, a condensed prototype for get looks like

```
get(x, pos)
```

With x the name of the object to be retrieved from the environment specified by pos.

To determine if an object x is present in an environment one uses the exists function in the form

```
exists(x, pos)
```

With the pos argument set to the environment that is the target for the search. The ls function will list the contents of an environment, environmentName via ls(environmentName). Finally, rm(objectName, env = environmentName) can be used to delete an object objectName from environmentName. All elements are deleted by the command rm(ls, env = environmentName)

First, an empty hashing table hT is created and examined using the env.profile function. The output from env.profile tells us that hT has three buckets (i.e., size is 3) with no chains (or linked lists) and no elements in any of the buckets as indicated by the values of counts. Next, four objects are inserted into hT using assign and its profile is examined. The hash table now has two chains or linked lists with two elements in each bucket and a third bucket that empty. The indexing operator [] and extraction operator $ provide alternatives for accessing elements in an environment as illustrated by retrieving the expression and sequence objects from hT. Note that the "index" used with [] must be the object's name. Finally, the sequence object is deleted from hT using rm and exists to check that the deletion has been successful.

A user-friendly interface for R tables is provided by the hash package which hash tables have been implemented as an S4 class called hash. The class constructor can take

```
hash(key, values)
```

with a set of keys (in the form, e.g., of a list) whose corresponding data objects are given in a list as the values argument. For example, we can recreate some aspects of the previous example with

```
> library(hash)
hash-2.1.0 provided by Decision Patterns

> hT <- list(list(1, 2, 3, 4), list(1, matrix(rnorm(16), 4, 4),
+ expression(1 + pi), 1:5))
> class(hT)
[1] "hash"
> attr("package")
[1] "hash"
> eval(hT[[3]]])
[1] 4.141593
```

The first package is loaded into the current environment. Then, a hash table object is formed using a group of R objects. A check reveals the new hash table is an object of the hash class. Evaluation of the expression object demonstrates that the entries in a hash object can be accessed with the indexing operator ]] using the object's key as the value.

The functions delete and has.key provide the same utility for hash objects as we obtained with rm and for environments. There is also a clear function that empties the table. The use of these functions in terms of our example produces

```
> delete("3", "4")
> has.key("4", hT)
4
FALSE
> clear(hT)
> hT
<hash containing 0 key-value pair(s).
NA NULL
```

The third and fourth entry are removed from the table with delete and has.key is employed to check that removal actually occurred. The clear function is applied to the hash object and an application of show indicates the table is empty.

Hash tables created (and, hence, produced with the hash package) store both the keys and their corresponding data objects in memory. For large data sets this can become problematic. One solution to problems of this nature can be obtained by using the file package from Section 9.3 where the key values are retained in memory while the corresponding data is stored on disk and accessed as needed.

- dbInsert, dbFetch (or indexing operator []) and dbDelete perform the hash table insertion, look-up and deletion dbExists can be used to check for the key.

```
> set.seed(123)
> dbInsert(hT, "a", 1)
> dbInsert(hT, "b", matrix(rnorm(16), 4, 4))
> dbInsert(hT, "c", expression(1 + pi))
> dbInsert(hT, "d", 1:5)
> eval(hT[["c"]])
[1] 4.141593
> dbExists(hT, "d")
[1] TRUE
> dbDelete(hT, "d")
> dbExists(hT, "d")
[1] FALSE
```

As before, four objects are inserted into the table and the third expression object is evaluated using the indexing operator to perform the table look-up. The existence of the fourth object is tested using the dbExists function, it is removed from the table with dbDelete and success of removal is checked.
