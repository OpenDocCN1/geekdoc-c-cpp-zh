To effectively handle problems of practical interest an output class should be constructed. An object from the class could then be used to write an to a specified file. The methods that might be created or object construction would depend on the data type for the array. This would require different methods to handle integer and floating-point data, for that would be done conveniently if we could create a generic data type that would allow arrays constructed from, e.g., any of the primitive types to be written to files with only a single method. This can be accomplished using a class template and that the solution will be developed.
The syntax for creating a template class looks like

```cpp
template<class T> class className{
    member declarations and method prototypes
};
```

Here T represents a "word of card" for sorts that must be specified by the calling program. In the general context of template classes T could be any data type including one that was created. For statistical purposes T will most be one of the primitive types such as char, int, float, etc., and there is no harm in viewing it from that perspective throughout this section.
The declarations for methods and well as specification of public and private class templates are exactly the same as for the non-template case. To specify method definitions outside the class declaration

```cpp
template<class T> returnType className<T>::methodName(arguments){
    body of method
};
```

There is a caveat here; the method definitions must reside in the same file as the class declaration. Previously class declarations have been physically separated from the method definitions in header and cpp files. The cpp files were then compiled into object files that were linked at the end to produce an executable. The problem with this approach for templates is the generic T is used as a place holder for the actual data type that will be substituted for T to produce a specific object. The class has no way to allocate storage for when an object file is created without an actual data type being specified. This is done only when a specific choice is made for T when the compiler essentially goes through both the source (i.e., cpp file) code and definitions for the class (that resides in the header) and substitutes in the "value" for T. However, if the cpp file compiled separately the compiler does not have it it assumes that for all the methods with the necessary "values" for T will exist as in precompiled object files. The class has two members: the output file fileName and a Boolean variable App that indicates whether the output is appended to fileName. A default value of false is used for App in the class. The constructor method is write which takes the row and column dimensions of the array pointer as arguments. Notice the use of T* const from Section 3.8 which ensures that the method does not modify the data of pData. The write method opens an output file in create/overwrite or append mode depending on the value of App. In either case a check is made to ensure that target file is open. For the first case with App = 0, the check is made using try/catch from Section 3.8. The instance of App = 1 is handled with the stream member that evaluates as false if problems are encountered in making connection to the specified output. Now us explore some of the details behind the use of exceptions in Listing 3.20. Here flags indicate input and output objects that provide information about the stream's state. These are variables with names ebit, failbit and badbit. The value of ebit is set to 1 if the end of file is reached and is 0 otherwise. Units for failbit indicate problems when reading or writing operations while badbit is set to 1 in the case of corruption of an input or output stream. It might be hoped that an exception would be thrown if any of the bits equals to 1. This is not true by default, but it can be made by using exceptions class with one or more of the bits. The bits are combined using bit-wise OR operator | evaluates to 1 if any of the bits are 1. The first write operation in Listing 3.20 illustrates that an ofstream object is created and then used to set up the conditions for throwing an exception. The argument std::ofstream::failbit | badbit will evaluate to 1 if either failbit or badbit is set. The exception class corresponds to stream objects will be thrown. The actual call to the open method is made inside a try block. If a failure is thrown, it is retrieved by the catch block and the information from its what method is output. The next listing uses the template class to write both integers and doubles to specified files.

```cpp
//Driver.cpp
#include "fileOut.h"

int main(int argc, char** argv[]) {

  int** pI = new int[2];
  double** pD = new double*[2];
  for(int i = 0; i < 2; i++){
    ppI[i] = new int[3];
    pD[i] = new double[3];
    for(int j = 0; j < 3; j++) {
      ppI[i][j] = (i + 1)*(j + 1);
      pD[i][j] = (double)(i + 1)/(j + 1);
    }
  }

  fileOut<int> outFile(argv[1], 0);
  outFile.write(2, 3, pI);

  // Now append to argv[2]
  fileOut<> outDouble(argv[2], 1);
  outDouble.write(2, 3, pD);
  return 0;
}
```
