One criticism can be directed at a functor as the one in Listing 8.2 is that it can encapsulate only one function. For example, a new functor would have to be created to containing the function ceil that returns the greatest integer that is not smaller than its argument. These two functions are of very similar nature in the sense that they both take a double argument and return an integer.” It would be nice to have a single class/struct that could hold either of these functions, or more generally, any function that takes a double argument and returns an int. One avenue for creating this type of functor is provided by function pointers.

The syntax for creating an ordinary function pointer is

```
returnType (*pFunc)(arguments)
```

This produces a pFunc that can point to any function with returnType as its type and an argument list of the same length with data types that match, in order listed for pFunc. Similarly, the pointer pFunc can be passed to a function which has a function pointer as an argument with returnType as its return type and an argument list with length and data types matching the pFunc. The pFunc pointer can be used as if it were ordinary function; writing pFunc(argumentValues) with argumentValues has the effect of dereferencing the pointer.
