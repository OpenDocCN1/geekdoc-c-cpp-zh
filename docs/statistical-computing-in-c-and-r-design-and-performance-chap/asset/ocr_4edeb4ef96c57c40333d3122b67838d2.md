The idea behind (2.6) is that any real number can be written as

```
$x = \pm \sum_{j=0}^{\infty} a_j 10^{p-j} \quad (2.7)$
```

There is no special about base 10 and the analog of (2.6) for base 2 looks like

```
$x = \pm b_0.b_1 b_2 \dots b_m 2^p \quad (2.8)$
```

with $b_0, \dots, b_m$ all having values of 0 or 1 and p, being a signed integer. As for the case of (2.6), (2.8) derives from

```
$x = \pm \sum_{j=0}^{\infty} b_j 2^{p-j}$
```

and then keeping the $m+1$ terms from the series. It is only necessary to deal with cases where $b_0=1$ means that a binary representation can always be written in the form

```
$x = \pm 1.b_1 b_2 \dots b_m. 2^p. \quad (2.9)$
```

This has the practical consequence that the value of $b_0$ need not actually be stored. Numbers represented in (2.9) are said to have normalized. The remaining part of the approximation $b_1 b_2 \dots b_m$ is called the mantissa or significand.

Let us see how an expression as (2.9) might be translated into a specific storage scheme. We will begin with a simple, nonrealistic, illustration and describe what can be expected on a typical machine.

Suppose that a number $x$ is to be stored in a floating-point representation that is allocate one byte. There are essentially four things that must be accounted for: the sign of the number, the value of the exponent of 2 in (2.9) as well as its sign, and the values for $b_1, \dots, b_m$. To account for the sign of $x$, take the least-most to be a bit with value 0 for a positive number and 1 for a negative value. The next three bits can be used to hold a two' complement representation of the exponent (that can range from -4 to 3). This leaves four bits (i.e., $m=4$) to hold the significand. To signify this idea to, e.g., the number -12.5, first observe

```
$12.5 = 2^3 + 2^2 + 2^{-1} \n = 1.1001 \times 2^3.$
```
