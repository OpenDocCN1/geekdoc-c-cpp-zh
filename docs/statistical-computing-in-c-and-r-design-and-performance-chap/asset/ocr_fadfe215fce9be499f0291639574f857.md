The matrix multiplication version of * is just the two-loop accumulation that would be expected here. The presence of two methods for scalar multiplication is for the same reason as in Listing 3.9 in Section 3.8.3. The first scalar multiplication method corresponds to multiplication of a Matrix A on the scalar b. In this case A* translates to A.operator*(b); that is, the method operator* belongs to the Matrix class and Matrix is using it with argument b. This works as expected. Problems arise when it is so fundamental to the Matrix class that if scalars had a structure it would look like b.operator*(A) and the operator could be defined as an overloaded version of multiplication for that. But, there is no scalar class and even if there were one would not make sense to specify in isolation from the other Matrix methods. In Listing 3.9, a work is obtained by defining a binary operator* that is not a class method. Once inside the function outcome is defined as A*.. Since scalar multiplication should not alter the original matrix, the Matrix argument is passed to * as a const reference. Consequently, the right-hand side of * needs to be a const member function to allow it to work with the one on the left.
