The value that goes in the b slot is the least-squares estimator for the coefficients in the regression of y on X. To create the X slot of regrCar is accessed and, since intercept is TRUE, the number of elements is added to the matrix so that the regression will include an intercept term. For now it is enough to know that a call to solve(A, v) will return the b of the system Ab = v provided that A is a nonsingular matrix. In particular instance, solve is applied with A = matrix, v = t(cbind(1, regrCar@X))%regCar and the resulting solution is assigned to the b slot of regr. A point of interest here is the use of drop on cbind(1, regrCar) on the right-hand side of the linear system being handled by solve. The problem here is that the multiplication of regrCar@y by the matrix object(cbind(1, regrCar@X)) promotes the object to matrix status which has been given to the b slot. One approach would be simply to coerce the outcome into the right by using the drop function that will delete the extra dimension from an array that has only one column or row. Using the new operator directly for construction of every object of a particular class can be tailored to particular situations frequently in practice. As in C++, constructor functions will generally have the same name as their class and involve arguments that are required to create an object in some particular situation. Constructor are created in the same way as one in R. A constructor for the regr class might look like

```R
regr <- function(X, y, intercept = TRUE) {
  regrCb <- new("regr", X = as.matrix(X), y = as.numeric(y))
  intercept <- intercept
  if(intercept){
    XTX <- t(cbind(1, regrCb@X))*%reggrCb@X
    regrCb@b <- solve(XTX, drop(cbind(1, regrCb@X)))*%regrCb@y)
  }
```

To make sure that the input data is appropriate for an object from a user-created class one can use the setValidity function. The code below employs this function to check the row length of the X and y slots as well as the appropriate

```R
setValidity("regr", object){
  if(nrow(object@X) != length(object)){
    return("The number of rows for X and y differ")
  }
  if(object@intercept){
    if(qr(cbind(1, object@X))$rank < ncol(object@X)+1){
      return("The matrix is singular")
    }
  } else{
    if(qr(object@X)$rank < ncol(object@X)){
      return("The matrix is singular")
    }
  }
  return(TRUE)
}
```

## CREATING CLASSES AND METHODS IN R

One of the polymorphic features of an object-oriented language is the ability to have inherited classes that extend a base class. The inheritance mechanism in R is fairly straightforward unless the specification of an additional argument contains for the setClass function. For our purposes, contains will be a character string that gives the name of the parent class. To illustrate in R, suppose that it is of interest to extend the regr class by including an additional member corresponding to the values. Again, there are already tools for this purpose to include it as a slot in the original regr class. For the purpose of illustration we will ignore these issues and proceed as if there is a valid reason for distinguishing between regr object types that do or not fit to the data.

Let us consider our new class regrFit. The class is created similarly to the regr class using

```R
setClass("regrFit", contains="regr", representation = list(yhat = "numeric", prototype(yhat = 0)))
```

This differs from our creation of the regr class through the presence of the contains argument in setClass that has been set to regr indicating that regrFit is a derived class for regr. Objects of the regrFit class will automatically inherit all the slots of the regr class: namely, X, y and intercept. It is only necessary to define the new slot for the values that has been named yhat.

The next step is to create a class constructor as

```R
regrFit <- function(X, y, intercept = TRUE){
  fitObj <- regr(X, y, intercept)
  fitObj <- as(fitObj, "regrFit")
  if(fitObj@intercept)
    fitObj@yhat <- drop(cbind(1, fitObj@X))*%fitObj@b
  else
    fitObj@yhat <- drop(fitObj@X*%fitObj@b)
  fitObj}
```

The arguments for the constructor are the the same as those for the regr class. Now, there is no reason to start from scratch as we already know how to create regr objects. To make use of this fact a regr object is created first with the regr constructor and is coerced or promoted to the regrFit class using as function.
