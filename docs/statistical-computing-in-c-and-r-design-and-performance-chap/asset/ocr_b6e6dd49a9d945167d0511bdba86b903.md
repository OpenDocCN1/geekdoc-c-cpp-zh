As is the case for MPI, Rmpi is designed for use in distributed memory settings. At present, there is no extension of OpenMP for R. An effective way to use R in a shared memory context is available through the multicore package that provides a parallel version of the R function called mclapply. This allows different elements of an input list to be handled by different processors. The syntax for mclapply is

```
mclapply(X, FUN)
```

with X to which the function FUN is applied. The default behavior is to portion the entire job sequentially across the processors/cores that are available in the system. If X has more elements than the list while the second processor applies FUN to the first component of the list while there are more cores, multiple elements will be assigned to some (or all) of the processors.
mclapply function can be used, for example, to carry out the selection calculations that are featured in the Rmpi example. The first step is to load the library and determine how many processors are available on the system.

```
> library(multicore)
> multicore::detectCores()
[1]
```

The :: syntax as appears here is for of namespace/scope resolution operator similar to the one discussed in Section 5.3. This one allows access to the internal variables in a namespace while :: accesses only those variables in a package that have been exported or made public. Here we are using :: to obtain access to the function detectCores in the multicore package. The output illustrates that the machine used for this example has four cores. Similar to our Rmpi formulation, each of these cores will be used to analyze different collections of subsets from the indexList object.
