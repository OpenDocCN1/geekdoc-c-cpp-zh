Unlike the integer case, extracting the binary representation of a floating-point number is a tricky thing. This is due to the fact that the bit-wise operators in the integer case cannot be used directly with floating-point numbers. A standard recommendation for an end run around this difficulty looks something like the code in the list below.

```cpp

void printbinary(char val) {
    for(int i = 7; i >= 0; i--) {
        if(val & (1 << i))
            cout << "1";
        else
            cout << "0";
    }
}

int main() {
    float f;

To conclude this section we will briefly discuss the methods of addition/subtraction multiplication of floating-point numbers. Consider the first multiplication of $x_1$ times $x_2$

```
x₁ = 1.b₁···bᵢm²ⁿ
```

for $i = 1, 2$. To compute the product $x_1x_2$ exactly there are 2 steps: 1), add the two exponents and 2) multiply the two significands $1.b_1...b_i$ and $1.b_2...b_j$. This last step results in $2^m$ binary number of the first $1.c_1...c_{m+1}$. The answer is

```
x₁x₂ = 1.c₁…c₂₊₁
```

Of course, if $m$ bits are available for storage, this answer must be rounded and even the evaluation of coefficient $c_{m+1}$ would be problematic. The use of extended precision for doing the computation prior to rounding is one way to solve this. But, other approaches are used in practice in the next section. Now adding $x_1$ and $x_2$ this process is more involved as a result of the common denominator that must be used to carry out addition as illustrated under our eight-bit floating-point scheme. Assume that $p_1 > p_2$ and then shift $x_2$ to form

```
x₂ = 0.0 \cdots b_{21} \cdots b_{2m}
```

with $p_1 - p_2$ bits being counted from the first bit on the right side of the decimal. The sum or difference can now be computed through binary addition or subtraction of the original $x_1$ and shifted $x_2$ significands with the result being rounded to $m$ bits to the right of the decimal. There are practical considerations that arise in terms of how to store the shifted version of $x_2$ and problems arise if only $m$ decimal bits are used. Guard bits (e.g., sticky) can be used to deal with such issues.

# ERRORS

As the last section, most numbers cannot be represented exactly in floating-point format. In this section we will explore the consequences of computations that are carried out in binary arithmetic. First let us address the losses that arise from conversion of a number to its floating-point representation. It is possible to place bounds on the amount of error that can be incurred. The bounds are, of course depending on the type of “rounding” that is employed. The simplest approach is truncation or chopping. So, suppose that $x$ is a positive real number that can be written

```
x = \sum_{j=0}^{\infty} bj 2^{p-j}
```

with $b_0 = 1$. Then, *chopping* replaces $x$ by the approximation

```
\tilde{x} = \sum_{j=1}^{m} bj 2^{p-j}
```

for some integer $m$. The error that is incurred by this approach is

```
x - \tilde{x} = \sum_{j=m+1}^{\infty} bj 2^{p-j} \le 2^p \sum_{j=m+1}^{\infty} 2^{-j} = 2^{p-m}.
```

Instead of choosing an alternative approximation $\tilde{x}$ can be produced by rounding to the value that is closest to $x$ in the sense of minimizing $|x - \tilde{x}|$. This cuts the bound in half for $2^{p-(m+1)}$ as we now demonstrate. First observe that the *round-to-close* value for $\tilde{x}$ is obtained by increasing $b_$ by one if $b_{m+1}=1$ and using the chopped approximation otherwise. Consequently,

```
\tilde{x} = 2^p \sum_{j=0}^{m} bj 2^{p-j} + \hat{b}_{m+1} 2^{-(m+1)}
```

with $\hat{b}_{m+1}$ being either two or zero depending on or not $b_{m+1}$ is 1 or 0, respectively.

Thus, when $b_{m+1} = 1$ the error is

```
|x-\tilde{x}|=2^p 2^{-(m+1)} - \sum_{j=m+2}^{\infty} bj 2^{-j} \leq 2^{p-(m+1)}.
```

On the other hand, if $b_{m+1}=0$, $x-\tilde{x} \leq 2^{p-(m+1)}$ from our analysis of rounding by chopping. Observe that, since $|x| \geq 2^p$, to translate the previous bounds to relative absolute error, observe that,

```
\frac{|x-\tilde{x}|}{|x|} \leq 2^{-(m+1)} \quad (2.12)
```

for round-to-closest value and

```
\frac{|x-\tilde{x}|}{|x|} \leq 2^{-m}
```

for chopping. These values are sometimes referred to as the machine epsilon. An application of (2.12) to the IEEE floating-point format gives error bounds on the order of $2^{-24} \simeq .6(10^{-7})$ for single precision and $2^{-53} \simeq 10^{-16}$ for double precision arithmetic (Exercise 2.8).
