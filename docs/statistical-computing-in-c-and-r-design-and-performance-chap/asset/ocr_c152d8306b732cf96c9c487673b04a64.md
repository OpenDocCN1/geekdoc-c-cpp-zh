# Algorithm 9.2 quickSort(A, left, right): Sort array elements A[left],...,A[right]

```
low = left, pivotIndex = [(left + right)/2], pivot = A[pivotIndex], high = right
while low <= high
  while pivot > A[low]
    low = low + 1
  end
  while A[high] > pivot
    high = high - 1
  end
  if low <= high
    temp = A[low], A[low] = A[high], A[high] = temp
    low = low + 1, high = high - 1
  end
  if low < right
    quickSort(A, left, right)
  end
  if left < low - 1
    quickSort(A, left, low - 1)
  end
```

The algorithm starts with low and high as the left-most and right-most array indices, respectively, and takes the pivot to be the value of the entry in a “middle” array index. It then moves the low index across the array until it encounters an element whose value is greater than or equal to the pivot succeeded by a decrease of the high array index until low is less than or equal to high the array elements are swapped. Otherwise, the subarray composed of those elements with indices low or larger will remain. A recursive call can then be made to quickSort using this subarray as the array argument. Similarly, the values in the subarray constructed from elements less than low will be all smaller than equal to the pivot and the quickSort function can be applied to all elements.

The average running time for quick is proportional to n log n for an n-element array. To assume n=2^k for some integer k and the pivot index falls at the center of the array in each step of the recursion, the first partitioning will require n operations to produce two arrays of size 2^{k-1}. These two arrays, in turn, each need O(2^{k-1}) flops to produce subarrays giving a total of four arrays of size 2^{k-2}, which will require a total of order n operations to advance to the next stage of the recursion. This remains true at every step in the recursion which means the overall effort is on the order of nk = n log n. It may be proved that, assuming the initial order of elements in the array is random (regardless of what the elements' values are really), the expected number of comparisons in quicksort is O(n log n) (see Exercise 9.6 or Corm, et al. 2003).

On the other hand, the worst case in running time for quicksort occurs when the partitioning always produces a subarray of size one. If this happens, either the low or high index will remain at left or right, respectively. For an array of size n this gives to n+1 comparisons: one comparison with the stationary index (either left or right) and the pivot and the n comparisons that occur as the other index works down or up the array.
