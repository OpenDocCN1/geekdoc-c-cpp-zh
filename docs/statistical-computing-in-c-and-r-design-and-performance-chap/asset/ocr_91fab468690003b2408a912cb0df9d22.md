# LEHMER TYPE GENERATORS in C++

Listing 4.1 contains a simple utility function that computes the value of an integer raised to a specified power. This function gives an illustration of using the C++ recursion capability that allows a function to call itself (Exercises 3.7-3.10). Notice that the function returns unsigned long and, accordingly, must return an unsigned long via a return statement at (or before) the end of the function's scope; it must return a value in the range of statements that appear between the two braces containing the body of the function. The unsigned long int type will give eight bytes of size which is needed (exactly) all the integer values used in the generator. One may check that the four bytes available with the int type are not enough and the resulting code could produce unusable output.
As PRNG implementations go, one leaves a lot to be desired. First, only one returns one number, and as from the results of running the program, it gives the same "random" every time. These shortcomings are easily fixed by allowing for user input. This can be done either by using line arguments or by cin from the iostream library. A possible implementation that allows for input of both the seed and the value for a sample size might appear in Listing 4.1 with the alternative main program section below.

```
int main(int argc, char* argv[]) {
unsigned long a = 63063006;
unsigned long seed = 0;
int n = 0;

cout << "Choose a value for the sample size:" << endl;
std::cin >> n;
cout << "Choose a value for the seed:" << endl;
std::cin >> seed;
unsigned long m = power(2, 31) - 1;

cout << "Your random numbers are " << endl;
for(int i = 0; i < n; i++) {
seed = (a*seed)%m;
```

Our modification of Listing 4.1 certainly represents an improvement over what the program could do. But, it still falls short of what might be needed from someone whose purpose is to generate a collection of random numbers. Although the actual numbers can be accessed or saved by redirecting the program's output to a file rather than the shell, the numbers are not retained in the program and, as a result, cannot be used in further calculations. In the grand scheme of things, a program like this would typically be used as a utility to generate random uniform devices for use in other settings. So, it really needs to be of a reusable nature that allows it to be easily called whenever it is needed.
