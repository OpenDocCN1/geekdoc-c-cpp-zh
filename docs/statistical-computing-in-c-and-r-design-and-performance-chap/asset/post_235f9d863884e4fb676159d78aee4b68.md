In instances it is useful to suppress the printing of output. The invisible function is invisible to the object or objects returned by a function; the output will then be returned but not printed. The function below represents another attempt at recreating R's sign function.

```r
f <- function(x) {
  if(x < 0) return(-1)
  if(x > 0) return(1)
}
```

Output from using this function might look like

```r
> f(-1); f(1); f(0)
[1] -1
[1] 1
[1] 0
```

In contrast, a reworking of f as

```r
f <- function(x) {
  if(x < 0) return(-1)
  if(x > 0) return(1)
  invisible(0)
}
```

uses invisible in strategic locations to produce

```r
> f(-1); f(1); f(0)
[1] 1
> 2*f(1)
[1] -2
```

- b) how to apply them.

There is no easy fix for part a) in R is a rich language that comes equipped with many functions. There are numerous texts about R and packages show how to increase one's R function "vocabulary". Examination of the code for R functions can also be a learning experience. There is somewhat more than can be said about part b) and this section explores that through discussion of the apply of functions and the outer and vectorize functions.

The apply function is discussed in Section 1 of Appendix B. It applies a specified function to the rows or columns of an array. There are also lapply and apply functions that operate on lists. These two functions have the same basic prototype: e.g.,

```r
lapply(X, FUN)
```

With X being a list object and FUN the function that is be applied to its components. The difference is in the output; lapply returns a list while apply returns a vector or matrix object possible. Results from an R session illustrate this difference.

```r
> A <- list(1:10, 20:30)
> lapply(A, FUN = sum)
[[1]]
[1] 55

[[2]]
[1] 275
```

The R function that was used is discussed in Section 1 of Appendix B.

The mean comparison of the previous section is one instance where apply and apply can be used to produce more efficient code than loop implementation. With this mind we write a function to carry out pairwise comparisons.

Listing 5.3 meanComp.r

```r
meanComp <- function() {
  indexList <- list()
  # fill indexList with all index pairs
  count <- 0
  for(i in 1:ncol(A)) {
    for(j in (i+1):ncol(A)) {
      indexList[[count + j - i]] <- c(i, j)
      count <- count + ncol(A) - i
    }
  }
  # compute the statistics for the columns
  meanVec <- apply(A, MARGIN = 2, FUN = mean, na.rm = TRUE)
  varVec <- apply(A, MARGIN = 2, FUN = var, na.rm = TRUE)
  nVec <- apply(A, MARGIN = 2, FUN =
    function(e) length(e) - sum(is.na(e)))
  # compute the t statistics
  apply(indexList, FUN = function(e) {
    n1 <- meanVec[e[1]]
    n2 <- meanVec[e[2]]
    Diff <- meanVec[e[1]] - meanVec[e[2]]
    n <- n1 + n2 - 2
    sdFactor <- sqrt((n1-1) + n2-1)
    pooled <- sqrt((n1-1)*varVec[e[1]] + (n2-1)*varVec[e[2]])n)
    Diff/(sdFactor)
  })
```

Another useful function for avoiding explicit R loops is outer. The name derives from its application to compute product of vectors or matrices. Given vectors a and b of dimensions n and m, respectively, their outer product is defined as the n x m matrix whose (i,j) is the product of the ith entry of a and the jth entry of b. The outer product of two vectors in R is written as a%. For example, the 10 multiplication table may be generated by invoking the outer product operator

```r
1:10 % 1:10
```

In fact, %% is a wrapper for the more general function outer that has prototype outer(X, Y, FUN) with X and Y typically vector or to catch an analog of %% on the X and Y objects where multiplication is replaced by the operation specified in FUN. Thus the output of outer is a matrix of length(X) x length(Y) generating elements of the FUN(X[i], Y[j]). By choosing X=Y=(1:10) and FUN = "*" reproduces the multiplication table that was previously obtained via %%.

In Listing 5.3 an array of index pairs for the columns of the data matrix was created that was used to determine which means were to be compared. An alternative spin on our mean comparison demonstrates how outer provides a means of bypassing explicit construction of such an index array.
