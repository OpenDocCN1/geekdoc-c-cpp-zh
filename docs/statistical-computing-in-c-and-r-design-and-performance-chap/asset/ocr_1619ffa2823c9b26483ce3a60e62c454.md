# ABSTRACT DATA STRUCTURES

lookup method is first applied to the key value for the input newPair object to obtain a target storage location. There are two things that can happen: either lookup returns the index of an empty slot or the slot is occupied which means the input key already exists. In the latter instance "error" index of -1 is returned. Otherwise, the new object is inserted at the hashed key and the Size member is augmented by 1. As with the lookup method, unnecessary output has been built into the function to allow us to track the hashing process in a test case.

A driver program with the main function below was used to illustrate the operation of our hashTable class.

```
int main() {
  htTable(53, 13);
  ht.insert(newPair(213, 10));
  ht.insert(newPair(54, 11));
  cout << ht.getData(54) << endl;
  return 0;
}
```

A request is made for a table with 53 slots and the Shift value is set to 13. Then, two newPair objects are inserted into the table and the Data component of the second object is accessed. The output produced by the program is

+   213 hashes to 1
isNull is true
Inserting at 1
54 hashes to 1
isNull is false
Collision at 1
Next try 14 that hashes to 14
isNull is true
Inserting at 14
54 hashes to 1
isNull is false
Collision at 1
Next try 14 that hashes to 14
isNull is false

213 = 53 * 4 + 1, 213 mod 53 = 1 and the first key value hashes to 1. The array slot with index i is empty (its., isNullMember evaluates to true) and a newPair object with data component of 10 is inserted at that point. The second object has a key of 54 that also initially hashes to. The slot is full (isNull is false) and the key of 54 for the new object is not the same as that of the occupying one (i.e., 213). So, the search with a new hash value 1+13 hashes to 14. This slot is empty and the newPair object with data component 11 is inserted into the table at that location. The loop in lookup being terminated when a slot's isMember is found to find an empty slot with true. the request for the data value of the key with 54 goes in the other direction; the search is for a specific, nonempty slot. The hashing process proceeds exactly the same steps as the targeted object was inserted: initially hashing to 1 before the probe shifts it slot 14. In this case the isNull member's key value still evaluates to false; but, the loop ends when a comparison of the element's key value with the one being sought true. The requested data value is then retrieved successfully.
