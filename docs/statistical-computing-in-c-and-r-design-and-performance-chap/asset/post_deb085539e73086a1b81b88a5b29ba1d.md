As it is used both to generate the service times for arrivals in the Server objects as well as the number of arrivals from the Poisson distribution. The latter application stems from Algorithm 4.5 which derives from the fact that the waiting times for arrivals in a Poisson process with mean λ are independent and exponentially distributed with mean 1/λ. As a result, generating values from this exponential distribution until their sum exceeds some fixed time t, we have realized a set of arrivals from a Poisson process over the interval [0,t]. The corresponding value for the Poisson random is the penultimate number in the sum.

After all the available Server objects (should any exist) have been assigned a Customer object, it becomes necessary to push any new Customer objects onto the queue using the priority_queue push method. These customers count in the sense that they have to wait and, hence, numberCustomer variable must be increased by the number of objects that have been added to the queue. The actual Customer objects have been initialized with the current time and a value for their Gold member determined by

```cpp
bool MMqueue::isGold() {
double u = 0;
Rng.ranUnif(1, &u);
if(u < goldProb)
return true;
return false;
}
```

This function uses the MMqueue object's ran member to simulate a Bernoulli random variable with probability goldProb.

The final step in update is to see if any Server objects have become available that can be assigned to the elements in the queue with the highest priority. The freeServer method is used to search for an available Server object, if found, its Busy value is set to true and a value for its serviceTime is generated from an exponential distribution with parameter lambdaExp. For each available Server object, a Customer object is removed from the queue in two steps. First, the priority_queue method is used to find the arrival time for the member at the top of the queue. The difference between this value and the current time is the length of the Customer object waited and this value is added to the waiting time totalTime. Next, the same highest priority element is removed from the queue with the pop method.

# THE MAP AND SET CONTAINERS

The STL provides four variants of ordered set structure: map, multimap and multiset. All container types are implemented using red-black trees. The map types provides the same basic set of operations that it suffices to pick one for exposition purposes. Accordingly, our discussion will focus only on the map container.

Access to the map container class is achieved through the include directive

```cpp
#include <map>
```

Then, an empty map object is created with the syntax

```cpp
map<Key, Data>;
```

With Key and Data the names of the data types that provide the key and data components of the nodes stored in the container. Objects of type Key are assumed to possess an inherent ordering that is quantified via a definition of the < operator for the class. It is also possible to provide a user-supplied function to be used in making comparisons an argument to one of the alternative class constructors. That option will not be explored here.

As true of the Tree in Section 9.4, map containers can be filled using their insert method. The basic operations used in insertion are from the pair class that was described in Section 9.2.4.2 map<Key, Data> object,

```cpp
m.insert(pair<Key, Data>(key, data));
```

will add a node to the tree with key value and its Data module and return an iterator that points to the position of insertion.

Look-up operation for a map container is carried out by the find method. This function takes an object of type Key as its argument and returns an iterator to either the position of the located object or end() if no object with that value exists. An indexing operator [] is also provided as an alternative to find. For a map object m[key] will return a reference to the Data member of the pair in the tree if it exists. Unlike find, if the specified Key value does not exist, a new node is inserted into the map with the given Key value and its Data component determined from the default constructor for the Data class. Because it returns a reference to the Data member, provides a means to modify an existing node or insert a completely specified new node into the map.

m[key] = data;
