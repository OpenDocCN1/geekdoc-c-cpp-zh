this matrix is first created that contains the information to be used in regr object:

```
> A <- as.matrix(c(1, 3, 6, 7))

The desired regr object could be obtained from

```
> regrCar <- new("regr", X = A[2:4], y = A[1])
```

The slots of object can be accessed using the @ operator or the function slot. Thus, if Obj is an object with a name s, Obj@ or slot(obj, "@") will return the contents of that particular slot. The code listing below how @ and slot can be used to fill and the b slot for the regr object that was created with the mtcars data

```
> XTX <- tbind(1, regrCar@X)%%tbind(1, regrCar@X)
> regrCb <- solve(XTX, drop(tbind(1, regrCar@X))%%regrCar@y)
> regrCb@
```

The value that goes in the b slot is the least-squares estimator for the coefficients in the regression of y on X. To create the X slot of regrCar is accessed and, since intercept is TRUE, the number of elements is added to the matrix so that the regression will include an intercept term. The resulting X'X matrix is evaluated, stored as XTX and calculated using R solve. This function will be discussed in more detail in the next chapter. For now it is enough to know that a call to the solve(A,v) will return the b of the system Ab = v provided that A is a nonsingular matrix. In particular instance, solve is applied with A = matrix, v = tbind(1, regrCar@X)%%regrCar@y and the resulting solution is assigned to the b slot of regr. A point of interest here is the use of the drop on tbind(1, regrCar) on the right-hand side of the linear system being handled by solve. The problem here is that the multiplication of regrCar@y by the matrix object(tbind(1, regrCar@X)) promotes the object to matrix status which has been given to the b slot. One approach would be simply to coerce the outcome into the right by instead using the drop function that will delete the extra dimension from an array that has only one column or row.
Using the new operator directly for construction of every object of a particular class can be tailored to particular situations that frequently in practice. As in C++, constructor functions will generally have the same name as their class and involve arguments that are required to create a object in some particular situation of interest. Constructor are created in the same way as one in R. For a constructor for the regr class might look like

```

regrCb <- new("regr", X = as.matrix(X), y = as.numeric(y),
intercept <- intercept

XTX <- tbind(1, regrCb@X)%%tbind(1, regrCb@X)

}
