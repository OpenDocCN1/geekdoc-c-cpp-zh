The utility of the diagonal matrix constructor for the pdBand is limited to its default route. In this regard, it uses a default value of -1 for q. Since the number of columns is q + 1, this has the effect of producing an inherited Matrix object with nRows and nCols as zero and, hence, a null pointer for pointer-to-member.

The destructor in class Matrix was designated as virtual. Declaring the virtual is generally a good practice when developing an inheritance relationship. Even though destructors are not inherited, the base class destructor will be called when an object goes out of scope. The default behavior for destruction of a derived class is to proceed in reverse order through the inheritance chain moving downward through the hierarchy of children unless the base class is reached. In the case of a pdBand object this means that the pdBand destructor will be called prior to that of the base class Matrix. In most instances this will work. However, it is possible to have a pointer for a base class to a derived object. In cases, only the base class destructor will be called when the pointer goes out of scope. If memory allocated in the derived class the result would be a memory leak. By making the base class destructor virtual the destructor of the heir will adapt to the type of the object pointed to rather than the type of the pointer. For the case of a pdBand object, the new data member is the integer q which needs no special treatment. Thus, the body of the destructor for the pdBand class in line 21 of Listing 7 is left empty.

Matrix pdBand::bandToFull() {
int nRows = this->getnRows();
double**pTemp = new double*[nRows];
for(int i = 0; i < nRows; i++) {
    pTemp[i] = new double[nCols];
    for(int j = 0; j < nCols; j++) {
        if(j <= std::min(nRows, i + q))
            pTemp[i][j] = (this->data)[i][j];
        else pTemp[i][j] = 0;
    }
}}
