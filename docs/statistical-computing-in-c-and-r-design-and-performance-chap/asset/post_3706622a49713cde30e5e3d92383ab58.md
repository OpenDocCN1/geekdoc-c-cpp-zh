
## APPENDIX A

## An introduction to Unix

In this appendix we will give a brief overview of some of the basic Unix commands. More detailed treatments are provided in a myriad of on-line tutorials and texts such as Kochan and Wood (2003).

The focal setting in this appendix is the command line of a Unix shell; although, much of the work in this text can be accomplished using various graphical user interfaces, the command line is always available even in remote logins. So, it is worthwhile to know how to work in that environment.

The interface between a user and the Linux operating system is provided by a command line interpreter generally referred to as the shell. There are a number of shell options that include Bourne (sh, bash and tsh) type, C (csh and tsch) type and Korn (ksh) shells. They each represent programming languages whose purpose is the interpretation of Unix commands that are entered on the shell line located at the shell prompt often takes the form of a $ or %. We will employ the bash shell exclusively in our work. It may be started by entering

```
$ bin/bash
```

on the command line.

Unix makes it possible to transfer and copy files, compile code, start applications, etc. These general commands have the form

```
commandName -option arguments
```

with commandName being a single, case-sensitive, “word" consisting of a few letters that often abbreviate the command’s purpose. A command may or may not involve additional options. The details behind such additional specifications can be obtained by referring to the command’s associated manual page by entering

```
man commandName
```

on the command line. A related, but sometimes different, set of information can be accessed by info commandName. If you can remember a command’s name but not recall what it does, that information is returned by entering what commandName. If you only remember part of a command commandNamePart, then apropos commandNamePart will search the whatis database for occurrences of the string commandName.

Disk memory is organized in Unix as a tree structure. It begins with the root directory or that represents the top of the tree and subdirectories branch from the root. These subdirectories have further subdirectories, etc. When you first log in, the shell will open up your personal home directory which has a name like

```
/home/yourUserName
```

or

```
/Users/yourUserName
```

with your UserName the user name you have given on the system. Your current location in your directory tree can be obtained by entering pwd (for present working directory) on the command line.

Starting from our original login location we would like to go various places and accomplish various things. Commands for such purposes will be discussed in subsequent sections. The presentation is organized by groupings of commands with similar or related purposes.

### A.1 Getting around and finding things

The main tool for moving from point A to point B in Unix is the change directory command cd. For example, by entering

```
cd pathToDirectory/directoryName
```

you will move from your current location along the path specified by pathToDirectory and end up at directoryName on the Unix tree. There are various shortcut ways to specify a path. But, what works is a list, separated by '/' starts at the root directory and details every stop along the way from the root to the location of interest. In general, this is what we refer to as a path throughout the text. For example, the command cd /usr/local/share will take you from your current location in the directory tree to the share subdirectory by going from the root / to the subdirectory usr and then to its sublocal directory.

A very useful shortcut is the ~ symbol which can always be used in place of the name for your home directory. Some related shortcut commands that come in handy are:

```
cd .. moves you one level lower to the root and
cd without an argument, which always returns you to your home directory.
```

### A.2 Seeing what’s there

So, now you have arrived at a location (or know of location of interest) and would like to find out what is there. The list command, ls, can be used for this purpose. Specifically:

```
ls pathToDirectory/directoryName
```

will provide a list of all the files in the directoryName reached by pathToDirectory. More generally,

```
ls -l pathToDirectory/directoryName
```

gives a complete listing that, from left to right, the following information for each file in the directory:

- - read, write and execute permissions (that will be discussed in more detail below),
- the number of hard links (i.e., the number of directory entries that reference the file or directory),
- the owning user,
- the owning group,
- the size of the file or directory in bytes,
- creation date and
- the file or directory name.

It turns out that neither ls nor ls -l tell the whole story. Many times there are files in your directory that begin with a . such as .bashrc and emacs. To see these you have to use ls -a. Using ls without a path specification returns the result of applying it to the current directory.

### A.3 Creating and destroying things

So far our interaction with Unix has been relatively static. But, things become much interesting once you can create and delete files. The simplest way to create a file is through the touch command which creates an empty file upon entering

```
touch fileName
```

To delete fileName, employ the remove command, rm, like

```
rm fileName
```

One of the most important things to create is a directory the make directory command-mkdir, can be used to accomplish this. For example,

```
mkdir directoryName
```

adds a new directory to the current directory. This directory may be-moved using the remove command rmdir with

```
rmdir directoryName
```

provided directoryName is empty. If this is not the case, it must be emptied a application (i.e., the -r option) of rm. Specifically,

```
rm -r directoryName
```

removes directoryName as well as all its contents.
Life would be quite complicated if all files had to be created from scratch. The copy command keeps us from having to do this by allowing to copy files from one to another. To copy a fileName pathToDirectory to a new fileName pathToDirectory

```
cp pathToDirectory/fileName pathToTargetDirectory
```

To move, rather than copy, the file one uses the move command in the form

```
mv pathToDirectory/fileName pathToTargetDirectory
```

Output redirection is useful for a variety of purposes. One of these is creation of files from a program. Output redirection is achieved with the > symbol using syntax as

```
command options arguments > fileName
```

For instance, write the contents of the file for the pwd into the text file temp.txt. The purpose of the cat command is concatenation of files. When used in conjunction of an output redirection sequence such as

```
cat temp.txt temp2txt temp.txt
```

create a new file temp.txt consisting of the file temp1.txt with temp2.txt appended to its end.

In order to copy and move files you must have permission to use them in such operations. Information about the permissions associated with a particular file or files in a directory can be obtained through the ls -l version of the ls command. As noted, this produces a variety of output which includes the permissions for the file, 10 character, component of the line associated with any particular file.
Permission information provides the details concerning who and cannot access a file or in directory. The first character in the string indicates the type of file is with d indicating a directory, 1 meaning a symbolic link and representing a common file. Characters 2-4 determine what the owner can do (i.e., r) write (i., w) and execute (i.e., x) the particular file. A – any of the slots permission is denied for that activity. The next three slots, characters 5-7, convey exactly the same information concerning permissions for the owning group with slots 8-10 giving the permissions allotted to all other users. Thus, a 10-character string corresponding to a fileName of the form

```
-rwxxr --
```
