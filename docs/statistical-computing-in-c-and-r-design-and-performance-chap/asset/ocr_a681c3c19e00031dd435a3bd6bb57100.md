# MISCELLANEOUS TOPICS

```
int main(){
  X x; Y y;
  return 0;
}
```

The initial line of code, struct Y;, that appears in Listing 3.10 would seem to be of questionable value and not particularly informative. This type of statement is known as a forward declaration and actually serves an important purpose. It tells the compiler that a struct Y exists that will be defined at a later point. In its present this list compiles and executes without a problem. Commenting out the forward declaration will produce a compile error that contains a statement as this

```
compiler.cpp5: error: ISO C++ forward declaration of 'Y' with no type
```

In for the X struct to use Y the compiler simply must know that the Y exists and the forward reference solves this problem. One course, this solution might be to just define the Y first, rather than defining it. But, the Y struct in this case X moves around the "circle" and a forward declaration of the X struct would be required before this alternate arrangement could be operable.
There is more going on in Listing 3.10 than just the use of a forward reference. Y objects arise in the X struct in form of pointers or references. If this is changed the case seeing that no details of Y have been supplied when the compiler encounters the definition of the X struct. If an actual Y is to be a member of the X struct or a method or return type, the compiler needs to determine how much memory to allocate or require a priori: namely, the four or eight bytes that is needed to hold an address. For similar reasons, if the Y struct definition were moved ahead of the X struct the resulting code would fail to compile even with the inclusion of a forward reference to the X struct. This happens because Y requires X objects by value.
While the positioning of the X and Y objects is somewhat inconvenient here, the problems arise in a more general context can be realized through restructuring the Listing 3.10 into separate files with separate headers. For the X struct we use
