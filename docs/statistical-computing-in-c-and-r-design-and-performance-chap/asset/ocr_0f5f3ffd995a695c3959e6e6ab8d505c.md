As discussed, the x argument is a g5List object and y is a list with the machine or machines to use in comparison as its first component and the numbers for the ball sets as A default value has been provided for the y argument that will result in the analysis of the entire data set i.e., a chi-square statistic will be calculated for the draws produced using both machines and all 10 ball sets. The R help page for setMethods states that in order for a default argument to be used in a method function "generic function must have some default expression for the same argument". Since, noted above, this is true for the y argument in the chisq.test function, the default list can be provided with a suitable signature when we define the method.

The initial step is to use the chisq.g5List function to extract the g5 objects from the x argument. Then, similar to the developments in the g5List constructor, supply is to obtain a vector of characters and a vector of integers that give the machines and ball sets for the g5 objects in the data. element function is applied to these vectors using y[[1]] and y[[2]] lists. The result is two vectors of logical variables, tempM and tempY, whose entries are TRUE or FALSE of whether or not the element's value is set by the machine component y[[1]] and set component y[[2]] of the y. Multiplication of logical variables 0 (if either of the vectors is FALSE) or 1 (if both are variables) produces TRUE. Thus, the result of tempM and tempY will have 0 entries for those g5 objects whose name and slots contain values that were in the intersection of y[[1]] and y[[2]]. The .logical function returns these values to TRUE and FALSE form. The subsetting feature for R lists the consequence when using logical variables is the operator, the output will be a subset corresponding to the elements of the list for which the index evaluates as TRUE. From this point the development proceeds along the lines of Section 5.6 exactly the analysis is working with a subset, rather than the entire collection of data.

We now establish chisq.g5List as a method function for chisq.test with
setMethod("chisq.test", signature(x = "g5List", y = "ANY",
+ definition = chisq.g5List)
[1] "chisq.test"

Our choice for signature requires a bit of decision. As a rule, our calls to chisq.test will involve two arguments with the first being a g5List object and an R list object. However, for a use the default argument that was supplied for the method function, the second argument will be missing. Thus, we need a signature that will match (x = "g5List", y = "list") and (x = "g5List",
y = "missing"). An option that works is (x = "g5List", y = "ANY")
