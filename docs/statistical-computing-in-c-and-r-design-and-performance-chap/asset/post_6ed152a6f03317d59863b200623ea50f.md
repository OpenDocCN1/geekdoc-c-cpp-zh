## 9.4.2 Balancing binary trees

Binary trees can become unbalanced which makes them computationally inefficient. Figure 9.10 illustrates such case. Whereas sequential insertion of the integers from 1 to 15 has led to an inefficient, unbalanced search tree instead of a maximum of fifteen comparisons, the data set is represented by the perfectly balanced search tree in four comparisons suffice to find any.

There are several ways to maintain the balance of a binary search tree under any arbitrary sequence of insertions and deletions. One of the frequently used approaches is as a red-black tree and requires each node in the tree to have an associated "color" attribute. The arrangement of these "colors" in the tree must satisfy a certain invariant. Specifically,

- the root is "colored" black,
- any child of a red node is black
- every path from the root to a leaf has the same number of black nodes.

These conditions imply a balance property of the red-black tree: namely, the lengths of any two paths from the root to a leaf are within a factor of 2.
