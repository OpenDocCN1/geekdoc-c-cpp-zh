The R package provides functions that can be used for bootstrapping. In particular, the boot function has this simplified prototype

```
boot(data, statistic, R)
```

The argument `data` is an array of data that will be used in the inferential process while `statistic` is the function that will be applied to data. The function specified for `statistic` must have two arguments: a data array and an array of indices that specifies the subset of the data that will be used to calculate the statistic. The `R` parameter is the number of bootstrap samples generated by $B$ in the above developments.

As an example, the function `med0` in the listing below can be used to provide an approximation to the null distribution of the sample median under the hypothesis that the median is zero.

```
med0 <- function(y, indices){
  x <- y - med(y)
  median(x[indices])
}
```

The centering of $y$ is so that the sample will behave like data from the null model when resampling takes place. An illustration of how this might be used by the following:

```
> set.seed(123)
y <- runif(20, -1, 1)
> median(y)
[1] 0.079505
> bootOut <- boot(y, med0, R = 1000)
> sort(bootOut[c(25, 975]))
[1] -0.342649 0.591728
```

In this case 20 observations are generated from a uniform distribution on the interval $[-1, 1]$ from which 1000 bootstrap samples are taken. The values of the median that are obtained in resampling are the $t$ members of the boot class `bootOut`. These values are sorted and their 2.5 and 97.5 percentiles are obtained. The sample median falls between these bounds, and the null hypothesis of a zero population median is rejected.

## Creating classes and methods in R

### 6.1 Introduction

The previous chapter focused on developing applications that worked with existing R classes. This chapter describes how new R classes and methods can be created for dealing with data analysis problems that require a more customized approach.

It is possible to create classes in R with member elements that in most ways are consistent with the C++ paradigm. However, the primary focus in R is on functions rather than classes. To expand on this last statement, `ObjA` is an object from a C++ class `A`. A method `func` for class `A` would be invoked via syntax resembling `ObjA$func` apart from any arguments that would be needed for the method. If `ObjB` is an object from another class `B`, the expression of the form `ObjB$func` need not have any meaning, and if so, there is no need for the method `func` to perform similar or related operations for objects from class `A` or `B`. The R version of OOP reverses the role of function and object compared to the C++ treatment. Classes do not have member elements. Instead, functions are a class in their own right and specific functions have "methods" that provide implementation of the function for different types of objects. Thus, if `func` is an R function, it may have methods with exactly the same name that would be applicable to perform properly on the objects `ObjA` and `ObjB` from classes `A` and `B`, respectively. The correct version or method function of `func` for an object (or objects) supplied as an argument (or arguments) is determined by the class of the argument (or arguments) through a process `method dispatch`.

The functions in R can (and often are) generic in a sense that is analogous to the use of template function in C++. A template function is not tied to any particular class, and at least in terms of syntax, expressions of the form `func(ObjA)` and `func(ObjB)` for `ObjA` and `ObjB` from entirely different classes `A` and `B` are conceptually valid, if not necessarily meaningful from a practical perspective. When means are called to call `func(ObjA)` and `func(ObjB)`, the generic spirit that underlies template function creation would lead us to expect that the specializations of `func` to class `A` and `B` will perform similar operations on the objects of each class. For example, template functions `print` or `plot` would be expected to perform analogous procedures across objects from different classes. With this in mind, generic functions in R might be viewed as a collection of template functions that carry out similar operations on a variety of R classes.

There are two class systems in R that are referred to as S3 (or "old style") classes (e.g., Chapter 4 of Venables and Ripley 2000 and Chapter 3 of Gentleman) and S4 (or "new style") classes (e.g., Chapters 7-8 of Chambers 1998, Chapter 5 of Venables and Ripley 2000 and Chapter 3 of Gentleman). The S3 class concept is essentially a naming convention that is employed, for example, in method dispatch. In contrast, the S4 class system allows for the creation of objects with member elements and other features that would be expected from an object-oriented language. Accordingly, our attention will be focused on the S4 framework which represents the subject of the next.

### 6.2 Creating a new class

Suppose that we wish to construct a class named regr for dealing with linear regression situation where an n response vector y is dealth to p independent variables contained in the columns of an n p matrix X. The analysis will produce a vector b of least-squares coefficients. Of course R already provides the facility for linear models (i.e., lm class) and this would be the option in cases of practical interest. The goal of the present exercise is not to produce a class that can compete with the lm class. Instead, the objective is to implement the steps involved in class creation in a relatively simple setting.

To create a class in R one uses the `setClass` and `representation` functions. For our regr class might take this form:

```
setClass("regr", representation(X = "matrix", y = "numeric", b = "numeric", intercept = "logical"))
```

This command creates a class with four members, X, y, b and intercept that are objects from existing R classes (matrix, numeric and logical). The variable intercept will be used to specify whether or not an intercept term is to be included in the regression fit.

The `getClass` command provides a way to check that a class has been created correctly. For example, an application of `getClass` to our regr class returns:

| Name | X | y | b | intercept |
| :--- | :--- | :--- | :--- | :--- |
| Class | matrix | numeric | numeric | logical |

This output tells that the class regr has four members (X, y, b and intercept) which R refers to as slots. The names of the elements (X, y, b and intercept) and their respective classes (matrix, numeric and logical) are also listed.

The command `removeClass("className")` will remove an existing class from the current R session demonstrated in the next:

```
> isClass("regr")
[1] TRUE
> removeClass("regr")
[1] TRUE
> isClass("regr")
[1] FALSE
```

Removal of the class was preceded and followed with an application of the `isClass` command that checks if its argument is a formally defined class. The FALSE return from its second application tells us the regr class is no longer defined.

An object from a class can be created with the `new` operator. In particular, using `new` with the regr class means:

```
> regrObj <- new("regr")
> regrObj
```
