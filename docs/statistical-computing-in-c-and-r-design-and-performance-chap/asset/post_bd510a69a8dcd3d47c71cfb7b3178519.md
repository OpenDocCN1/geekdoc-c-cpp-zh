gcSearch <- function(x, y, low, up, nEvents){
  gcVals <- seq(low, up, length = nEvents)
  cbind(gcVals, apply(gcVals, function(lLam)
  linss(x, y, 10~lLam[[2]]]))
}
```

The GCV function takes input the data vectors x and y along with lower and upper bounds (low and up, respectively) for the search size of grid (nEvents). The grid is constructed using the R seq function. A slight twist shows that the search is carried out on a scale with the grid representing a partition of powers of 10. The logarithmic scale is appropriate because it is known that the GCV criterion tends to behave like the power of the smoothing parameter near its minimum. The supply function is used in conjunction with its wrapper function to evaluate the GCV criterion across the specified grid.

The GCVSearch function was applied to the data in Figure 7.1:

This search carried out a 100 point grid for values of λ that are evenly spaced in log10 scale between -2 and 0. A plot of the result is shown in Figure 7.2. This suggests that the minimizer lies in the interval [10⁻¹, 10⁻¹/2]. We will return to this observation in Section 8.3.

## 7.2.6 Banded matrices via inheritance

So banded matrices have been treated as if were matrices (i.e., no pattern of zero elements) in terms of how they are stored, multiplied, transposed, with efficient solution of linear systems being the only use that has been made of the band structure. This is wasteful from a storage perspective. After all, if the matrix is symmetric with bandwidth q, there are q+1 unique, nonzero entries per row. This means that if the matrix has nRows, all nonzero entries can be held in, e.g., nRows*(q+1) memory locations rather than would be required. The special structure of banded matrices could be built directly into class Matrix by adding new constructors and methods.

Inheritance is a means of forming an "is a" relationship between two classes; class A every object of class B has all the qualities (i.e., members and methods) of class A. This object B can be viewed as an A object in the sense that it will have all the functionality by the C++ inheritance mechanism. The relationship is established syntactically in the class declaration which indicates that class B is derived from the base class. Derived classes automatically copy the elements and methods of the base class. The degree of access that is allowed to the base class is determined by the type of inheritance that is specified in the derived class. The most common one is public and that the only one that will be considered here. Under public inheritance, the private members/methods of the base class cannot be accessed by a derived class. The public portion of the base class is available for use with the exception of Figure 7.2 GCV criterion over $\lambda \in [-2,0]$:

- a) constructors
- b) destructors
- c) = or assignment operator
- d) friends

The reason for a)-c is that a derived class may have additional members that must be created or assigned. Friend status indicates a relationship between classes and such, there is no priori reason to expect it to be inherited in much the same sense as with friends where a child need not be friends of a parent. Listing 7.6 provides a simple example of most inheritance syntax and features that we will use in the remainder of this section.

#include <iostream>
using namespace std;

struct A {
    int iA;
    A(int ia) {iA = ia;}
    void output() {
        cout << iA << endl;
    }
    virtual void f() {
        cout << iA << endl;
    }
};

struct B : public A {
    int iB;
    B(int ia, int ib) : A(ia) {
        iB = ib;
    }
    void f() {
        cout << iA << " " << iB << endl;
    }
};

int main() {
    A aobj(2);
    B bobj(3, 5);
    A* pA;
    pA = &aobj;
    pA->f();
    pA = &bobj;
    bobj.output();
    return 0;
}
```

This indicates that the pA pointer is using the A version of the f function regardless of whether the calling object is class A or B. The inherited output performs similarly in that it uses the A version of f when called by a B class object. A more desirable outcome would be polymorphic behavior where the call to output as well as use of the pointer would adapt to the object involved in the function call. This is accomplished by commenting out line 11 and uncommenting line 12 of 7.6. A virtual keyword now comes into play whose use all functions in the derived class to override functions in the base class that have the same name, return type and arguments. If an explicit base class constructor is not specified the base class default constructor is called.

Let us consider the creation of a class pBand to represent positive-definite banded matrices. The “is-a” relationship that exists makes it natural to develop the pBand as a derived of class Matrix. The benefit of this approach is that Matrix already embodies many of the methods that were needed for the pBand class and these (public) features would become part of the pBand class automatically under an inheritance relationship. As a result, design of the pBand class can instead focus on just those modifications and enhancements that are appropriate for matrices that are positive-definite with banding.

To consider a padded down version of class Matrix with the header file Listing 7.7 simpleMath.h:

R
//simpleMath.h
#ifndef MATRIX_H
#define MATRIX_H
#include <iostream>
#include <vector>

class Matrix{
    int nRows, nCols;
    double** pA;
    Vector gauss(const Vector& RHS) const;

public:
    // constructors and destructors
    Matrix(int nrows = 0, int nCols = 0, double a = 0);
    Matrix(int nrows, int nCols, const double* const* pa);
    Matrix(const Matrix& A);
    virtual ~Matrix();

    // overloaded operators
    Matrix& operator=(const Matrix& B);
    const double* operator[](int i) const { return pA[i]; }

    // solution of a linear system
    virtual Vector solve(const Vector& RHS) const {
        std::cout << "Solution via gauss from class Matrix" << std::endl;
        return gauss(RHS);
    }

    // utilities and accessors
    void printMatrix() const;
    int getNRows() const {return nRows};
    int getNCols() const {return nCols};
};
#endif
