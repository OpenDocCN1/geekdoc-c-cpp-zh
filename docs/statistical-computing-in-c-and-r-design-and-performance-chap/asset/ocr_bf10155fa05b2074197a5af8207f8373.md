# NEWTON METHOD

```
Functor f(&fun, &fun1, &fun2);
Optim Opt = Optim(itMax, delta);
int ier = 0;
double fMin = Opt.approx(f, 0., 1., start, &ier);
std::cout << "The approximate minimizer is "
    << fMin << endl::
std::cout << "The error code is " << ier << endl::;
```

The functions fun, fun1 and fun2 are f and its first two derivatives. The addresses of these three functions are used to obtain the Functor object. Optim class object is created using new values for delta and itMax that are provided through command line input. The Optim object calls the newton method using the Functor object and a starting value obtained from the command line. The resulting approximate and the error value returned from newton are then written to standard output.
The Optim.cpp and newtonDriver.cpp files were compiled and linked to the executable. Using this obtained

```
The error code is 0
```

It seems like every check for the starting value works. A little checking reveals that iterations are always terminated when the iter newton method reaches two. Of course, this is no real surprise because a function of this is an ideal case for the Newton algorithm. The same would occur for any other quadratic function; i.e., the newton method for class Optim would return the exact (to machine precision) minimizer with iter=2 (Exercise 8.14nA criticism could explain why the errors are caused by our implementation of the Newton method. The current "solution" is to simply terminate the search when things go away. This actually works if the method is applied to a sequence of random starting points as we use the golden section algorithm. For general use there is no reason to stop computation. A new search can be started with the same parameters, apart from the starting value, using the C++ exception mechanism from Section 3.8.7.
