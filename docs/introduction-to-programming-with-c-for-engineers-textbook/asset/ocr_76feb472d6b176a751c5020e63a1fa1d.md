Then this project can be compiled, the built software can be executed, and so on. Let’s summarize the main benefits of using *CMake* to define our C++ projects:

+   - *CMake* lets us define generic rules for a project, which are then realized in order to create a project for a given platform
+   - *CMake* lets us define relations between projects, such as a library vs. an application that uses this library

*CMake* is a separate software system with its own syntax and hundreds of definitions and options. The obvious question is, why is this so difficult? Not only do we have to learn all these peculiarities of C++, but then, to be able to build C++ in real environments, we need to become an expert in *CMake*! Fortunately, the news is not that bad. First of all, if we stick to one platform, we can live happily without *CMake*, at least for a while. Second, although at first glance *CMake* might seem to be complicated, we can apply the 20/80 rule that says we can get the vast majority of the benefits while using fewer than 20% of its features.

To use *CMake*, we need to do at least two things:

+   - Install the latest version of *CMake*<sup>6</sup>
+   - Prepare a *CMakeLists.txt* file containing instructions for *CMake*

The *EmptyPro* project is a kind of template project undertaken in this book. You can start using *CMake* by trying it on *EmptyPro*.
