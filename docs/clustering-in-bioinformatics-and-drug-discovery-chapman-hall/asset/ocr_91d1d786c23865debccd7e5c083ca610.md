Again, in principal this algorithm should have a linear speedup in the number of processors. There of course is a latency period at each iteration while each processor finishes its task. The master calculates the new centroids once all of the assignments has been made, but it first has to assemble all of the near neighbors for each current centroid from each slave before doing so.

# Algorithm 11.3 ParallelK-Means(Data, K, X, M)

```
1:  G ← K EmptyLists()
2:  M ← ArcCenters(Data, K) // Find K arbitrary centers within Data
3:  if Master then
4:      DataRows ← PartitionData(Data) // Partition data into N/n rows
5:      Send(M, DataRows) // Send centroids and data rows to respective processors
6:      i ← 1
7:  end if
8:  if Slave then
9:      Receive(DataRow) // Receive data row
10: end if
11: repeat
12:     if Master then
13:         G′ ← G
14:         Receive(C) // Receive near neighbor assignments of data from Slaves
15:         G ← AssembleNN() // Assemble NN groups from all C to calculate new centroids
16:         M ← FindCentroids(G) // Calculate new centroids
17:         Send(M) // Send new centroids to Slaves
18:         i ← i + 1
19:     end if
20:     if Slave then
21:         Receive(M) // Receive new centroids
22:         C ← FindNN(DataRow, M) // Find the nearest neighbors to M
23:         Send(C) // Send near neighbor assignments of data to Master
24:     end if
25: until i == Iterations OR G == G′
26: Output: G, M
```

# 11.3.1  Divide K-Means

Divide K-means is nearly as simple to parallelize, provided that there is either shared memory or there is sufficient memory per core so that the data can be stored in full. Unlike those clustering methods that need a full or sparse proximity matrix, only the data need to be stored and thus are linear and not quadratic space, so even cores with only a modicum of available RAM can store millions of data items.
