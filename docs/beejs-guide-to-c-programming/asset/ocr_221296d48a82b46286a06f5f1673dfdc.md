2. The struct is somewhat large and it's more expensive to copy that onto the stack than it is to just copy a pointer.

For those two reasons, it's far more common to pass a pointer to a struct to a function, though by no means is illegal to pass the struct itself.

Let's try passing in a pointer, making a function that will allow you to set the .price field of the struct car:

```
#include <stdio.h>

struct car {
    char *name;
    float price;
    int speed;
};

int main(void) {
    struct car saturn = {.speed=175, .name="Saturn SL/2"};

    // Pass a pointer to this car, along with a new,
    // more realistic, price:
    set_price(&saturn, 79.99);

    printf("Price: %f\n", saturn.price);
}
```

You should be able to come up with the function signature for set_price() by looking at the types of the arguments we have here.

saturn is a car, so saturn must be the address of the struct car, AKA a pointer to a struct car, namely a struct 'car'.

And 79.99 is a float.

So the function declaration might look like this:

```
void set_price(struct car *c, float new_price)
    c.price = new_price; // ERROR!!
```

We need to write the body. One attempt might be:

```
void set_price(struct car *c, float new_price)
    (*c).price = new_price; // works, but it is ugly and non-idiomatic :
```
