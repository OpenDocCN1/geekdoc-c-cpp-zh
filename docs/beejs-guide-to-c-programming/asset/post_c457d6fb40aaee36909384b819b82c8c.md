
## 14.5.3 Floating Point Constants

You'd think a floating point constant like 1.23 would have a default type of float, right? Surprise Turns unsuffixed floating point numbers are type double! Happy belated birthday!

You can force it to be of type float by appending an f (or F—it's case-insensitive). You can force it to be of type long double by appending l (or L).

| Type | Suffix |
|---|---|
| float | F |
| double | None |
| long double | L |

For example:

```
float x = 3.14f;
double x = 3.14;
long double x = 3.14L;
```

This time though, we've been doing this, right?
float x = 3.14;

Isn't left a float and a double right? Yes! But C's pretty good with automatic numeric conversions, so it's more common to have an unsuffixed floating point constant than not. Or on that later.

### 14.5.3.1 Scientific Notation

Remember earlier when we talked how a floating point number can be represented by a significand, base, and exponent?

Well, there's a common way of writing such a number, here shown followed by its more recognizable equivalent is what you get when you actually run the math:

1.2345 × 10³ = 1234.5

Writing numbers in the form s × b¹⁰ is called scientific notation¹⁴. In C, these are using "E notation", so these are equivalent:

| Scientific Notation | E notation |
|---|---|
| 1.2345 × 10⁻³ | 1.2345e-3 |
| 1.2345 × 10⁸ | 1.23450000e+8 |

You can print a number in this notation with %:
printf("%s\n", 1.234560e+05);
A couple of little fun facts about scientific notation:

- You don't have to write them with a single leading digit before the decimal point. Any number of numbers can go in.

```
double x = 123.456e3; // 123456
```

However, when you print it, it will change the exponent so there is only one digit in front of the decimal point.

> ¹⁴https://en.wikipedia.org/wiki/Scientific_notation

The plus can be left off the exponent, it's default, but this is uncommon in practice from what I've seen.

1.2345e10 == 1.2345e+10

You can apply the F or L suffixes to E-notation constants:

1.2345e10
1.2345e10L

### 14.5.3.2 Hexadecimal Floating Point Constants

But wait, there's more floating to be done!

Turns out there are hexadecimal floating point constants, as well!

These work similar to decimal floating point numbers, but they begin with a 0x just like integer numbers.

The catch is that you must specify an exponent, and this exponent produces a power of 2. That is: 2^x.

And then you use a p instead of an e when writing the number:

So 0xa.1p3 is 10.0625 × 2^3 = 80.5.

When using floating point constants, We can print hex scientific notation with %:

double x = 0xa.1p3;

```
printf("%a\n", x);   // 0x1.42p+6
printf("%f\n", x);   // 80.500000
```

## Types III: Conversions

In this chapter, we want to talk all about converting from one type to another. C has a variety of ways of doing this, and some might be a little different that you're used to in other languages.

Before we talk about how conversions happen, let's talk about how they work when they do happen.

## 15.1 String Conversions

Unlike many languages, C doesn't string-to-number (and vice-versa) conversions in quite as streamlined manner manner as it does numeric conversions.

For these, we'll have to call functions to do the dirty work.

### 15.1.1 Numeric Value to String

When we want to convert a number to a string, we can use sprintf() (pronounced SPRINT-f) or snprintf() (s-n-print-f*)

These basically work like printf(), except they output to a string instead, and you can print that string later, or whatever.

For example, turning part of the value π into a string:

```c
#include <stdio.h>

int main(void)
{
    char s[10];
    float f = 3.14159;

    // Convert "f" to string, storing in "s", writing at most 10 characters
    // including the NULL terminator

    snprintf(s, 10, "%f", f);

    printf("String value: %s\n", s); // String value: 3.141590
}
```

So you can use %d or %u like you're used to integers.

> They're the same except snprintf() allows you to specify a maximum number of bytes to output, preventing the overflowing of your string. So it's safer.

### 15.1.2 String to Numeric Value

There are a couple families of functions to do this in C. We'll call the atoi (pronounced atoi-to-i) family and the strtol (str-to-long) family. For basic conversion from a string to a number, try atoi functions from <stdlib.h>. These have bad error handling characteristics (including undefined behavior if you pass a bad string), so use them carefully.

| Function | Description |
|---|---|
| atoi | String to int |
| atof | String to float |
| atol | String to long int |
| strtol | String to long int |

Though it doesn't count the beginning of the function stands for ASCII, so saying that is a bit centric. Here's an example converting a string to float:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    char *pi = "3.14159";
    float f;

    f = atof(pi);

    printf("%f\n", f);
}
```

But, like I said, you get undefined behavior from weird things like this:
int x = atoi("what"); // "what" ain't a number (When I run it, you get 0 back, but you shouldn't count on that any way. You could get something completely different.)

For better error handling, let's check out strtol functions, also in <stdlib.h>. Not only that, but they convert to more types and cases too!

| Function | Description |
|---|---|
| strtol | String to long int |
| strtoll | String to long long int |
| stroul | String to unsigned long int |
| strtou | String to unsigned long int |
| atof | String to float |
| strtod | String to double |
| strtold | String to long double |

These functions all follow a similar pattern of use, and are a lot of people' first experience with pointers! But never easier than it looks.

Let's do an example where we convert a string to an unsigned long, discarding error information (i.e. about bad characters in the input string):

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    char *s = "3490";

    // Convert string s, a number in base 10, to an unsigned long int.
    // NULL means we don't care about error information.

    unsigned long int x = strtol(s, NULL, 10);

    printf("%lu\n", x); // 3490
}
```

Notice a couple things. Even though you didn't capture any information about error characters in the string, strtol() won't give us undefined behavior; it will just return 0. Also, you specified that this was a decimal (base 10) number. Does this mean we can convert numbers of different bases? Sure! Let's go binary

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    char *s = "10110"; // What's the meaning of this number?

    // Convert string s, a number in base 2, to an unsigned long int.

    unsigned long int x = strtol(s, NULL, 2);

    printf("%lu\n", x); // 42
}
```

OK, that's all games, but what's that NULL in there? What's that for? That helps us figure out if an error occurred in the processing of the string. A pointer to a character, which sounds weird, but isn't once you wrap your head around it. Let's do an example where we feed in a deliberately bad number, and we'll see how strtol() lets us where the first invalid digit is.

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    char *s = "34X0"; // "X" is not a valid digit in base 10!
    char *badchar;

    // Convert string s, a number in base 10, to an unsigned long int.

    unsigned long int x = strtol(s, &badchar, 10);

    // It tries to convert as much as possible, so gets this far:

    printf("%lu", x); // 34

    // But we can see the offending bad character because badchar
    // points to it!

    printf("Invalid character: %c\n", *badchar); // "x"
}
```

So we have strtol modifying badchar points in order to show where things went wrong? But if nothing goes wrong? In case, badchar will point to the NUL terminator at the end of the string. So we can test for it:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
  char *s = "3490"; // "x" is not a valid digit in base 10!
  char *badchar;
  // Convert string s, a number in base 10, to an unsigned long int
  unsigned long int x = strtol(s, &badchar, 10);

  // Check if things went well
  if (*badchar == '\0') {
    printf("Success! %lu\n", x);
  } else {
    printf("Partial conversion: %lu\n", x);
    printf("Invalid character: %c\n", *badchar);
  }
}
```

So you have it. The atoi()-style functions are good in a pinch, but the strtol()-style functions give you more control over error handling and the base of the input.
