# 41.1.2 nooreturn and _Noreturn

This indicates to the compiler that a particular function will never return to its caller, i.e. the program will exit by some mechanism before the function returns.

It allows the compiler to perform some optimizations around the function call.

It also allows you to indicate to devs that some program logic depends on a function returning.
You'll likely never need to use this, but you'll see it in some library calls exit()² and everyone would recommend including <stdnoreturn.h> and using the easier-to-read nooreturn return instead.

It's undefined behavior if a function specified as nooreturn actually does return. It's computationally costly, see.

Here's an example of using nooreturn correctly:

```
#include <stdio.h>
#include <stdlib.h>
#include <stdnoreturn.h>
```

```
nooreturn void foo(void) // This function should never return!
{
    printf("Happy days\n");
    exit(1); // And it doesn't return--it exits here!
}
```

```
int main(void)
{
    foo();
}
```

If the compiler detects a nooreturn function could return, it might warn you, helpfully.

Replacing the foo() function with this:

```
nooreturn void foo(void)
{
    printf("Breakin' the law\n");
}
```

gets me a warning:

foo.c:7:1: warning: function declared 'nooreturn' should not return
