

# 第 23 章 指针 III：指针的指针及其他

## 23.2 多字节值

我们之前在很多地方都用过这种版本，但显然并不是每个值都能存储在单个内存字节中。某些东西占用多个字节的内存（假设它们不是 `char`）。你可以通过 `sizeof` 查看它们占用了多少字节。你可以使用标准的 `&` 运算符来确定内存中哪个地址是对象的第一个字节，它返回第一个字节的地址。

这里还有另一个趣知识！如果你遍历任何对象的字节，你就会得到它的内存表示形式。这些在内存中具有相同内存表示的东西是相等的。

如果你想遍历对象的内存表示，你应该使用 `unsigned char` 指针来操作。

让我们来实现这个版本的内存(5)，正好执行这个操作：

```c
void *memcopy(void *dest, void *src, size_t n)
{
    // 为 src 和 dest 创建本地变量，但类型为 unsigned char
    unsigned char *s = src;
    unsigned char *d = dest;

    while (n-- > 0) // 对于给定的字节数
        *d++ = *s++; // 将源字节拷贝到目的地

    // 大多数拷贝函数会返回目的地的指针，以便
    // 调用者使用

    return dest;
}
```

（这里面有一些关于后增和后减的极佳示例供你学习。）

需要注意的是，上面的这个版本效率可能比你系统自带的要低。

但你可以将任何类型的指针传递给它，它会拷贝这些对象。可以是 `int`、`struct animal*` 或任何东西。

让我们再做另一个例子，打印出一个结构体的内存表示字节，看看其中是否有填充（padding）以及它包含什么内容(6)。

```c
#include <stdio.h>
```

```c
struct foo {
    char a;
    int b;
};

int main(void)
{
    struct foo x = {0x12, 0x12345678};
    unsigned char *p = (unsigned char *)&x;

    for (size_t i = 0; i < sizeof(x); i++) {
        printf("%02x\n", p[i]);
    }
}
```

> ^5 https://beej.com/guide/bglcr/html/split/stringref.html#man-memcopy
^6 编译器并不要求添加填充字节，且添加的任何填充字节的值是不确定的。

我们在这里拥有一个 `struct foo` 结构体，它的构造方式鼓励编译器注入填充字节（尽管它并没有这样做）。然后我们得到了一个指向 `struct foo` 变量 `x` 第一个字节的 `unsigned char *`。

从这里开始，我们只需要知道 `sizeof x` 就可以遍历许多字节并打印出值（为了方便，使用十六进制）。

运行这个程序会输出一堆数字。我在下面对其进行了注释，以识别这些值存储存储的位置：

| 值 | 描述 |
| :--- | :--- |
| x.a == 0x12 | AB |
| | BF | 带有“随机”值的填充字节 |
| | 26 |
| | 78 |
| | 56 | x.b == 0x12345678 |
| | 34 |
| | 12 |

在所有系统上，`sizeof(char)` 都是 1，我们看到输出顶部的第一个字节持有我们存储的值 0x12。

然后我们拥有了填充字节——对于我来说，我们可以看到最后那 4 个字节。注意看它们与十六进制值 `0x12345678` 中的字节相同，但奇怪的是顺序是反的。

这就是对内存中更复杂实体的一种底层小窥探。

## 23.3 NULL 指针和 0

这些东西可以互换使用：

- *NULL*
- *'\0'*
- *(void\)***

我个人在想要表示 NULL 时总是使用 `NULL`，但你偶尔也会看到其他一些变体。虽然 `'\0'`（所有位都设为 0）比较也相等，但将它与指针进行比较是*很奇怪的*；你应该比较 `NULL` 指针。（当然，在字符串处理中，你经常会将指针与 `'\0'` 比较，这是正确的）。

0 被称为空指针常量，当与另一个指针进行比较或赋值给它时，它会被转换为相同类型的空指针。

## 23.4 作为整数的指针

你可以将指针强制转换为整数，反亦然（因为指针只是内存中的一个索引），但只有在你进行某些底层硬件操作时才真正需要这样做。此类操作的结果是由实现定义的，因此它们并不是固定的。而且可能会发生一些*奇怪*的事情。

> 这取决于架构，但我的系统是小端序，这意味着低位字节先存储。大端序系统会将 12 放在第一个，78 放在最后。但规范对这种表示法没有任何规定。

但 C 语言有一项保证：你可以将指针转换为 `uintptr_t` 类型，并能够将其转换回指针而不丢失任何数据。

`uintptr_t` 定义在 `<stdint.h>` 中。

此外，如果你想使用有符号类型，可以使用 `intptr_t` 来实现相同的效果。

## 23.5 将指针转换为其他指针

只有一种安全的指针转换：

- 1. 转换为 `intptr_t` 或 `uintptr_t`。
- 2. 转换为 `void*`。

两个！两种安全的指针转换。

- 3. 转换为 `char*`。

三个！三种安全的转换！

- 4. 在结构体指针和指向其第一个成员的指针之间进行转换，反亦然。

四个！安全的转换！
如果你将其转换为另一种类型的指针并访问它指向的对象，其行为是未定义的，这是由于某种被称为*严格别名*（strict aliasing）的机制。

普通的*别名*指的是通过多种方式访问同一个对象的能力。这些访问点是彼此的别名。

严格别名规定，你只通过与对象兼容的类型来访问对象。

例如，定义如下：

```c
int a = 1;
int *p = &a;
```

p 是一个指向 int 的指针，它指向一个兼容类型。
