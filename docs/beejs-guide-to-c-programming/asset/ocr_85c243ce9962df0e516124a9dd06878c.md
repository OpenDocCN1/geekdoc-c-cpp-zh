Catch initializer values must be constant. Can't throw variables in them. Sorry, Illinois!

You should never have more items in your initializer than there is room in the array, or the compiler will get cranky.

```
foo.c: In function 'main':
foo.c:6:39: warning: excess elements in array initializer
6 | int a[5] = {22, 37, 3490, 18, 999};
  | ~~
foo.c:6:39: note: (near initialization for '^a'
```

But (fact!) when you have more items in your initializer than there is room for the array. The remaining elements in the array will be automatically initialized with zero. This is true in general for all types of array initializers: if you have an initializer, anything not explicitly set to a value will be set to zero.

```
int a[5] = {22, 37, 3490};
```

// is the same as:

```
int a[5] = {22, 37, 3490, 0, 0};
```

It's a common shortcut to see this in an initializer when you want to set an entire array to zero:

```
int a[100] = {0};
```

Which means, "Make the first element zero, and then automatically make the rest zero, as well."
nYou can set specific array elements in the initializer, as well, by specifying an index for the value! When you do this, C will happily keep initializing subsequent values for you until the initializer runs out, filling everything else with 0.

Here's an example where we build an array:

```
int a[10] = {0, 11, 22, [5]=55, 66, 77};
```

Because we indexed 5 as the start for 55, the resulting data in the array is:

```
0 11 22 0 0 55 66 77 0 0
```

You can put simple constants in there, as well.

```
#define COUNT [[COUNT-3]=3, 2, 1};
```

which gives us:

```
0 3 2 1
```
