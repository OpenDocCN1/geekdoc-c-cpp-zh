# Chapter 16. Types IV: Qualifiers and Specifiers

# 16.2.2.2 static in File Scope

When you get out of file scope, outside blocks, the meaning rather changes.

Variables at file scope also persist between function calls, so that behavior is already there.

Instead static means in this context is that this variable isn't visible outside of this particular file. Kind like "global", but only in this file.

More on that in the section about building with multiple source files.

# 16.2.3 extern

The extern storage-class specifier gives us a way to refer to objects in other source files.

Let's say, the file bar.c had the following as its entirety:

```
// bar.c

int a = 37;
```

Just that. Declaring a new int in a file scope.

But if we had another source file, foo.c, and we wanted to refer to the that's in bar.c?

It's easy with the extern keyword:

```
// foo.c

int main(void)
{
    printf("%d\n", a); // 37, from bar.c!

    a = 99;

    printf("%d\n", a); // Same "a" from bar.c, but it's now 99
}
```

We could also made the extern int in a block scope, and it still would have referred to the a in bar.c.

```
// foo.c

int main(void)
{
    extern int a;

    printf("%d\n", a); // 37, from bar.c!

    a = 99;

    printf("%d\n", a); // Same "a" from bar.c, but it's now 99
}
```

Now, if a in bar.c had been marked static, this wouldn't have worked. static variables at file scope are not visible outside that file.

A final note about extern on functions. For functions, extern is the default, so it's redundant. You can declare a function static if you only want visible in a single source file.
