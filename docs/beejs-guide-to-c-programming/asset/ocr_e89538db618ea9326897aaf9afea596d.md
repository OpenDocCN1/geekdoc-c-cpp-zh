# 39.2 Things You Can Do

You can create a thread. It will begin running the function you specify. The parent thread that spawned it will also continue to run.

And you can wait for the thread to complete. This is called joining.

Or if you don't care when the thread completes and don't want to wait, you can detach.

A thread can explicitly exit, or it can implicitly quit it by returning from its main function.

A thread can also sleep for a period of time, doing nothing while other threads run.

The main() program is a thread, as well.

Additionally, we have thread local storage, mutexes, and conditional variables. But more on those later. Let's look at the basics for now.

# 39.3 Data Races and the Standard Library

Some of the functions in the standard library (e.g. asctime()) return or use static data elements that aren't threadsafe. But in general unless it's said otherwise, the standard library makes an effort to be so.

But keep an eye out. If a thread is maintaining state calls in a variable you don't own, or if a function is returning a pointer to a thing that you didn't pass in, it's unsafe.

# 39.4 Creating and Waiting for Threads

Let's hack something up!

We'll make some threads (create) and wait for them to complete (join).

We have a tiny bit to understand first, though.
Every thread is identified by an opaque variable of type thrd_t. It's a unique identifier for thread in your program. When you create a thread, it's given a new ID.

Also when you make the thread, you have to give it a pointer to a function to run, and a pointer to an argument to pass to it (NULL if you don't have anything to pass).

The thread will begin execution on the function you specify.

When you want to wait for a thread to complete, you have to specify its thread ID so C knows which one to wait for.

So the basic idea is:

+   1. Write a function to act as the thread's "main". It's not main()-proper, analogous to it. The thread will start running there.
2. From the main thread, launch a new thread with thrd_create(), and pass a pointer to the function to run.
3. In that function, the thread will do whatever it has to do.
4. Meanwhile, the main thread can continue doing whatever it has to do.
5. When the main thread decides to exit, it can wait for the child thread to complete by calling thrd_join() the thread to clean up it or else you'll leak memory.
