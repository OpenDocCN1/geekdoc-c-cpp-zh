# The C Preprocessor

Before your program gets compiled, it actually runs through a phase called preprocessing. It's almost like there's a language on top of the C language that runs first. And it outputs the C code, which then gets compiled.

We've already seen this to an extent with #include! That's the C Preprocessor! Where it sees directive, it includes the named file right there, just as if you typed it in there. And the compiler builds the whole thing.

But it turns out it's a lot more powerful than just able to include things. You can define macros that are substituted... and even macros that make arguments!

# 19.1 #include

Let's start with what we've already seen a bunch. This is, of course, a way to include other sources in your source. Very commonly used header files.

While the spec allows for all kinds of behavior with #include, we're going to take a more pragmatic approach and talk about the way it works on every system I've ever seen.

We can split header files into two categories: system and local. Things that are built-in, stdio.h, stdlib.h, math.h, and so on, you can include with angle brackets:

```
#include <stdio.h>
#include <stdlib.h>
```

Which, of course, implies that there must be a way to include local files from the current directory. And this is: with double quotes:

```
#include "header.h"
```

Or you can very probably include in relative directories using forward slashes, and like this:

```
#include "mydir/header.h"
#include "../someheader.py"
```

Don't use a backslash (\) for path separators in your #include! It's undefined behavior! Use forward slash (/) only, even on Windows.

In summary, use angle brackets (< >) for the system includes, and use double quotes (") for your personal includes.
