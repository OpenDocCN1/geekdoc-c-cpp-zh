
## Chapter 12. Manual Memory Allocation

The alignment is an integer power of greater than zero, so 2, 4, 8, 16, etc. and you give that to a aligned_alloc() function before the number of bytes you're interested in.

The other restriction is that the number of bytes you allocate needs to be a multiple of the alignment. But this might be changing. See C Defect Report 460.

Let's do an example, allocating on a 64-byte boundary:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
```

```c
int main() {
    // Allocate 256 bytes aligned on a 64-byte boundary
    char *p = aligned_alloc(64, 256); // 256 == 64 * 4

    // Copy a string in there and print it
    strncpy(p, "Hello, world!");
    printf("%s\n", p);

    // Free the space
    free(p);
}
```

I want to throw a note here about realloc() and aligned_alloc(). realloc() doesn't have any alignment guarantees, so if you need to get some aligned allocated space, you'll have to do it the hard way with malloc(ptr).

Here's a non-standard aligned_realloc() function, if you need it:

```c
void *aligned_realloc(void *ptr, size_t size, size_t alignment, size_t old_size) {
    char *new_ptr = aligned_alloc(alignment, size);

    if (new_ptr == NULL) {
        return NULL;
    }

    size_t copy_size = old_size < size ? old_size : size; // get min

    if (ptr != NULL) {
        memcpy(new_ptr, ptr, copy_size);
    }

    free(ptr);

    return new_ptr;
}
```

Note that it always copies data, taking time, while realloc() will avoid that if it can. This is hardly efficient. Avoiding needing to reallocate custom-aligned data.

## Scope

Scope is all about what variables are visible in what contexts.

### 13.1 Block Scope

This is the scope of almost all the variables devs define. It includes what other languages might call “function scope”, i.e. variables that are declared inside functions.

The basic rule is that if you've declared a variable in a block delimited by squirrelly braces, the scope of that variable is that block.

If there's a block inside a block, then variables declared in the inner block are local to that block, and cannot be seen in the outer scope.

Once a variable's scope ends, that variable can no longer be referenced, and you can consider its value to go into the great bucket¹ in the sky.

An example with nested scope:

```c
#include <stdio.h>

int main(void)
{
    int a = 12;           // Local to outer block, but visible in inner block

    if (a == 12) {
        int b = 99;      // Local to inner block, not visible in outer block

        printf("%d %d\n", a, b); // OK: "12 99"
    }

    printf("%d\n", a);      // OK, we're still in a's scope
    printf("%d\n", b);      // ILLEGAL, out of b's scope
}
```

> ¹https://en.wikipedia.org/wiki/Bit_bucket

### 13.1.1 Where To Define Variables

Another fact is that you can define variables anywhere in the block, within reason—they have the scope of that block, but cannot be used before they are defined.

```c
#include <stdio.h>

int main(void)
{
    int i = 0;

    printf("%d\n", i);    // OK: "0"

    // printf("%d\n", j);    // ILLEGAL--can't use j before it's defined

    int j = 5;

    printf("%d %d\n", i, j);    // OK: "0 5"
}
```

Historically, C required all the variables defined before any code in the block, but this is no longer the case in the C99 standard.

### 13.1.2 Variable Hiding

If you have a variable named the same thing at an inner scope as one at an outer scope, the one at the inner scope takes precedence as long as you're running in the inner scope. That is, *hides* the one at outer scope for the duration of its lifetime.

```c
#include <stdio.h>

int main(void)
{
    int i = 10;

    {
        int i = 20;

        printf("%d\n", i);    // Inner scope i, 20 (outer i is hidden)
    }

    printf("%d\n", i);    // Outer scope i, 10
}
```

You might have noticed that in example I threw a block there at line 7, not so much as a for or if statement to kick it off! This is perfectly legal. Sometimes a dev will want to group a bunch of local variables together for a quick computation and do this, but it's rare to see.

### 13.2 File Scope

If you define a variable outside of a block, it has *file scope*. It's visible in all functions in the file that come after it, and between them. (An exception is if a block defines a variable of the same name, it would hide the one at file scope.) This is closest to what you would consider to be "global" scope in another language. For example:

```c
#include <stdio.h>

int shared = 10; // File scope! Visible to the whole file after this!

void func1(void) {
    shared += 10; // Now shared holds 10
}

void func2(void) {
    printf("%d\n", shared); // Prints "10"
}

int main(void) {
    func1();
    func2();
}
```

Note if shared were declared at the bottom of the file, it wouldn't compile. It has to be declared before any functions use it. There are ways to further modify items at file scope, namely with static and extern, but we'll talk about those later.

### 13.3 for-loop Scope

I don't know what to call this. C §6.8.5 doesn't give it a proper name. We've already seen a few times in:

```c
for (int i = 0; i < 10; i++)
    printf("%d\n", i);

printf("%d\n", i); // ILLEGAL--i is only in for-loop
```

In that example, i's lifetime begins the moment it is defined, and continues for the duration of the loop. Unless the body is enclosed in a block, that inner scope hides them. This crazy example prints 5 times:

```c
#include <stdio.h>

int main(void) {
    for (int i = 0; i < 5; i++) {
        int i = 9; // Hides the i in for-loop scope
        printf("%d\n", i);
    }
}
```

### 13.4 A Note on Function Scope

The C spec refers to function scope, but it's used exclusively with labels, something we haven't discussed yet. More on another day.

## Chapter 14. Types II: Way More Types

We're used to char, int, and float types, but it's now time to take that stuff to the next level and see what we have out there in the types!

### 14.1 Signed and Unsigned Integers

So far we've used int as a signed int, that is, a value that can be negative or positive. But C also has unsigned integer types that can only hold positive numbers. These types are prefixed by the keyword unsigned.

```c
int a; // signed
signed int; // signed
signed a; // signed, "shorthand" for "int" or "signed int", rare
unsigned int b; // unsigned
unsigned c; // unsigned, shorthand for "unsigned int"
```

Why? Why would you decide you wanted to hold positive numbers? Answer: you can get larger numbers in an unsigned variable than you can in signed ones. But why is this? You can think of integers being represented by a number of bits². On your computer, an int is represented by 64 bits. And each permutation of bits that are either 0 or 1 represents a number. We can decide how to divvy up these numbers. With signed numbers, we use (roughly) half the permutations to represent negative numbers, and the other to represent positive numbers. With unsigned, we use all the permutations to represent positive numbers. On my computer with 64-bit ints using two's complement to represent unsigned numbers, I have the following limits integer:

| Type | Minimum | Maximum |
|---|---|---|
| int | -9,223,372,036,854,775,808 | 9,223,372,036,854,775,807 |

> ²Bit is short for binary digit. Binary is just another way of representing numbers. Instead of digits 0-9 we're used to, it's digits².
