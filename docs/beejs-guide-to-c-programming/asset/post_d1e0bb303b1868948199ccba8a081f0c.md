## Types IV: Qualifiers and Specifiers

Now that we have some more types under our belts, turns out we can give these types some additional attributes that control their behavior. These are the type qualifiers and storage-class specifiers.

## 16.1 Type Qualifiers

These are going to allow you to declare constant values, and also to give the compiler optimization hints that it can use.

### 16.1.1 const

This is the most common type you'll see. It means the variable is constant, and any attempt to modify it will result in a very angry compiler.

```c
const int x = 2;

x = 4; // COMPILER PUKING SOUNDS, can't assign to a constant
You can't change a constant value.
```

Often you see this in parameter lists for functions:

```c
void foo(const int x)
{
    printf("%d\n", x + 30); // OK, doesn't modify "x"
}
```

### 16.1.1 const and Pointers

This gets a little funky, because there are two usages that have two meanings when it comes to pointers.
For one thing, we can make it so you can't change the pointer points to. You do this by putting the const up with the type name (before the asterisk) in the type declaration.

```c
int x[] = {10, 20};
const int *p = x;

p++; // We can modify p, no problem
*p = 30; // Compiler error! Can't change what it points to
```

Somewhat confusingly, these two things are equivalent:

```c
const int *p; // Can't modify p points to
const int *p; // Can't modify p points to, just like the previous line
```

Great, so we can change the pointer points to, but we can change the pointer itself. What if we want the other way around? We will be able to change what the pointer points to, but not the pointer itself?

Just move the const the asterisk in the declaration:

```c
int *const p; // We can't modify "p" with pointer arithmetic

p++; // Compiler error!
```

But we can modify what they point to:

```c
int x = 10;
int *const p = &x;

p = 20; // Set "x" to 20, no problem
```

You can also make both const:

```c
const int *const p; // Can't modify p or *p!
```

If you have multiple levels of indirection, you should set the appropriate levels. Just because a pointer is const, doesn't mean the pointer it points to must also be. You can explicitly set them like in the following examples:

```c
char **p;
p++; // OK!
(*p)++; // OK!
```

```c
char **const p;
p++; // Error!
(*p)++; // OK!
```

```c
char *const *const p;
p++; // Error!
(*p)++; // Error
```

### 16.1.1.2 Correctness

One thing I have to mention is that the compiler will warn you on something like this:

```c
const int x = 20;
int *p = &x;
```

saying to the effect of:
initialization discards 'const' qualifier from pointer type target

What's happening here?
Well, we need to look at the types on the other side of the assignment:

```c
const int x = 20;
int *p = &x;
      ^ ^
```

```c
// | |
// int* const int*
```

The compiler is warning us that the value on the right side of the assignment is const, but one of the left is not. And the compiler is letting us know that it is discarding “const-ness” of the expression on the right.

That is, we can still try to do the following, but it’s just wrong. The compiler will warn, and it’s undefined behavior:

```c
const int x = 20;
int *p = &x;
```

```c
*p = 40; // Undefined behavior--maybe it modifies "x", maybe not!
printf("%d\n", x); // 40, if you're lucky
```

### 16.1.2 restrict

TLDR: you never have to use this and can ignore it every time you see it. If you use it correctly, you will realize some performance gain. If you use it incorrectly, you will realize undefined behavior.
restrict is a hint to the compiler that a particular piece of memory will only be accessed by one pointer and never another. If a developer declares a pointer to be restrict and then accesses the objects it points to in another way (e.g. via another pointer), the behavior of the restrict pointer is undefined.

C uses that information to perform certain optimizations. For instance, if you are dereferencing the restrict pointer in a loop, C might decide to cache the result and only store the final result after the loop completes. If any other pointer referred to that memory and accessed it in the loop, the result would not be accurate.

(Note that restrict has no effect on the object pointed to is never written to. It’s all about optimizations surrounding memory.)

Let’s write a function to swap two variables, and we use the restrict keyword to assure C that.

```c
void swap(int *restrict a, int *restrict b)
{
    int t = *a;
    *a = *b;
    *b = t;
}

int main(void)
{
    int x = 10, y = 20;
    swap(&x, &y);
    printf("x=%d, y=%d\n", x, y);
    return 0;
}
```

## 16.2 Storage-Class Specifiers

Storage-class specifiers are similar to quantifiers. They give the compiler more information about a variable.

### 16.2.1 auto

You barely ever see this keyword, since auto is the default for block scope. It's implied.

```c
{
  int a; // auto is the default...
  auto int a; // So this is redundant
}
```

The auto keyword indicates that this object has automatic duration. That is, it exists in the scope in which it is defined, and is automatically deleted when the scope is exited.

 gotcha with automatic variables is their value is indeterminate until you initialize them. We say they're full of "random" or "garbage" data, though neither of those really makes me happy. In any case, you won't know what's in it unless you initialize it.

Always initialize all automatic variables before use!

### 16.2.2 static

This keyword has two meanings, depending on if the variable is file scope or block scope.

Let's start with block scope.

#### 16.2.2.1 static in Block Scope

That is, its value will persist between calls. static block scope with an initializer will only be initialized one time on program startup, not each time the function is called.

Let's do an example:

```c
#include <stdio.h>
void counter() {
  static int counter = 1; // This is initialized one time

  printf("This has been called %d time(s)\n", counter);

  counter++;
}

int main(void)
{
  counter(); // "This has been called 1 time(s)"
  counter(); // "This has been called 2 time(s)"
  counter(); // "This has been called 3 time(s)"
  counter(); // "This has been called 4 time(s)"
}
```

See the value of counter persists between calls?

One thing to note is that static block variables are initialized to 0 by default.

```c
static int foo; // Default starting value is '0'
static int foo = 0; // So the '0' assignment is redundant
```

Finally, be advised that if you're writing multithreaded programs, you have to be sure you don't let multiple threads trample the same variable.
