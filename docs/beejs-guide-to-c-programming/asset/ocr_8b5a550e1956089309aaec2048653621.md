# Chapter 30. Variable-Length Arrays (VLAs)

```
scanf("%d", &n);
```

```
int v[n];

for (int i = 0; i < n; i++)
    v[i] = i * 10;

for (int i = 0; i < n; i++)
    printf("%d] = %d\n", i, v[i]);
```

(On line 7, I have fflush()) that forces the line to output even though I don't have a newline at the end.)

Line 10 is where the VLA—once execution gets past that line, the size of the array is set to whatever n was at runtime. The array can't be changed.

You can put an expression in the brackets, as well:
int v[x * 100];

+   - You can't declare a VLA at file scope, and you can't make a static one in block scope.
- You can't use an initializer list to initialize the array.

Also, entering a negative value for the size of the array invokes undefined behavior—in this, anyway.

# 30.2 sizeof and VLAs

We're used to sizeof using the size in bytes of any particular object, including arrays. VLAs have no exception.

The main difference is that sizeof on a VLA is computed at runtime, whereas on a non-variably-sized variable it is computed at compile time.*

But the usage is the same.

You can even compute the number of elements in a VLA with the usual trick:
size_t num_elems = sizeof v / sizeof v[0];

There's a subtle and correct implication from the line above: pointer arithmetic works just like you'd expect for a regular array. So ahead and use it to your heart's content:

```
#include <stdio.h>

int main(void)
{
    int n = 5;
    int v[n];

    int *p = v;

    *(p+2) = 12;
    printf("%d\n", v[2]); // 12
```

*This is due to how VLAs are typically allocated on the stack, and the whole idea with VLAs is they'll be automatically deallocated when the end of the function.
