## 8.4 The Arrow Operator

The arrow operator helps refer to fields in pointers to structs.

```c
void set_price(struct car *c, float new_price) {
  // (*c).price = new_price; // Works, but non-idiomatic:
  // /
  // The line above is 100% equivalent to the one below:

  c->price = new_price; // That's the one!
}
```

So when accessing fields, when do we use dot and when do we use arrow?

- If you have a struct, use dot ().
- If you have a pointer to a struct, use arrow (-).

## 9.1 The FILE* Data Type

When we do any kind of I/O in C, we do so through a piece of data that you get in the form of a FILE type. This FILE holds all the information needed to communicate with the I/O subsystem about which file we have open, where you are in the file, and so on.

The spec refers to these as streams, i stream of data from a file or any source. I'm going to use "files" and "streams" interchangeably, but really you should think of a "file" as a special case of a "stream". There are other ways to stream data into a program than just reading from a file.

We'll see in how to go from a filename to getting an open FILE for it, but first I want to mention three streams that are already open for you and ready for use.

| FILE name | Description |
| --- | --- |
| stdin | Standard Input, generally the keyboard by default |
| stdout | Standard Output, generally the screen by default |
| stderr | Standard Error, generally the screen by default, as |

We've actually using these implicitly lately, it turns out. For example, these two calls are:

```c
printf("Hello, world\n");
printf(stdout,"Hello, world\n");
```

But more on that. Also you'll notice that both stdout and stderr go to the screen. While this seems at first like oversight, it actually isn't. Typical operating systems allow you to redirect the output of either into different files, and it can be convenient to separate error messages from non-error output. In POSIX shell (like sh, bash, etc.) on a Unix-like system, we could run a program and send just the non-error (stdout) output to one file, and all the error (stderr) output to another.

```
foo > output.txt 2> errors.txt # This command is Unix-specific
```

For this reason, you should send serious messages to stderr instead of stdout.

## 9.2 Reading Text Files

Streams are largely categorized two ways: text and binary.
Text streams are allowed to do significant translation of newlines to their different representations. To be portable, your input should always end with a newline. Otherwise, it's binary.
But the general rule is that you're able to edit the file in the regular editor, it's a text file. So let's get to—how we open a file for reading, and pull data out of it? Let's create a file called hello.txt that has just this in:

Hello, world!

And let's write a program to open the file, read a character out of it, and then close the file when we're done. That's the game plan!

```c
#include <stdio.h>

{
    FILE *fp; // Variable to represent file
    fp = fopen("hello.txt", "r"); // Open file for reading

    int c = getchar(fp); // Read a single character
    printf("%c\n", c); // Print to stdout

    fclose(fp); // Close the file when done
}
```

To see how we opened the file with fopen(), it returned the FILE so we could use it later. (I'm leaving out for brevity, but fopen() ) will return NULL if something goes wrong, file-not-found, so you should really check it!)

Also notice that the "r" we passed means "open a text stream for reading". (There are various strings we can pass to fopen() with additional meaning, like writing, or printing, and so on.)

After that, we used the getchar() to get a character from the stream. You might be wondering why I've made a c instead of char—that hold on! Finally, we close the stream when we're done with it. All streams are automatically closed when the program exits, it's good and good housekeeping to explicitly close any files yourself when done. The FILE keeps track of position in the file. ## 9.3 End of File: EOF

There is a special character defined as a macro: EOF. This is what fgetc will return when the end of the file has been reached and you've attempted to read another character.

How I learned that Fun Fact, now. Turns out EOF is the reason why fgetc() and functions like it return an int instead of a char. EOF isn't a character proper, and its value falls outside the range of char. Since fgetc() needs to return any byte and EOF, it needs to be a wider type that can hold more values, so int it is. But unless you're comparing the returned value against EOF, you can know, it's a char.

All right! Back to reality! We can use this to read the whole file in a loop.

```c
#include <stdio.h>

int main(void)
{
    FILE *fp;
    int c;

    fp = fopen("hello.txt", "r");

    while ((c = fgetc(fp)) != EOF)
        printf("%c\n", c);

    fclose(fp);
}
```

And running this, we see:
