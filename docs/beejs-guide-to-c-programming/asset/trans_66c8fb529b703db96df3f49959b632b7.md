

# 第 31 章. goto

许多 Unix 类的系统都有一个 `SA_RESTART` 标志，你可以将其传递给 `sigaction()`，请求操作系统自动重启任何因 `EINTR` 失败的系统调用。

再次，这是 Unix 特有的，并且在 C 语言标准之外。

尽管如此，对于任何应该重启的函数，使用类似的技术是可能的。

## 31.8 goto 与防止死锁

这个示例直接摘录自《操作系统：三个体系》（Operating Systems: Three Easy Pieces），这是另一本由志同道合作者编写的优秀书籍，他们认为高质量书籍应该是免费下载的。并不是说我有什么主见之类的。

retry:

```c
thread_mutex_lock(L1);

if (thread_mutex_trylock(L2) != 0) {
    thread_mutex_unlock(L1);
    goto retry;
}
```

save_the_day();

```c
thread_mutex_unlock(L2);
thread_mutex_unlock(L1);
```

在这里，线程幸运地获取了互斥锁 L1，但随后可能需要获取由互斥锁 L2 保护的第二个资源（假设其他操作线程持有它）。如果我们的线程无法获取 L2 锁，它会释放 L1 然后使用 `goto` 干净地重试。

我们希望我们的线程最终能够获取两个互斥锁并化解于难，同时避免了恶性的死锁。

## 31.9 goto 与变量作用域

我们已经看到过标签（labels）具有函数作用域，但如果你跳过了某些变量的初始化，就会发生奇怪的事情。

看这个示例，我们从变量 `x` 作用域之外的地方跳转到其作用域的中间（块内部）。

这可以通过编译并运行，'x' 在此函数中被未初始化就使用了

warning: 'x' 在此函数中被未初始化使用

然后当我运行它时，它输出了 0（你的结果可能有所不同）。

基本上发生的情况是，我们跳转进了 `x` 的作用域（因此在 `printf()` 中引用它是可以的），但我们跳过了实际上将其初始化为 12345 的那行代码。该值是不确定的。

修复方法当然是无论通过什么方式让初始化位于标签之后。

```c
goto label;
{
    int x;
label:
    x = 12345;
    printf("%d\n", x);
}
```

让我们再看一个示例。

```c
{
    int x = 10;
label:
    printf("%d\n", x);
}
```

这里发生了什么？

在第一次通过块时，我们跳转进了 `x` 的作用域，但跳过了它的初始化。这意味着我们仍然可以打印它，但该值是不确定的（因为还没有被重新初始化）。

在我的机器上，它再次打印了 10（无限次地），但那只是运气。由于 `x` 是未初始化的，在 `goto` 之后它可能会打印任何值。

## 31.10 goto 与变长数组（VLA）

关于 VLA 和 `goto`，有一个规则：你不能从 VLA 作用域外跳转到该 VLA 的作用域内。

如果我尝试这样做：

```c
int x = 10;
goto label;
{
    int v[x];
label:
    printf("Hi!\n");
```

我得到了一个错误：

error: 跳到具有可变修改类型的标识符作用域

你可以跳转到 VLA 声明之前，如下所示：

```c
int x = 10;
goto label;
{
label:  ;
  int v[x];
  printf("Hi!\n");
}
```

因为这样 VLA 在其离开作用域并导致不可避免的销毁之前被正确分配了。
