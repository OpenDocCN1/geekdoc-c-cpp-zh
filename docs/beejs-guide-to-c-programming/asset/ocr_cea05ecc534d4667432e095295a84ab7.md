# 34.2.5 When Can't You longjmp()

It's undefined behavior if:

+   * You did not call setjmp() earlier
* You called setjmp() from another thread
* You called setjmp() in the scope of a variable length array (VLA), and execution left the scope of VLA before longjmp() was called.
* The function calling the setjmp() "exited" includes normal returns from the function, as well as if another longjmp() jumped back to "earlier" in the stack stack than the function in question.

On that last line, "longjmp() jumped back to "earlier" in the stack stack than the function in question.

# 34.2.6 You Can Pass 0 to longjmp()

If you try to pass the value to longjmp(), it will silently change that value to 1.

Since setjmp() ultimately returns this value, and having setjmp() return 0 has special meaning, returning 0 is prohibited.

# 34.2.7 longjmp() and Variable Length Arrays

If you are in scope of a VLA and longjmp() out, the memory allocated to the VLA could leak.
Same thing happens if you longjmp() back over any earlier functions that have VLAs still in scope.

This is one thing that really bugged me able VLAs—that you could write perfectly legitimate C code that squandered memory. But, hey—I'm not in charge of the spec.

> ³That is, remain allocated until the program ends with no way to free it.
