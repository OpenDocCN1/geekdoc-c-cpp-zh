And if you think about it, these rules make sense. All those operations rely on knowing the size of the data pointed to, and with void*, we don't know the size of the data being pointed to—it could be anything!

But wait—if you can't dereference a void* what good can it do for you?

Like `memcpy()`, it helps you write generic functions that can handle multiple types of data. But the secret is that, deep down, you convert the void* to another type before you use it!

Assignment is also easy: you can just assign it to a variable of the desired type.

```c
char a = 'X'; // A single char
void *p = &a; // p points to the 'X'
char *q = p; // q also points to the 'X'
```

```c
printf("%s\n", p); // ERROR-cannot dereference void*
printf("%s\n", q); // Prints "X"
```

Let's write our own `memcpy()` to try this out. We can copy bytes (chars), and we know the number of bytes because it's passed in.

```c
void *my_memcpy(void *dest, void *src, int byte_count) {
    char *s = src, *d = dest;

    // Now we have char*s, we can dereference and copy them
    while (byte_count--) {
        *d++ = *s++;
    }
    // Most of these functions return the destination, just in case
    // that's useful to the caller.
}
```

Right there at the beginning, we copy the void* into `char*s` so we can use them as `char*s`. It's easy as that.

Then in a while loop, we decrement `byte_count` until it becomes (0). Remember that with post-increment, the value of the expression is computed (for while we use) and then the variable is decremented.

And in some copy, we assign `*d = *s;` to copy the byte, but we do it with post-increment so both `d` and `s` move to the next byte after assignment is made.

Lastly, most memory and string functions return a copy of a pointer to the destination just in case the caller wants to use it.

Now that we've done that, I just want to point out that we can use this technique to iterate over the bytes of any object in C, floats, structs, or anything!

Let's run one more real-world example with the built-in `qsort()` routine that can sort anything thanks to the magic of void*.

(In the following example, you can ignore the word count, which we haven't covered yet.)

```c
#include <stdio.h>
#include <stdlib.h>

// The type of structure we're going to sort
struct animal {
    char *name;
    int leg_count;
};

// This is a comparison function called by qsort to help determine
// what exactly to sort by. We'll use it to sort an array of struct
// animals by leg_count.
int comp(const void *elem1, const void *elem2)
{
    // We know we're sorting animals, so let's make both
    // arguments pointers to struct animals
    const struct animal *animal1 = elem1;
    const struct animal *animal2 = elem2;

    // Return <00 or >0 depending on whatever we want to sort by.

    // Let's sort ascending by leg_count, so we'll return the difference
    // in the leg_counts
    if (animal1->leg_count > animal2->leg_count)
        return 1;

    if (animal1->leg_count < animal2->leg_count)
        return -1;

    return 0;
}

int main(void)
{
    // Let's build an array of 4 animals with different
    // characteristics. This array is out of order by leg_count,
    // we'll sort it in a second.
    struct animal a[4] = {
        {.name="Dog", .leg_count=4},
        {.name="Monkey", .leg_count=2},
        {.name="Antelope", .leg_count=4},
        {.name="Snake", .leg_count=0}
    };

    // Call qsort to sort the array. qsort needs to be told exactly
    // what to sort this data, and we'll do that inside the comp()
    // function.

    // This call is saying: qsort array a, which has 4 elements, and
    // each element is sizeof(struct animal) bytes big, and this is the
    // function that will compare any two elements.
    qsort(a, 4, sizeof(struct animal), comp);

    // Print them all out
    for (int i = 0; i < 4; i++) {
        printf("%d: %s\n", a[i].leg_count, a[i].name);
    }
}
```

As long as you give `sort()` a function that can compare two items that you have in your array to be sorted, it can sort anything. And it does this without needing to have the types of the items hardcoded in there anywhere. `qsort()` just rearranges blocks of bytes based on the results of the `comp()` function you passed in.

# 12. Manual Allocation

In many languages, memory is handled for you, but in C, you have to manage it yourself. This means you have to allocate memory when you need it and free it when you're done.

The heap is a large pool of memory that you can use at runtime. To get memory from the heap, we use `malloc()`. `malloc` stands for "memory allocation". It returns a pointer to the first byte of the allocated block.

The signature of `malloc()` is:
```c
void *malloc(size_t size);
```
The `size` argument is the number of bytes you want to allocate. It returns a `void*`, which is a generic pointer that can be converted to any other pointer type. If `malloc()` fails to allocate memory, it returns `NULL`.

It is always important to check if `malloc()` returned `NULL`.

```c
int *ptr = malloc(sizeof(int));
if (ptr == NULL) {
    // Handle error
    return 1;
}
```

Once you're done with the allocated memory, you must call `free()` to return it to the system. Failure to do so results in a memory leak.

```c
free(ptr);
```

After calling `free(ptr)`, the pointer becomes "dangling" because it still points to memory that is no longer yours. It's good practice to set it to `NULL` after freeing it.

```c
free(ptr);
ptr = NULL;
```
