And if you think about it, these rules make sense. All those operations rely on knowing the size of the data pointed to, and with void*, we don't know the size of the data being pointed to—it could be anything!

But wait—if you can't dereference a void* what good can it do for you?

Like memcpy(), it helps you write generic functions that can handle multiple types of data. But the secret is that, deep down, you convert the void* to another type before you use it!

Assignment is also easy: you can just assign it to a variable of the desired type.

```
char a = 'X'; // A single char
void *p = &a; // p points to the 'X'
char *q = p; // q also points to the 'X'
```

```
printf("%s\n", p); // ERROR-cannot dereference void*\nprintf("%s\n", q); // Prints "X"
```

Let's write our own memcpy() to try this out. We can copy bytes (chars), and we know the number of bytes because it's passed in.

```
void *my_memcpy(void *dest, void *src, int byte_count) {
char *s = src, *d = dest;

// Now we have char*s, we can dereference and copy them
while (byte_count--) {
    *d++ = *s++;
}
```

// Most of these functions return the destination, just in case
// that's useful to the caller.

Right there at the beginning, we copy the void* into char*s so we can use them as char*s. It's easy as that.

Then some in a while loop, we decrement byte_count until it becomes (0). Remember that with post-increment, the value of the expression is computed (for while we use) and then the variable is decremented.

And in some copy, we assign *d = *s; to copy the byte, but we do it with post-increment so both d and s move to the next byte after assignment is made.

Lastly, most memory and string functions return a copy of a pointer to the destination just in case the caller wants to use it.

Now that we've done that, I just want to point out that we can use this technique to iterate over the bytes of any object in C, floats, structs, or anything!
