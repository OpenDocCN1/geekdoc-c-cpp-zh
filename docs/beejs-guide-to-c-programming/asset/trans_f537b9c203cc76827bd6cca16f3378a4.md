# 2.1 对 C 语言的预期

“这些楼梯通向哪里？”
“它们通向上方。”
—Ray Stanz 和 Peter Venman，《捉灵器员》

C 是一门低级语言。

它过去并非如此。在那个人们还在花岗岩上刻制打孔卡的时代，C 是一种摆脱汇编¹等低级语言枯燥工作的惊人方式。

但在现代社会，当代语言提供了各种在 1972 年 C 发明时并不存在的功能。这意味着 C 是一门非常基础的语言，功能并不多。它可以做任何事情，但它会让你为此付出努力。

那么，我们为什么要使用它呢？

- 作为一种学习工具：C 不仅是一段多功能的计算历史，而且在某些现代语言无法做到的方面，它与裸机²直接相连。当你学习 C 时，你学习的是软件在底层是如何与计算机内存交互的。这里没有安全带。我向你保证，你将写出崩溃的软件。而这一切都是乐趣！
- 作为一种实用的工具：C 用于某些应用，例如操作系统³或嵌入式系统⁴。（尽管 Rust⁵ 编程语言正盯着这些领域！）

如果你熟悉另一种也处理指针的语言，那么几乎一切都很简单，但指针是异异的。指针背后的概念可能是你已经熟悉的，但 C 语言迫使你显式地使用它，使用你从未见过的运算符。

它是特别阴险的，因为当你领会⁶ 指针时，它们突然变得简单了。但在那时刻之前，它们就像滑溜的泥鱼。

# 2.2 Hello, World!

这是一个 C 程序的经典示例。每个人都使用它。（注意：左侧的数字仅供读者参考）。

- Hello world <stdio.h>

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n"); // 实际执行工作
}
```

我们将戴上厚手套，拿起手术刀，剖析这个东西，看看它是如何运作的。所以，准备好了，我们开始。

- /* */ 之间的任何内容都是注释，编译器会忽略它们。这允许你给自己和他人留下信息，以便在遥远的未来读回代码时，知道你曾想做什么。相信我，你会忘记的；

现在，什么是预处理器？问得好。编译有两个阶段：预处理器和编译器。任何以井号（或“八角号”）开头的内容都是在编译器启动之前预处理器处理的内容。常见的预处理器指令，正如它们所称的那样，有 #include 和 #define。

在我们继续之前，我为什么非要指出井号被称为 octothorpe？答案很简单：我觉得 octothorpe 这个词极其幽默，我必须在任何有机会的地方愉快地传播它。Octothorpe。Octothorpe，octothorpe。

在 C 预处理器处理完成后，结果已准备好供编译器提取生成汇编代码、机器码或它即将做的任何内容。机器码是 CPU 理解的“语言”，而且它理解非常快。这是 C 程序需要的原因之一。

现在不要担心编译的细节细节；只需知道你的源码通过预处理器，编译器通过其输出生成你可以运行的可执行文件。
