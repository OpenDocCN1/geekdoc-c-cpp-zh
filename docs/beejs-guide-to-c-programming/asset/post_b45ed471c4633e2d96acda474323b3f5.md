```c
case 3:
printf("3\n");
break;
```

If x == 1, this switch will hit case 1, it'll print the 1, but then it continues on the next line of
code... which prints 1!

And then, at last, we hit a break so we jump out of the switch.

if x == 2, then we just hit the case 2, print 2, and break as normal.

Not having a break is called fallthrough.

ProTip: ALWAYS put a comment in the code where you intend to fall through, like I did above. It will save
other programmers from wondering if you meant to do that.

In fact, this is one of the common places to introduce bugs in C programs: forgetting to put a break in your
case. You gotta do it if you don't want to roll into the next case^10.

Earlier I said that switch works with integer types—keep it that way. Don't use floating point or string types
inere. One loophole-ish thing here is that you can use character types because those are integers
them.

```c
char c = 'b';

switch (c) {
case 'a':
printf("It's 'a\n");
break;
case 'b':
printf("It's 'b\n");
break;
case 'c':
printf("It's 'c\n");
break;
}
```

Finally, you can use enums in switch since they are also integer types. But more on that in the enum chapter.

> ^10This was considered such hazard that the designers of the Go Programming Language made break the default; you have to
explicitly use Go's fallthrough statement if you want to fall into the next case.

## Functions

"Sir, not in an environment such as this. That's why I've also been programmed for over thirty secondary functions that—"

—C3PO, before being rudely interrupted, reporting a now-impressive number of additional functions, Star Wars script

Very much like other languages you're used to, C has the concept of functions.

Functions can accept a variety of arguments and return a value. One important thing, though: the arguments and return types are predeclared—that's how C calls it!

Let's take a look at this function. This is a function that takes an int as an argument, and returns an int.

```c
#include <stdio.h>

int plus_one(int n) // The "definition"
{
    return n + 1;
}
```

The int before the plus_one indicates the return type.
The int indicates that this function takes int argument, stored in parameter n. A parameter is a special type of local variable into which arguments are copied.

I'm going to drive home the point that the arguments are copied into the parameters, here. Lots of things in C are easier to understand if you know that the parameter is a copy of the argument, not the argument itself. More on that in a minute.

Continuing the program down into main(), we can see the call to the function, where we assign the return value into local variable j:

```c
int main(void)
{
    int i = 10, j;

    j = plus_one(i); // The "call"

    printf("%i + 1 is %d\n", j);
}
```

### 4.1 Passing by Value

I'd mentioned earlier that when you pass an argument to a function, a copy of that argument gets made and stored in the corresponding parameter.

If the argument is a variable, a copy of the value of that variable gets made and stored in the parameter.
More generally, the entire argument expression is evaluated and its value is determined. That value is copied to the parameter.

In any case, the value in the parameter is its own intent. It is independent of whatever values or variables you used as arguments when you made the function call.

So let's look at an example. Study it and see if you can determine the output before running it:

```c
#include <stdio.h>

void increment(int a)
{
    a++;
}

int main(void)
{
    int i = 10;

    increment(i);

    printf("i == %d\n", i); // What does this print?
}
```

## Chapter 4. Functions

At first glance, it looks like i is 10, and we pass it to the function increment(). There the value gets incremented, when we print it, it must be 11, right?

> "Get used to disappointment."
—Dread Pirate Roberts, The Princess Bride

But it's not 11—it prints 10! 

It's all about that the expressions you pass to functions copied onto their corresponding parameters. The parameter is a copy, not the original.

So i is 10 out in main(). And we pass it to increment(). The corresponding parameter is called a in that function.

And the copy happens, as if by assignment. Loosely, a = i. So at that point, a is also 10. And out in main(), i is also 10.

Then we increment to 11. But we're not touching i at! It remains 10.

Finally, the function is complete. All local variables are discarded (bye, a!) and we return to main(), where i is still 10.

And we print it, 10, and we're done

This is why in the previous example with the plus_one() function, we returned the locally modified value so that we could see it in main().
