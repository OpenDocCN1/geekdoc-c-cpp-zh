
## 12.3 Allocating Space for an Array

We've seen how to allocate space for a single thing; now what about a bunch of them in an array?

In C, an array is a bunch of the same thing back-to-back in a contiguous stretch of memory.

We can allocate a contiguous stretch of memory—we've seen how to do that. If we wanted 3490 bytes of memory, we could just ask for it:

```c
char *p = malloc(3490); // Voila
```

And--indeed—that's an array of 3490 chars (A string!) since each char is 1 byte. In other words, sizeof(char) is 1.

Note: there's no initialization done the newly-allocated memory—it's full of garbage. Clear it with memset() if you want to, or calloc(), below.

But we can just multiply the size of the thing by the number of elements we want, and access them using either pointer or array notation. Example!

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    // Allocate space for 10 ints
    int *p = malloc(sizeof(int) * 10);

    // Assign values 0-45:
    for (int i = 0; i < 10; i++)
        p[i] = i * 5;

    // Print all values 0, 5, 10, 15, ..., 45
    for (int i = 0; i < 10; i++)
        printf("%d\n\n", p[i]);

    // Free the space
    free(p);
}
```

The key's in malloc() line. If we know each int takes sizeof(int) bytes to hold it, and we know 10 of them, we can just allocate that many bytes by

```c
sizeof(int) * 10
```

And this trick works for every type. Just pass it to sizeof and multiply by the size of the array.

## 12.4 An Alternative: calloc()

This is another allocation that functions similarly to calloc(), with two key differences:

- Instead of a single allocation, you pass the size of one element, and the number of elements to allocate. It's like it's made for allocating arrays.
- It clears the memory to zero.

You still use free() to deallocate memory obtained through calloc().

Here's a comparison of calloc() and malloc():

```c
// Allocate space for 10 ints with calloc(), initialized to 0:
int *p = calloc(10, sizeof(int));

// Allocate space for 10 ints with malloc(), initialized to 0:
int *q = malloc(10 * sizeof(int));
memset(q, 0, 10 * sizeof(int)); // set to 0
```

Again, the result is the same size for both except malloc() doesn't zero the memory by.

## 12.5 Changing Allocated Size with realloc()

If you've already allocated 10 ints, but later you need 20, what can you do?

One option is to allocate some new space, and then memcpy the memory over... but it turns out sometimes you don't need to move anything. And there's one function that's smart enough to do the right thing in all circumstances: realloc().

It takes a pointer to some previously-allocated memory (by malloc() or calloc()) and a new size for the memory region to be.

It grows or shrinks that memory, and returns a pointer to it. Sometimes it might return the same pointer (if the data didn't have to be copied elsewhere), or it might return a different one (if the data had to be copied).

Be sure when you realloc(), you specify the number of bytes to allocate, and not just the number of elements that!

```c
num_floats = 2;
```

```c
np = realloc(p, num_floats); // WRONG: need bytes, number of elements!
```

```c
np = realloc(p, num_floats * sizeof(float)); // Better!
```

Let's allocate an array of 20 floats, and change our one and make it an array of 40.

We're going to assign the return value of realloc() into another pointer to make sure it's NULL. If it's not, then we can reassign it to our original pointer. (If we assigned the return value directly into the original pointer, we'd lose pointer if the function returned NULL and we'd have no way to get it back).

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    // Allocate space for 20 floats
    float *p = malloc(sizeof(float) * 20); // sizeof *p is sizeof(float)

    // Assign fractional values 0.0-1.0:
    for (int i = 0; i < 20; i++)
        np[i] = i / 20.0;

    // But wait! Let's actually make this an array of 40 elements
    float *new_p = realloc(p, p * 40);

    // Check to see if we successfully reallocated
    if (new_p == NULL) {
        printf("Error reallocing\n");
        return 1;
    }

    // If we did, we can just reassign p
    p = new_p;

    // And assign the new elements in the range 20-40
    for (int i = 20; i < 40; i++)
        p[i] = (i - 20) / 20.0;

    // Print all values 0-40
    for (int i = 0; i < 40; i++)
        printf("%f\n", p[i]);

    // Free the space
    free(p);
}
```

Notice how we took return value from realloc() and reassigned it into the same pointer p that passed in. That's pretty common. If also line is looking weird, remember that sizeof *p is equivalent to sizeof(float).

## 12.5.1 Reading Lines of Arbitrary Length

I want to demonstrate two things with this full-blown example:

1. Use of realloc() to grow a buffer as we need more data.
2. Use of realloc() to shrink the buffer down to the perfect size after we've completed the read.

What we see is a loop that calls getc() over and over to append to a buffer until we see that last character is a newline. Once it finds newline, it shrinks the buffer to just the right size and returns it.

```c
#include <stdio.h>
#include <stdlib.h>

char *readline(FILE *fp)
{
    int offset = 0; // Index next in the buffer
    int bufsize = 4; // Ideally power of 2 initial size
    char *buf; // The character we've read
    int c;

    buf = malloc(bufsize); // Allocate buffer
    if (buf == NULL) // Error check
        return NULL;

    // Main loop--read until newline or EOF
    while ((c = getc(fp)) != '\n' && c != EOF) {
        // Check if we're out of room in the buffer accounting for the extra byte for the NUL terminator
        if (offset == bufsize - 1) { // -1 for NUL terminator
            bufsize *= 2; // 2x the space

            char *new_buf = realloc(buf, bufsize);

            if (new_buf == NULL) {
                free(buf); // On error, free and bail
                return NULL;
            }

            buf = new_buf; // Successful realloc
        }
        buf[offset++] = c; // Add the byte onto buffer
    }

    // We hit newline or EOF...
    // If at EOF and we read bytes, free the buffer and return NULL to indicate we're at EOF:
    if (c == EOF && offset == 0) {
        free(buf);
        return NULL;
    }

    // Shrink to fit
    if (offset < bufsize - 1) { // If we're short of the
        char *new_buf = realloc(buf, offset + 1); // +1 for NUL terminator

        // If successful, point buf to new_buf;
        // otherwise we'll leave buf where it is
        if (new_buf != NULL)
            buf = new_buf;
    }

    // Add the NUL terminator
    buf[offset] = '\0';

    return buf;
}

int main(void)
{
    FILE *fp = fopen("foo.txt", "r");
    char *line;

    while ((line = readline(fp)) != NULL) {
        printf("%s\n", line);
        free(line);
    }
    fclose(fp);
}
```

When moving memory like this, it's common (though hardly a law) to double the space needed each step to minimize the number of realloc(s) that occurs.

Finally you might note that readline() returns a pointer to a malloc() buffer. As such, it's up to the caller to explicitly free() that memory when it's done with it.

## 12.5.2 realloc with NULL

Trivial time! These lines are equivalent:

```c
char *p = malloc(3490);
char *p = realloc(NULL, 3490);
```

That could be convenient if you have some kind of allocation loop and you don't want to special-case the first malloc().

```c
int *p = NULL;
int length = 0;

while (!done) {
    // Allocate 10 more ints:
    length += 10;
    p = realloc(p, sizeof *p * length);

    // Do amazing things
    //
}
```

In example, we didn't need an initial malloc() since p was NULL to start.

## 12.6 Aligned Allocations

You probably aren't going to use this.

And don't want to get too far off in the weeds talking about it now, but there's this thing memory alignment, which has to do with the memory address (pointer value) being a multiple of a certain number.

For example, a system might require 16-bit values begin on memory addresses that are multiples of 2. Or that 64-bit values begin on memory addresses that are multiples of 2, 4, 8, or for example. It depends on the CPU.

Some systems require this kind of alignment for fast memory access, or even memory access for all. Now, if you use malloc( ), calloc( ), or realloc( ), will give you a chunk of memory that is well-aligned for any value at all, even structs. Works in all cases.

But there might be times that you know some data can be aligned at a smaller boundary, or must be aligned at a larger one for some reason. I imagine this is more common with embedded systems programming.

In those cases, you can specify an alignment with an aligned_alloc( ).
