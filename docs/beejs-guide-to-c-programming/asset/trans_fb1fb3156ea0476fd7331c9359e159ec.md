## 17.3 static extern

这并不是规范的一部分，但在 C 世界中是 99.999% 常见的。

你可以将 C 文件编译为一种称为对象文件（object files）的中间表示。这些是尚未放入可执行文件的编译机器码。

Windows 中的对象文件具有 .OBJ 扩展名；在 Unix 类系统中，它们是 .o。

在 gcc 中，我们可以使用 `-c`（仅编译！）标志位来构建如下内容：

```c
gcc -c foo.c      # 生成 foo.o
gcc -c bar.c      # 生成 bar.o
```

然后我们可以将它们链接成一个单一的可执行文件：

```c
gcc -o foo.o bar.o
```

漂亮了，我们从两个对象文件生成了一个可执行文件 foo。

但你可能想，何必费此？我们不能直接：

```bash
gcc -o foo.c bar.c
```

并一石子二鸟吗？

对于小型程序，这没问题。我经常这样做。

但对于较大的程序，我们可以利用这样一个事实：从源码编译到对象文件相对慢，而链接一组对象文件相对快。

这在只重建比其输出文件新的源文件的工具中体现得尤为明显。

假设你有一千个 C 文件。你可以先编译所有对象文件（缓慢地），然后将所有对象文件合并成可执行文件（快速地）。

现在假设你修改了其中一个 C 源文件——魔法发生了：你只需要为该源文件重新构建那一个对象文件！然后重新构建可执行文件（快速）。所有其他 C 文件都不需要碰。

## 18.1 命令行参数

许多命令行工具接受命令行参数。例如，如果我们想查看所有以 .txt 结尾的文件，我们可以在 Unix 类系统上输入如下内容：

```bash
ls *.txt
```

（或在 Windows 系统上用其他代替 ls）。

在这种情况下，命令是 ls，但所有参数都是以 .txt 结尾的文件¹。

那么，我们如何看到从命令行传递到程序的参数呢？

假设我们有一个名为 `add` 的程序，它会加上命令行传递的所有数字并打印结果：

```bash
../add 10 30 5
45
```

这可用来付账单了！

但说真的，这是一个观察如何从命令行获取这些参数并拆解它们的绝佳工具。

```
arg 0: ./foo
```

这有点奇怪，因为第零个参数是可执行文件本身。但这只是需要习惯的。参数本身紧随其后。

来源：

```c
#include <stdio.h>

int main(int argc, char *argv[]) {

    for (int i = 0; i < argc; i++) {
        printf("%d %s\n", i, argv[i]);
    }
}
```

哇！`main()` 函数的签名是怎么回事？`argc` 和 `argv`²（读作 arg-cee 和 argv-wee） 是什么？

让我们从简单的开始：`argc`。它是参数计数，包括程序名本身。如果你把所有内容看作一个字符串数组（它们确实就是数组），那么你就可以把 `argc` 视为该数组的长度，这恰恰就是它的本质。

因此，我们在循环中做的是遍历所有的 `argv` 并逐一个地打印它们，所以对于给定的：

```
./foo i like turtles

arg 0: ./foo
arg 1: i
arg 2: like
arg 3: turtles
```

考虑到这些，让我们看看如何获取所有命令行参数。我们的计划是：

- 使用 `argc` 计数参数
- 使用 `argv` 访问字符串
- 遍历数组并打印每一个

```c
#include <stdio.h>

int main(int argc, char *argv[]) {

    for (int i = 0; i < argc; i++) {
        printf("%d %s\n", i, argv[i]);
    }
}
```
