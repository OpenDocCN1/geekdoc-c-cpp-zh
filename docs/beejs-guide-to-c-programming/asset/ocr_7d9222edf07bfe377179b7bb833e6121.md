# 19.2 Simple Macros

A macro is an identifier that expanded to another piece of code before the compiler even sees it. Think of it like a placeholder—when the preprocessor sees one of these identifiers, it replaces it with another value that you've defined.

Do this with #define (often read as "pound define"). Here's an example:

```
#include <stdio.h>

#define HELLO "Hello, world"
#define PI 3.14159

int main(void)
{
    printf("%s, %f\n", HELLO, PI);
}
```

On lines 3 and 4 we defined a macros. Wherever these appear elsewhere in the code (line 8), they'll be substituted with the defined values.

From the compiler's perspective, it's exactly as if we'd written this, instead:

```
#include <stdio.h>

int main(void)
{
    printf("%s, %f\n", "Hello, world", 3.14159);
}
```

See HELLO was replaced with "Hello, world" and PI was replaced with 3.14159? From the compiler's perspective, it's just like those values had appeared right there in the code. If the resulting C code is invalid, the compiler will puke.

Note that the macros don't have a specific type, per se. Really all that happens is they get replaced wholesale with whatever they're #defined as.

You can also define a macro with no value:

```
#define EXTRA_HAPPY
```

in that case, the macro exists and is defined, but is defined to nothing. So ayrıca it occurs in the text will be replaced with nothing. We'll see some use for this later.

It's conventional to write macro names in ALL_CAPS even though that's not technically required.

Overall, this gives you a way to define constant values that are effectively global and can be used any place. Even in places where a constant variable won't work, e.g. in switch cases and fixed array lengths.

That said, the debate ranges online whether a typed const variable is better than #define macro in the general case.

It can also be used to replace or modify keywords, a concept completely foreign to const, though this practice should be used sparingly.
