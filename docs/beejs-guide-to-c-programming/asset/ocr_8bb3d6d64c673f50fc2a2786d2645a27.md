# 27.10 Parse State, Restartable Functions

We're going to get a little bit into the guts of multibyte conversion, which is a good thing to understand, conceptually.

Imagine your program tracks a sequence of multibyte characters and turns them into wide characters, or vice-versa. It might, at some point, be partway through parsing a character, or it might have to wait for more bytes before it makes the determination of the final value.

This parse state is stored in an opaque variable of mbstate_t and is used every time conversion is performed. That is how the conversion functions keep track of where they are mid-work.

And if you need to change a character mid-stream, or try to seek to a different place in your input sequence, it could get confused over that.

Now you want to call me on one thing: we did some conversions, and I never mentioned any mbstate_t anywhere.

That's because the conversion functions like mbstows(), wcstomb(), etc. each have their own mbstate_t variable that they use. There's only one function, though, if you're writing multithreaded code, they're not safe to use.

Fortunately, we defines restartable versions of these functions where you can pass in your own mbstate_t per-thread if you need to. If you're doing multithreaded stuff, use these!

Quick note on initializing an mbstate_t variable: just memset() it to Zero. There's no built-in function to force it to be initialized.

mbstate_t mbs;

```
// Set the state to the initial state
memset(&mbs, 0, sizeof(mbs));
```
