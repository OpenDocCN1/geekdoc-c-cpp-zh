

# 第 16 章

## 类型 IV：限定符与说明符

现在我们已经掌握了更多类型，事实证明我们可以给这些类型添加一些额外的属性来控制它们的行为。这些就是类型限定符和存储类说明符。

## 16.1 类型限定符 (Type Qualifiers)

这些限定符允许你声明常量值，并为编译器提供一些优化提示。

### 16.1.1 const

这是你最常见的类型。它意味着该变量是常量，任何修改它的尝试都会导致编译器变得非常愤怒。

```c
const int x = 2;

x = 4; // 编译器发出了呕吐声，不能给常量赋值
你不能改变常量的值。
```

你通常会在函数的参数列表中看到它：

```c
void foo(const int x)
{
    printf("%d\n", x + 30); // OK，没有修改 "x"
}
```

### 16.1.1 const 与指针

这部分变得有点复杂，因为涉及到指针时，有两种用法对应两种不同的含义。
首先，我们可以让你无法改变指针所指向的内容。你通过在类型声明中将 `const` 放在类型名后面（星号之前）来实现这一点。

```c
int x[] = {10, 20};
const int *p = x;

p++; // 我们可以修改 p，没问题
*p = 30; // 编译器错误！不能改变它指向的内容
```

令人困惑的是，这两者是等价的：

```c
const int *p; // 不能修改 p 指向的内容
const int *p; // 不能修改 p 指向的内容，与上一行一样
```

太好了，我们可以改变指针指向的内容，但可以改变指针本身。如果我们想要相反的操作呢？我们希望能够改变指针指向的内容，但不能改变指针本身？

只需在声明中将 `const` 移动到星号后面：

```c
int *const p; // 我们不能通过指针算术修改 "p"

p++; // 编译器错误！
```

但我们可以修改它们指向的内容：

```c
int x = 10;
int *const p = &x;

p = 20; // 将 "x" 设置为 20，没问题
```

你也可以让两者都成为 `const`：

```c
const int *const p; // 不能修改 p 或 *p！
```

如果你有多个级别的间接层，你应该设置相应的级别。仅仅因为指针是 `const`，并不意味着它指向的指针也必须是 `const`。你可以像下面的示例一样显式地设置它们：

```c
char **p;
p++; // OK!
(*p)++; // OK!
```

```c
char **const p;
p++; // Error!
(*p)++; // OK!
```

```c
char *const *const p;
p++; // Error!
(*p)++; // Error
```

### 16.1.1.2 正性 (Correctness)

我必须提到的是，编译器会对类似这样的给出警告：

```c
const int x = 20;
int *p = &x;
```

信息大致为：
初始化丢弃了指针类型目标的 'const' 限定符

这里发生了什么？
嗯，我们需要查看赋值两边的类型：

```c
const int x = 20;
int *p = &x;
      ^ ^
```

```c
// | |
// int* const int*
```

编译器正在警告我们，赋值右侧的值是 `const` 的，但左侧的一个不是。编译器在告诉我们，它正在丢弃右侧表达式的“常量性”。

也就是说，我们仍然可以尝试执行以下操作，但这是错误的。编译器会警告，而且这是未定义行为：

```c
const int x = 20;
int *p = &x;
```

```c
*p = 40; // 未定义行为——可能修改了 "x"，也可能没有！
printf("%d\n", x); // 如果你运气好，是 40
```

### 16.1.2 restrict

简而言之（TLDR）：你永远不需要使用它，每次看到它时都可以忽略它。如果你使用正确，你会发现一些性能提升。如果你使用不当，你会遇到未定义行为。
`restrict` 是对编译器的提示，表示特定的内存将被由一个指针访问，永远不会被另一个访问。如果开发者声明一个指针为 `restrict`，然后通过另一种方式（例如通过另一个指针）访问它指向的对象，则该 `restrict` 指针的行为是未定义的。

C 使用该信息执行某些优化。例如，如果你在循环中解引用 `restrict` 指针，C 可能会缓存结果，仅在循环结束后存储最终结果。如果有任何其他指针引用了该内并在循环中访问它，结果将是不准确的。

（注意，如果指向的对象从未被写入，`restrict` 就没有影响。它完全是为了围绕内存的优化。）

让我们写一个交换两个变量的函数，并使用 `restrict` 关键字向 C 语言保证这一点。

```c
void swap(int *restrict a, int *restrict b)
{
    int t = *a;
    *a = *b;
    *b = t;
}

int main(void)
{
    int x = 10, y = 20;
    swap(&x, &y);
    printf("x=%d, y=%d\n", x, y);
    return 0;
}
```

## 16.2 存储类说明符 (Storage-Class Specifiers)

存储类说明符与限定符类似。它们为编译器提供更多关于变量的信息。

### 16.2.1 auto

你几乎很少看到这个关键字，因为 `auto` 是块作用域的默认值。它是隐式的。

```c
{
  int a; // auto 是默认的...
  auto int a; // 所以这是多余的
}
```

`auto` 关键字表示该对象具有自动生存期。也就是说，它存在定义的作用域内，并在退出作用域时自动删除。

自动变量的陷阱在于它们在初始化之前的值是不定的。我们说它们充满了“随机”或“垃圾”数据，尽管这两种说法都不准确。无论如何，除非初始化，否则你不知道里面有什么。

在使用之前初始化所有自动变量！

### 16.2.2 static

这个关键字有两个含义，取决于变量是在文件作用域还是块作用域。

让我们从块作用域开始。

#### 16.2.2.1 块作用域中的 static

也就是说，它的值会在调用之间保持。带有初始化器的静态块变量会在程序启动时初始化一次，而不是每次调用函数时初始化。

让我们来看一个例子：

```c
#include <stdio.h>
void counter() {
  static int counter = 1; // 这初始化一次

  printf("This has been called %d time(s)\n", counter);

  counter++;
}

int main(void)
{
  counter(); // "This has been called 1 time(s)"
  counter(); // "This has been called 2 time(s)"
  counter(); // "This has been called 3 time(s)"
  counter(); // "This has been called 4 time(s)"
}
```

看到计数器的值在调用之间保持了吗？

需要注意的是，静态块变量默认初始化为 0。

```c
static int foo; // 默认初始值为 '0'
static int foo = 0; // 所以 '0' 赋值是多余的
```

最后，请注意，如果你在编写多线程程序，必须确保不要让多个线程争踏同一个变量。
