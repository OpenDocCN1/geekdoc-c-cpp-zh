# Chapter 20. structs II: More Fun with structs

A quick rearrangement yields space savings from 16 bytes down to 12 bytes (on your system):

```
struct foo {
    // sizeof(struct foo) == 12 (for me)
    unsigned int a:1;
    unsigned int c:1;
    unsigned int b;
    unsigned int d;
};
```

And now, as a is int next to c, the compiler puts them together into a single int.

So we have one int for a combined a and c, and one each for b and d. For a grand total of 3 ints, or 12 bytes.

Put all your bitfields together get the compiler to combine them.

# 20.8.2 Signed or Unsigned ints

If you declare a bit-field to be int, the different compilers will treat it as signed or unsigned. Just like the situation with char.

Be specific about the signedness when using bit-fields.

# 20.8.3 Unnamed Bit-Fields

In some specific circumstances, you might need to reserve some bits for hardware reasons, but not need to use them in code.

For example, let's say you have a byte where the top 2 bits have meaning, the bottom 1 bit has meaning, but the middle 5 bits do not get used by you.

We could do something this:

```
struct foo {
    unsigned char a:2;
    unsigned char dummy:5;
    unsigned char b:1;
};
```

And that work—in our code we use a and b, but never dummy. It's just to eat up 5 bits to make sure a and b are in the "required" (by this example) positions within the byte.

C allows a way to clean up this: unnamed bit-fields. You can leave the name (dummy) out in this case, and C is perfectly happy for the effect:

```
struct foo {
    unsigned char a:2;
    unsigned char :5; //-- unnamed bit-field!
    unsigned char b:1;
};
```
