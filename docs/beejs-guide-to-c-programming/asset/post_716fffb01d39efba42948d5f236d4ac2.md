
## 19.3.5 Losing a Macro: #undef

If you've defined something but you don't need it any longer, you can undefine it with #undef.

```c
#include <stdio.h>

int main(void)
{
    #define GOATS

    #ifdef GOATS
    printf("Goats detected!\n"); // prints
    #endif

    #undef GOATS // Make GOATS no longer defined

    #ifdef GOATS
    printf("Goats detected, again!\n"); // doesn't print
    #endif
}
```

## 19.4 Built-in Macros

The standard defines a lot of built-in macros that you can test and use for conditional compilation. Let's look at those here.

### 19.4.1 Mandatory Macros

These are all defined:

| Macro | Description |
| --- | --- |
| __DATE__ | The date of compilation—like when you're compiling this file—in M dd yyyy format |
| __TIME__ | The time of compilation in hh:mm:ss format |
| __FILE__ | A string containing this file's name |
| __LINE__ | The line number of the file this macro appears on |
| __func__ | The name of the function this appears in, as a string² |
| __STDC__ | Defined with 1 if the standard C compiler |
| __STDC_HOSTED__ | This will be 1 if the compiler is a hosted implementation³, otherwise 0 |
| __STDC_VERSION__ | This version of C, a constant long int in the form yyyymmL, e.g. 20171L |

Let's put these together.

```c
#include <stdio.h>

int main(void)
{}
```

> ²²This isn't really a macro—it's technically an identifier. It is the only predefined identifier and feels very macro-like, so I'm including it here. Like a rebel.
> ³A hosted implementation basically means you're running the full C standard, probably on an operating system of some kind. You probably are. If you're running on bare metal in some kind of embedded system, you're probably on a standalone implementation.

```c
printf("This function: %s\n", __func__);
printf("This file: %s\n", __FILE__);
printf("This line: %d\n", __LINE__);
printf("Compiled on: %s %s\n", __DATE__, __TIME__);
printf("C Version: %ld\n", __STDC_VERSION__);
```

The output on my system is:

- This function: main
This file: foo.c
This line: 7
Compiled on: Nov 23 2020 17:16:27
C Version: 201710

__FILE__, __func__ and __LINE__ are particularly useful to report error conditions in messages to developers. The assert(macro) in <assert.h> uses these to call out where the code has assertion failed.

### 19.4.1 __STDC_VERSION__

In case you're wondering, here are the version numbers for different releases of the C Language:

| Release | ISO/IEC version | __STDC_VERSION__ |
| --- | --- | --- |
| C89 | ISO/IEC 9899:1990 | undefined |
| C89 | ISO/IEC 9899/Amd.1:1995 | 19949L |
| C99 | ISO/IEC 9899:1999 | 19990L |
| C11 | ISO/IEC 2011/Amd.1:2012 | 20112L |

The mark did not exist originally in C89.

Also note that the plan is the version numbers will strictly increase, so you could always check for, by "at least C99":

```c
#if __STDC_VERSION__ >= 199990L
```

### 19.4.2 Optional Macros

Your implementation might define these as well, or it might not.

| Macro | Description |
| --- | --- |
| __STDC_ISO_10646__ | If defined, wchar_t holds Unicode values, otherwise else |
| __STDC_MB_HIGHT_NEQ_WC__ | A 1 indicates that values in multibyte characters might not equal values in wide characters |
| __STDC_UTF_16_ | A 1 indicates that the system uses UTF-16 encoding in type char16_t |
| __STDC_UTF_32__ | A 1 indicates that the system uses UTF-32 encoding in type char32_t |
| __STDC_ANALYZABLE__ | A 1 indicates that the code is analyzable⁴ |
| __STDC_IEC_559__ | 1 if IEEE-754 (aka IEC 60559) floating point is supported |
| __STDC_IEC_60555_COMPLEX | 1 if IEC 60555 complex floating point is supported |

> OK, I know that was a cop-out author. Basically there's an optional extension compilers can implement they agree to limit certain types of undefined behavior so that the C code is more amenable to static analysis. It is unlikely you'll need to use this.

| Macro | Description |
| --- | --- |
| _STDC_LIB_EXT1_ | 1 if this implementation supports a variety of “safe” alternate standard library functions (they have _s suffixes on the name) |
| _STDC_NO_ATOMICS_ | 1 if this implementation does not support _Atomic or <stomic.h> |
| _STDC_NO_COMPLEX_ | 1 if this implementation does not support complex types or <complex.h> |
| _STDC_NO_THREADS_ | 1 if this implementation does not support <threads.h> |
| _STDC_NO_VLA_ | 1 if this implementation does not support variable-length arrays |

## 19.5 Macros with Arguments

Macros are more powerful than simple substitution, though. You can set them up to take arguments that are substituted in, as well.

A question often arises for when to use macros versus functions. Short answer: use functions. But you’ll see lots of macros in the wild and in the standard library. People tend to use them for short, mathy things, and also for features that might change from platform to platform. You can define keywords for one or the other.

### 19.5.1 Macros with One Argument

Let’s start with a simple one that squares a number:

```c
#include <stdio.h>

#define SQR(x) x * x // Not quite right, but bear with me

int main(void)
{
    printf("%d\n", SQR(3 + 4));
}
```

What’s saying is “everywhere you see SQR with some value, replace it with that value itself”. We’ve made an elementary error in that, one that we need to avoid. If we wanted to compute SQR(3 + 4)? Well, $(3+4)^2 = 49$, but the macro expansion gives:

```c
printf("%d\n", 3 + 4 * 4);
```

Oops! Since multiplication takes precedence, we do $4 \times 3 = 12$ first, and not what we were after. This is so common that you should automatically do it every time.

The fix is easy: just add some parentheses,

```c
#define SQR(x) (x) // Better... still not good enough
```

And now our macro expands to:

```c
printf("%d\n", (3 + 4) * (3 + 4)); // Woo!
```

But we will still have some problem if we have a higher-precedence operator than (*) nearby. The proper way to put the macro is to wrap the thing in additional parentheses, like:

```c
#define SQR(x) ((x)) // Good!
```

Just make it a habit to do that when you make math macro you can't go wrong.

### 19.5.2 Macros with One Argument

You can stack these things as much as you want:

```c
#define TRIANGLE(w, h) (0.5 * (w) * (h))
```

Let's make some macros for $x$ using the quadratic formula. In case you don't have it on your head, it says for equations of:

```
ax^2 + bx + c = 0
```

you can solve for $x$ with the quadratic formula:

```
x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}
```

Which is crazy. Also the plus-or-minus ($\pm$) in there, indicating that there are actually two solutions. Let's make some macros for:

```c
#define QUADP(a, b, c) (((-(b) + sqrt((b) * (b) - 4 * (a) * (c)))) / (2 * (a))
#define QUADM(a, b, c) (((-(b) - sqrt((b) * (b) - 4 * (a) * (c))) / (2 * (a)))
```

So that gets us some math. But let's define one more that we can use as arguments to printf() to print answers.

```c
//
// replacement
#define QUAD(a, b, c) QUADP(a, b, c), QUADM(a, b, c)
```

That's just some values separated by a comma—and we can use that as a "combined" argument of sorts to printf():

```c
printf("x = %f or x = %f\n", QUAD(2, 10, 5));
```

Let's put it together some code:

```c
#include <stdio.h>
#include <math.h> // For sqrt()
```

```c
#define QUADP(a, b, c) (-(b) + sqrt((b) - 4 * (a) * (c))) / (2 * (a))
#define QUADM(a, b, c) ((b) - sqrt((b) * (b) - 4 * (a) * (c))) / (2 * (a))
#define QUAD(a, b, c) QUADP(a, b, c), QUADM(a, b, c)

int main(void)
{
    printf("2*x^2 + 10*x + 5 = 0\n");
    printf("x = %f or x = %f\n", QUAD(2, 10, 5));
}
```

And this gives us the correct values:

2*x^2 + 10*x + 5 = 0
x = -0.563508 or x = -4.43642

Plugging in other values gives us roughly zero (a bit off because the numbers aren't):
-0.563508^2 + 10*-0.563508 ≈ 0

### 19.5.3 Macros with Variable Arguments

There is also a way to have a variable number of arguments passed to a macro, ellipses (...) after the known, named arguments. When the macro is expanded, all of the extra arguments will be in a comma-separated list in __VA_ARGS__ macro, and can be replaced from there:

```c
#include <stdio.h>

// Combine the first two arguments to a single number,
// then we have a comma list of the rest of them:
#define X(a, b, ...) (10*(a) + 20*(b)), __VA_ARGS__
int main(void)
{
    printf("%d %f %s\n", X(5, 4, 3.14, "Hi!", 12));
}
```

The substitution takes place on line 10 would be:
13 3.140000 Hi! 12

You can also "stringify" __VA_ARGS__ by putting a # in front of it:

```c
#define X(...) #__VA_ARGS__
printf("%s\n", X(1,2,3)); // Prints "1, 2, 3"
```

### 19.5.4 Stringification

Already mentioned, you can just turn any argument into a string by preceding it with a # in the replacement text.
For example, we could print anything as a string with this macro and printf():

```c
#define STR(x) #x
```

printf("%s\n", STR(3.14159));
```
