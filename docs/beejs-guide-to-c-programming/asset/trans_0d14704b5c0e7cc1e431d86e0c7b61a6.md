

# 第 14 章 类型 II：多得多的类型！

在我的系统上，`FLT_DIG` 是 6，所以我可以确定，如果我打印一个 6 位的浮点数，我将得到相同的结果。（它可能是更多位数——某些数字返回时会带有更多位数。但 6 位绝对是返回的。）

例如，按照这种位数递增的模式打印浮点数，我们显然在出现问题之前已经达到了 8 位，但之后（之后）我们又回到了 7 位正确的数字。

```
0.12345
0.123456
0.1234567
0.12345678
0.123456791 <-- 从这里开始出错
0.1234567910
```

让我们再做另一个演示。在这段代码中，我们有两个浮点数，这两个数字都有 `FLT_DIG` 位有效数字¹²。然后我们将它们相加，理论上应该有 12 位有效数字。但这超过了我们可以在浮点数中存储并恢复为字符串的范围——所以当我们打印它时，在第 7 位有效数字之后就开始出错。

```c
#include <stdio.h>
#include <float.h>

int main(void) {
    // 这两个数字都有 6 位有效数字，所以它们可以
    // 准确地存储在浮点数中：

    float f = 3.14159f;
    float g = 0.000002653538;

    printf("%.5f\n", f); // 3.14159 正确！
    printf("%.11f\n", g); // 0.000002653538 正确！

    // 现在将它们相加
    f += g;                // f 应该是 3.141592653538

    printf("%.11f\n", f); // 3.141592653724101 错误！
}
```

（上面的代码在数值常量后面有一个 `f`——这表示该常量是 `float` 类型，而不是 `double`。稍后会详细介绍。）

记住 `FLT_DIG` 是你可以在浮点数中存储的有效位数。有时你只能得到一或二位。但有时你会得到 `FLT_DIG` 位。可以肯定的的是：如果你在浮点数中存储包含 `FLT_DIG` 在内的任意位数，你一定能正确地找回它们。

故事就是这样。`FLT_DIG`。结束。
……或者没有？

## 14.4.2 转换为十进制和二进制

但将十进制存储在浮点数中并将其提取出来只是故事的一半。

> ¹²此程序正如其注释所示，运行在一个 `FLT_DIG` 为 6 且使用 IEEE-754 二进制浮点数的系统上。否则，你可能会得到不同的输出。

事实浮点数可以编码需要更多小数才能完整打印的数字。只是你的大十进制数可能映射到其中一个。

也就是说，当你查看相邻浮点数时，存在一个间隙。如果你尝试在该间隙中编码十进制，将使用最接近的浮点数。这就是为什么你只能为 `float` 编码 `FLT_DIG` 位。

但那些不在间隙中的浮点数呢？你需要多少位才能准确地打印它们？

这个问题的另一种表达方式是：对于任何给定的浮点数，如果我将十进制数转换回相同的浮点数，我需要保留多少个十进制数字？也就是说，我需要在十进制中打印多少位，才能恢复原始数字中二进制中的所有数字？

有时可能只有几位。但为了确保起见，你将希望使用某个安全的小位数转换为十进制。数字编码在以下宏中：

| 宏 | 描述 |
|---|---|
| FLT_DECIMAL_DIG | `float` 中编码的十进制位数。 |
| DBL_DECIMAL_DIG | `double` 中编码的十进制位数。 |
| LDBL_DECIMAL_DIG | `long double` 中编码的十进制位数。 |
| DECIMAL_DIG | 与最宽编码 LDBL_DECIMAL_DIG 相同。 |

让我们来看一个例子，其中 `DBL_DIG` 是 15（这样我们有一个常量），但 `DBL_DECIMAL_DIG` 是 17（因此我们必须转换为 17 位十进制以保留原始 `double` 的所有位）。

我们将 `0.123456789012345` 的 15 位赋值给 `x`，并将 1 位有效数字 `0.0000000000000006` 赋值给 `y`。

```
x 是: 0.123456789012345      打印 17 位小数
y 是: 0.0000000000000006
```

但让我们它们相加。看看：0.12345678901234536，但这超过了 `DBL_DIG`，所以可能会发生奇怪的事情。

```
x + y = 不完全对：0.12345678901234559      应该以 4560 结尾！
```

我们打印超过 `DBL_DIG` 位的结果就是这样，对吧？但看这个……上面的那个数字可以被精确地表示！如果我们把 `0.12345678901234559`（17 位）赋值给 `z` 并打印，我们得到：
z 是: 0.12345678901234559      17 位正确！

但随后——如果我们将 `z` 截断到 15 位，它的值将不再相同。为了保留 `double` 的所有位，我们需要 `DBL_DECIMAL_DIG` 而不仅仅是 `DBL_DIG`。

总而言之，很明显我们正在处理通用的十进制数，为了与原始基数及后续操作相关，打印超过 `FLT_DIG`、`DBL_DIG` 或 `LDBL_DIG` 位是不安全的。但在从 `float` 转换为十进制表示再转换回 `float` 时，务必使用 `FLT_DECIMAL_DIG` 以确保所有位都正确。

综上所述，很清楚我们在处理十进制数，打印超过 `FLT_DIG`、`DBL_DIG` 或 `LDBL_DIG` 位对于原始基数和任何后续操作来说是不安全的。但在从 `float` 转换为十进制表示再转换回 `float` 时，务必使用 `FLT_DECIMAL_DIG` 以确保所有位都正确。
