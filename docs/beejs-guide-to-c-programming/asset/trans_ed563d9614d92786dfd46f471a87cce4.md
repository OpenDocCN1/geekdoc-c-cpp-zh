

## 18.2 退出状态 (Exit Status)

你有没有注意到 `main()` 函数的签名返回类型是 `int`？这是怎么回事？这与一种所谓的“退出状态”有关，它是一个返回给启动它的程序的整数，用于告知程序运行情况如何。

现在，C 语言中有多种程序退出的方法：从 `main()` 返回，或者调用 `exit()` 的变体。

所有这些方法都接受一个 `int` 作为参数。

旁记：你是否注意到在我几乎所有的示例中，即使 `main()` 也应该返回一个 `int`，但我实际上并没有返回任何内容？在任何其他函数中这都是非法的，但 C 中有一个特殊情况：如果执行到 `main()` 的末尾而没有找到 `return`，它会自动返回 0。

但这意味着什么？我们还可以在那里放置什么数字？它们是如何使用的？

规范在这方面既清晰又模糊，这很常见。清晰是因为它列出了你可以做什么，但模糊之处在于它并没有特别限制你。

没有什么让它就此冲前进去搞清楚它

让我们先进入一下“盗梦空间”⁴：事实证明当你运行程序时，你是从另一个程序在运行它。

通常这个另一个程序是某种 shell⁵，它本身并不匹配什么，除了启动其他程序

- 1. shell 启动程序
- 2. shell 通常会进入睡眠状态（对于命令行 shell）
- 3. 你的程序运行
- 4. 你的程序终止
- 5. shell 唤醒并等待另一个命令

现在，在步骤 4 和 5 之间发生了一小段通信：该程序可以返回一个 shell 可以进行插值的状态值。通常，这个值用于指示你的程序的成功或失败，如果适用，还会指示什么类型的失败。

这个值就是我们一直从 `main()` 返回的值。它就是状态。

| 状态 | 描述 |
| --- | --- |
| EXIT_SUCCESS 或 0 | 程序成功退出。 |
| EXIT_FAILURE | 程序因错误退出。 |

让我们写一个从命令行读取两个数字并相乘程序。我们需要正好两个值。如果没有，我们将打印错误信息并以错误状态退出。

```c
#include <stdio.h>
#include <stdlib.h>
```

```c
int main(int argc, char **argv)
{
  if (argc != 3) {
    printf("usage: mult x y\n");
    return EXIT_FAILURE; // 告诉 shell 它没有成功
  }

  printf("%d\n", atoi(argv[1]) * atoi(argv[2]));

  return 0; // 等于 EXIT_SUCCESS，一切正常。
}
```

现在如果我们尝试运行它，在没有指定正确的命令行参数数量之前，我们会得到预期的效果：

```bash
$ ./mult x y
usage: mult x y

./mult 3 4 5
usage: mult x y
```

```bash
$ ./mult 3 4
12
```

但这并没有真正显示我们返回的退出状态，对吧？不过，我们可以让 shell 打印出来。假设你正在运行 Bash 或另一个 POSIX shell，你可以使用 `echo $?` 来查看。

让我们尝试：

```bash
$ ./mult x y
usage: mult x y
echo $?
1
```

```bash
$ ./mult 3 4 5
usage: mult x y
echo $?
1
```

```bash
$ ./mult 3 4
12
echo $?
0
```

很有意思！我们看到在我的系统中，`EXIT_FAILURE` 是 1。规范没有列出这一点，所以它可以是任何数字。但在你的系统上它也是 1。

### 18.2.1 其他退出状态值

状态 $0 绝对意味着成功，但所有其他整数，即使是负数呢？
在这里我们将进入 C 规范并进入 Unix 世界。通常情况下，虽然 $0 表示成功，但正非零数表示失败。Bash 虽说退出码应该在 0 到 255 之间，但有些状态码被预留了。

简而言之，如果你想在 Unix 环境中指示不同的错误状态，可以从 1 开始逐递增。

在 Linux 上，如果你尝试任何 0-255 范围内的代码，它将把代码与 `0xff` 进行位与运算，这实际上是将其限制在该范围内。

> *在 Windows 的 cmd.exe 中，输入 echo %errorlevel%。在 PowerShell 中，输入 $LastExitCode。*

你可以编写脚本使用这些状态码来对下一步做什么做出决策。

## 18.3 环境变量

在进入这个主题之前，我想提醒你，C 并没有规定什么是环境变量。因此，我将描述一种在我所知的每个平台上都有效的环境变量系统。

基本上，环境是指将运行你程序的程序，或者 bash shell。它可能定义了一些变量。万一你不知道，shell 可以创建自己的变量。每个 shell 都是不同的，但在 bash 中你只需要设置，它就会显示所有它们。

这里是 bash shell 中定义的 61 个变量的示例：

```
HOSTFILE=/home/beej/.bash_history
HOSTFILESIZE=500
HISTSIZE=500
HOME=/home/bee
HOSTNAME=FBILAPTOP
HOSTTYPE=XB8664
IFS='	'
```

注意它们是以键值对的形式存在的。例如，一个键是 `HOSTTYPE`，它的值是 `x8664`。从 C 的角度来看，所有值都是字符串，即使它们是数字？

总之！可以从你的 C 程序内部获取这些值。

让我们写一个使用标准 `getenv()` 函数来查找你在 shell 中设置的值的程序。

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	char *val = getenv("FROTZ"); // 尝试获取值

	// 检查它是否存在
	if (val == NULL) {
		printf("Cannot find FROTZ environment variable\n");
		return EXIT_FAILURE;
	}

	printf("%s\n", val);
}
```

如果我运行它，我会得到：

```
$ ./foo
Cannot find FROTZ environment variable
```

### 18.3.1 设置环境变量

尽可能使用 `getenv()`，因为它移植性更好。如果你必须遍历环境变量，使用 `environ` 可能是更好的选择。

### 18.3.2 Unix环境变量

另一种获取环境变量的非标准方法是作为 `main()` 的参数。它的工作方式非常相似，但你不需要添加 `extern environ` 变量了。据我所知，甚至 POSIX 规范都不支持这种方法，但在 Unix 世界中很常见。

```c
#include <stdio.h>

int main(int argc, char **argv, char **env) // <-- env!
    (void)argc; (void)argv; // 抑制未使用警告

    for (char **p = env; *p != NULL; p++) {
        printf("%s\n", p);
    }

    // 或者你可以这样做：
    for (int i = 0; env[i] != NULL; i++) {
        printf("%s\n", env[i]);
    }
}
```

就像使用 `environ` 一样，但移植性差。有目标是好事。
