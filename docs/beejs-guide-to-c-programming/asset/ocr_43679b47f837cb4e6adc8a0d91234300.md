# 2.6 Building from IDEs

If you're using an Integrated Development Environment (IDE), you probably don't have to build from the command line.

With Visual Studio, CTRL-F7 you can build and CTRL-F5 will run.

With VS Code, you can hit F5 to run via the debugger. (You'll have to install the C/C++ Extension.)

With Xcode, you can build with COMMAND-B and run with COMMAND-R. To get the command line tools, Google for "Xcode command line tools" and you'll find instructions for installing them.

For getting started, I encourage you to also try to build from the command line—it's history!

# 2.7 C Versions

C has come long way over the years, and it has many named version numbers to describe which dialect of the language you're using.

These generally refer to the year of the specification.

The most famous are C89, C99, C11, and C2x. We'll focus on the latter in this book.

But here's a complete table:

| Version | Description |
| --- | --- |
| K&R C | 1978, the original. Named after Brian Kernigh and Dennis Ritchie. Ritchie designed and coded the language, and Kernigh co-authored the book on it. You rarely see K&R code today. If you do, it'll look odd, like Middle English looks to modern readers.
| C89, ANSI C, C90 | In 1989, the American National Standards Institute (ANSI) produced a C language specification that set the tone for C that persists to this day. A year later, the reins were handed to the International Organization for Standardization (ISO) that produced the identical C90.
| C99 | A rarely-mentioned addition to C89 that included character support. The big overhaul with lots of language additions. The most people remember the addition of //+ comments. This is the most popular version of C in use of this writing.
| C11 | This major version includes Unicode support and multi-threading. Be advised that if you use these language features, you might be sacrificing portability with places that are still in C99. But, honestly, 1999 is getting to be a while back now.
| C17, C18 | Bugfree update to C17 seems to be the official name, but the publication was delayed until 2018. As far as I can, these are interchangeable, with C18 being preferred.
| C2x | What's coming next! Expected to eventually become C23.

You can force GCC to use one of these standards with the -std=c command line argument. If you want to be picky about standard, -pedantic.

For example:

```
gcc -std=c11 pediatric foo.c
```

For this book, I compile programs for C2x with all warnings set:

```
gcc -Wall -Wextra -std=c2x -pedantic foo.c
```
