# Chapter 23. Pointers III: Pointers to Pointers and More

C makes one guarantee, though you can convert a pointer to a uintptr_t type and you'll be able to convert it back to a pointer without losing any data.

uintptr_t is defined in `<stdint.h>`.

Additionally, if you feel like being signed, you can use intptr_t to cause the same effect.

# 23.5 Casting Pointers to other Pointers

There's only one safe pointer conversion:

+   1. Converting to intptr_t or uintptr_t.
2. Converting to and void*.

TWO! Two safe pointer conversions.

+   3. Converting to and char*.

THREE! Three safe conversions!

+   4. Converting and a pointer to a struct and a pointer to its first member, and vice-versa.

FOUR! safe conversions!
If you cast to a pointer of another type and access the object it points to, the behavior is undefined due to something called *strict aliasing*.

Plain old *aliasing* refers to the ability to have more than one way to access the same object. The access points are aliases for each other.

Strict aliasing says you are only allowed to access an object via compatible types to that object.

For example, this is defined as:

```
int a = 1;
int *p = &a;
```

p is a pointer to an int, and it points to a compatible type—namely int—so we are golden.

But the following isn't good because because int and float are not compatible types:

```
int a = 1;
float *p = (float *) &a;
```

Here's a demo that does aliasing. It takes a variable v of type uint32_t and aliases it to a pointer to a struct. That struct has int16_t in it. These are incompatible, so we're in violation of strict aliasing. The compiler will assume that these two pointers never point to the same object...but we're making it they do so. Which is naughty of us.

Let's see if we can break something.

```
#include <stdio.h>
#include <stdint.h>
```

```
struct words {
    int16_t v[2];
}
```
