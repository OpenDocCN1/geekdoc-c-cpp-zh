# Chapter 20. structs II: More Fun with structs

I want to be clear that the first part of the section is the old way of doing things, and we're going to do things the new way after that.

For example, maybe you could define a struct for holding strings and the length of that string. It would have a length and an array to hold the data. Maybe something like this:

```
struct len_string {
  int length;
  char data[8];
};
```

But that has 8 hardcoded as the maximum length of a string, and it's not much. What if we did something clever and just malloc() some extra space at the end of the struct, and then let the data overflow into that space?

Let's do that, and then allocate 40 bytes on top of it:

```
struct len_string *s = malloc(sizeof *s + 40);
```

Because data is the last field of the struct, if we overflow that, it runs out into that space that we already allocated! For this trick, this only works if the short array is the last field in the struct.

// Copy more than 8 bytes!

```
strcpy(s->data, "Hello, world!"); // Won't crash. Probably.
```

In fact, this was a common compiler workaround for doing this, where you'd allocate a zero length array at the end:

```
struct len_string {
  int length;
  char data[];
};
```

And then every extra byte you allocate was ready for use in that string.

Because data is the last field of the struct, if we overflow that, it runs out into that space that we already allocated!

// Copy more than 8 bytes!

```
strcpy(s->data, "Hello, world!"); // Won't crash. Probably.
```

But, of course, actually accessing the data beyond the end of that array is undefined behavior! In modern times, we no longer need to resort to such savagery.

Likely for us, we can still get the same effect with C99 and now it's legal.

Let's just change our definition to have no size for the array¹:

```
struct len_string {
  int length;
  char data[];
};
```

Again, this only works if the flexible array member is the last field in the struct.

And then we can allocate the space we want for strings by malloc() larger than the struct len_string, as we do in this example that makes a new struct len_string_from_c_string from a C string:

```

{
```
