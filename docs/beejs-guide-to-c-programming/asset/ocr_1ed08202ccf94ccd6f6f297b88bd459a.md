```
ASSERT(x < 20, "x must be under 20");
}
```

This has the output:

```
foo.c:23: assertion x < 20 failed: x must be under 20
```

# # 19.8 The #error Directive

This directive causes the compiler to error out as soon as it sees it.
Commonly, this is used inside a condition to prevent compilation unless some prerequisites are met:

```
#ifndef __SDC_IEC_550_
  #error I really need IEEE-754 floating point to compile. Sorry!
#endif
```

Some compilers the only time you're going to use a non-standard complementary #warning directive that will output a warning but not stop compilation, is the only time it is not in the C11 spec.

# # 19.9 The #pragma Directive

This is one funny directive, for "pragmatic". You can use it to do... well, anything your compiler supports doing with it.
Basically the only time you're going to add this to your code is if documentation tells you to do.

# # 19.9.1 Non-Standard Pragmas

Here's one non-standard example of using #pragma to cause the compiler to execute a loop in parallel with multiple threads (if the compiler supports the OpenMP extension):

```
#pragma omp parallel for
for (int i = 0; i < 10; i++) { }
```

There are all kinds of #pragma directives documented across all four corners of the globe.
All unrecognized #pragmas are ignored by the compiler.

# # 19.9.2 Standard Pragmas

There are also a few standard ones, that start with STDC, and follow the same form:
#pragma pragma_name on-off
The on-off position can be either ON, OFF, or DEFAULT.
And the pragma_name can be one of these:

| Pragma Name | Description |
| FP_CONTRACT | Allow floating point expressions to be contracted into a single operation to avoid rounding errors that might occur from multiple operations. |
