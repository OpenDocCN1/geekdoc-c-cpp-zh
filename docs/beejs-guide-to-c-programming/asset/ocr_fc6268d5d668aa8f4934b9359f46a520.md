I used temporary variables to set the next values of the parameters before jumping to the start of the function. See why they correspond to the recursive arguments that were in the recursive call?
Now, why use temporary variables? I could have done this:

```
a = n;
n = 1;
```

goto tco;
and actually works fine. But if I carelessly reverse those two lines of code:

```
n = 1; // BAD NEWS
a = * n;
```

--now we're in trouble. We modified n before using it to modify a. That's Bad because that's how it works when we call recursively. Using the temporary variables avoids this problem even if you're not looking out for it. And the compiler optimizes them out, anyway.

# 31.7 Restarting Interrupted System Calls

This is outside the spec, but commonly in Unix-like systems.

Certain long-lived systems call return an error if they're interrupted by a signal, and errno will be set to EINTR to indicate the syscall was fine; it just interrupted.

In those cases, it's really common for the program to restart the call and try it again.

```
retry:
byte_count = read(0, buf, sizeof(buf) - 1); // Unix read() syscall
```

```
if (byte_count == -1) { // An error occurred...
if (errno == EINTR) {
// But it was just interrupted
printf("Restarting...\n");
goto retry;
}
```
