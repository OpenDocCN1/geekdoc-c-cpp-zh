## 23.6 Pointer Differences

As you know from the section on pointer arithmetic, you can subtract one pointer from another¹¹ to get the difference between them in count of array elements.

Now that the type of difference is something that's up to the implementation, so it could vary from system to system.

To be more portable, you can store the result in a variable of type ptrdiff_t defined in <stddef.h>.

```c
int cats[100];

int *f = cats + 20;
int *g = cats + 60;

ptrdiff_t d = g - f; // difference is 40

And you can print by prefixing the format specifier with t:
printf("%d\n", d); // Print decimal: 40
printf("%x\n", d); // Print hex: 28
```

## 23.7 Pointers to Functions

Functions are just collections of machine instructions in memory, so there's no reason we can't get a pointer to the first instruction of the function.

And then call it.

This can be useful for passing a pointer to a function into another function as an argument. Then the second one could call whatever passed in.

The tricky part with these, is that C needs to know the type of the variable that is the pointer to the function.

And it would really like to know all the details.

Like "this be a pointer to a function that takes two arguments and returns void."

How do you write that so you can declare a variable?

Well, it turns out it looks very much like a function prototype, except with some extra parentheses.

```c
// Declare p to be a pointer to a function.
// This function returns a float, and takes two ints as arguments.
float (*p)(int, int);
```

Also notice that you don't have to give the parameters names. But you can if you want; they're ignored.

```c
// Declare p to be a pointer to a function.
// This function returns a float, and takes two ints as arguments.
float (*p)(int a, int b);
```

> ¹Assuming they point to the same array object.

Now that we know how to declare a variable, how do we know what to assign to it? How do we get the address of a function?

Turns there's a shortcut just like getting a pointer to an array: you can just refer to the bare function without parents. (You can put an & in front of this, but it's unnecessary and not idiomatic.)

Once you have a pointer to a function, you can just call it by adding parents and an argument list.

Let's do a simple example where I effectively make an alias for a function by setting a pointer to it. Then we'll call it.

This code prints 3490:

```c
#include <stdio.h>

void print_int(int n) {
    printf("%d\n", n);
}

int main() {
    // Assign p to print_int:
    void (*p)(int) = print_int;
    p(3490); // Call print_int via the pointer
}
```

Notice how the type of p returns the return value and parameter types of print_int. It has to, or else C will complain about incompatible pointer types.

One more example shows how we might pass a pointer to a function as an argument to another function. We'll write a function that takes a couple integer arguments, plus a pointer to a function that operates on those two arguments. Then it prints the result.

```c
#include <stdio.h>

int add(int a
print_math(add, 5, 7);   // 12
print_mult(mult, 5, 7);   // 35
}
```

Take a moment to digest. The idea here is that we're going to pass a pointer to a function print_math(), and it's going to call that function some math.

This we can change the behavior of print_math() by passing another function into it. You can see do that on lines 22-23 when we pass pointers to functions add and mult, respectively.

Now, on line 13, I think we can all agree the function signature of print_math() is a sight to behold. And, if you can believe it, this one is actually pretty straight-forward to some things you can construct¹¹.

But let's digest it. Turns out there are only three parameters, but they're a little hard to see:

```c
//                op        x    y
//      [---op---] |--| |--]
void print_math(*op)(int, int), int x, int y)
```

The first, op, is a pointer to a function that takes two as arguments and returns an int. This matches signatures for both add() and mult().

The second, and x and y, are just standard int parameters.

Slowly and deliberately let your eyes over the signature while you identify the working parts. One thing that always stands out for me is the sequence (*op)(, the parents and the asterisk. That's the giveaway it's a pointer to a function.

## Bitwise Operations

These numeric operations effectively allow you to manipulate individual bits in variables, fitting since C is such a low-level langauge¹.

If you're not familiar with bitwise operations, Wikipedia has a good bitwise article².

## 24.1 Bitwise AND, OR, XOR, and NOT

For each of these, the usual arithmetic conversions take place on the operands (which in this case must be integer type), and then the appropriate bitwise operation is performed.

| Operation | Operator | Example |
|---|---|---|
| AND | & | a = b & c |
| OR | | | a = b | c |
| XOR | ^ | a = b ^ c |
| NOT | | | a = ~c |

Note how they're similar to Boolean operators && |.

These have assignment variants to += -=;

| Operation | Example | Longhand equivalent |
|---|---|---|
| &= | c | a = a & c |
| |= | c | a = a | c |
| ^= | c | a = a ^ c |

## 24.2 Bitwise Shift

For this, the integers are promoted on each operand (which must be integer type) and then a bitwise shift is executed. The type of the result is the type of the promoted operand.

New bits are filled with zeros, with a possible exception noted in implementation-defined behavior, below.

| Operation | Operator | Example |
|---|---|---|
| Shift left | << | a = b << c |
| Shift right | >> | a = b >> c |

There's also the same shorthand for shifting:

| Operation | Example | Longhand equivalent |
|---|---|---|
| >>= | c | a = a >> c |
| <<= | c | a = a << c |

Watch for undefined behavior: no negative shifts, and no shifts that are larger than the size of the promoted operand.

Also watch for implementation-defined behavior: if you right-shift a negative number, the results are implementation-defined. (It's perfectly fine to right-shift a signed int, just make sure it's positive.)
