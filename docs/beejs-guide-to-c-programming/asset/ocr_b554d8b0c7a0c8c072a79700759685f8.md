# 17.2 Dealing with Repeated Includes

It's not uncommon that a header file will #include other headers needed for the functionality of its corresponding C files. I mean, why not?
And it could be that you have a header #included multiple times from different places. Maybe there's no problem, but it would cause compiler errors. And we can't control how many places #include it!
Even worse when we get into a crazy situation header a.h includes header b.h, and b.h includes a.h. It's an #include infinite cycle!
Trying to build such a thing gives an error:

```
error: #include nested depth 200 exceeds maximum of 200
```

What we need to do is that if a file gets included once, subsequent #includes for file are ignored.
The stuff that we're about to do is so common that we should automatically do it every time we make a header file!

And the common way to do this is with a preprocessor variable that we set the first time we #include the file. And for subsequent #includes, we first check to make sure that the variable isn't defined.
For variable name, it's super common to use the name of the header file, like bar.h, make it uppercase, and replace the period with an underscore: BAR_H.

Put a check at the very, top of the file where you see if it's already included, and effectively comment the whole thing out of it.

(Don't put a leading underscore (a leading underscore followed by a capital letter is reserved) or a double leading underscore (because that's also reserved).

```
#ifndef BAR_H // IF BAR_H isn't defined...
#define BAR_H // Define it (with no particular value)
```

// File bar.h
int add(int, int);
