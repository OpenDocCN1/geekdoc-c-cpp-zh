由于这两个原因，将结构体的指针传递给函数比直接要常见得多，尽管直接传递结构体本身绝非非法的。

让我们尝试传递一个指针，创建一个允许你设置 `car` 结构体 `.price` 字段的函数：

```c
#include <stdio.h>

struct car {
    char *name;
    float price;
    int speed;
};

int main(void) {
    struct car saturn = {.speed=175, .name="Saturn SL/2"};

    // 传递这辆汽车的指针，以及一个新的、
    // 更真实的价格：
    set_price(&saturn, 79.99);

    printf("Price: %f\n", saturn.price);
}
```

你应该能够通过观察这里参数的类型，推断出 `set_price()` 的函数签名。

`saturn` 是一个 `car`，所以 `saturn` 必须是 `struct car` 的地址，又称一个指向 `struct car` 的指针，即一个 `struct 'car'`。

而 `79.99` 是一个 `float`。

所以函数声明可能像这样：

```c
void set_price(struct car *c, float new_price)
    c.price = new_price; // 错误！！
```

我们需要编写函数体。一种尝试可能是：

```c
void set_price(struct car *c, float new_price)
    (*c).price = new_price; // 可以用，但很丑陋且不符合习惯：
```

那将不起作用，因为点运算符 `.` 是作用于结构体的……它并不能通过解引用指针来获取结构体本身。对 `struct car *` 的结果进行解引用，以便我们可以对指针指向的 `car` 的结果进行解引用，然后我们就可以对它使用点运算符了：

这样就可以了！输入所有这些括号和星号有点笨拙。C 有一种叫做“箭头运算符”的语法糖可以帮助解决这个问题。

> ^ 在 64 位系统上，指针占 8 字节。

## 8.4 箭头运算符 (Arrow Operator)

箭头运算符有助于引用指向结构体指针中的字段。

```c
void set_price(struct car *c, float new_price) {
  // (*c).price = new_price; // 可以用，但不符合习惯：
  // /
  // 上面的一行与下面这一行完全等价：

  c->price = new_price; // 就是这个！
}
```

那么在访问字段时，我们什么时候用点 `.`，什么时候用箭头 `->` 呢？

- 如果你有一个结构体，使用点 `.`。
- 如果你有一个指向结构体的指针，使用箭头 `->`。

## 8.5 拷贝和返回结构体

这里有一个简单的题留你练习！
直接从一个赋值给另一个即可！

```c
struct car a, b;
b = a;   // 拷贝结构体
```

返回结构体（与返回指针相反）也会对接收变量进行类似的拷贝。
这并不是一个“深拷贝”⁴。字段是按原拷贝的，包括指向某些内容的指针。

## 8.6 比较结构体

只有一种思考方式：一次比较一个字段。
你可能认为可以使用 `memcmp`⁵，但它无法处理其中可能存在的填充字节（padding bytes）。
如果你先用 `memset()` ⁶ 将结构体清零，那么它可能有效，尽管可能会有一些奇怪的元素，其比较结果可能不像你预期的那样⁷。

# 文件输入/输出 (File Input/Output)

我们已经见过过几个使用 `scanf()` 和 `printf()` 在控制台（屏幕/键盘）上进行 I/O 的示例。

但在本章中，我们将这些概念进一步推行。

## 9.1 `FILE*` 数据类型

我们在 C 中进行任何类型的 I/O 时，都是通过以 `FILE` 类型形式获得的数据来实现。这个 `FILE` 包含了与 I/O 子系统通信所需的所有信息，关于我们打开了哪个文件、你在文件的哪个位置等。

规范将这些称为“流”（streams），即从文件或任何源产生的数据流。我将交替使用“文件”和“流”，但实际上你应该把“文件”看作“流”的一种特例。除了从文件读取外，还有其他方法向程序流化数据。

我们将看到如何从文件名获取其打开的 `FILE`，但首先我想提到三个已经为你打开并准备好使用的流。

| FILE 名称 | 说明 |
| --- | --- |
| stdin | 标准输入，默认通常为键盘 |
| stdout | 标准输出，默认通常为屏幕 |
| stderr | 标准错误，默认通常为屏幕，作为 |

事实证明，我们最近隐式地使用了这些内容。例如，这两个调用是：

```c
printf("Hello, world\n");
printf(stdout,"Hello, world\n");
```

但稍后会详细介绍。你还会注意到 `stdout` 和 `stderr` 都输出到屏幕。虽然初看起来像像疏忽，但实际上并非如此。典型的操作系统允许你将任何一个的输出重定向到不同的文件，将错误消息与非错误输出分开会非常方便。在类 Unix 系统的 POSIX shell（如 sh, bash 等）中，我们可以运行程序并将仅有的非错误（stdout）输出发送到一个文件，将所有错误（stderr）输出发送到另一个文件。

```
foo > output.txt 2> errors.txt # 此命令是 Unix 特有的
```

出于这个原因，你应该将重要的消息发送到 `stderr` 而不是 `stdout`。

## 9.3 文件结束符：EOF

EOF 是一个定义为宏的特殊字符。当文件结束时，`fgetc()` 返回它。由于 `fgetc()` 需要返回一个超出 `char` 范围的值，所以它返回 `int` 而不是 `char`。` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` ` 好了! 回到现实！我们可以使用这个来读取整个文件。

```c
#include <stdio.h>

int main(void)
{
    FILE *fp;
    int c;

    fp = fopen("hello.txt", "r");

    while ((c = fgetc(fp)) != EOF)
        printf("%c\n", c);

    fclose(fp);
}
```

如果第 10 行看起来太奇怪，请注意 EOF 是导致这种嵌套括号的原因。我们第一件事是将 `fgetc()` 的结果赋值给 `c`，然后将其与 `EOF` 进行比较。我们刚刚把它们压缩到了一行。这可能看起来很难读，但学习一下——它是符合 C 语言习惯的。

运行它时，你会看到：

Hello, world!

但尽管如此，我们仍然是一个字符字符地操作，大量的文本在行级别上更有意义。让我们切换到那种方式。
