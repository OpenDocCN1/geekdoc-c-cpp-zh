# 2.1 What to Expect from C

"Where do these stairs go?"
"They go up."
—Ray Stanz and Peter Venman, Ghostbusters

C is a low-level language.

It didn't use to be. Back in the day when people carved punch cards out of granite, C was an incredible way to be free of the drudgery of lower-level languages like assembly¹.

But now in modern times, current-generation languages offer all kinds of features that didn't exist in 1972 when C was invented. This means C is a pretty basic language with not a lot of features. It can do anything, but it can make you work for it.

So why would we use it?

- As a learning tool: not only is C a versatile piece of computing history, but it is connected to the bare metal² in what that present-day languages are not. When you learn C, you learn about how software interfaces with computer memory at a low level. There are no seatsbelts. You will write software that crashes, I assure you. And that's all part of the fun!
- As a useful tool: C is used for certain applications, such as operating systems³ or in embedded systems⁴. (Though the Rust⁵ programming language is eyeing these fields!)

If you're familiar with another language that hangs up people pointers. Virtually everything is easy, but pointers are the weird one. The concept behind pointers is likely one you already know, but C forces you to be explicit about it, using operators you've never seen before.

It's especially insidious because you know go⁶ pointers, they're suddenly easy. But until that moment, they're slippery eels.

# 2.2 Hello, World!

This is the canonical example of a C program. Everyone uses it. (Note that the numbers to the left are for reader only).

- Hello world <stdio.h>

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n"); // Actually do the work
}
```

We're going down heavy gloves, grab a scalpel, and rip into this thing to see what makes it tick. So, scoop up, because here we go.

- Anything between /* */ is a comment and will be ignored by the compiler. This allows you to leave messages to yourself and others, so that you come back and read your code in the distant future, you'll know what it was trying to do. Believe me, you will forget;

Now, what's a Preprocessor? Good question. There are two stages to compilation: the preprocessor and the compiler. Anything that starts with pound, or 'octothorpe', is something the preprocessor handles before the compiler gets started. Common preprocessor directives, as they're called, #include and #define. On more than that

Before we go on, why would I ever begin to point out that a pound sign is called an octothorpe The answer is simple: I think the word octothorpe is so excellently funny, I have to happily spread it around wherever I get the opportunity. Octothorpe. Octothorpe, octothorpe.

After the C preprocessor has finished preprocessing, the results are ready for the compiler to take and produce assembly code¹, machine code, or whatever it's about to do. Machine code is the "language" the CPU understands, and can understand it very rapidly. This is one of the reasons C programs need to be.

Don't worry about the technical details of compilation for now; know that your source runs through the preprocessor, the output of which the compiler, then produces an executable for you run.
