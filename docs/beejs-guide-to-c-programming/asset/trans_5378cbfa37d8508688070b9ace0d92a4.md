## 2.3 编译细节

让我们来聊聊如何构建 C 程序，以及其背后发生了什么。

和其他语言一样，C 也有源代码。但取决于你从哪种语言转过来的，你可能从未需要将源代码编译成可执行文件。

编译是将你的源代码转换为操作系统可以执行的程序的过程。

JavaScript 和 Python 并不习惯于编译——尽管在背后有编译！Python 将你的源代码编译成 Python 虚拟机执行的字节码。Java 开发者习惯于编译，但那是产生 Java字节码。

在编译 C 时，会生成机器码。这是 CPU 可以直接且快速执行的 1 和 0。

通常不编译语言是解释性的。但对于 C，它是被编译成机器码的。这就是 C 如此快速的原因。

## 2.4 使用 GCC 编译

当你想要编译 C 时，可能会使用 GCC（GNU 编译器集合）。它是 Unix 类系统中非常常用的编译器。

要编译文件，你可以使用以下命令：

```
gcc hello.c -o hello
```

`-o` 标志告诉 GCC 输出文件的名称。如果你不使用它，输出将被命名为 `a.out`。

## 2.5 使用 Clang 编译

如果你在使用 Mac，可能会使用 Clang 而不是 GCC。语法非常相似：

```bash
clang hello.c -o hello
```

## 2.6 在 IDE 中编译

许多人使用集成开发环境（IDE），如 VS Code、CLion 或 Xcode。这些工具为你处理了编译，但了解底层发生了什么是很重要的。

## 2.7 C 版本

多年来 C 取得了巨大进步，它有很多版本号。这些版本通常指的是规范发布的年份。

| 版本 | 描述 |
| --- | --- |
| K&R C | 1978年的最初。以 Brian Kernighan 和 Dennis Ritchie 命名。 |
| C89, ANSI C, C90 | 1989 年，美国国家标准协会（ANSI）制定了一份 C 语言规范，设定了延续至今的 C 基调。 |
| C99 | 对 C89 的重大补充，包含了对字符的支持。 |
| C11 | 这个主要版本包含了 Unicode 支持和多线程。 |
| C17, C18 | 对 C17 的无 Bug 更新，官方名称似乎是 C17，但发布延迟到了 2018 年。 |
| C2x | 下一个版本！预计最终将成为 C23。 |
