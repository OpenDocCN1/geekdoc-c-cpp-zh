# Chapter 16. Types IV: Qualifiers and Specifiers

# 16.2.4 register

This is a keyword to hint the compiler that this variable is frequently-used, and should be made as fast as possible to access. The compiler is under no obligation to agree to it.

Now, modern C compiler optimizers are pretty effective at figuring out this themselves, so it's rare to see these days.

But if you must:

```
#include <stdio.h>

int main(void)
{
    register int a; // Make "a" as fast to use as possible.

    for (a = 0; a < 10; a++)
        printf("%d\n", a);

}
```

It comes at a price, however. You can't take the address of a register

```
register int a;
*p = &a; // COMPILER ERROR! Can't take address of a register
```

The same applies to any part of an array:

```
register int a[] = {11, 22, 33, 44, 55};
*p = &a[0]; // COMPILER ERROR! Can't take address of a[0]
```

Dereferencing any part of an array:

```
register int a[] = {11, 22, 33, 44, 55};
```

```
int a = (a + 2); // COMPILER ERROR! Address of a[0]
```

Interestingly, for the equivalent with array notation, gcc only gives:

```
register int a[] = {11, 22, 33, 44, 55};
```

```
int a = a[2]; // COMPILER WARNING!
```

with:

warning: ISO C forbids subscribing 'register' array

The fact that you can't take the address of a register variable frees the compiler to make optimizations around assumption that it hasn't figured it out already. Also adding register to a const variable prevents from accidentally passing its pointer to another function that would ignore its 'const'¹².

A bit of historic back: inside the CPU are little dedicated "variables" called 'registers'. They are super fast to access RAM, so using them you get a speed boost. They're not in RAM, so they don't have an associated address (which is why you can't take the address of or get a pointer to them).

But, like I said, modern compilers are really good at producing optimal code, using registers regardless of whether or not you specified the register keyword. Not only that, but the spec allows them to just treat it as if you'd typed out, there are no guarantees.
