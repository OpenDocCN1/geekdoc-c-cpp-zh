# Variable-Length Arrays (VLAs)

C provides a way for you to declare an array whose size is determined at runtime. This gives you the benefits of dynamic runtime sizing like you get with malloc(), but without needing to worry about free()ing the memory after.

Now, a lot of people don't like VLAs. They've been banned from the Linux kernel, for example. We'll dig into more of that rationale later.

This is an optional feature of the language. The macro __STC_NO_VLA__ is set to 1 if VLAs are not present (They were mandatory in C99, and then become optional in C11).

```c
#if __STC_NO_VLA__ == 1
  #error Sorry, need VLAs for this program!
#endif
```

But since neither GCC nor Clang bother to define this macro, you may get limited mileage from this. Let's dive first with an example, and then we'll look for the devil in the details.

## 30.1 The Basics

A normal array is declared with a constant size, like this:

```c
int v[10];
```

With VLAs, we can use a size determined at runtime to set the array, like this:

```c
int n = 10;
int v[n];
```

Now, that looks like the same thing, and in many ways is, but this gives you the flexibility to compute the size you need, and then get an array of exactly that size.

Let's ask the user to input the size of the array, and then store the index-times-10 in each of those array elements:

```c
#include <stdio.h>

int main(void)
{
  int n;

  printf("Enter a number: "); fflush(stdout);
  scanf("%d", &n);

  int v[n];

  for (int i = 0; i < n; i++)
    v[i] = i * 10;

  for (int i = 0; i < n; i++)
    printf("%d] = %d\n", i, v[i]);
}
```

(On line 7, I have fflush()) that forces the line to output even though I don't have a newline at the end.)

Line 10 is where the VLA—once execution gets past that line, the size of the array is set to whatever n was at runtime. The array can't be changed.

You can put an expression in the brackets, as well:
`int v[x * 100];`

- You can't declare a VLA at file scope, and you can't make a static one in block scope.
- You can't use an initializer list to initialize the array.

Also, entering a negative value for the size of the array invokes undefined behavior—in this, anyway.

## 30.2 sizeof and VLAs

We're used to sizeof using the size in bytes of any particular object, including arrays. VLAs have no exception. The main difference is that sizeof on a VLA is computed at runtime, whereas on a non-variably-sized variable it is computed at compile time.* But the usage is the same.

You can even compute the number of elements in a VLA with the usual trick: `size_t num_elems = sizeof(v) / sizeof(v[0]);`

There's a subtle and correct implication from the line above: pointer arithmetic works just like you'd expect for a regular array. So ahead and use it to your heart:

```c
#include <stdio.h>

int main(void)
{
    int n = 5;
    int v[n];

    int *p = v;

    *(p+2) = 12;
    printf("%d\n", v[2]); // 12
}
```

*This is due to how VLAs are typically allocated on the stack, and the whole idea with VLAs is they'll be automatically deallocated when the end of the function.

Like regular arrays, you can use parentheses with sizeof() to get the size of a variable-VLA actually declaring one:

```c
int x = 12;
printf("%zu\n", sizeof(x)); // Prints 48 on my system
```

## 30.3 Multidimensional VLAs

You can go ahead and make all kinds of VLAs with one or more dimensions set to a variable:

```c
int w = 10;
int h = 20;
int x[h][w];
int y[5][w];
int z[10][w];
```

Again, you can navigate these just like a regular array.

## 30.4 Passing One-Dimensional VLAs to Functions

Passing single-dimensional VLAs into a function is no different than passing a regular array for it.

```c
#include <stdio.h>

int sum(int count, int v[])
{
  int total = 0;

  for (int i = 0; i < count; i++)
    total += v[i];

  return total;
}

int main(void)
{
  int a = 5;
  int x[5]; // Standard array
  int y[a];  // VLA

  for (int i = 0; i < a; i++)
    x[i] = i + 1;

  printf("%d\n", sum(5, x));
  printf("%d\n", sum(a, y));
}
```

There's a bit more to it than you can also let C know that the array is a specific VLA size by passing that first and giving dimension in the parameter list:

VLA prototypes:
```c
void do_something(int count, int v[count]); // With names
void do_something(int count, int v[]); // Without names
```

Again, only works with the prototype—in the function itself, you'll have to put the explicit size. Now let's get multidimensional! This is where fun begins.

## 30.5 Passing Multi-Dimensional VLAs to Functions

Same as you did with the form of one-dimensional VLAs above, but this time we're passing in two dimensions and using those. In the following example, we build a multiplication table of a variable width and height, and pass it to a function to print out.

```c
#include <stdio.h>

void print_matrix(int h, int w, int m[h][w]) {
    for (int row = 0; row < h; row++) {
        for (int col = 0; col < w; col++) {
            printf("%d ", m[row][col]);
        }
        printf("\n");
    }
}

int main(void)
{
    int rows = 4;
    int cols = 7;

    int matrix[rows][cols];

    for (int row = 0; row < rows; row++) {
        for (int col = 0; col < cols; col++) {
            matrix[row][col] = row * col;
        }
    }

    print_matrix(rows, cols, matrix);
}
```

## 30.6 Compatibility with Regular Arrays

Because VLAs are just like regular arrays in memory, it's perfectly permissible to pass them interchangeably, as long as the dimensions match. For example, if we have a function that specifically wants a 3 × 5 array, we can still pass a VLA into it.

```c
int foo(int m[5][3]) {
    ...
}

int w = 3, h = 5;
int matrix[h][w];

foo(matrix); // OK!

int foo(int h, int w, int m[h][w]) {
    ...
}

int matrix[3][5];

foo(3, 5, matrix); // OK!
```

Likewise, if you have a VLA function, you can pass a regular array into it: Beware, though: if your dimensions mismatch, you're going to have some undefined behavior going on, likely.

## 30.7 typedef VLAs

You can typedef a VLA, but the behavior might not be as you expect. Basically, typedef makes a new type with the values as they existed the moment the typedef was executed. So it's not a typedef of a VLA so much as a new fixed size array of the dimensions at the time.

```c
#include <stdio.h>

int main(void)
{
    int w = 10;

    typedef int[w];

    // goat is an array of 10 ints
    goat x;

    // Init with squares of numbers
    for (int i = 0; i < w; i++)
        x[i] = i*i;

    // Print them
    for (int i = 0; i < w; i++)
        printf("%d\n", x[i]);

    // Now let's change w...
    w = 20;

    // But goat is STILL an array of 10 ints, because that was the
    // value of w when the typedef was executed.
}
```

So it acts like an array of fixed size. But still can't use an initializer list on it.

## 30.8 Jumping Pitfalls

You have to watch out when using goto near VLAs because a lot of things aren't legal. And when you're using longjmp() there's a case where you could leak memory with VLAs. But both of these we'll cover in their respective chapters.

## 30.9 General Issues

VLAs have been banned from the Linux kernel for a few reasons:

- Lots of places they were used should just be fixed-size.
- The code behind VLAs is slower (a degree that most people would notice, but makes a difference in an operating system).
- VLAs are not supported to the same degree by all C compilers.
- Stack size is limited, and VLAs go on the stack. If some code accidentally (or maliciously) passes a large value into a kernel function that allocates a VLA, _Bad Things™ could happen.
