Let's leave some of the initializer elements and see they get set to zero:

```
int a[3][2] = {
  {1, 2),
  {3}, // Left off the 4!
  {5, 6}
};
```

which produces:

+   1 2
3 0
5 6

Now let's leave the entire middle element:

```
int a[3][2] = {
  {1, 2),
  // {3, 4}, // Just cut this whole thing out
  {5, 6}
};
```

And now we get this, which might not be what you expect:

+   1 2
5 6
0 0

But if you stop thinking about it, we provided enough initializers for two rows, so they got used for the first two rows. The remaining elements were initialized to zero.

So far so good. Generally, if we leave off parts of the initializer, the compiler sets the corresponding elements to 0.

But let's get crazy.

```
int a[3][2] = { 1, 2, 3, 4, 5, 6 };
```

—That's a 2D array, but it only has a 1D initializer!

Turns out that's legal (though GCC will warn you about it with the proper warnings turned on).

Basically, what it does is starts filling in elements in row 0, then row 1, row 2 from left to right.

So when we print, it prints in order:

+   1 2
3 4
5 6
