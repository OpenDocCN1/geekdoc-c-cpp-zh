这里的问题在于：你无法访问原子结构体或联合体的字段……那么它的意义何在？嗯，你可以将整个结构体原子性地拷贝到一个非原子变量中，然后使用它。你也可以反向地进行原子拷贝。

#include <stdatomic.h>

int main(void)
{

你可以声明一个结构体，其中单个字段是原子的。字段上是否允许原子类型取决于实现定义。

## 40.12 原子指针

这里说明一下指针中原子类型（Atomic）的放置。

首先，指向原子的指针（即指针值本身不是原子的，但它指向的内容是子的）：

```cpp
_Atomic int x;
_Atomic int *p; // p 是指向原子 int 的指针
```

其次，指向非原子值的原子指针（即指针值本身是原子的，但它指向的内容不是）：

```cpp
int x;
int *_Atomic p; // p 是指向 int 的原子指针
```

```cpp
p = &x; // 正确！
```

最后，指向原子值的原子指针（即指针和它指向的内容都是原子的）：

```cpp
_Atomic int x;
_Atomic *_Atomic p; // p 是指向原子 int 的原子指针
```

## 40.13 内存顺序

p = &x; // 正确！

我们之前已经讨论过顺序一致性（sequential consistency），这是这些模式中最合理的一种。但还有其他几种：

| memory_order | 描述 |
| --- | --- |
| memory_order_seq_cst | 顺序一致性 |
| memory_order_acq_rel | 获取/释放 (Acquire/Release) |
| memory_order_release | 释放 (Release) |
| memory_order_acquire | 获取 (Acquire) |
| memory_order_consume | 消费 (Consume) |
| memory_order_relaxed | 松弛 (Relaxed) |

你可以通过某些库函数指定其他顺序。例如，你可以这样给原子变量增加一个值：

```cpp
atomic_int x = 0;
x += 5; // 顺序一致性，默认
```

或者你可以使用这个库函数实现相同：

```cpp
atomic_int x = 0;
atomic_fetch_add(&x, 5); // 顺序一致性，默认
```

或者你可以使用显式的内存顺序执行相同的操作：

```cpp
atomic_int x = 0;
atomic_fetch_add_explicit(&x, 5, memory_order_seq_cst);
```

但如果我们不想要顺序一致性呢？由于某种原因，你想要获取/释放语义？只需命名即可：

```cpp
atomic_int x = 0;
```

```cpp
atomic_fetch_add_explicit(&x, 5, memory_order_acq_rel);
```

我们将在下方对不同的内存顺序进行详细说明。除非你确定自己在做什么，否则不要动顺序一致性以外的任何东西。很容易出错并导致非常困难且难以复现的失败。

### 40.1.3 顺序一致性

- 加载（Load）操作执行获取（见下文）。
- 存储（Store）操作执行释放（见下文）。
- 读-修改-写操作先执行获取后释放。

此外，为了维护获取和释放的总顺序，任何获取或释放操作都不会彼此之间重排序。（获取/释放规则并不禁止重排一个释放随后的获取。但顺序一致性规则禁止。）

### 40.13.2 获取 (Acquire)

这是在原子变量上执行加载/读取操作时发生的情况。

- 如果另一个线程释放了这个原子变量，该线程执行的所有写入现在对此线程可见。
- 此线程中发生在该加载操作之后的内存访问不能被重排到它之前。

### 40.13.3 释放 (Release)

这是对原子变量执行存储/写入操作时发生的情况。

- 如果另一个线程获取了这个原子变量，此线程中在原子写入之前的所有内存写入对该另一个线程可见。
- 此线程中发生在该释放操作之前的内存访问不能被重排到它之后。

### 40.13.4 消费 (Consume)

这是一个旧概念，类似于不那么严格的获取版本。它影响依赖于原子变量的数据内存访问。

“数据依赖”模糊地意味着该原子变量被用在计算中。

也就是说，如果一个线程消费了一个原子变量，那么该线程中后续使用该原子变量的所有操作都能够看到释放线程中的内存写入。

与获取（acquire）相比，释放线程中的内存写入将对当前线程中的所有操作可见，而不仅仅是数据依赖的操作。
此外，获取对于哪些可以重排在消费（consume）之前的操作有限制。在获取中，你不能在它之前重排任何内容。在消费中，你不能重排任何依赖于所加载的原子值的内容。

### 40.13.5 获取/释放 (Acquire/Release)

这只适用于读-修改-写操作。它将获取和释放封装在一起了。

- 获取发生在读取阶段。
- 释放发生在写入阶段。

### 40.13.6 松弛 (Relaxed)

没有规则；它是无序的！所有操作都可以重排！线程之间没有任何同步。

对于这种内存顺序，你可以在某些情况下找到它，例如简单的计数器。

你可以使用内存障（fence）来强制对松弛写入进行同步。

它的工作方式与 `atomic_thread_fence()` 相同，但：

- 它只处理同一线程内的可见性；不会产生硬件指令。
