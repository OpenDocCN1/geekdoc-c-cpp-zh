# Chapter 39. Multithreading

When I run the threads, i count up from 0 to 4. And pass a pointer it to thrd_create(). This pointer ends up in the run() routine where we make a copy of it.

Simple enough? Here's the output:

```
Launching threads...
THREAD 2: running!
THREAD 3: running!
THREAD 4: running!
THREAD 2: running!
Doing things while the thread runs...
Waiting for thread to complete...
Thread 2 complete!
Thread 2 complete!
THREAD 5: running!
Thread 3 complete!
Thread 4 complete!
Thread 5 complete!
All threads complete!
```

Whaaa Where is THREAD 0? And why do we have a THREAD 5 when i is never more than 4 when we call thrd_create()? And two THREAD 2s? Madness!

This is getting into the fun of race conditions. The main thread is modifying before the thread has a chance to copy it. Indeed, i makes it all the way to 5 and ends the loop the last thread gets a chance to copy it.

We've got to have a big array of them. Or we could malloc() space (and free it somewhere—maybe in the thread itself).

Let's give that a shot:

```
#include <stdio.h>
#include <stdlib.h>
#include <threads.h>

int run(void *arg)
{
    int i = *(int*)arg; // Copy the arg

    free(arg); // Done with this

    printf("THREAD %d: running!\n", i);

    return i;
}
```
