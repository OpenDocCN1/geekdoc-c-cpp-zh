

## 第 27 章 Unicode、宽字符及其他内容

### 27.11.2 UTF-16, UTF-32, char16_t 和 char32_t

`char16_t` 和 `char32_t` 是两种潜在的宽字符类型，大小分别为 16 位和 32 位。它们并不一定是宽字符，因为如果它们无法表示当前区域环境中的每一个字符，就会失去宽字符的本质。规范在各处称它们为“宽字符”类型，事实就是如此。

引入这些类型是为了让事情稍微兼容 Unicode 一。

包含头文件：`<cuchar.h>`。（注意是 "u"，不是 "uw"）。

这个头文件在 OS X 上——目前还还没有。如果你只需要这些类型，可以：

```c
#include <stddef.h>

typedef int_least16_char16_t;
typedef int_least32_char32_t;
```

但如果你还想要相应的函数，那么它们得由你自己来实现。

假设你已经准备就绪，可以使用 `u` 和 `u` 前缀来声明这些类型的字符串或字符：

```c
char16_t *s = u"Hello, world!";
char16_t *c = u"B";
char32_t *t = u"Hello, world!";
char32_t d = u"B";
```

现在——这些这些值是存储在 UTF-16 还是 UTF-32 中？取决于实现。
但你可以测试一下它们是否是那样。如果宏 `__STDC_UTF_16__` 或 `__STDC_UTF_32__` 被定义为 (1)，则意味着这些类型分别持有 UTF-16 或 UTF-32。
如果你好奇，并且（根据我了解的情况）UTF-16 或 UTF-32 是以原生字节序存储的，那么你应该可以直接它们与 Unicode 代码点值进行比较：

```c
char16_t pi = u"\u03BC"; // pi 符号
#if __STDC_UTF_16__
pi == 0x03BC; // 始终为真
#else
pi == 0x030; // 可能为假
#endif
```

### 27.11.3 多字节转换

你可以使用一些辅助函数将多字节编码转换为 `char16_t` 或 `char32_t`。
（正如我所说的，除非转换宏被设置为 1，否则结果可能不是 UTF-16 或 UTF-32）。
所有这些函数都是可重新启动的（即你可以传递自己的 `mbstate_t`），并且所有它们都是逐字符操作的。

| 转换函数 | 描述 |
|---|---|
| mbrtoc16() | 将多字节字符转换为 char16_t 字符。 |
| mbrtoc32() | 将多字节字符转换为 char32_t 字符。 |

### 28.1 正常退出

我们将从退出程序的常规方式开始，然后转向更罕见的、更奇异的方法。

当你正常退出程序时，所有打开的 I/O 流都会刷新，临时文件会被删除。基本上，这是一个清理并处理好一切的良好退出。这是你大多数时候需要做的，除非有其他原因。

### 28.1.1 从 main() 返回

如果你注意到，正常情况下，从 `main()` 返回有一个 `int` 类型……并且最近发现，如果从 `main()` 结束处返回任何值，都是隐式的。

这是专门针对 `main()` 的（而且这种特殊情况不适用于其他函数）。

你可以任何时候从 `main()` 显式返回，并且有些程序员觉得这样更好。

所以……这里是 `main()` 的规则：
- 你可以使用 `return` 语句退出。

### 28.1.2 exit()

如果你在程序的任何地方调用 `exit()`，它会在该点退出。

你传递给 `exit()` 的参数是退出状态。

### 28.1.3 使用 atexit() 设置退出处理器

当程序退出时（无论是从 `main()` 返回还是调用 `exit()` 函数），你都可以通过调用 `atexit()` 注册函数名来完成。你可以注册多个退出处理器，它们将按照注册的反向顺序被调用。

这是一个示例：

```c
#include <stdio.h>
#include <stdlib.h>

void exit_1(void) {
    printf("handler 1\n");
}

void exit_2(void) {
    printf("handler 2\n");
}

int main() {
    atexit(exit_1);
    atexit(exit_2);
    return 0;
}
```
输出：
```
handler 2
handler 1
```

## 第 29 章

## 信号处理

在开始之前，我建议你通常忽略整个章，并使用操作系统的（很可能的）信号处理函数。Unix 类有 `sigaction()` 系列函数，而 Windows 有……它自己的方法。

排除这些差异之后，什么是信号？

### 29.1 什么是信号？

信号会在各种外部事件上触发。你的程序可以配置为中断以处理信号，并可选地在处理完毕后从离开的地方继续。

把它想象成当这些事件之一发生时会自动调用的函数。

这些事件是什么？在你的系统上可能有很多，但在 C 规范中只有几个：

| 信号 | 描述 |
|---|---|
| SIGABRT | 异常终止——调用 `abort()` 时发生的情况。 |
| SIGFPE | 浮点异常。 |
| SIGILL | 非法指令。 |
| SIGINT | 中断——通常是按下 CTRL-C 的结果。 |
| SIGSEGV | “段错误”：无效内存访问。 |
| SIGTERM | 终止请求。 |

你可以使用 `signal()` 函数设置程序对每个信号的忽略、处理或允许默认操作。

### 29.2 使用 signal() 处理信号

`signal()` 取两个参数：感兴趣的信号，以及当该信号被触发时采取的动作。

该动作可以是三种之一：

- 指向处理函数的指针。
