在多线程场景下，我们可能会遇到类似这样的伪代码：

```
int x = 0, y = 0;
```

```
thread1() {
    x = 2;
    y = 3;
}
```

```
thread2() {
    while (y != 3) {} // 自旋
    printf("x is now %d\n", x); // 2? ...还是 0?
}
```

thread 2 的输出是什么？

嗯，如果 x 在 y 被赋值为 3 之前被赋值为 2，那么预期输出是非常合理的：

x is now 2

当两个线程对共享内存的状态达成一致时，它们就同步了。正如我们所见，它们并不总是与代码保持一致。那么它们是如何达成一致的呢？

使用原子变量可以强制达成一致¹。当一个线程写入原子变量时，它表示：“任何读取此变量的人都将看到我对内存进行的所有更改（无论是否是原子的），包括该原子变量在内的更改。”

或者，用更通俗的话说，让我们坐在会议桌旁，确保我们在共享内存持有的值这一点上达成共识。你同意，你所做的内存更改以及原子存储操作，在我加载同一个原子变量后，对我来说是可见的。

所以我们可以轻松地修复示例：

```
int x = 0;
atomic int y = 0; // 设为原子
```

```
thread1() {
    x = 2;
    y = 3; // 在此处同步
}
```

```
thread2() {
    while (y != 3) {} // 在读取处同步
    printf("x is now %d\n", x); // 就是 2，无疑。
}
```

> ¹ 除非我另有说明，否则我泛指顺序一致性操作。关于其含义的更多信息

## 第 40 章. 原子性

因为线程跨 y 进行了同步，因此 thread 1 中在写入 y 之前发生的所有写入在 thread 2 写入 y 之后（while 循环之后）都是可见的。

注意以下几点：

- 1. 没有任何线程在睡眠。同步不是阻塞操作。两个线程都会全速运行直到退出。即使是自旋循环中的那个线程也不会阻塞其他线程运行。
- 2. 同步发生在一个线程读取原子变量而另一个线程写入该变量时。当 thread 2 读取时，thread 1 中之前的所有内存写入（即设置 x）在 thread 2 中都是可见的。
- 3. 注意 x 不是原子的。那是**因为**我们没有在 x 上进行同步，而在 thread 1 中写入时对 y 的同步，意味着 thread 1 中之前的所有写入——包括 x——将对其他线程可见……如果这些线程通过读取 y 来同步的话。

强制同步效率低的，并且可能比使用普通变量慢得多。这就是为什么除非特定应用程序有需要，否则我们不使用原子变量。

以上就是基础。让我们深入研究。

## 40.4 获取 (Acquire) 与释放 (Release)

更多术语！现在学习它们是有回报的。

当一个线程读取原子变量时，被称为一次获取（acquire）操作。

当一个线程写入原子变量时，被称为一次释放（release）操作。

这些是什么？让我们将它们与你处理原子变量时熟悉的术语对应起来：

**读 = 加载 (Load)** —— 获取。当你比较原子变量或将其读取到另一个变量时。
**写 = 存储 (Store)** —— 释放。当你向原子变量赋值一个值时。

在使用这些获取/释放语义的原子变量时，C 定义了会发生什么。

获取/释放构成了我们讨论的同步的基础。

当一个线程读取原子变量时，它可以看到另一个线程释放该变量时设置的值。

换句话说：

当一个线程读取原子变量时，可以看到另一个线程写入该变量时设置的值。

同步发生在获取/释放对之间。

更多细节：

对于特定原子变量的读取/获取：

- 另一个线程在写入/存储该原子变量之前发生的所有写入（原子或非原子）现在对当前线程都是可见的。
- 另一个线程对原子变量的新值对当前线程也是可见的。
- 当前线程中任何变量的读取或写入都无法重排到获取操作之前。
- 在代码重排方面，获取是一道单向屏障；当前线程的读取和写入可以从获取之前移动到它之后。但对同步更重要的是，没有任何操作可以从获取之后移动到它之前。

对于特定原子变量的写入/存储/释放：

- 当前线程中在释放操作之前发生的所有写入（原子或非原子）对读取/加载或获取了同一原子变量的其他线程都是可见的。
- 当前线程写入该原子变量的值对其他线程可见的。
- 当前线程中任何变量的读取或写入都无法重排到释放操作之后。
- 在代码重排方面，释放是一道单向屏障；当前线程的读取和写入可以从释放之前移动到它之后。但对同步更重要的是，没有任何操作可以从释放之后移动到它之前。
