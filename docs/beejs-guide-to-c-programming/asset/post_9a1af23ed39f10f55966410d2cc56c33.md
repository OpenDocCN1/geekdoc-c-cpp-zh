
## 18.2 Exit Status

Did you notice that the function signatures for main() have it returning type int? What's all about? It has to do with a thing called the exit status, which is an integer that can be returned to the program that launched it to let know how things went.

Now, there are a number of ways program can exit in C, returning from main(), or calling one of the exit() variants.

All of these methods accept an int as an argument.

Side note: you did see that in basically all my examples, even main() is supposed to return an int, I don't actually returning anything? In any other function, this would be illegal, but there's a special case in C: if execution reaches the end of main() without finding a return, it automatically returns 0.

But what does it mean? What other numbers can we put there? And how are they used?

The spec is both clear and vague on, as is common. Clear because it spells out what you can do, but vague in that it doesn't particularly limit it, either.

Nothing for it to forge ahead and figure it out

Let's Get Inception⁴ for a second: turns out when you run your program, you're running it from another program.

Usually this other program is kind of shell⁵ which doesn't match on its own except launch other

- 1. The shell launches program
- 2. The shell typically goes to sleep (for command-line shells)
- 3. Your program runs
- 4. Your program terminates
- 5. The shell wakes up and waits for another command

Now, there's a little piece of communication that takes place between steps 4 and 5: the program can return a status value that shell can interpolate. Typically, this value is used to indicate the success or failure of your program, and, if applicable, what type of failure.

This value is we've been returning from main(). That's the status.

| Status | Description |
| --- | --- |
| EXIT_SUCCESS or 0 | Program terminated successfully. |
| EXIT_FAILURE | Program terminated with error. |

Let's write a program that multiplies two numbers from the command line. We'll require that exactly two values. If you don't, we'll print an error message, and exit with an error status.

```c
#include <stdio.h>
#include <stdlib.h>
```

```c
int main(int argc, char **argv)
{
  if (argc != 3) {
    printf("usage: mult x y\n");
    return EXIT_FAILURE; // Indicate to shell that it didn't work
  }

  printf("%d\n", atoi(argv[1]) * atoi(argv[2]));

  return 0; // same as EXIT_SUCCESS, everything was good.
}
```

Now if we try to run this, we get the expected effect until we specify the right number of command-line arguments:

```bash
$ ./mult x y
usage: mult x y

./mult 3 4 5
usage: mult x y
```

```bash
$ ./mult 3 4
12
```

But that doesn't really show the exit status that we returned, does it? We get the shell to print it out, though. Assuming you're running Bash or another POSIX shell, you can use echo $? to see it.

Let's try:

```bash
$ ./mult x y
usage: mult x y
echo $?
1
```

```bash
$ ./mult 3 4 5
usage: mult x y
echo $?
1
```

```bash
$ ./mult 3 4
12
echo $?
0
```

Interesting! We see that on my system, EXIT_FAILURE is 1. The spec doesn't spell this out, so it could be any number. But it's 1 on your system, too.

### 18.2.1 Other Exit Status Values

The status $0 definitely means success, but all the other integers, even negative ones?
Here we're going into the C spec and into Unix land. In general, while $0 means success, a positive non-zero number means failure. Bash says the exit code should be between 0 and 255, though a number of codes are reserved.

In short, if you want to indicate different error statuses in a Unix environment, you can start with 1 and work your way up.

On Linux, if you try any code range 0-255, it will bitwise AND the code with 0xff, effectively clamping to that range.

> *In Windows cmd.exe, type echo %errorlevel%. In PowerShell, type $LastExitCode.*

You can script the shell to use these status codes to make decisions about what to do next.

## 18.3 Environment Variables

Before I get into this, I want to warn you that C doesn't specify what an environment variable is. So I'm going to describe the environment variable system that works on every platform I'm aware of.

Basically, the environment is the program that's going to run your program, or the bash shell. And it might have some variables defined. In case you don't know, the shell can make its own variables. Each shell is different, but in bash you can just set and it'll show all of them.

Here's an example of the 61 variables defined in bash shell:

```
HOSTFILE=/home/beej/.bash_history
HOSTFILESIZE=500
HISTSIZE=500
HOME=/home/bee
HOSTNAME=FBILAPTOP
HOSTTYPE=XB86_64
IFS=' 	'
```

Notice they are in the form of key/value pairs. For example, one key is HOSTTYPE and its value is x86_64.
From a C perspective, all values are strings, even if they're numbers?

So, anyway! Long story, it's possible to get these values from inside your C program.

Let's write a program that uses the standard getenv() function to look up a value you set in the shell.

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	char *val = getenv("FROTZ"); // Try to get the value

	// Check to make sure it exists
	if (val == NULL) {
		printf("Cannot find FROTZ environment variable\n");
		return EXIT_FAILURE;
	}

	printf("%s\n", val);
}
```

Use getenv() if at all possible because it's more portable. But if you have to iterate over environment variables, using environ might be the way to go.

### 18.3.2 Unix Environment Variables

Another non-standard way to get the environment variables is as a parameter to main(). It works much the same way, but you avoid needing to add your extern environ variable. Not even the POSIX spec supports this^ as far as I can tell, but it's common in Unix land.

```c
#include <stdio.h>

int main(int argc, char **argv, char **env) // <-- env!
    (void)argc; (void)argv; // Suppress unused warnings

    for (char **p = env; *p != NULL; p++) {
        printf("%s\n", p);
    }

    // Or you could do this:
    for (int i = 0; env[i] != NULL; i++) {
        printf("%s\n", env[i]);
    }
}
```

Just like using environ but less portable. It's good to have goals.
