# 39.7 Mutexes

If you want to only allow a single thread into a critical section of code at a time, you can protect that section with a 'mutex'.

For example, if we had a static variable and wanted to be able to get and set it in two operations without another thread jumping in the middle and corrupting it, we could use a mutex for that.

You acquire a mutex or release it. If you attempt to acquire a mutex and succeed, you may continue execution. If you attempt and fail (because someone holds it), you will block until the mutex is released.

If multiple threads are waiting for a mutex to be released, one of them will be chosen to run (at random, from our perspective), and the others will continue to sleep.

The gameplan is that we'll initialize a mutex variable to make ready to use with mtx_init().

Then subsequent calls call mtx_lock() and mtx_unlock() to get and release the mutex.

When we're done with the mutex, we can destroy it with mtx_destroy(), the logical opposite of mtx_init().

Because we're not using a mutex over the getting of the value (to print it) and the setting (to increment it), threads might get in each other's way in that critical section.
