# Chapter 17

# Multifile Projects

So far we've been looking at toy programs that the most part fit in a single file. But complex C programs are made up of many files that are all compiled and linked together into a single executable.

In this chapter we'll check out some of the common patterns and practices for putting larger projects.

# 17.1 Includes and Function Prototypes

A really common situation is that some of your functions are defined in one file, and you want to call them from another.

This actually works out of the box with a warning... let's first try it and then look at the right way to fix the warning.

For these examples, we'll put the filename as the first command in the source.

To compile, you'll need to specify all the sources on the command line:

```
# output file source files
# v v
# |---|---|-
gcc -o foo foo.c bar.c
```

In that examples, foo.c and bar.c get built into the executable named foo.

So let's take a look at the source file bar.c:

```
// File bar.c

 add(int x, int y)
{
    return x + y;
}
```

And the file foo.c with main in it:

```
// File foo.c
```

```
#include <stdio.h>

int main(void)
{
    printf("%d\n", add(2, 3)); // 5!
```
