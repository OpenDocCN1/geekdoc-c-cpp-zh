# 第 41 章

## 函数限定符 (Function Specifiers)、对齐限定符/运算符 (Alignment Specifiers/Operators)

在我的经验中，并没有看到它们被大量使用，但为了完整起见，我们在这里介绍它们。

## 41.1 函数限定符 (Function Specifiers)

当你声明一个函数时，可以给编译器提供一些关于该函数如何被调用或可能如何被使用的提示。这可以启用或鼓励编译器进行某些优化。

### 41.1.1 使用 `inline` 提高速度——也许吧

你可以这样声明一个内联函数：

```c
static inline int add(int x, int y) {
    return x + y;
}
```

 它的目的是鼓励编译器让这个函数调用尽可能快。从历史上看，实现这一点的方法之一是内联（inlining），这意味着函数的体将完整地嵌入到调用它的地方。这可以避免设置函数调用和销毁调用的所有开销，代价是代码体积变大，因为函数被复制到了到处，而不是被复用。

这似乎就是故事的结局了，但事实如此。`inline` 带来了一整套规则，让情况变得变得。我不确定是否理解所有的它们，而且行为似乎随编译器而异。

简短的答案是：在需要的文件中将 `inline` 函数定义为 `static`。然后在一个文件中使用它。你永远不需要担心其他的。

但如果你好奇，这里有更有意思的。让我们尝试去掉 `static`。

```c
#include <stdio.h>

inline int add(int x, int y) {
    return x + y;
}
```

```c
int main(void)
{
    printf("%d\n", add(1, 2));
}
```

gcc 对 `add()` 给出了链接错误……除非你用优化进行编译（可能吧！）
看，编译器可以选择是否内联，但如果它选择了内联，它将完全不使用任何函数。除非你定义了优化构建，否则 gcc 不会内联。

解决此问题的方法之一是在地方定义一个非内联的外部链接版本的函数，当内联版本不可用时使用它。但由于程序员无法确定会用哪一个，也许吧。如果两个都可用，编译器选择哪一个是未指定的。在 gcc 中，如果你用优化进行编译，将使用内联函数，否则将使用非内联的。如果这些函数的体是由……

另一种方法是将函数声明为 `extern inline`。然后它会尝试在此文件中进行内联，但也会创建一个具有外部链接的版本。这样 gcc 就会根据优化情况使用其中一个，但至少它们是同一个函数。

除非，当然，你还有另一个源文件包含一个同名的内联函数；它将根据优化情况使用内联函数或具有外部链接的版本。

但假设你正在进行一个编译器正在内联函数的构建。在这种情况下，你只需要使用普通的 `inline` 即可。然而，现在有了限制。

你可以引用任何 `static` 变量：

```c
static int b = 13;
inline int add(int x, int y) {
    return x + y + b; // 错误 -- 不能引用 b
}
```

你可以定义任何非 `const` 变量：

```c
int b = 13;
inline int add(int x, int y) {
    return x + y + b; // 错误 -- 不能定义 static
}
```

但将其变为 `const`：

```c
static const int b = 13;
inline int add(int x, int y) {
    return x + y + b; // 正确 -- static const
}
```

现在，你知道函数默认是外部的，所以你应该能够从另一个文件调用 `add()`。你可能认为是这样，但你不能！如果它只是一个普通的 `inline`，它只在该文件中可见。好吧，如果我们在那里抛出一个错误呢？现在我们又回到了之前讨论过的将 `inline` 与外部链接混合的话题。如果两个都可见，编译器可以选择使用哪一个。这里是带有 `inline` 的 `foo.c`：

```c
// foo.c
#include <stdio.h>

inline char *func(void) {
    return "foo's function";
}

int main(void) {
    printf("%s\n", func());
    bar();
}
```

回想，除非我们使用 gcc 的优化构建，否则 `func()` 将消失，我们将得到链接错误。除非我们在 `bar.c` 中定义了一个具有外部链接的版本。

```c
// bar.c
#include <stdio.h>

char *func(void) {
    return "bar's function";
}

void bar(void) {
    printf("%s\n", func());
}
```

所以问题是，输出是什么？看起来当我们从 `foo.c` 调用 `func()` 时，它应该打印 'foo's function'。从 `bar.c` 调用时，它应该打印 'bar's function'。如果我用 gcc 带优化进行编译¹，它将使用内联，我们将得到预期的：

```
foo.c: foo's function
bar.c: bar's function
```

太棒了！但如果在 gcc 中不带优化进行编译，它会忽略内联函数并使用来自 `bar.c` 的外部链接 `func()`！我们得到了这个：

```
foo.c: bar's function
bar.c: bar's function
```
¹你可以在命令行中使用 `-O` 实现这一点。

简而言之，这些规则异常复杂。我给自己留了 30% 的概率认为我正确描述了它们。

### 41.1.2 `nooreturn` 和 `_noreturn`

这向编译器指示特定函数永远不会返回其调用者，即程序在函数返回之前通过某种机制退出。它允许编译器在函数调用周围执行某些优化。它还允许向开发者指示某些程序逻辑取决于函数的返回。你可能需要使用它，但在某些库调用 `exit`² 中看到它，大家都会建议包含 `<stdnoreturn.h>` 并使用易读的 `nooreturn`。

如果被指定为 `nooreturn` 的函数实际上返回了，那是未定义行为。这在计算上是昂贵的，你看。这里有一个正确使用 `nooreturn` 的示例：

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdnoreturn.h>

noreturn void foo(void) // 这个函数永远不应该返回
{
    printf("Happy days");
    exit(1); // 在这里退出！
}

int main(void) {
    foo();
}
```

如果编译器检测到 `nooreturn` 函数可能返回，它会发出警告：

```
foo.c:7:5: warning: function 'foo' should not return
```

## 41.2 对齐限定符与运算符 (Alignment Specifiers and Operators)

对齐是关于可以存储对象的地址倍数。

### 41.2.1 `alignas` 和 `Aligns`

这并不是函数。相反，它是对齐限定符，你可以在变量声明中使用它。如果你需要 `char` 像 `int` 一样对齐，你可以这样强制它：

内置的是 `_Alignas`，`<stdalign.h>` 头文件将其定义为 `alignas`，如果你想看起来更酷的话。

```c
#include <stdalign.h>
char alignas(int) c;
```

你也可以传递常量值或表达式作为对齐。这必须由系统支持。2 的幂（1, 2, 4, 8, 16）通常是安全的。

```c
char alignas(8) c; // 8 字节边界
```

如果你想在系统使用的最大对齐，包含 `<stddef.h>` 并使用 `max_align_t` 类型，如下：

```c
char alignas(max_align_t) c;
```

你可以通过指定一个大于 `max_align_t` 的对齐来过度对齐，但这些情况取决于系统。

### 41.2.2 `alignof` 和 `Alignof`

该运算符将返回特定类型在该系统中用于对齐的地址倍数。例如，可能 `char` 按 1 个地址对齐，而 `int` 按 4 个地址对齐。内置运算符是 `_Alignof`，`<stdalign.h>` 头文件将其定义为 `alignof`。

这里有一个程序将打印出不同类型的对齐情况。再次，这些会随系统而异。注意 `max_align_t` 类型将给你系统使用的最大对齐。

```c
#include <stdalign.h>
#include <stdio.h> // 用于 printf(void)
#include <stddef.h> // 用于 max_align_t

struct t {
  int a;
  char b;
  float c;
};

int main(void) {
  printf("char" : %u\n", alignof(char));
  printf("short" : %u\n", alignof(short));
  printf("int" : %u\n", alignof(int));
  printf("long" : %u\n", alignof(long));
  printf("long long" : %u\n", alignof(long long));
  printf("double" : %u\n", alignof(double));
  printf("long double" : %u\n", alignof(long double));
}
```
