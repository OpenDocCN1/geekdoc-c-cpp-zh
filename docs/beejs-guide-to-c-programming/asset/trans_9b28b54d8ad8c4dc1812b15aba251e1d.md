## 26.2.1 货币数字分组

好了，这个部分有点绕绕。`mon_grouping` 是一个 `char*`，所以你可能认为它是一个字符串。在这种情况下，并不是，它是一个字符数组。它应该以 `theta` 或 `CHAR_MAX` 结尾。

这些值描述了如何对货币中小数点*左侧*（整数部分）的数字进行分组。

例如，我们可能会有：

```
2 1 0
-- ...
$100,000,000.00
```

这些是三位一组的数字。组 0（小数点左侧）有 3 位数字。组 1（左侧的下一组）有 3 位数字，最后一组也有 3 位。

所以我们可以从右侧（小数点）向左，用一组表示分组大小的整数值来描述这些组：

```
3 3 3
```

这对于高达 $100,000,000 的值有效。

但如果我们有更多呢？我们可以不断添加 3……

```
3 3 3 3 3 3 3 3 3 3 3 3 3
```

但那太疯狂了。幸运的是，我们可以设置 `theta` 来指示前一个分组大小是重复的：

```
3 0
```

这意味着每 3 位重复一次。这可以处理 $100,$1,000,$10,000,$10,000,000,$100,000,000,000 等。

你可以正理言章地疯狂使用这些值来表示某些奇的分组方式。

例如：

```
4 3 2 1 0
```

将指示：

```
$1, 0, 0, 0, 000, 000, 0000.00
```

另一个可能出现的值是 `CHAR_MAX`。它表示不应再进行分组，可以出现在数组的任何位置，包括第一个值。

```
3 2 CHAR_MAX
```

将指示：

```
100000000, 00, 000.00
```

例如。

只需在数组第一个位置放置 `CHAR_MAX`，就会告诉你完全没有分组。

## 26.2.2 分隔符与符号位置

所有 `sep_by_space` 变体处理货币符号周围的间距。有效值为：

| 值 | 描述 |
| --- | --- |
| 0 | 货币符号和值之间没有空格。 |
| 1 | 用空格将货币符号（如果有任何符号）与值隔开。 |
| 2 | 用空格将符号与货币符号（如果相邻）分开，否则用空格将符号与值隔开。 |

`sign_posn` 变体由以下值决定：

| 值 | 描述 |
| --- | --- |
| 0 | 在值和货币符号周围加上括号。 |
| 1 | 将符号放在货币符号和值的前面。 |
| 2 | 将符号放在货币符号和值的后面。 |
| 3 | 将符号直接放在货币符号前面。 |
| 4 | 将符号直接放在货币符号后面。 |

## 27.1 什么是 Unicode?

过去，以美国中心的世界使用 7 位或 8 位编码处理内存中的字符。这意味着我们可以有 128 或 256 个字符（包括不可打印字符）。这很好，但变成了兼容性噩梦。中文有超过 50,000 个字符，而一个字节无法容纳。为了解决这个问题，Unicode 发明了。它扩展到了无限（实际上）。

## 27.2 代码点 (Code Points)

我想在这里讨论两个概念。这很困惑，因为它们都是为了同一件事。但大致定义，*代码点*是指表示字符的数值。每个代码点代表一个唯一的字符。每个字符都有关联的代码点。例如，在 Unicode 中，数值 66 代表“B”，960 代表“n”。其他字符映射使用不同的值，可能让我们忘记它们并专注于 Unicode，未来！所以有一件事：代表每个字符的数字。在 Unicode 中，这些数字从 0 到 100 万。明白了吗？我们要翻转。

## 27.3 编码

8 位可以容纳 0-255 的值，这对于 66（即“B”）来说很棒——一个字节就能容纳。但“n”是 960，一个字节无法！我们需要另一个字节。如何在内存中存储所有这些？或者更大的数字，比如 195024？这将需要字节。大问题是：这些数字在内存中是如何表示的？这就是我们所说的字符编码。我们有两个：告诉我们特定字符序列的代码点。告诉我们要在内存中表示该数字的编码。有许多编码。如果你愿意，现在就可以编写自己的！我们将查看与 Unicode 使用的一些常用编码。

| 编码 | 描述 |
| --- | --- |
| UTF-8 | 一种面向字节的编码，每个字符使用数量字节。这是我们使用的。 |
| UTF-16 | 每个字符 16 位编码。 |
| UTF-32 | 每个字符 32 位编码。 |

对于 UTF-16 和 UTF-32，字节顺序非常重要，所以你可能使用 `UTF-16BE` 表示大端，`UTF-16LE` 表示小端。UTF-32 也是如此。技术上，如果没有指定，你应该假设为大端，但 Windows 广泛使用 UTF-16 和小端，有时会被这样假设。让我们看一些例子。将值精确地写为两个数字，并查看它们在内存中是如何排列的。

| A | 41 | 0041 | 00000041 | 4100 | 410000041 | 41 |
| B | 42 | 0042 | 00000042 | 4200 | 420000042 | 42 |
| E | 7E | 007E | 0000007E | 7E00 | 7E00007E | 7E |
