float f;
char c;

```c
char *s = _Generic(i,
int: "that variable is an int",
float: "that variable is a float",
default: "that variable is some type"
);
printf("%s\n", s);
```

Check out the _Generic expression starting on line 9.
When the compiler sees it, it looks at the type of the first argument. (In this example, the type of the variable i) It looks through the cases for something of that type. And then it substitutes the argument in place of the entire _Generic expression.

In this case, i is an int, so it matches that. The string is substituted in for expression. So the line turns into this when the compiler sees:

```c
char *s = "that variable is an int"
```

If the compiler can't find a match in the _Generic, it looks for the optional default case and uses that.
If it can't find a match and there's no default, you'll get a compile error. The first expression must match one of the types or default.

Because it's inconvenient to write _Generic over and over, it's often used to make the body of a macro that.
Let's make a macro TYPESTR(x) that takes an argument and returns a string with the type of the argument.

So TYPESTR(1) will return the string "int", for example.

Here we go:

```c
#include <stdio.h>

#define TYPESTR(x) _Generic((x), \
int: "int", \
long: "long", \
float: "float", \
double: "double", \
default: "something else")

int main(void) 
{
    int i;
    long l;
    float f;
    double d;
    char c;

    printf("i is type %s\n", TYPESTR(i));
    printf("l is type %s\n", TYPESTR(l));
    printf("f is type %s\n", TYPESTR(f));
    printf("d is type %s\n", TYPESTR(d));
    printf("c is type %s\n", TYPESTR(c));
}
```

This outputs:

```
i is type int
l is type long
f is type float
d is type double
c is type something else
```

Which should be no surprise, because, like we said, that code in main() is replaced with the following when it is compiled:

```c
printf("i %s\n", "int");
printf("l %s\n", "long");
printf("f %s\n", "float");
printf("d %s\n", "double");
printf("c %s\n", "something else");
```

And that's exactly the output we see.

Let's do one more. I've included some macros so that when you run:

```c
int i = 10;
char *s = "Foo";
PRINT_VAL(i);
PRINT_VAL(s);
```

you get the output:

```
i = 10
s = Foo!
```

We'll have to make use of some macro magic to do that.

```c
#include <stdio.h>
#include <string.h>

// Macro that gives back a format specifier for a type
#define FMTSPEC(x) _Generic((x), \
int: "%d", \
long: "%ld", \
float: "%f", \
double: "%f", \
char: "%s", \
// TODO: add more types)

// Macro that prints a variable in the form "name = value"
#define PRINT_VAL(x) do { \
    char fmt[512]; \
    snprintf(fmt, sizeof(fmt), "%x = %s\n", FMTSPEC(x)); \
    printf(fmt, (x)); \
} while(0)

int main(void)
{
    int i = 10;
    float f = 3.14159;
    char *s = "Hello, world!";

    PRINT_VAL(i);
    PRINT_VAL(f);
    PRINT_VAL(s);
}
```

for the output:
```

f = 3.141590
s = Hello, world!
```

## Arrays Part II

We're going to go over a few extra misc things this chapter concerning arrays.

- Type qualifiers with array parameters
- The static keyword with array parameters
- Partial multi-dimensional array initializers

They're not super-commonly seen, but we'll peek at them since they're part of the newer spec.

### 33.1 Type Qualifiers for Arrays in Parameter Lists

If you recall from earlier, these two are equivalent in function parameter lists:

```c
int func(int p) {......}
int func(int p[]) {......}
```

And you might recall that you can add qualifiers to a pointer variable like so:

```c
int const p;
int volatile p;
int const volatile p;
// etc.
```

But how can we do when we're using array notation? (Wait, the OCR text seems slightly garbled here, let's reconstruct based on context): 
But how can we do when we're using array notation in our parameter list? Turns out it goes in the brackets. You can put optional qualifiers after. The following lines are equivalent:

```c
int func(int volatile p) {......}
int func(int const p[]) {......}
int func(int const volatile p[]) {......}
```

If you have a multidimensional array, you need to put type qualifiers in the first set of brackets.

### 33.2 static for Arrays in Parameter Lists

Similarly, you can use the static keyword in array parameter list. This is something I've never seen in the wild. It is always followed by a dimension:

```c
int func(int static p[]) {......}
```

Anything else is undefined behavior.

```c
int func(int static p[]) {}

int main(void)
{
    int a[] = {11, 22};
    int b[] = {11, 22, 33, 44};
    int c[] = {11, 22};
}
```

Important note: there is nothing in the compiler that prohibits you from passing a smaller array. The compiler probably won't warn you, and won't detect it at runtime. By putting static there, you're saying, "I will never pass a smaller array than this." And the compiler says, "Yeah, fine," and trusts you to do the right thing.

### 33.3 Equivalent Initializers

C is a bit flexible, shall say, when it comes to initializers. We've already seen some of this where missing values are replaced with zero. For example, we can initialize a 5 element array to 1, 2, 0, 0, 0 with this:

```c
int a[5] = {1, 2};
```

Or an array entirely to zero with:

```c
int a[5] = {0};
```

But things get interesting when initializing multidimensional arrays. Let's make an array of 3 rows and 2 columns

```c
int a[3][2];
```

Let's write some code to initialize it and print the result:

```c
#include <stdio.h>

int main(void)
{
    int a[3][2] = {
        {1, 2},
        {3, 4},
        {5, 6}
    };
}
```

And when we run it, we get the expected:

```
1 2
3 4
5 6
```

Let's leave some of the initializer elements and see they get set to zero:

```c
int a[3][2] = {
    {1, 2},
    {3}, // Left off 4
    {5, 6}
};
```

which produces:

```
1 2
3 0
5 6
```

Now let's leave the entire middle element:

```c
int a[3][2] = {
    {1, 2},
    // {3, 4}, // Just cut this thing out
    {5, 6}
};
```

And now we get this, which might not be what you expect:

```
1 2
5 6
0 0
```

But if you stop thinking about it, we provided enough initializers for two rows, so they got used for the first two rows. The remaining elements were initialized to zero.

So far so good. Generally, if we leave off parts of the initializer, the compiler sets the corresponding elements to 0. But let's get crazy.

```c
int a[3][2] = { 1, 2, 3, 4, 5, 6 };
```

That's a 2D array, but it only has a 1D initializer! Turns out that's legal (though GCC will warn you about it with the proper warnings turned on). Basically, what it does is starts filling in elements in row 0, then row 1, row 2 from left to right. So when we print, it prints in order:

```
1 2
3 4
5 6
```

If we leave some off:

```c
int a[3][2] = { 1, 2, 3 };
```

they fill with zero:

```
1 2
3 0
0 0
```

So if you want to fill the whole array with {}, then go ahead and:

```c
int a[3][2] = {0};
```

But my recommendation is if you have a 2D array, use a 2D initializer. It just makes the code more readable. (Except for initializing the whole array with {}, in which case it's idiomatic to use {} no matter the dimension of the array.)

## Chapter 34

## Long Jumps with setjmp, longjmp

We've already seen goto, which jumps in function scope. longjmp() allows you to jump back to an earlier point in execution, back to a function that called this. There are a lot of limitations and caveats, but this can be a useful function for bailing out from deep in the call stack back up to an earlier state. In my experience, this is rarely-used functionality.

### 34.1 Using setjmp and longjmp

The dance we're going to do here is basically put a bookmark in execution with setjmp(). Later on, we'll call longjmp() and it jump back to the earlier point in execution where we set the bookmark with setjmp(). And it can do this if you've called subfunctions.

Here's a quick demo where we call functions a couple levels deep and then bail out of it. We're going to use a file variable env to keep the state of things when we setjmp() so we can restore them when we call longjmp(). This is in the variable we remember our "place".

The variable env is jmp_buf, an opaque type declared in <setjmp.h>.

```c
#include <stdio.h>
#include <setjmp.h>
jmp_buf env;
void depth2(void)
{
    printf("Entering depth 2\n");
    longjmp(env, 3490); // Bail out
    printf("Leaving depth 2\n"); // This won't happen
}
void depth1(void)
{
    printf("Entering depth 1\n");
    depth2();
    printf("Leaving depth 1\n"); // This won't happen
}
```
