# Chapter 18. The Outside Environment

```
printf("usage: mult x y\n");
return EXIT_FAILURE; // Indicate to shell that it didn't work
}

printf("%d\n", atoi(argv[1]) * atoi(argv[2]));

return 0; // same as EXIT_SUCCESS, everything was good.

```

Now if we try to run this, we get the expected effect until we specify the right number of command-line arguments:

```
$ ./mult x y
usage: mult x y

./mult 3 4 5
usage: mult x y
```

```
$ ./mult 3 4
12
```

But that doesn't really show the exit status that we returned, does it? We get the shell to print it out, though. Assuming you're running Bash or another POSIX shell, you can use echo $? to see it.

Let'try:

```
$ ./mult x y
usage: mult x y
echo $?
1
```

```
$ ./mult 3 4 5
usage: mult x y
echo $?
1
```

```
$ ./mult 3 4
12
echo $?
0
```

Interesting! We see that on my system, EXIT_FAILURE is 1. The spec doesn't spell this out, so it could be any number. But it's 1 on your system, too.

# 18.2.1 Other Exit Status Values

The status $ definitely means success, but all the other integers, even negative ones?
Here we're going into the C spec and into Unix land. In general, while $0 means success, a positive non-zero number means failure. Bash says the exit code should be between 0 and 255, though a number of codes are reserved.

In short, if you want to indicate different error statuses in a Unix environment, you can start with 1 and work your way up.

On Linux, if you try any code range 0-255, it will bitwise AND the code with 0xff, effectively clamping to that range.

> *In Windows cmd.exe, type echo %errorlevel%. In PowerShell, type $LastExitCode.
