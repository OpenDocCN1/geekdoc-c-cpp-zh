We hope our thread eventually manages to acquire both mutexes and save the day, all while avoiding evil deadlock.

## 31.9 goto and Variable Scope

We've already seen that labels have function scope, but weird things can happen if we jump past some variable initialization.

Look at this example where we jump from a place where the variable x is out of scope into the middle of its scope (the block).

This will compile and run, 'x' is used uninitialized in this function

warning: 'x' is used uninitialized in this function

And then it prints out 0 when I run it (your mileage may vary).

Basically what has happened is that we jumped into x's scope (so it was OK to reference it in the printf()) but we jumped over the line that actually initialized it to 12345. The value was indeterminate.

The fix is, of course, to get the initialization after the label one way or another.

```c
goto label;
{
    int x;
label:
    x = 12345;
    printf("%d\n", x);
}
```

Let's look at one more example.

```c
{
    int x = 10;
label:
    printf("%d\n", x);
}
```

What happens here?

The first time through the block, we're jumping into the scope of x, but past its initialization. Which means we can still print it, but the value is indeterminate (since it hasn't been reinitialized).

On my machine, it prints 10 again (to infinity), but that's just luck. It could print any value after the goto since x is uninitialized.

## 31.10 goto and Variable-Length Arrays

When it comes to VLAs and goto, there's one rule: you can't jump from outside the scope of a VLA into the scope of that VLA.

If I try to do:

```c
int x = 10;
goto label;
{
    int v[x];
label:
    printf("Hi!\n");
```

I get an error:

error: jump into scope of identifier with variably modified type

You can jump in ahead of the VLA declaration, like this:

```c
int x = 10;
goto label;
{
label:  ;
  int v[x];
  printf("Hi!\n");
}
```

Because that way the VLA gets allocated properly before its inevitable deallocation once it falls out of scope.

## 32.1 Compound Literals

This is a neat feature of the language that allows you to create an object of some type on the fly without assigning it to a variable. You can make simple types, arrays, structs, you name it. One of the main uses is for passing complex arguments to functions when you don't want to make a temporary variable to hold the value. The way you create a compound literal is to put the type in parentheses, and then put initializer list after. For example, an unnamed array of ints, might look like this:

```c
(int[]){1, 2, 4};
```

Now, that line doesn't do anything on its own. It creates an unnamed array of ints, and then throws them away. We could use a pointer to store a reference to the array...

```c
int *p = (int[]){11, 2, 4};
printf("%d\n", p[1]); // 2
```

But that seems a little like a long-winded way to have an array. Mean I could have done this:

```c
int p[] = {1, 2, 4};
printf("%d\n", p[1]); // 2
```

So let's take a look at a more useful example which isn't quite the same, since it's an array, not a pointer to an int.

### 32.1.1 Passing Unnamed Objects to Functions

Let's say we have a function to sum an array of ints:

```c
int sum(int p[], int count)
{
    int total = 0;
    for (int i = 0; i < count; i++)
        total += p[i];
    return total;
}
```

If we wanted to call it, we'd normally have to do something like this, declaring an array and storing values in it to pass to the function:

```c
int a[] = {1, 2, 3, 4};
sum(a, 4);
```

But unnamed objects use a way to skip the variable by passing in names listed above. Check it out—we're replacing the variable with an unnamed object that we are passing as the first argument:

```c
sum((int[]){1, 2, 3, 4}, 4);
```

Pretty slick!

### 32.1.2 Unnamed structs

We can do something without structs. First, let's do things without unnamed objects. We'll define a struct to hold some coordinates. Then we'll define one, passing values into its initializer. Finally, we'll pass it to a function to print the values:

```c
#include <stdio.h>

struct coord {
    int x, y;
};

void print_coord(struct coord c)
{
    printf("%d, %d\n", c.x, c.y);
}

int main(void)
{
    struct coord t = {.x=10, .y=20};
    print_coord(t); // prints "10, 20"
}
```

Straightforward enough. Let's modify it to use an unnamed object instead of the variable t we're passing to print_coord(). We'll just take t out of there and replace it with an unnamed struct:

```c
struct coord t = {.x=10, .y=20};
print_coord((struct coord){.x=10, .y=20}); // prints "10, 20"
```

Still works!

### 32.1.3 Unnamed Objects

You might have noticed in the last example that we were using a struct, we were passing a copy of the struct to print_coord() as opposed to passing a pointer to the struct. Turns out, we can just take the address of an unnamed object & with likes always. This is because, if an operator would have worked on a variable of that type, you can use that operator on an unnamed object of that type. Let's modify the code <stdio.h to pass a pointer to an unnamed object

```c
#include <stdio.h>

struct coord {
    int x, y;
};

void print_coord(struct coord *c) {
    printf("%d, %d\n", c->x, c->y);
}

int main(void) {
    // Note the &
    print_coord((struct coord){.x=10, .y=20}); // prints "10, 20"
}

// Additionally, this could be a nice way to pass even pointers to simple objects:
// Pass a pointer to an int with value 3490
foo(&(int)(3490));
```

Easy as that.

### 32.1.4 Unnamed Objects and Scope

The lifetime of an unnamed object ends at the end of its scope. The biggest way this could bite you is if you make a new unnamed object, give a pointer to it, and then leave the object's scope. In that case, the pointer will refer to a dead object. So this is undefined behavior:

```c
int *p;
{
    p = &(int){10};
}

printf("%d\n", *p); // INVALID: The (int){10} fell out of scope
```

Likewise, you can't return a pointer to an unnamed object from a function. The object is deallocated when it falls out of scope:

```c
#include <stdio.h>

int *get3490(void)
{
  // Don't do this
  return &(int){3490};
}
```

```c
int main(void)
{
  printf("%d\n", *get3490()); // INVALID: (int){3490} fell out of scope
}
```

### 32.1 Silly Unnamed Object Example

You can put any type in and make an unnamed object. For example, these are effectively equivalent:

```c
int x = 3490;
```

```c
printf("%d\n", x);           // 3490 (variable)
printf("%d\n", 3490);      // 3490 (constant)
printf("%d\n", (int){3490}); // 3490 (unnamed object)
```

That last one is unnamed, but it's silly. Might as well do the one on the line before. But hopefully that provides a little clarity on the syntax.
