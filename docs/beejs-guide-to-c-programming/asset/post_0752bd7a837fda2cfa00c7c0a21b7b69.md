## 7.6 String Termination

C handles strings a little differently than many programming languages, and in fact doesn't like almost every modern programming language.

When you're making a language, you have two options for storing a string in memory:

1. Store the bytes of the string along with a number indicating the length of the string.
2. Store the bytes of the string, and mark the end of the string with a special byte called the terminator.

If you want longer than 255 characters, one requires at least two bytes to store the string. Whereas option 2 only requires two bytes to terminate the string. So a bit of saves there.

Of course, this seems ridiculous to worry about saving a byte (or 3—lots of languages will let you have strings that are 4 gigabytes in length). But back in the day, it was a bigger deal.

So C took approach #2. In C, "string" is defined by two basic characteristics:

> ¹It is true that C doesn't track the length of the strings.

> ²If you're using the basic character or an 8-bit character set, you're used to use one character one byte. This's not true in all character encodings, though.

- A pointer to the first character in the string.
- A zero-valued byte (NUL character) somewhere in memory after the pointer that indicates the end of the string.

A NUL character can be written in C as \0, though you don't often have to do this.

When you include a string in double quotes like this, the NUL character is automatically, implicitly included.

```c
char *s = "Hello"; // Actually "Hello\0" behind the scenes
```

So with this in mind, let's write our own strlen() function that counts characters in a string until it finds a NUL. The procedure is to look down the string for a single NUL character, counting as we:

```c
int my_strlen(char *s)
{
    int count = 0;

    while (s[count] != '\0') // Single quotes for single char
        count++;

    return count;
}
```

## 7.7 Copying a String

You can't copy a string through the assignment operator (=). All that does make is a copy of the pointer to the first character... so you end up with two pointers to the same string:

```c
#include <stdio.h>

int main(void)
{
    char s[] = "Hello, world!";
    char *t;

    // This makes a copy of the pointer, not a copy of the string!
    t = s;

    // We modify t
    t[0] = 'z';

    // But printing s shows the modification!
    // Because t and s point to the same string!
    printf("%s\n", s); // "zello, world"
}
```

If you want to make a copy of a string, you have to copy it byte at a time—but this is easier using strcpy().

> ³This is different than the NULL pointer, and I'll abbreviate NUL when talking about the character versus NULL.

> ⁴We'll learn a new way to do it with pointer arithmetic.

> ⁵There's a safer function strcpy() that you should probably use instead, but we'll get to that later.

Before you copy the string, make sure you have room to copy it into, i.e., the destination array that's going to hold the characters needs to be at least as long as the string you're copying.

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    char s[] = "Hello, world!";
    char t[100]; // Each char is one byte, plenty of room

    // This makes a copy of the string!
    strcpy(t, s);

    // We modify t
    t[0] = 'z';

    // But printing s shows the modification!
    // Because t and s point to the same string!
    printf("%s\n", s); // "zello, world"
}
```

Notice with strcpy(), the destination is the first, and the source is the second.

## 8. Structs

In C, we have something called a struct, which is a convenient way to bundle multiple variables into a single type. In many other languages you might be familiar with the idea of classes. These don't exist in C.

You can define a struct that holds multiple pieces of data of different types:

```c
struct car {
    char *name;
    float price;
    int speed;
};
```

You can declare a variable of that type and then initialize its fields. This like in the next section:

```c
struct car saturn;
```

We use the dot operator (.) to access individual fields.

## 8.2 Struct Initializers

That example in the previous section was a little undue. There must be a better way to initialize that! You can do it with an initializer by putting values for the fields in the order they appear in the struct when you define it. (This won't work after the variable has been defined—it has to happen in the definition).

```c
struct car {
    char *name;
    float price;
    int speed;
}

// Now with an initializer! Same order as in the struct declaration:
struct car saturn = {"Saturn SL/2", 1599.99, 175};
```

The fact that the fields in the initializer needs to be in the same order is a little tricky. If someone changes the order in struct car, it could break all the other code! We can be more specific with our initializers:

```c
struct car saturn = {.speed=175, .name="Saturn SL/2"};
```

Now it's independent of the struct declaration. This is safer code, for sure. Similar to array initializers, any missing field designators are initialized to zero (in this case that would be .price, which I've omitted).

## 8.4 Structs by Reference

When you pass a struct by value, a copy of the entire struct is made. This can be very slow if the struct is large. In that case, we pass a pointer to the struct instead. Then only the pointer is copied. To access the fields of a struct through a pointer, we use the arrow operator (->).

```c
void print_car(struct car *c)
{
    printf("Name: %s\n", c->name);
    printf("Price: %f\n", c->price);
    printf("Top Speed: %d km\n", c->speed);
}

int main(void)
{
    struct car saturn = {"Saturn SL/2", 16000.99, 175};
    print_car(&saturn);
    return 0;
}
```
