

## 第 40 章 原子性

```
call_once() thrd_create() thrd_join()
mtx_lock() mtx_timedlock()
mtx_timedlock() mtx_trylock()
malloc() calloc()
aligned_alloc() dealloc() realloc()
```

call_once()—与针对特定标志的所有后续 `call_once()` 调用同步。通过这种方式，后续的调用就可以确保，如果另一个线程设置了该标志，你将能够看到它。

thrd_create()—与新线程的开始执行同步。新线程可以确保它看到了 `thrd_create()` 之前父线程对所有共享内存的写入。

thrd_join()—当一个线程结束时，它与此操作同步。调用了 `thrd_join()` 的线程可以确保它看到了最新的线程共享写入。

mtx_lock()—对同一互斥锁执行的早先 `mtx_unlock()` 调用保持同步。这反映了我们已经讨论过的获取-释放（acquire-release）过程。`mtx_unlock()` 对互斥变量执行释放（release），任何后续通过 `mtx_lock()` 执行获取（acquire）的线程都能看到临界区中的共享内存更改。

mtx_timedlock() 和 mtx_trylock()—与 `mtx_lock()` 的同步类似，如果执行成功，早先的 `mtx_unlock()` 调用将与此调用同步。

**动态内存函数**：如果你分配了内存，它将与该内存之前的释放操作同步。特定内存区域的所有分配和释放都处于一个所有线程都能一致的单一顺序（total order）中。我认为这里的想法是，释放操作将在它选择的区域发生，而我们想要确保随后的分配不会看到未清除的数据。如果有遗漏，请告诉我。

使用它们！它们与 C++ 中使用的别名一致，如果这有帮助的话。
如果你想要更多？

你可以使用类型限定符或类型说明符来实现。
首先，说明符！它是带类型的 `_Atomic` 关键字⁵——适用于 typedef：
```c
typedef _Atomic(double) atomic_double;

atomic_double f;
```

说明符的限制：你所原子化的类型不能是数组或函数，也不能是原子或限定的。
接下来，限定符！它是不带类型的 `_Atomic` 关键字。
做类似的事情⁶：

```c
_Atomic(int); // 类型说明符
_Atomic(int); // 类型限定符
```

问题是，你可以包含其他类型限定符：
`Atomic int k;`
限定符的限制：你所原子化的类型不能是数组或函数。

## 40.9 无锁原子变量

硬件架构能够原子化读写的数据量是有限的。这取决于如何实现。
如果你使用原子类型，你可以确保对它的访问是原子的……但有一个陷阱：如果硬件无法做到，则通过锁来实现。

⁵C++23 将此项作为宏添加。
⁶规范说明它们在大小、表示和对齐上可能有所不同。

原子访问变成了锁，这相当要慢，并且对信号处理器有影响。原子标志是唯一在所有实现中都保证无锁的原子类型。在典型的桌面世界，较大的类型可能是无锁的。

首先，有些宏——你可以在编译时通过 `#if` 使用它们。它们适用于符号和无符号类型。

| 原子类型 | 无锁宏 |
| :--- | :--- |
| atomic_bool | ATOMIC_BOOL_FREE |
| atomic_char | ATOMIC_CHAR_FREE |
| atomic_char16_t | ATOMIC_CHAR16_T_FREE |
| atomic_char32_t | ATOMIC_CHAR32_T_FREE |
| atomic_wchar_t | ATOMIC_WCHAR_FREE |
| atomic_short | ATOMIC_SHORT_FREE |
| atomic_int | ATOMIC_INT_FREE |
| atomic_long | ATOMIC_LONG_FREE |
| atomic_llong | ATOMIC_LLONG_FREE |
| atomic_intptr_t | ATOMIC_POINTER_FREE |

这些宏可能有三个不同的值：

| 值 | 含义 |
| :--- | :--- |
| 0 | 永远无锁。 |
| 1 | 有时无锁。 |
| 2 | 总是无锁。 |

等待——东西怎么可能是无锁的？这意味着答案在编译时未知，但在运行时已知。也许答案取决于你是在 Intel 还是 AMD 上运行这段代码，之类的。但你也可以在运行时使用 `atomic_is_lock_free()` 进行测试。如果特定类型是原子的，该函数返回 true 或 false。

那么我们为什么要关心这个？无锁更快，所以可能存在你需要规避的性能考虑。也许你需要在信号处理器中使用原子变量。

## 40.9.1 信号处理器与无锁原子

如果你在信号处理器中读取或写入共享变量（静态存储期或 `Thread_local`），它将产生未定义行为……除非你执行以下操作之一：

- 读取 `volatile sig_atomic_t` 类型的变量。
- 读取或写入无锁的原子变量。

据我所知，无锁原子变量是从信号处理器中获取信息的少数方式之一。

我只是随口想了这个例子。这在 Intel/AMD 上没关系，但在某些地方可能很重要，该死！

在我的理解中，规范对于在信号处理器中获取或释放原子变量时的内存顺序是模糊的。C++ 说（这也是合理的），访问相对于程序的其余部分是无序的（unsequenced）。毕竟，信号可以在任何时间被触发。我假设 C 的行为是类似的。

## 40.10 原子标志

标准只保证一种类型是无锁：`atomic_flag`。这是一个用于测试并设置（test-and-set）操作的不透明类型。

它可以被设置或清除。你可以将其初始化为清除：

```c
atomic_flag f = ATOMIC_INIT;
```

你可以通过 `atomic_flag_test_and_set()` 原子化地设置标志，它会设置标志并返回之前的状态（设置为为 true）。

你可以通过 `atomic_flag_clear()` 原子化地清除标志。

这里有一个示例，我们初始化标志，设置两次，然后再次清除它。

```c
#include <stdio.h>
#include <stdbool.h>
#include <atomic.h>

atomic_flag f = ATOMIC_INIT;

int main(void) {
    bool r = atomic_flag_test_and_set(&f);
    printf("Value: %d\n", r); // 0

    r = atomic_flag_test_and_set(&f);
    printf("Value: %d\n", r); // 1

    atomic_flag_clear(&f);
    r = atomic_flag_test_and_set(&f);
    printf("Value: %d\n", r); // 0
}
```
