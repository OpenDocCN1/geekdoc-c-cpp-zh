

## 第 34 章 使用 setjmp, longjmp 进行长跳转

```c
int main(void)
{
    switch (setjmp(env)) {
        case 0:
            printf("Calling into functions, setjmp returned 0\n");
            depthi();
            printf("Returned from functions\n"); // 这行不会发生
            break;

        case 3490:
            printf("Bailed back to main, setjmp() returned 3490\n");
            break;
    }
}
```

运行时，它的输出如下：
Calling into functions, setjmp() returned 0
Entering depth 1
Entering depth 2
Bailed back to main, setjmp() returned 3490

如果你尝试通过代码匹配并输出这些，你会发现这确实有一些非常*诡异*的事情。最显著显著的一点是 `setjmp()` 返回了两次。这到底是怎么回事？这又是什么魔术？

情况是这样的：如果 `setjmp()` 返回 0，意味着你成功地在该点设置了“书签”。如果它返回非零值，意味着你刚刚返回了之前的某个“书签”。返回的值是你传递给 `longjmp()` 的值。通过这种方式，你可以区分设置书签和返回书签的操作。

所以代码第一次调用 `setjmp()` 时，`setjmp()` 将状态存储在 `env` 变量中并返回 0。之后当我们使用相同的 `env` 调用 `longjmp()` 时，它会恢复状态，此时 `setjmp()` 会返回 `longjmp()` 传递的值。

## 34.2 陷阱

在底层，这非常简单。通常，栈指针（stack pointer）跟踪内存中存储局部变量的位置，而程序计数器（program counter）则跟踪当前执行指令的地址¹。

如果我们想跳转回早之前的函数，基本上是将栈指针和程序计数器恢复到在 `jmp_buf` 变量中保存的值，并确保返回值被正确设置。然后执行就会继续。

但存在许多困惑之处，导致了大量的未定义行为陷阱。

### 34.2.1 局部变量的值

如果你希望自动变量（非静态且非外部的局部变量的值在 `longjmp()` 发生后仍然在调用 `setjmp()` 的函数中持续存在，你必须将这些变量声明为 `volatile`。

> ¹“栈指针”和“程序计数器”都与底层架构和 C 实现有关，不属于规范的一部分。

从技术上讲，只有当它们在调用 `setjmp()` 和调用 `longjmp()` 之间发生变化时，它们才需要是 `volatile`。

例如，如果我们运行这段代码：

```c
int x = 20;

if (setjmp(env) == 0) {
    x = 30;
}
```

然后之后通过 `longjmp()` 跳回来，`x` 的值将是不确定的。

如果我们修复这个问题，`x` 必须是 `volatile`：

```c
volatile int x = 20;

if (setjmp(env) == 0) {
    x = 30;
}
```

现在，在 `longjmp()` 返回到此点后，值将是 30。

## 34.2.2 保存了多少状态？

当你执行 `longjmp()` 时，执行会在 `setjmp()` 的调用处恢复。规范指出，这就像是你跳转回到了执行 `longjmp()` 调用时的函数点，局部变量被设置为当时的值。

以下内容不会被恢复，规范规定：

- 浮点状态
- 打开的文件
- 抽象机器的任何组件

## 34.2.3 你不能命名任何 setjmp

你不能有任何名为 `setjmp` 的标识符。或者如果 `setjmp` 是一个宏，你不能定义它。这些都是未定义行为。

## 34.2.4 你不能在复杂的表达式中使用 setjmp()

也就是说，你不能这样做：

```c
if (x == 12 && setjmp(env) == 0) { ... }
```

由于在展开栈时必须发生的操作，这种操作太复杂了，是不允许的。

> ² 这里的原理是，程序在处理它时，可能会在寄存器中临时存储一个值。在此期间，寄存器持有正确的值，而栈上的值可能已经过时。随后值会被覆盖，并影响变量。

- 它可以是等值表达式的一部分，只要另一个操作数是整数。
if (setjmp(env) == 0) {..

- 它可以是整个表达式。
if (!setjmp(env)) {..

- 它可以是一个独立表达式，强制转换为 `void`。
(void)setjmp(env);

## 34.2.5 什么时候你不能 longjmp()

在以下情况下是未定义行为：

- 你之前没有调用过 `setjmp()`
- 你从另一个线程调用了 `setjmp()`
- 你在变长数组（VLA）中调用了 `setjmp()`，并在调用 `longjmp()` 之前离开了 VLA 作用域

`longjmp()` 跳转到了栈中更之前的函数。

## 34.2.6 你可以传递 longjmp()

如果你尝试将值传递给 `longjmp()`，它会将其变为 1。由于 `setjmp()` 最终返回这个值，因此禁止返回 0。

## 34.2.7 longjmp() 和变长数组

如果你在 VLA 作用范围内并 `longjmp()` 出，分配给 VLA 的内存可能会泄漏。当 `longjmp()` 跳回任何带有 VLA 的早之前函数时，也会发生同样的情况。

> ³ 也就是说，内存一直持续到程序结束，而没有方法可以释放它。

## 第 35 章

## 不完整类型

你可能会惊讶地发现，以下代码编译没有报错：

extern a[];

```c
int main(void)
{
    struct foo *x;
    union bar *y;
    enum baz *z;
}
```

我们没有给 `a` 指定大小。而且 `foo`、`bar` 和 `baz` 似乎在任何地方都没有声明。我收到的唯一警告是 `x, y, z` 未使用。

这些是不完整类型的示例。

不完整类型是一个大小未知（通过 `sizeof` 获取）的类型。另一种理解方式是一个尚未完成声明的类型。你可以有一个不完整类型的指针，但不能对其进行解引用或指针算术。你不能对它使用 `sizeof`。那么你能用它做什么呢？

## 35.1 用例：自引用结构

我知道一个真实的用例：对自引用或相互依赖结构的体或联合进行向前引用（在这些示例中我将使用 `struct`，但它们同样适用于 `union`）。让我们先看经典的例子。

但在在此之前，记住这一点！当你声明一个结构体时，在遇到右括号之前，该结构体是不完整的！

```c
struct antelope { // 此时 struct antelope 是完整的
    int leg_count; // 仍然不完整
    float stomach_fullness; // 仍然不完整
    float top_speed; // 仍然不完整
    char *nickname; // 仍然不完整
};

// 现在它是完整的。

这似乎足够了。但我们在做链表呢？每个链表节点都需要指向另一个节点的引用。但如果我们还没有完成节点的声明，如何创建指向另一个节点的引用呢？

C 对不完整类型的允许使得这成为可能。我们不能声明节点，但我们可以声明指向它的指针，即使它是不完整的！

```c
struct node {
  int val;
  struct node *next; // struct node 是完整的，但没关系！
};
```

即使节点在第 3 行是不完整的，我们仍然可以声明它的指针。

如果我们有两个相互引用的不同结构体，也可以同样操作：

```c
struct a {
  struct b *x; // 指向 `struct b`
};
```

```c
struct b {
  struct a *x; // 指向 `struct a`
};
```

如果没有对不完整类型的宽松规则，我们永远无法创建那对结构体。

## 35.2 不完整类型错误信息

你是否收到了这样的错误？
invalid application of 'sizeof' to incomplete type
invalid use of undefined type
dereferencing pointer to incomplete type
可能的罪祸首：你可能忘记包含声明该类型的头文件。

## 35.3 其他不完整类型

声明没有实体的结构体或联合会产生不完整类型，例如：struct foo;
枚举在遇到右括号之前是不完整的。

`void` 是一个不完整类型。

没有指定大小的外部数组是不完整的，例如：extern int a[];

如果是非外部数组没有指定大小且跟着初始化列表，它在遇到初始化列表的右括号之前是不完整的。
