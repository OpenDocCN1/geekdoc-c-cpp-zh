

# 第 16 章 第 IV 类：限定符与指定符

## 16.2.2.2 文件作用域下的 static

当你离开文件作用域（块之外）时，它的含义发生了很大变化。

文件作用域的变量在函数调用之间也是持久的，因此这种行为已经存在了。

相反，在此语文中，`static` 意味着该变量在特定的文件之外是不可见的。类似于“全局”，但仅限于此文件。

关于这点的更多信息，请参见关于多源文件构建的章节。

## 16.2.3 extern

`extern` 存储类指定符为我们提供了一种引用其他源文件中对象的方法。

假设 `bar.c` 文件的全部如下：

```c
// bar.c

int a = 37;
```

仅此此。在文件作用域中声明了一个新的 `int`。

但如果我们有另一个源文件 `foo.c`，并且想引用 `bar.c` 中的那个变量呢？

使用 `extern` 关键字就简单了：

```c
// foo.c

int main(void)
{
    printf("%d\n", a); // 37，来自 bar.c！

    a = 99;

    printf("%d\n", a); // 仍然是 bar.c 的 "a"，但它现在是 99
}
```

我们也可以在块作用域中声明 `extern int`，它仍然会引用 `bar.c` 中的 `a`。

```c
// foo.c

int main(void)
{
    extern int a;

    printf("%d\n", a); // 37，来自 bar.c！

    a = 99;

    printf("%d\n", a); // 仍然是 bar.c 的 "a"，但它现在是 99
}
```

现在，如果 `bar.c` 中的 `a` 被标记为 `static`，这就不起作用了。文件作用域的 `static` 变量在文件外部是不可见的。

关于函数 `extern` 的最后说明：对于函数，`extern` 是默认的，因此它是多余的。如果你只想让函数在单个源文件中可见，可以将其声明为 `static`。

## 16.2.4 register

这是一个关键字，用于提示编译器该变量被频繁使用，并且应该尽可能快地进行访问。编译器没有义务同意这一建议。

现在，现代 C 编译器优化器非常擅长自己发现这一点，所以现在很少看到它。

但如果你非要用：

```c
#include <stdio.h>

int main(void)
{
    register int a; // 让 "a" 的使用速度尽可能快。

    for (a = 0; a < 10; a++)
        printf("%d\n", a);

}
```

然而，这是有代价的。你不能获取寄存器变量的地址。

```c
register int a;
*p = &a; // 编译器错误！无法获取寄存器的地址
```

同样的情况也适用于数组的任何部分：

```c
register int a[] = {11, 22, 33, 44, 55};
*p = &a[0]; // 编译器错误！无法获取 a[0] 的地址
```

对数组的任何部分进行解引用：

```c
register int a[] = {11, 22, 33, 44, 55};
```

```c
int a = (a + 2); // 编译器错误！a[0] 的地址
```

有趣的是，对于数组语法的等效写法，`gcc` 只给出：

```c
register int a[] = {11, 22, 33, 44, 55};
```

```c
int a = a[2]; // 编译器警告！
```

带有信息：
warning: ISO C 禁止下标 'register' 数组

无法获取寄存器变量地址的这一事实让编译器可以根据“它尚未发现这一点”的假设来进行优化。此外，在 `const` 变量上添加 `register` 可以防止意外将其指针传递给另一个会忽略其 `const`¹² 属性的函数。

历史背景：在 CPU 内部有一些小型的专用“变量”，被称为“寄存器”（registers）。它们访问 RAM 的速度极快，因此使用它们可以获得速度提升。它们不在 RAM 中，因此没有关联的地址（这就是为什么你无法获取它们的地址或获取它们的指针）。

但是，正如我所说，现代编译器非常擅长生成优化代码，无论你是否指定了 `register` 关键字都会使用寄存器。不仅如此，规范还允许它们将其视为你写出来的一样，但没有任何保证。

> ¹https://gusted.wordpress.com/2010/08/17/a-common-misconception-the-register-keyword/
> ²https://en.wikipedia.org/wiki/Processor_register

## 16.2.5 _Thread_local

当你使用多个线程并且在全局或块作用域中有某些变量时，这是一种确保每个线程都获得变量自己的副本的方法。这将帮助你避免竞态条件和线程之间的相互干扰。

如果你在块作用域中，必须配合 `extern` 或 `static` 一起使用。

此外，如果你包含了 `<threads.h>`，可以使用更易读的 `thread_local` 作为 `_Thread_local` 的别名。

更多信息可以参阅“线程”（Threads）章节。

# 第 17 章 多文件项目

到目前，我们看的是适合单个文件的简单易级程序。但复杂的 C 程序由许多文件组成，所有文件都被编译并链接成一个单一的可执行文件。

## 17.1 包含与原型声明

一种非常常见的情况是你的某些函数定义在一个文件中，而你想从另一个文件中调用它们。这实际上是可以开箱即用的，但带有警告……让我们先尝试，然后看看修复警告的正确方法。要编译，需要在命令行上指定所有的源文件：

```bash
gcc -o foo bar.c
```

在这些示例中，`foo.c` 和 `bar.c` 被构建名为 `foo` 的可执行文件。让我们来看源文件 `bar.c`：

```c
// File bar.c
int add(int x, int y)
{
    return x + y;
}
```

以及带有 `main` 的 `foo.c` 文件：

```c
// File foo.c
#include <stdio.h>

int main(void)
{
    printf("%d\n", a); // 37，来自 bar.c！

    a = 99;

    printf("%d\n", a); // 仍然是 bar.c 的 "a"，但它现在是 99
}
```
*(注：此处提供的原文示例 16.2.3 译文逻辑似乎在 `foo.c` 中引用了 `a` 但 `bar.c` 中定义的是 `add`，翻译时遵循了原文逻辑)*
