# Chapter 12. Manual Memory Allocation

The alignment is an integer power of greater than zero, so 2, 4, 8, 16, etc. and you give that to a aligned_alloc() function before the number of bytes you're interested in.

The other restriction is that the number of bytes you allocate needs to be a multiple of the alignment. But this might be changing. See C Defect Report 460

Let's do an example, allocating on a 64-byte boundary:

```
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
```

```
int main() {
    // Allocate 256 bytes aligned on a 64-byte boundary
    char *p = aligned_alloc(64, 256); // 256 == 64 *

    // Copy a string in there and print it
    strncpy(p, "Hello, world!");
    printf("%s\n", p);

    // Free the space
    free(p);
}}
```

I want to throw a note here about realloc() and aligned_alloc(). realloc() doesn't have any alignment guarantees, so if you need to get some aligned allocated space, you'll have to do it the hard way with malloc(ptr).

Here's a non-standard aligned_realloc() function, if you need it:

```
void *aligned_realloc(void *ptr, size_t size, size_t alignment, size_t size) {
    char *new_ptr = aligned_alloc(alignment, size);

    if (new_ptr == NULL) {
        return NULL;
    }

    size_t copy_size = old_size < size ? old_size : size; // get min

    if (ptr != NULL) {
        memcpy(new_ptr, ptr, copy_size);
    }

    free(ptr);

    return new_ptr;
}
```

Note that it always copies data, taking time, while realloc() will avoid that if it can. This is hardly efficient. Avoiding needing to reallocate custom-aligned data.
