# 9.2 Reading Text Files

Streams are largely categorized two different ways: text and binary.

Text streams are allowed to do significant translation of the data, most notably translations of newlines to their different representations¹. Text files are logically a sequence of lines separated by newlines. To be portable, your input data should always end with a newline.

But the general rule is that you're able to edit the file in the regular text editor, it's a text file. Otherwise, it's binary. More on binary later.

So let's get to—how we open a file for reading, and pull data out of it?

Let's create a file called hello.txt that has just this in it:

Hello, world!

And let's write a program to open the file, read a character out of it, and then close the file when we're done. That's the game plan!

```
#include <stdio.h>
{
    FILE *fp; // Variable to represent open file
    fp = fopen("hello.txt", "r"); // Open file for reading

    int c = getchar(fp); // Read a single character
    printf("%c\n", c);   // Print to stdout

    fclose(fp); // Close the file when done
}
```

To see how we opened the file with fopen(), it returned the FILE so we could use it later. (I'm leaving out for brevity, but fopen( ) will return NULL if something goes wrong, file-not-found, so you should really check it!)

Also notice that the "r" we passed means "open a text stream for reading". (There are various strings we can pass to fopen() with additional meaning, like writing, or printing, and so on.)

After that, we used the getchar() to get a character from the stream. You might be wondering why I've made a c instead of a char—that hold on!

Finally, we close the stream when we're done with it. All streams are automatically closed when the program exits, it's good and good housekeeping to explicitly close any files yourself when done with them.

The FILE keeps track of position in the file. Subsequent calls to getchar() would get the next character in the file, and then the next, until the end.
