```
#include <stdio.h>
#include <stddef.h>

struct foo {
int a;
char b;
int c;
char d;
};

int main(void) {
    printf("%%u\n", offsetof(struct foo, a));
    printf("%%u\n", offsetof(struct foo, b));
    printf("%%u\n", offsetof(struct foo, c));
    printf("%%u\n", offsetof(struct foo, d));
}
```

For me, this outputs:

+   0
4
8
12

indicating that we're using 4 bytes for each of the fields. It's a little weird, because char is only 1 byte, right? The compiler is putting 3 padding bytes after char so that all the fields are 4 bytes long. Presumably this will run on my CPU.

# 20.7 Fake OOP

There's a slightly obvious thing that's sort of OOP-like that you can do with structs.

Since the pointer to struct is the same as a pointer to the first element of the struct, you can freely cast a pointer to the struct to a pointer to the first element.

What this means is we can set up a situation like this:

```
struct parent {
int a, b;
};

struct child {
struct parent super; // MUST be first
int c, d;
}
```

Then we are able to pass a pointer to a struct child to a function that expects either that or a pointer to a struct parent!

Because parent super is the first item in the struct child, a pointer to any struct child is the same as a pointer to that super field.

Let's set up an example here. We'll make structs as above, but then we'll pass a pointer to a struct child to a function that needs a pointer to a struct parent... and it'll still work.

> super isn't a keyword, incidentally. I'm just stealing some OOP terminology.
