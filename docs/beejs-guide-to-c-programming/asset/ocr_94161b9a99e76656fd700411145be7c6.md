# 11.2 Array/Pointer Equivalence

We're finally ready to talk about this! We've seen plenty of examples of places where we've intermixed array notation, but let's get over the fundamental formula of array/pointer equivalence:

```
a[b] == (a + b)
```

Study that! Those equal and can be used interchangeably!

I've oversimplified it, because by overusing an example a and b both be expressions, and we might want a few more parentheses to force order of operations in case the expressions are complex.

The spec is specific, as always, declaring (in C1 §6.5.2.1):

```
E1[2] is identical to (*((E1)+2))
```

but that's a little harder to make you parentheses if the expressions are complicated so all your paths happen in the right.

This means we can decide if we're going to use array or pointer notation for array or pointer (assuming it points to an element of an array).

Let's use array and pointer with both array and pointer notation:

```
#include <stdio.h>

int main(void) {
    int a[] = {11, 22, 33, 44, 55};

    int *p = a; // p points to the first element of a, 11

    // Print all elements of the array a variety of ways:

    for (int i = 0; i < 5; i++)
        printf("%d\n", a[i]); // Array notation with a

    for (int i = 0; i < 5; i++)
        printf("%d\n", p[i]); // Array notation with p

    for (int i = 0; i < 5; i++)
        printf("%d\n", (a + i)); // Pointer notation with a a

    for (int i = 0; i < 5; i++)
        printf("%d\n", (*p + i)); // Moving pointer with p Moving variable a--ERROR!
}

```

So you can see that in general, if you have an array variable, you can use pointer or array notation to access elements. Same with a pointer variable.

The one big difference is that you can modify a pointer to point to a different address, but you can't do that with an array.
