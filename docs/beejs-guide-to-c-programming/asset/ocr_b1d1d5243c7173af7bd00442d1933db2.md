If you don't declare your function before use it (either with a prototype or its definition), you're performing something called an implicit declaration. This was allowed in the first C standard (C89), and that has rules about it, but is no longer allowed today. And there is no legitimate reason to rely on it in new code.

You notice something about the sample code we've been using... That is, we've using the good old printf() function without defining it or declaring a prototype! How do we get away with this lawlessness? We don't. Actually there is a prototype; it's in that header stdio.h that we included with #include, remember? We're still legit, officer!

# 4.3 Empty Parameter Lists

You might see this from time to time in older code, but you shouldn't ever code one in new code. Always use void to indicate that a function takes parameters. There's never' a reason to do this in modern code.

If you're good at just remembering to put void in empty parameter lists in functions and prototypes, you can skip the rest of this section.

There are two contexts for this:

+   - Omitting all parameters where the function is defined
- Omitting all parameters in a prototype

Let's look at a potential function definition:

```
void foo() // Should really have a `void` in there
{
  printf("Hello, world!\n");
}
```

While the spec spells out the behavior in this instance is as-if you'd indicated void (C11 §6.7.3 ¹14), the void type is there for a reason. Use it.

But in the case of a function prototype, there is a significant difference between using void and not:

```
void foo();
void foo(void); // Not the same!
```

Leaving out of the prototype indicates to the compiler that there is no additional information about the parameters to the function. It effectively turns off all that type checking.

With a prototype definitely use void when you have an empty parameter list.

> ¹Never say "never".
