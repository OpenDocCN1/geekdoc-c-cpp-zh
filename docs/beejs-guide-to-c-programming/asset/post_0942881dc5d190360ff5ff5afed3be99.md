## The C Preprocessor

Before your program gets compiled, it actually runs through a phase called preprocessing. It's almost like there's a language on top of the C language that runs first. And it outputs the C code, which then gets compiled.

We've already seen this to an extent with #include! That's the C Preprocessor! Where it sees a directive, it includes the named file right there, just as if you typed it in there. And the compiler builds the whole thing.

But it turns out it's a lot more powerful than just able to include things. You can define macros that are substituted... and even macros that make arguments!

### 19.1 #include

Let's start with what we've already seen a bunch. This is, of course, a way to include other sources in your source. Very commonly used header files.

While the spec allows for all kinds of behavior with #include, we're going to take a more pragmatic approach and talk about the way it works on every system I've ever seen.

We can split header files into two categories: system and local. Things that are built-in, stdio.h, stdlib.h, math.h, and so on, you can include with angle brackets:

```c
#include <stdio.h>
#include <stdlib.h>
```

Which, of course, implies that there must be a way to include local files from the current directory. And this is: with double quotes:

```c
#include "header.h"
```

Or you can very probably include in relative directories using forward slashes, and like this:

```c
#include "mydir/header.h"
#include "../someheader.py"
```

Don't use a backslash (\) for path separators in your #include! It's undefined behavior! Use forward slash (/) only, even on Windows.

In summary, use angle brackets (< >) for the system includes, and use double quotes (") for your personal includes.

### 19.2 Simple Macros

A macro is an identifier that expanded to another piece of code before the compiler even sees it. Think of it like a placeholder—when the preprocessor sees one of these identifiers, it replaces it with another value that you've defined.

Do this with #define (often read as "pound define"). Here's an example:

```c
#include <stdio.h>

#define HELLO "Hello, world"
#define PI 3.14159

int main(void)
{
    printf("%s, %f\n", HELLO, PI);
}
```

On lines 3 and 4 we defined a macros. Wherever these appear elsewhere in the code (line 8), they'll be substituted with the defined values.

From the compiler's perspective, it's exactly as if we'd written this, instead:

```c
#include <stdio.h>

int main(void)
{
    printf("%s, %f\n", "Hello, world", 3.14159);
}
```

See HELLO was replaced with "Hello, world" and PI was replaced with 3.14159? From the compiler's perspective, it's just like those values had appeared right there in the code. If the resulting C code is invalid, the compiler will puke.

Note that the macros don't have a specific type, per se. Really all that happens is they get replaced wholesale with whatever they're #defined as.

You can also define a macro with no value:

```c
#define EXTRA_HAPPY
```

in that case, the macro exists and is defined, but is defined to nothing. So also it occurs in the text will be replaced with nothing. We'll see some use for this later.

It's conventional to write macro names in ALL_CAPS even though that's not technically required.

Overall, this gives you a way to define constant values that are effectively global and can be used any place. Even in places where a constant variable won't work, e.g. in switch cases and fixed array lengths.

That said, the debate ranges online whether a typed const variable is better than #define macro in the general case.

It can also be used to replace or modify keywords, a concept completely foreign to const, though this practice should be used sparingly.

### 19.3 Conditional Compilation

It's possible to get the preprocessor to decide whether or not present certain blocks of code to the compiler, or just remove them entirely before compilation.

We do that by basically wrapping the code in conditional blocks, similar to if-else statements.

#### 19.3.1 Defined, #ifdef and #endif

First of all, let's try to compile code depending on whether or not a macro is even defined.

```c
#include <stdio.h>
```

```c
#define EXTRA_HAPPY

int main(void)
{
    #ifdef EXTRA_HAPPY
        printf("Im extra happy!\n");
    #endif

    printf("OK!\n");
}
```

In example, we define EXTRA_HAPPY (to nothing, but it is defined), then on line 8 we check if it is defined with an #ifdef directive. the subsequent code will be included until the #endif.

Because it is defined, the code will be included for compilation and the output will be:

I'm extra happy!
OK!

If we were to comment out the #define, like so:

```c
//define EXTRA_HAPPY
```

then it wouldn't be defined, the code wouldn't be included.
