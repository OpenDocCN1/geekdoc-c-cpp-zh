## 39.8.1 Condition Wait

There's a variant of cnd_wait() that allows you to specify a timeout so you can stop waiting.

Since the child thread must reload the mutex, this doesn't necessarily mean that you'll be popping back to the instant the timeout occurs; you must still wait for any other threads to release the mutex.

But it means that you won't be waiting until the cnd_signal() happens.

To make this work, call cnd_timed_wait() instead of cnd_wait(). If it returns the value thrd_timed, it timed out.

The timestamp is always in UTC, not a time-from-now. Frankly the timespec_get() function in <time.h> seems custom-made for this case.

```c
struct timeout timeout;
timespec_get(&current_time, TIME_UTC); // Get current time
current_time.tv_sec += 1; // Timeout 1 second after now
```

```c
int result = cnd_timed_wait(&condition, &mutex, &timeout);

if (result == thrd_timedout) {
    printf("Condition variable timed out!\n");
}
```

## 39.8.2 Broadcast: Wake Up Waiting Threads

cnd_signal() only wakes up one thread to continue working. Depending on how your logic does, it might make sense to wake up more than one thread to continue once the condition is met.

Of course only one of them can grab the mutex, but if you have a situation where:

- *The newly-woken thread is responsible for waking up the next one, and— there's a chance the spurious-wakeup loop condition will prevent it from doing so, then—*

you'll want to wake the up so that you're sure to get at least one of the threads out of loop to launch the next one.

How, you ask?

Simply use cnd_broadcast() instead of cnd_signal(). Exact same usage, except cnd_broadcast() wakes up all the threads that were waiting on condition variable.

## 39.9 Running a Function One Time

Let's say you have a function that could be run by many threads, but you don't know when, and it's not work to try with all logic.

There's a way around it: use call_once(). Tons of threads could try to run the function, but only the first one counts¹²

To work with this, you need a special flag variable you declare to keep track of whether or not the thing's been run. And you need a wrapper to run the function, which takes no parameters and returns no value.

once_flag of = ONCE_FLAG_INIT; // Initialize it like this

```c
void run_once_function(void)
{
    printf("I'll only run once!\n");
}

int run(void *arg)
{
    call_once(&of, run_once_function);
    // ...
}
```

In this example, no matter how many threads get to the run() function, the run_once_function() will only be called a single time.

## 40.1 Testing for Atomic

## 40.2 Atomic Variables

Here's how atomic variables work:

If you have a shared atomic variable and write to it from one thread, that will be all-or-nothing in different thread. It's almost like there is a lock around the getting and setting of one variable. (And there might be Lock-Free Atomic Variables, below.)

And on that note, you can get away without using atomics if you use mutexes to lock critical sections.
