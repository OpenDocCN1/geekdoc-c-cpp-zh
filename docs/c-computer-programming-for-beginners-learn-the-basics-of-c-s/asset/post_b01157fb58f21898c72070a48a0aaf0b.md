## Automatic Garbage Collector in C#

Both in C and C++, many objects require the programmer to allocate their resources once declared, before the objects can be used safely. Once the object has been used, releasing these resources back to the free memory pool is also the responsibility of a programmer. If the sources are not released, the code is said to leak memory, since more and more resources are consumed unnecessarily. On the other hand, if resources are released prematurely, loss of data, the corruption of the memory areas, and null pointer exception occur.

However, C# prevents these dangers by independently managing the lifetime of all objects in use by an application. In C#, garbage collection is handled by CLR (Common language runtime). The CLR garbage collector periodically checks the memory heap for any unreferenced objects and releases the resources held by these objects. In other words, the garbage collector serves as an automatic memory manager. It enables you to develop an application without having to free memory and provides memory safety by making sure that an object cannot use the content of another object.
