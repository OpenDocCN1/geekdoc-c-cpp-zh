various elements like methods, classes, enumerators, structures, assemblies etc. in a program is called attribute. By using an attribute you can add declarative information to a program. A declarative tag is depicted by square brackets ([[]]) placed above the element it is used for.

The attributes are used for adding metadata, as compiler instruction and other information such as description, comments, classes, methods to a program. There are two types of attributes which are provided by the .Net framework –

- Pre-defined attribute
- Custom built attribute

Syntax to specify an attribute is as follows –

```
[attribute(positional_parameters, name_parameter=value, ...)]
```

### Element

The values of an attribute and its name are specified within the square brackets, before the element to which the attribute is applied. The name parameters specify the optional information and the positional parameters specify the essential information.

There are three pre-defined attributes –

- a) Attribute usage - it describes how a custom attribute class can be used. Attribute usage specifies the types of items to which the attribute can be applied.
- b) Conditional – it marks a conditional method whose execution depends on a specified preprocessing identifier. It causes a conditional compilation of method calls, depending on the specified value such as Trace or debug. Example – it displays the values of the variables while debugging.
- c) Obsolete – it marks a program entity that should not be used. This pre-defined attribute enables you to inform the compiler to discard a particular target element. E.g. – when a new method is being used in a class but you still want to retain the old method in the class, you can mark it as obsolete by displaying a message that the new method should be used in place of the old one.

Creating custom attributes – The .Net framework allows creation of custom attributes that can be used to store declarative information that can be retrieved at run-time. Information can be related to any target element depending upon the design criteria and application need. (Tutorials Point)

# The Anonymous methods in C#

As described earlier, delegates are used to reference methods that have the same signature as that of a delegate. This means that you can call a method that can be referenced by a delegate using that delegate object.

The anonymous methods provide a technique to pass a code block as a delegate parameter. These are the methods that only have the body, but no name. You need to specify the return type in an anonymous method; it is inferred from the return statement inside the method body.

The anonymous methods are declared with the creation of the delegate instance, with a delegate keyword. Example for anonymous method is as follows –

```
delegate void NumberChanger(int n);
```

```
NumberChanger nc = delegate(int x)
{
    Console.WriteLine("Anonymous Method: {0}", x);
};
```

Here, the code block `Console.WriteLine("Anonymous Method: {0}", x);` is the body of anonymous method.

One of the programming features of C# is the Lambda expression. The Lambda expression is an anonymous method that you can use to create expression or delegate tree types. By using this expression, you can write local functions that can be passed as arguments or returned as the value of function calls. The Lambda expressions are particularly helpful for writing LINQ (language integrated query) expressions. The Language integrated part means that LINQ is part of programming language syntax and query explains what LINQ does i.e LINQ is used for querying data and C# has LINQ capabilities. LINQ can be used to query different types of data including relational, XML and even objects.

To create a Lambda expression, you need to specify input parameters (if any) on the left side of lambda operator =>. The statement block or the expression is put on the other side. Example -

```
x => x *
```

This lambda expression specifies a parameter that's named x and returns the value of x squared.

# The Unsafe Codes

Using of pointer variables in a function of code block when it is marked by the unsafe modifier is allowed in C#. The unsafe or unmanaged code is a code block that uses pointer variable.

### What is a pointer?

A pointer is a variable whose value is the address of another variable, which means the direct address of the memory location. Like any variable or constant, you must declare a pointer before you can use it to store any variable address. The typical form to declare a pointer is:

`type*var-name;`

You can retrieve the data stored at the located referenced by the pointer variable, by using the `ToString()` method.

(Yogesh Joshi, 2016)

### Accessing array elements using a pointer

An array name and a pointer to a data type same as the array data, are not the same variable type in C#. Example – `int[] jp` and `int *p` are not same type. Here, you can increment the pointer variable p because it is not fixed in memory, but an array address is fixed in memory, therefore you cannot increment that.

In order to access data using pointer variable, you need to fix the pointer using the fixed keyword. (Tutorials Point)

# C# Class library

The .Net framework is a huge library made of various classes, value types, interfaces that provide access to system functionality. It is the foundation on which .Net framework components, applications and controls are built. Most Visual C# development projects use the .Net Class library extensively for everything from file system access and string manipulation to Windows forms and XML parsing.

We are listing some commonly used namespaces and namespace categories in the class library here -

- 1. System - this namespace contains fundamental classes and base classes that define commonly-used value and reference data types, interfaces, event handlers, attributes and processing exceptions.
- 2. System.Activities – it contains all classes which are necessary to create and work with Windows Workflow Foundation.
- 3. System.Directory – this namespace contains types that provide access to Active Directory.
- 4. System.Collections – it contains types that define various specialized, standard and generic collection objects.
- 5. System.Diagnostics – it defines types that provide the ability to diagnose application. This includes performance counters, event logging, tracing and interaction with system processes.
- 6. System.AddIn – this namespace contain types used to identify, register, activate and control add-ins. It also allows to communicate with a host application.
- 7. System.Globalization – it defines types that define culture-related information, including country, region, language, calendars, currency, dates, numbers and sort order for strings.
- 8. System.CodeDom – this namespace contains classes that represent elements of a source code document. This supports the generation and compilation of source code in supported programming languages.
- 9. System.Security – it contains classes that represent the .Net framework security system and permissions.
- 10. System.IO – this namespace contains types that support input and output. It also includes the ability to read and write data to streams, compress data in streams, create and use isolated stores, map files to an application’s logical address space, control multiple data objects in a single container, communicate using anonymous or named pipes, implement custom logging and to handle the flow of data.
- 11. System.Threading – it defines types that enable multithreading programming. A child namespace provides types that simplify the work of writing concurrent and asynchronous code.
- 12. System.Text – it defines types that support various regular expressions, character encodings and a more efficient mechanism for manipulating strings.
- 13. System.Configuration – this namespace contains types for handling configuration data, such as data in application configuration files or machine.
- 14. System.Data – this namespace contains classes for accessing and managing data from diverse sources.
- 15. System.Drawing – this namespace contains types that support basic GDI+
