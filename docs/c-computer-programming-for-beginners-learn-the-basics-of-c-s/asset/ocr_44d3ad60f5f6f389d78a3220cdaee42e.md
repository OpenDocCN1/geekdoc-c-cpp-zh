# Assembly Versioning

An assembly is also called as the building block of .Net application. It is a basic unit of application deployment and versioning. An assembly is either an .exe or .dll file. An assembly structure consists of following parts –

+   1. Assembly manifest i.e. name, version and language
2. CIL code (logic part)
3. Type Information (Datatype)
4. Resources

Assembly versioning is a feature introduced in .Net recently. It allows two versions of the same component that exists in a single folder side-by-side and in a single machine. A version number is provided by the programmer and is not controlled by .Net software.

There are two types of assemblies –

+   1. Private assembly (.exe) - it can be used in a single application.
2. Shared assembly (or class library) (.dll) – it can be used in multiple applications.

# Preprocessor Directives

The preprocessor directives give instruction to the compiler to preprocess the information before the actual compilation starts. The preprocessor directives with #, and only white-space characters may appear before a preprocessor directive on a line. One should keep in mind that these directives are not statements; therefore they do not end with a semicolon. (Weber, 2016)

C# compiler does not have a separate preprocessor, but the directives are processed as if there was one. The preprocessor directives in C# are used to help in conditional compilation. A preprocessor directive must be the only instruction on a line.
