## Easy to use generics

The C# generics allow delaying the specification of the data type of programming elements in a method or a class until it is actually used in the program. This means generics allow you to write a method or class that can work with any data type. The specifications for the method or a class are written with substitute parameters for data types. When the compiler encounters a constructor for the function call for the method or a class, it generates code to handle the specific data type.

### Features of generics

Generics enrich your program in the following ways -

- 1. Generics help you to maximize reuse, performance and type safety.
- 2. It allows you to create generic collection classes. The .NET framework class library contains several new generic collection classes in the System.Collections.Generic namespace.
- 3. It allows you to create your own generic interfaces, methods, classes, delegates and events.
- 4. You may create generic classes constrained to enable access to methods on particular data types.
- 5. By means of reflection you may get information on the types used in a generic data type at run-time.

## Understanding Simple Multithreading

A thread is defined as the execution path of a program. It defines a unique flow of control. In your application involves complicated and time-consuming operations, then it is helpful to set different execution paths or threads, where each thread performs a particular job. One common example of the use of thread is an implementation of concurrent programming by modern operating systems. The use of threads increases the efficiency of an application and saves the wastage of CPU cycle.

To make a program execute more than one task at a time, it can be divided into smaller threads.

## Thread life cycle

The life cycle of a thread starts when an object of the System.Threading.Thread class is created and ends when the thread completes execution or is terminated. The various states in the lifecycle of a thread are –

- a) Unstarted state- this is the situation when the instance of the thread is created but the Start method is not called.
- b) Ready state – this is the situation when the thread is ready to run and waiting CPU cycle.
- c) Not Runable State – the thread is not executable when –
    - Wait method has been called
    - Sleep method has been called
    - Blocked by I/O operations
- d) Dead state – this is a situation when the thread completes execution or is aborted.

## Main Thread

The System.Threading.Thread class is used for working with threads in C#. It allows accessing and creating individual threads in a multithreaded application. The first thread to be executed in a process is called the main thread. The main thread is automatically created when a C# program starts executing. The threads using the Thread class are called as child threads of the main thread. A thread can be accessed using the CurrentThread property of thread class.

Creating threads – Threads are created by extending the thread class. Extended thread class then calls Start() method to begin the child thread execution. For example –

## Assembly Versioning

An assembly is also called as the building block of .Net application. It is a basic unit of application deployment and versioning. An assembly is either an .exe or .dll file. An assembly structure consists of following parts –

- 1. Assembly manifest i.e. name, version and language
- 2. CIL code (logic part)
- 3. Type Information (Datatype)
- 4. Resources

Assembly versioning is a feature introduced in .Net recently. It allows two versions of the same component that exists in a single folder side-by-side and in a single machine. A version number is provided by the programmer and is not controlled by .Net software.

There are two types of assemblies –

- 1. Private assembly (.exe) - it can be used in a single application.
- 2. Shared assembly (or class library) (.dll) – it can be used in multiple applications.

## Preprocessor Directives

The preprocessor directives give instruction to the compiler to preprocess the information before the actual compilation starts. The preprocessor directives with #, and only white-space characters may appear before a preprocessor directive on a line. One should keep in mind that these directives are not statements; therefore they do not end with a semicolon. (Weber, 2016)

C# compiler does not have a separate preprocessor, but the directives are processed as if there was one. The preprocessor directives in C# are used to help in conditional compilation. A preprocessor directive must be the only instruction on a line.

## Conditional Directives

The conditional directives are useful for testing a symbol or symbols to check if they evaluate to true. You can use #if directive to create a conditional directive. If they do evaluate to true, the compiler evaluates all code between #if and the next directive.

Syntax –

#if symbol [operator symbol]....

Here, symbol is the name of the symbol which you want to test. You can also prepend symbol or false with the negation operator. The operator symbol is used for evaluating the symbol. The operators could be either of the following –

* Equality (==)
* Inequality (!)
* And (&&)

Operators with parentheses can be used to group symbols.

These directives are used for compiling code for a debug build or when compiling for a specific configuration. A conditional directive beginning with #if must explicitly be terminated with a #endif directive. (Weber, 2016)
