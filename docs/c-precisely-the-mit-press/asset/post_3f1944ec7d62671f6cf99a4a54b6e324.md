## 5.2 Reference Types

A reference type is a class, an array type, or a delegate type. A class is defined by a class declaration (section 10), an interface is defined by an interface declaration (section 15), and a delegate type is defined by a delegate declaration (section 17). Array types are discussed in section 9.

A variable of reference type either contains the special value null or a reference to an object or delegate that is allocated in the heap. The special value null does not refer to anything. The constant null, denoting the null value, can have any reference type. Assigning a reference value to a variable assigns only the reference and does not copy the object or delegate pointed to.

Types are organized in a type hierarchy, as shown, with class Object as the base of all other types. The methods implemented by these types are inherited by their derived types.

Class Object is the base (superclass) of all classes. ol1 and ol2 are expressions of type Object:

- ol1.Equals(ol2) returns true if ol1 and ol2 are equal; otherwise by default. Default, values of reference type are equal by the same execution of new; but (for example) String overrides Equals to compare the string contents (section 7), and class ValueType Equals that two values of a type are equal if all their fields are equal.

- Object.ReferenceEquals(ol1, ol2) returns true if both ol1 and ol2 are null, or if both refer to the same object or delegate; otherwise false. False if any of ol1 or ol2 has a value type.

- Object.Equals(ol1, ol2) returns true if Object.ReferenceEquals(ol1, ol2) or ol1.Equals(ol2) does; otherwise false. This is insufficient for values of type that have been decomposed using ol1's method.

- ol1.GetType() returns the unique class of type that represents the run-time type of ol1.

- ol1.GetHashCode() returns a hash code for ol1 as an int, when ol1 is used as a key in a hash table (section 27). Subclasses override this method so that (1) if ol1 and ol2 are equal by Equals, then they have the same hash code; (2) modifications to ol1 do not change its hash code; (3) the hash code should be uniformly distributed; and (4) the method must be fast and not throw exceptions. All simple types and String have appropriate GetHashCode methods.

- ol1.ToString() returns a frequently used human-readable-sensitive representation of the object or reference type (section 7).

Class String is a subclass of Object and the base of all array types as int[].

Class ValueType is a subclass of Object and the base of all value types, including the simple types, the struct types, and the enum types. It is not itself a value type. If v1 and v2 have a struct type that derives from ValueType, then v1.Equals(v2) uses reflection to compare the fields of v1 and v2 using Equals. This can be slow, so struct types should override Equals. Any type that derives from ValueType is a value type.

Class Enum is a subclass of ValueType and the base of all enum types. It is not itself a value type.

Class Delegate is a subclass of Object and the base of all delegate types. It is not itself a value type.

## Example 8 Methods Declared in Class Object

The methods declared in class Object are inherited by all types and can be used on all values.

```csharp
Object ol1 = new Object();
Object ol2 = new Object();
Object ol3 = new Object();
ol1.Equals(ol2); // returns false
ol1.Equals(ol3); // returns false
Object.ReferenceEquals(ol1, ol2); // returns false
Object.ReferenceEquals(ol1, null); // returns false
Object.ReferenceEquals(null, null); // returns true
ol1.GetType(); // returns System.Object
ol1.GetHashCode(); // returns a hash code
ol1.ToString(); // returns "System.Object"
```
