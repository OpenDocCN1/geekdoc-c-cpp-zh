**Example 200** Declaration of a Generic Class
An object of generic class LinkedList<T> is a linked list whose elements have type T; it implements interface MyList<T> (example 205). The generic class declaration has a nested class, an indexer result type method, takes arguments of type T, an Equals(Object) method that checks its argument can be cast to MyList<T>, an Equals(MyList<T>) method, an explicit conversion of Array to LinkedList<T>, an overloaded operator (+) for concatenation, and methods that return enumerators. See also examples 209 and 222.

```sharp
public class LinkedList<T> : MyList<T> {
    protected int size;                // Number of elements in the list
    protected Node first, last;        // Invariant: first=null iff last=null
    protected class Node {
        public Node next;
        public T Item;
    }

    public LinkedList() { first = null; size = 0; }
    public LinkedList(params T[] elements) : this(elements) { ... }
    public int Count { get { return size; }}
    public T this[int i] { get { ... } set { ... }}
    public void Add(T item) { Insert(size, item); }
    public void Insert(int i, T item) { ... }
    public void Remove(int i) { ... }
    public override bool Equals(Object obj) { return Equals(obj as MyList<T>); }
    public bool Equals(MyList<T> other) { ... }
    public override int GetHashCode() { ... }
    public static LinkedList<T> from(T[] arr) { ... }
    public static LinkedList<T> operator +(LinkedList<T> xs1, LinkedList<T> xs2) { ... }
    public IEnumerator GetEnumerator() { return new LinkedListEnumerator<T>(this); }
    IEnumerator GetEnumerator() { return GetEnumerator(); }
}
```

**Example 201** Subclass Between Generic Classes and Interfaces
The constructed type Point<String> is implicitly convertible to IMovable, and both ColorPoint<String,int> and ColorPoint<String,Color> are implicitly convertible to Point<String> and IMovable.

```sharp
interface IMovable { void Move(int dx, int dy); };
class Point<Label> : IMovable {
    protected internal int x, y;
    private Label lab;
    public Point(int x, int y, Label lab) { this.x=x; this.lab = lab; }
    public void Move(int dx, int dy) { x += dx; y += dy; }
}
class ColorPoint<Label, Color> : Point<Label> {
    private Color c;
    public ColorPoint(int x, int y, Label lab, Color c) : base(x, y, lab) { ... }
}
```

# 26.4 Constraints on Type Parameters

A declaration of a generic class C<T1,...,Tn> may have type parameter constraints

```csharp
class-modifiers class C<T1,...,Tn> subtype-clause parameter-constraints
class-body
```

The parameter-constraints is a list of constraint-clauses, each of this form:

```csharp
where T : C1, C2, ..., Cm
```

In the constraint clause, T is one of the type parameters T1,...,Tn and each ci is a constraint. A given type parameter Ti can have at most one constraint clause; that may constrain one or more constraints C1, C2, ..., Cm. The order of the constraint clauses for T1,...,Tn does not matter.
A constraint c must have one of these four forms:

- c is a type expression: a non-sealed class or an interface or a type parameter. The expression may be constructed by a type and involve the type parameters T1,...,Tn and type parameters of enclosing generic classes and structs. An array or a type parameter that has a struct constraint cannot be used as a constraint. Nor can the Object, System.ValueType, System.Delegate, System.Array, System.Enum. At most one of the constraints on a type can be a class, and that constraint must appear first. There can be any number of constraints that are interfaces or type parameters.
- c is the special class constraint. This means that the type parameter must be instantiated by a reference type. The special class constraint can appear only first in a constraint list and cannot appear together with a class or with the special struct constraint.
- c is the special struct constraint. This means that the type parameter must be instantiated by a non-nullable value type: a simple type such as int, or a non-nullable struct type. The struct constraint can appear only first in a constraint list and cannot appear together with a constraint that is a class or with.
- c is the special new() constraint. This means that the type parameter must be instantiated by a type that has an argumentless constructor. If a type parameter has a struct constraint, it is guaranteed to have an argumentless constructor; in that case the new() constraint is redundant and illegal. 206 illustrates the use of the new() constraint

It is illegal for constraints to be circular as in class<T,U> where T : U : T {. The types T1,...,Tn used when constructing a type must satisfy the parameter-constraints; if parameter Ti is replaced by type Ti throughout the parameter-constraints, for each constraint t : c, where c is a type expression, it must hold that t is convertible to c by an implicit reference conversion or a boxing conversion.

# Example 204 The class and struct
Without the class constraint, type parameter T might be instantiated as a value type, and then null would not be legal. Conversely, without the struct constraint, type parameter U might be instantiated with a reference type.

```sharp
class CI<T> where T : class {
    T f = null; // Legal: T is a reference type
}
class D<U> where U : struct {
    U? f; // Legal: U is a nullable value type
}
```

# 26.5 Generic Interfaces
A declaration of a generic interface I<T1,...,Tn> has one of these forms:

```csharp
interface-modifiers I<T1,...,Tn> extends-clause
  interface-body
```

```csharp
interface-modifiers I<T1,...,Tn> extends-clause parameter-constraints
  interface-body
```

In both cases, the T1,...,Tn are type parameters for generic classes (section 26.3), and the interface-modifiers, extends-clause and interface-body are as non-generic interfaces (section 15.1). If present, the parameter-constraints are as for generic classes (section 26.4).

A type constructed from the generic interface has I<t1,...,tn>, where the t1,...,tn are types. The types t1,...,tn must satisfy the parameter-constraints, if any, on the generic interface I<T1,...,Tn>, as described in section 26.4.

The parameters of a generic interface can have covariance modifiers out and in (section 26.12).

# 26.6 How Can Type Parameters Be Used?
Within the body { ... } of a generic class C<T1,...,Tn> { ... } or generic interface or struct, a type parameter Ti may be used almost as if it were a public type.

- One can use type parameter Ti in the return type or parameter types of methods, operators, properties, anonymous delegates, and indexers; in the type of fields, variables and parameters; and in member classes, struct types and delegate types.
- One can use new Ti[10] to create an array whose element type is Ti; (o is Ti) to test whether o is an instance of Ti; (o as Ti) to test and cast to Ti; (Ti)e for types; Ti when constructing a type C<Ti> from a generic type; and Ti in a typeof expression such as typeof(Ti) or typeof(C<Ti>).
- One can use expression default(Ti) to obtain the default value for type Ti. This is the null reference when Ti is instantiated with a reference type, and an appropriate value (0, 0.0, false, a zero member, struct with default value fields) when Ti is instantiated with a value type.
- One can use new Ti() to create an instance of Ti only if there is a parameter constraint of the form Ti : new() on Ti; see section 26.4 and example 206.
- One cannot call static methods on a type parameter Ti, as in Ti.M().
