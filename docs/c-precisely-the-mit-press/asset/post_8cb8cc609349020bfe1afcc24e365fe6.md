### Example 217 Variance in Predefined Interfaces
Notable predefined interfaces with covariant type parameters are `IEnumerable<out T>` (section 27.2) because it only outputs values of T, and `IEnumerator<out T>` because it only outputs something that only outputs values of type T. Notable predefined interfaces with contravariant type parameters are the comparison interfaces (27.3) because they only input values of type.

```
interface IEnumerator<out T> { T Current { get; } ... }
interface IEnumerable<out T> { IEnumerator<T> GetEnumerator(); }
interface IComparable<in T> { int Compare(T v1, T v2); }
interface IComparable<in T> { int Compare(T v); ... }
interface IEquality<in T> { bool Equals(T v1, T v2); int GetHashCode(T v); }
interface IEquatable<in T> { bool Equals(T v); ... }
```

If Class is a subclass of Person, then `IEnumerable<Student>` is a subclass of `IEnumerable<Person>`. Whenever a stream of Person objects is expected, as in method `Persons`, a stream of Student objects can be used; and whenever a comparator of Student objects is expected, as in method `Sorted`, a comparator of Person objects can be used.

```class
class Person { ... }
class Student : Person { ... }
class PersonComparer : IComparer<Person> { ... }

static void PrintPersons(IEnumerable<Person> ps) { ... }
static bool Sorted(IComparable<Student> cmp, Student[] a) { ... }

Student[] students = { new Student("Daniel"), ... , new Student("Vincenzo") };
IEnumerable<Student> ss = students;
PrintPersons(ss);
PrintPersons(students);
bool sorted = Sorted(new PersonComparer(), students);
```

### Example 218 Variance in Predefined Delegate Types

The Func and action families of generic delegate types are contravariant (in) in their arguments and covariant (out) in their return types.

Let Student be a subclass of Person as in example 217, and let ColoredPoint be a subclass of Point as in example 147. `Func<Person,ColorPoint>` is a subtype of `Func<Point,Point>`. Whenever one expects a function from Student to Point, a function `pc` from Person to Color will do.

Also, `Func<Func<Student,Point>,int>` is a subtype of `Func<Func<Person,ColoredPoint>,int>`. When one expects a function `fpi` that takes a Person-to-ColoredPoint function to apply to `fpc`, it must be because there is a Person-to-ColoredPoint function to apply to `fpc, and there a function `fpi` that takes a Student-to-Point function will do instead.

```cs
Func<Person,ColoredPoint> pc = (Person p) => new ColoredPoint(2, p.name.Length, Color.Red);
Func<Student,Point> sp = pc;
Func<Func<Person,Point>,int> fpi = (Func<Student,Point> fsp) => fsp(new Student("Lise")).y;
Func<Func<Person,ColoredPoint>,int> fpc = fpi;
```

## 27 Generic Collections: Sets, Lists, and Dictionaries

System.Collections provides efficient, convenient, and type-safe data structures for representing collections of related data. These data structures include sets, lists, stacks, and dictionaries (also called maps). A list is an ordered sequence where elements can be added and removed at any position; a set is a collection without duplicates; a stack is an ordered sequence where elements are added and removed only at one end; a queue is an ordered sequence where elements are added at one end and removed at the other; a dictionary associates values with keys. The collection classes are not thread-safe; using the same collection instance from threads produces unpredictable results.

![](img/0895719d2f186cd73b49fccec3a97f1f_192_0.png)

### 27.1 The ICollection<T> Interface
The generic `ICollection<T>` extends `IEnumerable<T>` so that collection can be enumerated, and collections support query using extension methods (section 28.5) and LINQ syntax (28.1). In addition, `ICollection<T>` describes the following members:

- Read-only property `Count` returns the number of elements in the collection.
- Read-only `IsReadOnly` returns true if the collection is read-only and cannot be modified.
- `void Add(T x)` adds element `x` to the collection. Throws `NotSupportedException` if read-only.
- `void Clear()` removes all elements from the collection. Throws `NotSupportedException` if read-only.
- `bool Contains(T x)` returns true if `x` is in the collection; otherwise false.
- `void CopyTo(T[] arr, int i)` copies the collection to array `arr`, starting at index `i`. Throws `OutOfRangeException` if `i<0` and `ArgumentException` if `i+Count>arr.Length`.
- `bool Remove(T x)` removes an element `x` from the collection. Returns true if an element was removed, else false. Throws `NotSupportedException` if the collection is read-only.

### Choosing an Appropriate Collection Class
The running time or complexity of an operation on a collection is usually given in O notation, as a function of size of the collection. $O(1)$ means constant time, $O(\log n)$ means logarithmic time (time most proportional to the logarithm of $n$), and $O(n)$ means linear time (time most proportional to $n$). For adding, or removing an element, respectively, corresponds to very fast, slow in this case, $n$ is the number of elements in the collection and $i$ is an integer index. Removing an element of a List is fast only near the end of the list, where $n-i$ is small. The average time per operation indicates amortized complexity: $O(1)$ means any single operation could take $O(n)$. HashSet and Dictionary use hash (and therefore their operations have similar speeds), whereas SortedSet and SortedDictionary use element comparison.

## 27.2 Enumerators and Enumerables

### 27.2.1 The Enumerator and IEnumerator<T> Interfaces
An enumerator is an object that enumerates (produces) a stream of elements, such as the elements of a collection. A class or struct that has a method GetEnumerator with return type `IEnumerator<T>` can be used in a foreach statement (section 13.6.2). System.Collections.IEnumerator describes these members:

- Read-only `Object Current` returns the enumerator's current value. Throws `InvalidException` if the enumerator has not reached the first element or is past the last element.
- `bool Next()` advances the enumerator to the next (or first) element, if possible. Returns true if it succeeded so that `Current` is valid; false otherwise. Throws `InvalidOperationException` if the underlying collection has been modified since the enumerator was created.
- `void Reset()` resets the enumerator so that the next call to `Next()` will advance to the first element, if any. Throws `NotSupportedException` if not supported.

The generic interface `System.Collections.Generic.IEnumerator<T>` interfaces `IEnumerator` and `IDisposable` (section 13.10) and describes these members:

- Read-only `T` returns the enumerator's current value, or throws `InvalidException` if the enumerator has not reached the first element or is past the last element.
- `bool Next()` is just for `IEnumerator`.
- `void Dispose()` is called by the caller (for instance, a foreach statement) when the enumerator is no longer needed. It should release the resources held by the buffer. `Current` should throw `InvalidOperationException` and `Next()` should return false.

A type that implements `IEnumerator<T>` must also implement `IEnumerator`, using explicit interface member implementation (section 15.3) to declare the `Current` property value, as in example 222.

### 27.2.2 The IEnumerable and IIEnumerable<T> Interfaces
An enumerable is one that implements `IEnumerable` or `IIEnumerable<T>`. This means that it has a method `GetEnumerator` that can produce an enumerator (example 200). System.Collections.IEnumerator describes this method:

- `IEnumerator GetEnumerator()` returns a non-generic enumerator.

The generic interface `System.Collections.Generic.IIEnumerable<T>` describes this method:

- `IEnumerator<T> GetEnumerator()` returns a generic enumerator.
