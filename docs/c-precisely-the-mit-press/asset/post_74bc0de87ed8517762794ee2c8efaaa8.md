## Example 229 Simple Dictionary Operations

The indexer `dict[k]` throws `ArgumentException` when used to get the value of a key not in the dictionary. When used to set the value of a key, as in `dict[k]=`, it succeeds whether or not the key is in the dictionary already.

```csharp
Dictionary<String, int> dict = new Dictionary<String, int>();
dict.Add("Sweden", 46); dict.Add("Germany", 49);
dict["Japan"] = 81; // New entry, no exception
Console.WriteLine(dict.Keys); // Japan Germany
Console.WriteLine(dict.Count); // 3
Console.WriteLine("Greece"); // ArgumentException
dict.Add("Germany", 49); // ArgumentException
bool b1 = dict.Remove("Greece"); // False (but no exception)
bool b2 = dict.Remove("Japan"); // True
Console.WriteLine(dict.Keys); // Sweden Germany
bool b3 = dict.Contains("Germany"); // True
dict["Sweden"] = 45; // No exception
Console.WriteLine("Sweden"); // 45
```

## Example 230 Fast Set Membership Test: Use a Hash Set or Binary Search?

To exclude keywords (section 2) from the file index in example 225 would require a fast way to recognize names. Method `IsKeyword` uses a `HashSet` built from a 77-element array of C keywords, and method `IsKeyword2` binary search in the sorted array. The HashSet is more than ten times faster than the binary search in this case.

```csharp
static readonly string[] keywordarray = 
{ "abstract", "as", "base", "bool", "break", "byte", ..., "while" };
static readonly HashSet<string> keywords = new HashSet<string>();

static bool IsKeyword(string id) { return keywords.Contains(id); }
static bool IsKeyword2(string id) { return Array.BinarySearch(keywordarray, id) >= 0; }
```

## Example 231 Using a Set as a Key in Dictionary

The standard algorithm for turning a non-deterministic finite automaton (NFA) into a deterministic finite automaton (DFA) creates composite states that are sets of integers. It is preferable to replace composite types with integers. This method takes as argument a collection of composite states and returns a renamer, which maps a composite state to a `Set<int>` from example 226 providing element-based hash codes to a simple state name (an int).

```csharp
static Dictionary<Set<int>, int> MkRenamer(ICollection<Set<int>> states) {
    IDictionary<Set<int>, int> renamer = new Dictionary<Set<int>, int>();
    int count = 0;
    foreach (Set<int> k in states)
        renamer.Add(k, count++);
    return renamer;
}
```

# 27.10 The Queue<T> Class

An instance of `System.Collections.Generic.Queue<T>` is a queue, in which elements can be added at the end and removed from the front. This is useful for implementing worklist algorithms and breadth-first traversal. The queue is stored in an underlying array that is automatically extended as needed. Class `Queue<T>` implements `ICollection` and has the following additional members:

- *Constructor `Queue()` creates a new empty queue.*
- *Constructor `Queue(int capacity)` creates a new empty queue with the initial capacity.*
- *Constructor `Queue(IEnumerable<T> enm)` creates a new queue, enqueueing the elements produced by `enm.*
- `Dequeue()` returns and removes the element at the head of the queue. Throws `InvalidOperationException` if the queue is empty.
- `void Enqueue(T x)` adds element `x` at the end of the queue.
- `Peek()` returns the element at the head of the queue without removing it. Throws `InvalidOperationException` if the queue is empty.
- `T[]ToArray()` returns a new array containing the elements of the queue.
- `void TrimSize()` trims the underlying array to the actual number of elements in the queue.

# 27.11 The Stack<T> Class

An instance of `System.Collections.Generic.Stack<T>` is a stack, in which elements can be added and removed only one end, the stack top. This is useful for implementing worklist algorithms and depth-first traversal. The stack is stored in an underlying array that is automatically extended as needed. Class `Stack<T>` implements `ICollection<T>` and has the following additional members:

- *Constructor `Stack()` creates new empty stack.*
- *Constructor `Stack(int capacity)` creates a new empty stack with the initial capacity.*
- *Constructor `Stack(IEnumerable<T> enm)` creates a new stack, pushing the elements produced by `enm.*
- `Peek()` returns the element at the stack top without removing it. Throws `InvalidOperationException` if the stack is empty.
- `Pop()` returns and removes the element at the top of the stack. Throws `InvalidOperationException` if the stack is empty.
- `void Push(T x)` adds element `x` at the top of the stack.
- `T[]ToArray()` returns a new array containing the stack elements; the stack top is in position 0.
- `void TrimSize()` trims the underlying array to the actual number of elements in the stack.

## Example 232 Using a Queue in a Worklist Algorithm

Some algorithms use a worklist, represented by a queue, containing subproblems still to be solved. For instance, given a set $ss$ of sets, one can compute its intersection closure: the least set $tt$ that $ss$ is a subset of $tt$ and that for any two $s$ and $t$ in $tt$, their intersection $s \cap t$ is also in $tt$. For instance, if $ss$ is $\{\{2,3\}, \{1,3\}\}$, then $tt$ is $\{\{2,3\}, \{1\}, \{1,2\}, \{2\}, \{1\}, \{\}\}$.

The set may be computed by putting all elements of $ss$ in the worklist, repeatedly selecting an element from the worklist, adding it to $tt$, and for every set $t$ in $tt$, adding the intersection of $s$ and $t$ to $tt$ if not already in $tt$. When the worklist is empty, $tt$ is intersection-closed. Sets are represented using class `Set<T>` (see example 220).

```csharp
static Set<T> IntersectionClose<Set<T>>(ss) {
    Queue<Set<T>> worklist = new Queue<Set<T>>(ss);
    Set<Set<T>> tt = new Set<Set<T>>();
    while (worklist.Count != 0) {
        Set<T> s = worklist.Dequeue();
        foreach (Set<T> t in tt) {
            if (!tt.Contains(s))
                worklist.Enqueue(s);
        }
        tt.Add(s);
    }
    return tt;
}
```

## Example 233 Using a Queue or Stack for Graph Traversal

A Node<T> is a node in a graph with label. VisitthFirst() prints the labels of all nodes reachable from root in breadth-first order: Making Stack instead of Queue would give depth-first.

```csharp
public void VisitthFirst() {
    Dictionary<Node<T>, bool> visited = new Dictionary<Node<T>, bool>();
    Queue<Node<T>> worklist = new Queue<Node<T>>();
    visited.Add(root, false);
    worklist.Enqueue(root);
    while (worklist.Count != 0) {
        Node<T> node = worklist.Dequeue();
        Console.Write(" " + node.label);
        foreach (Node<T> neighbor in node.Neighbors) {
            if (!visited.ContainsKey(neighbor)) {
                visited.Add(neighbor, false);
                worklist.Enqueue(neighbor);
            }
        }
    }
}
```

# 28 Linq, Language Integrated Query (C# 3.0)

## Introduction

Linq, or Language Integrated Query, is a framework for declarative processing of collections of data, a general query language embedded in C#. The Linq query syntax (section 28.1) is syntactic sugar for calls to extension methods on appropriate interfaces, such as `IEnumerable<T>` (section 28.5) and `IQueryable<T>`. Thus the same Linq expression can be used on in-memory enumerables, in-memory XML data, relational databases, and even on user-defined data types.

### 28.1 Query Expressions

This section focuses on queries for enumerables, so that the streams xs and ys are enumerables. The queries could be made on relational databases, in which case xs and ys would be database tables, the result of previous queries. In any case, the result of a query implements at least `IEnumerable<T>` for some type and therefore may be enumerated using the `foreach` statement (section 13.6.2).

#### 28.1.1 Query Expressions

A query-expression must begin with the phrase `from x in xs ...` which introduces a range variable x that denotes a single item from the stream xs. There are two kinds of Link query expressions. The first kind of query-expression generates a stream of items, each obtained by evaluating expression e for each combination of range variables. The result has type `IEnumerable<>`, where t is the type of e:

```csharp
from x in xs
query-body-clauses
select e
```

The second kind of query-expression generates a group of items, where each group of those items (that is, value of e1) that have the same key (value of e2). The result has type `IEnumerable<Grouping<t2,t>>`, where t1 is the type of e1 and t2 is the type of e2:

```csharp
from x in xs
query-body-clauses
group e1 by e2
let y = e
where b
join y in ys on e1 equals e2
join y in ys on e1 equals e2 into z
orderby e1, e2, ...
```
