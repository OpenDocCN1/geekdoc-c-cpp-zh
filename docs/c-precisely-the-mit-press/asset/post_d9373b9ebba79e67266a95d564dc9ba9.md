## Example 20 Inherited Members Are Preferred over Members of Enclosing Types

The call M() in C calls method B.M() because members of C, even inherited ones, are preferred members of enclosing classes. If B.M() is private it is not inherited by C, and method E.M() is called instead. If, furthermore, B.M(int) is public, then C has an accessible method M(int) and so the members of enclosing classes are ignored, but B.M(int) is not applicable and the call M() is not legal.

```csharp
class B {
    public static void M() { Console.WriteLine("B.M"); }
    private static void M(int i) { Console.WriteLine("B.M(int)"); }
}
class E {
    static void M() { Console.WriteLine("E.M"); }
    static void M(int i) { Console.WriteLine("E.M(int)"); }
}
class C : B {
    public static void Main(String[] args) { M(); }
}
```

### 12.17.2 Method Call: Run-Time Parameter Passing By-Value, ref or out

This section and the next one cover the run-time evaluation of a method call M(actual-list) when it is clear that method M is called, and focuses on the parameter-passing mechanism.

The call is evaluated by evaluating the actual-list from left to right to obtain the argument values. These argument values are then associated with the corresponding parameters in the method's formal-list, in order of appearance.

A by-value argument is not marked ref or out. The type of a by-value argument must be implicitly convertible (section 5.3) to the type of the method's corresponding formal parameter. During execution of the method call, a copy of the converted value is bound to the formal parameter, which is similar to an initialized local variable. For formal parameters of type (simple types and structs) this means that if the method changes the value of the formal parameter, this does not affect the value of the argument expression. For parameters of reference type, this means the formal parameter refers to the same object or array as the argument, and any changes made by that object or array will be visible after the method returns (examples 94 and 96).

A ref argument must be a variable, a non-readonly field, or an array access a[i]; it must denote a storage location. The storage location must be definitively assigned before the call. The ref argument expression must be exactly the same as the method's corresponding formal parameter. During the method call, the method modifies the storage as the argument expression, so any assignment to the formal parameter immediately modifies the storage.

An out argument is very similar to a ref argument. The differences are that the out argument need not be definitely assigned before the call, and that every execution path in the method must definitely assign a value to the out formal parameter.

When the argument values have bound to the formal parameters, the method body is executed. If the method's return type is non-void, the value of the method call expression is the value returned by the method. If the method's return type is void, the method call expression has no value and cannot be used in an expression. When the method returns, all parameters and locals in the method are discarded.

### 12.17.3 Method Call: Parameter Arrays

The formal parameter list of a method, constructor, or indexer may end with a parameter array: a formal parameter of array type preceded by the params modifier (section 10.7). Assume that this parameter is declared as params t[]. In such a method, the actual arguments conforming to t can either be zero or more by-value parameters of type implicitly convertible to t, or an array that is implicitly de- t. In the former case, a new array t[] is allocated, the argument expressions are evaluated and converted, their converted values are stored in the array, and the formal parameter xs is bound to the newly created array.

For overloading resolution, an explicit overload such as Max(int, int) is preferred over an expansion of a formal parameter array as Max(int, params int[]). An expansion of a formal parameter array is preferred over a signature that requires an implicit conversion (examples 54 and 95).

### 12.17.4 Compile-Time Processing of Method Calls

All methods may be overloaded, and instance methods may be overridden. Overriding of virtual methods is handled by a run-time, based on the run-time class of the object (section 12.17.5).

#### Compile-Time Step 1: Find Candidate Methods

The first step is to find a set of candidate methods. The notion of a candidate method TT.M(sig) includes the TT that contains its name M, and its signature.

If the call has the form M(actual-list), the candidate methods are named in the enclosing class that (declares or inherits) a member M. Or if the member M in the enclosing class is not a method, then the call is illegal.

If the call has the form base.M(actual-list), the candidate methods are the non-private methods named M in the base class of the current.

If the call has the form C.M(actual-list), where C is a class or struct type, the candidate methods are the accessible methods M in C.

If the call has the form o.M(actual-list), where the compile-time type of expression o is a class or struct type, the candidate methods are the accessible methods M in the compile-time type of o.

If the call has the form o.M(actual-list), where the interface is an interface method call and is specially handled at run-time (section 12.17.5).

#### Compile-Time Step 2: Find Best Applicable Method

The second step is to find those candidate methods that are applicable and then to find the best (most specific) one of these methods.

A candidate method is applicable if its formal-list has the same length as the call's actual-list, corresponding positions agree on parameter passing (by-value or ref), and corresponding types have the same type, and for by-value positions there is an implicit conversion from the argument's type to the corresponding formal parameter's type at that position. In addition, a candidate method whose formal-list ends with a parameter array t[] xs is applicable if replacing the parameter array by zero or more by-value parameters of t would make it applicable, and if there is no call with the resulting signature.

Now consider the set of applicable candidate methods. If the set is empty, then the call is illegal (no such method). If is no best signature, or more than one best signature, then the call is illegal (ambiguous).

If the call is legal, there is exactly one best signature that identifies a method TT.M(sig) from a particular class TT with a particular signature sig. This is used for further processing of the method call at run-time (section 12.17.5).
