## Example 2 Scope of Fields, Parameters, and Variables

The field and the variables are labeled #1,...,#5 for reference only.

```csharp
void M1(int x) { // Declaration of parameter x (#1); shadows x (#5)
    x = ?; // x #1 in scope; legal, but no effect outside M1

    int x; // Declaration of variable x (#2); shadows x (#5)
    x = ?; // x #2 in scope
}
void M4() {
    int x; // x #5 in scope
    // Would be ILLEGAL, giving a new meaning to x
}
void M5() {
    int x; // Declaration of variable x (#3); shadows x (#5)
    x = ?; // x #3 in scope
{
        int x; // Declaration of variable x (#4); shadows x (#5)
        x = ?; // x #4 in scope
}
    public int x; // Declaration of field x (#5)
}
```

## Example 13 Definite Assignment
x is definitely assigned (#1) below because it gets assigned regardless of branch of the if statement is executed, but y is not, because it gets assigned only in one of the branches. Variable z is not definitely assigned (#3) because it will be assigned only if the body of the loop gets executed (and the compiler does not take the value of variables in loop conditions into account when determining that).

```csharp
int x, y, z;
if (args.Length == 0)
    x = 10;
else
    x = args.Length;
Console.WriteLine(x); // x definitely assigned, and z not (#1)
y = x;
for (int i=0; i<y; i++) // x and y definitely assigned, z not (#2)
    z = i;
Console.WriteLine(z); // z still not definitely assigned (#3)
```

# 6.3 Local var Declarations: Compile-Time Type Inference (C# 3.0)

The var keyword may be used in a local variable declaration (section 13.4) to tell the compiler that the type of the declared variable should be inferred from the given expression:

```csharp
var identifier = expression;
```

The expression (section 12) must have a compile-time type and hence cannot be an anonymous method (section 12.22), a lambda expression (section 12.23), or the null literal. The declared variable is inferred for the expression as if that type had been explicitly stated; subsequent uses of, assignments to, the value do not affect this type inference process. The variable remains statically typed as if the type had been explicitly given.

The var keyword may also be used in for statements (section 13.6.1), foreach statements (section 13.6.2), and using statements. It cannot be used for declaration of fields, method parameters, or return types; their types must be explicitly given. Var is not a keyword that declares a variable using compile-time type, also cannot be used in casts, as array element type, as type parameter in generic types, and so on.

# 6.4 The Type dynamic: Run-Time Resolution of Calls and More (C# 4.0)

With type dynamic, one can obtain behavior similar to that of dynamically programmed languages like C#, Groovy, Javascript (Script), Python, Ruby, Scheme, and others.

If an expression has dynamic type, then a method call, operator application, delegate call, or field access involving that expression will be resolved dynamically at run-time rather than at compile-time. This means that any such expression will be accepted by the compiler but may fail with an exception at run-time.

Whereas var is a keyword, dynamic is a type. Unlike var, dynamic can be used for fields, method parameters, and return types as well as constructed types such as `dynamic<T>`.

Run-time resolution of method calls, operator applications, delegate delegations, and field accesses produces exactly the same result as compile-time resolution. In cases where compile-time resolution fails (causing the compiler to reject the program), run-time resolution will instead throw an exception (RuntimeBinderException). Thus the runtime repeats the compiler's resolution machinery for this purpose. Since compile-time operations are moved to run-time, where they may be executed repeatedly, operations involving expressions of type dynamic are slower than those resolved at compile-time; in extreme cases, up to ten times slower. Nevertheless, run-time resolution is convenient when calling external dynamic applications such as Microsoft Excel or web browsers.

The run-time resolution machinery is the Dynamic Language Runtime which is actually a set of libraries built on top of the ordinary .NET runtime system.

More information and examples using type dynamic are found in sections 12.178 and 18.

# Example 15 Compile-Time Resolution and Checking of Operators, Assignments, and Field Accesses

```csharp
class Phone {
    public readonly String name;
    public readonly int phone;
    public Phone(String name, int phone) { ... }
}

var dl = 34;                 // Inferred type int
int i1 = (int)dl * 2;
int i2 = (int)dl * 2;        // Cast(int)dl succeeds at compile-time
bool b1 = dl;                // Rejected at compile-time
dl = true;                   // Rejected at compile-time
var pl = new Phone("Kasper", 5170);
String s1 = pl.name;          // Field access checked only at compile-time
int n1 = pl.phone;
var p2 = new {"Kasper", phone = 5170}; // OK: field access rejected at compile-time
String s2 = p2.name;          // Field access checked only at compile-time
int n2 = p2.page;            // Field access rejected at compile-time
```

# Example 16 Run-Time Resolution of Assignments and Field Accesses
Contrast this example with 15. For anonymous objects, see section 12.24.

```csharp
dynamic dl = 34;
int i1 = (int)dl * 2;         // OK: cast(int)dl * 2
int i2 = (int)dl * 2;        // OK: cast(int)dl succeeds at compile-time
bool b1 = dl;                // Rejected at compile-time
dl = true;                   // Rejected at compile-time
dynamic pl = new Phone("Kasper", 5170);
String s1 = pl.name;          // Field access checked only at compile-time
int n1 = pl.phone;
dynamic p2 = new {"Kasper", phone = 5170}; // OK: field access rejected at compile-time
String s2 = p2.name;          // Field access checked only at compile-time

```

# Strings

A string is an object of the predefined class String. The keyword string is an alias for System.String. A string constant is a sequence of characters within double quotes, such as "New York", "B5", or the empty string. Internally, a character is stored as a number, where 0–127 coincide with the ASCII encoding. String constants and character constants may use escape codes:

| Escape Code | Meaning |
| :--- | :--- |
| \a | Alert (bell) |
| \b | Backspace |
| \t | Horizontal tab |
| \v | Vertical tab |
| \n | New line |
| \f | Form feed (page break) |
| \r | Carriage return |
| \" | The double quote character |
| \' | The single quote character |
| \\ | The backslash character |
| \0 | The NUL character (ASCII or Unicode) |
| \x | The character whose code is the hexadecimal number d |
| \xd | The character whose code is the hexadecimal number dd |
| \xdd | The character whose code is the hexadecimal number ddd |
| \xddd | The character with the four-digit hexadecimal encoding dddd |
| \udddddd | The character with the eight-digit hexadecimal encoding dddddd |

A character escape sequence represents a single character. Since the letter A has code 65 (decimal), it is written 41 in hexadecimal, the string constant "A\x41\u0000041" is the same as "AAAA". \udddddd is used only in string constants, not in character constants.

A verbatim string is a string prefixed with the @ character. Any escape sequence in a string denotes itself, like ordinary characters, that """ denotes the double quote character. Let s1 and s2 be types of string:

- * s1.ToString() returns s itself, and somewhat surprisingly, so does s1.Clone(), whereas String.Copy(s1) produces a new object containing the same sequence of characters as s1.
- * s1.Length of type int is the length of s1, that is, number of characters in s1.
- * s1[i] of type char is the character at position i in s1, counting from 0. If the index is less than 0, or greater than s1.Length, the exception IndexOutOfRangeException is thrown.
- * s1.Equals(s2) of type bool is true if s1 and s2 are non-null and contain the same sequence of characters. Uppercase and lowercase characters are considered different.
- * s1 == s2 is true if s1 and s2 are null, or if both are non-null and s1.Equals(s2); and the inequality s1 != s2 has the same meaning as !(s1 == s2). Here s1 != """ is true when s1 is a non-empty string, also when s1 is null.
