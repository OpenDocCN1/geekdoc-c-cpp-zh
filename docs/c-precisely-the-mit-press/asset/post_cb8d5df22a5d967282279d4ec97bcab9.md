# Example 44 Class with Static and Instance Members

The APoint declares a static field allpoints and two instance fields x and y. Each APoint object has its x and y fields, but all objects share the same allpoints field in the APoint class.

The constructor inserts the new object (this) in the array list allpoints. The instance method GetIndex returns the point's index in the list. The static method GetSize returns the number of APoint objects created so far. Instead of the methods GetIndex and GetSize it would be natural to use an instance property and a static property (section 10.15 and example 66). The static method GetPoint returns the ith APoint in the list. The class is used in example 91.

Be aware that every APoint will be reachable from allpoints. This prevents automatic recycling (garbage collection) of APoint objects at run-time; objects should not be kept live unless there is a very good reason to do so.

```sharp
public class APoint {
    private static List<APoint> allpoints = new List<APoint>();
    private int x, y;
    public APoint(int x, int y) { allpoints.Add(this); this.x = x; this.y = y; }
    public void Move(int dx, int dy) { x += dx; dy += dy; }
    public override String toString() { return "(" + x + ", " + y + ")"; }
    public int GetIndex() { return allpoints.IndexOf(this); }
    public static int GetSize() { return allpoints.Count; }
    public static APoint GetPoint(int i) { return allpoints[i]; }
}
```

# 10.2 Class Modifiers abstract, sealed, static

If a class C declared sealed, it cannot be instantiated, but non-abstract subclasses of C can be instantiated. An abstract class may have constructors that can be called from constructors in subclasses, by means of base(...) calls, when instantiating non-abstract subclasses. An abstract class may declare abstract and non-abstract methods, by a non-abstract class cannot declare abstract methods.

If a class is declared sealed, it cannot declare subclasses of C, and hence cannot override or hide any methods declared in C. This is useful for preventing rogue subclasses by violating data representation invariants.

A class cannot be both abstract and sealed, so no objects of that class could be created. However, a class may be declared static, in which case it has only static members, and no instances can be created from it. This is used for declaring utility classes such as System.Math and for declaring extension methods (section 10.9).

# 10.3 Member Access Modifiers private, protected, internal, public

A member (data, function, or type) is accessible in the class in which it is declared, except where shadowed by a variable or parameter of member, or by a member of a nested class or struct. The following access modifiers may be used to make the member accessible elsewhere. The following access modifiers are legal (in a class declaration or a struct type declaration):

| Member Modifier | Accessible With | In |
| --- | --- | --- |
| private or absent | This class or struct | private |
| internal | This assembly | internal |
| protected | This class + subclasses | C-protected |
| protected internal | This assembly + this class's | protected internal |
| public | Everywhere | public |

The modifiers protected and internal can be used on members of a class but not on members of a struct (section 14) because the latter cannot have subclasses. All members of an interface (section 15) are implicitly public, and only the public access modifier may, but need not, be.

- If a member is declared private in class C, it is accessible in C and its nested classes and struct types, but not in its subclasses or other classes.
- A member without an explicit access modifier is private.
- If a member is declared internal, then it is accessible everywhere C is, but only within the same assembly as C (section 1.1).
- If a member is declared protected, then it is accessible in subclasses of C.
- If a member is declared protected internal, then it is accessible everywhere C is, but within the same assembly as C, and in subclasses of C. (This is similar to Java's notion of a protected member).
- If a member is declared public, then it is accessible everywhere C is, also in other assemblies.

**Example 45** Classes, Subclasses, and Overriding
The abstract class Vessel the concept of a vessel for holding liquids: its field contents represents its actual contents, the abstract method Capacity computes its maximal capacity, and method Fill fills in more, but only up to its capacity; the abstract class Tank (a rectangular vessel), Cube (a cubic vessel, subclass of Tank) and Barrel (a cylindrical vessel). The subclasses implement the Capacity method; they inherit the field and the Fill method from the base class, and they override the toString method (inherited from class Object) to format each vessel object.

```sharp
public abstract class Vessel {
    private double contents;
    public abstract double Capacity();
    public void Fill(double amount) {
        if (amount + contents <= Capacity()) contents += amount;
        else contents = Capacity();
    }
    public override String toString() { return "(" + contents + ")"; }
}

public class Tank : Vessel {
    protected double length, width, height;
    public Tank(double length, double width, double height) {
        this.length = length; this.width = width; this.height = height;
    }
    public override double Capacity() { return length * width * height; }
    public override String toString() { return "tank(" + base.toString() + ")"; }
}

public class Cube : Tank {
    private double side;
    public Cube(double side) : base(side, side, side) { this.side = side; }
    public override double Capacity() { return side * side * side; }
    public override String toString() { return "cube(" + base.toString() + ")"; }
}

public class Barrel : Vessel {
    private protected double radius, height;
    public Barrel(double radius, double height) : base(0, 0, height) {
        this.radius = radius; this.height = height;
    }
    public override double Capacity() { return Math.PI * radius * radius * height; }
    public override String toString() { return "barrel(" + base.toString() + ")"; }
}
```

# 10.4 Subclass, Base, Inheritance, and Hiding
The declaration of a class C may explicitly declare its base B, using a base-clause: where B is a class. Then C is said to be derived from B. If class C does not explicitly declare its base class, it is a subclass of Object. Class C inherits all non-private members except constructors (section 15.2). A class can have at most one immediate base class. The predefined class Object has no base class. A constructor (section 10.11) in subclass C may be declared to explicitly call a particular constructor in base class, using this syntax:

```sharp
constructor-modifier C(formal-list) : base(actual-list)
constructor-body
```

If a constructor(...) in subclass C does not explicitly declare base(...) this way, then it implicitly calls the default constructor B() in base class as its first action, as if base(...). In this case B must have a nonargumentless constructor B(). Conversely, if there is no argumentless constructor in B, then a constructor(...) in C must use base(...) to explicitly call another constructor in B. A method declaration in C may override any non-sealed virtual M inherited from B by declaring method M with the exact same signature. An overridden method M can be referred to as base.M inside C's instance constructors and instance methods. The overriding method M in C must be at least accessible as the overridden method in B.

However, the declaration of a class C cannot redeclare a field f inherited from B, only hide it and declare an additional field of the same name (section 10.5). The hidden field B can be referred to as base.f inside's instance constructors and instance methods.

A declaration in C may hide members inherited from the base class B. Example 55 illustrates the difference between overriding and hiding for methods. The hiding method in C should have the modifier new, otherwise a compiler warning is given.
