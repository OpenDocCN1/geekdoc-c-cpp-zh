# 12.17.4 Compile-Time Processing of Method Calls

All methods may be overloaded, and instance methods may be overridden. Overloading is resolved at compile-time by finding the best method signature among the applicable for the call's signature. Overriding of virtual methods is handled by a run-time search, based on the run-time class of the object on which the instance method is called (section 12.17.5).

# Compile-Time Step 1: Find Candidate Methods

The first step is to find a set of candidate methods. The notion of a candidate method TT.M(sig) includes the TT that contains its declaration, its name M, and its signature sig.

If the call has the form M(actual-list), the candidate methods are named M in the innermost enclosing class that (declares or inherits) a member name M. Or if the member M in the innermost enclosing class is not a method, then the call is illegal.

If the call has the form base.M(actual-list), the candidate methods are the non-private methods named M in the base class of the current class.

If the call has the form C.M(actual-list), where C is a class or struct type, the candidate methods are the accessible methods M in C M.

If the call has the form o.M(actual-list), where the compile-time type of expression o is a class or struct type, the candidate methods are the accessible methods M in the compile-time type of expression o.

If the call has the form o.M(actual-list), where the interface is an interface method call and is specially handled at run-time (section 12.17.5).

# Compile-Time Step 2: Find Best Applicable Method

The second step is to find those candidate methods that are applicable and then to find the best (most specific) one of these methods.

A candidate method is applicable if its formal-list has the same length as the call's actual-list, corresponding positions agree on parameter passing (by-value or ref), and corresponding types have the same type, and for by-value positions there is an implicit conversion from the argument's type to the corresponding formal parameter's type at that position. In addition, a candidate method whose formal-list ends with a parameter array t[] xs is applicable if replacing the parameter array by zero or more by-value parameters of t would make it applicable, and if there is no call with the resulting signature already.

Now consider the set of applicable candidate methods. If the set is empty, then the call is illegal (no such method). If is no best signature, or more than one best signature, then the call is illegal (ambiguous).

If the call is legal, there is exactly one best signature that identifies a method TT.M(sig) from a particular class TT with a particular signature sig. This is used for further processing of the method call at run-time (section 12.17.5).
