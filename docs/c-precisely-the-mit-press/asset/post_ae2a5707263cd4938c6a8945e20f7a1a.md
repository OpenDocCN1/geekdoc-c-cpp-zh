### Example 64 An Enumerator as a Member Class
The member class SeqEnumerator, declared inside struct Seq (example 68), can enumerate the elements of a sequence. To support the foreach statement (section 13.6.2), the SeqEnumerator class must have a property Current to get the current sequence element and a method Next to move to the next one. If it has methods Dispose and Reset, it can implement interfaces IEnumerator and IEnumerator<T> explicit member implementation (section 15.3) of Current with return type Object is needed for the non-generic IEnumerator. The yield return statement provides a radically simpler implementation of enumerators (section 13.12 and example 140).

```cs
private class SeqEnumerator : IEnumerator {
    private readonly Seq seq;
    private int i;
    public SeqEnumerator(Seq seq) { this.seq = seq; Reset(); }
    public int Current {
        // For IEnumerator<int>
        get {
            if (0 < i && i < seq.n)
                return seq.b + seq.k * i;
            else
                throw new InvalidOperationException();
        }
    }
    object SC.Current { return Current(); } // For IEnumerator
    public bool Next() {
        return ++i < seq.n;
    }
    public void Reset() { i = -1; } // For IEnumerator
    public void Dispose() { } // For IEnumerator<int>
}
```

### Example 65 Nested Classes Can Access All Static Members of Enclosing Class
The nested class C.D can access all static members of the enclosing class C, even private ones, as well as non-private static members of the base class B of the enclosing class. The enclosing class cannot access the private members of a nested class C.D.

```cs
class B {
    protected static int bx = 10;
    private static int bz = 10;
}
class C : B {
    private static int cx = 11;
    public class D {
        private static int dx = bx + cx; // Can access protected bx and private cx
        // public static int dz = bz + 2; // Cannot access private bz in base class
    }
    static void m() {
        int z = D.dx; // Cannot access private dx in nested class
    }
}
```

## 10.15 Property Declarations

A property is used to get or set a value, using notations C.P and o.P and C.P=e and o.P=e similar to those for accessing or assigning a static instance field (section 12.18). Properties provide controlled access to private fields. A property may be read-only or write-only, as it defines only a get-accessor or a set-accessor or both. A declaration of the property P has the form

```cs
method-modifiers t P {
    get-body
    set-body
}
```

The get-accessor or set-accessor, but not both, may be left out. The type cannot be void. The method-modifiers are in section 10.7. A get-body is a block-statement that does not return a value of type. A set-body is a block-statement that is executed when an assignment P=e is performed, and can use the variable value of type t, which initializes the value of e.

The get-accessor of a property P of type t is a method get_P(), the set-accessor is a method void set_P(t value), and the accessors follow the restrictions imposed on them. For instance, the get-body and set-body of an abstract property must consist of a semicolon; only one class can declare any of properties with different names. Properties cannot be overloaded.

It is common to declare a private field with a corresponding public get-property (such as Count in example 66), so that the field can be read but not written outside the class. An automatically implemented property (C# 3.0) declares a property P by a hidden field (examples 82 and 83).

```cs
field-modifiers t P { access-modifier get; access-modifier set; }
```

## 10.16 Indexer Declarations

An indexer is used to get or set a value, using notations C[i] and C[i]=e or similar to those for accessing or assigning an array element (section 12.19). Indexers provide controlled access to elements of collections. An indexer may be read-only or write-only or read-write, as it defines a get-accessor or a set-accessor or both. A declaration of an indexer has the form

```cs
indexer-modifiers this[formal-list] {
    get-body
    set-body
}
```

The get-accessor or set-accessor, but not both, may be left out. The indexer-modifiers is a list of modifiers abstract, extend, a legal combination of override, sealed, and virtual (section 10.8), and a legal combination of access modifiers (section 10.3). An indexer cannot be static. The type cannot be void. The formal-list is a block-statement that must be non-empty and can include ref or out-parameters. A get-body is a block-statement that must return a value of type t; it can use the parameters in the formal-list. A set-body is a block-statement that must return a value of t. It can use the parameters in the formal-list and the variable value of type t that holds the value passed to the indexer in an assignment.

The accessors of an indexer are get_Item(t value, formal-list) and void set_Item(t value, formal-list). Indexers can be overloaded and may have different return types (example 149).

### Example 66 Property Used to Access a Log
Class Log implements a simple log that stores the SIZE strings written to it. The static property InstanceCount is the total number of Log objects created. Property Count is the number of log entries written to this log. Property Last is the latest string logged to this log. It has a set- as well as get-accessors, so one can use assignment operators over log.Last += "...". All returns an array of the (up to) SIZE strings created. Example 103 uses these properties. Example 199 shows how to declare automatically implemented properties Count and InstanceCount instead.

```cs
public class Log {
    private static int instanceCount = 0;
    private int count = 0;
    private String[] log = new String[SIZE];
    public Log() { instanceCount++; }
    public static int InstanceCount { get { return instanceCount; }}
    public void Add(String msg) { log[count++ % SIZE] = msg; }
    public int Count { get { return count; }
    public String Last {
        get { // Returns the last log entry, or null if not logged yet
            return count==0 ? null : log[(count-1)%SIZE];
        }
        set { // Updates the log entry, or creates one if not logged yet
            if (count==0)
                log[count++] = value;
            else
                log[(count-1)%SIZE] = value;
        }
    }
    public String[] All { ... }
}
```

### Example 67 Sparse Matrix Indexing
A sparse matrix has many zeros. A sparse matrix may be represented as an array of columns, where each column is an array list (section 27.6) of only the non-zero elements. Using a two-argument index, one can get and set its elements as A[i,j], as if it were one rectangular array. The indexer performs a linear search of column j for the element index i; this may surprise users because the array-like notation suggests constant time.

```cs
public double this(int i, int j) {
    get {
        List<double> col = this[j];
        int k = 0;
        while (k < col.Count && col[k] != i)
            k++;
        return k < col.Count ? col[k] : 0.0;
    }
    set { ... }
}
```

## 10.17 Operator Overloading
Some of the operators listed on page 61 can be overloaded in a user-defined type (class or struct) t. No operator symbols can be defined, and the precedence of existing operators cannot be changed. An operator declaration must have one of these forms, as the operator is binary or unary:

```cs
public static returype operator operator-symbol(formal, formal)
method-body
```

```cs
public static returype operator operator-symbol(formal)
method-body
```

The returype cannot be void. The operator is an overloadable operator. The formal parameters are as for a method declaration (section 10.7) but cannot be ref or out. The method-body is in section 10.7. A class inherits the operator declarations of its base class. A struct cannot contain two operator declarations with the same signature. An operator declaration must follow these rules:

- When overloading a binary operator + - / & | ^ != > <= in t, at least one argument must have type t. When overloading a shift operator << >>, the first argument must have type t and the second argument have type int.
- When overloading a unary operator in type t, these arguments and result are permitted:

| Operators | Argument Type | Result Type |
| --- | --- | --- |
| + - | t | Any |
| ++ -- | t | t |
| true false | | bool |

- There can be only one definition of the unary increment (++) and decrement (--) operators in a type. The same definition is used for prefix (++x) as well as postfix (x++) applications.
- Some operators go together in pairs; either none of them or both must be overloaded:

| Operator | Operator | Comment |
| --- | --- | --- |
| true false | | |
| == != | Methods Equals and GetHashCode must be overridden also |
| < | | |
| <= >= | |

- When a binary operator (say, +) is overloaded, the corresponding assignment operator (+=) is automatically overloaded also (example 145).
- A compound assignment operator (such as +=) can be overloaded only by overloading the corresponding binary operator (such as +).
- When any of the operators & or | is overloaded, the operators true and false must be overloaded also, and the corresponding sequential conditional && || is automatically overloaded.

Operator overloading is illustrated by examples 68, 145, and 200.
