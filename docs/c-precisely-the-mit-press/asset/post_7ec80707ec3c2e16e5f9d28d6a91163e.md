## Example 241 Linq orderby Clause
Using xs and ys from example 234, the first orderby example here causes select to process the x in decreasing order. The second orderby example here causes select to process the pairs (x, y) in order of (primarily) decreasing x and (secondarily) decreasing length of the string y.

```csharp
Show(from x in xs // 25 9
    orderby x descending
    select x);
Show(xs.OrderByDescending(x => x).Select(x => x*));
```

```csharp
Show(from x in xs // { x=5, y=C } { x=5, y=BB } ... { x=2, y=BA }
    from y in ys
    orderby x descending, y.Length
    select new { x, y });
Show(xs.SelectMany(x => ys, (x, y) => new { x, y }
    .OrderByDescending(xy => xy.x)
    .ThenBy(xy => xy.y.Length)
    .Select(xy => xy.x));
```

## Example 242 Left Outer Join in Linq
An inner join (example 240), leaves out items on the left that do not have a matching y on the right. A left join, by contrast, includes also items x and can be computed by a combination of join into the DefaultEmpty (section 28.5).

```csharp
Show(from x in xs // { x=2, z=C } { x=3, z=BB } { x=3, z=BA } { x=5, z=null }
    join y in ys on x-1 equals y into zs
    from z in zs.DefaultEmpty()
    select new { x, z });
Show(xs.GroupJoin(ys, x => x-1, y => y.Length, (x, zs) => new { x, zs }
    .SelectMany(zs => zs.DefaultEmpty(), (x, z) => new { x.x, z, z }));
```

## Example 243 Continuity, to the Into Clause
As in 234, the first two lines of the query create a stream containing groups, where the first group has 2 and two members (4, 25), and the second group has 0 and one member (9). The query continuation into g binds each group in range variable g is g.Key. The members of the group are available by enumeration over g, which is itself a non-empty sequence.

```csharp
Show(from x in xs // 20
    group x*x by x%3
    into g
    select g.Key);
Show(xs.GroupBy(x => x*x, x => x*x).Select(g => g.Key));
```

## 28.3 Differences between Linq and SQL

A Linq query select ... is rather similar to a SQL query select from ..., but one cannot use *, and some operations that are expressed as part of an SQL query must be expressed in Linq by calling a method on a result:

- Instead of SQL's SELECT COUNT(*) FROM ..., in Linq use (from select ...).Count(). Similarly, instead of the other SQL aggregation functions AVG, MAX, MIN, and SUM, Linq extension methods Average(), Max(), Min(), and Sum(), described in section 28.6.
- Instead of SQL's DISTINCT(...) FROM ..., in Linq use (from select ...).Distinct().
- Instead of SQL's UNION (SELECT ...) UNION (SELECT ...), in Linq use (from ...).Union(from select ...).
Similarly, instead of SQL's EXCEPT and intersect operators, Linq extension methods Except and Intersect.
- Instead of SQL's HAVING operator, group ... by ... int g where ...

## 28.4 Auxiliary Interfaces That Support Linq (C# 3.0)

Enumerables support Linq queries because the interface IEnumerable<T> implements the query pattern (section 27.2) via its extension methods (methods 28.5). The Gp<K,T> and O<T> parts of the query expression are implemented by two additional interfaces, IGrouping<K,T> and IOrderedEnumerable<T>.

IGrouping<K,T> in namespace System.Linq extends IEnumerable<T> and is used to represent a group of items. Extension methods such as GroupBy produce an enumerable of IGrouping<K,T> objects (section 28.5). An IGrouping<K,T> supports enumeration of its items because it derives from IEnumerable<T>, and in addition it can return the group's key:

- Read-only property Key returns the group's key.

ILookup<K,T> in namespace System.Linq extends IEnumerable<IGrouping<K,T>> and represents a collection of groups of items. The interface derives from IGrouping<K,T> and supports all the methods defined on it. In addition an ILookup<K,T> can retrieve a group by well as the number of groups:

- Read-only indexer IEnumerable<T> this[K key] returns an enumerable generating the items in the group with key k.
- Read-only property Count returns the number of groups.

IOrderedEnumerable<T> in namespace System.Linq extends IEnumerable<T> and represents an ordered enumerable: one in which the items have been ordered by one or more criteria. The interface derives from IEnumerable<T> and supports all the extension methods defined on interface. Application of further orderings (via extension methods) ThenBy and ThenDescending; see section 28.7) respects the ordering already applied.

```csharp
Console.WriteLine((from x in xs select x*x)); // 12.66666666666667
Console.WriteLine((from x in xs select x*x).Sum()); // 38
Console.WriteLine((from x in xs select x*x).Max()); // 25
Console.WriteLine((from x in xs select x*x).Min()); // 4
Console.WriteLine((from x in xs select x*x).Count()); // 3
Console.WriteLine((from y in ys select y).Max()); // C
Console.WriteLine((from y in ys select y).Min()); // BA
```

## Example 245 Query Continuation with Filtering: SQL HAVING
As in 243, the groups are bound to range variable g. Here, in addition, the groups are filtered on size to discard groups.

```csharp
Show(from x in xs // 2
    group x by
    into g
    where g.Count() > 1
    select g.Key);
```

## Example 247 Combining groups
This example shows how to combine multiple groups into a single result.

```csharp
Show(from x in xs
    group x by x%3 into g1
    from y in ys
    group y by y%3 into g2
    select new { g1, g2 });
```

## Example 248 Group Joining
This example shows how to join two groups based on a common key.

```csharp
Show(from x in xs
    group x by x%3 into g1
    from y in ys
    group y by y%3 into g2
    join k1 in g1.Key from k2 in g2.Key on k1 == k2
    select new { g1, g2 });
```

## Example 249 Flattening groups
This example shows how to flatten a group into a sequence.

```csharp
Show(from x in xs
    group x by x%3 into g
    from item in g
    select item);
```

## Example 250 Projecting groups
This example shows how to project each group into an object.

```csharp
Show(from x in xs
    group x by x%3 into g
    select new { Key = g.Key, Count = g.Count() });
```
