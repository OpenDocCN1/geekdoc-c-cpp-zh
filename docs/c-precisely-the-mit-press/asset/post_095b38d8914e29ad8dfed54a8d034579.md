## Example 166 Producers and Consumers Communicating via a Monitor

A buffer has room for integer, and a method Put for storing into the buffer (if empty) and a method Get for reading from the buffer (if non-empty); it is a monitor (section 21.2). A thread calling Get must obtain the lock on the buffer. If it finds that the buffer is empty, it calls Wait to release the lock and wait until something has been put into the buffer. If another thread calls Put and Pulse, then the getting thread will start competing for the buffer lock again, and if it gets it, will continue executing.

```csharp
class Buffer {
    private int contents;
    private bool empty = true;
    public int get() {
        lock (this);
        while (empty) Monitor.Wait(this);
        empty = true;
        Monitor.Pulse(this);
        return contents;
    }
    public void Put(int v) {
        lock (this);
        while (!empty) Monitor.Wait(this);
        empty = false; contents = v;
        Monitor.Pulse(this);
    }
}
```

## Example 167 Deadlock

Careless locking of more than one object can cause deadlock. Assume that there are one left shoe and one right shoe (two objects) and two people (threads) want to use them. First one person, the pair of shoes. But if two shoes are created by new Person("groucho", left, right) and new Person("harpo", right, left), then the first person may lock the left shoe, and the second person may lock the right one, and then both wait forever for the other shoe. This is avoided by always locking the objects in the same fixed order (instance, before right).

```csharp
class Person {
    String name, fst, snd;
    public Person(String name, String fst, String snd) {
        this.name = name; this.fst = fst; this.snd = snd;
        new Thread(new ThreadStart(Run)).Start();
    }
    public void Run() {
        lock (this);
        Console.WriteLine(name + " got " + fst);
        Thread.Sleep(0); // Yields to other threads
        lock (snd) { Console.WriteLine(name + " got " + snd);
            Console.WriteLine(name + " released " + snd);
        }
        Console.WriteLine(name + " released " + fst);
    }
}
```

## 22 Task Parallel Library (C# 4.0)

The Task Parallel Library is implemented by several types in namespace System.Threading.Tasks.

### 22.1 Class Parallel

Static class Parallel in namespace System.Threading.Tasks:

- * staticParallelLoopResult For(int m, int n, Action<int> body) executes body(m), body(m+1),....(n-1), possibly concurrently and out of order. Blocks until all calls complete; does nothing if m>=n.
- * staticParallelLoopResult For(int m, int n, Action<int, LoopState> body) executes body(m, loopState), body(m+1, loopState)....(n-1, loopState), possibly concurrently and out of order. A delegate i(loopState).Break(i) to signal that no iterations beyond the i/th are needed, or call loopState.Stop() to signal that no further iterations are at all. In some cases further iterations may be performed. Note that the loopState object of class ParallelLoopState is created by the For method.

For overload exists, for taking long instead of bounds, taking parallel options, and for creating thread-local state. See the .NET library documentation for details.

- * staticParallelLoopResult ForEach<T>(IEnumerable<T> xs, Action<T> body) executes body(x1).body(x2)....for all elements x1, x2.... of xs, possibly and out of order.

ForEach overload exists, for Action delegates that take a parallel loop argument, taking parallel options, and for creating thread-local state. See the .NET library documentation.

- * static void Invoke(params Action[] acts) calls the delegates in array acts, possibly and out of order. Also overloaded to take a parallel options argument.

- * Read-only property bool IsCompleted is true if all iterations were performed; otherwise false.
- * Read-only property length LowestBreakIteration returns the index of the lowest iteration from Break(i) was called, if it was null.

When multiple iterations of a parallel loop need to update the global resource, they must lock the resource (section 21.2). For instance, for the Parallel.For in example 170 were to retrieve the results in an array list results, rather than in distinct array, then the loop must lock the array while adding to it (but not while performing the computation):

```csharp
i => { String res = NcbProtein(ids[i]);
lock (results) results.Add(res); };
```

This approach is safe to prevent excess locking because some or all iterations may be performed on the same thread. Further overloads of For and ForEach provide ways to introduce thread-local resources and thereby save some locking. See the .Net library documentation.

## Example 168 Parallel Matrix Multiplication
Matrix multiplication R = AB can be implemented by a tripled nested loop. The usual sequential outermost loop may be replaced by a parallel outermost loop by calling method Parallel.Forwith a lambda expression expressing the inner loops. No synchronization is needed

```csharp
Parallel.For(0, rows, r => {
    for (int c = 0; c < cols; c++) {
        for (int k = 0; k < inner; k++) {
            R[r, c] += A[r, k] * B[k, c];
        }
    }
});
```

The Task Parallel Library can be used to retrieve data from multiple sources in parallel. 

```csharp
string[] results = new string[ids.Length];
```

## 22.2 The Task Classes
Class Task and its subclass Task<T> are used to create tasks and to implement asynchronous methods (section 23). Task represents an asynchronous activity that does not produce a result (a void delegate), whereas Task<T> represents a value of T (made from a delegate).

### 22.2.1 Class Task
Class Task from namespace.Threading.Tasks has the following members, among others:

- Constructor(Action act) creates a task that, when started, will execute act.
- ContinueWith(Action<Task> cont) creates and starts a task in which the given task continues; when task completes, cont(task) will be called.
- Task<U> ContinueWith(Func<Task, U> cont) is similar, but the continuation produces a result.
- static Delay(int ms) creates and starts a task that blocks for ms.
- static Run(Action act) creates and starts a concurrent task that execute().
- static Task<T> Run(Func<T> func) creates and starts a concurrent task that executes().
- RunSynchronously() starts the task for synchronous execution on the current task scheduler; blocks the current thread until the task is complete.
- Start() starts the given task for asynchronous execution on the current task scheduler. Throw InvalidOperationException if the task is already started or cancelled.
- Read-only property TaskStatus returns the task's state (see on page 141).
- Wait() blocks until the task completes. AggregateException if the task is cancelled or throws an exception.
- static Task WhenAll(params Task[] tasks) creates and starts a task that completes when all of the given tasks complete, returning an array of results.
- static Task<T[]> WhenAll(params Task<T>[] tasks) creates and starts a task that completes when all of the given tasks complete, returning an array of results.
- static Task<T> WhenAny(params Task<T>[] tasks) creates and starts a task that completes when any of the given tasks complete, returning one of the tasks completed.

The constructor and methods ContinueWith, Delay and Run have further overloads that take an additional CancellationToken argument (section 22.2.3 and 174) for cancellation of the resulting task. The ContinueWith method has overloads that take a task continuation option argument or a task scheduler argument. See the .NET class library documentation.
