# 28.1.2 Query Body Clauses

A clause from x in xs defines a range x that ranges over the items of stream.xs, where the right-hand side xs is evaluated for each combination of range variables already introduced. The type of x is inferred from the type of xs, which must implement IEnumerable<T> or IQueryable<T> or the query expression (section 28.2). The type may also be explicitly specified, using the notation from type x in xs. Along with foreach (section 13.6.2) this causes each of xs to be cast to being bound to x, and is useful for querying legacy collections that implement non-generic IEnumerable<T> (section 27.2.2).

A clause let y = e binds variable y to the value of expression e, where e may refer to previously defined order or range variables. The type of y is inferred from the type of e.

A where b is a filter that evaluates Boolean b for each combination of range variables. It discards from further processing combinations for which b is false.

There are two kinds of join clauses. The first kind is the inner join:

```
join in ys equals e2
```

It introduces an additional range variable y ranging over stream xs, and then generates a sequence of pairs (x,y) for which equals e2. The expressions of e1 and e2 must satisfy comparison for equality, for instance by being of some type t that implements IEquatable<t>. To allow efficient joins, y cannot appear in expression e1 and x cannot appear in expression e2.

The second kind is a group join:

```
join y in ys on e1 equals e2 into zs
```

It creates a variable zs whose value, for each item x in xs, is a stream of ys for which e1 equals e2. That is, result is a stream of y values, one group for each; for all values of y within a group the value of e2 is the same and equals ei. This is a left outer join: example 242 how to compute a traditional left outer join using the grouped one. The e1 and e2 must satisfy the same requirements as above.

In both kinds of join clause the type of y may be explicitly specified, this:

```
join type in ys on e1 equals e2
join type in ys on e1 equals e2 into zs
```

The effect and use of this is the same as for explicitly from clauses (see above).

The basic form of the orderby Linq clause is orderby e1 ascending; it causes the rest of the query to process the values of the range variables in the order of ascending values of expression e1, or in order of descending values of e1 if the qualifier is used instead. In SQL, the qualifier ascending is default and may be left out.

The general form orderBy e1, e2, ... can take multiple ordering criteria, each optionally preceded by ascending or descending. It causes the rest of the query to process the values of range variables in the order given by e1 as primary ordering criterion, e2 as secondary ordering criterion, and so on. The expressions ei must have a type that implements IComparable<T> or IComparable.
