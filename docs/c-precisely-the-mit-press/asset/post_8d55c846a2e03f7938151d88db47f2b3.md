Example 205 A Generic List Interface

The generic interface MyList<T> extends the interfaces IEnumerable<T> (section 27.2) and IEquatable<T> (section 27.3) with methods to add and remove list elements, an indexer to get and set the element at a particular position, and a generic method Map<U> that takes as an argument a delegate-in generic type Func<T,U> (page 222) and builds a list of MyList<U>. Note that the generic method Map<U> has an additional type parameter U.

```c
public interface MyList<T> : IEnumerable<T>, IEquatable<T> {
    int Count { get; } // Number of elements
    T this[int i] { get; set; } // Gets or sets element at index i
    void Add(T item); // Add element at index
    void Insert(int i, T item); // Inserts element at index i
    void Remove(int i); // Removes element at index i
    MyList<U> Map(Func<T, U> f); // Maps f over all elements
}
```

Example 206 A Generic Polyminal Type. Implementing Generic Twice

A value of type AddMul<A,R> supports addition and multiplication with values of type A, giving results of type R. A value of type Polynomial<E> is a polynomial with coefficients of type E; for this to make sense, values of type E must support addition and multiplication with values of type E, and E must have an argumentless constructor E() that creates a zero element of E.

In return, polynomials over E support addition and multiplication with values of type E (thus implementing interface AddMul<E,Polynomial<E>>) and support addition and multiplication with themselves (thus implementing interface AddMul<Polynomial<E>,Polynomial<E>>).

```csharp
interface AddMul<A,R> {
    R(A a); // Addition with A, giving R
    Mul(A a); // Multiplication with A, giving R
}
```

```csharp
class Polynomial<E> : AddMul<E,Polynomial<E>>,
    where E : AddMul<E,E>, new() {
        private readonly E[] cs;
        public Polynomial() { this.cs = new E[0]; }
        public Polynomial<E> Add(E other) { ... }
        public Polynomial<E> Mul(E other) { ... }

        for (int i=0; i<len; i++) {
            E sum = new E(); // Permitted by constraint E : new()
        }

        public Polynomial<E> Add(E other) { ... }
        public Polynomial<E> Mul(E other) { ... }
    }
```

## 26.7 Generic Methods

A generic method is a method that takes one or more type parameters. A generic method may be declared inside a generic or non-generic class, struct type, or interface.

A declaration of a generic method M<T1,...,Tn> has one of these forms:

```
method-modifiers return M<T1,...,Tn>(formal-list)
method-body
```

```
method-modifiers return M<T1,...,Tn>(formal-list)
parameter-constraints
method-body
```

The method-modifiers, return, and formal-list are as for non-generic methods (section 10.7). If present, the parameter-constraints are as for generic classes (section 26.4).
The type parameters T1,...,Tn may be used as types in the return, formal-list, method-body, as the type parameters of any enclosing generic class or struct type or interface. A type parameter Ti of a generic method may have the same name as a type parameter of the enclosing generic class or struct type, but this will cause a compiler warning.

A scope can have several methods, generic or not, with the same signature M(formal-list) if the methods have different numbers of type parameters. Only the number of type parameters is used to distinguish the methods, not the type parameter names or the constraints, if any.

When a generic method is declared inside a generic type (class or struct or interface) declaration, it is a compile-time error if there is instantiation of the type parameters of the enclosing generic type and the generic method that causes two method declarations to have the same signature.

If a generic method overrides a generic method declared in a base class or implements a method described in an interface, it must have parameter-constraints as methods. The names of the parameters are not significant, only their order in the type parameter list T1,...,Tn.

An application of a generic method can be written M<T1,...,Tn>(...) with generic arguments t1,...,tn, for the method's type parameters T1,...,Tn, or without them M(...). In the latter case, the compiler will attempt to infer the appropriate type arguments t1,...,tn automatically. Parameter constraints are not taken into account during inference but must be satisfied by the resulting arguments t1,...,tn. When inference is successful, the inferred type arguments are used to determine the method's signature for use in subsequent overloading resolution (section 12.17.4).

In those cases where the inference is unsuccessful, the generic method will not take part in subsequent overloading resolution. If no other method exists with an appropriate signature, then resolution fails, and one must write the method application in the first format M<t1,...,tn>(...), giving the type arguments explicitly.

Example 207 Generic Quicksort Using a Compar Object
This method sorts an array of T[] where T is a type parameter. A parameter of type IComparer<T> determines the element ordering (section 27.3 and example 224).

```csharp
private static void Quicksort<T>(T[] arr, IComparer<T> comp, int a, int b) {
    if (a < b) {
        int i = a, j = b;
        T x = arr[(i + j) / 2];
        do {
            while (comp.Compare(arr[i], x) < 0) i++;
            while (comp.Compare(x, arr[j]) < 0) j--;
            if (i < j) {
                T temp = arr[i]; arr[i] = arr[j]; arr[j] = temp;
                i--;
            }
        } while (i <= j);
        Quicksort(arr, comp, a, j);
        Quicksort(arr, comp, i, b);
    }
```

Example 209 A Generic Method in a Generic Class
The generic class LinkedList<T> (example 200) can be equipped with a generic method Map<U> that takes an additional type parameter U and returns a new list of type LinkedList<U>. The generic interface IList<T> is defined in example 205, and the generic delegate Func<T,U> is defined on page 122.

```csharp
public class LinkedList<T> : IList<T> {
    ...
    public IList<U> Map<U>(Func<T, U> f) { // Maps f over all elements
        LinkedList<U> res = new LinkedList<U>();
        foreach (T x in this) {
            res.Add(f(x));
        }
        return res;
    }
}
```

## 26.8 Generic Delegate Types

A declaration of a generic delegate D<T1,...,Tn> has one of these forms:

```
delegate-modifiers returnype D<T1,...,Tn>(formal-list);
delegate-modifiers returnype D<T1,...,Tn>(formal-list)
  where parameter-constraints;
```

The delegate-modifiers, returnype, and formal-list are as for non-generic delegates (section 17), except that the type parameters T1,...,Tn may be used in the returnype and formal-list. The parameter-constraints are as for generic classes (section 26.4). The type parameters of a delegate type can have co- and contravariant modifiers out and in (section 26.12).

## 26.9 Abbreviations for Constructed Types

With the using directive one can introduce abbreviations for constructed types which may otherwise become verbose. The relevant form of the using directive (section 29.1) is this one:

```
using T = t;
```

where T is a name. The right-hand side t is a type, possibly involving types constructed from generic types. A using directive can appear only at the beginning of a compilation unit or a namespace declaration (section 29), not inside classes, interfaces, or struct types.
A using directive does not affect other directives in the same namespace. Thus although a using directive can make type aliases in method headers and declarations more readable, the using directives themselves can become rather unwise.

For instance, assume one wants to introduce a type alias Set<int> and a type alias IntSet2 for the Dictionary<Set<int>,int> in this program:

```csharp
using System.Collections.Generic;
class Nfa {
  static List<int> Rename(IDictionary<Set<int>,int> renamer,
    IList<Set<int>> states) { ... }
}
```

Then the right-hand side of using directives must use the full type paths, like this:

```csharp
using Set = Set<int>; // Type abbreviation
using IntSet2 = System.Collections.Generic.IDictionary<Set<int>,int>;
class Nfa {
  static List<int> Rename(IntSet2 renamer, List<int> states) { ... }
}
```

In particular, the definition of IntSet2, the System.Collections.Generic prefix is needed, and Set<int> cannot be replaced by IntSet. One solution to this problem would be to artificially introduce nested namespace declarations: a using directive in an outer namespace does affect directives in inner namespaces. But this is not recommended.
