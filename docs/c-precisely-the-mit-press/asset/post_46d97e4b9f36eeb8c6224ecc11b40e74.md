**Example 234** Linq query expressions, the System.Linq namespace must be referred to at the beginning of the source file.

```csharp
using System.Linq;
```

The Linq examples that follow use the arrays xs and ys, which are enumerable and so can be queried.

```csharp
int[] xs = new[] { 2, 3, 5 };
String[] ys = new[] { "C", "BB", "BA" };
```

The first query expression produces a stream of three (4, 9, 25). The second query expression produces a stream containing two groups, where the first group has key 2 and two members (4, 25) and the second group has key 0 and one member (9).

```csharp
Show(from x in xs select x*x);           // 4 9 25
ShowGroups(from x in xs                   // 2: 4 0: 9
    group x*x by x%3);
```

**Example 235** A Linq Query Expression Is Rewritten to Method Calls
The compiler rewrites a query expression in the source syntax to a C# expression consisting of method calls on the streams that are queried. The first query in example 234 gets rewritten to a Select GroupBy. Both of these extension methods are on IEnumerable<T> (section 28.5). Lambda expressions (section 12.23) are used to pass the query's computations and conditions to the extension methods. Note that the from x in xs part does not get rewritten to a method call of its own; it just identifies which stream xs the query works on, and names the range variable.

```csharp
Show(xs.Select(x => x*x));
ShowGroups(xs.GroupBy(x => x%3, x => x*x));
```

**Example 236** Displaying the Result of a Linq Query
The result of any query expression is enumerable and can be printed by method Show. The result of a query ending in group is a stream of groups and can be printed by method ShowGroups.

```csharp
private static void Show<T>(IEnumerable<T> xs) {
    foreach (T x in xs) {
        Console.Write(x + " ");
    }
}
```

```csharp
private static void ShowGroups<K,T>(IEnumerable<IGroup<K,T>> gs) {
    foreach (IGroup<K,T> g in gs) {
        Console.Write(g.Key + " : ");
        foreach (T x in g) {
            Console.Write(x + " ");
        }
    }
    Console.WriteLine();
}
```

## 28.1.2 Query Body Clauses

A clause from x in xs defines a range x that ranges over the items of stream.xs, where the right-hand side xs is evaluated for each combination of range variables already introduced. The type of x is inferred from the type of xs, which must implement IEnumerable<T> or IQueryable<T> or the query expression (section 28.2). The type may also be explicitly specified, using the notation `from type x in xs`. Along with foreach (section 13.6.2) this causes each of xs to be cast to being bound to x, and is useful for querying legacy collections that implement non-generic IEnumerable<T> (section 27.2.2).

A clause let y = e binds variable y to the value of expression e, where e may refer to previously defined order or range variables. The type of y is inferred from the type of e.

A where b is a filter that evaluates Boolean b for each combination of range variables. It discards from further processing combinations for which b is false.

There are two kinds of join clauses. The first kind is the inner join:

```csharp
join y in ys on e1 equals e2
```

It introduces an additional range variable y ranging over stream xs, and then generates a sequence of pairs (x,y) for which e2. The expressions of e1 and e2 must satisfy comparison for equality, for instance by being of some type t that implements IEquatable<t>. To allow efficient joins, y cannot appear in expression e1 and x cannot appear in expression e2.

The second kind is a group join:

```csharp
join y in ys on e1 equals e2 into zs
```

It creates a variable zs whose value, for each item x in xs, is a stream of ys for which e1 equals e2. That is, result is a stream of y values, one group for each; for all values of y within a group the value of e2 is the same and equals e1. This is a left outer join: example 242 how to compute a traditional left outer join using the grouped one. The e1 and e2 must satisfy the same requirements as above.

In both kinds of join clause the type of y may be explicitly specified, this:

```csharp
join type in ys on e1 equals e2
join type in ys on e1 equals e2 into zs
```

The effect and use of this is the same as for explicitly from clauses (see above).

The basic form of the orderby Linq clause is orderby e1 ascending; it causes the rest of the query to process the values of the range variables in the order of ascending values of expression e1, or in order of descending values of e1 if the qualifier is used instead. In SQL, the qualifier ascending is default and may be left out.

The general form orderBy e1, e2, ... can take multiple ordering criteria, each optionally preceded by ascending or descending. It causes the rest of the query to process the values of range variables in the order given by e1 as primary ordering criterion, e2 as secondary ordering criterion, and so on. The expressions must have a type that implements IComparable<T>.

**Example 237** Linq from Clause
Using xs and ys from example 234, these examples show both the source notation and the corresponding method calls. The clause on y select to process all combinations of items, in order, from xs and ys.

```csharp
Show(from x in xs from y in ys select new { x, y }); 
```

**Example 238** Linq let Clause
The let clause introduces a value of y for each value of x, for use in select. The compiler rewrites this expression that packages the x and y in an anonymous object (section 12.4). Subsequent use of range variables x and y are rewritten to create anonymous.x and anonymous.y.

```csharp
Show(from x in xs let y = x*x select y);
Show(xs.Select(x => new { y = x*x }).Select(xy => xy.x + y));
```

**Example 239** Linq where Clause
The clause on x causes select to process only values of x.

```csharp
Show(from x in xs where x%2 != 0 select x*x);
Show(xs.Where(x => x%2 != 0).Select(x => x*x));
```

**Example 240** Linq join Clause
The first join clause selects to process only combinations of x and y for e1 equals e2. The second join clause selects for each pair (x,zs), where zs is an *inner join*. This is a stream of y for which e1 equals e2; this is a *group join*.

```csharp
Show(from x in xs join y in ys on e1 equals e2 select new { x, y });
Show(xs.Join(ys, x => e1, y => e2, (x, y) => new { x, y }));

(from x in xs join y in ys on e1 equals e2 into zs select new { x, y, zs = zs.Count() });
Show(xs.GroupJoin(ys, x => e1, y => e2, (x, zs) => new { x, y, zs = zs.Count() }));
```

## 28.1.3 Query Continuations

A query-expression may have any number of query-continuations, each beginning with into, like this:

```csharp
query-expression
into
    query-body-clauses
    select e
```

The into introduces a new range variable z that precedes it. Expression e is evaluated for each value of z and of any range variables introduced by the query-body-clauses, to produce the items of the query result. All range variables and bound variables introduced by the initial query-expression before e and the query-body-clauses cannot refer to any variables introduced before into. The meaning of into is rather different from the meaning of into in a group clause (section 28.1.2).

An important use of query continuations is to make the groups by a query expression ending in group, so that the groups can be further processed (examples 243 and 245).

## 28.2 The Query Expression Pattern

Any class or C<T> can support Linq queries by implementing the query expression pattern, that is, by having the methods and supporting types shown. This works because a Linq query is rewritten to method calls (examples 235–243). Note that Enumerable<T> and its supporting types (section 28.4) implement the query pattern through their extension methods (sections 28.5–28.8).

For Linq queries to make good sense, methods used in the query expression pattern should behave similarly to those in Enumerable<T>, but this cannot be enforced by the C# compiler.

```csharp
class C {
    public C<T> Cast<>();
}
class C<T> : C {
    public C<K, T> GroupBy<K>(Func<T, K> h);
    public C<K, E> GroupBy<K, E>(Func<T, K> h, Func<T, E> f);
    public C<K, V> GroupJoin<U, V>(Func<T, U> key, Func<U, K> fx, Func<T, V> fy, Func<T, U, V, U> g);
    public C<U, V> Select<U, V>(Func<T, U> key, Func<U, K> fx, Func<U, K> fy, Func<T, U, V> g);
    public C<U> Select<U>(Func<T, U> f);
    public C<R> SelectMany<U, R>(Func<T, U> selector, Func<U, IEnumerable<R>> resultSelector);
    public C<T> OrderBy<K>(Func<T, K> h);
    public C<T> OrderByDescending<K>(Func<T, K> h);
    
    public C<T> Where(Func<T, bool> p);
}
```
