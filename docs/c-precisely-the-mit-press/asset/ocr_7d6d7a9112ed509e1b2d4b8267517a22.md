# 26.7 Generic Methods

A generic method is a method that takes one or more type parameters. A generic method may be declared inside a generic or non-generic class, struct type, or interface.

A declaration of a generic method M<T1,...,Tn> has one of these forms:

```
method-modifiers retype M<T1,...,Tn>(formal-list)
method-body
```

```
method-modifiers retype M<T1,...,Tn>(formal-list)
parameter-constraints
method-body
```

The method-modifiers, retype, and formal-list are as for non-generic methods (section 10.7). If present, the parameter-constraints are as for generic classes (section 26.4).
The type parameters T1,...,Tn may be used as types in the retype, formal-list, method-body, as the type parameters of any enclosing generic class or struct type or interface. A type parameter Ti of a generic method may have the same name as a type parameter of the enclosing generic class or struct type, but this will cause a compiler warning.

A scope can have several methods, generic or not, with the same signature M(formal-list) if the methods have different numbers of type parameters. Only the number of type parameters is used to distinguish the methods, not the type parameter names or the constraints, if any.

When a generic method is declared inside a generic type (class or struct or interface) declaration, it is a compile-time error if there is instantiation of the type parameters of the enclosing generic type and the generic method that causes two method declarations to have the same signature.

If a generic method overrides a generic method declared in a base class or implements a method described in an interface, it must have parameter-constraints as methods. The names of the parameters are not significant, only their order in the type parameter list T1,...,Tn.

An application of a generic method can be written M<T1,...,Tn>(...) with generic arguments t1,...,tn, for the method's type parameters T1,...,Tn, or without them M(...). In the latter case, the compiler will attempt to infer the appropriate type arguments t1,...,tn automatically. Parameter constraints are not taken into account during inference but must be satisfied by the resulting arguments t1,...,tn. When inference is successful, the inferred type arguments are used to determine the method's signature for use in subsequent overloading resolution (section 12.17.4).

In those cases where the inference is unsuccessful, the generic method will not take part in subsequent overloading resolution. If no other method exists with an appropriate signature, then resolution fails, and one must write the method application in the first format M<t1,...,tn>(...), giving the type arguments explicitly.
