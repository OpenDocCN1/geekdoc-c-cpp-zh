## 10.18 User-Defined Conversion Operators

A class or struct may declare conversions to from that class or struct. A user-defined conversion from type to type tt may be implicit or explicit; the declaration must have one of these forms:

```csharp
public static implicit operator tt(ts x)
    method-body
public static explicit operator tt(ts x)
    method-body
```

The ts and tt are the source and target types of the conversion. At least one of them must be the type of the enclosing class or struct; neither can be the Object, nor an interface; and neither can be a base class of the other. A class or struct cannot define both implicit and an explicit conversion from type to tt.

The method-body must satisfy the same requirements as a method that has a single-parameter x of type and whose return type is tt. In particular, normally terminating paths should execute a return expression which is implicitly converted to tt. Although not enforced by the compiler, a user-defined conversion should have unexpected side effects, and an implicit conversion should always terminate successfully, whereas an explicit conversion may throw an exception.

User-defined implicit conversions are used in assignments, by-value parameter passing, and cast expressions, but not in inline tests (12.13).

User-defined implicit conversions can be subtle. The declaration of an implicit conversion may be accepted by the compiler but cause stack overflow at run-time, if the body of the conversion itself uses the implicit conversion.

## 10.19 Events

An E is a field holding handlers, where a handler is a delegate (section 17). An event is similar to a delegate type that can be invoked only from inside the declaring class, new handlers can be added and removed from the outside also. A declaration of E has one of two forms:

```csharp
method-modifiers event delegate-type E;
method-modifiers event delegate-type E { add add-body remove-body }
```

where add and remove must either be absent (as in the first form) or both be present (as in the second form). The delegate-type is the type of handlers associated with event E; it must be a delegate type. The methods are as for methods; the abstract cannot be used with the second form. Outside the class declaring an event, it can be used only on the left-hand side of the operators += and -= which return type void. In particular, the event does not provide access to the individual handlers for the event.

In the first form of event declaration, the event is just a delegate (holding event handlers). The usual delegate operations (section 17) can be used on E inside the class declaring it, and the operations += and -= are implemented as the corresponding delegate operations. In the second form of event declaration, the operations += and -= are implemented as calls to add-body and remove-body. These behave as return type void and single-value parameter whose type is delegate-type, and they must satisfy the same requirements as such.

# 11 The Machine Model: Stack, Heap, and Garbage Collection

The machine model describes how data are stored and manipulated at run-time during the execution of a C# program. It has two main components:

- The Stack, which is divided into frames. A frame has room for the local variables and parameters of one invocation of method. A new frame is created when the method is called, and thrown away when the method returns. Thus at any point in time, the frames on the stack correspond to those methods that have been called but have not returned.
- The heap stores objects, arrays, and aggregates. These data are automatically removed from the heap by a garbage collector when they are no longer needed by the program. The space can be reused for other data. There is no way to explicitly remove anything from the heap, not even by calling a so-called destructor (which is not the same as in C++).

In fact, there is a separate stack for each thread (section 21), but only one heap shared among all threads. The various values used in C# are stored as follows:

- All objects, arrays, and delegates are stored in the heap. If an array's element t is a simple type, each array element directly contains its value. If t is a reference type, then each array element contains null or a reference to an object, array, or delegate elsewhere in the heap. If t is a struct type, then each array element directly contains the struct value, that is, has room for its instance fields.
- Local variables and parameters are stored on the stack. A local variable of simple type contains its value. A local variable of reference type contains null or a reference to an object, or delegate stored in the heap. A local variable of struct type directly contains the struct, that is, has room for its instance fields.

## 11.1 Class and Object

At run-time, a class is represented by a chunk of storage, set aside when the class is loaded. The representation of a class contains the name of the class and all the static fields of the class (see the illustration in example 51). At run-time, an object (instance of a class) is allocated in the heap and has two parts: an identification of the run-time class C of object, which is the class used when creating it; and room for all the instance fields of the object. The class identification is used when evaluating instance test expressions (section 12.13), and array element assignments (section 9.1).

At run-time, a struct type is represented very much like a class: the representation of a struct type contains the name of the struct and all the static fields of the struct type. At run-time, a struct value (instance of a struct type) is allocated on the stack or as part of an array or object in the heap. Like an object the struct value has room for the instance fields of the struct, but unlike an object it contains no indication of its struct type.
