Instead of throwing an exception, a computation that may fail return the null value of a nullable type.

```csharp
public static int? Sqrt(int x) {
    if (x.HasValue && x.Value >= 0)
        return (int)(Math.Sqrt(x.Value));
    else
        return null;
}

Console.WriteLine("{0:(1}:{1}:{2}:", Sqrt(5), Sqrt(null), Sqrt(-5)); // Prints 2::null:
```

## Example 159 Computing with Nullable Types

Arithmetic operators such as + and * are automatically lifted to nullable numbers. Ordering comparisons such as > are false if any argument is null; the equality comparisons are not. The null-coalescing operator ?? gets the property value or a default. Note variable sum has int type.

```csharp
int i1 = 1, i2 = 2, i3 = null, i4 = i1+i2, i5 = i1+i3;
// Values: 12 23 33 null
int i6 = (int)i1; // Legal
int i7 = (int)i5; // Legal but fails at runtime
int i8 = (int)null; // Illegal
Object o1 = i2, o3 = i3; // Boxing of int? gives boxed int
Console.WriteLine(o1.GetType()); // System.Int32
int i9 = (int?)o7, i10 = (int?)o3; // Unboxing of boxed int gives?
Console.WriteLine("{0} [{1}]", i9, i10); // [11] [null]
int[] iarr = { i1, i2, i3, i4, i5 };
i2 *= i4;
i2 *= i4;
Console.WriteLine("{0} = {1}", i2); // 66 12+23
int sum = 0;
for (int i=0; i<iarr.Length; i++)
    sum += iarr[i] ?? 0; // 66 12+23
for (int i=0; i<iarr.Length; i++)
    if (iarr[i] > 11)
        Console.Write("{0} = {1}", iarr[i]); // 22 33
for (int i=0; i<iarr.Length; i++)
    if (iarr[i] != i1)
        Console.Write("{0} = {1}", iarr[i]); // 22 33 null
```

## 20 Exceptions

An exception is an object of an exception type: a subclass of Class Exception. An exception is used to signal and describe an abnormal situation during program execution. The evaluation of an expression or the execution of a statement may terminate abruptly by throwing an exception, either by executing a throw statement (section 13.8.1) or by executing a primitive operation, such as assignment to an element, that may throw an exception.

A caught exception may be rethrown by a throw statement. If the exception is not caught, then the entire program execution will be aborted, and information from the exception is reported to the user (in a console or log). What is printed depends on the exception's ToString() method.

In an exception, the Message property is set by the exception, and the StackTrace property is the stack at the point where the exception was thrown. Both have type String.

## Example 162 Paths through a try-catch-finally statement

To exercise paths through the try-catch-finally statement (section 13.8.2) in method M, run the program with each of the command-line arguments (0, 1, 2, 3, 4). The try clause terminates normally, exits by return, or by throwing an exception. The finally clause takes over. The catch clause ignores exceptions but catches them. The catch clause terminates normally, but by return, and throws an exception. The finally clause terminates normally and lets the try or catch clause determine whether terminate normally, by return, or by throwing an exception (the only exception thrown if the try and catch clauses did not throw an uncaught exception). Exits by break and continue statements are handled similarly to return; a more involved example could be constructed to illustrate their interaction.

```csharp
class TryCatchFinally {
    public static void Main(String[] args) {
        Console.WriteLine(int.Parse(args[0]));
    }

    static void M(int a) {
        try {
            Console.Write("try ... ");
            if (a == 0) return "returned from try";
            if (a == 1) throw new Exception("thrown by try");
            if (a == 2) throw new ApplicationException("thrown by try");
        } catch (ApplicationException) {
            Console.Write("catch ... ");
            if (a == 2) return "returned from catch";
            if (a == 3) throw new Exception("thrown by catch");
        } finally {
            Console.WriteLine("finally");
            if (a == 4) throw new Exception("thrown by finally");
        }
        return "terminated normally with " + a;
    }
}
```

## 21 Threads, Concurrent Execution, and Synchronization

### 21.1 Threads and Concurrent Execution

In sequential program execution, expressions are evaluated and statements are executed after the other, in a single thread of execution: a thread is an independent activity. A C# program may execute several threads concurrently, that is, overlapping in time. For instance, one part of a program may continue computing while another part is blocked waiting for input (example 163).

A thread is created and controlled using an object of the sealed class Thread in the namespace System.Threading. A thread object is created from a delegate of type void ThreadStart(), also from System.Threading. When started, the new thread executes the body of that delegate. To every thread (independent sequential activity) there is a unique controlling Thread object, so are identified.

To create and run, declare an argument method as void Run(), create a ThreadStart delegate from Run, and create a thread object from the delegate:

```csharp
Thread u = new Thread(new ThreadStart())
```

Call u.Start() to allow the thread to run concurrently with other threads (example 163).

Threads can communicate with each other via shared state, by assigning and assigning static fields, instance fields, and arrays (element 166). Two threads can communicate via a local variable or parameter only if both are created from anonymous delegates within the same method.

### States and Transitions of a Thread

A thread is alive if it has started and has not died. A thread dies by exiting the delegate from which it was created, either by returning or by throwing an exception. A live thread is in one of the states (ready to run), Running (actually executing), Sleeping (for a timeout), Joining (waiting for thread to die), Locking (trying to obtain the lock on object o), or Waiting (for notification on object o). The state transitions of a thread are summarized in the table and in the figure opposite:

| From | To State | Reason for Transition |
| --- | --- | --- |
| Enabled | Running | The system schedules the thread and another one |
| Running | Enabled | The thread executes Monitor.Wait(o), thus releasing the lock on o |
| Running | Waiting | The thread attempts to execute lock (o) { ... } |
| Running | Sleeping | The thread executes Thread.Sleep() |
| Running | Joining | The thread executes u.Join() |
| Running | Dead | The thread is exited by returning or by throwing an exception |
| Sleeping | Enabled | The period expires |
| Sleeping | Waiting | The thread was interrupted; throws ThreadInterruptedException when run |
| Joining | Enabled | The thread being joined died, or the join timed out |
| Joining | Waiting | The thread was interrupted; throws ThreadInterruptedException when run |
| Waiting | Enabled | Another thread executed Monitor.Pulse(o) or Monitor.PulseAll(o) |
| Waiting | Locking | The wait for the lock on o timed out |
| Waiting | Dead | The thread was interrupted; throws ThreadInterruptedException when run |
| Locking | Enabled | The lock on o became available and was given to this thread |
