
# Interfaces

## 15 Interfaces

### 15.1 Interface Declarations

An interface describes methods, properties, indexers, and events but does not implement them. An interface-declaration may contain method descriptions, indexer descriptions, and event descriptions. The descriptions in an interface may appear in any order:

```c
interface-modifiers interface I base-interfaces {
  method-descriptions
  property-descriptions
  indexer-descriptions
  event-descriptions
}
```

An interface may be declared at top level or inside a namespace or class or struct. At top level in a namespace, the interface-modifiers may be public or internal (which means internal). Inside a class or struct, the interface-modifiers may be any of the member modifiers (section 10.3). In a class it may also be to hide an interface inherited from a base class.

An interface declaration consists of one or more partial type declarations (section 30). The base-interfaces clause may be absent. Otherwise the interface declaration has this

```
interface-modifiers interface I : I1, I2, ... { }
```

Where I1, I2,... is a non-empty list of interfaces. If the base-interfaces clause is present, then interface I describes all members described by I1, I2,..., and is a subinterface of I1, I2,.... Interface I can describe additional methods, properties, indexers, and events not described by the base interface I1, I2,..., and it may hide inherited members by describing new members. A method-description for method M must have the

```
description-modifier returntype M(format-list);
```

where the description-modifier should be new if the description hides a member inherited from a base interface such as I1 (otherwise a compiler is given). No access modifiers can be given; all interfaces are implicitly public. A property-description for a property P must have the

```
description-modifier returntype P {
  get;
  set;
}
```

where one of get and set may be left out. An indexer-description must have the

```
description-modifier returntype this[format-list] {
  get;
  set;
}
```

where one of get and set may be left out. An event-description for an event E must have the

```
description-modifier event delegate-type E;
```

## Example 146 Three Interface Declarations

The Colored interface describes property GetColor, interface Drawable describes method Draw, and ColoredDrawable describes both. The methods are implicitly public.

```csharp
// System.Drawing; Graphics, SolidBrush, Pen, ...
interface IColored { Color GetColor(); get; }
interface IDrawable { void Draw(Graphics g); }
interface IColoredDrawable : IColored, IDrawable { }
```

## Example 147 Classes Implementing Interfaces

Property GetColor and method Draw must be public, as in the interfaces in example 146.

```csharp
class ColoredPoint : Point, IColored {
    protected Color c;
    public ColoredPoint(int x, int y, Color c) : base(x, y) { this.c = c; }
    public Color GetColor() { get { return c; } }
}
class ColoredDrawablePoint : ColoredPoint, IDrawable {
    public DrawablePoint(int x, int y, Color c) : base(x, y, c) { }
    public void Draw(Graphics g) {
        g.FillRectangle(new SolidBrush(c), x, y, 2, 2); 
    }
}
class ColoredRectangle : IDrawable {
    private int x1, x2, y1, y2; // (x1, y1) upper left, (x2, y2) lower right
    protected Color c;
    public ColoredRectangle(int x1, int y1, int x2, int y2, Color c) {
        this.x1 = x1; this.y1 = y1; this.x2 = x2; this.y2 = y2; this.c = c; 
    }
    public Color GetColor() { get { return c; }
    public void Draw(Graphics g) { g.DrawRectangle(new Pen(c), x1, y1, x2, y2); }
}
```

## Example 148 An Interface is a Type

A Colored value has a GetColor property; a Drawable value in addition has a Draw method.

```csharp
static void PrintColors(IColored[] cs) {
    for (int i=0; i<cs.Length; i++) {
        Console.WriteLine(cs[i].GetColor());
    }
}
static void Draw(Graphics g, IDDrawable[] cs) {
    for (int i=0; i<cs.Length; i++) {
        cs[i].Draw(g);
    }
}
```

## 15.2 Classes and Struct Types Implementing Interfaces

A class C (section 10.1) may be declared to implement one or more interfaces by a class-clause. Similarly, a struct type S (section 4) may be declared to implement one or more interfaces by a struct-clause. Both have the

```: I1, I2, ...```

If this is applied to the declaration of class C, it means that a reference of class C is implicitly convertible to type I1, I2, and so, by reference conversion (section 5.2). If applied to the declaration of struct S, it means a value of type S is implicitly convertible to type I1, I2, and so, by boxing conversion (section 5.3). The interfaces I1, I2, and so, are the base interfaces of the class or struct type. The compiler will check that C declares—or inherits from—every function member described by I1, I2, with exactly the prescribed signature, including ref and out modifiers, and the prescribed return type. Only public instance methods, properties, indexers, and events in a class or struct can implement a member described by interface; a static or non-public member cannot.

## 15.3 Explicit Interface Implementations

When a class implements an interface I, it may declare an explicit interface implementation of any method, property, indexer, or event. Such implementations have the following

returntype I.M(format-list) method-body
returntype I.P { get-body set-body }
returntype I.this[format-list] { get-body set-body }
delegate-type I.E { add-body remove-body }

An explicit interface implementation cannot access members but is implicitly public. A member cannot implement more than one interface. A member declared by explicit interface implementation is an instance member and may be accessed as o.M(...) or o.P, where o is an expression of type, possibly obtained by an explicit cast (section 150). Explicit interface implementation is useful when a class must implement both a generic interface such as IEnumerator<T> and a legacy non-generic interface as IEnumerator (section 2.2). Each of these interfaces describes a read-only property, Current, but with different types. Using explicit interface implementation, one can declare them as follows:

```csharp
T IEnumerator<T>.Current { get { ... } }
object IEnumerator.Current { get { ... } }
```

namespace System.Collections is abbreviated by SC. See also examples 6 and 4.

## Example 149 Interfaces Properties and Indexers

The ISeq interface IEnumerable<int> (can be enumerated as ints) describes a read-only property Count giving the length of the sequence, as well as two indexers that return sequence members. Struct Seq implements ISeq when the property and indexers have been added.

```csharp
interface ISeq : IEnumerable<int> {
    int Count { get; }
    int this[int i] { get; }
    int[] this[params int ii] { get; }
}
struct Seq : ISeq {
    ...
    public int Count { get; return n; }
    public int this[int i] { get { return b + k * i; }
    public int[] this[params int ii] { ... this[ii] }
}
```

## Example 150 Explicit Interface Member Implementation

Explicit interface implementations allow class C to implement method M0 by I1 as specified by I2, although the latter hides the former. It also allows class C to implement the method signature M1() despite I2 and I3 having different return types for it. A subclass of D inherits C's explicit interface member implementations.

```csharp
interface I1 { void M0(); }
interface I2 : I1 {
    new void M0();
    int M1();
}
interface I3 : I1 {
    void M1();
    int P { get; }
    int this[int i] { get; }
}
class C : I1, I2, I3 {
    public void M0() { Console.Write("C.M0 "); }
    void I1.M0() { Console.Write("C:I1.M0 "); }
    void I2.M0() { Console.Write("C:I2.M0 "); }
    int I2.M1() { Console.Write("C:I2.M1 "); return 1; }
    void I3.M1() { Console.Write("C:I3.M1 "); }
    int I3.P { get { return i+((I3)this).P; } }
    void I3.M0() { // Illegal: M0 not explicitly in I3 }
}
class D : C {
    C c = new C();
    // C.M0 C:I1.M0 C:I2.M0 C:I2.M1 C:I3.M1
    c.M0(); ((I1)c.M0()); ((I2)c.M0()); ((I2)c.M1()); ((I3)c.M1());
}
```
