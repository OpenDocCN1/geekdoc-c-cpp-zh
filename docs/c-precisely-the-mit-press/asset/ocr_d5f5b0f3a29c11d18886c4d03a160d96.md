### Example 174 Task Cancellation
To allow a task to be canceled, one must create a cancellation token source cts and pass the cancellation cts.Token to the method that creates the task. Moreover, the task itself must acknowledge cancellation by throwing OperationCanceledException with the token as argument. If the task's for cancellation requests were removed, it would keep running and eventually reach RanToCompletion.

```
public static void ComputeTaskWithAcknowledgement(CancellationToken token) {
    for (int i=0; i=100000000; i++) token.ThrowIfCancellationRequested();
}

CancellationTokenSource cts = new CancellationTokenSource();
CancellationToken token = cts.Token;
Task task = Task.Run(() => ComputeTaskWithAcknowledgement(token), token); // Running
cts.Cancel(); // Canceled
task.Wait(); // Would throw AggregateException containing TaskCanceledException
```

### Example 175 Exceptions in Tasks
If a running task throws an exception (other than an OperationCanceledException that acknowledges cancellation), it will complete in the Faulted state. Calling Wait() or Result on the task will throw an AggregateException whose InnerExceptions contains the exception thrown by the task.

```
Task task = new Task(delegate { throw new Exception("died"); }); // Created
task.Start(); // WaitingOr or Faulted
task.Wait(); // Would throw AggregateException containing Exception("died")
```

Task States and Task Transitions Enum TaskStatus from namespace System.Threading.Tasks describes task state. A task is completed in one of the last three states, and faulted in the last state.

| Task State | Meaning |
|---|---|
| Created | Created by a Task constructor, but not started |
| WaitingForActivation | Waiting to be activated and scheduled internally |
| WaitingToRun | Scheduled but not yet running |
| Running | Running but not yet completed |
| RanToCompletion | Completed successfully |
| Canceled | Canceled before running, or acknowledged its cancellation |
| Faulted | Completed due to anhandled exception |
