# 12.17.2 Method Call: Run-Time Parameter Passing By-Value, ref or out

This section and the next one cover the run-time evaluation of a method call M(actual-list) when it is clear that method M is called, and focuses on the parameter-passing mechanism.

The call is evaluated by evaluating the actual-list from left to right to obtain the argument values. These argument values are then associated with the corresponding parameters in the method's formal-list, in order of appearance.

A by-value argument is not marked ref or out. The type of a by-value argument must be implicitly convertible (section 5.3) to the type of the method's corresponding formal parameter. During execution of the method call, a copy of the converted value is bound to the formal parameter, which is similar to an initialized local variable. For formal parameters of type (simple types and structs) this means that if the method changes the value of the formal parameter, this does not affect the value of the argument expression. For parameters of reference type, this means the formal parameter refers to the same object or array as the argument, and any changes made by that object or array will be visible after the method returns (examples 94 and 96).

A ref argument must be a variable, a non-readonly field, or an array access a[i]; it must denote a storage location. The storage location must be definitively assigned before the call. The ref argument expression must be exactly the same as the method's corresponding formal parameter. During the method call, the method modifies the storage as the argument expression, so any assignment to the formal parameter immediately modifies the storage.

An out argument is very similar to a ref argument. The differences are that the out argument need not be definitely assigned before the call, and that every execution path in the method must definitely assign a value to the out formal parameter.

When the argument values have bound to the formal parameters, the method body is executed. If the method's return type is non-void, the value of the method call expression is the value returned by the method. If the method's return type is void, the method call expression has no value and cannot be used in an expression. When the method returns, all parameters and locals in the method are discarded.

# 12.17.3 Method Call: Parameter Arrays

The formal parameter list of a method, constructor, or indexer may end with a parameter array: a formal parameter of array type preceded by the params modifier (section 10.7). Assume that this parameter is declared as params t[]. In such a method, the actual arguments conforming to t can either be zero or more by-value parameters of type implicitly convertible to t, or an array that is implicitly to t. In the former case, a new array t[] is allocated, the argument expressions are evaluated and converted, their converted values are stored in the array, and the formal parameter xs is bound to the newly created array.

For overloading resolution, an explicit overload such as Max(int, int) is preferred over an expansion of a formal parameter array as Max(int, params int[]). An expansion of a formal parameter array is preferred over a signature that requires an implicit conversion (examples 54 and 95).
