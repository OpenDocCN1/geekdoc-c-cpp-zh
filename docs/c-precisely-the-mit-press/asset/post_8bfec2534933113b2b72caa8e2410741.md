
# 16 Enum Types

An enum type is an integer t and zero or more compile-time constants of that type.

An enum-type-declaration has the form

```
enum-modifiers enum t base-clause {
  enum-member-list
}
```

where enum-member-list is a (possibly empty) comma-separated list of enum member declarations, having one of these forms:

-   enum-member
enum-member = constant-expression

The enum-modifiers control the access of the enum type and follow the same rules as class access modifiers (section 10.14). The modifiers abstract and sealed cannot be used. The base-clause determines the representation type of the enum type. If the base-clause is present, it must have the form : type where type is one of byte, byte, short, ushort, or int. If the base-clause is absent, then the underlying representation type is int.

The value of an enum-member is the value of the constant-expression if the enum member has one. Otherwise, if the enum-member is the first one in the list, the value is zero. Otherwise is it the value of the preceding enum-member, plus 1. The constant-expression must be constant and may refer to (unqualified) enum-members from the same enum type, but it is a compile-time error for enum-members to be recursively defined. Distinct enum members may have different underlying representation value. It is a compile-time error for the constant-expression to evaluate to a value not representable in the underlying representation type.

Outside an enum declaration, an enum-member must be written in its fully qualified form, such as Month.Jan.

An enum member has the type of the enclosing enum type declaration. An enum member can be explicitly cast to the underlying representation type; there are no implicit conversions. The value 0 may be implicitly cast to the enum type; other values of the underlying representation type must be explicitly cast to the enum type. In either case the resulting value does not correspond to any declared member; this is not an error.

The following 14 operators can be applied to enum members:

```
= == < <= = + & ++
```

The comparison operators == can be applied to two arguments of the same enum type t; the result has bool. The operators + - can be used to add an integer to an enum value of t or subtract an integer from enum value of t; the result has t. The bitwise operators (^, &, and |) may be applied to two arguments of the same enum type t; the result has t.

Arithmetics on enum members may produce results in the underlying representation type that do not correspond to any declared enum member; this is not an error, not even in a checked context (section 12.3).

An enum type is a subclass of System.Its ToString method converts an value to a string. If the enum value corresponds to one or more declared enum members, it will be formatted as a symbol, such as "Jan"; if it does not, it will be formatted as an integer, such as "7".

# Example 151 Representing Weekdays and Months Using Enum Types

When specifying a date it is desirable to use numbers for years (2003), dates (31), and ISO week numbers (22), but symbolic values for weekdays (Sat) and months (May). In calendrical calculations it is useful to assign numbers 0–6 to the weekdays (Mon-Sun) and numbers 1–12 to the months (Jan-Dec). This is done in the enum Type Day and Month; note the Jan=1 in Method. MethodDaynumber uses m++ to increment a month number (an enum value), method Weekday computes the weekday by casting the remainder modulo 7 to enum type, and ToString casts a month (an enum value) to int.

```
public enum Day { Mon, Tue, Wed, Thu, Fri, Sat, Sun }
public enum Month { Jan=1, Feb, Mar, Apr, May, Jun, Jul, Aug, Sep, Oct, Nov, Dec }
public class Date {
    readonly int yy // 0-9999, // 1-31 *
    readonly int mm;
    public Date(int y, Month m, int dd) {
        ...
    }
    public static int MonthDays(int y, Month m) {
        switch (m) {
            case Month.Apr: case Month.Jun: case Month.Sep: case Month.Nov:
                return 30;
            case Month.Feb:
                return LeapYear(y) ? 29 : 28;
            default:
                return 31;
        }
    }
    public static Date Fromnumber(int n) {
        ...
        Month m = Month.Jan;
        int mdays;
        while (mdays < MonthDays(y, m)) < d) {
            d -= mdays;
            m++;
        }
        return new Date(y, m, d);
    }
    public static Day Weekday(int y, Month m, int d) {
        return (Day)((ToDaynumber(y, m, d)+6) % 7);
    }
    public override string ToString() { // ISO format as 2003-05-31
        return String.Format("{0:D4}-{1:D2}-{2:D2}", yy, (int)mm, dd);
    }
}
```

# Example 152 Naming Constants Using an Enum Type

Enum types can be used to also name constants whose values reflect some external representation.

```
public enum Color : uint
{ Red = 0, Green = 0x00FF00, Blue = 0xFF000FF }
```

# Delegate Types

A declaration of delegate type introduces a new distinct type, useful for creating a closure (a value that represents a function) from a static or instance method regardless of its declaring class. A delegate-type-declaration has the form

```
delegate-modifiers returntype D(parameter-list);
```

The delegate-modifiers control the accessibility of the delegate type and follow the same rules as class modifiers (section 10.14). The modifiers abstract and sealed cannot be used. A delegate type is a reference type (section 5.2) and is derived from System.Delegate. Operations on:

-   To create a delegate D of type D, evaluate D(M), where M is a static or instance method, or new D(o,M); where M is an instance method; or simply assign o to a variable of type D. In both cases the method must be compatible with delegate D. The invocation list of the resulting delegate calls M. If M is an instance method in reference type, then reference (the value of o) is included with the method. If M is an instance method in value type, then boxing conversion (section 5.3) occurs, and reference to boxed copy of the value is included with the method.

-   To call a delegate d1, evaluate the call d1(actual-list), where actual-list must be a call to a method (section 12.7) in the delegate's invocation list; if invocation list is empty, the call throws NullReferenceException. If the return type is non-void, the result of the delegate is the result of the method. If the delegate has ref parameter, it is passed through all the methods. If the delegate has out parameter, it is set by the method.

-   Delegates can be combined using the operators + and +=. The invocation list of d1+d2 consists of invocation list d1 followed by invocation list of d2. A method can appear multiple times on the invocation list.

-   Methods can be removed from a delegate using the operators - and -=. The invocation list of d1-d2 consists of invocation list of d1, except that methods appearing in invocation list of d2 are removed from the end of d1. If a method appears multiple times in d1, the last occurrence in d1 is removed first.

A method is compatible with delegate type if it has the same returntype and the same signature, as parameter-list, as the delegate; also ref and out specifications must match.

The Func and Action families of generic delegate allow description of functions (that return a result) and actions (that do not) up to 16 arguments. See also examples 22, 23, and 28:

```
delegate Func<out R>();
delegate void Action<out R>();
delegate Func<in T, out R>();
delegate void Action<in T, out R>();
```

# Example 153 QuickSort using a Delegate to Compare Elements

Method Qsort sorts an array of objects using the delegate cmp of type DComparer to compare elements. A comparer for strings may be a delegate created from the StringCompare method, or a compatible lambda expression (section 12.23) or Anonymous (section 12). Instead of delegate type DComparer one could use Func<Object,int>; see section 17.

```
public delegate int DComparer(Object v1, Object v2)
private static void Qsort(Object[] arr, DComparer cmp, int a, int b)
{
    if (a < b)
    {
        int i = a, j = b;
        Object x = arr[(i + j) / 2];
        do
            while (cmp(arr[i], x) < 0) i++; // Calls delegate cmp
            while (cmp(arr[j], x) > 0) j--; // Calls delegate cmp
            if (i < j)
            {
                Object tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
                i++;
            }
        } while (i <= j);
    Qsort(arr, cmp, a, j);
    Qsort(arr, cmp, i, b);
}
static int StringReverseCompare(Object v1, Object v2)
{ return String.Compare((String)v2, (String)v1); }
```

```
String[] sa = { "New York", "Rome", "Dublin", "Riyadh", "Tokyo" };
Qsort(sa, StringReverseCompare, 0, sa.Length-1);
Qsort(sa, (v1, v2) => String.Compare((String)v2, (String)v1, 0, sa.Length-1));
```

# Example 154 Combining Delegates

The initial list of dlg3 has two methods: o.M1 and M2. After adding dlg3 to itself, its invocation list is o.M1, M2, o.M1, and M2, so dlg3 makes four method calls. Each call returns the reference parameter by y. Subtracting o.M1 removes the copy of o.M1 from dlg3. Because the parameter is passed by reference, delegate type D cannot be replaced by Func<int,int>.

```
public delegate int D(ref int x)
static int M1(ref int x) { x++; Console.Write("M1/(0 ", x); return x; }
static int M2(ref int x) { x++; Console.Write("M2/(0 ", x); return x; }

TestDelegate o = new TestDelegate();
dlgg1 = o.M1, dlg2 = M2, dlg3 = dlg1 + dlg2;
dlg3 += dlg2;
int y = 0;
Console.WriteLine(dlg3(ref y)); // Prints M1/1 M2/2 M1/3 M2/4 4
dlg3 -= o.M1;
Console.WriteLine(dlg3(ref y)); // Prints M1/5 M2/6 M2/7
```
