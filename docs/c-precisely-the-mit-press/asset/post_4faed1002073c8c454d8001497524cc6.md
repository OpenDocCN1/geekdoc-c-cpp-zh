# Example 173 Implementing Timeout

Task timeout can be implemented using WhenAny to determine whether a given SlowFibTask (example 171) or a certain Delay completes. The WhenAny creates and starts a task, when completes, gets bound to the continuation's parameter task. The result of the task that completed, so one can test whether it is SlowFibTask and if so, return its result, otherwise some dummy value. Example 179 shows how this can be expressed more naturally.

```
public static Task<double> SlowFibTimeout(int n) {
    Task<double> slowFib = SlowFib(n);
    return Task.WhenAny(slowFib, Task.Delay(1000))
    .ContinueWith<double>((Task<double> task) =>
        task.Result == slowFib ? slowFib.Result : -1);
}
```

# 2.2.2 Class Task<T>

Class Task<T> from namespace System.Threading.Tasks represents computations that produce a result of T; it is a subclass of Task and has these additional members:

- * Constructor Task<T>(Func<T> func) creates a task that, when started, will execute func().
- * Task ContinueWith(Action<Task<T>> cont) creates and starts a task in which the given task continues with the computation cont; that, when task completes, cont(task) will be called.
- * Task<U> ContinueWith<U>(Func<Task<T>, U> cont) is similar, where the continuation produces a result of type U. Overloaded to take as arguments cancellation token, task continuation options, and task schedulers.
- * Read-only property Result blocks until the task completes and returns its result. Throws AggregateException if the task throws an exception or is cancelled.

# 2.2.3 Task Cancellation

When creating a task, one can pass it a CallbackContext. The token can subsequently be used to tell the task it may abort. The task may acknowledge the cancellation request (and complete) by throwing an OperationCanceledException that precisely token ct as argument; this moves the task to the cancelled state (page 141). A single cancellation token may be passed to multiple tasks, so that all those tasks may be cancelled by one to call Cancel().

Struct type CallbackContext from namespace System.Threading providing the following operations for use by tasks to which the token has been created:

- * Read-only property bool IsCancellationRequested returns true if cancellation is requested on the underlying cancellation token source.
- * void ThrowIfCancellationRequested() creates an OperationCanceledException with the given token (ct) as argument and throws the exception if IsCancellationRequested is true, acknowledging cancellation; otherwise does nothing.

Class CancellationTokenSource from namespace System.Threading is used to create a cancellation token; it provides the following operations:
- * Constructor CancellationTokenSource() creates a new cancellation token source.
- * void Cancel() requests cancellation via the associated cancellation token.
- * static CancellationTokenSource CreateLinkedTokenSource(params cts) creates a cancellation token source that requests cancellation whenever any of the cancellation token source is given in dtos.
- * Read-only property bool IsCancellationRequested returns true if cancellation was requested.
- * Read-only property CancellationToken returns the cancellation token.

A number of other cancellation-related types are described in the full .Net class library documentation.

### Example 174 Task Cancellation
To allow a task to be canceled, one must create a cancellation token source cts and pass the cancellation cts.Token to the method that creates the task. Moreover, the task itself must acknowledge cancellation by throwing OperationCanceledException with the token as argument. If the task's for cancellation requests were removed, it would keep running and eventually reach RanToCompletion.

```
public static void ComputeTaskWithAcknowledgement(CancellationToken token) {
    for (int i=0; i<100000000; i++) token.ThrowIfCancellationRequested();
}

CancellationTokenSource cts = new CancellationTokenSource();
CancellationToken token = cts.Token;
Task task = Task.Run(() => ComputeTaskWithAcknowledgement(token), token); // Running
cts.Cancel(); // Canceled
task.Wait(); // Would throw AggregateException containing TaskCanceledException
```

### Example 175 Exceptions in Tasks
If a running task throws an exception (other than an OperationCanceledException that acknowledges cancellation), it will complete in the Faulted state. Calling Wait() or Result on the task will throw an AggregateException whose InnerExceptions contains the exception thrown by the task.

```
Task task = new Task(delegate { throw new Exception("died"); }); // Created
task.Start(); // WaitingOr or Faulted
task.Wait(); // Would throw AggregateException containing Exception("died")
```

Task States and Task Transitions Enum TaskStatus from namespace System.Threading.Tasks describes task state. A task is completed in one of the last three states, and faulted in the last state.

| Task State | Meaning |
|---|---|
| Created | Created by a Task constructor, but not started |
| WaitingForActivation | Waiting to be activated and scheduled internally |
| WaitingToRun | Scheduled but not yet running |
| Running | Running but not yet completed |
| RanToCompletion | Completed successfully |
| Canceled | Canceled before running, or acknowledged its cancellation |
| Faulted | Completed due to unhandled exception |

# Asynchronous Methods: async and await (C# 5.0)

# 23 Asynchronous Methods: async and await (C# 5.0)

Asynchronous methods build on the Task and Task<T> classes to simplify the definition and composition of operations such as remote servers, user interactions, and heavy computations.

The async method modifier is used to declare (section 10.7) an asynchronous method:

```
async method-modifiers rentype Task
```

An asynchronous method must return Task or Task<T> (section 22.2) or out parameters. By convention, the name of an asynchronous method should end in Async.

Similarly, a delegate or lambda expression preceded by the async keyword will be asynchronous.

A call to an asynchronous method executes synchronously, from the caller's thread, until it evaluates an await expression (see below) when e is not a completed task. At this point the asynchronous method returns to the caller, while the task resulting from e is executing asynchronously.

An asynchronous method with return Task<T> can return only e, where the expression has type T. The return value of e can be retrieved using the Result property of the task produced by the asynchronous method. An asynchronous method with return Task or void may contain return statements, but these cannot have expression arguments.

An asynchronous method has this form:

```
await e
```

where e is an expression of type Task or Task<T> and must be non-null. When e has type Task<T>, the await expression has type T, and when e has type Task, the await expression has type void. The effect of the await expression is to create and start a task that (1) evaluates e to a started task, (2) awaits the completion of that task, and (3) continues with the rest of the asynchronous method.

Roughly, the C# compiler replaces await with an expression e.ContinueWith(result), where result is a delegate representing the remainder of the asynchronous method. For instance, example 7 is equivalent to what is in page 172. This explanation is too simplistic because the await expression may be expressed in one or more loops. To cover cases, an asynchronous method is implemented as a state machine.

An await expression can appear only inside an asynchronous method, delegate, or lambda expression and not inside a catch or finally block, a lock statement, or a nested synchronous delegate or lambda expression.

An exception thrown by an asynchronous method will not be propagated to the caller but will be encapsulated in an AggregateException when Wait or Result is called on the task returned from the asynchronous method. An exception thrown by a void asynchronous method may remain unreported.
