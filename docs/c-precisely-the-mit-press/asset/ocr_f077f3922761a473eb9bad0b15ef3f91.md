# # Compiling, Loading, and Executing C# Programs

Running a C# program involves three stages: compilation (which first checks that the C# program is wellformed and generates intermediate code, also called bytecode), loading (which loads and checks the bytecode and then generates machine code), and execution (which runs the machine code).

# ## 1.1 Source Files and Compilation

A C# program consists of one or more source files (filename suffix .cs). A source file may contain one or more declarations: classes, interfaces, structs, enum types, and delegates.
Before a C# program is executed, it must be compiled and loaded. The C# compiler, such as Microsoft's c or the Mono project's moc, checks that the program conforms to the syntax for C# programs, that operators (such as +) are applied to check the correct type of operands (such as 5 and x), and if this is fine, the compiler generates a module or file containing intermediate code.
A module resulting from compilation may be an Executable Prog.exe if it contains a static method Main() or Main(String[]) but not, or a library Lib.dll, or a raw module Prog.module.
An assembly of one or more modules, exactly of which one must be an assembly (.exe) can be deployed on its own: a manifest with version number and other metadata, so it can be deployed anywhere. A raw module can be added to an assembly using the /module compile option when generating the assembly. The assembly can access both internal and public members (section 10.14) of the module. The module remains a separate file.
An assembly may be referred to another assembly by using the /reference option when generating the referring assembly. A reference to the Net class library mscor.dll is included in the referring assembly. The default is access only public members of the referred-to-assembly.

| Compiler Option | Short Form | Meaning |
| :--- | :--- | :--- |
| /target:exe | /texe | Compile to an executable (.exe) file, the default |
| /target:library | /tibrary | Compile to a library (.dll) file |
| /target:module | /tmodule | Compile to a module (.module) file |
| /reference:Lib.dll | /r:Lib.dll | Include reference to library Lib |
| /module:M1.module | | Include module M1.module in assembly |
| /main:MyClass | /m:MyClass | Method in class MyClass is the entry point |
| /debug | | Add debugging information |
| /define:DEBUG | /d:DEBUG | Enable assertions (section 31) |

# ## 1.2 Execution

An executable file Prog.exe compiled from Prog.cs can be (loaded) and executed by typing its name on the command line or by invoking the run-time system. This will execute the static method Main(String[] args) in Prog.cs, in the latter case binding the command line args[0], args[1],... (see examples 1 and 2).
The /main compiler option can be used to specify the entry point: the class whose Main method must be executed after loading an executable.
