# 26.3 Generic Classes

A declaration of a generic class C<T1,...,Tn> may have this form:

```
class-modifiers class C<T1,...,Tn> class-base-clause
class-body
```

The T1,...,Tn are type parameters. The class-modifiers, class-body and class-base-clause are for a non-generic class declaration (section 10.1). In addition, a generic class can have type parameter constraints (section 26.4).

Inside-class-base and class-body the type parameters T1,...,Tn may be used wherever a type is expected, and so may be the parameters of any enclosing generic class or generic type (section 26.6).

A generic class C<T1,...,Tn> is not itself a class. However, each constructed type C<T1,...,Tn> is a class, just like a class declared by replacing each type parameter Ti with the corresponding type Ti in the class-body. A type that is substituted for a type parameter Ti in a constructed type can be any type: a class, a struct (for instance, int or bool), or a delegate type, or it can be a constructed type. However, it cannot be the pseudo-type void; the void-type is used only to indicate that a method has no return value.

Each constructed type from a generic class C<T1,...,Tn> is a distinct class and has a distinct copy of the static fields (if any) declared in the class-body. For instance, in example 199, there will be an instanceCount for each constructed type Log<T>; for Log<String>, or for Log<Int>, and so on.

A constructed type C<T1,...,Tn> is accessible when all its parts are accessible. Thus if the generic class C<T1,...,Tn>, or any of the type parameters Ti, is private, then the constructed type is private as well.

Also

generic class can have several classes, or not, with the same name C, if they have different types of parameters. Only the number of parameters is used to distinguish the classes, not the parameter names or the parameter constraints, if any.

A generic declaration is illegal if there exists types T1,...,Tn such that the constructed type C<T1,...,Tn> has two or more methods with the same signature.

An overloaded operator declared in a generic class C<T1,...,Tn> must have at least one whose type is the same as that of the enclosing type C<T1,...,Tn>, as explained in section 10.17.

The usual conversion follows rules for generic classes and generic interfaces. A generic class C<T1,...,Tn> is declared to be a subclass of generic class B<T1> or to implement interface I<T1>; then the constructed type C<T1> can be implicitly converted to the constructed types B<T1> and I<T1>: it is expected.

However, generic classes are invariant in their type parameters. Hence even if t1 is implicitly convertible to t2, the constructed type C<t1> is not implicitly convertible to the constructed type C<t2>. For instance, LinkedList<String> is not implicitly convertible to LinkedList<Object>. If one could create a LinkedList<String>, cast to LinkedList<Object>, store an Object into it, and rather get an Object out of the original LinkedList<String>.
