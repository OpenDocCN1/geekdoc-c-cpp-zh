
## 124 #18 Type dynamic (C# 4.0)

If an expression has type dynamic, then a method call, operator application, delegate call, or field access involving expression will be resolved dynamically, at run-time, rather than compile-time. This means that any such expression will be accepted by the compiler but may fail with an exception at run-time. An expression e of compile-type dynamic will have some value; if this value is non-null, it has a run-time type, obtainable as e.GetType(). The run-time type will never be the type dynamic itself (by possibly System.Object), and will be used to resolve method calls, delegate calls, and operator operations.

If the receiver or any expression e of a method call o(..., e ...) has type dynamic, then the method call will have dynamic too, regardless of the returned types of possible target methods. In this case, the resolution of method call and the resolution of operator overload is performed at run-time, not compile-time (section 12.17.8). If no suitable method exists at run-time, RuntimeException will be thrown.

Likewise, if any of an operator is except and the operators =\, +, and so on have type dynamic, then the operator application has type dynamic also, and the operator overloading resolution is performed at run-time. In expressions such as e+=1 or o+=2, where o has type dynamic, the relevant implementation of operator will be chosen. If no such operator exists, RuntimeException will be thrown.

The expression e has type bool even when e has type dynamic.

Assignments such as x=e and x += e so have the type of x when e has type dynamic. A plain assignment to x involves evaluating e and then attempting an implicit conversion from the run-time value to the type of x. If this succeeds, the result is assigned to x; otherwise RuntimeException will be thrown.

Type dynamic can be used as the delegate type of method parameters and return types, fields, and local variables (as in for, foreach, and using statements); can be used as element types in arrays (section 9) and as generic types in generics (section 26.6); and can be used in cases.

Type dynamic cannot be used as a base class for types; as a bound in a generic parameter constraint (section 26:4); or as an argument of typeof operator. There is no System corresponding to type dynamic, and therefore there could be no result from typeof(dynamic). More, a class or struct cannot implement an interface that has type argument dynamic, such as IEnumerable<dynamic>; but it may have a well base class that has type argument dynamic, such as <dynamic>.

Type dynamic is indistinguishable from type Object in the following contexts. In method matching, for ref and out parameters; as array element type; and as argument to generic types. At run-time, type object typeof(dynamic[]) is equal to type object typeof(Object[]), and type object typeof(List<dynamic>) is equal to type object typeof(List<Object>).

See also sections 6.4 and 12.17.8 and examples 16, 101, and 102.

## 155 Dynamic Operator Resolution

In method Plus2 the meaning of the operator + will be resolved only at run-time because v has type dynamic.

```csharp
static dynamic Plus2(dynamic v) { return v + 2; }
```

The following calls and their results show the meaning of (+) on the run-time type of v. It can mean either int plus (which overflows in this case) or long plus (which does not) or double plus string concatenation (with conversion of 2 to a string). An attempt to apply Plus2 to false would compile fine but throw RuntimeBinderException at run-time no operator + arguments of type bool and int.

```csharp
Console.WriteLine(Plus2(int.MaxValue-1)); // -2147483648, due to int overflow
Console.WriteLine(Plus2((long)int.MaxValue-1))); // 2147483648, no long overflow
Console.WriteLine(Plus2((11.5))); // 13.5
Console.WriteLine(Plus2("Spar")); // Spar2
```

## Example 156 Dynamic Method Argument, Return Type, and Instance Tests

Method Square takes a parameter v of type dynamic. it processes according to its run-time type, and returns a result of type dynamic. If argument v has been of type Object, then many explicit casts would be needed in the operators * and + in the delegate allocation of v. With dynamic, these casts are implicit, yet they are still performed at run-time.

```csharp
static dynamic Square(dynamic v) {
if (v is int || v is double)
    return v * v;
else if (v is String)
    return v + v;
else if (v is Func<int,int>)
    return ([Func<int,int>](x => v(v(x)));

}
```

## 138 Nullable Types over Value Types

A nullable type t? is used to represent missing values of type int. A nullable type t? is an alias for Nullable<t>. The nullable type bool? has values null, false, and true, as in the three-valued logic of the SQL language. The nullable type t? support the following:

- Read-only v1.HasValue of bool returns true if v is not null; false if it is null.
- Read-only v1.Value of type t returns the proper value in v1 if v is not null; it throws InvalidOperationException if v is null.
- Standard comparisons: The implicit conversion from v of type t? gives a non-null value.
- Standard explicit conversions: (t?) is equivalent to t value.
- Lifted conversions: Whenever there is an implicit (or explicit) coercion from value type to t?, to t?.
- Boxing and unboxing conversions: Boxing of a non-null type t gives a boxed t (not a boxed t?); and boxing of a null t gives a null value. Unboxing of a non-null reference gives a non-null t value; and unboxing of a null reference gives a null t value.
- Lifted unary operators ++ -- ! : If argument and result type of an existing operator are non-null value types, then an additional lifted operator is automatically defined for the corresponding types. If the argument is null, the result is null; otherwise the underlying operator is applied to the proper value in the argument.
- Lifted binary operators + - % / ^ | << >> : If argument and result type of an existing operator are non-null value types, then an additional lifted operator is automatically defined for the corresponding types. If any argument is null, the result is null; otherwise the underlying operator is applied to the proper value in the arguments. The corresponding compound assignment, as +=, is automatically defined for nullable types.
- Equality comparisons: v1==v2 is true if both v1 and v2 are null or both are non-null and contain the same value, false v1!=v2 is the negation of v1==v2. Unless v1.HasValue and v1.Value equals v1.Value.
- Ordering comparisons: v1<v2 and v1<=v2 and v1>v2 and v1>=v2 have type bool. A comparison evaluates to false if either is null; otherwise it compares the proper values in v1 and v2.

The operators & and | have special definitions that compute a proper value when:

| null | null | false | null | null | null | null | true |
| false | false | false | false | false | false | true | true |
| true | null | false | true | true | true | true | true |
