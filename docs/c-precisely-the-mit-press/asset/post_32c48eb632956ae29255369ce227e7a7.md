# Preface

This second edition of C# Precisely describes C# (pronounced "c sharp"), versions 3.0, 4.0, and 5.0. It is a quick reference for readers who have already learned or are learning C# from a standard textbook and want to know the language in detail. C# is a class-based object-oriented language for the Common Language Runtime platform, a managed execution environment with type-safe intermediate language and automatic memory management. Thus it was designed by Anders Hejberg and others from Microsoft Corporation. C# includes many useful features not found in Java: struct types, operator overloading, multidimensional arrays, user-definable properties, indexers, and delegates, but omits Java's inner classes and wildcards. In general, C# favors programmer convenience over language simplicity, and safety is much better because of garbage collection. In particular, there is no need to write destructors and finally.

This book presents C# as found in Visual Studio 2010, including lambda expressions, anonymous objects, object initializers, collection initializers, language integrated type, dynamic, type covariance and contravariance, and not least LINQ (language integrated query). In addition it describes asynchronous programming as found in C#'s .NET Framework, although only generic collection classes, and parts of Task are covered. The book does not cover unsafe code, reflection, preprocessing directives, details of IEEE 754 floating-point numbers or expression trees.

General rules of the language are given on left-hand pages, and corresponding examples are shown on the right-hand pages for each reference. All examples are fragments of legal C# programs, available at <csharprecely/. For instance, the code for example 17 is shown in Example17.cs.

# 2 Compiling, Loading, and Executing C# Programs

## Compiling, Loading, and Executing C# Programs

Running a C# program involves three stages: compilation (which first checks the program and generates intermediate code), loading (which loads the bytecode and then generates machine code), and execution (which runs the machine code).

## 1.1 Source Files and Compilation

A C# program consists of one or more source files (.cs). A source file may contain one or more declarations: classes, interfaces, structs, and delegates. Before a C# program is executed, it must be compiled and loaded. The C# compiler, such as Microsoft's, checks that the program conforms to the syntax. A module resulting from compilation may be an executable .exe if it contains a static method Main() or Main(String[]) but not a library .dll, or a raw module .module.

An assembly of one or more modules, exactly of which one must be an assembly (.exe) can be deployed on its own: a manifest with version number and other metadata, so it can be deployed anywhere. A raw module can be added to an assembly using the /module option when generating the assembly. The assembly can access both internal and public members (section 10.14) of the module. The module remains a separate file.

An assembly may be referred to another assembly by using the /reference option when generating the assembly. A reference to the class library mscor.dll is included in the referring assembly. The default is access only public members of the referred-to assembly.

| Compiler Option | Short Form | Meaning |
|---|---|---|
| /target:exe | /texe | Compile to an executable (.exe) file, the default |
| /target:library | /tibrary | Compile to a library (.dll) file |
| /target:module | /tmodule | Compile to a module (.module) file |

## 1.2 Execution

An executable file Prog.exe compiled from Prog.cs can be (loaded) and executed by typing its name on the command line or by invoking the run-time system. This will execute the static method Main(String[] args) in Prog.cs, in the latter case binding the command line args[0], args[1],... (see examples 1 and 2).

The /main compiler option can be used to specify the entry point: the class whose Main method must be executed after loading an executable.
