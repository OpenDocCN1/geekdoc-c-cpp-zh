# 62 Expressions Operators

# 12.2 Arithmetic Operators

The value of the postincrement x++ is that of x, and its effect is to increment x by 1; similarly for decrement x-- The value of the preincrement expression x++ is that of x+1, and its effect is to increment x by 1; similarly for predegment.

Integer division e1/e2 truncates, if e2 evaluates to true, rounds towards zero, 10/3 is 3, and (-10)/3 is -3. The integer remainder xy% equals x when y is non-zero; it has the same sign as x. Integer and decimal division or remainder by zero throws DivideByZeroException. Overflow does not throw an exception (unless in a checked context; see 12.3) wraps around. That is, the result is truncated by any higher-order bits that do not fit in the type. Division in expressions of type decimal always throws Overflow.

The floating-point remainder xy% equals x-(int)x)*y. Floating-point division and floating-point overflow never throws exceptions but produce special IEEE754 values (of type float or double) as Infinity or NaN (not a number).

# 12.3 The checked and unchecked operators

In a checked context, run-time integer overflow will not wrap around but an OverflowException, and compile-time overflow will produce a compile-time. In an unchecked context, both compile-time and run-time integer overflow will wrap around, and no exception will be a compile-time error.

The default for run-time integer arithmetic operations is unchecked (overflow wraps around), and the default for compile-time constant operations is checked (produces a compile-time error).

The overflow context for integer arithmetic operations is explicitly set using the checked and unchecked operators. Only the following operations are affected by the checked and unchecked operators: ++ - * / on integer types and conversions from double, float or integer to integer types. Note that the negation operator - will produce overflow when i is the integer type's MinValue (see the page on 77).

For arithmetic on enums (section 16) is is that the result is in the underlying representation type; it is not checked that the result corresponds to any declared member.

# 12.4 Logical Operators

The logical operators && || perform short-circuit evaluation: if e1 evaluates to true in e1&&e2, then e2 is evaluated to obtain the value of the expression; if e1 evaluates to false, then e2 is ignored and the value of the expression is false. If e1 evaluates to true in e1||e2, then e2 is ignored and the expression is true. In fact, e1&&e2 is equivalent to e1 ? e2 : false, and e1||e2 is equivalent to ? ? true : e2.

By contrast, the operators & (logical strict and) and ^ (logical strict exclusive-or) and | (logical strict) always evaluate both operands regardless of the value of the left-hand operand. On the nullable type bool? they have special definitions (section 19).

The logical negation operator ! evaluates its argument to true and returns false or true.
