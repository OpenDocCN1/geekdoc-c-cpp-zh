## 12.20 Type Cast Expression

A type cast expression is used to perform an explicit conversion (section 5.3) of a value from one type to another. When e is an expression and t is a type, a type cast of e to t is done using the expression

`(t)e`

This expression, when legal, has type t. It is evaluated by evaluating e to a value v. If e has a simple type and t is a simple type, the conversion is performed as described in section 5.3.1.

If e has a reference type and there is a standard conversion from type e to t, then if v is null or a reference to an object or array works implicitly to t, the conversion succeeds with result v; otherwise the exception InvalidCastException is thrown.

If e has a struct type and there is a standard conversion from type e to t (t must be an interface, Object, or ValueType), the conversion succeeds with a result that is a boxed copy of v.

If e has a class type, and that type or type t declares a conversion to type t, that conversion is used to obtain the result.

If e is a simple type, and type e declares a conversion from type e to type t, that conversion is used to obtain the result.

The type cast is illegal and rejected at compile-time when it can be determined at compile-time that it cannot possibly succeed at run-time; for instance, when e has type String and t is Array. When one or both is an interface, this cannot be determined at compile-time.

If the instance test e is t described in section 12.13 returns true, then the type cast (t) will succeed without throwing an exception. The converse does not hold. For example, the cast (t)e may succeed although e evaluates to null; it takes user-defined conversions into account, and it takes implicit conversion of simple types into account, where the instance test e is does.

## 12.21 The typeof Operator

Any type can be represented at run-time by an object of the predefined class Type from namespace System. This also holds for the pseudo-type void and for types constructed from generic types (section 26.2). There is a single Type object for any given type.

The expression typeof(t) evaluates to the Type representing the type t, and typeof(void) evaluates to the type object representing void. The typeof operator can be applied to all types, even types involving type parameters (section 26.6).

Note that whereas typeof(t) returns the Type object for a given type t, the method e.GetType() returns the Type object for the run-time type of a given value e. The GetType method is declared in class Object and is therefore available on all kinds of values (except anonymous methods); see section 5.2 and example 8).

## Example 107 Type Cases

The cast (long)i succeeds although i is false. In a case such as (C)s that involves a user-defined conversion, the type of s must be exactly the declared argument type of the conversion operator.

```csharp
class B {
  class C : B {
    private String s;
    public C(String s) { this.s = s; }
    public static explicit operator C(String s) { return new C(s + s); }
  }
}

int i = 471;
long ll = (byte)i + (long)i; // Simple type conversions
String s = "ole";
B b1 = new C(""), b2 = new B();
C1 = (C)b1; // Succeeds, b1 has class C
C2 = (C)b2; // Fails, b2 has class B
C3 = (C)s; // User-defined conversion String->C
Object o = (Object)s; // Always succeeds
C4 = (C)(String)o; // Succeeds, Object-->String-->C
C5 = (o); // Fails, no Object-->C conversion
Array arr = (Array)s; // Rejected at compile-time
```

## Example 108 Typeof operator

```csharp
interface I {
  class B : I {
    delegate void D(int i);
  }
  struct S : I {}
  class G { public static void WriteType<T>() { Console.WriteLine(typeof(T)); } }
}

Console.WriteLine(typeof(String)); // System.String
Console.WriteLine(typeof(int)); // System.Int32 (int)
Console.WriteLine(typeof(double)); // System.Double (double)
Console.WriteLine(typeof(int[])); // System.Int32[]
Console.WriteLine(typeof(int[][])); // System.Int32[][]
Console.WriteLine(typeof(int[][])); // System.Int32[][][]
Console.WriteLine(typeof(void)); // System.Void
Console.WriteLine(typeof(B)); // B
Console.WriteLine(typeof(C)); // C
Console.WriteLine(typeof(I)); // I
Console.WriteLine(typeof(D)); // D
Console.WriteLine(typeof(S)); // S
Console.WriteLine(typeof<int>)); // System.Int32
Console.WriteLine(typeof(G<String>)); // G[System.String]
G<int>.WriteType(); // System.Int32
Console.WriteLine(typeof(int)==typeof(Int32)); // True
```

## Anonymous Method Expression

Anonymous method expression is an expression that evaluates to a delegate, or nameless method. This is similar to nameless functions known from Lisp and Scheme (lambda), Standard ML (fn), and other functional languages. Anonymous methods are convenient for passing behaviors, such as comparers (15), to a library; this purpose is served by anonymous inner classes. Anonymous method expression has one of these forms:

- delegate-statement
- delegate(formal-list) block-statement

Formal-list is as a method (section 10.7), except that it cannot include parameter array (params) or an optional parameter (10). The block-statement is the anonymous method body. No goto or continue statement can leave the block-statement.

Anonymous method can use local variables and parameters that are bound in the enclosing function. In non-static code, the anonymous method expression that appears in a class cannot use the current instance this, which is assignable (section 14.2).

Anonymous method can be implicitly converted to a delegate type (17). Anonymous method of the first is compatible with any delegate D whose formal-list contains no out parameter. Anonymous method of the second is compatible with a delegate D if its formal-lists have the same parameters and ref/out modifiers; moreover, the delegate type has a parameter array (params) that matches nothing in the anonymous method. In both cases, if D's return type is void, then no return statement directly in the block-statement can return a value. Conversely, if D's return type is t, then every return statement directly in the block-statement must have an argument that is implicitly convertible to t, and the end of the block-statement must be reachable.

After an anonymous method has been converted to a delegate, it can be called like a delegate (section 17). The delegate call's arguments will be evaluated. In the first form of anonymous method, the argument values will be ignored; in the second form they will be bound to the anonymous method's formal parameters in call. The anonymous method will be evaluated, and if it executes a return statement, the anonymous method will terminate.
