# Partial Type Declarations

# 30 Partial Type Declarations

The declaration of a class or interface or struct type may consist of one or more parts, in one or more source files. All parts of such a declaration must be compiled together. Members declared in different parts can refer to each other as if they were declared in an ordinary class, interface, or struct type.

This is useful when parts of a declaration are created in different ways. For instance, one part may consist of code generated by a program generation tool, and another part may consist of customization written by a programmer. By separating them, the generated code can be re-generated without destroying the customization code. It also may be useful to separate code for different purposes: one part may contain alone, and another part may contain code written for testing purposes.

A class or struct declared in several parts may have member classes, member interfaces, and struct types that are declared in several parts of the enclosing type. Apart from these cases, each member (field, method, property, indexer, operator, delegate type, or enum type) must be completely contained in one part.

A partial type declaration must have the prefix part before class or interface or struct type:

```
class-modifiers partial type C class-base-clause
class-body
interface-modifiers partial interface I base-interfaces
{ ... }
struct-modifiers partial struct S struct-interfaces
struct-body
```

The following rules apply to partial type declarations:

+   * All parts of a type declaration must be declared in the same namespace.
* A modifier (new, sealed, abstract, public, ...) on one part of a partial type declaration applies to the entire result. The modifiers must be non-conflicting: a class declaration cannot have one part that is sealed and another part that is abstract.
* All parts of a partial type declaration that have access modifiers have the same access modifiers (public, protected, internal, private). If no part any access modifier, the resulting type has default access: internal for top-level types, private for nested types. The absence of an access modifier on a part does not imply default access.
* All parts of a class declaration that specifies a base class must specify the same base class. This is the base class of the resulting type, if any base class was specified; otherwise it is Object.
* The interfaces of a part must be implemented by the resulting type, not by that part in isolation. Different parts may list different base interfaces. The list of base interfaces of the resulting type is the union, without duplicates, of the interfaces of the parts.
* If a generic type (section 26) is declared in parts, then all parts must have the same type parameters. All parts that have parameter constraints (section 26.4) must have the same constraints, in some order; these are the parameter constraints of the generic type.
* An attribute (section 32) on a part applies to the entire type, not only to that part. The list of attributes of the resulting type is the concatenation, in some order and possibly with duplicates, of the attributes of the parts.
