Example 247 Using Standard Namespaces from Net Framework Class Library
Using directives are for example 253. The legacy non-generic System.Collection namespace is abbreviated to SC rather than importing all its members.

```
using System;
using SC = System.Collections;             // IEnumerator
using System.Collections.Generic;          // IEnumerable<T>, Queue<T>
using System.Diagnostics;                   // Debug
using System.IO;                            // TextReader, TextWriter
using System.Text;                          // StringBuilder
using System.Text.RegularExpressions;      // Regex
```

Example 248 Declaring Namespaces
The namespace N1 contains a declaration of class C1 and struct S13. Namespace N1.N2 contains a declaration of classes C12 and C22. All are accessible in this compilation unit; the internal modifier restricts access outside the compilation unit. The mutual dependence between N1 and N3.

```
namespace N1 {
    public class C1 { N3.C1 c31; }      // N1 depends on N3
    namespace N2 {
        public class C12 { }
    }
class C1 {                                // Default accessibility: internal
namespace N1 {
    public struct S13 { }
}
namespace N1.N2 {
    internal class C22 { }
}
namespace N3 {
    class C31 { N1.C1 c11; }      // N3 depends on N1
}
```

Example 249 Using Namespaces
This example uses the namespaces N1 and N1.N2 declared in example 248. If that example file is compiled to a library (.dll) and this is compiled with that library (section 1.1), then C1 and N1.N2.C22, which are internal to library, are not accessible in this example.

```
using N1;
using N1.N2;                    using N2; would not suffice here
class MyTest {
    public static void Main(String[] args) {
        C1 c1;
        C12 c12;
        // C1 c1;                      // Inaccessible: internal to declaring library
        S13 c13;
        // C22 c22;                   // Inaccessible: internal to declaring library
    }
}
```
