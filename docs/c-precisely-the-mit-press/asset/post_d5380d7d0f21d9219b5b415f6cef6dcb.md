**Example 71** Heap, Objects, Arrays, Structs, and Assignment
The assignment p = q of a variable of reference type (class Point, example 43) copies only the reference.
After p and q point to the same object, the assignment to p.x affects q.x. Likewise for the array assignment arr2 = arr1. By contrast, an assignment r = s of a variable type (Spoint, example 142) copies the struct from s to r; hence the later assignment to r.x does not affect s.x.
When method M2 calls itself recursively, the stack maintains a separate copy of local variables and parameters (here just i) for each unfinished call of the method.

```
public static void M1() {
    Point p = new Point(11, 111), q = new Point(22, 222);
    p = q;
    p.x = 33;
    Spoint[] r = new Spoint(44, 444), s = new Spoint(55, 555);
    r = 8;
    r.x = 66;
    int[] arr1 = new int[4];
    int[] arr2 = arr1;
    arr1[0] = 77;
    Spoint[] sarr = new Spoint[3];
    sarr[0].x = 88;
    M2(2);
}
public static void M2(int i) {
    if (i > 0)
        M2(i-1);
}
```

After executing the body of M1 and three calls of M2, just before M2(0) returns, the stack contains three frames for M2. The leftmost Point in the heap is not referred to by a variable anymore and will be removed by the garbage collector.

## 12 Expressions

An expression is evaluated to obtain a value such as 117 or true. In addition, evaluation of an expression may change the computer's state: the values of variables, fields and array elements, the contents of files, and so on. More precisely, evaluation of an expression

- + terminates normally, producing a value, or
- terminates abruptly by throwing an exception, or
- does not terminate at all (for instance, it calls a method that does not terminate).

One distinguishes the compile-time type of an expression from the run-time type of its value. An expression has a compile-type inferred by the compiler: when it is a reference type t, and the run-time value of the expression is o, the run-time type of o is a class that is implicitly convertible to t but not necessarily equal to t. For instance, the expression (Object)*"foo" has compile-type t, but its run-time value is an object of String, a subclass of Object.

### 12.2 Arithmetic Operators

The value of the postincrement x++ is that of x, and its effect is to increment x by 1; similarly for decrement x-- The value of the preincrement expression x++ is of x+1, and its effect is to increment x by 1; similarly for predegment.

Integer division e1/e2 truncates, if e2 evaluates to true, rounds towards zero, 10/3 is 3, and (-10)/3 is -3. The integer remainder xy% equals x when y is non-zero; it has the same sign as x. Integer and decimal division or remainder by zero throws DivideByZeroException. Overflow does not throw an exception (unless in a checked context; see 12.3) wraps around. That is, the result is truncated by any higher-order bits that do not fit in the type. Division in expressions of type decimal always throws Overflow.

The floating-point remainder xy% equals x-(int)x)*y. Floating-point division and floating-point overflow never throws exceptions but produce special IEEE754 values (of type float or double) as Infinity or NaN (not a number).

### 12.3 The checked and unchecked operators

In a checked context, run-time integer overflow will not wrap around but an OverflowException, and compile-time overflow will produce a compile-time. In an unchecked context, both compile-time and run-time integer overflow will wrap around, and no exception will be.

The default for run-time arithmetic operations is unchecked (overflow wraps around), and the default for compile-time constant operations is checked (produces a compile-time error).

The overflow context for integer arithmetic operations is explicitly set using the checked and unchecked operators. Only the following operations are affected by the checked and unchecked operators: ++ - * / on integer types and conversions from double, float or integer types. Note that the negation operator - will produce overflow when i is the integer type's MinValue (see the page on 77).

For arithmetic on enums (section 16) is is that the result is in the underlying representation type; it is not checked that the result corresponds to any member.

### 12.4 Logical Operators

The logical operators && || perform short-circuit evaluation: if e1 evaluates to true in e1&&e2, then e2 is evaluated to obtain the value of the expression; if e1 evaluates to false, then e2 is ignored and the value of the expression is false. In fact, e1&&e2 is equivalent to e1 ? e2 : false, and e1||e2 is equivalent to e1 ? true : e2.

By contrast, the operators & (logical strict and) and ^ (logical strict exclusive-or) and | (logical strict) always evaluate both operands regardless of the value of the left-hand operand. On the nullable type bool? they have special definitions (section 19).

The logical negation operator ! evaluates its argument to true and returns false or true.
