# 26.12 Variance of Type Parameters (C# 4.0)

A type parameter T of a generic interface (section 26.5) or generic delegate type (section 26.8) may be declared covariant (out) or contravariant (in):

```
interface-modifiers interface ICvariance-modifier T1,...>
delegate-modifiers returntype delegate ICvariance-modifier T1,...>(formal-list);
```

Here a variance-modifier is out, meaning covariant; or in, meaning contravariant; or absent, meaning invariant. To understand the effect of such a declaration, assume that type C is a subtype of type B.

If I has a covariant type parameter T, then I<C> is a subtype of I<B>; intuitively, if an I<T> can be seen to produce T objects, then a producer I<C> of objects can be used where a producer I<B> of objects is expected, because C is a subtype of B.

Conversely, if I has a contravariant type parameter T, then I<B> is a subtype of I<C>; intuitively, if an I<T> can be consumed or input T objects, then a consumer I<B> of objects can be used where a consumer I<C> of objects is expected, because C is a subtype of B.

Note that subscripting between variance types C and B is not related to relations between primitive types. For instance, I<int> is never a subtype of I<double>, although there is no implicit conversion from int to double.

There are restrictions on variance declarations: A type parameter declared covariant T must not appear as an input type, and a type parameter declared contravariant I must not appear as an output type. These restrictions preserve the soundness of subtyping (\u0value of a supertype is expected\u") without having to introduce further run-time checks.

Roughly, the return type of a method is an output type, and its arguments are input types. A type parameter may be both an output type and an input type at the same time; in that case, the type must be invariant (neither nor out) in the declaration. For instance, type parameter T in IList<T> (section 27.4) must be invariant because it appears as an input type, in method Add(T), and also as an output type, in the get-indexer[i].

+   * A type t is an output type in a method signature if it returns the return type of the method signature, or as an input type in another type expression that itself appears as an output type in the signature, or as an output type in another type expression (such as t[] or IList<t>) in the signature.

+   * Similarly, a type t is an input type in a method signature if it appears as a parameter t of the method signature, or as an input type in another type expression that itself appears as an output type, or as an output type in another type expression (such as t[] or IList<t>) in the signature.

A type is an input type (output type) in an interface if it is an input type (output type) of some method on the interface. A type is an input type (output type) in a delegate declaration if it is an input type (output type) in the delegate signature.
