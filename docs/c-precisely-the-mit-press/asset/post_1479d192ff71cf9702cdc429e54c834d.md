
# 13.9 The checked and unchecked Statements

An operation on integral numeric values may produce a result that is too large. In a checked context, runtime-integer overflow will throw an OverflowException, and compile-time integer overflow will produce a compile-time error. In an unchecked context, both compile-time and run-time integer overflow will wrap around (discard the most significant bits), not throw any exception or a compile-time error.

A checked statement creates a checked context for a block-statement; it has the form

```
checked
block-statement
```

An unchecked statement creates an unchecked context for a block-statement; it has the form

```
unchecked
block-statement
```

In both cases, only arithmetic operations textually inside the block-statement are affected. Arithmetic operations performed in methods called the block-statement are not affected, whereas arithmetic operations in anonymous delegate expressions and lambda expressions textually inside the block-statement are. These are analogous to checked and unchecked expressions (section 12.3).

# 13.10 The using Statement

The purpose of the using statement is to release a resource res, such as a file handle or database connection, after its use. You may have the form

```
using type res = initializer;
body
```

This declares res to have type type, or if the keyword was used instead of type, the inferred type of initializer (section 6.3). The initializer is evaluated and its result assigned to res, the body is executed, and finally Dispose() is called on res regardless of whether body terminates normally, throws an exception, or exits by return or continue. The type must be implicitly convertible to IDisposable and the body cannot be a declaration statement or a labeled statement. Variable res is read-only; it cannot be assigned to or used as a ref or argument. The statement is equivalent to this:

```
{
  type res = initializer;
  { body }
  finally { if (res != null) ((IDisposable)res).Dispose(); }
}
```

The IDisposable interface for namespace System describes a single method:

- void Dispose() is called to close or release resources held by an object, such as files, streams, or database connections. Calling multiple times must not throw an exception.

# Example 138 Checked and Unchecked Integer Operations

The checked and unchecked statements affect only the operations textually enclosed by the statements. Thus overflow that occurs in methods called from the statement is not affected by the explicit overflow checking text. For instance, the call int.Parse("999999999") always throws OverflowException regardless of checked or unchecked context.

In a checked context, an overflow computation performed at compile-time will cause a compile-time error, not throw an exception at runtime.

```
checked {
    Console.WriteLine(int.MaxValue + 1); // Compile-time error
    Console.WriteLine(int.MinValue - 1); // Compile-time error
    Console.WriteLine((uint)(0-1)); // Compile-time error
    int i = int.Parse("999999999"); // Throws OverflowException
}

unchecked {
    Console.WriteLine(int.MaxValue + 1); // -2147483648 (wrap-around)
    Console.WriteLine(int.MinValue - 1); // 2147483647 (wrap-around)
    Console.WriteLine((uint)(0-1)); // 4294967295 (wrap-around)
    int i = int.Parse("999999999"); // Throws OverflowException
}
```

See also example 73.

# Example 139 The using Statement

The using statement creates a TextReader from a given text file and attempts to read three floating-point numbers from it. The using statement ensures that regardless of whether the block terminates normally or by throwing an exception, the TextReader and the file get closed. This behavior is the same as example 137. Class TextReader implement IDisposable, so it can be used in the using statement.

```c
static double[] ReadRecord(string filename) {
    using (TextReader reader = new StreamReader(filename)) {
        double[] res = new double[3];
        res[0] = double.Parse(reader.ReadLine());
        res[1] = double.Parse(reader.ReadLine());
        res[2] = double.Parse(reader.ReadLine());
        return res;
    }
}
```

# 13.12 The yield Statement and Iterators

The yield statement is used to define enumerators and enumerables (section 27.2) in a convenient way.
The yield statement can be used only inside the body of a method or operator, or the get-accessor of a property or indexer, whose return type is IEnumerator, IEnumerable, IEnumerator<T>, or IEnumerable<T>. The body of this iterator method is then called an iterator block, and the yield type of the iterator block is Object or T, respectively. A yield statement cannot appear in an anonymous method.

A yield statement must have one of these two forms:
- yield return;
- yield break;

The type of expression must be implicitly convertible to the yield type of the enclosing block.
The statement will return expression value to a caller, just as a return statement does, but it does not terminate the enclosing block and does not execute any associated finally. Instead, the execution of the iterator block can be resumed after the yield statement, causing the iterator block to execute more yield statements. When the iterator block executes the yield break, or terminates by reaching the end of the iterator block, or throws an exception, it executes any associated classes, and exception cannot be resumed any more. Using the yield statement, an iterator block can produce a sequence of zero or more values.

An iterator method cannot have ref out parameters and cannot contain a return statement.
A yield return statement cannot appear inside a catch clause or inside a statement that has an attached clause. A yield break statement can appear anywhere in the iterator method except in a finally clause or an anonymous method.

| State | Call MoveNext() | yield | yield break, or end of block | Throw exception | Call Dispose() |
|---|---|---|---|---|---|
| Before | State--Running Restore variables Start executing block | N/A | N/A | N/A | State--After |
| Running | Unspecified | State--Suspended Current--e Return true | State--After Execute finely Return false | State--After Execute finely Throw exception | Unspecified |
| Suspended | State--Running Restore variables Resume after last yield | N/A | N/A | N/A | State--Running Execute finely State--After |
| After | Return false | N/A | N/A | N/A | |

The compiler turns the iterator block into a class that implements IEnumerable<T>, so it has a Current property whose is defined only in Suspended state. The effect of MoveNext() and Dispose() methods is shown in the table, where State-- means that the state changes to s. If the iterator method has return type IEnumerable or IEnumerable<T>, a call to the iterator method creates an instance of this, from which independent objects can be obtained.

# Example 140 Iterator for Integer Sequences

The yield statement can be used to enumerate a sequence of integers (struct Seq from 68) by declaring GetEnumerator as shown below. It has the same effect as a method that returns an object of SeqEnumerator in 64. To satisfy this, we use an explicit interface method (15.3).

```csharp
struct Seq : IEnumerator {
    private readonly int b, k, n;

    public IEnumerator<int> GetEnumerator() {
        for (int i=0; i<n; i++) {
            yield return b + k * i;
        }
    }
    IEnumerator SC.IEnumerable.GetEnumerator() { return GetEnumerator(); };
}
```

# Example 141 Enumerating Solutions to the Eight-Queens Problem

A solution to the n-queens problem is a placement of n queens on n by chessboard so that no queen can attack any other: there can be at most one queen on any row, column, or diagonal. For n = 8 the solution is on an ordinary chessboard. The iterator method Queens(w, n) enumerates partial n-queens solutions with w+1 queens placed in the first w+1 columns of the board. It follows that Queens(n-1, n) enumerates all solutions to the n-queens problem.

```csharp
public static IEnumerable<int[]> Queens(int w, int n) {
    if (w < 0)
        yield return int[n];
    else
        foreach (int[] sol in Queens(w-1, n)) {
            for (int r=0; r<n; r++) {
                for (int c=0; c<w; c++) {
                    if (sol[c] == r || sol[c]+(w-c) == r || sol[c]-(w-c) == r)
                        goto fail;
                }
                sol[w] = r;
                yield return sol;
                fail: {}
            }
        }
}

foreach (int[] sol in Queens(n-1, n)) {
    foreach (int r in sol)
        Console.Write("{0} ", r);
    Console.WriteLine();
}
```
