# 33 Main Differences between C# and Java

C# resembles the Java programming language but has a number of additional features:

+   * The names of all members must be distinct: a method and a field cannot have the same name.
* Rectangular C-style multidimensional arrays as well as Java-style arrays of arrays (section 9.2).
* Non-virtual demethod calls that look like virtual instance methods (section 10.7).
* Properties: get- and set-method calls that look like field access and assignment (section 10.15).
* Indexers: get-method and set-method calls that look like array indexing (section 10.16).
* Most operators can be overloaded, as in the C++ language (section 10.17).
* User-definable implicit and explicit conversions to and user-defined types (section 10.18).
* Call-by-reference passing for methods as in Pascal, Ada, and C++ (section 12.17.2).
* A yield for convenient definition of enumerators, called iterators in Java (section 13.12).
* User-definable value types, most notably structs (section 14). A value of evaluation stack or inline in an object or another structure, unlike objects, which are stored as separate entities in the heap (sections 5.1, 14, and 16).
* Nullable types: uniform handling of missing values, also for value types (section 19).
* Delegates: methods as values, also known as closures (section 17).
* Anonymous methods (section 12.22) and lambda expressions (section 12.23).
* Unlike Java, type parameters in generic types and methods can be instantiated with simple types. This avoids the time and space overhead of boxing and unboxing, and permits exact run-time types and type-safe array assignment.
* Unlike Java packages, namespaces have no source file organization concerns (section 29).
* The possibility to use unsafe code, pointers, and so on. This is discouraged in general programming.
* Unlike Java, a class declared inside another class or struct is a static member class. There are no inner classes (non-static member classes) or local anonymous classes (inside methods).
* Unlike Java, there is no way to declare or limit what can be carried by a method.
* Unlike Java, there is no way to declare that a local variable or parameter is read-only.
* C# has conditional compilation directives such as #define and #if (not described in this book).
* Optional method parameters (section 10.10) and named method arguments (section 12.17.6).
* Object initializers (section 12.10) and collection initializers (section 12.11).
* Compile-time type inference for local variables with the var keyword (section 6.3).
* Run-time resolution of method calls and overloading with type dynamic (sections 6 and 18).
* Anonymous object expressions (section 12.24).
* Variance declarations on generic interfaces and delegate types (section 26.12).
* Extension methods (section 10.9).
* Language integrated query (Linq) operators for enumerables, databases, and so on (section 28).
