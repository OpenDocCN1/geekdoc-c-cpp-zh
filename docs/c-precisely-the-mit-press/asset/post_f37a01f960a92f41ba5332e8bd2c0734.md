
## 14 Struct Types

A value is an instance of a struct type. A struct value can contain fields, methods, declarations, and other members, just like a class, but struct type is a value type. This means that a variable or element of struct type directly contains an instance of the struct type (struct value), whereas a variable or array element of class type contains only a reference to a class instance (object). Also, the assignment of a struct value to struct variable is performed by copying the fields of the struct value to the fields of the struct value held in the variable (example 71). By contrast, the assignment of an object to a variable type only copies a reference into the variable (example 71). Similarly, passing a struct type by argument or returning a struct type from a method will copy the struct value (example 96).

Struct types are well-suited for representing pairs, complex numbers, rational numbers, and other small, value-oriented or functional data structures: data structures may be freely copied because their fields are never modified after creation. Fields should be declared `readonly`.

```
A-declaration of struct type S struct-modifiers S struct-interface-clause
```

A declaration of struct type S introduces a new value type S (section 5.1). The `struct-modifiers` may be new and a class access modifier (section 10.14). It cannot be abstract or `sealed`. The `struct-interface-clause` may be left out; if it is present it has the form `: I1, I2,...` where I1, I2 are a non-comma-separated list of interface types that must be implemented by struct type S; see section 15.2.

A struct declaration may consist of one or more part declarations (section 30). The `struct-body` can have the same members as a `class-body` (section 10.1). A struct type is similar to a class, but there are some differences:

- A struct type implicitly inherits from `System.ValueType`, which inherits from Object (section 5.2). A struct type can inherit from no other class or struct type, and no class or struct type can inherit from a struct type. As a consequence a struct type cannot be abstract or sealed, and a struct member cannot be protected or `protected internal`.

- A struct can have virtual methods, properties, or indexers, and all calls are non-virtual. The `method-modifiers` virtual, sealed, and abstract are not permitted, and override can be used only on members inherited from Object or ValueType, as `ToString` in example 142.

- A struct is a value type, and therefore a variable or field of struct type cannot be null. A struct type has a predefined constructor `S()` that initializes the struct instance's fields with their default values; this initializes the struct's default initial value. No argueless constructor can be declared explicitly in a struct type.

- If S is an array whose element is a struct type S, then each array `arr[i]` holds an entire struct value, not just a reference to one. Creating new `S[3]` will set aside space for three instances of struct type S; see example 71.

- Conversion between a struct type and type interfaces is performed by boxing and unboxing (sections 5.3.3 and 14.1).

- Field declarations cannot have initializers; a field is always initialized with its default value.

### Example 142 A Struct for Points

The SPoint type declaration is very similar to the Point class declaration (example 43). The difference is that assigning an SPoint value to a variable copies the SPoint value (examples 71 and 96). (Thus struct types are most suitable for data structures where fields are read-only, as in example 145.)

```
public struct SPoint {
    internal int x, y;
    public SPoint(int x, int y) { this.x = x; this.y = y; }
    public SPoint Move(int dx, int dy) { x += dx; y += dy; return this; }
    public override String ToString() { return "(" + x + ", " + y + "); }
}
```

### 14.3 Struct Expressions: Value or Variable

An instance method in a class is always invoked on an object, explicitly as in `o.M(...)` or implicitly as `M(...)`, which means `M(...)`. If method is assigned to an instance field, then that will affect the field in the object referred to. However, when invoking an instance method in a struct type `o.M(...)`, one must distinguish whether `o` is a variable or value. The variable case is when `o` is a local variable or reference, a readonly field, or array element `a[i]`. The value case is when `o` is any expression, such as a boxing conversion, a read-only field, or a call to a method, delegate, or indexer. The field of the struct referred to is `o`. On the other hand, when o is a value, field assignment performed by `M` will affect a field of `o` which is not accessible in any other way. In particular, this happens in a field chain as `p.Move(5,5).Move(6,6)` because `p.Move(5,5)` is a value, not a variable (example 144). Moreover, it happens when o is a readonly field; then `o.Move(5,5)` has no effect on the field `o`.

### Example 145 A Struct for Rational Numbers

A rational number has the form `n/d`, where `n` and `d` are long arithmetic operators + can be represented as a struct of type `Frac`. `Frac` defines a constructor, overloaded arithmetic operators and *, an implicit version from long, an explicit conversion to double, comparison operators == and !=, methods `Equals`, `GetHashCode`, method `CompareTo` implements `IComparable`. Unfortunately the default constructor `Frac()` initializes n and d to zero, so the desirable invariant `d != 0` does not hold. Fortunately, computing with ill-formed `Frac` will `DivideByZeroException` (in auxiliary method `Gcd`).

```
struct Frac : IComparable {
    public readonly long n, d; // NB: Meaningful if d!=0
    public Frac(long n, long d) {
        long f = Gcd(n, d); this.n = n/f; this.d = d/f;
    }
    public static Frac operator+(Frac r1, Frac r2) {
        return new Frac(r1.n*r2.d+r2.n*r1.d, r1.d*r2.d);
    }
    public static Frac operator*(Frac r1, Frac r2) {
        return new Frac(r1.n*r2.n, r1.d*r2.d);
    }
    public static Frac operator++(Frac r) {
        return r + 1;
    }
    public static bool operator=(Frac r1, Frac r2) {
        return r1.n=r2.n && r1.d=r2.d;
    }
    public static bool operator==(Frac r1, Frac r2) { ... }
    public int CompareTo(object obj) { ... }
    public override bool Equals(object obj) { ... }
    public override int GetHashCode() { ... }
    public static implicit operator Frac(long n) {
        return new Frac(n, 1);
    }
    public static explicit operator double(Frac r) {
        return ((double)r.n)/r.d;
    }
    public override string ToString() { ... }
    private static long Gcd(long m, long n) { ... }
}
```
