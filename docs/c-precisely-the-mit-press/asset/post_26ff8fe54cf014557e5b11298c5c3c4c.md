## Example 99 Named Arguments

The following calls to method Date.Weekday (example 151) are all equivalent:

```
Date.Weekday(2009, 8, 7)
Date.Weekday(2009, m: 8, d: d)
Date.Weekday(y: 2009, m: 8, d: 7) // ISO order
Date.Weekday(m: 8, d: 7, y: 2009) // US order
Date.Weekday(d: 7, m: 8, y: 2009) // UK order
```

## Example 100 Named Parameters Are Resolved at Compile-Time of Target

The argument names x and y are from interface I, the compile-time type of a, not from the method A.M actually.

```
interface I { int M(int x, int y); }
class A { public int M(int x, int y) { return x + y; } }

I a = new A();
a.M(5, 3); // Returns 8
a.M(x: 5, y: 3); // Returns 8
Illegal: parameter names a and b unknown in type
```

## Example 101 Dynamic Method Receiver: Run-Resolution of Class

Since the receiver of the call v.Length has type dynamic, the choice of which to actually call is postponed to run-time, as v's run-time value is an array, a String, or other object that has a Length property.

```
dynamic v = "hello";
Console.WriteLine(v.Length);
```

## Example 102 Dynamic Arguments: Run-Resolution of Overloading

Consider these overloaded methods:

```
static int Process(int v) { return v; }
static double Process(double v) { return v; }
static String Process(String v) { return v; }
static int Process(Func<int, int> v) { return v(); }
```

In a call Process(v) which has type dynamic, the overloading resolution is postponed to run-time. The call will always be accepted but may fail (RuntimeException) if there is no suitable overload, for instance, if the value of v is null. Note that casting a method argument to dynamic can be used to resolve overloading only at run-time.

```
dynamic v = 5;
dynamic r = Process(v);
Console.WriteLine(r); // Prints 5
v = "hello";
r = Process(v);
Console.WriteLine(r); // Prints "hello"
```

## 12.18 Property Access Expression

A property get-access must have one of these forms:

- P
- C.P
- o.P
- base.P

where o is an expression of reference type. In the first case, P must be a static property declared in the enclosing class. In the second case, P must be a static property declared in C. In the third case, P must be an instance property declared in o. In the fourth case, P must be an instance property declared in the base class. In each case, the type of the property-access is the declared type of P. A property get-access is evaluated by evaluating o, if present, and then executing the body of the get-accessor. The value is returned by the return statement that terminates the execution of the get-accessor. Such a return will eventually be executed, provided the get-accessor terminates normally. If o is present but evaluates to null, NullReferenceException is thrown. A property set-access must have one of these three forms:

- P = expression
- C.P = expression
- o.P = expression
- base.P = expression

A property cannot be used as ref or out parameter.

## Example 103 Using Properties from Log Class

This example uses Log.Count. Note the use of += on the Last property, which invokes its get-accessor and then its set-accessor.

```
Log log1 = new Log();
log2 = new Log();
Console.WriteLine("Number of logs = " + Log.Count);
log1.Add("Alarm");
log1.Add("Coffee");
log1.Add("Bus");
log1.Add("Lunch");
Console.WriteLine(log1.Last);
log1.Last += "nap";
Console.WriteLine(log1.Last);
log1.Add("More work");
Console.WriteLine("Logged entries = " + log1.Count);
foreach (String s in log1.All)
    Console.WriteLine(s);
```

## Example 104 Static, Instance, and Virtual Properties

A class may declare abstract, static, instance, and virtual properties; they behave like the corresponding kinds of methods. A subclass may hide (new) or override properties inherited from the base class.

```
abstract class A {
    public abstract String Cl { get; }
}
class B : A {
    public static String Name { get { return "B"; } }
    public String Ty { get { return "B"; } }
    public override String Cl { get { return "B"; } }
}
class C : B {
    public new static String Name { get { return "C"; } }
    public new String Ty { get { return "C" + base.Ty; } }
    public override String Cl { get { return "C" + base.Cl; } }
}
B b1 = new B();
C c2 = new C();
B b2 = c2;
Console.WriteLine("B.Name = {0}, C.Name = {1}", B.Name, C.Name); // B C
Console.WriteLine("B1.Ty = {0}, c2.Ty = {1}", b1.Ty, c2.Ty); // B C:B
b1.Ty, b2.Ty, c2.Ty;
Console.WriteLine("b1.Cl = {0}, b2.Cl = {1}, c2.Cl = {2}"); // B C:C:B
b1.Cl, b2.Cl, c2.Cl;
```

## 12.19 Indexer Access Expression

An indexer get-access must have one of these three forms:

- o[actual-list]
- this[actual-list]
- base[actual-list]

where o is an expression of reference type. In the first case, the type of o must have an indexer with the given argument types. In the second case, the current class must have (declare or inherit) an indexer with the given argument types. In the third case, the base class of the current class must have an indexer with the given argument types. In each case, the type of the expression is the declared type of the indexer. An indexer get-access is evaluated by evaluating o, if present, and then evaluating the expressions in the actual-list to obtain argument values, implicitly converting them to the types of the formal parameters of the indexer. An indexer set-access must have one of these three forms:

- o[actual-list] = expression
- this[actual-list] = expression
- base[actual-list] = expression
