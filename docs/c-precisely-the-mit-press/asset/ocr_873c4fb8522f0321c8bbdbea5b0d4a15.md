# 12.17.5 Run-Time Processing of Method Calls

# Run-Time Step 1: Compute Target Object (Instance Methods)

In a call to an instance method, a target object or struct is needed, to be bound to during execution of the method.

In the case of M(actual-list) or base.M(actual-list), the compile-time type of o is a reference type, expression o in M(actual-list) must evaluate to an object reference.

In the case of M(actual-list) where the compile-time type of o is a reference type; if non-null, that is the target object; otherwise the exception NullReference is thrown.

In case of o(actual-list) where the compile-time type of o is a struct and o is a variable (field or this or array access), the method's reference will be bound to o during execution of the method. This method may modify the fields of the struct held in the variable. If o is not a variable, then this is bound to a copy of the value evaluation of the method, which cannot make any observable modifications to the fields of the struct (sections 14.2 and 14.3 and example 144). The method must be non-virtual when the compile-time type of o is a struct.

# Run-Time Step 2: Find the Method

If the method TT.M(sig) is static, then no search is needed: the method to call is the method M with signature sig in class TT.

If the method TT.M(sig) is a non-virtual instance method, then the method to call is M(sig) in TT. Otherwise, if TT.M(sig) is a virtual instance method, then the method to call is the most derived implementation of TT.M(sig) with respect to the run-time RT of the value of o. The most derived implementation of TT.M(sig) with respect to RT is found as follows. If RT contains the virtual declaration of TT.M(sig), or an override of TT.M(sig), then the most derived implementation is RT's. Otherwise the most derived implementation of M with respect to the base class of RT.

Note that if some class in the inheritance from RT up to TT hides TT.M(sig), then the most derived implementation of TT.M(sig) must be found in that class or above it in the inheritance hierarchy. See method M in examples 55 and 97.

If the compile-time type of o in the class o.M(actual-list) is an interface, then the method called is the implementation provided by the run-time RT of the value of o. This implementation is found as follows. If RT declares an explicit member implementation of I.M with a matching signature (identical names, return types, and formal parameter lists), then that is the method to call. Otherwise, if RT declares a public instance method with a matching signature, then that is the method to call for the implementation of M in the base class of RT, recursively.

Note that explicit interface member implementations take precedence over ordinary method declarations (sections 15.3 and example 150).
