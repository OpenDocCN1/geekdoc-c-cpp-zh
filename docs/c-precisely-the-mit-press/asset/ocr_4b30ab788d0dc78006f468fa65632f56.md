# Example 142 A Struct for Points

The SPoint type declaration is very similar to the Point class declaration (example 43). The difference is that assigning an SPoint value to a variable copies the SPoint value (examples 71 and 96). (Thus struct types are most suitable for data structures where fields are read-only, as in example 145.)

```
public struct SPoint {
    internal int x, y;
    public SPoint(int x, int y) { this.x = x; this.y = y; }
    public SPoint Move(int dx, int dy) { x += dx; y += dy; return this; }
    public override String ToString() { return "(" + x + ", " + y + "); }\ }
```

In a struct type declaration, this is assigning like a ref parameter, so method Move inside struct SPoint (example 142) can be written as shown in the first line below. Although this does not create a new struct value, it may be less efficient than direct field assignment.

When an struct returns this, the method call can call p.Move(5,5).Move(6,6) may not have the expected effect. The expression p.Move(5,5) is a value, the second call to Move works on a copy of struct, not the struct in variable. Also, a return type of struct is a value, so q.Move(5,5) works on copy of g and does not modify the field of q (section 14.3).

public SPoint Move(int dx, int dy) { return new SPoint(x+dx, y+dy); }
