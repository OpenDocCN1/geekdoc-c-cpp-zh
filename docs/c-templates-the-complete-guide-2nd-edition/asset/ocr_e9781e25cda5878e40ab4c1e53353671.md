# 15.6.1 Reference Collapsing Rules

Programmers are not allowed to directly declare a “reference to a reference”:

```
```cpp
int const& r = 42;
int const&& & ref2rref = i; // ERROR: reference to reference is invalid
```
```

However, when composing types through the substitution of template parameters, type aliases, or decltype constructs, such situations are permitted. For example:

```
```cpp
using RI = int&;
int i = 42;
RI r = i;
R const&& rr = r; // OK: rr has type int&
```
```

The rules that determine the type resulting from such a composition are known as the *reference collapsing* rules.⁴ First, any const or volatile qualifiers applied on top of the inner reference are simply discarded (i.e., only the qualifiers *under* the inner reference are retained). Then the two references are reduced to a single reference according to Table 15.1, which can be summarized as “if either reference is an lvalue reference, so is the resulting type; otherwise, it is an rvalue reference.”

| Inner reference | Outer reference | Resulting reference |
|---|---|---|
| `&` | `&` | `&` |
| `&` | `&&` | `&` |
| `&&` | `&` | `&` |
| `&&` | `&&` | `&&` |

*Table 15.1. Reference Collapsing Rules*

using RCI = int const&;

using RRI = int&&;
RRI const&& rr = 42; // OK: rr has type int&&
```
