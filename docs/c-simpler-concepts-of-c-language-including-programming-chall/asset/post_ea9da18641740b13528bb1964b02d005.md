Writing a small C code in Linux with C programming will help the reader to understand the concept in a great way. The following simple code will just print welcome to the C programming world. Here is the program presented along execution steps.
// Name the file as prog1.c and save it.

```c
#include <stdio.h>
int main ()
{
    printf("\n welcome to the C programming world");return 0;

Now to compile the program, written steps need to be followed. Before that it would be better to know the internal happenings when a file is compiled. When compilation is, firstly there is no compilation or syntax errors the object file will be formed and will be created with the extension .o. Then the object file will be made as an executable one process of linking with the library files. The executable file can then be run to get the above statement mentioned in C code printed.

All these in a sequence and are the commands presented for the same.
$ gcc -c prog1.c

In the above command, gcc is the compiler being used, expanded as GNU Compiler which will compile the code and get the object file. Object file will be generated with the same name as file name, here it is prog1.o. “.o” is to just say it is an object file.

After the process is over, one should get an executable file for the above generated object file. It is again a simple process and can be carried out with the following command.
$ gcc -o executable prog1.o

Above command will convert the object file to an executable file after linking the file with necessary library files. To complete the execution step has to be followed.
$ ./executable

### 13.1.1. Make file - Why is it needed

The reader can understand this easily, with the following simple example codes. Here bunch of C codes are written for understanding the concept behind the raise of make files.

// Three programs are to be used for this program.
// add.sub.c and main.c are the programs

```c
// main.c - This file will use the functions add and sub that has been written in two
// separate files.add.c and sub.c which are kept in the same directory as main.c
#include <stdio.h>
int main()
{
    int x=4, y=5;
    int res;
    res = add(x,y); printf("\n Added Result is %d", res);
    res = sub(x,y); printf("\n Subtraction is %d", res);
    return 0;
}
```

```c
// add.c
// This is meant for addition.
int add(int a, int b)
{
    printf("\n Addition");
    return (a+b);
}
```

```c
// sub.c
// This is for subtraction.
int sub(int a, int b)
{
    printf("\n Subtraction");
    return (a-b);
}
```

To get these entire one should go ahead with the following sequences.
1. gcc -c main.c -> This will generate object file main.o
2. gcc -c add.c -> This will generate object file add.o
3. gcc -c sub.c -> This will generate object file sub.o

Having generated the object files the next step is to get the executable file. That needs combining all the files and linking the necessary library files. How to do that would be the next? It is again easier and simple.

$ gcc -o main.o add.o sub.o

This will now get the executable generated and can be run as usual like ./main. If the file has to run many times, it would be difficult to do all the steps. Automating the process would be handy and make the job easier. But most important point is when change being made in any one of the files, say add.c or sub.c, user should execute the complete cycle again in the normal fashion. So time for execution will be more than if there are files in the project, when file is used, only the files in which change is made, add.c and main.c will be recompiled and will remain untouched if not undergo any change. This is the biggest advantage and prevents lot of time wasted.

If there are files and in the first run, all the files got compiled, then the user wishes to change file's content, all the files and would be restricted only to the files that changed. i.e., alone would be re run and final linking of executable file would happen with already available object files plus newly object files.

Keeping the same dealt example, here the make file is composed. Reader should carefully follow the syntax and it is mandatory. One important thing is to name the file. It can be named as Makefile it has no extension.

```makefile
CC=gcc
# CC and GCC Are the two compilers for C available in Linux. Here GCC is
# used for the compilation. Anything can be used indeed.

all:main
# all here has main followed by a:
# it means the compilation should start from main.
main:main.o add.o sub.o
# Here is where the compilation will start, first the compiler will look for main.o, so it would traverse the next line, main.o will be generated. Then it will look for sub.o, we traverse the sub.o code and will get sub.o generated. So is the case for add.o. Since all the .o. files are generated, they can be Linked and final executable can be obtained. It will be done through the following line.

$(CC) -o main.o add.o sub.o

main.o:main.c
$(CC) -c main.c

add.o:add.c
$(CC) -c add.c

sub.o:sub.c
$(CC) -c sub.c

clear:
rm -rf *.
rm main

One might get a query on usage of linux in the code. It is a simple way to avoid usage of gcc in all those places and if there is need to use cc compiler it needs to be changed in only one place, which is at the top of the code.

How to run the file? Very simple. Just type make and press enter key. Compilation would have happened now. User will not have the pain of running all the steps. main to be suited for execution. If someone wants to run the makefile again, if user issues make again, it would not remake it unless there is a change in any of the files, the older object files will be used instead of regenerating the same. This is real intelligent act of saving time and resources.

But then, if the user is so particular in running the make file again and it can still be done with a clear make. This means, deleting the object files and regenerating it. As rm is the command used to remove the files, the last section is used to remove all the object files created and the executable file, main. And now, user can go ahead and run the make file. It will generate the .o files and executable file as well which can be run.
