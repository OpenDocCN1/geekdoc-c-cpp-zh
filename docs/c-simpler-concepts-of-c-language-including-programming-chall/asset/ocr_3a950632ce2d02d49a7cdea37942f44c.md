# 7.8. DYNAMIC MEMORY ALLOCATION

Have you ever declared an array of size 20 or above and initialized 5 or so leaving the rest of the blank just because you never needed them? If yes, there is a loss of so many bytes allocated for the array! Is there a way to allocate bytes according to the necessity? The answer is YES! There where dynamic memory allocation enters the scene. It provides the flexibility to the programmers to allocate the memory as and when needed. There are few questions need to be addressed before the next section's window is opened.

# 7.8.1. The Heap memory

If the reader had come across Random Access Memory (RAM), it will be simpler to move along. When the system is booted for the first time, the OS occupies some memory in RAM, leaving the rest for the user's programs. To put it in a different way, apart from the OS, the executable files of user programs, the global variables declared in them, stack space will be allotted some memory space while the programs are executed. Those will be released after the programs terminate! Do you think, all the memory space available will be occupied all the time and won't be free memory space available? It is mostly not. There exists free space to be used the time. Such a free space is managed by the operating system. It is called the 'Heap' memory. From that area only, dynamic memory access is served with.

What are the functions available to allocate and de-allocate memory dynamically?

+   * malloc()
* calloc()
* free()
* realloc()

Let's make use of each of this in detail in the following.

# malloc():

Syntax:

void * malloc(size_t size) → allocates a block of size bytes! Returns a NULL if failed.

# Example:

int *p;

p=(int *) malloc(10);→ allocates 10 bytes of memory.

P=(int *) malloc(sizeof(int));→ allocates 20 bytes of memory.
