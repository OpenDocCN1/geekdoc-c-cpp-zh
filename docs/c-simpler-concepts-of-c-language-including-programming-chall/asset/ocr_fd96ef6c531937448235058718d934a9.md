# ## 14.2. USAGE

There are quite useful places where these can be used. They are listed below,

+   1. File inclusion
2. Macro substitution
3. Conditional compilation

Of the above usages, the first one is quite familiar. Isn't it? If 'Yes' comes from your side, hates off to you. Use, rectify, there are so many programs where #include<stdio.h>, #include<conio.h> have been used. It is nothing, but the files 'stdio.h' and 'conio.h' are included in the program. Second one will be like, substituting something for other thing. For example, substituting '34' for the constant 'PI'.

Third usage is similar to conditional constructs discussed in Chapter 2. If something is defined, define some other thing also. Else define a different thing. More about this is discussed shortly.

> Note: The pre-processor directives are executed before compilation stage. They can be placed even inside main() also.

# ## 14.2.1. File inclusion

In 'C', if we want to print something or read something, we need simple I/O functions like printf() and scanf(). Almost all the programs would need these methods. If it was like, only the programmer has to define the functions every time by his/her own before using them, it would have no sense. The time is going to consume much larger than time taken to code logic

So, it was decided to put up some common methods in a 'file' and when the methods are needed, it is simply enough to just include the 'file' as pre-processor directives. Once the files are included, all the methods in that file can be used freely. So, how to include other files?
