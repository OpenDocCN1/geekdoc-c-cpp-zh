### 13.3.3. Write system call

The next system call to be discussed is write(). It is simple to understand and here is program presented for the same. The system call needs a file created already with write permissions. File creation is done with create as above. Opened file can be written into write system call. The file descriptor of the created file (to which the programmer writes) has to be passed as an argument to write with the text to be written. The text can be kept in a char array which is named buffer here in the following code. Now that buffer along with size of the same also needs to be passed as arguments. It will serve the purpose and writing will be over. The file can be opened after execution and it will have "hello" written into it.

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main ()
{
  char buffer[5]="hello";
  // hello is written into buffer array.
  int fd, ret;

  fd = create("txt1.txt", 0777);
  // Create a new file with RWX permissions.
  ret = write(fd, buffer, sizeof(buffer));
  // Write has been performed here.
}
```

### 13.3.4. Read system call

The system call is followed by a read system call. A sample code would be useful and here to understand read. Here one will need 2 buffers (2 char arrays) for writing and for reading. The previous program is repeated for the first half of this code and the second part is slightly different. After writing into a char array named buf, reading can be performed with the file descriptor. Read system call needs fd as reference and to read into the next char array called declared in the code. It can be printed with printf which should get the content read on the screen. Execution snapshot is presented in Fig 13.8.

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main ()
{
  char buf[5]="hello";
  char buffer[5];
  int fd, ret, ret1;
  fd = create("txt1.txt", 0777);
  ret = write(fd, buf, sizeof(buf));
  ret1 = read(fd, buffer, sizeof(buffer));
  fflush(stdin);
  printf("\n %s", buffer);
}
```

```
ubuntu@ubuntu:~$ gcc -o prog1 prog1.c
ubuntu@ubuntu:~$ ./prog1
hello
ubuntu@ubuntu:~$
```

### 13.3.5. Close system call

Close is used to close the file descriptor issued. It will close that fd cannot be referred any anymore. A simple code will make life easier on close. The execution procedure remains same here. After execution, run the code and check. It will return '0' since fd has been closed. Reader can try with available fd for close operation. After execution it shall return -1.

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/stat.h>

int main ()
{
  int fd, ret;

  fd = open("txt1.txt", O_RDONLY|O_CREAT, 0777);
  ret = close(fd);
  // Closing the file descriptor here.
  // Also if closing is done perfectly it will return 0 else -1.
  printf("\n0 Success \n-1 failure");
  printf("\n %d", ret);
}
```

### 13.3.6. Unlink system call

Unlink is slightly better than close, it removes the file itself. Meaning it does the work of rm command. If the removal is successful, it will return '0' else '-1'. If a process had using the file, unlink will wait for usage of the file to complete. Only then it will remove the file. The following piece of code will do unlinking. And file name should be given as the argument for system call.

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/stat.h>

int main ()
{
    int fd1, ret;
    fd1 = open("txt1.txt", O_RDONLY|O_CREAT, 0777);
    ret = unlink("test.txt");
    printf("\n0 Success \n-1 failure");
    printf("\n %d", ret);
}
```

### 13.3.7. getpid() and getppid system calls

As discussed in the past, every process will have a process id and also parent process id. To get information on PID (Process ID) and PPID (Parent Process ID) we have getpid getppid system calls. The usage is very simple and the same has been presented in the following code. The execution procedure remains same as usual. Refer Fig 13.9 for understanding.

```c
#include <stdio.h>
#include <unistd.h>

int main ()
{
    printf("\n Process id is %d", getpid());
    printf("\n Parent Process is %d", getppid());
    return 0;
}
```

### 13.3.8. dup and dup2 system calls

As previously seen, file descriptors are unique identifiers for the processes which are open (Those who are familiar with 'C' can correlate file descriptor with a pointer). Each process has a file descriptor table associated with them. The table has the file descriptors which refer to an open file and a set of flags.

This particular system call 'dup' is intended to duplicate an open descriptor.

Note: dup() makes use of the lowest-numbered unused descriptor for the new descriptor. The snapshot Fig 13.10 stands as a proof for the duplication operation.

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main ()
{
  int fd1, fd2;
  fd1 = open("txt1.txt", O_RDONLY|O_CREAT, 0777);
  close(2);
  // closing error fd.
  // so generated fd should be kept in slot 2
  dup(fd1);
  while (1) {
  }
}
```
In this program, a file name 'txt1' has been created and assigned to a file descriptor named 'fd1'. In the next line, the file descriptor for standard error is closed; then 'fd1' is duplicated to the job of the subroutine 'stderr'. The execution has been done and snapshot is presented here for the reference. In the snapshot it is evident that file descriptor 2 has been assigned to the file txt1 instead of descriptor. So duplication has been done properly and task has been accomplished correctly.
