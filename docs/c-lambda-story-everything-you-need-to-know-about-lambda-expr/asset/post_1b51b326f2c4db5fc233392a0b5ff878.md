
## 4. Lambdas in C++17

C++17 added two significant enhancements to lambda expressions:

- constexpr lambdas
- Capture of `this`

The new C++17 also updated the type system - it now contains exception specification which also relates to lambda expressions. You can see specification related to lambdas in N65 (just before publication) and the lambda section. Additionally, you'll learn about the following:

- How to improve the IIFE pattern in C++17.
- How to improve variadic generic lambdas with fold expressions.
- How to derive from multiple lambdas.

## Lambda Syntax

With C++17, we have a few changes to the syntax of lambda:

- You can now add `constexpr` after parameter list.
- The dynamic exception specification was deprecated in C++11 and removed in C++17, so in practice, you should only use `noexcept`.

```cpp
() specifiers -> ret
optional: trailing return type
optional: mutable, constexpr, noexcept, attributes
parameter list (optional specifiers added)
lambda with optional capture list
```

You can read about this new modification in the next section.

## Exception Specification in Type System

Before we move to syntax improvements for lambdas, we need to cover one “general” feature that was introduced in C++17. Exception Specification for a function didn't belong to the type of the function, but in C++17, it's part of it. You can have two overloads: one with `noexcept` and the second without it. See below:

```cpp
using noexceptFunc = void (*)() noexcept;
void CallWith(noexceptFunc f) { f(); }

using voidFunc = void (*)();
void CallWith(voidFunc f) { f(); }

void fnoexcept() noexcept {}
void fRegular() {}

int main() {
    CallWith(fnoexcept);
    CallWith([]() noexcept { }); // cannot convert
    CallWith([]() {}); // cannot convert
    
    CallWith(fnoexcept); // converts to regular function
    CallWith(fRegular);
    CallWith([]() noexcept { }); // converts
    CallWith([]() {});
}
```

A pointer to `noexcept` function can be converted to a pointer to a regular function (this also works for pointer to a member function and also for lambdas). But it's not possible the way around (from a regular function pointer into a function pointer that is marked with `noexcept`).

One of the reasons for adding this feature is chance to optimise the code better. If the compiler guarantees that a function won't throw, it can potentially generate faster code. Inside the Standard Library, there are many places where `noexcept` is checked and based on this the code can be more efficient. This is how it works for `std::vector` which can differentiate between types that can throw or not. Here's an example which uses type traits and `constexpr` to check if a given object is marked with `noexcept`:

```cpp
#include <iostream>
#include <type_traits>

template <typename Callable>
void CallWith(Callable&& fn) {
    if constexpr (std::is_nothrow_invocable_v<Callable, int>) {
        std::cout << "Calling fn with optimisation" << std::endl;
        fn(10);
    } else {
        std::cout << "Calling fn normally" << std::endl;
        fn(10);
    }
}

int main() {
    int x = 10;
    const auto lam = [&x](int y) noexcept { x += y; };
    CallWith(lam);

    const auto lamEx = [&x](int y) {
        std::cout << "lamEx with x = " << x << std::endl;
        x += y;
    };
    CallWith(lamEx);
}
```

### The output:

```
Calling fn with optimisation
Calling fn normally
lamEx with x = 20
```

The code uses `std::is_nothrow_invocable_v` to check if the given callable object is marked with `noexcept`.

> In C++17, the Exception Specification is cleaned up. Effectively, you can only use `noexcept` for declaring a function that won't throw. The dynamic exception specification, i.e. `throw(X, Y, Z)`, is now removed.

> **Quick Question:** What happens if you mark a function with `noexcept` and yet it throws an exception? In that case, the compiler will call `std::terminate`.

## constexpr Lambda Expression

Since C++11, `constexpr` allowed more and more code to be evaluated at compile time. This not only affects the performance but more importantly makes compile-time coding much more pleasant and potent. In C++17, this powerful keyword can also be applied on lambdas. Let’s see `expr.prim.lambda`.

> The function call operator is a `constexpr` function if either the corresponding lambda-expression's parameter-declaration-clause is followed by `constexpr`, or it satisfies the requirements for a `constexpr` function.

In other words, if the lambda body follows the rules of a `constexpr` function then `operator()` for the closure type is implicitly defined as `constexpr`. To recall, in C++17, a `constexpr` function has the following rules:

- it shall not be virtual;
- its return type shall be a literal type;
- each of its parameter types shall be a literal type;
- its function-body shall be `delete`, `default`, or a compound-statement does not contain:
    - an asm-definition,
    - a goto statement,
    - an identifier label,
    - a try-block, or
- a definition of a variable of non-literal type or static or thread storage duration and for which no initialization is performed.

### For example:

```cpp
constexpr auto Square = [](int n) { return n * n; }; // implicit constexpr
static_assert(Square(2) == 4);
```

Since the body of `Square` is simple and it doesn't violate `constexpr` rules, then it's implicitly marked as `constexpr` and we can call it at compile-time with `static_assert`.

## Examples

How about more practical code samples? At start, let's consider an implementation of a popular numerical algorithm:

```cpp
constexpr lambda - Simple Accumulate
#include <iostream>
#include <array>

template <typename Range, typename Func, typename T>
constexpr T SimpleAccumulate(Range&& range, Func func, T init) {
    for (auto && elem : range) {
        init += func(elem);
    }
    return init;
}

int main() {
    constexpr std::array arr{ 1, 2, 3 };

    constexpr auto sum = SimpleAccumulate(arr, [](auto i) {
        return i * i;
    }, 0);

    static_assert(sum == 14);
}
```

The code uses `constexpr` lambda which is passed to `SimpleAccumulate`. The lambda is not explicitly marked as `constexpr`, but the compiler will declare its call operator with `constexpr`.

As another example we can use and enhance a recursive lambda from the C++14 chapter:

```cpp
int main() {
    constexpr auto factorial = [](int n) constexpr -> int {
        constexpr auto fact_impl = [](int n, const auto& impl) -> int {
            return n > 1 ? fact_impl(n - 1, impl) : 1;
        };
        return fact_impl(n, fact_impl);
    };
    static_assert(factorial(5) == 120);
}
```

## Capturing Variables

You can capture variables (assuming they are also constant expressions):

Capturing constexpr variable

```cpp
constexpr int add(int const& t, int const& u) { return t + u; }

int main() {
    constexpr int x = 0;
    constexpr auto lam = [&](int n) { return add(x, n); };
    static_assert(lam(10) == 10);
}
```

However, there’s an interesting case where you don’t “pass” a captured variable any further, like:

```cpp
constexpr int x = 0;
constexpr auto lam = [&](int n) { return n + x; };
```

In that case, in Clang, we might get the following warning:

warning: lambda capture ‘x’ is not required to be captured for this use
