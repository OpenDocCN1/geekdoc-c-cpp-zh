The critical thing to remember is while lambdas make it easy and convenient to create a thread, it’s still the asynchronous execution. Closures are not “special” and also vulnerable to all race conditions and blocking.

This is visible in the following example:

```
#include <iostream>
#include <thread>
#include <vector>

int main() {
    int counter = 0;

    auto maxThreads = std::hardware_concurrency();
    std::vector<std::thread> threads(maxThreads);
    for (int t = 0; t < maxThreads; ++t) {
        threads.push_back([&counter]() noexcept {
            for (int i = 0; i < 1000; ++i) {
                counter++;
                counter--;
                counter++;
                counter--;
            }
        });
    }

    for (auto &thread : threads) {
        thread.join();
    }

    std::cout << counter << std::endl;
}
```

In the example, we’re creating several threads 13, and each thread performs some computations on the counter variable. The variable is shared among all the threads.

> In C++20 you can use std::thread which is a thread that joins on destruction and also accepts stop tokens. This new kind of threading object allows more control for the thread execution.

While you might expect to see 0 as the final value of counter , the result is undefined. One thread can read the value while others might simultaneously write to it, causing the final result to be non-deterministic.
