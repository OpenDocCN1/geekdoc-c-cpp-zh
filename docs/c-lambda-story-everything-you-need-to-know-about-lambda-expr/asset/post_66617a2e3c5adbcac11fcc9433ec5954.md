
```cpp
int main () {
  struct PrintFunctor {
    void operator () (int x) const {
      std::cout << x << endl;
    }
  };
  std::vector<int> v(10, 1);
  std::for_each(v.begin(), v.end(), PrintFunctor());
}
```

Try to compile it with -std=c++98 and you'll see the following error on
GCC:

error: template argument for
'template-class__Iter, class__Funct> _Funct
std::for_each(__Iter, __Iter, __Funct)
uses local type 'Main::PrintFunctor'

Basically, in C++98/03, you couldn't instantiate a template with a local type.

Once the limitations are recognised and understood, C++ programmers found
ways to work around the issues with C++98/03. One solution is to prepare a
set of helpers.

# Composing With Functional Helpers

How about having some helpers and predefined functors?

If you check the <functional> header from the Standard Library, you'll find a lot of types and functions that can be immediately used with the standard
alg.

For example:

- std::plus<T>() - takes two arguments and returns their sum.
- std::minus<T>() - takes two arguments and returns their difference.
- std::less<T>() - takes two arguments and returns if the first one is
smaller than the second.
- std::greater_equal<T>() - takes two arguments and returns if the first
is greater or equal to the second.
- std::bind - creates a callable object with the first argument fixed to
the given value.
- std::bind2nd - creates a callable object with the second argument fixed
to the given value.
- and many more.

Let's write some code that benefits from the helpers:

Using old C++98/03 functional helpers. Live code @Wandbox

```cpp
#include <algorithm>
#include <functional>
#include <vector>

int main() {
    std::vector<int> v;
    v.push_back(1);
    v.push_back(2);
    // push_back until 9...
    const size_t smaller5 = std::count_if(v.begin(), v.end(),
        std::bind2nd(std::less<int>(),), 5));

    return smaller5;
}
```

The example uses std::bind2nd and fixes its second argument by using
std::bind2nd. This whole "composition" is passed into count_if. As you
can probably guess, the code expands into a function that performs a simple
comparison:

return x < 5;

If you wanted ready-to-use helpers, then you can also look at the boost
library, for example boost::bind.

Unfortunately, the main issue with this approach is the complexity and hard-
to-learn syntax. for instance writing code that composes two or more
functions is not natural. Have a look below:

Composing functional helpers. Live Code @Wandbox

```cpp
std::vector<int> v;
v.push_back(1);
v.push_back(2);
// push_back until 9...
const size_t val = std::count_if(v.begin(), v.end(),
    std::bind(std::logical_and<bool>(),),
    std::bind(std::greater<int>(),_1, 2),
    std::bind(std::less_equal<int>(),_1, 6)));
```

```cpp
// _1 comes from the std::placeholder namespace
```

The composition uses std::bind (from C++11, so we cheated a bit, it's not
++98/03) with std::greater and std::less_equal connected with
std::logical_and. Additionally, the code uses _1 which is a placeholder for
the first input argument.

While the above code works, you can define it locally, you probably
agree that it's complicated and not natural syntax. To mention that this
composition represents only a simple condition:

```cpp
return x > 2 && x <= 6 ;
```

Is there anything better and more natural to use?

# Motivation for a New Feature

As you can see, in C++98/03, there were several ways to declare and pass a
callable object to algorithms and utilities from the Standard Library.
However, all of those options were a bit limited. For example, you couldn't
declare a local functor object, or it was complicated to compose a function
with functional helper objects.

Fortunately with C++11 we finally saw a lot of improvements!

First of all, the C++ Committee lifted the template
instantiation with a local type. Now you can write functors locally, in the
place where you need them.

What's more, C++11 also brought another idea to life: what if the compiler
could “write” such small functors for developers? That would mean that with
some new syntax, we could create functors “in place” and open the door to
cleaner and compact syntax.

And that was the birth of “lambda expressions”!

If we look at N3337 - the final draft of C++11, we can see a separate section
for lambdas: [expr.prim.lambda].

Let’s have a look at this new feature in the next chapter.

# 2. Lambdas in C++11

Hooray! The C++ Committee heard voices of developers, and since C++11 we got lambda expression!

Lambdas quickly become one of the most recognisable features of modern C++.

You can read the spec located under N3337 - the final draft of C++11.

And the separate section for lambdas: [expr.prim.lambda].

I think the committee added lambdas in a smart way to the language. They incorporate new syntax, but then the compiler “expands” it into an unnamed “hidden” functor object. This way we have all the advantages (and disadvantages) of the real strongly typed language, and it’s relatively easy to reason about the code.

In this chapter, you’ll learn:

- What’s IIFE.

# The Syntax of Lambda

Below you can find a “diagram” that illustrates the syntax for lambdas:

```
[] () qualifiers -> ret {code }
^ ^ ^
| | | optional: return type
| | optional: parameter list
| introducer with optional capture list
```

The last example shows that before the body of the lambda, you can use other specifiers. In the code, we used mutable (so that we can change the captured variable) and noexcept. The third lambda uses mutable and noexcept and they have to appear in that order (so you cannot write mutable as the compiler rejects it).

# A Few Examples of Lambda Expressions:

```cpp
// 1. the simplest lambda expression:
[] {};
```

In the first example, you can see a "minimal" lambda expression. It only needs the [] and then empty {} for function body. The argument list - () - is optional and not needed in this case.

```cpp
// 2. with two params:
[](float f, int a) { return a * f; }
[](int a, int b) { return a < b; };
```

In the second example, probably one of the most, you can see that the arguments are passed into the () section, just like a regular function. The return type is not needed, as the compiler will automatically deduce it.

```cpp
// 3. trailing return type:
[](MyClass t) -> int { auto a = t.compute(a); print(a); return a; };
```

In the above example, we explicitly set a return type. The trailing return type is also available for function declaration since C++11.

```cpp
// 4. additional specifiers:
[x](int a, int b) mutable { return a < b; }
[](float param) noexcept { return param * param; }
[x](int a, int b) mutable noexcept { return a < b; };
```

The last example shows that before the body of the lambda, you can use other specifiers. In the code, we used mutable (so that we can change the captured variable) and noexcept. The third lambda uses mutable and noexcept and they have to appear in that order.

While the () is optional, if you want to apply mutable or noexcept then () to be in the expression:

```cpp
// 5. std::cout << x; // no () needed
[x] std { mutable { ++ x; }; // won't compile!
[]() mutable { ++ x; }; // fine - () required mutable
[] noexcept { }; // won't compile!
() noexcept { }; // fine
```

The same pattern for other specifiers that can be applied on lambdas.
