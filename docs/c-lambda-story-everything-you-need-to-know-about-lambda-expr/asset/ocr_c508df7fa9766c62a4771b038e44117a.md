
The code uses + which is a unary operator. This operator can work on pointers, so the compiler converts our stateless lambda into a function pointer and assigns it to funcPtr. On the other hand, if you remove the plus, then funcPtr is a regular closure object, and that's why the static_assert fails.

While it's probably not the best idea to write such a syntax with "+", it has the same effect if you write static_cast . You can apply this technique in a situation when you don't want the compiler to create too many function instantiations. For example:

Casting to a Function Pointer. Live code @CppInsights

```
template <typename F>
void call_function(F f) {
  f(10);
}

int main() {
  call_function(static_cast<int *>(int int)> ([])(int x){
    return x * 2;
  });
  call_function(static_cast<int *>(int int)> ([])(int x){
    return x * 2;
  });
}
```

In the above example the compiler has create only a single instantiation of call_function - as it only takes a function pointer int (*)int) . But if you remove static_cast s you'll get two versions of call_function as the compiler has to create two separate types for lambdas.

# IIFE - Immediately Invoked Functional Expression

In most of the examples, you could notice that I defined a lambda and then call it later.

However, you can also invoke lambda immediately:

Calling Lambda Now. Live code @Wandbox

```
#include <iostream>
int main() {
  int x = 1, y = 1;
  [&]() noexcept { ++ x; y; }(); // -- call ()
  std::cout << x << " " << y;
}
```
