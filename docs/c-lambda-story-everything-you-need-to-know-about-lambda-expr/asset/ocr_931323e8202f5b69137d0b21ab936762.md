```
// print addresses:
for (auto mit = numbers.begin(); mit != numbers.cend(); ++ mit)
std::cout << " " << mit << " = " << mit->second << "\n";

// each time entry is copied from pair<string, int>
std::for_each(std::begin(numbers), std::end(numbers),
    [](const std::pair<string, int> &entry) {
        std::cout << " " << entry.first << " = " << entry.second << "\n";
        entry.first << " = = " << entry.second << "\n";
    });

// while this entries are not copied, they have the same addresses
std::for_each(std::begin(numbers), std::end(numbers),
    [](const auto &entry) {
        std::cout << " " << entry.first << " = " << entry.second << "\n";
        entry.first << " = = " << entry.second << "\n";
    });
```

The first lines show the addresses of keys and values from the map. Later in lines 4, 5 and 6, you can see three new addresses which are the same, but they are probably temporary copies for the loop iteration. The last three lines illustrate the version with const auto&, and as you can notice, the addresses are the same as in the first three lines.

In our example, we focused on extra copies of keys, but it's vital to understand that also the value is copied. This might not be an issue when you use a cheap-to-copy type like int , but it might cost much more if the objects are larger like strings.
