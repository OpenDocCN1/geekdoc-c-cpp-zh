To create a customer, a list of Sales Regions must be available, so the Customer Repository Fake (as shown in Listing 4-20) uses Constructor Injection to insert the allowable values into the repository. It could have created its own list, but that would have thrown off the binding in XAML since the objects would be different.

What is Fake all about? Unit testers often need to write a test double: an object that fakes, or simulates, a real object. Often, test doubles are the only way to peek inside an otherwise impenetrable object, or the object does things you don't want it to do during testing. The fake SalesRegion repository in Listing 4-20 is an example of a test double. For much more information on Test Doubles and their uses, see the website at http://csharp102.info. Thus, faking certain things for testing purposes is a valid thing to do. Just don't fake the object you're testing. Fake the objects that it makes use of.
