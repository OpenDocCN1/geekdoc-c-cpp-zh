of them depends on the needs of your specific application. For instance, the definition of $n$-Gmaps is “homogeneous”, since all functions are involutions. This simplifies the definitions of related notions and the conception of algorithms. The definition of $n$-maps is more complex since $\beta_1$ is a partial permutation while other $\beta_i$ are partial involutions. However $n$-maps use twice less darts than $n$-Gmaps for representing an orientable object. Thus if memory footprint is a crucial criterion for your application, and if only orientable objects are handled, using $n$-maps is perhaps a better solution. But if nonorientable objects are handled, or if you want to simplify the implementation of operations by avoiding special cases, which are sometimes complex, using $n$-Gmaps is perhaps a better solution.
