As you can see, most of this is trivial. In `Fill()` we pick up the available candy sources and in `Render()` we iterate over them passing information to the view for it to display. Note that we've faked the implementation so far; the candy sources are not going to be "pickable" (the true constant) in all circumstances. `SetView()` and `SetRetriever()` are trivial. The `[NonSerialized]` attribute on `__view` is needed when you use out of process handling of the `Session` state in the ASP.NET application.

When we run the test now, it turns green. Hooray!
