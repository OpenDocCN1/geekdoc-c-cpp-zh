# Complexity of the Binary Search Algorithm

The complexity is measured by the number f(n) of comparisons to locate ITEM in DATA where DATA contains n elements. Observe that each comparison reduces the sample size in half. Hence we require at most f(n) comparisons to locate ITEM where

```
2^{f(n)} > n or equivalently f(n) = \lfloor \log_2 n \rfloor + 1
```

That is, the running time for the worst case is approximately equal to log2 n. One can also show that the running time for the average case is approximately equal to the running time for the worst case.

# Example 4.11

Suppose DATA contains 1 000 000 elements. Observe that 2^{10} = 1024 > 1000 and hence 2^{20} > 1000^2 = 1 000 000 Accordingly, using the binary search algorithm, one requires only about 20 comparisons to find the location of an item in a data array with 1 000 000 elements.
