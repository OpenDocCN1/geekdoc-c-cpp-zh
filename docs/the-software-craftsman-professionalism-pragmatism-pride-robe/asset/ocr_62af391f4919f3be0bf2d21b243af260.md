There are no deadlines, they do not to make money, you control the requirements, and most importantly, you use the technologies and methodologies you want, whatever you want, whatever want. You are the boss. In real projects, a professional software developer would first understand the problem domain, make technical decisions and decide whether to speak to stakeholders, product owners, users, businesses, marketing, and whoever is involved or could contribute to the business. These conversations, in a healthy Agile environment, should happen frequently throughout the project. According to the scope of the project, you can choose the most suitable methodologies to develop the project. Projects are exactly the opposite. We first decide what we want to learn—disciplines, methodologies, and technologies—and then find a problem to solve. It is easier to understand why and how we can use certain technologies if we have a project to try them out. Projects like this allow us to play, experiment, and learn, giving us the experience we need to apply what we have learned to projects.

Another important thing about projects is that we can experience some aspects of a real project. For example, we need to come up with an idea. Once we have an idea, we need to start defining the features and preparing a backlog. Planning means thinking about requirements, making priorities, writing estimations, stories, and splitting tasks. We also need to think about things, how we are going to deploy the application, version control, continuous integration, the user interface, infrastructure code, and databases. As we start using the application, we will learn more about our technology choices. This is exactly what happens in a real project. We do not need to have all in place, but if we can do it. We can use projects to learn any aspect of a real project. We can try to write a business plan for it if we want to learn something about it. Remember, we are the boss and we do whatever we want as long as we are learning. That's the goal.

Above, projects must be fun. A common problem is that developers with projects they are finding is finding a good idea. The good idea is that you are very passionate about it. You are not starting a new business. I always advise developers to choose a subject that they are passionate about. For example, if you want to try, create a website, a mobile app, or a game. You should be motivated with your own work, create an application that you can make whatever you feel like doing. If it is not matter if there are other applications that do want to do. There are different things you would like to do. The advantage of choosing a project you are passionate about is that you will never run out of ideas for it. Environments vary around the project. All things you want to do should be close to the project, and then this will have an enormous impact on your professional career.

A common question is if we should transform our projects into a real business. The answer is, "It depends.\ Normally I would say no to that if you want to have a business, code and learning new technologies should not be your number one priority. I would recommend that you find some material and get yourself familiar with Lean startup before writing a single line of code. The transformation from a project to a real business can be extremely painful and full of disappointments. I believe, I have tried myself. Many of you have got attached to our own applications, making code base, which is messy. I felt we should transform a little Frankenstein project into business, focus on the business first and be ready to throw whatever percentage of what you have written is what the business demands. Detach yourself from the code, clean it up, and leave the bare minimum to satisfy the business.

# Open Source

Open source projects can be very different from projects because they are useful, with few exceptions, very specific in scope. For example, it may be an object-relational (ORM) framework, a library to make web service calls, transaction management, a social network integrator, or so on. All these things are extremely important, necessary and useful, open source projects tend to be one of the libraries your professional applications will use, so not to forget to look at the whole world.

Another thing about open source is a great way to develop developers in action. Looking at how they code and solve problems can be a great way to learn how to code. Besides all of that, it is a great way to raise your professional profile.
