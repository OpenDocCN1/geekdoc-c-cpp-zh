# Blogs

Blogs are popular and a great way to keep ourselves up to date. Quite a few good developers I know and respect just blogs. They have many abandoned blogs. Blogs tend to fit well in the Software Craftsmanship industry because they provide a place to share findings, opinions, successes, and failures in short snippets. # Katas

Katas are simple coding domain that can be understood in a few minutes and are complicated enough to be solved too quickly. They normally take from a few minutes to a few hours to be solved and as a practice to try new techniques and approaches. An example would be a kata where we need to calculate the score of a good game or bowling game tic-tac-toe. We can use these katas to practice things we think we are not good at, like Test-Driven Development, language, or a framework.

Katas have been criticized by some in the Agile world, 'Some people say that it is plain silly to solve the same thing over and over again.' Well, there is some degree of truth to it. Usually it is said because the term comes from martial arts and that it is done in karate. For the example we do something over and again. However, solving katas with our current toolkit (the techniques and tools that we are comfortable with) does not make a lot of sense.

When doing, it is to stretch our outlets, practices, techniques, and technologies that we are not comfortable with, with the intent of getting better at. After practicing these things takes a few times, you may feel for weeks, days, and months before they feel like them. In a professional environment. About like this is exactly what we are trying to achieve.

Katas can be very beneficial when we know how to do them over and again by using a different approach or technique each time. That allows us to experiment and get correct. The correct word to define this practice, according to martial arts, as developers of all the world have already adopted the word kata, is keeping it instead of introducing another term.
