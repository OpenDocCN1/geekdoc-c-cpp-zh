# Refactoring

Refactoring for the sake of refactoring is a waste of time. Unless you have nothing else to do, there is no point in refactoring a piece of code that you don't need to change and spend days refactoring it. The Boy Scout says "leave the floor cleaner than you found it"—if not—"clean the whole until until you can clean the floor spotless." It is a pure waste of time and not very pragmatic.

When working with legacy code, we should always leave the area of code cleaner than we found it. When we need to add a new feature to the code I will usually study the code a little bit and refactor it (if needed) so I can accept the new feature more easily and gracefully.
