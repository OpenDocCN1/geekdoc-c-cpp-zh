## The Unit Test Card

When breaking about development tasks, I have seen many developers created a "unit test" card. The reason was that they wanted to format as time to it. We should never do that.

First, because unit tests are about writing our code and not a separate task we cannot say that a code task is done if it is not tested. Unit tests are one of the best ways to make sure what we are working correctly. We should use unit tests when the requirements change, making sure that it is working and specified by tests. If writing tests is the way to verify that the code implemented, unit tests should be part of each task and not a separate task.

## We Don't Have Time but Apparently Else Does

Imagine the situation above. Imagine an application with hundreds of lines of code. Imagine tests around seven or eight developers. Imagine these tests in five different countries with the same application. Then was the case. There were some tests (black-box tests) that took four hours to run and quite often there there was no really paid attention to them. Can you imagine the amount of wasted time per task or story? Don't forget the quality assurance (QA) team, because apparently testers have all the world on their shoulders. Every small change made, every QA change made. Even longer, time was lost because everyone was busy adding more code to it-code that all the other developers needed to debug. Now how about all the time we spent writing tests every week, every month, every year?
