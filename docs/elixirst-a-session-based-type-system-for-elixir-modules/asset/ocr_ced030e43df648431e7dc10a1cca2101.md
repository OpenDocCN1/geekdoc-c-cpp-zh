We note that, function calls can only transition subject to a well-formed function information environment (\(\Sigma\)) which contains details about all the functions available in the module. Since \(\Sigma\) remains static during transitions, we leave it implicit in the transitions rules.

The transitions are defined by the term transition rules listed in Fig. 8. Rules [RLET], and [RLET$_s$] deal with the evaluation of a `let` statement, \(x = t_1\); \(t_2\) modelling a call-by-value semantic, where the first term \(t_1\) has to transition fully to a value before being substituted for \(x\) in \(t_2\) denoted as \([t_1/v] \cdot t_2\) or \([t_1^{v_1}/v_1 \cdot t_2]\) for multiple substitutions). The send statement, `send`(\(t\), \(\{t_1, v_1, ..., v_n\}\)), evaluates \(t\) in \(t_2\) denoted as each part of the message to a value from left to right. This is carried out via rule [RCHOICE$_s$] which produces no observable side-effects. When the whole message is reduced to a tuple of values \(\{v_1, v_1, ..., v_n\}\), rule [RCHOICE] performs the actual message sending operation. This transition produces an action \(\uparrow\{t_1, v_1, ..., v_n\}\), where the message \(\{t_1, v_1, ..., v_n\}\) is sent to location \(t_1\) through the channel \(t\). A receive statement, `receive` do \(\{t_1:x_1, ..., t_n:x_n\} \rightarrow t_2\) end, is defined by rule [RBRANCH]. When a message is received (i.e., \(\sigma = \{?1, \vec{v}\}\)), it is matched with a value pattern from the received content using the label ?1. Should one of the labels match (\(\vec{j} \in i\) such that \(i_j = 1\)), the payload of the message (\(\vec{v}\)) is compared to the corresponding patterns in the selected branch (\(\vec{p}_j\)) using `match`(\(\vec{p}_j, \vec{v}\)). If the values match with the pattern, the **match** function (Definition 4.1) produces the substitutions \(\sigma\), mapping the matched variables in the pattern \(\vec{p}_j\) to values from \(\vec{v}\). This substitution is then used to instantiate the free values in continuation branch \(t_j\).

# Definition 4.1 (Pattern Matching).

The **match** function pairs patterns with a corresponding value, resulting in a sequence of substitutions (called \(\sigma\)), e.g., **match**(\(p, v\)) = \([v_1/x_1][v_n/x_n]\). The match function builds a meta-level list of substitutions, which should not be confused with the lists defined by the Elixir syntax in Fig. 3.

```
\(\text{\textbf{match}}(\vec{p}, \vec{v}) \stackrel{\text{def}}{=} \text{\textbf{match}}(p_1, v_1), ..., \text{\textbf{match}}(p_n, v_n) \quad \text{where } \vec{p} = p_1, ..., p_n \text{ and } \vec{v} = v_1, ..., v_n\)

\(\text{\textbf{match}}(p, v) \stackrel{\text{def}}{=} \begin{cases} [] & p = b, v = b \\ [/] & p = x \\ \text{\textbf{match}}(w_1, v_1), \text{\textbf{match}}(w_2, v_2) & p = [w_1 | w_2], v = [v_1 | v_2] \\ \text{\textbf{match}}(w_1, v_1), ..., \text{\textbf{match}}(w_n, v_n) & p = \{w_1, ..., w_n\} \text{ and } v = \{v_1, ..., v_n\} \end{cases}\)
```
