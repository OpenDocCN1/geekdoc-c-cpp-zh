
```csharp
static void Main()
{
    // Animal a = new Animal(); // ❌ Error! Cannot instantiate abstract class
    Dog myDog = new Dog(); // ✅ Valid
    myDog.Breathe(); // Inherited method
    myDog.MakeSound(); // Implemented method
}
}
```

```text

```

Abstract classes are used when multiple classes share common logic but differ in implementation of certain behaviors.

Key Points:

- You cannot create an instance of an abstract class.
- You can define methods with logic in abstract classes (called concrete methods).
- You must override abstract methods in derived classes.
- It enforces a contract while allowing shared code to prevent duplication.
- This is especially useful in real-world applications like game engines or UI systems, where base behaviors are consistent across many entities (e.g., all UI elements can "Draw", but each one draws differently).

An abstract class can contain fields, constructors, and implemented methods, unlike interfaces.

If any method is abstract, the class must be declared as abstract.

A class can only inherit one abstract class, supporting C#'s single class inheritance model.

## 26. MULTIPLE INTERFACES, NOT MULTIPLE CLASSES

C# allows a class to implement multiple interfaces, enabling flexibility. However, it can only inherit from one class, avoiding ambiguity from multiple class inheritance.

This example shows a class implementing two interfaces while also inheriting from a single base class.

**[Code Example]**

```csharp
using System;
// Base class
class Machine
{
    public void Start()
    {
        Console.WriteLine("Machine started.");
    }
}

// First interface
interface IPrintable
{
    void Print();
}

// Second interface
interface IScannable
{
    void Scan();
}

// Derived class
class MultifunctionPrinter : Machine, IPrintable, IScannable
{
    public void Print()
    {
        Console.WriteLine("Printing document...");
    }
    public void Scan()
    {
        Console.WriteLine("Scanning document...");
    }
}
class Program
{
    static void Main()
    {
        MultifunctionPrinter mfp = new MultifunctionPrinter();
        mfp.Start();  // Inherited from Machine
        mfp.Print();  // From IPrintable
        mfp.Scan();   // From IScannable
    }
}
```

**[Execution Result]**

```text
Machine started.
Printing document.
Scanning document.
```

C# doesn’t support multiple inheritance for classes to avoid the diamond problem—a situation where the compiler cannot determine which version of a method to inherit if the same method exists in multiple base classes.

Instead, C# allows you to implement multiple interfaces, which contain only method declarations and no implementation. This avoids ambiguity and maintains flexibility.

Real-world analogy:

Think of a smartphone. It could be a Device (base class), and also implement features like ICamera, IMusicPlayer, and IGPS. These are capabilities described by interfaces.

**[Supplement]**

Interfaces cannot contain any code (prior to C# 8); they only define what should be done, not how.

From C# 8 onwards, interfaces can include default implementations, but this should be used with caution.

Unlike classes, a C# class can implement any number of interfaces, giving it modular abilities.

## 27. ADD METHODS TO EXISTING CLASSES WITHOUT CHANGING THEIR CODE

Extension methods in C# allow you to add new methods to existing types (like classes or structs) without modifying the original source code.

Here’s a simple example where we add a method to the built-in string class that counts the number of words.

**[Code Example]**

```csharp
using System;

public static class StringExtensions
{
    // Define an extension method for the string type
    public static int WordCount(this string str)
    {
        // Split the string by spaces and count the resulting parts
        return str.Split(new char[] { ' ' }, StringSplitOptions.RemoveEmptyEntries).Length;
    }
}

class Program
{
    static void Main()
    {
        string message = "Hello from the C# world!";
        // Call the extension method as if it's a built-in method
        int count = message.WordCount();
        Console.WriteLine("Word count: " + count);
    }
}
```

**[Execution Result]**

```text
Word count: 5
```

Extension methods are declared in static classes and must be static methods themselves.

The keyword this before the first parameter (this string str) tells the compiler that this method is an extension for the string type.

Once defined, you can use the method as if it's a member of the type you're extending—no special syntax required when calling it.

This is especially useful when working with .NET types or libraries where you can't modify the original source code, but still want to add custom functionality.

They are also commonly used in LINQ, which heavily relies on extension methods.

**[Supplement]**

You must include the namespace where the extension method is defined (using YourNamespace;) in files where you want to use it.

IntelliSense in Visual Studio shows extension methods with a special icon (↓).

Extension methods don't override existing methods—they only work when no instance method with the same signature exists.

## 28. FLEXIBLE PROGRAMMING WITH GENERICS

C# supports generic classes, methods, and interfaces that work with any data type, helping you write reusable and type-safe code.

Below is an example of a generic class that stores a value of any type, and a generic method that swaps two variables.

**[Code Example]**

```csharp
using System;

// A generic class that can hold any data type
class Box<T>
{
    public T Value;
    public Box(T value)
    {
        Value = value;
    }
    public void Display()
    {
        Console.WriteLine("Box holds: " + Value);
    }
}

class Program
{
    // A generic method to swap two values
    static void Swap<T>(ref T a, ref T b)
    {
        T temp = a;
        a = b;
        b = temp;
    }
    static void Main()
    {
        // Using the generic Box class
        Box<int> intBox = new Box<int>(123);
        Box<string> strBox = new Box<string>("C# Rocks");
        intBox.Display(); // Outputs: Box holds: 123
        strBox.Display(); // Outputs: Box holds: C# Rocks
        // Using the generic Swap method
        int x = 1, y = 2;
        Swap(ref x, ref y);
        Console.WriteLine("x: " + x + ", y: " + y); // x: 2, y: 1
    }
}
```

**[Execution Result]**

```text
Box holds: 123
Box holds: C# Rocks
x: 2, y: 1
```

Generics allow you to write flexible, reusable code without sacrificing type safety.

The Box<T> class defines a type parameter T, which stands for "any type". When you create an object of this class, you specify the actual type (like int or string).

The Swap<T> method works with any data type and doesn't require code duplication for each type.

Generics are incredibly important for writing libraries, data structures, and utility functions. They eliminate the need for casting and boxing/unboxing, which makes your code faster and safer.

**[Supplement]**

Common built-in .NET generic types include List<T>, Dictionary<TKey, TValue>, and Nullable<T>.

You can constrain generic parameters using where clauses (e.g., where T : class).

Generics are heavily used in LINQ and collections like List<T> and Queue<T>.
