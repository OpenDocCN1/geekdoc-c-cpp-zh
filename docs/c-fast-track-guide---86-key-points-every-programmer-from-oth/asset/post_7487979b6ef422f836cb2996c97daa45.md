
## 34. USING TUPLES TO RETURN MULTIPLE VALUES

Tuples allow you to return multiple values from a method without creating a class or struct. They are lightweight, flexible, and readable.

This example shows how to return multiple values using a tuple and how to access those values.

[Code Example]

```csharp
using System;

class Program
{
    // A method returning a tuple with two values
    static (string name, int age) GetPerson()
    {
        return ("Bob", 28);
    }

    static void Main()
    {
        // Receiving the tuple result
        var person = GetPerson();
        // Accessing tuple values by name
        Console.WriteLine($"Name: {person.name}, Age: {person.age}");
    }
}
```

[Execution Result]

Name: Bob, Age: 28

The method GetPerson() returns a tuple of (string name, int age). This is much cleaner than creating a custom class just to return two values.

Key things to know:

- You can name the fields (name, age) for readability.
- Tuples are mutable, unlike anonymous types. You can change their fields after creation.
- You can use tuple deconstruction like this:

  ```csharp
  var (n, a) = GetPerson();
  Console.WriteLine($"Deconstructed: {n}, {a}");
  ```

C# tuples are different from System.Tuple<> introduced in earlier versions — the modern (T1, T2) syntax is more powerful and readable.

[Supplement]

Tuples are value types (structs), so they are stored on the stack unless boxed.

You can return tuples from methods, pass them as parameters, and use them in pattern matching.

If you need semantic meaning or methods, consider using a record or a class instead of tuples.

## 35. UNDERSTANDING C# RECORDS FOR IMMUTABLE DATA STRUCTURES

Records in C# are a type of reference object meant to store data immutably. Once created, their data cannot be changed.

Here’s a basic example of using a C# record to represent a person, showing how the data stays fixed after creation.

[Code Example]

```csharp
// Define a record type with two properties
public record Person(string FirstName, string LastName);

class Program
{
    static void Main()
    {
        // Create a new record instance
        var person1 = new Person("Alice", "Smith");
        // Use 'with' expression to create a new record with one changed property
        var person2 = person1 with { LastName = "Johnson" };
        Console.WriteLine(person1); // Output: Person { FirstName = Alice, LastName = Smith }
        Console.WriteLine(person2); // Output: Person { FirstName = Alice, LastName = Johnson }
    }
}
```

[Execution Result]

Person { FirstName = Alice, LastName = Smith }

Person { FirstName = Alice, LastName = Johnson }

Record types in C# were introduced in C# 9.

They are immutable by default, meaning their values can't be changed after creation.

You can use the with expression to create a copy with modified values.

Unlike classes, records provide value-based equality — two records with the same data are considered equal.

This is great for scenarios like DTOs (Data Transfer Objects), configurations, or event data.

Comparison vs. class:

- class: reference equality — same object in memory.
- record: value equality — same data content.

Why immutability matters:

- Avoids bugs caused by unexpected changes to data.
- Easier to reason about in multithreaded environments.

[Supplement]

Records can also have methods, constructors, and inheritance.

You can define records with property declarations (record Person { string FirstName; string LastName; }), but using positional syntax (like above) is more concise.

A record is still a reference type under the hood, even though it behaves like a value type in many ways.

## 36. USING INDEXERS TO MAKE OBJECTS ACT LIKE ARRAYS

Indexers allow a class or struct to expose array-like syntax for accessing its internal data.

This simple example shows how to implement an indexer to access elements of a collection-like class using square bracket syntax.

[Code Example]

```csharp
using System;

class Week
{
    private string[] days = { "Sunday", "Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday" };

    // Indexer declaration
    public string this[int index]
    {
        get { return days[index]; }
        set { days[index] = value; }
    }
}

class Program
{
    static void Main()
    {
        Week week = new Week();
        Console.WriteLine(week[0]); // Access like an array: Sunday
        week[0] = "Funday"; // Modify value using indexer
        Console.WriteLine(week[0]); // Now: Funday
    }
}
```

[Execution Result]

Sunday

Funday

- Indexers let you use array syntax ([]) on objects, making them feel more intuitive.
- You define them using the this keyword inside a class.
- They can be read-only, write-only, or read/write.
- Useful when you’re building classes that manage collections or want a cleaner API.

Syntax:

```csharp
public returnType this[parameter]
{
    get { ... }
    set { ... }
}
```

Behind the scenes, indexers are just special methods (get_Item, set_Item), but to the user, they behave like arrays.

[Supplement]

You can overload indexers — for example, this[string name] and this[int index] can coexist.

## 37. CUSTOM BEHAVIOR FOR OPERATORS USING OVERLOADING

Operator overloading allows developers to redefine how standard operators (like +, -, ==) behave for custom classes.

The following code demonstrates how to overload the + operator for a simple Point class so that two points can be added together intuitively.

[Code Example]

```csharp
using System;

class Point
{
    public int X, Y;

    public Point(int x, int y)
    {
        X = x;
        Y = y;
    }

    // Overload the + operator to add two Point objects
    public static Point operator +(Point a, Point b)
    {
        return new Point(a.X + b.X, a.Y + b.Y);
    }

    public override string ToString()
    {
        return $"({X}, {Y})";
    }
}

class Program
{
    static void Main()
    {
        Point p1 = new Point(3, 4);
        Point p2 = new Point(1, 2);
        Point result = p1 + p2; // This uses our overloaded + operator
        Console.WriteLine(result); // Output: (4, 6)
    }
}
```

[Execution Result]

(4, 6)

In C#, operator overloading allows you to define how an operator behaves when used with instances of a user-defined class. In the example above:

Point is a class with two integer fields: X and Y.

The static method operator + takes two Point instances and returns a new Point with summed coordinates.

This makes p1 + p2 possible, just like with primitive types.

Overloading operators makes your custom types easier and more intuitive to use, especially when the type represents something mathematical or logical (like vectors, complex numbers, etc.).

Important rules:

- Not all operators can be overloaded (e.g., &&, || must be overloaded with true and false).
- Overloaded operators must be public static.
- It improves code readability but should not be overused, or it may confuse other developers.

## 38. CUSTOM TYPE CONVERSION USING EXPLICIT AND IMPLICIT OPERATORS

Explicit and implicit conversion operators allow developers to define how one custom type can be converted to another type, or vice versa.

The following code demonstrates both explicit and implicit conversions between a Celsius class and a Fahrenheit class.

[Code Example]

```csharp
using System;

class Celsius
{
    public double Degrees;

    public Celsius(double degrees)
    {
        Degrees = degrees;
    }

    // Implicit conversion from double to Celsius
    public static implicit operator Celsius(double d)
    {
        return new Celsius(d);
    }

    // Explicit conversion from Celsius to Fahrenheit
    public static explicit operator Fahrenheit(Celsius c)
    {
        return new Fahrenheit(c.Degrees * 9 / 5 + 32);
    }

    public override string ToString()
    {
        return $"{Degrees} °C";
    }
}

class Fahrenheit
{
    public double Degrees;

    public Fahrenheit(double degrees)
    {
        Degrees = degrees;
    }

    public override string ToString()
    {
        return $"{Degrees} °F";
    }
}

class Program
{
    static void Main()
    {
        Celsius c = 25.0; // implicit conversion from double to Celsius
        Fahrenheit f = (Fahrenheit)c; // explicit conversion from Celsius to Fahrenheit
        Console.WriteLine(c); // Output: 25 °C
        Console.WriteLine(f); // Output: 77 °F
    }
}
```

[Execution Result]

25 °C

77 °F
