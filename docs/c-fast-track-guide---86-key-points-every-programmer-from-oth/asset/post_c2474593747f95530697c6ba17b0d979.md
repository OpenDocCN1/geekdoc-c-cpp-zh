
Hot Reload is a feature introduced in .NET 6 and improved in .NET 7 and beyond.

It allows you to change your code while the application is running, especially when debugging.

This is useful because:

- You don’t have to stop and rebuild the app.
- You can test small tweaks in real-time.
- You stay in the "flow" of debugging.

### How to use it:

- Open your project in Visual Studio or run from CLI with dotnet watch.
- Start the app in debug mode.
- Make changes in your code (like editing a message or logic).
- If Hot Reload supports it, it will automatically apply your changes.

### Important Notes:

- Works best with ASP.NET Core, WPF, WinForms, Console Apps.
- Not all changes are reloadable (e.g., changing class/struct definitions sometimes requires a rebuild).
- Visual Studio usually shows a lightning bolt [] icon when Hot Reload applies your code.

### [Supplement]

Hot Reload internally uses the Edit and Continue (EnC) feature of the .NET runtime.

You can trigger Hot Reload manually in Visual Studio using the Ctrl + Alt + F10 shortcut.

Some frameworks (like Blazor) support blazing fast UI Hot Reload, making frontend development extremely productive.

## 88. RAPID DEV CYCLES WITH DOTNET WATCH

The dotnet watch command automatically re-runs your project when you make changes to source files.

Use dotnet watch to continuously monitor your code and rerun your app instantly upon edits. Great for fast feedback loops.

### [Code Example]

```text
# Open a terminal in your project directory and run:
dotnet watch run
// Example: Program.cs
Console.WriteLine("This is the initial version.");
// After saving changes while dotnet watch is running:
Console.WriteLine("Code updated! dotnet watch reloaded the app.");
```

### [Execution Result]

```text
Terminal output:
dotnet watch □ started
watch : Started
This is the initial version.
watch : File changed: Program.cs
watch : Restarting
Code updated! dotnet watch reloaded the app.
```

dotnet watch is part of the .NET CLI toolset and works like a live observer of your project.

### Why it’s useful:

- It automatically recompiles and reruns your project when changes are saved.
- Perfect for Console Apps, APIs, or Blazor development.
- Saves time and avoids the boring manual stop-run cycle.

### How it works:

- Watches for changes in .cs files (and other relevant files).
- Triggers a rebuild and relaunches the app.
- Works with run, test, build, etc. Example:

dotnet watch test reruns your tests on every file change.

### When to use:

- During development of apps where instant feedback helps.
- When tweaking small bits of logic frequently.

### [Supplement]

dotnet watch can be configured using a watch section in your project’s .csproj file to ignore or include certain files.

It internally uses file system watchers to detect changes efficiently.

You can pass arguments too:

```text
dotnet watch run --my-arg value
```
