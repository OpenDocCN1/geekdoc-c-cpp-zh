
`Action<T>` is similar but returns nothing (void).

You can also use `Predicate<T>` if you need to return a bool.

Using these:

- You can store logic in variables.
- You can pass functions to other methods (great for callbacks, filtering, etc.).
- Makes code more modular and testable.

In Main, we assign an anonymous method (lambda expression) to `add` and `printMessage`.

The syntax `(a, b) => a + b` is a concise way to define a small function.

### [Supplement]

Delegates are the foundation of events, LINQ, and async programming in C#.

You can combine `Func<>` and `Action<>` with LINQ to write very expressive code.

`Func<>` can have up to 16 input parameters, but it's usually better to limit that for readability.

## 63. Running Tasks in Parallel with System.Threading.Tasks.Parallel

![](img/bb6e93ece31f33afd31e933e9dd494be_182_3.png)

The `System.Threading.Tasks.Parallel` class allows you to execute multiple tasks concurrently, taking full advantage of multi-core processors.

Here’s a simple example using `Parallel.For` to process multiple items simultaneously.

### [Code Example]

```csharp
using System;
using System.Threading.Tasks;

class Program
{
    static void Main()
    {
        // Using Parallel.For to process numbers from 0 to 4 in parallel
        Parallel.For(0, 5, i =>
        {
            Console.WriteLine($"Processing index {i} on thread {System.Threading.Thread.CurrentThread.ManagedThreadId}");
        });
    }
}
```

```text

Processing index 1 on thread 6

Processing index 2 on thread 7

Processing index 3 on thread 5

```

![](img/bb6e93ece31f33afd31e933e9dd494be_183_1.png)

`Parallel.For(start, end, action)` is like a regular for loop, but iterations can run simultaneously across multiple threads.

The `i => { ... }` is a lambda function that specifies what to do for each index.

This parallelism is handled by the .NET Task Parallel Library (TPL), which efficiently manages thread usage behind the scenes.

This approach is beneficial when the loop body contains CPU-bound operations and iterations are independent of each other.

## 64. THREAD-SAFE COLLECTIONS WITH SYSTEM.COLLECTIONS.CONCURRENT

The `System.Collections.Concurrent` namespace provides collections that are safe to use across multiple threads without additional locking.

This example demonstrates how to use `ConcurrentDictionary`, a dictionary designed to be thread-safe.

### [Code Example]

```csharp
using System;
using System.Collections.Concurrent;
using System.Threading.Tasks;

class Program
{
    static void Main()
    {
        var dict = new ConcurrentDictionary<int, string>();

        // Run 3 tasks in parallel to add items to the dictionary
        Parallel.For(0, 3, i =>
        {
            dict.TryAdd(i, $"Value {i}");
        });

        // Display the dictionary content
        foreach (var kvp in dict)
        {
            Console.WriteLine($"Key: {kvp.Key}, Value: {kvp.Value}");
        }
    }
}
```

### [Execution Result]

```text
Key: 0, Value: Value 0
Key: 1, Value: Value 1
Key: 2, Value: Value 2
(Order may vary)
```

In a multithreaded context, using standard collections like `Dictionary` can lead to exceptions or corrupted data if multiple threads access it simultaneously.

`ConcurrentDictionary` ensures that operations like Add, Update, and Get are thread-safe by handling internal locking mechanisms.

Here, `TryAdd` is used to safely insert a new key-value pair without risking race conditions.

The `Parallel.For` ensures that multiple threads are trying to add values at the same time — a perfect way to demonstrate thread safety.

For beginners:

- You don't need to write manual lock statements.
- Thread-safe collections help avoid bugs that are hard to find and fix.
- Ideal for producer-consumer patterns and real-time data processing.

### [Supplement]

Other thread-safe collections include: `ConcurrentQueue<T>`, `ConcurrentStack<T>`, `ConcurrentBag<T>`, and `BlockingCollection<T>`.

## 65. Memory Leaks from Event Handlers and Circular References

![](img/bb6e93ece31f33afd31e933e9dd494be_188_3.png)

Memory leaks can still occur in C#, especially when event handlers are not properly unsubscribed, or when circular references prevent the garbage collector from releasing objects.

This example demonstrates how memory leaks can occur if an object subscribes to an event but is never unsubscribed, even after it's no longer needed.

### [Code Example]

```csharp
using System;

class Publisher
{
    public event EventHandler SomethingHappened;

    public void TriggerEvent() => SomethingHappened?.Invoke(this, EventArgs.Empty);
}

class Subscriber
{
    public Subscriber(Publisher publisher)
    {
        // This subscription causes the publisher to hold a reference to this object
        publisher.SomethingHappened += HandleEvent;
    }

    private void HandleEvent(object sender, EventArgs e)
    {
        Console.WriteLine("Event received.");
    }

    ~Subscriber()
    {
        Console.WriteLine("Subscriber finalized (GC).");
    }
}

class Program
{
    static void Main()
    {
        Publisher publisher = new Publisher();
        CreateLeak(publisher);
        GC.Collect();
        GC.WaitForPendingFinalizers();
        Console.WriteLine("Finished GC.");
    }

    static void CreateLeak(Publisher publisher)
    {
        // The subscriber is out of scope, but still referenced by the publisher
        Subscriber sub = new Subscriber(publisher);
    }
}
```

![](img/bb6e93ece31f33afd31e933e9dd494be_190_0.png)

### [Execution Result]

```text
Finished GC.

(Notice: "Subscriber finalized (GC)." is NOT printed, showing it's still in memory)
```

![](img/bb6e93ece31f33afd31e933e9dd494be_190_1.png)

In this code, `Subscriber` subscribes to an event on the `Publisher`. Even though `sub` goes out of scope after `CreateLeak`, the `Publisher` still holds a reference to the `Subscriber` through the event handler. Therefore, the garbage collector cannot clean it up. The destructor (`~Subscriber()`) is never called, proving the object is still alive in memory.

To prevent this, always unsubscribe from events when your object no longer needs them, especially in long-living publishers like static classes or global singletons.

You can unsubscribe using:

```csharp
publisher.SomethingHappened -= HandleEvent;
```

Alternatively, use weak references or `WeakEventManager` patterns for advanced scenarios.

![](img/bb6e93ece31f33afd31e933e9dd494be_190_2.png)

### [Supplement]

C#'s garbage collector cannot automatically clean up references held by event subscriptions.

This is one of the most common causes of memory leaks in GUI apps (like WPF/WinForms).

Always treat events as references: subscribing means "holding on" to an object.

## 66. Why Forcing Garbage Collection with GC.Collect() Is Risky

![](img/bb6e93ece31f33afd31e933e9dd494be_192_3.png)

Although it's possible to manually trigger garbage collection using `GC.Collect()`, doing so is discouraged unless under very specific and advanced scenarios.

This example shows how to manually trigger garbage collection and what happens when you force it—along with why it's usually a bad idea.

### [Code Example]

```csharp
using System;

class Test
{
    ~Test()
    {
        Console.WriteLine("Finalizer called.");
    }
}

class Program
{
    static void Main()
    {
        CreateAndForget();

        // Force garbage collection
        GC.Collect();
        GC.WaitForPendingFinalizers();
        Console.WriteLine("GC forced manually.");
    }

    static void CreateAndForget()
    {
        Test t = new Test();
        // 't' goes out of scope here, eligible for GC
    }
}
```

![](img/bb6e93ece31f33afd31e933e9dd494be_193_0.png)

### [Execution Result]

```text
Finalizer called.

GC forced manually.
```

![](img/bb6e93ece31f33afd31e933e9dd494be_193_1.png)

Normally, C#'s garbage collector runs automatically in the background. It decides the best time to clean up unused memory to avoid performance issues.
