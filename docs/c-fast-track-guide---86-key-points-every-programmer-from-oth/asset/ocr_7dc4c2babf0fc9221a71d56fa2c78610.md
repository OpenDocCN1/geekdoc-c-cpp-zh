The C# runtime includes an automatic garbage collector that periodically checks for objects that are no longer accessible and frees their memory. This helps prevent memory leaks and simplifies memory management.

+   - Objects allocated in memory are stored in the managed heap.
+   - When an object is no longer referenced, the GC considers it for collection.
+   - GC runs automatically, but developers can trigger it manually using `GC.Collect()`, though this is generally discouraged as the runtime optimizes it better.

# #### **GC Performance Considerations**

+   - **Generational GC:** The GC categorizes objects into three generations (0, 1, 2). Objects that survive multiple collections move to older generations for efficiency.
+   - **Dispose and Finalize:** While GC manages most objects, some (like those with unmanaged resources) may require manual cleanup using `IDisposable` and `Dispose()`.
