
```csharp
Report report = new Report();
Printer<Report> printer = new Printer<Report>();
printer.PrintItem(report);
}
}
```

### [Execution Result]

Printing report...

This example defines a generic class `Printer<T>` with a `where T : IPrintable` constraint. This means you cannot use `Printer<T>` with any type that does not implement `IPrintable`.

The benefit of this is type safety—the compiler knows that `T` will always have a `Print()` method, so you avoid runtime errors.

You can use multiple constraints as well:

```csharp
where T : class, new(), IPrintable
```

This means:

- `T` must be a class (not a struct),
- must have a parameterless constructor (`new()`),
- and must implement `IPrintable`.

Constraints are powerful tools to write reusable but safe code.

### [Supplement]

You can constrain generic parameters to base classes, interfaces, or to `struct`, `class`, or `new()`.

The `where` clause helps with IntelliSense suggestions in IDEs since the compiler knows more about the type.

A generic method can have different constraints than the class it's in.

Constraints are only enforced at compile time, which boosts reliability without runtime checks.

The `dynamic` keyword disables compile-time checking. The compiler trusts that whatever you're trying to do will work at runtime.

This is helpful when:

- Using COM objects or interacting with dynamic languages like Python or JavaScript.
- Reading JSON or XML where types are not known at compile time.

But it’s dangerous:

If you call a method that doesn’t exist, the program will compile successfully, but crash at runtime with a `RuntimeBinderException`.

Using `dynamic` trades safety for flexibility. Use it only when absolutely necessary and when you're confident about the runtime behavior.

### [Supplement]

`dynamic` was introduced in C# 4.0.

It is part of the DLR (Dynamic Language Runtime).

Any operation on a dynamic variable is resolved at runtime, unlike `var` which is resolved at compile time.

IDEs usually won’t provide IntelliSense for dynamic objects.

## 31. INSPECT AND USE TYPES AT RUNTIME WITH REFLECTION

Reflection lets you inspect and interact with types (classes, methods, properties, etc.) during runtime in C#.

Here's a simple example of using reflection to inspect a class and invoke a method dynamically.

### [Code Example]

```csharp
using System;
using System.Reflection;

public class HelloWorld
{
    public void SayHello()
    {
        Console.WriteLine("Hello from reflection!");
    }
}

class Program
{
    static void Main()
    {
        // Get the type info of the HelloWorld class
        Type type = typeof(HelloWorld);

        // Create an instance of HelloWorld dynamically
        object instance = Activator.CreateInstance(type);

        // Get the method info for SayHello
        MethodInfo method = type.GetMethod("SayHello");

        // Invoke the SayHello method on the instance
        method.Invoke(instance, null);
    }
}
```

### [Execution Result]

Hello from reflection!

### Step-by-step explanation:

- `typeof(HelloWorld)` gets the `Type` object for the `HelloWorld` class. This object contains metadata about the class.
- `Activator.CreateInstance(type)` dynamically creates an instance of `HelloWorld`. You don’t need to use `new HelloWorld()` directly.
- `type.GetMethod("SayHello")` retrieves metadata about the method named `"SayHello"`.
- `method.Invoke(instance, null)` actually calls the method on the created instance.

### Why is this powerful?

- You can build flexible systems, like plugin loaders, object mappers, or test frameworks.
- Useful when you don’t know the exact types at compile-time.

### Common pitfalls:

- Reflection is slower than direct calls.
- You lose compile-time checking — misspelled method names won’t be caught until runtime.

### [Supplement]

- Reflection is part of the `System.Reflection` namespace.
- You can inspect fields, properties, constructors, interfaces, and more — not just methods.
- ASP.NET Core uses reflection internally for dependency injection and routing.
- You can combine reflection with custom attributes for powerful behaviors.

## 32. USING ATTRIBUTES AS METADATA TAGS

Attributes are like special tags added to your code. They add extra information (metadata) that tools or reflection-based code can read.

Here’s an example of defining and reading a custom attribute using reflection.

### [Code Example]

```csharp
using System;
using System.Reflection;

// Define a custom attribute
[AttributeUsage(AttributeTargets.Class)]
public class InfoAttribute : Attribute
{
    public string Message { get; }
    public InfoAttribute(string message)
    {
        Message = message;
    }
}

// Apply the custom attribute to a class
[Info("This class does something important.")]
public class ImportantClass
{
}

class Program
{
    static void Main()
    {
        // Get type information
        Type type = typeof(ImportantClass);
        // Check if the attribute is applied
        if (Attribute.IsDefined(type, typeof(InfoAttribute)))
        {
            // Get the attribute instance
            InfoAttribute attr = (InfoAttribute)Attribute.GetCustomAttribute(type, typeof(InfoAttribute));
            Console.WriteLine("Attribute message: " + attr.Message);
        }
    }
}
```

### [Execution Result]

Attribute message: This class does something important.

### Step-by-step explanation:

- `[AttributeUsage(AttributeTargets.Class)]` specifies where the attribute can be used (e.g., on classes).
- `InfoAttribute` is a custom attribute class that stores a message.
- `[Info("...")]` applies the attribute to the `ImportantClass`.
- `Attribute.IsDefined(...)` checks if the attribute is present.
- `Attribute.GetCustomAttribute(...)` retrieves the actual instance, so you can read the `Message` property.

### Why use attributes?

- They add structured, retrievable metadata.
- Common in frameworks — for example, `[Serializable]`, `[Obsolete]`, or `[HttpGet]`.

### Real-world usage:

- In ASP.NET, attributes define routes: `[HttpPost("login")]`
- In unit testing: `[TestMethod]`
- In Unity game development: `[SerializeField]`

### [Supplement]

- Attributes must inherit from `System.Attribute`.
- Built-in attributes include `[Obsolete]`, `[Serializable]`, `[DllImport]`, etc.
- You can define positional and named parameters inside attribute constructors.
- Reflection is used to access these attributes at runtime, making them powerful for framework-level decisions.

## 33. ANONYMOUS TYPES ARE IMMUTABLE AND DEFINED AT COMPILE-TIME

Anonymous types are objects without explicitly defined class names. They are used for quick grouping of data, especially useful in LINQ queries. Once created, their properties are read-only and cannot be changed.

Here's a short example that creates and uses an anonymous type.

### [Code Example]

```csharp
using System;

class Program
{
    static void Main()
    {
        // Creating an anonymous type with two properties
        var person = new { Name = "Alice", Age = 30 };
        // Accessing the properties
        Console.WriteLine($"Name: {person.Name}, Age: {person.Age}");
        // person.Age = 31; // This line would cause a compile-time error because properties are read-only
    }
}
```

### [Execution Result]

Name: Alice, Age: 30

Anonymous types are defined using the `new { }` syntax. They are mostly used when:

- You need a simple data structure for temporary use.
- You don’t want to create a full class for holding just a few pieces of data.

The compiler automatically infers the type and generates a class with read-only properties. You can only define them inside a method (not as a class member).

### Important:

- You can’t add methods to anonymous types.
- Once created, you cannot modify or add new properties.
- You cannot return anonymous types from methods unless using `dynamic` or returning to the same scope where it was created.

### [Supplement]

- Anonymous types are reference types.
- Their property names and types determine their type identity — if two anonymous types have the same properties and order, they are considered the same type only within the same assembly.
- They are commonly used with LINQ for projecting data into new shapes without defining new types.
