A switch expression is an expression (returns a value), not a statement.

That means it can directly be used to assign values, like in:

```csharp
string result = input switch { ... };
```

This differs from the classic switch statement which requires case blocks and break keywords, often making the code longer and more error-prone.

Also note:

- The `_` symbol means "any other case", i.e., the default.
- You can use pattern matching (e.g., ranges, types) inside switch expressions.
- The `or` keyword allows combining multiple conditions for one result.
- This is great for data mapping, UI logic, or simplifying if-else chains into a single expression.

### [Supplement]

switch expressions were introduced in C# 8.0. They support advanced patterns like type checks, relational patterns (e.g., <, >=), tuple patterns, and more. They encourage functional-style programming where functions return values directly from expressions.

In older C# versions, you’d have to write:

```csharp
if (pet is Dog)
{
    Dog d = (Dog)pet;
```

But with `is` + variable declaration (`is Dog d`), you both check and cast at the same time. This is:

- More concise: fewer lines.
- Safer: no accidental invalid casts.
- Scoped: the variable `d` only exists inside the `if` block.

This pattern is called type pattern matching, and it’s a clean, modern way to handle polymorphism in C#.

This becomes even more powerful with newer C# versions supporting nested patterns and the switch expression.

## 45. GETTING STRING NAMES OF VARIABLES AND MEMBERS WITH NAMEOF

The `nameof` operator returns the name of a variable, method, or property as a string.

This example shows how to use `nameof` to get the names of members without hardcoding strings.

### Code Example

```csharp
using System;
class Person
{
    public string FirstName { get; set; }
    public void SayHello()
    {
        Console.WriteLine("Hello!");
    }
}
class Program
{
    static void Main()
    {
        // Get the name of the property
        string propertyName = nameof(Person.FirstName);
        // Get the name of the method
        string methodName = nameof(Person.SayHello);
        // Get the name of a variable
        int age = 30;
        string variableName = nameof(age);
        Console.WriteLine(propertyName); // Output: FirstName
        Console.WriteLine(methodName); // Output: SayHello
        Console.WriteLine(variableName); // Output: age
    }
}
```

### Execution Result

FirstName
SayHello
age

The `nameof` operator is extremely useful for avoiding hardcoded strings in code, especially when working with things like logging, debugging, data binding, or implementing `INotifyPropertyChanged`.

For example, if you rename `FirstName`, the compiler will automatically update `nameof(Person.FirstName)`, but not a hardcoded string `"FirstName"`.

This leads to fewer bugs during refactoring and helps maintain cleaner, safer code.

It is evaluated at compile time, so it does not add any runtime overhead.

You can use `nameof` for:

- Local variables
- Class members (methods, properties, fields)
- Parameters
- Types (classes, structs, etc.)

### [Supplement]

- Introduced in C# 6.0
- `nameof` can be used in attributes, logging, exceptions, etc.
- It does not evaluate the expression—it just gives you the name.
- Safer than using magic strings for field/property names.

## 46. LIMITING PROPERTY ASSIGNMENT TO INITIALIZATION WITH INIT

`init` properties allow setting values only during object initialization, making objects more immutable.

This code demonstrates how to use `init` to create a property that can only be set when the object is first created.

### Code Example

```csharp
using System;

class Person
{
    // The 'init' accessor allows this property to be set only during object creation
    public string Name { get; init; }
    // Regular property can be changed anytime
    public int Age { get; set; }
}

class Program
{
    static void Main()
    {
        // Initializing with object initializer
        var person = new Person
        {
            Name = "Alice",
            Age = 30
        };
        Console.WriteLine($"{person.Name}, {person.Age}");
        // person.Name = "Bob"; // Compile-time error: 'init' property cannot be modified after initialization
        person.Age = 31; // 🔒 Allowed
    }
}
```

### Execution Result

Alice, 30

The `init` accessor was introduced in C# 9.0 and is part of the move toward more immutable data structures.

Unlike `set`, `init` allows setting the property only at the time of object creation—either through an object initializer or constructor.

This makes your objects more predictable and safe, especially useful in:

- Domain-driven design (value objects)
- Configuration objects
- Data transfer objects (DTOs)

It also works beautifully with records, which are often immutable by design.

By limiting mutation, `init` helps prevent accidental or unauthorized changes to properties after initialization.

### [Supplement]

- It can be combined with private setters: `public string Name { get; init; }`
- Supports object initializers but disallows modification after construction.
- Works well with immutable record types introduced in C# 9.

Attempting to set an `init` property after construction causes a compile-time error—not a runtime exception.

## 47. PREVENTING INHERITANCE WITH SEALED

The `sealed` keyword in C# prevents other classes from inheriting a class. It ensures that a class cannot be used as a base class.

Here is a basic example showing how the `sealed` keyword is used and what happens when someone tries to inherit from a sealed class.

### Code Example

```csharp
// This is a sealed class. It cannot be inherited.
sealed class Animal {
    public void Speak() {
        Console.WriteLine("The animal makes a sound.");
    }
}

// Trying to inherit from Animal will cause a compile-time error.
// Uncommenting the line below will produce a CS0509 error:
// class Dog : Animal { } // ERROR: cannot derive from sealed type 'Animal'
class Program {
    static void Main() {
        Animal a = new Animal();
        a.Speak(); // Works fine
    }
}
```

### Execution Result

The animal makes a sound.

In C#, inheritance allows you to create a new class based on an existing class. However, sometimes you want to prevent this—maybe for security, performance optimization, or to enforce architectural rules. That’s where the `sealed` keyword comes in.

Declaring a class as `sealed` tells the compiler: “This class is complete. Nobody can extend it.”

If someone tries to inherit from a sealed class, the compiler throws an error like:

"CS0509: 'Dog': cannot derive from sealed type 'Animal'"

You can use `sealed` alone, or also to seal methods in derived classes to prevent further overriding. For example:

```csharp
public sealed override void SomeMethod() { }
```

This is especially common in framework code to prevent misuse or unintended behavior through inheritance.

### [Supplement]

- `sealed` is often used with classes like `System.String`, which is sealed to prevent breaking immutability.
- If a class is sealed, it cannot also be abstract, since abstract requires inheritance.
- Marking a class sealed can allow the JIT compiler to optimize calls (devirtualization), improving performance.

## 48. WORKING WITH POINTERS USING UNSAFE

C# normally protects you from low-level memory access. But using `unsafe` allows you to use pointers, like in C or C++, for advanced memory manipulation.

Here's a simple, safe demo of how to use `unsafe` code to directly manipulate a variable's memory using pointers.

### Code Example

```csharp
using System;

class Program {
    static void Main() {
        int num = 10;

        // unsafe block to work with pointers
        unsafe {
            int* p = &num; // Get the address of num
            *p = 20; // Modify the value at the address
        }

        Console.WriteLine(num); // Output will be 20
    }
}
```

To compile this, you must enable unsafe code:

In Visual Studio: Project Properties → Build → Allow unsafe code

Or with command line:

```text
csc /unsafe Program.cs
```
