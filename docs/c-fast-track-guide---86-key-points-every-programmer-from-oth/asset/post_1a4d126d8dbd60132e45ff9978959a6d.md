
## 16. DELEGATES: PASS FUNCTIONS LIKE VARIABLES

Delegates in C# are type-safe pointers to methods. They allow you to pass methods as arguments or store them in variables.

Here's a basic example of how to define a delegate, assign it to a method, and call it.

[Code Example]

```
using System;

class Program
{
    // Define a delegate type that takes two integers and returns an integer
    delegate int Operation(int x, int y);

    // Method to add two numbers
    static int Add(int a, int b)
    {
        return a + b;
    }

    static void Main()
    {
        // Create a delegate instance and point it to the Add method
        Operation op = Add;

        // Call the method via the delegate
        int result = op(5, 3);
        Console.WriteLine(result); // Output: 8
    }
}
```

[Execution Result]

delegate int Operation(int x, int y); declares a delegate type that expects a method with two int parameters and an int return.

Operation op = Add; binds the delegate to the Add method.

op(5, 3) calls Add(5, 3) indirectly via the delegate.

This is functionally similar to function pointers in C++ but type-safe and secure.

Real-world use cases include:

- Passing logic into methods (like comparison rules for sorting).
- Implementing event systems (delegates are the core of C# events).
- Plugging in different behaviors dynamically at runtime.

### [Supplement]

Delegates are the foundation of events in C#.

Action<>, Func<>, and Predicate<> are built-in generic delegates that simplify delegate usage.

Anonymous methods and lambda expressions can also be assigned to delegates.

Delegates enable decoupling—your code becomes more flexible and testable.

## 17. USING DELEGATES AND EVENTS FOR THE OBSERVER PATTERN

In C#, events use delegates to implement the observer pattern, which allows an object to notify multiple subscribers when something happens.

Here’s a basic example of how events and delegates work to notify multiple listeners about a change.

[Code Example]

```csharp
using System;

// Define a delegate type
public delegate void NotificationHandler(string message);

// Publisher class
class Publisher
{
    // Declare an event using the delegate
    public event NotificationHandler OnNotify;
    public void DoSomething()
    {
        Console.WriteLine("Publisher is doing something important...");
        // Notify all subscribers
        OnNotify?.Invoke("Something happened in Publisher!");
    }
}

// Subscriber class
class Subscriber
{
    private string _name;
    public Subscriber(string name)
    {
        _name = name;
    }
    // Method that matches the delegate signature
    public void Respond(string message)
    {
        Console.WriteLine($"{_name} received: {message}");
    }
}

// Main execution
class Program
{
    static void Main()
    {
        Publisher pub = new Publisher();
        Subscriber sub1 = new Subscriber("Alice");
        Subscriber sub2 = new Subscriber("Bob");
        // Subscribe to the event
        pub.OnNotify += sub1.Respond;
        pub.OnNotify += sub2.Respond;
        // Trigger the event
        pub.DoSomething();
    }
}
```

[Execution Result]

Publisher is doing something important...
Alice received: Something happened in Publisher!
Bob received: Something happened in Publisher!

## 18. USING ASYNC AND AWAIT FOR NON-BLOCKING CODE

C# supports asynchronous programming using async and await to avoid blocking the main thread, especially during I/O operations like web requests or file access.

Here's a simple example that simulates waiting for a task to complete asynchronously without freezing the app.

[Code Example]

```
using System;
using System.Threading.Tasks;
class Program
{
static async Task Main()
{
Console.WriteLine("Starting...");
// Call an async method and await its completion
string result = await DoWorkAsync();
Console.WriteLine($"Result: {result}");
Console.WriteLine("Done.");
}
// Asynchronous method
static async Task<string> DoWorkAsync()
{
Console.WriteLine("Working...");
// Simulate delay (e.g., downloading, processing)
await Task.Delay(2000); // 2 seconds
return "Work complete!";
}
}
```

[Execution Result]

Starting...
Working...
(Result appears after 2 seconds)
Result: Work complete!
Done.

When using async and await, the code looks synchronous but runs asynchronously under the hood:

- async before the method tells the compiler this method may run asynchronously.
- await pauses execution until the awaited task finishes, but does not block the main thread.
- Task.Delay() is like Thread.Sleep() but non-blocking—it gives control back to the runtime while waiting.
- This is especially useful in UI apps or servers where blocking the main thread would freeze the app or cause delays.
- The key benefit: readable asynchronous code that’s easy to maintain.

### [Supplement]

async methods must return Task, Task<T>, or void (only in event handlers).

## 19. USE TASKS FOR ASYNCHRONOUS PROGRAMMING IN C#

TAP (Task-based Asynchronous Pattern) is the standard way to write asynchronous code in C#. It simplifies concurrency using async and await.

Here’s a simple example that fetches data asynchronously and waits for the result using Task and await.

[Code Example]

```csharp
using System;
using System.Net.Http;
using System.Threading.Tasks;
class Program
{
    // Main method must return Task if marked async
    static async Task Main()
    {
        Console.WriteLine("Starting async operation...");
        // Call an asynchronous method
        string data = await GetDataAsync();
        Console.WriteLine("Data received:");
        Console.WriteLine(data);
    }
    // Async method that returns a Task<string>
    static async Task<string> GetDataAsync()
    {
        using HttpClient client = new HttpClient();
        // Await a non-blocking network call
        string result = await client.GetStringAsync("https://example.com");
        return result;
    }
}
```

[Execution Result]

Starting async operation...

Data received:

```
<!doctype html><html>...<body>Example Domain...</body></html>
```

async marks a method as asynchronous.

await pauses execution until the awaited task finishes——without blocking the thread.

HttpClient.GetStringAsync() is non-blocking and returns a Task<string>.

This pattern allows you to keep the application responsive (e.g., UI stays smooth or backend doesn't freeze).

You must return Task or Task<T> from async methods (except for event handlers that return void).

Main() in modern C# can now be async Task Main() (as shown above).

### [Supplement]

TAP replaced older models like APM (Asynchronous Programming Model) and EAP (Event-based Asynchronous Pattern).

You can chain multiple async calls, and error handling with try-catch works naturally with await.

You should avoid .Result or .Wait() on Tasks unless absolutely necessary, as they may cause deadlocks.

## 20. PREVENTING RACE CONDITIONS WITH LOCK IN C#

The lock keyword in C# is used to ensure that only one thread accesses a block of code at a time, preventing race conditions.

Below is an example that safely increments a counter from multiple threads using a lock.

[Code Example]

```csharp
using System;
using System.Threading;
class Program
{
static int counter = 0; // Shared data
static object locker = new object(); // Lock object
static void Main()
{
Thread[] threads = new Thread[10];
// Create and start 10 threads
for (int i = 0; i < 10; i++)
{
threads[i] = new Thread(IncrementCounter);
threads[i].Start();
}
// Wait for all threads to finish
foreach (var thread in threads)
{
thread.Join();
}
Console.WriteLine("Final counter value: " + counter);
}
static void IncrementCounter()
{
    for (int i = 0; i < 1000; i++)
    {
        lock (locker)
        {
            // Only one thread can access this at a time
            counter++;
        }
    }
}
}
```

[Execution Result]

Final counter value: 10000

Without lock, multiple threads could read and write counter at the same time, leading to incorrect results (race condition).

lock (locker) ensures that only one thread can execute the code inside at any moment.

locker must be a private, non-null reference type object. It should not be a value type or a publicly accessible object.

Join() is used to wait for threads to finish before printing the result.

### [Supplement]

lock is syntactic sugar for Monitor.Enter() and Monitor.Exit().
