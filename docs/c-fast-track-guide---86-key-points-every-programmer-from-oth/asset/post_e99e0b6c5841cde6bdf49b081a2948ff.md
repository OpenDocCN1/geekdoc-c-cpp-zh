## 72. USING ENTITY FRAMEWORK CORE FOR DATABASE ACCESS

Entity Framework Core (EF Core) is the default Object-Relational Mapper (ORM) in C#. It helps developers work with databases using C# code instead of writing SQL manually.

This example shows how to define a simple model and use EF Core to insert and retrieve data from an in-memory database.

[Code Example]

```csharp
using Microsoft.EntityFrameworkCore;
using System;
using System.Linq;

// Define a model (table)
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
}
// Define a DbContext (database session)
public class AppDbContext : DbContext
{
    public DbSet<Product> Products { get; set; }
    protected override void OnConfiguring(DbContextOptionsBuilder options)
    => options.UseInMemoryDatabase("TestDb"); // Using an in-memory DB for testing
}
class Program
{
    static void Main()
    {
        using var db = new AppDbContext();
        // Add a new product
        db.Products.Add(new Product { Name = "Apple" });
        db.SaveChanges();
        // Read all products
        var products = db.Products.ToList();
        foreach (var product in products)
            Console.WriteLine($"Product: {product.Name}");
    }
}
```

[Execution Result]

Product: Apple

This program:

- Defines a Product class — a simple table schema.
- Configures EF Core to use an in-memory database (no need for actual DB setup).
- Adds a new product to the database.
- Saves changes with SaveChanges().
- Queries the data and prints it.

EF Core handles all the underlying SQL generation and execution. You work entirely in C# using familiar LINQ methods.

This is extremely helpful for:

- Rapid development
- Unit testing (using in-memory DB)
- Clean, strongly typed access to data

### [Supplement]

EF Core supports major databases like SQL Server, PostgreSQL, SQLite, and more.

You can use Code-First (write models in C#) or Database-First (generate models from DB).

Use `dotnet ef migrations` to generate migration scripts for schema updates.

LINQ (Language Integrated Query) is used for querying the database in C#.

## 73. Lightweight Database Access with Dapper

![](img/bb6e93ece31f33afd31e933e9dd494be_212_3.png)

Dapper is a simple and fast micro-ORM (Object Relational Mapper) for .NET. It enables clean, lightweight access to databases using raw SQL while still mapping results to C# objects.

Here's how to use Dapper to retrieve data from a SQL database in a minimal example.

[Code Example]

```csharp
// Required NuGet package: Dapper

// Required using directives

using System;
using System.Data.SqlClient;
using Dapper;
using System.Collections.Generic;

class Program
{
    // Define a simple data model
    public class User
    {
        public int Id { get; set; }
        public string Name { get; set; }
    }
    static void Main()
    {
        // Connection string (replace with your actual DB details)
        string connectionString =
            "Server=localhost;Database=TestDb;Trusted_Connection=True;";
        using (var connection = new SqlConnection(connectionString))
        {
            // Open the connection
            connection.Open();
            // Execute a query and map results to a list of User objects
            string sql = "SELECT Id, Name FROM Users";
            IEnumerable<User> users = connection.Query<User>(sql);
            // Display the results
            foreach (var user in users)
            {
                Console.WriteLine($"ID: {user.Id}, Name: {user.Name}");
            }
        }
    }
}
```

![](img/bb6e93ece31f33afd31e933e9dd494be_214_0.png)

[Execution Result]

ID: 1, Name: Alice

ID: 2, Name: Bob

ID: 3, Name: Charlie

![](img/bb6e93ece31f33afd31e933e9dd494be_214_1.png)

This example demonstrates the elegance of Dapper:

`Query<T>()` automatically maps SQL result columns to object properties.

No complex configurations or ORM setups are required.

Dapper is very fast because it works close to raw ADO.NET and doesn't track entity states like Entity Framework.

To use this, the Users table must exist in the TestDb database with at least Id and Name columns.

Add Dapper via NuGet with `dotnet add package Dapper`.

Dapper is great for scenarios where:

- You need raw SQL control.
- Performance is critical.
- You prefer simple, clear code over full ORM features.

![](img/bb6e93ece31f33afd31e933e9dd494be_215_0.png)

### [Supplement]

Dapper was created by Stack Overflow developers to handle high-scale database operations.

Unlike Entity Framework, Dapper doesn’t support change tracking — it’s all about retrieval speed.

Dapper can be used with stored procedures as well as inline SQL.

It’s not suitable when you need rich ORM features like lazy loading or complex relationship tracking.
