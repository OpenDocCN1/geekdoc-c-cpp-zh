The dynamic keyword disables compile-time checking. The compiler trusts that whatever you're trying to do will work at runtime.

This is helpful when:

+   - Using COM objects or interacting with dynamic languages like Python or JavaScript.
+   - Reading JSON or XML where types are not known at compile time.

But it’s dangerous:

If you call a method that doesn’t exist, the program will compile successfully, but crash at runtime with a RuntimeBinderException.

Using dynamic trades safety for flexibility. Use it only when absolutely necessary and when you're confident about the runtime behavior.

# [Supplement]

dynamic was introduced in C# 4.0.

It is part of the DLR (Dynamic Language Runtime).

Any operation on a dynamic variable is resolved at runtime, unlike var which is resolved at compile time.

IDEs usually won’t provide IntelliSense for dynamic objects.
