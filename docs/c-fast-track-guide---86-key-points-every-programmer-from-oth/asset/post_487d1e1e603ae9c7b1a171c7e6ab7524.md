
```csharp
var channel = GrpcChannel.ForAddress("https://localhost:5001");
var client = new Greeter.GreeterClient(channel);
var reply = await client.SayHelloAsync(new HelloRequest { Name = "Alice" });
Console.WriteLine(reply.Message);
```

### [Execution Result]

Hello, Alice

Here’s a breakdown of what’s happening:

- .proto files define the contract (like an interface) between client and server.
- These files are compiled using protoc or .NET tooling into C# classes.
- The server implements the service; the client consumes it via a generated client class.
- gRPC uses HTTP/2 under the hood for multiplexed, efficient communication.

To use gRPC in .NET:

- Add Grpc.AspNetCore to the server project.
- Add Grpc.Net.Client to the client project.
- Reference the .proto file in the .csproj with `<Protobuf>` tags.

gRPC is ideal when:

- You have many microservices communicating over the network.
- You need real-time, low-latency data exchange.
- You care about binary efficiency over text-based APIs like REST.

### [Supplement]

- gRPC was developed by Google and is used in production at massive scale.
- It uses Protocol Buffers (protobuf) for message serialization, which is faster and smaller than JSON.
- gRPC supports streaming — not just request/response, but bidirectional and server-side streams.
- gRPC is not ideal for browser-based APIs — although gRPC-Web exists, REST or GraphQL may be easier for frontend.

## 77. SIMPLIFIED WEB DEVELOPMENT WITH RAZOR PAGES

Razor Pages is a page-focused framework in ASP.NET Core that makes web app development easier by combining the controller and view logic into a single .cshtml file.

Below is a basic example of a Razor Page that handles a simple form submission.

### [Code Example]

```
// Pages/Hello.cshtml
@page
@model HelloModel
<h2>Hello Razor Page</h2>
<form method="post">
<input type="text" name="UserName" />
<button type="submit">Submit</button>
</form>
@if (!string.IsNullOrEmpty(Model.Message))
{
<p>@Model.Message</p>
}

// Pages/Hello.cshtml.cs
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.RazorPages;
public class HelloModel : PageModel
{
[BindProperty]
public string UserName { get; set; }
public string Message { get; set; }
public void OnPost()
{
  Message = $"Hello, {UserName}!";
}
}
```

### [Execution Result]

When the user submits their name in the input box and clicks "Submit", the page refreshes and displays:

Hello, [UserName]!

Razor Pages are part of ASP.NET Core and are ideal for scenarios where each page contains its own logic, especially for form-based pages.

- The @page directive at the top tells ASP.NET this is a Razor Page.
- The .cshtml file contains both HTML and Razor syntax (like @Model.Message).
- The associated .cshtml.cs file contains the backend logic.
- OnPost() is automatically called when the form is submitted via POST.
- BindProperty binds the form field to the property.
- This structure avoids needing a separate controller, making Razor Pages less complex than MVC for smaller applications or beginners.

### [Supplement]

- Razor Pages were introduced in ASP.NET Core 2.0.
- They follow the MVVM (Model-View-ViewModel) pattern, making them beginner-friendly.
- Routing is based on folder structure, so Pages/Hello.cshtml is accessible via /Hello.

## 78. Using Docker with C# Apps

![](img/bb6e93ece31f33afd31e933e9dd494be_228_3.png)

C# apps, especially ASP.NET Core ones, can be easily containerized using Docker for consistent deployment across environments.

Here’s how to containerize an ASP.NET Core app using Docker.

### [Code Example]

```dockerfile
# Dockerfile
FROM mcr.microsoft.com/dotnet/aspnet:6.0 AS base
WORKDIR /app
FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app
FROM base AS final
WORKDIR /app
COPY --from=build /app .
ENTRYPOINT ["dotnet", "YourApp.dll"]
# Build the Docker image
```
