
## 58. Organizing Code with Namespaces

Namespaces are used to group related classes, avoid name clashes, and keep code organized.

The following example shows how two classes with the same name can coexist in different namespaces.

### [Code Example]

```csharp
using System;

namespace MyApp.Utilities
{
    class Logger
    {
        public static void Log()
        {
            Console.WriteLine("Logging from Utilities namespace");
        }
    }
}

namespace MyApp.DebugTools
{
    class Logger
    {
        public static void Log()
        {
            Console.WriteLine("Logging from DebugTools namespace");
        }
    }
}

class Program
{
    static void Main()
    {
        // Fully qualify to avoid ambiguity
        MyApp.Utilities.Logger.Log();
        MyApp.DebugTools.Logger.Log();
    }
}
```

### [Execution Result]

- Logging from Utilities namespace
- Logging from DebugTools namespace

Namespaces in C# are like folders for your code. They prevent name conflicts when different parts of your application (or different libraries) use the same class names.

In the example, both Logger classes are valid because they are in different namespaces. You can access either by specifying the full path (MyApp.Utilities.Logger) or by using a using directive.

This is especially important in large projects or when integrating third-party libraries — without namespaces, identical class names would cause compile-time errors.

Also, Visual Studio automatically places files in a namespace that matches the folder structure, encouraging logical organization.

### [Supplement]

- The using directive can simplify access to types in a namespace.
- C# allows nested namespaces: namespace A.B.C is valid.
- The .NET Framework uses namespaces extensively (e.g., System.IO, System.Net, etc.) to group functionality.
- Namespaces are purely organizational — they don’t affect runtime behavior.

## 59. Splitting One Class into Multiple Files Using Partial Classes

![](img/bb6e93ece31f33afd31e933e9dd494be_172_3.png)

Partial classes let developers split the definition of a single class across multiple files.

This is useful when working on large classes or when auto-generated code and custom code need to coexist without conflict.

### [Code Example]

```csharp
// File: MyClass.Part1.cs

public partial class MyClass
{
    public void SayHello()
    {
        Console.WriteLine("Hello from Part 1");
    }
}

// File: MyClass.Part2.cs

public partial class MyClass
{
    public void SayGoodbye()
    {
        Console.WriteLine("Goodbye from Part 2");
    }
}
```

![](img/bb6e93ece31f33afd31e933e9dd494be_174_0.png)

In C#, a partial class allows you to break a single class into multiple .cs files. This is particularly helpful when:

- You have auto-generated code (e.g., designer code in WinForms or ASP.NET) that you don’t want to manually modify.
- You want to organize a large class into logical parts across files to make it easier to navigate and maintain.

All parts must be within the same namespace, and they must all use the partial keyword.

When compiled, the compiler merges all partial class parts into a single class. It's important to avoid naming conflicts (e.g., two methods with the same name) across the partial definitions.

Also, partial classes can be used with structs and interfaces, not just classes.

![](img/bb6e93ece31f33afd31e933e9dd494be_174_1.png)

### [Supplement]

Visual Studio's designer files (e.g., Form1.Designer.cs) are automatically declared as partial. This is so that the user-written logic in Form1.cs and the designer-generated layout code can exist in parallel without interfering with each other.

## 60. Using Lambda Expressions for Short Function Definitions

![](img/bb6e93ece31f33afd31e933e9dd494be_175_3.png)

Lambda expressions allow you to write functions in a short and expressive way.

They are especially useful in LINQ, event handling, or anywhere a quick function is needed inline.

### [Code Example]

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

class Program
{
    static void Main()
    {
        List<int> numbers = new List<int> { 1, 2, 3, 4, 5 };

        // Lambda expression to filter even numbers
        var evens = numbers.Where(n => n % 2 == 0);

        foreach (var n in evens)
        {
            Console.WriteLine(n);
        }
    }
}
```

![](img/bb6e93ece31f33afd31e933e9dd494be_176_0.png)

### [Execution Result]

2

4

![](img/bb6e93ece31f33afd31e933e9dd494be_176_1.png)

The line `numbers.Where(n => n % 2 == 0)` uses a lambda expression. Here's how to understand it:

`n => n % 2 == 0` means:

- `n` is the input parameter (each element of the list).
- `=>` separates the parameter from the body of the expression.
- `n % 2 == 0` is the condition being tested — only even numbers pass.

Lambdas can be:

- Single-expression: `x => x * x`
- Block-style: `x => { return x * x; }`

They're especially powerful when used with LINQ, event handlers, and anonymous methods.

You can assign them to delegates or use them inline. Their syntax can be tricky at first, but they drastically simplify your code once you get used to them.

![](img/bb6e93ece31f33afd31e933e9dd494be_177_0.png)

### [Supplement]

C# lambdas are converted to delegates behind the scenes. They can close over variables in their surrounding scope — this is called a closure. This means the lambda "remembers" variables from where it was defined, which is very useful in functional-style programming.

## 61. Defining Helper Methods Inside Methods (Local Functions)

Local functions in C# are methods declared inside another method. They're useful for isolating helper logic that doesn't need to be exposed outside the containing method.

Here’s a simple example showing how a local function is defined and used inside another method.

### [Code Example]

```csharp
using System;

class Program
{
    static void Main()
    {
        int number = 5;

        // Call the method that uses a local function
        int result = CalculateFactorial(number);
        Console.WriteLine($"Factorial of {number} is {result}");
    }

    static int CalculateFactorial(int n)
    {
        // Local function defined inside the method

        int Factorial(int x)
        {
            if (x <= 1) return 1;
            return x * Factorial(x - 1); // Recursive call
        }

        return Factorial(n); // Calling the local function
    }
}
```

### [Execution Result]

Factorial of 5 is 120

In this example, Factorial is a local function defined inside the CalculateFactorial method.

It cannot be accessed from outside CalculateFactorial, which helps keep the code clean and encapsulated.

### Why use local functions?

- Encapsulation: Keeps helper logic close to where it's used.
- Readability: Prevents polluting the class with methods used only in one place.
- Access to variables: Local functions have access to the outer method's variables (n in this case).

Note: You can also define local functions as static inside static methods if they don’t need outer scope access.

### [Supplement]

Local functions were introduced in C# 7.0.

You can nest multiple levels of local functions if needed (though it’s rare and can reduce readability).

They are different from lambda expressions and anonymous methods, which are inline delegates rather than named functions.

## 62. Using Func<> and Action<> for Functional Programming

`Func<>` and `Action<>` are built-in generic delegates in C#. They let you store methods in variables, pass them as parameters, and build flexible, reusable code using functional programming techniques.

This example shows how to use `Func<>` and `Action<>` to assign and use methods as first-class citizens.

### [Code Example]

```csharp
using System;

class Program
{
    static void Main()
    {
        // Func<int, int, int> means a function taking two ints and returning an int
        Func<int, int, int> add = (a, b) => a + b;

        // Action<string> means a method taking one string and returning void
        Action<string> printMessage = message => Console.WriteLine($"Message: {message}");

        int result = add(10, 20); // Calling the Func delegate
        printMessage($"The result is {result}"); // Using the Action delegate
    }
}
```

### [Execution Result]

Message: The result is 30

`Func<T1, T2, TResult>` is a generic delegate that takes parameters `T1`, `T2`, and returns a value of type `TResult`.
