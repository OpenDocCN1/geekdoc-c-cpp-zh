### 1. AUTOMATIC MEMORY MANAGEMENT WITH GARBAGE COLLECTOR

C# uses a Garbage Collector (GC) to automatically manage memory, preventing memory leaks and reducing manual deallocation errors.

In C#, memory is allocated dynamically when objects are created. The Garbage Collector (GC) automatically reclaims memory that is no longer in use, freeing developers from manually releasing objects. Below is a simple example showing how garbage collection works.

**[Code Example]**

```csharp
using System;

class Program
{
    class Sample
    {
        // Destructor (finalizer) to show when the object is collected
        ~Sample()
        {
            Console.WriteLine("Sample object is being collected!");
        }
    }

    static void Main()
    {
        // Creating and releasing objects
        Sample obj = new Sample();
        obj = null; // Make object eligible for garbage collection

        // Force garbage collection (not recommended in real applications)
        GC.Collect();
        GC.WaitForPendingFinalizers();
        Console.WriteLine("Garbage Collection executed.");
    }
}
```

#### [Execution Result]

Sample object is being collected!

Garbage Collection executed.

The C# runtime includes an automatic garbage collector that periodically checks for objects that are no longer accessible and frees their memory. This helps prevent memory leaks and simplifies memory management.

- Objects allocated in memory are stored in the managed heap.
- When an object is no longer referenced, the GC considers it for collection.
- GC runs automatically, but developers can trigger it manually using `GC.Collect()`, though this is generally discouraged as the runtime optimizes it better.

#### GC Performance Considerations

- **Generational GC:** The GC categorizes objects into three generations (0, 1, 2). Objects that survive multiple collections move to older generations for efficiency.
- **Dispose and Finalize:** While GC manages most objects, some (like those with unmanaged resources) may require manual cleanup using `IDisposable` and `Dispose()`.

#### How to manage memory efficiently in C#?

![](img/bb6e93ece31f33afd31e933e9dd494be_20_0.png)

**[Supplement]**

- The garbage collector does **not** immediately reclaim memory when an object becomes unreachable; it works based on an internal scheduling mechanism.
- The `using` statement is used for proper disposal of unmanaged resources like files and database connections.
- C# does not support explicit deallocation (`delete` like in C++); the GC handles it automatically.
- Large objects (LOH - Large Object Heap) are handled differently by the GC and may take longer to collect.
- Calling `GC.Collect()` frequently can degrade performance rather than improve it.

### 2. UNDERSTANDING VALUE TYPES AND REFERENCE TYPES

C# supports two fundamental types of data storage: **Value Types** (stored in the stack) and **Reference Types** (stored in the heap). This affects how data is managed in memory.

Understanding the difference between value types and reference types is crucial in C# programming. Below is an example demonstrating how assigning values works differently between them.

**[Code Example]**

```csharp
using System;

class Program
{
    struct ValueTypeExample
    {
        public int number;
    }

    class ReferenceTypeExample
    {
        public int number;
    }

    static void Main()
    {
        // Value type (struct) - stored in the stack
        ValueTypeExample v1 = new ValueTypeExample();
        v1.number = 10;
        ValueTypeExample v2 = v1; // Copying value (new copy in stack)
        v2.number = 20;
        Console.WriteLine("Value Type - v1: " + v1.number); // Outputs 10
        Console.WriteLine("Value Type - v2: " + v2.number); // Outputs 20

        // Reference type (class) - stored in the heap
        ReferenceTypeExample r1 = new ReferenceTypeExample();
        r1.number = 30;
        ReferenceTypeExample r2 = r1; // Copying reference (both point to the same object in heap)
        r2.number = 40;
        Console.WriteLine("Reference Type - r1: " + r1.number); // Outputs 40
        Console.WriteLine("Reference Type - r2: " + r2.number); // Outputs 40
    }
}
```

#### [Execution Result]

Value Type - v1: 10

Value Type - v2: 20

Reference Type - r1: 40

Reference Type - r2: 40

The key difference between **value types** and **reference types** is how they are stored and copied in memory:

#### Value Types (Stack)

- Stored in the **stack** (a small, fast memory area).
- When assigned to another variable, a **copy** is created.
- Changes in one variable **do not** affect the other.
- Examples: `int`, `double`, `char`, `bool`, `struct`, `enum`.

#### Reference Types (Heap)

- Stored in the **heap** (a dynamically allocated memory area).
