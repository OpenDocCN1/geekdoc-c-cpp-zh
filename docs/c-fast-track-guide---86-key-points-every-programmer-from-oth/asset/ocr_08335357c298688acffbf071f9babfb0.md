Span<T> represents a contiguous region of memory. Unlike arrays or lists, Span<T> does not cause heap allocations, making it faster and more memory-efficient for temporary data manipulation.

Key points:

+   - Span<T> can only live on the stack, so it can't be stored in fields of classes.
+   - You can create spans from arrays using AsSpan() and also from stackalloc.
+   - Changes made to the span reflect on the underlying data (e.g., the original array).
+   - It is mostly used in high-performance code, such as parsing or memory slicing.

Span<T> provides:

+   - Slicing: mySpan.Slice(start, length)
+   - Bounds checking
+   - Safety (unlike pointers, no unsafe code is needed)

[Supplement]

ReadOnlySpan<T> is an immutable version used when data should not be modified.

Span<T> is extremely useful in methods that process parts of strings, buffers, or arrays repeatedly.

Useful in scenarios like CSV parsing, string tokenization, or buffer manipulation without copying.
