- implicit: No cast is needed in code. This is safe and should not lose information or throw exceptions.
- explicit: Requires a cast in code using (Type), often used when there's potential for data loss or the conversion is not always valid.

Celsius can be created directly from a double with no cast, thanks to the implicit operator.

A Celsius object can be explicitly cast to Fahrenheit using the defined conversion logic.

These operators make the API cleaner and allow safer, controlled type conversions.

Why this matters:

It’s extremely useful in APIs, data transfer, or mathematical classes where natural type interactions matter.

### [Supplement]

## 39. AVOIDING NULL ERRORS WITH NULLABLE REFERENCE TYPES

C#'s nullable reference types help prevent null-related runtime errors by letting you explicitly declare whether a reference can be null or not.

Here’s a simple example demonstrating how enabling nullable reference types can help you catch potential null issues at compile time.

[Code Example]

```
#nullable enable // Enables nullable reference types
class Person
{
public string Name { get; set; } // Warning: May be null if not initialized
}
class Program
{
static void Main()
{
Person person = new Person();
Console.WriteLine(person.Name.Length); // Possible NullReferenceException warning
}
}
```

[Execution Result]

Warning: Dereference of a possibly null reference.

In C# 8.0 and later, the #nullable enable directive tells the compiler to treat reference types (string, object, etc.) as non-nullable by default. This means if you write string Name;, the compiler will assume Name should never be null and will warn you if it thinks it might be.

If a reference can be null, you must declare it explicitly using ?, like this:

```
public string? Name { get; set; } // nullable string
```

This makes the code safer and easier to understand. You’ll be warned at compile time if you try to use a variable that might be null, instead of encountering a crash at runtime.

This feature is compile-time only — it doesn't stop nulls at runtime, but helps developers catch issues early.

Enabling this feature across your whole project is done via project settings (<Nullable>enable</Nullable> in the .csproj file).

### [Supplement]

Nullable reference types were introduced in C# 8.0.

They only work if explicitly enabled (either per file with #nullable enable or globally via project settings).

It’s about warnings — no runtime performance hit.

You still need null checks or the null-coalescing operator ?? to handle values safely at runtime.

With person?.Name, the expression evaluates to null instead of crashing.

This is especially useful when chaining multiple property accesses.

Example:

```
string name = person?.Name ?? "Unknown"; // Returns "Unknown" if person is null
```

This operator is a concise and readable way to handle potential null values without verbose if statements.

Note: It only short-circuits the current access. If you write person?.Name.Length, it will throw an exception if Name is null, so use it wisely.

### [Supplement]

- Introduced in C# 6.0.
- It's one of the most effective tools to reduce if (x != null) clutter.
- Works with methods too: person?.ToString()
- Can be used with indexers: array?[index]
- Cannot be used in assignment targets (person?.Name = "John"; is invalid).

## 41. PROVIDING FALLBACK VALUES WITH ??

The null-coalescing operator ?? helps you safely assign fallback (default) values when a variable might be null.

Here’s how you can avoid null values by using ?? to supply a default value.

[Code Example]

```csharp
// This variable might be null
string? userInput = null;

// Use ?? to provide a fallback value if userInput is null
string result = userInput ?? "Default Value";

// Print the result
Console.WriteLine(result);
```

[Execution Result]

Default Value

In C#, a variable of a reference type (like string) can hold null, meaning "no value".

This can be risky—if you try to use a null value without checking, it can cause runtime errors (e.g., NullReferenceException).

The ?? operator solves this problem by letting you specify a "backup" value.

A ?? B means: if A is not null, use A; otherwise, use B.

This is extremely useful when you're dealing with user input, optional data, or data from uncertain sources.

In the code example:

userInput is null.

result = userInput ?? "Default Value" assigns "Default Value" to result since userInput was null.

You can also chain ?? to try multiple fallback options:

```csharp
string? input = null;
string? backup = null;
string final = input ?? backup ?? "Nothing available";
```

### [Supplement]

The null-coalescing operator works great with nullable types.

It’s especially helpful in APIs or databases where some values may be missing.

In C# 8.0 and later, there's also ??= which assigns a default only if the value is null:

```csharp
string? name = null;
name ??= "Guest";  // name becomes "Guest"
```

Use ?? often to write safer and cleaner code when dealing with uncertain data.

## 42. EASIER STRING FORMATTING WITH INTERPOLATED STRINGS

Interpolated strings make it easier to build strings with variables, replacing the older and harder-to-read string formatting methods.

Here's how you can combine variables and text in a clean and readable way using $"...".

[Code Example]

```
string name = "Alice";
int age = 30;
// Interpolated string using variables inside the string
string message = $"Hello, my name is {name} and I am {age} years old.";
Console.WriteLine(message);
```

[Execution Result]

Hello, my name is Alice and I am 30 years old.

Traditionally, C# developers used methods like string.Format() or concatenation (+) to combine strings and variables, which can be hard to read:

```
string msg = "Hello, my name is " + name + " and I am " + age + " years old.";
```

But interpolated strings—introduced in C# 6—make this much cleaner and more readable.

- Use the $ symbol before a string literal to start interpolation.
- Place variables or expressions inside {} directly in the string.

You can even perform calculations inside {}:

```
string summary = $"In 5 years, {name} will be {age + 5} years old.";
```

This makes your code more expressive and reduces the chance of mistakes.

It’s also very useful for debugging, logging, UI text, and anywhere you display dynamic information.

### [Supplement]

You can format values directly inside interpolated strings:

```csharp
double price = 12.5;
Console.WriteLine($"Total: {price:C}");  // Output: Total: $12.50 (depending on locale)
```

Use escape sequences like {{ or }} to print braces literally:

```
Console.WriteLine($"Value in braces: {{{123}}}");  // Output: Value in braces: {123}
```

Interpolated strings support everything expressions can do—math, method calls, even ternary operators. They're a powerful tool in writing readable, maintainable C# code.

## 43. CONCISE PATTERN MATCHING WITH SWITCH EXPRESSIONS
