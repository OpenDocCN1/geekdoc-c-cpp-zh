## 2.3.4 The Nordström-Robinson code

The existence of the Nordström-Robinson code shows that the upper bound on \( A_2(16, 6) \) discovered in Example 2.3.9 is met, and hence that \( A_2(16, 6) = 256 \).

The Nordström-Robinson code was discovered by Nordström and Robinson [247] and later independently by Semakov and Zin'cev [303]. This code can be defined in several ways; one of the easiest is the following and is due to Goethals [100] and Semakov and Zin'cev [304].

Let \(\mathcal{C}\) be the \((24, 12, 8)\) extended binary Golay code chosen to contain the weight 8 codeword \(\mathbf{c} = 11\cdots 100\cdots 0\). Let \(T\) be the set consisting of the first eight coordinates. Let \(\mathcal{C}(T)\) be the subcode of \(\mathcal{C}\) which is zero on \(T\), and let \(\mathcal{C}_T\) be \(\mathcal{C}\) shortened on \(T\). Let \(\mathcal{C}^T\) be \(\mathcal{C}\) punctured on the positions of \(T = \{9, 10, \dots, 24\}\). By Corollary 1.4.14, as \(\mathcal{C}\) is self-dual, the first seven coordinate positions of \(\mathcal{C}\) are linearly independent. Thus as \(\mathbf{c} \in \mathcal{C}\) and \(\mathcal{C}\) is self-dual, \(\mathcal{C}^T\) is the \([8, 7, 2]\) binary code consisting of all even weight vectors of length 8. Exercise 104 shows that the dimension of \(\mathcal{C}_T\) is 5. Hence \(\mathcal{C}_T\) is a \([16, 5, 8]\) code. (In fact \(\mathcal{C}_T\) is equivalent to \(\mathcal{R}(1, 4)\) as Exercise 121 shows). For \(1 \le i \le 7\), let \(\mathbf{c}_i \in \mathcal{C}\) be a codeword of \(\mathcal{C}\) with zeros in the first eight coordinates except coordinate \(i\) and coordinate 8; such codewords are present in \(\mathcal{C}\) because \(\mathcal{C}^T\) is all length 8 even weight vectors. Let \(\mathbf{c}_0 = \mathbf{0}\). For \(0 \le i \le 7\), let \(C_i\) be the coset \(\mathbf{c}_i + \mathcal{C}(T)\) of \(\mathcal{C}(T)\) in the extended Golay code \(\mathcal{C}\). These cosets are distinct, as you can verify in Exercise 105. Let \(\mathcal{N}\) be the union of the eight cosets \(C_0, \dots, C_7\). The *Nordström-Robinson code* \(\mathcal{N}_{16}\) is the code obtained by puncturing \(\mathcal{N}\) on \(T\). Thus \(\mathcal{N}_{16}\) is the union of \(C_0, \dots, C_7\), where \(C_i^*\) is \(\mathcal{C}_i\) punctured on \(T\). Figure 2.1 gives a picture of the construction. Clearly, \(\mathcal{N}_{16}\) is a \((16, 256)\) code, as Exercise 106 shows. Let \(\mathbf{a}, \mathbf{b} \in \mathcal{N}\) be distinct. Then \(d(\mathbf{a}, \mathbf{b}) \ge 8\), as \(\mathcal{C}\) has minimum distance 8. Since \(\mathbf{a}\) and \(\mathbf{b}\) disagree on at most two of the first eight coordinates, the codewords of \(\mathcal{N}_{16}\) obtained from \(\mathbf{a}\) and \(\mathbf{b}\) by puncturing on \(T\) are distance 6 or more apart. Thus \(\mathcal{N}_{16}\) has minimum distance at least 6 showing that \(A_2(16, 6) = 256\). In particular, \(\mathcal{N}_{16}\) is optimal.

We compute the weight distribution \(A_i(\mathcal{N}_{16})\) of \(\mathcal{N}_{16}\). Clearly

\[
\sum_{j=0}^7 A_i(C_j^*) = A_i(\mathcal{N}_{16}). \tag{2.20}

By Theorem 1.4.5(iv), \(\mathcal{C}\) contains the all-one codeword \(\mathbf{1}\). Hence as \(\mathbf{c} + \mathbf{1}\) has 0s in the first eight coordinates and 1s in the last 16, \(C_0^*\) contains the all-one vector of length 16. By Exercise 107 \(A_{16-i}(C_j^*) = A_i(C_j^*)\) for \(0 \le i \le 16\) and \(0 \le j \le 7\). As \(C_j^*\) is obtained from \(\mathcal{C}\) by deleting eight coordinates on which the codewords have even weight, \(A_i(C_j^*) = 0\) if \(i\) is odd. By construction \(\mathcal{N}_{16}\) contains \(\mathbf{0}\). As \(\mathcal{N}_{16}\) has minimum distance 6, we deduce that \(A_i(\mathcal{N}_{16}) = 0\) for \(1 \le i \le 5\) and therefore that \(A_i(C_j^*) = 0\) for \(1 \le i \le 5\) and \(11 \le i \le 15\). As \(C_0^* = C_7\) and the weights of codewords in \(C(T)\) are multiples of 4, so are the weights of vectors in \(C_0^*\). Since \(C_0^*\) has 32 codewords, \(A_0(C_0^*) = A_{16}(C_0^*) = 1\) and \(A_8(C_0^*) = 30\), the other \(A_i(C_0^*)\) being 0. For \(1 \le j \le 7\), the codewords in \(C_j\) have weights a multiple of 4; since each codeword has two 1s in the first eight coordinates, the vectors in \(C_j^*\) have weights that are congruent to 2 modulo 4. Therefore the only possible weights of vectors in \(C_j\) are 6 and 10, and since \(A_6(C_j^*) = A_{10}(C_j^*)\), these both must be 16. Therefore by (2.20), \(A_0(\mathcal{N}_{16}) = A_{16}(\mathcal{N}_{16}) = 1\), \(A_6(\mathcal{N}_{16}) = A_{10}(\mathcal{N}_{16}) = 7 \cdot 16 = 112\), and \(A_8(\mathcal{N}_{16}) = 30\), the other \(A_i(\mathcal{N}_{16})\) being 0.

## 2.3.5 Nearly perfect binary codes

We explore the case when bound (2.13) is met. This bound strengthens the Sphere Packing Bound and the two bounds in fact agree precisely when \((t+1)\mid(n-t)\). Recall that codes that meet the Sphere Packing Bound are called perfect. An \((n, M, 2t+1)\) binary code with \(M = A_2(n, 2t+1)\) which attains the Johnson Bound (2.13) is called _nearly perfect_.

A natural problem is to classify the nearly perfect codes. As just observed, the perfect Johnson Bound strengthens the Sphere Packing Bound, and so perfect codes are nearly perfect (and \((t+1)|(n-r)\)); see Exercise 109. Nearly perfect codes were first examined by Semakov, Zinov'ev, and Zaitsev [305] and independently by Goethals and Snover [101]. The next two examples, found in [305, Theorem 1], give parameters for other nearly perfect codes.

**Example 2.3.10** Let \(\mathcal{C}\) be an \((n, M, 3)\) nearly perfect code. So \(t=1\). If \(n\) is odd, \((t+1)|(n-r)\) and so the Sphere Packing Bound and (2.13) agree. Thus \(\mathcal{C}\) is a perfect single error-correcting code and must have the parameters of \(\mathcal{H}_{2,r}\) by Theorem 1.123. (We do not actually need Theorem 1.123 because the Sphere Packing Bound gives \(M = 2^n/(1+n)\); so \(n = 2^r - 1\) for some \(r\) and \(M = 2^{2^{r-1}-r}\).) If \(n\) is even, equality in (2.13) produces

\[
M = \frac{2^n}{n+2}.
\]

Hence \(M\) is an integer if and only if \(n = 2^r - 2\) for some integer \(r\). Therefore the only possible sets of parameters for nearly perfect \((n, M, 3)\) codes that are not perfect are \((n, M, 3) = (2^r - 2, 2^{2^{r-1}-r}, 3)\) for \(r \ge 3\). For example, the code obtained by puncturing the subcode of even weight codewords in \(\mathcal{H}_{2,r}\) is a linear code having these parameters. (See Exercise 110). \(\blacksquare\)

Prove that the code obtained by puncturing the subcode of even weight codewords in \(\mathcal{H}_{2,r}\) is a linear code having parameters \((n, M, 3) = (2^r - 2, 2^{2^{r-1}-r}, 3)\). \(\blacklozenge\)

**Example 2.3.11** Let \(\mathcal{C}\) be an \((n, M, 5)\) nearly perfect code. So \(t=2\). If \(n \equiv 2 \pmod 3\), \((t+1)|(n-r)\) and again the Sphere Packing Bound and (2.13) agree. Thus \(\mathcal{C}\) is a perfect double error-correcting code which does not exist by Theorem 1.123. If \(n \equiv 1 \pmod 3\), equality in (2.13) yields

\[
M = \frac{2^{n+1}}{(n+2)(n+1)}.
\]

So for \(M\) to be an integer, both \(n+1\) and \(n+2\) must be powers of 2, which is impossible for \(n \ge 1\). Finally, consider the case \(n \equiv 0 \pmod 3\). Equality in (2.13) gives

\[
M = \frac{2^{n+1}}{(n+1)^2}.
\]

So \(n = 2^m - 1\) for some \(m\), and as \(3|n\), \(m\) must be even. Thus \(\mathcal{C}\) is a \((2^m - 1, 2^{2^m-2m}, 5)\) code, a code that has the same parameters as the punctured Preparata code \(\mathcal{P}(m)^*\), which we will describe in Chapter 12. \(\blacksquare\)

These two examples provide the initial steps in the classification of the nearly perfect codes, a work begun by Semakov, Zinov'ev, and Zaitsev [305] and completed by Lindström [199, 200]; one can also define nearly perfect nonbinary codes.
