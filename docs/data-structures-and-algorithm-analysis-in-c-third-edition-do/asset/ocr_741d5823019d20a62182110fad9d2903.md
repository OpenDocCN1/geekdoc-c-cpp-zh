steps de do a total of $n$ of work, with an overall cost of $n \log n$ when
Quicksort finds perfect pivots.

Quicksort's average-case behavior falls somewhere between the extremes of
wor and best case. Average-case analysis considers the cost for all possible-anges of input, summing the costs and dividing by the number of cases. We
make one reasonable simplifying assumption: At each step, the pivot is
eally likely to end in any position in the (sorted) array. In other words, the pivot
is equally likely to break an array into partitions of sizes 0 and $n-1$, or $n-2$,nand so on.

Given this assumption, the average-case cost is computed from the following
eation:

```
$T(n) = cn + \frac{1}{n} \sum_{k=0}^{n-1} [T(k) + T(n-1-k)], \quad T(0) = e.$
```

This equation is in the form of a recurrence relation. Recurrence relations are
discussed in Chapters 2 and 14, and this one is solved in Section 14.2.4. This
says that there is one chance in $n$ that the pivot breaks the array into
subarrays of size 0 and $n-1$, and so on. The expression "$T(k)+T(n-1-k)$ is"
the cost for the two recursive calls to Quicksort on two arrays of size $k$ and $n-1-k$.
The initial $cn$ is the cost of doing the findpivot and partition steps,
some constant $c$. The closed-form solution to this recurrence relation is $\theta(n \log n)$.
Thus, Quicksort has average-case cost $\theta(n \log n)$.

have asymptotically growth rates. Consider what "average case" actually
means. We consider an average cost for inputs of size $n$ by summing up over
possible input of size $n$ the product of the running cost of that input times
trobability that that input will occur. To simplify things, we assumed that every
permutation is equally likely to occur. Thus, finding the average means summing
the cost for every permutation and dividing by the number of inputs ($n!$). We
