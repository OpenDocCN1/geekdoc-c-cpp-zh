However, the problem would occur if we process the vertices in order of distance from $S$. Assume that we have processed in order of distance from $S$ to the first $i - 1$ vertices that are closest to $S$; call this set of vertices **S**. ## 11.5 Minimum Spanning Trees

The minimum spanning tree (MST) takes as input a connected, undirected graph with edge weights, and outputs a tree that connects all vertices with the minimum total cost. Applications where this is useful include soldering the set of terminals on circuit board, and connecting a city of cities by telephone lines in such a way as to ensure the least amount of cost. The MST contains no cycles. If a MST had a cycle, a cheaper MST could be found by removing one of the edges in the cycle. Then, the MST is a free tree with |V|-1 edges. The name "minimum-cost spanning tree" comes from the fact that the required set of edges forms a tree, it spans the vertices (i.e., it connects them together), and has this minimum cost. Recording the path requires modifications to the algorithm that the single-source shortest-paths goal is left as an exercise.

Computer networks provide an application for the single-source shortest-paths goal. The goal is to find the cheapest way for one computer to broadcast a message to all other computers on the network. The network can be modeled by a graph with edge weights indicating time or cost to send a message to a neighboring computer.

For un graphs (whenever all edges have the same cost), the single-source paths can be found using a simple breadth-first search. When weights are added, BFS will not give the correct answer.

One approach to solving this problem when the edges having differing weights might be to process the vertices in a fixed order. Label the vertices $v_0$ to $v_{n-1}$, with $S = v_0$. When processing Vertex $v_1$, we take the edge connecting $v_0$ and $v_1$. processing $v_2$, we consider the shortest distance from $v_0$ to $v_2$ and compare that to the shortest distance from $v_1$ to $v_2$. When processing Vertex $v_i$, we consider the shortest path for Vertices $v_i$ through $v_{i-1}$ that have already been processed. Unfortunately, the true shortest path to $v_i$ might go through $v_j$ for $j > i$. Such a path will not be considered by this algorithm. However, the problem would occur if we process the vertices in order of distance from $S$. Assume that we have processed in order of distance from $S$ to the first $i - 1$ vertices that are closest to $S$; call this set of vertices **S**. We are now about to process the $i$th closest vertex X.

## Sec. 11.4 Shortest-Paths Problems

```
// Compute shortest path distances from "s"
// Return these distances in "D"
void Dijkstra(Graph* G, int* D, int s) {
    int i, v, w;
    for (i=0; i<G->n(); i++) { // Process the vertices
        v = minVertex(G, D); return; // Unreachable vertices
        G->setMark(v, VISITED);
        for (w=G->first(v); w<G->n(); w = G->next(v, w)) {
            if (D[w] > D[v] + G->weight(v, w))
                D[w] = D[v] + G->weight(v, w);
        }
    }
}
```

The shortest path from S to X must have its next-to-vertex in S. Thus,

$d(S,X) = min(d(S,U) + w(U,X))\ U \in S$

In other words, the shortest path from S to X is the minimum over all paths that go from S to U to X, where U is some vertex in S.

This is solved by Dijkstra's algorithm. It works by maintaining a distance D(X) for all vertices in V. The elements of D are initialized to INFINITE. Vertices are processed in order of distance from S. When a vertex V is processed, D(X) is updated for every neighbor X of V. Figure 11.17 shows an implementation for Dijkstra's algorithm. At the end, array D will contain the distance values.

There are two reasonable solutions to the key issue of finding the unvisited vertex with minimum value during each pass through the loop. The first method is to scan the list of |V| vertices searching for the minimum value, as:

```
int minVertex(Graph* G, int* D) { // Find min vertex
    int i, v = -1;
    // Initialize v to some unvisited vertex
    for (i=0; i<G->n(); i++))
        if (G->getMark(i) == UNVISITED) { v = i; break; }
    for (i++; i<G->n(); i++) // Now find smallest D value
        if (G->getMark(i) == UNVISITED) && (D[i] < D[v])
            v = i;
    return v;
}
```

Because this is done |V| times, and each edge requires a constant-update to D, the total cost for this approach is $\Theta(|V|^2 + |E|) = \Theta(|V|^2)$, because E is in O(|V|^2).

The second method is to store unvisited vertices in a min-heap ordered by distance values. The next-closest vertex can be found in the heap in $\Theta(\log |V|)$ time. Every time we modify D(X), we could reorder X in the heap by deleting and reinserting it. This is an example of a priority queue with priority update, as is described in Section 5.5. To implement true priority updating, we would need to store with each vertex its index within the heap. A simpler approach is to add the new (smaller) distance value for a given vertex in the heap as a new record in the heap. The smallest value for a given vertex in the heap will be found first, and greater distance values found later will be ignored because the vertex will already be marked as VISITED. The only disadvantage to repeatedly inserting distance values is that it will raise the number of elements in the heap from Θ(|V|) to Θ(|E|) in the worst case.
