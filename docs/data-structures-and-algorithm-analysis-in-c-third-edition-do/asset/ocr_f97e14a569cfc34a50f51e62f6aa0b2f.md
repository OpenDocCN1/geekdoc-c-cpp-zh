Path compression keeps the cost of each FIND operation very close to constant. To be more precise about what is meant by "very close to constant," the cost of processing n FIND operations on n nodes (when combined with the union rule for joining sets) is approximately Θ(log n). The notation "log n" means the number of times that log n must be taken before n ≤ 1. For example, log 65536 = 16, log 16 = 4, log 4 = 2, and finally log 2 = 1. Thus, log n grows very slowly, so the cost for a series of n FIND operations is very close to n.

That does not mean that the tree resulting from processing n equivalences pairs necessarily has depth Θ(log n). One can derive a series of equivalences operations that yields Θ(log n) depth for the resulting tree. However, many of the equivalences in such a series will only look at the roots of the tree being merged, requiring little time. The total amount of processing time required for n operations will be Θ(n log n), yielding nearly constant time for each equivalence. This is an example of amortized analysis, discussed further in Section 14.
