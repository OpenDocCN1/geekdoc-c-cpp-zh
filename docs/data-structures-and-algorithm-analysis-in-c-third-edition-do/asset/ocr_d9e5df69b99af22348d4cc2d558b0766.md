This algorithm passes over the list of n numbers in base r, with Θ(n+r) work done at each pass. The total work is Θ(nk+rk). What might be smaller in terms of n? One could use base 2 or 10. Base 26 would be appropriate for sorting strings. For now, we will treat k as a constant value and ignore it for the purpose of determining complexity. Variable k is related to the range key: The maximum number of digits that a key may have in base r. In some applications we can determine k to be of limited size and so might to consider it a constant. In this case, Radix Sort is Ω(n) in the best case, making it the best asymptotic complexity that we have studied.

It is a reasonable assumption to treat k as a constant? Or is there some relationship between k and n? If the range is limited and duplicate key values are common, there might be no relationship between k and n. To make this distinction clear, use N to denote the number of distinct keys used by the n records. Thus, N ≤ n. Because it takes a minimum of log N, base r digits to represent N distinct keys, we know that k ≤ log N.

Now, consider the situation in which no keys are duplicated. If there are n unique keys (n = N), then it requires n distinct code values to represent them. Thus, k ≥ log n. Because it requires at least Ω(log n) digits (with a constant factor) to distinguish between n distinct keys, k is Ω(log n). This yields an asymptotic complexity of Ω(n log n) for Radix Sort to process n distinct keys.

It is possible that the range is much larger; log n bits is merely the best case for n distinct values. Thus, the n estimate for k could be overly optimistic. The real of this analysis is that, for the general case of n distinct key values, Radix Sort is at best a Ω(log n) sorting algorithm.

Radix Sort can be improved by making base r as large as possible. Consider the case of an integer key value. Set r = 2^i for some i. In other words, the value of r is related to the number of bits of the key processed on each pass. Each time the number of bits is doubled, the number of passes is cut in half. When setting r = 2^16 allows the key to be processed one byte at a time. A 32-bit key requires only four passes.
