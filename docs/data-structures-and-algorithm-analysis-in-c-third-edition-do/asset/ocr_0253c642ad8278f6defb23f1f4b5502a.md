Before discussing external sorting techniques, consider the basic model for accessing information from disk. The file to be sorted by the program as a sequential series of fixed-size blocks. Assume (for simplicity) that each block contains the same number of fixed-size data records. Depending on the application, a record may be composed of a few bytes — or hundreds of bytes with a relatively small key field. Records are assumed not to cross block boundaries. These assumptions can be relaxed for special-purpose sorting applications, but ignoring such complications makes the principles clearer.

As explained in Section 8.2, the sector is the basic unit of I/O. In other words, all disk reads and writes are for one or more complete sectors. Sector sizes are typically a power of two, in the range 512 to 16KB, depending on the operating system and the size of the disk drive. The block size used for external sorting algorithms should be equal to a multiple of the sector size.

Under this model, a sorting algorithm reads a block of data into a buffer in memory, processes it, and at some future writes it back to disk. From Section 8.1 we see that reading or writing a block from disk takes the order of one million times longer than a memory access. Based on this fact, we can reasonably expect that the records contained in a single block can be sorted by an internal sorting algorithm such as Quicksort before it is required to read or write the block.

Under good conditions, reading a file in sequential order is more efficient than reading blocks in random order. Given this obvious sequential processing is faster. However, it is important to understand under what circumstances sequential processing is actually faster than random access, it affects our approach to designing an external sorting algorithm.

Efficient sequential access relies on seek time being kept to a minimum. The first requirement is that the blocks making up a file are fact stored on disk in sequential order and close together, preferably laying a small number of contiguous tracks. At the very, the number of extents making up the file should be small. Users typically do not have control over the layout of their file on disk, writing a file all at once in sequential order to a disk drive with a high percentage of free space increases the likelihood of such an arrangement.

The second requirement is that the disk drive's I/O head remains positioned over the file throughout sequential processing. This will not happen if there is competition of any kind for the I/O head.
