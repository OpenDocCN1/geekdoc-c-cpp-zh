**Theorem 5.3** Function *buildHuff* builds the Huffman tree with the minimum external path weight for the given set of letters.

**Proof:** The proof is by induction on $n$, the number of letters.

- **Base Case:** For $n=2$, the Huffman tree must have the minimum external path weight because there are only two possible trees, each with identical weighted lengths for the two leaves.
- **Induction Hypothesis:** Assume that any tree created by *buildHuff* that contains $n-1$ leaves has minimum external path weight.
- **Induction Step:** From a given tree $T$ built by *buildHuff* with $n$ leaves, $n \geq 2$, suppose that $w_1 \leq w_2 \leq \dots \leq w_n$ where $w_1$ to $w_n$ are the weights of the letters. Call $V$ the parent of the leaves with frequencies $w_1$ and $w_2$. From the lemma, we know that the leaf nodes containing the letters with frequencies $w_1$ and $w_2$ are as deep as any nodes in $T$. If any other leaf were deeper, we reduce their weighted path length by swapping them with $w_1$ or $w_2$. But the lemma tells us that no deeper nodes exist. Call $T'$ the Huffman tree that is identical to $T$ except that node $V$ is replaced with a leaf $V'$ whose weight is $w_1+w_2$. By the induction hypothesis, $T'$ has minimum external path length. Returning the children to $V$ restores $T$, which must also have minimum external path length.

By that mathematical induction, function *buildHuff* creates the Huffman tree with minimum external path length.

How efficient is Huffman coding? In theory, it is an optimal coding method whenever the true frequencies are known. In practice, the frequencies of letters in an English text change depending on context. For example, while E is the most commonly used letter of the alphabet in English documents, T is more common than the first letter of a word. This is why commercial utilities do not use Huffman coding as their primary coding method, but instead use techniques that adapt to the context for the letters.

Another factor that affects the compression efficiency of Huffman coding is the relative frequencies of letters. Some patterns will save no space as compared to fixed-length codes; others result in great compression. In general, Huffman coding does better when there is large variation in the frequencies of letters.
