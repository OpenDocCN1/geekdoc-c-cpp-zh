## **Improved Collision Resolution Methods**

How can we avoid primary clustering? One possible improvement might be to use linear probing, but to skip slots by a constant *c* other than 1. This would make the probe function

```
p(K, i) = (h(K) + ic) mod M
```

and so the *i*th slot in the probe sequence will records with adjacent home positions will not follow the same probe sequence. For example, if we were to skip by two, our offsets from the home slot would be 2, then 4, and so on.

One quality of a good probe sequence is that it will cycle through all slots in the hash table before returning to the home position. Clearly linear probing (which "skips" by one slot each time) does. Unfortunately, not all values for c will make this. For example, if c=2 and the table contains an even number of slots, each home position is in an even slot will have a probe sequence that cycles through only the even slots. Likewise, the probe sequence for a key whose home position is in an odd slot will cycle through the odd slots. Thus, this combination of table size and linear probing constant effectively divides

the records into two sets stored in two disjoint sections of the hash table. So long as both sections of the table contain the same number of records, this is not really important. However, from chance it is likely one section will become fuller than the other, leading to more collisions and poorer performance for those records. The other section would have fewer records, and thus better performance. But the overall system performance will be degraded, as the additional cost to the side that is more outfields the improved performance of the less-full side.

Constant $c$ must be relatively prime to $M$ to generate a linear probing sequence that visits all slots in the table (that is, $c$ and $M$ must share no factors). For a hash table of size $M=10$, if $c$ is one of 1, 3, 7, or 9, then the probe sequence will visit all slots of it. When $M=11$, any value for $c$ between 1 and 10 generates a probe sequence that visits all slots for every key.

Consider the situation where $c=2$ and we wish to insert a record with key $k_1$ such that $h(k_1)=3$. The probe sequence for $k_1$ is 3, 5, 7, 9, and so on. And if another $k_2$ has position at slot 5, then its probe sequence will be 5, 7, 9, and so on. The probe sequences of $k_1$ and $k_2$ are linked together in a manner that contributes to clustering. In other words, linear probing with a value of $c>1$ does not solve the problem of clustering. We would like to find a probe function that does not link keys together this way. We would prefer that the probe sequence for $k_1$ after the first step should not be identical to the probe sequence of $k_2$. Instead, their probe sequences should diverge.

The ideal function would select the next position on the probe sequence at random from the unvisited slots; that is, the probe sequence should be a pseudo-permutation of the hash table positions. Unfortunately, we cannot actually select the next position in the probe sequence at random, because we would not be able to duplicate this same probe sequence when searching for the key. However, we can do something called pseudo-random probing. In pseudo-random probing, the ith value in the probe sequence is $(h(K)+r_i) \bmod M$ where $r_i$ is the ith value in a random permutation of the numbers from 1 to $M-1$. All insertion and search operations use the same random permutation. The probe function is

```
p(K, i) = Perm[i-1],
```

where $Perm$ is an array of length $M-1$ containing a random permutation of the values from 1 to $M-1$.

**Example 9.9** Consider a table of size $M=101$, with $Perm[1]=5$, $Perm[2]=2$, and $Perm[3]=30$. Assume that we have two keys $k_1$ and $k_2$ with $h(k_1)=30$. The probe sequence for $k_1$ is 30, then 35, then 32, then 62. The probe sequence for $k_2$ is 35, then 40, then 37, then 67. While $k_2$ will probe to $k_1$'s home position as its second choice, the two keys' probe sequences diverge thereafter.

Another probe function that eliminates clustering is called quadratic probing. The probe function is some quadratic function $$p(K, i) = c_1i^2 + c_2i + c_3$$ for some choice of constants $c_1, c_2$, and $c_3$. The simplest variant is $p(K, i) = i^2$ (i.e., $c_1 = 1, c_2 = 0$, and $c_3 = 0$). The $i$th value in the probe sequence would be $(h(K) + i^2) \mod M$. Under quadratic probing, two keys with different positions will diverge probe sequences.

**Example 9.10** Given a hash table of size $M=101$, assume for keys $k_1$ and $k_2$ that $h(k_1)=30$ and $h(k_2)=29$. The probe sequence for $k_1$ is 30, 31, 34, 39. The probe sequence for $k_2$ is 29, 30, 33, 38. Thus, $k_2$ will probe to $k_1$'s home position as its second choice, the two keys' probe sequences diverge thereafter.

Unfortunate, quadratic probing has the disadvantage that typically not all slots will be filled. Using $p(K,i)=i^2$ gives particularly inconsistent results. For many hash table sizes, this probe function will cycle through a relatively small number of slots. If all cycle to full, the record cannot be inserted! For example, if our hash table has three slots, then record hashes to slot 0 can only probe slots 0 and 1, and the probe sequence will never visit 2. Thus, if slot 0 and 1 are full, the record cannot be inserted even though the table is not full. A more realistic example is a table with 105 slots. The probe sequence starting from any given slot will visit 23 slots in the table. If all of these 23 slots happen to be full, even if other slots in the table are empty, the record cannot be inserted because the probe sequence will continually hit those 24 slots.

Fortunately, it is possible to get good results from quadratic probing at low cost. The right combination of probe function and table size will visit many slots in the particular. If the hash table size is a prime number and the probe function is $p(K,i)=i^2$, then at least half the slots in the table will be visited. Thus, if the table is not half full, we can be certain that a free slot will be found. Alternatively, if the hash table size is a power of two and the probe function is $p(K,i)=(i^2+i)/2$, then every slot in the table will be visited by the probe function.

Both pseudo-random and quadratic probing eliminate primary clustering, which is if two keys hash to the same home position, then they will always follow the same probe sequence for every collision resolution method that we have seen so far. The probe sequences generated by pseudo-random and quadratic probing (for example) are entirely a function of the home position, not the original key value.

This is because p ignores its input for collision resolution methods. If the hash function generates a cluster at a particular home position, then the cluster remains pseudo-random and quadratic probing. This problem is called secondary clustering.

To avoid secondary clustering, we need to use the probe sequence of the original key in its decision-making process. A simple technique for doing this is to return to linear probing by a constant step size for the probe function, but to have that constant defined by a second hash function, $h_2$. Thus, the probe sequence would be of the form $p(K, i) = i \cdot h_2(K)$. This method is called double hashing.

**Example 9.11** Assume a hash table has size $M = 101$, and that are three keys $k_1, k_2$, and $k_3$ with $h(k_1) = 30, h(k_2) = 28, h(k_3) = 30, h_2(k_1) = 2, h_2(k_2) = 5$. Then, the probe sequence for $k_1$ will be 30, 32, 34, 36, and so on. The probe sequence for $k_2$ will be 28, 33, 38, and so on. The probe sequence for $k_3$ will be 30, 40, 45, and so on. None of the keys share substantial portions of the same probe sequence. Of course, if a fourth key $k_4$ has $h(k_4)=28$ and $h_2(k_4)=2$, then it will follow the same probe sequence as $k_1$. Pseudorandom or quadratic probing can be combined with double hashing to solve this problem.
