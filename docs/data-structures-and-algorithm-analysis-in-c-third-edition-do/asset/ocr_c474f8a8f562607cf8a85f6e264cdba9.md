This version of the algorithm will not compute a value more than once, so its
cost could be linear. Of course we didn't actually need to use a table storing of all
values, since future computations not need access to all prior subproblems.
Instead, we could build the value by working from 0 and 1 up to n rather than
backwards from n down to 0 and 1. Going from the bottom we only need to
store the previous two values of the function, as done by its iterative version.

This approach to designing algorithm that works by dynamic programming. The name is somewhat arcane,
because it doesn't bear much similarity to the process that is taking place
when storing variables in a table. However, it comes originally from the field of
dynamic control systems, which got its start before what we think of computer
programming. The act of storing precomputed values in a table for later reuse is
referred to as "programming" in that field.
