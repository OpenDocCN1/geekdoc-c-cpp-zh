In particular, the number of records, the size of the keys and the records, the allowable range of the key values, and the amount by which the input records are "out of order" can greatly affect the relative running times for sorting algorithms.

When analyzing sorting algorithms, it is traditional to measure the number of comparisons made between keys. This measure is usually related to the running time for the algorithm and has the advantage of being machine and data-type independent. However, in some cases records may be so large that their physical movement might take a significant fraction of the running time. If, it might be appropriate to measure the number of swap operations performed by the algorithm. In many applications we can assume that all records and keys are of fixed length, and that a single comparison or single swap operation requires a constant amount of time regardless of which keys are involved. Special situations "change the rules" for comparing sorting algorithms. For example, an application with records or keys having widely varying length (such as a sequence of variable length strings) will benefit from a special-purpose sorting technique. Applications require that a small number of records be sorted, but that the sort performed frequently. An example would be an application that repeatedly sorts groups of numbers. In such cases, the constants in runtime equations that are usually ignored in an asymptotic analysis now become crucial. Finally, situations require that sorting algorithm use as little memory as possible. We will note which sorting algorithms require significant extra memory beyond the input array.

# 7.2 $\Theta(n^2)$ Sorting Algorithms

This section presents three simple sorting algorithms. While easy to understand and implement, we will see that they are unacceptable slow when there are many records to sort. Nonetheless, there are situations where one of these simple algorithms is the best tool for the job.

# 7.2.1 Insertion Sort

Imagine that you have a stack of phone bills from the past two years and that you wish to organize them by date. A fairly natural way to do this is to look at the first two bills and put them in order. Take the third bill and put it into the right order with respect to the first two, and so on. As you take each bill, you would add it to the sorted pile you have already made. This naturally intuitive process is the inspiration for our first sorting algorithm, called **Insertion Sort**.
