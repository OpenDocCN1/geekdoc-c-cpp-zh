# **Example 9.7** Here is a hash function for strings of characters:

```c
int h(char * x) {
    int i, sum;
    for (i=0; x[i] != '\0'; i++)
        sum += (int) x[i];
    return sum % M;
}
```

This function uses the ASCII values of the letters in the string. If the hash table M is small, this hash function should do a good job of distributing strings evenly among the hash table slots, it gives equal weight to all characters. This is an example of the *folding* approach to designing a hash function. Note that the order of the characters in the string has no effect on the result. A similar method for integers would add the digits of the key value, assuming that there are enough digits to (1) keep any one or two digits with bad distribution from squaring the results of the process and (2) generate a sum much larger than M. With many other hash functions, the final step is to apply the modulus operator to the result, using table M to generate a value within the table range. If the sum is not sufficiently large, the modulus operator will yield a poor distribution. For example, because the ASCII value for “A” is 65 and “Z” is 90, **sum** will always be in the range 650 to 900 for a string of ten uppercase letters. For a hash table of size 100 or less, a reasonable distribution results. For a hash table of size 1000, the distribution is terrible because only slots 650 to 900 can possibly be home slot for some key value, and the values are not evenly distributed within those slots.

# Example 9.8 Here is a much better hash function for strings.

```c
// folding on a string, summed 4 bytes at a time
int sfold(char *key) {
    unsigned int *lkey = (unsigned int *)key;
    int intlength = strlen(key)/4;
    unsigned int sum = 0;
    for (int i=0; i<intlength; i++) {
        sum += lkey[i];
    }
    // Now with extra chars at the end
    int extra = strlen(key) - intlength*4;
    char temp[4];
    lkey = (unsigned int *)temp;
    lkey[0] = 0;
    for (int i=0; i<extra; i++) {
        temp[i] = key[intlength*4+i];
    }
    sum += lkey[0];

    return sum % M;
}
```

This function takes a string as input. It processes four bytes at a time, and interprets each of four-byte chunks as a single (unsigned) value. In addition, the resulting sum is converted to the range 0 to $M-1$ using the modulus operator. If, for example, "aaaaabb" is passed to sfold, the first four bytes ("aaaa") will be interpreted as the integer value 6337873 and the next four bytes ("bbbb") will be interpreted as the integer value 6501682 (when viewed as an unsigned integer). If the table size is 10 then the modulus function will cause this for sufficiently long string, the key to hash to 75 in the table. The sum for integer quantities will typically cause 32-bit integer to overflow (thus losing some high-order bits) because the resulting values are so large. This causes no problems when the goal is to compute a hash function. Recall from Section 2.2 that the implementation for mod m on many C++ compilers will yield a negative if n is negative. Implementors for hash functions need to be careful that their hash function does not generate a negative number. This can be avoided by ensuring that n is positive when computing mod m, or adding m to the result if mod m is negative. All computation in sfold is done using long values in part to protect against taking the modulus of a negative number.

# 9.4.2 Open Hashing

While the goal of a hash function is to minimize collisions, some collisions are unavoidable in practice. Thus, hashing implementations must include some form of collision resolution policy. Collision resolution techniques can be broken into two classes: **open hashing** (also called **separate chaining**) and **closed hashing** (also called **open addressing**). The difference between the two is whether collisions are stored outside the table (open hashing), or whether collisions result in storing one of the records at another slot in the table (closed hashing). Open hashing is treated in this section, and closed hashing in Section 9.4.3.

The simplest form of open hashing defines each slot in the hash table to be the head of a linked list. All records that hash to a particular slot are placed on that slot's list. Figure 9.3 illustrates a hash table where each slot stores one record and a link pointer to the rest of the list.

Records within a slot's list can be ordered in several ways: by insertion order, by key value or frequency-of-access order.
