When no program variable points to a block of space, no future access to that space is possible. Several algorithms have been used for garbage collection. One is the **reference count algorithm**, where every dynamically allocated block includes space for a count field. When a pointer is directed to a memory block, the reference count is increased. When a pointer is directed away from a memory block, the reference count is decreased. If the count becomes zero, then the memory block is considered garbage and is immediately placed in free store. This approach has the advantage that it does not require an explicit garbage collection phase, because information is put in free store immediately when it becomes garbage.

Reference counts are used by the UNIX file system. Files can have multiple names, called links. The file system keeps a count of the number of links to each file. When a file is “deleted,” in actuality its link field is simply reduced by one. If there is another link to the file, then no space is recovered by the file system. When the number of links goes to zero, the file’s space becomes available for reuse.

Reference counts have several major disadvantages. First, a reference count must be maintained for each memory object. This works well when the objects are large, such as a file. However it will not work well in a system such as LISP where the memory objects typically consist of two pointers or atoms (atom). Another major problem occurs when memory contains cycles. Another approach to garbage collection is the **mark/sweep** strategy. Here, each memory object needs only a mark bit rather than a counter field. When free store is exhausted, a separate garbage collection phase takes place as follows:

- Clear all mark.
- Perform depth-first search (DFS) beginning with static variables. Each element encountered during the DFS has its mark turned on.
- A “sweep” is made through the memory pool. Unmarked elements are considered garbage and placed in free.

The advantages of mark/sweep approach are that it needs less space than reference counts, and it works for cycles. However, there is a disadvantage. DFS is a recursive algorithm: it must be implemented recursively, in which case the runtime system maintains a stack, or the memory manager can maintain its own stack.
