### 11.3.2 Breadth-First Search

Our graph traversal algorithm is known as a **breadth-first search** (BFS). BFS examines all vertices connected to the start vertex before visiting further away. BFS is implemented similarly to DFS, except that a queue replaces the recursion stack. Note that if the graph is a tree and the vertex is at the root, BFS is equivalent to visiting vertices by level from top to bottom. Figure 11.10 provides an implementation for the BFS algorithm. ### 11.3.3 Topological Sort

Assume that we need to schedule a series of tasks, such as classes or construction jobs, which we cannot start one task until its prerequisites are completed. We wish to organize the tasks into a linear order that allows us to complete them one at a time without violating any prerequisites. We can model the problem using a DAG. The graph is directed because one task is a prerequisite of another — the vertices have a directed relationship. It is acyclic — a cycle would indicate a conflicting series of prerequisites that could not be completed without violating at least one prerequisite. The process of laying out the vertices of a DAG in a linear order to make the prerequisite rules is a topological sort. Figure 11.14 illustrates the process. An acceptable topological sort for this example is J1, J2, J3, J4, J5, J6.

A topological sort may be found by performing a DFS on the graph. When a vertex is visited, no action is taken (i.e., function PreVisit does nothing). When recursion pops back, function PostVisit prints the vertex. This yields a topological sort in reverse order. It does not matter where start starts, as long as all vertices are visited by the end. Figure 11.13 shows an implementation of the DFS-based algorithm.

```cpp
void BFS(Graph* G, int start, Queue<int>* Q) {
  int v, w;
  Q->enqueue(start); // Initialize Q
  G->setMark(start, VISITED);
  while (Q->length() != 0) { // Process all vertices on Q
    v = Q->dequeue(); // Take appropriate action
    PreVisit(G, v);
    for (w=G->first(v); w<G->next(v); w = G->next(v, w)) {
      if (G->getMark(w) == UNVISITED) {
        G->setMark(w, VISITED);
        Q->enqueue(w);
      }
    }
  }
}

Using this algorithm starting at J1 and visiting neighbors in alphabetical order, vertices of the graph in Figure 11.14 are printed out in the order J7, J5, J4, J6, J2, J3, J1. Reversing this yields the topological sort J1, J2, J3, J4, J5, J7.

We can implement topological sort using a queue instead of recursion, as follows. First visit all edges, counting the number of edges leading to each vertex (i.e., count the number of prerequisites for each vertex). All vertices with no prerequisites are on the queue. We then begin processing the queue. When Vertex V is off the queue, it is printed, and all neighbors of V (that is, vertices that have V as a prerequisite) have their counts decremented by one. Place on the queue when count becomes zero. If the queue becomes empty without printing all the vertices, then the graph contains a cycle (i.e., there is no possible ordering for the tasks that does not violate some prerequisite). The printed order for the vertices of the graph in Figure 11.14 using the queue version of topological sort is J1, J2, J3, J6, J4, J5, J7. Figure 11.15 shows an implementation for the algorithm.

// Topological sort: Queue
void Topsort(Graph* G, Queue<int>* Q) {
  int Count(G->n());
  int v, w;
  for (v=0; v<G->n(v); v++) Count[v] = 0; // Initialize
  for (v=0; v<G->n(v); v++) // Process every edge
    for (w=G->first(v); w<G->n(v); w = G->next(v,w)) {
      Count[w]--; // Add to v'2 prereq count
    }
  for (v=0; v<G->n(v); v++) // Initialize queue
    if (Count[v] == 0) // Vertex has no prerequisites
      Q->enqueue(v);
  while (Q->length() == 0) { // Process the vertices
    v = Q->dequeue();
    printout(v);
    for (w=G->first(v); w<G->n(v); w = G->next(v, w)) {
      if (--Count[w] == 0) // One last prerequisite
        Q->enqueue(w);
    }
  }
}
```
