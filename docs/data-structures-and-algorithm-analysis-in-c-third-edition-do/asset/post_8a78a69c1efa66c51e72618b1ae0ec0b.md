Given a summation, you often wish to replace it with an algebraic equation with the same value as the summation. This is known as a **closed-form solution**, and the process of replacing the summation with its closed-form solution is known as **solving** the summation. For example, the summation $\sum_{i=1}^n i$ is simply the expression "1" summed $n$ times (remember that $i$ ranges from 1 to $n$). Because of the sum of $n$ is $n$, the closed-form solution is $n$. The following is a list of useful summations, along with their closed-form solutions.

```math
$$\sum_{i=1}^n i = \frac{n(n+1)}{2} \quad (2.1)$$
```

```math
$$\sum_{i=1}^n i^2 = \frac{2n^3+3n^2}{6} = \frac{n(2n+1)(n+1)}{6} \quad (2.2)$$
```

```math
$$\sum_{i=1}^n \log n = n \log n \quad (2.3)$$
```

```math
$$\sum_{i=0}^n a^i = \frac{a^n}{1-a} \text{ for } 0 < a < 1. \quad (2.4)$$
```

```math
$$\sum_{i=0}^n a^i = \frac{a^{n+1}-1}{a-1} \text{ for } a \neq 1. \quad (2.5)$$
```

As special cases to Equation 2.5,

```math
$$\sum_{i=1}^n \frac{1}{2^i} = 1 - \frac{1}{2^n} \quad (2.6)$$
```

As a corollary to Equation 2.7,

```math
$$\sum_{i=0}^n 2^i = 2^{n+1}-1. \quad (2.7)$$
```

Finally,

```math
$$\sum_{i=1}^n \frac{i}{2^i} = 2 - \frac{n+2}{2^n}. \quad (2.9)$$
```

The sum of reciprocals from 1 to $n$, called the **Harmonic Series** and written $\mathcal{H}_n$, has a value between $\log_e n$ and $\log_e n+1$. To be more precise, as $n$ grows, summation grows closer to

```math
$$\mathcal{H}_n \approx \log_n n + \gamma + \frac{1}{2n} \quad (2.10)$$
```

where $\gamma$ is Euler's constant and has the value 0.5772...

Most of these equalities can be proved easily by mathematical induction (see Section 2.6.3). Unfortunately, induction does not help derive a closed-form solution. It only confirms if a proposed closed-form solution is correct. Techniques for deriving closed-form solutions are discussed in Section 14.1.

The running time for a recursive algorithm is most easily expressed by a recursive expression because the total time for the recursive algorithm includes the time to run the recursive call(s). A **recurrence relation** defines a function by means of an expression that includes one or more (smaller) instances of itself. A classic example is the recursive factorial:

```math
$n! = (n-1)! \cdot n > 1; \quad 1! = 0! = 1.$
```

Another example of a recurrence is the Fibonacci sequence:

```math
$Fib(n) = Fib(n-1) + Fib(n-2) \text{ for } n > 2; \quad Fib(1) = Fib(2) = 1.$
```

From this definition, the first seven numbers of the Fibonacci sequence $1, 1, 2, 3, 5, 8, and 13.$

Notice that this definition contains two parts: the general definition for $Fib(n)$ and the base cases for $Fib(1)$ and $Fib(2)$. Likewise, the definition for factorial contains a recursive part and base cases.

Recurrence relations are often used to model the cost of recursive functions. For example, the number of multiplications required by function **fact** of Section 2.5 for an input of size $n$ will be zero when $n=0$ or $n=1$ (the base cases), and it will be one plus the cost of calling **fact** on a value of $n-1$. This can be defined using the following recurrence:

```math
$T(n) = T(n-1) + 1 \text{ for } n > 1; \quad T(0) = T(1) = 0.$
```

With summations, we typically wish to replace the recurrence relation with a closed-form solution. One approach is to **expand** the recurrence by replacing any occurrences of $T$ on the right-hand side with its definition.

**Example 2.8** If we expand the recurrence $T(n) = T(n-1) + 1$, we get

```math
$T(n) = T(n-1) + 1 = T(n-2) + 1 + 1.$
```

We can expand the recurrence as many steps as we like, but the goal is to detect some pattern that will permit us to rewrite the recurrence in terms of a summation. In example, we might notice that

```math
$$T(n - 2) + 1 = T(n - 2) + 2$$
```

and if we expand the recurrence again, we get

```math
$$T(n) = T(n - 2) + 2 = T(n - 3) + 1 + 2 = T(n - 3) + 3$$
```

which generalizes to the pattern $T(n) = T(n - i) + i$. We might conclude that

```math
$$T(n) = T(n - (n - 1)) + (n - 1)$$
$$T(1) = n - 1$$
$$= n - 1$$
```

Because we have merely guessed at a pattern and not actually proved that this is the closed form solution, we should use an induction proof to complete the process (see Example 2.8).

**Example 2.9** A slightly more complicated recurrence is

```math
$T(n) = T(n-1) + n \quad n > 1; \quad T(1) = 1.$
```

Expanding this recurrence a few steps, we get

```math
$$T(n) = T(n-1) + n = T(n-2) + (n-1) + n = T(n-3) + (n-2) + (n-1) + n$$
```

which generalizes to the pattern $T(n) = T(n-i) + \sum_{j=0}^{i-1} (n-j)$. We might conclude that

```math
$$T(n) = T(n-(n-1)) + \sum_{j=0}^{n-2} (n-j)$$
$$T(1) = 1 + \sum_{j=0}^{n-2} (n-j)$$
$$= 1 + \sum_{k=2}^{n} k = \frac{n(n+1)}{2}$$
```

Because we have merely guessed at a pattern and not actually proved that this is the closed form solution, we should use an induction proof to complete the process (see Example 2.9).

## 2.5 Recursion

An algorithm is recursive if it calls itself to do some of its work. For this approach to be successful, the "call itself" must be on a smaller problem than the one. In general, a recursive algorithm must have two parts: the base case, which handles a simple input, and the recursive part which contains one or more recursive calls. Here is a C++ function to compute factorial.

```cpp
long fact(int n) {
    // Compute n! recursively
    assert(n <= 12, "Input out of range");
    if (n < 1) return 1; // Base case
    return n * fact(n-1); // Recursive call for n > 1
}
```

The two lines of function constitute the base cases. If $n \le 1$, then one of the base cases computes the solution for the problem. If $n > 1$, then fact calls a function that knows how to compute the $n-1$. happens to be fact itself. But we should not think too hard about that while writing the algorithm. The design for recursive algorithms can always be achieved in this way by combining the results of one or more smaller - but - subproblems. If the algorithm you write is correct, then you can rely on it (recursive) to solve the subproblems. The secret to success is: Do not worry how the recursive call solves the subproblem. Simply accept that it will solve correctly, and use this result in turn solve the original problem.

Recursion has no counterpart in everyday, physical-world problem solving. The concept can be difficult to grasp because it requires you to think about problems in a new way. To use recursion effectively, it is necessary to train yourself stop the recursive process beyond the recursive call. The subproblems take care of themselves. You just worry about the base cases and how to recombine the subproblems.
