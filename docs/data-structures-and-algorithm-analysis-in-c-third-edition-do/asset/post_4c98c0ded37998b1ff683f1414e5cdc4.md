## 7.4 Mergesort

```
// Modified version of Insertion Sort for varying increments
template <typename E, typename Comp>
void insertort2(E A[], int n, int incr) {
    for (int i=incr; i<n; i+=incr) {
        for (int j=i; j>=incr &&
            (Comp():prior(A[j], A[j-incr]))
            swap(A[j], A[j-incr]);
        }
    }
}

template <typename E, typename Comp>
void shellsort2(E A[], int n) { // Shellsort
    for (int i=n/2; i>0; i/=2) {
        for (int j=0; j<n; j++) {
            insertort2<E, Comp>(&A[j], n-j, i);
        }
    }
    shellsort2<E, Comp>(A, n, 1);
}
```

The analysis of Shellsort is difficult, so we must accept without proof that the average-case performance of Shellsort ("divisions by three" increments) is $O(n^{1.5})$. Thus, for the increments we can reduce this upper bound somewhat. Shellsort is substantially better than Insertion Sort, or any of the $\Theta(n^2)$ sorts presented in Section 7.2. In fact, Shellsort is not terrible when compared with the adaptive sorts whenever $n$ is of medium size (though it is to a bit slower than those other algorithms when they are well implemented). Shellsort illustrates how we can exploit the special properties of an algorithm (in this case, Insertion Sort) even if in general that algorithm is unacceptably slow.

A natural approach to solving is to divide and conquer. In terms of sorting, we might consider breaking the list to be sorted into pieces, process the pieces, and then put them back together somehow. A simple way to do this would be split the list in half, sort the halves, and merge the merged halves together. This is the idea behind **Mergesort**.

## 7.4 Mergesort

```cpp
template <typename E, typename Comp>
void mergesort(E A[], E temp[], int left, int right) {
    if (left == right) return; // one element
    int mid = (left+right)/2;
    mergesort(A, temp, left, mid);      // left half
    mergesort(A, temp, mid+1, right);  // right half
    for (int i=left; i<=right; i++) { // Copy subarray to temp
        temp[i] = A[i];
    }
    int il = left; int ir = mid + 1; // the two subarrays
    for (int curr=left; curr<=right; curr++) { // merge them back
        if (il > mid)                // sublist exhausted
            A[curr] = temp[ir++];
        else if (ir > right)        // sublist exhausted
            A[curr] = temp[il++];
        else if (Comp(temp[il], temp[ir]))
            A[curr] = temp[il++];
        else
            A[curr] = temp[ir++];
    }
}
```

When the input to Mergesort is an array, splitting it into two subarrays is easy if we know the bounds. Merging is also easy if we merge the subarrays into a second array. Note that this approach requires twice the space of any of the sorting methods presented so far, which is a serious disadvantage for Mergesort. It is possible to merge the subarrays without using a second array, but it is difficult to do efficiently and not really practical. Merging the subarrays into a second array, while simple to implement, presents another difficulty. The process ends with the sorted list in the auxiliary array. Consider how the recursive nature of Mergesort breaks the original array into subarrays, as in Figure 7.8. Mergesort is recursively called until subarrays of size 1 have been created, requiring log n levels of recursion. These subarrays are merged into subarrays of size 2, which in turn are merged into subarrays of size 4, and so on.

We need to devise an algorithm that alternates between two arrays. A much simpler approach is to copy the sorted sublists to the auxiliary array first, and then merge them back to the original array. Figure 7.9 shows a complete implementation for mergesort following this approach.
