# 6.3.2 The Left-Child/Right-Sibling Implementation

With the "list of children" implementation, it is difficult to access a node’s right sibling. Figure 6.10 presents an improvement. Here, each node stores its value and pointers to its parent, leftmost child, and right sibling. Thus, the basic ADT operations can be implemented by reading a value directly from the node. If two trees are stored within the same node, adding the subtree of the other requires setting three pointers. Combining trees in this way is illustrated by Figure 6.11. This implementation is more space efficient than the "list of children" implementation, and each node requires a fixed amount of space in the node array.

# 6.3.3 Dynamic Node Implementations

The two general implementations just use an array to store the collection of nodes. In contrast, our standard implementation for binary trees stores each node as a separate dynamic object containing its value and pointers to its two children. Unfortunately, a general tree can have any number of children, and this number may change during the life of the node. A general tree implementation must support these properties.
