One way to implement an alphabet trie is an array of 27 pointers indexed by letter. Because most nodes branch to only a small fraction of the possible letters in the alphabet, an alternate implementation is to use a linked list of pointers to the child nodes, as in Figure6.9.

The depth of a leaf node in the alphabet trie of Figure 13.2(b) has little to do with the number of nodes in the trie, or even with the length of the corresponding string. A trie's depth depends on the number of characters required to distinguish this word from any other. For example, if the words “anteater” and “antelepe” are both stored in the trie, it is not until the fifth letter that the two words can be distinguished. These, words must be stored at least as deep as level five. In general, the limiting factor on the depth of nodes in the alphabet trie is the length of the words stored.

Poor balance and clumping can result when certain prefixes are heavily used. For example, an alphabet trie storing the common words in the English language would have many words in the “th” branch of the tree, but none in the “qz” branch.

Any multway branching trie can be replaced with a binary trie by replacing the original trie with an equivalent binary code. Alternatively, we can use the techniques of Section 6.3.4 for converting a general tree to a binary trie without modifying the alphabet.
