Using the equation, we can solve for $n$ to determine the break-even point beyond which the array-based implementation is more space efficient in any particular situation. This occurs when

$n > DE/(P + E)$

If $P = E$, the break-even point is $D/2$. This would happen if the element field is a four-byte **int** value or a pointer, and the next field is a four-byte pointer. The array-based implementation would be more efficient (if the link field and the element field are the same size) whenever the array is more than half full.

As a rule of thumb, linked lists are more space efficient when implementing lists whose number of elements varies or is unknown. Array-based lists are generally more space efficient when the user knows in advance approximately how large the list will

Array-based lists are faster for random access by position. Positions can be adjusted forwards or backwards by the **next** and **prev** methods. These operations always take $\Theta(1)$ time. In contrast, singly linked lists have no explicit access to the previous element, and access by position requires that we march down the list from the front (the current position) to the specified position. Both of these operations require $\Theta(n)$ time in the average and worst cases, if we assume each position of the list is equally likely to be accessed on call to *prev* or *moveToPos*

Given a pointer to a suitable location in the list, the **insert** and **remove** methods (for linked lists require only $\Theta(1)$ time). Array-based lists must shift the remainder of the list or down within the array. This requires $\Theta(n)$ time in the average and worst cases. For many applications, the time to insert and delete dominates all operations. For this reason, linked lists are often preferred to array-based lists.

When implementing the array-based list, an implementor could allow the size of the array to grow and shrink depending on the number of elements that are actually stored. This data structure is a **dynamic array**. Both the Java and C++/STL Vector classes implement a dynamic array. Dynamic arrays allow the programmer to avoid the limitation on the standard array that its size cannot be changed once the array has been created. This also means that space need not be allocated to the dynamic array until it is used to. The disadvantage of this approach is that it takes time to deal with space adjustments. Each time the array grows, its contents must be copied.
