Searching a k-d tree for the record with a specified xy-coordinate is like searching a BST, except that each level of the k-d tree is associated with a particular discriminator.

**Example 13.5** Consider searching the k-d tree for a record located at $P = (69, 50)$. First compare $P$ with the point stored at the root (record $A$ in Figure 13.11). If $P$ matches the location of $A$, then the search is successful. In this example the positions do not match ($A$'s location $(40, 45)$ is not the same as $(69, 50)$, so the search must continue). The $x$ value of $A$ is less than $P$'s $x$ value of 69, so branch to the right subtree (all cities with $x$ value greater than or equal to 40 are in the right subtree). $A_y$ does not affect the decision on which way to branch to. At the second level, $P$ does not match $C$'s position, so another branch must be taken. However, at this level we branch based on the $y$ values of point $P$ and record $C$ (because $1 \pmod 2 = 1$, which corresponds to the $y$-coordinate). $C_y$'s value of 10 is less than $P_y$'s value of 50, so branch to the right. At this point, $P$ is compared against the position of $D$. A match is made and the search is successful.

If the search process reaches a NULL pointer, then that point is not contained in the tree. Here is a k-d tree search implementation, equivalent to the `findhelp` function of the BST class. **KD** class private member $D$ stores the $k$-dimension.

```
// Find the record with the given coordinates
bool findhelp(BinNode<E>* root, int* coord,
E& e, int discrim) const {
// Member "coord" of a node is an integer array storing
// the node's coordinates
if (root == NULL) return false; // Empty tree
int* curcoord = (root->val())->coord();
if (equalCoord(curcoord, coord)) { // Found it
    e = root->val();
    return true;
}
if (curcoord[discrim] < coord[discrim])
    return findhelp(root->left(), coord, e, (discrim+1)%D);
else
    return findhelp(root->right(), coord, e, (discrim+1)%D);
}
```

Inserting a new node in the k-d tree is similar to BST insertion. The k-d search procedure is followed until a NULL pointer is found, indicating the proper place to insert the new node.

Deleting a node from a k-d tree is similar to deleting from a BST, slightly harder. With a BST, the first step is to find the node (call it N) to be deleted. It is then necessary to find a descendant of N which can be used to replace N in the tree. If N has no children, N is replaced with a NULL pointer. Note that if N has one child that has children, we cannot simply assign N's parent to N's child as would be in BST. To do so would change the level of all nodes in the subtree, and the discriminator for a search would change. The result is that the subtree would no longer be a k-d tree because a node's child might violate the BST property for that discriminator.

Similar to BST deletion, the record stored in N should be replaced either by the record in N's right subtree with the least value of N's discriminator, or by the record in N's left subtree with the greatest value for this discriminator. Assume that N is at an odd level and therefore y is the discriminator. N could then be replaced by the record in its right subtree with the y value (call it Ymin). The problem is that Ymin is not necessarily the leftmost node, as it would be in the BST. A modified search procedure to find the y value in the left subtree must be used to find it instead. The implementation for findmin is shown in Figure 13.12. A recursive call to the delete routine then removes Ymin from the tree. Finally, Ymin's record is substituted for the node N.

Note that we can replace the node to be deleted with the least-valued node from the right subtree only if the right subtree exists.

Assume that we want to print out a list of all records that are within a certain distance d of a given point P. We will use Euclidean distance, that is, point P is defined to be within distance d of point N if

**Example 13.7** We will find all cities in the k-d tree of Figure 13.4 within 25 units of the point (25, 65). The search begins with the root node, which contains record A. Because (40, 45) is exactly 25 units from the search point, it will be reported. The search procedure determines which branches of the tree to take. The search circle extends to both the left and the right of A's (vertical) dividing line, so both branches of the tree must be searched. The left subtree is processed first. Here, record B has no child, processing of the left subtree is complete. Processing of node storing B found to fall within the search circle. Processing of A's right subtree begins now. The coordinates of record C are checked and not found within the circle. Thus, it should not be reported. However, it is possible that cities within C's subtrees could fall within the search circle if C does not. As C is at level 1, the discriminator is this $y$-coordinate. Because $65 - 25 > 10$, no record in C's subtree (i.e., records above C) could possibly be in the search circle. However, cities in C's right subtree (if it had one) need not be searched. Thus, search proceeds to the node containing record D. Again, D is outside the search circle. $25+25 < 69$, no record in D's right subtree could be within the search circle. This leads to comparing record E's coordinates against the search circle. Record E falls outside the search circle, and processing is complete. So we see that we only search subtrees whose rectangles fall within the search circle.
