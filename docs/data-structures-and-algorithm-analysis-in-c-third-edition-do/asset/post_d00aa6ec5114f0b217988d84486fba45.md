In particular, the number of records, the size of the keys and the records, the allowable range of the key values, and the amount by which the input records are "out of order" can greatly affect the relative running times for sorting algorithms.

When analyzing sorting algorithms, it is traditional to measure the number of comparisons made between keys. This measure is usually related to the running time for the algorithm and has the advantage of being machine and data-type independent. However, in some cases records may be so large that their physical movement might take a significant fraction of the running time. If so, it might be appropriate to measure the number of swap operations performed by the algorithm. In many applications we can assume that all records and keys are of fixed length, and that a single comparison or single swap operation requires a constant amount of time regardless of which keys are involved. Special situations "change the rules" for comparing sorting algorithms. For example, an application with records or keys having widely varying length (such as a sequence of variable length strings) will benefit from a special-purpose sorting technique. Applications require that a small number of records be sorted, but that the sort performed frequently. An example would be an application that repeatedly sorts groups of numbers. In such cases, the constants in runtime equations that are usually ignored in an asymptotic analysis now become crucial. Finally, situations require that sorting algorithm use as little memory as possible. We will note which sorting algorithms require significant extra memory beyond the input array.

## 7.2 $\Theta(n^2)$ Sorting Algorithms

This section presents three simple sorting algorithms. While easy to understand and implement, we will see that they are unacceptable slow when there are many records to sort. Nonetheless, there are situations where one of these simple algorithms is the best tool for the job.

### 7.2.1 Insertion Sort

Imagine that you have a stack of phone bills from the past two years and that you wish to organize them by date. A fairly natural way to do this is to look at the first two bills and put them in order. Take the third bill and put it into the right order with respect to the first two, and so on. As you take each bill, you would add it to the sorted pile you have already made. This naturally intuitive process is the inspiration for our first sorting algorithm, called **Insertion Sort**. Insertion Sort iterates through a list of records. Each record is inserted in turn at the correct position within a sorted list composed of those records already processed. following is a C++ implementation. The input is an array of *n* records stored in array **A**.

```cpp
template <typename T, typename Comp> // Insertion Sort
void insert(T A[], int n) {
  for (int i=1; i<n; i++) { // Insert i-th record
    for (int j=i; j>0 && Comp::prior(A[j], A[j-1]); j--)
      swap(A[j], A[j-1]);
  }
}
```

Consider the case where **insert** is processing the i-th record, which has key value **X**. The record is moved upward in the array as long as **X** is less than the key value immediately above it. As soon as a key value less or equal to **X** is encountered, the insertion is done with correct all records before it in the array have many swaps. Figure 7.1 illustrates how Insertion Sort works.

The **body** is made up of two nested **for** loops. The outer **for** loop is executed *n*-1 times. The inner **for** loop depends on how many keys in positions 1 to *i*-1 have a value less than that of the key in position i. In the worst case, each record must make its way to the top of the array. This would occur if the keys are initially arranged from highest to lowest, in the reverse of sorted order. In this case, the number of comparisons will be one the first time through the **for** loop, the second time, and so on.

$$\ \_{i=2}^{n} i^2/2 = \Theta(n^2) $$

In contrast, consider the best-case cost. This occurs when the keys begin in sorted order from lowest to highest. In this case, every pass through the inner **for** loop will fail immediately, and no values will be moved. The total number of comparisons will be $n-1$, which is the number of times the inner **for** loop executes. Thus, the cost for Insertion Sort in the best case is $\Theta(n)$.

### 7.2.2 Three $\Theta(n^2)$ Sorting Algorithms

While the best case is significantly faster than the worst case, the worst case is usually a more indication of the "typical" running time. However, there are situations where we can expect the input to be sorted or nearly sorted. Examples of algorithms that take advantage of Insertion Sort's near-case running time are the Shellsort algorithm and the Quicksort algorithm of Section 7.5. What is the average-case cost of Insertion Sort? When record $i$ is processed, the number of times the **for** loop depends on how "out of order" the record is. In particular, the inner **for** loop executes for each key greater than $i$ that appears in array positions 0 through $i-1$. For example, in the leftmost column of 7.1 the value 15 is preceded by five values greater than it. Each such comparison is called an **inversion**. Number of inversions (i.e., the number of values greater than a value that occurs prior to it in the array) will determine the number of comparisons and swaps that must take place. We need to determine what the average number of inversions will be for the record in position $i$. We expect on average that half of the keys in the first $i-1$ array positions will have a value greater than that of the key at position $i$. Thus, the average case should be half the cost of the worst case, or around $n^2/4$, which is still $\Theta(n^2)$.

Counting comparisons or swaps yields similar results. Each time the inner **for** loop yields both a comparison and a swap, except the last (i.e., the comparison that fails the inner **for** loop's test), which has no swap. The number of swaps for the entire sort operation is $n-1$ less than the number of comparisons. It is 0 in the best case, and $\Theta(n^2)$ in the average and worst cases.

Our next sorting algorithm called Bubble Sort. Bubble Sort is often taught to novice programmers in introductory computer science courses. This is unfortunate, because Bubble Sort has no redeeming whatsoever. It is a relatively slow sort, so it is easier to understand than Insertion Sort, it does not correspond to any intuitive counterpart in "everyday" use, and it has poor best-case running time. Bubble Sort can serve as an example for a better sorting algorithm that will be presented in Section 7.2.3.
