// Topological sort: Queue
void Topsort(Graph* G, Queue<int>* Q) {
  int Count(G->n());
  int v, w;
  for (v=0; v<G->n(v); v++) Count[v] = 0; // Initialize
  for (v=0; v<G->n(v); v++) // Process every edge
    for (w=G->first(v); w<G->n(v); w = G->next(v,w)) {
      Count[w]--; // Add to v'2 prereq count
    }
  for (v=0; v<G->n(v); v++) // Initialize queue
    if (Count[v] == 0) // Vertex has no prerequisites
      Q->enqueue(v);
  while (Q->length() == 0) { // Process the vertices
    v = Q->dequeue();
    printout(v);
    for (w=G->first(v); w<G->n(v); w = G->next(v,w)) {
      if (--Count[w] == 0) // One last prerequisite
        Q->enqueue(w);
    }
  }

# 11.4 Shortest-Paths Problems

On a map, a road connecting two towns is typically labeled with its distance. We can model a road as a directed graph whose edges are labeled with real numbers. These numbers represent the distance (or other metric, such as travel time) between two vertices. These labels may be called weights, costs, or distances, depending on the application. Given such a graph, a typical problem is to find the total length of the shortest path between two specified vertices. It is not a trivial problem, the shortest path may not be the edge (if any) connecting two vertices, but rather may be a path involving one or more intermediate vertices. For example, in Figure 11.16, the cost of the path from A to D is 15. The cost of the direct connection from A to D is 20. The cost of the path from A to C to B to D is 10. Thus, the shortest path from A to D is 10 (not the edge connecting A to D). We use the notation d(A, D) = 10 to indicate that the shortest distance from A to D is 10. In Figure 11.16, there is no path from E to B, so we set d(E, B) = ∞. We define w(A, D) = 20 to be the weight of edge (A, D), that is, weight of the direct connection from A to D. Because there is no edge from E to B, w(E, B) = ∞. Note that w(D, A) = ∞ because the graph of Figure 11.16 is directed. We assume all weights are positive.
