$f(n) = \sum_{i=1}^{n} i 2^i = 1 \cdot 2^1 + 2 \cdot 2^2 + 3 \cdot 2^3 + \dots + n \cdot 2^n.$

We can achieve our goal if we multiply by two:

$2f(n) = 2 \sum_{i=1}^{n} i 2^i = 1 \cdot 2^2 + 2 \cdot 2^3 + \dots + (n-1) \cdot 2^n + n \cdot 2^{n+1}.$

The $i$th term of $2f(n)$ is $i \cdot 2^{i+1}$, while the $(i+1)$th term of $f(n)$ is $(i+1) \cdot 2^{i+1}$. Subtracting one expression from the other yields the summation of $2^i$ and a few non-cancelled terms:

$2f(n) - f(n) = 2 \sum_{i=1}^{n} i 2^{i+1} - \sum_{i=1}^{n} i 2^i $

= $\sum_{i=1}^{n} 2^{i+1} - \sum_{i=1}^{n} 2^i$.

Shift $i$'s value in the second summation, substituting $(i+1)$ for $i$:

$n^{n+1} + \sum_{i=0}^{n-1} 2^{i+1} - \sum_{i=0}^{n-1} (i+1) 2^{i+1}$.

Break the second summation into two parts:

$n^{n+1} + \sum_{i=0}^{n-1} 2^{i+1} - \sum_{i=0}^{n-1} i 2^{i+1} - \sum_{i=0}^{n-1} 2^{i+1}$.

Cancel like terms:

$n^{n+1} - \sum_{i=0}^{n-1} 2^{i+1}$.

Again shift $i$'s value in the summation, substituting $i$ for $(i+1)$:

$n^{n+1} - \sum_{i=1}^{n} 2^i$.

Replace the new summation with a solution that we already know:

$n^{n+1} - (2^{n+1} - 2)$.

Finally, reorganize the equation:

$(n-1)2^{n+1} + 2$.

## 14.2 Recurrence Relations

Recurrence relations are often used to model the cost of recursive functions. For example, the standard Mergesort (Section 7.4) takes a list of size $n$, splits it in half, performs Mergesort on each half, and finally merges the two sublists in $n$ steps. The cost for this can be modeled

```
$T(n) = 2T(n/2) + n.$
```

In other words, the cost of the algorithm on size $n$ is two times the cost for input of size $n/2$ (due to the two recursive calls to Mergesort) plus (the time to merge the sublists).

There are many approaches to solve recurrence relations, and we briefly describe three here. The first is an estimation technique: Guess the upper and lower bounds for the recurrence, use induction to prove the bounds, and tighten as required. The second approach is to expand the recurrence to convert it to a summation and then use summation techniques. The third approach is to take advantage of already proven theorems when the recurrence is of a suitable form. In particular, divide and conquer algorithms such as Mergesort yield recurrences of a form that fits a pattern for which we have a ready solution.

### 14.2.1 Estimating Upper and Lower Bounds

The first approach to solving recurrences is to guess the answer and attempt to prove it. If a correct upper or lower bound is given, an easy induction proof will verify this. If the proof is successful, then try to tighten the bound. If the proof fails, then loosen the bound and again. Once the upper and lower bounds match, you are finished. This is a useful technique when you are only looking for asymptotic complexities. When seeking a precise closed-form solution (i.e., you seek the constants for the expression), this method will probably be too much work.

**Example 14.5** Using the technique to find the asymptotic bounds for Mergesort, whose running time is described by the equation

```
$T(n) = 2T(n/2) + n; \quad T(2) = 1.$
```

We begin by guessing that this recurrence has an upper bound in $O(n^2)$. To be precise, assume that

```
$T(n) \leq n^2.$
```

We prove this guess is correct by induction. In this proof, we assume that $n$ is a power of two, to make the calculations easy. For the base case,

$T(2) = 1 \le 2^2$. For the induction step, we need to show that $T(n) \le n^2$ implies that $T(2n) \le (2n)^2$ for $n = 2^N, N \ge 1$. The induction hypothesis is

$T(i) \le i^2$, for all $i \le n$.

It follows that

$T(2n) = 2T(n) + 2n \le 2n^2 + 2n \le 4n^2 \le (2n)^2$

which is what we wanted to prove. Thus, $T(n)$ is in $O(n^2)$. Is $O(n^2)$ a good estimate? In the next-to-last step we will compare $n^2+2n$ to the much larger $4n^2$. This suggests that $O(n^2)$ is a high estimate. If we guess something, such as $T(n) \le c$ for some constant $c$, it should be clear that this cannot work $c2n = 2cn$ and there is no room for the extra cost to join the two pieces together. Thus, the true cost must be somewhere between $cn$ and $n^2$.

Let us try $T(n) \le n \log n$. For the base case, the definition of the recurrence set $T(2) = 1 \le 2 \log 2 = 2$. Assume (induction hypothesis) $T(n) \le n \log n$. Then,

$T(2n) = 2T(n) + 2n \log n + 2n \log(n + 1) \le 2n \log 2n$

which is what we seek to prove. In similar fashion, we can prove that $T(n)$ is in $\Omega(n \log n)$. Thus, $T(n)$ is also $\Theta(n \log n)$.
