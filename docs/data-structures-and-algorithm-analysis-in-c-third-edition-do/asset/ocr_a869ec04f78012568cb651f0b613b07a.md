# 7.10 Further Reading

+   - Equivalently, a tree with $n$ nodes requires at least $[log(n + 1)]$ levels.

What is the minimum number of nodes that must be in the decision tree for any comparison-based sorting algorithm for $n$ values? Because sorting algorithms are in the business of determining which unique permutation of the input corresponds to the sorted list, the decision tree for any sorting algorithm must contain at least one leaf node for each permutation. There are $n!$ permutations for a set of $n$ nodes (see Section 2.2).

Because there are $n!$ nodes in the tree, we know that the tree must have $\Omega(n!)$ levels. From Stirling's approximation (Section 2.2), we know $n!$ is in $\Omega(n \log n)$ levels. Thus, for any comparison-based sorting algorithm must have nodes $\Omega(n \log n)$ depth. In the worst case, any sorting algorithm must require $\Omega(n \log n)$ comparisons.

Any sorting algorithm requiring $\Omega(n \log n)$ comparisons in the worst case requires $\Omega(n \log n)$ running time in the worst case. Because any sorting algorithm $\Omega(n \log n)$ running time, the problem of sorting also requires $\Omega(n \log n)$ running time. We already know the problem of sorting algorithms with $O(n \log n)$ running time, so we can conclude that no comparison-based sorting algorithm can improve on here and $\Theta(n \log n)$ time sorting algorithms by more than a constant factor.

The definitive reference for sorting is Donald E. Knuth's *Sorting and Searching* [Knu98]. A wealth of details is covered here, including optimal sorts for small $n$ and size proper sorting networks. It is a thorough (albeit dated) treatment on sorting. For an analysis of Quicksort and a thorough survey on its optimizations, Robert Sedgewick's *Quicksort* [Sed80]. Sedgewick's *Algorithms* [Sed11] describes most of the sorting algorithms described here and pays special attention to efficient implementation. The optimized Mergesort version of Section 7.4 comes from Sedgewick.

While $\Omega(n \log n)$ is the theoretical lower bound in the worst case for sorting, many times the input is sufficiently well ordered that certain algorithms can take advantage of this fast to speed the sorting process. A simple example is Insertion Sort's best-case running time. Sorting algorithms whose running time is based on the amount of disorder in the input are called **adaptive**. For more information on adaptive sorting algorithms, see “A Survey of Adaptive Sorting Algorithms” by Estivill-Castro and Wood [ECW92].
