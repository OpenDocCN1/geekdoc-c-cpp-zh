The *do* loop is guaranteed to move at least one position on each first pass. Each *while* loop moves its variable at least once (except in the special case where $r$ is at the left end of the array, but this can happen only). Knowing the cost of **findpivot** and **partition**, we can determine the cost of Quicksort. We begin with a worst-case analysis. The worst case will occur when the pivot does a poor job of breaking the array, that is, when there are no elements in one partition and $n-1$ in the other. In this case, the divide and conquer strategy has a poor job of dividing, so the conquer phase will work on a subproblem only less than the size of the original problem. If this happens at each partition step, the total cost of the algorithm will be

```
$$\sum_{k=1}^n \Theta(n^2)$
```

In the worst case, Quicksort is $\Theta(n^2)$. This is terrible, no better than Bubble Sort. When will this worst case occur? Only each pivot yields a bad partitioning of the array.
