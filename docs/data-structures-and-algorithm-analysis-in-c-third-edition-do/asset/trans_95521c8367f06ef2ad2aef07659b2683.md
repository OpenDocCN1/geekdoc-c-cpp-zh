**图 3.3** 在速度快十倍的计算机上，固定时间内可以运行的问题规模的增长情况。第一列列出了图 3.1 中五种增长率的右侧值。为了本示例的目的，任意假设旧机器在一小时内可以运行 10000 次基本操作。第二列显示了在旧机器上 10,000 次操作可以运行的 $n$ 最大值。第三列显示了 $n'$ 的值，即在速度快十倍的新机器上相同时间内可以运行的问题最大规模。变量 $n'$ 是在新机器上 $n$ 变为 $n'$ 的最大规模。第五列显示了以 $n'$ 与 $n$ 的比例表示的问题规模的增长。

如果你的算法增长率是线性的（即，如果描述规模 $n$ 运行时间的方程为 $T(n)=cn$，其中 $c$ 为常数），那么在新机器上处理 100,000 条记录所需的时间与旧机器上处理 10,000 条记录相同。如果算法的增长率大于 $cn$，例如 $c_1n^2$，那么你**将无法**在快十倍的机器上用相同的时间完成同等规模的问题。

在给定的时间内，更快的计算机可以解决多大的问题？新机器比旧机器快十倍。假设旧机器在一小时内可以解决规模为 $n$ 的问题。那么新机器在一小时内能解决多大的问题？图 3.3 显示了对于图 3.1 中的五种运行时间函数，在两台机器上可以解决多大的问题。

该表说明了许多重要点。前两个方程都是线性的；只是常数因子的值发生了变化。在这两种情况下，速度快十倍的机器的问题规模都增加了十倍。对于其他情况，常数的值会影响在固定时间内可以解决的问题绝对规模，但它不会影响更快的计算机所获得的问题规模*改进*（相对于原始规模的比例）。这种关系无论算法的增长率如何都成立：常数因子永远不会影响更快的计算机所获得的相对改进。

运行时间方程为 $T(n)=2n^2$ 的算法从更快的机器中获得的改进远没有线性增长率算法那么大。相反，这种改进不是十倍的，而是只有平方根的倍数：$\sqrt{10} \approx 3.16$。因此，增长率较高的算法不仅在给定时间内最初解决的问题较小，而且从更快的计算机中获得的加速也更少。随着计算机变快，问题规模之间的差异变得越来越大。

增长率为 $T(n) = 5n \log n$ 的算法改进程度比二次增长率的算法大，但没有线性增长率算法那么大。

注意对于运行时间呈指数级增长的算法的特殊情况。在图 3.1 中，运行时间与 $2^n$ 成比例的算法曲线上升非常快。在图 3.3 中，机器上问题规模的增长如所示大约是 $n+3$（精确来说，是 $n+\log_2 10$）。指数增长率算法的增长是常数相加，而不是倍数因子。因为 $n$ 的值为 13，新的问题规模是 16。如果你明年又买了一台快十倍的计算机，这台新计算机（比原始计算机快十倍）只能运行规模为 19 的问题。如果你有第二个增长率为 $2^n$ 的程序，且原始计算机在一小时内可以运行规模为 1000 的问题，那么快十倍的机器在一小时内就可以运行规模为 1003 的问题！因此，指数增长率与图 3.3 所示的其他增长率完全不同。这种差异的意义将在第 7 章中探讨。

与其购买更快的计算机，如果我们将运行时间与 $n^2$ 成比例的算法替换为运行时间与 $n \log n$ 成比例的新算法，会发生什么？在图 3.1 的图中，固定时间将表现为一条水平线。如果解决问题可用时间线位于上述两种增长率交点上方，则运行时间增长较慢的算法更快。当 $n$ 变大时，运行时间为 $n^2$ 的算法比 $n \log n$ 慢。
