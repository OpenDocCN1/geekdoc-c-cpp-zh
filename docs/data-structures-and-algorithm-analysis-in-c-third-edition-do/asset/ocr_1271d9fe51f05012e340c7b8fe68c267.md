While not nearly as important as changing an algorithm to reduce its growth rate,"code tuning" can also lead to dramatic improvements in running time. Code tuning is the art of optimizing a program to run faster or require less storage. For many programs, code tuning can reduce running time by a factor of ten, or once tuned a critical function in a program — without changing any basic — to achieve a factor of 200 speed. With this speedy, I did major changes in the representation of the information, converting from a symbolic coding scheme to a numeric coding scheme on which I was able to do direct computation.

Here are some suggestions for ways to speed up your programs by code tuning. The most important thing to realize is that most statements in a program do not have effect on the running time of that program. There are normally just a few subroutines, possibly even key lines of code within the subroutines, that account for most of the running time. There is little point to cutting in half the running time of a subroutine that accounts for only 1% of the total running time. Focus your attention on those parts of the program that have the most impact.

When code tuning, it is important to gather good statistics. Many compilers and operating systems include profilers and other special tools to help gather information on time and use space. These are invaluable when trying to make a program more efficient, because they can tell you where to invest your effort.

A lot of code tuning is based on the principle of avoiding work rather rather than speeding up work. A common situation occurs when we can test for a condition that lets us skip some work. However, such a test is never completely free. Care must be the cost of the test does not exceed the amount of work saved. While one test might be cheaper than the work potentially saved, the test must always be made and the work can be avoided only some fraction of the time.
