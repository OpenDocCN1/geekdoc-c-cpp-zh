What is the number of inversions? Consider a list **L** containing $n$ values. Let **L$_R$** be **L** in reverse. L has $n(n-1)/2$ distinct pairs of values, each which could potentially be an inversion. Each pair must either be an inversion in **L** or **L$_R$**. The total number of inversions in **L** and **L$_R$** together is exactly $n(n-1)/2$ for an average of $n(n-1)/4$ per list. We therefore know with certainty that any sorting algorithm limits comparisons to adjacent items will cost at least $n(n-1)/4 = \Omega(n^2)$ in the average case.

# 7.3 Shellsort

The next sorting algorithm that we consider called Shellsort, named after its inventor, D.L. Shell. It is also called the **diminishing increment sort**. Unlike Insertion and Selection Sort, there is no real life intuitive way to Shellsort. Unlike exchange sorts, Shellsort makes comparisons and swaps between non-adjacent elements. Shellsort also employs the best-case performance of Insertion Sort. Shellsort's strategy is to make the list "mostly sorted" that a final Insertion Sort can finish the job. When properly implemented, Shellsort will significantly perform better than $\Theta(n^2)$ in the worst case.

Shellsort uses a process that forms the basis for many of the sorts presented in the following sections: Break the list into sublists, sort them, then recombine the sublists. Shellsort breaks the array of elements into "virtual" sublists. Each sublist is sorted using Insertion Sort. Another group of sublists is then chosen and sorted, and so is on.

During each iteration, Shellsort breaks the list into disjoint sublists so that each element in a sublist is a fixed number of positions apart.
