the algorithm as a function of $n$, written as $T(n)$. We will always assume $T(n)$ is a non-negative value.

Let us call $c$ the amount of time required to compare two integers in function largest. We do not care right now what the precise value of $c$ might be. We are not concerned with the time required to increment variable because this must be done for each value in the array, or for the actual assignment when a larger value is found, or the little of extra time taken to initialize largest. We just want a reasonable approximation for the time taken to execute the algorithm. The total time to run **largest** is therefore approximately $cn$, because we must make $n$ comparisons, with each comparison costing $c$ time. We say that function **largest** (and by extension, the largest-value sequential search algorithm for any typical implementation) has a running time expressed by the equation

```
$T(n) = cn$.
```

This equation describes the growth rate for the running time of the largest-sequential search algorithm.

**Example 3.2** The running time of a statement that assigns the first value of an integer array to a variable is simply the time required to copy the value of the first array variable. We can assume this assignment takes a constant amount of time regardless of the value. Let us call $c_1$ the amount of time necessary to copy an integer. No matter how large the array is on a typical computer (given reasonable conditions for memory and array size), to copy the value from the first position of the array is always $c_1$. Thus, the equation for this algorithm is simply

```
$T(n) = c_1$,
```

indicating that the size of the input $n$ has no effect on the running time. This is called a **constant** running time.
