This method of computing sets from bit vectors is applied to document retrieval. Consider the problem of picking from a collection of documents those few contain selected keywords. For each keyword, the document retrieval systems store a bit vector with one for each document. If the user wants to know which documents contain a certain keywords, the three bit vectors are AND together. Those bit positions resulting in a value of 1 corresponds to the desired documents. Alternatively, a bit vector can be stored for each document to indicate those keywords appearing in the document. Such organization is called a signature file. The signatures can be manipulated to find documents with desired combinations of keywords.

# 9.4 Hashing

This section presents a completely different approach to searching arrays: by direct access based on key value. The process of finding a record using some computation to map its key value to a position in the array is called hashing. Most hashing schemes place records in whatever order satisfies the needs of the address calculation, so records are not ordered by value or frequency. The function that maps keys to positions is called a hash function and will be denoted by h. The array that holds the records is called the hash table. A position in the table is also known as a slot. The number of slots in hash HT will be denoted by $M$, with slots numbered from 0 to $M-1$. The goal of a hashing system is to arrange things such that, for any key $K$ and some hash function $h$, $i = h(K)$ is a slot in the table such that $0 \le h(K) < M$, and we have the record of stored at $HT[i]$ equal to $K$.

Hashing is not good for applications where multiple records with the same key value are permitted. Hashing is not a good method for answering range searches. In other words, we cannot easily find all records (if any) whose key fall within a certain range. Nor can we find the record with the minimum or maximum key value, or the records in key order. Hashing is most appropriate for answering the question, "What record, if any, has key $K$?" For applications where access involves only exact-match queries, hashing is usually the search method of choice because it is extremely efficient when implemented correctly. As you will see in this section, there are many approaches to hashing and it is easy to devise an inefficient implementation. Hashing is suitable for both in-memory and disk-based searching and is one of the two most used methods for organizing large databases stored on disk (the other is the B-tree, which is covered in Chapter 10).
