If your algorithm's growth rate is linear (i.e., if the equation that describes the running time on size $n$ is $T(n)=cn$ for some constant $c$), then 100,000 records on the new machine will be sorted in the same time as 10,000 records on the old machine. If the algorithm's growth rate is greater than $cn$, such as $c_1n^2$, then you **will not** be able to do the problem size in the same amount of time on a machine that is ten times faster.

How much larger a problem can be solved in a given amount of time by a faster computer? The new machine is ten times faster than the old. Say that the old machine could solve a problem of size $n$ in an hour. What is the largest problem the new machine can solve in one hour? Figure 3.3 shows how large a problem could be solved on the two machines for five of the running-time functions from Figure 3.1.

This table illustrates many important points. The first two equations are both linear; the value of the constant factor has changed. In both cases, the machine that is ten times faster gains an increase in problem size by a factor of ten. Others, the value of the constant affects the absolute size of the problem that can be solved in a fixed amount of time, it does not affect the *improvement* in problem size (as a proportion to the original size) gained by a faster computer. This relationship holds true regardless of the algorithm's growth rate: Constant factors never affect the relative improvement gained by a faster computer.

An algorithm with time equation $T(n)=2n^2$ does not receive nearly great an improvement from the faster machine as an algorithm with linear growth rate. Instead of an improvement by a factor of ten, the improvement is only square root that: $\sqrt{10} \approx 3.16$. Thus, the algorithm with higher growth rate not only solves a smaller problem in a given time in the first place, it also receives less of a speedup from a faster computer. As computers get faster, the disparity in problem sizes becomes ever greater.

The algorithm with growth rate $T(n) = 5n \log n$ improves by a greater amount than the one with quadratic growth rate, but not by as great as the algorithms with linear growth rate.

Note that mentioning special cases in the case of the algorithm whose running time grows exponentially. In Figure 3.1, the curve for the algorithm whose time is proportional to $2^n$ goes up very quickly. In Figure 3.3, the increase in problem size on the machine is as fast as shown to be about $n+3$ (to be precise, it is $n+\log_2 10$). The increase for an algorithm with exponential growth rate is by a constant addition, not by a multiplicative factor. Because the value of $n$ was 13, the new problem size is 16. If next year you buy another computer ten times faster yet, the new computer (10 times faster than the original) will only run a problem of size 19. If you had a second program whose growth rate is $2^n$ and for which the original computer could run a problem of size 1000 in an hour, then a machine ten times faster can run a problem of size 1003 in an hour! Thus, an exponential growth rate is radically different than the other growth rates shown in Figure 3.3. The significance of this difference is explored in Chapter 7.

Instead of buying a faster computer, what happens if you replace an algorithm whose running time is proportional to $n^2$ with a new algorithm whose running time is proportional to $n \log n$. In the graph of Figure 3.1, a fixed amount of time would appear as a horizontal line. If the line for the amount of time available to solve your problem is above the point at which the two growth rates in question, the algorithm whose running time grows less is faster. An algorithm with running time $n^2$ is slower than $n \log n$ as $n$ becomes large.
