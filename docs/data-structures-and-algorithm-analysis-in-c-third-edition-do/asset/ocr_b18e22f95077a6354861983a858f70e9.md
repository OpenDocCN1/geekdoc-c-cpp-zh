B+-tree insertion is similar to B-tree insertion. The first, the leaf that contain the record is found. If L is not full, then the new record is added, and no other B+-tree nodes are affected. If L is already full, split it in two (dividing the records among the two nodes) and promote a copy of the least-valued key in the newly formed node. With the 2-3-tree, promotion might cause the B+-tree to split, perhaps eventually leading to splitting the root and causing the tree to gain a new level. B+-tree insertion keeps all leaf nodes at equal depth. Figure 10.20 illustrates the insertion process through several examples. Figure 10.21 shows C++ pseudocode sketch of the B+-tree insert algorithm.

To delete record R from the B+-tree, first locate the leaf L that contains R. If L is more than half full, then we only remove R, leaving L still at half full. This is demonstrated by Figure 10.22.

If deleting reduces the number of records in the node below the minimum threshold (underflow), then we must do something to keep the node sufficiently full. The first choice is to look at the node's adjacent siblings to determine if they have a spare record that can be used to fill the gap. If so, enough records are transferred from the sibling so that both nodes have the same number of records. This is done so to delay as long as possible the next time a delete causes this node to underflow. This process might require that the parent node has its placeholder key reverted to reflect the first key value in each node. Figure 10.23 illustrates the process.
