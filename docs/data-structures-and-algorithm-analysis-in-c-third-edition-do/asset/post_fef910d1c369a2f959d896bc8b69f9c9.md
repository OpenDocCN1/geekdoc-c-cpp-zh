There are two new methods, **differ** and UNION. Method **differ** checks if two objects are in different sets, and method UNION merges two sets together. Private method **FIND** is used to find the ultimate root for an object.

An application using the UNION/FIND operations should store a set of n objects, where each object is assigned a unique index in the range 0 to $n-1$. The index refers to the connecting parent pointers in the array. Class ParTrTree creates and initializes the UNION/FIND array, and methods **differ** and UNION take array as inputs.

Figure 6.5 illustrates the pointer implementation. Note that the nodes can appear in any order within the array, and the array can store up to n separate trees. For example, Figure 6.5 shows two trees stored in the same array. This single array can store a collection of items distributed among any arbitrary (and changing) of disjoint subsets.

Consider the problem of assigning members of a set to disjoint subsets called **equivalence classes**. Recall from Section 2.1 that an equivalence relation is reflexive, symmetric, and transitive. Thus, if objects $A$ and $B$ are equivalent, and objects $B$ and $C$ are equivalent, we must be able to recognize that objects $A$ and $C$ are also equivalent.

There are many practical uses for disjoint sets and representing equivalences. For example, Figure 6.6 shows a graph of nodes labeled $A$ through $J$, there is some series of edges that connect any pair of nodes, but node $J$ is disconnected from the rest of the nodes. Such a graph might be used to represent connections as wires between components on a circuit board, or as roads between cities. A, H, and E would be equivalent in 6.6, but J is not equivalent to any other. A subset of equivalent (connected) edges in a graph is a connected component. The goal is to quickly classify the objects into disjoint sets that correspond to the connected components. Another application for UNION/FIND occurs in Kruskal’s algorithm for computing the minimum spanning tree for a graph (Section 11.5.2).

The input to the UNION/FIND algorithm is typically a series of equivalence pairs. In the case of the connected components example, the equivalence pairs would simply be the set of edges in the graph. An equivalence pair might say that object C is equivalent to object A. If so, C and A are placed in the same subset. If a later equivalence relates A and B, then by implication C is also equivalent to B. Thus, an equivalence pair may cause two subsets to merge, each of which contains several objects.

Equivalence classes can be managed efficiently with the UNION/FIND algorithm. Initially, each object is at the root of its own tree. An equivalence pair is processed by checking to see if both objects are pair in the same tree using method *differ*. If they are in the same tree, then no change needs to be made because the objects are already in the same equivalence class. Otherwise, the two equivalence classes should be merged by the UNION method.

**Example 6.2** As an example of solving the equivalence class problem, consider the graph of Figure 6.6. Initially, we assume that each node of the graph is in an equivalence class. This is represented by storing each as the root of its own tree. Figure 6.7(a) shows this initial configuration using the pointer array representation. Now, consider what happens when equivalence pair $(A, B)$ is processed. The root of the tree containing $A$, and the root of the tree containing $B$. To make them equivalent, one of these two roots is set to the pair of the other. In this case it is irrelevant which points to which, we arbitrarily select the first in alphabetical order to be the root. This is represented in the pointer array by setting the field of $B$ (the node in position 1 of the array) to store a pointer to $A$. Equivalence pairs $(C, H), (G, F)$, and $(D, E)$ are processed in similar fashion. When the equivalence pair $(I, F)$ is processed because $I$ and $F$ are their own roots, $I$ is set to $F$. Note that this also makes $G$ equivalent to $I$. The result of processing these five is shown in Figure 6.7(b).

The parent pointer representation places no limit on the number of nodes that share a parent. To make equivalence processing as efficient as possible, the distance from each node to the root of its respective tree should be as small as possible. Thus, we would like to keep the height of the trees small when merging two equivalence classes together. Ideally, each tree would have all nodes pointing directly to the root. Achieving this goal all would require too much additional processing to be worth the effort, so we settle for close as possible.

A low-cost approach to reducing the height is to be smart about how two trees are joined. One simple technique, called the weighted union rule, joins the tree with fewer nodes to the tree with more nodes by making the smaller tree's root to the root of the bigger. This will limit the total depth of the tree to $O\{\log n\}$, because the depth of nodes only in the smaller tree will not increase by one, and the depth of the deepest node in the combined tree can only be at most one deeper than the deepest node before the trees merged. The total number of nodes in the combined tree is therefore at least twice in the smaller.
