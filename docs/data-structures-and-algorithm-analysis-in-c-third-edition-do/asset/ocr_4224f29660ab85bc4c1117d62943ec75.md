Given a database storage records of a particular type, we might want to search for records in multiple ways. For example, we might want to store payroll records in one dictionary that allows us to search by ID, and also store the same records in a second dictionary that allows us to search by name.

4.29 shows an implementation of a payroll record. Class Payroll has multiple fields, which might be used as a search key. By varying the type for the key, and using the appropriate field in each record as the value, we can define a dictionary whose search key is the ID field, another search key is the name field, and a third search key is the address field. Figure 4.30 shows an example where Payroll objects are stored in two separate dictionaries, using the ID as the key and the other using the name as the key.

The fundamental operation for a dictionary is finding a record that matches a given key. This raises the issue of how to extract the key from the record. We would like any dictionary implementation to support arbitrary record types, so we need some mechanism for extracting keys that is sufficiently general. One approach is to require all record types to support some particular method that returns the key value. For example, in Java the Comparable interface can be used to provide to this effect. Unfortunately, this approach does not work when the same record type is meant to be stored in multiple dictionaries, keyed by a different field of the record.
