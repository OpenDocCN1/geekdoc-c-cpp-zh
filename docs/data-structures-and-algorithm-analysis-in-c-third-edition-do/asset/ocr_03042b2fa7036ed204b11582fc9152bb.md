An implementation detail to note is that Figure 10.17 shows internal nodes containing three keys and four pointers, BPNode is slightly different in it stores keys-pointer pairs. Figure 10.17 shows the B+-tree as it is traditionally drawn. To simplify implementation in practice, nodes really associate with each pointer. Each internal node should be assumed to hold the leftmost position of the node's subtree. that is less than or equal to any key value in the subtree. B+-implement typically store an additional dummy record in the leftmost leaf node whose key is less than any legal key value.

B+-trees are exceptionally good for range queries. Once the record in the range has been found, the rest of the records with keys in the range can be accessed by sequential processing of the remaining records in the first node, and then continuing the linked list of leaf nodes as far as necessary. Figure 10.18 illustrates the B+-tree.
