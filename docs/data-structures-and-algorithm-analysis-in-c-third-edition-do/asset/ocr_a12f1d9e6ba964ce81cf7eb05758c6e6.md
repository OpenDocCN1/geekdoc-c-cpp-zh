In practice these are unrealistic assumptions, such assumptions are implicitly part of many tournament organizations. Most tournament organizers, we can simply accept these assumptions and come up with an algorithm for playing the games that gives us some ranking based on the results we obtain.

Recall Insertion Sort, when we put element i into a sublist of the first i-1 elements. What if we modify the Insertion Sort algorithm to use binary search to locate where the ith element goes in the sorted sublist? This algorithm is called binary insert sort. For a general-purpose sorting algorithm, this is not practical because we have to (on average) move i/2 elements to make room for the newly inserted element in the sorted sublist. But if we count only comparisons, binary insert sort is pretty good. And we can use some ideas to get closer to an algorithm that uses the absolute number of comparisons to sort.

Consider what when we run insert sort on five elements. How many comparisons do we need? We insert the second with one comparison, the third with two comparisons, and the fourth with two. When we insert the fifth element into the sorted list of four elements, we need to do three comparisons in the worst case. Notice exactly what happens when we attempt to do this insertion. We compare the fifth element against the second. If the fifth is bigger, we have to compare it against the third, and if it is bigger we have to compare it against the fourth. In general, is binary search most efficient? When we have 2' - 1 elements in the list. It is least efficient when we have 2' elements in the list. So, can we do a bit better if we arrange our insertions to avoid inserting an element into a list of size 2' if possible.
