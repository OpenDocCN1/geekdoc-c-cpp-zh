After removing each of the remaining values in turn, the array will be properly sorted from least to greatest. This is Heapsort uses a max-heap rather than a min-heap as might have been expected. Figure 7.15 rates Heapsort. The complete C++ implementation is as follows:

```cpp
template <typename E, typename Comp>
void heapsort(E A[], int n) { // Heapsort
  E maxval;
  heap<E, Comp> H(A, n); // Build the heap
  for (int i=0; i<n; i++)      // Now sort
    maxval = H.removefirst();
}
```

Because the heap takes Θ(n) time (see Section 5.5), and because deletion of the maximum element takes Θ(log n) time, we see that the entire Heap operation takes Θ(log n) time in the worst, and best cases. While slower than Quicksort by a constant factor, Heapsort has an advantage over the other sorts studied so far. Building the heap is relatively cheap Θ(n) time. Removing the maximum element from the heap requires Θ(n + k log n). If k is small, this is a substantial improvement over the time required to find the k largest elements in an array, can we do so using one of the other sorting methods described earlier (many of which would require sorting all of the array first). One situation where we are able to take advantage of this concept is in the implementation of Kruskal's minimum-cost spanning tree (MST) algorithm of Section 11.5.2. That algorithm requires edges be visited in ascending order (so, use a min-heap), this process stops as soon as the MST is complete. Thus, only a relatively small fraction of the edges needs-sorted.

The extended Binsort is shown above. The hope is that the relatively inexpensive processing will keep only a small number of records in each bin, and a "cleanup sort" within the bins will then be relatively cheap.

There is a way to keep the number of bins and the related processing small while allowing the cleanup sort to be based on Binsort. Consider a sequence of keys in the range 0 to 99. If we have ten bins available, we can first assign records to the bin matching its rightmost decimal digit. Then, we take these records from the bins in order and reassign them to the bins on the basis of their leftmost (10's place) digit (define values in range 0 to 9 to have a leftmost digit of 0). In other words, assign the ith record from array A to a bin to have a leftmost digit... using the formula **A[i]/10**. If we know the values from the bins in order, the result is a sorted list. Figure 7.17 illustrates this process.

A generalization to Binsort yields bucket sort. Each bin is associated with not just one key, but rather a range of key values. A bucket sort assigns records to bins and relies on other sorting technique to sort the records within each bin. The hope is that the relatively inexpensive processing will keep only a small number of records in each bin, and a "cleanup sort" within the bins will then be relatively cheap.

Unfortunately, a large key requires an unacceptably large array B. Thus, the extended Binsort is useful only for a limited key range. Radix sort is another method that sorts keys by processing their digits. It starts from the least significant digit to the most significant, using a stable sort (like counting sort) for each digit.
