Since the heap is a complete binary tree, its height is guaranteed to be the minimum position. In particular, a heap containing $n$ nodes will have a height of $\lfloor\log n\rfloor$. Intuitively, we can see that this is true because to double the number of nodes in the tree (the $i$th level has $2^i$ nodes, and the sum of the first $i$ is $2^{i+1}$). Starting at 1, we can only do $\log n$ times to reach a value of $n$. To be precise, the height of a heap with $n$ nodes is $\lfloor\log(n+1)\rfloor$.

Each call to **insert** takes $\Theta(\log n)$ time in the worst case, because the value can be inserted at most the distance from the bottom to the top of the tree. Thus, if we insert $n$ values into the heap, one at a time, will take $\Theta(\log n)$ time in the worst case.

One algorithm stems from induction. Suppose that the left and right trees of the root are already heaps, and $R$ is the name of the root. This situation is illustrated by Figure 5.21. In this case there are two possibilities:

(2) $R$ has a value less than one or both of its children. In this case, $R$ should be exchanged with the child that has greater value. The result will be a heap, except that $R$ might be less than one or both of its (new) children. In any complete tree, approximately half of the nodes are leaves and cannot be moved downward at all. Removing the (root) value from a heap containing $n$ elements requires that we maintain the complete binary tree shape, and that the $n-1$ nodes conform to the heap property. We can maintain the proper shape by moving the element in the last position in the heap (the current last element in the array) to the root position. We now consider the heap to be one element smaller. Unfortunately, the new value is probably not the maximum value in the new heap. This problem is easily solved by *siftdown* to reorder the heap. Because the heap is $\log n$ levels deep, the cost of deleting the maximum element is $\Theta(\log n)$ in average and worst cases.

The heap is a natural implementation for the priority queue discussed in this section. Jobs can be added to the heap (using their priority value as the ordering key) when needed. *removemax* can be called whenever a new job is to be executed.
