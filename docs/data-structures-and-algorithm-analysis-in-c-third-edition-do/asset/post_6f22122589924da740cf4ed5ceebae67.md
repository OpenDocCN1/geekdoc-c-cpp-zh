### 15.2.2 Searching in Sorted Lists

We will now assume that $L$ is sorted. In this case, is linear search optimal? Clearly no, but why? Because we have additional information to work with that we do not have when the list is unsorted. We know that the standard binary search has a worst cost of $O(\log n)$. We can prove that this is the best possible in the worst case with a proof similar to that used to show the lower bound on sorting.

Again we use decision tree to model our algorithm. Unlike searching an unsorted list, comparisons between elements of $L$ tell us nothing about their relative order, so we consider only comparisons between $K$ and an element $L$. At the root of the decision tree, we know our rules out no positions in $L$, so all are potential candidates. As we take branches in the decision tree based on the result of comparing $K$ to an element in $L$, we gradually rule out potential candidates. We eventually reach a leaf node in the tree representing the single position that can contain $K$. There must be at least $n+1$ nodes in the tree because we have $n+1$ distinct positions that $K$ can be (in any position in $L$, plus not in $L$ at all). Some path in the tree must be at least $\log n$ levels deep, and the deepest node represents. Thus, any algorithm on a sorted array requires at least $\Omega(\log n)$ comparisons in the worst case.

We can modify this to find the average cost lower bound. Again, we model algorithms using decision trees. Except now we are not interested in the depth of the deepest node (the worst case) and therefore the tree with the least-deepest node. Instead, we are interested in knowing what the minimum possible is

of the leaf nodes. Define the total path length as the sum of the levels for each node. The cost of an outcome is the level of the corresponding node plus 1. The average cost of the algorithm is the average cost of the outcomes (total path/$n$). What is the tree with the least average depth? This is equivalent to the tree that corresponds to binary search. Thus, binary search is optimal in the average case.

Binary search is indeed an optimal algorithm for a sorted list in the worst and average cases searching a sorted array, there are a number of circumstances that might lead us to select another algorithm. One possibility is that we know nothing about distribution of the data in the array. We saw in Section 9.1 if each position in L is equally likely to hold X (equivalently, the data are well distributed over the full range), then an interpolation search $\Theta(\log n)$ in the average case. If the data are not sorted, using binary search requires us to pay the cost of sorting the list in advance, which is only worthwhile if many (at O(log n)) searches are performed on the list. Binary search also requires that the list (even if sorted) be implemented using an array or some structure that supports random access to all elements with equal cost. Finally, if we know all requests in advance, we might prefer to sort the list by frequency and do linear search in extreme search distributions, as discussed in Section 9.2.

How can we find the largest value in a sorted list? Obviously we just go to the last position. But what if we have an unsorted list? Can we do better than sort it? If we are looking for minimum or maximum value, certainly we can do better than sorting the list. This is true for second value? In later sections we will examine these questions. For this section, we will continue our examination of lower bounds by reducing the problem of finding the maximum value in an unsorted list. Here is a simple algorithm for finding the largest:

```c
// Return the largest value in "A" of size "n"
int largest(int A[], int n) {
    int largest = 0; // Holds largest position
    for (int i=1; i<n; i++) // For each element
        if (A[largest] < A[i]) // If A[i] is larger
            largest = i; // remember its position
    return largest; // Return largest position
}
```

Obviously this algorithm requires n comparisons. Is this optimal? It should be intuitively obvious that it is, but let us try to prove it (Before reading down your own proof.)

Proof 1: The winner must compare against all other elements, so there must be $n-1$ comparisons. This proof is clearly wrong because the winner does not need to explicitly compare against all elements to be recognized. For example a single-elimination tournament requires only $n-1$ comparisons, and the winner does not play again.

Proof 2: Only the winner does not lose. There are $n-1$ losers. A simple comparison generates (at most) one (new) loser. Therefore there must be $n-1$ comparisons. This proof is sound, although it will be useful to introduce the concept of poset as we did in Section 15.2. We can view the problem starting with a poset where there are no known relationships, so every member of the collection is in its own DAG of one element.

Proof 2a: To find the largest value, we start with a poset of $n$ DAGs each with one element, and we must build a poset having all elements in one DAG that is maximum (and by implication $n-1$ losers). We wish to connect the elements of the poset to a single DAG with the minimum number of links. This requires at least $n-1$ links. A comparison provides at most one new link. Thus, a minimum of $n-1$ comparisons must be made.

What is the cost of largest? Because it always does the number of comparisons clearly must cost $n-1$. We can also consider the number of assignments that largest must do. Function largest might do an assignment on any iteration of the for loop. Because this event happens, or does not, if we are given information about distribution we could guess that an assignment is made after each comparison with probability half. This is clearly wrong. In fact, largest does an assignment on the $i$-th iteration if $A[i]$ is the biggest of the first $i$ elements. Assuming all permutations are equally likely, the probability of this is $1/i$. The average number of assignments done is

$$\sum_{i=2}^{n} \frac{n}{i} = \sum_{i=1}^{n} \frac{n}{i}$$

which is the Harmonic Series $\mathcal{H}_n$, $\mathcal{H}_n = \Theta(\log n)$. More exactly, $\mathcal{H}_n$ is close to $\log_e n$. Is this average reliable? That is, how much will a given run of the program deviate from the mean? According to Chebyshev's Inequality, an observation will fall within two standard deviations of the mean at least 75% of the time.

For largest, the variance is

$$\mathcal{H}_n - \frac{\pi^2}{6} = \log_e n - \frac{\pi^2}{6}$$

The standard deviation is about $n - 2\sqrt{\log n}$ and $n + 2\sqrt{\log n}$. $75\%$ of the observations are between $\sqrt{\log n}$, $n$. So, is this a narrow spread or a wide spread? Compared to the mean value, this spread is pretty wide, meaning that the number of assignments varies widely from run to run of the program.

## 15.4 Adversarial Lower Bounds Proofs

Our next problem will be finding the second largest in a collection of objects. Consider what happens in a standard single-elimination tournament. If we assume that the “best” team wins every game, is the second best that in the finals? Not necessarily. We expect that the second best must lose to the best, but they might meet at any time.

Let us go through this “algorithm for algorithms” by first proposing an algorithm, then a lower bound, and seeing if they match. Unlike our analysis for most problems, this time we are going to count the exact number of comparisons for finding the second largest: first find the maximum (in $n-1$ comparisons), discard it, and then find the maximum of the remaining elements (in $n-2$ comparisons) for a total cost of $2n-3$ comparisons. Is this optimal? That seems doubtful, but let us now prove the step of attempting to prove a lower bound.

**Theorem 15.2** The lower bound for finding the second largest value is $2n-3$.

**Proof:** Any element that loses to anything other than the maximum cannot be second. So the only candidates for second place are those that lose to the maximum. Function largest compares the maximum element to $n-1$ others, we might need $n-2$ additional comparisons to find the second largest.
