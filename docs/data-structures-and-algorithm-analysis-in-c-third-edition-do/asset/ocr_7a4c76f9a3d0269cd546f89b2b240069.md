On the other hand, if we use a sorted array-list to implement the dictionary, then binary search can be used to find a record in only $O(\log n)$ time. However, insertion will now require $\Theta(n)$ time on average, because the proper location for the new record in the sorted list has been found, may the record must be shifted to make room for the new record.

Is there some way to organize a collection of records so that inserting and searching for records can be done quickly? This section presents the binary search tree (BST), which allows an improved solution to this problem.

A BST is a tree that conforms to the following condition, known as the **Binary Search Tree Property**: All nodes stored in the left subtree of a node whose key value $K$ have key values less than $K$. All nodes stored in the right subtree of a node whose key value $K$ have key values greater or equal to $K$. Figure 5.13 shows two BSTs for a collection of values. One consequence of the Binary Search Tree Property is that if the BST nodes are printed using an inorder traversal, the resulting enumeration will be in sorted order from lowest to highest.
