**Figure 12.17** Garbage cycle example. All elements in the cycle have non-zero reference counts because each element has one pointer to it, even though the entire cycle is garbage (i.e., no static variable in the program points to it).

Reference counts are used by the UNIX file system. Files can have multiple names, called links. The file system keeps a count of the number of links to each file. When a file is “deleted,” in actuality its link field is simply reduced by one. If there is another link to the file, then no space is recovered by the file system. When the number of links goes to zero, the file’s space becomes available for reuse.

Reference counts have several major disadvantages. First, a reference count must be maintained for each memory object. This works well when the objects are large, such as a file. However it will not work well in a system such as LISP where the memory objects typically consist of two pointers or a value (atom). Another major problem occurs when garbage contains cycles. Consider Figure 12.17. Here each memory object is pointed to once, but the collection of objects is still garbage because no pointer points to the collection. Thus, reference counts work only when the memory objects are linked together without cycles, such as the UNIX file system where files can only be organized as a DAG.

Another approach to garbage collection is the **mark/sweep** strategy. Here, each memory object needs only a single mark bit rather than a reference counter field. When free store is exhausted, a separate garbage collection phase takes place as follows.

+   1. Clear all mark links.
2. Perform depth-first search (DFS) following pointers beginning with the system's list of static variables. Each memory element encountered during the DFS has its mark turned on.
3. A “sweep” is made through the memory pool, visiting all elements. Unmarked elements are considered garbage and placed in free.

The advantages of the mark/sweep approach are that it needs less space than for reference counts, and it works for cycles. However, there is a major disadvantage. This “hidden” space requirement is needed to do the processing. DFS is a recursive algorithm: it must be implemented recursively, in which case the compiler’ runtime system maintains a stack, or the memory manager can maintain its own stack. What happens if all memory is contained in a single linked list? The depth of the recursion (or the size of the stack) is the number of memory cells! Unfortunately, the space for the DFS stack might be available at the worst conceivable case, that is, when free memory has been exhausted.
