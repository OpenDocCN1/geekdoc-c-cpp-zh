# 17.2.3 Coping with NP-Complete Problems

Finding that your problem is NP-complete might not mean that you can just forget about it. Traveling salesman need to find reasonable sales routes regardless of the complexity of the problem. What do you do when faced with an NP-complete problem that you must solve?

There are several techniques to try. One approach is to run only small instances of the problem. For some problems, this is not acceptable. For example, TRAVELING SALESMAN grows so quickly that it cannot run on modern computers for problem sizes much over 30 cities, which is not an unreasonable problem size for real-life situations. Some other problems in NP, requiring exponential time, still grow slowly enough that they allow solutions for problems of useful size.

Consider the Knapsack problem from Section 16.1.1. We have a dynamic programming algorithm whose cost is Θ(nk) for objects being fit into a knapsack of size K. It turns out Knapsack is NP-complete. Isn't this a contradiction? Not consider the relationship between n and K. How big is K? Input size is O(n log K) because the items are smaller than K. Thus, Θ(n) is exponential on input.

This dynamic programming algorithm is tractable if the numbers are "reasonable." That is, we can successfully find solutions to the problem when n is K in the thousands. Such an algorithm is called a pseudo-polynomial algorithm. This is different from TRAVELING SALESMAN which cannot be solved when n = 100 given current algorithms.

A second approach to handling NP-complete problems is to solve a special instance of the problem that is not hard. For example, many problems on graphs are NP-complete, but the same problem on restricted types of graphs is not difficult. For example, while the VERTEX COVER and K-CLIQUE problems are NP-complete, there are polynomial time solutions for bipartite graphs (i.e., graphs whose vertices can be separated into two subsets that no pair of vertices within one of the subsets has an edge between them). 2-SATFIABILITY (where every clause in a Boolean expression has at most two literals) has a polynomial time solution. Some geometric problems require only polynomial time in two dimensions, but are NP-complete in three dimensions or more. KNAPSACK is considered to run in polynomial time if the numbers (and K) are "small." Small means that they are polynomial on n, the number of items.

In general, if we want to guarantee that we get the correct answer for an NP-complete problem, we potentially need to examine all of the (exponential number of) possible solutions. However, with some organization, we might be able to examine them quickly, or avoid examining a great many of the possible answers in some cases.
