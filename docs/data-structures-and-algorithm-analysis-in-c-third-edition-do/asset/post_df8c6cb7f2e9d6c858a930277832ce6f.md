
## Preface

To keep the presentation as clear as possible, some important features of C++ are avoided here. I deliberately minimize use of certain features commonly used by experienced C++ programmers as class hierarchy, inheritance, and virtual functions. Operator and function overloading is used sparingly. C-like initialization syntax is preferred to some of the alternatives offered by C++.

While the C++ features mentioned above have valid design rationale in real programs, they tend to obscure rather than enlighten the principles espoused in this book. For example, inheritance is an important tool that helps programmers avoid duplication, and minimize bugs. From a pedagogical standpoint, however, inheritance makes examples harder to understand since it tends to spread the description of one logical unit among several classes. Thus, my definitions use only where inheritance is explicitly relevant to the point illustrated (e.g., Section 5.3.1). This does not mean that a programmer should do likewise. Avoiding code duplication and minimizing errors are important goals. Treat the programming examples as illustrations of data structure principles, but do not copy them directly into your programs.

One decision I had to make was to use templates in the code examples. In the first edition of this book, the decision was to leave templates out as it felt that their syntax obscures the meaning of the code for those not familiar with C++. In the following years, the use of C++ in computer science curricula has greatly expanded. I now assume that readers of the text will be familiar with C++. Thus, templates are used extensively in the code examples.

My implementations are to provide concrete illustrations of data structure principles, as as to the textual exposition. Code examples should not be read or used in isolation from the associated text as the bulk of each example's documentation is contained in the text, not the code. The code complements the class implementations, not the other way. They are not meant to be a series of commercial-quality class implementations. If you are looking for a complete implementation of a standard data structure for use in your code, you would do well to do an Internet search.

For instance, the code examples provide less parameter checking than is sound programming practice, since including checking would obscure rather than illuminate the text. Whether parameter checking and testing for other constraints (e.g., whether a value is being removed from an empty container) is included in the form of a call to Assert. The inputs to Assert are Boolean expression and characteristic string. If this expression evaluates to false, then a message is printed and the program terminates immediately. Terminating when a function receives a bad parameter is generally undesirable in real programs, but is quite adequate for understanding how a data structure is meant to operate. In real programming applications, C++'s exception handling features should be used to deal with input data errors. However, assertions provide a simpler mechanism for indicating required conditions in a way that is both adequate for clarifying how a data structure is meant to operate, and is easily modified into true exception handling.

See the Appendix for the implementation of **Assert.**

I make a distinction in the text between “C++ implementations” and “pseudocode.” Code labeled as a C++ implementation has actually been compiled and tested on one or more C++ compilers. Pseudocode examples often conform closely to C++ syntax, which typically contain one or more lines of higher-level description. Pseudocode is used when I perceived a greater pedagogical advantage to a simpler, but less precise, description.

**Exercises and Projects:** Proper implementation and analysis of data structures cannot be learned simply by reading a book. You must practice by implementing real programs, constantly comparing techniques to see what works best in a given situation.

One of the most important aspects of a course in data structures is that it is where students learn to program using pointers and dynamic memory allocation, implementing data structures as linked lists and trees. It is where students truly learn recursion. In our curriculum, this is the first course where students do significant design, because it often requires real structures to motivate design exercises. Finally, the fundamental differences between memory-based and disk-based access cannot be appreciated without practical programming experience. For all of these reasons, a structures course cannot succeed without a significant programming component. In our department, the structures course is one of the most difficult programming course in the curriculum.

Students should also work problems to develop their analytical abilities. I provide over 450 exercises and suggestions for programming projects. I urge readers to take advantage of them.
