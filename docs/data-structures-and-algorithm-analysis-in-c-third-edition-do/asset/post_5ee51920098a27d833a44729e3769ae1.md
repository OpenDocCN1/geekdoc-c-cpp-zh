From defining rules for 2-3 trees we can derive relationships between number of nodes in the tree and the depth. A 2-3 tree of height $k$ has at least $2^{k-1}$ leaves, because each internal node degenerates to the shape of a complete binary tree. A 2-3 tree of height $k$ has at most $3^{k-1}$ leaves, because each internal node can have at most three children.

Searching for a value in a 2-3 tree is similar to searching in a BST. Searching begins at the root. If the root does not contain the search key K, then the search progresses to the only subtree that may contain K. The value(s) stored in the root node determine which subtree is correct. For example, searching for the value 30 in the tree of Figure 10.9, we begin with the root node. Because 30 is between 18 and 33, it can only be in the middle subtree. Searching the middle child of the root node yields the desired record. Searching for 15, the first step is again to search the root node. Because 15 is less than 18, the first (left) branch is taken. At the next level, we take the second branch to the leaf node containing 15. If the search key was 16, upon encountering the leaf node 15 we would find that the search key is not in the tree. // Find the record that matches a given key value
template <typename key, typename E>
E TTTreeNode<key, E>* root, key k) const {
    if (root == NULL) return NULL; // value not found
    if (k < root->lkey) return root->lval;
    if (k > root->rkey) return root->rval;
    if (k < root->lkey) // Go left
        return findhelp(root->left, k); // EMPTYKEY
    else if (root->center) // 2 child node
        return findhelp(root->center, k); // Go center
    else if (k < root->rkey) // Go center
        return findhelp(root->center, k);
    else return findhelp(root->right, k); // Go right
}

Insertion into a 2-3 tree is similar to insertion into a BST to the extent that the new record is placed in the appropriate leaf node. Unlike BST insertion, a new node is created to hold the record inserted, that is, the 2-3 tree does not grow downward. The first step is to find the leaf node that would contain the record if it were in the tree. If this leaf node contains only one value, then the new record can be added to that node with no modification to the tree, as illustrated in Figure 10.12. In this example, a record with key value 14 is inserted. Searching from the root, we come to the leaf node that stores 15. We add 14 as the left value (pushing the record 15 to the rightmost position).

If we insert the new record into a leaf node L that already contains two records, then more space must be created. Consider the two records of L and the record to be inserted without concern for which two were already in L and which is the new record. The first step is to split L into two nodes. Thus, a new node—call it L'—must be created. L' receives the greatest of the three.

The 2-3 tree insert and delete routines do not add nodes at the bottom of the tree. Instead, they cause leaf nodes to split or merge, causing a ripple effect moving up to the root. If necessary the root will split, causing a new root to be created and making the tree one level deeper. if the last two children of the root merge, the root is removed and the tree will lose a level. In either case, all leaf nodes are always at the same level. When all leaf nodes are at the same level, we say that a tree is **height balanced**. Because the 2-3 tree is height balanced, and every internal node has at least two children, we know that the maximum depth of the tree is $\log n$. Thus, 2-3 tree insert, and delete operations require $\Theta(\log n)$ time.

When deleting a record from the 2-3 tree, there are three cases to consider. The simplest occurs when the record is removed from a leaf node containing two records. In this case, the record is simply removed, and no other nodes are affected. The second case occurs when the only record in a leaf node is removed. The third case occurs when a record is removed from an internal node. In both the second and the third cases, the deleted record is replaced with another that can take its place while maintaining the order. If the tree is sparse enough, there is no such record available. In this situation, sibling nodes are merged. The delete operation for 2-3 tree is excessively complex and will not be described further. Instead, a complete discussion of deletion will be postponed until the next section, where it can be generalized for the B-tree.
