# **Example 9.7** Here is a hash function for strings of characters:

```
int h(char * x) {
    int i, sum;
    for (i=0; x[i] != '\0'; i++)
        sum += (int) x[i];
    return sum % M;
}
```

This function uses the ASCII values of the letters in the string. If the hash table M is small, this hash function should do a good job of distributing strings evenly among the hash table slots, it gives equal weight to all characters. This is an example of the *folding* approach to designing a hash function. Note that the order of the characters in the string has no effect on the result. A similar method for integers would add the digits of the key value, assuming that there are enough digits to (1) keep any one or two digits with bad distribution from squaring the results of the process and (2) generate a sum much larger than M. With many other hash functions, the final step is to apply the modulus operator to the result, using table M to generate a value within the table range. If the sum is not sufficiently large, the modulus operator will yield a poor distribution. For example, because the ASCII value for “A” is 65 and “Z” is 90, **sum** will always be in the range 650 to 900 for a string of ten uppercase case letters. For a hash table of size 100 or less, a reasonable distribution results. For a hash table of size 1000, the distribution is terrible because only slots 650 to 900
