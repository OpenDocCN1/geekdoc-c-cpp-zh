# Lists, Stacks, and Queues

If your program needs to store a few things — numbers, payroll records, or job descriptions for example — the simplest and most effective approach might be to put them in a list. Only when you have to organize and search through a large number of things do more sophisticated data structures usually become necessary. This chapter describes the fundamental data structures: lists, stacks, and queues. 

The goals of this chapter are: (1) Give an intuitive definition of what we mean by list; (2) Illustrate the use of these data structures with asymptotic analysis; and (3) Introduce the concept of dictionaries.

The chapter is organized as follows: 
- 4.1 List
- 4.2 Stack
- 4.3 Queue
- 4.4 Dictionary

## 4.1 Lists

We have an intuitive understanding of what we mean by "list." Our first step is to define precisely what we mean so that this intuitive understanding can be converted into a concrete data structure. In other words, we perceive that there is a first element, a second element, and so on. We view a list as embodying a sequence, as defined in 2.1.

A list is said to be empty when it contains no elements. The number of elements stored is called the length of the list. The beginning of the list is called the head, and the end of the list is called the tail. Whether or not there be some relationship between the value of an element and its position in the list—for example, sorted lists—unordered lists have no particular relationship between element values and positions. This section will consider only unordered lists. Chapters 7 and 9 treat the problems of how to create and search lists.
