What is the cost of buildHeap? Clearly it is the sum of the costs for the calls to siftdown. Each siftdown operation can cost at most the number of levels it takes for the node being sifted to reach the bottom of the tree. In any complete tree, approximately half of the nodes are leaves and cannot be moved downward at all. One quarter of the nodes are one level above the leaves, and their elements can move down at most one level. At each step up the tree we get the number of nodes as at the previous level, and an additional height of. The maximum sum of total distances elements can go is

$\sum_{i=1}^{n} i_2 = \frac{n}{2} \sum_{i=1}^{n-1} i$

From Equation 2.9 we know that this algorithm gives a closed-form solution of approximately 2, so algorithm takes $\Theta(n)$ time in the worst case. This is far better than building the heap element at a time, which would cost $\Theta(n \log n)$ in the worst case. It is also faster than the $\Theta(n \log n)$ average-case time and $\Theta(n^2)$ worst-case time to build the BST.

Removing the (root) value from a heap containing $n$ elements requires that we maintain the complete binary tree shape, and that the $n-1$ nodes conform to the heap property. We can maintain the proper shape by moving the element in the last position in the heap (the current last element in the array) to the root position. We now consider the heap to be one element smaller. Unfortunately, the new value is probably not the maximum value in the new heap. This problem is easily solved by siftdown to reorder the heap. Because the heap is $\log n$ levels deep, the cost of deleting the maximum element is $\Theta(\log n)$ in average and worst cases.

The heap is a natural implementation for the priority queue discussed in this section. Jobs can be added to the heap (using their priority value as the ordering key) when needed. removemax can be called whenever a new job is to be executed.
