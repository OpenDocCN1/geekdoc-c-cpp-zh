// Modified version of Insertion Sort for varying increments
tntemplate <typename E, typename Comp>
void insertort2(E A[], int n, int incr) {
    for (int i=incr; i<n; i+=incr) {
        for (int j=i; j>=incr &&
            (Comp():prior(A[j], A[j-incr]))
            swap(A[j], A[j-incr]);
        }
    }
}

template <typename E, typename Comp>
void shellsort2(E A[], int n) { // Shellsort
    for (int i=n/2; i>0; i/=2) {
        for (int j=0; j<n; j++) {
            insertort2<E, Comp>(&A[j], n-j, i);
        }
    }
shellsort2<E, Comp>(A, n, 1);

The analysis of Shellsort is difficult, so we must accept without proof that the average-case performance of Shellsort ("divisions by three" increments) is $O(n^{1.5})$. Thus, for the increments we can reduce this upper bound somewhat. Shellsort is substantially better than Insertion Sort, or any of the $\Theta(n^2)$ sorts presented in Section 7.2. In fact, Shellsort is not terrible when compared with the adaptive sorts whenever $n$ is of medium size (though it is to a bit slower than those other algorithms when they are well implemented). Shellsort illustrates how we can exploit the special properties of an algorithm (in this case Insertion Sort) even if in general that algorithm is unacceptably slow.

# 7.4 Mergesort

A natural approach to solving is to divide and conquer. In terms of sorting, we might consider breaking the list to be sorted into pieces, process the pieces, and then put them back together somehow. A simple way to do this would be split the list in half, sort the halves, and merge the merged halves together. This is the idea behind **Mergesort**.
