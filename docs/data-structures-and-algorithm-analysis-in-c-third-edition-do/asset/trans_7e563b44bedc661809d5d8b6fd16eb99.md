

## 第7章 内部排序

```cpp
template <typename E, typename getkey>
void radix(E A[], E B[]) {
    int n, int k, int r, int cnt[] {
    // cnt[i] 存储桶[i] 中的记录条数
    int j;

    for (int i=0, rto=1; i<k; i++, rto*=r) { // 对于 k 位
        for (int j=0; j<r; j++) cnt[j] = 0; // 初始化 cnt

        // 统计此轮中每个桶的记录数
        for (int j=0; j<n; j++) cnt[getkey(A[j])/rto]++;
        // 索引 B: cnt[j] 将是桶 j 最后一个槽位的索引
        for (int j=1; j<r; j++) cnt[j] = cnt[j-1] + cnt[j];

        // 将记录放入桶中，从每个桶的底部开始
        // 由于桶是从底部填充的，因此 j 递减
        for (int j=n-1; j>=0; j--)
            B[--cnt[getkey(A[j])/rto]] = A[j];

        for (int j=0; j<n; j++) A[j] = B[j]; // 将 B 拷贝回 A
    }
}
```

图 17.8 基数排序算法。

在这个示例中，r=10 个桶，n=12 个位于 0 到 $r^2-1$ 范围内的键。总计算量为 $\Theta(n)$，我们对每个记录和每个桶都进行了常数次操作。这比简单的桶排序（Bsort）有了巨大的改进，在桶排序中桶的数量必须与键的范围一样大。注意，示例使用了 r=100，以便于可视化计算：记录根据最右侧和最左侧小数位的值放入桶中。任何数量的桶都可以。这是一个基数排序（Radix Sort）的示例，之所以命名是因为计算是基于任何键范围内键的基数（radix或base）。我们根据从右到左侧键的值将记录分配到桶中。如果有 $k$ 位，则要求我们排序 $k$ 次。

与合并排序一样，实现一个高效的基数排序是困难的。特别是，我们更倾向于对值数组进行排序并避免处理链表。如果每个桶中有很多值，则可以使用大小为 $r$ 的辅助数组来存放桶。例如，如果第一轮桶0接收了三条记录，桶1接收了五条记录，那么我们可以简单地为0预留前三个位置，并为1预留接下来的五个位置。图 7.18 的 C++ 实现采用了这种方法。在每一轮的结束时，记录被拷贝回原始数组。

## 7.7 桶排序与基数排序

第一个 for 循环初始化数组 `cnt`。第二个循环统计要分配到每个桶的记录数。第三个循环将 `cnt` 中的值设置为它们在数组 $B$ 内部的正确索引。注意存储在 `cnt[j]` 中的索引是桶 $j$ 的最后一个索引；桶从高索引到低索引填充。第四个循环将记录分配到桶中（在数组 $B$ 内）。最后一个循环仅将记录拷贝回数组 $A$ 以供下一轮使用。基数排序在第 $i$ 次迭代的二进制计算中存储 $r^i$。图 7.19 显示该算法如何处理图 7.17 中的输入。

该算法遍历基数为 $r$ 的 $n$ 个数字列表，每轮完成 $\Theta(n+r)$ 的工作。总工作量为 $\Theta(nk+rk)$。在 $n$ 方面什么值可能更小？可以使用基 2 或 10。基 26 适用于字符串排序。目前，我们将 $k$ 视为一个常数值，并在确定复杂性时忽略它。变量 $k$ 与键的范围有关：一个键在基 $r$ 下可能拥有的最大位数。在某些应用中，我们可以确定 $k$ 的大小有限，因此可能考虑将其视为常数。在这种情况下，基数排序在最坏情况下为 $\Omega(n)$，使其成为我们研究过的最佳渐近复杂度。

将 $k$ 视为常数是一个合理的假设吗？还是 $k$ 和 $n$ 之间是否存在某种关系？如果范围有限且重复键值很常见，那么 $k$ 和 $n$ 之间可能没有关系。为了清楚这种区别，使用 $N$ 表示由 $n$ 条记录所使用的不同键的数。因此，$N \le n$。因为表示 $N$ 个不同键至少需要 $\log_r N$ 位，所以我们知道 $k \le \log_r N$。

现在，考虑没有键重复的情况。如果有 $n$ 个唯一键（$n=N$），则需要 $n$ 个不同值来表示。因此，$k \ge \log_r n$。因为区分 $n$ 个不同键至少需要 $\Omega(\log n)$ 位（带常数因子），$k$ 是 $\Omega(\log n)$。这导致处理 $n$ 个不同键的基数排序复杂度为 $\Omega(n \log n)$。

范围可能大得多；$\log n$ 位只是 $n$ 个不同值的最好情况。因此，$k$ 的估计可能过于乐观。对于 $n$ 个不同值的通用情况，基数排序是 $\Omega(n)$ 的。基数排序可以通过使基 $r$ 尽可能大来改进。考虑整数键的情况。设置 $r = 2^i$。其他情况下，$r$ 与每轮处理的位数有关。每次位数翻倍，轮数就减半。设置 $r = 2^{16}$ 允许处理一个字节。32位键只需要四轮。在大多数计算机上使用 $r = 64$ 是不常见的。

## 7.8 排序算法的实证比较

哪种排序算法快？渐近复杂度分析可以让我们区分 Θ(n²) 和 Θ(n log n) 算法，但它不能帮助区分渐近复杂度相同的算法。渐近分析也无法告诉我们对于小列表什么算法最佳。对于这些问题，我们可以转向实验测试。
