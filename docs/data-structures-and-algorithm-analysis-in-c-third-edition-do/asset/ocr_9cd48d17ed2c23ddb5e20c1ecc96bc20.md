# 7.6 Heapsort

Discussion of Quicksort began by considering the practicality of a binary search tree for sorting. The BST requires more space than the other sorting methods and will be slower than Quicksort or Mergesort due to the relative expense of inserting values into the tree. There is also the possibility that the BST be unbalanced, leading to a Θ(n²) worst-case running time. Balance in the tree is closely related to Quicksort's partition step. Quicksort's pivot secures roughly the same as the pivot (root) value, while the left partition (subtree) stores values less than the pivot (root), while the right partition (subtree) stores values greater or equal to the pivot (root).

Heapsort is based on the heap structure presented in Section 5.5. Heapsort has all of the advantages. The complete binary tree is balanced, its array representation is space efficient, and we can load all values into the tree at once, taking advantage of the efficient buildheap function. The asymptotic performance of Heapsort is Θ(n log n) in the best, average and worst cases. It is not as fast as Quicksort in the average case (by a constant factor), but Heapsort has special properties that make it particularly useful when sorting sets too large to fit in main memory, as discussed in Chapter 8.

A sorting algorithm on max-heaps is quite straightforward. First we use the heap building algorithm of Section 5.5 to convert the array into max-heap order. Then we repeatedly remove the maximum value from the heap, restoring the heap property each time we do so, until the heap is empty. Note that each time we remove the maximum element from the heap, it is placed at the end of the array. As the n elements are stored in array positions 0 through n - 1.
