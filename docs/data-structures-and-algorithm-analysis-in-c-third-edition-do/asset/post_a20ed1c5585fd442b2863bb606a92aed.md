It turns out that there is a large collection of problems with this property: We know efficient non-deterministic algorithms, but we do not know if there are efficient deterministic algorithms. At the same time, we have not been able to prove that any of these problems do not have efficient deterministic algorithms. This class of problems is called $N^P$-complete. What is truly strange and fascinating about $N^P$-complete is that if anybody finds the solution to any of them runs in polynomial time on a regular computer, then by a series of reductions, every other problem that is in $N^P$ can be solved in polynomial time on a regular computer!

Define a problem to be $N^P$-hard if any problem in $N^P$ can be reduced to $X$ in polynomial time. $X$ is as hard as any problem in $N^P$. A problem $X$ is defined to be $N^P$-complete if:

1. $X$ is in $N^P$, and
2. $X$ is $N^P$-hard.

The requirement that a problem be $N^P$-hard might seem to be impossible, in fact there are hundreds of such problems, including TRAVELING SALESMAN. Another problem is called K-CLIQUE.

Nobody knows whether there is a polynomial time solution for K-CLIQUE, but if such an algorithm is found for K-CLIQUE or for TRAVELING SALESMAN, then that solution can be modified to solve the other, or any other problem in $N^P$, in polynomial time.

The primary theoretical advantage of knowing that a problem P1 is $N^P$-complete is that we can show that problem P2 is $N^P$-complete. This is by finding a polynomial reduction of P1 to P2. Because we already know that all problems in $N^P$ can be reduced to P1 in polynomial time (by the definition of $N^P$-complete), we know that all problems can be reduced to P2 as well as the simple algorithm of reducing to P1 and then from reducing to P2.

## 17.2.2 $NP$-Completeness Proofs

To start the process of being able to prove problems $NP$-complete, we need to prove just one $H$ is $NP$-complete. After that, to show that any problem $X$ is $NP$-hard, we need to reduce $H$ to $X$. When doing, $NP$-completeness proofs, it is very important not to get this reduction backwards! If we reduce candidate $X$ to known hard problem $H$, this means that we use $H$ as a step to solving $X$. When, when we reduce known hard problem $H$ to candidate problem $X$, we are using $X$ as a step to solve $H$. And if we know that $H$ is hard, then $X$ must also be hard (if $X$ were not hard, then there would be $H$ hard).

A crucial first step to getting this whole theory off the ground is finding one problem that is $NP$-hard. The first proof that a problem is $NP$-hard (and because it is in $NP$, therefore $NP$-complete) was done by Stephen Cook. For this, Cook won the first award, which is the closest Computer Science equivalent to the Nobel Prize. Used Turing machines in his proof because they are simple enough he could develop this transformation of Turing machines to Boolean expressions. There is a "universal" Turing machine that can take as input a description of that machine, an input string, and run the execution of that. The string is satisfiable if and only if the Turing machine accepts.
