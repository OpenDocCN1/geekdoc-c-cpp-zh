+   3. Swap record found with the record immediately preceding it in the list. This heuristic is called transpose. Transpose is good for list implementations based on either linked lists or arrays. Frequently used records will, over time, move to the front of the list. Records that were once accessed but are no longer used will drift toward the back. It appears to have good properties with respect to changing frequency of access. Unfortunately, there are pathological sequences of access that can transpose poorly. Consider the case where the last record of the list (call it X) is accessed. This is then swapped with the next-to-last record (call it Y), making Y the last. If Y is now accessed, it swaps with X. A repeated series of alternating accesses between X and Y will continually search to the end of the list, because neither record will ever make progress toward the front. However, such pathological cases are unusual in practice. A variation on transpose would be to move the accessed record forward in the list by some fixed number of steps.
