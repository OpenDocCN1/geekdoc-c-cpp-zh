To move $V$ to the right place, it is compared to its parent's value. If the value is less than or equal to the value of its parent, then it is in the correct position and the insert routine is finished. If the value of $V$ is greater than that of its parent, then the two elements swap positions until $V$ reaches its correct position.

Since the heap is a complete binary tree, its height is guaranteed to be the minimum position. In particular, a heap containing $n$ nodes will have a height of $\lfloor\log nfloor$. Intuitively, we can see that this is true because to double the number of nodes in the tree (the ith level has $2^i$ nodes, and the sum of the first $i$ is $2^{i+1}$). Starting at 1, we can only do $\log n$ times to reach a value of $n$. To be precise, the height of a heap with $n$ nodes is $\lfloor\log(n+1)floor$.

Each call to **insert** takes $\Theta(\log n)$ time in the worst case, because the value can be inserted at most the distance from the bottom to the top of the tree. Thus, if we insert $n$ values into the heap, one at a time, will take $\Theta(\log n)$ time in the worst case.

If $n$ values are available at the beginning of the building process, we can build the heap by just inserting the values into the heap one by one. From this example, it is clear that the heap for any set of numbers is not unique, and that some rearrangements of the input values require fewer exchanges than others to build the heap. How do we pick the best rearrangement?
