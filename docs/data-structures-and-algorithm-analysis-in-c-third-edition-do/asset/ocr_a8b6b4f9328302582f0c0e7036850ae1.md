# ### 15.2.2 Searching in Sorted Lists

We will now assume that $L$ is sorted. In this case, is linear search optimal? Clearly no, but why? Because we have additional information to work with that we do not have when the list is unsorted. We know that the standard binary search has a worst cost of $O(\log n)$. We can prove that this is the best possible in the worst case with a proof similar to that used to show the lower bound on sorting.

Again we use decision tree to model our algorithm. Unlike searching an unsorted list, comparisons between elements of $L$ tell us nothing about their relative order, so we consider only comparisons between $K$ and an element $L$. At the root of the decision tree, we know our rules out no positions in $L$, so all are potential candidates. As we take branches in the decision tree based on the result of comparing $K$ to an element in $L$, we gradually rule out potential candidates. We eventually reach a leaf node in the tree representing the single position that can contain $K$. There must be at least $n+1$ nodes in the tree because we have $n+1$ distinct positions that $K$ can be (in any position in $L$, plus not in $L$ at all). Some path in the tree must be at least $\log n$ levels deep, and the deepest node represents. Thus, any algorithm on a sorted array requires at least $\Omega(\log n)$ comparisons in the worst case.
