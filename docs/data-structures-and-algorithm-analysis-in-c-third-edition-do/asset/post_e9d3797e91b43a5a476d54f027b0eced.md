### 6.1.1 ADT for General Tree Nodes

Before general tree implementations, we should first make precise what operations implementations must support. Any implementation must be able to initialize a tree. We need access to the root of that tree. There must be some way to access the children of a node. In the case of the ADT for binary trees, this was done by providing member functions that give explicit access to the left and right child pointers. Unfortunately, because we do not know in advance how many children a given node will have in the general tree, we cannot give explicit functions to access each child. An alternative must be found that works for an unknown number of children.

### 6.1.2 General Tree Traversals

In Section 5.2, three tree traversals were presented for binary trees: preorder, preorder, and inorder. For general trees, preorder and postorder traversals are defined with meanings similar to their binary tree counterparts. A preorder traversal of a general tree visits the root of the tree, performs a preorder traversal of each subtree from left to right. A postorder traversal of a general tree performs a postorder traversal of the root's subtrees from left to right, visits the root. Inorder traversal does not have a natural definition for the general tree, because there is no particular number of children for an internal node. An arbitrary definition — such as visit the leftmost subtree of inorder, then the root, then visit the remaining subtrees in inorder. However, inorder traversals are generally not useful with general trees.

To perform a preorder traversal, it is necessary to visit each of the children for a given node (say R) from left to right. This is accomplished by starting at R's leftmost child (call it T). From T, we can move to T's right sibling, and then to that node's right sibling, and so on.

## 6.2 The Parent Pointer Implementation

Perhaps the simplest generic tree implementation is to store for each node only a pointer to node's parent. We will call this the parent pointer implementation. Clearly this implementation is not general purpose, because it is inadequate for such important operations as finding the leftmost child or the right sibling of a node. Thus, it may seem to a poor idea to implement a general tree in this way. However, the parent pointer implementation stores precisely the information required to answer the following, useful question: “Given two nodes, are they in the same tree?” To answer the question, we need only follow the series of parent pointers from each respective root. If both nodes reach the same root, then they must be in the same tree. If the roots are different, the two nodes are not in the same tree. The process of finding the ultimate root for a given node will be FIND.

The parent pointer representation is most used to maintain a collection of disjoint sets. Two disjoint sets share no members in common (their intersection is empty). A collection of disjoint sets partitions some objects that every object is exactly one of the disjoint sets. There are two basic operations that we wish to support:

- (1) determine if two objects are in the same set, and
- (2) merge sets together.

Because merged sets are merged, the merging operation is called UNION and the whole process of determining if two objects are in the same set and then merging the sets by the name “UNION/FIND”.

To implement UNION/FIND, we represent each disjoint set with a general tree. Two objects are in the disjoint set if they are in the same tree. Every node of the tree (except for the root) has precisely one parent. Thus, each node requires the space to represent it. The collection of objects is stored in an array, where each element of the array corresponds to one object, and each element stores the object's value. The objects also correspond to nodes in the various trees (one tree for each disjoint set), so we also store the parent value with each object. Those nodes that are the roots of their respective trees store an indicator node. This representation means that a single array is used to implement a collection of trees. This makes it easy to merge trees with UNION operations.
