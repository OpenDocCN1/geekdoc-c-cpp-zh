Property (3) is simply an extension of property (1). Property (4) tells us, that for variable $n$ and two integers $a$ and $b$, $\log_a n$ and $\log_b n$ differ by the constant factor $\log_a n$, regardless of the value of $n$. Most runtime analyses in this book are of a type that ignores constant factors in costs. Property (4) says that such analyses need not be concerned with the length of the logarithm, because this can change the total cost only by a constant factor. Note $2^{\log n}=n$.

When discussing logarithms, often often lead to confusion. Property (3) tells us $\log n^2=2\log n$. How do we indicate the square of the logarithm (as opposed to the logarithm of $n^2$?) This could be written as $(\log n)^2$, but it is traditional to use $\log^2 n$. On the other hand, we want to take the logarithm of the logarithm of $n$. This is written $\log \log n$.

A special notion is used in the rare case when we need to know how many times we take the logarithm of a number before we reach a value $\le1$. This quantity is written $\log^* n$. For example, $\log 1024=4$ because $\log 1024=10$, $\log 10 \approx 3.33$, $3.33 \approx 1.74$, and $\log 1.74=1$, which is a length of 4 log operations.

# 2.4 Summations and Recurrences

Most programs construct loops. When analyzing runtime costs for programs with loops, we need to add up the costs for each time the loop is executed. This is an example of a summation. Summations are simply the sum of costs for some function applied to a range of parameter values. Summations are typically written with the symbol $\Sigma$ notation:

> $\sum_{i=1}^n f(i)$.

This notation indicates that we are summing the value of $f(i)$ over some range of (integer) values. The parameter to the expression and its initial value are indicated below the $\Sigma$ symbol. Here, the notation $i=1$ indicates that the expression is $i$ and it begins with the value 1. At the top of the $\Sigma$ is the maximum value for the parameter $i$.
