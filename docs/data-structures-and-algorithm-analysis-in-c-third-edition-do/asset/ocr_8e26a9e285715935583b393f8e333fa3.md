# 14.3 Amortized Analysis

This section presents the concept of amortized analysis, which is the analysis for a series of operations taken as a whole. In particular, amortized analysis allows us to deal with the situation where the worst-case cost for n operations is less than n times the worst-case cost of any one operation. Rather than focusing on the individual cost of each operation independently and summing them, amortized analysis looks at the cost of the entire series and "charges" each individual operation with a share of the total cost.

We can apply the technique of amortized analysis in the case of a series of sequential searches in an unsorted array. For random searches, the average-case cost for each search is n/2, and so the expected total cost for the series is n²/2. Unfortunately, in the worst-case all of the searches will be the last item in the array. In this case, each search costs n for a total worst-case cost of n² this to the cost for a series of n searches that each item in the array is searched precisely once. In this situation, some of the searches will be expensive, but some must be cheap. The total number of searches, in the best, average, and worst case, for this problem is $\sum_{i=1}^n i \approx n²/2$. This is a factor of two better than the most pessimistic analysis that charges each operation in the series with worst-case cost.

Another example of amortized analysis, consider the process of incrementing a binary counter. The algorithm is to move from the lower-order (rightmost) bit toward the high-order (leftmost) bit, changing 1s to 0s until the first 0 is encountered. 0 is changed to a 1, and the increment operation is done. A[i] = 1;

If we count from 0 through $2^n - 1$, (requiring a counter with at least n bits), what is the average cost for an increment operation in terms of the number of bits processed? Naive-case analysis shows that if all n bits are 1 (except for the high-order bit), then n bits needs to be processed. Thus, if there are $2^n$ increments, the cost is $n2^n$. However, this is too much high, because it is rare for many bits to be processed. In half of the time the low-order bit is 0, and so only that is processed. One quarter of the time, the low-order two bits are 01, and so only the low-two bits are processed.
