Only the last two transition types increase the number of middles, so there must be $n - 2$ of these. The number of untested elements must go to 0, and the first transition is the most efficient way to do this. Thus, $[n/2]$ are required. Our conclusion is that the minimum possible number of transitions (comparisons) is $n + [n/2] - 2$. Thus, our algorithm is optimal.

# 15.6 Finding the ith Best Element

We now tackle the problem of finding the ith best element in a list. As observed earlier, one option is to sort the list and simply find the $i$th position. However, this process provides considerably more information than we need to solve the problem. The minimum amount of information that we actually know can be visualized as shown in Figure 15.4. Thus, all we need to know is the $i - 1$ items less than our desired value, and the $n - i$ items greater. We do not care about the relative order within lower and upper groups. Recall at the lower bound, can we tighten beyond the trivial lower bound of $n$ comparisons? We will focus on the specific question of finding the median element ($i$, the element with rank $n/2$), because the resulting algorithm can be easily modified to find the ith largest value for any $i$.
