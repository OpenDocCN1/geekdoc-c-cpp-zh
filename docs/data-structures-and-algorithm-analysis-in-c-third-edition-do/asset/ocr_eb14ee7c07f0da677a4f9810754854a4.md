By definition of the mod function, all generated numbers must be in the range 0 to t - 1. Now, consider what happens when r(i) = r(j) for values i and j. Of course then r(i + 1) = r(j + 1) which means that we have a repeating cycle.

Since the values coming out of the random number generator are between 0 and t-1, the longest cycle that we can hope for is length t. In fact, since r(0)=0, it cannot be ever this long. It turns out that to get a good result, it is crucial to pick good values for both b and t. To see, consider the following example.

**Example 16.4** Given a value of 13, we can get different results depending on the b value that we pick, in ways that are hard to predict.

```
r(i) = 6r(i - 1) mod 13 =
... 1, 6, 10, 8, 9, 12, 7, 3, 5, 4, 11, ...
r(i) = 7r(i - 1) mod 13 =
... 1, 7, 10, 5, 9, 11, 12, 6, 8, 4, 2, ...
r(i) = 5r(i - 1) mod 13 =
... 1, 5, 12, 8, 1, ...
... 2, 10, 11, 3, 2, ...
... 4, 7, 9, 6, 4, ...
... 0, 0, ...
```

Clearly, a value of 5 is far inferior to b values of 6 or 7 in this example.

If you would like to write a simple LCM random generator of your own, effective one can be made with the following formula.

```
r(i) = 16808r(i - 1) mod 2³¹ - 1.
```

# **16.3.5 The Fast Fourier Transform**

As noted at the beginning of this section, multiplication is considerably more difficult than addition. To multiply two n-bit numbers directly is O(n²), while addition of two n-bit numbers is O(n).

Recall from Section 2.3 that property of logarithms is

```
log nm = log n + log m.
```

Thus, if taking logarithms and anti-logarithms were cheap, we could reduce multiplication to addition by taking the log of the two operands, and then taking the anti-log of the sum.

Under normal circumstances, taking logarithms and anti-logarithms is expensive, so this reduction would not be considered practical. However, this reduction is precisely the basis for the slide rule.
