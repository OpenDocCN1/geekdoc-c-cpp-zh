Because an activation record is created and placed onto the stack for each subroutine call, making subroutine calls a relatively expensive operation. While recursion is often used to make implementation easy and clear, sometimes you might want to eliminate the overhead imposed by the recursive function calls. In cases, such as the factorial function of Section 2.5, recursion can easily be replaced by iteration.

Example 4.2 As simple example of replacing recursion with a stack, considering the following non-recursive version of the factorial function.

```
```
long fact(int n, Stack *s) { // Compute n!
 // To fit n in a long variable, require n <= 12
 Assert(n > 0) && (n <= 12), "Input out of range stack")
 while (n > 1) { s->push(n--); // Load up the stack
 long result = 1;
 while (s->length() > 0) 
 result = result * s->pop(); // Compute
 return result;
}
```
```

Here, we push successively smaller values of n onto the stack until the base case is reached, then repeatedly pop the stored values and multiply them into the result.

An iterative version of the function is simpler and faster than the version shown in Example 4.2. But it is not always possible to replace recursion with iteration. Recursion, or some imitation of it, is necessary when implementing algorithms that require multiple branching as in the Towers of Hanoi algorithm, or when traversing a binary tree. The Mergesort and Quicksort algorithms of Chapter 7 are also examples in which recursion is required. Fortunately, it is all possible to implement recursion with a stack. Let us now turn to a non-recursive version of the Towers of Hanoi function, which cannot be iteratively.
