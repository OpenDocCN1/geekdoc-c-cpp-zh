# Mathematical Preliminaries

This chapter presents mathematical notation, background, and techniques used throughout the book. This material is provided primarily for review and reference. You might wish to return to the relevant sections when you encounter unfamiliar notation or mathematical techniques in later chapters.

Section 2.7 on estimation might be unfamiliar to many readers. Estimation is not a mathematical technique, but rather a general engineering skill. It is enormously useful to computer scientists doing design work, because any proposed solution whose estimated requirements fall well outside the problem's source constraints can be discarded immediately, allowing time for greater analysis of more promising solutions.

## 2.1 Sets and Relations

The concept of a set in the mathematical sense has wide application in computer science. The notations and techniques of set theory are commonly used when describing and implementing algorithms although the abstractions associated with sets help to clarify and simplify algorithm design.

A set is a concept of distinguishable members or elements. The members are typically drawn from larger population known as the base type. Each member of a set is either a primitive element of the base type or is a set itself. There is no concept of duplication in a set. Each value from the base type is either in the set or not in the set. For example, a set P might consist of the three integers 7, 11, and 42. In this case, P's members are 7, 11, and 42, and the base type is integer.

A collection of elements with no order (like a set), but with duplicated-valued elements is called a bag.¹ To distinguish bags from sets, we use square brackets [] around a bag's elements. For example, bag [3, 4, 5, 4] is distinct from bag [3, 4, 5], while set {3, 4, 5, 4} is indistinguishable from set {3, 4, 5}. However, bag [3, 4, 4, 5, 4] is indistinguishable from bag [3, 4, 4, 5].

> The object referred to as a bag is sometimes called a multiset. But, I reserve the term multiset for a list that may contain sublists (see Section 12.1).

## Sec. 2.1 Sets and Relations

A sequence is a collection of elements with an order, and which may contain duplicate-valued elements. A sequence is sometimes called a tuple or a vector. In a sequence, there is a 0th element, a 1st element, 2nd element, and so on. I indicate a sequence using angle brackets {} to enclose its elements. For example, <3, 4, 5> is a sequence. Note that <3, 5, 4, 4> is distinct from sequence <3, 4, 5, 4>, and both are distinct from sequence <3, 5, 4, 5>.

A relation over set S is a set of ordered pairs from S. As an example of a, if S is {a, b, c}, then

```
{<a, a>, <b, c>, <c, b>}
```

is a relation, and

```
{<a, a>, <a, c>, <b, b>, <b, c>, <c, c>}
```

is a different relation. If <x, y> is in relation R, we may use the notation xRy. We often use relations such as the operator (<) on the numbers, which includes ordered pairs such as (1, 3) and (2, 23), but not (3, 2) or (2, 2). Rather than writing the relationship in terms of ordered pairs, we typically use infix notation for relations, with < 3.

Define the properties of relations as follows, with R a binary relation over set S.

- R is reflexive if aRa for all a in S.
- R is symmetric if aRb implies bRa.
- R is transitive if aRb and bRc implies aRc.

A binary relation is called a **partial order** if it is antisymmetric and transitive.$2 The set on which the partial order is defined is called a **partially ordered set** or a **poset**. Elements $x$ and $y$ of a set are **comparable** under a given relation if either $xRy$ or $yRx$. Every pair of distinct elements in a partial order is a **total order** or **linear order**.

**Example 2.4** For the integers, relations $<$ and $\le$ define partial orders. Operation $<$ is a total order because, for every pair of integers $x$ and $y$ such that $x \neq y$, either $x < y$ or $y < x$. Likewise, $\le$ is a total order because, for every pair of integers $x$ and $y$ such that $x \neq y$, either $x \le y$ or $y \le x$.

> $2$Not all authors use this definition for partial order. I have seen at least three significantly different definitions in the literature. I have selected the one that lets $<$ and $\le$ both define partial orders on the integers, because this seems the most natural to me.
