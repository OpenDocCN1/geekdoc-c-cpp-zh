## 11.5.1 Prim's Algorithm

The first of our two algorithms for finding MSTs is commonly referred to as Prim's algorithm. Prim's algorithm is very simple. Start with any Vertex $N$ in the graph, setting the MST to $N$ initially. Pick the least-cost edge connected to $N$. This edge connects $N$ to another vertex; Add Vertex $M$ and Edge $(N, M)$ to the MST. Next, pick the least-cost edge from either $N$ or $M$ to any other vertex in the graph. Add this edge and the new vertex it reaches to the MST. This process continues, at each step extending the MST by selecting the least-cost edge from a vertex currently in the MST to a vertex not in the MST.

Prim's algorithm is similar to Dijkstra's algorithm for finding the single-source shortest paths. The primary difference is that we are seeking the next closest vertex to the start vertex, but rather the next closest vertex to any vertex currently in the MST. Thus we replace the line

```
if D[w] > D[v] + G->weight(v, w)
nD[w] = D[v] + G->weight(v, w);
```

in Dijkstra's algorithm with the lines

```
if D[w] > G->weight(v, w)
D[w] = G->weight(v, w);
```

in Prim's algorithm.

Figure 11.21 shows an implementation for Prim's algorithm that searches the distance matrix for the next closest vertex. For each vertex $I$, when $I$ is processed by Prim's algorithm, an edge to $I$ is added to the MST that we are building. Array $V[I]$ stores the previously visited vertex that is closest to Vertex $I$. This information lets us know which edge enters the MST when Vertex $I$ is processed.

## 11.5 Minimum-Cost Spanning Trees

```cpp
void Prim(Graph* G, int* D, int s) { // Prim's MST algorithm
    int V[G->n()]; // Store closest vertex
    int i;
    for (i=0; i<G->n(); i++) // Process the vertices
        int v = minVertex(G, VISITED);
        G->setMark(v, VISITED);
        if (v != s) {
            AddEdgeToMST(v, w); // Add edge to MST
            if (D[v] == INFINITY) return; // Unreachable vertices
            for (w=G->first(v); w; w=G->next(w)) {
                if (D[w] > G->weight(v, w)) { // Update distance
                    D[w] = G->weight(v, w); // Where it came from
                }
            }
        }
    }
}
```

Prim's algorithm is an example of greedy algorithm. At each step in the for loop we select the least-cost edge that connects some vertex to unmarked vertex. The algorithm does not otherwise check that the MST must include this least-cost edge. This leads to an important question: Does Prim's algorithm work correctly? Clearly it generates a spanning tree (because pass through the loop adds one edge and one unmarked vertex to the spanning tree until all vertices have added), but does this tree minimum cost?
