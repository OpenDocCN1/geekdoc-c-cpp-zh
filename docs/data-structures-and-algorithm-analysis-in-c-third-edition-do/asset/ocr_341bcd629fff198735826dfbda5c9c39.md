# Sec. 15.4 Adversarial Lower Bounds Proofs

We go back to trying to improve the lower proof. To do this, we introduce the concept of an adversary. The adversary's job is to make an algorithm's cost as high as possible. Imagine that the adversary keeps a list of all possible inputs. We view the algorithm as asking the adversary for information about the algorithm's input. The adversary may never lie, in that its answer must be consistent with the previous answers. But it is permitted to "rearrange" the input as it fits in order to drive the total cost for the algorithm as high as possible. In particular, when the adversary asks a question, the adversary must answer in a way that is consistent with at least one remaining input. The adversary then crosses out all remaining inputs inconsistent with that answer. Keep in mind that there is not really an entity within the computer program that is the adversary, and we don't actually modify the program. The adversary operates merely as an analysis device, to help us reason the program.

As an example of the adversarial concept, consider the standard game of Hang. Player A picks a letter and tells Player B how many letters the word has. Player B guesses various letters. If B guesses a letter in the word, then A will indicate which position(s) in the word has the letter. Player B is permitted to make only so many guesses of letters not in the word before.

In the Hangman game example, the adversary is imagined to hold a dictionary of words of some length. Each time the player guesses a letter, the adversary consults the dictionary and decides if more words will be eliminated by accepting the letter (and indicating which positions it holds) or saying that it is not in the word. The adversary can make any decision it chooses, so long as at least one word in the dictionary is consistent with all of the decisions. In this way, the adversary can help to make the player guess as many letters as possible.

Before explaining how the adversary plays a role in our lower bounds proof, first observe that $n-1$ values must lose at least once. This requires at least $n-1$ comparisons. In addition, at least $k$ values must lose to the second largest value. That is, $k$ losers to the winner must be compared. There must be at least $n+k-2$ comparisons. The question is: How can we make $k$?

Call the strength of $A[i]$ the number of elements that $A[i]$ is (known to be) bigger. If $A[i]$ has strength $a$, and $A[j]$ has strength $b$, then the winner has strength $a+b+1$. The algorithm gets to know which two elements are compared next. The adversary decides to win any given comparison. What strategy by the adversary would cause the algorithm to learn the least at which any element improves its strength. It can do this by making the element with the greater strength win at every comparison. This is a "fair" use of an adversary in that it represents the results of providing a worst-case input for that given algorithm.
