Binary search is indeed an optimal algorithm for a sorted list in the worst and average cases searching a sorted array, there are a number of circumstances that might lead us to select another algorithm. One possibility is that we know nothing about distribution of the data in the array. We saw in Section 9.1 if each position in L is equally likely to hold X (equivalently, the data are well distributed over the full range), then an interpolation search $\Theta(\log n)$ in the average case. If the data are not sorted, using binary search requires us to pay the cost of sorting the list in advance, which is only worthwhile if many (at O(log n)) searches are performed on the list. Binary search also requires that the list (even if sorted) be implemented using an array or some structure that supports random access to all elements with equal cost. # 15.3 Finding the Maximum Value

How can we find the largest value in a sorted list? Obviously we just go to the th position. But what if we have an unsorted list? Can we do better than sort it? If we are looking for the minimum or maximum value, certainly we can do better than sorting the list. This is true for the second biggest value? For the median value? In later sections we will examine these questions. For this section, we will continue our examination of lower bounds by reducing the simple problem of finding the maximum value in an unsorted list.

Here is a simple algorithm for finding the largest:

```
// Return the largest value in "A" of size "n"
int largest(int A[], int n) {
    int currarge = 0; // Holds largest element position
    for (int i=1; i<n; i++) // For each array element
        if (A[currarge] < A[i]) // If A[i] is larger
            currarge = i; // remember its position
    return currarge; // Return largest position
}
```
