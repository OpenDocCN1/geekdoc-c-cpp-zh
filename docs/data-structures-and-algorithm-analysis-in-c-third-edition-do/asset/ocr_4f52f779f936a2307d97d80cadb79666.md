Note that when using the Flyweight design pattern, you cannot coordinates for the node in the node. This is an example of the concept of intrinsic versus extrinsic state. Intrinsic state for an object is state stored in the object. If you stored the coordinates for a node in the node, those coordinates would be intrinsic state. Extrinsic state is state information about an object stored elsewhere in the environment, such as global variables or passed to the method.

If your recursive calls that the process tree in the coordinates for the current node, then the coordinates will be extrinsic state. A flyweight can have only information that is accurate for all instances of the flyweight. Clearly coordinates do not qualify, because each leaf node has its own location. So, if you want to use a flyweight, you must pass in coordinates.

Another design choice is: Who controls the weight, the node class or the tree class? For example, on an insert operation, you could have the tree class flow down the tree, looking at (querying) the nodes to see their type and reacting accordingly. This is the approach used by the BST implementation in Section 5.4. An alternate approach is to have the node do the work. That is, you have an insert method for the node. If the node is internal, it passes the record to the appropriate child (recursively). If the node is a flyweight, it replaces itself with a new leaf node. If the node is not a full, it replaces itself with a subtree. This is an example of the Composite design pattern, discussed in Section 5.3.1. Use of the composite design would be difficult if NULL pointers are used to represent leaf nodes. It turns out that the PRtree insert and delete methods are easier to implement when using the composite design.

# 13.3.3 Other Point Data Structures

The differences between the k-tree and the PR quadree illustrate many of the design choices encountered when creating spatial data structures. The k-tree provides an object decomposition of the region, while the PR quadree provides a key space decomposition (thus, it is a trie). The k-tree stores records at all nodes, while the PR quadree stores only the leaf nodes. Finally, the two have different structures. The k-tree is a binary tree (and not full) with $2$ branches (in the two-dimensional case, $2^2=4$). Consider the extension of this concept to three dimensions. A k-tree for three dimensions would alternate the discriminator through the $x, y$, and $z$ dimensions. The three-dimensional equivalent of the PR quadree would be a tree with $2^3$ or eight branches. Such a tree is called an octree.
