None of these is what commonly meant when a theoretician uses the
word "hard". Throughout this section, "hard" means that the best-known alg-
orithm for the problem is expensive in its running time. One example of a hard
problem is Towers of Hanoi. It is easy to understand this problem and the solution.
it is also easy to write a program to solve this problem. But it takes an extremely
long time to run for "reasonably" large value of n. Try running a program to
solve Towers of Hanoi for only 30 disks!

The Towers of Hanoi problem takes exponential time, that is, its running time
is $\Theta(2^n)$. This is radically different from an algorithm that takes $\Theta(n \log n)$nor $\Theta(n^2)$. It is even radically different from a program that takes $\Theta(n^4)$.nThese are all examples of polynomial running time, because the exponents for all
these of equations are constants. Recall from Chapter 3 that if we buy a
computer that runs fast, the size of problem with complexity $\Theta(n^4)$ that
can solve in a certain amount of time is increased by the fourth root of two.
in other words, there is a multiplicative factor increase, even if it is a rather small
one. This is true for any algorithm whose running time can be represented by a
polynomial.

Consider what happens when you buy a computer that is fast and try to
s a bigger Towers of Hanoi in a given amount of time. Because its
complexity is $\Theta(2^n)$, we can solve a problem only one bigger! There is no
multiplicative factor, and this is true for any exponential algorithm: A constant
factor increase in processing power results in only a fixed addition in problem-
sol.

There are a number of other fundamental differences between polynomial run-
ing and exponential running times that are for treating them as quali-
tatively. Polynomials are closed under composition and addition. Thus,
running polynomial-time programs in sequence, or having one program with poly-
nomial running time can call another polynomial number of times yields polynomial
time. Also, all computers are polynomially related. That is, any program
runs in polynomial time today, when transferred to any other
computer, will still run in polynomial time.

in reasonable time. In contrast, most algorithms requiring exponential time are
