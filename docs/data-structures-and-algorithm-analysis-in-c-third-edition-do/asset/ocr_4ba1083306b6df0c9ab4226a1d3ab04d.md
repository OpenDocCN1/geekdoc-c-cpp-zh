to be the same size, then this might be an effective strategy. Like best fit, worst
 requires searching the entire freelist at each memory request to find the largest
block. Alternatively, the freelist can be ordered from largest to smallest free block,
possibly using a priority queue implementation.

Which strategy is best? It depends on the expected types of memory requests.
If the requests are of widely ranging size, best fit might work well. If the requests
to be of similar size, with large and small requests, first or worst fit
work well. there are always request patterns that one of the three
sequential fit methods will service, but which the other will not be able to
service. For example, if the series of requests 600, 650, 900, 500, 100 is made to
a freelist containing blocks 500, 700, 650, 900 (in order), the requests can all
be served by first fit, but not by best fit. Alternatively, the series of 600,
500, 700, 900 is served by best fit but not by first fit on this smallest freelist.

# Buddy Methods

Sequential-fit methods rely on a linked list of free blocks, which must be searched
a a suitable block at each memory request. The time to find a suitable free
block will be $\Theta(n)$ in the worst case for a freelist containing $n$ blocks. Merging
adjacent free blocks is somewhat complicated. Finally, we must either use add-	ional space for the linked list, or use space within the memory pool to support
memory manager operations. In the second option, both free and reserved blocks
require tag and size fields. Fields in free blocks do not cost any space (because they
are stored in memory for what is not otherwise used), but in reserved blocks
create additional overhead.

The buddy system solves most of these problems. Searching for a block of
t proper size is efficient, merging adjacent free blocks is simple, and no tag or
other information fields needed in reserved blocks. The buddy system
assumes that memory is of size $2^k$ for some integer $N$. Both free and reserved
blocks will always be of size $2^k$ for $k \le N$. At any given size, there might be
free and reserved blocks of various sizes. The buddy system keeps a separate list
free blocks of each size. There can be at most $N$ such lists, because there can
only $N$ distinct block sizes.

When a request comes in $m$ words, we first determine the smallest value of
k that $2^k \ge m$. A block of size $2^k$ is selected from the free list for that block
if one exists. The buddy system does not worry about internal fragmentation:
The entire block of size $2^k$ is allocated.

If no block of size $2^k$ exists, the next larger block is located. This block is split
half (repeatedly if necessary) until the desired block of size $2^k$ is created. Any
other blocks generated as a by-product of this splitting process are placed on the
appropriate freelists.
