# Limits to Computation

This book describes data structures that can be used in a wide variety of problems, and many examples of efficient algorithms. In general, our search algorithms strive to be at worst in O(log n) to find a record, and our sorting algorithms strive to be in O(n log n). A few algorithms have higher asymptotic complexity. But Floyd's all-pairs-shortest-paths algorithm and standard matrix multiply have running times of Θ(n³) (though for both, the amount of data being processed is Θ(n²)).

We can solve many problems efficiently because we are available (and to use) efficient algorithms. Given any problem for which you know some algorithms, it is always possible to write an inefficient algorithm to "solve" the problem. For example, consider an algorithm that tests every permutation of its input until it finds the correct permutation that provides a sorted list. The running time for this algorithm would be unacceptably high, because it is proportional to the number of permutations which is n! inputs. When solving the minimum spanning tree, if we were to test every subset of edges to see which the shortest spanning tree, the amount of work would be proportional to 2^|E| edges for a graph with |E| edges. Fortunately, for both of these problems we have clever algorithms that allow us to find answers (relatively) quickly without explicitly testing every possible solution.

Unfortunately, there are many computing problems for which the best possible algorithm takes a long time to run. A simple example is the Towers of Hanoi problem, which requires 2ⁿ to "solve" a tower with n disks. It is not possible for any computer to solve the Towers of Hanoi to run in less than Ω(2ⁿ) time, because that many moves must be printed.

Besides those problems whose solutions take a long time to run, there are many problems for which we do not know if there are efficient algorithms or not. The best algorithms that we know for such problems are very slow, but perhaps there are better ones waiting to be discovered. Of course, while having a problem with high running time is bad, it is even worse to have a problem that cannot be solved at all! Such problems do exist, and are discussed in Section 17.3.
