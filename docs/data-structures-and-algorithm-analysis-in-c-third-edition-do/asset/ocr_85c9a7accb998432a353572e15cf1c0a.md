From defining rules for 2-3 trees we can derive relationships between number of nodes in the tree and the depth. A 2-3 tree of height $k$ has at least $2^{k-1}$ leaves, because each internal node degenerates to the shape of a complete binary tree. A 2-3 tree of height $k$ has at most $3^{k-1}$ leaves, because each internal node can have at most three children.

Searching for a value in a 2-3 tree is similar to searching in a BST. Searching begins at the root. If the root does not contain the search key K, then the search progresses to the only subtree that may contain K. The value(s) stored in the root node determine which subtree is correct. For example, searching for the value 30 in the tree of Figure 10.9, we begin with the root node. Because 30 is between 18 and 33, it can only be in the middle subtree. Searching the middle child of the root node yields the desired record. Searching for 15, the first step is again to search the root node. Because 15 is less than 18, the first (left) branch is taken. At the next level, we take the second branch to the leaf node containing 15. If the search key was 16, upon encountering the leaf node 15 we would find that the search key is not in the tree.
