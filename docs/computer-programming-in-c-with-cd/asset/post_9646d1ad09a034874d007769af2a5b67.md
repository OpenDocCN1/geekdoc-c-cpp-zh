### Q4. Why cannot a virtual function be a static or global function?

**Ans.** A virtual function cannot be a static or global function because by definition, a virtual function is a member function of a base class and relies on a specific object to determine which implementation of the function is called. However, a virtual function can be declared a friend of another class. If a function is declared virtual in a base class, you can still access it directly using the `::` operator. Note that if you do not override a virtual member function in a derived class, a call to that function uses the function implementation defined in the base class.

### Q5. What is the difference between static binding and dynamic binding?

**Ans.** The act of associating an object or a class with its member, is known as binding. In C++, there are two types of binding, static and dynamic. Static binding is when a function call is matched with the correct function definition at compile time, and dynamic binding when a function call is matched with the correct function definition at run time. You declare a function with the virtual keyword if you want the compiler to use dynamic binding for the specific function.

Static binding is considered more efficient, and dynamic binding more flexible. In case of dynamic binding, the function calls are resolved at run time, thereby providing users the flexibility to alter a call without having to modify the code. For a programmer, efficiency and performance would probably be a primary concern but to a user, flexibility and maintainability might be much more important. Static binding is the practical implementation of the concept of static polymorphism, while dynamic binding represents dynamic polymorphism. Static binding is performed by the overloading of functions and operators, which is bound by the local (block scope) and class scope. On the other hand, dynamic binding is based on overriding principles, which is purely class scope, and based on inheritance.

### Q6. What is the difference between function overloading and function overriding?

**Ans.** Function overloading is the creating of more than one function with the same name, but with a different signature. Function overriding, on the other hand, is the creating of a function in a derived class with the same name and signature as the function in the base class.

### Q7. What is the order by which constructors and destructors are invoked when a C++ program has a virtual base class, a non virtual base class, member objects, and derived classes all together?

**Ans.** When a C++ program has a virtual base class, a non virtual base class, member objects, and derived classes all together, the order of constructor invocation is as follows:

- 1. Virtual base class constructors, in the order of inheritance
- 2. Non virtual base class constructors, in the order of inheritance
- 3. Member objects constructors, in the order of declaration
- 4. Derived class constructors

However, the sequence of destructor invocation is the opposite of constructor invocation as far as these classes are concerned, which is as follows:

- 1. Derived class destructors
- 2. Member objects destructors, in the reverse order of declaration
- 3. Non virtual base class destructors, in the reverse order of inheritance
- 4. Virtual base class destructors, in the reverse order of inheritance

### Q8. How a protected member of a class plays an important role in inheritance?

**Ans.** The protected access specifier enables the members of a class to be accessible or visible in the same class and in the derived classes of the class. A protected member of a class can be considered as a combination of private and public members. This means that a protected variable of a class is accessible within the member functions of the class, and is invisible outside the class. However, a protected variable is inherited by the derived class from its base class, and can be accessed by the member functions of the derived class.

### Q9. Differentiate between private and public inheritance

**Ans.** In private inheritance, all the private members of a base class remain private in the base class, and all public and protected members of the base class become private members of the derived class. In public inheritance, all private members of a base class remain private in the base class, protected members remain protected in the derived class, and public members remain public in the derived class. Note that private members of a base class are never inherited to its derived classes.

### Q10. What is a pure virtual function?

**Ans.** A virtual function with no body is called the pure virtual function. This is achieved by adding the notation =0 to the declaration of the virtual function. The following code snippet shows an example of declaring a pure virtual function, called displayResult():

```cpp
virtual int displayResult() = 0;
```

### Q11. Explain the concept of abstract class with an example.

**Ans.** In the real world, all objects cannot be modeled in the same manner. In fact, some classes are too abstract to exist by themselves. For example, if someone asks you to draw a shape, you will want to know the kind of shape. The term shape is an abstract concept; it could be a circle, a square, and so on. In C++, we create a base class as an abstract base class to represent an abstract concept. An abstract base class defines the properties that are common to the other classes derived from it. Therefore, we can say that class Shape is an abstract base class and Circle is one of its derived classes.

In C++ language, pure virtual functions are used to create abstract classes. A class containing one or more pure virtual functions is called an abstract class. For example, an abstract class can be created as shown in the following code snippet:

```cpp
class A{
public:
    virtual void display() = 0;
};
```

Note that you cannot use an abstract class as a parameter type, a function return type, the type of an explicit conversion, or declare an object of an abstract class. You can, however, declare pointers and references to an abstract class.

### Q12. Explain the various forms of inheritance.

**Ans.** The following is a brief description of the various forms of inheritance:

- **Single Inheritance:** A form of inheritance where a derived class is inherited from one base class
- **Multilevel Inheritance:** A form of inheritance where a derived class is inherited from a base class, and the same base class in its turn is inherited from another base class
- **Hierarchical Inheritance:** A form of inheritance where two or more derived classes are inherited from one base class
- **Multiple Inheritance:** A form of inheritance where a derived class is inherited from two or more base classes
- **Hybrid Inheritance:** A form of inheritance that is a combination of various types of inheritance, such as multiple inheritance and multilevel inheritance

### Q13. What is the significance of using access specifiers in inheritance?

**Ans.** In C++, member accessibility depends on the use of access specifiers (public, private, or protected) that not only grants the permission for accessing the members of a class outside the class, but also defines as to when the members of the base class can be used by the objects of the derived class. In other words, we can say that access restrictions can be imposed not only within a class but also while deriving the class. A derived class that inherits from a base class uses any one of the following access specifiers:

- **private:** When a base class is specified as private, all the private members of the base class remain private in the object and all the public and protected members of the base class become private members of the derived class
- **protected:** When a base class is specified as protected, all the private members of the base class remain private in the object, the protected members remain protected, but all the public members of the base class become protected members of the derived class
