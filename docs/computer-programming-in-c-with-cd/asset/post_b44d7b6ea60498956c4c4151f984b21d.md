### Explaining the Difference between Static and Dynamic Binding

Static binding refers to binding in which a function call matches with the correct function definition at compile time. However, dynamic binding is binding in which a function call matches with the correct function definition at run time. You declare a function with the virtual keyword if you want the compiler to use dynamic binding for the specific function.

Static binding is considered more efficient, while dynamic binding is more flexible. In dynamic binding, the function calls to its various forms are resolved dynamically when the program is executed. As you know, the term late binding refers to the resolution of the functions at runtime instead of at compile time. This feature increases the flexibility of the program by allowing the appropriate method to be invoked, depending on the context.

In case of dynamic binding, the function calls are resolved at run time, thereby providing users the flexibility to alter a call without having to modify the code. For a programmer, efficiency and performance would probably be a primary concern but to a user, flexibility and maintainability may be much more important. Static binding is the practical implementation of the concept of static polymorphism, while dynamic binding represents dynamic polymorphism. Static binding is performed by overloading of functions and operators. It is bound by scopes, local (block scope) and class scope. On the other hand, dynamic binding is based on overriding principles, which are related to class scope and based on inheritance.

## Creating Pure Virtual Functions

It is observed that often the virtual functions of a base class are not used. For example, let's consider a case of three classes: Polygon, Rectangle, and Triangle. Polygon is the base class of the Rectangle and Triangle classes, and has a virtual function, `area()`. Now, in real-life terms, the area of a polygon can be calculated only if we define the specific shape of the polygon; for example, a triangle or rectangle. Therefore, the area of a polygon would not hold relevance unless we define the shape of the polygon. Consequently, if we need to calculate the area of a polygon in our example, we must specify whether it is a rectangle or triangle. In doing so, we actually use the `area()` function of the derived class (Rectangle or Triangle).

Note that in such a case, the base class may not define the body of the virtual function.

A virtual function with no body structure is called a pure virtual function. You can declare a pure virtual function by adding the notation `=0` to the virtual function declaration. For example, `area()` is a virtual function, but when it is declared as shown in the following expression, it becomes a pure virtual function:

```cpp
virtual int area() = 0;
```

Listing 39 shows how to code a pure virtual function in a base class (you can find the PureVirtualFunction.cpp file on the CD in the Code\Chapter7 folder):

        width= first;

class Rectangle: public Polygon
{
public:

    {
        return (width * height);
