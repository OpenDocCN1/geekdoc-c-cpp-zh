
The state of an object can be described as a set of attributes and values of these attributes. For example, an account has a set of attributes, such as AccountNumber and AccountType; and the values of these attributes, such as 50770 and Current account, respectively.

The object also has a behavior that refers to the changes that occur to its attributes over a period of time. For example, when you put clothes, water, and detergent in a washing machine and switch it on, it exhibits a certain kind of behavior, that is, the process of washing actually starts.

Each object has a unique identity that distinguishes it from other objects. Two objects may exhibit the same behavior, may or may not have the same state, but never have the same identity. For example, two people have the same name, age, and gender, but they are not identical. The identity of an object never changes throughout its lifetime.

Objects can interact with one another by sending messages. For example, if employee and salary are two objects in a program, the employee object may send a message to the salary object to confirm the tax deduction from the salary. The object that receives the message is called a receiver, and the set of actions taken by a receiver is represented by a method.

Objects contain data and code to manipulate the data. An object can also be used as a user-defined data type with the help of a class. Objects are also called variables of the type class. After defining a class, you can create any number of objects belonging to that class. Each object is associated with the data of its class.

## Class

Class is a prototype that defines the abstract characteristics of an object, such as attributes, fields, or properties. It also defines the behaviors of objects, such as the methods, operations, or its features. In other words, you can say classes describe objects.

Classes provide modularity and structure in an object-oriented program. They are user-defined data types and behave similar to built-in types of a programming language. In fact, the syntax to use a class as a data type of an object in C++ is same as the syntax to use the data type of an integer. For example, if Fruit is considered to be a class; mango can be one of the objects of this class. The following code snippet shows the declaration of an object, mango, of the Fruit class:

```cpp
Fruit mango;
```

Similar to mango, other objects of the Fruit class can be apple, banana, and orange.

## Method

Methods represent the abilities of an object, for instance a dog, Buzo, has the ability to bark. The bark(), therefore, is one of Buzo's methods. The dog may have other methods as well, such as sit(), eat(), and walk(). In a program, a method usually affects only one particular object. For example, all dogs can bark, but you need a particular dog to bark.

## Message Passing

In OOP, a program consists of a group of objects that communicate with each other. Objects communicate by sending and receiving information, or just by passing messages. A message is a request, which is sent by an object, to execute a procedure or to call a procedure in the receiving object that generates the result. Message passing is carried out by specifying the name of an object, the name of a function (or called message), and the information to be sent. Note that objects also have a life cycle and can be created and destroyed. Communication with an object can be possible as long as it exists.

## Abstraction

Abstraction is a feature of OOP that represents the essential characteristics of an object without including background details or explanations. When you deal with a complex object, you generally tend to ignore the non-essential details of the object and concentrate only on those details that are essential or required. For instance, if you want to buy a television, you would typically pay attention to the size, ease of handling, color, its guarantee and warranty; however, you would not be interested in the gadgetry (internal part) inside it. Classes use the concept of abstraction and define a list of abstract attributes, such as size, weight, and cost as well as functions to operate on these attributes. These attributes are called data members because they hold information. The functions that operate on these data members are called methods or member functions. The classes that use the concept of data abstraction are known as Abstract Data Types (ADT). The counterpart of the abstraction feature is encapsulation, which is described next.

## Encapsulation

Encapsulation refers to a feature of OOP that prevents access to non-essential details of class. For example, when you switch on a television set, it displays the programs being telecast in the form of audio and video. However, you cannot see the actual complex process of the television, such as how the signals from the cable are being transformed into audio and video. Encapsulation is also referred to as data hiding, since it hides important and classified data from accidental manipulation by members of same program. Note that the encapsulated data of a class can be accessible outside the class only when the data is used in the function of the class. However, a limited number of operations can be performed on encapsulated data by executing the functions or methods of the class.

The concepts of data abstraction and data encapsulation are supported in C++ by using the `public` and `private` keywords, respectively. In a class, any element placed after the `public` keyword is accessible to all the users of that class; but the elements that are placed after the `private` keyword are accessible only to the methods of the class.

## Inheritance

Inheritance is a mechanism that allows a class to inherit properties and functionalities from another class. If the X class inherits properties from the Y class, then you can say that X has been inherited from Y. In this scenario, Y is called superclass or base class of X, and X is called a subclass or derived class of Y, as shown in Figure 1:

The objects of the X class have access to attributes and methods of the Y class. Objects of the subclass, X, can be used where objects of the corresponding superclass Y are required. This is because the objects of the subclass X share the same behavior as the objects of the superclass Y. Superclasses are also called parent classes and subclasses may also be called child classes or just derived classes.

Inheritance enables you to reuse the code of classes multiple times. This means that you can add additional features to an existing class without modifying it by deriving a new class from an existing class. In addition, you can define a subclass with some unique features that are different from the features already defined in the corresponding superclass. In addition to its own features, the new class contains the features of the parent class.

## Polymorphism

Polymorphism is the ability of an object to exist in different forms. The term polymorphism has been derived from the Greek words poly (many) and morphos (forms). In the context of OOP, polymorphism is the ability of a function to behave differently, depending on the context in which it is called.

Polymorphism can be generally classified into two categories, static polymorphism and dynamic polymorphism. Static polymorphism refers to an entity that exists in different physical forms at the same time. The concept can be understood by considering an example of a woman. A woman has to play the role of a wife, a mother, a sister, a daughter, and an executive at the same time.
