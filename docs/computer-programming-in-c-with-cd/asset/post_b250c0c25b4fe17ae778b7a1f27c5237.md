## Implementing Dynamic or Late Binding using Virtual Functions

In some situations, when we write programs in C++, the type of the object or pointer may not be known at the time of compilation. For example, there may be a requirement where a list of employee needs to be created. Depending on the request of the department and the kind of employees required, the net salary of the employees needs to be calculated. In such a scenario, the number of employees and their department are not fixed, and such values are provided at the time of execution. This means, in such situations, the binding of a function to a class is done during the run time, and this process is known as dynamic binding or late binding.

You know that in C++, a pointer to a base class can point to an object of any of the derived classes. For example, assume that there is a pointer object of class A. Now, this pointer object can point to an object of its subclasses B and C, as shown in the following code snippet:

```cpp
A *PtrObj;
PtrObj = new B;
PtrObj = new C;
```

In the preceding code snippet, note that while pointers are necessary for late binding, they are not sufficient to implement it. This is because, although the base class pointer can be initialized with the derived classes of the base class, but the base class pointer always invokes the members of the base class. Listing 36 shows an example of using base class pointer, which is initialized with derived classes (you can find the LateBinding.cpp file on the CD in the Code\Chapter7 folder):

### Listing 36: Initializing a Base Class Pointer with Derived Classes

```cpp
#include <iostream.h>

class A
{
public:
    void display()
    {
        cout << "Class A" << endl;
    }
};

class B: public A
{
public:
    void display()
    {
        cout << "Class B" << endl;
    }
};

class C: public A
{
public:
    void display()
    {
        cout << "Class C" << endl;
    }
};

int main()
{
    A *PtrObj;
    PtrObj = new B;
    PtrObj->display();
    PtrObj = new C;
    PtrObj->display();
    return 0;
}
```

Output:
```text
Class A
Class A
```

In Listing 36, the compiler always invokes the member function of class A although PtrObj is pointing to an object of class B. This is because, the content of the PtrObj pointer is not known at the time of its declaration and therefore binding takes place at compilation time.

Therefore, using base class pointers alone is not sufficient to implement late binding.

Late binding is ensured by implementing the concept of virtual functions. A virtual function is a function that is declared virtual in a base class and is redefined by a derived class. The declaration of a virtual function is always preceded by the `virtual` keyword. A function is declared virtual because its execution depends on the context (that is, the content of the base class pointer used to invoke it), which is not known at the time of compilation.

Listing 37 shows the implementation of late binding in a class by declaring the function of the base class virtual (you can find the LateBinding_VirtualFunc.cpp file on the CD in the Code\Chapter7 folder):

### Listing 37: Implementing Late Binding by Using the virtual Function

```cpp
#include <iostream.h>

class A
{
public:
    virtual void display()
    {
        cout << "Class A" << endl;
    }
};

class B: public A
{
public:
    void display()
    {
        cout << "class B" << endl;
    }
};

class C: public A
{
public:
    void display()
    {
        cout << "class C" << endl;
    }
};

int main()
{
    A *PtrObj;
    PtrObj = new B;
    PtrObj->display();
    PtrObj = new C;
    PtrObj->display();
    return 0;
}
```

Output:
```text
class B
class C
```

In Listing 37, the display() member function of class A is a virtual function. When a virtual function is inherited, its virtual nature is also inherited. The virtual nature of a function means that the function exists only conceptually, and does not have a real existence. Therefore, a virtual function is a member function of a base class that may be redefined in the derived classes. In addition, a virtual function in a base class ensures that the compiler invokes the redefined virtual function of the corresponding derived class, even if you have called the function with a pointer or reference to a base class. A class that declares or inherits a virtual function is called a polymorphic class.

A virtual function cannot be global or static because, by definition, a virtual function is a member function of a base class and relies on a specific object to determine which implementation of the function is called. You can declare a virtual function to be a friend of another class.

Note that when a function is declared as virtual in a base class, you can access this function directly by using the :: operator. This is because, the :: operator suppresses the call to the function implementation of the derived class and calls the function implementation defined in the base class.

In addition, if you do not override a virtual member function in a derived class, a call to that function uses the function implementation defined in the base class. Listing 38 shows how to call a virtual function of the base class by using the `::` operator (you can find the CallVirtualFuncBySRO.cpp file on the CD in the Code\Chapter 7 folder):

### Listing 38: Calling a Virtual Function of the Base Class by using the :: Operator

```cpp
#include <iostream.h>

class A
{
public:
    virtual void display1()
    {
        cout << "Class A: Function display 1" << endl;
    }
    virtual void display2()
    {
        cout << "Class A: Function display 2" << endl;
    }
};

class B: public A
{
public:
    void display1()
    {
        cout << "Class B: Function display 1" << endl;
    }
};

class C: public A
{
public:
    void display1()
    {
        cout << "Class C: Function display 1" << endl;
    }
    void display2()
    {
        cout << "Class C: Function display 2" << endl;
    }
};

int main()
{
    A *PtrObj;
    PtrObj = new B;
    PtrObj->display1();
    PtrObj->display2();
    PtrObj = new C;
    PtrObj->display1();
    PtrObj->A::display2();
    return 0;
}
```

Output:
```text
Class B: Function display 1
Class A: Function display 2
Class C: Function display 1
Class A: Function display 2
```

In Listing 38, class A has two virtual functions, display1() and display2(). The virtual function, display1(), is overridden by the derived classes, B and C, as both classes have their own display1() function. However, the display2() virtual function is overridden by the C derived class only.

Now, in the main() function, the PtrObj object of class A is created, which points out to the B class. The PtrObj object invokes the display1() function of class B and the display2() function of class A. This is because class B does not have the definition of the display2() function of its own. Next, the PtrObj object points out to the C class, then it invokes the display1() function of the C class and the display2() function of the A class, though the C class has its own display2() function. This is because the pointer object invokes the display2() function of class A explicitly by using the :: operator.
