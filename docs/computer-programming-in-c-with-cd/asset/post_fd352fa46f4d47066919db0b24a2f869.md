
After describing various types of inheritance, let’s discuss some ambiguities that arise in case of multiple inheritance.

## 7.9 Describing Some Problems While Implementing Multiple Inheritance

In C++, some ambiguities arise for the compiler while implementing multiple inheritance. For example, what happens when two base classes contain a function with the same name? The following code snippet shows this ambiguity, as the display() function is inherited from both the Myclass1 and Myclass2 classes:

```cpp
class Myclass1
{
public:
    void display()
    {
        cout<<"My class 1"<<endl;
    }
};
class Myclass2
{
public:
    void display()
    {
        cout<<"My class 2"<<endl;
    }
};
class DerivedClass: public Myclass1,public Myclass2
{
    //Empty class
};
int main()
{
    DerivedClass obj;
    obj.display();
    // ambiguous for compiler

}
```

In the preceding code snippet, the obj object of the DerivedClass class invokes the display() function. However, in this situation the C++ compiler generates a compilation error, because the C++ compiler does not know whether to invoke the display() function from the Myclass1 or Myclass2 class. This problem arises because the DerivedClass class has received two copies of the display() function, from the Myclass1 and Myclass2 classes.

Another ambiguity in multiple inheritance arises when the derived class has multiple copies of the same base class, as shown in Figure 7:

![](img/8a6886c00caa6a1651a6c0e62bff341f_533_0.png)

**Figure 7: Displaying the Inheritance of Multiple Copies of Class A to Class D**

In Figure 7, there are four classes, A, B, C, and D. Classes B and C are inherited from a common base class, A, and class D is inherited from both class B and class C. As a result, class D has two copies of class A. The following code snippet shows how a derived class receives multiple copies of a variable of a class:

```cpp
class BaseA
{
public:
    int varA;
    ...
};
class BaseB: public BaseA
{
public:
    int varB;
    ...
};
class BaseC: public BaseA
{
public:
    int varC;
    ...
};
class DerivedClass: public BaseB, public BaseC
{
    public:
        int varD;
    ...
};
int main()
{
    DerivedClass obj;
    obj.varA=10;
    return 0;
}
```

The preceding code snippet displays an error because the reference to the varA variable in the obj object is ambiguous. The ambiguity arises because the DerivedClass class inherits two copies of the varA variable, one from the BaseB class and another from the BaseC class.

Now, let’s describe how to resolve the ambiguities that arise in case of multiple inheritance. The first ambiguity can be resolved in the following two ways:

- Overriding the base class function in the derived class
- Using the Scope resolution operator (::)

The second ambiguity, again, can be solved in two ways, as follows:

- Using the Scope resolution operator (::)
- Implementing the concept of virtual base classes

Let’s describe these solutions in detail, one by one, in the following sections:

### Overriding Base Class Functions in the Derived Class

The problem of ambiguity that arises in multiple inheritance when two base classes contain a function of the same name, can be solved by overriding the base class functions in the derived class. In this case, you can call the base class function explicitly in the overridden function of the derived class. Listing 23 shows how to override a base class function in a derived class (you can find the OverridenMemberFunction.cpp file on the CD in the Code\Chapter7 folder):

**Listing 23: Resolving Ambiguity by Overriding a Base Class Function in a Derived Class**

```cpp
#include<iostream.h>

class Myclass1
{
public:
    void display()
    {
        cout<<"My class 1"<<endl;
    }
};
class Myclass2
{
public:
    void display()
    {
        cout<<"My class 2"<<endl;
    }
};
class DerivedClass: public Myclass1,public Myclass2
{
public:
    void display()
    {
        Myclass1::display();
        Myclass2::display();
        cout<<"Derived class "<<endl;
    }
};
int main()
{
    DerivedClass obj;
    obj.display();
    return 0;
}
```

**Output:**

```text
My class 1
My class 2
Derived class
```

In Listing 23, there is no ambiguity for the compiler as the display() function in the derived class overrides the base class functions.

Another way to solve the same problem is to use the :: operator. Let's understand this in the following section.

### Using the Scope Resolution Operator

The problem of ambiguity in multiple inheritance can also be solved by using the :: operator. Listing 24 shows how to use the :: operator to solve the problem of ambiguity that arises in multiple inheritance (you can find the UsingSRO1.cpp file on the CD in the Code\Chapter7 folder):

**Listing 24: Resolving Ambiguity by Using the :: operator**

```cpp
#include<iostream.h>

class Myclass1
{
public:

void display()
{
    cout<<"My class 1"<<endl;
}
};

class Myclass2
{
public:
    void display()
    {
        cout<<"My class 2"<<endl;
    }
};

class DerivedClass: public Myclass1,public Myclass2
{
    //Empty class
};

int main()
{
    DerivedClass obj;
    obj.Myclass1::display();        //Use of scope resolution operator (::)
    obj.Myclass2::display();        //Use of scope resolution operator (::)
    return 0;
}
```

**Output:**

```text
My class 1
My class 2
```

In Listing 24, no ambiguity arises since an object, obj, of the DerivedClass class explicitly invokes the display() member function of both the base classes (Myclass1 and Myclass2) by using the :: operator.

The importance of the :: operator does not stop here. The :: operator also solves another problem of multiple inheritance, which arises when the derived class has multiple copies of the same base class. Listing 25 shows how to use the `::` operator to solve the problem of ambiguity, which arises when the derived class has multiple copies of the same base class (you can find the UsingSRO2.cpp file on the CD in the `Code\Chapter7` folder):

**Listing 25: Using the :: Operator to Create a Single Copy of a Base class**

```cpp
#include<iostream.h>

class BaseA
{
public:
    int varA;
};
class BaseB: public BaseA
{
public:
    int varB;
};
class BaseC: public BaseA
{
public:
    int varC;
};
class DerivedClass: public BaseB, public BaseC
{
public:
    int varD;
};

int main()
{
    DerivedClass obj;
    obj.BaseB::varA=10;
    obj.BaseC::varA=50;
    return 0;
}
```

In Listing 25, an object, obj, of the DerivedClass class can access the varA variable of the BaseB and BaseC classes with the help of the :: operator.

### Implementing the Concept of Virtual Base Classes

We know that a problem arises for the C++ compiler when a base class is inherited by multiple classes, and then a derived class is inherited from these multiple classes. The whole process creates multiple copies of base class members in the derived class. This problem can be solved in two ways, by using :: operator (as discussed in the earlier section), and by using the concept of virtual base class.

The concept of virtual base class is to inherit one or more derived classes from a base class by using the virtual keyword. Note that when you create a virtual base class, you have only one copy of the base class members in memory. Moreover, such kind of inheritance, where a derived class is inherited from a virtual base class, is also called virtual inheritance. Listing 26 shows how to create and use a virtual base class (you can find the VirtualBase.cpp file on the CD in the Code\Chapter7 folder):

**Listing 26: Creating and using a Virtual Base Class**

```cpp
#include<iostream.h>

class BaseA
{
public:
    int varA;
};

class BaseB: virtual public BaseA
{
public:
    int varB;
};

class BaseC: virtual public BaseA
{
public:
    int varC;
};

class DerivedClass : public BaseB, public BaseC
{
public:
    int varD;
};

int main()
{
    DerivedClass obj;
    obj.varA=10;      /*No ambiguity because only one copy of varA exists*/
    return 0;
}
```

In Listing 26, the BaseB and BaseC classes are inherited from the virtual class, BaseA by using the virtual keyword and class DerivedClass is inherited from both the BaseB and BaseC classes, so that only one copy of the varA variable of BaseA is inherited by the DerivedClass class. In this way, any reference to the varA variable through an object of the DerivedClass class does not lead to ambiguity.
