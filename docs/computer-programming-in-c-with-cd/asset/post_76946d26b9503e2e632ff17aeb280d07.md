> As you know, the default access specifier used in C++ is private. Therefore, the declaration:
> 
> `class B : A`
> 
> is treated in the C++ compiler as:
> 
> `class B : private A`

The following points must be kept in mind while defining a member as `private`, `protected`, or `public`:

- A private member is accessible only to the members of its class. It cannot be inherited. A private member of a base class can be accessed in the derived class through the protected or public member functions of the base class.
- A protected member of a base class is accessible to the members of its own class and to the members of a derived class.
- Declare the members of a class as protected, rather than private, which is expected to be used as a base class in future. This is because the protected members of a base class are accessible in a derived class.
- A public member is accessible to the members of its own class, members of the derived class, and functions or classes outside the base class.
- Constructors of the base and derived classes are automatically invoked when the derived class is instantiated. If a base class has constructors with arguments, then their invocations must be explicitly specified in the initialization section of the derived class. However, the default constructor need not be invoked explicitly. Note that constructors must be defined in the public section of a class (base and derived); otherwise, the compiler generates the unable to access constructor error message.

## 7.5 Overriding Base Class Members

When a derived class creates a function with the same return type and signature as a member function in the base class, but with a new implementation, it is said to override that function. In overriding, the derived class redefines the members of the base class. The signature of a function is its name, and the number and type of its parameters. The signature does not include the return type of the member function. Listing 2 shows how to override the members of a base class in its derived class (you can find the OverrideBase1.cpp file on the CD in the Code\Chapter7 folder):

### Listing 2: Overriding Base Class Members

```cpp
#include <iostream.h>
class Animal
{
public:
    void eat();
    void sleep();
    void breathe();
};
class Fish : public Animal
{
public:
    void breathe();
};
void Animal::eat(){cout << "Eating..." << endl;}
void Animal::sleep(){cout << "Sleeping..." << endl;}
void Animal::breathe(){cout << "Breathing..." << endl;}
void Fish::breathe(){cout << "Bubbling..." << endl;}
int main()
{
    Fish bigfish;
    bigfish.breathe();
    return 0;
}
```

**Output:**

```text
Bubbling...
```

In Listing 2, Animal is a base class and Fish is the derived class of the Animal class. The Fish class is redefining the functionality of the breathe() function of the Animal class.

However, the base class function can be accessed either by creating an instance (or object) of the base class, or by using the scope resolution (::) operator. The following code snippet shows how to use the :: operator to access the base class function, breathe():

```cpp
Animal::breathe();
```

In the preceding code snippet, the breathe() function is called directly by using the name of the base class (Animal) and the :: operator. Listing 3 shows how to call a base class function, which is overridden by a derived class, by using the name of the base class and the :: operator (you can find the OverrideBase2.cpp file on the CD in the Code\Chapter7 folder):

### Listing 3: Accessing a Base Class Function

```cpp
#include <iostream.h>
class Animal
{
public:
    void eat();
    void sleep();
    void breathe();
};
class Fish : public Animal
{
public:
    void breathe();
};
void Animal::eat(){cout << "Eating..." << endl;}
void Animal::sleep(){cout << "Sleeping..." << endl;}
void Animal::breathe(){cout << "Breathing..." << endl;}
void Fish::breathe()
{
    cout << "Bubbling..." << endl;
}
int main()
{
    Fish bigfish;
    bigfish.breathe();
    bigfish.Animal::breathe();    //accessing base class function
    return 0;
}
```

**Output:**

```text
Bubbling...
Breathing...
```

Note that the concept of function overriding must not be confused with the concept of function overloading. These terms look similar, but they do different tasks. Function overloading is to create more than one function with the same name, but with different signatures. Function overriding, on the other hand, is to create a function in a derived class with the same name and signature as a function in the base class.

## 7.6 Invoking Constructors and Destructors of Base and Derived Classes

As we know constructors are used to initialize the data members of a class and allocate the required memory to the data members. Destructors, on the other hand, are used to de-initialize the data members. Now, the question arises, what happens when the base as well as derived classes have their own constructors and destructors? Are the constructors and destructors of the base class overridden? In such a case, remember that a derived class does not require a constructor or destructor as long as the base class has a default constructor and destructor. However, if the base class has a constructor with one or more parameters, then it is mandatory for the derived class to have a constructor with parameters and to pass the arguments to the base class constructor explicitly. In the application of inheritance, usually objects of the derived class instead of the base class are created. Therefore, it is imperative for the derived class to have a constructor and pass the arguments to the constructor of the base class.
