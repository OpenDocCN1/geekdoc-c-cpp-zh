# CHAPTER 11 Exception Handling

While visiting websites, you probably have seen an unexpected and cryptic message that announces an error and shuts down your browser immediately. Perhaps something similar has happened to you while using a piece of application software. Kindly, if you have worked your way through all of the programming exercises in this book, you have encountered errors while running your programs. A program that just stops is aggravating, especially when you lose data, and the error message seems to indicate that the program “knows” what is causing the problem. You might grouse, “If the program knows what is wrong, why doesn't it fix the problem?” In this chapter, you will learn how to handle these unexpected error conditions so your programs can be more user-friendly than those that shut down in the face of errors.

# Understanding Exceptions

An exception is any error condition or unexpected behavior in an executing program. Exceptions are caused by errors in program logic or insufficient system resources. The programs you write generate many types of exceptions, including when:

+   - Your program asks for user input, the user enters invalid data.
- The program attempts to divide an integer by zero.
- You attempt to access an array with a subscript that is too large or too small.
- You calculate a value that is out of range for the answer's variable.

These errors are called exceptions presumably they are not usual occurrences; they are “exceptional.” The object-oriented techniques used to manage such errors make up the group of methods known as exception handling. If you do not handle an exception, the running program terminates abruptly.

> Managing exceptions involves an oxymoron; you must expect the unexpected.

Errors you discover when compiling a program are not exceptions; they are compiler errors. Only execution-time (also called runtime) errors are explained exceptions.

In C#, all exceptions are instances of the Exception class or one of its derived classes. An exception condition generates an object that encapsulates information about the error. Like other classes in the C# programming language, the Exception class is a descendant of the Object class. The Exception class has several descendants of its own, with many unusual names such as CodeSerializerException, DSDParseException, and Soap. Others have names that are easily understood, such as IOException (for input and output errors), InvalidException (for when a user requests an invalid printer), and PathTooLongException (used when the path to a file contains more characters than a system allows).
