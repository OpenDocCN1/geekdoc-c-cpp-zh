# Understanding File Data Organization

When businesses use data, they group characters into fields. A field is a character or group of characters that has some meaning. For example, the characters T, o, and m represent your first name. Other data fields represent items such as last name, Social Security number, zip code, and salary.

Fields are grouped together to form records. A record is a collection of fields that contain data about an entity. For example, the fields that hold a person's first and last names, Social Security number, zip code, and salary collectively are that person's record. When programming in C#, you have created an Employee class or a Student class. You can think of the data typically stored in each object that is an instance of these classes as record. In other words, classes contain individual variables that represent data fields. A business's data records often represent a person, item, sales transaction, or some other concrete object or event.

Records are grouped to create files. Files consist of related records. For example, a company's personnel files contain many records—one for each company employee. Some files have only a few records; your professor maintains a file for your class with 25 records—one for each student. Other files contain thousands or millions of records. For example, a large insurance company maintains a file of policyholders, and a mail-order catalog maintains the company's inventory file of available items.

A file is a sequential access file when each record is read in order from first to last in the file. Usually, the records are stored in order based on the value in some field; for example, employees may be stored in Social Security number order, or inventory items item number order. The field used to uniquely identify each record in a sequential file is the key field. Frequently, records are sorted by the key field. When records are not used in sequence, the file is used as a random access file, in which records can be accessed

Before an application can use a data file, it must open the file. A C# application opens a file by creating an object and associating a stream of bytes with it. When you finish using a file, the program should close the file—that is, make the file no longer available to your application. Failing to close a file (a file from which you are reading) usually does not result in serious consequences; the data still exists in the file. However, if you fail to close an output file (a file to which you are writing data), the data might become inaccessible. You should always close every file you open, and close the file as soon as you longer need it. Leaving a file open for no reason uses computer resources, and your computer's performance will suffer. Also, within a network, another program might be waiting to use the file. For example, if your program leaves the company's inventory file open after adding a new item, the program that fills orders for customers might fail to work correctly.
