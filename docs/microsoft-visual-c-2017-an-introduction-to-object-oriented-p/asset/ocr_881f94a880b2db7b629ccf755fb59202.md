Suppose you write the application shown in Figure 11-29. Your application is similar to the price lists created earlier in this chapter, including a call to PriceList.DisplayPrice(). As in PriceListApplication1 and PriceListApplication2, your new program is ready to enter and display statements and then catches an exception. When you run the program with what you know to be a good item number, as in Figure 11-30, you are surprised to see the shaded "Error!" message you coded in the catch block. In the earlier examples that you used PriceList.DisplayPrice(), using an item number 1 would have resulted in a successful program execution.

```
using System;
using static System.Console;
class PriceListApplication3
{
    static void Main()
    {
        int item;
        try
        {
            Write("Enter an item number >> ");
            item = Convert.ToInt32(ReadLine());
            PriceList.DisplayPrice(item);
        }
        catch (Exception e)
        {
            WriteLine("Error!");
        }
    }
}
```

> When you compile the program in Figure 11-29, you receive a warning that variable e is declared but never used. If you omit the item e from the catch block, the application will execute identically without displaying a warning.
