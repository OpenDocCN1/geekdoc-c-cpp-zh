# Understanding Focus and Tab Control

When a GUI program displays a Form, one of the components on the Form has focus. The control with focus is the one that can receive keyboard input. When a Button has focus, a thin, bright line appears around it to draw your attention, and the Button's associated event executes when you click the button or press the Enter key on the keyboard. When a TextBox has focus, a blinking cursor appears inside.

# Adding Labels and TextBoxes to a Form

When an application is running, the user can give focus to a component by clicking it or can switch from one component to another using the Tab key. The order in which controls receive focus from successive presses is the tab order. By default, controls are assigned a tab order on the order in which you place them on a Form. The first control you place on a Form has TabIndex 0, the next control has TabIndex 1, and so on. When you start a program, the control with TabIndex 0 automatically has focus. You can control a control's tab order by viewing its TabIndex in the Properties list. If you do not want a control to be part of the tabbing sequence, you can change its TabStop property from true to false in the Properties list. Alternatively, you can select View from the menu bar and select Order to see a representation of the Form with a small number to each control to represent the values. To change the focus for the controls, simply click each control in the desired order.

# Formatting Data in GUI Applications

In Chapter 2, you learned about format strings that can be used to align numeric data properly, display the desired number of decimal places, and display dollar signs. For example, the following displays $4.55 because the double variable money is converted to currency and formatted in position 0 of the string:

```csharp
double money = 4.55;
string Sentence = String.Format("Total is {0}", money.ToString("C2"));
```

You can use String.Format() to create formatted strings in GUI applications. For example, suppose you have retrieved a double from a TextBox with a statement similar to:

```csharp
double money = Convert.ToDouble(textBox1.Text);
```

You display the value on a label with explanatory text and as currency with two decimal places with a statement similar to:

```csharp
label1.Text = String.Format("The money value is {0}", money.ToString("C2"));
```

If necessary, you can use escape characters in strings that are assigned to controls. For example, a two-line label might be created using the following:

```csharp
label1.Text = "Hello\nthere";
```

# Changing Label’s Font

The Font property for controls was described briefly in Table 3-2 earlier in this chapter. You will learn more about this property in Chapter 2, but you might want to experiment with it now to align numbers. When you click on a Form and examine its Properties list, you discover that the default font for controls is Microsoft Sans Serif. This font is a proportional font, which means characters have different widths. For example, w is wider than i. The opposite of a proportional font is a fixed-pitch font, or a monospaced font, in which each character has the same width. You might want to use a fixed-pitch font to help align text values on controls. For example, when you stack $11 and $88.88 on a Label, you typically want the characters to be equal width so that the values align.

To change the font for a Label, select the box with an ellipsis (three dots) to the right of the existing Form name in the Properties list, and select a new Font from the dialog box that opens. Courier New and Consolas are popular fixed-pitch fonts. (You can also change the font style and size if desired.)

# Naming Forms and Controls

Usually, you want to provide reasonable Name property values for all the controls on a Form. Although any identifier that starts with a letter is legal, note the following conventions that are used in some organizations:

- Start control names with a lowercase letter, and use camel casing as appropriate.
- Start Form names with an uppercase letter, and use camel casing as appropriate.
- Use the type of object in the name. For example, use names as okButton, firstTextBox, or ArithmeticForm.

Professional programmers usually do not retain the default names for Forms and controls. An exception is sometimes made for Labels that never change. For example, if three labels provide directions or explanations to the user and are never altered during a program's execution, many programmers would approve of retiring their names as label1, label2, and label3.

Most often, you will want to name controls as soon as you add them to a Form. If you rename a control that you have created an event for, the program still works, but the name of the control no longer corresponds to its associated method, making the code harder to understand. If you simply change the method name to match the control, the event code will generate errors. For example, assume that you have placed a button button1 on a Form and that you have double-clicked it, creating a method named button1_Click().

You might want to change this method for one or more of these reasons:

- Method names conventionally start with an uppercase letter.
- If you change the name of the Button, you might want its Click() method to match the new control name.

To rename a method, you must refactor the code. Code refactoring is the process of changing a program's internal structure without changing how the program works. To refactor the code after changing the button's name, do the following:

- View the code and right-click the name of the method button1_Click().
- From the menu that appears, click Rename. The Click method is highlighted on the left side of Figure 3-1.
- When you click Rename, the button1_Click method is highlighted and a box appears with the Rename button1_Click, as shown on the right side of Figure 3-2.
