
# CHAPTER 3 Using GUI Objects and the Visual Studio IDE

If you scroll through the exposed code, you see many generated statements, some of which are confusing. However, to make a Button active, you can ignore more of the statements. You only need to write code between the curly braces of the method with the following header:

```
private void button1_Click(object sender, EventArgs e)
```

Instead of automatically generating the method header that executes when a user clicks a Button, you could write it yourself. You would have to know more about both methods and event handlers because other code is automatically written elsewhere in the project that links the Form's button to the method. You will learn about these topics in later chapters.

You have seen the following method used in console applications:

```
static void Main()
```

The GUI application also contains a Main() method that is created automatically; you can see it by opening the Program.cs file that is part of the application.

The button1_Click() method and the Main() method both use the void return type, but the methods differ in the following ways:

- *The button1_Click() method has a private access specifier. An access specifier is a keyword that dictates which types of classes can use a method. By default, Visual Studio makes the button1_Click() method private, which limits the ability of other classes to use the method, but you could remove the word private and notice no difference in how the button works. You will learn about more access specifiers later in this chapter.
- *The Main() method is static, whereas the button1_Click() method is not. A static method executes without an object. The button1_Click() method cannot be static because it needs an object, which is the Form in it is running. The chapter called "Classes and Objects" provides more detail about the keyword static.
- *The Main() method header contains no parameters between its parentheses, but the button1_Click() method has two parameters, separated by a comma. These represent values about the event (the user clicking the button) that causes execution of the program to perform a task. When a user interacts with a GUI, an event is generated that causes the button's click fires a click event, which causes the button's Click() method to execute. This chapter discusses only events. You can learn about other events in the "Event Handling" chapter.
- *The Main identifier begins with an uppercase M, but the button1_Click() method identifier begins with a lowercase b. In Chapter 1, you will learn that in C#, we use Pascal casing or upper camel casing, which means they will start with an uppercase letter, so Pascal casing defines convention. However, to create the method Button1_Click(), you would have to name the Button Button1, not the default name supplied by C#. In this chapter, you will learn how to change the method name to follow C#'s naming convention.

If you change a Button's Name from button1 and place a second button on the Form, the new Button is named button1. If you leave the first Button's default name as button1, the second Button on the Form is named button2, and its default Click() is named button2_Click(). C# automatically creates a method name for each Button based on its object's name.

You are not required to create a Click() method for a Button. If, for some reason, you did not want to take any action when user clicked a Button, you would simply not include the method in your program. Alternatively, you could create an empty method that contains no statements between its curly braces and does nothing. However, these choices would be unusual and a poor programming practice—you usually place a Button on a Form because you expect it to be clicked at some point. You will frustrate users if you do not follow your controls to act in expected ways.

You can write any statements you want between the curly braces of the button1_Click() method. For example, you can declare variables, perform arithmetic statements, and produce output. You also can include block or line comments. The next sections of this chapter include several statements added to a Click().

# Adding Labels and TextBoxes to a Form

Suppose that you want to create an interactive GUI that accepts two numbers from a user and outputs them when the user clicks a Button. To provide prompts for the user to display output, you can add Labels to a Form, and get an input, you can use TextBoxes.

A label is a control that you use to display text to communicate with an application's user; the C# class that creates a label is Label. To add a Label, just like a Button, you can drag a Label onto a Form, as shown in Figure 3-7. By default, the first Label you drag onto a Form is named label1, and the text that appears on the Label is label1. You can change its Text property to display a string of text; depending on the amount of text you enter, you might need to change the size of the Label by dragging its handles or resizing its Size property.

In 3-7, Enter a number has been assigned to label1’s Text property. If you want to create multiple lines of text, click the small, downward-pointing arrow to the right the Text property value to open an editor, and type the needed text in separate lines. You might want a program to start with no text appearing on a label. If so, delete the entry from the Text property in the Properties list. If you make any changes to its color, the label will be invisible to the user. Note that a label’s Text property can be blank, but a Label’s Name property cannot.

A text box is a GUI control through which a user can enter data; the C# class is TextBox. Figure 3-8 shows a TextBox on a Form. If the intention is to enter data in a TextBox, you might want to start with its Text empty, but you are allowed to add text to it Text property if desired.

Figure 3-9 shows a Form with three Labels, two TextBoxes, and a Button. The first Label has not yet been provided with new text, so it still contains label3. You can delete the value in the Properties window if you want the Label1 to be empty at first.

When you run the program that displays the Form in Figure 3-9, the intention is for the user to enter a number in each TextBox. When the user clicks the Button, the sum of the two numbers will be displayed in label3. To sum them, you must write code for the Button. In the Form Designer, double-click to expose the prewritten shell of the button1_Click() method.
