# Catching Multiple Exceptions

The first statement within the try block in Figure 11-15 attempts to access element 13 of a three-element array, the program throws an IndexOutOfRangeException. The try block is abandoned, and the first catch block is examined and found unsuitable because the Exception object is of the wrong type—it is not a DivideByException object. The program logic proceeds to the second catch block, whose IndexOutOfRangeException argument is a match for the thrown Exception type. The message in second catch block and the Exception's Message value are therefore displayed. Figure 11-16 shows the output.

Sometimes you want to execute the same code, no matter what Exception type occurs. For example, in each version of the TwoErrors program, each catch block displays a unique message. Instead, you want both the DivideByZeroException catch block and the IndexOutOfRangeException catch block to use the thrown Exception's Message field. Because DivideByZeroException and IndexOutOfRangeException both are subclasses of Exception, you can rewrite the TwoErrors class as shown in Figure 11-17 and include only one Exception catch block that catches any type of Exception.

```
using System;
using static System.Console;
class TwoErrors3
{
    static void Main()
    {
        int num = 13, denom = 0, result;
        int[] array = {22, 33, 44};
        try
        {
            result = array[num];
            result = num / denom;
        }
        catch(Exception error)
        {
            WriteLine(error.Message);
        }
    }
}
```
