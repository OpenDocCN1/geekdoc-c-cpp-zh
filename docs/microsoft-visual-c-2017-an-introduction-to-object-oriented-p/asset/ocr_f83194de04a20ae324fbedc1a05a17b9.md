# Handling Exceptions Thrown From Outside Methods

An advantage of using object-oriented-exception handling techniques is the ability to deal with exceptions appropriately as you decide how to handle them. When methods from other classes throw exceptions, the methods don't catch them; instead, calling your program can catch them, and you can decide what to do.

For example, suppose that you want a user to enter a value at the console and then call the Convert32() method to convert the input to an integer with a statement such as this:

```
int answer = Convert.ToInt32(ReadLine());
```

If the user enters a noninteger value, a FormatException is generated from the Convert.ToInt32 method, but it is not caught and handled. Instead, your program can catch the exception, and you can take appropriate action for your specific application. For example, in one program you might want to force the user to reenter a value, or you might want to display an error message and terminate the program. This flexibility is an advantage when you need to create specific reactions to exceptions. In many cases, you might want a method to check for errors, but you do not want the method to handle an error if it finds one. Just as a police officer can de-escalate with a speeding driver differently depending on circumstances, you can react to exceptions specifically for your current purposes.

When you design classes containing statements that might throw exceptions, you most frequently check the methods that they throw the Exception object but not handle it. Handling an exception usually is left to the client—so the exception can be handled in an appropriate way for the application.
