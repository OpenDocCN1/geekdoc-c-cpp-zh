## Creating and Using Abstract Classes

Creating classes can become easier after you understand the concept of inheritance. When you create a child class, it inherits all the general attributes you need; you must create only the new, more specific attributes required by the child class. For example, a Painter and a Sculptor are more specific than an Artist. They inherit all the general attributes of Artists, but you must add the attributes that are specific to Painter and Sculptor.

Another way to think about a superclass is to notice that it contains the features shared by its subclasses. The derived classes are more specific examples of the base class type; they add features to the shared, general features. Conversely, when you examine a derived class, you notice that it is more general.

Sometimes you create a parent class to be so general that you never intend to create any specific instances of the class. For example, you might never create "just" an Artist; each Artist is more specifically a Painter, Sculptor, Illustrator, and so on. A class that you can create to extend, but not to instantiate, is a **concrete class**. An **abstract class** is one from which you cannot create concrete objects from which you can inherit. You use the keyword **abstract** when you declare an abstract class, or you will receive a compiler error.

Abstract classes are like regular classes that they can contain data fields and methods. The difference is that you cannot create instances of abstract classes using the **new** operator. Rather, you create abstract classes simply to provide a base class from which other objects are derived.

Abstract classes usually contain abstract methods, and they can also contain nonabstract methods. However, they are not required to contain any methods. Recall from Chapter 9 that an abstract method has no statements. Any class derived from a class that contains an abstract method must override the abstract method by providing a body (an implementation) for it. (Alternatively, the derived class can declare the method to be abstract; in that case, the derived class's children must implement the method.) You can create an abstract class with no methods, but you cannot create an abstract method outside of an abstract class.

> A method that declared virtual is not required to be overridden in a child class, but a method must be overridden.

When you create an abstract method, you provide the keyword **abstract** and the intended method type, but you do not provide statements within the method. You create an abstract class like Animal so that you can extend it. For example, suppose you want to create classes to represent different animals. You create a generic, abstract class **Animal** to provide generic data fields, such as the name, only once. An Animal is generic, but each specific Animal makes a unique sound. If you create an abstract **Speak()** in the abstract **Animal** class, then you require all derived classes to override and provide an implementation that is specific to the derived class. Figure 10-31 shows an **Animal** class that contains a data field for the name, a constructor that assigns a name, and an abstract **Speak()** method.

```csharp
abstract class Animal
{
    private string name;
    public Animal(string name)
    {
        this.name = name;
    }
    public string Name
    {
        get
        {
            return name;
        }
    }
    public abstract string Speak();
}
```

Figure 10-31 The Animal class is declared to be abstract. (The keyword is shaded.) You cannot place a statement such as Animal myPet = new Animal("Murphy"); within a program, because the program will not compile. Because Animal is an abstract class, no Animal objects can exist.

You create an abstract class like Animal so that you can extend it. For example, you can create Dog and Cat classes as shown in Figure 10-32. Because the Animal class contains a constructor that requires a string argument, both Dog and Cat must contain constructors that provide string arguments for their base class.

```csharp
class Dog : Animal
{
    public Dog(string name) : base(name)
    {
    }
    public override string Speak()
    {
        return "woof";
    }
}
class Cat : Animal
{
    public Cat(string name) : base(name)
    {
    }
    public override string Speak()
    {
        return "meow";
    }
}
```
