# CHAPTER 10 Introduction to Inheritance

You can think of an interface as a contract. A class that implements an interface must abide by the rules of the contract.

Beginning programmers sometimes find it difficult to decide when to create an abstract base class and when to create an interface. You can follow these guidelines:

+   - Typically, you create an abstract class when you want to provide some data or methods that derived classes inherit, but you want the subclasses to override some specific methods that you declare to be abstract.
- You create an interface when you want derived classes to override every method.

In other words, you inherit from an abstract base class when you want to create "is a" subtype, and you use an interface when the class you want to create act like the interface.
Interfaces provide you with a way to exhibit polymorphic behavior: If different classes implement the same interface in you you can treat each class type in the same way using the same language. When various classes use the same interface, you know the names of the methods that are available with those classes, and C# adopts a more uniform functionality; this consistency helps you to understand new you encounter more easily. If you know, for example, the method names contained in the IWorkable interface, and you see that a class implements IWorkable, you have a head start in understanding the class functions.

Now that you understand how to construct your own interfaces, you will benefit from rereading the section describing the IComparable interface in the chapter "Classes and Objects."
