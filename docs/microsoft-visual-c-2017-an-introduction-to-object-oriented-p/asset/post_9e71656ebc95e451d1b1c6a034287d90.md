## Understanding Serialization and Deserialization

Writing to a text file allows you to store data for later use. However, writing to a text file presents two disadvantages:

- Data in a text file are easily readable in a text editor such as Notepad. Although this feature is useful to developers when they test programs, it is not a very secure way to store data.

- When a record in a data file contains many fields, it is cumbersome to convert each field to text and combine the fields with delimiters before storing the record on a disk. Similarly, when you read a text file, it is somewhat uneasy to eliminate the delimiters, split the text into tokens, convert each token into the proper data type. Writing an object to a file at once would be more convenient.

C# provides a technique called serialization that can be used for writing objects to reading objects from data files. Serialization is the process of converting objects into streams of bytes. Deserialization is the reverse process; it converts streams of bytes back into objects.

To create a class that can be serialized, you mark it with the [Serializable] attribute, as shown in the shaded statement in Figure 14-21. The Employee class in the figure is identical to the one in Figure 14-10 except for the [Serializable] attribute.

```cs
[Serializable]
class Employee
{
    public int EmpNum {get; set;}
    public string Name {get; set;}
    public double Salary {get; set;}
}
```

**Figure 14-21** The serializable Employee class

Attributes provide a method of associating information with C# code. They are always contained in square brackets. Search for C# attributes at http://msdn.microsoft.com for more details.

![](img/7516c1fecf7bbbe7af10cf209b17ae3700)

In a class marked with [Serializable], every instance variable must be serializable. By default, C# simple types are serializable. However, if your class contains references to other objects, they must also be serializable.

If you create a class and want to write its objects to a file, you can implement the ISerializable interface instead of marking the class with the [Serializable] attribute. When you use this approach, you must write a method named GetObjectData(). Marking the class with the attribute is simpler.

Two namespaces are included in programs that employ serialization:

* System.Serialization.Formatters.Binary;
* System.Runtime.Serialization;

When you create a program that writes objects to files, you declare an instance of the BinaryFormatter class with a statement such as the following:
BinaryFormatter bf = new BinaryFormatter();

Then, if you have a class with object data, you can write it to the output file stream with a statement such as the following:
bf.Serialize(outFile, objectFilledData);

## Serialize method

The Serialize() method takes two arguments—a reference to the output file and a reference to a serializable object that may contain any number of data fields. The entire object is written to the data file with this single statement.

Similarly, when you read from a data file, you use a statement like the following:
objectInstance = (Employee)formatter.Deserialize(inFile);

This statement uses the Deserialize() method with a BinaryFormatter to read one object from the file. The object is cast to the appropriate type and can be assigned to an instance of the object. Then you can access individual fields. An entire object is read with this single statement, no matter many fields it contains.

Figure 14-22 shows a program that writes Employee classes to an output file and later reads them into the program. After the FileStream is declared for the first statement. The user enters an ID number, name, and salary for an Employee, and the completed object is written to a file in the second shaded statement. When the user enters 999, the completed object is closed.
