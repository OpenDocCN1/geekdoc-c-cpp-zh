## CHAPTER 2 Using Data

When you perform arithmetic operations with operands of dissimilar types, C# chooses a **unifying type** for the result and **implicitly** (automatically) converts nonconforming operands to the unifying type, which is the type with the **higher precedence**. The conversion is called **implicit conversion** or **implicit cast**—the automatic transformation that occurs when a value is assigned to a type with higher precedence.

The implicit numeric conversions are:

- sbyte to short, int, long, float, double, or decimal
- byte to short, ushort, int, uint, long, float, double, or decimal
- short to int, long, float, double, or decimal
- ushort to int, uint, ulong, float, double, or decimal
- int to long, float, double, or decimal
- uint to long, ulong, float, double, or decimal
- long to float, double, or decimal
- ulong to float, double, or decimal
- char to ushort, int, uint, ulong, float, double, or decimal
- float to double

Implicit conversions occur in simple assignments as well as in calculations. For example, if *money* is declared as a *double*, then the following statement implicitly converts the integer 15 to a *double*:

```
money = 15;
```

> Conversions from int, uint, or long to float and from long to double might cause a loss of precision but will never cause a loss of magnitude.

> A constant expression of type int, such as 25, can be converted to sbyte, short, ushort, int, or long. For example, sbyte age = 19; which assigns an int to a sbyte, is legal. However, you must make sure the assigned value is within the allowed range for the destination type, or the program will not compile. For example, sbyte age = 200; is illegal because the highest value for a sbyte is 127.
