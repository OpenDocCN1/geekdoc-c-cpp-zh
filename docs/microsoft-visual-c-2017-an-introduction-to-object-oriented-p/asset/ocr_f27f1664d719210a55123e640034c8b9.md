Figure 13-23 Three executions of the KeyDemo program

In the second execution in Figure 13-23, the user held Shift, pressed $a$, and then released the Shift key. This causes two separate separate events. The first has KeyCode $A$ with Shift true, and the second has KeyCode ShiftrtKey. Notice that the values generated after typing $a$ and $A$ are the same, but the value after typing Shift is different.

In the third execution in Figure 13-23, the user pressed the number $1$, whose code is D1.

When you view Form1.Designer.cs for the KeyDemo program, you see the automatically created event statement, which defines the composed delegate:

```
this.KeyUp += new System.Windows.Forms.EventHandler(this.Form1_KeyUp);
```

> TWO TRUTHS & A LIE Handling Mouse and KeyboardHandler

+   1. The delegate used to create mouse event handlers is Mouse.
2. Keyboard events, also known as key events, occur when a user presses and releases keyboard keys.
3. Unlike mouse events, every keyboard event-handling method must be parameterless.
