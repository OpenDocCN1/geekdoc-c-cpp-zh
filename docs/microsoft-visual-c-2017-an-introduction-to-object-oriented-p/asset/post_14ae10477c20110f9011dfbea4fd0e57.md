## Understanding Delegates

A **delegate** is an object that contains a reference to a method; object-oriented programmers would say a delegate encapsulates a method. In government, a delegate is a representative that you authorize to make choices for you. For example, states send delegates to presidential nominating conventions. When delegates arrive, they are free to make last-minute choices based on current conditions. Similarly, C# provide a way for a program to take alternative courses that are not determined at runtime. When you write a method, you don't always know which actions will occur at runtime, so you give your delegates authority to run the correct methods.

> In Chapter 1, you learned that encapsulation is a basic feature of object-oriented programming. Recall that encapsulation is the technique of packaging an object's attributes and methods into a cohesive unit that can be used as an independent entity.

After you have instantiated a C# delegate, you can pass this to a method, which then calls the method referenced within the delegate. In other words, a delegate provides a way to pass a reference to a method as an argument to another method. Although you can't pass a method to a method, you can pass an object that is a reference to a method. For example, if del is a delegate that contains a reference to the method M1(), you can pass del to a new method named MyMethod(). Alternatively, you can create a delegate that contains a reference to a method named M2() and pass this version to MyMethod(). When you write MyMethod(), you don't have to know whether it calls M1() or M2(); you only need to know that it calls whatever method is referenced within it.
