# CHAPTER 11 Exception Handling

The DivideByZeroException object was generated automatically by C#. It is an instance of
DivideByZeroException class that has four ancestors. It is a child of the ArithmeticException
class, which descends from the SystemException class. The SystemException class derives from the
Exception class, which is a child of the Object class.

Just because an exception occurs and an Exception object is created, you don't necessarily
have to deal with it. In the MilesPerGallon class, you simply let the offending program
terminate; that is why the error message in Figure 11-2 indicates that the Exception is
"Handled". However, the termination of the program is abrupt and unforgiving. When a
program divides two numbers, or performs some other task such as playing a game,
t user might be annoyed if the program ends abruptly. If the program is used for air-traffic
control or to monitor a patient's vitals during surgery, an abrupt conclusion could
disastrous. With exception handling, a program can continue after dealing with a problem. This
is especially important in mission-critical applications. The term mission critical refers to any
process that is crucial to an organization. Object-oriented error-handling techniques provide
more elegant solutions than simply shutting down.

Programs that handle exceptions appropriately are said to be more fault tolerant and robust than
th that do not. Fault-tolerant exceptions are designed so that they continue to operate, possibly at a
reduced level, when some part of the system fails. Robustness represents the degree to which a system is
resilient to stress, maintaining correct functioning.
