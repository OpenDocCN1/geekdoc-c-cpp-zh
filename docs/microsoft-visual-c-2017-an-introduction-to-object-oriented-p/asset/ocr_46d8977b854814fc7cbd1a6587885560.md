11-33 shows a NegativeBalanceException class that extends Exception. This class passes an appropriate string message to its parent's constructor. If you create an Exception object and design its Message property, you will see the Error in the application. When the NegativeBalanceException constructor passes the string Bank balance is negative, the Message property will hold this more descriptive message. The C# documentation recommends that you create all Exception subclass messages to be grammatically correct, complete sentences ending in a period.

```
class NegativeBalanceException : Exception
{
    private static string msg = "Bank balance is negative.";
    public NegativeBalanceException() : base(msg)
{
}
```

When you create a BankAccount class like the one shown in Figure 11-34, you can create the Balance property setter to throw a NegativeBalanceException when a client attempts to set the balance to negative.

Instead of creating the nbe object in the property in Figure 11-34, you could code the following statement, which creates and throws an anonymous NegativeBalanceException in a single step: throw(new NegativeBalanceException());

The Microsoft documentation recommends creating three constructors for every exception class you create: the default constructor, a constructor that takes a string message, and a constructor that takes a string message and an inner exception. To keep this example simple, NegativeBalanceException in Figure 11-33 contains just one constructor.
