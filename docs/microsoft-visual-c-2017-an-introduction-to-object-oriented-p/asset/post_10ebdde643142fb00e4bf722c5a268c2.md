## Returning a Reference from a Method

A new feature in C# 7.0 called ref return allows you to return a reference from a method.
Using a ref return has some restrictions; you can only return references that C# considers
"safe to return". For example, you can return a reference from a method if the reference was
passed into the method, but cannot if the value was passed into the method. Consider the program in Figure 8-14. It declares an array of five inventory item numbers and displays them. The program prompts the user for an item and finds it from the keyboard. In the shaded method, a reference named soldItem is declared and assigned the value returned from method FindItem().

```csharp
using System;
using System.Console;
class ReturnRefDemo
{
    static void Main()
    {
        int itemToDo;
        int x;
        int[] items = {123, 241, 375, 410, 555};
        WriteLine("Before replacement: " + items.Length);
        for(x = 0; x < items.Length; x++)
        {
            Write("  " + items[x]);
            Write("\nEnter the value to find >> ");
            itemToDo = Convert.ToInt32(ReadLine());
        }
        ref int soldItem = FindItem(itemToDo, items);
        soldItem = 0;
        WriteLine("After replacement: ");
        for(x = 0; x < items.Length; x++)
        {
            Write("  " + items[x]);
        }
    }
    public static ref int FindItem(int findValue, int[] elements)
    {
        int x;
        int position = -1;
        for(x = 0; x < elements.Length; x++)
        {
            if(findValue == elements[x])
            {
                position = x;
            }
        }
        return ref elements[position];
    }
}
```

Figure 8-14 The ReturnDemo program

You can see in the shaded method call that FindItem() accepts an integer to find in the array of item numbers. As you learned in Chapter 7, when an array is passed to a method, its address is received by the method. The FindItem() method in Figure-14 uses a for loop to search the elements array for a match to theValue parameter. When a match is found, the position is saved, and in the return statement, the memory address of the found element is returned. (Note that in this example, if findValue parameter is not matched in the array, the address of invalid element that uses a negative subscript (-1) is returned from the method. You need to learn about exception handling in Chapter 11 before you can handle this mistake.)

In the Main() method, following the call to FindItem(), item, which represents the memory address of the matching element, is set to 0 to indicate that it is longer available. When the items array is displayed, the correct element has been changed to 0. Figure 8-15 shows two separate executions of the program in which a different element is removed each time.

You could accomplish the removal of the items array in ReturnDemo program without returning a reference. For example, you could create the FindItem() method to return an integer subscript that is not a reference and use it to access the desired element in the Main() method. So, for now, returning a reference from a method will be of limited value to you. However, you should understand that you can return a reference in C#, and you might someday use the technique in a large program where it might be impractical to pass large amounts of data into and out of methods and much more practical to pass references.

## TWO TRUTHS & A LIE

- 1. A reference can be returned from any method.
- 2. When a reference is returned from a method, the calling method receives a new address.
- 3. When a method returns a reference, it cannot also return a value.

> For example, you can return a reference from a method if the value was passed into the method. The false statement is: there are some restrictions on the uses of ref returns.

## Overloading Methods

**Overloading** involves the ability to write multiple versions of a method using the same name. When you make a purchase at a store, you might use one of "pay" methods they accept: cash, a credit card, or a check. The "pay" method works differently depending on the type of currency sent to it, but all of the transactions are called "pay." When you overload a C# method, you write multiple method implementations with the same name but different parameter lists. A method's name and parameter list constitute the **signature**.

In this book, you have seen `WriteLine()` method used with a string and a numeric parameter. You can use it with no parameter to output a blank line. You have also seen the method used with several parameters when using a format string with several variables. Therefore, you know `WriteLine()` is an overloaded method.

Some C# operators are overloaded. For example, a + between two numeric values indicates addition, but a single + to the left of a value means the value is positive. The + has different meanings based on the operands used. In the chapter "Using Classes," you will learn to overload operators with your own classes. The compiler understands which method to use based on the arguments used in a method call. For example, suppose that you want a method to display a `string` surrounded by a border.
