# Recognizing Inheritance in GUI Applications

“Using Controls,” but even though you have worked with a few controls so far, you can understand the benefits inheritance provides, for both GUI and non-GUI classes.

When an automobile company designs a new car model, it does not build every component from scratch. The car might include a new feature—for example, some model contained the first air bag—but many of the new car's features are simple modifications of existing features. The manufacturer might create a larger gas tank or a more comfortable seat, but these new features still possess many of the properties of their predecessors from older models. Most features of new car models are not modified; instead, extending components, such as air filters and windshield wipers, are included in the new model without any changes.

Similarly, you can create computer programs more easily if many of the components are either “as is” or with slight modifications. Inheritance does not enable you to write any programs that you could not write if inheritance did not exist; you could create every part of a program from scratch, but reusing classes and interfaces makes your job easier.

You already have used many “as is” classes, such as Console, Int32, and String. Using these classes makes it easier to write programs than if you had to invent the classes yourself. Now that you have learned about inheritance, you can extend classes as well as just use them. When you create a useful, extensible base class, you and other programmers gain

+   - Derived class creators save development time because the code that is needed for the class already has been written.

+   - Derived class creators save testing time because the base class already has been tested and probably used in a variety of situations. In other words, the base class code is reliable.

+   - Programmers create or use new derived classes already understand how the base class works, so the time it takes to learn the new class features is reduced.

+   - When you create a derived class in C#, the base class source code is not changed. Thus, the base class maintains its integrity.

> Classes that are not intended to be instantiated and that contain only static members are declared as static classes. You cannot extend static classes. For example, System.Console is a static class.

When you think about classes, you need to think about the commonalities between them, and then you can create base classes from which to inherit. You might even be rewarded professionally when you see your own superclasses extended by others in the future.
