
## CHAPTER 10 Introduction to Inheritance

You can think of an interface as a contract. A class that implements an interface must abide by the rules of the contract.

Beginning programmers sometimes find it difficult to decide when to create an abstract base class and when to create an interface. You can follow these guidelines:

- Typically, you create an abstract class when you want to provide some data or methods that derived classes inherit, but you want the subclasses to override some specific methods that you declare to be abstract.
- You create an interface when you want derived classes to override every method.

In other words, you inherit from an abstract base class when you want to create an "is a" subtype, and you use an interface when the class you want to create acts like the interface.

 Interfaces provide you with a way to exhibit polymorphic behavior: If different classes implement the same interface, you can treat each class type in the same way using the same language. When various classes use the same interface, you know the names of the methods that are available with those classes, and C# adopts a more uniform functionality; this consistency helps you to understand new classes that you encounter more easily. If you know, for example, the method names contained in the IWorkable interface, and you see that a class implements IWorkable, you have a head start in understanding the class functions.

Now that you understand how to construct your own interfaces, you will benefit from rereading the section describing the IComparable interface in the chapter "Classes and Objects."

## Using Extension Methods

When you write a C# program, sometimes you wish a class had an additional method that would be useful to you. If you created the original class, you have two options:

- You could revise the existing class, including the new useful method.
- You could derive a child from the existing class and provide it with a new method.

Sometimes, classes you used were created by others, and you might not be allowed to either revise or extend them. Of course, you could create an entirely new class that includes your new method, but would require a lot of the work already done when the first class was created. In these cases, the best option is to write an extension method. **Extension methods** you can add to any type of class were introduced in C# 3.0.

Programmers sometimes define classes as sealed within the class header, as sealed InventoryItem. A **sealed class** cannot be extended. For example, the builtin String class is a sealed class.

For example, you have used the prewritten Int32 class throughout this book to declare integers. Suppose that you work for a company that frequently uses customer numbers, and that the company has decided to add an extra digit to each account number. For simplicity, assume that account numbers are two digits and the third digit, which will be third, you could handle this problem by creating a class named **AccountNumber**, including a method to provide the extra digit, and redefining every instance of a customer's account number in your applications as an **AccountNumber** object. if you already have many applications that define the account number as an integer, you might prefer to create an extension method that extends the **Int32 class**.

> In Chapter 2 you learned that each C# intrinsic type, such as int, is an alias for a class in the System namespace, such as Int32.

> When organizations add extra digits to account numbers, the extra digits are called check digits. *Check digits help ensure that all the digits in account numbers and other numbers are entered correctly.* If a digit used to calculate the check digit is incorrect, then the resulting check digit is probably incorrect as well.

Figure 10-40 contains a method that extends the **Int32 class**. The first parameter in an extension method specifies the type to be extended and must begin with the **keyword this**. For example, the (and in this case, only) parameter in the AddCheckDigit() method is **this num**, as shown in the shaded portion of the figure. Within the AddCheckDigit() method in Figure 10-40, the first digit is extracted from the two-digit number by dividing by 10 and taking the result number, and the second digit is extracted by taking the remainder. Those two digits are added, and the last digit of that is returned from the method.

```c
public static int AddCheckDigit(this int num) {
  int first = num / 10;
  int second = num % 10;
  int third = (first + second) % 10;
  int result = num * 10 + third;
  return result;
}
```

## Figure 10-40 The AddCheckDigit() extension method

For example, if 49 is passed into the method, first becomes 4, second becomes 9, and third becomes the last digit of 13, or 3. Then the original number (49) is multiplied by 10 and added to the third digit, resulting in 493.

An extension method must be static and must be stored in a static class. For example, the DemoExtensionMethod in Figure 10-41 shows an application that is declared static in the shaded portion of the class. The method AddCheckDigit() is used as if it were an instance method of the Int32 class; in other words, it is implied, just as these references are always implied.

```csharp
using static System.Console;
static class DemoExtensionMethod {
  static void Main() {
    int acctNum = 49;
    int revisedAcctNum = acctNum.AddCheckDigit();
    WriteLine("Original number was {0}", acctNum);
    WriteLine("Revised number is {0}", revisedAcctNum);
  }
  public static int AddCheckDigit(this int num) {
    int first = num / 10;
    int second = num % 10;
    int third = (first + second) % 10;
    int result = num * 10 + third;
    return result;
  }
}
```

You can create methods for your own classes in the same way one was created for the Int32 class. Just like other methods, unlike class instance methods, extension methods cannot access any private members of classes they extend. Furthermore, if a class contains an instance method with the same signature as an extension method, the instance method takes priority and will be the one that executes.

## Recognizing Inheritance in GUI Applications

When you create a Windows Forms application using Visual Studio's IDE, you automatically get inheritance. Every Form you create is a descendant of the Form class. Figure 10-43 shows a project in which the programmer double-clicked the automatically generated Form to expose the code. You can see that the automatically generated Form1 extends Form.

The Form class descends from the Object class like all other C# classes but not directly. It is six generations removed from the Object class in the following line of descent:

- Object
* MarshalByRefObject
* Component
* Control
* ScrollableControl
* ContainerControl
* Form
