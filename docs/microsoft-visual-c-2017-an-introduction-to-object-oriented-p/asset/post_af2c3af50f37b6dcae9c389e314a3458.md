# Handling Keyboard Events

Keyboard events, also known as key events, occur when a user presses and releases keyboard keys. Similar to the mouse events, each keyboard event-handling method must have two parameters. Depending on the event, the delegate used to create the event handler is either EventHandler and the type of the second parameter is KeyEventArgs.

| Keyboard event | Description | Event argument |
| --- | --- | --- |
| KeyDown | Occurs when a key is pressed | KeyEventArgs |
| KeyUp | Occurs when a key is released | KeyEventArgs |
| KeyPress | Occurs when a key is pressed | KeyEventArgs |

**Table 13-4** Keyboard events

Table 13-5 describes KeyEventArgs properties, and Table 13-6 describes KeyPress. An important difference is that KeyEventArgs objects include data about modifier keys that are pressed. For example, if you need to distinguish between user pressing Alt+A in your application, you must use a keyboard event that uses argument of KeyEventArgs.

| Property | Description |
| --- | --- |
| Alt | Indicates whether the Alt key was pressed |
| Control | Indicates whether the Control (Ctrl) key was pressed |
| Shift | Indicates whether the Shift key was pressed |
| KeyCode | Returns the code for the key |
| KeyData | Returns the key code with any modifier key |
| KeyValue | Returns a numeric representation of the key (this is known as virtual key) |

# Managing Multiple Controls

When Forms contain multiple Controls, you often want one to have focus. You also might want several actions for a single shared consequence. For example, you might want the same action to occur whether the user clicks a button or presses the Enter key, or you might want multiple buttons to generate the same event when they are clicked.

# Defining Focus

When users encounter multiple GUI Controls on a Form, usually one Control has focus. For example, when a Button has focus, a user expects that clicking the button or pressing the Enter will raise an event.

TabStop is a Boolean property of a Control that identifies whether the Control will serve as a stopping place—that is, a place where focus receives—in a sequence of Tab keys. The default value for Button is true, but the default value for Label is false because Labels are not expected to be part of a tabbing sequence. TabIndex is a numeric property that indicates the order in which the Control will receive focus when the user presses the Tab key. Programmers typically use small for Tab values, beginning with 0. When a Control's TabStop is true and the Control has the lowest TabIndex of a Form's Controls, it receives focus when the Form is initialized.

> Setting the TabIndex values of two or more Controls to 0 does not cause an error. Only one Control will receive focus, however.
