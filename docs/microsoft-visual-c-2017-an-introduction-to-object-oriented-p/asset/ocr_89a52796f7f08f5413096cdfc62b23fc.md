# Understanding Numeric Type Conversion

The error message in Figure 2-13 asks "are you missing a cast?" You can **explicitly** (or purposefully) override the unifying type imposed by C# by performing an explicit cast. An **explicit cast** involves placing the desired type in parentheses followed by the variable or constant to be cast. For example, two explicit casts are performed in the following code:

```
double bankBalance = 191.66;
float weeklyBudget = (float) bankBalance / 4;
// weeklyBudget = 47.915, one-fourth of bankBalance
int dollars = (int) weeklyBudget;
// dollars is 47, the integer part of weeklyBudget
```

The value of bankBalance / 4 is implicitly a double because divided by an int produces double. The explicit cast converts the double result to a float before it is stored in weeklyBudget. Similarly, the **float** weeklyBudget is cast to an **int** before it is stored in **dollars** (and the decimal-place values are lost).

It is easy to lose data when performing a cast. For example, the largest byte value is 255, and the largest int value is 2,147,483,647, so the following statements distort results because of the cast:

+   * int anOkayInt = 256;
* byte aBadByte = (byte)anOkayInt;

In this example, displaying aBadByte shows 0. If you stored 255 in anOkayInt, the result would appear as 1; if you stored 258, the result would appear as 2, and so on.
