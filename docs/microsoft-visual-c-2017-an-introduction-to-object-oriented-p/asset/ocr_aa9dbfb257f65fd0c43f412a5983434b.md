# TWO TRUTHS & A LIE
Using the protected Access Specifier

+   1. A child class does not contain the private members of its parent.
2. A child class cannot use the private members of its parent.
3. A child class can use the protected members of its parent, but outside classes cannot.

> The false statement is #1. A child class contains the private members of it, but cannot use them directly.

# Overriding Base Class Members

When you derive a derived class by extending an existing class, the new derived class contains properties and methods that were defined in the original base class. Sometimes, the superclass features are not entirely appropriate for the subclass objects. Using the same method or property name to indicate different implementations is called polymorphism. You first learned the term polymorphism in Chapter 1; it means "many forms". In programming, it means that many forms of action take place, even though you use the same name. The specific method executed depends on the object.

Everyday cases provide examples of polymorphism:

+   * Both both are instruments and have a Play() method, a guitar is played differently than a drum.
* Both both are vehicles and have an Operate() method, a bicycle is operated differently than a truck.
* Both both are schools and have a SatisfyGraduationRequirements() method, a preschool's requirements are different from those of a college.

You understand each of these methods based on the context in which it is used. In a similar way, C# understands your use of the same name based on the type of object associated with it.

For example, suppose that you have created a Student class as shown in Figure 10-11. Students have names, credits for each credit, and tuition amounts. You can set a Student's name and credits by using the set accessors in the Name and Credits properties, but you cannot set a Student's tuition directly because the Tuition property has no set accessor. Instead, tuition is calculated on a standard RATE ($55.75) for each credit that the Student takes. In Figure 10-11, the Student fields that hold credits and tuition are declared as protected because child class will use them.
