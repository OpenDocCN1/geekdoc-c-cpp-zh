# Comparing Traditional and Object-Oriented Error-Handling Methods

You also create a catch block omitting the parentheses and Exception type. If you do, the catch block will execute when any Exception type is thrown. In other words, catch and catch(Exception) are both correct ways to start a catch block to all Exceptions when you do not want to name the Exception object you do not care about its details.

Figure 11-5 shows the general format of a try...catch. The placeholder XException in the catch block represents the Exception class or any of its more specific subclasses. The placeholder xxxException is the data type of the anExceptionInstance object. A catch block looks like a method named catch(), which returns an instance that is of xxxException. However, it is not a method; you cannot call it directly. A method can accept multiple arguments, but a catch block can catch only one object, unlike a method, a catch block has no return type.

As XException implies, Exception classes typically are created using Exception as the second half of the name, in SystemException and ApplicationException. The compiler does not require this naming, but the convention makes catch Exception descendants easier to identify.

```
try {
  // Any number of statements;
  // some might cause an exception
catch(XxxException anExceptionInstance) {
  // Do something about it
}
// Statements execute where there was an exception or not
```

**Figure 11-5** General form of a try...catch pair

You can place any number of statements in a try block, including those you will never throw an exception. If any of the statements you place within a try block throws an exception, then the statements in the catch block that catches the exception will execute. Either way, if no exception occurs within the try block, then the catch block does not execute. Either way, the statements follow the catch block normally.
