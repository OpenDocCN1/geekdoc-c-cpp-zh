Some of the properties listed in the Properties window have a small plus sign that appears to the left of the property. This is a node that you can click to expand or condense a property if you click the Size node, you will see an expanded list that displays the two parts of Size (width and Height). When the list is expanded, the node changes to a minus sign, which you can then click to condense the list.

When you sort Properties in alphabetical order in the Properties window, the Name entry is not in alphabetical order—it appears near the top of the list. Name appears in parentheses because the opening parenthesis has a lower value than an A, so if the Properties list is sorted in alphabetical order, Name is near the top and easy to find. (An opening parenthesis like Appendix B contains information about Unicode.) For most professional applications, you will want to provide a Form with a recognizable identifier that is more descriptive than Form.

Do not confuse a Form's Name with its Text property. If you change a Form's Name, you don't notice any difference in the visual design, but all references to the form are changed in the code. Therefore, a Form's Name is an identifier, and it must follow the rules for variable names without digit. This means, for example, that a Form's Text appears in its title, and it can be any string. For example, in an accounting application, you might name a form BudgetForm but assign 2018 Budget Calculator as its Text.

In Chapter 2, you learned to enclose a string in quotation marks. Although a Form's Text is a string, you do not type containing quotes when you enter a value for the Text property in the Properties list. However, when you view C#, you will see quotation marks around your Text value.

# Using the Toolbox to Add a Button to a Form

When you open the IDE, the left border displays a Toolbox tab. (If you don't see the tab, you can select View and then Toolbox from the IDE's menu bar.) When you open the Toolbox, a list of tool groups is displayed. The list automatically closes when you move your mouse off the list and click elsewhere, or you can pin the Toolbox to the screen to keep it opening by the pushpin icon at the top of the list. When you pin the Toolbox, the Form moves to the right to remain as visible as possible, depending on how you have sized the windows in the IDE. Selecting All Forms at the top of the Toolbox displays a complete list of available tools; selecting Controls displays a smaller list that is similar to the original one. As shown in Figure 3-4, the Toolbox contains many controls: the GUI users can click or manipulate. The list includes controls you probably have seen when using Windows applications—for example, Button and CheckBox. You can drag these controls onto the Form. This chapter features three of the other controls from the Toolbox—Label, Button, and TextBox. You will learn about more of the controls in the chapter “Using Controls”

All windows in Visual# can be dockable or floating, hidden or visible, can be moved to new locations. To change the behavior of a window, click the arrow or pushpin icon on the title bar, and select from the options available. You can customize many aspects of the IDE by clicking the Tools menu, then clicking Options. To restore the windows to their original states, click Window on the main Visual Studio menu bar, and then Reset Layout.

# Adding Functionality to a Button on a Form

Adding functionality to a Button is easy when you use the IDE. After you have dragged a Button onto a Form, you can double-click to create a method that executes when the user clicks the Button. For example, if you have dragged a Button onto a Form and have not changed its default name from button1, code is automatically generated when you double-click the button, as shown in Figure 3-6 (The windows in the figure have been redrawn their borders so that you can see more of it). You can view the Form Designer again by selecting View from the menu bar. Then, you can revert to the code window by selecting View and **Code**. As you create GUI applications, you will frequently switch back and forth between the visual environment and the code. Alternatively, you can use the tabs or press one of the shortcut keys on the drop-down menu to switch the view.

When double-click a button to generate a click method, generate code for the button's default event. Clicking a button is a default event because users typically expect to click a button. As you learn more about C#, you will find that you can create other events for a button. For example, if you want to take a specific action if you double-clicks or right-clicks a button.
