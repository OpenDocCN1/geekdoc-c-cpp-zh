In C#, you can use either new or override when defining a derived class member that has the same name as a base class, but you cannot use both together. When you write a statement such as ScholarshipStudent s1 = new ScholarshipStudent(); you won't notice the difference. However, if you use new when defining the derived class Credits property and write a statement such as S2 = new ScholarshipStudent(); (using Student as the type), s2.Credits accesses the base class property. On the other hand, if you use override when defining Credits in the derived class, s2.Credits uses the derived property.

In the child ScholarshipStudent class in Figure 10-12, the Credits property is declared with the override modifier (see shading) because it has the same header (that is, the signature—the same name and parameter list) as a property in its parent class. The Credits property overrides and hides its counterpart in the parent class. (You could do the same with methods.) If you omit override, the program will still operate correctly, but you will receive a warning that you are hiding an inherited member with the same name in the base class. Using the keyword override eliminates the warning and makes your intentions clear. When you use the Name property with a ScholarshipStudent object, a program uses the parent class Name; it is not hidden. When you use Credits to set a value for a ScholarshipStudent object, the program uses the, overriding property from its own class.

> > If Credits and tuition have been declared private within the Student class, ScholarshipStudent would not be able to use them.

You are not required to override a virtual method or property in a derived class; a derived class can simply use the base class version. A base class member that is not hidden by the derived class is visible in the derived class.
