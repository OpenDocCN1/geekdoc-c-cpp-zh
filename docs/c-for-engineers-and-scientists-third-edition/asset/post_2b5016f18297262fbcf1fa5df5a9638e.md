## 9.1 Exception Handling

The traditional C++ approach to error handling uses a function to return a specific value to indicate specific operations. Typically, a return value of 0 or 1 is used to indicate successful completion of the function's task, whereas a negative value indicates an error condition. For example, with a function used to divide two numbers, a return value of -1 would indicate that the denominator is zero, and the division can't be performed. When error conditions can occur, different return values can be used to indicate specific errors.

Although this approach is still available and often used, a number of problems can occur. First, the programmer must check the return value to detect whether an error occurred. Next, the error-handling code frequently becomes intermixed with normal processing code, so sometimes it becomes difficult to determine which part is handling errors. Finally, returning an error condition from a function means must be the same type as a returned value; hence, the error code must be a specified value that can be identified as an error alert. This means the error code is embedded as one of the possible nonzero values the function might require and is available only at the point where the function returns a value. In addition, a function returning a Boolean value has no error handling condition.

None of these problems are unreasonable, and many of the latest C++ compilers have added a technique designed for error detection and referred to as exception handling. With this technique, when an error occurs while a function is executing, an exception is created. An exception is a value, a variable, or object containing information about the error at the point it occurs. This exception is immediately passed, at the point it was generated, to code called the exception handler, which is designed to handle the error. The process of generating and passing the exception is referred to as throwing. The exception is thrown from within function while it's still executing, which permits handling the error and then returning back to the function so that it can complete its assigned.

In general, two fundamental types of errors can cause C++ exceptions: those resulting from a program's inability to acquire a required resource and those resulting from flawed data. Examples of the first type are attempt to obtain a system resource, such as locating and finding a file for input. These errors are the result of external resources over which the programmer has no control.

The second type of error occur when a program prompts the user to enter an integer, and the user enters a string, as c23, that can't be converted to a numerical value. Another example is the attempt to divide two numbers when the denominator has a 0 value, a condition referred to as a "division by zero error." These errors can always be checked and handled in a manner that doesn't result in a program crash. Before seeing how to use exception handling, review Table 9.1 to familiarize yourself with the terminology used with processing exceptions.

## Table 9.1 Exception-Handling Terminology

| Terminology | Description |
|--- |--- |
| Exception | A value, a variable, or an object that identifies a specific error that occurred while a program is executing |
| Throw an exception | Send the exception to a section of code that processes the detected error |
| Catch or handle an exception | Receive a thrown exception and process it |
| Catch clause | The section of code that processes the error |
| Exception handler | The code that throws and catches an exception |

## Chapter 9

Exception Handling

The general syntax of the code to throw and catch an exception is the following:

```
try {
  // one or more statements,
  // at least one of which should
  // be capable of throwing an exception
} catch(exceptionDataType parameterName) {
  // one or more statements
}
```

This example uses two new keywords: try and catch. The try keyword identifies the start of an exception-handling block of code. At least one of the statements inside the braces must be capable of throwing an exception. As example, examine the try block in the following section of code:

```
try {
  cout << "Enter the numerator (whole numbers only):";
  cin >> numerator;
  cout << "Enter the denominator (whole numbers only):";
  cin >> denominator;
  result = numerator/denominator;
}
```

The try block contains five statements, three of which might result in an error you want to catch. In particular, a professionally written program would make sure valid integers are entered in response to prompts and the second value is not a zero. For example, you just catch that the second value wasn't zero.
From the standpoint of the try block, only the value of the second number matters. The try block is altered to say "Try all statements within me to see if an exception occurs, which in this case is a zero value, occurs." To check if the second value is zero, you add a statement in the try block, as follows:

```
try {
  cout << "Enter the numerator (whole number only):";
  cin >> numerator;
  cout << "Enter the denominator (whole numbers only):";
  cin >> denominator;
  if (denominator == 0)
    throw denominator;
  else
    result = numerator/denominator;
}
```

In this try block, the thrown item is an integer value. A string literal, a variable, or an object could have been used, but only one of these items can be thrown by any throw statement. The first four statements in the try block don't have to be included in the code; however, doing so keeps all the relevant statements together. Keeping related statements together makes it easier to add statements in the same try block to ensure that input values are integers.

A try block must be followed by one or more catch blocks, which serve as handlers for any exception thrown by the try block. Here's a catch block that handles the thrown exception, which is:

```
catch(int e)
{
    cout << "A denominator value of " << e << " is invalid." << endl;
    exit(1);
}
```

The exception handling this catch block provides is an output statement that identifies the caught exception and terminates execution. Note the parentheses are the data type of the exception following the catch keyword and a parameter name used to receive the exception. This parameter, which is a programmer-selected identifier to hold the exception value generated when an exception is thrown.

Multiple catch blocks can be used as long as each catch block matches a unique data type. The only requirement is providing at least one catch block for each try block. The more exceptions that can be caught with the same try block, the better. Program 9.1 provides a complete program that includes a try block and a catch block to detect a division by zero.

## Program 9.1

```cpp
#include <iostream>
using namespace std;

int main() {
    int numerator, denominator;

    try {
        cout << "Enter the numerator (whole number only): ";
        cin >> numerator;
        cout << "Enter the denominator (whole numbers only): ";
        cin >> denominator;

        if (denominator == 0)
            throw denominator; // an integer value is thrown
        else
            cout << numerator << '/' << denominator;
            cout << " = " << (double)numerator)/ double(denominator) << endl;
    } catch(int e) {
        cout << "A denominator value of " << e << " is invalid." << endl;
        exit(1);
    }

    return 0;
}
```

Instead of terminating program execution when a zero denominator is detected, more robust program can give the user the opportunity to reenter a non-zero value. To do this, the try block is included in a while statement, and then the catch block returns control to the while statement after informing the user that a zero value has been entered.
