## A A Closer Look: Programming Errors

The ideal in programming is to produce readable, error-free programs that work correctly and can be modified with a minimum of testing. To achieve this, keep in mind the different types of errors that occur, when they are usually detected, and how to correct them. You can detect an error at any of the following times:

- Before a program is compiled
- While the program is being compiled
- While the program is running
- After the program has been executed and the output is examined

The method for detecting errors before a program is compiled is desk checking because you are usually sitting at a desk with the code in front of you. It refers to the process of examining the source code for mistakes immediately after you type it.

Errors detected while the program is being compiled are compile-time errors, and errors that occur while the program is running are runtime errors. Other names for compile-time errors are syntax errors and parse errors, that emphasize the type of error the compiler detects.

By now, you have probably encountered numerous compile-time errors. Beginners tend to be frustrated by them, experienced programmers understand the compiler is just valuable, and correcting errors is usually easy. These errors occur while the program is being developed, not while a user is performing an important task, but none the programmer ever knows them. You fix them, and they go away.

Runtime errors are more troubling because they occur while a user is running the program; in most commercial systems, the user isn't the programmer. Many types of errors can cause a runtime error, such as a hardware failure. From a programming standpoint, however, most runtime errors are referred to as logic errors or faulty logic, which encompasses not analyzing what the program should do or anticipating how users use the program. For, if a user enters data that results in an attempt to divide a number by zero, a runtime error occurs.

As a programmer, the only way to protect against runtime errors is to anticipate everything a person might do errors and submit your program to rigorous testing. Beginning programmers tend to blame users for an error caused by entering incorrect data, but professionals don't. They understand that a runtime error is a flaw that can damage the reputation of the program and programmer.

To prevent compile-time and runtime errors, it is more fruitful to determine what causes them. As mentioned, compile-time errors are also called syntax errors: mistakes in the structure or spelling of a statement. For example, examine the following statements:

```
cout << "There are four syntax errors here\n* Can you find them";
```

They contain the following syntax errors:

- 1. A closing quotation is missing in line 1.
- 2. A semicolon ; is missing in line 1.
- 3. The keyword cout is misspelled in line 2.
- 4. The insertion operator, <<, is missing in line 2.

When the program is compiled, the compiler detects all these errors because they're syntax errors that violate the basic rules of C++. If they aren't detected by desk checking, the compiler detects them and displays an error message. Sometimes the error message is clear and obvious; at other times, understanding the compiler's error message takes a little effort. Because syntax errors are the only type that can be detected at compile time, "compiler errors" and "syntax errors" are used interchangeably. Strictly speaking, compiler refers to when the error is detected, and syntax refers to the type of error detected.

The misspelling of "them" in the second statement is not a syntax error. Although this spelling error results in a undesirable output line, it's not a violation of C++s rules. It's a typographical error, commonly referred to as a "typo". The compiler doesn't catch this type of error.

Another error the compiler can't detect is a logic error, which can cause a runtime error or produce incorrect results. These errors are characterized by unexpected, or unintended output that is a direct result of failure in the program's logic. These errors can be detected by desk checking, by testing, or when a user gets erroneous output while the program is executing, or not at all. If the error is detected while the program is executing, a runtime error can occur that generates an error message, causes the program to terminate.

The most serious errors are caused by not fully understanding the program requirements because logic reflects the logic of which it's coded. For example, if a program's purpose is to make the calculation, what inputs are needed to perform the calculation, or what special conditions exist (such as temperature affects the beam), a logic error occurs.
