If the optional argument, `terminatingChar`, is omitted when getline() is called, the default terminating character is the newline ('\n') character. Therefore, the statement `getline(cin, message, '\n')` can be used in place of the statement `getline(cin, message);`. Both these stop reading characters when the Enter key is pressed. In all the programs used from this point forward, input is terminated by pressing the Enter Key, which generates a newline character. For this reason, the third argument passed to `getline()`, which is the terminating character, is omitted.

**Caution: The Phantom Character** Seemingly strange results can happen when the cin input stream object and getline() are used together to accept data or when cin is used by itself to accept characters. To see how this result occur, take a look at Program 9.8, which uses cin to accept an integer entered at the keyboard. The integer is stored in the variable value, and a getline() function follows.

# Program 9.8

![](bbox=[0.106, 0.353, 0.183, 0.407])

```
#include <iostream>
#include <string>
using namespace std;

int main()
{
    int value;
    string message;

    cout << "Enter a number: ";
    cin >> value;
    cout << "The number entered is:\n"
         << value << endl;

    cout << "Enter text:\n";
    getline(cin, message);
    cout << "The text entered is:\n"
         << message << endl;
    cout << int(message.length()) << endl;

    return 0;
}

```

When Program 9.8 runs, the number entered in response to the prompt Enter a number: is stored in the variable value. At this point, everything seems to be working fine. Notice, however, that in entering a number, you enter the number and press the Enter key.
