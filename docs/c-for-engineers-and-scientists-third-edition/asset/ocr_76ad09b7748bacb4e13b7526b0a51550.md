If logic errors are detected, typically they’re revealed in one of two ways. First, the program executes to completion but produces incorrect results, such as the following:

+   - No output—This result is caused by omitting an output statement or using a sequence of statements that inadvertently bypasses an output statement.
- Unappealing or misaligned output—This result is caused by an error in an output statement.
- Incorrect numerical results—This result is caused by assigning incorrect values to variables in an expression, using an incorrect arithmetic expression, omitting a statement, making a round-off error, or using an improper sequence of statements.

Second, a runtime error occurs. Examples of logic errors that cause this result are attempt to divide by zero or to calculate the square root of a negative number.

Plan your program testing carefully to maximize the possibility of locating errors. In addition, remember although a single test can reveal the presence of an error, it does not verify that any error is lurking elsewhere in the program. Furthermore, the fact that one test revealed no errors does not mean there are no errors.

After you discover an error, however you must locate where it occurs and how to fix it. In computer jargon, a program runs line by line, and the process of isolating, correcting and verifying the correction is called debugging.

Although no hard-fast rules exist for isolating the cause of an error, some useful techniques can be applied. The first is prevent. Often programmers introduce errors in the code and run a program before what’s required and how to achieve the result, as many errors can be eliminated by desk checking the program before executing or compiling it.

A useful technique is using the computer by executing each statement by hand as the computer. This technique, program tracing, involves writing down each variable, as it’s encountered in the program, and listing the value that should be stored in the variable as each input and assignment statement is encountered. This sharpens your programming skills because it helps you understand what each statement in your program causes to happen.

A third technique is including some temporary code in your program that displays the values of selected variables. If the displayed values are incorrect, you can determine what part of your program generated them and make the necessary corrections. You could also add temporary code that displays the values of all input data. This technique, called printing, is useful in establishing that your program is receiving and returning input correctly.

The most powerful technique is using a special program called a debugger. A debugger can control the execution of a C++ program, the C++ program at any point in its execution, and display the values of all variables at the point of interest.

Finally, no discussion is complete without mentioning the mental insight needed for isolating and correcting errors successfully the task. After you write a program, you naturally assume it’s correct. Taking a step back to be objective testing and finding errors in your own software is difficult. As a programmer, you must remind yourself that because you think your program is correct doesn't make it so. Finding errors in your own programs is a sobering experience but one that helps you become a better programmer. The process can be exciting and if you approach it as a detection problem, with you as the master detective.
