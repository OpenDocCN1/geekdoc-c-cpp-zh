
# Chapter 6## Storage Categories

Variables of type auto and register are always local variables. Only non-static global variables can be declared using the extern keyword. Doing so extends the variable's scope into another file or function. Static variables cannot use the extern keyword. Except for static variables, variables are initialized each time they come into scope; static variables are initialized only once when they are defined. The actual storage for the variable must be somewhere else in the program by using one declaration statement which the extern has not been used. Initialization in a declaration statement is not allowed and causes a compilation error.

The existence of the extern storage category is the reason for carefully distinguishing between the creation and declaration of a variable. Declaration statements containing the extern word do not create storage areas; they only extend the scope of global variables. The last storage category, static, is to prevent extending a global variable into another file. Global variables are declared in the same way as local variables, except the declaration statement is placed outside any function. The scope of a static variable can't be extended beyond the file in which it is declared. Because they are "known" and can be used only in the file where they are declared, other files cannot access or change their values. Therefore, static variables can't be extended to a second file by using an extern statement. Trying to do so results in a compilation error.

## 6.7 Common Programming Errors

The following programming errors are common when constructing and using functions:

1. Passing incorrect data types to a function. The values passed to a function must correspond to the data types declared for the function. One way to verify that correct values have been received is to display all passed values in the function body before any calculations are made. After this verification has taken place, you can dispense with the display.
2. Another common error can occur when the variable is declared locally in both the calling and called functions. Even though the variable name is the same, a change to one local variable does not alter the value in the other variable.
3. A related error is one that can occur when a local variable has the same name as a global variable. Inside the function declaring it, the variable's name affects only the local variable's contents unless the scope operator `::` is used by the calling function.
4. Another common error is omitting the called function prototype or matching the calling function to the type of value to be returned; the function prototype provides this information. The prototype can be omitted if the called function is placed in a program before its calling function. Although omitting the prototype and return type for functions returning an integer is permitted, doing so is poor practice. The actual value a function returns can be verified by displaying it both before and after it is returned.
5. The last two common errors are terminating a function header with a semicolon and forgetting to include the data type of a function's parameters in the function header.

In practice, a good debugger program should be used.

## 6.8 Chapter Summary

1. A function is called by giving its name and passing any data to it in the parentheses following the name. If a variable is one of the arguments in a function call, the called receives a copy of the variable's value.
2. The common form of a user-written function is as follows:

```cpp
return dataType functionName(parameter list)
{
    // declarations and other C++ statements;
    return expression;
}
```
The first line of the function is the function header. The opening and closing braces of the function and all statements between these braces constitute the function body. The returned data type is, by default, an integer when no returned data type is specified. The parameter is a comma-separated list of parameter declarations.
3. A function's type is the data type of the function returns. If no type is declared, the function is assumed to return an integer value. If the function doesn't return a value, it should be declared as a void type.
4. Functions can return at most a single data type value to their calling functions. This is the value of the expression in the return statement.
5. Arguments passed to a function, when it is called, must conform to the parameters specified by the function header in order, order of arguments, and data type.
6. Using reference parameters, a variable's address is passed to a function. If a function is passed as an address, it has the capability to access the calling function's variable. Using addresses permits a function to return multiple values.
7. Functions can be declared to all calling functions by a means of prototype. The prototype provides a declaration for a function that specifies the data type the function returns, the function's name, and the data types of the arguments it expects. With all declarations, a function is prototyped with a semicolon and can be included in local variable declarations or as a global declaration.

```cpp
dataType functionName(parameter data type list);
```
If the function is placed above the calling function in the program, no further declaration is required because the function serves as a global declaration to all subsequent functions.
