## 647 Class Inheritance

### Point of Information

**Object-Based Versus Object-Oriented Languages**

In an object-based language, data and operations can be incorporated together in such a way that data values can be isolated and accessed through the specified class functions. The capability to bind data members with operations in a single unit is referred to as encapsulation. In C++, encapsulation is provided by its class capability.

For a language to be classified as object-oriented it must also provide inheritance and polymorphism. As discussed, inheritance is the ability to derive one class from another. A derived class incorporates all the data members and member functions of the parent class and can add its own data and function members. Polymorphism permits using the same function name to call one operation in a parent class's objects and a different operation in a derived class's objects.

C++, provides encapsulation, inheritance, and polymorphism, which is a true object-oriented language. Because C, is C++s predecessor, doesn't provide these features, it is not an object-based or object-oriented language.

Except for the access-specifier after the colon and the base class name, there is nothing new or complicated about the construction of the Cylinder class. Before providing a description of the Circle class adding data and function members to the Cylinder class, you need to reexamine access specifiers and how they relate to derived classes.

## Access Specifications

Now you use only private and public access specifiers in a class. Giving all data members status ensures that they can be accessed by class member functions or friends. This restricted access prevents access by nonclass functions (except friends) is sensible because without it, anyone could bypass the private restriction by deriving a class.

To retain access across derived classes, C++ provides a third specification—protected. A **protected** access behaves as private access, in that it permits access only to class member functions, but it permits any derived class to inherit this restriction. The derived class then defines what type of inheritance it's taking on, subject to the base class access specifier. This is is done by the class member specifier, which is listed at the start of the class declaration section. Table 11.3 lists the derived class member resulting from the base class member specifications and the derived class-access specifier.

The shaded region in Table 11.3 shows that if the base class has a protected and the derived class member is protected to its class. Similarly, if the base class has a public access and the derived class-access specifier is public. These specifications for base class data members are the most commonly used, so are the ones used in this section. For all classes intended for use as a base class, a protected member access is used instead of a private designation.

|---|---|---|
| private | private | inaccessible |

| public | private | private |

### An Example To understand the process of deriving one class from another, examine deriving a Cylinder class from a base Circle class. The definition of the Circle class is as follows:

```cpp
// class declaration section
class Circle
{
protected:
    double radius;
public:
    Circle(double r = 1.0); // constructor
    double calcalc();
};

// class implementation section
Circle::Circle(double r)
{
    radius = r;
}

// calculate the area of a circle
double Circle::calcalc()
{
    return(PI * radius);
}
```

Except for substituting the access specifier in place of the usual private specifier for the data member, this code is a standard class definition. The only variable not defined is PI, which is used in the calcalc() function. It’s defined as follows:

```cpp
const double PI = 2.0 * asin(1.0);
```

This definition is simply a “trick” that forces the computer to return the value of PI accurate to as many decimal places as your computer allows. This value is obtained by taking the arcsin of 1.0, which is π/2, and multiplying the result by 2.

Having the base class, you can now extend it to a derived class, which has this definition:

```cpp
// class declaration section where Cylinder is derived from Circle
class Cylinder : public Circle
{
  protected:
    double length; // add one additional data member
  public:
    // two additional member functions
    Cylinder(double r = 1.0, double l = 1.0) : Circle(r), length(l) {}
    double calcval();
};
```

```cpp
// class implementation section
Cylinder::calcval() // this calculates a volume
  return (length * Circle::calcval());
}
```

This definition encompasses several important concepts related to derived classes. First, as der derived class, Cylinder contains all the data members and member functions of its base class, Circle, plus any of its members it adds. In this case, the Cylinder class consists of radius data member, inherited from the Circle class, plus a length data member. Therefore, each Cylinder object contains two data members, as shown in Figure 11.8.

Figure 11.8 Relationship between Circle and Cylinder data members

In addition, the Cylinder class inherits Circle's member functions. This inheritance is shown in the Cylinder constructor, which uses a base/member initialization list (see Section 11.1) that calls the Circle constructor. It's also shown in Cylinder's calcval() function, which makes a call to Circle::calcval().

In both classes, the same function name, calcval(), has been used to illustrate overriding a base function with a derived function. When a Cylinder object calls calcval(), it's a request to use the Cylinder version of the function; a Circle object call to calcval() is a request to use the Circle version. In this case, the Cylinder class can access only the Circle version of calcval() by using the scope resolution operator, as in the call Circle::calcval(). Program 11.14 uses these two classes in the context of a complete program.

## 650 Class Functions and Conversions

### Program 11.14

```cpp
#include <iostream>
#include <cmath>
using namespace std;

const double PI = 2.0 * asin(1.0);

// class declaration section
class Circle
{
protected:
    double radius;
public:
    Circle(double r = 1.0); // constructor
    double calcalc();
};

// class implementation section
Circle::Circle(double r)
{
    radius = r;
}

// calculate the area of a circle
double Circle::calcalc()
{
    return(PI * radius);
}

// class declaration section where Cylinder is derived from Circle
class Cylinder : public Circle
{
  protected:
    double length; // add one additional data member
  public:
    // two additional member functions
    Cylinder(double r = 1.0, double l = 1.0) : Circle(r), length(l) {}
    double calcval();
};

// class implementation section
Cylinder::calcval() // this calculates a volume
{
  return (length * Circle::calcval());
}

int main()
{
    Circle circle_1, circle_2(2); // create two Circle objects
    Cylinder cylinder_1(3,4); // create one Cylinder object

    cout << "The area of circle_1 is " << circle_1.calcalc() << endl;
    cout << "The area of circle_2 is " << circle_2.calcalc() << endl;
    cout << "The volume of cylinder_1 is " << cylinder_1.calcval() << endl;

    circle_1 = cylinder_1; // assign a Cylinder to a Circle

    cout << "\nThe area of circle_1 is now " << circle_1.calcalc() << endl;
    return 0;
}
```

The first out lines are straightforward and are produced by the first three statements in the program. As the shows, a call to calcalc() with a Circle object activates the Circle version of this function, and a call to calcalc() with a Cylinder activates the Cylinder version of this function.

The assignment statement circle_1 = cylinder_1; introduces another important relationship between a base and a derived class: A derived class can be assigned to a base class object. This relationship shouldn't be surprising because base and derived classes share a common set of data members. In this type of assignment, only set of data members, which consists of all the base class data members, is assigned. Therefore, as illustrated in Figure 11.9, the Cylinder to Circle assignment results in the following memberwise assignment:

```cpp
circle_1.radius = cylinder_1.radius;
```
