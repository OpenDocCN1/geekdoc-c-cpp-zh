# 9.1 Exception Handling

The traditional C++ approach to error handling uses a function to return a specific value to indicate specific operations. Typically, a return value of 0 or 1 is used to indicate successful completion of the function's task, whereas a negative value indicates an error condition. For example, with a function used to divide two numbers, a return value of -1 would indicate that the denominator is zero, and the division can't be performed. When error conditions can occur, different return values can be used to indicate specific errors.

Although this approach is still available and often, a number of problems can occur. First, the programmer must check the return value to detect whether an error occurred. Next, the error-handling code frequently becomes intermixed with normal processing code, so sometimes it becomes difficult to determine which part is handling errors. Finally, returning an error condition from a function means must be the same type as a returned value; hence, the error code must be a specified value that can be identified as an error alert. This means the error code is embedded as one of the possible nonzero values the function might require and is available only at the point where the function returns a value. In addition, a function returning a Boolean value has no error handling condition.

None of these problems are unreasonable, and many the latest C++ compilers have added a technique designed for error detection and referred to as exception handling. With this technique, when an error occurs while a function is executing, an exception is created. An exception is a value, a variable, or object containing information about the error at the point it occurs. This exception is immediately passed, at the point it was generated, to code called the exception handler, which is designed to handle the error. The process of generating and passing the exception is referred to as throwing. The exception is thrown from within function while it's still executing, which permits handling the error and then returning back to the function so that it can complete its assigned.

In general, two fundamental types of errors can cause C++ exceptions: those resulting from a program's inability to acquire a required resource and those resulting from flawed data. Examples of the first type are attempt to obtain a system resource, such as locating and finding a file for input. These errors are the result of external resources over which the programmer has no control.

The second type of error occur when a program prompts the user to enter an integer, and the user enters a string, as c23, that can't be converted to a numerical value. Another example is the attempt to divide two numbers when the denominator has a 0 value, a condition referred to as a "division by zero error." These errors can always be checked and handled in a manner that doesn't result in a program crash.
