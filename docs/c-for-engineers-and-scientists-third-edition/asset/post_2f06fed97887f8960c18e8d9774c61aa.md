# Values and Identities

Apart from object behaviors, a characteristic feature of objects shared with variables are they always have a unique identity. An object's identity is what permits distinguishing one from another. This feature is not true of value, such as the number 5, because all occurrences of 5 are indistinguishable from one another. Therefore, values are not considered objects in object-oriented programming languages, such as C++.

Another difference between an object and a value is that a value can never be a container whose value can change, but an object clearly. A value is simply an entity that stands for itself.

Now consider a string as "Chicago". It's a value. However, because Chicago could also be a specific and identifiable object of the class City, the context in which the name is used is important. If the string "Chicago" is assigned to an object's name attribute, for example, it reverts to a value.

# Base/Member Initialization³

Except for the reference names olddate and newdate, a comparison of Program 11.3's copy constructor to Program 11.2's assignment operator show them to be essentially the same. The difference is that the copy constructor first creates an object's data members before using assignment to specify member values. Therefore, the constructor does not perform a true initialization, but a creation followed by assignment.

A true initialization has reliance on assignment which is possible in C++ by using the base/member initialization list. This list is used and only to constructor functions and can be written in two ways. The first way is inside a class's declaration section in this form:

```
ClassName(argument list) : list of data members(initializing values)
```

Here's an example of a default constructor performing true initialization in this form:

```cpp
// class declaration section
public:
Date(int mo = 4, int da = 1, int yr = 2006) : month(mo), day(da), year(yr) {
```

The second way is to declare a prototype with the class declaration section followed by the initialization list in the class implementation section. For the Date constructor, it takes this:

```cpp
// class declaration section
public:
Date(int mo = 4, int da = 1, int yr = 2006); // prototype with defaults

// class implementation section
Date::Date(int mo, int da, int yr) : month(mo), day(da), year(yr) {
```

# 11.2 Additional Class Features

This section covers additional features of classes, defining the scope of a class, creating static members, and granting access privileges to own functions. Each of these topics can be read independently.

# Class Scope

You learned about local and global scope in 6.5. As you saw, the scope of a variable defines the portion of a program where it can be accessed. For local variables, scope is defined by any brace pair, {}. This block includes the function body and any subclasses. Additionally, all parameters of a function are considered local variables.

Global variables can be accessed from their point of declaration throughout the remainder of the file, with three exceptions:

- If a local variable has the same name as a global variable, the global variable can be accessed only in the local variable's scope by using the resolution operator, ::
- A global variable's scope can be extended into another file by keyword extern.
- The same name can be reused in another file to define a separate and distinct variable by the keyword static.

In addition to local and global scope, each class defines an associated scope. That is, names of data and function members are local to the scope of their class. Therefore, if a global variable is reused in the same class, the global variable is hidden by the class member in the same way that a local variable hides a global variable. Similarly, function names are local to the class they're declared and can be used only by objects declared for the class. Additionally, local function variables hide the names of class variables. Figure 11.2 illustrates the scope of variables and functions for the following declarations:

```
double rate; // global scope
// class declaration section
{
  private:
    double amount, total; // class scope
  public:
    double extend(double, double); // class scope
};
```
