## Misuse of Globals

Global variables allow programmers to "jump around" the normal safeguards provided by functions. Instead of passing variables to a function, it is possible to make all global variables global. Do not do this. By indiscriminately making all global variables, you destroy the safeguards C++ provides to make functions independent and insulated from each other, including carefully designating the type of arguments a function needs, the variables used in the function, and the value returned.

Using only global variables can be disastrous in large programs with many user-created functions. Because all variables in a function must be declared, creating functions that use global variables requires remembering to write the appropriate global variables at the top of each program using the function—they no longer come with global variables. Devastating, however, is trying to track an error in a large program because a global variable can be accessed and changed by any function following the global declaration, locating the origin of an erroneous value is a time-consuming and frustrating task.

Global definitions are sometimes used in creating variables and constants that must be shared between many functions. Instead of passing the same variable to each function, defining the variable once as global is easier. Doing so also alerts anyone reading the program that many functions use the variable. Large programs almost always make use of a few global variables or constants. Smaller programs containing a few functions, however, should almost never contain global variables.

The misuse of globals doesn't apply to function prototypes, which are typically global. All the function prototypes you have used have been of global scope, which declares the prototype to all subsequent functions. Placing a function prototype in a function makes the prototype a local declaration, which makes it available only to the function it declared within.

## 6. Variable Storage Categories

The scope of a variable defines the location in program where it can be used. If you draw a box around the section of code where a variable is valid, the space inside the box represents the variable's scope. In addition to the space defined by scope, variables have a time dimension that refers to how long storage locations are kept. This time dimension is referred to as the variable's lifetime.

Beyond a type of data type and scope, every variable has a storage category. The four available storage categories are auto, static, extern, and register. If one of these category names is used, it must be placed before the variable's data type in a declaration statement. The following are examples of declaration statements that include a storage category:

```cpp
auto int num; // auto storage category and int
static int miles; // static storage category and int
register int dist; // register storage category and int
extern int volts; // extern storage category and int
auto float coupon; // auto storage category and float
static double yrs; // static storage category and double
extern float yield; // extern storage category and float
auto char inKey; // auto storage category and char
```

## Local Variable Storage Categories

Local variables can be members only of the auto, static, or register storage categories. If no category description is included in the declaration statement, the variable is assigned to auto automatically, so auto is the default C++ uses. All the local variables you have used have been auto variables because the storage category designation was omitted.

The term auto is short for "automatic". Storage for automatic local variables is reserved or created each time a function declaring variables is called. As long as the function hasn't returned to its calling function, all automatic variables to the function are "alive"—meaning storage for the variables is active. When the function returns to its calling function, its automatic variables "die"—meaning storage for the variables is released back to the computer. This happens each time a function is called. For example, in Program 6.17, the testauto() is called three times from main().
