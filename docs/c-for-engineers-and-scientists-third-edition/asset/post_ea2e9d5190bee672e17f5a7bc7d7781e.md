## 14.3 Refinements to the Bisection Method

The bisection method described in Section 14.2 presents the basics on which most root-finding methods are constructed. This brute-force method is rarely used in practice because for almost any, an alternative method that's faster, more accurate, and only slightly more complex is available. All refinements of the bisection method that might be devised on attempts to use as much information as available as the function's behavior at each iteration. In the ordinary bisection method, the only feature of the function that's monitored is its sign. Therefore, if you're searching for roots of the function

```
$f(x) = e^x - \sin(\sqrt{2}\pi x)$
```

you begin the search, in Section 14.1, by stepping along the x-axis and watching for a change in sign of the function, follows:

| i | x_i | f(x_i) |
|---|---|---|
| 0 | 0.0 | 2.0 |
| 1 | 0.1 | 1.33 |
| 2 | 0.2 | 0.75 |
| 3 | 0.3 | 0.29 |
| 4 | 0.4 | -.05 |

The next step in the bisection method is reducing the step size by half; that is, $x_5 = 0.35$. However, from the magnitude of the preceding numbers, you would expect the root to be closer to 0.4 than 0.3. Using information about the size of the functional value in addition to its sign, you can speed up the convergence. In this example, you might interpolate the root to be approximately

> $\frac{0.29 - 0.0}{f_3 - f_4} = 0.853$

of the distance $x_3 = 0.3$ to $x_4 = 0.4$ or $x_5 = 0.3853$. Continuing in this manner and interpolating at each step, you get the following results:

| i | x_i | f(x_i) |
|---|---|---|
| 3 | 0.30 | 0.29 |
| 4 | 0.40 | -0.05 |
| 5 | 0.385 | -0.0083 |
| 6 | 0.3823 | -0.0013 |
| 7 | 0.3819 | -0.00019 |
| 8 | 0.38185 | -0.000028 |
| 9 | 0.38184 | -0.000004 |

Comparing these results with the bisection method applied to a similar function in Section 14.2, you can see that the convergence rate for this method is much faster. The next task is to formalize this procedure into a method suitable for a general function.

## Regula Falsi Method

The basic idea in the refinement of the bisection method is that it's essentially the same as bisection, except instead of using the interval's midpoint at each step of the calculation, you use an interpolated value for the root. This method is illustrated in Figure 14.3. In this figure, a root is known to exist in the interval $(x_1 \leftrightarrow x_3)$, and in the drawing, $f_1$ is negative, and $f_3$ is positive. The interpolated position of the root is $x_2$. Because the two triangles ABC and CDE are similar, the lengths of the sides are related by

```
$$\frac{DE}{AB} = \frac{x_2 - x_1}{f_3 - f_1}$$
```

or which can be solved for the unknown position $x_2$ to yield the following:

```
$x_2 = x_1 - (x_3 - x_1) \frac{f_1}{f_3 - f_1}$
```

![](img/e2a849fc7bc04aa2e6669ad865e0c22b_781_0.png)

This value of $x_2$ replaces the midpoint used in the bisection method, and the rest of the procedure remains the same. Therefore, the next step is determining whether the actual root is to the left or the right of $x_2$, as before:

- If $f_1 \times f_2 < 0$, then the root is on the left.
- If $f_2 \times f_3 < 0$, then the root is on the right.

In the figure, the root is to the left of $x_2$, so the interval used for the next iteration is

```
$x_3 = x_2$
$f_3 = f_2$
$f_2 = f(x_2)$
```

In other words, to use this slightly faster bisection algorithm, the only change that has to be made to the previous bisection code is replacing statements of the form

```
$x_2 = (x_1 + x_2) / 2$
```

by a statement of this form:

```
$x_2 = x_1 - (x_2 - x_1) \frac{f_1}{f_1 - f_2}$
```

This method is still guaranteed to obtain a root eventually and almost always converges faster than the conventional bisection method. However, you pay a small price. The value of $f_1$ and $f_2$ in using for $x_i$ might be nearly equal, and you could be plagued by round-off errors in their difference. In the bisection method, you could predict with some precision the number of iterations required to find the root to a certain accuracy (see Section 14.1). This prediction is no longer possible if you use the interpolated values, so the code must include a check for excessive iterations.

This method shows that a change in the algorithm, which is based on more intelligent monitoring of the function, can reap considerable rewards in more rapid convergence. The formal name of this method is the **regula falsi method** (the method of false position).

Notice that in Figure 14.4, if the function is concave downward, the interval does not diminish significantly. If the function were concave upward, the converse would be true. The drawback of regula falsi method is that it doesn't necessarily result in a value of $f(x)$ that is "small". The point, however, is that successive iterations result in small changes to the interval, so continuing the process is not necessarily productive.

## Modified Regula Falsi Method

Perhaps the method can be made faster. The alternatives to the bisection code in 14.1 are incorporated into Program 14.2. The code in 14.2 requires some explanation, however:

1. The function(x) is evaluated only once per cycle. If the function is complicated and, therefore, costly to compute, this method of efficiency is often a deciding factor in choosing.
2. The code can terminate in three ways:
   - One success pass: The current fractional size of the interval—that is, (current interval) / (original interval)—is less than the user-supplied tolerance. If so, the program's original aim to bring a root nearly has been achieved. There's no guarantee that this criterion will result in a value of $f(x)$ that is 'small'. The point, however, is that successive iterations result in small changes to the interval, so continuing the process is not necessarily productive.
   - Two failure paths: If the number of iterations is greater than $Imax$, the maximum number of iterations specified by the programmer, the program stops. This allows the programmer to specify the maximum cost accepted for an attempted solution. Because the number of iterations is unpredictable in the regula and modified regula methods, this safeguard is essential. It is also a present precaution against errors in constructing the program that could cause it to run forever and not find a root.
2. If the function does not change sign ($f_i \times f_x > 0$), the process is stopped. Because the original interval is known to contain a root, the only way this condition can happen is by error. Usually, the error is in the code for the function $f(x)$; that is, you're attempting to find a root of a function different from the one intended.

Using this algorithm, the slope of the line is reduced *artificially*. The alternatives of the bisection method combined with regula falsi is known as **modified regula falsi method**.
