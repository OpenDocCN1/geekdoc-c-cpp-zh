## A Closer Look: Searching and Sorting

The value of using a binary search algorithm is that the number of elements that must be searched is cut in half each time through the while loop. The first time through the loop, n elements must be searched; the second time through the loop, n/2 of the elements have been eliminated and $n/2$ remain. The third time through the loop, another half of the remaining elements has been eliminated, and so on.

In general, after $p$ passes through the loop, the number of elements remaining to be searched is $n/2^p$. In the worst case, the search can continue until less or equal to one element remains to be searched. Mathematically, this procedure can be expressed as $n/2^p = 1$. Alternatively, it can be the smallest integer such that $2^p > n$. For example, for a 1000-element array, $n$ is 1000 and the maximum number of passes, $p$, required for a binary search is 10. Table 7.3 compares the number of loop passes for a linear and binary search for different list sizes.

### Table 7.3 A Comparison of Loop Passes for Linear and Binary Searches

| Array size | 10 | 50 | 500 | 5000 | 50,000 | 500,000 | 5,000,000 | 25,000,000 |
|---|---|---|---|---|---|---|---|---|
| Average linear search | 5 | 25 | 250 | 2500 | 25,000 | 250,000 | 2,500,000 | 25,000,000 |
| Maximum linear search | 10 | 50 | 500 | 5000 | 50,000 | 500,000 | 5,000,000 | 50,000,000 |
| Maximum binary search | 4 | 6 | 9 | 13 | 16 | 19 | 23 | 26 |

As shown, the maximum number of loop passes for a 50-item list is 10 times more for a linear search than binary search, and even more spectacular for larger lists. As a rule of thumb, 50 elements are generally used as the switch-over point: for lists smaller than 50 elements, linear searches are acceptable; for larger lists, binary search should be used.

## Big O Notation

On average, a large number of linear searches with $n$ items in a list, you would expect to examine $n/2$ of the items before locating the desired item. In a binary search, the maximum number of passes, $p$, occurs when $n/2^p = 1$. This relationship can be manipulated algebraically to $p = \log_2 n$, which approximately equals $3.33 \log_{10} n$.

For example, finding a particular name in an alphabetical dictionary with $n = 1000$ names requires an average of 500 ($n/2$) comparisons using a linear search. With a binary search, only about 10 ($\approx 3.33 \times \log_{10} 1000$) comparisons are required.

A common way to express the complexity of comparisons in any search algorithm using a list of $n$ items is to give the order of magnitude of the comparisons required to locate a desired item. Therefore, the linear search is said to be of order $n$ and the binary search of order $\log n$.

### Sorting Algorithms

Two major categories of sorting techniques, internal and external sorts, are available. Internal sorts are used when the data can be accommodated in computer's memory. External sorts are used for larger datasets that cannot be accommodated in memory, typically stored on disk or files.

For example, take the sort shown in Figure 7.15. The first pass through the list results in the smallest value being de exchanged with the first element. The second pass selects the next smallest value and exchanges it with the second element. This continues until the list is sorted.

```c
int selectionSort(int num[], int numel) {
    int i, j, min, minix, temp, moves = 0;

    for (i = 0; i < numel - 1; i++) {
        min = num[i];
        for (j = i + 1; j < numel; j++) {
            if (num[j] < min) {
                min = num[j];
                minix = j;
            }
        }
        if (minix != i) {
            temp = num[i];
            num[i] = num[minix];
            num[minix] = temp;
            moves++;
        }
    }
    return moves;
}
```

Program 7.14 was constructed to test selectionSort(). Program implements a selection sort for the list of 10 items used to test the algorithms. For comparison to other sorting algorithms, the actual number of moves the program makes to get data into sorted order is counted.

The output Program 7.14 produces as follows:

The sorted list, in ascending order, is:
5 10 22 32 45 67 73 98 99 101
8 moves were made to sort this list

Clearly, the number of moves displayed on the initial order of values in the list is the maximum number that must be n-1, where n is the number of items in the list. Further, each move is a final move that results in an element in its final location in the sorted list.

A disadvantage of the selection sort is that n(n-1)/2 comparisons are always required, regardless of the initial arrangement of the list. This number of comparisons is obtained as follows: The last pass requires one comparison, the next-to-pass requires two comparisons, and so on, to the first pass, which requires n-1 comparisons. Therefore, the total number of comparisons is

```
1 + 2 + 3 + ... + n - 1 = n(n - 1)/2 = n^2 - n/2
```
