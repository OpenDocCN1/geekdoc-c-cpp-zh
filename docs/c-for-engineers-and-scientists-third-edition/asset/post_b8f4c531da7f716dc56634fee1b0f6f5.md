As this program is rather simple and each task described by the algorithm is well defined, you can begin coding each task. To show that any task can be coded independently of any other task, you start by coding the function that calculates polar coordinates, or you could start with any function. As an added feature, this function will return the angle θ in degrees rather than the radian measure the atan(y) function returns. Because this function must receive two inputs, the x and y coordinates, and return two outputs, the r and θ coordinates, provide four parameters: two for the inputs and two for the outputs. Using the parameter x, y, r, and theta and the function name polar(), the following code performs the required calculation of polar coordinates

## 336 Modularity Functions

```
void polar(double x, double y, double& r, double& theta)
{
    const double DEGREE = 180.0/3.141593;

    r = sqrt(x * x + y * y);
    theta = atan(y/x) * DEGREE;

    return;
}
```

The polar() function is straightforward. The function header declares that the function returns no value, and each of its parameters is declared as floating-point type. The first two parameters are used to accept x and y values, and the last two parameters, which are reference parameters, are used to pass the converted distance and angle back to the calling function. In the body, a constant DEGREE is defined as 180.0/3.141593. The next two assignment statements use the parameters x and y to assign values to the r and theta parameters. The DEGREE constant is used to convert the radian value returned by the atan() function into degrees. As written, polar() function can be compiled to check for any compile-time errors. To understand how return values are passed, it's helpful to think of the reference r and theta as containers (variables) through which values can be passed in either direction. This situation is shown in Figure 6.13, which illustrates the fundamental characteristics of reference parameters: they simply make it for both functions and calling functions to access the same storage area with different names. As shown in Figure 6.13, the calling function can access the values assigned to r and theta in polar() with argument names ![](img/e2a849fc7bc04aa2e6669ad865e0c22b_355_0.png).

### Step 2 Testing the Function

After polar() is written, it can be tested by any other function. For this testing, you write a dedicated driver function that calls polar(), as shown in Program 6.11.

### Program 6.11

```cpp
#include <iostream>
#include <cmath>
using namespace std;

void polar(double, double, double&); // function prototype

int main()
{
    double distance, angle;
    polar(3.0, 4.0, distance, angle);

    cout << "r = " << distance << endl;
    cout << "angle = " << angle << endl;

    return 0;
}

void polar(double x, double y, double& r, double& theta)
{
    const double DEGREE = 180.0/3.141593;

    r = sqrt(x * x + y * y);
    theta = atan(y/x) * DEGREE;

    return;
}
```

Notice that in main(), the literals 3.0 and 4.0 are passed to polar(). The function accepts these inputs as x and y and uses these parameters in calculating values for the parameters r and theta. In main(), these last two parameters are known as distance and angle, and their values are displayed immediately after the call to polar(). This is the output produced When Program 6.11 runs:

r = 5
angle = 53.1301

These results are the same as those you would get from hand calculation. As the function performs only two calculations and the results displayed by the test program agree with those from a hand calculation, the function has been completely tested. It still remains to group the other two functions required for the complete program to make sure correct argument values are exchanged between each function.
