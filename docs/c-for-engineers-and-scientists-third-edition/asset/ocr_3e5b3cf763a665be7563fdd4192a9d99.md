This program would be complete if there were a function definition for findMax().
However, you really dont need a correct findMax() to test and run what has been
written; you will just need a function that acts is like it. A "fake" findMax() that accepts the
number of types and parameters returns values of the proper form for the function is all
y need for initial testing. This fake function, called a stub, is the beginning of a final function
and can be used as a placeholder for the final unit until the unit is completed. A stub for
findMax() is as follows:

```
void findMax(int x, int y)
{
    cout << "In findMax()\n";
    cout << "The value of x is " << x << endl;
    cout << "The value of y is " << y << endl;
}}
```

This stub can now be compiled and linked with the previously completed code
to produce an executable program. The code for function when it is completed, can then be further developed
with the "real" code replacing the stub portion.
The minimum requirement of a stub is that it compiles and links with its calling
module. In practice, it's a good idea to have a stub display a message that it has been entered
successfully and displays the values of its received parameters, as in the stub for findMax().
As the function is refined, you let it do more, perhaps allowing it to return intermediate or
incomplete results. This incremental, or stepwise, refinement is an important concept in
efficient program development that gives you the means to run a program that doesn't yet
meet its final requirements.
