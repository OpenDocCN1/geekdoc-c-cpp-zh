# Program 6.17

```cpp#include <iostream>
using namespace std;

void testauto();    // function prototype

int main() {
    int count;      // count is a local auto variable

    for(count = 1; count <= 3; count++)
        testauto();

    return 0;
}

void testauto() {
    int num = 0;    // num is a local auto variable
                   // initialized to 0
    cout << "The value of the automatic variable num is " << num << endl;

    num++;
}
```

Each testauto() is called, the automatic variable num is created and initialized to 0. When the function returns control to main(), the variable num is destroyed along with any value stored in num. Therefore, the effect of incrementing num in testauto(), before the function's return statement, is lost when control is returned to main().

For most applications, the use of automatic variables works just fine. In some cases, however, you want a function to remember values between function calls, which is the purpose of the static storage category. A local variable declared as static causes the program to keep the variable and its latest value even when the function that declared it has finished executing. The following are examples of static variable declarations:

```cpp
static int rate;
static double resistance;
static char inkey;
```

A static variable isn't created and destroyed each time the function declaring it is called. After they're created, local static variables remain in existence for the program's lifetime. This means the last value stored in the variable when the function finishes executing is available to the function next time it's called.

Because static variables retain their values, they are initialized in a declaration statement in the same way as automatic variables. To understand why, consider the automatic variable declaration num = 0;, which causes the automatic variable to be reset to 0 each time the function is called. This is called a runtime initialization because it occurs each time the declaration statement is encountered. This type of initialization would be disastrous for a static variable because resetting the value to 0 each time the function is called destroys the very value you're trying to save.

Initialization of static variables (both local and global) is done only once, when the program is first compiled. At compile time, the variable is created and any initialization value is placed in it.¹⁴ Thereafter, the variable is kept without further initialization. To see how this works, examine Program 6.18.

# Program 6.18

```cpp
#include <iostream>
using namespace std;

void teststat(); // function prototype
int main()
{
    int count;    // count is a local auto variable
    for(count = 1; count <= 3; count++)
        teststat();

    return 0;
}

void teststat()
{
    static int num = 0;    // num is a local static variable
    cout << "The value of the static variable num is now "
         << num << endl;

    num++;

    return;
}
```

> ¹⁴Some compilers initialize static variables the first time the definition statement is executed rather than when the program is compiled.

As this output shows, the static variable num is set to 0 only once. The teststat() function then increments this variable before returning control to main(). The value num when having the teststat() is returned and displayed when the function is next called.

Unlike automatic variables that can be initialized by constants or expressions using both constants and previously initialized variables, static variables can be initialized only by using constants or expressions, such as 3 * 2 = 8.0. Also, unlike automatic variables, all static variables are set to 0 when no initialization is given. Therefore, the specific initialization of num in Program 6.17 isn't required.

The remaining storage area available to local variables, register, isn't used extensively as auto or static variables. The following are examples of register declarations:

```cpp
register int time;
register double differ;
register float coupon;
```

The register variables have the same duration as auto variables; that is, a local variable is created when the function declaring it is entered and is destroyed when the function finishes. The only difference between register and auto is where the variable is stored.

Storage for all variables (local and global) is reserved in the computer's memory. Most computers have a few high-speed storage areas called registers, located in the CPU that can be used for variable storage. Because registers are located in the CPU, they can be accessed faster than memory storage areas located in the memory unit. Also, instructions referencing registers typically require less space than referencing memory locations because there are fewer registers than memory locations that can be accessed. When the compiler switches a register's location during program compilation, the instruction needs less space than address memory having millions of locations.

By decreasing a C++ program's size, using register variables can increase the execution speed if your program supports this data. Application programs intended to be executed on different types of computers shouldn't use registers, however. The compiler employs to do so by switching variables declared with the register storage category to the auto storage category automatically. # Global Variable Categories

Global variables are created and destroyed as the program is running. By their nature, global variables exist until the program in which they are declared has finished executing. Therefore, if a global variable is declared, it exists until the program ends.
