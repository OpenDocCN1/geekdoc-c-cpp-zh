Object-Oriented and Procedural Programs
Except for the bool type, all of C++ built-in data types are direct carryovers from the C procedural language. Not surprisingly, programs using only built-in data types can't be object-oriented programs. Instead, as in Program 2.5, they become procedural programs, based primarily on procedures, such as main().

Only when built-in data types are bundled together to form a packet of data, which becomes an object, an object-oriented program come into existence.

The output of Program 2.5 is compiler dependent, meaning each compiler reports the amount of storage it provides for the data type under consideration. When run on a computer using Microsoft of Visual C++ .NET compiler, for example, the following output is:

# Signed and Unsigned Data Types

A signed data type permits storing negative values in addition to 0 and positive values, so it is a signed type. An unsigned data type provides only for non-negative values (that is, 0 and positive values). Some applications require only unsigned values. For example, many applications store dates in the numerical format yearmonthday (storing 12/25/2007 as 20071225, for example) and are concerned only with dates after 0 CE. For these applications, which require no negative value, an unsigned data type can be used.

All unsigned integers, such as unsigned int, provide a range of positive values that, for all practical purposes, is double of their signed counterparts. This extra range is made available by using the negative of its signed version for positive numbers.
With understanding the difference between signed and unsigned data types, you can use Table 2.5 to determine the range of integer values supported by C++ compilers. As you can see, a long uses the same amount of storage (4 bytes) as an int. The only requirement of the ANSI C standard is that an int must provide at least as much storage as a short and a long must provide at least as much storage as an int. On early desktop computers with a memory capacity limited to thousands of bytes, a short typically used 1 byte of storage, an int 2 bytes, and a long 4 bytes. This storage limited the range of int values from -32768 to +32767 and unsigned int values from 0 to 65535, doubling the number of possible positive values, which was significant.
