# Chapter 13 Linked Lists

# 13.4 Linked Lists

A classic data-handling problem is making additions or deletions to existing structures that are maintained in a specific order. This problem is best illustrated by the alphabetical telephone list shown here:

+   - Acme, Sam
- (555) 898-2392
- Dolan, Edith
- (555) 682-3104
- Lanfrank, John
- (555) 718-4581
- Mening, Stephen
- (555) 382-7070
- Zemann, Harold
- (555) 219-9912

Starting with this set of names and phone numbers, you want to add new structures to the list in the correct alphabetical sequence and delete structures in such a way that storage for deleted structures is eliminated.
Although inserting or deleting ordered structures can be accomplished by using an array of structures, arrays aren't efficient representations for adding or deleting structures in reality. Arrays are fixed and have a specified size. Deleting a structure from an array creates an empty slot that requires special marking or shifting all elements below the deleted structure up to the empty slot.

Similarly, adding a structure to an array of structures requires shifting all elements below the addition to make room for the new, or the new element could be added to the beginning of the array, and the array could be restored to the structures' correct order. Therefore, adding or deleting records from this type of list generally requires restructuring and rewriting the list—time-consuming, and inefficient in practice.

A linked list provides a convenient way for maintaining a constantly changing list without needing to reorder. A linked list is simply a set of structures in which each structure contains at least one member whose value is the address of the next logically ordered structure in the list. Instead of reordering each record to be physically stored in the correct order, each new structure is physically added wherever the address of the next record in the record immediately preceding it is. From a programming standpoint, the current structure is being processed using the address of the next record, no matter where the next structure is actually stored.

Figure 13.5 illustrates the concept of a linked list. Although the actual data for the Lanfrank structure can be physically stored anywhere in the computer, the additional member included at the end of the Dolan structure maintains the correct alphabetical order. This member provides the starting address of the location where the Lanfrank record is stored. As you might expect, this member is a pointer.
