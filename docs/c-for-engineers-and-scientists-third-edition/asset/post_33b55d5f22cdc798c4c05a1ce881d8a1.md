Procedural, Hybrid, and Pure Object-Oriented Languages

Most high-level programming languages can be categorized as procedural, object-oriented, or hybrid. FORTRAN, the first commercial high-level programming language, is procedural. This makes sense because FORTRAN was designed to perform mathematical calculations using standard algebraic formulas. These formulas were described as algorithms, and then the algorithms were coded using function and subroutine procedures. Subsequent procedural languages included BASIC, COBOL, and Pascal.

Currently, there are only two pure object-oriented languages: Smalltalk and Eiffel. The first requirement of a pure object-oriented language is that it must contain three specific features: classes, inheritance, and polymorphism (described in this chapter and Chapter 11). In addition, a "pure" object-oriented language must, as well, in a pure object-oriented language, all data types are structured, all data operations can be overloaded, and every operation is executed only by using a class member of object-oriented language, it's impossible not to use object-oriented features in a pure program. This is not the case in a hybrid language.

In a hybrid language, such as C++, it is impossible not to use procedural elements in programs because the use of any built-in data type or operation violates the pure object-oriented requirements. Although a hybrid language must be able to define classes, its features are sufficient to write a complete program with only procedural code. Additionally, hybrid languages need not inheritance and polymorphism—but they provide classes. Languages that use classes but not provide inheritance are referred to as object-based languages rather must be produced to produce outputs by using clearly defined steps. In these applications, data is typically entered as character data from a keyboard, and then displayed as character on a printer or screen. Input and display of program output have always taken a back seat to processing, with a clear emphasis on the formulas being used.

With the emergence of graphical interfaces on computer desktops and laptops in the 1980s and 1990s, the subsequent insertion in multicolored, windowed systems, has shifted to a more balanced approach between input, output, and processing. Unfortunately, providing a graphical user interface (GUI) is a challenge, even an interface that requires only a single window. Programming multiple and overlapping windows increases the complexity when procedural code is used.

Unlike a procedural approach, an object-oriented approach fits graphically windowed environments well. Each object is constructed as self-contained rectangular object that can be moved and resized in relation to other objects on screen, and visual objects, such as check boxes, option buttons, labels, and text boxes, can be placed and moved easily.

Central to the creation of objects is the concept of an abstract data type, which is simply a user-defined data type, as opposed to the built-in data types provided by all languages (such as integer and floating-point types). Permitting a programmer to define new data types, such as a rectangular type, out of which specific rectangular objects can be created and displayed on screen, forms the basis of C++'s object orientation.

## Abstract Data Types

To gain a clear understanding of what an abstract data type is, take another look at the built-in data types in C++ integers, doubles, Boolean, and characters. In using these data types, typically you declare one or more variables of the desired type, use them in accepted ways, and avoid using them in ways that aren't specified. For example, you use the modulus operator on double-precision numbers. Because this operation makes no sense for double-precision numbers, it's never defined, in any programming language, for each data type consists of both a type of data, such as integer or double, and specific capabilities.

In computer terminology, the relation of data and associated operations is defined as a data type. That is, a data type defines both the types of data and the operations that can be performed on it. In this light, the integer type, the double-precision data type, and the character type provided in C++ are all examples of built-in data types defined by a type of data and specific operational capabilities for initializing and manipulating it. In a simple form, this relationship can be described as follows:

Data Type = Allowable Data Values + Operational Capabilities

Therefore, the operations you have been using in C++ are an inherent part of each data type you have been using. For each of these data types, C++ designers would have to carefully consider and implement specific operations.

To understand the importance of the operational capabilities a programming language provides, take a moment to review a list of capabilities supplied with C++'s built-in data types (int, double, and char). Table 10.1 lists the minimum set of such capabilities.

Table 10.1 C++ Built-In Data Type Capabilities
| Capability | Example |
| --- | --- |
| Define one or more variables of the data type | int a, b; |
| Initialize a value at definition | int a = 5; |
| Assign a value to a variable | a = 10; |
| Assign one variable's value to another variable | a = b; |
| Perform mathematical operations | a = a + b |
| Convert from one data type to another | a = int (7.2); |

Now see how this information relates to abstract data types (ADTS). By definition, an abstract data type is simply a user-defined type that defines both a type of data and the operations that can be performed on it. User-defined data types are required when you want to create objects that are more complex than simple integers and characters. To create your own data types, you must be aware of the type of data you're creating and the capabilities you provide to initialize and manipulate the data.

As a specific example, say you're programming an application that uses data extensively. Clearly, from a data standpoint, a date must be capable of accessing and storing a month, day, and year designation. From an implementation standpoint, there are several ways of date, from a user viewpoint, the implementation is irrelevant. For example, a date can be stored as three integers, one for the month, day, and year. Alternatively, a single integer in format yyyymdd can be used, so the date 5/16/08 is stored as the integer 20080516. For sorting dates, the long integer format is attractive because the numerical sequence of dates corresponds to their calendar sequence.

The structuring of the date internally supplies only a partial answer to your programming-effort, others must still satisfy a set of operations that can be used with dates. These operations could include assigning values to a date, subtracting two dates and comparing two dates to determine which is earlier and which, and displaying a date as in 12/03/06 rather than 123/6.

Notice that the details of how operation works depends on how you choose to store a date (called its data structure) and are of interest to you as you develop each operation. For example, the implementation of comparing two dates differs if you store a date as long integer using separate integers for the month, day, and year.

The combination of the architecture used for dates with a set of available operations defines the data type. After this type is developed, programmers who want to use it don't need to be concerned with how dates are stored or how operations are performed. All they need to know is what each operation does and how to invoke it, as they use C++'s built-in operations.

## Class Construction

A class defines both data and functions. This definition is universally accomplished by constructing a class in two parts: a declaration section and an implementation section. As shown in the following example code, the declaration section declares both the data types and functions. The implementation section then defines the functions whose prototypes have been declared in the declaration section.

```
// class declaration section
class className
{
    data members // the variables
    function members // prototypes
};
// class implementation section
function definitions
```

Both the variables and functions listed in the class declaration section are collectively referred to as class members. Separately, the variables are referred to as both data members and instance variables (the terms are synonymous), and the functions are referred to as member functions. A member function name can't be the same as a data member name. (When a function is part of a class, it's formally referred to as a method to denote class membership. By convention, however, the terms "class method" and "class function" are used interchangeably in C++).
