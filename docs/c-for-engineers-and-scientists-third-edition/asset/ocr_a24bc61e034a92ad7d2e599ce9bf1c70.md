# 5.8 Common Programming Errors

When using repetition statements, beginning C++ programs are prone to making the "off by one" error, in which the loop executes one or two too times than intended.

+   1. The most troublesome error for new programmers is the loop executes one or two too times than intended. For example, the loop created by the statement `for(i = 1; i < 11; i++)` executes 10 times, even though the number 11 is used in the statement. An equivalent loop can be constructed with the statement `for(i = 1; i <= 10; i++)`.
However, if the loop starts with an initial value of $i = 0$, using the statement `for(i = 0; i < 11; i++)`, the loop is traversed 11 times, as a loop constructed with the statement `for(i = 0; i <= 10; i++)`. In constructing loops, you must pay particular attention to both the initial and final conditions to control the loop and make sure the loop traversals aren't off by one or two too executions.

The next two errors pertain to the expression, and you have already encountered them with the switch statements:

+   2. Inadvertently using the assignment operator, `=`, in place of the equality operator, `==`, in the tested expression—for example, typing the assignment $a=5$ instead of the correct relation $a==5$. Because the tested expression is any valid C++ expression, including arithmetic and assignment expressions, the compiler does not detect this error.

+   3. Using the equality operator, `==`, when testing floating-point or double-precision operands. For example, the expression `fnum == 0.01` should be replaced by a test requiring that the absolute value of `fnum-0.01` be less than an acceptable amount. The reason is that all numbers are stored in binary. Using a finite number of bits, decimal numbers such as 0.01 have no binary equivalent, so tests equality with these numbers can fail. (See Section 4.1 for a more complete description of this numerical accuracy problem.)

The next three errors are particular to the following statement:

+   4. Placing a semicolon at the end of for's parentheses, which frequently produces a do-nothing loop. For example, take a look at these statements:

```
for(count = 0; count < 10; count++);
total = total + num;
```
