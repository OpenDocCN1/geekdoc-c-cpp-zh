## Arrays as Arguments

For these arrays, the following function calls can be made; note that in each case, the called function receives direct access to the named array:

```
findMax(nums);
findCh(keys);
calcTot(nums, volts, current);
```

On the receiving side, the called function must be alerted that an array is being made available. For example, the following are suitable function headers for the previous functions:

```
int findMax(int vals[5])
char findCh(char in_keys[26])
void calcTot(int arr1[5], double arr2[500], double arr3[500])
```

In each function body, the programmer chooses the names in the parameter list. However, the parameter names used by the functions still refer to the original array created outside the function, as Program 7.6 makes clear.

The parameter declaration in the findMax() header actually contains extra information not required by the function. All that findMax() must know is the parameter vals references an array of integers. Because the array has been created in main() and no additional space is needed in findMax(), the declaration for vals can omit the array size. Therefore, the following is an alternative header:

```
int findMax(int vals[])
```

This form of header makes more sense when you realize that only one item is actually passed to findMax() when the function is called: the starting address of the num array, as shown in Figure 7.9.

Because only the starting address of vals is passed to findMax(), the number of elements in the array need not be included in the declaration for vals.4 In fact, generally

The parameter names chosen inside the function body. However, the parameter names still refer to the original array created outside the function. Program 7.8 shows the use of the nested for, cycling through each array element.

```cpp
#include <iostream>
#include <iomanip>
using namespace std;
const int ROWS = 3;
const int COLS = 4;
void display(int nums[][4]); // function prototype
int main() {
    int val[ROWS][COLS] = {8,16,9,52, 3,15,27,6, 14,25,2,10};
    display(val);
    return 0;
}
void display(int nums[][4]) {
    int rowum, column;
    for (rowum = 0; row < ROWS; rowum++) {
        for (column = 0; column < COLS; column++) {
            cout << setw(4) << nums[rowum][column];
        }
        cout << endl;
    }
}
```

The parameter declaration for display() contains extra information not required by the function. The declaration for nums can omit the row size of the array, so as the following is an alternative prototype:

```
display(int nums[][4]);
```

The reason the column size must be included but the row size is optional becomes obvious when you see array elements are stored in memory. Starting with element val[0][0], each succeeding element is stored consecutively, by row, as val[0][0], val[0][1], val[0][2], val[0][3], val[1][0], val[1][1], and so on, as illustrated in Figure 7.10.

> Figure 7.10 Storage of the val array

As with all array accesses, a single element of the val[1][3] of the val array is obtained by adding an offset to the array's starting location. For example, element val[1][3] of the val array in Figure 7.10 located at an offset of 28 bytes from the start of the array. Internally, the compiler uses the row index, column index, and column size to determine this offset, using the following calculation (4 bytes for an int):

No. of bytes in a complete row

```
Offset = [(3*4)+[1*(4*4)] = 28 bytes
Bytes per integer
Column size
Row index
Column index
```

The column size is necessary in the offset calculation so that the compiler can determine the number of positions to skip over to get to the correct row.
