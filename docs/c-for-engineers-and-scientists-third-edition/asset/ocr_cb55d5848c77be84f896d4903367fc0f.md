Sequence defines the order in which the program executes instructions. Specifying which instruction comes first, and which second, is essential if the program is to achieve a well-defined purpose.

Selection provides the capability to make a choice between different operations, depending on the result of some condition. For example, the value of a number can be checked before a division is performed: if the number is not zero, it can be used as the denominator of a division; otherwise, the division isn't performed and the user is given a warning message.

Iteration, also referred to as "looping" and "repetition", for example, grades may be entered and added repeatedly based on a value of a condition. If a negative grade is entered, the entry of a negative grade is the condition that significant addition will start and addition of grades. At that point, an average for all grades could be calculated.

Invocation involves invoking, or summoning, a set of statements as executed. For example, computing a person's net pay involves the tasks of obtaining pay and hours worked, calculating the net pay, and providing a report or check for the required amount. Each task is typically coded as a separate unit that is called, or invoked, as is needed.

# Step 4 Test and Correct the Program

The purpose of testing is to verify that a program works correctly and fulfills its requirements. In computer terminology, a program error is called a bug² In practice, finding all errors would require checking all possible combinations of statement execution. The time and effort required, this is usually impossible, except for extremely simple programs.(Section 4.8 explains why this is generally considered impossible.)

Exhaustive testing isn't feasible for most programs, different philosophies and methods of testing have evolved, however requires conscious effort to make sure a program works correctly and produces meaningful results. This effort means giving thought to what the test is to achieve and the data used in it. If testing reveals an error (bug), the process of debugging, which includes locating, correcting, and verifying the correction, can be initiated. Although the fact that a test failed might reveal the presence of an error, it doesn't necessarily indicate the absence of one, for that a test revealed does not indicate that one isn't somewhere else in the program.

To catch and correct errors in a program, developing a set of test for determining whether the program gives correct results is important. In fact, often an accepted step in formal software development is to plan test procedures and create meaningful test before writing the code. This doing step helps you be more objective about what the program must do because of the subconscious temptation after coding to avoid test that would reveal a problem with your program. The procedures for testing a program should examine every possible situation in which the program will be used.
