# Chapter 11 Polymorphism 657

Program 11.16 produces the following output:

```
The computed value using a base class object call is 36
The computed value using a derived class object call is 16
```

As this output shows, the f2() function now calls different versions of the overloaded f1() function on the object type making the call. Basing on the object making the call is the classic definition of polymorphic behavior and is caused by the dynamic binding based on f1() it's a virtual function.

After a function is declared virtual, it remains virtual for the next derived class, or without a virtual declaration in the derived class. Therefore, the second declaration in the derived class isnt strictly necessary but should be included for clarity and to make any subsequently derived classes inherit the functionality.

In the inheritance diagram of figure 11.10, class C is derived from class B and class B is derived from class A. In this situation, if the f1() is virtual in class A but not declared in class B, it isn't virtual in class C. The only other requirement is that after a function has been declared as virtual, the return type and parameter list of all subsequent derived class override versions must be the same.
