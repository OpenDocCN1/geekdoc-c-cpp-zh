# Preliminaries

# Step 1 Analyze the Problem

The analysis of a problem can consist of up to two parts. The first part is a basic analysis that must be performed on all problems; it consists of extracting the complete input and output supplied by the problems. For this analysis, you must

+   - Determine and understand the output items the program must produce.
- Determine the input items.

Together, these two items are referred to as the problem's input/output (I/O). Only after determining a problem's I/O can you select specific methods for transforming inputs into outputs. By doing a hand calculation to verify that the output(s) can be obtained from the inputs is sometimes necessary and/or useful. Clearly, if you have a formula that relates to inputs, you can omit this step. If the required inputs are available and the desired outputs can be produced, the problem is to be clearly defined and solved.

For a variety of reasons, completing a basic analysis might not be possible. If so, an extended analysis might be necessary. An extended analysis simply means you gather more information about the problem so that you thoroughly understand what is being asked for and how to achieve the result. In this book, any additional information required to understand the problem is supplied along with the problem.

# Step 2 Develop a Solution

In this step, you select the exact set of steps, called an "algorithm," to solve the problem. Typically, you find the solution by a series of refinements, starting with the initial solution you find in the analysis step, until you have an acceptable and complete solution. This solution must be checked, if it's not done in the analysis step, to make sure it produces the required outputs correctly. The check is usually carried out by doing one or more calculations that haven't been done

For small programs, the selected solution might be extremely simple and consist of one or more calculations. Typically, you need to refine the initial solution and organize it into smaller subsystems, with specifications for the subsystems interface each other. To achieve this, the goal's description starts from the highest level (top) requirement and proceeds towards the parts that must be constructed to meet this requirement. To make this explanation more meaningful, a comprehensive program must track the number of items in inventory. The required output for a program is a description of all parts in inventory and the inventory of each item in stock; the given inputs are the initial quantity of each part, the number of items sold, the number of items returned, and the number of items purchased.
