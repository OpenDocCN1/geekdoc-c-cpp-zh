The parameter declaration for nums in display() contains extra information not required by the function. The declaration for nums can omit the row size of the array, so as the following is an alternative prototype:

```
display(int nums[][4]);
```

The reason the column size must be included but the row size is optional becomes obvious when you see array elements are stored in memory. Starting with element val[0][0], each succeeding element is stored consecutively, by row, as val[0][0], val[0][1], val[0][2], val[0][3], val[1][0], val[1][1], and so on, as illustrated in Figure 7.10.

![](bbox=[0.168, 0.403, 0.8, 0.513])

> Figure 7.10 Storage of the val array

As with all array accesses, a single element of the val[1][3] of the val array is obtained by adding an offset to the array's starting location. For example, element val[1][3] of the val array in Figure 7.10 located at an offset of 28 bytes from the start of the array. Internally, the compiler uses the row index, column index, and column size to determine this offset, using the following calculation (4 bytes for an int):

No. of bytes in a complete row

```
Offset = [(3*4)+[1*(4*4)] = 28 bytes
Bytes per integer
Column size
Row index
Column index
```

The column size is necessary in the offset calculation so that the compiler can determine the number of positions to skip over to get to the correct row.
