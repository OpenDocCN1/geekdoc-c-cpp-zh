As a general rule, whenever a selection statement doesn't act as you think it, test your assumptions about the values assigned to the tested variables by displaying your tests. If an unintended value is displayed, you have isolated the source of the problem to the variables rather than the structure of the if-else statement. From there, you can determine where and how the incorrect value was produced.

+   4. Using nested if without braces identifies the structure. Without braces, the compiler defaults to pairing else with the closest unpaired ifs, which sometimes destroys the selection statement's original intent. To avoid this problem and create code that is adaptable to change, writing all if-else statements as compound statements in this form is:

```
if (expression)
{
 // one or more statements in here
}
else
{
 // or more statements in here
}
```

No matter how many statements are added later, this maintains the if statement's original intent.

+   1. Relational expressions, also called conditions, are used to compare operands. If a relational expression is true, the value of the expression is the integer 1. If the relational expression is false, it has an integer value of 0. Relational expressions are created using the following relational operators:

| Relational Operator | Meaning | Example |
| --- | --- | --- |
| > | Less than | age < 30 |
| < | Greater than | height > 6.2 |
| <= | Less than or equal to | taxable <= 20000 |
| >= | Greater than or equal to | temp >= 98.6 |
| == | Equal to | grade == 100 |
| != | Not equal to | number != 250 |
