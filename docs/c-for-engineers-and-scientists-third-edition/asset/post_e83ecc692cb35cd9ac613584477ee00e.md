Object-Oriented and Procedural Programs
Except for the bool type, all of C++ built-in data types are direct carryovers from the C procedural language. Not surprisingly, programs using only built-in data types can't be object-oriented programs. Instead, as in Program 2.5, they become procedural programs, based primarily on procedures, such as main().

Only when built-in data types are bundled together to form a packet of data, which becomes an object, an object-oriented program come into existence.

## Signed and Unsigned Data Types

A signed data type permits storing negative values in addition to 0 and positive values, so it is a signed type. An unsigned data type provides only for non-negative values (that is, 0 and positive values). Some applications require only unsigned values. For example, many applications store dates in the numerical format yearmonthday (storing 12/25/2007 as 20071225, for example) and are concerned only with dates after 0 CE. For these applications, which require no negative value, an unsigned data type can be used.

All unsigned integers, such as unsigned int, provide a range of positive values that, for all practical purposes, is double of their signed counterparts. This extra range is made available by using the negative of its signed version for positive numbers.

With understanding the difference between signed and unsigned data types, you can use Table 2.5 to determine the range of integer values supported by C++ compilers. As you can see, a long uses the same amount of storage (4 bytes) as an int. The only requirement of the ANSI C standard is that an int must provide at least as much storage as a short and a long must provide at least as much storage as an int. On early desktop computers with a memory capacity limited to thousands of bytes, a short typically used 1 byte of storage, an int 2 bytes, and a long 4 bytes. This storage limited the range of int values from -32768 to +32767 and unsigned int values from 0 to 65535, doubling the number of possible positive values, which was significant. With the current range of int values in the -2 to +2 binary range, doubling positive values is rarely a consideration. Additionally, a long int is unnecessary now because it uses the same storage capacity as an int.

## Floating-Point Types

A floating-point number, more commonly known as a real number, can be the number 0 or positive or negative without a decimal point, as shown in:

+10.625, -6.2, 3251.92, 0.0, -6.67, +2 (example from context)

Therefore, the numbers 5, 0.0, and +2 are classified as floating-point values, but the same numbers written without a decimal point (5, 0, +2) are integers. With integer values, special symbols such as the decimal sign and comma aren't permitted in real numbers, as shown in these examples of invalid reals:

5,326, 24, 6,459, $10.29, 7.007.645

C++ supports three floating-point types: float, double, and long. The difference between these data types is the amount of storage the compiler uses. Most compilers use the amount of doubles for floats, which allows a double to have approximately twice the precision of a float. For this reason, a float is sometimes referred to as a single-precision number and a double as a double-precision number. The actual storage for each data type, however, depends on the compiler. The ANSI C++ standard requires only that a double have at least the same amount of storage as a float. Currently, most C++ compilers allocate 4 bytes for floats and 8 bytes for doubles and longs, which produces the range of numbers listed in Table 2.6.

## Problem Solving Using C++: What Is Precision?

In numerical theory, the term **precision** typically refers to numerical accuracy. In this context, the statement "This computation is accurate, or precise to the fifth decimal place" means the fifth digit after the decimal point has been rounded, and the number is accurate to ±0.0005.

In computer programming, "precision" can refer to the accuracy of a number or the amount of significant digits. **Significant digits** are defined as the number of digits plus one. For example, if the number 12.6874 has been rounded to the fourth decimal place, it's correct to say that this is precise to the decimal place. In other words, all digits except the fourth decimal digit have been rounded. Similarly, a number with six digits means the number 12.6874 has six significant digits.

The significant digits in a number need not relation to the number of displayed digits. For example, if the number 687.4567921 has five digits, it's accurate only to the value 687.46; the last digit is assumed to be rounded. Similarly, values in large financial applications are often rounded to the nearest dollar. In these applications, a displayed value of $12,400,000, for example, isn't accurate to the closest dollar.

In compilers use the same amount of storage for double and long, these two data types are identical (The sizeof() operator in Program 2.5 can always be used to determine the amount of storage your computer reserves for these types.). A float literal is indicated by appending 'f' to the number, and a long double is created by appending 'L' to the number. In the absence of these suffixes, a floating-point number defaults to a double. For example, take a look at the following:

- 9.234 indicates a double literal
- 9.234f a float literal
- 9.234L a long double literal

The only difference in these numbers is the amount of storage the computer can use for them. Appendix C describes the binary storage format used for floating-point numbers and its impact on number precision.
