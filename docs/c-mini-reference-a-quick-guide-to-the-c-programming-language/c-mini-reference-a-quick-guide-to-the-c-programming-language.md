# 前言

C# 最初是基于 Java 编程语言创建的，大约在 2000~2002 年，部分原因是微软当时想吸引熟悉 Java 的程序员。

Java 在面向对象编程（OOP）成为业界最主流编程范式时几年前就已创建。Java 变得非常流行。在 Java 中，一切都是类。函数被降级为类的“方法”。甚至那些实际上不属于对象的函数也需要成为类的一部分，例如作为“静态”方法。至少在语法上，你无法在不先创建类的情况下用 Java 编程。

C# 最初遵循了这种“一切皆类”的设计。现在，在过去的 20 多年里，C# 一直试图摆脱 Java 的幽灵。

近年来，人们开始认识到 OOP 的局限性，尤其是作为一种一刀切的编程范式。大多数现代编程语言，如 Go、Rust、Swift，甚至其他 JVM 语言如 Scala 和 Kotlin 都不施加此类限制。事实上，Java 和 C# 是仅有的两种具有这种内置类优先限制的广泛使用的语言。

C# 一直在不断演进。但它在 C# 6 和 C# 7 之间经历了重大变化。自那以后，C# 每年发布一个新主要版本。截至本文撰写时，C# 11 是当前最新版本。

尽管多年来有许多大大小小的更新，但最近的变化实际上是关于 C# 脱离 Java。C# 现在正式成为一种“多范式”编程语言，而不仅仅是 OOP 语言。现代 C# 鼓励函数式编程风格等。例如，C# 中的许多构造现在是表达式而不是语句。（另外，需要注意的是，C# 的许多新特性借鉴自 F#，另一种主要为函数式的 .NET 编程语言。）自 C# 9 起，我们可以使用顶层语句，至少在一个程序中不超过一个源代码文件。这种外观上的变化使我们能够摆脱现代 C# 中的大量样板代码。

C# 11 现在在接口中支持所谓的“静态抽象方法”。尽管其全部影响尚不完全清楚，这一变化使 C# 更接近其他更现代的语言。就其能力而言，C# 11 的接口可与 Go 的接口、Rust 的 trait 和 Swift 的 protocol 等相媲美。

本书主要关注 C# 语言的语法。但我们鼓励读者超越语法。特别是，我们需要调整编程风格，而不是坚持旧的“一切皆类”范式，以便利用新的现代特性并更有效地用 C# 编程。

话虽如此，如果你愿意，你可以从头到尾阅读本书，你将获得 C# 语言的完整图景。

需要注意的是，本书有相当多的交叉引用，如果你之前没有 C# 或其他类似语言如 C++ 或 Java 的编程经验，你可能在阅读本书的某些部分时会遇到一些困难。我们还跳过了 C# 的一些基础知识，以便在有限的篇幅内更详细地介绍更现代的特性。本书的目标读者是高级初学者到中级程序员。高级 C# 开发者也可以通过选择性地阅读更高级、更现代的特性从本书中受益。

需要注意的是，本书不是权威的语言参考。如果本书中存在任何不一致、令人困惑或似乎不正确的解释，我们建议读者参考官方语言规范。

# 1. 引言

C# 是一个相当复杂的语言。事实上，根据你衡量编程语言复杂性的方式，C# 可能是一些广泛使用语言中最复杂的语言。没有人喜欢复杂性。然而，C# 却是许多开发者最受欢迎和喜爱的语言之一。为什么？

编程语言是一种工具。有时，拥有一个复杂且灵活的工具可以使完成实际任务变得更简单、更容易。例如，使用电锯可以使砍树的任务更容易。C# 就是这种情况。

这有几个含义。一方面，C# 通常不被认为是对初学者友好的语言。在你获得收益之前，你需要做出前期投入。另一方面，一旦你掌握了工具，C# 可以成为构建大型企业级软件的强大工具。

总的来说，使用像 C# 这样“更复杂”的语言，你最终会得到“更简单”的程序。至少这是想法。因此，正确有效地使用 C# 相当重要。否则，使用重量级语言的缺点，如果你愿意的话，将大于使用此类语言的好处。

本书提供了 C# 语言语法的鸟瞰图。它分为几十个半独立的章节，涵盖了 C# 的大多数重要特性。

编程语言不仅仅是其特性的总和。然而，为了最有效地使用像 C# 这样的语言，你需要知道有哪些特性可以使用。你需要对每个特性都有透彻的高层次理解。如前言所述，读者在研究每一棵树时应避免迷失森林。



## 1.1. C## 与 .NET

冒着过度简化的风险，编程语言及其编程方式有三个方面：

-   语言本身，例如语法和标准库，
-   运行时，以及
-   工具链（例如语言编译器）。

例如，C++ 编程语言规范由 ISO 管理。另一方面，工具链由各种工具厂商提供，如 Microsoft、GNU/gcc 和 clang。C++ 本身没有独立的运行时，除运行时对标准库的支持外。C++ 程序直接编译为机器码。

在 C# 和 .NET 的情况下，Microsoft 基本上拥有包含 C# 语言全部三个部分的整个生态系统。（我们不讨论 Unity 等使用的 C# 的其他实现。） .NET 系统定义了一组标准库及其运行时支持。.NET 也是一个运行时，或虚拟机，用于运行从 C# 程序编译而来的字节码。

Microsoft 的 .NET 有着非常复杂的历史，有许多不同的版本和形态，以及许多不同的（且不断变化的）名称。本书中使用的框架和版本简单地称为 .NET 7（最初称为 .NET Core）。这是一个跨平台的 .NET 框架版本。也就是说，一旦你创建了针对 .NET 7 的 C# 程序，你就可以在 .NET 7 支持的任何系统上运行它。（此外，.NET 通常支持多种编程语言。）

这种紧密集成生态系统的另一个含义是 C# 不能独立存在。事实上，至少原则上，如果不知道其关联的 .NET 框架，就无法精确地阅读和解释 C# 程序。

这并不一定是 C# 独有的，所有编程语言都会随着时间的推移而演进等。但在 C# 和 .NET 的情况下，相互依赖性要紧密得多。

C# 使用项目文件来管理构建配置等。.NET 7 的默认 C# 版本是 C# 11。也就是说，如果你计划在 .NET 7 上使用不同版本的 C#，例如，那么你需要在项目文件中显式指定。

当你在 .NET 7 上脚手架一个空的 C# 项目时，例如使用 Visual Studio 或 dotnet CLI，它会创建以下占位项目文件：

清单 1. SampleProject.csproj

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net7.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>
</Project>
```

此文件中由工具设置的四个属性。OutputType 属性表示目标二进制文件的类型，例如 Exe（可执行文件）与 Lib（库）。我们通过 TargetFramework 针对 .NET 7（如果你使用基于 .NET 7 的工具链，这是一个自然值）。

最后两个属性 ImplicitUsings 和 Nullable 相当重要。C# 在过去经历了一些向后不兼容的更改。在原始 C# 中，这两个属性的值都将被禁用。现在向前看，C# 社区的大多数人可能会使用 enable 值，因此 C# 在实际上已变得向后不兼容。

我们将在本书中始终假设这两个值都设置为 enable。严格来说，本书中提供的一些信息可能“不正确”，例如在使用这些属性（以及可能还有其他属性）的不同值时。

除非你有遗留代码等，我们建议读者也这样做：对两者始终使用 enable。ImplicitUsings 的影响相对较小，但 Nullable 完全改变了 C# 程序的工作方式。我们将在下一节讨论这一点。

## 1.2. 可空上下文

引用类型的变量可以为 null。null 值 simply 意味着变量指向 nothing。也就是说，它不指向内存中的任何实际数据。引用变量的默认值是 null。

这在所有支持引用类型或指针类型的不同 C 风格编程语言中都是如此。当这些变量为 null 时访问它们一直是许多（可能可以预防的）错误的根源，称为空指针异常。

C# 提供了编译时支持来解决这个问题。此功能称为“可空上下文”。默认情况下它是禁用的，这意味着所有引用变量都是可空的，就像一直以来一样。在启用的可空上下文中，传统的（可空）引用变量变为不可空。将这些变量设置为 null 将导致编译时错误。此外，在启用的可空上下文中可以使用一种新型的引用变量，称为“可空引用变量”。所有可空引用变量在使用前都应检查其可空性。否则编译器可能会抛出编译时错误或警告。

你可以像上一节讨论的那样在 C# 项目文件中设置可空上下文。此外，你还可以使用 C# 的编译器指令在代码的某些部分有选择地启用或禁用可空上下文。要启用，可以在源代码文件中放入以下内容：

```
#nullable enable
```

这将一直生效到源文件末尾，或直到使用下一个 #nullable 指令（如果有）。要禁用，请使用以下内容：

```
#nullable disable
```

你也可以使用以下指令恢复之前上下文的值：

```
#nullable restore
```

可空上下文纯粹是编译时支持。.NET 运行时对可空上下文一无所知，就它而言，所有引用变量都是可空的。

## 1.3. 书籍组织

我们从 C# 程序的整体开始。C# 程序本质上是一组（将被）一起编译的 C# 源文件。可执行 C# 程序有且只有一个入口点，可以是启动类的 Main 方法或某个源代码文件中的顶层语句。我们还在本章中描述了访问的基本概念，例如 public 与 private、命名空间以及块和作用域。

源代码文件本质上是一个字符序列。接下来我们将介绍将输入字符序列转换为编译器理解的“标记”序列的基本过程。这通常被称为“词法分析”。C# 的词法结构与其它 C 风格编程语言的词法结构相当相似。

C# 程序在逻辑上由一个或多个命名空间组成。命名空间可以包含其他命名空间或自定义类型的声明，例如 using 指令等，这些又可以包含其他成员声明。在 C# 中，using 指令用于从其他命名空间导入名称。命名空间本身不参与访问控制。

C# 类型按层次组织，以基类 object 为根。与许多 C 风格语言一样，C# 具有值和引用（或指针），其特性不同。C# 支持两种不同且互斥的类型类别，即值类型和引用类型。此外，C# 包含 dynamic 类型，这在静态类型在某些情况下过于受限时有点像逃生舱口。



在近期的许多重要变化中，有几项值得注意。

- 首先，接口中的方法现在可以有默认实现，实现类（以及记录和结构体）可以继承这些默认实现。
- 其次，静态方法已成为接口不可或缺的一部分，而不再只是配角（如果你愿意这样理解的话）。
- 第三，从 C# 11 起，静态方法现在甚至可以参与定义接口的“行为”部分。

例如，C# 11 新增的泛型数学支持包括 System.Numerics 命名空间中的 INumber 接口：

```csharp
public interface INumber<TSelf> : IComparable<TSelf>, ... where TSelf : INumber<TSelf> {
    public static virtual int Sign(TSelf value);
    // ...
}
```

例如，所有实现 INumber 的类型都需要实现这个 Sign 虚拟静态方法。这个部分示例也说明了泛型类型的使用。在接口章节中，我们会介绍现代 C# 接口的一些基本要素，包括这些近期变化。

C# 具有统一的类型系统。每个（非接口）类型都继承自 object。这是 C# 1.0 的核心部分，即使经过二十年的语言演进，这一点仍然如此。

可以说，数组是任何编程语言中除基元类型之外最重要的数据结构。C# 的数组是泛型类型，它以类型安全的方式支持所有常见的数组操作，例如索引。数组和其他集合类型现在也支持基于范围的切片语法，使用的是相对较新的 .NET 类型 Index 和 Range。

另一对重要且相对较新的 .NET 类型是 `Span<T>` 和 `Memory<T>`，它们也与 C# 语言紧密集成。这些类型提供了一种安全的方式来访问和操作内存中的对象及其元素或成员，而不必依赖昂贵的内存操作。

设计和实现一个行为良好的类型需要大量工作。在许多像 Java 和 C# 这样以面向对象为主的语言中，有时仅仅为了创建一个简单类型就需要编写大量样板代码。object 类中定义的虚方法就是其中一些例子。原则上（但不一定在实践中），这些方法中的许多都需要被重写，此外还有许多其他方法，这使得创建新类型格外繁琐。

C# 演进中最大的趋势或主题之一，就是让创建自定义类型这项任务变得更容易。例如，委托自 C# 1.0 起就是 C# 的一部分，它只是一种带有一些编译器生成代码的特殊类，因此开发者无需手动实现它们。最近新增的记录和记录结构体，是 C# 中这一趋势的另一个例子。

在 .NET 世界中，元组（或值元组）是最容易创建和使用的复合类型。它们实际上是“轻量级”类，在许多情况下应优先使用它们，而不是创建更正式的类型。枚举类型也允许创建一种基于一组常量值的简单、特殊类型。

尽管有所有这些近期变化，类仍然是 C# 中最重要的构造。C# 编程从根本上说就是定义类型，例如使用类（以及记录和结构体之类的近亲）。在类章节中，我们会介绍 C# 的基本要素。需要注意的是，我们在类上下文中描述的许多内容也适用于记录和记录结构体。

记录用于创建不可变引用类型，主要用于简单的数据存储。C# 提供了简洁的语法来创建和使用记录。特别是，它支持用于创建记录类型的位置参数。例如，现在创建记录类型就像声明一个记录构造函数一样简单。编译器会自动生成整个类以及若干方法。

```csharp
record Book(string Title, string Author);
```

结构体是值类型，基于 System.ValueType 基类，而该基类又继承自 System.Object。结构体类型本身不支持继承。还存在一些特殊种类的结构体，例如只读结构体、ref 结构体和记录结构体。

C# 支持扩展方法，扩展方法是与其他现有类型关联的静态方法。扩展方法可以像目标类型的实例方法一样被调用。

在本书的第一部分，我们主要关注类型。在本书其余部分，我们会介绍 C# 中其余的重要构造，例如表达式和语句。

new 运算符是 C# 表达式最重要的组成部分之一。它用于创建数组，或创建指定类型（例如类或结构体）的新值或新对象。本章中我们还会介绍对象初始值设定项和集合初始值设定项语法。

除了其他编程语言中常见的表达式外，C# 中还有许多不同种类的表达式。本书通篇都会讨论表达式和运算符，但一些更常见的表达式集中在表达式章节中介绍。lambda 表达式是匿名函数。它使用“粗箭头”=> 运算符定义。Lambda 函数可以作为参数传递给其他方法。

C# 的语句与其他 C 风格语言中的语句大体相同，只有一些细微差别。我们在语句章节中快速过一遍 C# 的所有语句，主要是为了完整性。

switch 语句最初基于 C 的 switch-case 语句，它的一项显著变化是现在支持模式匹配，以及 is 和 switch 表达式。模式匹配最初由 Haskell 等函数式编程语言推广，如今已成为许多（函数式或命令式）编程语言不可或缺的一部分，包括 C#。

using 语句和 using 声明用于管理使用后需要清理的资源，例如文件句柄或数据库连接。当实现 IDisposable 接口的对象超出作用域时，会自动调用其 Dispose 方法。

# 2. C# 程序

一个 C# 程序可以由一个或多个源代码文件（称为编译单元）组成，例如位于文件系统中的一个或多个目录中。程序（可执行文件或库）中的所有源文件会一起编译，因此源文件之间没有特定顺序。

每个源代码文件可以包含一组特殊声明和自定义类型定义。类型定义可以包含在零个或多个嵌套命名空间中。C# 中的命名空间是一种逻辑组织单元，主要用于降低名称冲突的可能性。

## 2.1. Main 方法

可执行的 C# 程序（或“应用程序”）应当包含一个具有 Main() 静态方法的类型声明（例如类或接口），或者包含一个带有“顶级语句”的源文件。这是程序的入口点。

Main() 静态方法可以返回 int 类型的值，也可以不返回任何值（由 void 返回类型表示）。它可以接受 string[] 类型的参数，也可以定义为没有任何方法参数。Main() 方法可以是同步的，也可以声明为 async 并返回 Task 或 Task<int>。

因此，Main() 静态方法的有效签名有以下八种组合：

```csharp
static void Main() { /* ... */ }
static int Main() { /* ... */ }
static void Main(string[] args) { /* ... */ }

## 2.2. 顶级语句

自 C# 9 起，程序中的一个源文件可以使用顶级语句，只要该程序不包含任何其他入口点方法。它是一种语法糖，有助于移除一些样板代码。顶级语句会自动包装在隐式定义的启动类的 Main 方法中。

顶级语句可以使用类型为 string[] 的隐式定义变量 args 访问命令行参数。

如果顶级语句返回整数值，该值将成为返回给操作系统/运行时的整数返回代码。

顶级语句可以包含异步表达式。

例如，

```
Console.WriteLine("Hello World");
```

一个包含这一行代码的文件，使用自 C# 10 起可用的隐式全局 using 特性，大致等价于如下内容：

```
namespace Namespace1 {
    class Program {
        static void Main(string[] args) {
            Console.WriteLine("Hello World!");
        }
    }
}
```

自 C# 11 起，存在一些限制：

- 应用程序中只能有一个文件使用顶级语句。
- 该文件中的所有顶级语句都应放在任何其他命名空间成员（例如类型声明）之前。
- 程序不能同时具有顶级语句和显式入口点，例如 Main 方法。

# 4. 命名空间

编译单元（例如 C# 源代码文件）按照以下线性结构组织：

- 零个或多个 extern 别名指令，
- 零个或多个全局 using 指令（它们影响程序中的所有编译单元），
- 零个或多个（特定于源文件的）using 指令，
- 零个或多个全局特性，以及
- 零个或多个命名空间及其成员声明，或
- 一个文件作用域命名空间及其成员声明。

C# 程序默认使用（匿名的）全局命名空间，除非成员声明包含在显式命名空间声明中（文件作用域或其他形式）。

## 4.1 命名空间声明

从 C# 10 及更高版本开始，命名空间可以在有或没有显式块的情况下声明。没有块的命名空间的作用域延伸到整个编译单元/文件。“普通”块作用域命名空间由关键字 `namespace`、命名空间名称、主体和可选分号组成。例如，

```
namespace War {
    // Any member declarations
}
```

① 此命名空间的名称是 `War`。注意，单个编译单元中可以包含多个（可能嵌套的）带显式块的命名空间。

另一方面，文件作用域命名空间以关键字 `namespace`、名称和分号开头。编译单元的其余部分遵循相同的总体结构，例如零个或多个 extern 别名指令、using 指令（但不是全局 using 指令），随后是任何成员类型声明，它们都属于此命名空间。例如，

```
namespace Peace;
// ...
```

① 此命名空间声明延伸到源文件末尾。如果源文件包含（可能嵌套的）文件作用域命名空间声明，则它不能在同一编译单元中包含任何其他命名空间声明。

嵌套的文件作用域命名空间可以使用点限定名称声明。例如，

```
namespace Crime.Punishment;
// ...
```

上述声明例如等效于以下内容：

```
namespace Crime {
  namespace Punishment {
    // ...
  }
}
```

## 4.2 extern 别名指令

extern 别名指令为外部命名空间引入一个别名。例如，

```
extern alias Fruit;
Fruit::Apple apple;
```

① 它引入一个外部别名 `Fruit`。
② `Apple` 是在命名空间 `Fruit` 中声明的类型。这些命名空间/类型名称可以在此编译单元中使用，就像它们在本地声明一样。

## 4.3 using 指令

使用 using 指令，可以使用在其他命名空间中定义的命名空间和类型，而不必完全限定它们。（非全局）using 指令的作用域延伸到最内层封闭命名空间（包括文件作用域命名空间）内的成员声明（如果有），否则延伸到整个编译单元。

### 4.3.1 using 命名空间指令

using 命名空间指令将给定命名空间的类型导入当前命名空间主体（或编译单元）。using 声明的命名空间中包含的类型可以直接引用。

```
using NAMESPACE_NAME;
```

例如，

```
namespace Olympic.Soccer { class Match { } }

    using Olympic.Soccer;
    class SoccerStats {

}
```

### 4.3.2. using static 指令

using static 指令导入某个类型的嵌套类型和静态成员，以便无需限定即可使用这些成员和类型的名称。

```csharp

```

例如，

```csharp
namespace Arithmetic {
    public class Adder {
        public static void Add(int a, int b) => a + b;
    }
}
namespace App {
    using static Arithmetic.Adder;
    class Calculator {
        public int Sum(int a, int b) => Add(a, b);
    }
}
```

### 4.3.3. using alias 指令

using alias 指令为最内层包含命名空间（或编译单元）内的某个命名空间或类型引入一个标识符（即别名）。由 using alias 指令引入的标识符可用于引用给定的命名空间或类型。

```csharp
using IDENTIFIER = NAMESPACE_OR_TYPE_NAME ;
```

例如，

```csharp
namespace Europe.Ukraine {
    public class Citizen ()
}
namespace World {
    using Person = Europe.Ukraine.Citizen;
    class Farmer: Person ()
}
```

## 4.4. 全局 using

通过关键字 global，可以使 using 声明在整个程序中生效。全局 using 声明可用于三种 using 声明类型中的任意一种：using namespace、using static 和 using alias。但是，全局 using 只能用于编译单元中，而不能用于显式声明的命名空间内，并且其作用域覆盖整个程序。例如，

```csharp
global using Machine;
global using static Robot.Arm;
global using Orange = Modern.Black;
```

# 5. C# 类型系统

C# 和 .NET 具有统一的类型系统。C# 语言中的每个类型都直接或间接继承自 .NET 上的 object 基类型。

C# 中的类型分为两大类：引用类型和值类型。值类型的变量可以直接包含其数据，而引用类型的变量存储对其数据的引用。只需将引用类型的值视为 object 类型，这些值就会被当作对象处理。另一方面，值类型的值通过执行装箱和拆箱操作而被当作对象处理。

泛型类型将在后面讨论。泛型类型参数可以指定值类型或引用类型。

在可空引用类型上下文中，引用类型的所有变量都是不可空的。可以通过在类型名称后追加 ? 符号来显式声明可空变量，该符号表示可空引用类型。例如，

```csharp
string firstName = "Pele";
string? middleName = null;
```

①

变量 firstName 是不可空的。

②

string? 是引用类型 string 的可空对应形式。变量 middleName 是可空的。

对于可空引用类型，编译器使用流分析来确保在访问任何可空引用类型的变量之前，或在将其赋值给不可空引用类型之前，检查该变量是否为 null。

## 5.3. 动态类型

所有 C# 类型（内置或用户定义）都使用静态绑定。也就是说，变量或表达式的类型在编译时确定。dynamic 类型是一个例外。它在运行时使用动态绑定。在大多数情况下，dynamic 可以被视为与 object 相同（因为所有类型最终都继承自 object）。

例如，

```csharp
dynamic theSecret = 42;
dynamic theGreatestUnknown = "meh";
```

从语法上讲，dynamic 类型的表达式在运行时可以隐式转换为任何类型。但是，如果转换失败，则会引发运行时异常。如果不希望使用动态绑定，可以先将表达式转换为 object，然后再转换为所需类型。例如，

```csharp
dynamic realSecret = 42 * 42 * 42;
int huh = realSecret;
string cops = realSecret;
```

①

此隐式转换将在运行时成功。

# 6. 常量

常量是表示常量值的变量，即可以在编译时计算的值。常量成员将在后面讨论，例如在类常量成员一节中。

可以使用局部常量声明语句声明局部常量。

```csharp
const TYPE NAME = EXPR ;
```

①

常量使用关键字 const 声明。在此类记法中，全部大写的单词是占位符。也就是说，在实际语句中，TYPE、NAME 和 EXPR 需要分别替换为类型、名称（或标识符）和表达式。在局部常量声明中，右侧的 EXPR 必须是常量表达式。

可以在单条语句中声明多个常量。例如，

```csharp
const TYPE NAME1 = EXPR1 , NAME2 = EXPR2 ;
```



The above statement is equivalent to the following two declarations:

```
const TYPE NAME1 = EXP1 ;
const TYPE NAME2 = EXP2 ;
```

The scope of a local constant is the block in which the declaration occurs, similar to local variables. Within the scope of a local constant, it is a compile-time error to declare another local variable or constant with the same name.

# 7. 变量

变量表示存储位置。每个变量都有一个类型，该类型决定了可以存储在变量中的值。

## 7.1. 变量类别

变量属于以下几个不同的类别：

- 局部变量，
- 静态变量，
- 实例变量，以及
- 数组元素。

此外，函数参数也是变量。

### 局部变量

局部变量可以在块中通过局部变量声明来声明。这样声明的局部变量不会自动初始化，因此没有初始值。

### 静态变量

使用 static 修饰符声明的字段是静态变量。静态变量的初始值是其类型的默认值。

### 实例变量

非静态字段是实例变量。类（或 record 或 struct）实例变量的初始值是变量类型的默认值。

### 数组元素

数组中每个元素的初始值都是数组元素类型的默认值。

## 7.2. 局部变量声明

### 7.2.1. 局部变量

局部变量声明声明一个或多个局部变量，类似于局部常量

```
TYPE NAME ;
TYPE NAME1 , NAME2 ;
```

①
如所述，我们在本书中使用这种 somewhat 不寻常的记法来表示 C# 语法。TYPE 和 NAME 分别需要在实际语句中替换为正确的类型和有效的变量名。语句以分号结束

②
可以在一个语句中声明多个具有相同类型的变量。此特定示例仅包含两个变量，但它说明了变量之间用逗号分隔

变量可以带初始化器声明。

```
TYPE NAME = EXPR ;
TYPE NAME1 = EXPR1 , NAME2 = EXPR2 ;
```

当所有变量都有初始化器时，可以省略显式的类型名而使用 var。例如，

```
var NAME = EXPR;
var NAME1 = EXPR1, NAME2 = EXPR2;
```

标识符 var 在局部变量声明的上下文中是一个上下文关键字。隐式类型局部变量的类型是从关联的初始化器表达式的类型推断出来的。

丢弃变量 _ 可用作隐式声明的变量，例如，当你打算忽略表达式的结果时。丢弃变量常用于 lambda 表达式或模式匹配。以下是一个简单的示例。

```
var _ = 1 + 2;
```

### 7.2.2. Ref 局部变量

ref 局部变量用于引用使用 return 返回的值

```
ref TYPE NAME = REF_EXPRESSION ;
ref var NAME = REF_EXPRESSION ;
```

你通过在两个地方使用 ref 关键字来定义 ref 局部变量：

Before the variable declaration.

Immediately before the call to the method that returns the value by reference.

### 7.2.3. Ref readonly 局部变量

ref readonly 局部变量类似于 ref 局部变量，但它们不可写。

```
```csharp
ref readonly TYPE NAME = REF_EXPRESSION ;
ref readonly var NAME = REF_EXPRESSION ;
```
```

请注意，你不能在 C# 中声明 "readonly local" 变量（有些人可能会认为这是严重的限制，考虑到 C# 语言在各处都提供了大量对不可变性的支持）。

## 8.1. 局部函数

局部函数声明如下：

Local function header, comprising

Optional and optional local function modifiers,

The return type or

The function name,

A type parameter in case of a generic local function,

A formal parameter list in a pair of parentheses, followed by

An optional type parameter constraint and

Local function body, comprising

A function body block, or

An expression body ending with a semicolon

例如，

```
~~~csharp
static (int, int) DoAdditionTwice(int a, int b) {
    var fstTime = LocalAdd();
    var sndTime = LocalAdd();
    return (fst, snd);

    void LocalAdd() => a + b; ①
}
~~~
```

①

LocalAdd 局部函数使用封闭作用域的局部变量，即 DoAdditionTwice 的两个参数。

局部函数与 lambda 函数一样是闭包。局部函数修饰符可以是 async 或 unsafe 或两者兼有。

## 8.2. 静态局部函数

静态局部函数是局部函数的一种特殊形式。它们明确禁止使用或捕获封闭作用域中的局部变量、参数和 this。它们不能使用类型的实例成员。语法上，静态局部函数声明包含 static 修饰符。例如，

```
```
static int AbsoluteValue(int a) {
    return LocalAbs(a);
    static int LocalAbs(int x) =>
        x > 0 ? x : -x;
}
```
```

①

LocalAbs 局部函数不使用封闭作用域中的任何变量，因此可以声明为 static。

# 9. 形式参数

函数参数也是变量。当我们调用匿名函数或函数成员（例如，方法、构造函数、访问器或运算符）时，参数就会创建。参数可以用调用中给出的参数值进行初始化。函数参数通常按值传递。但它们可以使用 in、ref 或 out 关键字使用按引用传递语义。

## 9.1. 参数列表

形式参数列表由逗号分隔的固定参数和末尾的可选 params 数组参数组成。固定参数由以下部分组成

Optional

An optional modifier, in or ref

The parameter type,

The parameter name, followed by

An optional default argument

每个固定参数声明一个给定类型且给定名称的变量，该变量是函数体局部的。

具有默认值的固定参数称为可选参数。非可选参数需要参数。可选参数（如果有）只能放在任何必需参数之后，在可选 params 数组之前。带有 in 或 ref 修饰符的参数不能有默认值。

in 修饰符，即 in 或 ref 仅允许在非泛型、非嵌套静态类中的静态方法的第一个参数上使用。这种方法称为扩展方法。

## 9.2. 参数属性

函数或方法的调用是一个表达式。

```
EXPRESSION ( ARGUMENT_LIST )
```

EXPRESSION 应该是“可调用的”，例如方法或委托类型的值。ARGUMENT_LIST 可以为空。它或多或少遵循与参数相同的结构，并且每个给定的参数必须在参数列表中有一个对应的参数。

C# 支持两种参数语法，位置参数和命名参数。命名参数的形式为 PARAMETER_NAME: VALUE，而位置参数仅指定 VALUE。当参数在参数列表中的位置与参数列表中对应参数的位置相同时，可以使用命名或位置参数语法。否则，只能使用命名参数语法。例如，给定以下函数，

```
static void Metodo(int a = 1, char b = 'b') {
    Console.WriteLine($"a = {a}; b = {b}");
}
```

我们可以按以下任何方式调用此函数：

```
Metodo();
```

```
Metodo(2);
Metodo(a: 2);
```

```
Metodo(b: 'c');
```

```
Metodo(4, 'd');
Metodo(a: 4, 'd');
Metodo(4, b: 'd');
Metodo(a: 4, b: 'a');
Metodo(b: 'a', a: 4);
```

①
两个参数都是可选的，因此在此调用中 a:1 且 b:'b'。

②
位置与命名参数语法。这两个方法调用彼此等价，a:2 且 b:'b'。

③
此参数的位置为 0，而其对应参数的位置为 1。因此，此特定方法调用不能对该参数使用位置语法。此调用等价于 Metodo(1, b: 'c') 或 Metodo(a: 1, b: 'c')。

④
以下五个方法调用都等价，a:4 且 b:'d'。



⑤ 此调用中方法参数 `a` 被称为“非尾随命名参数”，因为它位于位置参数 `'d'` 之前（例如）。

⑥ 此调用中的 `a` 和 `b` 必须使用命名参数语法。

## 9.3. `params` 参数

在 C# 中，形式参数列表中的最后一个参数可以是 `params` 数组参数，它由以下部分组成

- 可选
- `params` 关键字
- 一维数组类型，以及
- 参数名。

`params` 参数是值参数。（但请注意，数组是引用类型。）在方法调用中，`params` 参数的参数可以指定为数组值，也可以指定为零个、一个或多个数组元素类型的参数。例如，给定以下函数，

```csharp
static int AddAll(params int[] operands) => operands.Sum();
```

可以将其与 int 数组参数一起调用，

```csharp
var ints = new int[] { 1, 2, 3 };
var sum1 = AddAll(ints);
Console.WriteLine($"sum = {sum1}");
```

## 9.4. 值参数

未使用任何参数修饰符声明的形式参数默认为值参数。值参数对应于一个局部变量，其初始值来自函数中提供的相应参数。因此，参数应为可隐式转换为参数类型的表达式。

## 9.5. `in` 参数

使用 `in` 或 `ref` 修饰符的参数按引用传递。`in` 关键字指定被调用的方法不修改值。`in` 参数对应于局部 `ref readonly`。`in` 参数使用参数规范中的 `in` 修饰符声明，并且可以包含默认值。例如，

```csharp
static void PrintCoord(in Coord cord) =>
    Console.WriteLine($"Lat = {cord.Lat}; Lon = {cord.Lon}");
record struct Coord(float Lat, float Lon);
```

① `in` 参数 `cord` 使用按引用调用语义。`PrintCoord` 函数无法修改其值。

此函数可以带或不带 `in` 关键字调用。

```csharp
var coord = new Coord(40.0f, -100.0f);
PrintCoord(coord);
PrintCoord(in coord);
```

尽管它使用引用语义，但它不能更改 `in` 参数的值。因此，可以在不必担心数据可变性的情况下预期一定的性能提升。

## 9.6. `out` 参数

使用 `out` 修饰符声明的参数是输出参数。相应的参数按引用传递。例如，

```csharp
static void SetCoord(out Coord c) =>
    c = new(0.0f, 0.0f);
```

① `out` 参数在被赋值之前不能被引用，并且必须在函数返回之前被赋一个值。

要使用 `out` 参数，方法定义和调用方法都必须显式使用 `out` 关键字。您可以在方法调用的参数列表中声明一个新的 `out` 变量。例如，

```csharp
SetCoord(out var c);
Console.WriteLine($"Lat = {c.Lat}; Lon = {c.Lon}");
```

① 我们也可以使用显式类型，例如 `SetCoord(out Coord c)`。这或多或少等同于 `Coord c; SetCoord(out c);`。

## 9.8. 通过引用返回

### 9.8.1. Ref 返回

C# 方法默认按与参数按值传递类似的方式返回值。相比之下，`ref` 返回是方法通过引用返回给调用者的值。也就是说，而不是复制方法返回的值，而是返回其引用。（或者，更准确地说，复制其引用。）`ref` 返回正常工作有三个方面。

方法签名中的返回类型需要以 `ref` 为前缀。例如，`public ref MyStruct`。

方法体中 `return` 语句的表达式需要标记为 `ref`。例如，`return ref`。

为了使调用者能够修改对象的状态，`ref` 返回值需要被赋给一个 `ref` 局部变量。

### 9.8.2. Ref 只读返回

被调用的方法也可以将返回值声明为 `ref readonly` 以通过引用返回该值，同时强制调用代码不能修改返回值。调用方法可以通过将值存储在局部 `ref readonly` 中来避免复制返回值。例如，

```csharp
static class RefReturnDemo {
    static ref readonly Coord Move(ref Coord moving) =>
        ref moving; // return ref
    public static void PrintAfterMove(Coord here) {
        ref readonly var t = ref Move(ref here);
        Console.WriteLine($"Lat = {t.Lat}; Lon = {t.Lon}");
    }
}
```

# 10. 内置值类型

本章将介绍几种简单类型。内置的 `string` 类型将在下一章讨论。

## 10.1. `bool` 类型

C# `bool` 类型是 .NET `System.Boolean` 结构类型的别名，其值可以是 `true` 或 `false`。`bool` 类型的默认值是 `false`。也就是说，`default(bool)` 返回 `false`。

### 10.1.1. 可空的 `bool?` 类型

可空的 `bool?` 类型可用于三值逻辑，例如在处理支持三值布尔类型的数据库时。预定义的 `&` 和 `|` 运算符支持 `bool?` 操作数的三值逻辑。

## 10.2. `char` 类型

C# `char` 类型是 .NET `System.Char` 结构类型的别名，表示 UTF-16 编码中的 Unicode 字符。`char` 类型的默认值是 `'\0'`；也就是说，`default(char)` 返回 `'\0'`。

### 10.2.1. 字符字面量

您可以使用以下方式指定 `char` 值：

- 一个字符字面量。
- Unicode 转义序列；或
- 十六进制转义序列，例如 `\x` 后跟字符代码的十六进制表示。

## 10.3. 整数类型

C# 支持 11 种整数类型：四种无符号整数类型和四种有符号整数类型，均使用二进制补码格式表示。`char` 类型也是整数类型。此外，C# 还包括两种本机整数类型，`nint` 和 `nuint`。

| 类型 | 描述 |
| --- | --- |
| `byte` | 值范围为 0 到 255 的无符号 8 位整数 |
| `sbyte` | 值范围为 -128 到 127 的有符号 8 位整数 |
| `ushort` | 值范围为 0 到 65535 的无符号 16 位整数。 |
| `short` | 值范围为 -32768 到 32767 的有符号 16 位整数。 |
| `uint` | 值范围为 0 到 4294967295 的无符号 32 位整数。 |
| `int` | 值范围为 -2147483648 到 2147483647 的有符号 32 位整数。 |
| `ulong` | 值范围为 0 到 18446744073709551615 的无符号 64 位整数。 |
| `long` | 值范围为 -9223372036854775808 到 9223372036854775807 的有符号 64 位整数。 |

`checked` 和 `unchecked` 运算符和语句用于控制整数类型算术运算和转换的溢出检查。

## 10.4. 本机整数类型

C# 现在包含两个新的上下文关键字，`nint` 和 `nuint`，它们分别表示本机有符号和本机无符号整数类型，旨在用于低级库。这些上下文关键字仅在名称查找在该程序位置找不到可行结果时才被视为关键字。

C# 类型 `nint` 和 `nuint` 分别对应于底层的 .NET 类型 `System.IntPtr` 和 `System.UIntPtr`，编译器支持在特定平台或操作系统上将这些类型作为本机整数类型的额外转换和操作。

## 10.5. 浮点类型

C# 支持两种浮点类型，`float` 和 `double`，它们分别使用 32 位单精度和 64 位双精度 IEC 60559 格式表示。浮点数字面量在词法分析章节中描述。

## 10.6. `decimal` 类型

`decimal` 类型是 128 位实数类型，适用于高精度计算。内部 `decimal` 表示为按十的幂缩放的整数。十进制数保证至少有 28 位精度。`decimal` 类型的精度更高，但范围可能小于浮点类型。

如果 `decimal` 算术运算产生的结果的绝对值对于 `decimal` 来说太大，则会抛出 `System.OverflowException`。



## 11.1. 带引号字符串字面量

在 C# 中，字符串字面量可以写成三种不同形式，即带引号字符串字面量、逐字字符串字面量和原始字符串字面量。此外，C# 11 新增了一种用于 UTF-8 编码字符串的特殊字面量语法。带引号字符串字面量以双引号开始和结束。带引号字符串字面量必须转义某些特殊字符，例如，\n 表示换行，\t 表示制表符等。

## 11.2. 逐字字符串字面量

逐字字符串字面量以 @ 开头，并且也用双引号字符括起来。它们有时被称为“@ 引号字符串”。逐字字符串字面量中的特殊字符不需要、也不应转义，这使它们更易于编写。特别是，逐字字符串字面量会将换行字符保留为字符串文本的一部分。因此，逐字字符串便于表示多行字符串，或包含许多反斜杠等的字符串。在 @ 引号字符串中，双引号可以转义为两个引号

例如，

```
Console.WriteLine(@"""Hello world"" is
    really a cliche now.");
```

此语句将输出

```
"Hello world" is
    really a cliche now.
```

①

请注意，前导空白字符以及第一行末尾的换行符都会包含在输出中。

## 11.3. 原始字符串字面量

C# 11 引入了一种新形式的原始字符串字面量，它以三个或更多双引号字符序列开头，例如，并以相同的字符序列结尾，例如，双引号数量相同。

开头的双引号序列后面可以紧跟一个可选的换行符；在这种情况下，所括起来的字符串内容也应结束于一个换行符。这些换行符不是字符串字面量的一部分。当开头的双引号序列后面没有换行符时，原始字符串字面量不能包含换行符，并且结尾的双引号序列应位于同一行。

对于多行原始字符串，结尾双引号序列的起始位置为所括字符串字面量内容设定了“修剪行”。也就是说，字符串字面量中该位置之前的空格不被视为字符串的一部分。例如，

```
var xml = """
    <element attr="content">
        <body>My body</body>
    </element>
""";
```

## 11.5. 字符串插值

插值字符串由 $ 前缀标识，并且可以在大括号中包含（待）插值的表达式。字符串插值可获得与 String.Format 方法相同的结果，但通常更受青睐，因为它往往能提高代码的可读性和可维护性。

### 11.5.1. 常量插值字符串

从 C# 10 起，当插值字符串中的所有插值表达式都是常量时，该字符串被视为常量表达式。

```csharp
const int year = 2022;
const string wc = $"World Cup {year}";
const string greeting = $"Welcome to {wc}!";
```

### 11.5.2. 逐字字符串插值

C# 还允许逐字字符串插值，即对逐字字符串字面量进行字符串插值，使用 $@ 或 @$ 语法。例如，

```
var myAnswer = "Huh?";
var conversation = $@"Tom: What do you say?
Me: {myAnswer} {myAnswer}";
```

### 11.5.3. 原始字符串插值

字符串插值也可用于（单行或多行）原始字符串字面量。在这种情况下，字面量开头存在的美元符号数量决定启动插值表达式所需的大括号数量。任何大括号数量少于该数量的大括号序列都仅被视为内容，并包含在输出中。例如，

```
var json = $"""
{
  "content": { "title": "Raw Oyster" },
  "length" : {{value,Length}}
};
"""
```

## 12.1. 泛型类型参数

### 12.1.1. 类型参数

泛型类型（以及泛型方法等）包括一个或多个类型参数（位于尖括号内）。通过为这些类型参数声明特定类型，会创建一个特定的构造类型。

类型参数是一个标识符，用于指定该参数要绑定到的值类型或引用类型。由于类型参数可以用许多不同的类型实参来实例化，因此类型参数的操作和限制与其他（实际）类型略有不同。例如，在泛型类型声明中，类型参数不能直接用于声明基类或接口。

作为一种类型，类型参数纯粹是编译时构造。在运行时，每个类型参数都绑定到通过在泛型类型声明中提供类型实参而指定的运行时类型。涉及类型参数的所有语句和表达式的运行时执行，都使用作为该参数的类型实参所提供的类型。

### 12.1.2. 类型参数约束

类型约束指示类型实参应具有哪些能力。约束使用上下文关键字 where 指定。如果使用的类型实参不满足给定约束，编译器将发出错误（或在某些情况下发出警告）。

## 12.2. 类型参数约束

在过去几个 C# 版本中，对泛型类型约束的支持在语法和语义方面都得到了极大扩展。截至 C# 11，目前支持以下类型的类型参数约束。

### 12.2.1. notnull 约束

```
class <T> where T : notnull { }
```

类型实参 T 必须是非可空类型。可以使用 notnull 约束来指定类型实参必须是非可空值类型或非可空引用类型。与大多数其他约束不同，如果类型实参违反 notnull 约束，编译器会生成警告而不是错误。

### 12.2.2. default 约束

```
class <T> where T : default { }
```

default 约束意味着基方法没有 class 或 struct 约束。当你重写方法或提供显式接口实现且需要指定无约束的类型参数时，此约束可解决歧义。

### 12.2.3. new() 约束

```
class <T> where T : new() {}
```

new() 约束断言 T 必须具有公共无参数构造函数。当与其他约束一起使用时，new() 约束必须最后指定。

### 12.2.4. enum 约束

```
class <T> where T : System.Enum { }
```

可以将任何 System.Enum 类型用作基类。使用 enum 约束后，类型参数 T 可以与 System.Enum 静态方法一起使用。T 也可以用于需要特定枚举类型的上下文中。

### 12.2.5. 委托约束

```csharp
class C1<T> where T : System.Delegate { }
class C2<T> where T : System.MulticastDelegate { }
```

泛型类型实参 T 必须是 System.Delegate 或 System.MulticastDelegate 类型。委托约束使你能够编写以类型安全的方式使用委托的代码。

### 12.2.6. struct 约束

```
class <T> where T : struct { }
```

类型实参 T 必须是非可空值类型。由于所有值类型都具有可访问的无参数构造函数，struct 约束隐含 new() 约束，并且它们不能组合使用。

### 12.2.7. class 约束

```
class<T> where T : class { }
```

此约束断言 T 必须是非可空引用类型。它适用于……或者当类型实参为可空引用类型时，会发出警告。

### 12.2.8. class? 约束

```
class<T> where T : class? { }
```

它断言 T 必须是引用类型，无论是可空还是非可空。

### 12.2.9. 接口类型约束

```
class <T> where T : I1, I2, I3<T> { }
```

可以指定一个或多个特定接口作为类型约束的一部分。在这种情况下，类型实参必须是继承给定接口的接口，或实现给定接口的非可空类型，例如本示例中的 I1、I2 和 I3。

如所示，约束接口可以是泛型的。它必须是实现指定接口的非可空类型，

```
class <T> where T : I1, I2, I3<T?> { }
```

此约束等同于上一个示例 T : I1, I2，不同之处在于 T 可以是可空或非可空引用类型，以及非可空值类型。




### 12.2.10. 基类类型约束

```
class C<T> where T : B1 { }
```

类型实参必须是或派生自指定的基类，例如，T 必须是从指定基类派生的不可为 null 的引用类型

```
class C<T> where T : B1? { }
```

同样，类型实参必须是或派生自指定的基类，T 可以是可为 null 或不可为 null 的类型。

### 12.2.11. 特定类型约束

```
class C<T, U> where T : U { }
```

类型实参 T 必须是 U 类型，或派生自 U 类型。

如果 U 是不可为 null 的引用类型，则 T 必须是不可为 null 的引用类型。

如果 U 是可为 null 的引用类型，则 T 可以为 null 或不可为 null。

## 12.3. 泛型中的类型变体

在 C# 中，类型变体支持对数组类型、委托类型和泛型类型参数进行隐式引用转换，以便可以使用更宽泛或更具体的类型。变体（协变或逆变）支持引用类型，但不支持值类型。

### 12.3.1. 协变

协变使你可以使用比泛型参数所指定的类型更派生的类型。这允许实现协变接口的类进行隐式转换，以及委托类型的隐式转换。具有协变类型参数的[接口](#)使其方法能够返回比该类型参数所指定的类型更派生的类型。
