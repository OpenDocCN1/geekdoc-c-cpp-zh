### 3.2.3 运算符和其他标点

运算符用于表示表达式中涉及一个或多个操作数的运算。标点用于分组和分隔。

```
{ } [ ] ( ) . , : ;
+ - * / % & | ! ~
= < > ? ?? :: ++ -- &&
-> == != <= >= += -= *= /=
%= ^ << <<= => >> >>=
```

### 3.3 字面量

另一类重要的标记是字面量，它们以文本形式表示某些内置类型的（常量）值。例如，默认字面量表示类型的默认值，下文将讨论。内插字符串在词法上也是字面量，但通常它们是（非常量）表达式。

### 3.3.1 null 字面量

null 字面量表示 null 值。null 值本身没有类型，但可以通过 null 字面量转换转换为任何可空引用类型或可空值类型。

### 3.3.2 布尔字面量

C# 中有两个布尔字面量值：true 和 false。这些 bool 字面量的类型是 bool。

### 3.3.3 整数字面量

整数字面量用于写入 int、uint、long 和 ulong 的值。它们有三种可能的形式：十进制、十六进制和二进制。

```
1_234
5678u
-10000000L
10_000_000uL
```

- ① 一个 int 整数字面量。
- ② 一个 uint 整数字面量。使用后缀 `u` 或 `U`。
- ③ 一个 long 整数字面量。使用后缀 `l` 或 `L`。
- ④ 一个 ulong 整数字面量。使用 `u`/`U` 和 `l`/`L` 的组合。

注意，（语义上不重要的）下划线 `_` 可用于整数字面量中，但开头和结尾位置除外。下划线不能连续重复。

### 3.3.4 实数字面量

实数字面量用于写入浮点类型 float 和 double 以及 decimal 的值。

```
1_234.567
1000d
10.5e5f
19.99m
```

- ① 一个 double 字面量。
- ② 一个 double 字面量。可使用后缀 `d` 或 `D`。
- ③ 一个 float 字面量。使用后缀 `f` 或 `F`。
- ④ 一个 decimal 字面量。使用后缀 `m` 或 `M`。

实数字面量中也可以使用不连续的下划线 `_`，但整数部分和小数部分的开头和结尾位置除外。下划线不影响实数字面量的值。

### 3.3.6 字符串字面量

C# 支持几种不同形式的字符串字面量。它们将在[字符串](strings)一章中详细讨论。

### 3.4 编译器指令

在 C# 中，编译器指令也称为“预处理指令”，它们作为词法分析阶段的一部分进行处理（例如，不是作为单独的预处理步骤）。它们可用于有条件地跳过编译单元的各节、报告错误和警告条件，或标记源代码的特定区域。

可用的预处理指令如下：

- `#undef` — 用于定义和取消定义条件编译符号。
- `#endif` — 用于根据编译符号跳过代码段。
- `#line` — 用于控制为错误和警告发出的行号。自 C# 10 起，`#line` 指令最多可接受 5 个十进制数作为参数，例如起始行、起始字符、结束行、结束字符和字符偏移量。
- `#error` — 用于发出错误或警告。
- `#nullable` — 用于启用或禁用[可空](#)。
- `#endregion` — 用于分别显式标记源代码节的开始和结束。主要供 IDE 使用。
- `#pragma` — 用于指定编译器预定义的编译符号。

## 4. 命名空间

编译单元（例如 C# 源代码文件）按照以下线性结构组织：

- 零个或多个 extern 别名指令，
- 零个或多个全局 using 指令（它们影响程序中的所有编译单元），
- 零个或多个（特定于源文件的）using 指令，
- 零个或多个全局特性，以及
- 零个或多个命名空间及其成员声明，或
- 一个文件作用域命名空间及其成员声明。

C# 程序默认使用（匿名的）全局命名空间，除非成员声明包含在显式命名空间声明中（文件作用域或其他形式）。

### 4.1 命名空间声明

从 C# 10 及更高版本开始，命名空间可以在有或没有显式块的情况下声明。没有块的命名空间的作用域延伸到整个编译单元/文件。“普通”块作用域命名空间由关键字 `namespace`、命名空间名称、主体和可选分号组成。例如，

```
namespace War {
    // Any member declarations
}
```

① 此命名空间的名称是 `War`。注意，单个编译单元中可以包含多个（可能嵌套的）带显式块的命名空间。

另一方面，文件作用域命名空间以关键字 `namespace`、名称和分号开头。编译单元的其余部分遵循相同的总体结构，例如零个或多个 extern 别名指令、using 指令（但不是全局 using 指令），随后是任何成员类型声明，它们都属于此命名空间。例如，

```
namespace Peace;
// ...
```

① 此命名空间声明延伸到源文件末尾。如果源文件包含（可能嵌套的）文件作用域命名空间声明，则它不能在同一编译单元中包含任何其他命名空间声明。

嵌套的文件作用域命名空间可以使用点限定名称声明。例如，

```
namespace Crime.Punishment;
// ...
```

上述声明例如等效于以下内容：

```
namespace Crime {
  namespace Punishment {
    // ...
  }
}
```

### 4.2 extern 别名指令

extern 别名指令为外部命名空间引入一个别名。例如，

```
extern alias Fruit;
Fruit::Apple apple;
```

① 它引入一个外部别名 `Fruit`。
② `Apple` 是在命名空间 `Fruit` 中声明的类型。这些命名空间/类型名称可以在此编译单元中使用，就像它们在本地声明一样。

### 4.3 using 指令

使用 using 指令，可以使用在其他命名空间中定义的命名空间和类型，而不必完全限定它们。（非全局）using 指令的作用域延伸到最内层封闭命名空间（包括文件作用域命名空间）内的成员声明（如果有），否则延伸到整个编译单元。

### 4.3.1 using 命名空间指令

using 命名空间指令将给定命名空间的类型导入当前命名空间主体（或编译单元）。using 声明的命名空间中包含的类型可以直接引用。

```
using NAMESPACE_NAME;
```

例如，

```
namespace Olympic.Soccer { class Match { } }
namespace Stats {
    using Olympic.Soccer;
    class SoccerStats {
        IList<Match> Matches { get; set; }
    }
}
```
