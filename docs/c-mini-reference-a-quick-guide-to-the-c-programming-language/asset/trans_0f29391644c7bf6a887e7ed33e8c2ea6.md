
## 11.1. 带引号字符串字面量

在 C# 中，字符串字面量可以写成三种不同形式，即带引号字符串字面量、逐字字符串字面量和原始字符串字面量。此外，C# 11 新增了一种用于 UTF-8 编码字符串的特殊字面量语法。带引号字符串字面量以双引号开始和结束。带引号字符串字面量必须转义某些特殊字符，例如，\n 表示换行，\t 表示制表符等。

## 11.2. 逐字字符串字面量

逐字字符串字面量以 @ 开头，并且也用双引号字符括起来。它们有时被称为“@ 引号字符串”。逐字字符串字面量中的特殊字符不需要、也不应转义，这使它们更易于编写。特别是，逐字字符串字面量会将换行字符保留为字符串文本的一部分。因此，逐字字符串便于表示多行字符串，或包含许多反斜杠等的字符串。在 @ 引号字符串中，双引号可以转义为两个引号

例如，

```
Console.WriteLine(@"""Hello world"" is
    really a cliche now.");
```

此语句将输出

```
"Hello world" is
    really a cliche now.
```

①

请注意，前导空白字符以及第一行末尾的换行符都会包含在输出中。

## 11.3. 原始字符串字面量

C# 11 引入了一种新形式的原始字符串字面量，它以三个或更多双引号字符序列开头，例如，并以相同的字符序列结尾，例如，双引号数量相同。

开头的双引号序列后面可以紧跟一个可选的换行符；在这种情况下，所括起来的字符串内容也应结束于一个换行符。这些换行符不是字符串字面量的一部分。当开头的双引号序列后面没有换行符时，原始字符串字面量不能包含换行符，并且结尾的双引号序列应位于同一行。

对于多行原始字符串，结尾双引号序列的起始位置为所括字符串字面量内容设定了“修剪行”。也就是说，字符串字面量中该位置之前的空格不被视为字符串的一部分。例如，

```
var xml = """
    <element attr="content">
        <body>My body</body>
    </element>
""";
```

## 11.5. 字符串插值

插值字符串由 $ 前缀标识，并且可以在大括号中包含（待）插值的表达式。字符串插值可获得与 String.Format 方法相同的结果，但通常更受青睐，因为它往往能提高代码的可读性和可维护性。

### 11.5.1. 常量插值字符串

从 C# 10 起，当插值字符串中的所有插值表达式都是常量时，该字符串被视为常量表达式。

```csharp
const int year = 2022;
const string wc = $"World Cup {year}";
const string greeting = $"Welcome to {wc}!";
```

### 11.5.2. 逐字字符串插值

C# 还允许逐字字符串插值，即对逐字字符串字面量进行字符串插值，使用 $@ 或 @$ 语法。例如，

```
var myAnswer = "Huh?";
var conversation = $@"Tom: What do you say?
Me: {myAnswer} {myAnswer}";
```

### 11.5.3. 原始字符串插值

字符串插值也可用于（单行或多行）原始字符串字面量。在这种情况下，字面量开头存在的美元符号数量决定启动插值表达式所需的大括号数量。任何大括号数量少于该数量的大括号序列都仅被视为内容，并包含在输出中。例如，

```
var json = $"""
{
  "content": { "title": "Raw Oyster" },
  "length" : {{value,Length}}
};
"""
```

## 12.1. 泛型类型参数

### 12.1.1. 类型参数

泛型类型（以及泛型方法等）包括一个或多个类型参数（位于尖括号内）。通过为这些类型参数声明特定类型，会创建一个特定的构造类型。

类型参数是一个标识符，用于指定该参数要绑定到的值类型或引用类型。由于类型参数可以用许多不同的类型实参来实例化，因此类型参数的操作和限制与其他（实际）类型略有不同。例如，在泛型类型声明中，类型参数不能直接用于声明基类或接口。

作为一种类型，类型参数纯粹是编译时构造。在运行时，每个类型参数都绑定到通过在泛型类型声明中提供类型实参而指定的运行时类型。涉及类型参数的所有语句和表达式的运行时执行，都使用作为该参数的类型实参所提供的类型。

### 12.1.2. 类型参数约束

类型约束指示类型实参应具有哪些能力。约束使用上下文关键字 where 指定。如果使用的类型实参不满足给定约束，编译器将发出错误（或在某些情况下发出警告）。

## 12.2. 类型参数约束

在过去几个 C# 版本中，对泛型类型约束的支持在语法和语义方面都得到了极大扩展。截至 C# 11，目前支持以下类型的类型参数约束。

### 12.2.1. notnull 约束

```
class <T> where T : notnull { }
```

类型实参 T 必须是非可空类型。可以使用 notnull 约束来指定类型实参必须是非可空值类型或非可空引用类型。与大多数其他约束不同，如果类型实参违反 notnull 约束，编译器会生成警告而不是错误。

### 12.2.2. default 约束

```
class <T> where T : default { }
```

default 约束意味着基方法没有 class 或 struct 约束。当你重写方法或提供显式接口实现且需要指定无约束的类型参数时，此约束可解决歧义。

### 12.2.3. new() 约束

```
class <T> where T : new() {}
```

new() 约束断言 T 必须具有公共无参数构造函数。当与其他约束一起使用时，new() 约束必须最后指定。

### 12.2.4. enum 约束

```
class <T> where T : System.Enum { }
```

可以将任何 System.Enum 类型用作基类。使用 enum 约束后，类型参数 T 可以与 System.Enum 静态方法一起使用。T 也可以用于需要特定枚举类型的上下文中。

### 12.2.5. 委托约束

```csharp
class C1<T> where T : System.Delegate { }
class C2<T> where T : System.MulticastDelegate { }
```

泛型类型实参 T 必须是 System.Delegate 或 System.MulticastDelegate 类型。委托约束使你能够编写以类型安全的方式使用委托的代码。

### 12.2.6. struct 约束

```
class <T> where T : struct { }
```

类型实参 T 必须是非可空值类型。由于所有值类型都具有可访问的无参数构造函数，struct 约束隐含 new() 约束，并且它们不能组合使用。

### 12.2.7. class 约束

```
class<T> where T : class { }
```

此约束断言 T 必须是非可空引用类型。它适用于……或者当类型实参为可空引用类型时，会发出警告。

### 12.2.8. class? 约束

```
class<T> where T : class? { }
```

它断言 T 必须是引用类型，无论是可空还是非可空。

### 12.2.9. 接口类型约束

```
class <T> where T : I1, I2, I3<T> { }
```

可以指定一个或多个特定接口作为类型约束的一部分。在这种情况下，类型实参必须是继承给定接口的接口，或实现给定接口的非可空类型，例如本示例中的 I1、I2 和 I3。

如所示，约束接口可以是泛型的。它必须是实现指定接口的非可空类型，

```
class <T> where T : I1, I2, I3<T?> { }
```

此约束等同于上一个示例 T : I1, I2，不同之处在于 T 可以是可空或非可空引用类型，以及非可空值类型。
