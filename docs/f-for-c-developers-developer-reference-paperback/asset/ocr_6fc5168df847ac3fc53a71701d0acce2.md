# Handling Exceptions

The async keyword seems to work nicely with the APM, but how about exception handling? Is it possible to handle the exception as you would code in that that is executed sequentially? The answer is "Yes.\ Listing 6-81 shows how to handle an exception inside of an asynchronous workflow.

LISTING 6-81 Asynchronous workflow exception handler

```
open System
let asyncOperationWithException =
    try
        // some operations could throw an exception
        with
            | DivideByZeroException as e -> printfn "divided by zero"
            | ArgumentException as e -> printfn "this is an argument exception"
```

You might have noticed immediately that this code is not safe. If failwith is put into the try section, the process can be broken down. Catch! The most obvious solution is to add an extra handler function in Listing 6-81. Another approach is to use the Async.StartWithContinuation function, as shown in Listing 6-80. If you like a more F#-oriented approach, examine Listing 6-82, which uses Async.Catch to solve the problem. The FSI result shows that a System.Exception with a "my error" message is caught.

LISTING 6-82 Handling an exception using Async.Catch

```
open System
let asyncOperationWithException =
    try
        Failwith "my error"
        with
            | DivideByZeroException as e -> printfn "divided by zero"
            | ArgumentException as e -> printfn "this is an argument exception"
asyncOperationWithException
| Async.Catch
| Async.RunSynchronously
| function
    | Choice10f2  -\> printfn "everything is good. No exception"
    | Choice20f2 ex -> printfn "caught error: %A" ex
```
