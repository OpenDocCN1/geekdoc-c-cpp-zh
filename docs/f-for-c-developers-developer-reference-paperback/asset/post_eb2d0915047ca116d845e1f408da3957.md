
In addition, the adapter pattern introduces the GI function, which breaks class encapsulation and makes possible communication between objects that do not share a common base class. It is not a recommended way to use the original object-oriented design; however, it is a feasible approach to wrap code because of inaccessibility to the source code. Likewise, F# provides this approach, and I'll leave the decision to you regarding when and how to use it.

It is totally fine to use standard object-oriented approach when doing design, especially when someone is new to the language. If you are motivated to use F# to write design, here are some principles that used to implement the design patterns in this chapter. If the design pattern is behavior design, its main focus is on how to organize the function, so consider using function composition pipeline operators. If the function needs to be organized into a unit, put the function into a module and use expressions to organize the function. If the design pattern is structural design, extra structure is needed. If the extra structure is needed to make unrelated objects work together, the GI function could be a good candidate to simplify the design. F# is a young language and how to properly apply its language into the system design is still a new topic. Keep in mind that F# provides OOP way of implementing class encapsulation, inheritance, and polymorphism. This chapter is only a small step to explore how to use F# in system design.

## CHAPTER 4: Type Providers

3.0 introduces a new feature called type providers. The major application of a type provider is to provide features for working within a data-rich environment. One example of data-rich environment is the database. One major problem when programming database is how to generate code for tables, stored procedures, and other database objects. Not every developer prefers to write database access code manually, and tooling is something developers always desire. Ideally, you could interact with data rich environment using Visual Studio features such as IntelliSense. Using IntelliSense would make it easier to write the necessary code, and would save the time otherwise to continually go back to check the database schema.

The SQL type provider is designed to solve this problem, and is shipped with Visual Studio 2012. One of the benefits you get with type providers is that they bring database or web service information to your fingertips in the form of IntelliSense. As a result, when you type, the remote data is retrieved, which helps you finish your coding more quickly. If you're familiar with generation tools such as SqlMetal.exe, you can think of type provider as a wrapper around the Visual Studio development environment (IDE).

The following built-in type providers can be used to access data from databases and web services:

- LINQ-to-SQL
- SQL Entity
- Web Services Language (WSDL)
- Open Data Protocol (OData)

This chapter focuses on how to use these type providers and F# queries. It also shows how to use type providers to access the Microsoft Azure Marketplace.

The type provider accepts a string value for its connection string. The value can be accessed only at runtime, and it is very difficult to use a run-time value to generate design time logic. One way to work around this is to use the Literal attribute and conditional compile symbols. The sample code is shown in Listing 4-2. This trick can work for all type providers. #### LISTING 4-2 Using the conditional symbol and constant with type providers

```fsharp
#if DEVELOPMENT

<Literal>

#else
<Literal>

#endif

// define a type provider with constant value
type T = Microsoft.FSharp.DataProvider.SqlDataConnection<ConnectionString=conStr>
let db = T.GetDataContext()
```

Using conditional compilation symbols is not a best practice when creating assemblies, it is totally fine when writing an F# script.
