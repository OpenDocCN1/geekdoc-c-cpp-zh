```
// object expression with abstract class and interface
let objExpressionInterfaceAbstract =
{
    new MyAbstractClass() with
        override this.F0() = printf "implement the abstract class"
        interface IInterface2 with
            member this.F2() = printf "from interface2"
}

// override the ToString method using object expression
let objExpressionExtendObject =
{
    new System.Object() with
        override this.ToString() = "hello from object expression"
}
```

As in C#, the base class (which contains some concrete class member implementations) must come before all interfaces in the derived class definition. In an F# object expression, an abstract class must be present before any. In other words, the code will not compile if MyAbstractClass is put after IInterface2 in the objExpressionInterfaceAbstract.

Listing 6-8 is a real-world example that implements a WPF command. WPF commands usually do not involve the construction of a class hierarchy. It is a perfect place to use an object expression. From the sample code, you can see the object expression can have fields that cannot be accessed directly from outside. The variable event1 can be viewed as a private field implemented in the object expression. This example also shows that an object expression with parameters, like in createCommand, can serve as a class factory to create objects based on passed-functions.

LISTING 6-8 WPF command using an object expression

```
// class factory to generate the WPF command execute=
let createCommand action canExecute =
    let event1 = Event<, _>()
        new ICommand with
            member this.CanExecute(obj) = canExecute(obj)
            member this.Execute(obj) = action(obj)
            member this.add_CanExecuteChanged(handler) =
                event1.Publish.AddHandler(handler)
            member this.remove_CanExecuteChanged(handler) =
                event1.Publish.RemoveHandler(handler)
```
