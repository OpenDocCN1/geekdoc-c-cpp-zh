# Using the XML Type Provider

This section shows you how to use the XML type provider's design-time feature. The definition of the type provider shows that it is a design-time adapter component. The example I present in this section explores the design-time part of the definition. Many applications use XML files as feeds of input data. The problem with this approach is that XML can become complicated and errors in this text file can be checked only at runtime. The XML type provider moves validation that is typically done during run time to design.

InvokeMethod in Provided returns a code quotation, and it can also contain other code. The quotation will be executed at runtime, whereas the other code is executed at design time. This is where the validation code can be inserted and executed.

The production code and the sample XML file are shown in Listing 5-37 and Listing 5-38, respectively. Both listings require that the XML file meet certain criteria: the start value must be equal or smaller than the end value. If the validation can happen only at runtime, that could be a disaster. Another approach is to use a validation tool, such as a check-in gate validator. None of these approaches provide a comparable coding experience if this validation can be performed on time. When a user invokes the method, he will see the error right away.

LISTING 5-37 Production code is invoked by the type provider

```fsharp
type MyProductionCode()
```
