```
// post the message
agent.Post "hello"
agent.Post "world"
```

At this point, you might be thinking that an agent is directly mapped to a thread. Luckily, this is not true. The mailbox processor is backed up by the ThreadPool. A mailbox processor is logically threaded at the back end, For example, to send 100 messages to 1 box, one thread is needed to process them. Sending 100 threads to 100 mailboxes will use X threads, where X is a number chosen by the ThreadPool. Listing 6-89 creates 100,000 agents. A 32-bit machine can barely create several threads, so this shows that the agent is not directly mapped to a thread. The execution result shows the execution time in FSI with the thread switch to ON. The mailbox processor can handle 100,000 messages in just two to three seconds!

**LISTING 6-89** Creating 100,000 agents

```
// rename the mailbox processor to Agent
type Agent<T> = MailboxProcessor<T>

// create agents
let agents =
[1 .. 100 * 1000]
| List.map (fun n ->
    Agent.Start(fun n ->
        async {
            while true do
                let! msg = n.Receive()
                if i % 20000 = 0 then
                    printf "agent %d got message %s" i msg
        })
)

// post message to all agents
for agent in agents do
    agent.Post "hello"
```

It's rare for an agent to exist in isolation. Often, you need to interact with other aspects of your code from within the body of an agent. One approach for accomplishing this is to publish an event from an agent to communicate with the outside world. Listing 6-90 fires an event for every 30,000 messages that are received.
