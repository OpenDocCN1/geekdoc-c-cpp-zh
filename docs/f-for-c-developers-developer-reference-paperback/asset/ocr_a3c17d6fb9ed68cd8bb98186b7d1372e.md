# Foreword

People often ask, "What can F# do C# cannot?" In this book, you will discover what of F# can do! You will see familiar things such as object programming and design patterns. Further, you will also see powerful new things like pattern matching, piping, first-class events, object expressions, options, tuples, records, discriminated unions, active patterns, agents, computation expressions and, perhaps most distinctively, type providers.

However, we also need to ask the other question: "What can C# do F# cannot?" There is one important part to this answer that I will focus on: C# can cause NullReferenceExceptions. "What?" I hear you. Does F# not have nulls? Right! Perhaps the most important thing that C# programmer needs to know is that F# does not use nulls in routine programming.

Let's look at some evidence. People using F# at a major UK company did a study of two similar ETL (Extract, Transform, Load) applications. Broadly speaking, the applications were in the same zone of functionality or, if anything, the F# application implemented more features. The F# project had a very low bug rate, and was 26 times smaller. The size difference is not only the result of language differences; there are also differences in design methodology. The C# project is characterized by the inappropriate verbose of elaborate object abstractions seen in Java projects—for example, elaborate and unnecessary class hierarchies.

Interestingly, the comparison records that the C# project had 3036 null checks, where a functionally similar F# project had 27, a reduction of 112 times in the total of null checks. The other statistics in the comparison are also compelling, particularly the "defects since live": the F# code had zero defects since "live," and the C# code had "too many." These are not unrelated; nulls cause defects. In my opinion, the lack of nulls in routine coding makes it worth switching your programming teams to F# where possible.

In this book, you will learn many wonderful things about F#. But don't lose sight of the big picture: F# is about writing accurate, correct, efficient, interoperable code that gets deployed in time enterprise scenarios. This does partly by removing the pernicious evils of nulls. If you and your team embrace it, then also being equal, your life will be simpler, happy, and more productive.
