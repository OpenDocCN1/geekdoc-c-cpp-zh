
## Type Inferences

At this point, you might be wondering why you don't have to specify type information writing the F# code shown in Listing 1-13. You might get the wrong impression that F# is a scripting language or a dynamic language, which usually do not emphasize the type. Actually, this is not true; F# is a strongly typed language. F# provides the ability to leave off definitions through a feature called type inference, which can identify type information based on how code is used. Listing 1-77 shows the function f and how its definition is shown in F#. The type for s can be determined by the call System.String.IsNullOrEmpty, which takes a string and returns a Boolean. This is how F# identifies the type information.

LISTING 1-77 A type inference sample

```
> let f s = System.String.IsNullOrEmpty s;

val f : string -> bool
```

Type inference works great, but it will need help sometimes, such as when processing overloaded methods, because overloaded methods distinguish themselves from each other by parameter type. For example, in Listing 1-78, the LastIndexOf method can get both char and string as input. You did not expect that the compiler could read your mind, did you? Because the variable ch can be either the string or char type, you have to specify the type for the variable ch. If you do not tell the parameter type, there is no way for F# to figure out which overloaded method to use. The correct code is shown in Listing 1-79.

LISTING 1-78 The type inference when using overloaded methods

```
> let f ch = "abc".IndexOf(ch);

let f ch = "abc".IndexOf(ch);
~~~~~~~~~~~~~~~~~~~
```

stdin(10,12): error F50041: A unique overload for method 'IndexOf' could not be determined based on type information prior to this program point. A type annotation may be needed. Candidates: System.String.IndexOf(value: char) : int, System.String.IndexOf(value: string) : int

LISTING 1-79 The type inference with type specified

```
> let f (ch:string) = "abc".IndexOf(ch);

val f : string -> int
```

It’s good to understand how type inference process work. It is performed from top to bottom and from left to right. It does not start from the program’s main function. So the code in Listing 1-80 does not compile. The string type cannot be inferred from the str.Length because there are tons of types in .NET that have a Length property.

## LISTING 1-80 The type inference from top to bottom

```
let f str = str.Length // str type cannot be determined

[EntryPoint]
let main argv =
    let result = f "abc"
    0 // return an integer exit code
```

Note It is a best practice to write the code as you go and let the F# compiler figure out the type for you. If there is an error, look at the code above the line the error is pointing to. These errors can be easily fixed by providing type information. Type inference is processed from top to bottom, which could not be the order of how code is executed. The program entry point is usually located at the end of the file, decorating the variable at entry point does not help.

IntelliSense uses a different way to provide type information for users. Sometimes IntelliSense shows the type information but the code will not compile. A simple code example is shown next. The type for str on the second line is unknown, although IntelliSense shows that str is of the System.String type.

```
let f str =
    let len = str.Length // str type is unknown
    str + "aa"
```

## Interop and Function Parameters

Some F# users start to use F# as a library authoring tool. The F# library is then referenced and invoked from C# application. Because F# is a .NET language, using interop with other languages is seamless. Adding a reference to F# project is exactly as adding one to C# project. The only thing that needs be explained is how to add a reference to:

1. Use #r to reference a DLL.
2. Open the namespace.

Listing 1-83 shows how to reference System.Core.dll, open the Collections.Generic namespace, and use HashSet<>.

## LISTING 1-83 Creating a HashSet in F# script file or in FSI

```
#r "System.Core"
open System.Collections.Generic
let a = HashSet<int>()
```

Note F# does not need new to instantiate an object. However, the new keyword is recommended when the class implements IDisposable interface.

Compared to C#, there is little difference in approach for invoking .NET method in F#. Here’s how to use a .NET method to convert a string to an integer:

```
System.Convert.ToInt32("2")
```

Passing a tuple to C# function seems well until you have a function that requires an out parameter. Tuples do not provide a way to say a value is ref or out, but a tuple does help to solve this problem.

```cs
public int SharpFunction(int k, out int n)
```

the function actually returns two values to the invoker. So the solution is to declare a tuple to hold the returned values:

```
let returnValue, n = SharpFunction(1)
```

This approach works for the method, which is not externally declared. A call to an externally declared method requires the & operator. Listing 1-84 shows how to handle an out parameter in an extern function.

## LISTING 1-84 Using F# to expose a C# extern function that has an out parameter

```cs
C# function definition
[DllImport("MyDLL.dll")]
public static extern int SharpFunction(IntPtr inRef, out IntPtrPtr);
```

Define and invoke the function in F# FSI:

```
[System.Runtime.InteropServices.DllImport("something.dll")]
extern int SharpFunction(IntPtr inRef, out IntPtrPtr);
let mutable myOutPtr
let n = SharpFunction(0, myOutPtr)
```

If you want to expose an out parameter to a C# project, you need a special attribute named System.Runtime.InteropServices.Out. By decorating a parameter with this attribute in F#, the C# invoker can see that the parameter is intended to be an out parameter. See the sample in Listing 1-85. The byref keyword is used to declare the variable as passed in a reference type.

## LISTING 1-85 Using F# to expose an out parameter to C#

```
let f ([System.Runtime.InteropServices.Out]a: byref) = a <- 9
```

I covered the out parameter, so now let's shift our attention to ref. It’s easy to handle the C# ref definition well. Listing 1-86 shows how to handle ref parameters in F#. There is a byref keyword in the sample code, which I'll introduce in Chapter 6, "Other Unique Features." For now, think of it as a reference variable.

## LISTING 1-86 Using F# to invoke a C# function that has a ref parameter

```cs
C function definition
namespace CSharp
{
    public class Chapter1Class
    {
        public static int ParameterFunction(int inValue, ref int refValue)
        {
            refValue += 3;
            return inValue + 7;
        }

        public static void ReturnSample(out int x)
        {
            x = 8;
        }
    }
}
```

```fs
F# code invoking the C# function
// declare a mutable variable
let mutableValue = 2

// declare a reference cell
let refValue = ref 2

// pass mutable variable into the function
let refFunction = CSharp.Chapter1Class.ParameterFunction(1, &mutableValue)

// pass reference cell into the function
let refFunction2 = CSharp.Chapter1Class.ParameterFunction(1, refValue)

// out parameter
let mutable x = Unchecked.default<>
CSharp.Chapter1Class.ReturnSample(&x)
```
