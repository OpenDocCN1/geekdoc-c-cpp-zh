## LISTING 6-48 Using DU and pattern matching in a currency calculation

type Currency =

## Using Variable Patterns and the when Guard

Up until now, the patterns you've looked at have not handled relationships among decomposed data items. If you want to know whether the decomposed data meets criteria, you can use the when guard. Listing 6-53 decides whether or not the (x,y) point is on the line f(x) = x.

**LISTING 6-53** Point relative to line f(x) = x

```fsharp
let testPoint tuple =
    match tuple with
    | x, y when x = y -> "on the line"
    | x, y when x > y -> "below the line"
    | _ -> "up the line"
```

Note: F# does not consider the when's result to decide whether the match expression is complex. Therefore, if you changed the last pattern in Listing 6-53 to `when x < y`, the compiler would still think the match expression was not complete and generate a warning. Another option is to use active patterns, which will be introduced in the next section.

## Using ? Pattern and as pattern

When the input parameter is decomposed to different parts, it might need a name. The as pattern is introduced for this purpose. Listing 6-54 shows how to check the type. Instead of using the as operator in C#, F# uses ? to check the type.

**LISTING 6-54** Type pattern example

```fsharp
let testType x =
    match x with
    | float as f -> printf "float value %f" f
    | int as i -> printf "int value %d" i
    | _ -> printf "type cannot process"
```

Note: The input parameter must be the type in the pattern. float and int are derived.

## Working with Active Patterns

As you've already seen, pattern matching introduces a way to decompose data into small pieces. However, the decomposition is only by its structure. If you need to check the data, a when guard is needed. When the logic gets complex, the when guard can have multiple conditions, making the code hard to maintain.

You can use active patterns to resolve this issue. It is a special function in itself. By evaluating this function, the data is segmented and associated with the pattern name. In other words, the active pattern is a way to decompose and label data.

## Using Single-Case Active Patterns

The simplest form of active pattern is the single-case pattern. Listing 6-56 defines an active pattern named Result. When using the active pattern, the expected value must be passed in. If the input value can make the active pattern yield the expected value

**LISTING 6-56** Defining a single-case active pattern

```fsharp
// define single-case active pattern
let (| Result |) x = x % 2

// use pattern to check even/odd number
let checkNumber x =
    match x with
    | 0 -> "even number"
    | 1 -> "odd number"
```

**Active patterns are not used in completeness.** Although the preceding pattern covers all cases, a warning will still be generated. The following code uses a wildcard to eliminate the warning:

```fsharp
// define single-case active pattern
let (| Result |) x = x % 2

// use pattern to check even/odd number
let checkNumber x =
    match x
    | 0 -> "even number"
    | 1 -> "odd number"
    | _ -> "other number"
```

In the final analysis, the active pattern is a special function. Listing 6-57 shows that a single-case pattern can be made a safe Dictionary object.

**LISTING 6-57** Using single-case active pattern as a function

```fsharp
open System.Collections.Generic

let (|SafeDict|) (d : Dictionary<_, _>) =
    if d = null then Dictionary<_, _>()
    else d
```

```fsharp
let tryFind (dic) key =
  if dic.ContainsKey key then
    Some dic[key]
  else None
```

You can use the single-case active pattern to categorize the data and clean up the code, but the value it provides falls short in more complex scenarios.

## Using Partial-Case Active Patterns

The partial-case active pattern is an enhanced version of the single-case active pattern. Partial-case active patterns identify only part of the incoming data and leave the rest of data untouched (unlabeled). The partial-case active pattern must return an option type. The pattern will be ignored when None is returned. Listing 6-58 defines partial-case active patterns. If the variable x is less than 10, the first pattern is triggered.

**LISTING 6-58** Partial-case active pattern

```fsharp
// define partial active patterns
let (|LessThan10|) x = if x < 10 then x else None
let (|Btw10And20|) x = if x >= 10 && x < 20 then x else None
```

```fsharp
let checkNumber2 x =
  match x with
    | LessThan10 -> printf "less than 10, the value is %d" a
    | Btw10And20 -> printf "between 10 and 20, the value is %d" a
    | _ -> printf "that's a big number %d" x
```

Unlike the single-case active pattern, the variable succeeding the active pattern is bound to the function's return value. For example, the a in LessThan10 is used to hold the values smaller than 10.
