You can use MailboxProcessor to simulate a message-box banking account system where the deposit and withdrawal operations are performed asynchronously. The sample code is shown in Listing 6-92.

## LISTING 6-92 Banking account using MailboxProcessor

```sharp
open Microsoft.FSharp

[<Measure>] type USD

// define account state
type AccountState =
| Overdrawn
| Silver
| Gold

// define operations: deposit and withdraw
type Operation =
| Deposit of decimal<USD>
| Withdraw of decimal<USD>

// define the account class
type Account() =
    let mut balance = 0.0m<USD>

    // define a MailboxProcessor<Operation>(fun inbox ->
    let bank =
        let rec loop () =
            async {
                let! msg = inbox.Receive()
                match msg with
                | Deposit n -> balance <- balance + n
                | Withdraw n -> balance <- balance - n
                return loop ()
            }
        loop ()
    loop ()

    // start MailboxProcessor instance
    do
        let _ = bank.Start()

    // define operations post the message to MailboxProcessor
    member this.Deposit(args) =
        bank.Post(Deposit(args))
    member this.Withdraw(args) =
        bank.Post(Withdraw(args))

    member this.State =
        get() {
            match balance
            | when balance <= 0.0mUSD -> AccountState.Overdrawn
            | when balance > 0.0mUSD && balance < 10000.mUSD -> AccountState.Silver
            | _ -> AccountState.Gold
        }
    member this.PayInterest() =
        while bank.CurrentQueueLength > 0 {
            System.Threading.Sleep(100)
            printf("current state is %A", this.State)
            match this.State {
                | AccountState.Overdrawn -> this.Deposit(balance * 0.01)
                | AccountState.Gold -> this.Deposit(balance * 0.02)
            }
        }
    member this.ShowBalance() =
        while bank.CurrentQueueLength > 0 {
            System.Threading.Sleep(100)
            printf("current balance is %A", balance)
        }

let account = Account()
account.Deposit(1000.mUSD)
account.Deposit(10000.mUSD)
account.PayInterest()
account.ShowBalance()
```

## Working with Computation Expressions

I introduced query and async in Chapter 4 of the "Asynchronous Workflows" section. When you look at the blue-color async and query syntax in the Visual Studio editor window, you might think they are keywords, like the this keyword in C#. However, if that were the case, these keywords couldn't be used as variable names. For example, how does the code in Listing 6-93 compile?

## LISTING 6-93 Using async, seq, and query as variables

```sharp
let async = 0
let seq = 1
let query = 2
```

Actually, the code compiles because async, seq, and query are not keywords. Instead, they are a special F# feature called computation expressions. The MSDN documentation (https://msdn.microsoft.com/en-us/library/dd231832.aspx) provides a good definition of computation expressions:

Computation expressions in F# provide a convenient syntax for writing computations that can be sequenced and bound using control flow constructs and bindings. They can be used to provide a convenient syntax for monads, a functional programming feature that can be used to manage data, control, and side effects in functional programs.

F# provides computation expressions so that the language can be expanded. The reason you can put your code inside a seq is it is a computation expression. Listing 6-94 revisits the sequence-generation code that was discussed in Chapter 1.

## LISTING 6-94 Sequence generation using a reference cell

```sharp
// Sequence generation code
let indices = [1, 2; 3; 4; 5; 6 ]

let newIndices = seq {
  let currentCell = ref 0
  for a, b in indices
    yield currentCell, a
    yield a, b
    currentCell := b
  yield !currentCell, 100
}

Execution result
> newIndices;
val it : seq<int> = seq [[0, 1); (1, 2); (2, 3); (3, 4); ...]
```

> Note: This sample code also demonstrates how to use a reference cell. It is invalid to use a mutable variable in the computation expression. The only way to define a mutable variable in this scenario is to use a reference cell.

In addition to the mutable-variable restriction, there is another restriction for computation expressions. It is invalid to use base in the computation expression. (See Listing 6-95.) The workaround is just to use this.

Wait, expanding the .NET language seems like an exciting possibility. Let's do it now. The first sample is a bank system where the decimal number is rounded when calculating interest, as shown in Listing 6-96.

## LISTING 6-96 Rounding computation expression

```sharp
// define a rounded computation expression
type RoundComputationBuilder(digits:int) =
    let round(x:decimal) = System.Math.Round(x, digits)
    member this.Bind(result, restComputation) =
        restComputation(result)
    member this.Return x = x

// calculate the bank interest
let bankInterest = RoundComputationBuilder {
  let! x = 23231.34m * 0.002m
  return x
}
```

The RoundComputationBuilder defines two special methods: Bind and Return. These two methods correspond to let! and return. Table 6-2 shows a full list of method names and corresponding settings. In most cases, the method name suggests its usage.

## TABLE 6-2 Computation expression methods

| Method | Description |
| :--- | :--- |
| For seq<a><a> * (<a> -> Result<unit>) -> Result<unit> | Enables the FOR loop |
| Zero unit -> Result<unit> | Enables the execute expression, which returns "void" in C# |
| Combine Result<a><a> * (<a> -> Result<<b>>) | Links the computation expression parts |
| While (unit -> bool) * Result<unit> -> Result<unit> | Enables the WHILE loop |
| Return <a> -> Result<a><a> | Enables the return keyword |
| ReturnFrom <a> -> Result<a><a> | Enables the return! keyword |
| Yield <a> -> Result<a><a> | Enables the yield keyword |
| YieldFrom seq<a><a> -> Result<a><a> | Enables the yield! keyword |
| Delay (unit -> Result<a><b>>) -> Result<a>:IDisposable | Used along with the Combine method to ensure the correct order of statement execution |
| Run Result<a><a> -> Result<a><a> | Executes before the execution of a computation expression—like C# |
| Using <a> -> Result<b>> -> Result<b> when <a>:System | Enables the use keywords |
| Bind Result<a><a> * (<a> -> Result<b>>) -> Result<b> | Enables the let and return keywords |
| Finally Result<a><a> * (unit -> unit) -> Result<a><a> | Enables the try...finally expression |
| TryWith Result<a><a> * (e -> Result<a>) -> Result<a> | Enables the try...with expression |

With the full list used, you can expand Listing 6-96 by adding two members, as shown in Listing 6-97. The *return* keyword returns the value without going through the rounding process. The *Run* method prints a message before any execution starts. Note that *let* (not let!) does not invoke any computation expression method.

## LISTING 6-97 Computation expression example with more methods implemented

```sharp
type RoundComputationBuilder(digits:int) = 
    let round(x:decimal) = System.Math.Round(x, digits)
    member this.Bind(result, restComputation) = restComputation(result)
    member this.Return x = round
    member this.Return X = X // keep the original value
    member this.Run f =
        printf "now start to run."
        f

    return x // invoke the Return
}

let roundedResult2 = {

}
```

A practical example is the retry computation expression, shown in Listing 6-98. It performs the retry logic a given number of times before giving up.

## LISTING 6-98 The retry computation expression code

```sharp
// define a retry computation expression
type Retry(retryTimes:int) = class
    let mutable success = false
    member public this.bind(value, restFunction:unit -> unit) =
        success <- false
        let mutable n = retryTimes
        while not success && n > 0 do
            n <- n - 1
            try
                value()
                success <- true
            with as e -> printfn "failed with %s, %d times" e.Message (retryTimes - n)
        restFunction()
    member public this.Return args =
        success
```
