# Using Variable Patterns and the when Guard

Up until now, the patterns you've looked at have not handled relationships among decomposed data items. If you want to know whether the decomposed data meets criteria, you can use the when guard. Listing 6-53 decides whether or not the (x,y) point is on the line f(x) = x.

**LISTING 6-53** Point relative to line f(x) = x

```
let testPoint tuple =
match tuple with
| x, y when x == y -> "on the line"
| x, y when x > y -> "below the line"
| _ -> "up the line"
```

> Note F# does not consider the when's result to decide whether the match expression is complex. Therefore, even if you changed the last pattern in Listing 6-53 to x, when x < y, the compiler would still think that the match expression was not complete and generate a warning message.

> Note Another option is to use active patterns, which will be introduced in the next section.

# Using the Type Pattern and as pattern

When the input parameter is decomposed to different parts, the different parts might need a name for future reference. The as pattern is introduced for this purpose. Listing 6-54 shows how to write a type check. Instead of using an is operator, as you might do in C#, F# uses ?: to check the type.

**LISTING 6-54** Type pattern example

```
let testType (x:obj) =
match x with
| ? float as f -> printf "float value %f" f
| ? int as i -> printf "int value %d" i
| _ -> printf "type cannot process"
```

> Note The input parameter must be the superclass of the type in the pattern. Listing 6-54, float and int are derived from obj.
