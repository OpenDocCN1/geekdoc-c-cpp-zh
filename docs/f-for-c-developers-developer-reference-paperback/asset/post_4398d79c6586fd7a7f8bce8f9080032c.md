## Using a Self-Identifier

Everything seems to be working perfectly until you try to assign a value to your property in the data binding section in Listing 2-24. If you put this Y <- 0 in the data binding, the F# compiler spits out an error complaining that this is not defined. This error can throw most C# developers off guard. Why does the keyword not be defined?

A self-identifier is a reference to the current instance. This in C# and Me in Microsoft Visual Basic are self-identifiers. Interestingly, F does not require the self-identifier to be any particular word. You can use any word as the self-identifier for the whole class definition or for any individual method:

- To define a self-identifier for the whole class, use the as keyword after the closing parentheses of the primary constructor and specify the identifier.
- To define a self-identifier for just one method, provide the member declaration before the method name and use a period () as a separator in between.

Listing 2-25 shows these two ways of creating a self-identifier. The scope for self is established for the whole class and the identifier is only in the Print method. So Print is prefixed with this, and you can still use self to print in the default constructor. Keep in mind that the self-identifier is decorated on the primary constructor. It is required to have a self-identifier on the other constructors code needs to access the resource from the current class instance.

### LISTING 2-25 Using a self-identifier

```fsharp
type MyClass(v) as self =
    let data = v
    do
        self.Print()
    member this.Print() =
        printf("MyClass print")
```

The error about this not being defined is explained. In the binding section, you have to define the self-identifier at the class level. See Listing 2-26 for the solution.

### LISTING 2-26 The self-identifier and access property in the binding section

```fsharp
// define a Point2D class with a parameterized primary constructor
type Point2D(xValue:double, yValue:double) as this=
    // field x
    let mutable x = xValue

    // define a static field named count
    static let mutable count = 0

    // perform a binding to increase the count
    do
        count <- count + 1
        this.Print("in constructor")

    //additional constructor
    new() = Point2D(0.,0.,.)

    // print out message
    member this.Print(msg) = printf("%s" msg)

    // define an X property
    member this.X with get() = x
        and set(v) = x <- v

    // define a Y property using an auto-implemented property
    member val Y = yValue with get, set

    // define a function to get the distance from the current point
    member this.GetDistance(point:Point2D) =
        let xIDIF = this.X - point.X
        let yIDIF = this.Y - point.Y
        let distance = sqrt(xIDIF*2. + yIDIF*2.)
        distance

    // define a static method to return a Point2D from (x,y) tuple
    static member From(x, y) =
        Point2D(x,y)
```

## Using Inheritance

F# uses the *inherit* keyword to represent the inheritance relationship. Listing 2-29 shows the C# code and its equivalent F# code.

**LISTING 2-29** Particle class using inheritance

```csharp
C# Particle class code
public class Particle : Point2D
{
    public double Mass { get; set; }
}

F# code
type Particle() =
    inherit Point2D
    member val Mass = 0. with; set
```

You might not have recovered yet from the shock of the F# self-identifier. Does F# allow a user to define any identifier for referring to a base class instance? The answer is no. Like C#, the *base* keyword is used to refer to the base class instance, and a user cannot define her identifier.

Listing 2-30 shows that the *inherit* keyword can be used to invoke a base class constructor. When the base class has multiple constructors, the *inherit* keyword can indicate which constructor to use.

### LISTING 2-30 Using the *inherit* keyword to invoke different base class constructors

```fsharp
// define BaseClass
type BaseClass =
val x : int
new () = BaseClass(0)
new (a) = { x = a }

// define a DerivedClass inherited from BaseClass
type DerivedClass =
inherit BaseClass
val y : int

// invoke the base constructor with one parameter
new (a, b) = { *inherit BaseClass(a); y = b }

// invoke the base constructor without a parameter
new (b) = { *inherit BaseClass(); y = b }
```
