In Listing 3-22, the factory inside factoryPattern is actually a function. It is a shortcut for a match statement. The checkWithFunction and checkWithMatch functions in Listing 3-21 are equivalent.

## LISTING 3-22 Example of the factory pattern

```fs
// define the interface
type IA =
  abstract Action : unit -> unit

// define two types
type Type =
| TypeA
| TypeB

let factoryPattern() =
// factory pattern to create the object according to the input object type
let factory = function
| TypeA -> { new IA with
member this.Action = printf "I am type A"
| TypeB -> { new IA with
member this.Action = printf "I am type B"}}

// create type A object
let obj1 = factory TypeA
obj1.Action()

// create type B object
let obj2 = factory TypeB
obj2.Action()
```

## Working with the Singleton Pattern

The Singleton pattern is a design pattern used to implement the mathematical concept of a singleton. It restricts the instantiation of a class to a single instance. This is useful when exactly one object is needed to coordinate actions across the system. One example of a singleton in F# is a value. An F# value is immutable by default, and this guarantees there is only one instance. Listing 3-24 shows how to make sure that an F# class is a singleton. The same declares a private constructor and ensures that the class has only one instance in memory.

## LISTING 3-24 An example of the singleton pattern

```fs
// define a singleton pattern class
type A private =
    static let Instance = A()
    static member Instance = instance
    member this.Action() = printf "action from type A"

// singleton pattern
let singletonPattern() =
let a = A.Instance
a.Action()
```

## Working with the Composite Pattern

The composite pattern is a partitioning design pattern. The composite pattern describes a group of objects that are treated in the same way as a single instance. The typical application is a tree representation. Listing 3-25 describes a tree structure. The sample focuses on how to access this tree and bring back the result. The dynamically generated object can be treated like a visitor to the tree. The visitor accesses nodes and brings the result to the invoker. In the sample code, CompositeNode not only defines the tree but also defines common ways to traverse.

## LISTING 3-25 An example of the composite pattern

```fs
// define visitor interface
type Visitor<'T> =
    abstract Do : 'T -> unit

// define composite node
type CompositeNode<'T> =
    | Node of 'T
    | Tree of 'T * CompositeNode<'T> * CompositeNode<'T>
    with
      // define in-order traverse
      member this.InOrder f =
        match with
        | Tree(left, right) ->
            f
        | Node(n) -> f

      // define pre-order traverse
      member this.PreOrder f =
        match with
        | Tree(left, right) ->
            left.PreOrder f
            right.PreOrder f
        | Node(n) -> f

      // define post-order traverse
      member this.PostOrder f =
        match with
        | Tree(left, right) ->
            left.PostOrder f
            right.PostOrder f
        | Node(n) -> f

let invoke() =
    // define tree structure
    let tree = Tree(Node(1), Node(2), Node(3))

// define visitor, it gets the summary of the node values
let wrapper =
  let result = ref 0
  { new Visitor<int> with
    member this.Do n =
      result := result + n }

// pre-order iterates the tree and prints out the result
tree.PreOrder(printf("result = %d" !result))
```

Execution result from composite pattern sample obtained by calling invoke
result = 3

## Working with the Template Pattern

The template pattern, as its name suggests, is an algorithm skeleton. In F#, we have higher-order functions that can serve as a template to generate other functions. Listing 3-26 defines a template function named TemplateF. The actual implementation is provided outside the class definition, and the user can pass in their own version of each.

## LISTING 3-26 Example of the template pattern

```fs
// the template pattern takes three functions and forms a skeleton named
TemplateF
type Template(conn, queryF, disconnF) =
  member this.Execute(constr, queryStr) =
    this.TemplateF constr queryStr
  member this.TemplateF =
    let f queryStr =
      connF queryStr
      disconnF ()
```

Note: The connect, query, and disconnect functions can be implemented as private functions in a class. The class design is convenient for C# projects that need to reference the implementation of this design pattern in an F# project. However, the class is not necessary in an F#-only solution. Listing 3-27 shows how to use higher-order functions to implement the template pattern.

## LISTING 3-27 Template with a higher-order function

```fs
// connection, query, and disconnect functions
let connect(conStr) = printf("connect using %s" conStr)
let query(queryStr) = printf("query with %s" queryStr)
let disconnect() = printf("disconnect")

// template pattern
let template(connect, query, disconnect) (conStr:string)(queryStr:string)=
connect(conStr)
query(queryStr)
disconnect()

// execute query
let queryFunction = template(connect, query, disconnect)

// execute the query
do queryFunction("<connection string>" "select * from tableA")
```

## Working with the Private Data Class Pattern

The private data class pattern is a design pattern that encapsulates class properties and associated data manipulation. The purpose of the private accessibility is to prevent the modification of these values. C# uses the readonly property, which does not have a setter function, to solve this problem. F# values are immutable by default, so implementing this readonly type of behavior is supported inherently. In the following example, I use an F# record type to implement the pattern by extending the record type. The word `with` in the code shown in Listing 3-28 is a way to tell the compiler that some property, method, or field will be added to the record type. In the sample code, the circle data remains the same once it is created. Some object-oriented implementations even implement another class so that there is little chance to modify the values. The immutability of record types eliminates the need of a second class, as well as for explicitly defining getter-only properties with a keyword.

## LISTING 3-28 Example of the private data class pattern

```fs
type Circle = {
  Radius : float;
  X : float;
  Y : float;
}

member this.Area = this.Radius**2 * System.Math.PI
member this.Diameter = this.Radius *2
let myCircle = {Radius = 10.0; X = 5.0; Y = 4.5}
printf "Area: %f Diameter: %f" myCircle.Area myCircle.Diameter
```
