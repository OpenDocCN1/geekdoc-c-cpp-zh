
## LISTING 2-39 Converting a number

```csharp
// C# conversion
int i = 5;
double d = (double)i;
```

```fsharp
// F# conversion
let i:int = 5
let d = double(i)
```

C# supports implicit conversion, which means that you can assign an integer to double without having to explicitly do casting. The ability to deduce type implicitly can make development easier at earlier stages, but it introduces more chances of runtime errors. F# statically resolves the type and minimizes the runtime error by only allowing explicit conversion. F# enum conversion is shown in Listing 2-40.

## LISTING 2-40 An enum conversion

```fsharp
type PixelColor =
    | R = 0
    | G = 1
    | B = 2

// convert number to enum
let r:PixelColor = 0
let g:PixelColor = G
let b:PixelColor = 2
```

## Upcasting and Downcasting

Casting an object up the hierarchy is the act of casting a derived object to its base object. You can use the `:>` operator or the `upcast` keyword to convert a derived instance to a base instance. Listing 2-41 shows a sample of how to use `:>` and `upcast`.

## LISTING 2-41 Upcasting conversion

```fsharp
// define a base class
type Base() =

// define a derived class
type Derived() = Base()

let myDerived = Derived()

// upcasting
let cast:Base = upcast myDerived
```

**Note** Casting to a base class (using `:>` or `upcast`) is always safe and can be verified at compile time. Casting an object down the hierarchy happens when you need to cast from a base object to a derived object. The `:>` operator or `downcast` keyword is used to accomplish this. The `downcast` operator does some sanity checks; for example, the type needs to have an inheritance relationship with current type, but most of checking has to be verified at runtime. If the cast fails, an `InvalidCastException` will be raised. Listing 2-42 casts the base class to a derived class.

## LISTING 2-42 example of downcasting

```fsharp
// define a base class
type Base() =

// define a derived class
type Derived() = Base()

let myDerived = Derived()

// upcasting
let upcastResult:Base = upcast myDerived

// downcasting
let downcastResult:Derived = downcast upcastResult
```

**Note** The `upcast` and `downcast` keywords are alternatives to the `:>` and `??` operators.

## Boxing and Unboxing

Like C#, F# also supports the concept of boxing and unboxing. When the common language runtime (CLR) boxes a value type, it wraps the value inside `System.Object` and stores it on the managed heap. Unboxing is the opposite process; it extracts the value from the object. Because F# does not support implicit conversion, an extra step is needed. See Listing 2-43.

## LISTING 2-43 Boxing and unboxing

```fsharp
let intValue = 4
let o = box(intValue)
// let r = o + 2 // does not compile because o is obj type
let i:int = unboxing(o)
let r = i + 2
```

**Note** F# uses `obj` as a type abbreviation for `System.Object`.

## Defining an Interface

An interface is just a collection of properties and methods, and its implementation is finished in the class that implements the interface. The interface provides a relationship to the type. Once the type implements the interface, it is basically broadcasting that it can perform the operations described in the interface definition. The typical interface declaration in F# is like the code in Listing 2-44. Listing 2-45 shows how to define an interface with a property and how the lightweight F# syntax allows the `end` keyword to be optional.

## LISTING 2-44 Defining an interface

```fsharp
type Interface =
    // a method that takes int and returns int
    abstract member InterfaceMethod : int -> int

type Interface2 = interface
    // a method that takes int and returns int
    abstract member InterfaceMethod : int -> int
end
```

## LISTING 2-45 Defining an interface with properties

```fsharp
// Interface definition with interface
type I2DLocation = interface
    abstract member X : float with get, set
    abstract member Y : float with get, set
end

// Lightweight interface definition
type I2DLocation =
    abstract member X : float with get, set
    abstract member Y : float with get, set
```

**Note** Unlike C#, an F# interface does not support the `partial` keyword. Therefore, an interface has to be in one file.

F# requires interfaces to be explicitly implemented; as a result, the code needs some extra work. See Listing 2-46. Adding an interface seems to add much value to this code; however, the interface can make code easy to expand and testing frameworks such as Fakes in Visual Studio require an interface.

## LISTING 2-46 Implementing an interface

```fsharp
// 2D location interface
type I2DLocation =
    abstract member X : float with get, set
    abstract member Y : float with get, set

// define a Point2D class with a parameterized primary constructor
type Point2D(XValue:double, yValue:double) as =
    // other Point2D members as property X and Y
    // define field x
    let mutable x = xValue

    // define an X property
    member this.X with get() = x
    and set(v) = x <- v

    // define a Y property
    member this.Y with get() = yValue
    and set(v) = yValue <- v

    // implement interface
    interface I2DLocation with
        member X with get() = x
        and set(v) = x <- v
        member Y with get() = yValue
        and set(v) = yValue <- v
```
