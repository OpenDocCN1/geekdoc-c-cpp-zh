## Using Delegates and Events

According to the definition in MSDN (http://msdn.microsoft.com/en-us/library/ms173171(v=80).aspx), a delegate is a safe way to reference a method. A delegate is similar to a C++ function pointer, but it is type-safe. A C++ function pointer can point to any function, but a delegate can point only to the function with the same function signature. The introduction of a delegate-enabled function can be treated as a variable and passed as a parameter. One of the major applications for a delegate is to define an event. Listing 2-64 shows how to define a delegate in F#.

### LISTING 2-64 Defining and invoking a delegate type

```sharp
let f a b = a + b

// define a delegate type
type MyDelegateType = delegate of int * -> int
let delegateValue = new MyDelegateType(f)

// invoking the function and delegate returns the same result
let fResult = f 1 2
let fromDelegate = delegateValue.Invoke(1,2)
```

If a class member takes a delegate as parameter, you can pass in a lambda expression and F# will create a delegate behind the scenes. See Listing 2-65.

### LISTING 2-65 Passing a lambda to a class that takes a delegate

```sharp
// define delegate type
type IntDelegate = delegate of int -> unit

// define a class that takes a delegate
type MyType =
    static member Apply(i:int, d:IntDelegate) =
    d.Invoke(i)

// pass lambda to the function that takes delegate
MyType.Apply(0, (fun x -> printf "%d"))
```

> Note The implicit conversion works only on class member. It will not work on binding.

A delegate is similar to F# function an extra feature called delegate combination. Combining multiple delegates allows a user to invoke combined functions with a single call. In Listing 2-66, a Combine function and Remove can be used to edit event set.

### LISTING 2-66 Delegate combination

```sharp
// define a delegate
type PrintDelegate = delegate of string -> unit

// create delegates
let printOne = PrintDelegate(fun s -> printf "%s" s)
let printTwo = PrintDelegate(fun s -> printf "%s" s)

// combine delegates
let printBoth = PrintDelegate.Combine(printOne, printTwo)

// invoke combined delegates
printBoth("aaa")
```

> Note A delegate created in F# does not have BeginInvoke and EndInvoke; therefore, you cannot invoke the delegate asynchronously.

An event is just a delegate property on a class. Invoking an event is nothing more than invoking combined delegate. An event is defined in Microsoft.FSharp.Control namespace in FSharp.Core.dll.

If you take a closer look at the namespace, there are two Event types defined. Both provide identical members. You can use either of them to define your event:

- Event<Delegate, Args> Event implementations for delegate type following the standard .NET Framework convention
- Event<T> Event implementations for IEvent<T> type

> Note If you do not remove the event from the object, the reference to the object will prevent garbage collection from reclaiming memory.

If you look at Listing 2-67, the process to define an event in F# is similar to the one in C#. First define a delegate, then define the event using the delegate. In the example, myEvent is defined as Event<D, T>. The Event supports two methods, Publish and Trigger. Publish is used to publish an event so it can be subscribed to, and Trigger is used to raise the event. The CLIEvent attribute is used to make the event compile as a CLI event, so you can use += to subscribe to this event from F# code.

### LISTING 2-67 Event<D, T> sample

```sharp
// Define a class in F#
// define a delegate
type Delegate = obj * System.EventEventArgs -> unit

// define a class with event
type MyClassWithEvent()
    let myEvent = new Event<Delegate, System.EventEventArgs>()
    [CLIEvent]
    member this.Publish = myEvent.Publish
    member this.RaiseEvent(args) = myEvent.Trigger(this, args)
let classWithEvent2 = new MyClassWithEvent()
classWithEvent2.Event.Add(fun (e) -> printfn "message is %A" e)
classWithEvent2.RaiseEvent(System.EventEventArgs())
```

```csharp
// C# code using F#
static void Main(string[] args)
{
    var myEventClass2 = new Chapter2.MyClassWithEvent();
    myEventClass2.Event += MyHandler;
    myEventClass2.RaiseEvent(new EventArgs());
}

private static void MyHandler(object sender, EventArgs e)
{
    // sender is myEventClass2
}
```

Listing 2-68 provides code that demonstrates how to use Event<T>, which is a simpler format. The underscore in the Event<T> definition is a placeholder used to inform the F# compiler to figure out the type information. If you compare these two Event implementations, they are different in the following:

- The Event<T> version is simpler.
- The Event<D, T> version adding FSharp.Core.dll as a reference. Otherwise, the compiler complains about not finding the type 'Microsoft.FSharp.Control.FSharpEventHandler<T0>'. Event<D, T> does not need reference to FSharp.Core.
- The sender value in MyHandler2 holds the sender instance, but MyHandler hides the information in the first element of the tuple.

### LISTING 2-68 Event<T> sample

```sharp
let classEvent = MyClassWithCLIEvent()

// subscribe the event by using Add
classEvent.MyEvent.Add(fun (sender, arg) -> printfn "message is %A" arg)
```

```sharp
// raise event
classEvent.RaiseEvent("hello world")
```

```csharp
// Using an F# event from C#
class Program
{
    static void Main(string[] args)
    {
        var myEventClass = new Chapter2.MyClassWithEvent();
        myEventClass.Event += MyHandler;
        myEventClass.RaiseEvent("Hello world");
    }

    private void MyHandler(object sender, Tuple<MyClassWithEvent,object> args)
    {
        // sender is NULL
        // args.Item1 is the sender
        // args.Item2 is the raised event
    }
}
```

> Note In C# code, the sender is NULL, and the sender is the first element of tuple. If you have an event on an interface and you want to interoperate with C#, you need to define the CLIEvent attribute on the interface and all implementations.
