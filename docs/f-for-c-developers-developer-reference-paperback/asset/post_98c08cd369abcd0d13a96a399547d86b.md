# Working with Code Quotation

F# code quotation, which can be shortened to just quotation, is another way to expose code information—even more information than reflection can provide. Reflection can give only the surface information of a function, such as return type or parameter type. However, the tree structure provided by a quotation can show the implementation details of a function.

You can choose or not to have a result of a quotation include type information. Listing 6-120 shows how to declare a quotation with and without type information. The <@> is used to get the typed code quotation and @@@ is used to get the untyped code quotation. The result shows that expr is an Expr<int> type and expr2 is an Expr (with a type).

* Note

# LISTING 6-120 Defining a quotation

```fsharp
Source code
open Microsoft.CSharp.Quotations

// A typed code quotation.
let expr : Expr<float> = <@ 1.2 + 2.4 @>

// An unused code quotation.
let expr2 : Expr = <@ 1.2 + 2.4 @@>

Execution result
val expr : Quotations.Expr<int> =
  Call (None, op_Addition, [Value (1), Value (1)])
let expr2 : Quotations.Expr = Call (None, op_Addition, [Value (1), Value (1)])
```

For a complex function, the <@> and <<>> are not the most convenient way to get the quotation. If that is the case, you can use the ReflectedDefinition attribute as shown in Listing 6-121. Before F# 3.0, ReflectedDefinition could be applied only on a function. F# 3.0 now also supports this attribute on the module. If a module is decorated with this attribute, it works as though all functions within the module have this attribute.

# LISTING 6-121 Using the ReflectedDefinition attribute

```fsharp
Source code
[<ReflectedDefinition>]
let ff a b =
  if a then b + 1 else b + 3

let q = <@ ff @>

Execution result
val ff : a:bool -> b:int -> int
val q : Expr<bool -> int -> int> =
Lambda (a, Lambda (b, Call (None, ff, [a, b])))
```

# Working with the Observable Module

The event is a nice feature that can notify others about something that happens elsewhere in the application. The .NET uses a delegate, which is similar to a function. According to the description MSDN (http://msdn.microsoft.com/en-us/library/ee37013.aspx), the Observable module introduces functions that make an event first class citizen. If you are not sure what I mean when I call it first class citizen, Table 6-3 might give you a better idea. If you see the similarity between an event and data, you get the point.

### Table 6-3 Comparison of the Observable module and the Seq module

| Feature | Observable module | Seq module |
| :--- | :--- | :--- |
| Nature | Push-based (events) | Pull-based (sequences) |
| Execution | Immediate when event occurs | Lazy when requested |
| Usage | Asynchronous notifications | Data processing pipelines |

So I'll explain more about the Observable module, starting with the partition function. Listing 6-123 fixes 10 events with arguments 1 to 10. Depending on the value of the provided argument, the events are partitioned or classified into two kinds of events: oddNumEvent and evenNumEvent. The event-handler prints out the number in the end. This sample shows how the Observable module can process events as if they were data.

# LISTING 6-123 Observable module partition function

```fsharp
// define an event
let myEvent = Event<int>()

// depending on the value, the event will be given a different label
let evenNumEvent, oddNumEvent =
    myEvent.Publish
    |> Observable.partition (fun n -> n % 2=0)

// set even-number event handler
evenNumEvent.Add(fun i -> printf "number %d triggered event" i)

// set odd-number event handler
oddNumEvent.Add(fun i -> printf "odd number %d triggered event" i)

// fire 10 events with arguments from 1 to 10
[1..10]
|> Seq.iter myEvent.Trigger
```
