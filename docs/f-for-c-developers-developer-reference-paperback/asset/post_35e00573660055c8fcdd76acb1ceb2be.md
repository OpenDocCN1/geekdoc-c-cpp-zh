
> Note: Auto-implemented properties are not supported in an object expression. Properties in object expressions can be declared only by using the old syntax.

If the field needs to be mutable, another approach is to use a reference cell. Listing 6-6 shows how to define a reference cell inside and outside of the object expression. And Listing 6-7 shows how to extend a base class.

# LISTING 6-6 Object expression with a property

```fsharp
// first interface
type IMInterface =
    abstract F : unit -> unit
    abstract Prop0 : string with get, set
    abstract Prop1 : string with get, set

// define a reference cell outside of objExpression
let myData = ref ""

// implement one interface using object expression
let objExpression =
    // define a reference cell inside the objExpression
    let x = ref ""
    new IMInterface with
        member.F() = printf "hello object expression"
        member.Prop0 with get() = !x and set(v) = x := v
        member.Prop1 with get() = !myData and set(v) = myData := v

// set the Prop0 and print out the result
objExpression.Prop0 <- "set Prop0"
printf "%s" objExpression.Prop0

// set the Prop1 and print out the result
objExpression.Prop1 <- "set Prop1"
printf "%s" objExpression.Prop1
```

# LISTING 6-7 Object expression based on class

```fsharp
// define an interface
type IMInterface2 =
    abstract F2 : unit -> unit

// abstract class definition
[AbstractClass]
type MyAbstractClass() =
    abstract F : unit -> unit
    member.this.F2() = printf "my abstract class"
```

```fsharp
// object expression with abstract class and interface
let objExpressionInterfaceAbstract =
    {
        new MyAbstractClass() with
            override this.F() = printf "implement the abstract class"
            interface IInterface2 with
                member this.F2() = printf "from interface2"
    }

// override the ToString method using object expression
let objExpressionExtendObject =
    {
        new System.Object() with
            override this.ToString() = "hello from object expression"
    }
```

As in C#, the base class (which contains some concrete class member implementations) must come before all interfaces in the derived class definition. In an F# object expression, an abstract class must be present before any. In other words, the code will not compile if MyAbstractClass is put after IInterface2 in the objExpressionInterfaceAbstract.

Listing 6-8 is a real-world example that implements a WPF command. WPF commands usually do not involve the construction of a class. It is a perfect place to use object expression. From the sample code, you can see the object expression can have fields that cannot be accessed directly outside. The variable event1 can be viewed as a private field implemented in the object expression. This example also shows that object expression with parameters, like createCommand, can serve as a class factory to create objects based on.

# LISTING 6-8 WPF command using object expression

```fsharp
// class factory to generate WPF command
let createCommand actionExecute =
    let event1 = Event<ICommand>()
        new ICommand with
            member this.CanExecute(obj) = actionExecute(obj)
            member this.Execute(obj) = actionExecute(obj)
            member this.CanExecuteChanged(handler) =
                event1.Add(handler)
            member this.RemoveExecuteChanged(handler) =
                event1.Remove(handler)

// create a dummy command that does nothing and can always be executed
let dummyCommand = createCommand(
  (fun -> ()) // execution does nothing
  (fun -> true) // command can always be executed
)
```

A scenario where you have functions and variables in your module and need a way to provide functionality to a C# method. The quickest way to organize the code inside a module is to use object expression. Listing 6-9 shows a sample with three projects. The following shows how to use F# object expression to organize code:

- First, a C# project is created in which an interface IMInterface is defined. This project will be referenced by other C# projects and the F# project.
- Second, a C# project is created and defines a class MyFunction, which takes IMInterface as a parameter.
- Finally, an F# project creates an object expression and passes it to the class.

# LISTING 6-9 Using object expressions to organize code

```csharp
// IMInterface definition in the first C# project
public interface IMInterface {
  void MyFunction();
  int MyProperty { get; set; }
}

// MyFunction definition in the second C# project
public class MyClass {
  public void MyFunction(IMInterface obj) {
    // my operations
  }
```

# Using object expression to organize and invoke C# function

```fsharp
// function library
module MyFunctionLibrary =
    let myFunction () = // other operations

// use object expression to organize code from module
let myData =
    let data = ref 0
    { new IMInterface with
        member.MyFunction() = MyFunctionLibrary.myFunction()
        member.MyProperty with get() = !data and set(v) = data := v
    }

// invoke the C# method using object expression
let instance = new MyClass()
instance.MyFunction(myData)
```

There are some restrictions for object expressions. The type information for the object is generated by the compiler; therefore, the type name is not user-friendly. The type that backs the object expression is sealed, so the backend type does not help you a lot when you really need a complex inheritance hierarchy.

# Working with Options

Listing 6-10 defines a function that returns an int option. According to the MSDN documentation, options have the following characteristics:

> The option type in F is used when an actual value might not exist for a named value or variable. An option has an underlying type and can hold a value of that type, or it might not have a value.

For a C# developer, Listing 6-10 is similar to Listing 6-11, which uses Nullable<T>. Both functions filter out odd numbers. The C# function returns NULL, the F# function returns None. Table 6-1 shows the members in the option.

# TABLE 6-1 Option property and method

| Property or Method | Type | Description |
| :--- | :--- | :--- |
| None | 'T option | The option None value. This is a static property. |
| IsNone | Boolean | If the option is None, it returns TRUE. |
| IsSome | Boolean | If the option has a value, it returns TRUE. |
| Some | 'T option | Like None, but it returns a Some. |
| Value | 'T | Retrieves the underlying value. If there is no value (None), a NullReferenceException is thrown. |

There is a subtle difference between NULL and None. First, F# classes and other reference objects do not accept NULL as a valid value. For example, the GetDistance function in Listing 2-16 cannot be passed NULL.

# LISTING 6-10 Function returns an int option

```fsharp
// function only returns even-number option
let filterOutOddNumber a =
    if a % 2 = 0 then Some(a)
    else None
```

# LISTING 6-11 C# function filters out odd numbers

```csharp
static Nullable<int> FilterOutOddNumber(int a) {
    if (a % 2 == 0) {
        return a;
    }
    else {
        return null;
    }
}
```

The fact that the F# function GetDistance cannot accept NULL as a parameter is not a bug. Actually, this is a carefully thought-out F# feature. Listing 6-12 shows how to check the user input in C# and F#. The C# code seems perfect until you realize that str can be null! So you have to first check that str != null and then perform the work. And this kind of error can be caught only at runtime. Many developers think about this error, but the errors are often missed. The person who implements read_string often assumes that the invoker should handle the NULL, and the compiler does not say anything if the NULL value is not being considered.
