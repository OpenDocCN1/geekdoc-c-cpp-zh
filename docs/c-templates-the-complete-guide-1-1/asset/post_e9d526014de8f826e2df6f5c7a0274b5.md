
```cpp
class InsertSorted<TList, Element, Compare, false>
{
  // compute the tail of the resulting list:
  using NewTail =
    typename IfThenElse<Compare<Element, Front<TList>>,
                        Identity<TList>,
                        InsertSorted<PopFront<TList>, Element, Compare>>::Type;

  // compute the head of the resulting list:
  using NewHead = typename IfThenElse<Compare<Element, Front<TList>>,
                                      Element,
                                      Front<TList>>::Type;

public:
  using Type = PushFront<NewTail, NewHead>;
};

// base case:
template<typename List, typename Element,
         typename Compare>
class InsertSorted<List, Element, Compare, true>
{
public:
  using Type = PushFront<List, Element>;
};
```

The basic case is again trivial, because a single-element list is always sorted. The recursive case differs based on whether the element to be inserted should go at the beginning of the list or after the front. If the element being inserted precedes the first element in the list (which is already sorted), the result is that element prepended to the list with `PushFront`. Otherwise, we split the list into its head and tail, then prepend the head to the result of inserting the element into the tail.

This implementation includes a compile-time optimization to avoid instantiating types that will not be used, a technique discussed in Section 9.7.9 on page 44. The following implementation would technically also be correct:

**Click here to view code image**

```cpp
template<typename List, typename Element,
         typename Compare>
class InsertSorted<List, Element, Compare, false>
  : public PushFront<List, Element>
{
};

template<typename List, typename Element,
         typename Compare>
class InsertSorted<List, Element, Compare, true>
  : public PushFront<
      InsertSorted<PopFront<List>, Element,
                   Compare>,
      Front<List>>
{
};
```

However, such a formulation of the recursive case would be unnecessarily inefficient, because it evaluates the template argument in both branches of an `IfThenElse`, even though only one branch will be used. In our case, the `PushFront` invocation in the first branch (where the recursive `InsertSorted` invocation in the else branch is not used) is instantiated anyway.

First, this formulation has the desirable property that the number of instantiations required to insert an element into a sorted typelist is proportional to the length of the resulting typelist. The number of recursive instantiations of `InsertSorted` is at most the length of the list. (Insertion sort remains quadratic in the number of instantiations for inputs sorted in reverse.)

The following program demonstrates the use of insertion sort to order a list of types based on size. The comparison operation used is the `SmallerThanT` predicate.

Click here to view code image

```cpp
template<typename T, typename U>
struct SmallerThanT
{
    static constexpr bool value = sizeof(T) < sizeof(U);
};

void test_insertion_sort()
{
    using Types = Typelist<int, char, short, double>;
    using BT = InsertionSort<Types, SmallerThanT>;
    std::cout << std::is_same<BT, Typelist<char, short,
        int, double>>::value << '\n';
}
```

### 24.3 NON-TYPE TYPELISTS

Typelists provide the ability to describe and manipulate a sequence of types in a rich set of algorithms and operations. In some cases, it is also useful to work with sequences of compile-time values, such as the length of a multidimensional array or indices into another typelist.

There are several ways to produce a typelist of compile-time values. One simple approach involves defining a `CTValue` class template (named for a compile-time value) that represents a value of a specific type within a typelist.

Click here to view code image

```cpp
template<typename T, T Value>
struct CTValue
{
    static constexpr T value = Value;
};
```

Using the `CTValue` template, we can now express a typelist containing integer values for the first five prime numbers.

Click here to view code image

```cpp
using Primes = Typelist<CTValue<int, 2>, CTValue<int, 3>,
                        CTValue<int, 5>, CTValue<int, 7>,
                        CTValue<int, 11>>;
```

With this representation, we can perform numeric computations on a typelist of values, such as computing the product of those primes.

First, `Multiply` accepts two compile-time values with the same type and produces a new compile-time value of that same type, multiplying the input values.

Click here to view code image

```cpp
template<typename T, typename U>
struct MultiplyT;

template<typename T, T Value1, T Value2>
struct MultiplyT<CTValue<T, Value1>, CTValue<T, Value2>>
{
    using type = CTValue<T, Value1 * Value2>;
};
```

```cpp
template<typename T, typename U>
using Multiply = typename MultiplyT<T, U>::type;
```

Then, by using `Multiply`, the following expression yields the product of all prime numbers:

`Accumulate<Primes, Multiply, CTValue<int, 1>>::value`

Unfortunately, this usage of `Typelist` and `CTValue` is fairly verbose, especially for the case where all the values are of the same type. We can optimize this particular case by introducing an alias template that provides a homogeneous list of values, described as a `Typelist` of `CTValue`s:

Click here to view code image

`typelist/ctypelist.hpp`

```cpp
template<typename T, T... Values>
using CValues = Typelist<CTValue<T, Values>...>;
```

We can now write an equivalent (but far more concise) definition of `Primes` using a `ValueList` as follows:

Click here to view code image

`typelist/ctypelist.hpp`

```cpp
template<typename T, T... Values>
struct ValueList {
};

template<typename T, T... Values>
struct IsEmpty<ValueList<T, Values...>> {
    static constexpr bool value = sizeof...(Values) == 0;
};

template<typename T, T Head, T... Tail>
struct Front<ValueList<T, Head, Tail...>> {
    using Type = CTValue<T, Head>;
    static constexpr T value = Head;
};

template<typename T, T Head, T... Tail>
struct PopFront<ValueList<T, Head, Tail...>> {
    using Type = ValueList<T, Tail...>;
};

template<typename T, T... Values, T New>
struct PushFront<ValueList<T, Values...>, CTValue<T, New>> {
    using Type = ValueList<T, New, Values...>;
};

template<typename T, T... Values, T New>
struct PushBack<ValueList<T, Values...>, CTValue<T, New>> {
    using Type = ValueList<T, Values..., New>;
};
```
