## Chapter 20: Overloading on Type Properties

Function overloading allows the same function name to be used for multiple types, as long as those functions are distinguished by their parameter types. For example:

```cpp
void f (int);
void f (double);
void f (char const*);
```

With function templates, one can overload on type patterns such as pointer-to-T or T[]:

```cpp
template<typename T> void f (T*);
template<typename T> void f (T[]);
```

Given the prevalence of type traits (discussed in Chapter 19), it is natural to want to overload function templates based on the properties of the type template arguments. For example:

```cpp
template<typename T, typename... Ts>
void f (std::pair<T, Ts...> const&); // only for pair
template<typename T, typename... Ts>
void f (std::vector<T, Ts...> const&); // only for vectors
```

However, C++ does not currently provide any direct way to express overloads based on type properties. In fact, the two function templates immediately above are actually declarations of the same function template, rather than distinct overloads, because the names of template parameters are ignored when comparing two function templates.

Fortunately, there are a number of techniques that can be used to emulate overloading of function templates based on type properties. These techniques, as well as the common motivations for such overloading, are discussed in this chapter.

### 20.1 ALGORITHM SPECIALIZATION

One of the common motivations behind overloading of function templates is to provide more specialized versions of an algorithm based on knowledge of the types involved. Consider a simple swap() operation to exchange two values:

```cpp
template<typename T>
void swap (T& a, T& b)
{
  T tmp(a);
  a = b;
  b = tmp;
}
```

This implementation involves three operations for any type T; however, we can provide a more efficient swap() operation, such as for an Array<T> that stores its data as a pointer to the array contents and a length:

```cpp
template<typename T>
void swap (Array<T>& a, Array<T>& b)
{
  swap(a.ptr, b.ptr);
  swap(a.len, b.len);
}
```

Both implementations of swap() will correctly exchange the contents of two Array<T> objects. However, the latter implementation is more efficient, because it performs only two operations instead of three and all operations are pointer/length, and therefore, no additional operations for T are required. Note also that this is not available for an arbitrary type. The latter function template is therefore (conceptually) more specialized than the former, because it performs the same operation for a subset of the types accepted by the former function template. Finally, the second function template is also more specialized based on the particular rules for function template overloading (that is, partial ordering): It is a more specialized template (and, therefore, more efficient) function template when it is applicable.

The design and optimisation approach of introducing more specialised versions of general algorithms is called algorithm specialisation. The previous sections detailed the general algorithm, describing which subset of types or properties the task is a special case of, and which are typically more efficient than the most general implementation of that general algorithm.

Central to the implementation of algorithm specialisation is the property that the more specialised variants are automatically selected when they are applicable, rather than the caller having to ensure that these variants are called. In our simple example, this was accomplished by overloading the function (or generally a function template) with a most general function template (the first one), and ensuring that the more specialised function template was also more specialised based on C++ partial ordering rules.

Not all conceptually more specialised algorithm variants can be directly translated into function templates that provide the right partial ordering behaviour. For a few examples, consider:

However, the alternative presented here is more broadly applicable:

```cpp
template<typename InputIterator, typename Distance>
void advanceIter(InputIterator& i, Distance n) {
    while (n > 0) {    // linear time
        ++i;

    }
}
```

For a certain class or class template—those that provide random access operators—we can provide a more efficient implementation.

```cpp

void advanceIter(RandomAccessIterator& i, Distance n) {
    i += n;    // constant time
}
```

Unfortunately, defining both of these function templates will result in a compiler error, because—as noted in the introduction—function templates are compared for partial ordering only if they are equally specialised. We can make this work by overloading the function template; this is shown below. However, the examples in this chapter will discuss techniques that enable the desired effect of overloading these function templates.

### 20.2 TAG DISPATCHING

One approach to algorithm specialisation is to “tag” different implementations of an algorithm with a unique type that describes that variant and allows the compiler to automatically select the best implementation for the task at hand. We can use the standard library’s iterator category tags (defined below) to simplify the two implementation variants of the advanceIter() algorithm:

```cpp
template<typename InputIterator, typename Distance>
void advanceIter(InputIterator& i, Distance n, std::input_iterator_tag) {
    while (n > 0) {    // linear time
        ++i;
        --n;
    }
}

template<typename RandomAccessIterator, typename Distance>
void advanceIter(RandomAccessIterator& i, Distance n,
                 std::random_access_iterator_tag) {
    i += n;    // constant time
}
```

Then, the advanceIter() function template itself simply forwards its arguments on using the appropriate tag:

```cpp
template<typename Iterator, typename Distance>
void advanceIter(Iterator& i, Distance n)
{
    advanceIter(i, n,
                std::iterator_traits<Iterator>::iterator_category());
}
```

The trait class std::iterator_traits provides a category for the iterator type that is passed to it. The iterator category is one of the five iterator types mentioned earlier, which specify what kind of interface the type has. In the C++ standard library, the available tags are defined as follows, using inheritance to reflect when one iterator category is derived from another:

```cpp
namespace std {
    struct input_iterator_tag { };
    struct output_iterator_tag { };
    struct forward_iterator_tag : public input_iterator_tag { };
```
