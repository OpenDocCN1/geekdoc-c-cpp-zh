
```cpp
void f(int) {

}

template<int N>
void f(int (*)[N]);

int main()
{
    f(&X<int>::s);        // fine: T deduced to be
}
```

In the function template `f()`, the subscript `X<T>` is a non-deduced context. However, the member-class component `X<T>` of the pointer-to-member type is deducible; hence, and when the parameter is, which is deduced from R, is plugged in the non-deduced context, a type compatible with that of the actual argument `X<T>::s` is obtained. The deduction therefore succeeds on that argument-parameter pair.

Conversely, it is possible to deduce contradictions for a parameter type entirely built from deduced contexts. For example, assuming suitably declared class templates X and Y:

Click here to view code image

```cpp
template<typename T>
void f(X<T>, Y<T>);

void g()
{
    f(X<int>{}, Y<int>{});       // OK

    f(X<int>{}, Y<char>{});      // ERROR: deduction
}
```

The problem with the second call to the function template `f<>` is that the two arguments deduce different arguments for the parameter `T`, which is not valid. (In both cases, the function argument is a temporary object created by calling the default constructor of the class template X.)

## 15.3 SPECIAL DEDUCTION SITUATIONS

There are several situations in which the pair (P, A) used for deduction is not obtained from the arguments to a function call and the parameters of a function template. The first situation occurs when the address of a function template is taken. In this case, P is the parameterized type of the function template declaration, and A is the function type underlying the pointer that is initialized or assigned to. For example:

Click here to view code image

```cpp
template<typename T>
void f(T, T&);

void (*pf)(char, char) = &f;
```

In this example, P is `void f(T, T&)` and A is `void f(char, char)`. Deduction succeeds with T substituted with char, and pf is initialized to the address of the specialization `f<char>`.

Similarly, function types are used for P and A for two other special situations:

- Determining a partial ordering between overloaded function templates
- Matching an explicit specialization to a function template
- Matching an explicit instantiation to a template
- Matching a friend function template specialization to a template
- Matching a placement operator delete or operator delete[] to a corresponding placement operator new or operator new[] template

Some of these topics, along with the use of template argument deduction for class template partial specializations, are further developed in Chapter 16.

Another special situation occurs with conversion function templates. For example:

Click here to view code image

```cpp
class S {
public:
    template<typename T> operator T();
};
```

In this case, the pair (P, A) is obtained as if it involved an argument of the type we are attempting to convert and a parameter type that is the return type of the conversion function template. The following illustrates one variation:

```cpp
f(s)
```

Here we are attempting to convert `s` to `int[20]`. Type A is therefore `int[20]` and type P is `T`. The deduction succeeds with `T` substituted with `int[20]`.

Finally, some special treatment is also needed for the deduction of the auto placeholder type. That is discussed in Section 15.4.10 on page 313.

## 15.4 INITIALIZER LISTS

When the argument of a function call is an initializer list, that argument doesn't have a specific type, so in general no deduction will be performed from that given input (i.e., because there is no A type example).

Click here to view code image

```cpp
#include <initializer_list>

template<typename T>
void f(T p);

int main() {
    f({1, 2, 3});   // ERROR: cannot deduce T from a braced-init-list
}
```

However, if the parameter type P, after removing references and top-level `const` and `volatile` qualifiers, is equivalent to `std::initializer_list<T>`, P can be deduced from a braced-init-list, deduction proceeds by comparing T to the type of each element in the initializer list, succeeding only if all of the elements have the same type:

Click here to view code image

```cpp
#include <initializer_list>

template<typename T>
void f(std::initializer_list<T>);

int main()
{
    f({2, 3, 5, 7, 9});       // OK: T is deduced
    f({4, 'c', 1, 'd'});       // ERROR: T has conflicting types
}
```

Similarly, if the parameter type P is a reference to an array type with element type P that has a deducible pattern, deduction proceeds by comparing P to the type of each element in the initializer list, succeeding only if all of the elements have the same type. Furthermore, if the bound has a deducible pattern (i.e., it just names a non-type parameter), then that bound is deduced to be the number of elements in the list.

## 15.5 PARAMETER PACKS

The deduction process matches each argument to each parameter to determine the values of template arguments. When performing template argument deduction for variadic templates, however, the relationship between parameters and arguments no longer holds, because a parameter pack can match multiple arguments. In this case, the same parameter pack (`P`) is matched to multiple arguments (`A`), and each matching produces an additional value for any template parameter pack in P.

Click here to view code image

```cpp
template<typename First, typename... Rest>
void f(First first, Rest... rest);

void g(int i, double d, int *p) {
    f(i, d, p);
}
```

Here, the deduction for the first function parameter is simple, since it does not involve any parameter packs. The second function parameter, `rest`, is a function parameter pack. Its type is a pack expansion (`Rest...`) whose pattern is the type `Rest`. This pattern serves as `P`, to be compared against the type of the second and third call arguments. When compared against the first such argument, `d` (the type `double`), the first value in the template parameter pack `Rest` is deduced to be `double`. Similarly, when compared against the second such argument, `p` (the type `int*`), the second value in the template parameter pack `Rest` is deduced to be `int*`. Thus, deduction determines the value of the parameter pack `Rest` to be the sequence `[double, int*]`, substituting the results of that deduction and the deduction for the first function parameter yields the function type `void f(int, double, int*)`, which matches the argument types at the call site.

Because deduction for function parameter packs uses the pattern of the expansion for its comparison, the pattern can be arbitrarily complex, and values for multiple template parameters and parameter packs can be determined from each of the argument types. Consider the deduction behavior of the functions `f()` and `h()` below:

Click here to view code image

```cpp
void h1(pair<T, Rest...> const&);

template<typename T, typename... Rest>
void h2(pair<T, Rest...> const&);

void foo(pair<T1, T2> const& p, int& pi, double* pd,
         pair<double*, double> pdd)
{
    h1(pi, pdd); // OK: deduces T to int, Rest to (float,
                 // double)
    h2(pi, pdd); // ERROR: T deduced to int from the first
                 // argument but to double from the second
    h1(pi, pdd); // OK: one deduces T to int, double, Rest
    h2(pi, pdd); // ERROR: T deduced to (int, double), Rest
                 // to (float, double)
}
```

For both h1() and h2(), P is a reference type that is adjusted to the unqualified version of the reference (pair<T, Rest...> or pair<T, T2>, respectively) for deduction against each argument type. Since all arguments are specializations of class template pair, the template arguments are compared. For h1(), the first template argument (T) is not a parameter pack, so it is deduced independently for each argument. If the deductions differ, as in the second call to h1(), deduction fails. For the second pair template argument both h1() and h2() (first) are different, and the function template argument deduction determines the corresponding types. For h2(), the second call to h2() has the same problem.

For both h1() and h2(), the function template parameter packs are deduced by comparing the pattern of the pack expansion embedded within the tuple type. The types must be compatible for the function call to succeed.

```cpp
template<typename... Types> class tuple { };

template<typename... Types>
tuple(Types&&...);

template<typename T1, typename... Types>
tuple(T1&&, Types&&...);

void bar(tuple<short, int, long> sv,
         tuple<unsigned short, unsigned long> uv)
{
    f1(sv, sv); // OK: Types is deduced to (short, int,
                // long)
    f2(sv, sv); // OK: Types is deduced to (short, int,
                // long)
    f1(sv, uv); // ERROR: Types is deduced to (short, int,
                // long) from the first argument but to
                // (unsigned short, unsigned long) from the
                // second
}
```

In both f1() and f2(), the template parameter packs are deduced by comparing the pattern of the pack expansion embedded within the Tuple type. The types for f1() are against each of the template arguments of the tuple type provided by the call argument, deducing successive values for the corresponding template parameter pack. The function f1() uses the same template parameter pack Types in both function parameters, meaning that deduction only succeeds when the two function call arguments have the same set of types. The function f2(), on the other hand, uses different parameter packs for the Tuple type in each of its function parameters, so the types of the function call arguments can be different as long as each specialization is compatible with its corresponding parameter pack.

### 15.5.1 LITERAL OPERATOR TEMPLATE

Literal operator templates have their argument determined in a unique way. The following example illustrates this:

```cpp
template<char...> operator "" _B7() { }        // #1

int n = 121_B7;                                // #2
```

Here, the initial 121_B7 contains a user-defined literal, which is turned into a call to the literal operator template with the template argument list of '1', '2', and '1'. Thus, an implementation of the literal operator such as

```cpp
template<char... Chars>
operator "" _B7()
{
    std::array<char, sizeof...(Chars)>
        arr = {Chars...};
    for (char c : arr)                     // and use it (print
        std::cout << c << " ";
}
```
