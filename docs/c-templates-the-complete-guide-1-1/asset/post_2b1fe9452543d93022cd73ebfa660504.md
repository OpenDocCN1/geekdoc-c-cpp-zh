
A template argument list would normally succeed by substituting A2 for T. In the other direction, deduction of this third template against the first's synthesized argument list succeeds by substituting the single-element sequence (A) for the parameter pack P. Partial ordering between the first and third templates would normally result in an ambiguity. However, a special rule prohibits an argument that originally came from a function parameter pack (e.g., the third template's parameter pack T...) from matching a parameter pack (e.g., the first template's parameter pack).

Hence, template deduction of the first template against the third's synthesized argument list fails, and the first template is considered more specialized than the third. This special rule effectively considers nonvariadic templates (those with a fixed number of parameters) to be more specialized than their variadic template counterparts.

The rules described above apply equally to pack expansions that occur in types in the function signature. For example, we can wrap the parameters as arguments of each of the function templates in our previous example into a variadic class template Tuple to arrive at a similar example not involving function parameter packs:

details/tupleoverload.cpp

```cpp

{
};

template<typename T>
int f(Tuple<T>)
{
    return 1;
}

template<typename... Ts>
int f(Tuple<Ts...>)
{
    return 2;
}

template<typename T, typename... Ts>

{
    return 3;
}

int main()
{
    std::cout << f(Tuple<int, double>{});    // calls f
    std::cout << f(Tuple<int, double>{});    // calls f
```

## 16.3 EXPLICIT SPECIALIZATION

The ability to overload function templates, combined with the partial ordering rules to select the “best” matching function template, allows us to use specialized templates for a generic implementation to use code appropriately for greater efficiency. However, class templates and variable templates cannot be overloaded; instead, partial specialization was chosen to enable transparent customization of class templates: explicit specialization of a class template is analogous to the function template specialization. For example, a programmer might want to provide a specialized template for a template with template parameters that are fully substituted. No template parameters remain. Class templates, function templates, and variable templates can be fully specialized.

So can members of class templates that may be defined outside the body of a class definition (i.e., member functions, nested data members, and member enumeration types) of a class template. Full specializations and partial specializations are both equally “explicit” in source code, which is why we avoid the term explicit specialization in our discussion. Neither full nor partial specialization introduces a totally new template or template instance. Instead, these customizations provide alternative definitions for instances that are already implicitly declared in the generic (or unspecialized) template. This is a relatively important implementation observation, and it is a key difference with overloaded templates.

### 16.3.1 Full Class Template Specialization

A full specialization is introduced with a sequence of three tokens: `template`, `<`, and `>`. In addition, the class name is followed by the template arguments for which the specialization is declared. The following example illustrates this:

```cpp
template<typename T>
class S {
public:
    void info() {
        std::cout << "generic (S<T>::info())\n";
    }
};

template<>
class S<int> {
public:
    void info() {
        std::cout << "fully specialized (S<int>::info())\n";
    }
};
```

Note how the implementation of the full specialization does not need to be related in any way to the generic definition: This allows us to have member functions of different names. However, the functionality is solely determined by the name of the class template.

The list of specified template arguments must correspond to the list of template parameters. For example, it is not valid to specify a non-type value for a template type parameter. However, template arguments for parameters with default template arguments are optional:

```cpp
template<typename T> class Types {
public:
    using Type = int;
};

template<typename T, typename U = typename Types<T>::Type>
class S;

template<> class S<> {        // #1
};

template<> class S<int> {     // #2
public:
    void f();
};

template<> class S<char, char> {  // #3
};

int main()
{
    S<int> p;             // OK: uses #2, no definition needed
    S<int, int> q;        // ERROR: uses #1, but no definition available
    S<double> rv;         // OK: uses #2, definition available
    S<double, char> s;    // OK: uses #3
    S<char> e;            // ERROR: uses #3, but no definition available
}
```

As the example also shows, declarations of full specializations (and of templates) do not necessarily have to be definitions. However, when a full specialization is declared, the generic definition is never used for the given set of template arguments. Hence, if a definition is needed but is not provided, the program is in error. For class template specialization, it is sometimes useful to “forward declare” types so that potentially dependent types can be constructed. A full specialization declaration is very similar to a normal class declaration in this way (it is not a template declaration!). The only differences are the syntax and the fact that the declaration must match a previous template declaration. Because it is not a template declaration, the members of a full class template specialization can be defined using the ordinary out-of-class member definition syntax (in other words, the `template<>` prefix cannot be omitted):

```cpp
template<typename T>
class S {
public:
    ...
};

template<> class S<char**> {
public:
    void print() const;
};
```

```cpp
template<>
void S<char**>::print() const
{
    std::cout << "pointer to pointer to char\n";
}
```

A more complex example may reinforce this notion:

```cpp
template<typename T>
class Outside {
public:
    template<typename U>
    class Inside {
    };
};
```

A full specialization is a replacement for the instantiation of a certain generic template, and it is not valid to have both the explicit and the generated versions of a template present in the same program. An attempt to use both in the same file is usually caught by a compiler:

```cpp
template<typename T>
class Invalid {
};

Invalid<void> x1;       // causes the instantiation of Invalid<void>

template<>
class Invalid<void> {  // ERROR: Invalid<void> already
                        // instantiated
};
```

Unfortunately, if this occurs in different translation units, this problem may not be caught by a compiler. The following invalid C++ example contains two files which use templates and invokes many implementations, but it is invalid and dangerous:

```cpp
// Translation unit 1:
template<typename T>
class Danger {
public:
    enum {
        max = 100
    };
};

char buffer[Danger<void>::max]; // use generic value

extern void clear(char*);

int main()
{
    clear(buffer);
}

// Translation unit 2:
template<typename T>
class Danger {
};

template<>
class Danger<void> {
public:
    enum { max = 100 };
};

void clear(char* buf)
{
    // mismatch in array bounds?
    for (int i = 0; i < Danger<void>::max; ++i) {
        buf[i] = 0;
    }
}
```

This example is clearly destined to keep its shirt, but it illustrates that care must be taken to ensure that the declaration of the specialization is visible to all the users of the generic template. In practical terms, this means that a declaration of the specialization should follow the declaration of the template in its header file. When the generic implementation comes from an external source, such that the corresponding header files should not be modified, this is not necessarily practical, but it may be worth creating a header including the generic template followed by declarations of the specializations to avoid these hard-to-find errors. We find that, in general, it is better to avoid specializing templates coming from an external source unless it is clearly marked as being designed for that purpose.
