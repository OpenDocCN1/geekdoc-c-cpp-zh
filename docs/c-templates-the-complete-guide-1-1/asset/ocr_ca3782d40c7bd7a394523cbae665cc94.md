Once we see, map operations are simply forwarded to the underlying Map object. However, when copying another array, we must take into account the possibility that the other array is really built on an expression template. Thus, we parameterize these copy operations in terms of the underlying Rep representation.

Thus subscribing operator deserves a little discussion. Notice that the core version of that operator uses a deduced return type rather than the more traditional type trait syntax. We do that because if Rep represents a M_array & A_util, its subscripting operator returns a temporary sub-expression, which cannot be returned by reference (and thus be a reference to that). If we decide no reference type for the rvalue result, then the operator produces a const lvalue, and the deduced return type will be a matching const reference for that case.
