code. However, we may know that from a low-level point of view, the code for `List<int>::append()` and `List<double>::append()` is the same. The template mechanism should generate essentially the same machine code, performing the same operations, and only the type of the parameter is different. Although this cannot be expressed in C++, we can achieve something similar by avoiding that all `List`s of pointers should be instantiated from a different template definition.

```
```cpp
template<typename T>
class List { // §
private:
    ListNode<T>* impl;

public:
    // ...
    inline void append(T x) {
        impl.append(x);
    }

    inline auto length() const {
        return impl.length();
    }
};
```
```

In this context, the original template at point x is called the primary template, and the later definition is called a partial specialization because the template arguments for which this template definition must be used are more specialized than those of the primary template. That is, our partial specialization is a specialization of a template parameter list declaration (Template<...>) and a set of explicitly specified template arguments on the name of the class template (T in our example).

Our code contains a problem because `ListNode<T>` innocently contains a member of that name (see `ListNode<T>` type). To break the cycle, we can prevent the partial specialization with a full specialization:

[Click here to view code image](#)

```
```cpp
template<>
class List<void*> { // §
    void* append(void* p);
    size_t length() const;
};
```
```

This works because matching full specializations are preferred over partial specializations. As a result, all member functions of `List<T*>` are now defined (though usually inefficiently) in terms of the implementation of `List<void*>`. This is an effective way to combat code bloat (of which C++ compilers are often accused).

There exist several limitations on the parameter and argument lists of partial specialization declarations. Some of these are as follows:

+   1. The arguments of the partial specialization must match in kind (type, template, or value) the corresponding parameters of the primary template.
+   2. The parameter list of the partial specialization cannot have default arguments; the default arguments of the primary class template are used instead.
+   3. The non-type arguments of the partial specialization should be either dependent values or plain template parameter types. You cannot make more complex dependent expressions like `2*N` (where N is a template parameter).
+   4. The list of template arguments of the partial specialization should not be identical (ignoring renaming) to the list of parameters of the primary template.
+   5. If one of the template arguments is a pack expansion, it must occur at the end of a template argument list.

An example illustrates these limitations:

[Click here to view code image](#)

```
```cpp
template<typename T, int I = 3>
class C {
    // primary template
};

template<typename T>
class C<T, 3> {
    // ERROR: parameter kind mismatch
};

template<typename T, int I>
class C<T*, I> {
    // ERROR: no default arguments
};

template<typename T, int I>
class C<T, I, I> {
    // ERROR: no template argument difference from primary template
};

template<typename T, int I>
class C<T, I> {
    // ERROR: no significant difference from primary template
};

template<typename... Ts>
class C<Ts, 0> {
    // ERROR: pack expansion not at the end of the list
};

template<typename T, typename U, typename... Ts>
class C<T, U, Ts..., 0> {
    // ERROR: pack expansion not at the end of the list
};
```
