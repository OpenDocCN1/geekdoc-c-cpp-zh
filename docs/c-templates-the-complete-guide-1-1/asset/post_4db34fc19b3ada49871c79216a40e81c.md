
## Chapter 25

### Tuples

Throughout this book we often use homogeneous containers and array-like types to illustrate the power of templates. Such homogeneous structures extend the concept of C/C++ arrays and are pervasive in most applications. C++ (and C) also has a nonhomogeneous equivalent: tuples. This chapter explores a nonhomogeneous aggregate data type that is similar to classes and structs. For example, a tuple containing an int, a double, and a string is a nonhomogeneous equivalent: a struct with int, double, and std::string members, except that the elements of the tuple are referenced positionally (as 0, 1, 2 rather than through member names). The positional interface and the ability to easily construct a tuple from a type-list make tuples more suitable than structs for use with template metaprogramming techniques.

An alternative view on tuples is as a manifestation of a typelist in the executable program. For example, while a typelist `TypeList<int, double, std::string>` describes the sequence of types containing `int`, `double`, and `std::string` that can be manipulated at compile time, a tuple `<int, double, std::string>` describes storage for an `int`, a `double`, and a string that can be manipulated at run time. For example, the following program creates an instance of such a tuple:

```cpp
template<typename... Types>
class Tuple {

  // implementation discussed below
};

Tuple<int, double, std::string> t{17, 3.14, "Hello World!"};
```

It is common to use tuples simultaneously with traits to separate tuples that can be used to store data. For example, even though we’ve serially selected `int`, `double`, and `std::string` as element types in the example above, we could have created the set of tuples stored by the tuple with a metaprogram.

In the remainder of this chapter, we will explore the implementation and manipulation of the `Tuple` class template, which is a simplified version of the class template `std::tuple`.

### 25.1 Basic Tuple Design

#### 25.1.1 Storage

Tuples contain storage for each of the types in the template argument list. That storage can be accessed through a function template `get`, used as `get<0>(t)` for a tuple `t`. For example, `get<1>(t)` in the following example would return a reference to the double `3.14` in the tuple.

The recursive formulation of tuple storage is based on the idea that a tuple containing N > 0 elements can be stored as both a single element (the first element, or head of the list) and a tuple containing N - 1 elements (the tail). The element type `Tuple<int, double, std::string>` can be stored as an `int` and a `Tuple<double, std::string>`. That two-element tuple can in turn be stored as a `double` and a `Tuple<std::string>`. That one-element tuple can be stored as an `std::string` and a `Tuple<>`. In fact, this is the same kind of recursive decomposition used in the generic versions of typelist algorithms, and the actual implementation of recursive tuple storage unfolds similarly:

```cpp
template<typename... Types>
class Tuple
{
};

// recursive case:

template<typename Head, typename... Tail>
class Tuple<Head, Tail...>
{
private:
    Head head;
    Tuple<Tail...> tail;

public:

    // constructor:

    Tuple() {
    }

    Tuple(Head const& head, Tuple<Tail...> const& tail)
        : head(head), tail(tail) {
    }

    Head& getHead() { return head; }

    Head const& getHead() const { return head; }

    Tuple<Tail...>& getTail() { return tail; }

    Tuple<Tail...> const& getTail() const { return tail; }

};

// basis case:

template<>
class Tuple<> {
    // no storage required
};
```

In the recursive case, each Tuple instance contains a data member head that stores the first element in the list, along with a data member tail that stores the remaining elements in the list. The basis case is simply the empty tuple, which has no associated storage.

The get function template allows this recursive structure to extract the requested element:

```cpp
// recursive case

template<unsigned I>
struct TupleGet {
    template<typename Head, typename... Tail>
    static auto apply(Tuple<Head, Tail...> const& t)
        -> decltype(TupleGet<I-1>::apply(t.getTail())) {
        return TupleGet<I-1>::apply(t.getTail());
    }
};

// basis case:

template<>
struct TupleGet<0> {
    template<typename Head, typename... Tail>
    static Head const& apply(Tuple<Head, Tail...> const& t) {
        return t.getHead();
    }
};

template<unsigned I, typename... Types>
```

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_392_0.png)

Notice that the function template `get` is simply a thin wrapper over a call to a static member function of `TupleGet`. This technique is effective as a workaround for the lack of partial specialization of function templates (discussed in Section 17.2 on page 303), which is used to specialize the value of `I`. In the recursive case (`I > 0`), the static member function `apply()` extracts the tail of the current tuple and decrements `I` to keep looking for the requested element number into the tuple. The basis `apply()` returns the head of the current tuple, completing the implementation.

#### 25.1.2 Construction

Besides the constructors defined so far:

```cpp
Tuple(Head const& head, Tuple<Tail...> const& tail)
  : head(head), tail(tail) { }
```

for a tuple to be useful, we need to be able to construct it both from a set of independent values (one for each element) and from another tuple. Constructing from a set of independent values passes the first of those values to initialize the head element (via its base class), then passes the remaining values to the base class representing the tail.

```cpp
template<typename... Tail>
Tuple(Head const& head, Tail const&... tail)
  : head(head), tail(tail...) { }
```

This enables our initial Tuple example:

```cpp
Tuple<int, double, std::string> t{7, 3.14, "Hello World!"};
```

However, this isn't the most general interface: Users may wish to move-construct to initialize some (but perhaps not all) of the elements or to have an element constructed from a value of a different type. Therefore, we should use perfect forwarding (Section 5.6.3 on page 88) to initialize the tuple:

```cpp
template<typename Value, typename... Tail>
Tuple(Value&& head, Tail&&... tail)
  : head(std::forward<Value>(head)),
    tail(std::forward<Tail>(tail)...) { }
```

Next, we implement support for constructing a tuple from another tuple:

```cpp
template<typename Value, typename... Tail>
Tuple(Tuple<Value, Tail...> const& other)
  : head(other.getHead()), tail(other.getTail()) { }
```

However, the introduction of this constructor does not suffice to allow two-way conversions: Given the tuple t above, an attempt to create another tuple with compatible types will fail:

```cpp
// ERROR: no conversion from Tuple<int, double, string>
// to long
Tuple<long, double, double> t2{t};
```

The problem here is that the constructor template must be initialized from a set of independent values (a larger tuple than the constructor parameter accepts a tuple). To address this problem, we have to use a special technique (see Section 6.3 on page 45 and Section 20.3 on page 690) to disable both member-function templates when the tail does not have the expected length.

```cpp
template<typename Head, typename... Tail>
    typename std::enable_if<sizeof...(Tail) ==
        std::tuple_size<...>::value>::type
Tuple(Head&& head, Tail&&... tail)
  : head(std::forward<Head>(head)),
    tail(std::forward<Tail>(tail)...) { }

template<typename Head, typename... Tail>
    typename std::enable_if<...>::type
Tuple(Tuple<Head, Tail...> const& other)
```

You can find all constructor declarations in `tuples/tuple.cpp`.

A `makeTuple()` function template uses deduction to determine the element types of the `Tuple` it returns, making it far easier to create a tuple from a given set of elements:

*tuples/makeTuple.cpp*

```cpp
template<typename... Types>
auto makeTuple(Types&&... elems)
{
    return Tuple<std::decay_t<Types>...>(std::forward<Types>(elems)...);
}
```

Again, we use perfect forwarding combined with the `std::decay<>` trait to convert string literals and other raw arrays into pointers and remove `const` and references. For example:

*tuples/makeTuple.cpp*

```cpp
makeTuple(19, 3.14, "Hello, World!")
```

initializes a `Tuple<int, double, char const*>`.

### 25.2 Basic Tuple Operations

#### 25.2.1 Comparison

Tuples are structures that contain other values. To compare two tuples, it suffices to compare their elements. Therefore, we can write a definition of `operator<` to compare two definitions element-wise:

*tuples/tuple.hpp*

```cpp
// basic case:
bool operator<(Tuple<> const&, Tuple<> const&)
{
    // empty tuples are always equivalent
    return false;
}

// recursive case:
template<typename Head1, typename... Tail1,
         typename Head2, typename... Tail2>
bool operator<(Tuple<Head1, Tail1...> const& lhs,
               Tuple<Head2, Tail2...> const& rhs)
{
    return lhs.getHead() < rhs.getHead() ||
           (!(rhs.getHead() < lhs.getHead()) &&
            lhs.getTail() < rhs.getTail());
}
```

Like many algorithms on typelists and tuples, the element-wise comparison visits the head element and then recurses to visit the tail, eventually hitting the base case. The `==`, `!=`, `<`, `<=`, `>`, and `>=` operators follow analogously.
