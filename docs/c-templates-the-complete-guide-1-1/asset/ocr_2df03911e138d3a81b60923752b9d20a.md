```
Note that, unlike a normal C++ if-then-else statement, the template arguments for both the “then” and “else” branches are evaluated before the selection is made, so neither branch may contain ill-formed code, or the program is likely to be ill-formed. Consider, for example, a trait that yields the corresponding unsigned type for a given signed type. There is a standard trait, `std::make_unsigned`, which does this conversion, but it requires that the passed type is a signed integral type and no `bool`; otherwise its result is undefined behavior. The naive approach is shown below.

**Click here to view code image**

```
```cpp
// ERROR: undefined behavior if T is bool or no integral type
template<typename T>
struct makeUnsignedT {
    using Type = typename IfThenElse<is_integral<T>::value
        && !std::is_same<T, bool>::value,
        typename std::make_unsigned<T>::type,
        IdentityT<T>>::Type;
};
```
```

The instantiation of `makeUnsignedT<bool>` is still undefined behavior, because the compiler will still attempt to get the type from the `std::make_unsigned<bool>` specialization.

**Click here to view code image**

`typename std::make_unsigned<T>::type`

To address this problem, we need to add an additional level of indirection, so that the `IfThenElse` arguments are themselves our type functions that map the result.

**Click here to view code image**

```
```cpp
// yield T when using member Type:
template<typename T>
struct IdentityT {
    using Type = T;
};

// to make unsigned after IfThenElse was evaluated:
template<typename T>
struct MakeUnsignedT {
    using Type = typename std::make_unsigned<T>::type;
};
```
```

In the definition of `UnsignedT`, the type arguments to `IfThenElse` are both instances of our function classes. However, the type functions are not actually evaluated before `IfThenElse` selection. Instead, the type arguments to `IfThenElse` are classes that define an inner `Type` member. Hence, the `IfThenElse` selects the type function instance of either `MakeUnsignedT<T>` or `IdentityT<T>` in the selected branch, and it can then be instantiated to produce `Type`.

It is worth emphasizing here that this relies entirely on the fact that the not-selected wrapper type in the `IfThenElse` construct is never fully instantiated. In particular, the following does not work:
```
