An excellent discussion of the core issues surrounding this problem can be found in [Fairbanks02], in which Bryce Adelstein Lelbach identifies two classes of approaches to determine whether a class template argument is valid: a syntactic one that attempts to identify the validity of an expression (e.g., `std::is_constructible`), and a semantic one that checks whether a given type is a legitimate match for a given template parameter. He also mentions that the resulting code is not always as efficient as the original code.

If the type that we pass in doesn't have the default constructor, an error is now diagnosed on the line where `std::is_class` was called. Not because the class is not actually true, but because the compiler attempts to instantiate the template for a type that doesn't have a default constructor. Unfortunately, many compilers still don't implement `std::is_class` well enough (or at least not correctly), and this approach still doesn't work. We can define a type to be used as a template parameter and use `std::is_class` to check whether the type is a class. This approach still doesn't work because of the first issue.

# ## Concept Checking

Clearly, the development of the dummy code in our example can become tedious. We need a better way to check whether a given template argument satisfies the syntactic requirements of a template. To meet this complexity, it is natural to introduce a concept in the language to check whether a type is valid for a template. The concept is a compile-time predicate that can be used to check whether a template argument is valid. This approach is more efficient than previous approaches and is the one currently used by the Standard Library. The most popular such library is Boost (see [Boost]).

Unfortunately, the technique isn't particularly portable (the way errors are diagnosed differs considerably from one compiler to another) and sometimes masks issues that cannot be expressed at a higher level.

Once we have concepts in C++ (see Appendix A), we will have other ways to specify requirements and expected behavior.
