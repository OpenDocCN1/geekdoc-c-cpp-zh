
are not compound from multiple underlying types. Simple compound types can be classified using partial specialization.

### Pointers

We start with one such simple classification, for pointer types:

Click here to view code image

traits2/traits/ptr.hpp

```cpp
template<typename T>
struct IsPointerT : std::false_type {    // primary template
};

template<typename T>
struct IsPointerT<T*> : std::true_type {  // partial specialization
    using BaseT = T*;                      // type pointing to
};
```

The primary template is a catch-all case for nonpointer types and, as usual, provides a value constant false through its base class std::false_type, indicating that the type is not a pointer. The partial specialization catches any kind of pointer (T*) and provides the value true to indicate that the provided type is a pointer. Additionally, it provides a type member BaseT that describes the type that the pointer points to. Note that this type member is only available when the original type was a pointer, making this a SFINAE-friendly type trait (see Section 9.4.8, on page 424).

The C++ standard library provides a corresponding trait std::is_pointer<>, which, however, does not provide a member for the type the pointer points to. It is described in Section 2.1 on page 76.

### Arrays

When defining traits to determine arrays, it may require a specialization that the partial specializations involve more template parameters than the primary template:

Click here to view code image

[traits/is_array_type.cpp](traits/is_array_type.cpp)

```cpp
#include <cstddef>

template<typename T>
struct IsArray : std::false_type {        /* primary specialization */
};

template<typename T, std::size_t N>
struct IsArray<T[N]> : std::true_type {   /* partial specialization */
    using BaseT = T;
    static constexpr std::size_t size = N;
};

template<typename T>
struct IsArray<T[]> : std::true_type {    /* partial specialization */
    using BaseT = T;
    static constexpr std::size_t size = 0;
};
```

Here, multiple additional members provide information about the arrays being classified: their base type and their size (with 0 used to denote an unknown size).

The C++ standard library provides the corresponding trait `std::is_array` to check whether a type is an array, which is described in Section 2.0 on page 70. In addition, traits such as `std::rank` and `std::extent` also allow us to query their number of dimensions and the size of a specific dimension (see Section 2.3.1 on page 75).

### Pointers to Members

Pointers to members can be created using the same technique:

Click here to view code image

[traits/is_pointer_to_member.cpp](traits/is_pointer_to_member.cpp)

```cpp
template<typename T>
struct IsPointerToMember : std::false_type {
};

template<typename T, typename C>
struct IsPointerToMember<T C::*> : std::true_type {
    using MemberT = T;
    using ClassT = C;
};
```

`ClassT` is the type of the class in which that member occurs.

The C++ standard library provides more specific traits, `std::is_member_object_pointer<T>` and `std::is_member_function_pointer<T>`, which are described in Section 2.1.1 on page 75, as well as `std::is_member_pointer<T>`, which is described in Section 3.2.2 on page 76.

### 9.8.3 Identifying Function Types

Function types are interesting because they have an arbitrary number of parameters in addition to the return type. Therefore, within the partial specialization matching a function type, we employ a parameter pack to capture all of the parameter types, as we did for the `Decay` trait in Section 10.3.2 on page 149.

Click here to view code image

```cpp
template<typename T>
struct IsFunctionT : std::false_type { /*primary
                                      template*/
};

template<typename R, typename... Params>
struct IsFunctionT<R(Params...)> : std::true_type {
  using Type = R;
  using ParamT = TypeList<Params...>;
  static constexpr bool value = true;
};

template<typename R, typename... Params>
struct IsFunctionT<R(Params...) &> : std::true_type {
  using Type = R;
  using ParamT = TypeList<Params...>;
  static constexpr bool value = true;
};
```

Notice that each part of the function type is expressed: The return type is the result type, while all of the parameters are captured in a single typelist as `ParamT` (typelists are covered in Chapter 4), and variadic indirection rather than the function type uses C-style varargs.

Unfortunately, this formulation of `IsFunctionT` does not handle all function types, because function types can have const and volatile qualifiers as well as an lvalue (`&`) and rvalue (`&&`) reference qualifiers (described in Section 2.1.1 on page 63), and since C++17, `noexcept` qualifiers. For example:

Click here to view code image

```cpp
using MyFunction = void(int) const;
```

Such function types can only be meaningfully used for nonstatic member functions that are function types themselves. Moreover, a function type member must consist of an exact arbitrary const type. To demonstrate, it is not able to strip the const from the function type. Therefore, to recognize function types that have qualifiers, we need to introduce a large number of additional partial specializations, covering every combination of qualifiers (both lvalue and rvalue). Here, we illustrate only a few of the many qualified partial specializations:

```cpp
template<typename R, typename... Params>
struct IsFunctionT<R(Params...) const> : std::true_type {
  using Type = R;
  using ParamT = TypeList<Params...>;
  static constexpr bool value = true;
};

template<typename R, typename... Params>
struct IsFunctionT<R(Params...) volatile>
  : std::true_type {
  using Type = R;
  using ParamT = TypeList<Params...>;
  static constexpr bool value = true;
};

template<typename R, typename... Params>
struct IsFunctionT<R(Params...) const volatile>
  : std::true_type {
  using Type = R;
  using ParamT = TypeList<Params...>;
  static constexpr bool value = true;
};

template<typename T, typename... Params>
struct IsFunction<T, Function<Params...>> : std::true_type {
  using Type = T;
  using ParamsT = Typelist<Params...>;
  static constexpr bool value = true;
};
```

With all this in place, we can now classify all types except class types and enumeration types. We tackle these cases in the following sections.

The C++ standard library provides the trait `std::is_function`, which is described in Section D.2.1 on page 706.

### 9.8.4 Determining Class Types

Unlike the other compound types we have handled so far, we have no partial specialization patterns that match class types specifically. Nor is it feasible to enumerate all class types, as it is for fundamental types. Instead, we need to use an indirect method to identify class types, by coming up with some trait that can be used to represent the kind of type in question (and not other types). With that type or expression, we can apply the SFINAE techniques discussed in Section 9.0 on page 411.

The most convenient property of class types to utilize in this case is that class types can be used as the basis of pointer-to-member types. That is, in a type construct of the form `X Y::*`, `Y` can also be a class type. The following formulation of `IsClass<T>` exploits this property (and picks an arbitrary type for `X`):

Click here to view code image

```cpp
trait/isclass.hpp

template<typename T, typename = void>
struct IsClassT : std::false_type { // primary template
};

template<typename T>
struct IsClassT<T, std::void_t<T T::*>> : std::true_type { // classes
  static constexpr bool value = true;
};
```

The C++ language specifies that the type of a lambda expression is a “unique, unnamed non-union class type.” For this reason, lambda expressions yield true when examining whether they are class type objects:

Click here to view code image

```cpp
void test() {
  auto l = []() {
    return IsClassT<decltype(l)>::value;
  };
}
```

The expression `T::*` is also valid for union types (they are also class types according to the C++ standard).

The C++ standard library provides the trait `std::is_class<T>` and `std::is_union<T>`, which are described in Section D.2.2 on page 705. However, these traits require special compiler support because distinguishing a class type from a union type cannot currently be done using any standard class language technique.

### 9.8.5 Determining Enumeration Types

The only types not classified by our trait are enumeration types. Testing for enumeration types can be performed directly by writing a SFINAE-based trait that checks for an explicit conversion to an integral type (say, `int`) and explicitly excluding fundamental types, class types, reference types, pointer types, and pointer-to-member types, all of which can be converted to an integral type but are not enumeration types. Instead, we simply note that any type that does not fall into any of the other categories must be an enumeration type, which we can implement as follows:

Click here to view code image

```cpp
trait/isenum.hpp

template<typename T>
struct IsEnumT {
  static constexpr bool value = !std::is_fundamental<T>::value
                          && !IsPointerT<T>::value;
};
```
