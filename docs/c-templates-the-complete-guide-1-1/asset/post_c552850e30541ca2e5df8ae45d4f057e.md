
```cpp
template<typename T>
class MyClass {
public:
    T m_t;                // user-initialize in subclass ctor
    ...
};
```

However, note that default arguments cannot use this syntax. For example:

```cpp
template<typename T>
void f(T t = T()); // ERROR
```

Instead, we have to write:

```cpp
template<typename T>
void f(T t = T()); // OK (T is an incomplete type) before C++11
```

### 5.3 USING THIS->

For class templates with base classes that depend on template parameters, using a name `x` by itself is not always equivalent to `this->x`, even though a member is found in a base class. For example:

```cpp
template<typename T>
class Base {
public:
    void bar();
};

template<typename T>
class Derived : Base<T> {
public:
    void foo() {
        bar(); // calls external bar() or error
    }
};
```

In this example, for reading the symbol `bar` inside `foo()`, `bar()` is not found in `Base<T>` (or in `Derived<T>`). Therefore, either you have an error or an external function `bar()` (such as a global `bar()`) is called.

We discuss this behavior in Section 9.4.2 on page 247. For the moment, a rule of thumb, we recommend that you always qualify any symbol that is declared in a base that is dependent on a template parameter with `this->` or `Base<T>::`.

### 5.4 TEMPLATES FOR RAW ARRAYS AND STRING LITERALS

When passing raw arrays or string literals to templates, some care has to be taken. First, if the template parameters are declared as references, the argument does not decay. That is, a parameter of type `T&` has the type `char[6]`. That can become a problem if raw arrays or string arguments of different length are passed because the types differ. Only when passed by value, the type decays, so that the type depends on the argument. This is discussed in detail in Chapter 7. Note that you can also provide templates that specifically deal with raw arrays or string literals. For example:

`basic/array.hpp`

```cpp
template<typename T, int N>
void foo(T (&)[N])
{
    for (int i = 0; i < N; ++i) {
        ...
    }
}
```

Here, when calling

```cpp
int a[3] = { 1, 2, 3 };
foo(a); // deduces T = int, N = 3
```

you can also use this template for string literals:

```cpp
foo("hello"); // deduces T = const char, N = 6
```

If you only want to provide a function template for string literals (and other char arrays), you can do this as follows:

function/array.cpp

```cpp
template<int N, int M>
bool less (char const(&a)[N], char const(&b)[M])
{
    for (int i = 0; i < N && i < M; ++i) {
        if (a[i] < b[i]) return true;
        if (b[i] < a[i]) return false;
    }
    return N < M;
}
```

Note that you can and sometimes have to overload or partially specialize for arrays of unknown bounds. The following program illustrates all possible overloads for arrays of known bounds, references to arrays of known bounds, arrays of unknown bounds, references to arrays of unknown bounds, and pointers.

function/array.hpp

```cpp
#include <iostream>

template<typename T>
struct MyClass;             // primary template

template<typename T, std::size_t SZ>
struct MyClass<T[SZ]>       // partial specialization for arrays of known bounds
{
    static void print() { std::cout << "print() for T[" << SZ << "]\n"; }
};

template<typename T, std::size_t SZ>
struct MyClass<T(&)[SZ]>    // partial spec. for references to arrays of known bounds
{
    static void print() { std::cout << "print() for T(&)[" << SZ << "]\n"; }
};

template<typename T>
struct MyClass<T[]>         // partial specialization for arrays of unknown bounds
{
    static void print() { std::cout << "print() for T[]\n"; }
};

template<typename T>
struct MyClass<T(&)[]>      // partial spec. for references to arrays of unknown bounds
{
    static void print() { std::cout << "print() for T(&)[]\n"; }
};

template<typename T>
struct MyClass<T*>          // partial specialization for pointers
{
    static void print() { std::cout << "print() for T*\n"; }
};
```

Each case is different and can occur when using arrays.

```cpp
template<typename T1, typename T2, typename T3>
void demo1(T1 a1, T2 a2, T3 a3) // pointers by using
{
    int a1[42];              // reference to array
    int a2[10];              // reference to array
    T1 a1;                   // passing by value
    T2 a2, T3& a3;           // passing by reference

    MyClass::demo1(a1);      // use MyClass
    MyClass::demo1(a2);      // use MyClass
    MyClass::demo1(a3);      // use MyClass
    MyClass::demo1(a1);      // use MyClass
    MyClass::demo1(a2);      // use MyClass
    MyClass::demo1(a3);      // use MyClass
}

int main()
{
    int a[42];
    MyClass::demo1(a);       // use MyClass

    extern int a[];
    MyClass::demo1(a);       // use MyClass

    double a, b, c, d, e, f;
    int a[] = { 0, 8, 15 };  // define forward
}
```

Note that a function parameter declared as an array (with or without length) by language rules really has a pointer type. Note also that templates for arrays of unknown bounds can be used for an incomplete type such as

```cpp
extern int a[];
```

And when this is passed by reference, it becomes an `int (&)[]`, which can also be used as a template parameter.

See Section 5.3.2 on page 60 for another example using the different array type in question.

### 5.5 MEMBER TEMPLATES

Class members can also be templates. This is possible for both nested classes and member functions. The application and advantage of this ability can be demonstrated with the `Stack<>` class template. Normally, you would not use a stack of stacks. However, when you want to use a stack whose element type is itself a stack, you need a stack with a member that is an element of any other type, even if there is an implicit type conversion for the element type defined:

```cpp
Stack<int> intStack;    // stack for ints
Stack<Stack<int> > intStackStack; // stack for stack for ints

intStack = intStack2;   // OK: stacks have same type
Stack<int> intStack;    // stack of ints
Stack<Stack<int> > intStackStack; // stack of stacks
intStack = intStack2;   // ERROR: stacks have different types
Stack<Stack<int> > intStackStack; // ERROR: stacks have different types
```

The default assignment operator requires that both sides of the assignment operator have the same type, which is not the case if stacks have different element types.

`basics/stack/stack1.hpp`

```cpp
template<typename T>
class Stack {
private:
    std::deque<T> elems;        // elements

public:
    void push(T const& elem);   // push element
    void pop();                 // pop element
    T const& top() const;       // return top element
    bool empty() const {        // return whether the
        return elems.empty();
    }

    // assign stack of elements of type T2
    template<typename T2>
    Stack& operator= (Stack<T2> const&);
};
```

The following two changes have been made:

- We added a declaration of an assignment operator for stacks of elements of another type T2.
- The stack now uses a `std::deque<>` as an internal container for the elements. Again, this is a consequence of the implementation of the new assignment operator.

The implementation of the new assignment operator looks like this:

`basics/stack/stack2.hpp`

```cpp
template<typename T>
template<typename T2>
Stack<T>& Stack<T>::operator= (Stack<T2> const& op2)
{
    Stack<T2> tmp(op2);              // create a copy

    elems.clear();                   // remove existing elements
    while (!tmp.empty()) {            // copy all elements
        elems.push_front(tmp.top());
        tmp.pop();
    }

    return *this;
}
```

First let's look at the syntax to define a member template. Inside the template with the template parameter T, an inner template with template parameter T2 is defined:

`basics/stack/stack3.hpp`

```cpp
template<typename T>
template<typename T2>
Stack<T>& Stack<T>::operator= (Stack<T2> const& op2)
{
```

Inside the member function, you may not simply access all necessary data for the assigned stack `op2`. However, this stack has a different type (for instance, if the class template has two different argument types, you get two different class types), so you are restricted to using the public interface. It follows that the only way to access the elements is calling `op2.top()`. However, each element has to become a top element, thus, a copy of `op2` must first be made, so that the elements are taken from that copy by calling `pop()`. Because `top()` returns the last element pushed onto the stack, we might prefer to use a container that supports the insertion of elements at the other end of the collection. For this reason, we use a `std::deque<>`, which provides `push_front()` to put an element on the other side of the collection.
