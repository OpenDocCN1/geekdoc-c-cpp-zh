```
```cpp

using PlusResultT = typename PlusResult<T1, T2>::type;
```
```

Given these alias templates, we can simplify our operator+ declaration down to

Click here to view code image

```
```cpp

Array<PlusResultT<T1, T2>>
operator+(const Array<T1>&, const Array<T2>&);
```
```

This second version is clearly shorter and makes the composition of the traits more obvious. Such improvements make alias templates more suitable for some uses of two traits.

However, there are downsides to using alias templates for type traits:

+   1. Alias templates cannot be specialized (as noted in Section 16.3 on page 613), and since many of the techniques for writing traits depend on specialization, an alias template will likely need to be a class template to a class template anyway.
+   
+   2. Some traits are meant to be specialized by users, such as a trait that describes whether a particular addition operation is commutative, and it can be confusing to specialize the class template when most uses involve the alias template.
+   
+   3. The use of an alias template will always instantiate the type (e.g., the underlying class template specialization), which makes it harder to avoid instantiating traits that don't make sense for a given type (as discussed in Section 19.7 on page 493).

Another way to express this point, is that alias templates cannot be used with metaprogramming forwarding (see Section 19.3.2 on page 494).

Because the use of alias templates for type traits has both positive and negative aspects, we recommend using them as we have in this section and as it's done in the C++ standard library. Prefer both class templates with a specific naming convention (we have chosen the suffix _t) and alias templates (with a slightly different naming convention (dropped the _t suffix)), and have each alias template defer to the underlying class template. This way, we can use alias templates wherever they provide clearer code, but fall back to class templates for whatever purpose.

Note that for historical reasons, the C++ standard library has a different convention. The type traits class templates yield a type and have no specific suffix (many were introduced in C++11). Corresponding alias templates (that produce the type directly) started being introduced in C++14, and were given a _t suffix, since the un-suffixed name was already standardized (see Section 19.4 on page 67).
