The general push_back() implementation works on any kind of typelist. Like previous algorithms developed in this section, it requires a linear number of template instantiations to evaluate. Because, for a typelist of length N, there will be N + 1 instantiations of PushBack<> and PushBack<T, List>, as well as N instantiations of Front<> and PopFront(). Counting the number of template instantiations can provide rough estimates of the time it will take to compile a particular algorithm, because template instantiation itself is a costly process for the compiler.

Compile time can be a problem for large template algorithms, so it is often desirable to minimize the number of template instantiations performed by these algorithms. In fact, our first implementation of PushBack<> employed a partial specialization on Typelist<> to optimize the algorithm, which requires only a constant number of template instantiations, making it far more efficient to use compile time than the generic version. However, because it is described as a partial specialization of PushBack<>, this efficient implementation will automatically be selected when performing PushBack<> on a Typelist<> instance, leaving the notion of algorithm specialization (as discussed in Section 20.1 on page 351) to template metaprograms. Many of the techniques discussed in this section can be applied to template metaprograms to reduce the number of template instantiations the algorithm performs.

# ### 24.2.2 Reversing a Typelist

When typelists have some ordering among their elements, it is convenient to be able to reverse the ordering of the elements in the typelist when applying some algorithms. For example, the Typelist Typelist<int, short, double> type would be reversed to Typelist<double, short, int>. This is a linear number of template instantiations. However, this is useful to reverse the order to match a particular protocol: Typelist<Typelist<int, long, int, short, signed char>> ordered by increasing size. The reverse algorithm implements this operation:

typelist/typelistreverse.hpp

```
    template<typename List, bool Empty = IsEmpty<List>::value>
    class ReverseT;
    
    template<typename List>
    using Reverse = typename ReverseT<List>::Type;
    
    // recursive case:
    template<typename List>
    class ReverseT<List, false>
      : public PushBackT<Reverse<PopFront<List>>, Front<List>>
    {};
    
    // basis case:
    template<typename List>
    class ReverseT<List, true>
    {
      public:
        using Type = List;
    };
```

The basis case of the recursion, this instantiation is identified by an empty typelist. The recursive case splits the list into its first element and the remaining list as the result. For example, if given the typelist Typelist<int, short, double>, Reverse<> separates the first element (short) from the remaining elements (Typelist<int, double>), and recursively reverses the remaining elements, producing Typelist<double, int>, and then appends the first element (short) to that result with PushBack<>, producing Typelist<double, short, int>.

The reverse algorithm makes it possible to implement a PopBack() operation for typelists to remove the last element from a typelist:
