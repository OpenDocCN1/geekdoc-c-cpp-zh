Parameterized types that are considerably more complex than just “T” can be matched to a given argument type. Here are a few examples that are still fairly basic:

Complex type declarations are built from more elementary constructs (pointer, reference, array, and function declarations; pointer-to-member declarations; template-id; and so forth), and the matching process proceeds from the top-level construct and recurses through the composing elements. It is fair to say that most type declaration constructs can be matched in this way, and there are called deduced contexts. However, a few constructs are not deduced contexts. For example:

+   - Qualified type names. For example, a type name like `C<T>::X` will never be used to deduce a template parameter.
+   - Nontype expressions that are not just a nontype parameter. For example, a type name like `C<T+1>` will never be used to deduce `T`. Neither will `f` be deduced by matching against a parameter of type `int`.

I think it is important to stress that although deduction is not always possible because the deduction would, in general, not be unique (or even finite), although this limitation of qualified type names is sometimes easily overlooked. A reduced context does not automatically imply that the program is in error or even that the parameter being deduced cannot participate in type deduction.
