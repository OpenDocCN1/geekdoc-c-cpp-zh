
```cpp
public:
    using Type = IfThenElse<(sizeof(First) >= sizeof(Rest)), First, Rest>;
};

// base case
template<>
class LargestTypeT<Typelist<> >
{
public:
    using Type = char;
};

template<typename List>
using LargestType = typename LargestTypeT<List>::Type;
```

The `LargestType` algorithm will return the first, largest type within the typelist. For example, if given the typelist `Typelist<char, int, long, short>`, this algorithm will return the first type that is the same size as `long`, which is likely to be either `int` or `long`, depending on your platform.

The primary template for `LargestTypeT` doubles as the recursive case for the algorithm. It employs the common functor/trait idiom, which has two steps. In the first step, it computes a partial result based on just the first element, which in this case is the first element of the list, and places it in `First`. Next, it removes the first element to compute the result for the rest of the elements in the list, and places that result in `Rest`. For example, in the first step of recursion for the typelist `Typelist<short, int, long, short>`, it will result in a type that is the result of applying the algorithm to the rest of the list. For instance, in the first step of recursion, the typelist `Typelist<int, long, short>` is created. Finally, the algorithm combines that result with the first type in the list, `First`, as well as the rest of the list. If `First` is the best candidate for the largest type, it returns that winner. The `>=` breaks this tie in favor of the element that comes earlier in the list.

The recursion terminates when the list is empty. By default, we set this as a sentinel type to initialize the algorithm, because every type is as large as `char`.

Note that the base case explicitly mentions the empty typelist `Typelist<>`. This is somewhat unfortunate, because it precludes the use of other forms of typelists, which we will return to in later sections (including Section 24.3 on page 556, Section 24.5 on page 571, and Chapter 25). To address this problem, we introduce an `IsEmpty` metafunction that determines whether the given typelist is empty.

[Click here to view code image](typelist/typelistlargesttype.cpp)

```cpp
template<typename List>
class IsEmpty
{
public:
    static constexpr bool value = false;
};

template<>
class IsEmpty<Typelist<> >
{
public:
    static constexpr bool value = true;
};
```

Using `IsEmpty`, we can implement `LargestType` so that it works equally well for any typelist that implements `Front`, `PopFront`, and `IsEmpty`, as follows:

[Click here to view code image](typelist/typelistisempty.cpp)

```cpp
template<typename List, bool Empty = IsEmpty<List>::value>
class LargestTypeT;

// recursive case:
template<typename List>
class LargestTypeT<List, false>
{
private:
    using Contender = Front<List>;
    using Best = typename LargestTypeT<PopFront<List>>::Type;
public:
    using Type = IfThenElse<(sizeof(Contender) >= sizeof(Best)),
                          Contender, Best>;
};

// base case:
template<typename List>
class LargestTypeT<List, true>
{
public:
    using Type = char;
};

template<typename List>
using LargestType = typename LargestTypeT<List>::Type;
```

The detailed second template parameter to `LargestTypeT`, `Empty`, checks whether the list is empty. First, the recursive case defines this parameter to be `false`, so it remains operating on the full sequence. The base case (which flips the argument to `true`) terminates the recursion and provides the initial result (`char`).

### 24.2.2 Applying to a Typelist

The `PushFront` primitive operation allows us to add a new element to the front of a typelist, producing a new typelist. Suppose that, instead, we wish to add a new element at the end of the list, so we define an operation with names such as `AddEnd`, and also add a reverse operation. For a `Typelist` `List`, this operation requires only a small modification to the `PushFront` implementation from Section 24.1 on page 540 to produce `PushBack`:

[Click here to view code image](typelist/typelistpushback.cpp)

```cpp
template<typename List, typename NewElement>
class PushBackT;

template<typename... Elements, typename NewElement>
class PushBackT<Typelist<Elements...>, NewElement>
{
public:
    using Type = Typelist<Elements..., NewElement>;
};

template<typename List, typename NewElement>
using PushBack = typename PushBackT<List, NewElement>::Type;
```

However, as with the `LargestType` algorithm, we can implement a generalization for `PushBack` that uses only the primitive operations `Front`, `PopFront`, and `PushFront`:

[Click here to view code image](typelist/pushback.hpp)

```cpp
template<typename List, typename NewElement, bool = IsEmpty<List>::value>
class PushBackList;

// recursive case
template<typename List, typename NewElement>
class PushBackList<List, NewElement, false>
{
    using Head = Front<List>;
    using Tail = PopFront<List>;
    using NewTail = typename PushBackList<Tail, NewElement>::Type;

public:
    using Type = PushFront<NewTail, Head>;
};

// base case
template<typename List, typename NewElement>
class PushBackList<List, NewElement, true>
{
public:
    using Type = PushFront<List, NewElement>;
};

// generic push-back operation
template<typename List, typename NewElement>
class PushBackT : public PushBackList<List, NewElement>
{
};

template<typename List, typename NewElement>
using PushBack = typename PushBackT<List, NewElement>::Type;
```

The `PushBackT` template manages the recursion. In the base case, we use `PushFront` to add `NewElement` to the empty list, because `PushFront` is equivalent to pushback on an empty list. The recursive case is far more interesting: It splits the list into its first element (`Head`) and a typelist containing the remaining elements (`Tail`). Then the element is appended to the end of `Tail`, recursively, to produce `NewTail`. When the recursion is over, `NewTail` is pushed onto the front of the list to form the final list.

Let's unwrap the recursion for a simple example!

`PushBack<Typelist<short, int>, long>`

In our outermost step, `Head` is `short` and `Tail` is `Typelist<int>`. We recurse to

`PushBack<Typelist<int>, long>`

where `Head` is `int` and `Tail` is `Typelist<>`.

We recurse again to compute

`PushBack<Typelist<>, long>`

which triggers the base case and returns `PushFront<Typelist<>, long>`, which itself evaluates to `Typelist<long>`. The recursion then unwinds, pushing the previous `Head` on the front of the list:

`PushFront<Typelist<long>, int>`

This produces `Typelist<int, long>`; the recursion unwinds again, pushing the outermost `short` onto this list:

`PushFront<Typelist<int, long>, short>`

This produces the final result:

`Typelist<short, int, long>`

The general `push_back()` implementation works on any kind of typelist. Like previous algorithms developed in this section, it requires a linear number of template instantiations to evaluate. Because, for a typelist of length N, there will be N + 1 instantiations of `PushBack<>` and `PushBack<T, List>`, as well as N instantiations of `Front<>` and `PopFront()`. Counting the number of template instantiations can provide rough estimates of the time it will take to compile a particular algorithm, because template instantiation itself is a costly process for the compiler.

Compile time can be a problem for large template algorithms, so it is often desirable to minimize the number of template instantiations performed by these algorithms. In fact, our first implementation of `PushBack<>` employed a partial specialization on `Typelist<>` to optimize the algorithm, which requires only a constant number of template instantiations, making it far more efficient to use at compile time than the generic version. However, because it is described as a partial specialization of `PushBack<>`, this efficient implementation will automatically be selected when performing `PushBack<>` on a `Typelist<>` instance, leaving the notion of algorithm specialization (as discussed in Section 20.1 on page 351) to template metaprograms. Many of the techniques discussed in this section can be applied to template metaprograms to reduce the number of template instantiations the algorithm performs.

### 24.2.3 Reversing a Typelist

When typelists have some ordering among their elements, it is convenient to be able to reverse the ordering of the elements in the typelist when applying some algorithms. For example, the `Typelist` `Typelist<int, short, double>` type would be reversed to `Typelist<double, short, int>`. This is a linear number of template instantiations. However, this is useful to reverse the order to match a particular protocol: `Typelist<Typelist<int, long, int, short, signed char>>` ordered by increasing size. The reverse algorithm implements this operation:

[Click here to view code image](typelist/typelistreverse.hpp)

```cpp
template<typename List, bool Empty = IsEmpty<List>::value>
class ReverseT;

template<typename List>
using Reverse = typename ReverseT<List>::Type;

// recursive case:
template<typename List>
class ReverseT<List, false>
  : public PushBackT<Reverse<PopFront<List>>, Front<List>>
{};

// base case:
template<typename List>
class ReverseT<List, true>
{
public:
    using Type = List;
};
```

The base case of the recursion is identified by an empty typelist. The recursive case splits the list into its first element and the remaining list as the result. For example, if given the typelist `Typelist<int, short, double>`, `Reverse<>` separates the first element (`int`) from the remaining elements (`Typelist<short, double>`), and recursively reverses the remaining elements, producing `Typelist<double, short>`, and then appends the first element (`int`) to that result with `PushBack<>`, producing `Typelist<double, short, int>`.

The reverse algorithm makes it possible to implement a `PopBack()` operation for typelists to remove the last element from a typelist:

[Click here to view code image](typelist/typelistpopback.hpp)

```cpp
template<typename List>
class PopBackT {
public:
    using Type = Reverse<PopFront<Reverse<List>>>;
};
```
