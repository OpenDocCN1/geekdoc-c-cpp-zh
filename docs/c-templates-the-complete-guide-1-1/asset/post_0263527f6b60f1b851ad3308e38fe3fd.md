
```cpp
class Collection {
public:
    template<typename T>             // an in-class member
    class Node {
        ...
    };

    template<typename T>             // an in-class (and the...
    T* alloc() {                     // member function tem...
        ...
    }

    template<typename T>             // a member variable
    static T zero = 0;

    template<typename T>             // a member alias tem...
    using NodeType = Node<T>;
};
```

Note that in C++17, variables—including static data members—and variable templates can be “inline,” which means that their definition can be repeated across translation units. This is redundant for variable templates, which can always be defined in multiple translation units. Unlike member functions, however, a static data member being defined in its enclosing class does not make it inline: The keyword `inline` must be specified on it.

Finally, the following code demonstrates how member templates that are not alias templates can be defined out-of-class:

```cpp
template<typename T>             // a namespace scope
class List {
public:
    List() = default;              // because a template

    template<typename T>           // another member class
    class Handler                  // without its definition
    ...

    template<typename T>           // a member function
    List (List<T> const&);          // (constructor)

    template<typename T>           // a member variable
    static T zero;
};

template<typename T>               // out-of-class member
template<typename T>               // out-of-class member
class List<T>::Handler {
    ...
};

template<typename T>               // out-of-class member
template<typename T>               // out-of-class member
List<T>::List (List<T> const& b)
{
    ...
}
```

```cpp
template<typename T>        // out-of-class static
template<typename U>
U List<T>::zero = 0;
```

Member templates defined outside their enclosing class may need multiple `template<>` parameterization clauses: one for every enclosing class template and one for the member template itself. The clauses are listed starting from the outermost class template.

Note also that a constructor template (a special kind of member function template) disables the implicit declaration of the default constructor (the default is implicitly declared if no other constructor is declared). Adding a defaulted declaration:

```cpp
List() = default;
```

ensures an instance of `List<T>` is default-constructible with the semantics of an implicitly declared constructor.

## Using Templates

Union templates are possible too (and they are considered a kind of class template):

```cpp
template<typename T>
union AllocChunk {
  T object;
  unsigned char bytes[sizeof(T)];
};
```

## Default Call Arguments

Function templates can have default call arguments, just like ordinary function declarations:

```cpp
template<typename T>
void report_top(Stack<T> const& s, int number = 10);

template<typename T>
void report_top(Stack<T> const& s,
                void fill(Array<T> const&));
```

The latter declaration shows that a default call argument could depend on a template parameter. It also can be defined (as the only way possible before C++11, see Section 5.2 on page 68)

```cpp
template<typename T>
void fill(Array<T> const& = T())  // T() is
                                     // the default value
{
  for (int i = 0; i < ...; ++i) {
    array[i] = T();
  }
}
```

When the `fill()` function is called, the default argument is not instantiated if a second function call argument is supplied. This ensures that no error is issued if the default call argument cannot be instantiated for a particular `T`. For example:

```cpp
class Value {
public:
  explicit Value(int);       // no default constructor
};

void foo(Array<Value> array)
{
  Value error;                // ERROR: default constructor not
                              // available
  fill(array, error);         // OK: default value not used
}
```

## Non-template Members of Class Templates

In addition to the four fundamental kinds of templates described inside a class, you can also have ordinary class members parameterized by being part of a class template. They are occasionally (or erroneously) also referred to as member templates. Although they can be parameterized, such definitions aren't quite class templates. Their parameters are entirely determined by the template of which they are members. For example:

```cpp
template<int T>
class Cupboard
{
  class Shelf;                 // ordinary class in
                                // class template
  void open();                 // ordinary function in
                                // class template
  enum type : int;             // ordinary enumeration
  static double totalWeight;   // ordinary static data
                                // member in class template
};
```

```cpp
template<int T>                 // definition of ordinary class
class Cupboard<T>::Shelf
{
    ...
};
```

```cpp
template<int T>                 // definition of ordinary function
                                  // in class template
void Cupboard<T>::open()
{
    ...
}
```

```cpp
template<int T>                 // definition of ordinary enumeration
                                  // type in class template
enum Cupboard<T>::type : int
{
    Maple, Cherry, Oak
};
```

```cpp
template<int T>                 // definition of ordinary static
                                  // member in class template
double Cupboard<T>::totalWeight = 0.0;
```

Since C++17, the static `totalWeight` member can be initialized inside the class template using `inline`.

```cpp
template<int T>
class Cupboard
{
    ...
    inline static double totalWeight = 0.0;
};
```

Although such parameterized definitions are commonly called templates, the term doesn't quite apply to them. A term that has been occasionally suggested for these entities is temploid. Since C++17, the C++ standard defines the notion of a templated entity, which includes templates themselves and, recursively, any entity defined or created in templated entities, such as a friend function defined inside a class template or the closure type of a lambda expression appearing in a templated entity. Neither temploid nor templated entity is a particularly useful term to use here, but they may be useful terms to communicate more precisely about C++ templates in the future.

### 12.1.1 Virtual Member Functions

Member function templates cannot be declared virtual. This constraint is imposed because the usual implementation of the virtual function call mechanism uses a fixed-size table with one entry per virtual function. However, the number of instantiations of a member function template is not fixed until the entire program has been translated. Hence, supporting virtual member function templates would require a different, or perhaps new kind of mechanism in C++ compilers and linkers.

In contrast, the ordinary members of class templates can be virtual because their number is fixed when a class is instantiated:

```cpp
template<typename T>
class Dynamic
{
public:
    virtual ~Dynamic() {    // OK: one destructor per instance
                             // of Dynamic
    }

    template<typename T2>
    void copy(T2 const&);   // ERROR: unknown number of instances
                             // of copy()
};

Dynamic<int> d;
```

### 12.1.2 Linkage of Templates

Every template must have a name, and that name must be unique within its scope, except that function templates can be overloaded (see Chapter 15). Note especially that, unlike class types, class templates cannot share a name with a different kind of entity:

```cpp
int C;

class C
{
    ...
};                      // OK: class names and nonclass names are in
                             // a different "space"

int X;

template<typename T>
class X                      // ERROR: conflict with variable X
{
    ...
};

template<typename T>
class S                      // ERROR: conflict with struct S
{
    ...
};
```
