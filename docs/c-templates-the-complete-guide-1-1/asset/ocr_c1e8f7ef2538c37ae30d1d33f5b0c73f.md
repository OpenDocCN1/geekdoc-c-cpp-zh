```
    template void f(Count);
    template void f(Count);
```

Note that every instantiation directive is valid. Template arguments can be deduced (see Chapter 15).

Members of class templates can also be explicitly instantiated in this way:

```
    template<typename T>
    class C {
      public:
        void f() {}
    };

    template void C<int>::f();
    template class C;
```

Furthermore, it is possible to explicitly instantiate a member of a class template specialization by explicitly instantiating the class template specialization. Because these explicit instantiation directives ensure that a definition of the named template specialization (or member thereof) is created. The only difference is that explicit instantiation declarations do not lead to automatic instantiation. They are primarily intended to be used to reduce compile times. However, the compiler may also optimize them away, which means that the compiler may choose not to instantiate the template if it is not needed. The resulting object file may not contain the definition. This is one of the main reasons why explicit instantiation declarations are often used in combination with explicit instantiation definitions. (See also Section 14.3.1 on page 1.)

# ### 14.3.1 Manual Instantiation

C++ programmers have observed that automatic template instantiation has a considerable negative impact on build times. This is particularly true with compilers that implement greedy instantiation (see Section 14.1 on page 1). Because the same template specializations may be instantiated and optimized in many different translation units.

A technique to improve build times consists in manually instantiating those template specializations that the program requires in a single location and inhibiting the instantiation in all other translation units. One portable way to ensure this inhibition is to use the technique described in this section. For example, in the translation unit where it is explicitly instantiated.

```
    // translation unit 1
    #include "f.h" // for declaration purposes
    void g() {
      f<int>(); // in this translation
    }
```

```
    // translation unit 2
    #include "f.h" // for declaration purposes
    template void f<int>(); // manual instantiation
    void g() {
      f<int>();
    }
```

In the first translation unit, the compiler cannot instantiate the definition of the function template f, so it will not (and cannot) provide an instantiation of f<int>. The second translation unit provides the definition of f<int> with an explicit instantiation directive; without it, the program would not link.

Manual instantiation has a clear disadvantage: We must carefully keep track of which entities are manually instantiated. For large projects this could be a burden. Also, for example, we have to understand the source code, and we want to be sure to not introduce errors.

However, manual instantiation also has a big advantage because the instantiation can be tuned to the needs of the program. Clearly, the overhead of large headers is avoided, as is the overhead of repeatedly instantiating the same templates with the same arguments in multiple translation units. Finally, the debugger sees the code in a single translation unit, and there is an additional advantage: you can easily set a breakpoint in the instantiated code.

Some of the headers of manual instantiation can be optimized by placing the template definition into a third source file, commonly with the extension .tpp. For our function f, this breaks down into:

```
    // f.h
    #include <iostream>
    template<typename T> void f(); // for declaration purposes

    // f.tpp
    #include "f.h"
    template<typename T> void f() {
      std::cout << "f()" << std::endl;
    }
```
