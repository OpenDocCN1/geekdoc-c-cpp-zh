
```cpp
using AddValueReference = typename AddValueReference...
```

The rules of reference collapsing (Section 6.15 on page 277) apply here. For example, calling `AddValueReference<int&>(...)` produces type `int&` (there is therefore no need to implement them manually via partial specialization).

If we leave `AddLValueReference` and `AddRValueReference` as they are and do not introduce specializations of them, then the convenience aliases can actually be simplified to

```cpp
template<typename T>
using AddLValueReference = T&;

template<typename T>
using AddRValueReference = T&&;
```

which can be instantiated without instantiating a class template (and is therefore a lighter-weight solution). However, this is risky, as it may not always work as expected. For example, as written above, we cannot use specializations to handle special cases.

```cpp
template<>
struct AddLValueReference<void> {
    using Type = void;
};

template<>
struct AddLValueReference<void const> {
    using Type = void const;
};

template<>
struct AddLValueReference<void volatile> {
    using Type = void volatile;
};

template<>
struct AddLValueReference<void const volatile> {
    using Type = void const volatile;
};
```

and similarly for `AddRValueReference`.

With that in place, the convenience alias template must be formulated in terms of those templates to ensure that the specializations are picked up (also since alias templates cannot be specialized).

The C++ standard library provides corresponding type traits `std::add_lvalue_reference<T>` and `std::add_rvalue_reference<T>`, which are described in Section 15.4.2 on page 279. The standard library also provides the specializations for `void` types.

## Removing Qualifiers

Transformation traits can break down into adding and removing any kind of compound type, not just references. For example, we can remove a `const` qualifier if present:

traits/RemoveConst.hpp

```cpp
template<typename T>
struct RemoveConst {
    using Type = T;
};

template<typename T>
struct RemoveConst<T const> {
    using Type = T;
};
```

Moreover, transformation traits can be composed, such as creating a `RemoveCV` trait that removes both `const` and `volatile`:

```cpp
#include "RemoveConst.hpp"
#include "RemoveVolatile.hpp"

template<typename T>
struct RemoveCVT : RemoveConst<typename RemoveVolatile<T>::Type>
{
};

template<typename T>
using RemoveCV = typename RemoveCVT<T>::Type;
```

There are two things to note with the definition of `RemoveCVT`. First, it is making use of both `RemoveConst<T>` and the related `RemoveVolatile<T>`, the first removing the `volatile` (if present) and then passing the resulting type to `RemoveConst<T>`. Second, it is using metafunction forwarding in order to let `T` become a member from `RemoveConst<T>` rather than declaring its own `T` member. This means that it is essential to include the `<type_traits>` header. Here, metafunction forwarding is used simply to reduce the amount of typing in the definition of `RemoveCVT`. However, metafunction forwarding is also useful when the metafunction is not defined for all inputs, a technique that will be discussed further in Section 19.4 on page 416.

The convenience alias template `RemoveCV` could be simplified to

```cpp
template<typename T>
using RemoveCV = RemoveConst<RemoveVolatile<T>>;
```

Again, this works only if `RemoveCVT<T>` is specialized. While in the case of `AddCV` a union of `AddConst` and `AddVolatile` is used, the same kind of metafunction forwarding is not needed here.

The C++ standard library also provides corresponding type traits: `std::remove_const<T>::type`, `std::remove_cv<T>::type`, and `std::remove_reference<T>::type`, which are described in Section 4 on page 48.

## Decay

To round out our discussion of transformation traits, we develop a trait that mimics type conversions when passing arguments to parameters by value. Derived from C++, this means that the arguments decay array types into pointers and function types into pointer-to-function types (see Section 7.4 on page 115 and Section 13.1.1 on page 159) and delete any top-level `const`, `volatile`, or reference qualifiers (because top-level type qualifiers on parameter types are ignored when resolving a function call).

The effect of this pass-by-value can be seen in the following program, which prints the actual parameter type produced after the compiler decays the specified type:

traits/is_paramtype.cpp

```cpp
#include <iostream>
#include <typeinfo>
#include <type_traits>

template<typename T>
void f(T)
{
}

template<typename A>
void printParameterType(void (*f)(A))
{
    std::cout << "Parameter type: " << typeid(A).name() << std::endl;
    std::cout << "is const: " << std::is_const<A>::value << std::endl;
    std::cout << "is volatile: " << std::is_volatile<A>::value << std::endl;
    std::cout << "is pointer: " << std::is_pointer<A>::value << std::endl;
}

int main()
{
    printParameterType<int(int)>();
    printParameterType<int const>();
    printParameterType<int[5]>();
}
```

In the output of the program, the `int` parameter has been left unchanged, but the `const int&`, `int&`, and `int` parameters have changed to `int`, `int`, and `int&`, respectively.

We can implement a trait that produces the same type conversion of passing by value. To match the C++ standard library trait `std::decay`, we name it `decay`. Its implementation combines several of the techniques described above: First, we define the same primary, nonfunction case, which simply discards cv-qualifiers.

```cpp
template<typename T>
struct decay {
    using Type = typename RemoveCV<T>::Type;
};
```

Next, we handle the array-to-pointer decay, which requires us to recognize any array types (with or without a bound) using partial specialization:

```cpp
template<typename T>
struct decay<T[]> {
    using Type = T*;
};

template<typename T, std::size_t N>
struct decay<T[N]> {
    using Type = T*;
};
```

Finally, we handle the function-to-pointer decay, which has to match any function type, regardless of the return type or the number of parameter types. For this, we employ variadic templates:

```cpp
template<typename R, typename... Args>
struct decay<R(Args...)> {
    using Type = R(*)(Args...);
};

template<typename R, typename... Args>
struct decay<R(Args..., ...)> {
    using Type = R(*)(Args..., ...);
};
```

Note that the second partial specialization matches any function type that uses C-style varargs. Together, the primary `decay` template and its four partial specializations implement parameter type decay, as illustrated by this example program:

```cpp
#include <iostream>
#include <typeinfo>
#include <type_traits>
#include "decay.h"

template<typename T>
void printDecayType()
{
    using A = typename decay<T>::Type;

    std::cout << "Parameter type: " << typeid(A).name()
              << std::endl;
    std::cout << "is const: " << std::is_const<A>::value
              << std::endl;
    std::cout << "is volatile: " << std::is_volatile<A>::value
              << std::endl;
    std::cout << "is pointer: " << std::is_pointer<A>::value
              << std::endl;
}

int main()
{
    printDecayType<int>();
    printDecayType<int const>();
    printDecayType<int[2]>();
    printDecayType<int(int)>();
}
```

As usual, we provide a convenience alias template:

```cpp
template <typename T>
using DecayT = typename decay<T>::Type;
```

As written, the C++ standard library also provides a corresponding type trait `std::decay<T>::type`, which is described in Section 1.4 on page 73.

### 9.9.3 Predicate Traits

So far we have studied and developed type functions of a single type: Given one type, provide other related types or constants. In general, however, we can develop type functions that depend on multiple arguments. This also leads to a special form of type traits, type predicates (type functions yielding a Boolean value).

### IsSameT

The `IsSameT` type trait tells whether two types are equal:

traits/isSameT.hpp

```cpp
template<typename T1, typename T2>
struct IsSameT {
    static constexpr bool value = false;
};

template<typename T>
struct IsSameT<T, T> {
    static constexpr bool value = true;
};
```

Here the primary template defines that, in general, two different types passed as template arguments differ. So the `value` member is false. However, using partial specialization, when we have the special case that the two passed types are the same, `value` is true.

For example, the following expression checks whether a passed template parameter is an integer:

```cpp
if (IsSameT<int, T>::value)
```

For traits that produce a constant value, we cannot provide an alias template, but we can provide a constexpr variable template that fulfills the same role:

```cpp
template<typename T1, typename T2>
constexpr bool isSameT = IsSameT<T1, T2>::value;
```

The C++ standard library provides a corresponding type trait `std::is_same<>`, which is described in Section 9.3.3 on page 726.

### true_type and false_type

We can significantly improve the definition of `IsSameT` by providing different types for the possible two outcomes, `true` and `false`. In fact, if we declare a class template `BoolConstant` with the two possible instantiations `true_type` and `false_type`:

traits/boolconstant.hpp

```cpp
template<bool val>
struct BoolConstant {
    using Type = BoolConstant<val>;
    static constexpr bool value = val;
};
```
