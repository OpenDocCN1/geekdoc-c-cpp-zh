While this approach has solved the initialization ordering problem, it has introduced a new (worse) problem. We can no longer extract elements from a tuple that has two elements of the same type, such as TupleList<int, int>, because the derived-to-base conversion from a tuple to TupleList of that type is ambiguous.

To break the ambiguity, we need to ensure that each TupleList base class is unique within a given Tuple. One approach is to encode the "depth" of this Tuple as a template argument, so that the depth of the tuple in the type list will be aligned with its depth in the tuple, starting at the root (the root is at depth 1 and its children are at depth 2 and so on).

template<typename... Types>
class TupleList {
    T value;
public:
    TupleList() = default;

    template<typename D>
    TupleList(D& other) : value(std::forward<D>(other)) {}

    T& get() { return value; }
    T const& get() const { return value; }
};
~~~

With this solution, we can produce a Tuple that applies the EBO while maintaining initialization order and support for multiple elements of the same type.
