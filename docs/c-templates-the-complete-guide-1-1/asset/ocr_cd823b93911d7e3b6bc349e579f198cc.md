```
```cpp
void f (X&& val)
{
    g(std::move(val));   // val is non-const lvalue => ...
}

int main()
{
    X x;                 // create variable
    X const cx;          // create constant

    f(x);                // f() for nonconstant object calls ...
    f(cx);               // f() for constant object calls ...
    f(X());              // f() for temporary value (rvalue)
    g(std::move(x));     // f() for movable rvalue calls ...
}
```
```

Here, we see three different implementations of f() forwarding its argument to g():

Click here to view code image:

```
```cpp
void f (X& val)
{
    g(val);              // val is non-const lvalue => calls g(X&)
}

void f (X const& val)
{
    g(val);              // val is const lvalue => calls g(X const&)
}

void f (X&& val)
{
    g(std::move(val));   // val is non-const lvalue => needs std::move() to call g(X&&)
}
```
```

Note that the code for movable objects (via an rvalue reference) differs from the other code: It needs a std::move() because according to language rules, every expression is not passed through. Although val in the third f() is declared as an rvalue reference its value category when used as an expression is lvalue. So to properly forward the argument, we use std::move(val). Without the move, g(X) is called for nonconstant values instead of g(X&&) would be called.

If we want to combine all three cases in generic code, we have a problem:

Click here to view code image:

```
```cpp
template<typename T>
void f (T&& val) {
    g(val);
}
```
```

works for the first two cases, but not for the (third) case where movable objects are passed.

C++11 for this reason introduces special rules for perfect forwarding parameters. The idiomatic code pattern to achieve this is as follows:

Click here to view code image:

```
```cpp
template<typename T>
void f (T&& val) {
    g(std::forward<T>(val));   // perfect forward val to g()
}
```
```

Note that std::move() has no template parameter and "triggers" move semantics for the passed argument, while std::forward<T>() "forwards" potential move semantic depending on a passed template argument.

Don't assume that T is for a template parameter T because as X is for a specific type T. Different rules apply! However, syntactically they look identical:

+   - `X&&` for a specific type X declares a parameter to be an rvalue reference. It can only be bound to a movable object (a prvalue, such as a temporary object, and an xvalue, such as an object passed with `std::move()`); see also the note below. It is always mutable and you can always call "steal its value."
+   - `T&&` for a template parameter T declares a forwarding reference (also called universal reference). It can be bound to a mutable, immutable (i.e., const), or movable object. Inside the function definition, the parameter may be mutable, immutable, or refer to a value passed as an rvalue, depending on the type of T.

Note that T must really be the name of a template parameter. Depending on a template parameter is not sufficient. For a parameter T, a declaration such as `typename T::...` is not an rvalue reference.
