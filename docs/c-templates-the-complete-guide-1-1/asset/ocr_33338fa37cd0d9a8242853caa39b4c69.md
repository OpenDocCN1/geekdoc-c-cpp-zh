# **initializer list**

A comma-separated list of expressions enclosed in braces used to initialize variables and members. For instance, `{1, 2, 3}` is an initializer list. Such lists can be used to initialize variables and members. Initializer lists may appear directly or in an indirect form, e.g. `initializer_list`, list object.

# **injected-class name**

The name of a class as visible in its own definition. The class template's name is the template's name followed by the angle brackets (if any) of the template's argument list. (Injected-class name is not followed by a template argument list.)

# **instance**

The term instance has two meanings in C++ programming. The meaning most closely associated with the term in object orientation is the notion of a class instance, also called an object, or an instance of a class. For example, `C x;` is an instance of `C`. The other meaning, more closely associated with generic programming, is the notion of a class or function instantiated by a template. For example, `C<int>` is an instance of the class template `C`. In the latter meaning, we also say that a template is instantiated by substituting a template's parameters by a set of template arguments. In this sense, an instance is also called a specialization, although the latter term is often meant for explicit specialization.

# **instantiation**

The replacement of the parameters of a template by a template argument to create a concrete entity, function, class, variable, or alias. Entity created from a template by replacing its parameters by a set of template arguments. The template instantiation is sometimes used as a synonym for a specialization. The alternative sense of creating an instance (object) of a class is not used in this book (see instance).

# **ISO**

Worldwide organization for International Organization for Standardization. An ISO subcommittee, WG21, is a working group that develops C++.

# **iterator**

An object that knows how to traverse a sequence of elements. Often, these elements belong to a collection (see collection).

# **linkable entity**

Any of the following: a function or function template, a global variable or a static data member, including any such things generated from a template, as visible to the linker.

# **linker**

A program or operating system service that links together compiled translation units and resolves references to linkable entities across those translation units.

# **lvalue**

A category of expressions that produces a location for a stored value that is not associated with a temporary (e.g., variables) or that is associated with a temporary (e.g., literals).

# **member class template**

A construct that represents a family of member classes. It is a class template declared inside another class or class template definition. It is a kind of member template. (Unlike a member class of a class template.)

# **member function template**

A construct that represents a family of member functions. It has two or more sets of template parameters (unlike a member function of a class template). It is very similar to a function template, but when all the template parameters are substituted, the result is a member function (instead of an ordinary function). Member function templates cannot be virtual.

# **member template**

A member class template, member function template, or static data member template.

# **Modern C++**

The phrase used in this book to refer to the language as standardized in C++11 and later (i.e., C++11, C++14, and C++17).

# **nondependent name**

A name that is not dependent on a template parameter. See dependent name and two-phase lookup.

# **ODR**

An acronym for one-definition rule. This term places some restrictions on the definitions that appear in a C++ program. See Section 10.4 on page 151 and Appendix A and Appendix D.

# **one-definition rule**

See ODR.

# **overload resolution**

The process that selects which function to call when several candidates are viable.
