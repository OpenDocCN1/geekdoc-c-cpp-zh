## D.4 TYPE CONSTRUCTION

The traits listed in Table D.6 allow us to construct types from other types.

| Trait | Effect |
|---|---|
| `remove_const<T>` | Corresponding type without `const` |
| `remove_volatile<T>` | Corresponding type without `volatile` |
| `remove_cv<T>` | Corresponding type without `const` and `volatile` |
| `add_const<T>` | Corresponding `const` type |
| `add_volatile<T>` | Corresponding `volatile` type |
| `add_cv<T>` | Corresponding `const volatile` type |
| `make_signed<T>` | Corresponding signed nonreference type |
| `make_unsigned<T>` | Corresponding unsigned nonreference type |
| `remove_reference<T>` | Corresponding nonreference type |
| `add_lvalue_reference<T>` | Corresponding lvalue reference type (rvalues become lvalues) |
| `add_rvalue_reference<T>` | Corresponding rvalue reference type (rvalues remain rvalues) |
| `remove_pointer<T>` | Referred type for pointers (same type otherwise) |
| `add_pointer<T>` | Type of pointer to corresponding nonreference type |
| `remove_extent<T>` | Element type for arrays (same type otherwise) |
| `remove_all_extents<T>` | Element type for multidimensional arrays (same type otherwise) |
| `decay<T>` | Transfers to corresponding “by-value” type |

Table D.6. Traits for Type Construction

`std::remove_const<T>::type`, `std::remove_volatile<T>::type`, and `std::remove_cv<T>::type` yield the type T without const and/or volatile at the top level.

Note that a const pointer is a const-qualified type, whereas a non-const pointer or reference to a const type is not const-qualified. For example:

```cpp
std::remove_const_t<const int>        // yields int
std::remove_const_t<const int*>       // yields const int*
std::remove_const_t<int const&>       // yields int const&
```

Instead, we may prefer to use `std::decay<>`, which, however, also removes array and function types to corresponding pointer types (see Section 5.4 on page 115).

```cpp
std::decay_t<const T>            // yields int
std::decay_t<const T&>           // yields int
```

- See Section 9.3.2 on page 696 for implementation details.

`std::add_const_t<T>`, `std::add_volatile_t<T>`, and `std::add_cv_t<T>` add the corresponding const/volatile qualifiers at the top level. Applying one of these traits to a reference type or a function type has no effect. For example:

```cpp
std::add_const_t<int>       // yields int const
std::add_const_t<volatile int> // yields int const volatile
std::add_const_t<int const>   // yields int const
std::add_const_t<int&>        // yields int&
std::add_const_t<int&&>       // yields int&&
std::add_const_t<int*>        // yields int* const
```

`std::make_signed_t<T>` and `std::make_unsigned_t<T>` yield the corresponding signed/unsigned type of T. This requires that T is an enumeration type or a (cv-qualified) integral type other than bool. All other types lead to undefined behavior (see Section 9.3 on page 696 for a discussion about how to avoid such undefined behavior).

```cpp
std::make_signed_t<char>        // yields signed char
std::make_unsigned_t<char>      // yields unsigned char
std::make_unsigned_t<char const> // yields unsigned char const
```

`std::remove_reference_t<T>` yields the type the reference type T refers to (or T itself if it is not a reference type). For example:

```cpp
std::remove_reference_t<int>         // yields int
std::remove_reference_t<int&>        // yields int
std::remove_reference_t<int&&>       // yields int
std::remove_reference_t<int const&>  // yields int const
std::remove_reference_t<int const&&> // yields int const
```

Note that a reference type itself is not const-qualified. For this reason, the member `type` of `remove_const_t<int const&>` is `int const&`.

```cpp
std::remove_const_t<std::remove_reference_t<int const&>> // yields int
std::remove_reference_t<std::remove_const_t<int const&>> // yields int const
```
