However, if a function has a more specific parameter as follows

Click here to view code image

```
```cpp
template<typename T>
void deduce(const initializer_list<T>&);

deduce(2, 3, 4); // OK, T deduced as int
deduce(2); // Error
```
```

Here deduction succeeds, copy-initializing {1,2,3,4} to the initializer_list variable with an initializer list is therefore defined in terms of the more specific parameter.

Click here to view code image

```
```cpp
auto primes = { 2, 3, 5, 7 }; // primes is initializer_list<int>
deduce(primes); // deduced as int
```
```

Before C++17, the corresponding direct-initialization of auto variable (e.g., when the = token was not used) only worked, but this was changed in C++17 to better match the behavior expected by most programmers.

Click here to view code image

```
```cpp
auto i = { 0, 6, 15 }; // ERROR: deduces to int
auto j = { 0, 6, 15 }; // OK, j has type std::initializer_list<int>
auto k = { 0, 6, 15 }; // OK, k has type std::initializer_list<int>
```
```

Prior to C++17, both initialization were valid, initializing both i and j as std::initializer_list<int>.

Interestingly, returning a braced initializer list for a function with a deduced placeholder type is invalid.

Click here to view code image

```
```cpp
auto list() {
    return { 1, 2, 3 }; // ERROR
}
```
```

This is because an initializer list in a function scope is an object that points into an underlying array object (the element values passed to the list) that exists when the function returns. Allowing the construct would thus encourage what is in effect a dangling reference.

Another special situation occurs when multiple variable declarations share the same auto, as in the following:

Click here to view code image

```
```cpp
auto first = container.begin(), last = container.end();
```
```

In such cases, deduction is performed independently for each declaration. In other words, there is no imposed template parameter T for first and another imposed template parameter T2 for last. Only if both deductions succeed, and the deductions for T and T2 are the same type, are the declarations well-formed. This can produce some interesting errors:

Click here to view code image

```
```cpp
char c;
auto *p = &c, d = 0; // OK
auto e = &c, f = 0; // ERROR: deduction mismatch char vs int
```
```

Here, two pairs of variables are declared with a shared auto specifier. The deduction of p and d deduces the same type char, so this is valid. For e and f, however, deduction of e yields char* while deduction for f yields int, so the combination is an error.

A somewhat parallel special situation can occur with placeholder for deduced return types. Consider the following example:

Click here to view code image

```
```cpp
auto f(bool b) {
    if (b) {
        return 42.0; // deduces return type double
    } else {
        return 0; // ERROR: deduction conflict
    }
}
```
```

In this case, each return statement is deduced independently, but if different types are deduced, the program is invalid. If the returned expression calls the function recursively, deduction cannot occur and the program is invalid unless a prior deduction has determined the return type. That means that the following code is invalid:

```
```cpp
auto f(int n) {
    if (n > 1) {
        return n * f(n-1); // ERROR: type of f(n-1) unknown
    } else {
        return 1;
    }
}
```
