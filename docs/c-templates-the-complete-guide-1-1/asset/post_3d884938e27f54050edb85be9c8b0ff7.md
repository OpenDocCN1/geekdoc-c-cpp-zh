
```cpp
template<typename T>
struct IsSame<T, T> : TrueType
{
};
```

Now, the resulting type of `IsSame<T, T>` is implicitly convertible to its base class `TrueType`, which not only provides the corresponding `value` member but also allows us to dispatch to a different function implementations or partial class template specializations at compile time. For example:

**Click here to view code image**

`traits/2.3/isame.cpp`

```cpp
#include <iostream>
#include <ostream>

template<typename T>
void fooImpl(T, TrueType)
{
    std::cout << "fooImpl(true) for int called\n";
}

template<typename T>
void fooImpl(T, FalseType)
{
    std::cout << "fooImpl(false) for other type called\n";
}

template<typename T>
void foo(T t)
{
    fooImpl(t, IsSame<T,int>{});  // choose impl, depending on type
}

int main()
{
    foo(42);  // calls fooImpl(42, TrueType)
    foo(7.0); // calls fooImpl(7.0, FalseType)
}
```

This technique is called tag dispatching and is introduced in Section 20.2.3 on page 467.

Note that our `IsSame` implementation includes a `Type` member, which allows us to reintroduce an alias template for `IsSame<T>`.

**Click here to view code image**

```cpp
template<typename T>
using IsSameT = typename IsSame<T>::Type;
```

That alias template can coexist with the variable template `IsSame`.

In general, traits yielding Boolean values should support tag dispatching by deriving from types such as `TrueType` and `FalseType`. However, to be as generic as possible, there should be only one type representing `true` and one type representing `false` in Boolean traits of any kind (and should therefore be defining its own types for Boolean constants).

Fortunately, the C++ standard library provides corresponding types in `<type_traits>` since C++11: `std::true_type` and `std::false_type`. In C++11 and C++14, they are defined as follows:

```cpp
namespace std {
    using true_type = integral_constant<bool, true>;
    using false_type = integral_constant<bool, false>;
}
```

the context of metaprogramming. Metaprogramming will be covered in detail in Chapter 23. (The convenience class templates are particularly helpful with multilevel nesting like this. Without them, we'd have to add a type name and a `::Type` type within every level.)

At this point, the array addition operator properly computes the result type when adding two arrays of possibly different element types. However, our formulation of `PlusResult<T>` places an undesirable restriction on the element types `T1` and `T2`: Because the expression `T1() + T2()` attempts to value-initialize values of type `T1` and `T2`, both of these types must have an accessible, non-deleted, default constructor (or be non-class types). The `Array` class default constructor uses value initialization of its element type, so this is an additional, unnecessary restriction.

## decltype

Fortunately, it is fairly easy to produce values for the `T` expression without requiring a constructor, by using a function that produces values of a given type `T`. For this, the C++ standard provides `std::declval<T>`, as introduced in Section 11.2.3 on page 965. It is defined in `<utility>` simply as follows:

**Click here to view code image**

```cpp
template<typename T>
add_rvalue_reference_t<T> declval() noexcept;
```

The expression `declval<T>()` produces a value of type `T` without requiring a default constructor (or any other operation).

This function template is intentionally left undefined because it's only meant to be used within the `decltype`, `sizeof`, or some other context where evaluation is never required. It has two other interesting attributes:

- For reference types, the return type is always an rvalue reference to the type, which allows `declval<T>` to work even with types that could not normally be returned from a function, such as abstract class types (classes with pure virtual functions) or array types. The transformation from `T` to `T&&` otherwise has no practical effect on the behavior of `declval<T>()` when used as an expression: Both are rvalues (if `T` is an object type), while lvalue reference types are unchanged due to reference collapsing (described in Section 19.7.2 on page 483).
- The `noexcept` exception specification documents that `declval` itself does not cause an expression to be considered to throw exceptions. It becomes useful when `declval<T>` is used in the context of `decltype` or other expressions (see Section 19.7.2 on page 483).

With `declval`, we can eliminate the value-initialization requirement for `PlusResult<T>`:

**Click here to view code image**

```cpp
template<typename T1, typename T2>
struct PlusResult {
  using Type = decltype(std::declval<T1>() + std::declval<T2>());
};

template<typename T1, typename T2>
using PlusResultT = typename PlusResult<T1, T2>::Type;
```

Result type traits offer a way to determine the precise return type of a particular operation and are often useful when describing the result types of function templates.

## 19.4 SFINAE-BASED TRAITS

The SFINAE principle (substitution failure is not an error; see Section 8.4 on page 132 and Section 10.2 on page 250) permits you to control errors during the formation of invalid types and expressions during template argument deduction (which would cause the program to be ill-formed) in simple function failures, allowing overload resolution to select a different entity. While originally intended to avoid spurious failures with function template overloading, SFINAE also enables remarkable compile-time techniques that can determine if a particular type or expression is valid. This allows us to write traits that determine, for example, whether a type has a specific member, supports a specific operation, or is a class. The two main approaches of SFINAE-based traits are SFINAE out function overloads and SFINAE out partial specializations.

### 19.4.1 SFINAE Out Function Overloads

Our first foray into SFINAE-based traits illustrates the basic technology using SFINAE with function overloading to find out whether a type is default constructible, so that you can create objects without any value for initialization. That is, for a given type `T`, an expression such as `T()` has to be valid.

A basic implementation uses the following:

```cpp
#include "Lesson.hpp"

template<typename T>
struct IsDefaultConstructible {
 private:
   // test() trying substitute call of a default constructor
   template<typename U, typename = decltype(U())>
   static char test(void*);

   // test() fallback
   template<typename>
   static long test(...);

 public:
   static constexpr bool value
     = sizeof(test<T>(nullptr)) == sizeof(char);
};
```

The usual approach to implement a SFINAE-based trait with function overloading is to declare two overloaded function templates named `test()` with different return types:

**Click here to view code image**

```cpp
template<class T> static char test(T*);
template<class> static long test(...);
```

The first overload is designed to match only if the requested check succeeds (we will discuss below how that is achieved). The second overload is the fallback. It always matches the call, but because it matches with ellipses (a variadic parameter), any other match would be preferred (see Section C.2 on page 86).

Our return value “value” depends on which overloaded `test()` member is selected:

**Click here to view code image**

```cpp
static constexpr bool value
  = IsSame<decltype(test<T>(nullptr)), char>::value;
```

If the first `test()` member—when return type is `char`—is selected, `value` will be initialized to `true` thanks to `sizeof(char) == sizeof(char)`. Otherwise, it will be initialized to `false` because `sizeof(long) != sizeof(char)`.

Now, we have to deal with the specific properties we want to test. The goal is to make the first `test()` overload valid if and only if the condition we want to check applies. In this case, we want to find out whether we can default construct an object of the passed type `T`. To achieve this, we pass `T` and a `void*` as the first declaration of `test()` argument (namely, template argument initialization with an argument that is valid if and only if the conversion is valid). In this case, we use the expression that can only be valid if an implicit or explicit default constructor exists: `U()`. The expression is surrounded by `decltype` to make this a valid expression to initialize a type parameter.

The second template parameter cannot be deduced, so no corresponding argument is passed. And we will not provide an explicit template argument for it. Therefore, it will be substituted, and if the substitution fails, according to SFINAE, that declaration of `test()` will be discarded so that only the fallback function will match.

Thus, we can use the trait as follows:

**Click here to view code image**

```cpp
IsDefaultConstructible<int>::value  // yields true

struct S {
  S() = delete;
};

IsDefaultConstructible<S>::value    // yields false
```

Note that we can use the template parameter `T` in the first `test()` directly:
