unknown bounds, and pointers. Each case is different and can occur when using arrays.

[Click here to view code image](#)

```
~~~cpp
template<typename T1, typename T2, typename T3>
void demo1(T1 a1, T2 a2, T3 a3) // pointers by using
{
    int a1[42];              // reference to array
    int a2[10];              // reference to array
    T1 a1;                   // passing by value
    T2 a2, T3& a3;           // passing by reference

    MyClass::demo1(a1);      // use MyClass
    MyClass::demo1(a2);      // use MyClass
    MyClass::demo1(a3);      // use MyClass
    MyClass::demo1(a1);      // use MyClass
    MyClass::demo1(a2);      // use MyClass
    MyClass::demo1(a3);      // use MyClass
}

int main()
{
    int a[42];
    MyClass::demo1(a);       // use MyClass

    extern int a[];
    MyClass::demo1(a);       // use MyClass

    double a, b, c, d, e, f;
    int a[] = { 0, 8, 15 };  // define forward
}
~~~
```

Note that a function parameter declared as an array (with or without length) by language rules really has a pointer type. Note also that templates for arrays of unknown bounds can be used for an incomplete type such as

```
~~~cpp
extern int a[];
~~~
```

And when this is passed by reference, it becomes a `int (&)[]`, which can also be used as a template parameter.

See Section 5.3.2 on page 60 for another example using the different array type in question.

# ## 5.5 MEMBER TEMPLATES

Class members can also be templates. This is possible for both nested classes and member functions. The application and advantage of this ability can be demonstrated with the `Stack<>` class template. Normally, you would not use a stack of stacks. However, when you want to use a stack whose element type is itself a stack, you need a stack with a member that is an element of any other type, even if there is an implicit type conversion for the element type defined:

[Click here to view code image](#)

```
~~~cpp
Stack<int> intStack;    // stack for ints
Stack<Stack<int> > intStackStack; // stack for stack for ints

intStack = intStack2;   // OK: stacks have same type
Stack<int> intStack;    // stack of ints
Stack<Stack<int> > intStackStack; // stack of stacks
intStack = intStack2;   // ERROR: stacks have different types
Stack<Stack<int> > intStackStack; // ERROR: stacks have different types
~~~
```

The default assignment operator requires that both sides of the assignment operator have the same type, which is not the case if stacks have different element types.
