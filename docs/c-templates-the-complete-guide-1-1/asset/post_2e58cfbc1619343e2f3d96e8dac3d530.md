
Here, template argument deduction from the first argument deduces T to int, while deduction from the second argument deduces T to double. Because both parameters are passed by reference, the deduction conflicts and the call is not possible. The same error can arise, however, if you use a parameter that is a common base class:

```cpp
std::max(static_cast<Base*>(&d1),&d2);
```

would have succeeded.

Perhaps you are wondering if that is the error message you would get. On the first line, the compiler detects the error because both parameters have different types deduced from a common base-class. But if you use a common base class as a common base class, the deduction does succeed. See Section 1.2 on page 7 for a discussion of this issue and possible solutions.

### 15.8.2 CLASS TEMPLATE ARGUMENTS

Prior to C++17, template argument deduction applied exclusively to function and member function templates. In particular, the arguments for a class template were not deduced from the arguments to a call of one of its constructors. For example:

```cpp
template<typename T>
class C {
public:
  C(T b) : a(b) {
  }

private:
  T a;
};

C c(42); // ERROR: Before C++17, the class template parameter T was not deduced from
         //            the constructor call argument
```

This limitation is lifted in C++17—see Section 15.10 on page 341.

### 15.8.3 DEFAULT CALL ARGUMENTS

Default function call arguments can be specified in function templates just as they are in ordinary functions:

```cpp
template<typename T>
void f(T x = T{}, T y = T{}) {
  T* p = &x;
  ...
}
```

In fact, as this example shows, the default function call argument can depend on a template parameter. Such a dependent default argument is prescribed—a principle that makes the following example valid:

```cpp
class B {
public:
  B(int, int);
};

template<typename T>
class D : public B {
public:
  using B::B;
};

D d(1, 2); // OK
```

Without the using declaration, initializing d(1, 2) would be an error because B has no constructor B(int, int).

Even when a default call argument is not dependent, it cannot be used to deduce template arguments. This means that the following is invalid C++:

```cpp
template<typename T>
void f(T = 42) {
}

f(); // ERROR: no T
```

### 15.8.4 EXCEPTION SPECIFICATIONS

Like default call arguments, exception specifications are only instantiated when they are used. The reason is that they can be part of a template's signature. For example:

```cpp
template<typename T>
void f(T) noexcept(noexcept(T::nonexistent())) {}   // #1

template<typename T>
void f(T, ...) noexcept {}                          // #2
```

```cpp
void test(int i)
{
    f(i);    // error: chooses #1, but the expression
             // T::nonexistent() is ill-formed
}
```

The noexcept specification in the function marked as #1 tries to call a nonexistent function. Normally, such an expression would trigger a template argument deduction failure (SFINAE), allowing the call f(i) to proceed by selecting the function marked #2 as the only choice. However, because an ellipsis parameter is the worst kind of match from the point of overload resolution (see Appendix C), and because exception specifications do not participate in template argument deduction, overload resolution selects #1 and the program becomes ill-formed when the noexcept specification is later instantiated.

The same rules apply to exception specifications that list the potential exception types:

```cpp
template<typename T>
void f(T, int) noexcept(T::nonexistent);    // #1

template<typename T>
void f(T, ...) noexcept;                    // #2
```

```cpp
void test(int i)
{
    f(i);    // error: chooses #1, but the type
             // T::nonexistent is ill-formed
}
```

However, these “dynamic” exception specifications have been deprecated since C++11 and were removed in C++17.

## 15.9 EXPLICIT FUNCTION TEMPLATE ARGUMENTS

When a function template argument cannot be deduced, it may be possible to explicitly specify it by allowing the function template name. For example:

```cpp
template<typename T> T default_value()
{
    return T{};
}

int main()
{
    return default_value<int>();
}
```

This may be done also for template parameters that are deducible:

```cpp
template<typename T> void compute(T p)
{
    // ...
}

int main()
{
    compute<double>(2);
}
```

Once a template argument is explicitly specified, its corresponding parameter is no longer subject to deduction. That, in turn, allows conversion to take place on the function call parameter that would not be possible in a deduced call. In the example above, the argument 2 in the call compute<double>(2) will be implicitly converted to double.

It is possible to explicitly specify some template arguments while having others be deduced. However, the explicitly specified ones are always matched left-to-right with the template parameters themselves. Therefore, parameters that cannot be deduced (but for that are likely to be specified explicitly) should be specified first. For example:

```cpp
template<typename T, typename U>
void convert(T p)
{
    // ...
}

int main()
{
    auto z = convert<double>(42);    // the type of parameter
                                     // p is deduced, while
                                     // the return type is
                                     // explicitly specified
}
```

It is occasionally useful to specify an empty template argument list to ensure the selected function is a template instance while still using deduction to determine the template arguments:

```cpp
template<typename T> T f(T);    // #1
int f(int);                      // #2

int main()
{
    f<>(42);
}
```

Here `f<>` selects the nontemplate function because overload resolution prefers an ordinary function over a function template if all other things are equal. However, for `f<>` the presence of a template argument list rules out the nontemplate function (even though no actual template arguments are specified).

In the context of friend function declarations, the presence of an explicit template argument list has an interesting effect. Consider the following example:

```cpp
void f();
template<typename T> void f();

namespace N {
  class C {
    friend int f();      // OK
    friend int f<>();    // ERROR: return type conflict
  };
}
```

When a plain identifier is used to name a friend function, that function is only looked up within the nearest enclosing scope, and if it is not found there, a new entity is declared in that scope (but it remains "invisible" except when looked up via argument-dependent lookup (ADL); see Section 13.2, on page 205). That is what happens with our first friend declaration: `void f()` is declared within namespace `N`, and so a new `f` is "invisibly" declared.

However, when the identifier naming the friend is followed by a template argument list, a template must be visible through normal lookup at that point, and normal lookup will go up any number of scopes that may be required. So, our second declaration above will find the global function template `f()`, the compiler will then issue an error because the return types do not match (since no ADL is performed here, the declaration created by the preceding friend function declaration is ignored).

Explicitly specified template arguments are substituted using SFINAE principles: If the substitution leads to an error in the immediate context of that substitution, the function template is discarded, but other templates may still succeed. For example:

```cpp
template<typename T> T f(T);                 // #1
template<typename T> typename T::type f(T);   // #2
```

Here, substituting `int*` for `T` in candidate #2 causes substitution to fail, but in candidate #1 it succeeds, and therefore that is the candidate selected. In fact, if after substitution exactly one candidate remains, then the name of the function template with the explicit template arguments is resolved to a pointer-to-function type in many contexts. That is, replacing `main()` above by

```cpp
int main() {
  auto x = f<int>;     // OK: x is a pointer to function
}
```

produces a valid translation unit. However, the following example:

```cpp
template<typename T> void f(T);
template<typename T> T f(T, T);

int main() {
  auto x = f<int>;     // ERROR: there are two possible f functions
}
```

is not valid because `f<int>` does not identify a single function in that case.

Variadic function templates can be used with explicit template arguments also:

```cpp
template<typename... T> void f(T... pa);

int main() {
  f<double, double, int>(1, 2, 3);  // OK: 1 and 2 are double, but int ...
}
```
