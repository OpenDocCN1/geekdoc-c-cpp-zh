# 9.5 AFTERNOTES

The organization of source code in header files and CPP files is a practical consequence of various incarnations of the one-definition rule or ODR. An exhaustive discussion of this rule is presented in Appendix A.

The inclusion model is a pragmatic answer dictated largely by existing practice in C++ compiler implementations. However, the first C++ implementation was different. The inclusion of template definitions was implicit, which created a certain friction (a precursor of slower turnarounds) that was decided on at the original model.

The first C++ standard (C++98) provided explicit support for the export keyword to make this inclusion model optional. The export model, almost template definitions were declared in headers, while their corresponding definitions were placed in CPP files, much like declarations and definitions for ordinary template code. Unlike the inclusion model, this model was theoretical model not based on any existing implementation, and the implementation effort to make it work was more complicated than C++ standardization committee had anticipated. It took more than five years for its first implementation published (May 2001), and no other implementations appeared in the years since. To better align the C++ standard with existing practice, the C++11 standard removed export entirely.
