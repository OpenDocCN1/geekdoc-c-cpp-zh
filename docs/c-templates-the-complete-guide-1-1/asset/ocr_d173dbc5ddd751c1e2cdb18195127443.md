# PERFECT FORWARDING FOR VARIADIC TEMPLATES

Perfect forwarding combines with variadic templates, allowing a function template to accept any number of function call arguments and forward each of them along to another function:

Click here to view code image

```
```cpp
template<typename... T> void forwardTo(T&&... x)
{
    g(std::forward<T>(x)...);    // forward all x to g()
}
```
```

The arguments in a call to `forwardTo()` will independently deduce recursive value for this parameter pack `T&&` (see Section 5.5 on page 55) so that the types and lvalue- or rvalue-ness of each argument is captured. The pack expansion (see Section 12.4.1 on page 291) in the call to `g()` will then forward each of these arguments using the perfect forwarding technique explained above.

Despite its name, perfect forwarding is not, in fact, “perfect” in the sense that it does not capture all interesting properties of an expression. For example, it does not distinguish whether an rvalue is a bit-field value, nor does it capture whether the expression has a specific constant value. The latter cases problems particularly when we're dealing with the null pointer constant, which is usually of integer type but which would be the constant value zero. Since the constant value of an expression is not captured by perfect forwarding, overload resolution in the following example will behave differently for the direct call `g(0)` than for the forwarded call to `g()`:

Click here to view code image

```
```cpp
void g(int*);
void g(...);

template<typename T> void forwardTo(T&& x)
{
    g(std::forward<T>(x));    // forward x to g()
}

void foo()
{
    g(0);                     // calls g(int*)
    forwardTo(0);             // essentially calls g(...)
}
```
```

This is yet another reason to use `nullptr` (introduced in C++11) instead of `NULL` pointer constants:

Click here to view code image

```
```cpp
g(nullptr);                 // calls g(int*)
forwardTo(nullptr);          // essentially calls g(int*)
```
```

All of our examples of perfect forwarding focus on the use of function arguments while maintaining their precise type and whether it is an lvalue or rvalue. The same problem occurs when forwarding the return value of a call to another function, with precisely the same type and value category, a generalization of lvalues and rvalues discussed in Appendix B. The `decltype` facility introduced in C++11 (and described in Section 15.10.2 on page 596) enables this use of same:

Click here to view code image

```
```cpp
template<typename T>
auto forwardTo(T&& x) -> decltype(g(std::forward<T>(x)))
{
    return g(std::forward<T>(x));    // forward all x to g()
}
```
```

Note that the expression in the return statement is copied verbatim into the `decltype` type, so that the exact type of the return expression is computed. Moreover, the trailing return type is used (i.e., the `auto` placeholder before the function name and the `->` indicate the return type) so that the function parameter pack is in scope for the `decltype` type. This forwarding function “perfectly” forwards all arguments to `g()` and then “perfectly” forwards its result back to the caller.
