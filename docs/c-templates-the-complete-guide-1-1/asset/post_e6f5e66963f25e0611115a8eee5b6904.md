
of top-level "array extents" from a type. You can use it as follows:

Click here to view code image

```cpp
RemoveAllExtents<int>             // yields int
RemoveAllExtents<int[5][10]>      // yields int[10]
RemoveAllExtents<int[10][5]>      // yields int[5]
RemoveAllExtents<int[5]>          // yields int
```

This metaprogram transforms its task by having the partial specialization that matches the top-level array can recursively "invoke" the metafunction itself.

Computing with values would be very limited if all that was available to us were scalar values. Fortunately, just about any programming language has at least one container of values construct that greatly magnifies the power of that language (and most languages have a variety of container kinds, such as arrays/vectors, hash tables, etc.). The same is true of type metaprogramming. Adding a container of types construct greatly increases the applicability of the discipline. Fortunately, modern C++ includes mechanisms that enable the development of such a container. Chapter 26 discusses a typical example of this, which is a fairly rich container of types, in great detail.

### 23.1.3 Hybrid Metaprogramming

With value metaprogramming and type metaprogramming we can compute values and types at compile time. Ultimately, however, we're interested in using the results of these metaprograms in runtime code in places where types and constants are expected. Metaprogramming can do more than that, however. We can programmatically assemble at compile time bits of code with a run-time effect. We call that hybrid metaprogramming.

To illustrate this principle, let's start with a simple example: computing the dot-product of two std::array values. Recall that std::array is a fixed-length container template declared as follows:

Click here to view code image

```cpp
template<typename T, size_t N>
struct array {
    T elems[N];
};
```

where N is the number of elements of type T in the array. Given two objects of that same array type, their dot-product can be computed as follows:

Click here to view code image

```cpp
template<typename T, size_t N>
auto dotProduct(const array<T, N>& x,
                const array<T, N>& y)
{
    T result{};
    for (size_t k = 0; k < N; ++k)
        result += x[k] * y[k];
    return result;
}
```

A straightforward compilation of the for-loop will produce branching instructions that on some machines may cause some overhead compared to straight-line execution of

```cpp
result = x[0]*y[0];
result += x[1]*y[1];
result += x[2]*y[2];
...
result += x[N-1]*y[N-1];
```

Fortunately, modern compilers will optimize the loop into whichever form is most efficient for the target platform. For the sake of discussion, however, let's rewrite our dotProduct() implementation in a way that avoids the loop:

```cpp
template<typename T, size_t N>
struct DotProduct {
    static inline T result(const T* a, const T* b) {
        return a[0] * b[0] +
            N > 1 ? result(a + 1, b + 1) : 0;
    }
};

// partial specialization as end criteria
template<typename T>
struct DotProduct<T, 0> {
    static inline T result(const T*, const T*) {
        return T{};
    }
};

template<typename T, size_t N>
auto dotProduct(const array<T, N>& x,
                const array<T, N>& y)
{
    return DotProduct<T, N>::result(x.begin(), y.begin());
}
```

This new implementation delegates the work to a class template DotProduct<T, N> that enables us to use recursive template instantiation with class template partial specialization to end the recursion. Note how each instantiation of DotProduct produces the sum of one term of the stages of the primary template and one instance of the terminating partial specialization. For this to be efficient, it is critical that the compiler inlines every invocation of the static member functions `result()`. Fortunately, this is generally true when a nonmodular level of C++ compiler optimization is enabled.

The central observation about this code is that it blends compile-time computation (achieved here through recursive template instantiation) that determines the overall structure of the code with a run-time computation (calling `result()`) that determines the specific run-time effect.

We mentioned earlier that the metaprogramming is greatly enhanced by the availability of a “container of types.” We’ve already seen that in hybrid metaprogramming a fixed-length array type can be useful. Nonetheless, the “zero overhead” hybrid metaprogramming trick is to use a tuple of a sequence of values, each with a selectable type. The C++ standard library includes a `std::tuple` class template that supports that notion. For example,

```cpp
std::tuple<int, std::string, bool> v{42, "7", true};
```

defines a variable that aggregates three values of types `int`, `std::string`, and `bool` (in that specific order). Because of the tremendous importance of tuple-like containers for modern C++ programming, we develop one in detail in Chapter 5. The type of value is very similar to a simple struct type like:

Click here to view code image

```cpp
struct MyTuple {
    int v1;
    std::string v2;
    bool v3;
};
```

Given that `std::array` and `std::tuple` give us flexible counterparts to array types and (simple) struct types, it is natural to wonder whether and how to implement a simple union type whose uses would also be useful for hybrid computation. The answer is yes. The C++ standard library introduced a `std::variant` template for this purpose in C++17, and we develop a similar component in Chapter 26.

Because `std::tuple` and `std::variant`, like struct types, are heterogeneous types, hybrid metaprogramming that uses such types is sometimes called heterogeneous metaprogramming.

### 23.1.4 Hybrid Metaprogramming for Unit Types

Another example demonstrating the power of hybrid computing is hybrids that are able to compute results of values of different unit types. We focus on a computation that is performed at run time, but the computation of the resulting unit is determined at compile time.

Let’s illustrate this with a highly simplified example. We are going to keep track of units in terms of their ratio (fraction) of a principal unit. For example, if the principal unit for time is a second, a millisecond is represented with ratio 1/1000 and a minute with ratio 60/1. The key, then, is to define a ratio type where each value has its own type.

Click here to view code image

```cpp
meta/ratio.hpp

template<unsigned N, unsigned D = 1>
struct Ratio {
    static constexpr unsigned num = N;  // numerator
    static constexpr unsigned den = D;  // denominator

    using Type = Ratio<num, den>;
};
```

Now we can define compile-time computations such as adding two units:

Click here to view code image

```cpp
meta/add.hpp

// implementation of adding two ratios:
template<typename T1, typename T2>
struct RatioAddImpl
{
private:
    static constexpr unsigned den = T1::den * T2::den;
    static constexpr unsigned num = T1::num * T2::den + T2::num * T1::den;

public:
    typedef Ratio<num, den> Type;
};
```

```cpp
template<typename R1, typename R2>
using RatioAdd = typename RatioAddImpl<R1, R2>::Type;
```

This allows us to compute the sum of two ratios at compile time.

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_362_0.png)

```cpp
using R1 = Ratio<1, 1000>;
using R2 = Ratio<2, 3>;
using R3 = RatioAdd<R1,R2>;    // R3 has num=2003, den=3000
// R3::num == 2003 && R3::den == 3000 // previous page 233,3000
using R4 = RatioAdd<R2,R3>;    // R4 has num=4003, den=3000
// R4::num == 4003 && R4::den == 3000 // previous page 25/21
```

We can now define a class template for durations, parameterized with an arbitrary value type and a unit type that is an instance of Ratio<>.

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_362_1.png)

```cpp
meta/duration.hpp

// duration type for values of type T with unit type U
template<typename T, typename U = Ratio<1>>
class Duration {
 public:
  using ValueType = T;
  using UnitType = typename U::Type;
 private:
  ValueType val;
 public:
  constexpr Duration(ValueType v = 0)
   : val(v) {
  }
  constexpr ValueType value() const {
    return val;
  }
};
```

The interesting part is the definition of an operator+ to add two Durations:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_362_2.png)

```cpp
meta/durationadd.hpp

// adding two durations where unit type might differ:
template<typename T1, typename U1, typename T2, typename U2>
auto constexpr operator+(Duration<T1, U1> const& lhs,
                         Duration<T2, U2> const& rhs)
{
  // resulting type is a unit with 1 as numerator and
  // the resulting denominator of adding both unit types
  using VT = Ratio<1, RatioAdd<U1,U2>::den>;
  // resulting value is the sum of both values
  // converted to the resulting unit type
  auto val = lhs.value() * VT::den / U1::den * U1::num +
             rhs.value() * VT::den / U2::den * U2::num;
  return Duration<decltype(val), VT>{val};
}
```

We allow the arguments to have different unit types, U1 and U2. And we use their common denominator as the resulting denominator to have a unit type whose numerator is 1. With all that in place, we can compile the following code:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_362_3.png)

```cpp
int a = 42;
Duration<int, Ratio<1,3>> d1(a);
```
