# Nontemplate.

Now, the non-template function `f(int)` is a better match when passing a nonconstant `int`. The reason is that for an `int` the instantiated template function `f(const T&)` is a worse match than `f(int)`. Thus, the difference is that only the first one function is a template and the other is not. In that case the general rules of overload resolution apply (see Section 6.1 on page 62). Only when calling `f()` for a `const int`, both signatures have the same type, so the non-template is preferred.

Nevertheless, this effect can easily occur accidentally and cause surprising behavior when member functions are defined that accept the same arguments as copy or move constructors. For example:

`details/nontrivial.cpp`

```
```cpp
#include <string>
#include <iostream>

class C {
public:
    C() = default;

    C(const C&)
    {
        std::cout << "copy constructor\n";
    }

    C(C&&)
    {
        std::cout << "move constructor\n";
    }

    template<typename T>
    C(T&&)
    {
        std::cout << "template constructor\n";
    }
};

int main()
{
    C x;

    C x2(x);                  // prints: template constructor
    C x3(std::move(x));       // prints: move constructor

    C const c;

    C x4(c);                  // prints: copy constructor
    C x5(std::move(c));       // prints: template constructor
}
```
```

The program has the following output:

```
```text
template constructor
move constructor
copy constructor
template constructor
```
```

Thus, the member function template is a better match for copying a `C` than the copy constructor. And for `std::move(c)`, which yields type `C const&&` (a type that is possible but usually doesn't have meaningful semantics), the member function template also is a better match than the move constructor.

For this reason, usually you have to multiply disable such member function templates when they might hide copy or move constructors. This is explained in Section 6.4 on page 99.
