
| Trait | Effect |
|---|---|
| `is_constructible<T, Args...>` | Can initialize type `T` with types `Args` |
| `is_trivially_constructible<T, Args...>` | Can trivially initialize type `T` with types `Args` |
| `is_nothrow_constructible<T, Args...>` | Can initialize type `T` with types `Args` and that operation won't throw |
| `is_default_constructible<T>` | Can initialize `T` without arguments |
| `is_trivially_default_constructible<T>` | Can trivially initialize `T` without arguments |
| `is_nothrow_default_constructible<T>` | Can initialize `T` without arguments and that operation can't throw |
| `is_copy_constructible<T>` | Can copy a `T` |
| `is_trivially_copy_constructible<T>` | Can trivially copy a `T` |
| `is_nothrow_copy_constructible<T>` | Can copy a `T` and that operation can't throw |
| `is_move_constructible<T>` | Can move a `T` |
| `is_trivially_move_constructible<T>` | Can trivially move a `T` |
| `is_nothrow_move_constructible<T>` | Can move a `T` and that operation can't throw |
| `is_assignable<T1, T2>` | Can assign type `T2` to type `T1` |
| `is_trivially_assignable<T1, T2>` | Can trivially assign type `T2` to type `T1` |
| `is_nothrow_assignable<T1, T2>` | Can assign type `T2` to type `T1` and that operation can't throw |
| `is_copy_assignable<T>` | Can copy assign a `T` |
| `is_trivially_copy_assignable<T>` | Can trivially copy assign a `T` |
| `is_nothrow_copy_assignable<T>` | Can copy assign a `T` and that operation can't throw |
| `is_move_assignable<T>` | Can move assign a `T` |
| `is_trivially_move_assignable<T>` | Can trivially move assign a `T` |
| `is_nothrow_move_assignable<T>` | Can move assign a `T` and that operation can't throw |
| `is_destructible<T>` | Can destroy a `T` |
| `is_trivially_destructible<T>` | Can trivially destroy a `T` |
| `is_nothrow_destructible<T>` | Can destroy a `T` and that operation can't throw. |
| `is_swappable<T>` | Can call `swap(t, u)` for this type (since C++17). |
| `is_nothrow_swappable<T>` | Can call `swap(t, u)` for this type and that operation can't throw (since C++17). |
| `is_swappable_with<T, U>` | Can call `swap(t, u)` for these two types with specific value category (since C++17). |
| `is_nothrow_swappable_with<T, U>` | Can call `swap(t, u)` for these two types with specific value category and that operation can't throw (since C++17). |

*Table 8.4. Traits to Check for Specific Operations*

Table 8.4 lists the type traits that allow us to check for some specific operations. The forms with `is_trivially_...` additionally check whether all (sub-)operations called for the object members or base classes are trivially (neither user-defined nor virtual). The forms with `is_nothrow_` additionally check whether the called operation guarantees not to throw. Note that all `is_..._constructible` checks imply the corresponding `is_..._destructible` check. For example:

**Click here to view code image**

`util/isconstructible.cpp`

```cpp
#include <iostream>

class C {
 public:
  C() { // default constructor has no noexcept
  }
  virtual ~C() = default; // makes C nontrivial
};

int main()
{
  using namespace std;
  cout << is_default_constructible_v<C> << '\n';
  cout << is_trivially_default_constructible_v<C> << '\n';
  cout << is_nothrow_default_constructible_v<C> << '\n';
  cout << is_copy_constructible_v<C> << '\n';
  cout << is_trivially_copy_constructible_v<C> << '\n';
  cout << is_nothrow_copy_constructible_v<C> << '\n';
  cout << is_destructible_v<C> << '\n';
  cout << is_nothrow_destructible_v<C> << '\n';
}
```

Due to the definition of a virtual destructor, all operations are no longer trivial. And because we define a default constructor without `noexcept`, it might throw. All other operations, by default, guarantee not to throw.

- `std::is_constructible<T, Args...>::value`
- `std::is_trivially_constructible<T, Args...>::value`
- `std::is_nothrow_constructible<T, Args...>::value`

Yields true if an object of type `T` can be initialized with arguments of the types given by `Args...` (without using a nontrivial operation or with the guarantee that no exception is thrown). That is, the following must be valid:

`T t(std::declval<Args>()...);`

A true value implies that the object can be destroyed accordingly (i.e., ...). Requires that the given type is either complete (see Section 30.3.1 on page 154), (cv-qualified) void, or arrays of unknown bound.

- For example:

**Click here to view code image**

```cpp
is_constructible_v<int>                         // true
is_constructible_v<const int>                   // true
is_constructible_v<long, int>                   // true
is_constructible_v<long[], int>                 // false
is_constructible_v<void*>                       // false
is_constructible_v<const char*, std::string>    // false
is_constructible_v<char*, std::string>          // true
```

- Note that `is_constructible` has a different order for the source and destination types.

```cpp
std::is_default_constructible<T>::value
std::is_trivially_default_constructible<T>::value
std::is_nothrow_default_constructible<T>::value
```

- Yields `true` if an object of type `T` can be initialized without any argument for initialization (without using a nontrivial operation or with the guarantee that no exception is thrown).
- Same as `is_constructible<T>`, `is_trivially_constructible<T>`, or `is_nothrow_constructible<T>`, respectively.
- A true value implies that the object can be destroyed accordingly (i.e., `is_trivially_destructible<T>` or `is_nothrow_destructible<T>::value`).
- Requires that the given type is either complete (see Section 30.3.1 on page 354), (cv-qualified) void, or an array of unknown bound.
- For example:

**Click here to view code image**

```cpp
is_default_constructible<int>                  // yields true
is_copy_constructible<U>                        // yields true
is_copy_constructible<std::unique_ptr<int>>     // yields false
is_copy_constructible<std::string>              // yields true
is_copy_constructible<const std::string>        // yields false
is_constructible_v<std::string, const std::string&> // yields true
is_constructible_v<std::string, std::string&&>  // yields true
is_constructible_v<std::string, std::string&>   // yields true
```

```cpp
std::is_move_constructible<T>::value
std::is_trivially_move_constructible<T>::value
std::is_nothrow_move_constructible<T>::value
```

- Yields `true` if an object of type `T` can be created from an rvalue of type `T` (without using a nontrivial operation or with the guarantee that no exception is thrown).

Provided `T` is a referencable type, same as in `is_constructible<T, Args...>`; in particular, `is_trivially_copy_constructible<T>::value` is false.

A cv-unqualified object that can be destroyed asynchronously (i.e., via `destroy_async()`, `is_trivially_destructible_v<T>`, `is_nothrow_destructible_v<T>`) is called "trivial".

Note that there is no way to check whether a nontrivial destructor has been called for an object of type `T`. It is often assumed that the destructor call does not have any effect (that is, the corresponding type is not an actual class (references or pointers to objects declared with this type)).

See section 9.7 on page 44 for the implementation details.

For example:

**Click here to view code image**

```cpp
is_move_constructible_v<int>       // yields true
is_move_constructible_v<double>    // yields true
is_move_constructible_v<std::unique_ptr<int>> // yields true
is_move_constructible_v<int&>      // yields true
is_move_constructible_v<const int&> // yields true
// in contrast to:
is_constructible_v<const int&, int&> // yields true
is_constructible_v<const int&, int&&> // yields true
is_constructible_v<const int&, const int&> // yields true
is_constructible_v<const int&, const int&&> // yields false
```

```cpp
std::is_assignable<T&, T> // yields true
std::is_trivially_assignable<T&, T> // yields true
std::is_nothrow_assignable<T&, T> // yields true
```

Requires that the given types are either complete (see Section 10.3.1 on page 154) or arrays of unknown bound.

Note that `is_assignable<>` for move-assignment is defined member-wise as if they were declared as copy assignment operators (but note that the assignment is = 7.1). Note: this is because it is a reference to a member function if the function is not virtual and a reference to a virtual function if the function is virtual.
