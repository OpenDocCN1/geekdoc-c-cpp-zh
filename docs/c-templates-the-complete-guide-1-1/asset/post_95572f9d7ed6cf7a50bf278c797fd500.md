### 25.7 AFTERNOTES

The tuple is one of these template applications that appears to have been independently attempted by many programmers. The Boost.Tuple library [Boost.Tuple] became one of the most popular formulations of this in C++.

Prior to C++14, many tuple implementations were based on the idea of a recursive pair structure; the first edition of this book, for example, [Vandevoorde1] illustrated one such approach via its "recursive class." One interesting alternative was developed by Andrei Alexandrescu in [Alexandrescu]. He cleverly separated the list of types from the list of fields, using the concept of typelists (as discussed in Chapter 2) as a foundation for tuples.

Tuple is the most widely used heterogeneous container, but it isn't the only one. The Boost.Fusion library [Boost.Fusion] provides other heterogeneous counterparts to containers, such as heterogeneous list, deque, set, and map. More important, it provides a framework for writing algorithms for heterogeneous collections, using the same kinds of abstractions and terminology as the C++ standard library itself (e.g., iterators, sequences, and containers).

[Boost.Hana] and [Boost.Fusion] take many of the ideas present in Boost.MPL and Boost.Fusion, both designed and implemented long before C++11 came to fruition, and reimplement them with the new C++11 language features.

- A complete implementation of `get<>` should also handle non-const and rvalue-reference tuples appropriately.
- Before C++11, inline variables were not supported. So, we had to initialize `rawCopies` outside the class structure in one translation unit.
- C++14 provides a similar template `make_index_sequence` that yields a list of indices of type `std::size_t`, as well as a more general `make_integer_sequence` that allows the specific type to be selected.

## Discriminated Unions

The types developed in the previous chapter aggregate values of some list of types into a single value, giving them roughly the same functionality as a simple struct. Given that analogy, it is natural to wonder whether the corresponding type would be a union. It would contain a single value, but that value would have a type selected from some set of possible types. For example, a class that might contain an int, a double, or a string (using a value of one of those types at any given time).

In this chapter, we develop a class template Variant that dynamically stores a value of one of a given set of possible value types, similar to the C++ standard library's std::variant. Variant is an advanced union, meaning that a variant knows which of its possible value types is currently active, providing better type safety than the equivalent C++ union. Variant also has a couple of template parameters, which accept the list of types the variant may have. For example, the variable

Click here to view code image

```cpp
Variant<int, double, string> field;
```

can contain an int, a double, or a string, but only one of those values at a time. The following program illustrates the behavior of Variant:

Click here to view code image

```cpp
#include "variant.hpp"
#include <iostream>
#include <string>

int main()
{
    Variant<int, double, std::string> field(17);
    if (field.is<int>()) {
        std::cout << "Field stores the integer "
                  << field.get<int>() << '\n';
    }

    field = 42;    // assign value of new type
    field = "hello"; // assign value of different type
    std::cout << "Field now stores the string "
              << field.get<std::string>() << '\n';
}
```

It produces the following output:

Click here to view code image

```text

Field now stores the string "hello"
```

The variant can be assigned a value of any type. We use two member functions to extract the contained value: is<T> checks whether the variant currently contains a value of type T using the member function is<int>(), then extract that stored value with the member function get<T>().

### 26.1 STORAGE

The first design aspect of our Variant type is how to manage the storage of the active value. That is, the value that is currently stored.

```cpp
template<typename T>
T* getBuffer() { return std::launder(reinterpret_cast<T*>(...)); }
```

Here, we use the LargestType metaprogram developed in Section 24.2.2 on page 552 to compute the size of the buffer, ensuring it is large enough for any of the value types. Similarly, the alignas expression ensures that the buffer will have an alignment suitable for any of the value types. The buffer we have created is essentially the machine representation of the union shown above. We can access a pointer to the buffer using getBuffer(); and manipulate the storage through the use of explicit casts, placement new (to create new values), and explicit destruction (to destroy the values we created). If you are not familiar with this concept (as used in getBuffer()), it is sufficient for now to know that it returns its argument unmodified; we will explain its role when we talk about assignment operators for Variant (see Section 24.3.3 on page 617).

### 26.2 DESIGN

Now that we have a solution to the storage problem for variants, we design the Variant type itself. As with the Tuple type, we use inheritance to provide behavior for each type in the list of Types. Unlike with Tuple, however, these classes do not have storage. Rather, each of the base classes uses the Union to provide the actual storage.

The class template VariantChoice is defined below, provides the core operations needed to operate on the buffer when the variant's active value is (or will be) of type T:

template<typename T, typename... Types>
class VariantChoice {
    using Derived = Variant<T, Types...>;

    Derived& getDerived() { return *static_cast<Derived*>(this); }

    Derived const& getDerived() const {
        return *static_cast<Derived const*>(this);
    }

protected:
    // compute the discriminator to be used for this type
    constexpr static unsigned Discriminator =
        FindIndexOf<T, Types...>::value + 1;

public:

    VariantChoice(T&& value);           // see variant...

    Derived& operator=(T const& value); // see variant...
    Derived& operator=(T&& value);      // see variant...
};
