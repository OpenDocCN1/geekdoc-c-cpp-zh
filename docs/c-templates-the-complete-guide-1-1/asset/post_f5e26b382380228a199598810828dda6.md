
whether a type has a value_type or a char_type, the member type is false.

```cpp
#include "bool_type.hpp"

#include <iostream>
#include <vector>

DEFINE_HAS_TYPE(value_type);
DEFINE_HAS_TYPE(char_type);

int main()
{
    std::cout << "int::value_type: "
              << HasType_value_type<int>::value << '\n';
    std::cout << "float::value_type: "
              << HasType_value_type<float>::value << '\n';
    std::cout << "std::vector<int>::value_type: "
              << HasType_value_type<std::vector<int>>::value << '\n';
    std::cout << "std::vector<char>::value_type: "
              << HasType_value_type<std::vector<char>>::value << '\n';
}
```

## 9.4.3 Detecting Nontype Members

We can modify the trait to check for data members and (single) member functions.

Click here to view code image

```cpp
#include "hasmember.hpp"

DEFINE_HAS_MEMBER(member)

template<typename T, typename = std::void_t<>>
struct HasMember : std::false_type {
};

template<typename T>
struct HasMember<T, std::void_t<decltype(T::member)>> {
    static bool const value = true;
};
```

Here, we use SFINAE to disable the partial specialization when &T::member is not valid. For that construct to be valid the following must be true:

- Member must unambiguously identify a member of T (e.g., it cannot be an overloaded member function name, or the name of multiple inherited members of the same name).
- The member must be accessible.
- The member must be a nontype, nonenumerator member (otherwise the prefix & would be ill-formed).
- If T is a class, the type must not provide an operator& that returns a different type (such as a weirdly overloaded operator&). However, we can then replace &T::member with std::addressof(T::member) (or similar) to still make that operator work.

Click here to view code image

```cpp
#include "hasmember.hpp"

#include <iostream>
#include <vector>
#include <utility>

DEFINE_HAS_MEMBER(size);
DEFINE_HAS_MEMBER(first);

int main()
{
    std::cout << "has:size: "
              << HasMemberT_size<int>::value << '\n';

    std::cout << "has:vector:size? "
              << HasMemberT_size<std::vector<int>>::value;

    std::cout << "std::pair<int,int>::first: "
              << HasMemberT_first<std::pair<int,int>>::value;
}
```

It would not be difficult to modify the partial specialization to exclude classes where T::member is not a pointer-to-member type (which means a non-static data member). Similarly, a pointer-to-member function could be excluded or required to limit the trait to data members or member functions.

### Detecting Member Functions

Note that the isMember trait only checks whether a single member with the corresponding name exists. That trait also will fail if two members exist, which might happen if we check for overloaded member functions. For example:

Click here to view code image

```cpp
DEFINE_HAS_MEMBER(begin);
std::cout << HasMemberT_begin<int>::value; // false
```

However, as explained in Section 8.4.1 on page 133, the SFINAE principle protects against attempts to create bad template types and expressions in function template declarations, allowing the overloading technique above to extend to testing whether arbitrary expressions are well-formed.

That is, we can simply check whether we can call a function of interest in a specific way and that can succeed even if the function is overloaded. As with the IsConvertible<> trait in Section 9.5 on page 428, the trick is to formulate the expression that checks whether we can call begin() inside a call to expression for the default value of an additional function template parameter:

Click here to view code image

traits/hasbegin.hpp

```cpp
#include <utility>      // for declval
#include <type_traits>   // for true_type, false_type

// primary template:
template<typename, typename = std::void_t<>>
struct HasBeginT : std::false_type
{
};

// partial specialization (may be SFINAE'd away):
template<typename T>
struct HasBeginT<T, std::void_t<decltype(std::declval<T>().begin())>>
  : std::true_type
{
};
```

Here we use

Click here to view code image

traits/hasbegin.hpp

```cpp
decltype(std::declval<T>().begin())
```

to test whether, given a value/object of type T (using std::declval to avoid constructing a type), calling a member begin() is valid.

### Detecting Other Expressions

We can use the technique above for other kinds of expressions and even compile multiple expressions. For example, we can test whether, given types T and U, there is a suitable < operator defined for values of these types.

Click here to view code image

```cpp
#include <type_traits> // for true_type, false_type,

// primary template:
template<typename, typename = std::void_t<>>
struct HasLast : std::false_type
{
};

// partial specialization (may be SFINAE'd away):
template<typename T>
struct HasLast<T, std::void_t<decltype(std::declval<T>().last)>>
    : std::true_type
{
};
```

As always, the challenge is to define a valid expression for the condition to check and use decltype to place it in a SFINAE context, where it will cause a fallback to the primary template if the expression isn't valid:

[Click here to view code image](#)

```cpp
decltype(std::declval<T>().last)
```

Traits that detect valid expressions in this manner are fairly robust: They will evaluate true only when the expression is well-formed and will correctly return false when the operator is ambiguous, deleted, or inaccessible.

We can use the trait as follows:

[Click here to view code image](#)

```cpp
HasLast<T>::value                         // yields true
HasLast<int>::value                       // yields false
HasLast<int*>::value                      // yields false
HasLast<SomeClass>::value                 // yields true
HasLast<SomeClass>::value                 // yields false
HasLast<SomeClass>::value                 // yields true
HasLast<SomeClass>::value                 // yields false
```

As introduced in Section 2.3.1 on page 30, we can use this trait to require that a template parameter "supports operator <":

[Click here to view code image](#)

```cpp
template<typename T>
class C
{
    static_assert(HasLast<T>::value,
                  "T must have a comparable operator <");
};
```

Note that, due to the nature of std::void_t, we can combine multiple constraints in a trait:

[Click here to view code image](#)

traits/hasvarious.hpp

```cpp
#include <utility> // for declval
#include <type_traits> // for true_type, false_type,

// primary template:
template<typename, typename = std::void_t<>>
struct HasVarious : std::false_type
{
};

// partial specialization (may be SFINAE'd away):
template<typename T>
struct HasVarious<T, std::void_t<
    decltype(std::declval<T>().first),
    decltype(std::declval<T>().second),
    decltype(std::declval<T>().last)>>
    : std::true_type
{
};
```

Traits that detect the validity of a specific syntax are quite powerful, allowing a template to customize its behavior based on the presence or absence of a particular operation. These traits will be used again both as part of the definition of SFINAE-friendly traits (Section 9.4) and in overloading based on type properties (Chapter 20).

## 9.6.4 Using Generic Lambdas to Detect Members

The isValidLambda, introduced in Section 9.4.3 on page 421, provides a more compact technique to define traits that check for members, helping to avoid the use of macros to turn the test members arbitrary.

The following example illustrates how to define traits checking whether a data type member such as first or size_type exists or whether operator< is defined for two objects of different types:

Click here to view code image

traits/isvalidall.cpp

```cpp
#include "isvalid.hpp"
#include <iostream>
#include <string>
#include <utility>

int main()
{
    using namespace std;
    cout << boolalpha;

    // define to check for data member first:
    constexpr auto hasFirst
        = isValid([](auto x) -> decltype((void)value(x).first) {
        });

    cout << "hasFirst: " << hasFirst(type...);

    // define to check for size_type
    constexpr auto hasSizeType
        = isValid([](auto x) -> decltype((void)std::declval<...>) {
        });

    struct CX {
        using size_type = std::size_t;
    };

    cout << "hasSizeType: " << hasSizeType(type<CX>) << ...;

    if constexpr (hasSizeType(type<int>)) {
        cout << "int has no size_type\n";
        ...
    }

    // define to check for <
    constexpr auto hasLess
        = isValid([](auto x, auto y) -> decltype(value(x) < value(y)) {
        });
```
