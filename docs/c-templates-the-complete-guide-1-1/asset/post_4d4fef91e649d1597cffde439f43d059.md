
```cpp
    return os << (a.first() ? 'A' : 'B');
  }
}

template<typename... Types>
void printTupleElements(Tuple<Types...> const& t) {
    bool isFirst = true;

    (
        std::cout << (isFirst ? "" : ", "),
        std::cout << t.getHead(),
        printTupleElements(t.getTail()),
        isFirst = false
    );
}

template<typename... Types>
std::ostream& operator<< (std::ostream& strm, Tuple<Types...> const& t)
{
    strm << "(";
    printTupleElements(t);
    return strm << ")";
}
```

Now, it is easy to create and apply such algorithms. For example:

```cpp
auto d = makeTuple(1, 2.5, std::string("hello"));
print(d);
```

## 25.3 TUPLE ALGORITHMS

A tuple is a container that provides the ability to access and modify each of its elements (through get()) as well as to create new tuples (directly or by concatenating, splitting, or applying some transformation to one or more existing tuples). These fundamental building blocks are reflected in a suite of tuple algorithms, such as adding or removing elements from tuples, reordering the elements in a tuple, or selecting some subset of the elements in the tuple.

### 25.3.1 Tuples as Typelists

If we ignore the actual run-time component of our Tuple template, we see that it has precisely the same structure as the Typelist template developed in Chapter 24. It accepts any number of template type parameters. In fact, with a few specializations, we can turn a Tuple into a full-fledged typelist:

```cpp
// determine whether the tuple is empty:
template<>
struct IsEmpty<Tuple<>>
{
    static constexpr bool value = true;
};

// extract front element:
template<typename Head, typename... Tail>
class Front<Tuple<Head, Tail...>>
{
public:
    using Type = Head;
};

// pop front element
template<typename Head, typename... Tail>
class PopFront<Tuple<Head, Tail...>> {
public:
    using Type = Tuple<Tail...>;
};

// add element to the front
template<typename... Types, typename Element>
class PushFront<Tuple<Types...>, Element> {
public:
    using Type = Tuple<Element, Types...>;
};

// add element to the back
template<typename... Types, typename Element>
class PushBack<Tuple<Types...>, Element> {
public:
    using Type = Tuple<Types..., Element>;
};
```

Now, all of the typelist algorithms developed in Chapter 24 work equally well with Tuple and TypeList, so that we can easily deal with the type of tuples. For example:

```cpp
Tuple<int, double, string> t1(1, 3.14, "Hello, World!");
using T2 = PushBack<decltype(t1), bool>::Type;
T2 t2(get<int>(t1), get<double>(t1), true);
std::cout << get<2>(t2) << std::endl;
```

Which prints:

```text
(3.14, Hello, World!, 1)
```

### 25.3.2 Adding to and Removing from a Tuple

For the values of tuples, the ability to add an element to the beginning or end of a tuple is important for building more advanced algorithms. As with typelists, insertion at the front of a tuple is far easier than insertion at the back, so we start with pushFront:

```cpp
template<typename... Types, typename V>
class PushFront<Tuple<Types...>, V>
{
public:
    using Type = Tuple<V, Types...>;
};
```

Adding a new element (called value) onto the front of an existing tuple requires us to form a new tuple with value as its head and the existing type as its tail. The resulting tuple type is `Tuple<V, Types...>`. However, we have applied the typelist algorithm `PushFront` to demonstrate the tight coupling between the compile-time and run-time aspects of tuple algorithms: The compile-time `PushFront` computes the new tuple type and constructs the tuple representation from the values.

Adding a new element to the end of an existing tuple is more complicated, because it requires a recursive walk of the tuple, building up the modified tuple as we go. Note how the structure of the `pushBack()` implementation follows the recursive formulation of the typelist `PushBack()` (from Section 24.2.3 on page 555).

As with typelists, we can now easily provide `pop_back()` by calling `popFront()` for the temporarily reversed list using `PopBack` from Section 24.2.4 on page 543.

`tuples/popback.hpp`

```cpp
template<typename... Types>
TupleBack<Tuple<Types...>>
popBack(Tuple<Types...> const& tuple)
{
    return reverse(popFront(reverse(tuple)));
}
```

### 25.3.4 Index Lists

The recursive formulation of tuple reversal in the previous section is correct, but it is unnecessarily inefficient at run time. To see the problem, we introduce a simple class that counts the number of times it is copied:

`tuples/copycounter.hpp`

```cpp
template<int SD>
struct CopyCounter
{
    inline static unsigned numCopies = 0;

    CopyCounter() {}

    CopyCounter(CopyCounter const&) {
        ++numCopies;
    }
};
```

Thus, we can now use and reverse a tuple of CopyCounter instances.

`tuples/copycountertest.hpp`

```cpp
void copycountertest()
{
    Tuple<CopyCounter<0>, CopyCounter<1>, CopyCounter<2>, CopyCounter<3>, CopyCounter<4>> copies;

    auto reversed = reverse(copies);

    std::cout << "0: " << CopyCounter<0>::numCopies << '\n';
    std::cout << "1: " << CopyCounter<1>::numCopies << '\n';
    std::cout << "2: " << CopyCounter<2>::numCopies << '\n';
    std::cout << "3: " << CopyCounter<3>::numCopies << '\n';
    std::cout << "4: " << CopyCounter<4>::numCopies << '\n';
}
```

This program will output:

```text
0: 5 copies
1: 5 copies
2: 5 copies
3: 5 copies
4: 5 copies
```

intermediate arguments, but doing so complicates our implementation considerably.

To eliminate extraneous copies in tuple reverse, consider how we might implement a one-off tuple reverse operation for a single tuple of known length (say, 5 elements, as in our example). We could simply use `makeTuple()`, and get `0`:

```cpp
auto reversed = makeTuple(get<4>(copies), get<3>(copies), get<2>(copies), get<1>(copies), get<0>(copies));
```

This program produces the exact output that we want, with a single copy of each tuple element:

```text
0: 1 copies
1: 1 copies
2: 1 copies
3: 1 copies
4: 1 copies
```

**Index lists** (also called index sequences, see Section 24.4 on page 570) generalize this notion by capturing the set of tuple indices—in this case 4, 3, 2, 1, 0—into a parameter pack, which allows the sequence of calls to be produced via a pack expansion. This allows the separation of the index decomposition, which can be an arbitrarily complicated template metaprogram, from the actual application of that index list, where run-time efficiency is most important. The standard type `std::integer_sequence` (introduced in C++14) is often used to represent index lists.

### 25.3.5 Reversal with Index Lists

To perform tuple reversal with index lists, we first need a representation of index lists. An index list is a typelist containing values meant to be used as indices into either a typelist or a heterogeneous data structure (see Section 24.4 on page 570). For our index list, we will use the `ValueList` developed in Section 24.3 on page 556. The index list corresponding to a tuple would be:

```cpp
ValueList<unsigned, 4, 3, 2, 1, 0>
```

How do we produce this index list? One approach would be to start by generating an index list counting upward from 0 to N − 1 (inclusive), where N is the length of a tuple, using a simple template metaprogram `MakeIndexList`:

`tuples/MakeIndexList.hpp`

```cpp
// recursive case

template<unsigned N, typename Result = ValueList<>>
struct MakeIndexListT : MakeIndexListT<N-1, PushFront<Result, CTValue<unsigned, N-1>>>
{
};

// base case

template<typename Result>
struct MakeIndexListT<0, Result>
{
  using Type = Result;
};

template<unsigned N>
using MakeIndexList = typename MakeIndexListT<N, ValueList<>>::Type;
```

We can then compose this operation with the typelist reverse to produce the appropriate index list:

```cpp
using MyIndexList = Reverse<MakeIndexList<5>>;
```
