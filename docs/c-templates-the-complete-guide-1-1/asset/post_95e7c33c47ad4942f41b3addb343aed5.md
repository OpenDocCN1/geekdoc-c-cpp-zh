
## Chapter 2: Class Templates

Similar to functions, classes can also be parameterized with one or more types. Container classes, which are used to manage elements of a certain type, are a typical example of this feature. By using class templates, you can implement such container classes while the element type is still open. In this chapter we use a stack as an example of a class template.

### 2.1 Implementation of Class Template Stack

As we did with function templates, we declare and define class Stack in a header file as follows:

[Click here to view code image](#)

`basics/stack1.hpp`

```cpp
#include <vector>
#include <cassert>

template<typename T>
class Stack {
private:
    std::vector<T> elems;    // elements

public:
    void push(T const& elem); // push element

    void pop();               // pop element

    T const& top() const;     // return top element

    bool empty() const {      // return whether the stack is empty
        return elems.empty();
    }
};

template<typename T>
void Stack<T>::push (T const& elem)
{
    elems.push_back(elem);   // append copy of passed element
}

template<typename T>
void Stack<T>::pop()
{
    assert(!elems.empty());  // error if stack is empty
    elems.pop_back();        // remove last element
}

template<typename T>
T const& Stack<T>::top() const
{
    assert(!elems.empty());  // error if stack is empty
    return elems.back();     // return last element
}
```

As you can see, the class template is implemented by using a class template of the C++ standard library `vector<>`. As a result, we don't have to implement memory management, copy constructor, and assignment operator, thanks to the interface of this class template.

#### 2.1.1 Declaration of Class Templates

Declaring a class template is similar to declaring function templates: Before the declaration, you have to declare the identifier or multiple identifiers as a type parameter(s). Again, a type is usually used as an identifier.

[Click here to view code image](#)

```cpp
template<typename T>
class Stack {
...
};
```

Here again, the keyword class can be used instead of typename:

[Click here to view code image](#)

```cpp
template<class T>
class Stack {
...
};
```

Inside the class template, T can be used just like any other type to declare members and member functions. In this example, T is used to declare the member function push() that uses a T as an argument, and to declare top() as a function that returns T:

[Click here to view code image](#)

```cpp
template<typename T>
class Stack {
private:
    std::vector<T> elems; // elements
public:
    void push(T const& elem); // push element
    void pop(); // pop element
    T const& top() const; // return top element
    bool empty() const { // return whether the stack is empty
        return elems.empty();
    }
};
```

The type of this class is `Stack<T>`, with T being a template parameter. Thus, you have to use `Stack<T>` whenever you use this class in a declaration except in cases where the template arguments can be deduced from the arguments of a member function. However, inside the class template the injected class name can be used without template arguments (see Section 2.1.3 on page 221 for details).

For example, if you have to define your own copy constructor and assignment operator, it typically looks like this:

[Click here to view code image](#)

```cpp
template<typename T>
class Stack {
    Stack (Stack const&); // copy constructor
    Stack& operator= (Stack const&); // assignment operator
};
```

which is formally equivalent to:

[Click here to view code image](#)

```cpp
template<typename T>
class Stack {
    Stack (Stack<T> const&); // copy constructor
    Stack<T>& operator= (Stack<T> const&); // assignment operator
};
```

but usually the `<T>` is redundant, so it's usually better to use the first form.

However, outside the class you'd need:

[Click here to view code image](#)

```cpp
template<typename T>
bool operator== (Stack<T> const &, Stack<T> const&);
```

Note that in places where the name and not the type of the class is required, only Stack may be used. This is especially the case when you use the name of the class in a class declaration, or in a member function. However, you cannot declare class templates inside functions or block scope. In general, templates can only be defined in global/namespace scope or inside class declarations (see Section 12.1 on page 177 for details).

#### 2.1.2 Implementation of Member Functions

To define a member function of a class template, you have to specify that it is a template, and you have to use the full type qualification of the class template. Thus, the implementation of the member function push() of Stack<T> looks like this:

Click here to view code image

```cpp
template<typename T>
void Stack<T>::push (T const& elem)
{
    elems.push_back(elem);        // append copy of passed elem
}
```

In this case, push_back() of the element vector is called, which appends the element at the end of the vector.

Note that pop_back() of a vector removes the last element but doesn't return it. The reason for this behavior is exception safety. It is impossible to implement a pop() function that returns the removed element (this topic was first discussed by Tom Cargill in [Cargill91] and is discussed in [Josuttis99] and [Alexandrescu01]). However, if you want a pop() that returns the just removed element, you can do this by simply using T to declare a local variable of the element type:

Click here to view code image

```cpp
template<typename T>
T Stack<T>::pop()
{
    assert(!elems.empty());     // error if stack is empty
    T elem = elems.back();      // save copy of last elem
    elems.pop_back();           // remove last element
    return elem;                // return copy of saved elem
}
```

Because back() (which returns the last element) and pop_back() (which removes the last element) have undefined behavior when there is no element in the vector, we should check whether the stack is empty. If it is empty, we assert because it is a huge error to call pop() on an empty stack. This is also done in top(), which returns a reference to the top element:

Click here to view code image

```cpp
template<typename T>
T const& Stack<T>::top() const
{
    assert(!elems.empty());
    return elems.back();
}
```

Of course, as for any member function, you can also implement member functions of class templates as an inline function inside the class declaration. For example:

Click here to view code image

```cpp
template<typename T>
class Stack {
public:
    void push (T const& elem)        // append copy of
                                     // passed elem
    {
        elems.push_back(elem);
    }
};
```

### 2.2 Use of Class Template Stack

To use an object of a class template, until C++17 you must always specify the template arguments explicitly. The following example shows how to use the class template Stack<>:

Click here to view code image.

```cpp
#include "stack1.hpp"

#include <iostream>
#include <string>

int main()
{
    Stack<int> intStack;       // stack of ints

    Stack<std::string> stringStack; // stack of strings

    intStack.push(7);
    std::cout << intStack.top() << '\n';

    // manipulate string stack
    stringStack.push("hello");
    std::cout << stringStack.top() << '\n';
    stringStack.pop();
}
```

By declaring `typedef Stack<int> IntStack`, `int` is used as type inside the class template. Thus, `IntStack` is created as an object that uses `int` as elements and, for all member functions that are called, code for this type is instantiated. Similarly, by declaring and using `StringStack`, an object that uses strings as elements is created, and for all member functions that are called, code for this type is instantiated.

Note that code is instantiated only for template (member) functions that are called. For class templates, member functions are instantiated only if they are used. Thus, of course, members and space are allocated only if they are used. This example illustrates how class templates are instantiated only partially, which we will discuss in Section 2.3 on page 32.

In this example, the default constructor, `push()`, and `top()` are instantiated for both `IntStack` and `StringStack`. However, `pop()` is instantiated only for `StringStack`. If a class template has static members, these are also instantiated for each type for which the class template is used.

An instantiated class template's type can be used just like any other type. You can qualify it with `const` or `volatile` or define array and reference types from it. You can also use it as a type definition within a `typedef` or `using` (see Section 2.8 on page 38 for details about type definitions) or use it as a parameter when building another template type. For example:

Click here to view code image

```cpp
void foo(Stack<int> const& s)   // parameter s is int stack
{
    using IntStack = Stack<int>; // IntStack is another name for Stack<int>
    Stack<int> intStack[10];     // intStack is an array of 10 int stacks
    IntStack stack2[10];         // stack2 is also an array of 10 int stacks (same type)
}
```

Template arguments may be any type, such as pointers to floats or even stacks of ints:

Click here to view code image

```cpp
Stack<float*> floatStack;       // stack of float pointers
Stack<Stack<int>> intStackStack; // stack of Stack<int>
```

The only requirement is that any operation that is called is possible according to this type.

Note that before C++11 you had to put whitespace between the two closing template brackets:

Click here to view code image

```cpp
Stack<Stack<int> > intStackStack; // OK with all C++ versions
```

If you didn't do this, you were using operator `>>`, which resulted in a syntax error.

Click here to view code image

```cpp
Stack<Stack<int>> intStackStack; // ERROR before C++11
```

The reason for the double-bracket rule was that it had been the first case where the compiler had to tokenize the source code independent of the semantics of the code. However, because the missing space was a typical bug that required corresponding error messages, the semantics of the code were taken into account anyway. So, with C++11 the rule to put a space between two closing template brackets was removed.
