template <class T>
class DB : public Base<T> {        // dependent base

At point 3 we find our reference to a nondependent name basefield. It must be looked up right away. Suppose we look it up in the template Base and bind it to the int member that we find there. However, shortly after this we override the specialization definition of Base with an explicit specialization. At this point, this specialization changes the meaning of the basefield member to which we originally committed? So, when we instantiate the definition of DB at point 3, we find that we too eagerly bound the nondependent name at point 1. There is no modifiable basefield in DB<double> that was specialized at point 2, and an error message should have been issued.

To circumvent this problem, standard C++ says that nondependent names are not looked up in dependent base classes (but they can still be looked up as soon as they are encountered). So, a standard C++ compiler must emit a diagnostic at point 1. To correct the code, it suffices to make the name a dependent name (by introducing dependent names to look up only at the time of instantiation, and at that time the concrete base instance that must be used is specified. For example, at point 3, the compiler will know that the base class of DB<double> is Base<double> and thus has been explicitly specialized by the programmer. In this case, our preferred way to make the name dependent is as follows:

```
```cpp
// Variation 2:
template<class T>
class DB : public Base<T> {
public:
    void f() {
        this->basefield = 0;        // lookup delayed
    }
};
```
```

An alternative consists in introducing a dependency using a qualified name:

```
```cpp
// Variation 3:
template<typename T>
class DB : public Base<T> {
public:
    void f() {
        if (Base<T>::basefield = 0) {  // lookup delayed
        }
    }
};
```
```

Care must be taken with this solution, because if the unqualified nondependent name is used to form a virtual function call, then the qualification inhibits the virtual call semantics and the meaning of the program changes. Nonetheless, there are situations when the first variation cannot be used and this alternative is appropriate:

```
```cpp
template<typename T>
class DB : public Base<T> {
public:
    void f() {
        if (0 < 1, 2 == 28, 4 == 496) {
            virtual void f();
        }
    }
};
```
```

Now we have used D<T>:: instead of B<T>:: in this example. In this case, either one works. In multiple-inheritance cases, however, we may not know which base class provides the desired member (in which case using the derived class for qualification works) or multiple base classes may declare the same name (in which case we may have to use a specific base class name for disambiguation).
