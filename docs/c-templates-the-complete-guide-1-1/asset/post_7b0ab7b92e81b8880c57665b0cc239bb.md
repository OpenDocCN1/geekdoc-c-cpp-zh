
## 12.4.2 Where Can Pack Expansions Occur?

Our examples thus far have focused on the use of pack expansions to produce a sequence of template arguments. In fact, pack expansions can be used essentially anywhere in the language where the grammar provides a comma-separated list, including:

- In the list of base classes
- In the list of base class initializers in a constructor
- In a list of call arguments (the pattern for the argument expression)
- In a list of initializers (e.g., in a braced initializer list)
- In the template parameter list of a class, function, or alias template
- In the list of exceptions that can be thrown by a function (deprecated in C++11 and C++14, and disallowed in C++17)
- Within an attribute, if the attribute itself supports pack expansions (although no such attribute is defined by the C++ standard)
- When specifying the alignment of a declaration
- When specifying the capture list of a lambda
- In the parameter list of a function type

We have already seen three of these (see Section 4.4.2 on page 63). We have also mentioned a use, in a pack expansion mechanism that does not produce a list, but rather produces a comma-separated list (see Section 6.2 on page 175).

Some of these pack expansion contexts are included merely for the sake of completeness, as we will focus our attention on only those pack expansions that occur in the list of template parameters. In many cases, once you understand all the cases from the previous section, you should be able to complete the examples from this section here on your own. We feel a need for a more explicit pack expansion context.

A pack expansion in a list of base classes expands to some number of direct base classes. Such expansions can be useful especially when an aggregate class needs to expand to a number of base classes and its use is mostly to inherit a set of mixins (see Section 12.4.1 on page 206). For example, the following class template expands to the set of base classes listed for each of the template parameters, with no following additional base classes:

```cpp
template<typename... Mixins>
class Point: public Mixins... { // base class pack expansion
  ...
};
```

```cpp
template<typename... Ts>
struct Values {
  template<Ts... Vs>
  struct Holder {
  };
};

int i;
Values<char, int, ...> values;
```

Note that once the type arguments of `Values` have been specified, the type arguments passed to `Values<...>::Holder` should have a fixed length; the parameter pack `Vs` is thus not a variable-length parameter pack.

`Vs` is a non-type template parameter pack for which each of the actual template arguments can have a different type, as specified by the types provided for the template type parameter pack `Ts`. Note that the ellipsis in the declaration of `Vs` plays a dual role, both declaring the template parameter pack `Vs` and expanding the template parameter pack `Ts`. The latter parameter pack is a pack expansion.

## 12.4.3 Function Parameter Packs

A function parameter pack is a function parameter that matches zero or more function call arguments. Like a template parameter pack, a function parameter pack is introduced using an ellipsis (...) prior to (or in the place of) the function parameter name and, also like a template parameter pack, a function parameter pack must be expanded by a pack expansion when it is used. Template parameter packs and function parameter packs together are referred to as parameter packs.

Unlike template parameter packs, function parameter packs are always pack expansions, so their declared types must indicate at least one parameter. In the following example, we introduce a new `Point` constructor that copy-initializes each of the `x`, `y`, and `z` members from supplied constructor arguments:

```cpp
template<typename... T>
class Point : public Mixin<T...> {
  double x, y, z;
public:
  // Default constructor, virtual functions, etc. elided
  Point(Mixin<T...> mixins, ...)
    : x(...), y(...), z(...)
  { }
};

struct Color { char red, green, blue; };
struct Label { char const* string; };
Point<Color, Label> p(Color(?, ?, ?), Label("center"));
```

A function parameter pack for a function template may depend on non-template parameter packs declared in that template, which allows the function template to accept an arbitrary number of call arguments without loss of type information:

```cpp
template<typename... Types>
void print(Types... values);

int main()
{
  std::string welcome("Welcome to ");
  print(welcome, "2011", 2011, 17); // calls
  print<std::string, char const*, int, int>(welcome, "2011", 2011, 17);
}
```

When calling the function template `print()` with some number of arguments, the types of the arguments will be placed in the argument pack to be substituted for the template type parameter pack `Types`, while the actual argument values will be placed into an argument pack to be substituted for the function parameter pack `values`. The process by which the arguments are determined from the call is described in Chapter 15. For now, it suffices to note that the type in `Types` is the type of the value in `values` and that both of these parameter packs are available within the body of the function template `print()`.

The actual implementation of `print()` uses recursive template instantiation, a template metaprogramming technique described in Section 6.1 on page 23 and Chapter 2.

There is a syntactic ambiguity between an unnamed function parameter pack appearing at the end of a parameter list and a C-style "varargs" parameter. For example:

```cpp
template<typename... T>
void print(T... values);

template<typename... T>
void print(T...);
```

In the first case, the `...` is treated as a function parameter pack because `T` is a type pack and the ellipsis is placed after the parameter name. In the second case, the `...` is treated instead as a C-style varargs parameter, with an unnamed parameter of type `T` followed by the varargs ellipsis. The disambiguation can be forced by adding a comma between the ellipsis and a C-style varargs parameter or by following the ellipsis by an identifier, which makes it a named function parameter pack. Note that in general, a trailing unnamed function parameter pack is a parameter pack if the type of the parameter is a pack expansion.

## 12.4.5 Zero-Length Pack Expansions

The pattern of a pack expansion can be arbitrarily complex and may include multiple distinct parameter packs. When instantiating a pack expansion, the pattern must be expanded with the same length. The resulting sequence of types or values will be formed exactly as we've been doing: the first argument of each parameter pack is put in the pattern, followed by the second argument of each parameter pack, and so on. For example, the following function call is an error, because the function takes two arguments of the same type:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_157_0.png)

```cpp
template<typename T, typename... Types>
void print(const T& firstArg, const Types&... args) {
    // ...
}
```

The call argument pack expansion names two parameters, `T` and `Types`. When instantiating this template, the element type of each argument pack is substituted for the elements of the corresponding pack. The resulting argument list consists of N-1 items of types `T1, ..., TN-1`, where `T` is the type of `firstArg`. Under the intuitive interpretation of pack expansion, a three-argument function call would look like this:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_157_1.png)

```cpp
template<typename T, typename T1, typename T2, typename T3>
void print(const T& firstArg, const T1& arg1, const T2& arg2, const T3& arg3) {
    // ...
}
```

Pack expansions themselves may also be nested. In each case, each occurrence of a parameter pack is "expanded" by its nearest enclosing pack expansion (only that pack expansion). The following example illustrates a nested pack expansion involving three different parameter packs:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_157_2.png)

```cpp
template<typename... Types>
class Nested {
    public:
        template<typename... Inner>
        void f(const Inner&... innerValues) {
            g(printInnerValues(innerValues)...);
        }
};
```

In the call to `f`, the pack expansion with pattern `printInnerValues(innerValues)...` is the innermost pack expansion, which expands both `Inner` and `innerValues` and produces a sequence of arguments to be initialized from the object returned by `printInnerValues`. The outer pack expansion pattern includes the inner pack expansion. Thus, the outer pack expansion expands the `Types` and `Inner` packs and produces a comma-separated list of the sequences of arguments produced by the inner expansion. Under the intuitive interpretation of the pack expansion, where `innerValues` has two arguments and `Inner` has three, the following code is more apparent:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_157_3.png)

```cpp
template<typename... Types, typename... Inner>
void g(const Types&... args1, const Inner&... args2) {
    // ...
}
```

Multiple and nested pack expansions are a powerful tool (e.g., see Section 26.2.4 on page 618).

The intuitive interpretation of pack expansions can be a useful tool for understanding how an instantiation of a variadic template will behave with different numbers of arguments. However, this intuitive interpretation fails in the presence of zero-length argument packs. To illustrate this, consider the `count` function from Section 12.4.1 on page 612, arbitrarily substituted with zero arguments:

```cpp
template<typename... Types>
size_t count() {
    return sizeof...(Types);
}
```
