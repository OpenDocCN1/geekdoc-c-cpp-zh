# 22.6 PERFORMANCE CONSIDERATIONS

Type erasure provides some of the advantages of both static polymorphism and dynamic polymorphism, but not all. In particular, the performance of generated code using type erasure tends to be less than that of dynamic polymorphism, because both the dynamic dispatch via virtual functions. Thus, some of the traditional advantages of static polymorphism—speed, such as the ability of the compiler to inline calls, may be lost. Whether this loss of performance will be perceptible is application-dependent, but it’s often easy to tell by considering how much work is performed in the function being called relative to the cost of a virtual function call: If the two are close (e.g., using `Function<>` to simply add two integers), type erasure is likely to execute far more slowly than a static-polymorphic version. If, on the other hand, the function call performs a significant amount of work—querying a database, sorting a large input, or updating a user interface—the overhead of type erasure is unlikely to be measurable.

# 22.7 AFTERNOTES

Kevin Henney popularized type erasure in C++ with the introduction of the `Any` type (`Boost.Any`/`boost::any`), which later became a popular Boost library (`Boost.Any`) part of the C++ standard library with C++17. The technique was refined somewhat in the Boost.Function library, which applied virtual functions and type-erasure operations and eventually became `std::function`. However, each of the early libraries addressed only a single set of operations: any was a simple value type with only copy and a set of operations limited to invocation.

Later efforts, such as the Boost.TypeErasure library (`Boost.TypeErasure`) and Adobe’s Poly library (`AdobePoly`), apply template metaprogramming techniques to allow users to form a typesafe value with some specified list of capabilities. For example, the following type constructed using the Boost.TypeErasure library handles any construction, a type-erased-like criterion, and output streaming for printing:

  typeid_<>,
  ostreamable
