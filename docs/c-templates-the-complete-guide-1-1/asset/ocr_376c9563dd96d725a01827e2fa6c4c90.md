The `decltype` deduces the type of the expression, but it also propagates the value category of the expression to the caller of the function. For example, consider a simple forwarding function `g()` that returns the result of calling `f()`.

```
decltype(f()) g()
{
    return f();
}
```

The return type of `g()` depends on the return type of `f()`. If `f()` were to return an lvalue, the return type of `g()` would be an lvalue reference as well. This is because the expression `f()` is an lvalue, and therefore the `decltype` of the expression preserves that value category. Similarly, if the return type of `f()` were an rvalue reference, the return type of `g()` would be an rvalue reference. This can be especially useful when forwarding the result of a function.

`decltype` can also be useful when the value-producing `auto` deduction is not sufficient. For example, assume we have a variable `pos` of some unknown iterator type, and we want to use a variable `element` that refers to the element stored by `pos`. We could use:

```
decltype(auto) x = *pos;
```

However, this will always make `x` a copy of the element. If we instead try:

```
auto& element = *pos;
```

then we will always receive a reference to the element, but the program will fail if the element's `operator*` returns a value. To address this problem, we can use `decltype(auto)` so that the value- or reference-ness of the iterator's `operator*` is preserved:

```
decltype(auto) element = *pos;
```

This will use a reference when the iterator supports it and copy the value when the iterator does not. Its primary difference is that it requires the initializer expression to be written twice: once in the actual initializer and once in the `decltype` expression. C++14 introduces this `decltype(auto)` construct to address that issue.

# 5.10.3 decltype(auto)

C++14 adds a feature that is a combination of `auto` and `decltype`: `decltype(auto)`. Unlike the `auto` type specifier, it is a placeholder type, and the type of a variable, return type, or template argument is determined from the type of the expression. However, unlike `auto`, which uses the rules for template argument deduction to determine the type of interest, the actual type is determined by applying the `decltype` construct directly to the expression. An example illustrates this:

```
int i = 42;              // i has type int
int const& ref = i;      // ref has type int const& and is a
                         // reference to i
auto x = ref;            // x has type int and is a new
                         // independent copy
decltype(auto) y = ref;  // y has type int const& and
                         // also refers to i
```

The type of `y` is obtained by applying `decltype` to the initializer expression here, which is `int const&`. In contrast, the rules for `auto` type deduction produce `int`.

Another example shows the difference when indexing a `std::vector` (which produces an lvalue):

```
std::vector<int> v = { 4, 12 };
auto x = v[0];             // x denotes a new object of
                           // type int
decltype(auto) y = v[0];   // y is a reference (type int&)
```

This neatly addresses the redundancy in our previous example:

```
decltype(auto) element = *pos;
```
