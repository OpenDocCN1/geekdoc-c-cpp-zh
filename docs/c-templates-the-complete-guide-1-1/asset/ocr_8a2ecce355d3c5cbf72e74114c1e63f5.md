# 27.3 PERFORMANCE AND LIMITATIONS OF EXPRESSION TEMPLATES

To justify the complexity of the expression templates described here, we have analyzed the greatly enhanced performance on array-view operations. As you read what happens with the expression templates, you'll find that many small inline functions call each other and that many small expression template objects are allocated on the call stack. The optimizer must perform complete inlining and elimination of the small objects to produce the best performance as well as manually achieved. In the first edition of this book, we reported that few compilers could achieve such optimization. Since then, the situation has improved considerably, no doubt due in part to the fact that the technique has proven popular.

The expression templates technique does not resolve all the problematic situations involving numeric operations on arrays. For example, it does not work for matrix-vector multiplications of the form

`x = A*x;`

where x is a column vector of size n and A is an n×n matrix. The problem here is that a temporary must be used because each element of the result is computed from each element of the original. Unfortunately, the expression template technique cannot handle this situation: it must use the newly computed element to compute the second element, which is wrong. The slightly different expression

`x = A*y;`

on the other hand, does not need a temporary if x and y aren't aliases for each other, which implies that a solution would have to know the nature of the operands at run time. This in turn suggests creating a run-time structure that represents the expression tree instead of reducing it to operator overloading. The expression templates from the NewMat library of Robert Davies (see [NewMat]) are well known long before expression templates were developed.
