rules for determining whether a type refers to a current instantiation or an unknown specialization. In such cases, it is safest to simply add the type name keyword to indicate that you intend the qualified name that follows to be a type. The type name keyword, even if it's optional, will provide documentation of your intent.

# 13.3.3 Dependent Names of Templates

A problem very similar to the one encountered in the previous section occurs even when a name of a template is dependent. In general, a C++ compiler is required to treat a `::` following the name of a template as the beginning of a template argument list; otherwise, it is a less-than operator. As is the case with type names, a compiler has to assume that a dependent name does not refer to a template unless the programmer provides extra information using the keyword `template`.

Click here to view code image

```
template<typename T>
class Shell {
public:
    template<int N>
    class In {
    public:
        template<int M>
        class Deep {
        public:
            virtual void f() {};
        };
    };
};

template<typename T, int N>
class Weird {
public:
    void case1(
        Shell<T>::template In<N>::template
        Deep<>* p) {
        p->template Deep<0>::f(); // explicit virtual call
    }

    void case2(
        typename Shell<T>::template In<N>::template
        Deep<>* p) {
        p->template Deep<0>::f(); // explicit virtual call
    }
};
```

This somewhat intricate example shows how all the operators that can qualify a name (`.`, `->`, `::`, and `>`) may need to be followed by the keyword `template`. Specifically, this is the case whenever the type of the more or expression preceding the qualifying operator is dependent on a template parameter and refers to an unknown specialization, and the name that follows the operator is a template (in other words, a template name followed by template arguments using angle brackets). For example, in the expression

`p->template Deep<>f();`

the type of `p` depends on the template parameter `T`. Consequently, a C++ compiler cannot look up `Deep` to see if it is a template, and use must explicitly indicate that `Deep` is the template by inserting the prefix `template`. Without this prefix, `p->Deep<N>` is parsed as the less-than operator. Note also that this may need to happen multiple times within a qualified name because qualifiers themselves may be qualified with a dependent qualifier. (This is illustrated by the declaration of the parameters of `case1` and `case2` in the previous example.)

If the keyword `template` is omitted in cases such as these, the opening and closing angle brackets are parsed as less-than and greater-than operators. As with the `typename` keyword, one can safely add the `template` prefix to indicate that the following name is a template, even if the template prefix is not strictly needed.

# 13.3.4 Dependent Names in Using Declarations

Using declarations can bring in names from two places: namespaces and classes. The namespace case is not relevant in this context because there are no such things as namespace templates. Using declarations that bring in names from classes, on the other hand, can bring in names only from a derived class. Such using declarations behave like members of the derived class to access the base class members, allowing them to be accessed as if they were actually a member declared in that derived class. A short but important example illustrates the difference between these two versions:

```
class X {
public:
    void f(int);
    void f(char const*);
    void g();
};

class DX : private X {
public:
    using X::f;
};
```

The previous using declaration brings in the name `f` of the base class `X` into the derived class `DX`. In this case, this name is associated with two different declarations, thus emphasizing that we are dealing with a nondependent name. Note also that this kind of using declaration can also be used to introduce names into a class template. The base class `X` and its members are private to the class `DX`, except that the functions `f` have been introduced to the public interface of `DX` and are therefore available to the clients of `DX`.
