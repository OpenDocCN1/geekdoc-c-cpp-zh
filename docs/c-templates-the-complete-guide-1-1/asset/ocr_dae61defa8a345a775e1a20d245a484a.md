struct IsPrime<0> { static constexpr bool value = false; };

template<>
struct IsPrime<3> { static constexpr bool value = true; };

The `IsPrime<>` class template returns in its `value` whether the passed template parameter is a prime number. To achieve this, it instantiates `IsPrime<n>::value`, which recursively expands to an expression checking for each divisor between 2 and `p/2` whether this divisor divides the number without remainder.

For example, the expression

`IsPrime<9>::value`

expands to

`DoIsPrime<9,4>::value`

![](bbox=[0.08, 0.402, 0.78, 0.419])

`9%4 != 0 && DoIsPrime<9,3>::value`

which expands to

![](bbox=[0.08, 0.451, 0.78, 0.468])

`9%4 != 0 && 9%3 != 0 && DoIsPrime<9,2>::value`

which expands to

![](bbox=[0.08, 0.498, 0.78, 0.515])

`9%4 != 0 && 9%3 != 0 && 9%2 != 0`

which evaluates to `false`.

As this chain of instantiation demonstrates:

+   - We use recursion expansion of `DoIsPrime<>` to iterate over all divisors from 2 down to 2 to find out whether any of these divisors divide the given integer exactly, i.e. without remainder.
+   - The partial specialization of `DoIsPrime<>` for `d` equal to 2 serves as the criterion to end the recursion.

Note that all this is done at compile time. That is,

`IsPrime<9>::value`

expands to `false` at compile time.

The template syntax is arguably clumsy, but code similar to this has been valid since C++98 (and earlier) and has proven useful for quite a few libraries.

See Chapter 3 for details.

# 8.2 COMPUTING WITH CONSTEXPR

C++11 introduced a new feature, `constexpr`, that greatly simplifies various forms of compile-time computation. In particular, given proper input, a `constexpr` function can be evaluated at compile time. While C++11 `constexpr` functions were introduced with stringent limitations (e.g., each `constexpr` function definition was essentially limited to consist of a return statement), most of these restrictions were removed with C++14. Of course, successfully evaluating a `constexpr` function still requires that all computations steps be possible and valid at compile time. Currently, that excludes things like heap allocation or throwing exceptions.

Our example to test whether a number is a prime number could be implemented as follows in C++14:

![](bbox=[0.08, 0.898, 0.79, 0.915])

```
```cpp
constexpr bool
doIsPrime (unsigned p, unsigned d)  // p is number to check
{
    return d > 2 ? (p%d != 0 && doIsPrime(p,d-1))  // check
                 : (p%2 != 0);                     // end of recursion
}
```
