
```cpp
template<typename T1, typename T2>
using PlusResultT = typename PlusResult<T1, T2>::type;
```

Given these alias templates, we can simplify our `operator+` declaration down to

```cpp
template<typename T1, typename T2>
Array<PlusResultT<T1, T2>>
operator+(const Array<T1>&, const Array<T2>&);
```

This second version is clearly shorter and makes the composition of the traits more obvious. Such improvements make alias templates more suitable for some uses of type traits.

However, there are downsides to using alias templates for type traits:

- 1. Alias templates cannot be specialized (as noted in Section 16.3 on page 613), and since many of the techniques for writing traits depend on specialization, an alias template will likely need to defer to a class template anyway.
- 2. Some traits are meant to be specialized by users, such as a trait that describes whether a particular addition operation is commutative, and it can be confusing to specialize the class template when most uses involve the alias template.
- 3. The use of an alias template will always instantiate the type (e.g., the underlying class template specialization), which makes it harder to avoid instantiating traits that don't make sense for a given type (as discussed in Section 19.7 on page 493).

Another way to express this point, is that alias templates cannot be used with metafunction forwarding (see Section 19.3.2 on page 494).

Because the use of alias templates for type traits has both positive and negative aspects, we recommend using them as we have in this section and as it's done in the C++ standard library. Provide both class templates with a specific naming convention (we have chosen the suffix `_t`) and alias templates (with a slightly different naming convention (dropped the `_t` suffix)), and have each alias template defer to the underlying class template. This way, we can use alias templates wherever they provide clearer code, but fall back to class templates for whatever purpose.

Note that for historical reasons, the C++ standard library has a different convention. The type traits class templates yield a type and have no specific suffix (many were introduced in C++11). Corresponding alias templates (that produce the type directly) started being introduced in C++14, and were given a `_t` suffix, since the un-suffixed name was already standardized (see Section 19.4 on page 467).

### Variable Templates and Traits

Traits returning a value require a trait value. If a value is needed, it must be in a static data member variable (to produce the result of the trait). In this case, `constexpr` variable templates (introduced in Section 5.6 on page 80) offer a way to reduce the verbosity.

For example, the following variable templates wrap the `IsSame` trait defined in Section 19.5.9 on page 429 and the `IsConvertible` trait defined in Section 19.5.8 on page 428:

```cpp
template<typename T1, typename T2>
constexpr bool IsSame_v = IsSame<T1, T2>::value;

template<typename FROM, typename TO>
constexpr bool IsConvertible_v = IsConvertible<FROM, TO>::value;
```

Now we can simply write

```cpp
if (IsSame_v<T, int> || IsConvertible_v<T, char>) ...
```

instead of

```cpp
if (IsSame<T, int>::value ||
    IsConvertible<T, char>::value)
```

Again, for historical reasons, the C++ standard library has a different convention. The traits class templates yield a value member and have no specific suffix. The corresponding variable templates were introduced in C++17, with a `_v` suffix (see Section 19.3 on page 497).

## 19.8 TYPE CLASSIFICATION

It is sometimes useful to be able to know whether a template parameter is a built-in type, a pointer type, a class type, and so on. In the following sections, we develop a suite of type traits that allow us to determine various properties of a given type. As a result, we will be able to write code specific to the type.

```cpp
if (IsClass<T>::value) {
    ...
}
```

If using the compile-time `if` available since C++17 (see Section 5.8 on page 143) and the features for traits convenience (see Section 19.7.3 on page 446), we can write

```cpp
if constexpr (Classifier<T>::value) {
    ...
}
```

or, by using partial specializations

```cpp
template<typename T>
class Classifier<T, bool> : public Classifier<T>       // partial specialization for
{                                                      // the general case
};
```

Furthermore, expressions such as `IsDefaultConstructible<T>::value` will be Boolean constants that yield unique template arguments. This in turn enables powerful template metaprogramming and even some powerful templates that specialize their behavior on the properties of their type arguments.

The C++ standard library defines several similar traits to determine the primary and composite type categories of a type. See Section D.2.1 on page 782 and Section D.2.2 on page 785 for details.

### 19.8.1 Determining Fundamental Types

To start, let's develop a template to determine whether a type is a fundamental type. By default, a type is not fundamental, and we specialize the template for the fundamental types.

```cpp
template<typename T>      // primary template: in general T is not a fundamental type
struct IsFundaT : std::false_type {
};

// macro to specialize for fundamental types
#define MK_FUNDA_TYPE(T) \
  template<> struct IsFundaT<T> : std::true_type { \
  };

MK_FUNDA_TYPE(void)
MK_FUNDA_TYPE(bool)
MK_FUNDA_TYPE(char)
MK_FUNDA_TYPE(signed char)
MK_FUNDA_TYPE(unsigned char)
MK_FUNDA_TYPE(wchar_t)
MK_FUNDA_TYPE(char16_t)
MK_FUNDA_TYPE(char32_t)

MK_FUNDA_TYPE(signed short)
MK_FUNDA_TYPE(unsigned short)
MK_FUNDA_TYPE(signed int)
MK_FUNDA_TYPE(unsigned int)
MK_FUNDA_TYPE(signed long)
MK_FUNDA_TYPE(unsigned long)
MK_FUNDA_TYPE(signed long long)
MK_FUNDA_TYPE(unsigned long long)

MK_FUNDA_TYPE(float)
MK_FUNDA_TYPE(long double)
MK_FUNDA_TYPE(std::nullptr_t)

#undef MK_FUNDA_TYPE
```

The primary template defines the general case. That is, in general, `IsFundaT<T>::value` will evaluate to `false`.

```cpp
template<typename T>
struct IsFundaT : std::false_type {
    static constexpr bool value = false;
};
```

For each fundamental type, a specialization is defined so that `IsFundaT<T>::value` is true. We define a macro that expands to the necessary code for convenience. For example:

```cpp
MK_FUNDA_TYPE(bool)
```

expands to the following:

```cpp
template <> struct IsFundaT<bool> : std::true_type {
    static constexpr bool value = true;
};
```

The following program demonstrates a possible use of this template:

```cpp
#include "isfundamental.hpp"
#include <iostream>

template<typename T>
void test (T& t)
{
    if (IsFundaT<T>::value)
    {
        std::cout << "T is a fundamental type" << std::endl;
    }
    else
    {
        std::cout << "T is not a fundamental type" << std::endl;
    }
}

int main()
{
    test(7);
    test("Hello");
}
```

It has the following output:

```text
T is a fundamental type
T is not a fundamental type
```

In the same way, we can define type functions `IsIntegral` and `IsFloatingPoint` to identify which of these types are integral types and which are floating-point scalar types.

The C++ standard library uses a more fine-grained approach than only checking whether a type is a fundamental type. It first defines primary type categories, where each type matches exactly one type category (see Section 2.1.2 on page 103), and then composite type categories such as `std::is_integral` or `std::is_fundamental` (see Section 2.1.2 on page 76).
