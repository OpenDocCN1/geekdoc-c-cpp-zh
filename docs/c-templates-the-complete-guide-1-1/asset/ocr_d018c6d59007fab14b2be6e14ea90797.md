```
```cpp
int main()
{
    std::string s = "hello";

    printf(s);              // print s passed by value
    printf(std::ref(s));    // print s passed by ref
}
```
```

The last call passes by value an object of type `std::reference_wrapper`, which then passes the parameter to the underlying type. This is what happens when there are references left back to its underlying type.

Note that the compiler has to know what an implicit conversion back to the original type is necessary. For this reason, `std::ref()` and `std::cref()` usually only work with types for which an operator is defined.

Click here to view code image

```
```cpp
template<typename T>
void print(T& arg) {
    std::cout << arg << '\n';
}

std::string s = "hello";
print(s);                 // OK
print(std::ref(s));      // ERROR: no operator << for
                         // reference wrapper defined
```
```

Also, the following fails because you can't compare a reference wrapper with a char const*: `std::isstring`.

```

{

}

std::string s = "hello";

{

}

```
```

It also doesn't help to give `arg1` and `arg2` a common type `T`:

```
```cpp

{
    return arg1 < arg2;

```
```

because then the compiler gets conflicting types when trying to deduce `T` for `arg1` and `arg2`.

The final effect of data is: a reference-wrapper-argument is left to use as a reference as a first-class object, which you can copy and therefore pass by value to function templates. You can also use it in classes, for example, to hold references to objects in a container. But you always finally need a conversion back to the underlying type.

# 7.4 DEALING WITH STRING LITERALS AND RAW ARRAYS

So far, we have seen the different effects for template parameters when using string literals and raw arrays:

+   - Call-by-value decays so that they become pointers to the element type.
+   - Any form of call-by-reference does not decay so that the arguments become references that still refer to arrays.
+   - Both can be passed by value. When decaying array to pointers, you lose the ability to distinguish between handling pointers to elements from handling passed arrays.

Both can be passed by value. When decaying arrays to pointers, you lose the ability to distinguish between handling pointers to elements from handling passed arrays. On the other hand, when dealing with parameters whose arguments are literals, not decaying can become a problem, because string literals of different sizes have different types. For example:

Click here to view code image

```
```cpp
template<typename T>
void foo(T const& arg1, T const& arg2)
{
    ...
}

foo("hi", "guys"); // ERROR
```
```

Here, `foo("hi", "guys")` fails to compile, because `"hi"` has type `char[3]`, while `"guys"` has type `char[5]`. But the template requires them to have the same type `T`. Only if the string literals were to have the same length would code compile. For this reason, it is strongly recommended to use string literals of different lengths in test cases.
