## 15.10.1 THE AUTO TYPE SPECIFIER

The auto type specifier can be used in a number of places (primarily, namespace scopes and local scopes) to deduce the type of a variable from its initializer. In each case, auto is called a placeholder type specifier. (Placeholder type specifiers will be described a little later in Section 15.10.2 on page 284.) For example:

**Click here to view code image**

```cpp
template<typename Container>
void print(const Container& container)
{
    auto pos = container.begin();
    while (pos != container.end())
    {
        auto element = *pos++;
        // operate on the element
    }
}
```

The use of auto in the example above eliminated the need to write two long and potentially complicated types, the container's iterator type and the iterator's value type:

**Click here to view code image**

```cpp
typename Container::const_iterator pos = container.begin();
while (pos != container.end())
{
    typename std::iterator_traits<typename Container::const_iterator>::reference
        element = *pos++;
}
```

Deduction for auto uses the same mechanism as template argument deduction. The type specifier auto is replaced by an invented template type parameter T, then deduction proceeds as if the variable were a function parameter and its initializer the corresponding function argument. For the first auto example, that corresponds to the following situation:

**Click here to view code image**

```cpp
template<typename T>
void deduce(T pos)
{
    ...
}
```

where T is the type deduced for auto. One immediate consequence of this is that a variable of type auto will never be a reference type. The use of auto& in the second auto example illustrates how to produce a reference to a deduced type. Its deduction is equivalent to the following function template call:

**Click here to view code image**

```cpp
template<typename T> void deduce(T& pos);
deduce(pos);
```

Here, element will always be of reference type, and its initializer cannot produce a temporary.

It is also possible to combine auto with rvalue references, but doing so makes it behave like a forwarding reference, because that deduction model for

```cpp
auto&& f = ...;
```

is based on a function template:

**Click here to view code image**

```cpp
template<typename T> void f(T&& f); // auto replaced by template parameter T
```

That explains the following example:

**Click here to view code image**

```cpp
int x;
auto&& r = 42;    // OK: an rvalue reference binds to an
                    // rvalue

auto&& r2 = x;      // OK: an lvalue reference binds to an lvalue
```

This technique is frequently used in generic code to bind the result of a function or operator invocation whose value category (lvalue vs. rvalue) is known, without having to make a copy of that result. For example, it is often preferred to declare the iterating value in a for loop:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_209_0.png)

```cpp
template<typename T> struct X { T const m; };
struct Y {
    using T = int;
    Y() : m(7) { }
    Y(int) : m(0) { }
    auto get() const { return m; } // OK? see text
    T m;
};
```

There are no exceptional reasons why C++ could not support all the uses in this example, but the C++ committee felt that the benefits were outweighed by the additional implementation cost and the potential for abuse.

In order to avoid confusing both programmers and compilers, the old use of auto as a "storage class specifier" is no longer permitted in C++11 (and later standards).

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_209_1.png)

```cpp
auto i = 42; // i has type int
auto i = 42; // error: i has type int
auto i = 42; // i has type int
```

This old use of auto (inherited from C) is always redundant. Most compilers can usually diagnose that use from the use as a placeholder (even though they don't have to), offering a transition path from older C++ code to newer C++ code. The old use of auto is simply no longer in the language, however.

### DEDUCED RETURN TYPES

C++11 added another situation where a placeholder type can appear: function return types. For example:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_209_2.png)

```cpp
auto f(int x) -> decltype(x) { return x; }
```

defines a function with return type int (the type of x). This can be expressed by using a trailing return type syntax also:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_209_3.png)

```cpp
auto f(int x) -> int { return x; }
```

The next mechanism exists to handle lambdas: if no return type is specified explicitly, the lambda's return type is deduced as if it were `auto`.

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_209_4.png)

```cpp
auto l = [] (int i) { return i; }; // OK
```

Functions can be declared separately from their definition. This is true with functions whose return type is deduced also:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_209_5.png)

```cpp
auto f(); // forward declaration
auto f() { return 42; }
```

However, the forward declaration is of very limited use in a case like this. The function can only be called after it has been defined. Perhaps surprisingly, it is not even possible to forward declare a function with a 'deduced' return type. For example:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_209_6.png)

```cpp
auto known();
auto known() { return 42; } // ERROR: incompatible return type
```

Mostly, the ability to forward declare a function with a deduced return type is only useful to make a member function definition available without the full definition because of syntax preferences.

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_209_7.png)

```cpp
struct S {
    auto f(); // the definition will follow the class definition
};
auto S::f() { return 42; }
```

### DEDUCIBLE NONTYPE PARAMETERS

Prior to C++17, a nontype template argument had to be declared with a specific type. However, that type could be a template parameter type. For example:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_209_8.png)

```cpp
template<typename T, T v> struct X {
    static constexpr T value = v;
};
```

In this example, having to specify the type of the nontype template argument—that is, specifying T in addition to v—can be tedious. C++17 therefore adds the ability to deduce nontype template parameters whose actual types are deduced from the corresponding template arguments.

which enables

```cpp
template<auto N> struct X {
    static constexpr auto value = N;
};

X<42> x; // OK
```

Here the type of the `42` is deduced to be `int` because `42` has type `int` and the literal `0` has type `int`. The type of `word` would have been deduced to `unsigned` (see Section 10.4 on page 262) for the details of deducing a type for specific types.

Note that the precise constraints on the type of `auto` template parameter come into effect. For example:

**Click here to view code image**

```cpp
template<auto N> struct X { };

X<42> x; // OK
X<42.0> y; // error: floating-point value not allowed
```

A template definition with that kind of deducible template parameter is often called an explicit type of the corresponding argument. That is exactly what we do when using the declaration `auto` (see Section 15.10.2 on page 565) for example.

**Click here to view code image**

```cpp
template<auto N> struct MyClass;
MyClass<42> c; // OK
MyClass<42> c2; // OK
```

auto template parameters are also useful to parameterize template parameters of a class. For example:

**Click here to view code image**

```cpp
template<typename T, typename M = std::pair<T,T>>
class MyClass {
public:
    using Pair = M;
    MyClass(Pair& p) : p(p) {}
    MyClass(MyClass const&) = default;
    MyClass(MyClass&&) = default;
    MyClass& operator=(MyClass const&) = default;
    MyClass& operator=(MyClass&&) = default;
    ~MyClass() = default;
    void swap(MyClass& other) noexcept {
        std::swap(p, other.p);
    }
private:
    Pair p;
};
void swap(MyClass& a, MyClass& b) noexcept {
    a.swap(b);
}
```

Here we used a helper class template `MyClass` to retrieve from a pointer to member type `Ptr` a class type, using class template partial specialization (described in Section 16.4 on page 347). With an `auto` template parameter, you don't have to specify the type of the class template. The compiler will deduce it for you. For example:

**Click here to view code image**

```cpp
template<typename T>
struct MyClass<T, std::pair<T,T>> {
    using Type = T;
};
```

which is wonderfully and fully redundant.

As you'd expect, that feature can also be used for non-type template parameter.

**Click here to view code image**

```cpp
template<int, bool> struct Value;
Value<42, true> v; // OK
Value<42, false> v2; // error: ...
```

The explicit example shows that each template parameter element of the pack can be deduced to a distinct type. (See the section of partial specialization for details in Section 15.10 on page 565.) Note that the requirement to use the declaration is equivalent.
