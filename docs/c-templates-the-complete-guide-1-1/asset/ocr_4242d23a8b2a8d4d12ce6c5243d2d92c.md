{
};

using RemoveCV = typename RemoveCVT<T>::type;
```
```

There are two things to note with the definition of `RemoveCVT`. First, it is making use of both `RemoveConst<T>` and the related `RemoveVolatile<T>`, the first removing the volatile (if present) and then passing the resulting type to `RemoveConst<T>`. Second, it is using `remove_reference` forwarding in order to let `T` become a member from `RemoveConst<T>` rather than declaring its own `T` member. This means that it is essential to include the `<type_traits>` specialization. Here, metafunction forwarding is used simply to reduce the amount of typing in the definition of `RemoveCVT`. However, metafunction forwarding is also useful when the metafunction is not defined for all inputs, a technique that will be discussed further in Section 19.4 on page 416.

The C++ standard library also provides corresponding type traits: `std::remove_const<T>::type`, `std::remove_cv<T>::type`, and `std::remove_reference<T>::type`, which are described in Section 4 on page 48.

# Decay

To round out our discussion of transformation traits, we develop a trait that mimics type conversions when passing arguments to parameters by value. Derived from C++, this means that the arguments decay (1) any type into pointers and function types into pointer-to-function types (see Section 7.4 on page 115 and Section 13.1.1 on page 159) and delete any top-level const, volatile, or reference qualifiers (because top-level type qualifiers on parameter types are ignored when resolving a function call).

The effect of this pass-by-value can be seen in the following program, which prints the actual parameter type produced after the compiler decays the specified type:
