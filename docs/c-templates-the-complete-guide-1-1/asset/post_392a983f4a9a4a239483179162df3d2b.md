
Note that declaring `ret` with `auto&` is not correct. As a reference, `auto&&` extends the lifetime of the returned value until the end of its scope (see Section 11.3.1 on page 167) but not beyond the `return` statement to the caller of the function.

However, there is also a problem with using `decltype(auto)`: If the callable has return type `void`, the initialization of `ret` as `decltype(auto)` is not allowed, because `void` is an incomplete type. You have the following options:

- Declare an object before that statement, whose destructor performs the observable behavior that we want to realize. For example:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_131_0.png)

```cpp
struct cleanup {
    ~cleanup() {
        // code to perform a return
    }
} dummy;

return std::invoke(std::forward<Callable>(op),
                   std::forward<Args>(args)...);
```

- Implement the `void` and non-void cases differently:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_131_1.png)

```cpp
#include <utility>       // for std::forward()
#include <functional>    // for std::invoke()
#include <type_traits>   // for std::is_void_v

template<typename Callable, typename... Args>
decltype(auto) call(Callable op, Args&&... args)
{
    if constexpr (std::is_same_v<std::invoke_result_t<Callable, Args...>, void>) {
        // return type is void:
        std::invoke(std::forward<Callable>(op),
                    std::forward<Args>(args)...);
        return;
    }
    else {
        // return type is not void:
        decltype(auto) ret{std::invoke(std::forward<Callable>(op),
                                       std::forward<Args>(args)...)};
        return ret;
    }
}
```

With

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_131_2.png)

```cpp
if constexpr (std::is_same_v<std::invoke_result_t<Callable, Args...>, void>) {
    ...
}
```

we test at compile time whether the return type of calling `callable` with `Args...` is `void`. See Section 13.1.1 on page 717 for details about `std::invoke_result_t`.

Future C++ versions might hopefully avoid the need for such special handling of `void` (see Section 17.?? on page 304).

## 11.2 OTHER UTILITIES TO IMPLEMENT GENERIC LIBRARIES

`std::invoke()` is just one example of useful utilities provided by the C++ standard library for implementing generic libraries. In what follows, we survey some other important ones.

### 11.2.1 Type Traits

The standard library provides a variety of utilities called type traits that allow us to evaluate and modify types. This supports various cases where generic code has to adapt to or react on the capabilities of the types for which they are instantiated.

```cpp
template<typename T>
class C
{
    // ensure that T is not void (ignoring const or
    // volatile):
    static_assert(!std::is_same_v<std::remove_cv_t<T>,
                                  void>);

    public:
        template<typename U>
        void f(U&& arg)
        {
            if constexpr (std::is_reference_v<T>) {
                // special code if T is a reference type
            }
            if constexpr (std::is_convertible_v<T, U>) {
                // special code if T is convertible to U
            }
            if constexpr (std::has_virtual_destructor_v<T>) {
                // special code if T has virtual destructor
            }
        }
};
```

As this example demonstrates, by checking certain conditions we can choose between different implementations of the template. Here, we use the compile-time if constexpr, which is available since C++17 (from 8.5 on page 134), but we could have used std::enable_if, partial specialization, or SFINAE to enable or disable helper templates instead (see Chapter 8 for details).

However, note that type traits must be used with particular care: They might have different behavior than the naive programmer might expect. For example:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_132_0.png)

```cpp
std::remove_const_t<const int&>    // yields const int&
std::remove_cv_t<const int&>       // yields const int&
```

Here, because a reference is not const (although you can't modify it), the call has no effect and yields the passed type.

As a consequence, the order of removing references and cv-qualifiers matters:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_132_1.png)

```cpp
std::remove_const_t<std::remove_reference_t<const int&>>
```

Instead, you might call just

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_132_2.png)

```cpp
std::decay_t<const int&>       // yields int
```

which, however, would also convert arrays and functions to the corresponding pointer types.

Also there are cases where type traits have requirements. Not satisfying those requirements results in undefined behavior. For example:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_132_3.png)

```cpp
make_unsigned_t<int>        // unsigned int
make_unsigned_t<const int>  // undefined behavior
```

Sometimes the result may be surprising. For example:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_132_4.png)

```cpp
add_cvref_t<int>                 // int
add_cvref_t<const int>           // const int&
add_cvref_t<volatile int>        // volatile int&
add_cvref_t<const volatile int>  // const volatile int&
```

Here we might expect that add_cvref always results in an lvalue reference, but the reference-collapsing rules of C++ (see Section 9.5.6, on page 273) cause the combination of an lvalue reference and an rvalue reference to produce an lvalue reference.

### 11.2.2 STD::ADDRESSOF()

The std::addressof() function template can reliably yield the actual address of an object or function. It works even if the object type has an overloaded operator &. Even though the latter is somewhat rare, it might happen (e.g., in smart pointers). Thus, it is recommended to use std::addressof() if you need an address of an object of arbitrary type:

Click here to view code image

```cpp
template<typename T>
void f (T x)
{
    auto p = &x;                  // might fail with overloaded operator &
    auto q =
        std::addressof(x);        // works even with
                                  // overloaded operator &
}
```

### 11.2.3 STD::DECLVAL()

The std::declval() function template can be used as a placeholder for an object reference of a specific type. The function doesn't have a definition and therefore cannot be called (and doesn't create an object). Hence, it can only be used in unevaluated operands (such as those of decltype and sizeof constructs). So, instead of trying to create an object, you can assume you have an object of the corresponding type.

For example, the following declaration deduces the default return type RT from the passed template parameters T1 and T2:

Click here to view code image

```cpp
#include <utility>

template<typename T1, typename T2>
using RT = decltype(std::declval<T1>()
                    + std::declval<T2>());

template<typename T1, typename T2>
RT max (T1 t1, T2 t2)
{
    return t1 < t2 ? t2 : t1;
}
```

To avoid that we have to call a (default) constructor for T1 and T2 to be able to call operator + in the expression in the type alias RT, we use std::declval() to "use" objects of the corresponding types without creating them. This is only possible in the unevaluated context of decltype, though.

Don't forget to use the std::declval<> function template to ensure the default return type can be a reference, because std::declval<T>() yields a value or reference. Otherwise, calls such as max (1, 2) will get a return type of int&.

## 11.3 PERFECT FORWARDING TEMPORARIES

As shown in Section 6.1 on page 91, we can use forwarding references and std::forward<> to "perfectly forward" generic parameters:

Click here to view code image

```cpp
template<typename T>
void f (T&& t)                 // t is a forwarding reference
{
    g(std::forward<T>(t));     // perfectly forward
}
```

However, sometimes we have to perfectly forward data in generic code that does not come from a parameter. In that case, we can use std::move to create a variable that can be forwarded. Assume, for example, that we have chained calls to functions get() and set() (where the return value of get() should be perfectly forwarded to set()):

Click here to view code image

```cpp
template<typename T>
void f(T t)
{
    auto&& val = t.get();
    t.set(std::move(val));
}
```
