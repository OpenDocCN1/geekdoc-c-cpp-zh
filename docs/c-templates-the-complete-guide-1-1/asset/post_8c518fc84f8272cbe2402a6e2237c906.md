
```cpp
int(std::forward<decltype(val)>(val));
```

This avoids extraneous copies of the intermediate value.

### 11.4 REFERENCES AS TEMPLATE PARAMETERS

Although it is uncommon, template parameters can become reference types. For example:

Click here to view code image

Example/printparam3.cpp

```cpp
#include <iostream>

template<typename T>
void printParamReference(T& t)
{
    std::cout << "T is reference: " << std::boolalpha <<
        std::is_reference_v<T> << '\n';
}

int main()
{
    std::cout << std::boolalpha;

    int i;

    int& r = i;
    printParamReference(i);       // false
    printParamReference(r);       // false
    printParamReference<int&>(i); // true
    printParamReference<int&>(r); // true
}
```

Normally, if a reference variable is passed to printParamReference(), the template parameter T is deduced to the type of the referenced type (because, for a reference variable, the expression has the referenced type). The type of the expression is not a reference. However, we can force this behavior by explicitly specifying the template:

```cpp
printParamReference<int&>(i);
printParamReference<int&>(r);
```

Doing this can fundamentally change the behavior of a template, and, as likely as not, a template may not have been designed with this possibility in mind, thereby triggering errors or unexpected behavior. Consider the following example:

Click here to view code image

basics/reference.cpp

```cpp
template<typename T, T Z = T{}>
class RefMem {
private:
    T zero;
public:
    RefMem() : zero{Z} {
    }
};

int null = 0;

int main()
{
    RefMem<int> rm1, rm2;
    rm1 = rm2;             // OK

    RefMem<int&> rm3;      // ERROR: invalid default value
    RefMem<int&, 0> rm4;   // ERROR: invalid default value

    extern int null;
    RefMem<int&, null> rm5, rm6;
    rm5 = rm6;             // ERROR: operator= is deleted
}
```

The class `RefMem` is parameterized with a non-type template parameter `T` that has a zero-initialized default value. Instantiating the class with type `int` works as expected. However, when trying to instantiate it with a reference, things become tricky:

- The default initialization no longer works.
- You can no longer pass just a `0` initializer for an `int`.
- And, perhaps most surprising, the assignment operator is no longer available because classes with nonstatic reference members have deleted default assignment operators.

Also, using reference types for non-type template parameters is tricky and can be dangerous. Consider this example:

Click here to view code image

`basics/reference2.cpp`

```cpp
#include <vector>
#include <iostream>

template<typename T, int& S>        // Note: size is a reference
class Arr {
private:
    std::vector<T> elems;
public:
    Arr() : elems(S)                  // use current size as the size
    {
    }

    void print() const {
        for (int i=0; i<S; ++i)       // loop over S elements
            std::cout << elems[i];
    }
};

int size = 10;

int main()
{
    Arr<int,size> y;                  // compile-time ERROR deep in the code
                                      // of class std::vector

    Arr<int,&size> x;                 // initializes internal vector with 10 elements
    x.print();                        // OK
    size += 100;                      // OOPS: modifies S in Arr<>
    x.print();                        // run-time ERROR: invalid memory access
}
```

Here, the attempt to instantiate `Arr` for elements of a reference type results in an error due to the code shown in `std::vector`, because it can be instantiated with references as elements:

Click here to view code image

```cpp
Arr<int,size> y;   // compile-time ERROR deep in the code of class std::vector
```

The error often leads to the "error novel" described in Section 9.4 on page 143, where the compiler provides the entire template instantiation history from the initial use of the instantiation down to the actual template definition in which the error was detected.

Click here to view code image

```cpp
template<typename T> ...
class A;
```

Using decltype to obtain a certain class's member types and their values is generally avoided in this context (use auto by default). See Section 9.3.1.3 on page 302 for details.

The C++ standard library for this reason sometimes has surprising specifications and constraints. For example:

- In order to fill in a few assignment operator in the template parameters are instantiated for references, classes, etc.:

Click here to view code image

```cpp
namespace std {
    template<typename T> typename ...
    struct pair {
        T first;
        T second;
        // ...
    };

    // default copy constructors are OK when ...
    references:
    pair<...> = default;
    pair<pair<...>> = default;

    // but assignment operators have to be defined to be
    // available with references:
    pair& operator=(pair const& p);
    pair& operator=(pair& p);
};
```

Because of the possibility of side effects, instantiation of the C++ standard library class templates std::optional and std::variant is often preferable to std::tuple, at least in C++17.

To disallow references, a simple static assertion is enough

Click here to view code image

```cpp
template<typename T>
class optional {
    static_assert(!std::is_reference<T>::value,
        "Invalid instantiation of optional<T> for reference");
    ...
};
```

Reference types in general are quite different from object types and subject to several unique language rules. This impacts, for example, the declaration of call parameters (see Section 9 on page 103) and also the way we define the traits (see Section 14.6 on page 435).

### 11.5 DEFER EVALUATIONS

When implementing templates, sometimes the question comes up whether the code can deal with incomplete types (see Section 10.3.1 on page 543). Consider the following class template:

Click here to view code image

```cpp
template<typename T>
class C {
private:
    T* elems;
public:
    ...;
};
```

So far, this class can be used with incomplete types. This is useful, for example, with classes that refer to elements of their own type:

Click here to view code image

```cpp
struct Node
{
    std::string value;
    Node* Child;        // only possible if Cont accepts incomplete type
};
```

However, for example, just by using some traits, you might lose the ability to deal with incomplete types. For example:

Click here to view code image

```cpp
template<typename T>
class C {
private:
    T* elems;
public:
    typename std::conditional<std::is_move_constructible<T>::value,
        T&,
        T>::type
    foo();
};
```

Here, we use the trait `std::conditional` (see Section 5.8 on page 254).

³ There was a proposal for C++17 to require that violations of preconditions of type traits must always result in a compile-time error. However, because some type traits have over-constraining requirements, such as always requiring complete types, this change was postponed.
