
The full specialization declaration can omit explicit template arguments when the template being specialized can be determined via argument deduction (using as argument types the parameter types specified in the declaration) and partial ordering. For example:

Click here to view code image:

```cpp
template<typename T>
int f(T) {                    // #1

    return 1;
}

template<typename T>
int f(T*) {                   // #2

    return 2;
}

template<> int f(int) {      // OK: specialization of #1

    return 3;
}

template<> int f(int*) {     // OK: specialization of #2

    return 4;
}
```

A full function template specialization cannot include default argument values. However, any default arguments that were specified for the template being specialized remain applicable to the explicit specialization:

Click here to view code image:

```cpp
template<typename T>
int f(T, T = 42)
{
    return x;
}

template<> int f(int, int = 35)   // ERROR
{
    return 0;
}
```

(That's because a full specialization provides an alternative definition, but not an alternative declaration. At the point of a call to a function template, the call is entirely resolved based on the function template.)

A full specialization is in many ways similar to a normal declaration (or rather, a normal redeclaration). In particular, it does not declare a template, and therefore only the declaration of a function with a nominal function type is appropriate. However, we must still ensure that a declaration of the full specialization follows the template to which it belongs in order to prevent attempts at instantiating the function template. The declarations for a template g() and one full specialization would therefore typically be organized in two files as follows:

- The interface file contains the definition of the primary template and partial specialization but declares only the full specializations:

  Click here to view code image:

  ```cpp
  #ifndef TEMPLATE_G_HPP
  #define TEMPLATE_G_HPP

  // template declaration should appear in header file?
  template<typename T>
  int g(T, T = 42);

  // specialization declarations should appear in header file
  template<> int g(int, int);

  #endif // TEMPLATE_G_HPP
  ```

- The corresponding implementation file defines the full specialization:

  Click here to view code image:

  ```cpp
  #include "template_g.hpp"

  template<> int g(int, int)
  {
      return y/2;
  }
  ```

Alternatively, the specialization could be made inline, in which case its definition can (and should be) placed in the header file.

### 16.3.3 Full Variable Template Specialization

Variable templates can also be fully specialized. By now, the syntax should be intuitive:

Click here to view code image:

```cpp
template<typename T> constexpr std::size_t sz = sizeof(T);
template<> constexpr std::size_t sz<int> = sizeof(int);
```

Clearly, the specialization can provide an initializer that is distinct from that resulting from the template:

```cpp
template<typename T> typename T::iterator
...
template<typename T> typename T::const_iterator
...
etc. and this is fine.
```

### 16.3.4 Full Member Specialization

Not only member templates, but also ordinary static data members and member functions of class templates, can be fully specialized. The syntax requires `template<>` prefix for every enclosing class template. If a member template is being specialized, a `template<>` must also be added to denote that it is being specialized. To illustrate the implications of this, let’s assume the following declarations:

Click here to view code image

```cpp
template<typename T>
class Outer {                         // #2
public:
  template<typename U>
  class Inner {                       // #2
  private:
    static int count;                 // #3
  public:
    static int code;                  // #4
    void print() const                // #5
    {
      std::cout << "generic";
    }
  };
};

template<typename T>
int Outer<T>::code = 6;                // #6

template<typename T>
template<>
int Outer<T>::Inner<int>::count = 7;   // #7
```

Click here to view code image

```cpp
template<>
class Outer<bool> {                   // #8
public:
  template<typename U>
  class Inner {                         // #10
  private:
    static int count;
  public:
    void print() const                  // #12
    {
      std::cout << "bool";
    }
  };
};
```

The ordinary members code at point #4 and `print()` at point #5 of the generic `Outer` template are members of a single enclosing class template and hence need one `template<>` prefix to specialize them fully for a specific set of template arguments:

Click here to view code image:

```cpp
template<>
int Outer<void>::code = 12;

template<>
void Outer<void>::print() const
{
  std::cout << "Outer<void>";
}
```

These definitions are used over the generic ones at points #4 and #5 for class `Outer<void>`, but other members of class `Outer<void>` are still generated from the template at point #1. Note that these definitions, as usual, do not make it legal to provide an explicit specialization for `Outer<void>`.

Just as with full function template specializations, we need a way to declare the specialization of an ordinary member of a class template without specifying a definition (to prevent multiple definitions). Although non-defining, an explicit specialization declaration is allowed in C++ for member functions and static data members of non-local class templates; they are often used by declaring them as members of an explicitly specialized class template. The previous definitions could be declared with the following:

Click here to view code image:

```cpp
template<>
int Outer<void>::code;

template<>
void Outer<void>::print() const;
```

The attentive reader might point out that the nondefining declaration of the full specialization of `Outer<void>::code` looks exactly like a definition to be initialized with a default constructor. This is indeed so, but such declarations are always interpreted as nondefining declarations. For a full specialization of a static data member with a type that can only be initialized using a default constructor, we must resort to initializer list syntax. Given the following:

Click here to view code image:

```cpp
class DefaultInitOnly
{
public:
  DefaultInitOnly() = default;
  DefaultInitOnly(const DefaultInitOnly&) = delete;
};

template<typename T>
class Static {
  ...
};
```

Click here to view code image:

```cpp
template<>
DefaultInitOnlyTraits Action<DefaultInitOnlyTraits>::?;
```

while the following is a definition that calls the default constructor

Click here to view code image:

```cpp
template<>
DefaultInitOnlyTraits Action<DefaultInitOnlyTraits>::? {};
```

Prior to C++11, this was not possible. Default initialization was not available for such specializations. Typically, an initializer copying a default value was used.

Click here to view code image:

```cpp
template<>
DefaultInitOnlyTraits Action<DefaultInitOnlyTraits>::? {}
```

Unfortunately, for example, that was not possible because the copy constructor is deleted. However, C++17 introduced mandatory copy-elision rules, which make that alternative valid, because no copy construction is involved anymore.

The member template `Outer<X>::Inner` can also be specialized for a given template argument without affecting the other members of the specialization of `Outer<>`. Such a member specialization must occur outside the class template. Again, because there is no enclosing template, we will need one `template<>` prefix. This results in code like the following:

```cpp
template<>
template<typename X>
class Outer<X>::Inner {
public:
    enum { count = 1 };
};

// the following is not valid C++:

// template<> cannot follow a template parameter list

template<typename X>
long Outer<X>::Inner<X>::count;
```

The template `Outer<X>::Inner` can also be fully specialized, but only for a given instance of `Outer<X>`. We now need two `template<>` prefixes: one because of the enclosing class and one because we're fully specializing the (inner) template:

Click here to view code image:

```cpp
template<>
template<>
class Outer<>::Inner<> {
public:
    enum { count = 2 };
};
```

## 16.4 PARTIAL CLASS TEMPLATE SPECIALIZATION

Full template specialization is often useful, but sometimes it is natural to want to specialize a class template or suitable template for a family of template arguments rather than just one specific set of template arguments. For example, let's assume we have a class template implementing a linked list:

Click here to view code image:

```cpp
template<typename T>
class List {             // #2
public:
    void append(T const&);
    inline std::size_t length() const;
};
```

A large project making use of this template may instantiate its members
