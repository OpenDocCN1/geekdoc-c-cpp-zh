
The following examples show which template is used by which specialization:

**Click here to view code image**

```cpp
MyClass<int, float> x;          // error: MyClass<T1,T2>
MyClass<int, float> a;          // error: MyClass<T>
MyClass<int, float, int> b;     // error: MyClass<T,T>
```

If more than one partial specialization matches equally well, the specialization is ambiguous:

**Click here to view code image**

```cpp
MyClass<int, int> x;            // ERROR: matches
MyClass<T, T>                    // and
MyClass<T, int>                  // ERROR: matches
MyClass<T, T>                    // and
MyClass<T, T*>
```

To resolve the second ambiguity, you could provide an additional partial specialization for pointers of the same type:

**Click here to view code image**

```cpp
template<typename T>
class MyClass<T*, T*> {
    ...
};
```

For details of partial specialization, see Section 16.4 on page 347.

## 2.7 DEFAULT CLASS TEMPLATE ARGUMENTS

As for function templates, you can define default values for class template parameters. For example, in Listing 16.2 you can define the container that is used to manage the elements as a second template parameter, using its default value as the default value:

**Click here to view code image**

```cpp
#include <vector>
#include <cassert>

template<typename T, typename Cont = std::vector<T> >
class Stack {
  private:
    Cont elems;                 // elements

  public:
    void push(T const& elem);   // push element
    void pop();                 // pop element
    T const& top() const;       // return top element
    bool empty() const {
      return elems.empty();
    }
};

template<typename T, typename Cont>
void Stack<T, Cont>::push(T const& elem)
{
  elems.push_back(elem);        // append copy of elem
}

template<typename T, typename Cont>
void Stack<T, Cont>::pop()
{
  assert(!elems.empty());
  elems.pop_back();             // remove last element
}

template<typename T, typename Cont>
T const& Stack<T, Cont>::top() const
{
    assert(!elems.empty());
    return elems.back();        // return copy of last element
}
```

Notice that we now have two template parameters, so each definition of a member function must be defined with these two parameters:

**Click here to view code image**

```cpp
template<typename T, typename Cont>
void Stack<T, Cont>::push (T const& elem)
{
    elems.push_back(elem);      // append copy of passed element
}
```

You can use this stack the same way it was used before. Thus, if you pass a first and only argument as an element type, a vector is used to manage the elements of this type:

**Click here to view code image**

```cpp
template<typename T, typename Cont = std::vector<T>>
class Stack
{
private:
    Cont elems;        // elements
};
```

In addition, you could specify the container for the elements when you declare a Stack object in your program:

**Click here to view code image**

```cpp
#include "stack1.hpp"

#include <iostream>

#include <deque>

int main()
{
    // stack of ints
    Stack<int> intStack;

    // stack of doubles using a std::deque<> to manage
    Stack<double,std::deque<double>> dblStack;

    // manipulate int stack
    intStack.push(7);
    std::cout << intStack.top() << '\n';
    intStack.pop();

    // manipulate double stack
    dblStack.push(42.42);
    std::cout << dblStack.top() << '\n';
    dblStack.pop();
}
```

With

**Click here to view code image**

```cpp

```

you declare a stack for doubles that uses a std::deque<> to manage the elements internally.

### Typedefs and Alias Declaration

To simply define a new name for a complete type, there are two ways to do it:

- 1. By using the keyword `typedef`:

Click here to view code image

```cpp

void foo (IntStack const& si);      // is a stack of
IntStack intStack[10];              // a stack array of 10
stacks of int
```

We call this declaration a typedef and the resulting name is called a typedef-name.

- 2. By using the keyword using (since C++11):

Click here to view code image

```cpp
using IntStack = Stack<int>;        // alias declaration
void foo (IntStack const& si);      // is a stack of
IntStack intStack[10];              // a stack array of 10
stacks of int
```

Introduced by [Dcl.spec.alias]/[Dcl.spec.alias.templates], this is called an alias declaration.

Note that in both cases we define a new name for an existing type rather than a new type. Thus, after the typedef

Click here to view code image

```cpp
typedef Stack<int> IntStack;
```

or

Click here to view code image

```cpp
using IntStack = Stack<int>;
```

`IntStack` and `Stack<int>` are two interchangeable notations for the same type.

As a common term for both alternatives to define a new name for an existing type, we use the term type alias declaration. The new name is a type alias.

Because it is more readable (always having the defined type name on the left side of the — for the remainder of this book, we prefer the alias declaration rather than syntax with typedef.

### Alias Templates

Unlike a typedef, an alias declaration can be templated to provide a convenient name for a family of types. This is also available since C++11 and is called an alias template.

The following alias template is parametrized over the element type T; it expands to a Stack that stores its elements in a std::deque:

Click here to view code image

```cpp
template<typename T>
using DequeStack = Stack<T, std::deque<T>>;
```

Thus, both class templates and alias templates can be used as parameterized types. However, an alias template simply gives you a new name to an existing type, which can still be used. Both `DequeStack<int>` and `Stack<int, std::deque<int>>` represent the same type.

Note again that, in general, templates can only be declared and defined in global/namespace scope or inside class declarations.

## 2.9 CLASS TEMPLATE ARGUMENT DEDUCTION

Until C++17, you always had to pass all template parameter types to class templates (unless they have default values). Since C++17+, the restriction that you always had to specify the template arguments explicitly was relaxed. Instead, you can skip defining the template arguments explicitly, if the constructor is able to deduce all template parameters (that don't have a default value).

For example, in all previous code examples, you can use a copy constructor without specifying the template arguments:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_47_3.png)

```cpp
template <typename T>
class Stack {
private:
    Stack() = default;                 // elements
    Stack (const T& elem);              // initialize stack
                                        // with one element
    ...
};
```

By providing constructors that pass some initial arguments, you can specify deduction of the element type of a stack. For example, we could provide a stack that is initialized by a single element:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_47_4.png)

```cpp
template<typename T>
class Stack {
private:
    std::vector<T> elems;              // elements
public:
    Stack() = default;
    Stack(T const& elem)                // initialize stack
      : elems{elem} { }
    ...
};
```

This allows you to declare a stack as follows:

![](img/58b3b6b55f5326ebb5db11acf6ac18cf_47_5.png)

```cpp
Stack<int> stack1;                 // Stack<int> deduced
since C++17
```

By initializing stack with the integer 0, the template parameter T is deduced to int, so that a Stack<int> is instantiated.

Note the following:

- Due to the definition of the init constructor, you have to request the default constructor to be available with its default behavior, because the default constructor is available only if no other constructor is available:

  `Stack() = default;`

- The argument `elem` is passed to `elems` with braces around to initialize the vector `elems` with an initializer list with `elems` as the only argument:

  `: elems{elem}`

There is no constructor for a vector that is able to take a single parameter as initial element directly.

Note that, unlike for function templates, class template arguments may not be deduced only partially (they explicitly specify only some of the template arguments). See Section 15.12 on page 934 for details.
