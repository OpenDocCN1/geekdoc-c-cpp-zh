These compilers then used well over 10,000 characters for `Trouble<...LongType>`. Never C++ implementation take into account the fact that nested template-like are fairly common in modern C++ programs and use clever comparison techniques to reduce considerably the growth in name encoding (e.g., a fun hundred characters for `Trouble<...LongType>`). These newer compilers also avoid generating a mangled name if one is actually needed because no level-of-code is actually generated because no low-level code is actually generated if the template instance is not used.

# 23.6 ENUMERATION VALUES VERSUS STATIC CONSTANTS

In the early days of C++, enumeration values were the only mechanism to create "true constants" (called constant-expression as named members in class declarations). With them, you could, for example, define a `Pow3` metaprogram to compute powers of 3 as follows:

Click here to view code image

static/pow3enum.hpp

```
```cpp
// primary template to compute 3 to the Nth
template<int N>
struct Pow3 {
    enum { value = 3 * Pow3<N-1>::value };
};

// full specialization to end the recursion
template<>
struct Pow3<0> {
    enum { value = 1 };
};
```
```

The standardization of C++98 introduced the concept of in-class static constant initializers, so that our `Pow3` metaprogram could look as follows:

Click here to view code image

static/pow3const.hpp

```
```cpp
// primary template to compute 3 to the Nth
template<int N>
struct Pow3 {
    static int const value = 3 * Pow3<N-1>::value;
};

// full specialization to end the recursion
template<>
struct Pow3<0> {
    static int const value = 1;
};
```
```

However, there is a drawback with this version: Static constant members are values (see Appendix B). So, if we have a declaration such as

```cpp
void foo(int const&);
```

and we pass it the result of a metaprogram:

```cpp
foo(Pow3<5>::value);
```

a compiler must pass the address of `Pow3<5>::value`, and that forces the compiler to instantiate and allocate the definition for the static member. As a result, the programmer is no longer limited to a "compile-time" effort.

Enumeration values aren't lvalues (i.e., they don't have an address). So, when we pass them by reference, no static memory is used. It's almost exactly as if you passed the computed value as a literal. The first edition of this book therefore preferred the use of enumerator constants for this kind of applications.

C++11, however, introduced `constexpr` static data members, and those can be initialized by integral types. They do not have the address issue raised above, but in spite of that shortcoming they are now a common way to produce results of metaprograms. They have the advantage of having a property as opposed to an artificial enum type, and that type can be deduced when the static member is declared with the `auto` type specifier. C++17 added inline static data members, which solve the address issue raised above, and can be used in conjunction with constant expressions.
