# The explicit Keyword

A deduction guide can be declared with the keyword `explicit`. It is then considered only for direct-initialization cases, not for copy-initialization cases. For example:

Click here to view code image

```
```cpp
template<typename T> struct X {
  X(T const&);
};

template<typename T> explicit X(T) -> X<T>;  // #1
```
```

```
```cpp
X x1 = 1;   // only considers #2 or no? first, leads x1
X x2{1};    // prefers #1
```
```

Note how the initialization of `x1` is copy-initialization, and therefore the deduction guide `#1` is not considered because it is declared explicit.

# Copy Construction and Initializer Lists

Consider the following class template:

Click here to view code image

```
```cpp
template<typename T> struct Tuple {
  Tuple(T...);
  Tuple(T const&);
};
```
```

To understand the effect of the implicit guides, let's write them as explicit declarations:

Click here to view code image

```
```cpp
template<typename T> Tuple(T) -> Tuple<T>;
template<typename T> Tuple(Tuple<T> const&) -> Tuple<T>;
```
```

Now consider the same example:

```
```cpp
auto x = Tuple(1, 2);
```
```

This clearly selects the first guide and therefore the first constructor: `x` is therefore a `Tuple<int, int>`. Let's continue with some examples that use syntax that is suggestive of copy-initialization:

```
```cpp
Tuple a = x;
Tuple b(x);
```
```

For both `a` and `b`, both guides match. The first guide selects the type `Tuple<T...>`, but `x` has the guide associated with the copy constructor produces `Tuple<int, int>`. Fortunately, the second guide is a better match, and therefore both `a` and `b` are copy-constructed from `x`.

Now, consider some examples using braced initializer lists:

```
```cpp
Tuple c{x, x};
Tuple d{x};
```
```

The first of these examples (`c`) can only match the first guide, and so produces a `Tuple<Tuple<int, int>, Tuple<int, int>>`. That is entirely intuitive and not a surprise. The second example (`d`), however, is treated as a copy of `x` because `Tuple<T> const&` is preferred. This also happens with functional-notation casts:

```
```cpp
auto z = Tuple(x);
```
```

Here, `x` is declared to be a `Tuple<int, int>`, not a `Tuple<Tuple<int, int>>`.

# Guides Are for Deduction Only

Deduction guides are not function templates: They are only used to determine template parameters and are not called. That means that the difference between passing arguments by reference or by value is not important for guiding declarations. For example:

Click here to view code image

```
```cpp
template<typename T> struct X {
  X(T const&);
};

template<typename T> X(T) -> X<T>;
```
```

Notice how the deduction guide does not quite correspond to the constructors of `X`. However, that does not matter, because the guide is only used for deduction. Given a value `x` of type `X<T>`, its value or reference will select the deduced type `X<T>`. Then, initialization will perform overload resolution on the constructors of `X<T>` to decide which one to call (which will depend on whether `x` is an lvalue or an rvalue).
