modified, then the assignment operator will swap-assign or move-assign the value in type `T` directly into the buffer, as appropriate. The discriminator is not changed.

If the variant does not store a value of type `T`, assignment requires a two-step process: Destroy the current value using `variant::destroy()`, then initialize a new value of type `T` using `variant::place()`, setting the discriminator appropriately.

There are three common problems with such a two-step assignment using placement new, each of which we have to take into account:

+   - Self-assignment
+   - Exceptions
+   - `std::launder()`

# Self-assignment

Self-assignment can occur for a variant `v` due to an expression like the following:

```
```cpp
v = v;
```
```

With the two-step process implemented above, the stored value would be destroyed before it could be copied, potentially leading to memory corruption. Fortunately, self-assignment always implies that the discriminator matches, so such code will invoke the assignment operator for `T` rather than this two-step process.

# Exceptions

If the destruction of the existing value completes, but the initialization of the new value throws an exception, what is the state of the variant? In our implementation, `variant::destroy()` resets the discriminator value to `-1`. In exceptional cases, the discriminator will be set appropriately for the new alternative. When an exception occurs during initialization of the new value, the discriminator remains to indicate that the variant does not store a value. In our design, this is the only way to produce a variant without a value.
