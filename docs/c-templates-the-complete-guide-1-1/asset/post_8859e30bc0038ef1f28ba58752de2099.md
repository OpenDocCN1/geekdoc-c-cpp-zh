Note that, unlike a normal C++ if-then-else statement, the template arguments for both the “then” and “else” branches are evaluated before the selection is made, so neither branch may contain ill-formed code, or the program is likely to be ill-formed. **Click here to view code image**

```cpp
// yield T when using member Type:

    using Type = T;

    using Type = typename std::make_unsigned<T>::type;
```


### 9.7.2 Detecting Nothrow Operations

It is generally useful to determine whether a particular operation can throw an exception. For example, a move constructor should be marked `noexcept`, indicating that it does not throw an exception, whenever possible. However, just because a move constructor is not marked `noexcept` does not mean that it can throw. It just means that no guarantee is made about whether the operation can throw. This is important because a type's move constructor can be implemented to be no-throw under certain circumstances. For example, consider the move constructor for a class template `Pair`:

Click here to view code image

```cpp
template<typename T1, typename T2>
struct Pair {
    T1 first;
    T2 second;
    Pair(const T1& x, const T2& y)
        : first(std::forward<T1>(x)), second(std::forward<T2>(y)) {
    }
};
```

`Pair`'s move constructor can throw exceptions when the move operations of either `T1` or `T2` throw. Given a trait `IsNothrowMoveConstructibleT`, we can express this property by using a computed `noexcept` exception specification in `Pair`'s move constructor. For example:

Click here to view code image

```cpp
template<typename T1, typename T2>
Pair(Pair&& other)
    noexcept(IsNothrowMoveConstructibleT<T1>::value &&
             IsNothrowMoveConstructibleT<T2>::value)
    : first(std::forward<T1>(other.first)),
      second(std::forward<T2>(other.second)) {
}
```

All that remains is to implement the `IsNothrowMoveConstructibleT` trait. We can easily implement this trait using the `noexcept` operator, which determines whether a given expression is guaranteed to be non-throwing:

Click here to view code image

```cpp
template<typename T>
struct IsNothrowMoveConstructibleT
    : std::bool_constant<noexcept(T(std::declval<T>()))> {
};
```

Here, the operator version of `noexcept` is used, which determines whether an expression is non-throwing. Because the result is a Boolean value, we can pass it directly to the `std::bool_constant`, which is defined in `<type_traits>` and is a `std::integral_constant<bool, ...>` as described in Section 3.3 on page 41.

However, this implementation should be improved because it is not `SFINAE`-friendly (see Section 8.4 on page 135). If the trait is instantiated with a type that does not have a move or copy constructor—making the expression `T(std::declval<T>())` invalid—the entire program is ill-formed:

Click here to view code image

```cpp
class X {
public:
    X() = delete;
};
```

```cpp
std::bool_constant<noexcept(T(std::declval<T>()))>::value // ...
```

false.

As discussed in Section 19.4.1 on page 43, we have to check whether the expression computing the result is valid before it is evaluated. Here, we have to find out whether move construction is valid before checking whether it is noexcept. Thus, we revise the first version of the trait by adding a template parameter that defaults to void and a partial specialization that uses std::void_t for that parameter with an argument that is valid only if move construction is valid.

Click here to view code image

```cpp
#include <utility>      // for declval
#include <type_traits>   // for true_type, false_type

// primary template:
template<typename T, typename = std::void_t<>>
struct isNothrowMoveConstructible
  : std::false_type
{
};

// partial specialization (may be SFINAE'd away):
template<typename T>
struct isNothrowMoveConstructible<T,
  std::void_t<decltype(T(std::declval<T>()))>>
  : std::bool_constant<noexcept(T(std::declval<T>()))>
{
};
```

If the substitution of std::void_t<> in the partial specialization is valid, that specialization is selected, and the `noexcept(...)` expression in the base class specifier can be evaluated. Otherwise, the partial specialization is discarded without instantiating it, and the primary template is instantiated instead (producing a `std::false_type` result).

Note that there is no way to check whether a move constructor throws without being able to call it directly. That is, it is not enough that the move constructor is public and not deleted, it also requires that the corresponding type is an attribute (or reference) of its parent? For this reason, the type trait is named `isNothrowMoveConstructible` instead of `HasNoThrowMoveConstructor`. For anything else, we'd need some support.

The C++ standard library provides a corresponding type trait `std::is_nothrow_constructible<>`, which is described in Section 3.2.3 on page 42.

### 9.7.3 Traits Convenience

One common complaint with type traits is their relative verbosity, because each use of a type trait typically requires a trailing `::type` and, in a dependent context, a leading `typename` keyword, both of which are boilerplate.
