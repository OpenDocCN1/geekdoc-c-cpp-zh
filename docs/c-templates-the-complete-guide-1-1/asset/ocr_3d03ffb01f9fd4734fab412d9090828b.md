1), we create a specific SFINAE context only for the second `test()` overload.

# Alternative Implementation Strategies for SFINAE-based Traits

SFINAE-based traits have been possible to implement since before the first C++ standard was published in 1998. The key to the approach always consisted in declaring two overloaded function templates returning different return types.

Click here to view code image

```
template <typename T> static char test(T*);
template <typename> static long test(...);
```

However, the original published technique used the size of the return type to determine which overload was selected (also using a minimum, because null pointers and constants were not available).

Click here to view code image

```
using SizeT = sizeof(test<T>(...)) == 1;
```

On some platforms, it might happen that sizeof(char) == sizeof(long) (for example, on digital signal processors (DSP) or C++ machines, all integral fundamental types could have the same size). So by definition sizeof(char) equals 1, so those machines sizeof(long) can equal 1 (long) and even sizeof(long) == sizeof(char).

Given that observation, we want to ensure that the return types of the `test()` functions have different sizes on all platforms. For example, after defining

Click here to view code image

```
using SizeT = char;
using SizeT2 = struct { char a[2]; };
```

or

Click here to view code image

```
using SizeT = char[6];
using SizeT2 = char[6][2];
```

we could define test() overloads as follows:

Click here to view code image

```
template <typename T> static SizeT test(void*);  // checking
template <typename> static SizeT2 test(...);  // fallback
```

Note also that the type of the call argument passed to `func()` doesn't matter. All that matters is that the passed argument matches the expected type. For example, you could also define to pass the integer 42:

Click here to view code image

```
template <typename T> SizeT test(int);     // checking
template <typename> SizeT2 test(...);      // fallback

return sizeof(test<T>(42)) == 1;
```

# Making SFINAE-based Traits Predictable

As introduced in Section 19.3.3 on page 410, a predicate trait, which returns a Boolean value, should return a value derived from `std::true_type` or `std::false_type`. This way, we can also solve the problem that one same platform's size of `char` == sizeof(long).

For this, we need an implicit definition of `is-type()` construct. The trait itself should derive from the type of a helper class, which yields the necessary base class. Fortunately, we can simply provide the core-trait-matching base classes as return types of the `test()` overloads:

Click here to view code image

```
template <typename T> static std::true_type test(T*);    // checking
template <typename> static std::false_type test(...);     // fallback

template<typename T>
using is_default_constructible = decltype(test<T>(nullptr));
```

That way, the `Type` member for the base class simply can be declared as follows:

Click here to view code image

```
using Type = decltype(SFINAE<...>);
```

and we no longer need the `isSameT` trait.
