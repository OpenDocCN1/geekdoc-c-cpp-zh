
All standard type traits yielding a value are derived from an instance of the helper class template `std::integral_constant`:

Click here to view code image

```cpp
template<typename T, T val>
struct integral_constant {
    static constexpr T value = val;          //
    using value_type = T;                    //
    using type = integral_constant<T, val>;

    constexpr operator value_type () const noexcept
    {
        return value;
    }
};
```

That is:

- We can use the `value_type` member to query the type of the result. Since many traits yielding a value are predicates, `value_type` is often just `int`.
- Objects of traits types have an implicit conversion to the type of the value produced by the type trait.
- In C++14 (and later), objects of type traits are also function objects (functors), where a “function call” yields their value.
- The `type` member just aliases the underlying `integral_constant` instance.

If traits yield Boolean values, then can also use

Click here to view code image

```cpp
template<bool T>
struct is_bool
{
    using bool_constant = integral_constant<bool, T>;  // since C++17
    using true_type = bool_constant<true>;
    using false_type = bool_constant<false>;
};
```

so that these Boolean traits inherit from `std::true_type` if a specific property applies and from `std::false_type` if not. That also means that their corresponding `value` members equal `true` or `false`. Having distinct types for the resulting values turned false allows us to tag-dispatch based on the results of type traits (see Section 9.3.3 on page 467).

For example:

Click here to view code image

```cpp
#include <type_traits>
#include <iostream>

int main()
{
    using namespace std;

    cout << boolalpha;

    using MyType = int;

    cout << is_const<MyType>::value << '\n';

    using VT = is_const<MyType>::value_type;  // bool

    using T = is_const<MyType>::type;         // integral_constant<bool, false>

    cout << is_same<VT, bool>::value << '\n';

    cout << is_same<T, integral_constant<bool, false>>::value
         << '\n';

    cout << is_same_v<T, integral_constant<bool, false>>;

    static constexpr auto mytypeConst = is_const<MyType>::value;

    if constexpr (mytypeConst)       // compile time
    {
        // discarded statement
    }

    static_assert(std::is_const<MyType>::value, "MyType should ...");
}
```

Having distinct types for non-Boolean `integral_constant` specializations is also useful in various metaprogramming contexts. See the discussion of the similar type `CTValue` in Section 24.3 on page 966 and its use for element access of tuples in Section 25.6 on page 959.

### D.1.2 Things You Should Know When Using Traits

There are a few things to note when using traits:

- Type traits apply directly to types, but `decltype` allows us to also test the properties of expressions, variables, and functions. Recall, however, that `decltype(<expr>)` produces the type of a variable or function only if the expression is the name of an entity (enclosed in parentheses); for any other expression, it yields a type that also reflects the type category of the expression. For example:

  ```cpp
  void foo (std::string& s)
  {
      // Check the type of s:
      std::is_lvalue_reference<
          decltype(s)>::value          // true
      std::is_lvalue_reference<
          decltype(std::move(s))>::value // false
      std::is_lvalue_reference<
          decltype((s))>::value         // true, s used as lvalue
  }
  ```

  See Section 15.10.2 on page 598 for details.

- Some traits may have nonintuitive behavior for the novice programmer. See Section 9.1.3 on page 159 for example.
- Some traits have requirements or preconditions. Violating these preconditions results in undefined behavior. See Section 20.1.1 on page 164 for some examples.
- Many traits require complete types (see Section 10.3.1 on page 54). To be able to use them for incomplete types, we can sometimes introduce templates to defer their evaluation (see Section 11.5 on page 174 for details).
- Sometimes the logical operators `&&`, `||`, and `!` cannot be used to define new type traits based on other type traits. In addition, dealing with traits that might fail can become a problem or at least require some drawbacks. For this reason, special traits are provided that allow us to logically combine Boolean traits. See Section D.6 on page 734 for details.
- Although the standard alias templates (ending with `_t` or `_v`) are often convenient, they also have downsides, making them unsuitable in some metaprogramming contexts. See Section 19.7.3 on page 424 for details.

We start with the standard traits that test primary and composite type categories (see Figure D.1). In general, each type belongs to exactly one primary type category (the white elements in Figure D.1). Composite type categories then merge multiple type categories into higher-level concepts.

### D.2.1 Testing for the Primary Type Category

This section describes type utilities that test the primary type category of a given type. For any given type, exactly one of the primary type categories has a `value` member that evaluates to `true`. The result is independent of whether the type is qualified with `const` and/or `volatile` (cv-qualified).

Note that for types `std::size_t` and `std::ptrdiff_t`, it is implementation-defined which of these primary type categories yields `true`. For type `std::max_align_t`, which one of these primary type categories yields `true` is also an implementation detail (this, in turn, depends on the language-specific ...).

| Trait | Effect |
|---|---|
| `is_void<T>` | Type void |
| `is_integral<T>` | Integral type (including `bool`, `char`, `char16_t`, `char32_t`, or `wchar_t`) |
| `is_floating_point<T>` | Floating-point type (`float`, `double`, or `long double`) |
| `is_array<T>` | Ordinary array type (not type `std::array`) |
| `is_pointer<T>` | Pointer type (including function pointer but not pointer to non-static member) |
| `is_null_pointer<T>` | Type of `nullptr` (since C++14) |
| `is_member_object_pointer<T>` | Pointer to a nonstatic data member |
| `is_member_function_pointer<T>` | Pointer to a nonstatic member function |
| `is_lvalue_reference<T>` | Lvalue reference |
| `is_rvalue_reference<T>` | Rvalue reference |
| `is_enum<T>` | Enumeration type |
| `is_class<T>` | Class/struct or lambda type but not a union type |
| `is_union<T>` | Union type |
| `is_function<T>` | Function type |

*Table D.4. Traits to Check the Primary Type Category*

`std::is_void<T>::value`

- Yields true if type `T` is (cv-qualified) `void`.
- For example:

**Click here to view code image**

```cpp
std::is_void<void>          // yields true
std::is_void<const void>    // yields true
std::is_void<int>           // yields false
void f();
std::is_void<decltype(f)>   // yields false
```

`std::is_integral<T>::value`

- Yields true if type `T` is one of the following (cv-qualified) types:
  - `bool`
  - a character type (`char`, `signed char`, `unsigned char`, `char16_t`, `char32_t`, or `wchar_t`)
  - an integer type (signed or unsigned variants of `short`, `int`, `long`, or `long long`; this includes `std::size_t` and `std::ptrdiff_t`)

`std::is_floating_point<T>::value`

- Yields true if type `T` is (cv-qualified) `float`, `double`, or `long double`.

`std::is_array<T>::value`

- Yields true if type `T` is a (cv-qualified) array type.
- Recall that a parameter declared as an array (with or without a length) by language rules really has a pointer type.
- Note that class `std::array<>` is not an array type, but a class type.
- For example:

```cpp
void foo(int i, int b[], int c)
{
  int a;
  is_array_v<decltype(a)>;        // yields false (a has type int)
  is_array_v<decltype(b)>;        // yields false (b has type int*)
  is_array_v<decltype(c)>;        // yields false (c has type int*)
}
```

- See Section 9.8.2 on page 405 for implementation details.

`std::is_pointer<T>::value`

- Yields true if `T` is a (cv-qualified) pointer.

This includes:

- pointers to static (global) functions
- parameters declared as arrays (with or without length) or function types

This does not include:

- pointer-to-member types (e.g., the type of `x::*` where `x` is a class type and is a nonstatic member function or nonstatic data member)
- the type of literals, such as `nullptr_t`

- For example:

**Click here to view code image**

```cpp
int* p = nullptr;                         // p has type int*
std::is_pointer<int*>::value;             // yields true
std::is_pointer<int* const>::value;       // yields true
std::is_pointer<int* volatile>::value;    // yields true
std::is_pointer<decltype(nullptr)>::value; // yields false
```

```cpp
void f(int* p1, int*& p2)
{
  is_pointer_v<decltype(p1)>;       // yields true (p1 has type int*)
  is_pointer_v<decltype(p2)>;       // yields false (p2 has type int*&)
  is_pointer_v<decltype(f)>;        // yields false
  is_pointer_v<decltype(f(1))>;     // yields false
  is_pointer_v<decltype(&f)>;       // yields true (pointer to function)
  is_pointer_v<decltype(f(1, p1))>; // yields false (return type is void)
}
```

- See Section 9.8.2 on page 405 for implementation details.

`std::is_null_pointer<T>::value`

- Yields true if `T` is the (cv-qualified) `std::nullptr_t`, which is the type of `nullptr`.
- For example:

**Click here to view code image**

```cpp
int* p = nullptr;
std::is_null_pointer<decltype(p)>::value; // yields false
void* q = nullptr;
std::is_null_pointer<decltype(q)>::value; // yields false (q has type void*)
std::is_null_pointer<int*>::value;        // yields false
std::is_null_pointer<decltype(nullptr)>::value; // yields true
std::is_null_pointer<std::nullptr_t>::value; // yields true
```

- Provided since C++11:

```cpp
std::is_member_object_pointer<T>::value
std::is_member_function_pointer<T>::value
```

- Yields true if `T` is a (cv-qualified) pointer to member type (e.g., for `int C::*` or for some class `X`).

```cpp
std::is_lvalue_reference<T>::value
std::is_rvalue_reference<T>::value
```

- Yields true if `T` is a (cv-qualified) lvalue or rvalue reference type, respectively.
- For example:

**Click here to view code image**

```cpp
int i;
std::is_lvalue_reference<decltype(i)>::value; // yields false
std::is_lvalue_reference<decltype((i))>::value; // yields true
std::is_rvalue_reference<decltype(i)>::value; // yields false
std::is_rvalue_reference<decltype((i))>::value; // yields false
std::is_lvalue_reference<decltype(std::move(i))>::value; // yields false
std::is_rvalue_reference<decltype(std::move(i))>::value; // yields true
std::is_lvalue_reference<int>::value; // yields false
std::is_rvalue_reference<int>::value; // yields false
```

- See Section 9.8.2 on page 405 for implementation details.
