```
T value(Type<T>) // no definition needed
```

Let's start with the definition of `isValid`: It is a constexpr variable whose type is a lambda's closure type. The declaration must necessarily use a placeholder type (`auto` in our code) because C++ has no way to express closure types directly. Prior to C++17, lambda expressions could not appear in constant expressions. With C++17, this ability is also available in constant expressions. With C++17, since `isValid` has a closure type, it can be invoked (i.e., called), but the item that it returns is itself an object of a lambda closure type, produced by the inner lambda expression.

Before delving into the details of this inner lambda expression, let's examine a typical use of `isValid`:

**Click here to view code image**

```
constexpr auto isDefaultConstructible
    = isValid([] (auto x) -> decltype(std::declval<decltype(x)>())
        { return {}; });
```

We already know that `isDefaultConstructible` has a lambda closure type and, as the name suggests, it is a function object that checks the trait of a type being default-constructible (we'll see why in what follows). In other words, `isValid` is a traits factory. A component that generates traits checking objects from its arguments.

The type helper variable template allows us to represent a type as a value. I use a `type` variable that you can turn back into the original type with `decltype(value)` and that's exactly what is passed to `isValid` above. If that extracted type cannot be default-constructed, the `decltype(value)` is invalid, and we will either get a compiler error, or an associated default function will be substituted, and the latter effect is what will achieve thanks to the details of the definition of `isValid`.

`isDefaultConstructible` can be used as follows:

**Click here to view code image**

```
isDefaultConstructible(type<int>)                 // true (int is
                                                     // default-constructible)
isDefaultConstructible(type<std::unique_ptr<int>>)   // false (references
                                                     // are not default-constructible)
```

So now all the pieces work together, consider what the inner lambda expression in `isValid` becomes with a call to a parameter `t` bound to the generic lambda argument specified in the definition of `isDefaultConstructible`. By performing the substitution in `isValid`'s definition, we get the equivalent of

**Click here to view code image**

```
constexpr auto isDefaultConstructible
    = [] (auto... args) {
        return decltype([] (auto x) -> decltype(std::declval<
            decltype(args)>()); 
        });
      };
```

If we look back at the first declaration of `isValid` above, we note that it includes a default template argument of the form

**Click here to view code image**

```
decltype([](decltype(auto) t) -> decltype(std::declval<T>()));
```

which attempts to invoke a value of the type of its first template argument, which is the closure type of the lambda in the definition of `isDefaultConstructible`, with a value of the type of the arguments (`decltype(std::declval<...>())`). In the type of the first argument to `isValid`, a regular lambda expression is made; its return type is specified as `decltype(std::declval<...>)`, as shown above. When the expression is substituted, the call is valid if the first declaration of `isDefaultConstructible` is well-formed. If it is not, the expression substitution fails, and SFINAE'd out. That leaves just the second declaration, which would otherwise be a lesser match, which produces a false value. Moreover, `isDefaultConstructible` produces a false type when `type<T>` is passed. If instead `type<T>` is passed, the substitution does not fail and the first declaration of `isValid<T>()` is selected, producing a true value.

Recall that for SFINAE to work, substitutions have to happen in the immediate context of the substituted templates. In this case, the substitution templates are the first declaration of `isValid<T>` and the call operator of the generic lambda passed to `isValid`. Therefore, the construct to be tested has to appear in the return type of that lambda, not in its body!

Our `isDefaultConstructible` trait is a little different from previous trait implementations in that it requires function-object instances instead of specifying template arguments. That is arguably a more usable notation, but prior style can be obtained also:

**Click here to view code image**

```
template<typename T>
using isDefaultConstructible = decltype(isValid(type<T>{}));
```
