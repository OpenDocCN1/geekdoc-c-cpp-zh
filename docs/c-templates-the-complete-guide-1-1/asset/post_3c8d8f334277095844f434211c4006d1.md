
## 27.2.1 OPERANDS OF THE EXPRESSION TEMPLATES

To complete the representation of the expression, we must reference the operands in each of the A_Add and A_Mult objects and retrieve the value of the scalar in the A_Add or A_Mult objects (or a reference thereto). Here are possible definitions for the corresponding operands:

[Click here to view code image](example/expression.cpp)

```cpp
#include <iostream>

#include <cassert>

// include helper class traits template to select whether
// expression template node either by value or by reference
#include "exprspecial.hpp"

// class for object that represent the addition of two operands
template<typename T, typename OP1, typename OP2>
class A_Add {
private:
    typename A_Traits<OP1>::ExprRef op1;    // first operand
    typename A_Traits<OP2>::ExprRef op2;    // second operand

public:
    // constructor initializes references to operands
    A_Add (OP1 const& a, OP2 const& b)
      : op1(a), op2(b) {
    }

    // compute sum when value requested
    T operator[] (std::size_t idx) const {
        return op1[idx] + op2[idx];
    }

    // compute size when requested
    std::size_t size() const {
        assert(op1.size()!=0 || op2.size()!=0
               || op1.size()==op2.size());
        return op1.size()!=0 ? op1.size() : op2.size();
    }
};

// class for object that represent the multiplication of two operands
template<typename T, typename OP1, typename OP2>
class A_Mult {
private:
    typename A_Traits<OP1>::ExprRef op1;    // first operand
    typename A_Traits<OP2>::ExprRef op2;    // second operand

public:
    // constructor initializes references to operands
    A_Mult (OP1 const& a, OP2 const& b)
      : op1(a), op2(b) {
    }

    // compute product when value requested
    constexpr auto operator[](std::size_t idx) const
    {
        return op1[idx] * op2[idx];
    }

    // size is maximum size
    std::size_t size() const
    {
        assert(op1.size() == 0 || op2.size() == 0
               || op1.size() >= op2.size());
        return op1.size() > op2.size() ? op1.size() : op2.size();
    }
};
```

As you can see, we added subscripting and size-querying operations that allow us to compute the size and the values of the elements for the array resulting from the operation represented by the subtree of nodes rooted at the object.

For operations involving arrays only, the size of the result is the size of either operand. However, for operations involving both an array and a scalar, the size of the result is the size of the array operand. To distinguish array operands from scalar operands, we define a size of zero for scalars. The A_Scalar template is therefore defined as follows:

Click here to view code image

`exprtmp/exprscalar.hpp`

```cpp
// class for objects that represent scalars
template<typename T>
class A_Scalar {
private:
    T const s;  // value of the scalar

public:
    // constructor initializes value
    constexpr A_Scalar(T const& v)
        : s(v) { }

    // for index operation, the scalar is the value
    constexpr T const& operator[](std::size_t) const
    {
        return s;
    }

    // scalars have zero as size
    constexpr std::size_t size() const
    {
        return 0;
    }
};
```

We have declared the constructor and member functions constexpr so this class can be used at compile time. This is, however, not strictly needed for our purposes.

Note that scalars also provide an index operator. Inside the expression, they represent an array with the same scalar value for each index.

You probably saw that the operator classes used a helper class A_Traits to define the members for the operands:

`exprtmp/exprtraits.hpp`

```cpp
template <typename T>
struct A_Traits {
    using ExprRef = T const&;   // type to refer to
    using ExprT   = T const&;   // type to refer to
};
```

This is necessary because, in general, we can declare them to be reference, since most temporary nodes are bound in the top-level expression and therefore live until the end of the evaluation of that complete expression. The one exception are the A_Scalar nodes. They are bound within...

In other words, we need members that are

- **constant references in general:**

    [Click here to view code image](#)

    ```cpp
    OP1 const& op1;    // refer to first operand by reference
    OP2 const& op2;    // refer to second operand by reference
    ```

- **ordinary values for scalars:**

    [Click here to view code image](#)

    ```cpp

    OP2 op2;            // refer to second operand by value
    ```

This is a perfect application of traits classes. The traits class defines a type to be a constant reference in general but an ordinary value for scalars:

[Click here to view code image](#)

```cpp
template<typename T>
class A_Traits {
public:
    using ExprRef = T const&;    // type to refer to
};

// partial specialization for scalars
template<typename T>
class A_Traits<A_Scalar<T>> {
public:
    using ExprRef = A_Scalar<T>;   // type to refer to
};
```

Note that since A_Scalar objects refer to scalars in the top-level expression, those scalars can use reference types. That is, A_Scalar<T> is a reference member.

## 27.2.2 The Array Type

With our ability to encode expressions using lightweight expression templates, we must now create an Array type that controls actual storage and that knows about the expression templates. However, it is also useful for engineering purposes to keep as similar as possible the interface for a real array with storage and one for a representation of an expression that results in an array. To this end, we declare the Array template as follows:

[Click here to view code image](#)

```cpp
template<typename T, typename Rep = ArrayTraits<T>::Rep>
class Array;
```

The type Rep can be SArray or an array of storage. Of course, it can be the nested template such as A_Add or ... that encodes an expression. Either way we are handling lazy instantiations, which considerably simplify our later handling. In fact, even the definition of the Array template needs no specializations to distinguish the two cases, although some of the members cannot be instantiated for types like A_Mult--substituted for Rep.

Here is the definition. The functionality is limited roughly to what was provided by our Array template, although once the code is understood, it is not hard to add to that functionality:

[Click here to view code image](#)

```cpp
#include <iostream>
#include <cassert>
#include "traits.hpp"

template<typename T, typename Rep = ArrayTraits<T>::Rep>
class Array {
private:
    Rep expr_rep; // (access to) the data of the array

public:
    // create array with initial size
    explicit Array (std::size_t n)
        : expr_rep(n) {
    }

    // create array from possible representation
    Array (Rep const& b)
        : expr_rep(b) {
    }

    // assignment operator for same type
    Array& operator= (Array const& b) {
        assert(size() == b.size());

        for (std::size_t i = 0; i < b.size(); ++i)
            expr_rep[i] = b[i];

        return *this;
    }

    // assignment operator for arrays of different types
    template<typename T2, typename Rep2>
    Array& operator= (Array<T2, Rep2> const& b) {
        assert(size() == b.size());

        for (std::size_t i = 0; i < b.size(); ++i)
            expr_rep[i] = b[i];

        return *this;
    }

    // size is size of represented data
    std::size_t size() const {
        return expr_rep.size();
    }

    // index operator for constants and variables
    decltype(auto) operator[] (std::size_t idx) const {
        assert(idx < size());
        return expr_rep[idx];
    }

    T& operator[] (std::size_t idx) {
        assert(idx < size());
        return expr_rep[idx];
    }

    // return what the array currently represents
    Rep const& rep() const {
        return expr_rep;
    }
};
```

Once again, many operations are simply forwarded to the underlying Rep object. However, when copying another array, we must take into account the possibility that the other array is really built on an expression template. Thus, we parameterize these copy operations in terms of the underlying Rep representation.

Thus the subscripting operator deserves a little discussion. Notice that the core version of that operator uses a deduced return type rather than the more traditional type trait syntax. We do that because if Rep represents an A_Mult, its subscripting operator returns a temporary sub-expression, which cannot be returned by reference (and thus be a reference to that). If we decide no reference type for the rvalue result, then the operator produces a const lvalue, and the deduced return type will be a matching const reference for that case.

## 27.2.3 The Operators

We have most of the machinery in place to have efficient numeric operators for our unary Array templates, except the operators themselves. As implied earlier, these operators only assemble the expression template objects—they don’t actually evaluate the resulting arrays.

For each adjoining binary operator, we must implement three versions: array-array, array-scalar, and scalar-array. To be able to compute our initial value, we need, for example, the following operators:

[Click here to view code image](#)

```cpp
// addition of two Arrays

template<typename T, typename R1, typename R2>
Array<T, A_Add<T,R1,R2>>
operator+ (Array<T,R1> const& a, Array<T,R2> const& b)
{
    return Array<T, A_Add<T,R1,R2>>
        (A_Add<T,R1,R2>(a.rep(),b.rep()));
}

// multiplication of two Arrays

template<typename T, typename R1, typename R2>
Array<T, A_Mult<T,R1,R2>>
operator* (Array<T,R1> const& a, Array<T,R2> const& b)
{
    return Array<T, A_Mult<T,R1,R2>>
        (A_Mult<T,R1,R2>(a.rep(),b.rep()));
}

// multiplication of scalar and Array

template<typename T, typename R2>
Array<T, A_Mult<T,R2,A_Scalar<T>>>
operator* (Array<T,R2> const& a, A_Scalar<T> const& b)
{
    return Array<T, A_Mult<T,R2,A_Scalar<T>>>
        (A_Mult<T,R2,A_Scalar<T>>(a.rep(),A_Scalar<T>(b)));
}

// addition of Array and scalar
```
