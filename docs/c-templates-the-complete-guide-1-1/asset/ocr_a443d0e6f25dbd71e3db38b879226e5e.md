but the following otherwise equivalent code is fine:

Click here to view code image

```
auto f(int n)
{
    if (n <= 1) {
        return 1;             // return type is deduced to be
                               // int
    }
    else {
        return n*f(n-1);       // OK: type of f(n-1) is int and
                               // so is type of n*f(n-1)
    }
}
```

Deduced return types have another special case with no counterpart in declared variable types or deduced non-type parameter types:

Click here to view code image

```
auto f1() { return; }       // OK: return type is void
auto f2() { return {}; }     // OK: return type is void
```

Both f1() and f2() are valid and have a void return type. However, if the return type pattern cannot match void, such cases are invalid:

Click here to view code image

```
auto* f3() { return; }      // ERROR: auto* cannot deduce as void
```

As you'd expect, any use of a function template with a deduced return type requires the immediate instantiation of that template to determine the return type quite visibly. That, however, has a surprising consequence when it comes to SFINAE (described in Section 8.1.8 on page 129 and Section 15.7 on page 824). Consider the following example:

Click here to view code image

```
template<typename T, typename U>
auto add(T t, U u) -> decltype(t+u)
{
    return t + u;
}

void add(...);

template<typename T, typename U>
auto add(T t, U u) -> decltype(auto)
{
    return t + u;
}

void add(...);

struct X
{
};

using AddResultA = decltype(add(X{}, X{})); // OK: ...
using AddResultB = decltype(add(X{}, X{})); // ERROR: ...
```

Here, we use the decltype(auto) rather than decltype(t+u) for add() causes an error during overload resolution. The function body of the add() template must be fully instantiated to determine its return type. That instantiation is fine in the immediate context (see Section 15.7.1 on page 828) of the call to add() and therefore doesn't fall under the SFINAE filter but results in an outright error. It is therefore important to remember that deduced return types (even if you use decltype(auto)) are not considered in overload resolution.

# 5.10.5 Structured Bindings

C++17 added a few features known as structured bindings. It is most easily illustrated with a small example:

Click here to view code image

```
struct MaybeInt { bool valid; int value; };
MaybeInt get();
auto const [b, v] = get(); // This is...
```

The call to get() produces a value (in this case a simple class aggregate of type MaybeInt) that can be decomposed into “elements” (in this case, the data members of MaybeInt). The value of that call is produced as if the bracketed list of identifiers were replaced with a corresponding declaration.
