
Note that

Click here to view code image

```cpp
template<typename T1, typename T2>
auto max (T1 a, T2 b) -> decltype(b < a ? b : a);
```

is a declaration, so that the compiler uses the rules that operator `?:` calls for parameters `a` and `b` to find out the return type of the expression at compile time. The implementation does not necessarily have to match. In fact, its return type as the condition for operator `?:` in the declaration is enough:

Click here to view code image

```cpp
template<typename T1, typename T2>
auto max (T1 a, T2 b) -> decltype(b < a ? b : a)
{
    return b < a ? b : a;
}
```

However, in any case this definition has a significant drawback: It might happen that the return type is a reference type, because under some conditions the expression might become a reference. For this reason you should return the type decayed from T, which looks as follows:

Click here to view code image

```cpp
#include <type_traits>

template<typename T1, typename T2>
auto max (T1 a, T2 b) -> typename std::decay<decltype(b < a ? b : a)>::type
{
    return b < a ? b : a;
}
```

Here, the type trait `std::decay<>` is used, which returns the resulting type in a manner that is defined by the standard library in `<type_traits>` (see Section 5.6 on page 732). Because the member type is `::type`, you have to qualify the expression with `typename` to access it (see Section 5.1 on page 672).

Note that an initialization of type `auto` always decays. This also applies to return values when the return type is just `auto`, so the result type becomes here just as in the following code, where `a` is declared by the decayed type of `i`:

Click here to view code image

```cpp
int i = 42;
int const& ir = i;        // ir refers to i
auto a = ir;              // a is declared as non-reference
                         // of type int
```

### 1.3.3 Return Type as Common Type

Since C++11, the C++ standard library provides a means to specify changing the return type. `std::common_type<>` is a type trait that defines the “common type” of two (or more) different types passed as template arguments. For example:

Click here to view code image

```cpp
#include <type_traits>

template<typename T1, typename T2>
std::common_type_t<T1, T2> max (T1 a, T2 b)
{
    return b < a ? a : b;
}
```

Again, `std::common_type<>` is a type trait, defined in `<type_traits>`, which yields a structure having a type member for the main resulting type. For example, its usage is as follows:

Click here to view code image

```cpp
std::common_type_t<int, double>
```

However, since C++14 you can simplify the usage of traits like this by using the `_t` suffix to the trait name and skipping `typename` and `::type` (see Section 2.8 on page 40 for details), so that the return type definition simply becomes:

Click here to view code image

```cpp
std::common_type_t<T1, T2>
```

The way `std::common_type<>` is implemented uses some tricky template programming, which is discussed in Section 5.2 on page 622. Internally, it chooses the resulting type according to the language rules of operator `?:` or a specialization for specific types. Thus, `bool`, `long`, `char16_t`, `int`, and `max(7.2, 4.0)` yield the same value `7.2` of type `double`. Note that `std::common_type<>` can also decay. See Section 5.9 on page 735 for details.

Template parameters can have default arguments. They may even refer to previous template parameters.

## 1.5 OVERLOADING FUNCTION TEMPLATES

Like ordinary functions, function templates can be overloaded. That is, you can have different function definitions with the same function name so that when that name is used in a function call, a C++ compiler must decide which one of the various candidates to call. The rules for this decision may become rather complicated, even without templates. In this section we discuss overloading when templates are involved. If you are not familiar with the rules of function overloading without templates, please look at Appendix C, where we provide a reasonably detailed survey of the overloaded resolution rules.

The following short program illustrates overloading a function template:

Click here to view code image

```cpp
// maximum of two int values:

int max (int a,
         int b)
{
    return b < a ? a : b;
}

// maximum of two values of any type:

template<typename T>
T max (T a, T b)
{
    return b < a ? a : b;
}

int main()
{
    ::max(7, 42);          // calls the nontemplate
    ::max(7, 42.0);        // calls max<double>
    ::max('a', 'b');       // calls max<char>
    ::max(7.0, 42);        // calls max<double>
    ::max<double>(7, 42);  // calls the template
}
```

As this example shows, a non-template function can coexist with a function template that has the same name and can be instantiated with the same type. All other factors being equal, the overload resolution process prefers the non-template over one generated from the template. The first call falls under this rule:

Click here to view code image

```cpp
::max(7, 42);    // both int values match the nontemplate function perfectly
```

If the template can generate a function with a better match, however, then the template is selected. This is demonstrated by the second and third calls of `max()`:

Click here to view code image

```cpp
::max(7, 42.0);    // calls the max<double> by argument deduction
::max('a', 'b');    // calls the max<char> by argument deduction
```

Here, the template is a better match because no conversion from `double` or `char` to `int` is required (see Section C.2 on page 682 for the rules of overload resolution).
