### Reading a Text File

Reading a text file is a crucial ability in Java and has many practical applications. FileReader, BufferedReader, and Scanner are useful classes for reading a plain text file in Java. Each of them possesses specific qualities that make them uniquely qualified to handle certain situations.

### BufferedReader

This technique reads text from a stream of character input. It buffers characters, arrays, and lines to be read efficiently. You can specify the buffer type or use the standard type. For most purposes, the default is big enough. In particular, each read request made of a Reader causes a corresponding read request to be made of the underlying character or byte stream. Therefore, it is advisable to wrap a BufferedReader around any Reader whose read() operations, like FileReaders and InputStreamReaders, can be expensive.

For example:

```java
BufferedReader in = new BufferedReader(Reader in, int size);
```

### FileReader

Convenience class for reading character files. This class's constructors assume the default character encoding and the default byte-buffer size are appropriate.

### Scanner

A simple text scanner that uses regular expressions to parse primitive types and strings. A Scanner uses a delimiter pattern to break its input into tokens, which by default match whitespace. Using various next methods, the resulting tokens can then be converted into values of different types.

```java
import java.io.File;
import java.util.Scanner;

public class ReadFromFileUsingScanner {
    public static void main(String[] args) throws Exception {
        // filepath is set as a parameter now so that it can be scanned
        File example = new File("C:\\Users\\userName\\Desktop\\example.txt");
        Scanner example1 = new Scanner(example);
        while (example1.hasNextLine())
            System.out.println(example1.nextLine());
    }
}
```

Using Scanner class without using loops:

```java
import java.io.File;
import java.io.FileNotFoundException;
import java.util.Scanner;

public class example {
    public static void main(String[] args)
            throws FileNotFoundException {
        File example = new File("C:\\Users\\userName\\Desktop\\example.txt");

        // we will use \\Z as a delimiter
        example1.useDelimiter("\\Z");
        System.out.println(example1.next());
    }
}
```

## Advanced Topics in Java

### Generics

In any non-trivial software project, bugs are simply a fact of life. Careful planning, programming, and testing may help diminish their omnipresence, but somehow they will always find a way to enter your system somewhere. This becomes especially apparent as new features are introduced, and your code base's magnitude and complexity increases.

Fortunately, it is easier to detect some bugs than others. Compile-time bugs, for instance, can be identified soon; you can use the compiler's error codes to determine what the issue is and solve it, right then and there. Runtime bugs, however, can be much harder; they do not always occur instantly, and when they do, they may be at a point in the program far apart from the true cause of the problem. Generics help stabilize your software by making it feasible at compile time to identify more of your bugs.

Generics, in a nutshell, allow parameters for types (classes and objects) when defining classes, interfaces, and methods. Like the more familiar formal parameters used in declarations of methods, type parameters provide you with different inputs to re-use the same code. The distinction is that values are the inputs to formal parameters, while types are the inputs to type parameters. Code using generics has many advantages over non-generic code. Through the use of generics, programmers can introduce generic algorithms that operate on different types of collections, can be tailored, and are safer and easier to read.

### Generic Types

A generic type is a type-parameterized generic class or interface. It is possible to modify a simple box class to show the idea. Consider a non-generic box class that works on any sort of object. It only requires providing two methods: set (adding an item to the box) and get (retrieving it). Because their methods accept or return an object, you are free to pass in whatever you want, as long as it is not one of the primitive types. There is no way to check how the class is used at compile time. One portion of the software may put an integer in the box and expect to get integers out of it, while another portion of the software may erroneously pass in a string, leading to a runtime error.

The type parameter section, denoted by angle brackets (< >), follows the class name. It indicates the type parameters (also known as type variables) T1, T2, ..., Tn. You generate a generic type declaration by altering the line `public class Box` to `public class Box<T>` to update the Box class to use generics. This introduces the type variable, T, which can be used anywhere inside the class. This replaces all Object occurrences with T. Any non-primitive type you specify can be a type argument: any class type, any interface type, any array type, or even another type variable. It is possible to apply this same method to generic interfaces. Type parameter names are single, upper case letters by convention. This contrasts sharply with the variable naming conventions you already know about, and for an excellent reason: without this convention, it would be hard to tell the difference between a type variable and a normal class or object name.

The most commonly used type parameter names are:

- E - Element (used extensively by the Java Collections Framework)
- K - Key
- N - Number
- T - Type
- V - Value
- S, U, V, etc. — 2nd, 3rd, 4th types

You'll see these names used throughout the JDK and the API.

### Invoking and Instantiating a Generic Type

To reference the generic Box class within your program, you must perform a generic type invocation that replaces T with a concrete value, such as Integer:

```java
Box<Integer> integerBox;
```

You may believe that a generic type invocation is similar to an ordinary method invocation, but instead of passing an argument to a method, you pass a type argument—Integer, in this case—to the Box class itself.
