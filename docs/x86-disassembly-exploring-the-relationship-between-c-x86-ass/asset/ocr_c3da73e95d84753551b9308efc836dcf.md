# 21.2.2 FASTCALL for MyFunction:

Here is the clexe listing for MyFunction:

```
PUBLIC          @MyFunction2020
PUBLIC          __real83ff000000000000
PUBLIC          __real8400000000000000
PUBLIC          __real8480000000000000
EXTRN           floatused:NEAR
CONST           COMDAT          __real83ff000000000000
                               SEGMENT
CONST           __real83ff000000000000 DQ 03ff000000000000r ; 1
                                ENDS
CONST           COMDAT          _
                               SEGMENT
CONST           __real8400000000000000 DQ 0400000000000000r ; 2
                                ENDS
CONST           COMDAT          _
                               SEGMENT
CONST           __real8480000000000000 DQ 04800000000000000r ; 3
                                ENDS
TEXT            _
x$ = 8                                     ; size = 8
y$ = 16                                     ; size = 8
z$ = 24                                     ; size = 4
@MyFunction2020 PROC NEAR
; Line 7
    mov             ebp, ebp
; Line 8
    fld             QWORD PTR y$[ebp]
    fadd            QWORD PTR _[__real83ff000000000000]
    fld             QWORD PTR _[__real8400000000000000]
    fmul            QWORD PTR ST(1)
    fld             QWORD PTR _[ebp]
    fadd            QWORD PTR _[__real8480000000000000]
    fmul            ST(1), ST(0)
; Line 9
    pop             ebp
    set             20                              ; 0000014H
@MyFunction2020 END
TEXT            ENDS
```

We can see that this function takes 20 bytes of worth, because the @20 decoration at the end of the function name. This makes sense, because the function is taking **double** parameters (8 bytes each), and one **float** parameter (4 bytes each). This is a grand total of 20 bytes. We can notice at a glance, without having to actually analyze or understand any of the code, that there is only one register being accessed here: ebp. This seems strange, considering that FASTCALL passes its regular 32-bit arguments in registers. However, that is not the case here: all the floating-point parameters (even z, which is a 32-bit float) are passed on the stack. We know this, because by looking at the code, there is no other place where the parameters could be coming from.
