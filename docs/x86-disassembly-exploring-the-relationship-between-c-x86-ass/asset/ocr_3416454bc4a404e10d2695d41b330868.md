# Calling Convention Examples

```
PUBLIC          _MyFunction8
_TEXT
    x = 8              ; size = 4
y = 12             ; size = 4
    _MyFunction8 PROC NEAR
    ; Line 4
    push           ebp
    mov            ebp, esp
    ; Line 5
    mov            eax, y$[ebp]
    imul           eax, eax
    mov            ecx, x$[ebp]
    lea            eax, [eax+ecx*2]
    ; Line 6
    pop            ebp
    ret
_MyFunction8 ENDP
_TEXT
END
```

The STDCALL listing has only one difference than the CDECL listing it uses "ret 8" for self clean up of stack. Let's do an example with more parameters:

```
int STDCALLTest(int x, int y, int z, int a, int b, int c)
{
    return x * y * z * a * b * c;
```

Let's look at how this function gets translated into assembly by cl.exe:

```
PUBLIC          _STDCALLTest024
_TEXT
    SEGMENT
    x = 8              ; size = 4
y = 12             ; size = 4
z = 16             ; size = 4
a = 20             ; size = 4
b = 24             ; size = 4
c = 28             ; size = 4
_STDCALLTest024 PROC NEAR
    ; Line 2
    push           ebp
    mov            ebp, esp
    ; Line 3
    mov            eax, x$[ebp]      2
    imul           eax, DWORD PTR, y$[ebp]
    imul           eax, DWORD PTR, z$[ebp]
    imul           eax, DWORD PTR, a$[ebp]
    imul           eax, DWORD PTR, b$[ebp]
    ; Line 4
    pop            ebp
    ret            24              ; 000001B8H
_STDCALLTest024 ENDP
ENDS
END
```

The only difference between STDCALL and CDECL is that the former does stack up in callee, the later in caller. This saves a little bit in X86 due to "ret n".
