
# File Format

Immediately following the DOS Header will be the classic error message "This program cannot run in DOS mode".

## 5.5.2 PE Header

At offset 60 from the beginning of the DOS header is a pointer to the Portable Executable (PE) File header (e_l in MZ structure). DOS will print the error message and terminate, but Windows will follow this pointer to the next batch of information.

```
00000000 4D 5A 90 00 03 00 00 04 00 00 00 FF FF 00
00000010 4B 00 00 00 00 00 00 00 00 00 00 00 00 00
00000000 00 00 00 00 00 00 00 00 00 00 01 (01000000000000000000)
00000030 00 00 00 00 00 00 00 00 00 00 00 00 54 68
00000040 0E 1F BA 6D 0B 49 CD 21 2B 01 4C E5 6F
00000050 69 73 20 70 6F 67 72 61 6D 20 63 61 72
00000060 74 20 63 69 73 74 74 72 72 72 64 61 64
00000070 62 64 65 2E 0D 0D 0A 24 00 00 00 00 00
00000080 6D 6F 64 65 20 74 6F 20 72 75 6E 20 73
00000090 E1 B1 D6 6F A2 E0 D2 E6 A2 D6
000000A0 00 00 F3 6D 00 00 62 A1 D6 5A A3 E0
000000B0 DA A4 E5 D6 63 62 A2 E0 D6 62 63 E0
000000C0 00 00 00 00 00 50 45 4C 01 03 00
```

The PE header consists only of a signature, with the value 'PE' where signature shows a) this is a legitimate PE file, and b) byte order will not be considered in this chapter, and all PE files are assumed to be in 'little endian' format.

The PE header defines the number of sections in the executable file. Each section definition is 40 bytes in length. Below is a hex from a program:

```
00000000 74 65 78 74 00 00 00 00 00 00 00 0000
00000010 64 61 74 61 00 00 00 00 00 00 00 0000
00000020 72 65 73 73 00 00 00 00 00 00 00 0000
```

The structure of a section defined as follows:

| Offset | Length | Section Name / Description |
| :--- | :--- | :--- |
| 0x00 | 8 bytes | Section Name - in the above example the names are |
| 0x08 | 4 bytes | Size of the section once it is loaded to memory |
| 0x0C | 4 bytes | RVA (location) of section it is loaded to |
| 0x10 | 4 bytes | Physical size of section on disk |
| 0x14 | 4 bytes | Physical location of section on disk (from start of disk) |
| 0x18 | 12 bytes | Reserved (usually zero) used in object formats |
| 0x24 | 4 bytes | Section flags |

Common sections are:

- .text/code/TEXT - Contains executable code (machine instructions)
- .bss/TEXTBSS - Present if Incremental Linking is enabled
- .data/idata/DATA - Contains initialized data
- .bss/BSS - Contains uninitialized data

## 5.5.3 COFF Header

The COFF header is present in both COFF object files (before they are linked) and PE files where it resides. The COFF header has some information that is useful to execute, and some information more useful to object file. Here is the COFF header, presented as a C structure:

```c
struct COFFHeader {
  short Machine;
  short NumberOfSections;
  long Timestamp;
  long PointerToSymbolTable;
  long NumberOfSymbols;
  short SizeOptionalHeader;
  short Characteristics;
};
```

## 5.5.4 PE Optional Header

The 'PE Optional Header' is not 'optional' per se, because it is required in Executable files, not in COFF. The Optional header includes lots of information that can be used to pick apart the file structure, and obtain useful information about it. The PE Optional Header occurs directly after the COFF header, and some sources show the two headers as being part of the same structure. This separates them out for convenience. Here is the PE Optional Header presented as a C data structure:

```c
struct PEOptionalHeader {
	short signature; // decimal number 9054.
	char MajorLinkVersion;
	char MinorLinkVersion;
	long SizeOfCode;
	long SizeOfInitializedData;
	long SizeOfUninitializedData;
	long AddressEntryPoint; // The RVA of the code entry point
	long SizeOfBase;
	long BaseBase;
	long ImageBase;
	long SectionAlignment;
	short FileAlignment;
	short MajorOSVersion;
	short MinorOSVersion;
	short MajorImageVersion;
	short MinorImageVersion;
	short MajorSubsystemVersion;
	short MinorSubsystemVersion;
	long Reserved;
	long SizeOfImage;
	long SizeOfHeaders;
	long Checksum;
	short Subsystem;
	short DLLCharacteristics;
	long SizeOfStackReserve;
	long SizeOfStackCommit;
	long SizeOfHeapReserve;
	long SizeOfHeapCommit;
	long LoaderFlags;
	long NumberOfRvaAndSizes;
	DataDirectory[16]; // Can have any number of elements, matching the NumberOfRvaAndSizes.
}

// However, it is always 16
struct data_directory {
  long VirtualAddress;
  long Size;
}
```

Some of the important pieces of information:

- MajorLinkerVersion, MinorLinkerVersion: The version, in x.y format of the linker used to create the PE.
- AddressEntryPoint: The RVA of the entry point to the executable. Very important to know.
- SizeOfCode: Size of the .text (.code) section.
- SizeOfInitializedData: Size of .data section.
- BaseOfCode: RVA of the .text section.
- BaseOfData: RVA of the .data section.
- ImageBase: Preferred location in memory for the module to be based at.
- Checksum: Checksum of the file, only used to verify validity of modules loaded into kernel space. The formula used to calculate PE file checksums is proprietary, although Microsoft provides API calls that can calculate the checksum for you.
- Subsystem: the Windows subsystem that will be invoked to run the executable:
  - 1 = native
  - 2 = Windows/GUI
  - 3 = non-GUI
  - 5 = OS
  - 7 = POSIX
- DataDirectory: Possibly the most interesting member of this structure, which are used for setting up RVAs and sizes which details of what these structures exist in other sections. The most interesting entries in DataDirectory are below:
- IMAGE_DIRECTORY_ENTRY_EXPORT (0): Location of export directory
- IMAGE_DIRECTORY_ENTRY_IMPORT (1): Location of import directory
- IMAGE_DIRECTORY_ENTRY_RESOURCE (2): Location of resource directory
- IMAGE_DIRECTORY_ENTRY_BOUND_IMPORT (11): Location of alternate import directory

## 5.6.1 Section Flags

Section flags is a 32-bit field (each bit in the value represents a certain thing). Here are the constants defined in the WINNT.h file for the meaning of the flags:

```c
#define IMAGE_SCN_TYPE_NO_PAD 0x00000008 // Reserved.
#define IMAGE_SCN_CNT_CODE 0x00000020 // Section
#define IMAGE_SCN_CNT_INITIALIZED_DATA 0x00000040 // Section contains initialized data.
#define IMAGE_SCN_CNT_UNINITIAL_DATA 0x00000080 // Section contains uninitialized data.
#define IMAGE_SCN_LNK_OTHER 0x00000100 // Reserved.
#define IMAGE_SCN_DATA 0x00000200 // Section contains comments or other type of information.
#define IMAGE_SCN_LNK_REMOVE 0x00008000 // Section will not become part of image.
#define IMAGE_SCN_LNK_CODAT 0x00001000 // Reserved. contains codat.
#define IMAGE_SCN_NO_DEFR_SPEC_ECC 0x00004000 // Reset speculative exceptions handling bits in the TLB entries for
#define IMAGE_SCN_GREL 0x00008000 // Section content can be accessible relative to GP
#define IMAGE_SCN_MEM_FDATA 0x00008000
#define IMAGE_SCN_MEM_PURGEABLE 0x00002000
#define IMAGE_SCN_MEM_LOCKED 0x00004000
#define IMAGE_SCN_MEM_PRELOAD 0x00008000
#define IMAGE_SCN_ALIGN_1_BYTES 0x00100000
#define IMAGE_SCN_ALIGN_2_BYTES 0x00200000
#define IMAGE_SCN_ALIGN_4_BYTES 0x00300000
#define IMAGE_SCN_ALIGN_8_BYTES 0x00400000 // Default
#define IMAGE_SCN_ALIGN_16_BYTES 0x00500000 // alignment if no others are specified.
#define IMAGE_SCN_ALIGN_64_BYTES 0x00600000
#define IMAGE_SCN_ALIGN_128_BYTES 0x00700000
#define IMAGE_SCN_ALIGN_256_BYTES 0x00800000
#define IMAGE_SCN_ALIGN_512_BYTES 0x00900000
#define IMAGE_SCN_ALIGN_1024_BYTES 0x00A00000
#define IMAGE_SCN_ALIGN_2048_BYTES 0x00B00000
#define IMAGE_SCN_ALIGN_4096_BYTES 0x00C00000
#define IMAGE_SCN_ALIGN_8192_BYTES 0x00D00000

#define IMAGE_SCN_MEM_WRITE 0x08000000 // Section is writeable.
```
