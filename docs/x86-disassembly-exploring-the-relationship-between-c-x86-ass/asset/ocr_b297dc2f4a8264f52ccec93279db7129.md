# 4.3 Virtual Memory

32 bit WinNT allows for a maximum of 4Gb of virtual memory space, divided into ‘pages'
that are 4096 bytes by default. Pages not in use by the system or any of the
applications may be written to a special section on the harddisk known as the ‘paging file.’
Use of the paging file may increase performance on some systems, although high latency for
I/O to the HDD can actually reduce performance in some instances.

# 4.4 System Architecture

The Windows architecture is heavily layered. Function calls that a programmer makes
be redirected 3 times or before any action is actually performed. There is an
unignorable penalty for calling Win32 functions from a user-mode application. However, the
uside is equally unignorable: code written in higher levels of the Windows system is
easier to write. Complex operations that involve initializing multiple data structures and
calling multiple sub-functions can be performed by calling a single higher-level function.

The Win32 API calls 3 modules: KERNEL, USER, and GDI KERNEL functions are layered on top
of NTDLL, and most calls to KERNEL are simply redirected into NTDLL calls.
USER and GDI are both based on Win32K (a kernel-mode module, responsible for
the Windows ‘look and feel’), although USER also makes calls to the more-primitive
functions in GDI. This and NTDLL both provide an interface to the Windows NT kernel,
NTOSRNL (see further).

NTOSRNL is also partially layered on HAL (Hardware Abstraction Layer), but this
interaction will not be considered in this. The purpose of this layering is to allow
processor variant issues (such as location of resources) to be separate from the actual
kernel itself. A slightly different system configuration thus requires just a different HAL
module, rather than a completely different kernel.
