## 3.1.4 Debugger Techniques

### Setting Breakpoints

As previously mentioned in the section in disassemblers, a 6-line C program doing something as outputting "Hello, World!" turns into massive amounts of assembly code. Most people don't want to sift through the entire mess to find out the information they want. It can be time consuming just to find the information desires by just looking through the code. As an alternative, one can choose to set breakpoints to halt the program once it has reached a given point within the program's code.

For instance, let's say that in your program you consistently experience crashes after one particular event: immediately after closing a message box. You set breakpoints on all calls to MessageBoxA. You run your program with the breakpoints, and it stops, ready to call MessageBoxA. Executing each line one-by-one thereafter (referred to as *stepping*) through the code, and watching the program stack, you see that a buffer overflow occurs soon after the call.
