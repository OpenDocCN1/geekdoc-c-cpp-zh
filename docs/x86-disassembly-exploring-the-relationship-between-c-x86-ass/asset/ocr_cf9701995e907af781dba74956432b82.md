# Calling Conventions

Notice that fmulup is the last instruction performed again, as in CDECL example. We can infer then, without investigating too deeply, that the result is passed to the top of the floating-point stack.

Notice also that x (offset [ebp + 8]), y (offset [ebp + 16]) and z (offset [ebp + 24]) are pushed in reverse order: z is first, x is last. This means floating point parameters are passed in right-to-left order, on the stack. This is exactly the same as CDECL code, although only because we are using floating-point values.

Here is the Gcc assembly for MyFunction2:

```
.align 8
LC5:
  .long 0
  .long 1073741824
  .align 8
LC6:
  .long 0
  .long 10742666112
  .glob @MyFunction2020;
  .def _2; .type 32; .endf
@MyFunction2020:
  pushl %ebp
  movl %esp, %ebp
  subl $16, %esp
  fstpl -8(%ebp)
  fld 16(%ebp)
  fstpl -10(%ebp)
  fld
  faddp %xst, %xat(1)
  fld -6(%ebp)
  LC5:
  faddp %xst, %xat(1)
  fmulp
  fld 24(%ebp)
  LC6:
  faddp %xst, %xat(1)
  fmulp
  leave
  ret $20
```

This is a tricky piece of code, but luckily we don't need to read it very close to find what we are looking for. First off, notice that no other registers are accessed besides ebp. Again, GCC passes all floating point values (the 32-bit float, z) on the stack. Also, the floating point value is passed on the top of the floating point stack.

We can see that GCC is something strange at the beginning, taking the values from the stack [ebp + 8] and [ebp + 16], and moving them to locations [ebp - 8] and [ebp - 16]. Immediately after being moved, these values are loaded onto the floating point stack and arithmetic is performed. z isn't loaded till later, and isn't ever moved to [ebp - 24], despite the pattern.

LC5 and LC6 are constant values, that most likely represent floating point values (because the numbers themselves, 1073741824 and 10742666112 not make any sense in the context of our example functions. Notice that both LC5 and LC6 contain two .long data items, for a total of 8 bytes of storage? They are therefore most definitely double values.
