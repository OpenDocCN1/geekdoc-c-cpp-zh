int FastTest(int x, int y, int z, int a, int b, int c)

    return x * y * z * a * b * c;
}

and the corresponding list:

```
@PUBLIC @FastTest24
_TEXT1 SEGMENT
-y = -8; size = 4
-x = -4; size = 4
-z = 8; size = 4
-a = 12; size = 4
-b = 16; size = 4
-c = 20; size = 4
@FastTest24 PROC NEAR
;-z = ecz
;-y = edx
```

```
; Line 2
    push ebp
    sub ebp, esp
    mov y$[ebp], edx
    mov x$[ebp], ecx
; Line 3
    mov eax, DWORD PTR z$[ebp]
    mov eax, DWORD PTR y$[ebp]
    mov eax, DWORD PTR a$[ebp]
    mov eax, DWORD PTR b$[ebp]
    mov eax, DWORD PTR c$[ebp]
; Line 4
    mov ebp, ebp
    pop
    ret 16 ; 0000010H
```

Now we have 6 arguments, four are pushed by caller from right to left, and last two are passed again in cx/dx, as was previous example. Stack cleanup is done by ret 16, which corresponds to 4 arguments passed before called.

For FASTCALL, compiler will try to pass arguments in registers, if not enough caller will push them into stack still in or from right to left. Stack cleanup is done by callee. It is called FASTCALL because if arguments can be passed in registers (for 64bit CPU the maximum number is 6), no stack push/clean up is needed.

The name-decoration scheme of the function: @MyFunction@, here n is stack size needed for all arguments.
