# Calling Convention Examples

lea ecx, [eax + eax]

Which is clearly as the multiplication by 2. The first value accessed must have been the last value passed, which would seem to indicate that values are passed right-to-left. To prove this, we will look at the next section of the list:

```
movl    2(ebp), %edx
movl    %edx, %eax
add    %eax, %eax
add    %edx, %eax
leal    (%eax), %eax
```

the value at +12 from ebp is moved into edx. edx is then moved into eax. eax is then added to itself (eax * 2), and is added back to edx (edx + eax). remember that eax = 2 * edx, so the result is eax * 3. This is clearly the y parameter, which is furthest on the stack, and was the first passed. CDECL then on GCC is implemented by passing arguments on the stack in right-to-left order, as same as cleve.

# 12.2.2 FALLCAST

```
.global %MyFunction1@
.def	.scl	2; .type	32; .endef
%MyFunction1@:
pushl    %ebp
movl    %esp, %ebp
subl    $8, %ebp
movl    %ecx,-4(%ebp)
movl    %edx,-8(%ebp)
movl    (%eax,%ecx), %edx
leal    -8(%ebp), %eax
movl    %edx, %eax
movl    %eax, %eax
addl    %eax, %eax
addl    %edx, %eax
leal    (%eax,%ebp), %eax
leave
ret
```

Notice that the same name decoration is used as in cleve. The astute observer will already have realized that GCC uses the same trick as cleve, the fallcast arguments from their registers (ecx and edx) again onto a negative offset on the stack. Again, optimizations are turned off. cex is moved into the first position (-4) and edx is moved into the second position (-8). The CDECL example above, the value at -4 is doubled, and the value at -4 is tripled. -4 (x) is x, and -8 (y) is y. It would seem from this listing that values are passed left-to-right, although we need to take a look at the larger: %MyFunction2 example:

```
.global %MyFunction2@
.def	%MyFunction2@; .scl	2; .type	32; .endef
%MyFunction2@:
pushl    %ebp
movl    %esp, %ebp
subl    $8, %ebp
movl    %ecx,-4(%ebp)
movl    %edx,-8(%ebp)
```
