```
imull     -8(%ebp), %eax
mov      8(%ebp), %edx
incl      %edx
imull     %edx, %eax
mov      12(%ebp), %edx
add      $2, %edx
imull     %edx, %eax
mov      16(%ebp), %edx
add      $3, %edx
imull     %edx, %eax
mov      20(%ebp), %edx
add      $4, %edx
imull     %edx, %eax
leave
ret
$16
```

By following the fact that inFunction2, successive parameters are added to increasing constants, we can reduce the density of each parameter. -4 is still x, and -8 is still y. +8 gets increased by 1 (z), +12 gets increased by 2 (a), +16 gets increased by 3 (b), and +20 gets increased by 4 (c). Let's list these values:

```
z = [ebp + 8]
a = [ebp + 12]
b = [ebp + 16]
c = [ebp + 20]
```

c is the furthest down, and therefore was the first pushed. z is the highest to the top, and was therefore the last pushed. Arguments were pushed in right-to-left order, just like cl.exe.

# 12.2.3 STDCALL

Let's compare the implementation of MyFunction1 in GCC:

```
.global MyFunction1@
.def _MyFunction1@;
.scl 2;\.type 32;\.endef
_MyFunction1:
push     %ebp
mov      %esp, %ebp
leal     8(%ebp), %edx
mov      12(%ebp), %edx
mov      %edx, %eax
add      %eax, %eax
add      %edx, %eax
leal     8(%ebp), %eax
pop      %ebp
ret
$8
```

The decoration is the same as in cl.exe, so STDCALL functions (and DECL and FASTCALL for that matter) can be assembled with either compiler, and linked with either linker. The stack frame is set up, then the value at [ebp + 8] is doubled. After that, the value at [ebp + 12] is tripled. Therefore +8 is x, and +12 is y. Again, these values are pushed in right-to-left order. This function also cleans its own stack with the 'ret 8' instruction.
