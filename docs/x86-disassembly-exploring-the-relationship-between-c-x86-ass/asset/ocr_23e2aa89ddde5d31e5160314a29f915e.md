Likewise, if we want to reserve room on the stack for an item bigger than a DWORD, we can use a subtraction to artificially move esp forward. We can then access our reserved memory directly as a memory pointer, or we can access it indirectly as an offset from esp itself.

Say we wanted to create an array of bytes values on the stack, 100 items long. We want to store the pointer to the base of this array in edi. How do we do it? Here is an example:

```
sub esp, 100    ; num of bytes in our array
mov edi, esp     ; copy address of 100 bytes area to edi
```

To destroy it, we simply write the instruction

```
add esp, 100
```

# 8.4 Reading Without Popping

To read values on the stack without popping them off the stack, esp can be used with an offset. For instance, to read the 3 DWORD values from the top of the stack into eax (but without using a pop instruction), we use the instructions:

```
mov eax, DWORD PTR: [esp]
mov eax, DWORD PTR: [esp + 4]
mov eax, DWORD PTR: [esp + 8]
```

Remember, since esp moves downward as the stack grows, the data on the stack can be accessed with a positive offset. A negative offset should never be used because data 'above' the stack cannot be counted on to stay where you left it. The operation of reading from the stack without popping is often referred to as 'peeking', but since this isn't the official term for this wikibook won't use it.

# 8.5 Data Allocation

There are two areas in the computer where a program can store data. The first, the one we have been talking about, is the stack. It is a linear LIFO buffer that allows allocations and deallocations, but has a limited size. The heap is typically a non-linear data storage area, typically implemented using linked lists, binary trees, or other more exotic methods. Heaps are slightly more difficult to interface with and to maintain than a stack, and allocations/deallocations are performed more slowly. However, heaps grow as the data grows, and new heaps can be allocated when data quantities become too large.

As we will see, explicitly declared variables are allocated on the stack. Stack variables are finite in number, and have a definite size. Heap variables can be variable in number and in size. We will discuss these topics in more detail later.
