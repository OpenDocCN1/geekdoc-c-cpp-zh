On an entry of function, esp points to the return address pushed on the stack by the call instruction (that is, previous contents of EIP). Any argument in stack of higher address then EIP is pushed before the call is made; in this example, the first argument is at offset +4 from esp (EIP is 4 bytes), plus 4 more bytes before the EBP is pushed on the stack. Thus, at line 5, esp saves to the frame pointer ebp, and arguments are located at addresses ESP+8 (x) and ESP+12 (y).

For CDECL, caller pushes arguments into stack in left order. Because ret 0 is used, it is the caller who cleans up the stack.

As point of interest, note how lea is used in this function to simultaneously perform the multiplication (ecx * 2), and the addition of that quantity to eax. Unintuitive instructions like this will be explored further in the chapter of unintuitive instructions.

# 12.1.2 FASTCALL

```
int MyFunction(int x, int y)
{
    return (x * 2) + (y * 3);
}
```

becomes:

```
PUBLIC                  MyFunction@S
SEGMENT
_y = -0                 ; size = 4
_x = -4                 ; size = 4
@MyFunction@S PROC NEAR
    _x = ecx
    _y = edx
; Line 4
    push                    ebp
    mov                     ebp, esp
    sub                     esp, 8
    mov                     _y$[ebp], edx
    mov                     _x$[ebp], ecx
; Line 5
    mov                     ax, _y$[ebp]
imul                   eax
    mov                     ecx, _x$[ebp]
lea                     ax, [ecx+ecx*2]
; Line 6
    mov                     esp, ebp
    pop                     ebp
    ret                     0
@MyFunction@S ENDP
_TEXT
END
```

This function was compiled with optimizations turned off. Here we see arguments are saved in stack then fetched from stack, rather than used directly. This is because the compiler wants a consistent way to use all arguments via stack access, not only one compiler likes like that.
