
# 15.5.2 Until Loop

Like the Do-Until loop, the standard Until-Loop looks like the following:

```
until(x)
{
  //loop body
}
```

which (likewise) gets translated to the following While-Loop:

```
while(!x)
{
  //loop body
}
```

# 15.5.3 Do-Forever Loop

A Do-Forever loop is simply an unqualified loop with a condition that is always true. For instance, the following pseudo-code:

```
dofever
{
  //loop body
}
```

will become the following while-loop:

```
while(1)
{
  //loop body
}
```

Which can actually be reduced to a simple unconditional jump statement:

```
beginning:
  ;loop body
jmp beginning
```

Notice that some non-optimizing compilers will produce nonsensical code for:

```
mov ax, 1
cmp ax, 1
je label
beginning:
  ;loop body
cmp ax, 1
je beginning
loopend:
```

Notice that a lot of the comparisons here are not needed since the condition is a constant.
Most compilers will optimize cases like this.

# 16 Loop Examples

## 16.1 Example: Identify Purpose

What does this function do? What kinds of parameters does it take, and what kind of results (if any) does it return?

```
push ebp
mov ebp, esp
mov esi, [ebp + 8]
mov ebx, 0
mov eax, 0
mov ecx, 0
_Label_1:
mov ecx, [esi + ebx * 4]
add eax, ecx
inc ebx
mp ebx, 100
je _Label_1
mov esp, ebp
pop ebp
ret 4
```

This function loops through an array of 4 byte integer values, pointed to by esi, and adds each entry. It returns the sum in eax. The only parameter (located in [ebp+8]) is a pointer to an array of integer values. The comparison between ebx and 100 indicates that the input array has 100 entries in it. The pointer offset [esi + ebx * 4] shows that each entry in the array is 4 bytes wide.

## 16.2 Example: Complete C Prototype

What is this function's C prototype? Make sure to include parameters, return values, and calling convention.

```
push ebp
mov ebp, esp
```

```
mov esi, [ebp + 8]
mov ebx, 0
mov eax, 0
mov ecx, 0
_Label_1:
mov ecx, [esi + ebx + 4]
add eax, ecx
inc ebx
cmp ebx, 100
jns _Label_1
mov esp, ebp
pop ebp
ret 4
```

Notice how the ret cleans its parameter off the stack? That means that this function is a STDCALL function. We know that the function takes, as its only parameter, a pointer to an array of integers. We do not know, however, whether the integers are signed or unsigned, because the je command is used for both types of values. We can assume one or the other, and for simplicity, we can assume unsigned values (unsigned and signed values, in this function, will actually work the same way). We also know that the return value is a 4-byte integer value, of the same type as is found in the parameter array. Since the function devent have a name, we can just call it 'MyFunction', and we can call the parameter 'array' because it is an array. From this information, we can determine the following prototype in C:

```
unsigned int STDCALL MyFunction(unsigned int *array);
```

## 16.3 Example: Decompile To C Code

Decompile this code into equivalent C source code.

```
push ebp
mov ebp, esp
mov esi, [ebp + 8]
mov ebx, 0
mov eax, 0
mov ecx, 0
_Label_1:
mov ecx, [esi + ebx + 4]
add eax, ecx
```

```
inc ebx
cmp ebx, 100
jne _Label_1
mov esp,ebp
pop ebp
ret 4
```

Starting with the function prototype above, and the description of what this function does, we can start to write the code for this function. We know that this function initializes ebx, eax, and ecx before the loop. However, we can see that ecx is being used as a simple intermediate storage location, receiving successive values from the array, and then being added to ecx.

We will create two unsigned integer values, a (for eax) and b (for ebx). We will define both a and b with the register qualifier, so that we can instruct the compiler not to create space for them on the stack. For each loop iteration, we are adding the value of the array, at location eax to the running sum, eax. Converting this to our a and b variables, and using C syntax, we see:

```
a = a + array[b];
```

The loop could be either a for loop, or a while loop. We see that the loop control variable, b, is initialized to 0 before the loop, and is incremented by 1 each loop iteration. The loop tests b against 100, after it gets incremented, so we know that b never equals 100 inside the loop body. Using these simple facts, we will write the loop in 3 different ways:

First, with a while loop:

```
unsigned int STDCALL MyFunction(unsigned int *array)
{
    register unsigned int b = 0;
    register unsigned int a = 0;
    while(b != 100)
    {
        a = a + array[b];
        b++;
    }
    return a;
}
```

Or, with a for loop:

```
unsigned int STDCALL MyFunction(unsigned int *array)
{
    register unsigned int b;
    register unsigned int a = 0;
    for(b = 0; b != 100; b++)
    {
        a = a + array[b];
    }
    return a;
}
```

And finally with a do-while loop:

```
unsigned int STDCALL MyFunction(unsigned int *array)
{
    register unsigned int b = 0;
    register unsigned int a = 0;
    do
    {
        a = a + array[b];
        b++;
    } while(b != 100);
    return a;
}
```

# 17 Variables

We've already seen some mechanisms to create variables. This chapter will talk about other techniques, including global variables.

## 17.1 How to Spot a Variable

Variables come in two distinct favors: those on the stack, and those global variables.

## 17.2 Spot a Variable

Variables come in two types: those that are hardcoded and those that change.

### Hardcoded address

Anything hardcoded is de-facto constant. Hardcoded addresses are often used in jump tables. Example of a hardcoded address:

```
mov eax, 0x401000
```

### Example of non-hardcoded

Variables that are not hardcoded are calculated at runtime. Example of a non-hardcoded address:

```
mov eax, [ebp+8]
```

## 17.3 .BSS and .DATA sections

Both .bss and .data sections contain values which can change. Typically, variables initialized to a non-zero value in the source are allocated in .data section. Variables that are not initialized, or initialized with a zero value, can be allocated to .bss section. Because all values of .bss variables are guaranteed to be at the start of the program, there is no need for the linker to allocate space in the binary file. Therefore, bss sections do not take space in the binary file, regardless of their size.

## 17.4 "Static" Local Variables

Local static maintain their value across function calls, and therefore cannot be created on the stack like local variables. How are static variables created? Let's take a simple example:

```
void MyFunction(int a)
{
    static int x = 0;
    printf("my number: %d\n", x);
    printf("%d\n", a);
}
```
