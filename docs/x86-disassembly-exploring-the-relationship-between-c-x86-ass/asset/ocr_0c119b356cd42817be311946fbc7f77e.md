# 12.2 GNU C Compiler

We will be using 2 example C functions to demonstrate how GCC implements calling conventions:

```
int MyFunction1(int x, int y)
{
    return (x * 2) + (y + 3);
}

int MyFunction2(int x, int y, int z, int a, int b, int c)
{
    return x * y * (z + 1) * (a + 2) + (b + 3) * (c + 4);
}
```

GCC does not have commandline arguments to force the default calling convention to change CDEC6 (for C), so they will be manually defined in the text with the directives: __decl, __fastcall, and __stdcall.

# 12.2.1 CDECL

The first function (MyFunction1) provides the assembly listing:

```
_MyFunction1:
push %ebp
mov %ebp, %eax
mov 8(%ebp), %eax
leal (%eax), %ecx
mov 12(%ebp), %edx
addl %edx, %eax
addl %eax, %ecx
addl %edx, %eax
leal (%ecx), %eax
pop %ebp
ret
```

First of all, we can see the name-decoration is the same as in cl.exe. We can also see that the instruction doesn't have an argument, so the calling function is cleaning the stack. However, since GCC does not provide us with the variable names in the listing, we have to deduce which parameters are which. After the stack frame is set up, the first instruction of the function is "mov 8(%ebp), %eax". One we remember (or learn for the first time) that GAS instructions have the general form:

```
instruction src, dest
```

We realize that the value at +8 - %ebp (the last parameter pushed on the stack) is moved into eax. The leal instruction is a little more difficult to decipher, especially if we don't have any experience with GAS instructions.
