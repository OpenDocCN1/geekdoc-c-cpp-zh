# DataDirectory

Possibly the most interesting member of this structure, which are used for setting up RVAs and sizes which locate various data structures, The details of what these structures exist in other sections of this page, but the execution environment of a module. The most interesting entries in DataDirectory are below:

+   * IMAGE_DIRECTORY_ENTRY_EXPORT (0) : Location of the export directory
* IMAGE_DIRECTORY_ENTRY_IMPORT (1) : Location of the import directory
* IMAGE_DIRECTORY_ENTRY_RESOURCE (2) : Location of the resource directory
* IMAGE_DIRECTORY_ENTRY_BOUND_IMPORT (11) : Location of alternate import-binding directory

# 5.6 Code Sections

The PE Header defines the number of sections in the executable file. Each section definition is 40 bytes in length. Below is an hex lex from a program I writing:

```
2E74657874000000000000000100000080500000.text
0000000000000000000000002000000000000000
2E64617461000000010000002000000086500000.data
0000000000000000000000004000000040000000
2E726573730000000000000002000000000000000.bes
00000000000000000000000080500000
```

The structure of a section defined as follows:

| Offset | Length | Section Name |
|---|---|---|
| 0x00 | 8 bytes | Section Name - in the above example the names are |
| .text | 4 bytes | Size of the section once it is loaded to memory |
| 0x0C | 4 bytes | RVA (location) of section it is loaded to |
memory |
| 0x10 | 4 bytes | Physical size of section on disk |
| 0x14 | 4 bytes | Physical location of section on disk (from start of |
disk) |
| 0x18 | 12 bytes | Reserved (usually zero) (used in object formats) |
| 0x24 | 4 bytes | Section flags |

A PE loader will place the sections of the executable image at the locations specified by these sections (relative to the base address) and usually the alignment is 0x1000, which matches the size of pages on the x86

Common sections are:

+   1. .text/code/CODE/TEXT - Contains executable code (machine instructions)
2. .testbss/TEXTBSS - Present if Incremental Linking is enabled
