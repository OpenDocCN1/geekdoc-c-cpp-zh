# Selecting and Implementing Solutions

In addition to maintaining suitable backups of data, in the cloud environment it is also important to develop a means to back up and restore server configurations. In an optimal situation the backup and replication approach includes the ability to deploy servers and data onto different cloud providers. Although this is likely to be an issue only for libraries adopting PaaS and IaaS solutions, it is important for libraries looking toward SaaS solutions to determine whether service providers have a plan for managing backup, recovery, and replication of services. There is an emerging set of businesses focused on service replication across cloud providers that fall into the NIST category of cloud broker. One example is RightScale (http://rightscale.com). This service supports multiple IaaS providers and synchronizes data and services back to a local private cloud environment or to other public clouds.

Regardless of the type of cloud or virtualized solution selected, replication and backup are key issues. Some important considerations in these decisions: (1) How important is a secondary cloud or localized service backup? (2) Which service works best with local capacity? (3) How important are short-, mid-, and long-term backups? (4) Is continuous data protection more important than durable long-term backups? (5) How important are industry standard backup platforms as compared to proprietary systems?

This fifth consideration can be a major stumbling block for libraries seeking to store data in the cloud. For example, libraries that are using the cloud as their primary digital object and metadata storage platform need to identify a solution that relies on traditional storage, version control, and bit-checking methods. In contrast, cloud and virtualization platforms make it much easier to take snapshots of file systems and save space by recording only the difference between versions of a file system. This process is highly efficient both for taking backups and restoring them, but it creates issues for organizations that want to have access to archived data using traditional file system tools (e.g., mountable file system and compression tools).

# Service-Level Agreements and Terms of Service

SLAs and terms of service are important documents that define the relationship between cloud computing providers and subscribers. SLAs define the level of service assured with a cloud service, including elements such as system uptime, system security, support contacts, and response-time agreements. Libraries may be familiar with SLA elements given their experience negotiating with electronic resource vendors.
