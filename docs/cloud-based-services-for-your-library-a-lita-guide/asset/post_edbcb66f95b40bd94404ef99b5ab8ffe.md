
## Service Complexity, Sustainability, and Durability

SaaS solutions are often selected because they offer a highly functional service with simple administrative requirements. By moving the responsibility for system uptime, durability, security, and upgrades to the vendor, the library removes the need to manage these tasks itself. The greatest source of complexity for SaaS systems often comes when trying to connect multiple systems and vendors, or trying to implement new services that leverage the abilities of an SaaS service. In these cases it may be necessary to write data transformation or transfer applications that pose their own complex problems.

Another key advantage to SaaS services is that the vendor providing the service assures their durability. A key risk in this area is the sustainability of a service and the limited number of options for libraries that adopt SaaS services that eventually disappear. Though less common for paid services, free services often change terms or functions and in some cases disappear altogether. Thus libraries should be cautious with regards to using SaaS services that offer no assurance of long-term stability or are still in the development stage.

## Service Cost

Calculating costs and ROI for SaaS services can be easier than with PaaS and IaaS services, given the fact that SaaS services often feature a longer subscription term (e.g., year-to-year terms rather than month-to-month terms). However, it can be difficult to compare the costs of SaaS services with those of PaaS, IaaS, and their nonvirtualized counterparts, given the difficulty of identifying hidden or soft costs. Libraries are, however, likely to have expertise in handling these types of subscription models and should be able to project costs over a multiyear period. This longer-term cost projection can be useful in helping libraries decide if an SaaS solution is a better fit than other alternatives.

## Service Portability and Interoperability

The ability to integrate SaaS solutions with other systems depends largely on the functions associated with the systems. In larger library-focused SaaS providers it is increasingly common to implement APIs that enable access to data and back-end service elements. Migrating away from SaaS solutions can be difficult because the process of acquiring and managing the data associated with the service can be made more difficult if the organization has lost (or never had) the capacity to work with that data.

## PaaS Using Traditional Server-Type Hosting

PaaS offers libraries seeking customized solutions an opportunity to implement web-based services without having to understand the complex inner workings of system administration. Traditional PaaS solutions offer varying levels of access to an IT system and tend to feature a form of LAMP (Linux, Apache, MySQL, and PHP) support. PaaS using a traditional server hosting platform tends to automate system management but often does not include dedicated server access, root access, or the ability to install new system-level tools (e.g., database platforms, scripting languages). Because of this, PaaS solutions should be carefully evaluated to ensure that the services supported match those required and that there is support for system backups, sufficient security measures at the vendor level, and no privacy or data ownership issues raised by using the service.

The server-style solutions featured in this section differ from other PaaS solutions in that they focus on providing limited computational power and storage space but a relatively wide range of IT services. These services often include database management, firewall protection, domain name system (DNS) resolution, e-mail hosting, and other core IT services. These server-based solutions feature a graphical administrative interface (e.g., cPanel) platform that simplifies the implementation and management of web services (e.g., WordPress, database applications, custom-developed PHP, Perl, or Python applications). Often these solutions are based on some form of a LAMP environment or some other common web application framework (Ruby on Rails, Python/Django). These solutions provide a robust IT framework that is best suited to website hosting and customized applications but can also be adapted to run more complex applications such as small-scale library catalogs, DAMSs, and other library-specific services. These solutions can be grouped into one of three types: shared web hosting, virtual private server hosting, and dedicated server hosting. Each of these types has strengths and weaknesses.

### Service Types and Providers

PaaS providers offer a good environment for website hosting, content management system hosting, development of web services using specific resources, and ad-hoc use of systems for development or other single-purpose uses. Commercial providers include DreamHost (http://dreamhost.com), HostMonster (http://hostmonster.com), and BlueHost (http://bluehost.com), as well as services run specifically for library environments such as LISHost. These systems are particularly useful for small to medium-sized libraries, libraries exploring virtualized computing for the first time, and libraries seeking to empower staff who have an IT-focused skill set but limited time. The graphical control panel used by PaaS server providers simplifies configuration tasks and eliminates the need to take on infrastructure-level IT management tasks such as operating system maintenance, hardware management, and LAMP stack maintenance. At the same time, it preserves the ability to configure back-end applications. Not every vendor offers these functions, however, and the variation of services and options can make it difficult to select a provider.

Generally speaking, it is important to focus on required features (e.g., hosting functionality, account/data privacy, server location and data center quality, guaranteed capacity, and long-term company viability) and select a solution that fits those needs. PaaS server providers may oversell capacity, assuring customers “unlimited data and bandwidth,” but these assurances typically come with caveats and restrictions on content or hosting services (e.g., no streaming of video, no long-term object storage) that reduce the value of these features. Low-cost PaaS providers tend to avoid strict SLA agreements but are likely to provide a “service-level indication” without any clauses for compensation for downtime or any firm guarantee of uptime. More expensive PaaS providers support elaborated SLAs, expand access to the server to include higher levels of administrative access (e.g., root or super-user access), and shy away from overselling capacity, instead leasing a specific amount of disk space, CPU capacity, and application memory to subscribers. The following three sections explore three broad types of PaaS providers in more detail.

### Shared Virtual Server

A shared virtual server entitles you to reserved storage resources on a virtualized platform. These providers may feature “unlimited” disk space and bandwidth, but review of their SLAs show that the disk space is limited to the provision of web services hosted on the box and that they do not include backups or storage for file serving purposes. In addition, these providers may restrict CPU use and may not guarantee available memory, making these solutions best suited for website services, small-scale database hosting, or other services that do not consume large amounts of CPU or RAM. Because of these features, shared virtual servers come with the highest amount of risk in a PaaS environment but at the lowest cost. In shared virtual server environments it can be difficult to determine the robustness or geographic/legal location of the data center, and access in these environments is typically limited to web-based control panels or SSH.

### Dedicated Virtual Server

A dedicated virtual server is a server to which a user account has exclusive access. Dedicated virtual servers are likely to have a web-based management console and are more likely to allow substantial access to the system for changes to application configuration and versions. At the same time, a dedicated virtual server is likely to be managed at the operating system level by the host company and to feature customized support including tutorials, guides, and even real-time assistance. Dedicated virtual servers include CPU, memory, and disk space allocations along with a level of separation from users not found in shared virtual server environments. As with shared virtual server environments, care should be taken to understand fully the security, privacy, replication, and management features of a dedicated virtual server environment. Legal and technical risks associated with running in a dedicated virtual server environment mean that it is important for providers to have automatic failover capabilities to ensure that a dedicated virtual server is not tied to specific hardware.

Dedicated virtual server environments are capable of running small-scale library-specific applications but are likely too small for discovery or DAMS services that require significant memory and disk storage. Dedicated virtual server environments are best suited for libraries with specific needs not met by hosting in a shared virtual server environment but that also do not want the cost or expertise requirements that come with dedicated server or IaaS solutions.

### Dedicated Physical Server

Dedicated physical servers more closely match a managed data center model than the other cloud computing and virtualization models discussed in this book. Many vendors offer dedicated physical servers as an alternative for organizations seeking more capacity or isolation but in a managed environment. This management level is likely to include web-based control panels and super-user access to the machine and does have even higher capacity than dedicated virtual servers. The physical isolation is likely to come with virtual network isolation as well, so that one's server is not accessible by other customers in the data center. This can be an advantage if there are significant concerns over security and privacy, but these advantages are most likely outweighed by the risks associated with being tied to specific IT hardware.
