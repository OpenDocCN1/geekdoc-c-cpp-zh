This actually may be preferable for libraries that use multiple database platforms in their information systems. Although this solution requires that libraries take on database management, it also offloads backup responsibilities. Linode's managed backup service takes care of the backup scheduling and rotation.

Cloud providers do experience occasional downtime, and this is a considerable risk with a single-vendor cloud. There are ways of mitigating this risk, however, for vendors that include multiple independent cloud zones. In the difficulty experienced in 2011, Amazon customers found out how important a redundant and easily replicated cloud infrastructure can be (Cockcroft et al. 2011; Tonjes 2011). In fact, Netflix's approach was to build a PaaS environment using the Amazon platform as a way of addressing this issue (Cockcroft 2012). In the Netflix architecture, emphasis was put on designing scalability, application publishing, and management using continuous integration tools, database storage using Cassandra (http://cassandra.apache.org), and prebuilt AMIs to deploy operational instances (Chan 2012; Cockcroft 2012). One of the interesting outcomes noted in Cockcroft's presentation on system architecture was a realignment of IT development away from system management roles (e.g. database administration, system administration).

Another challenge with this approach is the inability to move to a new cloud provider without considerable development time and expense. Although these providers support machine and data exports, the reliance on vendor-provided management services means that migration includes considerable learning and design work. Finally, as our cost analysis shows, relying on a single vendor may push libraries into paying for more capacity than they need in certain areas. Vendors have different cost models for network traffic, storage space, server size, and core versus add-on services. A single-vendor cloud would make it difficult to manage these costs over time as service needs change.
