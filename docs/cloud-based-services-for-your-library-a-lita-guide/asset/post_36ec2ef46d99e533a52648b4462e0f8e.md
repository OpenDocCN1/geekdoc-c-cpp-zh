## Budgeting and Service Subscription

Libraries turning to library-specific virtualization and cloud solutions often find that the budgeting and subscription terms provided by the vendor recognize the approaches typical of that industry, but they may also find that cloud providers from other areas are not used to working with libraries and other nonprofit institutions. In many of the cloud services explored in chapters 4 and 5, subscription terms are measured in hours or months rather than annually based. This can make budgeting and cost prediction more difficult and challenging. In addition, many cloud providers including Amazon and Microsoft rely primarily on credit cards as a form of payment and do not support purchase orders or other long-term subscription models by default.

Several PaaS and SaaS solutions are specifically for libraries. These include for-profit companies such as SerialsSolutions (http://serialssolutions.com), LibLime (http://liblime.com), Equinox (http://esilibrary.com), and ByWater Solutions (http://bywatersolutions.com/) as well as nonprofit organizations such as Lyrasis (http://lyrasis.org), OCLC (http://oclc.org), DuraCloud (http://duracloud.org), and Omeka (http://omeka.net). These nonprofit organizations (with the exception of OCLC) support the implementation of open-source platforms (e.g., DSpace and Omeka) that might not otherwise be implementable by libraries. For libraries interested in non-library-specific application hosting, there are companies such as LisHost (http://lishost.org) that focus on providing more generalized web hosting services for libraries. Selecting one of these cloud providers sidesteps some of the budgeting and payment issues libraries are likely to encounter with other cloud providers but also limits the platforms available for cloud adoption. Whether this is an issue depends entirely on organizational factors and preferred services.

## Disaster and Recovery Planning

In a traditional IT environment, disaster planning involves creating system backups, creating a service restoration plan, managing an IT infrastructure to enable redundancy and availability, and colocating backups and valuable data in multiple locations. Cloud computing and virtualized solutions enable new approaches to durable and disaster-proof service but also pose new requirements in the implementation of these services, including replication across cloud regions, recovery plans that include multiple cloud providers, and backups on cloud-based storage systems. Reese (2009, 119) discusses a range of issues related to disaster recovery in the cloud including data backups, server configuration storage, server redundancy, and disaster monitoring. Velte et al. (2009, 37) mention several benefits of using the cloud for backup including reduced data loss, simplified monitoring, faster recovery, and improved security.

Whatever the benefits, a cloud-based backup, replication, and recovery strategy needs to be considered within the context of organizational risk tolerance and legal liability. For example, when organizations shift away from local IT infrastructure to cloud platforms there is an increased need to support service replication across multiple cloud providers, backup data on multiple cloud networks, and automate processes to ensure that the library can leverage the backup, replication, and scalability features typically associated with cloud platforms. On February 29, 2012, for example, a leap day software bug in the Microsoft Azure platform caused systemwide downtime for Azure customers for several hours (Babcock 2012). Likewise, in 2011 Amazon had its own issues when a misconfigured network caused widespread problems in its Virginia cloud region (Babcock 2011). One of the key challenges to a manageable and successful backup and recovery policy for libraries moving to cloud platforms is maintaining consistent approaches across multiple cloud providers. Another complication is ensuring that your library is in compliance with organizational policies. This can be complicated by the fact that many IT organizations have backup procedures geared toward traditional backup methods (e.g., tape-based backups or server-rebuild processes). In a cloud environment, bandwidth limitations and local infrastructure can make backing up to local tape difficult, and the cost of transferring backup data sets across the network can make this approach cost prohibitive. There are cloud-based services that support low-cost, high-durability backups including BackBlaze (http://backblaze.com) and MozyPro (http://mozypro.com), but overall the trend is away from tape backups for cloud-based services. Some traditional backup applications such as Amanda (www.amanda.com) have been updated to leverage the open storage of Amazon S3 using open-source industry-standard backup tools. This may be preferable to system or volume snapshots, which are available only from within the cloud provider's system. In contrast, Amanda uses traditional archiving and compression tools that do not rely on a proprietary system. By backing up to S3, libraries can preserve the ability to download their backups at any time or via an automated process. It is worth noting that there are services that move in the other direction (e.g., using S3 as the redundant backup for local data). For example, using the Amazon Storage Gateway (http://aws.amazon.com/storagegateway/), subscribers can replicate data from local or other cloud-based services in the Amazon S3 system. This provides users the benefit of backing up to a service with a defined SLA and in a redundant and geographically replicated system. In 2012 Amazon also introduced an S3-backed storage solution called Amazon Glacier (http://aws.amazon.com/glacier/) that features built-in data replication and fixity checking services. Glacier is marketed as a tape-backup replacement service and achieves cost reductions by gearing the service around long-term storage assurances rather than immediate retrieval.

## Selecting and Implementing Solutions

In addition to maintaining suitable backups of data, in the cloud environment it is also important to develop a means to back up and restore server configurations. In an optimal situation the backup and replication approach includes the ability to deploy servers and data onto different cloud providers. Although this is likely to be an issue only for libraries adopting PaaS and IaaS solutions, it is important for libraries looking toward SaaS solutions to determine whether service providers have a plan for managing backup, recovery, and replication of services. There is an emerging set of businesses focused on service replication across cloud providers that fall into the NIST category of cloud broker. One example is RightScale (http://rightscale.com). This service supports multiple IaaS providers and synchronizes data and services back to a local private cloud environment or to other public clouds.

Regardless of the type of cloud or virtualized solution selected, replication and backup are key issues. Some important considerations in these decisions: (1) How important is a secondary cloud or localized service backup? (2) Which service works best with local capacity? (3) How important are short-, mid-, and long-term backups? (4) Is continuous data protection more important than durable long-term backups? (5) How important are industry standard backup platforms as compared to proprietary systems?

This fifth consideration can be a major stumbling block for libraries seeking to store data in the cloud. For example, libraries that are using the cloud as their primary digital object and metadata storage platform need to identify a solution that relies on traditional storage, version control, and bit-checking methods. In contrast, cloud and virtualization platforms make it much easier to take snapshots of file systems and save space by recording only the difference between versions of a file system. This process is highly efficient both for taking backups and restoring them, but it creates issues for organizations that want to have access to archived data using traditional file system tools (e.g., mountable file system and compression tools).
