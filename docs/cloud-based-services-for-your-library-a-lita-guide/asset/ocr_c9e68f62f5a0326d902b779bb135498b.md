# Ability to budget carefully.

Budgeting for IaaS systems is much less predictable than for SaaS and PaaS systems. For example, organizations must be able to predict bandwidth, storage utilization, and CPU requirements for a service and project capacity needs over time. IaaS providers including Amazon offer lower costs for organizations willing to commit for a specified period, so the ability to project resource utilization over one to three years can lead to sizable cost savings. This is a good thing for organizations but requires system administrators to know when organizations need to renew their reserved instance terms. Failing to renew ahead of the expiration date leads to a dramatic unplanned increase in server run-time costs. Though budgeting is often an administrative function, the many moving pieces of an IaaS infrastructure mean that IT personnel are more likely to be asked to determine what it will cost to run an IT service.

# Service Complexity, Sustainability, and Durability

One of the main drawbacks of IaaS platforms is their complexity. Libraries often find that an IaaS service is more complex than traditional server platforms, and they often do not have the IT resources to ensure sustainable services. Some keys to avoiding unnecessarily complex services include using a single server platform and application environment, using a single approach for managing all services, and avoiding complex service tuning that does not add sizable improvements. For example, in a traditional IT environment it is preferable to use a logical volume management (LVM) approach that allows volumes to span across multiple disks. By using LVM, IT departments can dynamically add space to volumes without downtime or complex rebuilding of disk space. The major downside of this approach is that LVM requires configuration files and a static set of disks. In a cloud environment it is much easier to image, increase, detach, and reattach volumes. This to some extent mitigates the benefits offered by LVM and has the added benefit of enabling easy imaging, replication, and restoration of disk images without having to keep track of LVM configuration files and volume associations.
