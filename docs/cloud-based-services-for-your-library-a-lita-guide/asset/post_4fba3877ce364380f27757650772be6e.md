Although the technical definitions of virtualization and cloud computing are very different from the operational definitions of outsourcing and service hosting, this book intentionally blurs the lines between cloud-based approaches such as software as a service (SaaS) and SaaS-style service hosting as provided by library IT vendors. ## CLOUD COMPUTING

Two organizations, Gartner and the National Institute of Standards and Technology (NIST), are regarded as having created well-formed definitions of cloud computing. Both approach this definition by discussing different facets of cloud computing services (Mell and Grance 2011; Smith 2010). NIST broadly defines cloud computing as “a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (e.g., networks, servers, storage, applications and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction” (Hogan et al. 2011). It additionally qualifies cloud computing through the use of three service models: SaaS, platform as a service (PaaS), and infrastructure as a service (IaaS). The NIST cloud computing framework defines features common to all cloud computing environments and differentiates cloud service models from cloud deployment models (Mell and Grance 2011).

Table 1.1 lists the characteristics and models of the NIST definition of a cloud environment. It is useful to understand that, although cloud solutions all employ a service model, a deployment model, and service features, each solution will likely include a different combination of service features and deployment models. For example, both Microsoft Azure and Amazon Web Services (AWS) offer a mix of PaaS and IaaS solutions, and RightScale and Rackspace help users bridge between public and private clouds. In addition, it is increasingly common for cloud providers to define custom cloud solutions for security, IT management, identity management, and other information services using the “as-a-service” model. This fragmentation can make it difficult for users to differentiate service types and points to the complex set of relationships that underlie a given cloud service.

### Essential Characteristics

The NIST model features several essential characteristics that can be used to help differentiate cloud services. These characteristics describe an environment in which IT services can be allocated by the end user (e.g., on-demand self service), can be scaled as needed (e.g., rapid elasticity), and which are paid for by a subscription as opposed to a one-time purchase fee (e.g., measured service). NIST essential characteristics also describe an environment in which services are available across the network and IT resources are colocated to facilitate sharing and scaling. In contrast, traditional IT environments focus on locally hosted hardware purchased through one-time capital expenditures, planned as opposed to on-demand capacity, and static or more slowly changed service offerings. It is important to consider these features (e.g., elasticity, scalability, on-demand) when examining cloud solutions, but it is equally important to consider which features are preferable for a given service. For example, in the library marketplace, outsourced or hosted IT services and dedicated SaaS providers often offer cloud services that are neither on-demand nor elastic but which may make use of these characteristics to create and manage their underlying cloud infrastructure.

### Service Models

SaaS, PaaS, and IaaS service models are the most common ones discussed in cloud computing definitions, but there are situations in which the distinctions between them are unclear. The “as-a-service” approach to cloud computing includes database as a service (DaaS; Howe et al. 2011), security as a service (SECaaS; Hussain and Abdulsalam 2011), and identity as a service (Krüger and Grabski 2009). The reuse of acronyms as well as a broadening of definitions in cloud computing can make it difficult for information organizations to identify and select services. At the same time, companies are able to provide niche services that would be difficult or too expensive for smaller organizations to implement. For example, CloudFlare (www.cloudflare.com) protects against denial of service and traffic load spikes by managing domain name service (DNS) and service replication across multiple cloud providers without the required load balancing and security configuration required for this type of service. By taking advantage of such a service, an information organization can build robustness into its IT configuration without the costs that would have been a necessity in more traditional IT environments. As our exploration of these service models in chapters 4 and 5 shows, the model a library chooses largely depends on factors such as local expertise, IT service requirements, organizational policy, and local preference.

### Deployment Models

NIST’s four deployment models (Fang et al. 2011) differentiate internal and external environments and examine approaches to cloud computing that serve specific communities. In this model, private clouds are defined as an environment in which the customer has exclusive physical or virtual access to its computing services. These services may be on-site or remotely hosted by a cloud provider, but typically they involve dedicated hardware and are available only via private physical or virtual networks. In community cloud environments a group of related customers have shared access to computing services. Although the actual computing services may be run in-house or by the cloud provider, community clouds tend to feature shared access to some or all resources in the cloud environment. Government clouds or educational clouds are good examples of community and private clouds. These environments may be run on dedicated hardware and networks, as in the case of private clouds, but may also be run on hardware that serves other cloud customers but with virtual isolation. The Amazon government computing cloud is just one of many community/private cloud solutions available. In contrast to private and community clouds, public cloud solutions feature a cloud-computing service and infrastructure that is made available to the general public. Though public cloud platforms are open to all subscribers, they often feature security layers that allow subscribers to create virtually private environments that are as secure as private clouds. For example, the AWS platform operates largely as a public cloud solution but is designed so that customer IT resources are virtually isolated from Amazon employees and other subscribers. Hybrid clouds are the “catch-all” of models in that they include features of two or more types of cloud systems (public, private, or community) but are bound together for data or application sharing.

There are both risks and advantages of scale that go with each deployment approach. For instance, in environments where physical security and virtual privacy are of utmost importance, public clouds are likely not the best solution. Likewise, where economies of scale and interoperability are important, private clouds are not likely to be best suited. It is important to be familiar with these models; understanding them helps contextualize options for cloud computing adoption. Good explanations that focus on the intersection between service models and deployment models have been prepared by various authors (Mell and Grance 2011; Metz 2011) and further inform on the differences between them.

In addition to understanding the distinction between service and deployment models, it is important to understand the roles of cloud providers and subscribers.
