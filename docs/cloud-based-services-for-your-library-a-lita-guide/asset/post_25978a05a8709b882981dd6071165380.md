## Issues

As the review of PaaS providers shows, the range of services, platforms, and management tools supported varies, and as a result it may be difficult for libraries that rely on off-the-shelf software to leverage these tools. Dedicated PaaS platforms, however, provide considerable capabilities for developers seeking to create and test new applications and likely will be more widely adopted by library system vendors and open-source development communities in the future. In addition to the lack of support of off-the-shelf library software, these types of PaaS systems require new approaches to SSL configuration, DNS name mapping, system backups, and application configuration and deployment. The techniques required often mean that the solutions are more durable than when working with traditional server-based IT approaches, but it can be difficult to learn and incorporate these techniques, particularly because IT departments have traditionally relied on server-based models that more closely match IaaS environments. For these reasons, libraries may find themselves unable to use this type of PaaS platform unless they can dedicate the time required to modify and manage applications so that they work in this environment. Despite this current issue with adoption, dedicated PaaS solutions offer economies of scale, low-cost or free use levels, and a level of durability that can be difficult to achieve without considerable expertise and investment of time and resources using other approaches.

## Expertise Required

In addition to the expertise required for server-type management of PaaS applications, dedicated PaaS solutions require specialized knowledge of the system being implemented, familiarity with version management solutions, and an understanding of how to implement and manage database structures in a nonserver environment. For example, Heroku allows one to use several different database platforms, each of which has its own advantages and drawbacks. Being able to differentiate between database and software platforms as well as manage and deploy applications via command line tools can make getting started with dedicated PaaS systems more difficult than working with server-based PaaS or IaaS solutions. As many of the reviewed services point out, these systems are geared toward software

developers who need production-level support for their applications but do not have the time or resources to manage the required infrastructure.

## Service Complexity, Sustainability, and Durability

PaaS solutions tend to be more complex than traditional IT systems. There are commonly more dependencies required, and each platform takes a unique approach to the deployment, configuration, and management of applications. At the least, a dedicated PaaS environment needs to include an application platform, a persistent digital object storage platform, and a database platform. In a sufficiently distributed architecture, each of these systems should persist without depending on the other. This enables the application to be upgraded, scaled, and redeployed without affecting valuable data and digital objects. One benefit of PaaS application environments is that they tend to include built-in monitoring, replication, and scaling features. Though the default levels of these functions are likely to suffice for most libraries, understanding how to scale these services or reconfigure them to support application deployment on multiple PaaS platforms is necessary for large-scale applications. In addition, for libraries seeking to utilize multiple PaaS providers to make their applications more durable, an external DNS system must be employed to enable easy switching from one service provider to another.

Although there are several issues that libraries must consider when using dedicated PaaS platforms, a key advantage of these systems is their built-in ability to scale and persist across service outages. Amazon’s Elastic Beanstalk, for example, includes the ability to scale automatically to handle increased traffic and features multizone redundancy to ensure that an application remains operational even if portions of the cloud infrastructure fail. Likewise, Heroku offers automatic replication and scalability that make it easier to test and deploy system updates. Finally, PaaS environments get their quick configuration speed and flexibility by using shared cloud services. The Zend PaaS (http://zend.com) framework, for example, integrates tightly with RightScale to launch and manage infrastructure-level services onto which are deployed multiple customers. This makes choices about system durability and long-term sustainability more complex and dependent on factors such as local expertise, tolerance for provider lock-in, and ability to implement services on multiple cloud providers.

## Service Cost

Whereas PaaS server solutions offer some form of ongoing subscription cost, dedicated PaaS solutions seek to make these service both more affordable and

customizable by allowing the subscriber to use only the services required at any given time. In addition, many products such as Heroku, RedHat OpenShift Express, and Google Apps Engine offer free levels of service that may appeal to small and medium-sized libraries. Dedicated PaaS providers tend to charge on the bases of add-ons and IT resources used. It can be difficult to compare costs across providers because each provider uses different measures. For example, Heroku uses a measure of front-end and back-end processes called “dynos” that would be difficult to compare to Amazon’s Elastic Beanstalk instances. In contrast, Google has a multifaceted charging model that includes CPU time, bandwidth, and data storage elements. Although there has been some research comparing the total cost of ownership of cloud services, this form of PaaS environment introduces new elements and is in need of deeper exploration.

## Service Portability and Interoperability

The complex customization requirements of dedicated PaaS solutions mean that they can be difficult to migrate to new providers. Certain platforms such as Heroku and Amazon’s Elastic Beanstalk allow application packages to be deployed on other platforms. In contrast, platforms that use a customized technology stack such as Google App Engine make migrating to another platform difficult if not impossible without additional application development.

## CONCLUSION

This chapter explores two broad platform types important to consider when exploring cloud computing and virtualization. The review of SaaS providers focuses largely on library-specific solutions but also highlights SaaS services for broader information uses. Providers such as WordPress and Salesforce may very well be suitable solutions for libraries but should be considered within the overall IT framework required. Indeed, if libraries are seeking to use SaaS solutions to replace all of their information service infrastructure, these options should be considered as ways of bridging the gap between library-specific and general web-based information services. At the very least, however, libraries that turn to SaaS solutions need to consider how they plan to monitor these services, manage contact and access information, and prepare for migration away from SaaS providers.
