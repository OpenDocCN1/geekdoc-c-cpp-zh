Libraries may desire dedicated physical servers if cost, subscriber privacy, or other issues outweigh the anticipated benefits of cloud providers. Libraries that want to operate on dedicated physical servers may also want to consider options in which the library purchases hardware and pays a subscription fee for hosting its hardware in a data center. This approach often comes with higher levels of service, which may include forms of system administration for additional fees, but also enables libraries to benefit from robust data center features such as network redundancy, environment quality, and off-site backup redundancy without giving up the benefits of owning the hardware on which their web services operate. This may be particularly attractive if libraries have adopted an IT service that operates on a platform with which they are not familiar.

It is worth noting that other PaaS solutions such as Salesforce, Heroku, or GoogleApps are not included in the three types of PaaS hosting mentioned above. These solutions focus on supporting highly customized information services such as customer management, site publishing, and content management without the overhead of server management tasks. As a result, these features are more scalable than the server-focused solutions mentioned here but require a tighter coupling between application and hosting environment. These PaaS solutions are reviewed later in this chapter.

When you are selecting a provider it is important to look for objective reviews of each company and to choose a provider based on elements important to your local organization. These elements likely include supported server software, platform security, system management tasks, and SLA options. ## Expertise Required

The expertise required for server-based PaaS solutions varies widely and depends to a large part on the PaaS platform selected and services implemented. This section reviews the top skills required to make effective use of a hosted server-type PaaS service.

### Using a web-based control panel.

Web-based control panels are designed to support many of the services that can be managed on a hosted site. Two of the most popular platforms are Plesk (http://plesk.com) and cPanel (http://cpanel.com), but there are a number of other solutions.

### Understanding DNS.

DNS is the means by which server IP addresses are resolved to host names. When registering with a PaaS provider, you have the option of establishing a new domain name or mapping an existing domain name to your server. For libraries operating as part of a larger institution, it is likely necessary to work with organizational IT to associate the IP address of your PaaS server with an organizationally managed DNS server. To do this libraries should identify a PaaS provider that includes a dedicated IP address along with the subscription; this is required only if the library wants to use a domain name that is related to the larger institutions (e.g., myschool.edu) and not an independent domain name (e.g., library.com). DNS is a complex process that includes the ability to create subdomains, redirect traffic based on name configuration, and support SSL certificates. If your institution is looking to provide its own DNS support, a good overview of DNS can be found in Liu and Albitz (2006).

### Understanding service configuration.

The support underlying server-based PaaS environments makes it much easier to install, configure, and deploy applications. Many PaaS providers support one-click installs of common content management systems such as WordPress and Drupal. Although these features make it easier to get your site up and running, it is equally important to understand where the files and databases are located for these applications and to understand how application upgrades are handled. It is particularly important to understand how a hosting provider supports the addition of optional modules to popular content management systems. This often requires SSH and SFTP access as well as the ability to set user permissions, extract files, and complete other configuration tasks outside of a web interface.

### Understanding SSH/SFTP.

To take advantage of PaaS solutions, SSH and SFTP are required to transfer files to/from and interact with your server. Selecting a provider that supports SSH and SFTP is important to enable automation, configuration, and transfer of resources. Many sites support some form of SSH but also require additional security measures before they activate this service. When you are selecting a provider, it is worth knowing if it supports multiple SSH accounts and if there is some provision for using firewall restrictions to limit the IP addresses that can SSH to the hosted server.

### Understanding databases.

One of the most important elements of a web application is its database. Many web services such as WordPress or Drupal require specific database platforms and may require manual interaction with those databases.

When you are selecting a provider it is important to check the database platforms supported as well as database versions and integration with an application platform. It is also important to know if your PaaS provider supports a web-based database administration tool such as phpMyAdmin or phpPgAdmin (http://phppgadmin.sourceforge.net). These tools make it much easier to configure, manage, and back up databases. It is also important to understand size restrictions, database instance restrictions, backup, and restoration methods coming from your PaaS provider. In addition to these skills, an understanding of database design, SQL, and database integration with web services is essential for application development.

### Managing firewalls.

One advantage of server-based PaaS solutions is that they feature provider-managed security, network, and operating system updates. A good PaaS provider should protect against denial of service attacks and security breaches in permissions and should block access to server ports by default. For libraries seeking to implement services in addition to a traditional web server (e.g., Tomcat or SOLR) it may be important to manage the ports that are open on your server. Though it can be possible to provide access to these other services through the main webserver port (port 80), it may not be possible to configure this in a PaaS environment. In these cases, having access to some form of firewall control in your control panel is useful. Managing firewall rules in a control panel interface is much easier than administering them directly on the server. This comes with the added benefit that, although an incorrectly applied rule can block access to your server instance, it is not likely to block your access to the administrative control panel. In contrast, firewall services administered in an IaaS environment can be more difficult and come with greater need for testing prior to activation.

## Service Complexity, Sustainability, and Durability

Because PaaS solutions offer technical support and simplify the implementation and management of web hosting services, they are best suited for simple web-based services such as library websites, content management services, and customized web services. Given their often limited technology stack and largely managed environment, server-based PaaS environments are often unable to serve as a hosting environment for complex services and may not serve multiple applications well. Providers may not allow root user access and support only recurring automated jobs. For these reasons, server-based PaaS environments offer only a limited ability to increase the IT capacity in a library. Further, though often featuring unlimited bandwidth and disk capacity, they often come with restrictions that prevent the installation of library-specific software such as Koha, Evergreen, DSpace, or Fedora.
