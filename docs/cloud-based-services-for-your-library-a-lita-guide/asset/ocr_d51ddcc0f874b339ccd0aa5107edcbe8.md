On February 29, 2012, for example, a leap day software bug in the Microsoft Azure platform caused systemwide downtime for Azure customers for several hours (Babcock 2012). Likewise, in 2011 Amazon had its own issues when a misconfigured network caused widespread problems in its Virginia cloud region (Babcock 2011). These service outages were both fairly short-term and did not result in long-term data loss, but still they underscore the importance of being comfortable with and planning for backup and service replication strategies.

One of the key challenges to a manageable and successful backup and recovery policy for libraries moving to cloud platforms is maintaining consistent approaches across multiple cloud providers. Another complication is ensuring that your library is in compliance with organizational policies. This can be complicated by the fact that many IT organizations have backup procedures geared toward traditional backup methods (e.g., tape-based backups or server-rebuild processes). In a cloud environment, bandwidth limitations and local infrastructure can make backing up to local tape difficult, and the cost of transferring backup data sets across the network can make this approach cost prohibitive. There are cloud-based services that support low-cost, high-durability backups including BackBlaze (http://backblaze.com) and MozyPro (http://mozypro.com), but overall the trend is away from tape backups for cloud-based services. Some traditional backup applications such as Amanda (www.amanda.com) have been updated to leverage the open storage of Amazon S3 using open-source industry-standard backup tools. This may be preferable to system or volume snapshots, which are available only from within the cloud provider's system. In contrast, Amanda uses traditional archiving and compression tools that do not rely on a proprietary system. By backing up to S3, libraries can preserve the ability to download their backups at any time or via an automated process. It is worth noting that there are services that move in the other direction (e.g., using S3 as the redundant backup for local data). For example, using the Amazon Storage Gateway (http://aws.amazon.com/storagegateway/), subscribers can replicate data from local or other cloud-based services in the Amazon S3 system. This provides users the benefit of backing up to a service with a defined SLA and in a redundant and geographically replicated system. In 2012 Amazon also introduced an S3-backed storage solution called Amazon Glacier (http://aws.amazon.com/glacier/) that features built-in data replication and fixity checking services. Glacier is marketed as a tape-backup replacement service and achieves cost reductions by gearing the service around long-term storage assurances rather than immediate retrieval.
