Although these solutions may be preferable for many libraries, the market is still somewhat limited in terms of product selection, and consolidating the number of vendors in this model comes at the expense of product selection. At the present time, libraries seeking to adopt SaaS solutions exclusively find themselves making decisions on both system functionality and vendor services. This is likely to change in the coming years as LIS providers optimize their software to run efficiently in the cloud.

For libraries seeking to use SaaS solutions to fill these gaps, there are an increasingly large number of case studies that explore SaaS alternatives to traditional library solutions. For example, Wilson (2011) explores the use of Drupal, Basecamp (http://basecamphq.com), and MIRA (http://atlassian.com/software/jira) as an alternative platform for electronic resource management systems. Wilson explores the challenges associated with adapting these platforms to serve a very specific function, as opposed to the implications of using an SaaS platform for this service, but the reported success of all three services point to an opportunity for these types of tools to have a dramatic impact on library IT decisions.

Perhaps the largest challenge in this adoption environment is managing the budgetary, license, identity management, and functional interoperability of these systems. Although many providers feature some form of integration through web-based plug-ins, back-end indexing, or automated data loading, making these services work together can be challenging, particularly for libraries interested in offloading as much technical work as possible. Unfortunately, these challenges may not emerge until a specific system is implemented or need found, and it can be difficult for libraries without in-house IT staff to identify potential solutions.

These data and interoperability problems do not have easy one-size-fits-all solutions, but there are potentially useful options. For example, Peter Murray (personal communication, March 2012) observed that Lyrasis tunes its hosting services based on library need and worked with outside consultants to bring data migration services to the table for libraries adopting its hosted IT services. In addition, there are IaaS providers whose primary purpose is to enable interoperability in an SaaS environment. Two examples are SnapLogic (http://snaplogic.com) and Jitterbit (http://jitterbit.com). These providers support data connections using a range of data sources (e.g., XML, CSV, ODBC), include a data migration design interface, and support HTTP endpoint services in which data queries and publishing actions can be activated by REST-based HTTP requests.
