The NIST model also defines the limits of expertise and responsibility that should be expected of the various players in a cloud computing solution. It is worth noting that the roles of consumer, auditor, provider, carrier, and broker may not apply in all cloud computing adoption frameworks; nevertheless, they are valuable roles to consider when exploring new IT systems. For example, in many cases libraries (e.g., the cloud consumer) interact directly with cloud providers rather than working through a cloud broker. In this case the process of working with and auditing service layers, security, privacy, and service-level agreements (SLAs) falls on the cloud consumer. The NIST model also provides a taxonomy of cloud features (Fang et al. 2011) that describes the issues cloud consumers should be aware of when selecting and implementing a cloud solution. This taxonomy defines the activities (e.g., service creation, publishing, auditing), components (e.g., processes, actions, tasks), and subcomponents (e.g., service provision, service decommission) that may be helpful for organizations seeking to understand relationships and interactions important in cloud computing adoption.

# VIRTUALIZATION

In contrast to cloud computing, virtualization is defined as “the abstraction of IT resources in a way that masks the physical nature and boundaries of those resources from resource users” (Gartner 2011). Virtualization enables creation of multiple virtual machines on a shared hardware platform; enhances flexibility in CPU, memory, and storage allocations between machines; and is designed to be portable across hardware platforms (Smith and Nair 2005). This is a broad definition that includes the virtualization of servers, clients, network-attached storage, and any number of other computing resources. Common server platforms include XEN (http://xen.org), Citrix (http://citrix.com), and VMware (http://vmware.com). Each virtualization platform has historically supported its own virtualization format (e.g., Kernel Virtual Machine, Bare Metal, VMWare VMDK), but there is also a movement to support an open virtualization standard that would enable easy interoperability among virtualization platforms. These solutions can be a valuable tool for libraries, but they often come with a requirement for technical infrastructure and expertise that commonly is not held by libraries.
