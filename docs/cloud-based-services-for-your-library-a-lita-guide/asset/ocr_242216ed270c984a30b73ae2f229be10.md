These features both enable an enterprise level of support for cloud-based systems and pose problems for libraries seeking to leverage them. For example, no off-the-shelf library applications have been designed to run on PaaS application platforms. Although this may change in the coming years, PaaS application solutions are currently best suited to locally developed applications or specific tailored versions of popular applications. This means that, although SaaS application platforms offer enterprise-level support for service replication and scalability and may offer multiple endpoint or availability zones, they also require the developer to work in a rather narrow development environment using a limited suite of development tools and IT stacks. Some PaaS providers including Heroku address this issue by supporting multiple development platforms and featuring prebuilt services to facilitate everything from database integration to messaging and service monitoring. Clearly these benefits come with their own tradeoffs, requiring more configuration and management of the PaaS service.

# PaaS Provider Examples

At the time of this writing, there are few library-specific solutions that run on application-based PaaS environments and no applications designed to work by default in an application-based PaaS environment. It is likely that open-source and perhaps commercial systems will migrate to PaaS platforms given the benefits of this IT approach and the current use of many of the same platforms (e.g., PHP, Python, Java, MySQL, PostgreSQL, Oracle). Key products in this area include Amazon Elastic Beanstalk, Heroku, Google Apps Engine, CloudFoundry, and Microsoft Azure.

# Amazon Elastic Beanstalk

Amazon Elastic Beanstalk is a service provided within the AWS framework. As of this writing, Beanstalk supports Java, PHP, Python, and .Net applications and leverages the other services in the AWS environment. It uses Amazon computing instances as a distribution platform and supports scaling through multiple-instance levels from micro (1 EC2 Compute Units, 613 MB RAM) to extra-large (26 EC2 Compute Units, 68.4 GB RAM).
