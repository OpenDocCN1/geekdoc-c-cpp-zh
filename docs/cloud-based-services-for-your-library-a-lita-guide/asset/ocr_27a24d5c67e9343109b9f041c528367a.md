Reese’s approach focuses on itemizing hardware costs and grouping labor costs into a single sum and includes an estimation of the cost of performance loss that may be a factor in selecting capacity in the cloud (e.g., an organization may select a mid-capacity cloud server that just meets current demand rather than overbuying capacity for a physical server). This cost of performance loss can be mitigated by designing scalable systems and actually could be viewed from the other direction (e.g., the capital cost of unutilized capacity).

In contrast, Feldman’s (2012, 19) ROI approach uses capital costs, operational costs, future capital cost (e.g., for savings), staffing impact, time savings for non-IT staff, resource provisioning (e.g., hardware acquisition/setup time), network expenses, implementation cost, and utility costs as factors. Whereas Reese’s calculations describe a wholly local or wholly cloud-based infrastructure in which capital investment savings realized from cloud deployment result in an overall lower total cost for cloud services, Feldman’s ROI analysis suggests that the most economical approach focuses on using private cloud services that support public cloud bursting (e.g., Eucalyptus, OpenStack, or Cloudstack) and differentiates long-term investments from short-term capacity need.

These conclusions show how difficult calculating ROI can be for cloud services and introduce three distinct approaches: nonvirtualized, private/public cloud, fully public/community cloud. # Cloud Bursting

Cloud bursting is the ability to scale computing and storage resources quickly from a private cloud into a public or community cloud environment using the same tools and standards employed in the private cloud. Two providers in particular, Amazon and RackSpace, support cloud bursting using different private cloud platforms. In March 2012, Amazon announced a formal agreement with Eucalyptus to design its cloud system using the same application programming interface tool design that was first deployed by Amazon (Eucalyptus 2012). Likewise, RackSpace was key in the development and release of OpenStack and is building toward the ability to migrate private OpenStack deployments easily to RackSpace services (Moorman 2011). In addition, data centers such as Internap (http://internap.com) are beginning to offer private cloud platforms using the OpenStack platform, enabling a new type of externally sourced private and public cloud architecture.
