All IT services include infrastructure (e.g., computing hardware, operating systems, networking, power, and cooling), platform (e.g., operating system, software stacks, development, and deployment frameworks), application (e.g., an information system that fills a single or multiple roles), and service elements (e.g., an end-point resource that provides some form of information service based on the functions of the application). ## TECHNICAL FACTORS

Of all issues to consider when exploring cloud-based and virtualized services, technical issues are likely to take center stage. Understanding the technical work required when a library takes on virtualized and cloud computing is an important first step that can help guide decisions about capacity and long-term sustainability.

### Infrastructure Administration

The administration of infrastructure-level services focuses on core elements including network, server, and operating systems. Infrastructure-level administration often comes with beginning-to-end responsibility for an information service and requires the ability to design and deploy a hardware (both virtualized or physical) infrastructure, install and configure software, secure and maintain distinct IT components (e.g., server, network, security), and manage change in service configuration and deployment. This requires a familiarity with security measures (e.g., firewalls, user access, and system updates) and IT service management (e.g., service configuration, deployment, backup, failover, and depreciation) and a granular understanding of the implications of system design on the information service. In a cloud environment this also means a wider familiarity with cloud service elements that constitute an IaaS environment (e.g., server images, volume snapshots, security groups). The NIST reference model expands on infrastructure-level skill requirements with ten technical factors to be considered in relation to cloud computing adoption (Fang et al. 2011):

- 1. Creating, accessing, updating, and deleting data objects in clouds
- 2. Moving virtual machines and virtual appliances between clouds
- 3. Selecting the best IaaS vendor for a private externally hosted cloud
- 4. Tools for monitoring and managing multiple clouds
- 5. Migrating data between clouds
- 6. Single sign-on access to multiple clouds
- 7. Orchestrated processes across clouds
- 8. Discovering cloud resources
- 9. Evaluating SLAs and penalties
- 10. Auditing clouds

Some of these tasks are highly technical and require infrastructure-level expertise. For example, creating, managing, and migrating virtual machines requires understanding how to allocate infrastructure resources and configure systems and applications. Other tasks including evaluating SLAs, discovering new cloud resources, and auditing cloud services are important for all approaches to cloud computing. Given the complexity inherent in many of these technical factors, it may be necessary to choose those that are more important in a particular environment. For example, whereas patron privacy and quality of service are major issues in libraries, single sign-on or fully interoperable cloud environments may not be necessary when selecting cloud-based information services.

Libraries can find it challenging to locate the resources in-house to manage technology infrastructure but also may find that cloud providers are reducing the complexity of these systems and lowering the costs (both financial and operational) to implement and manage these services. Though this list of required skills may be daunting, the ability to manage infrastructure-level services can be helpful for libraries given their tendency to adopt information services from different vendors or open-source communities. For librarians seeking to develop expertise in infrastructure administration, becoming familiar with local virtualization platforms such as Oracle's VirtualBox (http://virtualbox.org) and with cloud virtualization platforms offered by IaaS providers (e.g., Amazon, Rackspace, or Microsoft) is a good first step. These skills transfer easily, since the conceptual understanding required to use Amazon's platform is mirrored in other providers (e.g., the understanding of CPU time-based charging, storage resources, firewall resources, monitoring services, authentication services). Although specific services depend on the platform or application deployed, having an understanding of infrastructure-level capacity helps when librarians or IT administrators are faced with the process of designing a cloud-based or virtualized system.

### Platform Administration

Technical aspects of platform support typically include an emphasis on the software components that constitute an end-user-facing application. For example, a content management system running on WordPress requires familiarity with Apache, MySQL, PHP, and WordPress plug-ins and may require familiarity with authentication systems (e.g., LDAP, Shibboleth) and secure web connections (e.g., SSL). Depending on the platform selected, other skills may be required including programming familiarity, an understanding of web service architecture, or a more granular understanding of server infrastructure.

In a PaaS cloud environment, platform administration may require familiarity with a specific suite or configuration of web services. For example, Google App Engine (http://code.google.com/appengine/) requires users to design their applications within a specific framework that includes a database platform, programming framework, and web-service deployment architecture. ### Security

There are a host of security issues that affect both the comfort level for adoption of cloud services and also the sustainability of a cloud-based service once it is selected. In general, the goal of system security is to prevent unauthorized access to IT infrastructure, administrative services, and user-facing services. It also includes preventing interruptions in connectivity and the hardening of systems against intrusion attempts using open ports, cracked passwords, software vulnerabilities, and back-door and man-in-the middle attacks. The work in this area includes a necessary focus on traditional IT security measures including active monitoring, firewall and application control, penetration testing, and incident management and response, but it also involves new security issues related specifically to cloud platforms, such as virtual private networking, multiplatform monitoring, data center certification, and trusted user authentication (Constantin 2011). For librarians interested in learning more about security management, Limoncelli et al.’s (2001) guide to system administration provides a foundation for approaching IT security issues and includes a focus on the role of policy and auditing in ensuring consistent and durable system security.

A central policy and procedure checklist may help organizations with security monitoring, but other areas in a cloud environment also need attention. For example, the addition of multiple platforms in a cloud computing environment means that security concerns need to be assessed both for individual systems and for the connections between systems. In addition to the common security risk areas of authentication, server isolation, and data protection, cloud-centric risk areas include security holes in the selected hypervisor platform, the risks associated with running in a common virtualized environment, and the risks associated with operating servers in a public or community network (e.g., firewalls, access, file permissions).
