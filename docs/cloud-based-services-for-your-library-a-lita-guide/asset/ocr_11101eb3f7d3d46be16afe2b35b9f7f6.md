An internal IT security policy should include acceptable use, monitoring, privacy remote access, network connectivity, and log retention policies (Limoncelli et al. 2001, 124). In addition, organizations that implement externally virtualized or cloud-based services should obtain or define policies that ensure data integrity, preserve local ownership of resources located in the cloud, and ensure the integrity of the overall cloud platform. Although there are risks associated with operating in a public or community cloud environment, cloud virtualization systems have been designed to ensure the isolation of virtual machines. Vendor assurances can help mitigate the perceived risks of public or community cloud platforms and are good building blocks on which to base a local security policy. For example, Amazon has obtained certifications and accreditations that document its ability to provide secure cloud services (http://aws.amazon.com/security/#certifications). Using these certifications as a base level to evaluate infrastructure security can help organizations identify suitable cloud candidates. In addition, a thorough understanding of the details of these security policies can help organizations focus their work on other areas of vulnerability. More details on provider-level security and assurances are discussed in the legal and policy section of this chapter.

One complication that can come with cloud computing platforms is the need to replicate security measures in each adopted platform or vendor. Therefore, having a clear and consistent policy on what measures are in place and how they are implemented (e.g., how user accounts are created, managed, and audited) helps simplify the adoption of new computing environments. This does not necessarily mean the centralization of security responsibilities but rather that the organization as a whole needs to be well informed about the real risks and management practices required in a cloud environment. For example, in SaaS environments it may make sense to delegate these tasks to a mid-level administrative user rather than routing them through an IT department. In contrast, the level of access and expertise required to administer user accounts in an IaaS environment properly likely means that these tasks need to be managed by staff familiar with the processes and associated risks. In both cases, however, creating a layered security policy can help extend access to the appropriate levels while preventing compromises. In the Amazon EC2 environment, for example, security groups are used as a cloud environment–level firewall that allows the grouping of servers in access groups.
