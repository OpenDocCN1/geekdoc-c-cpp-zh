When you are selecting a provider it is important to check the database platforms supported as well as database versions and integration with an application platform. It is also important to know if your PaaS provider supports a web-based database administration tool such as phpMyAdmin or phpPgAdmin (http://phppgadmin.sourceforge.net). These tools make it much easier to configure, manage, and back up databases. It is also important to understand size restrictions, database instance restrictions, backup, and restoration methods coming from your PaaS provider. In addition to these skills, an understanding of database design, SQL, and database integration with web services is essential for application development.

# Managing firewalls.

One advantage of server-based PaaS solutions is that they feature provider-managed security, network, and operating system updates. A good PaaS provider should protect against denial of service attacks and security breaches in permissions and should block access to server ports by default. For libraries seeking to implement services in addition to a traditional web server (e.g., Tomcat or SOLR) it may be important to manage the ports that are open on your server. Though it can be possible to provide access to these other services through the main webserver port (port 80), it may not be possible to configure this in a PaaS environment. In these cases, having access to some form of firewall control in your control panel is useful. Managing firewall rules in a control panel interface is much easier than administering them directly on the server. This comes with the added benefit that, although an incorrectly applied rule can block access to your server instance, it is not likely to block your access to the administrative control panel. In contrast, firewall services administered in an IaaS environment can be more difficult and come with greater need for testing prior to activation.

# Service Complexity, Sustainability, and Durability

Because PaaS solutions offer technical support and simplify the implementation and management of web hosting services, they are best suited for simple web-based services such as library websites, content management services, and customized web services. Given their often limited technology stack and largely managed environment, server-based PaaS environments are often unable to serve as a hosting environment for complex services and may not serve multiple applications well. Providers may not allow root user access and support only recurring automated jobs. For these reasons, server-based PaaS environments offer only a limited ability to increase the IT capacity in a library. Further, though often featuring unlimited bandwidth and disk capacity, they often come with restrictions that prevent the installation of library-specific software such as Koha, Evergreen, DSpace, or Fedora.
