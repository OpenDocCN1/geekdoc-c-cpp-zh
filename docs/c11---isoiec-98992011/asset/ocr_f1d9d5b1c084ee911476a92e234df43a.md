# 7.14.1 Specify signal handling

# 7.14.1.1 The signal function

Synopsis

```
#include <signal.h>
void (*sig(int sig, void (*func) (int))) (int);
```

Description

+   2. The signal function chooses one of three ways in which receive of the signal sig is subsequently handled. If the value of func is SIG_DFPL, default handling for that signal will occur. If the value of func is SIG_IGN, the signal is ignored. Otherwise, func shall point to a function to be called when signals occur. An invocation of such a function as a signal, or (recursively) of any further functions called by that invocation (other functions in the standard library).²251 is called a signal handler.

+   3 When a signal occurs and func points to a function, it is implementation-defined whether the equivalent of signal(sig, SIG_DFPL); is executed or the implementation provides some implementation-defined set of signals (at least including sig) from occurring until the current signal handling has completed; in case of SIGILL, the implementation may alternatively define that no action is taken. The equivalent of (*func)(sig); is executed. If and when the function returns, the value of sig is SIG_FPE, SIGPIPE, SIGSEGV, or any other implementation-defined value corresponding to a computational exception, the behavior is undefined; otherwise the program will resume execution at the point it was interrupted.

+   4 If the signal occurs as the result of calling the abort or raise function, the signal handler shall not call the raise function.

+   5 If the signal occurs other than the result of calling the abort or raise function, the behavior is undefined if the handler refers to any object with static or storage duration that is not a lock-free atomic object than by assigning a value to an object declared as volatile_atomic_t, or the signal handler calls any function in the standard library other than the abort function, the _Exit function, or the signal function with the first argument to the signal number corresponding to the signal that caused the invocation of the handler. Furthermore, if a call to the signal results in a SIG_ERR return, the value of errno is indeterminate.²52

> 251) This includes functions called indirectly via standard library functions (e.g., a SIGABRT handler called via the abort function).

> 252) If any signal generated by an asynchronous signal handler, the behavior is undefined.
