9 The macros

```

```

expand to the integer constants 1 and 2, respectively; the macro

```
math_errandhandling
```

expands to an expression that has type int and the value MATH_ERRNO,
MATH_ERREXCEPT, or the bitwise OR of both. The value of math_errandhandling is constant for the duration of the program. It is unspecified whether
m_errandhandling is a macro or an identifier with external linkage. If the name
math_errandhandling, the behavior is undefined. If the expression
math_errandhandling & MATH_ERREXCEPT can be nonzero, the implementation
shall define the macros FE_DIVZERO, FE_INVALID, and FE_OVERFLOW in
fenv.h.

# 7.1.12 Treatment of error conditions

+   1 The behavior of each of the functions in <math.h> is specified for all representable
ues of its input arguments, except where stated otherwise. Each function shall execute
as it were a single operation without raising SIGFPE and without generating any of the
floating-point exceptions "invalid", "divide-by-zero", or "overflow" to reflect
t result of the function.

+   2 For all functions, a domain error occurs if an input argument is outside the domain over
the mathematical function is defined. The description of each function lists all
required domain errors; an implementation may define additional domain errors, provided
that such errors are consistent with the mathematical definition of the function.(231) On a
domain error, the function returns an implementation-defined value; if the integer
expression math_errandhandling & MATH_ERRNO is nonzero, the integer
errno acquires the value EDOM; if the expression math_errandhandling &
MATH_ERREXCEPT is nonzero, the "invalid" floating-point exception is raised.
