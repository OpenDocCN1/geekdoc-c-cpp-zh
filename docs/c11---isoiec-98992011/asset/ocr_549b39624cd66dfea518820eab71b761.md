EXAMPLE 3 The following obtrusive constructions

```
typedef signed int;
typed int plain;
struct {
    unsigned t:4;
    const t:5;
    plain r:5;
};
```

declare a type n with type signed int, a name plain with type int, and a structure with three bit-field members, one named t that contains values in the range [0, 15], an unnamed qualified-bit field (if it could be accessed) would contain values in the range [-15, +15] or [-16, +15], and one named r that contains values in the range of [0, 31], [-15, +15], or [-16, +15]. (The choice of range is implementation-defined). The first two bit-field declarations differ in that unsigned is a type qualifier (which forces t to be the name of a structure member), while const is a type qualifier (which modifies t is still a valid type name). If these declarations are followed in an inner scope

```
t f (t (t));
long t;
```

then a function f is declared with "function returning signed int with one unnamed parameter with pointer to returning signed int with one unnamed parameter with type signed int", and an identifier t with long int.

EXAMPLE 4 On the other hand, named types can be used to improve code readability. All three of the following declarations of the signal function specify exactly the same type, the first without making use of any typed names.

```
typedef void fv(int), (*fv)(int);
void (*signal(int, void (*int)))(int);
f *signal(int, void *);
pfv signal(int, pfv);
```

EXAMPLE 5 If a typedef name denotes a variable array type, the length of the array is fixed at the time the typedef name is defined, not each time it is used:

```
void copy(int)
{
    typedef int B[n]; // B is int, evaluated now
    int n = 1; // a is int, n without += 1
    B a; // a and b are different sizes
    int b[n]; // b
    for (int i = 1; i < n; i++)
        a[i-1] = b[i];
}
```
