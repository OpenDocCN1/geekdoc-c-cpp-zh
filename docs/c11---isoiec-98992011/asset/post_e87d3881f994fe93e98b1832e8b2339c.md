## 6.4.3 Universal character names

### Syntax

```
universal-character-name:
\u hex-quad
\u hex-quad hex-quad

hex-quad:
hexadecimal-digit hexadecimal-digit
hexadecimal-digit hexadecimal-digit
```

## Constraints

A universal character name shall not specify a character whose short identifier is less than 00A0 other than 0024 ($), 0040 (@), or 0060 ('), nor in the range D800 through DFFF inclusive.⁷³}

## Description

Universal character names may be used in identifiers, character constants, and string literals to designate characters that are not in the basic character set.

## Semantics

The universal character name \unnnnnnn designates the character whose eight-digit short identifier (as specified by ISO/IEC 10646) is nnnnnnn.⁷⁴

Similarly, the universal character name \unnnn designates the character whose four-digit short identifier is nnnn (and whose eight-digit short identifier is 0000nnnn).

> ⁷³) The disallowed characters are in the basic character set and the code positions reserved by ISO/IEC 10646 for control characters, the character DELETE, and the S-zone (reserved for use by UTF-16).

> ⁷⁴) Short identifiers were first specified in ISO/IEC 10646–1:1993/Amd.9:1997.

## 6.4.4 Constants

### Syntax

+ constant:
integer-constant
floating-constant
enumeration-constant
character-constant

## Constraints

+ Each constant shall have a type and the value of a constant shall be in the range of representable values for its type.

## Semantics

+ Each constant has a type, determined by its form and value, as detailed later.

## Description

+ 2 An integer constant begins with a digit, but has no period or exponent part. It may have a prefix that specifies its base and a suffix that specifies its type.

+ 3 A decimal constant begins with a nonzero digit and consists of a sequence of decimal digits. An octal constant consists of the prefix 0 optionally followed by a sequence of the digits 0 through 7 only. A hexadecimal constant consists of the prefix 0x or 0X followed by a sequence of the decimal digits and the letters a (or A) f (or F) with values 10 through 15 respectively.

## Semantics

+ 4 The value of a decimal constant is computed base 10; of an octal constant, base 8; that of a hexadecimal constant, base 16. The lexically first digit is the most significant.

+ 5 The type of an integer constant is the first of the corresponding list in which its value can be represented.

## Description

+ 2 A floating constant has a significand part that may be followed by an exponent part and may include a suffix that specifies its type.

+ 3 A decimal-floating-constant begins with a nonzero digit and consists of a sequence of decimal digits followed by a period and another sequence of decimal digits. A hexadecimal-floating-constant consists of the prefix 0x or 0X followed by a sequence of hexadecimal digits and the letters a (or A) f (or F) with values 10 through 15 respectively. The exponent part consists of e, E, p, or P followed by a signed digit sequence.

## Semantics

+ 4 The value of a decimal-floating-constant is computed base 10; of a hexadecimal-floating-constant, base 16. The significand is interpreted as a (decimal or hexadecimal) rational number; the exponent indicates the power of 10 or 2 by which the significand is to be scaled.

+ 5 The type of a floating constant is the first of the corresponding list in which its value can be represented.

+ 6 An suffixed floating constant has type **double**. If suffixed by the letter f or F, it has type **float**. If suffixed by the letter l or L, it has type **long double**.

+ 7 Floating constants are converted to internal format as if translation-time. The conversion of a floating constant shall not raise an exceptional condition or a floating-point exception at execution time. All floating constants of the source form⁷⁷⁵) shall convert to the same internal format with the same value.

## Recommended practice

8 The implementation should produce a diagnostic message if a constant cannot be represented exactly in its evaluation format; the implementation should then proceed with the translation of the program.

9 The translation-time conversion of floating constants should match the execution-time conversion of character strings by library functions, such as `strtod`, given matching inputs for both conversions, the same result format, and default execution-time rounding⁷⁶)

> ⁷⁷⁵) **1.23**, **123e-2**, **0.12-1.23L** are all different forms and do not need to convert to the same internal format and value.

> ⁷⁶⁾ The specification for the library functions recommends more accurate conversion than required for floating constants.
