## 7.12 Mathematics <math.h>

+ The header <math.h> defines two types and many mathematical functions and defines macros. Most synonyms specify a family of functions consisting of a principal function with one or more double parameters, a double return value, or both; and other functions with the same name with f and l suffixes, which are corresponding functions with float and long double parameters, return values, or both. Integer arithmetic functions and conversion functions are discussed.

+ The types
float_t
double_t
are floating types at least as wide as float and double, and such that double_t is at least as wide as float_t. If FLT_EVAL_METHOD equals 0, float_t and double_t are float and double, respectively; if FLT_EVAL_METHOD equals 1, they are both double; if FLT_EVAL_METHOD equals 2, they are both double; and for other values of FLT_EVAL_METHOD, they are otherwise implementation-defined.

+ The macro
HUGE_VAL
expands to a positive double expression, not necessarily representable as a float.

+ HUGE_VALF
HUGE_VALL
are respectively, float and long double analogs of HUGE_VAL.

+ The macro
INFINITY
expands to a constant expression of type float representing positive or unsigned infinity, if available; else a positive constant of float that overflows at translation time. A <math.h> function may pass arguments and return values in wider format than the syntax indicates. The types float_t and double_t are intended to be the implementation's most efficient types at least as wide as float and double. For FLT_EVAL_METHOD equal 0, 1, or 2, the type float_t is the narrowest type used by the implementation to evaluate floating expressions. HUGE_VAL, HUGE_VALF, and HUGE_VALL can be positive infinities in an implementation that supports infinity.

+ The macro
NAN
is defined if and only if the implementation supports NaNs for the float type. It expands to a constant expression of float representing a quiet NaN.

6 The number classification macros

```
FP_INFINITE
FP_NAN
FP_NORMAL
FP_SUBNORMAL
FP_ZERO
```
are the mutually exclusive kinds of floating-point values. They expand to integer expressions with distinct values. Additional implementation-defined classifications, with macro definitions beginning with FP_, an uppercase letter, may also be specified by the implementation.

7 The macro
FP_FAST_FMA
is optionally defined. If defined, it indicates that the fma function generally executes about fast as, or faster than, a multiply and add double operands. The macros
FP_FASTMAF
FP_FMAL
are, respectively, float and long double analogs of FP_FMA. If defined, these macros expand to the integer constant 1.

8 The macros
FP_ILOGB
FP_ILOGBNAN
expand to integer expressions whose values are returned by logb(x) if x is zero or NaN, The value of FP_ILOGB shall be INT_MIN or -INT_MAX. The value of FP_ILOGBNAN shall be either INT_MAX or INT_MIN. In this case, using INFINITY will violate the constraint in 6.4.4 and thus require a diagnostic. Typically, the FP_FAST_FMA macro is defined and only if the fma function is implemented directly with a hardware multiply-add instruction. Software implementations are expected to be substantially slower.

9 The macros
```
MATH_ERRNO
MATH_ERREXCEPT
```
expand to the integer constants 1 and 2, respectively; the macro
math_errhandling
expands to an expression that has type int and the value MATH_ERRNO, MATH_ERREXCEPT, or the bitwise OR of both. The value of math_errhandling is constant for the duration of the program. It is unspecified whether math_errhandling is a macro or an identifier with external linkage. If the name math_errhandling, the behavior is undefined. If the expression math_errhandling & MATH_ERREXCEPT can be nonzero, the implementation shall define the macros FE_DIVZERO, FE_INVALID, and FE_OVERFLOW in fenv.h.

## 7.1.12 Treatment of error conditions

+ 1 The behavior of each of the functions in <math.h> is specified for all representable values of its input arguments, except where stated otherwise. Each function shall execute as it were a single operation without raising SIGFPE and without generating any of the floating-point exceptions "invalid", "divide-by-zero", or "overflow" to reflect the result of the function.

+ 2 For all functions, a domain error occurs if an input argument is outside the domain over the mathematical function is defined. The description of each function lists all required domain errors; an implementation may define additional domain errors, provided that such errors are consistent with the mathematical definition of the function. On a domain error, the function returns an implementation-defined value; if the integer expression math_errhandling & MATH_ERRNO is nonzero, the integer errno acquires the value EDOM; if the expression math_errhandling & MATH_ERREXCEPT is nonzero, the "invalid" floating-point exception is raised.

+ 3 Similarly, a pole error (also known as a singularity or infinitary) occurs if the mathematical function has an infinite result as the finite argument(s) is approached in the limit (for example, log (0)). The description of each function lists any required pole errors, an implementation may define additional pole errors, provided that such errors are consistent with the mathematical definition of the function. On a pole error, the function returns an implementation-defined value; if the integer expression In an implementation that supports this, allows an infinity as an argument to be a domain error if the mathematical definition of the function does not include the infinity.
