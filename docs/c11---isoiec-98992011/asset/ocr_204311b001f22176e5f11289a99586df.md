# 5.2.3 Signals and interrupts

Functions shall be implemented such that they may be interrupted at any time by a signal, or may be called by a signal handler, both, or without notice to earlier, but still active; invocation' control flow (after the interruption), function return values, or objects with automatic storage duration. All such objects should be maintained outside the function image (the instructions that compose the executable representation of function) on a per-invocation basis.

# 5.2.4 Environmental limits

Both the translation and execution environments constrain the implementation of language translators and libraries. The following summarizes the language-related environmental limits on a conforming implementation; the library-related limits are discussed in clause 7.

# 5.2.4.1 Translation limits

The implementation shall be able to translate and execute at least one program that contains at least one instance of every of the following:¹⁸

+   - 127 nesting of blocks

+   - 63 nesting of conditional inclusion

+   - 22 pointer, array, and function declarators (in any combinations) modifying an arithmetic, union, or void type in a declaration

+   - 63 nesting of parenthesized declarators within a full declarator

+   - 63 nesting of parenthesized expressions within a full expression

+   - 63 significant initial characters in an internal identifier or a macro name (each universal character name or extended source character is considered a single character)

+   - 31 significant initial characters in an external identifier (each universal character name specifying a short identifier of 0000FFFF or less is considered 6 characters, each

> ¹⁸ Implementations should avoid fixed translation limits whenever possible.
