5 The library defines a number of atomic operations (7.17) and operations on mutex (7.26.4) that are specially identified as synchronization operations. These operations play a special role in making assignments in one thread visible to another. A synchronization on one or more memory locations is either an acquire operation, a release operation, both an acquire and release operation, or a consume operation. A synchronization operation without an associated memory location is a fence and can be either an acquire fence, a release fence, or both an acquire and release fence. We do not include atomic operations as synchronization operations although, like synchronization operations, they cannot cause data races.

7 All modifications to a particular object M occur in some particular total order, called the modification order of M. If A and B are modifications of an atomic object M, and A happens before B, then A will precede B in the modification order of M, which is defined below.

8 NOTE 3 This states that the modification orders must respect the "happens-before" relation.

9 NOTE There is a release order for each atomic object. There is no requirement that these be combined into a single total order for all objects. In general this will be impossible since different threads may observe modifications in different variants and orders.

10 A release sequence headed by a release operation A on an atomic object M is a maximal contiguous sequence of side effects in the modification order of M, where the first operation is A and every subsequent operation is performed by the same thread that performed the release or is an atomic read-modify-write operation.

11 Library calls synchronize with other library calls performed by another thread. In particular, an atomic operation A performs a release operation on an object M synchronizes with an atomic operation B performs an acquire operation on M and reads a value written by any effect in the release sequence headed by A.
