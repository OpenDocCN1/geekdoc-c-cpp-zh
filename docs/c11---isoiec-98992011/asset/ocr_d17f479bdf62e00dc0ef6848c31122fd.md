# 7.6.1 The FENV_ACCESS pragma

Synopsis

```
#include <fenv.h>
#pragma STDC FENV_ACCESS off-switch
```

Description

+   2 The FENV_ACCESS pragma provides a means to inform the implementation when a
program access the floating-point environment to test floating-point status flags or
run under non-default floating-point control modes,$^{213}$ The pragma shall occur either
outside external declarations or preceding all declarations and statements in a
compound statement. When outside external declarations, the pragma takes effect from
its occurrence until another `FENV_ACCESS` pragma is encountered, or until the end of
translation unit. When a compound statement, the pragma takes effect from its
occurrence until another `FENV_ACCESS` pragma is encountered (including within a
ested compound statement), or until the end of the compound statement; at the end of a
compound statement the state is restored to its condition just before the
compound statement. If a part of program is used in any other context, the behavior is
undefined. If a part of program tests floating-point status flags, sets floating-point control
modes, or runs under non-default mode settings, was translated with the state for the
`FENV_ACCESS` pragma “off”, the behavior is undefined. The state is implementation-defined. (When execution processes a part of
program translated with `FENV_ACCESS` “off” to a part translated with
`FENV_ACCESS` “on”, the state of the floating-point status flags is unspecified and
floating-point control modes have their default settings.)

> 212 See “future library directions” (73.14).

> 213 The purpose of the FENV_ACCESS pragma is to allow certain optimizations that could forbid flag
tests and changes (e.g., global subexpression elimination, code motion, and constant
folding). In general, if the state of FENV_ACCESS is “off”, the translator can assume default
modes and that flags are in effect and not changed.
