# 7.1.4 Use of library functions

+   Each of the following statements applies a function unless explicitly stated otherwise in the detailed descriptions that follow: if an argument has an invalid value (such as a value outside the domain of the function, or a pointer outside the address space of the program, or a null pointer, or a pointer to non-modifiable storage where the corresponding parameter is not const-qualified) or a type (after promotion) not expected by a function with variable number of arguments, the behavior is undefined. If a function argument is described as an array, the pointer actually passed to the function shall have a value such that all computations and accesses to objects (that would be valid if the pointer pointed to the first element of such array) are in fact valid. Any function declared in a header may be additionally implemented as a function-like macro defined in the header, so if a function is declared explicitly when header is included, one of the techniques shown below can be used to ensure the declaration is not affected by such macro. A macro definition of a function can be supported locally enclosing the name of the function in parentheses, because then it is not followed by the left parenthesis that indicates expansion of a macro name. For the same syntactic reason, it is permitted to take the address of a function even if it is also defined as a macro.¹185) The use of #undef remove any macro definition will also ensure that an actual function is returned. Any invocation of a function that is implemented as a macro shall expand to evaluate each of its arguments once, fully protected by parentheses where necessary, it is generally safe to use arbitrary expressions as arguments.¹186) Likewise, those function-like macros described in the following subclauses may be invoked in an expression where a function with a compatible return type may be called¹187) All object-like macros listed as expanding

185) This means that an implementation should provide an actual function for each library function, even if it also provides a macro for that function.

186) Such macros might not contain the sequence that the corresponding function calls.

187) Because external identifiers and some macro names beginning with an underscore are reserved, implementations may provide special semantics for such in-line code. For example, the identifier _BUILTIN_abs could be used to indicate generation of in-line code for the abs function. Thus, the appropriate coder should specify

```
#define abs (x) BUILTIN_abs (x)
```

for a compiler whose code generator will accept it.
In this manner, a user desiring to guarantee that a given library function such as abs will be a genuine function may write

#undef abs

whether the implementation's header provides a macro implementation of abs or a built-in implementation. The prototype for the function, which proceeds and is hidden by any macro definition, is revealed also.
