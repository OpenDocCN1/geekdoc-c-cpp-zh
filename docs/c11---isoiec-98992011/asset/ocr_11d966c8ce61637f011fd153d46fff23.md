# 6.5.16.1 Simple assignment

Constraints

+   One of the following shall hold:¹¹¹²
- the left operand has atomic, qualified, or unqualified arithmetic type, and the right has qualified arithmetic type;
- the left operand has atomic, qualified, or unqualified version of a structure or union compatible with the type of the right;
- the left operand has atomic, qualified, or unqualified pointer type, and (considering the type left operand would have Ivalue conversion) both operands are pointers to qualified or unqualified versions of compatible types, and the type pointed to the left has all the qualifiers of the type pointed to the right;
- the left operand has atomic, qualified, or unqualified pointer type, and (considering the type left operand would have Ivalue conversion) one is a pointer to an object type, and the other is a pointer to a qualified or unqualified version of void, and the type pointed to the left has all the qualifiers of the type pointed to the right;
- the left is an atomic, qualified, or unqualified pointer, and the right is a null pointer constant; or
- the left operand has type, qualified, or unqualified _Bool, and the right is a pointer.

# Semantics

+   In simple assignment (=), the value of the right operand is converted to the type of the assignment expression and replaces the value stored in the object designated by the left operand.

+   If the value being stored in an object is read from another object that overlaps in any map then the storage of the first object, then the overlap shall be exact and the two objects shall have qualified or unqualified versions of a compatible type; otherwise, the behavior is undefined.
