7 If the expression denotes the called function has a type that does include a prototype, the arguments are implicitly converted, as by assignment, to the types of the corresponding parameters, taking the type of each parameter to the unqualified version of its declared type. The ellipsis notation in a function declarator causes argument conversion to stop after the last declared parameter. The default arguments are performed on trailing arguments.

8 No conversions are performed implicitly; in particular, the number and types of arguments are not compared with those of the parameters in a function definition that does not include a function prototype declarator.

9 If the function is defined with a type that is not compatible with the type (of the expression) pointed to by the expression that denotes the called function, the behavior is undefined.

10 There is a sequence point before the evaluations of the function designator and the actual arguments. Every evaluation in the calling function (including other function calls) that is not otherwise specified before or after the execution of the called function is indeterminately sequenced with respect to the execution of the called function.⁹⁴

11 Recursive function calls shall be permitted, both directly and indirectly through any chain of other functions.

the f1, f2, and f4 may be in any order. All side effects have to be completed before the function pointed to by pf[f1(j)] is called.

# 6.5.2.3 Structure and union members

Constraints

1 The first operand of the . shall have atomic, qualified, or unqualified structure or union, and the second operand shall name a member of that type.

2 The first operand of the -> operator shall have type "pointer to atomic, qualified, or unqualified structure" or "pointer to atomic, qualified, or unqualified union", and the second operand shall name a member of the type pointed to.

⁹⁴ In order, function executions do not "interleave" with each other.
