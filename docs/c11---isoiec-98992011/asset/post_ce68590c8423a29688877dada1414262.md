## 6.7.5 Alignment speculator

### Syntax

```
alignment-specifier:
_Alignas ( type-name )
_Alignas ( constant-expression )
```

### Constraints

- An alignment attribute should not be specified in a declaration of a typedef, or a bit-field, or a function, or a parameter, or an object declared with storage-class specifier.
- The constant expression shall be an integer expression. It shall evaluate to a fundamental alignment, or to a valid alignment supported by the implementation in the context in which it appears, or to zero.
- The combined effect of all alignment attributes in a declaration shall not specify an alignment that is less than the alignment that would otherwise be required for the type of the object being declared.

### Semantics

- The first form is equivalent to _Alignas (type-name).- The alignment requirement of the declared object or member is taken to be the specified alignment. An alignment specification of zero has no effect. When multiple alignment specifies in a declaration, the effective alignment requirement is the strictest specifier. If the definition of an object has an alignment specifier, any other declaration of that object should either specify equivalent alignment or have no alignment. If the definition of an object does not have an alignment specifier, any other declaration of that object should also have no alignment. If declarations of an object in different translation units have different alignment specifiers, the behavior is undefined.

## 6.7.6 Declarators

```
declarator:
  pointer_opt direct-declarator
  direct-declarator:
    identifier
    ( declarator )
    direct-declarator [ type-qualifier-list_opt assignment-expression ]
    direct-declarator [ static type-qualifier-list assignment-expression ]
    direct-declarator [ type-qualifier-list static assignment-expression ]
    direct-declarator [ type-qualifier-list * ]
    direct-declarator ( parameter-type-list )
pointer:
  * type-qualifier-list_opt
  * type-qualifier-list pointer
type-qualifier-list:
  type-qualifier
  type-qualifier-list type-qualifier
parameter-type-list:
  parameter-list
  parameter-list, ...
parameter-declaration:
  declaration-specifiers declarator
  declaration-specifiers abstract-declarator_opt
```

- identifier-list: identifier, identifier-list
- Each declarator declares one identifier, and asserts that when an operand of the same form as the declarator appears in an expression, designates an object with scope, storage duration, and type indicated by the declaration specifiers.
- A full declarator is a declarator that is not part of another declarator. The end of a full declarator is a sequence. If, in the nested sequence of declarators in a full declarator, there is a declarator specifying a variable length type, the type specified by the full declarator is said to be variably modified. Furthermore, any type derived by the declarator from a variably modified type is itself variably modified.

In the following clauses, consider a declaration where T contains the declarator specifiers that specify T (such as int) and D1 is a declarator that contains an identifier. The type specified for the identifier in the various forms of declarator is described using this notation:

- If, in declaration T D1, D1 has the form identifier then the type specified for ident is T.
- If, in declaration T D1, D1 has the form ( D ) then the type specified by the declaration is T. Thus, a declarator in parentheses is identical to the unparenthesized declarator, but the binding of complicated declarators may be altered by parentheses.

### Implementation limits

As discussed in 5.2.4, an implementation may limit the number of pointer, array, and function declarators that modify an arithmetic, structure, or void type, either directly by one or more typedefs.

## 6.7.6.1 Pointer declarations

### Semantics

If, in the declaration T D1, D1 has the form * type-qualifier-list_opt D and the type specified for ident in the declaration T D is *-declarator-type-list T, and the type specified for ident is *-declarator-type-list type-qualifier-list pointer to T. For each qualifier in the list, ident is a so-qualified pointer. For two pointers to be compatible, both shall be identically identified and shall be pointers to compatible types.

EXAMPLE The following pair of declarations demonstrates the difference between a “variable pointer to a constant value” and a “constant pointer to a variable value”.

```c
const int *ptr_to_const;
int *const constant_ptr;
```

The contents of any object pointed by ptr_to_const shall not be modified by that pointer, but ptr_to_const itself may be changed to point to another object. Similarly, the contents of the int pointed by constant_ptr may be modified, constant_ptr itself shall always point to the same location.

The declaration of the constant pointer_ptr may be clarified by using a definition for the type “pointer to int”.

```c
typedef int *int_ptr;
const int *int_ptr constant_ptr;
```

declares constant_ptr as an object that has type “const-qualified pointer to int”.

## 6.7.6.2 Array declarations

### Constraints

In addition to type qualifiers and the keyword static, the [ ] may delimit an expression or *. If they delimit an expression (which specifies the size of an array), the expression shall have an integer type. If the expression is a constant expression, it shall have a value greater than zero. The element type shall not be an incomplete or function type. The only qualifiers and the keyword static shall appear only in a declaration of a function parameter with an array, and only in the outermost array derivation.

If an identifier is declared as having a variably modified type, it shall be an ordinary identifier (defined in 6.2.3), without linkage, and have either block scope or function prototype scope. If an identifier is declared to be an object with static or storage duration, it shall not have a variable length array type.

### Semantics

- If, in the declaration type-qualifier-list D, D has one of the forms:
```
D[ type-qualifier-list_opt assignment-expression ]
D[ static type-qualifier-list assignment-expression ]
D[ type-qualifier-list static assignment-expression ]
D[ type-qualifier-list * ]
```
and the type specified for ident in the declaration D is derived-declarator-type-list T, then the type specified for ident is derived-declarator-type-list array of T (See 6.7.3 for the meaning of optional type qualifiers and the keyword static.)
- If the size is not set, the array type is an incomplete type. If the size is * instead of being an expression, the array type is a variable length array of unspecified size, which can only be used in declarations or type names with prototype scope; such arrays are nevertheless complete types. If the size is an integer constant expression and the element type is not a variable length array; otherwise, the array is a variable length array. (Variable length arrays are a conditional feature that implementations may not support; see 6.10.8.3.)
- If the size is an expression that is not an constant expression: if it occurs in a declaration at function prototype scope, it is treated as if it were replaced by */; otherwise, each time it is evaluated it should have a value greater than zero. The size of each variable length array type does not change during lifetime. A size expression is part of the operand of sizeof operator and changing the value of the size expression would not affect the result of the operator, and it is unspecified or not the size expression is evaluated.
- For two types to be compatible, both should have compatible element types, and if both size specifiers are present, and are integer constant expressions, then both size specifiers are used in a context which requires them to be compatible, it is undefined behavior if the two size specifiers evaluate to unequal values.
