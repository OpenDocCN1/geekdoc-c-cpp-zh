# ISO/IEC 9899:2011 (E)

19 A visible side effect $A$ on an object $M$ with respect to a value computation $B$ of $M$ satisfies the conditions:

+   - A happens before B, and
- there is no other side effect $X$ to $M$ such that $A$ happens before $X$ and $X$ happens before B.

The value of a non-atomic scalar object $M$, as determined by evaluation $B$, shall be the value stored by the side effect $A$.

20 NOTE 8 If there is ambiguity about which side effect to non-atomic object is visible, there is a data race and the behavior is undefined.

21 NOTE 9 This states that operations on variables are not ordered. This is not actually detectable without data races, but as defined here, with suitable restrictions on the use of atoms, to data races in a single interleaved (sequentially consistent) execution.

22 The visible sequence of side effects on an atomic object $M$, with respect to a value computation $B$ of $M$ is a contiguous sub-sequence of side effects in the modification order of $M$, where the first side effect is visible with $B$, and for every subsequent effect, it is not the case that $B$ happens before it. The value of an atomic object $M$, as determined by evaluation $B$, shall be the value stored by some operation in the visible sequence of $M$ with respect to $B$. Furthermore, if a value computation $A$ of an object $M$ happens before a value computation $B$ of $M$, and the value computed by $A$ corresponds to the value stored by side effect $X$, then the value computed by $B$ shall either equal the value stored by $A$, or the value stored by side effect $Y$ where $Y$ follows $X$ in the modification order of $M.

23 This effectively disables reordering of atomic operations to a single object, even if both operations are “relaxed” loads. By doing so, we make the “ coherence” guarantee provided by most hardware to $C$ atomic operations.

24 The visible sequence depends on the “happens before” relation, which in turn depends on the observed values of loads, which we are restricting. The intended reading is that there exists an association of atomic loads with those they observe, with suitably chosen modification orders and the “happens before” relation as described above, satisfy the resulting constraints as imposed.

25 The execution of a program contains a data race if it contains conflicting actions in different threads, at least one of which is not atomic, and neither happens before the other. Any such data results in undefined behavior.

26 NOTE 12 It can be shown that programs correctly use mutexes and memory_order_seq_cast prevent all data races, and no synchronization behaves, as the operations executed by their constituent threads are interleaved, with each value computation of an object being the last value stored in that interleaving. This is referred to as “sequential consistency”. However, this only applies to data-free programs, and data-free programs cannot perform most transformations that do not change single-threaded program semantics. In fact, most single-threaded program transformations can be allowed, any program that behaves differently as a result undefined.
