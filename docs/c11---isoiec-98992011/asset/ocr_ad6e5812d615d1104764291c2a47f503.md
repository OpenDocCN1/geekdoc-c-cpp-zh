# F.8.5 Initialization

All computation for automatic initialization is done (as if) at execution time; thus, it is affected by any operate modes and floating-point exceptions as required by IEC 60559 (provided the state of the FENV_ACCESS pragma is “on”). All computation for initialization of objects that have static or thread storage duration is done (as if) at translation time.

```
#include <fenv.h>
#pragma STDC FENV_ACCESS ON
void f(void) {
    float u[] = { 1.1e75 }; // raises exceptions
    static float v = 1.1e75; // does not raise exceptions
    float w = 1.1e75; // raises exceptions
    double x = 1.1e75; // may raise exceptions
    float y = 1.1e75; // may raise exceptions
    long double z = 1.1e75; // raises exceptions
    /* ... */
}
```

The static of v raises (no execution-time) floating-point exceptions because its computation is done at translation time. The automatic initialization of u and w require an execution-conversion to float of the value 1.1e75, which raises floating-point exceptions. The automatic initializations of x and y entail execution-conversion; however, in some evaluation methods, the conversions are not to a narrower format, in case no floating-point exception is raised.³67 The automatic initialization of z entails execution-conversion, but not to a narrower format, so no floating-point exception is raised. That the conversions of the constants 1.1e75 and 1.1e75f of their internal representations occur at translation time in all cases.
