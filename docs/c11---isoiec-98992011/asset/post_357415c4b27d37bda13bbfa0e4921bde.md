# Description

- 2 An integer character constant is a sequence of one or more multibyte characters enclosed in single-quotes, as in 'x'. A wide character constant is the same, except prefixed by the letter L, u, or U. With a few exceptions detailed, the elements of the sequence are members of the source character set; they are mapped in an implementation-defined manner to members of the execution character set.

- 3 The single-quote ', the double-quote ", question-mark ?, the backslash \, and arbitrary integers are representable according to the following table of escape sequences:

| single quote ' | \' |
| double quote " | \" |
| question mark ? | \? |
| backslash \ | \\\ |
| octal character | \octal digits |
| hexadecimal character | \x hexadecimal-digit |

- 4 The double-quote " and question-mark ? are representable either by themselves or by the escape sequences \" and \?, respectively, the single-quote ' and the backslash \ shall be represented, by the escape sequences \' and \\.

- 5 The digits that follow the backslash in an escape sequence are taken to be part of the construction of a single character for an integer character constant or of a single character for a wide character constant. The numerical value of the octal integer so forms the value of the desired character or wide character.

- 6 The hexadecimal digits that follow the backslash and the letter \x in a hexadecimal escape sequence are taken to be part of the construction of a single character for an integer character constant or of a single character for a wide character constant. The numerical value of the hexadecimal integer so forms the value of the desired character or wide character.

- 7 Each octal or hexadecimal escape sequence is the longest sequence of characters that can constitute the escape sequence.

- 8 In addition, characters not in the basic character set are representable by universal character names and certain nongraphic characters consisting of the backslash \ followed by a lowercase letter: \a, \b, \f, \n, \r, \t, and \v(77).

# Semantics

An integer character has type int. The value of an integer constant containing a single character that maps to a single-byte execution character is the numerical value of the representation of the character interpreted as the integer. The value of integer constant containing more than one character (e.g., 'ab'), or containing a character or escape sequence that does not map to a single-byte execution character, is implementation-defined. If an integer constant contains a single character or escape sequence, its value is the one that results when a wide character prefixed by the letter L has type wchar_, defined in <stddef.h>; a wide character prefixed by the letter u or U has type char16_t or char32_t, respectively, unsigned types defined in <uchar.h> header. The value of a wide character containing a single multibyte character corresponding to the execution character set is the wide character as defined by mbtowc, mbrtoc6, or mbrtoc32 as its type, with implementation-defined value.

# Constraints

- 2 A sequence of adjacent string literal tokens shall not include both a wide string literal and a UTF–8 string literal.

# Description

- 3 A string literal is a sequence of zero or more multibyte characters enclosed in double-quotes, as in "xyz". A UTF–8 string literal is the same, except prefixed by u8. A wide string literal is the same, except prefixed by the letter L, u, or U.

- 4 The same considerations apply to each element of a string as if it were in an integer constant (for a character or UTF–8 string literal) or a wide character (for wide literal), which is representable by itself or by the escape sequence '\', but the double-quote " shall be represented by the escape sequence \".

# Semantics

- 5 In translation phase 6, the multibyte character sequences specified by any sequence of adjacent character and identically-prefixed string literal tokens are concatenated into a single multibyte character sequence. If any of the tokens has an encoding prefix, the resulting multibyte character sequence is treated as having the same prefix; otherwise, it is treated as a string literal. Whether differently-prefixed string literal tokens can be concatenated and, if so, the result of the resulting multibyte character sequence is implementation-defined.

- 6 In translation phase 7, a byte or code value of zero is encoded to each multibyte character sequence that results from a string literal or literals. The multibyte character sequence is then used to initialize an array of static storage duration and length sufficient to contain the sequence. For character literals, the array elements have type char, and are initialized with the individual characters of the multibyte character sequence. For UTF–8 string literals, the array elements have type char, and are initialized with the characters of the multibyte character sequence, as encoded in UTF-8. For wide string literals prefixed by the letter l, the array elements have type char_t and are initialized with the sequence of wide characters corresponding to the multibyte character sequence, as defined by the mbstows function with an implementation-defined current locale. For wide string literals prefixed by the letter u or O, the array elements have type char16_t or char32_t, respectively, and are initialized with the sequence of wide characters corresponding to the multibyte character sequence, as defined by successive calls to mbrtoc6, mbrtoc32 as appropriate for its type, the value of string literal containing a multibyte character or escape sequence not represented in the execution character set is implementation-defined.

- 7 It is unspecified whether these arrays distinct their elements have the appropriate values. If the program attempts to modify an array, the behavior is undefined.
