# 6.2.6 Representations of types

# 6.2.6.1 General

The representations of all types are unspecified except stated in this subclause.

Except for bit-fields, objects are composed of contiguous sequences of one or more bytes, the number, order, and encoding of which are either explicitly specified or implementation-defined.

Values stored in unsigned bit-fields and objects of type unsigned char shall be represented using a pure binary notation.^{49}

4 Values stored in non-bit-field objects of any other object type of n ×CHAR_BIT bits, where n is the size of an object of that type, in bytes. The value may be copied into an object of type unsigned char [n] by memcpy; the resulting set of bytes is called the object representation of value. Values stored in bit-fields of m bits, where m is the size that the bit-field comprises in the addressable storage unit it holds. Two values (other than NaNs) with the same object representation compare equal, but values that compare equal have different object representations.

5 Certain objects represent not a value of the object type. If the stored value of an object has such a representation and is read by anvalue expression that does not have character, the behavior is undefined. If such a representation is produced by a side effect that modifies or any part of the object by an Ivalue expression that does not have character, the behavior is undefined.^{50} Such representation is called a trap representation.

6 When a value is stored in an object of structure or union type, including a member object, the bytes of the object representation correspond to any padding bytes takes unspecified values.^{51} The value of a structure or union is never a trap
