# Semantics

As discussed in 6.2.5, a structure is a type consisting of a sequence, and a union may overlap. The keywords `struct` and `union` indicate that the type being specified is, respectively, a structure type or a union type.

The presence of a struct-declaration-list in a struct-or-union-specifier declares a new, within a translation unit. The struct-declaration-list is a sequence of declarations for the members of the structure or union. The type is incomplete until immediately after the list.

As specified in 6.7.2, if the actual type is `int` or a typedef-name defined as `int`, then it is implementation-defined whether the bit-field is signed or unsigned.

A bit-field is interpreted as having signed or unsigned type consisting of the specified number of bits. If the value 0 or 1 is stored in a nonzero-bit-field of type _Bool, the value of the bit-field shall compare to the value; a _Bool has the semantics of a _Bool.

An implementation may allocate any addressable storage unit to hold a bit-field. If enough space, a bit-field that immediately follows another bit-field in a structure shall be packed into adjacent bits of the same unit. In insufficient space, whether a bit-field does fit into the next unit or overlaps adjacent units is implementation-defined. The order of allocation of bit-fields within a unit (high-order to low-order or low-order to high-order) is implementation-defined. The alignment of the addressable storage unit is unspecified.
