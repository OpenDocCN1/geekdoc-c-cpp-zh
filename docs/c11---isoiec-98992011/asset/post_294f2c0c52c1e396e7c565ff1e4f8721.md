## 5.1.2.2.3 Program termination

If the return type of the main function is a type compatible with int, a return from the initial call to the main function is equivalent to calling the exit function with the value returned by the main function as its argument;¹¹ reaching the } that terminates the main function returns a value of 0. If the return type is not compatible with int, the termination status returned to the host environment is unspecified.

## 5.1.2.3 Program execution

The semantic descriptions in this International Standard describe the behavior of an abstract machine which issues of operation are irrelevant.

Accessing a volatile object, modifying an object, modifying a file, or calling a function that does any of those operations are side effects,¹² which change the state of the execution environment. Evaluation of an expression in general includes both value computations and initiation of side effects. Value computation for an Lvalue expression includes the determination of the designed object.

Sequenced before is an asymmetric, transitive, pair-wise relation between evaluations executed by a single thread, which induces a particular order among evaluations. Given any two evaluations A and B, if A is sequenced before B, then the execution of A shall precede the execution of B. (Conversely, if A is sequenced before B, then B is sequenced after A.) If A is not sequenced before or after B, then A and B are unsequenced. 9 EXAMPLE 1 An implementation might define a one-to-one correspondence between abstract and actual semantics: at every sequence point, the values of the actual objects would agree with those specified by the abstract semantics. The keyword **volatile** would be redundant.

10 Alternatively, an implementation might perform various optimizations within each translation unit, such that the actual semantics agree with abstract only when making function calls across translation unit boundaries. In such an implementation, the life of each function and return value where the calling and called function are in different translation units, the values of externally linked objects and all objects accessible via pointers therein agree with the abstract semantics. Furthermore, at the time of function entry the values of the parameters of the function and all objects accessible via pointers would agree with the abstract semantics. In this type of implementation, objects referred to by interrupt service routines would require explicit declaration of **volatile** storage, as well as other implementation-defined restrictions.

14 EXAMPLE 5 Rearrangement for floating-point operations is often restricted because of the precision as well as range. In the following fragment, rearrangements cannot replace decimal constants in order to rearrange expressions.

```c
double x, y, z;
/* ... */
x = (x * y) * z; // not equivalent to x = y * z;
z = (x - y) + y; // not equivalent to z = x;
z = z + x * y; // not equivalent to z = x * (1.0 + y);
y = x / 5.0; // not equivalent to y = x * 0.2;
```

15 EXAMPLE 6 To illustrate the grouping behavior of operators, in the following fragment
```c
int a, b;
/* ... */
a = a + 32760 + b + 5;
```
the expression statement behaves exactly as the
```c
a = ((a + 32760) + b);
```
due to the associativity and precedence of these operators. Thus, the result of the sum (a + 32760) next added to b, and then added to 5 results in the value assigned to a. On a machine which overflows produces an explicit trap and in which range of values representable by an int is [-32768, +32767], the implementation cannot rewrite this expression as
```c
a = ((a + b) + 32765);
```
since the values for a and b were respectively, -32754 and -15, the same a + b would produce an overflow.
