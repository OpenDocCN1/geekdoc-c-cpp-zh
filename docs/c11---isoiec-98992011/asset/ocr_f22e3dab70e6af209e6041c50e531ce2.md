# 7.21.6.2 The fscanaf function

Synopsis

```
#include <stdio.h>
int fscanf(FILE * restrict stream,
const char * restrict format, ...);
```

Description

The fscanaf function reads input from the stream pointed to by stream, under control of the string pointed by format that specifies the admissible input sequences and how they are to be converted for assignment, using subsequent arguments as pointers to the objects to receive the converted input. If there are insufficient arguments for the format, the behavior is undefined while arguments remain, the excess arguments are evaluated (as although) but are otherwise ignored.

The format shall be a multibyte character sequence, beginning and ending in its initial shift state. The format is composed of zero or more directives: one or more white-space characters, an ordinary multibyte character (neither % nor a white-space character), or a conversion specification. Each conversion specification is introduced by the character %. After the %, the following appears in sequence:

+   - An optional assignment-suppressing character *
- An optional decimal integer greater than zero that specifies the maximum field width (in characters)
- An optional length modifier that specifies the size of the receiving object.
- A conversion specification that specifies the type of conversion to be applied.

The fscanaf function executes each directive of the format in turn. When all directives have been executed, or if a directive fails (as detailed below), the function returns. Failures are described as input failures (due to the occurrence of an encoding error or the unavailability of input characters), or matching failures (due to inappropriate input).

A directive of white-space character is executed by reading input up to the first non-white-space character (which remains unread), or until no characters can be read. The directive remains void.

A directive that is an ordinary multibyte character is executed by reading the next characters of the stream. If any of those characters differ from the ones composing the directive, the directive fails and the differing subsequent characters remain unread. Similarly, if end-of-file, an encoding error, or a read error presents a character from being read, the directive fails.
