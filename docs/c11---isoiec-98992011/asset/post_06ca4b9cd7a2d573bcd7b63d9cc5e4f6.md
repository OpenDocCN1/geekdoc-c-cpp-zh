## 7.14 Signal handling <signal.h>

The header <signal.h> declares a type two functions and defines several macros, for handling various signals (conditions that may be reported during program execution).

The type defined is
sig_atomic_t
which is the (possibly volatile-qualified) integer type of an object that can be accessed as an atomic entity, in the presence of asynchronous interrupts.

The macros defined are
SIG_DFL
SIG_ERR
SIG_IGN
which expand to constant expressions with distinct values that have type compatible with the second argument, and the return value of, the signal function, and whose values compare unequal to the address of any declarable function; and the following, which expand to positive integer constant expressions with type int and distinct values that are the signal numbers, each corresponding to the specified condition:

- SIGABRT abnormal termination, such as is initiated by the abort function
- SIGFPE an erroneous arithmetic operation, as zero divide or an operation resulting in overflow
- SIGILL detection of an invalid function image, such as an invalid instruction
- SIGINT receipt of an interactive attention signal
- SIGSEGV an invalid access to storage
- SIGTERM a termination request to stop the program

An implementation need generate any of these signals, except as a result of explicit calls to the raise function. Additional signals and pointers to undefined functions, with macro definitions beginning, respectively, with the letters SIG and an uppercase letter or with SIG_, and an uppercase letter. may also be specified by the implementation. The complete set of signals, their semantics, and their default handling are implementation-defined; all signal numbers shall be positive.

### 7.14.1.1 The signal function

Synopsis

```c
#include <signal.h>
void (*sig(int sig, void (*func) (int))) (int);
```

Description

- 2. The signal function chooses one of three ways in which receive of the signal sig is subsequently handled. If the value of func is SIG_DFL, default handling for that signal will occur. If the value of func is SIG_IGN, the signal is ignored. Otherwise, func shall point to a function to be called when signals occur. An invocation of such a function as a signal, or (recursively) of any further functions called by that invocation (other functions in the standard library).²251 is called a signal handler.

- 3 When a signal occurs and func points to a function, it is implementation-defined whether the equivalent of signal(sig, SIG_DFL); is executed or the implementation provides some implementation-defined set of signals (at least including sig) from occurring until the current signal handling has completed; in case of SIGILL, the implementation may alternatively define that no action is taken. If and when the function returns, the value of sig is SIG_FPE, SIGPIPE, SIGSEGV, or any other implementation-defined value corresponding to a computational exception, the behavior is undefined; otherwise the program will resume execution at the point it was interrupted.

## 7.16 Variable arguments <stdarg.h>

- 1 The header <stdarg.h> declares a type and defines four macros, for handling signals, with macro definitions beginning, respectively, with the letters SIG and an uppercase letter or with SIG_, and an uppercase letter. may also be specified by the implementation.

- 2 A function may be called with a variable number of arguments. Its parameter list contains one or more parameters. The rightmost parameter plays a special role, and may be designated par in this description. The type declared is
va_list
which is a complete object suitable for holding information needed by the va_start, va_arg, va_end, and va_copy. If access to the varying arguments is desired, the function shall declare an object (generally referred to as ap) having type va_list. The object may be passed as an argument to another function; if function invokes the va_arg macro with ap, the value of ap is indeterminate and shall be passed to the va_end macro prior to any further reference to ap (253).

- 3 The va_start and va_arg macros described in this subclause will be implemented as macros for advancing through a list of arguments whose number and types are not known to the called function.

- 4 It is unspecified whether va_copy and va_end are macros or identifiers declared with external linkage. If a macro definition is suppressed in order to access an actual function, or a program defines an external identifier with the same name, the behavior is undefined. Each invocation of the va_start and va_copy macros shall be matched by a corresponding invocation of the va_arg macro in the same function.
