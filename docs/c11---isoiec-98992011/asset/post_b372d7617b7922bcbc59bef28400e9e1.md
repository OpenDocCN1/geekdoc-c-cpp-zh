## Description

+ 2 The strtol, strtoll, strtoul, and strtoull functions convert the initial portion of the string pointed to by nptr to long int, long long int, unsigned long int, and unsigned long long int representation. First, they decompose the input into three parts: an initial, possibly empty, sequence of white-space characters (as separated by the isspace function), a subject sequence

+ If the value of **base** is zero, the expected form of the subject sequence is that of an integer constant as described in 6.4.4.1, optionally preceded by a plus or minus sign, not including an integer suffix. If the value of **base** is between 2 and 36 (inclusive), the expected form of the subject sequence is a sequence of letters and digits representing the integer with the radix specified by **base**, optionally preceded by a plus or minus sign, but not including an integer suffix. The letters from a **a** (or **A**) through **z** (or **Z**) are assigned the values 10 through 35; only letters and digits whose values are less than that of **base** are permitted. If the value of **base** is 36, the characters **0x** or **0OX** are returned. They may optionally provide the sequence of letters and digits, following the sign if present.

+ The sequence is defined as the longest initial subsequence of the input string, starting with the first non-white-space character, that is of the expected form. The subject sequence contains no characters if the input string is empty or consists of entirely white space, or if the first non-white-space character is other than a sign or a permissible character or digit.

+ If the sequence has the expected form and the value of **base** is zero, the sequence of characters starting with the first digit is interpreted as an integer constant according to the rules of 6.4.4.1. If the sequence has the expected form and the value of **base** is between 2 and 36, it is used as the base for conversion, adapting each letter to value as given above. If the subject begins with a minus sign, the value resulting from the conversion is negated (in the return type). A pointer to the final string is stored in the object pointed to by **endptr**, provided that **endptr** is not a null pointer.

+ In other than the "C" locale, additional locale-specific subject sequence forms may be accepted.

+ If the sequence is empty or does not have the expected form, no conversion is performed; the value of **nptr** is stored in the object pointed to by **endptr**, provided that **endptr** is not a null pointer.

## 7.22.2 Pseudo-random sequence generation functions

## 7.22.2.1 The rand function

## Synopsis

```
#include <stdlib.h>
int rand(void);
```

## Description

The rand function computes a sequence of pseudo-random integers. The rand function is not required to avoid data races with other calls to sequence generation functions. The implementation shall behave as no library function.

## Returns

The rand function returns a pseudo-random integer.

## Environmental limits

The value of RAND_MAX shall be at least 32767.

## 7.22.2.2 The srand function

## Synopsis

```
#include <stdlib.h>
void srand(unsigned int seed);
```

## Description

The srand function uses the argument as a seed for a new sequence of pseudo-random numbers. If srand is called with the same seed value the sequence shall be repeated. If rand is called before any calls to srand have been made, the same sequence shall be generated as when srand is first called with a seed value of 1.

## Returns

The srand function returns no value.

```
static int next = 1;
int rand(void)      // RAND_MAX assumed to be 32767
{
    next = next * 110351245 + 12345;
    return (unsigned int)(next/65536) % 32768;
}
void srand(unsigned int seed)
{
    next = seed;
}
```

## 7.22.3 Memory management functions

The order and continuity of storage allocated by successive calls to the **aligned_alloc**, **malloc**, and **realloc** functions is unspecified. The lifetime of an allocated object extends from the allocation until the deallocation. Each allocation shall yield a pointer to an object disjoint from any other object. The pointer returned if the allocation succeeds is suitably assigned so that it may be assigned to a pointer to any object with a fundamental requirement and then used to access such an object or array of objects in the space. The pointer points to the start (lowest address) of the allocated space. If the size of the space requested is zero, the behavior is implementation-defined: either a null pointer is returned, or the behavior is as if the size were nonzero value, except that the returned pointer shall not be used to access an object.

For purposes of determining the existence of a data race, memory allocation functions behave as though they accessed memory locations accessible through their arguments and no other static duration. These functions may, however, visibly modify the state they allocate or deallocate. Each call to **free** or **realloc** deallocates a region $p$ of memory synchronizes with any allocation that allocates all or part of the region $p$. This synchronization occurs after any access of $p$ by the allocating function.
