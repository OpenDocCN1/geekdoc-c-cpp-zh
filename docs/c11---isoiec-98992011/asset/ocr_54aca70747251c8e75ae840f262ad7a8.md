# 6.10.3.3 The ## operator

Constraints

+   1 A ## preprocessing token shall not occur at the beginning or at the end of a replacement list for either form of macro definition.

Semantics

+   2 If, in the replacement list of a function-like macro, a parameter is immediately preceded or followed by a ## preprocessing token, the parameter is replaced by the corresponding argument’s preprocessing token sequence; however, if an argument consists of no preprocessing tokens, the parameter is replaced by a placemarker preprocessing token instead.(173)

+   3 For both object-like and function-like invocations, the replacement list is reexamined for more macro names to replace, each instance of a ## preprocessing token in the replacement list (not from an argument) is deleted and the preceding preprocessing token is concatenated with the following preprocessing token. Placemarker preprocessing tokens are handled specially: concatenation of two placeholders results in a single placemarker preprocessing token, and concatenation of a placemarker with a non-placemarker preprocessing token in the non-placemarker preprocessing token. If the result is not a valid preprocessing token, the behavior is undefined. The resulting token is valid for further macro replacement. The order of evaluation of ## operators is unspecified.

+   4 EXAMPLE In the following:

```
#define hash_hash ## #
#define mkstr(a) a
#define in_between(a) mkstr(a)
#define join(c, d) d_in_between(c hash_hash d)

char p[] = join(x, y); // equivalent to
// char p[] = "x ## y";
```

The expansion proceeds, at various stages:

```
join(x, y)
in_between(x hash_hash)
in_between(x ## y)
mkstr(x ## y)
"x ## y"
```

In other words, expansion hash_hash produces a new token, consisting of two adjacent sharp sharps, this token is not the ## operator.

> 173 Placemarker preprocessing tokens do not appear in the syntax because they are temporary entities that exist only within translation phase 4.
