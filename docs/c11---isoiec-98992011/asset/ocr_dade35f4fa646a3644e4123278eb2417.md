At program startup, three text streams are predefined and not be opened explicitly
— standard input (for reading conventional input), standard output (for writing
conventional output), and standard error (for writing diagnostic output). As initially
opened, the standard error is not fully buffered; the standard input and output
streams are fully buffered if and only if the stream can be determined not to refer
to an interactive device.

Functions that operate additional (temporary) files require a file name, which is a string.
The rules for composing valid file names are implementation-defined. Whether the same
file can be simultaneously open multiple times is also implementation-defined.

Although both text and binary wide-oriented streams are conceptually sequences of wide
characters, the external file associated with a wide-oriented stream is a sequence of
multyte characters, generalized as follows:

encodings for use internal to the program).

Moreover, the encodings used for multibyte characters may differ among files. Both the
nature and choice of such encodings are implementation-defined.

Each conversion occurs as by a call to the mbtwc function, with the conversion
described by the stream's own mbstate_t object. The input functions read
characters from the stream as by successive calls to the fgetc function.

The wide character output functions convert wide characters to multibyte characters and
write to the stream as if they were written by successive calls to the fputwc
function. Each conversion occurs as by a call to the mbctomb function, with the
conversion state described by the stream's mbstate_t object. The output
functions write characters to the stream as by successive calls to the fputc function.

In some cases, some of the input/output functions also perform conversions between
multibyte characters and wide characters. These conversions also occur as by calls to
the mbtwc and wctomb functions.
