## F.4 Floating to integer conversion

If the integer type is Bool, 6.3.1 applies and no floating-point exceptions are raised (even for NaN). If the floating value is infinite or NaN or the integer part of the floating value exceeds the range of the integer type, then the “invalid” floating-point exception is raised and the resulting value is unspecified (6.3.4). Conversion of an integral value that does not exceed the range of the integer type raises no floating-point exceptions; whether conversion of non-integral value raises the “inexact” floating-point exception is unspecified.

## F.5 Binary-decimal conversion

- Conversion from the widest IEC 60559 format to decimal with **DECIMAL_DIG** digits and back is the identity function.
- Conversions involving IEC 60559 follow all recommended practice. In particular, conversion between any supported IEC 60559 format and decimal with **DECIMAL_DIG** or fewer significant digits is correctly rounded (the current rounding mode), which assures that conversion from the widest IEC 60559 format to decimal with **DECIMAL_DIG** digits and back is the identity function.
- If the minimum-width IEC 60559 extended (64 bits of precision) is supported, **DECIMAL_DIG** shall be at least 21. If IEC 60559 double (53 bits of precision) is the widest IEC 60559 format supported, **DECIMAL_DIG** shall be at least 17. (By contrast, **LDBL_DIG** and **DBL_DIG** are 15, respectively, for these formats).

Functions such as strtod convert character sequences to floating types honor the rounding direction. Hence, if the rounding direction might upward or downward, the implementation cannot convert a minus sequence by negating the unsigned sequence.

## F.6 The return statement

If the return expression is evaluated in a floating-point format different from the return type, it is converted as if by assignment to the return type of the function and the resulting value is returned to the caller.

## F.7 Contracted expressions

A contracted expression is correctly rounded (once) and treats infinities, NaNs, signed zeros, subnormals, and the rounding directions in a manner consistent with the basic arithmetic operations covered by IEC 60559.

Recommended practice: A contracted expression should raise floating-point exceptions in a manner generally consistent with the basic arithmetic operations.

## F.8 Floating-point environment

The floating-point environment defined in `<fenv.h>` includes the IEC 60559 floating-point exception status flags and directed-rounding control modes. It also includes IEC 60559 dynamic rounding precision and trap enablement modes, if the implementation supports them.

### F.8.1 Environment management

IEC 60559 requires that floating-point operations implicitly raise floating-point exception status flags, and rounding control modes can be explicitly set to affect result values of floating-point operations. When the state for the `FENV_ACCESS` pragma (defined in `<fenv.h>`) is “on”, these changes to the floating-point state are treated as side effects which respect sequence points.

- Assignment moves carry any extra range.
- This specification does not require dynamic rounding precision nor trap enablement modes.
- If the state for the `FENV_ACCESS` pragma is “off”, the implementation is free to assume the floating-point control modes will be the default and the floating-point status flags will not be tested, which allows certain optimizations (see F.9).

### F.8.2 Translation

During the translation IEC 60559 default modes are in effect:
- The rounding direction mode is rounding to nearest.
- The rounding precision mode (if supported) is set so that results are not shortened.
- Trapping or stopping (if supported) is disabled on all floating-point exceptions.

Recommended practice: The implementation should ensure that the default modes are consistent.

### F.8.3 Execution

During execution the IEC 60559 default modes are in effect:
- The rounding direction mode is rounding to nearest.
- The rounding precision mode (if supported) is set so that results are not shortened.
- Trapping or stopping (if supported) is disabled on all floating-point exceptions.

Recommended practice: The implementation should ensure that the default modes are consistent.

## F.8.4 Constant expressions

An expression that has static or thread duration is evaluated as if by assignment at translation time, except by IEC 60559 (provided the state for the `FENV_ACCESS` pragma is “on”). For other expressions, the evaluation occurs during execution.

## F.8.5 Initialization

All computation for initialization of objects that have static or thread duration is done as if by assignment at translation time, except by IEC 60559 (provided the state for the `FENV_ACCESS` pragma is “on”). For other expressions, the evaluation occurs during execution.
