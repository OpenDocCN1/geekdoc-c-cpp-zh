
## 6.5.15 Conditional operator

Syntax

```
conditional-expression:
logical-OR-expression
logical-OR-expression ? expression : conditional-expression
```

Constraints

The first operand shall be scalar type.

One of the following shall hold for the second and third operands:

- both operands have arithmetic type;
- both operands have the same structure or union type;
- both operands have void type;
- both operands are pointers to qualified or unqualified versions of compatible types;
- one operand is a pointer and the other is a null pointer constant; or
- one operand is a pointer to an object type and the other is a pointer to a qualified or unqualified version of **void**.

Semantics

The first operand is evaluated; there is a sequence point between its evaluation and the evaluation of the second or third operand (whichever is evaluated). The second operand is evaluated only if the first compares unequal to 0; the result is the value of the second or third operand (whichever is evaluated), converted to the type described below.¹¹¹⁰.

If both the second and third operands have arithmetic type, the type that would be determined by the usual arithmetic conversions, they were applied to those operands, the result is the type of the result. If both operands have structure or union type, the result has that type. If both operands have void type, the result has void type.

If both the second and third operands are pointers and one is a null pointer constant and the other is a pointer, the result is a pointer to a qualified with all the qualifiers of the types referenced by both operands. Furthermore, if both operands are pointers to compatible types or to differently qualified versions of compatible types, the result is a pointer to an appropriately qualified version of the composite type; if one operand is a null pointer constant, the result is the type of the other operand; otherwise, one operand is a pointer to **void** or a qualified version of **void**, in which case the result type is a pointer to an appropriately qualified version of **void**.

> ¹¹⁰ A conditional expression does not yield an allowance.

## 6.5.16 Assignment operators

Syntax

```
assignment-expression: 0
conditional-expression
unary-expression assignment-operator assignment-expression
assignment-operator: one of
= /= % += -= << <= >= &= ^ = | |
```

# Constraints

An assignment operator shall have a modifiable lvalue as its left operand.

# Semantics

An assignment operator stores a value in the object designated by the left operand. An assignment expression has the value of the left operand after the assignment,(111) but is not an lvalue. The type of an assignment expression is the type of the left operand would have after value conversion. The side effect of updating the stored value of the left operand is sequenced after the value computations of the left and right operands. The evaluations of operands are unsequenced.

> 111) The implementation is permitted to read the object to determine the value but is not required to, even when the object has volatile-qualified type.

## 6.5.16.1 Simple assignment

Constraints

- One of the following shall hold:¹¹¹²
- the left operand has atomic, qualified, or unqualified arithmetic type, and the right has qualified arithmetic type;
- the left operand has atomic, qualified, or unqualified pointer to a complete object, and the right has integer type; or the left operand has atomic, qualified, or unqualified arithmetic type, and the right has arithmetic type.
- the left operand has atomic, qualified, or unqualified arithmetic type, and (considering the type the left operand would have Aftervalue conversion) each operand shall have arithmetic type consistent with those allowed by the binary operator.
- the left operand has atomic, qualified, or unqualified arithmetic type, and (considering the type left operand would have Aftervalue conversion) the right is compatible with the type;
- the left operand has atomic, qualified, or unqualified arithmetic type, and (considering the type left operand would have Aftervalue conversion) the right has qualified arithmetic type;
- the left operand has atomic, qualified, or unqualified arithmetic type, and the right has integer type;
- the left operand has atomic, qualified, or unqualified arithmetic type, and the right is a pointer.
- the left is atomic, qualified, or unqualified pointer, and the right is a null pointer constant; or
- the left is atomic, qualified, or unqualified pointer, the right is int.

# Semantics

- In simple assignment (=), the value of the right operand is converted to the type of the assignment and replaces the value stored in the left operand.
- If the value being stored in an object is read from another object that overlaps in any type, then the overlap shall be exact and the two objects shall have compatible types; otherwise, the behavior is undefined.

The asymmetric appearance of these constraints with respect to type is due to the conversion (specified in 6.3.2.1) that removes any type qualifiers (for example, it removes const volatile from the type int * const).
