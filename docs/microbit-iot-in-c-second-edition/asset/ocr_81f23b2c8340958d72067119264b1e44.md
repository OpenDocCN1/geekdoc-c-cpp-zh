Today the protocol is much the same, but there is little need for multiple stop bits and communication is often so reliable parity bits are dispensed with. Transmission speeds are also higher - typically 9600 or 115200.

To specify what exact protocol is in use, you will often encounter a short form notation - e.g. 9600 baud, 8 data bits, no parity, one stop bit would be written as 9600 8n1.

The first low is the start bit, then the even dots show the ideal sampling positions for the receiver. The basic decoding algorithm for receiving serial data is to detect the start bit and then sample the line at the center of each time. Notice the final high on the right is the stop bit.

For a serial connection to work, it is essential that the transmitter and the receiver are set to the same speed, data bits and parity. Serial interfaces often fail because they are not working with the same settings. A logic analyzer with a serial decoder is an essential piece of equipment if you are going to anything complicated with serial interlacing.

What is a baud? Baud rate refers to the basic bit time. That is, 300 baud has a start bit that is 1/300s baud. For 9600 baud a 1/9600, or roughly 104µs. At 115200 baud a 1/115200 or roughly 8.6µs. Notice baud rate doesn't equate to speed of sending data because there is an overhead in stop, start, and perhaps parity bits to include in the calculation.

# Hardware

A simple serial interface has a transmit pin Tx and a receive pin Rx. That is, a serial interface has as few as two wires for two-way communications. Typically you connect the Tx pin on one device to the Rx pin on the other and vice versa. The only problem is that some manufacturers label the pins by what they should be connected to, not they are, and you have to connect Rx to Rx and Tx to Tx, which is not really helpful. You generally need to check with a scope, logic probe or meter which is if you in any doubt.
