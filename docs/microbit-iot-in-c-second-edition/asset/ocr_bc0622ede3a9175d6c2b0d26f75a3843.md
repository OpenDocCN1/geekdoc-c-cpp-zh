If you run the program and don't get the data received correctly message, the most likely reason is that you have connected the wrong two pins or not connected them at all.

# The V2 CS Problem

If you connect a logic analyzer to the four pins involved, 13, 14, 15 and 16, you will see the data transfer and there is a difference between V1 and V2.

In the case of V2 the CS line is returned to high before the SPI interaction is complete. The transfer function is supposed to be blocking, but clearly it isn't:

```
CS.setDigitalValue(0);
sppi.transfer(buf, 1, buf, 1);
CS.setDigitalValue(1);
```

![](bbox=[0.25, 0.373, 0.642, 0.673])

You can put a wait after the call to transfer, but it is difficult to get the timing correct. A more sophisticated solution is to use the startTransfer method, which is asynchronous and accepts a callback function which is executed when the SPI transfer is complete. To use this we need a callback function:

```
void doneHandler(void *arg)
{
    CS.setDigitalValue(1);
};
```
