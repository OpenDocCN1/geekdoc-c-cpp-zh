Notice that this is an inverting buffer, but you can usually ignore this and
simple correct by inverting in software, i.e. read a 1 as low and a 0 as a high\state. The role of R1 is to make sure the 5V signal is
absent and R2 limits the current in the FET to about 0.3mA. In most cases,
you should try the simple voltage divider and only move to an active buffer if
it doesn't work.

# How Fast Can We Measure?

The simplest way to find out how quickly we can take a measurement using
micro-bit is to perform a pulse width measurement using a busy wait.
Applying a square wave to P0 we can measure the time that the pulse is high:
#include "MicroBit.h"

```
MicroBit uBit;
int main()
{
  int i;
  uBit.init();
  while (1)
  {
    while (i == 1) uBit.io.P0.getDigitalValue();
    while (i == 0) uBit.io.P0.getDigitalValue();
      for (i = 0; i < 1000; i++))
        if (i == 0) uBit.io.P0.getDigitalValue())
          break;
      uBit.serial.printf("%d\n\r", i);
  }
}
```

This might look a little strange at first. The inner while loops are responsible
getting us to the right point in the waveform. We first loop until the line
go low, then we loop until it goes high again, and finally we measure how
long before it goes low. You might think that we simply have to wait for it
go high and then measure how long it goes low, but this misses the
ibility that the signal might be part way through a high period when we
first measure it.

The second new aspect of the program is that we use printf to get
the information. This is a print function associated with the serial driver. It is
modeled on the standard C printf function, but it only supports a limited
number of data types. You can only use %c,%d, %s, %x and %X.
