
# Summary

- Specifying which of the 32 GPIO lines you want to use can be a problem as the definitions have changed between V1 and V2.
- Some GPIO lines have dedicated functions and should be avoided. Others have alternative uses and again should be avoided.
- The most basic use of any GPIO line is to set it to a digital value, i.e. 0 or 1.
- You can set the drive type of any GPIO line to up, down or none.
- A micro:bit V1 can generate 4µs pulses and a V2 can manage 1µs. In both cases, the need to service interrupts causes disruption to the pulse generation.
- You can sleep to suspend a program for a specified time in milliseconds. You can use wait_us on a V1 or system_timer_wait_us on a V2 to pause for microseconds.
- A busy wait is the best way of generating fast accurate pulses.
- When switching GPIO lines together, you need to be aware that there is a delay between each operation. By default GPIO lines do not change state at the same time.
- GPIO input is harder than output because you don't know when it is going to happen.
- You can service input using event handlers. This is not always the best way of doing the job, however, and simple polling usually provide a faster response time.

## Chapter 4
### Fast Memory-Mapped GPIO

The framework makes working with the GPIO and other devices as easy as it can be, but there are many layers of software to go through before you get to the hardware. Writing directly to the hardware can make things up to ten times faster and give you access to things that the framework doesn't. It is also an educational experience to deal with the raw hardware directly. However, this is an advanced topic and you may want to skip it and return when you have a need to go beyond the framework.

All of the peripherals that are directly connected to the processor are memory-mapped. What this means is that there is a set of addresses that correspond to 'registers' that control the devices and give their status. Using these is just a matter of knowing which addresses to use and the format of the registers.

This is easy to say, but can be difficult to get right, at initially. After you have got it right you forget what all the fuss was. The best way to understand how all of this works is to find out about a particular peripheral, the GPIO.

## GPIO Registers

If you look at the manual for the RF51 processor in the case of the microbit V1 or the RF52 you will find a long section on the registers that are connected to the GPIO lines. There are no major differences between the two processors as the first 32 GPIO lines are concerned. The micro:bit V1 and V2 have an identical bank of 32 GPIO lines usually indicated as P0_n where n goes from 0 to 31. The micro:bit V2 has a second bank of ten GPIO lines, usually indicated as P1_n where n goes from 0 to 9.

Each GPIO line follows the same pattern as far as memory registers are concerned. For each GPIO line there is a single configuration register, i.e. 32 registers, one for each line in the P0 bank.

There is also a 32-bit OUT register that is used to set each output line to high or low with each bit corresponding to the state of one line; and a single 32-bit IN register used to read the state of all 32 GPIO lines with one bit per.

In theory these are the only registers you need to know about to use the GPIO lines, but five more are provided to make things easier.

The OUTSET and OUTCLR registers can be used to set or clear any GPIO lines without changing the state of the others. If you write to either register then the lines that correspond to one bits are set or cleared according which register you write to. For example, suppose you want to set GPIO P0_0 to 1 you can write 0x01 to the OUT register. However, this sets all of the 31 pins to 0. If you write 0x01 to the OUTSET register then you set P0_0 high and leave all of the others in their current state. Similarly, writing 0x01 to OUTCLR sets P0_0 and leaves the other in their current state.

There is a 32-bit DIR register which can be used to set any combination of pins to input or output depending on whether you write a 0 or a 1 to the corresponding bit location.

The DIR and DIRCLR registers set the GPIO line to output or input when you write a 1 to the corresponding bit location and make it easier to set lines to input or output without altering the remaining lines set. Writing 0x01 to DIR sets P0_0 to output but all of the remaining 31 pins to input. Writing 0x01 to DIRSET will set only P0_0 to output and writing it to DIRCLR will set only P0_0 to input.

To summarize, the registers controlling the bank of GPIO lines:

- 32 PIN[n] configuration registers, for each GPIO line
- OUT sets any combination of GPIO lines high or low
- OUTSET sets any combination of GPIO lines high
- OUTCLR sets any combination of GPIO lines low
- IN reads the state of all GPIO lines
- DIR sets the I/O direction of any combination of GPIO lines
- DIRSET sets any combination of GPIO lines to output
- DIRCLR sets any combination of GPIO lines to input

Of course, need to know which bits in the configuration register control what aspect of the GPIO line.

| Bits | DIR |
|---|---|
| 0 | DIR 0 = input, 1 = output |
| 1 | INPUT 0 = disconnect input, 1 = connect |
| 3,2 | PULL 00 = No Pull, 01 = Pull-Down, 11 = Pull-Up |
| 10,9,8 | DRIVE 000 S01, 001 H0S1, 010 S0H1, 011 H0H1, 100 D0S1, 101 D0H1, 110 S0D1, 111 H0D1 |
| 17,16 | SENSE 00 |

## A Fast Pulse

Putting all this together, we now have the problem of how to implement it in C. Next we need to create a mask that picks out the bit corresponding to the pin we want to toggle. You need to keep in mind that the bit at position b corresponds to the internal GPIO line numbering and not the physical pins on the micro:bit. For example, if you want to pulse P0 on the micro:bit you need to pulse P0_3 on V1 or P0_2 on V2. You use the table in the previous chapter P0_3 to look up edge connector pin names and find which GPIO line is driving them.

GPIO P0_3 corresponds to bit 3 and GPIO P0_2 to bit 2 in the register and, in general, we need to construct a bit "mask" that sets the bits corresponding to the GPIO lines we want to control. The easiest way to do this is to left shift a 0x1 that is, if you want to work with GPIO line Pin you would create a mask using:

```c
unsigned int b=0x01<b;
```

So, if we want to work with GPIO P0_3, we need a mask:

```c
unsigned int mask = 1 << 3;
```

Our case for GPIO P0_3 the hex value is:

```c
unsigned int mask = 0x08;
```
