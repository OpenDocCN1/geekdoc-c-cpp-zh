
# Reading the Data

With preliminary checks complete, it is time to read the 40-bit data stream.
The first thing to do is to wait for the low that the device sends before the START bit:

```c
for (i = 1; i < 200; i++) {
    if (P0.getDigitalValue() == 0) break;
}
```

Next we can start to read in the bitstream. When doing this there are two things to keep in mind. The first is that it is only the time line is high that matters and you need to measure this accurately. You don't care so much about how long the line is for. The second is that it is usually better to collect the bits and only process them and extract the data. To this end it is usually a good idea to save the data in a buffer:

```c
int buf[41]; int j;
for(j=0;j<41;j++) {
    for(i=1;i<200;i++) {
        if(P0.getDigitalValue()==1) break;
    }
    for(i=1;i<200;i++) {
        if(P0.getDigitalValue()==0) break;
    }
    buf[j]=i;
}
```

You should be able to see how this works. The outer loop, indexed on j, repeats to read in all 40 data bits and the initial START bit. The first inner loop waits for the line to go high and i gives the time that the line has been low. There is no interest because the device keeps the line low for the same length of time for a zero or a one. The second for loop waits for the line to go low. The count in i is now proportional to the time the line was high and is stored in the buffer.

If you add:

```c
for(j=0;j<=40;j++){
    UBit.serial.printf("%d %d \n",buf[j]);
}
```

to the end of the program you will be able to see the counts and you should quickly be able to work out the value halfway between the long, one pulses and the short, zero pulses.

Examining the data reveals that for the micro:bit V1, short pulses returned 6, long returned 16, both plus or minus 1. Thus the threshold is approximately 11. For the micro:bit V2 the values are around 20 for a short pulse and 60 for a long, giving 40 as a reasonable choice of threshold.

With a threshold set we can classify the pulses into short and long and store zeros and ones in the buffer:

```c
int threshold=11;
//threshold=40;// uncomment for V2
int buf[41];
int j;
for (int i = 0; j < 41; j++) {
  for (i = 1; i < 200; i++) {
    if (P0.getDigitalValue() == 1) break;
  }
  for (i = 1; i < 200; i++) {
    if (P0.getDigitalValue() == 0) break;
  }
  buf[j] = 0;
  if (i > threshold) buf[j] = 1;
}
```

You can afford to include this extra processing in the data collection loop because it happens while the line is low and we aren't interested in measuring this time accurately.

**If you try this you will discover that it doesn't work.** Not only does it drop bits, it seems to drop the same bits each time you run the program. This is a particular problem for the microbit V2, which never manages to complete a reading correctly. This suggests that it is a systematic effect and the result of random noise.

The cause of the problem is, in fact, the system timer interrupt. The entire transaction takes about one interrupt interval and, as the timer is started when the program starts, the interrupt occurs at the same point time you run the program - hence the regularity. The solution is to turn off interrupts for the duration of the regularity. Turning off interrupts for any length time is not a good idea, but for the short time that the reading is being it causes no serious problems.

All you have to do surround the bit reading loop with `__disable_irq()` and `__enable_irq();`;

```c
int threshold=11;
//threshold=40// uncomment for V2
int buf[41];
int j;
disable_irq();
for (j = 0; j < 41; j++) {
  for (i = 1; i < 200; i++) {
    if (P0.getDigitalValue() == 1) break;
  }
  for (i = 1; i < 200; i++) {
    if (P0.getDigitalValue() == 0) break;
  }
  buf[j] = 0;
  if (i > threshold) buf[j] = 1;
}
__enable_irq();
```

With this change it all works.

# Extracting the Data

Now we have the data in the buffer as zeros and ones. All that remains is to decode it into temperature and humidity readings. But first we will convert bits into five bytes of data. The simplest way of doing this is to write a function that will pack eight bits into an uint32_t:

```c
uint32_t getByte(int b, int buf[])
{
  int i;
  uint32_t result = 0;
  b = (b - 1) * 8 + 1;
  for (i = b; i <= b + 7; i++) {
    result = result << 1;
    result = result | buf[i];
  }
  return result;
}
```

The b can be the byte that you want to extract from the array. For example, if b = 2 then the loop runs from i = 9 to i = 16, i.e. the second byte stored in the array. Notice that we skip the first bit because this just signals the start of the data. The bit manipulation in the for loop is a fairly standard shift left and OR the least significant bit into the result.

Using function to get the five bytes is trivial:

```c
uint32_t byte1 = getByte(1, buf);
uint32_t byte2 = getByte(2, buf);
uint32_t byte3 = getByte(3, buf);
uint32_t byte4 = getByte(4, buf);
uint32_t byte5 = getByte(5, buf);
```

The first two bytes are the humidity measurement, the second two the temperature and the final byte is the checksum. The checksum is just the sum of the first bytes reduced to 8 bits and we can test it using:

```c
UBit.serial.printf("Checksum %%%\n\r", byte5, (byte1 + byte2 + byte3 + byte4) & 0xFF);
```

If the two values are different, then there is a transmission error. In this case the simplest thing to do is get another reading from the device. However, you shouldn't read the device more than once every 2 seconds.

The humidity and temperature are also easy to reconstruct as they are transmitted high byte first and then the actual value. The only problem is the microbit byte doesn't have floating point support and so it is easier to keep the values as humidity*10 and temperature*10. The humidity data is easy:

```c
int16_t humidity = (byte1 << 8) | byte2;
```

The temperature is slightly more difficult because the topmost bit is used to indicate the sign. This is two's complement format.

```c
int16_t temperature = (byte3 << 8) | byte4;
if (temperature & 0x8000) temperature |= 0x7FFF;
```
