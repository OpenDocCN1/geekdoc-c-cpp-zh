At this point you can build the project. If you plan to stay with yotta and use a simple editor to create your/C+ files then you will build your application each time. If you plan to move to an IDE such as VS Code then the IDE will make use of the Ninja files created to build your program in the future.

So we need to use yotta to build the project. The problem is that there are no files in the source or test folders and yotta will simply ignore any empty folders in the build. Give the system something to add a .cpp file to the source folder.

Use your editor to add something trivial like:

```
#include "MicroBit.h"
MicroBit uBit; int main() {
uBit.init();
uBitBitdisplay.scroll("NEW PROGRAM");
release_fiber();
}
```

and store the result as main.cpp or any name you care to use.

Now we can build and test the program using:
yotta build

If you watch what happens you will see the program build and report that the build files have been written to build/bbc-microbit-classic-gcc directory in the project. You will also see lots of warnings about deprecated code and style problems – you can ignore these. The important part is that you will find the hex file in the directory:

pulse\build\bbc-microbit-classic-gcc\Source

The file that you need to download to the microbit: pulse-combined.hex and not the pulse.hex file. If you can't find a .hex file then check the messages produced by yotta and you will probably find that srec_cat.exe is mentioned as missing. See the instructions given earlier about obtaining and installing record.
