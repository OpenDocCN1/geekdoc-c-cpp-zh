Notice that USBTX and USBRX give the GPIO pins to use to connect to the USB port in the case of the V1, and MICROBIT_PIN_UART_TX, MICROBIT_PIN_UART_RX in the case of the V2.

For the rest of this chapter we will use the uBit serial property because this is by far the most common way of working. The constructor for the MicroBitSerial object takes the pins to be used, Tx and Rx, as the parameters tx and rx:

```
MicroBitSerial(PinName tx, PinName rx);
```

The default MicroBitSerial object created by the uBit object is set up by the constructor with USB pins. There is also a version of the constructor that lets you set the size:

```
MicroBitSerial( PinName tx, PinName rx, uint8_t rxBufferSize)
```

and also one to set the size of the Tx and Rx buffers separately:

```
MicroBitSerial( PinName tx, rx,
uint8_t rxBufferSize,
uint8_t txBufferSize)
```

You can mostly ignore the buffer size, for the moment at least, and simply use the default.

Once you have a MicroBitSerial object you can set its baud rate using:
aud( int baudrate)

for V1:
setBaudrate( int baudrate)

for V2:
This is currently the only setting you can change using the high-level micro:bit framework. Currently there is no easy way of changing the configuration of the V2 serial port, but you can use a method inherited from deep down in the mbed framework to modify the V1 serial configuration:
void SerialBase::format(int bits, Parity parity, int stop_bits)

where Parity is one:

```
enum Parity {
None = 0,
Odd,
Even,
Forced1,
Forced0
};
```

For example, to set two stop bits you might use (V1 only):

```
uBit.init();
uBit.serial.format(8,mbed::RawSerial::None,2);
uBit.serial.baud(115200);
uBit.serial.send("A\r\n");
```

The only problem with format is that there is no guarantee that it will not interact with the rest of the framework in some unexpected way, although it doesn't seem to.

The final configuration function is very important if you want to communicate with anything other than the USB connection by MicroBit object:

```
int redirect(PinName tx, PinName rx)
```

This changes the Tx and Rx pins to whatever you specify.

The rest of the configuration seems to transfer to the new pins as well. So, for example, to send something on physical Pin 1 on the edge connector and receive on Pin 2, you would use on the V1:

```cpp
#include "MicroBit.h"
MicroBit uBit;

int main() {
{
uBit.init();
uBit.serial.format(8,mbed::RawSerial::None,2);
uBit.serial.baud(115200);
uBit.serial.redirect(MICROBIT_PIN_P1, MICROBIT_PIN_P2);
uBit.serial.send("A\r\n");
}
```

and on the V2:

```cpp
#include "MicroBit.h"
MicroBit uBit;

int main() {
{
uBit.init();
uBit.serial.setBaudrate(115200);
uBit.serial.redirect(uBit.io.P1 , uBit.io.P2);
uBit.serial.send("A\r\n");
}
```

# Sending Data

We have already used the send function without really discussing it, but sending data isn't the difficult part of using serial. There are a set of send functions which differ in what they allow you to send:

- int sendChar(char c)
- int send(ManagedString s)
- int send(ManagedString s, MicroBitSerialMode)
- int send(uint8_t *buffer, int bufferLen)
- int send(uint8_t *buffer, int bufferLen, MicroBitSerialMode mode)

You can see that you can send a single character, a ManagedString or a buffer of bytes and this is usually more than enough to work with. In addition, there is also put which lets you send a character, but isn't really needed because you have sendChar. You also don't need puts, which sends an unmanaged string, because send will convert a standard C string into a managed string automatically.

The only inherited method that seems useful is:
send_break()

which sends a low for longer than a character time. Only available on the V1, this caters for devices that need a break signal to reset or do something special and which cannot be sent as a character code.

Finally there is a printf function with the serial driver. It is modeled on the standard C printf function but only supports a limited number of data types. You can use %c, %d, %s, %x and %X.

The mode parameter is more important when you are receiving data, but still has an effect when you send data.

There are three modes:

- ASY - the characters are sent to the buffer and the function returns once.
- SYNC_SPINWAIT - the characters are sent to the buffer and your program (i.e. the spins) waits.
- SYNC_SLEEP - the characters are sent to the buffer and your program sleeps.
