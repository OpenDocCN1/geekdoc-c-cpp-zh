
The biggest problem in working with the microbit in serial mode is the limited amount of memory. If your program seems to have a tendency to simply "go quiet" on you then suspect that you are creating a ManagedString that is just too large. This is not a big problem when it comes to a server, but it is for a client trying to process a lot of data.

There may also be better ways to handle the serial interaction between the two devices, but the method presented does seem to work reasonably well. If things get in a mess then the retry limits usually reset the entire transaction if you wait long enough.

There is still going to be the occasional unexplained crash and in this case the best solution is to use the soft reset command. It is also worth mentioning that the server program as presented does not actually handle multiple connections. It has to finish dealing with one connection before it can deal with the next.

# Summary

- Adding WiFi to the microbit is fairly easy using the low-cost ESP866-01, which connects via the serial port and makes use of AT commands to control the device as if it was a WiFi modem.
- In addition to an ESP866, you also need a power supply capable of running it.
- You can use AT commands to set the device into client mode and connect to a WiFi network.
- While it is possible to use ad-hoc protocols, there are advantages in using TCP, HTTP and HTML so other devices can work with the microbit.
- The microbit can use client mode to download data from web servers.
- It can also emulate a server to deliver data to any web browser or HTML-using client.

## The LED Display

The microbit's LED display may only be 5x5 but it is very versatile. If you want to make use of it directly then you are going to master some lower-level functions.

Mostly the functions provided by the framework are all you need to work with the LED display. They are also fairly-explanatory and easy to use so there is no point in going over them. You can look them up in the documentation and use them in programs without too much trouble. In this chapter, we cover the structure of the LED display and some interesting ways of using it in the hope that you might find creative ways to use the display.

## Driving the LEDs

The basic structure of the LED array is fairly simple and obvious if you have ever done anything similar. The LEDs are arranged in a grid of three rows and five columns. Each row has a GPIO line to drive it and a GPIO line determines whether the LED should be on or off and acts when activated.

Unfortunately, the layout for the LED displays is different for the two versions of the microbit. The arrangement of LEDs and GPIO lines for the V1 is:

# microbit V1 LEDs

The LEDs in the microbit V1 do not have a neat row, column numbering. Instead they are arranged in an order that makes the PCB layout easier:

| 1.1 | 2.4 | 1.2 | 2.5 | 1.3 |
| 3.4 | 3.5 | 3.6 | 3.7 | 3.8 |
| 2.2 | 1.9 | 2.3 | 3.9 | 2.1 |
| 1.8 | 1.7 | 1.6 | 1.5 | 1.4 |
| 3.3 | 2.7 | 3.1 | 2.6 | 3.2 |

To illuminate the LED at position row,column, all we have to do is set the row high and the column low - this picks out just one LED to be on. For example, to set the center LED 2,3 you would need to set GPIO line p0_14 high and line p0_6 low. The problem is that the framework provides objects for GPIO lines that are brought out to the edge connector and none of the row lines and some of the column lines are.

The solution is to make use of the mbed functions with which the framework is built. The disadvantage of this is that you don't get any of the event handling facilities. There are mbed functions for most of the hardware facilities that we have encountered and you can use them if you want to. They are slightly faster than the framework functions because in general the framework functions call the mbed functions to get the work done.
