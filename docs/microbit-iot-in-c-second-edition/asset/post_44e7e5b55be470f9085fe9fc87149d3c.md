
As p varies from 0 to 10, the position of the brightness moves from the first to the second LED.

We also need something to record how many times the button has been clicked. This can be done using an event handler that counts clicks using a global variable. There is no doubt that this would be better implemented as an object using C++ with methods such as getValue and reset, but in C we use:

```cpp
void setUpButton() {
    uBit.buttonB.eventConfiguration(MICROBIT_BUTTON_ALL_EVENTS);
    uBit.messageBus.listen(MICROBIT_ID_BUTTON_B, MICROBIT_BUTTON_EVT_CLICK, buttonClickCount);
}
```

Now buttonClickCount is called each time the user clicks buttonB:

```cpp
void buttonClickCount(MicroBitEvent e) {
    clickCount++;
}
```

## Summary

- The micro:bit has a 5x5 LED display, In the V2 this has a conventional five-row, five-column design but in the V1 it is arranged as three rows by nine columns with two missing LEDs.
- This means that the V1 LEDs are not positioned according to their GPIO line column and row numbers.
- You can switch an individual LED on by setting the column line high and the row line low.
- The impression that multiple LEDs are on is created by switching them on and off very quickly.
- You can work with MicroBitImage arrays to display small 5x5 images in greyscale with 0 to 255 shades.
- You can also use this technique to apparently increase the resolution of the display.
- Commando Jump is an example of a simple game that can be programmed even on a 5x5 LED display.
