## micro-bit V1.3

The accelerometer is a MMA8653 and you can find out how it works from its datasheet. It has I2C address 0xD. The magnetometer is a NXP MAG3110 and its datasheet reveals that it is I2C address 0xE0.

Of the two devices, the magnetometer is the simpler and so it provides a better introductory example. If you examine its datasheet you will find a table of registers:

| Name | Type | Address | Default | Comment |
|---|---|---|---|---|
| DR_STATUS | R | 0x00 | 0000 000 | Data status per axis |
| OUT X_MSB | R | 0x01 | (0x03) | Bits [15:8] of X measurement |
| OUT X_LSB | R | 0x02 | | Bits [7:0] of X measurement |
| OUT Y_MSB | R | 0x03 | (0x05) | Bits [15:8] of Y measurement |
| OUT Y_LSB | R | 0x04 | | Bits [7:0] of Y measurement |
| OUT Z_MSB | R | 0x05 | (0x07) | Bits [15:8] of Z measurement |
| OUT Z_LSB | R | 0x06 | | Bits [7:0] of Z measurement |
| WHO AM_I | R | 0x07 | 0xC4 | Device ID Number |
| SYSMOD | R | 0x08 | data | Current System |
| OFF X_MSB | R/W | 0x09 | 0000 000 | Bits [14:7] of user offset |
| OFF X_LSB | R/W | 0x0A | 0000 000 | Bits [6:0] of user X offset |
| OFF Y_MSB | R/W | 0x0B | 0000 000 | Bits [14:7] of user Y offset |
| OFF Y_LSB | R/W | 0x0C | 0000 000 | Bits [6:0] of user Y offset |
| OFF Z_MSB | R/W | 0x0D | 0000 000 | Bits [14:7] of user Z offset |
| OFF Z_LSB | R/W | 0x0E | 0000 000 | Bits [6:0] of user Z offset |
| DIE_TEMP | R | 0x0F | data | Temperature, signed 8 bits in C |
| CTRL_REG1 | R/W | 0x10 | 0000 0000 | Operation modes |
| CTRL_REG2 | R/W | 0x11 | 0000 0000 | Operation modes |

The comments give you a general idea of what each register is for. For example, the AM register has address 0x07, is read only and has default value 0x0C. This is a good register for trying out the I2C commands because we know what the result should be.

The address of the device is 0xE and so the address shifted by one is 0x1C. The register's address is 0x7. The datasheet also says that the device needs a repeated START bit for a register read, i.e. a STOP bit only at the end of the transaction:

```cpp
#include "MicroBit.h"
MicroBit uBit;
```

```cpp
int main() {
  uBit.init();
  char buf[]={0x07};
  uBit.i2c.write(0x1C,buf,1,true);
  uBit.i2c.read(0x1C,buf,1);
  printf("Id X%%X\r\n", (int)buf[0]);
  release_fiber();
  return 0;
}
```

If you connect a logic analyzer to Pin 19 and Pin 20 you can see the transaction in action. You will also see some other transactions as the framework initializes the built-in devices: img/23976341c9281123b186ea9db101.png

You can see that there is no STOP bit in the middle of the transaction, only at the end. While this is the way that the transaction should be done, you will discover that if you take out the "true" in the write you will find the same data provided by slave and the noticeable difference is slightly longer pauses between write and read.

Now that we can read the ID of the device it is interesting to read some real data. First however, we can use the framework's compass functions to get data from the device so we know what results to expect. The first part of the program gets the magnetic field in the x, y and z directions and prints them to serial:

```cpp
uBit.init();
uBit.compass.update();
int x = uBit.compass.getX();
printf("%d \r\n", x);
int y = uBit.compass.getY();
printf("%d \r\n", y);
int z = uBit.compass.getZ();
printf("%d \r\n", z);
```

We can repeat the readings, this time using I2C functions to talk directly to the device. If you consult the datasheet you will discover that the x, y and z data is stored in single-byte registers starting at 0x01. You can read values at a time, but the device also supports multibyte mode that will transfer all bytes in one operation. All you have to do is read six bytes from register 0x01 and you get the x, y and z data:

```cpp
char buf[] = {0x01};
char buf2[7];
uBit.i2c.write(0x1C, buf, 1, true);
uBit.i2c.read(0x1C, buf2, 6);
int i;
for (i = 0; i < 6; i++) {
    printf("%d %X \r\n", i, (int) buf2[i]);
}
```

The program reads the raw data to the serial port. We convert the raw bytes to 16-bit signed values by packing them into suitable integers:

```cpp
int16_t X = buf2[0] << 8 | buf2[1];
printf("%d \r\n", X);
int16_t Y = buf2[2] << 8 | buf2[3];
printf("%d \r\n", Y);
int16_t Z = buf2[4] << 8 | buf2[5];
printf("%d \r\n", Z);
```

If you try this program you will discover that the framework gives slightly different results because it uses a different set of coordinates - all values are multiplied by 100 and the x and y data are multiplied by -1.

## micro:bit V1.5 and V2

There are two possible accelerometers in use in the micro:bit v.5 and V2. To find out which is actually in use you have to read and test the WHO_AM register. Unfortunately this is in a different location in each case. Looking the values up in the datasheets allows us to write a program that tests for each device:

```cpp
#include "MicroBit.h"

#define LSM303 ADDR 0x32
#define LSM303 WHO 0x0F
#define LSM303_VAL 0x33

#define FX058700 ADDR 0x3C
#define FX058700 WHO 0x0D
#define FX058700_VAL 0xC7
MicroBit uBit;

int main() {
  uBit.init();
  uint8_t data[1];
  int status = 0;

  status = uBit._i2c.readRegister(LSM303_ADDR, LSM303_WHO, data, 1);
  if (data[0] == LSM303_VAL)
    uBit.serial.printf("LSM303 \n\r");

  status=uBit._i2c.readRegister(FX058700_ADDR,FX058700_WHO,data,1);
  if (data[0] == FX058700_VAL)
    uBit.serial.printf("FX05700 \n\r");
  return 0;
}
```

This works for the micro:bit V2 and uses the _i2c object to use the dedicated bus. To make it work on the V1.5 you simply change _i2c to i2c.
A final example let's read the data from the LSM303 magnetometer. This consists of magnetic field strengths in the x, y and z directions. Each value is a 16-bit value and this is represented as pairs of registers. The datasheet gives these register addresses as 0x68 to 0x6D.

All you have to do is read a pair of bytes from each pair of registers and then put the results together to make 16-bit values:

```cpp
#include "MicroBit.h"

#define LSM303 ADDR 0x32
#define LSM303 WHO 0x0F
#define LSM303_VAL 0x33

#define FX058700 ADDR 0x3C
#define FX058700 WHO 0x0D
#define FX058700_VAL 0xC7
MicroBit uBit;

int main() {
  uBit.init();
  uint8_t data[1];
  int status = 0;

  status = uBit._i2c.readRegister(LSM303_ADDR, LSM303_WHO, data, 1);
  if (data[0] == LSM303_VAL)
    uBit.serial.printf("LSM303 \n\r");

  status=uBit._i2c.readRegister(FX058700_ADDR,FX058700_WHO,data,1);
  if (data[0] == FX058700_VAL)
    uBit.serial.printf("FX05700 \n\r");
  return 0;
}
```
