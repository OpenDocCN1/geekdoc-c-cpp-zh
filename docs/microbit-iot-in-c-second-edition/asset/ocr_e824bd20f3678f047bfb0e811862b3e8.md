# Digital GPIO

With all of these possibilities, using the GPIO lines can seem quite complicated. For simplicity, and because it is the most common way they are used, we will concentrate on their use as simple digital I/O lines, and for the moment, ignore analog, PWM and touch inputs and their use using I2C and SPI buses, all of which are covered in later chapters.

The basic interface to the GPIO lines is the MicroBitPin object. You can create and use MicroBitPin objects as needed or you can use the MicroBitPin objects created on the uBit object. If you create your own MicroBitPin objects create them as global objects and do not create a uBit object.

For example, to access P0 you can use:

```
#include "MicroBit.h"
MicroBit uBit;
int main() {
  uBit.init();
  uBit.io.P0.setDigitalValue(1);
}
```

or

Don't worry about the MicroBitPin constructor or the setDigitalValue function. All that matters at the moment is that you see the two ways of getting a GPIO line.

If you are not troubled by resource shortages the uBit object approach because it frees you from having to instantiate a MicroBitPin object for each pin. If you are having resource problems instantiating only the objects you are going to use is a better strategy.

Notice that when you use the uBit object the GPIO lines are just referred to as P0, P1 and so on. Notice that these aren't just numbers but complete objects that provide access to the GPIO lines. Compare the difference between uBit.io.P0 and MICROBIT_PIN_ The first is an object with methods and properties and the second is just a number that indicates which GPIO line to use. Low-level functions that work with GPIO lines tend to need the number of the GPIO, but higher-level functions need a MicroBitPin object.
