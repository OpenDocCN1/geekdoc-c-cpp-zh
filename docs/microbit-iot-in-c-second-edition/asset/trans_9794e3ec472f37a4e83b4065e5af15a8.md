
一旦配置好无线电，发送接收数据的低级方法是使用 `send` 和 `recv` 函数，它们通过帧缓冲区进行工作：

```
FrameBuffer recv()
int send( FrameBuffer * buffer)
```

```c
FrameBuffer 结构体如下：
uint8_t length; // 剩余字节的长度
uint8_t version; // 协议版本代码
uint8_t group; // 组 ID
uint8_t protocol; // 内部协议 ID
uint8_t payload[MICROBIT_RADIO_MAX_PACKET_SIZE]; // 用户数据
FrameBuffer *next; // 指向下一个缓冲区的指针
int rssi; // 此帧的接收信号强度；
```

唯一难以处理的字段是 `protocol`，它应该设置为以下之一：

```
MICROBIT_PROTOCOL DATAGRAM
MICROBIT_RADIO_PROTOCOL_EVENTBUS
```

或者你新发明的东西，并且在写作时，`version` 设置为 1。

似乎没有什么理由直接使用 `FrameBuffer`，因为它提供了一组适用于更简单数据类型的函数。该方法可以发送更简单类型的数据：

```
int send(ManagedString data)
send(uint8_t * buffer, int len)
```

在大多数情况下，发送 `ManagedString` 是你所需要的，但整数数组也是很有用的。注意在每种情况下都被限制 32 字节。还有一个适用于托管类型的低级函数：

```
int send(FrameBuffer data)
```

`FrameBuffer` 记录了数据、长度和 RSSI（接收信号强度）。它是客户端设备接收到的功率水平的估计值：

```
FrameBuffer(uint8_t *data, int length, int rssi = 0);
```

对于接收数据，有两个版本的 `recv`：

```
int recv(uint8_t * buf, int len)
```

以及

```
FrameBuffer recv()
```

`FrameBuffer` 版本的函数比想象的要有用，因为 `ManagedString` 对象拥有一个可以转换 `FrameBuffer` 的构造函数，允许你编写这样的代码：

```
ManagedString s = uBit.radio.recv();
```

此时 `FrameBuffer` 的数据负载将转换为 `ManagedString`。

## 轮询或事件

如果你想向其他 microbit 发送一些数据，任务很简单。你所只需要创建缓冲区并使用 `send` 方法。对于接收数据，我们面临通常的问题：输入比输出困难。在接收无线消息的情况下，解决方案是使用轮询或事件。一旦启用无线电，它会持续监控传入的消息并存储它接收到的消息。

如果你使用 `radio.recv` 方法，它将返回第一个可用消息，如果没有消息准备好处理，则返回 `NULL`。如果你使用 `recv` 方法，将返回一个消息或空缓冲区。在任何情况下，你都可以使用 `recv` 方法编写轮询循环。例如：

```
while (1) {
  ManagedString s = uBit.radio.recv();
  if (s.length() != 0) {
    处理数据
  }
}
```

轮询循环的替代方案是设置事件处理器。事件仅针对对象实现，要启用它们，你需要使用：

uBit.messageBus.listen(MICROBIT_ID_RADIO, MICROBIT_RADIO_EVT_DATAGRAM, onData);

其中 `onData` 参数是当有数据需要处理时调用的函数。

例如：

```
void onData(MicroBitEvent e)
{
    ManagedString s = uBit.radio.recv();
    处理数据
}

int main()
{
    uBit.init();

    uBit.messageBus.listen(MICROBIT_ID_RADIO, MICROBIT_RADIO_EVT_DATAGRAM, onData);
    uBit.radio.enable();
    执行其他任务
}
```

这很简单，但你必须依赖在处理数据时入站消息队列的溢出。在许多情况下，你想发送给其他 microbit 的消息只是发生了一些事情。例如，如果按了按钮，你可能会发送 1，当释放时发送 2。这种工作既灵活又高效，但实际上你所做的是将一个事件传输到另一个 microbit。`MicroRadioEvent` 框架设计用于关联本地 microbit 上发生的事件，并通过无线电将它们传递给另一个 microbit。`radio` 对象有一个事件对象 `MicroRadioEvent`。该对象设计用于关联事件，使得接收到的事件在远程 microbit 上处理时，就像它们发生在本地发生一样，即它们被视为与标准事件相同的事件。

`MicroRadioEvent` 的关键方法是 `listen`：

```
int listen(uint16_t id, uint16_t value)
```

它将由 `id` 和 `value` 指定的事件关联到当前打开的无线通道。`id` 是引起中断的组件 ID，`value` 是具体的事件。你可以为这些或现有的事件类型使用自定义值。例如：

```
int main()
{
    uBit.init();
    uBit.radio.enable();

    uBit.radio.event.listen(MICROBIT_ID_BUTTON_A, MICROBIT_BUTTON_EVT_CLICK);

    while(1) {
        uBit.sleep(1000);
    }
}
```

设置无线电通过无线电传递任何按钮 A 的点击。要响应它们，接收端必须有类似的内容：

```
void onData(MicroBitEvent e)
{
  uBit.display.print("Click");
  return;
}

int main() {
  uBit.init();
  uBit.messageBus.listen(MICROBIT_ID_RADIO, MICROBIT_RADIO_EVT_DATAGRAM, onData);

  uBit.radio.enable();
  while(1) {
    uBit.sleep(1000);
  }
```

## 产生声音

microbit V1 没有标准音频功能，也没有内置扬声器。如果你想产生声音，可以使用引脚的 PWM 能力来创建正确频率的方波。你可以轻松地编写一个函数来实现：

```c
// 产生音调
void analogPitch(int frequency, int vol, int ms) {
  uBit.io.P0.setAnalogValue(vol);
  uBit.io.P0.setAnalogPeriodUs(100000/frequency);
  uBit.sleep(ms);
  uBit.io.P0.setAnalogValue(0);
}
```

频率单位为赫兹，音量 0 到 512，持续时间为毫秒。这适用于 P0，但你可以使用任何支持 PWM 的引脚。为了听到结果，你需要将扬声器连接到相应的引脚。
microbit V2 有了一套全新的音频系统，目前尚无文档且显然会发生变化——这里提供的说明并不完整。但对于处理常见任务已经足够。
