# Sending Data

We have already used the send function without really discussing it, but sending data isn't the difficult part of using serial. There are set of send functions which differ in what they allow you to send:

+   - int sendChar(char c)
- int send(ManagedString s)
- int send(ManagedString s,MicroBitSerialMode)
- int send(uint8_t *buffer, int bufferLen)
- int send(uint8_t *buffer, bufferLen,MicroBitSerialMode mode)

You can see that you can send a single character, a ManagedString or a buffer of bytes and this is usually more than enough to work with. In addition, there is also put which let you send a character, but isnt really needed because you have sendChar. You also not need puts, which sends an unmanaged string, because send will convert a standard C string into a managed string automatically.

The only inherited method that seems useful is:
send_break()

which sends a low for longer than a character time. Only available on the V1, this caters for devices that need a break signal to reset or do something special and which cannot be sent as a character code.

Finally there is a printf function with the serial driver. It is modeled on the standard C printf function but only supports a limited number of data types. You can use %c,%d, %s, %x and %X.

The mode parameter is more important when you are receiving data, but still has an effect when you send data.

There are three modes:

+   - ASY - the characters are sent to the buffer and the function returns once.
- SYNC_SPINWAIT - the characters are sent to the buffer and your program (i.e. the calling fiber) will wait until they are all sent.
- SYNC_SLEEP - the characters are sent to the buffer and your program sleeps another fiber to run.

The default is SYNC_SLEEP, but notice that if you have a single fiber program there't a lot of difference between the two versions of SYNC. Notice that ASYNC allows your fiber to get on with things while the characters are being sent and this is often the most useful option.
