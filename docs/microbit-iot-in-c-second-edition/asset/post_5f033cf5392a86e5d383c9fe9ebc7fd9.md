
To see the analog wave form, we need to put the digital output into a low-pass filter. A simple resistor and capacitor work reasonably well - the cut-off frequency for the filter is shown is 200Hz.

However, if you increase the cut-off then even more irregularities will show in the ramp. # Music

So how can the micro:bit generate musical notes? The simplest solution is to try to generate anything other than a square wave. That is, use the pulse period rather than duty cycle.

As the frequency of middle C is 261.6Hz, the period needed is roughly 3823µs and to generate middle C you could use:

```
uBit.io.P0..setAnalogValue(511);
uBit.io.P0..setAnalogPeriodUs(3823);
```

The resulting output is a square wave, which isn't particularly nice to listen to. You can improve it by feeding it through a simple low-pass filter like the one used for waveform synthesis. The correct values of R and C are a matter of taste, but 1µF to 0.1 and 1k work reasonably well.

The period t needed for any frequency f is:
t = 1/f

and you can look up the frequencies for other notes and use a table to generate them.

The micro:bit V2 is fast enough to do a much better job of creating complex sounds – so much so that it has a complete synthesizer in software. For more information, see Chapter 15.

# Controlling an LED

You can use PWM supply to control the brightness of an LED for example, or the rotation rate of a DC motor. The only differences in applications such as these are to do with the voltage and current you need and the way the duty cycle relates to whatever the physical effect is. In other words if you want to change some device by 50% how much do you need to change the duty cycle? For example how we "dim an LED?" By changing the duty cycle of the PWM pulse train you can set the amount of power delivered to an LED, or any other device, and hence change its brightness.

For example, an LED we might use a 3.3V supply and a current of a few tens of milliamperes. In the case of an LED connection between duty cycle and brightness is a complicated matter, but the simplest approach uses the fact that the perceived brightness is roughly proportional to the cube of the input power. The exact relationship is more complicated, but this is good enough for most applications.

As the power supplied to the LED is proportional to the duty cycle, we have: b = kd

b is the perceived brightness and d is the duty cycle. Notice that as the LED powered by PWM signal is either on or full off, there is no effect of the change in light output with current - the LED always runs at the same current. What all of this means if you want an LED to fade in a linear fashion you need to change the duty cycle in a non-linear fashion. Intuitively it means that changes when duty cycle is small produce bigger changes in brightness when duty cycle is large. For a simple example we need to connect a standard LED to the PWM line. Given that all of the micro:bit's GPIO lines work at 3.3V and ideally only supply 0.5mA, we need a transistor to drive the LED which typically draws 20mA. You could use a FET of some sort, but for this application an old-fashioned Bipolar Junction Transistor works very well and is cheap and available in through-hole mount i.e. comes with wires. Almost any general purpose npn transistor will work, 2N222 is very common:

![](img/23976341c9281123e7b181beea6e9dbd_80_0.png)

R1 restricts the current to 4mA, which is below the target 5mA, and assuming that the transistor has a minimum gain (listed as hfe or beta) of 50 provides 24mA to power it. R2 limits the current to 20mA. Notice that these values are for a red LED with forward voltage drop of 1.8V and LEDs of different color have different voltage drops and currents.

![](img/23976341c9281123e7b181beea6e9dbd_81_0.png)

As always, the positive terminal on the LED is the long pin. Assuming that you have this circuit constructed, then a simple PWM program to modify its brightness from low to high and back to low in a loop:

```c
#include "MicroBit.h"
//define wait_us system_timer_wait_us // uncomment for V2
MicroBit uBit;

int main() {
  uBit.init();
  uBit.io.P0.setAnalogValue(511);
  uBit.io.P0.setAnalogPeriodUs(1000);
  int w=1;
  int inc=1;
  for (;;) {
    uBit.io.P0.setAnalogValue(w);
    w+=inc;
    if(w>1024 || w<=0)inc=-inc;
    wait_us(5000);
  }
  release fiber();
  return 0;
}
```

The basic idea is to set up a pulse train with a period of 1ms. In the loop the duty cycle is set to 0% to 100% and back down to 0%. Notice that the way the loop counts up and down is use inc which is either 1 or -1 and using the old trick of flipping between 1 and -1 and back again by multiplying by -1.

If you watch the flashing you will see that it changes brightness very quickly, and then seems to spend a long time "stuck" at almost full brightness, and then suddenly starts to dim rapidly. This is a consequence of the way the human eye perceives light output as a function of input power.

# Changing the LED brightness

What about a linear change in brightness?

To achieve this reasonably isn't difficult all we need to do is increase the power or equivalently the duty cycle in steps that are cubic. If we use just 0 to 10 we get a pulse width of 0 to 1000, which is ideal for 1ms pulse used in the previous example, i.e. 0 to to 100% duty cycle.

If you need the ultimate speed you could pre-compute the powers, but for simplicity we will use integer multiplication:

```c
#include "MicroBit.h"
//define wait_us system_timer_wait_us // uncomment for V2
MicroBit uBit;

int main() {
  uBit.init();
  uBit.io.P0.setAnalogValue(511);
  uBit.io.P0.setAnalogPeriodUs(1000);

  int w=0;
  int inc=1;
  for (;;) {
    uBit.io.P0.setAnalogValue(w*w*w);
    w=w+inc;
    if(w>10 || w<=0) inc=-inc;
    wait_us(50000);
  }
  release_fiber();
  return 0;
}
```

As this produces 10 cubic steps, a wait_us of 50000 makes each step last 5ms and it takes 50ms to go from low to high.

If you try the program you should find that you see the LED increase steadily towards a maximum and then decrease steadily to a minimum.

If you replace the delay with a value of 100,000 you will get a 1-second cycle which, using only ten steps, to start like a little "flashy".

You can increase the number of steps by simply dividing by a suitable factor. If you cube 1 to 20 you get 8000 and dividing by 8 gives 0 to 1000. Dividing by 8 is just a matter of three right shifts and so not very accurate does allow fast computation with integer arithmetic:

```c
int w=0;
int inc=1;
for(;;) {
 uBit.io.P0.setAnalogValue((w*w*w)>>3);
 w+=inc;
 if(w>20 || w<=0) inc=-inc;
 wait_us(50000);
}
```

Notice that there are now twice as many steps we need each one to last half the time, i.e. 50µs.

In most cases, exactly how linear the response of the LED is irrelevant - a rough approximation looks as smooth as the human eye. The only exception is when you are trying to drive LEDs to create a gray level or color display when color calibration is another level of accuracy.

# Controlling a Servo

Hobby servos, the sort used in radio PWM models, are very cheap and easy to use and the micro-bit has enough PWM lines to control three of them without much in the way of extras and losing any other facilities. You can of course control more if you are prepared to sacrifice using the LED display.

A basic servo has just three connections - usually ground, a power line and a signal line. The colors used vary, but the power is usually red and the ground line is usually black or brown. The signal line is white, yellow or orange.
