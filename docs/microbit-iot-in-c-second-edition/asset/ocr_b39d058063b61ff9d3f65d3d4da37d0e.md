# Processing the Data

Our next task isn't really directly related to the problem of using the I2C bus, but it is a very typical next step. The device returns the data in three bytes, but the way that this data relates to the temperature isn't simple.

If you read the datasheet you will discover that the temperature data is the 14-bit value currently by putting together the most and least significant byte and zeroing the bottom two bits. The bottom two bits are used as status bits - bit zero currently isn't used and one is a 0 if the data is a temperature measurement and a 1 if it is a humidity measurement.

To put the two bytes we use:

```
unsigned int data6=((unsigned int) msb << 8) | 
(unsigned int) (lsb & 0FC);
```

This zeros the bottom two bits, shifts the msb up eight bits and ORs the two together. The result is a 16-bit temperature value with the bottom two bits zeroes.

Now we have raw temperature value, but we have still have to convert it to standard units. The datasheet gives the formula for temperature in degrees Celsius (°C) as:

-46.85 + 175.72 * data16 / 2^16

The only problem in implementing this is working out 2^16. You can work out 2^s with the expression 1<<x, i.e. shift 1 x to the left.

This gives:

```
float temp = (float)(-46.8 + (175.72 *data16/(float)(1<<16)));
```

As 2^s is a constant that works out to 65536, it is more efficient to write:
float temp = (float)(-46.8 +(175.72 *data16/(float)65536));

Note the use of floating point arithmetic. The microbits's processor doesn't have hardware floating point, the framework comes with a software implementation. Floating arithmetic is slow and it is usual to convert it into suitably scaled integer arithmetic.

In this case using floating point is convenient, but there is a snag. The printf function doesn't support floating point format. There is another "full" version which does, but this has to be imported into the build.
