# Your First Program - Blinky

The time comes to run your first program and deal with some details of using VS Code.

You can use either the V1 or V2 development environment and hence target either version of the micro:bit. It is assumed that you have set up a project called BlinkyV1 or BlinkyV2 following the instructions given earlier. Load the project into VS Code and do a clean configure and a clean rebuild. Next, delete all of the source files in the source directory, which is in the project root for both versions. Create a new file called main.cpp, or simply copy the code into the existing file, containing the following code:

```cpp
#include "MicroBit.h"
MicroBit ubit;
int main()
{
  ubit.init();
  ubit.display.setDisplayMode(DISPLAY_MODE_GRESCALE);
  for (;;) {
    ubit.display.setPixelValue(2, 2, 255);
    ubit.sleep(1000);
    ubit.display.setPixelValue(2, 2, 0);
    ubit.sleep(1000);
  }
}
```

Exactly the same code will work with the V1 or the V2 micro:bit. Do a clean reconfigure and a clean rebuild of the project. As usual you will see a lot of warnings scroll past for the V1 compile, but the build should finish without errors.

You will find the generated hex files in ~/BlinkyV1/build/source for the V1 program and the file you want to download is BlinkyV1-combined.hex.

For the V2 program you will find the hex in the project root and it is called MICROBIT.hex.

If you have set the templates correctly, you should see the middle LED in the display flash at 1 second intervals. Notice that if you simply change the main program, or make minor changes to any program in the project, you should only need to do a build and not a clean build.

Everything should work as advertised, including IntelliSense, auto-complete and error flagging. If not sure that the .vscode/c_properties.json file contains the line:

```json
"compileCommands": "${workspaceFolder}/build/compile_commands.json",
```

# First Steps With The GPIO

The most basic task when working with the microbit is controlling I/O lines. This isn't difficult if you use the framework provided, but there some points to watch out for.

The microbit has at least 32 General Purpose I/O (GPIO) lines, although not of them are available for use. Finding out how to use them is an important first step and you have to master both the hardware and the software aspects.

Warning: Despite the ease of making connections to the microbit using hoc cables and clips, the GPIO lines are very low power and sensitive to voltages and currents outside their normal range. Do not connect anything to the microbit, especially for output, without considering the voltage and current applied. The voltage should be 3.3V or less and the current should be 0.5mA or less.

# Pinouts

The big irritation of working with any electronic device that has GPIO lines is what you call them. The manufacturer will give them names like GPIO 01, GPIO 02 and so on, but when the processor is used in a finished product like the microbit these lines are brought out to physical pins, connections, on the printed circuit board. These are often called Pin01, Pin02 and so on and there is no need for Pin01 to correspond to GPIO 0. Indeed, in most cases pin numbers and GPIO numbers are fairly independent.

The microbit uses a strange system of pin names, connector numbers, PCB connector and what are printed on the edge connector and these correspond to different GPIO numbers. They are also extended to include the GPIO lines used to control on-board peripherals. For example, P0 is the first “pad” on all micro:bits, but it corresponds to GPIO line 3 in the V1 and line 2 in the V2. It is also pin 18 on the physical edge connector. On the schematic diagram, the same pin is labeled PAD1 just to increase the confusion.
