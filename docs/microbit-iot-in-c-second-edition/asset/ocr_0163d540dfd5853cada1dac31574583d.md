You pass the URL to the function as an IP address or as a full URL, but the device looks up domain names using a fixed set of DNS servers. It is recommended that you use an IP address, especially when testing. The CIPSTART command opens a socket to the specified IP address and port. You can also specify a TCP or UDP connection:

```
AT+CIPSTART=type, IP, port
```

In this case use port 80 on the specified IP address. If it works you will get back a message like this:

```
Connect
AT+CIPSTART="TCP", "192.168.253.23", 80
CONNECT
```

OK

Now we have a socket open we can send data to the server and wait for some data to be back to us. This is the most difficult part of using the microbit on the web. If you request a web page then it is fairly likely that the data you get back is of too much to hold in memory. Either you have to load a very small web page - a few hundred bytes - process it on the fly as the data comes in. For this example the web page is served by a small sensor that returns a JSON temperature and humidity reading. The sensor is another micro:bit and the web server is described in the next section.

To send data over a socket use CIPEND, which will send any data you specify to the server. As already made clear, what you send is a matter for whatever protocol you use over the socket. In this case it is HTTP and we are going to send headers corresponding to a GET request for index.html:ManagedString http = "GET /index.html HTTP/1.0\r\nHost:192.168.253.23\r\n\r\n"

There are two headers:

```
GET /index.html HTTP/1.0
Host:192.168.253.23
```

Note that an HTTP request always ends with a blank line.
To send this use the CIPEND command which specifies the number of characters that are to follow:

```
cmd = "AT+CIPSEND=" + ManagedString(http.length()) + "\r\n"
uBit.serial.send(cmd, SYNC_SPINWAIT);
```
