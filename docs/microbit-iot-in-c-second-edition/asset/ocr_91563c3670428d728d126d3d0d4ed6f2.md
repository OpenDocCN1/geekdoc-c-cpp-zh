The modes work in the same way as sent, but if you select ASYNC then the function returns immediately if there is nothing in the receive buffer and returns a null of some sort.

+   - The read a character function returns MICROBIT_NO_DATA.
- The read ManagedString functions return as many characters as available or a null string if there are none.
- The readUntil will return a null if the delimiter is not in the buffer.

The other modes hang your program until the request can be met. This is for sending data, but when you are receiving data you cannot be sure that the other device will give you anything out of the spinwait or the sleep.

To see how all this might work let's write a simple polling loop that reads characters from the serial Rx and sends them to the serial Tx. If you use this with the terminal will see characters echoed you type an x.

```
uBit.init();
int c;
do {
    uBit.serial.read(ASYNC);
    if((char)!=MICROBIT_NO_DATA)uBit.serial.send((char)c);
} while((char)c!='x');
```

This works, but you might be thinking what waste of processor power. This is true, but you can put whatever processing you want to perform in the do loop and check the receiver buffer when the loop repeats.

You can use the same trick to send characters from the USB serial port to another pin:

```
uBit.init();
int c;
do {
    uBit.serial.read(ASYNC);
    if(c)!=MICROBIT_NO_DATA){
        uBit.serial.redirect(MICROBIT_PIN_P1, MICROBIT_PIN_P2);
        uBit.serial.send((char)c);
        uBit.serial.redirect(USBTX, USBRX);
    }
} while((char)c!='x');
```

For V2 change redirect to:
uBit.serial.redirect(uBit.io.P1 , uBit.io.P2);

This works, but there is a problem. Each time the redirect occurs a spurious character is transmitted; a poorly framed character should be rejected by the other device as an error. This spurious character is a real problem because it stops you from writing a program that takes data from one serial port and sends it to another. If you have to rapidly switch between connections the spurious extra characters swap the connection.
