## Yotta And Offline Development

If you outgrowth the development template then you might well need to create your own project using Yotta. Getting micro:bit V1 development setup on the desktop isn't exactly the same as getting for general mbed development, but it very nearly is. The only real difference is the library used to support the hardware. To work locally we need to install the mbed build system which is called lotta, a suitable compiler tool set, and something to use as an editor.

## Build Systems

The biggest problem facing the embedded programmer is the apparent complexity of the build system. Back in simpler times an embedded C program might grow to a few hundred lines, perhaps with a simple single support library. Today libraries as mbed or the micro:bit library are complex and need other software components to complete them. You could manage these manually, which is what we did in the past. Each time you included a header you would have to find and resolve references to other headers and then find the object files corresponding to all of these libraries and link them to the final program. When the total amount of code was small this was entirely possible, as already mentioned, this is no longer the case.

The solution to the problem is a build system which can do the job for you automatically. You may already know build tools such as make that run scripts without the compiler and linker on all of the necessary files. A build system goes beyond this that it will also deduce dependencies, perhaps even get the files needed, and incorporate them into the build. An example of such system is cmake which generates files for you.

For the mbed project new build system lotta was invented. While it is still in use, it doesn't seem to be as well supported as it was. Offline development without yotta is possible, but it would require you to manually organize all of the files needed to build the project and create the commands for the compiler and linker to perform the build; lotta can do this for you.

Yotta generates CMake files which are then used to build the system using make or Ninja, which is the build engine. The micro:bit V2 also makes use of Cmake and it has yotta files which allow yotta to be used. However, it is properly better to focus on Cmake.

There are some problems with getting to grips with yotta. The first is that it is a complicated system and if things go wrong you can be left wondering what to do. The second is that this something new to learn. There are enough problems in embedded programming without adding another layer of complexity and, of course, the need to learn something new feeds back into the difficulties of working out what is going wrong. However, in practice, yotta turns out to be easy to use and mostly reliable.

## How Yotta Works

You don't need to know how yotta works under the covers to use, but a little knowledge is helpful.

Yotta works with modules, which roughly speaking consist of code and header files that do something. A yotta module includes a json format file which provides metadata such as its name, license, author and any modules that it makes use of, i.e. its dependencies. You don't have to create the json file manually, yotta has commands that do it for you.

Yotta also supports the same system for an executable and when you tell yotta to build the executable it reads the json file, gets the modules which are needed and then creates cmake files to build modules for a specified platform - the target. Finally cmake generates files that are actually used to build the entire project using Ninja or one of other make systems that it supports.

This is complicated because yotta feeds cmake, which feeds Ninja, which does the final job of compiling and linking the code. If you are feeling confused it will make a lot more sense after you have seen yotta in action. Notice that as well as automating the build of your program, you can also use yotta to create and publish modules that can be used by other people.

## Installing Yotta

Detailed instructions for yotta are provided on the mbed website:
https://docs.yottabuild.org/

First you need to check that you have an up-to-date copy of Python installed:
https://www.python.org/downloads/

If you use Python for other things you might want to set up a virtual environment, Yotta doesn't require any additional configuration. Make sure that you can run Python from the command line:
python --version

If not add the Python directory to the current path. You also need the latest version of pip:
python.exe -m pip install --upgrade pip

Next you need to install CMake:
https://cmake.org/download/

Select the correct installer for your machine and follow the prompts. Make sure that you add CMake to the Path option otherwise you will have to it yourself.
C:\Program Files\CMake

Make sure it works using:
cmake -version

If not check that it is on the path.

CMake uses Ninja under Windows to actually perform the build. Download this from:
https://ninja-build.org/

Download the ninja file for Windows and extract the ninja.exe file into a suitable folder that is on the path. A simple solution is to copy it to the CMake\bin directory.

The compiled binary is converted to a hex format file for flashing the microbit's memory. This needs a utility called srecord. You can get from Sourceforge as a source file that you can build yourself. Alternatively, and more simply, you can download a binary for Windows from:
https://sourceforge.net/projects/srecord/files/srecord-win32/

Simply unzip src_cat into a directory that is on the path – the CMake/bin directory is an easy choice.

You also need a cross compiler and the most commonly used is GCC ARM.
