For each bit you check if it is a one - if you replace the data with the data XOR. In either case you shift the divisor one place to the right:

```
for (int i = 0; i < 16; i++){
    if(data32 & (uint32_t)1<<(23 -i))data32 =data32 ^ divisor;
    divisor >>= 1;
}
```

When the loop ends, if there was no error, the data32 should be zeroed and the received checksum is correct and as computed on the data received.

A complete function to compute the checksum with some optimizations:

```
uint8_t crcCheck(uint8_t msb, uint8_t lsb, uint8_t check){
    uint32_t data32=((uint32_t)msb << 16) |
    ((uint32_t)lsb << 8)|((uint32_t) check);
    uint32_t divisor = 0x988B000;
    for (int i = 0; i < 16; i++){
        if(data32 & (uint32_t)1<<(23 - i ))data32 ^= divisor;
        divisor >>= 1;
    }
    return (uint32_t)data32;
}
```

It is rare to get a CRC error on an I2C bus unless it is overloaded or subject to a lot of noise.

# Another Bus

If you don't want to use the internal I2C bus then you have to give over two additional GPIO lines to the task of implementing a second one. If you need to do this, the good news is that it is fairly easy because the framework takes care of everything, configuring the GPIO lines to be open collector.

All you have to do instantiate your own I2C object - remembering not to instantiate or use a uBit object - making sure all the objects you create are global.

If you want to convert the program that we have developed so far, you also need a serial object to make printf send results to the serial port. For the microbit V1 this

```
MicroBitI2C i2c(MICROBIT_PIN_P1, MICROBIT_PIN_P2);
MicroBitSerial(USBTX, USBRX);
```

The MicroBit V2 uses:

```
MicroBitSerial(USB_UART_TX, USB_UART_RX);
```

In this case the I2C lines have been allocated to the first two pads, i.e. P0 and P1 on the connector. If you do this then you have to make sure that you don't configure or attempt to use these GPIO lines for any other purpose.
