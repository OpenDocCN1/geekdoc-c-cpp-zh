We now need to set P0_3 to output, making sure not to change any of
the other pins:

*dirset = mask;

We can now write a loop to toggle GPIO P0_3 as fast as possible:

```
for (;;) {
    *outset = mask;
    *outclr = mask;
}
```

The complete program is:

```
int main() {
    int GPIO=2; //Uncomment for V2
    volatile unsigned int *dirset=(unsigned int*) (0x50000000UL+0x518);
    volatile unsigned int *outset=(unsigned int*) (0x50000000UL+0x508);
    volatile unsigned int *outclr=(unsigned int*) (0x50000000UL+0x50C);
```

Notice that you don't have to include the microbit library to make this work.

If you run the program and measure the pulse widths you will find it is much
faster. The pulse width of a V1 is 0.25µs compared to the 3.5µs pulses we can
generate using the framework, i.e. more than ten faster.

![](bbox=[0.243, 0.626, 0.817, 0.723])

This only leaves the question as to why the low time, 0.5µs, is much longer
than the high time?

The answer might surprise you. The extra time is how long it takes the for
loop to perform its loop-end test and return to the start of the loop. The
memory-mapping instructions are now performing at the speed of the
processor and the pulse train produced is influenced by the way the
processor executes other instructions. You can't get rid of the time needed to
t control to another part of the program to form a loop - a goto
generates the same delay.
