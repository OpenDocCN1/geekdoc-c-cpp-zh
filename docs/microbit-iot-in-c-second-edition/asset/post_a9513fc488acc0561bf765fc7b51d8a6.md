# Chapter 8 Creating A Custom Protocol

In this chapter we use all the ideas introduced in earlier chapters to create a raw interface with the low cost DHT11/22 sensor as an exercise in implementing a custom protocol directly in C.

## The DHT22

The DHT22 is a more accurate version of the DHT11 and is used in this project, but the hardware and software will work with both versions and with the AM232, which is similar to the DHT22.

![](img/23976341c9281123e7b18beea6e9dbd_124.png)

| Model | AM232/DHT22 |
| :--- | :--- |
| Power supply | 3.3-5.5V DC |
| Output signal | digital signal via 1-wire |
| Sensing element | Polymer capacitor |
| Operating range | 0-100%RH; -40~80Celsius |
| Accuracy | ±2%RH; ±5Celsius |
| Resolution | ±0.1%RH; ±0.1Celsius |
| Repeatability | ±1%RH; ±0.2Celsius |

The device will work at 3.3V and makes use of 1-wire, open collector-style bus which makes it very easy to make the physical connection to the microbit. The 1-wire bus isn't standard and is only used by this family of devices, so we have little choice but to implement the protocol in C.

The pinouts are:
1. VDD
2. SDA data
3. not used
4. GND

and the standard way of connecting the device is:

![](img/23976341c9281123e7b18beea6e9dbd_125_1.png)

Although the recommended pull-up resistor is 1k, a higher value works better with the microbit - typically 4.7k, but larger will work. The serial protocol is fairly simple. The host pulls the line low for between 1ms and 9ms, usually 1ms. It releases the bus, which is pulled high. After 20µs to 200µs, usually 30µs, the device starts to send data by pulling the line down for around 80µs and then lets it float high for another 80µs. Next 40 bits of data are sent using a 70µs high for a 1 and a 26µs high for a 0 with the pulses separated by around 50µs low periods.

| Host pulls up | Sensor pulls up | Sensor output | Sensor output 1 bit data of "1" | Transmission |
| :--- | :--- | :--- | :--- | :--- |
| VCC | and wait for sensor's response | get ready to output signal | 1 bit data of "0" | Transmission ended, host pulls up |
| GND | Host send signal | Sensor send out response | Sensor output alternative of "0" or "1" based upon real value | Sensor pulls low |

![](img/23976341c9281123e7b18beea6e9dbd_126_0.png)

So what we have to do is pull the line for 1ms or so to start the device sending data and this is very easy. Then we have to wait for the line down and let it pull up again for about 160µs and then read the time that the line is high 40 times.

A 1 corresponds to 70µs and a 0 corresponds to 26µs. This is within the range of pulse measurement that can be achieved using standard library function. There is also a 50µs period between each data bit and this can be used to limited processing. Notice that we are only interested in the time that the line is held high.
