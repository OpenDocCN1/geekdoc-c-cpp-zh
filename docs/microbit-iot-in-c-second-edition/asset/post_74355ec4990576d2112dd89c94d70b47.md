
Select the correct installer for your machine and follow the prompts. Make sure that you select the option to add CMake to the path, otherwise you will have to add it yourself. CMake is installed to:

C:\Program Files\CMake\

Check it works using:

```
cmake --version
```

If not, check that it is on the path.
CMake uses Ninja under Windows to actually perform the build. Download this from:

https://ninja-build.org/

Download the ZIP file for Windows and extract the ninja.exe file into a suitable folder that is on the path. A simple solution is to copy it to the CMake\bin directory.

To check that Ninja is on the path and working, use:

```
ninja --version
```

There is another requirement in the form of a utility called srecord, but this is included with the project and you don't need to download it unless you are going to work without it. In that case, you can download a binary for Windows from:

https://sourceforge.net/srecord/files/srecord-win32/

Simply unzip srecord.exe into a directory that is on the path - then CMake\bin directory is an easy choice.

## Hello World For Microbit V1

Assuming that you have set up the prerequisites in the previous section, you can quickly move on to creating your microbit V1 application. First go to:

https://github.com/microbit-foundation/MicroBitV1 and download a zip (or use GitHub to also clone the repository). Once you have the file, you can unzip and extract the folder MicroBitVTemplate to the folder you can use to store projects:

| Name | Type |
|---|---|
| MicroBitVTemplate | folder |
| .gitattributes | Text Document |
| .gitignore | Text Document |
| LICENSE | File |
| README.md | File |

It doesn't matter where you store the folder, but there are advantages to keeping the path clear. For example, I copied it to a CProjects directory in my home directory:

C:\Users\harry.fairhead\Documents\CProjects

Once you have copied the template, you can change the name of the folder to something more appropriate for the project or rename it. In this case rename the folder "MicroBitVTemplate" to "HelloWorld".

The next problem is that we have to change all the absolute paths used in the CMake files. The obvious solution would be to convert all the paths to relative paths, which turns out to be very difficult to do as there are more than 10,000 occurrences of the absolute path in several types of files. While it would be possible to modify the CMake configuration using relative paths, or indeed to create a completely new CMake configuration that works appropriately, this is a poor investment of time. A quicker solution, although it is undoubtedly a "hack", is to use a file replace option to edit the incorrect absolute paths to correct absolute paths. And that is the task to change:

```
c:/MicroBitVTemplate
```

into whatever the new path is. In my case C:\Users\harry.fairhead\Documents\CProjects\HelloWorld

There are various ways to make a batch of files. VS Code will do the job, but not entirely reliable. Notepad++ is much more accurate and if you haven't installed Notepad++, it is generally useful. If you don't want to use Notepad++, you can use any text processor/editor that can make a set of files without changing their encoding.

If you use Notepad++, the command is Search, Find in Files and you should fill the dialog box in something like:

![](img/23976341c9281123e7b181beea69dbd_22.png)

Replace in Files: 10859 occurrences were replaced.

Notice the orientation of the path separators. CMake works best with Unix/Linux path separators but Windows works best with Windows separators. You can see from the dialog box 10,859 absolute paths are replaced, but this might change as files/folders are modified in the repo.

If you want to change the project name, which modifies the names of the compiled files including the hello files, then:

build\bbc-microsoft-classic-gcc\CMakeLists.txt

and change line 74 to:

```cmake
project(HelloWorld)
```

Now you can load the project into VS Code or any IDE that can work with CMake. Open a new VS Code window and load the HelloWorld folder. It should be recognized as a C/C++ CMake program.

If VS Code offers to configure the project then the best answer is to select Not now. If it does the project, you may have to do a clean reconfigure and clean build to get things working.

![](img/23976341c9281123e7b181beea6dbd_23_0.png)

No matter what happens, your next manual task is to select the CMake extension and then select Clean Reconfigure All Projects

![](img/23976341c9281123e7b181beea6dbd_23_1.png)

As this is the first time to configure the project you will be asked to select a “kit”. Essentially a kit is a compiler collection that can be used to build the project. If you have installed GCC you will see it in the list – if you don't see it then use the Scan for kits option. If you still don't see it, check that it is installed and on the path.

![](img/23976341c9281123e7b181beea6dbd_21.png)

The project configuration runs the CMakeLists.txt file in the root and this uses Git to download the missing libraries. For this work, you have to have Git – not GitHub – installed. If you don't you can download and copy the libraries manually.
