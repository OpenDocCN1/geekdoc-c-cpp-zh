
Notice that now we specify the target, a pause in milliseconds between polling attempts, and a timeout in terms of how many retries before the function gives up. Notice that the function returns 0 if there was a failure and the retry loop timed out and the number of retries remaining otherwise.

Using this utility function ATWiFi can be written:

```c
int ATWiFi() {
    uBit.serial.send("AT\n", SYNC_SPINWAIT);
    return waitForWiFi("OK",150,10);
}
```

This is a shorter and easier to understand.

# Configuring WiFi

The first thing we need to configure is the operating mode. The ESP8622 can operate as an access point, i.e it can allow other devices to connect to it. However, in most cases you will want it to work in client, connecting to your existing WiFi.

# Mode

A function to set its operating mode is:

```c
int modeWiFi(int mode) {
  ManagedString cmd="AT+CWMODE CUR="+String(mode)+"\r\n";
  uBit.serial.send(cmd, SYNC_SPINWAIT);
  return waitForWiFi("OK", 200, 10);
}
```

Notice now that we are constructing the command to send to the device in a separate step. If you try and do this on the fly in the function call, the rate of transmission of the serial data varies and the device can time out. In practice, construct all commands to send to the device first and then send them.

In this case the command is:

```
AT+CWMODE_n
```

where n is 1 for client, 2 for access point and 3 for both. If you want to make the change permanent change CUR to DEF and the setting is stored in Flash. Older devices do not support CWMODE_CUR. Simply change it to CWMODE, which is deprecated.

To set WiFi you would call:
modeWiFi(1);

and see OK sent back.

# Scan

The scan function is that everyone wants to try out, but in practice it isn't very useful. Why would you want a list of WiFi networks? There are some applications for this function, but not as many as you might think. In most cases, you simply want to connect to a known WiFi network, which is what we do in the next section.

The scan command is easy - just send AT+CWLAP and the device sends you a complete list of WiFi networks. The problem is that scanning takes long time and often hangs. This is one case where we really need to specify a long time until timeout:

```c
int scanWiFi() {
  uBit.serial("AT+CWLAP\r\n", SYNC_SPINWAIT);
  return waitForWiFi("OK", 200, 20);
}
```

Sometimes the loop completes with a full list, sometimes it doesn't. It depends on the WiFi networks that are available and how they reply to requests.
