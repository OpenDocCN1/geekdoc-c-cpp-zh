There is a bidirectional mode where a single wire is used for the data, but the microbit doesn't support this.

The standard signal lines are:

+   - MOSI Master Output Slave Input, i.e. data to the slave
- MISO Master Input Slave Output, i.e. data to the master
- SCLK Serial Clock which is always generated by the master

There can also be any Number of SS (Slave Select) or CS (Chip Select) lines, which are usually set low to select which slave is being addressed. Notice that unlike other buses, I2C for example, there are no SPI commands or addresses, only bytes of data. However, slave devices do interpret some of the data as commands to do something or send some particular data.

The microbit has two SPI Masters, but only one is exposed on the GPIO connector. There are no standard CE (Chip Enable) lines, although it is easy and logical to assign P16 to this task. This means that, in principle, you can connect only one SPI device to the microbit, although this restriction is easy to overcome by using additional GPIO lines for extra chip selects.

The second SPI Master can be used just as easily as the first, but you will have to allocate four GPIO lines to it and this is certain to mean loss of other functions.

In addition, the SPI bus hardware can be connected to any four GPIO lines, the pins that are normally used are:

| SPI | GPIO V1 | GPIO V2 |
|---|---|---|
| P13 SCLK | P0 23 | P0 17 |
| P14 MISO | P0 22 | P0 01 |
| P15 MOSI | P0 21 | P0 13 |
| P16 CE | P0 16 | P1_02 |

Notice that the use of P16 isn't mandatory and it isn't part of the usual pin allocation lists or diagrams.
