There is a problem we have to solve, however, the need for fast switching between input and output. Without intervention, changing between output and input mode is done using the system and is comparatively slow, approximately 80µs. In some cases this does matter because the protocol requires data from the master and receives data from the slave. For example, the DHT22 temperature and humidity sensor asks the processor to write to it a measurement and then sends data back without the processor writing anything, which permits the use of a single GPIO line, send the data, switch to input and read the data.

In the case of the 1-Wire buses are very different. The master has to send a fast pulse on the line for every bit received and it has to be able to read the output to input in time to read the data, although it could be done by writing with all 1-wire devices to the registers. A secure and simple solution that should work is to use two GPIO lines - one set to output and one to input. If you can't afford to use two GPIO lines then there is a way to do the job with, but only by resorting to directly accessing the GPIO line and not using the library functions, the end of this chapter for more details.

You can use any pair of GPIO lines, but for simplicity this example uses P0 and P1. The DS18B20 can be directly connected to the micro:bit's pads. The only complication is that you need the pull-up resistor. The internal pullup resistor is around 10-15k and is just too large to work. You need to put a 4.7k resistor in parallel with it to decrease the resistance.
