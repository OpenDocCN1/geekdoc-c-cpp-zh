this would mean the main program had to hold off sending another bit until the 60µs was up. This approach isn't efficient, but it is simple. Also notice that, the time periods are short and have to be fairly repeatable, a busy wait is the best option for the delay.

With these constants the measured widths are:

For a θ line is held low for just around 60µs with a pulse of about 10µs making the slot roughly 70µs.

For a 1 line is held low for 3-4µs and the slot is 70µs in total.

As the only critical operations are the actual setting of the line low and then back to high, there is no need to worry much about speed of operation of the entire function so we might well combine into a single writeBit function:

```
void writeBit(int b)
{
    int zero = 75;
    int zero = 240; //uncomment for V2
    int one = 8; //uncomment for V2
    int slot = 30;
    //slot = 300; //uncomment for V2

    volatile int i;
    int delay1, delay2;

    if (b == 1)
    {
        delay1 = one;
    }
    else
    {
        delay1 = zero;
        delay2 = slot - delay1;
        disable_irq();
        P0.setDigitalValue(0);
        for (i = 1; i < delay1; i++){
            P0.setDigitalValue(1);
        }
        for (i = 1; i < delay2; i++){
            enable_irq();
        }
    }
}
```
