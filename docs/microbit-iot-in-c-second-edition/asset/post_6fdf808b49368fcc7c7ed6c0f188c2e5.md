
## Configuration

There are two functions that set the format of operation.
The first sets the mode and the number of bits:
`void format(int bits, int mode = 0);`

where mode is set according to the table listed earlier and bits sets the number of bits between 4 and 16 to be transferred in a read/write operation.
The second simply sets the frequency of operation, i.e. the clock frequency:
`void frequency(int hz = 1000000);`

The allowed frequencies are:

- 125 kHz
- 250 kHz
- 500 kHz
- 1 MHz
- 2 MHz
- 4 MHz
- 8 MHz

If you don't select one of these the software selects the next highest.

## Data Transfer Function

Because of the SPI bus uses a full duplex transfer, you only need a single data transfer function, but this differs according to the micro:bit version you are using.

The micro:bit V1 has only:
`int write(int value);`

This sends a block of data to the slave while receiving a single block sent back. The number of bits sent and received is set by the configuration to anything from 4 to 16. In practice, this is a read/write function, but you can always throw away the data from the slave or send meaningless data to the slave to create something that looks like a read/write pair.

In the case of the micro:bit V2, the write function only sends the data and returns a zero or an error code. That is, it isn't bidirectional and hence not particularly useful. The bidirectional data transfer function:
`transfer(*txBuffer,Size, *rxBuffer, rxSize);`

This sends the data in the txBuffer and stores returned data in the rxBuffer.
It is slightly complicated to use but it is more useful.

It is easy to provide the V1 with a transfer function polyfill using the write function:

```c
int SPItransfer(uint8_t *txBuffer, uint32_t txSize, uint8_t *rxBuffer, uint32_t rxSize);
CS.setDigitalValue(0);
uint32_t i;
for (i = 0; i < txSize; i++) {
    if (i < rxSize)
    {
        rxBuffer[i] = spi.write(txBuffer[i]);
    } else {
        spi.write(txBuffer[i]);
    }
}
CS.setDigitalValue(1);
return 0;
```

It is assumed that txSize >= rxSize.

It is important to realize the write function does not control any CE line you may have defined. You have to set the CE line high when the SPI bus is being initialized and then lower it just before you write data to the slave. Then return the CE line high after the data transfer is complete.

Now we come to a subtle point. What is the difference between transferring multiple bytes and repeated single bytes? The answer is ten bytes, one byte at a time and the CE line has to be toggled. If you want to transfer ten bytes, one byte at a time, you have to perform ten calls to write, lowering the CE line before each and calling again before the next one. If you want to transfer ten bytes as a block then keep the CE line low until the tenth byte has been transferred. Sometimes this is not important and you can transfer three bytes activating the CE for each one or transfer three bytes keeping the CE line low until the transfer is over. However, some slaves will abort the current multibyte operation if the chip select line is deactivated in the middle of a multibyte transfer.

It is important to realize that the nature of the transfer is that the first byte is sent at the same time that the first byte is received. That is, unlike protocols where you send some data and then get back some data, the whole transfer works a byte at a time, the first byte is sent while the first byte is being received, then the second byte is sent at the same time the second byte is being received and so on.

## A Loopback Example

Because of the way that data is transferred on the SPI bus, it is very easy to test that everything is working without having to any components. All you have to do connect MOSI to MISO so that anything sent to it is also received in a loopback mode.

First connect pin 14 to pin 15 using a jumper wire. As this is a loopback test we really don't need to configure the bus but for completeness:

```c
spi.format(8,0);
spi.frequency(10000000);
```

Next we can send some data and receive it right back:

```c
uint8_t buf[1] = {0xAA};
SPITransfer(buf, 1, buf, 1);
```

V2:

```c
uint8_t buf[1] = {0xAA};
spi.transfer(buf, 1, buf, 1);
```

Notice that the V1 code makes use of the SPITransfer function in the previous section.

The hex value AA is useful in testing because it generates the bit sequence 10101010, which is easy to see on a logic analyzer. We can check that the received data matches the sent data in a variety of ways:

```c
if(read_data == 0xAA) printf("data received correctly");
```

We can also create and use a CE line using GPIO 16:

```c
MicroBitPin CS(MICROBIT_ID_IO_P16,
               MICROBIT_PIN_P16,
               PIN_CAPABILITY_DIGITAL );
```

To make the CE line work properly when connected to a real device, rather than just loopback mode, we need to set the CE line high when we initialize the bus and then lower it before sending data. Putting all of this together gives us the complete program:

```c
#include "MicroBit.h"
MicroBitPin CS(MICROBIT_ID_IO_P16,
               MICROBIT_PIN_P16,
               PIN_CAPABILITY_DIGITAL );

int SPItransfer(uint8_t *txBuffer, uint32_t txSize, uint8_t *rxBuffer, uint32_t rxSize) {
    CS.setDigitalValue(0);
    uint32_t i;
    for (i = 0; i < txSize; i++) {
        if (i < rxSize)
        {
            rxBuffer[i] = spi.write(txBuffer[i]);
        } else {
            spi.write(txBuffer[i]);
        }
    }
    CS.setDigitalValue(1);
    return 0;
}

int main() {
    uint8_t buf[1] = {0xAA};
    // V1 test
    SPITransfer(buf, 1, buf, 1);
    if(buf[0] == 0xAA) printf("data received correctly\n");

    // V2 test (requires manual CS control as per logic)
    // CS.setDigitalValue(0);
    // spi.transfer(buf, 1, buf, 1);
    // CS.setDigitalValue(1);

    return 0;
}
```
