Is there anything that can be done about the glitching? Yes and no. You can't do anything about the 40ms or so it takes to change from one duty cycle to another, but you can synchronize when it happens to the timer using the wait_us function. If you swap the waits for the 100µs delays to:

```
wait_us(100);
```

with the help of:

```
#define wait_us system_timer_wait_wait
```

for the V2, you will find that you consistently get three pulses of each duty cycle, separated by a longer pulse.

What all this is is really about trying to lower your expectation of how sophisticated you can be in using PWM on the micro:bit. The fastest PWM repetition rate that you can use with the V1 is about 30ms and minimize the glitches you need to leave the duty cycle stable from 10 to 20 pulses, i.e. about 200-600ms. In many applications this is very acceptable, but don't expect to use PWM to send coded data and using it for waveform synthesis as a D to A converter is limited to around 4kHz.

# Uses of PWM – Digital to Analog

What sorts of things do you use PWM for? There are lots of clever uses for it. However there are two cases which account for most PWM applications - voltage or power modulation and signaling to servos.

The amount of power delivered to a device by a pulse train is proportional to the duty cycle. A pulse train that has a 50% duty cycle is delivering current to the load only 50% of the time and this is irrespective of the pulse repetition rate.

So duty cycle controls the power, but the still matters in situations you want to avoid any flashing or other effects - a higher frequency smooths out the power flow at any duty cycle.

If you add a low-pass filter to the output of a PWM signal then what you get is a voltage is proportional to the duty cycle. This can be looked at in many ways, but again it is the result of the amount of power delivered by a PWM signal. You can also think of it as using the filter to remove the high frequency components of the signal, leaving only the slower components due to the modulation of the duty cycle.

The framework's PWM functions are designed to allow you to use this as a Digital to Analog (D-to-A) converter and this is why the function is setValue and notDuty cycle. It mimics the workings of an eight-bit D-to-A converter. You set the duty cycle using a value in the range 0 to 1023 and you get a voltage output that is:

3.3*value/1023 V
