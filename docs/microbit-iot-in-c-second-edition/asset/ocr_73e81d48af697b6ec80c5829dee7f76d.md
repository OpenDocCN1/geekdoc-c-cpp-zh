In the case of the microbit we have a system of events that stand in a software wrapping of the raw system interrupts that are available if you dig just a little deeper.
As far as GPIO lines are concerned you can determine how events occur using one of four settings. The most useful is the on-edge setting, which fires an event if a GPIO line transitions from high to low or low to high.

```
int eventOn(int eventType)
```

where eventType is one of:

| MICROBIT_PIN_EVENT_ON | Fire on rising or falling edge as specified when event registered |
| MICROBIT_PIN_ON_PULSE | Fire if pin is high or low as set when event registered |
| MICROBIT_PIN_EVENT_TOUCH | Fire if pin touched |
| MICROBIT_PIN_EVENT_NONE | Disable events for this pin |

As well as the eventOn setting you also have to register the event with the messagebus. You have to supply the ID of the pin generating the event, the event type, the function to be called when the event happens and how the event be handled. For example:

```
bus.listen(MICROBIT_ID_P0, MICROBIT_PIN_PULSE_HI, MESSAGE_BUS_LISTENER_IMMEDIATE)
```

will call onPulse when the PULSE_HI occurs on pin P0 and it will call the event handler at once. The event types that you can specify are:

```
MICROBIT_PIN_EVT_RISE
MICROBIT_PIN_EVT_FALL
MICROBIT_PIN_EVT_PULSE_HI
MICROBIT_PIN_EVT_PULSE_LO
```

The event handler has the signature:
voidHandler(MicroBitEvent evt)

and one of the most useful properties of the evt object is the timestamp of the event.

Events are only useful when you have a low frequency condition that needs to deal with on a low priority basis. Their use can simplify the logic of your program, but rarely using an event speed up things because the overhead involved in event, or interrupt, handling is quite high. For example, suppose you want to react to a doorbell push button. You could write a polling loop that simply checks the button status repeatedly and forever, or you could write an event to respond to the doorbell. How good a design depends on how much the doorbell event has to interact with the rest of the program.
