After a few seconds you should see:

```
AT+CWJAP CUR="myWiFi","myPassword"
WIFI DISCONNECT
WIFI CONNECTED
WIFI GOT IP
```

OK

Once you are connected and the "WIFI GOT IP" message has been received
you can ask what the IP address is:

```
int getIPWiFi() {
    uBit.serial.send("AT+CIFSR\r\n", SYNC_SPINWAIT);
    return waitForWiFi(\("OK", 200, 10);
}
```

Of course, if you really need to know the IP address in a program younneed to extract it from the string. The device replies with:

IP address:
AT+CIFSR
+CIFSR:STAIP,"192.168.253.4"
+CIFSR:STAMAC,"5c:cf:7f:16:97:ab"

OK

which makes very easy to get the IP address even without the help of
regular expression.

# Getting a Web Page

Now that we have many functions we can tackle the two standard tasks in\using the TCP stack - sending data as a client and as a server.
First, we tackle the problem of acting as a client. This isn't as common as
requirement as you might expect because most of the time devices like the
microbit are used to supply data to other servers, not the other way.
However, it is worth seeing how it is. It doesn't matter whether you are
implementing a client or a server, you make use of sockets which represent
the basic TCP connection. What you do with this connection is up to you. For
ine you send HTTP headers on an appropriate port then you can fetch
or deliver a web page, i.e. HTTP over TCP. However, what data you actually
send and receive over a socket connection is up to you and/or the protocol
you are trying to.

Hence the first thing we have to set up a socket connection between the
client, i.e. the microbit, and the server.

```
int getPageViewWiFi(ManagedString URL,ManagedString page) {
    ManagedString cmd = "AT+CIPSTART:\"",\"" + URL + "\",80\r\n";
    uBit.serial.send(cmd, SYNC_SPINWAIT);
    if (waitForWiFi(\("OK", 100, 20)) == 0) return 0;
}
```
