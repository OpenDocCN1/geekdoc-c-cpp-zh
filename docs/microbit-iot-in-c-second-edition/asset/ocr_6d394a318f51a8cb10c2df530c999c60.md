# Reading Data

When programming a serial connection it reading data that usually causes the most difficulty. Sending data is easy - you just send it, but receiving data requires you to know that there is some data to receive. In short, the problem is finding out when the other device has sent something to process. Basically there are only two ways of doing this. You can poll the receive buffer to detect when there is some data to read or set up an interrupt and have it call a function when there is something to read. While the interrupt approach seems to have a lot going for it, the simpler polling approach is often the better choice:

```
int read()
int read(MicroBitSerialMode)
ManagedString read(int size)
ManagedString read(int size,MicroBitSerialMode)
int read(uint8_t *buffer, bufferLen)
int read(uint8_t *buffer, bufferLen,MicroBitSerialMode)
```

The simple read command with or without mode specified a single character. It is often used in a loop to read characters until there are no more, if you are going to do this you need to set the correct mode.

The ManagedString function is as long as you know how many characters you are expecting. The read into a buffer has the same problem, i.e. you need to specify the number of bytes to read.

As well as these standard functions, there's a pair of readUntil functions:
ManagedString readUntil(ManagedString delimiters)
ManagedString readUntil(ManagedString delimiters,MicroBitSerialMode)

These will read the receive buffer until one of the delimiters included in the nManagedString is encountered. For example:

```
s = readUntil("\n");
```

will read characters from the receive buffer until it finds a new line code. Notice that the string matching is on a per character basis so:

```
s = readUntil("\n\r");
```

will stop on encountering a new line or a carriage return not a new line followed by a carriage return.
