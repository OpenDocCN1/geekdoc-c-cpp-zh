# Creating a Heap

The unsorted keys are taken sequentially one at a time and added into a heap. The size of the heap grows with the addition of each key. The $i^{th}$ key ($k_i$) is added into an existing heap of size $i-1$ and a heap of size $i$ is obtained. Initially, the node is placed in the heap of size $i-1$ in such a way that an almost complete constraint is satisfied. The value of $k_i$ is then compared with its parent's key value. If $k_i$ is greater, the contents of the newly added node and that of its parent's node are exchanged. This process continues until either $k_i$ is at the root node or the parent's key value is not less than $k_i$. The final tree is a heap of size $i$.

Let us assume that the heap is housed in an array where the relationships of the tree are not physically represented by link fields. Instead, they are implicit in the way we store them in the array. We store the binary tree in the array level-by-level, left to right. For example, Fig. 12.24 shows a binary tree.
