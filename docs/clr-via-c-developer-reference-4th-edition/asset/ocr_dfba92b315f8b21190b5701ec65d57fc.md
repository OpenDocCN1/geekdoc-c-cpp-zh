When the real SomeMethod returns, it returns to the proxy's SomeMethod method, which transitions the thread back to the default AppDomain, and then the thread continues executing code in the default AppDomain.

When a thread in one AppDomain calls a method in another AppDomain, the thread transitions between the two AppDomains boundaries are executed synchronously. However, at any given time, a thread is considered to be in one AppDomain, and it executes code using AppDomain's security and configuration settings. If you want to execute code in multiple AppDomains concurrently, you should create additional threads and execute them whatever you want in whatever AppDomains you want.

The next thing that Ch22-1-AppDomains application does is call AppDomain's public, static Unload method to unload the specified AppDomain, including all of the assemblies loaded into it. A garbage collection is forced to free any objects that were created by the unloading AppDomain. At this point, the default AppDomain mbr variable still refers to a valid proxy object; however, the proxy object no longer refers to a valid AppDomain (because it has been unloaded).

When the default AppDomain attempts to use the proxy object to call the SomeMethod, the proxy's implementation of this method determines that the AppDomain that contains the real object has unloaded, and the proxy's SomeMethod throws an AppDomainUnloadedException to let the caller know that the operation cannot complete.

I promised that I'd talk a little about instance fields. A type derived from MarshalRef can define instance fields. However, these fields are not defined as part of the proxy and are not contained inside a proxy object. When you write code that reads or writes to an instance of a type derived from MarshalRefObject, the JIT compiler embeds code that uses the proxy object (to find the real AppDomain/object) by calling System.Object's FieldGetter and FieldSetter methods, respectively. These methods are private and undocumented; they are basically methods that use reflection to get and set the value in a field. So although you can access fields of a type derived from MarshalRef, the performance is particularly bad because the CLR really ends calling methods to perform the field access. In fact, the performance is bad even if the object that you are accessing is in your own AppDomain.³
