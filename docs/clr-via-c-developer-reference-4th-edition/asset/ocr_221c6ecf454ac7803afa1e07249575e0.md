At this point, the end user would have no choice to reboot the computer by pressing the reset button or switch. Of course, users hated doing this (they still do, in fact) all running applications terminated; more importantly, any data that these applications were processing thrown out of memory and lost. Microsoft know that 16-bit Windows would not be a good operating system to keep Microsoft relevant as the computer industry progressed, so they set out to build a new operating system to address the needs of corporations and individuals. This new operating system had to be robust, reliable, scalable, and secure, and had to improve the many deficiencies of 16-bit Windows. This operating system originally shipped in Windows NT. Over the years, it has had many tweaks and features added to it. The latest version of this kernel ships in the latest versions of the Microsoft client and Windows operating systems.

When Microsoft was designing this operating system kernel, they decided to run each instance of an application in what is called a *process*. A process is a collection of resources that is used by a single instance of an application. Each process is a virtual address space, ensuring that the code and data used by one process is not accessible to another. This makes applications robust because one process cannot corrupt code or data being used. In addition, the operating system's kernel code and data are not accessible to processes; therefore, it's not possible for application code to corrupt operating system code or data. So, application code cannot corrupt other applications or the operating system itself, and the whole computing experience is much better for end users. In addition, the system is more secure because application code cannot access user names, passwords, credit card information, or other sensitive information that is in use by another application or the operating system.

This is all well and good, but what about the CPU itself? What if an application enters an infinite loop? Well, if there is only one CPU in the machine, then it executes the infinite loop and cannot execute anything else, although the data cannot be corrupted and is more secure, the system could still stop responding to the end user. Microsoft needed to fix this problem, and threads were the answer. A thread is a concept whose job is to visualize the CPU. Windows gives each process its own thread (which functions similar to a CPU), and if application code enters an infinite loop, the process associated with that code freezes up, but other processes (which have their own threads) are not frozen; they keep running!

# Thread Overhead

Threads are awesome because they enable Windows to be responsive when applications are executing long-running tasks. Also, threads allow the user to use one application (like Task Manager) to forcibly kill an application that appears frozen because it is executing a long-running task. But with every virtualization mechanism, threads have space (memory consumption) and time (runtime execution performance) overhead associated with them.
