The compiler automatically generates names for methods by getting get_ and set_ to the indexer name. Because the C# syntax doesn't allow the developer to specify an in-dexer name, the C# compiler had to choose a default name to use for the accessor methods; they chose Item. Therefore, the method names emitted by the compiler are get_Item and set_Item.

When examining the .NET Framework Reference document, you can tell if a type offers an indexer by looking for a property named Item. For example, the System.Collections.Generic.List offers a public instance named Item; this property is List's indexer.

When you program in C#, you never see the name of Item, you don't normally care that the compiler has this name for you. However, if you're designing an indexer for a type written in other programming languages you might want to change the default name, Item, by giving to your indexer get and set accessor methods. C# allows you to rename these methods by using the System.Runtime.CompilerServices.IndexerName custom attribute to the indexer. The following code demonstrates how to do this.

```
using System;
using System.Runtime.CompilerServices;

public sealed class BitArray{

    [IndexerName("Bit")
    public Boolean this[Int32 bitPos] {
        // At least one accessor method is defined here
    }
}
```

Now the compiler will emit methods get_Bit and set_Bit instead of get_Item and set_Item. When compiling, the C# compiler sees the IndexerName attribute, and this tells the compiler how to name the methods and the property metadata; the attribute is not emitted into the assembly's metadata.

  Console.WriteLine(ba(2)) - Displays True or False
- Visual Basic also allows you to access the indexer by its name.
  Console.WriteLine(ba.Bit(2)) - Displays same as previous line
