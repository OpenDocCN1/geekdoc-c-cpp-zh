t.ContinueWith(task => Console.WriteLine("The sum is: " + task.Result);
TaskContinuationOptions.OnlyRanToCompletion);

t.ContinueWith(task => Console.WriteLine("Sum threw: " + task.Exception.InnerException);
TaskContinuationOptions.OnlyOnFaulted);

t.ContinueWith(task => Console.WriteLine("Sum canceled")
TaskContinuationOptions.OnlyOnCanceled);

# A Task May Start Child Tasks

Finally, tasks support parent/child relationships, as demonstrated by the following code:

```
Task<Int32[]> parent = new Task<Int32[]>(() => {
var results = new Int32[3]; // Create an array for the results
// This creates and starts 3 child tasks
new Task(() => results[0] = Sum(1000), TaskContinuationOptions.AttachedToParent).Start();
new Task(() => results[1] = Sum(20000), TaskContinuationOptions.AttachedToParent).Start();
new Task(() => results[2] = Sum(30000), TaskContinuationOptions.AttachedToParent).Start();
// Returns a reference to the array (even though the elements may not be initialized)
return results;
});
// When the parent and its children have run to completion, display the results
var cwt = parent.ContinueWith(
parentTask => Array.ForEach(parentTask.Result, Console.WriteLine));
```

// Start the parent task so it can start its children
parent.Start();

Here, the task creates creates starts Three Objects. By default, the task created by another task are top-level tasks that have no relationship to the task that creates them. However, the TaskContinuationOptions.AttachedToParent flag associates a Task with the Task it creates so that the creating is not considered finished until all its children (and grandchildren) have finished running. When creating a Task by using the ContinueWith method, you can make the continue-with a child by specifying the TaskContinuationOptions.AttachedToParent.

# Inside a Task

Each object has a set of fields that make up the task's state. There is an Int32 ID (see Task's read-only Id property) representing the execution state of the Task, a reference to the parent task, a reference to the TaskScheduler when the Task was created, a reference to the callback method, a reference to the object that is passed to the callback method (queryable via Task's read-only AsyncResetEvent property), a reference to an ExecutionContext, and a reference to a ManualResetSlim. In addition, each task has a reference to some supplementary state that is created on demand. The supplementary state includes a Cancellation-Token, a collection of ContinueWithTask, a collection of Child tasks that have thrown unhandled exceptions, and more.
