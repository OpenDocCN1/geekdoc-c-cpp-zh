Important In general, I strongly discourage explicitly calling Dispose in your code. The reason is that the CLR's garbage collector is well written, and you should let it do its job. The garbage collector knows when an object is no longer accessible from application code, and only then will it collect the object. When code calls Dispose, it is effectively saying that the application knows no longer has a need for the object. For many applications, it is impossible to know for sure when an object is no longer required.

For example, if you code constructs a new object, and then pass a reference to this object to another, the method could save a reference to the object in some internal field variable (a root). There is no way for the method to know that this has happened. Sure, the method can call Dispose, but later, some other code might try to access the object, causing an ObjectDisposedException to be thrown. I recommend that you call Dispose only at places where you know you must clean up the resource (as in the case of attempting to delete an open file).

Along the same lines, it is possible to have multiple threads call Dispose on a single object simultaneously. However the design guidelines state that Dispose does not have to be thread-safe. The reason is because code should call Dispose only if the code knows for a fact that no other thread is using the object.
