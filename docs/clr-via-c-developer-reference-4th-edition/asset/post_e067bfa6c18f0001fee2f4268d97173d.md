Normally, because arrays are reference types, an array field defined in a structure is really just a pointer or reference to an array; the array itself lives outside of the structure’s memory. To embed an array directly inside a structure, there are several requirements:

- The field or its defining structure must be marked with the unsafe keyword.
- The array field must be marked with the fixed keyword.
- The array must be single-dimensional and zero-based.
- The array's element type must be one of the following types: Boolean, Char, SByte, Byte, Int16, UInt16, Int32, UInt32, Int64, UInt64, Single, or Double.

In this chapter, I talk about callback functions. Callback functions are an extremely useful mechanism that has been around for years. The Microsoft .NET framework exposes a callback mechanism by using delegates. Unlike callback mechanisms used in other platforms, as unmanaged C++, delegates offer more functionality. For example, delegates ensure that the callback method is type-safe, in keeping with one of the most important goals of the common language runtime (CLR). Delegates also integrate the ability to call multiple methods sequentially and support the calling of static methods as well as instance methods.

# A First Look at Delegates

The runtime's qsort function takes a pointer to a callback function to sort elements within an array. In Windows, callback functions are required for window procedures, hook procedures, asynchronous procedure calls, and more. In the .NET Framework, callback methods are used for whole slew of threads. For example, you can register callback methods to a variety of notifications such as unhandled exceptions, window state changes, menu item selections, file system changes, control events, and completed asynchronous operations.

In unmanaged C/C++, the address of a non-member function is just a memory address. This address does not carry any additional information such as the number of parameters the function expects, the types of these parameters, the function's return value, and the function's calling convention. In short, unmanaged C/C++ callback functions are not type-safe (although they are a very lightweight mechanism).

In the .NET Framework, callback functions are as useful and pervasive as in unmanaged Windows programming. However, the .NET Framework provides a type-safe mechanism called delegates.
