
## Canceling Task

Of course, you can use a CancellationTokenSource to cancel a Task. First, we must revise our Sum method so that it accepts a CancellationToken.

```csharp
private static Int32 Sum(CancellationToken ct, Int32 n) {
    Int32 sum = 0;
    for (; n = 0; n < n; n--) {
        // The following line throws OperationCanceledException when Cancel
        // is called on the CancellationTokenSource referred to by the token
        ct.ThrowIfCancellationRequested();

        checked { sum += n }; // if n is large, this will throw System.OverflowException
    }
    return sum;
}
```

In this code, the compute-bound operation's loop periodically checks to see if the operation is canceled by calling Cancellation.ThrowIfCancellationRequested. This method is similar to Task.IsCancellationRequested property shown earlier in the 'Cooperative Cancellation and Timeout' section. However, ThrowIfCancellationRequested throws an OperationCanceledException if the TokenSource has been canceled. The reason for throwing an exception is, unlike work items initiated with ThreadPool.UserWorkItem, tasks have the notion of having completed and a task can return a value. So, there needs to be a way to distinguish a completed task from a canceled task, and having the task exception lets you know that the task did not run all the way to completion.

Now, we will create the CancellationSource and Task objects as follows.

```csharp
CancellationSource cts = new CancellationSource();
Task<Int32> t = Task.Run(() => Sum(cts.Token, 1000000000), cts.Token);
```

```csharp
// Some time later, cancel the CancellationSource to cancel the Task
cts.Cancel(); // This is an asynchronous request, the Task may have completed already

try {
    // If the task got canceled, Result will throw an AggregateException
    Console.WriteLine("The sum is: " + t.Result); // An Int32 result
} catch (AggregateException x) {
    // Consider any OperationCanceledException objects as handled.
    // Any other exceptions cause a new AggregateException containing
    // only the unhandled exceptions to be thrown
    x.Handle(e => e is OperationCanceledException);
}

// If all the exceptions were handled, the following executes
Console.WriteLine("Sum was canceled");
```

When creating a Task, you can associate a CancellationToken by passing it to Task's constructor (as shown in the preceding code). If the CancellationToken gets canceled before the Task is scheduled, the Task gets canceled and never executes at all. But if the Task has already been scheduled (by calling the Start method), the Task's code must explicitly support cancellation if its operation to be canceled while executing. Unfortunately, while a Task object has a CancellationToken associated with it, there is no way to access it, so you must get the same CancellationToken that was used to create the Task object into the Task's code itself. The easiest way to use this is by lambda expression and "pass" the CancellationToken as a closure variable (as I've done in the previous example).

## Starting a New Task Automatically When Another Task Completes

In order to write scalable software, you must not have thread blocks. This means that Wait or querying a Task's Result when the task has not finished running will most likely cause the thread pool to create a new thread, which increases resource usage and hurts performance. Frankly, there is a better way to find out when a task has completed. When a task completes, you can start another task. This is a rewrite of the code that does not block any threads.

```csharp
// Create and start a Task, continue with another task
Task<Int32> t = Task.Run(() => Sum(CancellationToken.Token, 10000));
```

```csharp
// ContinueWith returns a Task but you don't care
Task cwt = t.ContinueWith(task => Console.WriteLine("The sum is: " + task.Result));
```

Now, when the ContinueWith starts executing tasks, this task will start another task (on some thread pool) that displays the result. The thread that executes the code does not block waiting for either of these two tasks to complete; the thread is allowed to execute other code, or if it is a thread pool thread it can return to the pool to perform other operations. Note that the task executing Sum could complete before ContinueWith is called. This will not be a problem because the ContinueWith method will see that the Sum is complete and it will immediately start the task that displays the result.

Also, note that ContinueWith returns a reference to a Task object (which my code placed in the cwt variable). Of course, you can invoke various members (Wait, Result, or ContinueWith) using this Task object, but usually you ignore this Task object and not save a reference to it in a variable.

I should also mention that Task objects internally contain a collection of ContinueWith. So you can actually call ContinueWith several times using a single Task object. When the task completes, all the ContinueWith tasks will be queued to the thread pool. In addition, when calling ContinueWith, you can specify a bitwise OR of TaskContinuationOptions.
