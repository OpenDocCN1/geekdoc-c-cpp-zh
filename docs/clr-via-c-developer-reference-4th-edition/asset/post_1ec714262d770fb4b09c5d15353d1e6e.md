
```csharp
using System;

public static class Program {
    public static void Main() {
        String s = new String("Hi there."); // <-- Error
        Console.WriteLine(s);
    }
}
```

Instead, you must use the following simplified syntax.

using System;

```csharp
public static class Program {
    public static void Main() {
        String s = "HI there.";
        Console.WriteLine(s);
    }
}
```

If you compile this code and examine it (using ILDasm.exe), you'd see the following:

```
.method hide static void Main() cil managed {
    .entrypoint
    // Code size 13 (0xd)
    .maxstack 1
    .locals ([0] string s)
    IL_0000: ldstr "Hi there."
    IL_0005: stloc.0
    IL_0006: call void [mscorlib]System.Console::WriteLine(string)
    IL_0007: ret
} // end of method Program::Main
```

The newobj IL instruction constructs a new instance of an object. However, no newobj instruction appears in the IL code example. Instead, you see the special ldstr (load string) IL instruction, which constructs a String object by using a literal string obtained from metadata. This shows you that the common language runtime does, in fact, have a special way of constructing String objects.

If you are using unsafe code, you can construct a String object from a Char* or Byte*. To accomplish this, you would use C# new operator and one of the constructors provided by the String type that takes Char* or Byte* parameters. These constructors create a String object, initializing the string from an array of Char instances or other constructors don't have any pointer parameters and can be called using safe (verifiable) code written in any managed programming language.

C# offers some special syntax to help you enter literals into the source code. For special characters such as new lines, carriage returns, and backspaces, C# uses the escape mechanism to C/C++ developers.

```csharp
// String containing carriage-return and newline characters
String s = "Hi\r\nthere."
```

> Important Although the preceding example hard-codes carriage-return and newline characters in the string, I don't recommend this practice. Instead, the System.Environment type defines a read-only NewLine property that returns a string consisting of these when your application is running on Windows. However, the NewLine property is platform-sensitive, and it returns the appropriate string required to obtain a newline by the underlying platform. So, for example, if the Common Language Infrastructure (CLI) is ported to a UNIX system, the New property would return a string consisting of just a single character \n. Here's the proper way to define the prefix string so that it works correctly on any platform.

```csharp
String s = "Hi" + Environment.NewLine + "there";
```

You can concatenate strings to form a single string by C#'s + operator as follows.

```csharp
// Three literal strings concatenated to form a single literal
String s = "Hi" + "" + "there";
```

In this code, all of the strings are literals, the C# compiler concatenates them at compile time and ends up placing just one—"Hi there." in the module's metadata. Using the + operator on literal strings causes the concatenation to be performed at runtime. To concatenate strings together at runtime, avoid using the + operator because it creates multiple string objects on a garbage-collected heap. Instead, use the System.Text.StringBuilder (which I'll explain later in this chapter).

Finally, C# offers a special way to declare a string in which all characters between quotes are considered part of the string. These special declarations are called verbatim strings and are typically used when specifying the path of a file or directory or working with regular expressions. Here is some code showing how to declare the same string with and without the verbatim character (@).

```csharp
// Specifying the pathname of an application
String file = "C:\Windows\System32\Notepad.exe";
```

```csharp
// Specifying the pathname of an application by using a verbatim string
String file = @"C:\Windows\System32\Notepad.exe";
```

You could use either of the preceding code lines in a program because they produce identical strings in the assembly's metadata. However, the @ symbol before the string on the second line tells the compiler that the string is a verbatim string. In effect, this tells the compiler to treat backslash characters as backslash characters instead of escape characters, making the path much more readable in your source code.

Now that you've seen how to construct a string, let's talk about the operations you can perform on String objects.

# Strings Are Immutable

The most important thing to know about a String is that it is immutable. That is, once created, a string can never get longer, shorter, or have any of its characters changed. Having mutable strings offers several benefits. First, it allows you to perform operations on a string without actually changing the string.

```csharp
if (s.ToUpperInvariant().Substring(10, 21).EndWith("EXE"))
  {}
```

ToUpperInvariant returns a new string; Substring operates on the string returned by ToUpperInvariant and returns a new string, which is examined by EndWith. The two temporary strings created by ToUpperInvariant and Substring are not referenced for long by the application code, the garbage collector will reclaim their memory at the next collection. If you perform a lot of string manipulations, you are creating a lot of String objects on the heap, which causes more frequent garbage collections, hurting your application's performance.

Having immutable strings also means that there are no thread synchronization issues when manipulating or accessing a string. In addition, it is possible for the CLR to share identical String contents through a single String object. This can reduce the number of strings in the system—conserving memory usage—and it is what string interning (discussed later in the chapter) is all.

For performance reasons, the String type is tightly integrated with the CLR. The CLR knows the exact layout of the fields defined within the String type, and the CLR accesses these fields directly. This performance and direct access come at a small development cost: String class is sealed, which means you cannot use it as a base class for your own type. If you were able to define your own type, using String as a base, you could add your fields, which would break the CLR's assumptions. In addition, you could break some assumptions that the CLR team have made about String objects being immutable.

# Comparing Strings

Comparing is probably the most common operation performed on strings. There are two reasons to compare two strings with each other. We compare strings to determine equality or sort them (usually for presentation to a user).

In determining string equality or comparing strings for sorting, it is highly recommended that you call one of these methods (defined by the String class).

When sorting, you should always perform case-sensitive comparisons. The reason is that if two strings differ only by case are considered, they would be ordered differently each time you sort them; which would confuse the user.

The comparisonType argument (in most of the methods) is one of the values defined by the StringComparison enumerated type, which is defined as follows.

```csharp
public enum StringComparison {
InvariantCulture = 0,
InvariantCultureIgnoreCase = 1,
InvariantCulture = 2,
InvariantCultureIgnoreCase = 3,
Ordinal = 4,
OrdinalIgnoreCase = 5
}
```

The options argument (in two of the methods) is one of the values defined by the CompareOptions enumerator type.

```csharp
[Flags]
public enum CompareOptions {
None = 0,
IgnoreCase = 1,
IgnoreNonSpace = 2,
IgnoreSymbols = 4,
IgnoreAlphaType = 8,
IgnoreCaseWidth = 0x00000010,
Ordinal = 0x40000000,
OrdinalIgnoreCase = 0x10000000,
StringSort = 0x02000000
}
```

Methods that accept a CompareOptions argument also force you to explicitly pass in a culture. When passing in the Ordinal or OrdinalIgnoreCase flag, these Compare ignore the specified culture.
