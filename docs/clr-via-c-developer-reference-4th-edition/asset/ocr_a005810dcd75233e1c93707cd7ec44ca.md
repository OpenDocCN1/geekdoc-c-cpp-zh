Now that you know how to apply a custom attribute, let's find out what attribute really is. A custom attribute is simply an instance of a type. For Common Language Specification (CLS) compliance, custom attribute classes must be defined, directly or indirectly, from the public abstract System.Attribute class. C# allows CLS-compliant attributes. By examining the .NET Framework documentation, you'll see that the following classes (from the earlier example) are defined: LayoutAttribute, MarshalAsAttribute, DllImportAttribute. All of these classes have to be defined in the System.InteropNamespace, but attribute classes can be defined in any namespace. Upon examination, you'll notice that all of these classes are derived from System.Attribute, as all CLS-compliant attributes must be.

**When** applying an attribute to a target in source code, the C# compiler allows you to omit the Attribute suffix to reduce programming typing and improve the readability of your code. My code examples in this chapter take advantage of this C# convenience. For example, my source code contains [DllImport(...)] instead of [DllImportAttribute(...)].

As mentioned earlier, an attribute is an instance of a class. The class must have a public constructor so that when you apply an attribute the syntax is similar to calling one of the class's constructors. In addition, a language might permit some syntax to set any public fields or properties associated with the attribute. Let's look at an example. The recall of the DllImport attribute as it was applied to the GetVersionEx method.

```
DllImport("kernel32", CharSet = CharSet.Auto, SetLastError = true)

```

The syntax of this line looks pretty strange because you could never use syntax like this when calling. If you examine the DllImportAttribute class in the documentation, you'll see that its constructor requires a single String parameter. In this example, "Kernel32" is being passed as this parameter. A constructor's parameters are *positional parameters* and are mandatory; the parameter must be specified when the attribute is applied.

What are the other two "parameters?" This special syntax allows you to set any public fields or properties of the DllImportAttribute object after the object is constructed. In example, when the DllImportAttribute object is constructed and "Kernel32" is passed to the constructor, the object's public instance fields, CharSet and SetLastError are set to CharSet.Auto and true, respectively. The "parameters" that set fields or properties are called *named parameters* and are optional the parameters don't have to be specified when you're applying an instance of the attribute. A bit later on, I'll explain what causes an instance of the DllImportAttribute class to be constructed.
