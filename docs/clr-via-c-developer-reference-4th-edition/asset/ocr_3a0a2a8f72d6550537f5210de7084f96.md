An ObjectHandle is a type that allows an object created in one AppDomain to be passed
round to other AppDomains without forcing the object to materialize. When you're ready
to materialize the object, you call ObjectHandle's Unwrap method. This method loads the
assembly that defines the type being materialized in the AppDomain where it is created.
If the object is being marshaled by reference, the proxy type and object are created.

+   **System.Activator.CreateInstance methods** The Activator class also offers
of set static CreateInstance methods. These methods behave just as the Create-
Instance method, except that you must always specify the type and its assembly via
parameters. The assembly is loaded into the calling AppDomain by using Assembly's Load-
From method (instead of Load). Because none of these methods take a Type parameter, all
of the CreateInstanceFrom methods return a reference to an ObjectHandle, which must
be unwwrapped.

+   **System.AppDomain.methods** The AppDomain offers four instance methods (each
with several overloads) that construct an instance of a type: CreateInstance, Create-
InstanceAndUnwrap, CreateInstanceFrom, and CreateInstanceFromAndUnwrap.
These works just as Activator's methods except that these methods are instance
methods, allowing you to specify which AppDomain the object should be constructed in.
The methods that end with Unwrap for convenience so that you don't have to make
an additional method call.

+   **System.Reflection.ConstructorInfo Invoke instance method** Using a reference
to a Type object, you can bind to a particular constructor and obtain a reference to the
constructor's ConstructorInfo object. Then you can use the reference to the Constructor-
Info to call its Invoke method. The type is always created in the calling AppDomain,\and a reference to the new object is returned. I'll also discuss this method in more detail later in
this chapter.

> Note The CLR doesn't require value types define any constructors. However, this
is a problem because all of the mechanisms in the preceding list construct an object by
calling its constructor. However, Activator's CreateInstance methods will allow
to create an instance of a value type without calling a constructor. If you want to create
an instance of a value type without calling a constructor, you must call the version of the
CreateInstance method that takes a single Type parameter or the version that takes
 and Boolean parameters.
