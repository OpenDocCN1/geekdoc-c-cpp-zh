# How Namespaces and Assemblies Relate

Be aware that a namespace and an assembly (the file that implements a type) aren’t necessarily related. In particular, the various types belonging to a single namespace might be implemented in multiple assemblies. For example, the System.IO.FileStream type is implemented in the MSCLib.dll assembly, and the System.IO.FileSystemWatcher type is implemented in the System.dll assembly.

A single assembly can contain types of namespaces. For example, the System.Int32 and System.Text.StringBuilder types are both in the MSCLib.dll assembly.

When you look up in the .NET Framework SDK documentation, the documentation will clearly indicate the namespace that the type belongs to and also the assembly that the type is implemented in. In Figure 4-1, you can see right (above the Syntax section) that the ResXFileRef type is part of the System.Resources and that the type is implemented in the System.Windows.dll assembly. To compile code that references the ResXFileRef type, you’d add a System.Resources; directive to your source code, /r:System.Windows.dll compiler switch.
