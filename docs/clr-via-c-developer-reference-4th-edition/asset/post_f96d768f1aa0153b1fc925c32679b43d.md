## Nullable Value Types

- C#'s Null-Coalescing Operator .............. 446
- The CLR Has Special Support for Nullable Value Types...... 447

As you know, a variable of a value type can be null; it always contains the value type's value itself. In fact, this is why we call these value types. Unfortunately, there are some scenarios in which this is a problem. For example, when designing a database, it is possible to define a column's data type to be a 32-bit integer that would map to the Int32 data type of the Framework Class Library (FCL). But a column in a database can indicate that the value is nullable. Then it is OK to have no value in the row's column. Working with database using the Microsoft .NET Framework can be quite difficult because in the common language runtime (CLR), there is no way to represent an Int32 value as null.

> Note: Microsoft ADO.NET table adapters do support nullable types. Unfortunately, the types in the System.Data.SqlTypes namespace are not replaced by nullable types, partially because there isn't a one-to-one correspondence between types. For example, the SqlDecimal type has a maximum of 38 digits, whereas the regular Decimal type can reach only 29. In addition, the SqlString type supports its own locale and compare options, which are not supported by the normal String type.

Here is another example. In Java, the java.util.Date class is a reference type, and therefore, a variable of this type can be set to null. However, in the CLR, a System.DateTime is a value type, and a DateTime variable can never be null. If an application written in Java wants to communicate a date/time to a web service running the CLR, there is a problem if the Java application sends null because the CLR has no way to represent this and operate on it.

To improve this situation, Microsoft added the concept of nullable value types to the CLR. To understand how they work, we first need to look at the System.Nullable<T> structure, which is defined in the FCL.

Here is logicalLayout representation of how the System.Nullable<T> is defined.

```csharp
[Serializable, StructLayout(LayoutKind.Sequential)]
public struct Nullable<T> where T : struct {

    // 2 fields represent the state
    private Boolean hasValue = false; // Assume null
    internal T value = default(T); // Assume all bits zero

    public Nullable(T value) {
        this.value = value;
        this.hasValue = true;
    }
}
```

```csharp
public Boolean HasValue { get { return hasValue; } }
```

```csharp
public T Value() {
    if (!hasValue) {
        throw new InvalidOperationException(
            "Nullable object must have a value.");
    }
    return value;
}
```

```csharp
public T GetValueOrDefault() { return value; }
```

```csharp
public T GetValueOrDefault(T defaultValue) {
    if (HasValue) return defaultValue;
    return value;
}
```

```csharp
public override Boolean Equals(Object other) {
    if (HasValue) return other != null; // Note: original likely had an error here, corrected logic
    if (other == null) return false;
    return value.Equals(other);
}
```

```csharp
public override int GetHashCode() {
    if (!hasValue) return 0;
    return value.GetHashCode();
}
```

```csharp
public override string ToString() {
    if (!hasValue) return "";
    return value.ToString();
}
```

```csharp
public static implicit operator Nullable<T>(T value) {
    return new Nullable<T>(value);
}
```

```csharp
public static explicit operator T(Nullable<T> value) {
    return value.value;
}
```

As you can see, this encapsulates the notion of a value type that can also be null. Nullable<T> is itself a value type, instances of it are still fairly lightweight. Instances can still be on the stack, and an instance is the same size as the original value type plus the size of a Boolean field. Note that Nullable<T>'s type parameter, T, is constrained to struct. This was done because reference type variables can already be null.

So, if you want to use a nullable Int32 in your code, you can write something like this.

```csharp
Nullable<Int32> x = 5;
Nullable<Int32> y = null;
Console.WriteLine("x: HasValue={0}, Value={1}", x.HasValue, x.Value);
Console.WriteLine("y: HasValue={0}, Value={1}", y.HasValue, y.GetValueOrDefault());
```

When I run this code, you get the following output:

- x: HasValue=True, Value=5
- y: HasValue=False, Value=0

## C#'s Support for Nullable Value Types

Notice in the code that C# allows you to easily use simple syntax to initialize the two Nullable<Int32> variables, x and y. In fact, the C# team wants to integrate nullable value types into the C language, making them first-class citizens. To that end, C# offers a cleaner syntax for working with nullable value types. C# allows the code to declare and initialize the x and y variables to be written using question mark.

```csharp
Int32? x = 5;
Int32? y = null;
```

In C#, Int32? is a synonym notation for Nullable<Int32>. But C# allows you to perform conversions and casts on nullable instances. And C# also supports applying operators to nullable instances. The following code shows examples of these:

```csharp
private static void ConversionsAndCasting() {
  // Implicit conversion from non-nullable Int32 to Nullable<Int32>
  Int32? a = 5;

  // Implicit conversion from 'null' to Nullable<Int32>
  Int32? b = null; // Same as Int32? b = new Int32(); which sets HasValue to false

  // Explicit conversion from Nullable<Int32> to non-nullable Int32
  Int32 c = (Int32) a;

  // Casting between nullable primitive types
  Double d = 5; // Int32->Double? (d is 5.0 as a double)
  Double e = b; // Int32?->Double? (e is null)
}
```

C# also allows you to apply operators to nullable instances. The following code shows examples of this.

```csharp
private static void Operators() {
    Int32 a = 5;
    Int32 b = null;

    // Unary operators (+ + -- ! ~)
    a++; // a = 6
    b = -b; // b = null

    // Binary operators (* / % & ^ << >>)
    a = a * 3; // a = 9
    b = b * 3; // b = null;

    // Equality operators (== !=)
    if (a == null) { /* no / */ } else { /* yes / */ }
    if (b == null) { /* yes / */ } else { /* no / */ }
    if (a == b) { /* yes / */ } else { /* no / */ }

    // Comparison operators (< <= >=)
    if (a < b) { /* no / */ } else { /* yes / */ }
}
```

Here is how C# interprets the operators:

- **Unary operators (+, -, !, ~)**: If either operand is null, the result is null.
- **Binary operators (*, /, %, &, ^, <<, >>)**: If either operand is null, the result is null.
- **Equality operators (==, !=)**: If both operands are null, they are equal.
- **Comparison operators (<, <=, >=)**: If either operand is null, the result is false.
