Because the CL automatically calls a type's constructor the first time attempts to access a member of the class, the first time a thread queries Singleton's GetSingleton method, the CLR will automatically call the class constructor, which creates an instance of object. Furthermore, the CLR ensures that calls to a constructor are thread safe. I explained all of this in Chapter 8. The one downside of this approach is that the type constructor is called when any member of a class is first accessed. If the Singleton type defined other static members, the Singleton object would be created when any one of them was accessed. Some people work around this by defining nested classes.
