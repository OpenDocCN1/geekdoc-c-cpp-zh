To make matters worse, when I look at the CPU Usage, it shows that my CPU is 5 percent of the time. This means 95 percent of the time, these 864 threads have literally nothing to do—they are just soaking up memory that is definitely not being used when the threads are not running. Do you have to ask yourself? Do these applications need all these threads to 95 percent of the time? The answer to this question is to “No.” Now, if you want to see which processes are the most wasteful, click the Task Manager’s Details tab, and add the Threads column, and sort this in descending order, as shown in Figure 26-2.2

As you can see, System has created 105 threads and is using 1 percent of the CPU, Explorer has created 47 threads to use 0 percent of the CPU, Visual Studio (Devvenexe) has created 36 threads to use 0 percent of the CPU, Microsoft Outlook has created 24 threads to use 0 percent of the CPU, and so on. What is going on here?

When developers were learning about Windows, they learned that a process usually takes several seconds, a lot of memory must be allocated, this memory must be initialized, the EXE and DLL files have to load from disk, and so on. By comparison, creating a thread in Windows is very cheap, so developers decide to stop creating processes and start creating threads instead Now we have lots of threads. Even though threads are cheaper than processes, they are still very expensive compared to most system resources, so they should be used sparingly and appropriately.
