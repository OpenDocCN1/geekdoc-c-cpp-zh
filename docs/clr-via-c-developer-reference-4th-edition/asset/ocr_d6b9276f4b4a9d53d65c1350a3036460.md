The following list summarizes the steps discussed in this section to develop assembly by using the delayed signing technique:

+   1. While developing an assembly, obtain a file that contains only your company's public key, and compile your assembly using the /keyfile and /delay compiler switches.

```
csc /keyfile:MyCompany.PublicKey /delays MyAssembly.cs
```

+   2. After building the assembly, execute the following line so that the CLR will trust the assembly's bytes by performing the hash and comparison. This allows you to install the assembly in the GAC (if you desire). Now, you can build other assemblies that reference the assembly, and you can test the assembly. Note that you have to execute the command line once per machine; it's not necessary to perform this step each time you build your assembly.

```
SN.exe -Vr MyAssembly.dll
```

+   3. When ready to package and deploy the assembly, obtain your company's private key, and execute the following line. You can install this new version in the GAC if you desire, don't attempt to install it in the GAC when executing step 4.

```
SN.exe -Ra MyAssembly.dll MyCompany.PrivateKey
```

+   4. To test in conditions, turn verification back by executing the following command line.

```
SN.exe -U MyAssembly.dll
```

At the beginning of this section, I mentioned how organizations generally keep their keys in a hardware device such as a smart card. To keep these keys, you must make sure that the keys are never persisted in a disk file. Cryptographic service providers (CSPs) offer containers that abstract the location of these keys. Microsoft, for example, uses a CSP that has container, when accessed, obtains the private key from a hardware device.

If public/private key is in a CSP, you'll need to specify different switches to the CSC.exe, ALEx, and SN.exe. When compiling (CSC.exe), specify the /keycontainer switch instead of its /keyfile switch; when linking (ALEx), specify its /keyswitch switch and when using the Strong Name program (SN.exe) to add a private key to a delayed-signed assembly, specify the -Rc switch of the -R switch. SN.exe offers additional switches that allow you to perform operations with a CSP.

> Important Delayed signing is also useful whenever you want to perform some other operation to an assembly before you package it. For example, you may want to run an obfuscator over your assembly. You can't obfuscate an assembly after it's fully signed because the hash value will be incorrect. So, if you want to obfuscate an assembly file or perform any other type of post-build operation, you should use delayed signing, perform the post-build operation, and then run SN.exe with the -R or -Rc switch to complete the signing process of the assembly with all of its hashing.
