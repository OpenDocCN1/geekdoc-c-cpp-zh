The following code demonstrates the difference between foreground and background threads.

using System;
using System.Threading;

```
public static class Program {
    public static void Main() {
        // Create a new thread (defaults to foreground)
        Thread t = new Thread(Worker);

        // Make the thread a background thread
        t.IsBackground = true;

        t.Start(); // Start the thread
        // If it is a foreground thread, the application won't die for about 10 seconds
        // If it is a background thread, the application dies immediately
        Console.WriteLine("Returning from Main");
    }

    private static void Worker() {
        Thread.Sleep(10000); // Simulate 10 seconds of work

        // The following line only gets displayed if this code is executed by a foreground thread
        Console.WriteLine("Returning from Worker");
    }
```

It is possible to change a thread from foreground and vice versa at any time during its lifetime. An application's primary thread and any threads explicitly created by constructing a Thread object default to being foreground threads. On the other hand, thread pools default to being background threads. Also, any threads created by native code that manage the execution are marked as background.

> Important Try to avoid using foreground threads as much as possible. I was brought into a consulting job once when an application wouldn't terminate. After I spent several hours researching the problem, it turned out that a UI component was explicitly creating a foreground thread (the default), and that was why the process wouldn't terminate. I changed the component to use the thread pool to fix the problem, and efficiency improved as well.

# What Now?

In this chapter, I've explained the basics about threads, and I hope I've made it clear to you that threads are very expensive resources that should be used sparingly. The best way to accomplish this is by using the thread pool. The thread pool will manage thread creation and destruction for you automatically. The thread pool creates a set of threads that get reused for various tasks so your application requires just a few threads to accomplish all of its work.
