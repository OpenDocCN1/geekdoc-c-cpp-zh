
your type can implement the System.Runtime.Serialization.ISerializable interface, which is defined as follows.

```
public interface ISerializable {
    void GetObjectData(SerializationInfo info, StreamingContext context);
}
```

This interface has just one method in it, GetObjectData. Most types that this interface will also implement a special constructor that I'll describe.

> **Important** The big problem with the ISerializable interface is that after a type implements it, all derived types must implement it too, and the derived types must make sure that they invoke the base class's GetObjectData method and the special constructor. In addition, after a type implements this interface, it can never remove it because it will lose compatibility with the derived types. It is always OK for sealed types to implement the ISerializable interface. Using the custom attributes described earlier in this chapter avoids of the potential problems associated with the ISerializable interface.

> **Important** The ISerializable interface and the special constructor are intended to be used by the formatters. However, other code could GetObjectData, which might then return sensitive information, or other code could construct an object that passes in corrupt data. For this reason, it is recommended that you apply the following attribute to the GetObjectData method and the special constructor:

[SecurityPermissionAttribute(SecurityAction.Action, SerializationFormatter = true)]

When a formatter serializes an object graph, it looks at each object. If it implements the ISerializable interface, then the formatter ignores all custom attributes and instead constructs a new System.Runtime.Serialization.SerializationInfo object. This object contains the actual set of values that should be serialized for the object.

When constructing a SerializationInfo, the formatter passes two parameters: Type and System.Runtime.Serialization.IFormatter. The Type identifies the object that is serialized. Two pieces of information are required to uniquely identify a type: the string name of the type and its assembly identity (which includes the assembly name, version, culture, and public). When SerializationInfo object is constructed, it obtains the type's full name (by internally querying Type's FullName property) and stores this string in a private field. You can obtain the type's full name by querying SerializationInfo's FullName property. Likewise, the constructor obtains the type's defining assembly (by querying Type's Module property by querying Assembly property followed by querying Assembly's FullName property) and stores this in a private field. You can obtain the assembly's identity by querying SerializationInfo's AssemblyName property.

The SerializationInfo object is constructed and initialized, the formatter calls the type's GetDataObject method, passing the reference to the SerializationInfo object. The GetDataObject method is responsible for determining what information is necessary to serialize the object and adding this information to the SerializationInfo object. GetObjectData indicates what information to serialize by calling one of the many overloaded methods provided by the SerializationInfo type. AddValue is called once for each piece of data you want to add.

The following code shows an approximation of how the Dictionary<TKey, TValue> type implements the ISerializable and IDerializationCallback interfaces to control the serialization and deserialization of its objects.

```
[Serializable]
public class Dictionary<TKey, TValue> : ISerializable, IDerializationCallback {
 // Private fields (not shown)

private SerializationInfo m_siInfo; // Only used for deserialization

 // Special constructor (required by ISerializable) to control deserialization
[SecurityPermissionAttribute(SecurityAction.Demand, Serialization, SerializationFormatter = true)]
protected Dictionary(SerializationInfo info, StreamingContext context) {
 // During deserialization, save the SerializationInfo for OnDeserialization
 m_siInfo = info;
}

 // Method to control serialization
[SecurityCritical]

info.AddValue("Comparer", m_comparer, typeof(IComparer<TKey>));
info.AddValue("HashSize", (m_buckets == null) ? 0 : m_buckets.Length);
```

Each AddValue method takes a String name and some data. Usually, the data is of a simple value like Boolean, Char, Byte, SByte, Int16, UInt16, Int32, UInt64, Double, Decimal, or DateTime. However, you can also call AddValue, passing a reference to an Object as a String. After GetDataObject has added all of the necessary serialization information, it returns to the formatter.

> Note You should always call one of the overloaded AddValue methods to serialize information for your type. If a field implements the ISerializable interface, don't call the GetDataObject on the field. Instead, call AddValue to the field; the formatter will see that the field implements ISerializable and the formatter will call GetDataObject for you. If you were to call GetDataObject on the field object, the formatter wouldn't need to create a new object when deserializing the stream.

The formatter now takes all the values added to the SerializationInfo object and serializes each of them out to the stream. You'll notice that the GetDataObject method passed another parameter: a reference to a System.Runtime.Serialization.StreamingContext object. Most types' GetObject methods completely ignore this parameter, so I will not discuss it here. Instead, I'll discuss it in the "StreamingContext" section later.

So now you know all of the information used for serialization. At this point, let's turn our attention to deserialization. The formatter extracts all from the stream, it allocates memory for the new object (by calling the System.Runtime.Serialization.Formatter type's static GetUninitializedObject). Initially, all of this object's fields are set to 0 or null. Then, the formatter checks if the type implements the ISerializable interface. If this interface exists, the formatter attempts to call a special constructor whose parameters are identical to that of the Getter.

If your class is sealed, it is highly recommended that you declare this special constructor to be private. This will prevent any code from accidentally calling security. If not, then you should declare this special constructor as protected so that only derived classes can call it. Note that the formatters are able to call this special constructor matter how it is declared.

This constructor receives a reference to a SerializationInfo object containing all the values added to when the object was serialized. The special constructor can call any of the GetBoolean, GetChar, GetByte, GetByteString, GetInt16, GetInt32, GetInt32, GetInt64, GetUInt64, GetString, GetDouble, GetDecimal, DateTime, String and GetValue methods, passing in a string corresponding to the name used to serialize a value. The value returned from each of these methods is then to initialize the fields of the new object.

When deserializing an object's fields, it will call the Get method that matches the type of value that was passed to the AddValue method when the object was serialized. In other words, if the GetDataObject method called AddValue, passing it an Int32 value, then the GetInt32 method should be called for the same value when deserializing the object. If the value in the stream doesn't match the type you're trying to get, the formatter will attempt to use an IFormatter-Convert object to "cast" the stream's value to the desired type.

As mentioned earlier, when a SerializationInfo object is constructed, it is passed an object whose type implements the IFormatterConverter interface. Because the formatter is responsible for constructing the SerializationInfo object, it chooses which IFormatterConverter type it wants. Microsoft.BinaryFormatter and SoapFormatter always construct an instance of the System.Runtime.Serialization.FormatterConverter type. Microsoft formatters don't offer any value for you to choose a different IFormatterConverter type.
