**Important** When developers start learning about weak references, they immediately start thinking that they are in caching scenarios. For example, they would think it would be cool to construct a bunch of objects that contain a lot of data and to create weak references to these objects. When the program needs data, the program checks the weak reference to see if the object contains the data is still around, and if it is, the program uses it; the program experiences high performance. However, if a garbage collection occurred, the objects that contained the data would be destroyed, and the program has to re-create the data, the program experiences lower performance.

The problem with this is following: garbage collections do not only occur when memory is full or close to full. Instead, garbage collections occur whenever generation is full. So objects are tossed out of memory more frequently than desired, and your application's performance suffers greatly.

Weak references can be used effectively in caching scenarios, but building a good cache algorithm that finds the right balance between memory consumption and speed is very complex. Basically, you want cache to keep strong references to all of your objects and then, when you see that memory is getting tight, turning strong references into weak references. The CLR offers no mechanism to notify an application that memory is getting tight. But some people have had success by calling the Win32 GlobalMemoryStatus function and returning the MEMORYSTATUS structure dwMemoryLoad member. If this member reports a value above 80, memory is getting tight, and you can start converting strings to weak references based on whether you use a least-recently used algorithm, a most-frequently used algorithm, or whatever.

Developers frequently want to associate a piece of data with another entity. For example, you can associate data with a thread or with an AppDomain. It is also possible to associate data with an individual object using the System.Runtime.CompilerServices.ConditionalWeakTable<TKey, TValue> class, which looks like this:

public sealed class ConditionalWeakTable<TKey, TValue>

        public TValue GetGetValue(TKey key);
        public TValue GetOrCreate(TKey key);
        public bool Remove(TKey key);
