When I execute Main, I get the following output.

```
M(Int32): 10
M(String): AA
```

To understand what's happening, let's start by looking at the C + operator. This operator has operands of the dynamic type. Because value is dynamic, the C# compiler emits code that can examine the actual type of value at run time and determine what the + operator should act upon.

The first time + operator evaluates, value contains 5 (an Int32) and the result is 10 (also an Int32). This puts this result in the value variable. Then, the Method is called, passing it. For the call to M, the compiler will emit payload code that, at run time, examine the actual type of the argument being passed to M and determine which overload of the method. When value contains an Int32, the overload of M takes an Int32 parameter is called.

The second time + operator evaluates, value contains "A" (a String) and the result is "AA" (the result of concatenating "A" with itself). Then, the Method is called, passing it value. This time, the payload code determines that the actual type being passed to M is a String and calls the overload of M that takes a String parameter.

When the type of a method, parameter, or return type is specified as dynamic, the compiler converts this to System.Runtime.CompilerServices.DynamicAttribute and applies an instance of to the field, parameter or return type metadata. If a local variable is specified as dynamic, then the variable's type will be of Object, but the DynamicAttribute is not applied to the local variable because its usage is self-contained within the method. Because dynamic is like the Object, you cannot write methods whose signature differs by dynamic and Object.

It is also possible to use dynamic when specifying generic type arguments to a generic class (reference type), a structure (value type), an interface, or a method. When you do this, the compiler converts dynamic to Object and applies DynamicAttribute to the various pieces of metadata where it makes sense. Note that the generic type you are using has already been compiled and will consider the type to be Object; no dynamic dispatch is performed because the compiler does not produce any payload code in the generic code.

Any expression can be dynamic because all expressions return a type that is derived from Object. Normally the compiler does not allow you to write code that implicitly casts an expression from Object to another type; you must use explicit cast syntax. However, the compiler allows you to cast an expression from dynamic to another type using implicit cast syntax.

```
Object o1 = 123; // OK: Implicit cast from Int32 to Object (boxing)
Int32 n1 = o1; // Error: No implicit cast from Object to Int32
Int32 n2 = (Int32) o1; // OK: Explicit cast from Object to Int32 (unboxing)
dynamic d1 = 123; // OK: Implicit cast from Int32 to dynamic (boxing)
dynamic n3 = d1; // OK: Implicit cast from dynamic to Int32 (unboxing)
```

> * And, as so, value types will be boxed.
