work is being performed on behalf of the original client request, the culture and identities to
‘flow’ to the new thread pool so any additional work done on behalf of the client is per-
formed using the client’s culture and identity information.

Fortunately, the FCL defines a base class, called System.Threading.SynchronizationContext,
which solves all these problems. Simply stated, a SynchronizationContext-derived object-nect an application model to its threading model. The FCL defines several classes derived from
SynchronizationContext, but usually you will not directly with these classes; in fact, many of
them are not publicly exposed or documented.

For the most part, application developers do not need to know anything about the Synchronroni-zContext class. When you await a Task, the calling thread’s SynchronizationContext
object is obtained. When a thread pool completes the Task, the SynchronizationContext
object is used, using the right threading model for your application model. So, when a GUI
avits a Task, the code following the await operator is guaranteed to execute on the GUI thread
well, allowing that code to update UI elements.12 For an ASP.NET application, the code following the
await operator is guaranteed to execute on a thread pool that has the client’s culture and
principal information associated with it.

Most of the time, having a state machine using the application model’s threading model is
phenally useful and convenient. But on some occasions, this can get you into trouble. Here is an
example that causes a WPF application to deadlock.

```
private sealed class MyWpfWindow : Window {
    public MyWpfWindow() { Title = "WPF Window"; }

    protected override void OnActivated(EventArgs e) {
        // Querying the Result property prevents the GUI thread from returning;
        // the thread blocks waiting for the result
        string http = GetHttp().Result; // Get the string synchronously!

        base.OnActivated(e);
    }

    private async Task<string> GetHttp() {
        // The HTTP request and let the thread return from GetHttp
        HttpResponse msg = await new HttpClient().GetAsync("http://Intellect.com/");
        // We never get the result: The GUI thread is waiting for this method to finish but this method
        // can't finish because the GUI thread is waiting for it to finish -- DEADLOCK!

        return await msg.Content.ReadAsStringAsync();
    }
}
```
