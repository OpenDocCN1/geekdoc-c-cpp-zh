Now that you know delegate objects are constructed and what their internal structure looks like, let's talk about how the callback method is invoked. For convenience, I've repeated the code for the Counter method here.

```
private static void Counter(Int32 from, Int32 to, Feedback fb) {
  for (Int32 val = from; val <= to; val++) {
    // If any callbacks are specified, call them
    if (fb != null)
      fb(val);
  }
}
```

At the line of code just below the comment. The if statement first checks if fb is not null. If fb is not null, on the next line, you see the code that invokes the callback method. The null1 check is required because fb is really a variable that can refer to a delegate object; it could also be null. It might seem as if I'm calling a function name fb and passing one parameter (val). However, there is no function called fb. Again, because it knows that fb is a variable that refers to a delegate object, the compiler generates code to call the delegate Invoke method. In other words, the compiler sees the following.

fb(val);

But the compiler generates code as the source code said the following.

fb.Invoke(val);

You can verify that the compiler produces code to call the delegate Invoke method by using ILDasm.exe to examine the Intermediate Language (IL) code created for the Counter method. Here is the IL for the Counter method. The instruction at IL_0099 in the figure indicates the call to Feedback's Invoke method.
