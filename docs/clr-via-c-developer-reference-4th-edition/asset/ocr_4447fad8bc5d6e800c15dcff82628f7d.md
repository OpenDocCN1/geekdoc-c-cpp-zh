What I'm about to describe is not specific to the CLR at all, but I'm going to describe so that we have a working foundation, and then I'll modify the discussion to incorporate CLR-specific information.

Figure 4-2 shows a single Windows process that has the CLR loaded into. In this process there may be many threads. When a thread is created, it is allocated a 1-MB stack. This space is used for passing arguments to a method and for local variables defined within a method. In Figure 4-2, the memory for one thread's stack is shown (on the right). Stacks build from high-memory addresses to low-memory addresses. In the figure, this thread has been executing some code, and its stack has some data on it already (shown as the shaded area at the top of the stack). Now, imagine that thread has executed some code that calls the M1 method.

All but the simplest methods contain some prologue code, which initializes a method before it can start doing its work. These methods also contain epilogue code, which cleans up a method after it has performed its work so that it can return to its caller. When the M1 method starts to execute, its prologue code allocates memory for the local variable from the thread's stack (see Figure 4-3).
