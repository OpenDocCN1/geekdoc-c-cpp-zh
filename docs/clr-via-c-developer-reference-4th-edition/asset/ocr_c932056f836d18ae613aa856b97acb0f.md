# C# Support for Volatile Fields

Making sure you use the Volatile.Read and Volatile.Write methods correctly
a to ask. It's hard for programmers to keep all of this in their minds and start imagining what
other threads might be doing in the background. To simplify this, the C# compiler
has the volatile keyword, which can be applied to static or instance fields of any of types:
Boolean, (S)Byte, (U)Int16, (U)Int32, IntPtr, or Char. You can also apply thenvolatile keyword to reference types and any enum field as long as the enumerated type has
underlying type of (S)Byte, (U)Int16, or (U)Int32. The JIT compiler ensures that all accesses a
vatile field are performed as volatile reads and writes, so that it is not necessary to explicitly call
Volatile's static Read or Write methods. Furthermore, the volatile keyword tells the C# and JIT
compiler not to cache the field in a CPU register, ensuring that all reads to and from the field actu-
 cause the value to be read from memory.

Using the volatile keyword, we can rewrite the ThreadsSharing class as follows.

```
internal sealed class ThreadsSharingData {
    private volatile Int32 m_flag = 0;
    private Int32 m_value = 0;

    // This method is executed by one thread
    public void Thread1() {
        // Note: m_value must be written before m_flag is 1 to m_flag
        m_value = 5;
        m_flag = 1;
    }

    // This method is executed by another thread
    public void Thread2() {
        // Note: m_value must be read after m_flag is read
        if (m_flag == 1)
            Console.WriteLine(m_value);
    }
}
```
