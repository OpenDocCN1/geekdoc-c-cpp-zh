
# Serialization Surrogates

Up to now, I've been discussing how to modify a type's implementation to control how a type serializes and deserializes instances of itself. However, the formatters allow code that is not part of the type's implementation to override how a type serializes and deserializes its objects. There are two reasons why application code might want to override a type's behavior:

- It allows a developer to serialize a type that was not originally designed to be serialized.
- It allows a developer to provide a way to map one version of a type to a different version of a type.

Basically, to make this mechanism work, you first define a "surrogate type" that takes over the actions required to serialize and deserialize an existing type. Then, you register an instance of your surrogate type with the formatter telling which existing type your surrogate is responsible for acting. When the formatter detects that it is serializing or deserialize an instance of the existing type, it will call methods on your surrogate object. Let's build a sample that demonstrates how all this works.

A serialization surrogate type must implement the System.Runtime.Serialization.ISerializationSurrogate interface, which is defined in the FCL as follows.

```c
public interface ISerializationSurrogate
    void GetObjectData(Object obj, SerializationInfo info, StreamingContext context);

    void SetObjectData(Object obj, SerializationInfo info, StreamingContext context, ISurrogateSelector selector);
```

Now, let's walk through an example that uses this interface. Let's say your program contains DateTime objects that are local to the user's computer. If you want to serialize the DateTime objects to a stream but want the values to be serialized in universal time? This would allow you to send the data over a network to stream to another machine in part of the world and have the DateTime value correct. Although you cannot modify the DateTime type that has the FCL, you can define your own surrogate class that can control how DateTime-objects are serialized and deserialized. Here is how to define the surrogate class.

```c
internal sealed class UniversalLocalSerializationSurrogate : ISerializationSurrogate
{
    public void GetObjectData(Object obj, SerializationInfo info, StreamingContext context)
    {
        // Convert the "Date" to UTC
        info.AddValue("Date", ((DateTime)obj).ToUniversalTime().ToString());
    }

    public void SetObjectData(Object obj, SerializationInfo info, StreamingContext context, ISurrogateSelector selector)
    {
        // Convert the DateTime from UTC to local
        return DateTime.ParseExact(info.GetString("Date"), "u", null).ToLocalTime();
    }
}
```

The GetObjectData method works just like the ISerializable interface's GetObjectData method. The only difference is that ISerializationSurrogate's GetDataObject method takes one additional parameter: a reference to the "real" object that is to be serialized. In the GetObjectData method above, this object is cast to DateTime, the value is converted from local time to universal time, and a string (formatted using universal date/time pattern) is added to the SerializationInfo collection.

The SetDataObject method is called in order to deserialize a DateTime object. When this is called, it is passed a reference to a SerializationInfo object. SetObjectData gets the string out of the collection, parses it as a full date/time formatted string, and then converts the resulting DateTime object from universal time to the machine's local time.

The Object that is passed for SetDataObject's first parameter is a bit string. Before just calling SetDataObject, the formatter (via Formatter's static GetUninitializedObject method) finds an instance of the type that the surrogate is. The instance's fields are all/null and no constructor has been called on the object. The code inside SetDataObject can simply initialize the fields of this instance using the values from the passed-in Serialization-Info object and then have return null. Alternatively, SetDataObject could create an entirely different object or even a different type of object and return a reference to this object, in which case the formatter ignores any changes that may or may not have happened the object passed in to SetDataObject.

In my example, myUniversalLocalSerializationSurrogate class acts as a surrogate for the DateTime type, which is a value type. And so, the obj parameter refers to a boxed instance of DateTime. There is no way to change the fields in most value types (because they are supposed to be immutable) and so, my SetDataObject method ignores the object and returns a new DateTime object with the desired value in it.

At this point, I'm sure you are wondering how the formatter knows to use this ISerializationSurrogate type when it tries to serialize/deserialize a DateTime object. The following code demonstrates how to use the UniversalLocalSerializationSurrogate class.

```c
private static void SerializationSurrogateDemo() {
    using (var stream = new MemoryStream()) {
        // 1. Construct the desired formatter
        IFormatter formatter = new SoapFormatter();

        // 2. Construct a SurrogateSelector object
        SurrogateSelector ss = new SurrogateSelector();

        // 3. Tell the surrogate selector to use our surrogate for DateTime objects
        ss.AddSurrogate(typeof(DateTime), formatter.Context, new UniversalLocalSerializationSurrogate());

        // NOTE: AddSurrogate can be called multiple times to register multiple surrogates

        // 4. Tell the formatter to use our surrogate selector
        formatter.SurrogateSelector = ss;
}
}
```

```c
// Create a DateTime that represents the local time on the machine & serialize it
TimeToBeforeSerialize = DateTime.Now;
formatter.Serialize(stream, localTimeBeforeSerialize);

// The stream displays the Universal time as a string to prove it worked
stream.Position = 0;
Console.WriteLine(new StreamReader(stream).ReadToEnd());

// Deserialize the Universal time string and convert it to a local DateTime
localTimeAfterDeserialize = (DateTime)formatter.Deserialize(stream);
```

```c
// Prove it worked correctly:
Console.WriteLine("LocalTimeBeforeSerialize={0}", localTimeBeforeSerialize);
Console.WriteLine("LocalTimeAfterDeserialize={0}", localTimeAfterDeserialize);
```

After steps 1 through 4 have executed, the formatter is ready to use the registered surrogate types. When the formatter's Serialize method is called, each object is looked up in the set maintained by the SurrogateSelector. If a match is found, the ISerializationSurrogate object's GetDataObject is called to get the information that should be written out to the stream.

When the formatter's Deserialize method is called, the type of the object to be deserialized is looked up in the formatter's SurrogateSelector and if a match is found, the ISerializationSurrogate object's SetDataObject is called to set the fields within the object being deserialized.

Internally, a SurrogateSelector maintains a private hash table. When AddSurrogate is called, the Type and StreamingContext make up the key and the ISerializationSurrogate object is the key value. If a key with the same Type/StreamingContext already exists, AddSurrogate throws an ArgumentException. By including StreamingContext in the key, you can register one surrogate type that knows how to serialize/deserialize a DateTime object to a file and register a different surrogate object that knows how to serialize/deserialize a DateTime object to a different process.

> The BinaryFormatter class has a bug that prevents a surrogate from serializing objects with references to each other. To fix this problem, you need to pass a reference to your ISerializationSurrogate object to FormServices' static GetSurrogateForCyclicalReference method. This method returns an ISerializationSurrogate object, which you can pass to the SurrogateSelector's AddSurrogateReference method, however, your surrogate's SetDataObject must modify the value inside the object referred to by SetDataObject obj the calling method. The downloadable code that accompanies this book shows how to modify the UniversalTimeToSerialization class and the SerializationSurrogateDemo method to support cyclical references.
