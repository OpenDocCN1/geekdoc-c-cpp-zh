Third, here is the code for a simple Host.exe assembly (a console application). To build this assembly, the HostSDK.dll assembly must be referenced. To discover usable add-in types, this host code assumes that the types are defined in assemblies ending with a .dll extension and that these assemblies are deployed into the same directory as the host's EXE file. Microsoft's Managed Extensibility Framework (MEF) is built on top of the various mechanisms that I show here, and it offers add-in registration and discovery mechanisms. I urge you to check MEF out if you are building a dynamically extensible application, because it can simplify some of the material in this chapter.

```
using System;
using System.IO;
using System.Reflection;
using System.Collections.Generic;
using Winintellect.HostSDK;
```

```
public static void Main() {
    // Find the directory that contains the Host exe
    String AddInDir = Path.GetDirectoryName(Assembly.GetEntryAssembly().Location);

    // Assume AddIn assemblies are in the same directory as host's EXE file
    var AddInAssemblies = Directory.EnumerateFiles(AddInDir, "*.dll");

    // Create a collection of Add-In types by using the host
    var AddInTypes =
        from file in AddInAssemblies
        let assembly = Assembly.Load(file)
        for t in assembly.ExportedTypes
        // Type is useful if it is a class that implements IAddIn
        where t.IsClass && typeof(IAddIn).GetInfo()...IsAssignableFrom(t.GetType())
}
```
