If you are trying to cast a reference type, you can also use the C# as operator. Here is code modified to use the operator as String (because Int32 is a value type).

```
private static void CastingGenericTypeVariable3<T>(T obj) {
  String s = obj as String; // No error
}
```

# Setting a Generic Variable to a Default Value

Setting a generic type variable to null is illegal unless the generic type is constrained to a reference type.

```
private static void SettingGenericTypeVariableToNull<T>() {
  T temp = null; // CS0403 - Cannot convert null to type 'T' because it could
  // be a non-nullable value type. Consider using default(T) instead
}
```

Because T is unconstrained, it could be a value type, and setting of a value type to null is not possible. If T were constrained to a reference type, setting to null would compile and run just fine.

Microsoft's C# team felt it would be useful to give developers the ability to set a variable to a default value. The C# compiler allows you to use the default keyword to accomplish this.

```
private static void SettingGenericTypeVariableOrDefault<T>() {
  T temp = default(T); // OK
}
```

The use of the default keyword tells the C# compiler and the CLR's JIT compiler to produce code to set temp to null if T is a reference type and to set all-bits-to zero if T is a value type.

# Comparing a Generic Variable with null

Comparing a generic type variable to null using the == or ! operator is legal regardless of whether the type is constrained.

```
private static void ComparingGenericTypeVariableNull<T>(T obj) {
  if (obj == null) { /* Never executes for a value type */ }
}
```

Because T is unconstrained, it could be a reference type or a value type. If T is a value type, obj can never be null. Normally, you'd expect the C# compiler to issue an error because of this. However, it compiles the code fine. When this method is called using an argument that is a value type, the JIT compiler sees that if the statement can never be true, the JIT will not emit the native code for the if test or the code in branches. If I had used the != operator, the JIT would not emit the code for the if test (because it is always true), and it will emit the code inside the if's braces.
