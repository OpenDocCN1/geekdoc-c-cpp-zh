
A dynamic expression is the same type as System.Object. The compiler assumes whatever operation you attempt on the expression is legal, so the compiler will not generate any warnings or errors. However, exceptions will be thrown at run time if you attempt to execute an invalid operation. In addition, Visual Studio cannot offer you IntelliSense support to help you write code around a dynamic expression. You cannot define an extension method (discussed in Chapter 8, "Methods") that extends dynamic, although you can define one that extends Object. And you cannot pass a lambda expression or anonymous method (discussed in Chapter 17, "Delegates") as an argument to a dynamic method call because the compiler cannot infer the types being used.

Here is an example of some C# code that uses COM IDispatch to interact with Microsoft Excel workbook and places strings in cell A1.

```
using Microsoft.Office.Interop.Excel;
...
public static void Main() {
    Application excel = new Application();
    excel.Visible = true;
    excel.Workbooks.Add(Type.Missing);
    ((Range)excel.Cells[1, 1]).Value = "Text in cell A1"; // Put this string in cell A1
}
```

Without the dynamic type, the value returned from excel.Cells[1, 1] is of type Object, which must be cast to the Range type before its Value property can be accessed. However, when producing a runtime call wrapper assembly for a COM object, any of VARIANT in the COM method is really converted to dynamic; this is called dynamification. Therefore, because excel.Cells[1, 1] is of type dynamic, you do not have to explicitly cast it to the Range type before its Value property can be accessed. Dynamification can greatly simplify code that interoperates with COM objects. The code is simpler.

```
using Microsoft.Office.Interop.Excel;
...
public static void Main() {
    Application excel = new Application();
    excel.Visible = true;
    excel.Workbooks.Add(Type.Missing);
    excel.Cells[1, 1].Value = "Text in cell A1"; // Put this string in cell A1
}
```

The following code shows how use reflection to call a method ("Contains") on a String target ("Jeffrey Richter") passing it a String argument ("ff") and storing the Boolean result in a local variable (result).

```
Object target = "Jeffrey Richter";
Object arg = "ff";
```

```
// Find the method on the target that matches the argument types
Type[] argTypes = new Type[] { arg.GetType() };
MethodInfo method = target.GetType().GetMethod("Contains", argTypes);

// Invoke the method on the target passing the derived arguments
Object[] arguments = new Object[] { arg };
Boolean result = Convert.ToBoolean(method.Invoke(target, arguments));
```

Using C#'s dynamic type, this can be rewritten with greatly improved syntax.

```
dynamic target = "Jeffrey Richter";
dynamic arg = "ff";
Boolean result = target.Contains(arg);
```

Earlier, I mentioned that the C# compiler emits payload code that, at runtime, figures out what operation to perform based on the actual type of an object. This payload code uses a class known as a runtime binder. Different programming languages define their own runtime binders that encapsulate the rules of that. The code for the C# runtime binder is in the Microsoft.CSharp.dll assembly, and you must reference this assembly when you build projects that use the dynamic keyword. This assembly is referenced in the compiler's default resource file, CSC.csproj. It is in this assembly that knows how to produce code (at runtime) that performs addition when the + operator is applied to two Int32 objects and concatenation when applied to two String objects.

At runtime, the Microsoft.CSharp.dll will have to load the AppDomain, which hurts your performance and increases memory consumption. Microsoft.CSharp.dll loads System.dll and System.Core.dll. If you are using dynamic to help operate with COM components, System.Dynamic.dll will also load. When the payload code executes, it generates dynamic code at runtime; this code will be in an in-memory assembly called "Anonymous HostedDynamicMethods Assembly". The purpose of this code is to improve the performance of dynamic dispatch in scenarios where a particular site makes many invocations using dynamic arguments that have the same runtime type.

Due to the overhead associated with C#'s dynamic evaluation feature, you should consider whether you are getting syntax simplification from the dynamic feature to make it worth the extra performance hit of loading all these assemblies and the extra memory that they consume. If you have only a couple places in your program where you need dynamic behavior, it might be more efficient to just do it the old-fashioned way, by calling reflection methods (for managed objects) or manual casting (for COM objects).

At runtime, the C# runtime binder resolves a dynamic operation according to the runtime type of the object. The binder first checks if the type implements the IDynamicMetaObjectProvider If the object implements this interface, the interface's GetMetaObject method is called, returns a DynamicMetaObject-derived type. This type can process all of the member, and operators for the object. The IDynamicMetaObjectProvider interface and the DynamicMetaObject base class are defined in the System.Dynamic namespace, and both are in the System.Core.dll assembly.

Dynamic languages, such as Python and Ruby, endow their types with DynamicMetaObject-derived types so that they can be accessed in a way appropriate for them when manipulated from other programming languages (like C#). Similarly, when accessing a COM component, the C# runtime binder is a DynamicMetaObject-derived type that knows how to communicate with a COM component. The DynamicMetaObject-derived type is defined in the System.Dynamic.dll assembly.

If the type of being used in the dynamic expression does not implement the IDynamic-MetaObjectProvider interface, then the C# compiler treats the object like instance of an ordinary C#-defined type and performs operations on the object using reflection.

One of the limitations of the dynamic variable is that you can only use it to access an object's instance members because you refer to it. But, there are occasions when it would be useful to dynamically invoke static members of a type where the type is determined at runtime. To accomplish this, I created a StaticMemberDynamicWrapper that derives from System.DynamicObject, which implements the IDynamicMetaObjectProvider interface. The class internally uses a bit of reflection (covered in Chapter 23, "Assembly Loading and Reflection"). Here is the code for my StaticMemberDynamicWrapper class.

```
internal class StaticMemberDynamicWrapper : DynamicObject {
    private readonly Type _type;
    public StaticMemberDynamicWrapper(Type type) { _type = type.GetType(); }

    public override IEnumerable<String> GetDynamicMemberNames() {
        return _type.DeclaredMembers.Select(mi => mi.Name);
    }

    public override Boolean TryGet(GetMemberBinder binder, out object result) {
        result = null;
        var field = GetField(binder.Name);
        if (field != null) { result = field.GetValue(null); } return true;

        var prop = GetProperty(binder.Name, false);
        if (prop != null) { result = prop.GetValue(null); } return true;
        return false;
    }

    public override Boolean TrySet(SetMemberBinder binder, object value) {
        var field = GetField(binder.Name);
        if (field != null) { field.SetValue(null, value); } return true;

        var prop = GetProperty(binder.Name, false);
        if (prop != null) { prop.SetValue(null, value); } return true;
        return false;
    }

    public override Boolean TryInvokeMember(InvokeMember binder, Object[] args, out Object result) {
        MethodInfo method = FindMethod(binder.Name);
        if (method == null) { return false; }
        result = method.Invoke(null, args);
        return true;
    }

    private MethodInfo FindMethod(String name, Type[] paramTypes) {
      return m_type.DeclaredMethods.FirstOrDefault(mi => mi.IsPublic && mi.IsStatic
        && mi.Name == name
        && Parameters(mi.GetParameters(), paramTypes));
    }

    private Boolean Parameters(ParameterInfo[] parameters, Type[] paramTypes) {
      if (parameters.Length != paramTypes.Length) return false;
      for (Int32 i = 0; i < parameters.Length; i++) {
        if (parameters[i].ParameterType != paramTypes[i]) return false;
      }
      return true;
    }

    private PropertyInfo FindProperty(String name, Boolean get) {
      if (get) {
        return m_type.DeclaredProperties.FirstOrDefault(
          pi => pi.Name == name && pi.GetMethod != null &&
          pi.GetMethod.IsPublic && pi.GetMethod.IsStatic());
      return m_type.DeclaredProperties.FirstOrDefault(
        pi => pi.Name == name && pi.SetMethod != null &&
        pi.SetMethod.IsPublic && pi.SetMethod.IsStatic());
    }
}
```

To invoke a static member dynamically, construct an instance of this class by passing in the Type you want to operate on and use the reference in a dynamic variable. Then, invoke the desired static member by using instance member syntax. Here is an example of how to invoke String's static Concat(String, String) method.

```
dynamic stringType = new StaticDynamicMemberwrapper(typeof(String));
var r = stringType.Concat("A", "B"); // dynamically invoke String's static Concat method
Console.WriteLine(r); // Displays "AB"
```
