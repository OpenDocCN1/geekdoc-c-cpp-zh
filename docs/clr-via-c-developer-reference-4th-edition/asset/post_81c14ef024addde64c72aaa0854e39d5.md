
The operations these collection classes offer are, nevertheless, pretty consistent. For example, they all maintain a set of elements that can be enumerated, and they all allow adding and removing elements. If you have a reference to an object whose type implements the IList<T> interface, you can write code to insert elements, remove elements, and search for an element without having to know exactly what type of collection you are working with. This is a very powerful mechanism.

Finally, it should be pointed out that you can actually do both: define an interface and provide a base class that implements the interface. For example, the FCL defines the IComparer<T> interface and any type can choose to implement this interface. In addition, the FCL provides an abstract base class, Comparer<T>, which implements this interface and provides a default implementation for the non-generic IComparer's Compare method. Having both an interface definition and a base class offers great flexibility because developers can now choose whichever they prefer.

## Characters

In the .NET Framework, characters are always represented in 16-bit Unicode code values, easing the development of global applications. A character is represented with an instance of the System.Char structure (a value type). The System.Char type is pretty simple. It offers two read-only fields: MinValue, defined as '\0', and MaxValue, defined as '\ffff'.

Given an instance of a Char, you can call the static GetUnicodeCategory method, which returns a value of the System.Globalization.UnicodeCategory enumerated type. This value indicates whether the character is a control character, a currency symbol, a lowercase letter, an uppercase letter, a punctuation character, a math symbol, or another character (as defined by the Unicode standard).

Space developing, the Char type also offers several static methods, as as IsDigit, IsLetter, IsWhitespace, IsLower, IsPunctuation, IsLetterOrDigit, IsNumber, IsSeparator, IsSurrogate, IsLowSurrogate, IsHighSurrogate, and IsSymbol. Most of these methods getUnicodeCategory internally and simply return true or false accurately. Note that all of these methods either take a single character for a parameter or a String and the index of a character within the String parameters.

In addition, you can convert a single character to its lowercase or uppercase equivalent in a culture-agnostic way by calling the ToLowerInvariant or ToToUpper methods. Alternatively, the ToLower and ToToUpper convert the character by using the culture-association with the calling thread (which methods obtain internally by querying the staticCurrentCulture property of the System.Globalization.CultureInfo class). You can also specify a particular character by passing an instance of the CultureInfo class to these methods. ToLower and ToToUpper require culture information because letter casing is a culture-dependent operation. For example, Turkish considers the uppercase of U+0069 (LATIN LOWER LETTER I) to be U+0130 (LATIN UPPERCASE LETTER I WITH DOT ABOVE), whereas other cultures consider the result to be U+0049 (LATIN CAPITAL I).

Besides these static methods, the Char type also offers a few methods of its own. The Equals method returns true if two Char represent the same 16-bit Unicode code point. The CompareTo methods (defined by the IComparable/IComparable<Char> interfaces) return a comparison of two characters; this comparison is not culture-sensitive. The ConvertUtf32 method produces a string consisting of one or two UTF-16 characters from a single UTF-32 character. The ConvertToUtf32 method returns a UTF-32 character from a low/high surrogate pair or from a string. The ToString method returns a string consisting of a single character. The opposite of ToString/Parse, which takes a single-character String and returns its UTF-16 code point.

The last method, GetNumericValue, returns the numeric equivalent of a character. I demonstrate this method in the following code.

```
using System;

public static class Program {
    Double d;
    // \u0033 is the "digit 3"
    d = Char.GetNumericValue(\u0033); // '3' would work too
    Console.WriteLine(d.ToString()); // Displays "3"

    // \u00bc is the "vulgar fraction one quarter ('¼')"
    d = Char.GetNumericValue(\u00bc);
    Console.WriteLine(d.ToString()); // Displays "0.25"

    // 'A' is the "Latin capital letter A"
    d = Char.GetNumericValue('A');
    Console.WriteLine(d.ToString()); // Displays "-1"
}
```

Finally, three techniques allow you to convert between various numeric types to Char instances and vice versa. The techniques are listed here in order of preference:

- Casting The easiest way to convert a Char to a numeric value such as an Int32 is simply by casting. Of the three techniques, this is the most efficient one because the compiler emits Intermediate Language (IL) instructions to perform the conversion, and no methods have to be called. In addition, some languages (such as C#) allow you to indicate whether the conversion should be performed using checked or unchecked code (discussed in Chapter 5, "Primitive, Reference, and Value Types").

- Use the Convert type The System.Convert type offers several static methods that are capable of converting a Char to a numeric type and vice versa. All of these methods perform the conversion as a checked operation, causing an OverflowException to be thrown if the conversion results in loss of data.

- Use the IConvertible interface The Char and all of numeric in the .NET Framework Class Library (FCL) implement the IConvertible interface. This interface defines methods such as UInt16 and ToChar. This technique is the least efficient of the three because calling an interface method on a value type requires that the instance be—Char and all of the numeric types are value types. The methods of IConvertible throw an InvalidCastException if the type can't be converted (such as converting a Char to a Boolean) or if the conversion results in loss of data. Note that many types (including the FCL's Char and numeric types) implement IConvertible as explicit member implementations (described in Chapter 13, "Interfaces"). This means that you must explicitly cast the instance to an IConvertible before you can call any of the interface's methods. All of the methods of IConvertible except GetTypeCode accept a reference to an object that implements the IFormatProvider interface. This parameter is useful if some reason the conversion needs to consider culture information into account. For most conversions, you can pass null for this parameter because it would be ignored anyway.

The following code demonstrates how to use these three techniques:

```
public static class Program {
    public static void Main() {
        Char c;
        Int32 n;

        // Convert number <-> character using C# casting
        c = (Char) 65;
        Console.WriteLine(c); // Displays "A"

        n = (Int32)c;
        Console.WriteLine(n); // Displays "65"

        c = unchecked((Char)(65536 + 65));
        Console.WriteLine(c); // Displays "A"
    }
}
```
