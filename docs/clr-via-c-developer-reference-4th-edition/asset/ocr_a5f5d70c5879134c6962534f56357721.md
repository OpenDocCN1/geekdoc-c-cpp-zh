Now, let's talk about performing linguistically correct comparisons. The .NET Framework uses the System.Globalization.CultureInfo type to represent a language/country pair (as described by the RFC 1766 standard). For example, "en-US" identifies English as written in the United States, "en-AU" identifies English as written in Australia, and "de-DE" identifies German as written in Germany. In the CLR, every thread has two properties associated with it. Each of these properties refers to a CultureInfo object. The two properties are

+   - **CurrentUIC** This property is used to obtain resources that are shown to an end user. It is most useful for GUI or Web Applications because it indicates the language that should be used when displaying UI elements such as labels and buttons. By default, this thread property is set to a CultureInfo object, which identifies the language of the Windows version is running using the Win32 GetDefaultLanguage function. If you're running a Multilingual User Interface (MUI) version of Windows, you can set this via the Regional And Language Options Control Panel dialog box. By a non-MUI version of Windows, the language is determined by the localized version of the operating system installed (or the installed package) and is not changeable.
- **CurrentCulture** This property is used for everything that isn't culture, including number and date formatting, string casing, and string comparison. When formatting, both the language and country parts of the Culture object are used. By default, when you create a thread, this property is set to a CultureInfo object, whose value is determined by calling the Win32 GetDefaultLC method, whose value is set in the Regional And Language Control Panel.

The two thread properties mentioned above, you can override the default value used by the system when you create a new thread with AppDomains by setting Culture's static DefaultThreadCulture and DefaultCultureInfo properties.

On many computers, a thread's CurrentCulture and CurrentCultureInfo properties will be set to the same object, which both use the same language/country information. However, they can be different. For example: an application running in the United States can use Spanish for all of its items and other GUI elements while displaying all of the currency and date formatting for the United States. To do this, the thread's CurrentCultureInfo should be set to a CultureInfo object initialized with a language of "es" (for Spanish), while the thread's CurrentCulture property should be set to a CultureInfo object initialized with a language/country pair of "en-US".
