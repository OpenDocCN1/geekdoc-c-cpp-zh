The following steps describe how a formatter automatically deserializes an object type has the SerializableAttribute applied to it:

+   1. The formatter reads the assembly's identity and full type name from the stream. If the as- is not currently loaded into the AppDomain, it is loaded (as described earlier). If the assembly cannot be loaded, a SerializationException is thrown and the object cannot be deserialized. If the assembly is loaded, the formatter passes the assembly identity information and the type's full name to FormatterServices static GetTypeFromAssembly method.

```
public static Type GetTypeFromAssembly(Assembly asem, String name);
```

This method returns a System. Type object indicating the type of object that is being deserialized.

+   2. The formatter calls FormatterServices static GetUninitializedObject method.

```
public static Object GetUninitializedObject(Type type);
```

This method allocates memory for a new object but does not call a constructor for the object. However, all the object's bytes are initialized to null or 0.

+   3. The formatter now constructs and initializes a MemberInfo array as it did before by calling the FormatterServices' GetSerializable method. This method returns the set of fields that are needed to be deserialized.

+   4. The formatter creates and initializes an Object array from the data contained in the stream.

+   5. The reference to the newly allocated object, the MemberInfo array, and the parallel Object array of values is passed to FormatterServices' static PopulateObjectMembers method.

```
public static Object PopulateObjectMembers(
Object obj, MemberInfo[] members, Object[] data);
```

This method enumerates the arrays, initializing each field to its corresponding value. At this point, the object has been completely deserialized.
