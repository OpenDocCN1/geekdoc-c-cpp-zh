promises not to fail, Cer.Success. Otherwise, Cer.MayFail. Any method that does not have
the ReliabilityContractAttribute applied to it is equivalent to being marked like this.

```
[ReliabilityContract(Consistency.MayCorruptProcess, Cer.None)]
```

The Cer.None value indicates that the method makes no guarantees. In other words, it
written with CERs in mind; it may fail and it may or not report that it failed. Remember
most of these settings are giving a method to do what it offers to potential callers
so that they know what to expect. The CER and JIT compiler do not use this information.

When you want to write a reliable method, make it small and constrain what it does. Make sure
at it doesn't allocate any objects (no boxing for example), don't call any virtual methods or inter-
face methods, use any delegates, or reflection which the JIT compiler can tell you what will
be called. You can manually prepare these methods by calling one of these
methods defined by the RuntimeHelper class.

```
public static void PrepareMethod(RuntimeMethodHandle
public static void PrepareMethod(RuntimeMethodHandle method,
RuntimeTypeHandle[] instantiation)
public static void PrepareDelegate(Delegate d);
public static void PrepareConstrainedDelegate(Delegate d);
```

Note that the compiler and CER do not knowing that you've written your method to actu-
live up to the guarantees you document via the ReliabilityContractAttribute. If you result in
ssomething wrong, state corruption is possible.

> Note Even if the methods are eagerly prepared, a method could still cause a
StackOverflowException. When the CER is not hosted, a StackOverflowException\causes the process to terminate immediately by the CER internally calling environment.
FailFast. When hosted, the PreparedConstrainedRegions method checks the stack to
see if there is approximately 48 KB of stack space remaining. If there is limited stack space,
the StackOverflowException occurs before entering the try block.

You should also look at RuntimeHelper.ExecuteCodeWithGuaranteedCleanup method,
which is another way to execute code with guaranteed cleanup.

```
public static void ExecuteCodeWithGuaranteedCleanup(TypeCode code, CleanupCode backup,
Object userData);
```

When calling this method, you pass the body of the try and finally block as callback methods
whose prototypes call these two delegates respectively.

```
public delegate void TryCode(Object userData);
public delegate void CleanupCode(Object userData, Boolean exceptionThrown);
```
