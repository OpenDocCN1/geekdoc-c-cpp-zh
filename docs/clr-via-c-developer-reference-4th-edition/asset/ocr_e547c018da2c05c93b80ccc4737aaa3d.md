In this code, the [assembly:CLRCompliant(true)] attribute is applied to the assembly. This attribute tells the compiler to ensure that any publicly exposed type doesn't have any construct that would prevent the type from being accessed by any other programming language. When this code is compiled, the C# compiler emits two warnings. The first warning is reported because the method returns an unsigned integer; some other languages cannot manipulate unsigned integer values. The second warning is because this exposes two public methods that differ only by case and return type: Ab and abc. Visual Basic and some other languages can't call both of these

Interestingly, if you were to delete public in front of 'sealed class SomeLibraryType' and recompile, both warnings would go away. The reason is that the SomeLibraryType type would default to internal and would no longer be exposed outside of the assembly. For a complete list of CLR rules, refer to the 'Cross-Language Interoperability' section of the .NET Framework SDK documentation (http://msdn.microsoft.com/en-us/library/730f1wy3.aspx).

Let met cls to something simple. In the CLR, every member of a type is either a field (data) or a method (behavior). This means that every programming language must be able to access fields and methods. Certain fields and certain methods are used in special and common ways. To ease programming, languages typically offer additional abstractions to coding these common programming patterns easier. For example, languages expose concepts such as enums, arrays, properties, indexers, delegates, constructors, finalizers, operator overloads, conversion operators, and so on. When a compiler comes any of these in your source code, it must translate these constructs into fields and methods so that the CLR and any other programming language can access the construct.
