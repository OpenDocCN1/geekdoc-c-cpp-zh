# Using Delegates to Call Back Static Methods

Now that you understand how the Counter method is designed and how it works, let's see how to use delegates to call static methods. The StaticDelegatedDemo method that appears in the previous code sample is the focus of this section.

The StaticDelegatedDemo method calls the Counter method, passing null in the third parameter, which corresponds to Counter's fb parameter. Because Counter's fb parameter receives null, each item is produced without calling any callback.

Next, the StaticDelegatedDemo method calls Counter twice, passing a newly constructed Feedback delegate object in the third parameter of the method call. This delegate object is a wrapper around a method, allowing the method to be called indirectly via the wrapper. In this example, the name of the static method, Program.FeedbackToConsole, is passed to the Feedback delegate constructor, indicating that it is the method to be wrapped. The reference returned from the new operator is passed to Counter as its third parameter. Now when Counter executes, it will call the Program type's static FeedbackToConsole method for each item in the series. FeedbackToConsole simply writes a string to the console indicating the item being processed.

> Note The FeedbackToConsole method is defined as private inside the Program type, but the Counter method is able to call Program's private method. In this case, you might not expect a problem because both Counter and FeedbackToConsole are defined in the same type. However, this code would work fine even if the Counter method was defined in another type. In short, it is not a security or accessibility violation for one type to have code that calls another type's private member via a delegate as long as the delegate object is created by that class has ample security/accessibility.

The third call to Counter in the StaticDelegatedDemo method is almost identical to the second call. The only difference is that the Feedback delegate object wraps the static Program, FeedbackToMsgBox builds a string indicating the item being processed. This string is displayed in a message box.

Everything in this example is type-safe. For instance, when constructing a Feedback delegate object, the compiler ensures the signatures of Program's FeedbackToConsole and FeedbackToMsgBox methods are compatible with the signature defined by the Feedback delegate. Specifically, both methods must have one argument (Int32), and both methods must have the same return type (void). If FeedbackToConsole had been defined like this:

```
private static Boolean FeedbackToConsole(String value) {
    ...
}
```

the C# compiler will not compile the code and issue the following error: error CS0123: No overload for 'FeedbackToConsole' matches delegate 'Feedback'.
