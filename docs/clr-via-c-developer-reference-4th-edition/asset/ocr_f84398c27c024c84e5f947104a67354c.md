The second problem is that the code does not reflect the order of operations that are performed on the StringBuilder object, making the code difficult to write, read, and maintain. The programmer wants to call Replace first and then call IndexOf(); but when you read the last line of code from left to right, IndexOf appears first on the line and Replace appears second. Of course, you could alleviate this problem by making the code's behavior more understandable by rewriting it like this.

```
// First, change period to exclamation mark
sb.Replace('.', '!');
```

```
// Now, get # characters in 1 sentence (S)
Int32 index = StringBuilderExtensions.IndexOf(sb, '!');
```

However, a third problem exists with both versions of this code that affects the code's behavior. The use of StringBuilderExtensions is overpowering and detracts the programmer's mind from the operation that is performed: IndexOf. If the StringBuilder class defined its own IndexOf method, then we could rewrite the code as follows:

```
// Change period to exclamation and get # characters in 1 sentence (S)
Int32 index = sb.Replace('.', '!').IndexOf('!');
```

Now, how look is this in terms of code maintainability? In the StringBuilder object, we're going to replace a period with an exclamation mark and then find the index of the exclamation mark.

Now, I can explain how C# extension method features does. It allows you to define a static method that you can invoke using instance method. Or, in other words, we can define our own IndexOf method and the three problems mentioned above go away. To simply we add this keyword as the first argument.

```
public static class StringBuilderExtensions {
    public static Int32 IndexOf(StringBuilder sb, char value) {
        for (Int32 index = 0; index < sb.Length; index++)
            if (sb[index] == value) return index;
        return -1;
    }
}
```

Now, when the compiler sees this like following, the compiler first checks if the StringBuilder class or any of its base classes has an instance method called IndexOf that takes a single Char parameter.

```
Int32 index = sb.IndexOf('!');
```

If an existing method exists, then the compiler will look at any static classes to define static methods called IndexOf that take as their first parameter a type matching the type of expression being used to invoke the method. This type must also be marked with this keyword. In example, the expression is sb, which is of the StringBuilder type. In this case, the compiler is looking specifically for an IndexOf method that takes two parameters: a StringBuilder (marked with this keyword) and a Char. The compiler will find our IndexOf method and produce IL that calls our static method.
