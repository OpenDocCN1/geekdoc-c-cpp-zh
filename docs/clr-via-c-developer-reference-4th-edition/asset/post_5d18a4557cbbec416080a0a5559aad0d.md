On the left side of the => operator is where you specify the names of any arguments that are to be passed to the lambda expression. There are some rules you must follow here. See the following examples.


> **Important** In case it's not obvious, let me explicitly point out that the main benefit of lambda expressions is that they remove a level of indirection from your source code. Normally, you'd have to write a separate method, give that method a name, and then pass the name of method where a delegate is required. The name gives you a way to refer to a body of code, and if you need to refer to the same body of multiple locations in your source code, writing a method and giving it a name is a great way to go. However, if you need a body of code that is referred to only once within your source code, then a lambda expression allows you to put that directly inline without having to assign it a name, thus increasing programmer productivity.

When C# 2.0 came out, it introduced a feature called anonymous methods. Like lambda expressions (introduced in C# 3.0), anonymous methods provide a syntax for creating anonymous functions. Of course, Microsoft's C# compiler supports both syntaxes for creating anonymous functions so developers are not forced to modify any code that was originally written for C# 2.0. # Syntactical Shortcut: No Need to Wrap Local Variables in a Class Manually

This example really shows-off how easy C# makes implementing what was used to be. The preceding method defines one parameter, numToDo, and two local variables, squares and done. And how the lambda expression refers to these variables.

Now imagine that the code in the body of the lambda expression is placed in a separate method (as required by the CLR). How would the values of variables be passed to the separate method? The only way to do this is to define a new helper class that also defines a field for each value you passed to the callback code. In addition, the callback would have to be defined as an instance method in this helper class. Then, the UsingLocalVariablesInCallback method would have to construct an instance of the helper class, initialize the fields in its local variables, and construct the delegate object bound to the helper object/instance.

> **Note** When a lambda expression causes the callback to generate a class with parameter/local variables turned into fields, the lifetime of the objects that the variables refer to is lengthened. Usually, a parameter/local variable goes out of scope at the last usage of the variable within a method. However, turning the variable into a field causes the field to keep the object that it refers alive for the whole lifetime of the object containing the field. This is not big deal in most applications, but it is something you should be aware of.
