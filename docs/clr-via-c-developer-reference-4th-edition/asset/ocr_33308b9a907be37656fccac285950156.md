And then, in the main class of our application, we define the static fields.

```
private static List<Customer> s_customers = new List<Customer>();
private static List<Order> s_pendingOrders = new List<Order>();
private static List<Order> s_processedOrders = new List<Order>();
```

We can now serialize our application state to a single stream with a method that looks like this.

```
private static void SaveApplicationState(Stream stream) {
  // Construct a serialization formatter that does all the hard work
  BinaryFormatter formatter = new BinaryFormatter();

  // Serialize our application's entire state
  formatter.Serialize(stream, s_customers);
  formatter.Serialize(stream, s_pendingOrders);
  formatter.Serialize(stream, s_processedOrders);
}
```

To reconstruct our application state, we would deserialize the state with a method that looks like this

```
private static void RestoreApplicationState(Stream stream) {
  // Construct a serialization formatter that does all the hard work
  BinaryFormatter formatter = new BinaryFormatter();

  // Deserialize our application's entire state (same order as deserialized)
  s_customers = (List<Customer>)formatter.Deserialize(stream);
  s_pendingOrders = (List<Order>)formatter.Deserialize(stream);
  s_processedOrders = (List<Order>)formatter.Deserialize(stream);
}
```

The third and last I'd like to point out how to deal with assemblies. When serializing an object, the full name of the type and the name of the type's defining assembly are written to the stream. BinaryFormatter outputs the assembly's full identity, which includes the assembly's file name (without extension), version number, culture, and public key information. When deserializing an object, the formatter first grabs the assembly identity and ensures that the assembly is loaded into the executing App.Reflection.Assembly.Load method (discussed in Chapter 23, "Assembly Loading and Reflection")

After an assembly has been loaded, the formatter looks in the assembly for a type matching or an exception is thrown if the assembly doesn't contain a matching type, and no more objects can be deserialized. If a matching type is found, an instance of the type is created and its fields are initialized from the values contained in the stream. If the type's fields exactly match the names of the fields as read from the stream, a SerializationException is thrown and no more objects can be deserialized. Later in this chapter, I will discuss some sophisticated mechanisms that allow you to override some of this behavior.
