# Demo #1: Cross-AppDomain Communication Using Marshall-by

In Demo #1, System.AppDomain.static CreateDomain method is called, instructing the CLR to create a new AppDomain in the windows process. The AppDomain type actually offers severalloads of the CreateDomain method; I encourage you to study and select the version that is most appropriate when you are writing code to create a new AppDomain. The version of CreateDomain I call accepts three arguments:

+   - A identifying the friendly name I assigned to the new AppDomain I'm passing in "AD 2" here.
- A System.Security.Policy.Evidence identifying the evidence that the CLR should use to calculate the permission set I'm passing null here that the new AppDomain will inherit the permission set as the AppDomain creating it. Usually, if you want to create a security boundary around code in an AppDomain, you would construct a System.Security.PermissionSet object, add the desired permission objects to it (instances of types that implement the IPermission interface), and then pass the resulting PermissionSet reference to the overloaded version of the CreateDomain method that accepts a PermissionSet.
- A.Setup identifying the configuration settings the CLR should use for the new AppDomain Again. I'm passing null here so that the new AppDomain will inherit the same configuration settings as the AppDomain creating it. If you want the AppDomain to have a specific configuration, construct an AppDomainSetup object, set its properties to whatever you want, as the name of the configuration file, and pass the resulting AppDomainSetup object reference to the CreateDomain method.

Internally, the CreateDomain method creates a new AppDomain in the process. This AppDomain will be assigned the specified friendly name, security, and configuration settings. The new AppDomain will have its own loader heap, which will be empty because there are currently no assemblies loading into the AppDomain. When you create an AppDomain, the CLR does not create any threads in this AppDomain; no code runs in the AppDomain unless you explicitly have a thread call in the AppDomain.
