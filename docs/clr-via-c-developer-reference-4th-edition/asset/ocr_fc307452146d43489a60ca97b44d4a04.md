If every type was a reference type, an application's performance would suffer greatly. How poor performance would be every time you used an Int32 value, memory allocation occurred! To improve performance for simple, frequently used types, the CLR offers lightweight called types. Value types are usually allocated on a thread's stack (although they can also be embedded in a reference type object). The variable representing the instance doesn't contain a pointer to an instance; the variable contains the fields of the instance itself. Because the variable contains the instance's fields, a pointer doesn't have to be dereferenced to manipulate the instance's fields. Value type instances don't come under the control of the garbage collector, so their use performance in the managed heap reduces the number of collections an application requires over its lifetime.

The .NET Framework SDK documentation clearly indicates which types are reference types and are value types. When looking up a type in the documentation, any type called is a class or the System.Exception class, the System.IO.FileSystem class, and the System.Random class are all reference types. On the other hand, the documentation refers to each value type as a structure or an enumeration. For example, the Int32 value, the System.Boolean structure, the System.Decimal structure, the System.Span structure, the System.DayOfWeek enumeration, the System.IO.FileAttributes, and the System.Drawing.FontStyle are all value types.

All of the types are immediately derived from the System.ValueType abstract type. System.ValueType is itself derived from the System.Object type. By definition, all value types must be derived from System.ValueType. All enumerations are derived from the System.Enum abstract type, which is itself derived from System.ValueType. The CLR and all programming languages give enumerations special treatment. For more information about enumerated types, refer to Chapter 15, "Enumerated Types and Bit Flags."

Even though you can choose a base type when defining your own value type, a value type can implement one or more interfaces if you choose. In addition, value types are sealed, which prevents a value type from being used as a base for any other reference type or value type. So, for example, it's not possible to define new types using Boolean, Char, Int32, UInt64, Single, Double, Decimal, and so on base types.

> Important For many developers (such as unmanaged C/C++), reference types and value types will seem strange at first. In unmanaged C/C++, you declare a type, and then the code that uses the type to decide if an instance of the type should be located on the thread's stack or in your application's heap. In managed code, the developer defining the type indicates where instances of the type are allocated; the developer using the type has no control over this.
