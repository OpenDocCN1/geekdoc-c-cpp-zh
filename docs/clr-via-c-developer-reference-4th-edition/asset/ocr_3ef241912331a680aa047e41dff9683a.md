Although MyMethodAsync seems rather contrived, it demonstrates some key things. First, it is an async function that returns a Task<String> but the code's body ultimately returns a String. Second, it calls other functions that execute operations asynchronously; one stand-alone and the other from a for loop. Finally, it also contains exception handling code. When compiling MyMethodAsync, the compiler transforms the code in this method into a state machine that is capable of being suspended and resumed.

I took the preceding code, and then reverse engineered the IL code back into C# source code. I then simplified the code and added a lot of comments to it you can understand what the compiler is doing making async functions work. The following is the essence of the code created by the compiler's transformation. I showed the transformed MyMethodAsync as well as the state machine it now depends on.

```
//AsyncStateMachine attribute indicates an async method (for tools using reflection);
// the type indicates which structure element implements the state machine
[DebuggerStep, AsyncStateMachine(typeof(StateMachine))]
private static Task<String> MyMethodAsync(Int32 argument) {
    // Create state machine instance and initialize it
    StateMachine stateMachine = new StateMachine() {
        // Create builder returning Task from this stub method
        // State machine accesses builder to set Task completion/exception
        m_builder = AsyncTaskBuilder<String>.Create();

        m_state = -1; // Initialize state machine location
        m_argument = argument; // Copy arguments to state fields
    };

    // Start executing the state machine
    stateMachine.m_builder.Start(ref stateMachine);
    return stateMachine.m_builder.Task; // Return state machine's Task
}
```
