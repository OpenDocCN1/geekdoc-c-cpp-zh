Next each Console.WriteLine is a comment that indicates the output. For multidimensional arrays, the zero-based arrays display a type name of System.String[,], whereas the 1-based arrays display a type name of System.String[*]. The * indicates that the CLR knows that this is not zero-based. Note that C# does not allow you to declare a variable of type String[*], and therefore it is not possible to use C# syntax to access a single-dimensional, non-zero-based array. Although you can call Array.GetValue and SetValue to access the elements of the array, this access will be due to the overhead of the method call.

For multidimensional arrays, the zero-based and 1-based arrays all display the same type name: System.String[,]. at run time This would make you think that the type name should display as System.String[*,*]; however, the CLR does not use the *s for multidimensional arrays because they would always be present, and the asterisks would just confuse developers.

Accessing the elements of a single-dimensional, zero-based array is slightly faster than accessing the elements of a non-zero-based, single-dimensional array or a multi-dimensional array. There are several reasons for this. First, there are IL instructions—such as newlem, Idelem, Idelema, L1dlem, and stelem—that the JIT compiler uses to optimize code. For example, the JIT compiler will emit code that assumes the array is zero-based, and this means that an offset doesn't have to be subtracted from the index when accessing an element. Second, in common situations, the JIT compiler is able to hoist the index range-checking code out of the loop, causing it to execute just once.
