# The ManualResetSlim and SemaphoreSlim Classes

The first hybrid constructs are System. Threading.ManualResetSlim and System.Threading.SemaphoreSlim. These constructs work exactly like their kernel-mode counterparts, except that both employ in user mode, and they defer creating the kernel-mode construct until the first contention occurs. Their Wait methods allow you to wait for a timeout and CancellationToken. Here is what these classes look like (some method overloads are not shown):

```
public class ManualResetSlim : IDisposable {
    public ManualResetSlim(boolean initialState, Int32 spinCount);
    public void Dispose();
    public void Reset();

    public boolean Wait(Int32 milliseconds, CancellationToken cancellation);

    public boolean IsSet { get; }
    public Int32 SpinCount { get; }
    public WaitHandle WaitHandle { get; }
}
```

# The Monitor Class and Sync Blocks

The most-used hybrid thread synchronization construct is the Monitor class, which provides a mutual-exclusive lock supporting spinning, thread ownership, and recursion. It is the most-used construct because it has been around the longest, # has a built-in keyword to support it, the just-in-time (JIT) compiler has built-in knowledge of it, and the common language runtime (CLR) itself uses it on your application.
