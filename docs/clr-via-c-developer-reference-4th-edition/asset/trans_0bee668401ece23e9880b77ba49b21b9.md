
指明您是想要执行阻塞（非当前）还是后台（并发）收集。以下是 `Collect` 方法最复杂的重载的签名。

```
void Collect(Int32 generation, GCCollectionMode mode, Boolean blocking);
```

`GCCollectionMode` 是一个枚举，其值如表 21-2 所示。

# 表 21-2 GCCollectionMode 枚举类型定义的符号

| 符号名称 | 说明 |
| --- | --- |
| Default | 等同于不带标志调用 `GC.Collect`。今天这等同于传递 `Forced`，但在 CLR 的未来版本中可能会发生变化。 |
| Forced | 强制对指定代及以上的所有代进行收集。 |
| Optimized | 垃圾回收器只有在收集能够产生效果（即通过释放大量内存或减少碎片）时才会执行。如果垃圾回收不会产生效果，则该调用将没有 |

**在大多数情况下，您应该避免调用任何 Collect 方法；** 最好让垃圾回收器自行运行，并根据实际应用程序的行为对其代数进行微调。然而，如果您正在编写用户界面 (UI) 或 GUI 应用程序，您的应用程序在在该进程中编码了进程和 GC。对于这些类型的应用程序，您*可能*可以使用 `Optimized` 的 `GCCollectionMode` 在某些时间建议进行垃圾回收。`Default` 和 `Forced` 正常模式用于调试和查找内存泄漏。

例如，如果发生了导致大量对象死亡的非周期性事件，您可能考虑调用 `Collect` 方法。在这种情况下调用 `Collect` 可能并不那么坏，原因是 GC 基于过去对未来的预测对于非周期性事件可能是不准确的。例如，在您初始化之后或用户保存数据文件之后，让应用程序对所有代强制全 GC 可能是意义的。由于 *Collect* 会导致代预算调整，请不要调用 `Collect` 来尝试提高应用程序的响应时间；而应调用它来减少工作集。

对于某些应用程序（特别是倾向于在内存中保留大量对象的服务器），GC 执行包含第 2 代在内的全收集所需的时间可能过长。如果收集花费很长时间，客户端会请求更多的超时时间。为了帮助此类应用程序，`GC` 类提供了 `RegisterFullGCNotification` 方法。通过使用此方法以及其他辅助方法（`WaitForFullGCApproach`、`FullFullGCComplete` 和 `CancelFullGCNotification`），应用程序可以在垃圾回收器即将执行全收集时收到通知。应用程序随后可以调用 `Collect` 在更合适的时间强制收集，或者应用程序可以与另一个服务器通信，以更好地加载客户端请求。如需更多信息，请查看 Microsoft .NET SDK 文档中的这些方法和“垃圾回收通知”。注意，您应该始终成对调用 `WaitForFullGCApproach` 和 `WaitForFullGCComplete` 方法，因为 CLR 在内部将它们作为成对处理。

# 监控应用程序的内存使用情况

在进程内部，有几个方法可以调用来监控垃圾回收器。具体来说，`GC` 类提供了静态方法，您可以调用这些方法来查看特定代发生了多少次收集，或者托管堆中的对象当前占用了多少内存。

```
Int32 CollectionCount(Int32 generation);
Int64 GetTotalMemory(Boolean forceFullCollection);
```

此时，您应该已经对垃圾回收和托管堆有了基本的了解，包括收集器如何回收对象的内存。幸运的是，大多数类型只需要内存。然而，某些类型为了有用，需要的不仅仅是内存；某些类型需要使用原生资源。

例如，`System.IO.FileStream` 类型需要打开文件（原生资源）并存储其句柄。`Read` 和 `Write` 方法使用它来操作文件。同样，`System.Threading.Mutex` 类型打开 Windows 内核对象（原生资源）并存储它，在调用 `Mutex` 的方法时使用它。

# 处理需要特殊清理的类型

这被称为析化（Finalization）。所有封装原生资源的类型——如文件、网络连接、套字或互斥锁——都支持析化。当 CLR 确定其中一个对象不再可访问时，GC 会执行自身的析化，释放它封装的原生资源，然后 GC 将从托管堆中回收该对象。

`System.Object` 是所有对象的基类，定义了一个保护方法 `Finalize`。当垃圾回收器确定一个对象是垃圾时，它会调用对象的 `Finalize`（如果被重写了）。微软 C# 团队认为 `Finalize` 方法是一种特殊的方法，在编程语言中需要特殊的语法（类似于 C# 需要特殊的语法来定义构造函数）。因此，在 C# 中，您必须通过在类名面前放置波浪号 `~` 来定义 `Finalize` 方法，如下代码所示。

```
internal sealed class SomeType {
  ~SomeType() {
    // 代码位于 Finalize 方法内部
  }
}
```
