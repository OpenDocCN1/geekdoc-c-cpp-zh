Task any = await Task.WhenAny(originalTask, cancelTask.Task);

// If any Task completes by CancellationToken, throw OperationCanceledException
if (any == cancelTask.Task) ct.ThrowIfCancellationRequested();

// await originalTask (synchronously); if it failed, awaiting
// throws 1 inner exception instead of AggregateException
return originalTask;

Now, you can call this extension method as follows.

```
public static async Task Go() {
    // Create a CancellationTokenSource that cancels itself after # milliseconds
    var cts = new CancellationTokenSource(5000); // To cancel sooner, call cts.Cancel()
    var ct = cts.Token;

    try {
        // I used Task.Delay for testing; replace this with another method that returns a Task
        await Task.Delay(10000).WithCancellation(ct);
        Console.WriteLine("Task completed");
    }
    catch (OperationCanceledException) {
        Console.WriteLine("Task cancelled");
    }
}
```

# Some I/O Operations Must Be Done Synchronously

The Win32 API offers many functions that execute I/O operations. Unfortunately, some of these methods do not let you perform the I/O asynchronously. For example, the Win32File method (called by FileStream's constructor) always executes synchronously. If you are trying to create or open a file on a network server, it could take seconds before CreateFile returnsthe calling thread is idle all the time. An application designed for responsiveness and scalability would ideally call a Win32 function that lets you create or open a file so that your thread is not sitting and waiting for the server to reply. Unfortunately, Win32 has no CreateFile-like function to let you do this, and therefore the FCL cannot offer an efficient way to open a file asynchronously. Windows also does not offer functions to asynchronously access the registry, access the event log, or get a directory's/directories, or change a file's/directory's attributes, to just a few.

Here is an example where this is a real problem. Imagine writing a simple UI that allows the user to type a file path and provides automatic completion (to the common File dialog box). The control must use separate threads to enumerate directories looking for files because Windows does not offer functions to enumerate files asynchronously. As the user continues to type in the UI, you have to use more threads and ignore the results from any previously spawned threads.
