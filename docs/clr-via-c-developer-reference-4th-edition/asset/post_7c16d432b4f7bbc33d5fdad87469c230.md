
There are overloads of the preceding methods that operate on Int64 values. Furthermore, the Interlocked class offers Exchange and CompareExchange methods that take Object, IntPtr, Single, and Double, and there is also a generic version in which the generic is constrained to class (any reference type).

Personally, I love the locked methods, because they are relatively fast and you can do so much with them. Let me show you code that uses the Interlocked to asynchronously query web servers and concurrently return the data. This code is pretty short, never blocks any thread, and uses thread pools to scale automatically, consuming up to the number of CPUs available if its workload could benefit from it. In addition, the code, as it is, supports accessing up to 2,147,483,647 (Int32.MaxValue) web servers. In other words, this is a great model for your own scenarios.

```csharp
internal sealed class MultiWebRequest {
    // This helper class coordinates all the asynchronous operations
    AsyncCoordinator m_ac = new AsyncCoordinator();
    // Set of web servers we want to query & their responses (Exception or Int32)
    // NOTE: Even though multiple could access this dictionary simultaneously,
    // there is no need to access it because the keys are
    // read-only after construction
    private Dictionary<String, Object> m_servers = new Dictionary<String, Object> {
        { "http://Winlect.com", null },
        { "http://Microsoft.com", null },
        { "http://1.1.1.1/", null }
    };

    public MultiWebRequest(Int32 timeout = Timeout.Infinite) {
        // Asynchronously initialize all the requests all at once
        var httpClient = new HttpClient();
        foreach (var server in m_servers.Keys) {
            m_ac.AboutToBegin(1);
            httpClient.GetByteArrayAsync(server)
            .ContinueWith(task => ComputeResult(server, task));
        }
        // Tell AsyncCoordinator that all operations have been initiated and to call
        // When AllDone all operations complete, Cancel is called, or the timeout occurs
        m_ac.AllBegun(AllDone, timeout);
    }

    private void ComputeResult(String server, Task<Byte[]> task) {
        Object result;
        if (task.Exception == null) {
            result = task.Exception.InnerException;
        } else {
            // Process I/O completion on thread pool thread(s)
            // Put your own code-intensive algorithm here...
            result = task.Result.Length; // This example returns the length
        }
        // Save result (exception/sum) and indicate that 1 operation completed
        m_servers[server] = result;
        m_ac.JustEnded();
    }

    // Calling this method indicates that the results don't matter anymore
    public void Cancel() { m_ac.Cancel(); }

    // This method is called after all web servers respond,
    // Cancel is called, or the timeout occurs
    private void AllDone(CoordinationStatus status) {
        switch (status) {
            case CoordinationStatus.Cancel:
                Console.WriteLine("Operation canceled.");
                break;
            case CoordinationStatus.Timeout:
                Console.WriteLine("Operation timed-out.");
                break;
            case CoordinationStatus.AllDone:
                Console.WriteLine("Operation completed; results below:");
                foreach (var server in m_servers) {
                    Console.Write(server.Key + ": ");
                    Object result = server.Value;
                    if (result is Exception) {
                        Console.WriteLine("failed due to (0).", result.GetType().Name);
                    } else {
                        Console.WriteLine("returned (0:NO) bytes.", result);
                    }
                }
                break;
        }
    }
}
```

OK, the preceding code doesn't actually use any Interlocked methods directly, I'll encapsulate all the coordination code in a reusable class AsyncCoordinator, I'll explain shortly. Let me first explain what this class is doing. When the MultiWebRequest class is constructed, it initializes an AsyncCoordinator and a dictionary to contain the set of server URIs (and their future result). It then issues all requests asynchronously one after the other. This is done by calling AsyncCoordinator.AboutToBegin method, passing the number of requests about to be issued. Then it initiates the request by calling HttpClient's GetByteArrayAsync. This returns a Task and I then call ContinueWith on this Task so when the server replies with the bytes, which can be processed by my ComputeResult method concurrently via many thread pools. After all the web servers have been made, the AsyncCoordinator's AllBegun method is called, passing the name of the method that should execute when all the operations complete and a timeout value. As each web server responds, thread pool threads will call the MultiWebRequest::ComputeResult method. This method processes the bytes returned from the server (or any error that may have occurred) and saves the result in the dictionary collection. After storing each result, AsyncCoordinator::JustEnded method is called to let the AsyncCoordinator know that an operation completed.

If all the operations have completed, the AsyncCoordinator will invoke the AllDone method to process the results from all web servers. The code executing the AllDone method will be the thread pool that just happened to be the last server response. If timeout or cancellation occurs, then AllDone will be invoked via whatever thread notifies the AsyncCoordinator of timeout or whatever thread happened to be the Cancel method. There is also a chance that the thread issuing the web server requests could invoke AllDone itself if the last request completes before AllBegun.

Note that there is a race because it is possible that all web server requests complete, AllBegun is called all at once, and Cancel is called at the exact same time. If this happens, the AsyncCoordinator will select a winner and three losers, ensuring that the AllDone method is never called more than once. The winner is identified by the status argument passed into AllDone, which can be one of the symbols defined by the CoordinationStatus type.

Now that you get a sense of what happens, let's take a look at how it works. The AsyncCoordinator class encapsulates all the thread coordination logic in. It uses Interlocked methods to ensure the code runs extremely fast and that no threads ever block. Here is the code for this class.

```csharp
internal sealed class AsyncCoordinator {
    private Int32 m_opCount = 1; // Decremented when AllBegun calls JustEnded
    private Int32 m_statusReported = 0; // 0=false, 1=true
    private Action<CoordinationStatus> m_callback;
    private Timer m_timer;

    // This method MUST be called BEFORE initiating an operation
    public void AboutToBegin(in Int32 opsToAdd = 1) {
        Interlocked.Add(ref m_opCount, opsToAdd);
    }

    // This method MUST be called AFTER result are processed
    public void JustEnded() {
        if (Interlocked.Decrement(ref m_opCount) == 0) {
            ReportStatus(CoordinationStatus.AllDone);
        }
    }

    // This method MUST be called AFTER initiating operations
    public void AllBegun(Action<CoordinationStatus> callback, int timeout) {
        m_callback = callback;
        m_timer = new Timer(TimeExpired, null, timeout, Timeout);
        if (m_opCount == 0) {
            ReportStatus(CoordinationStatus.AllDone);
        }
    }

    public void Cancel() {
        ReportStatus(CoordinationStatus.Cancel);
    }

    private void TimeExpired(Object o) {
        ReportStatus(CoordinationStatus.Timeout);
    }

    private void ReportStatus(CoordinationStatus status) {
        // If status has not been reported, report it; else ignore it
        if (Interlocked.Exchange(ref m_statusReported, 1) == 0) {
            m_callback(status);
        }
    }
}
```
