These string characters are encrypted, protecting the sensitive information from malicious
unsafe/unmanaged code. You can insert, remove, or set a character in the secure string by
any of these methods: AppendChar, InsertAt, RemoveAt, and SetAt. Whenever you call
of these methods, internally the method decrypts the characters, performs the operation in place,
and re-encrypts the characters. This means that the characters are in an unencrypted state for
short period of time. This also means that the performance of each operation is less than stellar,
so you should perform as few of these operations as possible.

The SecureString class implements the IDisposable interface to provide an easy way to
deterministically destroy the secure contents. When your application longer needs the
sensitive information, you simply call SecureString\Dispose method or a Secure-
string in a using constructor. Internally, Dispose zeroes out the contents of the memory
buffer to make sure the sensitive information is not accessible to malicious code, and then the
buffer is freed. Internally, a SecureString object has a field to a SafeBuffer-derived object, which
tains the actual string. Because the SafeBuffer class is ultimately derived from Critical-
FinalObject, discussed in Chapter 21, "The Managed Heap and Garbage Collection," the
string characters are guaranteed to be zero out and have its buffer free when it is finalized. Unlike-
a String object, when a SecureString object is finalized, the encrypted string characters will
longer be in memory.
