Obviously, associating a sync block data structure with every object in the heap is wasteful. To reduce memory usage, the CLR uses a more efficient way to offer the functionality described. Here's how it works: when theCLR initializes, it allocates an array of sync blocks in heap. As discussed in this book, whenever an object is created in the heap, it gets two additional overhead fields associated with it. The first overhead field, the type pointer, contains the memory address of the type's object. The second overhead field, the sync block index, contains an integer index into the sync blocks.

When an object is constructed, the object's sync block index is initialized to -1, which indicates that it doesn't refer to any sync block. Then, when Monitor is called, the CLR finds a free sync block in the array and sets the object's sync block index to refer to the sync block that was found. In other words, sync blocks are associated with an object on the fly. When Exit is called, it checks to see whether there are any threads waiting to use the object's sync block. If there are no threads waiting for it, the sync block is free, Exit sets the object's sync block index back to -1, and the free sync block can be associated with another object in the future.

30-1 shows the relationship between objects in the heap, their sync block indices, and elements in the CLR's sync block array. Object-A, Object-B, and Object-C all have their type object pointer member to refer to Type-T (a type object). This means that all three objects are of the same type. As discussed in Chapter 4, "Type Fundamentals", a type object is also an object in the heap, and like all other objects, it has two overhead members: a sync block index and a type pointer. This means that a sync block can be associated with a type object and a reference to a type object can be passed to Monitor's methods. By the way, the sync block array is able to create more sync blocks if necessary, so you shouldn't worry about the system running out of sync blocks if many objects are being synchronized simultaneously.
