# Waiting for a Task to Complete and Getting Its Result

With tasks, it is also possible to wait for them to complete and get their result. Let's say that we have a Sum that is computationally intensive if n is a large value.

```
private static Int32 Sum(Int32 n) {
    Int32 sum = 0;
    for (; n > 0; n--)
        checked { sum += n; } // if n is large, this will throw System.OverflowException
    return sum;
}
```

We can construct a Task<TResult> object (which is derived from Task), and we pass for the generic TResult among the compute-bound operation's return type. Now, after starting the task, we can wait for it and get its result using the following code.

```
// Create a Task (it does not start running)
Task<Int32> t = new Task<Int32>(n => Sum(Int32)n), 1000000000);

// You can start the task some later
t.Start();

// Optionally, you can explicitly wait for the task to complete
t.Wait(); // FYI: Overloads exist accepting timeout/CancellationToken
Console.WriteLine("The Sum is: " + t.Result); // An Int32 value
```

> Important When a thread calls the Wait method, the system checks if the Task that the thread is waiting for executing. If it has, then the thread calling Wait will block until the Task has running. But if the Task has not started executing yet, then the system may (depending on the TaskScheduler) execute the Task using the thread that called Wait. If this happens, the thread calling Wait does not block; it executes the Task and returns immediately. This is good in that no thread has blocked, thereby reducing usage (by not creating a thread to replace the blocked thread) improving performance (no time is spent to create a thread and there is no context switch-ing). It can also be bad, for example, the thread has taken a thread synchronization lock before calling Wait and then the Task tries to take the same lock, resulting in a deadlocked thread!

If the compute-bound task throws an unexpected exception, the exception will be swallowed, stored in a collection, and the thread pool is allowed to return to the thread pool. When the Wait method or the result property is invoked, these members will throw a System.Aggregate-Exception object.
