# Executing Assembly’s Code

As mentioned earlier, managed assemblies contain both metadata and IL. IL is a CPU-independent machine language created by Microsoft after consultation with several external commercial and academic language/compiler writers. IL is a much higher-level language than most machine languages. IL can access and manipulate objects, and has instructions to initialize objects, call virtual methods on objects, and manipulate array elements directly. It has instructions to throw and catch exceptions for error handling. You can think of IL as an object-oriented machine language.

Usually, developers will program in a high-level language, such as C#, Visual Basic, or F#. The compilers for these high-level languages produce IL. However, as any other language, IL can be written in assembly language, and Microsoft does provide an IL assembler, ILasm.exe. Microsoft also provides an IL Disassembler, IDasm.exe.

Keep in mind that any high-level language will most expose only a subset of the facilities offered by the CLR. The IL assembly allows a developer to access all of the CLR's facilities. So, should your programming language hide the CLR facilities that you really want to take advantage of, you can choose to write that portion of your code in IL or perhaps another programming language that exposes the CLR feature you.

The only way to know what the CLR offers is to read documentation specific to the CLR itself. In this book, I try to concentrate on CLR features and how they are exposed or not exposed by the C# language. I suspect that most books and articles will present the CLR via a language perspective, and most developers will believe that the CLR offers only the developer's chosen language exposes. As long as your language allows you to accomplish what you're trying to get done, this blurred perspective isn't a bad thing.

> Important I think this ability to switch programming languages easily with integration between languages is an awesome feature of the CLR. Unfortunately, I believe that developers will often overlook this feature. Programming languages such as C# and Visual Basic are excellent languages for performing I/O operations. APL is a great language for performing advanced engineering or financial calculations. From the CLR, you can write the I/O operations of your application in C# and then write the engineering calculations part in APL. The CLR offers a level of integration between these languages that is unprecedented and really makes mixed-language programming worthy of consideration for many development projects.
