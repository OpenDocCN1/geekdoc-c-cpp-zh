> Note If you want to execute an operation and prevent it from being canceled, you can pass the operation the CancellationToken returned from calling CancellationToken's static property. This very convenient property returns a special CancellationToken instance that is not associated with any CancellationSource object (its private field is null). Because there is no CancellationSource, no code can call Cancel, and the operation that is querying the special CancellationToken's IsRequested property will always return false. If you query CancellationToken's CanBeC property using one of these special CancellationToken instances, the property will return false. The property returns true for all other CancellationToken instances obtained by querying the CancellationSource object's Token property.

If you'd like, you can call CancellationSource's Register method to register one or more methods to be invoked when a CancellationSource is canceled. To this method, you pass an Action<Object> delegate, a state that will be passed to the callback by the delegate, and a Boolean indicating or not to invoke the delegate by the calling thread's SynchronizationContext. If you pass false for the useSynchronizationContext parameter, the thread that calls Cancel will invoke all the registered methods sequentially. If you pass true for the useSynchronizationContext parameter, then the callbacks are sent (as opposed to posted) to the captured SynchronizationContext object which governs which thread invokes the callback. The SynchronizationContext class is discussed in the 'Applications and Their Threading Models' in Chapter 28.

> Note If you register a method with a CancellationSource after it has already been canceled, the calling thread invokes the callback (possible via the calling thread's SynchronizationContext).

If Register is called multiple times, multiple callback methods will be invoked. These callback methods could throw an unhandled exception. If you call CancellationSource's Cancel, passing it true, the first callback method that throws an unhandled exception stops the other callback methods from executing. If you call Cancel passing it false, all registered callback methods are invoked. Any unhandled exceptions that occur are added to a collection. After all callback methods have executed, if any of them threw an unhandled exception, Cancel throws an AggregateException with its InnerExceptions property set to the collection of exception objects that were thrown. If no registered callback methods threw an unhandled exception, Cancel simply returns without throwing any exception at all.
