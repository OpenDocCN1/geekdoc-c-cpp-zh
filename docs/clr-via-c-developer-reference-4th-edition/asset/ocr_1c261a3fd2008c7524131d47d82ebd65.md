Here is some code that shows this.

```
private static void Method() {
    // Construct a List that operates on DateTime objects
    List<DateTime> dtList = new List<DateTime>();

    // Add a DateTime object to the list
    dtList.Add(DateTime.Now);    // No boxing

    // Add another DateTime to the list
    dtList.Add(DateTime.MinValue); // No boxing

    // Attempt to add a String object to the list
    dtList.Add("1/2004");    // Compile-time error

    // Extract a DateTime object out of the list
    DateTime dt = dtList[0];
}
```

Generics provide the following big benefits to developers as exhibited by the code just shown:

+   **Source code protection** Using a generic algorithm doesn't have to access to the algorithm's source code. With C++ templates, however, the algorithm's source code must be available to the developer who is using the algorithm.

+   **Type safety** When a generic is used with a specific type, the compiler and the CLR understand and ensure that only objects compatible with the specified data type are used with the algorithm. Attempting to use an object of an incompatible type will result in either a compiler error or a run-time exception being thrown. In the example, attempting to pass a String object to the Add method results in the compiler issuing an error.

+   **Cleaner code** Because the compiler enforces type safety, fewer casts are required in source code, meaning your code is easier to write and maintain. In the last line of Method, a developer doesn't need to use a (DateTime) cast to put the result of the indexer (querying element at index 0) into the dt variable.
