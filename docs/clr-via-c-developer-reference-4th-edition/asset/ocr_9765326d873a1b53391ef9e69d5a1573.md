RUT.netmodule, and FUT.netmodule. The Assembly Linker has no way to combine files into a single file.

The ALex utility can also produce PE files by using the /[target]:exe, /[target]:winex, or /[target]:app[target]:containtainerexe-command-line switches. But this is very unusual unless you've made an EXE PE file with enough IL code to call it in another module. You can specify which method in a module should be used as an entry point by adding the /main command-line switch when invoking ALex. The following is an example of how to call the Assembly Linker, ALex, by using the /main command-line switch.

```
csc /t:module /r:MultiFile.dll Program.cs
al /out:Program.exe /main:Program.Main Program.netmodule
```

Here the first line builds the Program.cs file into a Program.netmodule. The second line produces a small Program.exe PE file that contains metadata tables. In addition, there is a small global function named __EntryPoint is defined by ALex using the /main:Program.Main command-line switch. This function, __EntryPoint, contains the IL code.

```
method private static void __EntryPoint$PST06000001() il managed
{
    .entrypoint
    // Code size
    maxstack 8
    IL0000: tail
    IL0007: call void [.module 'Program.netmodule']Program::Main()
    ret
} // end of method 'Global functions'__EntryPoint
```

As you can see, this code simply calls the Main method contained in the type defined in the Program.netmodule file. The /main switch in ALex isn't useful unless you've ever created an assembly for an application that doesn't have its entry in the PE file that contains metadata tables. I mention the switch here to make you aware of its existence.

# Adding Resource Files to an Assembly

When using ALex to create an assembly, you can add a file as a resource to the assembly by using the /embed[resource] switch. This takes a file (any file) and embeds the file's contents into the resulting PE file. The manifest's ManifestResourceDef table is updated to reflect the existence of the resources.
