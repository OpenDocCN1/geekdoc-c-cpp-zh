In this example, the compiler has defined a class Feedback that is derived from the System.MulticastDelegate type defined in the Framework Class Library (FCL). (All delegates are derived from MulticastDelegate.)

> Important The System.MulticastDelegate class is derived from System.Delegate, which is itself derived from System.Object. The reason why there are two delegate classes is historical and unfortunate: there should be one delegate class in the FCL. Sadly, we need to be aware of both of these classes because even though delegate types you create have DelegateDelegate as a base class, you'll occasionally manipulate your delegate by using methods defined by the Delegate class instead of the MulticastDelegate class. For example, the Delegate class has static methods Combine and Remove. (I explain what these methods do later.) The signatures for both of these methods indicate that they take Delegate parameters. Because your delegate type is derived from MulticastDelegate, which is derived from Delegate, instances of your delegate type can be passed to these methods.

The class has privacy visibility because the delegate is declared as internal in the source code. The source code had indicated public visibility, the Feedback class the compiler generated would also be public. You should be aware that delegate types can be defined within a type (nested inside another type) or at global scope. Basically, because delegates are classes, a delegate can be defined anywhere a class can be defined.
