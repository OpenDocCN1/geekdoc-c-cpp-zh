# Properties and the Visual Studio Debugger

Microsoft Visual Studio allows you to inspect an object's property in the debugger's window. When you do this, every time you hit a breakpoint, the debugger calls the property's getter method and displays the returned value. This can be quite helpful in tracking down bugs, but it can also cause bugs to hurt your debugger performance. For example, let's say you have created a FileStream for a file on a network share and then you add FileStream's Length to the debugger's watch window. Now every time you hit a breakpoint, the debugger will call Length's getter method, which internally makes a network request to the server to get the current length of the file!

Similarly, if your property gets a side effect, this side effect will execute every time you hit a breakpoint. For example, let's say your property's getter method increments a counter every time you hit a breakpoint. Because of these potential problems, Visual Studio allows you to turn off evaluation for properties in watch windows. To turn property evaluation off in Visual Studio, select Tools, Options, Debugging, and the list in Figure 10-1, and clear the Enable Property Evaluation And Other Implicit Function calls box. Note that with this item cleared, you can add the property to the watch window and manually force Visual Studio to evaluate it by clicking the force evaluation circle in the watch window's Value column.
