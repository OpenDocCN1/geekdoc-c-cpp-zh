## Rules and Guidelines

There are some additional rules and guidelines that you should know about extension methods:

- C# supports extension methods; it does not offer extension properties, extension events, extension operators, and so on.

- Extension methods (methods with this before their first argument) must be declared in non-generic, static classes. However, there is no restriction on the name of the class; you can call whatever you want. Of course, an extension method must have at least one parameter, and only the first parameter can be marked with this keyword.

## PART II Designing Types

- The C# compiler looks for extension methods defined in static classes that are themselves defined at the file scope. In other words, if you define the static class nested within another class, the C# compiler will emit the following message: error CS1109: Extension method must be defined in a top-level static class; StringBuilderExtensions is in a nested class.

- Because the static classes can have any name you want, it takes the C# compiler time to find extension methods because it must look at all the file-scope static classes and scan their static methods for a match. To improve performance and also avoid considering an extension method that you not use, the C# compiler requires you to "import" extension methods. For example, if someone has defined a StringBuilderExtensions class in a Win namespace, then a programmer who wants to access to this class's extension methods must be using a using directive at the top of or his source code file.

- It is possible that multiple static classes can define the same extension method. If the compiler detects two or more extension methods exist, then the compiler issues the following message: error CS0121: The call is ambiguous between the following methods or properties: 'StringBuilderExtensions.IndexOf(string, char)' and 'OtherStringBuilderExtensions.IndexOf(string, char)'. To fix this, you must modify your source code. Specifically, you cannot use the static method syntax anymore; instead you now use the static method syntax to explicitly indicate the name of the static to explicitly tell the compiler which method you want to invoke.

- You should use this feature sparingly, because not all programmers are familiar with it. For example, when you extend a type with an extension method, you are actually extending types with this method as well. Therefore, you should not define an extension method whose first parameter is System.Object, because this method will be callable for all expression types and this will really pollute Visual Studio's IntelliSense window.

- There is a potential versioning problem that exists with extension methods. If, in the future, Microsoft adds an IndexOf method to their StringBuilder class with the same prototype as my code is attempting to call, when I recompile my code, the compiler will bind to Microsoft's IndexOf method instead of my method. Because of this, my program will experience different behavior. This versioning problem is another reason why this feature should be used sparingly.

## Extending Various Types with Extension Methods

In this chapter, I demonstrated how to define an extension method for a class, StringBuilder. I'd like to point out that because an extension method is really a static method, the CLR does not emit code ensuring that the value of the expression used to invoke the method is not.

```csharp
// sb is null
StringBuilder sb = null;
```

// Calling extension method: NullReferenceException will NOT be thrown when calling IndexOf
// NullReferenceException will be thrown inside IndexOf's for loop
sb.IndexOf('X');

// Calling instance method: NullReferenceException WILL be thrown when calling Replace
sb.Replace('.', '!');
```

I'd like to point out that you can define extension methods for interface types, as the follow code shows.

```csharp
public static void ShowItems<T>(this IEnumerable<T> collection) {
    foreach (var item in collection)
        Console.WriteLine(item);
}
```

The extension method above can be invoked using any expression that results in a type that implements the IEnumerable<T> interface.

```csharp
public static void Main() {
    // Shows Char on a separate line in the console
    "Grant".ShowItems();

    // Shows String on a separate line in the console
    new[] { "Jeff", "Kristin" }.ShowItems();

    // Shows Int32 value on a separate line in the console
    new List<Int32>{ 1, 2, 3 }.ShowItems();
}
```

> Important extension methods are the cornerstone of Microsoft's Language Integrated Query (LINQ) technology.
