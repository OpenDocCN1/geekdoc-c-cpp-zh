Although the last version of this code is the best, technically correct version, you can actually use the second version because the just-in-time (JIT) compiler is aware of this pattern and it knows not to optimize the local temp variable. Specifically, all of Microsoft's JIT compilers respect the invariant of not introducing new reads to memory and therefore, caching a reference in a local variable ensures that the heap reference is accessed only once. This is not documented and, if it could change, that is why you should use the last version. But in reality, Microsoft's JIT compiler would never embrace a break that would break this pattern because too many applications would. In addition, they are mostly used in single-threaded scenarios (Windows Presentation Foundation and Windows Store apps) and so thread safety is not an issue.

It is very important to note that due to this thread race condition, it is also possible that a method will be invoked after it has been removed from the event's delegate chain.

As a convenience, you could define an extension method (as discussed in Chapter 8, "Methods") encapsulates this thread-safety logic. Define the extension method as follows.

```
public static class EventArgsExtensions {
    public static void Raise<TEventArgs>(this TEventArgs e,
        Object sender, EventHandler<TEventArgs> eventDelegate)
    {
        // Copy to the delegate field now into a temporary field for thread safety
        EventHandler<TEventArgs> temp = Volatile.Read(eventDelegate);

        // If any methods registered interest with our event, notify them
        if (temp != null) temp.Raise(sender, e);
    }
}
```

And now, we can rewrite the OnNewMail method.

```
protected virtual void OnNewMail(NewMailArgs e) {
    e.Raise(this, mNewMail);
}
```

A class that uses MailManager as a base type is free to override the OnNewMail method. This capability gives the derived class control over away the raising of the event. The derived class can handle the new email message in any way it sees fit. Usually, a derived type calls the base type's OnNewMail method so that the registered method(s) receive the notification. However, the derived class might decide to disallow the event from being forwarded.
