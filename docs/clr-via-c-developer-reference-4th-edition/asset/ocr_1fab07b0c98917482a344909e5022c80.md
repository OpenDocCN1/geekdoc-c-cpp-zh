This chapter is all about error handling. It's not just about that. There are several parts to error handling. First, we'll define what an error actually is. Then, we'll talk about how to discover when your code is experiencing an error and how to recover from this error. At this point, state becomes an issue because errors tend to come at inappropriate times. It is likely that your code will be in the middle of mutating state when it experiences the error, and your code likely will restore some state back to what it was prior to attempting to mutate it. Or, we'll also talk about how your code can notify its callers that it has detected an error.

In my opinion, exception handling is the weakest area of the common language runtime (CLR) and therefore causes many problems for developers writing managed code. Over the years, Microsoft has made some significant improvements to help developers deal with errors, but I believe that there is much more that must be done before we can really have a good, reliable system. I will talk a about the various enhancements that have been made when dealing with unhandled exceptions, constrained execution regions, code contracts, runtime wrapped exceptions, uncatchable exceptions, and so on.
