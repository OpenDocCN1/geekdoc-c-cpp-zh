## Parameterized Properties

In the previous section, the get accessor methods for the properties accepted no parameters. For this reason, I called these parameterless properties. These properties are easy to understand because they have the feeling of accessing a field. In addition to these field-like properties, programming languages also support what I call parameterized properties, whose get accessor methods accept one or more parameters and whose setter methods accept two or more parameters. Different programming languages expose masterful properties in different ways. Also, languages use different terms to refer to them: C# calls them indexers and Visual Basic call them default properties. In this section, I will focus on how C# exposes its indexes by using parameterized properties.

In C#, parameterized properties (indexers) are exposed using an array-like syntax. In other words, you can think of an indexer as a way for the C# developer to overload the [] operator. Here's an example of a BitArray class that allows array-like syntax to index into the set of bits maintained by an instance of the class.

```cs
using System;

public sealed class BitArray {
    // Private array of bytes that holds the bits
    private Byte[] m_byteArray;
    private Int32 m_numBits;

    // Constructor that allocates the byte array and sets all bits to 0
    public BitArray(Int32 numBits) {
        // Validate arguments first.
        if (numBits <= 0)
            throw ArgumentOutOfRangeException("numBits must be > 0");

        // Save the number of bits.
        m_numBits = numBits;

        // Allocate the bytes for the bit array.
        m_byteArray = new byte[(numBits + 7) / 8];
    }

    // This is the indexer (parameterful property).
    public Boolean this[Int32 bitPos] {
        // This is the indexer's getter method.
        get {
            // Validate arguments first
            if ((bitPos < 0) || (bitPos >= m_numBits))
                throw ArgumentOutOfRangeException("bitPos");

            // Return the state of the indexed bit.
            return (m_byteArray[bitPos / 8] & (1 << (bitPos % 8))) == 0;
        }
        // This is the indexer's setter method.
        set {
            if ((bitPos < 0) || (bitPos >= m_numBits))
                throw ArgumentOutOfRangeException("bitPos", bitPos.ToString());
            if (value) {
                // Turn the indexed bit on.
                m_byteArray[bitPos / 8] = (byte)(m_byteArray[bitPos / 8] | (1 << (bitPos % 8)));
            } else {
                // Turn the indexed bit off.
                m_byteArray[bitPos / 8] = (byte)(m_byteArray[bitPos / 8] & ~(1 << (bitPos % 8)));
            }
        }
    }
}
```

The BitArray class's indexer is incredibly simple.

```cs
// Allocate a BitArray that can hold 14 bits.
BitArray ba = new BitArray(14);

// Turn all the even-numbered bits by calling the setter antar.
for (Int32 x = 0; x < 14; x++) {
    ba[x] = (x % 2 == 0);
}

// Show the state of all the bits by calling the getter accessor.
for (Int32 x = 0; x < 14; x++) {
    Console.WriteLine("Bit " + x + " is " + (ba[x] ? "On" : "Off"));
}
```

In the BitArray example, the indexer takes one Int32 parameter, bitPos. All indexers must have at least one parameter, but they can have more. These parameters (as well as the return type) can be of any type (except void). An example of an indexer that has more than one parameter can be found in the System.Drawing.Imaging.ColorMatrix class, which ships in the System.Drawing.dll assembly.

It's quite common to create an indexer to look up values in an associative array. In fact, the System.Collections.Generic.Dictionary type offers an indexer that takes a key and returns the value associated with it. Unlike parameterless properties, a type can offer multiple, over-loaded indexers as long as their signatures differ.

Like a parameterless property's setter accessor method, an indexer's setter accessor method also contains a parameter, called value in C#. This parameter indicates the new value for the "indexed element."

The CLR doesn't differentiate parameterless properties and parameterful properties; to the CLR, each is simply a pair of methods and a pair of metadata defined within a type. As mentioned earlier, different programming languages require different syntax to use parameter properties. The fact that C# requires[] as the syntax for expressing an indexer was purely a choice made by the C# team. This choice means that C# allows indexers to be defined only on instances of objects. C# doesn't offer syntax allowing a developer to define a static index property, although the CLR does support static particular properties.

Because the CLR treats parameterful properties just as it does parameterless properties, the compiler will emit two or three of the following items into the resulting managed assembly:

- A method representing the parameterful property's get accessor method. This is emitted only if you define a get accessor method for the property.
- A method representing the parameterful property's setter accessor method. This is emitted only if you define a setter accessor method for the property.
- A property definition in the managed assembly's metadata, which is always emitted. There's no special parameterful property definition table, to the CLR, parameterful properties are just properties.

For the BitArray class defined earlier, the compiler compiles the indexer as though the original source code were written as:

```cs
public sealed class BitArray {

    // This is the indexer's get accessor method.
    public Boolean getItem(Int32 bitPos) { /* ... */ }

    // This is the indexer's setter accessor method.
    public void setItem(Int32 bitPos, Boolean value) { /* ... */ }
}
```

The compiler automatically generates names for methods by getting get_ and set_ to the indexer name. Because the C# syntax doesn't allow the developer to specify an in-dexer name, the C# compiler had to choose a default name to use for the accessor methods; they chose Item. Therefore, the method names emitted by the compiler are get_Item and set_Item.

When examining the .NET Framework Reference document, you can tell if a type offers an indexer by looking for a property named Item. For example, the System.Collections.Generic.List offers a public instance named Item; this property is List's indexer.

When you program in C#, you never see the name of Item, you don't normally care that the compiler has this name for you. However, if you're designing an indexer for a type written in other languages you might want to change the default name, Item, by giving to your indexer get and set accessor methods. C# allows you to rename these methods by using the System.Runtime.CompilerServices.IndexerName custom attribute to the indexer. The following code demonstrates how to do this.

```cs
using System;
using System.Runtime.CompilerServices;

public sealed class BitArray{

    [IndexerName("Bit")]
    public Boolean this[Int32 bitPos] {
        // At least one accessor method is defined here
    }
}
```

Now the compiler will emit methods get_Bit and set_Bit instead of get_Item and set_Item. When compiling, the C# compiler sees the IndexerName attribute, and this tells the compiler how to name the methods and the property metadata; the attribute is not emitted into the assembly's metadata.

Here's some Visual Basic that demonstrates how to access this C# indexer.

- Construct an instance of the BitArray type.

- Visual Basic uses instead of [] to specify array elements.
  Console.WriteLine(ba(2)) - Displays True or False
- Visual Basic also allows you to access the indexer by its name.
  Console.WriteLine(ba.Bit(2)) - Displays same as previous line
