Then, M3 executes its code to construct a Manager object. This causes an instance of the Manager type, a Manager object, to be created in the heap, as shown in Figure 4-9. As you can see, the Manager object—as all objects—has an object type pointer and sync block index. This object also contains the bytes necessary to hold all of the instance data fields defined by the Manager type, as well as any instance fields defined by base classes of the Manager type (in this case, Employee and Object). Whenever a new object is created on the heap, the CLR automatically initializes the internal object type pointer member to refer to the corresponding type object (in this case, the Manager type). Furthermore, the CLR initializes the sync block index and sets all of the object's instance fields to null or 0 (zero) prior to calling the constructor's, a method that will likely modify some of the instance data fields. The new operator returns the memory address of the Manager object, which is saved in the variable e (on the stack's thread).

The next line of code calls Employee's static Lookup method. When calling a static method, the JIT compiler locates the type that corresponds to the type that defines the static method. Then, the JIT locates the entry in the type object's method table that refers to the method being called, Jits the method (if necessary), and calls the Jitted code. For our discussion, let's say that Employee's Lookup method queries a database to find Joe. Let's also say that the database indicates that Joe is a manager at the company, and internally, the Lookup method constructs a new Manager object on the heap, and returns the address of this object.
