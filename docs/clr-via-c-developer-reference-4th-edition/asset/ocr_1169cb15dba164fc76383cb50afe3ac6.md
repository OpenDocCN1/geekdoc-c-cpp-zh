When a thread pool blocks, the thread pool creates additional threads, and the time and memory resources required to create, destroy, and schedule threads is very expensive. When developers see that they have threads in their program that are not doing anything useful, they tend to create more threads in hopes that the new threads will do something useful. The key to building scalable and responsive applications is to not block the threads so that they can be used and reused to execute other tasks. Chapter 27, "Compute-Bound Asynchronous Operations," and Chapter 28, "I/O-Bound Asynchronous Operations," focused on how to use existing threads to perform compute-bound operations and how to use threads when performing I/O-bound operations.

In this chapter, I focus on thread synchronization. Thread synchronization is to prevent corruption when multiple threads access shared data at the same time. I emphasize at the same time, because thread synchronization is all about timing. If you have some data that is accessed by two threads and those threads cannot possibly touch the data simultaneously, thread synchronization is not required at all. In Chapter 28, I discussed how sections of async functions can be executed by different threads. Here we could have two different threads accessing the variables and data. But async functions can be implemented in a way that it is impossible for two threads to access this same data at the same time. Therefore, no thread synchronization is required when code data contained within the async function.

This is ideal because thread synchronization has many problems addressed with it. First, it is tedious and extremely error-prone. In your code, you must identify all data that could be touched by multiple threads at the same time. Then you must surround this with additional code that acquires and releases a thread synchronization lock. The lock ensures that only one thread at a time can access the resource. If you forget to surround just one block of code with a lock, the data will become corrupted. Also, there is no way to prove that you have added all your locking code correctly. You just have to run your application, stress-test it a lot, and hope that nothing goes wrong.
