Now, SingletonSerializationTest calls the formatter's Serialize method to serialize the array and its elements. When serializing the first Singleton, the formatter detects that the Singleton type implements the ISerializable interface and calls the GetDataObject method. This method calls SetType, passing in the SerializationHelper type, which tells the formatter to serialize the Singleton object as a SerializationHelper instead. Because AddValue is not called, no additional field information is written to the stream. The formatter automatically detected that both array elements refer to a single object, the formatter serializes one object.

After serializing the array, SingletonSerializationTest calls the formatter's Deserializer method. When deserializing, the formatter tries to deserialize a SingletonSerializationHelper object because this is how the formatter was "triggered" into serializing. (In fact, this is why the Singleton class does not provide the special constructor that is usually required when implementing the ISerializable interface.) After constructing the SingletonSerializationHelper object, the formatter sees that this type implements the System.Runtime.IObjectReference interface. This interface is defined in the FCL as:

```
public interface IObjectReference {
    Object GetRealObject(StreamingContext context);
}
```

When types implement this interface, the formatter calls the GetRealObject method. This method returns a reference to the object that you really want a reference to now deserialization of the object has completed. In my example, the SingletonSerializationHelper type GetRealObject returns a reference to the Singleton object that already exists in the AppDomain. So, when the formatter's Deserialize method returns, a2 array contains two elements, both of which refer to the AppDomain's Singleton object. The SingletonSerializationHelper object used to help with the deserialization is immediately unreachable and will be garbage collected in the future.

The second call to WriteLine displays "True," verifying that a2's array elements refer to the same object. The third and last call to WriteLine also displays "True," proving that the elements in both arrays refer to the exact same object.
