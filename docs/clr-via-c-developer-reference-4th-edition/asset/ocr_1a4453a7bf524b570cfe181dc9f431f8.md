In this code, I am using a Semaphore, but it would work just as well if I used an EventWait-Handle or a Mutex I'm not actually using the thread synchronization behavior that the kernel offers when creating any kind of kernel object. However, I am taking advantage of some thread synchronization behavior to let me explain how the preceding code works. Let's say that two instances of this process are started at the same time. Each process will have its own thread, and both will attempt to create a Semaphore with the same string name ("UniqueStringIdentifyingMyApp", in my example). Windows kernel ensures that only one thread actually creates a kernel object with the specified name; the thread will have its createdNew variable set to true.

For the second thread, Windows will see that a kernel object with the specified name already exists; the second thread does not get to create another kernel object with the same name, although if this thread continues to run, it can access the same kernel object as the first process's thread. This is how threads in different processes can communicate with each other via a single kernel object. However, in this example, the second process's thread sees that its createdNew variable is set to false. This thread now knows that another instance of this process is running, and the second instance of the process exits immediately.
