An assembly is deployed in two ways: privately or globally. A privately deployed assembly is an assembly that is deployed in the application's base directory or one of its subdirectories. A weakly named assembly can be deployed only privately. I talked about privately deployed assemblies in Chapter 2. A globally deployed assembly is an assembly that is deployed into some well-known location that the CLR looks in when it's searching for the assembly. A strongly named assembly can be deployed privately or globally. I'll explain how to create and deploy strongly named assemblies in this chapter. Table 3-1 summarizes the kinds of assemblies and how they can be deployed.

# TABLE 3-1 How Weekly and Strongly Named Can Be Deployed

| Kind of Assembly | Can Be Privately Deployed | Can Be Globally Deployed |
| --- | --- | --- |
| Weakly named | Yes | No |
| Strongly named | Yes | Yes |

# Giving an Assembly a Strong Name

If multiple applications are going to access this directory automatically the assembly must be placed in a well-known directory

Obviously, differentiating assemblies simply by a file name is not enough. The CLR needs to support some mechanism that allows assemblies to be uniquely identified. This is the term we strongly named assembly refers to. A strongly named assembly consists of four attributes that uniquely identify the assembly: a file name (without an extension), a version number, a culture and a public key. Because public keys are very large numbers, we frequently use a small hash value derived from a public key. This hash value is called a public token. The following assembly identity strings identify four different assembly files.

```
"MyTypes,Version=1.0.8123.0,Culture=neutral,PublicKeyToken=b77a5c561934e089"
"MyTypes,Version=1.0.8123.0,Culture=en-US,PublicKeyToken=b77a5c561934e089"
"MyTypes,Version=2.0.1234.0,Culture=neutral,PublicKeyToken=b77a5c561934e089"
"MyTypes,Version=1.0.8123.0,Culture=neutral,PublicKeyToken=b035f7f7d15d50a3"
```

The first identity string identifies an assembly file named MyTypes.dll (you can't determine the file extension from an assembly string). The company producing the assembly is creating version 1.0.8123.0 of this, and nothing in the assembly is sensitive to any culture Culture is set to neutral. Of course, any company could produce a MyTypes.dll (or MyTypes.exe) file that is marked with a version number of 1.0.8123 and a neutral culture.
