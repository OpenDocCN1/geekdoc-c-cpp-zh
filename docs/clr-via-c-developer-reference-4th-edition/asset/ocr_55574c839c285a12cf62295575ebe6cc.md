Now let me explain what is going on here. Upon entering the method, currentVal is initialized to the target at the moment the method starts. Then, inside the loop, startVal is initialized to this same value. Using startVal, you can perform any operation you want. This operation can be extremely complex, consisting of thousands of lines of code. Ultimately, you must end up with a result that is placed in desiredVal. In my example, I determine whether startVal or value contains the larger value.

Now, while this operation is running, another thread could change the value in the target. It is unlikely that this will happen, but it is possible. If this happens, then the value in desiredVal is based on an old value in startVal, not the current value in target, and therefore we should not change the value in target changed before our back, use Interlocked.CompareExchange. This method checks whether the value in target matches the value in startVal(which identifies the value that we thought was in target before performing the operation). If the value in target didn't change, CompareExchange changes it to the new value in desiredVal. If the value in target didn't change, then CompareExchange does not alter the value in target at all.

CompareExchange returns the value that is at the time when CompareExchange is called, which I place in currentVal. Then, a check is making startVal with the new value in currentVal. If these values are the same, then a thread did not change the target behind our back, target now contains the value in desiredVal, the while loop does not loop around, and if startVal is not equal to currentVal, then a thread did change the value in target behind our back, target did not changed to the value in desiredVal, and the while loop will loop around and try the operation again, this time using the new value in currentVal that reflects the other's change.

Personally, I have used this pattern in a lot of my code, and in fact, I made a generic method, Morph, which encapsulates this pattern.

```
delegate Int32 Morph<TResult, TArgument>(Int32 startValue, TArgument argument,
TResult morphResult);

static TResult Morph<TResult, TArgument>(ref Int32 target, TArgument argument,
Morph<TResult, TArgument> morpher) {

TResult morphResult;
Int32 currentVal = target, startVal, desiredVal;
do {
	startVal = currentVal;
	desiredVal = morpher(startVal, argument, out morphResult);
	currentVal = Interlocked.CompareExchange(ref target, desiredVal, startVal);
} while (startVal != currentVal);
return morphResult;

```

> 8 Obviously, the Morph method incurs a performance penalty due to invoking the morpher callback method. For best performance, execute the operation inline, as in the example.
