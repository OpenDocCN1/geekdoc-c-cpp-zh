When SomeType object is constructed, its m_x field will be initialized to 5. How does this hap-pen? If you examine the Intermediate Language (IL) for SomeType's constructor method (also called .ctor), you'll see the code shown here.

```

Instance .ctor() cil managed
{
    // Code size 14 (0xe)
maxstack 8
IL_0000: ldarg.0
IL_0001: ldc.i4.5
IL_0002: stfld      int32 SomeType::m_x
IL_0007: ldarg.0
IL_0008: call void [mscorlib]System.Object::ctor()
IL_000d: ret
} // end of method SomeType::ctor
```

In this code, you see that SomeType's constructor contains code to store 5 into m_x and then calls the base class constructor. In other words, the C# compiler uses the convenient syntax that lets you initialize fields inline and translates this to the constructor method to perform the initialization. What you should be aware of is code explosion, as illustrated by the following class definition.

```
internal sealed class SomeType {
    private Int32 m_x = 5;
    private String m_s = "Hi there";
    private Double m_d = 3.14159;
    private Byte m_b;

    // Here are some constructors.
    public SomeType() { }
    public SomeType(Int32 x) { ... }
    public SomeType(String s) { ...; m_d = 10; }
}
```

When the compiler generates code for these methods, the beginning of each method includes the code to initialize m_x, m_s, and m_d. After this initialization, the compiler inserts a call to the base class constructor, and then appends the code to the method methods. For example, the code generated for the constructor that takes a String parameter includes the code to initialize m_x, m_s, and m_d, call the base class (Object)'s constructor, and then overwrite m_d with the value 10. Note that m_b is guaranteed to be initialized to 0 even though no code exists to explicitly initialize it.

> Note The compiler initializes any fields by using the convenient syntax before calling a base class constructor to maintain the impression that these fields always have a value as the source code appearance dictates. The potential problem occurs when a base class's constructor invokes a virtual method that calls back into a method defined by the derived class. If this happens, the fields initialized by using the convenient syntax have been initialized before the virtual method is called.
