It is often valuable to cancel an operation after a period of time has elapsed. For example, imagine a server application that starts some work on a client request. The server application needs to respond to the client within two seconds, no matter what. In some scenarios, it is better to respond in a short period of time or with partially computed results as opposed to waiting a long time for a complete result. Fortunately, CancellationSource gives you a way to have itself-cancel after a period of time. # Tasks

Calling ThreadPool's QueueUserWorkItem method to initiate an asynchronous compute-bound operation is very simple. However, this technique has many limitations. The biggest problem is that there is no built-in way for you to know when the operation has completed, and there is no way to get a return value back when the operation completes. To address these limitations and more, Microsoft introduced the concept of tasks, and you use them via tasks in the System.Threading namespace.

So, instead of calling ThreadPool's QueueUserWorkItem method, you can do the same via tasks.

```csharp
ThreadPool.QueueUserWorkItem(ComputeBoundOp, 5); // Calling QueueUserWorkItem
new Task(ComputeBoundOp, 5).Start(); // Equivalent of preceding Task
Task.Run(() => ComputeBoundOp(5)); // Another equivalent
```

In the second line of preceding code, I am creating the Task object and immediately calling Start to schedule the task. Naturally, you can create the Task object and then call Start on it later. You could imagine code that creates a Task object and then passes it to some other method that decides when to call Start to schedule the task. Because it is common to create a Task object and then immediately call Start on it, you can call Task's convenient static run method as shown on the last line of the preceding code.

When creating a Task, a constructor, passing an Action or an Action<Object> delegate that you performed. If you pass a method that expects an Object, you must also pass to Task's constructor the argument that you ultimately passed to the operation. When calling Run, you can pass an Action or Func<TResult> delegate indicating the operation you performed. When calling a constructor or calling Run, you can optionally pass a CancellationToken, which allows the Task to be canceled before it has been scheduled (see the "Canceling a Task" later in this chapter).

You can also pass to the constructor some TaskCreationOptions flags that control how the Task executes. TaskCreationOptions is an enumerated type defining a set of flags that you can bitwise-OR together. It is defined as follows:

```csharp
[Serializable]
public enum TaskCreationOptions {
 None = 0x0000,// The default
// Hints to the Task that you want this task to run sooner than later.
 PreferFairness = 0x0001,
// Hints to the TaskScheduler that it should more aggressively create thread pools.
 LongRunning = 0x0002,
// Always honored: Associates a Task with its parent Task (discussed shortly)
 AttachedToParent = 0x0004,
// If a task attempts to attach to this parent task, it is a normal task, not a child task.
 DenyChildAttach = 0x0008,
// Forces child tasks to use the default scheduler as opposed to the parent's scheduler.
 HideScheduler = 0x0010
}
```

Some of these flags are hints that may or not be honored by the TaskScheduler that is being used to schedule a Task; the AttachedToParent, DenyChildAttach, and HideScheduler flags are always honored, because they have nothing to do with the TaskScheduler itself. TaskScheduler objects are discussed later in the "Task Schedulers" section.

# Waiting for a Task to Complete and Getting Its Result

With tasks, it is also possible to wait for them to complete and get their result. Let's say that we have a Sum that is computationally intensive if n is a large value.

```csharp
private static Int32 Sum(Int32 n) {
    Int32 sum = 0;
    for (; n > 0; n--)
        checked { sum += n; } // if n is large, this will throw System.OverflowException
    return sum;
}
```

We can construct a Task<TResult> object (which is derived from Task), and we pass for the generic TResult among the compute-bound operation's return type. Now, after starting the task, we can wait for it and get its result using the following code.

```csharp
// Create a Task (it does not start running)
Task<Int32> task = new Task<Int32>(Sum, 10);
task.Start();

// Wait for the task and get the result
Int32 result = task.Result;
Console.WriteLine("Result: {0}", result);
```
