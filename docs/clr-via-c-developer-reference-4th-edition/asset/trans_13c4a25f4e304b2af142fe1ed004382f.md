- **较差的运行时性能**：在编译为代码时，NGen 无法像 JIT 编译器那样对执行环境做出任何假设。这导致 NGen 生成的代码性能较差。例如，NGen 不会优化某些 CPU 指令的用法；它为静态字段访问添加了间接层，因为静态字段的实际地址直到运行时才未知。NGen 在各处插入了调用类构造函数的代码，因为并不知道代码执行的顺序，也不确定是否已经调用过类构造函数。（有关关于类构造函数的更多信息，请参阅第 8 章“方法”。）与 JIT 编译的对应程序相比，某些经过 NGen 的应用程序运行速度实际上慢了约 5%。因此，如果您考虑使用 NGen.exe 来提高应用程序的性能，您应该比较 NGen 版本和非 NGen 版本，以确保 NGen 版本实际上没有让运行变慢！对于某些应用程序，工作集的减少可以提高性能，因此使用 NGen 可能是一个净收益。

由于上述列出的所有问题，您在考虑使用 NGen.exe 时应该非常小心。对于服务器端应用程序，NGen.exe 几乎或没有任何意义，因为只有第一个客户端请求会受到性能影响；后续客户端请求将以高速运行。此外，对于大多数服务器应用程序，只需要一个代码实例，因此没有工作集的优势。

对于客户端应用程序，如果一个程序集同时被多个应用程序使用，则 NGen.exe 可能对于提高启动时间或减少工作集具有意义。即使在程序集被多个应用程序使用的情况下，对程序集进行 NGen 处理也可以改善工作集。此外，如果使用 NGen.exe 处理客户端应用程序的所有程序集，则 CLR 将不需要加载 JIT 编译器，从而进一步减少工作集。例如，如果只有一个程序集没有经过 NGen 处理，或者某个程序集的 NGen 文件无法使用，则会加载 JIT 编译器，应用程序的工作集随之增加。

对于启动时间较长的大型应用程序，微软提供了托管引导优化工具 (MPGO.exe)。该工具分析应用程序的执行情况，以查看其启动时需要什么。这些信息会被传递给 NGen.exe 工具，以便更好地优化生成的映像。这允许您的应用程序启动更快且工作集更少。当您准备好发布应用程序时，通过 MPGO 工具启动它，然后执行应用程序的常用任务。关于执行代码部分的信息会被写入配置文件，该文件嵌入在您的程序集文件中。NGen.exe 工具使用此配置文件来更好地优化其生成的原生映像。

# 框架类库 (The Framework Class Library)

.NET Framework 包含了框架类库 (FCL)。FCL 是一组 DLL 程序集，包含数千个类型定义，每个定义都暴露了某些功能。微软正在制作额外的库，例如 Windows Azure SDK 和 DirectX SDK。额外的库提供了更多类型，为您的使用暴露了更多功能。事实上，微软正在以惊人的速度生产许多库，让开发者使用各种微软技术比以往任何时候都更容易。

以下是开发者使用这些程序集可以创建的应用程序类型示例：

- **Web 服务**：使用微软的 ASP.NET XML Web 服务技术或微软通信基础 (WCF)，方法可以非常容易地处理通过互联网发送的消息。
- **Web Forms/MVC**：基于 HTML 的应用程序（网站）。通常，ASP.NET 将执行数据库查询和 Web 服务调用，合并并过滤返回的信息，然后通过任何基于 HTML 的用户界面在浏览器中显示这些信息。
- **富 Windows 应用程序 (Rich Windows applications)**：通过 .NET 框架提供的类型，可以轻松与任何基于 HTML 的用户界面进行交互。
- **控制台应用程序 (Console applications)**：使用 .NET 框架提供的类型，可以轻松创建应用程序。
- **Windows 服务 (Windows services)**：使用 .NET 框架提供的类型，可以轻松创建服务。
- **数据库存储过程 (Database stored procedures)**：使用 .NET 框架提供的类型访问数据库。
- **组件库 (Component library)**：使用 .NET 框架提供的类型创建组件。
