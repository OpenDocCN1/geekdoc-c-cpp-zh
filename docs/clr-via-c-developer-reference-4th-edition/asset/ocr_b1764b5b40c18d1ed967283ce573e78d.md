Important Symbols defined by an enumerated type are constant values. When a compiler sees code that references an enumerated type's symbol, the compiler substitutes the symbol's numeric value at compile time, and this code no longer references the enumerated type defined the symbol. This means that the assembly that defines the enumerated type may not be required at runtime; it was only when compiling. If you have code that references the enumerated type—rather than having references to symbols defined by the type—the assembly containing the enumerated type's definition will be required at run time. Some versioning issues arise because enumerated type symbols are constants instead of read-only values. I explained these in the "Constants" section of Chapter 7, "Constants and Fields."

For example, the System.Enum has a static method called GetUnderlyingType, and the System.Type has an instance method called GetUnderlyingType.

```
public static Type GetUnderlyingType(Type enum); // Defined in System.Enum
public Type GetUnderlyingType();                                 // Defined in System.Type
```

These methods use the core type to hold an enumerated type's value. Every enumerated type has an underlying type, which can be a byte, sbyte, short, int (the most common type and C# choices by default), uint, long, or long. Of course, the C# primitive types correspond to FOL. However, to make the implementation of the compiler itself, the C# compiler requires you to specify a primitive type here; using an FCL name (such as Int32) uint, long, or long expected. The following code shows how to declare an enumerated type with an underlying type of byte (System.Byte).

```
internal enum Color : byte {
    White,
Red,
Green,
Blue,
Orange
}
```

With the Color enumerated type defined in this way, the following code shows what Get-UnderlyingType will return.

```
// The following line displays "System.Byte".
Console.WriteLine(Enum.GetUnderlyingType(typeof(Color)));
```
