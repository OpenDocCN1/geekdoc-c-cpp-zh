```
C:\AppDir\en\AsName.dll

C:\AppDir\firstPrivatePath\en\AsName.dll

```

```
C:\AppDir\en\AsName.exe
C:\AppDir\en\AsName.exe

C:\AppDir\firstPrivatePath\en\AsName.exe
C:\AppDir\secondPrivatePath\en\AsName.exe
C:\AppDir\secondPrivatePath\en\AsName.exe
```

As you can see, the CLR probes for files with either .exe or .dll extension. Because probing can be very time-consuming (especially when the CLR is looking for files over a network), in the XML configuration file you can specify one or more culture elements to limit the probing the CLR performs when looking for satellite assemblies. Microsoft provides a FusLog tool you can use to see how the CLR is binding to assemblies at run. For more information about it, see http://msdn.microsoft.com/en-us/library/e7a18c4(v=vs.110).aspx.

The name and location of this XML configuration file is different depending on the application type:

+   * For executable applications (EXEs), the configuration file must be in the application's directory, and it must be the name of the EXE file with ".config" appended to it.
* For Microsoft ASP:NET Web Forms, the file must be in the Web application's virtual root directory and is always named Web.config. In addition, subdirectories also contain their own Web.config file, and the configuration settings are inherited. For example, a Web application located at http://Intellect.com/Training would use the settings in the Web.config files contained in the virtual root directory and in its Training subdirectory.

As mentioned at the beginning of this section, configuration settings apply to a particular application and to the machine. When you install the .NET Framework, it creates a Machine.config file. There is one Machine.config file per version of the CLR you have installed on the machine.

The Machine.config file is located in the following directory:

```
%SystemRoot%\Microsoft.NET\Framework\version\CONFIG
```

Settings in the Machine.config file define settings that all applications running on the machine. An administrator can create a machine-wide policy by modifying the settings Machine.config file. However, administrators and users should avoid modifying this file because it contains many settings related to various things, which makes it much more difficult to navigate. Plus, you want the application's settings to be backed up and restored, and keeping an application's settings in the application-specific configuration file enables this.
