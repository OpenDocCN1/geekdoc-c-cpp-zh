Note For the curious, metadata tokens are 4-byte. The high byte indicates the type of token (0x01=Ref, 0x02=AssemblyRef, 0x26=File (file definition), 0x27=ExportedType). For the complete list, see the CorToken enumerated type in the CorH.h file included with the .NET Framework SDK. The higher bytes of the token simply identify the row in the corresponding metadata table. For example, the implementation token 0x26000001 refers to the first row of the File table. Any client code that uses the MultiFileLibrary.dll assembly must be built using the [/reference]: MultiFileLibrary.dll compiler switch. This switches the compiler to the MultiFileLibrary.dll assembly and all of the files listed in its FileTable when searching for an type. The compiler requires all of the assemblies to be installed and accessible. If you were to delete the RUT.netmodule file, the C# compiler would produce the following fatal error CS00009: Metadata file 'C:\MultiFileLibrary.dll' could not be opened-'Error importing module 'RUT.netmodule' of assembly 'C:\MultiFileLibrary.dll'-The system cannot find the file specified.'This means that to build a new assembly, all of the files from the referenced assembly must be present.

As the client code executes, it calls methods. When a method is called for the first time, the CL detects the type references as a parameter, a return type, or as a local variable. The CL then attempts to load the referenced assembly's file that contains the manifest. If the type being accessed is in this file, the CL performs its internal bookkeeping, allowing the type to be used. If the manifest indicates that the referenced type is in a different file, the CL attempts to load the necessary file, and allows the type to be accessed. CL loads assemblies only when a method referencing a type in an unloaded assembly is called. This means that to run an application, all of the files from a referenced assembly do not need to be present.
