# Object Hash Codes

The designers of the FCL decided that it would be incredibly useful if instance of any object could be placed into a hash table. To this end, System.Object provides a virtual GetHashCode method that an Int32 hash code can be obtained for any and all objects.

If you define a type and override the Equals method, you should also override the GetHashCode method. In fact, Microsoft's C# compiler warns you if you define a type that overrides Equals without overriding GetHashCode. For example, compiling the following type yields this warning: warning CS0659: 'Program' overrides Object.Equals(object o) but does not override Object.GetHashCode().

```
public sealed class Program {
    public override Boolean Equals(Object obj) { ... }
}
```

The reason that a type defines Equals must also define GetHashCode is that the implementation of the System.Collections.Hashtable, the System.Collections.Generic.Dictionary type, and other collections require that any two objects that are equal have the same hash value. So if you override Equals, you should override GetHashCode to ensure that the algorithm you use for calculating equality corresponds to the algorithm you use for calculating the object's hash code.

Basically, when you add a key/value pair to a collection, a hash code for the key object is obtained first. This hash code indicates which "bucket" the key/value pair should be stored in. When the collection needs to look up a key, it gets the hash code for the specified object. This code identifies the "bucket" that is searched sequentially, looking for a stored object that is equal to the specified object. Using this algorithm of storing and looking up keys means if you change a key object in a hash table, the collection will no longer be able to find the object. If you intend to change a key object in a hash table, you should remove the original key/value pair, modify the key object, and add the new key/value pair back into the hash table.

Defining a GetHashCode method can be easy and straightforward. But depending on your data types and the distribution of data, it can be tricky to come with a hashing algorithm that returns a well-distributed range of values. Here's a simple example that probably work fine for Point objects.

```
internal sealed class Point {
    private readonly Int32 m_x, m_y;
    public override Int32 GetHashCode() {
        return m_x ^ m_y; // m_x XORed with m_y
    }
}
```
