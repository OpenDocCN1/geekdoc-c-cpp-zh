I can now have code that constructs a Classroom object and initializes the Students collection as follows.

```
public static void M() {
Classroom classroom = new Classroom {
    Students = { "Jeff", "Kristin", "Aidan", "Grant" };
}
```

```
// Show the 4 students in the classroom
foreach (var student in classroom.Students)
    Console.WriteLine(student);
```

When compiling this code, the compiler sees that the Students property is of type List<String> and that this type implements the IEnumerable<String> interface. Now, the compiler assumes that the List<String> type offers a method Add (because collection classes actually offer an Add method that adds items to the collection). The compiler generates code to call the collection's Add method. So, the preceding code is converted by the compiler into the:

```
public static void M() {
Classroom classroom = new Classroom();
classroom.Students.Add("Jeff");
classroom.Students.Add("Kristin");
classroom.Students.Add("Aidan");
classroom.Students.Add("Grant");
```

```
// Show the 4 students in the classroom
foreach (var student in classroom.Students)
    Console.WriteLine(student);
```

If the property's type implements IEnumerable or IEnumerable<T> but the type doesn't offer an Add method, then the compiler does not let you use the collection syntax to add items to the collection; instead, the compiler issues the following message: error CS0117: 'System.Collections.Generic.IEnumerable<string>' does not contain a definition for 'Add'.

Some Add methods take multiple arguments—for example, Dictionary's Add method.

```
public void Add(TKey key, TValue value);
```

You can pass multiple arguments to an Add method by using nested braces in a collection initializer.

```
var table = new Dictionary<String, Int32> {
    { "Jeffrey", 1 }, { "Kristin", 2 }, { "Aidan", 3 }, { "Grant", 4 } };
```
