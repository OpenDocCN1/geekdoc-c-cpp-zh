# Syntactical Shortcut #2: No Need to Define a Callback Method (Lambda Expressions)

In the preceding code, the name of the callback method, SomeAsyncTask, is passed to the Thread-Pool's QueueUserItem method. C# allows you to write to the callback method inline so it doesn't have to be written in its own method. For example, the preceding code could be rewritten as follows:

```
internal sealed class CLASS {
public static void CallbackWithoutNewingDelegateObject(){
    ThreadPool.QueueUserItem(obj) => Console.WriteLine(obj), 5);
}
```

Notice that the first "argument" is to the QueueUserItem method code (which I italicized!) More formally, the italicized code is a C# lambda expression, and it is easy to detect due to the use of C#'s lambda expression: =>. You may use a lambda expression in your code where the compiler would normally expect to see a delegate. And when the compiler sees the use of this lambda expression, the compiler automatically defines a new method in the class (in this example, this new method is called an anonymous function because the compiler creates the name of the method for you automatically, and normally, you wouldn't know its name. However, you could use such as ILasm.exe to examine it was able to see, by using ILasm.exe, the C# compiler compiled this name to CallbackWithoutNewingDelegateObject->b_0 and ensured that the method took a single Object argument and returned void.

The compiler chooses to start method name with a < sign as in C#, an identifier cannot contain a < sign; this ensures that you will not accidentally define a method that coincides with the name the compiler has chosen for. Incidentally, while C# forbids identifiers to contain a < sign, the CLR allows it. Also, note that although you could access the method via reflection by passing the method name as a string, the C# language specifies that there is no guarantee of how the compiler generates the name. For example, each time you compile the code, the compiler could produce a different name for the method.

Using ILasm, you might notice that the C# compiler applies the System.Runtime.CompilerGeneratedAttribute attribute to this method to indicate to tools and utilities that this was produced by a compiler as opposed to a programmer. The code to the right of the => operator is then placed in this compiler-generated method.

> When writing a lambda expression, there is no way to apply your custom attribute to the compiler-generated method. Furthermore, you cannot apply any modifiers (such as unsafe) to the method. This is usually not a problem because anonymous methods generated by the compiler always end up private, and the method is either static or static depending on whether the method accesses any instance members. So there is no need to apply modifiers as public, protected, internal, virtual, sealed, override, or abstract to the method.
