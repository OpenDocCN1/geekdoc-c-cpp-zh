Recall that unboxed value types are lighter-weight types than reference types for two reasons:

+   - They are not allocated on the managed heap.

+   - They don't have the additional overhead members that every object on the heap has: a type object pointer and a sync block index.

Because unboxed value types don't have a sync block index, you can't have multiple threads synchronize their access by using the methods of the System.Threading.Monitor (or using C#'s lock statement).

Even though unboxed value types don't have a type object pointer, you can still call virtual methods (such as Equals, GetHashCode, or ToString) inherited or overridden by them. If your value type overrides one of these virtual methods, then the CLR can invoke the method nontrivially because implicitly sealed and cannot have any types derived from them. In addition, the value type instance used to invoke the virtual method is not boxed. However, if your override of the virtual method calls into the base type's implementation of the method, then the value instance itself gets boxed when calling the base type's implementation so that a reference to a heap object gets to this pointer in the base method.

However, calling a noninherited method (such as GetType or MemberwiseClone) always requires the value type to be boxed because these methods are defined by System.Object, so the methods expect this argument to be a reference that refers to an object on the heap.

In addition, casting an unboxed instance of a value type to one of the type's interfaces requires the instance to be boxed, because interface variables must always contain a reference to an object on the heap.(I'll talk about interfaces in Chapter 13, "Interfaces.") The following code demonstrates.

```
System;

internal struct Point : IComparable {
    private Int32 m_x, m_y;

    // Constructor to easily initialize the fields
    public Point(Int32 x, Int32 y) {
        m_x = x;
        m_y = y;
    }

    // Override ToString inherited from System.ValueType
    public override string ToString() {
        // Return the value as a string. Note: calling ToString prevents boxing
        return String.Format("{0}, {1}", m_x.ToString(), m_y.ToString());
    }

    // Implementation of type-safe CompareTo method
    public Int32 CompareTo(Point other) {
        // Use the Pythagorean theorem to calculate
        // which point is farther from the origin (0,0)
        return Math.Sqrt(m_x * other.m_x + m_y * other.m_y);
    }
```
