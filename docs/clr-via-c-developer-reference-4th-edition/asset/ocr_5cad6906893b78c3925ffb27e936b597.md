Now, I will discuss what this code does and the CLR doing.

Inside the Marshalling method, I get a reference to an AppDomain object that identifies the
Domain calling thread is currently executing in. Windows, a thread is always created in the
context of one process, and the thread lives its entire lifetime in that. However, a one-to-one
correspondence does not exist between threads and AppDomains. AppDomains are a CLR feature;
Windows knows how multiple AppDomains can be in a single
Windows process, a thread can execute code in one AppDomain and then execute code in another
AppDomain. From the CLR's perspective, a thread is executing code in one AppDomain at a time. A
thread can ask the CLR what AppDomain it is currently executing in calling Thread.ing.
Thread's static GetDomain method. The thread could also query System.AppDomain's static, read-
only CurrentDomain property to get the same information.
