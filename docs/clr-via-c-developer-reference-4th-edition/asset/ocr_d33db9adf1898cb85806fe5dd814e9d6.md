private void ReportStatus(CoordinationStatus status) {
// If status has not been reported, report it; else ignore it
if (Interlocked.Exchange(ref m_statusReported, 1) == 0)
m_callback(status);
} }

The most important in this field is the m_opCount field. This field keeps track of the number of asynchronous operations that are still outstanding. AboutToBegin this method calls Interlocked.Add to the number passed to the m_opCount field must be performed atomically because web servers will be processing responses on thread pools as more operations are being started. As server responses are processed, JustEnded is called. This method calls Interlocked.Decrement to atomically subtract 1 from m_opCount. Whichever thread has set m_opCount to 0 calls ReportStatus.

![](bbox=[0.058, 0.493, 0.098, 0.532])

> Note The m_opCount field is initialized to 1 (not 0); this is critically important because it ensures A1Begin is not invoked while the thread executing the constructor is still issuing web requests. Before the constructor calls there is no way that m_opCount will ever reach 0. When the constructor calls A1Begin, A1Begin internally calls JustEnded, which decrements m_opCount and effectively undoes the effect of initializing it to 1. Now, m_opCount can reach 0, but only after we know that all the server requests have been initiated.

The ReportStatus arbitrates the race that can occur among all the operations completing, the timeout occurring, and Cancel being called. ReportStatus must make sure that only one of these conditions is satisfied by the winner so that the m_callback method is invoked only once. Arbitrating the winner is done via Interlocked.Exchange, passing a reference to the m_statusReported field. This field is really treated as a Boolean variable; however, it can't actually be a Boolean variable because there are no Interlocked methods that accept a Boolean variable. So I use an Int32 where means 0 false and 1 true.

Inside ReportStatus, the Interlocked.Exchange will change m_statusReported to 1. But only the first thread to do this will see Interlocked.Exchange returns a 0, and only this thread will invoke the callback method. Any other thread that call Interlocked.Exchange will get a return value of 1, effectively notifying these threads that the callback has already been invoked and it should not be invoked again.
