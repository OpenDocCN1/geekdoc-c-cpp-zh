# 14. 在许多情况下优先使用 auto。

我不是一个几乎总是使用 auto（AAA）的人，但让我问你这个问题：std::count 的结果类型是什么？

我的回答是，“我不在乎。”

```cpp
const auto const auto result = std::count( /* stuff * / );
```

或者，如果你更喜欢：

auto const

```cpp
auto const result = std::count( /* stuff * / );
```

使用 auto 避免不必要的转换和数据丢失。与基于范围的 for 循环相同。auto 需要初始化，与 const 相同，其良好理由相同。

示例：

可能的昂贵转换。

```cpp
const std::string value = get_string_value();
```

get_string_value() 的返回类型是什么？如果它是 std::string_view 或 const char *，我们将在所有编译器上得到潜在的昂贵转换而没有任何诊断。

Prefer auto in Many Cases.

没有可能的昂贵转换。

```cpp
// avoids conversion
const auto value = get_string_value();
```

此外，auto 返回类型实际上可以显著简化通用代码。

C++ 98 模板用法。

```cpp
// our example from "Don't Be Afraid of Templates"
template<typename> Arithmetic
divide(Arithmetic numerator, Arithmetic denominator) {
    return numerator / denominator;
}
```

这段代码迫使我们对分子和分母使用相同的类型（试试看，你会得到奇怪的编译错误）。

C++ 98 模板变得更通用？

```cpp
template<typename Numerator, typename Denominator>
/*what's the return type*/
ddivide(Numerator numerator, Denominator denominator) {
    return numerator / denominator;
}
```

C++98 对此问题没有解决方案，但 C++11 有。

Prefer auto in Many Cases.

C++11 尾随返回类型。

```cpp
// use trailing return type
template<typename Numerator, typename Denominator>
auto divide(Numerator numerator, Denominator denominator)
-> decltype(numerator / denominator)
{
  return numerator / denominator;
}
```

但在 C++14 中，我们可以完全省略返回类型（记得跳过 C++11）。

C++14 auto 返回类型。

```cpp
template<typename Numerator, typename Denominator>
auto divide(Numerator numerator, Denominator denominator)
{
  return numerator / denominator;
}
```

# 15. 优先使用基于范围的循环语法而不是旧式循环

我们将通过一系列示例来说明这一点。

```cpp
for (int std::size_t i = 0; i < container.size(); ++i) {
  // oops mismatched types
}
```

循环时容器不匹配。

```cpp
for (auto itr = container.begin();
  itr != container2.end();
  ++itr) {
  // oops, most of us have done this at some point
}
```

基于范围的循环示例。

```cpp
for(const auto &element : container) {
  // eliminates both other problems
}
```

> 在基于范围的 for 循环内部迭代时，切勿修改容器本身。

# 16. 在基于范围的 for 循环中使用 auto

不使用 auto 会使代码中出现静默错误变得更容易。

意外转换

```cpp
for (const int value : container_of_double) {
    // accidental conversion, possible warning
}
```

意外切片

```cpp
for (const base value : container_of_derived) {
    // accidental silent slicing
}
```

没有问题

```cpp
for (const auto &value : container) {
    // no possible accidental conversion
}
```

Prefer:

- const auto & 用于非修改循环
- auto & 用于修改循环
- auto && 仅在你需要处理像 std::vector<bool> 这样奇怪的类型时，或在从容器中移动元素时才使用

# 17. 优先使用算法而不是循环

算法传达了含义并帮助我们应用“const All The Things”规则。在 C++20 中，我们获得了 ranges，这使得算法的使用更加舒适。

采用函数式方法并使用算法，我们可以编写读起来像一句句子的 C++。

算法终局

```cpp
const auto has_value = std::any_of(begin(container), end(container), greater_than(12));
```

请注意，在某些罕见情况下，你的静态分析工具可能能够建议使用算法。

# 18. 不要害怕模板

模板是 C++ 中终极的 DRY 原则。模板可能很复杂、令人望而生畏，并且是图灵完备的，但它们不必如此。十五年前，似乎普遍的态度是“模板不是给普通人用的”。

幸运的是，今天这种情况已不那么明显。而且我们今天拥有更多工具，概念、通用 lambda 等等。

我们将在接下来的几章中构建一个示例。假设我们想编写一个函数来除任意两个值。

除以 double。

```cpp
double divide(double numerator, double denominator) {
    return numerator / denominator;
}
```

但你并不希望所有的除法都被提升为 double。

除以 float。

```cpp
float divide(float numerator, float denominator) {
    return numerator / denominator;
}
```

当然，你还想处理某种整数值。
