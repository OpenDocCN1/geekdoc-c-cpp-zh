In the final set of sections of this chapter, some sophisticated data structures are introduced. They allow, in most cases, the simulation data to be organized in a way that suits the given problem better and allows for quicker processing. Here, we present *lists*, *trees*, and *graphs*, together with some sample algorithms to create, modify and use them.

Once you have a little experience—a kind of library of samples in your head—this will become increasingly easier for you. In fact, many more data structures, usually based on the basic data structures presented here, and an overwhelming number of algorithms acting on these data structures exist. If you want to learn more, you should consult more specialized textbooks like Refs. [Aho et al. (1974); Cormen et al. (2001); Sedgewick (1990)].

For an arbitrary algorithm, to describe the dependence between a suitably chosen measure `n` of the problem size and the running time `T`, the 𝒪 notation is used.

### Definition 6.1

Let `T, g : ℕ → ℝ` be two real-valued functions. We write `T(n) = 𝒪(g(n))`, if there exist two positive numbers `c₁, c₂ > 0` and an integer `n₀`, such that `c₁g(n) ≤ T(n) ≤ c₂g(n)` is valid for all `n > n₀`. We say, `T(n)` is of order of `g(n)`.

Since constants are ignored when using the 𝒪 notation, one speaks of the *asymptotic* running time or *time complexity*. In theoretical computer science, usually one states an upper bound over all possible inputs of size `n`, i.e., the *worst-case running time*.

As an example, we look at a function which adds up `n` numbers:

The “summation algorithm” takes `C × n`, i.e. `O(n)`. Note that in this case the running time basically does not depend on the actual numbers which are summed up, i.e. the worst-case running time equals the typical running time. Nevertheless, there are examples where the running time might depend drastically on the actual problem instance given.

In Table 6.1, orders of running times which typically occur in the context of algorithms are presented, accompanied by the resulting values for problem sizes 10, 100, and 1000.

Table 6.1. Growth of functions as a function of input size `n`.

| T(n) | T(10) | T(100) | T(1000) |
|---|---:|---:|---:|
| n | 10 | 100 | 1000 |
| n log n | 10 | 200 | 3000 |
| n² | 10² | 10⁴ | 10⁶ |
| n³ | 10³ | 10⁶ | 10⁹ |
| n<sup>log n</sup> | 10 | 10⁴ | 10⁹ |
| 2ⁿ | 1024 | 1.3 × 10³⁰ | 1.1 × 10³⁰¹ |
| n! | 3.6 × 10⁶ | 10¹⁵⁸ | 4 × 10²⁵⁶⁷ |

Usually one considers problems easy if the running time is bounded by a polynomial; all others are considered hard. The reason can be understood from the table: Even if polynomial functions may take higher values for small `n`, asymptotically non-polynomial functions diverge much faster. Let us consider, e.g., the relative performance of two computers, one being twice as fast as the other. In a linear-time problem, the faster computer is able to solve a problem twice as large as the problem solvable in the same time on the slower computer. If the running time grows, however, as 2ⁿ, the faster computer is just able to go from `n` to `n + 1` compared with the slower one. We see that for such hard problems, the utility of higher-speed computers is very limited—a substantial increase in the size of solvable problems can only be achieved via the use of better algorithms.

## 6.2 Iteration and recursion

If a program has to perform many similar tasks, this can be expressed as an iteration, also called a loop, e.g. with the `for` statement from C/C++. Sometimes it is more convenient to use the concept of recursion, especially if the quantity to be calculated has a recursive definition. One speaks of recursion if an algorithm/function calls itself (maybe indirectly through other algorithms/functions). As a simple example, we present a C function for the calculation of the factorial `n!` of a natural number `n > 0`. Its recursive definition is given by:

`n! = { 1 if n = 0 or n = 1; n × (n − 1)! otherwise }` (6.1)

This definition can be translated directly into a C function:

```c
int factorial(int n)
{
    if(n <= 1)
        return(1);
    else
        return(n*factorial(n-1));
}
```

In line 3, the test is whether `n ≤ 1` instead of testing for `n = 0` or `n = 1`. Therefore, it is guaranteed that the algorithm returns something on all inputs.

# The Utility of Knowledge in Inductive Learning

K. Branting

Department of Computer Science, University of Waterloo, Waterloo, Ontario N2L 3G1, Canada

Abstract. A primary motivation for “hybrid” learning systems is that domain knowledge can reduce the number of training instances needed for inductive learning. However, no formal account has yet been proposed of the relationship between domain knowledge and inductive bias. This paper presents a formal framework for analyzing the utility of knowledge in inductive learning that is based on the notion of inductive bias as a partial ordering over hypotheses. For concrete illustration, the framework is applied to a connectionist learning system.

## 1 Introduction

The utility of domain knowledge in inductive learning is an issue of widespread interest. In many learning tasks, only a limited number of training instances are available, and some form of pre-existing knowledge may be the only means of adequately constraining the induction. For this reason, “hybrid” learning systems have been proposed that combine some form of domain knowledge with inductive learning from training instances. Many such systems have been shown experimentally to achieve higher predictive accuracy on tasks in their domains than purely inductive systems (see Section 5). However, there is as yet no formal account of why domain knowledge is useful in induction.

This paper proposes a framework for analyzing the utility of domain knowledge in inductive learning. The framework is based on a formalization of inductive bias as a partial ordering over hypotheses. The claim to be established is that the prior knowledge, or bias, of a learning system affects the number of training instances required to identify a target hypothesis. In particular, for a class of learning systems which are consistent Bayes classifiers, it can be shown that a system whose bias is a stronger ordering on a class of hypotheses requires fewer instances to identify a target hypothesis than a system that has a weaker ordering.

For concreteness, this analysis of bias is applied to the “recursive sigmoidal” network of [2], a novel connectionist architecture. The recursive sigmoidal network can be given a prior ordering on hypotheses with a direct connectionist interpretation, and, for such prior orderings, a bound on the number of instances needed for learning can be determined. This provides a theoretical basis for the experimentally demonstrated utility of initial connectionist knowledge.

The plan of this paper is as follows. Section 2 defines the form of inductive learning and inductive bias to which this analysis applies. Section 3 describes the recursive sigmoidal network of [2]. Section 4 uses the framework of Sections 2 and 3 to derive a sample bound for recursive sigmoidal networks. Section 5 discusses related and future work, and Section 6 presents some conclusions.
