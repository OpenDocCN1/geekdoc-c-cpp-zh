
I/O 操符会导致 `num` 值的格式化与不使用任何操符时不同。这些操符的声明并不在常用的 `iostream` 头文件中，而是在一个名为 `iomanip` 的单独头文件中：

```
#include <iomanip>
```

## 为什么需要新的 I/O 库？
考虑下面这个 C 程序：

```cpp
#include <stdio.h>
int main(void) {
    char a = 'a';
    char *b = "a string";
    double c = 3.14;

    printf("a = %d\n b = %d\n c = %d\n", a, b, c);
}
```

编译并执行时，该 C 程序会产生以下输出：

```
a = 97
b = 72688
c = -171818680
```

为什么？因为参数的类型和数量是由格式化字符串决定的，这由程序员来确保其正确。这里是用 C++ 编写的相同程序：

```cpp
#include <iostream>
using namespace std;
int main() {
    char a = 'a';
    char *b = "a string";
    double c = 3.14;

    cout << "a = " << a << endl;
    cout << "b = " << b << endl;
    cout << "c = " << c << endl;
}
```

编译并执行时，该 C++ 程序产生：

```
a = a
b = a string
c = 3.14
```

类型解析的负担从程序员身上被卸除了，因此减少了错误的概率。编译器根据参数的类型选择正确的输出运算符实例，或者在编译时将该调用标记标记为错误。

在 C++ 中，实际上为每种类型都定义了不同的输出运算符：

```cpp
class ostream : public virtual ios {
public:
    ostream& operator<<(int);
    ostream& operator<<(long);
    ostream& operator<<(float);
    ostream& operator<<(char);
    // ...
};
```

现在先不要担心语法。但请记住，程序员通过运算符重载机制屏蔽了这些多个实例的影响：

```cpp
cout << i << " " << << << f << '\n';
```

## iostream 库是可扩展的

在 C 中输出一个自定义类型，程序员必须提供一个唯一命名的自定义打印函数，而该类型的用户必须查找或记住该函数的名称和接口。例如：

```cpp
#include <stdio.h>

struct date {
    int month;
    int day;
    int year;
};

void printDate(struct date *pd) {
    printf("%d/%d/%d", pd->month, pd->day, pd->year);
}

void main(void) {
    struct date d = { 9, 18, 2012 };

    printf("Today's date is % ");
    printDate(&d);
    printf("\n");
}
```

在 C++ 中，自定义类型的的设计者为该类型提供一个输出运算符的实例。该类型的客户端不需要了解其输出是如何处理的。例如：

```cpp
#include <iostream>

using namespace std;

struct date {
    int month;
    int day;
    int year;
};

ostream& operator<<(ostream& os, date &d) {
    os << d.month << "/" << d.day << "/" << d.year;
    return os;
}

int main() {
    struct date d = { 9, 18, 99 };

    cout << "Today's date is " << d << endl;
}
```

同样，现在不需要担心语法问题。

## 字符串变量与常量

考虑以下 C++ 程序：

```cpp
#include <iostream>
using namespace std;

const int MAX = 50;

int main() {
    char buf[MAX];

    cout << "Enter a string: ";
    cin >> buf;
    cout << "You entered: " << buf;
}
```

如果用户输入的字符串比用于存储它的数组要长会发生什么？很简单。我们会覆盖内存。那么，我们该如何避免缓冲区溢出呢？我们可以告诉 `>>` 运算符限制它置于数组中的字符数：

```cpp
#include <iostream>
#include <iomanip>

using namespace std;

const int MAX = 50;

int main() {
    char buf[MAX];

    cout << "Enter a string: ";
    cin >> setw(MAX) >> buf;
    cout << "You entered: " << buf;
}
```

该程序使用 `setw()` 操符来指定输入缓冲区可以接受的最大字符数。用户可能会输入更多字符，但 `>>` 运算符不会将它们插入数组。实际上，插入的字符数比指定的数字少一个，因此缓冲区中留有空间来存放终止的空字符。

注意：提取操符（`>>`）将空格视为终止字符。因此，字符串由空格分隔，在空格之后键入任何内容都会被丢弃。

## 读取带空格的字符串

为了读取包含空格的文本，我们可以使用另一个函数 `cin.get()`，它调用了 `cin` 流类的成员函数 `get()`。

```cpp
#include <iostream>

using namespace std;

const int MAX = 50;

int main() {
    char buf[MAX];

    cout << "Enter a string: ";
    cin.get(buf, MAX);
    cout << "You entered: " << buf;
}
```
