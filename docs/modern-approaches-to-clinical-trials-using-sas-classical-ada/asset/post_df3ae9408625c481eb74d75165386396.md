However, it is important to emphasize that in the examples with utility boundaries discussed so far, the assumption was that futility boundary cannot be overruled. In other words, if the test statistic crosses the utility boundary, the trial must be terminated, or else the type I error will be inflated. This is called a "binding utility boundary". When calculating the efficacy boundaries, the presence of futility boundary will pull the efficacy boundary down, thus making it easier to cross under the null hypothesis, i.e. potentially inflating the type I error when the binding futility boundary is ignored at the interim. This binding futility is usually undesirable to sponsors of the trial because futility decisions are not always clear-cut. For that reason, a methodology is available to construct a non-binding futility boundary, non-binding boundary allows trial continuation even if such boundary is crossed without inflation of the type I error although increasing the overall sample size compared to binding futility boundary. In this case, in order to change the default setting `stop-both (binding)` one can opt to use `stop-both (nonbinding)` to construct a non-binding futility boundary. Special Issues, we will return to the issue of monitoring and briefly introduce some additional monitoring tools besides binding and non-binding futility boundaries.

## Example: Designing Sequential Tests for Cardiovascular Risk for Type 2 Diabetes Mellitus

When evaluating CV risk for T2DM, many development options are possible; limit our focus to a single cardiovascular outcomes trial (CVOT) to further illustrate the methods used for group sequential designs. The pros and cons of various approaches to assess CV risk for T2DM are discussed elsewhere [26, 27]. As described, for Stage 1 we can rewrite the non-inferiority null hypothesis as $H_{10}: \theta \le 0$ where $\theta = -\ln(\Delta_T / \lambda_C) + 0.5878$ and $\ln(1.8) = 0.5878$. The alternative hypothesis becomes $H_{11}: \theta > 0$. This is the preferred parameterization in SAS and Code 2.11 Sequential Analysis for Cardiovascular Outcome Trial of Type 2 Diabetes Mellitus is used to illustrate this example.

## Example Code 2.11 Sequential Analysis for Cardiovascular Outcome Trial of Type 2 Diabetes Mellitus

```
* Fixed-design for Stage 1 testing, default=0.1 *
proc seqdesign;
stagefixed: design stages=1 alt=twosided alpha=0.05;
samplesize model=twamplesvival(nullhazard=1.8 1.0 hazard=1.0);
run;

* Three-stage sequential design for Stage 1 testing 1.8 criterion /
* proc seqdesign errspend nstages=3 method=errfuncpow boundaryscale=mle plots=all;
stagedpower: design errspend=errfuncpow(rho=0.3) alt=twosided
alpha=0.05 cum(0.5 0.75 1)
samplesize model=twamplesvival(nullhazard=1.8 hazard=1.0)
ods Output=test_interim;
run;
```

proc ph data=T2DM;

run;
