This is called a "binding utility boundary". It is because, when calculating the efficacy boundaries, the presence of the futility boundary will pull the efficacy boundary down, thus making it easier to cross under the null hypothesis, i.e. potentially inflating the type I error when the binding futility boundary is ignored at the interim. This binding futility is usually undesirable to sponsors of the trial because futility decisions are not always clear-cut. For that reason, a methodology is available to construct a non-binding futility boundary, non-binding fut boundary allows trial continuation even if such boundary is crossed without inflation of the type I error because the corresponding efficacy boundary, as well as increasing the overall sample size compared to the binding futility boundary although the impact may be small. In this case, in order to change the default setting `stop-both (metaboundary-binding)` one can opt to use `stop-both (metaboundary-nonbinding)` to construct a non-binding futility boundary. In 2.5 Special Issues, we will return to the issue of monitoring and briefly introduce some additional monitoring tools besides binding and non-binding futility boundaries.
