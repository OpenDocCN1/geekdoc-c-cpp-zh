# ## The Switch Statements and How to Use Them

So, the first of these conditional statements on which we may concentrate our attention will be called the switch statements. These are useful conditional statements to work with since they can help us check for equality in our variables, which will be tested against the cases or values that you put up in your code. The variable that you are verifying here will then be compared to a variety of scenarios to determine whether or not it is accurate. This is simpler to work with than it may seem at first, so let's dig in and look at the syntax that we can use with the switch statement below:

```
~~~
Switch(expression) if constant-expression: statement(s); break; /optional if constant-expression:
statement(s); break; /optional
You may include as many of these case statements as you like.
Default: /Other statement(s);
~~~
```

When we bring out these switch statements, there are a few guidelines that we must follow to ensure that they perform properly in our code. First, the phrase we'll use with the switch statement will be either an integral or an enumerated class type. In addition to this, it may be a member of a class that contains a conversion function. The good thing is that when we deal with the C++ language, there are no restrictions to the number of case statements that you can put into the syntax above, so you can make the switch statements as long or as short as you like along the way dependent on your code. The important thing to remember here is that a colon must be appended to all of the values at the end of the right portions for the code to operate properly. After the variable has had some time to locate a value that is equal to it, it is time for the variable to continue running until it finds the break statement. When this break statement is discovered, the switch will be able to cease what it is doing. The control flow from this section will also be allowed to carry on to the next section of our code. You do not need to go through and add a break statement to the cases if it is not required. If you forget about it or decide not to include it, the control flow will simply go on to the next section.
