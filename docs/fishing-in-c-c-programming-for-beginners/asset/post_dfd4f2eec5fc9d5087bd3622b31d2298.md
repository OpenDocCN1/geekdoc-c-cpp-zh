## Constructors

One amazing thing about constructor is that has same name as the class. It is a function which is automatically called once an object is declared. It has no return type, not even void.

```
#include<iostream>

```
area::area(int a,int b)

Output

Here, we did not design any separate function to assign values, instead we merged it in a constructor. See carefully, we declared the objects with the arguments, e.g. class area rectangle(3,5); Here 3 and 5 are arguments. Here, area(int,int); is a constructor.

## Default Constructor

If the programmer does not create any constructor, then a constructor called default constructor with no argument is automatically created. So, we are able to create any object with no argument e.g. class area rectangle but if we try to declare any object with three arguments say class area cuboid(3,4,5) then since the corresponding constructor does not exist, so the compiler will give an error saying “no matching function to call for area::area(int,int,int)”. If we declare any constructor then the compiler does not provide the default constructor. So, if we declare any constructor with two arguments only then we cannot create any object with no argument or with one argument. To create any object with no argument, we have to declare and define a corresponding constructor too.

## Copy Constructor

Copy constructors are especially useful when we want to copy in our own fashion. Like the default constructor, the copy constructor is important, important enough that C++ thinks no class should be without one. If you don’t provide your own copy constructor, C++ generates one for you. (This differs from the default constructor that C++ provides unless your class has constructors defined for it.) The copy constructor provided by C++ performs a member-by-member copy of each data member. The copy constructor that early versions of C++ provided performed a bit-wise copy. The difference is that a member-by-member copy invokes all copy constructors that might exist for the members of the class, whereas a bit-wise copy does not.
We can also define our own copy constructor.
Consider the following program:

```
#include<iostream>
using namespace std;
class area
{
    int x, y;
public:
    area();
    area(area&);
    int calculate_area (void);
};
int main()
{
    class area rectangle;
    class area parallelogram(rectangle);
    cout<<"\nArea of rectangle is "<<rectangle.calculate_area()<<endl;
    cout<<"Area of parallelogram is "<<parallelogram.calculate_area();
    return 0;
}
area::area()
{
    x=y=1;
}
area::area(area& s)
{
    x=5;
    y=s.y;
    cout<<"Calling copy constructor";
}
int area::calculate_area()
{
    return x*y;
}
```

Output
Calling copy constructor
Area of rectangle is 1
Area of parallelogram is 5

## Destructor

Just like we called a constructor to create an object, similarly we can destroy an object using a destructor. It also has same name as the class. So, how to separate it from constructor? To separate it from constructor, we use a tilde sign (~) preceding it. Like constructor, it also returns nothing. The use of destructors is especially suitable when an object assigns dynamic memory during its lifetime and at the moment of being destroyed we want to release the memory that the object was allocated. It is also automatically called like constructors.

Consider the following program:
#include<iostream>
using namespace std;

```
class area
{
int *x, *y;
public:
area (int,int);
~area();
int calculate_area (void);
};
int main()
{
    class area parallelogram(4,2);
    cout<<"Area of parallelogram is "<<parallelogram.calculate_area();
    return 0;
}
area::area(int a,int b)
{
x=new int;
y=new int;
*x=a;
*y=b;
}
area::~area()
{
delete x;
delete y;
cout<<"\nPointers deleted";
}
int area::calculate_area()
{
return *x**y;
}
```

Output
Area of parallelogram is 8
Pointers deleted
