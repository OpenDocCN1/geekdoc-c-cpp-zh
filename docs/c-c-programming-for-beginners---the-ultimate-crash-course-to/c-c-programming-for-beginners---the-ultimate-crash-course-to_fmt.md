## 第 1 章 – 掌握基础符号

当你开始编写前几条命令时，你会注意到很多符号，如 `//` 和 `<在此处插入>` 以及其他命令如 `#include`。大多数人编写的代码都以一系列注释开头，这些注释是程序员使用的指令，用于确保程序朝着正确的方向发展。

程序的代码行可能是无尽的，从一眼看去，你可能无法准确判断某段代码的意思。这就是为什么程序员通常使用前 6 行左右来解释代码正在发生什么。

这些行以 `//` 开头，它们对程序本身实际上没有任何作用，只是为任何可能遇到这段代码副本的人提供一个清醒的目标。

如果你观察某行代码，可能还会发现大多数行都相对短。传统的标准是保持每行在 80 个字符左右。这不是强制性的，但你会发现这确实比滚动长代码行要容易得多，因为你不需要让眼睛在整个屏幕上来回移动。

你编写的每一行代码实际上都在告诉程序什么是“语句”，并且始终以 `;` 结尾。如果你能将编写代码的过程很大程度上看作类似于代数，那么你会进展顺利。比如 `if...then` 或者 `X=2-Y` 或某种的变体。你还会学到 C++ 是大小敏感的。

这大大增加了你所编写不同代码的可能性，但如果你不小心在某处大写了某个命令，而在另一个地方忘记这样做，就会变得很困难。

你在创建变量时为它们命名，一个聪明的程序员会学会保持它们的名称简洁明了。

当你设置变量时，你会使用命令 `int x`，或者将 `x` 替换为你任何想要作为变量的字母或数字。在 `{` 之后，你继续通过输入类似 `x=32;` 的内容告诉程序变量等于什么。

当然，这些只是基础知识，但希望它们能帮助你开始识别你看到的某些字符，这样你就能对它们的运作有更多一点了解。

请记住，学习 C++ 或任何代码，本质上都是在学习另一种语言。起初，它看起来会非常陌生，且完全毫无意义，直到你开始更多地观察它并识别正在发生什么，那种感觉才会出现——让你觉得它对你来说是有意义的。

只需坚持下去，不断扩大你的“词汇量”，并记住这很大程度上取决于你为每个变量和条件设置了什么。

## 第 3 章 – 学习切换思维

尽管编程有语言方面（这你会随着时间的推移和练习自发地学会），但你将需要重塑你思考问题的方式。

现在，你可能和世界上其他人一样，根据你眼前的物体来思考。现在，它就是你用来阅读这些内容的任何设备。

它很可能是一个手机，或者至少是一个平板电脑。我严重怀疑你们中许多人是在笔记本电脑屏幕或大显示器上阅读这些内容的，但也有可能。为了方便说明，让我们假设你正在手机上阅读这些行。

当你移动视线寻找某种有用信息时，你正用大拇指滑动。

你实际上只是在看单词。你获取有用信息的过程涉及快速扫视，而并没有深思考正在发生的所有其他过程。

要开始像程序员一样思考，你需要更深入地进入机器内部。

你需要思考当你的大脑信号你的大拇指在手机屏幕上移动时，所有的电路是如何工作的。你正在滑动屏幕，但为了实现这一操作需要什么样的代码流？这只是代码的一部分。它被称为“实例”。

然后，如果你更深层地进入机器内部，还有一个数据塔，它正将信息发送给你以便你查看。

从数据塔那里有一条回溯的路径，它可能来自亚马逊，或者你发现这本书副本的任何地方。

再往回溯，那里有一个出版商，有我这个作者，有我度过的那一天，还有为了实现这一切我消耗的咖啡。

这种回溯以及通过观察创建一个事件的许多不同抽象层的方法，就是你在编写代码时必须开始思考的方式。

你必须考虑实现预期结果所需包含的所有内容，而不仅仅仅仅思考你想要的结果是什么。

如果你过于关注你从客观视角看到的纯粹现实（即眼前的文字），那么你就无法深入到这一切的矩阵中，即无法看到幕后的真相。

当你学习编程时，这个过程会变得容易，然后变难，再变容易，甚至比你所想象的要复杂得多。这是一场通往兔子洞的疯狂追逐，有时看起来似乎永无止境。

这就是为什么你使用那前几行代码，以及其他可能获取你代码的人能让他们看出你正试图做什么。不可避免地，总会有那么时刻，你感到厌倦了，不再想继续下去，就像你现在对这本书的感受一样。

但请相信，简而言之，学习编程基本上意味着你将学习到：你需要放弃过去在使用程序时对你所看到的表面上所思考过的一切。这就是为什么程序员们会聚在一起。

他们被困在一个现实版的 RPG（角色扮演游戏）中，希望他们代码中的所有漏洞都能得到解决。代码中总有漏洞。你永远不会——我无意——仅仅坐下来就能写出完美的代码。它的运作方式不是那样的。

我们的大脑不是为此设计的。但你可以练习，再练习，最终，随着你学会了用更少的代码实现更多的功能，你将会减少错误并提高编码效率。

## 第 4 章 – 使用类帮助构建结构

当你编写代码时，会有一个阶段让你想要停止之前提到的所有功能代码（以及你肯定在开始时学会的一些其他代码），并想要开始定义“类”。

类是确保你输入的所有信息都保持在一个组内的绝佳方法。当你设置一个类时，你定义了这个类将成为什么。

你可以写下 `class BandStartYear`，并在围绕它构建代码时，你会编写如 `display(BandStartYear)` 之类的内容。你所说的代码，即你设计的输入乐队名称的程序，根据你输入的一系列乐队的大量代码，它将输出该乐队开始的相应日期。

你可以想象，仅仅为 30 个不同的乐队及其相应的开始日期编写代码就需要冗长的代码来产生非常有限的结果。

你意识到的重要的是，构建类将帮助你将一切分组，这样程序就将哪一组命令应用到你的类。

让我们假设你创建了一个类似于 `class Radio` 的类，为了让该类开始工作，你将使用定义为函数的不同短语，这些函数是分配给它们所属特定类的关键。

当你分配这些函数时，它们被称为“成员函数”，并且将始终引用你设置它们所在的特定类。

你可以在 `radio` 类内部编写类似 `channel()` 的函数，用于定义一个你非常熟悉的特定电台。程序可以存储你所在地区的可用电台列表，所有电台都属于 `class Radio`。

每当你通过 `channel` 示例向类添加成员函数的过程时，你只需要使用短语 `addChannel(int, double)`。

这让程序知道这将是一个数字，并且是你标准电台所拥有的值。为了将此成员函数完全连接到你的类，你需要通过输入以下内容 `Radio:addChannel(int,double)` 来建立连接。

这本质上是声明该函数属于该特定类的完整写法。它可以简短为简单的 `:addChannel(int.double)`，但这意味着该类与 Radio 类没有任何关系。

每当你添加不同的成员函数时，你会发现最好的方法是将它们直接与所属的类保持一致。这有助于减轻处理器的压力，但在某些时候你会发现需要将函数置于类之外。这引出了下一个重要的代码片段：`Next`。这就是该函数变为外部的。这将创建一个你的主类在需要时引用的源文件。

列表通常用于避免你必须声明对象将有多长。列表可以无限持续下去，也可以根据你的意愿缩短。

但是，列表的问题在于，它们不像其他形式（如数组）那样容易访问，因为在到达你想要的部分之前，必须遍历列表的每一个过程。

想象一下你为不同的应用程序设计那些精彩的形式时。很多时候，你想跳过一些不必要的信息，直接点击“接受”按钮，但你做不到。

## 第 6 章 – 保护你的成员

当你为某些类创建成员函数时，必须确保它们不会受到该类之外其他命令的影响。

这个过程在大多数情况下是为了保护它们免受你自己的影响，以免随着你编码的深入，你不会对成员函数的完整性造成任何破坏。这并不是要用某种极其安全的代码来保护它们，你只是在确保它们留在你让它们所在的地方。

这个过程也将帮助你确保你创建的类能够继续按照你设计的方式运行。

如果你的某另一行代码突然干扰了你设置的成员函数，那么你创建的类将不再按照之前的方式运行。这造成的破坏实际上远比你忽略保护的那个成员函数本身要得多。

这还能让你以一种更简单、更有组织的方式处理类的“块”。如果你需要替换它的部分内容或进行更改，你可以在不一定危及类的其他部分及其所属成员函数的情况下完成。

这也是编程中一个重要的一部分，对于程序使用者来说是完全不可见的。

这就是你真正开始在幕后创造魔法的时候。这本质上就是当你阅读这段文字时，流经手机的电流。

对于你的类是公共还是受保护，区分术语在这种情况下非常直观。你在类名旁使用“public”一词，来规定你之后添加到类中的任何其他成员函数也可以适用于该类。

如果你想保护它，只需在类名前面加上“protected”，以确保类的非成员无法介入并开始进行你不想或无法预料的更改。

当你开始开发类时，根据通用的做法，所有的程序员都会花时间输入这两个命令，来决定类是公有的还是受保护的。

在未来的开发中，在两者之间切换很快的，但为了保持良好的状态，理想做法是在每个代码中第一次构建类时就进行声明。

## 结论

对于学习 C++ 语言来说，这只是一个快速且简化的入门课程。个人花费一年甚至更久的时间仅仅是为了掌握足够的编码技能，以制作出一个像样的简单游戏。

如果你只是想构建一个简单的程序或库，这个过程并不困难。但尽管如此，你仍然需要几个月的密集学习才能达到对它感到从心的程度。目前你能做的也就是你到目前为止所做的一切。

尽可能多地接触编码和术语，并不断通过编程接触新事物。我知道我们已经涵盖了这一点，但它真的就像学习一门外语一样。

你可以去法国学习语言，但在去那里之前对该语言一点通通，这完全是一种心理压力。最终你会学会的，但很可能是通过其他会说这种语言的当地人的帮助。

编码也是如此。有人可能会认为，你从未真正作为一种语言去精通它。想想有多少会英语的人离声称对这门语言有完全掌握还非常远。当然，他们会说并在日常生活中应付自如，但他们并不是专家。

你编码就像这样。你会先学习一些基础知识，然后在此基础上增加。最终你会想要做更多，随着你的进行，你将遇到一整全新的、极其复杂的集合，它们会像最大的路障一样挡在你的面前。

你与程序接触得越多，就会发现事物在变化，整个编码领域正随着程序的升级而演变，而执行你代码中包含的所有不同基础控制的操作系统也在发生变化。

对此的回答是，你将通过不断改变对编码语言的理解，因为它绝不是一门严谨、精确的科学。

最好的想法是将这种语言看作一种工具，用来帮你解决构建所需程序的问题。记住，在编程领域，这并不是唯一的语言。

你可能会发现另一种语言更适合你，且使用起来更有逻辑。市面上还有大量新的编程接口，它们最终消除了参与和像 C++ 那样基础性工作的需求。

现在，你可以构建整个程序，而无需触碰任何代码。你可以通过视觉化方式完成这一切，对于许多人来说，在制作游戏或需要以更视觉化密集的方式运行的程序时，这要直观得多。

这些类型的程序通常通过更像积木式的拖放设置来完成，这种设置可以在花一个晚上玩一玩这种编程“语言”时就能学会。

当然，对于市面上存在的任何语言，知道如何使用它以及实际上用它构建出有价值的东西是两个完全不同的事情。

如果你决定坚持使用 C++（你真的没有理由不这样做），请做好进行多年学习和不断成长的准备，随着你对代码的理解不断推向边界（不，是不断推向你理解的边界）。

对于使用这种特定的编程语言，没有简单快速的答案。它可能比存在的任何口语语言都难学习和理解。

每当你尝试识别并攻克新问题时，可能存在的变量数量和灵活性几乎是无限的。

你在编码时能做的最重要的事情是，在构建时学会识别你所看到的问题，并在你设定了投入数百小时的编码并错过了编码早期的某些必要声明之前，能够绕过它。

这会随着时间的推移而逐渐学到，因为你从从小开始，逐步过渡到一些更密集的编程命令。记住，稳扎稳打才能赢得比赛，而这句话在编码领域的适用性再再贴不过了。

如果你坚持下去，能够编写这种水平代码的报酬将让你瞬间提升到“忍者程序员”的状态。C++ 绝非易事。祝你好运。
