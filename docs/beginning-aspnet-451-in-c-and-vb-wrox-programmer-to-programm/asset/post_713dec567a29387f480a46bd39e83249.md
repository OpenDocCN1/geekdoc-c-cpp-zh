# Configuring Your Website for Sending E-mail

Although the code to send e-mail is pretty easy, configuring your application and network can be a bit tricky. The machine you use to send e-mail must be able to access a SMTP server, either available locally on your network or the Internet. In many cases, you should use the SMTP server that you also use in your e-mail client (for example, Microsoft Outlook). If you're hosting your site with an external hosting party, you should use the SMTP server. Contact your network administrator or your ISP if you are unsure about your SMTP server.

When you have the address of the SMTP server, you can configure it globally in the Web.config file in the <system.net> element. When you are using the SMTP server from your ISP, the configuration looks like this:

```
<system.net>
  <mailSettings>
    <smtp method="Network" from="Your Name&lt;example.com&gt;">
      <network host="smtp.example.com" />
    </smtp>
  </mailSettings>
</system.net>
```

You must add the <system.net> element as a child of the Web.config file's root <configuration> element. Within <system.net> you add a <mailSettings> element, which contains an <smtp> element. Finally, the <network> element has a host attribute that points to your SMTP server.

The <smtp> element accepts an optional from attribute that enables you to send the name and e-mail address of the server in the format E-mail Address. Because the brackets < > in XML have special meaning, you must escape them with &lt; and &gt;. When you send e-mail programmatically, you can override this From as you will see in the next Try Out exercise.

If your ISP requires you to authenticate before you can send the e-mail or you want to use a different port number, use the <network /> element:

```
<smtp method="Network" from="Your Name&lt;example.com&gt;">
  <network host="smtp.example.com" username="UserName" password="Password"
    port="587" />
</smtp>
```

The port number varies from server to server. In some cases, you can leave the out port and the SmtpClient use the default port number (which is 25). Other port numbers that are frequently used include 465 and 587.

Some layers — like the one supplied by Gmail — require you to use Secure Sockets Layer (SSL), a technique that encrypts the data going to the mail server to improve security. In ASP.NET prior to version 4, you had to enable SSL programmatically in your own code. Frankly, with the enabledsl attribute on the <network> element, this is no longer the case. For a Gmail user or any other mail server that requires SSL, you can use a <network> element that looks like this:

```
<network enabledsl="true" host="smtp.gmail.com" password="Password" userName="YourAccount@gmail.com" port="587" />
```

Don't forget to enter your password and username — which in the case of Gmail is your email address. Depending on your settings, you may need to generate an application-specific password, which you can do here: http://bit.ly/N9Wv35.

For Outlook.com (the former Hotmail), you can use the following settings:

```
<network host="smtp.mail.com" password="Password" enabledsl="true" userName="yourdomain.com" port="587" />
```

And for Yahoo, you can use the following settings:

```
<network host="smtp.yahoo.com" password="Password" userName="YourAccount@yahoo.com" />
```

During development, there's a easier way to send mail by dropping it in a folder on your local hard drive. To do this, create a folder like C:\Mailbox. You need to create the folder because it won't be created automatically. Then configure the <smtp> element as follows:

```
<smtp deliveryMethod="SpecifiedPickupDirectory" from="PlanWrox&lt;planwatroxexample.com&gt;">
<specifiedPickupDirectory pickupDirectoryLocation="C:\Mail" />
</smtp>
```

With settings in Web.config, your messages are not dropped as physical files (with an .eml extension) to the folder configured in the PickupDirectoryLocation. You can read these with clients like Outlook or Windows Live (which you can download from the Internet). I prefer this setting during development over the network version because mail arrives instantly, and doesn't clutter your mail account or Inbox. Another alternative is to use a fake SMTP server as smtpdev. You can find out more about this on their website at http://smtp4dev.codeplex.com.

Refer to the MSDN documentation at http://tinyurl.com/bu79nkm for more about different settings the <mailSettings> element takes.

# Creating E-mail Messages

To send an e-message, you need to carry out four steps. First, you need to create an instance of the MailMessage class. You then configure the message by adding a body and a subject. The next step is provide information about the sender and receivers of the mail, and finally, you need to create an instance of the SmtpClient class to send the message. The following exercise shows how to code these four steps.

# TRY IT OUT Sending E-mail Messages

In this exercise, you create a simple page in the Demos folder. The code in this page creates an e-mail message that is sent when the page loads. In a later exercise, you modify the contact form so it can send the user's response by e-mail.

- 1. Under the Demos folder, create a new file called Email.aspx. Make sure it's based on your own base page template that has the right master page and inherits from BasePage automatically. Change the page's Title to E-mail Demo.
- 2. Switch to the Code by pressing F7. At the top of the file, add the following:
```csharp
Imports System.Net
```
- 3. In the Page_Load handler, add the following:
```csharp
Protected Sub Page_Load(sender As Object, e As EventArgs) Handles Me.Load
    Dim myMessage As New MailMessage()
    myMessage.Subject = "Test Message"
    myMessage.Body = "Hello world"
    myMessage.From = New MailAddress("you@example.com")
    myMessage.To.Add(New MailAddress("Receiver Name"))

    Dim SmtpClient As New SmtpClient()
    SmtpClient.Send(myMessage)
End Sub
```
- 4. Before the closing </configuration> tag, add the following:
```xml
<system.net>
  <mailSettings>
    <smtp method="Network" from="Your Name&lt;example.com&gt;">
      <network host="smtp.example.com" />
    </smtp>
  </mailSettings>
</system.net>
```
- 5. Save all changes, switch back to Email.aspx, and request it in your browser. After a while, you should receive an e-mail message at the address you specified in step 3 of this exercise or in your local pickup folder.

# COMMON MISTAKES

First, make sure you entered the right SMTP server in Web.config. You may need to talk to your internet provider or network administrator to get the right address and optionally a username and password. Also make sure that the mail server you are using allows you to send messages. If you get an error such as "The server requires a secure connection or the connection to client was not authenticated," your provider may require you to log in or use SSL to secure the connection. If that's the case, check the username, password, and port number in Web.config or try setting the enabledsl attribute of the <network /> element as shown earlier. In some cases you may receive an error when the name of your development machine contains an underscore. In that case, you either need to rename the account or use a different SMTP server.

Another reason for problems could be a mismatch between your account name and the address you specify in the From property in the code. Some mail servers require these values to be identical.

Finally, if you get the error "The specified string is not in the form required for an e-mail address," check if you entered a valid e-mail address in the from attribute in the Web.config file. You get this error if you leave out the @ symbol or make some other syntax error.
