## How It Works

As demonstrated in a previous Try Out exercise, when you put a breakpoint in the code, execution is halted as the line with the breakpoint is about to be executed. From there, you can jump around your code, investigate variables, and execute statements. In this exercise you saw how to step in and over code using the F10 and F11 shortcut keys. You use F10 to execute a line if you're not interested in seeing the underlying code that is being called. Use F11 if you want to see the code that is being executed, as you saw how to do the Add method.

The data tips and Watch and Locals windows are invaluable tools in examining and changing variables and values. For example, even though you entered 5 in the first text box in the browser, you were able to change that value to 12 during debugging. Any changes made while debugging are propagated to the rest of the code that still needs to be executed.

The Immediate window lets you try out some snippets of code. This can be useful to try some ideas, without the need to write it in the code window and debug. In this exercise, you wrote some code that created a new Calculator instance, called the Multiply method, and outputted the value using the question mark.

## DEBUGGING CLIENT-SIDE SCRIPT

So far, you have used the debugging tools to debug ASPX pages and C# Behind. However, that's not all there is to. VS also has great support for debugging client-side JavaScript. Debugging client-side JavaScript requires that you use Internet Explorer and won't work correctly with other browsers like Firefox or Opera. The cool thing about client-side JavaScript in VS is that you already know how to do it. You can use the same familiar tools that you have seen in this chapter to debug both server-side and client-side code.

The JavaScript that is eventually used by the page in the web browser can come from different sources. You may have JavaScript external files, embedded in the page, in a master page, and even server controls can emit their own JavaScript. This makes it difficult to break in the right code, because you don't know where it comes from. VS has a great solution for this: let set breakpoints in the final HTML displayed by the browser. To show you in what file you are adding breakpoints or what code you are debugging, VS updates the Solution Explorer and displays a list of all files containing client-side script that you can step through as you are in debug mode.

The easiest way to learn the new client-side JavaScript debugging possibilities is by trying them, so the next exercise dives right in and shows you how to debug the web service test page that you created in Chapter 10.
