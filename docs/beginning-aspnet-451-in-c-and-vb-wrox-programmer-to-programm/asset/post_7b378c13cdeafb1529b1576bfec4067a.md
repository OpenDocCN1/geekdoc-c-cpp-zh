# How it Works

The Table Designer in SSMS is straightforward. You type column name and define data type for the column, and you're much done. For those columns, set it (Identity property) to Yes. This means that SQL Server automatically assigns a sequential number to each new row you insert. The first row in the table gets an ID of 1, and the ID of subsequent rows is increased by one. You can change the behavior by setting the Identity Increment and Identity Specification for the column.

# Creating Relationships between Tables

Consider the tables you created so far. You created a Genre table with an Id column to uniquely identify a row. You also created a Review table with a GenreId column. Clearly each review should contain an ID that points to a row in the Genre table so you know which genre it belongs to. Now imagine that you delete a row from the Genre table that has reviews attached to it. Without a relationship, the database will let you do that. However, this is causing a great deal of trouble. If you try to display the genre together with a review, it will fail because there is no longer a matching genre. Similarly, if you want to list all the reviews in your system grouped by genre, you'll miss the ones that belong to the deleted genre.

To avoid these kinds of problems and keep your database in a healthy and consistent state, you can create a relationship between two tables. The database will stop you from accidentally deleting rows in one table that still have other rows attached to it.

Besides the protection of data, relationships also help you make your data model clearer. If you look at the database through a diagram (which you use in the next exercise), you'll find that relationships between tables help you understand how tables are connected and what data they represent.

You can define a relationship by creating the primary key of one table and a column in another. The column in another table is referred to as a foreign key. In the case of the Review and Genre tables, the GenreId column of the Review table points to the primary key Id of the Genre table, making GenreId a foreign key. In the next exercise, you will see how to create a relationship between two tables and execute a SQL statement that shows how the relationship is helping you to protect your data.
