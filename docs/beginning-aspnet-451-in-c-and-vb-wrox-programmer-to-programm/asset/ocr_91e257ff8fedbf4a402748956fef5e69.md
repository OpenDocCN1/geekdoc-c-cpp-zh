# How It Works

For the most part, this exercise works as a previous exercise where you displayed a list with the available genres. What's different this time is the way the SqlDataSource is to filter the Review table based on the selection you made in the DataList. Take a look at the code for the SqlDataSource to see how this works:

```
<asp:
<SqlDataSource Id="SqlDataSource2" runat="server"
    ConnectionString="<%= ConnectionStrings.MyConnectionString1 %>"
    SelectCommand="SELECT * FROM Review WHERE [GenreId] = @GenreId">
    <SelectParameters>
        <ControlParameter ControlID="DropDownList1" Name="GenreId"
            PropertyName="SelectedValue" Type="Int32" />
    </SelectParameters>
</SqlDataSource>
```

The SQL statement for SelectCommand contains a parameter for the GenreId variable in the Select statement. This means that the SQL statement returns from the Review table only for a specific genre. At runtime, the value for this parameter is retrieved from the control defined in the ControlParameter element. In this example, the code is set up to get the value from the DropDownList it access its SelectedValue property, so that adds to the PropertyName if you need a different property, you can simply change it in the ControlParameter's declaration.

With this set up, the GridView uses the SqlDataSource for its data. This data source takes the item from the DropList that the user has selected in the list. This value is inserted into the SQL statement, and the results are returned from the database are sent back through the data source to the GridView, which uses them to create the HTML table in the browser.

When you choose a Selection from the drop-down list, you get an empty page with no rows. In this case, the DropDownList returns an empty string as its value (defined in the Value property), which is converted to null, the database equivalent of nothing. In this turn causes the query to return rows from the Review table.

Now you've relied on the code-generation tools of VS to set up the GridView and the DetailsView. By default, VS creates a column (for the GridView) or a field (for the DetailsView) for each column that it finds in the data source. It's smart enough to recognize some of underlying types of data in the database so you get a CheckBoxField for boolean (bit) fields in the database, that's about it. To further customize the look and feel of these controls, you need to customize our Columns and Fields collections.
