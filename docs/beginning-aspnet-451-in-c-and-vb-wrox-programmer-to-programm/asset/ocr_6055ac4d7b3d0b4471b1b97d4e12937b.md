# How It Works

When you draw the Button and the TextBox on the Toolbox in Design View, VS added the corresponding code for you in Markup View. Similarly, when you changed the Text property in the Properties Grid, VS automatically updated the markup for the control in Markup View. Instead of using the Properties Grid, you could also have typed the text directly between the quotation marks of the Text property in Markup View.

After changing the Text property, your page should contain some code in Markup View:

```
<asp:TextBox Id="TextBox" runat="server"/> <asp:Button Id="Button" runat="server" Text="Submit Information" />
```

When you press Ctrl+F5 to view the page in your browser, the web server receives the request, the page is processed by the ASP.NET run, and the resulting HTML for the page is sent to the browser.

After you type some text and click, the same process is more or less repeated: The web server receives the request, the page is processed, and the results get sent back to the browser. When you click the button, you cause a postback to occur, where any information contained in the page — such as the text you typed in the text box — is sent to the server. ASP.NET reacts to the postback by reloading the page again. However, this prepopulates controls, like the TextBox, with the values that were sent to the page.
