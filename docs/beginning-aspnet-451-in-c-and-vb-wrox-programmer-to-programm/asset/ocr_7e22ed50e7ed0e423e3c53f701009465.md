First, however, you need to learn a bit more about the different events that the data-bound and data source controls fire. The following table lists some of the events that the DetailsView, the FormView, and the ListView expose and raise during their lifetime. The GridView has similar events, but they start with Row index of Item. Because the DataList and Repeater controls do not natively support editing of data, they do not have any of these events.

| EVENT | DESCRIPTION |
| ItemInserting | Fires before the Insert command is executed against the data source. This is an ideal location to change the data that is about to be sent to the database. |
| ItemInserted | Fires after the Insert command has been executed against the data source. |
| ItemUpdating | Fires before the Update command is executed against the data source. This is an ideal location to change the data that is about to be sent to the database. |
| ItemUpdated | Fires after the Update command has been executed against the data source. |
| ItemDeleting | Fires before the Delete command is executed against the data source. |
| ItemDeleted | Fires after the Delete command has been executed against the data source. |

These six events fire at very convenient moments in the life of the control: right before and after the data for the operation is sent to the database. You will see how to use them in the Try It Out.
