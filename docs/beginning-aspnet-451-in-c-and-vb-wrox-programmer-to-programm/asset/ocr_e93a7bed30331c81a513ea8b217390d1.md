# CHAPTER 18 EXCEPTION HANDLING, DEBUGGING, TRACING

To get the root exception that caused the problem in the first place, you need to call GetBaseException() on the Exception that is returned by Server.GetLastError(). This Exception instance, stored in the my variable, then gives you access to useful properties such as Message and StackTrace. In this exercise, the StackTrace displayed in the e-mail contains information that really isn't of interest to you. However, with other exceptions, such as one triggered by an incorrect configuration of the server or a device error, the StackTrace gives you information about the file that generated the error, the method that caused it, and even the line number in code, making it easy to find the error and fix it.

The remainder of the code creates an e-mail with the error details. It also adds information about the query string with:

# VB.NET

```
message &= "<strong>Query String</strong><br />" & \
    Request.QueryString.ToString() & "<br />"
```

# C#

```
message += "<strong>Query String</strong><br />" + \
    Request.QueryString.ToString() + "<br />";
```

Knowledge of the query string will help in debugging values if the query strings are used. You could extend the code in Application.Error and add other useful information such as collections and forms. For more information about accessing these kinds of collections, pick up a copy of Professional ASP.NET 4.5 by Wrox. Alternatively, check ELMAH—the Error Logging Modules and Handlers project—at http://code.google.com/elm/, which is an open source project run by At Aziz. It is extremely simple to integrate into your site (no programming required, you just need to add a few lines of configuration code to your Web.config.file). And even better: use a NuGet package that adds the necessary files and configuration for you. Simply run the following command from the Package Manager Console:

```
Install-Package Elmah
```

After you have ELMAH, you can get a list of the errors that occurred in the site by requesting a special page called http://localhost:49394/elmah.axd.

By default, you can access this page only from the local machine. Besides showing the errors in elmah.axd, you can configure ELMAH to store errors in the database, send them by e-mail, provide them as an RSS feed, and much more. Check out the ELMAH project site for more information.

I have been using ELMAH for most of my production projects for the past couple of years, and it has helped me find many bugs that otherwise would have gone unnoticed.

Although the ability to handle and log exceptions at runtime is useful, it's better to prevent them from happening in the first place. To write solid code with few bugs as possible, you need good tools to help you understand the execution of your code so you can debug it. VS comes with excellent debugging tools that you can use in your process. We will show how to use them in the next section.
