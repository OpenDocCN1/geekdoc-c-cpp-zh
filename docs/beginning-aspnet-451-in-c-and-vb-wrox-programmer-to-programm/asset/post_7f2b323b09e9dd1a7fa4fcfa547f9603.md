# MOVING DATA TO A REMOTE SERVER

Releasing a site to IIS on your local machine is pretty straightforward. Simply copy the data to a new location, configure IIS, change a few security settings, and that's it. Because the site continues to use your local copy of SQL Server, it will run fine.

# CHAPTER 19 DEPLOYING YOUR WEBSITE

However, in the real world when you need to move your site to an external server or host, things are not so easy. Although copying the files that make up your site is usually extremely simple using an FTP program, copying data from your SQL Server database to your host is often a bit trickier. This is because most hosts don't support the free Express or LocalDB instances, you can't just copy the .mdf file from your App_Data folder at home. Instead, these hosts often offer the full version of SQL Server, which you can access with a web-based management tool or with tools such as SQL Server Management Studio.

Getting your database from your local machine to your remote host is typically a two-step process:

- 1. Create a .sql script from your local SQL Server database.
- 2. Send this script to your host and execute it.

In the next section, you will see how to export your database to a .sql file. I won't show you how to recreateat that file at your host because this is different from host to host. Instead, I will give you some general pointers so you know what to look for.

# Exporting Your Data to a File

To make it easy to transfer data from your local SQL Server database into your web host database, SQL Server Management Studio comes with a tool to export your database structure and data to a file. This file contains all information required to recreate your database at a remote server.

This exercise assumes you've already downloaded and installed SQL Server Management Studio. If you haven't already, refer to the start of Chapter 12 for details.

- 1. Start SQL Server Management Studio from the Start menu. You will see a screen similar to Figure 19-14.
- 2. Enter the server name as localdb, and click Connect. Your database will already be listed in the Databases node; if it's not, right-click the Databases node, click Attach, and then browse for your database.mdf file in C:\SQLServer\Site\App_Data.
- 3. Right-click the database and choose Tasks -> Generate Scripts. Click Next. Ensure Entire Database and All Objects is selected, then click Next. The dialog box shown in Figure 19-15 appears.

# How It Works

The contents of a database can be separated into two categories: the structure of the database and the actual data. When the scripting tool runs, it investigates the structure of your database first and creates CREATE statements for all the items it finds in your database, such as the tables you created earlier. It creates INSERT statements that recreate all records as Views, Stored Procedures, and even users in the database. By clearing the Script Objects check box at the beginning of the wizard, you can selectively choose parts of your database, for example, to script only a few tables.

At the end, the scripting tool assembles all the SQL statements and saves them to a single .sql file. This file is now ready to be run to recreate the database.

# Recreating the Database

Although every host has its own rules and procedures when it comes to providing access to its SQL Server, they can be grouped in three categories.

> NOTE For detailed information about hosting your site with an external hosting party, check out the tutorials in the hosting section of the official ASP.NET site at www.asp.net/learn/hosting.

First, some hosts don't give you access to their database and require you to submit a .sql file so they can execute it for you. In this, you don't have to do anything other than send the file and wait for the host to create your database.

The second category contains hosts that allow you to execute SQL statements through a web interface. You typically log into your online control panel and execute the SQL statements created by the scripting tool, either by uploading the file or pasting its contents in a text area in a web page. Regardless of the method, you end up with a database that you can access from your application. How this works exactly differs with each host, so consult the hosting service's help or support system for information. Some known issues exist with web-based database management tools from some providers, resulting in errors when you try to run the generated SQL file. Although the file is technically valid, the tool may still run into issues with it. For that, contact your host for help on resolving the issue. If you run into issues, one of the ones you may want to try is to save your SQL file in a different format. The default format is Unicode, which is ANSI Text for the Save option when exporting your data, as shown in Figure 19-15.

The final category contains hosts that allow you to connect to their SQL Server over the Internet. This enables you to use SQL Server Management Studio to connect to the database at your host from desktop and execute the SQL statements remotely.
