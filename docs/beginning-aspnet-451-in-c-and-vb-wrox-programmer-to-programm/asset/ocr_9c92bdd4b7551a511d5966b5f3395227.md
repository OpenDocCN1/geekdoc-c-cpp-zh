cleaner URLs from a user's point of view. This is often used in so-called URL-rewrite scenarios that are used to create pretty URLs. For example, a user may request a page like this:

```
http://www.domain.com/Cars/Volvo/850/T5/
```

Under the hood the server transfer to:

```
http://www.domain.com/Cars/ShowCar.aspx?Make=643&Model=984&Type=7345
```

Clearly, the first URL is easier to understand and type in a browser. It also enables a user to guess other URLs that match the same pattern. For example, there's a fair chance you can request a page like this:

```
http://www.domain.com/Cars/Volvo/V70/R/
```

and end up right with the page showing you the Volvo V70 R.
In addition to being easier to understand, server-side transfers may also speed up your site a little. Instead of sending a response to the server to tell it to fetch a new page, which results in a request for a page, you can transfer the user directly to a new page, saving you some network overhead.

Server-side transfers are carried out with the Server object. As the Request and Response objects you saw earlier give you information about the request and response, so does the Server provide you with information about the server it is running on. You can use it to get information about the server, its IP address, and so on. One of its methods is Transfer, performs a server-side transfer.
You can use Server.Transfer only to redirect to other pages within your site. You cannot use it to send the user to pages on different domains. If you try to do so, the ASP.NET run time throws an error.

To see the difference between Response.Redirect and Server.Transfer, the following exercise shows you how to change the page Source.aspx to perform a Server.Transfer operation.

# TRY OUT Server-Side Redirecting

```
VB.NET
Protected Sub Page_Load(sender As Object, e As EventArgs) Handles Me.Load\Server.Transfer("Target.aspx?Test=SomeValue")
End Sub
```

```
C#
protected void Page_Load(object sender, EventArgs e)
{
```
