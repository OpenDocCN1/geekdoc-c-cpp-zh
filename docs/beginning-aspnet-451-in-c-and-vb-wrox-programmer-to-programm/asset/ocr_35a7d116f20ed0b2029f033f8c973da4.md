# C#

```
try
{
    mySmtpClient.Send(myMessage);
}
catch (SmtpException exception)
{
    userMessage = "Sorry, an error occurred while sending your message.";
}
catch (Exception ex)
{
    // Something else went wrong.
}
```

The order of the exception-handling blocks is important. .NET scans the list of Catch blocks from top to bottom and fires the code in the first block that matches a specific type of exception. In the preceding example, when an SmtpException occurs (which is a subclass of Exception), it will be caught by the Catch block that handles exceptions of SmtpException. Although an SmtpException is also an Exception, the code in the last Catch block won't be fired because only the first matching Catch block is handled. Therefore, if you reverse the order of the Catch blocks in this example, the more generic Exception block would be executed, and the code in the SmtpException block would never run.

> The preceding example shows how to catch all exceptions using the base Exception type in the Catch block. Don't use this in your own websites. handle only those types of exceptions that you know to deal with, and let all other, unknown exceptions bubble up in the application. Later in this chapter you will learn how to centrally handle these unhandled exceptions.

In this Try It Out, you will see how to write exception-handling code to catch problems with sending e-mail. These problems may occur when the mail server is down, for example. To simulate a broken mail server, you'll temporarily use a nonexistent mail server name to cause your crash.
