## How It Works

With the hard of getting your user's favorite theme and storing it in a cookie already, applying the theme is now very easy. The code in the PreInit event handler first verifies whether there is a cookie called PreferredTheme. This does by comparing the return value of the Get method to Nothing (null in C#).

```VB.NET
Dim preferredTheme As HttpCookie = Request.Cookies.Get("PreferredTheme")
If preferredTheme IsNot Nothing
```

```c#
HttpCookie preferredTheme = Request.Cookies.Get("PreferredTheme")
if (preferredTheme == null)
```

This code uses Request.Cookies to read the cookies that the user's browser send together with the request. If the cookie exists, its Value property is used to set the correct theme:

```VB.NET
Page.Theme = preferredTheme.Value
```

```c#
Page.Theme = preferredTheme.Value;
```

Because the theme is set early in the page's life cycle, this setting is applied throughout the page, effectively giving the page look and feel defined in it. To ensure that the code doesn't try to apply a theme that (no) longer exists, it uses Directory.Exists That returns true or false depending on the presence of the folder on disk. To get the full path of the theme folder on disk, it uses Server.MapPath to translate a virtual path into its physical counterpart. You learn more about virtual paths in the next chapter, where Server.MapPath is discussed in Chapter 9.

With the capability to set the theme programmatically, you're offering your users a quick and easy way to change the page to their liking. The theme affects colors and layout throughout each page in the entire website. Combined with master pages, this gives you a flexible way to influence the look and feel of an entire page. It could also be useful if you were able to change certain controls on a page. For example, you may need to give each button in your site the exact same look. This is where ASP.NET skins come into play.

## SKINS

Skins are simple text files that contain markup that enables you to define the look and feel of one or more controls from a central location. Placed in a theme folder, they are an integral part of the ASP.NET themes feature. A skin file (with a .skin extension) contains the server-side presentational elements of a control. These settings are then applied to all the controls to which the skin applies. To see how this works consider the following example that defines a skin — appearance of a Button control:

```asp
<asp:Button BackColor="#cccccc" ForeColor="#308462" runat="server" />
```

With this distinction, the buttons in your site will get a BackColor of #cccccc and ForeColor of #308462. All you need to do is create a skin file when you define others, add this to the markup and that's it. From then on, all the buttons will be handled automatically. Just as setting the properties on the controls directly as you would earlier, like BackColor and ForeColor, are transformed into client-side HTML and CSS.

Note that skin is similar to the markup of a button. First of all, the control in the skin file cannot have an ID attribute. The ID is to uniquely identify a control in the page, and because the skin is applied to all controls, there's no point in giving it IT. Another difference is the number of properties you can set in the markup. Not all properties of a control are skinnable. For example, you can set the Enabled property of the Button through a skin. Microsoft's MSDN documentation for each property whether or not they can be skinned. Another way to find out if you can set a certain property is by simply trying: set the property in the skin and if you're not allowed to it, you'll get an error at runtime.

Generally speaking, properties that influence the appearance (BackColor, ForeColor, BorderRadius, and so on) can be skinnable and properties that influence behavior (Enabled, EnableViewState, and more) cannot be.

When you create a new skin file using the Add Item dialog box, you get a bunch of text wrapped in a server-side control block. You can safely remove these controls because they only give you a short example of how skins work. You can define multiple controls in a single skin file. However, from a maintenance point of view, its easier to rename each skin file after the control it represents. For example, you would have a file named Button.skin for buttons, Label.skin for labels, and so on.

Instead of applying formatting elements directly to the controls in the skin and thus use the CssClass property to point to a CSS class in one of your CSS files. Then it is even easier to make site changes and avoid bloating the final HTML. Given the previous example, a file with the following skin definition and a class in the theme's CSS file would give the same effect:

```asp
<asp:Button CssClass="MyButton" runat="server" />
```

```css
.MyButton {
  color: #308462;
  background-color: #cccccc;
}
```

## Creating a Skin File

Skin files must be created in the theme folder. To see how this works, you should:

1. Open the theme folder.
2. Open the skin file.
3. In the editor, type the following:
```asp
<asp:Button CssClass="MyButton" runat="server" />
```
4. Save the file.
5. Refresh the page.

You will see that the button now has the look you defined. To change the look, modify the CSS in the .css file:

```css
.MyButton {
  color: #308462;
  background-color: #cccccc;
}
```

## CHAPTER 6 CREATING CONSISTENT LOOKINGBSITES

To use skins effectively across your website while keeping the look consistent, you should:

1. Create a new Web Form and call it SkinsDemo.
2. Drag a button from the Toolbox to the MainContent area.
3. Type the following:
```asp
<asp:Content ID="Content2" PlaceholderID="MainContent" runat="Server">
  <asp:Button ID="Button1" runat="Server" Text="Button" />
</asp:Content>
```
4. Save the file and open it in the browser. The button should have the default look.
5. To change the look, create a CSS file and add the following selector:
```css
.MyButton {
  color: #308462;
  background-color: #cccccc;
}
```
6. In the skin file, add the class to the button:
```asp
<asp:Button CssClass="MyButton" runat="server" />
```
7. Refresh the page. The button should now have the look you defined.
