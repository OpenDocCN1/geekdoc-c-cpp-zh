## How It Works

Just like the RequiredFieldValidator control, the other validators emit JavaScript to the client, which is triggered when you click the Send button or when the value of one of the controls is changed. The CompareValidator works by looking at the value of two different controls. When both contain the same data it will return true. It's important to realize that the CompareValidator control does not trigger its validation code when the text boxes are empty. Therefore, it's important to hook up a RequiredFieldValidator control as well. This control makes sure the user entered at least some data and then the CompareValidator ensures that the text is the same in both.

The RegularExpressionValidator works by checking the pattern of the data that it is validating. If you look at the ValidationExpression property of the control, you see some text, optionally followed by some long string. This pattern ensures characters like a dash (-) or period, followed by more text. It also ensures that there is an @ symbol in the address, followed by a domain name, a period, and then at least one character to represent the top-level domain like .com, .nl, or .uk. With this, you@example.com is considered a valid e-mail address. So is @a.a, whereas you won't.

Note that the RegularExpressionValidator only checks the syntax of the e-mail address. It's still perfectly possible to enter a nonexistent e-mail address that just looks valid or even invalid-mail address such as @@a.a. However, in many cases, this validator is good enough to filter out common types users use when entering e-mail addresses.

If you look at the source for the page you see a layer of JavaScript code at the end of the file. With this, ASP.NET has implemented the client-side validation since the first version of ASP.NET. However, starting with ASP.NET 4.5, you now have another alternative that uses jQuery under the hood. You learn more about jQuery and the alternative validation mechanism in Chapter 11.

The validation you have seen so far are very easy to use. You add them to a page, set a few properties, and then they all do the hard work for you. However, they do not support every possible scenario you may come up. For example, what if you wanted to ensure that a user entered at least one of the two phone numbers? And what if you wanted to present your users with a full list of all the errors they make in the form? This is where the CustomValidator and the ValidationSummary come in.

## The CustomValidator and ValidationSummary Controls

The CustomValidator enables you to create custom validation functions for the client (JavaScript) and the server (using VB.NET or C#). This gives you great flexibility with regard to the data you want to validate and the rules you want to apply.

The ValidationSummary control provides the user with a list of errors that it retrieves from the individual validation control's ErrorMessage properties. It can display errors in three different ways: using a list embedded in the page, using a JavaScript alert box, or using both at the same time. You control this setting with the ShowMessageBox and ShowSummary properties. Additionally, the DisplayMode property enables you to change the way list of errors is presented. The default setting is List where each error is in a bulleted list, but other options are List (without bullets) and SingleParagraph.

You learn how write client-side and server-side validation methods and how to use the ValidationSummary control in the following exercise.

## TRY OUT Writing Client- and Server-side Validation Methods

In this exercise, you will see how to use the CustomValidator in your page to ensure that at least one of the phone numbers is entered. The validation is carried out at the client and at the server. Additionally, you see how to use the ValidationSummary control to provide feedback to users about the errors they made in.

| PROPERTY | VALUE |
| --- | --- |
| CssClass | ErrorMessage |

| ErrorMessage | Enter your home or business phone number |
| Text | * |

- 5. Double-click the CustomValidator in Design View to have VS an event handler for the ServerValidate event. Add the following code to the handler:

```VB.NET
Protected Sub CustomValidator1_ServerValidate(source Object,
    args As ServerEventArgs Handles CustomValidator1.ServerValidate)
If Not String.IsNullOrEmpty(PhoneHome.Text) OrElse
    String.IsNullOrEmpty(PhoneBusiness.Text) Then
    args.IsValid = True
ElseElse
    args.IsValid = False
End If
End Sub
```

```csharp
protected void CustomValidator1_ServerValidate(object source,
    ServerEventArgs args)
{
    if (!string.IsNullOrEmpty(PhoneHome.Text) ||
        !string.IsNullOrEmpty(PhoneBusiness.Text))
    {
        args.IsValid = true;
    } else
    {
        args.IsValid = false;
    }
}
```

- 6. Switch to Markup View of the user control and add the following JavaScript code right before the table with:

```html
<script>
function validatePhoneNumbers(source, args)
{
    var phoneHome = document.getElementById('<%= PhoneHome.ClientID %>');
    var phoneBusiness = document.getElementById('<%= PhoneBusiness.ClientID %>');
    if (phoneHome.value == '' || phoneBusiness.value == '')
    {
        args.IsValid = true;
    } else
    {
        args.IsValid = false;
    }
}
</script>
<table class="auto-style">
```

In JavaScript, it's common to write names using camel casing, where the first word of the method name is written in lowercase, followed by the first letter in uppercase. If you find that VS is adding your opening braces {} at the end of a line, rather than on their own line, choose Tools Options. Expand the path Text Editor JavaScript Formatting, and check off both items in New Lines. This is a purely formatting preference; JavaScript runs fine without the curly brace on its own line.
