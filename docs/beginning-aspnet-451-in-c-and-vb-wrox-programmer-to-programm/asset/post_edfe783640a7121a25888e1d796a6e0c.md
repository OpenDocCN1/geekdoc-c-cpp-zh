If you're using Model Binding instead of a SqlDataSource control, you can accomplish the functionality with your GetData method:

```VB.NET
Public Function GridView1_GetData() As IQueryable
    Dim myEntities As New PlanetWroxEntities()
    Return From genre myEntities.Genres.Include("Reviews")
        Order By genre.Name
        Select genre
End Sub
```

```csharp
public IQueryable<Genre> GridView1_GetData()
{
    PlanetWroxEntities myEntities = new PlanetWroxEntities();
    return from genre in myEntities.Genres.Include("Reviews")
        orderby genre.Name
        select genre;
}
```

This selects each Genre along its associated Reviews. You can then get the Count of the Reviews and use that in the Markup to disable the Delete button:

```asp
<asp:LinkButton Id="DeleteLink" runat="server" CausesValidation="False"
CommandName="Delete" Text="Delete" Enabled="<%# Item.Reviews.Count > 0 %>">
</asp:LinkButton>
```

Note this code selects all reviews from the database, but it's not very efficient. As an alternative, you could select an anonymous object that contains the Genre's ID and Name properties, as well as a total count of all the reviews. This also means you need to implement your paging and sorting method in the code using LINQ's Skip and Take methods as Model Binding cannot do for you automatically with anonymous objects, or you could disable sorting and paging of the Grid.

By disabling the delete button, you can easily prevent errors that occur when you try to delete a genre that has associated reviews. However, you may not always able to prevent an error from occurring during a CRUD operation against a data source control. For example, you may try to delete a genre that initially didn't have any reviews attached. Imagine that before you try to delete the genre, somebody inserts a new review for it. When you then try to delete the genre you'll get an error because the genre is now linked to it. In such cases, the data source controls enable you to diagnose the error that occurred and then take the necessary measures, providing feedback to the users informing them their CRUD operation did not succeed.

# Handling Errors That Occur in the Data Source Controls

In Chapter 18 you see a lot about recognizing and handling errors that occur in your ASP .NET pages. That chapter demonstrates how to catch errors that may occur in your code, and handle them by logging them or by informing the user. Because the data source controls expose error information as well, it's interesting to look at data errors in this chapter.

The SqlDataSource control (and other data source controls well) give you information about errors (exceptions in parlance) that may occur during one of the four CRUD operations.
With the SqlDataSourceStatusEventArgs, all events accept an instance of SqlDataSourceStatusEventArgs. Figure 15-10 shows these three EventArgs classes and their properties.

This class has two important properties: Exception and ExceptionHandled. The first contains the actual exception that occurred or nothing (in VB.NET) or null (in C#) when everything goes to plan and no error occurs. You can examine this error and take appropriate action. For example, you can inform the user that something went wrong, or you can send an email to the user's webmaster informing about the error so follow-up action can be taken.

If you decide to handle the error in the handler of the data source control, you should set the ExceptionHandled property of the object to True. This signals the ASP.NET run time that you are aware of the error and have dealt with it adequately. If you omitting this property, the run time finishes with the exception, which is eventually displayed to the user.

# Handling Errors When Deleting Rows

In this Try Out you see how to deal with exceptions that occur in a GridView when deleting rows. You'll temporarily comment out the code that disables the Delete link so you can try to delete genres with associated reviews. The control displays an error message when a user tries to delete a genre that has reviews attached to it. This exercise mainly serves to demonstrate how to handle exceptions may be thrown by the source controls. From an end user's perspective, disabling the Delete link when it's not appropriate, as you did in an earlier exercise, take care of the problem in most circumstances, but someone could still insert a new review before you try to delete a genre. The way to handle this is by both solutions: Disable links that are not available, and handle an error gracefully in case someone else created a review for a genre you just tried to delete.

1. Open Genres.aspx from the Management folder. 
2. Switch to Design View and from the toolbox drag a Label control onto the GridView. This places the Label to hold an error message above the GridView. Change the ID of the Label to ErrorMessage and clear its Text property (Right-click the Text label in the Properties Grid and choose Reset. This removes the Text property and its value from the control's markup.) Set its CssClass to ErrorMessage. Finally, set its EnableViewState to false to ensure the label doesn't maintain its text after posts. You should end up with this code:

```asp
<asp:Label ID="ErrorMessage" runat="server" CssClass="ErrorMessage"
EnableViewState="false"/></asp:Label>
<asp:GridView ID="GridView1" runat="server" AllowPaging="True">
```
3. Open Management.css file from the Management folder and add the following rule:

```css
ErrorMessage
{
    color: Red;
    font-weight: bold;
}
```
4. Switch to Genres.aspx, make sure the page is in Design View, and click the SqlDataSource control to select it. Then open its Properties, switch to the Events tab, and set up an event handler for the Deleted event by double-clicking the event name.
5. At the top of the Code Behind, add the following namespace to bring the SqlException class into scope:

```VB.NET
Imports System.Data.SqlClient
```
6. Inside the event handler you added for step 4, write the following code:

```VB.NET
Protected Sub SqlDataSource_Deleted(sender As Object,
    e As SqlDataSourceEventArgs) Handles SqlDataSource.Deleted
    If e.Exception Is Not Nothing AndOf(e.Exception) Is SqlException Then
        Dim e.Exception As SqlException = CType(e.Exception, SqlException)
        If e.Exception.Number = 547 Then
            ErrorMessage.Text = "Sorry, you can't delete this genre because " &
            "it has associated reviews that you need to delete first."
            e.ExceptionHandled = True
        End If
    End If
End Sub
```

```csharp
protected void SqlDataSource_Deleted(object sender,
    SqlDataSourceEventArgs e)
{
    if (e.Exception != null && e.Exception is SqlException)
    {
        SqlException myException = (SqlException)e.Exception;
        if (myException.Number == 547)
        {
            ErrorMessage.Text = "Sorry, you can't delete this genre because
it has associated reviews that you need to delete first.";
            e.ExceptionHandled = true;
        }
    }
}
```
7. Comment out the code you added in your Try Out to stop the Delete link from being disabled. For this exercise it's enough to just comment out the line that disables the link:

```VB.NET
' deleteLink.Enabled = False
```

```csharp
// deleteLink.Enabled = false;
```
In that case, forget to remove the handler from the GridView's markup in C# as well.
