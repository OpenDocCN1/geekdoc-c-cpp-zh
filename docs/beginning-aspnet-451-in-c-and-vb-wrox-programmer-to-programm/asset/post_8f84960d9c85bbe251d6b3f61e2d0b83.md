
## CHAPTER 4 WORKING WITH ASP.NET SERVER CONTROLS

To see how these attributes appear in the browser, consider the following markup for a TextBox server control:

```
<asp:TextBox AccessKey="a" BackColor="Black" ForeColor="White" Font-Size="30px"
BorderColor="Yellow" Border="Dashed" BorderWidth="4" CssClass="TextBox"
Enabled="True" Height="40px" Width="90px" TabIndex="1" ToolTip="Hover text here"
Visible="True" ID="TextBox" runat="server" Text="Hello World">
</asp:TextBox>
```

When you request this page in the browser, you will end up with the following HTML:

```
<input name="TextBox" type="text" value="Hello World" id="TextBox1"
tabindex="1" title="Hover text here" class="TextBox" style="color:White;
background-color:Black;border-color:yellow;border-width:4px;
border-style:Dashed;font-size:30px;height:40px;width:200px;">
```

This results in the text shown in Figure 4-3.

Note of how the server-side control properties have been converted into inline styles with the style attribute.

When building websites, it is quite uncommon to define a TextBox in this manner. As you learned in the previous chapter, you should avoid inline styles as much as possible, and opt for cascading stylesheets instead. You can accomplish the same effect with this server-side control:

```
<asp:TextBox ID="TextBox1" AccessKey="a" CssClass="TextBox" TabIndex="1"
ToolTip="Hover text here" runat="server" Text="Hello World">
</asp:TextBox>
```

And with the following CSS:

```
.TextBox {
background-color: Black;
color: White;
font-size: 30px;
border-color: Yellow;
border-style: Dashed;
border-width: 4px;
height: 40px;
}
```

Obviously, the second example is much easier to read, reuse, and maintain. If you want another text with the exact same look, simply assign TextBox to the CssClass of that. Also, notice I used the Enabled and Visible properties. Both default to True, so there's no need to explicitly state that in control declaration.

Although it's recommended to use CSS classes instead of these inline styles, it is good to know how the server-side control properties work in case you need control over them. If you change the control's properties programmatically (as you learn how to do it), they still end up as styles, and thus possibly override settings in embedded or external stylesheets.

## Types of Controls

Now that you have seen the generic behavior that all server controls share, it is time to look at the large number of controls that ship with ASP .NET.

Out of the box, ASP.NET 4.5.1 comes with a large number of controls, supporting most of your web development needs. To make it easy for you to find the right controls, they have been separated in control categories in the VS Toolbox (accessible by pressing Ctrl+Alt+X). Figure 4-4 shows the Toolbox with all the available categories.

Note that depending on your version of Visual Studio, the Toolbox may have other categories.

A handy feature in VS is the ability to search in the Toolbox. Just type in a few letters of the control you're looking for in the search box at the top of the Toolbox, and VS filters the list matching your criteria.

In the following sections, you will see the controls in each category and the tasks for which they are designed.

With the discussion of the various controls, you see a mention of the properties of a control. For example, a TextBox has a Text property (among many others), a ListBox has a SelectedIndex property. Properties can only be set programmatically and not with the Properties Grid. Reading and changing control properties programmatically is discussed in detail in the next chapter.

### List Controls

```
<asp:DropDownList ID="FavoriteLanguage" runat="server">
<asp:ListItem Value="C#">C#</asp:ListItem>
<asp:ListItem Value="Visual Basic">Visual Basic</asp:ListItem>
<asp:ListItem Value="CSS">CSS</asp:ListItem>
</asp:DropDownList>
```

The DropDown enables a user to select only one item at a time. To see the currently active and selected item of a list control programmatically, you can look at its SelectedValue, SelectedItem, or SelectedIndex. SelectedValue returns a string that contains the value for the selected item, like C# or Visual Basic in the preceding example. SelectedIndex returns the zero-based index of the item in the list. If the user had chosen C#, SelectedIndex would be 0. Similarly, if the user had chosen CSS, the index would be 2 (the third item in the list).

For controls that allow multiple selections (like CheckListBox and ListBox), you can loop through the Items collection and see what items are selected. In this case, SelectedItem returns only the first selected item in the list; not all of them. You learn how to access all the selected items in the next exercise. Note that in the browser, the DropDownList and List control render as a <select> element, attributes such as size and multiple, set by these controls determine the appearance and behavior of the HTML element in the browser.

The BulletedList control doesn't allow a user to make selections, and as such doesn't support these properties.

To see how to add items to your list control, and how to read the selected values, the following exercise guides you through creating a simple Web Form with two list controls that ask users for their favorite programming language.

### TRY OUT Working with List Controls

In this exercise you add two list controls to a page. Additionally, you add a button that, when clicked, displays the selected items as text in a Label control.

- 1. In the Demo folder, create a new Web Form named ListControls.aspx. Make sure you create a Code Behind file by checking the Place Code in Separate file.
- 2. Switch to Design View and drag a DropDownList from the Toolbox onto the design view of the page within the <div> element that is already present in your page.
- 3. Notice that as you drop the DropDownList control on the page, a pop-up menu appears that is labeled DropDownList Tasks, as shown in Figure 4-6.

This pop-up menu is called the Smart Tasks panel. When it appears, it gives you access to the common controls of the control it belongs to. In the case of the DropDownList, you get three options. The first option enables you to bind the control to a data source, which is demonstrated in Chapter 13. The second item enables you to manually add items to the list, and the last option sets the AutoPostBack property of the control. With this option checked, the control submits the page in which it is placed to the server as the user chooses a new item from the list. Note that the browser must have JavaScript enabled for this to work.

The Smart Tasks panel appears only for the complex controls that have a lot of features. It won't appear for simple controls like Button or Label. To reopen the Smart Tasks panel, right-click the control in the designer and choose Smart Tag. Alternatively, click the small arrow at the top-right corner of the control, or press Shift+Alt+F10 when the control is selected. You can also open the Smart Tasks panel from markup view. Simply click anywhere on the opening or closing tag of a control or other piece of markup and press Ctrl+Dot (Ctrl+.). Alternatively, hover over the blue rectangle at the Smart Tasks panel of the DropDownList, click the grey arrow that appears.

On the Smart Tasks panel of the DropDownList, click the Edit Items to bring up the ListItem Collection Editor, in Figure 4-7.

This dialog box enables you to add new items to the list control. You add them through the window and they are added as <asp:ListItem> elements within the tags for the control.

- 4. Click the Add button on the left side of the screen to insert a new list item. Then in the Properties Grid on the right, enter C# for the Text property and press Tab.
