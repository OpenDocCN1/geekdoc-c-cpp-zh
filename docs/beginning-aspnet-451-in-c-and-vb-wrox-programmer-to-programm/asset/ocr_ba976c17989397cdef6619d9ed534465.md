Note that with server side redirects, you must specify the .aspx extension, as a server-side redirect bypasses the routing mechanism.

# How It Works

Instead of instructing the browser to fetch a new page, Server.Transfer takes place completely at the server. The output of the old page is discarded and a new page life cycle is started for the page that is being transferred to. This page generates its content and sends it back to the browser, leaving the browser’s address bar unmodified.

If you look at the emitted HTML in the browser, you see that the form action is set to the new page so any postback that occurs is executed against each page, which in turn changes the address in the address bar:

```
<form method="post" action="Target.aspx?Test=SomeValue" id="form1">
</form>
```
