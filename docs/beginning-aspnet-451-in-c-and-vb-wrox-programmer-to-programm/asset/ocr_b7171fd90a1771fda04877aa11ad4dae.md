# How It Works

When ASP.NET encounters a request for a folder by a file extension (for example, /Styles/css or /Scripts/), it takes all the files with the extension, combines them into a single file, and optimizes it by removing unused code as comments and irrelevant whitespace. The operation of this result is streamed back to the browser as a single file. To overcome caching issues, you don't point to /Styles/css from your server code. Instead, you add a StyleBundle to the Bundles collection in the Global.asax:Application_Start event handler and specify a virtual path that returns the style sheets. The IncludeDirectory method then scans the requested folder (-/) for the specified files (all files with a .css extension), which are bundled and minified and streamed back to the browser whenever a request for the virtual path StyleSheets is. ASP.NET adds a v parameter to the path with a cache key so the browser can cache the resulting CSS file. When the underlying files change (or when you delete or add files to the Styles folder), the cache changes as well, which causes the browser to fetch a fresh copy from the server.

Notice how in the final CSS from step 9 the underline property comes first. The standard logic for the bundling mechanism is to put files in alphabetical order. Some exceptions to this rule exist. For example, known frameworks as jQuery that other code may depend on are included first to avoid dependency issues.
