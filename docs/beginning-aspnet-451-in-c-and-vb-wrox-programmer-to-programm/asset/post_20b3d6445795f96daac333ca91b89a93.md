# How It Works

The Query Designer in SSMS is a very helpful tool for creating new queries against your database. Instead of hand-coding the entire SQL statement in the SQL pane, you use the Diagram and Criteria panes to create your queries visually. You can also use the SQL pane to make manual tweaks to the code that SSMS generates for you.

The final query executed returned all the rows that contain the word rock and had an ID larger than 4. The query shown in step 8 has a WHERE clause that consists of two parts: the first part limits the rows to those with an ID larger than 4. The second part filters the rows to contain the text rock. The two criteria are both applied at the same time using the AND keyword, so only rows with Alternative Rock, Indie Rock, and Rock genres are returned, while leaving out the Hard Rock and Grunge genres.

The Unicode data type enables you to store text for many different languages. In your queries you can usually leave out the ID because SQL Server will figure it out for you. For more information on the ID, check out this article: http://tinyurl.com/398wn7

At the end, the result is sorted in descending order on the SortColumn using the syntax ORDER BY SortOrder DESC. Notice that SortOrder is an arbitrarily chosen name. You can easily give this column a different name, or a different column like the Name column to retrieve the genres in alphabetical order.

In this example, you may only retrieve data from a single table. However, in real-world applications you can get your data from multiple tables that are somewhat related to each other. Define this relationship in SQL syntax using the JOIN keyword.

# Joining Data

A JOIN enables you to express a relationship between one or more tables. For example, you can use a JOIN to find all the results from the Review table that have been published in a specific genre and then select some columns from the Review table together with the Name of the genre.

The basic syntax for a JOIN looks like the following bold code:

```sql
SELECT
  SomeColumn
FROM
  LeftTable
  INNER JOIN RightTable ON LeftTable.SomeColumn = RightTable.SomeColumn
```

The first part is the SELECT part of the query you saw earlier, and the second part introduces the keywords INNER JOIN to specify the relationship between the two tables. This query only returns the rows in the leftTable with a corresponding row in RightTable. For example, to return the ID and the title of a review with the name of the genre it belongs to, you use this SQL statement:

```sql
SELECT
  Review.Id, Review.Title, Review.Genre
FROM
  Review
  INNER JOIN Genre ON Review.GenreId = Genre.Id
```

Note that in the SELECT statement each column is prefixed with the table name. This makes it clear what you are referring to and avoids conflicts when multiple tables have similar column names (like the id column that exists in both).

In addition to an INNER JOIN that returns only matching rows, you can also use an OUTER JOIN. The OUTER JOIN retrieves reviews from one table regardless of whether there is a matching row in the other. The following example returns a list of all the genres in the system together with the reviews in each genre:

```sql
SELECT
  Genre.Id, Genre.Name, Review.Title
FROM
  Genre
  LEFT OUTER JOIN Review ON Genre.Id = Review.GenreId
```

For each review assigned to a genre, a unique row is returned that contains the review's title. However, if a genre has no reviews assigned, the row is still returned as shown in Figure 12-14:
