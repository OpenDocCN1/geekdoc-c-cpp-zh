## DEBUGGING WITH THE PAGE INSPECTOR

If you want to build a site that is easy to maintain, probably make use of many of the features of ASP.NET and the browser offers. For example, you're probably using a master page for the general layout, you use page-specific content in a content page that uses that page, you may have one or more user controls for content to use across your site (such as the Contact Form in the Planet Wrox website), and you may be using themes and skins to separate the design from the rest of your application.

In the browser, all of this code comes together as a single HTML document in that includes references to external resources as JavaScript and CSS files. Because it's a single file, it is hard to debug code and understand where a certain piece of HTML comes from. In addition, multiple CSS selectors can influence the layout of your page, it may be hard to track down the file in which a certain piece of CSS is defined. Using the Page Inspector, introduced in VS 2012, this now becomes much easier.

## Introducing the Page Inspector

The Page Inspector is a diagnostics tool that runs inside Visual Studio and your browser, the ASP.NET run, and your source files. The Page Inspector comes with Visual Studio so you don't need to do anything to make use of it.

Although an upcoming exercise shows you many of the features that the Page Inspector offers, here's a quick description of how you can use it:

- You start the Page Inspector by choosing it as your target browser in the Debug Target drop-down. You then start your site as normally using F5 or Ctrl+F5.
- The Page Inspector presents itself as a browser window in the IDE (so you can see what the page looks like), along with a number of tools windows to diagnose your code.
- Once loaded, you can use the Page Inspector button to look at the various elements available in your page as navigation elements, buttons, and more.
- While hovering over the elements in the Page Inspector, the code editor is updated with a preview of the documents that contributed the HTML you're inspecting. As mentioned in the introduction of this section, this could be a master page, a content page, a user control, and so on.
- You can make these changes in VS and then you refresh the Page Inspector to show them up in the final page.
- The Page Inspector also helps you find the CSS rules in your CSS files, whether they are defined in a theme's folder or a custom folder.

If you've ever used Firebug (for Firefox) or the IE or Chrome Developer tools, some of this may sound familiar. These tools also enable you to inspect HTML elements in your page and look at the associated CSS. What makes the Page Inspector different and very special is that it is able to relate the final HTML back to the original ASP.NET source files. This enables editing of the file in the IDE, making changes and preserving the results.

You get a good look at the Page Inspector and its feature set in the exercise in the next section.

## Using the Page Inspector

Getting with the Page Inspector is pretty simple. It basically ships with VS, it's ready for use. However, it has a few prerequisites. First of all, you need to have Internet Explorer or later installed on your machine. Second, your site needs to run against .NET 4 or later. Because the Planet Wrox site runs against .NET 4.5.1, this is not a problem. Third, the Page Inspector needs to be installed and registered correctly on your machine. This is not either problem. The first prerequisite is that your site needs to be in debug mode, or you need to add a special key to your web.config to enable the Page Inspector. Enabled debugging for the Planet Wrox site earlier in this chapter, which means you don't have to do anything else for the Page Inspector to work correctly. For cases where you don't have debugging enabled and still want to use the Page Inspector, enable debugging or add the following key to your web.config in the appSettings element:

```xml
<appSettings>
  <add key="PageInspector:ServerCodeMappingSupport" value="Enabled"/>
</appSettings>
```

If debugging is not enabled or is not present, VS gives you a warning when you invoke the Page Inspector.
