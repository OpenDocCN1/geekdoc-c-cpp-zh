## AN INTRODUCTION TO ASP.NET 4.5.1

When you type a URL like www.xyz.com in your browser and press Enter, the browser sends a request to the web server at address. This is through HTTP, the HyperText Transfer Protocol. HTTP is the protocol by which browsers and web servers communicate. When you request the URL, you send a request to the server. When the server is active and the request is valid, the server accepts the request, and then sends the response back to the client browser. The relationship between the request and response is shown in Figure 1-8.

Because you are using IIS Express, the server and client are really the same machine. However, in a real-world scenario, you would host your website on an external web server where it can be accessed by many different clients.

For static files, like HTML files or images, the web server simply reads the file from its local hard drive and sends it to the browser. For dynamic files, such as ASP pages, this is obviously not good enough. If the web server was to send the ASP page directly to the browser as a text file, you wouldn't have seen the current date and time in the browser, but instead you would have seen the actual code (DateTime.ToString() %). So, instead of sending the direct file, the web server hands over the request to another piece of software that is able to process the page. This is done with a concept called

Application Mapping or Handler Mapping, where an extension of a file (.aspx in this example) is mapped to an application that is capable of handling it. During the processing of the page, three main areas can influence the way the page eventually ends up:

- Static text, like HTML, CSS, or JavaScript code you place in a page, is sent to the browser. You learn more about HTML, CSS, and JavaScript (a programming language used at the client) in this and subsequent chapters, including Chapter 3, which gives you a detailed look at CSS.
- ASP.NET Server Controls. These controls are placed in your ASP page and when they are processed, you emit HTML that is inserted in the page. You learn more about server controls after the discussion of HTML in this chapter, and Chapter 4 is devoted to explaining ASP.NET Server Controls.
- Programming code. When you include code, like Basic .NET or C#, directly in a page, as you saw in the previous Try It Out, you can also place code in a separate code file. The official term for this code is Code Beside. However, most developers refer to this as the Code Behind, which is the term I'll stick to in this. This code can be executed by the run time automatically, or based on a user's action. Either way, execution of the code can greatly influence the way the page is displayed, by accessing databases, performing calculations, and more. You learn more about this Code Behind in the next chapter, and programming your ASP.NET web pages is discussed in detail in Chapter 5.

Once the page is done processing, and all the HTML for the page has been collected, the HTML is sent back to the browser. The browser reads it, parses it, and, finally, displays the page for you to look at.

Because HTML is critical for displaying web pages, the next section gives you an overview of HTML.

### Understanding HTML

HTML is the de facto language for creating web pages and is understood by every browser that exists today. Since the beginning of the '90s it has been the driving force of the World Wide Web, part of the Internet that deals with web pages. HTML documents are simple text files that contain markup, text, and additional details that influence that text. The most recent version of HTML is HTML5. Although the specification of HTML5 is still under development, a lot of modern browsers support important parts of this specification, and this support increases with each new release of these browsers. Despite the fact that not all browsers support HTML5 fully, it is

really the future of HTML-based applications, and therefore use it in this book and for the Planet Wrox demo website. Don't worry about the limited browser support too much. All major browsers support all of the HTML5 features you use in this book, or support can be easily simulated by a script called Modernizr, which you see later in the book.

### HTML Elements and Tags

HTML uses text surrounded by brackets to indicate how your content should be rendered (displayed) in the browser. The text with angle brackets is referred to as a tag; a pair of tags holding some text or other content is referred to as an element. Take another look at the HTML you saw in the previous Try Out you opened the source window for the browser:

```
<h2>World</h2>
<p>Welcome to Beginning ASP.NET 4.5.1 on 11/16/2013 4:18:07 PM</p>
```

The first line of this example contains an <h2> element with an opening tag <h2> and a closing tag </h2>. This element is used to signify a heading at the second level (if you scroll up in the final source in the browser, with a similar tag, but with an additional slash (/) in </h2>). Any text between this opening and closing tags is considered part of the element, and is thus rendered in a larger font. In most browsers, the text is rendered as a heading. Similar to the <h2> tag are tags for creating headings up to level six, such as <h1>, <h3>, and so on.

Below the heading, you see a <p> element, which is used to denote a paragraph. By default, a browser renders a paragraph with some additional margin spacing at the bottom, although you can override that behavior.

Many tags are available in HTML, too many to cover them all. The following table lists some of the most important tags and how they can be used. For a complete list of all HTML elements, take a look at the website that maintains the HTML standard: www.w3.org/TR/html5/index.html.
