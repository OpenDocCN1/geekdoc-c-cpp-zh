# Introducing Browser Link

Browser Link enables Visual Studio to communicate with any open browser that is displaying a page from your site. When Browser Link is enabled (it's on default) you can let Visual Studio send a message to all open browsers to refresh the page when you make a change in a page in Visual Studio. This is a great time saver as reloading all browsers is done automatically. Browser Link works by injecting a JavaScript library at the bottom of the page. That JavaScript library uses SignalR under the hood for communication with Visual Studio. SignalR enables bi-directional communication between servers and clients and can be used for real-time solutions such as chat and live notifications. Visual Studio uses it to inform browsers of changes to the state. You can learn more about SignalR on ASP.NET at www.asp.net/signalr although no knowledge about SignalR is needed to work with Browser Link; as you'll in the next section, using Browser Link is simply means.

# Using Browser Link

Since Browser Link is on by default, you don't have to do anything to use it. You simply start one or more browsers, make changes to your site in Visual Studio, and then Ctrl+Alt+Enter to refresh the windows. You can turn Browser Link off and back on by clicking the arrow next to the Refresh icon in the Standard toolbar shown in Figure 18-29.

Using the same menu, you can also refresh all linked browsers (as an alternative for the Ctrl+Alt+Enter shortcut) and bring up the Browser Link Dashboard, shown in Figure 18-30.

The Browser Link Dashboard allows you to manually refresh an individual browser (by clicking its name). It also lists any issues you may need to resolve before using the debug option in Browser Link (such as the web.config file.
