# Calling Services from Client-side Code

Calling a WCF service from a client HTML page is really simple. ASP.NET takes care of most the hard work for you by generating the JavaScript to interact with the service. You all have to register the service with the ScriptManager control and then call it from client-side code. Given the NameService you saw earlier, you can set the ScriptManager as follows:

```
<asp:ScriptManager ID="ScriptManager1" runat="server">
 <Services>
  <asp:ServiceReference Path="~/WebServices/NameService.svc" />
 </Services>
</asp:ScriptManager>
```

In this example, the service file is called NameService.svc and is located in a folder WebServices in the root of your website.

Once you set up the service, you can call the service from client-side JavaScript in an ASPX page like this:

```
NameService.HelloWorld('Imar', helloWorldCallback);

function helloWorldCallback(result)
n  alert(result);
}
```

Note that this code uses camel case and Pascal case. To align with the .NET programming guidelines, the service method uses Pascal casing and is HelloWorld. In JavaScript it's common to use camel case, and thus the callback is written as helloCallback with a lowercase "h". I stick to naming conventions throughout the chapter, which will help you determine whether it is a client-side, or a server-side method. To call a service method, use ServiceName.Method. So, in the following example, NameService is the name of the service, and HelloWorld is the method you want to call.

Although the actual service definition only has a single parameter (the name parameter), the name parameter I set up in the HelloWorld service method is in this example for four parameters. The first one is the name parameter, and if you expected more parameters, they would be listed here as well. The second parameter allows you to pass a success callback—a method you define to get called when the service call completes successfully. In this example, the method is called HelloWorldCallback. You can name this anything you want (as long as it's a valid name in JavaScript), but I prefer to call it serviceMethodCallback to clearly express which code it serves as a callback. As a parameter, the callback method receives the value returned from the service. In this example, the result is a simple string, but you can see later how to pass complex objects.
