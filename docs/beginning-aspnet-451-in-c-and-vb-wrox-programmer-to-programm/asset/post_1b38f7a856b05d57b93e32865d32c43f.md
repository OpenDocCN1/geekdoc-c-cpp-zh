# How It Works

You have two important things to look at in this exercise. First of all, there is the LINQ query that is used to get the genres and reviews from the database. This query uses Include("Reviews") to prevent lazy loading as you earlier create a new object type with two properties: the Name of the Genre as a String and a collection of Review objects called Reviews. The class diagram for the new object type could look like Figure 1-6.

These Name and Reviews are used in the second important part: the Repeater control with the nested bullet list. First, take a look at the Repeater:

```
<Repeater ID="Repeater1" runat="server">
<ItemTemplate>
<asp:Literal ID="Literal" runat="server"
Text="+# Eval("Name") %></asp:Literal><h3></h3>
<!-- BulletedList here -->
<asp:BulletedList
></ItemTemplate>
</Repeater>
```

Although you haven't worked with the Repeater control before, it may look familiar, because it works in a manner similar to the other data controls. Within the <ItemTemplate> you define the property that you want repeated for each item in the data source. Using Eval you can get the value of the Name property and assign it to the Literal, which is wrapped in a pair of <h3>. A similar construct is used for the BulletedList to find a DataSource:

```
<asp:BulletedList ID="BulletedList1" runat="server" DisplayMode="Text"
DataSource="+# Eval("Reviews") %> DataField="Title" />
```

In addition to assigning simple properties like the Text of the Literal from the Name of the underlying data, you can also use Eval to get complex properties. In this example, Eval("Reviews") is used

After you have set up the Repeater and the query, you need to start the data-binding process. You do this by assigning the results of the query to the DataSource property of the Repeater, followed by a call to DataBind() as shown in this C# example:

```c
Repeater1.DataSource = allGenres.ToList();
Repeater1.DataBind();
```

These two lines set things in motion: As DataBind is called, the query is executed and the relevant events and reviews are retrieved from the database and bound to the DataSource property. In this example, they are sorted by their Name, but you can order them by other properties, such as SortOrder. When DataBind is called, the Repeater loops through each item in the result set (this item is the anonymous type you just saw) and uses item's Name to fill in the <h3> element with the genre name. The Repeater then assigns the Reviews collection to the inner BulletedList's DataSource property. This control loops over the available Review instances, using Title to build up the bullet list. In this example, you see that genres without reviews are displayed in the list as well. # USING BINDING WITH LINQ QUERIES

So far you have seen one way to bind the results of a LINQ query against a control in your ASPX page: assign the data to the control's DataSource property and then call DataBind(). Way of getting data into the controls is bit limited, as it does not support the editing, updating, and deleting of data directly. In order to support these operations, ASP.NET has a featured Model Binding that supports full CRUD operations against a data source from the data-bound controls such as the GridView, ListView, and DetailsView. works in the next section.

# Introducing Model Binding

Model Binding is a capability built into the data-bound controls to execute CRUD operations against a data source. Instead of depending on a data source control such as the Sql you've seen before, Model Binding relies on methods that you can define in your copy to supply the data and handle changes such as an insert, an update, or a deletion. These methods can be defined in the Code Behind of the Web Forms that contain the data-bound controls, or in other classes in your project. To point a data-bound control to methods that can retrieve or get

| Method | Description |
| :--- | :--- |
| Select | This method is used to retrieve data. |
| Insert | This method is used to insert new data. |
| Update | This method is used to update existing data. |
| Delete | This method is used to delete data. |

A very powerful feature of Model Binding is the ability to automatically generate the code needed to map data between your UI and your data model. This can save you a lot of manual coding.
