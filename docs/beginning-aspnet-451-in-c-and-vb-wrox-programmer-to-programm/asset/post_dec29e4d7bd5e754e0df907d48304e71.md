## USING WEB SERVICES IN AJAXITES

The ability to call web services from an Ajax-enabled ASP.NET is a great addition to your development toolkit. Being able to call a web service means it's now much easier to access data at the server from client-side code, giving you a great alternative to full postbacks. The next section discusses web services.

## What Are Web Services?

Web services are essentially methods that you can call over the Internet and that optionally return data to the calling code. This make them ideal for exchanging data between different systems. Because web services are based on solid and well-understood standards, they make it easy to exchange data between different types of platforms and systems. For example, with a web service it's possible to exchange data between an ASP.NET website running on Microsoft Windows and a PHP-based site running on Linux. But at the same time, it's also possible to exchange data between an ASP.NET or PHP website and a client browser using JavaScript.

WCF service methods are the topic of the next section.

## Introducing WCF

To build web services in an ASP.NET website, you use Windows Communication Foundation (WCF), Microsoft's platform for service-oriented applications using the .NET Framework. In previous versions of ASP.NET you could also use so-called ASMX web services, but these have now been deprecated in favor of WCF. However, this isn't really a problem because WCF can do anything ASMX services could and much more.

WCF supports a variety of differing network communication technologies such as HTTP, .NET Remoting, Microsoft Message Queuing, and Enterprise Services. This makes it an ideal platform for the exchange of data in a variety of scenarios such as locally on a machine, on a corporate network, or over the Internet. For public-facing websites such as the Planet Wrox site, HTTP or HTTPS (the secured version of HTTP) is the natural choice which will work cross-browser and across frameworks.

For information about the supported technologies, check out this article on the MSDN website at http://microsoft.com/library/dd94056.aspx or get a copy of Professional WCF 4: Windows Communication Foundation with .NET 4 by Pablo Cibraro, Kurt Claays, Fabio Cozzolino, Johann Grabnerer; Wrox, 2010; ISBN: 978-0-470-56314-4.

To build a web service, you add a WCF service (with an .svc extension) to your project. As you see, you have a few different templates available, each serving a different purpose. Inside this service file you define a Service Contract and an Operation Contract. The Service Contract defines the overall service and the Operation Contract defines the various methods that are available on the service. The following snippet shows a simple WCF service with a simple method:

# VB.NET

```vb
<ServiceContract(Namespace="")
<AspNetCompatibilityRequirements(
RequirementsMode:=AspNetCompatibilityRequirementsMode.Allowed)>
Public Class NameService
    <OperationContract()>
    Public Function HelloWorld(name String) As String
        Return String.Format("{0}", name)
    End Function
End Class
```

# C#

```csharp
[ServiceContract(Namespace = "")]
[AspNetCompatibilityRequirements(
RequirementsMode = AspNetCompatibilityRequirementsMode.Allowed)]
public class NameService
{
    [OperationContract]
    public string HelloWorld(string name)
    {
        return String.Format("{0}", name);
    }
}
```

You define the Service Contract by applying a ServiceContract attribute to your class. An attribute is like a tag or label that you can stick on code elements, like classes, methods, properties. ## Calling Services from Client-side

Calling web services from client-side is simple. Once you set up the service, you can call it. Using the ScriptManager control as follows:

```asp
<asp:ScriptManager ID="ScriptManager1" runat="server">
  <Services>
    <asp:ServiceReference Path="~/Services/NameService.svc" />
  </Services>
</asp:ScriptManager>
```

In this example, the service file is called NameService.svc and is located in a folder named Services. Once you set up the service, you can call it from JavaScript in an ASPX page like this:

```javascript
NameService.HelloWorld('Imar', helloCallback);

function helloCallback(result) {
    alert(result);
}
```

Note that this code uses camel case and Pascal case. To align with the .NET programming guidelines, the service method uses Pascal casing and In JavaScript it's common to use camel case, and thus the callback is written as helloCallback with a lowercase "h". To call a service method, use ServiceName.Method. So, in the following example, NameService is the name of the service, and HelloWorld is the method you want to call.
