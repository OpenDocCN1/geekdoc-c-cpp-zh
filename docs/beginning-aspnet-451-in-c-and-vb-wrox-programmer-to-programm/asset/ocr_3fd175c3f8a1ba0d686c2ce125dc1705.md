# ## WORKING WITH WEB FORMS

Web Forms, represented by .aspx files, are the core of ASP.NET Web Forms website. They are the actual pages that users see in their browsers when they visit your site.

As learned in the previous chapter, Web Forms can contain a mix of HTML, ASP.NET Server Controls, client-side JavaScript, CSS, and programming logic. To make it easier to see all his code ends up in the browser, VS offers a number of different views on your pages.

# ## The Different Views on Web Forms

VS enables you to look at your Web Form from a different angles. When you have a file with markup—like a Web Form or master page—open in the Document Window, you see three buttons at the bottom-left corner of the window. With these buttons, visible in Figure 2-9, you can switch between the different views. This figure shows a master page, which you will learn about in Chapter 6.

Source View is the default view when you open a page. It shows you the raw HTML and other markup for the page, and is very useful if you tweak the contents of a page and you have a good idea of what you want to change and where. As explained in the previous chapter, I use the Markup View rather than Source View to refer to the markup of ASP and HTML pages.

The Design button enables you to switch the Document Window into Design View, which gives you an idea of how the page will end up. In Design View, you can use the Visual Aids and Formatting Marks submenus from the Main menu to control visual markers like line breaks, borders, and spaces. But summenus offer a menu item called Show that enables you to turn the visual aids on or off. Turning off it is useful if you want to have an idea of how the page ends up in the browser. You should, however, use Design View to get an idea of how the page will end up. Although VS has a great rendering engine that shows the pages in Design View pretty well, you should always check your pages in browsers as well, because what you see in VS is the markup for the page before it gets processed.
