If you want to confirm this is really case, you can add a Label control to the ViewDetails.aspx page and update it with text saying whether or not the item was in the cache:

VB.NET

```vb
Label.Text = "In the cache"

    Label.Text = "NOT in the cache"
Using MyEntities As New PlanetWroxEntities
```

C#

```csharp
Label.Text = "In the cache";
if (myReview == null)
{
    Label.Text = "NOT in the cache";
}
using (PlanetWroxEntities myEntities = new PlanetWroxEntities())
```

This code initially sets the Label Text to "In the cache". However, if the item is not found, the Label is updated to reflect observation.

## How It Works

In the ViewDetails.aspx page you first added few labels that hold relevant properties of the Review, such as its Title, Summary, and Body. You assigned the Label control for the supply of CssClass so you can influence its styling from your CSS files. The .selector assigns an italic font and sets the display property to block, forcing the body text that follows to its own line.

The code in the Code Behind starts by looking at whether or not it can retrieve the item from the cache:

VB.NET
Dim myReview As Review = TryCache(Cache("Reviews" + reviewId.ToString()), Review)

C#
```csharp
myReview = Cache["Reviews" + reviewId.ToString()] as Review;
```

As for the cache key, the code uses a combination of the word Reviews and the Id of each item. If the item is not found in the cache (possibly because you're loading the page for the first time or it expired; ASP.NET removed it), the TryCache method in VB.NET and the as keyword in C# return Nothing/null. So, by checking the myReview variable for value, you can determine whether the item is in the cache. If you're pretty much done, but you don't need to get it from the database using a LINQ to Entities query similar to those you've seen before. The query that uses the SingleOrDefault() operator to limit the query to a single Review instance, because there should only be one by the given ID, or to Nothing/null when the item is not found. What you do when the item is not found is up to you; you can display an error message in a Label informing the user that the item is no longer available, or redirect to the homepage or another page in your site.

After the item is retrieved it's inserted into the cache with the following code:

VB.NET
Cache.Insert("Reviews" + reviewId.ToString(), myReview, Nothing,
DateTime.Now.AddMinutes(20), System.Web.Caching.Cache.NoSlidingExpiration)

C#
```csharp
Cache.Insert("Reviews" + reviewId.ToString(), myReview, null,
DateTime.Now.AddMinutes(20), System.Web.Caching.Cache.NoSlidingExpiration);
```

The first parameter of the Insert method is the cache key and the second parameter is the object you want to cache: the actual Review instance, in this case. The third parameter enables you to hook up any dependency, so the item is removed from the cache when the dependent object changes. This is not used in case, so null (Nothing in VB) is passed. The fourth parameter defines the absolute expiration date: the date and time when the item is considered outdated and has to be removed from the cache. In this case, this is constructed by adding 20 minutes to the current date and time, meaning the item will be cached for a maximum duration of 20 minutes. The final parameter can be used to set a new expiration time every time it is accessed. This is a great way to cache frequently used items and ensures that items that are not often used are removed from the cache sooner. However, the previous example uses an absolute expiration date, which means you have to pass the constant value of System.Cache.NoSlidingExpiration as the sliding expiration parameter because the two parameters are mutually exclusive.

At this stage, if the item exists in the database, you have a valid Review instance, whether or not it came from the cache. This instance is then used to fill the Label controls in the page and the page's Title and Meta.
