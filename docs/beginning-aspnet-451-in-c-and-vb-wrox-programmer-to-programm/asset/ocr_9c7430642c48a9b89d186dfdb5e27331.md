From the first query in this Try Out, it's probably easy to see what the query does: It gets a list of all the reviews in the system that have been authorized and orders them descending on their creation date. The result of the query is then assigned to the authorizedReviews variable. Notice that in both languages you can spread out the query over multiple lines to improve readability. This is not required, but you're encouraged to do it anyway because it makes your queries easier to understand and maintain.

You may notice some strange syntax in the query. The VB.NET example does not use an As clause to define the type of the variable. Similarly, the C# snippet uses the var keyword, also without a type name. You may not conclude from these code snippets, that the variables authorizedReviews are still strongly typed and not just a variable with an undefined type.

> NOTE Strongly typed refer to the fact that the type is explicitly defined when it's declared. Once you've defined the type for a variable (using Dim in VB or the type in C#) you cannot change it anymore at run time. Strongly typed languages—such as C# and VB.NET—bring many advantages, including the ability to check the types being used at compile time, something that a weakly typed programming language cannot do.

Because the code didn't state the type for authorizedReviews (the example used Dim or var instead), NET needs a solution to determine the type. This is done by a concept called type inference, where the compiler is to infer the type of a variable by looking at the right side of the assignment. In C#, the compiler sees that a list of Review objects will be returned from the query, and quickly types the authorizedReviews as a generic IQueryable(Of Review) in VB.NET syntax or IQueryable<Review> in C#. Although this looks a scary and incomprehensible at first, it becomes much easier to understand if you simply read it as "a bunch of Review objects of the type instead of using var or a statement without a data type, but exceptions do exist, as you'll see when anonymous objects are discussed.

These Review objects are then assigned to the DataSource property of the GridView. In previous chapters you saw how to use the DataSource to connect a control such as the GridView to a data source control using the SQLDataSource. By using the DataSource property instead, you can assign the actual data yourself, then the control uses to build up the UI.

# VB.NET

```
GridView1.DataSource = authorizedReviews.ToList();
GridView1.Bind();
```

# C#

