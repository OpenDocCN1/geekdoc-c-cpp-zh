
# Data Types and Variables

Microsoft .NET supports a large number of different programming languages, including VB.NET, C#, and others. All these languages are able to communicate with each other. For example, you can write some code in C#, using Visual Studio Express 2013 for Windows Desktop to compile it to a dll file (a file with reusable code that can be consumed by other .NET applications), and then use in a web application that uses VB.NET as the primary language. Because of this interoperability, it's necessary to agree on some system that enables all .NET languages to understand each other. This system is called the Common Type System (CTS). It is CTS that defines the data types that are accessible by all CTS-compliant languages. Each language is free to define a set of primitive types, which are essentially shortcuts or aliases for the more complex types in the .NET Framework. Even if the CTS defines a type called System.Int32, a language like C# is free to alias this type as int and VB is free to alias this as Integer to make it easier for a developer to work with.

Sometimes you need to convert data from one type to another. For example, you may have an Int32 that you need to treat as a Double. You can do this in a number of different ways.

## Converting and Casting Data Types

The most common way is to convert a type to a String. Web applications use string types in many places. For example, the Text returned from a TextBox is a String, and so is the SelectedValue of a DropDownList. To get a string representation of an Object, you can call its ToString() method. Every object in the .NET world supports this, although the behavior may differ from object to object. It's important to understand that ToString is a method — or an operation — on an object, like a String or a Double and even the parent Object itself. You learn more about methods and objects later in this chapter when object-oriented programming is discussed.

Using ToString() is easy, as the following example that outputs today's date and time on a Label control demonstrates:

### VB.NET

```
Label1.Text = System.DateTime.Now.ToString()
```

### C#

```
Label1.Text = System.DateTime.Now.ToString();
```

Another way to convert data types is using the Convert class.

> Note Classes are an important concept in .NET so they are discussed in their section later in this chapter. For now it's important to understand that a class is like a blueprint for objects that are used in .NET. You can create your own classes, but you will also use many of the standard classes that are part of the .NET Framework.

The Convert class contains functionality to convert a number of data types into another type. The following is a simple example of converting a String containing a value that looks like a boolean into a Boolean type:

### VB.NET

```
Dim myBoolean1 As Boolean = Convert.ToBoolean("True")   ' Results in True
Dim myBoolean2 As Boolean = Convert.ToBoolean("False") ' Results in False
```

### C#

```
bool myBoolean1 = Convert.ToBoolean("true");   // Results in true
bool myBoolean2 = Convert.ToBoolean("false"); // Results in false
```

Besides the ToString method, Convert offers you a host of conversion methods, including Int32(for integer types), ToDateTime(for dates), and ToString.

Another way to convert one type into another is using casting. Casting you actually force one type into another, which is different from converting, in which the underlying value of a data is transformed into a new value.

Casting only works for compatible types. You can, for example, cast a DateTime to an Integer. You can, however, cast similar types, like a Double to an Integer or a String to an Object. The reverse of the example isn't always true. Earlier that every data type in the .NET Framework is based on the Object data type, meaning that, for example, a String is an Object. However, not every Object is a String. When you try to cast one type into another get a compilation or runtime error, keep this in mind. Later chapters in this book will show you

To cast one type into another using VB.NET, you have a few options. You can use CType and DirectCast. CType is a bit more flexible in that it allows you to cast between two objects look similar. DirectCast, on the other hand, allows you to cast between compatible types performs slightly slower. The VB.NET example shows how this works:

```
Dim ol As Object = 1
Dim i1 As Integer = DirectCast(ol, Integer)   ' Works, because ol is an Integer
Dim i2 As Integer = CType(ol, Integer)      ' Works, because ol is an Integer

Dim o2 As Double = 1
Dim i3 As Integer = DirectCast(o2, Integer)   ' Does not compile, because o2 is
                               not an Integer
Dim i4 As Integer = CType(o2, Integer)      ' Works, because o2 looks like an
                               Integer
```

In the first part of the example, an object ol was declared and assigned as an Object, its underlying value is Integer of 1. When DirectCast is called, the cast succeeds because ol is, under the head, like an

In the second example, o2 is therefore, declared as a Double, a numeric type that looks something like Integer, but isnt really one. The call to DirectCast fails because Double cannot be cast to an Integer. CType, on the other hand, works, because the underlying value of the variable o2 looks like an Integer and can be cast to. It's important to realize that the Double has a decimal part, that part gets lost when casting it to an Integer.

The third option to cast in VB.NET is using the TryCast, which is somewhat similar to the two other options. When an object cannot be correctly cast, TryCast returns Nothing, whereas DirectCast and CType result in a crash of the code.

In C# you have two options to cast. The most common way is to put the type in parentheses in front of the expression you want to cast. This works similarly to CType in VB:

```
object ol = 1;
int i1 = (int)ol;             // Works

double o2 = 1;
int i12 = (int)o2;            // Works
```

Alternatively, you can use the keyword, which works similarly to TryCast in VB.NET in that the code doesn't crash if the cast fails. ## Using Arrays and Collections

So the data types you have are relatively straightforward and singular objects. For example, you store a value of True or False in a Boolean type, and you store a number 123 in Integer. But what if you have the need to store lots of integers? You may have the need to do if you want to store the points of a complex shape like a polygon. Or you may have the need to store all the roles that your application supports in a single variable so you can show them on a web page in the Management section, for example. Here's where arrays and collections come to the rescue.
