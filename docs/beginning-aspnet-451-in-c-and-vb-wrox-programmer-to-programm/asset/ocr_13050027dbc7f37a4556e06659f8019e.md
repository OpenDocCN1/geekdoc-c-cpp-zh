# How It Works

When you use Response.Redirect, ASP.NET sends an instruction to the browser to let it fetch a new page. In technical terms, it sends a "302 HTTP status code to indicate the page has moved temporarily. With this instruction it also sends the new URL, so the browser understands what page to fetch next. In this instance the new page was Target.aspx?test=SomeValue, which contains both the page name and a query string. The Target.aspx page is then requested by the browser, the Page_Load event fires, and the query string is displayed on the page. Because of this client, the new page name and query string are fully exposed to the client. If you use Response.RedirectPermanent, ASP.NET sends out "301 Moved Permanently". For some browsers, this means that if the original page has previously been cached by the browser, you're redirected to the new page if you request the original page. Once the browser cache is cleared, a request is made for the original page. Other browsers may continue to request the original page. Search engines interpret the 301 redirect as "not fetching this page again" and the page will no longer be indexed.

Redirects follow the same naming convention for URLs as used in server controls, where you can redirect a page like ~/Default.aspx to redirect the user to the file Default.aspx in the root.

In contrast to Response.Redirect and Response.RedirectPermanent, there is also Server.Transfer, which redirects to another page at the server.
