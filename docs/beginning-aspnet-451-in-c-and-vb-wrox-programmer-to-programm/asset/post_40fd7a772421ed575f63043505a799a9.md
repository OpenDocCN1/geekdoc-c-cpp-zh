
At run time, the code accesses these properties like this:

# VB.NET

```
myMessage.From = New MailAddress(AppConfiguration.FromAddress, AppConfiguration.FromName)
```

# C#

```c
myMessage.From = new MailAddress(AppConfiguration.FromAddress, AppConfiguration.FromName);
```

Because the properties have been defined as Shared (in C#), you can access them directly on the AppConfiguration class, without the need to create a new instance of AppConfiguration.

Although you could also use <appSettings> element in Web.config directly (for example, you could use ConfigurationManager.AppSettings.Get("FromAddress") to get the e-mail address in ContactForm.ascx file), it's better to wrap the <appSettings> elements in properties of their own class. This solution gives you IntelliSense on the AppConfiguration class, making it easy to see what configuration properties are available. It allows you to write centralized code that throws exception when the required application settings cannot be found or that supplies sensible defaults. Notice how the properties throw an exception only when a valid value cannot be returned. If you access Web.config directly in your code, you need to check for valid every time you access a setting.

The same principle is used for the MailOnError setting. When an exception occurs at run time, the code in Application_Error now sets the MailOnError property. This property then checks the <appSettings> element of Web.config to determine if an error message should be e-mailed. Because the MailOnError property is a boolean, the code uses Convert.ToBoolean to convert the string returned from the Web.config file into a boolean.

By storing values in Web.config instead of hard-coded them, your sites become easier to maintain and deploy. When you go live, all you need to create a copy of Web.config for your production environment and change a few settings. This enables you to turn off error logging by e-mail on your development machine.

With the hard-coded application settings moved to the central Web.config file, the next step in the deployment process is optimizing your CSS and JavaScript references.

## INTRODUCING BUNDLING AND MINIFICATION

Bundling and minification are two features that have been added to ASP.NET 4.5. Both are designed to improve the performance of your site by minimizing the number and size of your CSS and JavaScript files. With bundling, the ASP.NET runtime combines one or more CSS or JavaScript files into a single request. This minimizes the overhead, as the browser needs to make fewer requests. Minification works by removing irrelevant code from these files. Combining these two techniques greatly enhances the performance of your site.

The cool thing bundling and minification is that they are really simple to do, and require hardly any code. As an example, imagine you have two CSS files in your Styles folder called 1.css and 2.css. Without bundling and minification, you may have something like this in your master page:

```html
<link href="Styles/1.css" rel="stylesheet" type="text/css" />
<link href="Styles/2.css" rel="stylesheet" type="text/css" />
```

To enable bundling and minification, you change these two lines into the following single line:

```html
<link href="Styles/*.css" rel="stylesheet" type="text/css" />
```

Notice that you no longer specify a filename after the dot. Instead, just specify a file extension — .css in the Styles folder, bundle them into single response, and minify by removing unnecessary content like whitespace and comments. This final result is streamed to the browser, where it's interpreted the exact same way as it was with two separate files.

You can bundle and minify JavaScript files the same way by specifying js as the file extension to add rather than .css.

One problem with the previous example code is that if you change the CSS or JavaScript files, the browser may continue to use the old files. You can overcome this by creating a stylebundle that collects all the CSS files in a particular folder which are rendered as a <link> with a unique key for the files that is appended to the query string. As long as the files are unmodified on disk the same key is used, which tells the browser it's safe to keep using a cached copy of the file. However, as you change one of the files, the key changes as well, which in turn causes the browser to request a fresh copy of the bundle from the server. You will see how this works in the next exercise.

Enabling bundling and minification in your ASP.NET website is a three-step process:

1. Install the AspNet.WebOptimization.WebForms package using NuGet.
2. Enable bundling by writing code in Global.asax.
3. Remove <link> and <script> elements to replace them with a single control at the correct source.

The current page doesn't benefit a lot from bundling and minification because the number of CSS and JavaScript files is low. In addition, the CSS for the site is placed in the Styles folder which is not supported by bundling and minification. However, to show how to use bundling and minification in your own sites, where it may result in improved performance, in this exercise you optimize a few styles so that the Styles folder content is bundled and minified.

## TRY IT Using Bundling and Minification

In this exercise, add two new CSS files to the Styles folder. Then enable bundling and minification for this folder

3. Open your Global.asax file and at the top of the file, below the Import statement for System, add the following Import statement:

4. In the Application_Start event handler in the same file, add the following code below the line that creates the Bundles:

VB.NET
```vb
Bundles.Add(New StyleBundle("~/Styles*").IncludeDirectory("~/Styles", "*.css"))
```

C#
```csharp
Bundles.Add(new StyleBundle("~/Styles*").IncludeDirectory("~/Styles", "*.css"));
```

The path (~/Styles*) that is passed to the StyleBundle's constructor is the virtual path to which the bundle goes to respond. You can make your path anything as long as it maps to an existing folder (for example, ~/Styles).

9. Save all your changes and request the homepage in your browser. Notice how the heading is now underlined and green.

## How It Works

When ASP.NET encounters a request for a folder by a file extension (for example, /Styles/css or /Scripts/), it takes all the files with the extension, combines them into a single file, and optimizes it by removing unused code as comments and irrelevant whitespace. The operation of this result is streamed back to the browser as a single file. To overcome caching issues, you don't point to /Styles/css from your server code. Instead, you add a StyleBundle to the Bundles collection in the Global.asax:Application_Start event handler and specify a virtual path that returns the style sheets. The IncludeDirectory method then scans the requested folder (-/) for the specified files (all files with a .css extension), which are bundled and minified and streamed back to the browser whenever a request for the virtual path StylesSheets is.
