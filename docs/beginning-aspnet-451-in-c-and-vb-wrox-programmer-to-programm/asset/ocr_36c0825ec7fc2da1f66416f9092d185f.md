# Access Modifiers

Earlier in this chapter I mentioned a core concept of encapsulation. By creating members such as functions and properties, you make an object responsible for the implementation. Other objects interacting with this object consider those methods and properties as black boxes. They pass data in and optionally expect some result back. How the method performs its work is of no interest to them; it should work as advertised. To enable an object to share some of its inner operations, you need a way to control access to types and members. You can do this by specifying an access modifier in front of the class, property, or method name. The following table lists the available access modifiers for C# and VB.NET and explains their purpose.

| C# | VB.NET | DESCRIPTION |
| --- | --- | --- |
| public | Public | The class or member can be accessed from everywhere, including code outside the current application. |
| protected | Protected | Code with a protected access modifier is available only within the type that defines it or within types that inherit from it. For example, a protected member defined in the Page class is accessible to your ASPX page because it inherits from Page. |
| internal | Friend | Limits the accessibility of your code within the same assembly. An assembly is a set of one or more compiled code files (either an .exe or a .dll file) containing reusable .NET code. |
| private | Private | A class or member is accessible only within the type that defines it. For example, with the Person class, the _firstName variable is accessible only within the Person class. Other code, like an ASPX page, cannot access this field directly, and needs to access the public FirstName property to get the first name of a person |

Of these four access modifiers, protected and internal (Object and Friend in VB) can be combined. The other two must be used separately. By combining protected and internal, you can create members that are accessible by the current class and any class that inherits from it in the current assembly only.

Using access modifiers, you can create properties that are read-only for external code but can still be set from within by marking the getter as public.

As some of the other OO concepts, you won't be hiding your specific access modifiers in your code. However, it's good to know that they exist and what they do. That way, you might have a clause about why they don't show up in the IntelliSense list. A fair chance you forgot to specify the public access modifier (Public in VB.NET) on the class in that case. The default is internal (Friend in VB.NET), which makes the class visible to other classes in the same assembly but hides it from code outside the assembly. The keyword public or Public in front of the class definition should fix the problem.
