
# Connecting Your Application to SQL Server 2012

In the following section, I show you how to connect to SQL Server from two different but common scenarios: using SQL Server Authentication and using Windows Authentication when IIS and SQL Server are on the same server. For both scenarios, you will see how to configure SQL Server, the Planet Wrox website, and if necessary, your Windows accounts.

You're likely to use the first scenario when dealing with an external hosting company that hosts your site. When web hosts offer SQL Server, they often use SQL Server Authentication and, as such, you require to pass a username and password to the database.

The second scenario is if you host the site and have both SQL Server 2012 and IIS on the same machine.

More advanced scenarios, such as using Windows Authentication with IIS and SQL Server on two different machines, are beyond the scope of this appendix. For more information about configuring and SQL Server, get yourself a copy of Professional Microsoft SQL Server 2012 Administration by Adam Jorgensen, Steven Wort, Ross LoForte, and Brian Knight, 2012 (Wrox, ISBN: 978-1181-0688-4).

# Scenario 1 — Using SQL Server Authentication

From a configuration point of view, this is probably the easiest scenario to configure: All you need to make sure your SQL Server installation supports SQL Server Authentication, create a user in SQL Server, and use that account in the connection string of the Planet Wrox website. To do this, follow these steps:

- 1. In SQL Server Management Studio, right-click the server name in the Object Explorer shown in Figure B-3, choose Properties, and switch to the Security category. The dialog shown in Figure B-4 appears.

![](img/9e033e3b9560597824f8b22941d6d8bb_824_0.png)

Figure B-4

- 2. If not already selected, choose the SQL Server and Windows Authentication item at the top of the server. Before you click OK, choose the Help item at the top of the screen and read a bit about SQL and Windows Authentication, and determine if you really need SQL Server Authentication. Windows Authentication is more secure than SQL Server Authentication, so you are advised to use it whenever possible.

- 3. If you changed the server authentication, restart SQL Server. You can do this by right-clicking the server in the Object Explorer and choosing Restart. If you get an error about security permissions, you may need to reboot your computer.

- 4. In SQL Server Management Studio's Object Explorer, expand the server's security node at the bottom of Figure B-3. Make sure you choose one under your server, and not the one belonging to a database. Right-click Logins and choose New Login.

- 5. Type a login name, then select the SQL Server Authentication option and type a password (twice). In this and the following examples, I'll use PlanetWroxUser as the username, and PaSwOrd (with a zero instead of the letter o) as the password.

- 6. Clear the Enforce Password Expiration. This also disables User Must Change Password at Next login. Your dialog box should look like the one in Figure B-5.

![](img/9e033e3b9560597824f8b22941d6d8bb_825_0.png)

FIGURE B-5

If you want to learn about the individual settings on this screen, click the Help button at the top of the screen.

- 7. Click OK to create the new account.

With the account created, the next step is to give this new account the proper permissions to the database:

- 1. On the Object Explorer, expand Databases, then the PlanetWrox database, followed by the Security node. Finally, right-click the drop-down, choose SQL User with Login and choose New User.

- 2. In the User Type drop-down, choose SQL User with Login (this option doesn't exist in earlier versions of Management Studio). In the User name box, type PlanetWroxUser.

- 3. In the Login name text box, click PlanetWroxUser again. Alternatively, click the ellipsis button, click Browse, and select the user from the list that has appeared.

- 4. Click Membership in the list on the left and see a box labeled Role Membership (in earlier versions of SQL Server Management Studio this box is the same page where you enter the username). In this box, you can choose a number of roles that you can grant to your new user. The rule here is: Give users as few permissions as possible. A good choice is db_datareader and db_datwriter, which allows the account to both read and write to the database, choose these two options, visible in Figure B-6.

![](img/9e033e3b9560597824f8b22941d6d8bb_826_0.png)

FIGURE B-6

- 5. If you want to set fine-grained security options for your database, click the Security option you see in the left-hand part of Figure B-6. This dialog box enables you to determine permissions for the user account on objects in your database like tables, views, and stored procedures. For the Planet Wrox website, don't need any changes in this dialog box.

- 6. Finally, click OK to create the PlanetWrox User and assign it to db_datareader and db_datwriter.

- 7. You can close SQL Server Management Studio because you're done with it.

Now that SQL Server and your user accounts are configured, the final phase is to configure the website to use this new account.

- 1. Open the web.config file of the deployed Planet Wrox application from the C:\ASNET\Release folder.

- 2. Modify the <connectionStrings> element as follows:

```
<connectionStrings>
<add name="WroxConnectionString" connectionString="Data Source=ServerName;Initial Catalog=PlanetWrox;User ID=PlanetWroxUser;password=PaSwOrd" providerName="System.Data.SqlClient" />
<add name="PlanetWroxEntities" connectionString="Data Source=ServerName;Initial Catalog=PlanetWrox;User ID=PlanetWroxUser;password=PaSwOrd;MultipleActiveResultSets=True;" provider="System.Data.Entity" />
</connectionStrings>
```

In your configuration file, each connection string should be on a single line. Don't forget to replace the value ServerName in the Data Source with a valid server name. Depending on your server and configuration, this could be as simple as (local) to point to SQL Server on the local machine, DatabaseServer to point to a server on the network, or something like DatabaseServer\Sql2012 is the name of an installed instance sql2012 on a machine called DatabaseServer.

- 3. Save the changes and then open the site by browsing your browser. Everything should still work, but the site no longer uses the database in the App_Data folder; it uses the SQL Server you defined in your connection strings instead.

- 4. To make sure this connection string remains available in future updates of the site, you should also add it to the web.config in the website in Visual Studio.

If you get an error when browsing to the site on your localhost, you may need to turn off custom errors in Web.config (for security reasons, set it to RemoteOnly instead of off) to see the actual error message. Possible reasons for an error include an incorrect username, password, or server name in the connection string, and an incorrectly configured role membership for the PlanetWroxUser account.

# Scenario 2 — Using Windows Authentication with IIS and the Database on the Same Machine

This is a common scenario, especially when you're running your server on a local machine that you control yourself. Both the server (either IIS or the built-in development web server) and SQL Server run on the same physical machine. This scenario makes it easy to use Windows Authentication because both the web server and SQL Server use the same Windows Account.

To configure your server for this scenario, follow these steps:

- 1. Determine the account used by your web server. Refer to Chapter 19 for precise details of how to do this, you're likely to need the ApplicationPoolIdentity (called IIS AppPool\NET v4.5 (default)). I am using the IIS AppPool\NET v4.5 in the remainder of this section.

- 2. Next, you need to map this window to a SQL server login. To do this, open SQL Server Management Studio and log in to your SQL Server instance. Expand the Security node for the server (and not of an individual database), as shown at the bottom of Figure B-3. Then right-click Logins and choose New Login.

- 3. Open the Server node of PlanetWrox database, right-click the Users node, and choose New User.

- 4. In the User Type drop-down, choose SQL User with Login (this option doesn't exist in earlier versions of Management Studio). In the User Name text box, choose .NET v4.5.

- 5. For the Login Name text box, click the ellipsis button and click Browse to select a username. Choose the account you configured earlier (called IIS AppPool\NET 4.5) and click OK.

- 6. Check Membership in the left on the list and see a box labeled Database Role Membership (in earlier versions of SQL Server Management Studio this is on the same page where you enter the username). In this box, you can choose a number of roles that you can grant to your new user. The rule here is: Give users as few permissions as possible.
