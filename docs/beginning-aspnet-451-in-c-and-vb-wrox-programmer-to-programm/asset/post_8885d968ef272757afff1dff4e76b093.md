Because the photo album page displays pictures only for the current photo album (identified by the PhotoAlbum query string), you need to find a way to filter the correct pictures from the database using a LINQ query. Fortunately, you can use ASP.NET binding to find and retrieve the ID of the photo album and make it available in the ListView_GetData method. You can use that ID in the Where clause of a LINQ query. To implement this functionality, modify that method as follows. Note that you need to add a/import statement for the namespace System.Web.ModelBinding to bring the QueryString attribute into scope. You can either type this name manually at the top of the code file, or press Ctrl+(Ctrl+dot) in the method definition and pick the name from the list that appears.

```vbnet
Public Function ListListView_GetData(QueryString("PhotoAlbumId")

   Dim myEntities As New PlanetWroxEntities()
   Return From p in myEntities
      Where p.PhotoAlbumId = photoAlbumId
      Select p
End Function
```

```csharp
public IQueryable ListListView_GetData([QueryString("PhotoAlbumId")] int photoAlbumId)

   var myEntities = new PlanetWroxEntities();

      select p;
```

The QueryString attribute applied to the photoAlbumId parameter of the GetData method attribute signals the ASP.NET run to populate that parameter with the value from the associated PhotoAlbumId query string parameter.

```vbnet
Public Sub ListListView_DeleteItem(ByVal id As Integer)
    Using myEntities As New PlanetWroxEntities()
    Dim picture = (From p In myEntities.Pictures
        Where p.Id = id
        Select p).Single()
    myEntities.Pictures.Remove(picture)
    myEntities.SaveChanges()
End Sub
```

# How It Works

In order to understand how this works, I'll describe the ListView control and its templates first, followed by discussion of the Model Binding methods defined in the Code Behind. The LayoutTemplate you added to the ListView serves as the container for the other templates. Between its tags you define the markup that contains the individual items (the pictures for the current album, as well as the user to insert new pictures:

```html
<LayoutTemplate>
  <ul class="ItemContainer">
    <li Id="ItemPlaceholder" runat="server" />
  </ul>
</LayoutTemplate>
```

Note that this \<li> has its ID set to ItemPlaceholder. This tells the ListView control where to add the individual pictures. At runtime, this will be replaced by the actual items from the templates, like ItemTemplate.

When the ListView control displays its data (you will see later how the code retrieves the data), it creates an itemView based on ItemTemplate for each data item in the data source. In this example, each data item is a strongly typed Picture object, which provides access to properties such as Description:

```html
<ItemTemplate>
  <li>
    ToolTip:
    <asp:Label Id="Tooltip" runat="server" Text="<%= Eval("Tooltip")" />
    <asp:Button Id="DeleteButton" runat="server" CommandName="Delete" Text="Delete" CausesValidation="False" />
  </li>
</ItemTemplate>
```

With this code, each item in the data source is presented as a series of labels that represent properties of the picture. Eval(PropertyName) is used to retrieve the value of the object, which is then displayed as the Label control's text. At this stage, the ItemTemplate only displays data about the picture. You can use this to upload and display real pictures later.

Note the CommandName of the button in the ItemTemplate. It's set to Delete, which turns this button into a true Delete button. deleting pictures works when the various methods in the Code Behind are discussed.

The first time you load a new photo album, there won't be any pictures. However, as soon as you add items using the InsertTemplate of the ListView, you'll see them appear in the list.

In contrast to the other data-bound controls, the ListView also supports inserting by an InsertTemplate that contains one or more controls that are bound to properties in the underlying object. For example, the Description property of the picture is like this:

```html
<InsertTemplate>
  <li>
    Description:
    <asp:TextBox Id="Description" runat="server" Text='<% Bind("Description") %>' /><br />
  </li>
</InsertTemplate>
```

Instead of Eval(PropertyName), this code uses Bind(PropertyName) at runtime to set up a two-way mechanism. This ensures that the ASP.NET run figures out the relationship between the Description property of a Picture and the text box called Description, even after a postback. When you enter some details and click the special button (with its CommandName to Set), the control executes the method defined in InsertMethod property, as you'll see effect.
