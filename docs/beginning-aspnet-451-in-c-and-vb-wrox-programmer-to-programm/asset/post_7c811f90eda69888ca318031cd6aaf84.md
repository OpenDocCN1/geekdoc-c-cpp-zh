# Customizing the Appearance of the Data Controls

## How It Works

For the most part, this exercise works as a previous exercise where you displayed a list with the available genres. What's different this time is the way the SqlDataSource is to filter the Review table based on the selection you made in the DataList. Take a look at the code for the SqlDataSource to see how this works:

```asp
<asp:SqlDataSource Id="SqlDataSource2" runat="server"
    ConnectionString="<%= ConnectionStrings.MyConnectionString1 %>"
    SelectCommand="SELECT * FROM Review WHERE [GenreId] = @GenreId">
    <SelectParameters>
        <ControlParameter ControlID="DropDownList1" Name="GenreId"
            PropertyName="SelectedValue" Type="Int32" />
    </SelectParameters>
</asp:SqlDataSource>
```

The SQL statement for SelectCommand contains a parameter for the GenreId variable in the Select statement. This means that the SQL statement returns from the Review table only for a specific genre. At runtime, the value for this parameter is retrieved from the control defined in the ControlParameter element. In this example, the code is set up to get the value from the DropDownList it access its SelectedValue property, so that adds to the PropertyName if you need a different property, you can simply change it in the ControlParameter's declaration.

With this set up, the GridView uses the SqlDataSource for its data. This data source takes the item from the DropList that the user has selected in the list. This value is inserted into the SQL statement, and the results are returned from the database are sent back through the data source to the GridView, which uses them to create the HTML table in the browser.

When you choose a Selection from the drop-down list, you get an empty page with no rows. In this case, the DropDownList returns an empty string as its value (defined in the Value property), which is converted to null, the database equivalent of nothing. This turn causes the query to return rows from the Review table.

It's smart enough to recognize some of underlying types of data in the database so you get a CheckBoxField for boolean (bit) fields in the database, that's about it. # Configuring Columns and Fields of Data-binding Controls

Within the <columns> or <Fields> element of the GridView and the DetailsView, you can add the types of fields shown in the following table.

| FIELD TYPE | DESCRIPTION |
| :--- | :--- |
| BoundField | The default field for most database types. It renders as simple text in read-only mode, and as a TextBox in edit mode. |
| ButtonField | Renders as a link or button enabling you to execute a command on the server. |
| CheckBoxField | Renders as a read-only check box in read-only mode, and as an editable check in edit mode. |
| CommandField | Enables you to set various commands, including editing, updating, and deleting. |
| HyperLinkField | Renders as a link (<a> element). You can set properties like DataNavigateUrl, DataUrlFormatString, and DataTextField to influence the behavior of the hyperlink. You see more of this in the next exercise. |
| ImageField | Renders as an <img> element in the browser. |
| TemplateField | Enables you to define your own look and feel for various templates, like ItemTemplate, InsertTemplate, and EditItemTemplate. |

Clearly, each field type serves a distinct purpose so you can choose the one that best fits your needs. You see some of these fields in more detail in the next exercise.
