
## Using the Navigation Controls

| PROPERTY | DESCRIPTION |
|---|---|
| CssClass | Enables you to set a CSS class attribute that applies to the entire control. |
| StaticEnableDefaultPopOutImage | A boolean that determines whether images are used to indicate submenu on the top-level menu items. |
| DynamicEnableDefaultPopOutImage | A boolean that determines whether images are used to indicate submenu on submenu items. |
| DisappearAfter | Determines the time in milliseconds that menu items remain visible after you hover your mouse away from them. |
| MaximumDynamicDisplayLevels | Determines the level of submenu items that the control can display. Useful with very large site maps to limit the number of items being set to the browser. |
| DataSourceID | The ID of a SiteMapDataSource control that supplies the data for the menu from The sitemap file. |
| Orientation | Determines whether to use a horizontal menu with drop-out submenus, or a vertical menu with fold-out submenus. |
| RenderingMode | Introduced in ASP.NET 4, this property determines whether the control presents itself using tables and inline styles or unordered lists and CSS classes. |
| IncludeStyleBlock | Introduced in ASP.NET 4, this property gives you full control (and responsibility) in styling the control. When set to False, ASP.NET does not add the embedded stylesheet block to lay out the control, making you possible for writing the CSS. |

The Menu control also has a few properties that start with Static or Dynamic, two of which are shown in the preceding table. The Static properties are used to control the main menu items that appear when the page loads. They don't change or get hidden when you hover over them, they are considered static. The submenus are dynamic, because they appear only when you activate the relevant menu items.

In addition to these properties, the Menu control also has a number of style properties that enable you to change the look and feel of the different parts of the menu.

## Using the Rendering Mode

Earlier versions of the Menu control were criticized because of the HTML they generated. ASP. NET 2.0 and 3.5, the Menu control generated bloated HTML using tables and inline styles. Besides increasing the size of the page unnecessarily, this also meant that the Menu was much harder to style using your own CSS. Fortunately, this was fixed in ASP.NET 4 with the introduction of the RenderingMode property on the control. By default in ASP.NET 4.5.1 site, this property ensures the control renders itself as an unordered list using `<ul>` and `<li>` elements. You can override this by setting the RenderingMode property to Table insert.

You see the Menu control and the HTML it generates in the next exercise.

## Creating a Basic Version of the Menu Control

To see how the Menu control operates, you're best off creating a very basic version first. Once you understand how it works and how it operates under the hood, you can style the Menu to your liking so it blends with the design of the rest of your site.

## How It Works

When a page with the menu is sent to the master page, for data. This data source control reads the SiteMapDataSource, defined in the page and hands over the data to the Menu control. Based on hierarchical XML, the Menu is able to generate the necessary HTML and JavaScript. It generates a `<ul> for the top menu items with nested sub-menus. When you hover your mouse over one of the menu items, the submenu becomes visible. This is done by JavaScript.

If you search for the page for the JavaScript code that shows or hides the menu items, you won't find it. So is the JavaScript that is used to show and hide the relevant menu items? The answer is in the `<script>` tag in the page that looks like this:

```
<script src="WebResource.axd?t=vvruWHV77jJneEhWQMZmDB8pPWXKLryjtjbM921Ly00&amp;t=63925026135520" type="javascript"></script>
```

This-script tag references a ASP.NET handler called WebResource.axd. The seemingly remaining characters in the query string (the part of the URL after the question mark?) the ASP.NET run to fetch a JavaScript file that provides the functionality for the menu. The file doesn't exist on your disk, but is returned by the WebResource.axd handler on the fly based on the query string.
