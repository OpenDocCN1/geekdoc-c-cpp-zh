# Using the Rendering Mode

Earlier versions of the Menu control were criticized because of the HTML they generated. ASP NET 2.0 and 3.5, the Menu control generated bloated HTML using tables and inline styles. Besides increasing the size of the page unnecessarily, this also meant that the Menu was much harder to style using your own CSS. Fortunately, this was fixed in ASP.NET 4 with the introduction of the RenderingMode property on the control. By default in ASP.NET 4.5.1 site, this property ensures the control renders itself as an unordered list using <ul> and <li>` elements. You can override this by setting the RenderingMode property to Table insert.

You see the Menu control and the HTML it generates in the next exercise.

# Creating a Basic Version of the Menu Control

To see how the Menu control operates, you're best off creating a very basic version first. Once you understand how it works and how it operates under the hood, you can style the Menu to your liking so it blends with the design of the rest of your site.

# TRY OUT Adding a Menu to the Site

In this exercise, you see how to add a Menu control to the master page that uses the Web.sitemap file to build up the menu. The Menu is added to the <nav> element in the master page and presents the Menu items horizontally. Because of this orientation, this Menu is suitable only for the Monochrome theme. Later you add a TextView to represent the pages in the site, and write some code that shows the Menu for the Monochrome theme and the TreeView for the DarkGrey theme.

+   1. Open the master page in Markup View and locate the <nav> element. Remove the placeholder text `Menu Goes Here.`

2. From the Navigation category of the Toolbox, drag a Menu and drop it between the <nav> tags. Set the CssClass of the Menu control to MainMenu:

```
<nav>
<Menu ID="Menu" runat="server" CssClass="MainMenu"/>
</nav>
```

+   3. Switch to Design View. You may notice that the Design View doesn't look like the final page anymore. That is because you have removed the stylesheet attribute from the <pages> element in Web.config. You can leave this for now. With much of the styling already there, this isn't important. You can still see how the content the cpMainContent placeholder is going to end up in the footer. If your Design View looks much closer to the final page, open the Web.config file and remove the stylesheet attribute from the <pages> element.

+   4. Click the Menu control's gray arrow to open its Smart Tasks panel.

+   5. From the Data Source drop-down list select <New data source>. In the dialog box that appears, click the Site Map icon. Figure 7-3 shows the Data Source Configuration Wizard.

+   6. Click OK to close the dialog box.
