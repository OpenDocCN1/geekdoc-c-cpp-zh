# INTRODUCING SECURITY

Although security can be quite a complex subject, it often revolves around three questions:

- Who are you?
- How can you prove that?
- What are you allowed to do?

# Identity: Who Are You?

Identity is what makes you. The answer to this depends on context. In ASP.NET, identity is often represented by a username. In many cases, ASP.NET 2.0 and later use the identity to identify the user. However, the identity can be more than just a username; it can be a token, a certificate, or some other form. If the user is blocked specifically, access is denied. If the user is allowed, access is granted. To determine who a user is, the system needs to know the user identity.

# Authentication: How Can You Prove That?

Authentication is about providing evidence who you are. In ASP.NET, this is often done with a username and password. ASP.NET 2.0 and later use the application services to support authentication. These services are based on a provider model, which you will learn more about. The application services are still strongly present in ASP.NET 4.5.1 and have been updated to simplify configuration and deployment. Authentication is about your identity.

# Authorization: What Are You Allowed to Do?

To determine what a user is allowed to do, a system needs to know two things: the permissions for the current user and the authorization rules for the resource a user is trying to access.

The permissions for the user are based on their identity (which it represents) and the roles (or security groups) the user is optionally assigned. Similarly, resources can be opened or blocked for specific users or roles. When there is a match between the current user and the authorization rules for the resource a user is trying to access, the user is granted access. If the user is blocked, access is denied.
