At the bottom of the Document Window in Figure 1-9, you see three buttons called Design, Split, and Source. These buttons appear automatically when you're working with a file that contains markup, such as ASPX pages. They enable you to open the Design View of a page (giving you an idea of how the page will look in the browser), its Markup View (the HTML and other markup), or at the same time. How this works is explained in more detail in Chapter 2, but for now, it's important to realize you can switch between Markup, Split, and Design View by clicking one of the three. The Markup View is also often called the Source View or Code View. However, to avoid confusion with the code editor that is used to edit Code Behind files, this book uses the term Markup View exclusively.

# The Start Page

Whenever you start VS, the Start Page is loaded in the Document Window. With the Start Page, you can quickly create new and opening windows and other projects. The Start Page provides a number of links to related news and information about web development. To pin your projects to the Start Page, click the pin icon to the left of the project name in the list with recent projects. To unpin a project, right-click it and choose Remove from List. To reopen the Start Page, choose View Start Page.

To get a feel for how you can use all these windows, the following Try Out shows you how to build a simple web page that contains a few ASP.NET Server Controls.

# TRY OUT Creating Your First ASP.NET Web Page

This Try Out Exercise guides you through creating a new website with a single page that contains a number of ASP.NET Server Controls. See how to use windows like the Document Window and the Solution Explorer, and how to use the Toolbox and the Properties Grid to add ASP.NET Server Controls to the page and change their looks.

- 1. Start VS or Visual Studio 2013.
- 2. If you're using the Express edition, choose Tools Settings and choose Expert Settings to turn on the developer profile that gives you access to the full feature of VS.
- 3. On the File menu create New Web Site. Depending on configuration, you may have to choose File New VS instead. This triggers the New Web Site dialog box.
- 4. In this dialog, make sure ASP.NET Empty Web Site is selected and not the ASP.NET Web Forms item that you used in a previous exercise. Ensure that File System is chosen in the Web Location drop-down list. It doesn't matter if you choose Visual Basic or C# for this. Click OK to create the new site.
- 5. Next, right-click the new website in the Solution Explorer. Make sure you click the website (labeled WebSite2) and not the parent element. It's the highlighted element in Figure 1-5. From the context menu, appears how to create a new Add Item.
- 6. In the new window that appears, click Web Form and type Control as the name. The ASPX extension is added for you automatically when you click the Add button. You can leave the other settings in the dialog box at their default settings. The page should open in Markup View, showing you the default HTML, like the <html><head><title>, and <body> elements that VS adds for you when you create a new page.
- 7. Switch the page to Design View by clicking the Design button at the bottom of the Document Window.
- 8. If the Toolbox isn't open, press Ctrl+Alt+X to open or click the Toolbox Tab to show it and click the pin icon in the top-right corner to make the Toolbox visible at all times. Drag a TextBox and a Button from the Standard category of the Toolbox into the Design View of the page. You should end up with a Design View that looks like Figure 1-10.
- 9. Right-click the button in Design View and choose Properties. In the Properties Grid, click the text property under the Appearance category (shown in Figure 1-11) and change it from Button to Submit Information. As soon as you press Tab or click outside the Properties Grid, the Design View of the page is updated and shows the new text on the button.
- 10. Press Ctrl+F5 to open the page in your default browser. Note that it is not necessarily to save the changes to your page (although it is a good idea to do that anyway using the shortcut Ctrl+S). As soon as you press Ctrl+F to run the page, VS saves all changes to open documents automatically.

# How It Works

When you draw the Button and the TextBox on the Toolbox in Design View, VS added the corresponding code for you in Markup View. Similarly, when you changed the Text property in the Properties Grid, VS automatically updated the markup for the control in Markup View. Instead of using the Properties Grid, you could also have typed the text directly between the quotation marks of the Text property in Markup View.

After changing the Text property, your page should contain some code in Markup View:

```
<asp:TextBox Id="TextBox" runat="server"/> <asp:Button Id="Button" runat="server" Text="Submit Information" />
```

When you press Ctrl+F5 to view the page in your browser, the web server receives the request, the page is processed by the ASP.NET run, and the resulting HTML for the page is sent to the browser.

After you type some text and click, the same process is more or less repeated: The web server receives the request, the page is processed, and the results get sent back to the browser. When you click the button, you cause a postback to occur, where any information contained in the page — such as the text you typed in the text box — is sent to the server. ASP.NET reacts to the postback by reloading the page again. However, this prepopulates controls, like the TextBox, with the values that were sent to the page.

# The Output Window

When you try to build your site using the Build menu, the Output window tells you whether or not the build succeeded. If the build failed, for example because you have a programming error, it tells you the build failed. In the commercial versions of Visual Studio, the Output window is used for other information as well, including the status of extra plug-programs. Building—or compiling is discussed later in this book, including in Chapter 19, which deals with deployment of your website.
