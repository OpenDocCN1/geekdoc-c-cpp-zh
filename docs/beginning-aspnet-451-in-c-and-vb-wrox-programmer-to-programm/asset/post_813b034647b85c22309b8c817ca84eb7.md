
For all other HTTP status codes you haven't defined explicitly, the defaultRedirect attribute is used to determine the custom error page.

The redirectMode attribute determines the way the new page is shown to the user and is discussed later in this chapter.

Although custom error pages shield your users from the exception details, they don't help informing you that an exception occurred. All these pages do hide the real error and show a page with a custom error message inside. To be notified about these exceptions, you could write some code that looks at the exception and then sends you an e-mail with the details. Alternatively, you could write code that inserts the error details in a database, or writes them to a text file.

ASP.NET offers you a central location to write code that is triggered when an exception occurs. You could write this code in a special handler called Application_Error inside the Global.asax file that you first saw in Chapter 11. Inside this event, you can collect relevant data about the exception, stick it in an e-mail, and send it to your own Inbox. This gives you detailed information about exceptions that occur on your site, aiding in fixing the problem as soon as possible. You can see how to write this code in the next exercise.
