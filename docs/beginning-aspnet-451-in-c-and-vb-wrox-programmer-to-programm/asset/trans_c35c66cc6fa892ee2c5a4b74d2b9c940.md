## ASP.NET 4.5.1 简介

当你在浏览器中输入类似 www.xyz.com 的 URL 并按 Enter 时，浏览器会向该地址的 Web 服务器发送请求。这是通过 HTTP，即超文本传输协议进行的。HTTP 是浏览器和 Web 服务器通信的协议。当你请求 URL 时，你向服务器发送请求。当服务器处于活动状态且请求有效时，服务器接受请求，然后将响应发送回客户端浏览器。请求与响应之间的关系如 图 1-8 所示。

由于你使用的是 IIS Express，服务器和客户端实际上是同一台机器。然而，在现实世界场景中，你会将网站托管在外部 Web 服务器上，以便许多不同的客户端可以访问它。

对于静态文件，如 HTML 文件或图像，Web 服务器只需从本地硬盘读取文件并将其发送到浏览器。对于动态文件，如 ASP 页面，这显然不够好。如果 Web 服务器将 ASP 页面直接作为文本文件发送到浏览器，你在浏览器中看到的就不会是当前日期和时间，而是实际的代码（DateTime.ToString() %）。因此，Web 服务器不会直接发送文件，而是将请求交给另一段能够处理页面的软件。这是通过一种称为

在页面处理期间，有三个主要区域会影响页面最终呈现的方式：

- 静态文本，如你放置在页面中的 HTML、CSS 或 JavaScript 代码，会发送到浏览器。你将在本章及后续章节中了解有关 HTML、CSS 和 JavaScript（客户端使用的编程语言）的更多信息，其中第 3 章详细介绍了 CSS。
- ASP.NET 服务器控件。这些控件放置在你的 ASP 页面中，并在处理时发出插入到页面中的 HTML。你将在本章讨论 HTML 之后了解有关服务器控件的更多信息，第 4 章专门用于解释 ASP.NET 服务器控件。
- 编程代码。当你将代码（如 Basic .NET 或 C#）直接包含在页面中，如你在之前的 Try It Out 中所见，你也可以将代码放在单独的代码文件中。官方术语是 Code Beside。但是，大多数开发人员将其称为 Code Behind，我将在本文中沿用此术语。此代码可以由运行时自动执行，或基于用户的操作执行。无论哪种方式，代码的执行都可以通过访问数据库、执行计算等大大影响页面的显示方式。你将在下一章了解有关此 Code Behind 的更多信息，编程 ASP.NET Web 页面将在第 5 章中详细讨论。

### 理解 HTML

HTML 是创建 Web 页面的事实标准语言，当今存在的每个浏览器都理解它。自 90 年代初以来，它一直是万维网的驱动力，万维网是互联网中处理 Web 页面的部分。HTML 文档是包含标记、文本以及影响该文本的附加细节的简单文本文件。HTML 的最新版本是 HTML5。尽管 HTML5 的规范仍在开发中，但许多现代浏览器支持该规范的重要部分，并且随着这些浏览器的每次新版本发布，这种支持都在增加。尽管并非所有浏览器都完全支持 HTML5，但它

确实是基于 HTML 的应用程序的未来，因此本书中使用它，也用于 Planet Wrox 演示网站。不要太担心有限的浏览器支持。所有主要浏览器都支持本书中使用的所有 HTML5 功能，或者支持可以通过名为 Modernizr 的脚本轻松模拟，你将在本书后面看到它。

### HTML 元素和标签

HTML 使用方括号包围的文本来指示内容在浏览器中应如何呈现（显示）。带角括号的文本称为标签；包含一些文本或其他内容的标签对称为元素。再次查看你在之前 Try Out 中打开浏览器源代码窗口时看到的 HTML：

```
<h2>World</h2>
<p>Welcome to Beginning ASP.NET 4.5.1 on 11/16/2013 4:18:07 PM</p>
```

此示例的第一行包含一个 <h2> 元素，具有开始标签 <h2> 和结束标签 </h2>。此元素用于表示第二级标题（如果你在浏览器中向上滚动最终源代码，会看到类似的标签，但在 </h2> 中多了一个斜杠（/））。此开始标签和结束标签之间的任何文本都被视为元素的一部分，因此以较大字体呈现。在大多数浏览器中，文本呈现为标题。与 <h2> 标签类似，还有用于创建最高达六级的标题的标签，例如 <h1>、<h3> 等。

标题下方，你会看到一个 <p> 元素，用于表示段落。默认情况下，浏览器会以底部额外的边距间距呈现段落，尽管你可以覆盖此行为。
