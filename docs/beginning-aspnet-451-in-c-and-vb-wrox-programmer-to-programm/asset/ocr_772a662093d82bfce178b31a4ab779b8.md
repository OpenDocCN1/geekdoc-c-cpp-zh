One solution to this problem is to not output caching at the page level and move content that applies to all a user control, which you then embed in the page as you saw how to do with the Contact Form. For example, a list with news articles or the full list of reviews could be the same for all users. If you move the code for these lists to a user control with output caching enabled, your containing page is still created for each user, but the content from the user control is only generated the first time, and then for all subsequent requests.

Another solution is to instruct the data source to cache data for you, as you will see in the next section.

If you're not affected by the drawbacks of output caching (such as when you're not using them or the security-related controls), output caching is an excellent mechanism to improve the performance of your site.

# Caching with Data Source Controls

The biggest benefit of caching with the data source controls is that they only cache dynamic, database-driven data, and not the entire page. That enables you to keep other parts of the page dynamic, as a banner module or a personalized greeting welcoming the user. Caching is supported by design on most of the data source controls, except for the MapDataSource, LinDataSource, and EntityDataSource controls.

Caching with the data source controls is very easy: All you need to do is set the EnableCaching property and then specify CacheDuration. The following snippet shows how a SqlDataSource caches data for 10 minutes:

```
<SqlDataSource ID="SqlDataSource" runat="server" CacheDuration="600" EnableCaching="True" /asp:SqlDataSource>
```

What's cool about caching with the data source controls is that they are smart enough to see if you are making updates to the underlying data. So, when you set up a SqlDataSource control to cache data for the Select Command for 20 minutes, then a change to the data by using the InsertCommand, UpdateCommand, or DeleteCommand, the cache is invalidated automatically. This only works when you execute the insert, update, or delete command against the exact same SqlDataSource. If you have one page that displays and lists list with reviews (such as All.aspx, for example) and then another page that is used to insert a new review (such as AddEditReview.aspx in the Manager folder), this won't work. After you've inserted a new review in the Manager section of the site, it won't show up in All.aspx until the cache has expired.

Code-caching is useful in many situations. However, the data source controls cannot be used in every situation. If you want to cache the results of data you get from a completely different source? What if you want to cache data you receive in a hand-coded page tagging the Entity Framework, or the contents of a text or an XML file that you frequently access? For those cases, ASP.NET gives you access to the cache.
