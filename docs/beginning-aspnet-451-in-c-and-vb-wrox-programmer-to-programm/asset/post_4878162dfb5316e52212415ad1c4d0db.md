
## Data Source and Data-bound Controls Working Together | 47

A couple of interesting things are worth examining. First, note that the ConnectionString and ProviderName attributes point to a connection string that has been defined in the Web.config file. You will see more of this in the next section, including an explanation of the <% %> syntax used for the attributes.

You then see four commands, each one of them a SQL statement that is used for one of the four operations of the CRUD acronym. The INSERT, UPDATE, and DELETE commands contain parameters, identified by the symbol (@). At run time, when the control is asked to perform the relevant operation, these parameters are substituted by values. The SqlDataSource keeps track of the relevant parameters in the Parameters collection. For example, the <DeleteParameters> element contains a single parameter for the Id (the primary key) of the:

```xml
<DeleteParameters>
<asp:Parameter Name="Id" Type="Int32" />
</DeleteParameters>
```

Note that the name of the parameter minus the symbol (@) matches with the parameter in the SQL statement:

```sql
DELETE FROM [Genre] WHERE [Id] = @Id
```

Notice how VS has wrapped column and table names in square brackets ([]). You normally need these if your column or table name contains a special character such as a space or matches a reserved word. VS is cautious and adds them to all columns and tables. You can leave them if you write your own SQL statements. By itself, the SqlDataSource can't control what happens at this stage. The data-bound control tells it what operations to execute. In this exercise, the data-bound control is the GridView that is defined with this code:

```xml
<GridView ID="GridView" runat="server" AllowPaging="True" AllowSorting="True" AutoGenerateColumns="False" DataKeyNames="Id" DataSourceID="SqlDataSource" EmptyData="There are no records to display.">
<Columns>
<asp:CommandField ShowSelectButton="True" ShowEditButton="True" ShowDeleteButton="True" />
<asp:BoundField DataField="Id" HeaderText="Id" ReadOnly="True" SortExpression="Id" />
<asp:BoundField DataField="Name" HeaderText="Name" SortExpression="Name" />
<asp:BoundField DataField="SortOrder" HeaderText="SortOrder" SortExpression="SortOrder" />
</Columns>
</GridView>
```

The GridView contains few important attributes. First, the DataKeyNames attribute tells the GridView what the primary key of the data is. This uniquely identifies rows in the GridView. The DataSourceID attribute points to the SqlDataSource control you saw earlier. AllowPaging and AllowSorting enable their associated features on the GridView.

## CHAPTER 13 DISPLAYING AND UPDATING DATA

Under the <Columns> element you see a CommandField. A CommandField is a column in the GridView that enables a user to execute one or more actions for the row. It ends up in the browser as one or more text links or buttons. In this example, ShowDeleteButton, ShowEditButton and ShowSelectButton have all been set to True. This gives the grid the functionality you see Figure 15-3. When you click one of the links created by the CommandField, they will trigger a command at the server. For example, clicking the Edit link puts the GridView in edit mode so you can edit the selected row. Notice how the Select link doesn't seem to change the GridView at all. In Chapter 15 you see how to create styles for the GridView so you can radically change the appearance of a selected row from the others.

If you want the GridView to render buttons instead of links, you need to set ButtonType to True:

```xml
<asp:CommandField ShowDeleteButton="True" ShowEditButton="True" ShowSelectButton="True" ButtonType="Button" /></asp:CommandField>
```

The other three fields are bound-fields which map directly to the columns in the database with their DataField attribute so the GridView knows what data to display.

The GridView and SqlDataSource controls work together closely to retrieve and modify the data in the underlying data source. To give you an idea of how this works, here is a rundown of the events that occur when you request the page in your browser and then edit a single genre:

1. The GridView knows it is set up to retrieve and display data because it has a DataSourceID attribute that points to a SqlDataSource control. This connects this data source to the database and then asks it for data. The SqlDataSource in turn connects to the database and then fires its SelectCommand, the SQL statement that selects the Id, Name, and SortOrder from the Genre table in the database:
```sql
SelectCommand="SELECT [Id], [Name], [SortOrder] FROM Genre"
```
2. When the SqlDataSource receives the requested rows from the database, it hands them over to the GridView, which creates an HTML table of them using the bound fields that have been set up in the <Columns> element. The GridView keeps track of the unique ID for each row as displayed in the page by storing it in View State.
3. As you click the Edit link, the page posts back. The GridView is able to see what you clicked by looking at the associated DataKeys and retrieving the row's Id from View State. It gets the latest results from the database by asking the SqlDataSource again to fire its SelectCommand, and finally, puts the selected row in edit so you can change the retrieved details. When you click the Update link, the GridView collects the new values from the TextBox controls and then contacts the SqlDataSource again.
4. For each of the parameters in the <UpdateParameters> element of the SqlDataSource, the GridView supplies a value. It retrieves the Id of the genre from the selected row, and then retrieves the Name and SortOrder values from the TextBox controls in the page.
5. Armed with the relevant data for the Id, Name, and SortOrder, the SqlDataSource executes its UpdateCommand against the database:
```sql
UpdateCommand="UPDATE [Genre] SET Name = @Name, SortOrder = @SortOrder WHERE Id = @Id"
```
6. Finally, the GridView refreshes the page after asking the SqlDataSource to fire its SelectCommand. The GridView now shows the update you made.
