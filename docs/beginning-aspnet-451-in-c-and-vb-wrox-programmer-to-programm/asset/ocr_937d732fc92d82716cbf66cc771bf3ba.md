# How It Works

In this short exercise, you carried out all four parts of the CRUD acronym, which gave you a look at the life cycle of data in a SQL Server database from creation to deletion.

You started off with an INSERT statement:

```
INSERT INTO Genre (Name, SortOrder) VALUES ('Folk', 15)
```

This creates a new row in the Genre table. As in the next section, the Id column of the Genre is an identity column, which means each new row gets a new, sequential Id assigned automatically.

To retrieve the Id, you used a SELECT statement with ORDER BY clause that sorts the orders in the IDs in descending, so the most recent was on top of the list. Retrieving the new Id in this application is not reliable because you might end up with the Id of a row inserted by someone else. You will see in the book how to retrieve the ID in a reliable way, for the purposes of this exercise, the ORDER BY method works well.

Armed with the Id, you executed an UPDATE statement to change the Name and SortOrder of the newly inserted genre. If you want to update only a single column with the UPDATE statement — say you want to change only the Name — you can simply leave out the other columns. For example, the following UPDATE statement changes only the Name, leaving all other columns at their original values:

```
UPDATE
Genre
SET
Name = 'British Folk'
WHERE
Id = 13
```
