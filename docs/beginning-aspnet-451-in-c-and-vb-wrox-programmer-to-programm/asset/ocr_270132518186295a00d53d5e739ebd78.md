# Global Error Handling and Custom Error Pages

To shield your users from the technical details of the exception, you should provide them with a user-friendly error page inside. Fortunately, ASP.NET enables you to define custom error pages:X pages that are shown when an exception occurs. You can map different types of errors (server errors, page not found, security problems, and so) to different pages.

You define the error page or pages you want to show in the CustomErrors of the Web.config file. A typical element looks like this:

```
<customErrors mode="On" Redirect="~/Errors/Error500.aspx"
    redirectMode="ResponseWrite">
    <error statusCode="404" redirect="~/Errors/Error404.aspx" />
    <error statusCode="500" redirect="~/Errors/Error500.aspx" />
</customErrors>
```

The mode attribute determines whether or not a visitor to your site gets to see a detailed error page. The attribute supports the following values:

+   - On—Every visit to your site shows the custom error page when an error occurs.
- Off—The custom error page is never shown and full errors are displayed on the page.
- RemoteOnly—The full details are shown to local users (browsing the site from the same machine as the one runs), while all other users get to see the custom error page. This setting enables you to see error messages on your site during development, while your users are always presented with the custom error page.

Within the opening and closing tags of the customErrors element you define separate elements, one for each HTTP status code you want to support. The previous configuration defines two custom pages: one that is shown when the requested page could not be found (a 404 status code) and one that is shown when a server error occurs (a 500 code).
