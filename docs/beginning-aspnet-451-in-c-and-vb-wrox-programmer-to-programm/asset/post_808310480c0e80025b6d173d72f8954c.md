## How It Works

When you enable the Inspector, the .NET run time and the IDE keep track of which file or control contributes HTML to the final page. It uses that information to find the responsible file and highlight the relevant code in it when you inspect page elements in the Page Inspector. Changes you make to the source files are detected by the IDE so you can refresh the Page Inspector whenever it's needed.

## CROSS-BROWSER TESTING WITH BROWSER LINK

Earlier in this book I mentioned that it is important to test your website in different browsers. Although most modern browsers render pages almost identically, differences still exist, which may cause a page to look great in one browser but sub-optimal or even broken in another. In versions before VS 2012, cross-browser testing was a manual task; you started a browser by pressing Ctrl+F5 or F5, then you copied the URL for the site, started another browser and pasted in the URL. Visual Studio 2012 introduced a great improvement by enabling you to select multiple start browsers: click the down arrow next to the browser on the Standard toolbar, select Browse with and then press Ctrl while selecting multiple browsers. Chapter 3 showed how to do this. Visual Studio 2013 improves this even further with Browser Link as you'll see next.

## Introducing Browser Link

Browser Link enables Visual Studio to communicate with any open browser that is displaying a page from your site. When Browser Link is enabled (it's on by default) you can let Visual Studio send a message to all open browsers to refresh the page. This is bi-directional communication between servers and clients. Browser Link works by injecting JavaScript into the page, which allows you to see changes in real-time.

## Using Browser Link

Since Browser Link is on by default, you don't have to do anything to use it. You can see changes in all open browsers as you make them in Visual Studio. This is a great time saver for web development.
