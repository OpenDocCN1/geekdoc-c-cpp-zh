
## Understanding Default Documents

In the context of URLs you should also know about de default documents. When you browse to a site like www.domain.com you might magically see a page appear. How does this work? Each web server has so-called default documents, a list of document names that can be served to a browser when no explicit document is supplied. So, when you browse to www.domain.com, the web server scans the directory requested (the root folder in this example) and processes the first file from default lists it finds. In most ASP.NET scenarios, the web server is set up to use Default.aspx as the default document. So, when you browse to www.domain.com on an ASP.NET server, you are actually served the page www.domain.com/Default.aspx.

In the links you create, you should generally leave Default.aspx when it's not needed. It decreases the page size, but more important, it makes it easier for users to type the address.

Now that you have how to use URLs to point to documents and other files, it's time to look at some higher-level controls that make use of these URLs: the ASP.NET navigation controls.

## Architecture of the Navigation Controls

To make it easy to show relevant pages in your site using a Menu, a TreeView, or a SiteMap, ASP.NET uses an XML-based file that describes the logical structure of your website. By default, this file is called sitemap. This file is then used by the navigation controls in your site to present relevant links in an organized way. By hooking up one of the navigation controls to the Web.sitemap, you can create complex user interfaces like fold-out menus or a tree view.

## Examining the Web.sitemap File

By default, you should call the site map file Web.sitemap. This enables the controls to find the right file automatically. For more advanced scenarios you can have multiple site files with different names, with a configuration setting in the Web.config file that exposes these additional files to the system. In most cases, a single site map file is sufficient. A basic version of the site map file can look like this:

```xml
<xml version="1.0" encoding="UTF-8"?>
<siteMap xmlns="http://schemas.microsoft.com/AspNet/SiteMap-File-1.0">
  <siteMapNode url="/Home.aspx" description="Go to the homepage">
    <siteMapNode title="Reviews" description="Reviews published on the site" />
    <siteMapNode url="/About.aspx" title="About" description="About this site" />
  </siteMapNode>
</siteMap>
```

The site map file contains siteMapNode elements that form the logical structure of your site. In example, there is a single root node Home, which in turn contains two elements, Reviews and About.

## Key Elements of the Web.sitemap File

Each siteMap can have many child nodes (but there can only be one siteMap directly under the siteMap element), enabling you to create a site structure that can be both wide and deep. The siteMapNodes in this example have three of their attributes set: url, title, and description. The url attribute should point to a valid page in your website. You can use the syntax you saw in the previous section to refer to application-root-based URLs. The ASP.NET run time doesn't allow you to specify the same URL more than once, but you can work around that by making the URL unique by adding a query string. For example, ~/Login.aspx and ~/Login.aspx?type=Admin will be seen as two different pages. You see more of the query string later in this chapter.

The title attribute is used in the navigation controls to display the name of the page. You see more about this when you work with the Menu, TreeView, and SiteMap controls. The description attribute is used as a tooltip for the navigation elements. 7-2 shows a tooltip for the By Genre element.

The navigation controls work together with the ASP.NET mechanism. You can automatically hide elements from controls like the Menu that users do not have access to. Security is described in more detail in Chapter 16.

The SiteMap control that displays a breadcrumb (discussed later in this chapter) is able to find the Web.sitemap file. For the other two, the SiteMap control is able to find the Web.sitemap file. The SiteMap control is able to find the Web.sitemap file.

## TRY OUT Creating a Web.sitemap

In this exercise you add to the site.

1. Right-click the Solution Explorer, choose New Item, and leave the default name set to Web.sitemap.
2. Modify the sitemap file so that it contains this code:
   ```xml
   <xml version="1.0" encoding="UTF-8"?>
   <siteMap xmlns="http://schemas.microsoft.com/AspNet/SiteMap-File-1.0">
     <siteMapNode url="/Home.aspx" description="Go to the homepage">
       <siteMapNode title="Reviews" description="Reviews published on the site" />
       <siteMapNode url="/About.aspx" title="About" description="About this site" />
     </siteMapNode>
   </siteMap>
   ```
3. Save the file; you're done with now.

## How It Works

Although you didn't add any spectacular code in the Web.sitemap file, a few things are worth discussing. First of all, note that the site only contains a single root node Home. This is enforced by the Web.sitemap file, which doesn't allow more than one root. The downside of this is that this single root will be the root of your Menu and TreeNode controls. In Figure 7-2 you can see all submenu of the TreeNode fall under the Home node. In most websites, however, it's much more common to have the Home item at the same level as the others. Therefore, in this exercise you added an additional Home node directly under the parent node to align it with the Reviews, About, and Login items. In a later exercise you will see how to hide the root element from the controls, enabling you to only show the "first child" of the root and their children. To overcome the problem that URLs in the siteNode elements need to be unique, you set one to ~/ and the other to ~/Default.aspx. Because of the way web servers handle default documents, eventually points to the same file.

A Web.sitemap file by itself isn't very useful. You need to add navigation controls to your site to make use of the site map. In the next section you will see how to use the Menu control. Later sections dig into the TreeNode and SiteMap controls.
