# How It Works

Just like the login controls, the WSAT eventually tells the provider you configured in the Web.config file. In the case of the Planet Wrox application, it talks it to the DefaultMemberProvider and the DefaultRoleProvider, which in turn talks to a SQL Server LocalDB database identified by connection string. The users and roles you create are stored in tables within the database. Users that you create end up in the same location as created with the CreateUserWizard. In fact, the WSAT uses the CreateUserWizard to create new accounts. Any user that you use in the WSAT is able to log in using your login. Login page. In example, you can use the Manager account you created in this exercise to log into the site and access the Management folder.

To use the role you created in this exercise, you have a few options at your disposal. First, you can use the role name to access specific users in your web application through settings in the Web.config file. Secondly, you can use the role in controls like the LoginView to present different content to different users. Finally, you can use the role API to check whether the current user is in a specific role. This gives you fine control over the content or functionality you offer to certain privileged users.
