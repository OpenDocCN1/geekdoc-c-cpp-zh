If you get an error when browsing to the site on your local host, you may need to turn off
custom errors in Web.config (for security reasons, set it to RemoteOnly instead of off)
to see the actual error message. Possible reasons for an error include an incorrect username,
password, or server name in the connection string, and an incorrectly configured database
role membership for the PlanetWroxUser account.

# Scenario 2 — Using Windows Authentication with IIS and the
Database on the Same Machine

This is a common scenario, especially when you're running your server on a local machine that
y you control yourself. Both the server (either IIS or the built-in development web server)
and SQL Server run on the same physical machine. This scenario makes it easy to use Windows
Authentication because both the web server and SQL Server use the same Windows Account.
to configure your server for this scenario, follow these steps:

+   Determine the account used by your web server. Refer to Chapter 19 for precise details
of how to do this, you're likely to need the ApplicationPoolIdentity (called
IIS AppPool\.NET v4.5 (default). I am using the IIS AppPool\.NET v4.5 in the
remainder of this section.

+   Next, you need to map this window to a SQL server login. To do this, open SQL
Server Management Studio and log in to your SQL Server instance. Expand the Security
node for the server (and not of an individual database), as shown at the bottom of Figure
B-3. Then right-click Logins and choose New Login.

+   Open the Server node of PlanetWrox database, right-click the Users node, and choose
New User.

+   In the User Type drop-down, choose SQL User with Login (this option doesn't exist in
erlier versions of Management Studio). In the User Name text box, choose .NET v4.5.

+   For the Login Name text box, click the ellipsis button and click Browse to you
select a username. Choose the account you configured earlier (called IIS AppPool\.NET 4.5)
and click OK.

+   Check Membership in the left on the list and see a box labeled Database Role
Membership (in earlier versions of SQL Server Management Studio this is on the same
page where you enter the username). In this box, you can choose a number of roles that
y can grant to your new user. The rule here is: Give users as few permissions as possible.
A good choice is db_datareader and db_datwriter, which allows the account to both read
from and write to tables in the database, so check these two options, shown earlier in
Figure B-6.

> NOTE Check out SQL Server's Books Online for more information about the
various roles.
