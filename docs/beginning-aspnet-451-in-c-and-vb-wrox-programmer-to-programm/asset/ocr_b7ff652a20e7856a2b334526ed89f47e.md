By disabling the delete button, you can easily prevent errors that occur when you try to delete a genre that has associated reviews. However, you may not always able to prevent an error from occurring during a CRUD operation against a data source control. For example, you may try to delete a genre that initially didn't have any reviews attached. Imagine that before you try to delete the genre, somebody inserts a new review for it. When you then try to delete the genre you'll get an error because the genre is now linked to it. In such cases, the data source controls enable you to diagnose the error that occurred and then take the necessary measures, providing feedback to the users informing them their CRUD operation did not succeed.

# Handling Errors That Occur in the Data Source Controls

In Chapter 18 you see a lot about recognizing and handling errors that occur in your ASP .NET pages. That chapter demonstrates how to catch errors that may occur in your code, and handle them by logging them or by informing the user. Because the data source controls expose error information as well, it's interesting to look at data errors in this chapter.

The SqlDataSource control (and other data source controls well) give you information about errors (exceptions in parlance) that may occur during one of the four CRUD operations.
With the SqlDataSourceStatusEventArgs, all events accept an instance of SqlDataSourceStatusEventArgs. Figure 15-10 shows these three EventArgs classes and their properties.

This class has two important properties: Exception and ExceptionHandled. The first contains the actual exception that occurred or nothing (in VB.NET) or null (in C#) when everything goes according plan and no error occurs. You can examine this error and take appropriate action. For example, you can inform the user that something went wrong, or you can send an email to the user's webmaster informing about the error so follow-up action can be taken.

If you decide to handle the error in the handler of the data source control, you should set the ExceptionHandled property of the object to True. This signals the ASP.NET run time that you are aware of the error and have dealt with it adequately. If you omitting this property, the run time finishes with the exception, which is eventually displayed to the user.
