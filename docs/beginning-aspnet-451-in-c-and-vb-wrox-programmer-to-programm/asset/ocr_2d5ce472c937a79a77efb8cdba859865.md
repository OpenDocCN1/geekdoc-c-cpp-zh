# How It Works

When the application starts up the first time it fires its Application_Start event, the code in Global .asax handles it and calls Register on the RouteConfig class (a module in VB) that you created and inserts into System.Routing.RouteTable, a collection of routes that can be used to determine how to redirect a user based on the request. At this point, the collection is empty, so you remove the RegisterRoutes method in RouteConfig which tells ASP.NET how to handle extensionless URLs. This is all the code you need to configure friendly URLs. From on, whenever a request for a URL that ends with .aspx comes in, ASP.NET redirects the browser to its extension-less counterpart.

# Considerations for Extension-less URLs

When ASP.NET encounters a request for a URL with the .aspx extension, it instructs the browser to fetch a new page without the extension. This means that the browser is requesting two pages, only to show the final, extension-less page. Clearly, this is a waste of resources, once you've configured the friendly URLs you no longer link to pages with an extension. To optimize the current site, you should remove all .aspx extensions in links. If you followed along with all exercises in the book far, you will find two links to Default.aspx and one in TableDemo.aspx in the Demo folder. All you need to do is remove the .aspx extension as a link like this:

> You can <a href="Login.aspx">log in</a><a></a></p>

ends up like this:

> You can <a href="Login">log in</a><a></a></p>

Furthermore, you should remove the extension from the URLs in Web.sitemap that drives the Menu, TreeView, and SitemapPath controls. Here's an example of reviews page:

```
<siteMap url="~/Reviews/Default" title="Reviews"
description="Reviews published on this site">
```

For more information about routing, check out the following article by Scott Hanselman on ASP.NET team: http://bit.ly/RLzjetT.

In addition to navigating from the client browser as you've seen far, it's also very common to navigate a user to a different page from the server side using code. How this works is discussed in the next section.
