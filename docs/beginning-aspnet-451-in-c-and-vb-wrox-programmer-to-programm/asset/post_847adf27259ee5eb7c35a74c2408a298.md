## A note about View State and Performance

Because the View State engine adds a considerable amount of information to the page, it's often a good idea to turn it off when you don't need it. This way, you can minimize the size of the hidden _VIEWSTATE field, which means the page is smaller and loads faster in the browser. Note that when you turn off View State you still see the hidden _VIEWSTATE field because Control State uses the same field to store its data. Turning off View State is easy, and you can do it at three different places:

- At the web level — You can do this in the Web.config file in the root of the site by modifying (or adding) the <pages> element under <system.web>, setting the EnableViewState attribute to:
```xml
<pages enableViewState="false">
</pages>
```

- At the page level — At the top of each page you find the page directive, a series of instructions that you can set EnableViewState to False:
```vb
<%@ Page Language="VB" AutoEventWireup="False" CodeFile="State.aspx.vb"
Inherits="Demos_State" EnableViewState="False" %>
```

This is useful for pages where you don't need View State at all.

- At the control level — Each ASP.NET Server Control enables you to set EnableViewState individually, giving you the option to turn it off for controls, leaving it for others.

Once you've turned off View State at a higher level (the page or control level), setting EnableViewState to True at a lower level has no effect. However, using the ViewStateMode property you can accomplish this as follows:

- Do not turn off View State in the Web.config file.
- At the page level, set EnableViewState to True and ViewStateMode to Disabled like this:
```vb
<%@ Page Language="C#" EnableViewState="True" ViewStateMode="Disabled" %>
```
This turns off View State for all controls in the page except for those that explicitly enable it by setting the ViewStateMode to Enabled.

## Practical Tips on Working with Controls

For the controls you want to give View State support, the ViewStateMode=Enabled, like this:

```
<asp:Label ID="Label1" runat="server" Text="Label" ViewStateMode="Enabled" />
```

If you want to see this at work in your demo page, modify the directive of State.aspx in the previous example by setting EnableViewState to True and ViewStateMode to Disabled. Create a second label in the page and set ViewStateMode for the enabled:

```
<asp:Label ID="Label1" runat="server" Text="Label" ViewStateMode="Enabled" />
<asp:Label ID="Label2" runat="server" Text="Label" />
```

In the Code-Behind, set the text of both pages today and to the second label as:

### VB.NET

```
Label1.Text = DateTime.Now.ToString()
Label2.Text = DateTime.Now.ToString()
```

### C#

```
Label1.Text = DateTime.Now.ToString();
Label2.Text = DateTime.Now.ToString();
```

Finally, run steps 10 and 11 of the last Try Out Exercise. You will notice the first Label maintains its text, the second defaults back to the Label.

## PRACTICAL TIPS ON WORKING WITH CONTROLS

The following list presents some practical tips on working with controls:

- Spend some time trying the different controls in the Standard category. Many of them are used and discussed throughout the book, it's good to know how you should use them and how they operate. By experimenting with them now in a few sample pages, you will have a head start when the controls reappear in later chapters.

- Consider turning off View State for controls that don't need it. In many cases, especially with the data-driven controls discussed in Chapter 13 and onward, disabling View State can seriously decrease the size of your web page, resulting in shorter load times and improved user experience.

- Before you design a complex Web Form with multiple controls to accept user input, step back from your computer and take a piece of paper and a pen to draw out the required functionality. By thinking about the (technical) design of your application before you start coding, it's much easier to create a consistent and well-thought-out user interface. Making considerable changes in the page if you've taken a wrong route will always take more time than doing it (almost) right the first time.

- Experiment with the View State mechanism to get a better understanding of how it works. Create a couple of pages similar to the one you created in the last. Turn off View State at the page or control level and see how the page behaves. Take note of the controls, such as TextBox, that are capable of maintaining their value even with View State off.

## SUMMARY

This chapter gave you a good look at the large set of ASP.NET Server Controls. Because these controls are important and used throughout every ASP.NET application, it's really critical that you understand what controls you have in the Toolbox, what they are used for, how they work, and how they maintain their own state.

One of the biggest inventions in ASP.NET is the state engine that enables controls to maintain their state after postbacks. The state engine is a real time saver and frees you from writing loads of tedious and boring code in every single web page to replicate this behavior. However, you should turn State Off when possible to improve performance.

This chapter also introduced you to some server-side code in Visual Basic and C#. The next chapter gives you a much better understanding of programming ASP.NET pages. You see how a programming language works, what elements it contains, and how to write code to use in your ASP.NET pages. And best of all, the examples are presented in Visual Basic and C#, so you're not stuck with a language you may not like.
