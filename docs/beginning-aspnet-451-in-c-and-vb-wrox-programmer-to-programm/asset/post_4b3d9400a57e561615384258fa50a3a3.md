```csharp
var firstReview = (from r in myEntities.Reviews

```

```csharp
var lastReview = (from r in myEntities.Reviews
              orderby r.Id descending
              select r.First());
```

By reordering the result set in reverse order before executing First, you actually get the last row in the sequence. Note that in both cases, the type returned by the query is a true object, enabling you to access its properties, such as Id and Title.

Besides this LINQ Query Syntax, LINQ also supports method syntax. For the differences and an example, check out this MSDN article: http://tinyurl.com/MethodVersusQuery.

## Shaping Data with Anonymous Types

So far, you have seen in the previous sections returned full types. That is, the queries returned a list of Review instances (as the Select method), a single instance of Review (Single, First, or Last), or a numeric value (such as Count and Average).

Quite often, you don't need all of these objects. Figure 14-3 shows a GridView with all the properties of the Review object. To improve the presentation of this list, you usually want to skip properties like Body and Authorized, and instead of the genre ID probably want to display the genre name. Although you could use the GridView to display only the columns you want to see, it would be more efficient if you were able to limit the actual data. This is pretty easy to do with anonymous types, another feature available in C# and VB.NET. An anonymous type is a type whose name and members you don't define up front as you do with other types. Instead, you construct the anonymous type by selecting data and then letting the compiler infer the type for you. The anonymous type can only be accessed within the method that declared it, and as you cannot return an anonymous type from a method.

If you don't define a type and give it a name, how can you access the type and properties? This is once again with type inference, where the compiler can see what data is assigned to a variable and then creates a new, anonymous type on the fly.

Creating an anonymous type is instead of selecting the actual object using something like Select, you use the new keyword in C# and New in Visual Basic, and then define the properties you want to create within a pair of curly braces:

### VB.NET

```vb
Dim authorizedReviews = From MyReview In MyEntities.Reviews
Where myReview.Authorized = True
Select New {myReview.Id, myReview.Title, myReview.Genre.Name}
```

### C#

```csharp
var authorizedReviews = from myReview in myEntities.Reviews
                          where review.Authorized == true
                          select new { review.Id, review.Title, review.Genre.Name };
```

Although the type is anonymous and cannot be accessed by name directly, the compiler is still able to infer the type, giving you full IntelliSense for the new properties that were selected in the query. Figure 14-4 shows how you access the properties of the anonymous type in the authorizedReviews variable, using the var keyword in C#.

```csharp
var authorizedReviews = from review in MyEntities.Reviews
where review.Authorized == true
foreach(var review in authorizedReviews)
{
    // Note: The original OCR had a select inside a loop here, corrected for logic context
}
```

Note that the previous query accessed the actual Genre property of the Review (defined as a column in the table Review), the Review class also has a strongly typed Genre property, giving you direct access to the genre's properties, like the Name, as besides the previous queries.

Besides directly selecting properties — as shown in the query that selected the Id and Title of the Review and the Name of the Genre — you can also make up values and give them different names as you want. For example, the following query creates a new anonymous type that renames the Id as Number, limits the Title to the first 20 characters, and contains a boolean value that determines whether the item has been updated in the database previously:

### VB.NET

```vb
Dim allReviews = From myReview in MyEntities.Reviews
Select New With
{
    .Number = myReview.Id,
    .Title = myReview.Title.Substring(0, 20),
    myReview.Genre.Name,
    .HasBeenUpdated = (myReview.UpdateDateTime > myReview.CreateDateTime)
}
```

### C#

```csharp
var allReviews = from myReview in myEntities.Reviews
select new
{
    Number = myReview.Id,
    Title = myReview.Title.Substring(0, 20),
    myReview.Genre.Name,
    HasBeenUpdated = (myReview.UpdateDateTime > myReview.CreateDateTime)
};
```

## Introducing Query Syntax

Note the difference between VB.NET and C#: in the VB.NET, the names of new properties (Number, Title, and HasBeenUpdated) are prefixed with a period (.). C# doesn't have this requirement and you write new property names directly. If you don't introduce a new name (as is the case with the genre preceding example), the name of the property you're selecting is used. This means the genre name is stored in a property called Name.

The ability to select extra properties that are not present in the original object gives you great flexibility in the data you display. This example determines whether the item has been updated in the database previously.
