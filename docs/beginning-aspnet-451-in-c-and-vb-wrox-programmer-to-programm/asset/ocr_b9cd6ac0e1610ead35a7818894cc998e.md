# How It Works

When you press Ctrl+F5 in a browser as you have done up in this chapter, notice special happens. VS simply opens the browser, which requests the page from IIS Express. However, when you press F5 instead, VS gets into debugging mode and respects the breakpoints you have set. When a breakpoint is hit, execution of the code is stopped so you can look at the code and its environment, which you access to variables, controls, methods, and more. Note that the code on the line with the breakpoint has not been executed to this point. To continue executing the code, use F10, F1, or F5. You may use any of these shortcuts.

Before you debug your code, you need to configure the attribute to support it. You do do this by setting the debug attribute of the compilation element in Web.config to:

```
<compilation debug="true">
```

If you're using Visual Basic, you may see two additional attributes on this element: strict and explicit. By default, strict is set to false, which means Visual Basic will do silent calves and conversions for you. The strict attribute is set to true, which means you need to declare all your variables before you use them.

When you start debugging and the debug attribute of the <compilation /> is set to false, you get the dialog box shown in Figure 18-7 offering to turn it on for you. To avoid the overhead you always set it to false on a production server. You see more of this in the next chapter.
