# Configuring the ScriptManager

In an earlier section of this chapter you saw that the ScriptManager control is a required component in all Ajax-related operations. It registers client-side JavaScript files (used by the Ajax framework and yours own), takes care of partial-page updates with the UpdatePanel, and handles interaction with the web services you have defined in your website. You can add a ScriptManager to an individual page or to the master page so it becomes available throughout your site.

When using services, you also need to tell the ScriptManager that you want to expose your web service to client code. You have two ways to do this:

- In the ScriptManager in the master page
- In a content page that uses the web service, using the ScriptManagerProxy class

When you are going to use the web service in all or most pages, you're best off declaring the web service in the master page's ScriptManager control a <Services> element that contains one or more ServiceReference elements to point your services. For example, make the NameService.svc service you created available in all your pages, add the following highlighted code to the master page:

```asp
<asp:ScriptManager ID="ScriptManager" runat="server">
  <Services>
    <asp:ServiceReference Path="~/WebServices/NameService.svc" />
  </Services>
</asp:ScriptManager>
```

By registering the service in the master page, it becomes available to all pages based on that master. This means each page will download the JavaScript files needed to run this service. This is a waste of bandwidth and resources if you are not using the web service at all. So, for services that you use on one page, you're better off registering the service in the page itself. On a normal page that doesn't use a master page with a ScriptManager, you can simply add a ScriptManager to the Web Form directly. However, if you are using a master page that already has its own ScriptManager (as is the case with the Planet Wrox website), you need to use a

# Calling Web Services from Client-Side

In this exercise, you access the web service from client-side.

1. In the ScriptManager you added, add the <Services> element. You should end up with this:

```asp
<asp:ScriptManager ID="ScriptManager" runat="server">
  <Services>
    <asp:ServiceReference Path="~/WebServices/NameService.svc" />
  </Services>
</asp:ScriptManager>
```

2. Below the closing tag, add an input (Text) and an input (Button). You should end up with:

```asp
<asp:ScriptManager ID="ScriptManager" runat="server">
  <Services>
    <asp:ServiceReference Path="~/WebServices/NameService.svc" />
  </Services>
</asp:ScriptManager>
<input id="YourName" type="text" />
<input id="SayHello" type="button" value="Hello" />
```

3. Right below the input box, add JavaScript block with the following:

```javascript
<script>
function helloWorld() {
  var name = document.getElementById('YourName').value;
  NameService.HelloWorld(name, helloCallback);
}
function helloCallback(result) {
  alert(result);
}
</script>
```

4. Add an onclick attribute to the button so that it calls the helloworld method when you click it. Your code should look like:

```html
<input id="SayHello" type="button" value="Hello" onclick="helloWorld(); />
```

5. Save all changes by pressing Ctrl+Shift+S, and then request the WebServices.aspx page in your browser. Enter your name and click the Say Hello button. If everything turned out, you should be greeted with a message from the web service, repeating your name. Figure 10-9 shows the alert window in Apple's Safari.

COMMON MISTAKES If you get an error instead of this message box, or you see a small triangle in the bottom-left corner of the code snippet, make sure you typed the JavaScript exactly as shown. JavaScript is case sensitive, make sure you get all the capitalization right. Also make sure that the JavaScript block you added comes after the input box and button that you defined. Finally, make sure that the path to your web service matches the actual path of your .svc file.
