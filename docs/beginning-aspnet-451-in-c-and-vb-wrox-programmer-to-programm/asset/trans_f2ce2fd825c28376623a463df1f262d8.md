

一个 Web Site 项目只是一个包含许多文件和子文件夹的 Windows 文件夹。它没有一个集合文件（称为项目文件，扩展名为 .vbproj 或 .cbproj）来跟踪网站中所有单独的文件。你只需将 VS 指向一个文件夹，它就会立即将其作为网站打开。这使得创建站点副本、移动它们以及与他人共享变得非常容易，因为与本地系统上的文件不存在依赖关系。由于缺乏中央项目文件，Web Site 项目通常简称为网站，这是我在本书其余部分使用的术语。

> 注意：你不能使用 Web Site 项目来创建 Web API 应用程序。

## 在 Web Site 项目和 Web Application 项目之间选择

由于你有两个可供选择的选项，你可能会想知道应该选择哪种项目类型。一般来说，Web Site 项目是更好的工具。因为它只是平铺的，更容易将文件复制到不同位置，例如另一台工作站或生产服务器。此外，对代码文件的更改会被 Web 服务器拾取并自动应用，无需正式的部署过程。另一方面，Web Application 项目适用于团队开发人员在同一站点上协作，因为它规定了更正式的开发和部署流程，并且对与源代码控制版本系统（如 ASP.NET MVC 和 Web API）协作的支持更好。此外，它还支持其他技术，例如 ASP。

本书使用 Web Site 项目模型，因为如果你是 ASP.NET 新手，它更容易使用。然而，你会发现使用 Web Application 项目模型的站点与 Web Site 项目有很多共同之处，这意味着你可以使用从本书中获得的知识来构建使用 Web Application 项目模型的站点。如果你想跟随本书学习，你必须使用 Web Site 项目模型。在提及特定项目类型时，我将在本书中交替使用网站和 Web 应用程序这两个术语来指代网站的一般情况。

现在你已经了解了不同的项目模型，接下来要考虑的是不同的网站模板及其选项。

## ASP.NET Web Forms Site

此模板使你能够启动一个基本的 ASP.NET 网站。它包含许多文件和文件夹，可帮助你快速启动站点的开发。不同的文件类型将在本章后面讨论。特殊的 App_Data 文件夹以及 Account 文件夹中页面的功能将在本书后面讨论。此模板使用一个名为 Bootstrap 的外部框架，这是一个前端框架，可帮助你构建在桌面、平板电脑和手机等多种设备上看起来很棒的网站。不幸的是，ASP.NET 附带的许多控件（例如你在第 7 章中会看到的 Menu 控件）在使用 Bootstrap 时渲染不正常。这就是为什么我决定不在本书中使用此框架，而是专注于 ASP.NET 附带的所有功能。对于你的项目，你可以使用此 Visual Studio 模板与 Bootstrap，但你需要为 Menu 等控件实现替代方案。你可以在 http://getbootstrap.com 了解有关 Bootstrap 的更多信息。

## ASP.NET Web Site (Razor v2 / Razor v3)

你测试这些以使用 Microsoft 的 Web Pages 框架创建站点。你可以在《Beginning ASP.NET Web Pages with WebMatrix》（Wrox，2011，ISBN：978-1-115-05048-4）中了解有关 Web Pages 的更多信息。

## ASP.NET Empty Web Site

ASP.NET Empty Web Site 模板除了两个配置文件（Web.config 和 Web.Debug.config）之外什么都不给你。ASP.NET Empty Web Site 模板在你有一堆现有文件想要创建新的或在你想从头创建站点时很有用。你使用此模板作为本书中构建的网站的基础。

## ASP.NET Dynamic Data Entities Web Site

此模板使你能够创建一个灵活强大的网站来管理数据库中的数据，而无需大量手动代码。本书未讨论此模板，但你将在第 14 章学习模板使用的 ADO.NET Entity Framework 的更多信息。

## WCF Service

此模板使你能够创建包含一个或多个 Windows Communication Foundation（WCF）服务的网站。WCF 服务在某种程度上类似于服务，因为它使你能够创建可通过网络调用的方法。然而，WCF 服务比简单服务更进一步，并为你提供更多灵活性。你将在第 10 章中看到如何从浏览器创建和消费 Web 服务。

## 创建和打开新的

你有多种创建和打开现有网站的方式。你拥有的选择在很大程度上受你访问网站的方式（无论是在本地机器上使用 Visual Studio 还是在远程机器上）以及你是否想使用 IIS（随 VS 提供的内置 Web 服务器）或 IIS 的完整版本的影响。

本书中的所有示例都假设你从本地硬盘打开站点并使用 IIS Express，这是一个精简版的 IIS，因为使用它开发站点非常方便。然而，第 19 章展示了如何使用和配置 Internet Information Services，即 IIS 的完整版本。
