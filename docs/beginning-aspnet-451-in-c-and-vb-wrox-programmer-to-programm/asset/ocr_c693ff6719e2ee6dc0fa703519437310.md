The complete line, starting with Public, is referred to as the method signature because it defines the function of the function, including its name and its parameters. The Public keyword (public in C#) is called an access modifier and defines to what extent other pages or code files can see this. This is discussed in detail later in chapter. For now, you should realize that Public has the greatest visibility, so the method is visible to any calling

The name of the function is followed by parameters, which in turn can contain an optional parameter list. The italicized parts in these code examples will be replaced with real values in your code. The square brackets ([]) are optional. To make it a little more concrete, here are some examples of functions and subs:

# VB.NET

```
Public Function Add(a As Integer, b As Integer) As Integer
Return a + b
```

```
Sub SendEmail(emailAddress As String)
' Code to send an e-mail goes here
End Sub
```

# C#

```
public int Add(int a, int b)
{
    return a + b;
}
```

```
public void SendEmailMessage(string emailAddress)
{
    // Code to send an e-mail goes here
}
```

In these code examples it's clear that functions return a value, and subs don't. The Add method uses the Return keyword (return in all lowercase in C#) to return the sum of a and b. The Sub in VB.NET and the method in C# don't require the Return keyword, although you can use it to exit the method prematurely. without specifying a value.

Finally, both function and subroutine have a parameter list that enables you to define the name and type of variable. Inside the method you can access these variables as normal variables. In the case of Add method, you have two parameters: one for the left side of the addition and one for the right. The SendEmailMessage has only one parameter: String holding the user's e-address.

In earlier versions of VB.NET you would use the keyword ByVal in each parameter of the parameter list. This is the default type for all parameters, so VS no longer adds it for you. The opposite of ByVal is ByRef. When you specify ByVal, a copy of the variable is made. Any changes to that inside the method are lost as soon as the method finishes. In contrast, if you specify ByRef, a reference to the variable is sent to the method. Any changes to the incoming variable reflect on the original variable as well.
