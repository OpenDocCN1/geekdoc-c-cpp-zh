
You can have multiple groups within the <properties> tags, but you can have only one level of groups. This means that you can't nest a <group> element in another <group> or <add> element.

## Using Non-standard Data Types

In addition to the data types listed earlier as String, DateTime, and Int32, you can also use your own types (defined in the App_Code folder, for example).

As with the built-in .NET types, you need to refer to your type using its fully qualified name, which includes the namespace and the class name. Imagine that you have a type Preference that contains various properties (implemented as automatic properties in this example) related to the user's preference. To include this in the profile, you need to wrap it in a namespace first:

```VB.NET
Namespace PlanetWrox
  Public Class Preference
    Public Property FavoriteColor As String
    ' Other properties go here
  End Class
End Namespace
```

```C#
namespace PlanetWrox
{
  public class Preference
  {
    public string FavoriteColor { get; set; }
    // Other properties go here
  }
}
```

You then refer to the type in an <add /> element as follows:

```xml
<add name="Preferences" type="PlanetWrox.Preference" />
```

A situation where you might need to refer to a type in the profile setup is when you are using generics. Chapter 5 discusses how to refer to role names using a List of strings. Here's a quick refresh of the code you saw in that chapter:

```VB.NET
Dim roles As New List (Of String)
...
roles.Add("Members")
```

```C#
List<string> roles = new List<string>();
roles.Add("Members");
```

To give your profile a property that is of a Generic List type, you need to use some special syntax. The following setting in Web.config creates a property called FavoriteGenres that stores the user's favorite genres as a List (Of Integer) in VB.NET and as a List<int> in C#:

```xml
<add name="FavoriteGenres" type="System.Collections.Generic.List`1[System.Int32]" />
```

The first part of the type attribute looks quite normal. The List class lives in the System.Collections.Generic names makes it sense that you need to specify that here as well. However, right after the class name (List) you see `1`. This is not a type, but the .NET will refer to generic types in- to define it based on a generic type, you need to use the back tick (`) followed by an 1. The back tick is usually found to the left of the 1 key on your keyboard. The `1` is then followed by a pair of square brackets that contains the actual type you want to use for the list. The type specified in the FavoriteGenres profile property maps these to VB.NET and C# counterparts:

```VB.NET
Dim FavoriteGenres As New List(Of Integer)
```

```C#
List<int> FavoriteGenres = new List<int>();
```

You will see how to use this and other profile properties in the exercises. First, you will learn how to configure profile in web.config the next Try Out. Later exercises show how to work with these properties, and how to use the various methods of the List class.

## TRY IT OUT

In This Try Out, you see how to create a profile that is capable of storing a user's first and last name, a date of birth, a short biography, and a list of IDs of the user's favorite genres. This list is later used to show the results that match the user's interest.

1. Open the web.config file from the root of the site and locate the <profile> element that was added by NuGet in the preceding chapter. If you don't have this element yet, refer to the section "Introducing the Login Controls" in Chapter 16 to learn how to configure your site.
2. Add a new <properties> element as a direct child of <profile>. Make sure you don't accidentally add the element inside the <providers> element.
3. Complete the <profile> element so it ends up looking like this:

```xml
<profile defaultProvider="DefaultProvider">
  <properties>
    <add name="FirstName" />
    <add name="LastName" />
    <add name="DateOfBirth" type="System.DateTime" />
    <add name="Bio" />
    <add name="FavoriteGenres" type="System.Collections.Generic.List`1[System.Int32]" />
  </properties>
  <providers>
    ...
  </providers>
</profile>
```

Save the Web.config. As soon as you save the file, a background process starts to generate a class file that is used for the profile. After the class file has been created and compiled successfully, you can access it programmatically through the Profile property of the Page class.
