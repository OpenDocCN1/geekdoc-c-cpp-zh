With the discussion of the various controls, now, you should have a reasonably good understanding of how to perform CRUD operations using the GridView, DetailsView, and SqlDataSource controls.
Useful as the SqlDataSource control may be, many developers don't like to use it. One of the biggest drawbacks of this control is the fact that your SQL statements end up directly in your pages. This can be problematic if you are just starting your database schema. Even if you think there's no need to change, you can be pretty sure you'll need to change it one day. Once you do, things are likely to break. For example, if you rename the Name column of the Genre to Description, your application will break. You won't notice until you run time because VS is not able to check the database schema against the command texts defined in the SqlDataSource controls. You have few ways to work around this. One solution is to build strongly typed objects and work with the ObjectDataSource instead. Details of this solution are beyond the scope of this book, but you're invited to check out my website where I've published an article series demonstrating this concept: http://bit.ly/3weD7D. The concepts presented in this series are quite advanced, so you may want to postpone digging into it until you've finished this book.
Another alternative is to make use of the ADO.Net Entity Framework, the topic of the next chapter that also shows you how to Model Binding and the ListView and DataPager controls to perform similar actions without the need to embedded SQL queries in your code.

# PRACTICAL TIPS FOR DISPLAYING AND UPDATING DATA

The following list provides some practical tips for displaying and updating data:

+   Always store your connection strings in the Web.config file. Although it might seem easy to store them directly in the SqlDataSource control in page, you'll get in trouble when you need to make changes to your connection string later.

+   Always consider adding validation controls to your data entry pages. It makes it at easier for your users to find out what data is required, and in what format they should deliver, while you protect your system from receiving and processing incorrect data.
