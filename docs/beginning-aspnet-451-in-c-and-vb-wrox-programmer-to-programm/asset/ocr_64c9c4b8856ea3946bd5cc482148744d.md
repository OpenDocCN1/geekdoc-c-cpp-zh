# How It Works

Without the @ Register directive in the master page, the ASP.NET runtime scans the Web.config file for controls that have been registered there. It then finds the registration of the Wrox:Banner control so it is able to successfully find the file using the src attribute and add it to the page hierarchy.

With the control registration added to the Web.config file, it is much easier to move or rename the control. Instead of finding and replacing the @ Register directive in all pages that use, the only thing you need to change is the registration in the Web.config file. When you make a change, all pages using the control will automatically find the new location or name.

Useful as user controls, they have a few caveats that you need to be aware of.

# User Control Caveats

Earlier you saw that the ID of the Panel control you added to the page was modified by the ASP.NET runtime. Instead of getting a <div> element with its id set to VerticalPanel, you got the following id:

```
<div id="Banner1_VerticalPanel">\n</div>
```

In many cases, this is not problematic because you often don't need the client id. However, if you need to access this control from client-side JavaScript or CSS, it's important to understand why this id is modified.

# Understanding and Managing Client IDs

By design, all elements in an HTML page need to be unique. Giving them an id attribute is not required, but if you do so, you avoid conflicts in the final HTML code of the page, ASP.NET ensures that each server-element control gets a unique id by prefixing it with the name of their naming container. Within a panel container all elements should have unique IDs. VS warns you when you try to add a control that doesn't have a unique ID. For example, you get an error when you try to add a second panel to a page with an id of VerticalPanel or one in the master page and another in the content of the page? Potentially, you could end up with two client:<div> elements with an ID of VerticalPanel. To avoid this problem, ASP.NET prefixes each element with the ID of its nearest container. For the panel inside the user control it means it's prefixed with Banner1, the server-side ID of the user control in the master page.

You can use the ClientID of control to get its full client-side id. The following snippet shows how to display the ClientID of the Panel control on a fictitious Label control within the Banner.ascx user control:

```
VB.NET
Label.Text = VerticalPanel.ClientID
```

```
C#
Label.Text = VerticalPanel.ClientID;
```
