The IsValid property returns True when all the controls in the page or in the active ValidationGroup are valid. By checking the IsValid property on the server before you work with the data, you can be sure that the data is valid according to your validation controls, even if the user turned off JavaScript in the browser, and sent the form to the server without any client-side checks. You see the IsValid property used later in this chapter, when sending e-mail is discussed.

In addition to the validation controls you have seen so far, ASP.NET comes with another validation mechanism, which could be discussed next.

# Understanding Request Validation

By design, ASP.NET throws an error whenever one of the controls on a page contains content that looks like HTML tags. For example, see the error shown in Figure 9-10 when you enter `<h1>Hello World</h1>` or `<script>alert('Hello World');</script>` as the contents of the text box in the contact form.

The ASP.NET run time prevents this prevents users entering HTML or JavaScript that can potentially mess with the design or working of your website or could lead to security risks. If you're sure you want to allow users to enter HTML, you have a few options. First, you can disable request validation by setting the ValidateRequest attribute in the @ Page directive to False:

```
<@ Page Inherits="Contact" Title="Contact" ValidateRequest="False" %>
```

With setting it to False, users can enter HTML. In previous versions of ASP.NET, this was the only way to enable a user to send HTML to your page. The downside of this solution is that it is all or nothing. By turning off request validation at the page level, all controls in the page will now opens up your page for potential abuse. As a good security mechanism, you should allow HTML only for specific fields that you determine.
