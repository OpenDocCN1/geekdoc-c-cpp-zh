## TRY OUT Joining Data

To join data from two tables, you need to write a JOIN statement in your code. If you help to write the code, SMS adds a JOIN for you whenever you add related tables to the Diagram pane. However, sometimes this JOIN is not correct, so you'll need to check to see if it's.

- 1. In your test database SMS, click the Review table and choose Edit Top 200 Rows. You'll see all the reviews in the table appear. Next, enable the Diagram, Criteria, and SQL panes by clicking their respective buttons on the Query Designer toolbar.

- 2. Right-click an open spot of the Diagram pane next to the Review table and choose Add Table. Alternatively, choose Query Designer ⊟ Add Table to the main menu.

- 3. In the dialog box that opens, click the Genre table and then click the Add button. Finally, click Close.

- 4. The SQL statement that SMS generated looks like this:
```sql
SELECT TOP (200) Review.Id, Review.Title, Review.Summary, Review.Body,
Review.GenreId, Review.Authorized, Review.CreatedDateTime, Review.UpdateTime
FROM Review
INNER JOIN Genre ON Review.GenreId = Genre.GenreId
```
SMS correctly detected the relationship in the database between the GenreId column of the Review table and the Id column of the Genre table, and applied the correct JOIN for.

- 5. To see how you can create joins yourself without writing code directly, you'll manually re-create the JOIN. Right-click the line that draws between the two tables in the Diagram pane and choose Remove. The SQL statement now contains a CROSS JOIN.

- 6. Next, click the GenreId column of the Review table in the Diagram pane and drag it onto the id column of the Genre table. As soon as you release the mouse, SMS creates a new INNER JOIN in the SQL pane for you with the exact same code as you saw earlier. SQL Server understands the primary and foreign keys that have been set up in the database tables and correctly joins the primary key of the Genre table (id) to the foreign key of the Reviews table (GenreId).

Modify the SQL statement so it selects only the Id and the Title columns from the Review table and the Genre table. You can do this by altering the SQL statement manually by unchecking the columns in the Diagram pane. Your SQL statement should now look like this:

```sql
SELECT TOP (200) Review.Id, Review.Title, Genre.Name
FROM Review
INNER JOIN Genre ON Review.GenreId = Genre.Id
```

## How It Works

By using a JOIN in your SQL statement, you tell the database how to relate rows to each other. In this example, you joined the GenreId column of the Review table to the actual Id of the Genre table:

```sql
SELECT
Review.Id, Review.Title, Genre.Name
FROM
Review
INNER JOIN Genre ON Review.GenreId = Genre.Id
```

With this JOIN, you can retrieve data from multiple tables and present them in a single result set. SQL Server returns the correct name for each review, as shown in Figure 12-15.

In addition to selecting data, you also need to insert data into the database. You do this with the INSERT statement.

## Creating Data

To insert new rows in a SQL table, you use the INSERT statement. It comes in a few different flavors, but in its simplest form it looks like this:

```sql
INSERT INTO TableName (Column1, Column2) VALUES (Value1, Value2)
```

Just as with the WHERE clause, you need to include string and date values in single quotes, but you can enter numbers and boolean values directly in your SQL statement. The following snippet shows how to insert a new row in the Genre table:

```sql
INSERT INTO Genre (Name, SortOrder) VALUES ('Tribal House', 20)
```

The ID column of the Genre table is set up to generate a value automatically when you insert a new row (you will see more of this concept, called identity columns, later in this chapter). Because it's generated by SQL Server, it's not part of this query. After you have created some data, you may want to edit it. You do this with the UPDATE statement.

## Updating Data

To update a table, use the UPDATE statement:

```sql
UPDATE TableName SET Column1 = NewValue1, Column2 = NewValue2 WHERE Column3 = Value3
```

With the UPDATE statement, use Column = Value constructs to indicate the new value of the specified column. You can have as many of these as you want, with a maximum of one column in the table. To limit the number of items that get updated, use the WHERE clause, just with selecting as you saw earlier. Without a WHERE clause, all rows will be affected which is usually not what you want.

The following example updates the row that was inserted with the INSERT statement you saw earlier. It sets the Name to Trance and updates the SortOrder to 5 to move the item up a little in sorted lists. It uses the unique ID of the new row (13 in this example) in the WHERE clause to limit the number of rows that get affected with the UPDATE statement.

```sql
UPDATE Genre SET Name = 'Trance', SortOrder = 5 WHERE Id = 13
```

Obviously, you may also need to delete existing rows. It should come as no surprise that the SQL language uses the DELETE statement for this.

## Deleting Data

Just as with the SELECT and UPDATE statements, you can use the WHERE clause in a DELETE statement to limit the number of rows that get deleted. This WHERE clause is often very important, because if you leave it out you will delete the entire table. When you write a DELETE statement, you don't need to specify any column names. The following example deletes the row that was inserted in the previous example:

```sql
DELETE FROM Genre WHERE Id = 13
```
