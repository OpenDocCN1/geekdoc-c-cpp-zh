# 3.12 BEST AND AVERAGE CASE ANALYSIS

The standard analysis bounds the number of steps taken by any input of
n, so that it is a worst case analysis—if an algorithm is O(n), then the
alg takes no more than Kf(n) steps on any input of size n, including
t worst case.

Sometimes it is also useful to speak about the best case, the number of
steps required to solve the easiest instance of size n, or the average
case, the number of steps required over all possible inputs. For
example, in an algorithm to find an element in an unordered list, the best
case finds it in the first position, the worst finds it in the last (or not
all), and on average, it should be found approximately in the middle.

The average case can be tricky. For example, consider the case above
of finding an element in a list of length n. If the element is in the first posi-
t, one test for equality is required; if in the n. So, for elements
the last average number of tests is (1 + 2 + ... + n)/n = (n + 1)/2. But,
if the element is not in the list—in any such case, n tests are done.
So, to do a better case analysis, it would be necessary to know the
probability that the element is found in the list. Here, if it is known that
t item is found in the list p fraction of the time (0 ≤ p ≤ 1), then the aver-
age number of tests is p((n + 1)/2) + (1 - p)n.
