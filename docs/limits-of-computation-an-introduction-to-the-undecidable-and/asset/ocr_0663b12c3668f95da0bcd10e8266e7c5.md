Thus, we can retrieve all the information about the TM from its delta function. We need to know what $q_{start}, q_{accept},$ and $q_{reject}$ are, but we can encode them in a standard way:

```
$q_{start} = 0
$q_{accept} = 00
$q_{reject} = 000$
```

(The alert reader may complain that this assumes that these are three distinct states, and does not allow, for example, $q_{start} = q_{accept}$. This is true, but it does not eliminate any interesting Turing machines.)
Moves of the read/write head can be encoded:

```
Left = 0    Right = 00
```

One move of the Turing machine's transition function will look like:

```
1state1symbol_new_symbol1head_move
```

Thus, in a Turing machine with $q_{start}, q_{accept}, q_{reject}$ and four other states $q_1 = 0000, q_2 = 00000, q_3 = 000000, q_4 = 0000000$, a move from $q_1$ reading to $q_{accept}$ writing a blank and moving would look like

```
1000010000101010=1c, encoded>1<cq_{accept}encoded>1<blank>1<left>1
```

The encoding of the entire TM can be done:

```
1move_1 move_2 move_3 ... move_{last} 1
```

One more note: a Turing machine with n moves can have them listed in any order—thus, there are n! orderings of the moves, and thus n! different (at least, they are different) encodings of the same Turing machine. That is not a problem.
