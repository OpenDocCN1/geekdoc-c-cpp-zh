If k = 2, duplicate the second term: so (x_i ∨ ¬x_j) becomes (x_i ∨ ¬x_j ∨ x_k).
If k = 3, no change is needed, as the clause is already in 3-CNF.

If k > 3, the original clause will be of the form x_{j1}, ..., x_{jk} (where any of the terms might be the negation with ¬). The transformation of this clause requires the creation of r = (k - 3) new variables y_1, ..., y_r. The idea is to "pull apart" the original clause into multiple clauses bridged by the y_i's and their negations as follows:

+   (x_ij ∨ x_j2 ∨ y_1) First two terms of the clause
(¬y_1 ∨ x_j3 ∨ y_2) Third term of the clause
(¬y_2 ∨ x_j4 ∨ y_3) Fourth term of the clause
...
(¬y_r ∨ x_{j(k-1)} ∨ x_{jk}) Final two terms of the clause

For example, the clause, (x_3 ∨ ¬x_2 ∨ x_1 ∨ ¬x_3 ∨ ¬x_i) becomes:

+   (x_3 ∨ ¬x_2 ∨ y_1)
(¬y_1 ∨ x_1 ∨ y_2)
(¬y_2 ∨ x_1 ∨ y_3)
(¬y_3 ∨ ¬x_3 ∨ ¬x_i)

# YES TO YES

For clauses of length k ≤ 3, the true term that appears in the old clause also appears in the new clause, and so the new clause is still true.
For clauses of length k > 3, we have a whole new set of clauses, and they must all be true. At least one of the x_ij from the original clause was true. There will be a way to choose true values for the y_i, so that the new clauses are true.

+   If x_ij or x_j2 was true:
Set y_i to false.
Set all of the other y_j to true.
If x_ij was true for 2 < r < (j_k - 2):
Set y_m 1 ≤ m < r, to false.
Set all of the other y_j to true.
If x_{j(k-1)} or x_{jk} was true:
Set y_r to true.
Set all of the other y_i to false.
