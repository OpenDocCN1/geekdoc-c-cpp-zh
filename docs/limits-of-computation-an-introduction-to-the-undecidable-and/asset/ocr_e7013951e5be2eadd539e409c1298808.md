The machine so constructed is an NDTM. In its first phase, it has (prob- ably many!) choices at each step. But both phases are polynomial. The first phase is polynomial since it must stopping after p'(n) steps, and the second phase is the deterministic verified bounded by p'(n). Thus, the entire NDTM has an accepting path bounded by p'(n)*[length of time to make a guess for the next step] + p'(n) = CONSTANT*

This may not seem intuitive, and it will not seem efficient. For example, suppose you want to show there is a path from A to H in the graph:

A - B - C - D - E - F - G - H

A path is a sequence of nodes—so at each step, the NDTM certificate builder will: (1) to guess that the path is finished (if path length has reached |V|, then it knows the path be done), and (2) if not finished, it guesses the next node. It is very unlikely to guess the path above—it is very unlikely to guess a valid path with nonrepeating nodes. It is also allowed to stop the path after 2 or 3 or 4 nodes, or to keep going after 8 to 9, 10, or more, up to |V| +1.

For another example, 5041 is a composite number (it is divisible by 71, though not by any other primes). The NDTM begins by guessing a sequence of digits to write down—it could write one, two, three, or four digits. There are 5039 possibilities (2 ... 5040) for the number it guesses if we limit the guess by 5041 (9998 guesses if we just limit it to four digits, 2...9999). The inefficiency does not matter. It also does not matter that one of the 5039 (9998) possibilities works, so its chances of guessing are less than 1 in 5000 (or 10000). As long as (1) there is some way to guess correctly, and (2) we can verify that the guess is a certificate in polynomial time. One can find 5041/71 in time bounded by a polynomial in [5041] = 4 —that is all that we care about.

In other words, do not worry about missing the correct certificate. As as long as there is a short certificate that can be checked, that is sufficient. An omniscient omnipotent guesser could make the correct guess, that is enough.
