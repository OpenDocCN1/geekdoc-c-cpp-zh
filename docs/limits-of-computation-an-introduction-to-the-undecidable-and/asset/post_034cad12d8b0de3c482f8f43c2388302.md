## 3.2 DECISION PROBLEMS

A computational problem is a mapping between sets of sequences. As a language is a set of strings (which are sequences), a computational problem can also be seen as a statement about strings. This connection is an important one, and is the basis of computation theory.

Most of the computer science algorithms in standard texts find something in a set of data (“find the shortest path from A to B in the given graph”) or manipulate a set of input (“sort this array into ascending order”) or “output the amounts for current paychecks for employees in this database”. A simplification—but one we will be able to show without really losing anything—is to restrict the problems considered to only yes/no answers.

### Definition 3.3

A decision problem is a computational problem with output from the set {yes, no}.

Thus, a decision problem can be restated as a set membership question if S is the set of yes instances, is this instance in S or not?

The input is encoded as a string; this can be done in various ways (it is easy to encode an integer or an English sentence; a little less easy to encode a graph—and how would you encode a map?). Encodings of graphs will be discussed later.

### Example

“Find the shortest path from A to B in graph G” becomes the decision problem: “Given a number k and a graph G with vertices A and B and the path A = v₁, v₂, ..., v_ᵢ = B, is this a valid path in G with length ≤ k?” Here, if we do not care about the actual vertices that make up the path, we can translate it to: “Given a number k and a graph G with vertices A, B, does G contain a path of length ≤ k from A to B?” This becomes the language problem (or decision problem):

Language problem $L_{path\_of\_length\_k} = \{k, G, A, B : k integer, G graph with vertices A and B, and G has a path from A to B of length ≤ k\}$

### Example

Find an English language palindrome (phrase made up of legal words, that, ignoring spaces, punctuation, and upper/lowercase, is the same forwards as backwards).

Language problem $L_{palindrome} = \{string s | s is a \ palindrome according to the above definition\}$

Yes instances: Level; madam, I'm Adam; A man, a plan, a canal, panama

No instances: This is a palindrome; this is not a palindrome

### Example

“Find the nth prime P” can be restated as the decision problem: “Given n and P, is P the nth prime?” (Assume that 2 is the first prime).

Language problem: $L_{nth prime} = \{n, P | n, P are positive integer numbers and P is the nth prime\}$

Yes instances: 1, 2 (two is the first prime); 4, 7; 7, 17

No instances: 2, 8; 7, 19

### Example

“Add the integers n, m in binary to find their sum” is restated as “Given binary integers n, m, r, is r = n + m?”

Language problem: $L_{binary addition} = \{n, m, r | n, m, r are integers in binary and r = n + m\}$

Yes instances: 10, 10, 100; 1, 1, 10

No instances: 10, 10, 101; 1, 1000, 100

### Example

“Given a legal chess board configuration and that it is White’s move, which move should she make?” “Given this chess board and a suggested move, can White force a win by making this move?”

In all cases that we use, there are an infinite number of possible inputs, which are divided into the yes instances and the no instances. there were only a finite number of possible instances, the question could be answered by a simple table lookup, and would not be interesting.

Chess is something of an aberration—there are only a finite number of board configurations, and for each board configuration, only a finite number of possible moves. However, except for some near-end-game configurations with only a few pieces left on the board, the number of possible moves and countermoves is so large that no solution has been found. But because of the finiteness, standard 8 by 8 chess does not fit into the problems considered in this course.

Computational problems can always—with varying degrees of difficulty—be restated as decision problems. Certainly, a solution to the general problem solves the decision problem, but the reverse is also true. A machine powerful to answer the decision problem can—perhaps with some effort—do the path finding, prime generation, or addition (by restatements as those above). In formal language and computation theory, we will not lose any generality ourselves by restricting decision problems, and we will state all problems as language membership questions.

## 3.3 TRAVELING SALESMAN PROBLEM

A particularly important computational problem is the traveling salesman problem (TSP). It gets its name from a salesman who lives in a given city but must visit all other cities and return home—in what order should he make calls so that his travel time is minimized? For an entire book discusses the history and significance of TSP, see Cook (2011).

Version 1 (TSP): Given a weighted graph G with vertices $v_1 \dots v_n$ and edges $ij$, with a positive weight $w_{ij}$ between each pair of vertices $v_{ij}$, what is the length of the shortest path that starts at $v_i$ visits every vertex of G, and returns to $v_i$?

Note that G is assumed to be a complete graph—there is an edge and a weight between any two vertices. It would certainly be possible to allow consideration of other graphs. However, negative weights are not allowed.

Version 2 (Path TSP): Given a weighted graph G with vertices $v_1 v_2 \dots$ and edges $ij$ with a positive integer weight $w_{ij}$ between each pair of vertices $v_{ij}$, what is the best order of vertices to visit $(v_1, v_2, \dots, v_n)$ that yields the shortest path that starts at $v_i$, visits every vertex of G, returns to $v_i$? In other words, what is the length of the shortest path, and what is the ordering of vertices that gives this length?

**Version 3 (K-TSP or decision problem TSP):** Given a weighted graph G with vertices $v_1, v_2 \dots$ and edges $e_i$ with positive integer weight $w_i$ on each edge $e_i$, and a bound $K$, G has a path that starts at $v_i$, visits every vertex of $G$, and returns to $v_i$, such that the length of the path is less than $K$? Or, as a language problem: $L_K = \{\text{graph } G=(V, E, W), \text{integer } K \text{ has an appropriate circuit of weight } K, \text{ where } |V| \le |V| \times \min(w_i) \le K \le |V| \times \max(w_i)\}$. ('These are the only possible values for K. Why? This is clearly related to the Hamiltonian circuit decision problem. Given an unweighted graph, does it have any path that begins at $v_i$, visits every vertex of $G$, and returns to $v_i$? More on this in Chapter 9.)

Notice that this is a set of decision problems, for each K. The small K that $L_K$ is a yes instance will yield the shortest solution to TSP. It is also easy to answer TSP given an answer to decision problem, and vice versa. See the Exercises.

This relationship between search (find smallest/n such that ... ) and decision (does n satisfy...?) holds for many problems. But neither the search nor the decision problem has an easy transformation to find whatever makes the question into a yes instance—in this case, the actual shortest path through the graph.

## 3.4 ALGORITHMS: A FIRST LOOK

One of the main goals of computer science is the statement of a good definition of algorithm. Almost any computer scientist has an intuitive feel for what is meant by *algorithm*, but formalizing the definition is not easy. None of the definitions below are really adequate, but they will be good enough for a discussion of the number of steps in a process.

### Trial Definition I

An **algorithm** is a solution to a computational problem.

Thus, BubbleSort, HeapSort, MergeSort, and so on, are all solutions to the Sorting Problem. Each of these is a finite sequence of steps that provides a solution to every instance of the computational problem, that is, a mapping from all inputs to correct solutions (outputs).

The above definition is quite helpful: it tells us what an algorithm is in functional terms. It does not, however, tell how we arrive at this mapping. As programmers, we realize that there are many issues surrounding the design, implementation, and execution of computer algorithm. What logic do we use? What data structures do we need? How do we show that our algorithm is working correctly? There is clearly more attached to the notion of algorithm than this abstract statement.

The word algorithm itself is fairly recent in the English language; older dictionaries do not contain it, though they do contain related word.

### Trial Definition II (Merriam-Webster’s Collegiate Dictionary, 11th edition)

An algorithm is a “procedure” for solving a mathematical problem (as of finding the greatest common divisor) in a finite number of steps that frequently involves repetition of an operation; broadly, a step-by-step procedure for solving a problem or accomplishing some end, esp. by a computer. Donald Knuth may have had the most influence on the use of the word, and other computer science terms, with his three-volume book on algorithms, The Art of Computer Programming, which he began in 1962 (when he was a graduate student); it is most recently available in a third edition (1997).

### Trial Definition III (after Knuth, 1968, p. 4)

An algorithm is a finite set of rules that gives a sequence of operations for solving a specific type of problem, with five important features:

- Finite: It must always terminate after a finite number of steps.
- Definite: Each step is precisely defined; actions to be carried out must be rigorously and unambiguously specified for each case.
