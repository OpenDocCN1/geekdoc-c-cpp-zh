# Trial Definition IV

An algorithm is a well-defined finite sequence of steps, guaranteed to terminate.

Definition IV is a reasonable working definition for most programmers. The phrase “well-defined” can be interpreted as “expressible in some programming language”—after we have the definition of a Turing machine, that will be the preferred definition. “Termination” is the absence of any infinite loop. An algorithm to find an entry in a database will return that entry or announce that it is not there; an algorithm to sort a file will end with the file in proper order.

Some definitions for the word algorithm omit the restriction that it must terminate—and are certainly computer programs, such as the one managing a monitoring system in a hospital, that should never terminate. An almost algorithm, that may or does not terminate, will here be called a computation or computational method.

# 3.5 HISTORY

Although the word algorithm only began appearing in dictionaries, it has a long history. Algorithm/algorithm is derived from the name of Abu Abdullah Muhammad al-Khwarizmi, a Persian mathematician (from native of Khwarizm; so the word actually derives from a place name), who, 810 C.E., wrote an influential treatise on procedures for solving problems in algebra—also a word from the Arabic, al-jabr. The confusion between the word algorithm, which morphed into the word algorithm, is likely linked to similar words in English (such as arithmetic and logarithm).

The first standard examples of algorithms are much older than the word itself. The following dates back to Book 7 of Euclid’s Elements, c. 300 B.C.E. It is a standard example of an algorithm, the Euclidean method for

finding the greatest common divisor of two positive integers (the largest integer that divides both of them). Euclid's algorithm for GCD (n, m), with n, m positive integers:

```
while m != 0 do
    r := n mod m
    n := m
    m := r
  return n
```

This is fairly obviously a sequence of four simple steps: one test, one step to find a remainder, and two assignment statements. The loop must terminate (for positive inputs) since m decreases during each iteration.

# 3.6 EFFICIENCY IN ALGORITHMS

# Definition 3.4

An efficient algorithm requires at most polynomially many steps as a function of input size. That is, if computation returns the value f(x) on input x, where x is a string, then it is efficient if there exists a power K such that the number of computational steps is bounded by |x|^K, where |x| is the length (number of characters) of x.

Two parts of this definition require immediate comment: Why polynomial?, and How to count the size of the input? Also note that some standard functions, as f(n) = n ln n, are not themselves polynomial, but are bounded by a polynomial (ln n < n, so ln n < n²).

# 3.6.1 Why Polynomial?

It is not truly reasonable to say that all polynomials are small enough to say that an action that takes many steps should be efficient. For example, an algorithm that would take 10,000n¹⁰⁰ steps to do something to an array of size n would not be generally useful. However, this is the standard definition of tractable/reasonable/efficient for mathematical (and other) justifications that we will go into later.

The main reason for the definition is that problems not bounded by a polynomial, whose growth is faster than any polynomial, grow so fast that they are absolutely not efficient. These “superpolynomial” algorithms are exponential, although other functions (such as factorials and functions like n!ᵇⁿ) are superpolynomial.

The definitions of efficient and tractable for algorithms will be revised later chapters, with further justifications. For the moment, it will be enough to see that any superpolynomial algorithm is not efficient. Consider how long it would take a computer with a 1-nanosecond instruction cycle to compute the number of instructions by the first column in Table 3.1.

# 3.6.3 Size of the Input

Counting the size of the input string $x$ deserves a moment of discussion. This size of the input will be important, and will get further later in the text. In these examples, the input consists of two integers, with two digits. As input, one cannot write them together (where does one stop 6018?), so the length of the input is the number of digits in the first number + the number of digits in the second number + 1 for a separating character. Thus, if the input $x$ is the pair of numbers 60 and 18, it can be written as $x = 60\#18$, and $|x| = 5$. For the pair of numbers 600,132,157 and 18,924, the size of the input would be 18 (or 15 if we drop the three commas).

# 3.7 COUNTING STEPS IN AN ALGORITHM

Algorithms are analyzed since, if there is a choice between various algorithms, the most efficient would be the best choice. But what does it mean to analyze an algorithm. And what do we mean by an efficient algorithm? Analysis could mean many things. Efficiency could mean that it runs quickly, or that it does not use much memory, or even that it is easily modified by a programming maintenance team. The standard measure of efficiency is running time, but even here, do we mean best running time? Average case? Worst case? And on what computer or model?

The standard approach is to count the number of steps (operations) necessary to solve an input with size $n = |I|$ in the worst case with input size. Note that counting in the number of steps, it is automatically assumed that all steps require the same amount of time—division by 713191 is almost certainly more expensive than multiplication by 2—however, only by a constant factor. Constant factors do not affect rates of growth—it is more important than an (n ln) algorithm is better than an n³ algorithm might be better than a 5311n² algorithm. In fact, because the 3n² and 6311n² algorithms have the same polynomial order, they will be in sense considered the same size. Although 6311n² is more than 2000 times large as 3n², they grow faster than n term for size when n is large. One grows faster than the other, but constantly. On the other hand, n³ grows much faster than n². And the function 2 grows much faster than either.
We will say that n³ and 10,000n³ have the same rate of growth since they differ only by a constant.

# 3.8 DEFINITIONS

There are many ways to compare the sizes of two functions or two algorithms. We will use only O (capital letter omicron from the Greek alphabet, pronounced “big oh”). This is the way you probably first in data structures or algorithms analysis class. The main reason for using here is that it is an upper bound—which in this course is what we care about, rather than an exact measure—and it is usually convenient to calculate.

# Definition 3.5

For functions f and g defined on the integers, f is O(g) if there exist positive integers C and N such that |f(n)| ≤ |g(n)| for all n ≥ N.
