# Definition 5.8

A nondeterministic Turing machine $N = (\Sigma, \Gamma, Q, q_{accept}, q_{reject}, q_{start}, \delta)$ in which:

- $\Sigma$ is the **input alphabet** with $B \notin \Sigma$.
- $\Gamma$ is the **tape alphabet** with $B \in \Gamma$ and $\Sigma \subseteq \Gamma$.
- $Q$ is a finite **state set**.
- $q_{accept} \in Q$ is the unique **accept state**.
- $q_{reject} \in Q$ is the unique **reject state**.
- $q_{start} \in Q$ is the designated start state.
- $\delta: Q - \{q_{accept}, q_{reject}\} \times \Gamma \to \mathscr{P}(Q \times \{Left, Right\})$ is the **transition relation**.

Here, $\mathscr{P}$ is the power set, so each element is mapped to—possibly—a set of combinations.

The only difference between this definition and that of its deterministic counterpart occurs in its $\delta$ component. Examine this carefully: it maps into the power set! Thus, the value of $\delta(q, \sigma)$ is a set of zero or more triples, and $\delta$ is a relation and not a function. Thus, it is possible from a certain position (in state $q$, reading $\sigma$) that there is no possible move (as in an ordinary TM), or many possible moves.

# Theorem 5.9

A nondeterministic Turing machine $M$ has an equivalent deterministic Turing machine $M'$. $t$ steps of $M$ can be emulated in $2^{Kt}$ steps of $M'$, where $K$ is a constant. Thus, if an algorithm on input of size $n$ is bounded by $t(n)$ on a nondeterministic machine, it is bounded by $2^{Kt(n)}$ on a deterministic machine.

**Note:** Of course, a deterministic Turing machine is also a nondeterministic machine where the number of choices at each step is exactly one. So the theorem says that a language has an ordinary TM if and only (iff) it has a NDTM.

# Proof (of Theorem 5.9)

The idea is simple: the deterministic Turing machine must try all possible sequences of moves that the nondeterministic machine could make, and accept if it ever finds an accepting sequence of moves. The only complication is how to systematically try all sequences of moves. It can not take a sequence and follow until it reaches a resolution, as it might never do so. And, it does not have to be efficient, so it can restart at the very beginning time.

Thus, it should try:

- All sequences of moves of length 1 (all possible configurations that it can reach in one move)
- All sequences of moves of length 2
- All sequences of moves of length 3
