# Undecidability

6.1 INTRODUCTION AND OVERVIEW

Our definition of an algorithm is a Turing machine that decides a language—that is one that always halts by entering its accept or reject state as appropriate.

Now it is to tackle what it means to be undecidable. This will take some effort to prove, and also will take effort to understand the proof when we have it. First, we need to lay some groundwork.

What does it mean to be undecidable? “no algorithm exists”; that, there cannot be any Turing machine that halts on all inputs. But understanding this, and using it to show certain problems are undecidable, is a harder proposition.

In particular, finding the first undecidable problem takes some work. The only way to prove that something does not exist will be by contradiction—for a particular problem (acceptance of a string by a Turing machine), assume that an algorithm exists, show that this produces an impossible situation. That will mean that our assumption about the existence of the algorithm is wrong.

6.1.1 Problems That Refer to Thmselves (Self-Reference)

The key argument will come from self-reference. Self-reference means applying something to itself. For example, if I say, “I always lie,” that means that every statement I make, including the one “I always lie,” is untrue. This may or not present difficulties. (Consider the difference between the statements “I always lie” and “I always tell the truth”—see the Exercises.)
