The class of problems that we are next interested in are those that have short certificates, but no known short solutions (“short,” as usual, means bounded by a polynomial in the length of the input). Informally, these are problems where it is hard to find a solution, but easy to check a solution works if you are given one.

The class of problems with short certificates, NP, is called the class of nondeterministic polynomial (decision) problems. Of course, P ⊆ NP, so the problems that are interesting are those in NP \setminus P.

## Definition 8.2

A decision problem is in NP if there is a nondeterministic Turing machine (TM) $M$ that for any instance $X_y$, $M$ reaches $q_{accept}$ in time bounded by a polynomial in the size of the input to the machine, $|X_y|$.

That is, if $X$ is a yes or no instance of the problem, and the length (size) of the encoding of $X$ is $n$ ($|X|=n$), then there is a nondeterministic Turing machine (NDTM) $M_N$ and a polynomial $p$ such that:

- If $X$ is a yes instance, $M_N$ has a path of length $\le p(n)$ to the accept state.
- If $X$ is a no instance, $M_N$ has no path to the accept state.

## Definition 8.3

A decision problem is in NP if and only if it has a polynomial verifier.

That is, if $X$ is a yes instance of the problem, then $X$ has a certificate $C$, and there is a (deterministic) Turing machine $M_D$ that can check (verify) $C$—that it is valid—and this check is done in a number of steps bounded by a polynomial in the length of the problem.

If the length of the encoding of $X$ is $n$, and the length of the certificate $C$ is $m$, then there is a polynomial $p'$ such that the deterministic Turing machine (DTM) $M_d$ runs in steps bounded by $p'(n)$.

**Note:** The length of the certificate $m$ is not mentioned in the definition, but it must be bounded by a polynomial in $n$; otherwise, the DTM could not read the entire certificate in $p'(n)$.

**Note:** The initials N and P *do not stand* for nonpolynomial! That is a common misconception, but incorrect for several reasons: (1) it has not been proved that there are no polynomial algorithms for the problems in NP, (2) $P \subseteq NP$, some problems in NP have polynomial solvers, and (3) many problems are not in P. Instead, NP stands for nondeterministic polynomial.

## Theorem 8.4

The two definitions above (Definitions 8.2 and 8.3) are equivalent. We need to show that an NDTM solver exists if and only if a polynomial verifier exists.

**Direction 1:** Assume the first definition is satisfied—the problem has an NDTM solver, and a yes instance has a path to the accept state bounded by $p(n)$. The certificate here is the path. Remember that a certificate can be anything that proves this is a yes instance—so showing how to accept will do. To verify the certificate, just follow its path and see that one reached accept. The path is bounded by a polynomial number of steps.

**Direction 2:** Assume the second definition is satisfied—that is a yes instance of the problem has a certificate with a polynomial verifier bound $p'(n)$. Now show that a polynomial-bounded NDTM exists. We construct a two-phase machine. The first phase is to guess the certificate. This can be done by looking at the form of the certificate. At each step of the first phase (1, 2, ..., $p'(n)$), the choices of the NDTM are: (1) write down one possibility for this step, or (2) stop writing certificate and proceed to the second phase. Once the bound is reached, the NDTM must stop. The second phase of the NDTM is simply to run the deterministic verifier on the guessed certificate. The machine constructed is an NDTM. In its first phase, it has many choices at each step. But both phases are polynomial. The first phase is polynomial since it must stop after $p'(n)$ steps, and the second phase is deterministic bounded by $p'(n)$. Thus, the entire NDTM has an accepting path bounded by [length of time to make a guess for the next step] + $p'(n)$ = constant.

This may not seem intuitive and will not seem efficient. For example, suppose you want to show there is a path from A to H in the graph:

A - B - C - D - E - F - G

A path is a sequence of nodes—so at each step, the NDTM will: (1) guess that the path is finished (if path length has reached $|V|$, it knows the path is done), and (2) if not finished, it guesses the next node. It is unlikely to guess a path with repeating nodes. It is also allowed to stop the path after 2 or 3 or 4 nodes, or to keep going after 8 to 9, or more, up to $|V|+1$.

For another example, 49 is a composite number (it is divisible by 7, though not by any other prime). The NDTM begins by guessing a sequence of digits to write down—it could write one, two, three, or four digits. There are 48 possibilities (2...49) for the number it guesses if we limit the guess by 49 (9998 guesses if we just limit it to four digits, 2...9999). The inefficiency does not matter. It also does not matter that one of the 48 possibilities works, so its chances of guessing are less than 1 in 50 (or 100). As long as (1) there is some way to guess correctly, and (2) we can verify that the guess is a certificate in polynomial time, one can find 49/7 in time bounded by a polynomial—4—that is all that we care about.

In other words, do not worry about missing the correct certificate. As long as there is a short certificate that can be checked, that is sufficient. An omniscient omnipotent guesser could make the correct guess, that is enough.

## 8.3 POLYNOMIAL REDUCIBILITY

We already have seen when it is useful to reduce one problem to another:

$P_1 \le P_2$

so that answering $P_2$ will give answers to both $P_1$ and $P_2$. Intuitively, $P_2$ is harder than $P_1$ (or more correctly, $P_2$ is at least as hard as $P_1$, or $P_2$ is as hard or harder than $P_1$).

Here, because we are also concerned with the length of time—polynomial whatever—we must assume that mapping is of reasonable length. If the mapping took too long to compute, a fast solution to $P_2$ would not necessarily be a fast solution to $P_1$.

Thus, we will put a restriction on the definition of reducibility, so that solving the second problem not only solves the first, but fast solutions to the second are also fast to the first.

## Definition 8.5 (Definition 7.2 Restated)

A problem $P_1$ is polynomially reducible to a problem $P_2$ if there is a mapping $f$ from the domain of all instances of $P_1$ into the set of instances of $P_2$.

1. If $A$ is a yes instance of $P_1$, then $f(A)$ is a yes instance of $P_2$.
2. If $A$ is a no instance of $P_1$, then $f(A)$ is a no instance of $P_2$.
3. For any yes/no instance $A$ of $P_1$, $f(A)$ can be computed in polynomial time (polynomial, as usual, in the size of the input).

One can rephrase the second requirement as 2': If $f(A)$ is a yes instance of $P_2$, then $A$ was a yes instance of $P_1$. Write:

$P_1 \le_p P_2$

which means (more formally) that if the length of the encoding of $A$ is $|A|$, then there is a polynomial $p$ such that the number of steps to compute $f(A)$ is bounded by $p(|A|)$.

Sometimes, this mapping is trivial. For example, if $P_1$ is a subset of $P_2$, then we can use the identity mapping. This makes sense; restricted problems are easier (or at least no harder) than their generalizations.

If $L_1 \le_p L_2$ and $L_2$ is in P, then so is $L_1$.

## Theorem 8.7

If $L_1 \le_p L_2$ and $L_1$ is not in P, then $L_2$ is not in P.

If $L_1 \le_p L_2$ and $L_2$ is in NP, then so is $L_1$.
