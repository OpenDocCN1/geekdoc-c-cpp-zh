# COMMENTS

+   1. What about polynomial algorithms with large exponents— perhaps O($n^{³}$)? Is such an algorithm really tractable? Practical? The answer is that we will call this algorithm tractable, although we admit that we would prefer a faster algorithm.

By limiting the exponent in defining tractable, we make life easier for ourselves. We do not have to worry about exactly which exponent is in the polynomial. And, and we can combine algorithms in many ways and remain tractable (since the sum, product, and composition of two polynomials are polynomial).

It is also true that there are few algorithms known that have large exponents. And, many problems with higher-order exponents are replaced by better and lower-order algorithms—for example, multiplying n × n matrices has a simple algorithm of n³, but better algorithms of order n² ln n are known, and there is hope for even lower orders.

For many computation problems, distributed computation can be used to “parallelize” an algorithm so that each component machine does a small part of the overall work, decreasing the overall bound to a lower polynomial; however, an exponential algorithm will remain remain.

+   2. What about intractable problems? Won't they become tractable when someone finds a good algorithm? For some problems, maybe yes. For example, for a long time, linear programming had no known polynomial algorithm. Also, the problem PRIME = {p | p is a prime integer} was only recently found to have a polynomial algorithm.
