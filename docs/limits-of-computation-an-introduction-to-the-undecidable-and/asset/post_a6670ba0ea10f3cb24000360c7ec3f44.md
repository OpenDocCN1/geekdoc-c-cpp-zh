## Limits of Computation

Thus, we never find the string $z$ so that $M(z) \neq M_p(z)$. Now consider the even number $2i$. None of the conditions 1 to 3 can be satisfied and $f(n) = 2i$ from this point. That means there are only finite number of strings for which $|w|$ is odd, and $L$ differs from SAT in a finite number of strings. But then $L$ would imply that SAT is also in P, which contradicts the assumption $P \neq NP$.

$L$ is not NP-complete: Suppose it were, there is a polynomial reduction (which must be computed by $M_{Ri}$ from the enumeration of all polynomial reductions) from CNF-SAT to $L$, that is, $M_R(z_k) = M_{SAT}(z_k)$ for all $z_k$. So, after $2i-1$, none of conditions 4 to 6 are satisfied and $f(n) = 2i-1$ for all a finite number of $n$. Then $f(|w|)$ is only even for a finite number of strings, $L(M)$ is a finite language, and $L(M)$ is in P. But since we assumed $L$ is NP-complete, this again contradicts the assumption $P \neq NP$.

However, this is not a proof that constructs a language that is easy to describe, this does not yield a useful example. Are there any NP-intermediate languages that arise from natural problems? Surprisingly, no good examples are known. There are few candidate problems like the following.

### 10.5.1 Linear Programming

Until 1979, when Linear Programming was shown to be in P, it was considered a possible candidate for NP-intermediate.

Given $m$ integer vectors $(V_1 \dots V_m)$ of length $n$, vectors $D$ of length $m$ $(d_1 \dots d_m)$, and $C$ of length $n$ $(c_1 \dots c_n)$, and integer target $T$, there is a vector $X, X = (x_1 \dots x_n)$ such that:

$V \cdot X \leq d$, for all $i, 1 \leq i \leq m$
$C \cdot X \geq T$

The operator is the dot product of two vectors, $(x_1 \dots x_n) \cdot (y_1 \dots y_n) = x_1y_1 + x_2y_2 + \dots + x_ny_n$.

In NP: The certificate is the vector $X$.
In P: The polynomial algorithm is found (Khachian, 1979).

This problem has the interesting extra property that the simplex algorithm has long been used to solve it. The simplex algorithm is not polynomial—worst case running time is exponential. It could not be used to show membership in P. However, in practice, its usual running time has been fast.

One point here is that exponential algorithms should not be simply discarded as too slow. Even though an algorithm is exponential, it may run quickly enough in practice, on average cases, to be useful.

### 10.5.2 PRIME

Given a positive integer $N$, is $N$ prime?

In NP: The certificate is certainly not obvious—the certificate for COMPOSITE is any pair of factors. However, there is also a certificate for PRIME.

In P: The polynomial algorithm is found (Agrawal et al., 2020), so this cannot be our NP-intermediate problem.

### 10.5.3 Graph Isomorphism

Given two graphs $G_1 = (V, E)$ and $G_2 = (V, E_2)$, is there a way to match the vertices of $G_1$ to those of $G_2$ so there is an edge between the two vertices of $G_2$? (Note that we assume that the two graphs have the same number of vertices, $v_1, \dots, v_n$, otherwise there would be no hope of an isomorphism.)

In NP: The certificate is the vertex correspondence between the two graphs.

It is still unknown whether in P or NP-complete: Open question. It has been proven in P for some special cases of graphs.
