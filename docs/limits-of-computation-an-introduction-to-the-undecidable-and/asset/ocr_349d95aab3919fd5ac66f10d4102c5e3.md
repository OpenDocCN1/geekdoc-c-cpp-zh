If M accepts, M' looks at its input. If $x = z$, then M' writes $\tau$ on its tape.
(If $x$ is not $z$, M' can do whatever it wants: it can simply halt and reject or whatever.)
If M does not accept w, M' goes to the reject state without writing anything on the tape.
If M is looping on w, so is M', simply waiting or looping until M finishes.
M accepts w $\Rightarrow$ M' on z writes $	au$.
M does not accept w $\Rightarrow$ M' never writes $	au$ on $z$ (or any other string).

# Theorem 7.11

Given a Turing Machine M and a string w, it is undecidable whether M halts on w.

**Note:** This is the Halting problem, and the well-known language $HALT_{TM}$ can be defined as

$HALT_{TM} = \{M, w: M \text{ halts on } w\}$

We say that M halts on w if it enters either of the states $q_{accept}$ or $q_{reject}$. These are the only two states without moves out of the state; every other configuration has a next configuration. If M does not accept w, we do not say that it loops, although there are many ways in which it can loop (cycle back and forth between adjacent tape squares, move right forward, etc.).

# Proof

We want to show $ACCEPT_{TM} \leq HALT_{TM}$. In this case, we will do slightly differently, but again, we build a machine M' so that M' halts on w and only if M accepts w. But here, we do by letting M' change its state $q_{reject}$ into a new state $q_{new}$. This is a simple cut-and-paste; every occurrence of $q_{reject}$ in the delta function is replaced by $q_{new}$. In $q_{new}$ we add moves so that on every symbol, M' writes a blank and moves. (Technically, we require that M' has its own state $q_{reject}$ so we can add that, but no transitions to it, so it is unreachable).

Now, if M accepts w, M' halts on w. And if M does not accept w, it must either loop on w or reject it—and in either case, M' does not halt on w. Thus, goes to yes, goes to no, and answering whether M' halts on w also answers whether M accepts w.
