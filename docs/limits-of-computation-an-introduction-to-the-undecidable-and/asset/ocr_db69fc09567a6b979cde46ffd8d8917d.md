# 34 Limits of Computation

The domain of a computational problem is a set of data (the *questions*) called the input. The range is a set of *answers* called the output. A computational problem, then describes how questions are related to answers.

For example, students in computer science are frequently asked to arrange data in ascending order. This is known as the *Sorting Problem* and is defined as follows.

# Example: Sorting Problem

Input: $(i_1, i_2, ..., i_n)$, where $(o_1, o_2, ..., o_n)$ is a permutation of $(i_1, i_2, ..., i_n)$ such that $o_1 \leq o_2 \leq ... \leq o_n$

One solution to the sorting problem is the bubble sort algorithm, which correctly maps inputs (questions) to outputs (answers).

# Definition 3.2

An **instance** of a computational problem is one particular element from the input set. A **solution of an instance** is the corresponding element from the output set as specified by the computational problem.

For example, the (5, 4, 2, 3, 1) of the sorting problem has the solution (1, 2, 3, 4, 5), whereas the instance (20, 40, 20, 20, 60, 60, 80, 40, 20) has the solution (20, 20, 20, 20, 40, 60, 60, 80).

Note that there are several possible solutions to these instances! It does not matter, for example, which of the four twenty elements (20, 40, 20, 60, 20, 80, 40, 20) we permute into the first position of the output sequence as long as we place one of them at that location. There are in many (4! 2!) different solutions to this!

There is nothing in the statement of the sorting problem that places a limit on the number of elements that an instance may have. In other words, the sorting problem can take any number of arguments. This means, for example, the empty sequence () is a valid instance. It also means that an instance could be phenomenally, staggering. An instance cannot, however, be infinite. There must be some final element $i_n$ of an instance, as—by definition—a computational problem only describes a relation between *finite* sequences.
