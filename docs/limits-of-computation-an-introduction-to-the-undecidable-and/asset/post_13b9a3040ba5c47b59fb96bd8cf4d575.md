
These can be hard to understand. If we denote the special language $L_\varepsilon$ = $\{\varepsilon\}$, then note that

$L_1/L_\varepsilon = L_1$

$L_1 \setminus L_2 = L_2$

$L_i/L_1 = L_\varepsilon$ or $\varnothing$ (depending on whether $\varepsilon$ is in $L_1$)

$L_i/\Sigma^* = \text{Prefix}(L_1) = \{ \text{begin with something in } L_i; remove anything from the right}\}$

$\Sigma^* \setminus L_2 = \text{Suffix}(L_2) = \{ \text{begin with something in } L_2; remove anything from the left}\}$

# Example

$(01)^*/1 = (01)^0$

$(01)^*/11 = \varnothing$

$0^*\0*1^* = 0*1^*$

$0^*1*0*1^* = 1^*$

A word on notation: 01 is a string, but $(01)^*$ and $0*1^*$ denote sets of strings, or languages in our notation. (If this were a course in formal languages, we would say that $(01)^*$ and $01^*$ are regular expressions that have an associated language, but here we are avoiding discussions of regular expressions.)

Thus, one could say $(01)^*/1$ is a language, and 1 is a string, but the operation works on two languages. We will say that 1 can stand for the string 1 and the language with only one string (or $L_i = \{1\}$), and that it is clear from the context which is used.

One can also shuffle languages. The **shuffle** of $L_1$ and $L_2$ consists of all strings that are formed by shuffling any string $v$ from $L_1$ and any string $w$ from $L_2$. This is the set of strings that can be written in the form $v_1w_1v_2w_2...nv_n$, where $n \ge 1$ and $v_1, \dots, v_n$ are strings such that the concatenation $v_1 \dots v_n$ is in $L_1$ and $w_1, \dots, w_n$ are strings such that $w_1 \dots w_n$ is in $L_2$.

# Algorithms

## 3.1 COMPUTATIONAL PROBLEMS

A text with the word computation in the title will clearly need to describe what is meant by a computation. This is both easy (in one sense) and hard (in others).

## Definition 3.1

A computational problem specifies a relation between two sets of finite sequences (or two sets of strings).

Recall that a finite sequence is a finite ordered list of elements from a set. For example, an integer is a finite sequence of digits (so that 921,233,456,181 is a sequence of length 15 as written, but the commas could be omitted, which would make it a sequence of length 12). An English word is a finite sequence of letters. An array of integers can be considered a finite sequence of integers—this is the usual interpretation in an algorithms analysis class—or as a finite sequence of digits with separators.

(23, 512, 312, 987, 45, 641) is a sequence of six integers

or
23,512,312,987,45,641 is a sequence of 21 characters from 0 to 9 and commas.

## 3.4 Limits of Computation

The domain of a computational problem is a set of data (the *questions*) called the input. The range is a set of *answers* called the output. A computational problem, then, describes how questions are related to answers.

For example, students in computer science are frequently asked to arrange data in ascending order. This is known as the *Sorting Problem* and is defined as follows.

# Example: Sorting Problem

Input: $(i_1, i_2, \dots, i_n)$, where $(o_1, o_2, \dots, o_n)$ is a permutation of $(i_1, i_2, \dots, i_n)$ such that $o_1 \leq o_2 \leq \dots \leq o_n$

One solution to the sorting problem is the bubble sort algorithm, which correctly maps inputs (questions) to outputs (answers).

## Definition 3.2

An **instance** of a computational problem is one particular element from the input set. A **solution of an instance** is the corresponding element from the output set as specified by the computational problem.

For example, the (5, 4, 2, 3, 1) of the sorting problem has the solution (1, 2, 3, 4, 5), whereas the instance (20, 40, 20, 20, 60, 60, 80, 40, 20) has the solution (20, 20, 20, 20, 40, 60, 60, 80).

Note that there are several possible solutions to these instances! It does not matter, for example, which of the four twenty elements (20, 40, 20, 60, 20, 80, 40, 20) we permute into the first position of the output sequence as long as we place one of them at that location. There are in many (4! 2!) different solutions to this!

There is nothing in the statement of the sorting problem that places a limit on the number of elements that an instance may have. In other words, the sorting problem can take any number of arguments. This means, for example, the empty sequence () is a valid instance. It also means that an instance could be phenomenally, staggering. An instance cannot, however, be infinite. There must be some final element $i_n$ of an instance, as—by definition—a computational problem only describes a relation between finite sequences.

# Algorithms

There are, however, an infinite number of instances and solutions to the sorting problem. This distinction is important. Although each instance and solution to every computational problem must be finite, there may be infinitely many instances.

Consider another familiar problem from introductory computer science—searching.

# Example: Searching Problem

Input: $(k, i_1, i_2, \dots, i_n)$
Output: $(o)$, where $o = TRUE$ if $\exists j [i_j = k]$; $o = FALSE$ otherwise
Alternate output: $(n)$, where $n = j$ if $\exists j [i_j = k \text{ and } m < j, i_m \neq k]$; $n = -1$ otherwise

The input to this computational problem might seem a bit confusing at first. In the first case, the input sequence contains a key $k$ followed by a list of elements $i_1, i_2, \dots, i_n$. The output of the searching problem is $TRUE$ if it exists in this list, or $FALSE$ if it does not.

Just as the sorting problem, there is no upper limit to the number of elements $i$ that might appear in the input sequence—just as long as this number is finite. The empty sequence (), however, is not a valid instance of the searching problem, as a key $k$ must always be the first element of every input sequence.

# Example: Integer Addition Problem

Input: $(d_1 d_2 \dots d_n, c_1 c_2 \dots c_m)$, where $d_i$ and $c_i$ are digits with base 10
Output: $(b_1 b_2 \dots b_r)$, where this is the proper sum of the two integers

One valid input instance would be (10,341, 79,855); its solution would be (90,196).

The problem of real addition is not a computational problem—there is no way to specify a pair of arbitrary real numbers (or even a single number) as a finite sequence.
