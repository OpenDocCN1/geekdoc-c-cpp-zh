What about space? Space is of course important, and algorithms that require too much space are impractical. How should one count space? What about an algorithm that requires no additional space beyond what the input occupies? This question is interesting, and sometimes it is interesting to count only the space beyond that occupied by the input.

We will assume that every algorithm uses at least the space occupied by the input. Thus, for s(n) = number of Turing machine squares required to solve the worst case input of size n,

s(n) = max (n, tape cells beside the input required by the algorithm)

In the relationships between classes, there is one obvious fact: in t(n) time steps, Turing machine can access more than t(n) cells on the tape. This easily implies the facts below:

# Fact

Any algorithm that runs in time t(n) must also run in space t(n).

# Fact

P ⊆ PSPACE
