## 5.2 TURING MACHINES TO EVALUATE A FUNCTION

In this course, Turing machines are used to answer decision problems. However, there are other kinds of Turing machines that can be developed.

If $f$ is any function from strings to strings (and this is any computational problem that can be imagined), then a Turing machine $M$ calculates (or computes) the function $f$ if it starts with the input $(x_1, \dots, x_n)$ on its tape, and ends (in some specially designated state $q_{done}$) with $f(x_1, \dots, x_n)$ on the tape. This kind of Turing machine is sometimes called a transducer. A simple example would be a machine to add the numbers $n$ and $m$, written in decimal.

Addition Turing machine transducer:

- Start: $q_{start}$ $n\#m$
- Finish: $q_{done}$, $n + m$

## 5.3 ENUMERATING TURING MACHINES

A Turing machine enumerates a language $L$ if it has a special state $q_{found\_one}$. An enumerating TM takes no input. It starts with an empty tape, and lists the strings in $L$, one by one. Each time it writes a string from $L$ onto its output tape, it announces it has found one by entering the special state $q_{found\_one}$. It can erase the tape and work on producing another string from $L$. Eventually, every string in $L$ must be enumerated (although not in any particular order).

Enumerating Turing machine for $L=\{n|n\text{ is prime}\}$:

- Start: $q_{start}$ empty tape
- Intermediate configurations
- $q_{found\_one}$, 13; $q_{found\_one}$, 2; $q_{found\_one}$, 7; $q_{found\_one} \dots$ 23
- (in any order whatsoever, unless $L$ has a finite number of strings)

It would be easy to design a Turing machine to enumerate the language $L = \{w \mid w\text{ starts with aa}\}$ over $\Sigma = \{a, b, c\}$. It would be less easy, but difficult, to design one to enumerate $L = \{w \mid w\text{ is the decimal representation of a prime number}\}$. It would be natural to enumerate the strings in lexicographic order, but that is not necessary—it can enumerate them in any order whatsoever; it can list the same string more than once; the only requirement is that every string in the language will eventually be enumerated.

There are many variations in Turing enumerators. For instance, it is certainly not necessary to erase the tape between strings; they can be written one after another on the tape with a separator symbol:

```
13#2#7#23# ...
```

It is not necessary to have a special state $q_{found\_one}$ either; the enumerator can use the separator symbol to announce the end of each string that it finds. Finally, it may be useful to have one or more working tapes as well as an output tape.

## 5.4 THE CHURCH–TURING THESIS

There have been models of what computation means. Programs written in any one of the programming languages are some of these models, but the idea of computation goes back to well before the existence of computers and computer languages. The question goes back to Leibniz, and what was one of the important problems of the early 20th century (David Hilbert made several references to it). But it was only about 1930 that the problem was sufficiently precise to be answered. Two logicians/mathematicians first answered this question were Alonzo Church and Alan Turing.

Alonzo Church was an American mathematician at Princeton. He developed the model of computation called lambda calculus. Alan Turing was a British mathematician. He is well known for his codebreaking work during World War II at Bletchley Park. But he also wrote (1936) a paper, “On Computable Numbers, with an Application to the Entscheidungsproblem.” The Entscheidungsproblem is the problem of finding an algorithm for deciding whether a proposition in first-order logic is always true.

The work of Church and Turing showed that there is no algorithm to solve the Entscheidungsproblem. Part of the work in doing this requires the formalization: What is an algorithm? Church used lambda calculus, Turing used Turing machines (not his name for them). It was easily shown that these two characterizations of algorithms (Church’s and Turing’s) are equivalent.

Other theoretical ideas of computation have also been in use—recursive function theory, Post systems, Markov systems, register machines. (A register machine is the simplest possible computer; its only instructions are increment, decrement, test-and-branch, halt.) Each of these models can be simulated by a Turing machine.

The Church–Turing thesis states that every model of computation—even those not yet in existence—can be done, and is equivalent to a Turing machine.

Note that there is no hope of proving this. It is not possible to prove something about computation that has not yet been proposed. However, the thesis has been verified for all known models of computation. It is widely accepted in the communities of logic, mathematics, and computer science. Its unprovability is why it makes the name thesis instead of *theorem*.

Thus, we will use a Turing machine as our model of computation. Or, stated otherwise:

- Computation = expressible on a Turing machine
- Algorithm = expressible on a Turing machine that halts

## 5.5 A SIMPLE COMPUTER (OPTIONAL)

The problem here is the amount of detail that one is willing to go through specify details of an ideal computer, and then showing to emulate each instruction on a Turing machine. Various authors have done this (Hopcroft et al., 2007; Lewis and Papadimitou, 1997; Homer and Selman, 2001); each has a slightly different approach.

First, the two big differences between a Turing machine and a computer are:

- 1. Sequential access versus random access: A computer can access any memory cell in one instruction (O(1)), but a Turing machine must begin at one end of its tape and move position by position along the O(tape length); so access is an operation that is the length of its tape to reach and access any memory location.
- 2. The instruction set: A computer will have a whole set of machine instructions, but a Turing machine can only read, write, change state, and move left or right.

Let’s suppose a computer with one dedicated register, a program counter (PC). It could also have k registers, but these are not necessary. The machine below has three address registers, but they could be eliminated. All instructions also work on simple memory locations. On a real computer, it is generally faster to have operands in registers, but only by a factor of a constant. And, for theoretical purposes, there is no distinction between an operation that takes 1 nanosecond and one that takes a constant K nanoseconds, even if K is large—algorithms that differ only by a constant factor are essentially indistinguishable.
