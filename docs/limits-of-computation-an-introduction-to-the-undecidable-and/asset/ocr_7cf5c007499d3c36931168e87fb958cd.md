Of course, one may continue making natural classes. For example, NEXP (problems with a nondeterministic exponential solver) and EXPSPACE (problems solvable in exponential space).

PSPACE ⊆ EXSPACE

and of course, this implies that

```
P ⊆ EXSPACE
```

but very little is known about what set inclusions are proper.

# 10.12 SPACE RESTRICTIONS

In the other direction, there are interesting classes where one restricts space to be less than the size of the input. At first glance, this may not make sense, since one has to read the input, how can one use less space for an instance I than its size |I| However, for many problems, one does not need to store the input—it can reside on external storage, and be read in increments. For example, one can check that an array is sorted by bringing in the elements of the array two at a time, and checking for each successive pair, a[i] ≤ a[i +1], so the only space needed is log log (the maximum element of a[i]).

This model gives rise to deciding Turing machines that have a read-only input tape and a working space of limited size—generally log |I|, where I is the input. If the Turing machine is a deciding TM, that is all it needs; if it is a transducer to compute f(I), it will have a third tape for writing its output.

# Definition 10.15

The class LOGSPACE is the set of decision problems decided by a Turing machine with read-only input, and a working space bounded by the log of the size of the input.
