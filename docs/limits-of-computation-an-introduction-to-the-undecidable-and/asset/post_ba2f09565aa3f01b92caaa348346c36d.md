
We will assume for memory that there are an unbounded number of cells, and that each cell can hold an arbitrarily large number. Again, both of these are unreasonable—computer memories are bounded but very large (especially if one considers CDs, DVDs, USB drives, tape drives, and other external memory as part of memory). There is a bound on the largest number that can be stored in one word of memory (size of an integer, or long integer, something similar). The way around bounded word size is to store large integers and real numbers in linked lists of memory cells, but we will assume that is not necessary.

Our model of a computer will have:

- Program counter: Automatically incremented at each instruction, except for jumps (PC).
- Three registers: Used for any sequence of bits, generally used as address registers (AR1, AR2, AR3).
- Infinite memory: Each memory addressed by an integer (1, 2, 3, ...); each can hold any sequence of bits.
- Program: Set of instructions, stored in memory.
- Input from some standard device; output to some standard device.

Notice that we assume that each register (PC, AR) and each memory cell can hold arbitrarily long sequences of bits. Despite the instruction set and the lack of registers, this makes our model more powerful than the computer you use.

Instruction set: We will choose an instruction set to be small but not miniscule. Here, one can get into interesting side excursions. A “Tarpit” is a computer language designed to be Turing-complete but as small as possible—several different tarpsits have been developed. Each must be able to read a symbol, write a symbol, increment (or decrement), and have some kind of branch. At least one language has managed to do all this in one instruction. There is a language whose only instruction is “subtract and branch if negative.” There is also the language OISC (a reduced instruction set language)—the instruction set computer—whose instruction also combines the increment/decrement and the branch.

The instruction set we will use has a subset of some of the standard three-address instructions. Addressing can be:

| Instruction | Operation |
| :--- | :--- |
| READ ar MEM[ar] | LOADED FROM INPUT |
| READ @ar MEM[MEM[ar]] | := INPUT |
| WRITE ar MEM[ar] | MOVED TO OUTPUT
| ADD ar1, ar2, ar3 | MEM[ar3] := MEM[ar1]+MEM[ar2] |
| ADD @ar1, ar2, @ar3 | MEM[MEM[ar3]] = MEM[MEM[ar1]]+MEM[ar2] |
| MEM[ar3] := MEM[ar1]/2 | |
| SHFT ar MEM[ar1] | MEM[ar1] * 2 |
| JMP C | PC = C |
| JPOS ar C | IF MEM[ar] > 0, PC = C |

The Turing machine to emulate this computer will have several tapes:

- Tape 1: PC (holds one address, which can be arbitrarily long)
- Tape 2: Address tape, used for fetching operands (holds up to three addresses)
- Tape 3: Memory, stored in the form of (address, contents) (unlimited number of pairs)
- Tape 4: Input tape (holds whatever the standard input device would contain (unlimited))
- Tape 5: Output tape (TM writes all output to this tape) (unlimited)
- Tape 6: Scratch work tape, if desired (unlimited)

Example: ADD 23, @45, 96

- 1. Write 23 onto tape 2, the address tape.
- 2. Scan the memory tape until the number 23 is found; replace 23 with contents onto tape 2.
- 3. Write @45 onto tape 2 (following the number written in step 2).
- 4. Scan memory tape until 45 is found; copy its contents onto tape 2 (replace the 45).
- 5. Find this cell on the memory tape; replace address address its contents.
- 6. Add these two numbers, using the scratch tape if desired.
- 7. Find cell 96 on the memory tape.
- 8. Replace its contents by the sum from tape 2 (perhaps moving tape over to make room).

This simple computer starts its computation with its program stored in memory (tape 3) and all its input on tape 4. The combined length of these tapes is some number I. After t steps of the program, a three-address instruction set cannot have accessed more than 3t memory locations.

At each step, the computer uses at most one new memory location. The number stored in that memory location is at most size (I + t). No result of addition, doubling, or other operation adds more than one digit to a number in base 2. Thus, after t steps, the contents of tape t have length bounded by Kt².

This means a one-time-unit random access to memory can be emulated by the Turing machine in Kt²; thus t steps can be emulated in Kt³.

Now, recall that a multitape Turing machine can be emulated by a single-tape Turing machine, and the order is by most squared. Thus, the simple computer can be emulated by a standard Turing machine in K’t—and importantly, what is polynomial on this computer is still polynomial on a standard Turing machine.

## 5.6 ENCODINGS OF TURING MACHINES

For many uses of Turing machines, we want to encode them (and their inputs) into some standard alphabet. There are several reasons to do this. First, we are writing Turing machines for different problems. This is not efficient; we do not build different computers for different problems; rather, we write different programs that run on the same computer. Second, we want a (relatively) short and machine-readable description of a Turing machine—something more standard and concise than the rather long English descriptions or complicated diagrams we have been writing.

In computer science, this alphabet is most naturally Σ = {0, 1}. To use only two characters, one of the characters must be a separator. Thus, all information must be encoded as strings of 0’s; we will need to use the 1 as the separator character (or, of course, vice versa).

One problem is to encode the alphabet of the Turing machine. If all alphabets are subsets of some standard alphabet such as the ASCII or Unicode sets of characters, there would be less of a problem, since each character in any alphabet could be encoded in Unicode. In this sense, all “regular” characters have already been coded into the alphabet of {0,1}. But there is no restriction on the alphabets of formal languages requiring them to use any symbol already in existence anywhere.

## 106 Limits of Computation

A Turing machine is defined by its: (1) set of states, (2) input and tape alphabets, and (3) delta function. Each (useful) state appears as the object of a move in the delta function, and each useful input or tape alphabet symbol will appear somewhere in the arguments or values of the delta function. Thus, we can retrieve all the information about the TM from delta function. We need to know what $q_{start}, q_{accept},$ and $q_{reject}$ are, but we can encode them in a standard way:

- $q_{start} = 0$
- $q_{accept} = 00$
- $q_{reject} = 000$

(The alert reader may complain that this assumes these are three distinct states, and does not allow, for example, $q_{start} = q_{accept}$. This is true, but it does not eliminate any interesting Turing machines.)

Moves of the read/write head can be encoded: Left = 0, Right = 00.

One move of the Turing machine's transition function will look like: `1state1symbol_new_symbol1head_move`.

Thus, in a Turing machine with $q_{start}, q_{accept}, q_{reject}$ and four other states $q_1 = 0000, q_2 = 00000, q_3 = 000000, q_4 = 0000000$, a move from $q_1$ reading to $q_{accept}$ writing a blank and moving would look like `1000010000101010=1c, encoded>1<cq_{accept}encoded>1<blank>1<left>1`.

The encoding of the entire TM can be done: `1move_1 move_2 move_3 ... move_{last} 1`.

One more note: a Turing machine with n moves can have them listed in any order—thus, there are n! orderings of the moves, and thus n! different (at least, they are different) encodings of the same Turing machine. That is not a problem.
