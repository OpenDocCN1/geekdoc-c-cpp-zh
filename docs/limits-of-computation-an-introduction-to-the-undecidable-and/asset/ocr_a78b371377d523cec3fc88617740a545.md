In the above example, we can assume that the target T = Max(input); and no polynomial p exists such that T ≤ p log₁₀ T, where n log₁₀ T is a measure of the size of the input.

Note that problems like CNF-SAT and HC have no numbers at all. They are not number problems. A problem such as vertex cover, where the size of the cover is limited by the number of vertices, is also not a number problem. Wait, you may say, there are numbers in SAT and in any graph problem—we have the Boolean variables and we have numbered the vertices in the graph. Well yes, these numbers are just names, and not really numbers. And, the numbers are small compared to the size of the problem—the number of Boolean variables or the integer names of the vertices in the graph are not what make the large. PRIME is a number problem. It has only one number in its input, and that number is not polynomial in its own log, which is the length of the input.

# Definition 10.2

An algorithm is pseudopolynomial if it is polynomial in the two variables (1) the length of the input and (2) the size of the largest number in the input.

For problems with no numbers in the input, we take condition 2 to be 0 [Max(input) = 0], so an algorithm for a problem with no numbers is polynomial if and only if it is pseudopolynomial.

Since filling in the table for Subset Sum is polynomial in n and T, and we can assume that T is the largest number in the input, this is a pseudo-polynomial algorithm. The standard simple algorithm for PRIME is also pseudopolynomial.

# Definition 10.3

An NP-complete problem is strongly NP-complete if it is (1) NP-complete and (2) remains NP-complete even if it is restricted so that the largest number appearing in the problem is bounded by a polynomial in the length of the input.
