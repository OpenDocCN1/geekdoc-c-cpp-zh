## 10.10 SPACE-COMPLETE PROBLEMS

The kinds of problems that turn out to be PSPACE-complete are interesting. Many of them come from the theory of two-player games. That may be natural, since a position is a winning position in n moves if the first player (that is, player 1 can force a win in n moves):

```
move player_one can make so that
moves player_two can make
answering move player_one can make
} depth = n
moves player_two has to choose from
...
Player-one has won the game
```

Standard chess will not do as an example, although only for the reason that there are a finite (up to 32) number of pieces on an 8 × 8 board. Thus, the size of the input cannot grow past a fixed bound. Theoretically, there are only a finite number of possible chess positions, and theoretically, we

could determine for one what the best move would be, and then play chess by a simple table lookup. This has not happened—and is unlikely to happen—since the finite number is so large as to be unmeasurable.

Games such as chess, checkers, and Go can be generalized to n x n board, easily for checkers and Go with their pieces that are all the same, and less easily for chess with its pawns, rooks, knights, and so forth. Under such generalizations, it is known that the games of Geography and Hex are PSPACE-complete, while the games of checkers and Go are PSPACE-hard.

## 10.11 THE CLASS EXP

Another interesting class of problems is the set of decision problems that are solvable in exponential time; that is, have time bounded by $c^{p(n)}$ for some constant $c$, and polynomial $p$, with n the size of the input. This class is naturally called EXPTIME, or simply EXP.

## Facts

NP ⊆ EXP

PSPACE ⊆ EXP

This follows directly as corollary to Theorem 10.8.

To reiterate the important point, time and space are related.

P (poly time) ⊆ PSPACE (poly space) ⊆ EXP (exp time)

There is no easy way to find a problem in EXP but proved not in NP or PSPACE. Most problems are produced by diagonalization arguments, so the problem produced is not natural and is easy to describe. The proof that a particular problem is not in either of these classes is really difficult: one that no algorithm can ever be found that will run in polynomial space. There have been problems (such as combinatorial game problems) that have been proved complete for EXP, and thus are the hardest problems in EXP. These

## 10.12 SPACE RESTRICTIONS

In the other direction, there are interesting classes where one restricts space to be less than the size of the input. At first glance, this may not make sense, since one has to read the input, how can one use less space for an instance $I$ than its size $|I|$ However, for many problems, one does not need to store the input—it can reside on external storage, and be read in increments. For example, one can check that an array is sorted by bringing in the elements of the array two at a time, and checking for each successive pair, $a[i] \leq a[i+1]$, so the only space needed is $\log$ (the maximum element of $a[i]$).

This model gives rise to deciding Turing machines that have a read-only input tape and a working space of limited size—generally $\log |I|$, where $I$ is the input. If the Turing machine is a deciding TM, that is all it needs; if it is a transducer to compute $f(I)$, it will have a third tape for writing its output.

## Definition 10.15

The class LOGSPACE is the set of decision problems decided by Turing machine with read-only input, and a working space bounded by the log of the size of the input.

## 10.13 APPROACHES TO HARD PROBLEMS IN PRACTICE

So, what do you do if you need a solution to a problem that is NP-complete, or worse, PSPACE-complete? Even worse, undecidable? The bottom line is wary, but

the situation is not hopeless. For one thing, if the problem is NP-hard, it may only be exponential in the worst case. One approach is to use an exponential algorithm, with the expectation (hope?) that its running time for the usual sort of problem encountered will be reasonable.

In some cases, there may be an algorithm for identifying the worse (exponential) cases. You can then run that algorithm first, and your solution second.

If an approximation to the best solution is good enough (as it may well for Traveling Salesman), many NP-complete problems are known to have polynomial approximation algorithms. There are also probabilistic algorithms, which make random choices in their executions (which is different from nondeterminism). Some decision problems have good probabilistic algorithms, which will answer: “Yes, with probability 0.X.” If this probability is close enough to 1.0, that may be good enough.
