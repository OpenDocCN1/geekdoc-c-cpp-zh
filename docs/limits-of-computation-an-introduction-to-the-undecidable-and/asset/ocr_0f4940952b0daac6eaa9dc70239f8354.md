**Version 3 (K-TSP or decision problem TSP):** Given a weighted graph G with vertices $v_1, v_2 \dots$ and edges $e_i$ with positive integer weight $w_i$ on each edge $e_i$, and a bound $K$, G has a path that starts at $v_i$, visits every vertex of $G$, and returns to $v_i$, such that the length of the path is less than $K$? Or, as a language problem: $L_K = \{	ext{graph } G=(V, E, W), 	ext{integer } K 	ext{ has an appropriate circuit of weight } K, 	ext{ where } |V| \le |V| 	imes \min(w_i) \le K \le |V| 	imes \max(w_i)\}$. ('These are the only possible values for K. Why? This is clearly related to the Hamiltonian circuit decision problem. Given an unweighted graph, does it have any path that begins at $v_i$, visits every vertex of $G$, and returns to $v_i$? More on this in Chapter 9.)

Notice that this is a set of decision problems, for each K. The small K that $L_K$ is a yes instance will yield the shortest solution to TSP. It is also easy to answer TSP given an answer to decision problem, and vice versa. See the Exercises.

This relationship between search (find smallest/n such that ... ) and decision (does n satisfy...?) holds for many problems. But neither the search nor the decision problem has an easy transformation to find whatever makes the question into a yes instance—in this case, the actual shortest TSP path through the graph.

# 3.4 ALGORITHMS: A FIRST LOOK

One of the main goals of computer science is the statement of a good definition of an algorithm. Almost any computer scientist has an intuitive feel for what is meant by the word *algorithm*, but formalizing the definition is not easy. None of the definitions below are really adequate, but they will be good enough for a discussion of the number of steps in a computational process.

# Trial Definition I

An **algorithm** is a solution to a computational problem.

Thus, BubbleSort, HeapSort, MergeSort, and so on, are all solutions to the Sorting Problem.
