This formula for the length of input n and m in base 10 becomes 1+|⌈log₁₀(n+1)⌈+|⌊log₁₀(m+1)⌋ (where ⌈ denotes the ceiling function), or essentially 2max⌈log₁₀n,⌊log₁₀⌋). Since the first step reverses n and m if n < m and only adds one extra iteration, we can assume n ≥ m, and this is log₁₀n; that is, the size of the input is essentially the number of digits in n.

If used binary, or some other base for the input numbers, the algorithm still works. In one base is a constant times its length in some other base, the number of steps only changes by a constant factor.

Division only takes one step on a computer if the numbers are small enough to fit into the register(s) available for division. Here, we want to allow arbitrarily large numbers; restricting n and m to fit as integers, or to a standard word size, would be too restrictive.

In any iteration, n = km + r with m ≥ r and k ≥ 1 (since n ≥ m). Means n ≥ r + r = 2r; so r ≤ n/2. Then, n and m get r. In every two iterations, n ← m (old) number of iterations is certainly bounded by 2⌈log₀n⌈. Thus, the order of the algorithm is bounded by a constant multiplied by⌈log₀n⌈; and is polynomial (cubic, though a better analysis yields quadratic) in size of the input.

# Given

Given a Boolean expression in variables x₁, ..., xn, connected by ∧, ∨, →, and grouped with left and right parentheses, with an assignment of 0 (false) or 1 (true) to each of the xᵢ, is the expression e?

This is equivalent to evaluating one of the truth table for the expression e. One approach would be to scan the expression multiple times (certainly less than |e| times). First, replace each x with 0 or 1. Second, replace ¬0 by 1 and ¬1 by 0. Each scan-and-replace can be done in |e| times, and the procedure is done fewer than |e| times. This means the entire algorithm is bounded by |e|².
