# Other Interesting Questions and Classes

10.1 INTRODUCTION
In this chapter, we will look at interesting questions and classes that come out of the ideas in the previous chapters. Are there other complexity classes? The answer is yes, that there are entire hierarchies of classes, although most are not naturally defined as P and NP. We will consider some of the most important of these classes.

How do these relate to what has already been discussed? In many cases, we will be able to show some interesting relationships. But are there any subset relations known to be proper subsets? If so, which? What natural questions are still unanswered?

Are there distinctions between or among the members of the class of NP-complete problems? Are there any subclasses of NP except the classes P and NP-complete? Are all NP-complete problems of the same difficulty? In one sense, since of course any NP-complete problem is polynom reducible to any other NP-complete problem. However, some might be considered to be harder than others. A few owe their difficulty to aspects of the problem that disappear when certain limits are set on the input.

10.2 NUMBER PROBLEMS
Consider the following simple algorithm to decide whether an integer p is prime:

```
is_prime = ! (p mod 2 == 0);
div = 3;
while (div<= p) and is_prime {
  if (p mod div == 0) is_prime = false;
  div += 2};
```

This algorithm is bounded by $2\sqrt{p}$ (and will take many iterations when p is prime). Therefore, it would be tempting to say that the algorithm is better than polynomial, since it runs in $O(p^{1/5})$ iterations. But there is a fallacy in this thinking. It runs in $p^{1/5}$, but this is not polynomial in the length of the input, as is required in the definition of the class **P**. The length of the input is the number of digits in p, or, the ceiling of log p $\log_{10}p$, that is

```
$p^{1/2} = 10^{5\log p}=constant*sizeinput$
```

Thus, it is really exponentially in the size of the input. This distinction—an algorithm that is polynomial in *some part* of the input, but not the size or length of the input—appears in several **NP**-complete problems. A polynomial algorithm for PRIME has been found (Agrawal et al., 2004), but it is much more complex than the above algorithm.

Another interest we have shown to be **NP**-complete. Recall this problem of a multiset (a set with repeatedly repeated elements) of $n$ integers, $S = \{I_1, ..., I_n\}$ and a target $T$. The question is, can one choose subset of the integers $S' = \{I_{k_1}, ..., I_{k_j}\}$ so that the sum of the integers in $S'$ is $T$?

This problem has an interesting dynamic programming algorithm. Dynamic programming algorithms are those that are based on saving solutions to parts of the problem and building on these, combining into a whole solution.

One dynamic programming algorithm for Subset Sum is based on the construction of an $n \times (T+1)$ table. The rows are labeled by the $I_1, ..., I_n$, the columns from 0 to $T$. Each table$[i, j]$ will be TRUE if the $j$th number can be made a sum of the first $i$, ..., $I_n$. All entries are initialized to FALSE.

For example, suppose that $n=6, T=21$, $I_1=2, I_2=3, I_3=6, I_4=3, I_5=5, I_6=7$. The dynamic programming algorithm fills the table by row. Entries in the first row are set to TRUE (see Figure 10.1).

# Definition 10.1

A decision problem is a number problem if there is no polynomial bound
on the largest number that is part of the problem, in terms of
length of the input.

Let Max(input) be the size of the largest number in an instance of
problem (if A has no numbers, Max(input) = 0). The size of the
is, as usual, |I|. If there is no polynomial p such that Max(input) ≤ p(|I|), then A is a number problem.

# Definition 10.2

An algorithm is pseudopolynomial if it is polynomial in the two variables (1) the length of the input and (2) the size of the largest number in the input.

For problems with no numbers in the input, we take condition 2 to be 0 [Max(input) = 0], so an algorithm for a problem with no numbers is polynomial if and only if it is pseudopolynomial.

# Definition 10.3

An NP-complete problem is strongly NP-complete if it is (1) NP-complete and (2) remains NP-complete even if it is restricted so that the largest number appearing in the problem is bounded by a polynomial in the length of the input.
