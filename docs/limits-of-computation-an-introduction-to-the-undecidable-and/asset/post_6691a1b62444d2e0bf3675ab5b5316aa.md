# 4.7 TURING MACHINES: WHAT SHOULD BE ABLE TO DO?

## 4.7.1 If a Given Diagram Describes a Turing Machine

Suppose you are given a picture such as diagrams for $M_1, M_2, M_3$, above. Does this diagram really describe a Turing machine? Maybe yes, maybe no. Ask yourself:

- Does it have a start state?
- An accept state?
- A reject state?
- Is exactly one out of every state every symbol? (Check the arrows.)
- Are indeed no moves out of $q_{accept}$ and $q_{reject}$?

## 4.7.2 Given a Turing Machine, Trace Its Operation on a Given String

This should be easy. In the start state reading the first symbol of the input string (reading a blank if the input string is empty). Trace the sequence of configurations of Turing Machine. At each step, show (1) state it is in, (2) position of the head, and (3) entire nonblank contents of the tape. You can draw a picture of each configuration, or use the convention of the state followed by the string (position of head), or the other convention with the state embedded in the string.

## 4.7.3 Given a Turing Machine, Describe the Language It Accepts

This can be easy or hard or essentially impossible—a lot depends on complexity of the Turing machine. The tape alphabet should be obvious (just look at labels on the arrows). Try a few sample strings, running them through the machine, then see if you can figure out the logic behind the states and arrows.

## 4.7.4 Given a Language, Write a Turing Machine That Decides (or Accepts) This Language

The authors believe that each student should write out a Turing machine or two or three or four—in order to understand their basic operation. This is often tedious, because the operations are very limited.

We recommend beginning with an English description of how the Turing machine will operate—keep this with your final machine. Think of it as comments that allow the reader to understand some hard-to-read code (i.e., the Turing machine). Then write the Turing machine diagram. Finally, run some strings through the Turing machine to be sure it is operating in the way you expect (that is, test your Turing machine).

For example, writing a machine to accept strings of odd length over {0,1} whose center character is a 1. In English: (1) find the center character (if no center character, string is even length and reject), and (2) accept if this center character is 1.

However, "find the center character" is not so easy. Probably the best way is to cross out (change to blank) one character from the left end of the string, and one character from the right end. But, if the string length 1, you just blanked the center character and have lost it—you do not know if it was 1 or not.

In modified English:

1. If the string is empty, reject.
2. Check if the string is length 1 (move right one square; if blank, length was 1). If length was 1, move back to the single character and accept if it is 1.
3. If length > 1, move to left end and blank one character; move to right end and blank out another.
4. Repeat steps 1–3 until accept or reject.
