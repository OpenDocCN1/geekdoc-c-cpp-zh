# 3.10 PROPERTIES OF O NOTATION

The following properties are useful; all are easy to prove.

+   - f is O(f) for all f.
- f is O(1) if and only if it is a bounded function.
- Constant factors can be ignored in any O calculations; that is, Kf(n) is O(f(n)) for any positive constant K.
- log_n is O(log_b n) for any bases a and b, b > 1.
- log_n n is O(n) for any base b, b > 1.
- n^k is O(b^n) for all b > 1, k ≥ 0. Thus n⁵ and n⁵¹ are both O(2^n).
- If r ≤ s, then n' is O(n').
- Any polynomial p(n) is O(the highest-order term in p). (Thus 7n⁵ + 11n² + 5n + 1111 is O(n⁵)).
- For all k > 0, k is O(f).
- Iff f is O(g) and h is O(g), then f + h is O(g).
- If f is O(h) and g is O(h), then f is O(h).
- If f is O(h₁) and g is O(h₂), then f + g is O(max(h₁, h₂)).
- If f is O(h₁) and g is O(h₂), then f-g is O(h₁-h₂).

# 3.11 FINDING O: ANALYZING AN ALGORITHM

Analyzing O for an algorithm involves making a number of assumptions and simplifications. It can be difficult. In this course, we often do not care for the best analysis—an upper bound may be sufficient. Thus, we do not care if we over steps. It is easy to find an acceptable upper bound.

Two notes: (1) As usual, unless otherwise indicated, the analysis is for the worst case, the largest number of steps on input size n, and (2) algorithms may be written in C++, Java, any language, or any reasonable pseudocode, with each instruction counted as taking one unit of time.

Each example is stated as a decision problem, that is, a problem with yes/no solution.
