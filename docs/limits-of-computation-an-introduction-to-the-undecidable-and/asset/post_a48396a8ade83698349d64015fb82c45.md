## 8.5 COMPLETNESS

Another definition is in order—one that applies to this class of problems, but also to any other class C.
This will give us a formal definition for what it means to be the hardest kind of a problem in C—to be at least as hard as any other problem in the class.

## Definition 8.11

A problem Y is “complete for the class C” or **C-complete** if:

- 1. Y is in the class C.
- 2. For any problem X in C, $X \le_p Y$.

## Definition 8.12

A problem Y is **C-hard** if for any problem X in C, $X \le_p Y$.

Thus, any C-complete problem is also C-hard. A problem can be hard without being in the appropriate class. A problem might be C-hard without even being decidable.
These definitions of *hard* and *complete* do not work well for the class **P** of decision problems with polynomial solvers. Using these definitions, every nontrivial decision problem in **P** would be **P-hard** and **P-complete** (Exercise 10). Thus, there is a more restrictive version sometimes used for this class, but we will not consider it here. See Bovet and Cresenzi (1994).

## Definition 8.13

A problem Y is NP-complete if:

- 1. Y is in the class NP.
- 2. For any problem X in NP, X \le_p Y.

## Definition 8.14

A problem Y is NP-hard if for any problem X in NP, X \le_p Y.

There are two requirements for a decision problem to be NP-complete. One must show that it satisfies both 1 and 2. Showing 1 is often easy, and both texts and students tend to neglect it—either forget to mention it or say something such as “obviously in NP,” but one must not simply ignore this constraint.

The class of NP-complete problems is important. These are the hardest problems in NP.

## 8.6 INTRACTABLE AND TRACTABLE—ONCE AGAIN

## Definition 8.15

A problem is intractable if it is NP-hard. A problem is tractable if it is in P, the class of problems with polynomial solutions.

Why these definitions? First, why consider any problem in P to be manageable or tractable or easy? Problems with high-order polynomial solutions, such as an $n^{10}$ algorithm or worse, are surely not easy to solve! There are several reasons, though, why we call $n^0$—or even higher polynomial degrees—easy. First, compared to the exponential growth, $n^0$ is not big. Second, if we defined easy problems to be bounded by small polynomials, we would first have to decide how big a polynomial could be and still be called small—$n^2, n^3$, or $n^3$—and then we would have some difficulties with the composition of problems. One easy problem is tractable composed with another easy would not necessarily be easy, since if $f(n) = n^3$ and $g(n) = n^2$, the composition of the two functions, $fg$, has order $n^6$.

If we agree on the class being the tractable or easy problems, we have the nice properties listed in the next theorem:

## Theorem 8.16

If two functions f and g are in P, then so are (1) $f(n) \cdot g(n)$, (2) $f(n) + g(n)$, and (3) $f(g(n))$.

This means that if two problems are tractable, then one can combine easy problems in all standard ways and the result is tractable.
But why are NP-hard problems not easy? Why call them intractable?
This brings us to the boundaries of computer science knowledge.

There is no known polynomial algorithm for any NP-hard problem. However, it has never been shown—and will (almost certainly) never be shown that NP-hard problems do not have polynomial solutions. The incomplete theorem of Kurt Gödel shows that any theory will have some statements that are true but never be proved, and (most) computer scientists think that the nonexistence of polynomial solutions for NP-hard problems is in this category.

In other words, it is believed that no one will find a polynomial time algorithm for any NP-hard problem. It is also believed that no one will prove that a polynomial time algorithm does not exist. The person who can do one of these—find a polynomial algorithm for some NP-hard problem or show that one cannot exist—will be immediately famous, at least in the world of theoretical computer science. See the Web site referenced in Exercise 11 at Claymath.org for a temptation to take on this problem.

If either of these is achieved, the whole theory of complexity will essentially collapse, and the phrases NP-hard and NP-complete never again be mentioned in any computer science class, except perhaps in passing to the ignorance of the ancients.

To reiterate the important points: (1) NP-hard problem has a known polynomial algorithm, but (2) we cannot show that no polynomial algorithm exists.

## 8.7 A FIRST NP-COMPLETE PROBLEM: SATISFIABILITY

So far, we have defined NP-complete and NP-hard, but have given no examples. The first example, and the proof that it is in these classes, is basic to all further discussion. Recall Boolean logic, with expressions consisting of Boolean variables, with values either true or false, connected by standard Boolean operations of negation (¬), conjunction (∧), (∨), and implies (→). For example, with three Boolean variables x, y, z, one can write many Boolean expressions such as:

```
¬(x ∧ y) → z
```

This expression is true for many assignments to x, y, z. We say that a set of assignments to the variables x, y, z that makes it true satisfies the expression. For example, x = false, y = false, z = true will satisfy the expression above. However, the expression above is not in the special form called conjunctive normal form.

## Definition 8.17

A Boolean clause is a collection of terms connected by ∨. A term (or literal) is either a single variable ($x_i$) or the negation of a single variable ($\neg x_i$).

## Definition 8.18

A Boolean expression E is in conjunctive normal form if it consists of a set of clauses $C_1, C_2, \dots, C_m$ connected by ∧.

## Fact

Any Boolean expression can be converted into conjunctive normal form.

```
¬(x ∧ y) → z == (x ∨ z) ∧ (¬y ∨ z)
```

Clause list:

## Fact

An expression in conjunctive normal form (CNF) is true if and only if each of its clauses is true. Thus, some texts do not speak of an expression in conjunctive normal form; instead, they speak of a set of clauses that all have to be satisfied.

Decision problem: CNF satisfiability (abbreviated CNF-SAT).
Instance: A Boolean expression E over variables $x_1, \dots, x_n$ in conjunctive normal form.
Question: Is there an assignment of true values to the variables $x_1, \dots, x_n$, such that E is true?

This is our first NP-complete problem. The theorem is easily stated; the main part of the proof is the next section of the text, but the proof begins below.

## Theorem 8.19

(Cook-Levin) CNF-SAT is in NP.

Clearly, CNF-SAT is a decision problem. It is trivial to find yes and no instances—one can do so with $n=1$ and the single Boolean variable $x_1$. (Yes instances: $x_1, x_1 \vee \neg x_1$; no instance: 14a).

Claim: CNF-SAT is in NP.

A certificate for CNF-SAT is the assignment of true and false to the variables that satisfy the expression—make the expression true, or equivalently, make every clause true. We do not have to find the certificate—we guess it (omnipotently, omniscly) or it is simply handed to us. We do have to show that we can verify that this assignment of truth values makes the whole expression true, and the verification is bounded by time polynomial in the length of the input.

If we want to be very precise, we will have to spend a lot detail encoding the input and measuring its length. Suppose

```
E = C1 ∧ C2 ∧ C3 ... Cm, each Ci a clause containing some of x1, ..., xn
```

We can imagine a Turing machine with input alphabet $\Sigma = \{x, 0, 1, \dots, 9, ∧, ∨, (, )\}$. (Aside: All of symbols are not necessarily. We can eliminate the x and some of the logical symbols, and the parentheses (). How? Can we rewrite decimal in binary, to eliminate 2, ..., 9).

The Turing machine would begin with the certificate (a string of length n of 0's and 1's for the values, false or true, for the $x_1, \dots, x_{50}$), followed by the expression itself. One could encode $x_{59} \lor x_{67}$ as $x_{59} \neg x_{67}$, or just as $59 \lor \neg 67$ for the expression $(x_1 \land x_3 \land x_5) \land (\neg x_2 \lor x_4 \lor x_1) \land \neg(x_1 \lor x_4 \land x_3)$ with $x_1, x_2$ and $x_3$ true, and $x_4$ and $x_5$ false, might be encoded as:

```
11001(x_1 ∨ x_3 ∨ x_5) ∧ (¬ x_2 ∨ x_4 ∨ x_1) ∧ (¬ x_1 ∨ x_4 ∧ ¬(x_1))
```

which has 45 characters, but it could be encoded in other ways with fewer characters.

It might be easiest to begin by copying the certificate to a second tape. One approach would be to make $n$ passes across the expression. At the $i$-th pass, the machine would look at the value (true or false) and mark any true clause containing $x$ (if true) and $\neg x$ (if false). After $n$ passes, the expression is true if all clauses are marked true. Getting the true assignment for $x$ would take less than $n$ steps; making a pass over the expression would take less than $|E|$ steps, and is done $n$ times, so the entire procedure would take less than $n|E|$ steps.

The quantities, $n, m$, and $|E|$ are related. For interesting cases, $n$ is much less than $|E|$, although it would be possible to have an expression over many variables where only a few of them appeared at all. It is left as an exercise to explore in more detail the relationship between $n$ and $|E|$.
