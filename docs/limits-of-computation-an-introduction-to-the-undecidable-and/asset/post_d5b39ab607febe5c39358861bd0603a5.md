# Example

Sam sees some movies; Ann is a movie critic and sees every movie that comes out. Moreover, her taste exactly agrees with Sam's. If Sam likes a movie, so does Ann; if Sam does not like a movie, Ann does not like it either.

Question 1: We are told that Sam saw movie X. Did he like it (yes/no)?
Question 2: What did Ann think of movie X (Does she like it? yes/no)?

When is a problem harder (or more precisely, as hard or harder) than some other problem? We would surely say that Y is harder than X if knowing the solution to Y would give us the answer (yes or no) to X.

For example, in mathematics, you might want to know if a particular third degree polynomial has an integer root. Your book has an algorithm that works for all polynomials of degree up to 4. So this algorithm would also work for your third degree polynomial. That is, obviously, the prob "integer root of polynomial of degree up to 4" is harder than the same problem with degree to 3.

And clearly, an answer to a question about all polygons would answer a question about quadrilaterals.

The key here is that there is a mapping from one problem to another, and that yes answers of the first to yes answers of the second, while no's of the first becomes no's of the second. Instead of asking the question about the original problem, we only need to ask it for the second. Yes of the second means yes of the first, no means of the first. Answering the second question gives you a two-for-one bonus; you get answers to both problems.

Note that an answer to the first problem gives no bonus; you cannot (necessarily) get all the answers to problem 2 from problem 1. You can get some answers to problem—2 of problem 2, so by following the mapping, you get an answer for that instance of problem 2. If the mapping were onto, that is, if every instance of problem 2 were an image of something from problem 1, and the mapping $P_1$ to $P_2$ had an inverse mapping, then the problems would be equivalent (and answering either would answer both).

# 7.2 REDUCIBILITY

Definition 7.1

Suppose $P_1$ and $P_2$ are decision problems. Then $P_1$ is **reducible** to $P_2$, written $P_1 \leq P_2$, if there is a mapping $f$ from all possible instances (yes or no) of $P_1$ to possible instances of $P_2$ such that:

- 1. $f$ is computable (that is, some Turing machine—or transducer—can compute).
- 2. If $X$ is a yes instance of $P_1$, then $f(X)$ is a yes instance of $P_2$.
- 3. If $X$ is a no instance of $P_1$, then $f(X)$ is a no instance of $P_2$.

Note that 3 can be rewritten equivalently as:

3'. If $f(X)$ is a yes instance of $P_2$, then $X$ is a yes instance of $P_1$

since 3' is the contrapositive of 3. That is, “no goes to no” is equivalent to “yes comes from yes.” This second form is often easier to use in proofs.

This mapping can be visualized; see Figure 7.1.

Conditions 2 and 3 say that answering $P_2$ will also answer $P_1$. That is, if one looks at $f(X)$ and answers it is a yes (or no) instance of $P_2$, then it immediately follows that $X$ was a yes (or no) instance of $P_1$.

Be careful; as was as said before, nothing is said that answering $P_1$ will also answer $P_2$. The mapping must be defined on all instances of $P_1$—both yes and—but there may be many instances of $P_2$ that are not related to anything in $P_1$.

Note on the name for: Despite the best efforts of Donald Knuth, who did succeed in standardizing the terms NP-hard and NP-complete (see the next chapter), there are various terms used for what we have defined as reducible. Emil Post, in 1944, called this "many-one reducible" since the mapping may take many instances from $P_1$ to a single instance of $P_2$. Some authors use "mapping reducible"; others do not use a function. Instead, they speak of constructing a yes/no instance of $P_2$ from an instance of $P_1$.

There are other kinds of reducibility. If we add the requirement that the function calculated in polynomial time, we get "polynomial time mapping". We will find this definition very important in Chapters 8 through 10.

# Definition 7.2

A decision problem $P_1$ is polynomially reducible to decision problem $P_2$, written $P_1 \leq_p P_2$, if there is a mapping $f$ from possible instances (yes or no) of $P_1$ to possible instances of $P_2$, such that:

- 1. For any yes/no instance X of $P_1$, $f(X)$ can be computed by a Turing machine (transducer) in time bounded by a polynomial $p(|X|), |X|$ = length of the input.
- 2. If X is a yes instance of $P_1$, then $f(X)$ is a yes instance of $P_2$.
- 3. If X is no instance of $P_1$, then $f(X)$ is a no instance of $P_2$.

The only difference between definitions 7.1 and 7.2 is the addition of the restriction that the function can be computed in polynomial time.

Turing reducibility is a slightly different and more general concept in which the answer to the right-hand problem can be used to answer the left-hand problem. It is not used in this text. Log space reducibility is another different and more restrictive reducibility in which the function $f$ is only allowed to use a work space that is bounded by a constant times the log of the input size.

It would be tempting to think that answering $P_1$ would also answer $P_2$. That would be the case for yes or no instances that are in the range of $f$—that is, they come from something in $P_1$. Thus, in the two instances above, an answer to temperature too high will answer whether the warning light is on. An answer to raining/not raining will answer whether Professor Jones has an umbrella or not. In these two cases, the mapping is onto, or surjective, but the range is very small—{warning light on, warning light off} and (Jones has umbrella).

The mapping from the movies Sam sees to those that Ann sees is not onto. We need to assume Ann sees any movie that Sam has seen (otherwise, the domain of the function is too small), but if the movie is not seen, we cannot tell what Ann thought. Figure 7.1 demonstrates these ideas.

# 7.3 REDUCIBILITY AND LANGUAGE PROPERTIES

If you know something about one language $L_1$ and know it is related to another language $L_2$ by reducibility, then some properties follow. These include:

# Theorem 7.3
If $L_1 \le L_2$ and $L_2$ is decidable, then so is $L_1$.

# Theorem 7.4
If $L_1 \le L_2$ and $L_1$ is undecidable, then so is $L_2$.

# Theorem 7.5
If $L_1 \le L_2$, then $\overline{L_1} \le \overline{L_2}$.

# Theorem 7.6
If $L_1 \le L_2$ and $L_2 \le L_3$, then $L_1 \le L_3$.

# 7.4 REDUCIBILITY TO SHOW UNDECIDABILITY

So far, it has been proved that the problem ACCEPT$_{TM}$={<M,w>} M and w are encoded Turing machines and strings, and M accepts w is undecidable. For a different problem, we will be able to show P is undecidable by finding a mapping from ACCEPT$_{TM}$ to P.

There is fairly standard procedure for building this mapping from ACCEPT$_{TM}$ to P.

- 1. Build a yes/no instance L' = L(M') of P. M' will be a Turing machine with input x' over some alphabet Σ'. How do we build this and what Σ' is? One thing that almost never varies is that M' has M and w built into it—that is, M' depends on M and w, or M' has M and w hard-coded into it. How one actually would build M into M' is not important. It would take a lot of time and effort to actually do this, but it is not hard to see that it can be done.

- 2. The trick is to build M' so that the language it accepts is one of two different languages, one that is a yes instance of P and one that is no instance. Whether it is a yes or no instance should depend on whether M accepts w or not. There are times M' must look at its input and possibly accept before it runs on w. However, that is not the usual case.

- 3. Usual to build M':

First, run M on w. In doing this, three things could happen: (a) M accepts w, (b) M rejects w, or (c) M is looping on w, and has not—and will not—ever accept or reject.
