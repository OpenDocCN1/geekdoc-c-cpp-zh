A subtle assumption is made, and you should be questioning why one can encode |V| = n in the above expression 1 + 2|E| in one character. not, and a better (and very close) estimate would be the smallest integer greater than log₁₀|V|. If for example, the graph had 7285 nodes, and one was using decimal, it would take a length of 4 to encode |V|. log₁₀ n is much smaller than n, and is essentially treated as a small constant and ignored.

So, was a good estimate for the size of |G| in whatever encoding? Certainly, 0 ≤ |E| ≤ n(n-1) < n², where |V| = n. Any “interesting” graph has more than a few edges. Thus, we will generally take n² as the size of the encoding of G. To prove something is in NP-complete, we will have to show that there is a certificate that is polynomial in O(n²)—or, if we want to use the other characterization, that there is an NDTM of polynomial order in n². Note, that a function is polynomial in n² if and only if it is polynomial in n (a higher order in n, of course, but all we care about is a polynomial bound). Thus, we will often look for polynomial in n = |V|, although that is not exactly the size of |G|
