This algorithm is bounded by $2\sqrt{p}$ (and will take many iterations when p is prime). Therefore, it would be tempting to say that the algorithm is better than polynomial, since it runs in $O(p^{1/5})$ iterations. But there is a fallacy in this thinking. It runs in $p^{1/5}$, but this is not polynomial in the length of the input, as is required in the definition of the class **P**. The length of the input is the number of digits in p, or, the ceiling of log p $\log_{10}p$, that is

```
$p^{1/2} = 10^{5\log p}=constant*sizeinput$
```

Thus, it is really exponentially in the size of the input. This distinction—an algorithm that is polynomial in *some part* of the input, but not the size or length of the input—appears in several **NP**-complete problems. A polynomial algorithm for PRIME has been found (Agrawal et al., 2004), but it is much more complex than the above algorithm.

Another interest we have shown to be **NP**-complete. Recall this problem of a multiset (a set with repeatedly repeated elements) of $n$ integers, $S = \{I_1, ..., I_n\}$ and a target $T$. The question is, can one choose subset of the integers $S' = \{I_{k_1}, ..., I_{k_j}\}$ so that the sum of the integers in $S'$ is $T?

This problem has an interesting dynamic programming algorithm. Dynamic programming algorithms are those that are based on saving solutions to parts of the problem and building on these, combining into a whole solution.

One dynamic programming algorithm for Subset Sum is based on the construction of an $n \times (T+1)$ table. The rows are labeled by the $I_1, ..., I_n$, the columns from 0 to $T$. Each table$[i, j]$ will be TRUE if the $j$th number can be made a sum of the first $i$, ..., $I_n$. All entries are initialized to FALSE.
