can help. This function has one argument (a character); it returns true if its argument is one of the white space characters. With this in mind, we can skip any initial white space with this loop:

```
while (ins && !isspace(ins.peek()))
    ins.ignore();
```

+   ins, peek, ignore The loop also uses three iostream features:
+   
+   1. In a boolean expression, the name of the istream (which is ins) acts as a test of whether the input stream is bad. If ins results in a true value, then the stream is okay; a false value indicates a bad input stream.
+   
+   2. The peek member function returns the next character to be read (without actually reading it).
+   
+   3. The ignore member function reads and discards the next character.

After skipping the initial white space, your implementation should set the string to the empty string, and then read the input characters one at a time, adding each character to the end of the string. The reading stops when you reach more white space (or the end of the file).

Once the target string reaches its current capacity, our approach continues to work correctly, although it is inefficient because target is probably resized by the += operator each time that we add another character. Your documentation should warn programmers of this inefficiency so that a programmer can explicitly resize the target before calling the input operator.

An alternative method of reading input is provided by the getline function.
