# 12.3 CHAINED HASHING

In open-address hashing, a collision is handled by probing the array for an unused position. Each array component can hold just one entry. When the array is full, no more items can be added to the table. We could handle this problem by resizing the array and rehashing all the entries, placing each entry in a new, larger array. But this would require a careful choice of the new size and probably would require each entry to have a new hash value computed. Another approach is to use a different collision resolution method called chained hashing.

**In chained hashing**, also called **chaining**, each component of the hash table's array can hold more than one entry. As with all hashing, we still hash the key of each entry to obtain an array index. But if there is a collision, we don't worry too much. We simply place the new entry in its proper array component along with other entries that happened to hash to the same array index.

How does chaining place more than one entry in each component of the array?

The answer is that each array component must have some underlying structure. The most common structure that you will see for the array's components is to have each data[i] be a head pointer for a linked list.
