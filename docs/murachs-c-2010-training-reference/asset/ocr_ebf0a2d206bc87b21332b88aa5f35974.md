# What happens when two users try to update the same row

+   - When two or more users retrieve the data in the same row of a database table at the same time

# How to avoid concurrency errors

+   - For many applications, concurrency errors rarely occur. As a result, optimistic concurrency is adequate because the users will rarely resubmit an update or deletion that is refused.
- If concurrency is likely to be a problem, a program that uses a dataset can be designed so it updates and refreshes the database frequently. That way, concurrency errors are less likely to occur.
- Another way to avoid concurrency errors is to design a program so it retrieves and updates just one row at a time. That way, there's less chance that two users will retrieve and update the same row at the same time.
