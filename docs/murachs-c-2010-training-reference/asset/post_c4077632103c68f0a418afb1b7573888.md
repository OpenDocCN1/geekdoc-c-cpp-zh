# How to install an application from a web page

Once you publish an application, users can install it by displaying the generated web page in a browser. For example, figure 25-7 shows the web page that was generated for the application you saw in the previous figures. To install an application from this, the user simply clicks the Install button.

Depending on the options you select before publishing an application, the web page that's generated may look different than the one shown here. If, for example, the application is only available online, the page will include a Run button instead of an Install button. And if prerequisites other than the .NET Framework and Windows Installer are required, the page will list all the prerequisites. In addition, it will include a link that lets users skip the prerequisites if they're sure the required components are already installed on their computers.

When the user installs or runs the application, Launching Application dialog is displayed. Then, if the application doesn't come from a trusted source, a dialog box with a security warning is displayed. Before you publish the final release of an application, you'll want to eliminate this warning by installing a valid certificate for the publisher of the application. If the application is published to a server on an intranet, you may be able to use Microsoft Certificate services that comes with Windows Server 2008 to create your own certificate. If the application is published to a server on the Internet, you'll need to get a certificate from a certification authority such as VeriSign. For more information about certification authorities, you can search the Internet for “certification authorities” and “code signing certificate.”

# How to update an application

Figure 25-7 also shows the dialog box that's displayed when a user runs an application that was deployed using ClickOnce and an update is available. From this dialog box, the user can click the OK button to install the update or the Skip button to skip the installation. Note that if the update options for the application specify a minimum required version and the user doesn't have that version installed, the Update Available dialog isn't displayed. Instead, the update is installed automatically.

# How to create and use a Setup program

If XCopy or ClickOnce deployment isn't adequate for your application, you can create a Setup project that creates a Setup program that the user can run to install the application. This approach can be used for installing all but the most complex applications. However, creating a Setup program can be a complex process itself that varies widely from one application to another. As a result, the topics that follow are designed to give you a general idea of how to create a Setup program. Then, if necessary, you can do some additional research before creating your own Setup programs.

# How to create a Setup project

Figure 25-8 shows how to create a Setup project for a Windows application. To do that, you start by opening the solution for the project that contains the Windows application that you want to deploy. Then, use the Add New Project dialog box shown in this figure to add a Setup project for the application to that solution. # The Add New Project dialog box for a Setup project

![](img/3148667e42d4db35b3d08576aaa1fa01_790_0.png)

## Description

- You use a Setup project to create a Setup program that installs a Windows application. A Setup program is a type of Windows application that's used to install other Windows applications.
- To create a Setup project, open the solution that contains the Windows application that you want to deploy, and choose the File→Add→New Project. Then, expand Other Project Types, select Deployment, select the Setup template, enter a name for the Setup, and click OK.
- When you create a Setup project, it is added to the solution that you want to create.

## Express limitation

- Visual Studio 2010 Express Edition doesn't provide Setup projects.

# How to add output files to a Setup project

Once you create a Setup project, you can use the setup editors it provides to customize the project. To start, you'll want to add any output files you want the Setup program to deploy. Figure 25-9 shows how to do that.

To add output files to a Setup project, you use the File System Editor shown in this figure. This editor is displayed by default when you create a Setup project. In the left pane of this editor, you can see three folders that represent the folder where applications are installed on the user's system, the folder that contains the items that are displayed on the user's desktop, and the folder that contains the items that are displayed in the user's Programs menu. For complex applications, you can include special folders and custom folders. For simple applications, though, you'll use just the default folders and any subfolders you create.

A Setup project must include at least the primary output for the project, which is the exe file for a Windows application. In most cases, you'll add this file to the Application Folder. Then, when you select this folder, the file will appear in the right pane of the File System Editor as shown in this figure. To add a Readme file or a database file that's used by the application to add the primary output to the Application Folder, right-click on the folder, select the Add→Project Output command, and use the Project Output dialog box.

You can also use the Add menu to add files to a Setup project. For example, you might want to add a Readme file or a database file to the application. To do that, select the File command and identify the file.

Another common file that you'll include in a Setup project is a shortcut to the application. When the application is installed, for example, you may want a shortcut to be added to the user's desktop or Programs menu. To create a shortcut, right-click on the file that you want to create a shortcut to and select the Create Shortcut command. Then, the shortcut is created in the same folder as the file it was created from. At that point, you can give the shortcut an appropriate name and move it to the folder where you want it to appear on the user's computer.

For example, suppose you want a shortcut to the Future Value application to appear in the user's All Programs→Murach menu. To accomplish that, you start by adding a sub named Murach to the User's Programs Menu folder using the Add→Folder command. Then, you create and name the shortcut as described above and move it to the Murach subfolder.
