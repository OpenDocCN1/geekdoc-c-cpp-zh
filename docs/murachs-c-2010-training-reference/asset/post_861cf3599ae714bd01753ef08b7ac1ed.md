
## How to create a class library project

To create a class library project, you use the Class Library template that's available from the New Project dialog box. After you complete this dialog box, Visual Studio creates a class library project that consists of a single named Class1. Then, you can enter the code for this class and create additional classes using the techniques you've already learned. Or, if the classes you want to place in the library already exist in other projects, you can delete the Class1.cs file and use the Project→Add Existing Item command to copy the classes into the class library project.

16-7 shows a class library project named ValidationLibrary that includes a class named Validator. This that was presented in table 12. In this case, the class is stored in a class library project instead of the Windows project that it uses.

Notice the name of the namespace for this class. When you place classes in a class library, you should create a namespace that indicates the purpose of the classes in the namespace. In this case, I created a namespace Murach.Validation.

Before I go on, you should realize that if the classes in your class library access to namespaces other than the System namespace, you'll need to add a reference to the assembly that contains those classes. You'll learn the details of adding references in the next figure. For now, just realize that the Validator uses the MessageBox class in the System.Forms namespace. Because of that, a reference to this namespace was added to the ValidationLibrary class library.

When you're designing a class library, you build it to create an assembly. The assembly for a class library is a DLL file, or just DLL. This is a file with the dll extension that contains the executable code for the class library. By default, this file includes debugging information and is stored in the Debug folder beneath the project folder for the project. Because you don't want the final version of a class library to include debugging information, you'll want to create a DLL file without this information when you're done testing the class library. To do that, you change the solution configuration from Debug to Release. Then, the DLL is stored in the binRelease folder, and you can include a reference to this file in other projects as described in the next text.

As you're developing a class library, it's often useful to create the class library as a project that also has a Windows Forms project. That way, you can use the Windows Forms project to test the class library. To add a new class library project to an existing solution, right-click the solution in the Solution Explorer, choose Add→New Project... existing class library project to a solution by choosing Add→Existing Project. If you do that, though, keep in mind that you're working with the original class library project, not a copy of it. So any changes you make affect the original class library.

## How to add a reference to a class library

Figure 16-8 shows how to add a reference to a class library so you can use its classes in an application. To add a reference to a class library in a project, you can use the Add Reference dialog box. From this dialog box, you can click the Browse to locate the DLL file for the class library you want to refer to. Then, when you select that file and click the OK button, a reference to this file is added to the References folder in the Solution Explorer. Then, you can use the classes in the referenced class library.

If you have created a class library as a project in the same solution with a Windows Forms application, you can add a reference to the class library by selecting the project from the Projects tab of the Add Reference dialog box instead of locating the DLL for the project. Then, when you have the application working the way you want it to, you can remove the class library project from the solution and add a reference to the DLL file for this project.
