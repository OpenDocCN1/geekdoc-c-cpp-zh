## Description

- When we first create a Setup project, the File System Editor is displayed. You can use this editor to add files to the Setup project.
- To add project output, as the exe file for the application, to the setup project, right-click on the appropriate folder in the File System window and choose the Add→Project Output command to display the Add Project Output dialog box. Then, select the output that you want to add and click OK.
- To add additional files, such as a Read or database file, to the setup project, right-click on a folder in the File System window, choose the Add→File command, and then locate and select the file.
- To add a shortcut to the application to the user's desktop or Start menu when the application is installed, right-click on the Primary Output item and select the Create Shortcut command. Then, name the shortcut and move it to the User's Desktop or User's Programs folder.
- Visual Studio provides five editors in addition to the File System Editor that let you customize a Setup project. To display these editors, select the Setup project in the Solution Explorer and then use the buttons that are displayed at the top of the Solution Explorer. See figure 25-10 for more information on these editors.

## How to complete a Setup project

In addition to the File System Editor, five other editors are available for working with a Setup project. You can display these editors using the buttons that appear at the top of the Solution Explorer when you select the Setup project. These editors provide a variety of features for customizing a Setup project summarized in 25-10. For example, you can use the Registry Editor to specify the keys and values that should be added to the user's computer. And you can use the File Types Editor to establish an association between the files used by your application and the application.

The User Interface Editor lets you customize the dialog boxes that are displayed when you run the Setup project to install the application. For example, you can change the BannerBitmap property of any dialog box to display your company's logo in that dialog box. You can also change the text that's displayed in the dialog boxes, and you can add your own dialog boxes to those that are displayed by the Setup project.

The Custom Actions Editor lets you specify actions that are performed on the user's computer at the end of the install, commit, or uninstall phase. Visual Studio provides five predefined actions: the Event Log, Message Queue, Performance Counter, and Service. In addition, you can create your custom actions by developing a program or component. Note, however, a custom action can be difficult to develop.

Finally, Launch Conditions lets you set conditions that must be met before the application can be installed. For example, you can use a launch condition to check the operating system version or to see if a particular file exists on the computer. Then, if the condition isn't met, the Setup program aborts the installation.

Besides the setup editors, you can set the properties of the Setup project to customize the project. Of these properties, Manufacturer and ProductName are two of the most important ones. Because they are used to construct the path for the default installation folder as you see in the next figure, if you want to install another version of the application, you'll also need to change the version for the application you're installing. To do that, display the Project Properties window and enter a new version.

When you complete a Setup project, it builds to generate the files that will be used to install the application. This includes a Setup.msi file that contains the application and any required files and information, as well as a Setup.exe file that the user can execute to run the installer. By default, these files are stored in the Release directory within the project directory. If you want, you can change the path from the Properties dialog box for the project.

## The Setup editors for customizing a Setup project

| Editor | Description |
| :--- | :--- |
| File System Editor | Lets you specify the project outputs, files, and other items you want to include in the setup project and where they will be installed on the target computer. See figure 25-9 for more information. |
| Registry Editor | Lets you specify the registry keys and values that will be added to the registry on the target computer. |
| File Types Editor | Lets you specify the file types and file extensions that will be associated with your application when it's installed on the target computer. |
| User Interface Editor | Lets you customize the dialog boxes that are displayed when you run the Setup program. |
| Custom Actions Editor | Lets you specify additional actions that will be performed on the target computer at the end of various phases of the installation. |
| Launch Conditions Editor | Lets you specify conditions that must be met before an application can be installed. |

## Common properties of a Setup project

| Property | Description |
| :--- | :--- |
| Manufacturer | The name of the manufacturer of the application. This property is used as part of the default installation path. |
| ProductName | The name of the product. This property is used in the dialog boxes displayed by the Setup program and as part of the default installation path. |
| ProductCode | A unique identifier for an application that should vary for each version of the application. |
| Version | The version number of a Setup program. If you change this property, you should also change the ProductCode property. |
| RemovePreviousVersions | Determines which previous versions of the application are removed before the current version is installed. |

## Description

- The Manufacturer and ProductName properties are also displayed in the Uninstall or Change a Program window (Windows 7 and Windows Vista) or the Support Info dialog box that is available from the Add or Remove Programs window (Windows XP). Other properties listed above provide information for this window and dialog box.
- To build a Setup project, select the Release option from the Configuration combo box in the Standard toolbar, select the project in the Solution Explorer, and choose the Build Project command. This creates a Windows installer (Setup.msi) file that contains any deployment files, information about the application, and installation instructions, as well as a Setup.exe file that can be used to run the installer.
- By default, the msi and exe files for a Setup project are stored in the Release directory that's subordinate to the project directory. To store these files in another directory, select the project in the Solution Explorer, select the Project→Properties command, and set the path in the Output File name.

## How to use a Setup program to install an application

When the user double-clicks on the exe file for a Setup program, a standard setup wizard like the one shown in figure 25-11 is displayed. If you have installed a Windows application before, you should already be familiar with this type of wizard. Although this figure shows only the first two steps of the setup, these are two of the most important steps.

The first step displays the default welcome message and the default copyright warning. If you want to change the text of either of these, you can use the User Interface Editor. In addition, the ProductName property of the Setup project is displayed in the title bar of this wizard. If you want to change this, you can change the ProductName property of the Setup project.

The second step displays the default installation folder for the application. As I mentioned earlier, this folder is constructed by combining the application's manufacturer and a folder that has the name of the product. However, this is just a suggested folder, so the user can select another folder.

After the user completes these steps, the next three steps let the user confirm the installation, display the progress of the installation, and display a message when the installation has been completed. Although these steps aren't shown in this figure, you've probably seen these steps when you've installed other Windows applications. If necessary, you can use the User Interface Editor to control the appearance of these steps. Or, you can use this editor to add steps such as a step that displays a license agreement or registers a user.
