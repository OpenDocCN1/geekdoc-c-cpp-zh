### Description

- The Call Hierarchy window displays calls to and from methods, properties, and constructors using this. To display this window, use the View Hierarchy command. You can display this window at design-time and at runtime.
- To add a method, property, or constructor to the Call Hierarchy, right-click on that member and choose View Hierarchy from the menu. This also opens the Call Hierarchy window if it isn’t already open.
- To display the calls to from a member, click the ▷ in the tree pane. To hide the calls ◁.
- To display the locations of calls to from a member in the details pane on the right side of the Call Hierarchy window, click the member in the tree view.
- To jump to the location of a member in the Code Editor, double-click it in the tree view of the Call Hierarchy window. To jump to the location of a call, double-click it in the details pane.
- To remove a member from the Call Hierarchy, select the root for that member and then click the Remove button at the top of the window.
- You use the drop-down list at the top of the Call Hierarchy window to select whether calls in the current project, or the solution are displayed.

### How to view the Output window to view project information

11-11 shows how to use the Output window. You can display this by selecting the Output command from the Debug submenu. By default, this window is displayed in the lower group of windows. Although you can display this window when you enter break mode, you can also display this window before and after break mode.

This figure shows two types of information that are displayed in the Output window when it is displayed before after break mode. The first screen shows the debug output that automatically displayed in the Output window after application finishes. Here, the window identifies the files that were loaded and used by the application. These files include the .NET Framework library, the executable file for the project, and other files required by the project. Then, the Output window displays some information that an unhandled exception occurred.

The second screen, you can see the output that is displayed after a project has been built. The output indicates the progress and result of the build. In this case, a single project was built and the build was successful. If you run a project, it is automatically built before. However, to display it, you must select the Build item from the combo box that is at the top of the Output window. On the other hand, if you build solution by selecting one of the Build commands from the menu, the Output window will automatically select the Build option and show this information.

Most of the time, you won't need the information that is displayed in the Output window. If a build error occurs, for example the error is displayed in the Error List window and you can use that window to locate and correct the error. And if an unhandled exception occurs, you can use the information in the Exception window to identify the cause of the exception. Of course, once you exit break mode, the Exception is no longer available. However, some information about the exception is still available in the Output window. As a result, you can use the Output window to look up this information even after you've exited break mode.

### How to write data to the Output window

In some cases, it makes sense to use the methods of the Console class to write debugging information to the Output window. This can be useful for tracing the execution of an application or documenting the changing value of a property or variable. The only problem is that your debugging information is mixed with the other debugging information. The advantage of writing information to the Output window is that it remains available even when the application is no longer in break mode. As a result, you can display the Output window and review this information after the application has finished running.

To display information in the Output window, you can use the methods of the Console class to write any string. This is summarized in figure 11-12. Most of the time, you will use the WriteLine method because it automatically adds a line to the end of the string. When the next one of these methods is executed, the information is displayed on the next line. However, if you don't want to end the string with a line break, you can use the Write method.

The first example in this figure uses the WriteLine method to write data to the Output window. Here, the first statement displays a string value that indicates the CalculateFuture statements display the values for the month and future value for the month. Since the month is a multiple of 12, you can use the modulus operator (%) to check the month.

### How to use the Visualizer dialog boxes to view strings

Visual Studio includes some dialog boxes that can display the result of a string in a way that is easy for you to visualize. This feature works consistently across all of the debugging windows described in this chapter, and it works with strings that contain plain text, HTML, or XML.

In 11-13, the Locals window contains a variable named calculationsString that contains a string that represents one or more calculations. Since this is a string, the Visualizer icon (a magnifying glass) is displayed to the right of the value that's displayed in the Value column. Then, You can use the drop-down list that's available from this icon to display the string in the Text, XML, or HTML dialog box. Since this particular string contains plain text, this figure shows the Text Visualizer command being selected.

To help understand how useful the Visualizer dialog boxes can be, take a moment to consider what the string in this figure would look like without the Text Visualizer dialog box. It would look like this (without the word wrapping):

"Monthly Investment: $100.00\nYearly Interest Rate: $3.00\nYears: $3\nFuture Value: $771.46\n\n"

The HTML and XML Visualizer dialog boxes work like the Text Visualizer dialog box, except that they are designed to work with HTML or XML. As a result, if a string contains an HTML or XML document, you'll probably want to use these dialog boxes. Then, the HTML or XML document will be displayed in a user-friendly format.
