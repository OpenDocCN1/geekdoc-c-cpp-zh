# How to deploy database applications

If the application that you want to deploy works with a database, you need to make sure that each user has access to that database. The technique for doing that depends on where the database will be stored and which deployment technique you're using. In the two topics that follow, you'll learn how to deploy applications that work with databases on both network servers and local systems. And you'll learn how to do that using both ClickOnce deployment and a Setup server.

# Using ClickOnce deployment

If you've developed an application for a group of users who are connected to a LAN, you'll need to store the database on a network server. Then, you need to set the connection string in your application so it points to that. This is illustrated in the first connection string shown in figure 25-12. This connection string refers to a database named MMABooks running on a SQL Server Express database on network server named DBSERVER.

In addition to setting the connection string, you need to make sure that all users have adequate permissions to access the database. If you need help doing that, you should contact the network administrator.

If you've developed an application that's designed for an individual user, you'll need to store the database on the user's computer. To do that, you need to add the database file to the project. The best time to do that is when you're developing the project (see figure 18-2 in chapter 18). Then, when you create a data source from this database, Visual Studio will generate a connection string like the one shown in this figure. Otherwise, if you create a data source for a database that stays outside the project, Visual Studio will generate a connection string similar to the first one in this figure. In that case, before you deploy the application, you'll need to add the database to the project and then change the connection string to look like the one.

This connection string attaches the database file in the directory specified by DataDirectory to the instance of SQL Server Express. By default, DataDirectory points to the directory that contains the output file for the project, which is usually the binDebug folder within the project folder. You may remember from chapter 18 that Visual Studio copies the database file to this folder when you run the application. When you deploy the application, DataDirectory points to a special directory that's created to hold the database.
