# How to generate code stubs

In addition to the skills you learned for creating classes, you can use a new feature of Visual Studio 2010 called Generate From Usage to generate code stubs for a class and its members. This feature can help you quickly generate the starting code for a class from the code that uses the class. Then, you can enhance the code for the later as needed.

Figure 2-11 how the Generate From Usage feature works. In the first screen shown here, you can see that I declared a variable named product from a class named Product. Because the Product class didn't exist, though, Visual Studio marked it as a syntax error. Then, I used the Generate Class Command in the smart tag menu for the class to generate the class. The second screen is similar, but in this case, I generated a stub for a method named GetPrice.

This figure also shows the code that was generated for the class and method. The code for the class simply consists of the class declaration. The code for the method consists of the method declaration and a single statement. That statement throws an exception indicating that the method hasn't been implemented. Then, you can replace this statement with the code that implements the method.

Notice that this method stub uses the internal access specifier. This access specifier restricts access to the method to the current C# assembly. You'll learn more about this access specifier in 14.

Also notice that because the statement calling the GetPrice assigns the return value to a decimal variable, the method returns a decimal value. The method is defined with a string parameter. In this case, the generic name p is given to the parameter. If I had passed a variable instead of literal to the method, however, the parameter would have been the same name as the variable.

Instead of automatically generating a class declaration from the one in the first example, you can use the second link in the Generate options list to display the New Type dialog box. You can use this dialog box to specify the code you want to generate. For example, you can use it to specify a different access modifier for the class. You can also use it to generate an enumeration, structure, or interface instead of a class. Although this dialog box isn't shown here, you shouldn't have any trouble using it. By the way, you'll learn about structures later in this chapter, and you'll learn about interfaces in chapter 15.

In most cases use IntelliSense's standard completion mode to enter the name of a class or member. When you use this mode, the first item in the completion list that contains the letters you type is highlighted. Then, you can insert that item into your code by entering the next character in the statement, such as a period or parenthesis, or by pressing the Tab or Enter key.

When you enter the name of an undefined class or member, you may want to use suggestion mode rather than completion mode. In this mode, the completion list is displayed, but the current item is outlined rather than highlighted. Then, to commit the name you typed, you enter the next character in the statement or press the Enter key. This helps IntelliSense from inserting unwanted text.
