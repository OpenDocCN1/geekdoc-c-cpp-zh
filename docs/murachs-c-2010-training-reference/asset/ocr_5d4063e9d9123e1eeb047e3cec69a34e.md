# The code for the form

Figure 23-11 presents the code for the Customer Invoice form that uses the typed dataset you saw in the previous figure. Unlike the applications you saw in chapters 18 and 19, this application doesn't use any bound controls. Because of that, it uses code to create instances of the typed dataset and the Customers and Invoices table adapters that were generated by the Data Source Configuration Wizard. The three classes used by this form store these instances. Note that because the classes that define the table adapters are stored in a separate namespace a statement has been included for that namespace (it's not shown here). That makes it easier to refer to the table adapters in the variable declarations.

The first two statements event handler load data into the Invoices and Customers tables. To do that, you use the Fill method of the table adapters for these tables. This method executes the Select statement that's associated with the table adapter retrieve data from the database.

After that, the query expression joins the data in the Invoices and Customers, sorts it by invoice total in descending sequence within customer name, and selects the columns needed by the application. If you compare this query expression with the one used by the application that queries generic lists, you'll see that they're almost identical. The only difference is that the data sources in this query expression name the two data tables. This illustrates how similar query expressions work with different data sources can.

Now that you've seen two applications that use LINQ with two types of data sources, you might want to consider how you would accomplish the same without using LINQ. If you do, you'll see that LINQ makes it quick and easy to select the data you need.

To join data two generic lists without using LINQ, for example, you could include code that loops through one list looking for the object that's related to the object in the other list. And to join data from two tables of a dataset, you could use a relationship. In contrast, to join data from any two data sources using LINQ, you can simply code a join clause.

Similarly, to sort the data in a generic list without using LINQ, you'd have to write code to implement the sort yourself. If you needed to sort by a single field in ascending sequence, that would be manageable. If you needed to sort by more than one field, however, or you needed to sort by a field in descending sequence, it would be much more difficult. And if you needed to sort by fields in more than one data source, it would be extremely difficult. To sort the rows in a table by one or more columns, you could use a data view. However, you couldn't sort columns in two or more tables. In contrast, to sort by one or more fields using LINQ, you can simply code an orderby clause.

The bottom line is that LINQ provides concise language for querying data. So you should consider using it whenever you need to select data from one or more data sources.
