# How to complete a Setup project

In addition to the File System Editor, five other editors are available for working with a Setup project. You can display these editors using the buttons that appear at the top of the Solution Explorer when you select the Setup project. These editors provide a variety of features for customizing a Setup project summarized in 25-10. For example, you can use the Registry Editor to specify the keys and values that should be added to the user's computer. And you can use the File Types Editor to establish an association between the files used by your application and the application.

The User Interface Editor lets you customize the dialog boxes that are displayed when you run the Setup project to install the application. For example, you can change the BannerBitMap property of any dialog box to display your company's logo in that dialog box. You can also change the text that's displayed in the dialog boxes, and you can add your own dialog boxes to those that are displayed by the Setup project.

The Custom Actions Editor lets you specify actions that are performed on the user's computer at the end of the install, commit, rollback, or uninstall phase of the installation. Visual Studio provides five predefined actions that the Event Log, Message Queue, Performance Counter, Service, and Service processes. In addition, you can create your custom actions by developing a program or component that performs that action. Note, however, that a custom action can be difficult to develop.

Finally, the Launch Conditions lets you set conditions that must be met before the application can be installed. For example, you can use a launch condition to check the operating system version or to see if a particular file exists on the user's computer. Then, if the condition isn't met, the Setup program aborts the installation.

Besides the setup editors, you can set the properties of the Setup project to customize the project. Of these properties, the Manufacturer and ProductName are two of the most important ones. Because they're used to construct the path for the default installation folder as you'll see in the next figure. You' use the other properties if you want to install another version of the application. If you're replacing a previously installed version, you'll also need to change the file version for the application you're installing. To do that, display the Application page of the Project Properties window for the application. Then, click the Assembly Information button and enter a new file version.

When you complete a Setup project, you build it to generate the files that will be used to install the application. It includes a Setup.msi file that contains the application and any required files and information, and a Setup.exe file that the user can execute to run the Setup program. By default, these files are stored in the Release directory within the project directory. If that's not you want, you can change the path from the Properties dialog box for the project.
