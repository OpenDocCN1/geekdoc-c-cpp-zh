## How to deploy database applications

If the application that you want to deploy works with a database, you need to make sure that each user has access to that database. The technique for doing that depends on where the database will be stored and which deployment technique you're using. In the two topics that follow, you'll learn how to deploy applications that work with databases on both network servers and local systems. And you'll learn how to do that using both ClickOnce deployment and a Setup server.

## Using ClickOnce deployment

If you've developed an application for a group of users who are connected to a LAN, you'll need to store the database on a network server. Then, you need to set the connection string in your application so it points to that. This is illustrated in the first connection string shown in figure 25-12. This connection string refers to a database named MMABooks running on a SQL Server Express database on network server named DBSERVER.

In addition to setting the connection string, you need to make sure that all users have adequate permissions to access the database. If you need help doing that, you should contact the network administrator.

If you've developed an application that's designed for an individual user, you'll need to store the database on the user's computer. To do that, you need to add the database file to the project. The best time to do that is when you're developing the project (see figure 18-2 in chapter 18). Then, when you create a data source from this database, Visual Studio will generate a connection string like the one shown in this figure. Otherwise, if you create a data source for a database that stays outside the project, Visual Studio will generate a connection string similar to the first one in this figure. In that case, before you deploy the application, you'll need to add the database to the project and then change the connection string to look like the one.

This connection string attaches the database file in the directory specified by DataDirectory to the instance of SQL Server Express. By default, DataDirectory points to the directory that contains the output file for the project, which is usually the bin/Debug folder within the project folder. You may remember from chapter 18 that Visual Studio copies the database file to this folder when you run the application. When you deploy the application, DataDirectory points to a special directory that's created to hold the database.

If you add a database file to a project, it is automatically included in the list of files that will be published. At the top of this figure, for example, you can see the Application Files dialog for a version of the Customer Maintenance application that contains the MMABooks database. This dialog box includes the mdf file for the database as well as the ldf file that contains log information for the database. Because the publish status for these two files is set to Data File (Auto), they are included in the installation in the directory that contains the executable file by default.

# The Application Files dialog box for a project that contains a database file

![](img/3148667e42d4db35b3d08576aaa1fa01_798_0.png)

# The connection string for a database that's on a network server

Data Source=DBSERVER\SqlExpress;Initial Catalog=MMABooks;Integrated Security=True

# The connection string for a database that's included in the project

DataSource=\SQLEXPRESS;AttachDbFilename=|DataDirectory\MMABooks.mdf;Integrated Security=True;UserInstance=True

# Description

- To use a database that's available via a LAN, you need to make sure that the connection string is set correctly and all users have proper permissions to access the database. To do that, you may need to make the application a full trust edition.
- To deploy a database to the client along with the other files for the application, add the database file to the project. Then, that file and all related files are listed in the Application-Files dialog box, and those are published by default.
- If you store the connection string for an application in the app.config file, the configuration file is created when the application is published by default.
- If you add a SQL Server database file to a project, SQL Server 2008 Express is automatically included as a prerequisite.
- When you add a database file to a project, the connection string is set as shown in the second example above. Then, when application is deployed, the DataDirectory in this string points to a special directory that's created to hold the database file.
- When you add a database file to a project, the Data Source Configuration Wizard starts. If you've already created the data sources for the application, you will want to cancel out of this wizard and then change the connection string so it looks like the second one above.

## Using a Setup program

If you use a Setup program to deploy a database application, you need to be sure that the connection string is properly set and users have access to the database as you do with ClickOnce deployment.

To start, you need to add the database file to the Setup project. In this figure, for example, the database file has been added to a folder named Data so it points to this folder. Because you included the database file in the application you're deploying, the connection string is generated with a DataDirectory specification. When the application is deployed, DataDirectory points to the directory that contains the executable file for the application. Although you can't see it here, the file is included in the Application Folder by default.

Unlike ClickOnce deployment, SQL Server 2008 Express isn't automatically selected as a prerequisite if you deploy a database file with an application. Because of that, you'll need to set this prerequisite manually. To set the prerequisites for a Setup project, display the Properties dialog box for the project as shown in this figure. Then, click the Prerequisites button and select the appropriate option from the dialog box.
