# Two ways to create ADO.NET objects

Figure 17-15 shows two basic techniques you can use to create the ADO.NET objects you need as you develop database applications. First, you can create ADO.NET objects from a data source in the Data Sources window. Data sources became available with .NET 2.0, and they make it easy to quickly create forms with the data in a data source as a database. In this example, the data source corresponds with the data in the Products table in the MMABooks database.

In the next chapter, you'll learn how to create a data source. For now, you should know that once you create a data source, you can drag it onto a form to automatically display controls on the form and create ADO.NET objects for working with the data in the data source. In this figure, for example, you can see the controls and objects that are generated when you drag the Products table onto the form. A DataGridView control has been added to the form to display the products in the Products table, and a toolbar has been added that lets you work with this.

In addition, five objects have been added to the Component Designer below the form. These are ADO.NET objects. The first one, named mMBooksDataSet, defines the dataset for the form. Then, an object named ProductsTable adapter is similar to a data adapter, but it can only be generated by the designer. You'll learn more about table adapters in the next chapter. Finally, an object named tableAdapterManager makes that if two or more related tables are updated by the form, referential integrity is maintained.

The other objects in the Component Designer are used to bind the controls to the data source. The first object, named productsBindingSource, identifies the Products table as the data source for the controls. The second object, named productsBindingNavigator, defines the toolbar that displayed across the top of the form.

Although you don't usually need to change the properties of the objects in the Component Designer try, you should know that by using the same technique you can change the properties of a control on a form. That is, you select an object to display its properties in the Properties window and then work with them from there.

The second technique for creating ADO.NET objects is to write the code yourself. The code shown in this figure, for example, creates four objects: a connection, a command named selectCommand that contains a Select statement, a data adapter named productsDataAdapter, and a dataset productsDataSet.

Although creating through code is more time-consuming than using data sources, it can result in more compact and efficient code. In addition, creating ADO.NET objects through code encapsulates an application's database processing in specialized database classes. You'll learn how this works in chapter 20.
