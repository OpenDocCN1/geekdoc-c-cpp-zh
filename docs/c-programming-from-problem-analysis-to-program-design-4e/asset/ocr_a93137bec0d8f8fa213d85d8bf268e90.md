# Reading Text Files

The StreamReader class was designed to enable lines of text to be read from a file. If you do not specify a different type of encoding (coding representation), the characters read are converted by default to strings of Unicode characters.

> > **NOTE**  
> > By default, the Unicode UTF-16 encoding schema is used. This represents characters as sequences of 16-bit integers. You could specify Unicode UTF-8, in which characters are represented as sequences of 8-bit bytes, or use ASCII encoding, which encodes characters as single 7-bit ASCII characters.

Using members of the StreamReader class, accessing the contents of a text file is as easy as creating it. As shown in Table 13–6, several methods, including the ReadLine() method, are available to read characters from the file. As with the StreamWriter class, the constructor for StreamReader is overloaded. You may specify a different encoding schema or an initial buffer size for retrieval of data. If you specify a buffer size, it must be given in 16-bit increments.

With the StreamReader and StreamWriter objects, you can use members of parent or ancestor classes or static members of the File class. As shown in Table 13–2, File.Exists() can be used to determine whether the file exists. You can send the filename as an argument to Exists() before attempting to construct an object. This is a way to programmatically avoid having a FileNotFoundException or DirectoryNotFoundException exception thrown in your applications. This is illustrated in Example 13–5.

Values are read from text files in sequential fashion. Just as when you create a text file, a pointer moves through the file keeping track of the current location for the next read.
