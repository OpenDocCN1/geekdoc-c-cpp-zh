## Data Caching

**Data caching**, also known as application caching, is one of the most powerful features in the whole caching scenario in ASP.NET. So far, you have seen declarative ways of enabling caching in ASP.NET applications. However, data caching is all about enabling caching programmatically. Data caching is very useful when you need to cache custom data into cache memory. For example, if you need to cache a dataset to use it later in a Web site, you can use data caching.

In ASP.NET, caching is implemented using two mechanisms: application caching and page output caching. Application caching allows you to cache the generated data, such as a **DataSet** or a custom report. Page output caching saves the output of a Web page and reuses the same output in future. It supports the following basic types of dependency models:

- File Dependency
- Key Dependency
- SQL Dependency
- Aggregate Dependency
- Time Dependency
- Custom Dependency

Data caching in .NET is implemented by the **Cache** class, which is contained in the **System.Web.Caching** namespace. Using the Cache class to store data in cache is easy if you are dealing with simple data. The **Cache** class offers you a simple mechanism to store and access data by using the **KEY/Value** format, as shown in the following code snippet:

```csharp
Cache["myvalue"] = value
```

Using data caching, you can perform the following three main tasks:

- Adding items to cache
- Retrieving items from cache
- Deleting items from cache

Let's discuss these operations one by one in detail.

### Adding Items to Cache

You can use a number of available techniques, from simple to complex, depending on the requirement to add items to cache. The following code snippet shows how to add an item to cache:

```csharp
Cache["myvalue"] = value;
```

The Cache class also offers the Cache.Add and Cache.Insert methods to add items to the cache. Both these methods are useful when you need to manage different aspects of caching, such as expiration and dependency, but there are a few differences between these methods. The Cache.Add method always returns an object but the Cache.Insert method does not return any object. Moreover, if you use the Cache.Insert method to add an item which already exists in the cache, the Cache.Insert method replaces the item. This cannot be done with the Cache.Add method.

The following code snippet shows how to add an item to cache by using the Cache.Insert method:

```csharp
Cache.Insert("myvalue", value);
```

Using the Cache.Insert method in the preceding code snippet is similar to Cache["myvalue"] = value. However, you can do a lot more with the Cache.Insert method, such as using dependencies with the Cache.Insert method. Dependencies allow a cache item to be validated based on an external file.

For example, caching a complete Extensible Markup Language (XML) document without associating the dependency feature may create a problem. Moreover, let's suppose that a user accesses an XML document, which has no dependency specified to it. In such a case, any modification made in the server cannot be seen by the user until the cache expires and is re-generated. For this reason, the file dependency feature is used while inserting an item into the cache. The following code snippet shows how to specify the dependency of an item:

```csharp
Cache.Insert("MyData", data, new CacheDependency(Server.MapPath("data.xml")));
```

While using the Cache.Insert() method, you can specify the absolute expiration and sliding expiration policies using the time dependency model. Absolute expiration sets an absolute time for a cache item to expire and sliding expiration resets the expiration time of a Web page, each time the page is requested. The following code snippet shows how to use the Cache.Insert method to add an item to cache with the absolute expiration time of five minutes:

```csharp
Cache.Insert("Myvalue", value, null, DateTime.Now.AddMinutes(5),
    TimeSpan.Zero)
```

In the preceding code snippet, we have set the last parameter to TimeSpan.Zero as we do not want to specify the sliding time expiration for our item. The following code snippet shows how to use the sliding time expiration policy:

```csharp
Cache.Insert("Myvalue", value, null, DateTime.MaxValue,
    TimeSpan.FromSeconds(20))
```

The preceding code snippet inserts the item, Myvalue, in cache for 20 seconds, with the sliding time expiration policy.

When you use the sliding time expiration policy, the value of absolute expiration does not matter at all because this value varies according to the sliding time expiration. You can also disable the absolute expiration time by using the DateTime.MaxValue parameter. For example, if you specify the sliding time for 20 seconds and the item is accessed in the 18th second, then the whole time is again calculated for 20 seconds more and the item is available in cache for another 20 seconds. This means that 18 seconds + 20 seconds = 38 seconds is the time for which the item exists in cache before the cache gets destroyed, if not accessed in the last 20 seconds.

You can also define the priority of an item at the time of caching it by specifying a value from the CacheItemPriority enumeration. This priority setting informs the Web server about the importance of the item. Therefore, while removing items from cache, the Web server removes low priority items before the high priority items from the cache. The possible values for the **CacheItemPriority** enumeration are listed in Table 9.8:

**Table 9.8: Possible Values for the CacheItemPriority Enumeration**

| Values | Description |
|---|---|
| AboveNormal | Specifies that the cache items at this level are not deleted frequently when the server frees the system memory |
| BelowNormal | Specifies that the cache items at this level are deleted frequently when the server frees the system memory |
| Default | Specifies that the default value for a cached item is Normal |
| High | Specifies that the cache items at this level are least likely to be deleted when the server frees the system memory |
| Low | Specifies that the cache items at this level are most likely to be deleted when the server frees the system memory |
| Normal | Specifies that the cache items at this level are deleted after the deletion of the **Low** and **BelowNormal** priority items; this is the default value for all the cached items |
| NotRemovable | Specifies that the cache items at this level are not deleted automatically |

You can define the **CacheItemPriority** enumeration while inserting an item into cache, as shown in the following code snippet:

```csharp
Cache.Insert("MyValue", value, null, DateTime.MaxValue,
             TimeSpan.FromSeconds(20), CacheItemPriority.High, null)
```

The preceding code inserts the item into cache with high priority.

### Retrieving Data from Cache

Retrieving data from the cache and displaying it on the Web page is one of the easiest tasks in ASP.NET. To retrieve data, you need to specify the key and the value that represent the data, as shown in the following code snippet:

```csharp
value = Cache["MyValue"];
```

It is important to note that while retrieving the data from cache, you should check whether the data exists in the cache or not, as shown in the following code snippet:

```csharp
value = Cache["MyValue"];
if (value == null)
    // Do something here
else
    // Do something here
```

### Deleting Items from Cache

Generally, an expiration policy is used to implement data caching. This expiration policy removes data automatically on the basis of the time limit specified in it. However, there are times when you need to delete data from cache manually. The following code snippet shows how to delete data manually:

```csharp
Cache.Remove("MyData1");
```
