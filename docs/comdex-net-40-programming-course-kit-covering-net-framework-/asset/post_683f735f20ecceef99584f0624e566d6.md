### Using the XCOPY Deployment

XCOPY is used to deploy an application by copying a set of files to a folder on the target computer and then executing the application on the client. If the files are copied to the same folder, the application is executed without editing the configuration settings and registry values. In other words, the XCOPY deployment technique deploys a fully functional application by simply copying the files to the target computer. XCOPY provides various options to deploy applications.

Table A.1 lists some noteworthy options of the XCOPY command:

**Table A.1: Noteworthy Options of the XCOPY Command**

| Option | Description |
|---|---|
| /E | Copies directories, subdirectories, and files including empty ones from one directory to another directory |
| /S | Copies directories, subdirectories, and files excluding empty ones |
| /K | Copies attributes |
| /R | Overwrites read-only files |
| /O | Copies security-related information, such as file ownership and Access Control List (ACL) information |
| /H | Copies directories and subdirectories including hidden and system files |
| /I | Assumes the destination as a directory and creates the directory if it does not exist |
| /C | Continues copying even if an error occurs in deployment |

You can access the options listed in Table A.1 by using the following command at the command prompt:

```
xcopy /?
```

### Overview of Windows Phone Application Platform

Windows Phone 7 applications are supported by .NET Framework 4.0. You can use any of the .NET-compliant languages for developing Windows Phone 7 applications. .NET 4.0 provides the following two approaches to develop Windows Phone 7 applications:

- **Silverlight UI Framework for Windows Phone:** Allows you to develop event-driven Extensible Application Markup Language (XAML) based applications. XAML is a declarative markup language based on Extensible Markup Language (XML) introduced by Microsoft Corporation. This markup language allows designers to easily and quickly define and describe the elements for the User Interface (UI) of WPF applications. When creating a new Windows Phone application, you first need to choose a Silverlight framework upon which to build your application. The Silverlight Framework for Windows Phone, which is based on Silverlight 3, provides the core Silverlight functionalities along with some additional Application Programming Interface (APIs) and features. It allows you to use the existing Silverlight and .NET code, libraries, and markup for developing Windows Phone 7 Silverlight applications. Silverlight for Windows Phone is hosted as a client-device; therefore, the applications that are hosted on browsers cannot be developed using Silverlight for Windows Phone.
- **XNA Framework 4.0 for Windows Phones:** Refers to Microsoft's game development framework. It enables you to create cross-platform games that can run on both Windows and Xbox 360 (a video game console introduced by Microsoft). It provides great support for 2D and 3D games along with audio and video playback, Xbox Live multiplayer features, and Xbox 360 avatars. It includes a rich collection of classes, libraries, and APIs that are specific to game development, and allows you to develop advanced games for Windows Phone 7.

The Windows Phone Application Platform includes Visual Studio, Expression Blend, Windows Phone Marketplace services, and cloud-based Web services in it. It offers a complete platform to the developers for creating applications by providing a rich toolset, well-designed and integrated set of APIs, a service-based marketplace where the users can distribute their Windows Phone applications and a distinct sandbox (tightly-controlled set of resources) in which every Windows Phone application runs. It also provides runtime services that you can use to access Web services in the cloud, such as Xbox LIVE, Windows Azure, location, and notification services. In addition to these, the Windows Phone Application Platform also supports access to Windows Communication Foundation (WCF) and Representational State Transfer (REST) services across the Web. In short, the Windows Phone Application Platform is familiar and easy to use as it re-introduces the tools and technologies that are already known to many users.
