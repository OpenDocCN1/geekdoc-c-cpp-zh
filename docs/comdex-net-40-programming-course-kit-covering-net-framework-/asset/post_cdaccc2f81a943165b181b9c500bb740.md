
.NET Framework 4.0 provides the RoutingService class to implement routing services in WCF applications. The RoutingService class receives incoming messages from the client and sends them to the target service.

## Default Configuration

In WCF 4.0, you never need to have exact knowledge of the configuration of WCF to define an endpoint, behavior and other settings of WCF as required in previous versions of WCF. You also do not need to manually configure the endpoints, behaviors, and other settings; these are automatically configured by WCF. These configurations are added to the **Web.config** file of the application while creating the WCF service application. You can also change the default configuration in the application according to your requirements.

## Support for Discovery Behaviours

WCF 4.0 provides the support for WS-Discovery, which is an Organization for the Advancement of Structured Information Standards (OASIS) specification. It helps the client applications to discover the location of WCF service dynamically at runtime by defining the SOAP-based protocol. SOAP allows clients to examine the WCF service endpoints based on certain criteria to retrieve a list of the suitable candidates offering WCF services. The client can then select an endpoint from the discovered list and use it as a current runtime location of the WCF service endpoints.

## Improved REST Service Development

A RESTful service (now referred to as WCF WebHttp service) is a Web service based on Hypertext Transfer Protocol (HTTP) and REST principles. As per the REST principles, a service:

- Can be accessed with a simple Uniform Resource Identifier (URI)
- Supports Multipurpose Internet Mail Extensions (MIME) types
- Uses different HTTP methods

With the use of MIME types, different data formats, such as JavaScript Object Notation (JSON) and XML can be returned from the WCF service.

With WCF 4.0, it has become much easier and simpler to design, implement, and maintain the REST-based services. WCF 4.0 provides you with a new binding called WebHttpBinding to implement the REST-based service.

## Support for Integration of WCF with WF

WCF 4.0 provides a rich support for integrating WCF with WF that allows you to extend the functionality of workflows by using them with WCF endpoints. This implies that you can create WCF services that can easily transfer and persist data in and out of a workflow.

### Listing 10.1: Code for the WebService.cs File

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Web;
using System.Web.Services;

[WebService(Namespace = "http://tempuri.org/")]
[WebServiceBinding(ConformsTo = WsiProfiles.BasicProfile1_1)]
public class WebService : System.Web.Services.WebService
{
    public WebService()
    {
        //Uncomment the following line if using designed components
        //InitializeComponent();
    }

    [WebMethod]
    public double calculateSimpleInterest(double principal, double rate, int duration)
    {
        double SI;
        SI = principal * rate * duration / 100;
        return SI;
    }
}
```

## Using a Web Service

To use a Web service in a Web site, you need to generate a proxy class for the Web service to allow a Web site access the Web service. A proxy class is a local copy of the class that represents a Web service. You can generate a proxy class for a Web service by adding a Web reference to the Web site.

Perform the following steps to create an ASP.NET Web site, named **UsingSimpleInterestWebService**, to access the Web service created earlier in this chapter:
