In the preceding line of code, the value of the **Height** and **Name** attributes are **23** and **Button1**, respectively. The string **Welcome** is the text that appears on the button.

# Namespaces and XAML

The elements and attributes used in XAML are defined in certain predefined namespaces. Therefore, it is necessary to add references to those predefined namespaces. When you create a WPF application, references to the predefined namespaces are added by default in the **Window** element (in standalone applications) and the **Page** element (in XBAPs).

By default, two namespaces are included in WPF applications (Listing 5.1). The namespaces are added using the **xmlns** attribute of the **Window** or **Page** element. The **xmlns** attribute is set, as shown in the following line of code:

```
```xml
xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
```
```

In the preceding line of code, the **xmlns** attribute is set to the default namespace for the XAML code and WPF applications. The namespace defines all the XAML elements and attributes that are required specifically for working with WPF applications.

The second **xmlns** attribute is set, as shown in the following line of code:

```
```xml
xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
```
```

In the preceding line of code, the **xmlns** attribute is set to the namespace that is required to work with XAML in general. Moreover, this namespace is better than the default namespace as it defines all the essential XAML elements and attributes including those that are not specific to WPF, for example, the elements for Windows Workflow Foundation (WF) and Silverlight.

Note that the second **xmlns** attribute (that refers to the XAML namespace) specifies **x:** as an alias for the namespace. This alias has to be prefixed with every element or attribute that belongs to the XAML namespace, as shown in the following line of code:

```
```xml
x:Class="window1"
```
```

The **x:Class** attribute used in the **Window** element belongs to the XAML namespace and specifies the class (in the code-behind file) that implements the **Window** element.

# Markup Extensions

You have learned how to directly and explicitly set the values of attributes by using the string or numeric values. However, in some cases, you do not want to set an attribute to string or numeric value; rather you want to set an attribute to a reference to a particular object. For example, you may want to delay the assignment of an attribute value until runtime as the attribute value depends on some other object. In this case, you cannot directly assign a string or numeric value to the attribute. Therefore, for such cases, WPF offers markup extensions, which allow you to set the value of an attribute to an object reference. Markup extensions offer an easy and flexible way of assigning values to attributes.

In WPF, markup extensions are objects of classes that assist you to set the attribute to different types of values. All the markup extension classes are derived from the **System.Windows.Markup.MarkupExtension** class. Table 5.1 lists some of the common markup extension classes:

| Markup Extension | Markup Extension Class | Description |
|---|---|---|
| Binding | BindingBase | Allows you to specify a data bound value for a given property |
| StaticResource | StaticResourceExtension | Allows you to specify an existing resource for determining the value of a property |
| DynamicResource | DynamicResourceExtension | Allows you to set the property value dynamically by delaying the reference to a given resource until runtime |
