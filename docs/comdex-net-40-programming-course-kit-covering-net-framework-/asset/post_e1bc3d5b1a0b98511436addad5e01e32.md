## Explaining WPF 4.0 Architecture

WPF 4.0 has both managed and unmanaged components. Managed components refer to those components that use the services of Common Language Runtime (CLR), such as garbage collection and type safety, within the .NET environment, while unmanaged components are those components that do not use the CLR services. The managed and unmanaged components of WPF 4.0 are shown in Fig.VB-5.1:

Fig.VB-5.1

As you can see in Fig.VB-5.1, the architecture of WPF 4.0 contains the various components, such as PresentationFramework, PresentationCore, CLR, User32, and DirectX. The essential components of WPF 4.0 are PresentationFramework, PresentationCore, and milcore. Let’s now discuss the essential components of WPF 4.0 architecture, one by one.

### The PresentationFramework Component

The **PresentationFramework** component refers to the **PresentationFramework.dll** assembly in .NET Framework 4.0. It offers various classes, such as Calendar and DataGrid, to manipulate the appearance and presentation of WPF 4.0 applications. It also provides end-user presentation features, such as layout, animation, and data binding. The **PresentationFramework** component supports higher-level program abstraction implementation, such as styles.

### The PresentationCore Component

The **PresentationCore** component refers to the **PresentationCore.dll** assembly. It implements core services for WPF that allow you to manage properties and events. It supports base types such as UIElement and Visual that are parents of all the controls and shapes. Note that the **PresentationCore** component does not offer classes for the UI of WPF 4.0 applications as offered by the PresentationFramework component.

### The Milcore Component

**Milcore** or **Media Integration Layer (MIL)** is an unmanaged component of WPF 4.0. It interacts with **DirectX**, which is the component that processes all the design-related elements to display 2D and 3D graphical content in WPF 4.0 applications. It is the foundation of MIL and core rendering system of WPF.

## Describing Types of WPF Applications

WPF is a UI framework, which helps you to create interactive applications. There are various application development features such as controls, graphics, layout, and data binding that are supported by WPF. It is a next generation of UI framework that enables you to develop application with a rich user experience. You can create both Windows and Web applications using the WPF.

WPF applications are mainly of the following two types:

- Standalone WPF applications
- XAML Browser Applications (XBAPs)

Let's learn about each of these types of applications, one by one.

### WPF Standalone Applications

WPF standalone applications are similar to Windows Forms applications as you can install WPF applications on your computer and view them from the **Start** menu. Visual Studio 2010 provides you a project template that you can use to create WPF standalone applications. Some essential files, such as Application.xaml and MainWindow.xaml, are automatically added in your project when you start creating application using the project template.

Perform the following steps to create a sample WPF standalone application in Visual Studio 2010:

1. Start Visual Studio 2010.
2. Select **File→New→Project** from the menu bar. The **New Project** dialog box opens (Fig.VB-5.2).
3. Select **Visual Basic→Windows** from the **Installed Templates** section in the left pane of the **New Project** dialog box (Fig.VB-5.2). The project templates available for developing Windows-based applications in Visual Basic are displayed in the middle pane of the **New Project** dialog box.
4. Select the **WPF Application** template in the middle pane to create a WPF standalone application (Fig.VB-5.2).
5. Enter a name for the application in the **Name** text box (Fig.VB-5.2). In our case, we have entered **MyWPFApplication** (also available on the CD) as the name of the application.
6. Enter an appropriate location for the application in the **Location** combo box (Fig.VB-5.2). In our case, we have entered D:\Comdex\Applications\Visual Basic 2010\Chapter 5\.
7. Click the **OK** button to close the **New Project** dialog box, as shown in Fig.VB-5.2:

## XBAP Applications

XBAPs (pronounced as x-baps) are WPF applications that are hosted on a Web server and run in a Web browser, such as Windows Internet Explorer or Mozilla Firefox. An XBAP is similar to a website as it consists of pages similar to Web pages in a website that allows users to navigate in the Web browser. However, if the users are offline (disconnected from the Internet or the Web server on which the XBAP is hosted), then they cannot access the XBAP.

> **The .NET Framework must be installed on client machine to access an XBAP application.**

As with standalone applications, Visual Studio 2010 provides a project template that you can use to create XBAPs.

Perform the following steps to create a sample XBAP in Visual Studio 2010:

1. Start Visual Studio 2010.
2. Select File→New→Project from the menu bar. The New Project dialog box opens (Fig.VB-5.7).
3. Select Visual Basic→Windows from the Installed Templates section in the left pane of the New Project dialog box (Fig.VB-5.7).
4. Select the **WPF Browser Application** template in the middle pane to create a WPF XBAP application (Fig.VB-5.7).
5. Enter a name for the application in the **Name** text box (Fig.VB-5.7). In our case, we have entered **MyWPFBrowserApplication** (also available on the CD) as the name of the application.
6. Enter an appropriate location for the application in the **Location** combo box (Fig.VB-5.7). In our case, we have entered `D:\Comdex\Applications\Visual Basic 2010\Chapter 5\`.
7. Click the **OK** button to close the **New Project** dialog box, as shown in Fig.VB-5.7.
