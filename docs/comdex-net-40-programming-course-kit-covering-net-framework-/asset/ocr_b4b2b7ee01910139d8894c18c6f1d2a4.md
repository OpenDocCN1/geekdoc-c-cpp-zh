# ## CTS and CLS

CTS is an integral part of the runtime through which .NET Framework provides support for multiple languages because it contains a type system that is common for all programming languages. A CTS-compliant language does not require type conversion when calling the code written in another CTS-compliant language. CTS provides a base set of data types for all languages supported by .NET Framework. This implies that the maximum size limit of integer and long variables for all the programming languages remains the same. For example, the size of integer value remains 4 byte in C# as well as in Visual Basic language. However, each language uses aliases for the base data type provided by CTS. For example, CTS uses the data type, System.Int32, to represent a 4 byte integer value; however, Visual Basic uses the alias Integer to represent a 4 byte integer value. This is done for the sake of clarity and simplicity of code.

CLS contains a set of basic rules that enables interoperability between two .NET-compliant languages. CLS is a subset of CTS; therefore, the languages supported by CLS can use each other's class libraries as they use their own libraries. Application programming interfaces (APIs) designed by following the rules defined in CLS can be used by all .NET-compliant languages.

> > An API is a set of classes and methods that support the development of a software application.

# ## .NET Framework Class Library

The .NET Framework Class Library is a huge library made up of a hierarchy of namespaces wherein namespaces contain groups of related classes, interfaces, structures, and enumerations that can be used by any .NET-compliant language. The namespaces are logically defined by their functionality. For example, the System.Data namespace contains the functionality for accessing databases. This namespace is further broken down into other namespaces, such as System.Data.SqlClient, which exposes the functionality required to work with SQL Server databases and System.Data.OleDb, which exposes the functionality required to work with Object Linking and Embedding Database (OLE DB) databases. The classes, interfaces, structures, and enumerations are collectively referred to as types. The different types in the framework are arranged in a hierarchy of namespaces. This solves the problem of name collisions. A name collision between types occurs when two types, referenced in a code, have the same name.

The System namespace is the root namespace for commonly-used types in .NET Framework. Some important classes of the System namespace are Console, Math, Object, String, Array, Enum, and Delegate. The important structures of the System namespace are Boolean, Byte, Char, Decimal, Single, Double, and Int32.

# ## Assemblies and Metadata

In .NET, every application is compiled into an assembly which refers to a portable executable (PE) file. The PE file can be either a dynamic link library (.dll extension file) or an executable (.exe extension file) that contains the MSIL code of the compiled application. In addition to the MSIL code, an assembly also contains assembly metadata and type metadata. Assembly metadata refers to the information about the assembly itself and its components. Type metadata refers to the information about the types that are required for the assembly, such as classes, interfaces, enumerations, and structures. Two types of assemblies can be created in .NET Framework: private assemblies and shared assemblies. A private assembly is used by a single .NET application and stored in the application's directory; whereas, a shared assembly is referenced by more than one application and is stored in Global Assembly Cache (GAC).

A metadata contains information about the code in a language-neutral manner and includes the following information:

+   - Assembly information, such as the name and version of the assembly
+   - Information about types, such as name and members of the assembly where members include methods, fields, properties, and events
+   - Attribute information which modifies the types and members of a class

The information contained in the metadata of an application is used by the CLR to create objects, access data, and call member functions used in the assembly at run time.
