A Web service can be defined as an independent and self-sustaining unit of a software application (Web application) hosted on the Internet. Web services implement specific functionalities to execute the business logic of an application, such as preparing the pay slips for the employees of a company, calculating the income tax, broadcasting weather reports, and providing updated news. Consider a scenario where you want to host a Web site on the Internet that calculates the simple interest. To do so, you do not have to write the complete code to calculate the simple interest in the Web site. Instead, all you have to do is to use the Web service that provides this functionality.

A Web service also allows a Web site to communicate with other Web sites irrespective of the programming languages in which they are created. As a Web service complies with common industry standards, such as Simple Object Access Protocol (SOAP) and Web Services Description Language (WSDL), it can be accessed by any application, regardless of the software and hardware platforms on which the application is running. SOAP is a protocol that enables Web services to communicate with other Web applications over the Internet. SOAP specifies a format for Extensible Markup Language (XML) messages, which is used by Web applications to request for and receive a Web service from a Web server. These messages are also called SOAP messages. WSDL is an XML-based language that defines Web services. Every Web service consists of a corresponding WSDL document that specifies the location of the Web service and lists all the services that it provides.

Earlier, it was difficult to create applications to communicate between a client and a server, as it involves a number of technologies, such as ASP .NET Web Service (ASMX Web service), Web Service Enhancements (WSE), and Microsoft Message Queuing (MSMQ). Since different technologies offer different functionalities, so a developer has to master each of these technologies. To overcome this difficulty, Microsoft introduced the Windows Communication Foundation (WCF) technology. WCF brings together the functionalities of all these technologies under a unified programming model; thereby, simplifying the process of developing a distributed application.

WCF is a set of .NET technologies that act as a platform to create and distribute connected applications. It is also used to develop and deploy services on Windows operating system and provides a unified framework to build service-oriented applications rapidly. With the help of these applications, it is easy to build and use secure and reliable Web applications or Web services in the Web site.

Next, you learn to create and use a Web as well as a WCF service. Towards the end, you also learn to create WCF data services. Let’s begin by discussing the new features of WCF 4.0.

# ## Exploring New Features of WCF 4.0

With the release of .NET Framework 4.0, a new version of WCF, WCF 4.0 is introduced. WCF 4.0 has introduced various new features to increase the productivity of developers working with WCF services. It solves the problems related to configuration, tracing, diagnostics, serialization, and messaging. In WCF 4.0, you do not need to manually configure the endpoints, behaviors, and other settings of services, as these are automatically configured by WCF. The new features included in WCF 4.0 are listed as follows:

+   - Routing service
+   - Default configuration
+   - Support for Discovery Behaviors
+   - Improved Representational State Transfer (REST) Service Development
+   - Support for integration of WCF with WF

Let’s now explain each of these features in detail.

# ### Routing Service

.NET Framework 4.0 supports routing services that can be used in WCF applications. Routing service can be defined as a service that provides the ability to route a message based on its content. This feature allows a message to be forwarded to a client endpoint by specifying the value in the message itself.
