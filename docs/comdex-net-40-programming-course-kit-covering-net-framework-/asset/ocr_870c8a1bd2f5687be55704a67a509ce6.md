optional arguments can be used with methods, delegates, indexers, and constructors. When you use both named and optional arguments, arguments are evaluated in the order in which they appear in the parameter list. Named and optional arguments are very useful when you need to supply arguments for only a few parameters from a list of optional parameters. These arguments are especially useful in calls to COM interfaces, such as Microsoft Office Automation Application Programming Interfaces (APIs).

![](bbox=[0.217, 0.205, 0.269, 0.245])

> > A delegate is similar to a class that is used for storing the reference of a method and invoking that method at runtime. An indexer is a class property that allows you to access a class and all the member variables of the class in the same way as used in the case of arrays. A constructor is a special method that is called automatically when the instance of a class is first created. It is used to initialize all the class members whenever the class is accessed for the first time.

Suppose you need to calculate the body mass index (BMI) of a body by calling the Calculate() method that takes weight and height of the body as its arguments. You can call the Calculate() method without using named arguments, as shown in the following code snippet:

```
```csharp
Calculate(200, 50);
```
```

Now, by using named arguments, you can call the Calculate() method in either of the following ways:

```
```csharp
Calculate(weight:200, height:50);
```
```

Or,

```
```csharp
Calculate(height:50, weight:20);
```
```

Named and optional arguments can be used together; however, you should remember that optional arguments can be followed by named arguments but named arguments cannot be followed by optional arguments.

# New Command-Line Compiler Options

You can always compile and run C# applications from command-line. After compilation, the C# compiler typically generates executable (.exe) files and dynamic link libraries (.dll) files. C# 2010 introduces two new command-line compiler options, /langversion and /appconfig. The /langversion option allows you to execute the syntax that is valid for a specified version of C#. On the other hand, the /appconfig option allows you to specify the location of application configuration file of an assembly. An assembly is the smallest deployable unit of code in .NET providing a collection of types and resources that work together to form a logical unit of functionality.

![](bbox=[0.217, 0.584, 0.269, 0.619])

> > You can get more help on command-line options by typing csc -help on Visual Studio Command Prompt.

# Enhanced COM Interoperability

COM interoperability has been enhanced in C# 2010 to make it easier to call COM objects from the .NET code. Whenever a COM component is registered, the .NET Framework automatically creates a type library and special registry entries. The previous versions of .NET Framework require a large number of explicit type casts and excessive usage of ref keyword to call a COM object. However, with .NET Framework 4.0, .NET applications can easily interoperate with COM objects. In .NET Framework 4.0, features, such as dynamic types, support for named and optional arguments, and less dependency for Primary Interop Assemblies (PIAs) are attributed to the enhanced COM interoperability in C# 2010.

![](bbox=[0.217, 0.741, 0.269, 0.782])

> > PIA is a collection of the type definition of all the types that have been implemented with COM objects in .NET applications. A COM type can be described by any number of interop assemblies; however, only one interop assembly is tagged as PIA. The publisher of the original COM type signs PIA and includes some customizations that are intended to make types easier to use from managed code.
