## Using Anonymous Types in Queries

Anonymous types in LINQ provide a convenient way to group a set of read-only properties into an element that you want to include in a query result. You do not need to define the type for these properties because it is defined by compiler. These types enable you to create objects of a class, without writing the class definition. Such classes have no name; and therefore, are called anonymous types, which enable you to select any combination of available fields in a query and in any order, without defining a named data type for any element.

The compiler constructs an anonymous type dynamically and assigns a name to it. The name changes each time you build an application; and therefore, the name of an anonymous type cannot be used directly in the application.

Anonymous types in LINQ are used in query expressions to combine the columns of data selected by a query. They enable you to write a query that selects any number of columns and in any order.

## Using Lambda Expressions in Queries

A lambda expression is a function without a name that calculates and returns a single value. It is defined and executed at the same time. The lambda expressions use the lambda operator =>, which is read as **goes to**. The left side of the lambda operator specifies the input parameter and the right side specifies the expression or the statement, as follows:

```text
(input parameter) => expression
```

The parenthesis is optional if the lambda expression has only one parameter. However, if there are more than one parameter, parenthesis is necessary, and in such case, a comma (,) separates the parameters. With lambda expressions, there is no need to add a variable to the declaration because the compiler adds it.

The lambda expressions in LINQ form a base for using many standard query operators used in LINQ. The compiler creates lambda expressions to manipulate the calculations defined in a query, such as **Where**, **Select**, and **OrderBy**. The usage of a lambda expression is similar to that of a standard function except that it:

- Does not have a name
- Cannot have modifiers, such as **Overloads** or **Overrides**
- Does not use the **As** clause for the return type of the function representing the lambda expression
- Has its body as an expression and not a statement
- Has no **return** statement; rather the value returned by a function is the value of the expression in the body of the function
- Does not accept generic parameters

Let’s now learn about the PLINQ.

## Exploring PLINQ

PLINQ is a parallel implementation of the LINQ pattern and aims to use all the processors present in a system. Queries designed in PLINQ are syntactically very similar to the LINQ to Objects queries. For instance, consider the following simple LINQ to Objects query:

```csharp
var output = from x in source
             where (some condition)
             select (something)
```

Now, consider the following PLINQ query:

```csharp
var output = from x in source.AsParallel()
             where (some condition)
             select(something)
```

Note that the preceding PLINQ query is the same as the LINQ to Objects query, except the use of the AsParallel() method. This method is specific to PLINQ and is available in the ParallelEnumerable class. This class exposes most of the PLINQ functionalities and is available in the System.Linq namespace.

> The LINQ to Objects query indicates the use of LINQ queries on any in-memory `IEnumerable` or `IEnumerable<T>` interface. In LINQ to Objects queries, the queries are executed without using technologies, such as LINQ to SQL.

Similar to the non-parallel sequential LINQ queries, PLINQ queries perform operations on any in-memory `IEnumerable` or `IEnumerable<T>` interface. PLINQ divides a data source into different segments and then executes each of the segments on separate worker threads across multiple processors. In many cases, queries run much faster because of parallel execution. However, parallelization does not imply that all the queries will run fast as there may be various complexities involved with parallelization. Moreover, note that the PLINQ concept applies only to the LINQ to Objects queries.
