### Defining Styles as Resources

One of the most common uses of WPF resources is to apply a given style on several controls or elements uniformly. For example, you may want that all the buttons in your WPF application have the same background color. In such a case, you can define the style that can be applied on multiple controls as a resource.

In WPF, you can use the Style element to define a style as a resource. Each Style element specifies an element to which you want to apply the style. A Style element also has one or more Setter elements that specify the properties of the element to which you want to apply the style and property values. The syntax of the Style element is given as follows:

```xml
<Style x:Key="name" TargetType="elementName">
    <Setter Property="propertyName1" Value="propertyValue1"/>
    <Setter Property="propertyName2" Value="propertyValue2"/>
    .
    .
    <Setter Property="propertyNameK" Value="propertyValueK"/>
</Style>
```

In the preceding syntax:

- **x:Key:** Refers to the key name of the Style element
- **TargetType:** Refers to the name of the type of an element on which the style is to be applied
- **propertyName1, propertyName2, . . . , propertyNameK:** Refers to the names of the properties
- **propertyValue1, propertyValue2, . . . , propertyValueK:** Refers to the values of the properties

Perform the following steps to define styles as resources in a WPF standalone application:

- 1. *Start* Visual Studio 2010.
- 2. *Select* **File→New→Project** from the menu bar. The **New Project** dialog box opens.
- 3. *Select* **Visual Basic→Windows** from the **Installed Templates** section in the left pane of the **New Project** dialog box.
- 4. *Select* the **WPF Application** template in the middle pane to create a WPF standalone application.
- 5. *Enter* the name of the application as **MyStyle** (also available on the CD) in the **Name** text box and an appropriate location for the application in the **Location** combo box.
- 6. *Click* the **OK** button to close the **New Project** dialog box and create the **MyStyle** application.
- 7. *Replace* the default code in the XAML view of the **MainWindow.xaml** file with the code given in Listing 5.18.

**Listing 5.18:** Showing the Code to Define Styles as Resources

```xml
<Window x:Class="MainWindow"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    Title="MyStyle Application" Height="200" Width="300">
    <Grid>
        <Grid.Resources>
            <Style x:Key="MyButtonStyle">
                <Setter Property="Button.Background" Value="black"/>
                <Setter Property="Button.Foreground" Value="white"/>
            </Style>
        </Grid.Resources>
        <Button Name="Button1" Style="{StaticResource MyButtonStyle}"
                Margin="10,10,140,85">Button1</Button>
        <Button Name="Button2" Style="{StaticResource MyButtonStyle}"
                Margin="140,85,10,10">Button2</Button>
    </Grid>
</Window>
```

In Listing 5.18, the **Title** property of the **Window** element is set to **MyStyle Application**. This implies that the text **MyStyle Application** appears on the title bar of the window. The **Window** element has a **Grid** control as its child element. The **Resources** property of the **Grid** control is used to define a style as a resource by making the **Style** element as a child element of the **Grid.Resources** element. The **Style** element has a unique key, **MyButtonStyle**, which is used to reference the element. In the **Style** element, two **Setter** elements are included as its child elements. The first **Setter** element specifies that all the **Button** controls in the grid have a black background, while the second **Setter** element specifies that all the **Button** controls in the grid have a white foreground. Two **Button** controls are added to the **Grid** control to demonstrate the use of the **MyButtonStyle** style. The **Style** property of both the **Button** controls (**Button1** and **Button2**) is set by using the **MyButtonStyle** style as a static resource.

A workflow is a graphical representation depicting the flow of a process or a set of tasks that produces a result. Windows Workflow Foundation (WF) is one of the four foundations introduced in .NET Framework 3.0. The other three foundations are Windows Presentation Foundation (WPF), Windows Communication Foundation (WCF), and Windows CardSpace (WCS). The latest version of WF, WF 4.0, is released with many improvements, such as a Flowchart activity to implement loops and conditional branching in workflows. Moreover, WF enables you to use the built-in tools and flowcharts to perform a particular action or activity while writing predefined classes in an application. For example, to print your name on the screen, you simply need to drag the **WriteLine** activity from the **Primitives** tab of Toolbox and type your name in that activity. Now, when you run the application, your name will appear on the screen while in other platforms, such as simple Console Application of .NET, you need to write a detailed code to perform the same task. WF consists of a programming model, a runtime engine, and tools that help you to quickly and easily develop workflow-based applications for Windows. Visual Studio 2010 has built-in templates to create workflow-based applications.

This chapter begins by discussing the improvements in WF in .NET Framework 4.0. Then, you learn about workflow design principles. Next, the architecture of WF is discussed. Further, you learn how to develop a sample workflow application and how to implement conditions in workflows. Towards the end, you learn how to create and use custom activities.

Let’s begin by discussing the improvements in WF in .NET Framework 4.0.

### Exploring the Improvements in WF

In .NET Framework 4.0, several improvements have been made in WF to help users to easily create, execute, and maintain workflow applications. Some of the improvements in WF are as follows:

- Uses predefined activities, instead of classes, to perform a task, such as you can use the **SequentialWorkflowActivity** activity to initialize new task instances in a workflow
- Introduces a new control flow activity, called **Flowchart**, to provide an event-driven programming model
- Introduces the following new features to the built-in activity library:
  - Introduces new flow control activities, such as **DoWhile**, **ForEach**, **ParallelForEach**, **Switch**, **Pick**, and **TryCatch**
  - Adds activities, such as **Assign** and **AddToCollection** to the built-in activity library to help users to manipulate data members
  - Adds activities, such as **TransactionScope** and **Compensate** to the built-in activity library to control transactions
  - Introduces new messaging activities, such as **SendContent** and **ReceiveReply**
- Includes the following new options to run workflows:
  - **WorkflowServiceHost**: Specifies a host for workflows
  - **WorkflowApplication**: Specifies a host for a particular instance of a workflow
  - **WorkflowInvoker**: Acts as a method call to invoke a workflow
- Introduces the **Bookmark** object that can be used for resuming a pending workflow
