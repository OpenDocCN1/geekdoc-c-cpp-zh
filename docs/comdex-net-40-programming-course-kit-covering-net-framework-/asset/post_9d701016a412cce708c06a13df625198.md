## Dynamic Programming

**CHAPTER 3**

### In this Chapter:

- Explaining Dynamic Language Runtime
- Working With the Dynamic Type
- Creating Objects of the DynamicObject and ExpandoObject Classes

C# is a statically-typed language. This type is checked during compile time, yet in its latest version, Microsoft has introduced the concept of dynamic programming. The reason for the support of dynamic programming being introduced in C# is due to the growth and popularity of dynamic languages, such as Ruby, List Processing (LISP), Smalltalk, and Python. A programming language is said to be dynamic, if its type checking is performed during runtime. C# has become more dynamic with the inclusion of anonymous types and methods in C# 2005 and the var keyword in C# 2008.

Dynamic programming is one of the most exciting features of C# 2010, which is expected to give developers more flexibility. C# 2010 implements the concept of dynamic programming using Dynamic Language Runtime (DLR) and dynamic data type. Although dynamic is a static type, but if you declare any method, property, member, or operator of an object as dynamic, its actual type is resolved only at runtime.

DLR makes it possible to integrate dynamic programming languages, such as Python and Ruby, with the Common Language Runtime (CLR) so that these languages can run on .NET Framework. DLR provides an environment that enables the statically-typed languages to behave similar to dynamic languages without losing their own properties.

The chapter begins with the introduction of the DLR and later discusses the newly introduced dynamic type. You also learn how to perform implicit conversion and dynamic operations. Finally, you learn how to create an instance of the **ExpandoObject** and **DynamicObject** classes and how to work with these instances.

Let’s begin by discussing DLR.

### Explaining Dynamic Language Runtime

DLR is a runtime environment that integrates dynamic languages with the CLR by adding a set of services to the CLR. It helps you to run dynamic languages on the .NET Framework. DLR enables the identification of data types of an object at runtime and allows the statically-typed languages, such as C# and Visual Basic, to interoperate with the dynamic languages. Apart from these features, DLR also creates a number of libraries that help you to write less and simple code while operating with objects and accessing data members.

DLR is introduced as a part of the .NET Framework similar to the CLR. It can be implemented in an application by including the **System.Dynamic** and **System.Runtime.CompilerServices** namespaces in the application.

DLR provides various advantages, which are as follows:

- Allows you to easily implement the dynamic languages in the .NET Framework. Some examples of dynamic languages are LISP, JavaScript, Ruby, Hypertext Preprocessor (PHP), Python, ColdFusion, and Cobra.
- Provides dynamic features to statically-typed languages. The statically-typed .NET Framework languages, such as C# and Visual Basic, can create dynamic objects and use them together with statically-typed objects.
- Supports sharing of libraries and objects, which means that the objects and libraries implemented in one language can be used by other languages using DLR. The DLR also enables interoperation between statically-typed and dynamic languages. For example, you can use a dynamic object created in a dynamic language in a statically-typed language, such as C#.
- Enables fast execution of dynamic operations by supporting advanced caching.

In .NET Framework 4.0, DLR allows the dynamic languages to run on .NET Framework. DLR provides some services to the CLR, such as expression trees, call site caching, and dynamic object interoperability, to support language interoperation. These services are described as follows:

- **Expression Trees:** Refers to the representation of code in a data structure similar to a tree. However, expression trees in DLR are the advanced version of the expression trees that were introduced with Language Integrated Query (LINQ) in .NET 3.5. Therefore, DLR includes the functionalities of LINQ expression trees, such as control flow, assignment, and other language-modeling nodes. These expression trees define the semantics of a language in form of an abstract syntax tree (AST). The AST enables the DLR to dynamically generate code (expression trees) in place of Intermediate Language (IL), which the CLR executes at runtime.
- **Call Site Caching:** Enables DLR to store all the information of the variables, such as their data types, as well as of the operations performed on these variables. The call site caching also enables the DLR to check whether such operations have been performed previously and if so, the DLR retrieves all the information about the variables and then reuses that information whenever required. The place where DLR stores these values is called call site.
- **Dynamic Object Interoperability:** Enables the DLR to provide a set of classes and interfaces that represent dynamic objects and operations. The authors of dynamic libraries use these classes and interfaces to create dynamic libraries, which can be used with the static and dynamic type languages.

### Working With the Dynamic Type

With the release of .NET 4.0, a new reference data type is introduced, called **dynamic**. When you use the dynamic keyword with any member variable or member function, the compiler checks the type of that variable or function at runtime instead of compile time.

The syntax for declaring a variable as **dynamic** is as follows:

```
dynamic x;
```

There is one more data type, var, in C# that is similar to the dynamic data type. The only difference between **dynamic** and var is that the types of the variables declared as **dynamic** can be changed dynamically as compiler checks them only at runtime. On the other hand, if you once declare a variable as var, you cannot change its type throughout the execution of program.
