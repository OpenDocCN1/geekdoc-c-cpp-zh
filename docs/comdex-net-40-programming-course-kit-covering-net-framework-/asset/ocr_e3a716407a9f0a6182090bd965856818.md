# Database Deployment

In Visual Studio 2010, the deployment package includes dependencies, such as log files on the SQL Server database. The package definition contains the connection string you provide for the database. It also includes Structured Query Language (SQL) scripts related to database schema and data. Using dependencies, you can also create the customized SQL scripts and can create the sequence in which they should occur. At the time of deployment, the deployment process uses the appropriate connection string for the target server, which is used to run the SQL scripts on the server, for creating database schema.

# One-Click Publish for Web Applications

In Visual Studio 2010, the IIS remote management service is used to publish a Web application on the remote server. You have to create a publish profile for the testing or staging server to store the credentials securely. After creating a publish profile, you can deploy the Web application on the target server with one-click by using the Web One Click Publish toolbar. You can also use the MSBuild command line to publish the Web application.

# Deploying a Windows Application

Deployment of software or an application can be considered as an activity to make it available to use for a number of users. As you know, the Windows applications run locally on a user’s computer. When you develop a Windows application, it is executed on a computer on which you have developed it. However, you can deploy the application so that it can be easily installed on another computer without sharing the application’s code using Windows Installer. In this section, you learn to deploy applications using the following techniques:

+   - Windows Installer
+   - ClickOnce

Let’s discuss these techniques, one by one.

# Using Windows Installer

**Windows Installer** is a technique to deploy applications with the help of interactive setup wizard. It allows you to deploy Windows applications by creating a Windows Installer package. The installer package has an extension of .msi and contains the application to be deployed, dependent files, and registry entries. This package can be distributed to various end-users by simply copying it on the target computers. The end-users can then run the installer package to install the application on the hard disk of their computers. Once your application is installed on the target computer, end-users can open the application from the target computer.
