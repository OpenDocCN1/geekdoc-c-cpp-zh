You can use different languages in a single ASP.NET 4.0 application by configuring the Web application to treat the subfolders of the App_Code folder as separate compilable units. The CodeSubDirectories element of the compilation element in the Web.config file helps you to implement the multiple language support feature, in which each folder can contain source code of different programming language. For example, you can configure subfolders named VB and CS to compile into separate assemblies, by using the following code snippet in the Web.config file:

```
```xml
<compilation debug="false">
    <codeSubDirectories>
        <add directoryName="VB" />
        <add directoryName="CS" />
    </codeSubDirectories>
</compilation>
```
```

In the preceding code snippet, the reference to the VB and CS subfolders does not require any information about the programming language.

# Optimizing Dynamic Compilation

As you know, if you make any changes to a dynamically compiled ASP.NET file, it automatically invalidates the file's cached compiled assembly and triggers recompilation of all the affected resources, such as .dll files. However, in case of large applications, this process of recompilation may make the application unavailable for a long duration, even if the change is a small one.

You can avoid such a situation by setting the optimizeCompilations attribute to True in the web.config file. This implies that after setting this attribute to True, when you implement any change, only the files in which changes are made are recompiled.

# Describing the Disadvantages of Dynamic Compilation

The disadvantages of dynamic compilation in an ASP.NET application are as follows:

+   - Slow response time for the users as the ASP.NET pages and code must be compiled the first time they are requested
+   - No means to identify any compile-time bugs, before a user accesses the site
+   - No provision of creating a compiled version of the site that can be deployed on the production server without the source code
