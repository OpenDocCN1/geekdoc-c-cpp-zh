
You can easily identify markup extensions in the XAML code because their syntax is different from the rest of the XAML code. When you want to use a markup extension as a value for an attribute, you need to enclose it within the curly braces ({ }). The opening curly brace is followed by the name of the markup extension. The name of the markup extension is followed by a whitespace, which is then followed by the object reference. Let's take a look at the following XAML code snippet:

```xaml
<Button Name="Button1" Margin="100" Style="{StaticResource myBackground}">
    Welcome
</Button>
```

In the preceding code snippet, the **Style** attribute of the **Button** element is set by using the **StaticResource** markup extension. Note that in place of a string or numeric value, a pair of curly braces appears within the double quotes (" "). Inside the curly braces, **StaticResource** is the name of the markup extension and **myBackground** is the object reference. This implies that at runtime, the **Style** property of the **Button** element takes the value of the **myBackground** object.

You have learned how to use XAML in WPF. In the next section, you learn how to work with WPF controls.

## Working with WPF Controls

A control is a UI element that allows interaction between the application and its users. WPF has a rich set of controls that allows you to develop graphic-rich applications. In WPF, you can add and work with the controls in the Design view, code-behind file, and XAML view. The controls that you add in the Design view or XAML view can be seen at design time; however, the controls that you add in the code-behind file can be seen only at runtime and not at design time. Therefore, it is recommended that you add and manipulate the controls in the Design view or the XAML view and define the behavior of the controls in the code-behind file.

You can add a control in a WPF application by dragging it from the **Toolbox** and dropping it on the Design view. A control can also be added by double-clicking it in the **Toolbox** or writing the corresponding XAML code in the XAML view. Note that changes made to a control in the Design view are automatically reflected in the XAML view and the changes made in the XAML view are reflected in the Design view.

Some important WPF controls that you can use in your WPF applications in **Visual Studio 2010** are as follows:

- The **Grid** Control
- The **Button** Control
- The **TextBox** Control
- The **PasswordBox** Control
- The **TextBlock** Control
- The **Border** Control
- The **GridSplitter** Control
- The **Canvas** Control
- The **StackPanel** Control
- The **DataGrid** Control
- The **Calendar** Control
- The **DatePicker** Control

Let's discuss each of these controls, one by one.

### *Using the Grid Control*

As already learned, a **Grid** control is automatically added to a WPF application (both standalone and XBAP applications). The **Grid** control is a child element of the **Window** element (in standalone applications) and the **Page** element (in XBAP applications) because it is present in both the applications. It is a container control, which includes other controls (child controls or elements) and provides a predefined layout for those controls. The Grid control offers a predefined layout of a grid with its child controls or elements contained in the cells of the grid. By default, a Grid control consists of a single cell, that is, one row and one column. However, you can create additional cells (rows and columns) in the Grid control by setting its properties.

The Grid control is an instance of the Grid class. Table 5.2 lists the noteworthy properties of the Grid class:

| Property | Description |
|---|---|
| ColumnDefinitions | Returns an ordered collection of columns defined in the Grid control |
| RowDefinitions | Returns an ordered collection of rows defined in the Grid control |
| ShowGridLines | Returns or sets a value that indicates whether grid lines between the cells of the Grid control are visible |
| Column | Returns or sets a value that indicates the column in which a child element of the Grid control appears |
| ColumnSpan | Returns or sets a value that indicates the number of columns that a child element of the Grid control spans |
| Row | Returns or sets a value that indicates the row in which a child element appears |
| RowSpan | Determines how many rows a child content spans within a Grid control |

![](img/9862a98a1a2d3bb14334137965a1ec60_198_0.png)

> The Column, ColumnSpan, Row, and RowSpan properties are attached properties of the Grid class. An attached property is a property that can be accessed and set by other elements. For example, the Column, ColumnSpan, Row, and RowSpan properties can be accessed by child elements of a Grid control, such as Button or TextBox.

Perform the following steps to use the Grid control in a WPF standalone application:

1. *Start* Visual Studio 2010.
2. *Select* **File**→**New**→**Project** from the menu bar. The New Project dialog box opens.
3. *Select* **Visual Basic**→**Windows** from the Installed Templates section in the left pane of the New Project dialog box.
4. *Select* the **WPF Application** template in the middle pane to create a WPF standalone application.
5. Enter the name of the application as **MyGrid** (also available on the CD) in the **Name** text box and an appropriate location of the application in the **Location** combo box.
6. Click the **OK** button to close the **New Project** dialog box and create the **MyGrid** application.
7. *Replace* the default code in the XAML view of the **MainWindow.xaml** file (automatically created at the application creation time) with the code given in Listing 5.2:

**Listing 5.2:** Showing the Code to Add Rows and Columns to the Grid Control

```xml
<Window x:Class="MainWindow"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    Title="MyGrid Application" Height="350" Width="525">
    <Grid ShowGridLines="True" Background="Cornsilk">
        <Grid.RowDefinitions>
            <RowDefinition Height="68"/>
            <RowDefinition Height="68"/>
            <RowDefinition Height="68"/>
            <RowDefinition Height="68"/>
        </Grid.RowDefinitions>
        <Grid.ColumnDefinitions>
            <ColumnDefinition Width="139"/>
            <ColumnDefinition Width="139"/>
        </Grid.ColumnDefinitions>
    </Grid>
</Window>
```

8. Press the F5 key on the keyboard to run the application. The output of the application appears, as shown in Fig.VB-5.23:
