Among these assemblies, **mscorlib.dll**, **system.dll**, and **System.Windows.dll** are essential assemblies for Silverlight 4.0 applications. The rest of the assemblies are added to handle certain common functionalities, such as working with the Web browser and XML content. You can also add references to other assemblies from the **Add Reference** dialog box, which you can open by right-clicking the name of the Silverlight application in the Solution Explorer window and selecting the **Add Reference** option from the context menu.

Along with these assemblies, some files, such as **App.xaml** and **MainPage.xaml**, are also included automatically in the **Solution Explorer** window of **Visual Studio 2010**, whenever you create a new Silverlight 4.0 application, as shown in Fig.ASP-11.11.

As shown in Fig.ASP-11.11, the files which are included automatically in a Silverlight 4.0 application are as follows:

+   - **App.xaml:** Refers to the XAML file in which you can define application-level resources, such as brush and style objects.
+   - **App.xaml.cs:** Refers to the code-behind class for the **App.xaml** file. This file can be used to handle application-level events, such as **Application_Startup**, **Application_Exit**, and **Application_UnhandledException**.
+   - **MainPage.xaml:** Refers to the XAML file, which is used to define a page, similar to a page in a Web site. The **MainPage.xaml** file is by default the initial UI control, which is loaded when an application activates. You can use UI controls, such as **Button**, **Label**, and **TextBox** controls, inside the **MainPage.xaml** file to define the UI of a Silverlight application.
+   - **MainPage.xaml.cs:** Refers to the code-behind file of the **MainPage.xaml** file in which you can write the managed code for a Silverlight application.

Whenever you create a Silverlight application, **Visual Studio 2010** automatically creates an ASP.NET Web application to host that Silverlight application. This Web application contains **HTML**, **ASP.NET test host pages**, and a **JavaScript** helper file. You can run and test your Silverlight applications using either the HTML or the ASP.NET test page. You can view the references of some of those files in the **Solution Explorer** window, as shown in Fig.ASP-11.12.
