# Type Equivalence Support

In Visual Basic 2010, you can deploy applications that have embedded type information instead of Component Object Model (COM) type information imported from a Primary Interop Assembly (PIA). Embedded type information allows your application to use types at runtime without the need of a reference to the runtime assembly. An application containing the embedded type information can work with the different published versions of a runtime assembly, without being recompiled.

# Dynamic Support

Visual Basic 2010 allows you to delay the resolution of the data type for methods and properties till runtime to provide you more flexibility while developing applications. You can create objects that expose properties and methods dynamically at runtime by using the classes of the System.Dynamic namespace, such as DynamicObject and ExpandoObject. These classes have methods that you can override to provide your own implementation to these methods. This dynamic support in Visual Basic 2010 can be used to create objects, which can work with structures that do not match a static type or format. For example, a dynamic object can be used to reference the Hypertext Markup Language (HTML) Document Object Model (DOM), which can contain any combination of valid HTML markup elements and attributes.

# Covariance and Contravariance

In Visual Basic 2010, covariance and contravariance facilitate implicit type conversions for array types, delegate types, and generic type arguments. Using covariance, you can assign a smaller type to a larger type, such as assigning a Decimal type variable to an Object type variable. On the other hand, contravariance reverses the assignment compatibility that is preserved in covariance, for instance, you can treat an Object type variable as a Decimal type variable. You can use the Out keyword to implement covariance and the In keyword to implement contravariance.

# Visual Basic 2010 Keywords

Every programming language uses a set of predefined words in coding. These words are language-specific and are known as keywords. A keyword has a specific predefined meaning for the compiler. Visual Basic 2010 provides two types of keywords: reserved and unreserved. Reserved keywords are those keywords that cannot be used as names for programming elements, such as variables, methods, and classes, while unreserved keywords are those keywords that can be used as names for programming elements. However, you should avoid using variables and procedures as keywords, as this leads to subtle errors in the code and makes it difficult to understand.
