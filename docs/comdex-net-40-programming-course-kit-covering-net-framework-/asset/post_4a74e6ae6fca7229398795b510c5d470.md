
- **Self-Tracking Entities:** Refers to the entities that are able to track their own changes while working with n-tier applications. These changes are saved to a database. The .NET Framework 4.0 introduces T4 template to generate self-tracking entities.
- **Model-First Development:** Allows you to create your own EDM and then generate Transact-SQL (T-SQL) and customized code (relational model) database from that EDM with matching tables and relations.
- **Built-in Functions:** Enables you to use built-in SQL Server functions, such as date and time functions, directly in your queries.
- **Better N-Tier Support:** Supports Application Programming Interfaces (APIs) and templates to facilitate easier development of n-tier applications with the Entity Framework.

As shown in Fig.C#-4.1, the two main components of ADO.NET to access and manipulate data are data providers and the **DataSet** object. The data provider contains the **Connection**, **Command**, **DataReader**, and **DataAdapter** objects.

Now, let’s learn about the data providers and datasets in detail.

### Data Providers

A data provider is used to establish connection with a database, retrieve data from the database, store data in a dataset, read the data, and finally update the database. The data provider increases performance of applications without compromising on functionality.

Table 4.1 lists the different types of data providers included in ADO.NET:

| Data Provider | Description |
|---|---|
| .NET Framework Data Provider for SQL Server | Provides access to Microsoft SQL Server 7.0 or advanced version by using the **System.Data.SqlClient** namespace. |
| .NET Framework Data Provider for OLE DB | Provides access to databases exposed to OLE DB by using the **System.Data.OleDb** namespace. |
| .NET Framework Data Provider for ODBC | Provides access to databases exposed to ODBC by using the **System.Data.Odbc** namespace. |
| .NET Framework Data Provider for Oracle | Provides access to Oracle Database 8.1.7 or advanced versions by using the **System.Data.OracleClient** namespace. |

A data provider mainly contains the following four objects:

- **Connection:** Establishes connection with a database. The base class for all the **Connection** objects is the **DbConnection** class. The Connection objects contain methods to open and close connections.

  .NET Framework provides two types of Connection objects: the **SqlConnection** object, which is designed specifically to connect to Microsoft SQL Server, and the **OleDbConnection** object, which is designed to provide connections to a wide range of databases, such as Microsoft Access and Oracle. Some commonly used methods of the **Connection** object are the **Open()** and **Close()** methods. The **Open()** method is used to open a connection with a database and the **Close()** method is used to close the connection.
- **Command:** Executes a command against a database and retrieves a **DataReader** or a **DataSet** object. It also executes the **INSERT**, **UPDATE**, or **DELETE** commands against the database. The base class for all the **Command** objects is the **DbCommand** class. The **Command** object is represented by two classes: **SqlCommand** and **OleDbCommand**. It provides three methods, **ExecuteNonQuery()**, **ExecuteScalar()**, and **ExecuteReader()**, which are used to execute commands on the database. The **ExecuteNonQuery()** method executes the commands that have no return value, such as the **INSERT**, **UPDATE**, or **DELETE** commands. The **ExecuteScalar()** method returns a single value from a database query. The **ExecuteReader()** method returns a result set in the form of a **DataReader** object.
- **DataReader:** Retrieves data from the database in a forward-only, read-only mode. The base class for all the **DataReader** objects is the **DbDataReader** class. The **DataReader** object is returned as a result of calling the **ExecuteReader()** method of the **Command** object.
- **DataAdapter:** Retrieves data from a database, stores data in a dataset, and reflects the changes made in the dataset to the database. The base class for all the **DataAdapter** objects is the **DbDataAdapter** class. The **DataAdapter** object acts as an intermediary for all the communication between the database and the **DataSet** object. The **Fill** method of a **DataAdapter** object is used to fill a **DataTable** or **DataSet** object with data from the database. The **DataAdapter** object commits the changes to the database by calling the **Update()** method. It provides four properties that represent four database commands: **SelectCommand**, **InsertCommand**, **DeleteCommand**, and **UpdateCommand**.

### Datasets

The other major component of ADO.NET is the **DataSet** object. This object remains disconnected from a database; thereby, consequently reducing the load on the database. The data in the dataset can be manipulated and updated independent of the database as the dataset maintains a cached copy of the data from a database.

Table 4.2 lists the various components that make up a **DataSet** object:

**Table 4.2: Components of the DataSet Object**

| Component | Description |
|---|---|
| DataTableCollection | Contains all the tables retrieved from a database |
| DataTable | Represents a table in the **DataTableCollection** object of a dataset |
| DataRowCollection | Contains all the rows present in a **DataTable** object |
| DataColumnCollection | Contains all the columns present in a **DataTable** object |
| ConstraintCollection | Contains a collection of constraints for a **DataTable** |
| DataRelationCollection | Contains relationships and links between tables in a dataset |
