**The FlowDecision node is a node that decides the sequence of a workflow according to the specified conditions and accordingly transfers the control to the particular nodes.**

The Flowchart activity contains a collection of flow nodes that are inherited from the FlowNode class. The following types of nodes or elements can be a part of a flowchart:

+   - **FlowStep:** Shows one step of execution in the flowchart
+   - **FlowDecision:** Shows the execution on the basis of a Boolean condition. It is similar to the **If** construct
+   - **FlowSwitch:** Shows the execution on the basis of an exclusive switch. It is similar to the **Switch** construct

Next, let’s discuss about the procedural workflows.

# ## The Procedural Workflow

A procedural workflow helps you to create workflows by using basic and sequential execution standards. In WF, procedural workflows use flow control constructs, such as **If, While, ForEach,** and **Switch**. These flow control constructs are similar to branching statements that are found in procedural languages. Procedural workflows can also consist of other flow control activities, such as **Flowchart** and **Sequence**.

Next, let’s learn about the activity component in WF architecture.

# ## *Activity*

In WF, an activity is the basic unit of composition and execution of a workflow. In other words, an activity represents a unit of work in WF. Each activity in a workflow consists of its own variables and arguments and is a subclass of the Activity class. The variables in an activity are used to store the data in an activity while the arguments in an activity are used to move data in and out of an activity.

Workflows in WF can be created by implementing the abstract class, **CodeActivity,** for basic activity functionality, such as implementing control flow, conditions, event handling, and state management. In addition, the abstract class, **NativeActivity,** can be implemented to develop custom activities for basic activity functionality that implement specific behavior.

# ## *Built-In Activity Library*

The built-in activity library is a collection of activities that are used to create workflows. In .NET Framework 4.0, WF includes a new activity library with expanded functionality.

Table 6.1 lists the different types of activities available in the built-in activity library:

| Activity Type | Description | Examples |
|---|---|---|
| Control flow activities | Allow you to control the flow of execution within a workflow | If, ForEach, While, DoWhile, Parallel, ParallelForEach, Pick, and Switch |
| Flowchart activities | Allow you to control the execution and branching within a flowchart | FlowChart, FlowDecision, and FlowSwitch |
| Messaging activities | Enable workflows to send and receive Windows Communication Foundation (WCF) messages | Send, SendReply, Receive, and ReceiveReply |
| Runtime activities | Allow you to access workflow runtime features, such as persistence and termination | Persist and TerminateWorkflow |
