## Using the ProxyWebPartManager Control

Earlier you have learned that all the **WebParts** applications contain one **WebPartManager** control, which manages all the **WebParts** controls. If a **WebParts** application contains a master page, the **WebPartManager** control is placed in the master page, so that it can be linked with the master page. Now, all the content pages (Web pages inherited from the master page) can use the **WebPartManager** control to manage their Web Parts controls. Each content page declares a static link to connect to the WebPartManager control of the master page. This static link is declared with the help of the ProxyWebPartManager control.

## Creating a Web Application using WebParts Controls

As already discussed, you can personalize a Web site according to your needs by using the **WebParts** controls. Let’s follow these steps to create a Web application, containing Web Parts controls, to learn how to personalize it according to your specific requirements.

- 1. *Click* **Start→All Programs→Microsoft Visual Studio 2010→Microsoft Visual Studio 2010**.
- 2. *Select* **File→New→Web Site** from the menu bar.
  The New Web Site dialog box appears.
- 3. *Select* **Visual C#→ASP.NET Web Site** in the middle templates pane.
- 4. *Set* the name of the Web site as **WebPartsApplication**.
- 5. *Click* the **OK** button.
  The **WebPartsApplication** application is created.
- 6. *Drag* a **WebPartManager** control from the WebParts tab of the Toolbox and drop it onto the **Default.aspx** page.
- 7. *Drag* four **LinkButton** controls from the Standard tab of the Toolbox and drop them onto the **Default.aspx** page.

In our Web site, we have used four **LinkButton** controls to help the user change the mode of the Web page. Various modes of a Web page are:

- **Browse:** Refers to the default view of a Web page in which a user can view all the changes made to the content and layout of the Web page
- **Design:** Allows the end users to rearrange the components within or outside the WebPartZone
- **Catalog:** Allows the end users to restore the Web Parts controls, which were removed earlier
- **Edit:** Allows the end users to edit a Web Part, such as changing the Web Part’s title, color as well as properties

Once an end user has personalized the Web Parts controls, the changes can be seen in the Browse mode. Also, if the end user closes the Web page, then on the next visit to the Web site, the user is presented with the personalized Web page.
