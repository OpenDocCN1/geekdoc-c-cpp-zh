# Explaining ASP.NET 4.0 Provider Model

The provider model illustrates the position of providers, which work as a bridge between Data Stores, such as SQL Server and ASP.NET services, such as Membership in ASP.NET applications. Fig.ASP-1.4 shows the ASP.NET provider model.

![](bbox=[0.321, 0.23, 0.701, 0.403])

Fig.ASP-1.4

As shown in Fig.ASP-1.4 providers act as communication channels for data sources. To elaborate more on the concept of providers, let’s take the example of an online banking Web site, which allows its customers to access and modify their account information. In this case, the bank needs to maintain the records of each customer in a storage media, such as Oracle or DB2 databases. Whenever a user tries to access the information through a Web site, an appropriate provider is selected, which retrieves or updates the information in the data source. The type of provider selected depends on the type of data source used. The functionality of providers is similar to the device drivers that extract data from the hardware devices, such as floppy disc and CD.

Providers can be of two types, namely Membership and Roles providers, based on the type of services they provide. The Membership provider stores the user names and passwords, and the Roles provider stores the user roles. By default, ASP.NET 4.0 uses the AspNetSqlMembershipProvider provider. You can change the default provider by using the Web Site Administration Tool or the Microsoft Management Console (MMC), which provides various management tools called snap-ins.
