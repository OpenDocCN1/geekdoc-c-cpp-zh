WebParts controls are sets of controls of ASP.NET, which allow you to personalize a Web site, according to your individual requirements. Personalization means that you can edit a Web site to change its content, appearance, as well as behavior, dynamically at runtime. The WebParts controls were first introduced with ASP.NET 2.0, and are now available with all the new versions of ASP.NET,such as ASP.NET 3.0, ASP.NET 3.5, and ASP.NET 4.0. WebParts are objects that allow the end users to perform a variety of functions to customize the look and feel of a running Web site, such as opening or closing a control, maximizing and minimizing a Web page,adding or removing content, and changing the location of a controlby dragging it to the desired location on the Web page. A Web page can have more than one WebParts controls. You should note that the WebParts controls and WebParts are different from each other. WebParts controls are used to create WebParts for a Web site.

In this chapter, you learn about of the **WebParts** controls available in ASP.NET 4.0, such as the **WebPartManager** control, the **ProxyWebPartManager** control, the **WebPartZone** control, the **CatalogZone** control, the **EditorZone** control, and the **ConnectionsZone** control. The chapter also discusses the noteworthy properties, methods, and events of thesecontrols. Finally, you learn to create a Web site using all these WebParts controls.

Now, let's start our discussion with an overview of the **WebParts** controls.

# ## Introducing WebParts Controls

As already discussed, Web Parts controls in ASP.NET are sets of controls that work together to enable you to create a Web page which an end user can modify by changing the appearance and behavior of the user interface. In other words, Web Parts controlsenable you to build flexible websitesthat can be customized dynamically at runtime.

Table 7.1 lists various WebParts controls available in ASP.NET 4.0:

**Table 7.1: List of the WebParts Controls**

| Controls | Description |
| --- | --- |
| WebPartManager | Manages all the WebParts controls of a Web page. It has no user interface (UI), and it is invisible at runtime. |
| ProxyWebPartManager | Allows developers to specify static connections in a content page when the WebPartManager control has been specified in the master page. |
| WebPartZone | Describes a region for the WebParts controls that can be relocated, maximized, or minimized according to the requirements specified by the end-user. A page can contain one or more WebPartZone controls. |
| CatalogZone | Creates a catalog of the WebParts controls. |
| ImportCatalogPart | Imports the description file for a WebParts control (or any other ASP.NET server control that is used as a WebParts control), so that the control can be added to a Web page. |
| DeclarativeCatalogPart | Allows end-users to modify the functionality of a Web page. |
| PageCatalogPart | Restores the deleted WebParts controls on a Web page. It is the only means of restoring the deleted WebParts controls. |
| EditorZone | Edits the appearance, format, and structure of the WebParts controls on Web pages. It is the primary control used for editing. |
| LayoutEditorPart | Allows you to change the layout-oriented properties (such as state and title) for the linked WebParts controls. This control is visible when a WebParts page is in edit mode. |
| AppearanceEditorPart | Allows you to edit or change the characteristics of the WebParts controls displayed on a Web page. |
