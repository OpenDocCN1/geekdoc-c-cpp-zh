
Now, let’s discuss the directions of data flow in WPF applications, binding sources from which data can be accessed in a WPF application, and different ways to bind data to a WPF application.

## Data Flow Directions

WPF data binding supports different types of binding modes between the target and the source. The data flow in a binding can either move from the target to the source or from the source to the target. You should specify the mode of data binding while binding the data in a WPF application. You can use the **Mode** property to specify how the data will flow between the source and the target. There are four types of binding modes available in WPF:

- OneTime data binding
- OneWay data binding
- TwoWay data binding
- OneWayToSource data binding

Let’s learn about the functioning of each of these binding modes in detail.

### OneTime Data Binding

In the OneTime data binding mode, the data flows from the source to the target. The binding process occurs only once, when either the application starts or the data context changes. For example, when you do not have to change the data or add any other data to your database, you can use the **OneTime** binding mode in your application. The **OneTime** binding can only retrieve the data but cannot update the data in your database.

### OneWay Data Binding

Similar to the OneTime data binding, in the OneWay data binding mode, the data flows from the source to the target. However, the key difference between them is that in the OneWay data binding mode, the flow of data from source to target takes place once each time a change occurs in the source. This type of binding mode is useful for read-only data as it is not possible to change the data from the user interface. The OneWay binding mode in WPF is the default binding mode.

### TwoWay Data Binding

In WPF, the data in the TwoWay data binding mode moves in both directions, that is, from source to the target and from the target to the source. In the TwoWay data binding mode, you can change the data in the user interface. In this binding mode, the data from the source is sent to the target, and if there is any change in the target property value, the modified data is sent back to the source.

### OneWayToSource Data Binding

The OneWayToSource data binding mode is the reverse of OneWay data binding mode. In the OneWayToSource data binding mode, if the target property changes, the source property is updated automatically. You can use the OneWayToSource data binding mode when you want to change the data and get it updated in the source.

## Declaration of Data Binding in WPF

You can declare binding in WPF in different ways and formats. You can create binding in the XAML format, which is the markup file of a WPF application. You can also implement binding through the code-behind file of a WPF application. Another way to implement binding in WPF is to specify the **Path** property. You can specify the source value which you want to bind with the control, by using the **Path** property.

Let's learn how to implement the data binding process in a WPF application using these three ways.

### Using XAML

You can bind the WPF application with the data in the XAML format by specifying the **Binding** property, which is the markup extension. When you use the Binding property as an extension to declare binding, the declaration consists of a series of clauses. The clauses are in the **Name = Value** pair, where **Name** is the name of the **Binding** property and **Value** is the value that you set for the property. The syntax of using the **Binding** property in the XAML format is as follows:

```xml
<TextBox Text="{Binding Source={StaticResource myDataSource}, Path=ContactName}"/>
```

In the preceding syntax, the Text property of the TextBox control is bound to the data source by using the **Binding** property. The data binding process in WPF provides a simple and consistent way to present and interact with data. In WPF, you can implement binding by using the **Binding** property. Every binding in WPF has four components: binding target, binding source, target property, and a path of the source value.

### Using the Code-Behind File

Another way to implement data binding in WPF is to set the properties directly on the Binding object in code. You can call the SetBinding() method directly in your application to bind the control in code. The following code snippet shows how to implement binding in a WPF application using the code-behind file:

```csharp
this.MyText.SetBinding(TextBlock.TextProperty, Binding1);
```

In the preceding code snippet, we have bound the Text property of the TextBlock control to the Binding1 data source.
