Databases act as containers to store large amounts of data. They contain tables for data storage in which the data is stored in the form of columns and rows. Each column of a table represents a different name and is also termed as field. Each row, which is called record, stores entries or values for all attributes of the table. You can sort, index, update, and organize large number of records stored in tables. Examples of databases include Microsoft Access, Microsoft Structured Query Language (MS SQL), and Oracle. An application may need to access databases to perform various tasks, such as displaying the data in a user friendly format by retrieving the records from a database, displaying the data after processing the record retrieved from the database (for example, calculating the service duration of each employee and then displaying the records), processing the retrieved data and updating it in the database, and deleting the records from the database depending on specified condition. Data retrieval and data storage operations can be performed on databases by using the languages supported by database management systems.

ASP.NET applications must be capable of recognizing and communicating with the database to retrieve data, insert new data, and update the existing data. These tasks are performed by ASP.NET controls whose functionalities are defined by the classes in .NET namespaces. These classes have functions that use built-in features of databases to provide data services to .NET applications. Databases have their own data types to define and categorize the data. ASP.NET applications carrying out transactions with databases must enforce database compatibility with data types. ASP.NET provides various database controls, such as data-bound and datasource controls, which help in retrieving data from a database and displaying the data on a Web page.

In this chapter, you learn how to work with ADO.NET. You also learn about the use of various datasource and data-bound controls supported by ASP.NET 4.0, such as **SqlDataSource, AccessDataSource, ObjectDataSource, XmlDataSource, LinqDataSource, SiteMapDataSource, EntityDataSource, GridView, DataList, Repeater, DetailsView, FormView, ListView, DataPager, Chart,** and **QueryExtender**.

Let’s start by learning about ADO.NET.

# Working with ADO.NET

ADO.NET is a feature of .NET Framework. Any Windows or Web applications developed using .NET Framework use ActiveX Data Objects (ADO) to work with databases. As making an application to work with databases is a complex task and involves lots of small components; therefore, ADO.NET groups all the classes involved in this task under its domain to make the application work with database easily. Incorporating ADO.NET features, such as disconnected data access, in the applications has been made very simple in .NET Framework.

Traditionally, Web applications followed a connection-based model, which required continuously maintaining connection with the database. On account of maintaining a continuous link to a database, Web applications quickly consume all the system resources; thereby, reducing the efficiency and decreasing the system performance. An application that maintains connections very efficiently with 10 clients becomes significantly slow when it has to support 20 clients and finally becomes unusable when it comes to support 80 clients. ADO.NET addresses this issue with its unique disconnected data access model.

Now, let’s learn about the disconnected data model architecture used in ADO.NET for accessing data.

# Exploring Disconnected Data Architecture

The database-handling mechanisms in the .NET development environment define a methodology to create a copy of the database objects, such as tables, in the in-memory of the ASP.NET application. The application works on the copy of data stored in the local memory of the application. This shows that the application process runs in a detached mode with the database. The actual connection with the database is made only when the read, write, or update operations are performed on the database.
