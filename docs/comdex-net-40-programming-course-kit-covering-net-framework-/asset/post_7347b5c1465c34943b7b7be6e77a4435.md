Let’s now explore the new features introduced in Silverlight 4.0.

## Exploring New Features of Silverlight 4.0

In the preceding section, you have learned about some of the most common features of Silverlight. Along with these features, there are some new features introduced in Silverlight 4.0. These features are as follows:

- Supports Google Chrome browser.
- Supports Web cam and microphone.
- Supports printing options.
- Provides improved mouse support, such as **right-click** and **mouse-wheel** support.
- Supports notification to display messages to the users.
- Provides various new controls, such as **RichTextBox**, **ViewBox**, and **WebBrowser** and an enhanced **DataGrid** control.
- Includes Windows Communication Foundation (WCF) data layer enhancements.
- Includes localization enhancements with bi-directional text that enable you to set the direction of flow of any UI element. For this, you need to set the FlowDirection property that is provided with all UI elements.
- Supports Managed Extensibility Framework that facilitates you to deploy your application in multiple XAP files.
- Supports enhanced data binding.
- Provides enhanced animation effects.
- Supports clipboard and drag and drop facilities.
- Provides WCF Rich Internet Application (RIA) services. These services help in building n-tier applications by integrating the ASP.NET and Silverlight platforms together and providing you the built-in networking and data access functionality.
- Supports playing offline Digital Rights Management (DRM) protected media.

## Explaining the Silverlight Architecture

Silverlight is a combination of various existing technologies, such as HTML, JavaScript, XAML, and .NET Framework. These technologies are incorporated in Silverlight as different components and services. Fig.ASP-11.1 shows the components and services incorporated in Silverlight:

![](img/9862a98a1a2d3bb14334137965a1ec60_697_0.png)

Fig.ASP-11.1

As shown in Fig.ASP-11.1, Silverlight has two main components:

- **.NET Framework for Silverlight**: Refers to an abstract version of the Common Language Runtime (CLR), which offers basic functionalities, such as type checking, debugging, and garbage collection. It also allows you to integrate data in Silverlight applications through XML, LINQ, and LINQ to XML (XLINQ) as well as manipulate the data through serialization. The .NET Framework in Silverlight also enables you to easily access data and services at remote locations through WCF.
- **The core presentation Framework**: Refers to a component that offers features and services for designing the UI of Silverlight applications through controls, styles, templates, 2D vector graphics, animations, and multimedia. This component also allows you to accept user input through input devices, such as mouse and keyboard. It also enables you to bind data with various controls and specify the UI layout of Silverlight applications. The XAML parser is also present in the core presentation Framework to process the XAML content in Silverlight applications.

> Serialization is a process of converting a data object into a sequence of bits, so that it can be stored on a storage media, such as a database and file, and transmitted over the network.

## Assemblies and Files in Silverlight Applications

When you use Visual Studio 2010 to create Silverlight 4.0 applications, some essential assembly references and files automatically become a part of the application. You can view these assemblies in the **Solution Explorer** window, as shown in Fig.ASP-11.10:

![](img/9862a98a1a2d3bb14334137965a1ec60_701_1.png)

The assemblies that are referenced in a Silverlight 4.0 application are as follows:

- mscorlib.dll
- System.dll
- System.Core.dll
- System.Windows.dll
- System.Windows.Browser.dll
- System.Net.dll
- System.Runtime.Serialization.dll
- System.ServiceModel.dll
- System.ServiceModel.DomainServices.Client.dll
- System.ServiceModel.DomainServices.Client.Web.dll
- System.ServiceModel.Web.Extensions.dll
- System.ComponentModel.DataAnnotations.dll
- System.Xml.dll

Among these assemblies, **mscorlib.dll**, **System.dll**, and **System.Windows.dll** are essential assemblies for Silverlight 4.0 applications. The rest of the assemblies are added to handle certain common functionalities, such as working with the Web browser and XML content. You can also add references to other assemblies from the **Add Reference** dialog box, which you can open by right-clicking the name of the Silverlight application in the Solution Explorer window and selecting the **Add Reference** option from the context menu.

Along with these assemblies, some files, such as **App.xaml** and **MainPage.xaml**, are also included automatically in the **Solution Explorer** window of **Visual Studio 2010**, whenever you create a new Silverlight 4.0 application, as shown in Fig.ASP-11.11.

![](img/9862a98a1a2d3bb14334137965a1ec60_702_0.png)

Fig.ASP-11.11

As shown in Fig.ASP-11.11, the files which are included automatically in a Silverlight 4.0 application are as follows:

- **App.xaml:** Refers to the XAML file in which you can define application-level resources, such as brush and style objects.
- **App.xaml.cs:** Refers to the code-behind class for the **App.xaml** file. This file can be used to handle application-level events, such as **Application_Startup**, **Application_Exit**, and **Application_UnhandledException**.
- **MainPage.xaml:** Refers to the XAML file, which is used to define a page, similar to a page in a Web site. The **MainPage.xaml** file is by default the initial UI control, which is loaded when an application activates. You can use UI controls, such as **Button**, **Label**, and **TextBox** controls, inside the **MainPage.xaml** file to define the UI of a Silverlight application.
- **MainPage.xaml.cs:** Refers to the code-behind file of the **MainPage.xaml** file in which you can write the managed code for a Silverlight application.

Whenever you create a Silverlight application, **Visual Studio 2010** automatically creates an ASP.NET Web application to host that Silverlight application. This Web application contains **HTML**, **ASP.NET test host pages**, and a **JavaScript** helper file. You can run and test your Silverlight applications using either the HTML or the ASP.NET test page. You can view the references of some of those files in the **Solution Explorer** window, as shown in Fig.ASP-11.12.
