A workflow is a graphical representation depicting the flow of a process or a set of tasks that produces a result. Windows Workflow Foundation (WF) is one of the four foundations introduced in .NET Framework 3.0. The other three foundations are Windows Presentation Foundation (WPF), Windows Communication Foundation (WCF), and Windows CardSpace (WCS). The latest version of WF, WF 4.0, is released with many improvements, such as a Flowchart activity to implement loops and conditional branching in workflows. Moreover, WF enables you to use the built-in tools and flowcharts to perform a particular action or activity while writing predefined classes in an application. For example, to print your name on the screen, you simply need to drag the **WriteLine** activity from the **Primitives** tab of Toolbox and type your name in that activity. Now, when you run the application, your name will appear on the screen while in other platforms, such as simple Console Application of .NET, you need to write a detailed code to perform the same task. WF consists of a programming model, a runtime engine, and tools that help you to quickly and easily develop workflow-based applications for Windows. Visual Studio 2010 has built-in templates to create workflow-based applications.

This chapter begins by discussing the improvements in WF in .NET Framework 4.0. Then, you learn about workflow design principles. Next, the architecture of WF is discussed. Further, you learn how to develop a sample workflow application and how to implement conditions in workflows. Towards the end, you learn how to create and use custom activities.

Let’s begin by discussing the improvements in WF in .NET Framework 4.0.

# ## Exploring the Improvements in WF

In .NET Framework 4.0, several improvements have been made in WF to help users to easily create, execute, and maintain workflow applications. Some of the improvements in WF are as follows:

+   - Uses predefined activities, instead of classes, to perform a task, such as you can use the **SequentialWorkflowActivity** activity to initialize new task instances in a workflow
+   - Introduces a new control flow activity, called **Flowchart**, to provide an event-driven programming model
+   - Introduces the following new features to the built-in activity library:
+     - Introduces new flow control activities, such as **DoWhile**, **ForEach**, **ParallelForEach**, **Switch**, **Pick**, and **TryCatch**
+     - Adds activities, such as **Assign** and **AddToCollection** to the built-in activity library to help users to manipulate data members
+     - Adds activities, such as **TransactionScope** and **Compensate** to the built-in activity library to control transactions
+     - Introduces new messaging activities, such as **SendContent** and **ReceiveReply**
+   - Includes the following new options to run workflows:
+     - **WorkflowServiceHost**: Specifies a host for workflows
+     - **WorkflowApplication**: Specifies a host for a particular instance of a workflow
+     - **WorkflowInvoker**: Acts as a method call to invoke a workflow
+   - Introduces the **Bookmark** object that can be used for resuming a pending workflow
+   
+   After taking a look at the improvements in WF in .NET Framework 4.0, let’s discuss the WF architecture in the next section.
