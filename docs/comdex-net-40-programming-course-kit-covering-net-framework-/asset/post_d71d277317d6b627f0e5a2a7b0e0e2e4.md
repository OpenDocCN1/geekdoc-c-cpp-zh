### Auto-Implemented Properties

Visual Basic 2010 allows you to create auto-implemented properties that are used for data hiding. These are created without writing code for their Get and Set accessor functions. The Get accessor function gets the value of a variable; whereas, the Set accessor function sets the value of the variable. When you write code for an auto-implemented property, the Visual Basic compiler automatically creates a private variable to store property value in addition to creating Get and Set accessor functions for the property. The following code snippet shows how to create an auto-implemented property in Visual Basic 2010:

```vb
Property Name As String = "James"
```

The following code snippet is equivalent of the preceding code snippet that creates an auto-implemented property:

```vb
Private _Name As String = "James"
Property Name As String
    Get
        Return _Name
    End Get
    Set(ByVal value As String)
        _Name = value
    End Set
End Property
```

In the preceding code snippet, the _Name variable receives the value through the Set accessor function. The Get accessor function then returns the value of the variable when it is requested or required in the application.

### Collection Initializers

Collection initializers allow you to create collections and initialize them with a set of values. In the previous versions of Visual Basic, you need to declare collection initializer in one statement. However, in Visual Basic 2010, you can declare collection initializer in multiple statements. Collection initializers are useful in situations where you have to create collections with a set of known values, such as a set of menu options, days of a week, and names of months. A collection initializer uses the From keyword and a set of braces ({}) to declare a collection. The following code snippet shows the use of a collection initializer:

```
Dim names As New List(Of String) From
    {{1, "Peter"},
    {2, "James"},
    {3, "David"}}
```

In the preceding code snippet, we have created a collection, names, which contain a set of names.

### Implicit Line Continuation

In earlier versions of Visual Basic, a Visual Basic statement can be continued in the second line by using a space followed by an underscore character (_) at the end of the first line. The following code snippet shows the implicit line continuation:

```
Dim sampleString As String = "Hello James." _
    & "How are you?"
```

Visual Basic 2010 also allows you to continue a statement in the next line by using a space and an underscore character (_). However, in Visual Basic 2010, you can omit the use of a space and an underscore character (_) to continue a statement in multiple lines, in many cases. The cases where you can omit the use of a space and an underscore character (_) are as follows:

- After a comma (`,`), concatenation operator (`&`), opening parenthesis (`(`), and opening curly brace (`{`)
- Before a closing parenthesis (`)`) and closing curly brace (`}`)
- After an opening embedded expression (`<%=`) and before a closing embedded expression (`%>`) while using Extensible Markup Language (XML) syntax
- After assignment operators (`=`, `&=`, `:=`, `+=`, `-=`, `*=`, `/=`, `\=`, `^=`, `<<=`, `>>=`)
- After binary operators (`+`, `-`, `/`, `*`, `Mod`, `<>`, `<`, `>`, `<=`, `>=`, `^`, `>>`, `<<`, `And`, `AndAlso`, `Or`, `OrElse`, `Like`, `Xor`) in an expression
- After the `Is` and `IsNot` operators
- After a member qualifier character (`.`) and before the member name
- After an XML axis property qualifier (`.`, `@`, and `...`)
- After a less-than sign (`<`) and before and after a greater-than sign (`>`) when specifying an attribute
- Before and after query operators (`Aggregate`, `Distinct`, `From`, `Group By`, `Group Join`, `Join`, `Let`, `Order By`, `Select`, `Skip`, `Skip While`, `Take`, `Take While`, `Where`, `In`, `Into`, `On`, `Ascending`, and `Descending`)
- After the `From` keyword in a collection initializer
