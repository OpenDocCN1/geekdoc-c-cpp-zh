# Explaining Cache Dependencies

Cache dependencies allow a cache item to be validated based on an external file or some other cache item. If a cache dependency, such as an external file, is modified, the cache item is not validated and is removed from the cache.

To understand how a cache dependency works, consider a scenario in which an application reads financial data from an XML file, which is periodically updated. After reading the data, the application processes the data and creates a graph to represent it in a format, which can also be used by other applications. The application also caches the data and inserts a cache dependency in the XML file. If any modification is made in the XML file, the data stored in cache is removed and the application reads the data from the XML file and caches its updated copy.

ASP.NET provides the **System.Web.Caching.CacheDependency** class to develop custom cache dependencies. When you develop your own cache dependency, you have the advantage of using cache invalidation method to keep the cache content updated with the data contained in an external file or another cache item. This implies that if the data source of a cache item changes, the corresponding changes take place in cache item automatically. ASP.NET also provides two built-in classes of cache dependencies: **AggregateCacheDependency** and **SqlCacheDependency**. The **AggregateCacheDependency** class allows multiple dependencies to be aggregated for content, which depends on more than one resource. The **SqlCacheDependency** class allows the cached data to be dependent on a database. In Structured Query Language (SQL) cache dependency, data is removed from cache only if changes are made in the database.
