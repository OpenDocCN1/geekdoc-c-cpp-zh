## Live Semantic Errors

Semantic errors are grammatically correct statements, but syntactically incorrect. You can check the semantic errors by using the Live Semantic Errors feature. This feature has been enhanced in C# 2010 to display wavy lines representing errors and warnings for constructs. These constructs include constructs that are outside the method body, such as return types, parameter types, and default values in method declarations.

## Named and Optional Arguments

C# 2010 introduces the concept of named and optional arguments. Named arguments allow you to specify an argument for a parameter by associating the argument with the name of the parameter instead of associating it with the position of the parameter in the parameter list. On the other hand, optional arguments allow you to omit arguments for some of the parameters in a parameter list. Named and optional arguments can be used with methods, delegates, indexers, and constructors. When you use both named and optional arguments, arguments are evaluated in the order in which they appear in the parameter list. Named and optional arguments are very useful when you need to supply arguments for only a few parameters from a list of optional parameters. These arguments are especially useful in calls to COM interfaces, such as Microsoft Office Automation Application Programming Interfaces (APIs).

![](img/9862a98a1a2d3bb14334137965a1ec60_281_0.png)

> A delegate is similar to a class that is used for storing the reference of a method and invoking that method at runtime. An indexer is a class property that allows you to access a class and all the member variables of the class in the same way as used in the case of arrays. A constructor is a special method that is called automatically when the instance of a class is first created. It is used to initialize all the class members whenever the class is accessed for the first time.

Suppose you need to calculate the body mass index (BMI) of a body by calling the Calculate() method that takes weight and height of the body as its arguments. You can call the Calculate() method without using named arguments, as shown in the following code snippet:

```csharp
Calculate(200, 50);
```

Now, by using named arguments, you can call the Calculate() method in either of the following ways:

```csharp
Calculate(weight:200, height:50);
```

Or,

```csharp
Calculate(height:50, weight:200);
```

Named and optional arguments can be used together; however, you should remember that optional arguments can be followed by named arguments but named arguments cannot be followed by optional arguments.

## New Command-Line Compiler Options

You can always compile and run C# applications from command-line. After compilation, the C# compiler typically generates executable (.exe) files and dynamic link libraries (.dll) files. C# 2010 introduces two new command-line compiler options, /langversion and /appconfig. The /langversion option allows you to execute the syntax that is valid for a specified version of C#. On the other hand, the /appconfig option allows you to specify the location of application configuration file of an assembly. An assembly is the smallest deployable unit of code in .NET providing a collection of types and resources that work together to form a logical unit of functionality.

## Enhanced COM Interoperability

COM interoperability has been enhanced in C# 2010 to make it easier to call COM objects from the .NET code. Whenever a COM component is registered, the .NET Framework automatically creates a type library and special registry entries. The previous versions of .NET Framework require a large number of explicit type casts and excessive usage of ref keyword to call a COM object. However, with .NET Framework 4.0, .NET applications can easily interoperate with COM objects. In .NET Framework 4.0, features, such as dynamic types, support for named and optional arguments, and less dependency for Primary Interop Assemblies (PIAs) are attributed to the enhanced COM interoperability in C# 2010.

![](img/9862a98a1a2d3bb14334137965a1ec60_281_2.png)

> PIA is a collection of the type definition of all the types that have been implemented with COM objects in .NET applications. A COM type can be described by any number of interop assemblies; however, only one interop assembly is tagged as PIA. The publisher of the original COM type signs PIA and includes some customizations that are intended to make types easier to use from managed code.

## Introducing Keywords and Identifiers

In C#, you work with predefined and user-defined words or names. The words or names that are predefined are called keywords, while those that are user-defined are called identifiers. An identifier is the name that you give to the program elements created in a program. For example, the names that you give to variables and arrays are identifiers. A variable is a placeholder to store a single value of a particular kind. An array is an ordered collection of a particular kind of values.

Note that you cannot define an identifier that is the same as a keyword. This is because keywords are those words, which are defined in the programming language to perform a particular task or indicate some programming aspect, such as creating a class. C# has many keywords that are automatically recognized by its compiler. In C#, there are two types of keywords, reserved and contextual. A reserved keyword performs the same predefined task wherever you use it in your C# program; whereas, a contextual keyword may perform different tasks based on the context in which you use it.

## Describing Operators and Operator Precedence

While developing programs in C#, you are required to perform various operations, such as addition, multiplication, comparison, and concatenation, on the data used in a program. C# 2010 provides you a number of operators to perform the different operations in the program. An operator is a symbol or word that is reserved in the programming language to perform some predefined operation. For example, * is used to multiply two values.

In C#, operators take one or more number of operands, which refer to the values, variables, or expressions. An expression refers to a combination of variables, constants, keywords, and operators that evaluates to a value of a particular data type. Every operator takes its operands, performs an operation on the operands, and returns the result of the operation. The number and the data type of operands may vary from one operator to another. Depending on the number of operands that an operator takes, operators in C# are classified as follows:

- **Unary operators:** Refer to the operators that take only one operand, for example, the increment operator (`++`) that increments the value of operand by one.
- **Binary operators:** Refer to the operators that take two operands, for example, the division operator (`/`) that divides the first operand by the second operand.
- **Ternary operators:** Refer to the operators that take three operands. In C#, the conditional operator (`?:`) is the only ternary operator that returns either the second operand or the third operand depending on the Boolean value of the first operand.

![](img/9862a98a1a2d3bb14334137965a1ec60_283_1.png)

> Based on the context in which operators are used, certain operators can act as unary or binary operator. For example, when you prefix the + operator to a number, it acts as a unary operator indicating that the number is a positive number. However, when you use the + operator between two numbers, it acts as a binary operator, which adds the two numbers and returns the result.

A single expression can involve multiple operations, such as addition, multiplication, and division; therefore, you can have multiple operators in a single expression. While evaluating such expressions, the language compiler uses the precedence to determine which operation to perform first. Every operator in C# has a precedence level. Depending on the precedence level, the operators are evaluated. Operators with higher precedence are evaluated first, while operators with lower precedence are evaluated later.
