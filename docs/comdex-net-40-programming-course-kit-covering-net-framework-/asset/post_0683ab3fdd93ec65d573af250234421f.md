
## Robust Database-Driven Functionality

A software program is called robust if it is capable to work not only under the normal but also heavy-load and stressful conditions. Earlier, retrieving data from a database through a software is an error-prone and time consuming process. Moreover, in cases where a large amount of data is to be retrieved, the software often used to hang, disconnect from the database, or throw an exception. ASP.NET is mainly introduced to develop Web applications that can interact with a database. It is a robust program software that can connect and interact with multiple databases simultaneously. ASP.NET uses the ADO.NET (ADO stands for ActiveX Data Objects) technology, which is especially launched with .NET framework by Microsoft to handle all types of database-related queries, such as inserting and updating data.

## Faster Execution of Web Sites

ASP.NET Web sites are much faster than those created by using earlier technologies. Early programming languages, such as COBOL and BASIC, used to convert the source code to machine code through an interpreter. The main disadvantage of this kind of a program is that it runs slower than the compiled program, when interpreted. ASP.NET, on the other hand, needs a compiler to convert source code in the machine code, resulting in faster execution of code. Caching refers to the technique of storing information in a reserved section of the main memory or an independent high-speed storage device. Commonly-visited Web pages are cached for a predefined period to improve the performance of the Web site. Caching improves the performance of the Web site since it allows you to access content from the cache itself, which is quicker than if you were to retrieve the content from the server on each request.

## Memory Leak and Deadlock Protection

Now developers need not bother about errors, such as deadlocks and memory leaks because ASP.NET can automatically recover from these errors so that your Web site can always remain available to users.

Memory leak is a situation in which a program component fails to release memory when the memory is no longer needed. A deadlock is a situation in which two or more processes wait for each other to release a resource held by the other; as a result, none of the processes ever finishes.

## Easy Deployment

An application is deployed to ensure simple and easy installation of the application files on a client computer. .NET framework provides easy methods to deploy a Web site. Using ASP.NET 4.0, you can deploy a Web site by simply copying the Web site to the destination Web server. Unlike in the previous versions of ASP.NET, where you were required to use the regsvr32 tool to register any component, there is no such requirement in ASP.NET 4.0, which allows you to directly deploy the component.

## Interoperability

The interoperability feature of ASP.NET 4.0 allows you to develop a Web application using multiple programming languages. Some examples of languages that are supported by .NET framework are Visual Basic and Visual C#. The following are the benefits of using the interoperability feature while developing a Web application:

- Code modules written in one language can be used by a Web site written in another language.
- The flexibility in language allows developers to select the appropriate language for specific tasks. For example, PERL is preferred for regular expressions and COBOL for business applications.
- All languages that are supported by the .NET framework are equal in performance.

## Exploring New Features in ASP.NET 4.0

ASP.NET 4.0 was released along with Visual Studio 2010 on April 12, 2010. It uses the same engine as that of ASP.NET 3.5, with some additional features. ASP.NET 4.0 has simplified the process of building Web sites, making it easier than ever. Now let’s discuss the following new features added to ASP.NET 4.0:

- ASP.NET Core Services
- ASP.NET Web Forms
- Dynamic Data
- ASP.NET Chart Control
- Microsoft AJAX Functionality
- Support for Model-View-Controller (MVC) based Web Applications
- Improved Cascading Style Sheet Compatibility

Let's discuss these features one by one.

### ASP.NET Core Services

The ASP.NET 4.0 core services include features, such as output caching and session-state storage. The benefits of the ASP.NET core services are as follows:

- **Refactoring of web.config file:** Specifies that in this version of ASP.NET, the major configuration elements of the web.config file have been moved to the machine.config file. This implies that the web.config file in this new version of ASP.NET is either empty or consists of some of the basic code, which specifies the version of the Visual Studio framework the application is targeting. This has been done because with the new features being added in ASP.NET, such as AJAX, routing, and integration with IIS 7.0, the process of configuration or starting a new Web application has become difficult. Therefore, the major configuration settings have been moved to the machine.config file so that the application can inherit the settings and run without any difficulty.
- **Output caching:** Enables you to configure one or more output cache providers. The output caching feature in ASP.NET enables the developers to store the generated output of controls and HTTP responses in the memory. This is very helpful as in case of subsequent Web requests, the content can be retrieved from the output. However, the output caching feature was not helpful in the previous versions of ASP.NET as in situations of heavy traffic on the server; the memory required for output caching can affect the functioning of other Web applications. Therefore, in ASP.NET 4.0, you can select different output-cache providers for different controls. This implies that the developers can store the page responses outside the ASP.NET worker process by fully supporting the provider model.
- **Auto-start Web application:** Provides a better approach for starting an application pool, initializing an ASP.NET application, and accepting HTTP requests. In the earlier versions of ASP.NET, while loading a large amount of data or performing advanced initializing processing, you needed to run initialization code in the Application_Load method in the Global.asax file. However, in ASP.NET 4.0, a new feature called auto-start has been added, which solves this problem. This feature is available when ASP.NET 4.0 runs on IIS 7.5 and Windows Server 2008.
- **Redirecting a page:** Removes the unnecessary round trip made by the browser for temporary redirects. In the previous versions of ASP.NET, the Response.Redirect method was used to forward a request to a new URL. This method uses the HTTP 302 (temporary redirect) response, which results in an extra HTTP round trip. In ASP.NET 4.0, a new RedirectPermanent helper method has been introduced, which uses the HTTP 301 Moved Permanently response and avoids the round trip.
- **Compressing session state:** Reduces the size of the session-state data. In ASP.NET, there are two options that help in storing session state in a Web form. In the first option, the session-state provider invokes an out-of-process session-state server. In the second option, the session-state provider stores the data in Microsoft SQL Server database.
- **Range of allowable URLs:** Refers to the increase in the size of application URLs. In the previous versions of ASP.NET, the maximum URL path length was 260 characters. In ASP.NET 4.0, you have to increase the URL path length by using the two new HttpRuntime configuration attributes, which are maxRequestLength and maxQueryStringLength.

### ASP.NET Web Forms

The Web Forms form an integral part of ASP.NET applications. In ASP.NET 4.0, the following new features are introduced in Web Forms:

- Setting meta tags by using the MetaKeywords and MetaDescription properties of the Page class.
- Disabling view state for all controls or enabling view state for individual controls on a page by using the ViewStateMode property of the Control class. This implies that if the view state is disabled for a page, you can use the ViewStateMode property to enable view state for an individual control.
- Introducing a new feature called browser capabilities that provide support for new browsers and devices. In ASP.NET, the support for browser applications is represented by HttpBrowserCapabilities object in the HttpRequest.Browser property. In ASP.NET 4.0, the browser files are updated so that they support the new browsers and devices, such as Google Chrome, Research in Motion BlackBerry smart phones, and Apple iPhone.
- Providing support for custom code to determine browser capabilities. This new feature of ASP.NET 4.0 is referred to as browser capabilities providers, in which you can define the browser capabilities in an XML file, which resides in a machine-level or application-level folder.

Adding built-in support for routing with Web Forms. The routing feature in an ASP.NET application helps you to configure an application to use URLs and not specify the physical file names. The various improvements in routing in ASP.NET 4.0 are:

- No need to write a custom route handler as the PageRouteHandler class is now a simple HTTP handler class, which can be used while defining routes.
- Improvements in HttpRequest, RequestContext, and Page.RouteData properties so that it is easier to access information in the URL parameters.
- No change required in the web.config file to enable routing.

Introducing the ClientIDMode property that helps in writing the client script that references HTML elements for server controls. The ClientIDMode property helps you in specifying how the client ID is generated for controls. The ClientIDMode property is set at the page level, when you want to define a default value for all controls in the page. The default value of the ClientIDMode property is AutoID at the page level and Inherit at the control level. If you want to define a default setting for the ClientIDMode property, so that the setting is common for all controls in all pages in an application, you can set the ClientIDMode value in the configuration file.

Improving the GridView and ListView controls. In the previous versions of ASP.NET, if you select the 4th item on the 2nd page and then move to the 3rd page, the 4th item in the 3rd page would also get selected. This was because the row selection in a GridView or ListView control was based on the row index on the page. This problem has been solved in ASP.NET 4.0 by including a new feature known as persisted selection in the GridView and ListView controls. This feature can be enabled by setting the EnablePersistedSelection property of the control to True. In addition to this, the earlier version of the ListView control required you to specify a layout template, which contained a server control with a known ID. This has been removed in the new version of the ListView control, making it easy to work with the control.

Introducing the QueryExtender control that helps in making filtering easy. In ASP.NET, filtering excludes data, which do not meet a specified criterion, from being displayed in the data source control. This requires you to use the Where clause. However, in the LinqDataSource control, the Where clause was not able to expose the full functionality. Therefore, in this version of ASP.NET, the QueryExtender control has been introduced, which provides the following advantages:

- Provides better filtering of data in comparison to using the Where clause.
- Provides adaptability with not only the LinqDataSource control but also with EntityDataSource control.
- Provides multiple options to filter data, which can be used either individually or together.
- Eliminating exceptions that used to arise in the earlier versions of ASP.NET with respect to markup code that did not conform to HTML, XHTML, or their accessibility standards.
