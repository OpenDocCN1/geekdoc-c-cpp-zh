The preceding example is a very simple one, but in real time programming, eliminating logical errors is not so easy. The debugger mechanism helps you in tracing any logical error in the application. It runs the code in the break mode, which helps to break the program line-by-line and see the values that a property or variable is holding.

# Handling Exceptions

An exception, also called runtime error, is an abnormal or unexpected condition encountered by an application during the execution process. It arises because of some abnormal conditions, such as division of a number by zero or passing a string to a variable that holds an integer value. Whenever compiler encounters such type of exception, it creates an exception object and stores the information about the exception in that object. Exceptions occur during runtime; therefore, you cannot correct them at that time and your application terminates abruptly. To avoid such type of condition, you need to provide a handler to your program during implementation time. Exception handler is a mechanism to handle an exception by providing an alternate executable path, when the application fails to execute in the desired manner. It is also known as exception handling.

All exceptions derive from the base class Exception. Exceptions are mainly of two categories in the .NET Framework. The first category includes the exceptions generated by Common Language Runtime (CLR) and such exceptions are called system exceptions. The exceptions belonging to this category are derived from the SystemException class. The second category includes exceptions that are generated by a user's program and the exceptions in this category are called application exceptions. The exceptions of this category are derived from the ApplicationException class.
