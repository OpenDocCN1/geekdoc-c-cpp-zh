
## CHAPTER 6: Database Controls

**In this Chapter:**

- Working with ADO.NET
- Introducing DataSource Controls
- Working with Data-Bound Controls

Databases act as containers to store large amounts of data. They contain tables for data storage in which the data is stored in the form of columns and rows. Each column of a table represents a different name and is also termed as field. Each row, which is called record, stores entries or values for all attributes of the table. You can sort, index, update, and organize large number of records stored in tables. Examples of databases include Microsoft Access, Microsoft Structured Query Language (MS SQL), and Oracle. An application may need to access databases to perform various tasks, such as displaying the data in a user friendly format by retrieving the records from a database, displaying the data after processing the record retrieved from the database (for example, calculating the service duration of each employee and then displaying the records), processing the retrieved data and updating it in the database, and deleting the records from the database depending on specified condition. Data retrieval and data storage operations can be performed on databases by using the languages supported by database management systems.

ASP.NET applications must be capable of recognizing and communicating with the database to retrieve data, insert new data, and update the existing data. These tasks are performed by ASP.NET controls whose functionalities are defined by the classes in .NET namespaces. These classes have functions that use built-in features of databases to provide data services to .NET applications. Databases have their own data types to define and categorize the data. ASP.NET applications carrying out transactions with databases must enforce database compatibility with data types. ASP.NET provides various database controls, such as data-bound and datasource controls, which help in retrieving data from a database and displaying the data on a Web page.

In this chapter, you learn how to work with ADO.NET. You also learn about the use of various datasource and data-bound controls supported by ASP.NET 4.0, such as **SqlDataSource, AccessDataSource, ObjectDataSource, XmlDataSource, LinqDataSource, SiteMapDataSource, EntityDataSource, GridView, DataList, Repeater, DetailsView, FormView, ListView, DataPager, Chart,** and **QueryExtender**.

Let’s start by learning about ADO.NET.

### Working with ADO.NET

ADO.NET is a feature of .NET Framework. Any Windows or Web applications developed using .NET Framework use ActiveX Data Objects (ADO) to work with databases. As making an application to work with databases is a complex task and involves lots of small components; therefore, ADO.NET groups all the classes involved in this task under its domain to make the application work with database easily. Incorporating ADO.NET features, such as disconnected data access, in the applications has been made very simple in .NET Framework.

Traditionally, Web applications followed a connection-based model, which required continuously maintaining connection with the database. On account of maintaining a continuous link to a database, Web applications quickly consume all the system resources; thereby, reducing the efficiency and decreasing the system performance. An application that maintains connections very efficiently with 10 clients becomes significantly slow when it has to support 20 clients and finally becomes unusable when it comes to support 80 clients. ADO.NET addresses this issue with its unique disconnected data access model.

Now, let’s learn about the disconnected data model architecture used in ADO.NET for accessing data.

### Exploring Disconnected Data Architecture

The database-handling mechanisms in the .NET development environment define a methodology to create a copy of the database objects, such as tables, in the in-memory of the ASP.NET application. The application works on the copy of data stored in the local memory of the application. This shows that the application process runs in a detached mode with the database. The actual connection with the database is made only when the read, write, or update operations are performed on the database.

.NET Framework creates a data layer, named ADO.NET data layer, which contains all the logically independent physical data storage services that help in creating connection with the database. The services of this layer are used to create ASP.NET applications that can work with databases. These services are as follows:

- Connecting to a database
- Querying the database by using SQL statements, such as the Select statement
- Inserting new data into the database
- Updating records in the database
- Deleting records from the database

Now, let’s learn how to access data using ADO.NET.

### Accessing Data using ADO.NET

Accessing data in an application from external data sources, such as SQL Server consists of the following tasks:

- Connecting to a database
- Accessing data from the database
- Accessing database information, such as structure or layout of data (such as tables and the data types defined for the columns), constraints (such as the data in which null values are not allowed), and data relations (such as relating columns between two or more tables)

The connection with the database can be established with the help of providers. These providers are vendor-specific, such as SQL Server 2005 from Microsoft and Oracle 9i from Oracle Corporation. To communicate with different databases, the .NET environment uses different providers. Providers consist of three components, connection, commands for databases, and database adapters. You can establish a connection of a database with an application to perform two basic operations, reading and writing. To perform these operations, ADO provides the following two objects:

- **DataReader:** Allows ASP.NET applications to only read the data
- **DataAdapter:** Allows ASP.NET applications to use data in bi-directional mode, that is, reading and writing data from and to the database

As every task performed by the .NET environment is accomplished by using .NET base classes, these classes are defined in the .NET namespace hierarchy.

### Introducing DataSource Controls

The datasource controls allow you to work with various data sources, such as a SQL database or an Extensible Markup Language (XML) file. It connects to data sources, retrieves data from them, and then makes this data available for other controls to bind to, without ever bothering about writing the code. Datasource controls are extensible, implying that you can create your own datasource controls and connect them with different data sources to provide additional functionality. The built-in datasource controls provided by .NET Framework 4.0 are as follows:

- SqlDataSource
- AccessDataSource
- ObjectDataSource
- XmlDataSource
- LinqDataSource
- SiteMapDataSource
- EntityDataSource

Now, let’s discuss each datasource control in detail.

### The SqlDataSource Control

The SqlDataSource control enables you to work with ADO.NET managed data providers that provide access to a Microsoft SQL Server database. It is inherited from the SqlDataSource class that defines several properties and methods that the SqlDataSource control supports. Some noteworthy properties of the SqlDataSource class are given in Table 6.1.

**Table 6.1: Noteworthy Properties of the SqlDataSource Class**

| Property | Description |
|---|---|
| ConnectionString | Retrieves or sets the ADO.NET provider-specific connection string that the SqlDataSource control uses to connect to an underlying database |
| SelectCommand | Retrieves or sets the SQL string that the SqlDataSource control uses to retrieve data from the underlying database |
| InsertCommand | Retrieves or sets the SQL string that the SqlDataSource control uses to insert data into the underlying database |
| DeleteCommand | Retrieves or sets the SQL string that the SqlDataSource control uses to delete data from the underlying database |
| UpdateCommand | Obtains or specifies the SQL string that the SqlDataSource control uses to update data in the underlying database |

Table 6.2 lists the noteworthy methods of the SqlDataSource class:

**Table 6.2: Noteworthy Methods of the SqlDataSource Class**

| Method | Description |
|---|---|
| DataBind | Binds a SQL data source to the SQL Server DataSource control |
| Select | Retrieves the records or data from a SQL Server database |
| Insert | Inserts the records or data into a SQL Server database |
| Delete | Deletes the records or data from a SQL Server database |
| Update | Updates the records or data in a SQL Server database |

The SqlDataSource class represents the SqlDataSource control that enables you to work with Microsoft SQL Server. This datasource control is helpful in retrieving data from a relational database, such as SQL server, in the data-bound controls, such as the GridView control. The SqlDataSource control supports sorting, filtering, and paging data when the data is returned in a control.
