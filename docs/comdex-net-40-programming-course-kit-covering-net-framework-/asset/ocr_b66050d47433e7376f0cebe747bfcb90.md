.NET Framework creates a data layer, named ADO.NET data layer, which contains all the logically independent physical data storage services that help in creating connection with the database. The services of this layer are used to create ASP.NET applications that can work with databases. These services are as follows:

+   - Connecting to a database
+   - Querying the database by using SQL statements, such as the Select statement
+   - Inserting new data into the database
+   - Updating records in the database
+   - Deleting records from the database

Now, let’s learn how to access data using ADO.NET.

# Accessing Data using ADO.NET

Accessing data in an application from external data sources, such as SQL Server consists of the following tasks:

+   - Connecting to a database
+   - Accessing data from the database
+   - Accessing database information, such as structure or layout of data (such as tables and the data types defined for the columns), constraints (such as the data in which null values are not allowed), and data relations (such as relating columns between two or more tables)

The connection with the database can be established with the help of providers. These providers are vendor-specific, such as SQL Server 2005 from Microsoft and Oracle 9i from Oracle Corporation. To communicate with different databases, the .NET environment uses different providers. Providers consist of three components, connection, commands for databases, and database adapters. You can establish a connection of a database with an application to perform two basic operations, reading and writing. To perform these operations, ADO provides the following two objects:

+   - **DataReader:** Allows ASP.NET applications to only read the data
+   - **DataAdapter:** Allows ASP.NET applications to use data in bi-directional mode, that is, reading and writing data from and to the database

As every task performed by the .NET environment is accomplished by using .NET base classes, these classes are defined in the .NET namespace hierarchy.

# Introducing DataSource Controls

The datasource controls allow you to work with various data sources, such as a SQL database or an Extensible Markup Language (XML) file. It connects to data sources, retrieves data from them, and then makes this data available for other controls to bind to, without ever bothering about writing the code. Datasource controls are extensible, implying that you can create your own datasource controls and connect them with different data sources to provide additional functionality. The built-in datasource controls provided by .NET Framework 4.0 are as follows:

+   - SqlDataSource
+   - AccessDataSource
+   - ObjectDataSource
+   - XmlDataSource
+   - LinqDataSource
+   - SiteMapDataSource
+   - EntityDataSource
