Before leaving this topic, look at another example of a compilation error. Load hello.c into your editor and make the following changes:

+   1. Replace the semicolon at just the end of line 5.

+   2. Delete the double quotation mark just before the word Hello.

Save the file to disk and compile the program again. This time, the compiler will display error messages similar to the:

```
hello.c(5) : Error: undefined identifier 'Hello'
hello.c(7) : Lexical error: unterminated string
Lexical error: unterminated string
Lexical error: unterminated string
```

Fatal error: premature end of source file

The first error message finds the error correct, locating it in line 5 at the word Hello. The error message undefined identifier means that the compiler doesn't know what to make the word Hello because it is no longer enclosed in quotes. However, what about the other four errors reported? These errors, meaning of which you don't need to worry about now, illustrate that a single error in a C program can sometimes cause multiple errors.

The lesson to learn from all this is as follows: If the compiler reports multiple errors, you can find only one, go ahead and fix that and reconcile. You might find that your single correction is all that's needed, and the program will compile without errors.

# Linker Error Messages

Linker errors are relatively rare and usually result from misspelling the name of a C library function. In this case, you get an Error: undefined symbols: error message, followed by the misspelled name (preceded by an underscore). When you correct the spelling, the problem should go away.
