
# Summary

After reading this lesson, you should feel confident selecting C as your programming language is a wise choice. C offers an unparalleled combination of power, popularity, and portability. These factors, together with C's close relationship to the C++ object-oriented language as well as Java and C#, make C unbeatable.

This lesson explained the various steps involved in writing a C program—the process known as program development. You should have a clear grasp of the edit-compile-link-test cycle, as well as the tools to use for each step.

Errors are an unavoidable part of program development. Your C compiler detects errors in your source code and displays an error message, giving both the nature and the location of the error. Using this information, you can edit your source code to correct the error. Remember, however, that the compiler can't always accurately report the nature and location of an error. Sometimes you need to use your knowledge of C to track exactly what causes a given error.

# Q&A

- *If I want to give someone a program I wrote, which files do I need to give him?*

- *One of the nice things about C is that it is a compiled language. This means that after the source code is compiled, you have an executable program. This executable program is a stand-alone program. If you wanted to give hello to all your friends with computers, you can. All you need to give them the executable program, hello.exe. They don't need the source file, hello.c, or the object file, hello.obj. They don't need to know a C compiler, or those people you give the executable to use the same type of machine as you—such as a PC, Macintosh, Linux machine, and so on.*

- *After I create an executable file, do I need to keep the source file (.c) or object file (.obj)?*

- *If you get rid of the source file, you have no way to make changes to the program in the future, so you should keep this file. The object files are a different matter. There are reasons to keep object files, but they are beyond the scope of what you're doing now. For now, you can get rid of your object files after you have created your executable file. If you need the object file, you can recompile the source file. Most IDEs create files in addition to the source file, the object file (.obj or .o), and as long as you keep the source file (.c), you can always create the other files.

# Q If my compiler came with an editor, do I have to use it?

A Definitely not. You can use any editor, as long as it saves the source code in text format. The compiler came with an editor, you should try to use it. If you like a different editor better, use it. I use an editor that I purchased separately, even though my compilers have their own owners. The editors that come with compilers are getting better. Some of them automatically format your C code. Others color-code different parts of your source file to make it easier to find errors.

# Q What do I do if I have only a C++ compiler and not a C compiler?

A As mentioned in this, C++ is a superset of C. This means that you can use a C++ compiler to compile C programs.

# Q Can I ignore warning messages?

A Some warning messages don't affect the program runs, and some do. If the compiler gives you a warning message, it's a signal that something isn't right. Most compilers let you set the warning level. By setting the warning level, you can get only the serious warnings, or you can get all the warnings, including the most minute. Some compilers offer various levels in-between. In your programs, you should look at each warning and make a determination. It's always best to try to write all your programs with absolutely no warnings or errors. (With an error, your compiler won't create the executable file.)

# A Short C Program

Listing 2.1 presents the source code for bigyear.c. This is a simple program. All it does accept a year of birth from the keyboard and calculate what year person turns a specific age. At this stage, don't worry about understanding the details of how the program works. The point is for you to gain familiarity with the parts of a program so that you can better understand the listings in this book.

Before looking at the sample program, you need to know what a function is because functions are central to C programming. A function is an independent section of program code that performs a certain task and has been assigned a name. By referencing the function's name, your program can execute the code in the function. The program also can send information, called arguments, to the function and the function can return information to the main part of the program. The two types of C functions are library functions, which are part of the compiler package, and user-defined functions, which you, the programmer, learn about both types in this book.

Note that, with all the listings in this book, the line numbers in Listing 2.1 are not part of the program. They are included only for identification purposes, so don't type them.
