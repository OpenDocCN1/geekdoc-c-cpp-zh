In practical terms, this buffer operation means that, during program execution, data that your program wrote to the disk might still be in the buffer, not on the disk. If your program hangs up, if there's a power failure, or if some other problem occurs, the data that's still in the buffer might be lost, and you won't know what's contained in the disk file.

You can flush a stream's buffers without closing it by using `fflush()` or `flushall()` functions. Use `fflush()` when you want a file's buffer to be written while still using the stream. Use `flushall()` to flush the buffers of all open streams. The prototypes of these two functions are as follows:

```
int fflush(FILE *fp);
flushall(void);
```

The argument `fp` is the FILE pointer returned by `fopen()` when the file was opened. If a file were opened for writing, `fflush()` writes its to disk. The buffer is cleared. The function `fflush()` returns 0 on success or EOF if an error occurs. The function `flushall()` returns the number of open streams.

# Understanding Sequential Versus Random File Access

Every open file has a position indicator associated with it. The position specifies where read and write operations take place in the file. The position is always given in terms of bytes from the beginning of the file. When a new file is opened, the position indicator is at the beginning of the file, position 0. (Because the file is new and has a length of 0, there's no other location to indicate.) When an existing file is opened, the position indicator is at the end of the file if the file is opened in append mode, or at the beginning of the file if it is opened in any other mode.
