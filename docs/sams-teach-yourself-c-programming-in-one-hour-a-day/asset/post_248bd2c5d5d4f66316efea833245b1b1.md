# File Buffering: Closing and Flushing

When you finish using a file, you should close it using the `fclose()` function presented earlier in the list. Its prototype is

```c
int fclose(FILE *fp);
```

The argument `fp` is the FILE pointer associated with the stream; `fclose()` returns 0 on success or -1 error. When you close a file, the file's buffer is flushed (written to the file). You can also close all open streams except the standard ones (stdin, stdout, stderr), by using `flushall()`. Its prototype is

```c
int flushall(void);
```

This function flushes all streams and returns the number of streams closed. When a program terminates (either by reaching the end of `main()` or by executing the `exit()` function), all streams are automatically flushed and closed. However, it's a good idea to close streams—particularly those linked to disk—as soon as you finish with them. When you create a stream linked to a disk file, a buffer is automatically created and associated with the stream. A buffer is a block of memory used for temporary storage of data written to or from the file. Buffers are necessary because disk drives are block-oriented devices, which operate most efficiently when data is read and written in blocks. The size of the buffer, depending on the hardware used, is from a few hundred to a thousand bytes. You don't need to be concerned about the exact size. The buffer associated with a file serves as an interface between the stream (which is character-oriented) and the disk hardware (which is block-oriented). As your program writes data to the stream, the data is saved in the buffer until the buffer is full, and the entire contents of the buffer are written as a block to the disk. An analogous process occurs when reading data from a disk file. The creation and operation of the buffer is handled by the operating system and is entirely automatic; you don't have to be concerned with it (C offers some functions for buffer manipulation, but they are beyond the scope of this book).

In practical terms, this buffer operation means that during program execution, data that your program wrote to the disk might still be in the buffer, not on the disk. If your program hangs up, there's a power failure, or if some other problem occurs, the data that is still in the buffer might be lost, and you won't know what was contained in the disk file.

You can flush a stream's buffers without closing it by using the `fflush()` or `flushall()` functions. Use `fflush()` when you want a file's buffer to be written while still using the stream. Use `flushall()` to flush the buffers of all open streams. The prototypes of these two functions are as follows:

```c
int fflush(FILE *fp);
int flushall(void);
```

The argument `fp` is the FILE pointer returned by `fopen()` when the file was opened. If a file were opened for writing, `fflush()` writes its buffer to disk. The buffer is cleared. The function `fflush()` returns 0 on success or EOF if an error occurs. The function `flushall()` returns the number of open streams.

# Understanding Sequential Versus Random File Access

Every open file has a position indicator associated with it. The position specifies where read and write operations take place in the file. The position is always given in terms of bytes from the beginning of the file. When a new file is opened, the position indicator is at the beginning of the file, position 0 (Because the file is new and has a length of 0, there's no other location to indicate). When an existing file is opened, the position indicator is at the end of the file if the file is opened in append mode, or at the beginning of the file if it is opened in any other mode.

The I/O functions, covered earlier in this lesson, make use of the position indicator, although the manipulations go on behind the scenes. Writing and reading operations occur at the location of the position indicator and update the position indicator as well. For example, if you open a file for reading, and 10 bytes are read, you input the first 10 bytes in the file (by bytes at positions 0 through 9). After the read, the position indicator is at 10. Thus, if you want to read all the data in a file sequentially or write data to a file sequentially, you don't need to be concerned about the position indicator. The I/O functions take care of it automatically.

When you need more control, use the library functions that enable you to determine and change the value of the position indicator. By controlling the position indicator, you can perform random file access. Here, *random* means that you can read data from or write data to any position in a file without reading or writing all the preceding data.

# fseek() and rewind() Functions

To set the position indicator to the beginning of the file, use the library function `rewind()`. Its prototype is in `stdio.h`.

```c
void rewind(FILE *fp);
```

The argument `fp` is the FILE pointer associated with the stream. After `rewind()` is called, the file's position indicator is set to the beginning of the file (byte 0). Use `rewind()` if you've read some data from a file and you want to start reading from the beginning of the file without closing and reopening the file.

To determine the value of a file's position indicator, use `ftell()`. This function's prototype, in `stdio.h`, reads

```c
long ftell(FILE *fp);
```

The argument `fp` is the FILE pointer returned by `fopen()` when the file was opened. The function `ftell()` returns a type `long` that gives the current file position in bytes from the start of the file (the first byte is at position 0). If an error occurs, `ftell()` returns `-1` (a type `long -1`).
