# Analysis

The list_it.c program in Listing 2.2 displays C programs that you have saved. These listings display on the screen with line numbers added. Looking at this list, you can summarize where the different parts are. The main() function is in lines 8 through 32. Lines 2 and 3 have #include directives. Lines 6, 10, and 11 have variable definitions. Line 4 defines BUFF_SIZE as 256, the size for buffers. The advantage of doing this is that if the buffer size changes, you only need to adjust this one line and all lines using will update. If you hardcode a number like 256, you'd have to search all lines of code to make sure all match.

A prototype, void display_usage(void), is in line 5. This program has many statements (lines 13, 15, 16, 19, 21, 22, 25, 27, 28, 30, 31, and 37). A function definition for display_usage() fills lines 34 through 38. Braces enclose blocks throughout the program. Finally, only line 1 has a comment. In most programs, you should probably include more than one comment.

list_it.c calls many functions. It calls only one user-defined function, display_usage(). The library functions that it uses are fopen() in line 19; printf() in lines 21, 28, 36, and 37; fgets() in line 27; and fclose() in line 30. These library functions are covered in more detail throughout this book.

# Q&A

Q What effect do comments have on a program?

Comments are for programmers. When the compiler converts the source code to object code, it throws the comments and the white space away. This means that they have no effect on the executable program. A program with a lot of comments executes just as fast as a program with few comments. Comments do make your source file bigger, but this is usually of little concern. To summarize, you should use comments and white space to make your source code as easy to understand and maintain as possible.

Q What is the difference between a statement and a block?

A block is a group of statements enclosed in braces ({}). A block can be used in most places that a statement can be used.

Q How can I find out which library functions are available?

Many compilers come with online documentation dedicated specifically to documenting the library functions. They are usually in alphabetical order. Appendix C, “Common C Functions,” lists many of the available functions. After you begin to understand more of C, it would be a good idea to read that appendix so that you don't reinvent a library function. (There's no use reinventing the wheel!)
