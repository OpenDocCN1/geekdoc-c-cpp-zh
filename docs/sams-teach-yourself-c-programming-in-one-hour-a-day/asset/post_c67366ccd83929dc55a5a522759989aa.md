# Allocating Memory Space

The C library contains functions for allocating memory space at runtime, a process called dynamic memory allocation. This technique can have significant advantages over explicitly allocating memory by declaring variables, structures, and arrays. The latter method requires you to know exactly much memory you need when you're writing the program. Dynamic memory enables the program to run, while it's executing, demands for memory such as user input. All the functions for handling memory allocation require the header file stdlib.h; note that all allocation functions return type void pointer. As you learned in Lesson 19, void pointer must be cast to the appropriate type before being used.

# Allocating Memory Space

Before moving on to the details, a few words in order about memory allocation. What exactly does it mean? Each computer has a certain amount of memory (random access, or RAM) installed. This amount varies from system to system. When you run a program, whether you wrote it yourself or is loaded from the computer, the memory space the program occupies, as well as space for data declared in the source code, how much memory is available for allocation? All depends. If you run a large program on a system with a modest amount of memory, the free memory will be small. Conversely, when a small program runs on a multigabyte system, plenty of memory will be available. This means that your programs can't make any assumptions about memory availability. When a memory allocation is called, it must return its value to ensure that the memory was allocated successfully. In addition, your programs must gracefully handle the situation when memory allocation request fails. Later in this lesson, learn a technique for determining how much memory is available. Also note that your operating system might have an effect on memory. Some operating systems make only a portion of physical RAM available. In contrast, UNIX usually makes all physical RAM available. To complicate further, some operating systems, such as Windows, provide virtual memory on the hard disk as if it were RAM. In this situation, the memory available to a program includes not only the RAM but also the memory space on the hard disk. For the most part, these operating system differences in memory allocation should be transparent to you. If you use one of the C functions to allocate memory, it either succeeds or fails, and you don’t need to worry about details.

# Allocating Memory with the malloc() Function

In earlier lessons, you learned how to use the malloc() function to allocate storage space. The malloc() function isn’t limited to allocating memory for strings, of course; it can allocate for any need. This function allocates memory. Recall that the malloc() prototype is:

```
void *malloc(size_t num);
```

The argument size_t is defined in stdlib.h as unsigned. The malloc() function allocates bytes of storage space and returns a pointer to the first. This function returns NULL if the requested storage space couldn’t be allocated or if num == 0. Review the “malloc() Function” in Lesson 10, “Working with Characters and Strings,” you still a bit unclear on its operation.

# Allocating Memory with the calloc() Function

calloc() function also allocates memory. Rather than allocating a group of bytes as malloc() does, calloc() allocates a group of objects. The function prototype is:

```
void *calloc(size_t num, size_t size);
```

Remember that size_t is a synonym for unsigned for most compilers. The argument num is the number of objects to allocate, and size is the size (bytes) of each object. If allocation is successful, all allocated memory is cleared (set to 0), and the function returns a pointer to the first byte. If allocation fails or either num or size is 0, the function returns NULL.

Listing 21.2 illustrates the use of calloc().

# Allocating More Memory with the realloc() Function

The realloc() function changes the size of a block of memory that was previously allocated with malloc() or calloc(). The function prototype is:

```
void *realloc(void *ptr, size_t size);
```

The ptr argument is a pointer to the original block of memory. The new size, in bytes, is specified by size. There are several possible outcomes with realloc():

- If sufficient space exists to expand the memory block pointed to by ptr, the additional memory is allocated and the function returns ptr.
- If sufficient space does not exist to expand the current block in its current location, a new block of the size size is allocated, and existing data is copied from the old block to the beginning of the new block. The old block is freed, and the function returns a pointer to the new block.
- If the ptr argument is NULL, the function acts like malloc(), allocating a block of size bytes and returning a pointer to it.
- If the argument is 0, the memory ptr points to is freed, and the function returns NULL.
- If memory is insufficient for the reallocation (either expanding the old block or allocating a new one), the function returns NULL, and the original block is unchanged.
