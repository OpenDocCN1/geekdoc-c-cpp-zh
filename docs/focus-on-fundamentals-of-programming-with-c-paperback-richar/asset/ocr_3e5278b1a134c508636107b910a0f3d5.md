# Classes and Objects

+   ❖ Logically, an object is an indivisible encapsulation of state and operations.

+   ❖ However, since all objects of a class support the same operations, the operations or methods can be physically associated with the class.

+   ❖ Only the state or private information relating to a specific object need reside in the object itself.

+   ❖ Here, each object has its own account number and balance.

+   ❖ However, the operations for making deposits, withdrawals, and balance inquires can be shared by all objects and stored in the class.

+   ❖ When a message is sent to an object, the system searches for the operation in the class of the object.
