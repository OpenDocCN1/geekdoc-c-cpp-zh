## Inheritance

We often think of objects as specializations of other objects.

- Precious metals are specializations of metals.
- Sports cars are specializations of cars.
- Romance novels are specializations of books.

So we can view one class of objects as a specialization or subclass of another.

## Inheritance

But what does it mean to say that one class is a subclass of another?

Intuitively, we mean that the subclass has all the characteristics of the more general class, but EXTENDS it in some way.

- Precious metals have all the characteristics of metals but, in addition, they can be distinguished from some metals on the basis of monetary value.

Allows us to conceive of a new class of objects as a refinement of another, to abstract out the similarities between classes and to design and specify only the differences for the new class.

## Inheritance Structure

- An inheritance structure provides a design for the overall system.

- For example, a database that contained all the people at a college could be determined from a base class PERSON.

## Inheritance Relationship

In this example, PERSON is the base class and STUDENT and EMPLOYEE are the derived classes.

The class PERSON might contain information common to all people:

- name
- address
- social security number

Using inheritance we can say STUDENT and EMPLOYEE inherits everything that is known about person (has a name, address, social security number).

But in addition there are some specializations about STUDENTS and EMPLOYEES.

## Derived Class

- Frequently, a derived class adds new members to the existing base class members. This is the case with STUDENT and EMPLOYEE.
- Subclasses STUDENT and EMPLOYEE are specializations of class PERSON.
- A STUDENT is a PERSON:
  - has a gpa / major / student id / year
- An EMPLOYEE is a PERSON:
  - has a salary / health benefits / retirement plan

## Inheritance Relationship

- Procedural Programming - start from scratch
- Object-Oriented Programming - what classes of objects can I start with?
- If B inherits from A, all the features of A are automatically available in B, without any need to further define them.
- B is free to add new features for its own specific purposes.
- Instead of trying to solve every new problem from scratch, the idea is to build on previous accomplishments and extend their results.

## Derived Class Functionality

We've seen how inheritance allows reuse of existing code to hold information about each class of object.

But derived classes of a base class not only inherit data attributes (name, ss#, etc), but also inherit the behavior of the base class, the operations or functionality of the base class.

In fact, derived classes may also add new functionality or behavior, or even override or redefine existing behavior.

## Inheritance Summary

- Ability to create classes and objects that are specializations of other objects.
- "I want something just like that except ..."

## Message Interpretation

One of the most important characteristics of OO programming is that:
- The interpretation of a message is in the hands of the object.
- i.e., The same message can be interpreted in different ways by different receivers (objects).

## Polymorphism

Polymorphism is the ability of two or more classes of objects to respond to the same message, each in its own way.

This means that an object does not need to know to whom it is sending a message. It just needs to know that many different kinds of objects have been defined to respond to that particular message.

Different objects respond in object-specific manner to the same general message.

![](img/0603fdf2eefeabaf26542250cc2fb439_616_0.png)

## Pseudo-Code Example

### Non-Polymorphic Code:

```
for each item x    // loop over all items
  if x is a car    // depending on what x is
    call stopCar   // call different function
  else if x is a bike
    call stopBike  // for each different type
  else if x is a plane // send a specific stop
    call stopPlane // message
```

### Polymorphic Code:

```
for each item x    // loop over all items
  x.stop()         // send general message
                   // to x
```

This polymorphic solution is more adaptable to change and reuse.
