Each error has its own code - a 32-bit number.When a Windows function detects an error, it uses the thread's local memory mechanism to map the corresponding error code to the calling thread. (Thread local memory is discussed in Chapter 21) This allows threads to work independently of each other without interfering with other people's errors. When the function returns control to you, its return value will indicate that some kind of error has occurred. Of course, you must first translate the strings into the required languages ​​and embed this resource into your EXE or DLL module, then the function will automatically select the required language. The ErrorShow sample program at the end of this chapter demonstrates how to call this function to get a textual description of an error from its Microsoft-defined code.From time to time, someone asks me if Microsoft will compile a complete list of error codes for every possible Windows feature. Answer: alas, no. I will say more, there will never be such a list - it is too difficult to compile and maintain it for more and more new versions of the system.The problem with such a list is also that you call one API function, and it can call to another, that - to the third, etc. Any of these functions can fail (and for various reasons). Sometimes a higher-level function will itself deal with an error in one of the functions it calls and ultimately do what you want it to do. In general, to create such a list, Microsoft would have to trace the call chains in each function, which is very difficult. And with the advent of a new version of the system, these chains would have to be revised again.You can do it tooSo I showed you how Windows functions report errors. Microsoft allows you to use this mechanism in your own functions. Let's say you are writing a function that will be accessed by other programs.
