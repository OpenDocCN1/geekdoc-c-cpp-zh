And that's all! With only two lines of code, you called a SOAP web service from JavaScript and displayed the results with a declarative template. It's not complicated, all right?

Sure's not. Nevertheless, it is a often used scenario that every line counts, and therefore, the DataView interface provides direct support for it. You can strip out the <script> tag, the web service, and the success callback, and configure the web service URI directly on the DataView.

```
<ul>
  <ul class="sys-template"
    sys:attach="dv"
    dv:autofetch="true"
    dv:dataProvider="../Services/CountryService.asmx"
    dv:fetchoperation="GetCountriesByName">
  <li>
    {{ Name }} ((( Capital )))
  </li>
</ul>
```

The dataProvider of the DataView class can point to a JSON Web Service URI, or to an instance of a Sys.Net.WebService object, or any class that implements the Sys.DataProvider interface. In the fetchoperation property, you define the name of the method that you can call. By setting the autofetch property to true, you can ensure that you do not have to update the DataView manually. It will retrieve the data immediately from the source when it loads, or when the dataProvider or the fetchoperation is changed.

If you want to call a method that expects parameters, you must set the fetchParameters property as well:

```
<ul>
  <ul class="sys-template"
    sys:attach="dv"
    dv:autofetch="true"
    dv:dataProvider="../Services/CountryService.asmx"
    dv:fetchoperation="GetCountries"({ orderby: 'Capital', asc: false })"
  <li>
    {{ Name }} ((( Capital )))
  </li>
</ul>
```
