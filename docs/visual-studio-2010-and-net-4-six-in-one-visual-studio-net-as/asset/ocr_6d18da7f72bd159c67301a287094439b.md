Because you are already with the concept of script files, you know that this granular approach can reduce the total size of the scripts downloaded to the client. On the other hand, if there are a lot of individual files that should be downloaded, the separate HTTP connections may cause a notable delay at page time, and may degrade the overall performance. Many JavaScript experts recommend using fewer (but larger) scripts to minimize the overhead added by the HTTP transport. As that, you must balance between the two approaches based on your unique needs.

If you use script combining on the server, you can use the contains property in the metadata to inform the Script Loader that a single file contains multiple files, like Microsoft does with MicrosoftAjax.js (code snippet copied from Start.debug.js):

  name: "MicrosoftAjax",
  releaseUrl: "%/MicrosoftAjax.js",
  debugUrl: "%/MicrosoftAjax.debug.js",
  executionDependencies: null,
  contains: ["Core", "ComponentModel", "History",
"Serialization", "Network",
"WebServices", "Globalization"]
}
