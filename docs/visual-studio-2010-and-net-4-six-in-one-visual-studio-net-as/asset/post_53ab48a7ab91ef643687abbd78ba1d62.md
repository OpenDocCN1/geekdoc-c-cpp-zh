
# Flowcharts WF 4.0

Now, let's create a flowchart-based workflow that checks whether an integer number is a prime number. This is not a typical application of a workflow, this example can be helpful when learning about the Flowchart.

Create a new Workflow Console Application and name it PrimeWorkflow. Add a new code file to the project, name TestResult.cs, and define the enumerated type:

```csharp
namespace PrimeWorkflow
{
    public enum TestResult
    {
        NotTested,
        Prime,
        NonPrime
    }
}
```

The algorithm will return NotTested if the input argument is greater than 1 billion. If it is less, Prime or NonPrime will be returned according the test. Build the project right now — it will be important in a future step.

The check is very simple. Let's try to divide the number by a few prime numbers (from 2 to 31). If the number can be divided by the prime number without a remainder, it cannot be a prime number. For demonstration purposes, the workflow will be extended to count the number of different primes that divide the argument, and it will display a few messages accounting this counter.

# Adding a Flowchart to the Workflow

Open the Workflow.xml file and draw a Flowchart activity (located in the Flowchart tab) to the design surface. This activity will display a simple Start state representing the entry point of this activity.

Add an Int32 argument to the workflow and name NumberToTest. Add an output argument, and name it Prime. Click the Argument column, and in the drop-down list, select "Browse for Types." A new dialog pops up. Expand the <Current project> node and its children until you find the TestResult node, then select and close it. If you did not build the project earlier, you would not be able to find the TestResult type.

The algorithm will use two variables. Add the dividersCount variable with a type of Int32, and another one, with the type of Int32[]. For the latter, select the "Array of T" from the Variable column, and then select Int32 from the dialog that pops up.

# Adding a Decision Activity

Drag a Decision activity to the Flowchart begin the Start point. Set its properties to the following values:

- Condition: NumberToTest > 1000000000
- FalseLabel: Testable
- TrueLabel: Too big to test

Drop two Assign activities to the Flowchart and set their corresponding properties to these values:

- (First activity) To: IsPrime; Value: TestResult.NotTested
- (Second activity) To: IsPrime; Value: TestResult.Prime

Now, you can draw the flows using the Start point, the FlowDecision, and the two Assign activities. When you move the mouse over the Start point, four handles will appear on each side of this activity. Move the mouse to handle the Start point, click the mouse, and drag the line over the FlowDecision activity. When the handles belong to FlowDecision appear, release the button over one of these handles. An arrow will be drawn connecting the Start point with FlowDecision. This is how you can draw the connection among activities dropped to the design surface of a Flowchart.

When you move the mouse over the FlowDecision, the handles display their labels (you set them through the FalseLabel and TrueLabel properties earlier). Connect the big to test label with the first Assign activity, and then the Testable label with the second Assign activity.

# Adding a ForEach<T> Activity

Add a ForEach<T> activity to the design surface. The T parameter represents the type of elements in the collection. By default, it is System.Int32, and now you need exactly this type. Set the DisplayName property of this activity to "Check Each Divider".

Connect the Assign activity at the Testable branch of the FlowDecision to Init Prime Arrays, then this activity to Reset Counter and then this one to Check Each Divider. The topology of the workflow should look like Figure 11-10.

![](img/b5597c749e848b27b0d305153ae16106_543_0.png)

FIGURE 11-10: More activities added to the workflow

Now, double-click the Check Each Divider activity to edit its properties and nested activities. The design surface changes and zooms into this activity. At the top of the design pane, you see the Workflow $\rightarrow$ Prime Number Text $\rightarrow$ Check Each Divider path indicating where you are in the current workflow.

In the text box for the ForForEach set the cycle variable to divider, then the connection in the next text to primeDividers. (You can set this field later from the Values property as well.) This activity will iterate through the elements of primeDividers and makes the current value accessible through the divider variable in body activities.

Drag If activity to the body of the ForEach and set the Condition to (NumberToTest < 0) And (NumberToTest != divider). This condition will check divided with the current divider, and this number is not the divider (in this case, NumberToTest is a prime number).

Drag Sequence to the Then branch of the If activity, and add two Assign activities to its body with the following properties:

- (First Activity) To: IsPrime; Value: TestResult.NonPrime
- (Second Activity) To: dividerCount; Value: dividerCount + 1

# Adding a Switch Activity

Drag a Switch activity to the design surface. The Switch activity allows you to branch the workflow based on the value of an expression. In this case, we will use the IsPrime variable.

Set the Expression property of the Switch activity to IsPrime. Add two branches for the TestResult values Prime and NonPrime.

- Case: Prime; Add a WriteLine activity with text "This number is a prime number!"
- Case: NonPrime; Add a WriteLine activity with text "This number has several prime divisors!"
- Default: Add a WriteLine activity with text "This number has only one prime divider!"

Connect the Start activity to the Switch activity, and then each branch to its corresponding WriteLine activity.

# Running the Flowchart

As you can see from this list, flowchart workflows are managed exactly the same as sequential workflows. From the outside, you cannot notice any difference; you do not see how the workflow is internally implemented.

Run the workflow with the "NumberTest" argument set to 7, 4, and 459, you'll see the following:

- This number must be a prime number!
Test result for 7: Prime

- This number has only one prime divisor!
Test result for 4: NonPrime

- This number has several prime divisors!
Test result for 459: NonPrime
