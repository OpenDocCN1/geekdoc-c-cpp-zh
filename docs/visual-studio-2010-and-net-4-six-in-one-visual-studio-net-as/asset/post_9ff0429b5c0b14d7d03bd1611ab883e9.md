
The partial method cannot be seen from outside:

```csharp
class Program
{
    static void Main(string[] args)
    {
        CustomTypedCollection c = new CustomTypedCollection();
        c.AddElement(new CustomElement());
    }
}
```

If the Customization.cs file did not contain an implementation part for the BeforeAddingElement partial method, no code would be compiled for this method in Collection.cs.

Of course, partial methods have a few restrictions. For example, they must return void, and are not allowed to have out or ref parameters, nor can they have access modifiers, and they cannot be virtual.

## SUMMARY

Currently a multi-paradigm programming language, C# began life with version 1.0 in 2002 as a general-purpose, object-oriented language. The development team of the C# language was led by Anders Heijlsberg. The name was inspired from musical notation where a sharp indicates that the note should be made a half step higher in pitch.

The language evolved in parallel with the .NET Framework as the "native" programming language of the framework. New features and changes in the CLR and in the framework's class libraries inspired the language that turned into a real multi-paradigm language supporting not only the original object-oriented programming (OOP) principles, but also declarative, functional, and (with C# 4.0) the dynamic paradigm.

Chapter 24 will familiarize you with the new improvements to the C# language, such as dynamic lookup, named and optional parameters, the new COM-specific features, and variance.

## C# 4.0 Language Improvements

In Chapter 23, you learned about how C# evolved from a general-purpose, object-oriented programming (OOP) language to a multi-paradigm language. After its first release in 2002 (C# 1.0), the language matured amazingly. Version 2.0 added support for generic types and got great performance-boosting features such as the yield-construct, delegate inference, covariance and contravariance, and nullable types.

C# 3.0 gained a huge spin with the introduction of query expressions encapsulating LINQ technology into the language. This feature enabled the shift from the imperative data-processing model to the declarative one. In addition, many "syntax noise-reduction" features were put into C# 3.0 to achieve the intended declarative strength.

The main theme for C# 4.0 is dynamic programming. Increasingly, objects are "dynamic" in the sense that their structure and behavior is not captured by a static type or, at least, not one that the compiler knows about when compiling your program. While C# remains a statically typed language, the Managed Languages Team targeted vastly improved interaction with the following:

- Objects from other programming languages, such as Python or Ruby
- Component Object Model (COM) objects accessed through the IDDispatch interface
- Objects with dynamically changing structure, the ones in HTML Document Object Model (DOM)
- Ordinary .NET types accessed through reflection

After reading this chapter, you will be familiar with the following improvements introduced by C# version 4.0:

- Dynamic lookup — You can write method, operator, and indexer calls; property and field accesses; object invocations that bypass the C# compile-time static type checking. Instead, these invocations will get resolved at run-time with the help of Dynamic Language Run-time (DLR).
- Named and optional parameters — Parameters in C# can be specified as optional, and in member invocations, optional arguments are omitted. Furthermore, any argument can be passed by parameter name.
- COM-specific interoperability features — The language designers added a number of small features, combined with the strength of dynamic lookup, further improved the programmer's interoperability experience.
- Variance — .NET developers used to be by the fact that an IEnumerable<object> could not be substituted with an IEnumerable<T>. Now, this substitution can be done! C# embraces type-safe covariance and contravariance. The common Base Class types (primarily generic collection interfaces) have all been updated to support this behavior.

Before diving into the details of these topics, let's take a look at a short example demonstrating issues that were not previously addressed properly in C#, but have been adequately handled in version 4.0.
