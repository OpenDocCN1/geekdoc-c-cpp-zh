At this point, the previous WillCost function compiled fine, and without knowing this code, this new developer would never have noticed anything else needed to be addressed — which should raise flags on its own right, of course. However, let's say the original developer coded WillCost as follows:

```
let WillCost meth =
match with
  | Mail ->
      true
  | Email ->
      false
```

It would have been immediately obvious that the additional contact method needs further code changes.

Functional programming encourages fast prototyping and incremental development, and you should learn to turn to yours (or your team's) advantage. As a case in point, try to avoid the wildcard pattern in matches over most structured data, and spend the extra time to spell out all base cases/shapes.

And last, you can apply pattern matching not only to examine the schema of a particular value, but also of its type, as shown in Table 25-16. This is handy when you are dealing with catching exceptions. (You'll learn more about that later in this chapter).

TABLE 25-16: Additional Pattern Match Constructs

| PATTERN CASE | EXAMPLE | DESCRIPTION |
|---|---|---|
| patt when expr | 1 lst when List.length 1 > 0 | Conditional pattern |
| null | Null | Matches nulls |
| :? ty | ?: System.Int32 | Checks whether the expression being matches has type ty.|
