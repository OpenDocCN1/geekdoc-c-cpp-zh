Because Travelling completes and its Result property is set to travellingToken, the token will be assigned a CompensationToken instance. Registration is cancelled, although its Result property is to registrationToken, this variable remains null (Nothing in Visual Basic).

The exception raised by the Throw activity is caught, because only travellingToken has a null value, only the Compensate activity will be executed. The Travelling variable holds the information about the related CompensableActivity, and because it is the Target property of Compensate, the appropriate compensation handler is invoked. If you modify the Delay property that Registration finishes, the first output will be:

Conference preparations started
(Body) Pay $1,000 for travelling and hotel
(Body) Pay $1,500 registration fee
(Cancellation) Your hotel reservation has not been done
(Compensation) $1,500 registration fee paid back
Conference preparations completed

> This workflow is quite far away from being complete or correct. It does not handle many issues that you must manage in real workflows. However, it shows the WF 4.0 implementation of the compensating transaction pattern. Play with this example and try to modify it to reflect real-world situations.

# PERSISTENCE AND HUMAN INTERACTIONS

In a real business environment, workflows are not as simple as the examples you've seen so far in this chapter:

+   - In most cases, there are thousands of workflow instances running in an hour (or even a minute).
- Although many workflows are automated, there are almost always human interactions — human decisions — involved in workflows.
- Workflows are distributed. Several activities are done by external systems, or by humans working with their special applications.

By now, all the examples used Workflow kept in the operational memory of the computer where the workflow application ran. Imagine what would happen if hundreds of thousands of workflow instances were kept in memory! If humans are involved in the workflows, maybe most of the running workflows would be sitting and waiting for human interaction.

In this section, you will learn how WF 4.0 copes with situations similar to these. The related concepts are presented through a sample project named DomainNameworkflow that you can download from the book's company website (www.wrox.com).
