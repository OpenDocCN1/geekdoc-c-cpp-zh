# Workflow Activity Model Changes

The WF programming model has been totally redesigned to make it simpler and more robust. The key change in this model is that Activity is the core base in the programming model, and it represents both workflows and activities. The model becomes fully declarative. Remember the CodedWorkflow where the workflow declaration was about setting up activities and properties using object and collection initializers with lambda expressions.

With WF 3.5, you had to create a Workflow runtime to invoke a workflow. In WF 4.0, you can simply create a workflow instance (that is, an Activity-derived instance) and execute it. This benefits unit testing and application scenarios where you do not want to go through the trouble of setting a specific environment.

To demonstrate how the WF 4.0 programming model has changed, we compare two workflows, one written with WF 3.5 and the other one with WF 4.0. Both workflows define a custom activity that receives in its Message argument and displays it on the console.
