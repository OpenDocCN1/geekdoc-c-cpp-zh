The InitServiceHost creates an instance of WorkflowService, this instance is passed to the constructor of WorkflowServiceHost. The WorkflowServiceHost creates a new ApprovalWorkflow as the body of, and encapsulates the endpoints it is listening to. The code configuring that the host does not stop is extended with a DNRequestTrackingBehavior.

As the last step of the configuration, the Open method starts the host. It listens to messages and processes them until the application is closed. In this case, the Window_Unloaded event handler closes the host and its from responding to any more messages.

# Workflow Behaviors

You can add behaviors to the WorkflowServiceHost class when you configure the host instance. In the previous versions of the DomainNameWorkflow, you instantiated a workflow instance programmatically as a response for a button's Click (for example, the DNRequestTrackingParticipant) to that instance, and you were able to add extensions for. The WorkflowServiceHost does not allow you direct instantiation, another mechanism is required to inject extensions into the workflow instances.

This is where behavior enters the picture. Where a WorkflowServiceHost instantiates a new workflow, it goes through all its defined behaviors, generates and compiles the associated extension, and then adds it to the workflow instance that is started.

The DomainNameWorkflowHost project uses the DNRequestTrackingBehavior to extend the workflows with the following:

```
var trackingBehavior = new DNRequestTrackingBehavior();
_ApproveWorkflowHost.Description.Behaviors.Add(trackingBehavior);
```
