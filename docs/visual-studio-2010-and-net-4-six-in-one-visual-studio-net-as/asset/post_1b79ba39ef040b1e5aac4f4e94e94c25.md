
F# is a strongly typed functional language for .NET that provides a unique combination of object-oriented, functional, and imperative features. It allows developers to explore new ways of problem solving with asynchronous computations, and many others.

One distinction you will observe when you first look at F# is its support for functional programming. This chapter is primarily concerned with the basic aspects of F#, which will help you get up to speed with the language. There are several key characteristics of F# that differ from its origin:

- **Immutability**: Once values are created and assigned to names (bindings), they do not change. If you need data structures that are mutable, you can use reference cells wherever. You will see plenty of examples of defining and using functional data structures in this chapter.

- **Functions as first-class values**: The capability to pass functions or return them from others is a basic building block of functional higher-level abstractions. You will learn about these abstractions, such as higher-order functions, are now more readily available than before.

- **Algebraic data types**: These enable you to differentiate a group of “shapes” within a given type. For example, you may want to express that binary trees are nodes (one shape) that carry some value, or trees (the other shape) that have two subtrees. This often distills into a more natural recursion of your data. You will see plenty of examples on how to use discriminated unions, F# types to define algebraic data types, and how to write functions that operate on these values via pattern matching.

- **Pattern matching**: You can use pattern matching to deconstruct complex values (algebraic data types, tuples, lists) onto simpler ones in a type-safe and exhaustive way. You can apply pattern matching not only to discriminated unions and collection types but also to any value via active patterns, a unique F# feature that makes pattern matching extensible and provides complete encapsulation of data representations.

- **Type inference**: In F# code you will rarely see type annotations simply because the compiler can infer them from their use. This enables you to write and accomplish more (for example, write better code that is generic and reusable). For example, you can define functions without having to type their arguments, you just list the argument names instead. The compiler will try to find the most general signature for each argument by solving various type constraints and “equations” that your code poses. You should always aim to write generic code and eliminate any references, calls, and operators that are overly restrictive. This, when the compiler infers the signature for your functions, will be as generic as possible, and you can make changes easily and apply them to diverse data structures as possible.

- **Support for lazy evaluation**: You can delay the computation of certain values until they are actually needed. This enables you to compute as much as you really need to, and F# offers various ways to enable lazy computations. Notably, you will learn about sequences that can be enumerated on demand via a lazy interface erected around most F# and .NET collections, Language Integrated Queries (LINQ), and computations that may yield a lot of data as results. You will also see how you can construct and evaluate lazy values directly through the .NET type and the F# helper module, and syntax sugar around it.

## Trying Out With F#

One of the fun of F# development is always easy to quickly prototype and try them out-the-fly. In fact, this is also the reason why development with F# is a very satisfying and rewarding experience. A Visual Studio add-in called F# Interactive helps you accomplish this. You can also invoke Interactive as a command-line tool using `fsi.exe` from the F# distribution, and run it in a command window.

Working with the Visual Studio add-in for F# Interactive is the easiest way to get going. All you must do is to highlight some block of code and press Alt+Enter to send it to the interactive session. You can send any code you like; code will be interpreted just as you enter. Your interactive session is alive from the time you start until you decide to exit. Keep in mind, however, that redefining functions or types will not have any effect on what you have already entered unless you redefine. In other words, anything you enter is parsed and interpreted using lexical scoping. If you want to restart your interactive session, type `exit 1`.

## First Taste

F# is a script-language with very light, concise, and almost math-like syntax. It lends itself to exploratory programming, enabling you to quickly prototype short (but powerful) functional programs that are easy to maintain.

Listing 25-1 gives a taste of the functional core constructs of F#, including global and local nested functions, higher-order functions (HOFs), piping arguments, catching exceptions, and pattern matching against values and types.

LISTING 25-1: A Simple F# Function with Various Language Constructs

```fsharp
// Compute number based on a list of integers.
// Returns Nan and reports an error if any of the
// numbers are prime or on division by zero.
let lillyComputation numbers = // Global function
  let translate x =
    let isEven n = n%2 = 0 // Local, nested function
    let isPrime n =
      if n > 1 then // If-then-else
        (2 .. n/2) // Sequence
        |> Seq.exists (fun i -> n%i = 0) // Piping into a HOF
      else false
    if isPrime x then // If-then-elif-else
      failwith "Can't compute XYZ" // Raising a failure
  elif isEven x then
    -1./float x
  else
    1./float x
try
  numbers // try-with
    |> List.map translate
    |> List.reduce (+)
    |> fun res -> -res // Anonymous function
with
  |> Failure msg -> // Pattern matching
```
