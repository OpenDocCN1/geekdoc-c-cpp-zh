In contrast, MyDotNetException is not an F# exception, so you must catch it slightly differently by matching on its type:

```
try
    new MyDotNetException("error", 12) |> raise
with
    | : ? MyDotNetException as exc ->
        printf "%Caught message=%s," exc.Message exc.Value
```

Now that you have F# and .NET exceptions that can be raised, and caught, you can look at the rest of the exception primitives from Table 25-18.

You can signal a general failure using `failwith` or its format-enabled alternative, `failwith`. This will raise an instance of `System.Exception`. Normally you should use different exception subtypes to indicate different causes of failure so that the calling sites can recover appropriately, but when used in the small to yield a "general" failure these functions are indispensable.

A companion to raising exceptions with `failwith/failwith` is catching them via the `Failure` active pattern, defined in `Core.Operators`. This active pattern matches any instance (as opposed to a subtype) of `System.Exception` and binds the message carrier.

Consider implementing a simple division function that reports division by zero and by a prime number. Using the IsPrimePrime function you defined earlier in this chapter, you can implement this as follows:

```
let RequireNonPrime x =
    if IsPrime x then
        failwith "Prime"
    else
        x

let SpecialDiv x y =
    try
        x/RequireNonPrime y |> printf "Result=%d"
    with
        | Failure msg ->
            printf "%s" msg
        | :? System.DivideByZeroException ->
            printf "Error: division by zero"
```

Experiment with this new function in F# Interactive, as shown here:

```

val it : unit = ()
> SpecialDiv 1 17;
Failure: Prime
val it : unit = ()
> SpecialDiv 10 4;;
Result=2
val it : unit = ()
```
