Managed Package Framework (MPF) brings you a small library built on top of interop assemblies. It implements the most important core types to develop packages in managed code by using VB, C#, or other managed languages (including F# and the Iron family of languages). These core types deal with concepts like windows, window dialogs, commands, menus, documents, and many more.

When creating packages, you typically build your code on the MPF types and interop assemblies. In many cases, you use both the automation objects and the Package API. The interp assemblies, VSL, and the MPF are all parts of the VS SDK. Visual Studio installs only the Automation API, so you cannot develop your own packages out of the box.

# Editor Extensibility

Visual Studio 2010 is the first big move to migrate the unmanaged code base of Visual Studio into managed code. The best evidence of this is the re-architected text editor that actually could be a brand new editor. It is fully developed with managed code that leverages patterns frequently used in .NET programming.

The new editor uses WPF as its presentation technology, and it opens new opportunities for the simple features used before Visual Studio 2010. The development team designed the new editor with extensibility in mind and used the Managed Extensibility Framework (MEF) as the core technology to allow a straightforward and simple way of creating custom extensions. A great evidence of this architecture's usability is the fact that many editor features are physically implemented as extensions to a core functional set.

Following is a short list to show you an example of this well-thought-out architecture:

+   - There is a fine control over editor properties. It is possible to mix font faces, styles, and sizes. You can alter the formatting of built-in languages, and share the same formatting across different languages.
- A line transformation can be added for each editor line that translates into vertical scaling and defining the space surrounding the line.
- There is a way to create classifiers that can be assigned to the specific editor content (for example, the text in the Output window, or to the C# source in the editor). Classifiers can have their own formatting.
- You can add adornments to the text that can be any piece of WPF element definitions, including images, animations, and even video.
- If you do not like the presentation of IntelliSense in the editor, you can change it.

From an architectural point of view, the new editor clearly separates the roles of objects working behind the scenes — this is a big shift from the previous editor's implementation, which was poorly designed by means of object responsibilities and cooperation.
