
# Creating New Projects in a New Way

Often, a developer will have some code files somewhere on his or her computer, or a complete project in a directory, but not organized into a project. In Visual Studio 2008, you had to manually create a new project and add those files by hand. In Visual Studio 2010, invoke the Project From Existing Code from the File > New Project From Existing Code menu selection.

The first step of the wizard is to provide some basic information, including specifying the project that you would like to create.

In the next step, you name the project and specify the directory where your files are stored. You also tell the IDE type of project you would like to create.

Let's say that you have the following in a directory:

- Program.cs
- Data\City.cs
- Data\Country.cs
- Data\Person.cs

After you have clicked the Finish button, Visual Studio 2010 is unfolding the default project template for the selected language, and it has collected all the files from the directory, adding it to the project. When the wizard has finished its job, you get a ready-to-compile console application.

# Using the Add Reference Dialog Window

The Add Reference dialog window is one of the most used windows within Visual Studio. As you might think, multi-targeting can be a core functionality of the project system within the IDE, every functionality that is dependent on a version of the .NET Framework. Because of this, the target projects must be smarter and more developer-friendly.

That's why this dialog has been enhanced for Visual Studio 2010. Take a look at the Runtime column in Figure 2-5. In the upper part of the figure, you can see how the window is opened for a project that has the .NET 2.0 Framework. In the lower part of the figure, you can see that same information for a .NET 4-targeted project. This dialog not only filters based on the .NET Framework version, but also on the type of the project.

In the upper-right corner of the editor, above the scrollbar, you will find a splitter button. By dragging that, you can split your window and navigate within the same file in the two different windows. Although this functionality is not that, another new feature capitalizes on the power of WPF — you can zoom your code to any level you need. You no longer must change the font size when doing code-only presentations. You may now change the zoom level by holding the Ctrl key and moving the mouse wheel, and everyone will see the code (from the last row of the audience).

WPF and a brand new editor provide the opportunity to greatly enhance text selection within the code editor. Box selection can be activated by holding down the Alt key, in addition to the normal selection keys (or Shift, Alt and as well as other navigation keys). As shown in Figure 2-7, when you're doing an empty block selection, you can start to type, and the characters will appear in all rows.

```c
static class Program {
    string Name {get; set; }
    int Age {get; set; }
}
```

FIGURE 2-7: Empty box selection for typing in multiple rows simultaneously

Notice the thin vertical line following the "private" text in Figure 2-7, which is an empty block selection. Delete and overwrite operations work for box selection.

The code editor now incorporates the concept of a visualizer. Different extensible points are available for you to develop your extension, which provides a richer, more customized presentation of code. For example, the default comment presentation now displays in layouts.

Another powerful feature of the IDE is the IntelliSense. If you activate an IntelliSense visualizer, you are presented with a much richer IntelliSense presentation, as shown in Figure 2-8. Visual Studio provides a full WPF feature set to use when developing extensions for the editor.

IntelliSense also includes a new function for filtering on code. This feature is called Pascal case IntelliSense lookup, and it is very powerful when you type during your work, which enables a faster delivery for projects.
