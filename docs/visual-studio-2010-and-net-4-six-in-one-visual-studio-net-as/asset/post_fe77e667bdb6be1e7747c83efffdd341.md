## Workflow Tracking

The workflow run-time provides you with special built-extensions that you can use to track a workflow's execution. These are very useful for both diagnostics and the recording of an audit trail. In this section, you will examine WF 4.0 tracking extensions through an enhanced version of DomainNameWorkflow. This project is named DomainNameWorkflowTracking, and its source code is among the others that you can download from our companion website (www.wrox.com). Before turning to the source code of this project, let's explore an overview of the tracking pattern used by WF 4.0.

## Tracking Records

The workflow run-time triggers tracking events when something changes in the state of a workflow instance. You can also add your own to a workflow by classes derived from the TrackingRecord abstract class of the System.Activities.Tracking namespace.

Table 11-13 summarizes these classes.

### TABLE 11-13: TrackingRecord Derived Types

| TYPE | DESCRIPTION |
|---|---|
| ActivityStateRecord | This class describes a tracking record for an activity. The workflow run-time creates a record when the state of a specific activity in a workflow instance changes. |
| ActivityScheduledRecord | This class represents a tracking record of an activity being scheduled for execution. |
| WorkflowInstanceRecord | This class describes a tracking record for a workflow instance. The run-time creates a record when the state of workflow instance changes. this class has several derived classes associated with special workflow instance events, such as absorbing, suspending, terminating an instance, or observing unhandled exception. |
| BookmarkResumptionRecord | This class contains tracking information about resumed bookmark. |
| CustomTrackingRecord | This class contains activity-specific or user-defined tracking information. Its three-built derived classes include InteropTrackingRecord, ReceiveMessageRecord, and SendMessageRecord. |

Tracking records contain useful information about the event; you can access them through their properties. You can create any TrackingRecord derived classes. Use CustomTrackingRecord as the base for events belonging to your custom activities.

## Participating in the Tracking Process

The run-time uses extensions inherited from the TrackingParticipant abstract class of the System.Activities.Tracking namespace allowing catching of the tracking events. One or more extensions to a workflow instance, and are notified when a tracking event happens. Then your extensions can process the tracking records generated by the events.

WF 4.0 implements only one built-in tracking participant. It is EtwTrackingParticipant that emits an Event For Windows (ETW) event to an ETW session that contains the data from the tracking record.

When you add a tracking participant extension to a workflow instance, you can assign it with a tracking profile. The profile tells the run-time set of events the participant is interested in. The profile is assembled by several tracking queries that help the developer to set up a profile. For example, the participant's profile can define a query saying that it is interested only in activity state changes when the state is “New” or “Closed.” The run-time won't forward any other kind of events to the participant.

Later in this chapter, you will see a concrete example of creating a tracking profile with the help of tracking queries.

## Persisting Tracking Information

So, now you have enough information to dive into the source code. Open the source code of the DomainNameWorkflowTracking project that you can examine. This project has exactly the same functionality as a DomainNameWorkflow, except it implements a tracking participant that stores event information in a SQL Server database.

In order for you to see how this works, run the DNRequestTracking.sql script file in the Scripts folder after the DomainNameData database. Open the file, right-click, and start Execute. When the Connect dialog appears, click Options, select the DomainNameData in the Connection Properties tab, and click Connect.

This script creates a table called DNRequestTracking, and the DNRequest.edmx defines the entity to populate this table.

The key type of this application is DNRequestTrackingParticipant that implements a custom tracking participant, as shown in Listing 11-16.

```csharp
using System;
using System.Activities.Extensions;

{
    internal class DNRequestTrackingParticipant: TrackingParticipant
    {
        protected override void onTrack(TrackingRecord record, TimeSpan timeout)
        {
            using (var dataContext = new DomainNameDataEntities())
            {
                var wtr = record as WorkflowInstanceRecord;
                if (wtr != null)
                {
                    var tr = new DNRequestTracking
                    {
                        WorkflowID = wtr.InstanceId,
                        Type = "W",
                        EventDate = DateTime.UtcNow,
                        Data = wtr.State
                    };
                    dataContext.AddToDNRequestTracking(tr);
                }
                var btr = record as BookmarkResumptionRecord;
                if (btr != null)
                {
                  var tr = new DNRequestTracking
                  {
                    Workflow = btr.InstanceId,
                    Type = "B",
                    EventDate = DateTime.UtcNow,
                    Data = btr.BookmarkName
                  }
                  dataContext.AddToDNRequestTracking(tr);
                }
                var astr = record as ActivityStateRecord;
                if (astr != null) {
                  var tr = new DNRequestTracking
                    {
                      Workflow = astr.InstanceId,
                      Type = "A",
                      EventDate = DateTime.UtcNow,
                      Data = astr.Activity + " *" + astr.State
                    }
                  dataContext.AddToDNRequestTracking(tr);
                }
                var ctr = record as CustomTrackingRecord;
                if (ctr != null) {
                  var tr = new DNRequestTracking
                    {
                      Workflow = ctr.InstanceId,
                      Type = "C",
                      EventDate = DateTime.UtcNow,
                      Data = ctr.Data["Message"].ToString()
                    }
                  dataContext.AddToDNRequestTracking(tr);
                }
                dataContext.SaveChanges();
            }
        }
    }
}
```
