
Code snippets can be grouped into a hierarchical folder structure. For example, Visual C# snippets have the following folders:

- NetFX3 — These are snippets for .NET 3.0 new features.
- OfficeDevelopment — These are code snippets helping in Microsoft Office development tasks.
- other — This is the folder for other code snippets. Currently, a few WF snippets can be found here.
- Refactoring — These are snippets used by the C# language service for refactoring functions.
- Visual C# — These are general-purpose snippets related to the C# language (properties, events, classes, and so on).

System folders have so-called index files to enumerate snippets. This is the existence and the name of these files is SnippetIndex.xml for Visual Basic, and SnippetsIndex.xml for the other languages. The format of these index files is beyond the scope of this book, but free to open and examine them.

## Adding and Removing Snippets

The Code Snippets Manager allows you to add your custom folders with snippets. As mentioned previously, Code Snippets Manager stores only paths to folders. By using the Add button, you can add only top-level folders to the selected language. When you click the Add button, a folder-selection dialog with Code Snippets directory is popped to let you specify the folder to add. After you added the folder to the directory, it is displayed in the folder list. You can immediately browse its content.

When you select a folder in the list and click the Remove button, you can draw it off from the library. Of course, this operation does not delete the content of the folder; it omits it from the list handled by Code Snippets Manager. You can remove only top-level folders. The Remove button is disabled when you select a subfolder or snippet.

Be careful about removing system folders. The Code Snippets Manager allows you to remove them, and not even ask for confirmation. If you accidentally removed a system folder, you can add it later by selecting the physical folder you drew off. After adding it again, Visual Studio recognizes it as a system folder and handles it correctly.

## Importing Snippets

If you have a lot of snippets organized in a folder, you can add the folder to the appropriate language with Code Snippets Manager. However, if you have .snippet files that have not been organized in any folder, you can import them, and make the snippets within them a part of your library.

After you select one or more .snippet files, click the Import button to start importing snippets. The Import Code Snippet dialog shown in Figure 3-19 is displayed to let you select the import folder for each file.

## Multiple Snippets in a File

The .snippet file was intentionally designed to be able to describe one or more snippets. The <Snippet> element is a container that may hold one or more <CodeSnippet> elements, as seen in Listing 3-4.

LISTING 3-4: Multiple Code Snippets in One File

```xml
<?xml version="1.0" encoding="utf-8"?>
<CodeSnippet xmlns="http://schemas.microsoft.com/VisualStudio/2005/CodeSnippet">

<!-- First snippet -->
<CodeSnippet Format="1.0">
<Header>
  <Title>Write an empty line</Title>
  <Shortcut>wel</Shortcut>
  <Author>Istvan (DiveDeeper) Novak</Author>
  <Description>
    This snippet inserts a "Console.WriteLine()" invocation into the code.
  </Description>
</Header>
<Snippet>
  <Code Language="C#">
    <![CDATA[Console.WriteLine();]]]>
  </Code>
</Snippet>
</CodeSnippet>

<!-- Second snippet -->
<CodeSnippet Format="1.0">
<Header>
  <Title>Write a message</Title>
  <Shortcut>wmk</Shortcut>
  <Author>Istvan (DiveDeeper) Novak</Author>
  <Description>
    This snippet inserts a "Console.Write()" invocation into the code.
  </Description>
</Header>
<Snippet>
  <Code Language="C#">
    <![CDATA[Console.Write();]]]>
  </Code>
</Snippet>
</CodeSnippet>
```

## Code Snippets in Other Languages

As mentioned previously, Visual Studio 2010 supports code snippets for HTML, JScript, Visual Basic, C#, and SQL out-of-box. However, the infrastructure for code snippets is available for any other language. Visual Studio allows creating language services to implement other languages, and these languages can use the code snippet infrastructure to create their own support.

Language services can be customized to determine how they use code snippets, and what kind of support they provide in the code editor related to the specific language. As you can imagine, there is a big difference between the Visual Basic implementation and other languages when handling snippet kinds (for example, type declaration, method declaration, method body, and so on), as well as providing surrounding-type snippets.

Language providers can decide if they implement code snippets at all, or if they do, decide what features they support. For example, you can install IronPython for Visual Studio 2008 which provides a language service for the IronPython language, and indeed, implement the code snippets. Figure 3-21 shows Code Snippets Manager with a language filter for Python and the Python snippets installed.

When you look into the Python snippet files, you see that they use the standard code snippet infrastructure, with the well-known snippet schema. You can definitively recognize from the <code> element that these snippets belong to the Python language:

```xml
<Snippet>
  <Declarations>
    <Literal>
      <ID>Expression</ID>
      <ToolTip>Expression to evaluate</ToolTip>
      <Default>true</Default>
    </Literal>
  </Declarations>
  <Code Language="python">
    <![CDATA[while $expression$:
      $selected$end
    ]]>
  </Code>
</Snippet>
```
