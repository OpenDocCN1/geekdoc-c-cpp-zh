The C# compiler checks the syntax and decides what kind of operation is to be carried out with dyn. According to the type of the operation, it packages the necessary information so that the runtime can pick it and determine what the meaning of it is, an actual object referenced by dyn. The result of most dynamic operations is itself type dynamic; the exceptions are implicit or explicit conversion, and constructor call. These operations have a natural static type.

# Dynamic Dispatch

At-time, a dynamic operation is dispatched to the target object dyn with the following steps:

+   1. If dyn is a COM object, the operation is dispatched dynamically through COM IDpatch interface. This involves calling COM types that don't have a Primary Interoperability Assembly (PIA), and relying on COM features that don't have a counterpart in C# (such as indexed properties and default)
2. If dyn implements the interface of the System.Dynamic name, dyn is asked to perform the operation. (Of course, the run-time uses IDynamicMetaObject to do that)
3. Otherwise, dyn is a standard .NET object, and the operation will be dispatched using reflection on its type, and a C# "run-binder" that implements C#'s lookup and overload resolution semantics at run-time. (Run-time benders are explored in more detail later in this chapter, "Dynamic Language Run-time.")

The IDynamicMetaObjectProvider type is a great way to completely redefine the meaning of dynamic operations, and so is an extens point to define a custom run-binder to resolve any kind of type operations.

This is used by dynamically languages such as Python and Ruby to implement their own dynamic object models. It is also used by APIs (such as the HTML DOM) to allow direct access to the object's properties using C# syntax.

# Compile Time Semantics

It seems the compiler has an easy job to make a decision on which operations to compile to static binding and which dynamic binding. For example, you might think the compiler does with the following snippet:

```
dynamic someValue = DateTime.Now;
Console.WriteLine(someValue.Ticks);
```

You probably think the compiler works like this:

+   1. DateTime.Now is put into a dynamic object.
2. The property field Fields is resolved with dynamic binding.
3. Console.WriteLine is invoked with static (compile-time) binding.

Yes, it is Easy. But it would be a wrong solution if it wanted this way! Look at the following method where str is a string and dyn is a dynamic variable:

```
Console.WriteLine(str, dyn);
```
