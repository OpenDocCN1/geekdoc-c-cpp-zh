# Parallel.ForEach

The Parallel.ForEach method is very similar to the Parallel.For method. It allows executing iteration concurrently. The ForEach method also resembles For, because it has two main branches. ForEach<TSource> provides the functionality similarity to For, while ForEach<TSource, TLocal> implements the construct communication among iterations.

However, there is an essential difference between For and ForEach. While For iterates through a range of integral values (int or long), ForEach iterates over elements of an IEnumerable<TSource>. The ForEach method has overloads for For — actually, each variant of For having the matching variant of ForEach. Consider the following signatures of For:

```
ParallelLoopResult For(int inclusive, int toExclusive, ParallelOptions options,
Action<int> int body);
```

```
ParallelLoopResult For<TLocal>(int inclusive, int toExclusive,
ParallelOptions options,\Func<TLocal> localInit, Func<int, ParallelState, TLocal, TLocal> body,
Action<TLocal> localFinal);
```

You can find the matching versions of ForEach as shown in the following code snippet:

```
ParallelLoopResult ForEach<TSource>(IEnumerable<TSource> source,
ParallelOptions options, Action<TSource> body);
```

```
ParallelLoopResult ForEach<TSource, TLocal>(IEnumerable<TSource> source,
ParallelOptions options, Func<TLocal> localInit,
ForEach<TSource, ParallelState, TLocal> body,
Action<TLocal> localFinal);
```

The semantics for the ForEachState value, the localbody, and localFinally delegates are erased as the introduced earlier when treating the For methods. A slight difference is that the body takes an delegate of TSource instead of an iteration index. There are method overloads which you can pass a TSource and a long index to the body delegate with the following signature:

```
ForEach<TSource, TLocal>(long, long, TLocal> body);
```

When you think about how to implement a parallel For for partitioning, so that the work should however be distributed among the CPU cores (or threads). It's very easy to partition a range of integers represented by the frominclusive and toExclusive parameters. However, partitioning an IEnumerable<T> is more difficult, because its length is unknown, and it can be traversed sequentially.

The TPL uses an approach represented by the Partitioner<T> for partitioning strategies of IEnumerable<T> collections. In several scenarios, when the data in the collection is order (for example, items in a Dictionary can be ordered by item keys), partitioning can be done with ordering. The OrderingPartitioner<T> is a class for this approach.

ForEach has overloads where the source parameter of the methods can be represented by a Partitioner<T> or OrderedPartitioner<T>, inside of IEnumerable<T>.
