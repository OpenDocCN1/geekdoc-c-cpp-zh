# The Project Structure

When you created the AcmeLibrary project, Visual Studio generated several folders and files. You can follow this structure in the Solution Explorer tool, shown in Figure 18-7.

The first important folder from the web application's perspective is the Content folder. It contains the cascading style sheet (CSS) files for the application. Usually, an Images under the Content folder holds the images used in the web. You can change the overall design of your site by modifying Site.css file or changing it another CSS file (and, of course, replacing Site.css references in the appropriate masters).

The second important folder is the Scripts folder. It contains about a dozen JavaScript files for the project you created. It is worth mentioning that your project has built-in support for jQuery client-side scripting, and a jQuery validation plugin-to model validation in HTML forms without an additional round-trip to the server.

As their names suggest, the three other folders (Controllers, Models, and View) are also related to the MVC pattern. The Controllers folder contains the classes that play the controller role in project. Figure 18-7 shows Visual created two controllers, one for the Home page (HomeController.cs) and another one for the About page (AccountController.cs).

The Views folder is the container for all classes playing the view in the MVC pattern. Classes representing views and their helper are grouped into subfolders. The Account folder holds views related to the logon and account-handling functionality; Home encapsulates the views related the About and Home pages. (This is one in the Index.aspx file, and later this will be explained.) The Shared folder holds helper pages and type, as the Error.aspx, LogOnUserControl.cs and Master.files.

> When you look at the .aspx, .ascx, and Master files, you can recognize that they do not have code-behind files in contrast to the files with similar extensions in ASP.NET web projects. Many functions handled by the code-behind files in ASP.NET projects (such as, for example, collecting form data, validation, and navigation) are managed in a totally different way in ASP.NET MVC, with no need for a code-behind file.
