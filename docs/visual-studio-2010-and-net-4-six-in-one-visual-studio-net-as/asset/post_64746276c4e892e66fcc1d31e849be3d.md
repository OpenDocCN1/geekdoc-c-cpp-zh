
# Other Features

There are a lot of Silverlight features not yet examined. However, because this chapter is just an introduction to WPF and Silverlight, these features will only get a few paragraphs of coverage, despite the fact that entire chapters (or even books) could be written about some of them.

## Out-of-Browser (OOB) Applications

Silverlight applications mostly live in the browser as plug-ins. However, Silverlight supports applications out of the browser, and onto the desktop. Installing out-of-browser (OOB) applications is always a user-initiated process — either by right-clicking the Silverlight application and choosing "Install <appname> to this computer," or by clicking on a developer-created piece of UI that calls the Application.Install method. Either way, the user is prompted whether she really wants to install the application, and whether the installer should create a shortcut on the Desktop or Start Menu.

By default, OOB applications run within the same sandbox as the browser, so no user account (UAC) prompts are necessary. OOB applications work on OS X as well, so here is a great way to create OS desktop applications without even running a Mac!

Some features are only available in OOB mode. These include the WebBrowser control and the HtmlBrush control. The WebBrowser is a full-featured web browser that can be used as a rectangular frame within the Silverlight application, and any web page or HTML content (including websites that have other Flash, plug-ins). HTMLBrush is similar to VideoBrush. When attached to WebBrowser control it can be used as a brush for any element. However, WebBrowser control remains interactive and accepts keyboard and mouse input, VideoBrush handles the interactivity.

OOB applications can also be installed with elevated privileges. Figure 8-36 shows OOB settings in Visual Studio 2010. Elevated privileges enable the cross-domain policy, and allow reading from or sending information to files and directories; and allow a level of COM interoperability, so that automation can be denied.

## Printing

Printing is Silverlight's most requested feature. Printing in Silverlight is based on a callback model:

```csharp
PrintDocument pd = new PrintDocument();
pd.DocumentName = "Silverlight";
pd.PrintPage += (obj, args) => {
    args.PageVisual = LayoutRoot;
    args.HasMorePages = false;
};
pd.Print();
```

In the PrintPage handler, a UIElement can be defined that will be rasterized and sent to the printer. UIElement does not necessarily have to be in the visual tree; it can be constructed on-the-fly, and in memory. MorePages property tells the engine whether there will be more pages — if so, PrintPage event gets called again for the next page.

## Bitmap Effects

Bitmap effects (or shaders) originate from computer graphics and are usually tied to graphics processors (GPUs). In Silverlight, the language used to create shaders is High-level Shading Language (HLSL). However, adding shaders to a Silverlight application comes with a performance penalty. Even though shader program is JITed and run on available cores, it can still slow down the application. Silverlight has two built-in shaders: Blur and DropShadow. Both have properties allow fine-tuning them, and with the capacity to create custom effects using HLSL, they can really add to the visual appeal of application — when not overused.

## Local Messaging

If several Silverlight applications or plug-ins are on the same computer, local messaging enables communication between the applications — even if they are not running on the same web page or OOB. Local messaging works with message channels, and has a fairly simple API.

For sending messages, create a LocalSender object with the name of the messaging channel, and call its SendAsync(string). For receiving messages, a LocalReceiver object must be created the same way, and the MessageReceived event is fired when a message arrives. The receiver can also receive a reply using MessageReceivedEventArgs.Response property that the sender can receive in the SendAsyncCompleted event. For bidirectional communication, the applications can set up two communication channels — one for each direction.

## GPU Acceleration

Silverlight 3 and later versions support limited GPU acceleration. GPU acceleration can be turned on for the entire plugin via the `<object>` tag in the HTML file that holds the plug-in, adding the following parameter:

```html
<param name="enableGPUAcceleration" value="true" />
```

On Mac OS X, GPU acceleration only works in full screen. Another requirement is a DirectX-9-compatible video card or OpenGL-compatible for the Mac.

GPU acceleration can only help in certain situations. Unlike WPF (where GPU composition is the default), Silverlight doesn't have to be very over and where to use the GPU. The developer must manage the `UIElement` by setting the `CacheMode` property to `BitmapCache`.

The key to understanding how GPU acceleration works in Silverlight is that it is nothing more than transferring the rendered bitmap for the specified UIElement into the memory of the graphics card, and doing the rest of the composition. GPU acceleration can help when the pixels of the rendered UIElement (along with its children) are rarely changing and thus, the cache does not need to be invalidated.

Composition on the GPU can offload the work of translation, scale, rectangular clipping, or rotation animations and alpha blending to the GPU, freeing the CPU to do other tasks, increasing the performance of the entire application. Silverlight also has mechanisms in GPU-accelerating video, making full screen HD video possible even with today's high-resolution monitors. GPU can help accelerate perspective transforms, but in Silverlight 4, pixel shader effects are still performed by the CPU.

## Isolated Storage

Isolated storage is a local storage on the user's computer that can be used as a local cache, store user preferences, or other data. Every application has a quota of 1 MB per application, which increases to 25 MB when the application is installed as an OOB application. The quota can be increased needed with user consent. Even though the physical storage on the computer where the isolated storage files are stored is hidden, the actual content is not obfuscated, thus it is not suitable for storing passwords. Isolated storage can be thought of as a virtual file system. It also allows for key-value combination via the application-scoped IsolatedStorage.ApplicationSettings or site-scoped IsolatedStorage.SiteSettings.

## Navigation and Search Optimization

As Silverlight (and other RIA technologies) merge the web with desktop, some usability questions arise. Whether to choose a desktop-like or web-like experience is, of course, up to the UX designer. But, if deep linking and back button support is needed, Silverlight's built-in Navigation Framework can help. Visual Studio 2010 includes an template called Silverlight Application. Creating a project based on this template results in an application with a few pages (Home and About). Clicking on the navigation links behaves just like clicking on a browser — the program switches to “page,” and the URL changes (for, the About page's URL adds a # to the end).

The important difference between this and conventional browser navigation is that the page does not reload — Silverlight keeps running, and no intermediate page is shown, as is with HTML pages. Back and forward buttons in the navigation, just like bookmarking and deep linking. The key to the navigation API is the System.Windows.Controls.Frame class. Frame hosts Pages, handles navigation, and can integrate with the browser. There are also facilities to extract information from the query string (NavigationContext), and URL mapping (UrlMapper).

What about Search Engine Optimization (SEO)? It is not practical to build up a full website using Silverlight if search engines cannot read the information and, therefore, visitors won’t come to the site. The two-sentence version of the SEO trick is to build a “mirror” in ASP.NET that feeds from the same data, and outputs the relevant content and navigation within the fallback part of the Silverlight’s <object> tag in the hosting page. The ASP.NET application can also dynamically generate the robots.txt sitemap XML to direct the search engines' spider to the right content.
