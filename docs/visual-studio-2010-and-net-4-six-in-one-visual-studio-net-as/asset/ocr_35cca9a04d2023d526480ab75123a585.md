```
public dynamic MyOperation(int a, dynamic arg)
{
    return a + arg;
}
```

You can use them in members as types and also as constructor arguments, as shown here:

```
class MyClass
{
    dynamic _Arg;

    public MyClass(dynamic arg)
    {
        _Arg = arg;
    }
}
```

Compared to C# 4.0, the .NET Framework's Common Language Runtime (CLR) does not have a separate intrinsic type for dynamic. Instead, the compiler uses System.Object everywhere, and internally flags the variables as dynamic to use this information during compilation. This implementation has a few consequences:

+   - With System.Object, there is an implicit conversion from every type (other than pointer types) to dynamic, and an explicit conversion from dynamic to every such type.

+   - If method signatures differ only by dynamic versus System.Object, they are considered to be the same.

+   - The typeof(dynamic) expression is true.

Although System.Object and dynamic are considered the same, the type inference algorithm prefers System.Object if both are candidates for a certain expression.

# The Dynamic Language Run-time

An important component in the underlying implementation of dynamic lookup is the Dynamic Language Runtime (DLR), which is part of .NET Framework 4.0. DLR is a run-time environment that adds a set of services for dynamic languages to the Common Language Run-time (CLR), which makes it easier to develop dynamic languages to run on the .NET Framework, as well as to add dynamic features to statically typed languages. DLR is built on top of the CLR, and uses run-time binders to access the physical object model by dynamic expressions.

The DLR provides most of the infrastructure not only C# dynamic lookup, but also the implementation of several dynamic programming languages on .NET (such as IronPython and IronRuby). DLR provides an excellent caching mechanism (named Call Site Caching) that greatly enhances the efficiency of run-time dispatch. To the user of dynamic lookup in C#, the DLR is invisible.
