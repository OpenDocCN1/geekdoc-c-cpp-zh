```
*MyDataService.MyAjaxEnabledServiceAspNetAjaxBehavior* 
binding="webHttpBinding" contract="MyDataService.MyAjaxEnabledService" />
<service>
<behaviors>
<endpointBehaviors>
<behavior name="MyDataService.MyAjaxEnabledServiceAspNetAjaxBehavior">
<enableWebScript />
</behavior>
</endpointBehaviors>
<behaviors>
<behavior name="ServiceMetadata" httpGetEnabled="true" />
<serviceDebug includeExceptionDetailInFaults="false" />
</behavior>
</behaviors>
</behaviors>
</service>
<system.serviceModel>
```

You can see from this example that a service is defined, and the service endpoint is set up with a address using the webBinding and the specific service contract in your application.

Consuming this service is just drag and drop a ScriptManager in your web form and specify the Script reference path, as shown here:

```
<asp:ScriptManager Id="ScriptManager1" runat="server">
n<Services>
<asp:ServiceReference Path="~/MyAjaxEnabledService.svc" />
</Services>
</asp:ScriptManager>
```

With this complete, you can now refer the service name by within JavaScript for you application. For example, if MyAjaxEnabledService contained a method for GetWeatherInformation that returned a string, you could use the following code to display the information to the user.

```
<script type="text/javascript">
function GetWeather()
{
MyAjaxEnabledService.GetWeatherInformation(onSuccess);
function onSuccess(result)
{
document.getElementById('myelement').value = result;
}
n</script>
```

As you can see, this is very simple because the ScriptManager has completed most of the heavy lifting and created function calls with callbacks and other forms of management.
