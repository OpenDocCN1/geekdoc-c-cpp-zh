protected void ExpertiseList_SelectedIndexChanged(object sender, EventArgs e)
{
    var experts = new Dictionary<int, Expert>();
    ExpertiseList.Items.Clear();
    var da = new DataAccess(Server);
    foreach (var item in da.GetExpertList(ExpertiseList.SelectedValue))
    {
        ExpertiseList.Items.Add(new ListItem(item.Name, item.Id.ToString()));
        experts.Add(item.Id, item);
    }
    Session["Experts"] = experts;
    if (ExpertiseList.Items.Count > 0)
    {
        ExpertiseList.SelectedIndex = 0;
        ExpertiseList_SelectedIndexChanged(ExpertiseList, EventArgs.Empty);
    }
}

protected void ExpertiseList_SelectedIndexChanged(object sender, EventArgs e)
{
    var experts = Session["Experts"] as Dictionary<int, Expert>;
    if (experts != null && experts.TryGetValue(int.Parse(ExpertiseList.SelectedValue), out Expert expert))
    {
        Description.Text = expert.Description;
        Photo.ImageUrl = "/Photos/" + expert.Photo + ".jpg";
        Photo.Visible = true;
    }
}

# Improving FindExpertDemo with Ajax Control

There are a few issues with the FindExpertDemo solution. The first time you select an item from the expertise drop-downs, a postback occurs and the page flickers. The second is that you do not have similar "Select an expertise" or "Select an expert" drop-downs.

You can use the Ajax Control Toolkit to solve these issues. The Toolkit contains a control named CascadingDropDown that can be attached to ASP.NET DropList to get automatic population of a set of controls. CascadingDropDown also enables a scenario where the contents of one list depends on selection of another without having to embed the entire data set in the page or transfer it to the client.

# Adding a Toolkit to Ajax in ASP.NET

When you work with Ajax in ASP.NET, you must add a ScriptManager object to your page that is responsible for managing script libraries and files, partial-page rendering, and client proxy generation for web services. If you try to use the Ajax Control without it, you'll get some error messages that depend on what kind of control you use.

You should use the ToolkitManager object (you can drag it from the Ajax Control to your page) instead of ScriptManager. The ToolkitManager class derives from ScriptManager and enables the combination of multiple script files in the corresponding web page.

So, drag and drop the ToolkitManager to your page somewhere within the <form> element. The source code should look like this:

```html
<body>
  <form id="form1" runat="server">
    <asp:ScriptManager Id="ToolkitManager1" runat="server" />
    <!-- ... -->
  </form>
</body>
```

If you simply type the ToolkitManager declaration, the project will not contain the necessary references, and you will get an error about the unknown control.

# Adding CascadingDropDown Extenders

There are two drop-down lists on the page, one for each. You can also add these controls within the form. Let's add them directly before the closing </form> element:

```html
<form id="form1" runat="server">
  <asp:ScriptManager Id="ToolkitManager1" runat="server" />
  <!-- Form here -->
  <asp:CascadingDropDown Id="ccExpertise" runat="server"
    TargetControlID="ExpertiseList"
    Category="Expertise"
    PromptText="Select an Expertise"
    LoadingText="Loading..."
    ServicePath="ExpertiseService.asmx"
    ServiceMethod="GetDropDownContent" />
  <asp:CascadingDropDown Id="ccExpert" runat="server"
    TargetControlID="ExpertList"
    Category="Expert"
    ParentControlID="ExpertiseList"
    PromptText="Please select an Expert"
    LoadingText="Loading..."
    ServicePath="ExpertiseService.asmx"
    ServiceMethod="GetDropDownContent" />
</form>
```

As you can see, there are many properties used by CascadingDropDown. TargetControlID tells the extender which PromptText tells what to use for the default item in the list representing that no item is selected. When the control's content is loaded, the text defined by LoadingText is displayed in the control.

The content of the DropList may have different content depending on the UI logic. For example, in a use case, it may contain vehicle categories, or later concrete car models. The category is the only content of the DropList that should be populated.

The second extender with the control ID identifies a property name ParentControlID. It represents the identifier of the DropList that is used as the parent control. As the parent's values change, it is re-populated according to the value selected in the parent control. For example, in the FindExpertDemo, when the user uses the Expertise drop-down to "Visual Basic," the Expert drop-down is populated with the name of Visual Basic experts.

The CascadingDropDown extender uses ASP.NET web services to populate the content of the attached DropList. The ServicePath property refers to the web service responsible for the population, while ServiceMethod handles the name of the method to be called. This method has the following signature:

```csharp
public CascadingDropDownValue[] ServiceMethod(string knownCategoryValues,
  string category);
```

The knownCategoryValues argument contains entries when the service is called for a DropList that is not a parent (ParentControlID is set), or by the parent control's Category property and its selection. The category argument is for the control's Category property. For example, when the ExpertiseList is populated, knownCategoryValues is an empty string, while category is set to "Expertise." When you select "Visual Basic" the service is called to populate the ExpertiseList control with knownCategoryValues set to Expertise;1 and category to Expert.
