+   MyTemplate.vtemplate — This is the most important file in the archive — the template manifest. The IDE recognizes .zip file as a template from this manifest. This file is also used to describe information the IDE leverages to put the project or item into the appropriate category within the New Project and File dialogs, and also defines some behavior-related attributes.

Later in this chapter, you'll see a detailed description of the structure and the usage of the manifest file. First, let's take a look at a template directory storage structure.

# Template Folders

All archives representing project and item templates are stored in a specific location. Here are two kinds of folders:

+   System folders — These are installed with Visual Studio setup, and all of the users can access them. The root of the system folders can be found under the Visual Studio installation folder in the Common7\IDE\ProjectTemplates and in the Common7\IDE\ItemTemplates folders, respectively.

+   User folders — These are located within the current user's profile, and templates here can be accessed only by the owner using the profile. User folders can be found under the My Documents folder in the Visual Studio 10\Templates\ProjectTemplates and Visual Studio 10\Templates\ItemTemplates folders.

In addition to the system folders, you can find two other folders under Common7\IDE—ProjectTemplatesCache and ItemTemplatesCache. The internal structure of these folders is the same as ProjectTemplates and ItemTemplates, but instead of .zip files, you can find folders with the .zip extension representing the extracted content of the corresponding files. Visual Studio uses these cache folders for performance reasons.

Visual Studio scans the template information in the ProjectTemplates and Item folders when you open the New Project or Add Item dialog. It is difficult to understand how the folder structure and the .zip files are mapped to the structure you see in the dialogs. In addition to the folder structure, Visual Studio uses some other information to build the category hierarchy.

# Understanding the Project Template Hierarchy

To map the folders and templates into the categories that can be seen in the New Project dialog, the IDE counts on other information, including the following:

+   Visual Studio looks up the registry to build up the category structure in the dialog. This information can be found under the HKEY_CURRENT_USER hive in the Visual Studio 2010 configuration root (Software\Microsoft\Visual Studio\10.0\Config) in the NewProjectTemplates key.

+   A few template folders contain an XML file with .vstdir. These files are used to declare localized names and sort orders for the templates in the folder in the .vstdir file is located.
