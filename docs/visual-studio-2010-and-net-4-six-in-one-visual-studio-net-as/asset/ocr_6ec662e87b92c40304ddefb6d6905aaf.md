derived from Task, so you can substitute a Task instance with a Task<Result> instance anywhere.
Of course, the delegates representing task bodies must be instances of Func<T> instead of
instances of Action, because they must retrieve a TResult.computed value (object) can be
queried through the Task<TResult>.Result property.

Result has a nice behavior. If the task is not finished, Result will wait for the completion
before retrieving the property value. Be aware that Result does not start the task, so in case
of a non-running task, you should wait infinitely for Result.

Listing 10-16 shows a short example demonstrating Task<Result> concepts.

# Listing 10-16: Using Task<Result>

```
using System;
using System.Threading;
using System.Threading.Tasks;

namespace TasksWithResults
{
    class Program
    {
        static void Main(string[] args)
        {
            var task1 = Task.Factory.StartNew<int>(() =>
                int result = 0;
                for (int i = 0; i < 1000000; i++) result = i + i%10;
                return result;
            });
            var task2 = Task.Factory.StartNew<double>(() =>
            {
                double result = Math.PI;
                for (int i = 0; i < 10; i++)
                {
                    Thread.Sleep(10);
                    result *= (i+1)*Math.E;
                }
                return result;
            });
            var task3 = Task.Factory.StartNew<string>(() => "The result is: " +
                Console.WriteLine(task3.Result + task2.Result));
            Console.WriteLine("Press Enter to exit...");
            Console.ReadLine();
        }
    }
}
```
