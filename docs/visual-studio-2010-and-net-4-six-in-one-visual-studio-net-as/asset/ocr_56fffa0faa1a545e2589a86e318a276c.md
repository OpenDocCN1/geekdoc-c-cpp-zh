# TABLE 6-3: IDTExtensibility2 Members

| METHOD | DESCRIPTION |
| --- | --- |
| OnConnection | This event is raised when the add-in is loaded into the Visual Studio IDE. The application parameter points to the root object of the DTE automation model. addInst refers to the AddIn instance in the automation model describing this add-in. connectMode parameter defines the way in which the add-in is loaded into the IDE. Define this code to set up your add-in during connection time. |
| OnDisconnection | The Visual Studio raises this event when the add-in is disconnected from the IDE. The disconnectMode parameter specifies why the add-in has been disconnected. Use this method to put the add-in clean up code. |
| OnAddsUpdate | This event is raised by the IDE when the add-in is loaded or unloaded in the IDE. You must define this method when you want to check dependencies among add-ins. For example, to ensure that all add-ins on your add-in are loaded. |
| OnStartupComplete | This event is raised when Visual Studio finished the startup process. At this point, all add-ins are loaded into memory, so you can access them to finish your initialization. You should put all the initialization code here that assumes any other add-ins or Visual Studio services are available. |
| OnBeginShutdown | The IDE sends this event to the add-in when Visual Studio starts the shutdown process. |

You can see in Listing 6-1 that the OnConnection method defines how to initialize the add-in. All other methods have they. OnConnection first stores the references to the automation root in the _applicationObject and the current add-instance in the _addgetInstance field, because they are used later. When the IDE loads the add-in to set up its interface (using the ext_cm_UISetup connection), it triggers a few tasks implemented by this method:

+   - In a few steps, it obtains the reference to the Tools menu bar and stores it into the toolsPopup variable.
- It creates a new command with the AddNamedCommand2 passing the add-in instance and other parameters. It sets up the menu UI for this command (names, icon, and visual properties) As a result of the method, when the menu item is clicked, the IDE routes this command to the add-in.
- It adds the item to the Tools menu bar.

The IDocumentTarget interface defines two methods:

+   - The QueryStatus method is called by the Visual Studio IDE to check whether an add-in can understand the command (this is what the command means and execute it). The add-in also has a chance to retrieve the status of commands it supports (for example, enabled/disabled, visible/hidden). Also, this method is used by the IDE to allow the command to set its menu item and status bar.
