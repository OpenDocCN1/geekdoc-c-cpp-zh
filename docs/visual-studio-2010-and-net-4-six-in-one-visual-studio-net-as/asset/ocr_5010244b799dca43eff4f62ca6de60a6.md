The term "document window" reflects that any instance of them is associated with an entity document and is owned by a so-called hierarchy. The document and the hierarchy are abstractions that can have many different physical manifestations.

For example, the documents behind document windows in Figure 5-5 are the in-memory representations of the source files named in the title. The source files are not the documents; they are only the persisted forms of the abstraction called "document". You should edit a SQL server title within the IDE, for a document window would have an in-memory representation of the document that is persisted as a SQL server database.

The hierarchy represents a collection of documents and other resources that are used to build the artifacts of a solution composed from one or more projects. A project is the smallest unit of related documents that can be used to build an artifact (for example, C# source files and referenced assemblies that can be compiled into a class). In Solution Explorer, each project is a hierarchy.

The documents in Figure 5-5 are owned by the LoremQuery project (hierarchy) in the Solution Explorer. The hierarchies in the Server Explorer also offer document windows. For example, through data connections created in Server Explorer, you can edit the content of SQL server tables or modify stored procedures. Document windows in this case are owned by the hierarchy representing the data connection.
