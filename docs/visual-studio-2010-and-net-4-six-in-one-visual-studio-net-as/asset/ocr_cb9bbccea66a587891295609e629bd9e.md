The following code snippet shows how you can use Object Services to retrieve data exposed by the EDM:

```
using (ObjectContext context = new ObjectContext("Name=WroxEntities"))
{
    var result = from p in context.CreateQuery<WroxModel.Product>("WroxEntities.Product") select p;
    foreach (WroxModel.Product product in result)
    {
        Console.WriteLine(product.ProductName);
    }
}
```

# # CHOOSING BETWEEN LINQ TO ENTITIES AND LINQ TO SQL

Both the Entity Framework and LINQ to SQL provide ORM functionality. Deciding which of the two is more appropriate for a complicated decision-making process depends on your specific implementation.

For example, LINQ to SQL is a solution that is designed to go against Microsoft SQL Server directly. If you need communication with another data source, the Entity Framework is a much more appropriate solution.

The Entity Framework also supports much more complex data mapping and query processes. For example, LINQ to SQL provides one-to-one mapping of tables, views, and stored procedures. The Entity Framework has the capability to handle many-to-many relationships and other more complex situations, or for a single class to map data within multiple tables.

You consider LINQ to SQL as the predecessor (or "little brother") to the more robust and powerful Entity Framework. Various online sources indicate that Microsoft is recommending the Entity Framework as the "going forward" technology.
