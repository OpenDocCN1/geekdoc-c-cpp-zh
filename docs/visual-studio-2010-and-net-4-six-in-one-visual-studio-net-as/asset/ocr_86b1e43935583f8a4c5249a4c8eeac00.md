Here, the taskType, timeout, and useMultipleCores parameters are all optional and can be omitted in method invocations:

```
DoTheWork(123, "Processing", 4000, true);
DoTheWork(124, "Removing files", 6000);
DoTheWork(125, "Adding ID");
DoTheWork(126);
```

# Rules for Using Optional Parameters

C# 4.0 does not allow you to omit arguments between commas, so you cannot write something like this:

```
DoTheWork(123, , ,);
```

The designers of the language thought this could lead to highly unreadable comma-counting code — they are right. Instead of writing commas, use named arguments.

There are a few rules for using required and optional parameters:

+   * Parameters with ref or out modifiers cannot have default values.

+   * A required parameter (without a default value expression) cannot appear after an optional parameter in the formal parameter list.

+   * The default values of optional parameters must be constant expressions, or one of the new or the default operators must have a value type. These can be resolved during compile time, while other expressions cannot.

# Optional Parameters and Indexers

Accessors are actually methods, so you can use optional parameters in getter and setter methods of indexes. For example, you can define a class implementing a sparse matrix as follows:

```
public class SparseMatrix<T>
{
    public struct SparseIndex
    {
        public int Row;
        public int Column;
    }
    Dictionary<SparseIndex, T> _Storage = new Dictionary<SparseIndex,T>();
    public T this[int row = 0, int column = 0]
    {
        get
        {
            T result;
            return _Storage.TryGetValue(new SparseIndex { Row = row, Column = column }),
        }
}
```
