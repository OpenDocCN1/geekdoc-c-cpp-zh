The same issue also holds for ordinary object values, which are "sealed" against ordinary pattern matching, and once again when you resort to various members that publish and use these to drive pattern matching.

What's needed is a mechanism to translate values of a given type to a set of "shapes" that you can then pattern match. Luckily, F# provides this mechanism via its so-called active pattern feature. Active patterns (also called active pattern recognizers) allow you to define for any value a set of named partitions called the active pattern results that you can match against as they were simple cases in a discriminated union.

Active patterns can carry values as ordinary discriminated union constructors, allowing you to tag values of arbitrary complexity to each pattern result. Furthermore, your active pattern definitions can be total or partial.

There are three fundamental types of active patterns that you should be aware of, and each has its distinctive advantages and usage patterns. They are summarized in Table 25-17.

## TABLE 25-17: Active Pattern Uses

| GOAL | TYPE | DESCRIPTION |
|---|---|---|
| Conversion | Single-case, complete | Converts the given value to a new value. |
| Segmentation | Multi-case, complete | Groups all values of a given type into a set of shapes/groups. |
| Characterization | Single-case, partial | Provides a characteristic trait to some values in a given type. |

Active patterns patterns have a distinct place in the language, and they are treated differently than ordinary pattern matches.

When you define active patterns, you must separate each pattern recognizer with a pipe (|) character, and insure the entire set that belongs to a active pattern by pipes.

Let's walk through the different active pattern families from Table 25-17.

Single-case complete active patterns behave much like a normal function that converts the value being matched to another value. This conversion is more convenient than a simple function, however, since it allows you to bind and extract the result in the same step. Consider the following example, where you get input from your user and print trimmed from leading and trailing white-space:

```fsharp
// Define a trimming function
let trim (s: string) = s.Trim()

// Read user input
let input = System.Console.ReadLine()

// Perform trimming
let trimmed = trim input

// Print the result
trimmed | printf("Result=%s")
```

You can define an active pattern for the trimming "conversion":

```fsharp
// Define a conversion active pattern
let (|Trim|) (s: string) = s.Trim()

// Read user input and perform conversion
let (Trim trimmed) = System.Console.ReadLine()

// Print the result
trimmed | printf("Result=%s")
```

Note how you can perform the trimming by pattern matching using the Trim active case. You can also use active patterns as a function — in this case, you will need the pipes:

```fsharp
System.Console.ReadLine()
| (|Trim|)
| printf("Result=%s")
```

Multi-case active patterns (in addition to these, you have just seen) to segment a given value space into multiple active patterns. This is useful when you have a fixed set of "groups" that describe the values in a given type completely. A trivial example is splitting integers into even or odd numbers:

```fsharp
let (|Even|Odd|)(i: int) =
  if i%2 = 0 then
    Even
  else
    Odd
```

Another slightly more complex example is dividing string values into five different categories: nulls, empty (those strings that, when trimmed from white-space, yield an empty string), integers (those strings that store integer values), floats (those strings that store real numbers), and normal "strings" that don't fall into any of these categories.

First, System.Int32 and System.Double support a TryParse method that can be used to check whether a given string contains an integer or double, respectively. Instead of creating two nearly identical functions, you can create a generic one. This is parameterized over the type it can check. You can give it the "zero" value (or any value in that type matter) and the parse function that can take a string, and return whether it was successfully converted to the given type and the converted value. Without having to worry how TryParse is implemented (after some consideration, you would likely prefer a more comfortable signature, as mapping strings to int or float options), you have something like the following:

```fsharp
open System

let tryParseGeneric<'T> (zero: T) parse (s: string) =
  let i = ref zero
  if parse(s, i) then
    !i | Some
  else
    None

let tryParseInt = tryParseGeneric<int> 0 Int32.TryParse
let tryParseFloat = tryParseGeneric<float> 0 Double.TryParse
let (|Empty|Null|Integer|Float|String|) (s: string) =
  if s = null then
    Null
  elif s.Trim() = "" || String.IsNullOrEmptyOrEmpty then
    Empty
  else
    match tryParseInt s with
      | Some i ->
          Integer i
      | None ->
        match tryParseFloat s with
          | Some f ->
              Float f
          | None ->
              String (s.Trim())
```

Basically, complete active patterns use some heuristics (most typically, a set of if statements or match cases) to figure out which active pattern works. Whenever a particular result is appropriate, you would like to discriminate it that, by giving its name and supplying any values you want to make available in the pattern match when that is matched.

There is a subtle detail that you should be aware of. The pattern cases you list will constitute the closed list of shapes that can match against once the active pattern is applied to a value. So, even if you are not using a particular shape from those defined, you still need to cover it in an actual match expression.

So, going back to the example, this implementation guarantees that a particular string value can be only matched by one of the active pattern cases, and it guarantees that all strings fall into one of these pattern results. This is of great help, because the compiler can warn you of incomplete pattern matches. Simply try to remove any of the match cases from the following function to see that in action:

```fsharp
let PrintString = function
  Empty ->
    printfn "empty or whitespace"
  Null ->
    printfn "null"
  Integer i ->
    printfn "number:%d" i
  Float f ->
    printfn "float:%f" f
  String s ->
    printfn "other:%s" s
```

Often, though, the difference between the various "groups" is not so clear-cut — and you can either characterize the entire space at once (because you may not know about all possible cases), or you don't care to.

Consider the following *active patterns*, reusing the functions you defined earlier:

```fsharp
let (|Integer|) = tryParseInt
let (|Float|) = tryParseFloat
```

Here, the difference from the previous complete active patterns is that there is only one case, with the "partial" nature being reflected in the "catch-all" case — and you will get a compiler error if you try to define a partial active pattern with more than one.

In this example, tryParseInt and tryParseFloat have the following signature:

```fsharp
val tryParseInt = (string -> int option)
val tryParseFloat = (string -> float option)
```

Essentially, both they parse a string and return an option value of the appropriate type. Thus, you can use them as partial active patterns. Note how you bind the input parameter (to match against), making obvious that these functions behave exactly like partial active patterns.

As you expect, matching with partial active patterns always need a "catch-all" case:

```fsharp
match getSomeNumber() with
  Integer i ->
    printfn "Is an integer=%d" i
  Float f ->
    printfn "Is a float=%f" f
  | ->
    printfn "Unknown"
```
