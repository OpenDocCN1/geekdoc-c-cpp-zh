# TABLE 11-4: Flow Control Activities

| ACTIVITY | DESCRIPTION |
| --- | --- |
| DoWhile | This class represents a looping activity that executes contained activities at least once, until a condition is no longer true.

First, the body of DoWhile is executed, and then the Condition property is checked. While this condition is met, the body is executed cyclically. |
|ForEach<T> | This activity executes its body action for each value provided in the Values collection. T defines the type of values provided in the Values collection. |
| If | This activity models an If-Then-Else statement with a Boolean Condition. When it is evaluated to true, the activity in the Then property is executed; otherwise, the activity set in the Else property is carried out. You can leave either Or or Else empty.

This property is semantically the same as IfElse in WF 3.5. |
Parallel | This activity executes child activities simultaneously and asynchronously. The activity operates by simultaneously scheduling each Activity in its collection at the start. It completes when all of its Branches complete, or when its CompletionCondition property evaluates to true. While all the Activity objects run asynchronously, they do not execute on separate threads, so each successive activity only executes when the previously scheduled activity completes or goes idle. If none of the child activities of this activity go idle, this activity executes them in the same way as a Sequence activity (see more about this later)

This activity has the same name as the Parallel activity in WF 3.5, which is semantically different. |
 This activity enumerates the elements of a collection and executes an embedded statement for each of the Values collection in parallel. You can imagine it using the Parallel activity where the Branches property is set up according to the body of the corresponding ForEach<T> activity. All the executions treated for Parallel are for this activity. |
| Pick | This activity behaves similarly to Switch (see more on this later in this table) that it executes only one of several activities in response to events. The Branches property contains a collection of PickBranch events. Only one of these PickBranch activities is executed — the first that signs its trigger event has been fired. Other PickBranch activities are ignored.
