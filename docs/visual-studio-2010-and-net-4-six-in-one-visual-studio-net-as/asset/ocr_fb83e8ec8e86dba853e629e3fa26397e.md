# Printing

Printing is by Silverlight 4's most requested feature. Printing in Silverlight is based on a callback model:

```
PrintDocument pd = new PrintDocument();
pd.DocumentName = "My Silverlight document";
pd.PrintPage += (obj, args) => {
    args.PageVisual = LayoutRoot; args.HasMorePages = false;
};
npd.Print();
```

In the PrintPage event handler, a UIElement can be defined that will be rasterized and sent to the printer. The UIElement does not necessarily have to be in the visual tree; it can be constructed on-the-fly, and in-memory. The MorePages property tells the print engine whether there will be more pages to print — if so, the PrintPage event gets called again for the next page.

# Bitmap Effects

Bitmap effects (or shader effects, or shaders) originate from computer graphics and gaming, and are usually tied to graphics processors (GPUs). In Silverlight, the same language used to create shaders: High level Shading Language 2.0 (HLSL2.0). However, adding shaders to a Silverlight application comes with a performance penalty. Even though the shader program "JIT-ed" and is run on all available cores, it can still slow down the application. (WPF 4 supports HLSL 3.0, and can run shaders on the GPU).

Silverlight has two built-in shaders: Blur and DropShadow. Both have properties allow fine-tuning them, and, with the capacity to create custom effects using HLSL2.0, they can really add to the visual appeal of application — when, not overused.

# Local Messaging

If several Silverlight applications or plug-ins are on the same computer, local messaging enables communication between the Silverlight applications — even if they are not running on the same web page or if they are running OOB. Local messaging works with message channels, and has a fairly simple API.

For sending messages, create a LocalMessageSender object with the name of the messaging channel, and call its SendAsync(string) method. For receiving messages, a LocalMessageReceiver object must be created the same way, and the MessageReceived event is fired when a message arrives. The receiver can also receive a reply using the MessageReceivedEventArgs.Response property that the sender can receive in the SendAsyncCompleted event. A bidirectional communication is required, the two applications can set up two communication channels — one for each direction.
