delayed until the time of the query. Also, given this behavior, each iteration of results will result in a
new database query being executed.

In the following example, the entire contents of the Products table is returned twice, for each
foreach statement:

```
WroxDataContext dataContext = new WroxDataContext();
var result = from p in dataContext.Products select;
foreach (var v in result)
    Console.WriteLine(v.Name);
foreach (var v in result)
    Console.WriteLine(v.Name);
```

You can get out this limitation by converting the results to a list or an array. This will execute
the query and put the results in memory. The following example executes the query once:

```
WroxDataContext dataContext = new WroxDataContext();
var result = from p in dataContext.Products select;
var list = result.ToList();
foreach (var v in list)
    Console.WriteLine(v.Name);
foreach (var v in list)
    Console.WriteLine(v.Name);
```

The final thing to note here is that, because of the deferred execution model of LINQ to SQL, it is

proper data.

For example, consider the following:

```
result = from r in result order by r.ProductName select;
if(onlyActive) //Variable declared elsewhere

foreach(var item in result)

```

If you did not consider deferred execution when looking at this example, it would be assumed that
tree different database queries would be executed, once, during the foreach loop. Given the way LINQ filters,
the database query is executed once, this allows you to build out
dynamic filter/order condition. This can be especially helpful when working with an advanced
search or other configurable search.
