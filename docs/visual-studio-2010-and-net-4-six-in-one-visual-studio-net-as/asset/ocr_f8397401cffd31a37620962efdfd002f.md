# PAINS WITH INTEROPERABILITY

Before Visual Studio 2010 and .NET 4, using COM object hierarchies in C# were much more cumbersome than in Visual Basic or in macros. To demonstrate annoying details that prevented C# from being coequal with Visual Basic in the COM interoperability field, let's build a simple application using Microsoft Excel and Word. The application displays the ten processes by memory usage, creates an Excel chart, and inserts it into a Word document.

In this example, you will create two versions of the application. First, you will use the programming style you used with Visual Studio 2008 and C# 3.0, and then you will create it with C# 4.0 syntax. Comparing the source code between the two, you'll be able to see the marvelous improvements C# 4.0 offers. You do not have to install Visual Studio 2008 on your machine, because you can produce both applications with Visual Studio 2010.
