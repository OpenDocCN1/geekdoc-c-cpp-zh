## Client-Side Validation

In many cases, the simplest validation rules can be checked at the client side without a round-trip to the server. It's very easy to use JavaScript-based client-side validation with MVC 2. When you created the ASP.NET MVC 2 web application, the required JavaScript files were copied into the Scripts folder. You can easily add client-side validation support to your views. For example, you can modify the main content of the Create.aspx file, as the following code extracts:

```asp
<asp:Content ID="ContentHolderID" Content="MainContent" runat="server">
  <script src="Scripts/MicrosoftAjax.js" type="javascript"></script>
  <script src="Scripts/MicrosoftMvcValidation.js" type="javascript"></script>
  <%: Html.EnableClientValidation(); %>
  <h2><%: Html("Create") %></h2>
  <%: Html.BeginForm() %>
    <%: Html.ValidationSummary(false, "There are some invalid input data:") %>
    <fieldset>
      <legend>New Book Attributes</legend>
      <div class="editor-label">
        <%: Html.LabelFor(model => model.Author) %>
      </div>
      <div>
        <!-- Other fields are omitted from this listing -->
      </div>
    </fieldset>
  <% } %>
  <div>
    <%: Html.ActionLink("Back to List", "Index") %>
  </div>
</asp:Content>
```

You must add only the two `<script> tags and use the `<%: Html.EnableClientValidation()%>` tag. The next time you run the application, model rules defined by the Book metadata are validated at the client side.

However, there are two important things you should be aware of when using the client-side validation:

- The custom validation code you implemented explicitly at the server side (for example, the rule checking of future publication dates) is not checked—and so its failure is not indicated at the client side. When client-side validation rules used, then the model data is sent to the server, and the server-side validation happens there.

Even if you implement validation at the client side, you must not trust only client-side validation. Robust business logic should check all business rules at the server (service) as as well.

## Using Templated Helpers

MVC 2 has a new feature called template helpers, probably the most important feature for developer productivity. Earlier in this chapter, the source code listings of views, you may see several rendering tags that were not explained, such as the following:

```asp
<@ using (Html.BeginForm()) %>
<%= Html.LabelFor(model => model.Author) %>

<%= Html.TextBoxFor(model => model.Title) %>
<%= Html.ValidationMessage(model => model.Title) %>

<%= Html.ActionLink("Back to List", "Index") %>
```

The magical object that has the LabelFor, TextBox, and other methods are invoked in the System.Web.Mvc.PageView class derives the views from. It is type HtmlHelper, which has many methods and extension methods (defined in a dozen classes). With these extensions, you can get rid of creating HTML tags on your own. Actually, thisHelper methods help you with the following services:

- They know how to generate HTML output for native or compound HTML controls, including their attributes.
- They can query the metadata belonging to your model, and this information when generating the code for the view.

These methods work a bit trickier than they look. For example, the LabelFor method accepts a function that projects a model to a property. In the previous snippet, a lambda expression is used to project model.Author. The value of this expression is retrieved as a LINQ Expression (defined in the System.Linq.Expressions namespace) and not as a simple reference to the property value. The Expression class is a special class (it is beyond the scope of this book to explain why), and it provides access to the metadata of properties.

So, the LabelFor method can access the metadata of properties and render the HTML output according to it.

## Display and Edit Templates

There are two template types within MVC: display templates and edit templates. HtmlHelper provides a set of methods available at model and property levels to help the rendering of these templates.

These methods for model properties are available in two flavors. One accepts a string literal that contains the name of the property, and another accepts an expression. You have already seen the DisplayFor method:

```asp
<%= Html.Display("Title") %>
<%= Html.Editor(m => m.Title) %>
```

The DisplayFor method can access the metadata of properties and render the HTML output according to it.

The following code shows the EditorFor method:

```asp
<%= Html.EditorFor(m => m.Title) %>
```
