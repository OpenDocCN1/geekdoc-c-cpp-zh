Multiple inheritance is not supported by the language. A class can have only one base class, but is allowed to implement any number of interfaces. This was a design decision to avoid complication, dependency hell, and simplify architectural requirements throughout the CTS.

# Memory Management

The language has the New operator to allocate type instances from memory. However, it does not have any statement, function, or operator to free the allocated memory. It is automatically garbage-collected. Garbage collection addresses memory leaks by freeing the programmer of the responsibility for releasing memory that is no longer needed. It is a non-deterministic mechanism.

Visual Basic does not directly using pointers. Reference types physically use pointers as their implementation, and you can use them only for referencing the objects them. No pointer arithmetic is allowable.

Visual Basic programs can still store and compare pointers through the System.IntPtr type which provides interoperability between managed and unmanaged code, but objects and values behind IntPtr instances cannot be dereferenced.

# Generic Types

Generic types allow you to define type-safe data structures, without committing to actual data types. Results in higher-quality code, you can reuse data processing algorithms without duplicating type-specific code.

There is a similar concept in C++, called templates, while templates in C++ are supported by a compiler, .NET generic types are implemented at the Common Language Runtime- (CLR) level.
