If you resize the browser, you will notice the greeting text stays in the center, just as you would expect. Looking at the source code of the page displayed in the browser reveals that the Silverlight plug-in is displayed via an HTML <object> tag. If the visitor does not have Silverlight plug-installed, there is some HTML within the <object> tag that points to Microsoft’s Silverlight download site. This HTML section can be customized as you wish — there are even important Search Engine Optimization (SEO) techniques that utilize this area (discussed later in this chapter). The most important parameter of the <object> tag is the "source" parameter that points to "ClientBin/HelloWorld.xaml". This is compiled HelloWorld Silverlight application, automatically put within the ClientBin by the build process.

As you can see, XAML is a great way to describe the object hierarchy of the UI. XAML is also used elsewhere in the .NET Framework, such as describing workflows in Workflow Foundation, or being the base language of XPS. When the WPF team (or, as it called at the time, the Avon team) had the following goals in mind (among others):

+   - XAML is based on XAML — This means it is easily digestible for both computers and humans, and it is easy to validate.

+   - XAML is Tool — When using to design a UI, creating and interpreting XAML code is much easier than HTML because XAML does not allow non-closed tags. It is case-sensitive and generally stricter. With XAML, you don’t see the “Designer Generated — do not modify” warnings in C# or Visual Basic files. You can easily modify the XAML, and the visual designer will immediately reflect your changes.

+   - XAML can be compiled and interpreted — WPF compiles XAML, but it is also possible to load/create XAML on-the-fly, and load it into the application.

+   - XAML is extensible — You can define your own controls, or business classes, and have them within the XAML object hierarchy.

> For more information on the goals of XAML, see http://blogs.windowclient.net/rob_reelya/archive/2009/05/28/our-7-goals-of-xaml.aspx. For more information on the benefits of XAML, see http://blogs.windowclient.net/rob_reelya/archive/2008/11/06/the-8-benefits-of-xaml-for-ui-and-binding.
