# Animations

Animations are often considered eye candy and unnecessary, when designed by professionals and in a discrete manner, animations play a vital part in enhancing the overall user experience of a product. In the real world, transitions don't happen instantaneously, with a few exceptions, such as the case of turning on a lamp). They have speed, acceleration and deceleration. Animations and transitions can also help direct the attention of the user, explain why things happen (for example, when you minimize a window to the taskbar, the short animation shows where the window disappeared), and generally make the virtual experience smoother and by bringing it closer to the real world.

In Silverlight, animations are technically more than a gradual change of properties over time. Silverlight (WPF) animations are time-based instead of frame-based. This means that if an animation is set to 2 seconds, it will take exactly 2 seconds, if the computer is very busy, and can only display a few frames while the animations are running. In addition to the fact that time-based animation is more predictable, it also allows the Silverlight run-time to continuously adapt to the computer's performance by skipping or interpolating animation frames.

# Storyboards and Animations

The best tool for creating complex animations is Blend. However, to understand how animations work, it is enough to start with a simple example in XAML, as shown in Listing 8-16.

# LISTING 8-16: BouncingCircle.xaml

```xml
<UserControl
xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
xmlns:d="http://schemas.microsoft.com/expression/blend/2008"
xmlns:mc="http://schemas.openxmlformats.org/markup-compatibility/2006"
mc:Ignorable="d"
xmlns:i="clr-namespace:System.Interactivity;assembly=System.Interactivity"
xmlns:local="clr-namespace:Microsoft.Expression.Interactivity.Media;assembly=Microsoft.Expression.Interactions"
x:Class="AnimationDemo.BouncingCircle"
d:Height="300" d:Width="400">

<UserControl.Resources>
<Storyboard x:Name="Storyboard1">
<DoubleAnimation TargetProperty="Canvas.Left" />
<Storyboard.TargetName="ellipse" To="320" />
<DoubleAnimation TargetProperty="Canvas.Top" />
<Storyboard.TargetName="ellipse" To="320" />
</Storyboard>
</UserControl.Resources>
<Canvas x:Name="LayoutRoot">
<Ellipse x:Name="ellipse" Fill="Black" Height="50" Width="50" />
<i:Interaction.Triggers>
<i:EventTrigger EventName="MouseLeft">
<DoubleAnimation TargetProperty="Canvas.Left" To="20" />
</i:EventTrigger>
</i:Interaction.Triggers>
</Canvas>
</UserControl>
```

Code file [BouncingCircle.xaml] available for download at Wrox.com

The animation sample shown earlier is created for easy understanding, but is not ideal in terms of performance. The reason for this is that the bouncing cycle animates the Canvas.Left and Canvas.Top properties. This, in turn, triggers a recalculation of the layout for the Canvas and the Ellipse. Even though not noticeable in the sample, layout recalculation is an expensive operation — the affected part of the visual tree must be traversed with the MeasureOverride and ArrangeOverride methods. It is easy to imagine that in the case of a complicated scene, this will take considerable amount of time, making the animation jerky.

Transformations allow moving, rotating, scaling (changing the size), and skewing any UI element. Silverlight 3.3 also introduced a PlaneProjection that can rotate two-dimensional elements in three-dimension.
