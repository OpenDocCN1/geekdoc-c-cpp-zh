Project root nodes and pseudo folder nodes are described in the registry with localized names, sort order information, and folder nesting information.

The template folder hierarchy follows the structure of the folders in the ProjectTemplates (templates installed with Visual Studio 2010), the location is \Common\IDE\ProjectTemplates\ under the Visual Studio installation folder. For user templates, the location is My Documents\Visual Studio 10\Templates\ProjectTemplates\. The folder hierarchies from these locations are merged to create the project types; there is a .vdir file in any of these subfolders, it can describe the sort order of the template folder within its parent.

When the user clicks on a template folder, all templates in that folder are displayed. The IDE scans for the folder with .zip extension and the embedded manifest to recognize project templates. When an appropriate file has been found, the IDE uses the template manifest to display information (icon, name, description, and so on) about the project template.

Looking at the New Project dialog, you can see several project templates appear not only in the folder, but also in other folders. The template manifest may contain a <NumberOfParentCategoriesToCollide> entry that can declare a category level above the physical folder where the template should also be displayed.

# Understanding the Item Template Hierarchy

The New Item dialog uses a hierarchical approach to list available item templates, just like the New Project dialog.

When you add an item to a project, the hosting project's root type determines the physical folder under. For machine templates (templates installed in Visual Studio 2010), the location is \Common\IDE\ItemTemplates under the Visual Studio installation folder. For user templates, the location is My Documents\Visual Studio 10\Templates\ItemTemplates. The folder hierarchies from these locations are merged to create the project item category hierarchy. If there is a .vdir file in any of these subfolders, it can describe the sort order of the template folder within its parent.

Visual Studio scans this folder structure for .zip files with a template manifest stating the template is an item template. It uses the information in the manifest file to display items in a specific folder.

The root project type may filter the item templates. In the registry, there is an AddItemFilters key for the Visual Studio packages that recognizes the project type, and can list template directories or concrete templates that should be excluded from the list. The template manifest has two entries <TemplateID> and <TemplateGroupID> that can be used for further filtering and categorization of item templates based on the project's root type.
