You have built and exerted a simple project template and an item template. Let's dive in a bit deeper and examine how Visual Studio processes and stores templates.

## TEMPLATE STORAGE STRUCTURE

As you just learned, project and item templates are stored as .zip archives. This archive stores files that will be artifacts when the template is transformed into a concrete project or item, and some other files with "accessory" information. When you created the project and item templates earlier, the Export Template wizard added two files to the archives:

- __TemplateIcon.ico — This file is used by Visual Studio as the icon representing the project or item template.
- MyTemplate.vtemplate — This is the most important file in the archive — the template manifest. The IDE recognizes .zip file as a template from this manifest. This file is also used to describe information the IDE leverages to put the project or item into the appropriate category within the New Project and File dialogs, and also defines some behavior-related attributes.

Later in this chapter, you'll see a detailed description of the structure and the usage of the manifest file. First, let's take a look at a template directory storage structure.

## Template Folders

All archives representing project and item templates are stored in a specific location. Here are two kinds of folders:

- System folders — These are installed with Visual Studio setup, and all of the users can access them. The root of the system folders can be found under the Visual Studio installation folder in the Common7\IDE\ProjectTemplates and in the Common7\IDE\ItemTemplates folders, respectively.
- User folders — These are located within the current user's profile, and templates here can be accessed only by the owner using the profile. User folders can be found under the My Documents folder in the Visual Studio 10\Templates\ProjectTemplates and Visual Studio 10\Templates\ItemTemplates folders.

In addition to the system folders, you can find two other folders under Common7\IDE—ProjectTemplatesCache and ItemTemplatesCache. The internal structure of these folders is the same as ProjectTemplates and ItemTemplates, but instead of .zip files, you can find folders with the .zip extension representing the extracted content of the corresponding files. Visual Studio uses these cache folders for performance reasons.

Visual Studio scans the template information in the ProjectTemplates and Item folders when you open the New Project or Add Item dialog. It is difficult to understand how the folder structure and the .zip files are mapped to the structure you see in the dialogs. In addition to the folder structure, Visual Studio uses some other information to build the category hierarchy.

## Understanding the Project Template Hierarchy

To map the folders and templates into the categories that can be seen in the New Project dialog, the IDE counts on other information, including the following:

- Visual Studio looks up the registry to build up the category structure in the dialog. This information can be found under the HKEY_CURRENT_USER hive in the Visual Studio 2010 configuration root (Software\Microsoft\Visual Studio\10.0\Config) in the NewProjectTemplates key.
- A few template folders contain an XML file with .vstdir. These files are used to declare localized names and sort orders for the templates in the folder in the .vstdir file is located.

As shown in Figure 4-18, the New Project dialog displays three types of project template hierarchy nodes:

- Project type root nodes — These are related to languages, or, more precisely, language service packages such as Visual C# or Visual Basic. Figure 4-18 shows examples for Visual C#.
- Pseudo nodes — These are parent folders for a project root nodes. Other Languages and Other Project Types provide good examples in Figure 4-18.
- Template folder nodes — These are the children of project root nodes, and they are mapped to physical folders having template files under them. In Figure 4-18, the Windows, Web, and Silverlight nodes under Visual C# are examples of them.

The whole procedure of creating the template node hierarchy is a bit complex, so this discussion does not include all the details. Instead, here are a few points to help you understand the basics:

- To produce the project template hierarchy, Visual Studio uses the .vtemplate files within the .zip archive, registry keys, and values stored in the NewProjectTemplates key with the help of mentioned earlier, resources in the language packages (determined with the help of registry values), template folder structure, and .vstdir files.

Project root nodes and pseudo folder nodes are described in the registry with localized names, sort order information, and folder nesting information.

The template folder hierarchy follows the structure of the ProjectTemplates (templates installed with Visual Studio 2010), the location is \Common7\IDE\ProjectTemplates\ under the Visual Studio installation folder. For user templates, the location is My Documents\Visual Studio 10\Templates\ProjectTemplates\. The folder hierarchies from these locations are merged to create the project types; there is a .vdir file in any of these subfolders, it can describe the sort order of the template folder within its parent.

When the user clicks on a template folder, all templates in that folder are displayed. The IDE scans the folder with .zip extension and the embedded manifest to recognize project templates. When an appropriate file has been found, the IDE uses the template manifest to display information (icon, name, description, and so on) about the project template.

Looking at the New Project dialog, you can see several project templates appear not only in the folder, but also in other folders.

## Item Template Hierarchy

The New Item dialog uses a hierarchical approach to list available item templates, just like the New Project dialog.

When you add an item to a project, the hosting project's root type determines the physical folder under. For machine templates (templates installed in Visual Studio 2010), the location is \Common7\IDE\ItemTemplates under the Visual Studio installation folder. For user templates, the location is My Documents\Visual Studio 10\Templates\ItemTemplates. The folder hierarchies from these locations are merged to create the project item category hierarchy. If there is a .vdir file in any of these subfolders, it can describe the sort order of the template folder within its parent.

Visual Studio scans this folder structure for .zip files with a template manifest stating the template is an item template. It uses the information in the manifest file to display items in a specific folder.

The root project type may filter the item templates. In the registry, there is an AddItemFilters key for the Visual Studio packages that recognizes the project type, and can list template directories or concrete templates that should be excluded from the list. The template manifest has two entries <TemplateID> and <TemplateGroupID> that can be used for further filtering and categorization of item templates based on the project's root type.
