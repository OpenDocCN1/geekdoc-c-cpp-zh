This is not the only feature for Visual Basic. In other languages, you can edit the template of the code snippet when you try to edit something outside of the placeholders, template editing is terminated.

Visual Basic is different, in at least a couple of ways. While editing a placeholder, you are allowed to put a new line into the placeholder. Second, you can edit the placeholders in the code templates, not just directly into the snippet. If you use the IntelliSense Show Snilighting command to highlight all placeholders in the active code document, you are allowed to insert code snippets into the document, all of their placeholders will be highlighted, as shown in Figure 3-9.

Similarly, with IntelliSense Hide Snilighting commands, you can disable placeholder editing. When you close the file, and open it again, you lose the opportunity to edit template placeholders.

# HTML, SQL, and JavaScript Snippets

Visual Studio 2005 was the first version that implemented the code snippet feature, and it featured with a few dozen snippets out-of-the-box. At that time, Visual C#, Visual Basic, and Visual J# supported.

Visual Studio 2008 was the first version to support .NET 3.0 and .NET 3.5. This version added new snippets to the existing ones, many of them related to Workflow Foundation (WPF) and to Windows Presentation Foundation (WPF). Visual Studio 2008 abandoned Visual J#, so the corresponding snippets were also removed. However, it added great snippet support for extensible markup language (XML) and XML Schema Definition (XSD) files.

Visual Studio 2010 adds code snippet support for the HTML, SQL, and JavaScript languages. There are few dozen snippets supporting ASP.NET out-of-the-box, and Visual Studio does not skimp with JScript snippets. This should definitely be good news for web developers. SQL developers also benefit because Visual Studio 2010 2010 ships with about two dozen SQL snippets.
