Although the sys:if attribute allows you to execute any code, its primary purpose is to allow you to evaluate an expression that should return a true or a false value. If you want to execute some custom code before or after an item is rendered, you can do that in the sys:codebefore and the sys:codeafter attributes.

> The sys:if, sys:codebefor and sys:codeafter attributes provide great flexibility to the template engine. However, be careful, because the result is that the declarative template skeleton gets mixed with imperative code.

# Adding Interaction with Events Inside the Template

All the examples you have rendered the data for the user, and the user could do nothing else except it. In addition to reading the data, probably the most-performed user action is to select a record, and then do something with it. Fortunately, the DataView control supports user events and the Select event next.

Events are raised when the user clicks on an HTML tag rendered by the template. To specify the name of the command, the user uses the sys:command attribute on any HTML tag you want to support events. The Select command is handled specially, because it works without setting any additional properties, and the DataView control provides wrapper methods to retrieve the selected item.

In this example, you can see the previous country refactored, the user is able to select a single country, and then click on the "Get country details" link that displays additional information about the country in a pop-window, as shown in Figure 7-19.

```
<body xmlns:sys=javascript:Sys xmlns:dv=javascript:Sys.UI.DataView>
<ul
  id="countryList"
  class="sys-template"
  sys:attach="dv"
  dv:data="{ countries }}"
  dv:oninitselectedselectedIndexclass="selected">
  <li sys:command="Select" style="cursor: pointer">
    ({ Name })\ (( Capital ))
  </li>
</ul>
<a href="#" onclick="getDetails()">Get country details</a>
</body></html>
```
