This “small” compiler feature in .NET 3.5 was an important step toward supporting dynamic language integration. The compiler creates code to represent an operation, and allows the run-time to determine how to carry out the operation. This feature makes it possible to translate a LINQ expression into a SQL query to execute at the database backend.

## DLR to the Rescue

.NET 4 has a set of services that add dynamic programming capabilities to the CLR and allow interoperation between .NET objects and dynamic languages. The DLR solves the problem of dynamically typed languages like Python and Ruby not easily running directly on top of the CLR (because the CLR is primarily designed for statically typed languages). The DLR has services to help plug this hole and allow dynamically typed languages to run on top of the CLR (by working through the DLR).

Following are the main advantages of the DLR:

- The DLR helps implementers port their dynamic languages to .NET. — With the traditional approach, language implementers needed to edit code (of, in addition to implementing lexers, parsers, semantic analysis, and so on). Virtual machines allowed languages to use a higher-level intermediate language instead of fully optimized code. With the DLR, they do not need to edit code. Instead, they can produce an abstract semantic tree (.NET expression) and some run-helpers if needed. The DLR and CLR do the rest of the working of the operation represented by the semantic tree.

- Languages implemented using the DLR still benefit from improvements in the CLR. — The CLR is designed to support a wide variety of programming languages, and it contains shared services to this purpose such as garbage collection, just-in-time (JIT) compilation, a sandbox security model, and many more. When a new CLR is released (for example, with performance improvements), languages automatically benefit from these enhancements.

- In the DLR, Microsoft provides common language interoperability with fast dynamic invocations. — The interoperability is based on common protocols for objects implemented in one language to be used by other languages. Dynamic typing means that the object can be decided (at run-time) if it supports a particular operation with the specified parameters or not. The DLR enables dynamic objects to participate in this protocol for negotiating to perform abstract operations on any object. The DLR also provides a site caching mechanism that allows dynamic invocations without the performance penalties of the CLR's reflection model.

- Applications can use any language supporting the DLR hosting model. — The DLR provides multiple script run-time environments per AppDomain, as well as remote run-times in other AppDomains. Host applications can execute script files or snippets of code in the context of those bindings — by injecting variables into the context, and extracting variable values after executing the code.

Strongly typed languages (such as Visual Basic and C#) use the CLR directly to execute applications. Dynamically typed languages (such as Python and Ruby) cannot easily run directly on top of the CLR, because the CLR provides this missing layer for dynamically typed languages, and also helps statically typed access objects and services developed in a dynamic way.

Following are the fundamental services of the DLR (of course, there are others):

- **Call sites** — These provide a caching mechanism for operation in dynamic code. Every time you execute an operation with MyOp(A, B), the DLR would have to analyze what MyOp means with A and B as operations. For example, when MyOp is A as a floating-point number, and B is an integer, MyOp(B) results in a floating-point number representing A+B. With caching, this performance penalty can be significantly reduced.
- **Expression trees** — These are the extensions of expression trees introduced in .NET 3.5 with LINQ providers. They are key players in the lowering of the bar for (dynamic) languages to .NET, and are absolutely one of the core pillars of the DLR. Expression trees are compiled (the DLR ships this compiler as part of its services), and the result is a delegate invoking the code represented by the tree. own- **Dynamic object interoperability** — As a core principle of dynamic operations, objects receive messages describing operations with their actual parameters. Dynamic object interoperability is about providing service types to create that can translate these messages to explicit operations.

Depending on the physical type of the object to be accessed dynamically, separate communication models can be used. For example, to access CLR-hosted objects, some mechanism built over .NET reflection can be used. For COM objects, the standard IDispatch-based mechanism can be applicable. For other types of object provider environments, some other run-time binding could work. This kind of job is the responsibility of run-time binders. ## Invoking IronPython Code Example

In this example, you write a very simple IronPython program and access it with C# console application. It will be simple, so you should be able to understand it without any Python background. To use IronPython, you must download and install the run-time from the Downloads tab of IronPython's home page.

Create a C# console application project and name it IronPython. Use the Add Reference dialog to navigate to the Python run-time's installation folder, and add the selected assemblies shown in Figure 10-3.

![](img/b5597c749e848b27b0d305153ae161_446_1.png)

FIGURE 10-3: IronPython run-time assemblies

You will find this folder directly under your operating system's Program Files folder (64-bit systems, under the Program Files (x86) folder) in a folder with IronPython prefix.

Add a new text file and name it Calculate.py where .py is the standard extension for IronPython files. This file should be in the same folder from where the console application is started, set the Build Action property of Calculate.py to Content, and the “Copy to Output Directory” property to Copy Always.

Enter the following short program into the Calculate.py file:

```
def Add(A, B):
    return A + B
```

This small code snippet adds A and B and retrieves the result of this operation. What is less obvious if you are not familiar with Python that A and B can be any objects, and the operation will be successful when the “+ operator” is defined on their types.

Copy the code in Listing 10-1 to the Program.cs file to invoke the Python snippet.

# LISTING 10-1 Program.cs File of IronPythonRunner

```
using System;
using IronPython.Hosting;

namespace IronPythonRunner
{
    class Program
    {
        static void Main(string[] args)
        {
            var ip = Python.CreateRuntime();
            dynamic calculator = ip.UseFile("Calculate.py");
            Console.WriteLine(calculator.Add("Welcome to IronPython on ", DateTime.Now.ToShortDateString()));
            for (int i = 1; i < 4; i++)
            {
                for (int j = 5; j < 8; j++)
                {
                    Console.WriteLine("(" + (i) + " + \ + " + (j) + ") = ");
                    calculator.Add(i, j);
                }
            }
        }
    }
}
```
