
The themes assign a set of personalization styles and attributes to the site elements to be customized, including control properties, pagesheets, images, and so on.

A special directory is used to store all themes for a website or for the web server.

All themes contain at least one skin. Skin files contain property settings for controls such as Label, TextBox, Button, or Calendar. Control skin settings are similar to the control map, but contain only the properties.

Following are the types of skins:

- Default skin — When a theme is applied to a page, all of its controls of the same type will use the default skin defined by the theme. For example, if you create a TextBox default skin, all TextBox controls on your page will use this default skin.

- Named skin — When a control has a SkinID property, it's a named skin. These are not automatically assigned to the controls with the same type. You must explicitly assign the named skin to the controls. This can be done by setting the control's SkinID property. In that way, you're able to set different skins for instances of the same control.

## Web Parts

Web parts are units of a page that contain an integrated set of controls and information as a unit and enable users to build pages using web parts modify properties of the web parts directly from a browser. Web parts can be shared (which means their appearance and behavior is the same for all users) or personalized (which means a user can modify properties in his or her personal view of the page).

The main benefit of the ASP.NET web parts is that the end users are able to personalize and edit the web pages without needing the help of a developer or administrator. Moreover, web parts can be exported from one site and imported to another application, so the quantity of configuration tasks can also be reduced.

One other powerful capability of the web parts is their connectivity. Users can set connections between them, for example, the child part can display the details of the item chosen by the parent web part.

These capabilities make the ASP.NET web parts very powerful, and capable of being the base of various ASP.NET-based server applications (for example, SharePoint).

## Personalization Services

ASP.NET has a lot of personalization features available for all authenticated users, including the following:

- User profiles — ASP.NET user profiles are persistent collections of information fields about the individual user. These allow you to manage user properties without creating and maintaining a custom database.

- Themes — Themes allow you to define the look of pages by way of a property settings collection.

- Custom error pages — ASP.NET provides various ways to display user-friendly messages in case an error occurs. You can trap errors either on the page or at operation level.

With personalization features, your application defines its own collection of personalized data, and the ASP.NET run-time parses and compiles it. Personalized data is completely transparent to end users.

## Full Pre-Compilation

When users request a page for the first time, ASP.NET web pages and code files are compiled dynamically. Then, the compiled results will be cached, so that the next request to the same page is quick and efficient.

The pre-compilation of full sites is also available in ASP.NET.

This provides many benefits for the users, including the following:

- The response is faster.
- The compile-time bugs and errors can be identified early.
- The source code doesn't need to be deployed to the production server.

## Localization

By using localization, you can customize your application for a culture and locale. ASP.NET 2.0 improved the localization process, and had a lot of new features included the following:

- The auto-detection of the HTTP header field (Accept-Language) by the browser configures the set of languages preferred in the response to the request.
- Resources can be accessed programmatically.
- RES or RESOURCE files are compiled and linked into run-time assemblies.
- Controls and their properties can be tied to the resources in a declarative way.
- The creation of resources has design-time support.

The most important benefit using multilingual web applications with language-separated structures is that you need less maintenance during the site's lifecycle.

### Windows Communication Foundation (WCF)

WCF (codename “Indigo”) is a standardized, service-oriented communication infrastructure on top of binary information or XML. WCF is a real framework, with a lot of benefits that include:

- Security
- Transaction management
- Secure message transfer
- Logging
- Performance counters

In WCF, there are two roles: the *service* provides one or more endpoints, and the *clients* connect to this service, send requests to, and get responses from.

All endpoints contain three basics:

- Address — The URL of the endpoint where clients can connect
- Binding — The mode of the communication (for example, HTTP, TCP/IP)
- Contract — The interface that defines the supported operations of the service

### WindowsSpace (WCS)

WCS is a new, secure, and comfortable way of managing identities, instead of the classic username-password method. Following are the main benefits of using WCS:

- It provides a simple way of creating and maintaining digital authentication.
- It can also be a local authentication provider that generate secure personal tokens.

WCS-based solutions are one of the most modern browser-based applications and web services.

#### ASP.NET Ajax

Ajax (Asynchronous JavaScript and XML) is a web development technique used to build interactive web applications. Ajax applications can be more interactive, usable, and faster. They don't require the user to reload the full page after sending or receiving small data pieces from the database server.

Ajax is the combination of the following techniques:

- XHTML (or HTML)
- DOM
- XMLHttpRequest
- XML
