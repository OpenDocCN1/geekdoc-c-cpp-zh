# LISTING 22-3: Module1.vb: Console Application Demonstrating Late Binding

![](bbox=[0.047, 0.115, 0.098, 0.158])

Option Strict Off
Module Module1

```
Sub Main()
Dim xlApp As Object
Dim xlBook As Object
Dim xlSheet As Object
xlApp = CreateObject("Excel.Application")
xlBook = xlApp.Workbooks.Add
xlSheet = xlBook.Worksheets(1)
xlSheet.Activate()
xlSheet.Cells(1, 1) = "I"
xlSheet.Cells(1, 2) = "*I*"
For i = 1 To 10
xlSheet.Cells(i + 1, 1) = i
xlSheet.Cells(i + 1, 2) = i * i
Next
xlSheet.Application.Visible = True
End Sub
```

End Module

This application creates an Excel worksheet with a small table and displays it using Microsoft Excel automation objects.

The xlApp, xlBook and xlSheet variables are declared as type of Object. At build time, the compiler does not know what kind of objects will be present at run-time. For example, it does not know how to execute the following assignment:

```
xlBook = xlApp.Workbooks.Add
```

This is because it does not know how to access the Workbooks operation of xlApp and the Add operation from the xlApp.Workbooks operation. The compiler does not even know which kind of operations (method invocation or property access) they are.

The compiler emits code that uses the types in the Microsoft.VisualBasic.CompilerServices namespace heavily to resolve and execute these operations at run-time. When you run the application, the following actions are carried out:

+   1. The run-time recognizes that xlApp is an Excel automation object (COM object)
2. It asks xlApp to execute the Workbooks operation and retrieves its result.
3. When the Workbooks object is returned, the run-time asks this object to execute its Add operation.
4. When Add is executed, the result is stored in xlBook.
