mixing different active patterns in the same match expression will cause the active patterns to execute, possibly more than once (depending on the order of the match cases and the value being matched).

## Exceptions

Exceptions are a way to signal an error to a calling site, breaking the normal flow of execution and exiting without a return value. .NET exceptions are relatively expensive to create, so you should not use exceptions as a control-flow device. Instead, you might try to return option values, and signal an error with a None value. However, there are situations where exceptions come hard, some even when they are inevitable.

F# provides a shorthand of notations for dealing with exceptions. All F# exceptions are subtypes of the System.Exception class, the general .NET exception base class. Table 25-18 summarizes the practices to raise and catch exceptions.

### TABLE 25-18: Language Constructs for Exceptions

| CONSTRUCT | EXAMPLE | DESCRIPTION |
| --- | :--- | :--- |
| exception id of ty | exception CanNotCompute of string * int | Defines a new F# exception type. |
| raise | raise (new System.ArgumentException("message")) | Raises the given exception, either a type that inherits from System.Exception, or an F# exception. |
| | raise (MyException("message")) | |
| try expr with patt -> expr | try | Evaluates an expression and catches any exceptions as specified. |
| | 1/num | Some |
| | with | -> None | |
| try expr finally expr | | |
| failwith | failwith "Can't do it" | Raises a new instance of System.Exception with the given message. |
| failwithf | failwith "Failed at number %d" i | Same as failwith, but allows to format the error message using a printf-style format string. |

## F# exceptions can be defined using the exception keyword:

```
exception MyException string *
```

This defines a new exception type called MyException, a sub-type of System.Exception, that carries values. It is raised using the raise function defined in the Core.Operators module:

```
raise (MyException("message", 1))
```

Since the return type of raising an exception is a generic type, it will unify with any type, so you can raise an exception anywhere where a value is expected, as indicated by the type of raise:

```
> raise;
val it : (Exception -> 'a) = <fun:clo@11>
```

You can catch exceptions using a try-catch expression. If you want code that is executed regardless of whether any exception occurs you can wrap your try-catch expression in a try-finally expression:

```
try
  try
    MyException("error", 0) | raise
    with
      MyException (msg, i) ->
        printfn "Caught-%s, value=%d" msg i
  finally
    printf "Done"
```

You can use standard .NET exceptions. You simply define these as class types that inherit from System.Exception:

```
type MyNetNetException(msg: string, value: int) =
  inherit System.Exception()

  override self.Message = msg

  member self.Value = value
```

If you use .NET exceptions via classes, raising requires you to instantiate them using the new keyword (although this is optional):

```
new MyDotException("error", 12) | raise
```

Note that MyException (an F exception) you defined earlier does not require instantiation — although underneath it is a .NET exception sub-type, it is not a class type. Instead, it receives special treatment from the F# compiler, and behaves like a function that takes the arguments of the exception and returns a new instance. Similarly, F# exceptions can be used in the catch cases to be matched as if they were discriminated unions.

In contrast, MyDotNetException is not an F# exception, so you must catch it slightly differently by matching on its type:

```
try
    new MyDotNetException("error", 12) |> raise
with
    | : ? MyDotNetException as exc ->
        printf "%Caught message=%s," exc.Message exc.Value
```

Now that you have F# and .NET exceptions that can be raised, and caught, you can look at the rest of the exception primitives from Table 25-18.

You can signal a general failure using `failwith` or its format-enabled alternative, `failwithf`. This will raise an instance of `System.Exception`. Normally you should use different exception subtypes to indicate different causes of failure so that the calling sites can recover appropriately, but when used in the small to yield a "general" failure these functions are indispensable.

A companion to raising exceptions with `failwith/failwith` is catching them via the `Failure` active pattern, defined in `Core.Operators`. This active pattern matches any instance (as opposed to a subtype) of `System.Exception` and binds the message carrier.

Consider implementing a simple division function that reports division by zero and by a prime number. Using the IsPrime function you defined earlier in this chapter, you can implement this as follows:

```
let RequireNonPrime x =
    if IsPrime x then
        failwith "Prime"
    else
        x

let SpecialDiv x y =
    try
        x/RequireNonPrime y |> printf "Result=%d"
    with
        | Failure msg ->
            printf "%s" msg
        | :? System.DivideByZeroException ->
            printf "Error: division by zero"
```

Experiment with this new function in F# Interactive, as shown here:

```
> SpecialDiv 1 0;
Error: division by zero
val it : unit = ()
> SpecialDiv 1 17;
Failure: Prime
val it : unit = ()
> SpecialDiv 10 4;;
Result=2
val it : unit = ()
```

## Units of Measure

One impressive feature of F# is its support for measures and their units. Units of measure enable you to associate various units with your numeric values and functions that operate on those values. The compiler will verify that any operation that involves quantities produces the right unit of measure, saving precious time and preventing any programming mistakes. You will benefit most in your scientific coding by using units, but they can (and should) be used wherever you compute with various units to ensure no bugs creep into your programming logic, and that you safely address unit conversions, and different systems of units.

You can define a unit of measure as a new type by adding the Measure annotation to it:

```
<Measure>
type g

<Measure>
type kg
```

This defines units of measure, grams and kilograms. You can tag these units to a numerical quantity as:

```
let myWeight = 75<kg>
```

The unit and its quantity must match each other without any space for the compiler to correctly identify that this is a unit-tagged quantity. The type of this value will be derived as the type of the quantity (int in this example), enhanced with the specified unit, using int<kg>.

Quantities with units participating in arithmetic produce products that reflect the arithmetic operations performed. The unit language is expressive and frees the scientific conventions as closely as possible. In this language, you can use the following:

- The literal 1 — This represents a unitless quantity, and is equivalent to a quantity without any units.
- Units — Examples would be kg or m. These must be measure-annotated units that are in scope.
- Exponentiation — Examples would be kg^3 or m^-3. Powers must be integers, and can be negative for reciprocal.
- Division — An example would be m/s^2. You can list other units separated by spaces following the division. They will all be assumed to be in the denominator.
- Multiplication — An example would be kg * m. You omit the star and simply use spaces between the units that be multiplied, such as kg and m.
- units. When you use the star with division, the units following the star are assumed to be in the denominator.
- Parentheses — An example would be kg(m). The units you compose will be simplified, eliminating negative powers, and sorting units in the numerator.

When you write functions that require a certain unit, you must explicitly state that in its definition. For example, a typical conversion looks like the following:

```
let GramsToKilos (x: g) = x / 1000
```

Here, the compiler will tell you that you are trying to return an integer, whereas the function is defined to return int<kg>. By adding the unit to the divisor, you can solve this problem.

```
let BadGramsToKilos (x: g) : int<kg> = x / g
```

Values units are not compatible with the same units. This is the fundamental underpinning that ensures the type system can assist you with finding programming errors. Occasionally you may need to access the numerical value in a generic way — for example, if you wanted to print someone's weight. In this case, you can either define a conversion by multiplying your kilogram by the constant 1<kg>, or simply throw away the unit by applying the appropriate generic function, int or float:

```
> let a = 1<kg>;

val a : int<kg> = 1

> a*1<kg>;
val it : int = 1
> float a;
val it : float = 1.0
> int a;
val it : int = 1
```

Units can also be treated in a generic way. For example, you may want to have an aggregate data type that has varying parts sharing the same unit. You can define such types by utilizing the Measure annotation on the generic type variable:

```
type Expr[<Measure>] = 'U =
| Constant of int<'U>
| Binop of (int<'U> -> int<'U>) * Expr<'U> * Expr<'U>
| static Member (e1, e2) = Binop (( - ), e1, e2)
| static Diff (e1, e2) = Binop (( - ), e1, e2)
| static Prod (e1, e2) = Binop (( * ), e1, e2)
| static Div (e1, e2) = Binop (( / ), e1, e2)
```

Here, you have defined an expression similar to the one you saw earlier in this chapter on the discussion on discriminated unions. But this new type is generalized over a particular unit of measure, 'U. Its two basic shapes carry this measure, whether you have an integer constant that has the required unit, or you have a binary operation that carries two operands that themselves have this unit.
