# Variance with Multiple Type Parameters

At first sight, many developers may think that to covariant or contravariant is a property of a generic type. This is not true! Variance is property of type parameters in generic types. When you have a generic type, let's say MyType<T>, you cannot say "MyType" is invariant, covariant or contravariant. What you can say is "MyType is invariant, covariant, or contravariant in T."


# Variance with Type Options

Obviously, we are not constrained to using the generic types with variant parameters. You can create your own generic interfaces and delegates. use the in modifier s a contravariant, and the out for a covariant type parameter. Without a modifier, type parameter remains invariant.

For example, consider the following declarations:

```csharp
public interface IOperations<in T, U, V> { ... }
public delegate X YDelegate<in T, U, out X>(T t, U u);
```

Here, x is covariant, T is contravariant, and U are invariant type parameters.

The compiler ensures that you keep within the rules for variant type parameters. For example, in the following interface, all method declarations are invalid because one more contravariant type parameters are in output positions:

```csharp
public interface IOperations<in T, U, V> {
  T OutputUnsafeOp1(T t);
  U OutputUnsafeOp2(T t);
  List<T> OutputUnsafeOp3();
  Func<V, U> OutputUnsafeOp4();
  void OutputUnsafeOp5(out T t);
  void OutputUnsafeOp6(ref Func<V, U> u, ref T t);
}
```

Similarly, in the following interface definition, all operations are invalid because covariant variant parameters are in input positions:

```csharp
public interface IOperations<out T, U> {
  void InputUnsafeOp1(T t);
  U InputUnsafeOp2(T t);
  Func<U, T> InputUnsafeOp3(out T t);
  void InputUnsafeOp4(U u, ref T t);
}
```
