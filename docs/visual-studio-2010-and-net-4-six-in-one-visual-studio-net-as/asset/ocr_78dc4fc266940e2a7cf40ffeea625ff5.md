Top-level bindings that aim to expose quoted expressions produce metadata for the quotations that will not be automatically compiled into the assembly. If you want to access your quotations from outside the assembly, you should add the ReflectedDefinition attribute to your binding.

Quoting F code has a number of advantages, and it is primary way to provide alternate execution mechanisms to F code. As you will see in the next section, you can use quotations to author and effectively execute database queries. There are a number of Open Source and commercial projects that utilize F# quotations for other applications. For example, one can translate F# quotations to code that can be executed on the GPU. The WebSharper project, provides a framework to translate quotations to efficient JavaScript code to be executed in the browser, and it also manages many of the chores as client-server communication and serialization, freeing you most of the painful details of web application development, enabling you to write new applications with nothing but F# code.

# Working with Database Queries

As you saw in the previous section, quotations provide the mechanism to assist different execution strategies to F code. The F# PowerPack includes a query builder that can construct SQL queries from quotations. Using this query builder, quoted LINQ-like queries that use sequence and other operations against relational data generated by SQLMetal or other R/R tool can be translated to SQL and executed against the database specified in the context handler of the generated mappings. The results are then fetched and as prescribed in the queries, as sequences of objects that contain the extracted data fields.

Using higher-order functions to query, transform, or filter data is a fundamental abstraction, so you may expect, expressing queries in native F# is straightforward. Consider the following code that sorts the list of ca customer names for all orders that come in today:

```
// Get all orders
db.Orders
// Filter those that are from today
// Seq.Filter (fun o -> o.OrderDate = System.DateTime.Today)
// Filter those that are by CA customers
// Seq.Filter (fun o -> o.Customer.State = "CA")
// Map each order to the customer's last name
// Seq.map (fun o -> o.Customer.LastName)
// Sort the results
// Seq.sort
```

This code uses Seq members you saw in Table 25-14 to filter, transform, and sort an initial sequence (all orders) you obtained from the database via SQLMetal-generated objects. You may also use other techniques to query in-memory collections or XML files.

Although querying using Seq members are highly expressive, they may not be the best or most efficient execution mechanism when used directly. In the previous example, for instance, each time you visit a new order, it must be brought in the database (unless you have it "cached" in the database context you are using), and similarly for the associated customer records, an extra database read is necessary.
