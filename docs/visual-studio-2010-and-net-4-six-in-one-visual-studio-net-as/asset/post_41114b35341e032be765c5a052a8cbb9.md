## History of C#

Over the course of the past decade or so, the C# language (and, of course, the .NET Framework) has evolved to become a determining part of modern software development. From its first release in the beginning of 2002, the C# language has gone through an amazing progression, and attracted millions of developers into the .NET camp. As of today, C# is in its fourth version.

This chapter provides a brief overview of the history of the C# language. The discussions in this chapter do not teach you the language, which is definitely not in the scope of this book. ## THE EVOLUTION OF C#

Today, C# is a multi-paradigm programming language. However, it started out as a general-purpose, object-oriented language.

The development team of the C# language was led by Anders Hejberg, who joined Microsoft in 1996 (and who is still the leader of the development team) after exceptionally successful with Turbo Pascal and Delphi at Borland. At that time, Microsoft had already worked on something that later became the Common Language Runtime (CLR). Hejberg's team also put a lot of energy getting rid of the common flaws found in major programming languages. Recognizing those flaws helped considerably establishing the CLR, and also drove the development of the C# programming language.

Today, the name C# (pronounced as "C sharp") is used without any questions about "#" really means in the name, because today's users are used to ending with "sharp" (for example, J# or F#). The name of the programming language was inspired from the musical notation where a "sharp" indicates that the note should be a half step higher in pitch. This kind of inspiration is not unique — just like of C++ programming language, where "++" means "more than C." "#" in the name means "++ in two rows — in other words, "(C++)," suggesting that C# is superior to C++.

## Design Goals

The developers of C# got a lot of inspiration from C++ and Java in regard to both popular language features and flaws. The original design goal was to create a simple and modern general-purpose programming language. The developers also wanted to create a language that was a first-class citizen in developing software components suitable for deployment in distributed environments. Less obvious was the fact that the team aimed C# for suitable applications for both hosted and embedded systems, independently of whether a large and sophisticated operating system used or a very small one with dedicated functions.

Learning from the flaws of major programming languages, the team focused on creating a language that provided support for software engineering principles such as types, array bounds checking, detection of attempts to uninitialized variables, and automatic garbage collection.

## Short History

The history and evolution of C# cannot be uncoupled from the .NET Framework. Their origins have the same root, and their co-evolution is still driven by the forces moving the technology toward future trends.

The predecessor of the .NET Framework was called Common Object Runtime (COR). Traces of it can be found, for example, in the name of the Microsoft Common Object Runtime library (mscorlib.dll). At that time, the class library of COR was written in a managed code called Simple Managed C. The team formed by Anders Hejberg started to develop the new language, and chose the name C, which stood for "C-like Object Oriented." This name was overloaded that Microsoft did not use because of trademark reasons, and renamed it to C#. .NET was announced at PDC 2000, the class libraries were ported to C#. According to design goals, Microsoft decided to start the submission of the C# language as well as the Common Language Infrastructure (CLI) specification to the European Manufacturers Association (ECMA). This submission was also co-sponsored by Hewlett-Packard and Intel Corporation. About 16 months later, the result was ECMA-334 (December 2001), Microsoft also started the standardization at International Organization for Standardization (ISO), with C# becoming an ISO standard in 2003 with ISO/IEC 23270:2003. In 2002, the big leap reached the developer community. Visual Studio .NET (also known as VS2002) was released with C# 1.0 (and Visual Basic). The C# 1.0 compiler was the part of the .NET SDK, and had been fixed by 2003.

The next success of the language was C# 2.0 with its most appreciated feature: generics. In later iterations, Hejberg added this feature from the beginning, but had not enough experience to implement it in .NET. This new version was released with Visual Studio 2005 in October 2005. The related ECMA and ISO standards were also updated to match the C# 2.0 features.

Released with Visual Studio 2008, C# 3 made another huge leap with the introduction of Language Integrated Query (LINQ) and query expressions. LINQ is a .NET Framework component that adds data querying capabilities to .NET. Query expressions represent a new form of data syntax that resembles SQL. With LINQ involved in C#, the language took a new paradigm shift from the imperative approach to declarative and functional programming. Parallel with the query expressions, the language included small (but significant) features that were well used. The most current versions for C# programming language are ISO/IEC 23270:2006 and ECMA-334 edition.

The newest version of the language is 4.0, released with Visual Studio 2010. This signals that it has become a multi-paradigm language. This new version introduces new features as support for dynamic types, which introduces a great way to interoperate with dynamic languages. C# now has optional parameters, that mean other things with the same ease as Visual Basic. What will be C# 5.0? Right now, there is no official information from Microsoft about what the team is working on. But, because a new Visual Studio release is scheduled for every two years, you can be that the team is definitely working on exciting features to be encapsulated into C#.

## Implementations

Because the C# language is standardized, Microsoft Visual C# is not the only implementation, although it is the most used. There are other implementations that generally integrate the C# language compiler, together with the CLI, which is also standardized. Following is a brief list of well-known C# and CLI implementations:

- Mono project — This is considered to be the best non-Microsoft implementation of Open Source C#, as well as a complete implementation of the CLI with the required framework libraries as they appear in the ECMA specification. Mono was led by Xamarin for a long time; as of now, it is led by Novell.
- DotGNU — A part of the GNU Project by Free Source Foundation, this also provides an Open Source C# compiler and CLI with framework libraries as required by the ECMA specification. However, this implementation is not yet complete.
- Shared Source Common Language Infrastructure — This Microsoft project is licensed for education and research (formerly known as Rotor). This is a shared source implementation of a C# compiler and a subset of required framework libraries, according to the ECMA CLI specification.

From its first version, C# has been the programming language that most directly reflects the underlying CLI by design, and that train has not changed over time. The intrinsic types in C# correspond to value types implemented by the CLI framework.

## Type System

C# has a unified type system that is the Common Type System in the .NET Framework. Each type has a root ancestor, namely System.Object. Type system separates data types into two categories:

- Value types — These are plain allocations of data, and that these instances do not have referential identity or comparison semantics at all. Operations on value types are carried out with the actual data within the instances.
- Reference types — These have the notion of referential identity. Each instance of a reference type is inherently distinct from every other instance, even if the data within both instances is the same.

Both type categories can be extended by user-defined types. The value behind a value type instance can be converted into a value of a corresponding reference type by the boxing operation that is implicit in the C# language. The previously boxed value of a reference type can be converted into an instance of a value type with the unboxing operation. This requires an explicit cast. The type system allows full type reflection and discovery.
