## A Different Control Templating Model

WPF only introduced Silverlight's Visual State Manager (VSM) in WPF 4. Because of this, controls are on a different templating model than Silverlight. Here is a snippet from the template of a WPF TextBox:

```xml
<Setter Property="Template">
<Setter>
  <ControlTemplate TargetType={x:Type TextBox} Name="Bd">
  <Microsoft_Windows_Themes:ListBoxChrome x:Name="
    SnapsToDevicePixels="true" Background={TemplateBinding Background}
    BorderBrush={TemplateBinding BorderBrush}
    BorderThickness={TemplateBinding BorderThickness}
    Focused={TemplateBinding IsKeyboardFocusWithin}
    MouseOver={TemplateBinding IsMouseOver}>
  <ScrollView x:Name="PART_ContentHost">
    SnapsToDevicePixels={TemplateBinding SnapsToDevicePixels}/>
  </ScrollView>
  </Microsoft_Windows_Themes:ListBoxChrome>
  <Triggers>
    <Trigger Property="IsEnabled" Value="false">
      <Setter Property="Background" TargetName="Bd"
      Value="DynamicResource (x:Static SystemColors.ControlBrushKey)"/>
      <Setter Property="Foreground"
      Value="DynamicResource (x:Static SystemColors.GrayTextBrushKey)"/>
    </Trigger>
  </Triggers>
  </ControlTemplate>
</Setter>
</Setter>
```

FIGURE-45: Icon Overlay and Thumb Button

There are several interesting things in this template. One that is that the look and feel of WPF controls are coherent with the current Windows window. The other one operates with triggers. For example, the IsEnabled property automatically triggers two setters to change the colors accordingly — in the VSM model, you state a group control by the logic.

Similarly, the mouse hover states can be expressed as property triggers based on the MouseOver property. The WPF 4 controls also implement the VSM states for Silverlight compatibility, but the default controls are based on the trigger model.

## VisualBrush

VisualBrush is much like the Silverlight VideoBrush introduced early, but instead of video, its source can be any WPF control. This allows for cool effects, like the ever-so-popular reflection effect, with minimal performance overhead.

## WPF 3D

WPF sports a fairly sophisticated three-dimensional engine that is integrated with the rest of the visual tree that is sophisticated for a UI framework — don’t try to write your next CAD or game using WPF 3D. WPF 3D supports models, lights, materials, and colors. Two-dimensional elements can also be mapped to three-dimensional models.

In example, it is possible to put a DataGrid on a sphere, and it will interactively. However, dimension in WPF does not support three-dimensional primitives like spheres, cubes, or teapots — only the most basic three-dimensional building block, a triangle, is supported. Therefore, creating even the simplest three-dimensional scene is a lot of work. There is no simple access to the third dimension, like the perspective of Silverlight.

## A Solution Format

Visual Studio and Expression Blend share a common solution format. This means that a project created with Visual Studio 2010 can be opened with Blend, and vice versa. The people working on the project can be sure they are using exactly the same files. It is good practice to use source control in order to check-ins, and avoid editing the same physical file. Even if there is only one person working on a project, both Visual Studio and Blend offer to easily switch to the other tool. For example, right-clicking an XAML file in the Solution of Blend.
