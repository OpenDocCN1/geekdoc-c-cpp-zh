<SolutionFolder> — This element represents a virtual solution folder in a multi-project template to group projects. It has a required Name attribute specifying the solution folder name. The element can nest further <SolutionFolder> and <ProjectTemplateLink> elements recursively to represent the hierarchy of solution folders and projects lists the root .vtemplate file describing this multi-project template.

Listing 4-6: Application.vtemplate

```
<VTemplate Version="2.0.0" Type="ProjectGroup"
xmlns="http://schemas.microsoft.com/developer/vtemplate/2005*"
<TemplateData>
<CreateNewFolder>true</CreateNewFolder>
<Name-multi>Multi-project Application</Name>
<DefaultName>MultiProjApp</DefaultName>
<Description>Demonstrates how a multi-project template looks like</Description>
<Icon>MultiProjApp.ico</Icon>
</TemplateData>
<ProjectCollection>
<Content>
<ProjectTemplateLink ProjectName="Application project">
WinFormsApp\WinFormsApp.vtemplate
</ProjectTemplateLink>
<ProjectTemplateLink ProjectName="Library project">
FormLibrary\FormLibrary.vtemplate
</ProjectTemplateLink>
</Content>
</ProjectCollection>
</VTemplate>
```

As you see from Listing 4-6, the values of the two <ProjectTemplateLink> elements simply refer to the included .vtemplate files for the projects.

You can use solution folders to group projects within the multi-project template. Assuming that you created separate solution folders for WinFormsApp and FormLibrary, you could use the <SolutionFolder> to specify the virtual location of the projects:

```
<TemplateContent>
<ProjectCollection>
<SolutionFolder Name="Application">
<ProjectTemplateLink ProjectName="Application project">
WinFormsApp\WinFormsApp.vtemplate
</ProjectTemplateLink>
</SolutionFolder>
<SolutionFolder Name="Libraries">
<ProjectTemplateLink ProjectName="Library project">
FormLibrary\FormLibrary.vtemplate
</ProjectTemplateLink>
</SolutionFolder>
</ProjectCollection>
</TemplateContent>
```
