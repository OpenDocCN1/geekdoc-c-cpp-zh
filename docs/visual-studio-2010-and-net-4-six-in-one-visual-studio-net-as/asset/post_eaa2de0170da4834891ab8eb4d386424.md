
```csharp
[ProvideMenuResource("Menus.ctmenu", 1)]
[Guid(GuidList.guidSimplePackagePkgString)]
public sealed class SimplePackagePackage : Package
{
    public SimplePackagePackage()
    {
        Trace.WriteLine(string.Format(CultureInfo.CurrentCulture, "Entering constructor for: {0}", this.ToString()));
    }
    protected override void Initialize()
    {
        Trace.WriteLine(string.Format(CultureInfo.CurrentCulture, "Entering Initialize() of: {0}", this.ToString()));
        base.Initialize();
        OleMenuCommandService mcs = GetService(typeof(IMenuCommandService))
            as OleMenuCommandService;
        if (mcs != null)
        {
            CommandID menuItemID = new CommandID(GuidList.guidSimplePackageCmdSet,
                PkgCmdIDList.cmdExecuteSimpleCommand);
            MenuItem menuItem = new MenuItem(MenuItemCallback, menuItemID);
            mcs.AddCommand(menuItem);
        }
    }
}
```

```csharp
private void MenuItemCallback(object sender, EventArgs e)
{
    UIShell uiShell = (ISUIShell)GetService(typeof(SUIShell));
    Guid clsid = Guid.Empty;
    int result;
    Visual.VisualStudio.ErrorHandler.ThrowOnFailure(uiShell.ShowMessageBox(
        "clsid",
        "SimplePackage",
        string.Format(CultureInfo.CurrentCulture, "Inside of: {0}", this.ToString()),
        string.Empty,
        0,
        OLEMSBUTTON_OK,
        OLEMSDEFUTTON.OLEMSDEFUTTON_FIRST,
        OLEMSICON.OLEMSICON_INFO,
        0,
        // false
        result));
}
```

The SimplePackage class becomes a working package by inheriting the behavior defined in the Package class of the Microsoft.VisualStudio namespace and by using the attributes decorating the class definition.

The Package class elements implement the IVsPackage interface required by Visual Studio to take an object account as a package. This interface provides a few methods managing the life cycle of a package and offers methods to access package-related objects such as tool windows, options pages, and authentication objects.

The overridden Initialize method is called after the package has been successfully sited in the Shell through the IVsPackage interface. This method must do all the initialization steps that require access to services provided by the Shell or other packages. You should move this code to the package constructor, you probably would get a NullReferenceException, at point, all attempts to access the Shell would fail because the package is not yet sited, and has no contact with any Shell objects.

In this case, the Initialize method binds the single menu command provided by the package with its event handler method called MenuItemCallback:

```csharp
protected void Initialize()
{
    Trace.WriteLine(string.Format(CultureInfo.CurrentCulture, "Entering Initialize() of: {0}", this.ToString()));
    base.Initialize();

    // Add our command handlers for the menu (commands must exist in the .vsct file)
    OleMenuCommandService mcs = GetService(typeof(IMenuCommandService))
        as OleMenuCommandService;
    if (mcs != null)
    {
        // Create the menu item.
        CommandID menuCommandID = new CommandID(GuidList.guidSimplePackageCmdSet,
            (int)PkgCmdIDList.mdIDExecuteSimpleCommand);
        MenuCommand menuItem = new MenuCommand(MenuItemCallback, menuCommandID);
        mcs.AddCommand(menuItem);
    }
}
```

First, call the Initialize method of the base class — Package, in this case. Look at all of GetService. If you could select a method that is especially important when creating Visual Studio packages, the GetService method would be your choice. This method has one type parameter (call it service) that retrieves a service object implementing the service interface specified by the address type.

You obtain an OleMenuCommandService instance that you create a CommandID instance to address the command you put into the Tools menu, and then you instantiate a MenuCommand object to address the MenuItemCallback method as a response for the command specified with the CommandID. The result of this short initialization code is that the package handles when the user clicks on the Sample Command item in the Tools menu by executing the MenuItemCallback method, which uses the IVUIService to serve up a message box from the IDE.

As mentioned, packages are COM objects that are registered with Visual Studio to support the on-demand loading mechanism and allow merging menus and toolbars into the user interface of the IDE. The information to be registered is created during the build process from attributes assigned to the package class:

Table 6-7 summarizes the role of the attributes used by Visual Studio to integrate the package into the IDE.

## TABLE 6-7: Attributes Decorating the Package Class

| ATTRIBUTE | DESCRIPTION |
| :--- | :--- |
| PackageRegistration | Adding this attribute to the class, the build process will handle it as a package, and looks for other attributes to prepare the package registration according to your intention. In example, this sets the UseManagedResourcesOnly flag to tell that all resources used by the package are described in the managed package, not in a satellite DLL. |
| InstalledProductRegistration | This attribute is responsible for providing information to be displayed in the Help dialog in the IDE. The constructor of this attribute parameters describing the resources holding the information to be displayed. These resources are defined in VSPackage.resx file. |
| ProvideMenuResource | This attribute creates entries about menu and toolbar items provided by the package. Visual Studio uses the embedded resources to merge the package menus into the Visual Studio menus. |
| Guid | Packages COM objects, and they must have a GUID uniquely identifying them. The Guid attribute is used by the .NET framework to assign this GUID value to a type. |

> For more information about the many other registration attributes, look up the VS SDK reference documentation to get more details about them.

## The Command Table

The wizard generated a file SimplePackage.vsct. This is an XML file, and the file extension refers to the acronym coming from the Visual Studio Command Table (VSCT) expression. The schema of the XML files defines the command table owned by the package.

The command table is transformed into a binary format during the build process, and is embedded into the package as a resource. During the registration phase, the ID of this resource is put into the registry. When Visual Studio starts, it loads this binary information and merges it with the menus of the IDE, including toolbars and context menus. To avoid menus every time Visual Studio is launched, the IDE uses a cache mechanism, and carries out the process only for each package.

Listing 6-4 shows the command table of the sample package. All comments placed in the generated file have been removed from this list to save space. You read these comments in the generated .vsct file because it will help you understand the structure of the command table.

```xml
<CommandTable xmlns="http://schemas.microsoft.com/VisualStudio/CA-2005-10-18/CommandTable" xmlns:xs="http://www.w3.org/2001/XMLSchema">
 <Extern href="stidcdmd.h" />
 <Extern href="vsshids.h" />
 <Extern href="msobnid.h" />
 <Commands package="guidSimplePackagePkg">
  <Groups>
    <Group guid="guidSimplePackageCmdSet" id="MyMenuGroup" priority="0x06000">
      <Parent guid="guidSHLMainMenu" id="IDM_VS_MENU_TOOLS" />
    </Group>
  </Groups>
  <Buttons>
    <Button guid="guidSimplePackageCmdSet" id="cmidExecuteSimpleCommand" priority="0x0100" type="Button">
      <Parent guid="guidSimplePackageCmdSet" id="MyMenuGroup" />
      <Icon guid="guidImages" id="bmpPic1" />
      <Strings>
        <CommandName>cmidExecuteSimpleCommand</CommandName>
        <ButtonText>Simple Command</ButtonText>
      </Strings>
    </Button>
  </Buttons>
  <Bitmaps>
    <Bitmap guid="guidImages" href="Resources\Images_32bit.hmp" usedList="bmpPic1, bmpPic2, bmpPicSearch, bmpPicX, bmpPicArrows" />
  </Bitmaps>
 </Commands>
```
