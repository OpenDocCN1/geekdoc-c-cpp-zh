# Layout

Layout means the controls are sized and placed on the screen. The Silverlight layout is very flexible. It is easy to create layouts that automatically adapt to the following:

- Available screen size
- Number of items displayed
- Size of the displayed elements
- Magnification factor

Silverlight's layout strategy is different from what you may be used in Windows Forms or ASP.NET. The key to understanding Silverlight's layout system is to understand the concept of containers.

There are two kinds of containers in Silverlight. ContentControls can have only one. You can access the child of the ContentControl via the Content property. Examples for ContentControl descendants of Button, Checkbox, and ScrollViewer. You used the Content property of the Button earlier in the HelloWorld sample. But what if you want to place more than one element within the Button?

The trick is that you can place a Panel as the Content of a ContentControl. Panels can have more than one child the Children property. The Grid (which is a default panel when you create a new UserControl in Visual Studio) is an example of such a Panel. So, how do you place text next to the video in the HelloWorld application?

```xml
<Button HorizontalAlignment="Center" VerticalAlignment="Center">
<Button.Content>
<StackPanel>
<TextBlock Text="I am a button!" HorizontalAlignment="Center" Margin="5" />
<MediaElement Width="100" Height="75" Source="http://msdnchnline.llnw.net/d1/ch9/0/8/7/7/7/4/SL3Expressionlaunch_ch9.vm" />
</StackPanel>
</Button.Content>
</Button>
```

The Content of Button is now a StackPanel. The StackPanel arranges its children — a centered TextBlock, and the MediaElement that plays the video. By default, the StackPanel arranges its children so that they are below each other. So, the Button described with the previous XAML looks like Figure 8-9.

![](img/b5597c749e848b27b0d305153ae16106_357_0.png)

**FIGURE 8-9:** Button with text and video

If you want to change the layout so that the text is to the left of the video, you must change the StackPanel itself, and add an Orientation attribute, as shown here:

```xml
<Button HorizontalAlignment="Center" VerticalAlignment="Center">
<Button.Content>
<StackPanel Orientation="Horizontal">
<TextBlock Text="I am a button!" HorizontalAlignment="Center" VerticalAlignment="Center" Margin="5" />
<MediaElement Width="100" Height="75" Source="http://msdnchnline.llnw.net/d1/ch9/0/8/7/7/7/4/SL3Expressionlaunch_ch9.vm" />
</StackPanel>
</Button.Content>
</Button>
```

In this snippet, the TextBlock also received a VerticalAlignment attribute. If it is omitted, the TextBlock will have the same height as the MediaElement next to it, and thus the text will be displayed on the top instead of the bottom.

This shows how Silverlight works. It is not the controls that determine how they will be displayed, rather their containing. The StackPanel arranges its children to each other (if the Orientation property is set to Vertical), or the children next to each other (if the Orientation property is Horizontal).

The actual layout is a little bit more complex. The children have say in what size they would prefer to be. As the first step of the layout, from the top of the visual tree, Silverlight asks every element how it would like to be by calling MeasureOverride. Composite controls, like Panels calculate their answers by invoking MeasureOverride of their children.

In the second step, ArrangeOverride is called throughout the entire tree. In this case, parents tell their children the actual amount of space available for them — and it is the responsibility of children to fit in. If the available space is smaller than what the control needs can add a scroll bar, scale their content to a size (such as an image or video), or simply crop. The ultimate limit for how big the root element can be is the size given to the <object> tag — or, in the case of an out-of-browser (OOB) application, the size of the hosting window.

# Layout Containers in Silverlight

Layout containers in Silverlight include the following:

- Border
- Canvas
- StackPanel
- Grid
- Viewbox

# Border

Borders can have only one child (But, as in the previous Button, this can be another container.) As name implies, Border puts a border around its content.

```xml
<Border HorizontalAlignment="Center" VerticalAlignment="Center" BorderBrush="Black" BorderThickness="3" CornerRadius="5">
<TextBox Text="TextBox with a lot of text" Background="LightGray" />
</Border>
```

This creates a Border around the TextBox. As you can see in Figure 8-10, the border has a thickness of 3 pixels, and its corners are also rounded with a radius of 5 pixels. But what is more interesting is that the size of the textbox and the border are both defined by the size of the text within the textbox. This is the result of the layout engine. During the layout phase, Border asks the TextBox to measure itself, and TextBox does so by measuring its own elements — namely the text and decorators around it.

Because Border does not have any specific size (this is why the HorizontalAlignment and VerticalAlignment properties are used), it sizes itself around its content, the TextBox. If you run the previous example, you can see that if you change the text within the TextBox, the Border resizes itself.

You can also control the space between the borders and the TextBox by modifying the Border’s Padding property. The Padding property is defined in few pixels in Silverlight. For example, in a TextBox, Padding controls the space between the text and the bounds of the control.

# Canvas

Canvas is the simplest Panel, and it is the simplest layout that can have more than one child. In a Canvas, you can put pixels on absolute coordinates. The top-left corner is “0,0.” Canvas allows its children to be of any size. If the children do not fit the Canvas, they are still outside the bounds to the Canvas (In WPF, you can clip the content to the bounds using the ClipToBounds property). The size of the Canvas does not depend on its children. This simplicity makes it the fastest layout control, and the best choice when adaptive layout is not needed.

The following code places a Rectangle and an Ellipse in the Canvas. The Ellipse extends outside the Canvas.

```xml
<Grid x:Name="LayoutRoot" Background="White">
<Canvas Width="200" Height="300" Background="Gray">
<Ellipse Width="150" Height="100" />
<Canvas Left="100" Top="100" Fill="Black" />
<Rectangle Width="150" Height="100" />
<Canvas Left="20" Canvas.Top="33" Fill="White" />
</Canvas>
</Grid>
```
