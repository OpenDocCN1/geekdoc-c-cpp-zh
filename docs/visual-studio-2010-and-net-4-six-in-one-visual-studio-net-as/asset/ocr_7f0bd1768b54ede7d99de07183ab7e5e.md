The default WebFormEngine implementation derives from the VirtualPathProviderEngine abstract class that is an ASP.NET-based implementation, but is not Web-specific. This class is using ASP.NET's virtual path provider-based support for view discovery.

There are other view engine implementations you can use with MVC, as shown in Table 18-4.

# TABLE 18-4: Alternative View Engines

| VIEW ENGINE | DESCRIPTION |
| Spark View Engine | The Spark View Engine is a full-blown view engine with its own text template engine behind it. The goal of this engine is to reduce the clutter in your views, and provide a cleaner HTML (See http://dev.dejardin.org). |
| Brail Engine | This engine is a .NET port from MonoRail. The template used for this engine is Boo. The reason behind this is, that using the MonoRail framework, you can write your code in Boo, too, so you don't have to learn a new template language for authoring your views. This project is available within the popular MVCContrib CodePlex at http://mvccontrib.codeplex.com. |
| Tiles View Engine | This engine uses Java Standard Tag Library (JSTL) syntax-based template engine. In this way, it brings the JSTL syntax to ASP.NET MVC applications. (See http://sharptiles.org). |
| NH View Engine | This engine is a .NET port of the Hlam view engine available on Rails. The goal of this markup language is to make it possible to write clean HTML without the inline usage of code blocks. (See http://code.google.com/p/nhlam). |
| Django View Engine | Django (which is the base of the .NET implementation of this engine) is a template language for Python developers. Django is the .NET port and out-of-the-box it has a view engine implementation for ASP.NET MVC. (See http://ndjango.org). |
