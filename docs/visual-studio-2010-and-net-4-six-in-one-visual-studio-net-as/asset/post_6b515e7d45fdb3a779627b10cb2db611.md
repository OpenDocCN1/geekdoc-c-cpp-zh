## The Definition of the Start Page

The StartPage.xml in the SimpleStartPage project defines the essence of the Start Page. You can see that StartPage.xml does not have a code-file, and its Build Action property is to Content. The reason is that Visual Studio will load and parse the XML file on-the-fly at startup, and not its binary representation from the SimpleStartPage assembly.

Of course, that does not mean you cannot assign code to the StartPage.xml, but you must do it so that the page uses user-defined controls implemented in external assemblies. The code you intend to use should be placed into these external assemblies. The template follows this pattern; you can add code to the MyControl WPF user control class located in the SimpleStartPageControl assembly.

Open the StartPage.xml by double-clicking in the Solution Explorer. If you have not compiled the solution yet, the XML editor may warn you that you cannot display the page in the WPF Designer. After building the solution, you can reload the page.

The first thing you can observe is that the style of the page is different from what you see in the live Start Page. This case of phenomenon is that styles in the XAML file references defined by Visual Studio. The Start Page must be loaded in the context of a running Visual Studio instance so those classes can be accessed.

The structure of the XAML definition is simple, as the extract in Listing 5-2 shows.

> LISTING 5: StartPage.xml (Extract)

```xml
<xml xmlns="http://schemas.microsoft.com/winfx/2006/xml/presentation"
     xmlns:x="http://schemas.microsoft.com/winfx/2006/xml"
     xmlns:sp="assembly=Microsoft.VisualStudio.Shell.StartPage"
     xmlns:vs="assembly=Microsoft.VisualStudio.Shell.PlatformUI"
     xmlns:vsfx="assembly=Microsoft.VisualStudio.Shell.10.0"
     xmlns:assembly="assembly=Microsoft.VisualStudio.Shell.10.0"
     xmlns:my="assembly=SimpleStartPageControl"
     mc:ignorable="d"
     xmlns:d="http://schemas.microsoft.com/expression/2006/blend"
     xmlns:mc="http://schemas.openxmlformats.org/markup/2006/xaml"
     d:DesignWidth="600"
     d:DesignHeight="800">
  <Grid.Resources>
    <MergedDictionaries>
      <ResourceDictionary Source="Microsoft.VisualStudio.Shell.StartPage;Styles.xaml" />
    </MergedDictionaries>
  </Grid.Resources>

    Background="DynamicResource {Brushes.StartBackgroundColor}"
    Style="DynamicResource StartPage.Style">
    <!-- Grid omitted -->
  </Grid>
```

*Code file [StartPage.xml] available for download at Wrox.com*

The most eye-catching thing in this list is its root element is a Grid and not a Window, or UserControl. This Grid is a container holding the resources and defining the layout of the Start Page. As you see from the attributes of the Grid, it defines namespaces used by the referenced assemblies in Table 5-4, and also a tag for the SimpleStartControl assembly. The <Grid.Resources> element make them available for the page. The Nested Grid with the LayoutRoot defines the content of the Start Page. Visual Studio nests this UIElement into the Start Page. You can see how the StartBackgroundColor property of the Microsoft.VisualStudio.Shell.10.0 assembly is used to set up the background of the grid.
