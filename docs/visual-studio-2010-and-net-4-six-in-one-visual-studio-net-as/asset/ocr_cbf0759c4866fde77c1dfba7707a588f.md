# Smooth Streaming

Smooth streaming (or adaptive streaming) is one of the most interesting delivery methods for video on the web. As the bandwidth available at people's homes grows bigger and bigger, user demand for high-quality video increases. Silverlight aims to be the best solution for high-quality online video.

There are several problems with online video today that streaming set out to solve. One problem is network bandwidth. While HD quality video can be transmitted on 2-3 megabits per second, and a lot of Internet connections exceed this bandwidth, there are thousands of connections out there that are lower. If the available bandwidth is not enough for the stream played, there are constant interruptions while buffering. Also, the actual bandwidth between the player and the media server can vary greatly—the media server can be overwhelmed, or the end user may have a fraction of his previous bandwidth when others on the same network (household, for example) are also downloading files.

Another important factor that contributes to the end user's playback experience is the computing power of the computer used. Decoding and displaying HD video is a very intensive task—the value of pixels must be calculated at least 30 times per second. Any time the computer is not up for this (for example, the CPU is busy with something else, or the computer was not powerful enough to begin with), the glitch is noticeable.

It is also difficult to seek within a movie. Certain players using progressive download don't allow seeking to the end of the movie, until the entire file has been downloaded. This not only frustrates the user, but wastes the bandwidth of the content provider, as if the user only wants to see the last five minutes.

To solve these problems, content producers encode the video for different bitrates. However to choose the optimal quality, the user must know a lot of technical details, and perhaps switch between the "high bandwidth" and "low bandwidth" versions manually several times during a movie.

Smooth streaming also requires the content to be encoded with multiple bitrates. The big advantage is that streaming continuously monitors the available bandwidth and the CPU load—and, if any of those factors indicate that a slower bandwidth is needed, the streaming player automatically and seamlessly switches to the lower-quality version. The result is that users get the best possible continuous playback, even during rough bandwidth and CPU conditions.

Another advantage is that buffering is virtually eliminated. When a movie starts, or a seek is performed, the player automatically switches to the lowest possible bitrate. This makes seeking pretty instant—finding the right spot in the movie is just like doing it with a DVD player. After the movie has been playing for a few seconds with low quality, the heuristics automatically increase the quality as long as the network and the CPU can handle.

In the case of a live broadcast, smooth streaming can pause and rewind the video, retaining the previously mentioned advantages. Live encoding is, however, much more difficult than encoding for a video-on-demand service.
