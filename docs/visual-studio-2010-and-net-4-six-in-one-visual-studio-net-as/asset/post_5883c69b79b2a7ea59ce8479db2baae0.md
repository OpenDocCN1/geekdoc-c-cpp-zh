## Macro Deployment

Visual Studio provides a few templates for creating setup projects and installation kits for your applications. These kits can be used to copy the binaries and other content files, prepare shortcuts, register components, and so on. However, you cannot directly use them to create an install kit for a macro project.

Fortunately, macro projects are stored in binary .vmacros files that represent the unit of deployment for macros. You can deploy a macro developed and tested on your machine by following these steps:

- 1. Discover where your macro project is stored on your source machine and copy it.
- 2. Check where Visual Studio stores macro projects on the destination machines, and paste them to their appropriate location.
- 3. Start Visual Studio 2010 and open the Macro Explorer.
- 4. Use the Load Macro Project function in the context menu of the Macros root node to add the freshly copied project to the macro system.

After you follow these steps, the macros are ready on the destination machines. Generally, macros are stored in your user profile in the Documents\Visual Studio 2010\Projects folder, but this can be changed. To check where your macros are stored, open the Options dialog. Go to the Projects and Solutions category, and select the General tab. At the top of the dialog page, the "Visual Studio project location" selects the path you are looking for.

## Responding IDE Events

A great benefit of macro development is that macros can respond to Visual Studio IDE events. When you create a macro project, a module named EnvironmentEvents is also created that contains auto-generated code to access system events.

When you open this module, you can use the two combo boxes at the top of the code editor to generate code-handling skeletons. From the left combo box, you can select the event category; from the right combo box, you can select the specific event in category. if you want to respond to an event when a solution is opened, select the SolutionEvents category from the left combo box, and the Opened event in the right one, as shown in 6-15.

## Macro Samples

As discussed previously, recording macros and examining the Samples project can shorten your macro development learning curve. Patterns used here can also support you when developing other kinds of extensibility components, as add-ins and VPackages.

## Accessing IDE Options

Macros use Visual IDE options for specific tasks. The IncreaseTextEditorFontSize and DecreaseEditorFontSize macros in the Accessibility module are good examples to demonstrate option usage.

```
Public Sub IncreaseTextEditorFontSize()
Dim textEditorFontsAndColors As Properties
```

```
textEditorFontsAndColors = DTE.Properties("FontsColors", "TextEditor")
textEditorFontsAndColors.Item("FontSize").Value += fontSizeIncrement
```

```
Public Sub DecreaseTextEditorFontSize()
Dim textEditorFontsAndColors As Properties
```

Dim fontSize As [Property]

```
textEditorFontsAndColors = DTE.Properties("FontsAndColors", "TextEditor")
fontSize = textEditorFontsAndColors.Item("FontSize")
If fontSize.Value >= minimumSupportedEditorSize Then
fontSize.Value -= fontSizeIncrement
End If
End Sub
```

The key to accessing IDE options is the Properties collection of the DTE. This collection can be addressed with two indexes—the first being the name of the category, and the second name of the property page within that category. From the previous snippet, you can see that the FontsAndColors category defines the TextEditor property page.

First, you obtain an object representing that property page. The page holds a collection of objects, so go down to the one with index of FontSize. Obviously, this is the size of the font used by the text editor.

> Note that this produced an object and not a value. You can use the Value property of fontSize to read and change the real value behind that object.

## Writing Output Messages

Macros can be very useful in outputting some project-related information that you cannot directly gain from the Visual Studio IDE. This information can be written to a pane in the output window.

The following sample can be found in the VSDebugger module and demonstrates how to write messages to an output pane:

```
Sub ListBreakReason()
Dim outputPane As EnvDTE.OutputWindowPane

outputPane = Utilities.GetOutputWindow("Debugger")
Select Case DTE.Debugger.dgEventBreakReason
	 Case dbEventReason.dgEventReasonBreakpoint
		outputPane.String("Breakpoint hit" + vbCrLf)
	 Case dbEventReason.dgEventReasonNone
		outputPane.String("No reason" + vbCrLf)
	 Case dbEventReason.dgEventExceptionNotHandled
		outputPane.String("Exception not handled by the debugger" - 
		+ vbCrLf)
	 Case dbEventReason.dgEventExceptionThrown
		outputPane.String("Exception thrown" + vbCrLf)
End Select
End Sub
```

The output window displays a set of panes. The current pane can be selected in the "Show output combo box. When you want to write to a pane, the first task is to provide a reference to the EvDTE.OutputWindowPane object, and then you can call the OutputString method to display your message.

The Utilities class contains a method named GetOutputWindowPane that obtains the window pane for you. You can see from this, you are not tied to using only the built-in out panes. You can also create custom window panes by specifying a unique name:

```
Function GetOutputWindowPane(ByVal Name As String,
ByVal Name As Boolean = True) As OutputWindowPane
Dim window as Window
Dim outputWindow As OutputWindow
Dim outputPane As OutputWindowPane
```

```
window = DTE.Item(Constants.vsWindowKind)
If show.Visible = True
    outputWindow = window.Object
Try
    outputPane = outputWindow.OutputPanes.Item(Name)
Catch E As System.Exception
    outputPane = outputWindow.OutputPanes.Add(Name)
End Try
    outputPane.Activate()
Return
```

The OutputWindow is the one responsible for output panes. The method's logic is straightforward. If it does not find the specified pane, it creates a new pane and activates it. The OutputWindow is the one responsible for output panes.

## Traversing the Hierarchy

With macros, you can traverse the solution hierarchy, including projects and their items in order to produce them. ListProj accesses the active project through the ActiveSolutions collection, and uses ListProj to display items in project.

```
Sub ListProj()
Dim project As Project
Dim projectObjects As Object()
Dim window as Window
Dim target As Object

window = DTE.Item(Constants.vsWindowKind)
projectObjects = DTE.ActiveSolutions
If projectObjects.Length = 0 Then
    Exit Sub
End If
project = DTE.ActiveSolutions(0)
If (DTE.ActiveWindow is window) Then
    target = window.Object
    target = GetOutputPane("List Project")
    target.Clear()
End If
ListProj(project.ProjectItems(), 0, target)
End Sub
```

There is another interesting feature that ListProj also implements. It checks if the macro is started from the Command window, and puts the items into that window; otherwise, it creates a "List Project" pane in the output window.

```
Sub ListProj(ByVal projectItems As EnvDTE.ProjectItems,
ByVal level As Integer,
ByVal outputWinPane As Object)
Dim projectItem As EnvDTE.ProjectItem

For Each projectItem in projectItems
If projectItem.Class Is Project Then
Dim projectItems2 As EnvDTE.ProjectItems
Dim notCollection As Boolean

OutputItem(projectItem, level, outputWinPane)
projectItems2 = projectItem.ProjectItems
notCollection = projectItems2 Is Nothing
If not notCollection Then
ListProj(projectItems2, level + 1, outputWinPane)
End If
End If
Next
End Sub
```

ListProj used recursively to display project items. Each item is a collection of nested project items that is used as a base of recursive approach. The OutputItem method is called for every traversed item in order to display filename information.

```
Sub OutputItem(ByVal projectItem As EnvDTE.ProjectItem, ByVal level As Integer,
ByVal outputWinPane As Object)
Dim i as Integer = 0

While (i < level)
outWinPane.OutputString(" ")
i = i + 1
End While
WinPane.OutputString(projectItem.FileNames(1))
outWinPane.OutputString(Microsoft.VisualBasic.Constants.vbCrLf)
End Sub
```
