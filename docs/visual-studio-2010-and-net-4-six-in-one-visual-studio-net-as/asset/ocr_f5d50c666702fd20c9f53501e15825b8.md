Web Forms is suitable for Rapid Application Development (RAD) scenarios where developers either not have the knowledge of how to output XHTML-compliant HTML by, or are not required to do so. One thing is for. When going with Web Forms, the heavy lifting of input gathering and creation will be done by the developer by the framework, and he or she will not have to think about that. Web Forms will provide a stately UI solution.

> One introductory video (http://www.asp.net/mvc/videos/why-aspnet-mvc-3-minute-overview-video-for-decision-makers) uses the motorbike (MVC) comparison for describing how MVC relates to Web Forms. It says that Web Forms have a lot of abstraction levels over the technology (HTML) to render them, while MVC is "closer to the metal and is a much more hands-on experience."

ASP.NET MVC 2 covers some limitations of Web Forms and provides other ways to deal with complexity, such as separation of concerns, extensibility, and mapping methods to instead of files. MVC 2 brings several new design patterns, development methodologies, and components on board to help developers be more productive.

MVC is used in conjunction with several technologies (best practices), as well as with a few design patterns. In this chapter, you will develop a sample application that utilizes some of them. So, let's take a look at some of them.

# Test Driven Development (TDD)

TDD is not a testing methodology. It has nothing to do with your test team. TDD is an approach; it is about how you write your code.

For TDD, you use a Unit Testing Framework as MbUnit, xUnit, or you can use the great-in framework provided by Microsoft as part of Visual Studio 2010.

Another often-used component of successful TDD is a mocking framework that helps you to mock your classes and layers (such as a controller or a data access layer). Mock objects simulate the functionality and behavior of a given class, which you are in control. TDD is often used to create fake classes to be able to execute unit tests that need persistence functionality without connecting to a real data store (like a relational database or a set of XML files).
