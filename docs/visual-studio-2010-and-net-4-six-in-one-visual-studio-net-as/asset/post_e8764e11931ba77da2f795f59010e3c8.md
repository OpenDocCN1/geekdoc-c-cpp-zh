The process to query a DataTable/DataSet is slightly different from the need to call AsEnumerable() to get the results of a frame that be interacted with by the LINQ system. For the remainder of the LINQ statement, the syntax should be similar to how you use the standard array accessors to get individual fields — first you have the where clause to select type, then a select that returns the entity.

## LINQ to SQL

Previously known as DLIN, LINQ to SQL is an implementation of LINQ that can be used to query data from SQL Server databases. It is just like any other ORM tool that can be used to retrieve data from SQL Server databases.

To work with LINQ to SQL, you must create a DataContext. A DataContext is actually a gateway to LINQ to SQL queries. It accepts the LINQ queries as input, and then processes these to produce corresponding statements.

To create a DataContext in LINQ to SQL, follow these steps:

1. Right-click on the project in the Solution Explorer and Add New Item.
2. From the list of the templates displayed, select "LINQ to SQL Classes," as shown in Figure 12-1.

![](img/b5597c749e848b27b0d305153ae16106_611_0.png)

FIGURE 12-1: Creating a new LINQ data context

3. Provide a name to the DataContext and click OK.
4. Drag and drop the table you need (in this example, it's the Product table of the AdventureWorks database, as is shown in Figure 12-2).

![](img/b5597c749e848b27b0d305153ae16106_612_0.png)

FIGURE 12: The Server Explorer

Once the DataContext has been created, you can use LINQ to query data, as shown in the following snippet:

```csharp
WroxDataContext dataContext = new WroxDataContext();
var result = from p in dataContext.select p;
foreach (var v in result)
    Console.WriteLine(v.Name);
```

Working with LINQ from SQL is very simple because the generated data context is strongly typed, just as if you were working with manually created objects. So, all query functions can be completed as if public properties existed for each column within the database.

One important thing to note is that specific to LINQ to SQL is the query is not executed until you start the enumeration of the results. So, if you have a LINQ statement followed by ten lines of code before you work with the results, the execution of the query will be delayed until the time of the query. Also, given this behavior, each iteration of results will result in a new database query being executed.

In the following example, the entire contents of the Products table is returned twice, for each foreach statement:

```csharp
WroxDataContext dataContext = new WroxDataContext();
var result = from p in dataContext.Products select p;
foreach (var v in result)
    Console.WriteLine(v.Name);
foreach (var v in result)
    Console.WriteLine(v.Name);
```

You can get out this limitation by converting the results to a list or an array. This will execute the query and put the results in memory. The following example executes the query once:

```csharp
WroxDataContext dataContext = new WroxDataContext();
var result = from p in dataContext.Products select p;
var list = result.ToList();
foreach (var v in list)
    Console.WriteLine(v.Name);
foreach (var v in list)
    Console.WriteLine(v.Name);
```

The final thing to note here is that, because of the deferred execution model of LINQ to SQL, it is to perform a complex, conditional query, and ensure that the actual execution contains the proper data.

For example, consider the following:

```csharp
var result = from p in dataContext.products select p;
if(orderByProduct) //Variable declared elsewhere
    result = from r in result order by r;
foreach (var item in result)
    Console.WriteLine(item.Name);
```

## PARALLEL LINQ (PLINQ)

Parallel LINQ (PLINQ) is an extension to LINQ that allows queries to be executed in parallel. This is particularly useful for large datasets where the processing can be distributed across multiple CPU cores.

To use PLINQ, you simply call the AsParallel() method on your LINQ query. For example:

```csharp
var result = from p in dataContext.Products.AsParallel() select p;
```
