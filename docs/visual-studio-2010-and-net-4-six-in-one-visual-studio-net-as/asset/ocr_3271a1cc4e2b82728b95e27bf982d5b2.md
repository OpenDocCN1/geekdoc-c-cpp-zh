member initializers can also omit the type name entirely. In that case, an anonymous type is constructed on the types and names of the members initialized as a part of the expression. Consider the following example:

```
Module AnonymousType
Sub Main()
  Dim order = New With (.ID = 101, .Date = #1/1/2010, 
  .ProductID = "Q3456", .Quantity = 123)
  Console.WriteLine("ProductID: {0}, Quantity: {1}", 
  order.ProductID, order.Quantity)
End Sub
End Module
```

Of course, the compiler creates a real type behind the scenes, but does not expose its name to you. With Option On, you can declare for the anonymous type instance without needing to name the type above, as shown here:

```
Dim order2 = order --- declared as anonymous type
order2.Date = #12/31/2009#
```

By default, the properties generated by the anonymous type are read-write. It is possible to mark an anonymous type as read-only by using the Key modifier:

```
Dim order = New With { Key .ID = 101, .Date = #1/1/2010,
  .ProductID = "Q3456", .Quantity = 123}
```

The Key modifier specifies which field can be used to uniquely identify the value of the anonymous type represents.

# Lambda Expressions

Lambda expressions provide a new concise syntax to describe an anonymous function that can contain an expression, and can be used to create delegates. A lambda expression defines an anonymous method called a lambda method. Lambda methods make it easy to pass “inline” to other methods that take delegate types.

In Visual Basic 2005, you would have used explicit delegates like:

```
Module VB2005Module
Delegate Function BinaryOperation(ByVal op1 As Double,
  ByVal op2 As Double) As Double

Sub Main()
  Dim op1 As Double = 12.3
  Dim op2 As Double = 23.4
  Dim operation As BinaryOperation = AddressOf MyOperation
  Dim result As Double = operation(op1, op2)
End Sub
```
