The metadata interface also provides a way for the composition container to perform implicit filtering. The container checks if the exported parts define a metadata property for those are defined by the view. If they do, the import is satisfied; otherwise, it is not.

If you want filtering by a metadata property, you can do so by decorating it with the DefaultValue(false) attribute. You can see the ILogChannelProperties defines filtering only for the ItemType property. From the three parts implementing the ILoggerTask contract (LogError, GeneralLogChannel, SimpleChannel), the Properties container contains only two. The SimpleChannel part is partially filtered out, because it does not have an ItemType metadata property.

# A Few More Points on MEF

From the concepts and patterns introduced in this section you can see that MEF provides you with sophisticated tools for composing your application from smaller and pluggable parts. Under the covers, MEF provides many features and design principles to enable you to tailor it to your custom need. Following a few of them (without the need for completeness) will give you further direction to dive into MEF:

+   - MEF was designed with extensibility in mind. In all elements of MEF (parts, catalogs, and composition containers) can be tailored to your custom needs. The Export and Import attributes and all related notations are a concrete implementation—called the Attributed Programming Model—of an abstract model. Instead of using attributes, you can create your own programming model—for example, using configuration files—to export and imports

+   - From the examples presented earlier, you can see only very simple ways to query the container for parts. You can look up the documentation of GetExport, GetExportedValue, GetExportedOrDefault, and related methods in the CompositionContainer class for more information about how to author the query.

+   - You can have much more control handling changes (even dynamically) in catalogs. More information and samples can be obtained through the CompositionBatch and Part<> types. You can write your own dynamic catalogs triggering the change of context and recomposing your application—for example, responding to the event when the network becomes unavailable or a connection is restored.

+   - Although the samples in this chapter used only console applications, you can use MEF in all application or component types, including Windows Forms or WPF applications, ASP.NET, or ASP.NET MVC sites.

+   - MEF is also available for Silverlight 3 and Silverlight 4 applications.

> The MEF run-time is part of .NET Framework 4.0. The MEF samples and tools are not. They can be found on CodePlex, primarily in the MEF (http://MEF.codeplex.com) and MEFContrib (http://MEFContrib.codeplex.com).
