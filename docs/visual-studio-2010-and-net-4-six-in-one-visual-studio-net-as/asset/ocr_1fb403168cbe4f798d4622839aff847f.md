internal sealed class DNRequestTrackingBehavior: IServiceBehavior
{
    public void ApplyDispatchBehavior(ServiceDescription serviceDescription
        ServiceBase serviceBase)
    {
        var workflowService = serviceBase as WorkflowServiceHost;
        if (workflowService == null) return;
        var tracker = new DNRequestTrackingParticipant();
        workflowService.WorkflowExtensions.Add(tracker);
    }

    public void AddBindingParameters(ServiceDescription serviceDescription,
        ServiceBase serviceBase,
        Collection<Endpoint> endpoints,
        BindingParameterCollection bindingParameters)
    {
    }

    public void Validate(ServiceDescription serviceDescription
        ServiceBase serviceBase)
    {
    }
}

```

*DNRequestTrackingParticipant.cs available for download at Wrox.com.*

The class implements the IServiceBehavior interface of the System.ServiceModel.Description namespace. This interface can be found in the System.ServiceModel.dll assembly, so it is the part of WCF. This behavior uses only the ApplyDispatchBehavior method which explicitly adds DNRequestTrackingParticipant to the WorkflowExtensions collection of the service host. This will inject this entity into any new workflow instance.

# ## Running the Application

The application is ready to run. When you start it, you can add requests. The approval process takes about 10 seconds, it takes about 10 seconds a new request goes to either Approved or denied. Figure 11-28 shows the application in action.

You can try to send more than one request. When you query the DNRequestTracking table, you can observe that each approval workflow takes a separate workflow instance, and workflow processing overlapping requests overlap.
