Although C# is said to be the .NET programming language that is closest to the CLR, there are some limitations when using:

+   The D allows objects to be created from objects that represent classes. However, the current implementation of C# doesn't have syntax to support this.

+   Lambda expressions are type-ferred by their nature, so the compiler uses the context to infer what they mean. If lambdas appeared as arguments to a dynamic method call, the compiler cannot decide what type the lambda expression is to be converted to. So, lambdas are not allowed to appear as dynamic method arguments.

+   Dynamic lookup will not be able to find methods. The dynamic lookup happens at run-time, while extension methods are compile-time artifacts. Whether extension methods apply or not (which extension method, if there is more than one) depends on the static context of the call (that is, which using clauses occurs in the source file). This context information is not kept in the compiled binaries, and extension methods will not be found by the DLR.

# NAMED AND OPTIONAL PARAMETERS

Earlier, Listing 24-1 displayed some "code header" in terms of using noisy and hard-to-read method invocations, like this:

```
chart.ChartWizard(
range.CurrentRegion, // --- Source
Type.Missing, // --- Gallery
Type.Missing, // --- Format
Type.Missing, // --- PlotBy
Type.Missing, // --- CategoryLabels
Type.Missing, // --- SeriesLabels
Type.Missing, // + +"Memory Usage in *" + Environment.MachineName, // --- Title
Type.Missing, // --- CategoryTitle
Type.Missing, // --- ValueTitle
Type.Missing); // --- ObjectTitle
```

End-of-comments help you in guessing the role of arguments passed to the ChartWizard call, but without them, you could hardly decrypt what the Type.Missing arguments stand for.

Some APIs (most notably COM interfaces as the Microsoft Office and Visual Studio automation APIs) are written specifically with named and optional parameters in mind. Until now, it has been very painful to call into these APIs in C#, with sometimes as many as 30 arguments having to be explicitly passed, most of which have reasonable default values and could be omitted. With optional parameters introduced in C# 4.0, the preceding code looks exactly as it should from the:

```
chart.ChartWizard(
Source: range.CurrentRegion, // + Environment.MachineName);
Title: "Memory Usage in *" + Environment.MachineName);
```
