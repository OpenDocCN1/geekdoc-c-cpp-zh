The same issue also holds for ordinary object values, which are "sealed" against ordinary pattern matching, and once again when you resort to various members that publish and use these to drive pattern matching.

What's needed is a mechanism to translate values of a given type to a set of "shapes" that you can then pattern match. Luckily, F# provides this mechanism via its so-called active pattern feature. Active patterns (also called active pattern recognizers) allow you to define for any value a set of named partitions called the active pattern results that you can match against as they were simple cases in a discriminated union.

Active patterns can carry values as ordinary discriminated union constructors, allowing you to tag values of arbitrary complexity to each pattern result. Furthermore, your active pattern definitions can be total or partial.

There are three fundamental types of active patterns that you should be aware of, and each has its distinctive advantages and usage patterns. They are summarized in Table 25-17.

# TABLE 25-17: Active Pattern Uses

| GOAL | TYPE | DESCRIPTION |
|---|---|---|
| Conversion | Single-case, complete | Converts the given value to a new value. |
| Segmentation | Multi-case, complete | Groups all values of a given type into a set of shapes/groups. |
| Characterization | Single-case, partial | Provides a characteristic trait to some values in a given type. |

Active patterns have a distinct place in the language, and they are treated differently than ordinary pattern matches.

When you define active patterns, you must separate each pattern recognizer with a pipe (|) character, and insure the entire set that belongs to a active pattern by pipes.
