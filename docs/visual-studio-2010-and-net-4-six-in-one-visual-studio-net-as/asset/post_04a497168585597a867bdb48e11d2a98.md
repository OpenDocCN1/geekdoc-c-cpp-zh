## Working with DOM Elements

Earlier in this, you can see examples of how to use the get function to get a reference to a DOM element by its ID. While the get function is very useful, modern Web 2.0 applications need more flexibility over how DOM elements are selected. The Microsoft Ajax Library 4 introduces a new function (Sys.get) that allows selecting elements not only by their IDs, but by their names or CSS classes. Sys.get is also capable of returning references to Ajax Library components.

The Sys.get function expects two parameters:

- selector — This is to define what you are looking for.
- context — this is essentially the scope of the search.

If you omit the second parameter, the function searches the entire DOM.

- #id - If you use the # prefix, the method will behave like the $get function. Internally, the $get function delegates the call to the Sys.get function, and adds the # prefix to the ID.
- .class - If you use the . prefix, the Sys.get function will return an element with the specified name (for example,

## The Script Loader

Earlier in this chapter, you saw how Microsoft split the files loaded by ScriptManager to optimize the page load time. The same split script files can also be used in client-side code if you are using ASP.NET. Because the Microsoft Ajax Library consists of JavaScript files, the natural way of incorporating them into a page is by using the declarative script tag:

```html
<script type="text/javascript" src="MicrosoftAjax.js"></script>
```

However, Ajax enables you to download external files with imperative code, and the Script Loader of the Microsoft Ajax Library wraps this functionality and extends it with additional features. The Script Loader is implemented in the very small (11 KB) Start.js file. The Start.js file is designed to be a bootstrap for the whole Library, and it is the only file you need to reference in a script tag. Because the Microsoft Ajax Library is available via the Microsoft Ajax CDN, you can also load it from here:

```html
<script src="http://ajax.microsoft.com/ajax/beta/0911/Start.js" type="text/javascript"></script>
```

After the Start.js file is downloaded and parsed on the client, you can use the Sys.require method to define which standard script files your code depends. For example, if you need history and jQuery support, you can load them like this:

```html
<script src="Start.js" type="text/javascript"></script>
<script type="text/javascript">
Sys.require({
  Sys.scripts.History, Sys.jQuery],
  function() {
    // History and jQuery available here
  }
});
</script>
```

The Sys.require method accepts three parameters, but in most cases, you will probably call it with only two. In the first parameter, you can define the features that should be loaded. Table 19-1 shows the available split script file features (which acts like an enum) value to reference them.
