Let's dive into its details of this code. To understand every bit, you must understand a lot of information about the command-handling mechanism of Visual Studio. Treating all those details would at least double the length of this chapter, let's focus on a general overview of what the code does. If you want to look deeper behind the source code, use the reference documentation for the methods, parameters, and types.

The Connect class implements the IDExtensibility2 and IDCommandTarget interfaces. Both are COM interfaces, so as a result, the Connect class is an OBJ that can be integrated with Visual Studio 2010. IDExtensibility2 is responsible for the IDE integration. IDCommandTarget enables the IDE to send commands to the add-in. IDExtensibility2 defines the methods summarized in Table 6-3. All methods have an array parameter custom that can be used to pass data back to the caller.

# TABLE 6-3: IDTExtensibility2 Members

| METHOD | DESCRIPTION |
| --- | --- |
| OnConnection | This event is raised when the add-in is loaded into the Visual Studio IDE. The application parameter points to the root object of the DTE automation model. addInst refers to the AddIn instance in the automation model describing this add-in. connectMode parameter defines the way in which the add-in is loaded into the IDE. Define this code to set up your add-in during connection time. |
| OnDisconnection | The Visual Studio raises this event when the add-in is disconnected from the IDE. The disconnectMode parameter specifies why the add-in has been disconnected. Use this method to put the add-in clean up code. |
| OnAddsUpdate | This event is raised by the IDE when the add-in is loaded or unloaded. You must define this method when you want to check dependencies among add-ins. For example, to ensure that all add-ins are loaded. |
| OnStartupComplete | This event is raised when Visual Studio finished the startup process. At this point, all add-ins are loaded into memory, so you can access them to finish your initialization. You should put all the initialization code here that assumes any other Visual Studio services are available. |
| OnBeginShutdown | The IDE sends this event to the add-in when the shutdown process. |

You can see in Listing 6-1 that the OnConnection method defines how to initialize the add-in. All other methods have. OnConnection first stores the references to the automation root in _applicationObject and the current instance in _addinInstance because they are used later. When the IDE loads the add-in to set up its interface (using ext_cm_UISetup), it triggers few tasks by this method:

- In a few steps, it obtains the reference to the Tools bar and stores it into toolsPopup.
- It creates a new command with AddNamedCommand2 passing the add-in instance and other parameters. It sets up the UI for this command (names, icon, and visual properties). As a result of the method, when the menu item is clicked, the IDE routes this command to the add-in.
- It adds the item to the menu bar.

IDCommandTarget interface defines two methods:

- QueryStatus method is called by the Visual Studio IDE to check whether the add-in can understand the command (this is what the command means and execute). The add-in also has a chance to retrieve the status it supports (for example, enabled/disabled, visible/hidden). Also this method is used by the IDE to set its menu item and status bar.
- Exec method is called by the IDE when a command is about whether QueryStatus previously added the add-in supports that command. It responds only when the IDE is asking for status (not for command text). It checks if the command known by the add-in is called, and in this case, returns a status saying “I’m supporting the command, so you can execute it when the user clicks on the menu item, and also it is enabled on the UI. Exec checks again if the supported command is called. It shows the message box and signals that the command has been handled. The handle flag is important. Visual Studio can see the command to one or more add-ins (all support command). If one command does not set the handle flag (it leaves false!), the next add-in also has a chance to handle it.

# Managing and Loading Add-Ins

The Add-In Wizard generated two configuration files with the .addin extension and puts them the project. One of them, MySimple.addin is put into the same directory as the Connect.cs file.
