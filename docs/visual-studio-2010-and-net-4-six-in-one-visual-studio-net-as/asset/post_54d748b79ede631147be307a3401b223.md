
```cs
[DataContract]
public class CompositeType
{
    bool boolValue = true;
    string stringValue = "Hello ";

    [DataMember]
    public bool BoolValue
    {
        get { return boolValue; }
        set { boolValue = value; }
    }

    [DataMember]
    public string StringValue
    {
        get { return stringValue; }
        set { stringValue = value; }
    }
}
```

## Creating the Service Interface

Any WCF Service classes implement at least one service contract. In this example, the service contract that the Service class would implement is IEmployeeDataService.

Right-click on the project in the Solution Explorer and create a new file EmployeeDataService.cs. Place the following code here:

```cs
[ServiceContract]
public interface IEmployeeDataService
{
    [OperationContract]
    List<string> GetData();
    [OperationContract]
    List<string> GetEmployeeList();
}
```

This is the service that will be extended by a Service class you will create later. Note that there are two method declarations in this interface—the GetData() method and the GetEmployeeList() method. The former is not marked with the OperationContract attribute, the latter is. This implies that, of the two methods, only the GetEmployeeList() method will be exposed for client-callable operations. Because this means any method that isn't marked with the OperationContract attribute is not included in the service contract.

Given the use of interfaces to define a service, since the GetData method is not needed for service implementation, it would most often be a best practice to omit the method from the interface definition to prevent any service implementers from creating methods that are not needed.

## Defining Data Contracts

Similar to service contracts, you can also define data contracts. If the operations defined as part of the service contract return simple types (that is, primitive types), you do not need to declare a contract. However, data contracts are required if the service contract defines instances of complex types. As an example, the GetEmployeeList() method to return an instance of a class, you must define a data contract. Data contracts are used to define how in-memory types are converted to serialized format using the [DataContract] attribute, which can be applied to a struct or class. Individual members of data contract are then defined using the DataMember attribute. Here is an example:

```cs
using System.Runtime.Serialization;
[DataContract]
class EmployeeData
{
    [DataMember] public int employeeID { get; set; }
    [DataMember] public String firstName { get; set; }
    [DataMember] public String lastName { get; set; }
}
```

In this example, the EmployeeData class is defined as a data contract, and each of the members within the class is offered as DataMember.

## Specifying Binding Information

Now that you have created the service data contract, and the service implementation, you must specify the binding information for the service to make it accessible by services or clients. For a WCF service to be accessed by clients, the service must expose at least one endpoint. An endpoint denotes the address, binding, and contract information for the service. To specify the binding information for the service, open the App.Config file and insert the following code inside the <system.serviceModel> tags:

```xml
<system.serviceModel>
  <bindings>
    <basicHttpBinding name="BasicHttpBinding_EmployeeService"
      closeTimeout="00:01:00" receiveTimeout="00:10:00" sendTimeout="00:01:00"
      allowCookies="false" bypassProxyOnLocalAddress="false"
      hostNameMode="Wildcard"
      maxBufferSize="65536" maxBufferPoolSize="52428"
      maxReceivedMessageSize="65536"
      messageEncoding="Text" encoding="utf-8" transferMode="Buffered"
      useHttps="true">
      <readerQuota maxDepth="32" maxContentLength="8192" maxArrayLength="16384" />
      maxBytesPerReader="4096" maxNameTableCount="16384" />
      <security mode="None">
        <transport clientCredentialType="None" />
        <message clientCredentialType="Username" algorithmSuite="Default" />
      </security>
    </basicHttpBinding>
  </bindings>
  <client>
    <endpoint address="http://myservice/DataService.svc" binding="basicHttpBinding"
      bindingConfiguration="BasicHttpBinding_EmployeeService" contract="IEmployeeDataService"
      name="BasicHttpBinding_EmployeeService" />
  </client>
</system.serviceModel>
```

This creates a basicHttpBinding for the example service specifying additional properties on the binding (such as the openTimeout, receiveTimeout, send timeout, bufferSize, and maximum message size). Additional configuration on the binding specifies that no security is used for transport. The endpoint is defined with an address that specifies it will be hosted by IIS, the endpoint should use the configuration defined earlier in the configuration, and that the contract for the service is IEmployeeDataService.

This declarative method for defining endpoints is not the only way to configure your service. It is also possible to configure a service programmatically using the .NET API methods to create the service host, endpoint, and a simpler implementation using this method is as follows:

```cs
public static void main()
{
    ServiceHost serviceHost = new ServiceHost(
        typeof(MyDataService.EmployeeDataService));
    serviceHost.AddEndpoint(
        typeof(MyDataService.EmployeeDataService),
        new BasicHttpBinding(),
        "http://myserver/MyDataService/Service.svc");
    serviceHost.Open();
    Console.WriteLine("Press the ENTER key to stop the service");
    Console.ReadLine();
    serviceHost.Close();
}
```

## Hosting the WCF Service

A WCF service can be hosted using IIS, or by using Windows Activation Service (WAS). To host your WCF service in IIS, you must create a virtual directory, and point it to the directory where your service is located. WCF services hosted in IIS can be accessed using SOAP over HTTP.

Here's where you can find the App.Config file in the hosting application to access your WCF service hosted in IIS:

```xml
<?xml version="1.0" encoding="utf-8" ?>
<configuration>
  <system.serviceModel>
    <behaviors>
      <serviceBehaviors>
        <behavior>
          <serviceMetadata httpGetEnabled="true"/>
        </behavior>
      </serviceBehaviors>
    </behaviors>
    <protocolMapping>
      <add bindings="wsHttpBinding" scheme="http"/>
    </protocolMapping>
  </system.serviceModel>
</configuration>
```

This configuration information notes that it is possible for the service to publish metadata information using the Get method of the HTTP protocol. The second section maps the HTTP protocol to the wsHttpBinding. Note that your endpoint configurations must be completed and have been omitted from this example for brevity.
