
```vb
Public Class LinkedNode(Of 
K As Structure,
N As (IComparable(Of N), New))
...
End Class
```

There is a special type constrained New that requires the type to be able to be used in New expressions. There are also two special type constraints that limit the kind of type that can be used to satisfy the constraint:

- Class constraints the type parameter to references only.
- Structure constraints the type parameter to value types only, with the exception of nullable types.

You can use generic base types using either open or closed types, as shown in the following examples:

```vb
Public Class SortedNode(Of 
K As Structure,
N As (IComparable(Of N), New))
Inherits LinkedNode(Of K, N)
End Class
```

```vb
Public Class CodeNode(Of N As (IComparable(Of N), New))
Inherits LinkedNode(Of Integer, N)
...
End Class
```

```vb
Public Class TransferNode
Inherits LinkedNode(Of Integer, Transfer)
...
End Class
```

Not only types, you can also use methods with generics, as shown here:

```vb
Public Class MyUtilities
    Public Sub WriteToDebug(Of T) (ByVal item As T)
    ...
    End Sub
    Public Sub Serialize(Of T As ISerializable) (ByVal item As T)
    ...
    End Sub
End Class
```

Even Shared, MustOverride and Overridable methods can leverage generics, as shown here:

```vb
Public MustInherit Class BaseClass
    Public Shared WriteToDebug(Of T) (ByVal item As T)
    ...
    End Sub
    Public MustOverride Sub AbstractMethod(Of T) (ByVal item As T)
```

```vb

  '
End Sub
End Class
```

```vb

      '
    End Sub

      '

```

Operators and delegates are implemented as methods behind the scenes, and both of them support generics with all the power of generic methods. Here is a small example of defining and consuming delegates:

```vb

    Public Sub SomeMethod(ByVal arg As T)
      '
    End Sub

del(3)
```

In .NET 2.0, reflection was extended to support generic type parameters. The system.Type could now represent generic types with specific type arguments (closed), or unspecified (open) types.

Also, many types in .NET 2.0 — especially collections — had been changed or added to support generics. For example, Array now has a dozen new generic methods, and there were many generic collection classes to provide a new and performance-boosted experience related to the old .NET 1.1 collection types.

## Partial Types

The limitation that type definitions had be entirely in one physical file was a bottleneck in preceding Visual Basic versions, making the life of developers unnecessarily difficult. Large type definitions could not be split, and that was especially disadvantageous for those who used code generation intensively, because generated code could not be easily separated from user-defined code.

Partial types solve this issue. By using the Partial keyword, class, structure, and interface definitions can be split into multiple files or multiple segments in the same file. This solves the problem of separation of user-defined and generated code. During compile time, the partitions of the type definition are merged, including attributes, base classes, interfaces, and access modifiers.

For example, you can split SampleClass into two parts, as shown in the following example:

```vb
--- SampleClass1.cs
<Serializable>()
Partial Public Class SampleClass
    Private _IsDisposed As Boolean
End Class
```

```vb
--- SampleClass2.cs
Partial Class SampleClass
    Implements IEquatable(Of SampleClass) As Boolean
    Implements System.IEquatable(Of SampleClass).Equals

    Public Function EqualsWithSample(ByVal other As SampleClass) As Boolean
        ...
    End Function
```

The merging of these results in a class named SampleClass implementing the IEquatable(Of SampleClass) interface, and decorated with the Serializable attribute.

## Nullable Types

In CLR 1.0, one of the weaknesses of value types was the lack of value type's "nullability." To eliminate this, the CLR 2.0 designers added the concept of nullable types to the runtime. A new generic, the System.Nullable(Of T) structure, was introduced, where T should be a value.

The Visual Basic 2005 syntax allowed assigning Nothing to a System.Nullable(Of T) instance, and to compare an instance value with Nothing. The HasValue property tells if a nullable instance has a value, and if it has, it can be obtained through the Value property.

Using these properties, you could define the Nothing-aware Square method, as shown in the following example:

```vb
Public Function Square(ByVal n As Nullable(Of Integer)) As Nullable(Of Integer)
    Return IIf(n.HasValue, n.Value * n.Value, Nothing)
End Function
```

The Nullable(T) also defines a Narrowing cast operator from Nullable(Of T) to T, and a Widening cast operator from T to Nullable(Of T), so the following declarations are correct when using Option Strict:

```vb
Dim firstValue As Nullable(Of Integer) = 4
Dim secondValue As Nullable(Of Integer) = 5
Dim sumValue As Nullable(Of Integer) = firstValue + SecondValue
Dim squareValue As Integer = CType(Square(sumValue), Integer)
```

However, because the implicit conversion from Nullable(Of T) to T is not allowed, the last two of the following assignments will result in compilation errors with Option Strict On:

```vb
Dim firstValue As Nullable(Of Integer) = 4
Dim secondValue As Nullable(Of Integer) = 5
' Cannot convert Nullable(Of Integer) to Integer:
Dim myValue As Integer = secondValue
Dim sumAs Integer = firstValue + SecondValue
```

## Documentation Comments

The C# language has been inspired by Javadoc and since the first release of C# in 2000, Visual Basic 2005 introduced the similar concept with a slightly different syntax from that C# and Visual Basic have separate tokens for comments.

Document comments in Visual Basic are special comments that begin with ''' (three quotation marks). They must immediately precede the type or member that they document. All adjacent comments are appended together to produce a single document comment. Here is an example of documentation comments:

```vb
<summary>
'''This abstract class defines an attribute with a simple string value.
</summary>
'''remarks
'''The class is intended to derive new attributes having a simple string value.
'''Do not use this class to add other properties to the attribute!
'''
Public MustInherit Class StringAttribute
Inherits Attribute
<summary>
'''Creates a new instance of this attribute and sets its initial value.
</summary>
'''param name="val">Initial attribute value.</param> */
Protected Sub New(ByVal val As String)
Value = val
End Sub
'''Other parts of the declaration omitted
End Class
```

During compilation, document comments are transformed into an XML file that can be utilized to generate human-readable source documentation. The documentation generator accepts and processes any tag that is valid according to the rules of XML.

## Operator Declarations

Operator declarations are methods that define the meaning of an existing Visual Basic operator for the class. When the operator is applied to the instance, it is compiled into a call to the operator method. You can declare unary, binary and conversion operators. Defining an operator for a class is also known as operator overloading.

Operator declarations must always be Public and Shared, and the type of at least one of the operands (or the return value) must be the type that contains the operator. There is no function return defined for operators. The Return statement must be used to return values from an operator body. Only the unary and binary operators can be overloaded:

- Unary (+, -, logical Not, IsTrue, and IsFalse)
- Binary (+, -, *, Mod, and =)
- Relational operators (<, <>, <=, ==, and >=)
- Like, & (concatenation), logical And, Or, X

Relational operators must be declared in pairs - = <, > with <, and >= with <=.

The following code demonstrates operator declarations:

```vb
Public Structure Vector2D
Public X, Y As Double

Public Sub New(ByVal xc As Double, ByVal yc As Double)
X = xc
Y = yc
End Sub

Public Shared Widening Operator CType(ByVal v2D As Vector2D) As Vector3D
v3D.X = v2D.X
v3D.Y = v2D.Y
v3D.Z = 0
Return v3D
End Operator
```

```vb
Public Shared Operator +(ByVal v1 As Vector2D, ByVal v2 As Vector2D) As Vector2D
Dim result As Vector2D
result.X = v1.X + v2.X
result.Y = v1.Y + v2.Y
Return result
End Operator
```
