# Converting Literals and Values

You may know of the numeric types and sample literals in Table 25-2. These types have a corresponding set of conversion functions defined in Microsoft.FSharp.Operators, each having the same name as the type, to convert between various numeric formats. This conversion may result in a loss of precision or overflow. Consider the case where there is no loss of precision — converting a 32-bit float to a 64-bit one.

```
> System.MaxValue;
val it : float32 = 3.40282347e+38f
> float System.MaxValue;
val it : float = 3.402823466e+38
>
```

Underflow is unchecked:

```
> sbyte -129;
val it : sbyte = 127y
```

And so is overflowing:

```
> int16 = System.Int32.MaxValue;
val it : Int16 = -1ls
```

These conversion functions have alternatives in the Microsoft.FSharp.Operators.Checked module that raise an exception if there is an overflow or underflow in the conversion:

```
> Microsoft.FSharp.Operators.Checked.int16 System.Int32.MinValue;
System.OverflowException: Arithmetic operation resulted in an overflow.
at <StartupCode>$FSI_070.FSI_070.main#()
Stopped due to error
```

Numeric literals can also be converted to other types using the System.Convert class provided in the .NET framework. Note, however, that this conversion may fail in certain cases as the documented members of this class.

# Values and F# Types

Fundamentally, every value in your F# code will be compiled to .NET objects, making it easy to interoperate F# code with other .NET languages. However, the following are some of the multiple forms of types that will appear in a non-F# project, and it is important to understand how these types will appear from a non-F# project:

+   - Tuples
- Discriminated unions (algebraic data types)
- Options
- Records
- Lists
- Arrays
