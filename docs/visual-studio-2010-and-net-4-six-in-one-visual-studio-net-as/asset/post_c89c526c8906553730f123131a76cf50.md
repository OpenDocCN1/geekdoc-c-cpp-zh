
## Sequences

All F# collections, such as lists and arrays, implement the System.Collections.IEnumerable<T> interface. In F# code, you often see this interface type as seq<T>, which is a type abbreviation for this interface type. As in .NET code, sequences are lazy data structures. They are enumerated on demand, and sequence values are not computed until they are requested.

It is important to understand that, using sequences, you can turn F# lists and arrays lazy by operating on them with the various Seq.* static members. As you will see, there is a lot of similarity between these and the aggregate operations defined in the List module in Table 25-11, and, indeed, this is true for all F# collections as well. However, the Seq module also supports operations for calculating minimum, average values, sort and average, and traverse in various ways to pick elements.

## Range Expressions

In adding to the various members in Table 25-24, sequences can be constructed in a variety of other ways. For example, numerical sequences can be constructed using range expressions, adding sugar to the more general sequence expressions you will see later in this chapter:

```
seq ( 0 .. 100 )
```

This constructs a sequence of integers between 0 and 100, served on demand. If you need elements of another type, you can add a type suffix to the initial and last element in the range expression, to yield a sequence of float32 values:

```
seq ( 0.0f .. 100.0f )
```

You can also use a skip value to specify an increment. For example, the following will give you all even numbers between 0 and 100.

```
seq ( 0 .. 2 .. 100 )
```

## Sequence Expressions

Sequence expressions are a form of computation expressions, built with the seq computation builder, that yield sequences. They are a versatile abstraction and special handling in terms of syntax from the compiler. You can use them for a host of different purposes — for example, to create a stream of computed elements, or serve large collections incrementally. Consider the following function, AllFiles, that returns all of the filenames in a given folder and all of its subfolders:

```
open System.IO

let rec AllFiles folder =
  seq ( for file in Directory.GetFiles folder do
    yield file
    for subfolder in Directory.GetDirectories folder do
      yield! AllFiles subfolder )
```

This has two parts. First it fetches all files in the given folder using a single System.IO call, and serves their names one by one. Remember that sequences are lazy data structures, and elements are only computed when they are requested.

Once all files in the specified folder have been served, the second part of the function fetches all thefolders and calls itself for recursively enumerate the files. Note the use of yield! to flatten the resulting sequence into one that is being.

In terms of the expression language that you can use inside a seq computation, the following constructs are not supported from the general computation capabilities:

- let!
- use!
- return (you must use yield to return a value from a sequence expression)

All others are available, and you can use them to build your sequence computations. Also, as you saw earlier, you can also use yield! to flatten a sequence of values and return them as part of the original sequence you are building.

## Asynchronous Flows

Asynchronous workflows enable you to write code whose execution is non-blocking. This is often highly desirable — for example, in situations where you need to keep a UI active while performing some intensive computation in the background. Here, your application design not to be single-threaded to avoid the computation becoming the bottleneck of your application.

An important characteristic of a computation is whether it is more CPU or more I/O bound — in other words, whether it spends most of its time calculating the CPU at 100 percent, or whether it waits for the inherently slower I/O operations to complete.
