This is the same example grouped as previously, with the added visual features. There are two VisualStateGroups for a Button: CommonStates (Normal, Pressed, Disabled, and MouseOver) and FocusedStates (Focused and Unfocused). There is also an implicit Base state that essentially represents the visual tree as within the ControlState.

Only one state can be active at a certain time within a VisualStateGroup. That Pressed implies MouseOver, so there is no contradiction here — but the designer may need to copy some settings from MouseOver to Pressed if two states change different properties, in order to keep the consistency of the "feel."

While there can be only one active state within a VisualStateGroup, the VisualStates themselves are independent. A Button can be in the Focused and the MouseOver states at the same time. If the two states change the same properties over the Base state, the resulting behavior is undefined. Likely, Blend wraps around this, as shown in Figure 8-20.
