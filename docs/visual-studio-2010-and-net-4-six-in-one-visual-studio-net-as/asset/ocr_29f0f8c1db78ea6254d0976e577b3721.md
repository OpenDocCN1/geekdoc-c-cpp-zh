Unfortunately, to use ValidateInputAttribute with .NET 4, you must also make a further configuration change. To successfully disable request validation, you must add the following to your web.config file:

```
<configuration>
  <system.web>
    <httpRuntime ValidationMode="2.0"/>
  </system.web>
</configuration>
```

This is because the request processing pipeline was changed in .NET 4.

# Action and Role Filtering

When the user is authorized to execute an action (all attributes IAuthorizationFilter allowed to go with the execution), the real action is wrapped by objects implementing IActionFilter:

```
public interface IActionFilter{
  void OnActionExecuting(ActionExecutingContext filterContext);
  void OnActionExecuted(ActionExecutedContext filterContext);
}
```

The methods implementing these two interface methods are attributes decorating the action method. The MVC framework provides the abstract ActionFilterAttribute class to derive your filter attributes.

First, all OnActionExecuting methods are called. This method receives the execution context as its argument. It can return an ActionResult or a null if the filter does not want to alter the result. A Cancel property is defined in the ActionExecutingContext class that the method can flag the cancellation of the action to prevent it from being executed.

After the execution of the action, the OnActionExecuted is invoked — in the reverse order as ActionExecuting methods were called. At this point of execution, there is some kind of ActionResult available.

Before returning the result to the user, the next step of the processing pipeline is to use the IResultFilter interface:

```
public interface IResultFilter{
  void OnResultExecuting(ResultExecutingContext filterContext);
  void OnResultExecuted(ResultExecutedContext filterContext);
}
```
