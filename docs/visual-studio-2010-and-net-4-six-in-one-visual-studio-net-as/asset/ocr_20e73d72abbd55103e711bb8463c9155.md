# A Few Points About Macro Development

There are about a dozen of books published about Visual Studio development. The following discussion will not teach you every aspect, but highlight a few important things to help you to understand the macro development life cycle.

# Building and Running Macros

Macro projects must be built before running any macros within them. During the build process, the macro syntax and semantics are checked, just as with standard Visual Studio projects, and debug information can also be included to allow tracing and debugging macros. There is no partial build for modules or individual macros. If there is any build-time discoverable error that prevents the project from building successfully, no macro in that project can run. Macros IDE provides an error accessible through the View -> Error List menu item (as shown in Figure 6-9) where you can check builds.

There are several ways to run macros. You have already learned that you can start from Macro Explorer. You can also run them from the Macros IDE, where you start with or without debugging by moving the cursor to the name of the macro definition within the editor. Visual Studio allows you to customize your menus and toolbars with items running macros.

# Debugging a Macro

When you develop macros, you suffer from the same programming mistakes as any other programming language, and the majority of these issues can be solved with the help of a debugger. The Macros IDE provides the same tools for debugging as you can use the same techniques to find and remove bugs as other languages and project types.

In this figure, you see a breakpoint on the first line of the macro, and the current execution line that is one after the breakpoint. At the bottom of the screen, the Locals tool window shows the variables in the macro where you can drill down to the internal values of the locally declared objects.
