# # Auto-Implemented Properties

C# 3.0 introduced automatic properties in 2008. As a sign of co-evolution, Visual Basic 2010 also introduces this feature — even when C# did! Auto-implemented properties (the name is intentionally different from the C# terminology) enable you to specify a property of a class without having to write code to Get and Set. When you write code for an auto-implemented property, the Visual Basic compiler creates a private field to store the property value, in addition to creating the Get and Set procedures.

The following code snippet shows an example defining several auto-implemented properties:

```
Public Class Order
    Public Property ID As Integer
    Public Property CustomerName As String = "Unknown"
    Public Property OrderDate As Date = DateTime.Now
    Public Property Items As New List(OrderItem)
End Class

Public Class OrderItem
    End Class
```

With auto-implemented properties, a property (including a default value) can be declared in a single line. Type inference also allows this: if you provide a default value, the compiler infers the type (assuming Option Inf is on). Should you turn off type inference, properties with default values will be of System.Object.

The Order class defines four properties, the last three with default values. While CustomerName and OrderDate define their types, the type of Items is inferred from the default value.

An auto-implemented property is equivalent to a property for which the property value is stored in a private field. When you declare an auto-implemented property, Visual Basic automatically creates a private backing field to contain the property value. The backing field name is the auto-implemented property name preceded by an underscore (_). For example, the compiler generates the following code:

```
Private _Items As List(OrderItem)
Public Property Items As List(OrderItem)
```
