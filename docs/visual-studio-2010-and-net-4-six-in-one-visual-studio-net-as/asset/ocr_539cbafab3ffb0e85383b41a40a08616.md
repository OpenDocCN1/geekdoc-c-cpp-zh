However, keep in mind that match cases can be arbitrarily complex, so deciding when you have an exhaustive set can be difficult in certain situations. Frankly, the F# compiler has a great deal of to pinpoint patterns that are not exhaustive, and you will get a compiler warning in such cases:

```
> let result =
    match myListWith
    [ ] ->
        1
    [ _ ] ->
        1 :: [ ] ->
        2;
```

C:stdin(3,11): warning FS0025: Incomplete matches on this expression.
For example, the value '[:_]' may indicate a case not covered by the pattern(s).

```
val result : int = 1
```

If you don't handle the missing cases, the compiler will insert an automatic "catch-all" case that simply does nothing but raise a MatchFailure exception. Therefore, it is imperative that you always have exhaustive pattern matches in production code (all code, really), because an unexpected runtime error can have disastrous consequences.

You may be tempted to use the wildcard pattern. However, you should take some precautions. Although using the wildcard pattern removes the compiler warning you just saw, it makes your code less extensible. Consider the following example where you have a discriminated union type representing how clients want to be contacted, and a function that determines whether a particular choice will cost anything. The original developer that added only snail mail cost

```
type ContactVia =
    Email of string
    Mail of string
```

```
let WillCostS =
    match meth with
    Mail ->
        true
    [ ] ->
        false
```

However, in a subsequent iteration, another developer added a new contact method:

```
type ContactVia =
    Email of string
    Mail of string
    Sms of string
```
