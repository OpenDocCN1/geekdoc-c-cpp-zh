# # F AT FIRST GLANCE

F# is strongly typed functional programming language for .NET that also provides a unique and effective combination of object-oriented and imperative features — a sort of “best-of-breeds” language.

If you have a background in other .NET, the first question you may ask when you first look at F# is about its support for object-oriented programming. This chapter is primarily concerned with the basic functional aspects of F#, it is important to establish early in your language exploration that these functional features sit on top of a simple and well-defined object-oriented layer, inherent with the foundations of .NET.

One distinction you will observe in this chapter is the use of the word **object value**. While every object is a value, and ultimately every value is an object, you will see the word *object* to refer to instances of classes only, and *value* for any other F# type. As you will see shortly, there are a host of F#-specific types (such as records, lists, arrays, and others) that get special treatment in F# — although they will all be compiled to .NET classes to make interoperability with other languages properly.

There are several key characteristics of F# that differ from its functional origin. Understanding these will help you get to speed with F# much quicker.

+   **Immutability** — Once values are created and assigned to names (bindings), they do not change, or change only rarely via marked constructs (such as assigning to reference cells). Those data structures that break immutability are *mutable* or imperative data structures, are most (if not all) of the data structures you deal with in your C# or VB programming. With F#, you should think about your data structures mostly *functional*, and *avoid mutation* wherever. You will see plenty of examples of defining and using functional data structures in this chapter.

+   **Functions as first-class values** — The capability to pass functions or return them from others is the basic building block of functional, higher-level abstractions. You will learn about these abstractions in this chapter. You should think of higher-order functions and function values as a natural supplement to what is now more readily available than ever before. In F#, as you will see shortly, these enable you to come up with more robust, and fundamentally simpler abstractions.

+   **Algebraic data types** — These enable you to differentiate a group of “shapes” within a given type. For example, you may want to express that binary trees are nodes (one shape) that carry some value, or trees (the other shape) that have two sub-trees and a value. This often distills into a more natural recursion of your data type.
