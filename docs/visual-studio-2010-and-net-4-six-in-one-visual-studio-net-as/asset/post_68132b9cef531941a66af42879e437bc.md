
# The Project Structure

When you created the AcmeLibrary project, Visual Studio generated several folders and files. You can follow this structure in the Solution Explorer tool, shown in Figure 18-7.

The first important folder from the web application's perspective is the Content folder. It contains the cascading style sheet (CSS) files for the application. Usually, an Images folder under the Content folder holds the images used in the web. You can change the overall design of your site by modifying Site.css file or changing it to another CSS file (and, of course, replacing Site.css references in the appropriate masters).

The second important folder is the Scripts folder. It contains about a dozen JavaScript files for the project you created. It is worth mentioning that your project has built-in support for jQuery client-side scripting, and a jQuery validation plugin-to-model validation in HTML forms without an additional round-trip to the server.

As their names suggest, the three other folders (Controllers, Models, and View) are also related to the MVC pattern. The Controllers folder contains the classes that play the controller role in the project. Figure 18-7 shows Visual Studio created two controllers, one for the Home page (HomeController.cs) and another one for the About page (AccountController.cs).

FIGURE 18-7: Solution Structure

The Views folder is the container for all classes playing the view in the MVC pattern. Classes representing views and their helpers are grouped into subfolders. The Account folder holds views related to the logon and account-handling functionality; Home encapsulates the views related to the About and Home pages. (This is one in the Index.aspx file, and later this will be explained.) The Shared folder holds helper pages and types, such as the Error.aspx, LogOnUserControl.cs and Master.files.

> When you look at the .aspx, .ascx, and Master files, you can recognize that they do not have code-behind files in contrast to the files with similar extensions in ASP.NET web projects. Many functions handled by the code-behind files in ASP.NET projects (such as, for example, collecting form data, validation, and navigation) are managed in a totally different way in ASP.NET MVC, with no need for a code-behind file.

The Models folder is a container for defining model types in the MVC pattern. The Home page and About page do not reference any model class — or you could even say they use an empty model with no properties or operations. The AccountModel.cs in this folder contains model classes for the account-handling functions.

The Models, Controllers, and Views folders are not just for simply organizing files in the project. They provide role-specific context menus. For example, when you right-click the Controllers folder, in the context menu, the Add submenu, you can see the "Controller..." command, as shown in Figure 18-8. This command allows you to add a new controller to your website.

Similarly, you will find a "View..." command under the Add submenu when you right-click the Views folder. You can build your application, but it won't run (or at least not as expected). You will also lose the folder-specific commands in the context menus. Keep the folder names as they are.

The Global.asax and the Web.config file play the same role in MVC 2 as in the traditional ASP.NET projects.

# How Does it Work?

When you create an application with ASP.NET, at the end of the day, requests are mapped to .aspx files (or to HTML files). For example, when the request is represented by http://MySuperWebsite.com/KnowledgeBase/WindowsIssues.aspx URL, the WindowsIssues .aspx file under the KnowledgeBase folder will be rendered to generate the HTML output in the browser.

The MVC framework requests differently. Let's look at the Site.Master file located in the Shared folder under Views. Listing 18-5 shows this file. (Line breaks and a few comments after <div> tags are inserted for the better readability).

LISTING 18-5: Site.Master

```
  <html>
    <h1>My MVC Application</h1>

  <div> <!-- <div id="logindisplay"> -->
    @Html.RenderPartial("LogOnUserControl") %>

    </ul>
  </div>

    <div id="main">
      <asp:ContentPlaceHolder Id="MainContent" runat="server" />

    </div>
  </div>
  <div> <!-- Page -- -->
  </div>
</div>
</body>
</html>
```

While an ASP.NET web master page inherits from the class that derives from the System.Web.UI.MasterPage type, this page (as you see here in the %@ Master tag) inherits from the System.Web.Mvc.ViewPage class that derives from System.Web.MasterPage. The structure of the master page is very similar to ASP.NET.
