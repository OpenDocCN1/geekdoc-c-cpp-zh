## 8.3.1 Cloud Computing

The National Institute of Standards and Technology (NIST) defined cloud computing as “a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (e.g., networks, servers, storage, applications, and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction” [3]. Because of the significant benefits, such as ubiquity, convenience, on-demand resources sharing, high computing and storage capabilities, as well as low costs, cloud computing has become attractive to many large companies (e.g., Amazon, Google, Facebook, etc.) that deliver services over the Internet to gain economic and technical benefits [7]. From the user perspective, cloud hides the underlying complexity and heterogeneity through infrastructure-as-a-service (IaaS), platform-as-a-service (PaaS), and software-as-a-service (SaaS) [8]. Users can outsource their tasks to service providers, instead of purchasing expensive devices for small tasks. The rise of cloud computing has changed the way industries and enterprises do business and has created brand new opportunities for them. However, the problems of network unavailability, overfull bandwidth, and delays make cloud computing unable to solve all problems [9].

## 8.3.2 Fog Computing

The new generation of smart devices, which are capable of processing data locally rather than sending them to the cloud, enable a new distributed computing paradigm, namely fog computing [9]. Fog computing was initially introduced by Cisco, which is one of the world-leading providers of network solutions. Fog computing is considered as an extension of cloud computing to the edge network, providing services (e.g., computing, storage, etc.) closer to near-user edge devices, instead of sending data to the cloud [9–11]. By directly processing data on the network, for example, network routers, the fog computing paradigm can improve efficiency, reduce the amount of data that have to be transferred, and enhance security [8]. Fog computing can be characterized by location awareness, low latency, edge location, real-time interaction, interoperability, support for online interplay with the cloud, etc. [4,12]. These characteristics make application services deployment more convenient. Therefore, fog computing will play a key role in numerous delay-sensitive applications for smart manufacturing.

## 8.3.3 Edge Computing

Edge computing is a scattered architecture that is driven by increasing smart terminals, massive networked devices in IoT, and decreasing cost of computer components [13]. Due to its bright application prospects, many companies have devoted themselves to edge computing, such as Intel, ARM, and Huawei, who are main providers of information and communication technology (ICT) equipment [14]. Similar to fog computing, edge computing also allows computation to be performed at the edge of the network, but at the closer proximity to data sources. Therefore, the edge can be defined as the resources more toward the terminals’ side, which are not only data consumers, but also data producers [5]. Through data analysis and processing in edge devices, edge computing can achieve sensing, interaction, and control between underlying objects and objects. In manufacturing, edge computing can meet the critical requirements of agile connectivity, real-time optimization, and other applications at the manufacturing site.

## 8.4 THREE-LEVEL DIGITAL TWINS BASED ON EDGE COMPUTING, FOG COMPUTING, AND CLOUD COMPUTING

In light of the widespread applications of New IT in manufacturing, manufacturers are facing an explosive growth of data [15]. The essence of the DT is to acquire data from the physical entities and environment through sensors, and then compute and analyze them in the virtual space, so as to control the physical entities and environment. As a result, the data closed loop is established, forming the interaction and fusion between the physical space and the virtual space. The various levels of DTs in manufacturing have different requirements for data processing and data circulation, such as latency, bandwidth, security, etc. Edge computing, fog computing, and cloud computing with complementary properties provide new ideas and ways for the implementation of the unit-level, system-level, and SoS-level DTs. From the perspective of efficient use of resources, DTs deployed at the unit level based on edge computing, system level based on fog computing, and SoS level based on cloud computing can achieve asset control, management, optimization, and business optimization [16].

### 8.4.1 Unit-Level Digital Twin Based on Edge Computing

The basic requirements that need to be met in constructing a unit-level DT include (1) state perception, (2) computing and processing of data, and (3) control of physical entities. As an architecture that extends computing, networking, and storage capabilities from the cloud to the edge, edge computing enables perception, computing, and control for objects through data analysis and processing in edge nodes. As shown in Fig. 8.2, the manufacturing resources (e.g., machine, robot, component, AGV, etc.) with physical devices (e.g., machine body, spindle, tools, etc.) and cyber parts (e.g., embedded system, sensory device, etc.), form the unit-level DT. The cyber parts can monitor and perceive information from the physical devices, and exert control onto the physical devices through an actuator that is capable of receiving control instructions. Due to the perception, data analysis, and control capacities, edge computing can be deployed on the unit-level DT, which can be considered as an edge node. Because of the data circulating on the unit device, edge computing can implement smaller applications that can help provide better real-time responses. The real-time applications provided by edge computing at the unit level include real-time processing and analysis for sensory data, data buffering, high-performance real-time control, actuator monitoring, fault diagnosis, health feature extraction, cycle count accumulation, fault

### 8.4.2 System-Level Digital Twin Based on Fog Computing

As shown in Fig. 8.2, multiple unit-level DTs are connected to the network through the network interface and the information management systems, for example, enterprise resource planning (ERP), manufacturing execution system (MES), supply chain management (SCM), and customer relationship management (CRM). The system-level DT integrates a variety of heterogeneous unit-level DTs. Besides, through the human–machine interface (HMI), each unit-level DT can be accessed and controlled to monitor and diagnose states and health conditions of the corresponding system. The system-level DT emphasizes the interconnections and interoperability among its component elements. On this basis, it focuses on the real-time and dynamic collaborative control of different elements, to achieve the coordination and unification of the physical space and the virtual space. In general, the system-level DT is geographically concentrated (mainly within the manufacturing enterprise), which is well suited to the fog computing model. The data of the system-level DT (i.e., enterprise internal data) can be directly dealt with by fog computing to improve efficiency, rather than be spread to and returned back again from the cloud. Taking delays, network traffic, cost, etc. into account, fog computing provides services at the edge of a network, promoting real-time interaction, scalability, and interoperability. The fog computing environment can be constituted by network components (such as routers, proxy servers, base stations, and others). These components can provide different computing, storage, and networking capabilities to support the implementation of smart manufacturing applications. The unit-level DTs use sensors to collect operating data on each device and analyze them. The fog computing environment summarizes the data from all the unit-level DTs, and provides actionable information (such as cooperation with each other to finish tasks) for smart manufacturing.
