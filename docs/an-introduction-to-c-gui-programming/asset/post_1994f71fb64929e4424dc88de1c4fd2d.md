## Buttons

Make your empty window more interesting and interactive by adding a button

The simple program we looked at in the previous chapter draws a window on the screen, but it looks rather bare. There's also that problem closing the window with the X button leaves the program still running. We're going to fix both of those by adding a button to close the window.

A button is another standard GTK widget and it supports all the features you'd expect - you can have a label on it; you can see its appearance change when you click it; you can activate it with a keyboard shortcut; you can disable it temporarily and grey it out.

The first thing to do is add the button to the window. When we've done that, we can look at making it something useful.

Modify the code for the previous example as:

```c
#include <gtk/gtk.h>

void main (int argc, char *argv[])
{
    gtk_init (&argc, &argv);
    Gtkwidget *win = gtk_window_new (GTK_WINDOW_TOPLEVEL);
    GtkWidget *btn = gtk_button_new_with_label ("Click me");
    gtk_container_add (GTK_CONTAINER (win), btn);
    gtk_widget_show_all (win);
    gtk_main();
}
```

Let's look at the changes:

```c
GtkWidget *btn = gtk_button_new_with_label ("Click me");
```

This creates a GtkButton widget. There is a standard gtk_button_new function, but using this version, `gtk_button_new_with_label`, allows us to add a label to the button at the same time as we create it.

```c
gtk_container_add (GTK_CONTAINER (win), btn);
gtk_widget_show_all (win);
```

Finally, the call to `gtk_widget_show` is now replaced with a call to `gtk_widget_show_all` – this tells GTK to show both the widget and any widgets it contains; if this line wasn't changed, the window would be shown, but the button would remain hidden. If you build and run the code, you'll find a window with a button labelled 'Click me' displayed on it:

## Containers

In the example, we use the line to put the button into the window. As you've probably noticed, each function call in GTK starts with the prefix `gtk_` which is followed by the name of the widget type upon it operates – `gtk_window_new` creates a widget of type GtkWindow. This function call therefore operates on properties of type GtkContainer, but we are using it on `win`, which is a GtkWindow.

There is a hierarchy of widget types within GTK, and a widget type inherits its parents within the hierarchy, that type can be described as a child of the widget types above it. Because GtkContainer is one of the parents of GtkWindow, you can use gtk_container functions on Gtk widgets. Putting one widget inside another like this is something we need to do often. You will notice that when `win` is supplied as an argument to the `gtk_container_add` function, it is wrapped inside the `GTK_CONTAINER()` function – this casts the argument to a variable of type GTK_CONTAINER, it tells the function to treat `win` as a GtkContainer. The code will still work if this function isn't included, but the compiler will complain! (GTK includes a function for every type of widget, as it is quite common to cast a widget to a different type.)

## Signals

If you run the application, you can click the button with the mouse, and it will highlight to show that it has been clicked. You can also hit the ENTER key on the keyboard to do the same thing - behaves exactly like the buttons we are used to seeing in applications, but it still doesn't actually do anything. The next step is to fix that.

The way to do that is to connect a handler function to the signal generated when the button is clicked.

Here's the code with a handler added:

```c
#include <gtk/gtk.h>

void end_program(GtkWidget *wid, gpointer ptr) {
    gtk_main_quit();
}

void main (int argc, char *argv[]) {
    gtk_init(&argc, &argv);
    GtkWidget *win = gtk_window_new(GTK_WINDOW_TOPLEVEL);
    GtkWidget *btn = gtk_button_new_with_label("Click");
    g_signal_connect(btn, "clicked", G_CALLBACK(end_program), NULL);
    gtk_container_add(GTK_CONTAINER, win, btn);
    gtk_widget_show_all(win);
    gtk_main();
}
```

The handler function, otherwise known as a callback, is called `end_program`, and all it does is to call the GTK function `gtk_main_quit` - as you'd expect from the name, this function exits the loop within `gtk_main` and allows the program to end.

```c
g_signal_connect(btn, "destroy", G_CALLBACK(end_program), NULL);
```

This line connects the handler (end_program) to the signal called clicked, which is emitted by a button widget when the mouse is clicked on it. We use the GTK_CALLBACK function to make sure the compiler knows that the end_program function is a valid callback. This isn't perfect, though - if we click the X, the window closes but the program doesn't exit. Let's fix that by connecting another handler to the signal generated when that X.

Signals are used a lot in GTK, all widgets generate signals under various circumstances - mostly interacted with by the user, but also when certain system events occur. Each type of widget has a set of signals it can generate, the `g_signal_connect` function is used to 'connect' a handler function to them, meaning it will be called when the signal is generated.

Handling signals is one of the most important jobs of the main loop which runs inside `gtk_main` - if a signal is generated, code in the main loop checks to see if there is a handler associated with that signal, and calls the handler if there is. By building and running the new code, now we have a button on the window as before, but when we click the button, the window closes and, importantly, the program exits.
