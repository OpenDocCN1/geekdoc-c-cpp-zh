
The third argument to gtk_box_pack_start is called expand. If set to TRUE, then when a window is enlarged, the amount of space allocated for this widget is enlarged in proportion. If set to FALSE, the amount of space allocated for this widget is never more than the minimum it requires.

The fourth argument is called fill. This has no effect if expand is set to FALSE, but if expand is set to TRUE, it controls whether or not it is the space allocated to the widget or the widget itself grows. If expand is TRUE and fill is FALSE, the widget itself stays the same size, if both expand and fill are TRUE, the widget itself grows to fill the increased space.

That is somewhat hard to follow when written down, but a few examples will help to get it straight. Change the GtkHB back to a GtkVBox in the example above, and then both expand and fill for all three gtk_box_pack_start calls in the example above to FALSE. If you resize the window, the label and two buttons will stay the same height at the top of the window.

![](img/6a7eee5b22417c3d49170130a20b16f2_91_0.png)

The layout with expand and fill both set to FALSE for all widgets

Now try the same thing, but change the expand parameter in the gtk_box_pack_start for btn to TRUE:

![](img/6a7eee5b22417c3d49170130a20b16f2_92_0.png)

The layout with expand set to TRUE and fill set to FALSE for the 'Close window' button

The button now moves down the window to fit in the middle of the increased space, the extra space has been allocated to the button, but the button itself is the same size.

Finally, try changing both expand and fill to TRUE for btn to see a result like the image overleaf.

Enlarging the window now causes the whole button to fill the extra space.

We can see that these parameters only affect the vertical size of the widgets; this is because they are used inside a GtkVBox. If we want to control the horizontal size of the widgets as well, we need to create a GtkBox which contains a set of GtkBoxes, which are then used to contain the widgets themselves.

The final argument in the call to `gtk_box_pack_start` is called `padding` – this is the amount of free space (in pixels) which is inserted at either end of this widget, this is in addition to the `spacing` which was requested between all widgets in the `gtk_box_new_call`.

By careful tweaking of `expand`, `fill`, and `padding` parameters, you can create a window which displays all its widgets tidily and resizes exactly as you expect.

# Tables

You might be wondering how you put four items in a window with each of two lines. Well, it is perfectly acceptable to put a GtkHBox as one of the items inside a GtkVBox, or vice versa. It's even acceptable to put an GtkHBox as an item inside GtkHBox (but it's generally a bit pointless). Using a combination of nested GtkHBoxes and GtkVBoxes, you can lay out all the widgets in a window the way you want.

Nesting GtkBoxes and GtkVBoxes works perfectly well for laying out widgets in two dimensions, and actually give you the best control over how they appear, there is a simpler alternative, the GtkTable widget.

A GtkTable is a two-dimensional box, which is defined as having a certain number of rows and columns when it is created. Widgets can then be located at various row and column coordinates. This is not as flexible as using nested GtkBoxes and GtkVBoxes, because every widget has to be aligned in both a row and a column - this means that any row is always at least high as the tallest widget anywhere in it, and any column is at least wide as the widest widget anywhere in it, this can lead to a lot of wasted space. But often a simple arrangement like this is all that is needed, a Table works fine.

Here are the changes to our example if we use a GtkTable to position the label and buttons:

```
void main (int argc, char *argv[])
{
    gtk_init(&argc, &argv);

    GtkWidget *win = gtk_window (GTK_WINDOW_TOPLEVEL);
    GtkWidget *btn = gtk_button_with_label ("Click me");
    g_signal_connect(btn, G_CALLBACK (end_program), NULL);
    g_signal_connect(win, G_CALLBACK (end_program), NULL);

    GtkWidget *lbl = gtk_label_new ("My label");

    GtkWidget *btn2 = gtk_button_with_label ("Button 2");
    g_signal_connect(btn2, G_CALLBACK (count_button), lbl);

    GtkWidget *table = gtk_table_new (2, 2, TRUE);
    gtk_table_attach_defaults (GTK_TABLE (table), lbl, 0, 1, 0, 1);
    gtk_table_attach_defaults (GTK_TABLE (table), btn2, 1, 2, 0, 1);
    gtk_table_attach_defaults (GTK_TABLE (table), btn, 0, 2, 1, 2);
    gtk_container_add (GTK_CONTAINER (win), table);
    gtk_widget_show_all (win);
    gtk_main ();
}
```

We create a new GtkTable with:
```
GtkWidget *tbl = gtk_table_new (2, 2, TRUE);
```

The arguments to the gtk_table_new function are the number of rows and the number of columns. To insert a widget into the table, we use:

```
gtk_table_attach_defaults (GTK_TABLE (tbl), lbl, 0, 1, 0, 1);
```

We pass as arguments the table and the widget we are putting into it. The following numbers are the coordinates where the widget is attached to the table - in order they are the position of the left and right edges, and then the top and bottom edges. This positions the widget in the first column - between x 0 and 1 - and in the first row - between y 0 and 1. Note that you can spread a widget across multiple rows or columns, as in how btn is placed:

```
gtk_table_attach_defaults (GTK_TABLE (tbl), btn, 0, 2, 1, 2);
```

In this case, the widget spans the first and second columns because it is attached to 0 at the left and 2 at the right. For completeness, note that gtk_table_attach_defaults is a shortened version of the function gtk_table_attach which has several other options. These other options include the ability to expand, fill and set padding for each widget as in the gtk_box_pack functions described in the previous chapter. But these functions can get typed out - using gtk_table_attach_defaults sets padding to 0 and expand to TRUE for each widget. If you build and run this code, you will end up with a window that looks like the one below. Note that the 'Close window' button spans both columns of the table as described above.

A GtkTable allows widgets to be aligned in rows and columns to enable users to enter text and select options using check and radio buttons. We've seen how we can display text on a window using a label, but what if we want to read some text that the user has typed? GTK provides the GtkEntry widget for this.

# Text entry

Modify the example code above to add a new cell to the table with the GtkEntry widget, like so:

```c
#include <gtk/gtk.h>

GtkWidget *txt;

void end_program(GtkWidget *wid, gpointer ptr)
{
    gtk_main_quit();
}

void edit(GtkWidget *wid, gpointer ptr)
{
    const char *input = gtk_entry_get_text(GTK_ENTRY(txt));
    gtk_label_set_text(GTK_LABEL(ptr), input);
}

void main(int argc, char *argv[])
{
    gtk_init(&argc, &argv);
    GtkWidget *win = gtk_window_new(GTK_WINDOW_TOPLEVEL);
    GtkWidget *btn = gtk_button_new_with_label("edit");
    gtk_signal_connect(btn, "clicked", G_CALLBACK(end_program), NULL);
    gtk_signal_connect(win, "delete_event", G_CALLBACK(end_program), NULL);
}
```

```c
GtkWidget *lbl = gtk_label_new ("My label");
```

```c
GtkWidget *btn2 = gtk_button_new_with_label ( ... );
g_signal_connect (btn2, G_CALLBACK (copy_text), lbl);
```

```c
txt = gtk_entry_new();
```

```c
GtkWidget *tab = gtk_table_new (2, 2, TRUE);
gtk_table_attach_defaults (GTK_TABLE (tab), lbl, 0, 0, 1, 1);
gtk_table_attach_defaults (GTK_TABLE (tab), btn2, 1, 0, 0, 1);
gtk_table_attach_defaults (GTK_TABLE (tab), win, 0, 1, 1, 2);
gtk_table_attach_defaults (GTK_TABLE (tab), txt, 1, 2, 1, 2);
gtk_container_add (GTK_CONTAINER (win), tab);
gtk_widget_show_all (win);
int main() {
}
```

In this example, we declare a pointer to the GtkEntry widget txt as a global variable. This is because we need to access it from the button handler, which in this case the handler needs access to the Gtklabel widget. We previously used the general-purpose pointer in the g_signal_connect function to pass widget information to a handler, but for two separate widgets we've only got one pointer (There are ways of using a single pointer for this, but using a global variable is easier to understand).

We've added a new function, copy_text which uses the function gtk_entry_get_text to get a pointer to the text buffer by the GtkEntry, which stores whatever the user has typed into the entry box. Note that this buffer of chars is declared with the modifier const - this indicates a variable that cannot be changed by the programmer. We then pass this buffer to gtk_label_set_text, which copies the contents of the GtkEntry to the GtkLabel.

Finally, we created the GtkEntry itself with gtk_entry_new, and added it to the table (Note we've also moved the attachment points of btn so that it only takes one cell of the table rather than two, so as to give enough space for the GtkEntry).

Build the code and run it; try typing something into the entry box and pressing the 'Copy' button to see what happens.
