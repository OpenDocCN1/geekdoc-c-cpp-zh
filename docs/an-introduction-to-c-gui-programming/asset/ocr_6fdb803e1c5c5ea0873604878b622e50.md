# Chapter 12
Header files and the preprocessor

Splitting code up into multiple files

Il the examples we've seen so far have put all the code for a program in a single file. But once programs get big, it makes more sense to be able to split them into units, grouping similar functions together. To understand how this works, we need to look in more detail at what the compiler actually does:

In all the examples so far, we've called gcc on a single source file and it has created a single executable program. This hides the fact that gcc actually does two things: first it compiles your C source file into what's an object file, and then links the object file with all the library functions to create the executable. This second step is performed by a program called a linker, gcc does.

If you create a program with multiple source files, you just need to include the names of all the source files in the call to gcc. It will create one object file for each source file, and then link all your object files together to create the executable

There's one snag, though: if you separated your code into separate files (usually referred to as modules), you'll have some files which make calls to functions in other files in order to work. These files do not find out about how the linker operates on them; the files are compiled individually, and the compiler will complain if you use functions in a file it doesn't know about

We fix this using header files. These are files with extension .h which hold the declarations of functions (and global variables) defined in a module, so that the compiler can be told about them when they are used by another module. We have already seen this many times, remember that #include <stdio.h> at the top of the examples? That is exactly this process; it's telling the compiler that functions declared in the system header file stdio.h are used in this module.

# KEEP NAMES CONSISTENT

While you can call header whatever you like - there's no obligation about the names - it's good practice to give the header file for the functions in a particular file the same name as the C file itself, with h extension rather than c. This makes it easier for someone reading your code to find the files where functions are defined
