## // DEVELOPING ALGORITHMS

为了开发算法，你将遵循一种类似于自顶向下设计方法的方法，但你希望将问题保持尽可能狭窄。

接下来，你考虑算法想要的输出。 显然，你想要输出一个移动，即算法能够确定的最佳移动。

如果你面临做出选择，你有 3 个基本步骤：
- 列出所有可能的合法移动。 对于 Connect 4，每个玩家都有 7 个移动——任何未满的列。
- 评估这些移动中的每一个，以获得衡量每个移动好坏的指标。
- 确定这些移动中哪一个最好并返回结果。

算法的目的是让计算机确定它在游戏中可以做出的最佳移动。 考虑到这个目标，你想知道在游戏的哪个阶段？ 因此，输入将是当前游戏棋盘的状态以及轮到哪个玩家的指示。

清楚地指定输入和输出是算法设计的重要组成部分——与算法本身的步骤一样重要。 算法通常被实现为函数； 算法的步骤成为函数中的代码。 你可以以与自顶向下程序设计类似的方式来处理这种设计，查看整体挑战并将其分解为更简单的部分。

看看如果做出该移动会是什么样子），然后确定该移动使你处于多好或多坏的状态。

你想考虑计算机需要考虑多少步。 因此，你将接受一个输入：你所在的递归级别。 每次你进行递归调用——也就是说，每次你决定最佳移动——你将比之前多做一个递归级别。 如果你达到最大值，你将停止进行递归调用。 一旦你达到最大递归级别，你只需评估棋盘以获得分数。

这是你的棋盘评估：
- 如果游戏平局，那么你会给 player1 一个负分——分数越负，player 1 赢得越多。
- 如果 player 2 寻求获胜，你会给一个正分：分数越大，player 2 的优势越大。
- 如果其中一名玩家实际获胜，你应该有一个非常负或非常正的分数。

这里的想法是尽可能多地向前思考。 你可以一次生成所有可能的移动，但这在内存需求方面可能会变得非常昂贵。 相反，你需要搜索棋盘，分为两种情况：要么你不想向前看很多步，只想看看当前棋盘位置有多好，要么你想选择其中哪些移动。

当你通过递归评估多个移动时，仅知道下一个移动是不够的——你还需要知道该移动有多好。 因此，你不仅要返回最佳移动，还要返回该移动的分数； 换句话说，你的返回信息增加了。 你将使用该分数来调用移动并确定哪一个最好。

如果愿意向前看多一点，那么你需要从对手的角度重新开始这个过程； 也就是说，你想通过这个算法，但现在从对手的移动开始。

算法的输入是当前棋盘状态。 算法的输出将是该棋盘的分数。 如果棋盘表明 player 1 获胜——也就是说，如果玩家得到 4 个她的棋子连成一排，称为 connect4——那么你返回一个很小的数字，比如 -1000。 如果棋盘表明 player 2 获胜，那么你返回一个非常大的数字，比如 1000。 如果游戏以平局结束，那么你将棋盘评估为 0。
