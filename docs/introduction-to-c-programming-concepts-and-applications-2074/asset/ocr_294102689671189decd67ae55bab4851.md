The key thing to realize is that the base class, **shipping_company**, declared a pure virtual function with no implementation. Only in the derived classes were actual definitions for that function given.

When you have pure virtual functions, it's important to realize that you can't have an instance of the base class. In the example, it doesn't make any sense to have a shipping company; there's no way to know what the shipping cost would be for some generic shipping company. Instead, you need to have a specific shipping company.

You can't create an object out of an abstract class, though you can have references to an abstract class. Classes that do provide the implementation details—the lower-level derived classes that create objects are—concrete classes.

So, if you take the same prior definitions and change the **main** routine to create an instance of a **shipping_company**, you end up with an error telling you that you can't declare an abstract type. ◆

A class that has pure functions is an **abstract class**. It defines an interface, like **shipping_company**, that can't refer to any specific instance of the class, but rather defines some more general, abstract representation.

```
// Error when trying to instantiate an abstract class
int main() {
  shipping_company;
}
```
