
## // OVERLOADING STREAM OPERATORS

It is very common that you'd want to stream data an object to output it to the console, a file, or a string. Likewise, it's common that you'd want to stream data into an object. It would be nice to declare a `lightblue` object and just to be `cout` or `cin` in it. But this, you have to overload the stream operations.

Remember that the syntax of an operator is that you have the stream on the left, `<<` for output or `>>` for input, and then the thing you are wanting to stream out of or in. And the stream should be able to continue.

Because the stream itself comes the left of the list, that means you can't write a stream operation for your new class as part of that.

So, instead you need to have the stream outside the class. It's a good idea to make this stream operator a friend operator, because that you'll have access to the member variables.

You can think: "If I'm outputting to a stream, I'll have an `ostream`. If I'm inputting, I'll have an `istream`." Both are predefined stream types, where `cin` is an example of an `istream` and `cout` is an example of an `ostream`.

## 18 Dynamic Memory Allocation and Pointers

You usually think of the computer's main working memory (the memory stored in RAM) as one uniform block of memory. Items you declare space set aside for them ahead of time. This is known as static memory allocation, and it's how standard variables and parameters are stored. But as you start developing more complex objects, sometimes you want to allocate new memory during the program—memory you didn't know you need ahead of time. That's what dynamic memory allocation is for.

## // DEREFERENCING POINTERS

Main working memory comes in of 2 varieties: the stack or the heap.
* The stack is static memory that you know and allocate as you declare them. The stack stores all the variables and parameters.
* The heap is for dynamic memory allocation—for anything that's not known in advance and is instead allocated as. The heap is sometimes referred more formally as the free store.

It's not uncommon to be uncertain as how much memory you'll need. You use dynamic memory allocation whenever you want to store an uncertain amount of information that will keep coming, and thus growing over time. Often classes hide this from you. The vector class hides how and where it's allocating new memory.

But vectors don't always fit the problem you have. Sometimes you need to allocate memory for yourself.

To allocate memory on the heap in this more dynamic way, you need a pointer, a variable that holds an address in memory. Usually, but not necessarily, there is some data at that point, but keep in mind that the pointer variable does not store the data—just the location where the data is.
