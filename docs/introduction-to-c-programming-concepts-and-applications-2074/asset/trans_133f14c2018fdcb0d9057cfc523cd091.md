

这种初始化-比较-递增模式如此常见，以至于它有自己的循环形式：**for**。**Program 5_12** 和 **Program 5_13** 具有完全相同的效果。

请注意，你已将来自 **while** 循环结构中的 3 个部分——变量的初始化、条件和变量更新——放入了 **for** 循环的开头。

还要注意，你以单词 **for** 而不是 **while** 开始循环。**for** 循环基本上将原本会分散在 **while** 循环中的几个部分打包在一起。

**for** 循环总是以关键字 **for** 开始，然后像 **while** 循环一样，有括号和大括号，保护循环体。不同之处在于其模式是什么。与 **while** 循环只有条件不同，你实际上有 3 个不同的部分由分号分隔；

- 初始化，即在 **while** 循环形式中会在循环之前出现的地方，是你为循环中使用的变量设置初始值的地方。
- 条件的工作方式与 **while** 语句中的条件完全相同。
- 更新发生在循环的每次迭代结束时。

```
// Program 5_13
// For loop for computing balance for set number of payments
#include <iostream>
using namespace std;
int main() {
    float balance = 1000.0;
    float payment = 100.0;
    float interest = 0.05;
    int numpayments;
    for (numpayments = 0; numpayments < 5; numpayments++) {
        cout << "Balance after " << numpayments << " payments is: " << balance << endl;
        balance += balance * interest;
        balance -= payment;
    }
}
```

## While loop

```
while (condition) {
    // Commands to do each iteration of loop
    // (This is the body of the loop)
    // update
}
```

因此，当你有一个 **for** 语句时，首先执行初始化命令，然后在循环的每次迭代中检查条件，最后在循环的每次迭代结束时运行更新命令。

## For loop

```
for (initialization; condition; update) {
    // Commands to do each iteration of loop
    // (This is the body of the loop)
}
```

for 语句要做的全部就是条件；与 while 循环不同，可以省略 for 语句内部的初始化和更新。

例如，在此版本的代码中，你将初始化放在 for 语句之外。你仍然需要分号来分隔不同的部分，但你可以只省略第一部分。

通常，for 循环的优点是理解循环所需的所有信息都将包含在 for 语句中——括号内。如果初始化、条件和更新都在一个地方，就更容易理解循环的工作方式。

在那第三次迭代之后，变量的值为 4，因此它不再小于 4，这样循环就不会再进行另一次迭代。循环之后，i 的值为 4，因此你输出最后一行 loop: 4。

重点是控制循环的变量——称为循环控制变量——在之后仍然有一个值。通常，它将是导致条件失败的第一个值。

而在此版本中，你也省略了更新部分，将更新放回循环中显式执行。因此，for 语句在实例中工作方式与 while 语句完全相同，只是条件被分号在两侧包围。

因此，如果你想打印出数字 1、2 和 3 的乘法表，你可以使用此处所示的代码，其中有 2 个嵌套的循环。最外层的循环有变量 i 从 1 迭代到 3，内部循环有变量 j 从 1 迭代到 3。对于每个，代码将打印出 i 和 j 的乘积。

因此，在这种情况下，当 i 的值为 1 时，j 将具有 1 到 3 的值。然后，i 将具有值 2，j 将再次获得到 3 的值。最后，i 具有值 3，j 再次获得 1 到 3 的值。因此，该程序有 9 行输出。

```
// Program 5_17
// Nested for <iostream>
using namespace std;
int main() {
    int i;
    int j;
    for (i = 1; i < 4; i++) {
        for (j = 1; j < 4; j++) {
            cout << i << " " times " << j << " " is " << i * j << endl;
        }
    }
}
```

使用 i 和 j 作为循环控制变量是非常常见的。即使这些并不是特别具描述性的名称，如果你
遍历一系列值，使用 i 来表示这些值是很常见的，如果你有 2 个嵌套循环，使用 j 表示内部循环是很常见的。因为人们期望 i 和 j 是循环迭代索引，所以这是一个单字母本身成为描述性变量名的时刻。

## SCOPE OF VARIABLES

作用域不仅仅适用于循环；它甚至可以适用于条件语句。但循环是你通常想要使用作用域的第一个地方。

简单来说，每次你声明一个变量，你就在内存中为该变量获得一个新的“盒子”。但该变量仅在代码块内持续存在——由大括号定义的一段命令。一旦你离开由闭合大括号定义的块，该块的内存就会消失。

Program 5_18，for 循环的初始化部分不仅仅初始化整数——还声明了它。这意味着声明的变量——在本例中为 i——仅存在于该循环本身中。它的作用域只是那个循环。

在这种情况下，循环按预期运行，并输出值 1、2 和 3。

然而，如果你尝试在循环后打印 i 的值，那么你会得到一个错误！变量 i 在那时不再被定义；内存的盒子已被销毁！

在 Program 5_19 中，你在循环内部声明变量 j。如果运行它，你会得到预期的迭代次数，就像你预期的那样，i 的值在循环体中依次取 1、2 和 3，在循环结束后为 4。但为什么 j 的值总是 j++，这似乎会改变 j 的值？

```
// Program 5_18
// Declaring a variable in a loop header
// include <iostream>
using namespace std;
int main() {
    for (int i = 1; i < 4; i++) {
        cout << i << endl;
    }
}
```

```
// Program 5_19
// Declaring a variable in a loop
// include <iostream>
using namespace std;
int main() {
    for (int i = 1; i < 4; i++) {
        int j = 1;
        cout << "In loop: " << i << " " << j << endl;
    }
    cout << "After loop: " << i << endl; // Error here
}
```

```
// Program 5_21
// New variable name inside loop
#include <iostream>
using namespace std;

int main() {
    int j;
    int j = 1;
    for (i = 1; i < 4; i++) {
        int j = 500;
        cout << "In loop: " << i << " " << j << endl;
    }
}
```

声明它为 j，当循环体执行时，j 会再次被声明。因此，你创建一个新的名为 j 的盒子，并将其初始化为 1。稍后在循环体中，你递增 j，因此它将具有值 2，然后循环体结束。此时，内存被销毁；j 不再可用。

下一次你通过循环时，你创建变量 j 并将其初始化为 1。因此，每次打印出来时，显示的值都将为 1。

要在循环的一次迭代到下一次迭代之间保持静态，你可以在循环内部声明一个静态变量。如果你把 static 放在声明前面，它表示你想要声明一个变量，并且该声明即使超出作用域也持续存在。因此，如果你稍后在代码的这一部分返回到该变量，你将可以访问它。

在循环内部声明一个变量会为该变量分配新的内存，即使它与循环外部的变量同名。当循环结束时，该新内存被销毁，但原始变量仍然存在。

| int j = 1; | static int j = 1; |

在这种情况下，变量 j 在你进入循环体第一次时创建。每次以后通过主体时，该行会被跳过，你不会在循环结束时销毁名为 j 的盒子。因此，每次遇到 j++ 行时，它都会递增 j，并且新值会在下一次迭代中保留。

在那之后超出作用域。如果你尝试在循环后访问 j，你仍然会得到一个错误。
你在大括号内声明的变量可以与在大括号外声明的另一个变量同名；你创建一个作用域仅在循环期间持续的新 j，一旦你离开循环，先前的变量 j 再次被使用（Program 5_21）。♦

然而，这并不意味着 j 在循环结束后仍然存在；它仍然会返回
