To develop the algorithm, you'll follow an approach that is similar to the top-down design approach, but you want to keep the problem as narrow as possible.

Next, you consider the output you want from the algorithm. Clearly, you want to output a move, the best one the algorithm could determine.

If you're faced with making a choice, you have 3 basic steps:

+   Make a list of possible valid moves. For Connect 4, each player has 7 moves—any column that's not full.

+   Evaluate each of those moves to get measure of how good or bad each is.

+   Determine which of those moves is best and return the result.

The purpose of the algorithm is to let a computer determine the best move it can make in a game. With that goal, in mind you want to know at what point during the game? So, the input will be the current state of the game board and an indication of which player's turn it is.

Specifying the input and output clearly is an important part of algorithm design—just as important as the steps of the algorithm itself. Algorithms are often implemented as functions; the steps of the algorithm become the code in function. You can approach this design in a similar way that you would approach top-down program design, looking at the overall challenge and breaking it into simpler parts.
