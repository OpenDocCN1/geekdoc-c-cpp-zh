There's another key part of the debugger. When the debugger runs, there is a window at the bottom that lets you examine the values of variables.

Next to each other is the value of that variable. Notice that neither date nor meter is initialized to anything. The date should have an empty string as value, while the meter could have any possible number. You've never read anything into either of them yet. The variable electricfile doesn't have a meaningful value; it's reporting on one hour

In the electric usage, put a breakpoint right before the first line you stream from electricfile and start the debugger. It will execute right up to that line.

If you push Step Over, you are inside the for loop. If you push Step Over once, you print the i value and go back to the top of the for loop, where you will check the conditional. And you can keep stepping through.

At the bottom of the screen, you should see a window that shows variables. In Visual Studio, it will have 3 tabs Autos, Locals and Watch 1, and one of them (probably Locals). You should select 3 items listed there. In alphabetical order, these are the 3 variables you have at this point in the program: date, electricfile, meter.

If you go forward line, by pressing Step Over, move on to the next line of the code. You also see that the values in both date and meter have updated. The previous line read data into both of the file. In this case, you have a date of 1024. As you go through the code, you can keep an eye on the window to see what the values of variables.

You'll notice that you go through all iterations of your loop and eventually leave the loop condition is false.

To stop your debugging session, you can hit the Square button, which will stop the entire run.

Besides the Step Command to step over the next line of code, there's a Step Into command, which doesn't just "execute the next line of code." If that next line of code has a call in it, then the execution goes into that function. You'll be able to see how the function itself is working. There's also a Step Out if you are tired of looking inside a function's inner workings and want to return to the place it was called.
