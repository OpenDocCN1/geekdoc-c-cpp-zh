
## // CONSTRUCTORS WITH INHERITANCE

When using inheritance, constructors for the most part work much like all the constructors you've seen before, but it can be tricky to handle constructors when you're inheriting some of your properties and not have direct access to them.

```
// Program 19_5
// Inheritance Example: Constructors
#include<iostream>
#include<string>
using namespace std;

class bank_account {
private:
    string owner_name;
    string owner_address;
    long long int account_number;

protected:
    double balance;

    void set_account(long int acctnum, double startbalance) {
        account_number = acctnum;
        balance = startbalance;
    }

public:
    bank_account() {
        owner_name = "";
        owner_address = "";
        account_number = 0;
    }

    bank_account(string name, string address, long long int num, double bal) {
        owner_name = name;
        owner_address = address;
        account_number = num;
        balance = bal;
    }
```

The way of this is that when you call a constructor in a derived class, you need to first have a constructor for the base class. After all, the derived class is only adding additional stuff whatever was in the base class. So, first you need to have the base class set up, and then you can add whatever additional things are needed for the derived class.

This way is done is that when a constructor is defined, you put a colon after the constructor declaration, giving the constructor to use for the base class.

For example, lets define 2 constructors for the base bank_account. First, you'll have a default constructor that basically sets everything to strings or to . Then, you'll have a constructor that takes in all the various parameters to initialize all the member variables to specific values. In this case, there are 4 parameters: for the owner's name, owner's address, account number, and starting balance. You use these parameters to initialize the various member variables of the bank_account class. All of this is just like you would have had for any other constructor ().

Now let's look at the constructors for the derived classes, the checking and savings accounts. For a checking_account, there are no new member variables. So, the checking_account constructor doesn't need to do anything more than the base bank_account constructor. You define 2 constructors for checking accounts: one default and one with the 4 parameters to initialize a bank_account.

For the default constructor, you write checking_account() : bank_account() and then a few curly braces inside (r). That bank_account with no arguments in the parentheses means when this checking_account constructor is called, it will first call the bank_account constructor with no arguments. In other words, it will call the curly braces, so nothing more is done.

Likewise for the other constructor, you'll call the bank_account constructor with 4 parameters (s). Again, there won't just define anything in the curly braces. You use the checking_account constructor to take in 4 parameters and then write : bank_account and, in the parentheses, pass those same 4 parameters as arguments to the constructor. This will call the non-default bank_account constructor with those arguments and do whatever is in the curly braces, which in this case is nothing.

With the savings_account, there is one more member variable. You'll define 2 savings_account constructors, just like for the checking_account. Everything will be the same about, except that the member interest_rate must be set in each constructor. The default constructor just sets this member variable to 0.0 after calling the default bank_account constructor (t). The other constructor takes 5 parameters and 4 of those as arguments to the bank_account constructor.

When you are defining a constructor in a derived class child, you probably need to make use of the constructor in the parent class to fully initialize an object. In particular, if the instances have any private member variables, you'll initialize those by using the parent's constructor, because the derived class cannot access variables itself.

You can see that you declare instances of the checking_account and savings_account variables with the non-default constructors, do get everything initialized correctly (v).
