## 19 Object-Oriented Programming with Inheritance

The most important idea of object-oriented programming is encapsulation, which is the wrapping of data and functions together in one tidy package. Another powerful idea is inheritance, which is the idea that you should be able to create classes that can inherit this encapsulation of member variables and functions from another class. In short, you can use an abstraction you already have to create one or more new abstractions. This creates a hierarchy: Objects can inherit from a "parent," and the relationships among various inheriting objects can form a tree structure.

## // INHERITANCE

Inheritance offers several benefits.

Inheritance plays a powerful role in object-oriented design. It lets you define something single time in one class and then use it in multiple other classes. It means that you can define a new class, and rather than writing every piece of it from scratch, you can start with everything already defined in another class.

- It prevents having to rewrite the same code over and over. An ancestor can save on properties to all of its offspring. In terms of coding, this can save a lot of time and work.

In practice, there are a few ways that inheritance works.

- It reduces the number of places that bugs could be introduced to the program, so you reduce debugging time.

From a top-down viewpoint, object-oriented inheritance can be thought of as a way of making a more general idea and dividing it into more specialized views. It can also work from a bottom-up viewpoint, where you start with the offspring and decide what sort of ancestor they have. Whether top-down or bottom-up, the result is a similar arrangement of classes.

Inheritance also creates a hierarchy of classes—a relationship between ancestors and descendants.

- It enables polymorphism, which you'll learn about in the next lecture.

## TERMINOLOGY

There are different terminologies that are used to describe the relationships between different classes in a class hierarchy.

You've already seen a few areas in which inheritance is used to define classes. Important area involve streams. You've seen streaming to and from the console, and to and from strings. All of them are basically derived classes that inherit from a more general base class.

Following the terminology used for trees, you may refer to a parent class and child class. One parent can have several children, also known as offspring.

A second area of inheritance you've already encountered is exceptions, which can cause a function to exit when an exceptional case is encountered. There is a general exception class and more specialized child classes, each of which has more specific classes.

#include<iostream>

using namespace std;

class product {
public:
    float wholesale_cost;
    float retail_cost;

class cup : public product {

};

int main() {
    cup plastic_cup;
    plastic_cup.wholesale_cost = 0.10;

    plastic_cup.color = "red";

    cout << "The plastic cup costs "

}

A superclass is the class in the hierarchy, and a subclass is a class below a point in the hierarchy. A superclass encompasses many different classes, while a subclass is a narrower description of a class.

In this example, you have a general class, the product. Products contain member variables for both a wholesale and a retail cost (a).

The base class is effectively the parent, and the derived class is the child.

Then, there is a separate class created for a specific product: the cup. The cup has 2 member variables of its own: a volume that the cup holds and a color for the cup, represented as a float and a string, respectively (b).

For the most part, if you hear the terms parent class, superclass, or base class, they probably mean the same thing. And if you hear the child class, subclass, or derived class, they probably mean the same thing.

The key difference from what you've seen before is that the cup is also defined to be a child of the product. You see this by the : public product placed right after the name. Because this is the case, the cup inherits the member variables from the product class.

Then in the main routine, you can define a cup object, named plastic_cup. This will let you not just the volume and color, but also the wholesale and retail costs for the cup. You do this by assigning values to plastic_cup.wholesale_cost and plastic_cup.retail_cost, the same as you would would the other member variables, plastic_cup.volume and plastic_cup.color (c).

To keep things simple, let's assume that everything is public.

When creating a class, if you want to inherit from some other class, you declare the class statement as usual, but using a colon, access public or private, and then the name of the parent class.

In Program 19_a, because you wanted to create a cup class that was derived from the product class, you would write class cup : public product and then the class definition in curly braces (13).

You can also inherit in a larger class hierarchy. For example, you might want to distinguish your cups by some of them that were specifically measuring. You could make a new class, a measuring_cup class. It would inherit from cup, so you'd declare class measuring_cup : public cup in the declaration (19).

That means it inherits the features of the cup class, which also means it inherits the features of the product class. It can also define its own member variables and functions. In this case, you can define two new variables for the measuring_cup: a Boolean to note whether it is metric or English units and an integer number of graduations (d). A measuring_cup has access to 6 different member variables: the 2 that were defined for measuring, and the 2 that were defined in the product class (e).
