First, notice the line that begins with the word **cout**, which is an expression "console output". The **console** means that there's going to be output, and the output will be going to the console—it is to the default output area. In an IDE, the default output area may be an output pane within the main window, or it might pop up a new window if you're running the code in a browser. It will show you the result in that window you're running.

The next thing that gets streamed to the output is the word **endl**, which is a way of saying "end line" for output. If you don't include **endl**, then the next line'll be printed out immediately after the first one; you include **endl**, so that the next thing to be printed will come at the beginning of the next line.

+   The only times you don't have a semicolon; for a few special cases:
* **#include** line isn't a command that you want to perform as part of the program but rather a command to the compiler that translates the code to machine instructions
* the braces around **main** are not a command but rather a way of grouping commands

Next is what looks like a double-less-sign. This is the output **stream operator (<<)**. The less-signs as arrows pointing in the direction that the information is flowing. In this case, you have something that you want to print, so that you're printing will flow toward the console output. Notice there are 2 stream operators on one, which shows that different items are streamed in: The thing to the left will reach the console output before the thing to the right.

> The **endl** indicates an end of line what is output, not necessarily the end of a line of code.

Finally, a semicolon appears at the end of the line of code. In C++, the semicolon indicates that you've reached the end of a line.

Any time you finish with an individual command, it will need to have a semicolon at the end.

Unlike other languages, the order and spacing of your C++ code doesn't matter. You can put instructions of code on one line with no space after the semicolons, or you spread a single instruction over multiple lines. The compiler basically ignores everything as it converts the program to machine instructions. Instead, you separate one command from another by using the semicolon to mark the end of a statement.

> Just as a period ends a sentence in English, a semicolon ends a statement in C++.

Just like a sentence you can write across more than one line—or you can have 2 sentences on the same written line—a statement in C++ can go across more than one line, or you can have more than one C++ statement in the same written line. It's the semicolon, not just moving to a new line, that ends a statement.

After the stream operator is the text that you actually want to output. Notice that the text you want is enclosed in a pair of quotation marks. You have to use quotation marks to identify text in your code; otherwise, the letters will be misinterpreted by the compiler. The words **Hello** and **World**, with punctuation—a command and appear inside the quotation marks.

Comments can be anything that helps people understand what the code is for. Comments are skipped entirely by the compiler; when a compiler sees a double slash, it reads what follows as a comment. While processing code, it skips over, all the way to the end of the line. So, including comments is purely to help people reading the code.
