When approaching any large programming problem, start with a top-down design, build it incrementally, and use the debugger to help you verify that things are working.

The other useful item in the debugger is Call Stack. In Visual Studio, Call Stack is found in the lower right, and in Xcode, there's a window showing the Call Stack.

The whole reason you're using the debugger here is to verify that your code is correct. The debugger will also be very useful when you encounter bugs and need to find where they are occurring.

If you have written your functions and stepped into them, then the Call Stack will also show which functions have been called from other functions. In Visual Studio, the Call Stack will also show the line numbers.

# READINGS

+   Top-down design is a long-standing software development practice and is a typical approach used in procedural programming for languages that do not support object-oriented design, such as C.

+   Top-down design with functions can be found in several C textbooks—e.g., Problem Solving and Design in C (8th ed.) by Jeri R. Hanly and Elliott B. Koffman—C++ textbooks with more of a build-on-C e.g., Problem Solving, Abstraction, and Design Using C++ (6th ed.) by Frank L. Friedman and Elliott B. Koffman.
