
## INPUT

Input is handled in a very similar way as output. Values are streamed in variables. You get your input from the user typing in data into a window. This window is again referred to as console, so the term *cin* is used to designate that you have input from the console.

Just like the output indicated that the stream of information should flow from variables toward *cout*, for input, the information will flow rightward from *cin* to the variables. So, you'll use >> to designate this; the direction of the stream of data is *cin* to the variables.

Look at this modified calorie-counting code. First, there is a **stream operator** with output for the console, giving the user instructions on what to do with (10). In this case, the user is to enter the grams of each type.

Next, you have 3 *cin* lines to indicate input that you'll get from the console (h).

The first of these indicates that the first thing the user types will be stored in the variable *carb_grams*. The second thing the user enters goes into *protein_grams*, and the third will go into *fat_grams*.

```cpp
// Program 2_19
// Compute calories for dish based on user input
#include <iostream>
using namespace std;

int main() {
    int carb_grams;
    int protein_grams;
    int fat_grams;

    cout << "Enter the number of grams of carbohydrates, protein, and fat, separated by spaces." << endl;
    cin >> carb_grams;
    cin >> protein_grams;
    cin >> fat_grams;

    int calories = 4 * carb_grams + 4 * protein_grams + 9 * fat_grams;
    cout << "There are " << calories << " calories in this dish" << endl;
}
```

In short, now the user can choose the grams of each type instead of having those values stuck on the initial values set in the code.

If you run the program and enter the values 10, 20, and 30, for example, you get an output telling you that there are 390 calories in this dish; that is, a dish with 10 grams of carbohydrates, 20 grams of protein, and 30 grams of fat will have 390.

Just like the output streams could be combined with multiple stream operators on each line, you can combine multiple input stream operators on one line. The input line you see here is the same as the 3 lines shown previously.

```cpp
cin >> carb_grams >> protein_grams >> fat_grams;
```

You read the first piece of entered data into carb_grams, the second into protein_grams, and the third into fat_grams. The program gives the same output as before.

If you wanted to ask users for carb, fat, and protein grams using 3 different questions?

You could have 3 different cut output lines, each showing what to enter, as shown in Program 2_21. Each is followed by a separate line, returning values in each of the variables.

```cpp
// Program 2_21
// Prompting user for multiple inputs
#include<iostream>
using namespace std;

int main() {
    int carb_grams;

    cout << "Enter the number of grams of carbohydrates: ";
    cin >> carb_grams;
    cout << "Enter the number of grams of protein: ";
    cin >> protein_grams;
    cout << "Enter the number of grams of fat: ";
    cin >> fat_grams;

    int calories = 4 * carb_grams + 4 * protein_grams + 9 * fat_grams;
    cout << "There are " << calories << " calories in this dish" << endl;
}
```

## Valid Names
(but not great choices)

Naming a variable something tells you too little about what it's supposed to hold.

The i is also valid as a variable name. There are circumstances that you could use a single letter like i for a example, in math, you might have a value like x and use i as a subscript or superscript.

A name like account is not horrible, it's not clear what value stores: It is the account balance, the account ID, the account name, etc.? A name account_balance would be much easier to understand.
