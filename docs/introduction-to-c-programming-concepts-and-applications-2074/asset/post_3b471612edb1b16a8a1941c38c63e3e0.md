
Suppose you have a savings account balance and you'd like to increase the balance by percentage to account for earning interest.

Passing by reference makes it possible to modify a value. It also has the advantage of not having to go through the process of copying the variable.

You can create a function increase_percentage that will take 2 parameters: the value you want to increase and the percentage to increase. The key here is that you are going to modify the balance so that the first parameter will be a reference, not just a basic parameter. So, you will write float& value for the first parameter.

Copying is not a big deal in most cases, unless the variable is really large, such as an video file, you don't want to waste the computational time and memory of going through it.

So, when the function is called, with arguments savings_balance and 10, the first argument, savings_balance, is passed by reference. In the function's memory, the parameter value just refers to the exact block of memory as savings_balance from the main function. The second argument, 10, is passed by value, so a new box of memory named percentage is created in the function's memory area, and 10 is copied into the first parameter.

The ability to not have to copy information needlessly is an advantage, so wouldn't you do that just by reference? Wouldn't you always pass by reference?

There are two reasons:

- 1. One is if you want to modify the parameter in your function but don't want it affected in the main function. You'd like the function to be disconnected from where it was called, so you don't need needlessly tie anything that could get tied. Passing by value is the right solution when you want your function to be as much of a black box as possible, because you need to make a copy of that data regardless.

- 2. The other reason for passing by value is a little subtle: if you pass by reference, the argument that you call needs to be a variable. It can't be a literal—because there's no box of memory to refer to. If you try to pass in a string literal, you will get a compiler error.

```
// Program 13_8
// Passing by Reference
#include<iostream>
using namespace std;

void increase_percentage(float& value, int percentage) {
    value += value * (percentage / 100.0);
}

int main() {
    float savings_balance = 1000.0;
    cout << savings_balance << endl;
    increase_percentage(savings_balance, 10);
    cout << savings_balance << endl;
}
```

Thus, when the variable named value in the function, you're actually modifying the box of memory as savings_balance in the main function. After the function returns, you'll find that the value in savings_balance has in fact changed.

To avoid frustration and failure, you should approach the process of debugging methodically, following 6 steps:

- - isolate the error,
- narrow in on the failure point,
- identify the problem,
- fix the problem,
- retest, and,
- consider similar cases where the error you've fixed might reappear elsewhere in your program.

## STEP 1: ISOLATE

The first step is to isolate an error. This involves writing good test cases, which helps make sure that the code is running as expected. You want to run tests until either cannot come up with any tests that give problems or find gives a repeatable error. It's important for the error to be repeatable; you want to make sure every time you run the program with that test, you get the same incorrect result.

> Debugging is a methodical process. It's not just a matter of randomly jumping through your code to find errors and make bugs disappear.
