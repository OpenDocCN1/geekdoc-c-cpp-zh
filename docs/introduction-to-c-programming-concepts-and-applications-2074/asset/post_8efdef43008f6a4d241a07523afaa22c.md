
## parameter
Values passed into function when called. Parameters are specified in the function header and behave like the function. Each parameter corresponds to one argument, and the corresponding argument provides the initial value of the parameter. (L12)

## polymorphism
Object-oriented programming technique for creating member functions that can operate differently for each subclass yet all be called in the same way. In this way, a superclass can take on many different shapes, depending on which subclass implementation is used. (L28) See inheritance.

## passing by reference
When a function is called, the parameter becomes a reference to the actual argument; no copying of values is performed. Changing the parameter value changes the value in the argument itself (L13). You have to give a variable argument, not a specific value—unless passing by constant reference, which can be a reference to a literal or a variable but does not allow any modification.

## preprocessor commands
Commands to be performed before code is compiled. Includes importing header files or defining values. (L4)

## print
To send output to the console or any other output device. (L1)

## passing by value
When a function is called, making a copy of the argument and setting the parameter to that value. (L13)

## priority queue
A data structure used to order items based on some priority. Items are pushed into the queue, and the highest-priority item can be popped from the front of the queue. (L23)

## pointer
A variable type that is not actually storing a value but, rather, the memory location where some value is stored. The pointer type or object being pointed to must be stored when the pointer is declared. Pointers must be dereferenced to access the values (or functions) in the actual variable or object. (L18) A pointer is similar to a reference, but pointers can change values (point to new memory locations) and be dereferenced. A pointer can treat anything in an inheritance hierarchy as an example of the base type.

## private member variable/function
A function or variable defined within a class or struct that is accessible only in that class and not in subclasses or outside the class. This is default for members of a class. (L16)

## procedural programming
A form of programming in which computation is divided into a number of functions (also called procedures), each of which is a small program of its own, performing a particular task. (L1) Contrast with object-oriented programming.

## protected member variable/function
A function or variable defined within a class or struct that is accessible in any class or subclasses not outside the class hierarchy. (L19)

## recursion
When a function calls itself. (L18, L24)

## pseudocode
A summary of the general steps that should be taken in a program or algorithm. Pseudocode is not code in a programming language, but a programmer can easily convert it to actual code. (L4)

## reference
A variable name that is used to refer to some other variable. A reference is a pointer that does not have to be explicitly dereferenced. References are most commonly seen when passing parameter values by reference, where a function's parameter names are used to refer to the actual variable specified in the argument. (L13)

## pseudorandom
Generating values that seem random, are actually being generated through some deterministic process. Often a (perishable) seed value is used to begin the pseudorandom generation process. (L6) Available via the <cstdlib> library in the C++ Standard Library.

## release mode
A compiler setting produces more-efficient code; debuggers cannot be used on code compiled in release mode. (L11) Contrast with debug mode.

## public member variable/function
A function or variable defined within a class or struct that is accessible anywhere, including commands outside the class. This is the default for members of a struct. (L16)

## return
A value that a function computes and is returned to the place the function call was made, replacing the function call in location. Each function has a return type, specifying the type of value that is returned. A function that simply performs actions without producing a value that needs to replace the function call does not need to return anything. Referred as "returning a value." (L12)

## pure virtual function
A virtual function that is not defined in the base. A class containing a pure virtual function is an abstract class and cannot be instantiated. Pure virtual functions must have an implementation in a subclass. (L28)

## scaffold
A portion of code used to test out a function. The scaffold does not need to be a complete program but just needs to set up variables and data so that a function can be called. (L15) Compare with stub function.

## queue
A data structure supporting first-in-first-out behavior. Items are pushed on the back of the queue and popped off the front. (L22)

## scope
The range of a program in which a variable is defined. Variables are said to be either "in scope" or "out of scope." (L5, L12)

## Standard Template Library (STL)
A library provided by default with C++ that contains several commonly used template data structures and algorithms. (L22, L23)

## sentinel value
An unusual value so far outside the range of expected values that its appearance can signal the program that it is time for a loop or other process to end. Sentinel values are used when a number of iterations is not known or there is another way to predict or otherwise test when input or data should end. (L5)

## static memory allocation
Memory that will be needed in a function or program at the time the program is written and is set aside in a part of memory known as stack. The memory is automatically allocated when a program run or a function is called. Contrast with dynamic memory allocation. (L18)

## separate compilation
Breaking a program into different parts (e.g., a header file and a source file), of which is compiled on its own. The program requires linking the separately compiled parts together. This is used to simplify individual files or to enable reuse of code, as in a library. (L15)

## static variable
A variable declared in a way that it persists (within a loop or function) beyond when it would otherwise fall out of scope. (L5)

## signature
The information needed for a function to be called. This includes not only the function name but also the number and types of parameters. Function signatures must be unique and how the compiler determines which function should be executed by the function call. (L13)

## stream
A source of input or a destination for output. Streams include the console, files, or strings. (L1, L10)

## stream operator
An operator that is used to direct input from a stream (>>) or output to a stream. (L1, L2, L10)

## stack
Memory holds all of the variables you declare and all those you pass as parameters. (L18) Contrast with heap.
A data structure that supports last-in-first-out behavior. Items are pushed on top of the stack and popped off the top. (L22)

## string
An ordered grouping or collection of characters—letters, numbers, punctuation, space, strings. Strings can be either specific values known as literals and specified within quotation marks, or variables of the string type, included in C++ via #include <string>. (L9)

## struct
A container, equivalent to a class, for packaging variables data. Developed in C, structs had only public member variables. In C++, structs are identical to classes, except the default is that all members are public. Short for structure. (L16)

## try-catch blocks
A set of programming commands used to handle exceptions. Code that should run but may have exceptions are contained in a try block, and one or more catch blocks are used to determine what happens for various types of exceptions. (L14)

## stub function
A short implementation of a function that does not correctly implement can be used for testing a larger program before the function has fully implemented. Stub functions can be called and return some value result so that code containing a function can be tested and debugged. (L15) Compare with scaffold.

## tuple
An associative data structure that allows multiple values of various types to be easily combined into a single structure. (L23)

## template
A C++ technique for implementing generic programming. Templates allow a general class, data structure, or function to be defined, where the specific type of an element of the data structure or a parameter of the function is determined when the variable is declared or the function is called. For example, a vector is a template data structure, and the specific type of a vector is determined when the vector is declared (vector<int> for vector of integers). (L8, L22, L23)

## type
The way that information in memory should be interpreted. Each value or variable in a program has a particular type. In C++, variables must be specified when they are declared and cannot change. Common types are int (integer), float (floating-point), bool (Boolean), and string, but a type can be any class. (L2)

## type casting (aka casting value)
Converting one variable into another. This can be done by specifying the new type in parentheses in front of the variable or by setting the new type and the value or variable to convert parents. (L5)

## test case
A specific set of input and expected output for a function, program, or portion of code. Test cases are used to check if code is working as expected and are an important part of debugging. (L4) Also see unit test.

## Unified Modeling Language (UML)
Developed in the 1990s and 2005 to aid the design of object-oriented software. UML uses a standardized set of notation and graphical indicators to describe class structures, their relationships, and a wide variety of program behavior. (L21)
