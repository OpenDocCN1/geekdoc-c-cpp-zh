Functions are a key part of programming. They enable you to organize your programs by breaking up ideas into individual pieces—the functions—and they can sometimes save a lot of repeated coding. You've already been using functions; you've imported functions from libraries and used functions to get input, for file operations, and with vectors. All of these functions performed some computation for you, all by just making a function call.

### // FUNCTIONS AS BLACK BOXES

The easiest to think of a function as a so-called black box. You have some program, consisting of various instructions. When you want something to happen, you make a function call. You possibly send from the function input parameters; these are the arguments, then the function takes action, and possibly returns a final return value sent back to part of the program that called the function. But the inner workings of the function—that is, knowing what the function does—are hidden from the main program.

On the other hand, when you write a function, you don't have to worry about how it is used. You might be getting some input parameters, and you might know you need to return some particular value. But you shouldn't need to worry about it at all how that function is called. You don't care about the function's role in the main program; you need to know that the function is going to do its job.

This brings you the 2 main reasons why you have functions:

+   Functions offer a conceptual separation of ideas. Functions let you write code without worrying about details. Either you're writing a function and not worrying about how it is called or you're writing the calling program and not worrying about how the function works.

+   Using functions lets you avoid the work of writing the same code over and again.

## # CREATING YOUR FUNCTIONS

Suppose you want to write a function that takes in a string and returns the number of words the string contains.

Then, there will be a pair of parentheses, inside of which will be the parameters (c). For now, you need to specify the type of the parameter being passed and give it a name. In this example, you are passing a string and are going to counting words in string, so the parameter is of type string and has the name `str_count`.

The first part of the definition of a function is the return type (a), which states what type of the return value will be. In this example, you're counting the number of words, you'll want to return an integer, so the type is `int`.

As you now writing your own functions, you'll again have values that are specified in parentheses, but now these values are called parameters.

The next part of the definition is the function (b)—the name you will use to call the function. You're writing a function that will count words, so `word_count` seems like a reasonable name for the function.

A part of function up to this point is called the function header (d), which contains the return type, name of the function, and the parentheses giving the parameter list. The function header contains all of the information needed for the block of function to interact with the larger program.

The parameters are directly tied to the arguments. The arguments that you put in parentheses when you call a function match one-to-one with the parameters you use inside the function itself. Because the arguments and parameters are linked together so closely, the terms are used interchangeably. But if you're being careful, arguments will be the values in the function call, and parameters will be the values that come inside the parentheses of the function.

Finally, there is a pair of braces, inside of which will be the actual instructions for the function (e). This is called the function body. These are the actual contents of the block-commands run whenever the function is called. (For initial code snippet, there are no specific commands for the function body.)

> When naming functions, you should take the same care as you do when naming variables. Use a descriptive, memorable, and consistent name.

![](img/bdf1aaea7e08f6cbf15b0a740771ecdc_137_0.png)

Sending in parameters is called passing. When you transfer a value from the calling side to the function, you say that you are "passing in" a parameter.

You've used functions that take one parameter, more than one parameter, and even no parameters. You can specify each situation—one parameter, multiple parameters, or no parameters—in function header. You have already defined a function, word_count, that takes a single parameter, a string.

If you have multiple parameters, you just separate the parameters with commas. Each of the parameters is defined the same way an individual parameter would be. But note that each parameter needs both a type and a name.

To define a function that has no parameters, you put nothing between the parentheses.

Sometimes you don't need a function to return anything; it just to do something on its own and not return a type of any sort. In this case, you can specify a different return type, called void.

When a program is compiled, the function definition should occur in the program before the function is actually called. Typically, functions are defined near the beginning of the file. You write the function definitions, and later you can make calls to that function. When the compiler comes along and encounters it sees a function name, with some arguments of various types, and it matches up to the function with that name and parameters.

Actually, it's slightly more complicated; all the compiler needs to know at first is the function header. In fact, there are ways you can give just the function header information and put the body of the function elsewhere. You'll learn more about this in lecture 15.

### // THE FUNCTION BODY

The body of the function is the set of instructions that you want to follow when the function is called. When you see a function call, you can think of it almost as if the commands in the body of the function definition are being stuck into the code right.

Within the body of the function, you can declare variables, just like you would in the main program. And you can use this variable just like you would a variable in the main program.

Suppose you're going to write a tic-tac-toe program and one thing you want to be able to print help for someone who doesn't know the rules.

Each of the parameters also becomes a variable of the function's memory. The name in the function is the name that used for the parameter, and the variable is initialized with whatever value was given as an argument.

In this case, you can define a function called print_help to print information. The function doesn't need any parameters, and it doesn't need to return anything. So, the function header will be void print_help(6).

To return a value from a function, the command is return and then the value being returned.

As soon as the function encounters the statement return, the function ends, and returns that value to the main program.

Then, you can define the body of the function. Inside of the braces, you will have a set of cout statements to output the help information (f). You could put all them in one cout, or in even more cout statements, if you wanted to.

The return command will run as soon as it's encountered. So, if you have multiple lines of code and encounter a return statement before you've executed all of them, then you just miss some lines.

Then, in the main program, you can make a call to the function by just writing print_help(18). When this happens, the text you had in the cout is printed.

Also, if a function has a return type, then you just write return—no need for a value to be returned.

Or you can just leave the return statement if the return type is void; the function automatically returns at the end.

```
int main() {
print_help();
}
```
