# The static_cast Operator

This type of cast is the simplest type. Typically, the static_cast operator is used to cast one type to another related type. For example, one pointer to another in a class hierarchy or a numeric type (e.g., integer) to another (e.g., float). It has the same syntax as the others:

```cpp
static_cast<type_name>(expression);
```

The type of the expression will be converted to the type_name. The operator can be used to convert pointers to related classes, such as from a derived class to a base class pointer (upcast) and the opposite, that is, convert a base pointer to a derived pointer (downcast). For example:

```cpp
class A {...};
class B : public A {...};

A *a1 = new A;
B *b1 = static_cast<B*> (a1); // Not safe.
B *b2 = new B;
A *a2 = static_cast<A*> (b2); // Safe.
```

Let's not use the unsafe cast. As we know, when an object is not B, the downcast is not safe. However static_cast does not fail, so the programmer is not informed about this risky situation. Recall that in case of dynamic_cast, the value of b1 would be the null pointer. Therefore dynamic_cast adds an overhead due to runtime checks, whereas static_cast does not since it is applied at compile time, the use of dynamic_cast is safer because the runtime checks protects us from unsafe casts like this one.

# The reinterpret_cast Operator

The reinterpret_cast operator is typically used to perform casts to unrelated types. It has the same syntax as other operators:

```cpp
reinterpret_cast<type_name>(expression);
```

It can be used to cast any pointer type to any other type. It also allows the conversion of an integer to any pointer and vice versa. For example:

```cpp
int *p = reinterpret_cast<int*>(0);
```

In the traditional way, this conversion is done as follows:

```cpp
int *p = (int*)0;
```

In general, conversions made with this operator are potentially unsafe and should be avoided. That is, it allows you to convert a float to string*, this can lead to dangerous situations. It is the responsibility of the programmer to ensure that the conversion will not cause problems. For example, dereferencing that pointer may cause a crash. Similarly, it is not safe to convert a pointer to another unrelated class and then use that pointer. But, if for some reason you decide to make such a conversion it would be preferable to use the reinterpret_cast operator and not the traditional way, so that you can quickly identify these dangerous casts.

# SMART POINTERS

A smart pointer is an object that facilitates the management of dynamically allocated memory. It behaves like an ordinary pointer with the difference that it can release the memory that it manages by itself. Thus we don't have to worry about forget to release the allocated memory and creating memory leaks. The memory will be released automatically when no longer needed. For example, with ordinary pointers the following code may create a memory leak:

```cpp
void f() {
    int *p = new int[10000];
    ...
}
```

If an error occurs, the exception will be created and let's add delete and release the memory before each return statement which might exist in other part of the code or in catch blocks that handle exceptions. Believe it is not so hard to "remember" to release the memory, even worse instead of delete[], is there a way to ensure so? Yes, by using smart pointers. If the pointer had a destructor, the destructor could release the memory when the object was destroyed. This is the idea behind smart pointers; to use an object to prevent memory leaks. The definitions of the classes are included in the memory file. C++11 introduces unique_ptr, shared_ptr, and weak_ptr types. We'll describe them in brief.

# The unique_ptr Type

C++98 supported auto_ptr. C++11 deprecated its use and introduced the unique_ptr type. Let's see an example:

```cpp

#include <exception>
#include <memory>
using namespace std;

class C {
public:
    double v;
    ~C() {cout << "End\n";}
};

double f(double a, int b);
int main() {
    double i;
    int j;

    cout << "Enter two numbers: ";
    cin >> i >> j;
    try {
        cout << f(i, j) << '\n';
    } catch (exception& e) {
        cout << e.what() << '\n';
        return 0;
    }
}
double f(double a, int b) {
    unique_ptr<C> p(new C);
    // Alternatively, unique_ptr<C> p(make_unique<C>());
    if(b == 0)
        throw exception();
    p->v = a/b;
    return (*p).v;
}
```

To create a unique_ptr object we use the usual template syntax. As we say, smart pointers are templates. When we put the type that smart pointers point to <>. When we create a smart pointer we can initialize it with the pointer that the new operator returns. If b is 0, f() creates an exception. The unique_ptr overloads the * and -> operators, so that we can use it as an ordinary pointer. Notice that there is no need to delete memory. The allocated memory is released when the pointer is destroyed. This happens when p goes out of scope, in the function is returned, either due to an exception or not. Then, p is destroyed and its memory will be released if there is a forced exit from the block. Then, p is destroyed and its destructor will release the memory. Then C is called and the program ends in both cases, whether the exception is thrown or not.

C++14 introduced the std::make_unique<>() function template to create a unique_ptr object. In this, it is recommended to use this operator. The arguments of the make_unique<T>(...) are the same as the ones used in the new T(...) form. To make the syntax simpler we can use the auto identifier. For example:

```cpp
auto p(make_unique<C>());
```
