As another example of the default constructor, consider the following class:

```cpp
class A
private:
    int x, v;
public:
    A(int i, int j = 0);
    ...
};
```

See now which declarations are accepted:

```cpp
A a; // there is no default constructor.
A a(1, 2); // OK.
A a(1); // the default value of j is used.
```

The default constructor can also be useful when a member of the class is object. For example:

```cpp
class C // Example 17.7
public:

public:
    C() {};
    C(int m) {p = m};
    ...
};
```

```cpp
class B
public:
    C c;
    ...
};
```

```cpp
int main()
{
    B b;
    ...
};
```

For the construction of the b object the default constructor of class B is called and for the construction of the c object the default constructor of class C is called. If it was missing, the compiler would display an error message, as it could not construct the c object.

Note that we can also use the C++11 syntax to initialize a member that is object. For example, let's change the declaration of the c object:

```cpp
class B
{
public:
    C c{10}; /* We can also write C c = {10}; Notice that it is not allowed to use parentheses, that is, it is illegal to write C c(10). */
    ...
};
```

To create the c second constructor will be called, the value 10 is passed, so the value of b.c.p becomes 10.
C++11 supports the assignment of value to the members of a class. For example:

A a; // x is 10 and a v is 20.
A a(1); // a x is 1 and a v is 20.
A a(1, 2); // a x is 1 and a v is 2.

When the default constructor is used to create an object of class A, its members are initialized to the specified values, that is, 10 and 20.

## Non-Public Constructors

In the question, a constructor can be private, the answer is yes. For example, we can have many public constructors, which all call a private constructor that undertakes to create the object. We will see that technique with the delegating constructor in Chapter 19. One reason to use a private constructor is when we don't want to expose it to the outside world.

In the similar, a constructor can be protected, the answer is again yes. For example, in inheritance, a constructor can be declared protected in the base class to prevent the direct creation of base objects and only derived classes to use it. For example, as we'll see in Chapter 20, we can write:

A a; // Error.
A b; // OK.

## Default Functions

Until now, we've learned the functions that the compiler provides by default for a class T:

- a. The default constructor: T().
- b. The default copy assignment operator, which is a function declared as: T& operator=(const T&). For example, we'll see in Chapter 18, when we write t1 = t2; operator= function is called, which copies the values of the non-static members of t2 to t1. If the member is an array, its elements are copied. The function returns a reference to the left operand.
- c. The default destructor: ~T().

These are the functions that the compiler will generate for you and by default, unless you've defined your own versions. Notice in Chapter 19 there are some special cases where the compiler does not create the default functions. The general rule is that if a class has a member by definition cannot be constructed, copied, or destroyed, then the compiler deletes it, as we'll see in Chapter 19, the corresponding default function. For example, if the class contains a reference or const member, the compiler does not generate the copy assignment operator. See the following code and read the comments:

```cpp
class T
{
    const int r;
    T(int i) : r(i) {} /* r becomes equal to i. We'll see this syntax in */
};
```

```cpp
t1(10), t2(20); // Compilation error, because the copy assignment operator is deleted. If you want to make the copy, you'll need to define your own copy function, as you'll learn in Ch.18. */
```

It makes sense for the compiler to delete the copy function, since it is not allowed to change a const variable. Let's have a short test, find the errors in the following program:

Just to remind, when we use the new operator to allocate memory we use the delete operator and we use the delete[] operator to release it. In general, if a class allocates resources (e.g., memory), most likely need to define a destructor to release them.

> If you allocate memory in the constructor or elsewhere in the implementation of the class do not forget to release it. Typically, the destructor is the best place to do that.

A good programming technique is to try to allocate memory, and in general any kind of resources you need, in the constructor and release in the destructor all the resources that are owned by the object. It is easier to control and maintain the program. This technique is typically referred to as Resource Acquisition Is Initialization (RAII).
