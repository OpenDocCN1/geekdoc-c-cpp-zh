# Handling Uncaught Exceptions

As we've seen, an uncaught exception causes, by default, the program to terminate. For example, this can happen if no matching catch block is found for an exception or if the function that created the exception is not contained in a try block. If an exception is uncaught, the terminate() library function is called, which calls abort() and then terminates the program. The standard allows us to change the behaviour of terminate() and call it another instead of abort(). To do that, we need to use the set_terminate() function. The terminate() and set_terminate() functions are declared in the exception file. The declaration of the set_terminate() looks like:

```
typedef void (*terminate_handler)();
terinate_handler set_terminate(terminate_handler p);
```

That is, the set_terminate() takes as parameter a pointer to a function that has no parameters and its return type is void. In general, it is not recommended to override the behaviour of terminate() unless you want to do a "last" before the program exits, such as to output some diagnostic messages to help you solve the problem or return a specific error code to the environment. Notice that the registered function after performing any desired tasks should terminate the program. If it does not and returns to the caller, the behaviour of the program is undefined.

You may wonder the new terminate function terminate the program? Remember, set_terminate() is designed to handle irreversible errors. If there is no code to handle these errors, the program is not supposed to resume its normal operation. Unfortunately, it is in some unexpected, erroneous state, which affects badly its operation. Therefore, the only option is to terminate its exception. The following program registers a new terminate function, which in case of an uncaught exception, writes a message and calls abort().
