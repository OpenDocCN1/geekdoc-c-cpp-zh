Notice that in an overloaded function the type of at least one operand must be a user defined, such as a class. You cannot define an overloaded function where all operands are basic types. For example, you cannot define an overloaded function of the == operator with two arguments char* or int.

In the previous program, an overloaded function of the > operator that takes a parameter Rect (e, r) and returns true if the area of the calling function is greater than the r, false otherwise. Use the area() function to calculate the area. Modify main() to test the operation of the function.

```cpp
bool Rect::operator>(const Rect& r) /* The declaration is added in the class. */
{
    if(area() > r.area())
        return true;
    else
        return false;
}
```

```cpp
int main()
{
    Rect r1(10, 20), r2(30, 40);

    if(r1 > r2)
        std::cout << "Bigger\n";
    else
        std::cout << "Not bigger\n";
    return 0;
}
```

The expression r1 > r2 is translated to r1.operator>(r2), so the function operator> of r1 is called with argument r2. That is, strange as it may see, the expression r1+r2 or r1 > r2 do not perform the math operations, but calling the operator functions. Because the function returns false the program displays Not bigger.

Let's now look at the case of copying objects that contain pointer(s). Pay close attention, what is wrong with the following program?

```cpp
#include <cstring>
```

```cpp
public:
```

```cpp
T::~T()
```

```cpp
int main()

    T t1("Peter"), t2("Mike");
    t2 = t1;
    t2.show();
    return 0;
}
```

The statement t2 = t1; causes a problem in the operation of the program. Let's see why. The copy operation makes t2.s pointer to point to the same memory as the t1.s. The memory reserved for t2.s is not released. When the program terminates the destructor of t2 is called, it releases the memory t2.s points to. Since the t2.s and t1 point to the same memory, the destructor of t1 attempts to release that memory once more. As we know, the effect of deleting an already released memory is undefined (e.g., it may cause the program to crash).

In such a case the ability of overloading operators proves to be particularly useful. Specifically, to avoid dangerous situations we overload the = operator in order to define how the copy will be performed. For example:

```cpp
class T
{
public:
    ...
    T& operator=(const T& t);
};
```

```cpp
T& T::operator=(const T& t)
{
    /* Something is missing. */
    delete[] s;
    s = new char[strlen(t.s)+1];
    strcpy(s, t.s);
    return *this;
}
```

```cpp
t1 = t1; // Now, the code won't work.
```

When the function is called, the common memory pointed to s and t.s will be released, so it'd be wrong to use t.s to re-allocate new memory and copy something that no longer exists. How can we fix this problem? Before answering, someone might ask, what is the point of making an assignment in the first place? Yes you right, this self-assignment does not make sense, but in their copy could be two pointers (e.g., *p1 = *p2) that you have no clue if they point to the same object. The traditional way is to check for self-assignment before releasing the memory:

```cpp
T& T::operator=(const T& t)
{
  if(this == &t) // We check for self-assignment (e.g., t1 = t1).
    return *this;
}
```

> Don't forget to test for self-assignment when overloading the copy assignment operator. If you forget to that, fatal errors may occur if an object is accidentally assigned to itself.

The if condition compares the address of the invoking object to check if the referenced object is itself. If the addresses are the same, could it not be just void? Yes, it could, but then, why could we not use += in expressions, as t1 = t2; is translated to t1.operator=(t2); Because = operator has right-to-left associativity, this statement is translated to: t1.operator(operator=(t3)); When t2.operator=(t3) is called, the memory pointed to s and t.s will be released, so memory is reserved for t2.s and the string pointed by t3.s is copied to it. The function returns the reference to t2, which becomes the next. Thus, t1.operator=(t2) is now called. Similarly, t2.s is copied to t1.s. Okay, you might find difficult to understand the above, we'll analyze a similar expression in the next (e.g. r1 = r2); and you will get it. If you do not want to support chained assignments, you declare void and you are done. The usual practice is to return a reference in order to support them. Another question, will be a problem if instead of the reference to the object we pass the object itself? That is, to write:

```cpp
class T
{
  void operator=(T);
};
```

Of course there will be a problem. As we said, the statement t2 = t1; is translated to t2.operator=(t1); Since t1 is passed by value, t is a copy of t1. That is, the values of the members are copied to the members of t. But, when the function terminates, the destructor of t will release memory. Memory, the program will not work properly. So we see more when passing references does not only save time and memory but also avoid dangerous situations. Since C++11, if we do not want to define another copy function we can disable the default copy using delete syntax. For example:

```cpp
class T {
  ...
  T& operator=(const T&) = delete;
}
```

Now we are not allowed to write t2 = t1; it causes a compilation error. We'll see delete syntax again in Chapter 19.

## OVERLOADING RESTRICTIONS

Most operators can be overloaded in the way as previous examples. Actually, as we see below, overloaded operators, with some exceptions, do not have to be member functions. However, there are some restrictions in use:

- At least one operand of the operator must be a defined type. This rule prevents operator overloading for base types. For example, you cannot overload the + operator to return the difference of the two integers instead of their sum.
- You are not allowed to change the syntax of the operator. For example, you are not allowed to use the addition operator with just one operand. Similarly, you cannot change the behaviour of ++ from unary to binary.
- Specifically for the operators && we know from Chapter 4 that the second operand is not always evaluated due to short-circuit evaluation. This rule does not apply when overloaded, they are treated as binary operators and both operands evaluated. In fact, they are the arguments of the && (or ||) overloaded function they are evaluated when the function is called. Because with regular function evaluation the programmers would expect is not valid anymore, it is better to avoid overloading the precedence and associativity of the operator. For example, in an expression a*b+c where a, b, and c are objects and the operators * and + are overloaded, the multiplication is performed first and then the addition.
- You are not allowed to create new symbols and overload them. For example, you are not allowed to declare the operator to define exponentiation, where the operator does not exist.
- You are not allowed to overload the following operators:

```
. :: sizeof alignas noexcept
```
- Most operators can be overloaded either by member or non-member functions. However, the following operators can only be overloaded with non-static member functions:

```
= () [] ->
```
- Without being a constraint, when an operator is overloaded it is useful for the better understanding and control of the program to perform a function similar to its original purpose. For example, when the + operator is overloaded it'd better to perform the addition and not some other operation. In the same sense, you should not overload the add operator. It is strange and confusing to use it in a different way than the usual one. In general, unconventional use of operators can be a significant distraction and potential source of errors. Also, if the use of an overloaded operator is not obvious, it's better to use a function instead, as the function's name indicates its purpose and makes the program easier to read. For example, it'd better to declare a function with an explanatory name, such as swap(), to swap the dimensions of a Rect rather than overload the operator for that. In general, when an operator is overloaded it should be easy to apply, simplify the programming tasks, and generate comprehensible code.

## OVERLOADING EXAMPLES OF UNARY OPERATORS

We've seen some examples of overloading binary operators, let's see some examples of overloading unary operators, that is, operators that accept one operand. Let's overload the ~ operator to swap the dimensions of the object calling:

```cpp
void Rect::operator~() // The declaration is added in the class.
{
    int tmp;

    tmp = length;
    length = height;
    height = tmp;
}
```

To test its operation, we write in main():

```cpp
int main()
{
    Rect r(10, 20);

    ~r; // Equivalent to r.operator~();
    r.show(); // The program displays 20 and 10.
    return 0;
}
```

Note that you are free to choose the return value according to your needs. Here is just an example that uses void. For example, when overloading a unary operator it is very common to return a reference to the respect object. Let's change the code:

```cpp
Rect& Rect::operator~()
{
    ...
    return *this;
}
```
