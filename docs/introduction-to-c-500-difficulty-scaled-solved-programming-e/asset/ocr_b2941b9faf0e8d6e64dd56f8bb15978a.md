# The stack template class

The stack class implements a LIFO (Last In First Out) stack, where elements are inserted and extracted from only one end of the container. The implementation supports the basic functionality of a stack, we can add an element at the top of the stack, remove the element from the top, find the value of the element at the top, check if the stack is empty, and find the number of the stored elements. Random access to its elements is not supported nor we traverse the stack. To use the stack we must include the stack header file. Let's look at an example:

```
#include <iostream> // Example 26.11
#include <stack>
int main() {
    std::stack<int> s;
    s.push(10);
    s.push(20);
    s.push(30);
    std::cout << "Top: " << s.top();
    s.pop();
    std::cout << "Size: " << s.size();
    return 0;
}
```

push() adds the element to the top of the stack. top() returns the value of the top element, pop() removes the element and size() returns the number of the elements in the stack. Therefore, the program displays: Top: 30 Size: 2

# Associative Containers

Associative containers associate each element with a key and use the key to find the element in the container. That is, associative containers are designed to find and access its elements by their position. For example sequence containers suppose that each element is a structure which represents a student with members such as name, code, grade, address, contact information, and on. The key can be the student's code which is unique. The container uses a key to store and locate each element. When we add elements we cannot specify the position in where they will be inserted, because the container applies an algorithm to determine the insert position. The usual of implementing an associative container is in the form of a binary tree. The container provides fast access to its elements.

STL provides the set, multiset, map and multimap containers, which store the elements in order. The first two are defined in the set file and the other in the map file. In the set container each element is identical to its key and while the multiset container may contain elements with the same key. In the map container the key of each element is associated with mapped data. Each key is unique, the unordered_set, unordered_multiset, unordered_map, and unordered_multimap containers, which do not store its elements in order. These are useful in applications where the elements do not need to be stored in some order. Let's look at two examples with the set and map containers.
