As we have described, with the creation of the bc object the t member of the B sub-object becomes 10 and the v member of the C sub-object becomes 11. Because A is virtual, the A constructor that will be the default constructor. Then, the r member of the single A sub-object becomes 30. Finally, the program displays:

```
Def_A()    B()    C()    BC()
B:10      A:30   C:11   A:30   BC:20
~BC()     ~C()   ~B()   ~A()
```

But if we do not want the default constructor of the virtual class to be called and we want to specify some other then we call it directly. For example:
BC(int x) : A(x+5), B(x), C(x+1), z(2*x) {cout << BC();};

As we learned in Chapter 20, the constructors that are allowed to be included in an initialization are list constructors of the immediately preceding base class. Therefore, we would expect that the calls to the B and C constructors are allowed, but not that of A. The exception is that if a class derives directly from a virtual base class, its constructor can be called directly. If A was not virtual, the compiler will issue an error message. So, if we write the BC constructor like this, the program will display:

```
A()       B()    C()    BC()
B:10      A:15   C:11   A:15   BC:20
~BC()     ~C()   ~B()   ~A()
```

> If a class derives directly from a virtual base class, its constructor is allowed to call directly the constructor of the virtual base class. Otherwise, the default constructor will be called, if it does not exist. Then a compilation error will occur.

To summarize, when we use multiple inheritance, and different paths lead to the creation of multiple subobjects of a base class, we should ask ourselves if it has multiple copies of the same members. If it does not bother us, we do nothing. Otherwise, we need to make the base class virtual. In this case, the construction of the single base sub-object is undertaken by the constructor of the most distant derived class. In general, be aware that using virtual classes is more complex and time consuming for the compiler, so if you can, it would be better to avoid it.
