# NAMESPACES

We've discussed about the scope of program elements such as variables and functions. For example, we know that we can use the same name for local variables of different functions. What about names with global scope? Elements that are declared with a global scope, such as global variables, we say that they belong in the global namespace. In large programs, where the code is split in many files written by different programmers, the probability of name conflict increases. For example, we may have defined a class Queue in the queue.h file and the same name is used in one of the libraries we use (e.g., in the game.h file):

```
#include "queue.h"
#include "game.h"
```

The compilation will fail due to the multiple definition of the Queue class. Class of, if we change the name of our class (e.g., to My_Queue) the problem is fixed. However, in the case of using libraries by others and the same names are chosen, we cannot change them. To avoid such conflicts, C++ provides an elegant mechanism with the use of namespaces.

A namespace is a region with its own scope in which we can put the entities of our program (e.g., classes, functions, ...) Namespaces allow us to organize the entities of our program into logical groups and prevent collisions with names declared outside of it. For example, we can create the Network namespace and put classes related to network protocols and devices within it. In large applications, where many namespaces are typically used, their become more valuable, because splitting the program into different logical scopes referred to by names (e.g., graphics, library for web services, prevents name collisions and facilitates its management, comprehension, and maintenance.
