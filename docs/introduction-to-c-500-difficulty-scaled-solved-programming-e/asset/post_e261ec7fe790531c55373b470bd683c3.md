
## const Objects

An object can be declared const. For example, consider the following program:

```cpp
#include <iostream> // Example 17.3

class Student
{
private:
    int code;
    mutable float grd;
public:
    Student(int c) {code = c};
    int courses;
    int get_code() {return code;}
    void set_grd(float g) const { grd = g;}
    void show() const {std::cout << grd << '\n';}
};

int main()
{
    const Student s(100);

    // s.get_code(); Wrong. The function must be declared const.
    /* s.courses = 10; Wrong. Assignment is not allowed, the member is read-only. */
    s.set_grd(5); // OK.
    s.show(); // OK.
    return 0;
}
```

`s` is a const object, which means it is not allowed to change the members of `s`. That is, all member variables of `s` become const variables. Therefore, they don't permit any change in the values of members. Calling a non-const function causes a compilation error. If we want to change the value of a member we must use the `mutable`.

As you can see, `set_grd()` is declared as const, it can change the value of `grd`. Note that if `show()` was not declared const the compiler would display an error due to calling a const function. If you wonder whether the constructor can change the value of the `code`, the answer is that the object actually becomes const once the constructor completes its construction. Thus, a constructor, which we'll discuss about shortly, is allowed to set values in the members of a const object.

> Objects that are const, as well as references or pointers to const objects can only call const members.

## Friend Functions

As we've learned, a member function can access private members of a class. There is a way for a non-member function to have access to private members? Yes, provided that it is declared as a friend to the class. In short, a friend is a non-member function that can access the members of a class regardless of the point of their declaration. That is, a friend has the same access rights as a member function of the class. To make a function friend it must be declared in the class with the prefix `friend`. The place does not matter, it can be declared in the private, protected, or public section; the section does not affect its accessibility. But do not forget that, although it is declared in the class, it is not a member of the class.

When defined, it is not a member of the class, the scope resolution operator `::` and the class name are not added. When it comes to declare friend functions, it is a common practice to group them at the beginning or end of the class (I prefer it to stand out). Let's look at the following program:

```cpp
#include <iostream> // Example 17.4

class T
{
private:
    int a;
public:
    void show() { std::cout << a << '\n'; }
    friend void f(T& t);
};

void f(T& t) // The friend keyword is not added in the definition.
{
    t.a = 10; // It is not an error to write t.a = 10;
}

int main()
{
    T t;
    f(t);
    t.show();
    return 0;
}
```

Since a friend function is not a member of the class `t` and we don't add the `T::` in the definition of `f()`, we access private members of `T`. For the same reason, `f()` is not a member of `T` and the compiler would display an error message similar to `not a member of T` members by just using their names. Notice that the friend keyword is added to the definition, unless it is defined inside the class. As we said, that friend allows access to access its private member function. Thus, it is allowed to access the private member and the program displays 10.

A friend function can be a global function in this example or it can be a member of another class. One may ask, is it necessary to declare `f()` as friend, we can't declare it an ordinary function outside the class? Or we can, but since `a` is private it is not allowed to access it. So, we need to add a public function to the class, when called to change the value of `a`. For example:

```cpp
class T
{
public:
    void set(int i) {a = i};
};

void f(T& t)
{
    t.set(10);
}
```

To avoid this detour, it is more convenient and simple to make `f()` friend. Yes, it is simpler, but why not making `f()` a member of the class at the first place? Yes, we could.

```cpp
#include <iostream>
class A
{
private:

    template <typename T>
    A(T val) {p = val};

int main()
{

    return 0;
}
```

## CONSTRUCTORS AND DESTRUCTORS

The constructor is a special function of the class, which is called when an object is created. In particular, it must have the same name as the class, it has no return type, and it can be overloaded.

## Constructor

The constructor is a special function of the class, which is called when an object is created. In particular, it must have the same name as the class, it has no return type, and it can be overloaded. Typically, a constructor is used to assign initial values to the members. For example:

```cpp
class T
{
private:
    string name;
    int age;
public:
    T(string n, int a) : name(n), age(a) {}
};
```

## Destructor

A class may contain another special function, which is called destructor. The destructor is called automatically when an object of this class is destroyed (e.g., when it goes out of scope) to deal with any cleanup that may be necessary.
