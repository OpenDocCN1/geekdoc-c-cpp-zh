And if we want to call the show() of the base class from the derived class could we do that? Yes, we just use the scope operator with the name of the base class. For example:

```cpp
void Book::show() {
    cout << "T:" << title << " A:" << auth << '\n';
    Product::show(); /* Pay attention, if we only write show() an infinite recursion will be created. */
}
```

As the comment says, if we write Product::show() the compiler assumes that the show() of the Book class is called, resulting in the creation of an endless recursion. The scope operator also be applied when the object is used to call the function. For example:

```cpp
Book b("B", 2, "Nice", "Many");
b.show(); // The Book::show() is called.
b.Product::show(); // The Product::show() is called.
```

Fine, that's clear when an object is used to call the function. But what happens when a pointer is used to call the function? For example:

```cpp
Book b("B", 2, "Nice", "Many");
Product *p = &b;
p->show(); // Which show() will be called, that of Product or Book?
```

I will answer briefly now, however, I'll make the same question later on when we discuss virtual functions. Because the type of the pointer is Product*, although it points to a Book object, the show() will be called is that of the Product class.

# Function Redefinition with Different Signature

Let's now examine the case where the base class function is declared differently in the derived class. For example:

```cpp

class A {
public:
    void show() const { std::cout << "A\n"; }
};

class B : public A {
public:
    void show(int k) const { std::cout << k << '\n'; }
};
```

Redefining a function hides the declarations of all base-class functions of the same name, regardless of the function signatures.

Redefining a function in a derived class is not a function overloading.

As explained in the previous section, it is not a function overloading overloaded functions must be defined within the same scope, while the derived class defines a separate scope. Thus, the declaration of show() in class B we do not have two overloaded versions of show(), but this declaration hides the respective declaration in base A. In particular, with the statement the compilers search for the name in show B. Once it finds, it stops searching. Then, because an argument must be passed to show(), the compilation fails. I write it again, the important thing to understand is that the compiler stops searching, not keep looking for another version of the show() in the classes of B that matches the call. Similarly, the declaration of show() in the derived class C hides the respective declarations in classes A and B. Therefore, the compiler displays two error messages. As, to call the show() of a base class we must use the scope operator and the class name. A::B::show(10); What if we want to have overloaded versions of a base class function in a derived class? Could we do that? Yes, using declarations. Specifically we use the using keyword and the name of the function. The using declaration introduces the function into the scope of the derived class, so the versions are available within the derived class. The compiler checks the signatures to distinguish them. For example:

```cpp
class C : public B
{
public:
    using B::show;
    void show(const char *s) const { std::cout << s << '\n'; }
};
```

```cpp
int main()
{
    C c;
    c.show("Test"); // The C::show() is called.
    c.show(10); // The B::show() is called.
    c.show(); // The A::show() is called.
    return 0;
}
```

Now, the program is compiled successfully. In particular, we have three overloaded versions of show() in the scope of C. The compiler checks the argument and selects the appropriate version. Thus, the program displays Test, 10, and A. Note that the using declaration adds all the functions with the same name. For example, if the class A contains the overloaded version int show(int a, int b) {...}, the using declaration adds it as well.

Product p("A", 1);

In the case of ptr2->show(), you'd probably answer that since ptr2 points to b, the show() of the Book class will be called. No, the compiler checks the type of pointer and decides accordingly. Thus, since ptr2 is a pointer to the Product class the show() of that class is called. As you see, the decision of which function to execute is made when the program is compiled, and this decision won't change. This method is called static binding. The term early binding is also used. Essentially, the function name is associated with the memory address of the code that will be executed each time the function is called. The same applies for references, that the compiler uses static binding to select the respective show(). With pointers, the selection is based on the type of the reference, not on the type of the object being referenced. Therefore, the code displays:

```cpp
C:A P:1;
C:B P:2;
C:B P:2;
```

Let's discuss now virtual functions and one of the most important features of C++, the dynamic or runtime polymorphism. If we declare show() as virtual in the base class, the results are different. To declare it as virtual we use the keyword virtual. For example:

```cpp
class Product
{
    virtual void show() const;
};

class Book : public Product
{
    virtual void show() const;
};
```

In order for the virtual mechanism to work, the function of the derived class must override the function of the base class. When a function in a derived class redefines a function of the base class with the same signature, it is called overriding. Regarding the type, in general, the return type of the derived class should be the same as that of the base class. Strictly speaking, and without getting into details, it should be covariant with the classes of the function. If the return types are not, the derived class won't compile.

Notice that the signatures do not match exactly, the derived class does not override the function of the base class, but it is a new function which hides one of the base, as we saw in the previous section.
