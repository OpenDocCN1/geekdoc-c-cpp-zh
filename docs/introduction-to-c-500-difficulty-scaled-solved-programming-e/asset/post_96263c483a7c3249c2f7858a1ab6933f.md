```cpp
void test ()
{
    static int i = 100, arr[1];
    int j = 0;

    i++;
    arr[0] += 2;
    j++;
    std::cout << i << ' ' << arr[0] << ' ' << j << '\n';
}
```

When test() is called, i becomes 101. Since i is declared as static, it retains its value and the next call of test() makes it 102. Similarly, the third call makes it 103. Since the elements of a static array are initialized to 0 by default, arr[0] becomes 2, 4, and 6, respectively. On the other hand, j is an automatic variable, it does not retain its value between test() calls. Therefore, the program outputs:

```
101 2 1
102 4 1
103 6 1
```

The linkage of a global variable or function is external by default, that is, it may be shared in different files. However, if it is declared as static, the linkage changes to internal, which means that it is visible only within the file in which is defined. For example:

```cpp
#include <iostream>
using namespace std;

static void test(int i);
static int flag;

int main() {
  ...
}

static void test(int i) {
}
```

flag and test() are visible only within this file, which means they cannot be accessed by functions in other files. In particular, flag has file scope, static storage duration, but internal linkage. The main reason of declaring them as static is from other files, preventing it from being used as extern when it is not desired. In a large program split in several files, typically written by different programmers, it is a good idea to declare your functions as static. Besides hiding information, another reason is if the code of a static function should be modified later, you won't worry if those changes affect functions in other files (with the exception that the pointer to function is passed to a function of another file). Also, you don't have to worry if the names you choose are used in other files as well, if it happens, there will be no conflict. Since the linkage is internal, the same names can be reused in other files. Another way to define names with internal linkage, and this is what is recommended, is by using unused namespaces, as we'll see in Chapter 25. However, since static is used quite extensively in existing code it is good to know how it is used.

Let's see one example that combines these concepts. Consider the following program which consists of two source files. Both must be compiled and linked to produce the final executable. Can you tell what it displays?

```cpp
// First file.
#include <iostream> // Example 11.19

void test();
int ext = 10;
static int st = 20;

int main() {
  test();
  std::cout << ext << ' ' << st << '\n';
  return 0;
}
```

```cpp
// Second file.
#include <iostream>

extern int ext;
static int st;
```

# ONE-DIMENSIONAL ARRAY AS ARGUMENT

```cpp
void test()
{
  st++;
  std::cout << ext << ' ' << st << '\n';
  ext = 30;
}
```

Since the st is declared in the first file as static it does not conflict with the st in the second file (regardless of whether this st is declared static or not). Note that the test() is defined in the second file. Since, it is initialized to 0 by default, test() displays 10 and 1. Since test() changes the value of ext to 30, main() displays 30 and 20.

When a parameter of a function is a one-dimensional array, we write the name of the array followed by a of brackets. The length of the array can be omitted; in fact, this is the common practice. I'll explain later. For example:

```cpp
void test(int arr[]);
```

When passing an array to a function, we write only its name, without brackets. For example:

```cpp
test(arr);
```

> When the name of an array is passed to a function, it is always treated as a pointer. We often say that the name "decays" to a pointer. In effect, the passing argument is the memory address of its first element, not a copy of the array itself. Since no copy of the array is made, the time required to pass an array to a function does not depend on the size of the array.

So remember, when an ordinary variable is passed to a function, the function works with a copy of it. But if an array is passed, no copy is made; the function works with the original array. Why is that decision choice? For better performance, to save memory and time that otherwise would be required to copy all the elements. It just pointer to its first element is passed and the function may access any of its elements. For example:

```cpp
#include <iostream> // Example 11.20
```

```cpp
void test(int arr[]);
int main()
{
  int i, a[5] = {10, 20, 30, 40, 50};
  test(a);
  for(i = 0; i < 5; i++)
    std::cout << a[i] << ' ';
  return 0;
}
void test(int arr[])
{
  arr[0] = 0;
}
```

Note that in test() we could use the name instead of arr, since you know that local variables of different functions are not related even if they are named the same. When test() is called, we have arr = &a[0]. The statements arr[0] = 0; and arr[1] = 0; change the values of the first two elements and the program displays: 0 40

Array parameter can be declared as a pointer, as well. For example, the declarations:

```cpp
void test(int arr[]); and void test (*int arr);
```

are equivalent. The compiler treats both and passes the pointer to the function. The first declaration is more accurate since it clearly states that pointer is passed, not a copy of the array. The second declaration is ambiguous; the reader cannot figure out whether the function accepts number of values or pointer to a single variable. Alternatively, we could pointer arithmetic to access the array elements. For example:

```cpp
void test(int arr[]) {
*arr = 0; // Equivalent to arr[0] = 0.
arr++;
*arr = 0;
}
```

What is really interesting is the statement arr++. Can we change the value of an array? Certainly not, know from Chapter 8 that the name of arr is used as pointer. So, why the compiler allows this statement? Because, although arr is declared as array, it is actually a pointer. Therefore we can give it a new value. One more example: the following code will compile, and if, what is the output?

```cpp
#include <iostream> // Example 11.21
void test(int arr[]);
int main() {
int a[3] = {5};
  test(a);
  std::cout << a[0] << '\n';
  return 0;
}
test(int arr[]) {
int i = 20, b[10];
arr = b;
*arr = 10;
arr = &i;
*arr = 30;
std::cout << b[0] << ' ' << i << ' ';
}
```

Of course, arr is treated as an ordinary pointer. test() outputs 10 and 30. Since test() did not access a[0], the program outputs 5. And of course, we make sure when using an ordinary array, that all the actions are within the limits of the array. Note that if we want to pass the whole array instead of the pointer to its first element, we'll see such an example with reference in Chapter 16.

# Determining Array Size

Although we can use the sizeof operator to find the size of an array variable, we cannot use it in a function to find the size of an array parameter. For example, consider the following program:

```cpp
#include <iostream> // Example 11.22

void test(int arr[]);

int main()
{
    int a[] = {1, 2, 3, 4, 5};

    test(a);
    std::cout << "Array = " << sizeof(a) << " bytes\n"
    return 0;
}

void test(int arr[])
{
    std::cout << "Ptr = " << sizeof(arr) << " bytes\n"
}
```

Since an array parameter is treated as a pointer, the sizeof operator calculates the size of the pointer variable (e.g., 4), not the actual size of the array. The program outputs 4 and 20 for the array.

Because it is the pointer that is actually passed to the function, it has no effect if we put the length of the array inside the brackets (e.g., void test(int arr[5])). The compiler ignores it; it won't know the array actually has the indicated length (e.g., 5). Essentially, passing the pointer is a pointer to the first element of an array of unknown length. What I recommend leaving the brackets empty so that you do not create the false impression that the compiler would enforce that only arrays of specific size (5) can be passed as an argument. No, the compiler successfully processes the program no matter what is the length of the array. An easy way to make known to the function the length of the array is to pass it as an additional argument. For example, we could declare test() as:

```cpp
void test(int arr[], int size);
```

and write test(a, 5); to call it.
Alternatively, we define a constant, e.g., const SIZE = 5; and use that constant wherever needed of passing an additional argument. Another way is to use a special value to indicate the end of the array, provided of course, that value would not occur in the array. For example, if an array contains a C-string it is needed to pass its length, since the null character indicates its end.
Another way is to pass pointers to the first element and the next place after the last element. For example, we could declare test():

```cpp
void test(int *beg, int *end)
{
    while (beg != end)
        std::cout << *beg << '\n'; /* The Values of the elements are displayed. */
}
```

and to call it: test(a, a+5); or use the library functions begin() and end() and write:
test(begin(a), end(a));
