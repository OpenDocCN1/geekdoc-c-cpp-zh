# 702 Introduction to C++

```
int main() {
    int i;
    Person per("First", 1);
    Programmer pro("Second", 2, "Net");
    Author auth("Third", 3, 5);
    Person *p[3] = {&per, &pro, &auth};

    for (i = 0; i < 3; i++) {
        p[i]->show();
    }
    return 0;
}
```

The constructors of the Programmer and the Author classes use the syntax to initialize their members and call the constructor of the base class. The show() of the derived classes use the name of the base class and the :: operator to call the base show(). Since the show() is virtual, the program checks the type of the object that has p[i] pointer to and calls the corresponding show(). If show() had not been declared as virtual in the base class, the compiler would check the type of the p array and call the Person::show() of Person three times. So so far, this program is essentially another example that demonstrates the behaviour of virtual functions. Let's see what happens when we use the following code:

```
ProgAuth pro_auth;
pro_auth.show(); // Compilation error.
```

When the pro_auth object is created the four default constructors are called. Specifically, the constructor of the ProgAuth object is called the Person and the Programmer constructors to create the corresponding sub-objects, and the Person and Author constructors to create the corresponding sub-objects, each sub-object of the Author class contains two sub-objects of the Person class. What would happen if any of the default constructors of the Person, and the Author classes were missing? The compiler would issue an error message, since all these classes have the default constructor is not created automatically; it must be added.

Next to pay attention. Which() will be called? That of Programmer or Author? Because the compiler does not know which to call, it will display an error message similar to ProgAuth::show() is ambiguous. One solution is to use the :: scope operator and the name of the respective class. For example:

```
pro_auth.Programmer::show(); // The show() of Programmer is called.
pro_auth.Author::show(); // The show of Author is called.
```

Alternatively, another approach is to define a show() in the ProgAuth class and call from there the show(); We want for example:

```
class ProgAuth : public Programmer, public Author {
public:
    virtual void show() const override;
};

void ProgAuth::show() {
    Programmer::show();
}
```

Now, we can write: pro_auth.show(); and the show() of the Programmer is called.
