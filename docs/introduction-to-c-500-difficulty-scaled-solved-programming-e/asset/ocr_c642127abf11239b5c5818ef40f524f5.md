> When we want to create a single sub-object of the common base class we make it virtual.

However, with virtual classes the ways the constructors are called are changed. Let's see why. In our example, the constructors of the B and C classes pass information to the constructor of the A class. No problem, the constructor of each A sub-object is called. But now we've made the A class virtual we have only one A-object. The logical question is from which path it will be initialized? From the B or C path? To resolve this, C disables the passing of information from an intermediate class to the base class, which is virtual. That is, the B and C constructors initialize the t and v respectively, but the calls to A are ordered.

Fine, but the A-object must be constructed. So, how will it be constructed? The answer is that responsibility for constructing the sub-object of a virtual base class goes to the constructor of the most derived class (e.g., BC). In particular, when the BC object is created the compiler calls the default constructor of A. Is there a default constructor in our example? No, the compiler will display an error message similar to A::default constructor is missing. Let's add it. The rest of the program remains the same as that we made the A class virtual.

```
class A
{
    A(int k) : r(k) {cout << " A()";}
    A() {cout << " Def A()"; r = 30;}
    virtual ~A() {cout << " -A()";}
};
```

```
class B : virtual A
{
    B(int m) : A(m), t(m) {cout << " B()";}
    ~B() {cout << " -B()";;}
};
```

```
class C : virtual A
{
    C(int p) : A(p), v(p) {cout << " C()";}
    ~C() {cout << " -C()";;}
};
```
