
You may wonder, don't these implied conversions (e.g., t = s) make the code more difficult to understand? Yes, I agree. My preference is to make clear the creation of the temporary object and not to use the constructor to convert the type. That is, I prefer to write:

```cpp
t = T("text"); rather than t = s.
```

Are the implicit conversions safe? No, they are not; or due to their automatic nature, an unintended assignment may cause an undesirable conversion and introduce a bug that will change the behaviour of t program. Let's see such an example:

```cpp
#include <iostream> // Example 19.2
#include <string>
using std::string;

class Student
{
private:
    string name;
    int grd[5];
public:
    Student(int g);
    Student(string s);
    int& operator[](int i);
};

Student::Student(string s)
{
    for(int i = 0; i < 5; i++)
        grd[i] = -1;
}

Student::Student(int g)
{
    for(int i = 0; i < 5; i++)
        grd[i] = g;
}

int& Student::operator[](int i)
{
    return grd[i];
}

int main()
{
    Student s("first");

    s = 2; /* The intention is to change the value of an element in the array,
    but the programmer made a mistake and didn't specify the element.
    Instead, this assignment changes the name to none and the values of the grd
    array to 2. */
    return 0;
}
```

The intention of the programmer is to change the value of an element in the array. For example, suppose that you want to make the first grade equal to 2. Instead of writing grd[0] = 2, which calls the operator[] function to change the grd[0], you make a mistake and set s = 2; however, with this statement, the compiler uses the Student (int g) constructor and converts the value 2 to a temporary object, which is copied by s. So the value of s.name changes from first to none and all elements of the grd array become equal to 2.

Had we made the conversion explicit, that is, writing explicit Student (int g); the compiler would not allow the conversion and produce an error message to the programmer. No, I have not made such a mistake to date. But, because there is always a first time for everything, I prefer to declare as explicit a constructor that accepts a single argument, in order to protect myself from potential unintended single-argument constructor bugs. In fact, I'd prefer the standard having made a single-argument constructor explicit by default.

## CONVERSIONS FROM CLASS TYPE

As a type can be converted to an object, (e.g., t) can also be converted to a type. For example:

```cpp
int i = t;
```

This statement is allowed if a conversion function is defined in the class, as follows:

```cpp
operator type();
```

where type is the name of the type to which the object will be converted. If this definition is missing the compiler issues an error message since it cannot assign a t to int.

When declaring conversion functions rules apply. For example, the conversion function must be a member of the class, with no return type specified in its declaration and take no arguments. The return type is that of type. For example, the function prototype for conversion to int is:

```cpp
operator int();
```

Also, when the conversion function is declared, explicit conversions are allowed. For example:

```cpp
int i = static_cast<int>(t);
```

Usually, the conversion function does not change the state of the respective object, so it is declared as const.

```cpp
#include <iostream> // Example 19.3
class T
{
private:
  int a;
  double d;
public:
  T(int i);
  operator int() const; // Conversion function to int.
  operator double() const; // Conversion function to double.
};
```

```cpp
T::T(int i)
{
    a = i;
    d = 1.2;
}

T::operator int() const /* It is an error to add the return type and write int T::operator int() const. */
{
    return a+2;
}

T::operator double() const
{
    return d+2;
}

int main()
{
    int i;
    double k;
    T t = 3; // The int type is converted to class type.
    i = t; // The int conversion function i = t.int(); is called.
    k = t; // The double conversion function k = t.double() is called.
    std::cout << i << ' ' << static_cast<int>(t) << '\n'; /* The Program displays 5 twice. */
    std::cout << k << ' ' << static_cast<double>(t) << '\n'; /* The Program displays 3.2 twice. */
    return 0;
}
```

Strange as it may seem, we can see that no return type is specified in the declaration of conversion function. The return type is that of target type. With the statement i = t; the int conversion function is called and becomes 5. With the statement k = t; the double conversion function is called and becomes 3.2. Similarly, with static_cast<> the conversion functions are called. Note that if we do not use implicit conversion and write << t; the compiler will display an error message because it does not know which int or double conversion to use.

Again one might ask, don't these implicit conversions make the code more difficult to understand and less safe? Yes, I agree. My preference is to make clear the creation of the temporary object and not to use the constructor to convert the type. That is, I prefer to write:

```
t = T("text"); rather than t = s.
```

A popular usage of conversion function is checking the state of a stream in a condition:

```cpp
while(cin >> i) {...}
```

As we know, with the istream operator value will be read, stored in i and reference is returned. Thus, to evaluate the condition, the conversion function is called, which, if the state is valid, returns true, otherwise, if error occurs, returns false. As a constructor, if we do not want to allow implicit conversions can use the word explicit. If the conversion function is made explicit we must use typecast to use it:

```cpp
class A
{
    explicit operator int() const {return 10;}
}
int i;
i = a; // Wrong.
i = static_cast<int>(a); // Correct.
```

Before we move on the next section, I'd like to say that I'm not fond of implicit conversions class type because I prefer things to be clear, simple, and safe. That is what really matters.

## POINTER TO A FUNCTION MEMBER

In Chapter 8, we discussed pointers to functions. For example, with void (*ptr)(int, int); ptr is declared as a pointer to a function, which takes integer parameters and returns nothing. Now let's see how we can declare pointers to functions are members of a class. For example:

```cpp
#include <iostream> // Example 19.4
class T
{
public:
    void f(int a, int b) {std::cout << a-b << '\n';}
}
void (T::*fptr)(int a, b);

int main()
{
    T t;
    T::*fptr; // Pointer declaration.
    fptr = &T::f; /* This is the syntax to make the pointer point to the member function.*/
    (t.*fptr)(8, 5); // Call the function through * operator.
    T::*r = &T::f;
    (r->fptr)(8, 5); // Call the function through -> operator.
    return 0;
}
```

To make it easier to write the pointer declaration and the type of corresponding variables it is more convenient to use the typedef statement and create a synonym for the type of the pointer. But about the syntax of this declaration it seems complex, it is not, as long as we follow the method that we've mentioned in Chapters 8 and it. As we said, an easy way to declare a pointer to a function is to first write the prototype of the function and then replace the function name with an expression of the form (*ptr). For example, we use the typedef word to declare the declaration of fptr, and so we can use fptr name in the program. Then, if fptr is a synonym of the type "pointer to function member of class T, which takes integer parameters and returns nothing". Using this synonym makes the declaration of corresponding variables (e.g., p) simple.

Alternatively, as we know from Chapter II, we can use the using keyword to create a synonym. For example, we can use

```cpp
using fptr = void (T::*) (int, b);
```

Without synonyms we can declare the p pointer as follows:

```cpp
int main()\{
    void (T::*p)(int a, b); // Pointer declaration.
    p = &T::f;
    ...
}
```

Alternatively, the declaration becomes very easy with C++11, because we can use auto to deduce the type of the variable for us. For example, we write:

```cpp
auto p = &T::f;
```

As I told you, my intention is to show you several alternatives and not just the easiest so that you know how they work in code written by others. To make a pointer to a class member, we apply the & operator to the full name of the member. As mentioned in the contents of the program, if the object is used to call the function, we use the . operator, or if a pointer is used, we use the -> operator. They must be enclosed in parentheses, because the priority of the call operator ( ) is higher. The program displays 3 and 3.

A pointer to member function may be used to call the function when we do not know its name. If we use it, there is no reason to use a pointer. Then, we make the call directly by writing t.f(8, 5); So, don't be with the example, you may never use a pointer. If it happens, this is an example of how to use it. The second reason for this example is to discuss the * and -> operators, so that you don't wonder about their meaning when you see them in priority. A static member is not associated with an object, so don't use its full name to declare it. For example:

```cpp
class T {
public:
    static void f() {}
};
void (T::*p)() = &T::f; // Wrong.
void (*p)() = &T::f; // Correct.
auto p = &T::f;
```
