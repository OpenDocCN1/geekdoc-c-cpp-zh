unique_ptr<double> f();

```
int main() {
    auto p1 = f();
    cout << *p1 << '\\n';
    return 0;
}
```

```
unique_ptr<double> f() {
    auto p2 = make_unique<double>();
    *p2 = 1.2;
    return p2; /* We could avoid the declaration of p2 and write directly;
    return make_unique<double>(1.2); /*;
}
```

When f() returns, p1 takes ownership of the memory that p2 originally owned. And it is logical for the compiler to allow this action, because it knows that p2, it is a local variable, will be destroyed, there are no two objects pointing to the same memory. The memory will be released when p1 is destroyed. The program displays 1.2.

Let's change f() to return an ordinary pointer and compare the two approaches:

```
void g() {
    double* p1;
    p1 = f();
    // If we forget to make delete p1; we have a memory leak.
}
```

```
double* f() {
    double* p2 = new double();
    *p2 = 1.2;
    return p2;
}
```

g() is responsible to release the memory allocated in f(). If we forget to release it we have a memory leak. In particular, when f() returns p1 will be destroyed, the memory it points to not be released. If we change g() to return p1, then the memory should be released by the function that call g(), and so on. With the use of unique_ptr we don't need to worry about the release of the memory, since the memory will be released by the object that it is destroyed.

As said, we cannot copy a unique_ptr to another. However, if we want to transfer the ownership to unique_ptr object and use the object again to another location, we can do by using the move() function. For example:

```
int main() {
    unique_ptr<double> p1, p2;
    auto p3 = make_unique<double>();

    *p3 = 3.4;
    p1 = move(p1); /* We use move() to transfer the ownership from p1 to p2.
    As said, if we write p2 = p1; we'll have a compilation error. */
}
```
