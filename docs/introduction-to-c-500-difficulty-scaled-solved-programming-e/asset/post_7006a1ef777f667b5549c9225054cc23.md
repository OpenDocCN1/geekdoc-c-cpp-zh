We've discussed about the scope of program elements such as variables and functions. For example, we know that we can use the same name for local variables of different functions. What about names with global scope? Elements that are declared with a global scope, such as global variables, we say that they belong in the global namespace. In large programs, where the code is split in many files written by different programmers, the probability of name conflict increases. For example, we may have defined a class Queue in the queue.h file and the same name is used in one of the libraries we use (e.g., in the game.h file):

```cpp
#include "queue.h"
#include "game.h"
```

The compilation will fail due to the multiple definition of the Queue class. Class of, if we change the name of our class (e.g., to My_Queue) the problem is fixed. However, in the case of using libraries by others and the same names are chosen, we cannot change them. To avoid such conflicts, C++ provides an elegant mechanism with the use of namespaces.

A namespace is a region with its own scope in which we can put the entities of our program (e.g., classes, functions, ...) Namespaces allow us to organize the entities of our program into logical groups and prevent collisions with names declared outside of it. For example, we can create the Network namespace and put classes related to network protocols and devices within it. In large applications, where many namespaces are typically used, their become more valuable, because splitting the program into different logical scopes referred to by names (e.g., graphics, library for web services, prevents name collisions and facilitates its management, comprehension, and maintenance.

# Create a Namespace

To create a namespace we use the namespace keyword. For example:

```cpp
namespace A
{
    int var;
    double d = 1.2;
    int f();
    struct S{...};
    class C{...};
} // Semicolon is required
```

Inside a namespace we can declare the elements we want, such as variables, function declarations and definitions, templates, classes, and objects. A namespace is allowed to be declared in the global namespace or within another namespace, but not within a block (e.g., function). A namespace defines its own scope. The scope of each member extends from the point of its declaration to the end of the namespace. Every name declared within a namespace has the name of the namespace (e.g., A) attached to it. Thus the names we use in a namespace do not conflict with the same names in other namespaces or in the global namespace. That is, if we create the namespace A and the B that both contain a variable named var there will be no name conflict between that, is, between the A::var, B::var, and the global var. This is the main advantage of namespaces to avoid name conflicts. In large projects involving many programmers, it is common practice to separate namespaces so that even if the same names are chosen, they will not cause conflicts.

Inside a namespace we can add new elements the name of the namespace. For example, the following statement extends the scope of the namespace A and adds the declaration of the g() function in the elements of A:

```cpp
namespace A
{
    void g();
}
```

As another example, we can use again the A name and add the definition of f() later on. For example:

```cpp
namespace A
{
    int f()
    {}
}
```

Alternatively, we can define it, as we define a function outside its class:

```cpp
int A::f()
{
    ..
```
