
Storing data in a binary file can save space compared to a text file. For example, suppose that we are using the ASCII character set to write the number 47654 in a text file. In this system represent with five characters, the size of the file will be 5 bytes, as shown in the following figure:

| 0010100 | 0010111 | 0010110 | 0010101 | 0010100 |
| '4' | '7' | '6' | '5' | '4' |

On the other hand, if this number is stored in binary, the size of the file will be 2 bytes, as shown in the following figure:

```
00111110 00101010
47654 = =
```

Binary files might seem a better choice; they have some disadvantages, though. When a binary file is transferred from one system to another the data might not be represented the same, because different systems store them in different ways. For example, a system may store the high byte of a number, while some other system the lower byte. Furthermore, because the sizes of the data types may differ from system to system, number of bytes might be written. For example, a function using sizeof(int) to save an integer into a file may write four bytes in one system, eight in another.

# FILE INPUT AND OUTPUT

To manage files, C++ provides a variety of useful classes. In particular, the ofstream class which derives from ostream is used to write data in a file, the ifstream class which derives from istream is used to read a file, and the fstream class which derives from iostream which derives from ostream and istream is used to both write and read a file. These classes inherit the ios_base constants and functions we saw earlier in order to check the state of the stream. To use them we include the fstream header file.

Let's look at a simple example of writing data into a file. In short, the steps to follow are to create an ofstream object, associate it with the file and then use the object, as we use cout, to write the data in the file.

```cpp
#include <iostream> // Example 24.1
#include <fstream>
#include <cstdlib> // For exit()

int main()
{
    int i;
    std::ofstream fout; /* fout is an output stream object which that has been associated with a file. */
    fout.open("test.txt"); /* Open a file for writing and associate the object with it. We could create fout and associate it with the file in one statement line: ofstream = fout("test.txt"); */
    if(fout.is_open() == false) /* Alternatively, we can write if(!fout).
    {
        std::cout << "Error: File can not be opened\n";
        exit(EXIT_FAILURE); /* Since the file is not opened, the program terminates. */
    }
    for (i = 0; i < 3; i++) {
        fout << "Hello " << i+1 << '\n';
    }
    fout.close(); // Close the file.
    return 0;
}
```

The name of the object can be any C++ name (e.g., fout). When we open a file for writing in this way, the program creates the file, if it does not. If it exists, contents are deleted. Next, we'll see how to write to an existing file without deleting its contents.

If the file exists in the same folder with the executable program, we just put the file in double quotes. If it does not exist, the file is created in the same folder with the executable, then the full path must be specified.

If the operating system uses the character \ to specify the path, \\, as we saw in Chapter 3, C++ treats \ as an escaping sequence.

For example, if our program runs in Windows and we intend to write to the test.txt file that resides in the d:\dir\dir2 path, we should write:

```cpp
fout.open("d:\\dir\\dir2\\test.txt");
```

However, if the program obtains the file name from the command line, it is not needed to add an extra \. For example, we use d:\dir\dir2\test.txt.
With is_open() we check if the path is opened successfully. If not, the program terminates. For example, is_open() fails when the file path is invalid or we do not have permission to write to the file. Because ostream is derived from the ostream class, its objects can use the ostream functions, such as the overloaded operator<< functions.

If we want to associate the object with a different file we should first close the existing file. For example:

```cpp
fout.close(); // Close the file.
fout.open("new.txt"); // Open a new file.
```

close() closes the file associated with the calling object. All data in memory is written to the file. Also, an open file closes the associated object ceases to exist, for example, when the program terminates.
Similarly, to the readers of a file, we need to create an istream object, associate it with the file, and use it, as we use cin, to read its contents. In the following example, suppose that each line of the input contains the temperatures of an array. A program reads and displays those within [–5,5].

```cpp
#include <iostream> // Example 24.2
#include <fstream>
#include <string>
#include <cstdlib>
using namespace std;

int main() {
    double temp;
    string fname;
    cout << "Enter file name: ";
    cin >> fname;
    ifstream fin(fname.c_str()); // Because the type of parameter in constructor is const char*, we make a C-style string as argument.
    if(fin.is_open() == false) {
        cout << "Error: File cannot be opened\n";
        exit(EXIT_FAILURE);
    }
    while (1) {
        fin >> temp;
        if (!fin) { // If an error occurs in reading the data or we reach the end of the file the operator returns false.
            break;
        }
        if (temp >= -5 && temp <= 5) {
            cout << temp << '\n';
        }
    }
    fin.close();
    return 0;
}
```

The ifstream class is derived from the istream class, its objects can use the istream functions, with the overloaded operator>>. If we want to read and write in a file we must associate the file with an fstream object. The ifstream class is derived from istream and ostream classes, so it inherits their functions. Let's look at an example:

```cpp
#include <iostream> // Example 24.3
#include <fstream>
#include <cstdlib>
#include <string>
using namespace std;

struct Student {
    string name;
    int code;
    float grd;
};

int main() {
    Student s1 = {"Lee", 100, 5.8}, s2;
    fstream fstr("test.txt", ios_base::trunc);
    if(fstr.is_open() == false) {
        cout << "Error: File cannot be opened\n";
        exit(EXIT_FAILURE);
    }
    fstr << s1.name << ' ' << s1.code << ' ' << s1.grd << '\n';
    fstr.seekg(0);
    while (fstr >> s2.name >> s2.code >> s2.grd) {
        cout << s2.name << ' ' << s2.code << ' ' << s2.grd << '\n';
    }
    fstr.close();
    return 0;
}
```

# STREAM BUFFER

The ofstream class uses a buffer for data. For each created object, the program allocates memory. This memory acts as an intermediary buffer between the program and the file. The data is not written directly to the file, but stored in this output buffer. When it becomes full, the program flushes the buffer and the data is written to file. Buffering increases the performance since one large transfer to the disk is much more efficient than many individual transfers. Similarly, buffering applies when we are using an ifstream object to read a file from the disk. That is, the program reads large blocks of data, stores them in the input buffer of the object, and the data in the buffer are processed. This approach is much faster and more efficient than reading one byte at a time from the disk.

Note that we can flush the output buffer whenever we want. For example, as we saw in Chapter 3, we can use the flush, endl, or unitbuf to flush the buffer. A write operation in this second stream may be associated with another output stream. For example, the cin and cerr streams are by default associated with cout. Thus, reading from cin (e.g.) or writing to cerr flushes the buffer of cout.

If the program crashes (abnormally), the buffer is not flushed. Thus, it is very likely that data which are still in the buffer are not processed (e.g., not printed in the screen). However, this loss can lead us to erroneous conclusions about the operation of the program. For example, when we debug a program that crashed we want to see all the messages that have been printed to know which parts of the code have been executed. If some messages do not appear we assume that the respective code was not executed which the messages were not printed because the output buffer was not flushed.

> For the better control of the program, the diagnostic messages related to its operation should be printed directly (e.g., with endl), so that in the case of crashes the programmer has seen them.

# CLOSE A FILE

As we said, when we write data to the file, with the buffering approach the data will not be written directly to the file on the disk but to the buffer that is reserved for this purpose. When it is full or the file is closed, the buffer is flushed and the data is stored in the file. Thus we often reduce the access to the disk, which degrades the performance of the program. The close() function is used to close an open file. If the file is open for writing, close() stores in the file the data that may still be left in the buffer.
