
When c is destroyed, the destructors are called in reverse order, that is, first of C, then that of B, and last of A. Here is a more difficult example. Consider the following inheritance scheme, where each class contains the default constructor and destructor. In what order will they be called?

```cpp

class B {......};

class D {......};
class E : public D {......};
class F : public E {......};

```

```cpp
int main() {
  G g;
  ...
}
```

The construction order of the sub-objects is D, E, F, B, A, C, G. When g is destroyed, the destructors of the sub-objects are called in reverse order.

## Creation of Multiple Base Objects

If in the class hierarchy more than one path exists between a base class and a derived class, multiple objects of the base class are created and, therefore, multiple copies of its members. This may not be desirable. Can we avoid it? We'll answer it later, at first, consider the following program:

```cpp
#include <iostream> // Example 21.5
using std::cout;
```

```cpp
class A {
private:
  int r;
public:
  A(int k) : r(k) { cout << " A()"; };
  virtual ~A() { cout << " ~A()"; };
  void show_A() const { cout << " A:" << r; }
};
```

```cpp
class B : public A {
private:
  int t;
public:
  B(int m) : A(m), t(m) { cout << " B()"; };
  ~B() { cout << " ~B()"; };
  void show_B() const;
};
```

```cpp
void B::show_B() const {
  cout << " B:" << t;
  show_A();
}
```

```cpp
class C : public A
{
private:
public:
    int v;
    C(int p) : A(p), v(p) { cout << " " << C(); };
    ~C() { cout << " " << "~C()(); }
    void show_C() const;
};
```

```cpp
void C::show_C() const
{
    cout << " C:" << v;
    show_A();
}
```

```cpp
class BC : public B, public C
{
private:
    int z;
public:
    BC(int x) : B(x), C(x+1), z(2*x) { cout << " BC()" << "\n"; };
    ~BC() { cout << " ~BC()"; };
    void show_BC() const { cout << " BC:" << z << "\n"; }
};
```

```cpp
int main()
{
    BC bc(10);

    bc.show_B();
    bc.show_C();
    bc.show_BC();
    return 0;
}
```

The B and C classes are derived from the A class. The BC class is derived from these two classes. I made the constructors to have parameters so that we remember the constructor of a derived class can pass values to the constructor of the base class. When the BC object is created the constructor of the base class is called:

```cpp
BC(int x) : B(x), C(x+1), z(2*x) { cout << " BC()" << "\n"; };
```

At first recall, as in the class hierarchy of example C20.4, a constructor of a derived class can call a constructor of its direct base classes. An exception to this rule is virtual base classes, which we'll see below. Now, let's get to the BC constructor. It calls the constructor of B and C classes and passes to the value 10. In turn, the first sub-object of the A class is created and x becomes 10. Then, the constructor of the C class is created and the value 11 is passed to it. It calls the constructor of the A class and passes the same value to it. Thus, the second sub-object of the A class is created and x becomes 11. Then, the sub-object of the C class is created and v becomes 11. To sum up, the bc object contains two sub-objects of the A class, one sub-object of the B class and one of the C class.

With multiple inheritance an object of derived class contains a sub-object for each of its base classes.

As we said, in the order in which the objects of the base classes is constructed from left to right, the base classes appear in the declaration of the class (e.g., public B, public C). The order in which the constructors appear in the initialization list does not matter. But, if we change the order and write:

```cpp
BC(int x) : C(x+1), B(x), z(2*x) {cout << " BC()\n";};
```

the constructor of the B class will be called first again and then that of C.
c.show_B() calls the show_B() of the B class. It displays the value of t and calls the show_A() of its own sub-object. Similarly, show_C() calls the show_C() of the C class, which displays the value of v and calls the show_A() of its own sub-object. The destructors are called in the reverse order from the one that the constructors were called. Finally, the program displays:

```
A() B() A() C() BC()
B:10 A:10 C:11 A:11 BC:20
-BC() -C() -A() -B() -A()
```

As you guess, duplications and ambiguities arise from such repeated inheritance. For example, we write:

```cpp
bc.show_A();
```

No, the compiler will display an error message similar to BC::show_A() is ambiguous. The reason is that there are two sub-objects of the A class, the compiler cannot choose the object to show_A(). In the A sub-object of the B class or in the A sub-object of the C class? In example, I skipped this problem by making show_A() to be called through the functions of the B and C sub-objects. Thus, the compiler will show the show_A() of the A sub-object contained in each class. As we know, another way is to use the :: scope operator and specify the A sub-object we want. For example:

## Multiple Base Objects and Problems

Let's look at a more realistic example with the construction of multiple base objects and problems that may arise. This time I won't choose show_names (e.g., show_A), which is the easy case since it is clear which show will be called, but I will choose the same name show() and use virtual functions for polymorphism. The program defines the Person class and uses it to derive the Programmer and Author classes. The ProAuth class is derived from these two classes. Essentially, the program seems of being a programmer and a writer.

```cpp
int main() {
    int i;
    Person per("First", 1);
    Programmer pro("Second", "Net");
    Author auth("Third", 5);
    Person *p[3] = {&per, &pro, &auth};

    for (i = 0; i < 3; i++) {
        p[i]->show();
    }
    return 0;
}
```

The constructors of the Programmer and Author classes use the syntax to initialize their members and call the constructor of the base class. The show() of the derived classes use the name of the base class and the :: operator to call the base show. If show() had not been declared as virtual in the base class, the compiler would check the type of the p array and call Person::show() three times. So so far, this program is another example that demonstrates the behaviour of virtual functions. Let's see what happens when we use the following code:

```cpp
ProgAuth pro_auth;
pro_auth.show(); // Compilation error.
```

When the pro_auth object is created the four default constructors are called. Specifically, the constructor of the ProgAuth object is called the Person and Programmer constructors to create the corresponding sub-objects, and the Person and Author constructors to create the corresponding sub-objects, each sub-object of the Author class contains two sub-objects of the Person class. What would happen if any of the default constructors of the Person, and the Author classes were missing? The compiler would issue an error message, since all these classes have the default constructor is not created automatically; it must be added. Next to pay attention. Which() will be called? That of Programmer or Author? Because the compiler does not know which to call, it will display an error message similar to ProgAuth::show() is ambiguous. One solution is to use the :: scope operator and the name of the respective class. For example:

```cpp
pro_auth.Programmer::show(); // The show() of Programmer is called.
pro_auth.Author::show(); // The show of Author is called.
```

Alternatively, another approach is to define a show() in the ProgAuth class and call from there the show(); We want for example:

```cpp
class ProgAuth : public Programmer, public Author {
public:
    virtual void show() const override;
};

void ProgAuth::show() {
    Programmer::show();
}
```

Now, we can write: pro_auth.show(); and the show() of the Programmer is called.
