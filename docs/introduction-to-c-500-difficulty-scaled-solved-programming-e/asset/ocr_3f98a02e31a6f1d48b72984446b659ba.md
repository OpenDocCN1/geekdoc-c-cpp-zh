C.8.14 How many compilation errors can you detect in the following program?

```
#include <iostream>
int main() {
    int i, arr[5] = {10, 20, 30, 40, 50};
    for(i = 0; i < 5; i++)
        std::cout << arr[i] << '\n';
    std::cout << 2[arr]-3[arr] << '\n';
    return 0;
}
```

**Answer:** Did you escape the trap or ptr? The normal answer to give is the expression i[arr] is wrong, because arr is not declared as an array. For the same reason, the expressions 2[arr] and 3[arr] are wrong as well. However, the compiler not complain. Yes, you've read it correctly, it is not a typing error; the compiler has no reason to complain about. And now, what will we do after that converting?

Relax, listen to Getting Away with It (All Missed Up) from James and wait for the smoke to clear. Nothing is missed up, let's see why. As, the compiler converts i[arr] to *(i+arr), which is equivalent to *(arr+i), or to i(arr).

```
arr[i] = *(arr[0]+i) = *(arr+i) = i[arr]
```

Though,2[arr] is equivalent to arr[2]. Therefore, the program is compiled successfully and displays the values of the array's elements, as well as the difference of arr[2] and arr[3], that is, -10. In the same "irrational" sense, could we write the following?

