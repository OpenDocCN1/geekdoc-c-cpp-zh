Regarding the design of a class, we should think about whether to overload operators or not. In general, if overloading simplifies the operation and makes the use of your class easier and safer to do, otherwise we do not it. I think this is the most important guideline. The usual candidate operators are:

+   a. If the class supports input/output operations makes sense to overload the << and >> operators.
b. If the class supports equality tests makes sense to overload the == and != operators.
c. If the class supports comparison tests makes sense to overload the relational operators (e.g., <).
d. If an arithmetic (e.g., +) or bit operator is overloaded, makes sense to overload the corresponding compound operator (e.g., +=), in order to provide that to the users of the class would expect.
e. A good practice for the type of function is to be compatible with the type of the operator that normally produces, so that the use of the function makes the typical use of the operator. For example, the return type of functions that overload the logical and relational operators, for arithmetic operators (e.g., +) to be that of the class, and for assignment operators (e.g., *=) to be a reference (e.g., T&), reference to the first argument of the assignment expression which is defined as non-member), so that we can use the result of the assignment expression in a binary chained expression. As for the parameters, for operators that normally do not modify their operands (e.g., relational operators) they are usually defined as const references to avoid copying the argument and to be modified as well.

Before continuing with the exercises, I'd like to point out that overloading the [], <<, and >> operators is very common. Also, it is very common to overload the () call operator and create function objects. You'll see examples with such objects in Chapter 26.
