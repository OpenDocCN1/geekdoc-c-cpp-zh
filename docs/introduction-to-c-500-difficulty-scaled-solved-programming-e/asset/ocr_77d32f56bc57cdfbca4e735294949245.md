As shown, the compiler replaces test() call with its code and make it "in line" with the rest code. Since the function is not called, the performance of the program is improved. On the other hand, since the code of an inline function is added wherever it is called, the size of the executable program may significantly increase if the function is called many times. This can be a problem in systems with limited memory, such as an embedded system.

As discussed in Chapter 15, macros serve a similar purpose. However, remember their weaknesses and the problems that may occur due to their syntax. Inline functions are a much better alternative; they are more secure as they provide type control and are simple to declare and use as an ordinary function.

As for when to declare a function as inline, if the execution time of function is long compared to the delay added by call mechanism, the inline declaration will not bring significant improvement. If the execution time is short and the function is called frequently, then the inline declaration may improve the performance. However, the size of the executable file will increase. In general, when making a function inline does not mean that the performance of the program will improve; it may or not depend on the usage. You should consider making inline short functions that are frequently called.

Notice that if you declare a function as inline it does not satisfy your and make the function inline. The inline suggestion is just a suggestion to a compiler. That is, the compiler may ignore it and handle it like an ordinary function. For example, if the compiler considers that its code is too large or complex enough, it may ignore the inline suggestion and use the conventional way to call the function. And yes, a smart compiler may find it more efficient and make a function inline by itself, if you haven't declared it.
