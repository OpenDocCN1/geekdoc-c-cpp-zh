# Operator Overloading 18

In Chapter 16, we learned that we can define several functions with the same name, provided that they have different signatures. One of the main goals of C++ was the types that a programmer defines to behave like the basic types. In this chapter, we will see how C++ achieves this goal, that is, we will see how we can extend the concept of function overloading to operators so that user defined types, such as classes, to behave like the basic types.

# OPERATOR OVERLOADING

Just as a function can be overloaded, an operator can also be overloaded and perform different tasks. In fact, you've already encountered examples of operator overloading. For example, the * operator when applied to numbers yields their product, when applied to a pointer it yields the value stored in. The compiler checks the name and type of arguments to determine how to use the operator.

C++ allows us to extend the concept of operator to user defined types. For example we can overload the + operator to add two objects of our own class. By a matter of fact, we see in Chapter 10 that we can use the + operator to add two string objects or use the < and the == operators to make comparisons. In fact, the string class overloads these and many more. This natural way of performing operations reveals the beauty of operator overloading. If applied, it simplifies the programming tasks and leads to an easy to read and write code. To overload an operator declare one using the operator keyword, as follows:

```
return_type operatorop (parameters)
```

The name of the function is operatorop. The op can also accept any of the C++ operators (e.g., +, -, *, ...) with some exceptions. Like any ordinary function, it has a body, return type, and can accept parameters. The number of parameters is the same as the number of the operator's. That is, the overloaded function of a binary operator accepts two parameters, while that of unary operator accepts one. As we said, operator overloading is usually applied to classes that operate in a more natural way. For example, the following program defines the Rect class, which contains a function that overloads the + operator:

```cpp
#include <iostream> // Example 1

class Rect
{
private:
    float length;
    float height;
public:
    Rect(float l = 0, float h = 0); // Default constructor with default values
    operator+(const Rect& r) const;
    float area() const;
    void show() const;
};
```

```cpp
Rect::Rect(float l, float h)
{
    length = l;
    height = h;
}
```

```cpp
Rect::operator+(const Rect& r) const
{
    Rect tmp;
    tmp.length = length + r.length;
    tmp.height = height + r.height;
    return tmp;
}
```

```cpp
float Rect::area() const
{
    return length;
}
```

```cpp
void Rect::show() const
{
    std::cout << "L:" << length << " H:" << height << '\n';
}
```

```cpp
int main()
{
    Rect r1(10, 20), r2(30, 40), r3;
    r3 = r1+r2; // Equivalent to r3 = r1.operator+(r2)
    r3.show();
    return 0;
}
```

Before discussing the operator overloading, let's answer that. Since the length and height members are private, the compilation does not fail when those members are accessed in the operator+ function (e.g., r1.length?). The answer is that when the compiler encounters the r1+r2 statement it examines the types of operands and realizes that it must call the operator+ function. Specifically, the r1+r2 statement is implemented as r1.operator+(r2), so the operator+ function of the r1 object is called with the argument r2. In general, when the overload of a binary operator is declared in the class, the left (e.g., r1) is the object that calls it, while the right operand (e.g., r2) is passed as an argument to the function. Note that if the operator function was not declared, the compiler would display an error message for illegal action, since objects cannot be added. Alternatively, it could explicitly call the function and write r1.operator+(r2). Naturally, the usage of the operator is easier to read and write than the explicit call. The function returns a new object with dimensions equal to the corresponding dimensions of the two objects.

This program demonstrates that C++ operators associated with a class can have a special behaviour when applied to objects of that class. For example, the objects can participate in ordinary expressions (e.g., r1+r2) like the basic types. The conventional way is to define corresponding functions in the usual way. For example, instead of overloading the + operator we can define the add() function:

```cpp
Rect add(const Rect& r1, const Rect& r2)
{
    Rect tmp;
    tmp.length = r1.length + r2.length;
    tmp.height = r1.height + r2.height;
    return tmp;
}
```

```cpp
int main()
{
    r3 = add(r1, r2);
}
```

The benefit of operator overloading is that the operation of the class looks more natural and the program becomes easier to read and write. I also find that it is programmatically more elegant for the class developer to provide such convenient services to class users than making them to implement those services. It also simplifies the flow of the class user (e.g., with statements like r1+r2), but gives less time to the class programmer (who has to write the operator functions to support these "natural" operations). After all, as we saw, one of goals of C++ is to make class objects behave like basic types.

Before continuing, did you notice anything strange with the number of the operator's operands? Why is that? If the number of parameters is one, the operator accepts one operand, while the binary operator accepts two operands. If the overloaded function is a class member, the memory address of the first operand (e.g., r1), which is actually the this pointer, is implicitly passed as a "hidden" argument as we saw in Chapter 17 when discussing this pointer. This is why the overloaded functions of class members have one parameter less than the number of operands. For example, if the class overloads the ! operator, which is unary, we write operator!() without any parameters. If the overloaded function is not a class member, it accepts the number of operands.
