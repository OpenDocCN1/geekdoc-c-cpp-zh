Redefining a function hides the declarations of all base-class functions of the same name, regardless of the function signatures.

Redefining a function in a derived class is not a function overloading.

As explained in the previous section, it is not a function overloading overloaded functions must be defined within the same scope, while the derived class defines a separate scope. Thus, the declaration of show() in class B we do not have two overloaded versions of show(), but this declaration hides the respectives declaration in base A. In particular, with the statement the compilers search for the name in show B. Once it finds, it stops searching. Then, because an argument must be passed to show(), the compilation fails. I write it again, the important thing to understand is that the compiler stops searching, not keep looking for another version of the show() in the classes of B that matches the call. Similarly, the declaration of show() in the derived class C hides the respective declarations in classes A and B. Therefore, the compiler displays two error messages. As, to call the show() of a base class we must use the scope operator and the class name. c::B::show(10); What if we want to have overloaded versions of a base class function in a derived class? Could we do that? Yes, using declarations. Specifically we use the using keyword and the name of the function. The using declaration introduces the function into the scope of the derived class, so the versions are available within the derived class. The compiler checks the signatures to distinguish them. For example:

```
class C : public B
{
public:
    using B::show;
    using B::show;
    void show(const char *s) const std::cout << s << '\n';
}
```
