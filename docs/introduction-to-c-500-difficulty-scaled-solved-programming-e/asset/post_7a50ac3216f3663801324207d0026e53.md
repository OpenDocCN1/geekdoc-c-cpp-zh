Suppose now that we want a pointer to the base class to point to a ProgAuth object. As we know, we can:

```
Person *p;
ProgAuth *pro_auth;
p = &pro_auth; // Compilation error.
```

However, the compiler will display an error message. Let's see why. Since each of the Programmer and Author sub-objects are derived from the Person class, the ProgAuth object also contains two Person sub-objects. Normally, as we know, when the address of a derived object is assigned to a pointer to the base class, the pointer points to the address of the base object inside the derived object. But in the ProgAuth object there are two sub-objects of the base class. Which of the two to point? Because the compiler does not know which class to choose, it displays an error similar to "Person is an ambiguous base class of ProgAuth". And how can we solve this problem? We use type cast For Example:

```
Person *p1, *p2;
ProgAuth *pro_auth;
p1 = static_cast<Programmer*>(&pro_auth); /* The Person sub-object of the Programmer sub-object is selected. */
p2 = static_cast<Author*>(&pro_auth); /* The Person sub-object of the Author sub-object is selected. */
```

The last and most important question. Since a ProgAuth object has two Person sub-objects, it will have two names and two codes. What does make sense? Of course, not who is a programmer and a writer should have one name and identity like everyone, not two. And how can we make this possible? The answer is by using virtual base classes. In general, typically, we would want to avoid having multiple sub-objects, so let's see how we can do that.

# Virtual Base Classes

The declaration of a base class virtual allows an object derived from multiple classes which are derived from a common base class to contain one sub-object of that base class. In other words, to avoid a derived class to contain more than one sub-objects of the same base class, we declare that base virtual. To make the base class virtual we use the word virtual in the declaration of the derived class that inherits it. For example, in the program C.21.5 we write:

```
class B : virtual public A {......};
class C : virtual public A {......};
```

Now the B and C sub-objects share a common A sub-object. Thus, a BC object contains only one A-object. If we write:

```
bc.show_A();
```

the compiler will not display an error message, as in the case of the non-virtual A class, now the bc object contains only one A sub-object. No qualification is needed. Note that the words virtual and public can also be used in reverse order. Note also, that the same word virtual is used to denote virtual classes and virtual functions, these two concepts are different from each other. Now, why is it decided to use the same word and not introduce some new word that better demonstrates the uniqueness of the sub-object (e.g., the word unique), I guess that the C++ committee did not want to extend the set of the reserved words and put new restrictions on the selection of names.

> When we want to create a single sub-object of the common base class we make it virtual.

However, with virtual classes the ways the constructors are called are changed. Let's see why. In our example, the constructors of the B and C classes pass information to the constructor of the A class. No problem, the constructor of each A sub-object is called. But now we've made the A class virtual we have only one A-object. The logical question is from which path it will be initialized? From the B or C path? To resolve this, C disables the passing of information from an intermediate class to the base class, which is virtual. That is, the B and C constructors initialize the t and v respectively, but the calls to A are ordered.

Fine, but the A-object must be constructed. So, how will it be constructed? The answer is that responsibility for constructing the sub-object of a virtual base class goes to the constructor of the most derived class (e.g., BC). In particular, when the BC object is created the compiler calls the default constructor of A. Is there a default constructor in our example? No, the compiler will display an error message similar to "A::default constructor is missing". Let's add it. The rest of the program remains the same as that we made the A class virtual.

```
#include <iostream> // Example 21.7
using std::cout;
```

```
class A
{
    A(int k) : r(k) {cout << " A()";}
    A() {cout << " Def A()"; r = 30;}
    virtual ~A() {cout << " -A()";}
};
```

```
class B : virtual A
{
    B(int m) : A(m), t(m) {cout << " B()";}
    ~B() {cout << " -B()";;}
};
```

```
class C : virtual A
{
    C(int p) : A(p), v(p) {cout << " C()";}
    ~C() {cout << " -C()";;}
};
```

```
class BC : public B, public C
{
    ...
    BC(int x) : B(x), C(x+1), z(2*x) {cout << " BC()";}
    ~BC() {cout << " -BC()";;}
};
```

```
int main()
{
    BC bc(10);
    ...
    return 0;
}
```

As we have described, with the creation of the bc object the t member of the B sub-object becomes 10 and the v member of the C sub-object becomes 11. Because A is virtual, the A constructor that will be the default constructor. Then, the r member of the single A sub-object becomes 30. Finally, the program displays:

```
Def_A()    B()    C()    BC()
B:10      A:30   C:11   A:30   BC:20
~BC()     ~C()   ~B()   ~A()
```

But if we do not want the default constructor of the virtual class to be called and we want to specify some other then we call it directly. For example:
BC(int x) : A(x+5), B(x), C(x+1), z(2*x) {cout << " BC()"};

As we learned in Chapter 20, when we use multiple inheritance, the sub-objects of the base classes are constructed according to the order they appear in the declaration. If a class has more than one virtual base class, the sub-objects of the virtual classes are constructed from left to right in the order they appear in the list of base classes. Then, the non-virtual classes are constructed after the virtual base classes. In this case, the sub-object of the virtual class is constructed by the constructor of the most derived class. Note that the same execution order also applies for the default constructors (e.g., to create e2), as well as when the members are copied with the default copy function (e.g., e3 = e2). As usual, the destructors are called in reverse order of the constructors, the first of E, the last of B. If the classes B and A are not declared as virtual, the construction of the sub-objects is D, C, B, and A.

# Mixed Virtual and Non-Virtual Base Classes

A base class may be virtual in several derived classes and non-virtual in others. What happens when a new class is derived from them? When a class derives from a base class through virtual and non-virtual paths, the class contains one sub-object of the base class corresponding to all virtual paths and separate sub-objects for each non-virtual path. For example, in the program, the A class is a virtual base class for the B and C classes and non-virtual for the D and E classes. The F class is derived from the B, C, D and E classes.
