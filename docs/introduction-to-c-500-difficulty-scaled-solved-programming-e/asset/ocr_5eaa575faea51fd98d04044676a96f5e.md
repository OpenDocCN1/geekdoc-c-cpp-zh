In addition to the rules given earlier, there are two conventions that are good to follow when naming your variables. These are not enforced by the compiler, "rules of thumb" will tend to make your programs easier for you to understand, as well as for those who will read your code.
Use descriptive names for variables (of course, the same applies to functions, types), ... It is much easier to read a program when the use a variable that holds the sum of some values, gives it a name like sum than an irrelevant name like i. Many programmers prefer to use lowercase names when naming variables and uppercase letters when defining macros or constants. Short names (e. i) are usually used as indexes in arrays or loops. Don't give names to variables that are slightly different (e.g., more and More); it is very easy to make a mistake and use one variable in place of the other.

When necessary, the usual practice is to describe the role of a variable. If a variable consists of words, the practice is to separate them with the underscore _ for better readability. For example, you might call a variable that holds the number of days days_number, instead of daysnumber, or something less readable. In general, whatever approach you choose, it is very easy to be consistent and apply throughout the program.

# Data Types

C++ provides a set of data types. Each variable must have a type. The type determines the amount of memory allocated to the variable, the range of values that can be assigned to it, and the kind of operations that can be applied to it. The size of the types is implementation dependent, that is, vary among different systems. The types and their size in a 32-bit system can be seen in Table 2.1.
C++11 adds the following types:

```
char16_t: Used to store 16-bit character, such as UTF-16.
char32_t: Used to store 32-bit character, such as UTF-32.
long long int: Used for very large integers (e.g., at least 64 bits). It is valid that sizeof(long) <= sizeof(long int).
```

The memory space that a data type may vary from one system to another. For example, the int type may reserve two bytes in an embedded or older system, four bytes, or eight bytes in a modern system. To learn the number of bytes a data type reserves on your system, use the sizeof operator, as discussed in Chapter 4.
