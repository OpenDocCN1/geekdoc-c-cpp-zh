
Although an open file is closed automatically when a program terminates normally, it'd better to close it when you no longer use it. A good reason is that if the file is opened writing and the program crashes after the file is closed, the file won't be affected.

For example, let's look at the following code:

```
int *p;
ofstream fout("test.txt");
// Write data in the file.
...
// We finished with the data writing, but we did not close the file.
*p = 20; // Wrong action.
```

Because p does not point to a value, the program may crash. In that case, the data may be left in the buffer. If we had called `close()` after we've finished with the writing, the buffer would have been flushed and the data would be stored in the file. So, remember to close the file when you no longer need it, to be sure that no data be lost.

## FILE MODES

When associating a file with a stream object, either by initializing the object with the file name or first create the object and then use the open function, we can use a second argument, which determines the actions to perform on the file. The `ios_base` class defines constants that represent the open modes (e.g., `ios_base::in`). The `|` operator can be used to enable multiple modes, as shown in the following table.

| OPEN MODE | ACTION |
|---|---|
| ios_base::in | ios_base::out | ios_base::trunc | Open file for reading. If the file exists, it will be truncated and its data will be lost. If it does not exist, it will be created. |
| ios_base::app | Open file for appending. If the file exists, the existing data will be preserved and the new data will be added at its end. If it does not exist, it will be created. |
| ios_base::in | ios_base::out | ios_base::trunc | Open file for reading and writing. If the file exists, it will be truncated and its data will be lost. If it does not exist, it will be created. |
| ios_base::in | ios_base::out | ios_base::app | Open file for reading and appending. If the file exists, the existing data will be preserved and the new data will be added at its end. If it does not exist, it will be created. |

There is also the `ios_base::ate` option, which places the file pointer at the end of the file. The difference between `ios_base::app` and `ios_base::ate` is that the first choice allows you to add data to the end of the file, while the second just places the file pointer at the end of the file.

To open a file we choose one of the above modes. To open a binary file we add the constant `ios_base::binary`. For example, to open a binary file for reading we write `ios_base::in | ios_base::binary`, while to open it for both reading and writing we write `ios_base::in | ios_base::out | ios_base::trunc | ios_base::binary`.

As we said, the mode is an optional argument. If not specified, as in examples C24.1 and C24.2, the default mode applies. In particular, the default value for istream open() and the constructor is ios_base::in, for ofstream open() and the constructor is ios_base::out. The default value for fstream open() and the constructor is ios_base::in; Let's look at some examples:

```
ifstream fin("test.txt"); /* The file opens for reading with the default mode
ofstream out("test.txt", ios_base::app); /* The file opens for writing and
appending new data at its end. The existing data are preserved. */
fstream f("test.txt", ios_base::out | ios_base::trunc); /* The
file opens for reading and writing. The existing data are deleted. */
```

## OPEN MULTIPLE FILES

An application may need to open many files. If the files are opened simultaneously, then we must declare separate objects for each file. The number of the files that can be open simultaneously depends on the operating system.

- In applications where many files are opened, it is advisable to close the files you need more, because the operating system sets a limit to the number of files that can be opened simultaneously.

When we close a file, the buffer is flushed and the file is released. If we close a file, it's important to remember that any data still in the buffer is written to the file. If we do not close the file, the data might be lost if the program crashes.

```cpp
ifstream fin("test.txt");
ofstream out("test.txt");
// ... use the files
fin.close();
out.close();
```

## Random File Access

For random access of a file, we can use the seekg() and seekp() functions. These functions allow us to move the file pointer to any position in the file. The first version of seekg() is for istream objects, and the second is for ofstream objects.

```cpp
seekg(streampos offset, ios_base::seekdir dir);
seekp(streampos offset, ios_base::seekdir dir);
```

The `dir` parameter specifies the point from which the offset is calculated. The possible values for `dir` are:

- ios_base::beg: the beginning of the file.
- ios_base::cur: the current position.
- ios_base::end: the end of the file.

If the offset is negative, the pointer moves backwards. Here's look at some examples:

```cpp
seekg(0, ios_base::end); // Move to the end of the file.
seekg(20, ios_base::beg); // Move 20 bytes from the beginning.
seekgp(-5, ios_base::cur); // Move 5 bytes back from the current position.
```

If we want to find the current position of the pointer we can use the tellg() and tellp() functions. tellg() returns a streampos, which represents the current position of the input pointer in bytes from the beginning of the file, or -1 if an error occurs. tellg() may be used with seek() to return to a previous file location, like this:

```cpp
// Store the location to which we want to return.
streampos old_pos = fin.tellg();
// ... move to another location to read.
fin.seekg(old_pos); // Return back to the first location.
```

Similarly, for the random access of a file that is associated with an ofstream object we use the seekp() and tellp() functions. As we said, an ofstream object contains an output pointer to write data to the file. Note that if seek() and seekp() are used with text files, care is required with the new line character(s). For example, suppose that the following code writes text '\n' to '\r' and '\n', the value of offset should be 6 in order to move to the beginning of the second line.

```cpp
cout << "text\n";
out << "another text\n";
/* Move to the beginning of the second line. */
out.seek(6, ios_base::beg);
```

> It is safer to use seekp() and seekg() with binary rather than text files, because translations of the new line character can produce unexpected results.
