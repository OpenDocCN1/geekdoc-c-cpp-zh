Since p points to the address of b, the f(b) of the B class will be called. Note that if f(f) was not declared as virtual, the f(f) of the A class would be called.

A class declared as virtual automatically becomes virtual in all classes declared directly or indirectly from it. That is, word virtual in the declaration of show() in the Book class is not needed. Any non-function, except the constructor, can be declared as virtual. Constructors, static functions, and function templates cannot be virtual. A friend function must be defined in the class in which it is declared for the first time, as we see in Chapter 21, it is declared as pure virtual function. That is not necessary to be redefined in a derived class that does not need its own version. If not defined, the version of the base class is used. If the derived class belongs to a long chain of derivations, the most recently defined version is used.

# Dynamic Polymorphism

So, with virtual functions, the decision about which version of the function will be called is not made during the compilation of the program, but during its execution. That is, with virtual functions, polymorphism is achieved dynamically at runtime and not at compile. This is because the compiler does not know when compiling the program (I refer to the general case and not to the previous code) the type of object that reference will refer to the pointer it will point to. Here is an example where the type depends on user choice:

```cpp
int a;
Product *ptr;
cin >> a;
if(a == 1)
    ptr = new Product("A", 1);
else
    ptr = new Book("B", 2, "Nice", "Many");
ptr->show(); /* When compiling the program, the compiler does not know the type
of object that the pointer will point to. It depends on the user's choice. */
```

What the compiler does is create code, which when the program runs, binds show() with Product::show() and with the Book::show(), depending on the type of object that ptr points to. Because the function is selected as the program, this selection method is called dynamic binding. The late binding is the typical way the compiler handles the virtual functions for each class to create an array, usually referred to vtable, which holds the memory addresses of the virtual functions of the class. Indeed, with virtual functions allocates more memory than the equivalent object with the same functions declared as non-virtual. When a virtual function is called, the compiler checks the type of the object, finds the function address in the vtable of the corresponding class, goes to that, and executes the code found there.

> For non-virtual functions the memory address of the called function is known when the program is compiled (static binding), while for virtual functions it is specified when the program runs (dynamic binding).

Make sure you understand the different processing of a virtual function from a non-virtual, let's look at another example. What does the following program display?

```cpp
#include <iostream> // Example 20.9
using std::cout;

class A
public:
    void f() const { cout << "A "; }
    virtual void g() const { cout << "A "; }
    void v() const { cout << "A "; }
};

class B : public A
public:
    void f() const { cout << "B "; }
    virtual void g() const { cout << "B "; }
    virtual void v() const { cout << "B "; }
};

int main()
{
    B b;
    A &r = b;
r.f();
r.g();
r.v();
return 0;
}
```

When a pointer or reference is used to call a function we check if the function is virtual or not. If the binding is static and we look at the type of the pointer or reference. If it is virtual, the binding is dynamic and we look at the type of the object pointer points to or reference refers to. Let's apply this rule to the program.

Since f is not virtual, the compiler uses static binding to select which version to call. Because the type of r is reference to class A, A.f() will be called. Since g() is virtual, dynamic binding is used. Because the type of b is the object referred by r is class B, B.g() will be called. The declaration of v() is virtual in the derived class and not in the base class has no effect. Thus, as a result, the program displays: A B A

Now, we've discussed virtual functions let's sum up. C++ supports:

- a. Polymorphism at compile time (e.g., templates).
- b. Polymorphism at runtime through virtual functions.

# Using the override and Final Specizers

C++11 introduced the word override as a safeguard against mistakes in the declaration of the virtual function in a derived class. For example:

```cpp
class Book : public Product
{
    void show() override;
    void show(); // Wrong
};
```

The word override is added at the end of the declaration and explicitly states that the class will override the inherited virtual function. Also, as with the word virtual, it is wrong to be added in a definition for the class.

```cpp
virtual void Book::show(); // Wrong
```

The use of override aids the compiler to spot such errors and inform the programmer. That is, if we:

```cpp
class B : public A
public:
    void f() const override { cout << "B"; } // Wrong, f() is not virtual.
    void g(int) const override { cout << i; } // Wrong, class A has no virtual function g(int).
```
