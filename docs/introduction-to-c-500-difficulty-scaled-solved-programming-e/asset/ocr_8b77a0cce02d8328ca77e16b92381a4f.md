# 662 Introduction to C++

```
class B : public A
{
public:
    virtual void f() const { cout << "B"; };
    virtual void g(int i) const { cout << i; }
};

int main()
{
    B b;
    A &r = b;

    r.f();
    r.g();
    return 0;
}
```

The programmer forgot to declare f() as virtual in A. The fact that it is declared as virtual in B has no effect. The program is compiled successfully and displays A. If f() was declared virtual, which was the actual intention of the programmer, to display B. As you can see, an oversight, which is easy to happen, not only affects the behaviour of the program but also, in a large application, it is an error difficult to spot.

Let's see the detection of g(i). Suppose that you intend to override g(i) in B and g(int) are different functions and have the same name but you made a mistake in the parameter list and added an extra parameter or forgot to add the const word. Both errors are critical, as a derived class function must have the exact signature in order to override a virtual base class. The compiler will not inform the programmer of this mismatch, because it allows a derived class to have a different signature with a virtual base class function, although they have the same name. It assumes that g(i) and g(int) are different functions and the program runs normally. It does not inform the programmer that the g(i) in B does not override the virtual g(i) of A. Therefore, the g(i) of A is called and the program displays again.

The use of override aids the compiler to spot such kind of errors and inform the programmer. That is, if we:

```
class B : public A
public:
    void f() const override { cout << "B"; } /* Wrong, f() is not virtual. */
    void g(int i) const override { cout << i; } /* Wrong, class A has no
virtual function g(int). */
```

In case of the compiler would display an error message to indicate that f(i) is declared to override the virtual function of the base class but there is no such function in A. Thus, the programmer understands that the virtual is missing in the declaration of f(i) in A. In case of g(i) the compiler would display an error similar to B::g() with 'override' specifier does not override a base class member. Since override prevents from potential errors that are difficult to detect, we will use it from now on overriding virtual functions. It is not hard, so just add the override word at the end of the declaration; it may save us from a lot of trouble, especially in large and complicated hierarchies.

For more safety it is recommended to use the override specifier when you override a virtual function in a derived class. This enables the compiler to detect mismatches in the function signature in the base and derived classes. If you ever change the signature of the base class function, it protects you from forgetting to change the function signatures in the derived classes.
