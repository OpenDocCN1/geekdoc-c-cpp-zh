For those who have experience with C, because C does not support overloading, in order to get the same result, we should have three functions with different names as abs(), fabs(), and labs(). Note that the order of the overloaded functions does not affect the selection of the appropriate version.

Notice that the only the signature, and not the return type, allows functions to be overloaded. Remember, in order to overload a function, the functions must have different signatures, that is, different number of parameters or types, or both. The compiler does not examine the return types. For example, the signature of the third abs_v() is int(int, int). Therefore, if we add the following abs_v():

```
int abs_v(int a, int b);
```

the compiler will display an error message for two versions with the same signature.
Before overloading, check if you can get the same result by using default arguments. For example, instead of declaring the three overloaded functions:

```
int f(int a, int b);
int f(int a, int b, int c);
 f(int a, int b, int c, int d);
```

to calculate the sum of their arguments, we could declare a single function with default arguments. For example:

```
int f(int a, int b = 0, int c = 0, int d = 0);
```

And it is definitely better to declare a single function, because you have to write code for just one and if you ever need to change it'll make the changes in one place. Also, the compiler allocates memory for one function instead of three.

# Ambiguous Situations

There are cases where functions with signatures that look different cannot be overloaded. For example:

```
int f(int a);
int f(int& a);
```

When f() is called (e.g., f(i)), the compiler cannot decide which of the two to call. To avoid this ambiguity, when the compiler examines the signatures it considers that the reference to a type and the type itself have the same signature. The compiler will display an error message in the f() call similar to ambiguous call to overloaded function.

Ambiguity may arise if the arguments in the function call do not exactly match prototype. For example:

```
int f(double a);
void f(char *a);
int f(int a);
int f(long a);
```

What will the compiler do in a call such as f(i) if i is declared as float? When no prototype matches the function call, the compiler applies the conversion rules, and if ambiguity arises, it selects the closest match. Thus, i is converted to double and the first f() is selected. What happens if i is unsigned int?
