The application provides a menu of choices and simulates the message exchange between the two parties to establish and release calls. Each message is identified by a unique code and specific information. For example, the code of the SETUP message is 5 and it contains several information elements, such as the phone number of the calling user. Having the object-oriented philosophy in mind, we represent each call by an object. Each call is identified by a unique number, which is named CRV (Reference Value). For simplicity, let's assume that each message contains only its code and the CRV.

The usual choice for the file that contains main() is the name of the application, example, prctl.cpp. We split the functionality of the program into several modules. Each of the following source files represents a module:

prctl.cpp. It contains functions which interfaces the interface with the upper and lower layer. It parses and forwards the messages it receives to the fsm.cpp. The concept of layers is described in Open Systems Interconnection (OSI) model, a reference model which describes how an application that runs in system A can communicate, through a network, with another application than runs in system B. A layer may be implemented in software or hardware. For example, the lower layer might be the driver of the network card or the card itself, the upper layer might be an application which provides the means to communicate with another system (e.g., web browser). In our program, the upper layer is a simple console application which provides a menu of choices to the user.

fsm.cpp. It contains the function which implements the protocol finite state machine. Each call is in a state. For example, when the SETUP message is sent (i.e., to establish the call), the call goes to the INIT state. In this state, the CONNECT message (sent by the user) is received, the call goes to the ACTIVE state, which means that the call is established. When the RELEASE message is sent (i.e., to release the established call), the call goes to the RELEASE_INIT state, and when the RELEASE_COMPLETE message (sent by the user) is received, the call is released.

send.cpp. It contains the function which creates messages and sends them to the lower layers. Also, here simulate the side of the called side by sending the CONNECT and RELEASE_COMPLETE replies.
