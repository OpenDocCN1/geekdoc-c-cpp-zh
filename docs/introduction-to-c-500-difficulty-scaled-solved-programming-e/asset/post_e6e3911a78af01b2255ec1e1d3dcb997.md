## MEMBER INITIALIZATION LIST

As we know, one method to initialize class members is within the body of the constructor. For example:

```cpp
class T
{
private:
    int a;
public:
    double b;
    string s;
    T(int arg1, double arg2);
};
```

```cpp
T::T(int arg1, double arg2)
{
    a = arg1;
    b = arg2;
    s = "Text";
}
```

Alternatively, class members can be initialized with a special syntax when the constructor of the class is called. This syntax is called member initializer list. For example:

```cpp
T::T(int arg1, double arg2) : s("Text"), a(arg1), b(arg2)
```

Notice that this member initializer list syntax can only be used with constructors, not with member functions. As shown, a colon is added and the comma is used to separate the member and we write the name of the member and its initial value in parentheses. Thus, Text is stored in s, a becomes arg1 and b becomes arg2. Note that these initializations happen when the object is created and before the body of the constructor is executed.

Although it is logical to think that initializations are made from left to right, that is, first s is initialized and the rest, the first is that members are initialized in the order in which they appear in the class declaration, that is, first a, then b, and last s. In general, the initialization order plays no role. But if one value of member is related to the initialization of another then it may have an effect. For example:

```cpp
class C
{
    int a;
    int b;
    C(int m) : b(m), a(b) {}
};
```

```cpp
int main()
{
    C c(10);
    ...
}
```

When the c object is created, first a will be initialized with the random value of b and then b will become equal to 10.

To avoid unintended initializations it is safer to initialize the list members in the same order in which they are declared in the class. In fact, it is better to use members to initialize other members.

A typical of the member initializer list is to initialize const variables. Recall from Chapter 17 that because the definition of the class does not allocate memory for its members we cannot initialize a const member. However, we can use this syntax and initialize it. For example:

```cpp
class T
{
    const int k; // It is not allowed to write const int k = 10;
}
T::T(int arg1, double arg2) : a(arg1), b(arg2), k(10)
{}
```

When the constructor is called, k becomes 10. With const members, we can use this syntax to initialize reference variables. For example:

```cpp
int g = 20;
class T
{
    int &r; // It is not allowed to write int &r = g;
    ...
}
```

```cpp
T::T(int arg1, double arg2) : a(arg1), b(arg2), r(g)
{}
```

> We can use the member initializer list syntax to initialize const members and references.

When the constructor is called, r becomes 20. If the member is pointer, it can also be initialized. For example:

```cpp
class T
{
    int *p;
    ...
}
```

```cpp
T::T(int arg1, double arg2) : p(new int[arg1])
{}
```

To make clearer the initialization, I prefer to initialize the ordinary variables in the body of the constructor and not all mixed together in the same line. For example:

```cpp
T::T(int arg1, double arg2) : k(10), r(g)
{
    a = arg1;
    b = arg2;
    s = "Text";
}
```

Others prefer to initialize all members in the list. One reason is to avoid compilation errors that may occur with members that require initialization (e.g., const). A second reason is for better performance. For example, in the previous approach, the default constructor of the string class is called first to initialize with an empty string, and then the copy function is called to assign the Text to it. Yes, it is more efficient to initialize it in member list since the copy constructor of the string class, we'll see below, makes directly the initialization. Note that for basic types (e.g., a) there is no difference in the performance whether the initialization is done in the list or in the body of the constructor.

## FORWARDING CONSTRUCTOR

C++11 extends initialization capabilities by providing the forwarding constructor. During the process of creating an object, such a constructor calls another constructor of the class to delegate a task. This is why its common name is forwarding or delegating constructor. Let's see an example:

```cpp
int n1 = 5;
int n2 = 10;

class T {
private:
    int x;
public:
    T(int a, int b) {x = a+b;} // Non-forwarding constructor.
    T() : T(n1, n2) {} // Forwarding constructor.
    T(int a) : T(a, n2) { cout << "Delegate\n"; } /* Forwarding constructor. */
    void show() const { cout << x; }
}
```

The two constructors call the first one. When a forwarding constructor calls a second constructor, the body of that second constructor (e.g., x = a+b) will be executed first and then its own (e.g., cout << "Delegate\n"); creation of the object is completed. As shown, the syntax of forwarding constructor is similar to that of the member list except the list must contain only one item, which is the target. That is, it is not allowed to initialize extra members. For example:

```cpp
T() : T(n1, n2), x(10) // Wrong
```

Typically, a constructor is called by others when they need to perform a common set of actions. For example, we could change the class to:

```cpp
class T
{
private:
    int x;
public:
    T(int a, int b) {x = a+b};
    T() : T(n1, n2) {x = 10};
}
```

Comparing the two implementations, I think that it is more readable and safer for the code to exist in a single place than to be repeated, so that if a change needs to be made you have to edit it once. Thus, forwarding constructors can simplify the construction process and make it easier to control. Notice that this method of calling the constructor works differently from the explicit call of the constructor inside the body. For example, if you write something like:

```cpp
T()
{
    T(n1, n2); // Creation of unnamed object
}
```

the constructor will not be called as you intended, but a temporary object will be created, which will not be used. That is, if we write:

```cpp
int main()
{
    T t;
    t.show();
    return 0;
}
```

the program will display a random value for x and not. ## COPY CONSTRUCTOR

The copy constructor is a special function that is automatically invoked whenever a new object is created and initialized with an existing object. For example:

```cpp
#include <iostream>
class T
{
private:
    int a;
public:
    int b;
    T(int i, int j) {a=i;b=j};
    void show() const {std::cout << a << ' ' << b << '\n'};
};
```

```cpp
int main()
{
    T t1(1, 2);  // The copy constructor is called.
    T t2(t1); // The copy constructor is called.
    T t3 = t1; // The copy constructor is called.

    t2.show();
    t3.show();
    return 0;
}
```

As the compiler defines the default constructor if no constructor is defined, the default destructor if no destructor is defined and the default copy function, it provides the copy constructor if none is defined. Thus, to create the t2 and t3 objects, the copy constructor is called. And what does this constructor do? As its name implies it copies non-static members of the existing object into the new one. For example, with the statement t2(t1); the compiler copies the existing object and calls the copy constructor to copy the members of t1 to t2.

This also allows shallow copy. Each member will depend on its type. The basic types are copied directly, its array elements are copied and if it is an object the copy constructor of its class is called to make the copy. Similarly, with the T3 = t1; statement, which is an alternative to T3(t1); the copy constructor is called and copies the members of t1 to t2. If the class contains members that are not affected since they belong to the class and not to an object, the program displays the value twice.

Note that in one assignment, as t2 = t1; it is not the copy constructor that is called, but the default copy-function, which copies the members t1 to t2. To make it clear, the copy constructor is called when the object is created (e.g., T2(t1)); whereas the object already exists (e.g., t2 = t1); the copy function is called.

## Define Our Copy Constructor

There are some situations that we need to define our copy constructor. The typical situation is when the class contains pointer(s); we'll see examples later. Fine, how do we declare it? The copy constructor has the same name as the class, it has no return type, and takes as a parameter reference to an object of the respective class. The usual convention is to declare the reference as const, in the sense that the copy constructor creates a copy of object without modifying it. If we make it const, it would not be allowed to pass a const object, so we could not copy objects. A reference to const allows const and non-const objects to be copied. After all, the parameter should be a const reference, the job of the copy constructor, as its name indicates, is to make a copy, not to change the original object. In fact, the parameter type for a default copy constructor of any class is a const reference. For example, the prototype of the default copy constructor for the class T is:

```cpp
T(const T&);
```

As an implementation example of our copy constructor, if we add the following in the class definition:

```cpp
T(const T&) { std::cout << "In\n"; }
```

this copy constructor will be called. Then, the program will display 1 twice and junk values for the members of t2 and t3.

Of course, it is allowed our copy constructor to call another constructor or have initialization list as we saw earlier. For example:

```cpp
T(const T& t) : T(t.a, t.b) {}
```
