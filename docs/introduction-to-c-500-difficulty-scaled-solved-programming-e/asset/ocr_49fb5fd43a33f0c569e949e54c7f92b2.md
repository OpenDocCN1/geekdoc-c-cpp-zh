The first approach uses the index of the element, while the second one uses the name of the array as a pointer. My preference is to use array subscripting rather than pointer arithmetic. The reason is to get a clearer and less error code. In order, I consider that arr[i] is easier to read and safer than *(i). For example, the lack of parentheses introduces a bug, which is not so easy to trace. because both are popular, you must learn and use both of them. In terms of performance, the optimizations that to dated advanced compilers make produce the same efficient code, no matter how you write.

The important thing to remember is that the compiler converts arr[i] to *(arr+i). We could say that arr[i] is an elegant shortcut for *(arr+i). You'll encounter a really weird application of this rule in exercise later. The trap has been set and is waiting for you!

The following program uses another variable to display the values and addresses of array

```
#include <iostream> // Example 8.13
int main() {
    int *ptr, arr[5] = {10, 20, 30, 40, 50};
    ptr = arr;
    for(i = 0; i < 5; i++) {
        std::cout << "Addr: " << ptr << " Val: " << *ptr << '\n';
        ptr++; /* ptr becomes equal to the memory address of the next array element. Equivalently, we can write ptr = &arr[i]; */
    }
    return 0;
}
```

The statement ptr = arr makes ptr to point to the first element, while each execution of ptr++ makes ptr to point to the next element. I don't write that ptr = &arr; because the type of &arr corresponds to a pointer to array, while ptr is a pointer to integer. It's a compilation error.

> Tip: When the name of an array is used as a pointer, C++ treats it as a const pointer. Therefore, it is not allowed to change its value and make it somewhere else. An array is not modified value; its value will be equal to the memory address of its first element.

Therefore, if we write arr++; or arr = &i; in our last example, the compiler will display an error for illegal allocation. Now, you can understand why I told you in Chapter 7 that it is illegal to write b = {}; in order to copy the elements of the array into b. However, it is allowed to copy its value in a pointer variable, as we use ptr = arr; and use the pointer to access the elements.

Although arrays and pointers are closely related, it is clear to note that an array is not a pointer and vice versa. For, de example, the declarations int a[50]; and int *a; are different. With the first declaration the compiler allocates memory for 50 integers. The array can be filled with different values at different times, but the name always refers to the same memory address. As said, it is not possible to assign a new value, if it is illegal to write a = arr. With the second declaration the compiler allocates memory to store the value of the pointer (e.g., typically 4 bytes). Unlike the array, it is allowed to assign a new value to the pointer and make it somewhere else, for example, it is legal to write a = arr.
