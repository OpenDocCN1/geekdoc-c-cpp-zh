# References to const

A reference can be associated with a const variable. The reference must be declared as a reference to const. Of course, such a reference cannot be used to change the value of the referred variable. For example:

```cpp
const int a = 10;
const int& r1 = a; // Correct.
r1 = 20; // Wrong, it is not allowed to change the value.
int& r2 = r1; // Wrong, r2 is not a const reference.
```

If the last statement were allowed we could use r2 to change the value referred by r1, that is, value of a. A reference to const can refer to a non-const variable or constant expression. It is not allowed to change the value of the non-const variable through the reference. For example:

```cpp
int a = 10;
const int r1 = a; // Correct.
const int r2 = 20; // Correct.
const int& r3 = &a; // Correct. 
a = 30; // Correct, the variable is not const.
r1 = 30; // Wrong, it is not allowed through the reference.
```

# References as Function Parameters

As we've learned, when we want a function to change the value of an argument we pass a pointer to the corresponding variable. An alternative is to pass a reference to it. For example:

```cpp
#include <iostream> // Example 16.5

void test(int& a, int& b);

int main()
{
    int i = 10, j = 50;

    test(i, j);
    std::cout << i << ' ' << j << '\n';
    return 0;
}

void test(int& a, int& b)
{
    a = 100;
    b = 200;
}
```

When a reference to a variable is passed to a function, it is the memory address of the variable that is actually passed. The function can access the value of the calling function. For example, when test() is called, the variable is passed by reference. In this method, of passing data is named call by reference. The & operator is only added to the function, not called. When test(), a refers to i, that is, a is used as if. In other words, a is an alias of, not a copy of i. On the contrary, we acknowledge, the variable j is passed by value, that is, b is copy of j. So, the value of j does not change and the program displays: 100 50

If we do not want the function to be able to change the original value we make the reference const. For example, we write:

```cpp
void test(const int& a, int& b);
```

the statement a = 100; is not allowed. The declaration of a reference-argument const prevents any change in the value of the referred.
Using reference parameters instead of pointers may seem simpler and easier to understand. However, in such cases we use pointers, so that the arguments that we want change are clearly shown. For example, when using references a call such as f(i, j, k) gives no clue to the reader if f() can change the values of all, or none of the arguments. The only way to learn it is to look for the function prototype or its definition. Instead, if we use pointers and f(&i, j, k), the reader would conclude that f() may only change the value of i. Also, it is very easy to spot the * dereference operator inside the function and finds the places where the value of the argument changes. Thus, it is much easier to control the code. On the other hand, when the function returns a pointer and we intend to dereference it should check that it is not a null pointer, otherwise the program crash. This cannot happen with references, because a reference always refers to a variable; there is no null reference. Of course, I may prefer pointers I started programming with C and C does not support references. C uses pointers to access the original data. Had I started with C++, I might have preferred references, thus their use is simpler.

In the question when to use a pointer or a reference, what I usually do is use pointers when passing basic types (e.g., int), unions, and because C++ often requires references in class design, I use references when classes are passed to the function. Of course, this is just my preference, and there might be reasons to make different choices. Regardless of your choice, what is certain that you should know both ways, because both are quite popular.

And as you know from Chapter 13, when large entities are passed to the function, such as structures and classes, we choose to pass a reference or pointer even if the copy is not going to modify them. The reason is to save time and memory required to make a copy of the original entity. Thus, the performance of the program is improved. For simple variables, such as basic types, the typical choice is the call by value, as long as we do not intend to modify the original values.
