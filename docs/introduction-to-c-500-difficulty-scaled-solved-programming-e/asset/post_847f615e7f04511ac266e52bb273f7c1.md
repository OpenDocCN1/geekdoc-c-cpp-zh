The reason to define a destructor is when we want to do something when an object is destroyed. If nothing needs to happen, then the default destructor, as we'll see later, is sufficient. For now, can you tell me what does the following program output?

```cpp
#include <iostream> // Example 17.5

class Test {
public:
    int a, b;

    Test();
    Test(int i, int j);
    ~Test();
    void check();
};

Test::Test() {
    std::cout << "First\n";
}

Test::Test(int i, int j) {
    std::cout << "Second\n";
    a = i;
    b = j;
}

Test::~Test() {
    std::cout << "Out\n";
}

void Test::check() {
    Test t;
}

int main() {
    Test t1, t2(5, 10);

    std::cout << t1.a << ' ' << t1.b << '\n';
    std::cout << t2.a << ' ' << t2.b << '\n';
    t1.check();
    return 0;
}
```

As we said, the constructor and the destructor do not have a return type. Because there are two overloaded constructors, the compiler selects the appropriate one depending on how each object is created. We'll see next, a constructor that does not accept any parameters is called a default constructor. When the t1 object is created the first constructor is called, the program displays First. The variables a and b of t1 are initialized with garbage values. In fact, it was my intention to initialize them in order to that they have garbage values; don't forget to initialize data members unless unexpected problems occur when you use them.

Constructors follow the same overload as ordinary functions. The compiler checks the types of arguments to select the appropriate one. Therefore, when t2 is created, the second constructor is called, the values 5 and 10 are passed, and the program displays the garbage values of a and b of the t1 object and the values 5 and 10 for the respective ones of t2. When check(), the object is created and the first constructor is called. check() terminates and t ceases to exist. Therefore, the destructor of t is automatically called, which displays the message Out.

When the program ends, the destructors of t1 and t2 are called and the program displays out more times. Let's see in what order the destructors are called. Because the memory for variables t1 and t2 is reserved on the stack, the last object is destroyed. The destructor of t2 will be called first and then of t1. If we have an array of objects, Test[10]; the destruction order will be from the last to the first, that is, t[9]...t[0].

The non-static members of the class are automatically destroyed when the destructor is executed. If a member has a class type, the corresponding destructor for class will be called. For example, in the C.17.1 example, the destructor of the string class will be called to free the memory reserved for the name member outer the object is destroyed.

## Calling the Constructor

First of all, we cannot use an object to call a constructor, as we can call a function of class (e.g., t1.check()), because the object has not been created yet. The constructor is used to create the object. If we want to pass values, the most common way is as we did with the t2 object. We can also call the directly constructor such as:

```cpp
Test t2 = Test(5, 10);
```

t2.a becomes 5 and t2.b becomes 10.

Since C++11 we can use the braces {} to pass the initial values to the constructor. For example: Test2(5, 10);

As said in Chapter 2 this method is preferable, as the compiler can inform us about incompatible values.

Note that the dynamic creation of an object with the new operator also invokes the constructor. For example:

```cpp
Test *p = new Test(5, 10);
```

In this case, the *p represents the object and the p pointer can be used to manage the object. In general, an initialization statement such as:

```cpp
class_name *p = new class_name(value);
```

invokes the constructor class_name(type_name), where the type_name is the type of the value. To be more precise, as it first triggers the call of the operator new function to allocate memory for the object, and then invoke the constructor. When we use the delete operator to destroy the object (e.g., delete p) first destructor will be invoked, and then the memory used for the object will be released.

Similarly, a statement such as:

```cpp
class_name *p = new class_name;
```

invokes the default constructor, that we'll see next.

```cpp
Test *p = new Test;
```

If a constructor accepts a single argument, it is allowed to initialize an object with a value of the same type as the argument.

## Default Constructor and Destructor

The existence of a constructor is essential for the creation of objects. But one, might ask how Student objects created in our first example, since no constructor is defined? The answer is if a class does not contain any constructor, the compiler automatically provides the default constructor, which has no body. Without this constructor, we would not be able to create Student objects. Each time a Student object is declared, the compiler calls the default constructor to create the object. The default constructor does not initialize members of basic types (e.g., int). It also calls the constructors of the respective classes for members that are objects. Similarly, if the destructor is not defined, the compiler provides the default destructor which has no body. For example, the default constructor and destructor for the Student class are:

```cpp
Student::Student() {} and Student::~Student() {}
```

As you see, both of them take no arguments and do nothing.

> The compiler automatically provides the default constructor only if no other constructor is defined.

For example, if you define the constructor Student(const string& n, int c, float g); it is your responsibility to define your own version of the default constructor, if you need it. If you don't, then a declaration as s:

Student is unacceptable and the compiler will display an error message similar to No default constructor available. If you write:

```cpp
Student s("P.Lew", 100, 5.5);
```
