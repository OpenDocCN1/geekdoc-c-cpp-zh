When defined, it is not a member of the class, the scope resolution operator :: : and the class name are not added. When it comes to declare friend functions, it is a common practice to group them at the beginning or end of the class (I prefer it to stand out). Let's look at the following program:

```
#include <iostream> // Example 17.4

class T
{
private:
    int a;
public:
    void show() { std::cout << a << '\n';
    friend void f(T& t);
};

void f(T& t) // The friend keyword is not added in the definition.
    t.a = 10; // It is an error to write a e = 10;
}

int main()
{
    f(t);
    t.show();
    return 0;
}
```

Since a friend function is not a member of the class t and we don't add the T:: in the definition of f(). To make it, we declared it a member of T. For the same reason, f() is not a member of T and the compiler would display an error message similar to `not a member of T`. members by just using their names. Notice that the friend keyword is added to the definition, unless it is defined inside the class. As we said, that friend allows access to access its private member function. Thus, it is allowed to access the private member and the program displays 10.

A friend function can be a global function in this example or it can be a member of another class. One may ask, is it necessary to declare f() as friend, we can't declare it an ordinary function outside the class? Or we can, but since a is private it is not allowed to access it. So, we need to add a public function to the class, when called to change the value of a. For example:

```
class T
{
public:
    void set(int i) {a = i};
};

void f(T& t)
{
    t.set(10);
}
```
