
```cpp
template <typename T> void do_swap(T& a, T& b)
{
    T tmp;

    tmp = a;
    a = b;
    b = tmp;
}
```

The first call of do_swap(). T is replaced with int and in the second call with double. program displays: 2 1 5.6 3.4
Note that the arguments must have the same type, as the compiler expects to replace T with the same type. That is, if we write

```cpp
do_swap(a, c); // Wrong.
```

The compiler will display an error message. Someone might wonder, the compiler does not do the usual arithmetic conversions. The answer is no. In particular, it converts an array or function argument to a pointer and points to a parameter that is a reference or pointer to non-const. For example

```cpp
template <typename T> void f(T a);
template <typename T> void g(const T& a);
int arr[10];
f(arr); // Correct, the array is converted to a pointer to its first element and the type T becomes int*.
string s="one";
g(s); // Correct, it is allowed to pass a non-const reference argument to a const type.
```

When you pass an array of characters to a function template does not mean that it will work for all types. For example, if you pass an array of characters to do_swap(), the compiler will display error messages for not allowed assignments:

```cpp
char s1[10] = "one";
char s2[10] = "two";
do_swap(s1, s2); // Wrong.
```

One way to solve this problem is, to you will see in the next section, overloaded version with the corresponding types. For example:

```cpp
void do_swap(char a[], char b[])
{
    char tmp[10];

    strcpy(tmp, a);
    strcpy(a, b);
    strcpy(b, tmp);
}
```

Also, when writing function template, the code may not support certain operations for some types or provide meaningless results. For example:

```cpp
template <typename T> int cmp(const T& a, const T& b)

    return a < b ? 1 : 2;

```

If we pass numeric values to cmp() it will work as expected, but if we pass two arrays, it will compare their addresses, not the elements. If we pass a user-defined type, such as a class, cmp() will work only if the class overloads the < operator, as seen in Chapter 18. Otherwise, the compiler will display an error message.

# Template Parameters with Different Types

The template parameters can have different types. For example, let's write a function template that displays the layers of two types:

```cpp
#include <iostream> // Example 16.13

template <typename T1, typename T2> void f(T1 a, T2 b)

int main()
{
    int i = 10, j = 20;
    float k = 1.23;
    double p = 5.64;

    f(i, j); // T1=int, T2=int;
    f(p, i); // T1=double, T2=int;
    f(j, k); // T1=int, T2=float;
    return 0;
}

template <typename T1, typename T2> void f(T1 a, T2 b)
{
    if (a < b)
        std::cout << a << '\n';
    else
        std::cout << b << '\n';
}
```

For the example shown above, the compiler replaces the T1 type with double, the T2 type with int, and the resulting definition is:

```cpp
void f(double a, int b)
{
    if (a < b)
        std::cout << a << '\n';
    else
        std::cout << b << '\n';
}
```

One problem that may occur when writing a template that you't know what type to use in a declaration. Let's change f() to assign the sum of its arguments to a variable:

```cpp
template <typename T1, typename T2> void f(T1 a, T2 b)
{
    auto sum = a+b;
}
```

What will be the type of sum? Since we do not know in advance how f() will be used we cannot specify the type. If T1 is double and T2 is int, sum must be declared as double. However, if T1 is short and T2 is int, sum must be declared as int. One way to solve this problem is to use the auto specifier. Alternatively, we can use decltype specifier. For example:

```cpp
template <typename T1, typename T2> void f(T1 a, T2 b)
{
    decltype(a+b) sum;
}
```

The type of sum becomes the same as a+b. The next question is, and what if the function template returns a value whose type depends on the arguments? For example, what should the return type be? The solution is to use the auto specifier as we saw in Chapter 11, when we discussed deduction of types. See the program:

```cpp
#include <iostream> // Example 16.14
template <typename T1, typename T2>
auto f(T1 a, T2 b)
{
    auto sum = a+b;
    return sum;
}

int main()
{
    int a = 1;
    double b = 2.3;

    auto c = f(a, b);
    std::cout << c << "\n";
    return 0;
}
```

The word auto is put in the place of the return type. Absolutely fantastic, what a nice feature is the type deduction! The type will be deduced from the arguments when the function is called. Thus, the return type becomes double.

# Set Types of Template Parameters

There are cases where we may want to not explicitly the type of a template argument. Such a case is when a function returns a value whose type differs from the types of its parameters. For example:

```cpp
template <typename T1, typename T2, typename T3> f(T2 a, T3 b);
```

When we call f<> specify the T1 type. The T2 and T3 types will be deduced from the values of its arguments. If we write:

```cpp
int i;
double j;
f<int>(i, j); // f(int, double);
```

The T1 will be replaced by int and the compiler will determine the T2 and T3 types from the types of the corresponding arguments. When template arguments are explicitly set, each argument (e.g., int) corresponds to the respective template parameter (e.g., T1) from left to right.

# Use of Non-Type Parameters

A function template can accept the following parameters:

- Types
- Integer types (e.g., int).
- Pointers and references to a function or an object type.
- Pointer to a class member.
- Enumeration type.

The number of parameters can be fixed or variable, as we'll see below. The most common parameter is the one encountered so far, the template. Let's look at some examples again:

```cpp
template <typename T> void f(T& a);
double d = 2.3;
f<double>(d); // T becomes double.
vector<int> v;
f(v); // T becomes vector<int>.
```

A non-type parameter represents a value instead of a type. The values of the non-type arguments should be determined at compile time. A typical use of integers is when we want to specify the size of a memory:

```cpp
template <typename T, int size> f(T& a)
{
  T arr[size]; // The size of the array is specified.
  arr[0] = a;
  size = 20; // Wrong.
}
```

```cpp
int i = 5;
f<int, 10>(i); /* T becomes int, size becomes 10 and arr[0] becomes equal to i, that is, 5. */
```

A parameter value is considered constant within the function and we are not allowed to change its value. That is, it is error to write size = 20. We'll discuss more non-type parameters in the corresponding section in Chapter 23.

# Default Parameter Values

As ordinary functions, we can set default values to the parameters of a function template. For example:

```cpp
template <typename T1, typename T2 = int> void f()
{
  T1 i;
  T2 j;
  ...
}
```

If the type of T2 is omitted, we write f<double>(); the type of T1 will be double and the type of T2 will be int.
We can also specify default values for non-type parameters. For example:

```cpp
template <typename T, int s = 20> void f(){...}
```

If we write f<int>(); the type of T will be int and s equal to 20.

# Explicit Instantiation

In addition to the implicit instantiation we can instruct the compiler to create the function definition directly. This type instantiation is called explicit instantiation. An explicit instantiation begins with the word template without the <. The types are contained inside < For example, if we add the statement in C.16.11:

```cpp
template int abs<int>(int a);
```

the compiler will an instance of the abs() function to create directly a definition using the int type. Explicit instantiation also occurs if the function is used in the program. For example:

```cpp
double c = 3.4;
cout << abs<double>(c) << '\n';
```

This creates an explicit instantiation for the double type. If the specified type does not match the type of the argument, the compiler will attempt a type conversion. For example, if we write:

```cpp
cout << abs<int>(c) << '\n';
```

the compiler makes an instance of the int type. Thus, c is converted to int and the code outputs 3. So, be careful with type mismatches, because the compiler may provide an undesirable implicit conversion.
