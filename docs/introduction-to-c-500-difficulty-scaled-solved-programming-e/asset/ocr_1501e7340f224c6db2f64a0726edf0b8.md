To answer the question in question whether to use the while or the for statement, given that both produce elegant code, I would say that it is a matter of personal preference. Typically, the while statement is used when the number of the iterations is unknown or a condition is directly tested without initializing a variable or using a step.
When the number of iterations is a step and is used, it is preferable to use the for statement, because its compact form makes the loop easier to read. However, there are cases where the for statement, although it may seem the best option, can produce "inelegant". The code of for in exercise C.7 is such an example. If the user enters a wrong value, the step changes inside it the body (e.g., i--), which is something that I consider "inelegant". If this for statement is replaced with a while statement, the code becomes more elegant. Do it and see the difference.
If exp is true the loop is executed forever, unless its body contains an exit statement (e.g., break). For example, the following loop is infinite:

```
while(1)
    cout << "One\n";
```

By convention, most programmers use the value 1 or true to create an infinite loop. However, any non-zero counter can be used. When a program continuously reads data until a condition becomes true, I prefer to use an infinite loop. For example, let's read integers:

```
int i;
while(1)
{
    cout << "Enter number: ";
    cin >> i;
    ...
}
```

Others prefer not to prompt the user to enter data and put the cin statement in the while condition:

```
while(cin >> i)
{
    ...
}
```

In this way not only the value is entered but the loop condition of the cin is also checked. If something goes wrong, the condition becomes false and the message about what to enter and then the loop ends. I prefer the first way, that is, first guide the user with an appropriate message. If we want to check the state of the input stream, we can do it after the input. As I mentioned in Chapter 3, for the sake of brevity and simplicity, I omit such checks.
