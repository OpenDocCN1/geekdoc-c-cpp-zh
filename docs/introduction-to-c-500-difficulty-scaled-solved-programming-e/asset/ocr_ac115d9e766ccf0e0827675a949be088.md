As you see, there are no many things left to do with ptr. Essentially, what is left is to test the pointer value. And yes, that's a very rare declaration to see in practice. Here is an example to have in mind something similar:

```
const char* const days[] = {"Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"};
```

The outer const prevents the modification of the strings, while the inner prevents the pointers to point somewhere else. We'll discuss array pointers later in this chapter.
Here is a question for you, is the following code correct?

```
const int i = 10;
int *p = &i;
```

Of course, the second statement won't compile. Why? If allowed, we could use the pointer to change the value of i (e.g., *p = 2;) and violate its const nature. The address of a const variable can only be stored in a pointer to const. That, we must write: const int *p;

# Pointers and Integers

The standard says that adding or subtracting an integer from a pointer is guaranteed to produce reliable results only if the pointer points to an array, otherwise the result is undefined. Suppose a pointer variable ptr points to an element of an array. The addition of a positive integer n in an assignment such as:

```
ptr = ptr + n;
```

increases the value by n*size of the pointer's data type and makes the pointer to the address of the n-th element after one to. For example, if ptr points to the array arr[i] and n is 3, ptr will point to arr[3]. In Chapter 2, ptr is declared as a pointer of int or float, its value is increased by n*4, since the size of both types is four. If it is a char array, its value is increased by n*1, while if it is a double array, it is increased by n*8. After adding the integer to the pointer, the pointer must point to an array element or the first place past the end which is considered a valid result. Let's see the following program:

    *ptr = 10;
