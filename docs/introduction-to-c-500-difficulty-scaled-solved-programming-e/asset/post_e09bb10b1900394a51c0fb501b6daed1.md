
Let's see an example of memory leak:

```
void f()
{
    int *ptr = new int[10000];
    ptr = new int[200];
    ...
    delete[] ptr;
}
```

In this example we forget to release the first memory block before the new allocation. This is a memory leak, which occurs every time f() is called.
Another common example of memory leak is when we allocate memory in one place and forget to release it in another place where it is supposed to do so. For example:

```cpp
double* f(int size)
{
    return new double[size];
}
```

```
void g()
{
    double* p = f(10000);
    /* Do some stuff with p, but then we forget to release the memory allocated in f(). */
}
```

When g ends, the local variable p is automatically destroyed, the memory it points to is not automatically released. We have to do it explicitly by calling delete[] p. As you guess, in complex and large programs when memory is allocated in one part of the program and released in another part, the programmer may forget to do so and create a memory leak that is difficult to sort. To avoid such leaks, we'll see in Chapter 25, a safer practice is the use of smart pointers. That is, if we use a smart pointer in place of p the memory will be released automatically.

Another usual of memory leak occurs when we assign one pointer to another, but we forget to release the memory to which the original pointed. For example, find the errors in the following program and fix them:

```cpp
#include <iostream> // Example 14.6
int main()
{
    char *p1, *p2;

    p1 = new char[10];
    p2 = new char[10];
    p1 = p2;
    delete[] p1;

    p2[0] = 'a';
    delete[] p2;
    return 0;
}
```

# 14 Memory Management and Data Structures

Let's see the problems:

- a. The statement p1 = p2; makes p1 and p2 to point to the same memory. The statement delete[] p1; releases this memory, so, the next statement assigns a value to a non-allocated memory.
- b. The statement delete[] p2; releases memory already released.
- c. The first block of memory pointed to by p1 was never released.

Note if we add the statement delete[] p1; before the p1 = p2; the program operates normally.
One, find the errors in the following program and fix them:

```cpp
#include <iostream> // Example 14.7

struct Test
```

Are t->i[0] = 'a' or t->c[5] = 50? Certainly, we just assign two integers. What about the loop? Not wrong with that, if we use array subscript to display the existing values. What about the memory release? Well, here is the bug. First we have release the memory allocated for the members of the structure and then the memory for the entire structure, not the other way around. Therefore, we must delete t; at the end.

As we will see in Chapter 25 another safe practice to avoid problems with the dynamic memory management is to use smart pointers. Once more, using either a container class (e.g., vector) or a smart pointer is a much safer approach than manipulating memory directly. Then, you don't have to worry about potential dangerous situations, such as dangling pointers and memory leaks. # MEMORY MANAGEMENT FUNCTIONS

This section discusses briefly the memcpy(), memmove(), and memcmp() functions that are often used for memory management. memcpy() is used to copy any type of data from one memory region to another. It is declared in cstring:

```cpp
void *memcpy(void *dest, const void *src, size_t size);
```

memcpy() copies bytes from the memory pointed to by src to the destination pointed by dest. If the source and destination addresses overlap, its behaviour is undefined. For example, the following code allocates memory for "ABCDE" string in it:

```cpp
char *arr = new char[6]; // Allocate one extra byte for the null character.
memcpy(arr, "ABCDE");
```

The main difference with strcpy() is that strcpy() stops copying when the null character is. On the other hand, memcpy() does not stop copying until the number of specified bytes are filled. For example, if we:

```cpp
char str2[6], str1[] = {'a', 'b', 'c', '\0', 'd', 'e'};
```

and write: memcpy(str2, str1, 6);
the content of str2 would be the same as str1.

On the other hand, if we write: strcpy(str2, str1);
the content of str2 would be: {'a', 'b', 'c', '\0'}.

memmove() is similar to memcpy(), except that memmove() guarantees that the data will be copied correctly if source and destination memory overlap. Because memcpy() does not check if the two memory regions overlap, it executed at least bytes, which means that existing data will be overwritten. For example, the next copy is wrong because the size of destination memory is 3 bytes, while the copied bytes are:

```cpp
char str1[3], str2[] = "abcde";
memcpy(str1, str2); // Be careful.
```

memcpy() is very useful, because it is implemented in a way that copying blocks of data is practically faster than an iteration loop. For example, the following code uses memcpy() to copy any array to another:

```cpp
int arr1[SIZE], arr2[SIZE];
memcpy(arr2, str1, sizeof(arr1)); /* We use memcpy() instead of iteration loop such as:
  for(int i = 0; i < SIZE; i++)
    arr2[i] = arr1[i]; */
```

memcmp() is used to compare the data stored in one memory region with the data stored in another. memcmp() in cstring:

```cpp
int memcmp(const void *ptr1, const void *ptr2, size_t size);
```

memcmp() compares size bytes. Their main difference is that strcmp() compares when encounters the null character in either string; memcmp(), on the other hand, stops only when the null character is met. For example:

```cpp
#include <iostream> // Example 14.8
#include <cstring>
using std::cout;

int main()
{
    char str1[] = {'a', 'b', 'c', '\0', 'd', 'e'};
    char str2[] = {'a', 'b', 'c', '\0', 'd', 'f'};

    if(strcmp(str1, str2) == 0)
        cout << "Same\n";
    else
        cout << "Different\n";

    if(memcmp(str1, sizeof(str1)) == 0)
        cout << "Same\n";
    else
        cout << "Different\n";
    return 0;
}
```

Because strcmp() stops comparing when the null character is met, the program displays Same. On the contrary, memcmp() compares all bytes, and the program displays Different.
