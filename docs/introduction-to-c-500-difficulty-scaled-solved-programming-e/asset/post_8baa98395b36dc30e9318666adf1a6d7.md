```cpp
#include <iostream> // Example 20.1
#include <string>
using std::cout;
using std::cin;
using std::string;

class Product {
public:
    string code;
    float prc;

    Product() { cout << "Base Constructor\n"; }
    ~Product() { cout << "Base Destructor\n"; }
    void show() const { cout << "\nC:" << code << " \n"; }
};

class Book : public Product {
public:
    string title;
    string auth;

    Book() { cout << "Derived Constructor\n"; }
    ~Book() { cout << "Derived Destructor\n"; }
    void display() const { cout << "T:" << title << " A:" << auth << " P:" << prc << "\n"; } // The function may access the members of the base class.
};

int main() {
    Book b;

    cout << "Product Details: ";
    cin >> b.code >> b.prc; // Access the members of the base class.

    cout << "Book Details: ";
    cin >> b.title >> b.auth;

    b.show(); // Call a function of the base class.
    b.display();
    return 0;
}
```

Again, a Book object inherits the code and prc members and the show() function. Book contains its own members and functions.

When a derived object is created, the constructor of the derived class is called first. Then, it calls the constructor of the base class to create the object of the base class contained in the derived object. Thus, the derived object contains a base class sub-object. This relationship is also referred to as is-a relationship, in the sense that a derived class object is also a base class object. For example, a Book object is also a Product object.

In particular, the sub-object of the base class must be created first and then part of the derived object. So, when b is created of Book first calls the constructor of Product to create the Product sub-object and then continues with the construction of b, that is, the body of the Book constructor is executed. ### Is-a and Has-a Relationships

As mentioned earlier, public inheritance models get better is-a relationship, that is, a derived class should also be a base class object. For example, a Book object is also a Product object. To understand the is-a relationship, I'll give you an example that does not match that. Suppose that we have a Bookstore class. A bookstore is not a book. Therefore, it'd be better to not derive from Bookstore class. To clarify, if you make that derivation, it does not mean the code will compile or an error will occur when the program is executed. Nothing prevents you from doing that, but such a program design usually leads to programming problems. Since bookstore has books, the proper approach to associate classes is the model of has-a. That is, to include a Book object as a member of the Bookstore class.

So, when you have decide whether to add a class as a member or derive from it, the general rule is to see which one of the has-a and is-a fits better and act accordingly. Since car has engine and tires, it'd fit to use the has-a model and writing something like that:

```cpp
class Car
{
    Engine eng;
    Tires tir;
}
```

In another example of has-a relationship, suppose that you have defined the Date class and want to define the Employee class. Since an employee has date information we'd write:

```cpp
class Employee
{
    Date hire_date;
    Date birth_date;
}
```

Now, suppose that you've defined the Shape class and want to define the Circle class. Since a circle is a shape, it'd fit to use the is-a model and writing something like that:

```cpp
class Circle : public Shape
{
}
```

Similarly, suppose that you've defined the Account class and want to define the CheckingAccount class. Since checking an account is a special type of bank account we'd use inheritance.
What about an Animal class and a Cat class? Since a cat is a kind of animal, it is possible to use inheritance and derive Cat from Animal.
