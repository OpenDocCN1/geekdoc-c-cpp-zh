```cpp
int main() {
    B *b = new B;
    A *a = dynamic_cast<A*>(b); // Safe cast.
    if(a) {
        a->show();
        std::cout << ' ' << b << '\n';
    }
    C *c = dynamic_cast<C*>(b); // Not safe cast.
    if(c) {
        c->show();
    } else {
        std::cout << "Error\n";
    }
    delete b;
    return 0;
}
```

The first cast is safe and the dynamic_cast operator returns a non-null pointer. show() is virtual and the pointer points to an object of the B class, the program displays B. Then, since the a and b pointers point to the same address, the program displays the same value. Because the second cast is not safe, the operator returns a null pointer and the program displays Error.

As we said, we can apply dynamic_cast to a reference. In case of failure the notion of null reference does not exist to be returned, the operator throws an exception of type bad_cast. This exception is derived from the exception class and it is declared in the typeinfo file. For example:

```cpp
#include <iostream> // Example 25.4
#include <typeinfo>
int main() {
    B b;
    B &br = b;
    try {
        C &c = dynamic_cast<C&>(br); // Not safe cast.
    } catch (std::bad_cast&) {
        std::cout << "bad_cast exception is caught\n";
    }
    return 0;
}
```

## The typeid Operator

The `typeid` operator is used to determine the type of an object. It returns a reference to a `type_info` object, as its name suggests, holds information about the type of the passed argument. The `type_info` class is declared in the `typeinfo` file. In its usual use, `typeid` takes as a parameter the name of a class or an expression that is evaluated to an object. If it is a type (e.g. int) the returned value represents the type. If it is an expression identifies a polymorphic class (a class with least one virtual function), the returned value represents the dynamic type of the expression. Otherwise, if the expression identifies a non-polymorphic class, the returned value represents the static type of the expression. The `type_info` class overloads the `==` and `!=` to compare types. For example, let's use the previously defined `A`, `B`, and `C` classes:

```cpp
#include <iostream> // Example 25.5
#include <typeinfo>
int main() {
    B *p = new C;
    C *c;
    A& r = c;

    try {
        if (typeid(C) == typeid(*p)) /* Compare with the type of the object p points to. */ {
            p->show();
            std::cout << typeid(*p).name() << '\n';
        }
        if (typeid(C) == typeid(r)) /* Compare with the type of the object r refers to. */ {
            r.show();
        }
    } catch (const std::bad_type&) {
        std::cout << "bad_type exception is caught\n";
    }
    delete p;
    return 0;
}
```

Since C is polymorphic, the first `if` condition checks the type of the object that p points to. Since it points to an object of the C class, the condition is true and the program displays C. Because C class is polymorphic the `*p` is evaluated at runtime. If p is a null pointer, `typeid(*p)` throws the `bad_type` exception. This exception is derived from the exception class and is declared in the `typeinfo` file. Also, the `type_info` class contains the `name()` function, which returns a C string that refers to the name of the type and uses the same name as the class. For example, with the compiler I used the program displays `Class C`. Then, because C is polymorphic the second `if` condition is true and because `show()` is virtual the program displays C.

Note if we make the show() non-virtual in classes A and B, the C class is no longer polymorphic, and the typeid returns the static type (known at compile time) of the expression. Therefore, the if condition are false and the program displays nothing. In particular, the typeid(*p) returns the type of the B class, similarly the typeid(r) returns the type of the A class, this is the static type of *r. If p is a null pointer, the operator does not create the bad_type exception, it does not need to be a valid pointer to evaluate the type of *p.

Type identification should only be used when necessary.

## TYPE CASTATORS

C++ provides operators that we can use to make type casts. We saw the dynamic_cast operator. The other operators are const_cast, static_cast, and reinterpret_cast. All of them are processed at compile time.

## The const_cast Operator

The const_cast operator is used to add or remove the const attribute from a variable. const_cast is used with pointers and reference. The syntax is similar to that of dynamic_cast:

```cpp
const_cast<type_name>(expression);
```

The type_name and expression should be of the same type, except for the const volatile qualifiers. That is, const_cast cannot change the underlying type (e.g., from const int to double*). The returned type is that of type_name. It is used to remove the constness of the passed argument. Let's see an example of how it is used:

```cpp
#include <iostream> // Example 25.6
int main()
{
    int *pl, i = 10;

    const int *p2 = &i;
    // It is not allowed to write *p2 = 20.
    pl = const_cast<int*>(p2);
    *pl = 20;
    std::cout << i << '\n';
    return 0;
}
```

Suppose that we want to change the value of i through a pointer. Since we cannot use p2 to do that, we use another pointer. The use of the const_cast operator removes the const attribute, but the p1 pointer can change the value of i. Note that this is still impossible for p2. So, the program displays 20. Of course, we could make the type cast in the traditional way instead of using const_cast:

```cpp
p1 = (int*)p2;
```

In another case though, we can accidentally write:

```cpp
double *p3 = (double*)p2;
```

where the compiler will not display an error message to notify us for this unintended action. We had used the const_cast operator instead, that is:

```cpp
double *p3 = const_cast<double*>(p2);
```

the compiler would display an error message because the type of p2 is not double*. Therefore, using const_cast is safer than the simple type cast.
