Let’s explain the syntax of a lambda expression. In its simplest form it is defined as:

```
[capture_clause](parameters) -> return_type
{
  lambda_body;
}
```

The parameter list and the trailing return type are optional parts. i) A lambda begins with the capture
clause []. This part specifies the variables that are captured (e. g.) and whether they are captured by
reference or value. The variables must be in the enclosing scope where the definition of the lambda
empty lambda list (e.g., []) indicates nothing is captured. In this case, the lambda can
work with only its arguments and the variables that are declared locally within it. For example, if we
not add i in the first call to for_each the compiler would issue an error message. Also, if we try to
j within the lambda compilation fails, j is not captured in the capture list.

The reason i used i and j differently in [i, j] is to show the capture modes. Specifically, if
& precedes the name of the variable it means that the variable is captured by reference (e. g., [&]), that
t lambda can change its value. If the name is used, it means it is captured by value (e. g., i),
that is, a copy of the local variable is passed to the function. As a matter of fact, the compiler by default,
or avoid any confusion, not allow to change the value of that copy. For example, in the
first lambda it is an error to write i = 10. Note that it is allowed to mix the modes and capture by
value and others by reference (e. g., [j]).
