C.4.8 Bitwise operators are often used in applications that communicate with the hardware. For example, a common communication method used in asynchronous serial communication is eight-bit characters, with one *start_bit*, one *stop_bit*, and one *parity_bit*. The transmission of data is signalled with the *start_bit* set to 0 to inform the receiver of arrival of data. The *stop_bit* indicates the end of the transmission. For example, the data bits 10100 are encoded as follows:

![](img/25e0e40b08b8016a58f1aab13ac2e812_80_0.png)

The sender may optionally transmit a *parity_bit*, which is used by the receiver to detect transmission errors. There are two variants of parity: even parity and odd parity. In even parity, the value of the *parity_bit* is calculated in a way that the total number of 1s plus parity bit is even. In case of odd parity, the total number should be odd. In our example, we choose even parity. Therefore, since the number of 1s in data is two, we, the *parity_bit* set to 0.

## OPERATOR PRECEDENCE

As shown in A, each operator has precedence that determines the order in which operators are evaluated. In an expression with several operators, the operators with higher precedence are evaluated first. For example, since * has higher precedence than + and -, the result of 10-2+1 is 3.

When operators of equal precedence appear in the same expression, the operators are evaluated according to associativity. For example, since * and / have the same precedence and are left associative, the result of 6/2*4 is 4, because the division 6/2 is executed first, then the multiplication 3*4 is 12. In another example, can you tell what the following program will output?

```cpp
float a, b = 4, c = 3;
a = 2/3*b;
a = b/c;
```

Since the result of 2/3 is 0, the first statement assigns 0 to a. Since multiplications are performed first and b is float, the second statement assigns 8 to a.

```cpp
#include <iostream>
int main() {
    int a = 2, b = 6, c = 9;

    c = (a < b);
    std::cout << (a == b) << '\n';

    a += c;
    std::cout << a << ' ' << c << '\n';

    return 0;
}
```

According to A, < and operators have the same precedence and are left associative. Therefore, the expression (a < c) is first evaluated. Since a is 2 and c is 9, its value is true. So, the expression is equivalent to 1 - b, because it is false because b is 6. It becomes 0.

Next, all values equal to 5. Since == operator is left associative, the expression a == b is first evaluated. Since a equals b, its value is true. Therefore, the expression a == b == c is equivalent to 1 == c. Since c is 5, this expression evaluates to false and the program outputs 0. If c were 1, the program would output 1. Note that if it is, this expression evaluates unless the whole expression is enclosed in parentheses, because << operator has higher precedence than ==.

The compound operators are executed from right to left. Therefore, the expression is equivalent to a = -(b += c). Then, b+=b+(c). Therefore, b+=5, while c is decremented and becomes 4. As a result, the expression is equivalent to a-10 = -5 and the program outputs: -5 4.

Some operators have precedence over the expected one or the one we'd like to have. For example, suppose that we want to shift a variable two places to the left and add 3. It would be plausible to: a = b << 2 + 3; assuming that the evaluation is from left right. Unfortunately, to be wrong, addition is performed first because the + operator has higher precedence. To get the desired result, the expression b << 2 must be enclosed in parentheses. In another example:

```cpp
if(a & 8 == 0)
    cout << "One\n";
```

Since the == operator has higher precedence than the & operator, the expression 8 == 0 is first evaluated, which is false, and then the value of a & 0 is false for any value of a. As a result, this if condition is always false. To get the desired result the expression a & 8 must be enclosed in parentheses.

You do not need to memorize the precedence and associativity of all the operators. If you are not certain about the evaluation order, use parentheses. In fact, use of parentheses, even if it is not necessary to, increases the readability of code and clarifies the way that expressions are evaluated. For example, it is clearer to write: a = b-(c/d)+d; instead of a = b-c/d+d;
