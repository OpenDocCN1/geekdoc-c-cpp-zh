If you are assigned to implement a network protocol here are some advices. Suppose that you implement the A side. You code and send messages to the B side. The question is, how could you verify that your code handles properly the responses received from the B side? If you can find an application in the market that simulates the B side, it is fine, and you can use it to test your code. But if you cannot find it For example, I was involved with the development of a protocol where the B side was a switching node of a wireless network and I could not find an application to simulate its operation. The company I used for was a small one and did not afford the cost to be a real one. So, what I did?

I did what you said. That, I used the LOOPBACK_MODE macro and code to simulate the B side into the same application. As a result, I managed to test the most part of the code and fix bugs locally in my office, before going to the customer's premises to develop the software. Course, the operation of the protocol was thoroughly tested when integrated into the customer's network platform, but most tests had already been performed. Thus, to the loopback testing, the integration phase completed earlier than expected. For your information, the customer was a manufacturer of network equipment (e.g., switches) looking for systems that would simulate the behaviour of many subscribers (e.g. thousands of calls in parallel and data sets) in order to evaluate the performance of its equipment it to the network operators.

In another application, I implemented the application that simulates the B side in another system and A side. Course, with both approaches, the simulation code should be written with special care, because in case it hits errors, it will lead you to the wrong conclusion that the A side is not written correctly. For this reason, the code of the B simulator should be written step by step, first to start some basic tests and gradually add functionality to support more complex tasks.
