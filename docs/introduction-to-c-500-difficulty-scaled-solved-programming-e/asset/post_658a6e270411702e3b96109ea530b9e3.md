## ARITHMETIC CONSTANTS

The integer numbers we've used in our examples (e.g., 5) are decimal constants. An integer constant can be written in decimal, oct, hex, or binary notation; they are nothing more than alternative ways of writing the same number. By default, count displays the values in decimal form. A decimal constant contains the digits of the decimal system 0-9, but not must with 0. If it begins with 0, it is interpreted as an octal constant. An octal constant contains the digits 0-7.

```
int a = 0123;
```

The value of a becomes 123 in the decimal system, but 83, is interpreted as an octal number. Since each digit corresponds to a power of 8 we have 123₈ = 3×8² + 2×8¹ + 1×8 = 83₁₀ A constant that begins with 0x or 0O is interpreted as hexadecimal. A hexadecimal constant contains the digits 0-9 and hex letters.

```
int a = 0x2f;
```

The value of a becomes 47, since 2F₁₆ = 47₁₀ The letters may be either uppercase or lowercase. Annex provides a brief introduction to hex int. Typically, the hex notation is used in applications that communicate with the hardware. C++14 allows integer to be written in binary format. The syntax uses the 0b or 0B prefixes.

```
int a = 0b11111; // a becomes 15.
```

Of course, no matter how you write a number (e.g., 12), it is 12, 014, 0XC, or 0b1100 it will be stored in the computer memory as a binary value. All that notations can be combined in one expression. For example, the following statement assigns the 80 to a:

```
int a = 10 + 020 + 030 + 0b111000;
```

The type of an unsixed constant is the smallest of the int, long int, and long int types that can represent it. For example, the type of 200000 is int in a system with 32-bit integers, while it is long int in a system with 16-bit integers. If it is suffixed by L or L(), 02XL, it is the first of the int and long int types that can hold its value, if it is suffixed by LL or LL then its type is either unsigned int or unsigned long int. If it is suffixed by U or U(), the type is the first of the unsigned int. If the suffixes are combined (e.g., 100UL), its type is the first of the unsigned long int. The order of L and U does not matter, not their choice. For example:

```
char ch = 'a';
```

A floating constant is a value with decimal digits. Notice that we use dot (.) for the decimal part, and not comma (,). we write 1.23, not 1,23:

A floating constant can be written in scientific notation using the letter E or e that corresponds to base 10 and an exponent with a positive or negative sign. For example, we can write a = 123E-2; which means 123 is multiplied by 0.01. Similarly, we can write a = 0.123e-1. Scientific notation is most useful when the number is very small or large to make it easier for the programmer to read and write. By default, the compiler treats a floating constant (e.g., 1.23) as double. Because of that, if we declare a float in example, the compiler would probably issue a type incompatibility warning message as: ‘initializing’ ‘const double’ to ‘float’. To make the compiler store it as float, add the letter f or F at the end (e.g., 1.23f), or the letter L or l to store it as double (e.g., 1.23L).

As we will see in Chapter 4, when both operands are integers the division operator / cuts the fractional part and produces an integer. For example:

```
int i = 8;
double j = i/5;
```

Since both operands are integers, the value of i/5 is integer. Therefore the value assigned to j is 1, regardless of the type of j. A common mistake is to assume that because j is double, the value to stored will be 1.6. No, the type of the variable to which the result is assigned (e.g., j) plays no role.

If either of the operands is floating-point, the fractional part is not truncated. For example, if i is declared as floating-point, j will be 1.6. This happens if we write 5.0 instead of 5, since the divisor is a floating-point constant.

C++14, the single-quote character ‘’ may be used as a digit separator in both integer and floating point constants. It can make large numbers easier. For example:

```
int a = 1'000'000'000;
double b = 0.0'123'456'2;
int c = 0b011'001'1000'0001;
```

## ARITHMETIC CONVERSIONS

C++ allows different data types to be mixed in the same expression. For example, adding an int and a double value. In such cases the compiler performs type conversions according to the rules we’ll see below. In general, the goal of a conversion is the type of the result be produced to be that of the operand. The arithmetic conversions are applied to binary operators that expect operands of arithmetic type, such as arithmetic, relational, and equality operators. The conversion of one type to another is either implicitly or explicitly. Implicit conversion is caused by the compiler, explicit by the programmer.

## Implicit Conversions

When implicit conversion is performed, the compiler, without the programmer’s intervention, promotes the type of the operand with the “narrower” type capable of storing its value. We examine two cases:

- 1. If one operand has a floating type. In this case, the operand whose type is narrower is promoted in that: float->double->long double. That is, if one operand is long, the other is converted to long double. Otherwise, if one operand is double, the other is converted to double. Otherwise, if one operand is float, the other is converted to float. Notice these rules also apply in case of an integer operand. That, if one operand is double and the other is int, the int operand is converted to double.

- 2. If neither operand has a floating type. Integral promotions are applied in both operands. Specifically, the bool, char, signed char, unsigned char, short int, and unsigned short int are promoted to int or to unsigned int if the int cannot represent all the values of the original type. In particular, true is promoted to 1 and false to 0. The char16_t, char32_t, wchar_t, and the scoped enumeration type (we'll discuss about it in Chapter 4) are promoted to the first of: int, unsigned int, long int, unsigned long int, or long long int types that represent all the values of the original type.

Then, the operand with the narrower type is promoted in that: int->unsigned int->long int->unsigned long int->long long int->

- a. If one operand is unsigned long int, the other is converted to unsigned long int.
- b. Otherwise, if one operand is long int and the other is unsigned long int, then if the long int can represent all the values of the long int, the unsigned long int is converted to long int. If not, both operands are converted to unsigned long int.
- c. Otherwise, if one operand is unsigned long int, the other is converted to unsigned long int.
- d. Otherwise, if one operand is long int and the other is unsigned int, then if the long int can represent all the values of the unsigned int, the unsigned int is converted to long int. If not, both operands are converted to unsigned long int.
- e. Otherwise, if one operand is long int, the other is converted to long int.
- f. Otherwise, if one operand is unsigned int, the other is converted to unsigned int.
- g. Otherwise, the type of both operands is int.
