Another question. Suppose we have the following function:

```cpp
void check(T a)
{
    int i = 10;
}
```

in main() we call check(), as shown below. Is the code correct? Pay attention, important exercise.

```cpp
int main()
{
    T t(10);
    check(t);
    t.show();
    return 0;
}
```

Although there is no problem in check(), since it does not do anything special, its call creates a big problem. Let's see why. When check() is called the t object is passed by value. The object is a copy of t, that a.data is equal to t.data and a.size equal to t.size. When check() terminates, the destructor of a object is called and releases the memory that a.data points to, which is the same that t.data points to. So, when show() is called, the memory has been released and the program will not work properly. Also, an error occurs when the program ends. Then, the destructor of the t object attempts to release a memory that has already been released, which is wrong.

> Be careful when passing an object by value, because if it contains pointer(s) severe problems may occur. In Chapter 18, we'll see that similar problems may occur when copying one object to another.

Fine, and what can we do to avoid this problem? We could pass a reference or a pointer to the object so that no copy is created. For example:

```cpp
void check(const T& a)
{
    int i = 10;
}
```

# THE this POINTER

Each member function, with the exception of the static functions as we will see below, has access to a hidden pointer called this. The important thing to remember is that when a member function is called, this points to the object that class calls. For example, suppose that the T class contains the f() and g() functions, an integer member named mem and t is an object of that class. If we

t.f();
The compiler passes the address of the t object to f() and the this pointer in the f() is initialized with that address. As is is, the compiler interprets it as:

```cpp
f(at) and the declaration as f(T *const this);
```

The this parameter is defined for us implicitly. Inside function any direct access to a member is assumed to be an implicit reference through this. For example:

```cpp
T::f()()
{
    mem = 10; // It is as we've written this->mem = 10;
    g(); // It is as we've written this->g();
}
```

When mem is accessed, the compiler accesses the mem of the object that this points to. That is, the compiler actually translates the access to this->mem. We could write the statement as the comment says, but it is not necessary since the compiler does it for. The same happens when g() is called.

The most common use of the this pointer is when we want the function to return a pointer to the object that called itself. For example, consider the following program:

```cpp
#include <iostream> // Example 17.11

class Test {
public:
    int a;

    Test(int i) {a = i;}
    Test* cmp(Test* t);
};

Test::cmp(Test* t) {
    if(t->a > a) // Equivalent to if(t->a > this->a)
        return t;
    else
        return this;
}

int main() {
    Test *p, t1(5), t2(10);
    p = t1.cmp(&t2);
    std::cout << p->a << '\n';
    return 0;
}
```

The cmp() function takes as argument a pointer to a Test object and if the value of a of the object that the pointer points to (i.e., t2) is greater than the value of a of the object that called the function (i.e., t1), it returns that. Otherwise, it returns the this pointer, which points to the object that called the function, that is, to t1.

Let's see in this example how the this pointer works. As we said, a non-static member function accesses the object that called via an indirect parameter not shown in the parameter list, the this pointer. When the function is called, this is initialized to the address of the invoking object. For example, with t1.cmp() the compiler passes the address of t1 to the unknown this parameter of cmp. To put it simply, remember this:

```cpp
T::f()
{
    mem = 10; // It is as we've written this->mem = 10;
    g(); // It is as we've written this->g();
}
```

When mem is accessed, the compiler accesses the mem of the object that this points to. That is, the compiler actually translates the access to this->mem. We could write the statement as the comment says, but it is not necessary since the compiler does it for. The same happens when g() is called.

The most common use of the this pointer is when we want the function to return a pointer to the object that called itself. For example, consider the following program:

```cpp
#include <iostream> // Example 17.11

class Test {
public:
    int a;

    Test(int i) {a = i;}
    Test* cmp(Test* t);
};

Test::cmp(Test* t) {
    if(t->a > a) // Equivalent to if(t->a > this->a)
        return t;
    else
        return this;
}

int main() {
    Test *p, t1(5), t2(10);
    p = t1.cmp(&t2);
    std::cout << p->a << '\n';
    return 0;
}
```

The cmp() function takes as argument a pointer to a Test object and if the value of a of the object that the pointer points to (i.e., t2) is greater than the value of a of the object that called the function (i.e., t1), it returns that. Otherwise, it returns the this pointer, which points to the object that called the function, that is, to t1.

Let's see in this example how the this pointer works. As we said, a non-static member function accesses the object that called via an indirect parameter not shown in the parameter list, the this pointer. When the function is called, this is initialized to the address of the invoking object. For example, with t1.cmp() the compiler passes the address of t1 to the unknown this parameter of cmp. To put it simply, remember this:

> When a non-static member function is called, this points to the object that called.
