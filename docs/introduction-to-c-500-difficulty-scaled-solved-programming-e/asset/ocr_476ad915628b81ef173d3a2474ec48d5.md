and write s.show(); the value of grd of the s object becomes 2. If we don't want a function to be able
change the values of the invoking object we add the const keyword at the end of its declaration.
The const keyword must also be added in its definition. For example, the declaration of the show()
comes:

void show() const; and its definition:

```
void Student::show() const
{
    grd = 2; // Wrong.
}
```

If show() attempts to change the value of a member, such as grd, the compiler will display an error
message for illegal action.

> For better control of the class operation, it'd be better to declare functions that do not change
the values of its members as const.

Inside a const function we can call another const member function, but it is an error to call
non-const function. This makes sense because the non-const function may modify the object,
which removes the const protection. For example:

```
void Student::show() const
{
    set(5); // Wrong.
}
```

Now, suppose that we add the following member function:

```
float& Student::get() const {return grd;} // Wrong.
```

Is it correct? No, the compiler will not let you do. You cannot return a reference or pointer
to a class member. Within a const function, every data becomes const so that it cannot be
modified. The reference must be const:

```
const float& Student::get() const {return grd;} // Fine.
```

For example, if you were allowed to return a non-const reference, then you could violate the constness
of a const object, then to alter an object that must not be modified. For example, to write such
like this:

```
const Student s;
s.get() = 10; // The value of s.grd becomes 10.
```

Therefore, the compiler in order to preserve the constness does not allow us to return non-const
references to member variables from const functions.
