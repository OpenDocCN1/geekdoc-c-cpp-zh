# OVERLOADING RESTRICTIONS

Most operators can be overloaded in the way as the previous examples. Actually, as we'll see below, overloaded operators, with some exceptions, do not have to be member functions. However, there are some restrictions in their use:

+   a. At least one operand of the operator must be a defined type. This rule prevents operator overloading for the base data types. For example, you cannot overload the + operator to return the difference of the two integers instead of their sum.
b. You are not allowed to change the syntax of the operator. For example, you are not allowed to use the addition + operator with just one operand. Similarly, you cannot change the behaviour of ++ from unary to binary. Specifically for the operators && || we know from Chapter 4 that the second operand is not always evaluated due to the short-circuit evaluation. This rule does not apply when overloaded, they are treated as binary operators and both operands evaluated. In fact, they are the arguments of the && (or ||) overloaded function they are evaluated when the function is called. Because with regular function evaluation that the programmers would expect is not valid any more, it is better to avoid overloading the precedence and associativity of the operator. For example, in an expression a*b+c where a, b, and c are objects and the operators * and + are overloaded, the multiplication is performed first and then the addition.
d. You are not allowed to create new symbols and overload them. For example, you are not allowed to declare the operator^^ to define exponentiation, where the operator does not exist.
e. You are not allowed to overload the following operators:

```
. * : : ?: sizeof alignas noexcept
```

+   f. Most operators can be overloaded either by member or non-member functions. However, the following operators can only be overloaded with non-static member functions:

= () [] ->
