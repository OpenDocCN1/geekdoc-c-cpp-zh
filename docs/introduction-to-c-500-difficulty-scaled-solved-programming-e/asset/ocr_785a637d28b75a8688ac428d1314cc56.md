```
B::B()
{
    a1 = 1; // Wrong.
    a2 = a3 = 2; // OK.
}
```

Although we can can use the constructor of the derived class to initialize base members I do not prefer this approach. The main reason is to not want responsibilities to be confused. I want to know which constructor is responsible for initializations. Controlling and maintaining code where each constructor can initialize members of base classes becomes difficult and prone error. It is much more convenient and safer to know that each constructor is only responsible for the initialization of its class members. Thus, I prefer a derived class to let the constructor of the base class undertake the initialization of members of the contained sub-object. After all, the derived constructor cannot initialize the members of the base class (e.g., a1).

By the way, although that the non-private members of the base class can be accessed from the derived class, it is not allowed to initialize them in the initialization list of the derived constructor. For example:

```
B::B() : a2(2), a3(2) {} // Wrong.
```

If we want to initialize them, we should do within the body of the derived constructor.
