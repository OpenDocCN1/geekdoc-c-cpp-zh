```
void f(int *p)
```

Before ending section i, notice that you should not use it to change a const value. For example:

```
const int i = 10;
int *p = const_cast<int*>(&i);
*p = 20; // The behavior is undefined.
```

The attempt to change a const value causes the undefined behaviour of the program.
In the same sense, as we know, you can use const_cast to remove the const of a const object you should not do to. If an object is designed to be const, it means that it is not expected to be modified.
If, for some reason, you have to do it, pay extra attention not to violate the const nature of the object, otherwise you may need hard to trace bugs.

# The static_cast Operator

This type of cast is the simplest type. Typically, the static_cast operator is used to cast one type to another related type. For example, one pointer to another in a class hierarchy or a numeric type (e.g., integer) to another (e.g., float). It has the same syntax as the others:

```
static_cast<type_name>(expression);
```

The type of the expression will be converted to the type_name. The operator can be used to convert pointers to related classes, such as from a derived class to a base class pointer (upcast) and the opposite, that is, convert a base pointer to a derived pointer (downcast). For example:

```
class A {...};
class B : public A {...};

A *a1 = new A;
B *b1 = static_cast<B*> (a1); // Not safe.
B *b2 = new B;
A *a2 = static_cast<A*> (b2); // Safe.
```

Let's not use the unsafe cast. As we know, when an object is not B, the downcast is not safe. However static_cast does not fail, so the programmer is not informed about this risky situation. Recall that in case of dynamic_cast, the value of b1 would be the null pointer. Therefore dynamic_cast adds an overhead due to runtime checks, whereas static_cast does not since it is applied at compile time, the use of dynamic_cast is safer because the runtime checks protects us from unsafe casts like this one.
