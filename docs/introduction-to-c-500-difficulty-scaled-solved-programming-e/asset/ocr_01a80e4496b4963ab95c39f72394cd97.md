If the null character is not found, the copy operation won't perform successfully. For example:

```
char str1[] = "abcd", str2[] = {'e', 'f', 'g'};
strncpy(str1, str2);
```

Since str2 does not contain the null character, the copy operation won't perform successfully and a runtime error may occur.

> Because strcpy() does not check if the string pointed to by src fits into the memory pointed by dest, is the programmer's responsibility to ensure the destination memory is large enough to hold all characters. Otherwise, the memory past the end of the dest will be overwritten causing the unpredictable behaviour of the program.

For example, consider the following:

```
#include <iostream> // Example 10.6
#include <cstring>
int main()
{
    char c = 'a', str[10];

    strcpy(str, "Longer text. The program may crash");
    std::cout << str << ' ' << c << '\\n';
    return 0;
}
```

Since the size of str is not large enough to hold the characters of the string, the data past the end of str will be overwritten (e.g., c could be stored in that position).

And yes, it is a serious error to pass an uninitialized pointer to strcpy(). For:

```
char *str;
strcpy(str, "test"); // Wrong, str is not initialized.
```

The strcpy function is declared in cstring:

```
char strncpy(char *dest, const char *src, size_t count);
```

strncpy is similar to strcpy(), with the difference that only the first count characters of the string pointed to by src will be copied into dest. If the value of count is less or equal to the length of the string that str points to, a null character won't be appended to the memory pointed to by dest. If it is greater, null characters are appended, up to the value of count.

> strncpy() specifies the maximum number of the copied characters it is safer than strcpy().
