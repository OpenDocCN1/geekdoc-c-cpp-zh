Another reason is for better performance. For example, assume that f() returns an integer. When we write:

```cpp
i = f();
```

the return value of f() may be copied to a temporary memory location and then this value is copied to the i. In case f() returns a reference, no copy is created, the return value is assigned directly to i, since the reference is just a synonym of the referred variable. The memory and time saving is not significant with basic types, but if the return value is a large entity, such as a large structure, and the function is called many times, it is more efficient to return a reference and avoid a series of copy operations in temporary locations. Of course, an optimizing compiler may skip the copy, but if this is not certain, it'd be better to return the reference to the entity.

> What you should not do is to return a reference to a variable that ceases to exist after the function is terminated.

For example, the following code is not correct:

```cpp
int j = test();

int test()
{
    int b = 10;
    return b; // Serious error, don't do it.
}
```

The variable b ceases to exist after test() terminates, the function returns a reference to a variable that does not exist anymore. What will happen if we attempt to return a reference that is unpredictable. Essentially, this is similar to the one we discussed in Chapter 11 in case a function returns a pointer. Remember, never return the address of a local variable unless it is declared static. That is, if b was declared static there would be no problem.

Note that if you want the compiler to deduce the return type you should use auto, not auto, to have the compiler deduce a reference type. For example:

```cpp
auto& max(int& a, int& b)
{
    return a > b ? a : b;
}
```

If you write auto to the first element of &, the compiler will deduce int as return type, not int&.

## rvalue References

C++11 introduces a new type of reference, the rvalue reference. An rvalue reference refers to a temporary object, which will not be used again after its use. Thus, an rvalue reference can refer the result of an rvalue expression, even though this value is generally temporary. Once an rvalue reference is bound to the result, the lifetime of the object is used to extend the result as long as the rvalue reference is in scope. Then declare an rvalue reference use two & following the type name. For example:

```cpp
int a = 10, b = 10;
int&& r = a+b;
std::cout << r; // The code outputs 20.
```

The r is an alias for the result of the rvalue expression a+b. Note that this example has no real value; it is just to see the syntax of the rvalue reference.

The main purpose of an rvalue reference is because the object is temporary, to convert a copy operation into a move operation. For example, when copying elements that contain lot of data (e.g., vector) it would be more efficient, if the source is not used again, instead of copying the data, which is not only necessary but also costly, to move. But how do we tell the compiler to move data? Using an rvalue reference. For example, consider the following program:

```cpp
#include <iostream> // Example 16.8
#include <string>
using std::cout;
using std::string;
```

```cpp
int main()
{
    string s1("one"), s2;
    s2 = static_cast<string&&>(s1); // Move data.

    cout << s2 << ' ' << s1 << '\n'; // It outputs a single 'one'.
}
```

With static_cast, which will be in Chapter 25, if the type (e.g., string) overloads the = operator to provide a move assignment operator, then the move operation will be performed. If not, the move operation will not be performed, and the usual copy operation will be performed instead. Since the string provides the move assignment operator, one moves from s1 to s2. The string "" is assigned to s1. Therefore, the program displays a single object. If we don't use an rvalue reference, then we write:

```cpp
s2 = s1;
```

instead of the move operation the normal copy operation will be performed and the program will display once twice.
Because the use of static_cast makes the code more difficult to read we can alternatively use the move() function of the standard library. Essentially, the move(a) is equivalent to static_cast<T&&>(a), where T is the type of a. That, despite its name, move() does not move its argument (e.g., a), it just returns an rvalue reference to it. I say, move move() neither moves nor copies data; it only performs a copy to an rvalue reference when used as an argument, as we see in Chapter 19, instructs the compiler to use a move constructor or move assignment operator. So, we can move the data in a different way by writing:

```cpp
s2 = std::move(s1);
```

As said, if the move operation is to apply it to data whose will not be used again in our program, after calling move() we can destroy the source object (e.g., s1) or assign it a new value, but we cannot make assumptions about its internal value or current state.
