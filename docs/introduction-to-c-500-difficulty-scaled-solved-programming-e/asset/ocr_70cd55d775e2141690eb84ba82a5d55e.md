What the compiler does is create code, which when the program runs, binds show() with
tProduct::show() and with the Book::show(), depending on the type of object that ptr points to.
Because the function is selected as the program, this selection method is called dynamic binding.
the late binding is the typical way the compiler handles the virtual functions for each class to create an array, usually referred
to vtable, which holds the memory addresses of the virtual functions of the class. Indeed, with
virtual functions allocates more memory than the equivalent object with the same functions declared as
on-virtual. When a virtual function is called, the compiler checks the type of the object, finds the function
address in the vtable of the corresponding class, goes to that, and executes the code found there.

> For non-virtual functions the memory address of the called function is known
when the program is compiled (static binding), while for virtual functions it is specified when
t program runs (dynamic binding).
