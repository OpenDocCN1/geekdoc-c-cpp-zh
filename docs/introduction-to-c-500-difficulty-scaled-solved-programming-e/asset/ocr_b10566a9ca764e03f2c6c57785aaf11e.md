Because the class has a pointer member we have made to improve our copy constructor and copy
ignment operator. The program looks fine, is there any problem? No, but we could improve its perf-
formance. Let's see the copy of arr2. As we know, the copy constructor is called and the members
of arr1 are copied since we won't use arr1, we do not need to have two copies (arr1
and arr2), so we do not need to copy the data of arr1, but move it. The same applies to the
ignment of arr2 to arr3. Since we won't use again arr2, it is more efficient to move its data. Well, in
this program it does not make a considerable difference in the performance if we move the data, but what
out in another application where the objects contain thousands of integers and we have many similar
calls? Then, if every one is temporary and not used more, it is more efficient to move the data it contains
rather than copy them. Let's see another example:

```
MyArray f()
{
  MyArray arr(SIZE);
  ...
  return arr;
}
arr1 = f();
```

Since arr1 is a local variable that is destroyed when f() terminates, then we can never reuse it,
n't it be more efficient to move the data from arr to arr1 and avoid the copy?
Indeed, data moving improves the performance, but how can we move the data? The compiler must
how able to determine when to copy and when to move data. This decision is based on rvalue
references. If we wanted a certain type (e.g., MyArray) to support move operations, it
must provide a move constructor and an overload function of the = operator to assign the data through
ment. You may recall from Chapter 16 in order to express to the compiler our intention to move
d we use value references. Read the comments to understand the additions:

```
class MyArray
{
public:
  MyArray(MyArray&& a) noexcept; // Move constructor.
  MyArray& operator=(MyArray&& a) noexcept; // Assign value through
movement. The argument is a rvalue reference. */
};
```
