# 21 • More about Inheritance 697

```
class C : public A, public B
{
  ...
}

int main(){
  C c;
  c.show(); // Ambiguity, which show() will be called
  ...
}
```

The C is declared with public inheritance from the A and B classes. It inherits the members of both A and B classes. As shown in the declaration of C, the classes are separated by commas and we specify the access specifier for each base class. If in the missing, the compiler assumes that the access is private. For example, we write:

```
class C : public A, B
```

class B is inherited with private access.
For the construction of C, the sub-objects of its base classes are first constructed. The construction order is, from left to right, as the base classes appear in the declaration of C (e.g., public A, public B). Specifically, when it is created, the default constructor of C is called, which calls the default constructor of A, then of B, and then the creation of C is completed. That is, the A-object is created and then the B-object.
As you'll see in the following sections, the implementation of the inheritance can be more difficult and problem-prone compared to single inheritance. With multiple inheritance, the same names can be inherited, and as shown in the above code, ambiguity may arise. show() will be that of A or B? Because the compiler does not know which one to call, it will display an error message similar to call show() is ambiguous. Note that there is no problem for a class to inherit multiple members with the same name. The compiler will complain only if we attempt to use a common name, such as show(). To overcome the problem, one solution is to use the scope operator :: and the name of the class that contains the show() that we want to call. For example:

```
c::show(); // The show() of A is called.
```

One may ask, could we not rewrite the classes and use a different name? Sure, you can do that. As matter of fact, you should avoid using the same names when writing classes for each inheritance. But you may run into the situation that you are unable to rewrite them, as using base classes from a library. Then, you need to qualify the name of the function.
Another solution is to use a declaration inside the C class to specify from which base class the duplicated member will be selected.

```
class C : public A, public B
{
public:
  using A::show;
  ...
}
```

Now, when we write c.show(); the show() of A will always be called. If you want to call always a duplicated member function this should be preferred against the option to use the qualified name (e.g., c::show()); It is simpler and helps you avoid the compilation errors that would otherwise occur if you forget to add the qualified name.
