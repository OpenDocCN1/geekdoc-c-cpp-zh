# One Header File

A simple way to organize a program consisting of many files is to place the definitions (e.g., functions, classes, ...) in the code files where they are used and all the declarations in a single header file. This header file is included in each code file. By convention, the extension of the header file is .h. Yes, for a small-size program, this approach might be convenient, since we've have only one place to search for declarations and edit. However, it is not an efficient approach for large programs. One reason is that every time contents change all the code files have to be re-compiled, which is time consuming for a large application. Also, changes in this file by many programmers are a source of risk for potential errors. And of course, its large size makes such difficult tasks as to read it, use it, understand, and maintain.

# Many Header Files

An alternative approach is each code file to have its own header file. The header file facilitates one who reads to get quickly what part of the code file implements and the services it provides. In large programs where organizing files is the best way, it is very helpful for the control, understanding, and maintenance of the program services that the code file provides to be split into many one header files. If there is a change in one header file, only the code that include it are compiled again.

The declarations are placed in the header file and the definitions in the respective code files. Common information used in more than one code file having a common header is what we need to make when we do not need to change in different files to make change, we do it in one place. For example, the declaration of a class used in many code files is placed in a header file, which is included in any code file that uses it. The functions of the class can be defined in the code files that use them in the same way as we have a single code file, that is, with the class name and the :: operator.

The purpose of the program is not to understand the details of the implementation, but to get an idea of the object-oriented design approach and how the different programs communicate. Also, if you ever need to get involved with the area of communication protocols, this example might help you start.

At first, what is a network protocol? Simply put, it is a set of rules that enables system communication. A protocol may be implemented in hardware, software, or both. Typically, its operation is based on the standard defined by an international organization. A protocol example is the famous Internet Protocol (IP). It is specified by the IETF organization in RFC 791. A protocol standard specifies, among others, the information exchanged between systems, the format of the exchanging messages, significance, and the message handling protocols. Typically, the guideline for the implementation of a protocol is a finite-state machine that models the protocol operation in states and events.
