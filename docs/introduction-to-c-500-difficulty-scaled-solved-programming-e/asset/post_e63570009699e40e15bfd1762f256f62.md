Although we would expect the program to output Yes, it outputs No. Here is why. Since a and b operands have different types, the implicit conversion rule says that the type of a is promoted to unsigned int before the comparison. Therefore, the value of a will be converted to a large positive number greater than b (in a 32-bit system, it is 2^{32}-20). As a result, the program outputs No.

> Be very careful mixing signed and unsigned operands, even better, don't mix them at all, in order to avoid unpleasant surprises.

Implicit arithmetic may also occur in assignments when the type of the right side does not match the type of the variable on the left. The applied rule says that the type of the expression is converted to the type of the variable. If the type of the variable is at least as wide as the expression, there will be no loss of information. For example:

```cpp
char c;
short s;
float f;
long double ld;
s = c; // The type of c is converted to short.
f = s; // The type of s is converted to float.
ld = f; // The type of f is converted to long double.
```

In a similar way, the statement `double d = 10;` is equivalent to `double d = 10.0;` because the compiler converts the integer constant 10 to the type of d, that is, double. However, there are conversion cases where information may be lost. These are called narrowing conversions. For example, when a floating-point value is assigned to an integer variable:

```cpp
int i;
double d = 11.9999;
i = d; // i becomes 11.
```

The fractional part is truncated and i becomes 11. Notice that the assigned value is not rounded to 12. Loss of precision may also occur when a floating-point type is assigned to a smaller one (e.g., double to float) or a bigger integer to a smaller one (e.g., long to int).
As you know, narrowing conversions can be the cause of unexpected errors; the compiler most probably issue a warning message to inform the programmer. At the initialization, C++11 prevents narrowing conversions with the {} syntax as we saw earlier.

## Explicit Conversions

Besides the implicit way how the compiler performs the conversion, the programmer can explicitly convert the type of one expression to another using the cast operator. The cast expression in the traditional way, that is, before the introduction of special operators, has the following syntax:

```cpp
(data_type) expression or data_type(expression)
```

The first syntax is inherited from C. The type of the expression is converted to the data_type. For example, after declaring the following variables:

```cpp
double a, b, c = 1.23;
```

the expression:

```cpp
a = (int)c;
```

casts temporarily the type of c from double to int and becomes 1. Notice that the case does not change the value of c, that is, remains 1.23. The term "temporarily" means that the compiler treats c as double. In a similar way, the statement:

```cpp
b = int(c+3.7);
```

casts the result of the addition to int and assigns that result to b. Therefore, b becomes 4. Let's look at this example. What will be the value of d?

```cpp
int d = (int)2.99 * 20;
```

To answer this question we need to know if the cast precedes the multiplication. Therefore, we must consider the precedence table in Annex A. Because the cast operator has higher precedence than * operator, d becomes 40. If the expression were enclosed in parentheses, that is (2.99 * 20), would become 59.

Besides the traditional method, C++ provides special operators to perform explicit conversions. We'll talk about them in Chapter 25. For example, the static_cast<> operator can be used for converting values from one numeric type to another

```cpp
d = static_cast<int>(c); // double to int.
```

The variable to be converted (e.g., c) is enclosed in parentheses and in brackets (e.g., int). The type of c is temporarily converted to int and the value is assigned to d. As Chapter 25 describes, the main reason for using special operators is for safety, in order to avoid costly errors that may cause problems in the program. Also, with a simple search of the operator name (e.g., static cast) in the program we can find all the castings, resulting in better control of the program. On the contrary, in the traditional way, we've to search the program line by line and waste much more time to find the castings, since there is no special mark to identify them.

## CONSTANT VARIABLES

Besides the type of a variable, we can specify additional properties. For example, sometimes we want to declare a variable whose value remains constant during the program execution. Such a variable is called constant. To declare a constant variable, we use the const keyword. A const variable must be initialized when it is declared and is not allowed to change its value. For example:

```cpp
const int a; // Wrong, it is not initialized.
const int a = 5; // OK, it is initialized when the program is compiled.
const int a = f(); /* OK, it is initialized with the return value of f() when the program runs. */
```

An attempt to change the value of a later in the program (e.g., a = 20;) will produce a compile error. A const variable can participate in expressions like a non-const variable, as long as no attempt is made to its value. For example:

```cpp
float a = 1.23;
const float b = a; // OK, it does not matter that a is not const.
const c = b; // OK, it does not matter that c is not const.
b = a*c; // Wrong, it is not allowed to change the value of b.
```

C++11 introduced the constexpr qualifier to declare a constant. The main difference between them is that a const variable is not required to be initialized at compile time, it is initialized at runtime (i.e., when the program runs), a constexpr variable must be initialized with a value known at compile time. If the initialization value is not a constant expression, or in general, the compiler cannot initialize the variable, the compilation fails. Here are some examples:

```cpp
int i = 3;
constexpr int a = 5; // OK.
constexpr int b = a+2; // OK, the a+2 is a constant expression. The value of
b is calculated when the program is compiled. /*/
constexpr int c = i; // Wrong, i is not a constant.
constexpr int e = f(); // OK, only if f() is a constexpr function. We'll show
about constexpr functions in Ch.16. /*/
void h(int d) {
    constexpr int g = d; /* Wrong, the value of d is not known at compile
time. */
}
```

Both const and #define can be used to create names for constants, there are significant differences between them. We can use #define to create a macro for numerical, character, or string constant. However, we cannot specify the data type of constant. On the other hand, we can use const with any type, such as arrays, pointers, and classes. Second, the const constants have the same scope as the variables (discuss them in II), whereas #define constants are not. Third, the scope of const is limited to a particular function. Another difference is that the constants can be viewed in the debugger; the #define constants cannot, because the preprocessor has replaced the names with their values. These are some of the reasons why it is recommended to use const or constexpr instead of #define.
