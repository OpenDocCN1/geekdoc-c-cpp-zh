
As a matter of fact, a class that overloads the [] operator to provide array-like access for both reading and writing typically defines two overload variants: const and non-const. For example:

```cpp
int& Array::operator[] (int i) {return arr[i];}
const int& Array::operator[] (int i) const {return arr[i];};
```

The first version applies to non-const objects and returns a reference, so that you may modify the value of the returned element. For example:

```cpp
Array a;
a[0] = 5; // OK.
int i = a[0]; // OK.
```

The second version applies to a const object and returns a const reference. Since it cannot appear on the left of an assignment, the constness of the returned element is preserved. For example:

```cpp
const Array a;
a[0] = 5; // Wrong.
int i = a[0]; // OK.
```

Note that for small objects, such as int, there is no overhead cost to return back by value. Instead, using const& as return type you could also write:

```cpp
int Array::operator[] (int i) const {return arr[i]};
```

#include <iostream>

Since a non-default constructor is defined in A, the declaration of a2 is wrong, no default constructor is defined. ## OVERLOADING WITH NON-MEMBERS FUNCTIONS

As mentioned, most operators can be overloaded using functions that are not class members. In fact, there are cases where their use is necessary. For example, consider the class A of the previous exercise. As we've seen, the statement a+5 is acceptable, but not 5+a. To achieve this we declare a member function. Such a function cannot be called by an object. Specifically, the values of operands are passed as arguments to the function. The restriction is that at least one of the operands must have class type. In our example, the prototype of the function is:

```cpp
void operator+(int i, A& a);
```

Now, the expression a+5 is translated to operator+(5, a). Let's define it:

```cpp
void operator+(int i, A& a)
{
    a.t += i;
}
```

Is it correct? No, because the member is private. What did we learn in the previous chapter? How non-member function access the private members? We declare it as friend. Let's see the program.

```cpp
#include <iostream>

class A
{
public:
    int t;
    A(int i) { t = i; }
    void operator+(int i) { t += i; }
    friend operator+(int i, A& a);
    void show() const { std::cout << t << '\n'; }
};

void operator+(int i, A& a)
{
    a.t += i;
}

int main()
{
    A a(10);
    a+5; // Translated to operator+(5, a).
    a.show(); // The program outputs 15.
    5+a; // Translated to operator+(5, a).
    a.show(); // The program outputs 20.
    return 0;
}
```

Note that it is not necessary to declare the function as friend. We could use:

```cpp
void operator+(int i, A& a)
{
    a+i; // Equivalent to operator+(i);
}
```

We just change the order of operands so the function is called. In general, when a function is associated with a class, I prefer to declare it as friend even if it does not access private members. Also, if it is ever needed to access the private members, you only have to change the function definition and not the class declaration. So remember, when we want to overload an operator where the first operand is some basic type (e.g., int), the overloaded function cannot be a member. If we want the function to have access to the private members, we declare it friend.

## Overloading the << Operator

Now you've seen some examples of operator overloading, you can understand that the << operators have been overloaded to output data. For example, cout is an object of the ostream class, which contains overloaded functions for basic types. Thus, one definition with int argument, one with char*, and so on. For example, if we write:

```cpp
int a = 10;
cout << a;
```

the cout.operator<<(int) function is called, which displays the integer. Let's see how we can use cout with a user defined type, such as Rect. The typical way to display the values of a class is to define a show() function and call it. The question is, could we, instead of show(), write something like this and display their values?

```cpp
Rect r(10, 20);
cout << r;
```

Yes, provided that the << operator is overloaded. In fact, it is very common to overload the << and use it together with the cout to display the values of an object. See how it works. Since the left operand is an object of the ostream class and the right one is an object of the Rect class, we must define a function that accepts two such types. Should that function be friend to the class or not? Since the function must have access to private members in order to display their values, it should be friend. Let's see the program:

```cpp
class Rect
{
public:
    friend operator<<(ostream& out, const Rect& r);
    ...
};

ostream& operator<<(ostream& out, const Rect& r)
{
    out << r.length << ' ' << r.height << '\n';
    return out;
}

```cpp
int main() {
  Rect r(10, 20);
  cout << r; // Translated to operator(cout, r).
  return 0;
}
```

Let me ask you, could the reference to out be const? No, because writing to out changes its status. Note that the argument is reference to const because we cannot copy an ostream object. Usually, the second parameter is declared as a reference to const not to avoid the argument but also the function does not change its status. Besides cout, we can also pass other ostream objects (or derived as well see in Chapter 20) to the function. For example, the cerr, which by default directs the output to the screen. And cerr can be redirected out sent to a file. We also see that depending on the type of the passed ostream object, we can use the operator<< function to direct the output either to the screen or to a file.

Another question, suppose that the r1 and r2 objects are declared, could we use the following statement and function:

```cpp
cout << r1 << r2;
```

To answer that question, we analyse the part of the statement. The statement is executed from left to right, that is equivalent to: (cout << r1) << r2;
Therefore, the cout << r1 calls the operator<<(cout, r1); will be executed first. Fine, and what does it return? Nothing, so we continue with the << r2 part. What should be the return type? What be of the left of r1. In particular, it should be a reference to an ostream object, so that the execution of the statement continues. Thus, we change the function definition to:

```cpp
ostream& operator<<(ostream& out, const Rect& r) {
  out << r.length << ' ' << r.height << '\n';
  return out;
}
```
