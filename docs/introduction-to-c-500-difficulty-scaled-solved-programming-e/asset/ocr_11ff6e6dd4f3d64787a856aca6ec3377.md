# Introduction to C++

Since the a and f(1) members have been declared private, it is not allowed to access them from outside the class. Therefore, the statements t.a = 1 and t.f1(); are wrong. The same applies for the protected members. The statements t.b = 2 and t.f2(); are wrong. Since the access to the public members is allowed, the statements t.c = 2 and Init(); are acceptable. Finally, since the functions of a class can access its members, the code of f(1), f(2), and f(3) is compiled successfully. To put it in another way, f(1) can be used directly by the programmer who wrote the class, but not by the programmer who uses the class. So, we remember that access to private and protected members is allowed through functions that are class members, and as we'll see later, through friends.

A class may not contain an access specifier, in which case all members are private by default. Also, specifiers can be used multiple times within the class and in any order. The specified access remains valid until the next specifier or the end of class appears. For example:

```
class A
private:
int a;
public:
int b;
private:
int c;
void f();
};
```

For the better understanding and organization of the class it's better not to have repetitive sections. Regarding the order of the sections, when I want to emphasis to the members that the user of the class has access to, I place the public section first. Otherwise, I put private first. Typically, the public section is put first, because it is the part that matters most the user of class to look to.

# Class Design

When we design a class, we declare the members that we do not want to be directly accessible as private (e.g., functions related to the implementation of the class), while we declare the members that we've decided to constitute the interface with the external environment as public. Essentially, the user of a class communicates with the class through its public members. We have already encountered the example C.10.10, whereas users of the string class use public functions (e.g., size()) to handle it. We did in example C.7 to manage the vector class.

As another example, in one of my applications, I have implemented the Protocol that simulated the operation of a network protocol. When finished, I passed it to another team of developers at the company, which was implementing an application that would use this class to send data in an encrypted format. To communicate with the class, I had placed the Init(), Stop(), and Send_Data() functions in the public section. However, the Operation() function and other data (e.g., algorithms for encryption) to hide them from the users of the class, for security against mishandling and there is no reason to publish implementation details, I placed them in the private section. Data hiding prevents their accidental manipulation and ensures the integrity of the class data and its operation. If an error occurs that changes the state of the class data, this error is due to the implementation of the class and not to the way the class is used. Thus, the error search is limited to the code, resulting in faster detection.

In principle, the basic idea of a class is to separate the part related to the implementation of the class from the part related to the implementation of its interface with the outside world.
