C++11 we can specify a list of initial values. For example:

```
int *p = new int[100]{10, 20, 30};
```

The first three elements are initialized with the respective values and the rest with 0. If the initial values are more than the number of elements, a compilation error occurs. Similarly, to allocate memory for 100 structures of type Student we write:

```
Student *p = new Student[100];
```

As we know from Chapter 8, we can use the pointer with array notation. That is, we can write p[0] instead of *p for the first element, p[1] for the second, and so on. Notice that the pointer does not know the number of elements it has; this can be the source of many problems. For example, if we allocate memory for 100 integers, we are allowed to write:

```
p[200] = 10; even p[-10] = 20;
```

and access unrelated memory out of the valid range. The compiler will not prohibit this; it trusts that we know what we are doing and lets us access that memory. As we know, disaster is on the way. This kind of bug is particularly hard to find, and the worse is that each time you run the program it may have different behaviour, which makes it difficult to spot the bug.

Of course, do not forget, that as we see in several examples (e.g., C.11), new can use a vector object. In that we can safely manage the elements and deal with memory allocation and release. The container undertakes these tasks for us. For example:

```
int num;
cin >>num;
vector<int> v(num);
```

In fact, usually I try to avoid using a pointer for memory allocation because it carries risks; we'll see more below. For example, we may forget to release the memory.

> If you need to allocate memory for a number of elements, it'd be better to use a standard class (e.g., vector) instead of new[]. Its use is easy, fast, and most importantly, safe.

Before ending this section, that it'd be better not to allocate memory for local variables, if you do it statically. For example:

```
void f())
{
    int *p = new int[1000];
    delete[] p;
}
```

This code is error prone. For the programmer may act somewhere in the function a return statement without releasing the memory. If it is executed, a memory leak will be created. It is much safer to use an ordinary variable (e.g., int p[1000]), so that memory will be automatically released when the function terminates. In general, in a long-running repetitive memory leaks can cause serious performance degradation and possibly a program crash.
