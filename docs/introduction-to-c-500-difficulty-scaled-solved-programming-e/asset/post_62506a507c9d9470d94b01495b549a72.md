## LAMBDA FUNCTIONS

One of the most exciting features that C++11 introduced is the ability to create lambda functions. The typical use of lambdas is as argument in STL functions that accept a function pointer or functor as argument. As we use, a functor is more powerful than a function pointer; however, it is required to write some code to support its functionality (e.g., to define a class and overload the () operator). A lambda expression or just lambda is often a better alternative than using a functor or a function. In particular, a lambda expression may be viewed as an anonymous inline function, which is defined just-in-place where we want to use it. Then, don't define separate functions or functors. For example, let's replace the Class with lambda as:

```cpp
#include <iostream> // Example 26.17
#include <vector>
#include <string>
#include <algorithm>
using namespace std;
```

```cpp
int main()
{
  int i = 6, j = 3;
  string tmp("test");
  vector<int> v = {5, 3, 8, 12, 1};

  cout << "Show less than 6: ";
  for_each(v.begin(), v.end(),
  [i](int a){if(a < i) cout << a << ' '});

  cout << "\nShow less than 3: ";
  for_each(v.begin(), v.end(),
  [&j](int a){if(a < j) cout << a << ' '});

  vector<string> s[]{"one", "two", "three"};
  cout << "\nShow less strings: ";
  for_each(s.begin(), s.end(),
  [&tmp](const string& a){if(a < tmp) cout << a << ' '});

  return 0;
}
```

Let’s explain the syntax of a lambda expression. In its simplest form it is defined as:

```cpp
[capture_clause](parameters) -> return_type
{
  lambda_body;
}
```

The parameter list and the trailing return type are optional parts. i) A lambda begins with the capture clause []. This part specifies the variables that are captured (e. g.) and whether they are captured by reference or value. The variables must be in the enclosing scope where the definition of the lambda is empty lambda list (e.g., []) indicates nothing is captured. In this case, the lambda can work with only its arguments and the variables that are declared locally within it. For example, if we do not add i in the first call to for_each the compiler would issue an error message. Also, if we try to use j within the lambda compilation fails, j is not captured in the capture list.

The reason I used i and j differently in [i, j] is to show the capture modes. Specifically, if & precedes the name of the variable it means that the variable is captured by reference (e. g., [&]), that the lambda can change its value. If the name of the variable is used, it means it is captured by value (e. g., [i]), that the lambda cannot change its value.
