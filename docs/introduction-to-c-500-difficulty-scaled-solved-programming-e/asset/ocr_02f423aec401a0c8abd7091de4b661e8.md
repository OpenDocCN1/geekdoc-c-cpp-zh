The same easy is with assert(). To disable assert() we define the macro NDEBUG before including
the cassert. If we need to reactivate assert() we remove the definition of NDEBUG. For example:

```
#define NDEBUG // assert() is ignored.
#include <cassert>
```

One more thing, dont call functions assert() that are necessary for the correct operation
your program or might create side-effects. For example:

```
assert(len = strlen(str)) > 10);
/* Use of len. */
```

If NDEBUG is defined, assert() will be ignored, strlen() will be called and len will not be updated.
The expression of the assert(exp) is checked dynamically, at runtime.
C++11 provides ability of static assertion with the static_assert(exp, msg) statement.
The condition is checked statically, at compile time. exp must produce a result at
time that can be converted to bool. For example, static_assert() cannot check the size() of a vec-
t object. If exp evaluates to false, the compilation fails and the message appears on the screen.
it is true, the assertion does nothing for:

```
#int main()
{
    static_assert(sizeof(int) == 4, "Other size\n");
}

```

If the size of the int type is not 4 the compilation fails and the corresponding mes-
sage is displayed on the screen. C++17, the msg argument is optional. For example: static-
assert(sizeof(int) == 4); in that case the displayed diagnostic message is platform dependent.
important use of static_assert is in generic programming to make assertions about types used as-
types.

```
#include <iostream> // Example 15.6

#define LEN20
#define test std::cout << "example\n";

int main()
{
    int arr [LEN] = {10};
    if(arr[0] == 10)
        test;
    else
        std::cout << "Not 10\n";
        return 0;
}
```

Because there is no space between LEN and 20, the compiler will produce an error message for the
declared variable LEN. The second compilation error is due to the; at the end of test. When test is
replaced, the second; does not let else to be associated with the if statement.
