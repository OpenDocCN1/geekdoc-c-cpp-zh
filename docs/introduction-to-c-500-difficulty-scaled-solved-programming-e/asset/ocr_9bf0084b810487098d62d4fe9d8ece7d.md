Sharing variables among files is quite popular, care has to be taken, because a wrong assignment in one file may make unpredictable results in the other files that it. Also, a program that uses many extern variables is more difficult to read and maintain, since the independences of the extern variables make it more complex. Thus, as with global variables, I try to avoid using extern variables. We will see an example of using extern variables later in this chapter and in the program of Chapter 27.

# Static Variables

As discussed, the memory that is allocated to store a local variable is released when the function terminates. Therefore, there is no guarantee that a local variable would still have its old value when the function is called again. If we want a local variable to retain its value, we should use the static storage class classifier. Unlike an ordinary local variable, a static variable has static storage duration, that is, it has a permanent lifetime. The memory for a static variable is reserved only the first time the function is called. The variable resides at the same location throughout throughout execution, and memory is not released when the function terminates, but once the program terminates. To sum up, the default properties of a static variable declared inside a function is block scope, no linkage, and static storage.

A static variable is initialized only once, the first time that the function is called. As with global variable, the initializer must be a constant expression; if it is not explicitly initialized, the default value is 0. In next calls, it retains its value and it is not initialized again. For example, consider the following program:

```
#include <iostream> // Example 11.17
```

```
void test();

int main()
{
    test();
    test();
    test();
    return 0;
}
```
