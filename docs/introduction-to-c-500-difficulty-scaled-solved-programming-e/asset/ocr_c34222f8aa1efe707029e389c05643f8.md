```
int main()
{
    string s1("one"), s2;
    s2 = static_cast<string&&>(s1); // Move data.

    cout << s2 << ' ' << s1 << '\n'; // It outputs a single 'one'.
}
```

With static_cast, which will be in Chapter 25, if the type (e.g., string) overloads the = operator to provide a move assignment operator, then the move operation will be performed. If not, the move operation will not be performed, and the usual copy operation will be performed instead. Since the string provides the move assignment operator, one moves from s1 to s2. The string "" is assigned to s1. Therefore, the program displays a single object. If we don't use an rvalue reference, then we write:

```
s2 = s1;
```

instead of the move operation the normal copy operation will be performed and the program will display once twice.
Because the use of static_cast makes the code more difficult to read we can alternatively use the move() function of the standard library. Essentially, the move(a) is equivalent to static_cast<T&&>(a), where T is the type of a. That, despite its name, move() does not move its argument (e.g., a), it just returns an rvalue reference to it. I say, move move() neither moves nor copies data; it only performs a copy to an rvalue reference when used as an argument, as we see in Chapter 19, instructs the compiler to use a move constructor or move assignment operator. So, we can move the data in a different way by writing:

```
s2 = std::move(s1);
```

As said, if the move operation is to apply it to data whose will not be used again in our program, after calling move() we can destroy the source object (e.g., s1) or assign it a new value, but we cannot make assumptions about its internal value or current state. Let's look at an example of swapping values using a function template (we'll discuss this in a chapter) to better understand the usefulness of moving data:

```
template<typename T> void do_swap(T& a, T& b)
{
    T tmp = a; // After the assignment to , we have two copies of a.
    a = b; // After the assignment to a, we have two copies of b.
    b = tmp; // After the assignment to b, we have two copies of tmp.
}
```

It'd be more not to copy the data in the assignments but move to them. For example, in the first assignment, there is no reason to have two copies of a. Since the data is stored in tmp and a is not going to be used again, there is no reason to keep them in memory. To realize the performance gain, consider the case a being a vector of string thousands, containing hundreds of characters. The cost of copying and maintaining two copies would be significant. If it is important to move the data to the destination (e.g., tmp) and then release the resources reserved for the source object (e.g., a).
