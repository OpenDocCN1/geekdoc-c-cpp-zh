Note that it is not necessary to declare the function as friend. We could change its definition to:

```
void operator+(int i, A& a)
{
    a+i; // Equivalent to a.operator+(i);
}
```

We just change the order of the operands so the class function is called. In general, when a function is associated with a class, I prefer to declare it as friend, even if it does not access private members, in order to clear the association. Also, if it is ever needed to access the private members, you only have to change the function definition and not the class declaration.

So remember, when we want to overload an operator where the first operand is some basic type (e.g., int), the overloaded function cannot be a class member. If we want the function to have access to the private members of the class, we declare it as friend.

# Overloading the << Operator

Now you've seen some examples of operator overloading you can understand what you read in Chapter 3 (it is a long way back) that the << >> shift operators have been overloaded to output and input data. For example, cout is an object of the ostream class, which contains overloaded operator functions for the basic types. Thus, one definition with an int argument, one double, with char*, and so on. For example, if we write:

```
int a = 10;
cout << a;
```

the cout.operator<<(int) function is called, which undertakes to display the integer.

Let's see how we can use cout with a user defined type, such as Rect. The typical way to display the values of a class is to define a show() function and call it. The question is, could we, instead of show(write), write something like this and display their values?

```
Rect r(10, 20);
cout << r;
```

Yes could, provided that the << operator is overloaded. In fact, it is very common to overload the << and use it together with the cout to display the values of an object. See how it works. Since the left operand is an object of the ostream class and the right one is an object of the Rect class, we must define a function that accepts arguments as two such types. Should that function be friend to the class or not? Since the function must have access to the private members in order to display their values, it should be friend. Let's see the program:

```
class Rect
{
public:
    friend void operator<<(ostream& out, const Rect& r);
    ...
nvoid operator<<(ostream& out, const Rect& r)
{
    out << r.length << ' ' << r.height << '\n';
}
```
