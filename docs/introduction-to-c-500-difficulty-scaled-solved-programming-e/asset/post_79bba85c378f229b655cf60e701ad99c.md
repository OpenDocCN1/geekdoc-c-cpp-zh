By default, the compiler initializes a global variable or the elements of a composite type (e.g., array) to 0; however, I prefer to do it myself in order to make it clear. Let's see an example of using global variables:

```
#include <iostream> // Example 11.15

void add();
void sub();

int glob = 0; /* Although the compiler initializes it to 0, I prefer to do
myself. */

int main() {
    add();
    glob += 2;
    sub();
    std::cout << glob << '\n';
    return 0;
}

void add() {
    glob++;
}

void sub() {
    glob--;
}
```

All functions have access to the global variable, since it is declared before their definitions. The program displays 2.

Although global variables may seem tempting to use, you should avoid their use. One reason is that it makes more difficult to identify erroneous conditions. For example, if a wrong value is assigned to a global variable, you will have to check all the functions in order to identify the guilty one. Excessive relying on global variables may have a bad effect on program design and make it more difficult to understand and manage. For example, it would be more difficult for the reader to correlate each global variable with the functions that use it. In general, in large programs where each file may use hundreds of variables you should keep them as local as possible for the best management and maintenance of the program.

# Use of extern

A global variable can be visible in more than one source file, that is, it may have external linkage. This is very useful, particularly in large programs, because several source files may need to share the same variable. The extern keyword is a storage class specifier that enables a variable to be shared among several files. Typically, such a variable is declared in the file used most and the other files refer to it using the extern keyword.

We've discussed the distinction between declaring and defining a variable in Chapter 2. Let's see again the difference. The statement int size; not only declares the type of size to be int, but defines size as well, that is, the compiler allocates memory to store its value. A variable can have only one definition; other files may contain extern declarations to access it. For example, to use it in another file we write:

```
// Second file.
extern int size; // Only declaration.
```

Because of this, the variable size is only declared, that is, the compiler is informed about the name and the type of the variable. The variable is not defined, that is, the compiler does not allocate memory for it. The linker will link the reference to size with its definition in another file. If we forget the word extern, the separate compilation for each file will be successful, but the linker will display an error message that size is defined twice. The variable can only be initialized when it is defined, and that, is what we write in the second file:

```
extern int size = 10; // Wrong.
```

size can be accessed and modified, if, in any of those files it is referred to as extern. Since the compiler does not allocate new memory, if the variable is an array we can omit its length in an extern declaration. For example:

```
extern int arr[];
```

Note that the linkage of a const global variable, as well as a static one as we'll see below, is internal, the variable can only be used in the file that contains its declaration. For example:

```
const int size = 10; // Internal linkage.
```

If we want to have external linkage, we must add the word extern to its definition. For example:

```
extern int size;
```

Unlike an ordinary local variable, a static variable has static storage duration, that is, it has a permanent lifetime. The memory for a static variable is reserved only the first time the function is called. The variable resides at the same location throughout execution, and memory is not released when the function terminates, but once the program terminates. To sum up, the default properties of a static variable declared inside a function is block scope, no linkage, and static storage.

A static variable is initialized only once, the first time that the function is called. As with global variable, the initializer must be a constant expression; if it is not explicitly initialized, the default value is 0. In next calls, it retains its value and it is not initialized again. For example, consider the following program:

```
#include <iostream> // Example 11.17
```

```
void test();

int main()
{
    test();
    test();
    test();
    return 0;
}
```

# Static Variables

As discussed, the memory that is allocated to store a local variable is released when the function terminates. Therefore, there is no guarantee that a local variable would still have its old value when the function is called again. If we want a local variable to retain its value, we should use the static storage class.
