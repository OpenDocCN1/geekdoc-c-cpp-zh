As a static member function is not needed to be called by some object. If it is declared in the public section, in this example, it can be called using the class name and the :: scope operator (e.g., T::get_objs()). Of course, you can use an object to call it (e.g., t1). If it was declared in the private section, the compiler would display an error message for not allowed access. Yet, as the comment says, you can define a static member function which is not associated with a particular object.

Because a static member is not associated with a particular object, it has not a this pointer. Therefore, it cannot be declared as const and the use of this within its body is not allowed. In fact, like static variable, a static member function can be called even if no object of the class is created. For example, let's change main() to:

Since no object has been created, the program outputs 0.

# MOVE SEMANTICS

Before starting to read this section, I would suggest to read again the section about rvalue references in Chapter 16, to refresh your memory. It will make easier for you to understand this section.

One of the most important features that C++11 added is the ability to move object instead of copying it. Older versions only copy the operation. As we said in Chapter 16 when we have to copy entries that may contain a lot of data, if the source will not be used again, it is much more efficient, instead of copying the data, which is an expensive operation, to move them. For example, the vector and string classes move operations. As a move example, consider the string class. Each string object has a pointer to an array of memory where the characters are stored. The move constructor copies that pointer rather than allocate new memory and copies the characters to that memory. Let's see a similar example:

```cpp
#include <iostream> // Example 19.8
#include <string>

class myArray {
private:
    int *p;
    int size;
public:
    MyArray(int s);
    ~MyArray() { delete[] p; }
    MyArray(const myArray& arr);
    MyArray& operator=(const myArray& arr);
    const int& operator[](int i) const;
};

MyArray::MyArray(int s) {
    int i;
    size = s;
    p = new int[size];
    for (i = 0; i < size; i++)
        p[i] = i; // Initial values.
}

MyArray::MyArray(const myArray& arr) {
    size = arr.size;
    p = new int[size];
    memcpy(p, arr.p, size * sizeof(int));
}

MyArray& myArray::operator=(const myArray& arr) {
    if (this == &arr)
        return *this;
    delete[] p;
    size = arr.size;
    p = new int[size];
    memcpy(p, arr.p, size * sizeof(int));
    return *this;
}
```

const int& MyArray::operator[](int i) const
{
  return p[i]; /* For simplicity, it is not checked if the value of i is
  acceptable limits. */

}

```cpp
int main()
{
  const int SIZE = 10;
  MyArray arr1(SIZE), arr3(SIZE);
  MyArray arr2 = arr1;
  arr3 = arr2;
  for (int i = 0; i < SIZE; i++)
    std::cout << arr3[i] << '\n';
  return 0;
}
```

Because the class has a pointer member we have made to improve our copy constructor and copy assignment operator. The program looks fine, is there any problem? No, but we could improve its performance. Let's see the copy of arr2. As we know, the copy constructor is called and the members of arr1 are copied since we won't use arr1, we do not need to have two copies (arr1 and arr2), so we do not need to copy the data of arr1, but move it. The same applies to the assignment of arr2 to arr3. Since we won't use again arr2, it is more efficient to move its data. Well, in this program it does not make a considerable difference in the performance if we move the data, but what out in another application where the objects contain thousands of integers and we have many similar calls? Then, if every one is temporary and not used more, it is more efficient to move the data it contains rather than copy them.

```cpp
MyArray f()
{
  MyArray arr(SIZE);
  ...
  return arr;
}
arr1 = f();
```

Since arr1 is a local variable that is destroyed when f() terminates, then we can never reuse it, isn't it be more efficient to move the data from arr to arr1 and avoid the copy?
Indeed, data moving improves the performance, but how can we move the data? The compiler must be able to determine when to copy and when to move data. This decision is based on rvalue references. If we wanted a certain type (e.g., MyArray) to support move operations, it must provide a move constructor and an overload function of the = operator to assign the data through movement. You may recall from Chapter 16 in order to express to the compiler our intention to move we use value references. Read the comments to understand the additions:

```cpp
class MyArray
{
public:
  MyArray(MyArray&& a) noexcept; // Move constructor.
  MyArray& operator=(MyArray&& a) noexcept; // Assign value through movement. The argument is a rvalue reference. */
};
```

To distinguish move operations from copy operations, remember that the copy constructor and the copy assignment function take lvalue references as parameter, while the move constructor and the move assignment function take lvalue references as parameter. Also, these references are not declared as const, so the referred entities can be modified. And how we trigger the calls to the move functions? Recall from Chapter 16, we can use the move() function. move() returns a value reference to its argument. Let's see the program:

```cpp
int main()
{
    const int SIZE = 10;
MyArray arr1(SIZE), arr3(SIZE);

    MyArray arr2 = std::move(arr1);
    arr3 = std::move(arr2);
    for(int i = 0; i < SIZE; i++)
        cout << arr3[i] << '\n';

    return 0;
}
```

If a class (e.g., MyArray) defines both the copy constructor and the move constructor, the compiler checks the types of argument to call the appropriate one. The same applies for the copy and move functions. That is, whether an lvalue or rvalue reference is passed. Take a look at the following examples to see how function is called (well, in the case of return values the compiler may perform NRVO, but I refer to the general case):

```cpp
MyArray arr4 = arr3; /* Because arr3 is lvalue the copy constructor is called. */
arr4 = arr3; /* Because arr3 is lvalue the copy function is called. */
```
