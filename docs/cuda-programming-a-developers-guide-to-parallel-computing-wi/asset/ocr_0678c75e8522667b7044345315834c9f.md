Notice that we're mixing the loading of data with the addition. We could move all the loads to the start of the function. However, consider that each uint4 type requires four registers. Thus, the ILP32 example would require 32 registers just to hold the values from a single read iteration. In addition, some are needed for the addition and final write. If we use too many registers, the number of blocks that can be scheduled is reduced or the kernel spills registers to "local" memory. Such local memory is the L1 cache for compute 2.x devices and global memory for the compute 1.x devices. The results for these ILP kernels are shown here:

# Reduction of the number of blocks

Currently, we're invoking N blocks where N is the problem size, 12 million elements (48 MB) divided by the number of threads per block multiplied by the number of elements
