If we consider shared memory, we need to think about bank conflicts. Thread 0 would need to read banks 0 and 1, plus write to bank 0. Thread 1 would need to reads banks 2 and 3 and write to bank 2. In a compute 1.x system with 16 banks, thread 8 would wrap around and start accessing banks 0 and 1. On compute 2.0 hardware, we'd see the same effect at thread 16. Thus, we'd have four bank conflicts per thread on compute 1.x hardware and two bank conflicts per thread on compute 2.x hardware with a shared memory implementation.
