# Loading Textures

We already have an asset registry defined. So, let's add a function to load textures. Below is a code snippet that shows how a texture can be loaded to the asset registry. Make sure to update your asset registry accordingly.

```
```cpp
// ...
engine/src/assets/registry.h
// ...
FUSE_INLINE texture_asset* load_texture(const std::string& src,
const std::string& name, SDL_Renderer* rd) {
texture texture;
texture.data = IMG_LoadTexture(rd, src.c_str());
texture.filename = src;
if (!texture.data) {
FUSE_ERROR("%s", IMG_GetError());
return NULL;
}
SDL_QueryTexture(texture.data, NULL, NULL, &texture.width,
&texture.height);
auto asset = new texture_asset();
asset->instance = texture;
asset->name = name;
_data[type_id<texture_asset>()].push_back(asset);
return asset;
}
// ...
```
```

IMG_LoadTexture() is a built-in function in SDL_image that loads pixel data from files. It supports a variety of image formats, including PNG, TIFF, JPG, and JPEG. This method loads the pixel data into a memory block and returns the address to the first pixel data.

In order for us to know the size of a texture, we need to explicitly query it using the SDL_QueryTexture() function. This function takes a pointer to a texture and two integer pointers for the width and the height to store the requested size.

The load_texture() function also takes the name of the asset as an argument. This makes sure that every asset has a name that can be used to find it. Two assets can have the same name, but they will never have the same asset_id. That's why we don't have to worry about an asset being overwritten due to its name already being used.
