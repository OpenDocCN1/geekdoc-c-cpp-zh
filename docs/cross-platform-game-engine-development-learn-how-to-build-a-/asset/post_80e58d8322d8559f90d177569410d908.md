We stated in the introduction that our project would consist of an engine library and a game executable. As a result, we have a folder called "engine" and another called "game" in our project folder tree.
The folder "windows" will be used to store all dependencies related to the Windows platform like .lib, .dll files, and external include header files.
To enable VS-Code to use the C/C++ extension we installed previously, we must first create a folder named ".vscode" in which we will place the three JSON files shown below: "c_cpp_properties.json", "launch.json", and "tasks.json".
Let's go through each file role one by one.

## c_cpp_properties.json

```json
{
  "configurations": [
    {
      "name": "configs",
      "includePath": [
        "${workspaceFolder}/windows/includes/**",
        "${workspaceFolder}/engine/src/**"
      ],
      "defines": ["_DEBUG", "FUSE_EXPORT"],
      "cStandard": "c17",
      "cppStandard": "c++17",
      "intelliSenseMode": "${default}"
    }
  ],
  "version": 4
}
```

This file is used to configure the C/C++ extension in VS-Code to offer proper IntelliSense, error checking, and syntax highlighting. It is important to note that this has no effect on the code compilation process. Its purpose is only to improve our coding experience in VS-Code.
The symbols defined here are only for code highlighting. The same is true for the C++ language standard; it's only to improve code completion. The IntelliSense mode is set to "default" to make sure we are using the current system default mode. We can also specify a mode like: "clang-x64".

## launch.json

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Windows",
            "type": "cppvsdbg",
            "request": "launch",
            "console": "integratedTerminal",
            "cwd": "${workspaceFolder}/build/bin/Debug",
            "program": "${workspaceFolder}/build/bin/Debug/game.exe"
        },
        {
            "name": "Linux",
            "type": "cppdbg",
            "request": "launch",
            "console": "integratedTerminal",
            "miDebuggerPath": "/usr/bin/gdb",
            "cwd": "${workspaceFolder}/build/bin",
            "program": "${workspaceFolder}/build/bin/game"
        }
    ]
}
```

This file is used to configure the debugger in VS-Code. We must define a configuration for each platform because our program will operate on both Windows and Linux.
We name each configuration, then provide the type of debugger we wish to use.
We next decide whether we want to utilize the built-in terminal in VS-Code or a separate console to output debug messages, and finally, we tell VS-Code which program to execute when we start debugging. In this example, our game executable file will be in the "build/bin/Debug" folder for Windows and "build/bin" for Linux.

- tasks.json

```json
{
  "tasks": [
    {
      "type": "shell",
      "label": "build everything",
      "windows": { "command": "${workspaceFolder}/build-win.bat" },
      "linux": { "command": "${workspaceFolder}/build-linux.sh" },
      "problemMatcher": [ "$gcc" ],
      "options": { "cwd": "${workspaceFolder}" },
      "group": { "kind": "build", "isDefault": true },
    },
  ],
  "version": "2.0.0"
}
```

This file is used to configure VS-Code tasks like build tasks, clean tasks, and so on. Because VS-Code does not know how to compile our project by default, we must tell it exactly what to do by giving it a command or Shell script that will be executed when we request that the project be compiled.

## Build Shell Scripts

In the root directory of our project’s tree (Figure 17), you can see two script files: build-win.bat and build-linux.sh, for Windows and Linux, respectively.

## build-win.bat (Windows)

```
@echo off

if not exist build mkdir build

rem generate cmake files
cmake -S. -B ./build -DCMAKE_BUILD_TYPE=Debug -DBUILD_SHARED_LIBS=ON

rem copy assets & dll files to output dir
robocopy "./resource" "./build/bin/Debug/assets" /E
robocopy "./windows/bin/" "./build/bin/Debug/" /E

rem compile project
cd build && cmake --build .
echo compilation finished!
```
