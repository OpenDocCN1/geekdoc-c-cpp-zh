The definitions of some essential elements required for our entity component system are contained in the header file ecs.h. We want to know which and how many components belong to an an entity. That is why we have the signature, which is nothing more than a set of components id. A signature will be assigned to each entity which is represented by a 64-bit unsigned integer under the name: entityid. The element is the array_entry. This template structure stores a component of type "T" and the entity it belongs to. We've defined a cast operator to entityid because, while searching for a component in the component_array, we will simply use the entityid to search for the component. This structure also represents how components will be stored in the component_array. Since we want to store our components in memory in a cache-friendly way, we must create a custom component array to store them. Each component type will have its own component array. That's why we created an interface called array_instance which for now only has a single virtual function called erase(). We then use that interface to create a template structure called component_array that takes the type of the component to store as a template parameter. If you look closely, you will see that this component array is nothing but a wrapper around the C++ std::vector container. It contains functions like push, remove, and get, just like a standard array.
