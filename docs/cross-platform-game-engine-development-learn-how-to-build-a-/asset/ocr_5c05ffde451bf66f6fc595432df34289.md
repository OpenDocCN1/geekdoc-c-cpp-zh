Linking the engine dynamically makes it easy to add scripting with other programming languages to our game engine, which is an essential feature for a game engine. It also makes it simplify to add new features while keeping the same executables.

The game itself is a little application that loads and configures some of the engine's modules. It's done this way to keep the engine's internal workings hidden from the game. In the design above, there are two executables, or programs, which are allowed to load the engine's library, for their specific purposes. We have "game" and "editor".

In most cases, the editor will load the engine's modules at runtime to allow the user to create the video game of his or her choice. The game executable will use the same library as before, but this time to run the final game created in the editor.
