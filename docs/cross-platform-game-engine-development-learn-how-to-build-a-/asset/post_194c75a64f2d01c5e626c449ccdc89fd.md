## Delta Time

In game programming and computer graphics, delta time describes a concept that ensures a hardware-independent speed of processes in a game loop. Delta Time describes the time difference between the previous frame and the currently rendered frame. The concept of delta time was introduced to solve a problem in early computer games in which games delivered at different speeds depending on the speed of the processor and were therefore sometimes no longer playable on faster processors than intended by the game developer. [22]

## Frame Rate Based Games

These types of games are not based on time but on the frame rate of the computer used. Moving an object using a 30 FPS machine will progress with half the speed when using a 60 FPS machine. Framerate dependent games can severely affect gameplay, since the flow of the game will depend on the device's frame rate used to play the game.

## Time Based Games

Games that are time-based have similar behaviour (motions, animation, and physics) on different machines, regardless of the framerate. That means, an object moving in a "time-based" game will move at the same rate regardless of the computer speed.

This technique is used when the goal is to design multi-platform games. That is also the reason we want to use that in our engine.

static bool is_running = true;

    return is_running = false;

FUSE_INLINE void compute_deltatime() {
    deltatime = get_ticks() - last_tick;
    if (deltatime > MAX_DELTATIME) {
        deltatime = MAX_DELTATIME;
    }
    last_tick = get_ticks();

    // ...

    last_tick = get_ticks();

    while (is_running) {
        compute_deltatime();
        inputs::dispatch_events();
        SDL_RenderClear(renderer);
        scene->update(deltatime);
        SDL_RenderPresent(renderer);
    }

    // ...
}
}

## Collision Handling

2D collisions are determined by the types of shapes colliding. For example, we have a rectangle-to-rectangle collisions or circle-to-circle collisions. In general, we would have a simple rectangular shape around the entity known as a "box collider". This technique is not perfect, but it offers a particularly good ratio between performance and function.

![](img/2763810ed0a1572c2bec59ee52dd75be_167_0.png)

Figure 36 Collision

A collision can be detected only when the two colliders are overlapping. This type of collision detection is not pixel perfect. What happens after the collision is up to us to decide.

We are going to create a collider component to make sure that only entities with a collider component can react to collisions. This is important because it will reduce the number of collision tests.

We are also going to create a separate system for collision handling to keep our code clean because it will make it easier for us later to add scripting features.

## Collision System

The collision system compared to another system will implement the start function because we need to make sure that the position of the box collider is aligned with the entity's initial position.
The next code snippet shows how the collision system is implemented. The start function retrieves all entities with a collider component and sets their position to the transform position of the entity to which they belong.
In the update function, we repeat that process every frame while checking if any collision occurred. To detect the collision, we simply check if there is an intersection between two rectangular shapes. You can see that in the function check_collision().
For now, we are just printing a message in the console to when two entities collide. To prevent objects from colliding with themself, we always check if the entities involved in the current collision are not equal.

engine/src/ecs/systems/collision_system.h

```cpp
#pragma once
#include "ecs/system.h"

namespace fuse::ecs {
struct collision_system: system {
    FUSE_INLINE void start() {
        for (auto& e : view<collider_component>()) {
            auto& tr = e.get_component<transform_component>();
            auto& col = e.get_component<collider_component>();
            col.collider.x = tr.translate.x;
            col.collider.y = tr.translate.y;
        }
    }

    FUSE_INLINE void update(float) {
        // get entity list
        auto entities = view<collider_component>();

        for (auto& e : entities) {
            auto& tr = e.get_component<transform_component>();
            auto& c1 = e.get_component<collider_component>();

            // update box collider offset
            c1.collider.x = tr.translate.x;
            c1.collider.y = tr.translate.y;

            // continue if disabled
            if (c1.disabled) { continue; }

            // check collision with others
            for (auto& o : entities) {
                if (o == e) { continue; }
                auto& c2 = o.get_component<collider_component>();

                if (check_collision(c1.collider, c2.collider)) {
                    FUSE_INFO("collision: %d -> %d", e.id(), o.id());
                }
            }
        }
    }

private:
    bool check_collision(const SDL_FRect& a, const SDL_FRect& b) {
        return ((a.x < b.x + b.w) && (a.x + a.w > b.x) &&
                (a.y < b.y + b.h) && (a.y + a.h > b.y));
    }
};
}
```
