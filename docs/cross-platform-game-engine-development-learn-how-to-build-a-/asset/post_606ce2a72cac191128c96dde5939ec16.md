## What this book covers

This book will take you through the entire process of designing and implementing a cross-platform Entity-Component-System-based game engine. It begins by describing how to set up a multiplatform development environment. It then goes over how to add custom features to the engine before concluding with a demonstration of how to utilize the game engine to make a simple Flappy Bird game.

## INTRODUCTION

### Introduction

I used to take the logic behind the scenes of games for granted. Making a game involves more than just graphics and storytelling. Things like memory management, event handling, physics, animation, serialization, platform compatibility, and many other factors are critical for a game to run effectively. Learning how to design and implement a game engine yourself gives you a better understanding of game mechanics and greater control over the features of the game we are trying to build.

The primary purpose of this book is to establish a solid foundation for building a cross-platform game engine from the ground up.

However, some game engine functionalities, such as networking and multiplayer support, will not be implemented in this book as they aren't required features to make a game. The emphasis will be on features such as texture rendering, animation, physics, scripting, and much more.

### Software Design

A game engine is a piece of software that is mostly used for the creation of video games. It typically holds essential libraries as well as support tools to allow the user to rapidly develop a game without having to think about things like how to load and render a texture, and so on.

Below (Figure 1) is an example of a simple software design for a typical game engine. The engine itself is simply a shared library. A shared library, also known as a shared object, is a file that is meant to be shared by several programs. The shared library's modules will be linked to a program's memory at runtime to perform actions defined by the developer.

### Static Linking vs Dynamic Linking

A computer program, in general, is a sequence of instructions written in a programming language to instruct the computer to perform certain actions. Those actions often require the use of other external libraries to function properly. Linking is the act of connecting an external library with an executable. There are primarily two types of linking techniques: static and dynamic linking.

Static linking combines the libraries and the program into a single executable file. This is done by the linker, which is the last step in the compilation process. To resolve external references, the linker mixes the required libraries with the program code. The linker creates an executable file that may be loaded into memory after that. The statically linked file contains both the library modules and the executable. This will generally result in a heavyweight output file.

Dynamic linking is handled by the operating system. The shared library is only loaded in memory when the executable starts its execution. As a result, the size of the executable file is reduced. External libraries can be updated and recompiled. The load time is also reduced if the shared library code is already in memory.
