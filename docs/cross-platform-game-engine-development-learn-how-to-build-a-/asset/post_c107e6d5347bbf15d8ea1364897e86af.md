The function **SDL_GetTicks(void)** is used to get the value of the time elapsed since the initialization of SDL in milliseconds. We are simply creating a macro that will be replaced during the compilation process by the function call. The reason it is done this way is that if we ever want to change the way time is retrieved in our game engine, we can simply change the function here and it will be reflected in the entire project.

Finally, we have a function to generate universally unique identifiers. A Universally Unique Identifier (UUID) in the game-dev industry is generally a 64-bit identifier that is used to uniquely identify a game object or an asset. The value generated is unique across the entire program.

- engine/src/pch.cpp

```
#include "pch.h"

namespace fuse {
static std::random_device randomizer;
static std::mt19937_64 generator(randomizer());
static std::uniform_int_distribution<ui64> distribution;

ui64 generate_uuid64() {
    ui64 uuid = INVALID_ID;
    do {
        uuid = distribution(generator);
    } while (uuid == INVALID_ID);
    return uuid;
}
}
```

std::random_device is a uniformly distributed integer random number generator that produces non-deterministic random numbers. As you can see, we are generating a 64-bit unsigned integer and we ensure that its value is not equal to INVALID_ID which is "0".

You can generate a uuid in your application.cpp like shown below.

### Window And Events

![](img/2763810ed0a1572c2bec59ee52dd75be_64_0.png)

A game loop is a game's primary event loop. It starts the processing of the user's input, performs the calculation of the game world's state, and generates a new output. An example would be trying to move the player in the game world using a gamepad or the keyboard. As a result, the user will press a button, and the state of the button will be processed by the input system. Then the player's next position will be calculated and passed to the renderer, which will eventually display the result on the screen for the player. All this will happen in a time range of milliseconds or even less, based on your computer power.

### Creating the Window

The first step in building our game-loop is to create a window. The good news is that SDL2 already has everything we need to achieve that.

The next code snippet is the code of the application.cpp which allows us to create our first window.

We simply create a window and a renderer with SDL_CreateWindow() and SDL_CreateRenderer(). The flag SDL_WINDOW_ALLOW_HIGHDPI ensures that the window will keep a consistent look on high-dpi monitors because this kind of monitor will have more dots or pixels per inch.

It is essential to instruct SDL about using the hardware or GPU (Graphics Processing Unit) for rendering because, in some cases, SDL might use the CPU instead. Because CPUs aren't inherently designed for graphics rendering, we want to make sure we are using the graphic power provided by the GPU. That is the reason the SDL_RENDERER_ACCELERATED flag is used.

To synchronize our window's refreshing rate with the current monitor refreshing rate, we use the flag SDL_RENDERER_PRESENTVSYNC when creating the renderer. This is also important because our final game or application will run on different devices with different refreshing rates. Even if our motions and animation will not be frame-based but time-based.

When a texture or a text is rendered in SDL, it will all be batched in the renderer and the final result will be presented to the screen using the SDL's built-in function SDL_RenderPresent().

engine/src/core/application.cpp

```
#include "pch.h"
#include "application.h"

namespace fuse {
static bool is_running = true;

FUSE_API void run_application(const app_config& config) {
if (SDL_Init(SDL_INIT_EVERYTHING) < 0) {
FUSE_ERROR("%s", SDL_GetError());
exit(EXIT_FAILURE);
}

// init SDL_image
if ((IMG_Init(IMG_INIT_JPG | IMG_INIT_PNG) < 0) {
FUSE_ERROR("%s", IMG_GetError());
}

// init SDL_ttf
if (TTF_Init() < 0) {
FUSE_ERROR("%s", TTF_GetError());
}

// init SDL_mixer
if (Mix_Init(MIX_INIT_MP3 | MIX_INIT_OGG) < 0 ||
Mix_OpenAudio(44100, MIX_DEFAULT_FORMAT, 2, 512)) {
FUSE_ERROR("%s", Mix_GetError());
}

// create window
auto w_flags = (SDL_WindowFlags)(SDL_WINDOW_RESIZABLE |
SDL_WINDOW_ALLOW_HIGHDPI);
SDL_Window* window = SDL_CreateWindow(config.title.c_str(),
SDL_WINDOWPOS_CENTERED,
SDL_WINDOWPOS_CENTERED, config.width, config.height,
w_flags);

// create renderer
auto r_flags = (SDL_RendererFlags)(SDL_RENDERER_ACCELERATED |
SDL_RENDERER_PRESENTVSYNC);
auto renderer = SDL_CreateRenderer(window, -1, r_flags);
if (!window || !renderer) {
FUSE_ERROR("%s", SDL_GetError());
exit(EXIT_FAILURE);
}

while (is_running) {
SDL_RenderClear(renderer);
SDL_RenderPresent(renderer);
}
}
}
```

The SDL_RenderClear() function will clear the renderer so that the next frame can be rendered into it. We also can change the background color, but we will talk about that later.

To initialize the SDL_mixer, we must call Mix_OpenAudio(). The first argument sets the frequency of the sound. 44100 is a common frequency supported by most systems. The second argument defines the sample format, which in this case is set to the default. The third argument is the number of hardware channels, which is two for stereo in this case. The fourth argument is the sample size, which defines the size of the chunks we use when playing sound. 512 is the value that fits for me if you ever have issues when playing song, try other values like: 1024 (1kb) or 2048 (2kb).
