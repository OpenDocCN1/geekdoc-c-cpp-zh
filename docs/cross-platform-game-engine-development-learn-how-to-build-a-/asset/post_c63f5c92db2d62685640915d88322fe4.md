## Message Logger

The message logger is a crucial element for software development in general. This feature will enhance our development experience by talking back to us about our code failures.

Add the code below to the bottom of your precompiled header file pch.h.

```
// ...

#if defined(_DEBUG)
#define FUSE_LOG(level, message, ...) \
    fprintf(stderr, "[%%] ", level); \
    fprintf(stderr, message, ##__VA_ARGS__); \
    fprintf(stderr, "\n");

#define FUSE_WARN(message, ...) FUSE_LOG("warning", message, ##__VA_ARGS__)
#define FUSE_ERROR(message, ...) FUSE_LOG("error", message, ##__VA_ARGS__)
#define FUSE_INFO(message, ...) FUSE_LOG("info", message, ##__VA_ARGS__)
#else
#define FUSE_INFO
#define FUSE_ERROR
#define FUSE_WARN
#endif
```

As you can see if we compile our code with the _DEBUG symbol defined, the macros FUSE_INFO, FUSE_WARN, FUSE_ERROR will also be compiled. But if the _DEBUG symbol is not defined, they won't be compiled. That's something we want because when we are done developing and testing our project, we would want it to only hold what is necessary for the user. We have defined a macro around fprintf().

Below is the snippet to quickly test the message logging.

FUSE_API void run_application(const app_config& config) {
    FUSE_INFO("this is an info!");
    FUSE_ERROR("this is an error!");
    FUSE_WARN("this is a warning!");
}
}

## Static and Runtime Assertions

Assertions can be used to hunt down the line of code where the program broke or even to prevent compilation from starting if a given condition is not met. A static assertion will confirm a condition before the code is compiled, whereas a runtime assertion will trigger an event at runtime to prevent your application from continuing. Add the following lines of code to the bottom of your pch.h file.

```
engine/src/pch.h
// ...
// runtime assertion
#define FUSE_ASSERT assert
// static assertion
#if defined(__clang__) || defined(__gcc__)
#define FUSE_STATIC_ASSERT _Static_assert
#else
#define FUSE_STATIC_ASSERT static_assert
#endif
```

Because assertions are different across compilers, we use the if-statement to ensure that the proper assertion call is made for the current compiler used. Below is a code snippet to test this feature:

```
engine/src/core/application.cpp
#include "pch.h"
#include "application.h"

namespace fuse {
    FUSE_API void run_application(const app_config& config) {
        FUSE_ASSERT(false && "runtime assertion!");
        FUSE_STATIC_ASSERT(false && "static assertion!");
    }
}
```

You will see that the code will not compile unless you set the static assertion's condition to true. When the code is finally compiled, the runtime assertion will trigger an event and show the following window when the program is executed.

![](img/2763810ed0a1572c2bec59ee52dd75be_57_0.png)

If you click on **Retry**, the line where it was triggered will be highlighted in the code editor and you will be able to know the reason for the crash.

## Function In-lining

Functions in-lining is one of the numerous fascinating C++ features that can be quite handy when it comes to program performance. In C++, an inline function is an optimization feature that reduces the execution time of a program. Whenever a function with the keyword inline is encountered during the compilation process, the compiler will try to replace that function with a copy of its definition. Inline functions are typically used when the function declarations are short, and the functions are called several times throughout a program.

Once again, add the following code snippet to the bottom of your **pch.h**.

- engine/src/pch.h

```
// . . .

// function inlining
#if defined(__clang__) || defined(__gcc__)
    #define FUSE_INLINE __attribute__((always_inline)) inline
    #define FUSE_NO_INLINE __attribute__((noinline))
#elif defined(_MSC_VER)
    #define FUSE_INLINE __forceinline
    #define FUSE_NO_INLINE __declspec(noinline)
#else
    #define FUSE_INLINE inline
    #define FUSE_NO_INLINE
#endif
```

You will also notice that the inline keyword is different across different compilers, so we also need to make sure the correct version is used when compiling our project on different platforms.
