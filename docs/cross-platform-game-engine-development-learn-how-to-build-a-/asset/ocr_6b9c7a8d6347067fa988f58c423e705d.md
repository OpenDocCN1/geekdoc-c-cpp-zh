# Figure 28 Tile set

The tile map in our game engine will be composed of multiple entities with a tile component attached to them. It gives us the ability to add more components to tile to achieve more advanced game effects. For example, we can choose to only add a collider component to some tiles to handle collisions only on those tiles. It will reduce the number of collision tests that have to be conducted, and it will result in a better performance for the end product.

Note : I always use "struct" instead of "class" because I just like structures. They remind me of C. Feel free to use the classes if you want. The only difference is that the member variables and functions defined by a structure are public by default.

```
engine/src/assets/tilemap.h
#pragma once
#include "asset.h"

namespace fuse {
struct tileset {
    std::set<asset_id> tilesets;
    int col_count = 0;
    int row_count = 0;
    int tilesize = 0;
};

struct tilemap_asset : asset {
    FUSE_INLINE tilemap_asset() = default;
    tilemap instance;
};
}
```

A tile map should also have the ability to combine many tiles sets to create a scene. That is the reason we have an std::set to store all tile sets. It is also important to know the unit size of a tile because a tile map is nothing but a grid.
