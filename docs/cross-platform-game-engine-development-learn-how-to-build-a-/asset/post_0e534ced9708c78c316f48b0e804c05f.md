## Entity Serializer

We are going to create a custom serializer to serialize all entities and their components. We will also create a serializer for our assets later.

### Basic Serialization Example

```cpp
void serialize_info(YAML::Emitter& em, ecs::entity& e) {
    auto& i = e.get_component<ecs::info_component>();
    em << YAML::Key << "info_component";
    em << YAML::BeginMap;
    em << YAML::Key << "uuid" << YAML::Value << i.uuid;
    em << YAML::Key << "name" << YAML::Value << i.name;
    em << YAML::Key << "tag" << YAML::Value << i.tag;
    em << YAML::EndMap;
}
```

The code snippet above shows how the "info_component" can be serialized using yaml-cpp. It takes a YAML::Emitter as a parameter and the entity we want to retrieve the component from. The emitter is just a handle that can be used to push data to the buffer allocated for the current serialization process. Each field of the component is stored using a key. The key will be used to retrieve the data by deserialization. The component itself is a map which contains data fields.

### Basic Deserialization Example

```cpp
void deserialize_info(YAML::Node node, ecs::entity& e) {
    if (auto data = node["info_component"]) {
        auto& i = e.add_component<ecs::info_component>();
        i.name = data["name"].as<std::string>();
        i.tag = data["tag"].as<std::string>();
        i.uuid = data["uuid"].as<u64>();
    }
}
```

To deserialize an object, you need the YAML::Node that represents the object in the YAML file you are trying to deserialize from. That's why this function takes a YAML::Node as a parameter and the target entity that will have the component attached to. All nodes in a YAML document (including the root) are represented by YAML::Node. We have the ability to access any data in the node using its key. The template function "as<T>()" is used to convert the value to its correct type.

### Operators Overloading

yaml-cpp only supports serialization and deserialization of basic types, such as int, float, double, and string. However, we also want it to be able to serialize custom types such as our vec2f or vec2i, among others. So let us overload some operators to make that possible.

Create a new folder called "helpers" and a header file called "yaml.h" in that folder. Below is a code snippet that shows the content of the header file.

### engine/src/helpers/yaml.h

```cpp
#pragma once
#include "math/vec2.h"
#include "yaml-cpp/yaml.h"
namespace YAML {
template <>
struct convert<fuse::vec2f> {
FUSE_INLINE static Node encode(const fuse::vec2f &rhs) {
Node node;
node.push_back(rhs.x);
node.push_back(rhs.y);
node.SetStyle(EmitterStyle::Flow);
return node;
}
FUSE_INLINE static bool decode(const Node &node,
fuse::vec2f &rhs) {
if (!node.IsSequence() || node.size() != 2) {
return false;
}
rhs.x = node[0].as<float>();
rhs.y = node[1].as<float>();
return true;
}
};
// stream operator
FUSE_INLINE Emitter &operator <<(Emitter &emitter, const
fuse::vec2f &v) {
emitter << Flow;
emitter << BeginSeq << v.x << v.y << EndSeq;
return emitter;
}
}
```

Because we will only need the vec2f to serialize our components, we have only overloaded the operators for the vec2f datatype. You can do the same for vec2i by just changing the vec2f to vec2i. As you can see this is done in the YAML namespace because we are overloading operators from the yaml-cpp library.

We are now ready to serialize our entities and their components.

### Output File Format

It is important for us to have an idea of the structure of the file we will get at the end when everything is serialized because it helps us to know how to implement our serializer.

Below is a file that shows the example scene serialized from our game.

      id: 2234281881859053318

      source: assets/bg1.png

      name: music
      source: assets/song.mp3

This file has two main parts: "assets" and "entities". Our focus, for now, is only on the "entities" part. As you can see, a new entity starts with a minus character ("-") followed by its components. The entity id is not serialized because it is a runtime value. Comments can be added using the hash character "#". Each component is stored with its name as key and its data fields as values to the key. Each field will simply be addressed by its key just as we would access a field in a std::map.
