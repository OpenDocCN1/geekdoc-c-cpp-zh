
```cpp
#pragma once
#include "script_instance.h"

namespace fuse {
struct player_controller : script_instance {
    FUSE_INLINE void on_collision(ecs::entity e) {
        auto& sp = get_component<ecs::sprite_component>();
        sp.sprite = get_asset<texture_asset>("dead")->id;
        get_component<ecs::collider_component>().disabled = true;
        get_component<ecs::rigid_body_component>().disabled = true;
    }

    FUSE_INLINE void on_update(float dt) {
        auto& rb = get_component<ecs::rigid_body_component>();
        if (inputs::is_key(SDL_SCANCODE_SPACE)) {
            rb.body.set_force_y(-1000.0f);
        }
        else {
            rb.body.set_force_y(0.0f);
        }
    }
};
}
```

To keep the plane in the air, we use the space key. When it is pressed, an upward thrust is applied to the plane to respond to the gravity forcing it to fall. The player also has to respond to collisions with pipes and the ground.

We are implementing both the "on_update" and "on_collision" functions. The update function will simply apply thrust to the plane every time the space key is pressed. If the player collides with either a pipe or the ground, we will change its sprite to a different one that shows that the player is dead. Then we disable the rigid body and the collider component to prevent them from continuing to be updated by the systems.

Note: You can as well use a mouse button instead of the space key.

In the member variables section, we have some important variables defined. We have an array called "pipes", which is going to hold a list of all the pipes created. This is important because we want to destroy the pipe when it is outside the screen viewport.

Another way to achieve that would be to create a script and attach it to the pipe when it is created. The script will check the current position of the pipe each frame and destroy it when it gets out of bounds. But it is not a good practice to attach a script to an object that has a short lifecycle like a particle because creating a script requires heap allocation, which can cause performance issues when there are too many active scripts.

We have a Boolean called “game_over” which tells us if the plane has crashed or not. We will use the “time” to know when to spawn new pipes and finally we have the “score”.

```
// ...
FUSE_INLINE void spawn_pipe(float x, float y) {
    auto pipe = add_entity();
    auto& tr = pipe.get_component<ecs::transform_component>();
    tr.translate = vec2f(x, y);

    // add rigid body
    auto& rb = pipe.add_component<ecs::rigidbody_component>();
    rb.body.gravity_scale = 0.0f;
    rb.body.velocity.x = -100.0f;

    // add sprite
    auto pipe_sprite = get_asset<texture_asset>("pipe");
    auto& sp = pipe.add_component<ecs::sprite_component>();
    sp.flip = (y < 0) ? SDL_FLIP_NONE : SDL_FLIP_VERTICAL;
    sp.sprite = pipe_sprite->id;

    // add collider
    auto& cl = pipe.add_component<ecs::collider_component>();
    cl.collider = {
        tr.translate.x,
        tr.translate.y,
        (float)pipe_sprite->instance.width,
        (float)pipe_sprite->instance.height
    };
    pipes.push_back(pipe);
}
// ...
```

Above is the pipe spawner script member function which is used to generate a pipe. It takes the position that the pipe must be generated as an argument.
As you can see we are creating an entity with a rigid body, sprite, and collider component. Because we always have to create a pipe from top to bottom and another one from bottom to top, we are checking if the position on the y-axis is smaller than zero to know if the sprite must be flipped vertically or not.
The size of the box collider is the same as the sprite size.

## "update_pipes" works.

```
engine/src/scripts/pipe_spawner.h

// ...
FUSE_INLINE void update_pipes() {
    auto it = pipes.begin();
    while (it != pipes.end()) {
        // remove dead pipe
        auto& pipe = (*it);
        if (!pipe.is_alive()) {
            it = pipes.erase(it);
            continue;
        }
        it++;
    }
}
// ...
```

The main job of the "update_pipes" function is to loop through the pipe list to check if any pipe is out of bounds and destroy it. This is really important because, without it, the memory size will increase every time a pair of pipes is created. A while loop is used because we want to be able to erase data from the array while looping through it.

Before we take a look at the “on_update” function, I want you to define the following function in your math folder because it will be used to generate random numbers.

```
engine/src/math/random.h
#pragma once
namespace fuse::math {
    FUSE_INLINE int random(int min, int max) {
        static bool first = true;
        if (first) {
            srand(time(NULL)); // seeding for the first time only!
            first = false;
        }
        return min + rand() % ((max + 1) - min);
    }
}
```
