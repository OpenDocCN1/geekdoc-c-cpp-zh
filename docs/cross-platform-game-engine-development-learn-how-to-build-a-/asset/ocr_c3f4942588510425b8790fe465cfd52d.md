When you ask the computer to find something in memory at a specific address, it will not only copy what you ask for, but it will also copy other data around what you asked for and store it all in Cache memory. So, the next time you ask for something else, the computer will just grab it from cache rather than fetch it from RAM again. The fact that data is saved inconsistently in memory drastically reduces CPU-Cache usage, resulting in a performance hit.

# Component-Oriented Design

The following picture shows how a component-oriented design is made. As you can see, each game object will have a list of components that define its behaviour. All components like Transform, Sprite, etc. will inherit an abstract class called Component.

This technique will not solve the problem of memory and CPU-cache usage of the OO design, but it takes away the virtual lookup table for virtual functions and offers the ability to have a boss than can also be a player because being a player or a boss is just a matter of components added or removed. This will perform better than OO.
