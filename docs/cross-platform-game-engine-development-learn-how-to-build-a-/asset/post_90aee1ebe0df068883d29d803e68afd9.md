
## Member Variables

The **registry.h** header file contains the definition of a structure called "registry". This structure oversees storing and managing all existing entities and their components. Let's start with the member variables.
The first member variable is an `std::unordered_map` called `_components`. It's a map of component arrays that stores a specific array for each component type id.
The second member variable, `_signatures`, is a map that assigns to each existing entity a signature of components. If we want to know, for example, if an entity has a transform component, we will simply check if the **componentid** of the transform component is found in the signature of the entity. The last member variable is a counter for entityids. This variable will be increased every time a new entity is added.

## Member Functions

Let's look at all the member functions defined in this file. We will start from top to bottom.
The first function is the **clear()** which simply has the role of cleaning the memory of the registry and resetting the entityid counter.

The function **add_entity()** as the name says, will add a new entity to the registry by assigning a unique entityid and an empty signature. Every time a new component is added to the entity, the id of that component will be added to the signature.

Adding entities also implies destroying them. So, the **destroy()** function will look for any data related to that entityid and destroy it. Data like components and signatures.
The function **view()** is used to retrieve all entities with a component of type "T". This will be used in our systems to update those components.

**get_component(), add_component(), remove_component(),** and **has_component()** is used to retrieve, add, and remove components, as well as to determine whether an entity has a component. Finally, we have **get_component_array()**, which is a function we can use to get a specific component array for further use like erasing a component of a specific entity, etc. This function will first make sure the array is already registered and register if not.

### engine/src/ecs/entity.h

```cpp
#pragma once
#include "registry.h"

namespace fuse::ecs {
struct entity {
    FUSE_INLINE entity(registry* r): _registry(r) { _entity = r->add_entity(); }
    FUSE_INLINE entity(entity_id e, registry* r): _registry(r),
    _entity(e) {}
    FUSE_INLINE operator entity_id() { return _entity; }
    FUSE_INLINE entity() = default;

    template <typename T, typename... Args>
    FUSE_INLINE T& add_component(Args&&... args) {
        return _registry->add_component<T>(_entity, std::forward<Args>(args)...);
    }

    template <typename T>
    FUSE_INLINE T& get_component() {
        return _registry->get_component<T>(_entity);
    }

    template <typename T>
    FUSE_INLINE void remove_component() {
        _registry->remove_component<T>(_entity);
    }

    template <typename T>
    FUSE_INLINE bool has_component() {
        return _registry->has_component<T>(_entity);
    }

    FUSE_INLINE bool is_alive() {
        return _registry && _registry->is_alive(_entity);
    }

    FUSE_INLINE entity_id id() { return _entity; }

    FUSE_INLINE void destroy() { _registry->destroy(_entity); }

private:
    entity_id _entity = INVALID_ID;
    registry* _registry = NULL;
};
}
```

Above is the definition of the entity structure. This will make it easy for us to manipulate single entities without having to use the registry every time. This is just a wrapper around an entityid and the registry because we are simply calling the functions, we defined in the registry earlier.

```cpp
#pragma once
#include "entity.h"

namespace fuse::ecs {
struct system {
    FUSE_INLINE virtual ~system() = default;

    FUSE_INLINE void prepare(registry* rg, SDL_Renderer* rd) {
        this->_registry = rg;
        this->_renderer = rd;
    }

    template<typename T>
    FUSE_INLINE auto view() {
        std::vector<entity> entities;
        for(auto& e : _registry->view<T>()) {
            entities.push_back(entity(e, _registry));
        }
        return entities;
    }

    FUSE_INLINE virtual void update(float) {}
    FUSE_INLINE virtual void start() {}

protected:
    SDL_Renderer* _renderer = NULL;
    registry* _registry = NULL;
};
}
```

The system.h header file defines the minimal behavior of a system. It has some pointers to access some variables we created before, like the renderer, and the registry. The derived classes will have the choice to implement their own versions of the functions start(), and update().
The function prepare() simply sets the member pointers to their specific target values. The view() function will convert all entityids into entity objects so that we can quickly access their components.

> Note: Whenever you create an interface or an abstract class, make sure it has a virtual destructor. It will ensure its destruction when the children's class is destroyed.

## Creating Components and Systems

We are going to create some components in this section to test if our entity-component system works properly. The components we will create are the info- and the transform components.
A transform stores the position, the scale, and the rotation of a game object in the scene. This information is important to the renderer system because it will be used to know how and where to render a specific object. To reduce the number of included statements in our project, we will group our components in various categories. The first category as you can see below is called “common”. This category is for components that are required for all entities.

### engine/src/ecs/components/common.h

```cpp
#pragma once
#include "math/vec2.h"

namespace fuse::ecs {
struct info_component {
    FUSE_INLINE info_component(const info_component&) = default;
    FUSE_INLINE info_component() = default;

    uuid64 uuid = generate_uuid();
    std::string name = "entity";
    std::string tag = "default";
};

struct transform_component {
    FUSE_INLINE transform_component(const transform_component&) = default;
    FUSE_INLINE transform_component() = default;

    vec2f translate = vec2f(0.0f);
    vec2f scale = vec2f(1.0f);
    float rotation = 0.0f;
};
};
```

Each game object should at least have a name and a position. The **info_component** stores the name and a unique universal identifier for the entity it belongs to. The UUID can be used for serialization (more about later) or event parent-child relationship between entities.

Let’s create a simple system to test if our entity component system performs well. The system below retrieves all entities with a transform component, increase its position, and print the result to the console.

### engine/src/ecs/systems/test_system.h

```cpp
#include "ecs/system.h"
#include "ecs/components/common.h"

namespace fuse::ecs {
struct test_system : system {
void update(float dt) {
for (auto e : view<transform_component>()) {
auto& t = e.get_component<transform_component>();
FUSE_INFO("id: [%d], x: %f", e.id(), t.translate.x++);
}
}
};
}
```

## Creating a Scene

To test our ECS, we need a scene in which the entities must exist. So, we are going to create a scene in which we can add entities.

- engine/src/ecs/scene.h

```cpp
#pragma once
#include "systems/test_system.h"

namespace fuse::ecs {
struct scene {
    FUSE_INLINE scene(SDL_Renderer* rd): _renderer(rd) {
        register_system<ecs::test_system>();
    }

    FUSE_INLINE ~scene() {
        for (auto& s : _systems) { FUSE_DELETE(s); }
        _registry.clear();
        _systems.clear();
    }

    FUSE_INLINE ecs::entity add_entity(const std::string& name) {
        auto entity = ecs::entity(&_registry);
        entity.add_component<info_component>().name = name;
        entity.add_component<transform_component>();
        return entity;
    }

    FUSE_INLINE void update(float dt) {
        for (auto& sys : _systems) { sys->update(dt); }
    }

    FUSE_INLINE void start() {
        auto e = this->add_entity("test");
        e.add_component<transform_component>();
        for (auto& sys : _systems) { sys->start(); }
    }

    template <typename T>
    FUSE_INLINE void register_system() {
        FUSE_STATIC_ASSERT(std::is_base_of<ecs::system, T>::value);
        auto new_system = new T();
        new_system->prepare(&_registry, _renderer);
        this->_systems.push_back(new_system);
    }

private:
    std::vector<ecs::system*> _systems;
    SDL_Renderer* _renderer = NULL;
    ecs::registry _registry;
};
};
```

In the member variables section, we have an array called `_systems`, where all our systems will reside. The function `register_system()` is used to register the system defined by the template argument.
