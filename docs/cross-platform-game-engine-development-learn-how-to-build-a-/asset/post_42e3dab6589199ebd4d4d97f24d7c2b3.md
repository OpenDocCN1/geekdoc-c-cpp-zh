## Script Instance Update

In the previous chapter, we tested the script system by just moving an entity around using the keyboard. But what if we want to get access to some assets? Or let's say we want to find a specific entity in the scene, etc. For instance, we want to change the sprite of the player when he dies. That's exactly what we want to do here. We want to add more member functions to the script instance that allow access to the asset registry.

```
engine/src/scripts/script_instance.h
protected:
// ...
FUSE_INLINE void destroy() {
    _registry->destroy(_entity);
}

FUSE_INLINE ecs::entity find_entity(const std::string& name) {
    for(auto& e : _registry->view<ecs::info_component>()) {
        auto& i = _registry->get_component<ecs::info_component>(e);
        if(!i.name.compare(name)) {
            return ecs::entity(e, _registry);
        }
    }
    return ecs::entity();
}

template <typename T>
FUSE_INLINE T* get_asset(const std::string& name) {
    return _assets->get<T>(name);
}
// ...
```

The first function “destroy” can be used to delete the entity that is currently holding the script. The second “find_entity” function looks for an entity using the name provided as an argument. Finally, we have a method that takes a string, a template type and returns an asset pointer. This function will search the asset of type “T” with the name supplied as argument.

## Adding Ground Sprite

We want to add a ground to prevent the plane from falling forever. The ground will have a box collider to allow collision checking against the plane. It will also be animated to give the feeling of a continuous translation motion.

![](img/2763810ed0a1572c2bec59ee52dd75be_193_1.png)

Figure 40 Ground Translation Motion

Because the game must last as long as the player is alive, we must make this animation endless. We can achieve the same effect by simply switching from one frame to the next in a frame animation. However, because I am not an artist and we want to see the potential of the scripting system, we will simply do it using a script.

```
engine/src/scripts/scrolling_ground.h
#pragma once
#include "script_instance.h"
namespace fuse {
struct scrolling_ground : script_instance {
FUSE_INLINE void on_start() {
width = get_asset<texture_asset>("ground")->instance.width;
}
FUSE_INLINE void on_update(float dt) {
auto& tr = get_component<ecs::transform_component>();
if(tr.translate.x + width < 380) {
tr.translate.x = 0.0;
}
}
private:
float width;
};
}
```

We are implementing a start function and an update function in this script. The start function will retrieve the width of the ground sprite. It is important because we will use it to check if the current position of the sprite plus its height is smaller than the width of the window. If that's the case, we will know that we need to bring the ground sprite back to its initial position. The "380" used in the "on_update" function is nothing but the width of the window.

We could have passed the game's configuration as a parameter to the "script_instance" constructor so that we would get the width by calling a parent function, but that's your job.

// load player sprites

bg.add_component<sprite_component>().sprite = background->id;

// ground
auto gd = add_entity("ground");
auto& gds = gd.add_component<ecs::script_component>();
gds.bind<scrolling_ground>();
gds.name = "scrolling_ground";
auto& gd_tr = gd.get_component<transform_component>();
gd_tr.translate = vec2f(0.0f, 620);
gd.add_component<rigidbody_component>().body.velocity.x = -100.0f;
auto& gd_sp = gd.add_component<sprite_component>().sprite = ground->id;
auto& gd_cl = gd.add_component<collider_component>();
gd_cl.collider = { 0, 0, (float)ground->instance.width,
(float)ground->instance.height };

// start systems
for (auto& sys : _systems) { sys->start(); }
}
