
to de- and serialize other components.
As you can see, we are including all component types here because we are going
to de- and serialize all of them. The constructor of the serializer takes a pointer to
the registry where all entities and components are stored. The deserialize function
takes the root node of entities, and the serialize function takes a reference to the
buffer where everything will be stored before being exported to a YAML file.
Let's take a look at each function's implementation specifically.

```
engine/src/ecs/serializer.h
FUSE_INLINE void deserialize(YAML::Node nodes) {
  // clear registry
  _registry->clear();

  // deserialize entities
  for (auto node : nodes) {
    ecs::entity e(_registry);
    deserialize_info(node, e);
    deserialize_transform(node, e);
    deserialize_rigidbody(node, e);
    deserialize_collider(node, e);
    deserialize_sprite(node, e);
    deserialize_animation(node, e);
    deserialize_text(node, e);
    deserialize_script(node, e);
  }
}
```

This function starts by making sure that the registry is cleared. This will prevent
the data loaded to be added on top of the already existing data in the registry.
Then we will loop through the entity's node given as an argument. For each node,
we will create an entity and call for each component type the deserialize function.
Don't worry about all the functions called here we will implement each one of
them in just a moment.

The next code snippet shows the definition of the serialize function. This function
takes a reference to an emitter as an argument. It starts by creating a sequence
called "entities", which is where all our entities will be listed.
Then we follow up by adding a map for each in which the entity's components
will be listed. Similar to the deserialize function, we are calling the serialize
function for each component type, passing the entity we want to retrieve the
component from.

Note: it is required to close all the nodes we have opened. Because all entities
have an info_component by default, we can retrieve a list of all entities by just getting a view of the info_component, which returns the list of all entities with an info_component.

```
engine/src/ecs/serializer.h
FUSE_INLINE void serialize(YAML::Emitter& em) {
  em << YAML::Key << "entities" << YAML::Value << YAML::BeginSeq;
  for (auto& e : _registry->view<ecs::info_component>()) {
    ecs::entity entity(e, _registry);

    em << YAML::BeginMap;
    serialize_info(em, entity);
    serialize_transform(em, entity);
    serialize_rigidbody(em, entity);
    serialize_collider(em, entity);
    serialize_sprite(em, entity);
    serialize_animation(em, entity);
    serialize_text(em, entity);
    serialize_script(em, entity);
    em << YAML::EndMap;
  }
  em << YAML::EndSeq;
}
```

## Info Component Serialization

```
// serialize info_component
FUSE_INLINE void serialize::info(YAML::Emitter &em, entity &e) {
    if (e.has_component<ecs::info_component>()) {
        auto &i = e.get_component<ecs::info_component>();
        em << YAML::Key << "info_component";
        em << YAML::BeginMap;
        em << YAML::Key << "uuid" << YAML::Value << i.uuid;
        em << YAML::Key << "name" << YAML::Value << i.name;
        em << YAML::Key << "tag" << YAML::Value << i.tag;
        em << YAML::EndMap;
    }
}
```

```
// deserialize info_component
FUSE_INLINE void deserialize_info(YAML::Node node, entity &e) {
    if (auto data = node["info_component"]) {
        auto &i = e.add_component<ecs::info_component>();
        i.name = data["name"].as<std::string>();
        i.tag = data["tag"].as<std::string>();
        i.uuid = data["uuid"].as<uint64>();
    }
}
```

The functions above show how the info component is de- and serialized. We always have to check if the entity has the component before attempting any serialization. The same thing is done while deserializing. We need to make sure there is a node available with that component's name.

Below is the same definition for the transform component. The transform component is mainly the reason why we had to implement an encode and decode for the vec2f type. But as you can see, there is no difference in the way a vec2f is serialized or deserialized compared to an integer, for example. We are using the same operator because we have overloaded it.

## Transform Component Serialization

```
// serialize transform component
FUSE_INLINE void serialize_transform(YAML::Emitter& em, entity& e) {
    if (e.has_component<transform_component>()) {
        auto& t = e.get_component<transform_component>();
        em << YAML::Key << "transform_component";
        em << YAML::BeginMap;
        em << YAML::Key << "translate" << YAML::Value << t.translate;
        em << YAML::Key << "rotation" << YAML::Value << t.rotation;
        em << YAML::Key << "scale" << YAML::Value << t.scale;
        em << YAML::EndMap;
    }
}
// deserialize transform component
FUSE_INLINE void deserialize_transform(YAML::Node node, entity& e) {
    if (auto data = node["transform_component"]) {
        auto& t = e.add_component<transform_component>();
        t.translate = data["translate"].as<vec2f>();
        t.rotation = data["rotation"].as<float>();
        t.scale = data["scale"].as<vec2f>();
    }
}
```

To keep things consistent, we have chosen to use the name of the member variable as the key. Sometimes, you would use a shorter version of the name to reduce the size of the output file.
