
```bash
#!/bin/bash

# check build dir
if [ ! -d build ]
then
    mkdir build
fi

# generate cmake files
cmake -S . -B ./build -DCMAKE_BUILD_TYPE=Debug -DBUILD_SHARED_LIBS=ON

# copy assets files to output dir
cp -R "./resource" "./build/bin/assets"

# compile project
cd build && cmake --build .
echo compilation finished!
```

Both scripts will check if a build folder exists in the project's root directory and create one if not. Then CMake will produce all the files required for building the project for the current platform.

Because we will be using assets like audios, textures, and fonts, we want to copy the contents of the resource folder into the output folder of the built project.

Additionally, the win-build.bat will make sure all libraries .dll files required are copied from the folder windows/bin to the output folder. CMake will go on to compile the project using the platform-specific compiler that was installed earlier in the previous chapter.

CMake needs to know where to find the root CMakeLists.txt file to generate the project files for the current platform. That's why we need to pass that information to CMake as an argument using [-S <path to file>].

The [-B <output dir>] is used to tell CMake where to store all the build files generated.

The symbol BUILD_SHARED_LIBS is required to force the compiler to build all the libraries in our project as a shared library instead of a static library.

## CMakeLists.txt Files

CMake can generate build files by combining multiple CMakeLists.txt files in various locations. In our project's folder tree (Figure 16), you can see that there is a CMakeLists.txt file in the root folder and in both the "engine" and "game" folders. These files define how CMake must generate the build files for our project.

Note: these files must be named: "CMakeLists.txt" because of how CMake operates.

CMake will search for that specific filename in all directories to collect all the necessary information before generating the build files of the project. Let's take a close look at each CMakeLists.txt file.

- Project/CMakeLists.txt

```cmake
cmake_minimum_required(VERSION 3.16)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS ON)
set(CMAKE_CXX_STANDARD 17)

project(fuse2d)

# output directories
set(CMAKE_ARCHIVE_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)
set(CMAKE_LIBRARY_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)

# add engine and game
add_subdirectory(engine)
add_subdirectory(game)
```

The CMakeLists.txt file described above is the one located in the project's root directory. As you can see, we begin by providing the minimum version of CMake that is allowed (version 3.16). This is important because some older versions of CMake perform differently. We'd also like to declare which standard version of C++ we'll be using. It is C++17 in this scenario. We then proceed to create a project (solution or workspace) called "fuse2d," which is the name we've given to the game engine. You may choose any name you like.

We want CMake to save all build files generated in a specific directory, so we use the built-in macro CMAKE_BINARY_DIR, which is the complete path to the top level of the current CMake build tree or basically, the path to the root directory of the project.

Lastly, we add the engine and the game project to the workspace using the function “add_subdirectory”, so that there can all be merged before CMake builds the project.

That's all we need to do for the root CMakeLists.txt. Let's do the same for the engine CMakeLists.txt file.

- Project/engine/CMakeLists.txt

```cmake
# engine project (shared lib)
project(engine VERSION 0.0.1)

# get all cpp-files
file(GLOB_RECURSE SRC_FILES src/*.cpp CMAKE_CONFIGURE_DEPENDS)
add_library(${PROJECT_NAME} ${SRC_FILES})

# define symbols
add_definitions(-DFUSE_EXPORT)
add_definitions(-D_DEBUG)

# windows platform
if (WIN32)
	target_include_directories(${PROJECT_NAME} PUBLIC ${CMAKE_SOURCE_DIR}/windows/includes)
	target_link_directories(${PROJECT_NAME} PUBLIC ${CMAKE_SOURCE_DIR}/windows/libs)
endif (WIN32)

# linux platform
if (UNIX)

endif (UNIX)

# precompile headers
target_precompile_headers(${PROJECT_NAME} PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}/src/pch.h)

# add include directory
target_include_directories(${PROJECT_NAME} PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}/src)
```

The engine’s CMakeLists.txt file, as described above, can be found in the folder "Project/engine". As you can see, we don’t need to define the CMake version as well as the C++ standard version here because they are already defined in the root CMakeLists.txt file. We simply start by creating a project called “engine” with the version number “0.0.1”. The specification of the version number is optional.

We then want to recursively search for all .cpp files in the source folder of the engine project (engine/src) because they will all be compiled to generate the engine library.

CMake allows us to define symbols that can affect how we would want the code to be compiled. We’ve defined _DEBUG and FUSE_EXPORT in this scenario. The _DEBUG macro instructs the compiler to generate data for the debugging. FUSE_EXPORT will be used to instruct the compiler about which modules of the engine to export into the library (more about later). We also want to make sure CMake knows where the external libraries that the engine will be using are on Windows. which is why we are using the if(WIN32) statements to check if the current platform used is Windows. You will get later why we don’t have to do that for Linux.

A precompiled header (PCH) is a header file (C/C++) that has been compiled into an intermediate form that the compiler can parse more quickly. Precompiled headers can significantly reduce compilation time, especially for large header files, header files that include many other header files, or header files that are included in many translation units. CMake gives us the ability to add precompile headers to our project via the function: target_precompile_headers().

There is a file called “pch.h” in the folder “engine” which is the precompiled header for the engine library. It will be used to include all important C++ standard libraries as well as other custom code that will be accessible globally. This will significantly reduce the time needed to compile the engine library.

Note: The only requirement for using precompile headers is that we must include the pch.h header file in all .cpp-files of the engine.

We call the function “target_include_directories” to attach all include directories, so that the compiler will know which header files to include during the compilation process.

The last CMakeLists.txt file we will talk about is the one found in “game”.

- Project/game/CMakeLists.txt

```cmake
# runtime project (.exe)
project(game VERSION 0.0.1)

# get all cpp-files
file(GLOB_RECURSE SRC_FILES src/*.cpp CMAKE_CONFIGURE_DEPENDS)
add_executable(${PROJECT_NAME} ${SRC_FILES})

# link libraries
target_link_libraries(${PROJECT_NAME} engine)

# includes directories
include_directories(${CMAKE_SOURCE_DIR}/engine/src)
target_include_directories(${PROJECT_NAME} PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}/src)
```

The code above shows how the game-executable's **CMakeLists.txt** file is defined. Important to note here is that we are linking the engine as a library, and we also include its source directory as an include directory so that the game project can also access the code from the engine library.
