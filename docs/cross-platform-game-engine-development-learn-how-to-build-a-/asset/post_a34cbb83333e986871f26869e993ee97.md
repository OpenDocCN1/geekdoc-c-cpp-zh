
## Events Handling

Events can occur in various places in a program, e.g., when a user clicks a button or moves the mouse. The event system's job is to recognize the event and execute a specific callback action. We now want to give our window the ability to respond to events like resizing, mouse motion, key down, and more. Create two files in your project, **inputs.h** and **inputs.cpp**.

```cpp
#pragma once

namespace fuse::inputs {
FUSE_API void initialize(SDL_Window*);
FUSE_API void dispatch_events();
FUSE_API bool is_key(int);
}
```

```cpp
#include "pch.h"
#include "inputs.h"

namespace fuse::inputs {
static const uint8_t* keyboard = NULL;

bool is_key(int key) { return keyboard[key]; }

void initialize(SDL_Window* window) {
    keyboard = SDL_GetKeyboardState(NULL);
}

void dispatch_events() {
    static SDL_Event event;
    while (SDL_PollEvent(&event)) {
        switch (event.type) {
        case SDL_KEYDOWN:
            keyboard = SDL_GetKeyboardState(NULL); break;
        case SDL_KEYUP:
            keyboard = SDL_GetKeyboardState(NULL); break;
        }
    }
}
}
```

The code snippet above shows the code of the **inputs.cpp** file. The keyboard is represented here by a small array of 8-bit unsigned integers in which each index stores the state of a key. SDL has predefined macros to distinguish between event types. For example, when a key is pressed, the `SDL_KEYDOWN` event is triggered, or `SDL_MOUSEDOWN` when a mouse button is pressed. The `is_key(int)` function will simply return the state of the key code past as argument.

You can test the setup in your main loop using the following code snippet.

```
// engine/src/core/application.cpp
// ...
inputs::initialize(window);

while (is_running) {
    inputs::dispatch_events();
    if (inputs::is_key(SDL_SCANCODE_A)) {
        FUSE_INFO("key 'a' pressed!");
    }
    SDL_RenderClear(renderer);
    SDL_RenderPresent(renderer);
}
```

> [info] key 'a' pressed!
> [info] key 'a' pressed!

We now have a basic concept in place. But we still can't close the windows or event notify our application about the event that just occurred.

## Identification of Events

We want to create a system in which each event triggered can also be broadcast to the entire application via a sort of notification system. That way, we will be able to implement callback functions anywhere in our program and make it respond to a specific event occurrence. Now, one major problem with a notification system is recognizing what type of message or event is being sent. As a result, we will create a type system in which each event's type will be assigned a unique number. That number will be used to recognize that event and call the proper callback when it occurs. Create the following header file in your project:

- engine/src/core/typeid.h

```cpp
#pragma once

namespace fuse {
FUSE_INLINE const uint32_t get_unique_typeid() {
    static uint32_t type = 1u;
    return type++;
}

template <typename T>
FUSE_INLINE const uint32_t type_id() {
    static const uint32_t type = get_unique_typeid();
    return type;
}
}
```

In **typeid.h** above, we have the function **get_unique_typeid()** that returns an unsigned integer. Its definition is found in the **typeid.cpp** file. This function will simply increase a static variable every time it is called. You will also find a template function called **type_id()** in the header file.

A template function is not a type, function, or any other entity. A source file holding only template definitions yields no code. A template must be instantiated before any code can appear: the template arguments must be determined so that the compiler may build an actual function [4].

What will happen is that the compiler will generate a definition of this function for each template type used while calling it. Since the value returned by the function **get_unique_typeid()** is stored in a static constant integer, it will remain the same every time the function is called with the same template type.

You can test it like shown below:

```cpp
auto id1 = type_id<int>(); // id1 = 1
auto id2 = type_id<int>(); // id2 = 1
auto id3 = type_id<float>(); // id3 = 2
```

Just like that, we have something in place to attach a unique id to any type in our program. We will also use this type-system as the foundation for our entity-component system (ECS). More about that later.

## Event Callback

An event callback is just a function that will be called when a specific event is triggered. Create a new header file called "event.h" like shown below.

```cpp
#pragma once
#include "typeid.h"

namespace fuse {
using event_id = uint32_t;

struct event_instance {
    FUSE_INLINE virtual ~event_instance() = default;
};

// callback lambda
template <typename T>
using callback_function = std::function<bool(const T&)>;

struct callback_instance {
    FUSE_INLINE virtual ~callback_instance() = default;
    virtual bool run(event_instance*) = 0;
};

template <typename T>
struct event_callback : callback_instance {
    FUSE_INLINE event_callback(callback_function<T>&& clbk):
    callback(std::move(clbk)) {}

    FUSE_INLINE bool run(event_instance* e) {
        auto data = static_cast<const T&>(*e);
        return callback(data);
    }

private:
    callback_function<T> callback;
};

using callback_list = std::vector<std::shared_ptr<callback_instance>>;
}
```

We start by defining an abstract structure called **event_instance** which is the base structure of all kinds of event. Every time we create a new type of events, we will make sure it inherits from this structure.

As mentioned earlier, the event system will recognize an event and call the proper callback action or function for that event. Since the type of the event, we will implement the callback function for is not unique, we will use the template feature of C++ to generalize the concept. The **callback_function** is a function type definition that takes a pointer to an **event_instance** and returns a Boolean to tell if the event system should continue managing that event or stop.

We then use that **callback_function** type we just created to define our final **event_callback** structure, which must also be templated to make sure its callback function member variable also has a specific type. The function "execute" is a virtual function that the **event_callback** structure must implement to make sure the callback function can be executed by the dispatcher.

**callback_list** is simply a typedef of an array of callbacks. It will make our code more readable.

## Event Dispatcher

We have a system in place to recognize events, and we also have a structure for an event callback. Now let's put together a dispatcher that will manage everything both the events and the callbacks.

Go ahead and create a new header file called **dispatcher.h** in your project.

```cpp
#pragma once
#include "event.h"

namespace fuse {
struct dispatcher {
    // posts an event with the type T
    template <typename T, typename... Args>
    FUSE_INLINE void post(Args&&... args) {
        FUSE_STATIC_ASSERT(std::is_base_of<event_instance,
            T>::value);
        _events[type_id<T>()] = new T(std::forward<Args>(args)...);
    }

    // registers a callback for the event of type T
    template <typename T>
    FUSE_INLINE void add_callback(callback_function<T>&& cbk) {
        FUSE_STATIC_ASSERT(std::is_base_of<event_instance,
            T>::value);
        auto entry = std::make_shared<event_callback<T>>(cbk);
        _callbacks[type_id<T>()].push_back(entry);
    }

    // handles all event and keep memory clean
    FUSE_INLINE void dispatch() {
        if (!_events.size()) { return; }
        for (auto& [code, entry] : _events) {
            for (auto& cbk : _callbacks[code]) {
                if (cbk->run(entry)) { break; }
            }
        }
        _events.clear();
    }

private:
    std::unordered_map<event_id, event_instance*> _events;
    std::unordered_map<event_id, callback_list> _callbacks;
};
};
```

The event dispatcher is just a structure with three primary functionalities.
