# # ECS Architecture

Even though the ECS design is well-known for its high performance and ease of use in terms of maintenance, memory, and CPU cache usage, it lacks a specific implementation approach. I usually divide the approach of implementing ECS into two categories: pure ECS and hybrid or mixed ECS.

In a pure ECS, the component has no logic. Only the system holds logic to update the components. The hybrid ECS allows components to have logic to update themselves.

We are going to build a pure ECS in this book.

![](bbox=[0.078, 0.3, 0.92, 0.56])

What makes a the ECS design different from the data-oriented design is the fact that the entity, the component, and the system are all separated. The entity is just a unique identifier (number) that stands for a specific game object in the scene. It is often a 32-bit or 64-bit unsigned integer. The component is simple structure that store all data require for the logic. The system targets all entities with a specific set of components (signature) and update their components.

# ## Advantage ECS:

+   - ECS is a user-friendly approach to multi-threading because each system can be assigned to a specific thread.
+   - shorter and less complicated code.
+   - Ease integration of scripting languages.
+   - Makes unit testing and mocking ease.
+   - New features can be easily implemented.

# ## Disadvantages ECS

+   - No standard implementation method defined.
