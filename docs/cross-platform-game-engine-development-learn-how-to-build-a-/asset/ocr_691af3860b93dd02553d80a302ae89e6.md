```
#pragma once

namespace fuse {
FUSE_INLINE const uint32_t get_unique_typeid() {
    static uint32_t type = 1u;
    return type++;
}

template <typename T>
FUSE_INLINE const uint32_t type_id() {
    static const uint32_t type = get_unique_typeid();
    return type;
}
}
```

In **typeid.h** above, we have the function **get_unique_typeid()** that returns an unsigned integer. Its definition is found in the **typeid.cpp** file. This function will simply increase a static variable every time it is called. You will also find a template function called **type_id()** in the header file.

A template function is not a type, function, or any other entity. A source file holding only template definitions yields no code. A template must be instantiated before any code can appear: the template arguments must be determined so that the compiler may build an actual function [4].

What will happen is that the compiler will generate a definition of this function for each template type used while calling it. Since the value returned by the function **get_unique_typeid()** is stored in a static constant integer, it will remain the same every time the function is called with the same template type.

You can test it like shown below:

```
auto i d1 = type_id<int>(); // i d1 = 1
auto i d2 = type_id<int>(); // i d2 = 1
auto i d3 = type_id<float>(); // i d3 = 2
```

Just like that, we have something in place to attach a unique id to any type in our program. We will also use this type-system as the foundation for our entity-component system (ECS). More about that later.
