
and then plays that sound using the SDL function "Mix_PlayChannel". This function takes the channel, the audio data, and the loop count, respectively to play the sound.

We want the background music to be played directly at the start of the game. So, we can simply add that in the pipe spawner script's start function. Add the following code to your pipe spawner.

```cpp
// ...
engine/src/scripts/pipe_spawner.h

// ...
FUSE_INLINE void d_on_start() {
  // play music on channel "1" infinite loop
  play_audio("music", 1, -1);
}

// ...
```

We are playing the sound asset called "music" on channel number "1" as long as the program is running. However, we want to be able to stop the background music when the player dies. To do so, simply call SDL_HaltChannel(channel) to stop that specific channel.

We can do that in the pipe spawner script or the player controller script. But because we played it in the spawner script, we will also stop there when the plane crashes.

### Plane Crash Sound Effect

We want to have a sound effect played when the plane crashes. We can do that in the "on_collision" function of the player controller script. Whenever a collision is triggered, we will simply play the sound.

```cpp
// ...
engine/src/scripts/player_controller.h

// ...
FUSE_INLINE void d_on_collision(ecs::entity e) {
  play_audio("boom");
  auto& sp = get_component<ecs::sprite_component>();
  sp.sprite = get_asset<texture_asset>("dead")->d;

```

We are not specifying a specific channel to play the sound because we want SDL to choose one for us. We also want it to be played only once at the default volume.

## Serialization

The previous chapter covered creating a small game with some of the features we have added to our engine so far. We need serialization in order to save the state of our game in such a manner that we can reload when necessary. The game we created is part of the engine's code, however, we want to separate the game's definition from the engine's code by storing all entity and object information in external files using a serializer.

### Definition

Serialization is the process of converting a data object into a formatted binary or text file that can be easily reloaded and used by a program. [27]

![](img/2763810ed0a1572c2bec59ee52dd75be_217_0.png)

The reverse process where the binary or text file is used to recreate the actual object in memory is called "Deserialization".

![](img/2763810ed0a1572c2bec59ee52dd75be_217_1.png)

We'll serialize the data from our game in a human-readable format. Binary serialization is significantly faster and generates small-size files compared to readable serialization. It is just the process of saving a block of memory (binary data) in a file. However, because our scene has a complex data structure that cannot be directly saved in binary form, we will create a custom serializer to do the job for us.

### What is YAML?

YAML is a human-friendly data serialization language [29], [19]. YAML originally stood for "Yet Another Markup Language", but since 2002 it has been replaced with the recursive acronym "YAML Ain't Markup Language". As a result, YAML is defined as an encoding language that isn't one.

Markup languages like XML, HTML are primarily used to store data in a human-readable format. YAML differs from XML in that it uses a simple approach. The main justification for YAML is its simplicity, which includes constraints that arise from XML's broad application spectrum. However, YAML's main competitor is JSON, rather than XML.

### How does YAML work?

YAML turns data from a program's internal format into a text file. Because this is possible even for complex data types like two- or multidimensional arrays, the elements are serialized and sent one after the other.

If we were to serialize the following data structure using YAML, the result will look like shown below.

```
struct transform_component {
    vec2f translate = vec2f( 0.0f );
    vec2f scale = vec2f( 1.0f );
    float rotation = 0.0f ;
};
```

Figure 46 Data Structure

```
transform_component:
    translate: [0, 0]
    scale: [1, 1]
    rotation: 0
```

Figure 47 YAML File

There are libraries available for almost all major programming languages like C/C++, Java, C#, Dart, Js, Rust, etc. that allow serialization with YAML.

- YAML Frameworks and Tools for C/C++:
  - libfyaml "C" YAML 1.2 processor (YTS) [7]
  - libyaml "C" Fast YAML 1.1 (YTS) [8]
  - libcyaml YAML de/serialization of C data (using libyaml) [6]
  - yaml-cpp C++ YAML 1.2 implementation [5]

Above is a list of some well-known libraries for C++ serialization using YAML. "yaml-cpp" is going to be our choice for this book. It is a YAML parser and emitter in C++ matching the YAML 1.2 specification. We are going to clone the yaml-cpp repository and compile it ourselves.
