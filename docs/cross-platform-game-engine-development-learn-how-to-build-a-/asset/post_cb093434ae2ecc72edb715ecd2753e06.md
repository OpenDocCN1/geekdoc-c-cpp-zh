
## Rigid Body

A rigid body is a solid object on which external force causes no deformations. The assumption that there is no deformation to the body simplifies the analysis by reducing the number of parameters required to perform a realistic simulation. The idea is to make our player, or any object affected by gravity for collision handling and more.

### Cinematics

Before we can create any component or system, we first need to understand how rigid bodies behave in an environment. We won't get too deep into this topic, but we will briefly talk about the necessary stuff. In the real world, rigid bodies are described using three dimensions (x, y, and z), but because the focus of this book is to deal with 2D-games, we won't use the third dimension in our simulations. The following table describes how rigid body's parameters are related to each other for linear uniform motions.

| Parameters | Equations |
| :--- | :--- |
| Acceleration [m/s²] | a = (F + Fr + Fg)/m |
| Velocity [m/s] | V = a * t + V0 |
| Position [m] | P = V * t + P0 |

Each parameter in the table above is a 2D-vector with (x, y) components.

### Acceleration (a)

In mechanics, acceleration is the rate of change of the velocity of an object with respect to time. Accelerations are vector quantities (in that they have magnitude and direction). The orientation of an object's acceleration is given by the orientation of the net force acting on that object. The magnitude of an object's acceleration, as described by Newton's Second Law, is the combined effect of two causes [21]:

- The net balance of all external forces acting onto that object — magnitude is directly proportional to this net resulting force.
- That object's mass, depending on the materials out of which it is made — magnitude is inversely proportional to the object's mass.

### Velocity (V)

The velocity of an object is the rate of change of its position with respect to a frame of reference and is a function of time. Velocity is equivalent to a specification of an object's speed and direction of motion (e.g., 60 km/h to the north). Velocity is a fundamental concept in kinematics, the branch of classical mechanics that describes the motion of bodies. [28]

### Friction (Fr)

Friction is a force that acts between two surfaces that meet. When forces are applied to make the two surfaces slide over each other, there will be an opposing frictional force acting along (parallel to) the surfaces. It is a force that opposes the sliding of the surfaces. The surfaces may slide (then we call the frictional force dynamic) or they may not (then we call the frictional force static). [15]

## Rigid Body Component

Now that we have a basic understanding of what rigid bodies are, we want to use that knowledge to implement our rigid body component. We will first create a rigid body instance and then use that instance to define our component.
Create a new directory in the folder tree of the engine called "physics" and add the file described below.

```
engine/src/physics/rigidbody2.h
#pragma once
#include "math/vec2.h"

namespace fuse {
struct rigidbody2 {
FUSE_INLINE void set_force(const vec2f &f) { force = f; }
FUSE_INLINE void set_force_x(float x) { force.x = x; }
FUSE_INLINE void set_force_y(float y) { force.y = y; }

float gravity_scale = 0.0f;
vec2f velocity;
vec2f force;
};
};
```

The gravity scale defines how an object is affected by gravity. We are assuming that all objects have a mass of 1 kg, and we will use the gravity scale to simulate the difference of mass.
We are not defining the acceleration here because we will simplify the equation from the table by directly embedding the equation of the acceleration in the velocity's equation.
We have implemented some functions that can be used to apply diverse types of forces to the rigid body.

```
engine/src/ecs/components/physics.h
#pragma once
#include "physics/rigidbody2.h"

namespace fuse::ecs {
struct rigidbody_component {
FUSE_INLINE rigidbody_component(const rigidbody_component &) = default ;
FUSE_INLINE rigidbody_component() = default ;
bool disabled = false;
rigidbody2 body;
};
};
```

We have created a header file called "physics.h" for a new category of components. Any component related to physics will be added to this header file.
The rigid body component is quite simple. It has an instance of a rigid body and a Boolean which tells if the rigid body physics should be simulated or not.

## Rigid Body System

The rigid body system code comes next. It works in a loop across all entities with a rigid body component.
Before we begin any physics simulation, we must ensure that the rigid body is not disabled.

```
engine/src/ecs/systems/rigidbody_system.h
#pragma once
#include "ecs/system.h"
namespace fuse::ecs {
struct rigid_body_system: system {
FUSE_INLINE void update(float dt) {
for (auto& e : view<rigid_body_component>()) {
auto& bd = e.get_component<rigid_body_component>();
if (bd.disabled) { continue; }

auto& tr = e.get_component<transform_component>();
vec2f f_g = vec2f(0.0f, bd.body.gravity_scale * 9.8f);
bd.body.velocity += (bd.body.force + f_g) * dt;
tr.translate += bd.body.velocity * dt;
}
}
};
}
```

As you can see, we simply check if the rigid body is enabled, and we then proceed to calculate its current position based on the force and gravity.

## Quick Test

As usual, let's test everything in the scene. Open your **scene.h** header file, and register the rigid body system in the constructor, and add an entity with a rigid body component, as shown in the code snippet below.

```
engine/src/ecs/scene.h

FUSE_INLINE void start() {
    // load sprite
    auto sp = _assets.load_texture("assets/obj1.png", "", _renderer);

    // add tilemap entity
    auto entity = add_entity("rigid body");
    entity.add_component<sprite_component>().sprite = sp->id;
    auto& rb = entity.add_component<rigid_body_component>();
    rb.body.gravity_scale = 1.0f;

    // start systems
    for (auto& sys : _systems) { sys->start(); }
}
```

If you run your code right now, nothing will happen because of the delta time. There is one thing I said earlier about making all motions and animations in our engine time-based. The reason nothing is happening is that the delta time so far has been zero. We will add a timer to compute the delta time for us but for now, we are going to apply a quick solution to test our rigid body system.

## Quick Fix

If you open your **application.cpp** you will see that the scene's update function is called with zero as delta time value. To quickly test the rigid body system, we can simply pass a constant delta time value like shown in the following code snippet.

```
engine/src/core/application.cpp

while (is_running) {
    inputs::dispatch_events();
    SDL_RenderClear(renderer);
    scene->update(0.016666666);
    SDL_RenderPresent(renderer);
}
```

The number 0.016666666 is the value of the delta time you would get if you had a game running at around sixty frames per second (60 FPS). If you compile your code and run, you will see your game object falling due to gravity. You can play around with the gravity scale to see how it affects the simulation of the rigid body.
