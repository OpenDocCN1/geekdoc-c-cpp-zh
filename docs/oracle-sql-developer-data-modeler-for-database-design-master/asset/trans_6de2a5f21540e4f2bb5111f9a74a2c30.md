## 与其他用户共享域

Data Modeler 使用的唯一域文件是 `default.xml`，位于您在“默认系统目录”（Default System Directory）首选项中设置的目录。向其他用户共享新域有两种可能：您可以修改默认文件并与其它用户共享，或者您可以修改一个单独的文件并将其与所有导入到其本地默认文件的用户共享。为您的组织的标准域集准备一个单独的文件是有用的，这可以确保每个人都使用同一文件的最新版本。该解决方案还允许用户定义不会与其他用户共享的自定义域。

如果您决定使用默认域文件并共享它，可以将该文件复制到所有计算机的“默认系统类型目录”（Default System Types Directory）指定的目录中，这样所有用户都可以在他们的设计中使用这些域。

如果您决定为公司特定的域准备一个单独的文件，您可以将其与用户共享，但在使用新域之前，您必须先将设置导入到本地默认文件中。可以通过“文件”（File）菜单中的“导入”（Import）功能进行导入：选择文件 | 导入 | 域（Import | Domains）。选择“打开域文件”（Open Domain File），并选择想要的文件。勾选“导入到默认域”（Import In Default Domains）框并点击“导入”（Import）。如果您没有勾选“导入到默认域”框，您将不会

## 性能调优

Data Modeler 是一个 Java ，需要 Java 开发包（JDK）。Data Modeler 包含多个目录和 XML 文件，必须在内存中。如果设计很大，内存可能会耗尽，运行 Data Modeler 会变得太慢。您可能会收到警告消息（低内存）提示您内存不足。如果您有一个良好的设置，可以进行此查看内存使用情况，使用 JavaVM。如果您安装了 Oracle Developer，您将在 /bin 目录下找到 jvm.exe。在图 2-1 中，您可以看到 JavaVM 分配的内存。已使用了多少。如果您想更改 4.0 之前的设置，要更改的文件是 /datodeler/datodeler.conf 或 /datodeler/datodeler64.conf，但从 4.0 开始，它是每个用户的配置设置，要编辑的文件是 C:\Users\username\AppData\Roaming\Oracle SQL Data Modeler\buildno\product.conf。buildno 是您的版本号的一部分。您仍然可以使用 buildno.conf 文件，但在此设置生效之前。检查内存设置时，查找 AddVMOption -Xmx。它通常有一个值为 800M；您可能想将其更改，例如改为 1250M 甚至可能是 3GB 或 4GB。但请注意，如果将设置得太大，Data Modeler 可能无法启动。在这种情况下，请减小值。您可以通过绿色按钮在规则集对话框中创建规则集，可以通过红色按钮删除现有的规则。您可以在规则集选项卡上点击带有铅笔图标的规则添加规则，如图 2-20 所示。![](img/431f8ac8f273fa89a28377c50ed60d7_62_0.png)

## 共享规则

Data Modeler 的共享规则对所有用户都是相同的。如果您决定创建自己的库和规则，您必须共享它们。共享是通过导出/导入功能完成的。导出的默认文件夹在“首选项”（Preferences）中设置，导入在“首选项”（Preferences）中设置。同样，自定义规则可以导出和导入。
