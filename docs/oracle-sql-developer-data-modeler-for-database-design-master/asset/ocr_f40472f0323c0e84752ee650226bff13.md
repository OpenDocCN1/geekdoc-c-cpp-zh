If A and B in fact have different values at some given time, we might certainly say, informally, that there's an inconsistency in the data stored at that time. But that “inconsistency” is an inconsistency as far as the system is concerned only if the system has been told that A and B are supposed to be equal—i.e., only if “A = B” has been stated as a formal constraint. If it and column, then (a) the fact that A ≠ B at some time doesn't in itself constitute a consistency violation as far as the system is concerned, and (b) importantly, the system will never rely on an assumption that A and B are equal.

+   Us, if we want for A and B to be equal “eventually”—i.e., if we're content for that requirement to be handled in the application layer—all we have to do as far as the database system is concerned is omit any declaration of “A = B” as a formal constraint. No problem, and in no violation of the relational model.
