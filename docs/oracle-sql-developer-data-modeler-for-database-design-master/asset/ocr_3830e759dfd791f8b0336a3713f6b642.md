If you select Use Object Types, you can specify the name of the object type (Object Type Name) and the name of the table (Table Name). If you select Use Model Clause property, the default statement will be included in the SQL statement, and if you select RowToCell default statement will be included in the SQL statement.

After clicking the SQL Statements, you will be able to view and change the order of attributes (Attributes Order) and to view and edit the SQL statement that reflects the current settings (SQL Statements). By selecting Show Formatted Limit Map, you may define the dimension information can be divided over several lines. On the Dimensions and Attributes tab, you can view, edit, add, and remove dimensions associated with the object. For each dimension, you can specify predefined attributes and hierarchies. On the Measures tab you can view, edit, add, and remove measures. You can also specify comments, notes, and a description for a slice, for example, the name of sales (SalesAmount) or the quantity of sales (SalesQty)

For a cube, you can also specify a description, notes, and a description for the partitioning (Partitioning Description).

Then you create levels. Usually a data is summarized by a level. For instance, you might also want to be summarized by weekly, monthly, and yearly levels (levels). On the General tab for Level Properties, define the level name (Name) and the entity associated with this level (Level Entity). If you enable Value Base Hierarchy, that means you have defined the hierarchy as value-based; otherwise, it will be level based. Level is more common and the default in Data Modeler. The difference is in a value-based hierarchy, the parent-child relationships do not have named levels (like they do when using a level-based hierarchy). If you have selected the value-based hierarchy, you should also define the Root Identification (ParentBlankSelfOrMissing,ParentSelf,ParentMissing,ParentHasValue) and Identification Value settings. In both cases, you can also select a default from a list needed.

On the Selection Criteria tab, you can specify the criteria for this level. On the Level tab, you can write a description for it. On the Key tab, you can view all the attributes that are keys for the level. You can add and remove attributes to/from the key list, and you can edit some of the attribute properties. On the Descriptive Attributes tab, you can see, add, and remove descriptive attributes. For a new descriptive attribute, you define the name (Name) and select from the list (Attribute). You also define whether it will be indexed (Indexed) and whether it is a slowly changing attribute (Slow Changing, NONE, 1, 2, 3). If the level has been defined as a value-based hierarchy, you can see the list of attributes of the parent entity of the Parent Key tab to be selected as a parent key. On the Calculated Attributes tab, you can define calculated attributes and their expressions.
