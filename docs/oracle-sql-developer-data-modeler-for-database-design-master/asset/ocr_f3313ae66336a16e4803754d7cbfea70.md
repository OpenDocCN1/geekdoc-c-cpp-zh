There are three ways to implement the inheritance in a relational model: specialization (table) for each entity), generalization (single table), or neither of those (table child). There is no right way to model an inheritance; it always depends on what the requirements are.

Specialization of an entity that will be divided into subtypes. For instance, an entity Customer may be divided into Person and Customer. All common attributes will be in the Customer entity. Person and Customer will have only the specific attributes for those entities. This is similar to what you saw in the arc solution in Figure 4-16. In Data Modeler this is called Table For Each, (see Figure 4-20) to Table For Entity, and you can select it by setting the Subtype Generation option in the Entity Properties dialog (see Table For Each Entity). When Table For Entity is selected, all entities in the current subtype will be selected for engineering.

There are several questions you should ask to be sure that the solution is the right one. Can a Person be a company? Usually this is not a good solution in the sense of performance because probably need to join these tables quite often.

Generalization of an entity that will be created for a set of entities. It is possible that a subtype has attributes that are not suitable for all entities generalized under this supertype. Let you have entities called Customer, Company, and Person. You can generalize all of these under a supertype called Customer. This supertype now generalizes the subtypes. The subtype inherits the attributes from the supertype and possibly has attributes of its own. In Data Modeler, this is called Single Table, and you can select it by setting the Subtype Generation option in the Entity Settings dialog to Single Table. In Data Modeler, the Engineer To for this property will be set, and it will be cleared for all subtypes in the current subtype.
