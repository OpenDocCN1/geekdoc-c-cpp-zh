There are many situations when you need to compare two designs with each other or the design with the database. You can compare two designs by choosing File | Import | Data Modeler Design or by choosing Tools | Compare/Merge Models. The main difference between these two methods is that in Compare/Merge Models you can compare only the relational and physical models, whereas via Import | Data Model Design you can compare everything in a design. On the other hand, by Compare/Merge Models you can also preview and influence the DDLs that will be generated. A design and a database can be compared with Synchronize Model With Data Dictionary or Synchronize Data Dictionary With Model, and the actual comparison will be done in the Compare Models dialog. A comparison to a design can also be based on DDLs or data dictionary. This comparison also takes place in the Compare Models dialog.

In all comparisons, you always have a target and a source, and the possible changes are always performed on the target. The source is shown on the left, and the target is shown on the right in the comparison screens. A target in design is the one that is open in Data Modeler when the comparison starts. In synchronization, Synchronize Model With Data Dictionary the target is the model, and in Synchronize Data Dictionary With Model it is the database. The best part of comparisons and synchronizations is that you can select any differences you want from source and implement them in the target telling you what you want to be

# Setting Preferences and Properties

There are some preferences that will affect the comparisons—not what objects will be compared but what features will be compared. You can find them in the Preferences by selecting Data Modeler | DDL | DDL/Comparison. The DDL Comparison Options section includes the preferences for adjusting the comparisons.

+   A Data Type Kind comparison is always done, but if you select the ‘Data Type Kind’ In Compare Functionality preference, the difference will be enabled for merging automatically. Data Type Kind means that if a column on one side of the comparison is VARCHAR (10 CHAR) and the other side is defined as VARCHAR, or been defined as Logical Type (VARCHAR) and on the other side as Domain (FirstName), even though both are of the same data type and length (VARCHAR(30)), they differ from each other in Data Type Kind.
