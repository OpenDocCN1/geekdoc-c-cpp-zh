+   - The Generate Short Form Of NOT NULL Constraint preference defines whether the NOT NULL constraint name is used in the CREATE TABLE statement for column definitions.

+   - By Selecting Quoted Identifiers, you define that object names will be enclosed in double quotes in the generated DDL statements (for example, "CUSTOMER" instead of CUSTOMER).

+   - If you select Generate Comments In RDBMS, the text in the field Comment In RDBMS will be included in the generated DDL statements. Remember that if you have changed the Comment In RDBMS field in the physical model, the link between the comments has been cut, and the text written in the relational model will be used if the physical model is not open. If it is open, the Comment In RDBMS text in the physical model is used. The same logic applies to other properties that can be changed in both the relational and physical models.

+   - If you Generate Inline Column Check Constraints, the Column Constraint clause will be included in the CREATE TABLE statement. If this is not selected, a ALTER TABLE statement for the constraint definition will be created.

+   - If the Generate Valid Value Constraints is selected, the List Of Values and Range Values constraints are included in the generated DDL; if it is not selected, the generated DDL will be without the List Of Values and Range Values constraints. This is useful if you want to define the constraints in your model but not actually to implement them in the database.

+   - The Include Default Settings In DDL preference will add all possible DDL keywords for the object created in the generated DDL statements. This option is useful if you want to use the syntax for an object DDL.

+   - Include Logging In DDL, Include Schema in DDL, Include Tablespace in DDL, Include Redaction in DDL, and Include Sensitive Data Protection in DDL define whether the mentioned parameter is included in the generated DDL. If a schema is not included in the DDL, the object will be created for the schema of the username that has been used to log in to the database for running the DDL. If the tablespace is not included in DDL, in Oracle the default tablespace of the username who logged in is used. If the storage is not included, in Oracle the storage setting of the tablespace where the object is saved is used.
