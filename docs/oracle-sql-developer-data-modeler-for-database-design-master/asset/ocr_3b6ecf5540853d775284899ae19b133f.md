The Data Modeler works sometimes cause conflicts when merging designs. As mentioned earlier, Data Modeler has directories for each element type (table, entity, view, and so on), but the directory is created only when the first of kind element is created, and therefore a conflict may arise. For example, let's assume there is the trunk and branch, and in both a new element type has been created for the first time let's say it's a view. So, somebody creates a view for the branch, and somebody else creates another view for the trunk. Now the directory for views has been created in both versions for the first time. You try to merge the designs and get an error saying there is a conflict. That is correct; there is a conflict: A directory for views has been created in both versions, and you must decide which one is the correct. What you need to do now is to remove the directory from the local target design by right-clicking in Action screen below the Revision screen in Merge Design and deleting Local Folder. If there are outgoing changes, commit them and update the working copy. Now there should be no more conflict, and the merge can be completed. Everything is OK you get back what was in the local directory you deleted. You can do this by choosing Team | Design Version History. Select and then restore the view file that was in the removed directory. After that you should have a complete merge to the trunk.

Every-element-type directory includes a subdirectory called seg_0, and if there are more than 70 elements of the same type, a new subdirectory of the same level is created (seg_1). Other directory can have only 70 files. This is for performance reasons. Data Modeler creates the new subdirectory when needed and removes it when a Save As is performed if there is no need for that subdirectory anymore.
