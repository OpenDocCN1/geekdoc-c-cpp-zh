# 10 Oracle SQL Developer Data Modeler for Database Design Mastery

StudentRecord(the one from Student and the one from Course) have the attribute FacultyID in it. This situation is fine if a Student can take Courses from other Faculties than the one signed up for; this means those two FacultyIDs can be different. If a Student take Courses only from their own Faculty, it might be confusing to bring the FacultyID from different routes. You can see the same thing in the Entity Properties dialog on the Overlapping Attributes tab, shown in Figure 5-3.

On this path you can specify that the attribute will be folded (not engineered as a column) by selecting the box without a heading (highlighted in Figure 5-3). The attribute with the actual attribute name (FacultyID) will be engineered, but the attribute with a name that contains a version number (FacultyID1) will be folded. You can define this with the creation order of relationships. Later in this chapter you will see how folding affects the process of engineering to the relational model.

Chapter 4 discussed the concept of inheritance. Before starting the transformation, check that your settings are correct for the transformation you want for the inheritance. In the next section, you will see, for instance, how the inheritance will be transformed in Data Modeler.
