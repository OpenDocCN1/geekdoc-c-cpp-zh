# Sharing Preferences with Other Users

You can share your Data Modeler preferences with other users using the Export/ Import buttons at the bottom of the Preferences dialog when Data Modeler is selected. To export the preferences, click the Export button. You will be asked for the name and the location to save the XML file, and it will be saved accordingly. This XML file can be imported to another computer with the Import button. You need to define the settings only once, and then you can import them to other computers in your organization. Make sure to export/import the new preferences

to all users every time you change the official preferences in your working environment.

# Introducing Design Properties

In addition to properties that help set up your Data Modeler working environment, there are also properties that affect only the particular design you set for. This is a new behavior starting with Data Modeler version 4.0. Since version 4.0.3, either double-click the design name in the Browser pane or right-click and select Properties to open the Design Properties dialog. You can select the Global Design Level Options under Settings. If you Use Global Design Settings, the properties are modified automatically by global design-level settings from the datamodel\datamodel\types\dl_settings.xml. Also, when some of the properties are changed in a design that has Global Design Level Settings, the changes are saved both to the local file and to the global file.

As mentioned, you can find the design-level properties either double-clicking the design name in the Browser pane or right-click and select Properties.

## Naming Standards

Naming standards making work easier and improve the quality of your designs. For instance, you can decide how names in logical models will be separated. In logical model, you can select either space (camelCase) or a character. For example, if you select a space, the customer name would be Customer Name. If you select title case, the customer name would be CustomerName. If you select underscore(_), the customer name would be Customer_name. In a relational model, you can also select Abbreviated Only, which means that abbreviated words are used. The naming standards can be verified against the selected glossary. You can find more information about glossaries in the “Introducing Glossaries” section. You can add, modify, and remove naming standards for attributes, columns, domains, entities, and tables, and these standards will be checked when you apply design rules.

## Implementing naming standards using templates

In my opinion, the most valuable tab under Naming Standard in the Design Properties dialog is Templates, as shown in Figure 2-10. On the Templates tab you can define how different elements as primary keys, foreign keys, constraints, and indexes will be named. You can specify the format string for naming, and Templates can include variable and fixed parts of the name. Templates are used when generating elements automatically.
