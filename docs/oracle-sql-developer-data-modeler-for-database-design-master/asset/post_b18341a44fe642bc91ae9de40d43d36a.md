## Discovering Foreign Keys

If you not have foreign keys in the database, you will not have them in your model either. What is the value of a data model without relationships? You will have plenty of tables, and you will have plenty of entities, but they do not have anything to do with other.

In Data Modeler you can ask the tool to try to find the foreign keys for you. The discovering is based on the name and data type matching between columns. You specify foreign key column names to be used in the process. Go to the Browser pane and select the relational model. Right-click and select Discover Foreign Keys; the Create Discover Foreign Keys screen opens. In the dialog you will see a list of primary keys that can be used in foreign keys. You can select and unselect them. In the list you can select the referred table, the referred key, and the column. With Column referred table, referred key, and in Filter, you can type a string to restrict the list. You can, for example, restrict the list to only table names with LINK. If Single Use OF FK column selected, a foreign key column can be bound to only one foreign key. You can define the naming policy for selecting the foreign key candidates by selecting the FK key name policy. The possible values are Referred Column, FK Column Template, Referred And Template, or Template Referred And Referred.

- If you select Referred Column, Data Modeler will look for a foreign key that has the same name as the referred column.
- If you select FK Column Template, Data Modeler is looking for columns with the name generated using the foreign key template.
- If you select Referred And Template, Data Modeler first applies the Referred Column policy and then the FK Column Template policy.
- If you select Template And Referred, Data Modeler first the FK Column Template policy and then the Referred Column policy.
