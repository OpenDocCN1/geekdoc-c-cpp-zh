## Sharing Domains with Other Users

The only domain file Data Modeler uses is default.xml located in the directory you set in the Default System Directory preference. There are two possibilities for sharing new domains to other users: You can make changes to the default file and share with other users, or you can make changes to a separate file and share that with all users imported into their local default file. It is useful to have a separate file for your organization's standard set of domains to ensure everyone is using the latest version of the same file. That solution also allows users to define their own domains that will not be shared with other users.

If you decide to use the default domain file and share that, you can copy the file to all computers to the directory specified in Default System Types Directory, and all the users will have the domains available to be used in their designs.

If you decide to have a separate file for company-specific domains, you can share that with users, but you must first import the settings to the local default file before the new domains can be used. Importing can be done with the Import functionality found in the File menu: Choose File | Import | Domains. Select Open Domain File, and select the file wanted. ## Introducing Design Rules

As mentioned, design rules are an easy way of having standardized testing for your database design. The testing is automatic, but you must start it manually whenever you think it is needed. There are preset design rules in the tool, and you can also create your own rules and sets of rules. Choose Tools | Design Rules and Transformations | Design Rules to open the Design Rules dialog.

## Performance Tuning

Data Modeler is a Java application that requires the Java Development Kit (JDK). Data Modeler consists of several directories and XML files that must be held in memory. If a design is large, the memory might run out, and working with Data Modeler gets too slow. You can get a warning message (Low Memory Warning) saying you not have enough memory. If you have a good setting, you can do it to see how the memory is used, with a called JavaVM. If you have Oracle Developer installed, you will find it named jvm.exe in the /bin directory. In Figure 2-1, you can see the memory allocated in JavaVM and how much of it has been used. If you want to change the settings in versions before 4.0, the file to change is /datodeler/datodeler.conf or /datodeler/datodeler64.conf, but since 4.0, it is a configuration setting for each user, and the file to edit is C:\Users\username\AppData\Roaming\Oracle SQL Data Modeler\buildno\product.conf. The buildno is the part of the number of your version of Data Modeler. You can still use the buildno.conf file, but before this setting takes effect. Remember, when editing this file, Data Modeler must be closed. When checking the memory setting, look for AddVMOption -Xmx. It usually has a value of 800M; you might want to change that, for instance, to 1250M or maybe even to 3GB or 4GB. But be careful if you change the setting to be too large, it is possible that Data Modeler will not start. In that case, make the value smaller.

TIP Using subviews might help you. Opening a diagram with 5,000 objects is definitely slower than opening a subview with 50 objects. Besides, if the diagram is too large, it is difficult to read it.
