## Making Changes to a Design
You Have Worked with Before

To start with a design, open it from its working directory as usual (choose File | Open). How do you know if there are any changes that other users may have made to the design? Go to the Incoming Changes in Pending Changes (earlier in Figure 9-2) and select Refresh Incoming Changes. You can see exactly what has been changed compared to your local copy by right-clicking the element in Pending Changes and selecting either Compare (Figure 9-3) or Compare As Text (Figure 9-4). Then select Update Working Copy by clicking the icon on the Refresh icon. Now you will have the latest version of the design in your local working directory.

If you made changes before and forgot to commit them in Subversion, you will see them on the Outgoing Changes tab in Pending Changes. Commit them. If there is a conflict in design versions, you must solve it. To avoid conflicts, always commit to Subversion before leaving the tool.

### Checking Out a Design from Subversion

If you want to work with a design that someone else has updated, you must first update your local copy. To do this, go to the Incoming Changes in Pending Changes and select Refresh Incoming Changes. If there are new changes, select the Update Working Copy icon. This will bring the latest version into your local working directory. If there are conflicts, you will be prompted to resolve them. 

If you have made changes that you have not yet committed to Subversion, they will be listed in the Outgoing Changes tab. You can commit these changes to share your work with others. If you have added new files to your working directory, they will appear in the Unversioned Files tab. You can add these files to Subversion by clicking the green plus sign.

## Solving Conflicts

A conflict (Figure 9-5) means you have made changes to a version that has been changed by someone else. This usually happens if one of the users does not commit immediately after making changes but then does it later. So, you do not see the other person's changes in your Incoming Changes and therefore cannot update them to your copy. When you both finally commit to Subversion, that situation is called a conflict and must be solved by the person who committed last. Conflicts are shown in red in Pending Changes. Solving a conflict must be done manually; it cannot be done automatically. In real life, you cannot have a pattern solution for every conflict.
