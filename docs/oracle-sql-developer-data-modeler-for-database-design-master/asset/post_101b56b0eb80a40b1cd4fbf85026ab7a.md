
# Name Abbreviations and Prefix Management

You can use name abbreviations and prefix management to quickly change the naming of objects to meet your needs.

## Name Abbreviation

You can use the Name Abbreviations utility for bulk changing names or abbreviations. You can use it for changing all similar words to the same one; for instance, you could change both C and CUST to CUSTOM. Or you can use it to add abbreviations to tables and columns. The change is based on a comma-separated value (CSV) file. In the file there are pairs of words, and those words are separated by a comma or another separator defined when performing the change. The first word is the name, and the second word is the abbreviation.

Name dialog. If you select Name Abbreviation for Direction, the first word will be replaced with the second word. But if you select Abbreviation To Name, the second word in the list will be replaced with the first one. In other words, the Direction setting tells how the list will be read.

You can perform name abbreviation for names or for abbreviations by selecting All Objects or Abbreviations for Scope setting. A name abbreviation for names can be done to tables, views, foreign key constraints, primary and unique key constraints, columns, and indexes.

Start name abbreviation by selecting the CSV file; click the Browse button in Name Abbreviations dialog and find the correct file. For separator, you can define a comma or any other separator. If you select a separator that does not exist in the file, you will get an error. After you select the file, you select the scope and direction for transformation. If you want to keep the original case when changing part of the name, select Keep Case. If you want to use the case defined in the CSV file, disable this property. For instance, if you have a column containing customer_name, and you disable Keep Case, the column name will be changed to CUST_NAME. When the property is selected, the column name will be changed to CUSTNAME.

If you perform name abbreviations in both directions with the same file and settings, names should be the same as they started. In this case, name combinations must be unique.

In data model, you can find two example files for name abbreviations: ABREV.csv and plurals.csv. plurals.csv file is an example of use of this utility. If you decide in the middle of the project that table names should actually be plurals instead of singular, you can use this utility to change the naming easily.

## Prefix Management

Prefix management is also quite useful when designing a database. Prefixes can be used to separate and categorize kinds of objects for purposes when you do not want to use different schemas. You might want to use prefix management for objects that have different life cycles, for instance history tables (HIST_) or summary tables (MONTH_DAY). You might want to use prefix management to categorize them based on the application or part of the application, for instance CUST_ for all customer information, tables, and so on. Oracle data dictionary views are an example of this: USER_ALL_, and DBA_. Or you might want to use prefixes to describe the usage of the object, such as TEMP_ for temporary objects or IDX_ for tablespaces that have only indexes in them.

The prefix can for DDL generation. You can add the prefix to the object name manually when creating the object or changing its properties. For example, instead of naming ADDRESS, you can use CUST_ADDRESS. You can also do it automatically using the Data Modeler utility. You can do it for tables, views, foreign key constraints, primary and unique key constraints, and indices that are in a relational model or in a specific subview. In the Browser pane, go to the relational model, right-click, and choose Change Object Names Prefix. You might have your objects divided into subviews exactly based on the criteria you are using for prefix naming. In that case, select the subview from the Browser pane, right-click, and choose Change Object Names Prefix. Or you might have the classification type attached to the object, which allows you to change the prefix for all of that classification type, as described in Chapter 8. Depending on your needs, any of these can be used, and they all lead to the Change Object Names Prefix dialog, as shown in Figure 5-30.

In the Change Object Names Prefix dialog, you can select Prefix Replacement or Add Classification Prefix. Add Classification Prefix is explained in Chapter 8. Now you will see what you can do with Prefix Replacement. If you select Prefix Replacement, you can replace an existing prefix or add a new one. If you want to replace an existing prefix, just set the current prefix to Current Prefix and the new prefix to New Prefix. You can spell the prefix either with the _ or sign without it; it makes no difference if you already have a prefix with an underscore (_). For example, CUST and CUST_ are the same. It makes no difference whether the current prefix has been added manually or by using the Data Modeler Object Names Prefix utility. Then select whether you want the search for current prefixes to be sensitive by selecting Case Sensitive. If this is selected and you have typed CUST for Current Prefix, objects with a prefix of “cust” are not selected. Select the object you want to select in the Apply To section of the dialog. The Change Object Names Prefix operation will affect the object set that is in the relational model/subview and the object types specified here. Then click Apply.

If you want to add a prefix for the objects, select New Prefix and type the prefix in the New Prefix field; remember to also type the _ at the end of it. If you already had a prefix in the object name, this will be added in front of it, so make sure to use the replace functionality if you want to replace the existing prefix and use only the Add Prefix functionality if you want to add a new one.

You can also change the prefix when generating the DDLs. Choose File | Export as explained in Chapter 7. If you have several designs open, select the one you want to generate the DDLs for select the relational model you want to use for DDL generation. Select the RDBMS site wanted, and if you want a view from the selected relational model, select that. Click Generate. Select Name Substitution in the DDL Generation Options dialog. Type the prefix you want to replace in the Old field and the prefix you want to use in the New field. For example, CUST_ in Old and TEST_ in New. Then select Selected Name substitution to be included in the DDL generation process. Select the Object Types tab and enable the object types you want to be included in the change. For example, select Table to perform the change only on table prefixes. Then select Apply Name Substitution on the bottom of the screen. If you do not select this, no substitution is performed. Here is an example of a DDL script generated for the table CUST_CUSTOMER using the name substitution:

```
PROMPT CREATING TABLE 'CUST_CUSTOMER';
CREATE TABLE "TEST_CUSTOMER"
(\ "Cust No" NUMBER (16) NOT NULL,
 "CustName" VARCHAR2 (30) NOT NULL
 )
```
