# 160 Oracle SQL Data Modeleler for Database Design Mastery

There are different kinds of indexes. The most common is a B-tree index (B-tree, B+-tree, B*-tree); for spatial data there is the R-tree index (R-tree, R+-tree, R*-tree), and there are the following: bitmap index, context index, multilevel index, hash index, function-based index, bitmap join, reverse index, and so on. A primary key has a special index called a primary index, and a table can have only one of them. Many indexes for foreign keys are created to support the joins and to avoid locking problems. To be able to decide about other possible indexes, you should research the most common queries and their frequency. If the query retrieves a small part of the data, an index might be not useful because a full scan will be more efficient.

When defining the index, it is vital to set the index columns in the right order, with the most selective ones in front. Also, the columns used in "equals" to evaluations would be set in front of the index and the ones used in range evaluation at the end. When using an index in performing a query, usually the biggest cost comes if you need to go to the table to get something. For this reason, sometimes in the WHERE, JOIN, ORDER BY, or SELECT part of a query are added to the index to avoid the need to access the table. Make sure you not have too many indexes in a table and that they are not too similar. Remember that updating a column in an index costs two to three times than a column not in index. Be careful when selecting columns for the index, make sure they are in right order, and you can also use temporary indexes in some cases.

For instance, WHERE ProductID=123 would not perform well since ProductID is numeric and it is compared to a character set.
