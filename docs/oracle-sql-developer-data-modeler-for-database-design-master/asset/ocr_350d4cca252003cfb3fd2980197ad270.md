If you want to revoke privileges, select the privilege or object you want to revoke from the list and right-click the arrow pointing left. If you have many privileges in the Objects box, you can filter them by object type by selecting the type from the Filter By list.

> NOTE
You can see the privileges granted to a object only if you select the name in the Objects box.

If needed, you can define quotas for users. A quota that a user can use only a certain amount of a defined tablespace. This is a way to ensure that a single user will not use all the space in a tablespace. This might be useful, for instance, in a test environment to make sure every user has equal resources. Right-click, and choose New. In the Qualitem dialog, go to Quotas under the username in the Browser pane, define the tablespace (select from the list of tablespaces) and the amount (Size). This space is not allocated to the database, but it is watched by the RDBMS, and if the user tries to use more space than this, the user will get an error. You can also document the quota on the Comments tab.

A role is a set of privileges that can be granted to a user or to another role, and when you grant it, you actually grant all the privileges the role has. You can use roles to easily administer database privileges. You could, for instance, have a role called SystemAdminUser that has Select privileges on selected tables, a SystemInsertRole SystemAsuperRole that has Delete privileges. You also have similar roles for SystemB: SystemReportUser, SystemBMainUser, and SystemBSuperUser. Maybe you have a user named Mark who needs to see all the reports in both systems (these are in the same database; you can grant him two roles: SystemReportUser and SystemBReportUser). If there is a new role in SystemA, you do not need to worry about Mark's privileges since the new role will be granted to SystemReportUser and Mark gets it automatically. And maybe you have two superusers, Lisa and Tom, who can do almost anything in the system (delete rows) but only in SystemA and not in SystemB, where they are not allowed to see any data. You can grant Lisa and Tom the role SystemASuperUser
