# Sharing Design Rules

The design rules with Data Modeler are the same for all users. If you decide to create your own libraries and design rules, you must share them with other users to let them use them. The sharing is done with export/import functionality. The default folder for exporting is set in Default Save Directory in Preferences, and for importing it is set in Default Import in Preferences. You can share libraries by clicking Export in the Custom Libraries dialog and saving the XML file. After that, select Import on the other user's computer and select the exported file to be imported. Likewise, custom design rules can be exported and imported the same way in the Custom Design Rules dialog.

# Performance Tuning

Data Modeler is a Java application that requires the Java Development Kit (JDK). Data Modeler consists of several directories and XML files that must be held in memory. If a design is large, the memory might run out, and working with Data Modeler gets too slow. You can get a warning message (Low Memory Warning) saying you do not have enough memory. If you have a good setting, you can do it to see how the memory is used and what would be a good setting, with a called Java VisualVM. If you have Oracle SQL Developer installed, you will find it named jsvm.exe in the /bin directory. In Figure 2-1, you can see the memory allocated in Java VisualVM and how much of it has been used. If you want to change the settings in versions before 4.0, the file to change is /datodeler/datodeler/datodeler.conf or /datodeler/datodeler/datodeler64.conf, but since 4.0, it is a configuration setting for each user, and the file to edit is C:\Users\username\AppData\Roaming\Oracle SQL Data Modeler\buildno\product.conf. The buildno is the part of the number of your version of Data Modeler. You can still use the buildno.conf file, but before this setting takes effect. Remember, when editing this file, Data Modeler must be closed. When checking the memory setting, look for AddVMOption -Xmx. It usually has a value of 800M; you might want to change that, for instance, to 1250M or maybe even to 3GB or 4GB. But be careful if you change the setting to be too large, it is possible that Data Modeler will not start. In that case, make the value smaller.

> TIP

Using subviews might help you. Opening a diagram with 5,000 objects is definitely slower than opening a subview with 50 objects. Besides, if the diagram is too large, it is difficult to read it.
