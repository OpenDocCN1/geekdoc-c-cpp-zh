# 124 Oracle SQL Developer Modeler for Database Design Mastery

TIP
To see the DDL for a table or a view, right-click the object on the canvas and select DDL Preview. When the previewer is open, you can select another object in the relational model, and the previewer is updated accordingly.

In the table properties there are also a list of columns and their properties. There are three tabs: Details, Overview, Security. By double-clicking (or clicking the Property icon), you can see more column properties. On the Security tab, you can find a list of columns and their security properties (you can find the same properties from the attribute Properties Security). It is possible to define a sensitive type for an attribute, as mentioned in Chapter 4, but there are many options than personally identifiable information (PII) or sensitive information, and masking type (FULL, NO, PARTIAL, RANDOM, REGEXP). If you select PARTIAL or REGEXP, you can also select Mask Template (Chapter 4 for creating a mask template). A mask template must be of same data type as the column it is attached to. If you mark a as Sensitive Info, the name of the column will be shown in red on any diagram. If you know you will create an Oracle database (Enterprise Edition 11.2.0.4 or newer version, licensed with the Advanced Security option), you might also want to define a redaction policy for your table. The redaction policy can be defined in the table properties under Redaction Policy. You can define the name for the policy, define whether the policy is enabled and take into account when generating DDLs (Generate In DDL), and whether the real data will be presented empty, or by showing all data not defined to be masked to the users. Each redaction policy is for only one table columns belonging to that table. So, after defining the redaction policy, you go to the column properties and define the Contains PII, Sensitive Info, Masking Type, and Mask Template for the properties you want to be marked and maybe even masked. These security features were introduced in Data Modeler version 4.0.

If a column is based on a structured type, for instance PersonName(FirstName, LastName), you can see that the Nested Columns tab. Each name (.FirstName, Name.LastName), data type, and information about whether that column is a primary key (PK), foreign key (FK), or mandatory field (M) is shown, and you can go and see other properties either by clicking the Properties button (pencil icon) or double-clicking the column name.

If you decided to split your structured type into regular attributes and columns, you might want to use the Column Groups properties to keep those columns
