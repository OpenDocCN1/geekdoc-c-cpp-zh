After you have selected the connection, select the schema or schemes wanted for the reverse engineering (see Figure 10-4). You can set the options under Import To the objects will be imported to an existing relational model (Relational_1) or if a new relational model will be created for them (New Relational Model); in the next list, you can select from existing RDBMS sites of the ones that matches the database version of the archive. For instance, if you have defined several RDBMS sites for Oracle 11g, this list will show all. If you click Options, you can leave some objects out from importing (see Figure 10-5). For example, if you have a large set of partitions, you need not to import them if you don't want. In Compare Maps, you can see the comparing maps, covered in Chapter 12. When you click Next, you can select the object to be imported to Data Modeler (see Figure 10-6). You can select the objects by type, and you can use filter to narrow down the list of objects. After selecting the objects, click Next. In the summary (shown in Figure 10-7), you can see the summary of the import.
- If it is not what you wanted, click Cancel, and no import is performed. If you are happy with it, click Finish. If you click Finish, you will also see the final log (shown in Figure 10-8). You will now have a relational model and a physical model in Data Modeler.
