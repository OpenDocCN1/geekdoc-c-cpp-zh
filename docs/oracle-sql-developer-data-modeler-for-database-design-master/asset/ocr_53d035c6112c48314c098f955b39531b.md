# 258 Oracle SQL Data Modeler for Database Design Mastery

Reporting functionality is a must when selecting a tool for database design.
If you cannot create reports using the tool, it is not worth using. There are so many needs for reporting: auditing, quality reviews, documenting, talking with end users, informing internally, and so on. Data Modeler has strong reporting functionalities. In Data Modeler, you can generate reports from designs that are open or from the optional repository on all designs uploaded to the repository. You can generate reports with the reporting functionality or by using the search feature and generating the search results as a report. Reports can be used, for instance, to create documentation for tables, entities, domains, glossaries, structured types, distinct types, collection types, requests, or measurements. You can also print a diagram by choosing File | Print Diagram. You can print the diagram either to an image file (To Image File) or to a PDF file (To PDF File). A user can create templates for the reports easily, and SQL can be used to query the reporting repository. You can find useful information on reporting in datamodeler\reports.

Data Modeler uses a standardized transformation to produce reports from the source Extensible Markup Language (XML) files. Extensible Stylesheet Transformation (XSLT) defines the syntax and semantics for transforming XML documents to other document formats or XML documents. Data Modeler uses XSLT 1.0, but you can also download the Saxon XSLT 2.0 processor and use that in reporting. Version 2.0 is more advanced and supports, for large PDFs and multibyte characters in Rich Text Format (RTF) reporting. If you know that you will be producing large PDFs or will be running reports from designs including multibyte characters, using the Saxon XSLT 2.0 processor will be essential.

You can generate PDF reports with Apache Formatting Objects Processor (FOP) v0.95. The FOP configuration file is named fop.conf. The file contains only the basic fonts and default settings which automatically adds fonts from the systems directory. If the PDF report does not support the fonts you need, edit the fop.conf file as explained in datamodeler\reports\Reports_Info.txt.

When Data Modeler generates reports, it first creates a file called report_data.xml (or report_data_rs.xml). In the directory datamodeler\reports\templates, there are two subdirectories for templates: 10 and 20. If you are using the XSLT 1.0, then templates are in directory 10, and if you have XSLT 2.0, they are in directory 20. All template files are named on the element type and output format, such as AllTablesDetails_jrt.xsl

A report can be saved and saved in different formats depending on the settings. PDF and HTML formats are always supported. PDF is a good format when you want to send reports that no one should edit, for instance during a review. HTML is useful as a custom web page that could be, for instance, as an online dictionary on an internal web site or for technical people who want to see the information without installing Data Modeler.
