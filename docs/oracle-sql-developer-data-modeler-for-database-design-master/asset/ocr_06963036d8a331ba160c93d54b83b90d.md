# Checking Out a Design from Subversion

If you have not worked with this design before, you must check it out from Subversion the first time you start working with it. If you already checked it out, you just open the design and start working as earlier.

First, create the subdirectory in your designs directory for the design or let Data Modeler create it for when checking out. Then Choose Team | Check Out, or go to the Versions branch, select the directory for the design, right-click, and choose Check Out. If you are using the Team menu, select the correct Subversion repository (Repository Connection) and the correct directory (Path). Then select the working directory in Destination. If you have not created a directory yet, do not worry; specify the desired directory and finish the specification with a backward slash (\), and Data Modeler will create the directory automatically. If you do not want to get the latest version of the design, you can specify the version. Select Revision and select the desired revision by clicking the Select Revision button. In the Depth list, you can define where in the directory you want to go with your checkout. When checking out a design, I suggest you not touch the Depth selection but go with Infinity: Fully Recursive, which is the default. OK. Then open the design from your working by choosing File | Open.

If you tried to check out to a directory that already has files in it, you will get an error message: "Checking out into a directory which is not empty may cause undesirable results. Are you sure you want to check out to C:..." I do not recommend you do this since working with an integrated version control is challenging by itself and should not be interfered with. Reply No to this. If you wanted to continue working on a design you have already checked out, please follow the instructions on how to work with a design you have worked with before. And if you really want to check out again, please select a new directory as a working directory or remove all the files from this working copy directory before checking it out. Data Modeler will create a new directory for you automatically and suggest a name for it (MyDesign_0, MyDesign_1, and so on).

# Solving Conflicts

A conflict (Figure 9-5) means you have made changes to a version that has been changed by someone else after you updated your working copy. In other words, you have changed a version that is not the latest version, and you have changed something that conflicts with other changes. Usually that happens if one of the users does not commit immediately after making changes but then does it later. So, you do not see the other person's changes in your Incoming Changes list (because they have not been committed to Subversion) and therefore cannot update them to your local copy, and you continue working without knowing about the changes.
