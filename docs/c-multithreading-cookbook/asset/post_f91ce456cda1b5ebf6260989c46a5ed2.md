```cpp

{
    CLOCK* outerLock = new CLOCK(a->szLock);
    if (dAmount < a->dBalance)

        b->dBalance += dAmount;

The preceding code looks correct, but it isn't. It's incorrect! Assume the situation where thread wants to transfer some amount from account X to account Y, while at the same time, thread B wants to transfer some amount from account Y to account X. When thread enters the Transfer method, it will acquire the lock that belongs to account X. Now, assume that the name of the mutex that used for X is lock_X. Then, assume that the next scheduled thread is B and acquires the lock that belongs to account Y, and its mutex name is lock_Y. Next, thread A continues and tries to acquire the lock that belongs to account Y. It blocks because lock_Y is held by thread B and belongs to account Y. Now, thread B continues and tries to acquire lock_X, which is held by the previously suspended thread A.

# Understanding Concurrent Code Design

This is illustrated by the following figure:

| T | Thread A (transfer from X to Y) | Thread B (transfer from Y to X) |
|---|---|---|
| 0 | Clock* outerLock = new Clock(a->LockName()); // Thread A acquires a lock_1 on account X | Clock* outerLock = new Clock(a->LockName()); // Thread B acquires a lock_2 on account Y |
| 1 | | if (dAmount < a->dBalance) |
| 2 | | |
| 4 | Clock* outerLock = new Clock(b->LockName()); // Thread A tries to acquire a lock_2 on account Y and it gets suspended | Clock* outerLock = new Clock(b->LockName()); // Thread B tries to acquire a lock_3 on account X and it gets suspended |
| 5 | // WAIT WAIT FOREVER || suspended // WAIT WAIT FOREVER || |
| 7 | | |

Again, the first column (**T**) is the time to execute the statements. The following column consists of the **Thread A** code statements. Next is the **Thread B** code statements. The illustrated situation may occur very rarely, but when we are going to design parallel code, we must be aware of such situations at all times.
