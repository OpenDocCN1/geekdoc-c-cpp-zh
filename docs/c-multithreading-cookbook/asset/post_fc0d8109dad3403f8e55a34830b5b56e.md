# How it works...

We choose to draw an 800 x 600 (pixels) figure in our example. That's why we've set iWidth to 800 and iHeight to 600. Then, we'll allocate Bitmap and the color array. We will draw a symmetrical left and right part of the canvas, we will iterate through half of. That's why we'll set the maximum to iWidth / 2. When we click the Start button, we'll create a method delegate in order to pass it the Tasks::Invoke. Before we call a parallel invoke, we need to instantiate the barrier object with two participants and a postAction delegate. This post action delegate is important for because we want to draw the figure after the entire calculation is done. We could accomplish this with an event, or we could post a message to the window message queue, but this is the proper way when using threads: post action method is needs to draw the plot and set the label text. We must use delegates to invoke proper methods because a different thread will make this call and we will avoid cross-thread operations with UI elements.

## Introduction

Even though synchronization and time are significant factors in developing parallel applications, adding concurrency to programs brings many additional concerns. Parallel programming can be a sword with two edges: you can do great things with it, such as scaling a program to be executed over up-to-date modern multicore processors. Furthermore, parallelism presents great software capabilities you can develop a responsive and rich user interface in GUI applications. However, you must still be aware of the fact that if parallelism is used incorrectly, it can cause serious performance issues.
