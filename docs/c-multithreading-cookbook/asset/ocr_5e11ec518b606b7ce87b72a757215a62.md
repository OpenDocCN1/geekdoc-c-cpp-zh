# Introduction to C++ Concepts and Features

The protected methods are copy constructor (copy constructor) and operator=(operator equal). Why do we set these two methods as protected? The list implemented here, as we said, saves pointers to objects that "live" outside the list itself. It would be dangerous to allow the user to copy the list intentionally or unintentionally without caution, either using copy constructor or equal op for using it. In order to achieve this, we need to declare, and later implement, both methods; else the compiler will generate them as public, but we decided to protect copy constructor or equal op from using it. We declare them as private, by default, implementing them with copying pointers one by one, which is wrong. It is not for classes derived from the CList base class. In such a case, the problem will occur for classes equal op, else these methods will be public, generated from the compiler by default. When copy constructor exists in base, the derived copy constructor will call it by default, except if the derived class calls it explicitly in another way. As we want to enable the CList copy constructor to be made available to the derived classes, it is declared as protected.

The private section of the CList class contains objects needed for the implementation of the linked list as a linear linked list. This means that every element points to the next, while the head node points to the first element.

The Queue and Stack classes implement queue and stack, respectively. Notice how easy their implementation was after properly designing the CList base class (especially the Enqueue, Dequeue, Push, Pop, and Peek methods). Once the CList class is carefully designed, it is very simple to design and implement Queue and CStack, or even some other classes later.
