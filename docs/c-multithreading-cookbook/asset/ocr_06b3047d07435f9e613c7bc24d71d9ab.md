# Synchronization object – mutex

How and when the signal arrives depends on the object. For example, one important feature of a mutex is that only one thread can run it at a time. It does nothing, except that it allows ownership for only one. If you need a few threads to work with one, you can create a mutex to protect the file. When any thread starts an operation on the file, it must first ask for the ownership of the mutex, and if no other thread is holding the mutex, the thread gets access. If, on the other hand, some other thread grabbed the mutex for itself, the request fails; the thread is blocked and suspended while waiting to take the ownership of the mutex. When a thread finishes writing, it releases the mutex, and the thread becomes alive again on receiving the mutex and performs the requested operations on the file.

A mutex does not protect anything. It works in the following manner: the threads that will use it agree not to use a shared object without the mutex ownership first. There is nothing to prevent the threads from attempting to enter at once. A mutex is a signal, like the Boolean variable done from the previous example. A mutex can be used to protect a global variable, a hardware port, etc. Every time multiple threads share a system resource, you should consider using a mutex for the synchronization, in order to avoid the mutual conflicts.

The following code shows the de routines for mutex usage. To create or open an existing mutex object, you can use CreateMutex:

```
HANDLE WINAPI CreateMutex(
    LPSECURITY_ATTRIBUTES lpMutexAttributes,
    BOOL bInitialOwner,
    LPCTSTR szName
);

```

You can set the security attributes or leave them empty for default values. If TRUE is set for bInitialOwner, the caller gets immediate ownership of the mutex. The mutex name must be supplied.
