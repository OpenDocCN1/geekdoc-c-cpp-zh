# Understanding Concurrent Code Design

```
T* CList::Pop( void )
{
    CClock* lock = new CClock(T("_tmp_lock_"));

    CList* node = next;
    if (node == NULL)
    {
        return 0;
    }

    next = node->next;
    delete lock;

    return node->value;
}
```

Now even if the OS will change its execution from one thread to another, we won't have situations where the Correctness problem can occur, because we have properly secured the intensive operations and statements. However, protecting more statements means more sequential execution, so you must be aware of the performance improvement at all times.

The idea is to design an application execution flow in such way that the critical points are grouped in some heavily-protected portions, and we must take care of as many usage scenarios (cases) as possible, only to determine the correct parallel execution flow.

Let's talk a bit about Liveness problems. They dont usually terminate the program, and as such, are very difficult to detect and diagnose. In most situations, these problems will lead to the application causing to respond. In some cases, the application will stop temporarily.
