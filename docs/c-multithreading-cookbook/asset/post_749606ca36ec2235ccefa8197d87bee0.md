
# The Concepts of Process and Thread

The calling thread can use the WaitForIdle function to wait until the new process has finished its initialization and is waiting for user input with no input pending. This can be useful for synchronization between parent and child processes, because CreateProcess returns waiting for the new process to finish its initialization. For example, the creating process would use the WaitForIdle function before trying to find a window associated with the new process.

The proper way to terminate a process is by calling the ExitProcess function, as it sends a notification of approaching to all DLLs attached to the process. Other methods used to shut down a process, such as using the TerminateProcess API, do not notify the attached DLLs. Note that when a thread calls the ExitProcess function, the other threads of the process are terminated without an opportunity to execute any additional code (including the thread termination of the attached DLLs).

# There's more...

Although each process is an independent entity, with its own pointer and internal state, processes often need to interact with other processes. One process might generate output data that another process might use as input. Depending on the relative speed of the two processes, it might happen that in example, the read operation is ready to run, but there is no input waiting for it. When a process is blocked, it cannot execute anything. This is because the process is waiting for input that is not yet available. It is possible for a process to be stopped because the operating system has deallocated the CPU to another process for a while. These two conditions are completely different. In the first case, the suspension is inherent in the problem technicality of the system (not enough CPUs to give each process its own time on the processor).

In the following figure, we see a diagram that shows the three states of a process may be: they are as follows:

- Running: This means the process is actually using the CPU at that instant
- Ready: This means the process is runnable; it is temporarily stopped to let another process run
- Blocked: This means the process is unable to run until some external event occurs

Running and Ready states are similar. In both cases, the process is willing to run. However, in the second one, there is temporarily no CPU available for the process. The Blocked state is different from the first two; the process cannot run, even if the CPU has nothing else to do.

# Implementation of processes

In modern multitasking systems, the Process Control Block (PCB) stores many different items of data, all needed for correct and efficient process management. PCB is the data structure that resides in the operating system kernel which contains the information needed to manage the process. The PCB is the representation of the process in the operating system. Though the details of these structures are system-dependent, there are some common parts, which could be classified into three main categories:

- Process identification data
- Process state data
- Process control data

The role of the PCB is central in process management. It is accessed and/or modified by most operating system utilities, including those involved in scheduling, memory and I/O resource access, and performance monitoring. Data structuring for processes is often done in terms of PCBs. For example, pointers to other PCBs inside a PCB allow the creation of queues in various scheduling states (Ready, Blocked, and so on), which we mentioned earlier.

The operating system must manage resources on behalf of processes. It continuously takes care of the state of each process and its resources and internal values. The following example will demonstrate how to obtain a basic process information structure address, where one of the attributes is the address of PCB. Another attribute is the unique process ID. For the simplicity of this example, we will simply output a process ID read from the object.

# How it works...

For this example, we used some additional header files: Winternal.h and Windows.h. Header include includes for the majority of Windows' internal routines and data representation; this includes the PROCESS_BASIC_INFORMATION structure with the following:

```cpp
typedef struct PROCESS_BASIC_INFORMATION {
    VOID Reserved1;
    PEB BaseAddress;
    VOID Reserved2[2];
    ULONG_PTR UniqueProcessId;
    VOID Reserved3;
} PROCESS_INFORMATION;
```

The preceding structure is used by the operating system in calls made between the user mode and kernel mode subroutines. In combination with the PROCESSINFORMATIONCLASS::ProcessBaseInformation, we use the UniqueProcessId attribute to obtain the process identifier, only as a demonstration.

First, we define QUERYINFORMATION, a typedef for the NtQueryInformationFunction loaded from the ntdll.dll library. When the address of the function is obtained using the GetProcAddress Win32 API, we can query for the PROCESS_BASIC_INFORMATION object. Pay attention to the PebBaseAddress field; it is a pointer to the PCB of the newly created process. If you want to check the newly created process, you will have to use the ReadProcessMemory routine in runtime, because the memory to which PebBaseAddress points belongs to the newly created process.
