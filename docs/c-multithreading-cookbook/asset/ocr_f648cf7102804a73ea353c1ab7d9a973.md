# IPC – Interprocess Communication

It is very important that processes have some way of communicating with each other. Operating systems provide such mechanisms, but we need to focus on issues related with it. For example, if two processes in an airline reservation system are trying to sell the last seat on the plane at the same time? Of course, this is very wrong because you can't sell the same seat twice. There is also a dependency problem: if Process produces some kind of data and process B is reading that data (for example, to print it), then B must wait until process A produces the required data. The difference between processes and threads is that the first task for the thread is much easier to implement due to fact that threads share a common address space processes do not. Regarding the second issue, it is equally applicable to threads; that's very important to understand synchronizing mechanisms.

To see how IPC appears, let's consider a simple example: a CD burner. When a process wants to burn something, it sets the handles (we are burning more files at once) in a special burn buffer. Another process, responsible for burning, checks if there are any files to be burned and if there are, it burns them and removes the handles from the buffer. Let's assume that the buffer has enough indices, numbered 10, 11, 12, and so on. Also assume that there are two shared shared variables, p_next and p_free, which points to the next free index in the buffer to be burned. These variables must be available to all processes. At a certain instant of time, indexes 10 to 12 are empty (the files have already been burned) and slots 13 to 15 are filled.
