# The Concepts of Process and Thread

The calling thread can use the WaitForIdle function to wait until the new process has finished its initialization and is waiting for user input with no input pending. This can be useful for synchronization between parent and child processes, because CreateProcess returns waiting for the new process to finish its initialization. For example, the creating process would use the WaitForIdle function before trying to find a window associated with the new process.

The proper way to terminate a process is by calling the ExitProcess function, as it sends a notification of approaching to all DLLs attached to the process. Other methods used to shut down a process, such as using the TerminateProcess API, do not notify the attached DLLs. Note that when a thread calls the ExitProcess function, the other threads of the process are terminated without an opportunity to execute any additional code (including the thread termination of the attached DLLs).

# There's more...

Although each process is an independent entity, with its own pointer and internal state, processes often need to interact with other processes. One process might generate output data that another process might use as input. Depending on the relative speed of the two processes, it might happen that in example, the read operation is ready to run, but there is no input waiting for it. When a process is blocked, it cannot execute anything. This is because the process is waiting for input that is not yet available. It is possible for a process to be stopped because the operating system has deallocated the CPU to another process for a while. These two conditions are completely different. In the first case, the suspension is inherent in the problem technicality of the system (not enough CPUs to give each process its own time on the processor).

Running and Ready states are similar. In both cases, the process is willing to run. However, in the second one, there is temporarily no CPU available for the process. The Blocked state is different from the first two; the process cannot run, even if the CPU has nothing else to do.
