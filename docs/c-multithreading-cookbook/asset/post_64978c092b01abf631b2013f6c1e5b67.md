# Installing WinDK – Driver Development Kit

In order to use Windows Driver Kit, you need to perform the following operations:

- 1. Open your web browser and navigate to http://msdn.microsoft.com/en-us/library/windows/hardware/hh852365.aspx. Since we are using Visual Studio 2013, you'll need to download WDK 8.1 or use the following address:
  http://go.microsoft.com/fwlink/link/p?LinkId=393659. The following is a screenshot of the WDK download page:

![](img/412b0f5bbb36adcce2ddd2d5b7416516_399_0.png)

- 2. Select Next and choose whether you want to participate in Customer Experience Improvement Plan, and then accept License Agreement to start the installation. You will see a window in the following screenshot:

![](img/412b0f5bbb36adcce2ddd2d5b7416516_399_1.png)

- 3. Wait for the installation to complete and close the wizard.

![](img/412b0f5bbb36adcce2ddd2d5b7416516_400_0.png)

Now, Windows Driver Kit is successfully installed.

# Setting up a Visual Studio project for driver compilation

In order to get the features from Windows Driver Kit, such as compilers and libraries, you need to set up the Visual Studio project properties. To do this, perform the following operations:

- 1. If you have followed instructions from Chapter 2, Thread Concept, the example Implementing threads in kernel - open the solution KernelThread. In Solution Explorer, right-click on the DriverApp and select Properties. Under the General tab, select Target Extension and choose Edit. Rename .exe to .sys. Click on Apply, as shown in the following screenshot:

![](img/412b0f5bbb36adcce2ddd2d5b7416516_401_0.png)

- 2. Expand the C++, node and under General, select **Additional Directories**. Click on **Edit** and enter the following path: `C:\Program Files (x86)\Windows Kits\8.1\Include.km`. Click on **OK** and then on **Apply**.

![](img/412b0f5bbb36adcce2ddd2d5b7416516_401_1.png)

- 3. Now, under C++, remove all Preprocessor, and under Preprocessor Definitions, choose Edit. Remove all the lines and enter _x86_ if the Win32 configuration is active, or _AMD64_ if the x64 configuration is active, as follows:

![](img/412b0f5bbb36adcce2ddd2d5b7416516_402_0.png)

- 4. Click on OK and then on Apply. Now, under Code Generation, select Enable C++ Exceptions and delete all the text and leave it blank. Click on Apply. Under Basic Runtimes Check, select Default and then click on Apply. Under Security Check, select Disable Security Check (/GS-) and click on Apply.

![](img/412b0f5bbb36adcce2ddd2d5b7416516_403_0.png)

- 5. Now, under advanced, select calling convention and choose _stdcall (/Gz) as follows:

![](img/412b0f5bbb36adcce2ddd2d5b7416516_403_1.png)

- 6. Now, expand the linker node, and under General, select Enable Incremental Linking and choose No (INCREMENTAL:NO). Now, under Input, select Additional Dependencies (x86) and click on Edit. Enter the following lines: C:\Program Files (x86) Windows Kits\8.1\Lib\winkm\x64\ntoskrnl.lib and C:\Program Files (x86) Windows Kits\8.1\Lib\winkm\x64\hal.lib. Pay attention to change x64 to x86, depending on your solution configuration:

![](img/412b0f5bbb36adcce2ddd2d5b7416516_404_0.png)

- 7. Click on OK and select Apply. Now, expand the Manifest File node and select Generate Manifest. From the drop-down list, select No (/MANIFEST:NO). Click on Apply. Now, expand the System node and select SubSystem. From the drop-down list, choose Native (/SUBSYSTEM:NATIVE). Select Driver and from the drop-down list, choose Driver(Driver). Click on Apply.

![](img/412b0f5bbb36adcce2ddd2d5b7416516_405_0.png)

- 8. Finally, select the **Advanced** node and select **Entry Point**. Insert the text `DriverEntry`. Under **Base Address**, insert the text `x0`. Then, select **Randomize Base Address** and delete all the text and leave it blank. Then, select **Data Execution Prevention** and delete all the text and leave it blank. Select Import Library and insert the text `ntoskrnl.lib`.

![](img/412b0f5bbb36adcce2ddd2d5b7416516_405_1.png)

Now, you can compile and run the test DriverApp. Note that if you're using a 64-bit operating system, starting a digitally-unsigned driver is not possible, until you make changes to Advanced Boot Options; Vista and the later versions of Windows support the F8 Advanced Boot Option, that is, Disable Driver Signature Enforcement, which disables the load-time signature enforcement for a kernel-mode driver for the current session system. This does not persist across system restarts (from MSDN). For more information on this, http://microsoft.com/en-us/library/windows/hardware/ff57565(v=vs.85).aspx.

# Using the DebugView application

In order to display the output from the driver, you'll need to use the DebugView application. Perform the following operations:

- 1. Open your web browser and navigate to http://technet.microsoft.com/en-us/internals/bb96647.aspx. Download the DebugView ZIP file and extract it to a folder. Run the DebugView application and, from the menu, select Capture. Add a tick to Capture Kernel or press Ctrl + K.

![](img/412b0f5bbb36adcce2ddd2d5b7416516_406_0.png)

- 2. Now, if you run the driver, you will see the output in the DebugView window.
