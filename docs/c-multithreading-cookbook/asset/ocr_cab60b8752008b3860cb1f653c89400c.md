# Thread Synchronization and Concurrent Operations

The upsides are generally, in lower probability of errors. The context and address space of a process is private for the process and all its resources, including threads. If you allocate memory location in one process and pass a pointer to another, it will be meaningless! The operating system creates separate address spaces for all processes. The running process does not know about other processes, and as such, it is greedy; it wants all resources for itself. So, when working with multiple processes, you need a shared memory location if you want to share data, and/or a called pipe for communication. There are other communication objects such as socket, but we will need another book to explain everything here. We have chosen pipe because it is faster and easier to work with.

The downside is a lot harder work because anything that you want to share among processes you have to write shared memory from which process can then read. Our example will use the same task as in the previous three examples, only this time, there are no working threads; we will have working processes. This approach is good for daemon tasks such as servers and printers.
