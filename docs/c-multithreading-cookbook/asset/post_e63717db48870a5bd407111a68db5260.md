
When one thread finishes, the scheduler looks for the next thread that will be executed. While selecting the next thread, the threads with higher priority have an advantage. Some activities such as response to power loss are always executed with higher priority. Elements that perform system interrupts have a higher priority than user processes. The bottom line is that every process has a priority list, and thread base priority comes from the owning process.

As've seen before, thread object attributes include the base and dynamic priority. When we use commands for changing priority, we can only change the base priority. Still, it is not possible to change the thread priority by more than two levels, even if two levels above or two levels below. That is because the thread can't be more important than its parent process. Through the process the thread can't change its priority by more than two steps, the system can. The system allows some kind of improvement—dynamic priority—to the threads that need to be executed. When the thread performs some action in the application window as a key stroke or a mouse click, the system always increases the owning priority. When the thread that waits for data from hard drive gets the data, the system increases the priority for that thread too. These temporary priority improvements, when added to base priority, form the dynamic priority. ## Thread Synchronization and Concurrent Operations

Decreasing the dynamic priority starts immediately after completion of task. Dynamic priority decreases one step each time the thread receives requested time on the CPU, and finally stabilizes on base priority. The following example demonstrate basic use of process and thread. We will create an application where the main thread will owe the main window, while another thread will be responsible for drawing figures. It is important that the main thread has at least one step higher priority than drawing thread. This is required because the main thread must respond to any user input, such as moving or closing the application. Make sure Visual Studio is up and running.

LRESULT CALLBACK WindowProcedure(HWND hWnd, UINT Msg, WPARAM wParam, LPARAM lParam)
{
    switch (Msg)
    {
        case WM_CREATE:
        {
            SetWindowLongPtr(hWnd, GWLP_USERDATA, (LONG_PTR)lParam);
            SetThreadPriority(GetCurrentThread(), THREAD_PRIORITY_NORMAL);
            return 0;
        }
        case WM_SIZE:
        {
            LONG_PTR pThreadData = (LONG_PTR)GetWindowLongPtr(hWnd, GWLP_USERDATA);
            if (pThreadData) {
                // Handle resize
            }
            return 0;
        }
        case WM_PAINT:
        {
            PAINTSTRUCT ps;
            HDC hDC = BeginPaint(hWnd, &ps);
            LONG_PTR pThreadData = (LONG_PTR)GetWindowLongPtr(hWnd, GWLP_USERDATA);
            if (pThreadData) {
                DrawProc(hDC);
            }
            EndPaint(hWnd, &ps);
            return 0;
        }
        case WM_DESTROY:
        {
            PostQuitMessage(0);
            break;
        }
        default:
        {
            return DefWindowProc(hWnd, Msg, wParam, lParam);
        }
    }
    return 0;
}

void WINAPI StartAddress(LPVOID lpParameter)
{
    HWND hWnd = (HWND)lpParameter;
    SetThreadPriority(GetCurrentThread(), THREAD_PRIORITY_HIGH);

    while (true)
    {
        if (WaitForSingleObject(hEvent, 0) == WAIT_OBJECT_0)
        {
            SetThreadPriority(GetCurrentThread(), THREAD_PRIORITY_NORMAL);
            break;
        }
        Sleep(10);
    }
}

void DrawProc(HDC hDC)
{
    for (int i = 0; i < 10; i++) {
        int x = rand() % WINDOW_WIDTH;
        int y = rand() % WINDOW_HEIGHT;
        int size = 10 + rand() % 50;
        HBRUSH brush = CreateSolidBrush(RGB(rand() % 255, rand() % 255, rand() % 255));
        SelectObject(hDC, brush);
        Rectangle(hDC, x, y, x + size, y + size);
        DeleteObject(brush);
    }
}
