The CBankAccount class implemented in CBankAccount.h along with Clock and CParameters remains the same. The Transfer method is changed in a way that at the beginning of the method, a sleep time of 0.1 second is added. This is intentionally added in order to create a situation with deadlock. After two threads are started, if we were to remove the sleep time probably deadlock would not occur the system would give enough time to the CPU to thread it not request for lock in the same time as another.

Furthermore, in CThread.h we've implemented a more smarter CThread class. Using the CThread object in the thread pool as an abstraction of a working object. The object has the lpThreadStart attribute for the thread start address, hThread used for the thread handle, dvThreadId used for the thread id, dvExitCode used for thread exit, and pThreadContext used for the context thread. As illustrated in earlier diagram, creating another thread will gain more control over execution. The context implementation is assembled as an internal structure consisting of the following attributes: lpThreadStart is used for the user-defined start address; lpParameter is passed by the user for the start context; hThread is used for the context handle; dvThreadId is used for the context id; dvMaxWaitTime is used for setting the timeout for waiting for the context thread. The CThread class implements one where the exit code is set to zero. Constructor arguments are slightly changed, lpDispatcherId is added to create a STARTCONTEXT object where we set lpThreadStart with a user-defined start address. The dvDispatcherId is used to pass the actual manager to identify the thread. In constructor, we pass as well, as dvMaxWaitTime with MAX_TIME default value and we return a worker with the CONTEXT_SUSPENDED flag. In the destructor, we delete the first used by pThreadContext and then we query if still using the StillAlive method and then close the thread handle. The Start method sets the lpThread attribute by the user and resumes the worker thread. The StillAlive method returns the STILL_ACTIVE macro with the return value of ExitStatus, The Handle and ThreadId methods return a handle to the worker and thread id respectively. The ContextHandle and Contextmethods return a handle to the context and the context thread respectively. The ExitStatus method calls the GetExitCodeThread to obtain its exit code or ACTIVE. The SetWaitTime sets the maximum waiting time attribute. The StartAddress method is added in order to perform task execution by creating another thread and the completion, in the worst case, a maximum of the pThreadContext-dvMaxWait interval. Either the interval has passed or returned. Then, the context thread handle is closed and the MSG_ENDTASK message is posted to the dispatcher queue.

The CParameters class remains the same. Instead of searching through the list with a specified wait time, we'll block the dispatcher and wait for the MSG_ENDTASK message posted from the first worker thread.
