# How it works...

This is a much better approach than the previous examples. We removed the Lock class and at the same time we avoided using the shared object, which is the primary spot for errors and interference. We've added the ManualResetSlim variable in the private scope. It is declared static due to safety, which was explained before. In the MyForm constructor, we will create a new instance of ManualResetSlim, which is not good if you have multiple instances. For simplicity of the given example, we choose to do it like this. It is left to the user to improve the application if more than one instance is required. Also the ManualResetSlim constructor accepts a bool parameter, which designates whether to set the initial state of an event to signaled or not. When the working thread starts execution, it will set the state to nonsignaled. By calling the Wait method, it will enter a suspended state and wait for an event until its state becomes signaled. In the main thread, inside the WndProc function, after the user continues to continue, we will set the state to signaled. In this, the working thread can continue with its execution.

# There's more...

ManualResetSlim provides a faster version of ManualEvent and gives better performance when the wait time is expected to be less, and when the event is not shared between different processes. When the wait time is smaller, the ManualResetSlim overhead is much less expensive, usually in situations other than waiting for some wait handles. However, if the state doesn't become signaled within a short time period, the event behaves as a regular ManualEvent object.
