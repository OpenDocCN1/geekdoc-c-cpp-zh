# Understanding Concurrent Code Design

In the private scope, we've placed the Random(double dMin, double dMax) and Seed(void) methods that return a random number from dMin to dMax and seed for a random generator respectively.

As previously mentioned, the Evaluate methods were declared as virtual, and for the Schwefel class, implementation is straightforward. First, we call the GetSystemTime API, with Start as the parameter in order to store the time before we start calculating; then, inside the outer loop, we'll calculate the sum and multiply it with itself. According to Schwefel's formula, we'll add it to code and calculate the best value. When in the outer loop, we'll GetSystemTime with the std parameter in order to obtain the system time again. When we subtract these two times, we'll get the elapsed time for calculation. One thing about the Evaluate method: for the sake of future implementation (for example, class derivation), we've planned one argument but you can pass as many arguments as you like in a manner-just like any of our examples, which use some routine for the CreateThread API.

Since the SYSTEMTIME structure does not implement for the SYSTEMTIME subtraction, we'll implement our own: SYSTEMTIME operator - (const SYSTEMTIME& stFirst, const SYSTEMTIME& stSecond); This method, we'll convert the system time to file time using the SystemTimeToFile API so that we get the integer value from the human-readable time for both the arguments. Then, we'll subtract these two integers and we'll convert the result to a human readable time using the FileTimeToSystem API.

In our application's entry point, we'll simply instantiate the Schwefel object with a size of 100,000 alleles and call the Evaluate and Elapsed methods.
