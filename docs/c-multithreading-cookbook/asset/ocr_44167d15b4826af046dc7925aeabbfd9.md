# Understanding Concurrent Code Design

Another scenario is called Composite Actions, where a constant tradeoff between single-threaded performance (due to more locks) and parallel (without locks) execution is made. In other words, proper decision on what are the statements or areas of code to protect is critical.

Imagine a situation using a simple linked list, and we remove the head node. When we mention the tradeoff, when we remove the list's head node, we'd have two critical regions. If first, when the query head node equals zero (0), that is, node = NULL, and then on the assignment of a new node, none = node->next. If we protect a lot of statements, the fewer protected statements, the more concurrency we can achieve.

Assume that our list has only one node. We'll use the CClock class from the previous example for an exclusive access. The code is as follows:

```
template class<T>
class CList<T> {\public:
    CList() : next( 0 ), value( 0 ) {}
    T Pop( void );
private:
    CList* next;
    T* value;
};
t
template class<T>
T* CList::Pop( void ) {
    CList* node = next;
    if (node == NULL) {
        return 0;
    }

    CClock* lock = new CClock(_T("_tmp_lock_"));
    next = node->next;
    delete lock;

    return node->value;
}
```
