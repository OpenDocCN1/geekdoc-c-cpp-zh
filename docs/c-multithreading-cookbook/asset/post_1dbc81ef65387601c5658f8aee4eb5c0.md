# How it works...

This example has a lot more code. However, the good part is that, because there is no security among threads (without proper synchronization, of course), and one thread can mess with the other thread's data, global variables, working with processes is safer by definition. What we mean is that processes are divided by their own address space, global variables, and synchronization operations. On the other hand, if one thread blocks all the threads that wait for its shared resources all will be blocked. When you learn about synchronization, it is important to understand the process model and Interprocess Communication (IPC) as well. Let's explain main.h first. As most projects use a pipe name as a mutex and file mapping name, we will define them as macros inside the main header file. All remain the same.

Now, let's focus on concurrent_operations5. The application entry point remains much the same. We'll create an event, mutex, and file mapping before the main thread enters the message loop. We'll dispose all the mentioned objects after the application is closed. The other thing about file mapping is that we set the size of the shared object correctly; so we will set the size to sizeof(QueueElement).

We'll also create a listener that will use ListenerRoutine as a start address. This task is to loop for, until the event state becomes signaled.
