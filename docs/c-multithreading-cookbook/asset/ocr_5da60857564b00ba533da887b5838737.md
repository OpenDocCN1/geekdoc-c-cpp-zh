# Understanding Concurrent Code Design

```
{
CSwefel CSwefel(100000);
CSwefel.Evaluate();

_printf_s(CSwefel.Elapsed());

CSwefelMT CSwefelMT(100000);
CSwefelMT.Evaluate();

_printf_s(CSwefelMT.Elapsed());

#ifdef DEBUG
return system("pause");
#endif

return 0;
}
```

# How it works...

As CSwefelMT is derived from CSwefel, we only need to implement the constructors and destructors along the virtual Evaluate method. We must disallow the programmer from using the copy constructor and the equal operator for the same reasons as in the CSwefel class. In the private scope, we've added a StartAddress routine for the threads and the ThreadParams structure for passing the arguments to the threads.

What about the Evaluate method now? It's simple. We instantiate ThreadNumber of threads and ThreadNumber of parameters for them; then we will call GetSystemTime and run the declared threads; we'll create a barrier, or in other words, we'll wait for their return using the WaitForMultipleObjects routine, and then we'll call GetSystemTime once again close all the thread handles.

What about StartAddress? Is it straightforward? Let's see. If we follow the logic from the previous single-threaded example, our Evaluate method will have many Correctness problems!
