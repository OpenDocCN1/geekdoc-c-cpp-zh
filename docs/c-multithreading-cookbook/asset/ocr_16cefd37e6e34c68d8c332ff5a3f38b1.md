If a problem occurs and the pool is blocked for some reason, this thread will try to resolve the problem. That's why it is imperative that it does not execute under any thread that belongs to the pool and could be blocked along with the pool. Its task is to loop forever, or until the program exits, when the event is set to the signaled state. So, on each iteration, it will WaitWaitForObject with a handle to the event passed along with a 0.01 second interval. If the event is set, the thread will exit. If not, it will iterate through the entire thread list, and it will call the Stillalive method for each thread. If the thread is alive, it will call the OpenThreadWaitChainSession API that creates WCT or Wait Chain Traversal.

> Wait Chain Traversal (WCT) enables diagnosing eventual application hangs and deadlocks. A wait chain is an alternating sequence of threads and synchronization objects; each thread waits for the object that follows it, which is owned by the subsequent thread in the chain (MSDN).
