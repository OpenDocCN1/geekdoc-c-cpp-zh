# Description

- To add a new customer, the user clicks the Add button on the Customer Maintenance form to display a blank Add Customer form. Then, the user enters the data for the new customer and clicks the Accept button to return to the Customer Maintenance form.
- To modify the data for an existing customer, the user enters the customer ID and clicks the Get Customer button to display the information for that customer. Then, the user clicks the Modify button to display the Modify Customer form, makes the appropriate modifications, and clicks the Accept button to return to the Customer Maintenance form.
- To delete an existing customer, the user enters the customer ID and clicks the Get Customer button to display the information for that customer. Then, the user clicks the Delete button and responds to the dialog box that’s displayed to confirm the delete operation.

# The code for the Customer Maintenance form

Figure 20-18 shows the code for the Customer Maintenance form. After the default constructor (not shown here), it declares two class variables. The first stores an instance of the DB context object that’s used by the form, and the second stores the customer that’s currently displayed on the form.

Because this form doesn’t contain a Load event handler, no data is displayed when the form is first loaded. Then, the user can enter a customer ID and click the Get Customer button to retrieve the data for a customer, or the user can click the Add button to add a new customer.

The event handler for the Click event of the Get Customer button starts by calling the IsValidData() method. This method, in turn, calls the IsInt32() method in a class named Validator to check that the user entered an integer for the customer ID. This class contains methods like the ones in the Validator class from chapter 12.

If the customer ID is an integer, it’s used to get the customer with the ID entered by the user from the database. To do that, the code calls the Find() method of the Customers entity collection. This method will return a Customers object if the customer with the specified ID is found. Otherwise, it will return null.

The statement that calls the Find() method is coded within a try-catch statement. That’s because the Find() method will throw an exception if the DB context is no longer available or the database can’t be found. So, this event handler should catch that exception. To handle this exception, the catch block passes the Exception object to the HandleGeneralError() method shown on page 4 of this code listing.

After it executes the Find() method, the event handler checks if the Customers object contains a null value. If it does, a message is displayed indicating that the customer wasn’t found, and a method named ClearControls() is called. This method, which is presented on page 2, clears the data from the controls on the form and moves the focus to the Customer ID text box so the user can enter another ID.

If the Customers object contains a value, the event handler checks whether the States object for that customer has been loaded. That will be the case if the data for another customer in the same state has already been displayed. If it hasn’t been loaded, the Load() method is called to load it.

Finally, the event handler calls the DisplayCustomer() method. This method, which is presented on page 2, displays the data retrieved from the database on the form.

public partial class frmCustomerMaintenance : Form
{
    // default constructor
    private MMABooksContext context = new MMABooksContext();
    private Customers selectedCustomer;
    private void btnGetCustomer_Click(object sender, EventArgs e)
    {
        if (IsValidData())
        {
            int customerID = Convert.ToInt32(txtCustomerID.Text);
            try
            {
                selectedCustomer = context.Customers.Find(customerID);
                if (selectedCustomer == null)
                {
                    MessageBox.Show("No customer found with this ID. " +
                        "Please try again.", "Customer Not Found");
                    this.ClearControls();
                }
                else
                {
                    if (!context.Entry(selectedCustomer)
                        .Reference("StateNavigation").IsLoaded)
                    {
                        context.Entry(selectedCustomer)
                            .Reference("StateNavigation").Load();
                    }
                    this.DisplayCustomer();
                }
            }
            catch (Exception ex)
            {
                this.HandleGeneralError(ex);
            }
        }
    }
    private bool IsValidData()
    {
        bool success = true;
        string errorMessage = "";
        errorMessage = Validator.IsInt32(txtCustomerID.Text,
            txtCustomerID.Tag.ToString());
        if (errorMessage != "")
        {
            success = false;
            MessageBox.Show(errorMessage, "Entry Error");
            txtCustomerID.Focus();
        }
        return success;
    }
}

The DisplayCustomer() method at the top of page 2 of figure 20-18 assigns the appropriate properties of the selectedCustomer object to the Text properties of the text boxes. For the State text box, the value is retrieved from the related States object using the navigation property of the selectedCustomer object. That’s why the States object for the customer had to be loaded. And, that’s how the form can display the state name instead of the state code. Finally, the method enables the Modify and Delete buttons so the user can choose to update or delete the selected customer.

The ClearControls() method assigns empty strings to the text boxes on the form and disables the Modify and Delete buttons. Finally, it moves the focus to the Customer ID text box so the user can enter another ID.

The Click event handler for the Add button displays the Add/Modify Customer form as a dialog box. But first, it creates an instance of that form and sets its public AddCustomer property to true. That way, the form knows that a new customer is being added. And, it assigns a collection of States objects to the public States property of the form. To do that, it uses the States collection of the DB context and orders the states by name.

If the customer is added successfully, the new customer is retrieved from the Customer property of the Add/Modify Customer form. Then, within a try clause, the Add() method of the DB context is called to add that Customers object to the Customers collection. Next, the SaveChanges() method is executed to add the customer to the database.

After the try clause, the catch clauses handle the exceptions that might be thrown. If a DbUpdateException is thrown, it’s passed to a method named HandleDataError(). If any other exceptions are thrown, they’re passed to a method named HandleGeneralError(). Both of these methods are presented on page 4 of this code listing. For these catch clauses to work, the clause for the DbUpdateException object must be coded first. That’s because a DbUpdateException object is more specific than an Exception object.

private void DisplayCustomer()
{
    txtCustomerID.Text = selectedCustomer.CustomerId.ToString();
    txtName.Text = selectedCustomer.Name;
    txtAddress.Text = selectedCustomer.Address;
    txtCity.Text = selectedCustomer.City;
    txtState.Text = selectedCustomer.StateNavigation.StateName;
    txtZipCode.Text = selectedCustomer.ZipCode;
    btnModify.Enabled = true;
    btnDelete.Enabled = true;
}

private void ClearControls()
{
    txtCustomerID.Text = "";
    txtName.Text = "";
    txtAddress.Text = "";
    txtCity.Text = "";
    txtState.Text = "";
    txtZipCode.Text = "";
    btnModify.Enabled = false;
    btnDelete.Enabled = false;
    txtCustomerID.Focus();
}

private void btnAdd_Click(object sender, EventArgs e)
{
    var addModifyForm = new frmAddModifyCustomer {
        AddCustomer = true,
        States = context.States.OrderBy(s => s.StateName).ToList()
    };
    DialogResult result = addModifyForm.ShowDialog();

    if (result == DialogResult.OK)
    {
        selectedCustomer = addModifyForm.Customer;
        try
        {
            context.Customers.Add(selectedCustomer);
            context.SaveChanges();
            this.DisplayCustomer();
        }
        catch (DbUpdateException ex)
        {
            this.HandleDataError(ex);
        }
        catch (Exception ex)
        {
            this.HandleGeneralError(ex);
        }
    }
}
