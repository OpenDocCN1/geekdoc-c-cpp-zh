## How to browse, display, and edit classes

Now that you’ve seen a complete application that uses classes, you’re ready to learn how to browse the classes in a solution and how to display and edit classes. Although you can create applications without using these features, they often make it easier to visualize and work with the classes in a project.

### How to browse the classes in a solution

The easiest way to browse classes in Visual Studio 2019 is to use the Solution Explorer as shown in figure 12-22. The solution in this figure is for the Product Maintenance application that was presented in figures 12-11 through 12-15. Here, I’ve expanded the Product.cs file in the Solution Explorer and the Product class that’s subordinate to it to display the members of this class. As you can see, these members include the private fields named code, description, and price; two constructors; the Code, Description, and Price properties; and two signatures for the GetDisplayText() method. Notice that the icons for the private fields include padlocks, which indicate that these fields are not accessible from outside the class.

You can also use the Solution Explorer to display the code for any member of a class in the Code Editor. To do that, just double-click on the member. In this figure, for example, you can see the code that was displayed when I double-clicked the Description property.

Another way to browse the classes of a solution is to use the Class View window, which is displayed in the same group of windows as the Solution Explorer. The top pane of this window displays the classes of the project, and the bottom pane displays the members of the class selected in the top pane. Just as when you work with classes from the Solution Explorer, you can double-click on a member in the bottom pane of the Class View window to display the code for the member in the Code Editor.

When a class is displayed in the Code Editor, the line above a class definition and the definitions for any members of that class includes a link that indicates how many times the class or member is referred to by other code. This is part of the CodeLens feature of Visual Studio that can help you see where and how the classes and members of a project are used by the project.

To find out more about the references to a class or member, you can click on the link to display a popup like the one shown in this figure. Here, the three references to the Price property are listed. As you can see, one of these references is in the Product class and two are in the ProductDB class. You can also see the code that’s on the line that contains each reference.

To get more information about any of the references, you can point to one of them. Then, another popup is displayed that shows two lines before and two lines after the line that contains the reference so you can see it in context. You can also double-click on a reference to preview the file that contains it and jump to the reference.

### How to use the Peek Definition and Go To Definition features

As you’re developing the code for an application that uses custom classes, you may need to view the code for a class to see how it works. Although you could do that by displaying the code in another Code Editor window, Visual Studio 2015 introduced an easy way to display the code in a class without leaving the class you’re currently working on. To do that, you use the Peek Definition window shown in figure 12-23.

Here, the code for the GetDisplayText() method is shown in a Peek Definition window within the Code Editor window for the Product Maintenance form. To display a window like this, you just right-click on the member whose code you want to display and select Peek Definition from the shortcut menu. Then, the Peek Definition window is displayed below the member you selected, and you can scroll through the window to display the code for the member or any other code in the class.

You can also work outside of the Peek Definition window while that window is open, and you can edit the code in the Peek Definition window. When you make a change to the code, the file that contains that code is opened in another Code Editor window, and the changes you make are reflected in that window. Before you close the Peek Definition window, be sure you save the changes or they’ll be lost.

Another way to display the code for a member is to use the Go To Definition feature that became available with Visual Studio 2017. When you use this feature, the class that contains the member is displayed in another Code Editor window and the name of the member is highlighted. Although that takes you away from the current class, it lets you display and edit any of the code in the class that the member belongs to. This feature is most useful if you know that you want to edit a member of a class or if you want to display all of the code for a class.

**Description**

- You can use the *Peek Definition* window that became available with Visual Studio 2015 to display and edit the code for a member in another class from within the class that refers to it.

- You can use the *Go To Definition* feature that became available with Visual Studio 2017 to display the code for a member in another Code Editor window.
- To use the Go To Definition feature, place the cursor inside the member name and press F12, right-click the member name and choose the Go To Definition option, or press the Ctrl key and click the member whose code you want to display.
