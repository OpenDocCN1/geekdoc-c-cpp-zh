# Perspective

In this chapter, you learned another technique for developing database applications. Instead of using Entity Framework, you learned how to use ADO.NET to create and work with connections, commands, and data readers. When you work this way, you have to write code to perform many of the tasks that are handled automatically by EF. As a result, you have to write more code. However, you also gain control over how the data is processed.

# Terms

| ADO.NET (ActiveX Data Objects .NET) | parameter |
| .NET data provider | parameterized query |
| command | named variable |
| connection | scalar value |
| data reader | aggregate value |

For this exercise, you’ll develop a version of the Product Maintenance application that uses ADO.NET for database access. To make that easier for you to do, we’ll give you the two forms for the project, the Product class, the Validator class, as well as starts for two database classes.
