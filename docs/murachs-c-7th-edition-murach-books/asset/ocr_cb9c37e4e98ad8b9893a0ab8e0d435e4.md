# Object types and casting

Now that you’ve learned the basics of inheritance and you’ve seen an example of an application that uses it, you’re ready to learn some additional techniques that are often required when you work with inheritance. That includes casting objects and getting information about an object’s type.

# How to use the Type class to get information about an object’s type

As you know, the System.Object class includes a GetType() method that you can use to get a Type object that represents the type of a .NET object. Figure 14-13 lists some of the members of the Type class that you can use to get information about an object. For example, you can use the Name property to get the name of a type, such as “Product” or “Book”; you can use the Namespace property to get the name of the namespace that contains a type, such as “ProductMaintenance”; and you can use the FullName property to get the fully qualified name of a type, such as “ProductMaintenance.Book”. In addition, you can use the BaseType property to get a Type object that represents the type of the class that a type inherits.

The first example in this figure shows how you can use these properties to display information about an object. Here, the GetType() method is used to get information about a Book object that’s accessed through a variable of type Product. Notice that even though the variable has a type of Product, the Type object that’s returned by the GetType() method represents a Book object.

The second example shows how you can code an if statement to test an object’s type. Here, I used the typeof operator to get a Type object for the Book class. Then, I compared this Type object to the Type object that’s returned by the GetType() method of the Product object.

The third example shows another way to test an object’s type. Here, after I called the Product object’s GetType() method, I used the Name property to get the name of the resulting Type object. Then, I compared that name to the name that’s returned by the nameof operator of the Book class. Note that you could also compare the name of the Product object to a string literal like this:

```
if (p.GetType().Name == "Book")
```

The advantage of using the nameof operator, though, is that the compiler can check that the type is valid. In addition, if you ever change the name of the type, you can use refactoring to change all occurrences of the type name.

Although this example only shows how to use the nameof operator to get the name of a type, you should know that you can also use it to get the name of any variable or member. For more information, see the Visual Studio documentation for this operator.

Remember from chapter 12 that you can also use pattern matching with C# 7.0 and later to test an object’s type. If you need to get information about a type, though, you’ll need to use the members of the Type class as shown in this figure.
