## How to create an Entity Data Model

In the topics that follow, you’ll learn how to create an Entity Data Model. But first, you need to know how the Entity Framework works and where the Entity Data Model fits into that framework.

## How Entity Framework Core works

Entity Framework (EF) Core is an Object Relational Mapping (ORM) framework that allows you to map the objects of an application to a database. Its goal is to address the mismatch that often exists between the tabular structure of a relational database and the objects used in an application. To resolve this problem, the Entity Framework uses an Entity Data Model that maps the conceptual model of the objects used by the application to the relational model of the database.

Figure 20-1 shows the basic components of the Entity Framework. As you can see, the two key components are Object Services and the EntityClient data provider. These components work together to manage the transfer of data to and from the ADO.NET data provider, which accesses the database.

When you use Entity Framework, you use queries to retrieve data from a database. However, these queries are executed against a conceptual model that is part of an Entity Data Model. This conceptual model defines the objects, or entities, used by the application and the relationships between those entities. The Entity Data Model also includes a storage model that describes the structure of the objects in the database. Finally, the Entity Data Model defines the mappings between the conceptual model and the storage model.

The Entity Framework sits between the application and the database. It translates queries into a form that the database understands, and it translates the data that’s returned from the database into the objects that are used by the application. It also tracks any changes that are made to those objects and provides for submitting those changes to the database.

Once a conceptual model has been created, you can query the data in several ways. First, you can use LINQ to Entities. Second, you can use Entity SQL, which works by using a dialect of SQL that’s not specific to the database. Third, you can use query builder methods. These queries are like the method-based queries you use with LINQ, but they use Entity SQL. In this chapter, you’ll learn how to use LINQ to Entities.

It’s important to understand that because the Entity Framework has abstracted away the details of the underlying data source, you query the objects in the conceptual model, not the database itself. In fact, once the mappings have been set up, you don’t need to consider how the underlying data source is configured. Instead, you work with the objects and properties that represent the tables and columns of the database.
