```csharp
Product p1 = new Product("C#", "Murach's C#", 57.50m);
```

## Code that copies a structure and changes a value

```csharp
Product product = new Product("C#", "Murach's C#", 57.50m);
Product copy = product;
copy.Price = 59.50m;
```

Description

- When you declare a variable with a structure type, an instance of that structure is created. If you don’t use the new keyword to create the instance, the instance variables aren’t initialized.
- To create an instance of a structure and initialize its instance variables to default values, you use the default constructor with the new keyword.
- To create an instance of a structure by calling a constructor that accepts parameters, you must use the new keyword.
- You can’t call any of the properties or methods of a structure until you initialize all of its instance variables.
- You can use the assignment operator (=) to create a copy of a structure, just as you would create a copy of any value type.
- Unlike classes, structures can’t be inherited by other classes. For more information about how inheritance works, please see chapter 14.

## How to create and use a record

Figure 12-26 shows the syntax for creating a record. This syntax is similar to the syntax for creating a class or structure. A record can have all the same types of members as a class or structure, including fields, properties, methods, and events. Like classes but unlike structures, records support inheritance.

The first example in this figure shows a Product record. This is similar to the Product class and Product structure examples presented earlier in this chapter. This record defines three properties, a constructor that sets the values of these properties, and a public method named GetDisplayText().

Like a class, a record defines a reference type. However, a record handles equality comparisons like a structure. In other words, the values of each property of a record are compared. If they’re all the same, the comparison returns true. Otherwise, the comparison returns false. In the next chapter, you’ll learn how an object that’s created from a class handles comparisons. For now, you just need to know that, by default, the Equals() method of a record works differently than the Equals() method of an object that’s created from a class.

The second code example in this figure demonstrates how this works. Here, two records whose properties contain the same values are stored in variables named p1 and p2. As a result, when the first Equals() method compares the two variables, it returns true. However, when the code changes the Price property of the p2 record, the values stored in the properties of the two variables no longer match. So when the second Equals() method compares the two variables, it returns false.

You can also create a record that contains only read-only properties, as shown by the second syntax in this figure. This is similar to the read-only structure you saw in figure 12-24, except that a read-only record can’t contain methods. To create a read-only record, you pass a list of properties to a constructor-like statement. Note that because this is a statement, it ends with a semicolon.

As you saw in the previous figure, you can make a copy of a structure by assigning it to a new variable. However, this doesn’t work for reference types. That’s because the variable for a reference type stores a reference to the object, not the object itself. Because of that, if you copy the variable to another variable, both variables refer to the same object. Then, if you use one variable to change a property, that change is reflected by the other variable too.

As a result, to copy a reference type, you need to create a new instance of the object and then assign the property values of the original object to the new object. The last example in this figure shows two ways to do that. First, you can assign the original object’s values to the copy, and you can change any values you want. This works with classes or records. Second, you can use the with keyword with a set of braces that includes the values for any properties you want to change. In this figure, for example, the last statement creates a copy of the Product object but changes the value of the Price property. Or, if you want to make a copy of the object without changing any properties, you can leave the braces empty. This works only with records.

## The syntax for creating a record (C# 9.0 and later)

```csharp
public record RecordName
{
    record members...
}
```

## A Product record

```csharp
public record Product
{
    public Product(string code, string description, decimal price) {...}

    public string Code { get; set; }
    public string Description { get; set; }
    public decimal Price { get; set; }

    public string GetDisplayText(string sep) =>
        Code + sep + Price.ToString("C") + sep + Description;
}
```

## Code that creates and compares two record instances

```csharp
Product p1 = new Product("C#", "Murach's C#", 57.50m);
Product p2 = new Product("C#", "Murach's C#", 57.50m);
bool isEqual = p1.Equals(p2);              // isEqual is true

p2.Price = 59.50m;
isEqual = p1.Equals(p2);                    // isEqual is false
```

## By passing the values of the original to the constructor of the copy

```csharp
Product copy1 = new Product(product.Code, product.Description, 59.50m);
```

## By using the with keyword

```csharp
Product copy2 = product with { Price = 59.50m };
```

Description

- A *record* is a reference type like a class. Unlike a class, a record’s Equals() method compares the values of its properties. This works like a structure.
- A record can contain the same types of members as a class, it can be inherited, and you can create an instance of a record with an object initializer.
- You can create a record that only contains read-only properties by passing a list of properties to the record, but you can’t use an object initializer with this type of record.
- You can use the *with* keyword to copy a record and change one or more property values.

## Perspective

At this point, you may be wondering why you should go to the extra effort of dividing an application into classes. The answer is twofold. First, dividing the code into classes makes it easier to use the code in two or more applications. For example, any application that needs to work with the data in the Products file can use the Product and ProductDB classes. Second, using classes helps you separate the business logic and database processing of an application from the user interface. That can simplify the development of the application and make it easier to maintain and enhance later.

Now that you’ve had this introduction to the use of classes, you can continue in two different ways. If you already feel comfortable with the use of classes, you can read the next four chapters in this section to learn more about object-oriented programming. That will give you the background you need for understanding how the .NET classes work and for creating complex classes of your own.

On the other hand, if you’re new to programming and the use of classes, you may want to skip to section 4 or 5 where you’ll see how business classes are used in other applications. As you will see in the chapters in those sections, this chapter has already given you the skills that you need for developing most business classes and applications. Then, when you’re more comfortable with the use of classes, you can return to the last four chapters in this section.
