# How instantiation works

The process of creating an object from a class is called *instantiation*. Figure 12-4 describes how instantiation works. Here, you can see two *instances* of the Product class. Each instance represents a different Product object. Because both instances were created from the same class, they both have the same properties. However, the instances have distinct values for each property. For example, the value of the Code property for the product1 object is C#, but the value of the Code property for the product2 object is ASPMVC.

The first code example in this figure shows how you can create these two object instances. Here, the first line of code declares two variables named product1 and product2 that have a type of Product. Then, the next two lines create Product objects. To do that, they use the new keyword, followed by the name of the class and the values that will be passed to the constructor and used to initialize the objects.

The second code example assumes that the Product class doesn’t have a constructor that accepts the code, description, and price. Instead, the first statement creates an instance of the class by calling its default constructor. Then, the next three statements manually assign values to the object’s properties.

The third code example shows how to create the same object instance using an *object initializer*. An object initializer lets you create an instance of an object and assign values to it without explicitly calling a constructor. To do that, you follow the class name with a list enclosed in braces that specifies the names of the properties you want to initialize and the values you want to assign to those properties. This is an improvement over the second example because it results in code that’s shorter and easier to read.

If you’re working with existing code that doesn’t use object initializers and you’re using Visual Studio 2017 or later, you can use refactoring to modify the code so it does use object initializers. To do that, place the cursor in the statement that creates the object, press Ctrl + period (.), and select “Object Initialization can be Simplified” from the Quick Actions menu.

The fourth code example shows three ways to declare and create an object in a single statement. Here, the first statement explicitly declares the Product type on the left side of the assignment statement. Then, the second statement uses the var keyword to let the compiler determine that the variable is of the Product type. This technique is known as implicit typing, and it can make your code shorter, especially if you’re working with classes that have long names. With C# 9.0 and later, you don’t need to code the type after the new keyword if the compiler can determine the type from the surrounding code. In this case, the compiler can determine that the variable is of the Product type. The main advantage of this technique is that it makes your code shorter.

At this point, it’s important to realize that a class defines a *reference type*. That means that the variable that’s used to access an object contains the address of the memory location where the object is stored, not the object itself. In other words, the product1 variable holds a *reference* to a Product object, not an actual Product object.
