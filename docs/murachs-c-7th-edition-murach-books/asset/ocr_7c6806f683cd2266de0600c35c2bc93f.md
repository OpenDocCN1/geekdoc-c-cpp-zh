Page 2 presents the code for the Click event of the Add Customer button. First, this code displays the Add Customer version of the Add/Modify Customer form. That way, the user can enter the data for the new customer. Then, if the customer is added successfully, the data entered in the Add/Modify Customer form is retrieved and passed to the AddCustomer() method of the CustomerDB class. Finally, the new customer is displayed on the Customer Maintenance form. First, though, the GetState() method is called to load the related state data for the customer.

Page 3 presents the code for the Click event of the Modify Customer button. First, this code calls the CloneCustomer() method to create a Customer object that contains the original values for the customer. Then, it displays the Modify Customer version of the Add/Modify Customer form. If the customer is modified successfully, the data entered in the Add/Modify Customer form is retrieved and the old and new customers are passed to the UpdateCustomer() method of the CustomerDB class. What happens next depends on the return value of that method. If it returns true, the update was successful and the new data is displayed in the Customer Maintenance form. Otherwise, a concurrency error occurred. Then, the HandleConcurrencyConflict() method that’s shown on page 4 is called.

Pages 3 and 4 present the code for the Click event of the Delete button. First, this code confirms the operation. If it’s confirmed, it calls the DeleteCustomer() method of the CustomerDB class to delete the customer. Once again, what happens next depends on the return value of that method. If it returns true, the delete was successful and the Customer Maintenance form is cleared. Otherwise, a concurrency error occurred. Then, the HandleConcurrencyConflict() method is called.

Page 4 presents the code for the HandleConcurrencyConflict() method. It starts by calling the GetCustomer() method of the form to reload the customer. Then, it checks whether the customer variable is null. If so, the user is notified that the customer has been deleted by another user, and the form controls are cleared. Otherwise, the user is notified that the customer has been updated by another user, and the updated customer data is displayed for the user to review.

Page 4 also presents the HandleDatabaseError() and HandleGeneralError() methods. These methods are used to handle the exceptions that might be thrown by methods in the database classes.
