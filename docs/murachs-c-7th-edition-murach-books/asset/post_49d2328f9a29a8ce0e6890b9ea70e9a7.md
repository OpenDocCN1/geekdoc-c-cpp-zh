    public static Customer GetCustomer(int customerID)
    {
        Customer customer = null; // default return value
        string selectStatement =
            "SELECT CustomerID, Name, Address, City, State, ZipCode " +
            "FROM Customers " +
            "WHERE CustomerID = @CustomerID";
        using SqlConnection connection = new SqlConnection(
            MMABooksDB.ConnectionString);
        using SqlCommand command = new SqlCommand(
            selectStatement, connection);
        command.Parameters.AddWithValue("@CustomerID", customerID);
        connection.Open();

            CommandBehavior.SingleRow & CommandBehavior.CloseConnection);

        {
            customer = new Customer {
                CustomerId = (int)reader["CustomerID"],
                Name = reader["Name"].ToString(),
                Address = reader["Address"].ToString(),
                City = reader["City"].ToString(),
                StateCode = reader["State"].ToString(),
                ZipCode = reader["ZipCode"].ToString()
            };
        }
        return customer;
    }

After the command for the INSERT statement is created, the parameters are added to the Parameters collection of the command. Then, the connection is opened and the ExecuteNonQuery() method of the command object is executed. If a SQL Server exception occurs, a SqlException object is thrown. You could catch and handle that exception here by coding the ExecuteNonQuery() method within a try-catch statement that catches SQL Server exceptions. Or, you can let any exceptions be handled by the calling method, which is the approach taken by this application.

After executing a command, this code checks the value that’s returned to determine if any rows in the database were affected. If so, the insert was successful. In that case, the code assigns a SELECT statement that retrieves the ID of the customer that was just added to the CommandText property. Then, this new statement is executed using the ExecuteScalar() method of the existing command. Next, this customer ID is assigned to the CustomerId property of the Customer object that was passed to the method.

The UpdateCustomer() method receives two arguments: a Customer object named oldCustomer that contains the original data for the customer to be updated, and another Customer object named newCustomer that supplies the updated values for the customer. The properties of these objects are used to set the values of the parameters defined by the UPDATE statement associated with the command object. Notice that the properties of the oldCustomer object are assigned to parameters in the WHERE clause of the UPDATE statement. That way, the UPDATE statement will update a row only if none of the customer columns have been changed since the customer was retrieved.

After the parameter values are set, the UpdateCustomer() method uses the ExecuteNonQuery() method to execute the UPDATE statement. Then, the value that’s returned by the ExecuteNonQuery() method is tested to determine whether the update was successful. If so, it returns true. Otherwise, it probably means that the customer has been modified or deleted by another user. In that case, this method returns false.

public static bool UpdateCustomer(Customer oldCustomer, Customer newCustomer)
{
    string updateStatement =
        "UPDATE Customers SET " +
        "Name = @NewName, " +
        "Address = @NewAddress, " +
        "City = @NewCity, " +
        "State = @NewState, " +
        "ZipCode = @NewZipCode " +
        "WHERE CustomerID = @OldCustomerID " +
        "AND Name = @OldName " +
        "AND Address = @OldAddress " +
        "AND City = @OldCity " +
        "AND State = @OldState " +
        "AND ZipCode = @OldZipCode";
    using SqlConnection connection = new SqlConnection(
        MMABooksDB.ConnectionString);
    using SqlCommand command = new SqlCommand(
        updateStatement, connection);
    command.Parameters.AddWithValue("@NewName", newCustomer.Name);
    command.Parameters.AddWithValue("@NewAddress", newCustomer.Address);
    command.Parameters.AddWithValue("@NewCity", newCustomer.City);
    command.Parameters.AddWithValue("@NewState", newCustomer.StateCode);
    command.Parameters.AddWithValue("@NewZipCode", newCustomer.ZipCode);
    command.Parameters.AddWithValue(
        "@OldCustomerID", oldCustomer.CustomerId);
    command.Parameters.AddWithValue("@OldName", oldCustomer.Name);
    command.Parameters.AddWithValue("@OldAddress", oldCustomer.Address);
    command.Parameters.AddWithValue("@OldCity", oldCustomer.City);
    command.Parameters.AddWithValue("@OldState", oldCustomer.StateCode);
    command.Parameters.AddWithValue("@OldZipCode", oldCustomer.ZipCode);
    connection.Open();
    int count = command.ExecuteNonQuery();

    return (count > 0);
}

The DeleteCustomer() method receives a Customer object as an argument. This method implements concurrency checking using the same technique as the UpdateCustomer() method. ## The code for the StateDB class

Figure 21-13 shows the code for the StateDB class. This class contains two methods named GetStates() and GetState().

The GetStates() method returns a generic List<> object that contains one State object for each of the rows in the States table, sorted by state name. To get this list, it creates a command with a SELECT statement that retrieves the appropriate data. Then, it executes this command to create a data reader that can be used to read each state. Next, this method uses this reader to read each row in the table, create a State object for each row, and add each State object to the List<> object. Finally, the method returns the list of State objects.

The GetState() method accepts a state code as a parameter and returns a single State object. To get this object, it creates a command with a SELECT statement and a parameter for the state code. Then, it executes this command to create a data reader that can be used to read the selected state. Since this command only retrieves a single row, it adds the SingleRow command behavior to the CloseConnection behavior. Next, it uses the reader to read the single row, create a State object for it, and return that State object.
