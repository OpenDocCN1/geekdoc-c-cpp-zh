# # How to create and use a record

Figure 12-26 shows the syntax for creating a record. This syntax is similar to the syntax for creating a class or structure. A record can have all the same types of members as a class or structure, including fields, properties, methods, and events. Like classes but unlike structures, records support inheritance.

The first example in this figure shows a Product record. This is similar to the Product class and Product structure examples presented earlier in this chapter. This record defines three properties, a constructor that sets the values of these properties, and a public method named GetDisplayText().

Like a class, a record defines a reference type. However, a record handles equality comparisons like a structure. In other words, the values of each property of a record are compared. If they’re all the same, the comparison returns true. Otherwise, the comparison returns false. In the next chapter, you’ll learn how an object that’s created from a class handles comparisons. For now, you just need to know that, by default, the Equals() method of a record works differently than the Equals() method of an object that’s created from a class.

The second code example in this figure demonstrates how this works. Here, two records whose properties contain the same values are stored in variables named p1 and p2. As a result, when the first Equals() method compares the two variables, it returns true. However, when the code changes the Price property of the p2 record, the values stored in the properties of the two variables no longer match. So when the second Equals() method compares the two variables, it returns false.

You can also create a record that contains only read-only properties, as shown by the second syntax in this figure. This is similar to the read-only structure you saw in figure 12-24, except that a read-only record can’t contain methods. To create a read-only record, you pass a list of properties to a constructor-like statement. Note that because this is a statement, it ends with a semicolon.

As you saw in the previous figure, you can make a copy of a structure by assigning it to a new variable. However, this doesn’t work for reference types. That’s because the variable for a reference type stores a reference to the object, not the object itself. Because of that, if you copy the variable to another variable, both variables refer to the same object. Then, if you use one variable to change a property, that change is reflected by the other variable too.

As a result, to copy a reference type, you need to create a new instance of the object and then assign the property values of the original object to the new object. The last example in this figure shows two ways to do that. First, you can assign the original object’s values to the copy, and you can change any values you want. This works with classes or records. Second, you can use the with keyword with a set of braces that includes the values for any properties you want to change. In this figure, for example, the last statement creates a copy of the Product object but changes the value of the Price property. Or, if you want to make a copy of the object without changing any properties, you can leave the braces empty. This works only with records.
