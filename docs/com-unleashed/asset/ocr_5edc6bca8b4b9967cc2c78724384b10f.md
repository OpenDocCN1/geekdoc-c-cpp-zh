There are lots of ways to design a callback I/O sequence. A popular approach is to kick off the I/O from a thread's entry point and then perpetuate the I/O by making the next I/O request from within the I/O completion routine itself.

Listing 25.13 shows a sample application that uses a callback routine to receive incoming MSMQ messages. This is one of the several Pong programs. I introduced the Ping application earlier in the chapter as a means to explore message acknowledgment and delivery timeouts. The various Pong applications pretty much only oblige the Ping side by receiving messages. The main thread creates a worker thread to handle the I/O work. When instructed to quit, the main thread signals an event to notify the waiting worker thread that it's time to go.
