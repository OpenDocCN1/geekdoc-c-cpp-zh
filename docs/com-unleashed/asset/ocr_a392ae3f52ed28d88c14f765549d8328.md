Overlapped structure and callback function fields are used for asynchronous behavior, which we'll take a look at in the next chapter.

The next `MQReceiveMessage()` call parameter field of interest is the action field. Table 24.4 lists the available action options.

| Receive Action | Receive Behavior |
|---|---|
| `MQ_ACTION_RECEIVE` | Reads the current message and removes it |
| `MQ_ACTION_PEEK_CURRENT` | Reads the current message without removing it |
| `MQ_ACTION_PEEK_NEXT` | Reads the next message without removing it |

Because a queue might have more than one message available, MSMQ provides cursors that enable an application to scan through the queue, much like cursors used in database programming. The example will set the `MQReceiveMessage()` cursor handle field to `NULL`, thus limiting you to reading from the front of the queue. Because you do not require a transaction, the transaction object is also set to `NULL`.
