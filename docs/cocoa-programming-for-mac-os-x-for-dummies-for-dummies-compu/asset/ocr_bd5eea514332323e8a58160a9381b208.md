# Instantiating an object

After you create a class, you'll want to use it as an object. When you want to create an Objective-C object, you send the alloc message to the class, like so:

```
MyClass* anInstance = [MyClass alloc];
```

The alloc allocates memory and creates the class. An instantiated object must also be initialized. You do so by sending the init method to the instance, like this:

```
[anInstance init];
```

Because alloc and init are both required for a generic instantiation, it's customary to embed them in one statement:

```
MyClass * anInstance = [[MyClass alloc] init];
```

Then, you're free to work with the object (anInstance) as you need. You could send the drawString@"hello" to the instance:

```
[anInstance drawString@"hello" atThisXPosition:10 atThisYPosition:6];
```

Because you used alloc to create the instance, you must free up that memory using release:

```
[anInstance release];
```

# Managing memory

Recent versions of Cocoa provide support for garbage collection, but historically Cocoa hadn't had garbage collection. Garbage collection dynamically frees memory that you've allocated for objects. This is a newer feature and because so many sources of sample code do the old way, it's best that you understand management in Cocoa without garbage collection.

Cocoa tracks memory by way of reference counting. This is a simple counter that runs behind the scenes, keeping track of how many objects have allocated memory and how many objects have released memory. When you create an object with alloc, you increase the reference count by one. When you send a release message to the object, you decrease the count by one. The name of the game is that your reference count could end up being zero after you finish using an object. If the count is greater than zero, you're leaking memory.
