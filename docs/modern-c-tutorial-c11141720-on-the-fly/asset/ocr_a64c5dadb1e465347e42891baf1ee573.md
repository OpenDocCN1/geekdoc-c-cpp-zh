```
const std::string& lv2 = lv1 + lv1; // legal, const lvalue reference can extend temp variable's
lv2 += "Test"; // illegal, const ref can't be modified

```

```
std::string& rv2 = lv1 + lv2; // legal, rvalue reference for extend lifecycle
rv2 += "string"; // illegal, non-const reference can be modified
std::cout << rv2 << std::endl; // string,string,string,string
```

```
reference(rv2); // output: lvalue
```

```
}
```

rv2 refers to an rvalue, but since it is a reference, rv2 is still an lvalue.

Note that there is a very interesting historical issue, let's look at the following code:

```
#include <iostream>

int main() {
    int &a = std::move(1); // illegal, non-const lvalue reference cannot ref rvalue
    const int &b = std::move(1); // legal, const lvalue reference can

    std::cout << b << std::endl;
}
```

The first question, why not non-linear references to bind to non-values? This is because there is a logic error in this approach:

```
void increase(int &v) {
    v++;
}
```

```
void foo() {
    double s = i;
    increase(s);
}
```

Since int& can't reference a parameter of type double, you must generate a temporary value to hold the value of s. Thus, when increase() modifies this temporary value, s itself is not modified after the call is completed.
