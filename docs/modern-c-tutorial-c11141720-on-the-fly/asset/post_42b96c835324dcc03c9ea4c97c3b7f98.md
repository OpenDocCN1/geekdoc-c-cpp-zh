
```cpp
int foo(int para) {
  return para;
}
```

```cpp
int main() {
  // std::function wraps a function that take int parameter and returns int value
  std::function<int(int)> func = foo;

  int important = 10;
  std::function<int(int)> func2 = [&](int value) -> int {
    return 1+value+important;
  };

  std::cout << func(10) << std::endl;
  std::cout << func2(10) << std::endl;

```

std::bind and std::placeholder is used to bind the parameters of the function call. It solves the requirement that we may not be able to get all the parameters of a function at one time. Through this function, part of the call parameters are bound to the function in advance to become a new object, and then complete the call after the parameters are complete. e.g:

```cpp
int foo(int a, int b, int c) {
  //
}
int main() {
  // bind parameter 1, 2 on function foo, and use std::placeholders::_1 as placeholder
  // for the first parameter.
  auto bindFoo = std::bind(foo, std::placeholders::_1, 1,2);
  // when call bindFoo, we only need one param left
  bindFoo();
}
```

## 3.3 rvalue Reference

rvalue references are one of the important features introduced by C++11 that are synonymous with Lambda expressions. Its introduction solves a large number of historical issues in C++. Eliminating extra overhead such as std::vector, std::string, and making the function object container std::function possible.

### lvalue, rvalue, prvalue, xvalue

To understand what the rvalue reference is all about, you must have a clear understanding of the lvalue and the rvalue.

lvalue, left value, as the name implies, the value to the left of the assignment symbol. To be precise, an lvalue is a persistent object that still exists after an expression (not necessarily an assignment expression).

Rvalue, right value, the value on the right refers to the temporary object that no longer exists after the expression ends.

In C++11, in order to introduce powerful rvalue references, the concept of rvalue values is further divided into: prvalue, and xvalue.

prvalue, pure rvalue, purely rvalue, either purely such as 10, true; either the result of the evaluation is equivalent to a literal or anonymous temporary, for example 1+2. Temporary variables returned by non-references, temporary variables generated by operation expressions, original literals, and Lambda expressions are all pure rvalue values.

Note that string literal becomes rvalue in a class, and remains an lvalue in other cases (e.g., in a function)

```cpp
class Foo {
  const char*& right = "this is a rvalue";

public:
  void bar() {
    right = "still rvalue"; // the string literal is a rvalue
  }
};

int main() {
  const char* const &left = "this is an lvalue"; // the string literal is an lvalue
}
```

xvalue, expiring rvalue is the concept proposed by C++11 to introduce rvalue references (so in traditional C++, prvalue and rvalue are the same concept), a value that is destroyed but can be moved.

It would be hard to understand the xvalue, let's look at the code like this:

```cpp
std::vector<int> foo() {
  std::vector<int> temp = {1, 2, 3, 4};
  return temp;
}

std::vector<int> v = foo();
```

In code, as far the traditional understanding is concerned, the return value temp of the function is internally created and assigned to v, whereas v gets this object, the entire temp is copied. And then destroy temp, if this temp is very large, which will cause a lot of extra overhead (this is the problem that traditional C++ has been criticized for).

In the last line, v is the lvalue, and the value returned by foo() is the rvalue (which is also pure rvalue). However, v can be caught by other variables, and the return value by foo() is used as a temporary value. Once v, it will be destroyed, and cannot be obtained or modified. The xvalue defines a behavior which temporary values can be identified while still being able to be moved. After C++11, the compiler does some work for us, where lvalue is subjected to this implicit rvalue conversion, equivalent to static_cast<std::vector<int>&&>(temp), where here moves the value returned locally.

### rvalue reference and lvalue reference

To create an xvalue, you need the declaration of rvalue reference: T&&, where T is the type. The statement of rvalue reference extends the lifecycle of this temporary value and as long as the variable is alive, it will continue to. C++11 provides std::move method to unconditionally convert lvalue to rvalues. With it we can get a temporary rvalue object, for example:

```cpp
#include <iostream>
#include <string>

void reference(std::string& str) {
    std::cout << "lvalue" << std::endl;
}
void reference(std::string&& str) {
    std::cout << "rvalue" << std::endl;
}

int main() {
    std::string l1 = "string"; // l1 is a lvalue
    std::string&& r1 = l1; // illegal, rvalue can't ref to lvalue
    std::string&& rv1 = std::move(l1); // legal, std::move can convert lvalue to rvalue
    std::cout << rv1 << std::endl;

    const std::string& lv2 = l1; // legal, const lvalue reference can extend variable's
    lv2 += "Test"; // illegal, const ref can't be modified
    std::cout << lv2 << std::endl;

    std::string& rv2 = l1 + l2; // legal, rvalue reference extends lifecycle
    rv2 += "string"; // illegal, non-const reference can be modified
    std::cout << rv2 << std::endl;

    reference(rv2); // output: lvalue
    return 0;
}
```

rv2 refers to an rvalue, but since it is a reference, rv2 is still an lvalue. Note that there is a very interesting historical issue, let's look at the following code:

```cpp
#include <iostream>

int main() {
    int &a = std::move(1); // illegal, non-const lvalue reference cannot ref rvalue
    const int &b = std::move(1); // legal, const lvalue reference can
    std::cout << b << std::endl;
}
```

The first question, why not non-linear references bind to non-values? This is because there is logic error in this approach:

```cpp
void increase(int &v) {
    v++;
}

void foo() {
    double s = i;
    increase(s);
}
```

Since int& can't reference a parameter of type double, you must generate a temporary value to hold the value of s. Thus, when increase() modifies this temporary value, s itself is not modified after the call is completed.

The second question, why do constant references allow binding to non-values? The reason is because Fortran needs it.

Traditional C++ has designed the concept of copy/copy for class objects through copy constructors and assignment operators, in order to implement the management of resources. The caller must use the method of copying and then destroying first, otherwise you need to implement the interface of the move object yourself. Moving your home directly to your new home instead of copying everything (buying) to your new home. Throwing away (destroying) all the originals is a very anti-human thing.

Traditional C++ does not distinguish between the concepts of "move" and "copy", resulting in a large amount of data copying, wasting time and space. The appearance of rvalue references solves the confusion of these cases, for example:

```cpp
#include <iostream>
class A {
public:
    int *pointer;
    A():pointer(new int()) {
        std::cout << "construct" << pointer << std::endl;
    }
    A(A& a):pointer(new int(*a.pointer)) {
        std::cout << "copy" << pointer << std::endl;
        // meaningless object copy
    }
    A(A&& a):pointer(a.pointer) {
        a.pointer = nullptr;
        std::cout << "move" << pointer << std::endl;
    }
    ~A() {
        std::cout << "destruct" << pointer << std::endl;
        delete pointer;
    }
};

// avoid compiler optimization
A return_rvalue(bool test) {
    A a,b;
    if(test) return a; // equal to static_cast<A>(a);
    else return b; // equal to static_cast<A>(b);
}
int main() {
    A obj = return_rvalue(false);
    std::cout << "obj:" << obj.pointer << std::endl;
    std::cout << obj.pointer << std::endl;
    std::cout << *obj.pointer << std::endl;
    return 0;
}
```
