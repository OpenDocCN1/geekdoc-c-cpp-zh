# 1.1 Deprecated Features

Before learning modern C++, let's take a look at the main features that have been deprecated
C++11:

> **Note:** Deprecated is not completely unusable, it is only intended to imply that features will disappear from future standards and should be avoided. However, the deprecated features are still part of the standard library, and many of the features are actually “permanently” reserved for compatibility reasons.

+   * The string literal is no longer allowed to be assigned to a char *. If you need to assign and initialize a char * with a string literal, you should use char * or auto.

```
char *str = "hello world"; // A deprecation warning will appear
```

+   * C++98 exception description, unexpected_handler, set_unexpected() and other related features are deprecated and should use noexcept.

+   * auto_ptr is deprecated and unique_ptr should be used.

+   * register keyword is deprecated and can be used but longer has any practical meaning.

+   * The ++ operation has a destructor, the properties for which it generates copy constructors and copy assignment operators are deprecated.

+   * C language type conversion is deprecated (ie using convert_type)) before variables, static_cast, reinterpret_cast, const_cast should be used for type conversion.

+   * In particular, some of the C standard libraries are deprecated in the latest C++17 standard, such as <complex>, <cstdalign>, <cstdlib> and <cmath>

+   * and many more

There are other features such as parameter binding (C++11 provides std::bind and std::function), export, and etc. are also deprecated. These features mentioned above If you have never used or heard of it, please don't try to understand them. You should move closer to the new standard and learn new features directly. After all, technology is moving forward.
