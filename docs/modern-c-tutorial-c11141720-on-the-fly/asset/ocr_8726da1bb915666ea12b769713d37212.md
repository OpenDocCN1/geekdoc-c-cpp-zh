In code, as far the traditional understanding is concerned, the return value temp of the function is internally created and assigned to v, whereas v gets this object, the entire temp is copied. And then destroy temp, if this temp is very large, which will cause a lot of extra overhead (this is the problem that traditional C++ has been criticized for). In the last line, v is the lvalue, and the value returned by foo() is the rvalue (which is also a pure rvalue). However, v can be caught by other variables, and the return value generated by foo() is used as a temporary value. Once v, it will be destroyed immediately, and cannot be obtained or modified. The xvalue defines a behavior which temporary values can be identified while still being able to be moved.

After C++11, the compiler does some work for us, where the lvalue is subjected to this implicit rvalue conversion, equivalent to static_cast<std::vector<int>&&>(temp), where here v moves the value returned by foo locally. This is the semantics we will mention later.

# rvalue reference and lvalue reference

To create an xvalue, you need the declaration of the rvalue reference: T&&, where T is the type. The statement of the rvalue reference extends the lifecycle of this temporary value, and as long as the variable is alive, the xvalue will continue to.

C++11 provides the std::move method to unconditionally convert lvalue parameters to rvalues. With it we can get a temporary rvalue object, for example:

```
#include <iostream>
#include <string>

void reference(std::string& str) {
    std::cout << "lvalue" << std::endl;
}
void reference(std::string&& str) {
    std::cout << "rvalue" << std::endl;
}

int main() {
    std::string l1 = "string"; // l1 is a lvalue
    std::string&& r1 = l1; // illegal, rvalue can't ref to lvalue
    std::string&& rv1 = std::move(l1); // legal, std::move can convert lvalue to rvalue
    std::cout << rv1 << std::endl; // string,
```
