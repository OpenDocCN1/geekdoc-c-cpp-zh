### decltype(auto)

decltype(auto) is a slightly more complicated use of C++14.

To understand it you know the concept of parameter forwarding in C++, which we will cover in detail in the Language Runtime Hardening chapter, and you can come back to the contents of this section later.

In simple terms, decltype(auto) is mainly used to derive the type of a forwarding function or package, which does not require us to explicitly specify the parameter expression of decltype. Consider the following example, when we need to wrap the following functions:

```cpp
std::string lookup1();
std::string& lookup2();
```

```cpp
In C++11:
std::string look_up_a_string_1() {
    return lookup1();
}
```

```cpp
std::string& look_up_a_string_2() {
    return lookup2();
}
```

With decltype(auto), we can let the compiler do this annoying parameter forwarding:

```cpp
decltype(auto) look_up_a_string_1() {
    return lookup1();
}
decltype(auto) look_up_a_string_2() {
    return lookup2();
}
```

### if constexpr

As we saw at the beginning of this chapter, we know that C++11 introduces the constexpr keyword, which compiles expressions or functions into constant results. A natural idea is that if we introduce this feature into the conditional judgment, let the code complete the branch judgment at compile time, can it make the program more efficient? C++17 introduces the constexpr keyword into the if statement, allowing you to declare the condition of an expression in your code. Consider the following code:

```cpp
#include <iostream>

template<typename T>
auto print_type_info(const T& t) {
    if constexpr(std::is_integral<T>::value) {
        return t + 1;
    } else {
        return t + 0.001;
    }
}
int main() {
    std::cout << print_type_info(5) << std::endl;
    std::cout << print_type_info(3.14) << std::endl;
}
```

At compile time, the actual code will behave as:

```cpp
int print_type_info(const int& t) {
    return t + 1;
}
double print_type_info(const double& t) {
    return t + 0.001;
}
int main() {
    std::cout << print_type_info(5) << std::endl;
    std::cout << print_type_info(3.14) << std::endl;
}
```

C++ templates have always been a special art of the language, and templates can even be used independently as a new language. The philosophy of template is to throw all the problems that can be processed at compile time, and only deal with those at runtime, so as to greatly optimize the performance. Therefore, templates are also regarded as one of the black magic of C++.

### External templates

In traditional C++, templates are instantiated by the compiler only when they are used. In other words, as long as a fully defined template is encountered in each compilation unit (file), it will be instantiated. This results in increase in compile time due to repeated instantiations. We have no way to tell the compiler not to trigger the instantiation. To this end, C++11 introduces external template that extends the syntax allowing us to explicitly tell the compiler when to instantiate a template:

```cpp
template class std::vector<bool>; // force instantiation
extern class std::vector<double>; // should not instantiation
```

In traditional C++, `>>` is always treated as a right shift operator. But actually we can easily write code for nested template:

```cpp
std::vector<std::vector<int>> matrix;
```

This is not compiled under the traditional C++ compiler, and C++11 starts with continuous brackets that become legal and can be compiled successfully. Even the following writing can be compiled:

```cpp
template<typename T>
class MagicType {
    T magic;
};

// in main function
std::vector<MagicType<bool>> v; // legal, but not recommended
```

### Type alias templates

Before you understand type alias template, you need to understand the difference between "template" and "type". Templates are used to generate types. In traditional C++, typedef can define a new name for the type, but there is no way to define a new name for the template because the template is not a type. E.g.:

```cpp
template<typename T, typename U>
class MagicType {
    T data;
    U magic;
};

// not allowed
template<typename T> MagicType<std::vector<T>>;
```

C++11 uses using to introduce the alias syntax, and at the same time supports the same effect as traditional typedef. We usually use typedef to define an alias, but the definition syntax for aliases such as function pointers is different, which usually causes a degree of difficulty for direct reading.

```cpp
typedef int (*process)(void);
using NewProcess = int(*)(void);
template<typename T>
using TrueMagic = MagicType<std::vector<T>, std::string>;

int main() {
    TrueMagic m;
}
```

### Default template parameters

We may have defined an addition function:

```cpp
template<typename T, typename U, typename V>
auto add(T x, U y) -> decltype(x+y) {
    return x+y;
}
```

When used, it is found that to add, you must specify the type of its template parameters each time. A convenience is in C++11 to specify the default parameters of the template:

```cpp
template<typename T = int, typename U = int>
auto add(T x, U y) -> decltype(x+y) {
    return x+y;
}
// Usage: add(1, 2) or add<double>(1, 2.0) 
```

### Variadic templates

The template has always been one of C++’s unique black magic. In traditional C++, both a class template and a function template could only accept a fixed set of template parameters as specified; C++11 added a new representation, allowing any number of template parameters of any category, and there is no need to fix the number of parameters when defining:

```cpp
template<typename... Ts> class Magic;
```

The class Magic object can accept unrestricted number of typename as a formal parameter of the template, such as the following definition:

```cpp
class Magic<int,
    std::vector<int>,
    std::map<int, std::string>,
    std::vector<std::vector<int>>> darkMagic;
```

Since it is arbitrary, a template parameter with a number of 0 is also possible:

```cpp
class Magic<> nothing;
```

If you do not want to generate 0 template parameters, you can manually define at least one template parameter:

```cpp
template<typename Require, typename... Args> class Magic;
```

The variable length template parameter can also be directly adjusted to the template function. The printf function in the classical C can reach the call of an indefinite number of formal parameters, but is not class safe. In addition to the variable-length functions that define class safety, C++11 can also make print-like functions handle objects that are not self-contained. In addition to the use of ... in the template parameters to indicate the indefinite length of the template parameters, the function also uses the same representation to represent the indefinite length parameters, which provides a convenient means for us to simply write variable length parameter functions, such as:

```cpp
template<typename... Args>
void printf(const std::string &str, Args... args);
```

Then we define variable length template parameters, how to unpack the parameters?

First, we can use sizeof(...) to calculate the number of arguments:

```cpp
#include <iostream>
template<typename... Ts>
void magic(Ts... args) {
    std::cout << sizeof...(args) << std::endl;
}
```

We can pass any number of arguments to the magic function:

```cpp
magic(); // 0
magic(1); // 1
magic(1, ""); // 2
```
