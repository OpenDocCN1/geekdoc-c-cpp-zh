C# 的祖父是 C。C# 从 C 继承了其语法、许多关键字和运算符。C# 在 C++ 定义的对象模型基础上进行了构建和改进。如果你了解 C 或 C++，你会对 C# 有宾至如归的感觉。C# 和 Java 的关系比较复杂。如前所述，Java 同样源自 C 和 C++。它也共享 C/C++ 的语法和对象模型。与 Java 类似，C# 旨在生成可移植的代码，并且 C# 程序在安全、托管的运行时环境中执行。然而，C# 并非源自 Java。更确切地说，C# 和 Java 更像是表亲，拥有共同的世系，但在许多方面有所不同。不过，好消息是，如果你了解 Java，许多 C# 概念将会熟悉。另一方面，如果你以后需要学习 Java，你学到的许多有关 C# 的知识将会有帮助。

C# 包含许多创新特性，我们将在本书的课程中详细研究这些特性，但它一些最重要的特性与它对软件组件的内置支持有关。事实上，C# 被描述为一种面向组件的语言，因为它包含了对软件组件组合的基本支持。例如，C# 包含直接支持组件构成要素（如属性、方法和事件）的特性。然而，C# 在安全的混合语言环境中工作的能力也许是其最重要的面向组件的特性。

## C# 的演变

自 1.0 首次发布以来，C# 一直在快速发展。C# 1.0 发布后不久，微软发布了 1.1 版本。它包含许多细微的更改，但没有增加重要的特性。然而，随着 C# 2.0 的发布，情况发生了很大变化。这是 C# 生命周期中的一个分水岭事件，因为 2.0 版本包含了许多新特性，如泛型、分部类型和匿名方法，从根本上扩展了语言的威力、范围和疆域。2.0 版本稳固地将 C# 置于编程语言发展的前沿。它也证明了微软对该语言的长期承诺。

C# 的下一个主要版本是 3.0，而且（在撰写本文时）这是 C# 的当前版本。由于 C# 2.0 包含许多新特性，人们可能会预期 C# 的开发会有所放缓，以便让程序员有机会赶上，但事实并非如此。

借助 3.0 版本，微软再次将 C# 置于语言设计的前沿，这次包含了大量重新定义编程格局的创新特性。也许 C# 3.0 中两个最令人兴奋的新特性是语言集成查询（LINQ）和 lambda 表达式。LINQ 使你可以使用 C# 编程元素编写数据库查询。lambda 表达式经常用于 LINQ 表达式中。它们共同为 C# 编程增添了全新的维度。其他创新还包括隐式类型变量和扩展方法。由于本书基于 C# 3.0，因此涵盖了这些主要进展。

## C# 与 .NET

尽管 C# 是一门可以独立学习的语言，但它与其运行时环境 .NET Framework 有着特殊的关系。理由有两个。首先，C# 最初由微软设计，用于为 .NET Framework 创建代码。其次，C# 使用的库正是 .NET Framework 定义的库。因此，尽管可以将 C# 语言与 .NET 环境分开，但两者紧密相连。因此，对 .NET Framework 及其对 C# 的重要性有一个总体了解很重要。

简而言之，.NET Framework 定义了一个支持高度分布式、基于组件的应用程序开发和执行的环境。它使不同的编程语言能够协同工作，并为 Windows 平台提供了安全性、程序可移植性和通用编程模型。

就与 C# 的关系而言，.NET Framework 定义了两个主要元素。第一个是公共语言运行时。这是管理程序执行的运行时。在其他优点中，公共语言运行时是 .NET Framework 的一部分，它使程序可移植、支持混合语言编程并提供安全性。

第二个元素是 .NET 类库。这个库使你的程序能够访问运行时环境。例如，如果需要进行 I/O 操作，比如在屏幕上显示内容，你会使用 .NET 类库来完成。如果你是编程新手，“类”这个术语可能很陌生。虽然稍后会详细解释，但简要地说，类是一种面向对象的构造，用于组织程序。只要你的程序仅限于使用 .NET 类库定义的功能，你的程序就可以在任何支持 .NET 运行时框架的地方运行。由于 C# 自动使用 .NET 类库，C# 程序自然可以移植到每个 .NET 环境中。
