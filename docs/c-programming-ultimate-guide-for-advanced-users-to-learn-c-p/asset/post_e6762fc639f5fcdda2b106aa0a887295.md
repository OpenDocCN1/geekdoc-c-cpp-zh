
## Loading a Text File

Load content from an external file by calling the LoadFile method. LoadFile takes three forms, the simplest of which determines the file name of a file containing RTF formatting:

```csharp
richTextBox1.LoadFile("file.rtf");
```

A second overload of LoadFile has a RichTextBoxStreamType parameter that enables you to specify the kind of formatting the file contains. For instance, to load plain text, you could modify the LoadFile statement:

```csharp
richTextBox1.LoadFile("file.rtf", RichTextBoxStreamType.PlainText);
```

RichTextBoxStreamType is an enumeration defined in the System.Windows.Forms namespace. You should use the fully qualified name or ensure there is a using statement that refers to the System.Windows.Forms namespace.

## Saving a Text File

RichTextBox.SaveFile performs the symmetric action to LoadFile. SaveFile writes the contents of the RichTextBox control to an RTF or TXT file by calling SaveFile and passing a file name.

## Using the ZoomFactor

RichTextBox.ZoomFactor is an interesting property. With ZoomFactor you can specify a percentage increase in the size of the text. Setting ZoomFactor to 2 will double the size of the text, and .64 will reduce the size of the text by approximately half. Acceptable values are from .64 to 64, the latter being 64 times the normal size. This property is an amazing feature for applications supporting individuals with disabilities and for presentations. Assume, for instance, that you are displaying the contents of the RichTextBox on an overhead projector. Setting the ZoomFactor to increase text size will make it easier for your audience to see the contents in the RichTextBox control.

At last, we come to multithreading. Multithreading is a complex subject. There are several facets to multithreading, so we will confine our discussion of multithreading in this section to the way it was used to help implement the AssemblyViewer.

The AssemblyViewer uses a separate thread to display the Splash screen while the application is loaded. A luxury, no doubt, but what is the purpose of a splash screen if it is executed in a linear fashion? That is, while the splash screen is loading, no actual initialization happens, and I never liked letting the splash screen contain the initialization code. (You are likely to discover, however, that many splash screens do actually contain initialization code.)

In our example application, the splash screen is on its own thread. There are four different ways to simulate apparently asynchronous behavior in .NET. The Timer control and Application.Idle event provide event-driven synchronous behavior. Controls support the asynchronous BeginInvoke and EndInvoke. The ThreadPool class provides a pool of available threads, and the Thread class enables you to create and manage threads yourself.

The AssemblyViewer uses a thread from the ThreadPool class; hence, that is the aspect of threading presented here.

## ThreadPool Threading

The ThreadPool is a class that manages a pool of threads for you. Multithreading using threads in the ThreadPool is the same as creating a Thread object. However, your task is helped a bit, and grabbing a thread from the pool is often somewhat quicker than creating an instance of the Thread class because the pool probably has a thread waiting for you to give it work.

To use a thread in the ThreadPool, you simply give the ThreadPool some work to do as a delegate. In this example, the delegate will act as a method representing work for the thread to do. Every other part of threading is identical to creating a Thread object yourself. The most important thing to remember is that ThreadPool threads require the same amount of care as Thread instances, particularly with regard to Windows Forms controls. Windows Forms controls are not thread-safe; therefore, you should take additional care when interacting with Windows Forms controls from a thread.

### Queuing a Work Item in the ThreadPool

Delegates are critical to the point that event handlers don't work without them, and you can't use multithreading in any .NET language unless you understand delegates. To recap, a delegate contains the address of at least one method. Threading works by giving a thread a delegate containing methods representing work to be done by the thread.

In Listing 2-3, the static method Splash creates the Splash form with an Opacity of 0. When Form.Opacity is 0, the form is transparent; 1 represents an opaque form. With an Opacity value somewhere in the range of 0 and 1, you have a semi-transparent form. The Splash form is displayed transparently, and the thread will gradually increase the Opacity value until the form is opaque, at which point the thread is done.

The Show method is defined on lines 11 through 26 in Listing 2-3. This Show method gradually fades in the form by modifying the Opacity. Unfortunately, because Windows Forms controls are not thread-safe, the Opacity must be changed on the same thread as the one it lives on. The Show method is not on that thread.

The way we actually update the Opacity value is by calling the form's Invoke method. Invoke is thread-safe; Invoke marshals the delegate argument into the same thread as the thread that the calling object is on. (Again, without delegates, thread-safe threading would not be possible.)

Invoke requires a MethodInvoker delegate and executes the code inside the method used to initialize the delegate. The Increment method updates the Opacity value. The done field is used to indicate that the form is opaque. We lock the done field while we are updating it, preventing the thread running Show from checking the done value until it has been updated.
