## Using TimeSpan to Evaluate Time Differences

The TimeSpan structure is used to measure time spans as short as 100 nanoseconds, which are represented as one tick in a TimeSpan. TimeSpan values can be represented as positive and negative ranges of time expressed in terms of days, hours, minutes, seconds, and fractions of seconds. The string format d.hh:mm:ss.ff would show the days, hours, minutes, seconds, and parts of a second represented by a single TimeSpan. The largest unit of time represented by the TimeSpan is the day.

If the default string representation of the TimeSpan were acceptable, then we could use the TimeSpan.ToString() method, which would return the TimeSpan in hh:mm:ss format normally.

In case you perform an arithmetic operation on DateTime values, for instance subtracting one time from another, the operation will return a TimeSpan object.

## Summary

This section introduces the Broadcaster.Broadcast method. This is a method I defined for sending internal data to a single location, permitting listeners who need to know what is happening to tune into the broadcaster. For example, we could register the main form as a listener and show the status of tasks on the main form. The AssemblyViewer does precisely this; the main form has a status bar that is used to show the progress of the AssemblyManager during a load operation.

A class that implements IListener and registers with the Broadcaster is capable of receiving string messages sent to the Broadcaster. The class and the interface demonstrate a couple of notable methods, so we will look at each.

## Implementing the Broadcaster

The Broadcaster demonstrates the Singleton pattern. A Singleton is a class that you need to ensure has only one instance. Typically, this instance is used to represent the existence of a single resource, similar to a single printer. A Singleton class is created by making the constructor protected or private and providing access only through a static member. The Broadcaster does this through the internal, private Instance property.

Each public method in Broadcaster is static. When you invoke a public member in the Broadcaster (or any Singleton), the method references the read-only Instance property. The Instance property checks whether the single instance of the Broadcaster has been created. If the Singleton doesn't exist, then one instance is created and assigned to the private field instance. The Singleton object is then returned. The result is that the Broadcaster contains a reference to an instance of itself.

If you add an IListener to the ArrayList of listeners, then each time the static method Broadcast is called, all listeners who are listening will receive the string content. This technique can be used to display internal status information, write to a log file, monitor your distributed application, or to perform a combination of these tasks. (It is recommended that you use Debug and Trace listeners related to the Broadcaster idiom.) Also, note that the IEnumerable is used to iterate the ArrayList of listeners.

## Defining the Interface

The IListener interface defines two methods: Listening and Listen. Listening is a function that returns a Boolean indicating whether the object implementing the IListener interface wants to receive messages. This enables the object to figuratively plug its ears without unregistering from the Broadcaster. The Listen method is the method that will receive the string content when listening.

You can use the Broadcaster by implementing the IListener interface. The FormMain class implements IListener to display broadcast messages in the status bar. In the case of the main form, you can add the form to the list of listeners in the Form's Load. Another great place to add a listener to the list of listeners is in the constructor of a class. Consider implementing IDisposable and Dispose to remove the object from the Broadcaster's listener list when the object is disposed.
