重载运算符是方法。具体来说，它们是具有特殊语法的方法。可以将重载运算符视为两部分来理解。第一部分实现一个标准命名方法，用于执行该运算符本应执行的操作。第二部分使用特殊语法定义运算符方法，并在运算符内部调用该命名方法。（显然，通常可以跳过重载运算符，但那样会令人不快。）

## 重载运算符的准则与限制

定义重载运算符时要谨慎。最需要避免的事情是创建古怪的运算符。例如，重载加法运算符来执行减法。不要这样做。遵循以下重载运算符的基本规则，可以让你避免麻烦：

- 定义执行该操作的方法时，使用 op_ 前缀后跟运算符名称，以支持 Visual Basic .NET 等不支持运算符重载的语言。
- 通过调用命名方法来实现重载运算符。（为什么要两次分类运算符行为？）
- 仅在运算符适用的类中重载该运算符。
- 当操作符合直觉且结果看起来合理时，使用运算符重载。
- 对称地重载运算符。如果实现了加法，就实现减法。

## 特性

正是像 interface 和 attributes 这样的口语化术语，让我们作为软件工程师陷入困境。原因是这些术语承担了双重职责。很长一段时间里，“interface”本质上意味着类中声明的成员。当 COM 出现时，interface 又有了另一层含义；interface 变成了一种构造——非常像类。（对于 VB 开发者来说，接口和类之间的界限很模糊。）

“attribute”和修辞意义上的 Attribute 也存在类似问题。在一般意义上，“attribute”与“property”同义。特性是类型的一种属性。C# 的 Attribute 本身实际上是一个类。（围绕特性的令人困惑的讨论，可能与围绕父与子、超类与子类、对象与类的讨论一样多。）

在 ADVANCED C# 中，首字母大写的 Attribute 将是一个向程序集添加元数据的类。
