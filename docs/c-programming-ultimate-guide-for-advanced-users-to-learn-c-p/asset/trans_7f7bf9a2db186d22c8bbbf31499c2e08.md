如果我们以某种方式弄清楚如何在 Visual Basic 程序中使用用 C# 描述的 IndexedProperty 类。在许多编程语言中，新分配内存的释放是手动处理的。例如，在 C++ 中，使用 delete 运算符来释放已分配的内存。然而，C# 采用了一种不同的、更无忧的方法：垃圾回收。C# 的垃圾回收框架会自动回收对象——直接在幕后进行，无需程序员干预。其工作方式如下：当对象不存在任何引用时，该对象就被认为不再需要，其占用的内存就会被释放。这些被重复使用的内存可用于后续分配。

在程序执行期间，垃圾回收只是偶尔发生。它不会仅仅因为存在一个或多个不再使用的对象而发生。因此，你无法确切知道垃圾回收何时会发生。可以定义一个方法，让垃圾回收器在对象最终销毁之前调用它。此方法称为析构函数，在某些高度特殊的情况下，它可以用来确保对象干净利落地结束。例如，可以使用析构函数来确保释放对象拥有的系统资源。必须首先说明，析构函数是一种高级功能，适用于某些特定情况。通常并不需要它们。然而，由于它们是 C# 的一部分，这里为了完整性而简要介绍。

## 实现一些方法

[] 中的所有语义特性都是可选的。在实现方法（或其他成员）时，你不必使用特性；当你理解它们时，你就会知道何时以及为何使用特性。修饰符（例如 public）描述可访问性。修饰符与信息隐藏有关。所有方法都需要一个返回类型。可以与函数对比的是返回 void 的方法，而函数返回非 void 数据类型。方法的名称应该是动作短语或动作动词。你可以提供零个或多个参数。参数的形式是类型名，如果使用多个参数，则后面跟一个逗号。项目符号摘要概述了开发者建议的方法命名规则。

### 构造函数

有两个特殊方法：构造函数和析构函数。构造函数与类具有完全相同的名称。除构造函数外，任何其他成员都不能与类同名（包括大小写也相同）。构造函数可以有零个或多个参数，并且没有返回类型。（我们将在下一节讨论析构函数。）构造函数只需通过合并具有不同签名的额外构造函数即可实现重载。以下项目符号列表概述了构造函数规则。

- 如果类只有静态成员，则实现一个私有构造函数以防止创建实例。
- 保持构造函数简短，只执行简单任务，例如在构造函数中进行参数到字段的赋值。这种技术可以快速创建对象。
- 提供一个受保护的构造函数供派生类使用。
- 作为规则，不要为结构体实现空构造函数。如果你不为结构体提供无参数空构造函数，编译器会合并一个默认构造函数，将所有成员初始化为其默认值。
- 使用构造函数参数来设置属性。使用参数构建类，或使用默认构造函数创建对象并赋值属性，应产生类似的结果。
- 命名参数时要保持一致。常见做法是为每个重载构造函数合并越来越多的参数。

C# 利用非确定性销毁。CLR 实现了一个垃圾回收器，在对象不再使用时清理内存。这意味着在 C# 中，你不必像在 C++ 或 Delphi 中那样担心析构函数。

当对象不再需要时，垃圾回收器将为你的对象调用析构函数。析构函数将调用任何 Finalize 方法。你可以通过调用 GC.Collect 强制进行垃圾回收，但这不是推荐的做法。垃圾回收器会挂起任何正在运行的线程，这可能会影响性能。此外，垃圾回收器在决定何时运行方面会做得很好。

## 执行 Dispose 方法

如果你的类中有非托管资源，那么你可以实现一个 Dispose 方法来帮助确定性清理。通过允许使用者调用 Dispose 方法，你可以给使用者一个机会来选择他们何时完成文件或系统连接的使用。

使用如下模式来实现 Dispose 方法。

- 首先，声明一个私有字段 disposed，用于跟踪 Dispose 方法是否已被调用，将 disposed 初始化为 False。
- 在 Dispose 方法中，验证 Dispose 是否已被调用，如果已被调用则返回。
- 执行清理，然后调用 GC.SuppressFinalize() 方法，传递需要抑制其 Finalize 的对象的引用。
- 最后，将字段 disposed 设置为 True。

大多数时候，你不需要实现析构函数或 Dispose 方法。CLR 中的托管对象会被自动垃圾回收。只有在你确定需要时，才实现析构函数和 Dispose 方法。
