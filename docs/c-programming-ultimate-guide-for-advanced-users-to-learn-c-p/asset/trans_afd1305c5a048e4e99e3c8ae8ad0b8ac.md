
此时，参数 x 的值为 9。在第三次调用中，实参为 8，这就是 x 获得的值。实际情况是，调用 IsEven() 时作为实参传入的值，就是其形参 x 接收到的值。

一个方法可以有多个参数。只需声明每个参数，并用逗号将一个参数与下一个参数分隔开。例如，Factor 类定义了一个名为 IsFactor() 的方法，用于判断第一个参数是否为第二个参数的因子。

## 参数化方法：

可以使用参数化方法向 Vehicle 类添加另一个组件：计算给定距离所需燃油量的能力。这个新方法称为 FuelNeeded()。该方法接收你需要行驶的英里数，并返回所需的汽油加仑数。FuelNeeded() 方法的定义方式如下：

```
public double FuelNeeded(int miles) {
    return (double) miles / Mpg;
}
```

注意，此方法返回 double 类型的值。这很有用，因为给定距离所需的燃油量可能不是整数。如果要用一句话概括类的实质，可能会是这样：类体现功能。当然，有时难点在于知道一个“功能”在哪里结束、另一个从哪里开始。通常，你会希望类成为更大应用程序的构建块。为此，每个类必须表示一个单一功能单元，执行界限清晰的活动。按照这个思路，你会希望类在合理范围内尽可能小——但不能再小！也就是说，包含不必要功能的类会使代码混乱并破坏其结构，而包含过少功能的类则支离破碎。平衡点是什么？现在正是：

```
minivan.Mpg = 21;
```

这样的方法绝不可能用于专业编写的 C# 代码。除了容易出错（你可能忘记设置某个字段）之外，完成这项任务本质上还有更好的方法：构造函数。构造函数在对象创建时初始化对象。它与类同名，语法上类似于方法。但是，构造函数没有显式返回类型。构造函数的一般形式如下：

```
access class-name(param-list) {
    // constructor code
}
```

通常，你会使用构造函数为类定义的实例变量赋初值，或执行构建完整对象所需的其他启动任务。通常，访问修饰符为 public，因为构造函数一般从类外部调用。参数列表可以为空，也可以指定一个或多个参数。所有类都有构造函数，无论你是否定义，因为 C# 会自动提供默认构造函数，使所有成员变量初始化为其默认值。对于大多数值类型，默认值为零。对于 bool，默认值为 false。对于引用类型，默认值为 null。但是，当你定义自己的构造函数时，默认构造函数不再使用。

注意，构造函数被标记为 public，因为构造函数将从其类外部定义的代码中调用。如前所述，大多数构造函数出于这个原因被声明为 public。该构造函数将 MyClass 的实例变量 x 赋值为 10。创建对象时，构造函数由 new 调用。例如，在 MyClass t1 = new MyClass(); 这一行中，构造函数 MyClass() 在 t1 对象上调用，使 t1.x 的值为 10。对 t2 也是如此。构造后，t2.x 的值为 10。随后，程序的输出为 10。

上一个示例使用了无参构造函数。虽然这在某些情况下没问题，但经常需要接受一个或多个参数的构造函数。向构造函数添加参数的方式与向方法添加参数类似：只需在构造函数名后的括号内声明它们。既然已经学习了类及其构造函数，我们应该研究 new 运算符。它具有以下一般形式：

```
new class-name(arg-list)
```

这里，class-name 是被实例化的类的名称。类名后跟括号决定了该类的构造函数，如上一节所述。如果类没有定义自己的构造函数，new 将使用 C# 提供的默认构造函数。由于内存有限，可以想象 new 可能因内存不足而无法为对象分配内存。如果发生这种情况，将发生运行时异常。对于本书中的示例程序，你不必担心内存耗尽，但在你编写的真实项目中应考虑这种可能性。

在 C# 中，值类型的变量包含其自身的值。保存此值的内存会在程序运行时自然提供。因此，没有充分理由使用 new 显式分配此内存。另一方面，引用变量存储对对象的引用。保存此对象的内存会在执行期间动态分配。不将主要类型（例如 int 或 char）设为引用类型，会极大提高程序性能。使用引用类型时，存在一层间接寻址，会给每次对象访问增加开销。值类型避免了这种开销。

有趣的是，允许对值类型使用 new，如下所示：

```
int i = new int();
```

这样做会调用 int 类型的默认构造函数，将 i 初始化为零。总的来说，对值类型调用 new 会调用该类型的默认构造函数。但是，它不会动态分配内存。说实话，大多数软件工程师不会对值类型使用 new。

## 垃圾回收：

如你所见，对象通过 new 运算符从空闲内存池中动态分配。显然，内存不是无限的，空闲内存可能耗尽。因此，new 可能因空闲内存不足无法创建所需对象而失败。因此，任何动态分配方案的关键部分之一，是从未使用对象中回收空闲内存，使该内存可供后续重新分配。在许多编程语言中，释放最近分配的内存是手动处理的。例如，在 C++ 中，使用 delete 运算符释放已分配的内存。但是，C# 使用另一种更少问题的方案：垃圾回收。C# 的垃圾回收框架自动回收对象——直接在后台发生，无需开发人员干预。其工作方式如下：当不存在对对象的引用时，该对象被视为不再需要，对象占用的内存被释放。然后，这块被重用的内存可用于后续分配。

垃圾回收只在程序执行期间偶尔发生。它不一定因为存在一个或多个不再使用的对象而发生。因此，你无法确切知道垃圾回收何时发生。可以定义一个方法，该方法仅在垃圾回收器最终销毁对象之前被调用。此方法称为析构函数，可在某些非常特殊的情况下用于确保对象整洁地结束。例如，可以使用析构函数确保释放对象拥有的系统资源。必须在一开始说明，析构函数是极其高级的特性，与某些特定情况相关。它们通常不是必需的。
