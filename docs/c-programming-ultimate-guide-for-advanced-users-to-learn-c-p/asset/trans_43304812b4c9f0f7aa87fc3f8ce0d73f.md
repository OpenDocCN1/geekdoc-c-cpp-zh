
## 加载文本文件

通过调用 LoadFile 方法从外部文件加载内容。LoadFile 有三种形式，其中最简单的一种用于确定包含 RTF 格式的文件的文件名：

```csharp
richTextBox1.LoadFile("file.rtf");
```

LoadFile 的第二个重载具有一个 RichTextBoxStreamType 参数，使你可以指定文件包含的格式类型。例如，要加载纯文本，可以修改 LoadFile 语句：

```csharp
richTextBox1.LoadFile("file.rtf", RichTextBoxStreamType.PlainText);
```

RichTextBoxStreamType 是定义在 System.Windows.Forms 命名空间中的枚举。你应当使用完全限定名，或确保存在引用 System.Windows.Forms 命名空间的 using 语句。

## 保存文本文件

RichTextBox.SaveFile 执行与 LoadFile 对称的操作。SaveFile 通过调用 SaveFile 并传入文件名，将 RichTextBox 控件的内容写入 RTF 或 TXT 文件。

## 使用 ZoomFactor

RichTextBox.ZoomFactor 是一个有趣的属性。通过 ZoomFactor，可以指定文本大小的百分比增幅。将 ZoomFactor 设置为 2 会使文本大小翻倍，而设置为 .64 会使文本大小约减小一半。可接受的值为 .64 到 64，后者是正常大小的 64 倍。对于支持残障人士的应用程序以及演示而言，此属性是一项了不起的功能。例如，假设你正在投影仪上显示 RichTextBox 的内容。设置 ZoomFactor 来增大文本大小，将使观众更容易看到 RichTextBox 控件中的内容。

## ThreadPool 线程处理

ThreadPool 是一个为你管理线程池的类。在 ThreadPool 中使用线程进行多线程处理与创建 Thread 对象相同。不过，你的任务会稍微轻松一些，而且从池中获取线程通常比创建 Thread 类的实例要快一些，因为池中可能已经有线程在等待你给它分配工作。

要使用 ThreadPool 中的线程，只需以委托的形式给 ThreadPool 一些要做的工作。在此示例中，委托将充当表示线程要完成的工作的方法。线程处理的其他每个部分都与自行创建 Thread 对象相同。需要记住的最重要一点是，ThreadPool 线程需要像 Thread 实例一样谨慎对待，尤其是在涉及 Windows Forms 控件时。Windows Forms 控件不是线程安全的；因此，从线程与 Windows Forms 控件交互时，你应当格外小心。

### 在线程池中排队工作项

委托至关重要，以至于没有它们事件处理程序就无法工作；而且除非你理解委托，否则无法在任何 .NET 语言中使用多线程。回顾一下，委托包含至少一个方法的地址。线程处理的工作方式是：向线程提供一个委托，其中包含表示该线程要完成的工作的方法。

在 Listing 2-3 中，静态方法 Splash 创建 Opacity 为 0 的 Splash 窗体。当 Form.Opacity 为 0 时，窗体是透明的；1 表示不透明窗体。当 Opacity 值在 0 到 1 之间的某个范围内时，窗体就是半透明的。Splash 窗体以透明方式显示，线程会逐渐增大 Opacity 值，直到窗体变为不透明，此时线程就完成了。

Show 方法定义在 Listing 2-3 的第 11 行到第 26 行。这个 Show 方法通过修改 Opacity 使窗体逐渐淡入。遗憾的是，由于 Windows Forms 控件不是线程安全的，Opacity 必须在与窗体所在线程相同的线程上更改。Show 方法不在该线程上。

我们实际更新 Opacity 值的方式是调用窗体的 Invoke 方法。Invoke 是线程安全的；Invoke 会将委托参数封送到与调用对象所在线程相同的线程中。（再次说明，没有委托，就不可能实现线程安全的多线程处理。）

Invoke 需要一个 MethodInvoker 委托，并执行用于初始化该委托的方法内部的代码。Increment 方法更新 Opacity 值。done 字段用于指示窗体不透明。在更新 done 字段时，我们锁定该字段，从而防止运行 Show 的线程在 done 值更新之前检查它。

最后，Show 使用 try/finally 结构来捕获异常并关闭窗体。例如，如果用户在 Splash 窗体完全变为不透明之前关闭了应用程序，Show 将引用一个已释放的窗体（这是 Listing 2-3 中的第 17 行）并引发异常。异常处理程序会作出响应，促使应用程序迅速关闭。
