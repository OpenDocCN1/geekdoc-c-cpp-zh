Each step of the way, the new approach took the best elements of the past methods and moved forward. The same is true for object-oriented programming. Before OOP, many projects were approaching (or surpassing) the point where the structured approach no longer worked. A better way to handle complexity was required, and object-oriented programming was the answer. Object-oriented programming took the best ideas of structured programming and combined them with a few new concepts. The result was a different and better way of organizing a program.

In the most general sense, a program can be organized in one of two ways: around its code (what is going on) or around its data (what is being affected). Using only structured programming techniques, programs are typically written around code. This approach can be thought of as "code acting on data." Object-oriented programs work the other way around. They are organized around data, with the key principle being "data controlling access to code." In an object-oriented language, you define the data and the routines that are allowed to act on that data. Thus, a data type defines precisely what kind of operations can be applied to that data.

## Polymorphism

Polymorphism is a C# technique. Polymorphism (from Greek, meaning "many forms") is the quality that enables one interface to access a general class of actions. A simple example of polymorphism is found in the steering wheel of a car. The steering wheel (the interface) is the same, no matter what type of actual steering mechanism is used. That is, the steering wheel works the same whether your car has manual steering, power steering, or rack-and-pinion steering. Thus, turning the steering wheel left causes the car to go left regardless of what type of steering is used. The advantage of the uniform interface is, obviously, that once you know how to operate the steering wheel, you can drive any type of car.

A similar principle can also apply to programming. For instance, consider a stack (which is a first-in, last-out list). You may have a program that requires three different kinds of stacks. One stack is used for integer values, one for floating-point values, and one for characters. In this case, the algorithm that implements each stack is the same, even though the data being stored differs. In a non-object-oriented language, you would be required to create three different sets of stack routines, with each set using different names. However, because of polymorphism, in C#, you can specify the general form of a stack once and then use it for all three specific circumstances. Thus, if you know how to use one stack, you can use them all. More generally, the concept of polymorphism is often expressed by the phrase "one interface, multiple methods." This means it is possible to design a generic interface to a group of related activities. Polymorphism reduces complexity by allowing the same interface to be used to specify a general class of action. It is the compiler's job to choose the specific action (that is, method) as it applies to each circumstance. You, the programmer, need not make this determination manually. You need only remember and use the general interface.

## Inheritance

Inheritance is the process by which one object can acquire the properties of another object.

This is important because it supports the concept of hierarchical classification. After all, most knowledge is made manageable by hierarchical (that is, top-down) classifications. For example, a Red Delicious apple is a part of the classification apple, which, in turn, is part of the fruit class, which is under the larger class food. That is, the food class has certain qualities (edible, nutritious, etc.) that also, logically, apply to its subclass, fruit. In addition to these qualities, the fruit class has specific qualities (succulent, sweet, etc.) that distinguish it from other food. The apple class defines those qualities specific to an apple (grows on trees, not tropical, etc.). A Red Delicious apple would, in turn, inherit all the qualities of every preceding class and would define only those qualities that make it unique. Without the use of hierarchies, each object would need to explicitly define all of its attributes. Using inheritance, an object need only define those qualities that make it unique within its class. It can acquire its general attributes from its parent. Thus, it is the inheritance mechanism that makes it possible for one object to be a specific instance of a more general case.

## First C# Program

It is now time to learn how to create, compile, and run a C# program. Since this is a "hands-on" guide to C# programming, being able to successfully complete these tasks is a critical first step. Here is the program we will use:

```csharp
/*
This is a simple C# program.
Call this program Example.cs.
*/
using System;
class Example {

    // A C# program begins with a call to Main().
    static void Main() {
        Console.WriteLine("C# gives you programming power.");
    }
}
```

### Compiling the Program

To compile the program, execute the C# compiler, csc.exe, specifying the name of the source file on the command line, as shown here:

```
C:\>csc Example.cs
```

The csc compiler creates a file called Example.exe that contains the MSIL version of the program. Although MSIL is not executable code, it is still contained in an .exe file. The Common Language Runtime automatically invokes the JIT compiler when you attempt to execute Example.exe. Know, however, that if you attempt to execute Example.exe (or any other .exe file that contains MSIL) on a computer for which the .NET Framework is not installed, the program won't execute, because the CLR will be missing.
