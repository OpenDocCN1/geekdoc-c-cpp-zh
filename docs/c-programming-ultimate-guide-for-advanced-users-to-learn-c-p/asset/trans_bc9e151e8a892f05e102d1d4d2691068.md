
C++由比雅尼·斯特劳斯特鲁普于1979年在新泽西州默里山的贝尔实验室创立。他最初将这种新语言称为“带类的C”。然而，在1983年，名称被改为“C++”。C++包含了整个C语言。因此，C是构建C++的基础。斯特劳斯特鲁普对C所做的大部分增强都是为了支持面向对象编程。从根本上说，C++是C的面向对象版本。通过以C为基础，斯特劳斯特鲁普为OOP提供了一条平滑的迁移路径。C程序员无需学习一种全新的语言，只需掌握少数几个新特性，就能享受面向对象方法带来的好处。这使得大批程序员能够轻松地从结构化编程转向面向对象编程。因此，到20世纪90年代中期，C++成为开发高性能代码的主流语言。

必须理解的是，开发C++并不是为了创造一种新的编程语言，而是对一种已经非常成功的语言的升级。这种语言改进方法——从现有语言出发并将其推向前进——形成了一种延续至今的趋势。

本章的目的是展示C#，包括推动其诞生的力量、其设计理念，以及几个最重要的特性。学习编程语言最难的一点在于，没有任何一个部分可以孤立存在。相反，语言的各个部分是协同工作的。正是这种相互关联性使得在不涉及其他部分的情况下理解C#的某一部分变得困难。为了克服这个问题，本章简要概述了C#的几个特性，包括C#程序的一般形式、两条控制语句和几项要点。本章不会深入过多细节，而是侧重于任何C#程序都通用的基本概念。

C语言的出现标志着现代编程时代的开始。C语言由丹尼斯·里奇于20世纪70年代在DEC PDP-11（运行UNIX操作系统）上创建。虽然一些早期的语言，尤其是Pascal，已经取得了显著进展，但正是C语言确立了至今仍塑造编程发展方向的视角。

C语言诞生于20世纪60年代的结构化编程革命。结构化语言的特点在于其丰富的组织良好的控制命令、带局部变量的子程序、代码块，以及其他使得程序更易于管理和维护的增强功能。

## 互联网的出现

编程语言领域的下一个重要进步是Java。Java的工作最初名为Oak，于1991年在Sun Microsystems启动。Java设计的主要推动力是詹姆斯·高斯林，帕特里克·诺顿、克里斯·沃思、埃德·弗兰克和迈克·谢里丹也发挥了作用。

Java是一种结构化、面向对象的语言，其语法和设计理念源于C++。Java的创新之处更多不是由编程技艺的进步（尽管确实有一些）驱动，而是由计算环境的变化驱动。在互联网普及之前，大多数程序都是针对特定的CPU和特定的操作系统编写、编译和运行的。

尽管程序员一直喜欢重用代码，但将程序从一个环境有效移植到另一个环境的能力，相对于更紧迫的问题而言，一直被放在次要位置。然而，随着互联网的兴起——各种类型的CPU和操作系统相互连接——可移植性的老问题变得愈发重要。为了解决这个问题，需要一种新语言，而这种新语言就是Java。

Java通过将程序的源代码解释为一种广泛适用的语言（称为字节码）来实现可移植性。然后，该字节码由Java虚拟机（JVM）执行。这样，Java程序就可以在任何提供了JVM的环境中运行。此外，由于JVM通常易于实现，因此它很快便在无数环境中得到了应用。

除了可移植性的需求外，还有第二个基本问题需要在基于互联网的编程成为现实之前得到解决。这个问题就是安全性。所有互联网用户都知道，计算机病毒构成了真实且持续的潜在威胁。如果无法信任可移动代码，它们还有什么用处呢？谁会愿意冒险执行通过互联网传输的程序呢？它可能包含恶意代码。幸运的是，安全性问题的解决方案同样体现在JVM和字节码中。由于JVM执行字节码，它完全控制程序，并且可以阻止Java程序做出不应该做的事情。因此，JVM和字节码同时解决了可移植性和安全性这两个问题。

必须理解，Java使用字节码的做法与C和C++截然不同，后者总是被编译为可执行的机器代码。机器代码与特定的CPU和操作系统相关联。因此，如果要在另一个系统上运行C/C++程序，就必须针对该环境重新编译为机器代码。要使C/C++程序能够在多种环境中运行，就需要该程序的多个可执行版本。这不仅代价高昂，而且极其困难。Java使用一种通用语言的做法既巧妙又经济。这也是C#将为其自身独特目的而采用的解决方案。

如前所述，Java源自C和C++。其语法基于C，其对象模型源自C++。尽管Java代码在向上或向下的兼容性上并不与C或C++完全一致，但其语法足够相似，使得庞大的现有C/C++程序员群体能够轻松过渡到Java。此外，由于Java同样建立在已存在的视角之上并对其进行了改进，高斯林等人得以将精力集中在新颖和创新的特性上。正如斯特劳斯特鲁普在创建C++时不必“重新解决一个已经解决的问题”，高斯林在创建Java时也不必发明一种全新的语言。

## C#的诞生

虽然Java已经有效解决了互联网环境中围绕可移植性和安全性的许多问题，但它仍然缺少一些特性。其中之一是跨语言互操作性，也称为混合语言编程。这是一种语言编写的代码能够与另一种语言生成的代码协同工作的能力。跨语言互操作性对于构建大型分布式软件系统至关重要。它对于软件组件同样具有吸引力，因为最成功的组件是那种能够在最多操作环境中被最广泛代码所使用的组件。
