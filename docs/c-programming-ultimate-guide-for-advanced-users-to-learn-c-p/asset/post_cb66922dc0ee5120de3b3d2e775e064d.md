There are individuals still alive who can discuss reading the output of the most modern computer in existence by holding a cardboard ruler up to an oscilloscope and deciding the signal as either a one or a zero. As late as the mid 1980s, the most powerful computers in widespread use (the DEC PDP series) could be programmed by flipping switches on a panel, directly controlling chip-level signal. Furthermore, until the 1990s, it was inconceivable for a computer programmer to be unfamiliar with a wide range of interrupt requests and the memory locations of different devices.

Between the mid-1960s, when the IBM 360 was released and Gordon Moore stated his popular law that transistor density in a given area would continue to double at regular intervals, the cost of a single processing instruction has decreased by roughly 99.99%. This has completely transformed the economics of programming. Where once it made sense for the software engineer to work with a mental model of the computer's internal representation and to sacrifice development time for execution efficiency, now it makes sense for the computer to be given a model corresponding to the developer's internal representation of the task, even if that representation is not ideally efficient.

## Peer To Peer:

One of the last web technology buzzwords of the month was peer-to-peer (also called P2P, which had the marketing advantage of being the same abbreviation as one of the last business-buzzwords of the month, way to productivity).

Unexpectedly, P2P is the kind of engineering that one would anticipate from the expression World Wide "Web." In a P2P design, services are created in two stages: peer resources are found by some kind of centralized server (whether or not the server is under the legal control of the planning organization) and then the peers are connected for resource sharing going forward without any more intervention.

C# and .NET have strong facilities for the creation of P2P systems, after all systems require the creation of rich clients, refined servers, and facilities for making robust resource sharing systems. P2P is tainted by the prevalence of file sharing systems, yet projects such as SETI@Home and Folding@Home show the potential for distributed computing, which can apply stunning amounts of calculation as a powerful tool for solving problems.

The value that has been created from a foundation of HTML is staggering. The value that will be created from the clearly more flexible and expressive Extensible Markup Language (XML) will outstrip everything that has gone before (perhaps not in terms of stock prices and company valuations, however in real profitability and productivity, there is no doubt). Web Services convey value by standard Web protocols and XML-based data representation that doesn't care about how it is displayed (Web Services are headless).

Web Services are the raison d'être of Microsoft's whole .NET approach, which is impressively broader than "simply" the biggest update in programming APIs in 10 years. .NET is wrongly interpreted by many business journalists as an attempt by Microsoft to position itself as a central intermediary in over-the-Web transactions. The fact of the matter is simpler; Microsoft wants to own the operating systems on all Web-connected devices, even as the type and number of such devices soar. The more that computers move from performing fundamentally computational tasks towards communication and control tasks, the more that Web Services have to offer, and Microsoft has always understood that operating system dominance is limited by software development.

The .NET system is in any case a move towards a post-desktop reality for Microsoft and software development. The .NET Framework, which combines an abstraction of the underlying hardware with extensive Application Programming Interfaces (APIs), proposes to engineers that "write once, run anywhere" is a chronologically mistaken view that advances the idea of a component running on a computer. The .NET approach recognizes that rich clients ("rich clients" meaning non-server applications that are responsible for computing more than just their display and data capabilities) working on a variety of devices, powerful servers, and new applications running on the not-to-be-surrendered desktop "legacy" machines are not separate markets at all, but rather are segments that all software applications will fundamentally need to address. Whether software engineers start with a browser-based client for their Web Service (or, for that matter, whether software engineers develop a Windows-based rich client for a Java-based Web Service), part of the .NET approach is to make it unfailingly easy to extend the value onto another device: a rich client on the PocketPC or 3G phone or a better database in a backend rack. Web protocols will connect all of these devices, yet the value is in the data, which will flow via Web Services. If .NET is the most catalytic approach to create Web Services, Microsoft will definitely gain market share over the entire range of devices.

The quality of Microsoft's coding is often judged unfairly. No operating system but Windows is judged by what obscure hardware configurations it doesn't run on and Microsoft Office may take up a vexing amount of disk space to install, yet it's solid and fit enough to consume the business world. However, where Microsoft has genuinely messed up is in security. It's bad enough that Microsoft generally makes security a win or bust choice ("Enable macros, yes or no?" "Install this control (permanently), yes or no?") however the way that they give you no information for that win or bust choice ("Be sure that you trust the sender!") is unforgivable. When you consider the number of files that have been moved on and off the average PC and the lack of advancement of many users, the only thing that is amazing is the way in which rare truly devastating attacks have been.

The .NET Framework SDK includes a new security model based on fine-grained permissions for such things as accessing the file system or the network and digital signatures based on public key cryptography and certificate chains. While Microsoft's stated goal of "trusted computing" goes beyond security and will require significant changes in both their operating systems and, perhaps even more fundamentally, legally in Microsoft Office and Outlook, the .NET Framework SDK provides modern components which one can imagine giving rise to a much more secure computing environment.
