
Argument x at that point has the value 9. In the third call, the argument is 8, which is the value that x gets. The fact of the matter is that the value passed as an argument when IsEven() is called is the value received by its parameter, x.

A method can have more than one parameter. Just declare every parameter, separating one from the next with a comma. For instance, the Factor class defines a method called IsFactor() that determines whether the first parameter is a factor of the second.

## Parameterize Method:

You can use a parameterized method to add another component to the Vehicle class: the ability to calculate the amount of fuel required for a given distance. This new method is called FuelNeeded(). This method takes the number of miles that you need to drive and returns the number of gallons of gas required. The FuelNeeded() method is defined this way:

```
public double FuelNeeded(int miles) {
    return (double) miles / Mpg;
}
```

Notice that this method returns a value of type double. This is useful, since the amount of fuel required for a given distance may not be a whole number. If one were to attempt to summarize the substance of the class in a single sentence, it might be this: A class embodies functionality. Of course, sometimes the trick is knowing where one "functionality" ends and another starts. As a rule, you will want your classes to be the building blocks of your larger application. To do this, each class must represent a single functional unit that performs clearly delineated activities. Along these lines, you will want your classes to be as small as reasonably possible—yet no smaller! That is, classes that contain unnecessary functionality confuse and destructure code, yet classes that contain too little functionality are fragmented. What is the balance? It is now that

```
minivan.Mpg = 21;
```

A methodology like this could never be used in expertly written C# code. Besides being error prone (you may neglect to set one of the fields), there is essentially a better way to accomplish this task: the constructor. A constructor initializes an object when it is created. It has the same name as its class and is syntactically similar to a method. However, constructors have no explicit return type. The general form of a constructor is shown here:

```
access class-name(param-list) {
    // constructor code
}
```

Normally, you will use a constructor to give initial values to the instance variables defined by the class, or to perform some other startup tasks required to make a fully constructed object. Usually, access is public because a constructor is generally called from outside its class. The parameter list can be empty, or it can specify one or more parameters. All classes have constructors, whether you define one or not, because C# automatically provides a default constructor that makes all member variables be initialized to their default values. For most value types, the default value is zero. For bool, the default is false. For reference types, the default is null. However, when you define your own constructor, the default constructor is no longer used.

Notice that the constructor is indicated as public because the constructor will be called from code defined outside of its class. As referenced, most constructors are declared public for this reason. This constructor assigns the instance variable x of MyClass the value 10. The constructor is called by new when an object is created. For instance, in the line MyClass t1 = new MyClass(); the constructor MyClass() is called on the t1 object, giving t1.x the value 10. The same is true for t2. After construction, t2.x has the value 10. Subsequently, the output from the program is 10.

In the previous example, a parameterless constructor was used. While this is fine for some circumstances, frequently you will require a constructor that accepts one or more parameters. Parameters are added to a constructor similarly to the way they are added to a method: just declare them inside the brackets after the constructor's name. Since you have learned about classes and their constructors, we should investigate the new operator. It has this general form:

```
new class-name(arg-list)
```

Here, class-name is the name of the class that is being instantiated. The class name followed by brackets determines the constructor for the class, as described by the previous section. If a class doesn't define its own constructor, new will use the default constructor provided by C#. Since memory is limited, it is conceivable that new won't be able to allocate memory for an object because insufficient memory exists. If this occurs, a runtime exception will happen. For the example programs in this book, you won't have to worry about running out of memory, but you should consider this possibility in real projects that you write.

In C#, a variable of a value type contains its own value. Memory to hold this value is naturally provided when the program is run. Therefore, there is no compelling reason to explicitly allocate this memory using new. On the other hand, a reference variable stores a reference to an object. The memory to hold this object is allocated dynamically during execution. Not making the major types, for example, int or char, into reference types enormously improves the performance of your program. When using a reference type, there is a layer of indirection that adds overhead to each object access. This overhead is avoided by a value type.

As a point of interest, it is allowed to use new with the value types, as shown here:

```
int i = new int();
```

Doing so invokes the default constructor for type int, which initializes i to zero. By and large, invoking new for a value type invokes the default constructor for that type. It doesn't, however, dynamically allocate memory. To be honest, most software engineers don't use new with the value types.

## Garbage Collection:

As you have seen, objects are dynamically allocated from a pool of free memory by using the new operator. Obviously, memory isn't infinite, and the free memory can be depleted. Therefore, it is possible for new to come up short because there is insufficient free memory to create the desired object. Thus, one of the key parts of any dynamic allocation scheme is the recovery of free memory from unused objects, making that memory available for subsequent reallocation. In many programming languages, the release of recently allocated memory is handled manually. For instance, in C++, you use the delete operator to free memory that was allocated. However, C# uses an alternate, more issue-free approach: garbage collection. C#'s garbage collection framework recovers objects automatically—happening directly, in the background, with no developer intervention. It works this way: When no references to an object exist, that object is considered to be no longer required, and the memory occupied by the object is released. This reused memory can then be used for a subsequent allocation.

Garbage collection happens only sporadically during the execution of your program. It will not necessarily happen because one or more objects exist that are no longer used. Consequently, you can't know exactly when garbage collection will happen. It is possible to define a method that will be called only before an object's final destruction by the garbage collector. This method is known as a destructor, and it can be used in some highly particular circumstances to ensure that an object ends neatly. For instance, you may use a destructor to ensure that a system resource owned by an object is released. It must be stated at the outset that destructors are an exceptionally advanced feature that are relevant to certain particular circumstances. They are not typically required.
