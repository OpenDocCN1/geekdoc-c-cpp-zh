## 继承

描述继承关系时，至少需要两个类。一个是父类，第二个是子类。（父类与子类之间的关联也称为超类和子类，其中超类与父类同义，子类与子类同义。）这种父子关系称为 IsA 关系。例如，我是我父亲（和母亲）的后代，所以我是 Kimmel（和 Symons）家族的人，继承了源自 Kimmel（和 Symons）家族的 DNA 物质。

在 C# 中描述继承关系时，子类会获得父类中描述的所有成员。继承时，你会获得父类中描述的所有字段、属性和方法。面向对象继承不是染色体遗传，它意味着你获得一切。

我假设你们大多数人都理解继承，但既然继承是一个重要概念，我还想再展示一个示例。如果类 B 继承自类 A，那么从逻辑上讲，B 的实例会是一个 A。

继承的文档与接口继承的文档不同。要表示类 B 继承自类 A，你会这样编写类头：

```
public class B : A
```

与接口继承不同，当你从类继承时，不必实现父类中的任何方法，因为它们已经在父类中实现。

### 继承术语

与继承关联相关的术语很多。由于你会在本书中遇到它们，我在这里快速概述其中几个。

- 如果类 B 继承自 A，则 A 是父类，B 是子类。
- 如果类 B 继承自 A，则 A 也称为超类，B 称为子类。
- 继承关系满足 IsA 测试。在我们的模型中，我们会说 B IsA A（尽管从词源上看这很可怕）。
- 继承也称为泛化。
- 兄弟类是从共同父类继承的类。
- 偶尔你会听到人们在谈论继承关系时提到祖父母、祖先和后裔。

这些用于指代本质上与继承相同事物的说法可能会引起混淆。

显然，在谈论对象继承关系时，没有人会提到远房表亲或远房姑姨，但这些术语可以且应该被用来描述与人类家庭关系不同的关联。例如，表亲是你父母兄弟姐妹的后代。

### 继承的一般准则

在继承方面，你是决策者。实际上，我收录了几条使用继承关联的规则；最终你应逐案选择。

- 如果你描述了一个类，后来意识到它应该被重构，那么考虑从基类继承以纳入新代码。
- 尽量让你的继承关系保持浅而宽。兄弟类与子类的数量之间没有完美比例，但在成熟结构中，兄弟类通常比后代多。
- 研究重构。重构是迄今为止指导软件工程师改进现有代码的最佳方式。从根本上说，重构是一种改进现有代码的有纪律的方法。（不幸的是，我们无法在此解释重构，但本书中的代码清单将使用重构。）
- 不要犹豫去检验并改变你的观点。
- 研究现有框架以了解其范围。（值得研究的优秀框架包括 Delphi 的 VCL 和 .Net Framework。）

## 封装与聚合

封装和聚合指类包含成员的能力。更具体地说，聚合指类（和结构）包含类型也是类（或结构）的成员的能力。

我最喜欢的封装示例是人体与膀胱之间的联系。幸运的是，膀胱被封装在人体内。你能想象一个现实吗：人们可以通过按压你的膀胱来表达对你的失望？“哎哟，那是我的脚！”捏一下。真是一团糟。

显然，膀胱是一个类。它执行一种功能并具有状态。我们理解功能是什么，并且经常在最困难的时候感受到状态。幸运的是，膀胱被封装在皮肤、骨骼和天生的个人空间感之后。

这就是你应该看待封装和聚合的方式。封装使你能够将信息安全地放入类中，限制访问并避免尴尬情况。聚合使你能够将复杂类型安全地放入类中，同样限制访问并避免尴尬情况。

根据语义重要性判断特定信息组件应置于何处，并将该信息放入合适的类中。思考信息应放在哪里的一个好方法是思考拥有并保护该信息是谁的职责。（别让你的邻居拥有你的膀胱。）把聚合看作将复杂类型——也就是类——包含到新类型中。膀胱是一种复杂类型，而人体有一个部分是膀胱。

在专业医疗框架中，实现一个表示人体和膀胱的类可能是合适的。尽管如此，为方便起见，我们将扩展我们的 Radio 示例来演示聚合和封装。该清单展示了另一个类 BoomBox，它包含一个 AMFMRadio。AMFMRadio 体现了封装和聚合。

## 多态

多态已从各种角度得到描述。我多次看到有人提到它的希腊词根“多种形式”，有时描述又长又复杂。我要尝试一点不同的做法。我将使用一个希望你们能理解的类比。

假设你有一项适合孩子做的家务。我有四个孩子。我们让他们十八个月大就开始做家务。确实，小孩十八个月大就能倒垃圾桶。也许有点冷酷，但很实用。关系是这样的。

你正在看超级碗。比赛进入第四节，还剩两分钟，你的球队控球但落后8分。他们不仅要达阵，你的球队还需要完成两分转换。更添紧张的是，你还和赌注经纪人押了500美元赌你的球队赢。现在，你的啤酒没了。你需要啤酒，但不能离开比赛，因为等你回来比赛就结束了。你需要一个孩子跑腿买啤酒，任何孩子都行。

这就是多态。

当你有一个通用问题，而它可以由共同的一组提供者中的任意一个解决时，你就需要多态。
