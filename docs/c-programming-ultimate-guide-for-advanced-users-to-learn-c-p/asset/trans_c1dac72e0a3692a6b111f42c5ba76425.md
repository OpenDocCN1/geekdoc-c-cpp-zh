
### 线程池线程处理

ThreadPool 是一个为你管理线程池的类。利用 ThreadPool 中的线程进行多线程处理，与创建 Thread 对象是一样的。话虽如此，你手头的任务会得到一些帮助，而且从线程池中抓取一个线程通常比创建 Thread 类的实例要快一些，因为线程池中很可能已经有一个线程在等待你给它分配工作。

要在 ThreadPool 中使用线程，你只需要给 ThreadPool 一些工作作为委托即可。在这个示例中，该委托将充当一个方法，表示线程要执行的工作。线程处理的其他每个部分都与你自己创建 Thread 对象没有区别。要记住的最重要的一点是，ThreadPool 线程需要与 Thread 实例同等程度的关照，尤其是在涉及 Windows 窗体控件时。Windows 窗体控件不是线程安全的；因此，当从线程与 Windows 窗体控件交互时，必须格外小心。

### 在线程池中排队工作项

委托至关重要，没有委托事件处理程序就无法工作，而且在任何 C# 语言中不使用委托就无法使用多线程。回顾一下，委托包含至少一个方法的地址。线程处理的原理是向线程提供一个委托，该委托包含表示线程要完成工作的方法。

在清单 2-3 中，静态方法 Splash 创建了一个 Opacity 为 0 的 Splash 窗体。当 Form.Opacity 为 0 时，窗体是透明的；1 表示不透明窗体。当 Opacity 值在 0 和 1 之间时，就是半透明窗体。Splash 窗体以透明方式显示，线程将逐渐增大 Opacity 值，直到窗体不透明，此时线程完成。

Show 方法定义在清单 2-3 的第 11 至 26 行。这个 Show 方法通过修改 Opacity 来逐渐淡入窗体。遗憾的是，由于 Windows 窗体控件不是线程安全的，Opacity 必须在其所在线程上修改，而 Show 方法并不在该线程上。

我们实际更新 Opacity 值的方式是调用窗体的 Invoke 方法。Invoke 是线程安全的；Invoke 会将委托参数封送到调用项所在线程的同一线程上。（再次强调，没有委托，安全的线程处理就不可能实现。）

Invoke 需要一个 MethodInvoker 委托，并执行用于实例化该委托的方法内的代码。Increment 方法刷新 Opacity 值。done 字段用于指示窗体已不透明。我们在刷新 done 字段时对其加锁，从而阻止运行 Show 的线程在 done 值被刷新之前查看它。

最后，Show 利用 try/finally 构造来捕获异常并关闭窗体。例如，如果客户端在 Splash 窗体完全不透明之前关闭了应用程序，Show 将引用一个已释放的窗体（这在清单 2-3 的第 17 行）并引发异常。该异常处理程序会响应并提示应用程序立即关闭。

也许许多书没有展示完整应用程序的原因是，即使是创建基础应用程序也需要许多技能。正如本部分所示，简单的应用程序就可能涉及广泛的编程技能。
