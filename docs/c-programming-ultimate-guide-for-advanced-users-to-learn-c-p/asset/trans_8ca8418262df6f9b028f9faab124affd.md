
AssemblyViewer 使用不同的线程在应用程序启动时显示 Splash 屏幕。毫无疑问，这是一种奢侈，但如果启动屏幕是在单线程设计中执行的，那它还有什么意义？也就是说，当启动屏幕正在加载时，并没有发生真正的初始化，而且我从来不喜欢让启动屏幕包含初始化代码。（不过，你很可能会发现，许多启动屏幕实际上确实包含初始化代码。）

在我们的示例应用程序中，启动屏幕在它自己的线程上显示。在 .NET 中，有四种不同的方式可以模拟表面上的异步行为。Timer 控件和 Application.Idle 事件提供事件驱动的异步行为。控件支持异步的 BeginInvoke 和 EndInvoke。

ThreadPool 类提供一个可用线程池，而 Thread 类使你能够自行启动和管理线程。

AssemblyViewer 使用来自 ThreadPool 类的一个线程；因此，这里介绍的就是这种线程处理特性。

## ThreadPool 线程处理

ThreadPool 是一个为你管理线程池的类。使用 ThreadPool 中的线程进行多线程处理与创建 Thread 对象相同。不过，你的工作量会稍微减轻一些，而且从池中抓取线程通常比创建 Thread 类的实例要快一些，因为池中很可能有一个线程正等待你给它分配工作。

要使用 ThreadPool 中的线程，你只需以 Delegate 的形式给 ThreadPool 一些工作去做。在此示例中，Delegate 充当一种表示线程要执行的工作的机制。线程处理的其他所有部分都与你自行创建 Thread 对象相同。要记住的最重要一点是，ThreadPool 线程需要与 Thread 实例同样多的谨慎处理，尤其是在涉及 Windows Forms 控件时。Windows Forms 控件不是线程安全的；因此，当你从某个线程与 Windows Forms 控件交互时，应格外小心。

### 在 ThreadPool 中排队工作项

委托至关重要，以至于没有它们事件处理程序就无法工作，而且除非使用委托，否则在任何 .NET 语言中都无法使用多线程。简而言之，委托包含至少一个方法的地址。线程处理的工作原理是给线程一个委托，该委托包含表示该线程要完成的工作的方法。

在清单 2-3 中，静态方法 Splash 创建 Opacity 为 0 的 Splash 窗体。当 Form.Opacity 为 0 时，窗体是透明的；1 表示不透明窗体。当 Opacity 值介于 0 和 1 之间时，你会得到半透明窗体。Splash 窗体以透明方式显示，线程会逐渐增大 Opacity 值，直到窗体不透明，此时线程就完成了。

Show 方法定义在清单 2-3 的第 11 行到第 26 行。这个 Show 方法通过修改 Opacity 逐渐淡入窗体。不幸的是，由于 Windows Forms 控件不是线程安全的，Opacity 必须在它所属的同一线程上更改。而 Show 方法不在那个线程上。

我们实际更新 Opacity 值的方式是调用窗体的 Invoke 方法。Invoke 是线程安全的；Invoke 会将委托参数封送到调用对象所在线程的同一线程中。（再次说明，没有委托，安全线程处理将不可能实现。）

Invoke 需要一个 MethodInvoker 委托，并执行用于初始化该委托的方法内部的代码。Increment 方法更新 Opacity 值。done 字段用于指示窗体不透明。我们在更新 Done 方法时锁定它，防止运行 Show 的线程在 Done 值更新之前检查该值。

前两条语句创建两个复数的实例。最后一条语句调用 operator+ 方法，将一个新对象返回给变量 e。

## 理解重载运算符的最佳方式

理解重载运算符的最佳方式是编写一些简单示例，并在调用运算符的语句中以及运算符方法中设置断点。你很快就会观察到，该操作会导致方法调用。

## 重载运算符的准则和限制

定义重载运算符时要谨慎。最重要的一点是避免做出古怪的运算符。例如，重载加法运算符来执行减法。不要这样做。遵循以下重载运算符的基本规则可以让你避免麻烦：

- 定义执行该操作的方法，使用 op_ 前缀后跟运算符名称，以支持 Visual Basic .NET 等不支持运算符重载的语言。
- 通过调用命名方法来实现重载运算符。（为什么要将运算符行为重复两次？）
- 仅在运算符适用的类中重载该运算符。
- 当操作直观且结果看起来合乎逻辑时，使用运算符重载。
- 对称地重载运算符。如果你实现了加法，那么也要实现减法。

## 特性

正是像 interface 和 attributes 这样的术语让我们作为软件工程师陷入困境。解释在于这些术语承担了双重职责。很长一段时间里，“interface”本质上指类中声明的成员。当引入 COM 时，interface 又有了另一层含义；interface 成为一种构造——非常像类。（对于 VB 开发者来说，接口和类的界限非常模糊。）

“attribute”和惯用语 Attribute 也存在类似问题。在一般意义上，“attribute”与“property”同义。特性是类型的属性。.NET 的 Attribute 本身实际上是一个类。（围绕特性的令人困惑的讨论，很可能和关于父与子、超类与子类、对象与类的讨论一样多。）

在 C# 中，大写 A 的 Attribute 将是一个向程序集添加元数据的类。

添加元数据（即额外信息）是为了帮助消除“DLL 地狱”。从历史上看，应用程序所需的外部信息存储在库或 INI 文件中。属性使这些辅助信息能够随程序集一起提供。Attribute 类使你能够向程序集添加元数据，而 Reflection 使你能够在需要时检索该元数据。这非常类似于从库中读取和写入。由于元数据被巧妙地折叠到程序集中，部署 .NET 应用程序比交付基于 COM 的应用程序更容易。

特性的示例可以在 AssemblyInfo.cs 模块中找到。一个示例是 AssemblyTitleAttribute 类。

通过在 AssemblyTitleAttribute 的方括号之间包含内容，你可以为程序集包含一个将出现在“属性”对话框中的标题。按照约定，特性类带有 Attribute 后缀，但在使用特性时会省略该后缀。assembly: 标记表明这是一个程序集级特性。

由于特性是作为类实现的，你可以泛化现有的 Attribute 类，以便为新用途创建新的特性。特性用于许多方面，从为组件属性提供提示到请求安全权限。将会创建大量新特性，但使用 Attribute 的模式类似于开发对象。将 Attribute 类的名称放在该 Attribute 所描述的元素之前，并传递由该 Attribute 的构造函数定义的参数。构造函数参数称为位置参数。你同样可以通过传递命名参数来初始化 Attribute 对象中的属性。
