### 在循环内部控制循环
当你在 for 循环内部声明一个变量时，有一点很重要需要记住：该变量的作用域在 for 语句结束时结束。

关于 break 请记住。首先，一个循环中可能出现多个 break 语句，但要谨慎。过多的 break 语句往往会破坏你的代码。其次，退出 switch 语句的 break 只影响该 switch 语句本身，不会影响任何外层循环。第三，C# 的创建者没有为 break 或 continue 提供那种功能。相反，break 和 continue 在 C# 中的工作方式与在 C 和 C++ 中相同。C# 在这个问题上没有遵循 Java 的做法的一个原因是 Java 不支持 goto 语句，而 C# 支持。因此，Java 需要为 break 和 continue 提供额外的功能，以弥补 goto 的缺失。

可以强制提前进行循环的迭代，绕过循环的正常控制结构。这是通过使用 continue 实现的。continue 语句强制执行循环的下一次迭代，跳过中间的任何代码。因此，continue 基本上是 break 的补充。例如，它可以导致对 WriteLine() 的调用被跳过。在 while 和 do-while 循环中，continue 语句会使控制直接转到条件表达式。对于 for，循环的迭代表达式会被求值，然后执行条件表达式。

continue 的良好用法并不常见。一个原因是 C# 提供了丰富的循环语句，适用于大多数应用。然而，对于需要提前迭代的特殊情况，continue 语句提供了一种有条理的实现方式。

### goto 语句
goto 是 C# 的真正跳转语句。当遇到它时，程序流程会跳转到 goto 指定的位置。该语句多年前在软件工程师中失宠，因为它鼓励创建“意大利面条代码”，即由真正的跳转组成的混乱堆，导致代码难以理解。尽管如此，goto 仍有时被使用——在某些情况下使用得相当成功。本书不会对其作为程序控制形式的有效性做出判断。然而，应该指出的是，没有任何编程情况要求使用 goto 语句——它并不是使语言完整所必需的东西。相反，它是一种便利，只要明智使用，在某些编程情况下可以带来优势。因此，除本节外，本书中不会使用 goto。多数软件工程师对 goto 的主要担忧是它倾向于搞乱程序，使其几乎无法辨认。尽管如此，有时使用 goto 可以澄清程序流程，而不是使其混乱。goto 需要一个标签来操作。标签是一个有效的 C# 标识符后跟冒号。此外，标签必须与使用它的 goto 位于同一方法中。去掉 goto 将迫使使用三个 if 和 break 语句。在这种情况下，goto 简化了代码。虽然这是一个为说明而构造的示例，但你可以设想 goto 可能有用的真实情况。

goto 有一个重要的限制：你不能跳转到一个块内部。显然，你可以从一个块中跳出，正如第一个示例所示。goto default 跳转到 default 标签。goto case 1 跳转到 case 1。由于上述限制，你不能从 switch 外部的代码跳转到 switch 的中间，因为 switch 定义了一个块。因此，这类 goto 语句必须从 switch 内部执行。正如你在一些早期示例中看到的，一个循环可以嵌套在另一个循环内部。嵌套循环用于解决各种编程问题，是编程的重要组成部分。因此，在离开 C# 循环语句的主题之前，让我们再看一个嵌套循环示例。下面的程序使用嵌套的 for 循环来查找 2 到 100 的数字的因子：
