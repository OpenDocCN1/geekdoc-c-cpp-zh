
The general form of a class definition that contains just instance variables and methods is shown here:

```
class classname {
// Declare instance variables.
access type var1;
access type var2;
// ...
access type varN;
}
```

Notice that every field and method is preceded with access. Here, access is an access specifier, for example, public, which indicates how the member can be accessed. As referenced in Section 1, class members can be private to a class or more public. The access specifier determines what kind of access is permitted. The access specifier is optional and, if missing, the member is private to the class. Members with private access can be used only by other members of their class. For the examples in this section, all members (with the exception of the Main() method) will be declared as public. This means they can be used by all other code—even code defined outside the class. (The Main() method will continue to use the default access because this is the currently recommended practice.) We will return to the subject of access specifiers in a later section, after you have learned the basics of the class. Although there is no syntactic rule that enforces it, a well-structured class should define one and only one logical entity. For instance, a class that stores names and phone numbers will not normally also store data about the stock market, average precipitation, sunspot cycles, or other unrelated data. The point here is that a well-designed class groups consistently associated data. Placing unrelated data into the same class will rapidly destroy your code!

## How Objects Are Created:

In the previous projects, the following line was used to create an object of type

**Vehicle:**

```
Vehicle minivan = new Vehicle();
```

This declaration performs three functions. First, it declares a variable called minivan of the class type Vehicle. This variable is not, itself, an object. Rather, it is simply a variable that can refer to an object. Second, the declaration creates a real, physical instance of the object. This is done by using the new operator. Finally, it assigns to minivan a reference to that object. Thus, after the line executes, minivan refers to an object of type Vehicle. The new operator dynamically allocates (that is, allocates at runtime) memory for an object and returns a reference to it. This reference is then stored in a variable. Thus, in C#, all class items must be dynamically allocated.

As you may expect, it is possible to separate the declaration of minivan from the creation of the object to which it will refer. The first line declares minivan as a reference to an object of type Vehicle. Thus, minivan is a variable that can refer to an object, but it is not an object itself. The next line creates a new Vehicle object and assigns a reference to it to minivan. Now, minivan is associated with an object. The fact that class objects are accessed through a reference explains why classes are called reference types.
