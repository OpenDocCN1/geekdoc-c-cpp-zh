
## Classes

When you describe an inheritance relationship, there are at least two classes required. One class is the parent and the second is the child. (The association between parent and child is also called superclass and subclass, where superclass is synonymous with parent and subclass is synonymous with child.) Such a parent-child relationship is referred to as an IsA relationship. For example, I am a descendant of my father (and mother), so I am a Kimmel (and Symons), gaining the DNA that comes from the Kimmels (and Symons).

When you describe an inheritance relationship in C#, the child class gets all of the members described in the parent class. When you inherit, you get all of the fields, properties, and methods described in the parent. Rather than chromosomal inheritance, object-oriented inheritance means you get everything.

I consider that you get inheritance, but there is one more description that I'd like to show since inheritance is an important concept. If class B inherits from class A, then logically, an instance of B would be class A.

The notation for inheritance is the same as that for interface inheritance. To show that class B inherits from class A, you would write the class header as follows:

```
public class B : A
```

Unlike with interface inheritance, when you inherit from a class, you don't have to implement any methods from the parent class because they are already implemented in the parent class.

When you have a general problem that can be solved by any provider within a common set of providers, then you need polymorphism.

Keep in mind that I said that inheritance is also referred to as generalization? ## Utilizing Modifiers

Modifiers address data hiding. Data hiding embodies the saying "out of sight, out of mind." That is, as a maker, if you can hide something from a consumer, then they don't need to worry about it. Consequently, out of mind.

Access modifiers allow you to put things out of mind when you are programming. When creating classes, make just those things public that consumers need to interact with to use the class. By restricting what you expose in the public interface, you make it easier to consume your classes. This is true whether or not you are the primary consumer of the classes you produce.

There are a few access modifiers to choose from. C# supports public, protected, internal, protected internal, private, and readonly for fields. The bulleted list quickly describes the purpose of each access modifier.

- The public modifier gives unrestricted access to types and members.
- The protected access modifier gives unlimited access inside and to child classes and limited access to consumers. The protected access modifier can be applied to nested types.
- The private access modifier gives the most limited access. Only the creator of a class may use its private members. Consumers and children have no access to private members. The private access modifier can be applied to nested types.
- The internal access modifier means that types and members are available only inside the same assembly. The internal modifier is used to enable code to work internally across class boundaries without exposing those components to consumers outside the assembly.
- The protected internal modifier limits access to the same assembly for nested types.

When declaring top-level types, you should use the public or internal access modifier. You may use private and protected access for types only when those types are nested. A nested type is a type definition that is contained within another type definition.

You may not combine access modifiers, with the exception of the protected internal modifier. You may not use access modifiers on namespaces. If you don't specify an access modifier, then a default access level will be used. It is best to explicitly show the level of access rather than relying on a default access.

### Utilizing Class Modifiers

When you define classes and the enclosing element is a namespace, then the class can be defined to have public or internal access. If you don't specify a modifier for a top-level class, then the class will have public access.

Nested classes can be defined with any access modifier, but you may only use protected, protected internal, and private access modifiers on nested classes.

Class access modifier rules apply to any struct and enum types, as well.

You may use any access modifier on members of types, as well. If you define members without an access modifier, then members are private by default.

Basic operators, like the addition operator, +, exist for value types. An example of a value type is an integer, like 5. It is intuitive to perform operations like 5 + 4 on integer types.
