编程语言的下一次重大进步是 Java。Java 的开发于 1991 年在 Sun Microsystems 开始，最初名为 Oak。Java 设计的主要推动者是 James Gosling，Patrick Naughton、Chris Warth、Ed Frank 和 Mike Sheridan 也发挥了作用。

Java 是一种面向对象的语言，其语法和语义源自 C++。Java 的创新部分与其说是由编程艺术的进步所驱动（虽然确实有），不如说是由计算环境的变化所驱动。在互联网成为主流之前，大多数程序都是针对特定 CPU 和特定操作系统编写、编译和执行的。

虽然程序员总是喜欢重用代码，但将程序从一个环境轻松移植到另一个环境的能力，相对于更紧迫的问题而言，优先级较低。然而，随着互联网的兴起，许多不同种类的 CPU 和操作系统相互连接，可移植性这个老问题变得越来越重要。为了解决这个问题，需要另一种语言，这种新语言就是 Java。

Java 通过将程序源代码翻译成一种称为字节码的中间语言来实现可移植性。然后由 Java 虚拟机（JVM）执行该字节码。这样，Java 程序就能在任何有 JVM 可用的环境中运行。此外，由于 JVM 相对容易实现，它在众多环境中都很容易获得。

虽然可移植性的需求很重要，但在基于互联网的编程成为现实之前，还有第二个基本问题必须解决。这个问题就是安全性。正如所有互联网用户所知，计算机病毒构成了非常现实且持续的威胁。如果没人能信任可移植程序，那它们还有什么用呢？谁愿意冒险执行通过互联网传送的程序呢？它可能包含恶意代码。幸运的是，安全问题的解决方案也存在于 JVM 和字节码中。由于 JVM 执行字节码，它完全控制程序，并能阻止 Java 程序做它不应该做的事情。这样，JVM 和字节码同时解决了可移植性和安全性这两个问题。

必须从根本上理解，Java 对字节码的使用不同于 C 和 C++，后者总是被编译成可执行的机器代码。机器代码与特定的 CPU 和操作系统绑定。因此，如果你想在不同的系统上运行 C/C++ 程序，就必须针对该环境将其重新编译为机器代码。要使 C/C++ 程序能在多种环境中运行，就需要该程序的多个不同可执行版本。虽然这是可能的，但成本很高。Java 使用可移植的中间语言是一种经济高效的方案。这也是 C# 为实现自身目的而采用的方法。

如前所述，Java 源自 C 和 C++。其语法基于 C，其对象模型基于 C++。虽然 Java 代码与 C 或 C++ 既不向上兼容也不向下兼容，但其语法足够相似，因此大量现有的 C/C++ 程序员可以毫不费力地转向 Java。此外，由于 Java 在一种经过验证的方法之上进行了构建和改进，Gosling 等人得以将精力专注于新的创新特性。正如 Stroustrup 在创建 C++ 时不必“重复解决已经解决的问题”，Gosling 在创建 Java 时也不必创造一种全新的语言。

## Java 只写属性

只写属性声明只有 setter。只写属性不如只读属性常见，因为读取属性比写入属性更难造成危害。

你可能想使用可写属性的一个场合是在查询密码时。你可能不想在密码提供后让使用者有机会询问提供了什么密码。也许某个恶意开发者会窥探包含密码的对象。

Java Studio 的帮助文档指出不要使用只写属性。从语义上讲，只写属性是修改对象的方法，而没有读取已更改值的方法。你可以为只写属性发明一个有用的短语。对于只写属性没有技术限制。
