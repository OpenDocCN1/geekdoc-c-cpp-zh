
通过定义作用域，可以防止作用域之外的代码访问或修改它。作用域规则为封装提供了基础。

作用域可以嵌套。例如，每次创建代码块时，都会创建另一个嵌套作用域。此时，外层作用域包围内层作用域。这意味着在外层作用域中声明的局部变量对内存作用域中的代码可见。然而，反过来则不成立。在内层作用域中声明的局部变量在该作用域之外不可见。

正如注释所示，变量 `x` 在 `Main()` 作用域的开头声明，并且对 `Main()` 内所有后续代码开放。在 `if` 块内声明了 `y`。由于块定义了作用域，`y` 仅对其块内的其他代码可见。这就是为什么在其块外，`y = 100;` 这一行被注释掉了。如果删除第一个注释符号，就会发生编译时错误，因为 `y` 在其块外不可见。在 `if` 块内可以使用 `x`，因为块内（即嵌套作用域）的代码可以访问外层作用域声明的变量。

如果你有 C/C++ 背景，就会知道对内层作用域中声明的变量命名没有限制。因此，在 C/C++ 中，在外层 `for` 循环的块内声明 `count` 是完全合法的。然而，在 C/C++ 中，这种声明会隐藏外层的 `count`。C# 的设计者认为这种名称隐藏很容易导致编程错误，因此将其禁止了。

### 定义接口

`IListener` 接口定义了两个方法：`Listening` 和 `Listen`。`Listening` 是一个返回布尔值的函数，指示实现 `IListener` 接口的对象是否希望接收消息。这使对象可以形象地“堵住耳朵”，而无需从 `Broadcaster` 注销。`Listen` 方法是在监听时接收字符串内容的方法。

你可以通过实现 `IListener` 接口来使用 `Broadcaster`。`FormMain` 类实现 `IListener`，以在状态栏中显示广播消息。对于主窗体，可以在窗体的 `Load` 事件中将该窗体添加到监听器列表中。另一个添加控件的好地方是你编写的实际程序。

在 C# 中，值类型的变量包含其自身的值。保存此值的内存在程序运行时自动分配。因此，无需使用 `new` 显式分配此内存。另一方面，引用变量存储对对象的引用。保存此对象的内存在执行期间动态分配。不将 `int` 或 `char` 等基本类型设为引用类型，会显著提高程序性能。使用引用类型时，存在一层间接寻址，这会增加每次对象访问的开销。值类型避免了这种开销。

### using 语句：

你会看到 `using` 关键字的两个地方。`using` 语句用于导入命名空间，并作为用于释放对象的块语句。

清单 2-1 展示了如何使用命名空间。可以将 `using` 语句视为添加对 DLL 的引用。框架中的程序集实际上包含在 DLL 文件中；因此，`using System.Reflection;` 意味着一个以单词 System 开头的 DLL。

你可以通过导航到 `C:\WINNT\Microsoft.NET\Framework\v1.0.3705\` 来检查 .NET Framework 中的程序集。

### 使用 using 指令创建别名

你可以使用 `using` 指令为命名空间创建别名。将 `using System.Diagnostics;` 改为 `using Diag = System.Diagnostics;` 会为 `System.Diagnostics` 命名空间创建一个名为 `Diag` 的别名。在任何要使用完全限定的 `System.Diagnostics` 命名空间的地方，都可以将其替换为别名 `Diag`。

### 描述 using 作用域

`using` 的第二种用法类似于 VB.NET 中的 `Using` 语句。当你在代码中对对象使用 `using` 语句时，你定义了一个作用域，该作用域会在 `using` 块结束时自动释放对象。只要在 `using` 块中创建的对象实现了 `IDisposable` 接口，那么即使在 `using` 块结束前抛出异常，对象也会被释放。
