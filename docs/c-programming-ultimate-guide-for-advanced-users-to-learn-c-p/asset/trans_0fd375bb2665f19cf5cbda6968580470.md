## C# 的演进：

自最初的 1.0 版本发布以来，C# 一直快速发展。C# 1.0 发布后不久，微软发布了 1.1 版。它包含许多细微更改，但没有重大新特性。然而，随着 C# 2.0 的到来，情况完全不同。这是 C# 生命周期中的分水岭事件，因为 2.0 版包含许多新特性，例如泛型、分部类型和匿名方法，从根本上扩展了语言的范围、能力和作用域。2.0 版牢固地将 C# 置于编程语言发展的前沿。它也展示了微软对该语言的长期承诺。

## 语言运行时的工作原理：

公共语言运行时（CLR）负责 .NET 代码的执行。其工作原理如下。当你编译 C# 程序时，编译器的输出并不是可执行代码。相反，它是一个文件，其中包含一种称为 Microsoft 中间语言（简称 MSIL）的特殊伪代码。MSIL 定义了一组与特定 CPU 无关的可移植指令。基本上，MSIL 定义了一种可移植的低级汇编语言。另一点是，尽管 MSIL 在概念上类似于 Java 的字节码，但二者并不相同。CLR 的职责是在程序运行时将中间代码转换为可执行代码。因此，任何编译为 MSIL 的程序都可以在运行 CLR 的任何环境中运行。这是 .NET Framework 实现可移植性的一部分。

Microsoft 中间语言通过 JIT 编译器转换为可执行代码。JIT 意为“即时”。其过程如下：当执行 .NET 程序时，CLR 会激活 JIT 编译器。JIT 编译器会按需将 MSIL 转换为本地代码，即当程序的每个部分需要时进行转换。因此，你的 C# 程序实际上以本地代码执行，尽管它最初被编译为 MSIL。这意味着你的程序运行速度几乎与一开始就编译成本地代码时一样快，同时还能获得 MSIL 的可移植性和安全性优势。除了 MSIL 之外，编译 C# 程序时还会产生另一样东西：元数据。

元数据描述程序所使用的信息，并使你的代码能够与其他代码交互。元数据与 MSIL 包含在同一个文件中。幸运的是，就本书而言，并且对大多数编程任务来说，没有必要进一步了解 CLR、MSIL 或元数据。C# 会为你处理这些细节。

## 托管代码与非托管代码：

通常，当你编写 C# 程序时，你创建的是所谓的托管代码。托管代码在公共语言运行时的管理下执行，正如刚才所述。由于托管代码在 CLR 的管理下运行，因此它受到某些约束——同时也带来一些好处。这些限制已被清晰描述并得到满足。编译器必须创建面向 CLR 的 MSIL 文件（C# 会这样做），并使用 .NET Framework 类库（C# 也会这样做）。托管代码的优点很多，包括现代内存管理、混合语言的能力、更好的安全性、版本控制支持，以及编程组件协作的理想途径。

与托管代码相对的是非托管代码。非托管代码不在公共语言运行时下执行。因此，在 .NET Framework 创建之前，所有 Windows 程序都使用非托管代码。托管代码和非托管代码可以互操作，因此 C# 生成托管代码这一点，并不限制其与以前的程序协同工作的能力。
