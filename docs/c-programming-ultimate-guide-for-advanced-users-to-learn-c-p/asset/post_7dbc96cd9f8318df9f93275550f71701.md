In C#, a method can call itself. This process is called recursion, and a method that calls itself is said to be recursive. In general, recursion is the process of defining something in terms of itself and is somewhat like a circular definition. The key part of a recursive method is that it contains a statement that executes a call to itself. Recursion is a powerful control mechanism. The classic example of recursion is the calculation of the factorial of a number. The factorial of a number N is the product of all the whole numbers between 1 and N. For example, 3 factorial is 1 × 2 × 3, or 6. The accompanying program demonstrates a recursive method to compute the factorial of a number. For comparison purposes, a nonrecursive equivalent is also included. For example, given

```
int x;
x = 10;
```

x contains the value 10 because x is a variable of type int, which is a value type. However, in the case of

```
Vehicle minivan = new Vehicle();
```

minivan doesn't, itself, contain the object. Rather, it contains a reference to the object. In an assignment operation, reference variables act differently than do variables of a value type, such as int. When you assign one value type variable to another, the situation is clear. The variable on the left gets a copy of the value of the variable on the right. When you assign one object reference variable to another, the situation is more complicated because you are making the variable on the left refer to the object referred to by the variable on the right. At the outset, it is easy to imagine that car1 and car2 refer to different objects, but this isn't the case. Rather, car1 and car2 will both refer to the same object. The assignment of car1 to car2 just makes car2 refer to the same object as does car1. In this manner, the object can be acted on by either car1 or car2.

As explained, instance variables and methods are two of the essential constituents of classes.

So far, the Vehicle class contains data, but no methods. Although data-only classes are perfectly valid, most classes will have methods. Methods are subroutines that manipulate the data defined by the class and, as a rule, provide access to that data. Commonly, different parts of your program will interface with a class through its methods. A method contains at least one statement. In well-written C# code, each method performs just one task. Every method has a name, and this name is used to call the method. By and large, you can name a method using any valid identifier that you please. However, remember that Main( ) is reserved for the method that starts execution of your program. Additionally, don't use C#'s keywords for method names. When denoting methods in text, this book has used and will continue to use a convention that has become common when writing about C#. A method will have parentheses after its name. For example, if a method's name is GetVal, it will be written GetVal( ) when its name is used in a sentence. This notation will help you distinguish variable names from method names in this book.

The general form of a method is shown here:

```
access ret-type name(parameter-list) {
    // body of method
}
```

Here, access is an access modifier that governs what other parts of your program can call the method. As explained earlier, the access modifier is optional. If not present, the method is private to the class in which it is declared. Until further notice, we will declare methods public so that they can be called by any other code in the program. The ret-type specifies the type of data returned by the method. This can be any valid type, including class types that you create. If the method does not return a value, its return type must be void. The name of the method is specified by name. This can be any valid identifier other than those which would cause conflicts within the current declaration space. The parameter-list is a list of type and identifier pairs separated by commas. Parameters are essentially variables that receive the value of the arguments passed to the method when it is called. If the method has no parameters, the parameter list will be empty.

As just explained, the methods of a class normally manipulate and provide access to the data of the class. In view of this, recall Main( ) in the former examples computed the range of a vehicle by multiplying its fuel consumption rate by its fuel capacity. While technically correct, this isn't the best way to handle this calculation. The computation of a vehicle's range is something that is best handled by the Vehicle class itself. The reason for this conclusion is easy to understand: The range of a vehicle is dependent upon the capacity of the fuel tank and the rate of fuel consumption, and both of these quantities are encapsulated by Vehicle. By including a method to Vehicle that computes the range, you are improving its object-oriented structure. To add a method to Vehicle, declare it inside Vehicle's declaration. For instance, the following version of Vehicle contains a method called Range( ) that displays the range of the vehicle. Let's take a look at the key components of this program, starting with the Range( ) method itself.

The first line of Range( ) is

```
public void Range() {
```

This line declares a method called Range that has no parameters. It is specified as public, so it can be used by any other part of the program. Its return type is void. Accordingly, Range( ) doesn't return a value to the caller. The line ends with the opening curly brace of the method body. The body of Range( ) consists exclusively of this line:

```
Console.WriteLine("Range is " + FuelCap * Mpg);
```

This statement displays the range of the vehicle by multiplying FuelCap by Mpg. Since each object of type Vehicle has its own copy of FuelCap and Mpg, when Range( ) is called, the computation uses the calling object's copies of those variables. The Range( ) method ends when its closing curly brace is encountered. This causes program control to move back to the caller. Next, take a look at this line of code from inside Main( ):

```
minivan.Range();
```

This statement invokes the Range( ) method on minivan. That is, it calls Range( ) relative to the object referred to by minivan, by use of the dot operator. When a method is called, program control is moved to the method. When the method ends, control is moved back to the caller, and execution resumes with the line of code following the call. In this case, the call to minivan.Range( ) displays the range of the vehicle defined by minivan. Similarly, the call to sportscar.Range( ) displays the range of the vehicle defined by sportscar. Each time Range( ) is invoked, it displays the range for the specified object.

There is something important to see inside the Range( ) method: The instance variables FuelCap and Mpg are referred to directly, without use of the dot operator. When a method uses an instance variable that is defined by its class, it does so directly, without explicit reference to an object and without use of the dot operator. This is easy to understand. A method is always invoked relative to some object of its class. Once this invocation has occurred, the object is known. Thus, inside a method, there is no need to specify the object a second time. This means FuelCap and Mpg inside Range( ) implicitly refer to the copies of those variables found in the object that invokes Range( ).
