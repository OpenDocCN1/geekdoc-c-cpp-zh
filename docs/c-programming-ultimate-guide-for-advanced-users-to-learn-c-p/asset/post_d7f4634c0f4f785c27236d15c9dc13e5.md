For instance, in C++, you use the delete operator to free memory that was allocated. However, C# uses a different, more problem-free approach: garbage collection. C#'s garbage collection framework reclaims objects automatically—happening directly, off camera, with no programmer intervention. It works this way: When no references to an object exist, that item is thought to be no longer required, and the memory occupied by the item is released. This reused memory can then be used for a subsequent allocation.

Garbage collection happens only sporadically during the execution of your program. It will not happen just because one or more objects exist that are no longer used. Therefore, you can't know exactly when garbage collection will happen. It is possible to define a method that will be called just before an object's final destruction by the garbage collector. This method is known as a destructor, and it can be used in some highly specialized circumstances to ensure that an object ends neatly. For instance, you may use a destructor to ensure that a system resource owned by an object is released. It must be stated at the start that destructors are an advanced feature that are suited to certain specific circumstances. They are not ordinarily required. However, since they are a part of C#, they are briefly described here for completeness.

### Constructors

There are two special methods, the constructor and the destructor. Constructors have the exact same name as the class. No other members may have the same name—where same applies to case, also—as the class, other than the constructor. Constructors can have zero or more parameters and don't have return types. (We'll talk about the destructor in the following section.) Constructors are overloaded just by incorporating additional constructors with distinct signatures. The following bulleted list gives an overview of constructor rules.

- If a class has only static members, then implement a private constructor to prevent instances from being created.
- Keep constructors short, performing only simple tasks like parameter-to-field assignment in the constructor. This technique enables objects to be created quickly.
- Provide a protected constructor for use by derived classes.
- As a rule, don't implement an empty constructor for structs. If you don't provide the empty parameterless constructor for structs, the compiler incorporates a default constructor that initializes all members to their default values.
- Use constructor parameters to set properties. Building classes with parameters or creating objects with the default constructor and assigning properties should yield a similar result.
- Be consistent when naming parameters. A common practice is to incorporate an increasing number of parameters for each overloaded constructor.

C# utilizes non-deterministic destruction. The CLR implements a garbage collector that cleans up memory when objects are no longer used. This implies you don't need to worry as much about destructors in C# as you do in C++ or Delphi.

The garbage collector will call the destructor for your objects when they are no longer required. The destructor will call any Finalize method. You can force garbage collection by calling GC.Collect, but this isn't a recommended practice. The garbage collector suspends any running threads, which can mess up performance. Also, the garbage collector will do a fine job of deciding when to run.

## Executing a Dispose Method

If you have unmanaged resources in your classes, then you can implement a Dispose method to help deterministic cleanup. By enabling consumers to call a Dispose method, you can give the consumer a chance to choose when they are done with files or system connections.

Use a pattern like the following to implement a Dispose method.

- First, you declare a private field, disposed, to be used to track whether the Dispose method has been called already, initializing disposed to False.
- In the Dispose method, verify whether Dispose has already been called and return if it has.
- Perform the cleanup and then call the GC.SuppressFinalize() method, passing the reference to the object whose Finalize you need to suppress.
- Finally, set the field disposed to True.

A great deal of the time you won't need to implement a destructor or a Dispose method. Managed objects in the CLR will be garbage collected automatically. Implement a destructor and Dispose method only if you are certain you need them.
