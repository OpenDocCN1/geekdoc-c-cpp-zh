
为了调整图像控制的强度，以适应扩展的思考层次对当前机器速度、存储和传输通道带宽的物理需求。至今仍在世的一些人，还能谈论如何手持纸板尺对准示波器，将信号判定为 1 或 0，从而读取现存最先进的计算机的输出。直到 20 世纪 80 年代中期，广泛使用的最强大的计算机（DEC PDP 系列）仍可通过拨动面板上的开关来编程，直接控制芯片级信号。此外，直到 20 世纪 90 年代，计算机程序员如果对各种中断请求和不同设备的内存位置不熟悉，那是不可想象的。

20 世纪 60 年代中期，IBM 360 发布，戈登·摩尔提出了他那条广为人知的定律，即给定区域内的晶体管密度会每隔一段时间持续翻倍。自那时以来，单条处理指令的成本已下降约 99.99%。这彻底改变了编程的经济性。过去，软件工程师在头脑中建立计算机内部表示模型，并牺牲开发时间以换取执行效率，这种做法是有意义的；而现在，让计算机拥有与开发者对任务的内部表示相对应的模型才有意义，即使这种表示并非理想高效。

如今，评判一种编程语言质量的标准，是它能多有效地表达各种各样的问题和解决方案。按照这一标准，面向对象的过程式编程语言完全主宰了软件开发世界。过程式语言是这样一种语言：向计算机发出一个指令序列：做这个，然后做那个，然后再做另一件事。过程式方法可能看起来是编程的“自然”方式，因为它与我们关于计算机如何工作的心智模型有关；但正如上文所讨论的，这不再是一个选择编程语言的好理由。想想用电子表格解决几个问题有多简单，电子表格可以被看作一种非过程式编程。无论如何，过程式编程已经深深植根于标准的时代精神之中，并且是……

这并不意味着 ASP.NET 和 Visual Basic 是差劲的语言；恰恰相反，这意味着它们的编程模型非常灵活，以至于要在其中做出非凡的工作，确实需要比使用 C# 时更多的理解力和控制力。

## 点对点：

当月最后的网络技术流行词之一是点对点（peer-to-peer，也称为 P2P，P2P 在营销上的优势在于，它与当月最后的商业流行词之一——“生产率之路”——的缩写相同）。出乎意料的是，P2P 正是人们从“万维网”这一表述中预期到的那种工程。在 P2P 设计中，服务的创建分为两个阶段：首先通过某种集中式服务器找到对等资源（无论该服务器是否处于规划组织的合法控制之下），然后将对等点连接起来进行资源共享，此后无需任何更多干预。

C# 和 .NET 为创建 P2P 系统提供了强大的工具，毕竟这类系统需要创建富客户端、精良的服务器，以及构建健壮资源共享系统的工具。P2P 因文件共享系统的盛行而蒙上污名，但 SETI@Home 和 Folding@Home 等项目展示了分布式计算的潜力，这种计算能够运用惊人的计算量，成为解决问题的强大工具。

以 HTML 为基础所创造的价值是惊人的。以明显更灵活、更具表现力的可扩展标记语言（XML）为基础所将创造的价值将超越以往的一切（或许在股价和公司估值方面并非如此，但在实际盈利能力和生产率方面，毫无疑问）。Web 服务通过标准 Web 协议和基于 XML 的数据表示来传递价值，这种表示不关心内容如何显示（Web 服务是无头的）。

Web 服务是微软整个 .NET 方法存在的理由，而这一方法的广度令人印象深刻，它不仅仅是 10 年来编程 API 的最大更新。许多商业记者错误地将 .NET 解读为微软试图将自身定位为 Web 交易中的中央中介。事实其实更简单：微软希望拥有所有联网设备上的操作系统，即便这类设备的类型和数量正急剧增长。计算机越是更多地从执行基本的计算任务转向通信和控制任务，Web 服务能够提供的就越多，而微软一直明白，操作系统的主导地位受到软件开发的制约。

无论如何，.NET 系统都是微软和软件开发向“后桌面”现实迈出的一步。.NET Framework 结合了对底层硬件的抽象与广泛的应用程序编程接口（API），它向工程师表明，“一次编写，到处运行”是一种在时间顺序上错误的观点，它推进了组件在计算机上运行的理念。.NET 方法认识到，在各种设备上运行的富客户端（“富客户端”指不仅仅负责显示和数据能力，还负责更多计算的非服务器应用程序）、强大的服务器，以及在不可放弃的桌面“旧式”机器上运行的新应用程序，根本不是相互分离的市场，而是所有软件应用程序从根本上都需要应对的细分市场。无论软件工程师是为其 Web 服务从基于浏览器的客户端开始（或者说，无论软件工程师是为基于 Java 的 Web 服务开发基于 Windows 的富客户端），.NET 方法的一部分就是让价值扩展到另一台设备上变得无比容易：PocketPC 或 3G 手机上的富客户端，或者后端机架中更好的数据库。Web 协议将连接所有这些设备，但价值在于数据，数据将通过 Web 服务流动。如果 .NET 是创建 Web 服务最具催化作用的方法，微软必然会在所有设备领域中赢得市场份额。

微软的编码质量常常被不公平地评判。只有 Windows 会因为它不能运行于某些生僻硬件配置而受到评判；Microsoft Office 安装时可能会占用令人恼火的磁盘空间，但它足够稳定和适用，足以占据商业世界。然而，微软真正搞砸的是安全。微软通常把安全做成要么全赢、要么全输的选择，这已经够糟了（“启用宏：是还是否？”“安装此控件（永久）：是还是否？”），但更不可原谅的是，他们给出这个非赢即输的选择时不提供任何信息（“请确保您信任发件人！”）。当你考虑到普通 PC 上来来往往的文件数量，以及许多用户缺乏长进时，唯一令人惊讶的是，真正破坏性的攻击竟然如此罕见。

.NET Framework SDK 包含一个新的安全模型，该模型基于细粒度权限（用于访问文件系统或网络等操作）以及基于公钥加密和证书链的数字签名。虽然微软宣称的“可信计算”目标超出了安全的范畴，将要求其操作系统以及——也许更根本地——在法律上对 Microsoft Office 和 Outlook 进行重大改变，但 .NET Framework SDK 提供了现代组件，可以想象这些组件将带来一个更安全的计算环境。
