
Returning to our model containing the public event EventHandler Changed, when we raise the event by calling Changed, each delegate assigned to Changed is called. This is referred to as multicasting. Delegates can be bound to a single method or to multiple methods.

It is possible to attach several methods to one event by assigning several delegates to a single event. What you should not do is rely on delegates being invoked in a particular order.

## C# Evolution

Since its initial 1.0 release, C# has been evolving at a rapid pace. Not long after C# 1.0, Microsoft released version 1.1. It contained numerous minor changes, but added no significant features. However, the situation was quite different with the release of C# 2.0. This was a watershed event in the lifecycle of C# because version 2.0 included numerous new features, such as generics, partial types, and anonymous methods, that fundamentally extended the power, scope, and range of the language. Version 2.0 firmly put C# at the forefront of programming language development. It also demonstrated Microsoft's long-term commitment to the language.

The next major release of C# was 3.0, and (at the time of this writing) this is the current version of C#. Due to the numerous new features included in C# 2.0, one might have expected the development of C# to slow somewhat, just to give programmers a chance to catch up, but this was not the case.

With version 3.0, Microsoft once again put C# at the forefront of language design, this time including a host of innovative features that redefined the programming landscape. Perhaps the two most exciting new features in C# 3.0 are language-integrated query (LINQ) and lambda expressions. LINQ enables you to write database queries using C# programming elements. Lambda expressions are frequently used in LINQ expressions. Together they add a whole new dimension to C# programming. Other innovations include implicitly typed variables and extension methods. Since this book is based on C# 3.0, these major advances are covered.

## C# and .NET

Even though C# is a language that can be studied on its own, it has a special relationship to its runtime environment, the .NET Framework. The reason for this is twofold. First, C# was initially designed by Microsoft to create code for the .NET Framework. Second, the libraries used by C# are the ones defined by the .NET Framework. Thus, even though it is possible to separate the C# language from the .NET environment, the two are closely connected. Therefore, it is important to have a general understanding of the .NET Framework and why it is important to C#.

In a sentence, the .NET Framework defines an environment that supports the development and execution of highly distributed, component-based applications. It enables different programming languages to work together and provides security, program portability, and a common programming model for the Windows platform.

As it relates to C#, the .NET Framework defines two major elements. The first is the Common Language Runtime. This is the runtime that manages the execution of your program. Among other advantages, the Common Language Runtime is the part of the .NET Framework that enables programs to be portable, supports mixed-language programming, and provides security.

The second element is the .NET class library. This library gives your program access to the runtime environment. For instance, if you need to perform I/O, such as displaying something on the screen, you will use the .NET class library to do it. If you are new to programming, the term class might be new. Although it will be explained in detail somewhat later, briefly, a class is an object-oriented construct that organizes programs. As long as your program limits itself to the features defined by the .NET class library, your programs can run anywhere that the .NET runtime framework is supported. Since C# automatically uses the .NET class library, C# programs are automatically portable to every .NET environment.

The Common Language Runtime (CLR) manages the execution of .NET code. Here is how it works. When you compile a C# program, the output of the compiler is not executable code. Rather, it is a file that contains a special kind of pseudocode called Microsoft Intermediate Language, or MSIL for short. MSIL defines a set of portable instructions that are independent of a specific CPU. Essentially, MSIL defines a portable low-level language. One other point: although MSIL is similar in concept to Java's bytecode, the two are not the same.
