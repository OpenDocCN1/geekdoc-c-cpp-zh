## C# Class Library:
The example projects presented in this part use two of C#'s built-in methods: WriteLine( ) and Write( ). As mentioned, these methods are members of the Console class, which is part of the System namespace, which is defined by the .NET Framework's class library. As explained earlier in this section, the C# environment depends on the .NET Framework class library to provide support for such things as I/O, string handling, networking, and GUIs. Therefore, C# as a whole is a combination of the C# language itself, plus the .NET standard classes. As you will see, the class library provides a great deal of the functionality that is part of any C# program. Indeed, part of becoming a C# developer is learning how to use the standard library.

Throughout this book, various components of the .NET library classes and methods are described. However, the .NET library is very large, and it is something you will also want to explore more on your own.

## Important Data Types:
Data types are particularly important in C# because it is a strongly typed language. This means that all operations are type-checked by the compiler for type compatibility. Illegal operations will not compile. Therefore, strong type checking prevents errors and improves reliability. To enable strong type checking, all variables, expressions, and values have a type. There is no concept of a "typeless" variable, for instance. Moreover, the type of a value determines what operations are permitted on it. An operation permitted on one type may not be permitted on another.

### C# Value Type:
C# contains two general categories of built-in data types: value types and reference types. The difference between the two kinds is what a variable contains. For a value type, a variable holds an actual value, such 101 or 98.6. For a reference type, a variable holds a reference to the value. The most commonly used reference type is the class, and a discussion of classes and reference types is deferred until later. The value types are described here. At the core of C# are the 13 value types shown in Table 2-1. Generally, these are referred to as the simple types. They are called simple types because they consist of a single value. (In other words, they are not a composite of two or more values.) They form the foundation of C#'s type system, providing the basic, low-level data elements upon which programs work. The simple types are also sometimes referred to as primitive types. C# carefully specifies a range and behavior for each simple type. Based on portability requirements and to support mixed language programming, C# is strict on this account. For instance, an int is the same in all execution environments. There is no need to revise code to fit a particular platform. While carefully specifying the size of the simple types may cause a little loss of performance in certain situations, it is essential in order to achieve portability.

The difference between signed and unsigned numbers is whether the high-order bit of the integer is interpreted. If a signed integer is specified, the C# compiler will generate code that assumes the high-order bit of an integer is to be used as a sign flag. If the sign flag is 0, the number is positive; if it is 1, the number is negative. Negative numbers are most often represented using the two's complement approach. ## Literals:
In C#, literals refer to fixed values that are represented in their readable form. For example, the number 100 is a literal. Generally, literals and their use are so intuitive that they have been used in some form by all the first example programs. Now is the time to explain them formally.

C# literals can be of any of the value types. The way each literal is represented depends upon its type. As explained before, character literals are enclosed between single quotes. For example 'a' and '%' are both character literals. Integer literals are specified as numbers without fractional parts. For instance, 10 and – 100 are integer literals. Floating point literals require the use of the decimal point followed by the number's fractional part. For example, 11.123 is a floating point literal. C# also allows you to use scientific notation for floating point numbers. Since C# is a strongly typed language, literals, too, have a type. Normally, this raises the following question: What is the type of a numeric literal? For instance, what is the type of 12, 123987, or 0.23? Luckily, C# specifies some easy-to-follow rules that answer these questions. First, for integer literals, the type of the literal is the smallest numeric type that will hold it, starting with int. Consequently, an integer literal is of type int, uint, long, or ulong, depending on its value. Second, floating point literals are of type double.

If C#'s default type isn't what you want for a literal, you can explicitly specify its type by adding a suffix. To specify a long literal, add an l or an L. For example, 12 is an int, but 12L is a long. To specify an unsigned integer value, append a u or U. Thus, 100 is an int, but 100U is a uint. To specify an unsigned, long integer, use ul or UL. For example, 984375UL is of type ulong.

To specify a float literal, append an F or f. For example, 10.19F is of type float. Although redundant, you can specify a double literal by appending a D or d. (As just mentioned, floating point literals are double by default.) To specify a decimal literal, follow its value with an m or M. For example, 9.95M is a decimal literal.

Although integer literals make an int, uint, long, or ulong value by default, they can still be assigned to variables of type byte, sbyte, short, or ushort as long as the value being assigned can be represented by the target type.

### HexaDecimal Literals:
In programming, it is sometimes easier to use a number system based on 16 rather than 10. The base 16 number system is called hexadecimal and uses the digits 0 through 9, and the letters A through F, which represent 10, 11, 12, 13, 14, and 15. For example, the hexadecimal number 10 is 16 in decimal. Due to the frequency with which hexadecimal numbers are used, C# allows you to specify integer literals in hexadecimal format. A hexadecimal literal must start with 0x (a zero followed by an x).

### Character Escape Seq:
Enclosing character constants in single quotes works for most printing characters, but a few characters, for example, the carriage return, present a special problem when a text editor is used. In addition, certain other characters, for example, single and double quotes, have special significance in C#, so you can't use them directly. Thus, C# provides special escape sequences.

Notice how the \n break sequence is used to produce a new line. You don't have to use multiple WriteLine() statements to get multiline output. Simply embed \n inside a longer string at the points at which you want the newlines to occur.
