C# 的鼻祖是 C。C# 从 C 继承了语法、许多关键字和运算符。C# 基于并改进了 C++ 定义的对象模型。如果你了解 C 或 C++，你会对 C# 感到得心应手。C# 与 Java 的关系更为复杂。如前所述，Java 同样源自 C 和 C++。它也共享 C/C++ 语法和对象模型。与 Java 一样，C# 旨在生成可移植代码，并且 C# 程序在受保护的托管运行时环境中执行。然而，C# 并非源自 Java。相反，C# 和 Java 更像是表亲，共享共同血统，但在许多方面不同。它们让软件工程师有机会快速上手，但事实并非如此。

通过 3.0 版本，微软再次将 C# 置于语言设计的前沿，这一次包含了许多重新构想编程格局的创新功能。C# 3.0 中也许最令人兴奋的两个新功能是语言集成查询（LINQ）和 lambda 表达式。LINQ 使你能够利用 C# 编程构造来编写数据库查询。lambda 表达式常用于 LINQ 表达式。它们共同为 C# 编程增添了全新维度。其他进步包括隐式类型变量和扩展方法。由于本书基于 C# 3.0，因此涵盖了这些重大进展。

尽管 C# 是一种可以独立考虑的语言，但它与其运行时环境 .NET Framework 有着特殊关系。原因有两方面。首先，C# 最初由微软设计，用于为 .NET Framework 编写代码。其次，C# 使用的库是由 .NET Framework 定义的库。因此，尽管可以将 C# 语言与 .NET 环境分离，但二者紧密相连。因此，对 .NET Framework 以及它对 C# 为何重要有一个总体了解，是很重要的。

简而言之，.NET Framework 定义了一个环境，支持高度分布式、基于组件的应用程序的开发和执行。它使不同编程语言能够互操作，并为 Windows 平台提供安全性、程序可移植性和通用编程模型。

就与 C# 的关系而言，.NET Framework 定义了两个重要元素。第一个是公共语言运行时。这是管理程序执行的框架。除了其他优势外，公共语言运行时是 .NET Framework 中使项目可移植、支持混合语言编程并提供安全性的部分。

第二个元素是 .NET 类库。该类库使你的程序能够访问运行时环境。举例来说，如果你需要执行 I/O，例如在屏幕上显示内容，你将使用 .NET 类库来完成。如果你是编程新手，类这个术语可能很陌生。尽管稍后会更详细地说明，但简而言之，类是组织程序的面向对象构造。只要你的程序限制在 .NET 类库定义的功能内，你的项目就可以在任何支持 .NET 运行时框架的地方运行。由于 C# 自动使用 .NET 类库，因此 C# 程序可移植到每个 .NET 环境。

公共语言运行时（CLR）负责 .NET 代码的执行。其工作方式如下。编译 C# 程序时，编译器的输出不是可执行代码。相反，它是一个包含特殊类型伪代码的文件，这种伪代码称为微软中间语言，简称 MSIL。MSIL 定义了一组与特定 CPU 无关的可移植指令。基本上，MSIL 定义了一种可移植的低级计算构造。另一点：尽管 MSIL 在思想上与 Java 的字节码相当，但二者并不相同。当程序运行时，CLR 的职责是将中间代码转换为可执行代码。这样，任何编译为 MSIL 的程序都可以在任何实现了 CLR 的环境中运行。这是 .NET Framework 实现可移植性的一部分。
