
编译为 MSIL 的代码可以在实现了 CLR 的任何环境中运行。这是 .NET Framework 实现可移植性的一部分。

Microsoft Intermediate Language 利用 JIT 编译器被转换为可执行代码。JIT 的意思是“just in time”。其工作流程如下：当 .NET 程序运行时，CLR 会激活 JIT 编译器。JIT 编译器会按需将 MSIL 转换为本地代码，即在程序的每个部分需要时进行转换。随后，你的 C# 程序实际上以本地代码执行，尽管它最初是编译为 MSIL 的。这意味着你的程序运行速度与最初编译为本地代码时差不多，但它获得了 MSIL 的紧凑性和安全性优势。除了 MSIL 之外，编译 C# 程序时还会产生另一项内容：元数据。

元数据描述了程序所使用的数据，并使你的代码能够与其他代码交互。元数据与 MSIL 包含在同一个文件中。幸运的是，就本书的目的而言，以及对于大多数编程项目来说，没有必要了解有关 CLR、MSIL 或元数据的其他任何内容。C# 会为你处理这些细节。

通常，当你编写 C# 程序时，你创建的是所谓的托管代码。托管代码在通用语言运行时的控制下执行，正如刚才所述。由于它在 CLR 的控制下运行，托管代码需满足某些要求——同时也享有若干好处。其限制很容易描述并满足。编译器必须为 CLR 创建 MSIL 文件（C# 会这样做）并使用 .NET Framework 库（C# 也会这样做）。托管代码的优势众多，包括现代化的内存管理、混合语言的能力、更好的安全性、对版本控制的支持，以及编程组件交互的清晰路径。

托管代码的对立面是非托管代码。非托管代码不在通用语言运行时下执行。以这种方式，在 .NET Framework 出现之前的所有 Windows 程序都使用非托管代码。托管代码和非托管代码可以协同工作，因此 C# 生成托管代码这一事实并不会限制其与旧程序协作的能力。

C# 的核心是面向对象编程（OOP）。面向对象的方法是 C# 的固有特性，所有 C# 项目或多或少都是面向对象的。由于其对 C# 的重要性，在编写甚至是简单的 C# 程序之前，了解 OOP 的基本原理是有价值的。

OOP 是编程任务中的一种开创性方法。自计算机发明以来，编程技术发生了巨大变化，基本上是为了适应项目日益增长的复杂性。例如，计算机刚被发明时，计算机编程是通过拨动开关，使用计算机前面板输入二进制机器指令来完成的。只要项目只有两三百条指令长，这种方法就有效。随着项目的增长，汇编语言被发明出来，以便程序员能够处理更大、更复杂的项目，使用机器指令的符号表示。随着项目的不断发展，像 FORTRAN 和 COBOL 这样的高级语言被引入，为程序员提供了更多处理复杂性的工具。当这些早期语言开始达到其极限时，结构化编程被创建出来。

想一想：在编程发展的每个里程碑上，都创造了技术和工具来使开发人员能够管理日益增长的复杂性。每一步，新方法都吸收了过去策略的最好部分并向前推进。面向对象编程也是如此。在 OOP 之前，许多项目正接近（甚至超过）结构化方法不再有效的临界点。需要一种更优的方法来处理复杂性，而面向对象计算机编程就是解决方案。面向对象编程吸收了结构化编程的最佳思想，并结合了一些新思想。结果是一种不同且更好的程序组织方法。

从最广义上讲，程序可以以两种不同的方式组织：围绕其代码（正在发生什么）或围绕其数据（受影响的是什么）。仅使用结构化编程技术，程序通常围绕代码编写。这种方法可以被视为“code acting on data”。面向对象的项目则以不同的方式工作。它们围绕数据编写，其关键原则是“data controlling access to code”。在面向对象的语言中，你定义数据以及允许作用于该数据的例程。以这种方式，数据类型精确定义了可以应用于该数据的任务类型。

为了帮助理解面向对象编程的原理，所有 OOP 语言，包括 C#，都有三个共同特征：封装、多态性和继承。

封装是一种编程机制，它将代码与其控制的数据绑定在一起，并使两者免受外部干扰和滥用。在面向对象的语言中，代码和数据可以绑定在一起，形成一个独立的黑盒。盒子内部包含所有重要的数据和代码。当代码和数据以这种方式连接在一起时，就形成了一个对象。从某种意义上说，对象是支持封装的装置。

在对象内部，代码、数据或两者可能是该对象的私有部分或公共部分。私有代码或数据仅为对象的另一部分所知并可访问。也就是说，私有代码或数据不能被对象外部存在的程序部分访问。当代码或数据是公共的时，你的程序的不同部分可以访问它，即使它是在对象内部定义的。通常，对象的公共部分被用来为对象的私有组件提供受控接口。

C# 封装的基本单元是类。类定义了对象的类型。它指定了数据以及将作用于该数据的代码。C# 利用类规范来创建对象。对象是类的实例。由此，类基本上是一组确定如何构造对象的蓝图。

构成类的代码和数据称为类的成员。特别是，类定义的数据被称为成员变量或实例变量。作用于该数据的代码被称为成员方法或简称为方法。“Method”是 C# 对子程序的称呼。如果你熟悉 C/C++，你可能会意识到 C# 程序员所称的方法，C/C++ 开发者称之为函数。由于 C# 是 C++ 的直接后代，术语“function”在指代 C# 方法时有时也会被使用。

多态性（源自希腊语，意为“多种形式”）是一种属性，它使一个接口能够访问一类通用操作。多态性的一个简单例子可以在车辆的转向盘上找到。转向盘（接口）是相同的，无论使用何种实际转向系统。也就是说，无论你的车辆是手动转向、助力转向还是齿条小齿轮转向，转向盘的工作方式都相同。由此，左转转向盘就会使车辆向左行驶，无论使用何种转向系统。统一接口的好处显然是，一旦你知道如何操作转向盘，你就可以驾驶任何类型的车辆。

类似的原则也可以应用于编程。例如，考虑一个栈（即先进后出列表）。你可能有一个程序需要三种不同的栈。一个栈用于整数值，一个用于浮点值，一个用于字符。在这种情况下，实现每个栈的算法是相同的，尽管存储的数据各不相同。在非面向对象的语言中，你需要创建三套不同的栈例程，每套使用不同的名称。然而，由于多态性，在 C# 中，你可以一次性确定栈的通用类型，然后将其用于三种特定情况。由此，如果你知道如何使用一个栈，你就可以使用它们全部。更一般地说，多态性的概念通常用短语“one interface, multiple methods”来表达。这意味着它是可能的
