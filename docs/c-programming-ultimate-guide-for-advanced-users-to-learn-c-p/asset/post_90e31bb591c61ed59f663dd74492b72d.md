### Saving a Text File

RichTextBox.SaveFile performs the symmetric action to LoadFile. SaveFile writes the contents of the RichTextBox control to an RTF or TXT file by calling SaveFile and passing a file name.

### Using the ZoomFactor

RichTextBox.ZoomFactor is an interesting property. With ZoomFactor you can specify a percentage increase in the size of the text. Setting ZoomFactor to 2 will double the size of the text, and 0.64 will reduce the size of the text by about half. Valid values are from 0.64 to 64, the last being 64 times the normal size. This property is a great feature for applications supporting individuals with disabilities and for presentations. Assume, for instance, that you are displaying the text of the RichTextBox on an overhead projector. Setting the ZoomFactor to increase text size will make it simpler for your audience to see the text in the RichTextBox control.

Finally, we come to multithreading. Multithreading is a complex subject. There are a few aspects to multithreading, so we will confine our discussion in this section to the way it was used to help implement the AssemblyViewer.

The AssemblyViewer uses a different thread to show the Splash screen while the application is loaded. A luxury, no doubt, but what is the purpose of a splash screen if it is executed in a linear fashion? That is, while the splash screen is loading, no real initialization happens, and I never liked allowing the splash screen to contain the initialization code. (You are probably going to discover, however, that many splash screens do really contain initialization code.)

In our example application, the splash screen is spawned on a separate thread. There are four different ways to simulate apparently concurrent behavior in .NET. The Timer control and Application.Idle event provide event-driven synchronous behavior. Controls support the asynchronous BeginInvoke and EndInvoke.

The ThreadPool class gives a pool of available threads, and the Thread class enables you to start up and manage threads yourself. The AssemblyViewer uses a thread from the ThreadPool class; hence, that is the feature of threading presented here.

### ThreadPool Threading

The ThreadPool is a class that deals with a pool of threads for you. Multithreading using threads in the ThreadPool is the same as creating a Thread object. However, your workload is helped a bit, and grabbing a thread from the pool is frequently somewhat quicker than creating an instance of the Thread class because the pool no doubt has a thread waiting for you to give it work. To use a thread in the ThreadPool, you simply give the ThreadPool some work to do as a Delegate. In this example, the Delegate will act as a mechanism representing work for the thread to do. Every other part of threading is indistinguishable from starting a Thread object yourself. The most important thing to remember is that ThreadPool threads require the same amount of care as Thread instances, particularly with regard to Windows Forms controls.
