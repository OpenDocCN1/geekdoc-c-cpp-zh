事实上，即使是最简单的商业网页，也需要一些编程来处理Web表单输入。虽然这些通常可以由脚本语言（例如Perl）处理，但Perl与基于Windows的服务器的集成不如与UNIX的集成那样好（许多可从Web下载的Perl脚本都假定存在各种UNIX设施，例如sendmail）。.NET Framework HttpHandler类提供了一种直接而简洁的方法来创建基本的表单处理程序，同时也为构建具有复杂方案的更精细框架提供了一条途径。

ASP.NET是一个完整的框架，用于创建内容会随时间动态变化的页面，非常适合电子商务、客户关系管理以及各种高度动态的网站。“动态服务器页面”将编程指令与基于HTML的表示指令结合起来，这种可能性最初被视为受过平面艺术训练的Web设计师与更为严谨的编程世界之间的桥梁。然而，服务器页面编程发展成了面向软件工程师的一项创新，如今已被广泛用作完整Web解决方案的模型。

服务器页面编程，如ASP.NET的代码隐藏编程模型，鼓励表示层关注点与业务逻辑关注点交织在一起。本书提出这样一种观点：对于复杂应用而言，这种交织并不理想。这并不意味着ASP.NET和VB.NET是糟糕的语言；恰恰相反，这意味着它们的编程模型适应性太强，以至于要在其中做出卓越的工作，实际上需要比经典ASP更多的理解和控制。

最近一个网站创新的“月度宣传热词”是“共享”（又称P2P，它具有一个宣传优势：其缩写与最近一个商业“月度宣传热词”“通往生产力之路”的缩写相似）。

出乎意料的是，P2P正是人们从“万维网”这个说法中会期待的那种工程。在P2P设计中，服务分两个阶段创建：先由某种集成服务器发现对等资源（无论该服务器是否处于规划组织的合法控制之下），然后对等节点相互关联，以便在无需进一步干预的情况下继续进行资源共享。

ASP.NET和.NET为创建P2P框架提供了坚实的基础设施；毕竟，这类框架需要创建富客户端、精密服务器，以及用于构建健壮资源共享框架的设施。P2P因文件共享框架的普遍存在而蒙上污名，但SETI@Home和Folding@Home等项目展示了网格计算的潜力，它可以动用惊人的计算量来应对具有挑战性的问题。

基于HTML所创造的价值令人惊叹。而由明显更具适应性和表现力的可扩展标记语言（XML）将创造的价值，将超过此前的一切（也许不是在股价和同行的估值方面，但在真正的盈利能力和生产力方面，毫无疑问）。Web服务通过标准Web约定和基于XML的信息表示来传递价值，而后者并不关心自身如何被展示（Web服务是无头的）。

Web服务是微软整个.NET方法论的存在的理由，而.NET方法论远比“仅仅”是十年来编程API的最大更新要广泛得多。许多商业记者错误地将.NET解读为微软试图把自己塑造成通过Web进行交易的中央中介。事实更简单：微软希望拥有所有与Web关联设备上的操作系统，即使这类设备的种类和数量急剧增加。PC越是从事基础计算任务转向通信和控制任务，Web服务所能提供的东西就越多；微软一直明白，操作系统的优势受制于软件开发。

.NET体系是微软和软件开发向“后桌面”现实的一次全面转型。.NET Framework将基础硬件的抽象与大量应用程序编程接口（API）结合起来，向工程师提出，“一次编写，到处运行”在技术上是误导性的观点，它推崇的是在PC上运行的组件这一理念。.NET方法论认识到，运行在各种设备上的富客户端（“富客户端”指非服务器应用程序，负责计算的不仅仅是其显示和数据能力）、高性能服务器，以及运行在不可放弃的桌面“遗留”机器上的新应用程序，绝不是彼此分离的市场，而是所有软件应用程序从根本上都需要涉及的细分领域。无论软件工程师是从基于浏览器的客户端开始构建其Web服务（或者就此而言，无论软件工程师是否为基于.NET的Web服务构建基于Windows的富客户端），.NET方法论的一部分就是让在另一台设备上扩展价值变得始终简单：PocketPC或3G电话上的富客户端，或后端机架中的高性能数据库。Web约定将连接所有这些设备，但价值在于数据，而数据将通过Web服务流动。如果.NET是创建Web服务最有说服力的方法，微软必将获得整个设备范围内的市场份额。

微软编码的本质经常受到不公正的评判。除了Windows，没有哪个操作系统会因为无法运行某些晦涩的硬件配置而受到评判；Microsoft Office安装时可能会占用令人烦恼的大量磁盘空间，但它足够稳固和适用，足以占据商业世界。尽管如此，微软真正搞砸的地方是安全性。微软在很大程度上把安全变成非赢即输的选择（“启用宏，是或否？”“安装此控件（永久），是或否？”），这已经够糟糕了；然而，他们不为这种非赢即输的选择提供任何信息（“请确保你信任发件人！”），这是不可原谅的。当你考虑到普通PC上移入移出的文件数量以及许多用户缺乏经验时，最令人惊讶的主要是真正具有破坏性的攻击竟然如此少见。

.NET Framework SDK包含一种新的安全模型，它依赖于针对访问文件系统或网络等事项的细粒度权限，以及依赖于公钥加密和证书链的数字签名。虽然微软所宣称的“可信计算”目标超越了安全，并且将需要在他们的操作系统中，也许更根本地，直接在Microsoft Office和Outlook中做出显著调整，但.NET Framework SDK提供了现代组件，人们可以设想这些组件将催生一个安全性显著更高的计算环境。

### 完成已用时间时钟

已用时间时钟在Timer tick时刷新。使用Timer控件是执行轻量级事件处理的一种有用策略。显然，使用Timer并不是多线程，但对于刷新时钟这样基本的任务而言，Timer是合理且足够的。

Timer控件的工作方式是：当以毫秒指定的时间间隔过去时，就引发一个事件。就在Timer.Interval到期时，SetPosition过程使用Player.Elapsed属性来刷新Tracker的位置。刷新Tracker的进度指针的一个结果，是刷新包含以数字时钟形式显示的已用时间的标签。

位置值以秒表示；这样一来，位置值可用于生成时钟显示所需的时间输入。这是通过创建TimeSpan结构的实例并传入已用秒数来完成的。创建时钟的代码将紧接着展示。
