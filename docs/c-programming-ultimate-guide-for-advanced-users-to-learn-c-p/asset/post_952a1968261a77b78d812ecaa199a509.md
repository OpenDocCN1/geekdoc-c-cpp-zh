### Controlling the Loop Inside the Loop

When you declare a variable inside a for loop, there is one important point to remember: The scope of that variable ends when the for statement does.

Remember about break. First, more than one break statement may appear in a loop, but be cautious. Too many break statements tend to destroy your code. Second, the break that exits a switch statement affects only that switch statement and no enclosing loops. Third, the creators of C# didn't offer break or continue with that capability. Rather, break and continue work the same in C# as they do in C and C++. One reason that C# didn't follow Java's lead on this issue is that Java doesn't support the goto statement, but C# does. Thus, Java needs to offer break and continue with additional capability to compensate for the absence of the goto.

It is possible to force an early iteration of a loop, bypassing the loop's normal control structure. This is accomplished using continue. The continue statement forces the next iteration of the loop to occur, skipping any code in the middle. Thus, continue is basically the complement of break. For example, it can cause the call to WriteLine() to be skipped. In while and do-while loops, a continue statement will cause control to go directly to the conditional expression. In the case of the for, the iteration expression of the loop is evaluated and then the conditional expression is executed.

Good uses of continue are uncommon. One reason is that C# provides a rich set of loop statements that fit most applications. However, for those special conditions in which early iteration is required, the continue statement gives an organized way to achieve it.

### The goto

The goto is C#'s true jump statement. When encountered, program flow jumps to the location specified by the goto. The statement dropped out of favor with software engineers many years back because it encouraged the creation of "spaghetti code," a tangled mess of true jumps that resulted in hard-to-follow code. Nonetheless, the goto is still sometimes—and in some cases successfully—used. This book won't make a judgment regarding its validity as a form of program control. It ought to be stated, however, that there are no programming circumstances that require the use of the goto statement—it is not something essential for making the language complete. Rather, it is a convenience, which, whenever used wisely, can be of advantage in certain programming circumstances. As such, the goto isn't used in this book outside of this section. The main concern most software engineers have about the goto is its inclination to mess up a program and render it almost garbled. Nonetheless, there are times when the use of the goto can clarify program flow as opposed to confuse it. The goto requires a label for operation. A label is a valid C# identifier followed by a colon. Furthermore, the label must be in the same method as the goto that uses it. Eliminating the goto would force the use of three if and break statements. In this situation, the goto simplifies the code. While this is a contrived example used for illustration, you can envision real circumstances in which a goto may be useful.

The goto has one important limitation: You can't jump into a block. Obviously, you can jump out of a block, as the first example shows. The goto default jumps to the default label. The goto case 1 jumps to case 1. Because of the restriction stated above, you can't jump into the middle of a switch from code outside the switch because a switch defines a block. ## Chapter 4: Class, Objects, and Methods

We have been using classes since the beginning of this book. Obviously, only amazingly simple classes have been used, and we have not taken advantage of most of their features. As you will see, classes are significantly more powerful than the restricted ones shown up until now. Let's start by reviewing the basics. A class is a template that defines the form of an object. It typically specifies both code and data, with the code acting on the data. C# uses a class specification to construct objects. Objects are instances of a class. Thus, a class is essentially a set of plans that specify how to build an object. It is important to be sure about one issue: A class is a logical abstraction. It isn't until an object of that class has been created that a physical representation of that class exists in memory. One other point: Recall that the methods and variables that constitute a class are called members of the class.

When you define a class, you declare the data that it contains and the code that operates on it. While very simple classes may contain only code or only data, most real classes contain both. In general terms, data is contained in instance variables defined by the class, and code is contained in methods. It is important to state at the start, however, that C# defines several specific kinds of members, which include instance variables, static variables, constants, methods, constructors, destructors, indexers, events, operators, and properties. For now, we will restrict our discussion of the class to its fundamental components: instance variables and methods. Later in this section, constructors and destructors are discussed.
