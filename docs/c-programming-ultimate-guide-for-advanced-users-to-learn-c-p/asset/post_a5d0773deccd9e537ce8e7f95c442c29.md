## Multithreading

Finally, we come to multithreading. Multithreading is a complex subject. There are several aspects to multithreading, so we will confine our discussion in this section to the manner in which it was used to help implement the AssemblyViewer.

The AssemblyViewer uses a separate thread to show the splash screen while the application is loaded. A luxury, no doubt, but what is the purpose of a splash screen if it is executed in a linear fashion? That is, while the splash screen is loading, no real initialization happens, and I never liked giving the splash screen the initialization code. (You are likely to discover, however, that many splash screens do actually contain initialization code.)

In our example application, the splash screen is run on a separate thread. There are four different ways to simulate seemingly asynchronous behavior in .NET. The Timer control and Application.Idle event provide event-driven synchronous behavior. Controls support the asynchronous BeginInvoke and EndInvoke.

The ThreadPool class provides a pool of available threads, and the Thread class enables you to spin up and manage threads yourself.

The AssemblyViewer uses a thread from the ThreadPool class; hence, that is the aspect of threading presented here.

## ThreadPool Threading

The ThreadPool is a class that manages a pool of threads for you. Multithreading using threads in the ThreadPool is the same as creating a Thread object. However, your workload is eased somewhat, and grabbing a thread from the pool is often somewhat faster than creating an instance of the Thread class because the pool probably has a thread waiting for you to give it work.

To use a thread in the ThreadPool, you simply give the ThreadPool some work to do as a Delegate. In this example, the Delegate acts as a method representing work for the thread to do. Every other part of threading is indistinguishable from spinning up a Thread object yourself. The most important thing to remember is that ThreadPool threads require the same amount of care as Thread instances, particularly with regard to Windows Forms controls. Windows Forms controls are not thread safe; therefore, you should take additional care when interfacing with Windows Forms controls from a thread.
