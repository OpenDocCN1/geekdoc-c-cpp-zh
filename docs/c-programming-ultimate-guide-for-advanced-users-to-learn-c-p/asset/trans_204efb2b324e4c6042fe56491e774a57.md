## 声明新的委托类型

如果需要定义自定义委托，可以遵循上一节中演示 `EventHandler` 委托的基本模型。

委托定义实际上等同于方法头，其中在访问修饰符和返回类型之间包含关键字 `delegate`。下面的示例为返回 `void` 且不带参数的方法定义了另一个委托。

```
public delegate void Delegate();
```

请注意 C# 是区分大小写的，并且第一个示例展示了一个名为 "Delegate" 的委托。任何返回 `void` 且不带参数的方法都可以分配给声明为 `Delegate` 类型的事件或字段。

### 作为生产者引发事件

生产者引发事件。在 C# 中引发事件是通过使用事件名称调用方法来完成的。根据惯例，事件由受保护的成员引发，其名称与事件相似，以 "On" 作为前缀。

回到我们独特的 `Changed` 事件案例，该事件定义为 `EventHandler` 类型，我们可以将事件与引发事件的受保护方法匹配。

事件名为 `Changed`。使用者可以将任意数量与 `EventHandler` 委托签名匹配的方法分配给此一个事件成员。在包含代码的类内部，你可以在需要引发 `Changed` 事件的任何地方调用 `OnChanged`。`OnChanged` 会检查 `Changed` 是否至少被分配给一个委托；如果没有，则 `OnChanged` 返回。否则，生产者会将 `Changed` 当作方法处理并调用它，同时生产者向其传递关键参数。

当生产者引发带有 `sender` 参数的事件时，该值始终设置为对自身的内部引用：`this`。在我们的基本模型中，我们传递一个 null `System.EventArgs` 参数，因为我们不使用该值。如果必须向使用者的事件处理程序传递特定值，则可以创建 `System.EventArgs` 的实例或创建一个接受 `EventArgs` 特定子类的委托。

使用者通过将事件处理程序连接到对象的事件成员来处理事件。模型程序 `EventsDemo.sln` 包含类 `EventChanged` 和 `Form1`。就我们的情况而言，我们期望 `Form1` 包含一个 `EventChanged` 对象并需要处理 `EventChanged.Changed` 事件。为此 `Form1` 需要创建 `EventChanged` 的一个实例并将一个方法分配给 `EventChanged.Changed`。

`EventChanged` 对象名为 `obj`，并作为表单中的字段启动。`Form1_Load`（本身就是一个事件）将 `EventChanged.Changed` 事件连接到 `Form1` 的 `button1_Click` 方法。（按钮点击方法本已可访问，并且恰好具有与 `Changed` 事件相似的签名。）`+=` 运算符用于将新的 `System.EventHandler` 对象分配给 `Changed`。这样做会将事件处理程序添加到调用列表中。

只有 `+=` 和 `-=` 运算符被重载以将事件处理程序附加到事件的调用列表或从中移除。你不能使用赋值运算符将委托分配给事件。

把事件声明想象成一个字段，其类型是委托类型：一个委托。当你将委托分配给事件时，你是将委托插入到委托类型的一个成员列表中。当你通过将其作为方法调用来引发事件时，你实际上是在调用委托。

当事件方法在内部被调用时，它会遍历附加到内部列表的所有委托并调用每一个。

回到包含公共事件 `EventHandler Changed` 的模型，当我们通过调用 `Changed` 来引发事件时，每个分配给 `Changed` 的委托都会被调用。这被称为多播。委托可以绑定到单个方法或多个方法。

通过将多个委托分配给单个事件，可以将一些功能层叠到一个事件中。你不应该依赖委托按特定顺序被调用。
