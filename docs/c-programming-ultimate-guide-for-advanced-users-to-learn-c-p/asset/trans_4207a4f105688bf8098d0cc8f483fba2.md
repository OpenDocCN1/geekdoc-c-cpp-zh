Java 的创新之处更多是由计算环境的变革驱动，而非编程艺术的进步（尽管其中也确实有一些）。在互联网普及之前，大多数程序都是为特定的 CPU 和特定的操作系统编写、编译并针对其进行开发的。虽然程序员一直喜欢重用代码，但将程序从一个环境轻松移植到另一个环境的能力，相对于更紧迫的问题而言优先级较低。然而，随着互联网的兴起，其中连接了各种各样的 CPU 和操作系统，旧有的可移植性问题变得更加重要。为了解决这个问题，需要另一种语言，而这种新语言就是 Java。Java 通过将程序的源代码翻译成一种称为字节码的中间语言来实现可移植性。这种字节码随后由 Java 虚拟机（JVM）执行。因此，只要环境中可用 JVM，Java 程序就可以在任何环境中运行。此外，由于 JVM 通常易于实现，它在无数情况下都很容易获得。除可移植性需求外，在基于互联网的编程成为现实之前，还必须解决第二个关键问题。这个问题是安全性。正如所有互联网用户所知，计算机病毒构成了真实且持续的潜在威胁。如果没人能信任它们，可移植的程序有什么用呢？谁愿意冒着执行通过互联网传输的程序的风险？它可能包含恶意代码。幸运的是，安全问题的解决方案也存在于 JVM 和字节码中。由于 JVM 执行字节码，它完全控制着程序，可以防止 Java 程序执行不应该执行的操作。因此，JVM 和字节码同时解决了可移植性和安全性这两个问题。必须理解，Java 对字节码的使用与 C 和 C++ 有根本不同，后两者几乎总是编译成可执行的机器码。机器码与特定的 CPU 和操作系统绑定。因此，如果你需要在不同的系统上运行 C/C++ 程序，它

关于 for 循环的一个重要点是，条件表达式在循环顶部不断被测试。这意味着如果条件初始为假，循环内部的代码可能根本不会被执行。

此循环永远不会执行，因为其控制变量 count 在进入循环时大于五。这使得条件表达式 count < 5 从开始就为假；因此，循环的迭代甚至不会发生一次。这里，用逗号分隔两个初始化语句和两个迭代表达式。循环开始时，i 和 j 都被初始化。每次循环重复时，i 会递增而 j 会递减。多个循环控制变量通常很有用，可以简化某些计算。你可以有任意数量的初始化和迭代表达式，但在实践中，超过两个会使 for 循环变得繁琐。

重复单个语句的 for 循环的一般形式是

```
for(initialization; condition; iteration) statement;
```

重复一个块的一般结构是

```
for(initialization; condition; iteration)
{
    statement sequence
}
```

初始化通常是一个赋值语句，用于设置循环控制变量的初始值，该变量充当控制循环的计数器。条件是一个布尔表达式，用于确定循环是否会重复。迭代表达式定义了每次循环重复时循环控制变量将改变的量。请注意，这三个重要的循环部分必须用分号分隔。只要条件测试为真，for 循环就会继续执行。当条件变为假时，循环将退出，程序执行将继续执行 for 循环之后的语句。
