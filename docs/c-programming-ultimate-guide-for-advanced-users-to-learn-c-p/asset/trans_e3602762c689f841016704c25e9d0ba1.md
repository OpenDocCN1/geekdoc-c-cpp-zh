
首先，你声明一个私有字段 disposed，用于跟踪是否已经调用过 Dispose 方法，并将 disposed 初始化为 False。在 Dispose 方法中，检查是否已经调用过 Dispose，如果已调用则返回。执行清理，然后调用 GC.SuppressFinalize() 方法，并传入需要抑制其 Finalize 的对象的引用。最后，将字段 disposed 设置为 True。

大多数情况下，你不必实现析构函数或 Dispose 方法。CLR 中的托管对象会被自动垃圾回收。如果你确定需要它们，再实现析构函数和 Dispose 方法。

## 实现事件

事件构成了 Windows 面向对象三要素的顶点，属性与方法构成其基础。事件旨在对代码中的事件作出反应。与属性和方法一样，事件也可以从两个视角来看待：消费者的视角和生产者的视角。

编写类时，你会希望定义内部事件，让消费者有机会对这些事件作出反应。对于这些事件，你需要声明一个事件，并在事件发生时引发该事件。使用类时，你需要编写事件处理程序，将它们连接到对象的事件上，并编写在事件引发时实际作出反应的代码。（连接事件本质上意味着将方法与事件连接起来。）

在 C++ 中，我们使用函数指针惯用法；在 Delphi 中，我们使用过程类型惯用法来实现事件和事件处理程序。C# 发展出了实际上相当于原始函数指针的机制。C# 实现的是委托惯用法。委托是存储函数指针的特殊类。原始函数指针与委托的区别在于，委托可以维护多个函数指针。包含多个函数指针的委托称为多播委托。

实际上，委托定义将方法签名描述为一种类型。任何签名与委托签名匹配的方法都可以添加到委托对象的调用列表中。定义委托签名等同于在 C++ 中定义函数指针，或在 Delphi 中定义过程类型。以下三条语句展示了相似之处。

每种声明通常表示相应语言中的函数指针声明。区别在于，只有 C# 委托（或任何 .NET 语言委托）可以存储多个地址。C++ 中的函数指针和 Delphi 中的过程类型只能引用一个函数地址。在 C++ 和 Delphi 中，你需要创建指针类型数组来引用不同的函数地址。C# 实际上在类型中包含该数组，使一个委托可以存储多个地址。这就是巨大的区别。

显然，如果你是 VB6 开发者，那么你需要了解什么是函数指针，然后了解委托有什么不同。对于 C++ 和 Delphi 专家，可以把委托看作具有单一签名的函数指针数组。遗憾的是，如果你不知道什么是函数指针以及如何使用委托，那么你编写的代码将如同两条腿的凳子一样不完整。

### 现有委托：

事件声明很直接。通常，事件旨在供类消费者使用，因此通常声明为公共成员。下面展示了一个语法示例。

Access-Modifier 通常是 public。event 关键字是表示该成员为事件的关键字。Delegate-Type 是一个由方法签名描述并使用 delegate 关键字的类。现有委托的一个示例是 EventHandler 委托。Event name 是事件的成员名称；消费者将在代码中使用它来引用该事件。以下声明展示了一个使用 EventHandler 委托的事件。

EventHandler 的签名是一个返回 void 并具有两个参数（object 和 System.EventArgs）的方法。EventHandler 委托的声明在 CLR 中如下：

```csharp
public delegate void EventHandler(object sender, EventArgs e);
```

（该委托已经存在；因此，你不需要自己定义它。）EventHandler 是许多 Windows Forms 控件使用的委托，例如 Button 控件的 Click 事件。

### 声明新的委托类型

如果需要定义自定义委托，可以遵循上一节提供的展示 EventHandler 委托的基本模型。

委托定义实际上等同于一个方法头，只是将 delegate 关键字插入到访问修饰符和返回类型之间。以下示例为另一个返回 void 且不接受参数的方法定义了委托。

```csharp
public delegate void Delegate();
```

请记住 C# 区分大小写，并注意第一个示例创建了一个名为“Delegate”的委托。任何返回 void 且不接受参数的方法都可以赋给声明为 Delegate 类型的事件或字段。

### 作为生产者引发事件

生产者引发事件。在 C# 中，引发事件是通过使用事件名称调用一个方法来执行的。按照惯例，事件由受保护成员引发，这些成员与事件同名，并以“On”为前缀。

回到我们最初的示例，其中 Changed 事件定义为 EventHandler 类型，我们可以用一个引发该事件的受保护方法来匹配该事件。

该事件名为“Changed”。消费者可以将任意数量的、与 EventHandler 委托签名匹配的方法分配给这一个事件成员。在包含该代码的类内部，你可以在任何需要引发 Changed 事件的地方调用 OnChanged。OnChanged 会检查以确保 Changed 已至少分配给一个委托；如果尚未分配，则 OnChanged 返回。否则，生产者将 Changed 当作方法来处理并调用它，同时向它传递必要的参数。
