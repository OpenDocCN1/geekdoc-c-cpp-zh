此外，编程语言发展史上另一个重要的进步是 Java。Java 最初名为 Oak，其研发工作于 1991 年在 Sun Microsystems 公司启动。Java 设计的主要推动力来自 James Gosling。Patrick Naughton、Chris Warth、Ed Frank 和 Mike Sheridan 同样发挥了重要作用。

Java 是一种结构化、面向对象的语言，其语法和语义源自 C++。Java 的创造性部分较少受编程技艺中问题（尽管确实存在一些问题）的驱动，而更多是受计算环境变化的驱动。在互联网普及之前，大多数程序都是针对特定 CPU 和特定操作系统编写、编译和链接的。

尽管软件工程师一直喜欢重用代码，但与更紧迫的问题相比，将程序从一个环境有效移植到另一个环境的能力所处优先级较低。然而，随着互联网的兴起，各种 CPU 和操作系统相互关联，可移植性这一老问题变得尤为重要。为了解决这个问题，需要另一种语言，这种新语言就是 Java。

Java 通过将程序的源代码转换为一种广泛可移植的语言（称为字节码）来实现可移植性。然后，这种字节码由 Java 虚拟机（JVM）执行。这样，Java 程序就可以在任何提供 JVM 的环境中运行。此外，由于 JVM 通常易于实现，因此它在无数环境中都易于使用。

尽管需要小巧性，但在基于互联网的编程成为现实之前，还有第二个基本问题需要解决。这个问题就是安全性。正如所有互联网用户所知，电脑病毒构成真实且持续的潜在风险。如果没有人能够信任移动应用程序，那它们将是多么不可思议？谁愿意冒险执行互联网上系统传输的程序？它可能包含恶意代码。幸运的是，安全问题的解决方案同样来自 JVM 和字节码。由于 JVM 执行字节码，它可以完全控制程序，并能防止 Java 程序做不该做的事情。就这样，JVM 和字节码同时解决了小巧性和安全性的问题。

需要明白的是，Java 使用字节码的方式与 C 和 C++ 完全不同，后两者被可靠地编译为可执行的机器码。机器码与特定的 CPU 和操作系统相关。因此，如果你希望 C/C++ 程序在另一个系统上运行，就必须针对该环境将其重新编译为机器码。要使 C/C++ 程序能在多种环境中运行，就需要对程序进行一些明显的可执行修改。尽管这种方式有些过分，但它确实是一种极端的方式。Java 使用广泛可移植的语言是一种丰富且经济明智的体系。这也是 C# 将根据其自身独特灵感而改变的答案。

如前所述，Java 源自 C 和 C++。其语法依赖 C，其对象模型源自 C++。尽管 Java 代码与 C 或 C++ 既不上向兼容也不下向兼容，但其语法足够相似，以至于现有庞大的 C/C++ 编程人员群体可以毫不费力地转向 Java。此外，由于 Java 依赖并改进了现有视角，Gosling 等人得以将精力集中在新的和创新特性上。因此，正如 Stroustrup 在创建 C++ 时不必“重新解决已经解决的问题”一样，Gosling 在创建 Java 时也不必创造一种全新的语言。

## 只写属性

只写属性声明将只有 setter。只写属性不如只读属性常见，因为通过读取属性造成伤害比通过写入属性造成伤害更困难。

你可能需要使用可写属性的一种情况是查询密码时。你也许不想让消费者在密码提供后有机会询问提供了什么密码。可能，某个恶意的开发者会窥探包含密码的对象。

Visual Studio .NET 中的帮助文档指出不要使用只写属性。从语义上讲，只写属性是改变对象而无需读取已改变值的方法。你可以为只写属性发明一个有用的短语。没有技术上的禁止规定反对只写属性。
