Drawing methods use a Pen object to draw a boundary representing the shape. The shapes are expressed as a region bounded by a bounding rectangle. FillEllipse works almost identically to DrawEllipse; however, rather than a Pen, you have to pass a Brush to FillEllipse because the fill method paints the inside of a region.

There are two kinds of fill and draw methods. One version takes integer arguments defining the rectangular area, and the other version accepts floating-point numbers representing the rectangular region. The advantage of having a floating-point version of shape-drawing methods is that you can perform math operations that return floating-point numbers without truncating those numbers to integers.

The particular drawing or filling method invoked depends on the type of the arguments. Polymorphism helps here. There are several overloaded versions for each of the drawing and filling methods, and the compiler decides, based on the argument types, which explicit method to call.

In addition to defining the rectangular region by specifying four points, you can express the rectangular areas as a pair of Point structures or a Rectangle structure. If you use points or rectangles, then you should use Point or Rectangle if the underlying values are integers, and PointF and RectangleF if the underlying values are floating-point values. A few examples showing the use of the Point and Rectangle structures can be found in the RoundButton.cs file.

## Applying Transforms to Graphics Objects

GDI+ uses world, page, and device coordinates. When you make a call to a Graphics method, the positions you express are in world coordinate space. GDI+ transforms the world coordinate arguments through two transformations, from world coordinates to page coordinates and then device coordinates. GDI+ handles these transformations in the background. The advantage to us as software engineers is that we can change the origin, change the PageUnit from the default pixel to some other unit of measure, and perform tasks like scaling pictures.

These capabilities were used to create the enhanced visualization of the button changing position when RoundButton items are clicked by the client. If the button doesn't change appearance, however slightly, when the client taps the button, then the illusion is lost. The accompanying passage from the RoundButton class applies a scaled Matrix transformation to the Graphics object before drawing the button graphic, resulting in the illusion that the button has moved slightly when the client has tapped the button.

When the client clicks an instance of the RoundButton control, the OnMouseDown method is fired. From the listing we can establish that the base class OnMouseDown method is called. This will enable clients to catch that event; that is, we aren't disturbing the default behavior. At that point, the down field is set to True and the control is invalidated. Calling the Invalidate method forces a repaint to happen. Now, the overloaded OnPaint method is called. Once more, we perform the base.OnPaint behavior followed by the custom behavior.

The custom Paint behavior draws the button, and afterward draws the graphic. If down is True—which in our situation, it is—the DrawDownGraphic method is invoked. (This is where the transformation comes into play.) DrawDownGraphic creates a Matrix object. Matrix.Scale is called to scale the Matrix object, and that Matrix object is applied to the graphics.Transform property. The final product is a graphic that looks as though it has moved slightly when the button is depressed.

When you understand the mechanics, you will see them as very clear. The creativity is finding the correct blend of brushes, hues, and shadings to make the illusion as realistic as possible. You should decide for yourself how realistic the button appears to be by running the VideoKiosk.sln test application.

The better the creativity, the more excellent the application.

## Linear Gradient Brushes

Brushes are used to fill the insides of shapes. There are several sorts of brushes, including the HatchBrush, LinearGradientBrush, PathGradientBrush, SolidBrush, and TextureBrush. These brush types produce a particular sort of result when you use them to fill graphic shapes. When you need a brush, you can make an instance of one of these brush types or use the Brushes class, which contains predefined solid brushes.

If this book were printed in color, what you would be able to see from Figure 3-1 is that the custom round buttons are using a LinearGradientBrush to enhance the 3D effect. A LinearGradientBrush is a brush whose shading advances from a beginning color to an ending color over the space painted by the brush. You have presumably observed this procedure used frequently in splash screens or on older-style install programs.

The LinearGradientBrush has several overloaded constructors. The version used on lines 45 to 50 of Listing 3-3 takes two points and two colors. The points depict the beginning and ending points of the gradient, and the colors depict the start and end colors of the gradient. In the example, by using a White beginning color and a darker ending color, we get the appearance of light shining on the button, which enhances the 3D appearance.

You can determine a wide assortment of properties that refine the gradient effect. The Blend property is a class that depicts what percentages of the beginning and ending colors to use at positions along the gradient. The GammaCorrection property is a Boolean that shows whether gamma correction is applied to the gradient. The InterpolationColors property enables you to determine a ColorBlend that supports showing multicolor linear gradients. The LinearColors property is an array of colors containing the beginning and ending colors for the gradient. The Transform property defines a Matrix that enables you to translate, scale, rotate, or slant gradients. Finally, the Rectangle property defines the beginning and ending points of the gradient brush.

The LinearGradientBrush is used to paint the inside of RoundButtons. The hues used to create the gradients depend on the value of the down field. Up buttons are light and down buttons are darker.

### Characterizing the Tracker Control

For our purposes, it is sensible to implement the Tracker as a custom control. The Tracker is shown as the little slider at the top of the PlayControl in Figure 3-1. The Tracker behaves simply like the ProgressBar control you are most likely already acquainted with.

Like the ProgressBar, the Tracker uses a graphic to show relative advancement. The Tracker enables the client to express a minimum, maximum, and position value. If position is nearer to the minimum value, then the graphic advancement pointer is nearer to the left side of the control; if the position is nearer to the maximum value, then the progress pointer moves toward the right side of the control.
