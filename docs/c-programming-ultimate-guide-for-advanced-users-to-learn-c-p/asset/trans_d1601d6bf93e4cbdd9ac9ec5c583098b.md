
基本上，为了适应程序日益增长的复杂性。例如，当计算机刚被发明时，编程是通过使用计算机的前面板切换二进制机器指令来完成的。只要程序只有几百条指令长，这种方法就有效。随着程序的增长，汇编语言被发明出来，以便程序员能够处理更大、越来越复杂的程序，使用机器指令的符号表示。随着程序继续增长，像 FORTRAN 和 COBOL 这样的高级语言被引入，为程序员提供了更多处理复杂性的工具。当这些早期语言开始达到其极限时，结构化编程被开发出来。

请考虑以下几点：在编程发展的每个里程碑上，都创建了技术和工具，以使开发人员能够管理日益增长的复杂性。每一步，新方法都汲取了过去方法的最佳要素并向前推进。面向对象编程也是如此。在 OOP 之前，许多项目正接近（或超过）结构化方法不再有效的临界点。需要一种更好的处理复杂性的方法，而面向对象编程就是答案。面向对象编程汲取了结构化编程的最佳思想，并结合了一些新概念。结果是一种不同且更好的程序组织方式。

从最一般的意义上讲，程序可以以两种方式之一组织：围绕其代码（正在发生什么）或围绕其数据（受影响的是什么）。仅使用结构化编程技术，程序通常围绕代码编写。这种方法可以被视为“代码作用于数据”。面向对象的程序则相反。它们围绕数据组织，其关键原则是“数据控制对代码的访问”。在面向对象的语言中，你定义数据以及允许作用于该数据的例程。因此，数据类型精确地定义了可以应用于该数据的操作类型。

## 多态
多态是 C# 的一种技术。多态（源自希腊语，意为“多种形式”）是指一种质量，使一个接口能够访问一类通用操作。多态的一个简单例子可以在汽车的方向盘上找到。方向盘（接口）是相同的，无论使用何种实际的转向机构。也就是说，无论你的汽车是手动转向、动力转向还是齿条和小齿轮转向，方向盘的工作方式都相同。因此，无论使用何种转向方式，向左转动方向盘都会使汽车向左行驶。统一接口的优点显然是，一旦你知道如何操作方向盘，你就可以驾驶任何类型的汽车。

类似的原则也可以应用于编程。例如，考虑一个栈（即先进后出列表）。你可能有一个程序需要三种不同类型的栈。一个栈用于整数值，一个用于浮点值，一个用于字符。在这种情况下，实现每个栈的算法是相同的，尽管存储的数据不同。在非面向对象的语言中，你需要创建三套不同的栈例程，每套使用不同的名称。然而，由于多态性，在 C# 中，你可以一次性指定栈的通用形式，然后将其用于全部三种特定情况。因此，如果你知道如何使用一个栈，你就可以使用它们全部。更一般地说，多态的概念通常用短语“一个接口，多个方法”来表达。这意味着可以为一组相关活动设计一个通用接口。多态通过允许使用相同的接口来指定一类通用操作，从而降低了复杂性。选择特定操作（即方法）在每种情况下如何应用是编译器的任务。你，程序员，无需手动做出此决定。你只需记住并使用通用接口。

## 继承
继承是一个对象可以获取另一个对象属性的过程。

这很重要，因为它支持层次分类的概念。毕竟，大多数知识都是通过层次（即自上而下）的分类变得可管理的。例如，红美味苹果属于苹果分类，而苹果又属于水果类，水果类属于更大的食物类。也就是说，食物类具有某些特性（可食用、有营养等），这些特性在逻辑上也适用于其子类水果。除了这些特性外，水果类还具有特定的特性（多汁、甜等），使其与其他食物区分开来。苹果类定义了苹果特有的特性（生长在树上、非热带等）。红美味苹果反过来将继承所有前序类的特性，并且只定义使其独一无二的特性。如果不使用层次结构，每个对象都需要显式定义其所有属性。使用继承，一个对象只需定义使其在其类中独一无二的特性即可。它可以从其父类获取其通用属性。因此，正是继承机制使得一个对象能够成为更一般情况的特定实例成为可能。

```csharp
/*
This is a simple C# program.
Call this program Example.cs.
*/
using System;
class Example {

    // A C# program begins with a call to Main().
    static void Main() {
        Console.WriteLine("C# gives you programming power.");
    }
}
```

### 编译程序
编译程序时，执行 C# 编译器 csc.exe，并在命令行上指定源文件名称，如下所示：

```
C:\>csc Example.cs
```

csc 编译器创建一个名为 Example.exe 的文件，其中包含程序的 MSIL 版本。虽然 MSIL 不是可执行代码，但它仍然包含在 .exe 文件中。公共语言运行时在你尝试执行 Example.exe 时会自动调用 JIT 编译器。然而请注意，如果你尝试在未安装 .NET Framework 的计算机上执行 Example.exe（或任何其他包含 MSIL 的 .exe 文件），程序将无法执行，因为 CLR 将缺失。
