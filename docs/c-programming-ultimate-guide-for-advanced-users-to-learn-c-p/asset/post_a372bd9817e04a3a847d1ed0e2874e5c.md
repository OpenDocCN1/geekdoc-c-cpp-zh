The innovative aspects of Java were driven less by advances in the art of programming (although some surely were) than by changes in the computing environment. Before the mainstreaming of the Internet, most programs were written, compiled, and targeted for a particular CPU and a particular operating system. While it has always been true that programmers like to reuse their code, the ability to easily port a program from one environment to another assumed a lower priority relative to more pressing issues. However, with the rise of the Internet, in which a wide variety of CPUs and operating systems are connected, the old issue of portability became considerably more significant. To solve this issue, another language was required, and this new language was Java. Java achieved portability by translating a program's source code into an intermediate language called bytecode. This bytecode was then executed by the Java Virtual Machine (JVM). Accordingly, a Java program could run in any environment for which a JVM was available. Moreover, since the JVM is generally simple to implement, it was readily available for countless situations. Notwithstanding the need for portability, there was a second key issue that had to be solved before Internet-based programming could become a reality. This issue was security. As all Internet users know, computer viruses constitute a genuine and ongoing potential threat. What good would portable programs be if nobody could trust them? Who would want to risk executing a program delivered via the Internet? It may contain malicious code. Luckily, the solution to the security issue is also found in the JVM and bytecode. Since the JVM executes the bytecode, it has full control of the program and can prevent a Java program from doing something that it shouldn't. Thus, the JVM and bytecode solved both the issues of portability and security. The for loop can proceed in a positive or negative direction, and it can change the loop control variable by any amount. For instance, the following loop prints the numbers 100 to -100, in decrements of 5:

```csharp
// A negatively running for loop.

for(x = 100; x >= -100; x -= 5)
{
    Console.WriteLine(x);
}
```

A significant point about for loops is that the conditional expression is constantly tested at the top of the loop. This means the code inside the loop may not be executed at all if the condition is false initially.

This loop will never execute because its control variable, count, is greater than five when the loop is first entered. This makes the conditional expression, count < 5, false from the beginning; therefore, not even one iteration of the loop will happen. Here, commas separate the two initialization statements and the two iteration expressions. When the loop starts, both i and j are initialized. Each time the loop repeats, i is incremented and j is decremented. Multiple loop control variables are often useful and can simplify certain calculations. You can have any number of initialization and iteration expressions, but in practice, more than two make the for loop cumbersome.

The general form of the for loop for repeating a single statement is

```
for(initialization; condition; iteration) statement;
```

For repeating a block, the general structure is

```
for(initialization; condition; iteration)
{
    statement sequence
}
```

The initialization is normally an assignment statement that sets the initial value of the loop control variable, which acts as the counter that controls the loop. The condition is a Boolean expression that determines if the loop will repeat. The iteration expression defines the amount by which the loop control variable will change each time the loop is repeated. Notice that these three significant parts of the loop must be separated by semicolons. The for loop will continue executing as long as the condition tests true. When the condition becomes false, the loop will exit, and program execution will continue with the statement following the for loop.
