## Utilizing Modifiers

Modifiers address data hiding. Data hiding embodies the platitude "need to know." That is, as a maker, if you can hide something from a customer, then they don't need to worry about it. Subsequently, out of mind.

Access modifiers enable you to put things out of mind when you are coding. When creating classes, make just those things public that consumers need to interact with to use the class. By restricting what you expose in the public interface, you are making it simpler to consume your classes. This is true regardless of whether you are the first consumer of the classes you produce.

There are a few access modifiers to choose from. C# supports public, protected, internal, protected internal, private, and readonly for fields. The bulleted list quickly describes the purpose of each access modifier.

The public modifier gives unrestricted access to types and members.

The protected access modifier gives unrestricted access within and to child classes and limited access to consumers. The protected access modifier can be applied to nested types.

The private access modifier gives the most limited access. Just the author of a class may use its private members. Consumers and children have no access to private members. The private access modifier can be applied to nested types.

The internal access modifier implies that types and members are available just inside the same assembly. The internal modifier is used to enable code to interact within across class boundaries without exposing those components to consumers outside of the assembly.

The protected internal modifier limits access to the same assembly for nested types.

When you are declaring top-level types, you should use the public or internal access modifier. You may use private and protected access for types just when those types are nested. A nested type is a type definition that contains a type definition.

You may not combine access modifiers, with the exception of the protected internal modifier. You may not use access modifiers on namespaces. If you don't specify an access modifier, then a default access level will be used. It is best to explicitly show the degree of access as opposed to relying on a default access.

## Utilizing Class Modifiers

When you define classes and the enclosing element is a namespace, then the class can be defined to have public or internal access. If you don't specify a modifier for a top-level class, then the class will have public.

Nested classes can be defined with any access modifier, however you may just use protected, protected internal, and private access modifiers on nested classes.

Class access modifier rules apply to any struct and enum types, as well.

## Utilizing Member Modifiers

You may use any access modifier on members of types, as well. If you define members without an access modifier, then members are private by default.

## Operator Overloading:

Operators are tokens that perform an action on data. Data are referred to as operands when they are the subject of an action. Basic operators, such as the addition operator, +, exist for value types. An example of a value type is an integer, such as 5. It is intuitive to perform operations like 5 + 4 on integer types.

Unfortunately, all of the potential types that may exist cannot be envisioned; yet when types are created, it may also be natural to perform simple operations on those types, as well. An example is demonstrated by the string concatenation operator. When you encounter code like

```
string s = "overload operators " + "are cool"
```

it is intuitively understood that the statement is performing string concatenation.

Overload operators are methods. In particular, they are methods with a special language syntax. You can understand operators by considering overload operators as two parts. The first part executes a standard named method that performs the task that the operator would perform. The second part defines the operator method using the special syntax and calls the named method within the operator. (Obviously, you could generally skip overloading operators, yet that would be unpleasant.)
