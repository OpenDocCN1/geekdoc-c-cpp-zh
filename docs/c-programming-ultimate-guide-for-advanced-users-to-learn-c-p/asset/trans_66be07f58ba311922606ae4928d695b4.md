## 描述接口

IListener 接口定义了两个方法：Listening 和 Listen。Listening 是一个属性，返回一个布尔值，指示实现 IListener 接口的对象是否希望接收消息。这使对象可以形象地“堵住耳朵”，而无需从 Broadcaster 注销。Listen 方法是在监听时接收字符串内容的方法。

可以通过实现 IListener 接口来使用 Broadcaster。FormMain 类实现 IListener，以在状态栏中显示通信消息。对于主窗体，可以在 Form 的 Load 中将该窗体添加到监听器列表中。将控件添加到监听器列表的另一个好位置是类的构造函数。考虑实现 IDisposable 和 Dispose，以便在对象被丢弃时将其从 Broadcaster 的监听器列表中移除。

### 多线程

最后，我们来到多线程。多线程是一个难以预测的主题。多线程有若干特性，因此在本节中，我们将把多线程的讨论限制在它用于帮助实现 AssemblyViewer 的方式上。

AssemblyViewer 在加载应用程序时使用另一个线程显示 Splash 屏幕。这无疑是一种奢侈，但如果启动屏幕以顺序方式执行，那它还有什么意义？也就是说，在启动屏幕加载期间，不会发生真正的初始化，而且我从来不喜欢让启动屏幕有机会包含初始化代码。（不过，你可能会发现，许多启动屏幕确实包含初始化代码。）

在我们的示例应用程序中，启动屏幕运行在单独的线程上。在 .NET 中，有四种不同的方式可以实现看似异步的行为。Timer 控件和 Application.Idle 事件提供事件驱动的同步行为。控件支持异步的 BeginInvoke 和 EndInvoke。

ThreadPool 类提供可访问线程的池，而 Thread 类使你能够自行启动和管理线程。

AssemblyViewer 使用 ThreadPool 类中的一个线程；因此，这里介绍的就是这种线程特性。
