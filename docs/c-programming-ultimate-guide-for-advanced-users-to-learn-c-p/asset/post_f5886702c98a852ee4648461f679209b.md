## Reflection

Reflection is a facility implemented in C# that enables you to dynamically find information, such as the namespaces, interfaces, classes, methods, properties, and fields in an assembly. In addition to providing an approach to request the value of metadata described by attributes, Reflection enables you to learn about the types and members in types defined in an assembly, and Reflection enables you to emit Intermediate Language (IL) code at run-time. IL is similar in intent to Java byte code. IL is the code before it is assembled into machine code. Reflection is amazing magic.

C# 3.0 defines 13 contextual keywords that have a special meaning in specific contexts. In those specific contexts, they act as keywords. Outside their context, they can be used as identifiers for other program elements, such as variable names. In this manner, they are not actually reserved. As a general rule, however, you should consider the contextual keywords reserved and avoid using them for any other purpose. Using a contextual keyword as a name for another program element can be confusing and is considered bad practice by many software engineers. In C#, an identifier is a name assigned to a method, a variable, or some other user-defined thing. Identifiers can be from one to several characters in length. Variable names may begin with any letter of the alphabet or with an underscore. The next character might be a letter, a digit, or an underscore.

The underscore can be used to improve the readability of a variable name, as in line_count. Remember that you cannot begin an identifier with a digit. Therefore, 12x is invalid, for instance. Good programming practice dictates that you use identifier names that reflect the meaning or use of the things being named. Although you cannot use any of the C# keywords as identifiers, C# allows you to precede a keyword with an @, enabling it to be a legal identifier. For instance, @for is a valid identifier. In this case, the identifier is really for and the @ is disregarded. Honestly, using @-qualified keywords for identifiers isn't recommended, except for specific purposes. Likewise, the @ can precede any identifier, but this is considered bad practice.

The difference between signed and unsigned numbers is how the high-order bit of the integer is interpreted. If a signed integer is indicated, the C# compiler will create code that assumes the high-order bit of an integer is to be used as a sign bit. If the sign bit is 0, the number is positive; if it is 1, the number is negative. Negative numbers are almost always represented using the two's complement approach. In this strategy, all bits in the number are inverted, and afterward 1 is added to this number.
