## 5.3

## Implementing HTTP Servers and Clients

The Hypertext Transfer Protocol (HTTP) is a cornerstone of the web, enabling the communication between web servers and clients. While numerous high-level programming languages offer libraries to abstract the complexities of HTTP operations, implementing HTTP servers and clients in C provides a deep understanding of the protocol’s underpinnings. This section introduces the basics of HTTP, followed by detailed examples of implementing simple HTTP servers and clients in C.

Understanding HTTP: HTTP is a request-response protocol in the client-server computing model. A client, typically a web browser or a specialized HTTP client, sends an HTTP request to the server. The server, which stores content and service resources, processes the request and returns HTTP response. This interaction is stateless, meaning each request-response pair is independent, with no stored context between transactions.

HTTP requests and responses are composed of:

- A start line defining the request method, URI, and HTTP version for requests, or the status code and phrase for responses, which carry metadata for request and response messages.
- An optional message containing the transmitted data.

Implementing a Simple HTTP Server: A basic HTTP server can be implemented using TCP sockets, as HTTP is an application-layer protocol that runs over TCP/IP. The server needs to handle incoming client connections, parse HTTP requests, and generate appropriate HTTP responses. Below is a simple C program demonstrating a minimal HTTP server.

```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <netinet/in.h>

int main() {
    int server_fd, client_fd;
    struct sockaddr_in server_addr, client_addr;
    socklen_t sin_len = sizeof(client_addr);
    char buf[2048];
    server_fd = socket(AF_INET, SOCK_STREAM, 0);
    server_addr.sin_family = AF_INET;
    server_addr.sin_addr.s_addr = INADDR_ANY;
    server_addr.sin_port = htons(8080);
    bind(server_fd, (struct sockaddr *)&server_addr, sizeof(server_addr));
    listen(server_fd, 5);
    if ((client_fd = accept(server_fd, (struct sockaddr *)&client_addr, &sin_len)) != -1) {
        read(client_fd, buf, 2047);
        char response[] = "HTTP/1.1 200 OK\r\nContent-Type: text/plain\r\n\r\nHello, world!";
        send(client_fd, response, strlen(response), 0);
        close(client_fd);
    }
    return 0;
}
```

This server listens on port 8080 and responds with a simple "Hello, world!" message to every HTTP GET request. It demonstrates the basics of parsing HTTP requests and constructing responses. However, a real-world HTTP server would need to handle various HTTP methods, parse headers, support concurrent connections, and serve actual content.

Hello, world!

Implementing a Simple HTTP Client: An HTTP client in C can be implemented similarly by establishing a TCP connection to the server, sending a an HTTP request, and processing the response. Below is an example of a simple HTTP client.

```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <netdb.h>
#include <netinet/in.h>

int main() {
    struct addrinfo hints, *res;
    int sockfd;
    char buf[2048];
    memset(&hints, 0, sizeof(hints));
    hints.ai_family = AF_UNSPEC;
    hints.ai_socktype = SOCK_STREAM;
    getaddrinfo("example.com", "80", &hints, &res);
    sockfd = socket(res->ai_family, res->ai_socktype, res->ai_protocol);
    connect(sockfd, res->ai_addr, res->ai_addrlen);
    char http_request[] = "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n";
    send(sockfd, http_request, strlen(http_request), 0);
    read(sockfd, buf, 2047);
    printf("%s", buf);
    close(sockfd);
    freeaddrinfo(res);
    return 0;
}
```

This client establishes a connection to "example.com" on port 80, sends a simple HTTP GET request for the root document, and prints the response. Notice the use of getaddrinfo to retrieve the address structure for the server, abstracting away the handling of IPv4 and IPv6 addresses.

Implementing HTTP servers and clients in C offers an enriching learning experience, showcasing the interaction between TCP/IP and application-layer protocols. While modern applications might leverage high-level libraries and frameworks for HTTP communications, the principles illustrated here are fundamental to network programming.
