# Analyzing Core Dumps with gdb

To analyze a core dump, you can use the GNU Debugger (gdb). Assuming your program is named faulty and the generated core dump is named you can start the analysis with the following command:

```
gdb faulty core
```

Once in gdb, you can inspect the state of the program at the time of the crash. Useful commands include:

+   print the stack trace, showing the function call sequence leading to the crash.

+   info display local variables in the current stack frame.

+   show the source code around the current line.
