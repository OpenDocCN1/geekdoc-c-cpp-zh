# Interpreting gdb Output

Upon analyzing the core dump of the previous example in gdb, you might see output similar to the following:

```
Program terminated with signal SIGSEGV, Segmentation fault.
#0 0x0000000000004012f in main () at faulty.c:5
5    *(str + 1) = 'a';
(gdb) bt
#0 0x0000000000004012f in main () at faulty.c:5
(gdb) list
1  #include
2
3  int main() {
4      char *str = "hello, world";
5      *
      (str + 1) = 'a'; // Attempt to modify a string literal causes segmentation fau
6-lt
6      printf("%s\n", str);
7      return 0;
8  }
```

This gdb session indicates that the program crashed due to a segmentation fault at line 5 of exactly where the attempt to modify a string literal occurs.

Core dumps are a critical tool for understanding the circumstances leading to a program’s crash, especially when dealing with complex systems
