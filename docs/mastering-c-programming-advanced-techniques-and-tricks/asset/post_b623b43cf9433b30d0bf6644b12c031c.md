## 5.1 Basics of Socket Programming: TCP and UDP Sockets

In the realm of network programming, the concept of sockets plays a pivotal role. Sockets provide the necessary communication endpoint for sending and receiving data between different processes, either within the same system or across a network. Broadly, there are two types of sockets that cater to different needs and protocols: TCP (Transmission Control Protocol) sockets and UDP (User Datagram Protocol) sockets. This section delves into the fundamentals of socket programming, covering both TCP and UDP sockets, and demonstrates their usage through detailed code examples.

Understanding Sockets: At its core, a socket is an interface for communication between two processes. Imagine a socket as one end of a two-way communication link between a client and server. Each socket has an associated IP address and port, which work together to identify the communication endpoint uniquely.

TCP provide a reliable, connection-oriented way to send and receive data. The data sent over a TCP connection is guaranteed to arrive in order and without duplication, making TCP sockets suitable for applications where reliable delivery is crucial, such as web servers.

UDP, on the other hand, is a connectionless, unreliable service. Data packets sent over UDP may arrive out of order or be lost altogether. However, the lightweight nature of UDP, with no connection setup or teardown and minimal protocol overhead, makes it ideal for applications that can tolerate loss but require fast, efficient communication, like video streaming or online gaming.

Creating a TCP Socket: Starting with TCP typically involves creating a socket, binding it to an address and port, listening for incoming connections, accepting a connection, and reading from or writing to the socket. Below is a simple C program that demonstrates creating a TCP server socket.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <netinet/in.h>

int main(int argc, char *argv[]) {
    int sockfd, newsockfd, portno, clilen;
    char buffer[256];
    struct sockaddr_in serv_addr, cli_addr;
    int n;

    sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd < 0) return 1;

    memset(&serv_addr, 0, sizeof(serv_addr));
    serv_addr.sin_family = AF_INET;
    serv_addr.sin_addr.s_addr = INADDR_ANY;
    portno = 5001;
    serv_addr.sin_port = htons(portno);

    if (bind(sockfd, (struct sockaddr *)&serv_addr, sizeof(serv_addr)) < 0) return 1;

    listen(sockfd, 5);
    clilen = sizeof(cli_addr);
    newsockfd = accept(sockfd, (struct sockaddr *)&cli_addr, &clilen);
    if (newsockfd < 0) return 1;

    n = read(newsockfd, buffer, 255);
    if (n < 0) {
        buffer[n] = '\0';
        printf("Here is the message: %s\n", buffer);
        send(newsockfd, buffer, strlen(buffer), 0);
    }
    close(newsockfd);
    return 0;
}
```

This code snippet outlines a basic server setup that listens on port 5001. Upon receiving a connection, it reads the message sent by the client, displays it, and then sends a response back to the client.

Creating a UDP Socket: UDP socket programming is somewhat simpler since there's no need to listen or accept connections. Data can be sent and received directly once the socket has been created and bound. Here’s an example UDP server program:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <netinet/in.h>

int main() {
    int sockfd;
    struct sockaddr_in serv_addr, cli_addr;
    socklen_t addrlen = sizeof(cli_addr);
    char buffer[1024];
    int n;

    sockfd = socket(AF_INET, SOCK_DGRAM, 0);
    if (sockfd < 0) return 1;

    memset(&serv_addr, 0, sizeof(serv_addr));
    serv_addr.sin_family = AF_INET;
    serv_addr.sin_addr.s_addr = INADDR_ANY;
    serv_addr.sin_port = htons(5002);

    if (bind(sockfd, (struct sockaddr *)&serv_addr, sizeof(serv_addr)) < 0) return 1;

    while (1) {
        n = recvfrom(sockfd, buffer, 1024, MSG_WAITALL, (struct sockaddr *)&cli_addr, &addrlen);
        buffer[n] = '\0';
        printf("Received: %s\n", buffer);
        sendto(sockfd, buffer, strlen(buffer), 0, (struct sockaddr *)&cli_addr, addrlen);
    }
    return 0;
}
```

Through TCP and UDP sockets, programmers can achieve both reliable, connection-oriented communications and faster, connectionless communications according to the needs of their applications. ## 5.2 Developing Scalable Servers with Non-blocking Sockets and I/O Multiplexing

The scalability of networked applications, especially servers that handle multiple client connections simultaneously, often hinges on the effective use of non-blocking sockets and I/O multiplexing. These features are imperative for designing high-performance systems that can manage thousands of concurrent connections without succumbing to the limits of traditional blocking I/O. This section introduces non-blocking sockets, dives into the essentials of I/O multiplexing, and demonstrates how to leverage these concepts to build scalable servers in C.

Non-blocking Socks: In traditional socket programming, sockets are in blocking mode by default. This implies that the call to send or receive data over a socket is blocked until the operation completes. While this model is straightforward and works well for applications with low concurrency requirements, it significantly limits scalability. With blocking sockets, each connection generally requires a dedicated thread or process to handle I/O operations independently, leading to excessive resource utilization and scalability bottlenecks.

Non-blocking sockets, as the name suggests, allow socket operations to return immediately, even if the operation does not complete. This permits the application to carry on with other tasks or even handle I/O on multiple sockets concurrently within a single thread. To enable non-blocking mode, the call is used to change the socket’s properties. In non-blocking mode, functions return a status indicating whether the operation would block, allowing the application to decide how to proceed.

I/O Multiplexing: Leveraging non-blocking sockets alone does not fully solve the problem of managing multiple connections efficiently. This is where I/O multiplexing comes into play, allowing a single thread to monitor multiple file descriptors (sockets in this case) for readiness to perform I/O operations. Techniques like select and epoll are used for I/O multiplexing in Unix-like systems.

a way to check multiple sockets for activity by specifying a list of sockets to monitor and waiting for one or more of these sockets to become "ready" for reading or writing. epoll available on Linux, is more efficient than a large number of sockets, as it does not require the list of sockets to be rebuilt for each call.

Implementing a Server with Non-blocking Sockets and epoll: Below is an example demonstrating a simple echo server that utilizes non-blocking sockets along with epoll for handling multiple client connections easily.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <netinet/in.h>
#include <sys/epoll.h>

#define MAX_EVENTS 10

void set_nonblocking(int sockfd) {
    int opts = fcntl(sockfd, F_GETFL);
    if (opts < 0) return;
    fcntl(sockfd, F_SETFL, opts | O_NONBLOCK);
}

int main() {
    int sockfd, newsockfd, portno = 5003;
    struct sockaddr_in serv_addr, cli_addr;
    socklen_t clilen = sizeof(cli_addr);
    int epoll, nfds;
    struct epoll_event ev, events[MAX_EVENTS];

    sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd < 0) return 1;
    set_nonblocking(sockfd);

    memset(&serv_addr, 0, sizeof(serv_addr));
    serv_addr.sin_family = AF_INET;
    serv_addr.sin_addr.s_addr = INADDR_ANY;
    serv_addr.sin_port = htons(portno);

    if (bind(sockfd, (struct sockaddr *)&serv_addr, sizeof(serv_addr)) < 0) return 1;
    listen(sockfd, 5);

    epoll = epoll_create1(0);
    ev.events = EPOLLIN;
    ev.data.fd = sockfd;
    epoll_ctl(epoll, EPOLL_CTL_ADD, sockfd, &ev);

    while (1) {
        nfds = epoll_wait(epoll, events, MAX_EVENTS, -1);
        for (int i = 0; i < nfds; i++) {
            if (events[i].data.fd == sockfd) {
                newsockfd = accept(sockfd, (struct sockaddr *)&cli_addr, &clilen);
                if (newsockfd >= 0) {
                    set_nonblocking(newsockfd);
                    ev.events = EPOLLIN;
                    ev.data.fd = newsockfd;
                    epoll_ctl(epoll, EPOLL_CTL_ADD, newsockfd, &ev);
                }
            } else {
                char buffer[256];
                int n = read(events[i].data.fd, buffer, 255);
                if (n > 0) {
                    buffer[n] = '\0';
                    send(events[i].data.fd, buffer, strlen(buffer), 0);
                } else if (n == 0) {
                    epoll_ctl(epoll, EPOLL_CTL_DEL, events[i].data.fd, NULL);
                    close(events[i].data.fd);
                }
            }
        }
    }
    return 0;
}
```
