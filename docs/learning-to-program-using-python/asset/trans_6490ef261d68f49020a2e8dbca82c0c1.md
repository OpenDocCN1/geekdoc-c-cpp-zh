

## 第 8 章
### 字典

除了列表，字典是 Python 中最有用的数据类型之一。Python 字典是无序的对象集合，通过关键字进行匹配。而 Python 列表则是使用数值偏移量的有序集合。

由于其结构特性，字典可以替代在 C 及相关语言中常见的许多“典型”搜索算法和数据结构。对于来自其他语言的开发者来说，Python 字典就像哈希表，其中对象映射到键名。

字典包含以下特性：

1. 通过关键字而非偏移量访问。字典类似于关联数组。字典中的每个项目都有一个对应的关键字；使用关键字来“调用”该项目。
2. 存储的对象以随机顺序排列，以提供更快的查找速度。创建时，字典按任意顺序存储项目。要获取值，只需提供键。如果你需要对字典内的项目排序，必须自行处理；没有内置方法实现此功能。
3. 字典长度可变，可持有任意类型的对象（包括其他字典），并支持深层嵌套（字典中可以包含多个层级的项目，例如另一个字典内的列表，该字典又位于另一个字典中）。
4. 它们是可变的，但不能像列表或字符串那样直接修改；它们是支持映射的唯一数据类型。
5. 内部实现上，字典作为哈希表实现。

以下是（现已标准化的）常用操作列表：

- `d1 = {}` 空字典
- `d2 = {'spam': 2, 'eggs': 3}` 双项目字典
- `d3 = {'food': {'ham': 1, 'egg': 2}}` 嵌套
- `d2['eggs'], d3['food']['ham']` 按键索引
- `d2.has_key('eggs'), d2.keys(), d2.values()` 方法：成员测试、键列表、值列表等
- `len(d1)` 长度（存储的条目数）
- `d2[key] = new, del d2[key]` 添加/修改，删除

### 8.1 创建字典

如前所述，你通过键创建字典并访问项目。键可以是任何不可变类型，如字符串、数字或元组。值可以是任何类型的对象，包括其他字典。创建字典的格式如清单 8.1 所示：

```python
Listing 8.1: 字典格式

>>> dictionary = {"key_name": "value"}
```

然而，键名和值可以是允许的任何内容，例如：

```python
Listing 8.2: 字典键示例

>>> dictionary = {"cow":"barn", 1:"pig", 2:["spam", "green", "corn"]}
```

请注意，字典使用花括号，关键字与其关联值之间的分隔符是冒号，每个键/值对之间由逗号分隔。这只是可能导致程序中出现语法错误的部分问题。

### 8.2 基本操作

`len()` 函数可用于给出字典中存储的项目数或键列表的长度。`keys()` 方法将字典中的所有键作为列表返回。以下是几个示例：

```python
Listing 8.3: 一些字典方法
>>> d2 = { 'spam' :2, 'ham':1, 'eggs' :3}
>>> d2[ 'spam' ] #获取键对应的值
2
>>> len(d2) #字典中的条目数
3
>>> d2.has_key('ham') #键是否存在？（1 表示真）
1
>>> d2.keys() #键列表
['eggs', 'spam', 'ham']
```

由于字典是可变的，你可以添加和删除其值，而无需创建新的字典对象。只需为键分配值即可更改或创建条目，并使用 `del` 删除与给定键关联的对象。

```python
Listing 8.4: 修改字典
>>> d2[ 'ham' ] = [ 'grill', 'bake', 'fry'] # 更改条目
>>> d2
{'eggs' : 3, 'spam' : 2, 'ham' : [ 'grill', 'bake', 'fry' ]}
>>> del d2[ 'eggs' ] #根据关键字删除条目
>>> d2
{'spam' : 2, 'ham' : [ 'grill', 'bake', 'fry']}
>>> d2['brunch'] = 'Bacon' #添加新条目
>>> d2
{'brunch': 'Bacon', 'ham' : [ 'grill', 'bake', 'fry' ], 'spam' : 2}
```

与列表相比，向字典添加新对象只需创建一个新关键字和值。如果偏移量超出列表末尾，列表会返回“索引越界”错误。因此，你必须使用追加或切片向列表添加值。

下面是一个更贴近实际的字典示例。以下示例创建一个表格，将编程语言名称（键）映射到它们的创造者（值）。你可以通过语言名称索引来获取创造者名称：

```python
Listing 8.5: 使用字典

>>> table = {'Python':'Guido van Rossum',
...         'Perl':'Larry Wall',
...         'Tcl':'John Ousterhout'}
...
>>> language = 'Python'
>>> creator = table[language]
>>> creator
'Guido van Rossum'
>>> for lang in table.keys(): print lang, '\t', table[lang]
...
Tcl John Ousterhout
Python Guido van Rossum
Perl Larry Wall
```

从这个例子中，你可能会注意到最后一个命令类似于使用 *for* 命令进行的字符串和列表迭代。然而，你还会注意到，由于字典不是序列，因此不能使用标准的 *for* 语句。你必须使用 *keys()* 方法返回所有关键字的列表，然后像普通列表一样对其进行迭代。

你可能还注意到，字典可以像轻量级数据库一样工作。上面的示例创建了一个表，其中编程语言的“列”通过创造者的“行”进行匹配。如果你需要数据库，可能考虑使用字典代替。如果数据适合存储，你可以节省大量不必要的编码工作，并减少处理完整数据库带来的麻烦。诚然，你拥有不到真正数据库的灵活性和强大功能，但对于快速且简单的解决方案，字典已经足够。

### 8.3 字典细节

1. 序列操作不适用。如前所述，字典是映射，不是序列。由于字典项目没有顺序，诸如拼接和切片等函数不起作用。
2. 分配新索引会添加条目。键可以在创建字典时（即初始创建字典时）或通过向现有字典添加新值来创建。过程相似，最终结果相同。
3. 键可以是任何不可变对象。之前的示例显示键为字符串对象，但任何非可变对象（如列表）都可以用作关键字。数字可用于创建类似列表的对象，但没有顺序。元组（稍后介绍）有时用于创建复合键；设计为不可变的类实例（稍后介绍）在需要时也可使用。

好吧，我们几乎完成了 Python 类型的内容。下一章将涵盖元组，基本上是不可变的列表。

## 第 9 章
### 元组

最后一个内置数据类型是元组。Python 元组的工作方式与 Python 列表完全相同，除了它们是不可变的，即不能就地修改。通常写在括号内以区别于使用方括号的列表，但你会发现，括号并不总是必要的。由于元组是不可变的，其长度是固定的。若要扩展或缩小元组，必须创建一个新的元组。

以下是元组常用操作的列表：

- `()` 空元组
- `t1 = (0, )` 单项目元组（不是表达式）
- `t2 = (0, 1, 2, 3)` 四项目元组
- `t3 = 0, 1, 2, 3` 另一个四项目元组（与上一行相同，只是没有括号）
- `t3 = ('abc', 'def', 'ghi')` 嵌套元组
- `t1[n], t3[n][j]` 索引
- `t1[i:j]` 切片
- `len(tl)` 长度
- `t1 + t2` 拼接
- `t2 * 3` 重复
- `for x in t2,` 迭代
- `3 in t2` 成员测试

第二个条目展示了如何创建单项目元组。由于括号可以包围表达式，因此你需要通过在项目后放置逗号来向 Python 表明单个项目实际上是元组。第四个条目展示了一个没有括号的元组；当元组无歧义时可以使用这种形式。然而，弄清楚何时可选比直接使用括号更麻烦。

### 9.1 为什么要使用元组？

元组通常存储异构数据，类似于列表通常存储同质数据。这并非硬性编码规则，而只是一部分 Python 程序员遵循的惯例。由于元组是不可变的，它们可用于存储关于特定事物的不同数据。例如，联系人列表可以存储在元组中；你可以在一个数据对象中包含姓名和地址（都是字符串）以及电话号码（整数）。

最需要记住的一点是，切片和迭代等标准操作会返回新的元组对象。在我的编程中，除了不想让集合改变的情况外，我喜欢对所有情况都使用列表。这减少了我需要思考的集合数量，而且元组不允许你向其中添加新项目或删除数据。在这些情况下，你必须创建一个新的元组。

有时你的代码要求你不得不使用元组。然而，很多时候你并不知道代码的具体用途，而列表的灵活性可能很有用。

那么为什么要使用元组？除了有时它是让代码工作的唯一方式外，没有其他理由使用元组：

- 元组的处理速度比列表快。如果你创建一组不会改变的值常量，并且只需要简单地进行迭代，请使用元组。
