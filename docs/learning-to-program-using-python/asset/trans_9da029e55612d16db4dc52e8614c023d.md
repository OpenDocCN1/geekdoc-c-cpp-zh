简单来说，命名空间存储了关于标识符及其值的信息。Python 有三种命名空间：局部、全局和内置。当一个标识符首次被访问时，Python 会先在局部查找它的值，即它周围的代码块。在上面的示例中，“x”是在函数 **square()** 内部定义的。每个函数都会被分配一个自己的局部命名空间。函数无法使用在其他函数中定义的标识符；它们基本上是不可见的。如果一个函数试图调用另一个函数中定义的变量，你会得到一个错误。如果一个函数试图定义一个之前已定义的变量，你得到的将是一个恰好同名但值不同的全新变量。

然而，如果标识符没有在局部定义，Python 会检查它是否存在于全局命名空间中。全局命名空间与局部命名空间的区别在于，全局标识符可以被其他函数使用。因此，如果你定义了一个全局变量 `cars_in_shop = 2`，程序中的所有函数都可以访问该变量并按需使用它。这样，你就可以在一个位置定义变量，并在多个地方使用它，而无需反复定义。但是，这并不推荐，因为这可能导致安全问题或编程问题。例如，将变量设为全局意味着任何函数都可以访问它们。如果你开始让多个函数使用同一个变量，你就无法知道在任何给定时刻该变量正在发生什么；没有保证说当你使用它时，它的值会是你期望的那样。

这并不意味着全局变量是绝对禁止使用的。如果使用得当，它们非常有用，可以让你的工作更轻松。但它们可能会限制程序的可扩展性，并且经常导致难以解释的逻辑错误，所以我倾向于避免使用它们。

内置命名空间是为 Python 的内置函数预留的。（挺方便的，对吧？）因此，像 **range()** 这样的关键字和标准函数调用在 Python 解释器启动时就已经定义了，你可以“开箱即用”。

你可能已经猜到，命名空间是嵌套的：

- 全局
- 局部

如果标识符未在局部找到，Python 会检查全局命名空间。如果那里也没有，Python 会检查内置命名空间。如果仍然找不到，它会抛出错误并终止。

需要考虑的一点（我稍早些也提到了）是，当你向下遍历命名空间树时，你可以隐藏标识符。如果你在全局定义了 `cars_in_shop = 2`，你可以创建一个具有完全相同名称但不同值的函数，例如 `cars_in_shop = 15`。当函数调用此变量时，它将使用 15 而不是 2 来计算结果。这是全局变量的另一个问题；如果你没有良好的变量命名习惯，它们可能会引起问题，因为你可能忘记了实际上使用的是哪个变量。

### 13.3 默认参数

创建函数时，你可以为参数设置默认值，以防调用者没有提供任何参数。例如：

![](img/d63d52373cb3bc50aa7b31d0d4a29406_102_0.png)

```python
def perimeter(length = 1, width = 1):
    return length * width
```

如果你想调用这个特定的函数，你可以提供必要的测量值 `perimeter(15, 25)`，或者提供一个 `perimeter(7)`，或者直接默认使用 `perimeter()`。每个参数按顺序与传入的值匹配，所以如果你打算这样做，请确保你知道哪些参数会被匹配，即如果你只提供一个参数，它将替换第一个默认值，而其他值将保持默认。

你还可以使用关键字参数，它们根据对应的关键字匹配参数。这样，你就不用担心参数给出的顺序。例如，对于上面的“perimeter()”示例，你可以简单地说“perimeter(width = 12)”。这将使函数对长度使用 1，对宽度使用 12。这比记住参数的顺序更容易；然而，这也意味着你需要输入更多内容。如果你有大量具有此类参数的函数，这会变得繁琐。

此外，一旦你为一个参数指定了关键字，你就不能回去使用位置来指示匹配。例如：

```python
# Listing 13.5: Default arguments and position
def abstract_function(color = "blue", size = 30, range = 40, noodle = True):
    pass

# call the function
abstract_function("red", noodle = False, 45, range = 50)    # not allowed
```

尝试以这种方式调用它会给你一个错误。一旦你开始使用关键字，你就必须对剩余的参数集合继续使用关键字。

关于使用函数编程的内容大概就是这些。它们相当简单，你看到的示例越多，就越能理解它们。Python 很酷，因为你可以将函数和类（带有方法）混合在同一个模块中，而不用担心出错。这样，你就不会局限于一种编程方式；如果一个简短的函数有效，你不必花费时间创建一个完整的类来实现同样的事情。

如果你不想处理面向对象编程，你可以坚持使用函数并玩得开心。不过，我将在后面的章节中开始介绍 OOP，向你展示了解和使用它为什么很好。而且，在 Python 中，它不像其他语言中的 OOP 实现那样可怕。

# 异常

我之前谈过异常，但现在我将深入讨论它们。本质上，异常是修改程序流程的事件，无论是有意为之还是由于错误。它们是特殊事件，可能因错误而发生，例如尝试打开一个不存在的文件，或者当程序到达标记处，例如循环完成。异常按定义来说，并不经常发生；因此，它们是“规则的例外”，并且已为它们创建了一个特殊的类。

异常在 Python 中无处不在。几乎标准 Python 库中的每个模块都使用它们，并且 Python 本身也会在多种不同情况下引发它们。这里只是几个例子：

- 访问不存在的字典键会引发 KeyError 异常。
- 在列表中搜索不存在的值会引发 ValueError 异常。
- 调用不存在的方法会引发 AttributeError 异常。
- 引用不存在的变量会引发 NameError 异常。
- 在未进行强制转换的情况下混合数据类型会引发 TypeError 异常。

异常的一个用途是捕获故障并允许程序继续工作；我们在谈论文件时已经见过这种情况。这是使用异常最常见的方式。在使用 Python 命令行解释器编程时，你不需要担心捕获异常。你的程序通常足够短，即使发生异常也不会受到太大伤害。此外，异常在命令行发生是快速判断代码逻辑是否有问题的简便方法。然而，如果同样的错误发生在你的实际程序中，它将失败并停止工作。

可以在代码中手动创建异常，通过引发异常。它的操作与系统引发的异常完全相同，只是程序员是有意为之的。这可能是出于多种原因。使用异常的好处之一是，就其本质而言，它们不会对代码处理造成任何开销。因为异常本不应经常发生，所以直到它们发生时才会被处理。

异常可以被视为 *if/elif* 语句的特殊形式。实际上，你可以用 *if* 块做与异常相同的事情。然而，如前所述，异常直到发生时才会被处理；而 *if* 块始终会被处理。正确使用异常可以提高程序的性能。错误发生的可能性越低，使用异常对你越有利；使用 *if* 块要求 Python 在继续之前始终测试额外的条件。异常也使代码管理更容易：如果你的编程逻辑与错误处理 *if* 语句混合在一起，阅读、修改和调试你的程序可能会很困难。
