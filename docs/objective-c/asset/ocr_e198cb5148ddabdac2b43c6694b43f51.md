# Adding an observer

```
```objc
[obj addObserver:self
        forKeyPath:@"memberVariable"
           options:(NSKeyValueObservingOptionNew |
                    NSKeyValueObservingOptionOld)
           context:NULL];
```
```

The Observer parameter is usually self, and is the object that receives the notification when the observed value changes. The key path parameter specifies the key path to the attribute for which you want to observe changes. The options parameter specifies a set of flags that tell KVO how you want changes to be sent to you. These values are or'd together using the '|' operator. The possible values that can be passed here are shown in Table 6.2.

| Value | Purpose |
|---|---|
| `NSKeyValueObservingOptionNew` | Send the new value as part of the change information. |
| `NSKeyValueObservingOptionOld` | Send the old value as part of the change information. |
| `NSKeyValueObservingOptionInitial` | Send an initial update as soon as the observer is registered. |
| `NSKeyValueObservingOptionPrior` | Send separate updates before and after the change is made rather than only one update after the value has changed. |

The context parameter is a void * parameter is passed unchanged through the KVO system and back to your object when the change notification occurs. Essentially, as far as KVO is concerned, this parameter is an opaque blob of data that is entirely implementation dependent. Whatever you want to pass in here is passed through unchanged.

# NOTE

Remember when working with void * context parameters that there are special rules that apply for garbage collection and that is up to you to make sure that whatever data that void * is pointing to is still allocated and valid when you later need to access it. In other words, don't pass things that are stored on the stack into this parameter. That will cause a crash.
