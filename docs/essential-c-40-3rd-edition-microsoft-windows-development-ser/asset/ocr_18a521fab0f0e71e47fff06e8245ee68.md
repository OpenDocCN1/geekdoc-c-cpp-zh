In this example, x (a local variable) is accessed within a parallel for loop and so multiple threads will modify it simultaneously, creating a race condition very similar to Listing 19.1. The output is unlikely to yield the value 0 even though x is incremented and decremented the same number of times.

# Synchronization Using Monitor

To synchronize multiple threads so that they cannot execute particular sections of code simultaneously, use a monitor to block the second thread from entering a protected code section before the first thread has exited that section. The monitor functionality is part of a class called System.Threading.Monitor, and the beginning and end of protected code sections are marked with calls to the static methods Monitor.Enter() and Monitor.Exit(), respectively.

Listing 19.3 demonstrates synchronization using the Monitor class explicitly. As this listing shows, it is important that all code between calls to Monitor.Enter() and Monitor.Exit() be surrounded with a try / finally block. Without this, an exception could occur within the protected section and Monitor.Exit() may never be called, thereby blocking other threads indefinitely.
