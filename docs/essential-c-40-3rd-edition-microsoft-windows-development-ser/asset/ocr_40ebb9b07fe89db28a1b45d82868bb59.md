Modifications such as those in Listing 20.17 and Listing 20.18 lead to unexpected behavior. For example, if you reassigned text to "55280ft" following the Console.WriteLine() statement and then redisplayed text, the output would still be Smile because the address of two equal string literals is optimized to one string literal referenced by both variables. In spite of the apparent assignment

```
text = "55280ft";
```

after the unsafe code in Listing 20.17, the internals of the string assignment are an address assignment of the modified "55280ft" location, so text is never set to the intended value.

# Accessing the Member of a Referent Type

Dereferencing a pointer makes it possible for code to access the members of the referent type. However, this is possible without the indirection operator (&). As Listing 20.19 shows, it is possible to directly access a referent type's members using the -> operator (that is, a->b is shorthand for (*a).b).

# LISTING 20.19: Directly Accessing a Referent Type's Members

```
unsafe
{
    Angle angle = new Angle(30, 18, 0);
    Angle* pAngle = &angle;
    System.Console.WriteLine("0° {1}' {2}''",
        pAngle->Hours, pAngle->Minutes, pAngle->Seconds);
}
```

The results of Listing 20.19 appear in Output 20.4.

# OUTPUT 20.4:

```
30° 18' 0
```
