The simplicity of the LU_Solve interface to LAPACK'S LU solver comes at the cost of lesser generality. The member function factorize() assumes the matrix to be square, with its leading dimension exactly equal to the size of its columns. Similarly, solve() assumes that the number of right-hand sides is nrhs=1 to offer a simpler interface.

Some LAPACK routines, including triangular solve, are optimized for multiple right-hand sides in the MKL library. Making repeated calls instead of a single call with a suitable nrhs may degrade program speed considerably.

Narrow classes such as LU_Solve are simple to code but can be quite useful. 

All C++ classes defined in this book from onward are of the same type.

If the Intel compilers and the MKL library are used, one may include the header mkl.h/include, which includes declarations of BLAS/LAPACK functions. One simply needs to pass the -mkl option to the compiler and will look for the header file in the right place. Linking is equally easy. One needs to pass the -mkl-sequential option to link the sequential version of the MKL library.

If the GNU compilers are used, compiling and linking source BLAS and LAPACK libraries can be equally easy. If the header file is put in a standard location as /usr/include, there is no need to do anything when the CBLAS header file cblas.h is included. One may need to explicitly declare the LAPACK functions with C linkage. Likewise, if BLAS functions are used, instead of CBLAS, they may need to be declared explicitly. If the libraries are put in a standard place such as /usr/lib1, it suffices to pass options -lbl and -llapack to link the BLAS and LAPACK libraries. The online MKL library advisor may be consulted to link MKL libraries with gcc/g++.
