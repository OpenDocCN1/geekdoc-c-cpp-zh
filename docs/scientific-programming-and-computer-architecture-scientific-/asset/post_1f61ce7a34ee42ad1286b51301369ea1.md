names that have to do with the workings of the `ifort` compiler. An `ifort` linker would automatically take care of resolving those names, but the `icc` linker does not. So we have to do something explicit to resolve the undefined names created by the `ifort` compiler.

To figure out what to do, we will build an executable with Fortran object files and the following command:

```
ifort -v -o leibniz.exe leibniz.o aitken.o
```

The `-v` option to the `ifort` links the linker to be verbose and point out every step of what it does. The linker produces quite a few. From that output, it appears that the Fortran runtime library is fetched by `-lifcore`. We are now in a position to tackle the linking of `aitken.o` produced from Fortran source with `leibnizFinC.o` produced from a C source. We issue the command:

```bash
icc -o leibnizFinC.exe leibnizFinC.o aitken.o \
  -lifcore
```

Fortunately, the `-lifcore` option resolves all the undefined names and an executable is generated. With the GNU compilers, the `-lgfortran` option ensures that the Fortran runtime libraries are linked. Linking object files generated from Fortran with C++ object files presents a new issue. Suppose we code the C source file `leibnizFinC.c` as follows:

```bash
cp leibnizFinC.c leibnizFinCPP.cpp
icpc -c leibnizFinCPP.cpp
ifort -c aitken.f
icpc -o leibnizFinCPP.exe leibnizFinCPP.o \
  aitken.o -lifcore
```

We can try to build the executable as follows. The linking will fail because of C++ name mangling. In `leibnizFinCPP.cpp`, we have the extern declaration:

```cpp
extern void aitken_(double * seq1, double * seq2,
  int * len);
```

When it generates object code for that source file, the `icpc` compiler assumes that `aitken_` is externally defined and the name of a C++ function. So it mangles the name.

## 2.2. Using BLAS and libraries

The BLAS library is split into three levels. Functions for vector operations such as dot products are included in the first level, for matrix-vector operations in the second level, and for matrix-matrix operations in the third level. The split into three levels is conceptual and reflects the historical order in BLAS functions were specified. The original papers on BLAS are Lawson et al. (1979); Dongarra et al. (1988, 1990). The basic reference for LAPACK is Anderson et al. (1999). The Intel MKL manuals include documentation for BLAS and LAPACK.
