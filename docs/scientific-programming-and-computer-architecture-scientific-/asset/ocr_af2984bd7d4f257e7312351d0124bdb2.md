In sections 3.3.1 and 3.3.2, we give a general overview of the processor pipeline and related matters. This overview is specialized to x86. A distinction must be made between instruction set architectures such as SSE and AVX2 (see table 3.1) and microarchitectures. The microarchitecture specifies the type of pipeline implemented in hardware to consume instructions. Even when the instruction set architecture is the same, microarchitectures can differ. The differences in microarchitecture can be of importance in optimizing the instruction pipeline. Therefore, we pay attention to the microarchitecture in addition to the instruction set.

Sections 3.3.3 and 3.3.4 get into the gritty details, which can be hair-rising but also exciting. The thrill of making nontrivial programs faster by factors of 2 or 10 by understanding how machine instructions map to the microarchitecture is undeniable. However, the thrill is not easily attained. Part of the difficulty is that some details of the microarchitecture need to be discovered through reverse-engineering.

The chief aspect in sections 3.3.3 and 3.3.4 is matrix multiplication. We have already seen that MKL can be more than twice (on SSE2) or more than 10 times (on AVX2) faster than ordinary C/C++ programs (see table 3.3). Our aim is to understand how that speed comes from.

The number of arithmetic operations in $C = C + AB$, if all matrices are square dimension $n$, is $2n^3$ with equally many additions and multiplications. Because double is 8 bytes, the total amount of memory used by the three matrices is $2n^2$ bytes. As $n$ increases, the number of arithmetic operations increases superlinearly, as the 1.5th power, with the size of data in memory. This is better than with the FFT, where the superlinear factor is only logarithmic.

There are two stages in writing a good matrix multiplication. The first stage is to produce a microkernel that multiplies small matrices using instruction pipeline resources optimally. The second stage is to use the microkernel to code multiplication of larger matrices while hiding the cost of memory access. The cost of memory accesses can be almost completely hidden by the number of arithmetic operations grows superlinearly in data size. Thus, coding a good microkernel is decisive. The second stage, like most memory optimizations, can be implemented in C/C++ and is deferred to the next chapter. In this chapter, we focus on the microkernel.
