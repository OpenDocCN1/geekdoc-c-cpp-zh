The function `blocktrans()` assumes the array `a[]` stores $n \times m$ matrix with leading dimension $m$ and saves its transpos in `b`. The transposed $n \times m$ matrix is stored in `b` using leading dimension $n$. The transposed splits the columns of `a[]` equally between themselves on lines 11 and 12. The matrix transposed by each has dimension $m \times nn$, where $nn$ is defined on line 11. The function call on line 14 shifts the first entry of `a[]` by `nfst` cores and the first of `b[]` by `nfst` to isolate the submatrix that works on.

Table 5.4 shows the bandwidth for varying number of threads and varying block sizes $B$. The matrix transposed was square with dimension close to 40,000 as possible subject to the divisibility conditions assumed on lines 3 and 4. On the 12-core SSE2 machine and the 16-core AVX machine, the bandwidth realized in transposing is nearly 80% of the bandwidth for copying, as may be verified by comparing with table 5.4. Although we had complaints about the compiled code for a single processor with a single thread, such complaints might not be justified. Getting to 80% of the best possible in a matrix transpose is quite good.
