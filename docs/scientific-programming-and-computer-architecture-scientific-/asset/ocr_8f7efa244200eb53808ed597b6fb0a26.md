The complete definition of the leibniz() kernel follows.

```
1 __global__ void
2 __launch_bounds__(THInBLK, BLKinMP)
3 leibniz(int n, double *result){
4 int tid = threadIdx.x*blockIdx.x*blockDim.x;
5 double ans=0;
6 int step = blockDim.x*gridDim.x;
7 for(long i=tid; i < n; i+=step)
8 ans = ans + 4.0/(2.0*i+1.0);
9 if(tid%2==1)
10 ans = -ans;
11 result[tid] = ans;
12 }
```

This program introduces four CUDA defined variables on lines 4 and 6:

```
threadIdx.x, blockIdx.x, blockDim.x, gridDim.x
```

These parameters determine the layout of threads (see figure 8.3) and the position of a particular thread within it.

CUDA kernels are never launched one at a time. Every time the kernel is launched, we must specify the number of threads in a block and the number of threads in the grid. The Leibniz series is laid out in a line for simplicity, we assume the thread block and grid are one dimensional.

If we imagine a thread block as a single vertical column (similar to figure 8.3 but with the threads in a warp laid out vertically), blockDim.x, which is the number of threads in a block, is equal to the number of rows. The CUDA-defined variable threadIdx.x allows each thread to access its location along a thread block. It is then the same as the row index.

> strictly speaking, the launch parameters are an upper bound on the number of threads in a block and a lower bound on the number of threads resident on a multiprocessor. The bounds are merely advisory.
