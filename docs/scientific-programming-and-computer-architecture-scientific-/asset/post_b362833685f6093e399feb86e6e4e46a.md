The stored program concept is regarded as an early landmark in the development
of computers. Instead of thinking instructions and data as separate entities, the stored program slightly blurs the distinction between the two, with both programs
and data stored in the same computer memory. In modern computers, including
supercomputers, desktops, laptops, and all kinds of mobile devices, memory invariably refs to DRAM. Although file systems reside on hard disk or some other
media, when a program is running, much of the data that is handled is from DRAM.
DRAM sits external to the processor as shown in section 3.3.2 (see figure 3.6). It is
estimated that 40% of the instructions in a typical computer are loads and stores, and
these instructions address locations in DRAM. Thus, within a program, for most
purposes, memory means DRAM memory. In DRAM memory, every bit is stored on
a single microscopically small capacitor, which is accessed using a single transistor.

DRAM technology is how DRAM hardware and caches are configured. In section 4.1, we
take a look at how word DRAM can be more than 100 times slower than accessing a register. Although
memory available through registers is only the order of kilobytes (KB), a register
can be accessed in a single cycle. In contrast, memory available through DRAM runs
to tens, hundreds, of gigabytes (GB), it can take more than 100 cycles
to access a word from DRAM. A great part of computer design is an attempt to
mitigate this gap in speed and capacity. The aim or hope is to approximate
speed of the registers with the capacity of DRAM. A key idea is to store caches on
the processor itself. The cache is a record of words in DRAM that are most
frequently accessed by the processor. The words that may be accessed directly
within the processor without exchanging signals with DRAM units external
the processor.

On modern computers, caches can be quite large. It is not unusual for a processor package to have more than 10 megabytes (MB) of cache. Both cache and
DRAM capacities are increasing inexorably. When caches are large enough
to comfortably hold a million grid point is firmly in the past. In a lot of
scientific computing, computations do not go out of cache. Caches are implemented
using Static Random Access Memory (SRAM), each bit is stored using
multiple transistors with circuitry to switch the bit on or off rapidly. Caches are intermediate between DRAM and registers in expense, speed, and capacity.

## Chapter 4. Memory

Companies that make DRAM are about as profitable as low-end grocery stores, if they are lucky enough to make a profit. DRAM is as close to a commodity, mass-market technology as there exists in the world of computing. Its low cost has made it ubiquitous across the whole computing spectrum. Engineers have been able to meet market demand for increasing capacity at a low cost, and the potential for disruptive innovations in this area appears limited.

Section 4.1 gives an overview of DRAM and cache memory. The organization of DRAM into memory channels and of caches into multiple levels influences programming technique in several ways. ## 4.1 DRAM and cache memory

DRAM was invented by Intel in 1973. In DRAM, a single capacitor is used to store a single bit, and each capacitor is equipped with an access transistor. DRAM technology has evolved over the years to the point where memory is in mobile devices. For a schematic illustration of where memory fits into the whole, see figure 3.6.

Section 4.1.1 is an overview of DRAM. Arrays of bits are organized into banks, ranks, and channels. At the finest level, DRAM is an array of bits.

In section 4.1.2, we look at caches. Unlike DRAM, caches reside on the processor package. Accessing cached memory is much faster than accessing DRAM. Caching is done automatically by the hardware, and in principle, the programmer does not need to know which caches exist. However, a basic knowledge of cache organization, including items such as cache line size, is essential for writing optimized programs.

Section 4.1.3 is an introduction to virtual memory. The virtual memory set up can have major implications for program speed, especially in the multreaded context, as we will see on several occasions later.

Sections 4.1.4 and 4.1.5 utilize latency of DRAM, cache lines, as well as virtual memory measure latency to DRAM. Latency to DRAM is the number of cycles between issuing an instruction to load a word into a register from DRAM and the completion of that instruction. Finding the latency to DRAM might appear straightforward. It might appear that all we need to do is time a load or store instruction.

In fact, determining latency to memory is not so straightforward. Just as in register pipelines, there is a great deal of parallelism in the memory system.
