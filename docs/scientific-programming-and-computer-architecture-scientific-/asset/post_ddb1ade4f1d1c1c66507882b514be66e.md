
## 5.4. Program memory

Figure 5.3 is a schematic depiction of how vm areas are accessed. The vm areas are stored in a linked list. Each vm area specifies the beginning and end of a valid area of virtual memory.

For every process, the kernel creates a process descriptor, and the process descriptor contains a pointer to an mm_struct that contains a pointer to the list of vm areas that the program may legally access. There is a single vm area that corresponds to the stack of the process. There can be multiple vm areas corresponding to dynamically allocated memory.

If the generated address page faults belongs to one of the vm areas, there is no memory error. The page fault handler will assign a page frame to the page (assuming one is available) that contains the address tables. There is a memory error (segmentation fault) only if the address does not belong to any of the vm areas of the process.

## Functions ff0(), f0(), and f1()

We shall write a few functions to exercise the user mode stack and trigger segmentation faults in a controlled manner.

The function sum_arr() prints the sum of an array of longs. Its definition is listed for completeness.

```c
void sum_arr(long *p, long len){
    long ans=0;
    for(long i=0; i < len; i++)
        ans += p[i];
    printf("sum = %ld\n", ans);
}
```

The heart of our attempts to exercise the user mode stack is the function ff0(). Its definition follows:

```c
void ff0(long *a0, long *list, long n){
    for(int i=0; i < 1000; i++)
        a0[i] = 0;
    for(long i=0; i < n; i++)
        a0[list[i]] = list[i]*list[i];
    printf("in ff0: %d ");
```

```c
sum_arr(a0, 1000);
}
```

The function ff0() is always called by f0(), and f0() defines a0 using long a0[1000]. To begin with, the entries of the array a0[] are set to zero. The pointer list is located dynamically, and the entries of list[] are not stored on the stack.

The usefulness of list[] lies in being able to generate controlled illegal accesses into a0[]. For example, if list[] is the sequence 0,-1,...,1000, locations of lower addresses than a0 are accessed. If list[] is the sequence -500,...,-1000, locations with addresses lower than a0 are accessed by skipping 500 locations. If list[] is the sequence 1000,...,1999, then a thousand locations with addresses higher than a0, and just beyond the legal limit of the array a0[], are accessed.

The chief purpose of f0(), whose definition is given below, is to call ff0(), which it at at the end.

```c
void f0(long *list, long n){
    a0[1000];
    printf("a0 (in f0) = %p\n", a0);
    printf("pid (in f0) = %ld\n", getpid());
    ff0(a0, list, n);
}
```

The array a0[] is allocated on the stack and takes up 8000 bytes. Because of the modifications made to the Linux kernel, getpid() will print the start and end of the vm area of the stack. The array list[0..n-1] specifies entries of a0[] that will be modified by the call to ff0().

The function f1() defined calls ff0(), which we have seen calls ff0(). It defines a 8 MB array on the stack.

```c
void f1(long *list, long n){
    a1[1000*1000];
    for(int i=0; i < 1000*1000; i++)
        a1[i] = 0;
    f0(list, n);
    printf("in f1: %s ");
    sum_arr(a1, 1000*1000);
}
```

### Segmentation fault caused by illegal address

We begin exercising the stack with the following function:

```c
void run1(){
    long *list = new long[5000];
    for(int i=0; i < 5000; i++)
        list[i] = i;
    f0(list, 5000);
    delete[] list;
}
```

The stacking of function calls is shown in figure 5.4. Figure 5.4 shows a0 between f0 and run1, with f0 to its left, because the array a0[] is defined after run1() calls f0() but before f0() calls ff0(). What is run1() doing? It is in effect forcing ff0() to generate accesses to entries numbered 0...499 of the array a0[]. Of course, a0[] defined by f0() has only $10^3$ entries (see figure 5.4). We will understand exactly how the segmentation fault occurs.

Just before f0() calls ff0(), which is the situation depicted in figure 5.4, the vm area corresponding to the stack looks as follows:

```
vm_end = 0x7ff64a500
a0 = vm_end - 13312
vm_start = vm_end - 13264
```

Here the address vm_end is given, a0 and vm_start are given as offsets from vm_end in convenience. The pointer a0 is 13312 bytes below vm_end through array a0[] has only 8000 bytes. The system appears to use up around 5000 bytes near the top of the stack. There is also a lot of padding between a0 and vm_start.

Because a0[] is an array of type long and $999 \times 8 > 13312$, the locations well below vm_end When the address generated contains vm_end, there is a fault. The page fault handler will find that there is no valid area containing the address and trigger a segmentation fault. With a little trouble, we can calculate exactly which iteration of the for-loop in ff0() triggers a segmentation fault. iteration is $i = 13312/8 = 1664$.
