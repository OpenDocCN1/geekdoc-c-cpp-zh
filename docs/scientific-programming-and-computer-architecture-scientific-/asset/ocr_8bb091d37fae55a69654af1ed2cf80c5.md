Infiniband host channel adapters maintain virtual memory tables. A reflection will show that such a facility is essential. Work requests for sending and receiving messages are posted directly to queue pairs that reside on host channel adapters. The memory address for accessing data resides within the work request. Because the work request is created by a user process, the only kind of address that a work request can pass on to the host channel is the virtual address.

If the host channel adapter is to access DRAM directly, it must be able to convert the virtual address into physical addresses. The main pages map virtual addresses to physical addresses, but the host channel adapter cannot and not access the page tables. Indeed, the whole point of Infiniband is to bypass the kernel and concentrate all the layers of networking within the host channel adapter. To enable the host channel adapter to map virtual addresses to physical addresses, Infiniband requires the user process to register memory before posting a work request.

The Verb that registers memory is ibv_reg_mr(). This Verb uses a system call to map a region of virtual memory, supplied via arguments, to physical addresses. The map is saved on the host channel adapter using a protection domain. All commands that transfer data across the network are required to register memory. A memory region is unregistered (deregistered) using the verb ibv_dereg_mr().

Infiniband provides conventional channel semantics as well as RDMA read and write. We will first discuss conventional channel semantics. In conventional semantics, a queue pair at the sender is bound to a queue pair at the receiver to create a channel. A send work request is posted on the send queue of the queue pair at the sender side. A receive work request is posted on the receive queue of the receiver. The send work request must be matched with a receive work request to complete a data transfer across the channel.
