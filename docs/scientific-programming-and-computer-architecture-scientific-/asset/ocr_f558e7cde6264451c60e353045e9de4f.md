# 4.1. DRAM cache memory

Most of the details of the memory controller are entirely hidden from the programmer (as well as the operating system). Fortunately, one does not need knowledge of the hardware at the level of the memory controllers or write optimized programs. Thus, the principal purpose of the information in section 4.1.1 is to provide context. The information is not directly useful in writing actual programs. However, its indirect implications can be of considerable importance.

In section 4.1.2, we look at caches. Unlike DRAM, caches reside on the processor package. Accessing cached memory is much faster than accessing DRAM. Caching is done automatically by the hardware, and in principle, the programmer does not need to know which caches exist. However, a basic knowledge of cache organization, including items such as the cache line size, is essential for writing optimized programs.

When the same data item size in DRAM memory as well as multiple caches, there is the problem of keeping caches coherent. In the next chapter, we will find that cache coherence is the basis of multithreaded programming. Inasmuch as multithreaded programming is a common paradigm from scientific computing to web servers and mobile apps, it is unavoidable to proceed without an ignorance of caches. Multiththreaded programs can be written without heading caches. Doing so would introduce inefficiencies as well as the danger of falling into error without realizing it.

DRAM memory is a shared resource. At any given point in time, dozens of programs on a computer could be using DRAM memory. Each of these programs is written as if the program owns its own memory. The Linux kernel implements virtual memory, with the help of the processor hardware. Thanks to virtual memory, programs can be written assuming a tractable memory model. Section 4.1.3 is an introduction to virtual memory. The virtual memory set up can have major implications for program speed, especially in the multithreaded context, as we will see on several occasions later.

Sections 4.1.4 and 4.1.5 utilize latency of DRAM, cache lines, as well as virtual memory measure latency to DRAM. Latency to DRAM is the number of cycles between issuing an instruction to load a word into a register from DRAM and the completion of that instruction.
