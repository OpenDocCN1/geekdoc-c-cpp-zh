# 5.4.3 Segmentation faults and memory errors

In this section, we take a detailed look at segmentation faults and memory errors. Throughout this section, we assume that the maximum size of the stack is at least 2^23 bytes or 8.39 MB. The examples can be easily modified for smaller stacks. The size of the stack may be determined using the GNU/Linux command ulimit -a.

Most of the segmentation faults and memory errors are caught by the page system. Suppose a user process invokes an instruction as movq $80, (%rsi) to load the 80 into the 64-bit location to which the register %rsi is pointing. The processor first looks up the TLB to map the virtual address stored in %rsi to a physical address. If there is no TLB entry for that, it uses the %cr3 register to access the page tables. If there is no page table entry, there is a page fault and the page fault handler is invoked. Many memory errors are caught by the page fault handler.

The fact that the page fault handler has been invoked does not imply a memory error. The page might have been swapped out to disk. Likely, the memory may have been allocated dynamically using malloc() or statically on the stack using a definition such as x[1000] but uninitialized. A page is mapped to a page frame at the point of first use (demand paging).
