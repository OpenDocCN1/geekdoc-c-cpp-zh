The second discussion is of .d files and the ways dependencies on header files are

Line 10 gives the dependency of lusolve.o on the source lusolve.cpp. It is
typical for each object file to depend primarily on one source file. However, the source
 typically includes several header files that in turn include other header files.
source lusolve.cpp includes the following header files:

```
#include <math>
#include <iostream>
#include <mkl.h>
#include "../utils/utils.hh"
#include "lusolve.hh"
```

These header files include others yet, and the command

```
icpc -O03 -M -mkl -c lusolve.cpp
```

shows all the included files, which are 123 in number. This command uses the icpc
option supported by the icpc compiler to find the MKL header files. The -M option
tells the compiler to give a list of all the included header files. If any of these header
are altered, the object file lusolve.o must be rebuilt, although lusolve.cpp is
unchanged.

Lines 11 and 13 are responsible for tracking the dependence of lusolve.o and
test_lusolve.o, respectively, on header files. To understand how these lines work,
should go back to line 4 of makevars.mk, which included the -MMD and -MP options
in CFLAGS. When icpc is invoked with -MMD -MP, it creates a .d file along with the
object file. The .d file contains dependencies on the header files. For example, the
generated lusolve.d contains the following:

```
lusolve.o: lusolve.cpp ../utils/utils.hh lusolve.hh \
/opt/caen/intel-12.1/mkl/include/mkl.h \
[...] mkl header files omitted ...] \
```
