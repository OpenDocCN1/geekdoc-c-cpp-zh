# 5.3 Introduction to Pthreads

So far our discussion of threads has been limited to OpenMP. OpenMP is a limited programming model. It applies mainly to those situations where the data is static and the access patterns are regular. Pthreads are a more powerful programming model.

The Pthread interface for creating and running threads is supported by the Linux kernel. In Linux, each thread is a separate process. Thread creation is the same as process creation. The distinguishing feature of a group of threads is that they all use the same page tables. The same virtual address generated by different threads in the same group maps to the same physical memory location. Threads, thus offer a seamless way for different processes to share memory.

Pthreads are a powerful programming model. The range of programs that can be written using Pthreads goes well beyond scientific computing. In this section, we introduce Pthreads, beginning with elementary and progressing to more advanced topics.

In 5.3.1, we introduce Pthreads using a simple program to print messages. The two main techniques for achieving mutual exclusion, mutexes and spinlocks, are introduced. Summing the Leibniz series is another example.

Every thread needs a stack to save its state through success of function calls. The user mode stack (explained in the next section) can be used by only one thread (the master thread). In 5.3.1, we explain how a stack is set up for each thread. Thread stacks are normally a few MB and not large. Therefore, it is important not to abuse the stack in threaded programming.

In 5.3.2, we determine that the overhead of thread creation is typically around 10⁶ and can be 10 or 100 times as large on occasion. This number explains the large overhead of the first parallel region an OpenMP program enters. Threads are created the first time an OpenMP program enters a parallel region, and thread creation overhead a major cost. The cost can even go into the milliseconds.

Section 5.3.3 considers several advanced topics. The theme of that section is to implement OpenMP-type parallel regions using Pthreads. Several implementations are explored. If the number of threads in the parallel region remains constant, threads are created for the first parallel region can be reused repeatedly. This explains the low cost of a typical OpenMP parallel region compared with the first parallel region.
