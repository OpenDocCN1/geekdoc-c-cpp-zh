### 2.3.2 Targets, prerequisites, and dependency graphs

Dependencies are fundamental to make. Figure 2.3 shows that each object depends on a single source and a header. Typically, the dependency is on multiple header files, unlike the situation shown in the figure. Each executable in turn depends on multiple object files.

The first purpose of Makefile is to capture the dependency graph between headers, object files, and executables. Each object in the dependency graph is typically a file in figure 2.3. All files that have incoming edges in the dependency graph are targets. The incoming edges indicate that a target file must be built using other files. Those other files are the prerequisites. The targets may reappear as prerequisites, as is the case for all the object files in figure 2.3. Typically, make assumes that a target file may not exist. The target file is considered out of date if its timestamp (accessed using stat on Linux) is older than any of its पड़ेगा. If a target either does not exist or is out of date, make takes upon itself to create a file corresponding to the target. The question arises of how make can create a new file corresponding to a target. To answer this, the second purpose of Makefile is associates each target with a recipe, and the recipe is a shell command invoked by the make utility to build the target if the target is either absent or out of date. The executables linux.exe and logseries.exe are built using the following Makefile:

```makefile
1 linux.exe: -o linux.o aitken.o
2 linux.exe: -o linux.o aitken.o
3 logseries.exe: -o logseries.o aitken.o
4 logseries.exe: -o logseries.o aitken.o
5 linux.o: -fPIC -c linux.c
6 linux.o: -fPIC -c linux.c
7 aitken.o: aitken.c aitken.h
8 aitken.o: aitken.c aitken.h
9 logseries.o: -c logseries.c 
10 logseries.o: -c logseries.c
11 linux.o: -c linux.c
12 linux.o: -c linux.c
13 logseries.o: -c logseries.c 
14 logseries.o: -c logseries.c
```

This listing is a fraction of the Makefile in the linking/aitken directory in the source tree. Other parts of the Makefile are used to build executables from Fortran and C++ sources. This simple Makefile consists of two types of information. Lines 1, 4, 7, 10, and 13 are dependencies. In each dependency, the item before the colon is the target. Thus, the targets in lines 1, 4, 7, 10, and 13 are linux.exe, logseries.exe, aitken.o, linux.o, and logseries.o, respectively. The prerequisites follow the colon. In the rule on line 1, linux.o and aitken.o. Together the five rules specify the dependency graph shown in figure 2.3. For each executable, the dependency graph shows all the object files on which it depends. For each object file, the graph shows the source file and one of the header files on which the object file depends. When an executable is built, the flow of information is from source files to object files and from object files to executables as shown in the figure.

The other type of information in the Makefile are the recipes. Lines 2, 5, 8, and 11 are recipes. Each recipe begins with a tab and corresponds to the target in dependency above it. Beginning each recipe with a major aspect of make syntax. Thus, line 2 corresponds to the target linux.exe. Together the dependency and the recipe form a rule. For example, lines 1 and 2 form a rule.

The make utility makes two passes. In the first pass, it consumes all the dependency rules builds a dependency tree such as the one shown in figure 2.3. In addition, targets are associated with recipes. In our example, there are five targets: linux.exe, logseries.exe, aitken.o, linux.o and logseries.o. These targets appear on lines 1, 4, 7, 10, and 13, respectively. The recipes that are bound to targets in the first pass occur on the following lines.

In the second pass, the make utility brings the target list given at its invocation to date. For each target, it makes sure that its prerequisites are up to date before bringing the target up to date. In general, this leads to a depth first traversal part of the dependency graph.

Once the recipes are up to date, the make utility checks whether the target is older. If each target and prerequisite is assumed to be a file, make finds the date of each file using a GNU/Linux command called stat (a system call of the same name) and takes to be the date of the target or the prerequisite. A target is out of date if any of its prerequisites is newer. If the target is out of date or older, the corresponding recipe is invoked to bring it up to date (make does not check the heart of the target after executing the recipe). This two-pass operation is the heart of how make works.

