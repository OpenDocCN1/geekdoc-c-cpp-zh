# 7.3. Two examples: FFT and matrix multiplication

The final instruction we consider is vpermmf32x4 shown in figure 7.6. The instru-

vpermmf32x4 $78, %zmm0, %zmm0

treats the ZMM0 register as divided into four blocks of 128 bits. In figure 7.6, these
blocks d0-d1, c0-c1, b0-b1, and a0-a1. The number 78 determines the permutation
that is effected. In binary, 78 is 01[00]11|10 or 4^5+1+4^2+0+3+4^9*2. Therefore,
the permutation takes effect, the block in second position moves to the zeroth
block in third position to the first position, and vice versa. Thus, we have
the permutation shown in figure 7.6, which swaps the lower half of the ZMM register
with the upper half. This instruction cannot be executed on the V-pipe.

# A microkernel for matrix multiplication

The assembly code shown in figure 7.7 implements a function with the following
declaration:

```
asm8x1x8(double *A, double *B, double *C);
```

All pointers must be 64-bit aligned. An 8 x 1 column is stored in A[], and a
1 x 8 row is stored in B[]. The function computes their outer product AB adds
the 8 x 8 matrix stored in C[]. To simplify implementation, the storage format
of C is a little odd.

Figure 7.8 shows the diagonals of an 8 x 8 matrix. It is assumed that C
is stored diagonal by diagonal, with the eight entries of diagonal 1 preceding
of diagonal 2 and so on. This is not an restrictive assumption. If each 8 x 8
submatrix of a large 8n x 8n matrix is stored in this skewed manner, passing back
and between the skewed and skewed formats needs to be done only once and
is much cheaper than the cost of multiplying such large matrices.

In figure 7.7, the function name asm8x1x8(C) is mangled according to C++/Linux
ventions (2 and 3). A C++ program (but not a C program) can call the
function as simply asm8x1x8(). The first three arguments, which are pointers to the
matrices A, B, and C, are passed in the registers %rdi, %rsi, and %rdx (index
4, 5, 6), conforming with the GNU/Linux convention.

On lines 7 and 8, the matrices A and B are loaded into the registers ZMM0 and
ZMM1. On line 9, the first diagonal of C is loaded into ZMM2. On line 11,
the first diagonal of C is updated using vfmfadd231pd instruction.
