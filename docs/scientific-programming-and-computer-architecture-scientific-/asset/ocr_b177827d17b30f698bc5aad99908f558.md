To keep things simple, the worker threads do not return anything. They could return a pointer at the point of exit, which is `pthread_exit()` in this case. If some other thread joins to this one, it can pick up the returned pointer when it joins (as in the `leibum()` example).

The manager creates threads, assigns work to worker threads, owns its share of the work, and shuts down the worker threads. It uses the following function to create threads:

```
1 spawn_workers(){
2 pthread_t plist[nthreads-1];
3 static int tidlist[nthreads];
4 for(int i=0; i < threads; i++) {
5 work_count[i] = 0;
6 done_count[i] = 0;
7 tidlist[i] = i;
8 if(i>0){
9 pthread_create(plist+i-1, NULL, worker,
10 (void *)(tidlist+i));
11 pthread_detach(plist[i-1]);
12 }
13 }
14 }
```

The manager uses the array `tidlist[]` defined on line 3 and initialized on line 6. Notice that threads are created only if i>0 (lines 8 through 12) because the manager thread has identifier 0. The initialization on lines 5, 6, and 7 is complete before the thread is created on lines 9 and 10, as it must be.

There are two new elements in this function that merit comment. Why is `tidlist[]` defined on line 3 to be `static`? Variables defined to be `static` persist in memory even after the function returns. The function `spawn_workers()` may exit before the worker threads start executing, in which case the storage allocated to `tidlist[]` may disappear before the threads access it. The `static` specifier ensures that the storage persists in memory.
