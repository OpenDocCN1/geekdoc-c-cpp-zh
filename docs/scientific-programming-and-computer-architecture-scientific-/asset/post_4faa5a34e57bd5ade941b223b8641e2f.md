A declaration of a member function can specify that some of the arguments are references. The declaration `void add(const Vector& v)` (line 19) specifies that the argument named `v` is passed by reference (the `const` qualifier is discussed later). The crucial symbol here is the `&`, which precedes `v` in the declaration. If arguments are passed as references, we do not have to worry about the correct semantics for copying.

Functions may also return a reference as does the member function `operator()` (line 16). This function is defined as

```cpp
double& operator()(long int i){
    assert(i < size);
    return(data[i]);
}
```

in Vector.hh within the scope of the class Vector. Here if `v` is a `Vector` object and we say `v(6)=17`, this member function is called with `v` as the target and with argument `i` equal to 6. Assuming the member function returns `data[i]`, which is the same as `v.data[i]` by reference. Whatever is returned is another name for the 6th entry of the `Vector` object. Thus, saying `v(6)=17` has the effect of setting that entry to 17.

## Operator and function name overloading

We have already seen how the function operator is overloaded. In this example, the assignment operator is overloaded.

```cpp
Vector& operator=(const Vector& v){
    assert(size==v.size);
    memcpy((char*)data, (char*)v.data,
        size*sizeof(double));
    return(*this);
}
```

The assignment operator uses `memcpy()` to copy the data in `v` to its target.¹¹⁵ If we say `w=v`, with both `v` and `w` being `Vector` objects, the member function `operator=()` is invoked with w as the target and v as its argument. As before, size and data refer to the corresponding items of the target.

> ¹⁵Strict speaking, the overloaded = should check that `data` and `v.data` do not overlap.

## 1.3. C++ review

A bit of syntax here is the keyword `this`. Within a member function, `this` is a pointer to the target. Therefore, `*this` is the target. The overloaded assignment operator returns a reference to the target.

If u, v, and w are Vector objects, and we say u=v=w, the compiler interprets that u=(v=w). In C/C++, the assignment operator is right associative. The result of v=w is a reference to v, which is the argument in the next call to the overloaded assignment operator that assigns to u.

C++ also allows function name overloading. For instance, we can define another function as

```cpp
void add(double *vx, const double *w,
    const int len){...}
```

which adds the array w to the array v. We can define another function

```cpp
void add(const double *u, const double *w, double *v,
    const int len){...}
```

which leaves the sum of u and v in v. In C, the two definitions would conflict they are both trying to bind a definition to the same name add. However, in C++, the compiler allows both definitions because they can be disambiguated by the number and types of the arguments. The compiler internally generates mangled names to keep the definitions separate in the object file, so as not to confuse the linker.

## Function call inlining

The member functions of the class Vector are defined in the header file Vector.hh within the scope of the class definition. If we wanted to define the overloaded function operator elsewhere, we can give its definition as

```cpp
double& Vector::operator()(long int i) {
    assert(i < size);
    return(data[i]);
}
```

In fact, it is better to define the overloaded function operator within the scope of the class as we did. Every source that uses the Vector class will include the header Vector.hh. Thus, every compilation unit will see the complete definition of the function operator. If we see v(i) = 7.0, with v being a Vector object, the compiler does not actually generate a function call for v(i). Instead it scans the definition of the overloaded function operator and splices in the body of the function at the point of call. The overhead of making a function call is eliminated. This is called function call inlining.

The function call overhead in modern processors is quite small and is typically less than 10 cycles.¹¹⁶ Much of the time it is nothing to worry about. However, if a member function compiles to only a few instructions and is called frequently, one must ensure that the member function is inlined.

In C++, one can explicitly ask the compiler to inline functions that are not member functions. For instance, a function with the declaration `void add(Vector u, Vector v)` is instead declared `inline add(Vector u, Vector v)` and defined within the header file, the compiler will try and almost certainly succeed in inlining that function. The compiler may refuse or fail to inline functions that are large and complicated without warning.

If several source files are compiled and linked simultaneously with interprocedural optimization turned on (-ipo in option -icpc), the compiler will again try to inline certain functions. Normally, we will avoid interprocedural optimization, preferring to build object files for each source file or compilation unit. Suppose we need to replace each entry of an array by the cumulative sum of the preceding entries. We can write the code in C using pointers and pointer arithmetic or we use a class such as the Vector class. A well-written C-style loop will lead to faster and more compact assembly code for reasons explained in a later chapter (see section 3.2.6). Inlining occasionally leads to worse code as we illustrate later in this chapter.

## Constructors and destructors

Constructors and destructors are central to the class mechanism in C++. The three constructors of the Vector class are defined below.

## 1.3. C++ review

```cpp
//empty constructor
Vector(){
    size = 0;
    data = NULL;
    owner = 0;
}
```

```cpp
//only constructor to allocate space for data
Vector(long int n){
    size = n;
    data = (double *)malloc(sizeof(double)*n);
    owner = 1;
}
```

```cpp
//*this becomes shadow of Vector v
//(copy constructor)
Vector(const Vector& v){
    size = v.size;
    data = v.data;
    owner = 0;
}
```

The empty constructor and the copy constructor do not allocate space. The constructor in the middle allocates space using malloc()`. These member functions are understood to be constructors because they have the same name as the class. Constructors are not allowed to return anything.

Constructors are called implicitly at the point of definition of class. It is essential to understand when constructors are called. Suppose we define a vector object as

```cpp
Vector v;
```

the empty constructor is called to initialize the object v. If we define an array of vectors

```cpp
Vector v[100];
```

the empty constructor is called for each object in the array. It is illegal to define an array of objects if the class is not equipped with an empty constructor.

If we define a vector object as

```cpp
Vector v(27)
```

the constructor in the middle is called. The compiler notes that the object v is being built with the single argument 27, which is a constant of type int. The constructor that calls malloc() takes long int as an argument. In C/C++, an int is automatically promoted to a long int if necessary.

The constructor uses malloc() to claim space for this Vector object. If we make the call

```cpp
malloc(1000*1000)
```

the function returns a pointer to 10^6 bytes. The pointer is of type void *. In the usage

```cpp
data = (double*)malloc(sizeof(double)*n)
```

void * is cast to double*. Type casts are used to convert values of one type to another type. For example, we may say (int)1.4142 to convert the double value 1.4142 to int (it will be truncated). The cast is needed here because data is of double * while malloc() returns void *.

What happens during malloc()? The short answer, is will be elaborated later, that the function first goes to the C library. The C library may turn call the operating system if it is not able to come up with the memory by itself. The operating system typically allocates an area in virtual memory to the calling process. No region in physical memory is set aside. Physical memory is set aside when the process first tries to access the memory it has claimed for itself. There is a page fault during first access, and the page fault handles aside physical memory.
