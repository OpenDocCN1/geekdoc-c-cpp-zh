# 2.3. Building programs using GNU Make

One advantage of shared libraries is that the system needs to load only one copy of the library if many processes are linked against the same shared library. Another advantage is that programs benefit automatically from updates and bug-fixes to shared libraries (at least in theory). The memory map and page tables of a process change when a shared library is loaded. Shared libraries must be supported by the operating system kernel.

The list of shared libraries available on a system may be obtained using the `ldconfig -v` command. The list can be long, and the only purpose it serves may be overwhelm.

The GNU/Linux `ld` command can be used to find which shared libraries are linked with the executable. There can be several versions of MKL or FFTW on a system, making it uncertain which version of a library has been linked. If we say `ld test_lib.exe` at the command prompt in GNU/Linux, we get the following sort of information:

```
libmkl_sequential.so => /opt/intel/...mkl/lib/...
libmath.so => not found
```

Of the 10 libraries, we have shown only two. For the MKL library, the command outputs the path to the shared that will be linked dynamically at runtime. For our libmath.so, it says “not found” because the shell variable `LD_LIBRARY_PATH` has not been set to include the current directory. If this program is run, there will be an error at runtime when the `xmath` library cannot be found. With that option, we may find out how the system looks for libraries . For example, if we say `ld -verbose -lfftw3`, we get a sense of what happens if the `-lfftw3` option is used to link fft3.

```

...

...
attempt to open /usr/lib/x86_64-linux-gnu/libfftw3.so
```
