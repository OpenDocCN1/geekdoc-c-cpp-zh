Host computers can inject packets into the network at great speed. If an application issues a send() system call, the data to be sent must fall through through the TCP layer, the IP layer, the ARP layer, and the device driver before it reaches the network. The Linux TCP/IP stack is highly optimized. One major optimization in Linux as many other implementations is to avoid repeated copies. In fact, the data is copied just once from the application's user space to kernel buffers. The kernel buffers for TCP/IP packets are of the type sk_buff. This struct is organized in such a way that the TCP header, IP header, and Ethernet header can be tasked without copying the data.

The realized bandwidth is determined to a great extent by TCP's congestion control algorithm. TCP implements both flow control and congestion control. In flow control, the sender keeps track of the available room in the receiver's buffer. The sender slows down if there is too little room in the receiver's buffer. The sender continually adjusts its size to avoid overwhelming (or starving) the receiver with packets.

The basic flow of packets in TCP is from the sender to the receiver. The receiver may have to reorder buffers, and some packets may be dropped by the routers. Just as in Infinib, the receiver sends an ACK when it receives a packet. The sender has to retransmit packets if they have not been acknowledged for a long while. The ACK packets the sender receives has a field in which the receiver advertises the window available in its buffers. The ACK packets may carry data if the receiver executed a send() system call after receiving. The receiver's advertised window is the basis for flow control.

For data transfer between UM and TACC, congestion control has a much greater bearing on realized bandwidth than flow control. In this setting, both endpoints inject and remove packets quickly from the network, but the Internet would strain and buckle if all the hosts inject packets at a rapid rate. The sender tries to ensure that the number of packets in flight, is the number sent but not yet acknowledged, is within the congestion window.
