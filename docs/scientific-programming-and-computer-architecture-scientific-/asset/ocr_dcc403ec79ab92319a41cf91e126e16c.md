//usr/lib/x86_64-linux-gnu/libfftw3.so
found libm.so.6 at //lib/x86_64-linux-gnu/libm.so.6

We see the order in which the loader goes through a number of directories looking for FFTW3. In every directory, it first looks for the shared and the static version of FFTW3. When FFTW3 is found, it begins to look for shared libraries needed by FFTW3, and so on.

The loader looks for shared libraries in the following order.¹14 First, it looks at directories that may be explicitly embedded in the executable file using options as -rpath. Second, it looks at directories in LD_LIBRARY_PATH. Third, it looks in the cache /etc/ld.cache file. The entries of this library cache file may be manipulated by the ldconfig command. Fourth, it looks at /usr/lib.

Understanding the manner in which programs use shared libraries are loaded and set up requires knowledge of the paging system, reviewed later in section 4.4, and the concept of system calls, which are functions defined by the operating system kernel which may be invoked by user programs (see section 5.4.1). To complete our discussion of shared libraries, we anticipate later discussion of these topics and explain how shared libraries are set up.

There are three parts to understand how shared libraries work at the level of machine instructions. The first of these is the manner in which shared libraries are loaded into memory. Suppose a program abc.exe, which calls functions in libraries that may call functions in shared libraries, is invoked from the command line or in some other way. The Linux system call execve() is invoked with the abc.exe as one of its arguments. Linux creates a process descriptor that holds administrative information about the process or program for its use. It maps the contents of abc.exe to the virtual address space of the process with the intention of passing control to the process. Before passing it notices that the executable relies on shared libraries. Consequently, it loads the dynamic linker ld-linux.so or ld.so into the same virtual address space and passes control to the dynamic linker. The dynamic linker looks for the library in the file system in the order given above.
