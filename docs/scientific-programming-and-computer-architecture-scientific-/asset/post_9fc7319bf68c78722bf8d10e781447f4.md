
## 8.3. Two examples

This kernel is assumed to be launched with two-dimensional thread blocks in a two-dimensional grid. The size of the thread block is assumed to be SQRTT \times SQRTT. On the K20, we take SQRTT to $32 = \sqrt{1024}$ because 1024 is the maximum number of threads in a block.

The matrix dimension N is assumed to be divisible by SQRTT. The grid is assumed to be $N/SQRTT \times N/SQRTT$. The total number of threads is equal to $N^2$. A natural map from indices to entry of the $N \times N$ matrix C. The mmult_gmem() calculates the indices of $(i, j)$ of the thread map and then updates the corresponding entry of the matrix C[] given to a different thread for updating.

The syntax for this kernel using two-dimensional thread blocks and grids is shown in the listing below. Multiple dimensions are specified using dim3 objects.

```cpp
double mmult(*A, double *B, double *C, int N){
    assert(SQRTT*SQRTT==THINBLK);
    assert(N%SQRTT==0);

    dim3 grid(N/SQRTT, N/SQRTT);
    dim3 tblk(SQRTT, SQRTT);

    dhmem<double> dhA(N*N);
    dhmem<double> dhB(N*N);
    dhmem<double> dhC(N*N);
    for(int i=0; i<N*N; i++){
        dhA.host()[i] = A[i];
        dhB.host()[i] = B[i];
        dhC.host()[i] = C[i];
    }

    dhA.hostTodevice();
    dhB.hostTodevice();
    dhC.hostTodevice();

    mmult_gmem<<<grid, tblk>>>(dhA.device(),
        dhB.device(), dhC.device(), N);

    dhC.devicehost();
    for(int i=0; i < N*N; i++)
        C[i] = dhC.host()[i];
}
```

Copying data into out of the device using the sharedmem class implies extra copying. That is an overhead we accept in the interest of a more modular program.

## Shared memory

In the Kepler microstructure, each multiprocessor owns some on-chip memory that is split between L1 cache and shared memory (see figure 8.2). On the K20, default, there is 8 KB of shared memory for each of its 13 multipiprocessors. Accesses of shared memory are considerably faster than global memory accesses.

The following program assumes SQRTT x SQRTT thread blocks and N/SQRTT x grid as before. However, it uses shared memory and blocking.

To help decipher this program, we turn to figure 8.4. Each submatrix CC as the submatrices of the thread block is SQRTT x SQRTT matching the dimensions of the thread block. Because the grid is of dimension N/SQRTT x N/SQRTT, we may assume that each submatrix CC belongs to a certain thread block. The entries of CC are further split between the threads in the thread block. The kernel mmut_smem() thinks of updating the CC in block terms:

```
CC = A1 + B1 + A2 + B2 + ... + An x Bn
```

where n = N/SQRTT.
On line 9, the program claims shared memory using the __shared__ qualifier. The memory is split between a subblock of A (line 10), a subblock of B (line 11), and the subblock CC (line 12). Each thread also computes the indices (i, j) of the entry of C it will update (lines 13 and 14). The outer-loop (line 16) steps through blocks. The index k is incremented in steps of SQRTT. So to get the jth block, we must take k=j*SQRTT. On line 18, subblock Aj is loaded into shared memory, with each thread loading exactly one. Similarly, on line 19, subblock Bj is loaded into shared memory. The mmut_smem() is an example of a program where the thread hierarchy affects the structure of the entire loop, making the code difficult to comprehend.

The `CuMult` class is our interface to the matrix multiplication routine.

```cpp
#include <cublas_v2.h>

class CuMult{
private:
    int N;
    dhmem<double> memA, memB, memC;
    cublasHandle_t h;
public:
    CuMult(int Ni);
    ~CuMult();
    /*
     * C = C + A*B, A[], B[], C are NxN matrices
     * returns time in milliseconds
     */
    double mult(double *A, double *B, double *C);
}
```

The handle h is one of the private data members. It is used to access the cuBLAS facilities. The class constructor is defined as follows:

```cpp
CuMult::CuMult(int Ni)
    :N(Ni), memA(N*N), memB(N*N), memC(N*N) {
    cublasStatus_t code;
    code = cublasCreate(&h);
    assert(code == CUBLAS_STATUS_SUCCESS);
}
```

The main task of the constructor is to initialize the handle by calling cublasCreate(). It also initializes memA/B/C used for sending and retrieving data from the device. The destructor releases the handle.

```cpp
CuMult::CuMult() {
    cublasStatus_t code;
    cublasDestroy(h);
    assert(code == CUBLAS_STATUS_SUCCESS);
}
```

The definition of the member function mult() follows.

```cpp
void CuMult::mult(double *A, double *B, double *C) {
    cublasStatus_t code;
    for(int i=0; i < N*N; i++){
        memA.host()[i] = A[i];
        memB.host()[i] = B[i];
        memC.host()[i] = C[i];
    }

    memA.host2device();
    memB.host2device();
    memC.host2device();

    double alpha = 1.0;
    double beta = 1.0;

    hstTimer hclk;
    hclk.tic();
    code = cublasDgemm(h,
        CUBLAS_OP_N, CUBLAS_OP_N,
        N, N, N,
        &alpha, memA.device(), N,
        memB.device(), N,
        &beta, memC.device(), N);
    double tms = hclk.toc();
    assert(code == CUBLAS_STATUS_SUCCESS);

    memC.device2host();
    for(int i=0; i < N*N; i++)
        C[i] = memC.host()[i];

    return tms;
}
```
