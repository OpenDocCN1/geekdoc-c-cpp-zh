From DRAM memory, computer programs have a tendency to access the same word or nearby words repeatedly. Thus, it makes sense to keep the word in a fast cache after it is first accessed. Later accesses can be serviced quickly from the cache without contacting the slow DRAM devices.

All transfers between DRAM memory and the processors are in cache line multiples. A cache line is 64 bytes or 512 bits on most x86 computers. Thus, a cache line is big enough to hold 8 doubles or 16 ints. The cache lines are aligned in memory to begin at addresses whose last 6 bits (that 2⁶ = 64) are zero.

## Cache parameters

Figure 4.6 shows cache organization on typical x86 processors. Each processor has its own L1 and L2 caches. The L1 is smaller than L2 but faster to access. All processor core on the same package L3 cache. The L3 cache is much bigger in size than the L2 cache.

Having multiple levels of cache implies that the penalty of a miss at a certain level is not too high if the cache line is found at the next level. Thus, the cost of a cache miss worsens gradually.

The size of the cache in bytes is equal to the product of the number of sets, associativity, and 64, which is the number of bytes in a single cache line. Cache size and cache associativity program program speed, with greater being better.

To understand what sets and associativity mean in the context of cache organization, we turn to figure 4.7. Suppose the processor wants to look for a byte whose physical address is $\alpha$ in L1 data cache. The address of its cache line will be:

$$\alpha - \alpha \pmod{64}$$

because a cache line begins every 64th byte. Cache lines are mapped to sets cyclically. The cache line containing the byte whose address is $\alpha$ maps to set number

$$\frac{\alpha - \alpha \pmod{64}}{64} \quad mod 128$$

if there are 128 sets in the L1 data cache. The cache line could be in any of the four slots in that set. The processor will check the four slots simultaneously for a match. If there is a match, the processor will extract the byte from the cache line in the matching slot.

If many addresses map to the same set, there will be cache conflicts even if other sets of the cache are not heavily used. If the frequently used addresses in a program segment map to only a few sets, the effectiveness of the cache is reduced, and cache conflicts become more likely. A fully associative cache, which has a single set and in which a cache line can be stored in any of the slots, is the best for reducing cache conflicts. However, such an ideal cache is too expensive to implement.

The effect of cache conflicts is not easy to detect in modern computers as used to be the case. Multiple levels of caching, instruction-level parallelism, the large size of the caches, and the sheer complexity of the memory system can make the effect of cache conflicts on strided accesses difficult to detect.

## Cache protocols

How do the cache controllers decide which cache lines to keep in cache and which ones to evict from cache? Suppose certain cache line is accessed. If the cache line is already in cache, the processor will extract the byte from the cache line in the matching slot. If the cache line is not in cache, it must be fetched from DRAM and placed in the cache. This is a cache miss. If the cache line is in the cache, it is a cache hit.

The replacement policy determines which cache line is evicted when a new line must be loaded. A common policy is least recently used (LRU), which evicts the line that has not been accessed for the longest time. This is effective because lines that were used recently are likely to be used again in the future.

The cache protocol ensures consistency across multiple caches. When one processor modifies a cache line in its cache, the other caches must be updated or invalidated. There are several protocols used to handle this, such as write-through and write-back. In a write-through cache, every write is performed to both the cache and the memory. In a write-back cache, the write is only performed to the cache, and the memory is updated only when the cache line is evicted.

The coherence protocol is essential in multi-core systems to ensure that all processors see a consistent view of memory. Without coherence, different processors might read different values for the same memory location, leading to program errors. Common coherence protocols include MESI (Modified, Exclusive, Shared, Invalid). This protocol tracks the state of each cache line and ensures synchronization.

## Virtual memory in action

How does the hardware look up an actual word in memory using a virtual address? The answer is complicated. The first step on x86 is to form a 64-bit address by adding a segment register. This is trivial and we will ignore it.

The next and far more important step is to map virtual addresses to physical addresses. Once a physical address is formed, it is used to look up DRAM or the caches.

To map addresses from virtual to physical memory, virtual memory is partitioned into pages. A page is 4096 bytes (the command getconf PAGESIZE may be used to find out the page size). Thus, in a virtual address of 48 bits, the first 36 bits constitute a page address, and the following 12 bits are the address within that page. Correspondingly, DRAM memory is broken up into page frames, each of which is the same size as a page. Page tables map page addresses to page frame addresses.

The manner in which page tables are set up does not concern us. They are set by the operating system kernel and left in a place where the processor hardware can look them up. The translation lookup-buffer (TLB) is a cache of the page tables. When an address such as (%rax, %rsi, 2) is formed, the next step is to look up the TLB to convert it to a physical address. Each entry in the TLB maps exactly one page to a page frame. If there is a TLB miss, the processor looks up the page tables.
