The broadcast operation uses the link in only one direction, and we find that it reaches more than 0.75 bytes/cycle in some instances. The performance does not degrade as the number of host computers increases. On the contrary, it gets better.

Infiniband, like many other network architectures, supports broadcast in hardware. The MPI library $MPI\_Broadcast()$ uses the hardware-level architectural facility for broadcasting. The advantages of supporting broadcasting in hardware are obvious. In the fat-tree, a single Infinand switch may be connected to many other switches. The hardware can move the broadcast data to a switch just once and route it to all the host computers that may be reached from that switch. The send/receive implementation is forced to send data through the switch multiple times, for each host computer that may be reached from that switch. The Internet supports a broadcast protocol for radio broadcasts, sporting events, and the like.

The MPI standard states that all collective function calls are blocking. Therefore, a broadcast initiated at the root must wait until every process has a matching call to $MPI\_Broadcast()$. The overhead of blocking will be of the order of several thousand cycles and is insignificant when the data being transferred is a megabyte or more, as shown by table 6.9.
