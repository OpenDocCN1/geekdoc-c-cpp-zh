```cpp
for(int j=0; j < ncols; j+=B){
    int iib = (nrows-i < B)?nrows-i:B;
    int jjb = (ncols-j < B)?ncols-j:B;
    for(int ii=0; ii < iib; ii++)
        for(int jj=0; jj < jjb; jj++)
            out[j+jj+(i+ii)*ncols]
                = in[i+ii+(j+jj)*lda];
}
```

This for-loop implements matrix transpose block by block. In a large problem, most blocks are $B \times B$, but the block sizes are adjusted using iib and jjb at the edges of matrix. The outermost loop is parallelized using OpenMP. Matrix transpose with blocking was discussed in chapters 4 and 5. The choice of $B = 50$ for the block size here influenced by that earlier discussion.

The definition of copywlda() is altered as follows:

```cpp
void copywlda(double *in, int nrows, int ncols,
               double *out, int lda){
#pragma omp parallel for
    num_threads(THREADS)
    shared(in, nrows, ncols, out, lda)
    for(long j=0; j < ncols; j++)
        for(long i=0; i < nrows; i++)
            out[i+j*lda] = in[i+j*nrows];
```

The modification is simpler. The outer-loop has been qualified using the OpenMP model-construct.

## Overlapping network and processor activity

Table 6.7 shows the improvement in bandwidth when network activity is overlapped with processor activity, in addition to using fast copies as discussed. The realized network bandwidth is 75% of the peak of 5 GB/s with 100 nodes. With 10 nodes the realized bandwidth is more than 90% of the peak.

The new class FastTrans shows how network activity may be overlapped with processor activity.

```cpp
class FastTrans{
  private:
    int p; // rank
    int P; //number of processes
    long M;
    long N;
    long *fstM;
    long *fstN;
    double *sendbuf, *recvbuf;
    MPI_Request *sreqlist, *reqlist;
    int *sender;
    int *rcvd_list;

public:
    FastTrans(int rank, int nprocs, long Mi, long Ni);
    FastTrans();
    long fstM(int rank){return fstM[rank]};
    long fstN(int rank){return fstN[rank]};
    void copyToSendbuf(int q, double *localMN);
    void postsend(int q);
    void postrecv(int q);
    void wait(); /* wait on all sends */
    void copyFromrecvbuf(int q, double *localMN);
    void transpose(double *localMN, double *localMN);
};
```

The class FastTrans is similar to Transpose in many ways, although there are some changes. In the private section, two new items appear: sender and rcvd_list. These are used by member function transpose() to order sends and keep track of receives. In the public section, the member functions postsend() and postrecv() take the argument q. The send and receive requests no longer initiated simultaneously. The member function transpose() orders sends and receives to overlap network activity with processor activity. The array sender[] is initialized by the class constructor.

```cpp
FastTrans::FastTrans(int rank, int nprocs, long Mi, long Ni)
    :p(rank), P(nprocs), M(Mi), N(Ni) {
    fstM = new long[P+1];
    fstN = new long[P+1];
    BlockDivide(M, P, fstM);
    BlockDivide(N, P, fstN);
    long ncols = fstN[p+1]-fstN[p];
    long nrows = fstM[p+1]-fstM[p];
    assert(ncols > 0);
    sendbuf = new double[ncols*M];
    assert(nrows > 0);
    recvbuf = new double[nrows*N];
    sreqlist = new MPI_Request[P];
    reqlist = new MPI_Request[P];
    sender = new int[P];
    rcvd_list = new int[P];
    sender[0] = 0;
    for(int i=0; i < P/2 + P%2; i++) {
        sender[2*(i-1)+1] = i;
        sender[2*(i-1)+2] = P-i;
    }
    if(P%2 == 0) {
        sender[P-1] = P/2;
    }
    for(int i=0; i < P; i++) {
        sender[i] = (sender[i]+p)%P;
    }
}
```

The initialization of the row and column partition indices fstM[] and fstN[] are in the class Transpose. The send and receive buffers have exactly the same size as before. However, the sending and receiving will be done in quite a different manner. On lines 23 through 29, the array sender[] is initialized to
0, 1, P-1, 2, P-2, 3, P-3, ...

This send order is valid assuming the local rank is p = 0. To obtain the send order for the current process of rank p, the for-loop on lines 31 and 32 modifies entries of sendorder[] by adding the rank p modulo P, where P is the total number of MPI processes.

The order sends assumes that a process of rank p is next to those of rank (p-1) mod P and (p+1) mod P. In fact, the assignment of ranks to processor nodes can be almost random. No such assumption can be true. Even so, there appears to be some benefit in the reciprocity found between the send orders of processes of two different ranks.

The definitions of copyTosendbuf() and copyFromrecvbuf() are the same as before, except they take an argument index q. They copy only that part of the matrix that is being sent to or received from the process of rank q.

```cpp
void FastTrans::copyTosendbuf(int q, double *localMN) {
    long ncols = fstn[p+1] - fstn[p];
    long rows = fstm[q+1] - fstm[q];
    long sbufindex = ncols * fstm[q];
    long localindex = fstm[q];
    long lda = M;
    transposewlda(localMN+localindex, lda,
        rows, ncols,
        sendbuf+sbufindex);
}
```

```cpp
void FastTrans::copyFromrecvbuf(int q, double *localNM){
  long ncols = fstm[p+1]-fstm[p];
  long nrows = fstN[q+1]-fstN[q];
  long rbufindindex = ncols*fstN[q];
  long localindex = fstN[q];
  long lda = N;
  copywlda(recvbuf+rbufindex, nrows, ncols,
localNM+localindex, lda);
}
```

Unlike the corresponding member functions of the class Transpose, these member functions do not use a for-loop to communicate with every other MPI process. As a result, they are slightly more transparent. The functions transpose() and copywlda() are exactly the same as the versions earlier and are omitted.
The member function postend() and postrec() communicate with a single other process of rank q.

```cpp
void FastTrans::postend(int q){
  long ncols = fstm[p+1]-fstN[p];
  long nrows = fstm[q+1]-fstm[q];
  long sbufindex = ncols*fstm[q];
  int count = ncols*nrows; //MPI can't handle long
  int tag = 0;
  MPI_Isend(sendbuf+sbufindex, count, MPI_DOUBLE,
  q, tag, MPI_COMM_WORLD, sreqlist+q);
}
```

```cpp
void FastTrans::postrec(int q){
  long ncols = fstm[p+1]-fstm[p];
  long nrows = fstN[q+1]-fstN[q];
  long rbufindindex = ncols*fstN[q];
  int count = nrows*ncols; //MPI can't handle long
  int tag = 0;
  MPI_Irec(recvbuf+rbufindex, count, MPI_DOUBLE,
  q, tag, MPI_COMM_WORLD, rreqlist+q);
}
```
