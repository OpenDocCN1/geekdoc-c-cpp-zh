# 3.1.2 64-bit x86 assembly programming

Each processor fetches instructions from memory and executes them. These instructions are stored in memory as a sequence of bytes. In assembly language, the bytes that encode machine instructions are replaced by mnemonics. For example, an instruction to move a quad word, which is eight bytes in size, from register r8 to rex is coded as the following hex sequence 4C 89 C0. The first byte 4C is the-called REX byte, the second byte 89 is CO. The opcode, and the third byte CO encodes the fact that the source register is r8 and the destination is rex.7 In the 64-bit x86 architecture, opcodes can be one, two, or three bytes. A single instruction can be as many as 17 bytes.

Unlike processors, we cannot just look at bytes and make sense of them, which is the assembly languages provide mnemonics. The GNU assembler, which is called GAS, the mnemonic for the instruction to move a quad word from r8 to rex is movq %r8,%rax. To move a double word, which is four bytes stored in the lower halves of the 64-bit registers, the mnemonic is movl %r8,%ax. These mnemonics vary with the assembler. In the MASM assembler, the mnemonic for moving a quad word from r8 to rex would be MOVQ R8—notice that the registers are in reverse order.

There is no standardization in the word of x86 assembly languages. The documentation for the instruction, which includes the mnemonics for various instructions, is published by AMD and Intel. However, mnemonics can change in a predictable fashion depending on the assembly language. For instance, a register referred to as R8 in the AMD/Intel documentation becomes %r8 in GAS. One point is to keep in mind, in the AMD/Intel manuals, the destination precedes the source. In GAS, the destination follows the source. We will always use the GAS convention. On Linux computers, even the compilers use the GNU assembler.
