The cyclic pattern is also a simple one, but it allows us to examine how well the network bandwidth holds up when there are many communicating agents on the network. We will find that it holds up quite well.

The Cycle class follows:

```cpp
class Cycle{
private:
    double *sendbufl, *sendbufr;
    double *recvbufl, *recvbufr;
    int bufsize;
    MPI_Request sreq1, sreq2;
    MPI_Request rreq1, rreq2;
    Timestamp clk;
public:
    Cycle(int rank, int procs, int bufsize);
    -Cycle();
    void post();
    double wait();
    double *getsendbufl(){return sendbufl;}
    double *getsendbufr(){return sendbufr;}
    double *getrecvbufl(){return recvbufl;}
    double *getrecvbufr(){return recvbufr};
};
```

This class has an interface similar to the Exch class. The difference is that it has send and receive buffers to communicate with the process to its left as well as the process to its right.

To time cyclic exchange, the send and receive requests are posted using post() on each MPI process. The $post()$ is immediately followed by $wait()$, although in general program may perform some computations before it waits for the posted requests to be complete.

The bandwidth is measured by each host as the number of bytes transferred into or of it in a single cycle. The reported numbers are medians of a large number of trials and correspond to the process of rank 0. For this simple pattern of communication, the bandwidth realized are often in the advertised QDR Infiniband port bandwidth of 5 GB/s, which corresponds to 1.5 bytes/cycle.

### 6.3.2 Jacobi iteration

The Jacobi iteration is a technique for solving linear systems that arise when partial differential equations are discretized. Jacobi is an iterative method. Successive iterations improve the guess with each iteration, reducing the error by a factor greater than 1. The iterations are stopped when the error is designed to be low enough.

Poisson's equation $u_{xx} + u_{yy} = f$ is amenable to the Jacobi iteration once the equation is discretized using finite differences or finite elements. The Jacobi iteration by itself is not a particularly effective method for solving such differential equations. However, the Jacobi iteration can be supplemented by other ideas, such as multigrid, and turned into a powerful method.

The data in the Jacobi iteration is laid out as a matrix $a_{ij}$, $0 \le i < m$ and $0 \le j < n$. The matrix is split between MPI processes by column. Each MPI process gets a contiguous set of columns. The iteration is to be:

```
$b_{ij} \leftarrow \frac{a_{i-1,j} + a_{i+1,j} + a_{i,j-1} + a_{i,j+1}}{4}$$
```

In this form, the iteration does not directly correspond to any partial differential equation. There is no right-hand side vector corresponding to the source term in the partial differential equation. We have simplified the Jacobi iteration to focus better on certain aspects of its implementation. Nevertheless, we have to specify boundary conditions on the data $a_{ij}$ at the boundary points $i = 0$ or $i = m - 1$ or $j = 0$ or $j = n-1$. One version of the Jacobi iteration generates indices that fall outside the domain for boundary points $a_{ij}$. For example, $a_{i,j-1}$ has a negative row index if $i=0$. We interpret all indices modulo $m$ and all column indices modulo $n$. Thus, row indices of $-1$ and $m$ are interpreted as $m-1$ and $0$, respectively, and column indices of $-1$ and $n$ are interpreted as $n-1$ and $0$, respectively. In differential equations jargon, we are assuming periodic boundary conditions here.

This section illustrates how OpenMP constructs may be mixed with MPI message passing. There will be one MPI process on each node of a 12-core 3.33 GHz SSE2 computer (table A.1), but that process will use OpenMP constructs to create multiple threads. The matrix $a_{ij}$ is split across the compute nodes, and each compute node will do a further split to assign part of the Jacobi iteration to each of its threads. As far as program optimization is concerned, it will emerge that the MPI part is irrelevant. The process speed is determined by optimizing the Jacobi iteration within a single node.

### The Jacobi class

If the matrix $a_{ij}$ is $m \times n$ globally, each MPI process out of a total of $P$ processes gets approximately $n/P$ columns. The Jacobi iteration entails entries in neighboring rows and columns. Thus, each process must exchange messages with the process to its left and the process to its right. The pattern of communication is cyclic.

The organization of data in the Jacobi2 class, whose definition follows, is guided by the pattern of communication.

```cpp
class Jacobi2{
  private:
    int nthreads;
    int dim1;
    int dim2;
    double *a, *b;
    int lrank;
    int rrank;
    MPI_Request reqlist[4];
    void leftright();
    void initialize(int col1, int col2);
    void update(int col1, int col2);
    void copy(int col1, int col2);
public:
    Jacobi2D(int rank, int nprocs, int d1, int d2, int nth);
    - Jacobi2D();
    void initializepp();
    void postsendrecv();
    void wait();
    void update();
    void copy();
    double* geta(){return a+dim1;}
};
```

The dimension of the matrix stored on each processor node is $dim1 \times dim2$ (lines 4 and 5). The matrix is stored in arrays a[] and b[] (line 6). In each step of Jacobi, the entries of b[] are computed using the entries of a[]. Figure 6.8 shows the data layout assumed by the Jacobi2 class. Although the matrix in each node is $dim1 \times dim2$, the actual stored is $dim1 \times (dim2+2)$. The leftmost column is a copy of the column to the left and the rightmost column a copy of the column to the right. Thus, during any single iteration, a processor node can update all its $dim2$ columns.

Assuming jacobi is an object of class Jacobi2D, any single iteration looks like:

```
jacobi.postsendrecv();
jacobi.wait();
```
