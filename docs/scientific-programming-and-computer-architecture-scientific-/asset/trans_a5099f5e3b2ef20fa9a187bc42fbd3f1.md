# 每个核心分配一个 MPI 进程是一个坏主意

为每个核心分配一个 MPI 进程的方法仍然非常流行。它避免了学习线程的麻烦。表 6.8 解释了这是一个坏主意的部分原因。为了生成此表的节点，我们使用了与表 6.7 相同的 MPI 进程。该程序使用相同的 C/C++ 编译器编译，带有相同的标志，并链接到相同的 MPI 库。区别在于 NTHREADS（一个 #define 宏变量）被设置为 1 以关闭多线程，并为每个核心分配了一个 MPI 进程。

表 6.8 显示，跨网络的数据传输带宽急降。当有 10 个节点时，带宽低于峰值的 50%，当有 100 个节点时甚至不足 20%。

在每个核心上运行进程会增加对主机通道适配器（HCA）的竞争。即使性能损失不是那么严重，这也是一个坏主意。为每个核心分配进程会增加硬件设计的模块化。处理器节点是一个带有多个核心的硬件模块，在大多数时间内，每个节点上都有一个网卡。硬件设计从寄存器级别向上都是模块化的。有一个单一内存系统来管理所有核心。如果某一层的用户忽略了他们所依赖的软件或硬件的模块化，将很难维持良好的设计实践。

## 6.3.4 集体通信

我们到为止编写的 MPI 程序使用 $MPI\_Send()$ 和 MPI\_Recv() 的版本传输数据。此类调用是由单个进程自主发起的，但它们的完成取决于其他进程的匹配调用。MPI 库提供了几个用于集体通信的函数调用。集体函数必须由组中的所有进程执行。如 Bcast、Scatter、Gather 和 Alltoall 等集体调用的结果涉及所有进程的数据传输。

到目前为止我们遇到的唯一集体操作是函数 `unsafe()` 中的 $MPI\_Barrier()$。插入屏的目的是展示 MPI 语法。它对函数 `unsafe()` 没有产生影响。

在本节中，我们将查看 $MPI\_Bcast()$、$MPI\_Scatter()、$MPI\_Alltoall()$ 和 $MPI\_Reduce()$。所有这些集体函数都在参与进程之间传输数据，原则上可以使用进程之间的发送和接收操作来实现。对于广播，发送/接收的实现太慢了。

由 $MPI\_Alltoall()$ 实现的全对全数据传输可以使用发送/接收来实现。然而，如果我们目前仅限制于发送/接收语法，那么得到的实现没有库函数快。在推导一种有效的发送/接收实现时，我们遇到了一个非常有价值的发送/接收语法方面。不意外，这种新语法是有价值的，因为它可能与 Infiniband 硬件提供的便利有关。

在典型的 MPI 程序中，要解决的问题被分在几个进程之间。然而，归约操作例如分布在多台计算机和进程中的数据的最小值、最大值或和。$MPI\_Reduce()$ 函数可以使用发送/接收操作实现，但有效的发送/接收实现需要树形或递归的通信模式。类似于矩阵转置，归约提供了将网络活动与处理器活动重叠的机会。在矩阵转置的情况下，处理器活动涉及在缓冲区之间进行拷贝。在归约中，处理器还进行最小化、最大化或求和。

# 广播

在广播操作中，根进程将数据发送给每个其他进程。使用以下函数对 $MPI\_Bcast()$ 进行计时：

```c
double bcast(int rank, int nprocs, double *buffer,
    int bufsize){
    TimeStamp clk;
    int root = 0;
    clk.tick();
    MPI_Bcast(buffer, bufsize, MPI_DOUBLE, root,
    MPI_COMM_WORLD);
    double cycles = clk.toc();
    return cycles;
}
```

此 bcast() 函数必须由每个 MPI 进程调用，且 bufsize 的值必须完全相同。bcast() 函数调用了 $MPI\_Bcast()$，这是一个集体操作。通常情况下，整个通信器必须进行该调用。（等待，OCR 文本在这里似乎有破碎/乱码的句子，我将根据提供的文本流进行重新对齐）。

带宽报告为从根节点周期传出的字节数。QDR Infiniband 单端口的最大双向带宽切换为 1.5 字节/周期。广播操作仅在一个方向上使用链路，我们发现某些实例中超过了 0.75 字节/周期。性能并没有随着主机数量的增加而退化。相反，它变得更好。

Infiniband 与许多其他网络架构一样支持硬件广播。MPI 库 $MPI\_Broadcast()$ 使用了硬件级架构设施进行广播。支持硬件广播的优势显而易见。在胖树中，单个 Infinand 交换机可能连接到许多其他交换机。硬件只需将广播数据移动到交换机，然后将其路由到从该交换机可以的所有的所有。发送/接收实现被迫通过交换机多次发送数据，针对每个可能的主机。Internet 支持无线广播、体育赛事之类的广播协议。

MPI 标准规定所有函数调用都是阻塞的。因此，根节点启动的广播必须等待每个进程都有匹配的 $MPI\_Broadcast() 调用。阻塞开销约为几千个周期，当传输的数据为 1MB 或更多时，这种开销可以忽略不计，如表 6.9 所示。
