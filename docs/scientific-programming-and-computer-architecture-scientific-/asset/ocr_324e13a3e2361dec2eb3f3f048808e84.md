In the dependency rule with target test_lsolve.exe on lines 11 and 12, all object file names are given in full as absolute path names. The object files in the local module are prefixed with $(D)/. In contrast, the object files that are external to the module are given relative to the root prefix $(R)/. By using absolute path names and pattern rules specific to each module, we avoid recursive make entirely and instead build a single dependency graph.

One disadvantage of the technique just described is that when make runs and echoes the commands that it passes to the shell, the messages that appear have absolute path names that are almost unreadable. This deficiency can be remedied by resorting to complicated make syntax.
