If the compiler were doing a good job, one should see `movpd` instructions (pd stands for packed double), which use the entire capacity of the YMM registers, in the innermost loop. Instead, one sees `movsd` instructions (sd for single double), which use only a quarter of the YMM registers. Thus, the poorer performance could be a consequence of suboptimal compilation, a phenomenon encountered several times in the previous chapter and whose probability increases on more recent hardware.

# Leading dimension divisible by a high power of 2

If two locations in memory are separated by a high power of 2, they are likely to map to the same set in cache and TLB. Table 4.6 shows the bandwidth realized when a matrix of $2^{14} \times 2^{14}$ is transposed. Successive entries in the same row of this matrix are separated by $2^{11}$ cache lines. All entries of a row map to the same set in L1 and L2 caches as level 1 and level 2 TLB.

For a matrix of dimension $2^{14} \times 2^{14}$, `exports()` a bandwidth of 0.43 bytes per cycle, which is less than a third of the bandwidth realized for a matrix of dimension $20,000 \times 30,000$. With blocking, the best bandwidth observed is 1.34 bytes per cycle and the optimal block size is $16 \times 16$.
