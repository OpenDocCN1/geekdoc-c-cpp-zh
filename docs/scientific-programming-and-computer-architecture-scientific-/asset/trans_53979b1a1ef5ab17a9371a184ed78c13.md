

## 5.1. OpenMP 简介

此循环采用标准形式。如果使用了 OpenMP `for` 构造，编译器能够在语法上将其拆分为每个线程单独的独立循环。然而，结果将是错误的。为了遵循循环携带的 RAW（读后写）依赖关系，每次迭代都必须等待上一次迭代完成。当 for 循环被拆分且线程开始并行执行它们各自的迭代时，这种情况并不会发生。对此 for 循环应用并行（parallel）构造会导致程序错误。

在 OpenMP `parallel for` 构造的末尾有一个隐式屏障（barrier）。由于隐式屏障的存在，我们可以将 for 循环视为由多个线程执行的顺序执行程序的一部分。

在许多 OpenMP 编程中，人们不需要超越 `parallel for`。然而，所示的 `parallel for` 包含了许多隐式假设。这些假设在下方不简洁语法中被显式化：

```
double parallelfor(long n, int nthreads){
    assert(nthreads%2==0){
    double ans=0;
#pragma omp parallel for
    num_threads(nthreads)
    schedule(static)
    default(none)
    shared(n)
    reduction(+:ans)
    for(long i=0; i < n; i = i+2)
    {
        ans += 4.0/(2*i+1);
        ans -= 4.0/(2*i+3);
    }
    return ans;
}
```

第4行的的 `parallel for` 和第9行的的 `reduction` 子句与之前相同。`parallel for` 构造（或编译器指令）适用于第10行到第14行的整个 for 循环。

第5行的的 `num_threads()` 子句指定了要创建的线程数。这里我们要求 `nthreads`（`parallelfor()` 的一个参数）为偶数。

如果省略 `num_threads` 子句，默认情况下线程数通常是处理器核心数。可以使用环境变量 `OMP_NUM_THREADS` 将其设置为其他值。在大多数情况下，依赖默认行为更简单且更好。

第6行的的 `schedule()` 子句告诉编译器将 for 循环分发到各个线程。调度选项给出为 `static`（静态）。我们描述的静态调度在实践中最有用，且是默认选项。假设 $n$ 为偶数，第10行的 for 循环的循环变量 $i$ 遍历一系列值列表：

```
0, 2, \dots, n-2.
```

由于第6行的的调度被给出为 `static`，每个线程将获得一组大小大致相同的连续迭代。例如，如果有 $N$ 个线程，则每个线程大约有 $n/N$ 次迭代，线程号 $t$ 的线程的迭代从 $i \approx t \times n/N$ 扩展到 $i \approx (t+1) \times n/N$。其他调度方式也是可能的。迭代可以用轮询（round robin）方式或动态方式分配。

在并行块内部声明的变量对于每个线程都是私有的（private）。因此，在第10行定义的变量 $i$ 对每个线程都是唯一的。

问题在于，并行块内出现的如 $ans$ 和 $n$ 等在块外声明并定义的名称是否为内存中同一位置的名称。此类变量在并行块中可能是共享的（shared）或未使用的（即使是私有的——但很难想象这种功能的有意义用法）。人们可以使用 `default(shared)` 子句将并行块外定义的所有变量都变为共享变量。在此，第7行的的 `default(none)` 子句用于显示在块外声明的变量默认情况下在并行块内部是不可见的。第8行的的 子句声明变量 $n$ 在块内部可见并由所有线程共享。变量 $ans$ 没有被标记为共享，因为它是一个归约变量（reduction variable）。

## omp critical

`omp critical` 构造在以下方面与 `omp barrier` 类似。这两者都是很少使用的构造，但理解它们至关重要。理解 `barrier` 构造很重要是因为它隐式出现在并行区域（parallel regions）的末尾，使得我们能够将 OpenMP 程序作为带有并行区域的顺序程序使用。每当使用归约变量时，都会隐式使用关键区域，而 `critical` 构造使关键区域显式化。

下面列出的 `ompfor()` 函数除了 `omp critical` 之外，还引入了同名的 `omp for` 构造和 `omp parallel` 指令。

```
1 double ompfor(long n){
2     double ans=0;
3 #pragma omp parallel \
4     default(none) \
5     shared(n, ans)
6     {
7         double sum=0;
8 #pragma omp for
9         for(int i=0; i < n; i = i+2)
10            sum += 4.0/(2*i+1);
11            sum -= 4.0/(2*i+3)
12        }
13    #pragma omp critical
14    ans += sum;
15    }
16    return ans;
17 }
```
