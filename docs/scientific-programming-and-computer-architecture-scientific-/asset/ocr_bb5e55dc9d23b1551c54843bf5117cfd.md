The typical cost of creating and destroying Pthreads appears to be somewhat less $10^6$ cycles. The number is not unreasonable given that each process descriptor used by the kernel is nearly 6 KB. The cost of creating threads will vary from system to system, but the numbers are qualitatively the same on many different systems. The 3.4 GHz AVX computer with four cores used here had a single processor package. The cost of creating a thread per core may be expected to be higher on computers with multiple processors.

However, the cost of creating three threads is much more likely to run into millions of cycles on the quad-core 3.4 GHz AVX computer than on a machine with a dozen cores, even if the processor cores are split into two packages. A thread is more likely to wait for the time quantum of some other process to expire on a quad-core computer than on a computer with 12 cores.

# 5.3.3 Parallel regions using Pthreads

This section begins with a simple OpenMP program. The OpenMP program alternates between two parallel regions. In the first parallel region, every thread runs a function called `addone()`. In the second parallel region, every thread runs a function called `addtwwo()`.

Later in the section, the parallel regions are implemented in plain C, except for creating and launching Pthreads. The second and third implementations use spinlocks and mutexes, respectively. The final implementation uses conditional variables.

The basic idea in all four implementations is as follows. If the number of threads is $n$, including the master thread, the master begins by creating $n-1$ workers. The worker threads do not exit when their job is done but waiting for the master to send them more work. The threads exit only when the master tells them to.

Corresponding to the parallel regions of the OpenMP program, the master tells the workers to alternately execute `addone()` and `addtwwo()`. The master thread itself alternately executes those two functions.
