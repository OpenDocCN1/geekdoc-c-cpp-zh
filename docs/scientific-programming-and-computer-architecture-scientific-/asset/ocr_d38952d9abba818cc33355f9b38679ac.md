The make utility makes two passes. In the first pass, it consumes all the dependenncy rules builds a dependency tree such as the one shown in figure 2.23. In
addition, targets are associated with recipes. In our example, there are five targets:
ibniz.exe, logseries.exe, aitken.exe, leibniz.o and logseries.o. These
target appear on lines 1, 4, 7, 10, and 13, respectively. The recipes that are bound

In the second pass, the make utility brings the target list given at its invocation
u to date. For each target, it makes sure that its prerequisites are up to date
before bringing the target up to date. In general, this leads to a depth first traversal
part of the dependency graph.

Once the recipes are up to date, the make utility checks whether the target
is older. If each target and prerequisite is assumed to be a file, make finds the date
of each file using a GNU/Linux command called stat (a system call of the same
name) and takes to be the date of the target or the prerequisite. A target is out
of date or if any of its prerequisites is newer. If the target is out of date or older,
t corresponding recipe is invoked to bring it up to date (make does not check the heart
of the target after executing the recipe). This two-pass operation is the heart of
how make works.

Suppose we change to the linking/aitken dependency and invoke the make utility
at a shell prompt as follows:

```
make logseries.exe
```

During the first pass, the make utility notes that the target logseries.exe depends
logseries.o and aitken.o. These object files in turn depend on the correspondingsources and the header file aitken.h. If the object file logseries.o is older than
either logseries.c or aitken.c, the target logseries.o is considered to be out of
date during the second pass. Each file is stored with a time stamp that indicates
time at it was last modified or changed (you can use the GNU/Linux utility
stat to look at the time stamp of a file). If the target does not exist as a file, it
is considered to be out of date.
