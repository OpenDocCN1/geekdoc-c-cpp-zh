We use macros and the inline assembly facility to embed instructions that manipulate
XMM registers into C/C++ programs. The first of these is as follows:

```
/* R must be "%xmmi" 0<=i=15 */
#define zeromm(R) \\
    asm volatile ("%xorps " R", "\n\t"::R);
```

The 16 XMM registers are %mm0 through %xmm15 in GNU assembly (GAS). To zero
of them, we say %xmm7 zeromm("%xmm7") inside a C/C++ program. Macro
expansion and inline assembly produce the machine instruction

```
xorps %mm7, %mm7
```

followed by a newline and a tab for formatting. The mnemonic xorps behaves
as as XOR packed. Its two operands must be 128 bits wide. It treats
each operand as four single-precision floating point numbers. Its effect is to
exclusive or (xor) the two operands by bit. The xor of two is 1 when exactly
of one the two bits is 1, the other 0. Because we are xoring %xmm7 with itself,
get 0 for each of the 128 bits.

There are other ways to set a register to zero. For example, we can move the
value 0 into each part of the 128-bit XMM register, or we store 0 in
memory and load it. The use of xorps is preferred because the
st is three bytes, if the register is %xmm0 through %xmm7, or four bytes,
if the register is %xmm8 through %xmm15. Other methods may lead to longer
inructions. For example, the xorpd instruction is a longer byte. In addition, the
xorps instruction takes only to expand a single cycle to execute.
