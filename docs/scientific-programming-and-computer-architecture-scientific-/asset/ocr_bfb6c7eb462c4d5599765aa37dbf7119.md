File systems, implemented inside the operating system kernel, impose a logical structure on hard disk storage and facilitate it. Files and directories are stored on the hard disk. In everyday usage, files are read and written with the understanding that the data is stored on a hard disk. Between the file as viewed inside a C/C++ program and the hard disk, there are layers of software. These layers of software provide modularity, enabling the operating system kernel to handle several different file systems with a uniform interface and greatly improve speed of access.

The Linux kernel implements a number of optimizations to speed up access to the disk. The most important optimization is to use a page cache. The page cache is a list of page frames that corresponds to data in the disk. When a file is read, Linux will service the read using the page cache if possible. A read or write file operation has to fall through a number of software layers before it reaches the disk. The `read()` and `write()` calls are issued by the C library functions `fread()` and `fwrite()`. The C library may do some buffering of its own. The kernel will service the calls using a page cache if possible. If not, it invokes the file system to which the file belongs. There are software layers for combining, queuing, and scheduling requests to read or write to the hard disk. The request is finally issued using a device driver.

The command `lspci -v` may be used to find out the type of hard disk as well as the driver that is in. Although it is useful to understand that every disk access falls through layers of the file system within the operating system, knowing specific details about the type of hard disk and the driver is of little use in actual programming. There can be considerable variation in capacity as well as bandwidth of different hard disk systems, but that does not affect programming technique.
