The -I option gives the directory where the header file mpi.h is found. A simpler
command to compile this MPI program is

```
mpiCC -c procname.cpp
```

Here we have omitted options for the C++ compiler for simplicity. Depending on
the flavor of MPI, the compilation method may be mpixx or mpi++ or mpiCC or\mpiicpc. The simpler form is the one that is used almost universally. All that the
simpl form does pass suitable -I options to the compiler.

The linking command is

```
icpc 'mpiCC -showme:link' -o procname.exe procname.o
```

Like the following command, this linking command too is specific to the Open MPI
implementation. This that is spliced in

```
-pthread -L/home1/00013/tg456871/openmpi-1.6.3/lib/
-lmpi_cxx -lmpi -ldl -lm -lnuma -Wl,--export-dynamic\
-lrt -lnsl -lutil
```

The first line ends with the shell continuation character \ for convenient displaying. The libraries are linked dynamically. Therefore, the program must be able to
find the libraries at runtime using LD_LIBRARY_PATH or some other mechanism. The
simpl form of the linking command is

```
mpiCC -o procname.exe procname.o
```

All the simpl form does a few libraries automatically.

The compilation and linking of MPI programs is no different from that of any sequential. The declarations of the library functions must be visible at compile, and the executable is linked against libraries. However, the manner in which\he program is run is quite different. An MPI program must be started simultaneously on several nodes. During startup, the processes on different nodes have to set up data structures to recognize each other across the network.
