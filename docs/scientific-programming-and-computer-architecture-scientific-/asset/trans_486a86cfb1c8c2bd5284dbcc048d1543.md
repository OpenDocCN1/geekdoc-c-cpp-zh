表 6.12：通过 QDR Infiniband 连接的 1 PB  Lustre 文件系统上的带宽（单位：GB/s）。报告的数字为五次测试的最大值。文件总大小除以进程数 (nprocs) 得到 `lsize`。

类定义通过成员函数 `printinfo()` 完成。

```cpp
void LustreFile::printinfo() {
    if(rank!=0) {
        return;
    }
    char cmd[200];
    sprintf(cmd, "ls -1 %s", dir);
    system(cmd);
    sprintf(cmd, "lfsstripe %s/%s", dir, fname);
    system(cmd);
}
```

与 `lstripe()` 类似，`printinfo()` 使用 `system()` 通过通过 shell 发布命令。表 6.12 报告了从 8 MB 到 2 TB 不等文件的带宽测量值。表中的某些测量值，特别是 `lsize` 为 8 MB 的那些，可能受到了缓存的影响。在 Lonestar 集群上，Lustre 文件系统在使用 50 个条带（stripes）时可以达到近 7 GB/s 的带宽。该集群被大量科学家使用，测量结果很有可能受到集群上运行的其他作业的影响。然而，我们认为这种可能性不大。在不同日期、不同时间进行的测量也得到了相似的数值。

与几乎所有的文件系统一样，Lustre 文件系统在每个客户端上也会经过页缓存（页缓存参见第 4.3 节）。该页缓存的最大 own记录在文件

```
/proc/sys/lustre/max_dirty_mb.txt
```

为 12.6 GB。这是该集群中每台 3.33 GHz SSE2 计算机总内存的一半。即使每个 MPI 进程向同一个文件写入并随后读取 20 GB 数据，页缓存可能仍然影响测得的带宽。花费精力去消除页缓存影响是不值得的。消除缓存影响可能会导致仅适用于少数真实程序的改进措施。未耗尽可用内存的程序将从页缓存中获益。对应表 6.12 最后两列的运行任务在每个 MPI 进程上都持有一个 20 GB 的数组。Xeon 5680 主机上 24 GB 内存中超过 80% 已被用尽，无法用于页缓存。Lustre 的早期版本没有在对象存储服务器（Object Storage Servers）上使用缓存，但较新版本也可以在对象存储服务器上进行缓存¹

如果条带数固定为 50，表 6.12 显示使用 50 个或 100 个进程可以实现几乎相同的带宽。当 10 个条带时，读取带宽约为 2.6 GB/s，写入带宽约为 1.70 GB/s（使用 10、20 或 50 个运行在 Xeon 5680 主机上的客户端，机器信息参见表 A.1）。如果条带数为 10 且由单个客户端访问，带宽略低于 1 GB/s。当固定条带数而增加客户端数时，Lustre 依然保持健壮。
