To figure out what to do, we will build an executable with Fortran object files and the following command,

```
ifort -v -o leibniz.exe leibniz.o aitken.o
```

The -v option to the ifort links the linker to be verbose and point out every step of what it does. The linker produces quite a few. From that output, it appears that the Fortran runtime library is fetched by -lifcore.
Are now in a position to tackle the linking of aitken.o produced from Fortran source with leibnizFinC.o produced from a C source. We issue the command

```
icc -o leibnizFinC.exe leibnizFinC.o aitken.o \
  -lifcore
```

Fortunately, the -lifcore option resolves all the undefined names and an executable is generated. With the GNU compilers, the -lgfortran option ensures that the For runtime libraries are linked.
Linking object files generated from Fortran with C++ object files presents a new issue. Suppose we code the C source file leibnizFinC.c as follows:

```
cp leibnizFinC.c leibnizFinCPP.cpp
icpc -c leibnizFinCPP.cpp
ifort -c aitken.f
icpc -o leibnizFinCPP.exe leibnizFinCPP.o \
  aitken.o -lifcore
```
