# 4.2.3 Optimized matrix multiplication

Some of the most nettome issues in implementing matrix multiplication arise at the level of the processor pipeline. In section 3.3.4, we wrote an assembly program for $4 	imes 200 	imes 4$ matrix multiplication, which reached 3.5 flops per cycle, assuming all the matrices to be in cache. Here we show how to optimize matrix multiplication.

Suppose $A, B$, and $C$ are matrices of dimensions $\ell 	imes m, m 	imes n$, and $\ell 	imes n$, respectively. The matrices are assumed to be in DRAM memory and not in cache. The cost of operation $C = C+AB$ is $2lmn$ arithmetic operations, half of which are additions and half of which are multiplications. If the cache is large enough, each of the matrices can be loaded into cache and kept there as the matrix multiplication is performed. Loading the matrices into cache would take $\ell mn + ln$ memory accesses. If $\ell, m$, and $n$ are large, the number of arithmetic operations is much greater than the number of memory accesses. We expect the cost of the computation to be dominated by the arithmetic operations, allowing us to approach the peak bandwidth of 4 flops per cycle on a single core of SSE2 machine (the figures are 8 flops per cycle and 16 flops per cycles for AVX and AVX2 machines, respectively).
