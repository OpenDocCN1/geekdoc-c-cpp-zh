When a single array is accessed with a constant stride, a cache line brought into cache is used in a single go. Once the array moves past a cache line, we do not return to it. In matrix transpose with blocking, we rely on a cache line remaining in cache as we return to it repeatedly after working on other columns of the matrix block. This type of cache usage is more delicate. We find that the performance of the matrix transpose depends on a nonmonotonic manner on the size of the blocks. The performance degrades abruptly if the leading dimension of the matrix is divisible by a high power of 2. Such effects, disconcerting to the programmer, cannot be eliminated.

The cache and TLB parameters of SSE2/AVX/AVX2 machines we use are given in tables 4.1 and 4.2. On all the machines, the L1 data cache is big enough to hold 4,000 doubles and the L3 cache can hold more than a million double-precision numbers.

# Blocking

The function easytrans() listed below uses a simply nested loop to transpose the matrix a[]. The matrices are $m \times n$ and $n \times m$. Both of them are assumed to be stored in column-major order with leading dimension (section 2.2.1) equal to the number of rows.

```
void easytrans(double *restrict a, double *restrict b,
    int m, int n);

        for(int j=0; j < n; j++)
            b[j+i*n] = a[i*j+m];
```
