# 7.2. Offload

Section 7.2.2 introduces the target(mic) compiler directive. This directive, which is currently implemented only by the Intel compilers, may be applied to function definitions as well as globally defined variables. Any function prefixed with target(mic) will be compiled to run on Phi/MIC devices as well as the host.

Section 7.2.3 uses the familiar Leibniz example to show how the Phi/MIC device communicates with the host. The offload compiler directive is supported by clauses such as in, out, nocopy, and in to enable communication between the coprocessor and the host. Arrays are automatically copied into the Phi and copied back when the region exits. An offload region is sent back and forth using clauses appended to the offload directive.

The offload extension supports addressing array[] on the host and its copy on the Phi/MIC device using identical syntax. If v[i] refers to an entry on the host, v[i] refers to its copy or image on the Phi device. The offload extension supports partial views of an array. For example, we may offload v[offset:len] to the segment

```
v[offset], v[offset+1], ..., v[offset+len-1]
```

to the device. The entry v[i] on the Phi corresponds to the entry v[i] on the host, but on the Phi, the legal range for the index is limited to offset ≤ i < offset+len. These elegant elements simplify offloading to multiple Phi devices.

Section 7.2.4 shows that the bandwidth from host to Phi/MIC is similar to the bandwidth at a single node of an Infiniband network. The bandwidths are good enough to enable nontrivial usage of coprocessor devices but are far from stopping. The bandwidths are less than a tenth of bandwidth to memory from the AVX.

The discussion in this section may make offloading to Phi devices easy. It is indeed easy, even elegant, in simple programs. However, the basic setup where dissimilar coprocessor devices and the host compete to do the same work breaks modularity at the hardware level. In more complex programs, offloading will look less elicitous than it does here.
