此函数与 leibniz1() 完全相同，不同之处 offload 构造被修改了，且第 19 行的 `printf` 位于 offload 区域内部。这里的 offload 使用了强制性（mandatory）并添加了 `signal` 子句。如果没有 `signal` 子句，主机处理器将阻塞直到执行完成。如果使用 `signal` 子句，它将发布 offload 任务并继续向下执行而不会阻塞。通常情况下，使用信号允许主机处理器活动与 MIC 活动重叠。

## 7.2. Offload 517

下面的 offload 构造在 MIC 设备上分配 6.4 GB 的数组 `v[]` 并将其拷贝到那里：

```c
11 #pragma offload target(mic:0) \
12 in(v:length(n) align(64) alloc_if(1) free_if(0))
13 {}
```

在进入 offload 区域时分配以及在退出时释放的默认内容可能会让人困惑。在这里，分配和释放是显式的。修饰符 `alloc_if(1)` 表示数组 `v[]` 应该在进入时在 MIC 设备上分配。修饰符 `free_if(0)` 表示数组 `v[]` 在退出时不应被释放。它可以被随后的 offload 重用。因为这是一个子句，数组 `v[]` 将始终在进入时从主机拷贝到 MIC。这种拷贝是该子句的主要效果，因为构造体的体（第 13 行）是空的。

下一个 offload 构造具有非空的主体。

```c
14 #pragma offload target(mic:0) \
15 nocopy(v:length(n) alloc_if(0) free_if(0))
16 hostmic_scale(v, n);
```

`nocopy` 子句（第 15 行）意味着数组 `v[]` 在进入和退出时都不被拷贝。`alloc_if(0)` 和 `free_if(0)` 修饰的内存在进入时未在 MIC 设备上分配，在退出时也没有被释放。该构造的唯一效果是将第 16 行的函数 `hostmic_scale()` offload 到 MIC 设备上。一旦该它，驻留在 MIC 设备上的数组 `v[]` 就可以通过 $4^{1/3}$ 进行缩放，但主机上的数组保持不变。

进一步的缩放如下：

```c
17 #pragma offload target(mic:0) \
18 out(v:length(n) align(64) alloc_if(0) free_if(0))
19 hostmic_scale(v, n);
20
21 hostmic_scale(v, n);
```

该 offload 构造具有一个 `out` 子句。数组 `v[]` 在进入时不会从主机拷贝到 MIC，但在退出时会从 MIC 拷贝到主机。该数组在 MIC 设备上既不被分配也不释放。offload 区域（第 19 行）再次是 `host_mic()` 的单调用。从 offload 构造退出时，数组 `v[]` 在主机和 MIC 设备上都按 $4^{2/3}$ 缩放。

第 21 行在主机上执行函数调用 `hostmic_scale()`。在此之后，数组 `v[]` 在主机上缩放了 4 倍，在 MIC 设备上缩放了 $4^{2/3}$。

`leibniz3()` 的定义完成如下：

```c
22 double sum;
23 #pragma offload target(mic:0) \
24 in(v)length(n) align(64) alloc_if(0) free_if(1)
25 sum = hostmic_sum(v
```

注意该子句（第 24 行）`v[]` 从主机拷贝到 MIC。数组 `v[]` 在主机上缩放了 4 倍，但在 MIC 设备上仅缩放了 $4^{2/3}$。因此，如果我们想要获得 $\pi$ 的正确值，拷贝是必不可少的。这里 `v[]` 在退出时从 MIC 设备上释放。和在第 25 行在 MIC 设备上计算。

## 主机和 MIC 指针

`leibniz3()` 函数显示了存储在主机上的数组 `v[]` 与在 MIC 设备上的对应项之间的紧密联系。函数打印了主机上的指针 `v`（第 10 行）。有三次 `hostmic_scale()` 调用（第 16、19 和 21 行），其中两个来自 MIC 设备，一个来自主机。每个调用都会打印指针的值。打印了以下几行：

```
host pointer v = 0x2af1d0000040
scale:host/mic pointer v = 0x7fe5cd07040
scale:host/mic pointer v = 0x7fe5cd07040
scale:host/mic pointer v = 0x2af1d0000040
```

显然，指针在主机和 MIC 上的值不同，尽管它们在程序中具有相同的名称。在进入 offload 区域期间，主机需要知道该值。

## 到多个设备的 Offloading

在具有多个 MIC 设备的系统上，执行此操作的最自然方法是将数组划分到每个设备。`leibniz4()` 的开头部分如下：

```c
void leibniz4(){
    int nmic;
    mic_init(nmic);
    assert(nmic > 0);
    long n = 11*1000*1000*800;
    long nbytes = n*8;
    double* v = (double *)mm_malloc(nbytes, 64);
    leibniz_init(v, n);
}
```

这里 `sum[]` 是具有多个 MIC 设备的数组。跨设备划分数组的新语法所示：

```c
/*
* 在 mic 设备上分配内存
*/
for(int mc=0; mc < nmic; mc++){
  long shift = mc*n/nmic;
  long len = (mc+1)*n/nmic - mc*n/nmic;
#pragma onload_transfer target(mic:mc) \
 nocopy(v[shift:len]):align(64) alloc_if(1) free_if(0))
}
```

在 `for` 循环体内，分配到编号为 mc 的 MIC 设备的数组 `v[]` 部分从 `v[shift]` 开始到 `v[shift+len-1]` 结束。这里的 offload 区域在 MIC 设备上分配相应的内存。它是空的，没有任何拷贝。这里的关键语法是 `v[shift:len]`。在 MIC 设备上分配了一个长度为 `len` 的数组。与之前一样，在 offload 区域内部，主机上的指针 `v` 对应 上的另一个 `v`。即使在这种设置下，`v[i]` 也指向 Phi 以及主机上 `v[]` 的对应元素，但索引 `i` 的合法值必须在 `shift <= i < shift + len` 范围内。Phi 上的 `v[]` 拷贝再次是主机 `v[]` 的镜像，但镜像中只表示了原始数组的一个片段。定义的其余部分显示了更多 offload 实例。

```c
/*
* 将缩放和求和 offload 到 mic 设备
*/
for(int mc=0; mc < nmic; mc++){
  long shift = mc*n/nmic;
  long len = (mc+1)*n/nmic - mc*n/nmic;
#pragma offload target(mic:mc) \
 in(v[shift:len]:alloc_if(0) free_if(0)) \
 out(sum[mc:1]) \
 signal(1)
{
  hostmic_scale(v+shift, len);
  hostmic_scale(v+shift, len)
}
```
