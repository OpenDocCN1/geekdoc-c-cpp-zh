# A source with arrays and pointers

So far our discussion of arrays and pointers has been with reference to figure 1.3. We will now write a simple C program illustrating the discussion.

Before looking at C source, a few comments about indentation are in order. For program source not meant for display in a book, we use eight-space indentation.¹10 Tabs are separated by eight characters and terminal screens are conventionally 80 character wide. When the program is lined up according to tab stops, the code is much easier to browse. The nesting level of loops becomes readily evident. The nesting level is an indication of the level of complexity of the code. Therefore, it is useful to be able to recognize the nesting level immediately. Too many levels of nesting often imply poorly structured.

Let us look at the following code, which uses five-space indentation. The suggestion of eight-space indentation assumes 80-character-wide lines. The lines are about 50 characters, and the indentation has been scaled down proportionally.

```
#include <stdio.h>
int main()
{
    int x;
    int list[3];
    a = &x;
    list[1]=2;
    *a = 35+list[1];
    printf("%p %d\n", &x, list, x);
}
```

We are allowed to say list[1] = 2 (line 8), but list = &x would have been illegal. The reason is that list has a value but is not the name of any location. On one run, the code had the following output (line 10).

```
0xffff3cb8e414 0xffff3cb8e400 37
```

> ⁰The Linux programming guidelines require eight-space indentation. See www.kernel.org/doc/Documentation/CodingStyle. While noting style is a matter of personal choice, Linus Torvalds, the creator of the Linux operating system, adds that using four-space indentation "is akin to trying to define the value of PI to be 3."
