The OpenMP memory model is in play every time threads use a shared variable to communicate directly or indirectly. For finding the partial sum of the Leibniz series, the threads communicate indirectly using a shared variable to which each adds part of the sum. The correctness of almost every carried OpenMP program depends on flush operations that are implicitly carried out at the beginning and end of parallel and critical constructs and at every barrier.

In general, OpenMP allows the compiler to generate assembly for a parallel region or for forks of a for-loop assigned to a thread, as the code is sequential—except for implicit flush statements. Of course, the compiler must also handle variables correctly.

The peculiar implications of the OpenMP memory model can be difficult to grasp with just a single example. Therefore, we give another more complex example. The variable x is the only variable shared by the two threads created by the function printstuff(), which listing follows.

```
1 void printstuff(){
2   int x;
3   #pragma omp parallel         \
4       num_threads(2)          \
5       default(none)           \
6       shared(x)
7   {
8       int tid = omp_get_thread_num();
9       if(tid==0){
10          x = 0;
11      }
12      else if(tid==1){
13          x = 1;
14          printf("x = %d\t", x);
15          printf("x = %d\n", x);
16  }
}
```
