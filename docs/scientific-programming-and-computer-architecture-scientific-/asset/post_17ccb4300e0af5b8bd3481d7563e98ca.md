We were careful to break instruction-level parallelism. We flushed the entire array out of cache (not shown here) before calling the function and respect cache boundaries. However, we forgot to think about a third element. Memory management is done using pages, page frames, page directories, and page tables. Because the array is large, every memory reference is likely to hit a new page. The page table for that page is unlikely to be in TLB and may have to be brought in from DRAM memory. What we thought was one memory access is likely to be two or more.

This little example may give us a sense of the complex in which parts of the memory system interact. Cache line size, parallelism in memory access, and the cost of TLB misses are all of no significance to program optimization.

## 4.1. DRAM cache memory

Our earlier attempts to measure latency to DRAM memory failed because we did not account for the overhead of creating and accessing page table entries.
