# 2.2.2 BLAS and LAPACK

BLAS and LAPACK functions typically have long argument lists. For example, the Fortran interface to the BLAS function for multiplying a matrix and a vector has the declaration in C:

```
extern 'C' void dgemv_(char *,int *,int *,double *, *double *,
 int *, *double *,int *double *,double *,
 int *, *int);
```

This function, which has 12 arguments in total, implements the operation y ← αAx+by or y ← αAy+β. The first argument, which is a character string, allows us to specify whether the matrix A must be transposed or not. The next 10 arguments allow us to specify the entries and dimensions of the matrix A and of the vectors x and y, as well as the scalars α and β.

The last argument to dgemv() is the only one that is not a pointer. Because all arguments to Fortran subarrays are by reference, we may expect all arguments in the C declaration of a Fortran subroutine to be pointers. Why is the last argument not a pointer? The answer lies in the differing conventions for character strings in C and Fortran. In C, a character string may be passed as a pointer of type char*. There is no such convention in Fortran, and the lengths of character strings is determined by the terminating character '0'. There must be supplied explicitly. The last argument type int must be the length of the first argument, which is a character string. This argument is invisible in Fortran as the Fortran compiler takes care to supply it surreptiously.
