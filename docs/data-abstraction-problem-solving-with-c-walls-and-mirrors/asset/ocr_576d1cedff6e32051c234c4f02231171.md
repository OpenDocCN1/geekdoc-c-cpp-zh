But you really want to increment currentTime by 1?You would for a time-driven simulation, where you would determine arrival and departure times at random and compare those times to currentTime. Video games use this approach, since events can occur or be processed in almost every unit of time, which is typical in a frame. In such case, you would increment currentTime by 1 to simulate the ticking of a clock.

A time-driven simulation simulates the ticking of a clock
only the times of certain events, in this case, arrivals and departures

Recall, that this simulation is event driven, so you have plenty of predetermined arrival and transaction times. Because you are only interested in those times which arrival and departure events occur, no action is required between events, you can advance currentTime from the time of one event directly to the time of the next.
Thus, you can use the pseudocode solution as:

```
Initialize the line to "customers"
while (events remains to be processed)
{
    currentTime = time of next event
    if (event is an arrival event)
        Process the arrival event
    else
        Process the departure event

// When an arrival event and departure event occurs at the same time,
// arbitrarily process the arrival event first
}
```

First revision of the simulation algorithm

You must determine the time of next arrival or departure so that you can implement the state

```
currentTime = time of next event
```

To make this determination, you must maintain an event list. An event list contains all arrival and departure events that will occur but have not occurred yet. The times of the events in the list are in ascending order, and then the next to be processed is always the beginning of the list. The algorithm simply gets the beginning of the list, advances to the time specified, and processes the event. The difficulty, then, in successfully managing the event list.

An event list contains all future arrival events and departure events

Managing and processing customers and events. As customers, you go to the back of the line. The current customer, who was at the front of the line, is being served and it is this customer that you remove from the system next. It is natural to use a queue, banque, to represent the customers in the bank. For this, the only information you must store in the queue about each customer is the time of arrival and the length of the transaction.

Arrival events and departure events are ordered by time, and we always want to remove and process the next event that occur—the highest-priority event. The ADT priority queue is used in this way. Our events can be stored in the priority queue event,ListPQueue. We can initialize eventListPQueue with the arrival events in the simulation data file and later add the departure events as they are generated.
