the previous section, you know that $n-1$ is the minimum number of edges necessary for a graph of $n$ vertices to be connected. Thus, $n-1$ is the minimum number of lines that can connect $n$ cities.

If the cost of installing each line is the same, the problem is reduced to one of finding any spanning tree of the graph—that is, the total installation cost—the **cost of the spanning tree**—is the sum of the edges in the spanning tree. However, as in Figure 20-22 shows, the cost among each line varies. Because there may be more than one spanning tree, and because the cost of different trees may vary, you need to solve the problem by selecting a spanning tree with the least cost; that is, you must select a spanning tree for which the sum of the weights (costs) is minimal. Such a tree is called the **minimum spanning tree**, and it is not unique. There may be several minimum spanning trees for a particular graph, their costs could equal.

A minimum spanning tree of a connected undirected graph has a minimal edge-weight sum

One simple algorithm, Prim's, finds a minimum spanning tree that begins at any vertex. Initially, the tree contains only the starting vertices. At each stage, the algorithm selects a least-cost edge among those that begin with a vertex in the tree and a vertex not in the tree. The latter vertex and least-cost edge are added to the tree. The following pseudocode describes this:

```
// Determines a minimum spanning tree for a weighted,
// connected, undirected graph whose weights are
// nonnegative, beginning with any vertex v.
primAlgorithm(v: Vertex)
  Mark v as visited and include it in the minimum spanning tree
  while (unvisited vertices)
    Find the least-cost edge (v, u) from a visited v to some unvisited vertex u
    Mark u as visited
    Add u to the tree and the edge (u, v) to the minimum spanning tree
```
