Three basic kinds of relationships are possible. In this section we discuss is-a and as-a relationships, which involve inheritance. We discuss an important third relationship, has-a, in Section C4.2.

Is-a relationships. Earlier in this interlude, we used public inheritance to derive the class MagicBox from PlainBox. You should use public inheritance only when an is-a relationship exists between two classes of objects. In this example, a magic box is a plain box, as Figure C-7 illustrates. That is, whatever is true of the base class PlainBox is also true of the derived class MagicBox. Wherever you use an object of type PlainBox, you can also use an object of type MagicBox. This feature is called object compatibility. Thus, you can use an instance of a derived class instead of an instance of its base class, but not the other around.

In particular, the object type of argument in a call to a method can be the descendant of the object type of the corresponding class. For example, suppose your program uses the classes PlainBox and MagicBox and contains the following ordinary function, which is not a member of any class:

```
void displayItem(PlainBox*string) {
    cout << "The item stored in the box is " << string->getitem() << "\n";
} // enddisplayItem
```

The first call is unremarkable because both the argument myPlainBox and the parameter type have the same data type. The second call is more interesting: the data type of the argument myMagicBox is a descendant of the data type of the parameter. A magic box is a plain box, but it can behave like a plain box. That is, MagicBox can perform plain behaviors, so you can use MagicBox wherever you use PlainBox. Note that object type compatibility applies to both value and reference arguments.
