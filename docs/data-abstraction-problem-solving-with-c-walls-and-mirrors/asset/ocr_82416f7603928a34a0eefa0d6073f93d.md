$\alpha$ is a measure of how full the hash table is. As the table fills, $\alpha$ increases and the chance of collision increases, search times increase. Thus, hashing efficiency decreases as $\alpha$ increases.

Unlike the efficiency of earlier dictionary implementations, the efficiency of hashing does not depend solely on the number $n$ of items in the dictionary. While it is true for a fixed$tableSize efficiency decreases as $n$ increases, for a given $n$ you can choose $tableSize$ to increase efficiency. Thus, when determining the size of the hash table, you should estimate the largest $n$ and select $tableSize$ so that it is small as you will shortly, should not exceed 2/3.

Hashing efficiency for a particular search also depends on whether the search is successful. An unsuccessful search requires more time in a successful search. The following analyses$^3$ enable a comparison of collision-resolution techniques.

**Linear probing.** For linear probing, the approximate average number of comparisons to a search requires is

```
$$\left[ 1 + \frac{1}{\alpha}\right]$ for a successful search, and
```

```
$$\left[ 1 + \frac{1}{(1 - \alpha)^2} \right]$ for an unsuccessful search
```

As collisions increase, the probe sequence increases in length, causing unsuccessful search times. For example, for a dictionary that is two-thirds full ($\alpha = 2/3$), an unsuccessful search might require at most five comparisons, or a successful search might require at most two comparisons. To maintain efficiency, it is important to prevent the hash table from filling up.

**Quadratic probing and double hashing.** The efficiency of quadratic probing and double hashing is given by

```
$$- \frac{\log(1 - \alpha)}{\alpha}$ for a successful search, and
```

```
$$- \frac{1}{1 - \alpha}$ for an unsuccessful search
```

On average, both techniques require fewer comparisons than linear probing. For example, for a dictionary that is two-thirds full, an unsuccessful search might require at most three comparisons, or a successful search might require at most two comparisons. You can use a smaller hash table for quadratic probing and double hashing than you can for linear probing. However, because they are open-addressing schemes, all three suffer when you are unable to predict the number of insertions and removals that will occur. If your hash table is too small, it will suffer efficiency.

**Separate chaining.** The table,$tableSize$ places the new item at the beginning of a linked chain within the table, as is $O(1)$. The get and remove operations, however, are not as fast. Each search of the linked chain, ideally you would like for these to be short.

For separate chaining,$tableSize$ is the number of chains, not the maximum number of dictionary items. Thus, it is entirely possible, even when, the current number of dictionary items exceeds $tableSize$. That is, or $n/tableSize$, the factor $\alpha$, can exceed 1. Because $tableSize$ is the number of linked chains, $n/tableSize$—that is, $\alpha$—is the average length of each linked chain.
