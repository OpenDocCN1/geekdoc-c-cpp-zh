```
} // end toVector
```

Here curPtr points to each node in a non-empty chain during the course of the loop's execution, so the data portion of each node is accessed and assigned to the end of the vector. After the last node is accessed, curPtr becomes nullptr, and the loop terminates. When the bag is empty—that is, when headPtr is nullptr—the loop is skipped. The variable counter, while not necessary, provides a defense against going beyond the end of the chain.

> **Programming Tip:** A common error in the while statement we used to compare curPtr->next() of curPtr with nullptr. When curPtr points to the last node of a non-empty chain, curPtr->getNext() would make the loop terminate before accessing the data in the last node. In addition, when the bag is empty, headPtr-- and therefore are nullptr, making the value of curPtr->getNext() undefined. References incorrect should be avoided.
