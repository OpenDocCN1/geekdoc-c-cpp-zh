The first methods are straightforward, but let's look more closely at getPosition. Given an entry in the sorted list, the method getPosition returns the position number within the list, as you would expect. We number the entries beginning with 1, as we do for the ADT. But what if the entry is not in the sorted list? In this case, getPosition returns the position number where the entry belongs. The returned number is negative, however, to signal that the entry is not in the list. For example, if missingObject(object) is not in the sorted list it will return at position 3, -3.

The sorted list also has, but not all, of the operations of an ADT list. We have already mentioned adding an entry at a given position is not possible, otherwise the client could destroy the order of the sorted list. For this reason, the list's setEntry is not available for a sorted list. The other operations of the ADT however, are useful for a sorted list as well, including the ones that retrieve or remove the entry at a given position. The methods getEntry and remove have a position number as a parameter, but they will not alter the order of the entries in the sorted list.
