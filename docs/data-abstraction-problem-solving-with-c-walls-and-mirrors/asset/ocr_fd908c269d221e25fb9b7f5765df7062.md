During OOA, you express the problem and the requirements of a solution in relevant objects. These objects may represent real-world objects, software systems, or ideas. Using OOA, you describe these objects and their interactions among one another. Analysis work involves the discovery associated with understanding the problem. It does not involve thinking about a solution to the problem, and instead focuses on thinking about the problem itself.

The results of analysis act as input to the process of design. During object-oriented design (OOD), you describe a solution to the problem, fulfilling the requirements you discovered during analysis. You express the solution in terms of software objects, and you note how objects collaborate. Objects collaborate when they send each other messages; that is, objects call on another to perform operations. The interactions are as important as the objects themselves and require careful planning. To solve the problem efficiently, the collaborations among objects should be minimal and meaningful.

During OOD, you typically create one or more models for the solution. Some of the models emphasizes the interactions among objects; others show the relationships among objects. Taken, they create a design that can be implemented in C++ or any other object-oriented language.

# 1.1.2 Aspects of an Object-Oriented Solution

Unless otherwise, a solution to a problem in this book is a computer program. A program comprises working modules. A module is a self-contained unit of code and could be a single-alone-function, a class, a method itself, a group of functions or classes that work closely together, or other blocks of code. Exactly how a module depends on the type and size of the application. Functions and methods implement algorithms, which are step-by-step recipes for performing a task within a finite period of time. One action that an algorithm performs is operating on a class.

When designing a solution, your challenge is to create a good set of modules. These modules must store, move, and alter data. They also use methods to communicate with one another. When constructing a solution, you organize your data collection so that you can operate on the data in the manner an algorithm requires. In fact, most of this book describes ways of organizing data.

Object-oriented programming languages allow you to build classes of objects. A class combines the attributes—characters of a type with the objects' behaviors—into a single unit. The individual items specified in a class are called data members. Operations are typically data, and methods are functions that often operate on data. In programming languages such as C++ and Java, classes specify the attributes and operations for the objects.

Encapsulation is a technique that hides inner details. Whereas functions encapsulate behavior, objects encapsulate data as well as behavior. For example, a class encapsulates the time—an attribute—along certain operations, such as setting or displaying the time. You can request that a class perform operations but you cannot see how they are done (unless you have a mechanical class with see-through sides).

Classes can inherit properties and operations from other class. For example, once you define a base class of objects, you can design a subclass that inherits the properties of it but adds attributes that provide the functionality of an ally. You can produce an alarm clock quickly because the clock portion is done. Thus, inheritance—another object-oriented concept—allows you to reuse classes you defined earlier for a related purpose by extending that implementation with modifications.
