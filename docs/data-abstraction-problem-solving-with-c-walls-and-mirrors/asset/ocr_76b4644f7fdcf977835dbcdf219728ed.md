mergeSort(theArray, first, last) has the general form

```
mergeSort(theArray, first, last)
if (first < last)
    mergeSort(Left half of theArray)
    mergeSort(Right half of theArray)
    Tidy up after the recursive calls
```

The partition in quickSort is to partition the array into regions S and S'. The algorithm then sorts S and S', independently, because every item in S, belongs to the left of every item in S'. In mergeSort, on the other hand, no work is done before the recursive calls: The algorithm sorts each half of the array with respect to itself. However, the algorithm must still deal with the interacnion between the items in the two halves. That is, the algorithm must merge the halves of the
array after the recursive calls.

Now recall the pseudocode function ksmall, described in Chapter 2, that returns the kth
smallest value in an array:

```
ksmall(k, theArray, first, last): Integer
Choose a pivot p from anArray[first...last]
Partition the values of anArray[first...last] about p
if (k < pivotIndex - first + 1)
    return ksmall(k, anArray, first, pivotIndex - 1)
else if (k == pivotIndex - first + 1)
    return p
else
    return ksmall(k - (pivotIndex - first + 1), anArray,
    pivotIndex + 1, last)
```

The recursive calls to ksmall act only on the section of the array that contains the desired
item, and it is not called all if the desired item is the pivot. On the other hand, quickSort
is called recursively on all unsorted sections of the array. Figure 11-13 illustrates this
difference.
