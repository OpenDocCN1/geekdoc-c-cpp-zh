# 16.2 A Link-Based Representation

You can use C++ pointers to link the nodes in the tree. Doing so is the most common way of implementing a tree. Listing 16-2 shows the class BinaryNode for a link-based implementation of the ADT binary tree.

LISTING 16-2 The header file containing the class BinaryNode for a link-based implementation of the ADT binary tree

```
/** class of nodes for a link-based binary tree.
 * @BinaryNode.h */

#ifndef _BINARY_NODE
#define _BINARY_NODE

template<class ItemType>
class BinaryNode{
private:
    ItemType item; // Data portion
    BinaryNode<ItemType>* leftChildPtr; // Pointer to left child
    BinaryNode<ItemType>* rightChildPtr; // Pointer to right child

public:
    BinaryNode();
    BinaryNode(const ItemType& aItem);
    BinaryNode(const ItemType& aItem,
               BinaryNode<ItemType>* leftPtr,
               BinaryNode<ItemType>* rightPtr);

    void set(const ItemType& aItem);
    ItemType get() const;
    bool isLeaf() const;

    BinaryNode<ItemType>* getLeftChildPtr() const;
    BinaryNode<ItemType>* getRightChildPtr() const;

    void setLeftChildPtr(BinaryNode<ItemType>* leftPtr);
    void setRightChildPtr(BinaryNode<ItemType>* rightPtr);
}; // end BinaryNode

#include "BinaryNode.cpp"
#endif
```

Given the class BinaryNode in Listing 16-2, a class of link-based binary trees will declare one data member—a pointer rootPtr—to point to the tree's root. If the tree is empty, rootPtr contains nullptr. For a binary tree that is not empty, rootPtr->getLeftChildPtr() points to the root's left subtree, and rootPtr->getRightPtr() points to the root's right subtree. The header file in Listing 16-3 declares the class BinaryNode in anticipation of its link-based implementation. Note the protected methods that the public methods call to perform their operations. These methods require pointers as arguments. Should not be public and available to clients. After all, clients should not have access to node. The public section declares constructors more than we have in the past, allowing a client to define binary trees in a variety of circumstances. For example, you can construct a binary tree:

- That is empty
- Data from its root, which is its only node
- Data from its root and all of subtrees

For example, the following statements invoke three constructors:

```cpp
BinaryTree<string>* tree;
BinaryTree<string>* tree2 = new BinaryTree("A");
BinaryTree<string>* tree3 = new BinaryTree("B");
BinaryTree<string>* tree4 = new BinaryTree("C", tree2, tree3);
```

Sample uses of public constructors

tree is an empty binary tree, tree2Ptr and tree3Ptr point to trees that have only a root. These two roots contain "A" and "B", respectively, and tree4Ptr points to a binary tree whose root contains "C" and has subtrees pointed to tree2Ptr and tree3Ptr. In the previous example, if you were to use BinaryTreeInterface instead of BinaryTree in the type of either tree2Ptr or tree3Ptr, you would have to cast the variable to BinaryTree before you could call the constructor. For example, suppose you define tree2Ptr as follows:

```cpp
BinaryTree<string>* tree2Ptr = new BinaryTree("A");
```

You would define tree4Ptr as follows:

```cpp
BinaryTree<string>* tree4Ptr = new BinaryTree("C", static_cast<BinaryTree<string>*>(tree2Ptr), tree3);
```
