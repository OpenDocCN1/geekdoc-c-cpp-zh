# Chapter Overview

Readers of this book should have completed a programming course, preferably in C++. Appendix A covers the essentials of C++ that we readers will know. You can use this appendix as a review or as the basis for making the transition to C++ from another programming language. Note that Appendices K and L offer help for those who are transitioning from Java or Python, etc.

+   - **Chapters 1 through 5**: Chapter 1 introduces object-oriented concepts and focuses on the specification of abstract data types (ADTs). Our ADTs now store data type which is chosen by the client. To accomplish this, each specification of an ADT includes a C++ template interface. For example, Chapter 1 introduces the ADT by. Much of the software engineering we make in Chapter 1 is now in the appendices.
- Next is Chapter 6, which presents C++ classes. It gives more detail about template interfaces—like the one presented in Chapter 1 and shows how to define a class derived from an interface.
- As said in later chapters, Chapter 2 introduces recursion, and Chapter 5 develops it as a problem solving tool. Recursion is revisited throughout the book.
- We clearly specify the specification, use, and implementation of the bag by dividing the material across several chapters. Chapter 1 specifies the bag and provides several examples of its use. Chapter 3 covers implementations that use arrays. Just before Chapter 4 introduces classes of linked nodes and uses one in the definition of a class of bags, Chapter 2 introduces pointers, polymorphism, and dynamic memory allocation. Chapters 3 and 4 include recursion in their presentation.
- In a similar fashion, we provide specification throughout the book when we discuss other ADTs. You can choose to cover the chapters that specify and use the ADTs and then cover the chapters that implement them. Or you can cover the chapters as they appear, implementing each ADT after studying its specification and use. A list of chapters appears later in this to help you plan your path through the book.
- Chapter 3 does more than simply implement the ADT. It shows how to approach the implementation of a class by focusing on core methods. When defining a class, it is often useful to implement and test these methods first and leave definitions of the other methods for later. Chapter 4 follows this in its development of a linked-based implementation of the ADT.
- **Chapters 6 and 7**: Chapter 6 discusses stacks, giving examples of their use, and Chapter 7 implements the stack using an array and then again using a chain. Between these is C++++ 3, which discusses C++ exceptions; Chapter 7 shows how to use exception in the implementation of the ADT, when a client demands method protection.
- **Chapters 8 and 9**: The next two chapters introduce the ADT list. This list contains this abstract and then implement it using an array and then a chain of linked nodes. Once again, we use exceptions to enforce methods.
- **Chapters 10 and 11**: Chapter 10 introduces the complexity of algorithms, a topic that we integrate into future chapters. Chapter 11 discusses various sorting techniques and their relative complexities. We consider both iterative and recursive versions of these algorithms.
- **Chapter 12**: Chapter 12 introduces the sorted list, looking at a linked implementation and a sorted list and shows how to use the list as a base class for the sorted list. Note that Chapter 12 is preceded by C+++ 4 which discusses class relation-ships and the various ways a class can be reused. Chapter 12 puts that discussion into immediate use.
- **Chapters 13 and 14**: Chapter 13 presents the ADTs de-queue and priority queue, along with some of these containers. In doing so, we give an example of situation that uses both ADTs, and finally summarize the difference between position oriented and value oriented ADTs. Chapter 14 introduces the queue, and introduces tail pointers, circularly linked chains, and circular arrays. We offer an implementation of the priority queue by using a sorted list, but a better approach will come later when we introduce the ADT head.
