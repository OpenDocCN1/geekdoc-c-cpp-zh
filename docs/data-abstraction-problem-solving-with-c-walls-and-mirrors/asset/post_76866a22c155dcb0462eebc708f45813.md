## 19.2 2-3 Trees

A **2-3 tree** is a tree in which each internal node (nonleaf) has either two or three children and all leaves are at the same level. For example, Figure 19-2 shows a 2-3 tree of height 3. A node with two children is called a **2-node**—the nodes in the binary tree are all 2-nodes—and a node with three children is called a **3-node**.

FIGURE 19-2 A 2-3 tree of height 3

![](img/d0cb86b2f18b2db569968ad7c743510e_595_0.png)

A 2-3 tree is not a binary tree, because a node can have three children; nevertheless, a 2-3 tree resembles a full binary tree. If a particular 2-3 tree contains only 2-nodes—a possibility, according to the definition—it is like a full binary tree, because all of its internal nodes have two children and all of its leaves are at the same level. If, on the other hand, some of the internal nodes of a 2-3 tree do have children, the tree will contain more nodes than a full binary tree of the same height. Therefore, a 2-3 tree of height $h$ always has at least as many nodes as a full binary tree of height $h$; that is, it has at least $2^{h-1}$ nodes. To prove this way, a 2-3 tree with $n$ nodes has height greater than $[\log_2(n+1)]$, the minimum height of a binary tree with $n$ nodes.

Given these observations, a 2-3 tree might be useful as an implementation of the AD dictionary. Indeed, if this is the case the 2-3 tree orders its nodes to make it useful as a search tree. Just as we distinguish between a binary tree and a search tree, we could distinguish between a “2-3 tree” and a “2-3 search tree.” The previous description would define a 2-3 tree, and the recursive definition next would define a 2-3 search tree. Most people, however, not make such a distinction and use the term “2-3” to mean “2-3 search tree”; we will do so as well. ### 19.2.1 Traversing a 2-3 Tree

The algorithms for the traversal, retrieval, insertion, and removals operations on a 2-3 tree are recursive. You can avoid daunting implementation details by defining the base case for recursive algorithms to be a leaf rather than an empty subtree. As result, the algorithms must assume they are not passed an empty tree as argument. You can traverse a 2-3 tree in sorted order by performing the analogue of an inorder traversal on a binary tree.

```cpp
// Traverses a nonempty in sorted order.
void inorder(2-3Tree T): void {
    if (T's root node r is a leaf)
        Visit the data item(s)
    else if (r has two data items)
    {
        inorder(left subtree of T's root);
        Visit the first data item;
        inorder(middle subtree of T's root);
        Visit the second data item;
        inorder(right subtree of T's root);
    }
    else // r has one data item
    {
        inorder(left subtree of T's root);
        Visit the data item;
        inorder(right subtree of T's root);
    }
}
```

### 19.2.2 Searching a 2-3 Tree

The ordering of items in a 2-3 tree is analogous to the ordering in a binary search tree and allows you to search a 2-3 tree efficiently for a particular item. In fact, the retrieval operation for a 2-3 tree is quite similar to the retrieval operation for a binary search tree, as you can see from the following pseudocode:

```cpp
// Locates the target value in a nonempty 2-3 tree. Returns either the located
// entry or an exception if a node is not found.
ItemType findItem(2-3Tree T, target: ItemType): ItemType {
    if (target is in T's root node r)
    {
        treeItem = the data portion of r;
        return treeItem; // Success
    }
    else if (r is a leaf)
        throw NotFoundException; // Failure
    // Else search the appropriate subtree
    else if (r has two data items)
    {
        if (target < smaller-item in r)
            return findItem(r's left subtree, target);
        else if (target < larger-item in r)
            return findItem(r's middle subtree, target);
        else
            return findItem(r's right subtree, target);
    }
    else // r has one data item
    {
        if (target < r's data item)
            return findItem(r's left subtree, target);
        else
            return findItem(r's right subtree, target);
    }
}
```

You can search the 2-3 tree and the shortest tree with approximately the same efficiency, because

- A binary tree with n nodes cannot be shorter than [log₂(n+1)]
- A 2-3 tree with n nodes cannot be longer than [log₂(n+1)]
- A node in a 2-3 tree has at most two items

Searching a 2-3 tree is not more efficient than searching a binary tree, however. This observation may surprise you, because after all, the nodes of a 2-3 tree can have three, and hence a 2-3 tree might be shorter than the shortest possible binary search tree. Although true, this advantage in height is offset by the extra time required to compare a value with two values instead of only one. In other words, you might visit fewer nodes searching a 2-3 tree, but you might have to make more comparisons at each node. As a consequence, the number of comparisons to search a 2-3 tree for a given item is approximately equal to the number of comparisons required to search a binary search tree that is as balanced as possible. This number is approximately log₂n.

If you can search a 2-3 tree and a balanced binary tree with approximately the same efficiency, why then should you use a 2-3 tree? Because maintaining the balance of a binary search tree is difficult in the face of insertion and removal operations, maintaining the shape of a 2-3 tree is relatively simple.
