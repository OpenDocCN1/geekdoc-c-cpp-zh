# C++ INTERLUDE 7 The Standard Template Library

+   - Developing simple ADTs provides a foundation for learning to develop other ADTs, especially those that are not in the STL.
- STL containers are not part of a class hierarchy and cannot take advantage of polymorphism in the same way as ADTs can.
- You might find yourself working in a language that does not provide predefined ADTs. You need the ability to develop ADTs on your own, and hence you must understand the process.
- If the ADTs defined by the language you are using are insufficient, you need to develop your own or enhance existing ones.

The STL provides support for predefined ADTs through the use of three basic items: containers, iterators, and algorithms. Containers are objects, such as a list, that hold other objects. Iterators provide a way to cycle through the contents of a container and are defined in C++ Interlude 6. Algorithms, such as a sorting algorithm, also exist. STL containers are implemented as templates, similar to the ADTs we implemented in this text.
You are already familiar with one STL container—the class vector—which is used in Chapter 3 to implement the ADT method vector. Moreover, many introductory C++ courses use the STL class vector instead of arrays as a simple way to store multiple items of a similar type
There are three types of containers in the:

+   - Container adapters provide efficient, restricted, position-based access to the collection. They are considered adapters because they use other STL containers to implement their operations.
- Sequence containers provide sequential access to the collection. The containers in this group provide trade-offs in efficiency for insertions and removals.
- Associative containers provide efficient key-based access to the collection. Each of these containers organizes and accesses the search keys to provide efficient groups of operations.

Each container type implements similar operations, but with a different emphasis in efficiency. You'll find that many of these operations have corresponding operations in the ADTs that we defined in this text, but the STL size might be different.
Two operations that all STL containers define are empty and size. These correspond to isEmpty and for associative containers, the container size is the number of entries it can hold. If the container is empty, it does not have any entries, but cannot hold any. To add a new entry to the container, you must use one of the methods that increases the container size during the addition operation, or in the case of sequence containers, resize the container *resize method*.

| OPERATION | DESCRIPTION | EFFICIENCY |
| --- | --- | --- |
| Constructor | Creates a container; sequence containers allow the user to specify an initial size. | Varies |
| Destructor | Destroys all entries in the container, and destroys the container. | O(n) |
| operator= | Assigns entries in the container on the right-hand side to the left-hand side. | O(n) |
| bool empty() | Returns true if the container is empty (size is 0). | O(1) |
| uint size() | Returns the number of locations in the container. | O(1) |

uint is the data type for an unsigned integer
