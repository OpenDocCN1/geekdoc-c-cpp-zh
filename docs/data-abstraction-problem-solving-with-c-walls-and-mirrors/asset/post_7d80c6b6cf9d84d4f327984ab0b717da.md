The use of virtual methods has a significant impact on future use of a class. Imagine that you had compiled the class PlainBox and its implementation before you wrote the derived class MagicBox. If you wrote new MagicBox, assuming access to the compiled PlainBox, you could override getItem because it is virtual in PlainBox. You can add capabilities to a derived class without having access to the source statements.

# 2.5.1 Resizable Array-Based Bag

We can use an array to implement the add method so that the bag never becomes full. If we use the header file for the class ArrayBag, as in Listing 3-1 of Chapter 3, and the implementation of the various methods, we see that only the add method needs to be changed. When the array—and the bag—becomes full, double the capacity of the array instead of failing to add the item. The revised method follows. Since the bag is never full, this version of the add method can always return true.

```cpp
template<class ItemType>
bool ArrayBag<ItemType>::add(const ItemType& newEntry)
{
    bool hasRoomAddTo = (itemCount < maxItems);
    if (hasRoomAddTo)
    {
        ItemType* oldArray = items;
        items = new ItemType[2 * maxItems];
        for (int index = 0; index < maxItems; index++)
            items[index] = oldArray[index];
        delete[] oldArray;
        maxItems = 2 * maxItems;
    }
// end if if
// We can always add the item
```

```cpp
items[itemCount] = newEntry;
itemCount++;
return true;
}// end ResizableArraybag
```

Doubling the array each time the bag is full is not as attractive as it might first seem. Each time you expand the size of an array, you copy the 50-element array to a 100-element array before completing the addition. When the array is a small 50-element array, 49 additions can be made quickly without copying the array.

If you have a 50,000-element array that is full, you must allocate memory for 100,000 entries before copying the 50,000 entries in the current array. This takes considerably longer to do and a significantly greater amount of memory. It is possible that you needed storage for only 50,001 entries and will have 49,999 unused array elements wasting memory. Once you realize that your array is too large, you could reduce its size by allocating a smaller array and copying the entries to this new array. However, there is no way to predict whether or not you should do so.
