That is, you can use either inheritance or containment to hide the underlying list in the implementation of the sorted list. ## SUMMARY

- 1. The ADT sorted list maintains its entries in sorted order. It, not the client, determines where to place an entry.
- 2. The ADT sorted list can add, remove, or locate an entry, giving the entry as an argument.
- 3. The ADT sorted list has several operations that are the same as the corresponding operations of the ADT list. However, a sorted list will not let you add or replace an entry by position.
- 4. A chain of linked nodes provides a reasonably efficient implementation of the sorted list.
- 5. A class of sorted lists that has a list as a data field is to use containment. Although such a class is easy to write, its implementation of the ADT list is inefficient.
- 6. Although it seems a sorted list is a list, deriving a class of sorted lists from classes using public inheritance is not the appropriate. Doing so requires you to override some methods of the ADT that a client of the sorted list should not be able to use. Additionally, public inheritance would make the two classes object-type compatible, but you cannot use a sorted list anywhere that a list is used.
- 7. Private inheritance provides a reasonable alternative to containment as an approach to using the ADT list in the implementation of the ADT sorted list. Usually, however, containment is preferable.
