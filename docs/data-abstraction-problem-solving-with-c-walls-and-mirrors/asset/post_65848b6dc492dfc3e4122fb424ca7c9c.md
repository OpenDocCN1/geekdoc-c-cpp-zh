The nodes of a tree typically contain values. A binary search tree is a binary tree that is, in a sense, sorted according to the values in its nodes. For each node $n$, a binary search tree satisfies the following three properties:

- $n$'s value is less than all values in its right subtree $T_R$

## 15.1.2 The Height of Trees

Trees come in many shapes. For example, although the binary trees in Figure 15-5 all contain the same nodes, their structures are quite different. Each of these trees has seven nodes; some are “taller” than others. The height of a tree is the number of nodes on the longest path from the root to a leaf. For example, the trees in Figure 15-5 have heights of 3, 5, 7, and 7. Many people’s intuitive notion of height would lead them to say that these trees have heights of 2, 4, 6, and 6. Indeed, many authors define height to agree with this intuition. However, the definition of height used in this book leads to a clearer statement of many algorithms and properties of trees.

There are other equivalent ways to define the height of a tree. One way is using the following definition of the level of a node $n$:

- If $n$ is the root of $T$, its level is 1.
- If $n$ is not the root of $T$, its level is 1 greater than the level of its parent.

For example, in Figure 15-5, node A is at level 1, node B is at level 2, and node D is at level 3. The height of a tree $T$ in terms of its nodes is defined as follows:

- If $T$ is empty, its height is 0.
- If $T$ is not empty, its height is equal to the maximum level of its nodes.

By applying this definition to the trees in Figure 15-5, you will find that their heights are, respectively, 3, 5, and 7, as was stated earlier.

## 15.1.3 Full, Complete, and Balanced Binary Trees

In a **full binary tree** of height $h$, all nodes at a level less than $h$ have two children.
Figure 15-6 depicts a full binary tree of height 3. Each node in a full binary tree has left and right subtrees of the same height. Among binary trees of height $h$, a full binary tree has as many leaves as possible, and they are all at level $h$. Intuitively, a full binary tree has no missing nodes.

![](img/d0cb86b2f18b2db569968ad7c743510e_457_0.png)

When proving properties about binary trees—such as how many nodes they have—the following recursive definition of a full binary tree is convenient:

- If $T$ is empty, $T$ is a full binary tree of height 0.
- If $T$ is not empty and has height $h > 0$, $T$ is a full binary tree if its root's subtrees are all full binary trees of height $h-1$.

This definition closely reflects the recursive nature of a binary tree.
A **complete binary tree** of height $h$ is a binary tree that is full down to level $h-1$, with level $h$ filled in from left to right, as Figure 15-7 illustrates. More formally, a binary tree $T$ of height $h$ is complete if

A complete binary tree

1. All nodes at level $h-2$ and above have two children each, and
2. When a node at level $h-1$ has children, all nodes to its left are filled.

Parts 2 and 3 of this definition formalize the requirement that level $h$ be filled from left to right. Finally, a binary tree is balanced, or simply balanced, if the height of its left and right subtrees differs by no more than 1.

## Terminology

| Term | Definition |
| :--- | :--- |
| **Full binary tree** | A binary tree of height $h$ where all nodes at level less than $h$ have two children. |
| **Complete binary tree** | A binary tree of height $h$ that is full down to level $h-1$, with level $h$ filled in from left to right. |
| **Balanced binary tree** | A binary tree where the height of the left and right subtrees differ by at most 1. |
| **Height** | The number of nodes on the longest path from the root to a leaf. |
| **Level** | The root is level 1; the level of a node is 1 greater than the level of its parent. |
| **Ancestor** | Any node on the path from the root to that node. |
| **Descendant** | Any node in the subtree rooted at that node. |
| **Leaf** | A node with no children. |
| **Sibling** | Nodes that share the same parent. |

## 15.1.4 The Maximum and Minimum Heights of a Binary Tree

You can maximize the height of a binary tree with n nodes simply by giving each internal node (non-leaf) exactly one child, as shown earlier in parts c and d of Figure 15-5. This process will result in a tree of height n. The n-node tree with height n in Figure 15-5d resembles a chain of linked nodes.

> Note: The maximum height of an n-node tree is n.

A minimum-height binary tree with n nodes is a bit more difficult to obtain. As a first step, consider the nodes a binary tree with given height h can have. For example, if h = 3, the possible binary trees include those in Figure 15-8. Thus, binary trees of height 3 can have between three and seven nodes. In addition, Figure 15-8 shows that 3 is the minimum height for a binary tree with four, five, six, or seven nodes. Similarly, binary trees with more than seven nodes require a height greater than 3.

Intuitively to minimize the height of a binary tree given n nodes, you must fill each level of the tree as completely as possible. A complete tree meets this requirement, although it does not matter whether the nodes on the last level are filled from left to right. In fact, except for the tree in part a, the trees in Figure 15-8 are complete trees.
