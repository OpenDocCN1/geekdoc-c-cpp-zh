# LISTING C4-2 The class MagicBox, originally given in Listing C1-7

```
template<class ItemType>
class MagicBox : public PlainBox<ItemType>
private:
    bool firstItemStored;
public:
    MagicBox();
    MagicBox(const ItemType& item);
    void setItem(const ItemType& item);
}; // MagicBox
```

Adding a colon PlainBox after class MagicBox indicates that PlainBox is a base class of MagicBox, or equivalently, that MagicBox is a derived class of PlainBox.

An instance of the derived class has two members—one, which is inherited, and firstItemStored, which is new. Because an instance of a derived class can invoke any method of the base class, an instance of MagicBox has all the methods that PlainBox defines; constructors, a new, compiler-generated destructor, and a refined method setItem. Although an instance of a derived class contains copies of inherited member data, the code for inherited methods is not copied.

A derived class cannot access the private members of its base class by name, even though they are inherited. Inheritance does not imply access. After all, you can inherit a locked vault but be unable to open it. In example, the data item is private so you can reference it only within the definition of the class PlainBox and not within the definition of ToyBox or MagicBox. However, the class ToyBox can use PlainBox's public methods setItem and getItem to obtain the value of item.

Within the implementation of MagicBox, you can use the public methods that MagicBox inherits from PlainBox. For example, the refined method setItem calls the inherited version of the method setItem, which you indicate by writing PlainBox<ItemType>::setItem. This notation is necessary to differentiate between the two versions of the method. Thus, you can access a base member, even though it has been redefined, using the scope resolution operator ::. The implementation of MagicBox's setItem method is

```
template<class ItemType>
void MagicBox<ItemType>::setItem(const ItemType& item)
```
