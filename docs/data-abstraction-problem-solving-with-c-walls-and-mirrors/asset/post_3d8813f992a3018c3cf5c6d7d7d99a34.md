## 4.1 Preliminaries

Let consider components that can be linked to one another. Each component—usually called a node—contains both a data item and a "pointer" to the next item. Because each node must contain two pieces of information—the data item and the pointer to the next node—it is natural to conclude that each node should be an object. One member of the node is the data item and the other is a pointer. Typically, such pointers are C++ pointer variables.

Figure 4-1 illustrates a single node, and Figure 4-2 shows several nodes linked together. Here, the data portion of each node contains a string. We use arrows to represent the pointers, but what type of pointer should you use within a node, and to what it point? You might guess that the pointer should point to a string, but actually it must point to a node that contains the string. Because pointers can point to any data type except files—and nodes are objects—pointers can, in fact, point to nodes. If this value is nullptr, we can easily detect when we have reached the end of the linked nodes.

We have one more detail to consider: Nothing far points to the first node. If you cannot get to the first node, you cannot get to the second node; and if you get to the second node, you cannot get to the third; and so on. The solution is to have an additional pointer whose purpose is to point to the first of linked nodes. Such a pointer is called the head pointer or the head pointer of data structure.

Figure 4-3 illustrates a linked chain of nodes with a head pointer. Observe that the head pointer headPtr is different from the other pointers in the diagram that it is not within one of the nodes. The variable headPtr simply enables you to access the chain's beginning. What value should headPtr contain if there are no nodes for it to point to? Assigning headPtr the value nullptr is a logical choice in this case.

> Programming Tip: A value is a common mistake to think that before you can assign headPtr you must first create a new Node object. This misconception is rooted in the belief that the variable headPtr does not exist or does not point to a node. This is not at true; headPtr is a pointer waiting to be assigned a value. Thus, for example, you can use nullptr to headPtr without using new. In the sequence

```cpp
headPtr = new Node; // An incorrect use of new
headPtr = nullptr;
```

destroys the only pointer—headPtr—to the newly created node, as Figure 4-4 illustrates. Thus, you needlessly created a new node and then made it inaccessible. This action creates a memory leak in your program and should be avoided!

## 4.1.1 The Class Node

Before we continue, let's examine the C++ code for the class Node. Listing 4-1 gives the header file for the class. In addition to the data members item and next that we introduced earlier, the class declares three constructors, two accessor methods—one for item and next—and two mutator methods—again one for each item and next. Notice that with this class, a pointer to a node has the data type Node<ItemType>

```cpp
// LISTING 4-1 The header file for the template Class Node
/** @file Node.h */
#ifndef NODE_NODE
#define NODE_NODE
template<class ItemType>
class Node {
private:
    ItemType item; // A data item
    Node<ItemType>* next; // Pointer to next node
public:
    Node();
    Node(const ItemType& item);
    Node(const ItemType& item, Node<ItemType>* nextNodePtr);
    void setItem(const ItemType& item);
    void setNext(Node<ItemType>* nextNodePtr);
    ItemType* getItem() const;
    Node<ItemType>* getNext() const;
}; // end Node
#include "Node.cpp"
#endif
```

Listing 4-2 shows the implementation file for Node.

```cpp
// LISTING 4-2 The implementation file for the class Node
/** @file Node.cpp */

#include <cstddef>
```

template<class ItemType>
Node<ItemType>::Node() : next(nullptr)

    return next;
}

## 4.2 A Link-Based Implementation of the ADT Bag

Unlike array-based implementations, a link-based implementation does not impose a fixed size on the data structure—except, of course, imposed by the storage limits of the system. Additionally, data items do not move during an ADT’s insertion and removal operations.
