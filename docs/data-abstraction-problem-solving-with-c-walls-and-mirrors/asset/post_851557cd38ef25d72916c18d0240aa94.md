## 19.3.3 Removing Data from a 2-3-4 Tree

The removal algorithm for a 2-3-4 tree has the same beginning as the removal algorithm for a 2-3 tree. You first locate the node n that contains the item I that you want to remove. Then find I's inorder successor and swap it with I so the removal will always be at a leaf. If leaf is either a 3-node or a 4-node, you simply remove it. If you can ensure that I does not occur in a 2-node, you can perform the removal in one pass through the root to leaf, unlike removal from a 2-3 tree. That is, you will not have to back away from the leaf and restructure the tree.

In fact, you can guarantee that I does not occur in a 2-node by transforming each node you encounter during the search for I into a 3-node or a 4-node. Several cases are possible, depending on the configuration of the 2-node's parent and its nearest sibling. (Arbitrarily, node's nearest sibling is its left sibling, unless it is left child, in which case its nearest sibling is to the right.) That is, if the parent or sibling could be a 2-node, a 3-node, or a 4-node. For example, if the next node that you encounter is both and its sibling 2-nodes, apply the transformation that Figure 19-28 illustrates, but in reverse; if the parent or sibling is a 3-node, apply the transformation that Figure 19-29 illustrates, but in reverse; if the parent or sibling is a 4-node, apply the transformation that Figure 19-30 illustrates, but in reverse.
