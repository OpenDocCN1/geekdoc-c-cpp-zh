
## Recursion That Returns Value

The factorial of a negative integer is undefined. You should have no trouble writing an iterative function based on this.

To define factorial(n) recursively, you first need to define factorial(n) in terms of factorial of a smaller number. To do so, observe that the factorial of n is equal to the factorial of (n - 1) multiplied by n; that is,

```
factorial(n) = n × [(n - 1) × (n - 2) × ... × 1]
n = n × factorial(n - 1)
```

The definition of factorial(n) in terms of factorial(n - 1) is an example of a recurrence relation. This implies that you can also define factorial(n - 1) in terms of factorial(n - 2), and so on. This process is analogous to the dictionary search, in which you search a dictionary by searching a smaller dictionary in exactly the same way.

The definition of factorial(n) lacks one key element: the base case. As done in the dictionary search however, you must define one case differently from all the others, or else the recursion will never stop. The base case for factorial is factorial(0), which you know is 1. Because n decreases or factorial decrements by 1, you will always reach the base case. With the addition of the base case, the complete recursive definition of the factorial is

```
factorial(n) = {1 if n = 0
n × factorial(n - 1) if n > 0}
```

To be sure that you understand this recursive definition, apply it to the computation of factorial(4). Because 4>0, the recursive definition states

```
factorial(4) = 4 × factorial(3)
```

Similarly,

```
factorial(3) = 3 × factorial(2)
factorial(2) = 2 × factorial(1)
factorial(1) = 1 × factorial(0)
```

You have reached the base case, and the definition directly states

```
factorial(0) = 1
```

At this point, the application of the recursive definition stops and you still do not know the answer: What is factorial(4)? However, the information to answer this question is available:

```
factorial(0) = 1, factorial(1) = 1 × 1 = 1
factorial(1) = 1, factorial(2) = 2 × 1 = 2
factorial(2) = 2, factorial(3) = 3 × 2 = 6
factorial(3) = 6, factorial(4) = 4 × 6 = 24
```

You can think of recursion as a process that divides a problem into a task you can do and a task that a friend can do for you. For example if you compute factorial(4) your friend uses the same process to compute factorial(3) as you are using factorial(4). Your friend determines that factorial(3) is not the base case, and asks another friend to compute factorial(2). Knowing factorial(2) enables your friend to compute factorial(3), and when you learn the value of factorial(3) from your friend, you can compute factorial(4).

Notice the recursive definition of factorial(4) yields the same result as the iterative definition. To prove that the two definitions of factorial are equivalent for all nonnegative integers, you would use mathematical induction. Example gives 4 × 3 × 2 × 1 = 24. (See Appendix E.) Chapter 5 discusses the ties between recursion and mathematical induction.

The recursive definition of the factorial function illustrated two points:
- Intuitively, you can define factorial(n) in terms of factorial(n - 1).
- Mechanically, you can apply the definition to determine the value of factorial. In this simple example, the recursive definition required quite a bit of work. That, of course, is where the computer comes in.

Once you have a recursive definition of factorial(n), it is easy to construct a C++ function that implements it:

```cpp
/**
 * computes the factorial of the nonnegative integer n.
 * @pre n must be greater or equal to 0.
 * @post None.
 * @return The factorial of n; unchanged. */
int fact(int n) {
    if (n == 0)
        return 1;
    else // n > 0, so n-1 >= 0. Thus, fact(n-1) returns (n-1)
        return n * fact(n - 1); // n * (n-1)! is n!
} // end fact
```

This fits the model of a recursive function given earlier in this chapter as:
- One action of fact is to call itself.
- At each recursive call, the integer you need to compute is diminished by 1.
- The function handles the factorial of 0 differently from all the other: It does not generate a recursive call. Rather, you know that fact(0) is 1. Thus, the base case occurs when n is 0.
- Given that n is nonnegative, this assures that you will always reach the base case.

Note: A recursive algorithm has a base case, which you know directly without making any recursive calls. Without a base case, a recursive function will generate an infinite sequence of calls.

The function reacts as its precondition. At the time of the recursive call fact(n-1), n is positive, so the recursive call satisfies fact's precondition, you can expect that fact(n-1) will return the factorial of n. Therefore, fact(n-1) is the factorial of n. Chapter 5 uses mathematical induction to prove that fact(n) returns the factorial of n.

If you violated fact precondition, the function would not behave correctly. That is, if the caller passed a negative value an infinite sequence of recursive calls—terminated only by a system-defined limit—would occur, and the function would never reach the base case. For example, fact(-4) would call fact(-6), and so on. The function should ideally test itself by testing for negative n. If n < 0, the function could crash, return 0 or set an error flag. Appendix B discusses error checking in Sections B.2 “Style” and B.5 “Full-Safe Programming”; you might want to review that discussion at this time.

At an intuitive level, it should be clear that the function implements the recursive definition of factorial. Now consider the mechanisms of executing this recursive function. The logic is straightforward, except for perhaps in the else case. This recursion can be explained as:

Violating fact precondition causes “infinite” recursion:
- Each operand of the product n * fact(n-1) is evaluated.
- The second operand—fact(n-1)—is a call to fact. Although this is a recursive call (the function fact calls the function fact), there is nothing special about it. Imagine substituting a call to another function—the standard function abs, for example—for the recursive call to fact. The principle is the same: Evaluate the function.

In theory, evaluating a recursive function is no more difficult than evaluating a nonparametric function. However, manual bookkeeping can quickly get out of hand. The next section introduces a systematic way to trace the actions of a recursive function. For a computer, the bookkeeping is simple but can use more memory than is allocated for such a task.

Question1 The function computes the sum of the first n ≥ 1 integers. How this function satisfies the properties of a recursive function.

```cpp
/// computes the sum of the integers from 1 through n.
@pre n > 0.
@post None.
@param n positive integer.
@return the sum 1 + 2 + . . + n /
```

```cpp
int sumUpTo(int n)
{
    int sum = 0;
    if (n == 0)
        sum = 1;
    else
        sum = n + sumUpTo(n - 1);

    return sum;
} // end sumUpTo
```
