If the height of the binary search tree is $log(n+1)$, the efficiency of its operations is $O(\log n)$. However, what will the height of a binary search tree actually be? The factor that determines the height of a binary search tree is the order in which you perform insertion and removal operations on the tree. Recall that starting with an empty tree, if you insert names in the order Alan, Bob, Eliza, Nancy, Tom, Wendy, you would obtain a binary search tree of maximum height as shown in Figure 15-14b. On the other hand, if you insert names in the order Bob, Tom, Alan, Eliza, Nancy, Wendy, you would obtain a binary search tree of minimum height, as shown in Figure 15-13.

Which of these should you expect to encounter in the course of a real application? It can be proven mathematically that if insertion and removal operations occur in a random order, the height of the binary search tree will be close to $log n$. Thus, in this sense, the previous analysis is not unduly optimistic. However, in a real-world application, is it realistic to expect insertion and removal operations in random order? In many applications, the answer is yes. There are applications where this assumption is dubious. For example, the person preparing the previous sequence of names for the insertion operations might decide to "help you" by arranging the names to be inserted into sorted order. This arrangement, as mentioned, would lead to a tree of maximum height. In many applications you can expect the behavior of a binary search tree to be excellent, you should be wary of the possibility of poor performance due to some characteristics of a given application.

Are you worried that operations might not occur in a random order? Similarly, is there anything if you have an enormous number of items and need to ensure that the height of the tree is close to $log n$?
