Finally, we will define the method peekTop, if it must throw an exception if the heap is empty.
Although you might intend to simply return items[0], it always contains the top of the heap, if you do, peekTop will return a value when the heap might be empty. Thus, you need to write peekTop for an empty heap, in the following definition:

```
template<class ItemType>
ItemType ArrayHeap<ItemType>::peekTop() const throw (PreconditionViolatedException)
{
    if (isEmpty())
        throw PreconditionViolatedException("Attempted peek into an empty heap.");
    return items[0];
} // end peekTop
```

# 17.3 Heap Implementation of the ADT Priority Queue

Section 13.3 of Chapter 13 introduced the ADT priority queue, and Section 14.2 of Chapter 14 offered an implementation based on a sorted list. At that time, we mentioned that using a heap to define a priority queue results in a more time-efficient implementation.
Once you have implemented the ADT, the implementation of the ADT priority queue is straightforward, because priority queues are exactly analogous to heaps. The priority value in a priority queue corresponds to an item in a heap. Thus, the implementation of a priority queue can use ArrayMaxHeap. To do so, use an instance of ArrayMaxHeap as a data member of the priority queue class, or use inheritance. Although a heap provides an excellent implementation of a priority queue, a priority queue is not a heap. Since is-a-relationship does not exist between ArrayMaxHeap and the class of priority queues, public inheritance is not appropriate. But we can use private inheritance, and that is what we will do. Let's assume that we have an interface for the ADT priority queue, as Exercise 8 in Chapter 13 asked you to write, so that we can derive our new class from it.
