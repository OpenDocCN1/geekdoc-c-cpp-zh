Will you ever to evaluate an infix expression? Certainly—you have written expressions in programs. The compiler that translated your programs had to generate machine instructions to evaluate the expressions. To do so, the compiler transformed each infix expression into postfix form. Knowing how to convert an expression from infix to postfix notation will not only lead to an algorithm to evaluate expressions, but also give you some insight into the compilation process.

If you manually convert a few expressions to postfix form, you will discover three important factors:

+   * The operands always stays in the same state with respect to one another.
* An operator will only "to the right" with respect to the operands; if, in the infix expression the operand precedes the operator op, it is also true that in the postfix expression the operand precedes the operator op.

+   * All parentheses are reserved.

As a consequence of these three factors, the primary task of the conversion algorithm is determining where to place each operator.

The following pseudocode describes a first attempt at converting an infix expression to an equivalent expression postfixExp:

```
Initialize postfixExp to the empty string
{
  switch (ch) {
    case ch is an operand:
      Append ch to the end of postfixExp
      break
    case ch is an operator:
      Save ch until you know to place it
      break
    case ch is '(' or ')':
      Discard ch
      break
  }
}
```
