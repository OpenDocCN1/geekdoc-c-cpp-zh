# 16.3 A Link-Based Implementation of the ADT Binary Search Tree

Also keep in mind that the data items in the binary search tree are unique.

The method creates a new node and passes pointers to the tree and the new node to a recursive method that actually performs the insertion. The following high-level pseudocode describes this insertion process:

First draft of the insertion algorithm

```
// Inserts a new node into a binary search tree.
insertInOrder(subtreePtr, BinaryNodePointer,
    newNodePtr, BinaryNodePointer): BinaryNodePointer

    Search the pointed to by subtreePtr for the item in the node pointed
    if (the search terminates at parent's left subtree)
        SetLeftChildPtr of parentNode to newNodePtr
    else
        SetRightChildPtr of parentNode to newNodePtr
```

The appropriate pointer—leftChildPtr or rightChildPtr—of node parentNode must be set to the new node. The recursive nature of the search algorithm provides an elegant means of setting the pointer, provided that you return this possibly changed pointer. The situation is quite similar to the insertion method for the AD list we saw in Chapter 9. If the tree was empty before insertion, the external pointer to the root of the tree would be nullptr and would not make a recursive call. Thus, you would return a pointer to the new node. First draft of the removal algorithm **Removing an entry.** Removing an entry from a binary search tree is a bit more involved than adding one. First, you use the search algorithm to locate the item and then, if it is found, you must remove it from the tree. A first draft of the algorithm follows:

```
// Removing the target from a binary search tree.
// Returns true if the removal is successful or false otherwise.
removeValue(target: ItemType): boolean {
  Locate the target by using the search algorithm
  if (target is found) {
    return true
  } else {
    return false
  }
}
```

The essential task is to remove the target from the tree. Assuming that removeValue locates the target in a particular node N, there are three cases to consider:

- N is a leaf
- N has only one child
- N has two children

Three cases for the node N containing the item to be removed
Case 1: Set the pointer in the left's parent to null
Case 2: Two possibilities for a node with one child
Let's parent adopt N's child

Case 1. The first is easiest. To remove the leaf containing the target, you only set the pointer in its parent to nullptr.
Case 2. The second case is a bit more involved. If N has only one child, you have two possibilities:

- N has a left child
- N has a right child

The two possibilities are symmetrical, so it is sufficient to illustrate the solution for a left child. In Figure 16a, L is the left child of N and P can be either the left or right child of P. Suppose let L take the leaf of N as one of P's children, as in Figure 16b. This adoption preserves the binary search property.
If N is the left child of P, all items in the subtree rooted at N are less than P. Therefore, after N is removed and L is adopted by P, all items in P's left subtree are still less than the item in P. If N is a right child of P, and therefore the binary search property is preserved in case.

Case 3. The most difficult of the three cases occurs when the item to be removed in node N has two children, however, when N has two children, the child replaces N: N's parent has room for only one of N's children as a replacement. A different strategy is necessary.
In fact, you not delete N at all. You can find another node that is easier to delete and delete instead of N. This strategy may sound like cheating, but the clients only need an entry to be removed from the ADT. It is right, because of the wall between the program and the ADT implementation, to specify a particular N in the tree to be deleted.

Consider, an alternative strategy. To remove from a binary search tree item that resides in a node N that has two children, take the following steps:

- 1. Locate another node M that is easier to remove from the tree than the node N.
2. Copy the item that is in M to N, effectively removing the item originally in N.
3. Remove the node M from the tree.
