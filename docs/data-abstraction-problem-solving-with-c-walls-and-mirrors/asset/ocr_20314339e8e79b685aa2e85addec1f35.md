An object may also send messages to itself, as is done in the generateReceipt and count messages in Figure C-1. Notice the piggybacked activation bars, which indicate that the Bank class is calling its own member methods.

A sequence diagram can also show the creation of a new object. In Figure C-2, a new account is created. This diagram can represent a part of an alternate scenario in a use case, in which a customer comes into the bank but not yet have an account. In the UML, the notation <<create>> is what is known as a stereotype. Stereotypes use left and right guillemets << and >> when drawing a sequence diagram you can simply label the message arrow with create. A stereotype is used to identify a unique characteristic of an element in a UML diagram.

The UML sequence diagram is a design document that gives guidance on several levels to the programmer implementing a solution. It gives a view of how the objects will dynamically interact (collaborate) to solve a use scenario. In particular, a sequence diagram shows

+   * Which objects collaborate to solve a particular use-case scenario
* The synchronous nature of the messages that are passed between objects in the scenario, providing the order in which tasks are accomplished
* Which object is responsible for what task or tasks by handling a particular message

> Note: UML sequence diagrams
* Provide a visual representation of the flow of messages between objects in the scenario
* Indicate the responsibilities of an object
* Indicate the collaborations among objects

# C.3 UML Class Diagrams

The last element we will introduce is the UML class diagram, or static diagram. The class diagram shows the attributes and operations of an individual class and how multiple classes are related to one another. These elements do not change after they have been created within a solution—that is, they are static, or unchanging.

The class diagram shown in Figure C-3 represents a class of banks. Each diagram consists of a square-rectangle box containing the name of the class within its borders. Figure C-3a shows the simplest of class diagrams: a class with a name but no attributes or operations. Figure C-3b shows the bank's attributes in the middle section and operations in the bottom section. If a class has no attributes, in Figure C-3c, an empty middle section must be present.
