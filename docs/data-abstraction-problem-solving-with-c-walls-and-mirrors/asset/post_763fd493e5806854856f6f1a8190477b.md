## 4.2.1 The Header File

The header file in Linking 4-3 declares the class LinkedBag. The private data members are headPtr, which points to the first node in the linked chain that contains the items in the bag, and itemCount, which counts these items. The private section of class also declares a private method, constructor whose purpose is declared shortly. The public section declares a default constructor, a copy constructor whose purpose is discussed near the end of Section 4.2.2—a destructor, and the public methods declarations are identical to those in class ArrayBag given in Chapter 3. As you will see, the compiler-generated constructor and destructor are not sufficient for linked-list implementations.

Recall from C++ Interface 2 that destructors should be virtual. We have tagged LinkedBag's destructor with the keyword virtual in the header file. Failure to do so will result in a warning from the compiler.

## 4.2.2 Defining the Core Methods

Just as we did when defining an array-based implementation of the ADT bag in Chapter 3, we begin our new implementation by defining the same core methods: the constructor, add, toVector, getCurrentSize, and isEmpty. We will use stubs for the remaining methods, including the constructor and destructor.

The constructor. The following default constructor initializes the head pointer and the current number of items in the bag:

```cpp
template<class ItemType>
LinkedBag<ItemType>() : headPtr(nullptr), itemCount(0)
{
}// end default constructor
```

The add method. A bag does not order entries, so the method can insert a new item at any convenient location within the linked chain of nodes that contains the bag's entries. The most convenient place for us to make this insertion is at the beginning of the chain, because the first node is the only one we can access directly. Figure 4-6 illustrates how we add a new node to the beginning of an existing chain of nodes.

You must make headPtr point to the new node, and the new node point to the node that had been at the beginning of the chain. Note how the following definition accomplishes this:

```cpp
template<class ItemType>
bool LinkedBag<ItemType>::add(const ItemType& newEntry)
{
  // Add to beginning of chain: new node references rest of chain;
  // (headPtr is nullPtr if chain is empty)
  Node::ItemType* newNodePtr = new Node<ItemType>();
  newNodePtr->setItem(newEntry);
  newNodePtr->setNext(headPtr); // New node points to chain
  headPtr = newNodePtr;        // New node is now first node
  itemCount++;

  return true;
} // end end
```

The method vector. Recall that the method vector retrieves the items that are in a bag and returns them to the client within a vector. A loop within vector adds the bag's entries to this vector. In array-implementation, this simply accesses an array of these entries. Here we must retrieve the items from the nodes in a chain. To do that, we must move from node to node; that is, we must traverse the chain. As we visit each node, we copy its data into the vector.

A traversal operation visits each node in the linked chain.

Let's write some high-level pseudocode for this loop, given the linked chain pictured in Figure 4-5.

```
Let a current pointer point to the first node in the chain
while (the current pointer is not the null pointer)
{
  Assign the data portion of the current node to the next element in a vector
  Set the current pointer to the next pointer of the current node
}
```

This solution requires you to keep track of the current position within the chain. Thus, you need a pointer variable—let's call it curPtr—that points to the current node.

> Note: The pointer variable curPtr is analogous to the integer variable curIndex that we used in 3.2.4 of Chapter 3 to keep track of the current entry in an array.

Initially, curPtr must point to the first node. Because headPtr points to the first node, simply copy headPtr into curPtr by writing

```cpp
NodeItemType* curPtr = headPtr;
```

Then you can use the expression curPtr->getItem() to access the data of the current node. After copying the data into the vector, you advance the current pointer to the next node by writing

```cpp
curPtr = curPtr->getNext();
```

Figure 4-7 illustrates this action. If the previous assignment statement is not clear, consider

```cpp
NodeItemType* temp = curPtr->getNext();
curPtr = temp;
```

and then convince yourself that the intermediate variable temp is not necessary.
