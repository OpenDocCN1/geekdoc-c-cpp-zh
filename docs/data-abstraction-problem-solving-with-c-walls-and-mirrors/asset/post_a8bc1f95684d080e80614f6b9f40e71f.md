## 5.1.1 Overloading = for Assignment

Overloading the assignment operator = is similar to overloading the equality operator, but it presents additional concerns. Once again, suppose that myList and yourList are instances of Linkedlist. If you place several items in your list and then write

- `myList = yourList;`

you would expect myList to be an exact copy of your list. Without an overloaded assignment operator, however, you would get a shallow copy of your list as shown in Figure 4-8 in Chapter 4 illustrates. Although a shallow copy might be sufficient for statically allocated structure, a deep copy is necessary for a dynamically allocated one like the chain of linked nodes in the linked-based implementation Linkedlist. A shallow copy of a LinkedList object—yourList—would only copy the data members itemCount (the length of the list) and headPtr (the pointer to yourList's first item). The items in the list would not be copied.

To provide an assignment operator for the class LinkedList, you would add the declaration
`LinkedList<ItemType>& operator=(const LinkedList<ItemType>&rightHandSide);`
to the class definition in LinkedList's header file. The argument rightHandSide represents the object to be copied—that is, the object will appear on the right-hand side of the assignment operator. The method is not void, but returns a value to accommodate such as

```
myList = yourList = thisList
```

As you see, the method returns a reference to the invoking object.
Implementing this method, you must deal with a few subtleties. Suppose that myList and yourList each contains several items. If you

```cpp
myList = yourList;
```

what happens to the items that were in yourList? You might not care, as long as myList ultimately contains a copy of the items in yourList. You should care, however, if you have a link-based list. Before you can copy the items in yourList, you need to deallocate the nodes in myList. Failure to do so results in a memory leak—that is, memory that was not returned to the system. Thus, the assignment of your myList must take these steps:

```text
Deallocate memory assigned to myList
(for each item in yourList)
{
    Allocate a new node for myList
    Set the node's data to a copy of the item in yourList
}
```

The tasks here are like that you implemented when you wrote the destructor and copy constructor for LinkedList. To deallocate memory currently used by LinkedList nodes, you can call clear. When using the underlying chain of nodes, you can avoid redundancy by defining a private or protected method, copyNodes, that both copy constructor and the assignment operator can call.
Now you suppose

```cpp
myList = myList;
```

Notice what our pseudocode tells you to do: Deallocate myList and then make a copy of myList. After you have deallocated myList, there is nothing to copy! Your implementation should test for this by asking whether the object on the left side of the = operator is the same as the object on the right. If it is, your assignment operator should do nothing—it should be fail-safe.

You can make this test by comparing the addresses of the two list objects by comparing the items on the lists. In C++, this is a pointer to the invoking object. Thus, you

```cpp
if (this != &rightHandSide)
```

In this textbook, this is only done when it is necessary to use the & symbol as the "address of" operator.

## 5.1.2 Overloading + for Concatenation

As discussed in the previous section, the operator + is used for both integer and floating-point addition. In C++, + is also used as a concatenator to append strings. This ability illustrates one of the concerns some programmers have about overloading operators—a symbol can represent several different operations. Suppose you want to maintain code else went wrote and find the following statement in a method:

```cpp
theThing = myThing + yourThing;
```

Can you quickly determine whether the + performs scalar addition—adding two integers or floating points—or concatenates two strings? Without knowing the data type of the variables myThing and yourThing, you cannot determine what operation performs. In a well-written program, most variables are declared close to their, thus helping to clarify the symbol, but this is not always the case.
When you choose to overload an operator, you should not change the meaning of the symbol. Your definition should extend the current operation for use with a new data type—when working with lists, the concatenation definition of the + symbol applies better than scalar addition, so let's see what is involved in appending one list onto another.

Link-based lists. If we choose to overload the + for the list-based implementation of the ADT list, we would add the following declaration to the class definition:

```cpp

operator+(const LinkedList<ItemType>& rightHandSide) const;
```
