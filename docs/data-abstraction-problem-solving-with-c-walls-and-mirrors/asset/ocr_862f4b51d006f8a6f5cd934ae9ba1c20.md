You should always place a class data members within its private section. Typically, you provide methods—such as setRadius and getRadius—to access the data members. In this way, you control how and whether the rest of the program can access the data members. This design principle should lead to programs that are not easy to debug, but also have fewer logical errors from the beginning. Some method declarations, such as

```
double getRadius() const;
```

are tagged with const. Such methods cannot alter the data members of the class. Making getRadius a const method is a fail-safe technique that ensures it will return the current value of the sphere's radius, without changing it.

Let's begin implementing the class Sphere by examining its constructors.

**Constructors.** A class constructor allocates memory for an object and can initialize the object's data to particular values. A class can have more than one constructor, as is the case for the class Sphere. The first constructor in Sphere is the **default constructor:**

A default
constructor has no
arguments

```
Sphere();
```

A default constructor by definition has no arguments. Typically, a default constructor initializes data members to values that the class implementation chooses. For example, the implementation

```
Sphere{
    theRadius = 1.0;
} // end default constructor
```

sets theRadius to 1.0. Chapter 3 will show you how to initialize data members within constructors that is preferable to using assignment statements.
Notice the qualifier Sphere:: that precedes the constructor's name. When you implement any method, qualify its name with its class type by the **scope resolution operator** :: to distinguish it from other methods that have the same name.

When you declare an instance of the class, you implicitly invoke a constructor. For example,
Sphere unitSphere;

invokes the default constructor, which creates the unit Sphere and sets its radius to 1.0. Notice that you do not include parentheses after unitSphere.
