**Double hashing.** Double hashing is yet another open-addressing scheme, drastically reduces clustering. The probe sequences that both linear and quadratic probing use are key independent. For example, linear probing inspects the locations in the hash table sequentially no matter what the hash key is. In contrast, double hashing defines key-dependent probe sequences. In this scheme the probe searches the hash table in a linear order, starting at the location $h_1(key)$, but a second hash $h_2(key)$ determines the size of the steps taken.

Although you choose $h_1$ as usual, you must follow these guidelines for $h_2$:

+   $h_1(key) \neq 0$
nh_2 \neq 1$

Clearly, you need a nonzero size $h_2(key)$ to define the probe sequence. In addition, $h_2$ must differ from $h_1$ to avoid clustering.

For example, let $h_1$ and $h_2$ be the primary and secondary hash functions defined

+   $h_1(key) = key \pmod{11}$
nh_2(key) = (key-7) \pmod{7}

where a hash table of 11 items is assumed, so that you can readily see the effect of these functions on the hash table. If $key=58$, $h_1$ keys to dictionary 3 (5-8 mod 11), and $h_2$ indicates that the probe sequence takes steps of size 5 (7-5 mod 7). In other words, the probe sequence will be 3, 8, 2 (wraps), 7, 1 (wraps), 6, 0, 5, 10, 4, 9. On the other hand, if $key=14$, $h_1$ keys to table location 3 (14 mod 11), and $h_2$ indicates that the probe sequence should take steps of size 7 (7-14 mod 7), so the probe sequence will be 3, 10, 6, 2, 9, 5, 1, 8, 4, 0.

Each of these sequences visits all the locations. This phenomenon always occurs if the size of the hash table and the size of the probe sequence are relatively prime, that their greatest divisor is 1. Because the size of a hash table is commonly a prime number, it will be relatively prime to all step sizes.

Figure 18-13 illustrates the insertion of 58, 14, and 91 into an empty hash table. Because $h_1(58)$ is 3, you insert into table[3]. You find that $h_1(14)$ is also 3, so avoid a collision, you step by $h_2(14)=7$ and place into table[3+7], or table[10]. Finally, $h_1(91)$ is 3 and $h_2(91)$ is 7.
