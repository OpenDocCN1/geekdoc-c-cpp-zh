## 3.1.2 Using Fixed-Size Arrays

When implementing an ADT that represents a data collection, you store the data items and track their number. In an array-based implementation, you store the items in an array. How much of the array will items occupy? Possibly all of it, but this is not likely. Then, you need to keep track of the array elements that have been assigned to the container and those that are available for use in the future. The maximum length of the array—its physical size—is known, a fixed value such as MAX_SIZE. You can keep track of the current number of items in the collection—that is, the collection's logical size—in an array. An obvious benefit of this approach is that implementing an operation that reports this value will be easy.

When you add an entry to an array, you typically place it in the array's first element—that is, the element index is 0. Doing so is not a requirement, especially for arrays that implement containers. For example, some implementations can ignore the array element index is 0 and use index 1 as the first element in an array. Sometimes you might want to use the entries at the end of the array before one at its beginning. For the ADT bag, we have no reason to be typical, so the objects in a bag begin at index 0 of the array. Requiring the method to place objects into an array consecutively is certainly reasonable, but why should we care? It is a concern, and this is really a concern! We need to establish certain truths, or assertions, so our planned implementation that the action of the method has not been detrimental to other methods. For example, the vector must “know” where it has placed the entries. We also need to define what must happen later when we remove an entry from the container. If we insist that the bag entries occupy consecutive array elements, the method must ensure that they remain stable.

What happens after add places a new entry into the last available array element? A subsequent addition will be impossible unless an entry is removed from the last array. An add method will return a boolean value to indicate whether it was successful. In C++ Interlude 2, which follows this chapter, you will learn how to resize the array. Rather than returning a value, a method can signal it by throwing an exception. C++ Interlude 3 will discuss this approach.

### 3.2.1 The Header File

Having chosen the data members, knowing the details of BagInterface, which we developed in Chapter 1, we can write the header file shown in Listing 3-1 for our class bags. We name the class ArrayBag and give it a default constructor, which is sufficient for this example. Notice the small value given to the constant DEFAULT_CAPACITY. It enables us to fill a bag completely. After Interlude 2, we will be able to add another constructor that enables the client to set the capacity of the bag during program execution. We include the field maxItems in anticipation of this enhancement.
Also notice that we declare a private method indexOf. This method returns the index of the element within the array that contains a given entry. As you will see, we can use indexOf to make the methods.

```
/* LISTING 3-1 The header file for the class ArrayBag
 * Header file for array-based implementation of the ADT bag. */

#ifndef ARRAY_BAG
#define ARRAY_BAG

#include "BagInterface.h"

class ArrayBag : public BagInterface<Item>
{
private:
    static const int DEFAULT_CAPACITY = 50;
    Item items[DEFAULT_CAPACITY]; // Array of bag items
    int itemCount; // Current count of bag items
    int maxItems; // Max capacity of the bag

    int indexOf(const Item& target) const;

public:
    ArrayBag();
    int getSize() const;
    bool isEmpty() const;
    bool add(const Item& newEntry);
    bool remove(const Item& anEntry);
    void clear();
    int getFrequency(const Item& ofEntry) const;
    bool contains(const Item& anEntry) const;
    vector<Item> toVector() const;
};

#endif
```

> **Programming Tip:** When a class has several data members, the constructor initializes them in the order in which they appear in the class definition instead of the order in which the initializers appear in the constructor. You should use the same order in both cases to avoid confusion.

**The add method.** To add a new item to a bag that is not full, we can place it right after the last item in the array by writing the following statement:

```
items[itemCount] = newEntry;
```

If we are adding to an empty bag, itemCount will be zero, and the assignment will be to items[0]. If the bag contains one entry, an additional entry will be assigned to items[1], and so on. In this way, no other items in the array need to move. After each addition, we increase the counter itemCount. Figure 3-3 depicts this insertion. If add succeeds, it returns true. Otherwise—if the bag is full, it returns false, as you can see from its definition:

```cpp
template<class Item>
bool ArrayBag<Item>::add(const Item& newEntry)
{
  bool hasRoomToAdd = (itemCount < maxItems);
  if (hasRoomToAdd) {
    items[itemCount] = newEntry;
    itemCount++;
  }
  return hasRoomToAdd;
}
```

> Note: The entries in a bag have no particular order. Thus, the add method can place a new entry into any convenient element of the array items. In the previous definition of add, that element is the one immediately after the last element used.
