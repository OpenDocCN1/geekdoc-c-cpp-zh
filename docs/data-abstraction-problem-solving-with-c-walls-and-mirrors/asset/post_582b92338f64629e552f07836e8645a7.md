
## CHAPTER 6 Stacks

Our study of data management has three goals. The first is to identify useful sets of operations—that is, to abstract data types. The second goal is to examine applications that use abstract data types. The third goal is to construct implementations for the abstract data types—that is, to develop data structures and classes. As you will discover, the nature of the operations of an abstract data type, along with the application in which you will use it, influences the choice of its implementation.

The ADT badge discussed in Chapter 1 does not organize its data. However, you can organize either by position or by value. In general, these organizations are appropriate for applications of different natures. For example, if an application needs to ask a question about the first person in a line, you should organize the data by position. On the other hand, if an application needs to ask a question about the employee named Smith, you should organize the data by value. Throughout the rest of this book, you will see several ADTs that use these two organizations.

### 6.1.1 Developing an ADT During the Design of the Solution

When you type a line of text on a keyboard, you are likely to make mistakes. If you use the Backspace key to correct these mistakes, each backspace erases the previous character. Consecutive backspaces are applied in sequence and erase several characters. For instance, if you type the line

`abcabcd←cfg`

← represents the backspace character, the corrected input would be

`abcd`

How can a program read the original line and get the correct input? In designing a solution problem, you must eventually decide how to store the input line. In accordance with the ADT approach, you should postpone this decision until you have a better idea of what operations you will need to perform on the data.

A first attempt at a solution leads to the following pseudocode:

```cpp
// Read the line, correcting mistakes along the way
while (not end of line)
  Read a new character ch
  if (ch is not '←')
    Add ch to the ADT
  else
    Remove from the ADT (discard) the item that was added most recently
```

Initial draft of a solution

This solution calls attention to two of the operations the ADT will have to include:

- Add a new item to the ADT.
- Remove from the ADT the item that was added most recently.

Notice that potential trouble occurs if you type a $\leftarrow$ when the ADT is empty—that is, when the ADT contains no characters. If this situation should occur, you have three options: (1) the program terminate and write an error message, (2) throw an exception, or (3) have the program ignore the $\leftarrow$ and continue. Any of these options is reasonable, so let's suppose that you decide to ignore the $\leftarrow$ and continue. Therefore, the algorithm

```cpp
// Read the line, correcting mistakes along the way
while (not end of line)
{
  Read a new character ch
  if (ch is not a '←')
    Add ch to the ADT
  else if (the ADT is not empty)
    Remove from the ADT the item that was added most recently
  else
    Ignore the '←'
}
```

The "read and correct" algorithm

```cpp
// Display the line
while (the ADT is not empty)
{
```

A false start at writing the line

This pseudocode is incorrect for two reasons:

- When you remove an item from the ADT, the item is gone, so you cannot display it. What you should have done to look at the item that was added to the ADT most recently. An accessor operation returns an item—allowing you to look at it—but does not change the ADT's data. After getting and displaying the item you remove it from the ADT.
- The last character of the input line is the most recently added to the ADT. You certainly do not want to write it. The resolution of this particular difficulty is left to you as an exercise.

Reasons why the attempted solution is incorrect

The while-backward algorithm

```cpp
// Display the line in reverse order
while (the ADT is not empty)
{
  Get the item that was added to the ADT most recently and assign it to ch
  Display ch
  Remove from the ADT the item that was added most recently
}
```

### 6.1.2 Specifications for the ADT

Although you have yet to think about an implementation of, you know that you must be able to perform four specific operations. These operations define the required stack:

- See whether a is empty.
- Add a new item to the stack.
- Remove the item from the stack that was added most recently.
- Get the item that was added to the stack most recently.

The term "stack" is intended to conjure visions of things encountered in daily life, such as a stack of plates in the cafeteria, a stack of books on your desk, or a stack of assignments that you need to work on. In common usage, "stack of" and "pile of" are synonymous. To computer scientists, however, a stack is not just any pile. The property that the last added to the stack will be the first removed is commonly referred to as last, first out or simply LIFO.

LIFO: The last item inserted onto a stack is the first one out

A stack of plates in a cafeteria makes a very good analogy of the abstract data type stack, Figure 6-1 illustrates. As new plates are added, the old ones drop further into the well beneath the surface. At any particular time, only the last plate placed on the stack is above the surface and visible. This plate is at the top of the stack and the one that must be removed. In general, the plates are placed in the opposite order from that they were added.

The LIFO property of stacks seems inherently unfair. Think of the poor person who finally gets the last on the cafeteria's stack, one that has been there for six ago. Or would you like to be the first person to arrive on the stack for a movie—as opposed to the line for a movie. You would be the last person alone! These examples demonstrate the reason that stacks are not especially prevalent in everyday life. The property that we usually design in our daily lives is first, first out, or FIFO. A queue, which you will learn about in Chapter 13, is the ADT with the FIFO property. Most people would prefer to wait in a movie queue—as a line is called in Britain—than in a movie stack.
