Merging sorted runs in Phase 2

Given this overall strategy, how can you merge the sorted runs at each step of phase 2? The state of the problem provides only sufficient internal memory to manipulate at most 300 records at once. However, in the later stages of phase 2, more than 300 records, so you must merge one pair at a time. To accomplish this, you must divide the program's memory into three arrays, $in1$, $in2$, and $out$, each capable of holding 100 records (the block size). You read block-sized pieces of the runs into the two arrays and merge them into the out array. Whenever an array is exhausted—that is, all of its entries have been copied to out—you read the next piece of the run into an array—whenever the out array becomes full, you write the completed piece of the sorted run to one of the files.

Consider how you perform the first merge. You start this with the pair of runs $R_1$ and $R_2$, which are in the first and second blocks, of $F_1$ (See Figure 21-3a). Because this first merge step involves only two blocks, an entry run can fit into one of the arrays. You can read $R_1$ and $R_2$ into the arrays $in1$ and $in2$, and then merge $in1$ and $in2$ into $out$. However, although the result of merging $in1$ and $in2$ is a sorted run two blocks long (200 records), out can hold only one block (100 records).
