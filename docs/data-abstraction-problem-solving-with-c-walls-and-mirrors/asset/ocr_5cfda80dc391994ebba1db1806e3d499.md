Implementing this method, you must deal with a few subtleties. Suppose that myList and yourList each contains several items. If you

```
myList = yourList;
```

what happens to the items that were in yourList? You might not care, as long as myList ultimately contains a copy of the items in yourList. You should care, however, if you have a link-based list. Before you can copy the items in yourList, you need to deallocate the nodes in myList. Failure to do so results in a memory leak—that is, memory that was not returned to the system. Thus, the assignment of your myList must take these steps:

```
Deallocate memory assigned to myList
(for each item in yourList)
{
    Allocate a new node for myList
    Set the node's data to a copy of the item in yourList
}
```

The tasks here are like that you implemented when you wrote the destructor and copy constructor for LinkedList. To deallocate memory currently used by LinkedList nodes, you can call clear. When using the underlying chain of nodes, you can avoid redundancy by defining a private or protected method, copyNodes, that both copy constructor and the assignment operator can call.
Now you suppose

```
myList = myList;
```

Notice what our pseudocode tells you to do: Deallocate myList and then make a copy of myList. After you have deallocated myList, there is nothing to copy! Your implementation should test for this by asking whether the object on the left side of the = operator is the same as the object on the right. If it is, your assignment operator should do nothing—it should be fail-safe.

You can make this test by comparing the addresses of the two list objects by comparing the items on the lists. In C++, this is a pointer to the invoking object. Thus, you

```
if (this != &rightHandSide)
```

to compare the addresses of the objects on the left and right side of the = & symbol; when used in this manner, it means the "address of". We would then return the statement as "if the address of this object is not equal to the address of rightHandSide, then...". In this textbook, this is only done when it is necessary to use the & symbol as the "address of" operator.
The link-based implementation of the overloaded assignment operator for LinkedList lists:

```
template <class ItemType>
LinkedList<ItemType>& LinkedList<ItemType>::operator=(const LinkedList<ItemType>& rightHandSide)
{
    // Check for assignment to self
    if (this != &rightHandSide)
}
```
