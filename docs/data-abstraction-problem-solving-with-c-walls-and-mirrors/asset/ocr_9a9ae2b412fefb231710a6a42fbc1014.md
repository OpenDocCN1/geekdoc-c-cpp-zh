**Analysis.** The while loop in the function Sort executes $n-1$ times. This loop contains an inner loop for loop sorts values of unsorted that start from 1 to $n-1$. Then, in the worst case, the algorithm's comparison

$1 + 2 + \dots + (n - 1) = n \times (n - 1)/2$

In addition, the inner loop moves data items twice the same number of times. The outer loop moves data twice per iteration, or $2 \times (n - 1)$ times. Together, there are

$n \times (n - 1) + 2 \times (n - 1) = n^2 + n - 2$

major operations in the worst case.
Therefore, the insertion sort algorithm is $O(n^2)$ in the worst case. For small arrays—say, fewer than 25 items—the simplicity of insertion sort makes it an appropriate choice. For large arrays, an insertion sort can be prohibitively inefficient—unless the array is already sorted. In case, the inner loop exits immediately, making the sort $O(n)$ in its best case.
