# Measuring the Efficiency of Algorithms

The following examples illustrate the definition:

+   - Suppose that an algorithm requires $n^2 - 3 	imes n + 10$ to solve a problem of size $n$. If constants $k$ and $n_0$ exist such that

  $k 	imes n^2 > n^2 - 3 	imes n + 10$ for all $n \ge n_0
t algorithm is $O(n^2)$. In fact, if $k$ is 3 and $n_0$ is 2,

  $3 	imes n^2 > n^2 - 3 	imes n + 10$ for all $n \ge 2$

as Figure 10-2 illustrates. Thus, the algorithm requires no more than $k 	imes n^2$ time units for $n \ge n_0$, and so is $O(n^2)$.

+   - Previously in Section 10.2.1, we found that displaying a linked chain's first $n$ items requiresn
  $(n+1)(a+c) + n 	imes w

time units. Because $2 	imes n \ge n+1$ for $n \ge 1$,

$(2 	imes n) 	imes (a+c) + n 	imes w \ge (n+1) 	imes (a+c) + n 	imes w$ for $n \ge 1$

After factoring $n$ on the left side of the equation, we have

$(2 	imes a + 2 	imes c + w) 	imes n \ge (n+1) 	imes (a+c) + n 	imes w for n >= 1$

+   - Thus, the task is $O(n)$. Here, $k$ is $2 	imes a + 2 	imes c$ with $w$ and $n_0$ is 1.

Similarly, the solution to the definition of Towers of Hanoi problem requires $(2^m-1) 	imes m$ time units. Because

$m 	imes 2^m > (2^m-1) 	imes m$ for $n \ge 1$

the solution is $O(n^2)$.
The requirement $n \ge n_0$ in the definition of $O(f(n))$ means that the time estimate is correct for sufficiently large problems. In other words, the time estimate is too small for most a finite number of problem sizes. For example, the function log takes the value 0 when n is 1. The fact that k log1 is 0 for all constants implies an unrealistic time requirement; presumably, all algorithms require more than 0 time units, even to solve a problem of size 1.
