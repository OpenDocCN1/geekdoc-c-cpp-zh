## 2.6.2 Organizing a Parade

You have been asked to organize the Fourth of July parade, which will consist of bands and floats in a single line. Last year, adjacent bands tried to outlay each other. To avoid this problem, the sponsors have asked you to never place one band immediately after another. In how many ways can you organize a parade of length $n$?

Assume that you have at least $n$ marching bands and $n$ floats which to choose. When the number of ways to organize the parade, assume that the parade-float and float-band, for example, are different and count as two. The parade can end with either a float or a band. The number of ways to organize the parade is simply sum the number of ways of parades of each type. That is,

$P(n)$ = number of ways to organize a parade of length $n$
$F(n)$ = number of parades of length $n$ that end with a float
$B(n)$ = number of parades of length $n$ that ends with a band

Then

$P(n) = F(n) + B(n)$

First, consider $F(n)$. If you have a length of $n$ ends with a float by placing a float at the end of any acceptable parade of length $n-1$, the number of acceptable parades of length $n$ that ends with a float is precisely equal to the total number of acceptable parades of length $n-1$; that is,

$F(n) = P(n-1)$

Next, consider $B(n)$. The only way to have an end with a band is if the unit is just before the float (if it is, you will have adjacent bands). The only way to organize an acceptable parade of length $n$ that ends with a band is to organize a parade of length $n-1$ that ends with floats and then add a band to the end. Therefore, the number of acceptable parades of length $n$ that ends with a band is precisely equal to the number of parades of length $n-2$:

$B(n) = P(n-2)$

Thus you have $F(n)$ and $B(n)$ in terms of smaller problems $P(n-1)$ and $P(n-2)$, respectively. You then obtain

$P(n) = F(n) + B(n)$

The form of this recurrence relation is identical to the solution for rabbit problem. As you saw in the rabbit problem, two base cases are necessary because the recurrence defines a problem in terms of two smaller problems. As you did for the rabbit problem, you can choose $n=1$ and $n=2$ for the base cases. Both problems use the same values of $n$ for their base cases, there is no reason to expect that $rabbit(1)$ is equal to $P(1)$ and that $rabbit(2)$ is equal to $P(2)$. Two base cases are necessary because there are two smaller problems. A little thought reveals that the parade,

$P(1)=2$ (The cases of length 1 are float and band).
$P(2)=3$ (The cases of length 2 are float-band, band-float, and float-band).

In summary, the solution to this problem is

$P(1)=2$
$P(2)=3$
$P(n)=P(n-1)+P(n-2)$ for $n>2$

A recursive solution example demonstrates the following points:

- Sometimes you can solve a problem by breaking it up into cases—for example, parades that end with a float and that end with a band.
- The values you use for the base cases are extremely important. Although the recurrence for $P$ and rabbit are the same, their base cases (when $n=1$ or 2) are different. These difference cases $rabbit(n)$ and $P(n)$ differ when $n$ is greater than 2. For example, $rabbit(20)=6765, P(20)=17111$. The larger the value of $n$, the larger the discrepancy. You should think about why this is.

## 2.6.3 Choosing out of n

A rock band wants to visit $n$ cities. Unfortunately, time will allow visits to only $k$ cities. The band considers the different visiting $k$ cities out of $n$ possibilities. Because time is short, the band members are not concerned about the order in which they visit the $k$ cities.

Let $g(n,k)$ be the number of groups of $k$ cities chosen from $n$. If we visit either $C$ or not. If we visit $C$, we have to choose $k-1$ cities to visit from the $n-1$ others. Thus the number of ways is $g(n,k)$. On the other hand, if we do not visit $C$, we have to choose $k$ cities from the remaining $n-1$ cities. The number of groups of $k$ cities that do not include $C$ is $g(n-1,k)$. We can compute $g(n,k)$ by solving two smaller problems of the type such as:

The number of ways to choose out of $n$ cities is the sum of the ways to choose out $k-1$ of $n-1$ and the number of ways to choose out $k$ of $n-1$ things

$g(n,k)=g(n-1,k-1)+g(n-1,k)$,

We need to find the base case(s) and demonstrate that each of the two smaller problems reaches a base case. First, if the band needs to visit all $n$ cities—that is $k=n$—there is one way. Thus the recursive solution is:

$g(n,n)=1$

If $k<n$, the first term $g(n-1,k-1)$ will reach a base case. The second term $g(n-1,k)$ will reach a base case. This is because the first argument of $g$ decreases with each call, and the second argument either decreases or stays the same.

```cpp
/**
 * Computes the number of groups out of n.
 * @pre $n$ and $k$ are nonnegative integers.
 * @param $n$ The number of cities.
 * @param $k$ The number of cities to visit.
 * @return The number of ways.
 */
int getGroups(int n, int k) {
    if (k == 0 || k == n) {
        return 1;
    } else if (k > n) {
        return 0;
    } else {
        return getGroups(n-1, k-1) + getGroups(n-1, k);
    }
}
```

## 2.7 Recursion and Efficiency

Recursion is a powerful problem-solving technique that often produces clean solutions to even the most complex problems. By using recursion, you can write simple, short implementations of your solution.

The overriding concern of this chapter is to give you a solid understanding of recursion so that you will be able to construct recursive solutions of your own. Unfortunately, many recursive solutions are so inefficient that you should not use them. The recursive functions binarySearch and sortTowers are the notable exceptions, as they are quite efficient.

Two factors contribute to the inefficiency of recursive solutions:

- The overhead associated with function calls
- The inherent inefficiency of recursive algorithms

The first of these factors does not pertain specifically to recursive functions but is true of functions in general. In most implementations of C++ and other high-level programming languages, a function call can incur a certain amount of bookkeeping overhead. As is analogous to a box in the box trace. Recursive functions magnify this overhead because a single initial call to the function can generate a large number of recursive calls. For example, the factorial(n) generates n recursive calls. On the other hand, the use of recursion, as true of modularity in general, can greatly clarify complex programs. This clarification frequently more compensates for the additional overhead.

> Recursion can clarify complex solutions
