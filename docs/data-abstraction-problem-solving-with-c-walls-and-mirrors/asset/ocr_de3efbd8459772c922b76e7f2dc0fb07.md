# 21.1 A Look at External Storage

You external storage when your program reads from and writes data to a C++ file. Also, when you use a word processing program, for example, choose Save, the program saves your current document in a file. This action enables you to exit the program and then use it to retrieve your document for revision. This is one of the advantages of external storage: It exists beyond the execution period of a program. In this sense, it is “permanent” storage of volatile like internal memory.

Another advantage of external storage is, in general, there is far beyond all internal memory. If you have a collection of one million data items, each of which is of moderate size, you will probably not be able to store the entire collection in internal memory at one time. On the other hand, this data can easily reside on external storage. As a consequence, with collections of this magnitude, you cannot simply read all of the data into memory when you want to operate on it and write back to the disk when you are finished. Instead, you must design ways to operate on data and search it while it resides indefinitely.

In general, you can create files for either sequential or direct access. To access the data stored in a file given a sequential access file, you must find the view beyond all the intervening data. To access a particular node in the chain, that sequential access file remembers the chain itself until you reach the desired node. In contrast, a direct access file allows you to access the data at a given point without the consequence. A direct access file remains in an array that you can access the element at data[i] without accessing the elements before.

Without direct access, it would be impossible to support dictionary operations efficiently in an external environment. Many programming languages, including C++, support both sequential and direct access files. However, to implement a language-independent decision, we will construct a model of direct access files that illustrates how a programming language that does not support such files might implement them. This model will be a simplification of reality but will include the necessary features for this discussion.

Imagine that a computer's memory is divided into two parts: internal memory and external memory, as Figure 21-1 illustrates. Assume that an executing program, with all its data, resides in the computer's internal memory; the parameters of the computer reside in the external memory. Further assume that the external storage devices have the characteristics of a disk (although some systems use other devices).

A file consists of data records. A data record can contain anything from a simple value, such as an integer, to an aggregate structure, such as an employee record. For simplicity, assume the data in any file are all of the same type.

The records of a file are organized into one or more blocks, as Figure 21-2 shows. The size of a block—that is, the number of bits it can contain—is determined by both the hardware configuration and the software system of the computer. In general, an individual program has no control over this size. Furthermore, the number of records in a block is a function of the size of the records in the file. For example, an integer file will have more records per block than a file of employee records.
