When an internal node would contain three items, split it into two nodes and accommodate its children

On the other hand, if the parent cannot accommodate the item moving up, you must split the parent, as follows. You split an internal node n that contains three items by using the process just described for a leaf, except that you take care of $n$'s four children. As Figure 19-13 illustrates, you split n$ into $n_1$ and $n_2$, place $n$'s s into $n_1$, attach $n$'s largest item L into $n_2$, attach $n$'s two right children to $n_2$, and move $n$'s middle item M up to $n$'s parent.

When the root would contain three items, split it into two nodes and create a new root

After this, the process of splitting a node and moving an item up to the parent continues until a node is reached that has only one item before the insertion and has only two items after it takes on a new item. Notice in the previous sequence of insertions that the tree's height never increased from its original value of 3. In general, as long as there is at least one node containing only one item on the path from the root to the leaf into the new item is inserted. The insertion strategy of a 2-3 tree has postponed the growth of the tree's height more effectively than the strategy of a basic binary search tree.

When the height of a 2-3 tree grows, it does so from the root. An increase in the height of a 2-3 tree will occur if every node on the path from the root of the tree to the leaf into the new item is inserted. In this case, the recursive process of splitting a node and moving an item up to the node's parent will eventually reach the root $r$. When this occurs you split $r$ into $r_1$ and $r_2$ exactly as you would any other internal node. However, you must create a new node that contains the middle item of $r$ and becomes the parent of $r_1$ and $r_2$. Thus, the new node is the root of the tree, as Figure 19-14 illustrates.
