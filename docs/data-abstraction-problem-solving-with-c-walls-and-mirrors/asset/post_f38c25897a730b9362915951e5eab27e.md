
## 4.4 Testing Multiple ADT Implementations

In Chapter 3, we developed a short program, in Listing 3-2, that tested the core methods of our array-based implementation. Because we used ADT bag when we tested our implementation, we can use the same code—with a few changes—to test our linked implementation. You need to change each occurrence of ArrayBag to LinkedBag and recompile the program.

But if we want to change the array-based implementation and want to test it? You need to change each occurrence of LinkedBag back to ArrayBag. Let's examine a way we can verify the test program by letting the user decide which bag implementation needs testing. By taking advantage of polymorphism, we can do this without needing to duplicate the code.

In Chapter 1, we declared our ADT in the abstract class BagInterface. Since both ArrayBag and LinkedBag share public methods defined in class, we made each a subclass of BagInterface. In our test program, we declare the bagPtr as a pointer to an object that the methods in BagInterface, we can use an instance of either ArrayBag or LinkedBag as the object reference. We declare bagPtr

```
BagInterface<string>* bagPtr;
```

We then ask the user which implementation to test, and if we assign 'A' or 'L' to the variable userChoice, we can instantiate an instance of the requested bag type and run the test by the following code:

```
if (userChoice == 'A') {
    bagPtr = new ArrayBag<string>();
    cout << "Testing the Array-Based Bag:" << endl;
} else {
    bagPtr = new LinkedBag<string>();
    cout << "Testing the Link-Based Bag:" << endl;
} // end if
```

```
cout << "The initial bag is empty." << endl;
bagTester(bagPtr);
delete bagPtr;
bagPtr = nullptr;
```

To accommodate the data type of bagPtr, we need to change the parameter lists of the functions in our test program as follows:

```
void displayBag(BagInterface<string>* bagPtr);
```

and

```
void bagTester(BagInterface<string>* bagPtr);
```

Finally, we must change the notation used to call methods on the instances of bagPtr, since it is a pointer. For example,

```
bag.isEmpty()
```

must be changed to

```
bagPtr->isEmpty()
```

Listing 4-4 is a complete listing of the modified test program for core methods of classes that are implementations of the ADT bag.

#include "BagInterface.h"
#include "ArrayBag.h"
#include "LinkedBag.h"

#include <string>
#include <cctype>

void displayBag(BagInterface<string>* bagPtr)
{
    cout << "The bag contains " << bagPtr->getCurrentSize();
    cout << " items:" << endl;
    vector<string> bagItems;
    bagPtr->toVector(bagItems);
    int numberOfEntries = bagItems.size();
    for (int i = 0; i < numberOfEntries; i++)
    {
        cout << bagItems[i] << " ";
    }
    cout << endl << endl;
 // end displayBag

void bagTester(BagInterface<string>* bagPtr)
{
    cout << "isEmpty returns : " << bagPtr->isEmpty();
    cout << " should be 1 (true)" << endl;
    string items[] = { "one", "two", "three", "four", "five", "one" };
    cout << "Add 6 items to the bag: " << endl;
    for (int i = 0; i < 6; i++)
    {
        bagPtr->add(items[i]);
    }
    displayBag(bagPtr);
    cout << "isEmpty returns : " << bagPtr->isEmpty();
    cout << " should be 0 (false)" << endl;
    cout << "getCurrentSize returns : " << bagPtr->getCurrentSize();
    cout << " should be 6" << endl;
    cout << "To add another entry: add(\"extra\") returns "
    cout << bagPtr->add("extra") << endl;
}
 // end bagTester

int main()
{
    BagInterface<string>* bagPtr = nullptr;
    char userChoice;
    cout << "Enter 'A' to test the array-based implementation\n";
    cout << " ' or 'L' to test the link-based implementation: ";
    cin >> userChoice;

    if (toupper(userChoice) == 'A')
    {
        bagPtr = new ArrayBag<string>();
        cout << "Testing the Array-Based Bag:" << endl;
    } else
    {
        bagPtr = new LinkedBag<string>();
        cout << "Testing the Link-Based Bag:" << endl;
    } // end if

    cout << "The initial bag is empty." << endl;
    bagTester(bagPtr);
    delete bagPtr;
    bagPtr = nullptr;
    cout << "All done!" << endl;

    return 0;
} // end main

## 4.5 Comparing Array-Based and Link-Based Implementations

Typically, an array-based implementation has a fixed size. When you select an array, you must weigh the advantages and disadvantages. One advantage of an array is that it provides random access. However, if the array becomes full, you may need to allocate a new, larger array and copy all the elements over. This is an expensive operation.

A linked-based implementation does not have a fixed size. You can always add another item to a linked list. However, the disadvantage is that a linked list does not provide random access. To find the $n$-th element, you must traverse the list from the beginning. This is a slow operation.

Another advantage of a linked-based implementation is that it can grow its size dynamically. The disadvantage is that each element requires extra memory to store the pointer to the next element. This means that a linked list uses more memory than an array for the same number of elements.
