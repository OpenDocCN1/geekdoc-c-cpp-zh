# CHAPTER 2 Recursion: The Mirrors

The goal of this chapter is to ensure you have a basic understanding of recursion, which is one of the most powerful techniques available to the computer scientist. This chapter assumes that you have little or no previous introduction to recursion. If, however, you have already studied recursion, you can review this chapter as necessary.

By presenting relatively simple problems, the chapter demonstrates the techniques that lead to recursive solutions. These problems are diverse and include examples of counting, searching, and organization. In addition to presenting recursion from a conceptual viewpoint, this chapter discusses techniques that will help you understand the mechanics of recursion. These techniques are particularly useful for tracing and debugging recursive functions.

Some recursive functions are more elegant and concise than the best of nonrecursive counterparts. For example, the classic Towers of Hanoi problems may be quite difficult, yet they have an extremely simple recursive solution. On the other hand, some recursive solutions are terribly inefficient, as you will see, and should not be used.

Chapter 5 continues the formal discussion of recursion by examining more difficult problems. Recursion will play a major role in many of the solutions that appear throughout the remainder of this book.

## 2.1 Recursive Solutions

Recursion is an extremely powerful problem-solving technique. Problems that at first appear to be quite difficult often have simple recursive solutions. Unlike other problem-solving techniques, recursion breaks a problem into smaller problems. What is striking about recursion is these smaller problems are of the same type as the original problem—mirror images, so to speak.

Did you hold a mirror in front of another mirror so the two mirrors face each other? You will see many images of yourself, each behind and slightly smaller than the other. Recursion is like mirror images. That, a recursive solution solves a problem by solving a smaller instance of the same problem! It then solves this new problem by solving a smaller instance of the same problem. Eventually, the problem will be so small that its solution will lead to the solution of the original problem.

For example, suppose you could solve problem $P_i$ if you had the solution $P_j$, which is a smaller instance of $P_i$. Suppose that you could solve problem $P_j$, if you had the solution to problem $P_k$, which is a smaller instance of $P_j$. If it was small enough to reach, you would be able to solve $P_k$. You could then use the solution to $P_k$ to solve the original problem $P_i$.

Recursion can seem magic, especially at first, but as you will see, it is a real and important problem-solving approach that is alternative to iteration. An iteration solution involves loops. You should know that not all recursive solutions are better than iterative ones. In fact, some recursive solutions are impractical because they are so inefficient. However, recursion can provide elegant solutions to problems of great complexity.

As an illustration of the elements in a recursive solution, consider the problem of looking up a word in a dictionary. Suppose you wanted to look up "vacademem". Imagine starting at the beginning of the dictionary and looking at every word until you find "vacademem". That is what sequential search does, and for obvious reasons, you want a faster way to perform search.

One approach is the binary search, which in spirit is similar to the way in which you actually use a dictionary. You open the dictionary—maybe to a point near its middle—and by glancing at the page, determine which "half" of the dictionary contains the desired word. The following pseudo-code is a first attempt to formalize this process:

A binary search of a dictionary

```
// Search a dictionary for a word by using a recursive binary search
if (the dictionary contains only one page)
    Scan the page for the word
else
    Open the dictionary to a point near the middle
    Determine which half of the dictionary contains the
    if (the word is in the first half of the dictionary)
        Search the first half of the dictionary for the word
    else
        Search the second half of the dictionary
```

Parts of this solution are intentionally vague: How do you scan a single page? How do you find the middle of the dictionary? Once the middle is found, how do you determine which half contains the word? The answers to these questions are not difficult, but they would obscure the solution strategy right now.

The previous search strategy reduces the problem of searching the dictionary to a problem searching half of the dictionary for the word, as Figure 2-1 illustrates. Notice two important points. Once you have divided the dictionary in half, you already know how to search the appropriate half. You can easily use the same strategy that you employed to search the original dictionary. Note, that there is a special case that is different from all the other cases: After you have divided the dictionary so many times that you are left with only a single page, the division ceases. At this point, the problem is small enough that you can solve it directly by scanning the single page that remains for the word. This special case is called the base case (or basis or degenerate case).

This strategy is called divide and conquer. You solve the dictionary search problem by first dividing the dictionary into two halves and conquering the appropriate half. You solve the smaller problem by using the same divide-and-conquer strategy. The division continues until you reach the base case. As you will see, this strategy is inherent in many recursive solutions.

To explore the nature of the solution to the dictionary problem, consider the following a slightly more rigorous formulation.

- Recursion breaks a problem into smaller identical problems
- Some recursive solutions are inefficient and impractical
- Complex problems can have simple recursive solutions

- A recursive function calls itself
- Each recursive call identifies an identical, but smaller, problem
- A test for the base case enables the recursive calls to stop
- Eventually one of the smaller problems becomes the base case

These facts describe the general form of a recursive. Though not all recursive solutions follow these criteria as this solution does, the differences are far greater. If you attempt to construct a new recursive solution, you should keep in mind the following questions:

> Note: Four questions for constructing recursive solutions
1. How can you define the problem in a smaller problem?
2. How does each recursive call diminish the size of the problem?
3. What instance of the problem can serve as the base case?
4. As the problem diminishes, will you reach this base case?

Now consider relatively simple problems: computing the factorial of a number and writing a string backward. Their recursive solutions further illustrate the points raised by the solution to the dictionary search. These examples also illustrate the difference between a recursive valued function—which returns a value—and a recursive function.

## 2.2 Recursion Returns a Value

The mechanics of recursion are clearer when the recursive function returns a value instead of just performing an action, and we examine in detail.

### 2.2.1 A Recursive Valued Function: The Factorial of n

Computing the factorial of an integer n is a good example because its recursive solution is easy to understand and nearly fits the mold described earlier. However, because the problem has a simple and efficient iterative solution, you should not use the recursive solution in practice.

```
factorial(n) = n * (n - 1) * (n - 2) ·· * 1 for an integer n > 0
factorial(0) = 1
```

- Do not use recursion if a problem has a simple, efficient iterative solution
