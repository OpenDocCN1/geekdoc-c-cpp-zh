A time-driven simulation simulates the ticking of a clock only the times of certain events, in this case, arrivals and departures

First revision of the simulation algorithm

You must determine the time of next arrival or departure so that you can implement the state

```
currentTime = time of next event
```

To make this determination, you must maintain an event list. An event list contains all arrival and departure events that will occur but have not occurred yet. The times of the events in the list are in ascending order, and then the next to be processed is always the beginning of the list. The algorithm simply gets the beginning of the list, advances to the time specified, and processes the event. The difficulty, then, in successfully managing the event list.

An event list contains all future arrival events and departure events

Managing and processing customers and events. As customers, you go to the back of the line. The current customer, who was at the front of the line, is being served and it is this customer that you remove from the system next. It is natural to use a queue, to represent the customers in the bank. For this, the only information you must store in the queue about each customer is the time of arrival and the length of the transaction.

Arrival events and departure events are ordered by time, and we always want to remove and process the next event that occur—the highest-priority event. The ADT priority queue is used in this way. Our events can be stored in the priority queue event_ListPQueue. We can initialize eventListPQueue with the arrival events in the simulation data file and later add the departure events as they are generated.

How can you determine the times for the departure events? Observe that the next departure event corresponds to the customer that the teller is currently serving. As soon as a customer begins service, the time of his or her departure is simply

time of departure = time service begins + length of transaction

Recall that the length of the customer's transaction is in the event list, with the arrival time. Thus, as soon as a customer begins service, you place a departure event corresponding to this customer in the event list. Two tasks are required to process each event

Now consider how you process an event when it is time for the event to occur. You must perform two general types of actions:

- Update the bank line: Add or remove customers.
- Update the event list: Add or remove events.

To summarize, you process an arrival event as follows:

```
// TO PROCESS AN ARRIVAL EVENT
// Update the event list
// Remove the arrival event for customer C from the event list
// Update the bank line
if bank line is empty and teller is available
  Departure time of customer C is current time + transaction length
  Add a departure event for customer C to the event list
  Mark the teller as unavailable
else
  Add customer C to the bank line
```

The algorithm for arrival events

A new customer always enters the queue and is served at the teller's front

When customer C arrives at the bank, if the line is empty and the teller is not serving another customer, C can go directly to the teller. The wait time is 0 and you insert a departure event into the event list. If other customers are in line, or if the teller is assisting another customer, C must go to the end of the line. You process a departure event as follows:

The algorithm for departure events

```
// TO PROCESS A DEPARTURE EVENT
// Update the event list
// Remove the departure event from the event list
// Update the bank line
if bank line is not empty
{
  Remove customer C from the bank line
  Customer C begins transaction
  Departure time of C is current time + transaction length
  Add a departure event for C to the event list
}else
  Mark the teller as available.
```

When a customer finishes a transaction and leaves the bank, if the line is not empty, the next customer leaves and joins the teller. You can now combine and refine the solution into an algorithm that performs the simulation by using the ADTs and priority queue:

```
// Performs the simulation.
simulate(): void {
  Create an empty queue bankQueue to represent the bank line
  Create an empty priority queue eventListQueue
  tellerAvailable = true
  // Create and add arrival event to event list
  while (data is not empty) {
    Get next arrival time a and transaction time t from file
    newArrivalTimeEvent = a new arrival event containing a and t
    eventListQueue.add(newArrivalTime)
  }
  // Event loop
  while (eventListQueue is not empty) {
    newEvent = eventListQueue.peek()
    // Get current time
    currentTime = time of newEvent
    if (newEvent is an arrival event)
      processArrival(newEvent, eventListQueue, bankQueue)
    else
      processDeparture(newEvent, eventListQueue, bankQueue)
  }

  // Processes an arrival event.
  processArrival(arrivalEvent: Event, eventListQueue: PriorityQueue,
  bankQueue: Queue)
  // Remove this event from the event list
  eventListQueue.remove()

  customer = customer referenced in arrivalEvent
  if (bankQueue.isEmpty() && tellerAvailable)
{
    departureTime = currentTime + transaction time in arrivalEvent
    newDepartureEvent = a new departure event with departureTime
    eventListQueue.add(newDepartureEvent)
    tellerAvailable = false
}else
  bankQueue.enqueue(customer)

  // Processes a departure event.
  processDeparture(departureEvent: Event, eventListQueue: PriorityQueue,
  bankQueue: Queue)
  // Remove this event from the event list
  eventListQueue.remove()

  if (!bankQueue.isEmpty())
{
    customer = bankQueue.dequeue()
    // Customer begins transaction
    departureTime = currentTime + transaction time in departureEvent
    newDepartureEvent = a new departure event with departureTime
    eventListQueue.add(newDepartureEvent)
}else
  tellerAvailable = true
}
```
