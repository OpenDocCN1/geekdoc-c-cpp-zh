You can search the 2-3 tree and the shortest binary tree with approximately the same efficiency, because

+   - A binary tree with n nodes cannot be shorter than [log₂(n+1)]
- A 2-3 tree with n nodes cannot be longer than [log₂(n+1)]
- A node in a 2-3 tree has at most two items

Searching a 2-3 tree is not more efficient than searching a binary tree, however. This observation may surprise you, because after all, the nodes of a 2-3 tree can have three, and hence a 2-3 tree might be shorter than the shortest possible binary search tree. Although true, this advantage in height is offset by the extra time required to compare a value with two values instead of only one. In other words, you might visit fewer nodes when searching a 2-3 tree, but you might have to make more comparisons at each node. As a consequence, the number of comparisons to search a 2-3 tree for a given item is approximately equal to the number of comparisons required to search a binary search tree that is as balanced as possible. This number is approximately log₂n.

If you can search a 2-3 tree and a balanced binary tree with approximately the same efficiency, why then should you use a 2-3 tree? Because maintaining the balance of a binary search tree is difficult in the face of insertion and removal operations, maintaining the shape of a 2-3 tree is relatively simple.
