# 18.4 Dictionary Traversal: An Inefficient Operation Under Hashing

For many applications, hashing provides the most efficient implementation of the ADT dictionary. One important dictionary operation—traversal in sorted order—performs poorly when hashing implements the dictionary. As mentioned previously, a good hash function scatters items as randomly as possible throughout the array, so that no ordering exists between a search key that hashes into table[i] and one that hashes into table[i+1]. As a consequence, if you must traverse the dictionary in sorted order, you have sort the items. If ordering were required, hashing would be a far less efficient implementation than a search tree.

Traversing in sorted order is just one example of a whole class of operations that hashing does not support well. Many similar operations that you often wish to perform on a dictionary require that the items be ordered. For example, consider an operation that finds the dictionary item whose search key is the smallest or largest. If you use a search-tree implementation, these are in the leftmost and rightmost nodes of the tree. If you use a hashing implementation, you do not know where these items are—you would have to search the entire dictionary. A similar type of operation is a range query, which requires you to retrieve all items whose keys fall in a range of values. For example, you might want to retrieve all items whose search keys are in the range 129 to 755. This task is relatively easy to perform by using a search tree (see Exercise 3 in the next chapter), but by using hashing, there is no efficient way to answer the query.

In general, if application requires these ordered operations, you probably use a search tree. The getItem, add, and remove operations are somewhat more efficient when you use hashing the dictionary implementation of a balanced search tree, the search tree supports these operations so effectively that, in most cases, the difference in speed for these operations is negligible (whereas the advantage of the search tree over hashing is significant)

In the context of external storage, the story is different. For data that is external, the difference in speed between hashing's implementation of getItem and a search tree implementation may be significant, as you will see in Chapter 21. In an external setting, it is not uncommon to use a hashing implementation of the getItem operation and a search-tree implementation of the ordered operations used simultaneously.
