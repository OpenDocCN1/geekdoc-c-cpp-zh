
postfixExp * x means concatenate the string currently in postfixExp and the character x—that is,
follow the string in postfixExp with the character x.

```
for (each character ch in the infix expression)
{
    switch (ch)
    {
        case operand: // Append operand to end of postfix expression—step 1
            postfixExp = postfixExp + ch;
            break;
        case '(': // Save '(' on stack—step 2
            aStack.push(ch);
            break;
        case operator: // Process operators of greater precedence—step 3
            while (!aStack.isEmpty() && aStack.peek() is not '(' and
                precedence(ch) < precedence(aStack.peek()))
            {
                Append aStack.peek() to the end of postfixExp
                aStack.pop();
            }
            aStack.push(ch); // Save the operator
            break;
        case ')': // Pop stack until matching (‘’—step 4
            while (aStack.peek() is not '(')
            {
                Append aStack.peek() to the end of postfixExp
                aStack.pop();
            }
            aStack.pop(); // Remove the open parenthesis
            break;
    }
}
// Append to postfixExp the operators remaining in the stack—step 5
while (!aStack.isEmpty())
{
    Append aStack.peek() to the end of postfixExp
    aStack.pop();
}
```

## 6.4 Using a Stack to Search a Flight Map

The previous chapter described the HAir problem, whereby we searched an airline's flight map to see whether we could fly from some origin city to some destination city. At that time, we used a recursive solution to the problem. We will now solve the problem using a stack instead of recursion. Doing so will bring to light the close relationship between stacks and recursion.

Use a stack to organize an exhaustive search

- Possible outcomes of the exhaustive search strategy
- Use backtracking to recover from a wrong choice

Let's recall some of the discussion about this problem from the previous chapter. Given HAir's flight map shown in Figure 6-6, we can fly from city P to city Z flying first to city W, then to city Y, and finally to city Z. We need to find this by trying every possible sequence of flights until we either find a sequence that gets to the destination city or determine that no sequence exists. You will need the stack in using this strategy.

If we were to perform the search by hand, we could start at the origin city C and select a departing flight to the next city. If C happens to be the destination city, we are done; otherwise, we must try to fly from C to the destination city. By repeating this strategy, we will encounter three possible outcomes, just as you were in the previous chapter.

1. You reach the destination city.
2. You reach a city C from which there are no departing flights.
3. You go around circles forever.

Even if a sequence of flights exists from the origin city to the destination city, we might not find it and instead reach outcome 2 or 3. As we did in the recursive solution, if we reached a city C from which there are no departing flights out of C—we would backtrack to the city C' that we visited just before visiting city C—we would select a flight to some other city. Once back at city C*, we would backtrack again—this time to the city that was visited before city C. To avoid outcome 3, we mark the cities as we visit them, just as we did in Chapter 5, and never visit a city more than once.

For the algorithm to implement this strategy, it must maintain information about the order in which it visits the cities. First notice that when the algorithm backtracks from a city C, it must retreat to the city that it most recently before C. This observation suggests that the sequence of visited cities is a stack. That is, each time you decide to visit a city, you push its name onto the stack. For example, if you want to fly from city P to city Z in Figure 6-6, the algorithm might choose to go from city P to city R and then on to city X. Parts a, b, and c of Figure 6-7 illustrate the stack for these flights. You select the next city to visit from those adjacent to the city on the top of.
