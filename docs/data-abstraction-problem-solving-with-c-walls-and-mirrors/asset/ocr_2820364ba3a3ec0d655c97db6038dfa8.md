A virtual method is one that you can override

A method that is virtual in a base class is virtual in any derived class

A virtual method in a derived class can override a virtual method in the base class if they have the same declaration. An overriding method is similar to redefining a method. You can override only virtual methods. Note that you can override a virtual in the derived class. A method in a derived class that has the same declaration as an ancestor's virtual method—such as setItem—is also virtual without explicit declaration, although tagging is desirable.

Every class has a virtual method table (VMT), which remains invisible to the programmer. For each virtual method, the VMT contains a pointer to the instructions that implement the method. For a method that is not virtual, the compiler can establish this pointer, since it knows the method's definition. For a virtual method, the compiler cannot complete the VMT. A call to a constructor during program execution sets the pointer, as in Figure C4-5. That is, the constructor establishes the VMT pointers to the versions of the virtual methods that are appropriate for the object. Thus, the VMT is the mechanism that enables late binding.

C++ inheritance and access

In addition to public and private sections, a class can have a protected section. By creating a protected section, a class designer can hide members from a class but make them available to a derived class. That is, a derived class can reference the members of its base class directly, but clients of the base class or derived class cannot.
