
## 2-3 Trees 579

The following high-level algorithm summarizes the entire insertion strategy:

```
// Inserts a new item into a 2-3 tree whose items are distinct and differ from the
// new item.
insertItem(2Tree: TwoThreeTree, newItem: ItemType)

Locate the leaf, leafNode, in which newItem belongs
Add newItem to leafNode

if (leafNode has three items)
  split(leafNode)

// Splits node n, which contains two items. If n is
// not a leaf, it has four children.
split(n: ThreeNode)

if (n is the root)
  Create a new node p
else
  Let p be the parent of n

Replace node n with two nodes, n1 and n2, so that p be their parent
Give n1 the item in n with the smallest value
Give n2 the item in n with the largest value

if (n is not a leaf)
{
  n1 becomes the parent of n's two leftmost children
  n2 becomes the parent of n's two rightmost children
Move the item in n that has the middle value up to p
if (p now has three items)
  split(p)
}
```

## 19.2.4 Removing Data from a 2-3 Tree

The removal strategy for a 2-3 tree is as inverse of its insertion strategy. It removes throughout the tree by splitting nodes when they would become too full; it removes throughout the tree by merging nodes when they become empty. An example of the 2-3 tree's removal strategy, consider the removal of 70, 100, and 80 from the tree in Figure 19-15.

**Remove 70.** By searching the tree in Figure 19-15, you find that 70 is in the node <70 < 90>. Because you want to remove a node at a leaf, the first step is to swap 70 with its inorder successor—the value that follows it in the sorted order. Because 70 is the smaller of the two values in the node, its inorder successor (80) is in an internal node or will always be in a leaf subtree. After the swap, the tree appears as shown in Figure 19-15b. The 80 is in a legal position of the search tree because it is larger than all the values in its node's left subtree and smaller than all the values in its node's right subtree. The tree 70 is not in a legal position, but this is of no concern, because the next step is to remove this value from the leaf.

In general, after you remove a value from a leaf, another value may remain in the leaf (because the leaf contained two values before the removal). If this is the case, you are done, a leaf of a 2-3 tree can contain a single value. In this example, however, once you remove 70 from the leaf, the node is left without a value, as Figure 19-15 indicates.

You then delete the node, as Figure 19-15d illustrates. You see that the parent of the deleted node contains two values (80 and 90) and has two children (60 and 100). This situation is not allowed in a 2-3 tree. You can remedy the problem by moving the smaller value (80) from the parent into the leaf, as Figure 19-15e illustrates. Deleting the leaf and moving a value down to a sibling is called *merging the leaf with its sibling*. The 2-3 tree that results from this removal is shown in Figure 19-f.

Remove 100. The search strategy discovers that 100 is in the leaf <100> of Figure 19-f. When you remove the value from this leaf, the node becomes empty, as Figure 19-16a indicates. In this case, no merging of nodes is required because the sibling <60 80> can share a value. That is, the sibling has two values, whereas a 2-3 tree requires that it has at least one. However, if you move the value 80 into the empty node—as Figure 19-16b illustrates—you find that the search tree order is destroyed. The value in n's right should be greater than 90, but it is 80. Instead, you move the larger value (80) from <60 80> into the parent and move the value 90 down into the node that had been empty, as Figure 19-16c. This preserves the search tree order, and you have completed the removal. The resulting 2-3 tree is shown in Figure 19-16d.

**Remove 80.** The search strategy finds that 80 is an internal node of the tree in Figure 19-16d. You must first swap 80 with its inorder successor, 90, as Figure 19-17a illustrates. When you remove 80 from the leaf, the node becomes empty, as Figure 19-17b. Because the sibling of the empty node has only one value, you cannot redistribute as you did in the removal of 100. Instead you must merge the nodes, bringing the value 90 down from the parent and deleting the empty leaf, as Figure 19-17c.

You are not yet finished because the parent contains no data and has only one child. You must recursively apply the removal strategy to this internal node without a value. You should check to see whether the node's sibling can carry a value. Because the sibling <30> contains only the single value, it cannot redistribute—the merging of internal nodes is identical to the merging of leaves, except that the <60 90> of the node must be adopted. Because the sibling of the empty node contains only one value—and hence can have two children, as in the rule for 2-nodes—it can become the parent of <60 90> only if you bring the value 50 down from the sibling. The new tree appears as Figure 19-17d. Note that this operation preserves the search property of the tree.

Now the parent of the merged nodes is left without a data item and only one child. Usually, the root is special because if the root is empty and has only one child, you can simply delete it, as <30 50> become the root of the tree, as Figure 19-17e illustrates. This deletion has caused the height of the tree to shrink by 1.

To summarize, we have removed 70, 100, and 80 from the 2-3 tree in Figure 19-15a and obtained the 2-3 tree in Figure 19-17e and 19-18. In contrast, after removing 70, 100, and 80 from the balanced binary search tree in Figure 19-5a, you are left with the tree in Figure 19-18b. Notice that the removals affected only one part of the binary tree, causing it to lose its balance. The left-subtree has not been affected at all, and the overall height of the tree has not been diminished.

## The removal algorithm. In summary, to remove an item I from a 2-3 tree, you first locate the node n contains it. If n is not a leaf, you insert I into its successor and swap with I. As a result of the swap, the removal always begins at a leaf. If the leaf contains an item in addition to I, you simply remove I and do nothing. On the other hand, if the leaf contains only I, you delete the leaf.
