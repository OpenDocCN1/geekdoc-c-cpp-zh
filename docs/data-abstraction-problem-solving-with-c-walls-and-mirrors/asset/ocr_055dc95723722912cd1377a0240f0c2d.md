# 15.3.3 Creating a Binary Search Tree

Suppose that you want to insert a record for Frank in the binary search tree of Figure 15-13. As a first step, imagine you want to search for the string “Frank”. The search algorithm searches the tree rooted at Jane, then the tree at Bob, and the tree at Elisa. It searches the tree at the right child of Elisa. Because this is empty, as Figure 15-16 illustrates, the search algorithm has reached a base case and will terminate with report that Frank is not present. What does it mean if search looked for Frank in the right subtree of Elisa? For one thing, it means that if Frank was the right child of Elisa, search would have found Frank.

> This observation indicates a good place to insert Frank as the right child of Elisa. Because Elisa has no right child, the insertion is simple, requiring only the addition of a new leaf node. More important, Frank belongs in this location—search will look for Frank. Specifically, inserting Frank as the right child of Elisa will preserve the tree’s binary search property. Because search, when searching for Frank, would follow a path that leads to the right child of Elisa, you are assured that Frank is in the proper relation to the names above it in the tree.

Use search to determine the insertion point

> Note: Using search to determine where in the tree to insert a new name always leads to an easy insertion. No matter what item you insert into the tree, search will always terminate at an empty subtree. Thus, search always tells you to insert the item as a new leaf.
