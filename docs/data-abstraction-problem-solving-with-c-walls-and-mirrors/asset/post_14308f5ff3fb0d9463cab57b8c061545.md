# C1.4.1 Base Classes and Derived Classes

We use PlainBox as a base class, or superclass, for our ToyBox class. You can think of a base class as a parent class. The ToyBox class is the derived class, or subclass, of the PlainBox class. To indicate that ToyBox is derived from PlainBox, we use the following syntax in the class header of ToyBox:

```cpp
class ToyBox : public PlainBox<ItemType>
```

Any instance of the derived class is also considered to be an instance of the base class and can be used in a program where any of the base class can be used. Also, when the keyword public is used with the base class, any of the publicly defined methods or data fields in the base class can be used by instances of the derived class. In C++, a derived class inherits all the members of its base class, except the constructors and destructor. That is, a derived class inherits the data and methods of the base class in addition to the methods it defines, though it can access only publicly defined members.

As you see in Listing C1-5, ToyBox only defines the constructors and new methods specific to it, it has no need to revise any methods of the base class. The methods setItem and getItem are inherited from the PlainBox class and can be used in your ToyBox class.

LISTING C1-5 Template header file for the class ToyBox
```cpp
/** file ToyBox.h */
#ifndef TO_BOX
#define _TO_BOX
#include "PlainBox.h"

enum Color {BLACK, RED, BLUE, GREEN, YELLOW, WHITE};
template<class ItemType>
class ToyBox : public PlainBox<ItemType>
{
private:
    Color boxColor;
public:
    ToyBox();
    ToyBox(const Color& theColor);
    ToyBox(const ItemType&theItem, const Color& theColor);
    Color getColor() const;
}; // end ToyBox
#include "ToyBox.cpp"
#endif
```

An instance of the class ToyBox has two data fields—item, which is inherited, and boxColor, which is new. Because an instance of a derived class can invoke any public method in the base class, an instance of ToyBox has all the methods that PlainBox defines; new constructors; a compiler-generated destructor; and a new method getColor(). Although an instance of a derived class contains copies of inherited data fields, the code for inherited methods is not copied.

A class cannot access the private members of the base class directly, even though they are inherited. Inheritance does not imply access. After all, you can inherit a locked vault. In this event, you can inherit a locked vault, so you can access only the publicly defined members.

# C.1.42 Overriding Base-Class Methods

You can add any new members to a derived class as you like. Although you cannot revise a base-class private data fields and should not hide their names, you can redefine inherited methods; a method in a derived class overrides, or redefines, a method in the base class if the two methods have the same name and parameter declarations—that is, if the same signature.

To see an example of when we need to redefine a base-class method, let's consider the implementation of the MagicBox. This box magically changes any item placed inside to a copy of the first item it ever had. A simple way to do this is to store only the first item. All calls to setItem will then do nothing; therefore, every get returns the first item in the box.

```cpp
string favoriteToy = "Jack-in-the-Box";
toyBox<string> myCase(favoriteToy, RED); // A red toy box
string oldToy = myCase.getItem(); // oldToy is a Jack-in-the-Box
favoriteToy = "Spinning Top";
myCase.setItem(favoriteToy); // myCase now holds a Spinning Top
```
