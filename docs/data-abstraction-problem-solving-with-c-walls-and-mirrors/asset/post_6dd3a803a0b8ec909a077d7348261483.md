## 19.4.1 Searching and Traversing a Red-Black Tree

Because a red-black tree is a binary search tree, you can search and traverse it by using the algorithms for a binary tree. You simply ignore the pointers.

## 19.5 AVL Trees

An AVL tree—named for its inventors, Adelson-Velsky and Landis—is a balanced search tree. Because the heights of the left and right subtrees of any node in a balanced binary tree differ by no than 1, you can search an AVL tree almost as efficiently as a minimum-height search tree. This section will introduce you to the notion of AVL tree—which is a form of balanced binary tree—and leave the details for another course.

It is, in fact, possible to rearrange any binary tree of nodes to obtain an AVL tree with the minimum possible height $\lfloor\log_2(n+1)\rfloor$. Recall the algorithms developed in Section 16 that we use to save and restore a binary tree. You can start with an arbitrary binary search tree, save its values in a field, and construct from these values a new binary tree of minimum height. Although this approach may be appropriate in the context of a dictionary that is saved and restored, it requires too much work to perform every time an insertion or removal leaves the tree unbalanced. The cost of rebuilding could outweigh the benefit of searching a tree of minimum height.

The AVL algorithm maintains a binary tree with a height close to the minimum, but it is easy to do so with less work than would be needed to keep the height of the binary tree exactly equal to the minimum. The basic strategy of the AVL algorithm is to monitor the shape of the binary search tree; after each insertion or deletion, you check that the tree is still an AVL tree—that is, determine whether any node in the tree has left and right subtrees whose heights differ by more than 1. For example, suppose that the binary tree in Figure 19-3a is the result of a sequence of insertions and removals. The heights of the left and right subtrees of the root differ by 2. You can restore this tree's property—that is, its balance—by rearranging nodes. For example, you can rotate the tree so the node becomes the root, with left child and right child, as in Figure 19-3b.

Rotations are not necessary after every insertion or removal. For example, you can insert 40 into the AVL tree in Figure 19-3b and still have an AVL tree, as Figure 19-3c shows. It can be proven that the height of an AVL tree with $n$ nodes is always very close to the theoretical minimum of $\lfloor\log_2(n+1)\rfloor$. The AVL tree implementation of a dictionary is, therefore, one implementation that guarantees a binary search-efficiency. Usually, implementations that use a 2-3-4 tree or a red-black tree will be simpler.
