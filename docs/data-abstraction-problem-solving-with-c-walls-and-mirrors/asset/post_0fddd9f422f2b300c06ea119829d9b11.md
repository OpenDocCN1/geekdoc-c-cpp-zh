CHAPTER 1 Data Abstraction: The Walls

This chapter summarizes fundamental principles that serve as the basis for dealing with the complexities of large programs. The discussion reinforces the basic principles of programming and demonstrates that writing well-designed and well-documented programs is essential. The chapter also introduces algorithms and data abstraction and indicates how these topics relate to the main theme of problem solving. Data abstraction is a technique for increasing the modularity of a program—“walls” between a program and its data structures. During the design of a solution, you will discover need to support several operations on the data and therefore to define abstract data types (ADTs). Only after you have clearly specified the operations of an ADT should you consider data structures for it. This chapter will introduce a simple ADT and use it to demonstrate the advantages of ADTs in general.

In subsequent chapters, we examine ways of organizing and using data. As we focus on these new day, pay attention to all of the solutions we take at the basic principles discussed in this chapter.

## 1.1 Object-Oriented Concepts

Where did you write your last program? After reading the program specifications and going through the requisite amount of procrastination, most novice programmers simply begin to write code. Otherwise, their goal is to get their programs to execute, with correct results. Therefore, they run their programs, execute error messages, insert semicolons, change the logic, delete semicolons, and otherwise torture their programs until they work. Most of their time is probably spent checking syntax and program logic. Currently, your programs are better than when you wrote your first program, but are you able to write a large program using the approach you used? Maybe, but there are better ways.

Whereas a first course in computer science typically emphasizes programming issues, the focus of this book is on the broader issues of problem solving. The term problem solving refers to the entire process of making the statement of a problem and developing a computer program that solves it. This process requires you to pass through many phases, from gaining an understanding of the problem to be solved, to designing a conceptual solution, to implementing the solution to a computer program. In a large software project, problem solving requires not only the development of a computer program, but also the examination of workflow features and possible changes to how a user performs daily.

Object-oriented concepts

A solution specifies a system of interacting objects

Object-oriented analysis and design (OOAD) is a process for problem solving. From an object-oriented perspective, a solution is a computer program consisting of interacting classes of objects. An object has a set of characteristics and behaviors related to the solution. Each object is responsible for some aspect of the solution. A set of objects having the same type is called a class. An object of a class is also known as an instance of the class. When you create an object of a class, you instantiate it.

An object is an instance of a class

### 1.1.1 Object-Oriented Analysis and Design

Object-oriented analysis (OOA) is the process of understanding what the problem is and what the requirements of a solution are. It is the initial stage in problem solving. During analysis you get an accurate perception of what end users expect the solution to be and do. The requirements of a solution give you a description of what solution must be and what solution must do—without imposing how to design or implement that.

OOA explores a problem, not a solution
