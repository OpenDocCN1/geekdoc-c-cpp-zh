## 10.2.3 分析与大 O 符号

如果算法 $A$ 需要与 $f(n)$ 成比的时间，则称该算法的阶数为 $f(n)$，记作 $O(f(n))$。函数 $f(n)$ 称为算法的增长率函数。该符号使用大字母 $O$ 表示阶，被称为大 O 符号。如果一个大小为 $n$ 的问题需要与 $n$ 直接正比的时间，该问题就是 $O(n)$——即阶 $n$。如果时间需求与 $n^2$ 直接正比，问题就是 $O(n^2)$，以此此类推。

下面的形式化定义了这一点：

> 注意：算法阶的定义
> 如果存在常数 $k$ 和 $n_0$，使得对于所有大小 $n \ge n_0$ 的问题，$A$ 所需的时间单位不超过 $k \times f(n)$，则算法 A 的阶为 $f(n)$——记作 $O(f(n))$

$O(f(n))$ 定义中的要求 $n \ge n_0$ 将“足够大的问题”的概念形式化。通常情况下，$k$ 和 $n$ 的许多值可以满足该定义。

## 衡量算法的效率

以下示例说明了该定义：

- 假设一个算法解决大小为 $n$ 的问题需要 $n^2 - 3 \times n + 10$ 次。如果存在常数 $k$ 和 $n_0$，使得对于所有 $n \ge n_0$，$k \times n^2 > n^2 - 3 \times n + 10$，则该算法是 $O(n^2)$。事实上，如果 $k$ 为 3 且 $n_0$ 为 2，如图 10-2 所示，对于所有 $n \ge 2$，$3 \times n^2 > n^2 - 3 \times n + 10$。因此，算法对于 $n \ge n_0$ 所需的时间单位不超过 $k \times n^2$，因此是 $O(n^2)$。

- 在之前的第 10.2.1 节中，我们发现显示链链的前 $n$ 个项需要 $(n+1)(a+c) + n \times w$ 个单位。因为对于 $n \ge 1$，$2 \times n \ge n+1$，所以对于 $n \ge 1$，$(2 \times n) \times (a+c) + n \times w \ge (n+1) \times (a+c) + n \times w$。在对方程左侧提取 $n$ 后，我们得到对于 $n \ge 1$，$(2 \times a + 2 \times c + w) \times n \ge (n+1) \times (a+c) + n \times w$。

- 因此，该任务是 $O(n)$。这里，$k$ 为 $2 \times a + 2 \times c$，而 $w$ 和 $n_0$ 为 1。

同样，汉诺塔问题的定义的解决方案需要 $(2^m-1) \times m$ 个时间单位。因为对于 $m \ge 1$，$m \times 2^m > (2^m-1) \times m$，该解决方案是 $O(n^2)$。

$O(f(n))$ 定义中的要求 $n \ge n_0$ 意味着时间估计对于足够大的问题是正确的。换句话说，对于大多数有限数量的问题规模，时间估计太小了。例如，函数 $\log n$ 在 $n=1$ 时取值为 0。对于所有常数，$k \log 1$ 为 0 这一事实意味着一个不现实的时间需求；推测所有算法都需要超过 0 个时间单位，即使是解决大小为 1 的问题。因此，如果 $f(n)$ 是 $\log n$，你可以忽略大小为 1 的问题。

为了进一步戏剧化算法比例增长率的意义，请考虑图 10-3 中的表格和图表。部分 *a* 中的表格对于不同的 *n* 值，是某些增长率函数的近似值，按顺序排列如下：

常用函数的增长阶
$O(1) < O(\log n) < O(n) < O(n \times \log n) < O(n^2) < O(2^n)$

表格展示了函数值增长相对速度。图 10-3 显示这些增长率具有以下直观解释：

增长率的直观解释

- 增长率为 1 意味着问题的时间需求是常数，与问题大小 $n$ 无关。

- 对数算法的时间需求随问题增大而增长缓慢。如果你将问题大小平方，其时间需求仅翻倍。你在第 2 章学过的这种行为。记得二分搜索平分数组并搜索其中一半。

- $\log n$ 的底数不影响增长率，你可以省略它。

- $O(n)$ 是**线性**，随大小直接正比增长。

- $O(n \times \log n)$ 增长比线性快。

- $O(n^2)$ 是**二次**，随大小直接正比增长。

- $O(2^n)$ 是**指数**，增长极快。
