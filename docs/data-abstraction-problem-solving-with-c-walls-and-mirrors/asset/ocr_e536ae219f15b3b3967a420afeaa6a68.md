As you can see, the previous examples derive an algorithm's time requirement as a function of the problem size. To measure a problem's size depends on the application—typical examples are the number of nodes in a linked chain, the number of disks in the Towers of Hanoi, the size of array, or the number of items in a stack. The time units in the previous two statements must be the same before you compare the efficiency of the two algorithms. If we had written

Algorithm A requires n² / 5 seconds to solve a problem of size n

our earlier discussion indicates the difficulties with such a statement: On what computer does the algorithm require n² / 5 seconds? What caused the algorithm to require n² / 5 seconds?

What specifically do you want to know about the time requirement of an algorithm? The most important thing to learn is how quickly the algorithm's time grows as a function of the problem size. Statements such as

+   - Algorithm A time proportional to n²
- Algorithm B time proportional to n

each an algorithm's proportional time requirement, or growth rate, and enable you to compare algorithm A with another algorithm B. Although from these statements, you can determine the exact time requirement for either algorithm A or B for large problems, B requires significantly less time than A. That is, B's time requirement—as a function of the problem size n—increases at a slower rate than A's time requirement, because n increases at a slower rate.
