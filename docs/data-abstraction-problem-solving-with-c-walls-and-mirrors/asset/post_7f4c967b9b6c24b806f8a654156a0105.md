Although you can perform each retrieval operation by using only one of the indexes (that is, use the name index for retrieveName and the soc index for retrieveSoc), insertion and removal operations must update both indexes. For example, the remove-by-name operation removeByName(Jones) requires the following steps:

- 1. Search the name index for files and remove the index record.
- 2. Remove the appropriate data record from the data file, the soc index value ssn of this record.
- 3. Search the soc index file for ssn and remove this index record.

In general, the price paid for multiple indexing is more space and an additional overhead for each index whenever you modify the data file.
This chapter has presented at a very high level the basic principles of managing data in external storage. The details depend heavily on your specific computing system. Particular situations often mandate variations of the techniques described here or completely different approaches. In courses and work experience, you will undoubtedly learn more about these techniques.

# SUMMARY

- 1. An external file is partitioned into blocks. Each block typically contains many data records, and a block is the smallest unit of transfer between internal and external memory. That is, to access a record, you must access the block that it contains.
- 2. You can access the nth block of a direct access file without accessing the blocks that precede it. In this sense direct access files resemble random arrays.
- 3. Before you can process (for example, inspect or update) a record, you must read it from an external file into internal memory. Once you modify the record, you must write it back to the file.

- 4. Block accesses are typically quite slow when compared to other operations. Therefore, you must carefully organize a file so that you can perform tasks using only a few block accesses. Otherwise, response time can be very poor.
- 5. You can modify the merge sort algorithm, presented in Chapter 11, so that it can sort an external file of records without requiring all of records to be in internal memory at one time.
- 6. An index to a data file is a file that contains an index record for each record in the data file. An index contains both the key of the data record and the number of the block in the data file that contains the data record.
- 7. If a record is inserted or removed from a data file, you must make the corresponding change to the index file. If a file has more than one index, you must update each index file. Multiple indexing has overhead.
- 8. You can organize an index file by using hashing or a B-tree. These schemes allow you to perform the basic dictionary operations using only a few block accesses.
- 9. Although external hashing generally performs retrievals, insertions, and removals to be performed more quickly than a B-tree, it does not support such operations as traversals or range queries. This deficiency is one motivation for multiple indexing.
- 10. You can have several index files for the same data file. Multiple indexing allows you to perform different types of operations efficiently, such as retrieval by name and retrieval by Social Security number.

- 2. The problem of managing the blocks of an external data file indexed by a B-tree or an external hashing scheme is similar to managing memory for internal structures. When an external structure such as a data file needs more memory (for example, to insert a new record), it gets a new block from the list that the system manages. If the file contains n blocks, the system can allocate it to an (n + 1)th block. When the file needs a longer block, you can deallocate it and return it to the system.
The complication in managing external storage is that a file may have available space interspersed with data. For example, after you have removed a record from the middle of a data file, the block that contained record will have space available for at least one record. Therefore, you must be able to keep track of blocks that have space available for one or more records as recognize when blocks are completely empty (so that you can return them to the system).
