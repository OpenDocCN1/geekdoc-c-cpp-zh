
Adding to a text file. When you open a file, you can specify a second argument in addition to the file's name. This second argument has the form

```
ios::mode
```

where mode has values as in, out, or app. Until now, this argument has been omitted because ifstream files are by default opened for input, whereas ofstream files are opened for output. You can append a component to an ofstream by first opening it in append mode. Either the statement

```
ofstream outFile("Sample.DAT", ios::app);
```

or the statements

```
ofstream outFile;
outFile.open("Sample.DAT", ios::app);
```

prepare the file for output and position the file window after the file's last component. Thus, the contents of the file are retained, and you can write additional components.

Searching for a text file. Suppose that you have a text file of data about a-company's employees. For simplicity, assume that file contains two consecutive lines for each employee. The first line contains the employee's name, and the next line contains data such as salary.

Given the name of an employee, you can search for the file and then determine other information about this person. A sequential search examines the names in the order in they appear in the file until the desired name is located. The following function performs a sequential search. If the person is found, it returns that worker's salary; otherwise, it returns -1.0.

```
double getSalary(string fileToSearch, string desiredName)
{
  bool found = false;
  string nextName;
  double nextSalary = -1.0;
  ifstream inFile(fileToSearch);
  while (inFile && getline(inFile, nextName))
  {
  inFile >> nextSalary; // Salary for nextname.
  inFile.ignore(); // Ignore remaining whitespace in line.
  if (nextName == desiredName)
    found = true;
  } // end while
```

```
inFile.close(); // Always close file before return statement.
return nextSalary;
} // end getSalary
```

This function needs to look at all the names in the file before determining that a particular name does not occur. If the names were in alphabetical order, you could determine when the search passed the place in the file that contained the desired name, if it existed. In this way, you could terminate the search before needlessly searched the rest of the file.

Accessing a text file directly. Although you usually process a file sequentially, you can access the character stored at a given position without first reading the preceding characters.

The characters in a text file are numbered sequentially in order of appearance in the file, beginning with zero. The seekg function provides access to any character in the file, giving the character's number. For example,

```
myFile.seekg(15)
```

advances the file window to the character numbered 15, which is actually the 16th character in the file.
Immediately following this operation, you can read the character.

You can also locate a character relative to either the beginning of the file, the current position in the, or the end of the file by specifying—as the second argument to seek—

```
ios::mode
```

where mode is one of beg, cur, or end. Thus,
myFile.seekg(2, ios::cur)
```

seeks the character after the one at the present location of the file window.

## G.3 Binary Files

Files that are not text files are called binary (or nontext) files. Like a text file, a binary file is a sequence of bytes grouped together into file components. It is important to emphasize that each file component is an invisible entity. For example, each component of a binary file is an integer in the computer's internal representation. If you write the integer value 234 to a binary file, the system would write the computer's internal representation of 234, which is 0000000011011010 in binary, to the file, rather than the three ASCII characters 2, 3, 4, which are, respectively, 00110010, 00110011, and 00110100 in binary. If you could to look at the file, you would see gibberish. You create a binary file not by using an editor—as you can for a text file—but rather by running a program.

The statement

```
ofstream outFile(myFileName, ios::binary);
```

associates the stream variable outFile with the external binary file whose name is in the string variable fileName. A binary file has an end-of-file symbol at its end, just as a text file does. However, the notion of lines does not exist for a binary file, although a binary file might contain data that incidentally looks like an end-of-line symbol. Except for the differences noted here, C++ treats binary files in the same way that it treats text files.
