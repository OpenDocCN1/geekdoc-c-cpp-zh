# 19.5 AVL Trees

An AVL tree—named for its inventors, Adel'Son-Skii and Landis—is a balanced search tree. Because the heights of the left and right subtrees of any node in a balanced binary tree differ by no more than 1, you can search an AVL tree almost as efficiently as a minimum-height search tree. This section will introduce you to the notion of an AVL tree—which is the oldest form of balanced binary tree—and leave the details for another course.

It is, in fact, possible to rearrange any binary tree of nodes to obtain an AVL tree with the minimum possible height [log(n+1)]. Recall, for the algorithms developed in Section 16.4 of Chapter 16 that we use to save and restore a binary search tree. You can start with an arbitrary binary search tree, save its values in a field, and construct from these same values a new binary search tree of minimum height. Although this approach may appropriate in the context of a dictionary that is saved and restored, it requires too much work to perform every time an insertion or removal leaves the tree unbalanced. The cost of rebuilding could well outweigh the benefit of searching a tree of minimum height.

The AVL algorithm maintains a binary tree with a height close to the minimum, but it is easy to do so with less work than would be needed to keep the height of the binary search tree, exactly equal to the minimum. The basic strategy of the AVL algorithm is to monitor the shape of the binary search tree, after each insertion or deletion, you check that the tree is still an AVL tree. That is, determine whether any node in the tree has left and right subtrees whose heights differ by more than 1. You can restore this tree's property—that is, its balance—by rearranging nodes. Notice that you take care not to destroy the tree's ordering during the process of rebalancing.
