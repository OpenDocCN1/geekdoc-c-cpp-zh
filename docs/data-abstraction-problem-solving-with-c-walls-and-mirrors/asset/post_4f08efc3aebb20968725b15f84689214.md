
## h(4567) = h(7597) = 22

h will tell you to place the two items into the same array, table[22]. That is, the search keys 4567 and 7597 have collided.

Even if the number of items can be in the array at any one time is small, the only way to avoid collisions completely is for the hash table to be large enough that each possible-key value can have its own location. If, for example, Social Security numbers are the search keys, you would need an array location for each integer in the range 000000000999999. This situation would certainly require a good deal of storage! Reserving vast amounts of storage is impractical; collision-resolution schemes are necessary to make hashing feasible. Such schemes usually require that the hash function places items throughout the hash table.

To summarize, a typical hash function: own- Be easy and fast
- Place items evenly throughout the hash table

Note that the size of the hash table has the ability of hash function to distribute the items throughout the table. The requirements of hash function will be discussed in more detail later in this chapter.

## 18.4.1 Hash Functions

It is sufficient to consider hash functions that have an arbitrary integer as argument. If search key is not an integer, you can simply convert a search key into an integer. At the end of this section, you will see one way to do this. If your search key is a nine-digit employee ID number 001364825, you could select the first and last digit to obtain 35 as the index to the hash table. That is, $h(001364825) = 35$ (select the first and last digits). Therefore, using digit selection you would store the item search key 001364825 in table[1]. For example, the first three digits of Social Security number are based on the geographic region in which you live; you will map people from the same state into the same location. Digit-selection hash functions are simple and fast, but generally they do not evenly distribute the items in the hash table.

### Folding.

One way to improve the previous approach of selecting digits is to add the digits. The resulting process is known as folding. For example, you can add all the digits in 001364825 to obtain:

0+0+1+3+6+4+8+2+5 = 29

If you add all the digits from a nine-digit search key 001364825, you would store the item in table[29]. Notice that if you add all the digits you use only table[0] through table[8]. To change the size of the hash table, you can use groups of digits. For example, you can form groups of three digits from the search key 001364825 and add them as follows:

001+364+825 = 1190

For this hash function, if 1190 is larger than the size of the hash table, you can choose more than one function to search key. For example, you could select some of the digits from the search key before adding them, or you could apply folding to the previous result 29 and 97.

### Modulo arithmetic.

Modulo arithmetic provides a simple and effective hash function that we will use in the rest of this chapter. For example, consider the hash table has elements. In particular, if tableSize is 101, $h(x) = x \pmod{101}$ maps any integer $x$ into the range 0 through 100. For example, $h(001364825) = 12$, and so on. For $H(x) = x \pmod{tableSize}$, many $x$'s map to table[0], many $x$'s map to table[1], and so on. That collisions occur, you can distribute the dictionary items over all of table—by choosing a prime number as tableSize. In instance, 101 in the previous example is prime. The choice of tableSize will be discussed in more detail later in this chapter. For the typical hash table, 101 is much too small.

### Converting a string to an integer.

If your search key is a string—like name—you can convert it into an integer before applying the hash function $h(x)$. To do this, you could first assign an integer value to each character in the string. For example, the word "NOTE" you could assign the ASCII values 78, 79, 84, and 69 to the letters N, O, T, and E. Or, if you assign the values 1 through 26 to the letters A through Z, you could assign 14 to N, 15 to O, and 20 to E.

If you simply add these numbers, you will get an integer, but it will not be unique to the character string. For example, the word "TONE" will give you the same result. Instead, you can use the numeric value for each character in binary and concatenate the results. If you assign the values 1 through 26 A through Z, you obtain the following result for the word "NOTE":

N is 14, or 01110 in binary
O is 15, or 01111 in binary
T is 20, or 10100 in binary
E is 5, or 00101 in binary

Concatenating the binary values gives you the binary integer 011100011111100000101, which is 764,757 in decimal. You can apply the hash function mod hashTable for $x = 764,757$.

Remember that this book uses "mod" as an abbreviation for the mathematical operator modulo. In C++, the operator is %.

Now consider a more efficient way to compute 764,757. Rather than converting the previous binary number to decimal, you can evaluate the expression:

$14 \times 32^3 + 15 \times 32^2 + 20 \times 32^1 + 5 \times 32^0$

This computation is possible because we have represented character as binary number, and $2^i$ is 32. By factoring this expression, you can minimize the number of arithmetic operations. This technique is called Horner’s rule and results in:

$((14 \times 32 + 15) \times 32 + 20) \times 32 + 5 = 2997$

Clearly, if 2997 is larger than the size of the hash table, you want to alter the function by adding 29 and 97.
