A heap versus a binary search tree as a priority queue. How does a heap compare to a binary search tree as an implementation of a priority queue? If you know the maximum number of items in the priority queue, the heap is the better implementation. Because a heap is complete, it is always balanced, which is its major advantage. If the binary search tree is balanced, both implementations will have the same average performance for n items: they will be O(log n). The height of a binary tree, however, can increase during insertion and removal of entries, greatly log n and degrading the implementation's efficiency to O(n) in the worst case. The heap implementation avoids this decrease. In Chapter 19, you will see how to keep a search tree balanced, but the operations that do this are far more complex than the heap operations.

Finite, distinct priority values. If you have a number of distinct priority values, such as the integers 1 through 20, many items will likely have the same priority value. You could place items whose priority values are the same in the order you encounter them. A heap of queues accommodates this situation, one for each distinct priority value. To insert an item into the priority queue, you add the item's priority value to the heap, if it is not already there. Then you insert the item into the corresponding queue. To remove an item from a priority queue, you remove it from the front of the queue that corresponds to the highest priority value in the heap. If the removal leaves the queue empty, you remove the item from the heap. Programming Problem 7 at the end of this chapter treats priority values further.

# 17.4 Heap Sort

As its name implies, the heap sort algorithm uses a heap to sort an array of items that are in particular order. Suppose that we use a heap and an empty array whose size is the number of items in the heap. A call to peekTop gets the largest item in the heap, and we can place that item at the end of the array. A call to remove removes that from the heap. By repeatedly calling peekTop and remove, we can move items from the heap in descending order and place them sequentially decreasing positions in the array. The result is an array sorted into ascending order.

While this approach will work, it uses more memory and time than necessary. Let's start over an array of unordered values. Our first step would be to transform the array into a heap. Recall the method heapCreate from our implementation of the ADT heap in Section 17.2.2. This method transformed the array items, which is a data member of the class of heaps, into a heap. The body of heapCreate is simply the following:

```cpp
for (int index = itemCount / 2; index >= 0; index--)
    heapRebuild(index);
```

As the class ArrayHeap, both heapCreate and heapRebuild have access to the class's data members, including the array items and its number of entries, itemCount. To use heapRebuild in a heap sort, we must revisit it that it has the array and its size as parameters. Let's define heapRebuild as a function outside of ArrayHeap, as:

```cpp
void heapRebuild(int index, ItemType array[], int n)
```

After transforming the array into a heap, heap sort partitions the array into two regions—the Heap region and the Sorted region—as Figure 17-10. The Heap region is in array[0..last], and the Sorted region is in array[last+1..n]. Initially, the Heap region is all of array and the Sorted region is empty.

![](img/d0cb86b2f18b2db569968ad7c743510e_545_0.png)

Each step of the algorithm moves item i from the Heap region to the Sorted region. In this process, the following statements are true—they are the algorithm's invariant:

- The Sorted region contains the largest values in array[], and they are sorted in order—that is, array[n-1] is the largest, array[n-2] is the second, and so on.
- The items in the Heap region form a heap.

So that the invariant holds, i must be the largest value in the Heap region, and therefore i must be the root of the heap. To accomplish this, we exchange the item in the root of the heap with the last item in the heap—that is, exchange array[0] with array[last]—and decrement the value of last. As a result, the item swapped from the root into array[last] becomes the smallest item in the Sorted region (and is in the first position of the Sorted region). After the move, you must transform the Heap region back into a heap because the new root may be out of place. You can accomplish this transformation using heapRebuild() to trickle the item now in the root so that Heap region is again a heap. The following algorithm summarizes these steps:

```cpp
// Sort anArray[0..n-1]
heapSort(anArray: ArrayType, n: integer) {
    // Build initial heap
    for (index = n / 2 down to 0) {
        // Assertion: The tree at index is a semi
        heapRebuild(index, anArray, n)
        // Assertion: The tree at index is a heap
    }
    // Assertion: anArray[0] is the largest item in array[0..n-1]
    // Move the largest item in the Heap region—the root to the beginning
    // of the region by swapping items and then adjusting the size of the regions
    Swap(anArray[0], anArray[n-1])
    heapSize = n - 1 // Decrease the size of the Heap region, expand Sorted region
    while (heapSize > 1) {
        // Make the Heap region again
        heapRebuild(0, anArray, heapSize)
        // Move the largest item in the Heap region—the root—to the beginning
        // of the region by swapping items and then adjusting the size of regions
        Swap(anArray[0], anArray[heapSize])
        heapSize-- // Decrease the size of the Heap region, expand Sorted region
    }
}
```

Heap sort is (n × log n) If we begin with the array shown in Figure 17-9, the first steps of heap sort are the same as those shown in the figure, and they transform the array into a heap. Figure 17-11 traces the heap sort from that point. The C++ implementation of heap sort is left as an exercise. The analysis of efficiency of heap sort is similar to that of merge sort, as given in Chapter 11. Both algorithms are O(n × log n) in both worst and average cases. Heap sort has an advantage over merge sort that it does not require a second array. Quick sort is also O(n × log n) in the average case but is O(n²) in the worst case. It is generally the preferred sorting algorithm.
