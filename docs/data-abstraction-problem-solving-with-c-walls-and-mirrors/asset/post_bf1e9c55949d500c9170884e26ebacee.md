- **Termination.** The search algorithms terminate when they reach the destination city or when they exhaust all possibilities. All possibilities are exhausted when, backtracking to the origin city, no unadjacent cities remain. This situation occurs when boxes are boxed off in the trace and a return occurs to the point of the original city to the algorithm. For search 8, no unadjacent cities are adjacent to the origin when the stack becomes empty.

Thus, the two search algorithms really perform the identical action. In fact, provided that they use the same rule to select an unvisited city—for example, traverse the current city's list of adjacent alphabetically—they will always visit the identical cities in the identical order. The similarities between the algorithms are far more coincidence. In fact, it is possible to capture the actions of a recursive function by using a stack.

An important context in how the tie between stacks and recursion is explicitly utilized is common for a compiler to use a stack to implement a recursive function in a manner that greatly resembles the box trace. When a recursive call function occurs, the activation record must remember certain information. This information consists essentially of the same local environment that place in the boxes—values of both arguments and local variables and a reference to the point from which the recursive call was made.

You can use a similar strategy to implement a nonrecursive version of a recursive algorithm. You might need such a nonrecursive form to make it more efficient, as mentioned in Chapter 2. The previous discussion should give you a taste of the techniques for removing recursion from a program. You will encounter recursion removal as a formal topic in more advanced courses, such as compiler construction.

> Typically, stacks are used to implement recursive functions
> Each recursive call generates an activation record that is pushed onto a stack
> You can use stacks when implementing a nonrecursive version of a recursive algorithm
