- **终止。** 搜索算法在到达目标城市或耗尽所有可能性时终止。当回溯到起点城市且没有剩余的非相邻城市时，即意味着所有可能性都已耗尽。这种情况发生在追踪中的框被封锁，且算法返回到原始城市的起始点时。对于搜索 8，当栈为空时，起点城市周围没有相邻的城市了。

因此，这两种搜索算法执行的是完全相同的动作。事实上，只要它们使用相同的规则来选择未访问过的城市——例如，按字母顺序遍历当前城市的相邻列表——它们总是会以相同的顺序访问相同的城市。算法之间的相似性更多是巧合。事实上，可以使用栈来捕获递归函数的动作。

在栈与递归之间的纽带被显式利用的背景中，一个重要的点是：编译器通常使用栈来实现递归函数，其方式与框追踪（box trace）非常相似。当发生递归调用函数时，激活记录（activation record）必须记住某些信息。这些信息本质上由位于框中的相同局部环境组成——参数值、局部变量值，以及指向执行递归调用位点的引用。

你可以使用类似的策略来实现递归算法的非递归版本。正如第 2 章提到的，你可能需要这种非递归形式来提高效率。之前的讨论应该让你对从程序中移除递归的技巧有了初步了解。在更高级的课程（如编译器原理）中，你将遇到作为“消除递归”的正式课题。

> 通常情况下，栈被用于实现递归函数
> 每次递归调用都会生成一个并推入栈的激活记录
> 在实现递归算法的非递归版本时，可以使用栈

| 3 | 你可以使用栈来确定两个城市之间是否存在航班序列。栈跟踪已访问城市的序列，并允许搜索轻松回溯。然而，按照从起点到终点的正常顺序显示城市序列会很麻烦，因为起点城市在栈底，而终点在栈顶。 |
| 4 | 递归与栈之间存在强有的关系。大多数递归的实现都以类似于框追踪的方式维护激活记录栈。 |
