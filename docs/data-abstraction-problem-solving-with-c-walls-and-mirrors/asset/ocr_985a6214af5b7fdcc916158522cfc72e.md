# C.5.2 Abstract Classes

The previous example used a virtual setItem method so that a choice could be made during program execution between two implementations of the methodItem. We can use this same idea to assist our design of each ADT as a public interface that describes its functionality and is implementation independent. Declaring our ADT methods as virtual allows an application using our class to take advantage of polymorphism when the ADT's methods are invoked.

We avoid this error by writing our methods as pure virtual methods. A pure virtual method is a method that has no implementation. We can now create an abstract class which is one that has at least one pure virtual method. To tell the compiler that a method is a pure virtual method, you write = 0 before the semicolon at the end of the prototype, as in the example:

```
virtual void setItem(const Item& item) = 0;
```

Listing C1-9 defines the template class BoxInterface that is an abstract class, because it contains at least one pure virtual method. Remember that abstract classes cannot be directly instantiated.
