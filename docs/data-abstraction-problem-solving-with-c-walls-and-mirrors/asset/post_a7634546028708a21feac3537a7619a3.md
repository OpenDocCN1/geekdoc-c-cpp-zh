## B.5.1 Guarding Errors in Input Data

Suppose that you are computing statistics about the people in income brackets between $10,000 and $100,000. The brackets are rounded to the nearest thousand dollars: $10,000, $11,000, and so on to $100,000. The raw data is a file of one or more lines of the form

G N where N is the number of people with an income that falls into the G-thousand-dollar group. If several people have compiled the data, several entries for the same value of G might occur. As the user enters data, the program must add and record the number of people for each value of G. From the context, it is clear that G is an integer in the range 10 to 100, and N is a nonnegative integer.

As an example of how to guard against errors in input, consider an input function for this problem. The first attempt at writing this will illustrate common ways in which a program can fall short of the fail-safe ideal. Eventually you will see an input function that is much closer to the original solution.

A first attempt at the function might be

```cpp

This function has problems. If an input line contains unexpected data, the program will not behave reasonably. Consider two possibilities:

- The first integer on the input line, the function assigns to group, is not in the range LOW_END to HIGH_END. The reference incomeData[group - LOW_END] is incorrect, because it accesses an array element outside the bounds. This error also happens when the user tries to end the input by entering zeros for group and number.
- The second number on the input line, the function assigns to number, is negative. Although a negative value for number is valid, because you cannot have a negative number of people in an income group, the function will add to the group's array. Thus, the arrayData will be incorrect.

After the function reads values for group and number, it must check whether group is in the LOW_END to HIGH_END and whether number is positive. If either value is not in range, you handle the input error.

Suppose instead of checking the value of number before you add it to the array incomeData[group - LOW_END], you perform the addition and see whether the sum is positive. This approach is insufficient, you might add a negative value to an entry of incomeData without that becoming negative. For example, if number is -4,000 and the resulting entry in the array incomeData is 10,000, a negative value for number could remain undetected invalidates the results of the rest of the program.

One possible course of action for the function to take when data is invalid is to set an error flag and terminate. Another possibility is to set the error flag, ignore the bad input line, and continue. Which action is correct depends on how the program uses the data once it is read.

The following readData attempts to be as universally as possible and to make the function as adaptable as possible. When the function encounters an error in it, it returns to the calling module to determine the appropriate action—such as abort or continue—when an input error occurs. Thus, you can use the same function in many contexts and can easily modify the approach upon enormous.

```cpp
/**
 * readData program income statistics.
 * @param incomeData A tabletype of income statistics.
 * @pre The calling line contains exactly two integers in the form G N,
 * where N is the number of people in an income in a G-thousand-dollar group and LOW_END <= G <= HIGH_END. An input line with value zero for both terminates the input.
 * @post incomeData[G - LOW_END] is the total number of people with an income in the G-thousand-dollar group. The values are read displayed. If either G or N is erroneous (either G < LOW_END, G > HIGH_END, or N < 0), the function ignores the data line and continues execution.
 * @return If either G or N are erroneous (either G < LOW_END, G > HIGH_END, or N < 0) for any data line read. In this case, calling program should take action. The return value is true if the data line is error-free. */
bool readData(TableType incomeData)
{
    int group = -1;
    int number = -1; // Input values
    bool dataCorrect = true; // No data error found as yet
    bool userFinished = false;

    for (group = LOW_END; group <= HIGH_END; group++)
        incomeData[group - LOW_END] = 0;
    do {
        cout << "Please enter group and number of ";
        cout << "number, separated by a space: ";
        cin >> group >> number;

        cout << "Input line specifies that income group ";
        cout << group << "\ncontains " << number << "\n";
        if (group >= LOW_END) && (group <= HIGH_END) {
            if (number >= 0)
                // Input data is valid - add to tally
                incomeData[group - LOW_END] += number;
            else if (group == 0) && (number == 0)
                userFinished = true; // User is finished
            else
                // Error in input data:
                // Set error flag and ignore input
                dataCorrect = false;
        }
    } while (dataCorrect && !userFinished); // end do-while
    return dataCorrect;
} // end readData
```

Although this function will handle gracefully the most common input errors, it is not completely fail-safe. What happens if an input line contains only one integer? What happens if an input line contains nonexistent? The function would be more fail-safe if it read its character by character, converted the characters to an integer, and checked for the end of the input line. In most contexts, this would be a bit extreme. However, if the people who enter the data by typing nonintegers, you could alter the input function easily because the function is an isolated module. In any case, the function's initial comments should include any assumptions it makes about the data and an indication of what might make the program abort normally.
