The method removeSorted can call getPosition to determine where in the sorted list given entry exists or belongs. This time, however, we need to know whether the entry exists in the list. If it does not, we cannot remove it; removeSorted will return false when this is the case. Otherwise, the returned position will be positive, and removeSorted can call the list's method to delete the entry. We leave the implementation of removeSorted to you in Checkpoint 11.

The method getPosition. Implementing getPosition is somewhat harder than implementing the previous methods. To decide where in a sorted list entry exists or belongs, we need to compare it in the list, beginning with the first one. If the given entry is in the list, we obviously compare entries until we find a match. If it is not in the list, we want to search for the point where it belongs in the sorted list. We take advantage of the sorted order of the objects by using logic similar to that described in Section 12.2.2

**The remaining methods.** Each of the methods isEmpty, getLength, clear, and getEntry() of the ADT list has the same specifications as in the ADT list. Each can simply invoke the corresponding list method. For example, the method remove has the following implementation in SortedListHasA:

```
template<class ItemType>
bool SortedListHasA<ItemType>::remove(int position)
{
return listPtr->remove(position);
} // end remove
```

Efficiency issues. Except for some logic in getPosition, you can write the implementation quickly and with few, if any, errors. Saving time is attractive feature of using an existing class to build another. But in this particular implementation, several methods invoke getPosition, so their efficiency depends on getPosition's efficiency.

The method getPosition calls the list method getLength, which is an O(1) operation. Therefore we are not concerned with it. On the other hand, a loop handles the entries in the list at a time by invoking getEntry until the entry is located. The efficiency of getPosition depends on part of the efficiency of getEntry. However, the efficiency of getEntry depends on which implementation of the ADT you use. For the link-based implementation, getEntry is getEntry in a loop, getPosition is O(n²) in the worst case. Each time that getEntry retrieves the next entry in the list, it starts at the beginning of the chain. This is the cause of getPosition's inefficiency.
