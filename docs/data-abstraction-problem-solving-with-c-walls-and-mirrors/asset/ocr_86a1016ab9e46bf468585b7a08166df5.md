# Removal under external hashing of an index file. To remove the data record whose search key is searchKey, you take the following steps:

+   1. Search the index file for the corresponding index record. You apply the hash function to searchKey, letting
i = h(searchKey)

You search the chain of index blocks pointed by the entry table[i] for an index record whose key value equals searchKey. If you do not find such a record, you can conclude that the file does not contain a record whose search key equals searchKey. However, if you find an index record <searchKey,p>, you remove it from the index file after noting the block number p, which indicates in the data file you can find the data to be removed.

+   2. Remove the data record from the data file. You know that the data record is in block. You simply access this block, search for the block, remove the record, and write the block back to the file.

Observe that for each of the operations the number of block accesses is very low. You never have to access more than one block of the data file, and at worst have to access all of the blocks along a single chain of the index file. You can take measures to keep the length of each of the chains quite short (for example, one or two blocks), just as you can with internal hashing. You should make the size of the array large enough so that the average length of a chain is near zero, and the hash function should scatter the keys evenly. external balanced search tree using the techniques described in the next section.

The hashing implementation is the one you choose when need to perform removal, insertion, and removal operations on a large external dictionary. As is the case with internal hashing, this implementation is not practical for certain operations, such as sorted traversal, retrieval of the smallest or largest item, or range queries that require ordered data. When these types of operations are added to the basic dictionary operations, you should use a search-tree implementation instead of hashing.

# 21.3 B-Trees

Another way to search an external dictionary is to organize it as a balanced search tree. Just as you can apply external hashing to the index file, you can organize the index, not the data file, as an external search tree. The implementation developed here is a generalization of the 2-3 tree of Chapter 19.

You organize the blocks of an external file into a tree structure using block numbers for child pointers. In Figure 21-1a, for example, the blocks are organized into a 2-3 tree. Each of the file is a node and contains three child pointers, of each is the integer number of the child. A child pointer value of -1 represents the pointer of a null pointer, and thus, for example, a leaf will contain three child pointers with the value -1.

If you organize the file in a 2-3 tree, each node (block of the index file) would contain either or two index records, each of the form <key, pointer>, and three child pointers. The pointer position of an index record has nothing to do with the tree structure of the index file; pointer indicates the block (in the data file) that contains the data record whose search key equals keys. (See Figure 21-10b.) To help avoid confusion, the pointers in the tree structure of the index file will be referred to as child pointers.
