As you saw in Chapter 15, a complete tree of height $h$ is full to level $h$ and has level $h$ filled from left to right. 17-3a shows a complete binary tree with its nodes numbered according to a level-by-level scheme. The root is numbered 0, and the children of the root—which are at the next level of the tree—are numbered, left to right, and 1 and 2. The nodes at the next level are numbered, left to right, 3, 4, and 5. You place these nodes in the array `items` in numeric order. Thus, `items[i]` contains the node numbered `i`; 17-3b illustrates. Now, given any node index `i`, you can locate both of its children and its parent.

> The binary tree is complete and remains complete, you can use a memory-efficient array-based implementation

+   * Its left child, if it exists, is `items[2 * i + 1]`
* Its right child, if it exists, is `items[2 * i + 2]`
* Its parent, if it exists, is `items[(i - 1) / 2]`

Remember that the root in `items[0]` does not have a parent. This array-based representation requires a complete binary tree. If nodes were missing from the middle of the tree, the numbering would be thrown off, and the parent-child relationship among nodes would be ambiguous. This requirement implies that any changes to the tree must maintain its completeness.

As you see, an array-based representation of a heap is useful in the implementation of the ADT priority queue.
