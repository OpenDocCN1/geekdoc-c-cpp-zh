# G.1 File Input and Output

You have used files ever since you wrote your first program. In fact, your C++ source program is in a file that you probably created using a text editor. You can create and access such files outside of, and also independently of, any particular program. Files can also contain data that is either read or written by your program. This is type of file that concerns us here.

A file is a sequence of bytes that resides in actually storage, often a disk. Files are useful because they can be large and can exist after program execution. In contrast, for example, represent memory that is accessible only within the program that creates them. When program execution terminates, the operating system reuses its memory and changes its contents.

Because files can exist after program execution, they not only provide a record for human users, also allow communication between programs. Program A writes its output into a file that program B can use later for input. However, files that disappear after program execution are not unusual. Chapter 16 discusses such a file that can help balance a binary search tree. You can also use such file as a scratch pad during program execution when you have too much data to retain in memory at once.

Files are classified as follows. A text file is a file of characters that are organized logically into lines. The files that we write in C++ programs are text files. Because text files consist of characters, and characters by position number is usually inconvenient, you typically process a text file sequentially. A file that is not a text file is called a binary file or, sometimes, a general file or nontext file.

# G.2 Text Files

Text files are designed for easy communication with people. As such, these files are flexible and easy to use, but they are not as efficient with respect to computer time and storage as binary files.

One special aspect of text files is that they appear to be divided into lines. This illusion is often the source of confusion. In reality, a text file—like any other file—is a sequence of bytes, that a text file is a sequence of characters. An end-of-line character creates the illusion that a text file contains lines by making the file behave as if it were divided into lines.

When you create a text file by typing data at character, each time you press the Enter, or Return, you insert one end-of-line character into the file. When an output device, such as a printer or monitor, encounters an end-of-line character in a text file, the device moves to the beginning of the next line. In C++, this end-of-line symbol is \n.

In addition, you might find a special end-of-line character that follows the last component in a file. Such a symbol may not actually exist in the file, but C++ behaves as if one did. The defined constant EOF, for "end of file," represents this symbol within your program. This book assumes that all files—including the empty file—have both an end-of-line symbol and an end-of-file symbol. Figure G-1 depicts a text file with these special symbols.

C++ stream library provides three types: ifstream for input, ofstream, and ofstream for both input and output. You can think of a file as streams. To use a file, there are three simple steps:

1. Open the file.
2. Read data from the file or write data to the file.
3. Close the file.

# G.2.1 Opening and Closing Text Files

Opening a file. Before you read or write to a file, you need to open it. That is, you need to initialize the file with a name.

Alternatively, you can declare an input stream by

```
ifstream inputFile;
```

and then use the open method to associate it with the file's name:

```
inputFile.open("Ages.DAT");
```

Regardless of how you open a file, you can check the stream variable to see if the process was successful with writing

```
if (inputFile)
// Deal with failure to open file
```

Closing a file. You close a particular file—that is, disassociate it from a stream and free system resources—using the close method:

```
myFile.close();
```

Once a file is closed, it is no longer valid for input or output until a program opens it again.
