Do not use a recursive solution if it is inefficient and you have a clear, efficient iterative solution

However, you should not use recursion for the sake of using recursion. For example, you probably should not use the recursive function in practice. You can easily write an iterative factorial function, giving the iterative definition that was stated earlier in this chapter. The iterative function is as clear as the recursive one and more efficient. There is no reason to incur the overhead of recursion when its use does not gain. Recursion is truly valuable when a problem has no iterative solutions.

The second point about recursion and efficiency is that some algorithms are inherently inefficient. This inefficiency is a very different issue than that of overhead. It has nothing to do with how a compiler implements a recursive function, but is rather related to the technique that the algorithm employs.

As an example, consider the recursive solution for the multiplying problem that you can solve in this chapter:

```
rabbit(n) = if n is 1 or 2
  rabbit(n - 1) + rabbit(n - 2) if n > 2
```

The diagram in Figure 2-19 illustrated the complexity of rabbit(7). Earlier, you were asked to think about what the diagram would look like for rabbit(10). If you thought about this question, you may have come to the conclusion that such a diagram would fill up most of this. The diagram for rabbit(100) would fill up most of universe!

The fundamental problem with rabbit is that it computes the same values over and over. For moderately large n, the number of values are recalculated literally trillions of times. This enormous number of computations makes the solution infeasible, even if each computation requires only a trivial amount of work.

However, do not conclude that the recurrence relation is of use. One way to solve the problem is to construct an iterative solution based on this recurrence relation. The iterative solution goes forward backward and computes each value only once. You can use the following iterative function to compute rabbit(n) even for large values of n.

You can use rabbit's recurrence relation to construct an efficient iterative solution

```
/* Iterative solution to the rabbit problem. */
iterRabbit(int n) {
  // Initialize base cases:
  int previous = 1; // Initially rabbit(1)
  int current = 1; // Initially rabbit(2)
  int next; // Result when n is 1 or 2
  // Compute next rabbit values when n >= 3
  for (int i = 3; i <= n; i++) {
    current = rabbit(i - 1), previous = rabbit(i - 2)
    next = current + previous;
    // ... logic corrected for clarity
  } // end for
  return next;
}
```

Convert from recursion to iteration if it is easier to discover a recursive solution but maybe more efficient to use an iterative solution

Thus, an iterative solution can be more efficient than a recursive solution. In some cases, it may be easier to discover a recursive solution than an iterative solution. Therefore, you may need to convert a recursive solution to an iterative one. This conversion process is easy if your recursive function calls itself once, instead of twice. Be careful when deciding whether your function calls itself more than once.

Converting a recursive solution to an iterative one is even easier with the recursive call is the last action that the function takes. This situation is called tail recursion. For example, the function writeBackward exhibits tail recursion because its call is the last action that the function takes. Although its recursive call appears last in the function definition, fact last action is the multiplication. Thus, last call is not-recursive.

### A tail-recursive function

Recall the definition of writeBackward:

```
void writeBackward(string s)
{
    int length = s.size();
    if (length > 0)
    {
        // Write last character
        cout << s.substr(length - 1, 1);
        writeBackward(s.substr(0, length - 1)); // Write reverse
    } // end if
} // end writeBackward
```

Because this function is tail-recursive, its recursive call can simply repeat the function with altered arguments. You can perform this recursion by using an iteration that will be straightforward and often more efficient. For the following definition of writeBackward is iterative:

### Removing tail recursion is often as straightforward

```cpp
/* Iterative version */
void writeBackward(string s)
{
    int length = s.size();
    while (length > 0)
    {
        cout << s.substr(length - 1, 1);
        length--;
    } // end while
} // end writeBackward
```

Because tail-recursive functions are often less efficient than their counterparts, and because the conversion of a recursive function to an iterative one is rather mechanical, some compilers automatically replace tail recursion with elimination. Other forms of recursion is usually more complex and a task that you would need to undertake, if necessary.

## SUMMARY

- 1. Recursion is a technique that solves a problem by solving a smaller problem of the same type.
- 2. When constructing a recursive solution, keep the following four questions in mind:
    - a. How can you define the problem in a smaller problem of the same type?
    - b. How does each recursive call diminish the size of the problem?
    - c. What instance of the problem can serve as the base case?
    - d. As the problem size diminishes, will you reach this base case?
- 3. When constructing a recursive solution, you should assume that a recursive call is correct if its precondition has been met.
- 4. You can use the box to trace the activations of a recursive function. These boxes resemble activation records, which many compilers use to implement recursion. Although the box is useful, it cannot replace an intuitive understanding of recursion.
- 5. Recursion allows you to solve problems—such as the Towers of Hanoi—where iterative solutions are difficult to conceptualize. Even the most complex problems have straightforward recursive solutions. Some solutions can be easier to understand, describe, and implement than iterative.
- 6. Some recursive solutions are much less efficient than a corresponding iterative solution due to their inefficient algorithms and the overhead of function calls. In such cases, the iterative solution can be preferable. You can use the recursive solution, however, to derive the iterative solution.
- 7. If you can easily, and efficiently solve a problem by iteration, you should do so.
