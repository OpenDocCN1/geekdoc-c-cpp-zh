To use the STL classes, you must include the appropriate header file, which has the same name as the STL class. To use the class stack, for example, your code must have the following statement:

```
#include <stack>
```

To instantiate a stack, you must supply the type of item it will hold, just as you instantiated our ADTs. For example, the following statement creates a vector that can hold 10 items:

```
vector<string> cities(10); // Create a vector to hold 10 strings
```

All STL containers are part of the std:: namespace. Therefore, if you do not use the statement

```
using namespace std;
```

in your code, you must precede any reference to the container with std:: as shown here:

```
std::vector<string> cities(10); // Create a vector to hold 10 strings
```

In our ADTs, we use ItemType to represent the type of item stored in the collection. The STL header files use value_type or simply T to represent the item in a collection. If the collection is similar to our ADT dictionary, with key and item types, the STL uses key_type and mapped_type respectively.

## C.7.1 STL Container Adapters

The STL container adapters are stack, queue and priority_queue. These correspond to the ADTs stack, queue, and priority queue and optimized so that the operations listed below perform at O(1). These containers grow to accommodate new entries as they are added. When entries are removed, the size of the container decreases. Thus, each of these containers has a size exactly equal to the number of entries in it currently.

| OPERATION | DESCRIPTION |
| --- | --- |
| value_type& top() | Returns a reference to the top entry on the stack. |
| void push(value_type& item) | Pushes item onto the top of the stack. |
| void pop() | Removes the top entry from the stack. |

| OPERATION | DESCRIPTION |
| --- | --- |
| value_type& front() | Returns a reference to the front entry in the queue. |
| value_type& back() | Returns a reference to the last (back) entry in the queue. |
| void push(value_type& item) | Adds item onto the back of the queue. |
| void pop() | Removes the front entry from the queue. |

| OPERATION | DESCRIPTION |
| --- | --- |
| value_type& top() | Returns a reference to the front entry in the priority queue. |
| void push(value_type& item) | Inserts item into the priority queue. |
| void pop() | Removes the front entry in the priority queue. |

Listing C7-1 provides an example of how to use the STL stack.

```
LISTING C7-1 Example use of the STL stack
#include <iostream>
#include <stack>
using namespace std;
int main() {
    stack<int> aStack;
    // Right now, the stack is empty
    if (aStack.empty()) {
        cout << "The stack is empty." << endl;
    }
    for (int j = 0; j < 5; j++) {
        aStack.push(j); // Places items on top of stack
    }
    while (!aStack.empty()) {
        cout << aStack.top() << " ";
        aStack.pop();
    }
    return 0;
} // end main
Output
The stack is empty.
4 3 2 1 0
```

## C7.1.2 Sequence Containers

The elements in a sequence container are ordered in a linear sequence and can be accessed, inserted, and removed by position. Similar to the arrangement in traditional arrays, the positions in sequence containers are numbered from 0 to size - 1. The **front** of these containers is at position 0, and the **back** is at position size - 1.

The sequence containers are: array, vector, deque, list, and forward_list. Let's consider each of these containers.

The **sequence container array** . As part of the recent C11 standard, the STL array provides a fixed-size container that is implemented as a traditional array, unlike other STL containers, an STL array container cannot grow or shrink in size. You can access individual elements in an STL array just as you access elements in a traditional way, by using the operator [ ]. An advantage of an STL array over traditional C++ arrays is the method that allows for range checking. For example, a traditional array declared as

```
int myArray[5];
```

permits the programmer to access elements beyond the memory allocated to the array by using an expression as myArray[24]. This leads to unpredictable results and a common source of errors in a program.

An STL array declared as

```
array<int> mySTLArray(5);
```

would have the same issue if the programmer used the expression myArray[24]. In situations where accessing elements outside the bounds of the array is possible, it is better to use an expression such as mySTLArray.at(24). This expression will throw an out_of_bounds exception that you can catch, enabling you to fix the error and allow the program to continue execution safety.

Two other important features of the STL array are its size method—enabling you to determine how many locations are in the array—and the availability of iterators.

### ARRAY OPERATIONS

| OPERATION | DESCRIPTION |
| --- | --- |
| value_type& front() | Returns a reference to the front entry in the array. |
| value_type& back() | Returns a reference to the last (back) entry in the array. |
| value_type& at(size_type n) | Behaves the same as [ ], but performs a bounds check. |
| void fill(const value_type& val) | Fills the array with val. |
| iterator begin() | Returns an iterator to the first element of the array. |
| iterator end() | Returns an iterator to the last element of the array. |
| reverse_iterator rbegin() | Returns a reverse iterator to the last element of the array. |
| reverse_iterator rend() | Returns a reverse iterator to the first element of the array. |

Other sequence containers have many operations. For example, vector and deque permit access to specific locations using [ ], but list is for sorting. These containers can grow and shrink as entries are added and removed.

### COMMON TO SEQUENCE CONTAINERS

| OPERATION | DESCRIPTION |
| --- | --- |
| value_type& front() | Returns a reference to the front entry in the container. |
| value_type& back() | Returns a reference to the last (back) entry in the container. |
| void push_back(value_type& item) | Adds item onto the back of the container (grows container). |
| void pop_back(value_type& item) | Removes the entry from the container (shinks container). |
| void resize(uint newSize) | Resizes the container to have newSize elements. |
| void clear() | Destroys all entries in the container, and resizes to 0. |
| void insert(uint position, value_type& item) | Inserts item at position and grows the container. |
| void insert(iterator position, value_type& item) | Inserts item at position and grows the container. |
| void erase(uint position) | Removes element from the container (shinks container). |
| void erase(iterator position) | Removes element from the container (shinks container). |
| iterator begin() | Returns an iterator to the first element of the container. |
| iterator end() | Returns an iterator to the last element of the container. |
| reverse_iterator rbegin() | Returns a reverse iterator to the last element of the container. |
| reverse_iterator rend() | Returns a reverse iterator to the first element of the container. |

The STL class vector. The STL vector is implemented using dynamic arrays so that it can increase in size as necessary. Access individual elements in a vector just as you do for an STL array using [ ] or at. Since vectors are stored in an array in a contiguous sequence of memory locations, vectors are good for accessing elements by either position or iteration, and for adding elements to or removing elements from the back.

### ADDITIONAL VECTOR OPERATION

| OPERATION | DESCRIPTION | EFFICIENCY |
| --- | --- |
| value_type& at(size_type n) | Behaves the same as [ ], but performs a bounds check. | O(1) |

The STL container deque. The STL container deque allows access to individual elements using [ ] and enables the efficient addition and removal of entries at both its front and back. Unlike our ADT, the deque permits insertion(insert) and removal(erase) from the interior of the container.

The deque does not use contiguous memory locations, but stores sequences of its entries in multiple blocks of memory that tracks internally. While this makes the deque more complex to implement, it enables to grow in size more efficiently, since additional memory can be allocated without the need to copy all existing entries into the new elements.
