# # C++ Documentation Systems

Documenting programs has never been a very enjoyable task. With the advent of the javadoc documentation system, commenting Java programs is at least less tedious. Inspired by javadoc, others have produced utility software to process documentation for other programming languages, including C++. Documentation tools like doxxygen (oxygen.net) and DOC++ (docpp.source-forge.net) read C++ source code and generate HTML-based documentation from javadoc-style comments embedded within the code. The comments in this book assume that oxygen will prepare the documentation.

The oxygen tool extracts the header for the class, the headers for all public methods, and methods that are written in a certain form. No method bodies and private items are extracted.
For a comment to be extracted, the comment must satisfy two conditions:

+   - The comment must occur immediately before a public class definition or the header of a public method.
- The comment must begin with /** and end with */ and is a special form of the C++ multiline comment /* ... */.

Inside the comment, oxygen identifies different aspects of the documentation, such as the programmer's name and a method's parameters and return value. Doxygen tags with the symbol @. Note that some oxygen tags differ from those used by javadoc.

+   - @author lists the name of a class's programmer.
- @file identifies the name of the file containing a class.
- @param identifies a method's parameter by name and includes its description.
- @post identifies a method's postcondition.
- @pre identifies a method's precondition.
- @return describes a method's return value.
- @throw lists an exception that a method can throw.

You write @param tag for each parameter in a method. You should list these in the order of which the parameters appear in the method's header. After the @param tag, you give the name and description of the parameter. For example, for the parameter customer, you might write

@param customer The string that names the customer.
