## 19.2.3 Inserting Data into a 2-3 Tree

Because the nodes of a 2-3 tree can have two or three children and can contain one or two values, you can insert items into the tree while maintaining its shape. The following paragraphs describe the sequence of insertions that produced the 2-3 tree shown in Figure 19-6b from the original tree in Figure 19-5b.

Insert 39. As is true with a binary search tree, the first step in inserting a node into a 2-3 tree is to locate the node where the search for the value to be inserted would terminate. To do this, use the strategy of the FindItem algorithm given previously; an unsuccessful search will always terminate at a leaf. In the tree of Figure 19-5b, the search for 39 terminates at the leaf <40>. (We will use this angle-bracket notation to denote a node and its contents.) Because this node contains only one item, you can simply insert the new item into this node. The result is the 2-3 tree in Figure 19-7.

Insert 38. In a similar manner, you would search the tree in Figure 19-7 for 38 and find that the search terminates at the node <39 40>. You cannot place 38 in this node, as Figure 19-8a illustrates, because a node cannot contain three values. You arrange these three values, however, into the smallest (38), middle (39), and largest (40) values. You can move the middle value (39) up to the node's parent p and separate the remaining values (38 and 40) into nodes that you attach to p as children, as Figure 19-8 indicates. Because you chose to move up the middle value of <38 39 40>, the parent correctly separates the values of its children; that is, 38 is less than 39, which is less than 40. The result of the insertion is the 2-3 tree in Figure 19-8.

**Insert 36.** The search for 36 terminates at the node <30 38> in Figure 19-9, but the node has no room for 36, as Figure 19-10a indicates. Thus, you arrange the three values 36, 37, and 38 into the smallest (36), middle (37), and largest (38) values, as you did. You then try to move the middle value (37) up to the node's parent <30 39> and give the parent the smallest (36) and largest (38) values, as Figure 19-10b illustrates. However, the node <30 39> cannot contain three values and have four children. This situation is familiar, with the slight difference that the node is not a leaf but has four children. As you did before, you divide the node into the smallest (30), middle (37), and largest (39) values and move the middle value to the node's parent. Because you are splitting an internal node, you must account for its four children—what happens to nodes <10 20>, <36>, and <40>? The solution is to attach the left pair of children—<10 20> and <36>—to the smallest value (30), and attach the right pair of children—<38> and <40>—to the largest value (39), as shown in Figure 19-10. The final result of this insertion is the 2-3 tree in Figure 19-10d.

Question 1 To be sure that you fully understand the insertion algorithm, insert 32 into the 2-3 tree in Figure 19-11. The result should be the tree in Figure 19-6b. Once again, compare this with the binary search tree in Figure 19-6a and notice the dramatic advantage of the 2-3 tree strategy.

The insertion algorithm. Let's consider the general strategy for inserting an item into a 2-3 tree. To begin, locate the leaf that the search for the new item would terminate. If the leaf does not contain two items, insert the new item into the leaf, and are done. If the leaf already contains two items, you must split it into two nodes, $n_1$, and $n_2$. As Figure 19-12 illustrates, you place the smallest item $S$ into $n_1$, place the largest item $L$ into $n_2$, and try to move the middle item $M$ up to the leaf's parent. If the parent has room for a new item—as is true here—$n_1$ and $n_2$ become children of the parent, and you are finished. The parent now has three children and contains two items.

> When a leaf would contain three items, split it into two nodes

When an internal node would contain three items, split it into two nodes and accommodate its children

On the other hand, if the parent cannot accommodate the item moving up, you must split the parent, as follows. You split an internal node $n$ that contains three items by using the process just described for a leaf, except that you take care of $n$'s four children. As Figure 19-13 illustrates, you split $n$ into $n_1$ and $n_2$, place $n$'s $s$ into $n_1$, attach $n$'s largest item $L$ into $n_2$, attach $n$'s two right children to $n_2$, and move $n$'s middle item $M$ up to $n$'s parent.

When the root would contain three items, split it into two nodes and create a new root

After this, the process of splitting a node and moving an item up to the parent continues until a node is reached that has only one item before the insertion and has only two items after it takes on a new item. Notice in the previous sequence of insertions that the tree's height never increased from its original value of 3. In general, as long as there is at least one node containing only one item on the path from the root to the leaf into the new item is inserted. The insertion strategy of a 2-3 tree has postponed the growth of the tree's height more effectively than the strategy of a basic binary search tree.

When the height of a 2-3 tree grows, it does so from the root. An increase in the height of a 2-3 tree will occur if every node on the path from the root of the tree to the leaf into the new item is inserted. In this case, the recursive process of splitting a node and moving an item up to the node's parent will eventually reach the root $r$. When this occurs you split $r$ into $r_1$ and $r_2$ exactly as you would any other internal node. However, you must create a new node that contains the middle item of $r$ and becomes the parent of $r_1$ and $r_2$. Thus, the new node is the root of the tree, as Figure 19-14 illustrates.
