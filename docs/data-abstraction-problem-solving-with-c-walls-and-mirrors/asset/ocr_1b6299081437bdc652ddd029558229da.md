# 19.1 Balanced Search Trees

As you saw in the chapter, the efficiency of the binary search tree implementation of the ADT dictionary is related to the tree's height. The operations add, remove, and get follow a path from the root of the tree to the node that contains the desired item (or, in the case of the add operation, to the node that is to become the parent of the new item). At each node along the path, you compare a given value to the search key in the node and determine which to search next. Because the maximum number of nodes on a path is equal to the height of the tree, the maximum number of comparisons that the dictionary operations require is equal to this height.

As you know, the height of a binary search tree of n nodes ranges from a minimum of 0 to a maximum of $\lceil\log(n+1)\rceil$. As a consequence, locating a particular item in a binary search tree requires a sequential search of n comparisons; thus a search of a binary search tree can be as inefficient as a sequential search of linked nodes or a binary search of a sorted array. Efficiency was the primary reason for developing the binary search tree implementation of the dictionary: we wanted to perform a search of a linked structure as efficiently as we could a binary search of an array. Thus, we want to optimize the behavior of the binary search tree.

What affects the height of a binary search tree? As you learned in Chapters 15 and 16, the height of the tree is sensitive to the order in which you insert or remove items. For example, a binary search tree that contains the items 10, 20, 30, 40, 50, 60, and 70.
