Although just the operations add, remove, and getItem in the previous set of operations are sufficient for some applications, you cannot delete significant things without additional operations. For instance, you cannot display all the dictionary items, because you cannot retrieve a item unless you know the value of its search key. You cannot display the entire dictionary unless you traverse the dictionary.

The traverse operation visits each item in the dictionary once. In defining this operation, you must specify the order in which the traverse visits the items. One common specification is to visit the items in order sorted by search key, but you do not care about the order in which the items are visited. As you will see, the way you define traverse—if you request it at all—can affect the way you implement the dictionary.

> **Note:** Search keys
The concept of a search key for the dictionary items is essential to the implementation of the dictionary. It is important that the value of the search key remains the same as the item stored in the dictionary. Changing the search key of an existing entry in the dictionary could make that entry or other dictionary entries impossible to find. Thus, the client must not be able to modify the value of an entry's search key once that entry is in the dictionary.

Like the operations for the ADT binary tree, traverse has a visit function as its argument. Because it can visit any number of things—including the dictionary via the ADT operations—traverse is a versatile operation. We illustrate this with three brief examples, in which the dictionary contains the data for the items listed in Figure 18-1.

Examples: Each of the following tasks will use the dictionary name as the search key. The class City contains all the information for a city, including its name, country, and population. The class has accessor and mutator methods for each of these pieces of data.

+   **Display, in alphabetical order, the name of each city and its population.** This requires you to write the city names alphabetically. Since the city names are search keys, traverse must visit items alphabetically by search key. You post the name of the function getItem(anItem: ItemType): void
