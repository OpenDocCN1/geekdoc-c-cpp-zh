C++ has two families of exceptions that function can throw. You can select one of these or derive a class of them. Although the exception in a throw statement does not need to be derived from a standard C++ exception class, it is a good programming practice to do so. Figure C3-1 shows the family of exception classes provided by C++.

Exceptions derived from runtime_error or one of its derived are thrown by errors that are detectable at runtime, such as division by zero or numeric overflow. If such an exception is thrown, the program will halt, unless it is caught by an assertion. Unlike assertions, however, when a runtime_error exception is thrown, it can contain a message that is displayed to the user giving details about the error and the program remains handled.

Classes derived from the logic_error class represent errors in the logic of the program, such as a precondition or a failure to satisfy a condition, that you could detect before the program executes. In findBox example, if we wanted to throw an exception to indicate the failure to find the target string, we would write:

```cpp
if (!found) {
    throw logic_error("Target not found in box!");
}
```

When we throw exceptions, we first test for an error or unusual condition using an if statement. Then if one occurs, we use the throw statement to throw an exception containing a message to our client.

To restrict the exceptions that a function or method can throw, you include a throw clause in its header. This allows the client to know that the function might throw an exception. A throw clause consists of the keyword throw followed by a list of exception types separated by commas and enclosed within parentheses. For example, here is the prototype of our findBox function with a throw clause added:

```cpp
PlainBox<string> findBox(PlainBox boxes[], int size, string target) throw(logic_error);
```

# C++ INTERLUDE 3 Exceptions

LISTING C3-3 Revised findBox function that throws an exception

PlainBox<string> findBox(PlainBox<string> boxes[], int size, string target) throw(logic_error)

```cpp
{
    int index = 0;
    bool found = false;
    while (!found && (index < size))
    {
        if (target == boxes[index].getItem())
            found = true;
        else
            index++;
    } // end while
    if (!found)
        throw logic_error("Target not found in a box!");
    return boxes[index];
}
```

**Programming Tip:** Including a throw clause in a function specification ensures that the function can only throw those exceptions. An attempt by the function to throw any other exception will result in a runtime error. Omitting a throw clause allows a function to throw any exception.

**Note:** Standard exceptions
The header <stdexcept> defines several exceptions. The header contains two kinds: runtime exceptions and logic exceptions.
The runtime exceptions are:

| Exception | Description |
| :--- | :--- |
| overflow_error | Arithmetic overflow occurred |
| range_error | Range error occurred |
| underflow_error | Arithmetic underflow occurred |

The logic exceptions are:

| Exception | Description |
| :--- | :--- |
| invalid_argument | Invalid argument used |
| length_error | An attempt was made to create an object that was too large |
| out_of_range | The value was out of range |

**Note:** If an exception occurs in the middle of a try block, the destructors of all objects local to that block are called. This ensures that all resources allocated that block are released, even if the block is not completely executed.

# Handling Exceptions 234

In the previous section, we looked at how to throw an exception. In this section, we look at how a client can handle. To handle an exception, code consists of two pieces. The first piece, the try block, contains the statements that might throw. The second piece consists of one or more catch blocks. Here is the general syntax for a try block followed by catch block:

```cpp
try {
    // statements that might throw an exception
} catch (ExceptionClass) {
    // statements that react to the exception
}
```

The statements within the try block execute as if the block was not there. If an exception occurs, execution immediately transfers to the catch block. If the block completes, execution continues with the statement after.

Programming Tip: An important implementation detail of a try block is that it should contain as few statements as possible—ideally, only the statement that throw exception. Keeping the try block small reduces the risk of either important code not being executed or allocated memory not deallocated.

The syntax for a catch block resembles that of a function definition. This identifier—called a catch block parameter—provides a name for the exception that can be used within the catch block. Although a catch block is not a function, throwing an exception is like calling a catch block as if it were. The catch block parameter represents the exception object provided by the throw statement.

The steps taken in a catch block vary from situation to situation and can be as simple as doing nothing or displaying an error message, or as elaborate as tasks that update variables and retry the function that threw the exception. Every exception class in the C++ Standard Library defines the accessor method what(), which returns a descriptive string when the exception is thrown. The body of the catch block can display this string to provide an indication of the exception.
