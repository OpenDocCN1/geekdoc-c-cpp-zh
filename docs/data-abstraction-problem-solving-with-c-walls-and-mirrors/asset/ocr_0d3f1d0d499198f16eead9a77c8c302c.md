Another way in which you should make a program fail-safe is to each function check its precondition. For example, consider the following function, factorial, which returns the factorial of an integer:

```
/** Computes the factorial of an integer.
 * @param n Given integer.
 * @pre n > 0.
 * @post None.
 */
int factorial(int n) {
    int fact = 1;
    for (int i = n; i > 1; i--) {
        fact *= i;
    }
    return fact;
} // factorial
```

The initial comments in this function contain a precondition—information about what assumptions are made—as always be the case. The value that this function returns is only if the precondition is met. If n is less than zero, the function will return the incorrect value of I. In the context of the precondition for which this function was written, it may be reasonable to make the assumption that n will never be negative. That, if the rest of the program is working correctly, it will call factorial only with correct values of n. Ironically, this observation gives a good reason for factorial to check the value of n: If n is less than zero, the warning that results from the check indicates that something might be elsewhere in the program.

Another reason the function factorial should check whether n is less than zero is that the function should be correct outside the context of its program. If, if you borrow the function for use in another program, the function should warn you if you use it incorrectly by passing it an n that is negative. A stronger check than the statement of the precondition in a comment is desirable.

> Note: A function should state its assumptions and, when possible, check whether its arguments conform to these assumptions.

In this example, factorial could check the value of n and, if it is negative, return zero, because factors are never zero. The program that uses C++ could check for this unusual value. Alternatively, factorial could abort execution if it is negative. Many programming languages, including C++, provide a mechanism for handling every exception. A module indicates that an error has occurred by throwing an exception. A module reacts to an exception by catching the exception and executing code to deal with the error condition. C++ Interlude provides more information about exceptions.

C++ also provides a convenient function assert(expression) that displays an informative message and aborts a program if expression is zero. You can use assert to check for both error conditions and the validity of preconditions within your program. C++ Interlude 3 provides more information about assert.
