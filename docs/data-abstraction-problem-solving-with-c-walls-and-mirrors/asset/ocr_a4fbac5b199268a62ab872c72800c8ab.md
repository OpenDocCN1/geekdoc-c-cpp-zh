# C++ INTERLUDE 1 C++ Classes

Header (.h), or specification, files in C++ provide a mechanism to partially separate the design of a class from the implementation in the source, (.cpp), the header file must also contain a description of the data fields for the class and any private methods used by the class. A client does not need to know about the private methods or data fields to use the class in a program. To provide a public interface for an ADT, you can write an abstract class, thereby separating design from implementation. An abstract class allows the client to take full advantage of polymorphism when using our class.

To introduce these concepts, let's look at a simple problem that illustrates all three of the fundamental concepts of object-oriented programming: encapsulation, inheritance, and polymorphism.

# C1.1 A Problem to Solve

Suppose that you are creating a video game asked you to and develop a group of classes to represent three types of boxes carried by the game. Each type of box can only hold one item. A character can put an item in the box or look at the item in the box. The three types of boxes are:

+   - Plain box—a plain box that holds only one item.
- Toy box—a box that has color and holds only one item.
- Magic box—a box that holds only one item, but magically changes it to the first item that was stored in the box.

Let's begin by designing an ADT plain box. It is the simplest of the three boxes, and we may be able to use its implementation for the other two boxes. Since game characters can only place items in the box or look at them, the box needs only two public methods, setItem to place an item in the box or getItem to get the stored item. Here is the UML notation for these methods:

```
+setItem(theItem: ItemType)
+getItem(): ItemType
```

We define ItemType as the type of item stored in the box by using a typedef concept, to have the box hold a double, we can write

```
typedef double ItemType;
```

To have the box hold another type of data, we need only to replace the double with the new data type. Listing C1-1 shows the declaration of class PlainBox that would appear in a header file. To save space, we show only contents that describe the class element and omit the specifications, preconditions, and postconditions. We use the object-oriented concept of encapsulation to group together data—the item stored in the box—with the methods that operate on data: two constructors, a method setItem to change the item's value, and a method getItem to return the item's value.
