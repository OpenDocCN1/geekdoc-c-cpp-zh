+   a. Write pseudocode B-tree implementations of traversals and range queries that need to access entire data records, not only the search keys.
b. To reduce the number of block accesses required by these operations, various modifications of the basic B-tree structure are frequently used. The central idea behind such structures is to keep the data itself sorted. First, assume that you can keep the data file in sequential order—that is, the records are sorted within each block and the records in $B_i$ for $i=2,3$, and so on to the number of blocks in the file. Rewrite your implementations of the traversal and range-query operations to take advantage of this. How many block accesses does these operations require?
c. Because it is too inefficient to maintain a sequentially data file in the face of frequent insertions and removals, a composite scheme is often employed. One such possible scheme is as follows: If a data record belongs in block $B$ and $B'$, a new block is allocated and linked to $B$, allowing the new record to be inserted into its proper sorted location. The difficulty is that you must now view each index record in the B-tree as indicating possibly several blocks in a chain of blocks that might contain the corresponding data record. Rewrite the add, remove, getItems, and rangequery operations. What is the effect on their efficiency?
