One of the most frequently performed computing tasks is the maintenance of a collection of data in some specified order. Many examples easily come to mind, such as students placed in order by their names, baseball players listed in order by their batting averages, and corporations listed in order by their assets. The items in these examples are in sorted order. In contrast, the items on a grocery list might occur in the order in which they appear on the grocer's shelves, but they are probably not sorted by name. These items are ordered simply by their positions within the list.

## The ADT sorted list maintains items in sorted order

The ADT sorted list maintains its entries in sorted order. The problem of maintaining sorted data involves more than simply sorting data. You often need to insert new data item into a proper, sorted list. Similarly, you often need to remove some data item. For example, suppose your university maintains an alphabetical list of the students who are currently enrolled. The registrar must add names and remove names from this list because students constantly enter and leave school. These operations should preserve the sorted order of the data.

This chapter specifies the ADT sorted list and then implements it in several ways. A major goal of this chapter is to show you we can develop a class of sorted lists from an existing class of lists.

## 12.1 Specifying the ADT Sorted List

The ADT list leaves it to the client to manage the entries in a given collection. The client can maintain the entries in any order that meets its needs. Recall that when you use the `insert` operation of the ADT list, you specify both the new entry and its position within the list. The ADT sorted list differs from the ADT list that it inserts and removes items by their values and not by positions. For example, the sorted list insertion operation determines the proper position for the new entry according to its value. Since a sorted list is responsible for organizing its entries, it has no operation that inserts a new entry by position. If you were allowed to specify a new entry's position, you might destroy the order of the sorted list's entries.

> Note: The ADT sorted list is a container of items that determines and maintains the order of its entries by their values. For simplicity, we will allow the sorted list to contain duplicate items. Insisting that the sorted list contain only unique items is somewhat complicated, and we will leave this variation as an exercise.

What operations do we want for this ADT? We've already mentioned that you could add an entry to the sorted list. Since the sorted list determines the position of a new entry, you could ask the ADT for its position. That is, you could ask for the position of an existing entry or for the position in which a proposed entry would occur if you added it to the list. You could also ask the ADT for an entry at a particular position. And clearly you should be able to remove a particular entry by its value, but we could also remove an entry by its position in the sorted list. We will include both of these removals.

Let's item the sorted list's operations—including common ones like getting the current number of entries—and specify them more carefully. Notice that none of the operations on a sorted list involve the position of an entry that destroys the list's sorted order.

> Note: ADT sorted list operations
> * Test whether a sorted list is empty.
> * Get the number of entries in a sorted list.
> * Insert an entry into a sorted list.
> * Remove a given entry from a sorted list.
> * Remove the entry at a given position from a sorted list.
> * Remove all entries from the sorted list.
> * Look at (get) the entry at a given position in the list.
> * Get the position in a sorted list of a given entry.

The first methods are straightforward, but let's look more closely at getPosition. Given an entry in the sorted list, the method getPosition returns the position within the list, as you would expect. We number the entries beginning with 1, as we do for the ADT. But what if the entry is not in the sorted list? In this case, getPosition returns the position where it belongs. The returned number is negative, however, to signal that the entry is not in the list. For example, if the object is not in the sorted list it will return -3.

The sorted list also has, but not all, of the operations of an ADT. We have already mentioned adding an entry at a given position is not possible, otherwise the client could destroy the order of the sorted list. For this reason, the list's setEntry is not available for a sorted list. The other operations of the ADT however, are useful for a sorted list as well, including the ones that retrieve or remove the entry at a given position.

## 12.1.1 An Interface Template for the ADT Sorted List

The C++ interface given in Listing 12-1 formalizes our initial specifications of the ADT sorted list.

LISTING 12-1 A C++ interface for sorted lists

```
/** Interface for the ADT sorted list */
@file SortedListInterface.h */

#ifndef SORTED_LIST_INTERFACE
#define SORTED_LIST_INTERFACE

template<<class ItemType>
class SortedListInterface
{
public:
    /** Inserts an entry into this sorted list in its proper order
       so that the list remains sorted. */
    @pre None.
    @post newEntry is in the list, and the list is sorted.
    @param newEntry The entry to insert into the sorted list. */
    virtual void insertSorted(const ItemType& newEntry) = 0;
```
