## 15.3 The ADT Binary Search Tree

![](img/d0cb86b2f18b2db569968ad7c743510e_468_0.png)

The ADT binary search tree

Searching for an item is one operation for which the ADT tree is ill suited. The binary search tree corrects this deficiency by organizing its data by value. Recall that each node n in a binary tree satisfies the following three properties:

- * n's value is greater than all values in its left subtree $T_L$
- n's value is less than all values in its right subtree $T_R$
- Both $T_L$ and $T_R$ are binary search trees.

A recursive definition of a binary search tree

As an ADT, the binary search tree has operations that are like the operations for the ADTs you studied in previous chapters, in that they involve inserting, removing, and retrieving data. Unlike the position-oriented ADTs stack, list, and queue, like the ADT sorted list, the insertion, removal, and retrieval operations are by value, not by position. ## 15.3.2 Searching a Binary Search Tree

Consider again the search tree in 15-13. Each node in the tree contains a person's name. Suppose that you want to locate Elise in the binary search tree. The root node of the tree contains Jane, so if Elise is present in the tree, it must be in Jane's left subtree, because the search "Elisa" is ner "Jane" alphabetically. Because a binary search tree is recursive, it is natural to formulate recursive operations on the tree. Thus, you that Jane's left subtree is a also binary tree, so you use the same search strategy for Elise. The root of this tree contains Bob, and the search "Elisa" is greater than the search"Bob", Elise must be in Bob's right subtree. That right subtree is also a binary tree, and happens is in the root node of this tree. The search has located Elise.
