+   * A finite number of objects, each associated with a search key.

isEmpty() Task Sees whether this dictionary is empty.
Input: None.
Output: True if the dictionary is empty; or otherwise false.

getNumberOfItems() Task Gets the number of items in this dictionary.
Input: None.
Output: The number of items in the dictionary.

add(searchKey, newItem) Task Inserts an item into this dictionary to the item's search key.
Input: newItem is the item to be inserted; searchKey is the item's search key and differs from all search keys present in the dictionary.
Output: True if the insertion is successful, or false if not.

remove(searchKey) Task Removes the item with the given search key from this dictionary.
Input: searchKey is the search key of the item to be removed.
Output: True if the removal is successful, or false if not.

clear() Task Removes all entries from this dictionary.
Input: None.
Output: None.

getItem(searchKey) Task Gets an item with a given search key from this dictionary.
Input: searchKey is the search key of the item to be retrieved.
Output: The item with the given search key.

contains(searchKey) Task Sees whether this dictionary contains an item with a given search key.
Input: searchKey is the search key of the desired item.
Output: True if the dictionary contains the desired, or false if not.

traverse(visit) Task Traverses this dictionary and calls a client function for each item.
Input: The client function, which exists outside the ADT implementation.
Output: visit's action occurs for each item in the dictionary and possibly alters the item.

Various sets of dictionary operations are possible

You should realize that these operations are only one possible set of dictionary operations. A client might require a subset of these or others not listed here to apply the application at hand. It may also be beneficial to modify the definitions of some of the operations. For example, these operations assume that no two items have the same search keys. In many cases it is reasonable to expect duplicate search keys. If this is the case, you must redefine the operations to eliminate the ambiguity that would arise from duplicate search keys. For example, which item should getItem return if several the specified search key? You should tailor your definition of the ADT dictionary to the problem at hand.
