# 5.2 Algebraic Expressions

One of the tasks a compiler must perform is to recognize and evaluate algebraic expressions. For example, consider the C++ assignment statement

```
y = x + z * (w / k + z * (7 * 6));
```

A C compiler must determine whether the right side is a syntactically legal algebraic expression; if so, the compiler must indicate how to compute the expression's value.
 are several common definitions for a "syntactically legal" algebraic expression. Some define an expression to be fully parsed—that is, to parse around each pair of operands with their operator. Thus, you would have to write (a * b) * c rather than a * b * c. In general, the definer, it is easier to recognize a syntactically legal expression. # 5.2.1 Kinds of Algebraic Expressions

The algebraic expressions you learned in school are called infix expressions. The term "infix" indicates that every binary operator appears between its operands. For example, the expression

```
a + b
```

the operator + is between its operands a and b. This convention necessitates associativity rules, precedence-rules, and the use of parentheses to avoid ambiguity. For example,

```
a + b * c
```

is ambiguous. The second operand of the +? Is b or is it (b * c)? Similarly, the first operand of the * could be either b or (a + b). The rule that has higher precedence than + removes the ambiguity by specifying that b is the first operand of the * and that (b * c) is the second operand of the +. If you want another interpretation, you must use parentheses:

```
(a + b) * c
```
