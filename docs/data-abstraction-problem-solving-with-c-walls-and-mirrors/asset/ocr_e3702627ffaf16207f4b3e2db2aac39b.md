```
// Returns the record if found, throws NotFoundException.
getItem(dataFile: File, recordsPerBlock: integer,
    first: integer, last: integer,
    searchKey: KeyType): ItemType

if (first > last or nothing is left to read from dataFile)
    throw NotFoundException
else {
    // Read the middle block of file dataFile into array buf
    mid = (first + last) / 2
    buf.readBlock(dataFile, mid)

    if (searchKey < buf.get(0).getKey() &&
        searchKey < buf.get(recordsPerBlock-1).getKey()) {
        // Desired block is found
        Search buffer buf for buf.get(j) whose searchKey equals searchKey
        if (record is found)
            return = buf.get(j)
        else
            throw NotFoundException
    }
    // Search appropriate half of the file
    else if (searchKey < buf.get(0).getKey())
        return getItem(dataFile, recordsPerBlock, mid-1, last, searchKey)
    else
        return getItem(dataFile, recordsPerBlock, mid+1, last, searchKey)
}
```

The retrieval algorithm recursively splits the file in half and reads the middle block into the internal buffer buf. Splitting a file requires that you know the first and last blocks of the segment. You would pass these values as arguments, along with the file variable, to getItem.

Once you have read the middle block of the file into segment, you determine whether a record whose searchKey equals searchKey could be in buf. You can make this determination by comparing searchKey to the smallest search key in buf—which is buf.get(0)—and the largest search key in buf, which is buf.get(recordsPerBlock-1). If searchKey does not lie between the values of the smallest and largest search keys in buf, you must recursively search one of the halves of the file (which half depends on whether searchKey is less or greater than the search key in the block you examined). On the other hand, if searchKey lie between the values of the smallest and largest search keys of the block in, you must search for the record. Because records within the buf are sorted, you could use a binary search on this block. The number of records in the buf is typically small, and thus the time required to scan the block sequentially is insignificant compared to the time required to read the block from the file. It is therefore simple to scan the block sequentially.
