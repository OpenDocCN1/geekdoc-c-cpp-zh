### D.3 What About the Waterfall Method?

The RUP is probably new to you, as is another development process—the waterfall method—in which the solution is defined by sequentially moving through phases such as requirements-design, implementation, testing, and deployment. We think the waterfall method is inferior to RUP. However, you should know what it is. The waterfall method often results in the following actions:

- Systems analysts produce a set of documents specifying the proposed system.
- The requirements are passed to a design team that produces a set of design documents, which are passed to programmers.
- The code is passed to a testing team, which verifies that the code correctly implements the requirements specified by systems analysts at the beginning.

Notice that the phases occur one after the other. If systems analysts do not understand everything about the system and its environment, it is likely they will specify the wrong system as users' needs and other systems must be used, global environment, and so. Incorrect analysis will create a design that, when implemented, leads to a correct system for the problem.

The difficulty with trying to specify the requirements of proposed system upfront is that requirements are not predictable. Most things in the world today, especially in high-tech worlds, are highly speculative. Change is constant. This implies that requirements of any system might change at any time. The development process must allow the system to evolve and adapt to the changing environment. The waterfall method requires analysis to be omnipotent. For a system to succeed, the waterfall method should not be used. Using iterative, incremental, evolutionary development processes, however, allows feedback to guide the adaptation of the system to a correct solution.

Be careful not to impose the waterfall method on RUP. For example, the RUP's inception phase is not the same as the waterfall phase. During the inception phase, some but not all, requirements are specified and programmers also make sure feasibility estimate of cost to develop and identify significant risks that might doom the project. Trying to develop all use scenarios in the inception phase makes the system same as the waterfall method.

Further, the RUP's elaboration phase is not the same as the waterfall design phase. During the elaboration phase, but not all, design is done, and programmers also do analysis, coding, and testing. If the elaboration phase degrades to having one iteration, the development process becomes the waterfall method. Similarly, the RUP's construction phase is not only about implementation, and it is not the same as the waterfall implementation phase. ![](img/d0cb8b2f18bdb56968ad7c43510e_779_0.png)

## Mathematical Induction

Many proofs of theorems or invariants in computer science use a technique called mathematical induction, or simply induction. Induction is a principle of mathematics that is like a row of dominoes standing on end. If you push the first domino, all the dominoes will fall one another. What is it about the dominoes that allows us to draw this conclusion? If you know when one domino falls the next will fall, then you know that pushing the first domino will cause them all to fall in succession. More formally, you can show that all the dominoes will fall if you can show that the following facts are:

- The first domino falls.
- For any $k \ge 1$, if the $k^{th}$ domino falls, the $(k+1)^{th}$ domino will fall.

The principle of mathematical induction is an axiom that is stated as follows:

**Axiom E-1. The principle of mathematical induction.** A property $P(n)$ that involves an integer $n$ is true for all $n \ge 0$ if the following holds:

1. $P(0)$ is true.
2. If $P(k)$ is true for any $k \ge 0$, then $P(k+1)$ is true.

**A proof by induction on $n$** uses the principle of mathematical induction. Such a proof consists of the two steps given in Axiom E-1. The first step is the basis, or base case. The second step is the *inductive step*. We usually break the inductive step into two parts: the *inductive hypothesis* ("if $P(k)$ is true for any $k \ge 0$") and the *inductive conclusion* ("then $P(k+1)$ is true").

### **Example 1**

```
pow2(x: integer, n: integer)
  if (n == 0)
    return 1
  else
    return x * pow2(x, n-1)
```

You can prove that pow2 returns $x^{n}$ for all $n \ge 0$ by using the following proof by induction on $n$.

**Basis. Show that the property is true when n = 0.** That is, you must show pow2(x, 0) returns $x^0$, which we can see from the definition of pow2, pow2(x, 0) is 1, which establishes your basis.

Now you establish the inductive step.

**Inductive Hypothesis. Assume the property is true when n = k;** that is, assume the property is true for $k$.

**Inductive Conclusion. Show that the property is true when n = k + 1.** To do so, you can proceed as:

By the inductive hypothesis, the property is true for $n = k$, you must show the property is true for $n = k + 1$. By the definition of pow2,

```
pow2(x, k+1) = x * pow2(x, k)
```

By the inductive hypothesis, pow2(x, k) returns $x^k$, so

```
pow2(x, k+1) = x * x^k = x^{k+1}
```

which is what you needed to show. The proof is complete. We demonstrated the two cases in Axiom E1 are true, so the principle of mathematical induction guarantees pow2 returns $x^n$ for all $n \ge 0$. **(End of proof.)**

### **Example 2**

Prove that

```
1 + 2 + ... + n = n(n+1)/2
```
when $n \ge 1$. It will be helpful to represent the sum $1 + 2 + ... + n$ when $n = 0$, as is the case here. You can use $n = 1$ as the base (Actually, you can use any value of $n \ge 0$ as the base, but a value of 0 or 1 is typical.)

You need to show that the sum $S_k$, which is simply $k$, is equal to $k(k+1)/2$. This fact obvious.

**Inductive Hypothesis. Assume the formula is true when $n = k$;** that is, $S_k = k(k+1)/2$.

**Inductive Conclusion. Show that the formula is true when $n = k + 1$.** To do so, you can proceed as:

```
S_{k+1} = (1 + 2 + ... + k) + (k + 1)
```
by the definition of $S_{k+1}$,

```
S_{k+1} = S_k + (k + 1)
```
by the inductive hypothesis,

```
S_{k+1} = \frac{k(k+1)}{2} + (k + 1)
```
by common denominator,

```
S_{k+1} = \frac{k(k+1) + 2(k+1)}{2}
```
by factorization,

```
S_{k+1} = \frac{(k+1)(k+2)}{2}
```

The last expression is $n(n+1)/2$ when $n = k + 1$. Thus, if the formula for $S_k$ is true, true. By the principle of mathematical induction, the formula is true when $n \ge 1$. **(End of proof.)**
