The AD dictionary, or map, or table, also allows you to look up information easily and has a special operation for your purpose. Typically, the items in the AD dictionary are objects that contain several pieces of data. You can facilitate the retrieval of an item by basing the search on a specified search key. In the dictionary of cities, for example, you could designate city as the search key if you needed to retrieve information about a city. You can define implementations of a dictionary that allow the rapid retrieval of item whose search key matches some specified value. However, if you need to retrieve item(s) based on a value that is not a search key, you will have to inspect the entire dictionary. The choice of a search key sends the ADT implementer the following message:

Arrange the data to facilitate the search for an item, given the value of your search key.
The basic operations that define the ADT dictionary are as follows:

> Note: AD dictionary operations
* Test whether a dictionary is empty.
* Get the number of items in a dictionary.
* Insert a new item into a dictionary.
* Remove the item with a given search key from a dictionary.
* Remove all items from a dictionary.
* Get the item with a given search key from a dictionary.
* Test whether a dictionary contains an item with a given search key.
* Traverse the items in a dictionary in sorted search-key order.

For simplicity, we assume that all items in the dictionary have distinct search keys. This assumption can affect our design in one of several ways:

- *Distinct search keys can be a precondition of the insertion operation*
- The insertion operation can deny any attempt to insert a new entry whose search key already exists in the dictionary
- The insertion operation can replace an existing entry whose search key matches the search of a new entry with the new entry

We will choose the first option.

Although just the operations add, remove, and getItem in the previous set of operations are sufficient for some applications, you cannot delete significant things without additional operations. For instance, you cannot display all the dictionary because you cannot retrieve a item unless you know the value of its search key. You cannot display the entire dictionary unless you traverse it.

The traverse operation visits each item in the dictionary once. In defining this operation, you must specify the order in which traverse visits the items. One common specification is to visit the items in order sorted by search key, but you do not care about the order in which the items are visited. As you will see, the way you define traverse—if you request it at all—can affect the way you implement the dictionary.

> **Note:** Search keys
The concept of a search key for the dictionary items is essential to the implementation of the dictionary. It is important that the value of the search key remains the same as the item stored in the dictionary. Changing the search key of an existing entry in the dictionary could make that entry or other dictionary entries impossible to find. Thus, the client must not be able to modify the value of an entry's search key once that entry is in the dictionary.

Like the operations for the ADT binary tree, traverse has a visit function as its argument. Because it can visit any number of things—including the dictionary via the ADT operations—traverse is a versatile operation.
