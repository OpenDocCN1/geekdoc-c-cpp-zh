# C1.4 Inheritance

Now that the class PlainBox has been written, we will look at the other two boxes. The toy box is very similar to our plain box, but it has an additional characteristic, color, which we can represent with an enumerated type Color. We set the color of our toy box when it is created. The characters in the game can ask about the box's color but cannot change it. Here is the UML notation for these methods:

```
+getColor(): string
+setItem(Item item)
+getItem(): ItemType
```

The methods setItem and getItem behave exactly as the similarly named methods implemented for the PlainBox class. We can reuse the code in PlainBox by using inheritance. Inheritance allows us to reuse and extend work we have already completed and tested.

# C1.4.1 Base Classes and Derived Classes

We use PlainBox as a base class, or superclass, for our ToyBox class. You can think of a base class as a parent class. The ToyBox class is the derived class, or subclass, of the PlainBox class. To indicate that ToyBox is derived from PlainBox, we use the following syntax in the class header of ToyBox:

```
class ToyBox : public PlainBoxItemType
```

Any instance of the derived class is also considered to be an instance of the base class and can be used in a program where any of the base class can be used. Also, when the keyword public is used with the base class, any of the publicly defined methods or data fields in the base class can be used by instances of the derived class. In C++, a derived class inherits all the members of its base class, except the constructors and destructor. That is, a derived class inherits the data and methods of the base class in addition to the methods it defines, though it can access only publicly defined members.

As you see in Listing C1-5, ToyBox only defines the constructors and new methods specific to it, it has no need to revise any methods of the base class. The methods setItem and getItem are inherited from the PlainBox class and can be used in your ToyBox class.
