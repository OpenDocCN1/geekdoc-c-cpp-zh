# An Array-Based Implementation of the ADT Bag

> Note: References as bag.itemCount and bag.items[4] would be illegal within the client, because itemCount and items are within the private portion of the class.

> Note: To implement an ADT, given a implementation-independent specifications of the ADT's operations, you must first choose a data structure to contain the data. Next, declare a class within a header file. The ADT's operations are public methods within the class, and the ADT's data consists of class members that are typically private. You then implement the class's methods within an implementation file. The program that uses the class will be able to access the data only by using the ADT's operations.

> Note: In practice, when choosing implementations of an ADT, you must ask whether the fixed-size restriction of an array-based implementation presents a problem in the context of a particular application. The answer to this question depends on two factors. The obvious factor is, for a given application, you can predict in advance the maximum number of items in the ADT at any time. If you cannot, it is quite possible that an operation—and the entire program—will fail the ADT in the context of a particular application requires more storage than the array can provide.
On the other hand, if for a given application you can predict in advance the maximum number of items in an ADT at any time, you must explore a more stable structure: Would you suggest declaring an array to be large enough to accommodate this maximum number of items? Consider a case in which the maximum number of items is large, but a bag could contain as many as 10,000 items, but the actual number of items in the bag rarely exceeds 50. If you declare 10,000 array locations at compilation time, at least 9,950 array locations will be wasted of the time.
We can avoid both of the previous cases by allocating a larger—or smaller—array during execution. The next C++ Interlude will show you how.
