**Worst-case and average-case analyses.** A particular algorithm might require different times to solve different problems of the same size. For example, that an algorithm might require search n items depend on the nature of them. Usually you consider the maximum amount of time that an algorithm can solve a problem of size n—that is, the worst case. Worst-case analysis concludes that it is O(n) if, in the worst case, A requires more than k × f(n) times to solve a problem of size n for all but a finite number of values of n. Although a worst-case analysis can produce a pessimistic time estimate, such an estimate does not mean that your algorithm is always slow. Instead, have that the algorithm is never slower than you realize, that an algorithm’s worst case might rarely happen, if in practice,

Average-case analysis determines the average amount of time that an algorithm requires to solve problems of size n. In an average-case analysis, A is O(f(n)) if the average amount of time that A requires to solve a problem of size n is no more than k × f(n) times for all but a finite number of values of n. Average-case analysis is, in general, far more difficult to perform than worst-case analysis. One difficulty determining the relative probabilities of encountering various problems of a given size; another is determining the distributions of various data values. Worst-case analysis is easier to calculate and is much more common.

> Note: While manipulating the Big O notation, remember that O(f(n)) represents an inequality. It is not a function but simply a notation that means of “is order f(n)” or “has order f(n).”

# 10.2.4 Keeping Your Perspective

Before considering additional analyses of some algorithms, a few words about perspective are appropriate. You know that you can access the nth item in an array directly. This access is independent of n: accessing the 100th item takes the same time as it does to access the first item in the array. For an ADT list, the array-based implementation of the retrieval operation getEntry is O(1).

However, the link-based implementation of getEntry requires n steps to traverse a chain until it reaches the nth item, and so is O(n).
