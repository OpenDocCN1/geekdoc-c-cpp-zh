Now consider how you can use an index to a data file to get the same advantage as the library catalog. As Figure 21-6 illustrates, you leave the data file in a disorganized state and maintain an organized index to it. When you need to locate a particular record in the data file, search the index for the corresponding entry, which will tell you where to find the desired record in the data file.

An index to the data file is simply another file, which called the **indexed file**, that contains an **index record** for each record in the data file, just as a library catalog contains an entry for each book in the library. An index record has two parts: a key, which contains the same value as the search key and a "pointer", which shows the number of the block in the data file that contains this record. Despite its name, an index record's pointer contains an integer, not a C++ pointer. You can then determine which block of the data file contains the record whose search key equals search for the index file whose record equals searchkey.

Maintaining an index for data file has benefits advantages to those provided by the library's catalog.

+   * In general, an index record will be much smaller than a data record. The data record may contain many components, an index record contains only two: a key and a single integer, which is the block number. Thus, just as a library occupies only a small fraction of the space occupied by the books it indexes, an index file is only a fraction of the size of the data file. As you will see, the small size of the index often allows you to manipulate it with fewer blocks than you would need to manipulate the data file.
* Because you do not need to maintain the data file in any particular order, you can insert new records in any convenient location, such as at the end of the file. As you will see, this flexibility eliminates the need to shift the records during insertions and removals.
* You can maintain several indexes simultaneously. Just as a library can have one catalog organized by title and another by author, you can have one index that indexes the data file by search key (for example, an index that consists of <name, pointer>), and a second index file that indexes the data file by another search key (for example, an index file that consists of <sec, pointer>). **Multiple indexing** is discussed briefly at the end of this chapter.
