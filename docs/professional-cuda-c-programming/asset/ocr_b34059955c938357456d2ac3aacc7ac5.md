associated with a provided integer ID has completed. Combining async and wait clauses
kernels regions allows chaining of asynchronous accelerated regions:

```
#pragma acc kernels async(0)
{
}
#pragma acc kernels wait(0) async(1)
{
}
#pragma acc kernels wait(1) async(2)
{
}
#pragma acc kernels wait(2)
```

In addition, OpenACC also supports checking if asynchronous computation has completed
without blocking. This can only be done using library functions, acc_async_test(int) checks if
the kernels for a given ID have completed, while acc_async_test_all checks that asynchro-
ous work has completed. If all asynchronous work completes, a non-zero value is returned.
Otherwise, zero is returned.

Note that clauses can be combined. For example, the #pragma below would mark a kernels region
asynchronous, but only execute on an accelerator if N=128. For example, if the clause
applies to the kernels, not to any of the kernels directive.

```
#pragma acc kernels if (N > 128) async
```

# Using the parallel Directive

While the kernels directive and its associated clauses are powerful tools for rapid acceleration of an
application, using them may leave you with little control over the actual execution of your applic.
TheACC compiler will automatically analyze your code and choose a parallelization
strategy with little input from you. To address this, OpenACC includes another directive similar to
kernels, which offers more control over execution: the #pragma acc parallel directive.
The directive allows you to group the marked code into as many kernels
of parallelism deems necessary, using a parallel directive allows all gangs and workers
are launched at the very start of the parallel directive and only executing at the end. The comp-
is is not permitted to adjust the dimensionality of parallelism in the parallel
region, though you can gain control over exactly much parallelism created based on your directives. This
gives you complete control over exactly much parallelism is created, just as in CUDA.

The parallel directive supports the if, async, and wait clauses, which were explained as part of
the kernels directive. Additionally, the parallel directive supports clauses that set the number
of gangs to create using num_gangs(int), the number of workers with num_workers(int), and
vector width of each worker with vector_length(int). This should be familiar to you from config-
ing number of thread blocks and threads per block in CUDA, with an added dimension.
