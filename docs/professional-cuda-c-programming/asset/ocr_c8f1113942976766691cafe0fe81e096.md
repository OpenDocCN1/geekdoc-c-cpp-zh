# Multi-GPU Crypt

As clouds offer more GPU deployments and organizations increasingly move their production systems into the cloud, the importance of flexibly supporting drastic changes in the execution environment has grown. For crypt, this implies adding the ability to split the workload across all available GPUs, as well as falling back on host execution if no GPUs can be detected.

The source code in crypt.flexible.cu is an example of a flexible implementation of the crypt application that runs on any number of GPUs, including none. crypt selects host or device execution based on the presence or absence of GPUs, the cudaErrorNoDevice error code. Note that crypt is made into a host_device_function to choose between both implementations, reducing duplicate and maintenance costs for two copies of the same algorithm.

The core logic for partitioning work across multiple GPUs is included here for convenience:

```
for (int d = 0; d < nDevices; d++) {
    CALL_CUDA(cudaSetDevice(d));
    int start = d * chunksPerDevice * CHUNK_SIZE;
    int len = chunksPerDevice * CHUNK_SIZE;
    if (start + len > textLen) {
        len = textLen - start;
    }
    decrypt_driver(text + start, crypt + start, key, len, nThreadsPerBlock, ctxs + d);
}
CALL_CUDA(cudaEventRecord(finishEvent));

// Wait for each device to finish its work.
for (int d = 0; d < nDevices; d++) {
    CALL_CUDA(cudaSetDevice(d));
    CALL_CUDA(cudaDeviceSynchronize());
}
```

In this code, multiple decrypt_driver is called on each GPU to asynchronously data transfers and a kernel launch. Once no work has started on every device, the host waits and pauses for each complex device.

# Hybrid OpenMP-CUDA Crypt

While the previous approach in crypt.flexible.cu made use of the CPU if there were no GPUs available for execution, the CPU left idle if any GPUs were present. While performing all computations on GPUs of a system may lead to performance improvement, it also leads to underutilization of available hardware. For some applications it is beneficial to support hybrid parallelism: CPU and GPU cooperating in the same problem.

In general, there are two types of hybrid parallelism:

+   1. Data-parallel hybrid: The CPU executes the same data-parallel computation across the GPUs but CPU cores insert of GPU SMs. The CPU essentially becomes another device in the system. In this case, a host_device_function can be used to execute the same logic on both processes.

+   2. Task-parallel hybrid parallelism: The CPU executes different computation than the GPU, computation that is more suited for the hosted-based architecture. For example, the GPU may execute tasks with complex control-flow or irregular access patterns.
