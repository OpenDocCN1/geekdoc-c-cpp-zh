However, that is not the whole story. As a result of those 128-bit loads of each the references to gain will likely hit in L1 or L2 cache, depending on your GPU's architecture, and no global memory references are required. Every byte loaded into cache is cached, but may not be of that particular load instruction. Hence, this is a case of nvp reporting suboptimal resource utilization, that with more scrutiny, turns out not to be an actual performance problem since the data is cached.

However, the Timeline Analysis shows a Low Compute Utilization warning. Recall that previous runs also register an Occupancy warning in the Multiprocessor area due to consumption. Some of these warnings indicate that the thread configuration used for this kernel might not be optimal. As the per-SM registers are being spread thinly across a block, leading to more blocking on I/O as values are spilled from registers, and lower computing utility. It is more difficult to verify this conclusion based on analysis of the code. Instead, experimentation with different thread configurations can be used to see if improvement is possible.
