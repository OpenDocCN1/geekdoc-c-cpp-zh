are potential hazards (read-after-write, write-after-read, and write-after-write) which will result in undefined application behavior and undefined state at those memory locations. This undesirable behavior can be avoided by synchronizing threads between conflicting accesses.

You must be particularly careful when using __synctreads in conditional code. It is only valid to call __synctreads if a conditional is guaranteed to evaluate identically across the entire block. Execution is likely to hang or produce unintended side effects. For example, the following code may cause threads in a block to wait indefinitely for each other unless all threads in a block hit the same barrier point.

```
if (threadID % 2 == 0) {
  __synctreads();
} else {
  __synctreads();
}
```

By not allowing synchronization across blocks, blocks can be executed in any order, or in parallel. This independent nature of block execution makes CUDA programming scalable across an arbitrary number of cores. If a CUDA kernel requires global synchronization across blocks, you can likely achieve the desired behavior by splitting the kernel at the synchronization point and performing multiple kernel launches. Because each successive kernel launch must wait for the preceding kernel launch to complete, this produces an implicit global barrier.

# Memory Fence

Memory fence functions ensure that any memory before the fence is visible to other threads after the fence. There are three variants of memory fences depending on the desired scope: block, grid, or system.

You can create a memory fence within a block loop using the intrinsic function:

```
void __threadfence_block();
```

__threadfence_block ensures that all writes to shared memory and global memory made by a call before the fence are visible to other threads in the block after the fence. Recall that memory fences do not perform any thread synchronization, so it is not necessary for all threads in a block to actually execute this instruction.

You can create a memory fence at the grid level using the following intrinsic function:

```
void __threadfence();
```

__threadfence stalls the calling thread until all of its writes to global memory are visible to threads in the same grid.

You can also set a memory fence across the system (including host and device) using the following intrinsic function:

```
void __threadfence_system();
```
