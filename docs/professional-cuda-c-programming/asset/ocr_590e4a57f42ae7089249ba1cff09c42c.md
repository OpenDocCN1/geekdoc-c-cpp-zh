# Global Memory Reads

In SM, data is pipelined through one of the three cache/buffer paths, depending on what type of device memory is referenced:

+   - L1/L2 cache
- Constant cache
- Read-only default

L1/L2 cache is the default path. To pass through the other two paths requires explicit management by the application, but can lead to performance improvement depending on the access patterns used. Whether global memory operations pass through the L1 cache depends on two factors:

+   - Device compute capability
- Compiler options

On Fermi GPUs (compute capability 2.x) and Kepler K40 or later GPUs (compute capability 3.5 and up), L1 caching of global memory loads can be either enabled or disabled with compiler flags. By default, the L1 cache is enabled for global memory loads on Fermi devices and disabled on K40 and later GPUs. The following flags inform the compiler to disable the L1 cache:

```
-Xptxas -dlcm-cg
```

With the L1 cache disabled, all load requests to global memory go directly to the L2 cache; when an L1 miss occurs, the requests are served by DRAM. Each memory transaction may be conducted by one, two, or four segments, where each segment is 32 bytes.

The L1 cache can also be explicitly enabled with the flag:

```
-Xptxas -dlcm-ca
```

With this flag set, global memory load first attempt to hit in L1 cache. On an L1 miss, the requests go to L2. On an L2 miss, the requests are served by DRAM. In this mode, a load memory request is served by a 128-byte device memory transaction.
