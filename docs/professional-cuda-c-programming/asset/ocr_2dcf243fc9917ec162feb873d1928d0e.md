Certain hardware solutions enable the generation of what are arguably true random numbers, but the RNG algorithms that many libraries use to generate random numbers are well defined and well-structured attempts at producing the illusion of randomness. However, this is not an entirely bad characteristic, and can actually be used in certain cases.

For example, RNGs start with a seed, a starting value from which to produce a random sequence of values. You can think of this as the first value in Figure 8-10, on which all other values are based. You can repeat the same seed to a well-defined RNG algorithm and receive the same random sequence of values every time. This can be useful for testing your application, enabling the reuse of the same random sequence over and over again.

RNGs are divided into two categories: pseudo-random RNGs and quasi-random RNGs. Both have their uses, and are both supported by cuRAND.

A pseudo-random RNG (PRNG) uses an RNG algorithm to produce a sequence of random numbers where each value has an equal probability of being anywhere along the range of valid values for the storage that RNG uses. For retrieving a value from an integer PRNG, the probability of the returned value being P(1), is the same as the probability of it being 2, P(2), or 3, P(3), all the way to P(INT_MAX). This is true for every value retrieved from the PRNG. This means that just because the last value retrieved was 2 does not mean that the probability of the next value being 2 is any lower. In other words, each sampling of a pseudo-random number sequence is a statistically independent event, and does not affect the value observed by future samplings.

This does not hold true for quasi-random number generators (QRNG). A QRNG makes an effort to fill the range of the type evenly; if the last value used was 2, then P(2) for the next value has actually decreased. The samplings of a QRNG's sequence are not statistically independent.

Both PRNGs and QRNGs are used in different applications. When true randomness is required, a PRNG is a better choice. For a password-generating application, a PRNG would be a better choice than a QRNG because it would prevent an entry from gaining information about some of the generator passwords to improve their chances of guessing other passwords in the same sequence.

On the other hand, QRNGs are useful in exploring spaces that are not well understood. They guarantee a even sampling of a multi-dimensional space than PRNGs but might also find features that a regular sampling interval will miss. For example, certain applications of Monte Carlo methods benefit from using a QRNG rather than a PRNG.

# Overview of the cuRAND Library

The cuRAND library can be used to sample values from both pseudo-random and quasi-random sequences. It is unique among the CUDA libraries discussed here in that it has a host API and a device API. This means it can be directly called from both host code and kernel code. Many concepts exposed by the cuRAND library are shared between the two APIs, though some options are added when using the device API.
