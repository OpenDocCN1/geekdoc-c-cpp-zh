You can also observe how the L1 cache for global memory loads affects performance. With forced loads, recompile the code and add the following nvcc option:

```
-Xptxas -dlcm-cg
```

Note that this flag will change the behavior of Fermi and Kepler K4 or later GPUs. Sample outputs are included below:

```
$ ./readoffset 0
readoffset << 32768, 512 offset 0 elapsed 0.001825 sec
./readoffset 11
readoffset << 32768, 512 offset 11 elapsed 0.002309 sec
./readoffset 128
readoffset << 32768, 512 offset 128 elapsed 0.001823 sec
```

The results show that overall performance with uncached loads is slower than the cached accesses. The case with misaligned accesses is particularly affected by a lack of caching. With the cache enabled, a misaligned access might bring data into the L1 cache that would be used to satisfy part of a later, misaligned memory request. Without the L1 cache, each of the misaligned requests requires multiple memory transactions and provide no benefit for future requests.

You can also check global load efficiency with uncached loads. Sample results are included below:

```
Offset 0: global_efficiency 100.00%
Offset 11: global_efficiency 80.00%
Offset 128: global_efficiency 100.00%
```

For the misaligned case, load efficiency improved with L1 cache, from 49.8 percent efficiency to 80 percent. Since the L1 cache is disabled, each load request is served at a 32-byte granularity of 128-byte; the number of loaded (but unused) bytes increases.

You might notice that overall time was not reduced with uncached loads, even though global efficiency is improved. This is true, but just for this test case. With higher device occupancy, uncached loads might help improve overall bus utilization. The amount of unused data transferred can be significantly reduced for uncached, misaligned load patterns.

# Read-Only Cache

The read-only cache was originally reserved for use by texture memory loads. For GPUs of compute capability 3.5 and higher, the read-only cache can also support global memory loads as an alternative to the L1 cache.

The granularity of loads through the read-only cache is 32 bytes. In general, this finer granularity loads are better for scattered reads across the L1 cache.

There are two ways to direct memory reads through the read-only cache:

+   - Using the function __ldg
- Using a declaration qualifier on the pointer being dereferenced

For example, consider the following copy kernel:

```
__global void copyKernel(int *out, int *in) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    out[idx] = in[idx];
}
```
