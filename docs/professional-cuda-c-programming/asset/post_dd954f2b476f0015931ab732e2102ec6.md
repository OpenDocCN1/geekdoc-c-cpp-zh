## Example of Misaligned Writes

To verify the effect of misalignment on memory store efficiency, modify the vector addition kernel as follows. Two different indices are used: Index k is shifted by given offset, but i is not (and therefore result in aligned accesses). Loading from arrays A and B uses the aligned index, causing memory load efficiency. Writing to array C, likely causing misaligned writes depends:

```cpp
global void writeOffset(float *A, float *B, float *C,
const int n, int offset) {
  unsigned int i = blockDim.x * blockIdx.x + threadIdx.x;
  unsigned int k = i + offset;
  if (k < n) C[k] = A[i] + B[i];
}
```

The host vector addition code needs to be modified to match these:

```cpp
void sumArraysHost(float *A, float *B, float *C, const int n,
int offset) {
  for (int idx = offset, k = 0; idx < n; idx++, k++) {
    C[idx] = A[k] + B[k];
  }
}
```

The main function is nearly identical to the one when studying misaligned loads. You can download the full code example in writeSegment.cu from Wrox.com.

Compile the code with the following command, and run it.


## Array of Structures versus Structure of Arrays

As a programmer, you should be familiar with two ways of organizing data: an array of structures (AoS), and a structure of arrays (SOA). This is always an interesting topic, because each represents a different way to take advantage of two powerful data types (struct and array) when storing sets of structured data.

Consider the following illustrative example that stores a set of paired float data elements. First, consider how a set of these paired data elements would be using the AoS approach. Define a structure named innerStruct as:

```cpp
struct innerStruct {
    float x;
    float y;
}
```

Next, define an array of these structs as shown below. This is the AoS way of organizing data. It stores related data (for example, x and y) together, which results in good locality on CPU.

```cpp
struct innerStruct myoS[N];
```

Next, consider the data stored using SoA approach: here, all values for each field in the original struct are separated into their own array. This stores data for neighboring points together, but stores the data for a single point across multiple arrays. You can define a variable using this structure:

```cpp
struct innerArray {
    float x[N];
    float y[N];
};
```

Figure 4-22 illustrates the memory layout of both AoS and SoA approaches. Storing the example in AoS format on the GPU and performing an operation that only requires the x field would result in 50 percent loss of bandwidth as y values are implicitly loaded in each 32-byte segment or 128-byte cache line. AoS format would use L2 cache space on unused y values. Storing the data in SoA fashion makes full use of GPU bandwidth. Because there is no interleaving of elements of the same field, the SoA layout on the GPU provides coalesced accesses and can achieve more efficient memory utilization.

## AOS VERS SOA

Many parallel programming paradigms, particular SIMD-style, prefer SoA. In CUDA programming, SoA is also typically preferred because data elements of the same field that are referenced by the same memory operation are adjacent to each other. To help understand the performance implications of accessing data in each layout, you will compare two kernels with the same math operation: one implemented to process AoS data layout, and the other for SoA data layout.

### Example: AoS Data Layout

The following kernel is implemented using AoS layout. The global memory array of structs is stored linearly with x and y interleaved. The inputs and outputs of each thread are a single innerStruct structure.

```cpp
__global void testInnerStruct(innerStruct *data,
    result *result, const int n) {
    unsigned int i = blockIdx.x * blockDim.x + threadIdx.x;

    if (i < n) {
        innerStruct tmp = data[i];
        tmp.x += 10.f;
        tmp.y += 20.f;
        result[i] = tmp;
    }
}
```

The input length is defined as LEN:

```cpp
#define LEN 128
```

Global memory is allocated with the following statements:

```cpp
int nElem = LEN;
size_t nBytes = nElem * sizeof(innerStruct);

innerStruct *d_A, *d_C;
cudaMalloc((innerStruct*)&d_A, nBytes);
cudaMalloc((innerStruct*)&d_C, nBytes);
```

The input array is initialized with the following function:

```cpp
void initInnerStruct(innerStruct *ip, int size) {
  for (int i = 0; i < size; i++) {
    ip[i].x = (float)(rand() & 0xFF) / 100.0;
    ip[i].y = (float)(rand() & 0xFF) / 100.0;
  }
  return;
}
```

In the following code, a warm-up kernel is run to limit the impact of CUDA startup overhead and make it possible to obtain a more accurate time measurement of the innerStruct kernel.

Listing 4-5: Simple math with Ao data layout (simpleMathAo.cu) (main function only listed)

```cpp
int main(int argc, char **argv) {
  // set up device
  int dev;
  cudaDeviceProp deviceProp;
  cudaGetDeviceProperties(&deviceProp, dev);
  printf("%s test array of %s\n", argv[0]);
  printf("%device: %s\n", dev, deviceProp.name);
  cudaSetDevice(dev);

  // allocate host memory
  int nElem = LEN;
  size_t nBytes = nElem * sizeof(innerStruct);
  innerStruct *h_A = (innerStruct*)malloc(nBytes);
  innerStruct *hostRef = (innerStruct*)malloc(nBytes);
  innerStruct *gpuRef = (innerStruct*)malloc(nBytes);

  // initialize array
  initInnerStruct(h_A, nElem);
  testInnerStructHost(h_A, hostRef, nElem);

  // allocate device memory
  innerStruct *d_A, *d_C;
  cudaMalloc((innerStruct**)&d_A, nBytes);
  cudaMalloc((innerStruct**)&d_C, nBytes);

  // copy data from host to device
  cudaMemcpy(d_A, h_A, nBytes, cudaMemcpyHostToDevice);

  // set offset for summary
  int blocksize = 128;
  if (argc<1) blocksize = atoi(argv[1]);

  // execution configuration
  dim3 block(blocksize);
  dim3 grid((nElem+block.x-1)/block.x);

  // kernel 1: warmup
  double start = seconds();
  warmup << grid, block >>> (d_A, d_C, nElem);
  cudaSynchronize();
  double iElaps = seconds() - start;
  printf("%d, %d, elapsed %f sec\n", grid.x, block.x, iElaps);
  cudaMemcpy(gpuRef, d_C, nBytes, cudaMemcpyDeviceToHost);

  // kernel 2: testInnerStruct
  start = seconds();
  testInnerStruct << grid, block >>> (d_A, d_C, nElem);
  cudaSynchronize();
  iElaps = seconds() - start;
  printf("%d, %d, elapsed %f sec\n", grid.x, block.x, iElaps);
  cudaMemcpy(gpuRef, d_C, nBytes, cudaMemcpyDeviceToHost);
  checkInnerStruct(hostRef, gpuRef, nElem);

  // free memories both host and device
  cudaFree(d_A);
  cudaFree(d_C);
  free(h_A);
  free(hostRef);
  free(gpuRef);

  // reset device
  cudaDeviceReset();
  return EXIT_SUCCESS;
}
```
