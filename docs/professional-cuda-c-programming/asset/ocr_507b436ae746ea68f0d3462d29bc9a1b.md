```
// convert idx to transposed (row, col)
unsigned int row = idx / blockDim.Y;
unsigned int col = idx % blockDim.Y;

// convert back to smem idx to access the transposed element
unsigned int col_idx = icol * blockDim.x + row;

// shared memory store operation
tile[idx] = idx;

// wait for all threads to complete
__syncthreads();

// shared memory load operation
out[idx] = tile[col_idx];
```

Shared memory size must be specified as part of the kernel launch:

```
setRowReadColDyn(cgrid, BDIMX * BDIMY * sizeof(int)>(d_C);
```

When you check the shared memory transactions via nvprof, the following is reported:

```
Kernel: setRowReadColDyn(int*)
1 shared_load_transactions_per_request 8.000000
1 shared_store_transactions_per_request 1.000000
```

The write operation is conflict-free, while the read operation reports an eight-way conflict. Dynamically allocating shared memory does not affect bank conflicts.

# Padding Statically Declared Shared Memory

You can use shared memory padding to resolve bank conflicts for rectangular shared memory. However, for Kepler devices, you must calculate how many padding elements are needed. For the case of coding, use a macro to define the number of padding columns added to each row:

```
#define NPAD 2
```

The padded shared memory is declared as follows:

```
__shared int tile[BDIMY][BDIMX + NPAD];
```

The setRowReadCol kernel is identical to setRowReadCol, except for the shared memory padding:

```
global_ void setRowReadColPad(int *out) {
    // static shared memory
    __shared int tile[BDIMY][BDIMX+NPAD];
    // mapping from 2D thread index to linear memory
    unsigned int idx = threadIdx.y * blockDim.x + threadIdx.x;
    // convert idx to transposed (row, col)
    unsigned int row = idx / blockDim.Y;
    unsigned int col = idx % blockDim.Y;
```
