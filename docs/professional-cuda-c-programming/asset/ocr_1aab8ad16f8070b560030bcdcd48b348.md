In this chapter, you will take a close look at how streams behave on devices with various compute capabilities.

# CUDA Streams

CUDA operations (both kernels and data transfers) either explicitly or implicitly run in a stream. There are two types of streams:

+   - Implicitly declared stream (NULL stream)
- Explicitly declared stream (non-NULL stream)

The NULL stream is the default stream that kernel launches and data transfers use if you do not explicitly specify a stream. All examples in the previous chapters of this book used the NULL default stream.

On the other hand, *non-null streams* are explicitly created and managed. If you want to overlap different CUDA operations, you must use non-null streams. Asynchronous, stream-based kernel launches and data transfers enable the following types of *coarse-grain concurrency:*

+   - Overlapped host computation and device computation
- Overlapped host computation and host-device data transfer
- Overlapped host-device data transfer and device computation

Consider the following code snippet using the device stream:

```
cudaMemcpy(..., cudaMemcpyHostDevice);
kernel<<<grid, block>>>();
cudaMemcpy(..., cudaMemcpyDeviceHost);
```

To understand the behavior of a CUDA program, you should always consider it from the viewpoint of both the device and the host. From the device perspective, all three operations in the previous code segment are assigned to the default stream, and are executed in the order that they were issued. The device has no awareness of any host operations being performed. Each data transfer is synchronous and forces the idle host to wait for it to complete. The kernel launch is asynchronous, so the host application immediately resumes execution afterwards, regardless of whether the kernel completed or not. This default behavior makes it straightforward to overlap device and host computation.

Data transfers can also be asynchronous; you must explicitly select the stream to place them in. The CUDA runtime provides the following asynchronous version of `cudaMemcpy:`

```
cudaError_t cudaMemcpyAsync(void* dat, const void* src, size_t count,
cudaMemcpyKind kind, cudaStream_t stream = 0);
```

Note the stream identifier added as the fifth argument. By default, the stream is set to the default stream. This function is asynchronous with respect to the host, so control returns to the host immediately after the call is made. You can easily associate a copy operation with a non-null stream. However, first you will need to create a non-null stream:

```
cudaError_t cudaStreamCreate(cudaStream_t* pStream);
```
