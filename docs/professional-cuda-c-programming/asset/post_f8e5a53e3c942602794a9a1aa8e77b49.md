
```cpp
__global__
void test_shfl_swap(int *d_out, int *d_in, int mask, int firstIdx,
    int secondIdx) {
    int idx = threadIdx.x * SEGM;
    int value[SEGM];

    for (int i = 0; i < SEGM; i++) value[i] = d_in[idx + i];

    swap(value, threadIdx.x, mask, firstIdx, secondIdx);

    for (int i = 0; i < SEGM; i++) d_out[idx + i] = value[i];
}
```

# Parallel Reduction using the Warp Instruction

In an earlier section, "Parallel Reduction with Shared Memory," you learned how to use shared memory to optimize parallel reduction algorithms. In this section, you will learn how to solve the same problem using warp shuffle instructions.

The basic idea is fairly simple. It consists of three levels of reduction:

- Warp-level reduction
- Block-level reduction
- Grid-level reduction

A thread block may have several warps. For warp-level reduction, each warp performs its own reduction. Instead of shared memory, each thread uses a register to store one data element, reading from global memory:

`int mySum = g_idata[idx];`

Warp-level reduction is implemented as an inline function, as follows:

```cpp
__inline __device__ int WarpReduce(int mySum) {
    mySum += __shfl_xor(mySum, 16);
    mySum += __shfl_xor(mySum, 8);
    mySum += __shfl_xor(mySum, 4);
    mySum += __shfl_xor(mySum, 2);
    mySum += __shfl_xor(mySum, 1);
    return mySum;
}
```

Upon return this function, warp sum is saved to shared memory based on thread index and warp size, as shown:

```cpp
int laneIdx = threadIdx.x % warpSize;
int warpIdx = threadIdx.x / warpSize;
int mySum = warpReduce(mySum);
if (laneIdx == 0) smem[warpIdx] = mySum;
```

For block-level reduction, the block is synchronized and the same warp reduce function is used to add each warp's sum. The final output produced by the block is then saved to global by the first thread in the block, as shown:

```cpp
__syncthreads();
mySum = (threadIdx.x < SMEMDIM) ? smem[laneIdx] : 0;
if (warpIdx == 0) mySum = warpReduce(mySum);
if (threadIdx.x == 0) g_odata[blockIdx.x] = mySum;
```

For the grid-level reduction, g_odata is copied to the host where the final reduction is performed. Here is the complete reduceShfl kernel:

```cpp
__global void reduceShfl(int *g_idata, int *g_odata, unsigned int n) {
    // shared memory for each warp sum
    shared int smem[SMEMDIM];

    // boundary check
    unsigned int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx >= n) return;

    // read from global memory
    int mySum = g_idata[idx];

    // calculate lane index and warp index
    int laneIdx = threadIdx.x % warpSize;
    int warpIdx = threadIdx.x / warpSize;

    // block-wide warp reduce
    mySum = warpReduce(mySum);

    // save warp sum to shared memory
    if (laneIdx == 0) smem[warpIdx] = mySum;

    // block synchronization
    __syncthreads();

    // last warp reduce
    mySum = (threadIdx.x < SMEMDIM) ? smem[laneIdx] : 0;
    if (warpIdx == 0) mySum = warpReduce(mySum);

    // write result for this block to global
    if (threadIdx.x == 0) g_odata[blockIdx.x] = mySum;
}
```

# SUMMARY

To obtain maximum performance, you need a memory hierarchy that can be explicitly managed. In C programming, there are no means to directly control data movement. In this chapter you learned about memory types, such as shared memory, constant memory, and read-only cache. You learned how to control when data is brought in or evicted from shared memory to significantly improve performance. You also learned about the behavior of constant memory and the read-only cache and how to use them effectively.

Shared memory can be declared as 1D or 2D array, shared memory is one-dimensional and accessed through 32 banks. Avoiding bank conflicts is an important factor during optimization. Shared memory is partitioned among resident thread blocks; therefore it is a critical resource and limit occupancy.

There are two main reasons to use shared memory in a kernel. One is to cache data on-chip and reduce the amount of global memory traffic. The other is to transform how data is arranged in shared memory to avoid non-coalesced global memory accesses.

Constant memory is optimized for read-only data that is broadcast to many threads at a time. Constant memory also uses its own cache, preventing reads from constant memory from interfering with global memory accesses passing through the L1 cache. As result, using constant memory for appropriate data will not only optimize the accesses to that particular item but also improve global throughput.

The read-only cache offers an alternative to constant memory that is more optimized for scattered reads of data. This read-only cache uses a separate access pipeline to make data accessible to the SM. As result, the read-only cache shares many of its benefits with constant memory but is optimized for a different access pattern.

The shuffle instruction is a warp-level intrinsic function that enables threads in a warp to share data with each other quickly and directly. The shuffle instruction has lower latency than shared memory and does not require allocating additional resources. Using the shuffle instruction can reduce the number of warp-synchronous optimizations for a kernel. However, in many cases the shuffle instruction is not a replacement for shared memory as shared memory is visible to an entire block.

This chapter went into depth on a number of special-purpose types of memory. Although the use of each of these memory types is less general than global memory, using them appropriately improves bandwidth utilization and decreases overall memory latency. Keeping shared memory, constant memory, the read-only cache, and shuffle instructions in mind is important when you are investigating optimization opportunities.
