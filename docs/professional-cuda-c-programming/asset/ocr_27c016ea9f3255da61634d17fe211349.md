Even though the host and device are stored in the same file, they exist in completely different worlds. The host cannot directly access a device variable even if it is visible in the same scope. Similarly, device code cannot directly access a host variable either.

You might argue that the host in fact can access the device global variable using the following code:

```
cudaMemcpyToSymbol(devData, &value, sizeof(float));
```

Yes, notice that:

+   * cudaMemcpyToSymbol is in the CUDA runtime API and uses GPU hardware behind the scenes to perform the access.
* The variable devData is passed here as a symbol, not as the address of the variable in device memory.
* In the kernel, devData is used as a variable in global memory.

cudaMemcpy cannot be used to transfer data into devData using the address of the variable:

```
cudaMemcpy(&devData, &value, sizeof(float), cudaMemcpyHostToDevice);
