
The function used to transfer data between the host and device: cudaMemcpy, and its function signature is:

```
cudaError_t cudaMemcpy ( void* dst, const void* src, size_t count,
cudaMemcpyKind kind )
```

This function copies the bytes from the source memory area, pointed to by src, to the destination memory area, pointed to dst, with the direction specified by kind, where kind takes one of the following types:

- cudaMempyHostToHost
- cudaMempyHostToDevice
- cudaMempyDeviceToHost

This function exhibits synchronous behavior because the host application blocks until cudaMemcpy returns and the transfer is complete. Every CUDA call, except kernel launches, returns an error code of enumerated type cuda_t. For example, if GPU memory is successfully allocated, it returns:

```
cudaSuccess
```

Otherwise, it returns:

```
cudaMemoryAllocation
```

You can convert an error to a human-readable message with the following CUDA runtime function:

```
char* cudaErrorString(cudaError_t error)
```

## MEMORY HIERARCHY

One of the notable characteristics of the CUDA programming model is the exposed hierarchy. Each GPU device has a set of different memory used for different purposes. In the GPU hierarchy, the two most important types of memory are global memory and shared memory. Global memory is analogous to system memory, while shared memory is similar to the CPU cache. However, GPU shared memory can be directly controlled from a CUDA kernel.

### LISTING 2-1: Host-based array summation (sumArraysHost.c)

```c
#include <stdlib.h>
#include <string.h>
#include <time.h>

void sumArraysHost(float *A, float *B, float *C, int N) {
  for (int idx = 0; idx < N; idx++) {
    C[idx] = A[idx] + B[idx];
  }
}

void initialData(float *ip, int size) {
  // generate seed for random number
  time_t t;
  srand((unsigned int) time(&t));

  for (int i = 0; i < size; i++) {
    ip[i] = (float)(rand() & 0xFF) / 10.0f;
  }
}

int main(int argc, char **argv) {
  int nElem = 1024;
  size_t nBytes = nElem * sizeof(float);

  float *h_A, *h_B, *h_C;
  h_A = (float*)malloc(nBytes);
  h_B = (float*)malloc(nBytes);
  h_C = (float*)malloc(nBytes);

  initialData(h_A, nElem);
  initialData(h_B, nElem);

  sumArraysHost(h_A, h_B, h_C, nElem);

  free(h_A);
  free(h_B);
  free(h_C);

  return(0);
}
```

Because this is a pure C program, you can compile it with your C compiler. You can also compile and run it with nvcc as follows. It will finish silently.

```bash
$ nvcc -Xcompiler -std=c99 sumArraysHost.c -o sum
$ sum
```

The CUDA compiler allows you to pass many options directly to the internal compilation tools that CUDA encapsulates. The flag -Xcompiler specifies options directly to the C compiler or preprocessor. In the preceding example, -std=c99 is passed to the compiler because the C code here is written with the code style according to the C99 standard. You can find options in the CUDA compiler document (http://docs.nvidia.com/cuda/cuda-compiler-driver-nvcc/index.html).

Now, you can modify the code to perform array summation on the GPU. Use cudaMalloc to allocate the memory on the GPU.

```c
float *d_A, *d_B, *d_C;
cudaMalloc((float**)d_A, nBytes);
cudaMalloc((float**)d_B, nBytes);
cudaMalloc((float**)d_C, nBytes);
```

Use cudaMemcpy to transfer data from the host to the GPU global memory with the parameter cudaMemcpyHostToDevice specifying the transfer direction.

```c
cudaMemcpy(d_A, h_A, nBytes, cudaMemcpyHostToDevice);
cudaMemcpy(d_B, h_B, nBytes, cudaMemcpyHostToDevice);
```

As soon as the kernel is called, the control is immediately returned to the host. At this point, the host may perform other functions while the kernel is running on the GPU. Thus, the host may be asynchronous with respect to the host.
