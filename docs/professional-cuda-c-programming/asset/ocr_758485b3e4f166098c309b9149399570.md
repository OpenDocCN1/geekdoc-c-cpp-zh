the requested transformation. Different plan creations can be used to generate plans of increasing complexity and dimensionality;

```
cuffResult cuftPlan1d(cuffHandle *plan, int nx, cufftType type, int batch);
cuffResult cuftPlan2d(cuffHandle *plan, int nx, int ny, cufftType type);
cuffResult cuftPlan3d(cuffHandle *plan, int nx, int ny, int nz, cufftType type);
```

cuFF also supports a variety of input and output types, including:

+   - Complex-to-complex

+   - Real-to-complex

+   - Complex-to-real

For many real-world applications, the most useful type is real-to-complex, enabling you to input real-valued measurements from real-world systems to cuFF.

Once a cuFF plan is configured, it is executed using a cuffExec* function call (for example, cuffExec2c). In general, function calls take as input the plan, the location where inputs are stored, the location to place outputs, and whether this a forward FFT (time domain to frequency domain) or inverse FFT (frequency domain to time domain).

# # Demonstrating cuFFT

This section covers a simple example using the cuFFT API to perform a complex-to-complex, 1D FFT. You can download the sample code in cufft.cu from Wrox.com or follow along in the code snippet below

```
// Setup the cuFFT plan
cuffPlan1d(&plan, N, CUFFT_C2C, 1);

// Allocate device memory
cudaMalloc(void **)&complexSamples, sizeof(cuffComplex) * N);

// Transfer inputs into device memory
cudaMemcpy(dComplexSamples, complexSamples, sizeof(cuffComplex) * N, cudaMemcpyHostToDevice);

// Execute a complex-to-complex 1D FFT
cuffExec2c(plan, dComplexSamples, dComplexSamples, CUFFT_FORWARD);

// Retrieve the results into host memory
cudaMemcpy(complexFreq, dComplexSamples, sizeof(cuffComplex) * N, cudaMemcpyDeviceToHost);
```
