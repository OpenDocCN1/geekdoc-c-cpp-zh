
You do not need to set a current device for the copy operations; however, you must specify a current device before launching a kernel.

## 2D Stencil Computation with Multiple GPUs

In this section, a simple 2D stencil is implemented using multiple GPUs. Two device arrays are used in the 2D stencil calculation. One holds the current wave field, and the other holds the updated wave field. If you define x as the innermost ray dimension and y as the outermost dimension, the computation can be divided across devices along the y.

Because updating one point requires access to the nine nearest points, any of the points will share input data. Hence, shared memory is used to reduce global memory accesses. The amount of shared memory used is equal to the size of the thread block padded with an additional eight points to hold the neighbor data, as illustrated in Figure 9-6 and in the following code snippet

```cpp
shared float line[4 + BIMX + 4];
```

The nine float values used to store the y-axis stencil values are declared as an array local to the kernel, and all will be stored in registers. Registers are used here like shared memory to reduce redundant accesses when loading elements ahead and behind the current element along the y axis.

```cpp
// registers for the y dimension
float yval[9];
```

Once the input data has been allocated and initialized, the stencil computation implementing a Finite Difference (FD) operator in each GPU thread can be written as follows:

```cpp
// central point
float tmp = coef[0] * 2.0f;
```

```cpp
// stencil computation in the x dimension
for (int d = 1; d <= 4; d++) {
    tmp += coef[d] * (line[stx-d] + line[stx+d]);
}
```

```cpp
// stencil computation in the y dimension
for (int d = 1; d <= 4; d++) {
    tmp += coef[d] * (yval[4-d] + yval[4+d]);
}
```

```cpp
// update the new variable for the central point
g_ul[idx] = 2.0f - current - g_ul[idx] + alpha * tmp;
```

The full kernel code for the 2D stencil computation is:

```cpp
__global void kernel_2df(float *g_u2, const int nx, \
    const int iStart, int iEnd) {
    // thread index to row index
    unsigned int ix = blockIdx.x * blockDim.x + threadIdx.x;

    // mem index for current point
    unsigned int stx = threadIdx.x + NPAD;

    // global index with offset to start line
    unsigned int idx = ix + iStart * nx;

    // declare the shared memory for x dimension
    shared__ float line[BIMX+NPAD2];

    // a coefficient related to physical properties
    const float alpha = 0.12f;

    // declare nine registers for y value
    float yval[9];
    for (int i=0; i<8;i++) yval[i] = g_u2[idx+(i-4)*nx];

    // offset from current point to yval[8]
    int iskip = NPAD*nx;

#pragma unroll 9
    for (int iy = iStart; iy < iEnd; iy++) {
        // set yval[8] here
        yval[8] = g_u2[idx-iskip];

        // read halo part in x dimension: both left and right
        if(threadIdx.x) {
            line[threadIdx.x] = g_u2[idx-NPAD];
            line[stx-BIMX] = g_u2[idx+BIMX];
        }
    }

    // center point
    line[stx] = yval[4];

    // syn for get data from gmem
syncthreads();
```

```cpp
// fd operator: 8th order in space and 2nd order in time
if ((ix >= NPAD) && (ix < nx-NPAD)) {
  // update center point
  float tmp = coef[0]*line[stx]*2.0;
```

```cpp
// 8th order in x dimension
#pragma unroll
for(int d=0; d<4; d++) {
  tmp += coef[d]*line[stx-d] + line[stx+d];
}
```

```cpp
// 8th order in y dimension
#pragma unroll
for(int d=1; d<4; d++) {
  tmp += coef[d]*(yval[4-d] + yval[4+d]);
}
```

```cpp
// 2nd order in time dimension
g_ul[idx] = yval[4] + yval[4] - g_ul[idx] + alpha*tmp;
}

// advance unity
#pragma unroll
for(int i=0; i<8; i++) yval[i] = yval[i+1];

// syn for next step
__syncthreads();
}
}
```

## Overlapping Computation and Communication

The execution configuration for this 2D stencil uses a 1D grid with 1D blocks, declared on the host as follows:

```cpp
dim3 block(BDIMX)
dim3 grid(nx/ block.x);
```

The wave propagation over time is controlled on the host by iterating in a time loop with nsteps iterations. During the first step, a disturbance is introduced to the medium on GPU with the kernel kernel_add_wavelet. Further iterations propagate the disturbance over. Because the halo region computation and data exchanges are scheduled in time stream_halo on each device and the internal region calculations are scheduled in time stream_internal on each device, the computation and communication in this 2D stencil can be overlapped.

```cpp
// add a disturbance onto gpu0 on the first time step
cudaDevice(0);
kernel_add_wavelet<<<grid, block>>>(d_u2[0], 20.0, nx, iny, ngpus);
```

```cpp
// for each time step
for (int istep = 0; istep < nsteps; istep++) {
// add a disturbance on into gpu0 at first step
if (istep==0) {
    cudaSetDevice(gpu[0]);
    kernel_add_wavelet<<<grid,block>>>(d_u2[0],20.0,nx,ny,ngpus);
}
}
```

```cpp
// update halo and intern asynchronously
for (int i = 0; i < ngpus;++) {
    cudaSetDevice(i);
}
```

```cpp
// compute the halo regions in the halo stream
kernel_2dfdc<<<grid, block>>>(d_u1[i], d_u2[i], nx, haloStart[i], haloEnd[i]);
```

```cpp
// compute the internal region values in the internal stream
kernel_2dfdc<<<grid, block, 0, stream_internal[i]]>>>
d_u1[i], d_u2[i], nx, bodyStart[i], bodyEnd[i]);
```
