You can download the legacy application code from Wrox.com in a file named crypt.c crypt implements IDEA encryption and decryption. The crypt application is made up of three parts:

+   1. Application setup is initiated in main. Setup includes reading input, pre-allocating space for output, reading a secret key: a sequence of bits which must be known to the sender and receiver of a message to successfully encrypt or decrypt the

+   2. Keys for encrypting or decrypting the input are generated from the shared secret key using generateEncryptKey and generateDecryptKey.

+   3. The actual encryption and decryption of the input is done in encrypt_decrypt with 8-byte chunks.

The primary input to crypt is a file to be encrypted or decrypted. Additionally, crypt takes a key file storing the 64-bit secret key to be used to encrypt or decrypt the input. Utilities to generate example data (generate_data.c) and a secret key (generate_userkey.c) are provided in Wrox.com. Figure 10 outlines the high-level flow of data through the crypt application. # Assessing crypt

There are many tools available for assessing the performance of host applications. For this example you will use gprof because it is widely available, free, and offers low-overhead profiling.

Before assessing crypt, you need to generate a sample key and 1 GB of sample data, as follows:

$ ./generate_userkey key
$ ./generate_data_data 1073741824
