
If you were given a dense two-dimensional column-major matrix A of single-precision floating-point values on the host with M rows and N columns, you could use cublasSetMatrix to transfer the entire matrix using:

```
cublasSetMatrix(M, N, sizeof(float), A, dA, M);
```

You could also use cublasSetVector to transfer a single column of A to a vector DV on the device. cublasSetVector takes the following arguments:

```
cublasStatus_t cublasSetVector(int n, int elemSize, const void *x, int incx, void *y, int incy)
```

where x is the source location on the host, y is the destination location on the device, n is the number of elements to transfer, elemSize is the size of each element in bytes, and incx/incy is the stride between elements. Transferring a single column of length M of column-major matrix A to a vector DV can be done:

```
cublasSetVector(M, sizeof(float), A, 1, DV, 1);
```

You could also use cublasSetVector to transfer a single row of matrix A to a vector DV on the device:

```
cublasSetVector(N, sizeof(float), A, M, DV, 1);
```

This function copies N elements from A to DV, skipping M elements in A at a time. Because A is column-major, this command would copy the first row of A to the device. Copying row i would be implemented as:

```
cublasSetVector(N, sizeof(float), A + i, M, DV, 1);
```

This is a much simpler data than the one exposed by cuSPARSE. Unless your application significantly benefits from sparse structures, using cuBLAS will likely improve performance and lead to a simpler development process.

The cuBLAS example demonstrated here will focus on the uniformity of cuBLAS and its performance benefits of GPUs can lead to greater than 15 times speed-relative to optimized host-only BLAS libraries, and the development effort to use cuBLAS is only marginally greater than that of legacy BLAS implementations.

## A Simple cuBLAS Example

This example will perform matrix-vector multiplication on the GPU, a cuBLAS Level 2 operation. You can follow along by downloading the sample code in cublas.cu from Wrox.com or using the following snippet:

```
// Create the cuBLAS handle
cublasCreate(&handle);
```

```
// Allocate device memory
cudaMalloc(void **DA, sizeof(float) * M * N);
cudaMalloc(void **DX, sizeof(float) * N);
cudaMalloc(void **DY, sizeof(float) * M);
```

```
// Transfer inputs to the device
cublasSetVector(N, sizeof(float), X, 1, dX);
cublasSetVector(M, sizeof(float), Y, 1, dY);
cublasSetMatrix(M, N, sizeof(float), A, M, dA, M);
```

```
// Execute the matrix-vector multiplication
cublasSgemv(handle, CUBLAS_OP_N, M, N, &alpha, dA, dX, &beta, dY);
```

```
// Retrieve the output vector from the device
cublasGetVector(M, sizeof(float), DY, 1, Y);
```

Using the cuBLAS library is straightforward. cublas.cu demonstrates a much smaller subset of the common library workflow compared to the previous cuSPARSE. It includes the following steps:

- 1. Create a cuBLAS handle using cublasCreateHandle.
- 2. Allocate device memory for inputs and outputs using cudaMalloc.
- 3. Populate the allocated device memory with inputs using cublasSetVector and cublasSetMatrix.
- 4. Execute the cublasSgemv library to offload a matrix-vector multiplication operation to the GPU.
- 5. Retrieve results from device memory using cublasGetVector.
- 6. Release CUDA and cuBLAS resources using cudaFree and cublasDestroy.

This example can be built using the following command:

```
$ nvcc -lcublas cublas.cu
```

Using the cuBLAS library requires less effort than the cuSPARSE library, primarily because cuBLAS is built to be highly compatible with the legacy BLAS library.

## Porting of BLAS

Porting a legacy application from the BLAS library to cuBLAS is straightforward. The porting process generally consists of four main steps:

- 1. Adding device memory allocation (cudaMalloc) and device memory release (cudaFree) for any input or output vectors or matrices.
- 2. Add methods to transfer input and matrices between the host and device (for example, cublasSetVector, cublasSetMatrix, cublasGetVector, cublasGetMatrix).
- 3. Transform the actual call to the BLAS library to the equivalent cuBLAS routine. This will likely require minor changes to the arguments. For instance, the previous example used the cuBLAS function:

```
cublasStatus_t cublasSgemv(cublasHandle_t handle, cublasOperation_t trans, int m, int n, const float *alpha, const float *A, const float *x, const float *beta, float *y, int incy);
```

The equivalent BLAS function from the library has a slightly different interface:

```
void cblas_sgemv(const CBLAS_ORDER order, const CBLAS_TRANSPOSE trans, int m, int n, const float *alpha, const float *A, int lda, const float *x, int incx, const float *beta, float *y, int incy);
```

While many of the arguments are the same or similar (trans, m, n, alpha, lda, x, incx, beta, y, incy), cuBLAS includes the order argument (enabling you to specify inputs in row-major or column-major order), and cuBLAS adds the handle. Also note that the alpha and beta arguments to BLAS are not passed by reference as they are in cuBLAS. These are minor differences for all cuBLAS functions, and do not represent a major hindrance to porting applications to cuBLAS.

Finally, you might also choose to optimize your new cuBLAS application after implementation. This step can include:

- a. Reusing memory allocations rather than allocating and freeing for every cuBLAS call.
- b. Removing redundant device-to-host copies for vectors and matrices that are used for the next cuBLAS call.
- c. Adding stream-based execution using cublasStream to enable asynchronous transfers. See Chapter 6, "Streams and Concurrency," for more information on how streams can improve performance.

## Important Topics in cuBLAS Development

Compared to cuSPARSE, cuBLAS is more familiar and intuitive if you have experience with the legacy BLAS library. As a result, it is easier to understand the processes happening behind the scenes. This also implies that potential issues that may arise are easier to manage with cuSPARSE.

If you use row-major programming languages, development with cuBLAS can require extra attention to detail. It is easy to use the code patterns with which you are most familiar, for example, flattening an array using row-major indexing. To help, you can define macros to automate the conversion of zero-based row-major indexing to column-major:

```
#define R2C(r, c, nrows) ((c * (nrows) + (r))
```

However, even using macros like this, you must put more thought into the ordering of the surrounding loops. Many C/C++ programmers will be tempted to:

```
for (int r = 0; r < nrows; r++) {
  for (int c = 0; c < ncols; c++) {
    A[R2C(r, c, nrows)] = ...;
  }
}
```

While this code would be correct, it would be suboptimal if it does not linearly scan the memory locations in the array a. For example, if the array starts at memory location zero, the first three references of this loop will be at locations 0, nrows, and 2×nrows. Given that nrows might be very large, widely separated memory accesses lead to poor cache locality. Therefore, you must take care to invert the order of the loops using column-arrays:

```
for (int c = 0; c < ncols; c++) {
  for (int r = 0; r < nrows; r++) {
    A[R2C(r, c, nrows)] = ...;
  }
}
```

Be careful when doing so, as you may inadvertently cause poor-cache-locality on the right hand side of the assignment instead.

The most alluring aspect of cuBLAS is its ease-of-use when transitioning from the legacy BLAS library. In that case, the only major changes necessary are the additions of device memory management and transfer CUDA calls.

## THE cuFFT LIBRARY

The cuFFT library provides an optimized, CUDA-based implementation of the fast Fourier transform (FFT). An FFT is a transformation in signal processing that converts a signal from the time domain to the frequency domain. An inverse FFT does the opposite. Another way, an FFT receives as input a sequence of samples taken from a signal at regular time intervals. It uses those samples to generate a set of frequencies that are superposed to recreate the signal generated by the input samples.
