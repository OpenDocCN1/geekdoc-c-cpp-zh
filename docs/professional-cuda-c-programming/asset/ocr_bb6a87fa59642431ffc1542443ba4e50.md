# REDUCING GLOBAL MEMORY ACCESS

One of the primary reasons to use shared memory is to cache on-chip, thereby reducing the number of global memory accesses in your kernel. Chapter 3 introduced parallel reduction kernels using global memory, and on the following issues:

+   - How to avoid warp divergence by rearranging data access patterns
- How to unroll keep operations in flight to saturate instruction and memory bandwidth

In this section, you will re-examine those parallel reduction kernels, but this time shared memory as a program-managed cache to reduce global memory accesses.

# Parallel Reduction with Shared Memory

The reduceGmem` kernel below will be a starting point for baseline performance. It should look familiar from Chapter 3. Parallel reduction is implemented using only global memory and the inner loop over elements is completely unloaded. For the following kernels can be found in reduceInteger.cu on Wrox.com.

```
global _ void reduceGmem(int *g_idata, int *g_odata, unsigned int n) {
  // thread ID
  unsigned int tid = threadIdx.x;
  int *idata = g_idata + blockIdx.x * blockDim.x;

  // boundary check
  unsigned int idx = blockIdx.x * blockDim.x + threadIdx.x;
  if (idx >= n) return;

  // in-place reduction in global memory
  if (blockIdx.x >= 124 && tid < 512) idata[tid] = idata[tid + 512];
```
