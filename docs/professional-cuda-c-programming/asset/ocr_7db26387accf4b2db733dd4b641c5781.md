# MATRIX ADDITION WITH UNIFIED MEMORY

You learned how to add two matrices on the GPU in Chapter 2. To simplify managing separate host and device memory spaces and to make this CUDA program more readable and easier to maintain, you could apply the following revisions to the main function of matrix addition using Unified Memory:

+   - Replace the host and device memory allocations with managed memory allocations to eliminate duplicate copies.

+   - Remove all explicit memory copies.

You can start by declaring and allocating three arrays: A and B are used for input and gpuRef is for output:

```
float *A, *gpuRef;
cudaMalloc(void **)&A, int nBytes);
cudaMalloc(void **)&B, int nBytes);
cudaMalloc(void **)&gpuRef, int nBytes);
```

Then, you should initialize the two input matrices on the host using the pointers to manage memory:

```
initialData(A, nxy);
initialData(B, nxy);
```

Finally, invoke the matrix addition with the pointers to the managed memory:

```
sumMatrixGPU<<grid, block>>>(A, B, gpuRef, nx, ny);
cudaDeviceSynchronize();
```

Because the kernel launch is asynchronous with respect to the host and a blocking call to cudaMemcpy is no longer necessary with managed memory, you need to explicitly synchronize on the host side before accessing the output of the kernel. Compared to the un-managed version of matrix addition program from the previous chapter in this book, the code is here simplified thanks to Unified Memory.

You can download the full code in sumMatrixGPU.cu from Wrox.com. You also find its counterpart sumMatrixManual.cu, which uses the same matrix addition kernel but does not use managed memory. It instead performs explicit memory copies to the device. Both versions use a warm-up kernel to avoid kernel startup overhead and obtain more accurate timing results. Using CUDA 6.0 and a Kepler or later GPU, compile both versions, named one and the other manual.

```
$ nvcc -arch=sm_30 sumMatrixGPU.cu -o managed
$ nvcc -arch=sm_30 sumMatrixManual.cu -o manual
```

If you are testing with more than one GPU, an extra step is required for the managed app. Because managed memory allocations are visible to all devices in a system, you will want to constrain which device is visible to your application so that memory is allocated on just one device. To do this, use the CUDA_VISIBLE_DEVICES environment variable to expose a single GPU to CUDA:

```
$ export CUDA_VISIBLE_DEVICES=0
```
