
```cpp
cudaMalloc(void **) &d_B[i], iBytes);
cudaMalloc(void **) &d_C[i], iBytes);
```

```cpp
// allocate locked host memory for asynchronous data transfer
cudaMallocHost(void **) &h_A[i], iBytes);
cudaMallocHost(void **) &h_B[i], iBytes);
cudaMallocHost(void **) &hostRef[i], iBytes);
cudaMallocHost(void **) &gpuRef[i], iBytes);
```

```cpp
// create streams for timing and synchronizing
StreamCreate(&stream[i]);
```

Note that page-locked (pinned) memory is allocated in order to perform asynchronous data transfers between the device and host. Also, cudaSetDevice is used at the start of every iteration of the loop to set the current device before allocating memory or creating any streams.

# Distributing Work from a Single Host Thread

Before distributing operations among devices, you need to initialize the state of the host arrays for each device:

```cpp
for (int i = 0; i < ngpus; i++) {
cudaSetDevice(i);
initialData(h_A[i], iSize);
initialData(h_B[i], iSize);
}
```

With all resources allocated and initialized, you are ready to distribute data and computation among multiple devices using a loop:

```cpp
// distributing the workload across multiple devices
for (int i = 0; i < ngpus; i++) {
cudaSetDevice(i);
cudaMemcpyAsync(d_A[i], h_A[i], iBytes, cudaMemcpyHostToDevice, stream[i]);
cudaMemcpyAsync(d_B[i], h_B[i], iBytes, cudaMemcpyHostToDevice, stream[i]);
kernel<<<grid, block, 0, stream[i]>>>(d_A[i], d_B[i], iSize);
cudaMemcpyAsync(gpuRef[i], d_C[i], iBytes, cudaMemcpyDeviceToHost, stream[i]);
cudaDeviceSynchronize();
}
```

This loop iterates over multiple GPUs, asynchronously copying the input arrays for that device. It launches a kernel in the same stream operating on iSize elements. An asynchronous copy from the device is issued to transfer the results from the kernel back to the host. Because all functions are asynchronous, control is returned to the host thread immediately. It is then safe to switch to the next device while tasks are still running on the current device.

# PEER-TO-PEER COMMUNICATION ON MULTIPLE GPUs

In this section, you are going to explore transferring data between two GPUs. The following three cases will be tested:

- Unidirectional memory copy between two GPUs
- Bidirectional memory copy between two GPUs
- Peer memory access in a kernel

# Enabling Peer-to-Peer Access

First, you must enable bi-directional peer-to-peer access among all devices, as demonstrated in the following code:

```cpp
/*
 * enable P2P memory between GPUs (all GPUs must compute
 * capability 2.0 or later).
 */
inline void enableP2P(int npus) {
    for (int i = 0; i < npus; i++) {
        cudaSetDevice(i);
        for (int j = 0; j < npus; j++) {
            if(i == j) continue;

            int peer_access_available = 0;
            cudaDeviceCanAccessPeer(&peer_access_available, i, j);

            if (peer_access_available) {
                cudaDeviceEnablePeer(j, i);
                printf("GPU%d enabled direct access to GPU%d\n", i, j);
            } else {
                printf("GPU%d, %d not supported\n", i, j);
            }
        }
    }
}
```

The function iterates over all pairs of devices (i, j) and if peer access is supported, enables it in both directions using cudaDeviceEnablePeer.

# Peer-to-Peer Memory Copy

After peer-to-peer access has been enabled, you can copy data directly between two devices. If peer access is not supported, this example prints device IDs for which peer-to-peer access could not be enabled (likely because they are not connected to the same PCIe root) and continues without errors. However, recall that if peer-to-peer access is not enabled between two GPUs, a peer-to-peer memory copy between these two devices will be staged through host memory, reducing performance. How performance affects your application depends on how much time your kernel spends computing and performing peer-to-peer transfers. If spending enough time computing, you may be able to hide the latency of peer-to-peer copies that pass through host memory by overlapping it with device computation.

With peer-to-peer access enabled, the following code snippet performs a ping-pong synchronous copy between devices hundred times. If peer-to-peer access was fully enabled on all devices, the data transfers pass directly over the PCIe bus without host.

```cpp
// ping pong unidirectional gmem copy
cudaEventRecord(start, 0);
for (int i = 0; i < 100; i++) {
    if (i % 2 == 0) {
        cudaMemcpy(d_src[1], d_src[0], iBytes, cudaMemcpyDeviceToDevice);
    } else {
        cudaMemcpy(d_src[0], d_src[1], iBytes, cudaMemcpyDeviceToDevice);
    }
}
```

Note that there is no device switching before the memory because memory copies across devices do not require you to explicitly set a current device. If you specify a device before a memory copy, it will not affect its behavior.

To measure transfer performance between devices, start and stop events are recorded on the same device, wrapping the ping-pong memory copies. cudaElapsedTime is used to calculate the elapsed time between events.

```cpp
cudaDevice(0);
cudaEventRecord(start, 0);
for (int i = 0; i < 100; i++) {
}
cudaDevice(0);
cudaEventRecord(stop, 0);
cudaEventSynchronize(stop);
```

```cpp
float elapsed_time_ms;
cudaEventElapsedTime(elapsed_time_ms, start, stop);
```

Then, the bandwidth achieved by this ping-pong test can be estimated as follows:

```cpp
elapsed_time_ms = 100.00;
printf("Ping-pong unidirectional cudaMemcpy: \t%.2f ms\n", elapsed_time_ms);
printf("performance: %.2f GB/s\n", iBytes / (elapsed_time_ms * 1e6));
```
