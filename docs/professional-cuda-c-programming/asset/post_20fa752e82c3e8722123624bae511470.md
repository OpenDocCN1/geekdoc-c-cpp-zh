The replay of global memory stores is reduced from 32 to 2. Because the block width in the transpose block is 16, the writes of the first half and the second half of a warp are stripped by 4,08; therefore, a warp request to write to global memory is serviced by two transactions. Changing the block size to 32x32 would reduce the count to 1. However, a thread block configuration of 32x16 enables more parallelism than the 32x32 launch configuration. Clearly, reads from a column of the 2D shared memory array create bank conflicts. Running this kernel on the Tesla M2090 would yield a replay of 16 transactions. Accessing a column on a Fermi GPU with a bank width of 4 bytes would result in a 16-way conflict because one column has 16 data elements with a length of 4 bytes. However, the Tesla K40 has a bank width of 8 bytes, leading to a reduction in bank-conflicts.

# Matrix Transpose with Padded Shared Memory

By adding column to row in the 2D shared memory array tile, the data elements in the same column of the original matrix are evenly distributed among shared memory banks. The number of columns that tested kernel depends on compute capacity and thread block size. For the 32x16 thread block, columns of padding must be added for a Tesla K40 and one column for a Tesla M2090. The following statement declared the padded shared memory for the Tesla K40:

```
__shared float tile [BLOCKIDX] [BLOCKDIM + 2];
```

Additionally, to stores and loads it must be transformed to account for the extra columns in each row. Padding columns give you identical speedup, as shown in Table 5-4.

# Matrix Transpose with Unrolling

The following kernel unrolls the simultaneous processing of two data blocks: Each thread transposes two data elements strided by one data block. The goal of this transformation is to improve memory bandwidth by creating more in-flight loads and stores.

```cpp
__global__ void transposeSmemUnroll(float *out, float *in, int nx, int ny) {
    // static shared memory with padding
    __shared__ float tile[BLOCKDIM*(BLOCKDIM+2)];
    // coordinate in original matrix
    unsigned int ix = blockIdx.x * blockDim.x + threadIdx.x;
    unsigned int iy = blockIdx.y * blockDim.y + threadIdx.y;
    // linear memory index for original matrix
    unsigned int ti = iy * nx + ix;
    // thread index in transposed block
    unsigned int bdx = threadIdx.y * blockDim.x + threadIdx.x;
    unsigned int row = bdx / blockDim.y;
    unsigned int col = bdx % blockDim.y;
    // coordinate in transposed matrix
    unsigned int ix2 = col;
    unsigned int iy2 = 2 * blockDim.x + row;
    // linear memory index for transposed matrix
    unsigned int to = iy2*nx + ix2;
    if (ix+blockDim.x < nx && iy < ny) {
        // load two rows from global memory to shared memory
        unsigned int row_idx = threadIdx.y * (blockDim.x + 2) + threadIdx.x;
        tile[row_idx] = in[ti];
        tile[row_idx+BLOCKDIM] = in[ti+BLOCKDIM];
        // thread synchronization
        __syncthreads();
        // store two rows to global memory from shared memory
        unsigned int col_idx = col*(blockDim.x+2) + row;
        out[to] = tile[col_idx];
        out[to+BLOCKDIM] = tile[col_idx+BLOCKDIM];
    }
}
```

In this kernel, the 1D shared array tile with added column padding is declared statically:
__shared__ float tile[BLOCKDIM*(BLOCKDIM+2)];`

For a given thread, the input matrix coordinates and the index into the global memory array to store the input matrix are calculated as follows:

```
ix = blockIdx.x * blockDim.x * 2 + threadIdx.y;
y = blockIdx.x * blockDim.y + threadIdx.x;
ti = iy * nx + ix;
```

As illustrated in Figure 5-17, a block configuration of 32 x 16 is used with an unrolled block of size (32+32) x 16. The new index in the transposed block in shared memory is calculated as follows:

```
bidx = threadIdx.y * blockDim.x + threadIdx.x;
irow = bdx / blockDim.y;
col_idx = col * (blockDim.x + 2)
```

Because the shared memory array tile is 1D, the 2D thread index must be converted to a 1D shared memory order to access the padded index:

```
row_idx = threadIdx.y * (blockDim.x + 2) + threadIdx.x;
col_idx = col * (blockDim.x + 2) + irow;
```

Because the padded memory is not used to store data, padded columns must be skipped when calculating indices.

Finally, the output matrix coordinates in the transposed matrix and the corresponding index into global memory to store the result are calculated as follows:

```
ix2 = blockIdx.y * blockDim.y * 2 + col;
y2 = blockIdx.x * blockDim.x + 2 + irow;
to = iy2 * nx + ix2;
```

A slight extension to this kernel could provide more flexibility. You could replace the declaration of the shared memory array tile with the line below to allow for dynamic shared memory allocation. As observed in previous examples, a slight performance degradation is expected.

```
extern __shared float tile[];
```
