Your mangled functions name vary depending on compiler version. What would be familiar are the open bracket immediately after the .entry and a matching bracket later in the file. Just as in C, these brackets enclose the instructions that define each function's logic. For instance, the first function defined in your foo.ptx file is the intrinsic version and should look similar to:

```
.entry Z9intrinsicPf(
    .param .u64 _cudarm_Z9intrinsicPf_ptr
{
    .reg .u64 %rd3<3>;
    .reg .f32 %f<7>;n    .loc 14 4 0
.LDWben Z9intrinsicPf:
    .loc 14 5 0
    ld.u64 %rd1, [_cudarm_Z9intrinsicPf_ptr];
    ld.global.f32 %f1, [%rd0];
    lg2.approx.f32 %f2, %f1;
    mov.f32 %f3, 0x04000000;
    mul.f32 %f4, %f2, %f3;
    ex.approx.f32 %f5, %f4;
    st [%rd0], %f5;
    .loc 14 6 0
    exit;
.LDWend Z9intrinsicPf:
} // Z9intrinsicPf
```

It takes 17 lines to implement the intrinsic _powf, and a mere few instructions to perform a floating-point exponentiation. However, if you take a look at the standard powf defined in your foo.ptx file, it is likely, much longer (344-lines using the CUDA 5.0 Toolkit). While line counts cannot directly translate to instructions or cycles, you can imagine the savings in performance are still significant.

However, it is not performance that separates standard and intrinsic functions; they also differ in precision.
