At some point in the OpenACC parallel region may transition to parallelize work across gangs. In that case, the region enters gang-partitioned mode. In gang-partitioned mode, there is still only one active element and one active worker in each gang, but each vector element is executing a different piece of the parallel region. Hence, the work of this computational region is partitioned across gangs. In CUDA, gang-partitioned mode would be implemented as a single thread in each block processing a separate data point. For vector addition, a CUDA kernel executing in gang-partitioned mode would look like

```
```cpp
__global void kernel(int *n1, int *n2, int *out, int N) {
    if (threadIdx.x == 0) {
        int i;
        for (i = blockDim.x; i < N; i += gridDim.x) {
            out[i] = n1[i] + n2[i];
        }
    }
}
```
```

What about worker and vector parallelism? Well, when a single worker is active per gang it is called worker-single mode. When a vector element is active per worker it is called vector-single mode. Both gang-redundant and gang-partitioned modes are therefore also worker-single and vector-single modes.

In worker-partitioned mode, the work of a parallel region is divided among multiple gangs but also workers. Using all workers in gangs provides G × W-way parallelism. In CUDA, worker-partitioned mode would be implemented by the first thread in each gang:

```
```cpp
__global void kernel(int *n1, int *n2, int *out, int N) {
    if (threadIdx.x == 0) {
        int workerId = threadIdx.x / warpSize;
        int workersPerBlock = blockDim.x / warpSize;
        int i;
        for (i = blockDim.x * warpsPerBlock + workerId; i < N; i += gridDim.x * warpsPerBlock) {
            out[i] = n1[i] + n2[i];
        }
    }
}
```
```

In vector-partitioned mode, the work is divided among gangs, workers, and vector elements, providing full G × W × v-way parallelism. This is the mode that is most similar to what you have been writing CUDA. As a result of these OpenACC directives, the parallelism of an application can be adjusted dynamically within a single parallel region of code.

When using OpenACC, compiler directives are inserted by the programmer to indicate regions of code that can be, should be, in parallel. Compiler directives also indicate the type of parallelism to use. A compiler directive is a single line of source code that, in C/C++, starts with #pragma. OpenACC directives are uniquely identified with the acc keyword, meaning that all OpenACC directives begin with #pragma acc.
