# CUDA Programming Structure

The CUDA programming model enables you to execute applications on heterogeneous computing systems by annotating code with small extensions to the C programming language.
A heterogeneous environment consists of CPUs complemented by GPUs, each with its own memory shared by a PCI-Express bus. Therefore, you should note the following:

+   - Host: The CPU and its memory (host memory)
- Device: The GPU and its memory (device memory)

To clearly design the different memory spaces, example code in this book uses variable names that start with h_ for host memory, and d_ for device memory.
Starting with CUDA 6, NVIDIA introduced a programming model improvement called Unified Memory, which bridges the divide between host and device memory. This improvement allows you to access both the CPU and GPU using a single pointer, while the system automatically migrates data between the host and device. More details about the unified memory will be covered in Chapter 4. For now, it is important that you learn how to allocate the host and device memory, and explicitly copy data that is shared between the CPU and GPU. The programmer-managed control of memory and data gives you the power to optimize your application and maximize hardware utilization.

A key component of the CUDA programming model is the kernel—the code that runs on the GPU. As the developer, you can express a kernel as a sequential function. From the scenes, CUDA schedules scheduling kernels on GPU threads. From the host, you define how your algorithm is mapped to the device based on application data and GPU capability. The intent is to enable you to use the logic of your algorithm in a straightforward fashion (by writing sequential code) and not get bogged down by details of creating and managing thousands of GPU threads.

The host can operate independently of the device for most operations. When a kernel has launched, the control is returned immediately to the host, freeing the GPU to perform additional tasks complemented by parallel code running on the device. The CUDA programming model is primarily asynchronous so that GPU computation performed on the GPU can be overlapped with host-communication. A typical CUDA program consists of serial code complemented by parallel code. As shown in Figure 2-2, the serial code (as well as task parallel code) is executed on the host, while the parallel code is executed on the GPU device. The host code is written in ANSI C, and the device code is written using CUDA. You can put all in a single source file, or use multiple files to build your application or libraries. The NVIDIA Compiler (nvcc) generates the executable code for CUDA both host and device.

A typical processing flow of a CUDA program follows this pattern:

+   1. Copy data from CPU memory to GPU memory.
2. Invoke kernels to operate on the data stored in GPU memory.
3. Copy data back from GPU memory to CPU memory.
