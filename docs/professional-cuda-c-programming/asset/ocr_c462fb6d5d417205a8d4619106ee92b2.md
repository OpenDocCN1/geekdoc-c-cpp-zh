This example can be built using:

```
$ nvcc -lcurand replace-rand.cu -o replace-rand
```

Both of these works are illustrated by the replace-rand.cu example. In replace-rand.cu, there are three different functions for retrieving a random, single-precision-floating-point value between 0.0f and 1.0f. host_rand simply fetches a random value from the host’s system call. cuda_host_rand uses curRAND’s API to pre-generate a batch of random values and iterates over that batch in successive calls to cuda_host_rand. It keeps track of the number of values that were pregenerated and the number of values already used, and uses these to determine when a new batch must be generated. cuda_device_rand uses the curRAND device API to perform the same task by pre-allocating a set of curRAND state objects on the device, using those objects to generate batches of random numbers and managing the data in the same way that cuda_host_rand does.

One item of note with the curRAND implementation provided in this example is the jitter caused by creating bursts. While the majority of calls to cuda_host_rand and cuda_device_rand will be fast and consist of only an array reference and a counter increment, every call will need to regenerate a batch of random numbers using the GPU and will take much longer. This unexpected and unpredictable performance might be undesirable in certain applications. To end, a slightly modified example is provided in replace-streams.cu on wrox.com uses CUDA streams and the curRAND ability to bind to a CUDA stream and asynchronously run number generation on the GPU while the application is running.
