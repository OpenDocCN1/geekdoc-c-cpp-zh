# GRID MANAGEMENT UNIT

Kepler introduces a new grid management and dispatch system, the Grid Management Unit (GMU). The GMU can pause the dispatch of new grids and queueing suspended grids until they are ready to execute, providing the flexibility to enable multiple runtimes, such as Dynamic Parallelism.

In Fermi devices, grids are passed to the CUDA Work Distributor (CWD) from the stream queue. In Kepler devices, grids are passed to the GMU, and the GMU manages and prioritizes grids to be executed on the GPU.

The GMU creates multiple hardware work queues to reduce or eliminate false dependencies. With the GMU, streams can be kept as pipelines of work. Even when the GMU is restricted to a single hardware work queue, test above verify that grid-dependency analysis performed by the GMU can help eliminate dependencies.

# Overlap Using Breadth-First Scheduling

Earlier examples demonstrated that Fermi GPUs delivered the best results while dispatching kernels using the breadth-first approach. Now, we examine the effect of breadth-first ordering in the overlapping data transfers and compute kernels.

The following code segment dispatches both computation and communication among streams using a breadth-first approach:

```
// initiate asynchronous transfers to the device
for (int i = 0; i < NSTREAM; i++) {
    int offset = i * iElem;
    cudaMemcpyAsync(&d_A[offset], &h_A[offset], iBytes,
        cudaMemcpyHostToDevice, stream[i]);
    cudaMemcpyAsync(&d_B[offset], &h_B[offset], iBytes,
        cudaMemcpyHostToDevice, stream[i]);
}
```

```
// launch a kernel in each stream
for (int i = 0; i < NSTREAM; i++) {
    int offset = i * iElem;
    sumArrays<<<grid, block, 0, stream[i]>>>(&d_A[offset], &d_B[offset],
        &d_C[offset], iElem);
}
```

```
// queue asynchronous transfers from the device
for (int i = 0; i < NSTREAM; i++) {
    int offset = i * iElem;
    cudaMemcpyAsync(h_C[offset], &d_C[offset], iBytes,
        cudaMemcpyDeviceToHost, stream[i]);
}
```
