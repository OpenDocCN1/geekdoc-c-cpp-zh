# C Data Types ◀ 39

Observe the usage of i_ as a prefix along with the actual identifier name in the preceding examples. This notion of prefixing i_ gives an indication that the identifier defined would be of type integer. Hence, if a programmer who is trying to maintain the C program even if he is at the 1000th line of a program can easily know the type of identifier without looking at its definition. This convention of defining an identifier has been used throughout this book.

The memory space allocated to the data type `int` is compiler dependent. In some compilers, it uses 2 bytes of memory space, while in other, it may use 4 bytes of memory. To verify the size of an integer data type, we can use the sizeof operator, which will be discussed afterward. The range of values that can be stored within the identifier will also differ based on the number of bytes allocated by the compiler. Table 1 lists the range of signed integer data type:

**Table 1: Range of Signed Integer Data Type**

| :-------- | :---------------------------------------: | :---: | :---------- | :---------- | :------ | :------ |
| int       |                    2                      |  16   |             |            | -32768  | +32767 |
|           |                    4                      |  32   | Data type used to store a positive or a negative whole number in an identifier | | -2147483648 | +2147483647 |

The value range listed in Table 1 depends on the number of bytes allocated to the memory space by the compiler. For signed integers, the value range is calculated as −2<sup>(n − 1)</sup> to +2<sup>(n −1)</sup> − 1, where n refers to the number of `bits` required for storage of the range of values.

By default, all integer identifiers are considered to be signed. Hence, we can also store a negative value in the identifier, and in many cases, we may only require positive values; for example, the age of a person, year of birth, and date of birth can never be negative.
