Program 10 will be preprocessed in two steps: first, at the time of preprocessing, the preprocessor replaces 1 wherever it finds the macro name TRUE. Similarly, FALSE is replaced by 0. Thus, the statement # ISEVEN(i_x) ((i_x%2) == 0 ? TRUE : FALSE ) will be converted to #define ISEVEN(i_x) ((i_x%2) == 0 ? 1 : 0).  Observe that the macros TRUE and FALSE have been used within the macro ISEVEN, and this property is termed as macro nesting.

In the next step, the preprocessor expands the macro name ISEVEN to ((i_x%2) == 0 ? 1 : 0).  Along with the expansion, the preprocessor also replaces with the required parameters passed while calling a macro. In Program 10, variable i_num is passed as a parameter. Hence, i_x will be replaced by i_num. Thus, ISEVEN (i_num) will be replaced by ((i_num%2) == 0 ? TRUE : FALSE )

Note that when macro expansion is to be used for calculations, the entire macro body should be enclosed within parentheses. Program 11 illustrates macro call leading to unexpected result, if we fail to enclose the macro body within parentheses:

# Program 11

```
/* Program to illustrate importance of enclosing macro body within parentheses*/
#include<stdio.h>
#define CUBE(i_x) i_x * i_x * i_x

main()
{
  int i_num = 10, i_result;

  i_result= 1000 / CUBE(i_num);
  printf("The result is %d \n", i_result);
  return;
}
```

Output:

```
The result is 10000
```

Program 11 intended to calculate 1000 divided by cube of 10. The expected result is 1. However, the result of the program as displayed is 10000. This happens as i_result = 1000 / CUBE(i_num); is converted to i_result = 1000/10 * 10 * 10 after preprocessing. According to the operator precedence rule, division and multiplication hold the same precedence level and are evaluated from left to right. Thus, 1000/10 is calculated first. This results into 100, and then the expression 100 * 10 * 10 is evaluated. Macros, though advantageous, can lead to unexpected results if not defined carefully. The next section discusses about the advantages of using macros.

# Advantages of Using Macros

Macros are very useful when replacement for a single macro is to be done at multiple places in a program. It increases the readability of the program. It is also very easy to modify the constant value as modification needs to be done at a single place. Suppose a constant like PI, which we have used in Program 3, appears multiple times in a single program. The value of PI is defined as 3.14. Now, it is decided to change the value of PI
