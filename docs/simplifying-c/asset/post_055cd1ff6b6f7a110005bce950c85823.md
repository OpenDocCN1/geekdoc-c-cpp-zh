Binary file, on the other hand, is a file that holds bytes with values in the range from 0 to 0xff (0 to 255). These bytes have meanings associated with it. For example, a value of 13 means carriage return, 10 means line feed, 26 means end of file (EOF), and so on. Executable files are example of binary files. ## Text File versus Binary File

Both text files and binary files have their advantages and disadvantages. File operations on text files are slower than file operations on binary files. In binary files, no conversion takes place when the data is written into it, while the data needs to be converted to ASCII value before it is written into a text file. Depending on the compiler, integer may take two bytes, character may take one byte, and float may take four bytes of storage space in a binary file. On the other hand, irrespective of the data type, each ASCII character will take 1 byte of storage space in a text file. For example, a float value 45.789 will require 4 bytes (turbo compiler) storage space in a binary file, while in text file, each of the digits in the float value 45.789 will occupy 1 byte of storage. The decimal point itself will also occupy 1 byte of storage. Thus, the total bytes required to store a float value 45.789 in a text file would be equal to 6 bytes. File transportability across different hardware platforms is an issue with binary files. If the operating system on which the binary file is created is different from the operating system on which the binary file is being run, the file may not be interpreted. This may happen as the operating systems may have different file structure mechanism. Binary files are more suitable if random access of file contents is the requirement. They are most commonly used by programmers while dealing with records.

## 13.2 Files and Streams

A stream is a sequence of elements, which may be characters or digits. As discussed in Chapter 4, C program treats input and output as streams. In other words, the data input from the keyboard and displayed on display terminal are streams of characters or digits. Thus, the programmer does not have to worry about the different ways of sending and receiving data to various devices. The reason is that in all cases, it is the same type of stream that is send and received. Data send to and received from files are also streams. The only thing the user has to worry about is specifying pointer to a file to be accessed.

To declare pointer to a file, FILE structure type is used. It is a structure defined in a stdio.h header file. The syntax to define pointer to file is as follows:

```
FILE *fp;
```

In the preceding syntax, note that FILE is typed in upper case. The asterisk precedes the identifier name, indicating that the identifier is a pointer. The identifier *fp* here points to a file as it is declared to be of type FILE. Assuming that the programmer aims to work with file named contacts, the file pointer declaration can be as follows:

```
FILE *fp_contacts;
```

The name of the identifier is chosen to be *fp_contacts* to increase the readability of a program. It suggests that the file pointer is pointing to the file named contacts. The prefix *fp* stands for file pointer.

When a C program is executed, the following three streams are automatically opened:

- Standard input connected to standard input device keyboard
- Standard output connected to standard output device display terminal (monitor)
- Standard error connected to the display terminal (monitor)

These three files are referenced using standard predefined identifiers of the FILE type. The standard input file is referenced using file pointer *stdin*. The standard output file is referenced using file pointer *stdout*. The standard error file is referenced using file pointer *stderr*.

C library functions, such as *printf*, *putc*, and *putchar*, use the *stdout* file pointer to display output. Library functions, such as *scanf*, *getc*, and *getchar*, use the *stdin* file pointer to accept input from the keyboard. These library functions consider *stdin* and *stdout* as default arguments. Thus, the programmers do not need to worry about their declarations. However, to work with user files, the programmer has to explicitly declare a file pointer and an associate file pointer with the file he/she desires to work with. Once a file pointer is declared and associated with a file, various operations can be performed on the file.

## 13.3 File Operations

To work with files, we need to perform certain operations on it in C language. The basic file operations include the following features:

- Opening a file
- Reading data from a file
- Writing data to a file
- Appending data to a file (adding contents at the end of the file)
- Updating contents of a file
- Closing a file

C language supports number of predefined functions to assist the programmer to perform various file operations. File functions can be broadly classified into the following two types:

- High-level file I/O functions
- Low-level file I/O functions

High-level file I/O functions are basically standard library functions and can be easily used by a programmer. Low-level file I/O functions use system calls of the underlying operating system to perform lower-level I/O operations. They are relatively more complex in nature when compared to high-level file I/O functions. However, these functions are more efficient. ## 13.4 Opening and Closing a File

Before performing any operations such as reading contents of a file and writing contents to a file, the file should be first opened. To open a file, function fopen is available in C library. The function fopen accepts two parameters. The syntax of its usage is as follows:

```
file_pointer = fopen("filename", "mode of opening");
```

The first parameter is the name of the file to be opened. By default, function fopen attempts to locate file from the folder that contains C program. If a programmer wishes to open a file located in a different file, he/she can specify full path, including the file name as a first parameter. The second parameter is the mode in which a file can be opened. Mode specifies the purpose of opening a file. Table 2 lists the various modes of opening a file and its related purpose:

**Table 2: File Opening Modes**
| Mode | Purpose |
| :--- | :--- |
| r | To open a text file for reading. A file must exist if it is to be opened in a read mode. |
| w | To write contents in a text file. If the file already exists, its contents will be overwritten. If file does not exist, an attempt to create a file will be made. |
| a | To open a text file for appending contents at the end of the file. If the file already exists, its contents will be retained. If the file does not exist, an attempt to create a file will be made. |
| r+ | To open a text file for both reading and writing. A file must exist if it is to be opened in a read plus mode. |
| w+ | To create a text file both for reading and writing. If the file already exists, its contents will be overwritten. If a file does not exist, an attempt to create a file will be made. |
| a+ | To open a text file both for reading and appending. If the file already exists, its contents will be retained. If the file does not exist, an attempt to create a file will be made. |
| rb | To open a binary file for reading. A file must exist if it is to be opened in a read mode. |
| wb | To write contents in a binary file. If the file already exists, its contents will be overwritten. If the file does not exist, an attempt to create a file will be made. |
| ab | To open a binary file for appending contents at the end of the file. If the file already exists, its contents will be retained. If the file does not exist, an attempt to create a file will be made. |
| rb+ | To open a binary file for both reading and writing. A file must exist if it is to be opened in a read plus mode. |
| wb+ | To create a binary file both for reading and writing. If the file already exists, its contents will be overwritten. If the file does not exist, an attempt to create a file will be made. |
| ab+ | To open a binary file both for reading and appending. If the file already exists, its contents will be retained. If the file does not exist, an attempt to create a file will be made. |
