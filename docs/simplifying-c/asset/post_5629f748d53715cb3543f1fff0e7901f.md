## 15.3 Macro Expansion

Macros are brief abbreviations for fragment of code. Wherever macro name is used in a program, it is replaced by the contents of the macro body. The process of replacing a macro call with the contents of the macro body is called expansion of the macro call. We can create macros with the #define directive. The syntax to define macro is as follows:

```
#define macro_name macro_body
```

For example, #define TRUE 1 defines a macro named TRUE with associated macro body as 1. After the definition of the macro TRUE, if the macro is used as part of an expression within the C program, all such occurrences of macro TRUE will be replaced with value 1.

Generally, macro names used in the preprocessor directives are typed in capitals. In this way, other variables used in a program are differentiated from the macros. Program 3 illustrates the usage of preprocessor directive for substitution of symbolic constant:

### ▶ Program 3

```
/* Program to calculate the area of a circle */
#include<stdio.h>
#define PI 3.14
main()
{
    float f_rad, f_area;

    printf("\n Enter radius ");
    scanf("%f", &f_rad);

    f_area=PI*f_rad*f_rad;
    printf("Area of radius is: %f ", f_area);
    printf("\n");
    return;
}
```

**Output:**

Enter radius 4
Area of radius is: 50.240002

Program 3 calculates the area of a circle with radius 4. The area of a circle is calculated as PI * f_rad, where the value of *PI* is predefined as 3.14 and f_rad is the radius of the circle provided by the user. The value of *PI* will be the same throughout the program. Thus, it can be defined using the preprocessor directive. It increases the readability of a program. Program 3, when compiled, will be first preprocessed by the preprocessor. The preprocessor will locate PI in the entire program. It will substitute PI with 3.14, as shown in Figure 2:

![](img/5d422ba7108ffdf64376be51eaf0c459_338_0.png)

▲ Figure 2: Macro Substitution

It is known that the preprocessor directives do not end with a semicolon. A programmer may make a mistake of ending statement with a semicolon or a programmer may write a statement as `#define PI 3.14;`. Figure 3 illustrates the expansion of the source code that contains define statement with semicolon at the end:

![](img/5d422ba7108ffdf64376be51eaf0c459_339_0.png)

▲ Figure 3: Macro Substitution without Error

It can be observed in Figure 3 that the preprocessor simply replaces all the contents found after macro name. Thus, the statement f_area = PI * f_rad * f_rad, when received by the preprocessor, is converted to f_area = 3.14; * f_rad * f_rad. The preprocessor will not generate any error at this point. However, the translator will not allow the program to compile, as this statement is syntactically incorrect.

Normally, both macro name and macro body are written in a single line. No semicolon (;) is expected at the end of a preprocessor directive. We can extend a preprocessor directive by more than one line by placing a backslash (\) character at the end of each line. However, the macro will be expanded into a single line. Program 4 illustrates how to define a multiple line macro:

### ▶ Program 4

```c
/* Program to illustrate to define macro body spanning in multiple lines */
#include<stdio.h>
#define CHAR 'c',\
           'a',\
           't'
main() {
    char c_arr[] = { CHAR };
    int i_ctr;

    for (i_ctr = 0; i_ctr <= 2; i_ctr++)
    {
        printf ("%c", c_arr[i_ctr]);
    }
    printf ("\n");
    return;
}
```

# Output:

cat

In Program 4, a set of characters is defined using a macro named CHAR. Each character is separated using a backslash, considering that the next character will be replaced in a new line. An array declared in the main program is initialized using macro, where the macro CHAR is replaced by a set of characters in a single line by a preprocessor. The output of Program 4 clearly shows that CHAR is replaced by sequence of characters c, a, and t. Thus, all characters are replaced in a single line.

Preprocessor directives are usually placed in the source program before the main function statement. However, they can be defined anywhere within the program; it is not necessary to define all preprocessor directives at the beginning of the program or before the main function. As a C program is preprocessed sequentially, the use of preprocessor directive will come in effect only if the directive is used in statements written after its definition. Program 5 illustrates the usage of preprocessor directive defined inside the main function:

### ▶ Program 5

```
/* Program to illustrate defining macro within main function */
#include<stdio.h>
main()
{
    #define TRUE 1
    printf("%d\n", TRUE);
    return;
}
```

# Output:

1

In Program 5, a macro named TRUE is defined within main function. As the macro is used after its definition, the program is compiled and executed successfully. Program 6 illustrates how macros should not be used in a program:

### ▶ Program 6

```
/* Program to illustrate correct sequence to define and use macros */
#include<stdio.h>
main()
{
    printf("%d", TRUE);
    #define TRUE 1
    return;
}
```

In Program 6, macro TRUE is used before it is defined. The preprocessor will try to replace the contents of TRUE while preprocessing. However, it will not be able to resolve the replacement of TRUE. Thus, Program 6 will not compile successfully and the executable file for program will not be created.
