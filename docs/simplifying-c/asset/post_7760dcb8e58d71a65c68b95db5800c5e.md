# Real Constant

Real constant refers to decimal numbers that have fractional part. Examples of real constant are 99.657, –53.42, and so on. Real constant can also be represented by using scientific notation. In this form, a number is represented by using a *mantissa* and an exponent. For example, the value 53.42 can be represented as $0.5342 \mathrm{e} 2$ or $0.5342 \mathrm{E} 2$, where $0.5342$ is known as mantissa and 2 as exponent. # Character constant

Character constants, as the name suggests, consist of single or set of characters. There are two types of character constant in C language: single-character constant and string constant.

### Single-Character Constant

A single-character constant is represented by using single character enclosed within single quotes. Each character constant in C is associated with a numeric value known as the American Standard Code for Information Interchange (ASCII) value. Appendix II in the book lists the ASCII values associated with different characters used in C language. Examples of single-character constants are S, j, 7, and ?.

### String Constant

String in C represents set of characters. It is denoted by using sequence of characters enclosed within double quotes. String constants don’t have any ASCII value associated with it. In C, string constant “H” is not equal to single character constant 'H'. This happens because of the way in which these constants are stored in the memory. The string constant “H” will be allocated two memory spaces, while 'H' will be allocated only one memory space. This is due to the fact that strings in C are ended by adding \0, a null character. Examples of string constants are “C Programming”, “Language”, and “H”.

### Back Slash Characters

C language provides a special two-character constant. These constants are known as back slash characters or escape sequences. They are known as back slash characters as the first character is always a back slash (\), and as the output of these constants is not a printable character but white space, they are also known as escape sequence characters. Similar to single-character constants, these constants also have an ASCII value associated with them. ### Symbolic Constant

At times numeric and character constants are defined using symbolic identifier. Such constants are known as symbolic constant. To define a symbolic constant, the following syntax is used:

```c
#define identifier value
```

where #define is known as a preprocessor directive. The preprocessor directive statement instructs the compiler that the occurrence of the symbolic constant used in the program should be replaced by the constant value specified in the definition. Identifier is a symbolic name of the constant to be defined, and value is the constant value that will be associated with the symbol. Examples of symbolic constants are as follows:

```c
#define S scanf
#define MAX 1000
```

The first statement defines a symbolic constant named "S" that refers to a keyword "scanf". The second statement defines a symbolic constant named "MAX" that refers to an integer value "1000". The values of S and MAX will remain unchanged throughout the execution of the C program.

Symbolic constant when used in program allows us to make the global definition for constants that can be accessed across all functions. It also improves the readability of the program.

# 2.7 Creation and Execution of a C Program

In the previous sections, we have discussed about C programs and their outputs without bothering about how to create and execute them. Let us now learn how to create and execute the C program. The steps that we need to perform while creating and executing C program are as following:

1. Create a C program using any text editor. This program is known as a *source code* or a *source program*. The extension of the executable C program is .c.
2. We then compile the source program using a C compiler. A C compiler consists of two different programs, namely, a preprocessor and a translator. The preprocessor removes all the preprocessor directive statements from the source code and prepares the source code for translation. The translator then converts the source code into a machine language code, and vice versa. The machine language code is known as an *object code* or an *object program*. The extension of the object code is .obj.
3. The object code is then linked, if needed, with the library functions giving *executable code* or *executable program*. The extension of the executable code is .exe. For linking the object code with the object code of inbuilt functions used in a C program, we use a program called linker. The linker is needed in C as most of the operations that we perform in C have been provided as inbuilt functions.
4. Finally, the executable code is loaded to the memory by a program called loader, along with the data required to give us the output. The data required for execution of program can be fetched from a file or entered by the user. Once the program finishes its work, the control is returned to the operating system by removing the program from the memory.

This compiler is available for operating systems such as Windows, Unix, and Linux, and comes bundled with all Linux versions.

As mentioned earlier, we can use any good text editor to create a C program. The only thing that should be kept in mind is the fact that the file created should be saved with an extension .c. Make sure that c is in lower case. In Linux environment, we have editors such as vi, emacs, pico, and many more. Choose the one you are comfortable with. Once the program is ready, save it; for example, assume that Program 1 given in this chapter is saved as prog2_1.c, then the following command is written on the Linux prompt to compile it:

```
$ gcc prog2_1.c
```

If everything goes fine, a new prompt line will be visible. In case, we have errors, then appropriate error message would appear on the screen. If error occurs, we need to rectify the program and recompile. If no error appears, it means that the compilation is successful and an executable file with the name a.out is available in the same directory as the source file.
