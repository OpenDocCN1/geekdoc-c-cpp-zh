## 15.1 A Preprocessor Directive

Preprocessor directives are special lines included in the source code of C programs. These lines are not executable program statements, but provide instructions to the preprocessor. The preprocessor based on the instructions given by the lines then performs some tasks in C program. From the earlier chapters, we know that a C program is a collection of statements known as source code. When the program is compiled, the first program that it comes across is preprocessor. Recall that till now, we have written #include<stdio.h> in almost every program. This statement is a preprocessor directive statement. The main task of the preprocessor is to replace the preprocessor directive statements with its actual definition. Thus, some symbolic constants or statements in the C source code will be replaced by other lines of code as defined in the preprocessor directive.

Preprocessor directives follow a special syntax; they always begin with the hash (#) sign. Unlike other C statements, the preprocessor directives do not end with a semicolon (;). End of the line is considered as end of the directive. C language provides different category of preprocessor directives for different purposes. Table 1 lists a set of common preprocessor directives and their purpose:

Table 1: Preprocessor Directives

| Category | Directive | Purpose |
| :--- | :--- | :--- |
| File inclusion | #include | Specify source code of external files to be included in a program |
| Macro expansion | #define | Define substitution macros |
| Conditional compilation | #if, #else, #ifndef, #ifend, #endif | Conditional compilation of macros |
|  | #undef | Undefine macros |

The next section discusses about each of the directives mentioned in Table 1 with examples.

## 15.2 File Inclusion

C language allows modular programming; hence, a code once created can be reused again. To reuse the code, we may prepare C files, which are considered to be external files. The external files usually contain functions, macros, prototype declarations, or any other valid C statements. To use them in any C program, we then need to use the preprocessor directives. The syntax to include the header file in a current C program is as follows:

```
#include<file name>
```

For example, #include<stdio.h> will be replaced by the source code written in stdio.h header file. Figure 1 shows the expansion of the source code expanded by the preprocessor:

![](img/5d422ba7108ffdf64376be51eaf0c459_335_0.png)

It can be observed in Figure 1 that the preprocessor inserts the entire code of file stdio.h in the program in which the preprocessor directive is defined. Normally, the files included are either header files with .h extension or C files with .c extension. We may include any text file in a C program without worrying about the extension. The text file included should contain statements that adhere to C syntax. C language provides a huge collection of header files in the C library. Functions and declarations available in these header files can be readily used by programmers.

The preprocessor, when it finds #include directive with a header file name, first locates the header file. Then it inserts the contents of the header file in C program. Note that we have used less than (<) and greater than (>) symbols to enclose the file name. These symbols direct the preprocessor to locate the header file from within the system library. Another form of using the same directive is to enclose the file name between double quotation (“”). The syntax for enclosing the file name between double quotations is as follows:

```
   #include “file name”
```

For example, #include “factorial.c” includes a user-created file named factorial.c in the current C program. As the file name is enclosed within double quotes (“”), the preprocessor looks for the file in the folder that contains the source code. Normally, it tries to look into the current folder. This preprocessor directive helps to create personal C library. The reason for creating a personal library is to reuse the code once it has been written. For example, the function to calculate the factorial of a number can be used for many different purposes. We can define the function in one C program. Let us name the program as prog15_1.c. Later, prog15_1.c can be included in another C program using the #include directive. The factorial function then can be used as if it is defined in the same program.
