# ### 15.4 #undef Directive

At times it is desirable to undefine an existing macro. This can be accomplished by #undef directive. For example, to undefine the macro TRUE defined in Program 10, the statement #undef TRUE can be used. Once a macro has been undefined, the identifier associated with that macro can be reused to define another macro in a subsequent #define directive.

C has a rich collection of directives; the next section discusses the conditional compilation directives available with C.

# ### 15.5 Conditional Compilation

So far we have seen that statements in C program are executed sequentially. To change the sequence of execution, or skip some statements, or execute one set of statements on one condition and another set on other condition, we have discussed sequence control structures in Chapter 6. A preprocessor conditional compilation directive causes the preprocessor to compile portions of the source code based on conditions specified by the user. These directives test a constant expression or an identifier to determine which tokens the preprocessor should pass on to the compiler and which tokens should be bypassed during preprocessing. Table 3 lists the various directives and their purpose:

| Directive | Purpose |
| :--- | :--- |
| #if | The code following the #if directive will be executed only when the condition specified along with #if is true |
| #ifdef | To check whether the macro is defined or not |
| #else | To specify alternate code to be executed in case of if condition failure |
| #ifndef | To specify set of statements to be executed if macro is not defined |
| #elif | To specify alternate condition in case of if condition failure |
| #endif | End of if expression |

We have defined macro CUBE in Program 11. Program 12 illustrates the usage of #ifdef directive to check whether CUBE is defined or not. If defined, the statements following the #if directive will be compiled.
