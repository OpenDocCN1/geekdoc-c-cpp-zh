# ■ **Binary file**

Binary file, on the other hand, is a file that holds bytes with values in the range from 0 to 0xff (0 to 255). These bytes have meanings associated with it. For example, a value of 13 means carriage return, 10 means line feed, 26 means end of file (EOF), and so on. Executable files are example of binary files. The contents of the binary file when open in an editor would not be of any significance to the user as it cannot be read. Figure 3 illustrates a binary file opened in a Notepad editor:

# ■ **Text File versus Binary File**

Both text files and binary files have their advantages and disadvantages. File operations on text files are slower than file operations on binary files. In binary files, no conversion takes place when the data is written into it, while the data needs to be converted to ASCII value before it is written into a text file. Depending on the compiler, integer may take two bytes, character may take one byte, and float may take four bytes of storage space in a binary file. On the other hand, irrespective of the data type, each ASCII character will take 1 byte of storage space in a text file. For example, a float value 45.789 will require 4 bytes (turbo compiler) storage space in a binary file, while in text file, each of the digits in the float value 45.789 will occupy 1 byte of storage. The decimal point itself will also occupy 1 byte of storage. Thus, the total bytes required to store a float value 45.789 in a text file would be equal to 6 bytes. File transportability across different hardware platforms is an issue with binary files. If the operating system on which the binary file is created is different from the operating system on which the binary file is being run, the file may not be interpreted. This may happen as the operating systems may have different file structure mechanism. Binary files are more suitable if random access of file contents is the requirement. They are most commonly used by programmers while dealing with records.
