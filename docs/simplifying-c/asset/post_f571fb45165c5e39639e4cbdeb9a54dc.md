Opening a file basically establishes a linkage between a program and the file to be used. To use a file, a file pointer has to be associated, as discussed in section 13.3 of this chapter. The function fopen returns a pointer to a file being opened. Thus, the following two statements are to be stated in a program to start working with files:

```
FILE *fp_data;
fp_data = fopen("data.txt", "r");
```

There is a possibility that due to some reason, the file we are trying to open may not be opened. For example, a file named data.txt may not exist. As stated in Table 2, a file must exist for reading. Similarly, while opening a file in a write mode, the function fopen may fail to open a file. The reason could be insufficient memory space, damaged disk, read-only file, and so on.

If the function fopen fails to open a file, it returns NULL value. Remember that NULL is defined in the stdio.h header file. Thus, an appropriate message can be displayed to the user if there is some error in opening a file. Program 1 illustrates how to open a file and display appropriate message in case of failure to open the file.

## ▶ Program 1

```
/* Program to open a file for reading*/
#include<stdio.h>
/* Beginning of main function */
main()
{
	FILE *fp_data;
	fp_data=fopen("data.txt","r");
	if (fp_data==NULL)
	printf("File could not be opened successfully....\n");
	else
	printf("File is ready for reading....\n");
	fclose(fp_data);
	return;
}
/* End of function main */
```

## Output 1:

```
File could not be opened successfully......
```

## Output 2:

```
File is ready for reading....
```

In Program 1, a file pointer named fp_data is defined to be of type FILE. This file pointer can be associated with any file. The function fopen is called to open a file named data.txt. The mode specified to open a file is r. It indicates the file is opened only for reading its contents. As discussed earlier, the function fopen returns NULL value if file cannot be opened. The if condition is used to check whether a file is opened for further operations or not. Note that two outputs of Program 1 are shown. You may get a message File could not be opened successfully...... if no file named data.txt exists in the folder where Program 1 is located. Create a text file named data.txt. Now execute Program 1 again and you will get a message File is ready for reading... This indicates that the file is successfully opened.

Note the statement fclose(fp_data); in Program 1. It contains the function fclose with the file pointer as a parameter. The function fclose is used to close the opened file. Each opened file through a C program must be closed once its purpose of opening is over. When an opened file is closed, two tasks are performed. The contents of the file will be saved to disk and an EOF character is appended at the end of the file.

## 13.5 Characters and File

Once a file has been opened, it is ready to read, or write, or both, as specified in a mode. In Chapter 4, the functions getchar and putchar were discussed to read characters from standard input device and display characters on standard output device. The function getchar accepts single character from a file, and the function putchar displays single character at a time on the screen. Similarly, to write a single character to a file, the function fputc can be used.

The function fgetc can be used to read a single character from a file. Remember that a file pointer is associated with each file when a file is opened. The file pointer is positioned at the beginning of the file when it is opened. The function fputc writes one character in a file where a file pointer is positioned. It then advances the file pointer by one character. Thus, next time when the function fputc is called, a new character is written at the next position. After the character is written, the file pointer is advanced by one character again. Figure 4 illustrates how the function works:

![](img/5d422ba7108ffdf64376be51eaf0c459_297_0.png)

**Figure 4: Working of the Function fputc**

Similarly, the function fgetc returns a character that is positioned at the file pointer. It then advances file pointer by one character. Thus, next time when the function fgetc is called, it returns next character.

The syntax for the usage of function fputc is as follows:

```
fputc(ch, fp);
```

where ch is a character to be written to a file and fp is a pointer associated with a file in which the character is to be written.

The syntax for the usage of function fgetc is as follows:

```
ch = fgetc(fp);
```

where fp is a pointer associated with a file from which the character is to be read and ch is a character read from a file. Program 2 illustrates how to write contents to a file as well read the same file again and display its contents on the screen:

## ▶ Program 2

```
/* Program to illustrate the use of functions getc and putc */
#include<stdio.h>
/* Beginning of main function */
main()
{
    char c_temp;

    /* declaring file pointer */
    FILE *fp_names;

    /* Opening a file names.txt in writing mode*/
    fp_names=fopen("names.txt","w");
    if (fp_names == NULL)
    {
        printf("File could not be opened successfully\n");
        exit(1);
    }

    printf("\nEnter data you want to enter into a file, Press Ctrl+D at the end:\n ");

    /* Accepting character from keyboard */
    while ((c_temp=getchar())!=EOF)
    {
        /* writing characters to a file */
        fputc(c_temp,fp_names);
    }

    /* Closing a file */
    fclose(fp_names);

    /* Opening a file in reading mode*/
    fp_names=fopen("names.txt","r");
    if (fp_names == NULL)
    {
        printf("File could not be opened successfully\n");
        exit(1);
    }

    printf("\n \n Printing contents of file...............\n");

    /* Reading characters from a file*/
    while ((c_temp=fgetc(fp_names))!=EOF)
    {
        /* Displaying characters in screen*/
        printf("%c",c_temp);
    }
    printf("\n");
    fclose(fp_names);
    return;
}
/* End of function main */
```

## Output:

```
Enter data you want to enter into a file, Press Ctrl+D at the end:
Anya Gangele
Harshit Jain

 Printing contents of file . . . . . . . . . .
Anya Gangele
Harshit Jain
```

In Program 2, a file pointer named fp_names is defined to be of type FILE. Then a file named names.txt is opened in write mode. If file exists, its existing contents will be destroyed. If the file does not exist, a new file named names.txt will be created. Characters from the user are accepted with function getchar. This function accepts character and the character is written in the file using the function fputc. When the user presses the Ctrl + d keys, −1 is returned by the function getchar, which is the value of EOF. The while loop stops there. Once writing work is over, the file names.txt is closed by passing its associated file pointer fp_names in function fclose.

The file names.txt is again reopened using the function fopen in reading mode. The program then reads the file content character by character with the function fgetc. The character that is returned by the function fgetc is then displayed on the screen. As discussed earlier, the function fgetc will advance the file pointer by one character. When the function fgetc encounters EOF marker, reading is terminated. The file is then closed with function fclose.

Execute Program 2 twice. You might have noticed that old contents of the file gets lost and new contents are written in the file. To retain the contents, open the names.txt file in append mode. Change the mode *w* to mode *a* in the statement fp_names=fopen("names.txt","W"); Thus, the new statement will be fp_names=fopen("names.txt","a"); Recompile the program and execute it. Type Shalini Gangele. You will find that the typed contents are transferred to the file. The file is read again and the contents are displayed back on the screen. Execute the program once again. Type Puja Sethia. The name recently typed on the screen will be transferred to the file. However, when the file is opened for reading and its contents are displayed on the screen, both the names are displayed. This shows that new contents are appended at the EOF without overwriting the old contents.
