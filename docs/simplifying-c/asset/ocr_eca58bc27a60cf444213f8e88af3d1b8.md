In the earlier chapters of this book, we have discussed about many C programs, and also compiled these programs using the C compiler. C language compiler consists of two different programs, namely, a preprocessor and a translator. The preprocessor, as its name implies, is a program that processes the code before it is passed to the translator. The preprocessor removes all the preprocessor directive statements such as #include <file> from the source code and prepares the source code for translation. The translator then converts the source code into a machine language code, and vice versa. Preprocessor directives make a program easy to read, modify, and more efficient. In this chapter, various preprocessor directives for file inclusion, macro expansion, and conditional compilation are discussed. The need of directive, its usages, as well as pros and cons of the directives are also mentioned. Finally, stringizing and token pasting operator are also discussed in this chapter.

# ## 15.1 A Preprocessor Directive

Preprocessor directives are special lines included in the source code of C programs. These lines are not executable program statements, but provide instructions to the preprocessor. The preprocessor based on the instructions given by the lines then performs some tasks in C program. From the earlier chapters, we know that a C program is a collection of statements known as source code. When the program is compiled, the first program that it comes across is preprocessor. Recall that till now, we have written #define<stdio.h> in almost every program. This statement is a preprocessor directive statement. The main task of the preprocessor is to replace the preprocessor directive statements with its actual definition. Thus, some symbolic constants or statements in the C source code will be replaced by other lines of code as defined in the preprocessor directive.
