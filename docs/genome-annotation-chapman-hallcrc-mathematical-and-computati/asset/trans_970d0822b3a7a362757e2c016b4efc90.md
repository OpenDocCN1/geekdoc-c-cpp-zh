### 8.3.3 功能注释

MAKER 生成的模型转录本首先被翻译成蛋白 FastA 格式。在基础层面，MAKER 将通过 BLASTP 对比 UniProt/SwissProt 识别出的假设功能（Magrane et al., 2011）。除了这种“最佳命中”方法外，使用 GMOD 组件进行功能注释的机制尚未标准化。GMOD 组件被许多模式生物社区使用，每个社区都有其生成功能注释的偏好机制。它们所使用方法的多样性反映了植物、真菌、哺乳动物和其他社区所面临的不同数据源挑战，以及它们所能投入到注释过程的人力和计算资源数额。这些系统的共同点是它们将结果存储在名为 Chado 的 GMOD 数据库系统中（Zhou et al., 2006）。从 Chado 数据库中中，随后可以使用多个 GMOD 工具进一步处理数据，例如用于可视化。

### 8.3.4 用户界面

在命令行上运行时，MAKER 的输入本质上是一个 FastA 格式的序列文件和（如果可用）转录本数据。提供基于 Web 的 MAKER 版本，它要求将上述若干输入上传到服务器。MAKER 的输出为 GFF3 或 FastA 格式，旨在直接加载到 GMOD 基因组浏览器组件中。GBrowse 查看器（Stein et al., 2002）可以将注释信息与其他数据源叠加进行查看。如需编辑注释，可以使用 Apollo 基因组浏览器。图 8.7 显示了一个示例，其中 Apollo 显示了最终的 MAKER 预测结果以及生成它而收集的所有证据。

### 8.4 AGeS

随着细菌基因组测序已成为常态，对快速、自动化注释的需求促使了此类分析工具的发展。AGeS（Kumar et al., 2011）是专注于原核生物的基因组注释工具的典型示例。

### 8.4.1 分析管理

AGeS 使用 OpenMPI 库（www.open-mpi.org）来实现计算密集型任务的并行化，并通过 PBS（www.pbworks.com）队列系统管理任务调度。分析任务的状态及其结果存储在嵌入式关系型数据库管理系统 (RDBMS) Apache Derby（http://db.apache.org）中，这需要很少的人工管理。该数据库与 Web 服务器协作，为基因组注释过程的任务监控和结果提供图形界面。

### 8.4.2 结构注释

AGes 基于现有的注释流水线 DIYA（Stewart et al., 2009），DIYA 经过定制，使用 Glimmer（Delcher et al., 2007）预测基因位置，通过 RNamer（Lagesen et al., 2007）预测核糖 RNA，并使用 tRNAScan-SE（Lowe and Eddy, 1997）预测转移 RNA。原核生物基因检测的简单性意味着，单一结构预测方法对于大多数用途即可。

### 8.4.3 功能注释

AG 的功能注释部分是 PIPA。一种自动化本体映射生成算法将各种分类方案映射到 GO。PIPA 通过将 GO 语映射到多个程序和数据库（如第 7 章讨论的 InterPro 和 NCBI 跨域数据库）的异异结果来预测蛋白质功能。蛋白质谱生成算法创建自定义数据库以预测特定的蛋白质功能，以提高注释的特异性。该算法用于构建内置酶谱数据库 CatFam（Yu et al., 2009），它可以预测由 EC 编号描述的催功能。

共注释基于集成程序和数据库的自动协调。计算各种原核生物注释流水线之间一致性可以在多个水平进行。一种常用方法是比较 EC 或 GO 术映射。使用这种方法，AGes 的注释与 IMG（Markowitz et al., 2010）等流行的 Web 系统生成的注释高度一致。原核生物注释系统之间的主要区别在于功能描述文本以及与外部数据源的链接程度。
