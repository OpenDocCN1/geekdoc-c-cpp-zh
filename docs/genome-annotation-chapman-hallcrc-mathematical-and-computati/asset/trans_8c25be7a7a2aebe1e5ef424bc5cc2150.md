## 10.4.2 结果界面

点击绿色箭头（图标栏中的第五个图标，位于图 10.5 主栏上方）将使 Taverna 验证工作流。如果验证成功，显示将切换到结果视图，如图 10.6 所示。该视图的主要组件有：(a) 执行中的工作流（进度条）；(b) 工作流输出；(c) 输出列表；以及 (d) 工作流执行列表。

在执行工作流之前，会提示任何所需的输入参数，以便用户提供。根据工作流的不同，这些所需的输入可能是单个文本值、带有多个条记录的特殊格式输入文件或一个电子表格。Taverna 将从提供的输入列表遍历每个工作流步骤，与手动分析基因组规模数据相比，实现了极高的效率。

![](img/7da802df4d7c0829a4a41adf9acaf30d_204_0.png)

图 10.6 结果模式下的 Taverna 界面。主要组件为：(a) 工作流执行进度的实时显示；(b) 单个服务或工作流总输入/输出的显示；(c) 服务输入/输出数据树；以及 (d) 工作流实例选择器。

工作流并不总是需要用户的显式输入。例如，一个工作流可能起始于对牛（*Bos taurus*）基因数据库进行固定的 BioMart 查询。该固定查询可以产生一个基因名称列表，这些名称将作为工作流其余部分的输入（例如，文献检索）。运行此工作流不需要用户输入。要更改工作流的行为（例如使用不同的物种），用户必须在设计模式（Design mode）下编辑 BioMart 处理器的设置。

在工作流执行期间，工作流中的每个处理器都会显示（图 10.6a）使用颜色条的进度指示器。对于基因组规模数据分析的效率而言，Taverna 在数据可用时自动将其转发到下一个工作流步骤至关重要；系统不会等待所有输入完成一个任务才开始下一个分析步骤。在图 10.6 中这一点很清楚，因为根据进度指示器，多个步骤正在同时进行中。在工作流执行期间和之后，可以通过点击所需的处理器并导航到生成的数据树（图 10.6c）查看中间结果。数据树的导航需要记住 Taverna 中数据处理的嵌套列表处理模型。在用户钻取到数据树的最底层之前，感兴趣的实际结果不会显示在图 10.6d 中。

Taverna 将工作流执行结果存储在内部数据库中。需要注意的是，为了确保任何感兴趣的结果都能被妥保存，必须在退出 Taverna 之前将它们保存到磁盘，否则它们将会丢失。

## 10.4.3 工作流仓库

通常情况下，复用和修改现有的工作流作为进一步基因注释的基础，与从头开始开发新的工作流一样，这都是一项异常艰巨的任务。myExperiment.org 网站（Goble and De Roure, 2007）是一个生物信息学相关工作流的仓库，包含了为 Taverna 和 Galaxy 编写的工作流。可以通过关键词对仓库进行搜索，因为对于特定的分析步骤或分析工具需要访问服务提供者，也可以通过作者提供的工作流自由文本描述进行搜索。用户可能希望查看现有的工作流是否可以完成他们想要的任务，从而避免进行任何新的工作流编程。或者，可能存在一个执行相关任务的工作流，只需使用 Galaxy 或 Taverna 编辑器进行少量修改即可实现所需结果。无论何种情况，仓库都包含每个可用工作流的许可和归属信息。

## 10.5 SEAHAWK

Seahawk 结合了 Galaxy 的“围墙花园”门户方法的易用性与 Taverna 开放 Web 服务方法的灵活性和强大。这种组合在 Seahawk 中通过使用一种名为 Moby 的 Web 服务（BioMoby Consortium et al., 2008）实现。Moby 由一个领域特定数据类型的开放本体论（如图 10.7 所示）以及一种用于在 Web 服务之间通信这些领域特定输入和输出的格式（XML）组成。这些特殊的 Web 服务被称为 Moby Web 服务（BioMoby Consortium et al., 2008）。
