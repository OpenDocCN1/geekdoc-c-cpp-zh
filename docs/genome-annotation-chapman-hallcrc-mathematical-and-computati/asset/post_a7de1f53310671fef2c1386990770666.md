# Web-Based Workflows

## 10.1 INTRODUCTION

The annotation pipelines discussed in Chapter 8 have fairly fixed inputs, analysis steps, and outputs. Dynamic display systems as those discussed in Chapter 9 can help achieve individually customized view of the results. On the other hand, redefining the outputs in existing pipelines is very difficult for non-programmer. In this chapter, we explore the means by which a user with limited programming abilities can create their own pipelines, for example, to supplement standard genomic pipelines with additional evidence or to find a subset of genes of interest. In general terms, end-user pipeline tools (also known as workflow editors) for local resources, such as Kepler (Ludaescher et al., 2006), will not play a major role in the field of genome annotation at this point. Three Web-based pipeline tools, which do not require large local infrastructure, are discussed in detail.

## 10.2 PRINCIPLES OF WEB-BASED WORKS

### 10.2.1 Motivation

Besides the obvious reason that automation provides efficiency for custom analysis of genome-scale data sets, there are several reasons for adopting workflows in bioinformatics. First, a formal workflow can be used to document the analysis process, which provides useful information for papers because they are communicative and provide the background for reproducibility. Workflows can be rerun periodically to ensure the results are up to date, with respect to the reference databases they were compared to. Creating a workflow can save effort; for example, through slight modifications it might be used to perform different but related analyses. Web-based workflows may take different forms, either as workflow environments that use local tools or desktop workflow environments that are accessed via a Web portal. Both types of Web-based workflows are described in detail, with Galaxy in the first category, and Taverna in the latter.

### 10.2.2 Early Workflow Environments

In 2004, Knikker et al. (2004) provided a bioinformatics scenario involving Web services. They tried to implement this in three ways: with a Java program, with a workflow tool, and with Taverna (Oinn et al., 2004). They concluded that the Java program was the most straightforward approach, but this was derived from the perspective of the professional programmer. The programming of scientific workflows has been a gradual evolution toward graphical editors and workflow repositories. Graphical tools simplify the process of custom analysis by biologists, as they require less knowledge of programming. A few prominent tools for bioinformatics workflow automation are:

- BioPipe (Hoon et al., 2003) uses a hand-written XML specification for the workflow and is implemented as a set of command-line scripts interfacing to the BioPerl (Stajich et al., 2002) library of analysis modules.
- Pegasus (Shah et al., 2004) has a graphical workflow builder for locally installed tools. The system is backed by a custom database.
- Integrator (Chagoyen et al., 2004) uses XQuery (www.w3.org/XML/Query) for dissecting and coordinating disparate Web-based resources. It also includes a custom instruction set to integrate data from multiple sources using collection and filtering steps. It relies on the pertinent data being available in a format known as XML.
- Wildfire (Tang et al., 2005) includes a graphical workflow builder with more advanced control elements, such as for-each loops. For the analysis steps, it employs grid-based computing for large data sets, with programs accessed via command-line definitions in EMBOSS format (Rice et al., 2000).
- Jopera (Pautasso and Alonso, 2005) started as a bioinformatics workflow tool but became business-oriented during its development. It includes spreadsheet-like evaluation functions, integrates the Eclipse editor (www.eclipse.org) and uses Web Services (see Section 10.4) for analysis tasks.
- Bio-STEER (Lee et al., 2007) has a relatively simple graphical interface and workflow composition mechanism, and uses World Wide Web Consortium's OWL-S standard (www.w3.org/Submission/OWL-S) to describe Web services, with knowledge domain-specific labels.

Three more contemporary approaches to workflow automation are described in more detail next.

## 10.3 GALAXY

### 10.3.1 Interactive Analysis

The Galaxy site (www.usegalaxy.org) provides a Web portal for running large-scale bioinformatics analyses (Gocks et al., 2010). The typical Galaxy user interacts with the system stepwise, interacting data files they upload to the system. Entries in files containing records are all automatically processed the same way, allowing users to process large-volume data sets efficiently. Figure 10.1 shows the Web interface for this interactive analysis process. The interface has three main panels, with the list of available actions on the left, the input form in the middle, and the action history on the right.
