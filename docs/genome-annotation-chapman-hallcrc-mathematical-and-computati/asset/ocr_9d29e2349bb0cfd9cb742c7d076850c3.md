Workflows can be rerun periodically to ensure the genome annotation results are up to date, with respect to the reference databases they were compared to, and by extension the current scientific knowledge base. Creating a workflow can save effort the road through its reuse. For example, through slight modifications it might be used to perform different but related analyses in follow-up research.

Web-based workflows may take different forms, manner either as workflow environments that use local analysis tools but are accessed via a Web portal interface, or desktop workflow environments that coordinate Web-based analysis services. Both types of Web-based workflows are described in detail, with Galaxy in the first category, and Taverna and Seahawk both in the latter.

# 10.2.2 Early Workflow Environments

In 2004, Knikker et al. (2004) provided a bioinformatics analysis scenario involving Web services. They tried to implement this in three ways: with a Java program, with a business workflow tool, and with Taverna (Oinn et al., 2004). They concluded that the Java program was the most straightforward approach, but this conclusion was derived from the perspective of the professional programmer. The programming of scientific workflows has been a gradual evolution toward graphical editors and workflow component repositories. Graphical editing tools simplify the process of custom programmatic analysis by biologists, as they require less resources and less knowledge of a programming syntax. +   - BioPipe (Hoon et al., 2003) uses a hand-written XML specification file for the workflow and is implemented as a set of command-line Perl scripts interfacing to the BioPerl (Stajich et al., 2002) library of bioinformatics analysis modules.

+   - Pegasus (Shah et al., 2004) has a graphical workflow builder for locally installed tools. The system is backed by a custom database.
