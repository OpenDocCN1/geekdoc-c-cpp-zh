## 16.6 异常规范

可选的异常规范（也称为抛出列表）枚举了一个函数可以抛出的异常列表。例如，考虑以下函数声明：

```
int someFunction( double value )
    throw ( ExceptionA, ExceptionB, ExceptionC )
{
    // function body
}
```

在此定义中，异常规范以函数参数列表右括号后的关键字throw开头，表明函数someFunction可以抛出类型为ExceptionA、ExceptionB和ExceptionC的异常。函数只能抛出规范所指示类型的异常，或抛出从这些类型派生的任何类型的异常。如果函数抛出的异常不属于指定类型，异常处理机制将调用函数unexpected，进而终止程序。

未被捕获的异常终止时，该函数中的所有局部变量都会被销毁，控制权返回到最初调用该函数的语句。如果try块包围该语句，则会尝试捕获该异常。如果try块不包围该语句，则再次发生栈展开。如果没有catch处理程序捕获此异常，则调用函数terminate来终止程序。图16.4中的程序演示了栈展开。

```
// Fig. 16.4: Fig16_04.cpp
// Demonstrating stack unwinding.
#include <iostream>
using std::cout;
using std::endl;

#include <stdexcept>
using std::runtime_error;

// function3 throws runtime error
void function3() throw ( runtime_error )
{
    cout << "In function 3" << endl;

    // no try block, stack unwinding occurs, return control to function2
    throw runtime_error( "runtime_error in function3" ); // no print
} // end function3

// function2 invokes function3
void function2() throw ( runtime_error )
{
    cout << "function3 is called inside function2" << endl;
    function3(); // stack unwinding occurs, return control to function1
} // end function2

// function1 invokes function2
void function1() throw ( runtime_error )
{
    cout << "function2 is called inside function1" << endl;
    function2(); // stack unwinding occurs, return control to main
} // end function1

// demonstrate stack unwinding
int main()
{
    // invoke function1
    try
    {
        cout << "function1 is called inside main" << endl;
        function1(); // call function1 which throws runtime_error
    } // end try
    catch ( runtime_error &error ) // handle runtime error
    {
        cout << "Exception occurred: " << error.what() << endl;
```

如果对象有成员对象，并且在外层对象完全构造之前抛出异常，那么将执行在异常发生之前已构造的成员对象的析构函数。如果对象数组在发生异常时已部分构造，则只会调用数组中已构造对象的析构函数。

异常可能会阻止通常释放资源的代码运行，从而导致资源泄漏。解决此问题的一种技术是初始化一个局部对象来获取资源。当异常发生时，该对象的析构函数将被调用，并可以释放资源。

## 错误预防提示 16.4

当在new表达式中创建的对象的构造函数抛出异常时，该对象动态分配的内存会被释放。

## 16.10 异常与继承

各种异常类可以从一个公共基类派生，正如我们在16.3节讨论的那样，当时我们创建了类DivideByZeroException作为类exception的派生类。如果catch处理程序捕获基类类型异常对象的指针或引用，它也可以捕获从该基类公有派生的所有类对象的指针或引用——这允许对相关错误进行多态处理。

## 错误预防提示 16.5

将继承与异常结合使用，可以让异常处理程序用简洁的记号捕获相关错误。一种方法是分别捕获每一类派生类异常对象的指针或引用，但更简洁的方法是改为捕获基类异常对象的指针或引用。此外，分别捕获派生类异常对象的指针或引用容易出错，特别是如果你忘记显式测试一个或多个派生类指针或引用类型。

## 16.11 处理new失败

C++标准规定，当operator new失败时，它会抛出bad_alloc异常（定义在头文件<new>中）。然而，一些编译器不完全符合C++标准，因此使用失败时返回0的new版本。例如，Microsoft Visual C++ 2005在new失败时抛出bad_alloc异常，而Microsoft Visual C++ 6.0在new失败时返回0。

不同编译器对new失败处理的支持各不相同。许多较老的C++编译器在new失败时默认返回0。某些编译器在包含头文件<new>（或<new.h>）时支持new抛出异常。其他编译器则默认抛出bad_alloc，无论是否包含头文件<new>。请查阅编译器文档，以确定该编译器对new失败处理的支持。

在本节中，我们给出三个new失败的示例。第一个示例在new失败时返回0。第二个示例使用在new失败时抛出bad_alloc异常的new版本。第三个示例使用函数set_new_handler处理new失败。[注意：图16.5–16.7中的示例分配了大量动态内存，这可能导致你的计算机运行变得迟缓。]
