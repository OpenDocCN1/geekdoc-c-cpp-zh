## 5.9 混淆相等（==）和赋值（=）运算符

有一种错误类型是C++程序员无论多么有经验都容易犯的，而且频繁到我们认为有必要单独用一节来讨论。这种错误是不小心将==（相等）和=（赋值）运算符互换。这种互换之所以危害巨大，是因为它们通常不会引起语法错误。相反，带有这些错误的语句往往能正确编译，程序也能运行到底，却经常通过运行时逻辑错误产生错误结果。[注意：有些编译器在=用于通常应使用==的上下文中时会发出警告。]

C++的两个方面导致了这些问题。其一，任何产生值的表达式都可以用在任何控制语句的判定部分。如果表达式的值为零，则被视为假；如果值非零，则被视为真。其二，赋值会产生一个值——即赋值给赋值运算符左侧变量的值。例如，假设我们本意要写

```
if ( payCode == 4 )
    cout << "You get a bonus!" << endl;
```

但意外地写了

```
if ( payCode = 4 )
    cout << "You get a bonus!" << endl;
```

第一个if语句正确地给payCode等于4的人发放奖金。第二个if语句——即带有错误的那条——将if条件中的赋值表达式求值为常量4。任何非零值都被解释为真，因此这条if语句中的条件始终为真，不管实际paycode是什么，这个人总是会得到奖金！更糟糕的是，paycode本来只应被检查，现在却被修改了！

### 常见编程错误 5.14

> 使用运算符==进行赋值和使用运算符=进行相等性判断都是逻辑错误。

### 错误预防提示 5.3

> 程序员通常编写诸如x == 7这样的条件，变量名在左，常量在右。如果反过来，让常量在左、变量名在右，例如7 == x，那么当你意外地将==运算符替换为=时，编译器会保护你。编译器会将其视为编译错误，因为你无法改变常量的值。这将防止运行时逻辑错误的潜在破坏。

变量名被称为左值（lvalue，意为“左边的值”），因为它们可以用在赋值运算符的左侧。常量被称为右值（rvalue，意为“右边的值”），因为它们只能用在赋值运算符的右侧。注意，左值也可以用作右值，但反之则不然。

还有一种同样令人不愉快的情况。假设你想要用如下简单语句给变量赋值：

```
x = 1;
```

但反而写了

```
x == 1;
```

这里，同样也不是语法错误。相反，编译器只是计算这个条件表达式。如果x等于1，条件为真，表达式求值为true。如果x不等于1，条件为假，表达式求值为false。无论表达式的值是什么，因为没有赋值运算符，所以该值就丢失了。x的值保持不变，这可能导致执行时的逻辑错误。不幸的是，我们没有一个现成的技巧来帮助你解决这个问题！

### 错误预防提示 5.4

> 使用文本编辑器搜索程序中所有出现的=，并检查在每个位置使用的是正确的赋值运算符还是逻辑运算符。
