
## Welcome to the EMBOSS Developer's Guide

### Summary

This manual was written with newcomers to EMBOSS in mind. You will benefit from at least a basic appreciation of molecular biology and some familiarity with UNIX and the C programming language. You should know how to open, use, save and close files using a text editor. It will also help if you've used the EMBOSS programs and are familiar with the command line (see the *EMBOSS User's Guide*).

All of the material in the EMBOSS Guides is available on the EMBOSS website:

http://emboss.open-bio.org

### Chapter 1. Getting started

Things you should know about before you start programming, including details of the software license, installation instructions for the CVS (Developer's) release, a summary of developer documentation and instructions on how to navigate the library documentation, details of the mailing lists and how to contribute software.

### Chapter 2. Your first EMBOSS application

A step-by-step guide to writing your first EMBOSS application. This is a gentle introduction to application development and illustrates the necessary common steps.

### Chapter 3. Software development under EMBOSS

This chapter summarises the inbuilt functionality which any native application can make use of with little or no additional coding. Basic steps to development are explained: project management and planning, ACD file and C source code development, integration and compilation, debugging, quality assurance testing, documentation, distribution, maintenance, support and training. Standards and guidelines for C coding, code documentation and application documentation are included.

### Chapter 4. ACD file development

Every EMBOSS and EMBASSY program has an ACD (AJAX command definition) file which describes the application, its options (parameters) and command line interface. The ACD file controls the behaviour of the application at the command line, particularly, all the user input operations. This chapter describes all aspects of ACD file development. It shows how to write application and data definitions, how to perform operations in ACD files and control prompting of the user. Finally, utilities for debugging and testing ACD files are described.

### Chapter 5. C programming

An in-depth look at programming and memory management of EMBOSS objects (C data structures), which is essential to master and extend the libraries. The coverage includes basic C datatypes, EMBOSS objects (C data structures), a primer on programming with C pointers and memory management.

### Chapter 6. Programming with AJAX

Guides to programming with AJAX that complement the online library documentation. They include the handling of ACD files, arrays, alignments, codon usage tables, exception messages, features, file input and output, graphics, lists, maths, matrices, menus, sequence patterns, phylogenetic data, application reports, sequences, translation, ‘simple’ ACD datatypes, strings, system code and tables.

### Chapter 7. Quality assurance

Various quality assurance tests are performed on the EMBOSS code and documentation to maintain the quality and integrity of the package. You will learn how to write and run quality assurance tests for your applications.

### Chapter 8. Application documentation standards

Software without documentation often has little value whereas good documentation can enhance the usefulness of software immensely. You will learn how to write comprehensive documentation for new applications conforming to the EMBOSS style.

### Chapter 9. A complete application: secret

A detailed look at all the steps needed to develop a complete application (secret). Development of the ACD file and C source code illustrate the powerful inbuilt functionality that any EMBOSS program can make use of with little or no additional coding.

### Chapter 10. Incorporating third-party applications

There are good reasons for incorporating third-party applications into EMBOSS. This chapter summarises the benefits of wrapping and porting third-party code. Guidelines for the development of application wrappers and porting of code are given. Things are illustrated for the HMMERNEW EMBASSY package which wraps Scan Eddy’s hmmer applications for hidden Markov models. Approaches to porting applications are summarised.

### Appendix A. ACD syntax reference

The AJAX command definition (ACD) language was designed for writing ACD files for EMBOSS applications. Here the entire syntax is described in a concise form.

### Appendix B. C programming libraries

Reference information for the AJAX and NUCLEUS programming libraries.

### Appendix C. C coding standards

To ensure consistency in the EMBOSS code, all C code should conform to a basic style. These standards, which mostly concern code layout, are described in detail.

### Appendix D. Code documentation standards

The EMBOSS code documentation standards describe how to comprehensively document your code. Recommendations are provided for general comments and for structured comments documenting application and library source files, functions and datatypes.

### Appendix E. Resources

A list of programmatic interfaces to EMBOSS.

### 1.1 Licence information

EMBOSS is licensed for use by everyone under the GNU Software licences. The AJAX and NUCLEUS libraries are released under the GNU Lesser General Public Licence (LGPL). The applications are released under the GNU General Public Licence (GPL). If you plan to develop proprietary software using the libraries you should read the full licensing conditions:

```
GPL (http://www.gnu.org/copyleft/gpl.html)
LGPL (http://www.gnu.org/copyleft/lgpl.html)
```

The licences were chosen to provides maximum flexibility and encourage development. They give you freedom in software development, so long as you preserve those freedoms for others.

### 1.1.1 General Public Licence (GPL)

The GPL allows you to freely modify, copy and distribute the application source code so long as the source code of the derived work is licensed under GPL and made available. This means you can freely extend and improve the EMBOSS applications.

It is important to distinguish a ‘derived work’ from entirely new code. Typically, a derived work is either a direct modification of the original source code or is linked (statically or dynamically) to the original. For instance, software using a GPL licensed shared library would be a ‘derived work’, which is why the LGPL is used for the EMBOSS libraries to avoid this restriction. Parsing of ACD files does *not* constitute a ‘derived work’ and would not in itself be subject to the licence. Many developers have done this, for example, when writing an interface to EMBOSS.

> **Important**
> 
> The rules of the GPL licence only take effect when you distribute the code. This means you can use and modify the code for your own internal use without obtaining permission or having to notify anyone.

### 1.1.2 Lesser General Public Licence (LGPL)

The LGPL requires that all changes to the libraries must be published openly (the source code must be made available). It is possible, however, to develop a completely new application that uses the libraries without the requirement of releasing the source. The libraries can be linked with proprietary software whereas had they been licensed under the GPL the libraries could only be used with free programs.

### 1.1.3 Licensing under EMBASSY

Developers who do not use the GPL or LGPL licence can still contribute. The EMBASSY collection can include packages that use AJAX or NUCLEUS but under their own licensing conditions. They will be bound by the LGPL of the AJAX and NUCLEUS libraries, but not necessarily by the full GPL.

### 1.2 Installation of CVS (Developer's) Release

Only very basic information on EMBOSS installation is included here. For complete instructions see the *EMBOSS Administrator's Guide*. The basic installation steps are:

- 1. Download the EMBOSS source code.
- 2. Configure EMBOSS. The stable release contains a ‘configure’ script for this whereas the developer’s (CVS) version contains the files necessary to create this script.
- 3. Compile EMBOSS. This will generate the executable files from the application source code.
- 4. Set a `PATH` to the executables.
- 5. Test the installation.
- 6. Set up your databases.

#### Caution

To configure and compile EMBOSS the following GNU configuration tools must be installed on your system:

- - autoconf
- - automake
- - libtool

Your OS will often provide these packages; if not then they can be downloaded (from ftp://ftp.gnu.org/gnu/) as source code and installed (in the order shown above and making sure that each newly installed package is being found, in preference to any older version, before installing the next).

You may hit other software dependencies if, for example, you are developing graphics software; see the *EMBOSS Administrator's Guide* for more information.
