A simple method of implementing first fit would process each item by scanning down the list of bins sequentially. This would take O(N^2). It is possible to implement first fit to run on O(N log N); we leave this as an exercise.

A moment's thought will convince you that at any point, at most one bin can be more than half empty, since if a second bin were also half empty, its contents would fit into the first bin. Thus, we can immediately conclude that first fit guarantees a solution with at most twice the optimal number of bins.

On the other hand, the bad case that we used in the proof of next fit's performance bound does not apply for first fit. Thus, one might wonder if a better bound can be proven. The answer is no, but the proof is complicated.

# Theorem 10.3

Let M be the optimal number of bins required to pack a list I of items. Then first fit never uses more than 11/9 M + 7/9 bins. There exist sequences such that first fit uses 11/9 (M - 1) bins.

An example where first fit does almost as poorly as the previous theorem would indicate is shown in Figure 10.25. The input consists of 6M items of size 1/2 + epsilon, followed by 6M items of size 1/3 + epsilon, followed by 6M items of size 1/7 + epsilon. One such packing places one item of each size in a bin and requires 6M bins. First fit requires 10M bins.

When first fit is run on a large number of items of sizes uniformly distributed between 0 and 1, empirical results show that first fit uses roughly 2 percent more bins than optimal. In many cases, this is quite acceptable.
