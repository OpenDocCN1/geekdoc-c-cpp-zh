# Accessing a Collection via an Enumerator

Often you will want to cycle through the elements in a collection. For example, you might want to display each element. One way to do this is to use a `foreach` loop, as the preceding examples have done. Another way is to use an enumerator. An enumerator is an object that implements either the non-generic `IEnumerable` or the generic `IEnumerable<T>` interface.

`IEnumerator` defines one property called `Current`. The non-generic version is shown here:
```csharp
object Current { get; }
```
For `IEnumerator<T>`, `Current` is declared like this:
```csharp
T Current { get; }
```
In both cases, `Current` obtains the current element being enumerated. Since `Current` is a read-only property, an enumerator can only be used to retrieve, but not modify, the objects in a collection.

`IEnumerator` defines two methods. The first is `MoveNext()`:
```csharp
bool MoveNext()
```
Each call to `MoveNext()` moves the current position of the enumerator to the next element in the collection. It returns true if the next element is available, or false if the end of the collection has been reached. Prior to the first call to `MoveNext()`, the value of `Current` is undefined. (Conceptually, prior to the first call to `MoveNext()`, the enumerator refers to the nonexistent element that is just before the first element, you must call `MoveNext()` to move to the first element.)

You can reset the enumerator to the start of the collection by calling `Reset()`, shown here:
```csharp
void Reset()
```
After calling `Reset()`, enumeration will again begin at the start of the collection. Thus, you must call `MoveNext()` before obtaining the first element.

In `IEnumerator<T>`, the methods `MoveNext()` and `Reset()` work in the same way.
Two other points: First, you cannot use an enumerator to change the collection that it is enumerating. Thus, enumerators are read-only relative to the collection. Second, any change to the collection under enumeration invalidates the enumerator.
