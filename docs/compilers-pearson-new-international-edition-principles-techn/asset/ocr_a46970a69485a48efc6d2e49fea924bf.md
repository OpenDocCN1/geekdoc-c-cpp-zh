In the iterative algorithm, if we visit the nodes in the order $B_1, B_2, B_3, B_4$, then

$$\operatorname{IN}[B_4] = f_{B_3}\left(f_{B_1}(v_{ENTRY}) \land f_{B_2}(v_{ENTRY})\right)$$

While the meet operator is applied at the end in the definition of MOP, the iterative algorithm applies it early. The answer is the same only if the data-flow framework is distributive. If the data-flow framework is monotone but not distributive, we still have $\operatorname{IN}[B_4] \leq \operatorname{MOP}[B_4]$. Recall that in general a solution $\operatorname{IN}[B]$ is safe (conservative) if $\operatorname{IN}[B] \leq \operatorname{IDEAL}[B]$ for all blocks $B$. Surely, $\operatorname{MOP}[B] \leq \operatorname{IDEAL}[B]$.

We now provide a quick sketch of why in general the MFP solution provided by the iterative algorithm is always safe. An easy induction on $i$ shows that the values obtained after $i$ iterations are smaller than or equal to the meet over all paths of length $i$ or less. But the iterative algorithm terminates only if it arrives at the same answer as would be obtained by iterating an unbounded number of times. Thus, the result is no greater than the MOP solution. Since $\operatorname{MOP} \leq \operatorname{IDEAL}$ and $\operatorname{MFP} \leq \operatorname{MOP}$, we know that $\operatorname{MFP} \leq \operatorname{IDEAL}$, and therefore the solution MFP provided by the iterative algorithm is safe.
