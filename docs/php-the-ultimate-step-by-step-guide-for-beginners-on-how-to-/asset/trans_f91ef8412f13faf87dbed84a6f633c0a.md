

## 10.2 数据的备份与恢复

数据类型是对特定类型数据的分类。当你阅读时，你已经习惯了某些形式，例如字母和数字。因此，考虑到你利用了图像、数字和字母，识别不同类型的信息是非常简单的。你起初就可以判断一个数字是比率、时期还是现金的度量。帮助你理解比率、时间或现金度量的图像就是该信息的种类。数据库使用代码来保持对其所存储的不同类型信息的知晓。

许多编程语言要求软件设计者声明每个信息对象的数据类型，而大多数数据库框架都要求客户端指定每个信息字段的类型。可用的信息类型在不同的编程语言之间、在不同的数据库应用程序之间会有所变动。尽管如此，三种基本信息类型——数字、日期/时间字符串——仍然以某种结构的形式存在。

数值型 ID 字段结合大量的特殊数字，提供了一种确保键字段是唯一性的方法。在创建表时指定 `auto_increment` 值是为表记录生成唯一 ID 的极佳方法。例如，如果有两个名为 John Smith 的作者，而你使用他们的名字作为键，那么在识别你使用的是哪一个 John Smith 时就会遇到问题。保留其中一个的键是确保你在数据库中拥有正确信息的关键部分。

## 备份与恢复数据

事实上，即使是维护得最好的数据库偶尔也会出现问题。工具故障，特别是工具故障，真的会破坏你的网站页面。由于你正在使用数据库，仅仅下载 Web 服务器上的文档（HTML、PHP 和图片）是不够的。没有比告诉你的 Web 客户端他们需要返回数据（例如他们的记录）或需要重新制作列表项目更糟糕的了。拥有一个完整的备份可以在 60 分钟的停机时间与需要重新整理数据之间产生巨大差异。

## 复制数据库文件

你同样对你的 MySQL 数据库数据文件进行简单的文档备份，就像你下载 HTML 和 PHP 文档一样。如果你下载下载，就可以下载 MySQL 数据库文档。

我们不建议使用这种策略将数据库从一台机器迁移到另一台服务器，因为 MySQL 的不同版本可能预期这些文档具有不同的设计。MySQL 将其数据文件存储在一个特殊的信息注册表中，在 Windows 上通常位于 `C:\Program Files\MySQL\MySQL Server 4.1\data\[database_name]\`，在 Unix 变体（例如 Linux 和 Mac OS X）上位于 `/var/lib/mysql`。在执行复制备份之前关闭 MySQL 服务，以确保在操作时所有文档都来自同一时间点。

要使用你当前的数据文件完全下载并恢复 MySQL 数据库，所有文档必须在下载时的同一个注册表中进行替换。然后必须重启数据库。

## mysqldump 命令

使用 MySQL 命令行创建完整的数据库备份是理想的。你用于下载和恢复的相同工具也用于更改阶段或将数据库从一台服务器迁移到另一台；`mysqldump` 创建包含所需的 SQL 语句的内容文档，用于重建数据库对象并补充信息。`mysqldump` 命令从命令行运行，并接收下载单个表、单个数据库或所有的参数。命令语法为：

```
mysqldump -u client -p objects_to_backup
```

`mysqldump` 命令创建的备份输出到标准输出（默认打印到屏幕）。指定一个对你需要下载的对象具有访问权限的客户端。将被提示该客户端的相关密码。

使用大于符号 `>` 后跟一个文件名将此输出重定向到文档。

## 备份

我们将向你演示如何从命令行备份一个名为 `store` 的数据库。

```
mysqldump -u root -p store > my_backup_of_store.sql
```

这告诉 `mysqldump` 以 root 客户端登录数据库并下载 store 数据库。你将被提示输入设置的 root 密码。命令的输出通过重定向字符（也称为大于符号 `>`）存放在名为 `my_backup_of_store.sql` 的文件中。

## 恢复 MySQL 备份

好消息是，从 `mysqldump` 记录恢复你的数据库并不困难。备份文件的内容实际上是 SQL 语句，因此可以由 MySQL 命令行客户端准备恢复下载的信息。

如果你使用 `mysqldump --all-databases` 将你的数据库备份到名为 `my_backup.sql` 的文件，你可以恢复你的数据库：

```
mysql -u root -p < my_backup.sql
```

如果你对单个数据库进行了特定备份，情况会更复杂一些。要恢复此类备份文件，请使用 `-D` 命令行开关：

```
mysql -u root -p -D store < my_backup.sql
```

既然你已经知道如何恢复默认转储记录，我们可以继续学习关于导出和导入信息的其他应用。

## 与其他格式一起

尽管处理基于 SQL 的记录是有益的，但有时你可能需要以不同的配置保存信息。例如，处理信息列表的一种策略是 CSV（逗号分隔值）格式。`mysqldump` 命令支持这种配置。你只需要指定 `-no-create-info`、`-tab` 以及 `-fields-terminated-by` 参数：

```
mysqldump -u root -p -no-create-info -tab=/home/jon -fields-terminated-by=',
```

这告诉 `mysqldump` 为每个表生成单独的文档。它们都将被放在 /home/jon。每个文件的名称将是表名。每个文件包含由命令行指定的逗号字符（`,`）分隔的记录。

## mysqlimport 命令

当你设置数据库时，可能需要从另一个数据库或 CSV 格式的电子表格获取信息。例如，如果你正在为书籍设置数据，你可能获取当前的书籍索引。示例 8-2 显示了书籍。

要导入示例 8-2 中的信息，请使用 `mysqlimport` 命令：

```
mysqlimport -u root -p --fields-terminated-by= books.txt
```

文件名的基本部分（不包括年份或文件扩展名）决定了表名。在之前的示例中，表名是 books。该表必须存在，否则会报错。另一个重要的参数是 `ENCLOSED BY`，它允许你指定字符（例如双引号 `"`）包裹文件中的每个字段。这对于避免像《Exemplary Shell Scripting, Second Edition》这样的书名引起的问题很有用，否则会导致 `mysqlimport` 将标题的 Second Edition 部分处理为下一个字段的开始。
