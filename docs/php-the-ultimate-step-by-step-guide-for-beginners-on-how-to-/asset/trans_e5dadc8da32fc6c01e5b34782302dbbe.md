## 10.3 高级 SQL

在本节中，我们将介绍一些数据库理念，虽然这些理念对于构建你的网站来说并非完全基础，但可以增强执行效率并让你的查询更具适应性。

## 索引 (Indexes)

记录的工作方式就像书的目录符合预期一样。如果你在没有索引的情况下搜索“Make TABLE”这个魔法词，你将不得不花费大量精力翻阅书的每一页，寻找可能相关的区域。然后你得检查整个段落。这绝对不是你的时间或数据库引擎时间的有效利用。这种安排方式就是一个列表。

列表中的信息经过排序和组合，使得发现特定值变得更加明智。如果属性是排序过的，且你正在搜索某个特定内容，数据库在发现一个比你正在查找的项更大的属性时，就可以停止查找。

然而，你面临的问题与书是相同的。如果一条记录是如此独特，为什么不记录所有内容呢？有多种原因：

- 可用空间有限。
- 在编写书籍时，生成并维护一个巨大的、广泛包含的索引是低效的。
- 文件中信息过多意味着在选择信息时需要更多时间查阅文件。

通过这种方式，可以对在表中记录哪些字段做出某些深有见解的选择。每个文件都根据容量需要其特定的数据文件，当一个有序字段的内容在数据库中时，这可能包括一些准备时间。

## 何时使用索引

如果你执行一个不带 WHERE 子句的简单 SELECT 语句，将不会使用索引。

列表可以使用的三个显著区域有：

### 在 WHERE 子句中

例如，查询 `SELECT * FROM creators WHERE creator = ‘Ellen Siever’;` 如果存在 creator 部分的记录，它将利用该记录。

### 在 ORDER BY 子句中

例如，查询 `SELECT * FROM contacts ORDER BY creator;` 如果存在 creator 段落的记录，它将利用该段落的记录。

### 在 MIN 和 MAX 子句中

例如，如果 MIN 或 MAX 函数指定的段落有记录，则该查询将使用列表。

只需记住，文件在使用之前必须先定义。

## 在何处指定索引

数据库记录可以指定为 CREATE TABLE 命令的一部分，也可以通过特殊的 SQL 语句添加到当前表中。如果列表是作为 CREATE TABLE 命令的一个主要部分创建的，它在代码段的末尾指定：

`UNIQUE aud(creator)`

`UNIQUE` 命令在 creator name 字段上创建一个列表。同样，并不是所有列表都是唯一的。

## 多列索引 (Multicolumn indexes)

创建使用多个字段的 MySQL 列表也是可行的。多列唯一索引保证了字段属性的组合是唯一的。

最适合列出的字段是那些往往被用作 WHERE 语句部分的字段，特别是当你意识到包含键的组合将被使用时。这些是添加到多列列表的极佳字段。在多列记录中请求字段时，目标是让经常用于引导的字段放在前面。MySQL 使用多列文件来加速查询，无论只使用了列表的第一个估计。

主文件也是新增的。每个表允许一个主文件。尽管如此，你可以拥有你内心所愿的数量的特殊文件。

我们将执行一个带有特定 WHERE 条件的查询，然后使用 EXPLAIN 获取关于 MySQL 如何准备该查询的见解：

`SELECT * FROM creators WHERE creator = 'Arnold Robbins';`

EXPLAIN 输出提供了大量关于 MySQL 如何准备该查询的数据。

它告诉您：

- 我们正在使用 creators 表。
- 查询类型为 ALL，每条记录都经过过滤以检查正确的值。
- 由于没有匹配的记录，`possible_keys` 为 NULL。
- 此查询使用的 `key` 为 NULL。
- `key_len` 是键的长度；目前为 NULL，因为没有使用键。
- `ref` 部分显示使用了键的字段或常量；目前为 NULL。
- 必须遍历的列数。

注意，许多属性相对于索引已经发生了变化：

- `ref` 意味着从该表中读取具有协调的列表属性的行进行匹配。
- `possible_keys` 显示一个名为 `authind` 的可能键。
- `key` 显示使用了 `authind` 键。
- `key_len` 显示键的长度为 126。
- `ref` 告诉你正在使用一致的键。
- `columns` 显示搜索了一行，这比以前多得多。

相关性表明，即使对于小表，添加索引也节省了大量的处理时间。

## 使用 LEFT JOIN ON 子句进行选择

我们讨论过在 SELECT 语句中使用 WHERE 子句来执行连接（join），但也另一种连接表的方法。

与其使用 WHERE 关键字，可以使用 `LEFT JOIN ON` 来执行左连接或外部连接。左连接本质上允许你查询两个通过关系连接的表，但允许其中一个表在没有匹配的情况下也返回行。以商店表为例，你可能需要执行一个连接客户（clients）和购买（buys）的查询。使用语法：

`SELECT * FROM clients LEFT JOIN buys ON clients.user_id = buys.user_id;`
