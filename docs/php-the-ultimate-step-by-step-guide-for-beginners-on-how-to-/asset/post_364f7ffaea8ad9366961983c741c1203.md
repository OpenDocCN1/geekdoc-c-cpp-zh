
# 4.1 HTTP and the Internet

Some basic knowledge of how the Internet functions may be helpful on the off chance that you haven't programmed for the Web recently. The HyperText Transfer Protocol (HTTP) identifies how site pages are exchanged over the Internet. HTTP is the system used to exchange or pass on data on the World Wide Web. Its unique reason for existing was to give an approach to publish, distribute and recover HTML pages. The World Web Consortium (W3C) and the Internet Engineering Task Force standardized the development of HTTP, which are request-response protocols that join customers and servers. The client at the starting point, normally a web browser, is alluded to as user agent. The destination server, which stores or builds resources as well as HTML documents and pictures, is known as server. Between user agents and server, there may be intermediaries such as proxies. An HTTP customer starts a request by setting up a Transmission Control Protocol (TCP) connection to a specific port on a remote host (port 80 is default). An HTTP server listening on that port waits for the customer to send a request.

After accepting the request, the server sends back a status line, as “HTTP/1.1 200 OK,” and its own response. Depending upon the status, this response could be the file, an error message, or some other data. HTTP is made on top of TCP, which is itself layered on top of Internet Protocol (IP). The two are often termed TCP/IP. Applications on organized hosts can make associations with each other and afterward exchange information. The protocol ensures solid conveyance of information from sender to collector. TCP underpins a hefty portion of the Internet’s most prominent applications, comprising Web, email, and Shell.
