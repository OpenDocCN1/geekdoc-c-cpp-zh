The main difference between the POTS and VoIP dial configuration is the use of the session target command rather than the port command. When you use the context-sensitive help after the session target command, the router simply replies with WORD. This means that whatever you enter after the command is freeform. The time, you use the syntax ipv4:sip address> to enter a remote IP address, as shown in Example 6-11. This command also allows you to direct calls to DNS names (using dns<name> syntax) or to a variety of call-management servers, such as H.323 gatekeepers or Session Initiation Protocol (SIP) proxy servers.

After you set the session target, you can optionally use the codec destination to select the codec router should use when placing a call to this destination.

> Note: If the codec values do not match between the two routers, the call fails and returns a reorder tone (fast busy signal). This is commonly called a codec mismatch. The default codec value for VoIP dial peers is G.729.

Finally, notice that the dial peer 1100 on ROUTER_B uses the command destination-pattern 110, to direct all calls starting with the digits 110 to the CME A router. Without this wildcard, you would need to create two dial peers on ROUTER_B: one for 1101 and one for 1102.

Note: Notice that dial-peer tag 2000 is used on the CME router for VoIP peer and used on ROUTER B for POTS dial peer. This combination works just fine. The only restriction to keep in mind is that you cannot use the same dial peer value for different functions.

## Dial Peer Wildcards

As you saw in the previous sections, configuring dial peers (and destination patterns) without wildcards would be extremely consuming. Far, the most commonly used wildcard is the dot (.) which represents any dialed digit. You will find a few wildcards useful in your configurations. Table 6-3 describes these wildcards.

| Wildcard | Description |
| :--- | :--- |
| (.) | Matches any dialed digit from 0–9. |
| (+) | Matches one or more instances of the preceding digit. For example, 5+23 matches 5523, 55523 and so on. This continues up to 32 digits. |
| ([]) | Matches a range of digits. For example, [1-3]22 matches 122, 222, and 322. |
| (^) | Matches a number that does not match the entered range. |
| T | Matches any number of dialed digits (from 0–32). |
| (,) | Inserts a 1-second pause between dialed digits. |

Note: The pound symbol (#) on the keypad is not a wildcard. It immediately processes a dialed number when entered without waiting for additional digits. Tip: If you plan to create a dial peer using only the T wildcard as the destination pattern, Cisco recommends that you create the destination as .T. This requires a user to dial at least one digit to match the destination pattern. Typically, the brackets wildcard is the most difficult to understand, because it is the most flexible. Table 6-4 shows a few examples of how it can be used.

| Pattern | Description |
| :--- | :--- |
| 555[1-3]... | Matches dials numbers beginning with 555, having 1, 2, or 3 as the fourth digit, and ending in any three digits. |
| [14-6]555 | Matches dials numbers where the first digit is 1, 4, 5, or 6 and the last three digits are 555. |
| 55[59]12 | Matches dials numbers where the first two digits are 55, the third digit is 5 or 9, and the last two digits are 12. |
| ^[1-7].,[135] | Matches dials numbers where the first digit is 1–7, the second and third digits are any number, and the last digit is 1, 3, or 5. |

These wildcards are most often used when creating dial plans for PSTN access. Initially, the most logical destination pattern choice for the PSTN may seem to be 9T (for an outside line followed by any number of digits). The problem with this is that Cisco designed the T wildcard to match variable-length strings from 0-32 digits. When a user dials an outside number, such as 1408551212, the router configured with the T wildcard will sit silently and wait for the user to dial more digits. By default, the router will wait for additional dialed digits for 10 seconds, which is the interdigit timer (also called the T302 timer). Although you can force the router to process the call immediately after dialing the number by pressing the pound key (#), this is not something you would want to train all of your users to. Creating a PSTN dialing plan using wildcards other than T is not extremely difficult, as long as you think through the reachable PSTN numbers. Table 6-5 provides a sample PSTN dial-plan that you could use in the United States.

| Pattern | Description |
| :--- | :--- |
| [2-9]...... | Used for 7-digit dialing areas |
| [2-9].[2-9]...... | Used for 10-digit dialing areas |
| 1[2-9].[2-9]...... | Used for 11-digit long-distance dialing |
| [469]11 | Used for service numbers, such as 411, 611, and 911 |
| 011T | Used for international dialing |

**Note:** Although you can manually create an international dial-plan without using the T symbol, doing so can become tedious. Example 6-12 illustrates the configuration of a North American PSTN dial-plan on a router. In this example, the T1 CAS port 1/0:1 is connected to the PSTN, and internal users must dial 9 for outside PSTN access.
