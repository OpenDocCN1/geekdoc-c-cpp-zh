
# Example 6-12 Configuring a North American PSTN Dial-Plan

```
VOICE_RTR(config) dial-peer 90 pots
VOICE_RTR(config-dial-peer) description Service Dialing
VOICE_RTR(config-dial-peer) destination-pattern [469]11
VOICE_RTR(config-dial-peer) forward-digits 3
VOICE_RTR(config-dial-peer) port 1/0:1
VOICE_RTR(config-dial-peer) exit
VOICE_RTR(config) dial-peer 91 pots
VOICE_RTR(config-dial-peer) description 10-Digit Dialing
VOICE_RTR(config-dial-peer) destination-pattern [2-9]..2-9]......
VOICE_RTR(config-dial-peer) port 1/0:1
VOICE_RTR(config-dial-peer) exit
VOICE_RTR(config) dial-peer 92 pots
VOICE_RTR(config-dial-peer) description 11-Digit Dialing
VOICE_RTR(config-dial-peer) destination-pattern 9[2-9]..2-9]......
VOICE_RTR(config-dial-peer) forward-digits 11
VOICE_RTR(config-dial-peer) port 1/0:1
VOICE_RTR(config-dial-peer) exit
VOICE_RTR(config) dial-peer 93 pots
VOICE_RTR(config-dial-peer) description International Dialing
VOICE_RTR(config-dial-peer) destination-pattern 9011T
VOICE_RTR(config-dial-peer) prefix 011
VOICE_RTR(config-dial-peer) port 1/0:1
VOICE_RTR(config-dial-peer) exit
```

Two commands in this syntax deal with the automatic digit-stripping feature of POTS: dial forward-digits <numbers> and prefix <number>. The forward-digits <number> command allows you to specify the number of right-justified digits you want to forward. Notice the first dial 90 in Example 6-12. With a destination pattern of [469]11, the router would automatically strip the 9 and the 2s from the pattern before sending the call. By using the command forward-digits 3, the router forwards the right-justified digits (411, 611, or 911) and only strips the 9.

The prefix <number> command adds specified digits to the dialed number before routing the call. This is useful for dial peer 93 in Example 6-12. Because international numbers can be a variable length, it is impossible to tell what value to enter for the forward-digits command. By using the prefix 011 command, the automatic digit-stripping feature of POTS, dial peers strip the explicitly defined 9011 digits from the pattern, and the prefix adds the 011 back in its place.

# Private Line Automatic Ringdown

Although not directly related to dial peer configuration, Private Line Automatic Ringdown (PLAR) relies heavily on existing dial peers to connect a call. Ports configured with PLAR capabilities automatically dial a number as soon as the port detects an off-hook signal. The most obvious use for PLAR configurations is emergency phones in locations such as elevator or parking garages. Example 6-13 shows x1101 (shown in Figure 6-8) as a PLAR extension that immediately dials x1102 as soon as a user lifts the receiver.

# Figure 6-9 FXO PSTN Connections

Although the destination-pattern command dial peer configuration mode is useful for dictating what can go out the FXO ports, it is not useful for handling what comes in the FXO ports. When the CME_A router in Figure 6-9 receives an incoming call from the PSTN, the call information sent from the PSTN carrier does not include dialed number information (This is known as Dialed Number Identification Service [DNIS].) It includes caller ID information (known as Automatic Number Identification [ANI]), but this does not help the router know where to send the call when it is received.

As a result, the CME_A router hears a second dial tone played after they dial into the CME from the PSTN. This is essentially the router saying, "Yes, I received your call; please tell me what to do." If the caller on the phone were to dial 1500, the CME_A router would forward them to the receptionist. However, the likelihood of a PSTN caller doing this is slim. This is when PLAR comes to the rescue. Example 6-14 configures two analog FXO ports as PLAR connections for incoming calls.

# Example 6-14 FXO Port Configuration

```
CME_A(config)# voice-port 2/0/0
CME_A(config-voiceport)# connection diar 1500
CME_A(config-voiceport)# exit
CME_A(config)# voice-port 2/0/1
CME_A(config-voiceport)# connection diar 1500
CME_A(config-voiceport)# exit
```

By entering the connection plar 1500 command under both FXO ports, the router receives incoming calls from the PSTN and immediately forwards them to the receptionist rather than playing a second dial tone.

> Note: Configuring PLAR connections for incoming calls is everything you only need to do for analog FXO trunks. Digital PSTN connections (such as T1 or E1) receive DNIS information for incoming calls, which the router can use for Direct Inward Dial (DID) services.

# Understanding Router Call Processing and Digit Manipulation

Understanding how the router processes dialed digits is critical to accurately implement dial peers. There are two primary rules to guide you in your dial peer strategy:

- The most specific match wins.
- When a match is found, the router immediately processes the call.

This section presents examples of these rules in action. Example 6-15 shows the dial peers for:

# Example 6-15 Sample Peer Configuration 1

```
dial-peer voice 1 voip
destination-pattern 555[1-3]...
session target ipv4:10.1.1
dial-peer voice 2 voip
destination-pattern 551...
session target ipv4:10.1.2
```
![](img/e4ad7862dc47b4e5de0cde3b4550ad65_159_0.png)

If a user dials 55124, both peers match, but the router chooses 2 because it is a more specific match (551...). Now, Example 6-16 shows what happens if you add a third dial peer to this configuration:

# Example 6-16 Sample Peer Configuration 2

```
dial-peer voice 1 voip
destination-pattern 555[1-3]...
session target ipv4:10.1.1
dial-peer voice 2 voip
destination-pattern 551...
session target ipv4:10.1.2
dial-peer voice 3 voip
destination-pattern 5551
session target ipv4:10.1.3
```

If a user dials 555124, the router uses 3 to route the call. Likewise, the router processes only the 5551 digits and drops the 24 digits. This can be useful for emergency patterns such as 911 or 911 (North America).

> Tip: If you ever have a question of which dial peer will match a specific string, Cisco routers include a handy testing feature. From privileged mode, enter the command dialplan <number>, where number is the number you want to test. The router displays all the matching dial peers in the order in which the router will use them. The router lists more specific matches first.

> Tip: Because the router immediately routes the call after it makes a specific match, it is best to avoid overlapping dial-plans if possible.

Avoiding overlapping dial-plans may be impossible at times. In these cases, you need to get creative with your dial peers to accomplish your objectives. For example, if you are required to have a dial peer matching the destination pattern 5551 while a second dial peer has the destination pattern 5551..., you could use a configuration like this:

```
dial-peer voice 2 voip
destination-pattern 5551...
session target ipv4:10.1.2
dial-peer voice 3 voip
destination-pattern 5551T
session target ipv4:10.1.3
```
