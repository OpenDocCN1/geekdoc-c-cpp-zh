## Matching Inbound and Outbound Dial Peers

When a router receives a voice call, it must always match a dial peer in some way for the router to process the call. Although this might seem like a simplistic statement, there is actually a lot of strategy that must be in place to accomplish this in both the inbound and outbound direction. Take the scenario presented in Figure 6-10, which expands on the call leg scenario that this section on dial peers.

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_161_0.png)

Figure 6-10 Inbound and Outbound Dial Peers

In addition to the call legs, Figure 6-10 displays the dial-peer configurations to complete end-to-end calls from x1101 to x2510 and vice versa. Now, matching the outbound dial peers is easy: Take the dialed digits and compare them to the destination patterns under the dial peers you configured on the router to find the most specific match. For example, if x1101 dials x2510, the router looks out its dial peers and realizes there a VoIP dial peer direct matching the call to the IP address 10.1.1.2. When ROUTER B receives it, it realizes the dialed digits are an match to the POTS dial peer 2510, which causes the router to call out the T1 interface to access the PBX system. This process explains how routers match the outbound dial peers (shown in Figure 6-10 as call leg 2 and call leg 4), but how does router match the inbound dial peers? A router matches inbound dial peers through the following methods:

- 1. Match the dialed number (DNIS) using the incoming call-number dial peer configuration command.
- 2. Match the caller ID (ANI) using the answer-address dial peer configuration command.

In this case, the VoIP dial peer 1101 on ROUTER_B doubles as both the outgoing dial peer for calls placed to x1101, and as an incoming dial peer for calls coming from x1101.

Now, to see the inbound matching process in its entirety, imagine that there is no VoIP dial peer 1101 on ROUTER_B, as shown in Figure 6-11.

| dial-peer voice 2510 voip | dial-peer voice 2510 pots |
| :--- | :--- |
| destination-pattern 2510 | destination-pattern 2510 |
| session target ipv4:10.1.1.2 | no digit-strip |
| | port 1/0:1 |

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_163_0.png)

**Figure 6-11** Matching Inbound Dial Peers Using Dial Peer 0

The result is that you could not place calls to x1101 from ROUTER_B (or the PBX system attached to ROUTER_B). However, what if x1101 called x2510? The CME_A and ROUTER_B routers have enough information to match the outbound legs. ROUTER_B is missing the information for the inbound dial peer (call leg 3). Here's how the decision process would follow:

- 1. (NO MATCH) 2510 (the dialed number) does not match an **incoming call-number** dial peer configuration on ROUTER_B, because this command does not exist in the configuration.
- 2. (NO MATCH) x1101 caller ID information (ANI) does not match an **answer-address** dial peer configuration on ROUTER_B, because this command does not exist in the configuration.
- 3. (NO MATCH) x1101 caller ID information (ANI) does not match the **destination-pattern** dial peer configuration, because the VoIP dial peer 1101 was moved to ROUTER_B.
- 4. (NO MATCH) x1101 did not come in a POTS interface (FXS, FXO, E&M, BRI/T1/E1 digital interface) that could be matched using the port command; rather, x1101 called a VoIP connection.
- 5. (MATCH) Because ROUTER_B could not find a match using the previous methods, it uses dial peer 0.

So, now begs the question, "What is dial peer 0?" Dial peer 0 is like a default gateway dial peer that appears when there is no dial match (this applies only for inbound dial peers, not for outbound dial peers). This allows the call to complete, you have no control over dial peer 0. It does not change any of its default settings.
Dial peer 0 uses the following, unchangeable settings:

- Any voice codec: Dial 0 handles any incoming voice codec; it is not hard-coded to any specific codec.
- No DTMF relay: DTMF relay sends dialed digits outside the audio stream. This is useful because compressed codecs often distort dialed tones on the call.
- IP Precedence 0: This is probably the most painful default of dial peer 0. Setting the traffic to IP Precedence (IPP) to 0 strips all QoS markings. The router now treats voice traffic same as the data traffic.
- Voice Activity Detection (VAD) enabled: VAD allows you to save bandwidth by eliminating voice traffic during silence on the call.
- No Resource Reservation Protocol (RSVP) support: The lack of RSVP goes along with the lack of QoS for voice calls. The router does not reserve any bandwidth specifically for dial 0.
- Fax-rate voice: The router limits the bandwidth available to fax signals the maximum allowed by VoIP codec. This could affect fax calls if you are using a compressed codec.
- No application support: Dial peer 0 cannot refer calls to outside applications, such as Interactive Voice Response (IVR).
- No DID support: Dial peer 0 cannot use the DID to automatically forward calls from PSTN carrier to internal devices.

In light of this list of dial peer 0 features, it is best to always match an inbound dial peer where you can control the configuration.

## Using Digit Manipulation

Digit manipulation is the process of adding or removing digits from a dialed number to help a call reach an intended destination. You have already seen a few of digit manipulation commands during the discussion of the automatic digit-stripping feature of POTS dial peers. Before we look at examples, Table 6-6 shows a list of common digit-manipulation commands you can use on Cisco router.

### Table 6-6 Common Digit-Manipulation Methods on Cisco Routers

| Command | Mode | Description |
| :--- | :--- | :--- |
| prefix | POTS dial peer | Allows you to specify digits for the router to add before the dialed digits. Example: prefix 011 adds 011 to the first of the originally dialed number |
| forward-digits | POTS dial peer | Allows you to specify the rightmost digits to forward. Example: forward-digits 4 forwards only the rightmost four digits from the dialed number |
| no digit-strip | POTS | Enables or disables the default digit-stripping behavior of POTS dial peers. Example: no digit-strip turns off the automatic digit-stripping behavior under a POTS dial peer. |
| num-exp match | Global | Transforms any dialed number into the digits specified in the string. Example: num-exp 4 matches any four-digit number beginning with 4 into a four-digit number beginning with 5 (4123 becomes 5123). Example: num-exp 0 5000 matches the dialed digit 0 and changes it to 5000. |
| voice translation-profile | Global and POTS or VoIP dial peer | Allows to configure a translation profile consisting of up to 15 rules to transform numbers however you want. The translation profile is created globally and then applied to any dial peers (similar to an access list). |

## Practical Scenario 1: PSTN Failover Using the prefix Command

One of the benefits of VoIP communication over traditional telephony is the ability to have more than one path to a destination. Figure 6-12 shows a commonly encountered scenario.

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_165_0.png)

Figure 6-12 Multiple Voice Paths

The organization shown in Figure 6-12 prefers to use the IP WAN as its primary communication path between Arizona and Texas. However, if the IP WAN should, calls between the offices should use the PSTN as their communication path.

One of the benefits of using VoIP is the merging of voice networks into one seamless communication path. Because calls are traveling over the IP WAN, users in the Arizona office can dial the users in the Texas office using their four-digit (6XXX) extension. Like users in the Texas office can dial the users in the Arizona office using their four-digit (5XXX) extension. It would be inconvenient to require all the users in the Arizona office to dial the Texas office using the PSTN DID range rather than the four-digit extension (and vice versa).

Using a combination of preference and prefix commands, you can allow this failover transformation to occur dynamically, as shown in Example 6-17.

### Example 6-17 Dynamic WAN to PSTN Failover Implementation

```
Arizona(config)# dial-peer voice 10 voip
Arizona(config-dial-peer)# destination-pattern 6...
Arizona(config-dial-peer)# session target ipv4:10.1.1.2
Arizona(config-dial-peer)# preference 0
Arizona(config-dial-peer)# exit
Arizona(config)# dial-peer voice 11 pots
Arizona(config-dial-peer)# destination-pattern 6...
Arizona(config-dial-peer)# port 1/0:1
Arizona(config-dial-peer)# preference 1
Arizona(config-dial-peer)# no digit-strip
Arizona(config-dial-peer)# prefix 1512555
Texas(config)# dial-peer voice 10 voip
Texas(config-dial-peer)# destination-pattern 5...
Texas(config-dial-peer)# session target ipv4:10.1.1.1
Texas(config-dial-peer)# preference 0
Texas(config-dial-peer)# exit
Texas(config)# dial-peer voice 11 pots
Texas(config-dial-peer)# destination-pattern 5...
Texas(config-dial-peer)# port 1/0:1
Texas(config-dial-peer)# preference 1
Texas(config-dial-peer)# no digit-strip
Texas(config-dial-peer)# prefix 1480555
```
