
After you enter the command ephone <tag>, the CME router moves you into ephone configuration mode. Every command you enter after this directly affects the Cisco IP Phone matched to this.

After initially creating the ephone, you need to logically link it to the physical phone it represents. The CME router uses the MAC address of a Cisco IP Phone for this purpose. There are three ways to find the MAC address of a Cisco IP Phone:

- On the box of the Cisco IP Phone: The box the Cisco IP Phone ships in has the MAC address of the phone next to a UPC code.

- On the back of the Cisco IP Phone: A sticker on the back side of the phone lists the MAC address of the device. The address appears next to a UPC code.

- From the Settings menu of Cisco IP Phone: All IP Phones have a Settings button that enables you to manually configure various settings for the device. On most models of Cisco IP Phones, choosing Settings and then Network Configuration displays the MAC address of the phone on the LCD display.

> Note: A UPC code containing the MAC address information of the IP phone is beneficial if you have a handheld UPC scanner (barcode scanner). You can set the scanner to allow you to scan the MAC address of each device and then the extension number into an Excel spreadsheet. You can export this information for bulk entry of devices.

When you have the MAC address of the IP phone, you can enter it from ephone configuration mode, as shown in Example 5-7.

## Example 5-7 Assigning a MAC Address to an Ephone

```
CME_Voice(config)# ephone 1
CME_Voice(config-ephone)# mac-address ?
H.H.H Mac address
<cr>
CME_Voice(config-ephone)# mac-address 0014.1c48.e71a
```

This show output shows two configured phones: one currently registered ephone 1) with the IP address 172.30.60.31 and the other currently unregistered (phone 2).

**Tip:** If you see a phone status as DECEASED in the show phone output, the CME router has lost connectivity with the IP phone through a TCP keepalive failure. The UNREGISTERED status indicates the CME router closed the connection to the IP phone a normal manner.

With the ephone linked to a physical Cisco IP Phone, you can now begin assigning the buttons to the ephone-dn.

## Associating Ephones and Ephone-DNs

Linking phones and ephone-dns is probably the most confusing section of the CME configuration because there are so many options. You can assign ephone-dns by using the button command from ephone configuration mode. The basic syntax of this command is as follows:

```
button <physical> <separator> ephone-dn
```

Example 5-9 demonstrates the basic use of the button command.

## Example 5-9 Assigning Ephone-DN 2 to Button 1 on Ephone 1

| CME_Voice(config)# ephone 1 |
| :--- |
| CME_Voice(config-ephone)# button 1:2 |
| CME_Voice(config-ephone)# restart |

The 1:2 syntax assigns ephone-dn 2 (configured in Example 5-3) to button 1 of ephone 1. The colon (:) separator designates that this is a "normal ring" button assignment. That is, calls to 101 (the number of ephone-dn 2) causes the IP phone to audibly ring and the light on the handset to blink. The restart syntax causes the phone to perform a warm reboot and reload its configuration file from the TFTP server. Example 5-2 illustrates what the IP phone looks like after making this assignment.

You can assign multiple lines to a phone by entering multiple button commands, as shown in Example 5-10, or putting multiple entries on the same line, as shown in Example 5-11.

## Example 5-10 Assigning Buttons Using Multiple Commands

| CME_Voice(config)# ephone 1 |
| :--- |
| CME_Voice(config-ephone)# button 1:2 |
| CME_Voice(config-ephone)# button 2:1 |

## Example 5-11 Assigning Buttons Using One Command

```
CME_Voice(config)# ephone 1

```

The show ephone command is also used to verify button assignments, as shown in Example 5-12.

## Example 5-12 Verifying Button Assignments using the show ephone command

```
CME_Voice show ephone
ephone 1: Mac:0014.62A.C2DA TCP socket:[5] activeLine:0 REGISTERED in SCCP ver 8
mediaActive:offhook:0 ringing:0 reset_sent:0 debug:0 caps:7
IP:172.30.60.32 14179 7912 keepalive 2701 max_line 2 dual-line

```

Notice the two lines of this show output. You are now able to verify the ephone-dns assigned to the ephone. As an added benefit, the output displays the actual extension as well. Notice the first button shows CH1 and CH2 as IDLE, whereas the second button just shows CH1 as IDLE. This is because ephone-dn 2 was configured with the dual-line syntax, which enables two active channels.

Let's wrap this initial ephone/ephone-dn discussion with a final configuration example. In this example, a company wants to create five DNs for its three IP phones:

- IP phone 1 (normal employee)
  - Line 1: Directory number 1010
  - Line 2: Directory number 1015
- IP phone 2 (normal employee)
  - Line 1: Directory number 1011
  - Line 2: Directory number 1015
- IP phone 3 (receptionist)
  - Line 1: Directory number 1012
  - Line 2: Directory number 1013
  - Line 3: Directory number 1015

The company wants the employees to share directory number 1015 so any of them can answer calls. The configuration in Example 5-13 accomplishes this.

## Example 5-13 Multiple ephone-dn

```
CME_Voice(config)# ephone-dn dual-line
CME_Voice(config-ephone)# number 1010
CME_Voice(config)# ephone-dn dual-line
CME_Voice(config-ephone)# number 1011
CME_Voice(config)# ephone-dn dual-line
CME_Voice(config-ephone)# number 1012
CME_Voice(config)# ephone-dn dual-line
CME_Voice(config-ephone)# number 1013
CME_Voice(config)# ephone-dn dual-line
CME_Voice(config-ephone)# number 1015
CME_Voice(config)# ephone 5
CME_Voice(config-ephone)# mac-address 0a0.932a.b34c
CME_Voice(config-ephone)# button 1:10 2:15
CME_Voice(config-ephone)# exit
CME_Voice(config)# ephone 6
CME_Voice(config-ephone)# mac-address 0a0.aa25.431b
CME_Voice(config-ephone)# button 1:11 2:15
CME_Voice(config-ephone)# exit
CME_Voice(config)# ephone 7
CME_Voice(config-ephone)# mac-address 0a0.a819.90a1
CME_Voice(config-ephone)# button 1:12
CME_Voice(config-ephone)# button 2:13
CME_Voice(config-ephone)# button 3:15
CME_Voice(config-ephone)# exit
```

**Note:** The receptionist phone also can be entered using the command 1:12 2:13 3:15. Example 5-13 shows them on separate lines to make it a little easier to understand.

## Adding Directory Numbers, Phones, and Users with CCP

For the not-so-command-line-at-heart, Cisco provides the Cisco Configuration Professional (CCP) GUI to configure ephones and ephone-dns using a point-and-click interface. Because the CCP keeps everything in order and formal, simply adding ephone-dns (called "Extensions" in CCP) and ephones (called "Phones" in CCP) is not possible. If you try to do it, CCP displays the error message shown in Figure 5-3.

The Telephony Service configuration is essentially the same configuration from the Base CME commands shown in Example 5-4. To access the Telephony Service configuration in CCP, access Configure > Unified Communications > Telephony Settings. CCP then provides a window to configure the max-phones, max-dn, and ip source address commands (see Figure 5-4). The IOS CLI preview confirms this.
