

**关键点：** 链路路由元素的配置顺序为：设备（Devices）、路由组（Route Groups）、路由列表（Route Lists）、路由模式（Route Patterns）。话流则是相反的：拨号数字匹配一个路由模式，模式指向一个路由列表，路由列表指向一个路由组，路由组引用设备。

# 呼叫路由行为

数字分析是 CUCM 将拨号数字匹配到呼叫路由可能目标的过程。不同的协议和设备以不同的方式进行数字分析：使用键键标记语言（KPML）的 SCCP 和 SIP 电话逐位分析拨号；而基础 SIP 电话、中继和大多数网关则采用整块分析（一次性处理一组数字）。

# 数字分析

CUCM 用来选择呼叫路由请求目标的数字分析逻辑是基于“最接近匹配”（closest match）。考虑以下组路由模式：

- 1111
- 1211
- 1[23]XX
- 131
- 13[0-4]X
- 13!

记住这些路由模式（这些模式并非真实的；它们仅用于说明模式匹配逻辑），让我们来看看 CUCM 如何处理三种不同拨号字符串的示例：

示例 1：如果用户 A 拨打 1111，则与模式“1111”精确匹配。没有其他模式匹配，呼叫将扩展到该目标。

示例 2：如果用户 B 拨打 1211，CUCM 有两个可能的匹配项：

- 1211：匹配 1 位数字字符串。
- 1[23]XX：匹配 200 位数字字符串。
CUCM 选择最接近的匹配目标（匹配可能字符串最少的那个）（在此情况下，为 1211）。

示例 3：如果用户 C 拨打 131，CUCM 有四个可能的匹配项：

- 1[23]XX：匹配 200 位数字字符串。
- 131：匹配 1 位数字字符串。
- 13[0-4]X：匹配 50 位数字字符串。
- 13!：匹配几乎 10000 亿亿数字字符串。（对于我们的目的而言，这实际上是无限的数字。）

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_312_0.png)

模式 13 精确匹配，但其他模式也匹配：其他模式更长，因此 CUCM 必须等待用户 C 是否还会拨打另一个数字。如果她拨打了，13 不再匹配并作为可能目标被丢弃。等待时间由 T.302 逐数字超时（InterDigit Timeout）值设置，默认为 15 秒。如果用户 C 拨打了第四位数字，T.302 定器将重新开始，因为仍然有一个更长的模式可能匹配（“13”）。如果用户 C 在拨打 4 位数字后停止，在 15 秒后（T.302 定器超时），呼叫将扩展到“13-04X”模式的目标。如果她在用户数字计数内拨打了另一个数字，则“13-04X”模式被丢弃，因为不再匹配。当用户 C 完成拨号时，T.302 定器必须耗尽，呼叫才会路由。

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_313_0.png)

**核心概念：** 逐位分析意味着 CUCM 在数字拨号时逐一个收集数字。随着数字的收集，不再匹配字符串的模式将作为可能性的路由目标被丢弃。

“最接近匹配”将根据以下标准选择模式目标：

- 模式匹配拨号字符串。
- 在所有潜在匹配项中，除实际拨号字符串外，它匹配的字符串最少。

# 振叫组 (Hunt Groups)

振叫组是 IP 电话（技术上，是电话上的目录号码 [DN]），可以通过拨打一个公共号码接通。经典的例子是帮助台；用户拨打 7777，帮助台人员的所有 DN 就会按顺序响铃，直到其中一人接听电话。

振叫组的组成部分是：

- **振叫列表（Hunt Lists）：** 包含按顺序响铃的 DN。线路组（Line groups）允许选择呼叫分配算法：自上向下、循环、最长空闲或广播。设置允许控制何时或是否继续进入振叫列表中的下一个线路组。
- **振叫列表（Hunt Lists）：** 包含自上向下排序的线路组列表。每个新电话都路由到列表中的第一个振叫组；如果该组无法提供呼叫覆盖，则尝试振叫列表中的下一个线路组，直到列表耗尽。
- **振叫试点（Hunt Pilot）：** 这是一个呼叫路由项（类似于路由模式），匹配拨号字符串并指向振叫列表（继而指向线路组）。振叫试点号码可以是网内的、E.164 或所需的任何格式。

# 控制类 (Class of Control)

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_313_1.png)

控制类定义为对设备应用呼叫限制的能力。典型的示例包括以下：

- 防止某些个人拨打长途电话
- 在一天的不同时间将同一号码路由到不同的目标
- 在不同位置将同一号码路由到不同的目标

控制类使用分区（Partitions）和呼叫搜索空间（Calling Search Spaces）配置（在后续章节中讨论）。

## 分区 (Partition)

分区是具有相似可达性特性的对象的分组。通常，你可以认为分区被分配给你可以拨打的实体，例如：

- DN
- 路由模式
- 翻译模式
- 语音信箱端口
- 会议模式

默认情况下存在一个分区，即空分区（Null Partition），尽管它在 CUCM 网页上列显示为 <none>。可以一次创建最多 75 个额外的分区。

## 呼叫搜索空间 (Calling Search Space, CSS)

呼叫搜索空间是自上向下排序的分区列表。呼叫搜索空间可以应用于设备（如 iPhone 或网关），也可以应用于 IP 电话上的线路。默认存在一个 CSS，且默认情况下它只包含空分区。你可以将 CSS 视为分配给可以拨打呼叫的实体。

## 分区与呼叫搜索空间的交互

要理解的本质点是：如果拨打的目标不在呼叫方 CSS 的某个分区中，则呼叫将失败。这种行为允许我们设计特定的呼叫权限方案，并将其应用到不同的呼叫设备或线路。考虑以下示例：一家公司想要实施呼叫限制，使大堂的电话无法拨打长途电话。创建一个新分区“PSTN. Local. PTN”。匹配 7 位和 10 位（免付费）PSTN 的路由模式被分配给 PSTN_Local PTN 分区。

创建一个新的 CSS 为 Lobby CSS。将 PSTN_Local PTN 分区添加到 Lobby_CSS 中。

将 Lobby CSS 应用于电话配置。一旦进行了该更改，当大堂的电话尝试拨打任何不匹配 Lobby_CSS 中 7 位或 10 位模式的数字时，它们将收到铃声。因此，没有人能通过拨打长途电话来滥用大堂电话并产生费用。

几点相关内容：

- 如果用户尝试从大堂电话拨打 911，那也将失败，除非紧急电话模式也添加到 PSTN_Local PTN 分区或间接添加到 Lobby_CSS 的其他分区中。确保每部电话都能拨打紧急电话通常是一个好主意。
- 当路由模式从默认分区 <none> 移动出来时，它将不再能被默认 CSS 访问。这意味着在完成新的、有效的 CSS/分区结构之前，匹配该路由模式的呼叫将失败。因此，最好在电话投入之前计划并实现服务类（CoS）配置，以避免服务中断。
- 每个 CSS 都包含默认分区 <none>，位于自定义分区列表的末尾。这意味着任何留在默认分区 <none> 中的内容都可被每个呼叫设备访问。

# 线路-设备配置 (Line-Device Configuration)

到目前为止，我们假设 CSS 仅应用于设备（即 IP 电话）。也可以将 CSS 应用于电话上的线路；线路 CSS 可能非常不同，并包含其他分区，这些分区又包含不同的路由模式，依此类推。

如果同时应用了设备 CSS 和线路 CSS，两个 CSS 中的分区将按自上向下的顺序串联，其中线路 CSS 分区列在前面，设备 CSS 分区

CUCM 将按照该顺序分析分区列表，在列表中的模式中寻找拨号数字的匹配项。如果找到了匹配项，则呼叫将路由到目标。如果发现了多个相同的匹配项，则串联列表中位于前面的匹配项所在分区将成为目标。换句话说，线路 CSS 覆盖了设备 CSS。

使用线路/设备方法有几个益处。通常，最佳实践建议设置设备 CSS 以允许对模式的完全呼叫权限，并根据设备的位置设置相应的呼叫路由（例如通过本地网关拨打 PSTN）。然后使用线路 CSS 应用呼叫限制，该 CSS 可以包含匹配长途号码的路由模式，但配置为阻止这些呼叫。结果是需要配置的 CSS 总数更少，这使得号计划的管理和扩展变得简单。
