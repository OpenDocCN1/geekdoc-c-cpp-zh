## Configuring Intercom Features

As previously discussed, the Intercom feature uses special Intercom DNs, Partitions, and Calling Search Spaces. The following steps walk through setting up the Intercom feature:

- 1. Navigate to Call Routing > Intercom Route Partition.
2. Click Add New. In the Configuration Page, enter the name and comma-separated description of the new Intercom Partition. You can create up to 75 Partitions at once on this page.
3. Click Save.
4. Navigate to Call Routing > Intercom > Intercom Calling Search Space. Click Find, and note that an Intercom CSS will be automatically created as a result of creating the Intercom Partition (the auto-named entry will be <partition_name>_GEN). The auto-generated CSS automatically includes the Intercom Partition just created. You may use the auto-generated CSS to modify it, or create custom Intercom CSSs as desired.

Note: A custom Intercom CSS is really only necessary if an Intercom button needs to support multiple (dialed instead of dialed) targets, and access to some of those targets must be limited. If you are creating point-to-point Intercom lines, there is no need to customize the Intercom CSS.

- 1. Navigate to Call Routing > Intercom > Intercom Directory Number.

## Configuring Presence-Enabled Call Lists

As described earlier, the CUCM system can track the on-hook status of phones both through BLF Dials and Presence-Enabled Call Lists. Presence-Enabled Call Lists use the device's configured Subscribe CSS and Presence Groups to determine whether a device can watch Presence status:

- If the Subscribe applied does not include the Partition of the DN being watched, Presence status is unavailable.
- If the Inter-Presence Group subscription is denied between the groups, Presence status is unavailable.
- If both the Subscribe CSS and Presence Groups are used together, both must allow the subscription in order for Presence status to be.

Configuring Presence-Enabled Call Lists is somewhat more complex than BLF Dials, but it allows greater flexibility, precision, and scalability when large numbers of devices need to watch large numbers of DNs. To configure Presence-Enabled Call Lists, follow these steps:

- 1. Navigate to System > Enterprise Parameters. Scroll down to Enterprise Parameters Configuration.
- 2. Set Enable BLF for Call Lists to Enabled.

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_346_0.png)

- 3. If using a custom Subscribe CSS is desired, create new Subscribe CSSs. It is generally recommended to create custom Subscribe CSSs and use existing Partitions, the overall Class of Control plan should be thought thought prior to making these changes.
- 4. Apply the appropriate CSS to phones and SIP trunks as required.

## Configuring Custom Presence Groups

Because all devices and DNs are part of the Standard Presence Group by default and all devices can watch DNS within the same Presence Group, the configured Subscribe CSS and existing Partitions provide adequate control over Presence subscriptions. If a more complex design is required, it may be necessary to set up custom Presence Groups and define custom inter-Presence Group subscriptions, as follows:

- 1. Navigate to System > Presence Group.
- 2. Click Add New and configure a name.
- 3. Set the Presence Group Relationship to each other Presence Group (Allow Subscription or Disallow Subscription) to control whether or not this group can watch the Presence status of other groups.
