# Notification Devices

Message notification should not be confused with MWI; notification refers to CUC making a phone call or sending an email to a user that he has a new message. CUC supports notification on a Pager, Work Phone, Home Phone, and Mobile Phone and via SMTP by default. Additional notification devices may be added.

For each device, the following as needed:

- Enable: Check this box to allow CUC to send notifications to this device.
- Display Name: Modifies the name as needed.
- Delay Before First Notification Event: Sets the number of minutes CUC waits for a new message is left before it sends a notification using this device.
- Notify Repeat Interval: How frequently CUC resends the notification.
- Notify Me Of: Select the checkboxes to allow CUC notifications for All Messages, Voice Messages, Fax Messages, Calendar Appointments, Calendar Meetings, and for each type, to send for Urgent Only.

- Pager/Phone Settings: Sets the Phone Number CUC should call. Modify the extra settings to edit digits, wait times, and so on to ensure the call completes correctly. All these settings should be applied to the individual user account rather than at the template.

# Importing Users from CUCM

If the CUCM server already has a fully populated user database, those entries may be easily imported and synchronized in the CUC database. To enable this capability, perform the following actions on the CUC and CUCM server:

1. From the Cisco Unified Serviceability interface, use the Tools menu, select Service Activation.
2. Select the Cisco AXL Web Service and click Save.
3. In Cisco Unity Connection Administration, navigate to Telephony Integrations > Phone System.
4. Click the name of the CUCM server from which you want to import users.
5. Under the Edit menu, click Cisco Unified Communications Manager AXL Servers.
6. In the Edit AXL Servers page, under AXL Settings enter the User Name and Password of the account that CUC will use to login to the CUCM AXL server.
7. Click Save.
8. In the AXL Servers section, click Add New.
9. Enter the IP Address and Port of the CUCM server. (CUCM 8.x supports SSL, so use port 8443 or 443).
10. Click the Test button. Test message successfully sent to AXL server `<ip_address:Port>` appears in the Status section.
11. Click Save to complete the integration.

Figure 13-14 shows the AXL Servers setup page with a successful test message.

Now that AXL is working properly, we can use it to import users, as outlined in the following steps:

1. On the CUC server, from the Cisco Unity Connection Administration interface, navigate to Users > Import Users.
2. Select the CUCM server from the Find End Users in drop-down. Filter the search if needed.
3. Choose the appropriate User Template from the Based on Template drop-down.
4. Click Find.
5. Select the user(s) to import from the list, and then click Import Selected.

# Importing Users from LDAP

LDAP is a standards-based user, password, and privilege system. CUC can import users from a number of vendors' implementations of LDAP. These user accounts are held and maintained in the LDAP system. To enable synchronization, follow these steps:

1. In the Cisco Unified Serviceability interface, navigate to Tools > Services.
2. Select the DirSync service and click Save.
3. In the CUC Administration interface, navigate to System Settings > LDAP > Setup.
4. Check the Enable Synchronizing From LDAP checkbox.
5. Choose the LDAP Server Type from the drop-down.
6. In the LDAP Attribute for User ID drop-down, select the LDAP attribute that will be mapped to the CUC Alias. The selected attribute must contain data, and the data must be unique.
7. Navigate to LDAP > Directory Configuration.
8. Enter the LDAP Configuration Name. It is recommended to use a name that identifies the users being imported, especially if multiple Search Bases are configured.
9. Enter the LDAP Manager Distinguished Name and LDAP Password: This is the LDAP account and password that CUC uses to read and import the LDAP database.
10. Enter the LDAP User Search Base: This entry defines the point where CUC will begin reading the LDAP database. Most LDAP designs are hierarchical tree structures; CUC starts the LDAP search at the point specified by the User Search Base and can read all branches of the tree. It cannot move up the tree from that point, nor can it cross to other branches. CUC can only integrate with a single LDAP database.

11. In the LDAP Directory Synchronization schedule, choose to Perform Once if you do not want to have CUC perform a regular sync. Refresh update current user information; it will not import any new users created since the agreement was synchronized. A new User Import must be performed to create these users in CUC.
12. To have CUC synchronize on a regular scheduled basis, set the Perform a Re-sync Every as desired.
13. To configure the mappings between LDAP attributes and CUC user database attributes, set the desired values in the User Fields to Be Synchronized section. Different fields will be changeable, with different field names listed depending on the LDAP type/vendor selected.
