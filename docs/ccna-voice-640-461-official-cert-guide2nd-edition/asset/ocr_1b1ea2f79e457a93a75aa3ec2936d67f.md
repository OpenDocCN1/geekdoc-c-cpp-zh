**Figure 6-11** Matching Inbound Dial Peers Using Dial Peer 0

The result is that you could not place calls to x1101 from ROUTER_B (or the PBX system attached to ROUTER_B). However, what if x1101 called x2510? The CME_A and ROUTER_B routers have enough information to match the outbound legs.
UTER_B is missing the information for the inbound dial peer (call leg 3). Here's how the decision process would follow:

+   1. (NO MATCH) 2510 (the dialed number) does not match an **incoming call-number** dial peer configuration on ROUTER_B, because this command does not exist in the configuration.

+   2. (NO MATCH) x1101 caller ID information (ANI) does not match an **answer-address** dial peer configuration on ROUTER_B, because this command does not exist in the configuration.

+   3. (NO MATCH) x1101 caller ID information (ANI) does not match the **destination-pattern** dial peer configuration, because the VoIP dial peer 1101 was moved to ROUTER_B.

+   4. (NO MATCH) x1101 did not come in a POTS interface (FXS, FXO, E&M, BRI/T1/E1 digital interface) that could be matched using the port command; rather, x1101 called a VoIP connection.

+   5. (MATCH) Because ROUTER_B could not find a match using the previous methods, it uses dial peer 0.

So, now begs the question, "What is dial peer 0?" Dial peer 0 is like a default gateway dial peer that appears when there is no dial match (this applies only for inbound dial peers, not for outbound dial peers). This allows the call to complete, you have no control over dial peer 0. It does not change any of its default settings.
