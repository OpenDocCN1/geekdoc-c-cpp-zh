
The paging configuration in Example 7-10 demonstrates the configuration of a multiple-group paging system. Ephones 1 and 2 continue to use ephone-dn 80 as their dedicated paging group. Ephones 3 and 4 use ephone-dn 81. This time, a third paging group enables you to page-multiple paging groups at once. This gives an organization the flexibility to page specific departments or the company as a whole.

## Example 7-10 Configuring Multiple-Group Paging

```
CME_Voice(config)# ephone-dn 80
CME_Voice(config-ephone-dn)# number 5555
CME_Voice(config-ephone-dn)# paging
CME_Voice(config-ephone-dn)# exit
CME_Voice(config)# ephone-dn 81
CME_Voice(config-ephone-dn)# number 5556
CME_Voice(config-ephone-dn)# paging
CME_Voice(config-ephone-dn)# exit
CME_Voice(config)# ephone-dn 82
CME_Voice(config-ephone-dn)# paging group 80,81
CME_Voice(config-ephone-dn)# exit
CME_Voice(config)# ephone 1
CME_Voice(config-ephone)# paging-dn 80
CME_Voice(config-ephone)# exit
CME_Voice(config)# ephone 2
CME_Voice(config-ephone)# paging-dn 80
CME_Voice(config-ephone)# exit
CME_Voice(config)# ephone 3
CME_Voice(config-ephone)# paging-dn 81
CME_Voice(config-ephone)# exit
CME_Voice(config)# ephone 4
CME_Voice(config-ephone)# paging-dn 81
```

With the configuration in Example 7-10, a call to DN 5555 pages ephones 1 and 2, a call to DN 5556 pages ephones 3 and 4, and a call to DN 5557 pages all ephones. You do not need to assign any ephones to paging-dn 82, because this ephone-dn represents a group of both paging-dns 80 and 81.

**Note:** CME allows you to list up to ten paging numbers using the paging group command.

## Configuring After-Hours Call Blocking

In the traditional telephony realm, there have been many recorded incidents of unauthorized calls being placed after-hours, when most, if not all, staff has left for the evening. To prevent this, you can implement after-hours call blocking on CME.

After-hours call blocking allows you to define ranges of times specified as after-hours intervals. You can then list number patterns that are disallowed during those intervals. If a user places a call during the after-hours time range that matches one of the defined patterns, CME will play a reorder tone and disconnect the call.

Of course, there are exceptions to every rule. You may want to have some phones completely exempt from the policy, or give users a "back door" around the restrictions if they are working late and need to make business-related calls that CME would typically restrict. After-hours call blocking configuration on CME provides for both of these scenarios. You have the option to completely exempt certain IP phones from the after-hours restrictions or provide users with a PIN they can enter into the IP phone. If they enter the PIN correctly, CME exempts the IP phone from the after-hours policy for a configurable amount of time.

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_229_0.png)

Figure 7-19 Configuring Multiple-Group Paging in CCP

Note: There are some patterns that may be beneficial to block all the time. For example, 1-900 numbers in the United States often represent high-cost, less-than-reputable businesses that are typically banned by all corporate environments. CME also allows you to create a 24/7, non-exemplary pattern that is disallowed at all times, using the after-hours call system.

After-hours call blocking has three major steps of configuration:

- Step 1. Define days and/or hours of the day that your company considers off-hours.
- Step 2. Specify patterns that you want to block during the times specified in Step 1.
- Step 3. Create exemptions to the policy, if needed.

You will perform most of the configuration for the after-hours call blocking restrictions from telephony service configuration mode. Example 7-11 demonstrates the after-hours time intervals.

## Example 7-11 Configuring After-Hours Time Ranges and Dates

```
CME_Voice(config)# telephony-service
CME_Voice(config-telephony)# after-hours
block define after-hours block pattern
date define month and day
day define day in week
CME_Voice(config-telephony)# after-hours day ?nDAY day of week (Mon, Tue, Wed, etc)
CME_Voice(config-telephony)# after-hours day ?nhh:mm Time to start (hh:mm)
CME_Voice(config-telephony)# after-hours day mon 17:00 ?
hh:mm Time to start (hh:mm)
CME_Voice(config-telephony)# after-hours day mon 17:00 8:00
CME_Voice(config-telephony)# after-hours day tue 17:00 8:00
CME_Voice(config-telephony)# after-hours day wed 17:00 8:00
CME_Voice(config-telephony)# after-hours day thu 17:00 8:00
CME_Voice(config-telephony)# after-hours day fri 17:00 8:00
CME_Voice(config-telephony)# after-hours date ?nMONTH Month (Jan, Feb, Mar, etc)
CME_Voice(config-telephony)# after-hours date dec ?
<1-31> day of month in date
CME_Voice(config-telephony)# after-hours date dec 25 25 ?nhh:mm Time to start (hh:mm)
CME_Voice(config-telephony)# after-hours date dec 25 00:00 ?nhh:mm Time to start (hh:mm)
CME_Voice(config-telephony)# after-hours date dec 25 00:00 00:00
CME_Voice(config-telephony)# after-hours date jan 1 00:00 00:00
```

The configuration in Example 7-11 defines weekdays, from 5:00 p.m. to 8:00 a.m. the next day, as after-hours, with the entire day dec 25 (Christmas) and January 1 (New Year's Day).

In the next step of the after-hours configuration, you define the patterns that CME blocks during the after hours you have configured (see Example 7-12).

> Note: Chapters 8 and 9 discuss the patterns you can use for matching fully. For now, examples in this chapter use the *, wildcard, which matches any digit dialed, and the "T" wildcard, which matches any number of digits.

## Example 7-12 Configuring After-Hours Block Patterns

```
CME_Voice(config)# telephony-service
CME_Voice(config-telephony)# after-hours block ?npattern block pattern
CME_Voice(config-telephony)# after-hours block pattern ?n<1-32> index of patterns
CME_Voice(config-telephony)# after-hours block pattern 1 ?nWORD digits string for after hour pattern
CME_Voice(config-telephony)# after-hours block pattern 1 91...
CME_Voice(config-telephony)# after-hours block pattern 2 98...
CME_Voice(config-telephony)# after-hours block pattern 3 9100...
```

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_230_0.png)

You might have noticed on the context-sensitive help in Example 7-12 that the CME router allows you to configure up 32 indexes of block patterns. The initial block pattern 1 matches and blocks long distance numbers; block pattern 2 matches international numbers; block pattern 3 matches 900 calls. Notice that block pattern 3 is followed by the 24 keyword. This additional syntax tells the CME router to block calls at all times. If you enter block patterns with this keyword, exempted after-hours numbers are not.

**Note:** If you need more flexibility than after-hours blocking, you can also use Class of Restriction (COR) features with CME.

The final step in the configuration of after-hours blocking is to allow any necessary exemptions to the policy, as shown in Example 7-13. You can add exemptions on a per-IP phone basis or by using one or more PIN numbers to allow on-demand access to block patterns (with the exception of patterns defined with the 7-24 keyword) from any IP phone. Example 7-13 configures phone 1 to be exempt from the after-hours blocking policy. Phones 2 and 3 are configured with PIN numbers.

## Example 7-13 Configuring After-Hours Exemptions

```
CME_Voice(config)# phone 1
CME_Voice(config-phone)# after-hours exempt
CME_Voice(config-phone)# exit
CME_Voice(config)# phone 2
CME_Voice(config-phone)# pin 7
  WORD A sequence of digits representing personal identification
CME_Voice(config-phone)# phone 1234
CME_Voice(config-phone)# exit
CME_Voice(config)# phone 3
CME_Voice(config-phone)# pin 4321
CME_Voice(config-phone)# exit
CME_Voice(config-phone)# telephony-service
CME_Voice(config-telephony)# login timeout 120 clear 23:00
```
