## 5-4 Telephony Service Configuration from CCP

> Tip: CCP might not refresh the CME configuration after making a change (such as configuring the base telephony service features). If you configure the telephony service as shown in Figure 5-4 and still receive the message stating that the telephony service must be set up (before configuring extensions or phones), refresh the CME configuration in CCP by clicking the Refresh button at the top of the utility.

Now, we can return to the Extension configuration (Configure -> Unified Communications -> Users, Phones and Extensions > Extensions). CCP does not immediately connect the extensions (phone-dn) and phones (phones); you can configure them in whatever order you feel most comfortable. For now, we start with the extensions: At the bottom of the CCP Extensions window is a button labeled Create. Clicking this causes the Create Extension dialog box to appear, as shown in Figure 5-5.

This window provides the same capabilities that we had added the phone-dn from a command-line interface (CLI) without knowing a lick of command-line syntax. Upon clicking the OK button, the CCP IOS CLI Preview displays the following:

- phone-dn 1 dual-line
- number 1050 secondary 14805551050
- label Jeremy Ciara
- description Primary line
- exit

As you add the extensions to CCP, they are stored on the CME running-configuration (don't forget to save when you're done!) and appear as valid extensions in CCP (see Figure 5-6).

Now, we can move on to adding the phones. Clicking the Phones CCP configuration (Configure > Unified Communications > Users, Phones and Extensions > Phones) reveals a window almost identical to the Extensions window. Clicking the Add button pops up a simple interface asking for two keys: model of Cisco IP Phone you want to add and the associated MAC address (shown in Figure 5-7).

After you click the OK button, the CCP CLI Preview displays the following syntax:

```
ephone 1
mac-address 0014.1C48.E71A
type 7960
auto-line
exit
```

You can repeat this operation for as many phones as you want to.

**Tip:** On the right pane of the CCP interface is a bulk import wizard. This exists both for the extensions and phones. If you format all the required data in a Comma Separated Value (CSV) file, you can perform a bulk import of both extensions and phones into the system (which takes much less time than adding them individually for a large group of devices).

Now that we add extensions and phones to the system, we can move into the final piece of the configuration: adding users. Unlike the pure command-line configuration of CME, which links ephone-dns to phones, CCP ties the extensions and phones through a user account. By creating a user account, the end user can have the ability to manage his her phones through a web interface. For now, let's get the phones working.

To add a user in CCP, navigate to Configure > Unified Communications > Users, Phones and Extensions > User Settings. After you are there, you can create a new user, as shown in Figure 5-8. The only required field is the User ID, which represents the username the user uses when logging on to the system. You can configure these additional fields:

- First Name
- Last Name
- Display Name (used for Caller ID)
- Password (used to log on to the system)
- PIN (used for features like Extension Mobility)

This simple configuration window also contains the information CME uses to build a directory of users. After you add these users to CME, the users of the VoIP system will be able to press the directories button on their IP phone, navigate to Local Directory, and search the database of users contained in CME.

![](img/e4ad7862dc47b4e5de0cde3b4550ad65_128_0.png)

Figure 5-7 Adding a Phone using CCP

After you enter the user information, you can click the Phones/Extensions tab at the top of the Create User window to associate the phone, extensions, and user account. Notice how CCP organizes this window in Figure 5-9. You first select the phone by referencing its MAC address. Based on the model you chose when originally configured the phone, CCP displays an image of the phone (definitely a nice touch by Cisco). Beneath the phone drop-down box, you can then choose which line you want to configure (because this is a Cisco 7960 IP Phone, you can configure up to six lines), the type of line (you most often choose a Regular line), and its ring type (normal ring, silent ring, beep, ring beep, and so on). Near the bottom of the window, CCP displays the extensions you previously configured. In the case of Figure 5-9, I assigned extension 1050 to the ButtercupC user.

After we click the OK button in CCP to submit the configuration, it displays the following-syntax:

- 1
username ButtercupC password asdasdf
pin 12345
button 1:1
restart
exit
ephone-dn 1
name Buttercup Ciara
exit

If you have not already connected the IP phone to the network, doing so now causes it to appear as a completely configured device.

Because nearly any verification and troubleshooting is typically a command-line realm, CCP provides a template of show commands you are able to perform using a drop-down box. In addition, CCP enables you to use the drop-down box as a "free form" field where you are able to type any custom show command you want. To access this area in CCP, navigate to Configure > IOS Show Commands. The view section is apart from the normal configuration categories under the Utilities section of CCP. Figure 5-10 shows the output from the show phone register command, which you can use to validate that the phone has registered with CME.
