# Manual Configuration of IP Phones

The basic steps for manually adding an IP Phone are as follows:

- 1. Navigate to Device > Phone, and then click New.
- 2. Choose the IP Phone Model from the drop-down list.
- 3. Choose the device protocol (either SCCP or SIP); some phones will support only one protocol, and this step will be skipped.
- 4. Select, or enter, the required specific information for the phone. The four required fields that do not have default values (must be manually configured) include the following:
    * MAC Address: The MAC address is the unique identifier that links the IP Phone hardware to the software configuration in CUCM. If you are building a phone for Bob, you must obtain the MAC address of the phone that will end up on Bob's desk, or Bob will not get the correct settings, DN, and so forth.
    * Device Pool: The Device Pool (as described earlier in this chapter) applies many common settings to the phone that are relevant to its physical location and desired behavior.
    * Phone Button Template: The Phone Button Template (also detailed earlier in this chapter) defines what functions are assigned to the buttons on the phone (DNs, Speed Dials, Services, and so on).
    * Device Security Profile: Applies a set of security-related configurations, described previously in this chapter.
- 5. Click Save.

When the page reloads, a new pane labeled Association Information appears on the left, in which you can configure the phone buttons. The functionality (Line, Speed Dial, Intercom, Service, and so on) is defined by the Phone Button Template specified previously; here is where you specify what the DN number on the line(s) will be, what Service is accessed, or which Intercom DN is dialed. In the Association Information pane, continue the basic phone configuration steps, as follows:

- Click Line [1] - Add New DN. The Directory Number Information page opens, in which you must enter a Directory Name, and optionally select the Partition and other optional configurations. The following points highlight a few of the settings found on the Directory Number Configuration page:
    - **Route Partition:** As discussed in Chapter 10, “Understanding CUCM Dial-Plan Elements and Interactions,” the Partition is the part of the calling privileges system or of Control.
    - **Alerting Name:** This is the name to display on the caller's phone when phone is ringing. Some PSTN connections might not support this functionality.
    - **Call Forward and Call Pickup Settings:** This is where the administrator can determine how to forward a call if the DN is busy or not, or for Call Forward All. The user can set Call Forward All at the phone itself using the CallFWD softkey, or on their User Web Page; other Call Forward settings (such as Busy and No Answer) are available to the user only on the user’s Web Page.
    - **Display:** The text entered in the Display field serves as an internal ID. When this DN calls another IP Phone, the Display text replaces the calling DN number. - 7. Click Save.
- 8. In the Related Links drop-down, select Configure Device (<Phone>), and then click Go.
- 9. You are now at the Phone Configuration page for the new phone. At this point, if you need to continue making config changes you can do so, or you can click Save the changes so far. The page prompts to "Click on the Apply Config button to have the changes effect." This happens in order for the phone to adopt the changes, it has to reload with its new config. This requires either a Restart or a Reset, depending on what was changed.

There is a great deal of confusion about Restart, Reset, and Apply Config. The differences are explained in the following points:

- A Reset reboots the firmware and the configuration of the phone. Some information such as firmware version, local changes, SRST, or Communications Manager Groups require a full reset so that the phone will pull a new page from the TFTP server. A Reset is triggered from the Administration web page, or from the phone itself by entering Settings >## (using the keypad).
- A Restart restarts the phone, and the phone comes right back and registers again. Because Communications Manager reads the database for this device when it registers, it is a good way to refresh information that is not passed through the configuration button. But changes, names, and forwarding would only require a Restart. A Restart is faster than a Reset, because the firmware is not rebooted at all.
- The confusion between Restart and Reset was that in CUCM 8.X, a new function labeled "Apply Config" was introduced. This button intelligently triggers either a Reset or a Restart as appropriate, depending on what changes were made to the device. In all cases, the phone has to be registered for the Reset or Restart to be sent to the phone.

It is common, especially with advanced features as Extension Mobility or Cisco Unified Personal Communications, to associate a user with a particular Device (IP Phone). It is required to associate the user with the Device if you want to be able to use the User Web Pages to customize their phone. The End User is associated with the Device (IP Phone), and the Device is associated with one or more DNs. This allows the user not only to access the User Web Pages to configure this phone, but for other applications and processes to interact with the user through the phone system.

So, what happens if you delete an End User who is associated with a device that is associated with a DN? Nothing. Although the association exists and is important and useful, the three database entities of User, Device, and DN are independent of each other. The device and DN do not go away if the User is deleted, and the same result applies if the Device or DN are deleted (although a phone without a DN, or a DN without a phone, can't make calls).

# Autoreistration of IP Phones

CUCM includes the Autoreistration feature, which dynamically adds new phones to the database and allows them to register, including issuing each new phone a DN so it can place and receive calls. Autoreistration is supported by all Cisco IP Phones.

To enable Autoreistration, perform the following steps:

- 1. Verify the Autoreistration Phone Protocol. Access this setting under System > Parameters; choose either SCP (default) or SIP. Phones that do not support the chosen protocol will still register using their native protocol.
- 2. Verify that at least one CM Group has Autoreistration enabled (by selecting the checkbox for Auto-registration).
- 3. Enable and configure autoreistration on one or more CM servers within the CM Group enabled for autoreistration:
    - Enable Autoreistration by deselecting the Auto-registration Disabled on this Unified Communications Manager checkbox; it is disabled by default, so unchecking the box enables it.
    - Configure the range of DNs that will be dynamically and sequentially issued to auto-registering phones. The default Starting Directory Number is 1000; if you change the Ending Directory Number to anything higher than 1000, Autoreistration is automatically enabled. If you set the Starting and Ending DNs to the same value, Autoreistration is automatically disabled. (Autoreistration is disabled by default, because both the Starting and Ending Numbers are set to 1000.)
    - Set the Partition that will be assigned to the autoregistered DNs.
    - Verify that the Auto-registration Disabled checkbox is unchecked, and then click Save.

A simple way to test autoreistration is to plug in a new phone; if it receives a DN in the range you specified (or a DN in the range of 1000–1999 if you left it at the defaults), Autoreistration is working.

Some administrators use Autoreistration as a security weakness, because any IP phone will be dynamically added to the database and potentially begin making calls, perhaps even to the PSTN if it is not restricted. It is common to enable Autoreistration only when it is needed to prevent the occurrence of "rogue phones."
