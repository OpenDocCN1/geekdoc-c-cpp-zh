To address these challenges, the following link efficiency mechanisms have been introduced:

+   - Payload Compression: Compresses application data sent over the network so the router sends less data across the WAN link.
- Header Compression: Some traffic (such as VoIP) may have a small amount of application data (RTP audio) in each packet but sends many packets. In this case, the amount of header information becomes a significant factor and often consumes more bandwidth than the data itself. Header compression addresses this issue directly by eliminating many of the redundant fields in the header. Amazingly, RTP compression (also called Real-time Transport Protocol (-RTP)) reduces a 40-byte header down to 2-4 bytes
- Link Fragmentation and Interleaving (LFI): LFI addresses the serialization delay by chopping large packets into smaller pieces before they are sent. This allows the router to move more critical VoIP traffic between the now-fragmented pieces of the data traffic (which is called “interleaving” the voice). You can use LFI on PPP or Frame Relay connections (using FRE/T1 Annex C).

> Tip: One thing to understand: Link efficiency mechanisms are not a magic way to get more bandwidth. Each of them has their drawback: Compression adds delay, and processor load and link fragmentation increases the amount of data being sent on the line (because all the fragmented packets now need their own header information). Cisco does not recommend using these methods on links faster than T1.

# Queuing Algorithms

Queuing defines the rules the router should apply when congestion occurs. The majority of network interfaces use First-in, First-out (FIFO) queuing by default. In this method, whatever packet arrives first is sent first. Although this seems fair, not all traffic is equal. The primary goal of queuing is to ensure that the network servicing your critical or time-sensitive business applications gets sent before non-essential network traffic. Beyond FIFO queuing, there are three primary queuing algorithms used in today:

+   - Weighted Fair Queuing (WFQ): WFQ tries to balance available bandwidth among all senders (the “fair” queuing). By using this method, a high-bandwidth sender gets less priority than a low bandwidth sender. On Cisco routers, WFQ is the default method applied to serial interfaces.
- Class-Based Weighted Fair Queuing (CBWFQ): This queuing method allows you to specify guaranteed amounts of bandwidth for your various classes of traffic. For example, you could specify that web traffic gets 20 percent of the bandwidth, whereas traffic gets 50 percent of the bandwidth (you can specify values as a percent or a specific bandwidth amount). WFQ is then used for all the unspecified traffic (the remaining 30 percent, in the previous example).
- Low Latency Queuing (LLQ): LLQ is often referred to as PQ-CBWFQ because it is exactly the same thing as CBWFQ, but adds a priority queuing (PQ) component.
