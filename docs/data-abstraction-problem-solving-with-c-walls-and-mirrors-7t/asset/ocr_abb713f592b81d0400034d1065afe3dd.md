The first two methods are straightforward, but let's look more closely at getPosition. Given an entry in the sorted list, the method getPosition returns the entry's position number within the list, as you would expect. We number the entries beginning with 1, just as we do for the ADT list. But what if the given entry is not in the sorted list? In this case, getPosition returns the position number where the entry belongs in the list. The returned number is negative, however, to signal that the entry is not in the list. For example, if missingObject is not in the sorted list but would belong at position 3, getPosition(missingObject) will return -3.

The sorted list also has some, but not all, of the operations of an ADT list. We have already mentioned that adding an entry at a given position is not possible, because otherwise the client could destroy the order of the sorted list. For the same reason, the list's setEntry method is not available to a sorted list. The other operations of the ADT list, however, are useful for a sorted list as well, including the ones that retrieve or remove the entry at a given position. The methods getEntry and remove each have a position number as a parameter, but they will not alter the relative order of the entries in the sorted list.
