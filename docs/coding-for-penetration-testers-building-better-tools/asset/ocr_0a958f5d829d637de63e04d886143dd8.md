First, let's look at the vulnerable application. This application takes a search option and says what we searched for along with prepulating the search box with our last query. When we print the information we searched for, htmlspecialchars function is used to generate safe HTML. However, when populating the search box, no escape functions are used. This would be okay as long as the input doesn’t have a ” symbol in it. However, once we place a quotation symbol in the search box, the HTML output will now have the value corrupted within the tag.

Fig. 9.14 shows the output of search.php when the query ‘test”xss’ is submitted.

We can see in Fig. 9.14 that the quote and greater-than sign have closed out the INPUT tag in the source and the xss phrase is displayed to the screen. We can take advantage of this vulnerability with our scripts. When we convert our input into a valid HTML script, we introduce our own functionality to the Web page. In Fig. 9.15, we have sent the query "><script>alert('xss')</script>’ and have gotten a pop-up box verifying that we can run scripts successfully.
