# Introduction

Websites contain some of the world’s most critical data. From credit card numbers to health records, web security is one of the biggest areas for penetration testing today. In order to maximize the quality of a web-based penetration test, some scripting ability is almost always required. Whether it's to catch the data from a XSS vulnerability or to add functionality to a website, scripting is a critical piece of a penetration tester's toolkit.

When a vulnerability assessment detects a remote file inclusion vulnerability in a Web page, or when exploits are chained on a remote server, a penetration tester can interact with the operating system through the Web server software. Being able to execute shell commands, manipulate file systems, communicate with databases, and communicate over sockets can be useful in leveraging a compromised Web server during a penetration test. With this in mind, this chapter focuses on web-based penetration testing. After discussing PHP code manipulation basics, the chapter delves into subjects that are crucial to a successful penetration test: saving data collected through PHP scripts, pulling data from other sources, and using the server running the PHP to help further access to the network. To tie everything together, the chapter concludes with details on how to build a basic PHP shell.

In many organizations, web application penetration testing is seen as a specialized skillset, leading to two diverging types of penetration tests: network-based penetration tests and Web-based penetration tests. Although languages such as Python and Ruby have heavily leveraged network protocols, and binary manipulation, this chapter will focus on the Web application side of penetration testing.

# Where Web scripting Is Useful

Web scripting provides us two advantages: the ability to manipulate Web pages to change the functionality of the page, and to aid in data exfiltration. Whether we have found a Web page to have a remote file inclusion vulnerability, or when we are chaining exploits to have our code run on a remote server, additional scripting frequently gives us the ability to interact with the operating system by using the Web server software. Being able to execute shell commands, manipulate file systems, communicate with databases, and, in some cases, communicate over sockets, can help us further compromises and perform postexploitation tasks during a penetration test.

While performing tests, we may also need to engage in some level of credential theft or social engineering. PHP and JavaScript frequently work together in this situation where we inject JavaScript code into a Web page to gather information and send it back to our receiving server. In this case, our PHP will parse that information and log it for future use. We will look at this type of example in Chapter 9, Exploitation scripting.

# Getting Started With PHP

PHP stands for PHP: Hypertext Processor and is an open source scripting language designed primarily for Web development. PHP pages are typically HyperText Markup Language (HTML) pages with PHP code interspersed in order to merge the functionality of the website with the HTML code. Frequent uses for PHP include database applications and applications which are handling as PHP form-based parsing and the data manipulations which are part of form-based applications. PHP is also used as the framework for many Web 2.0 applications to handle databases easily and respond through common Web 2.0 protocols such as Extensible Markup Language (XML) and JavaScript Object Notation (JSON).

PHP is rich and full-featured, with capabilities ranging from databases, to sockets, and file system manipulations.
