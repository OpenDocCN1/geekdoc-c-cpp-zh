# Warning

By default, many versions of Netcat for Windows are compiled with the -e option enabled, allowing us to use Netcat to run an executable file on the system and connect it to the network through Netcat's facilities. Many antivirus tools on Windows will be upset by this and will flag Netcat as malware. If this is an issue, we can reclaim Netcat without this option, or download a compiled version without the -e option present at http://www.rodneybeede.com/Compile_Netcat_on_Windows_using_MinGW.html.

# Netcat variants

As we mentioned earlier, Netcat is an open source tool. This leaves open to the tinkering of the masses of programmers and would-be programmers who might feel inclined to retool it in order to add features, make changes, and so on. A large number of Netcat derivatives are floating about the Internet, let's take a look at a few of them quickly to see what the differences are. Some of the more interesting variations are Socat, CryptCat, and Ncat, but this is by no means an exhaustive list.

Socat¹ is an implementation of Netcat that provides several very interesting features. One of the more useful bits is that Socat can use a number of channels to send and receive data, including TCP/IP, serial lines, files, pipes, and so on. This allows us to considerably extend the number of uses to which we can put Socat. Socat also has a large set of other features that extend the capabilities of Netcat, and more information can be found at http://www.destreach.org/socat/doc/README. Socat is available for both UNIX-like and Microsoft platforms.
