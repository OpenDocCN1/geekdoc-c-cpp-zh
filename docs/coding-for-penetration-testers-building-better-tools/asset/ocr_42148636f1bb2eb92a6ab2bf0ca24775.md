We can see the state of the stack and the current running command. ESP is the Extended Stack Pointer, or the address where the stack begins. EBP is the Extended Base Pointer, and points at the bottom of the stack so that application knows the range of the stack space. ESI and EDI are used for string copy. EIP stands for Extended Instruction Pointer and is used to track the address of the current instruction running inside the application.

# Note

In this chapter, we only begin to scratch the surface of the basics of exploit writing. A better understanding of the registers and basic assembly language knowledge would be helpful to best understand this subject. A number of books are devoted to exploit writing, so there is no way to become an expert in this one chapter. To learn more about exploit writing, find a book that has a comfortable reading style and work through that manual. To learn more about uptodate techniques, read the articles written by the Corelan Team on both the basics of exploit writing and new techniques. Next, we want to see what the program is doing. To this, we type in “x/5i $eip”. This tells the program to examine (x) the first 5 instructions pointed at EIP. In Fig. 9.2 we see that here the program is executing a “pop” instruction. There are different ways to format the examine command, so for instance 10h will show the next 10 hex values, 3s will show the next 3 strings, 5t will show the next 5 binary values, and 16c will show the next 16 characters. We will be looking at this more as we go through our exploit.
