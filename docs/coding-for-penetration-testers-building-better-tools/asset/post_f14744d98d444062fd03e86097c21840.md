Next, we create two additional checks. When we view the file outside our script by typing `cat /proc/net/arp` we see that there is a header line. We need to get rid of that line which starts with `IP` and also any blank ARP entries which will have the default value of `00:00:00:00:00:00`. We use the `next` keyword on these lines with an inline `if` statement to go to the next iteration if the first field in our line is either of these values. Finally, if we have a good ARP entry, we create a hash using the `{}` syntax and use the `:ip` and `:mac` symbols as the keys for the values that we parsed. We assign each key value with the `=>` operator. The two fields we have are the IP address, and the MAC address, which is the fourth element. Because arrays start with an index of 0, we count up from 0, giving us array fields of 0 and 3. Now that we have our hash, we append it to the end of our `up_hosts` array using the `<<` append syntax, resulting in our hash appearing as the last element of that.

```ruby
print "Active network hosts\n"
print "%-12s\t%s\n" % ["IP Addr", "MAC Address"]
```

We now have an array of hashes that we have found via ARP resolution. We need to print them in an easy-to-view format. By printing our header using the print format string, we use `%s` to indicate a string, and `%-12s` to indicate a 12-character string that is left-aligned. Once we have our format string created, we need to pass it our strings to print. We use a `%` sign after our format string to use Ruby that our next array will contain our data. We create an array using `{}` and use our two header strings for each element.

```ruby
up_hosts.each do |host|
  print "%-12s\t%s\n" % [host[:ip], host[:mac]]
end
```

Now that our header is in place, we enumerate through our `up_hosts` array and assign each hash to the `host` variable. We use our format string again, and this time we create an array with our two hash values in it. To access the hash values, we use the same syntax we access array elements, but instead of putting an integer into the `[]` we put our symbol name.

We name our script arp.rb and run it using the ruby binary. Fig. 4.1 shows an example of how our output may look like. Individual networks will have different data, but this illustrates how to run our script in Kali and shows the output formatted the way we expect it in our environment.

```ruby
#!/usr/bin/ruby
require 'socket'
s = UDPSocket.new
254.times do |i|
  next if i == 0
  s.send("test", 0, "192.168.1.1" + i.to_s, 53)
end
f = File.open("/proc/net/arp", 'r')
data = f.read.split("\n")
up_hosts = []
data.each do |line|
  entry = line.split(/\s+/)
  next if entry[3] == "00:00:00:00:00:00"
  next if entry[0] == "IP"
  up_hosts << {:ip => entry[0], :mac => entry[3]}
end
print "Active network hosts\n"
printf "%-12s\t%s\n", "IP Addr", "MAC Address"
up_hosts.each do |host|
  print "%-12s\t%s\n" % [host[:ip], host[:mac]]
end
```

# Control statements

Earlier, we used some basic if statements and for loops. Ruby conditionals are very similar to what we have seen before. The Python and Perl conditional operators work identically in Ruby. Let's look at an example.

```ruby
#!/usr/bin/ruby
data = `last`.split("\n")
```

We begin by running the last command. The last command lists the logins for the system. We put the last command in marks in order to tell Ruby that we want to run that command within the operating system, and then return stdout to the application. The execution returns a string, which we split based on newlines and assign to our data array.

```ruby
users = []
hosts = []
data.each do |l|
  if l == ""
    next
  elsif l.start_with? "reboot"
    next
  elsif l.start_with? "wtmp"
    next
  else
    l.strip!
    users << l[0,8].strip
    hosts << l[17,16].strip.lstrip
  end
end
```

Next, we create two arrays to store the unique users and hosts that we discovered with the last command. We iterate through each line of our output from last with our for loop and assign each item to the `l` variable. Then we use an if/elsif/else conditional block to check for different values that we want to ignore. If the line is empty, or if the line starts with reboot or wtmp, we want to skip it; otherwise, we want to process it. These checks are a good example of the Ruby syntax for asking questions about objects. The question mark is a Boolean test which returns true or false based on the value tested. In this case, we are determining our line starts with certain values, and if it does, we want to skip it.

After each elsif, we fall into our default else statement where we did our final processing.
