Once that is, we need to compile our vulnerable program. To do this, we issue the command "gcc -ggdb -fno-stack-protector -z execstack -m32 -o vuln vuln.c".

For this command "-ggdb" means include debugging symbols so that we can see function calls inside gdb. The argument "fno-stack-protector" disables the stack canary so we can overflow the stack and it won't kill off the application. To allow an executable stack, we use the argument "-z execstack". Finally we want to make this a 32 bit application so we add the flag "-m32". The "-o" argument specifies the output file. This so will compile our binary as a 32 bit binary with an executable stack, no stack canary, and with debugging symbols in it.

# Setting Up Debugging

Next, we need to set up debugging so that we can see what happens to our program. Inside a terminal we are going to execute the command "gdb --quiet ./vuln" which will execute our program "vuln" in the GNU Debugger without printing the startup banner. As in Fig. 9.1, typing in "r" at the prompt will run our program. The r is short for run, and either command will work but brevity is frequently when debugging.
