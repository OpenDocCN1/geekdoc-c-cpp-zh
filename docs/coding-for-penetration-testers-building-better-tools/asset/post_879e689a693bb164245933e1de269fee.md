For this command "-ggdb" means include debugging symbols so that we can see function calls inside gdb. The argument "fno-stack-protector" disables the stack canary so we can overflow the stack and it won't kill off the application. To allow an executable stack, we use the argument "-z execstack". Finally we want to make this a 32 bit application so we add the flag "-m32". The "-o" argument specifies the output file. This will compile our binary as a 32 bit binary with an executable stack, no stack canary, and with debugging symbols in it.

After we run the program, we want to inspect the state of the program. By hitting "CTRL+c" we will break the execution of the program. We can see that the program received a "SIGINT" signal, which means it was an interrupt signal caused by pressing "CTRL+c". Once the program is stopped, we issue the command "i r". This command is short for "info registers" which will show the values of each register. Knowing what these values look like before exploit is useful so that we can see what changes during exploit. These registers are important because they indicate the current state. We see the general purpose registers: EAX, ECX, EDX, and EBX. These registers are short for Accumulator Pair, Counter Pair, Data Pair, and Base Pair. The reason these are called pairs is because each register is 32 bit, and it can be split into registers that are the portion of 32 bit value. For instance, EAX can be split into the 16 bit register of AX, and then the AX can be split into two 8 bit registers AH and AL, the high and low portions.

We can see the state of the stack and the current running command. ESP is the Stack Pointer, or the address where the stack begins. EBP is the Base Pointer, and points at the bottom of the stack so that application knows the range of the stack space. ESI and EDI are used for string copy. EIP stands for Instruction Pointer and is used to track the address of the current instruction running inside the application.
