By default, many versions of Netcat for Windows are compiled with the -e option enabled, allowing us to use Netcat to run an executable file on the system and connect it to the network through Netcat's facilities. ## Netcat variants

As we mentioned earlier, Netcat is an open source tool. This leaves open to the tinkering of the masses of programmers and would-be programmers who might feel inclined to retool it in order to add features, make changes, and so on. A large number of Netcat derivatives are floating about the Internet, let's take a look at a few of them quickly to see what the differences are. Some of the more interesting variations are Socat, CryptCat, and Ncat, but this is by no means an exhaustive list.

Socat¹ is an implementation of Netcat that provides several very interesting features. One of the more useful bits is that Socat can use a number of channels to send and receive data, including TCP/IP, serial lines, files, pipes, and so on. This allows us to considerably extend the number of uses to which we can put Socat. Socat also has a large set of other features that extend the capabilities of Netcat, and more information can be found at http://www.destreach.org/socat/doc/README. Socat is available for both UNIX-like and Microsoft platforms.

CryptCat² is a relatively stock implementation of the Netcat source, with one interesting feature added: encryption. CryptCat supports Twofish encryption, enabling us to secure the network traffic we are sending it through. CryptCat is available for UNIX-like and Windows operating systems.

Ncat is a Netcat implementation that ships with the Nmap scanner distribution. Ncat, very similar in nature to Socat, is a Netcat derivative that adds a great number of features, including the ability to chain multiple Ncat instances together, enhanced support for using Ncat as a proxy, SSL support, and a number of other features. Ncat, like Nmap, is also functional on several platforms.

## Building a Web Server With Netcat

As we discussed earlier, we can use Netcat to serve a file. The simplest form of web server we can create is with a single line:

```bash
#!/bin/bash
while true; do nc -l -p 8080 < index.html
```

Wait, the script above has a problem: it will only serve one request before exiting. To fix this, we can use a loop to keep it running:

```bash
#!/bin/bash
while true; do
  nc -l -p 8080 < index.html
done
```

Actually, this still has a problem: it can't handle multiple concurrent connections. To handle multiple connections, we can use a tool like `xargs`:

```bash
#!/bin/bash
while true; do
  nc -l -p 8080 -e /bin/bash
done
```

Wait, the `-e` option is not available in all versions of Netcat. In that case, we can use `socat`:

```bash
#!/bin/bash
while true; do
  socat TCP-LISTEN:8080,fork EXEC:./server
done
```

This is a more robust way to create a simple web server. Now, we can add some more features to our server, such as logging requests and handling different types of files.

## Transferring Files With Netcat

Another thing we can do with Netcat is to send and receive files over the network. This works largely the same as sending any other sort of network traffic we might care to, which is what it ultimately. The simplest form of file transfer we can do is with a quick command-line usage of Netcat. On the receiving end, we would run nc -v -w 30 -p 80 > myfile.txt. This will run Netcat in verbose mode with a timeout of 30 seconds, listening on port 80, and sending whatever it receives to myfile.txt.

On the sending end, we would execute something along the lines of nc -v -w 5 10.0.1.1 80 < myfile.txt. This will fire up Netcat in verbose mode, a timeout of 5 seconds, and sending myfile.txt to whatever is listening on port 80.
