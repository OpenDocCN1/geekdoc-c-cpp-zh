To be sure, we can create a NOP sled, or a padding of NOP instructions which tell the application to do nothing and move on. By NOP is a computer instruction that does nothing and moves on. By adding these NOP instructions, we can create a landing pad for our code. Let's modify our code for the new information we have.

#!/usr/bin/python
import socket
s = socket.socket()
host = '127.0.0.1'

We can see a few modifications here. We have modified the EIP value and set it to the value of a space on our stack. The x86 platform is little endian, and we have to put the location jump in reverse order. This makes 0xffffcc30 turn into 0x30ffff. Next, we update our buffer to have our additional 32 bytes of NOP instructions (0x90) Finally we change the last portion of our buffer from C's to "\xCC". This is the code for INT interrupt that will cause the debugger to stop. This will tell us that our code has successfully executed once we run it. Let's give it a go.

## Adding Shellcode

Now that we have control of the execution of the application, it’s time to add custom shellcode to our script. This will allow us to execute arbitrary code within the application. This means that if our application is running as an administrator on the machine, our code will have the same privileges. Sadly, shellcode doesn’t grow on trees, so we’ll have to generate it.

> Note
> When we are referring to shellcode, we mean the code that we are injecting into a process. This code typically results in shell access to a machine, but the term is used generically to describe any binary code that we will inject into an application. When we build an exploit, executing the shellcode is one of the final steps to gaining access to a remote system. We execute the shellcode by redirecting the execution of the application we are exploiting so that we execute the arbitrary instructions. Our shellcode is made up of these instructions.

The Metasploit Framework has a tool to help us add shellcode to our exploit called msfvenom. The msfvenom tool will allow us to generate shellcode to perform tasks as encode it in such a way that characters will be interpreted by the application can be excluded. For our example, we are going to use a payload that will just start up a network listener.

There are two types of payloads in Metasploit: staged and single payloads will load a second part over the network, where the single payloads have all of the code to finish the exploit in one pass. The staged version of our linux bind shell will be "linux/x86/shell/bind_tcp" where the single version is "linux/x86/shell_bind_tcp". We are going to use the "linux/x86/shell_bind_tcp" module which has one option that has to be set; the LPORT or listening port.

In our example, we need to do a few things. We need to generate our code in Python to add our script. We need to make sure the shellcode is clean of characters that might prematurely end our string. These characters are typically a NULL character, which acts as a string terminator, the new line and carriage. When we put this together, we get the command "msfvenom -p linux/x86/shell_bind_tcp -b \x00\xa\xd" -f python LPORT=8675" which can be seen in Fig. 9.8.

Then, send our exploit string. Once the string is sent, our exploit should execute, and then we should be able to access port 8675 on our local host and have a shell.

When we access our shell we will want to use netcat instead of Telnet. Telnet adds additional characters for terminal control that will mess with our shell.
