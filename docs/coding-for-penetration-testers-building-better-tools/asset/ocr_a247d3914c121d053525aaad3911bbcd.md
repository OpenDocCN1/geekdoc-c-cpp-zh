Sometimes system administrators make compromises in security for a little ease of use. Let's examine a hypothetical case. Our system administrator has created a top-secret PHP script logview.php in order to look at servers from anywhere. Since the script isn't linked anywhere, our administrator feels it's secure in the Web root. Let's look at the steps the administrator has taken to create and allow his Web script to work.

```
<?php
print "pre";
print passthru('/var/log/apache2/access.log');
?>
```

The PHP code prints a pre HTML tag to indicate that the output has been preformatted. It then executes the cat command on the Web access log and uses the PHP passthru command to print the output to the screen. This is a quick and easy log viewer with a critical vulnerability. So, if we create a script that injects HTML into the log, the PHP script will happily render it in our unsuspecting administrator's Web browser. In order for this to work, our system administrator also has changed the mode on the Apache log directory to be world-readable.

To reproduce this, add the code to /var/www/html/viewlog.php and execute the commands chmod 755 /var/log/apache2 and chmod 644 /var/log/apache2/. Then verify that the Web server is started, and the rest of the examples in this chapter should work.
