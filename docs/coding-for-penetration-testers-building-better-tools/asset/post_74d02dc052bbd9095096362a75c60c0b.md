
Next, we create a new instance of the Hypertext Transfer Protocol (HTTP) object using a Ruby technique referred to as a block. The indentation defines the beginning and end of the block. We don't have to use a loop here, but by using this block, we assign our value to the http variable. When our block is over, the Net::HTTP class will close the socket and take care of our cleanup. Our http variable holds the HTTP object which allows us to issue HTTP commands to the Web server. We use the head method to send an HTTP Head request on the Web server as the context. This returns information including the date, the type of Web server, request parameters, and frequently, the last-modified header which indicates when the page was changed. The two pieces of data we are trying to extract from the server are the software being used and the last modified date which we will return as an array.

Finally, we close our loop, allowing the HTTP object to clean up for us. If, for some reason, our request fails, we add a fallback to return an array with nil values. This ensures consistent return information from our function. Let's make our function parse options passed from the command line, and use those variables to call our function.

Notice the difference in the handling of ARGV. In many languages, the first array element in ARGV is the program name itself. In Ruby, the first element of ARGV is the first option. To reference the program name itself, we use $0.

If we have an invalid number of ARGV arguments, we present an error message and exit. The notation we are using in our error string allows us to embed code or variables into strings effectively. By wrapping either code or a variable in the #{} symbols, we are telling Ruby to evaluate the code inside the symbols and insert that value into our string. In this case, we include the name of the script that was called by inserting $0.

# Building Classes With Ruby

Classes allow us to group data with methods that can help manipulate, augment, and report that data. In Ruby, classes can build upon each other; they are designed to be extended and augmented to create custom classes for specific purposes. This allows us to build a basic socket server class and extend it to make different protocols work. We can leverage the base code from the socket server and write smaller amounts of code for each protocol. By doing this, when we find a bug in the base class, we don't have to copy and paste to propagate code throughout to define protocols.

Let's take the header function that we created and wrap it in a class.

### Building a Class

We will create a class named Header. The initialize method will be used to set up the host and port. We will then define the getHeader method to perform the request.

```ruby
#!/usr/bin/ruby
require 'net/http'

class Header
  def initialize(host, port = nil)
    @host = host
    @port = port || 80
  end

  def getHeader
    Net::HTTP.start(@host.to_s,@port) do |http|
      resp = http.head('/')
      return [resp['server'].to_s,resp['Last-Modified'].to_s]
    end
    return [nil,nil]
  end
end

if ARGV.size <= 0 || ARGV.size > 2
  print "Usage: #{$0} Host [Port]\n"
  exit
end

header = Header.new(ARGV[0], ARGV[1])
server, modified = header.getHeader
print "Server #{ARGV[0]}:#{ARGV[1] || 80}(#{server}) last-modified #{modified}"
```

By wrapping the logic in a class, we have made the code more organized and reusable. We can now create multiple instances of Header with different hosts and ports if needed.
