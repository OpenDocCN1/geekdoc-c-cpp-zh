# Penetration Testing Uses for PowerShell

We can use PowerShell in many ways during a penetration test. Since PowerShell has access to Microsoft’s .NET libraries as well as core operating system functions, isn't much that we can't do with PowerShell. We will go over a few uses for PowerShell, such as controlling processes and services, interfacing with the event logs, sending and receiving files over the network, and interfacing with the Registry.

# Controlling Processes and Services

Being able to create and destroy process and interact with services is one of the key capabilities required on a pen test. There are frequently times when we will have to run commands to gain additional insight into systems or to further our access. For this section, we will continue to focus on our WinRM scripts, but the PowerShell that we are running can be used directly from PowerShell on the remote system as well. Let's start with an example of getting a remote process list.

```
import winrm
# Place Script Here
script = ""\Get-WmiObject Win32_Process|select ProcessId, ProcessName, CommandLine \
Sort-Object ProcessId ""
ses = winrm.Session('<username>','<password>',auth=)
r = ses.run_ps(script)
print r.std_out , r.std_err
```

In our example we use the Get-WmiObject cmdlet to retrieve the process table from the system. There is a lot of information returned about running processes by this cmdlet, but we only care about a subset. The Select cmdlet allow us to choose only certain fields to be displayed. We limit it to just the ProcessId, ProcessName, and CommandLine fields. Finally, we want to sort these processes by ProcessId, so we use the Sort-Object cmdlet to sort the output by the ProcessId.
