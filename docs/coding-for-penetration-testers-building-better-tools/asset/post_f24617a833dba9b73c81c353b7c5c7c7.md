This is the basic template we need to generate our module. We are going to create the module as vuln.rb in the ~/.msf/modules/exploits/linux directory. This branch is our personal copy of the Metasploit branch where we can add modules that will just impact our user and not interfere with any git updates or upgrades.

We include the msf/core module so that we have access to all the Metasploit Framework code. Next, we extend the Msf::Exploit::Remote class to create a new Metasploit4 class. By extending the class, we get helper functions to deal with socket handling and encoding data for the network.

In our initialization method, the super method will pass the output from the update_info method to the underlying classes to ensure that the setup of our class is correct. The update_info method updates the module's default information with information that is specific to our exploit. We pass two pieces of information into the update_info method: the info hash that was passed into our initialization method when it was called, and the key-value pairs of data regarding additional information we wish to update.

The key-value pairs help us find our module and tell Metploit how to treat it. The name and description are what we see when we pull information about the exploit. The license is the license under which we want our module to be released. The payload contains information to tell Metploit about our payload.

The default platform for this template is Win. If we are creating something not for Windows, we need to update this field to correspond to the appropriate platform. The disclosure date is added so that folks know when the vulnerability was discovered, and finally the default target is the target we want the module to use by default.

We can see that this hasn't been filled in yet, so we need to add to the appropriate values to our module. This is the user directory for Metploit and will create a module that is only visible to our user, and will also survive if we update or reinstall Metploit. Next we will update the fields so that we include the TCP functions for remote exploitation so that we don't have to rewrite socket connection routines. To do this we add the line “include Msf::Exploit::Remote::Tcp” right before we initialize function. Then we update the Name, Description, Author, and References settings. We also update our platform to “Linux” and change our Target to “Kali 2.0.” When we change this field we will also need to update the address for our return value. This value is the one we recorded to put into our Python exploit, but instead of reversing the byte order it goes normally.

For our payload, we need to copy over our bad character list as well as adding in a field telling Metasploit how larger the payload can be. We built our last payload so that the message we sent would always be 1024 characters, so we are going to stick with that. That means that the payload size is 1024 minus the sum of our overflow (268 bytes), the EIP overwrite (4 bytes), and the NOP sled (32 bytes).
