Intuitively, vertices sharing a lot of neighbors should belong to the same cluster. To formalize this intuition, a similarity function for pairs of vertices $v$ and $w$, denoted by $sim(v,w)$, is defined as follows on the intersection of their sets of neighbors:

```
$sim(v,w) = \frac{|\Gamma(v) \cap \Gamma(w)|}{\sqrt{|Gamma(v)| \cdot |Gamma(w)|}}$
```

where $\Gamma(v)$ denotes the set of all (direct) neighbors of vertex $v$, i.e., $\Gamma(v) = \{w|(v,w) \in E\} \cup \{v\}$. The $\epsilon$-neighbor of a vertex $v$ is given by the set of vertices whose similarity exceeds the threshold of $\epsilon$, i.e.,

```
$N_{\epsilon}(v) = \{w|w \in \Gamma(v) \wedge sim(v,w) \geq \epsilon\}$
```

A vertex $v$ is called a core, if its $\epsilon$-neighborhood has a cardinality of at least $\mu$. Based on these definitions, the concepts of direct structure-reachability, structure-reachability, structure-connectivity, (structure-connected) cluster respect to $\epsilon$ and $\mu$ can be introduced in analogy to the DBSCAN concepts.

If a vertex is not a member of any cluster, it is either a hub or an outlier, depending on whether it has neighbors in at least two clusters, and it is an outlier otherwise, i.e., if all neighbors belong to the same cluster or to none.

The SCAN algorithm is completely analogous to the DBSCAN algorithm. The crucial operation is the retrieval of neighbors of a given vertex, which can be efficiently supported using an adjacency list, a data structure where each vertex is associated with a list of directly neighboring neighbors. With this structure, the cost of a vertex is proportional to the number of neighbors, which is the degree of the vertex. SCAN performs at most one neighborhood query per vertex. The total running time of SCAN is $O(m)$, where $m$ denotes the number of edges, which scales well to large datasets.

However, in applications more informative graphs are where features are associated with vertices representing object properties such as demographic attributes of customers and expression data of genes. Integrating the concepts of dense subgraphs and subspace clusters, Moser et al. [28] introduced the problem of finding cohesive patterns. A cohesive pattern is defined as a subgraph

- 1. connected,
- 2. has a density exceeding the threshold of $\alpha$, and
- 3. has homogeneous values in a least $d$ features, for example, the values of these features may have at most a specified variance within the vertices of the pattern.

Different from graph partitioning methods and similar to frequent pattern mining methods, cohesive patterns can overlap and not cover the entire dataset. Furthermore, the number of patterns does not need to be specified in advance. Integrating constraints on the feature reduces the number of patterns substantially and adds meaning to the identified patterns. In order to reduce the potentially large number of cohesive patterns, the search is restricted to finding only maximal cohesive patterns, i.e., those whose supergraphs do not form cohesive patterns.

The problem of discovering cohesive patterns is NP-hard, but it becomes tractable in many practical cases by exploiting the monotonicity properties. A constraint is called if the satisfaction of a pattern implies the satisfaction of another. A constraint is called anti-monotone if the satisfaction of a pattern implies the satisfaction of its subgraphs. A constraint is called monotone if the satisfaction of a pattern implies the satisfaction of its supergraphs. Finally, the algorithm terminates at a level where no more patterns can be added.

### 5.8 Other Directions

A data stream consists of a sequence of data points that arrive continuously and rapidly are too large to be stored permanently, so an algorithm can take only look at each point to analyze the data stream. Stream data is becoming available in many applications, e.g., sensor data and click data. For density-based clustering of data streams, [6] introduces the concepts of core-micro-clusters, potential core-micro-clusters and outlier micro-clusters to maintain the statistical significance. A novel pruning strategy is designed based on these concepts, allows accurate clustering in the context of limited memory. [7] presents the D-Stream algorithm, which uses an online component to map input data into a grid and an offline component to produce the density decaying technique to capture the dynamic changes of a data stream. resulting from outliers in the data stream, are detected and removed.

Recently, uncertain data has more common in scenarios such as mobile services, where the locations of moving objects are transmitted at discrete time stamps and only be estimated with some uncertainty between these times. Absolutely values are generalized to probability distributions over the attribute domain. For density-based clustering of uncertain data, the FBSCAN algorithm [24] introduces a probabilistic concept of density-based clusters generalizing the deterministic concept of DBSCAN. In particular, the distance function is replaced by a distance function and a distribution function for certain uncertain data, and the Boolean core point property is replaced by a core point probability. The main challenge of the implementation is the efficient computation of the core point probability. A Monte-Carlo sampling method is developed in order to approximate this probability. A similar generalization (OPTICS) has been proposed for [], supporting the density-based clustering of uncertain data. See Chapter 18 on clustering uncertain data for other clustering methods.

Januzaj et al. [19] investigate density-based clustering of distributed databases. The databases are clustered locally, and representatives from the clusters are determined. These representatives are sent to a global server where the overall clustering is computed on local representatives. In [20], the same authors improve the scalability of this approach, allowing the user to specify the trade-off between clustering quality and the number of transmitted objects from the different local databases to the global server.
