**Top-Down Subspace Search.** The rationale of top-down approaches is to determine the subspace of a cluster from the full-dimensional space. This is usually done by determining a subset of attributes for a set of points—cluster members—such that the points meet the cluster criterion when projected onto this subspace. Obviously, the dilemma is that for the determination of a cluster, at least [some] cluster members must be identified. On the other hand, in order to determine cluster membership, the subspace of each cluster must be known. To escape this cluster dependency, the top-down approaches rely on a rather strict assumption, which has been called the *locality assumption* [90]. It is assumed that a cluster can be derived from the local neighborhood (in the full-dimensional data space) of the (provisional) cluster center or the (provisional) cluster members. In other words, it is assumed that in the full-dimensional space, the subspace of each cluster can be learned from the local neighborhood of cluster representatives or cluster members—an assumption that may make sense if the dimensionality of the subspaces is not much smaller than the dimensionality of the data.

Other top-down approaches that do not rely on locality use random sampling or a heuristic to generate a set of potential cluster members.

**Bottom-Up Subspace Search.** The exponential search space of all possible subspaces of a data space needs to be traversed is equivalent to the search space of the frequent item-set in market basket analysis in the area of transaction databases. For example, an itemset may contain items *A, B, C*, etc. The key idea of APRIORI algorithm [15] is to start with item-sets (“transactions”) of size 1 (containing a certain item, irrespective of other items also contained in the transaction) and exclude those larger item-sets from the search that cannot be frequent anymore, given the knowledge that smaller item-sets are frequent. For example, if a 1-itemset *A* is not frequent (i.e., we count such an item-set less than a minimum support threshold), all 2-itemsets, 3-itemsets, etc., containing *A* (e.g., *{A, B}*, *{A, C}*) cannot be frequent (either either item-set *A* would have met the minimum support threshold). Theoretically, the search space remains exponential, yet practically the search is substantially accelerated.

Transferring the item-set problem to subspace clustering, each attribute represents an item and each cluster is a transaction. Frequent attributes span the corresponding subspace. Finding attributes relates to finding all combinations of attributes that constitute a subspace containing at least one cluster. This observation is the rationale of many bottom-up subspace clustering approaches. The subspaces that contain clusters are determined by searching all 1-dimensional subspaces that contain at least one cluster by employing a search strategy similar to frequent item-set mining algorithms. To apply any frequent item-set mining, the cluster algorithm must implement a downward closure property (also monotonicity property):

If subspace S contains a cluster, then any subspace T *⊆* S must also contain a cluster.

For pruning (i.e., excluding specific subspaces from consideration), the antimonotonic reverse implication can be used.

- If a subspace T does not contain a cluster, then any superset S ⊇ T cannot contain a cluster.

Let us note that there are bottom-up algorithms that do not use an APRIORI-like search but instead other search heuristics.

### 9.4.1.3 Clustering Algorithms

The two basic techniques resulted initially in two “subspacing” paradigms that have been named by the pioneers in this field “subspace clustering” [14] and “projected clustering” [12]. For the latter, a variant has emerged called “soft clustering” [82]. Many algorithms, do not clearly fit in one of these categories. We list some examples as “hybrid approaches.”

**Projected Clustering.** The objective of projected clustering is to find sets of tuples $(O_i, D_i)$, where $O_i$ is the set of objects belonging to cluster $i$ and $D_i$ is the subset of attributes where the points $O_i$ are “similar” according to a given criterion. The approach introducing the task of “projected clustering” is PROCLUS [12], a k-medoid algorithm. PROCLUS normally determines a set of potential clusters $M$ on a set of points first. In the iterative refinement, for each of the medoids the subspace is determined by minimizing the standard deviation of the points in the neighborhood along each dimension. Points assigned to the closest medoid are refined by replacing medoids with new medoids as much as the clustering allows. The algorithm outputs a partition of the data into clusters (represented by its medoid) and a (potentially empty) set of noise points. The k-medoid model of PROCLUS tends to produce spherical clusters in their corresponding subspaces. In addition, since the set $M$ of possible medoids is determined in a randomized procedure, runs of PROCLUS with the same parameterization result in different clusters. Variations of PROCLUS are, for example, BIT [130] and SSPC [134]. BIT employs heuristics to enhance efficiency and clustering accuracy. SSPC offers the capability of further enhancing using domain knowledge or attributes. PreCon applies a density-based (full-dimensional) clustering algorithm DBSCAN [46] using a specialized measure that captures the subspace of each cluster. The definition of this specialized distance is based on the so-called subspace preference assigned to each point $p$: if the variance of the points in the neighborhood of $p$ is smaller than a user-defined threshold $\delta$, the specialized distance between points is a weighted Euclidean distance where dimensions relevant for the subspace preference of a point are weighted by a constant $\kappa \gg1$ while the algorithm determines the number of clusters automatically and handles noise implicitly. In addition, its results exhibit any shape in the corresponding subspace. However, PreCon requires the user to specify a number of input parameters that are hard to guess. Especially $\epsilon$, the radius, has different meaning in different dimension (cf. Aspect 5 of the curse of dimensionality) but is used both for the first neighborhood (locality assumption) in the full-dimensional space as well as for the adapted neighborhood in some lower-dimensional space.

**Soft Clustering.** There is a rich literature concerned with so-called soft clustering [43, 55, 79, 28, 42, 98]. These are useful optimization approaches derived from k-means clustering, using some weight vector for the weighting of attributes. Thereof, weights $w_i$ for $i=1,\dots d$ are introduced over the distance measure:

$$\|x-y\|_p^p = \sum_{i=1}^{d} w_i |x_i - y_i|^p$$

Usually, in these approaches, weights are restricted to at least the condition

$$0 < w_i \leq 1,$$

i.e., to ensure the applicability of optimization techniques, no attribute is truly omitted, and hence the resulting clustering resides in the full-dimensional, though skewed data space. The fact that the clustering is not truly searched for in a projected space (i.e., no subspace is assigned to a specific cluster) is indicated by the term soft. However, these approaches are generally named "subclustering,” which reflects the differences discussed here. Essentially, all these approaches can be seen as variants of EM-clustering [40].

Geometrically, the effect of these approaches is just to allow the shape of clusters to become axis-parallel ellipsoids. This does not necessarily account for relevance or irrelevance of different attributes. It relates more to some sort of normalization of attributes per clusters.

An example for these methods is LAC (Locally Adaptive Clustering) [43], which starts with $k$ centroids and $k$ sets of $d$ weights (for $d$ attributes). The algorithm proceeds to approximate a set of $k$ Gaussians by adapting the weights.

COSA [55], another prominent example, does not define a clustering but merely a similarity matrix that can be used by an arbitrary clustering algorithm. The matrix contains weights for each point a subspace preference of the points to PreDeCon. The weights for a point $p$ are determined by starting with the Euclidean $k$-nearest neighbors of $p$ and by computing the average distance distribution along each dimension. Roughly, the weight for a given attribute is the ratio between the distances of the point $p$ to all $k$-nearest neighbors of $p$ in all attributes. The higher the variance of the $k$-nearest neighbors along an attribute is, the higher the weight that is assigned to that attribute. The weight, however, cannot become 0. As long the vector weights still change, the $k$-nearest neighbors are again determined using the current weights and the number of neighbors is an input parameter. Very different from PreDeCon, the weights can have arbitrary values rather than two fixed values. In addition, the weighting matrix is tested using several full-dimensional clustering algorithms rather than integrating it into only one specific algorithm. Note that the effect of weight vectors is very different in density-based approaches like PreDeCon where the shape of clusters is not defined beforehand.
