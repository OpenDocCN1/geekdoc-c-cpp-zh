Input: a set S of objects.
Parameters: (1) δϕ : the increment for ϕ.
(2) threshold for ϕ : the maximum number of values that can differ between an object and the mode of its cluster.
Default parameter values: (1) δϕ=1.
(2) threshold = the number of categorical attributes m.

Output: a set of clusters.
Method:
1. Order objects by decreasing frequency of their attributes.
2. Insert the first object into a new cluster, use the mode of the cluster, and remove the object from S.
3. Initialize ϕ to 1.
4. Loop through the objects until S is empty or ϕ > threshold
a. For each object o in S
i. Find o's nearest cluster c using the dissimilarity metric to compare o with the modes of all existing cluster(s).
ii. If the number of different values between o and c's mode is larger than ϕ, insert o into a new cluster
iii. Otherwise, insert o into c and update c's mode.
iv. Remove o from S.
b. For cluster c, if there is only one object in c, remove and put the object back in S.
c. If in this no objects were inserted in a cluster with size > 1, increment ϕ by δϕ.

12.7 shows the main part of the MULIC clustering algorithm. MULIC does not store the cube in makes simplifications to decrease the runtime. A MULIC starts from a dense area and expands outwards via radius represented by the ϕ variable. When MULIC expands a cluster it does not search all member objects as HIERDENC does. Instead, it uses a model that summarizes the content of the cluster. The mode is a vector μ = {μ₁, ..., μm} where μi is the most frequent value for the ith attribute in the given cluster c [47]. The MULIC algorithm ensures that whenever an object o is clustered, it is inserted into the cluster with the least dissimilar mode. The default dissimilarity metric between o and μ is the Hamming distance, although any metric could be used. A MULIC cluster consists of layers formed gradually, by relaxing the maximum dissimilarity criterion for inserting objects into clusters. MULIC does not require the user to specify the number of clusters and can identify outliers.

MULIC has several differences from traditional hierarchical clustering, which stores all distances in an upper square matrix and updates the distances after each merge [50, 61]. MULIC clusters have a clear separation. MULIC does not require a cut-off to identify the clusters, in hierarchical clustering; this of benefit for some MULIC applications, such as the one on protein interaction networks discovered in [7]. One of the drawbacks of hierarchical clustering is that the sequence of cluster mergers affect the result and “bad” mergers cannot be done later in the process. Moreover, if several large clusters are merged, interesting local cluster structure is likely to be lost. MULIC does not merge clusters during the clustering process.

## 12.4.4 Model-Based Clustering

Model-based clustering assumes that objects match a model, or clusters objects that they match the distribution. The model may be user-specified and the parameter may change during the process. In bioinformatics, model-based clustering methods integrate background knowledge into gene expression, interactomes, and sequences [23, 66, 45, 51, 52]. Building models is an unsupervised; some assumptions may be false and the results will be inaccurate. Another disadvantage of model-based clustering (especially neural networks) is slow processing on large datasets.

### 12.4.4.1 BILCOM Empirical Bayesian (Mixed Categorical and Numerical)

BILCOM Bi-Level Clustering Of Mixed categorical and numerical data types is a model-based method [10]. This algorithm adapts an empirical Bayesian approach, with categorical data as the guide. In biological applications to genes, Gene Ontology (GO) annotations represent the categorical data and gene expression data numerical. Model-based clustering finds arbitrary gene expression clusters by incorporating background knowledge [1, 24, 45, 51, 52, 69, 20, 64].

The BILCOM performs clustering at two levels, where the first level clustering serves as a foundation for the second level, simulating a pseudo-Bayesian process. BILCOM is primarily applied to datasets from the domain. In these sets, categorical data represents semantic information on the objects, while numerical data represents experimental results. Categorical similarity is emphasized at the first level and numerical similarity at the second level. The first level output is given as input to the second level and the second level result is the output of BILCOM. Figure 12 shows clusters. The second level consists of substructures. Object A is assigned to different first and second level clusters, where the numerical similarity at the second level is stronger than the categorical similarity at the first level. On the other hand, object B is assigned to the same clusters because both categorical and numerical similarities support this classification. BILCOM considers categorical and numerical similarities of objects to the clusters to which it may be assigned.

Different types of data are used at first and second levels. The numerical data represents results results involving objects. For example, the numerical data used at the second level might look as follows: BILIRUBIN: 0.39; ALBUMIN: 2.1; PROTIME: 10. The categorical data represent what was observed to be true about the objects of the example. For example, the categorical data used at the first level might be existing information on objects looking as follows: SEX: male; STEROID: yes; FATIG: no.

The main disadvantage of BILCOM is that the user has to specify the number of clusters.

### 12.4.4.2 AutoClass (Mixed Categorical and Numerical)

AutoClass is a clustering algorithm for mixed datasets, which uses a Bayesian method for determining the optimal clusters based on prior distributions [71]. AutoClass finds the most likely classifications of objects in clusters, given a prior distribution for each attribute, symbolizing prior beliefs of the user. In the first step the user selects a probabilistic distribution for each of the m attributes in the dataset. As an example, let the evidence on an object X = {age=28, blood-type=A, weight=73kg}; blood-type is a categorical attribute that is modeled with a Bernoulli distribution, age and weight are numerical attributes modeled with a normal (Gaussian) distribution. At each loop, AutoClass changes the classifications of objects in clusters, so that each object is assigned to the cluster with the attribute probability distributions (considering the current means and variances) that give the highest probability of observing the object' values. Additionally, AutoClass iteratively examines different number of clusters, which are not user-specified. Then, AutoClass changes the means and variances of the probability distributions for the attributes in cluster. The iteration continues until the clusters and the attributes' probability distributions stabilize. The AutoClass output is a mixture of several likely clusters, where a clustering classifies each object into the most likely cluster on the basis of the attributes' probability distributions.

Drawbacks of AutoClass include that users have to specify the model spaces to be searched and in wrong models may produce wrong results. Also, AutoClass can be slow to converge to a clustering result on some datasets.

### 12.4.4.3 SVM (Mixed Categorical and Numerical)

Support Vector Machines (SVMs) provide a method for supervised learning. SVMs construct a separating hyperplane using a training of data, as shown in Figure 12.9. Despite their superiority, SVMs have been applied to categorical data to find clusters in an unsupervised manner. The approach involves randomly assigning objects to pairs of clusters and recomputing the separating hyperplane, until there is a convergence of object assignment and the hyperplane.

Previously, SVM-Internal (usually referred to as a one-class SVM) used internal of Support Vector Machines to find the closest sphere in data. The internal approach to SVM clustering lacked robustness and is biased towards clusters with a spherical shape feature. In the case of real-world problems, the SVM-Internal algorithm could only detect the relatively small cluster cores.

To remedy this, an external-SVM algorithm was introduced to clusters data with no prior knowledge of each object's classification. Initially, every object in the dataset is densely labeled and a binary SVM is trained. After the initial convergence is achieved, the sensitivity + specificity will be low, likely near 1. The algorithm improves this result by iteratively relabeling only those misclassified objects, which have confidence factors beyond some threshold, followed by rerunning the SVM on the newly labeled dataset.
