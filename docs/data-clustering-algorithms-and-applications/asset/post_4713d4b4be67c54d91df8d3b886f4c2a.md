## 12.4.3.5 CLO

CLOPE stands for “Clustering with SLO”. It is useful for clustering transactional databases with high dimensions, such as market-basket data and web server logs. CLOPE is considered to be fast and scalable on transactional databases and high-dimensional datasets. CLOPE uses a heuristic of increasing the height-to-width ratio of the cluster [74]. Given a cluster C, CLOPE finds all the items in the cluster, with their respective occurrences, i.e., the number of transactions containing that item. D(C) is the set of distinct items, and Occ(i) the occurrence of i in cluster C. CLOPE draws the histogram of a cluster C, with the X-axis decreasing ordered by their occurrences, and as the Y-axis.

Figure 12.5 shows an example of clustering with two clusters each. For each cluster, the occurrence of every distinct item is counted and the results are plotted as histograms. The height (H) and width (W) of the histogram for each cluster is obtained. Using the height-to-width ratio of the cluster histograms, CLOPE defines a global criterion function for clustering. This example shows that a larger height-to-width ratio of the histogram means better intra-cluster similarity.

The main disadvantage of CLOPE clustering is that the histogram may be suboptimal for some datasets.

## Clustering Categorical Data

We are given a dataset of objects $S$ (which might contain duplicates) with $m$ categorical attributes, $X_1, \dots, X_m$. Each attribute has a domain $D_i$ with finite number of $d_i$ values. The space $S^m$ can be viewed as an $m$-dimensional 'cube' with $\prod_{i=1}^m d_i$ cells. A cell $\mathbf{x} = (x_1, \dots, x_m) \in S^m$ represents a set of objects given by function $freq(\mathbf{x})$ with all $m$ attributes equal to $(x_1, \dots, x_m)$. We define the HIERDEND hyper-cube $C(\mathbf{x}_0, r) \subset S^m$, centered at $\mathbf{x}_0$ with radius $r$, as:

```
$C(\mathbf{x}_0, r) = \{\mathbf{x} \in S^m \text{ and } dist(\mathbf{x}, \mathbf{x}_0) \leq r \text{ and } freq(\mathbf{x}) > 0\$
```

The $dist(-)$ is a distance, which may be the Hamming distance.
Figure 12.1 illustrates two HIERDEND hyper-cubes in a 3-dimensional cube. Cells' cubes for $freq(x) = 1$ are not shown as not objects having a cubic shape. Normally, a hyper-cube will equal a subspace of $S^m$.
The density of a subspace $X \subset S^m$, where X could equal a hyper-cube $C(\mathbf{x}_0, r) \subset S^m$, involves the sum of $freq(x)$ evaluated over all cells of $X:

```
$density(X) = \sum_{\mathbf{c} \in X} \frac{freq(\mathbf{c})}{|\mathbf{c}|}$
```

This density can be viewed as the likelihood that a hyper-cube contains a random object from $S$, where $|S|$ is the size of $S$. HIERDEND densest the densest hyper-cube $C(\mathbf{x}_0, r) \subset S^m$. This is the one with the maximum likelihood of containing a random object from $S$.
Figure 12.6 shows the HIERDEND clustering algorithm. $G_k$ represents the k-th cluster. The remainder set, $R=\{\mathbf{x} \in S^m \text{ and } \mathbf{x} \notin G_i; i=1, \dots, k\}$, is the union of collected objects of all $k$ clusters.
Step 1 retrieves the densest hyper-cube $C \subset S^m$ of radius $r$. Step 1 checks if the densest hyper-cube represents more than one object ($density(C) > 1$), otherwise the cluster includes zero or one object, then $r$ is increased, ending up option. Step 2 creates a new leaf cluster at level $r \geq1$. Starting from an existing leaf, step 3 tries to move to the densest hyper-cube of radius $r$ nearby. If a hyper-cube is dense, step 4 expands the cluster by including the hyper-cube's cells. This is repeated for a cluster until no connection can be made. New objects are created until $r=m$, most objects are $freq(r) \leq1$ and the unconnected clusters are treated as outliers (step 5). For many datasets, most objects are likely to be clustered before $r=m$.
Initially $r$ is 1 by default, since most datasets contain subsets of similar objects. Subsets are clustered when $r$ is increased, a special process merges clusters that connected relative to $r$. Although the initial $r=1$ value may result in many clusters, similar clusters are merged gradually. A link represents between two or more clusters, created at a level $r \geq2$. A link represents a group of merged clusters. This process constructs one or more tree structures, building hierarchical clustering [50, 61]. The user specifies a cut-off level (e.g., $r=3$) to cut tree branches; links at the cut-off relative to $r$ and if links exist at level $r$, Step 5 checks if a newly formed cluster is connected to another cluster. Step 6 links existing clusters into a tree, until $r=m$. By allowing $r$ to reach $m$, an entry is built. At the top of the tree, there is a single cluster containing all objects of the dataset.
