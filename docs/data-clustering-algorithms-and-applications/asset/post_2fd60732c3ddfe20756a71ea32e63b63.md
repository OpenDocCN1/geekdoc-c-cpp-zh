## Grid-Based Clustering

## 6.2 The Classical Algorithms

In this section, we introduce three classical grid-based clustering algorithms with their variants: GRIDCLUS, STING, and WaveCluster.

### 6.2.1 Earliest Approaches: GRIDCLUS and BANG

Shikuta [25] introduced the first GRID-based hierarchical clustering algorithm called GRIDCLUS. The algorithm partitions the data space into a grid structure composed of disjoint-dimensional hyper rectangles or blocks. Data points are considered points in $d$-dimensional space and are designated to blocks in the grid structure such that topological populations are maintained. Once the data is assigned to blocks, clustering is done by a neighbor search algorithm. In some respects, GRIDCLUS is the canonical grid-based clustering algorithm and its basic steps coincide with those for grid-based algorithms in Section 6.1. GRIDCLUS inserts points into its grid structure, calculates the resultant of the blocks, stores the blocks to their density, recognizes the most dense blocks as cluster centers, and constructs the rest of clusters using a neighbor search on the blocks.

The grid structure has a scale to partition the $d$-dimensional space and this partitioning is stored in the grid directory. The data blocks contain the data points and there is an upper bound on the number of points per block. The blocks must be nonempty, cover all the data points, and not have any data points in common. Hinrichs offers a more thorough discussion of the grid file used [13].

The density of a block, $B$, is defined as the number of points in the block divided by the spatial volume of the block, i.e.

$$D_B = \frac{P_B}{V_B} \quad (6.1)$$

where $P_B$ is the number of data points in the block $B$ and $V_B$ is the spatial volume of the block, i.e.,

$$V_B = \prod_{i=1}^d e_{Bi}, \quad (6.2)$$

where $d$ is the number of dimensions and $e_{Bi}$ is the extent of the block in the $i$ dimension. GRIDCLUS selects the blocks according to their density and those with the highest density are chosen as the cluster centers. Blocks are clustered in order of decreasing density to generate a sequence of nonempty, disjoint clusters. Starting from cluster centers only neighbors are merged. The neighbor search recursively starting at the cluster center, checking for adjacent blocks that should be added to the cluster, and for only those neighbors added to the cluster, continuing. The GRIDCLUS algorithm is described in Algorithm 23 and the function NEIGHBOR_SEARCH is the recursive procedure in Algorithm 24 [10, 25].

While explicit complexity analysis is given for GRIDCLUS in the original paper, other hierarchical clustering algorithms in the worst case number of blocks in the case is $O(n)$ where $n$ is the number of data points and sorting the blocks is $O(n \log n)$. However, this complexity would still be better than hierarchical clustering. The problem is that step 4 can also require $O(n)$ if all the blocks have different densities and step 7 can also require $O(n)$ if all the blocks have the same density. In addition, while the number of neighbors of any block is a function of the number of dimensions, the depth of the recursive calls to the neighbor search function can also be $O(n)$. This can occur if the blocks are adjacent in a simple plane analogous to a spanning tree that is a straight line. Without any discriminatory density thresholds, the pathological case of step 7 could also apply and the complexity would be $O(n^2)$. (Granted average case complexity for several distributions may be significantly better (i.e., $O(n)) and that may be a better analysis to consider).

#### Algorithm 23 GRIDCLUS Algorithm

```
Algorithm 23 GRIDCLUS Algorithm
1: Set u := 0, W := {}. C := {initialization};
2: Create the grid structure and calculate the block densities;
3: Generate a sorted block sequence B1, B2, ..., Bp; mark all blocks "not active" and "not clustered";
4: while a "not active" block exist
5: u := u + 1;
6: mark first B1, B2, ..., Bp with equal density index "active";
7: for each "not active" block Bp := B1, B2, ..., Bp
8: Create a new set C[u];
9: W[u] ⊄ W[u] + 1.C[u, W[u]] ⊄ Bp;
10: Mark block Bp clustered;
11: NEIGHBOR_SEARCH(Bp, W[u]);
12: end for
13: for each "not active" block B
14: W[u] ⊄ W[u] + 1.C[u, W[u]] ⊄ B;
15: end for
16: Mark all blocks "not clustered";
17: end while
```

#### Algorithm 24 Procedure NEIGHBOR_SEARCH(B,C)

```
Algorithm 24 Procedure NEIGHBOR_SEARCH(B,C)
1: for each "active" and "not clustered" neighbor B' of B
2: C ← B';
3: Mark block B "clustered";
4: NEIGHBOR_SEARCH(B',C);
5: end for
```

The BANG algorithm introduced by Shikuta and Erhart [26] is an extension of the GRIDCLUS algorithm. It addresses some of the inefficiencies of the GRIDCLUS algorithm in terms of grid structure, searching, and managing blocks by their density. BANG also places data points in blocks and uses variants of the grid directory called BANG to maintain blocks. Neighborhood search and processing the blocks in decreasing order of density are determined by the maximum dimensions shared by a common between blocks. A binary tree is used to store the grid structure; that neighbor searching can be done more efficiently. From this the dendrogram is calculated. Centers of clusters are still the most highly blocks in the clustering phase. The BANG algorithm is summarized in Algorithm 25 [10]. While both GRIDCLUS and BANG discern nested clusters efficiently, BANG has been shown to be more efficient than GRIDCLUS on data sets because of significantly reduced growth of grid structure [26].

### 6.2.2 STING and STING+: The Statistical Information Grid Approach

Wang et al. [28] proposed a STAtistical InformationGrid-based method (STING) to cluster spatial databases and facilitate queries. STING divides the spatial area into cells and maintains summary statistics for each cell.

#### Algorithm 25 BANG-Clustering Algorithm

```
Algorithm 25 BANG-Clustering
1: Partition the feature space into rectangular cells which contain up to p_{max} data points.
2: Build a binary tree to maintain the cells, in which node depth corresponds to level.
3: Calculate the dendrogram in which the density of all blocks are calculated.
4: Starting with the highest density index, all regions are identified and classified.
5: Repeat step 4 for the remaining blocks (the tree).
```

STING maintains summary statistics for each cell in its hierarchical tree. As a result, parameters of parent cells can be easily computed from child cells. The distribution types may be normal, uniform, exponential, and none. Value of density may be either assigned by the user or obtained by hypothesis tests such as the $\chi^2$ test. Even though measures of these parameters are bottom-up from leaf node, STING adopts a top-down approach for clustering and querying from the root of its hierarchical tree. The algorithm is summarized in Algorithm 26 [10, 28].

The tree is constructed in $O(N)$, where $N$ is the total number of data points. Cells are identified and clustered by examining the density of these cells in a similar vein to the density-based DBSCAN algorithm [7]. If the cell has $K$ cells, the complexity of spatial querying and clustering for STING is $O(K)$. A common misconception is that $K$ is $O(2^d)$ where $d$ is the number of dimensions and that this would be problematic in high dimensional data. STING may have problems with higher dimensional data than grid-based algorithms (e.g., handling noise and selecting most relevant attributes) [111], but scalability of the STING structure is not one of them.

There are several advantages of STING. First, it is a query-independent approach where the statistics are independent of queries. The computational complexity of STING is $O(K)$, and this is efficient in clustering large data sets when $K \ll N$. The algorithm is readily parallelizable and allows for multiple resolutions for examining the data in its hierarchical grid structure. In incremental data updating is supported, there is lower overhead for incorporating new data.
