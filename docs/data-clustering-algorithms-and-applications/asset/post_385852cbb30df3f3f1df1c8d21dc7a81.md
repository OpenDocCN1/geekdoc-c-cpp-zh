## 11.4.2 DBDC: Density-Based Clustering

DBDC [24] is a density-based distributed clustering algorithm. Density-based clustering aims to discover clusters of arbitrary shape. Each cluster has a density of points which is considerably higher than that of the cluster. Also, the density within the areas of noise is lower than the density in any of the clusters.

DBDC is an exemplary algorithm that follows the general framework given in Section 11.4.1. Initially the data is partitioned over machines. At the local clustering step, each machine performs a carefully designed clustering algorithm to output a set of few representatives with an accurate description of clusters. The representatives are merged in the global clustering using DBSCAN [17], a single-machine density-based clustering algorithm. Then the global clusters are sent back to all client sites which relabel all objects on their site independently of each other.

The experimental results show the advantage of the distributed clustering. The running time of DBDC is more than 30 times faster than the serial clustering counterpart. Moreover, DBDC yields almost the same clustering quality as the serial algorithm.

## 11.4.3 ParMETIS: Graph Partitioning

ParMETIS [31] is a graph partitioning algorithm. Given a vertex and edge weighted graph, k-way graph partitioning partitions the vertices into k subsets so that the weight of the vertices in each subset is roughly the same, and weight of the edges whose incident edges belong to different subsets is small. For example, Figure 11.8 shows an example of 3-way graph partitioning of a graph with 14 vertices. The graph partitioning is essentially a clustering problem where the goal is to find good clusters of vertices.

There have been many works on the graph partitioning. One of the state-of-the-art graph-partitioning algorithms is METIS [30]. ParMETIS is a parallel algorithm of METIS for distributed memory system.

METIS is a multilevel partitioning algorithm. In the first coarsening phase, maximal matching on the original graph is performed. Then, the matched vertices are collapsed together to create a smaller graph. This process is repeated until the number of vertices is small enough. In the second partitioning phase, $k$-way partitioning of the coarsened graph is performed by a multilevel recursive bisection algorithm. In the third uncoarsening phase, the partitioning from the second phase is projected back to the original graph by a greedy refinement algorithm.

ParMETIS performs the three phases of METIS using message-passing systems. ParMETIS does not follow the general framework in Section 11.4.1, since the clustering is mainly based on the coarsening and uncoarsening operations which are graph operations different from clustering operations. Initially each processor receives an equal number of vertices. At the coarsening phase, ParMETIS first computes a cluster of a graph and then projects a global graph incrementally moving vertices of the same color one at a time. At the partitioning phase, the coarsened graph is broadcasted to all the machines. Each machine performs recursive bisection by exploring only a single path of the recursive bisection tree. In the uncoarsening phase, vertices of the same color are merged. Subsets of the vertices that lead to a reduction in the edge-cut are made. When moving vertices, the vertices themselves do not move until the final stage: only the partition number associated with each vertex moves to minimize communication cost.

Experiments were performed on a 128-processor Cray T3 computer with distributed memories. In terms of partition quality, the edge-cut produced by the parallel algorithm is quite close to that produced by the serial algorithm. The running time of the ParMETIS using 128 processors was 14 to 35 times faster than the serial algorithm.

## 11.4.4 PKMeans: K-Means with MapReduce

MapReduce has been used for many clustering algorithms. Here we describe PKMeans [48], a $k$-means [37, 2, 23, 46] clustering algorithm on MapReduce. Given a set of $n$ objects and the number of cluster $k$, the $k$-means clustering algorithm partitions the objects so the objects within a cluster are more similar to each other than the objects in the different clusters. Initially, $k$ objects are randomly selected as the center of clusters. The $k$-means algorithm performs the following two tasks iteratively:

- Step 1. Assign each object to the cluster whose center is the closest to the object.
- Step 2. For each cluster, update the center with the mean of the objects in the cluster.

PKMeans uses MapReduce to distribute the computation of k-means. PKMeans follows the general framework shown in Section 11.4.1. The partitioning is implicitly performed when the data is uploaded to the distributed file system (e.g., DFS or HDFS) of MapReduce. The local clustering, which corresponds to Step 1 above, is performed in the mapper. The global clustering, which corresponds to Step 2 above, is performed in the combiner and the reducer.

The specific data $x_1, \dots, x_n$, which are also $d$-dimensional points, of clusters are given to the mapper in the format of $\{i_j, y_j\}$ by the parameter passing mechanism of Hadoop. The mapper, the combiner, and the reducer are as:

- Mapper: Read the data $x_i$, and find the center $y_j$ which is closest to $x_i$. That is, $j = \text{argmin} ||x_i - y_j||$. Emit $i < j$.
- Combiner: Take $<j, \{y_j\}$ and emit $<j, \sum x_i, \text{num}$ where $\text{num}$ is the number of objects that the combiner received with the key $j$.
- Reducer: Take $<j, \{\sum x_i, \text{num}\}$, and compute the new center. Emit the new center $<j, y_j>$ of the cluster.

The outputs of the reducer are centers of clusters which are fed into the mapper of the next iteration. The combiner greatly decreases the amount of intermediate data by emitting only the sum of the input.

Experimental results show that PKMeans provides good speed, scale up, and size up. The system is evaluated by the rating of running time while keeping the dataset constant and increasing the number of machines in the system. PKMeans shows near-linear speed up. The scale measures whether x-times larger system can perform x-times larger job in the same run-time as the original system. PKMeans provides a good scale up, better than 0.75 for 4 machines. PKMeans has a linear size up: given the number of machines, the running time grows linearly with the data size. Finally, PKMeans is an exact algorithm, and thus the quality of the clustering is the same as that of $k$-means.

## 11.4.5 Co-Clustering with MapReduce

DisCo [42] is a co-clustering algorithm with MapReduce. Given a data matrix, co-clustering groups the rows and columns so that the resulting permuted matrix has concentrated nonzero elements. For example, co-clustering on documents-to-words matrix finds documents as well as groups. For an $n \times m$ matrix, co-clustering outputs the row and column vector $r \in \{1, \dots, k\}^n$ and $c \in \{1, \dots, l\}^m$, respectively, and $k \times l$ matrix $G$ where $k$ and $l$ are the number of desired row and column partitions, respectively. Searching for an optimal cluster is NP-hard [12], and thus co-clustering algorithms perform a local search. In the local search, each row is to be assigned to the best group that gives the minimum cost while the column assignments are fixed. Then in the fashion each column is iterated while the row group assignments are fixed. This process continues until the cost stops decreasing.
