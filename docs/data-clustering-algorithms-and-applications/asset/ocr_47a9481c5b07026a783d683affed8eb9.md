The icons proposed in [9] for data visualization can grow from individual data objects to larger clusters. During the process of cluster growing, the icons get vastly larger. Therefore, the user gets the impression of interacting with clusters.

The principle of growing icons, assigns to all data objects a certain amount of visual space. When a data object is not yet part of any cluster, the visual area is a connected and convex region. The area of the data object is subdivided into many subareas as there are dimensions. The sizes of the subareas are proportional to the data values in the feature vector describing the data object. This assumes that the feature vector consists of quantitative attributes only. The color of each subarea represents the respective dimension. When data objects are grouped together, the visual spaces added up form the icon of the newly built cluster. The subareas of the individual objects are rearranged such that subareas of same color form a connected larger sub. Thus, adding a data object to clusters the subareas fit into the cluster, they are still discernible, the user could click on the cluster and the other subareas of the respective data are highlighted. Beside the relative contributions of the dimensions, the visualization of a cluster icon can also show information about the data distribution within the cluster, e.g., the Kurtosis. Limitations of Icon (i) the number of dimensions is limited by the number of distinct colors and (ii) the number of data objects is limited by the screen resolution.

# 19.2.2 Parallel Coordinates

The difficulty of displaying multidimensional points with more than three dimensions in a single view instead be alleviated by using parallel coordinates [28, 27]. Parallel coordinates display a multidimensional data vector as a set of connected lines (polyline) drawn in a two-dimensional space. The active domain of each dimension of the multidimensional data space is represented by axis. All axes are scaled to the same size and drawn in parallel. Each end of a polyline is placed at one of the parallel axes. The position of it is computed by mapping the numerical value of the data's respective dimensions onto the line of the axis. Thus, the polyline connects the numerical values of that vector mapped onto the parallel axes. An example of a data vector from the Iris data is shown in Figure 19.3.

Clusters would show up in parallel coordinates as clusters that become dense at one or several dimensions, e.g., see Figure 19.3(b). Lines in the original geometric space show up as intersections of many polyline segments in parallel coordinates [27], this technique has been considered to explore correlations in the data [30]. However, parallel coordinates suffer from several types of visual cluster and the ambiguity of the graphical representation in two different cases (nearly) common data value in one of them is not displayed at the border of the visualization.

Several approaches have been suggested to address these problems and especially enhance the visual recognition of clusters in parallel coordinate displays. A general idea is to combine density with parallel coordinates in order to emphasize high density regions in the plot. Clusters in data are closely related to the data space, as cluster centers are often regions of high density. Data density is a function defined on the whole data space that measures how many data vectors are close to a given location in the data space [40, 42]. A simple example of a density function is a histogram. One-dimensional histograms showing marginal distributions of single dimensions have be added to parallel coordinates as bars of different thickness that are centered around the axes [20]. Two-dimensional histograms defined by pairs of consecutive dimensions have been used in [5]. The density of a data projection to a particular pair of consecutive dimensions is mapped to the brightness of the line segment that connects the respective data values.
