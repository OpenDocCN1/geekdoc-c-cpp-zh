Intuitively, vertices sharing a lot of neighbors should belong to the same cluster. To formalize this intuition, a similarity function for pairs of vertices $v$ and $w$, denoted by $sim(v,w)$, is defined as follows on the intersection of their sets of neighbors:

```
$sim(v,w) = \frac{|Gamma(v) \cap \Gamma(w)|}{\sqrt{|Gamma(v)| \cdot |Gamma(w)|}}$
```

where $\Gamma(v)$ denotes the set of all (direct) neighbors of vertex $v$, i.e., $\Gamma(v) = \{w|(v,w) \in E\} \cup \{v\}$. The $\epsilon$-neighbor of a vertex $v$ is given by the set of vertices whose similarity exceeds the threshold of $\epsilon$, i.e.,

```
$N_{\epsilon}(v) = \{w|w \in \Gamma(v) \wedge sim(v,w) \geq \epsilon\}$
```

A vertex $v$ is called a core, if its $\epsilon$-neighborhood has a cardinality of at least $\mu$. Based on these definitions, the concepts of direct structure-reachability, structure-reachability, structure-connectivity, (structure-connected) cluster respect to $\epsilon$ and $\mu$ can be introduced in analogy to the DBSCAN concepts.

If a vertex is not a member of any cluster, it is either a hub or an outlier, depending on whether it has neighbors in at least two clusters, and it is an outlier otherwise, i.e., if all neighbors belong to the same cluster or to none.

The SCAN algorithm is completely analogous to the DBSCAN algorithm. The crucial operation is the retrieval of neighbors of a given vertex, which can be efficiently supported using an adjacency list, a data structure where each vertex is associated with a list of directly neighboring neighbors. With this structure, the cost of a vertex is proportional to the number of neighbors, which is the degree of the vertex. SCAN performs at most one neighborhood query per vertex. The total running time of SCAN is $O(m)$, where $m$ denotes the number of edges, which scales well to large datasets.

SCAN, like other methods of network clustering as graph partitioning and clique finding on graph data only. However, in applications more informative graphs are where features are associated with vertices representing object properties such as demographic attributes of customers and expression data of genes. Often features and edges contain complementary information, i.e., neither the relationships can be derived from the attributes vice-versa.
