## 11.1 Introduction

With the advance of Web2.0, the data size is increasing explosively. For example, Twitter data spans terabytes; Wikipedia data (e.g., articles and authors) is of similar size; web-click data is reported to reach petabyte scale [36]; Yahoo! web graph in 2002 has more than 1 billion nodes and almost 7 billion edges [27].

On the other hand, many data clustering algorithms have a high intrinsic complexity. For example, the classic k-means clustering is NP-hard when k=2. The normalized cut (NCut), a representative spectral clustering algorithm, is also NP-hard [43]. Therefore, a key challenge for data clustering lies in its scalability, that is, how we can speed up/scale the clustering algorithms with the minimum sacrifice to clustering quality.

At the high level, many data clustering algorithms have the following procedure: after some
initialization (e.g., randomly choose the k clusters in k-means), it takes iterative process until convergence criteria is met. In each iteration, it adjusts/updates the cluster membership for each data point (e.g., assign to the closest cluster centers in k-means). Therefore, in order to speed up/scaleup clustering, we have three basic ways: (1) reducing the iteration number (e.g., one-pass algorithm) [47, 22], (2) reducing the access to the data points (e.g., by randomized techniques) [25, 38], and (3) by distributing/parallelizing the computation [28, 13]. In this chapter, we will review representative algorithms for each of these categories.

Notice that another important aspect related to the scalability for the stream data, that is, we can adopt the batch-mode clustering algorithms in the case the data arrives in the stream mode, so that ideally the algorithms scale well with respect to the size of the new arrival data as opposed to that of the entire data set [16, 4, 35]. These issues will be discussed independently in the chapter on density-clustering.

## 11.2 One-Pass Clustering Algorithms

In this section, we will review some early, classic clustering algorithms which are designed for large-scale data sets. CLARANS [39, 40] is one of the earliest algorithms to use randomized search to fight with the exponential search space in the K-medoid clustering. In BIRCH [47], a new data structure clustering feature tree (CF-tree) was proposed to reduce the I/O cost when the input data exceeds the memory size. Finally, CURE [22] uses multiple data points for each cluster to order the irregular shapes and further adds sampling to the hierarchical clustering procedure. Thanks to these techniques, we can often largely reduce the iteration number in clustering procedure. In some extreme cases, they often generate pretty good results by one pass over the input data. We collectively collect these algorithms as one-pass clustering algorithms.

### 11.2.1 CLARANS: Fighting with Exponential Search Space

Let us start with one of the earliest representative algorithms, i.e., Partitioning Around Medoids (PAM) [32]. The basic idea of PAM is to choose one representative point from each cluster (e.g., the most central data point in the cluster). If we want to find k for n data points, the algorithm essentially tries to find the k medoids. Once optimal k-medoid is found, the remaining (nonmedoid) data points are assigned to the selected medoids based on their distance to the k-medoid. This follows an iterative procedure where each iteration, it replaces one of the current medoids by a nonmedoid data point. It is easy to see that the computational cost for PAM is high: first of all, in each iteration, we need to check all the (n-k) × k possible pairs; the overall search space is exponential, we have possible k-medoid assignment. To address this, Clustering Large Applications (CLARA) [32] relies on sampling to reduce the search space. Instead of trying to find the optimal k-medoid from the original entire data set as in PAM, CLARA first takes a sample of k from the original n data points and then calls PAM to find medoid. Once the optimal medoid is found, the remaining (unsampled) data points are assigned to one of these k clusters based on their distance to the k-medoid.

Conceptually, both PAM and CLARA can be regarded as graph-searching problems. In this graph, each node is a possible clustering solution (i.e., a k-medoid), and the nodes are linked to each other if they only differ in 1-out-of-k medoids. PAM starts with one of the randomly chosen

### 11.2.2 BIRCH: Fighting with Limited Memory

When the data exceeds the available memory, the I/O cost may dominate the memory computational time, when (e.g., PAM, CLARA) suffer. Balanced Iterative Reducing and Clustering using Hierarchies (BIRCH) [47] was one of the first methods to address this, and explicitly tries to reduce the I/O costs the given amount of memory.

The key of BIRCH is to introduce a new data structure called *clustering feature* (CF) as well as CF-tree. Therefore, before we present the BIRCH algorithm, let us take a short detour to introduce these concepts.

CF can be regarded as a concise summary of each cluster. This is motivated by the fact that every data point is important for clustering and we cannot afford to keep every data point in the main memory where the overall memory is limited. On the other hand, for purpose of

To be specific, a CF is $<N, LS, SS>$ which contains the number of the data points in the cluster (i.e., the zero-order moment $N$), the linear sum of the data points in the cluster (i.e., the first order moment LS), and the square of the data points in the cluster (i.e., the second order moment SS). It is easy to check that CF satisfies the additive property; that is, if we want to merge two existing clusters, the CF for the merged cluster is simply the sum of the CFs of the two original clusters. This feature is crucial as it allows us to easily merge two existing clusters without accessing the original data set.

CF-tree is a height-balanced tree which tracks of the hierarchical structure for the entire data set. Each node in the CF-tree represents a cluster which is in made up of at most B clusters, where B is the so-balancing factor. All the leaves are chained together for the purpose of efficient scanning. In addition, for each subcluster in the leaf node, diameter is upper-bounded by a second parameter $T$ (the threshold). Apparently, the larger $T$, is, the smaller the CF-tree in tree height. The insertion into CF-tree can be performed in a similar manner as the insertion in the B-tree. Figure 11.2 presents a pictorial illustration of the CF-tree.

There are two main steps in the BIRCH algorithm. First, as it inserts the data points, it builds a CF-tree by inserting with a default threshold $T=0$. By setting the threshold $T=0$, we treat each data point as an individual cluster at the leaf node. Thus, the size of the resulting CFtree may be very large, which might lead to an out-of-memory issue in the middle of the scanning process. If such happens happens, we increase the threshold $T$ and rebuild the CF-tree by reinserting all the leaf nodes from the old CF-tree. By grouping data points together, the resulting CFtree builds an initial summary of the data set which reflects its clustering structure.

Due to the skewed input and/or splitting by the page size, the clustering structure from initial CF-tree might not be accurate enough to reflect the really clustering structure. To address this issue, the second key step (“global clustering”) to cluster all the clusters in the leaf nodes. This is done by converting a subcluster with $n'$ data points $n'$ times at the centroid and then running another agglomerative hierarchical clustering algorithm or modified clustering algorithm.

Between these two main steps, there is an optional step to refine the CF-tree by reinsert its leaf entries (“tree condensation”). Usually, this leads to a much more compact CFtree. After the global clustering step, there is another option (“clustering refinement”), which assigns all the data points to the cluster centroid produced by the global clustering step.
