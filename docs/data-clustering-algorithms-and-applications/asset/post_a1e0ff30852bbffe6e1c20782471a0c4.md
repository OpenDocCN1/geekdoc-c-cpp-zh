## 10.2.2.3 Online Clustering with ClStream

The microclustering phase is the online data collection portion of the algorithm. The aim is to maintain statistics at a sufficiently high level of (temporal and spatial) granularity so that it can be effectively used by the offline components such as horizon-periodic clustering or algorithm analysis. The algorithm works in an iterative fashion, always maintaining a set of microclusters. It is assumed that a total of $q$ microclusters are stored at any moment by the algorithm. We will denote these microclusters by $\mathcal{M}_1...\mathcal{M}_q$. Associated with each microcluster $i$, we create a unique $id$ if first created. If two microclusters are merged (as well) as one a list of $ids$ is created in order to identify the constituent microclusters. The value of $q$ is determined by the amount of memory available in order to store the microclusters. Therefore, typical values of $q$ are significantly larger than the natural number of clusters in the data but are also significantly smaller than the number of data points arriving in a long period of time for a massive data stream. These microclusters represent the current snapshot of clusters which change over the course of the stream as new points arrive. Their status is stored away on disk whenever the clock is divisible by $\alpha^i$ for any integer $i$. At the time $\alpha^r$ units, any microclusters of order $r$ which were stored at a time in the past more than are deleted by the algorithm.

Whenever a new data point $X_i$ arrives, the microclusters are updated to reflect the changes. Each data point needs to be absorbed by a microcluster or into a cluster of its own. The first preference is to absorb the data point into a existing microcluster. The distance of each point to the microcluster centroids $M_1...M_k$ is determined. The distance value of the data point $X_i$ to the centroid of the microcluster $M_j$ is denoted by $dist(M_j, X_i)$. Since the centroid of the microcluster is in the cluster feature vector, this value can be computed relatively easily. This distance is used to compare the distance of the cluster $M_p$ to the data point $X_i$. In many cases, the point $X_i$ does not naturally belong to the cluster $M_p$. These cases are as follows:

- The data point $X_i$ corresponds to an outlier.
- The data point $X_i$ corresponds to the beginning of a new cluster because of evolution of the data stream.

While the two cases cannot be distinguished until more data points arrive, the data point $X_i$ needs to be assigned to microcluster of its own with a unique id. In order to make this decision, the cluster feature vector of $M_p$ is used to decide if this data point falls within the maximum boundary of the microcluster $M_p$. If so, then the data point $X_i$ is added to the microcluster $M_p$ using the CF affinity property. This is defined as a factor of $1/m$ of the RMS deviation of the data points in $M_p$, from the centroid. We define this as the maximum boundary factor. For a cluster with more than one previous point, the maximum boundary is a heuristic value. Specifically, it is chosen to be 3 times that of the closest cluster.

If the data point does not lie within the boundary of the nearest microcluster, a new microcluster will be created and assigned a new id which can identify it at any future stage of the data stream process. However, in order to create this microcluster, the number of other clusters must be reduced by one in order to delete an old cluster or joining two of the old clusters. Our management algorithm first determines if it is safe to delete the outliers. If not, any of the microclusters are possibly outliers which can be deleted by the algorithm. While it might be simply picking the microcluster with the fewest number of points as the microcluster to be deleted, this may often lead to misleading results.

In cases, a given microcluster might correspond to a point of considerable past in the history of the stream, but may no longer be an active cluster in the current view of point. An ideal goal would be to estimate the average timestamp of the $m$ lists in each cluster and delete the microcluster with the least recent timestamp. While this is possible, the overhead of maintaining timestamps for every microcluster might be prohibitive. Instead, one can use the timestamp of the last point added to the microcluster as a proxy for its age.

## 10.3 Density-Based Clustering

Density-based methods [18, 30] construct a density profile of the data for clustering purposes. Typically, kernel density estimation methods [58] are used in order to construct a smooth density of the underlying data. Subsequently, the data are separated into density-connected regions. These density connected regions may be of different shapes and sizes. One of the advantages of density-based algorithms is that an implicit shape is not assumed for the clusters. For example, when Euclidean distance functions are used, it is always assumed that the clusters are spherical shapes. Another aspect of density-based clustering is that it does not preclude the number of clusters. Rather, a threshold on the density is used in order to determine the connected regions. Of course, this changes the nature of the parameter which needs to be presented to the algorithm (density threshold instead of number of clusters), but it does not necessarily make the approach parameter-free.

The main challenge in the stream scenario is to construct density-based algorithms which can be efficiently executed in a single pass of the data, since the process of density estimation may be computationally intensive. There are two classes of techniques:
