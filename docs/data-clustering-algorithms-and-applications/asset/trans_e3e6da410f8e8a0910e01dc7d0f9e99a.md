[48] 中的方法通过修改词 $w$ 和簇 $C_j$ 的软 $p(w|C_j)$ 来工作。概率 $p(w|C_j)$ 被建模为两个因素的线性组合：（a）最大似然模型，该模型计算为每个簇生成特定词的概率，以及（b）间接（翻译）词成员概率，该概率首先确定每个签名的最大似然概率，然后乘以给定主题签名的每个词的条件概率。我们注意到，我们可以使用 $p(w|C_j)$ 来估计 $p(d|C_j)$，方法是使用文档中的构成词。为此，我们使用文档 $d$ 中词 $w$ 的频率 $f(w,d)$：

```
$p(d|C_j) = \prod_{w\in d} p(w|C_j)^{f(w,d)}$
$$(10.10)$$
```

我们注意到，在静态情况下，为了提高估计过程的鲁棒性，还可以添加一个背景簇。然而，在数据流中这是不可能的，因为背景集合模型可能需要在构建时进行多次遍历。[48] 中的工作以在线方式保持这些属性，使用利用衰减函数的属性的簇概要。我们注意到簇概要类似于 [12] 中引入的凝聚液滴的概念。关键算法 OCTS 是维护一个动态的簇集合，文档通过相似性计算逐步分配到其中。在 [48] 中已展示如何有效地使用簇概要来计算每个传入文档的 $p(d|C_j)$。该值随后用于确定与不同簇的相似性，并将文档分配到其最接近的簇。我们注意到 [12, 中的方法在以下方面共享许多相似之处：（a）维护簇概要，（b）使用簇概要（或凝聚液滴）来计算相似性并将文档分配到最相似的簇，以及（c）用于决定何时应创建新的单例簇或替换较旧簇的规则。

两种算法之间的主要区别是用于计算簇相似性的技术。OCTS 算法使用概率计算 $p(d|C_j)$ 来计算簇相似性，该计算在计算过程中考虑了相位信息。关于 OCTS 的一个观察是，它可能允许当前集合中存在非常相似的簇。这减少了不同簇的空间。 [48] 中还提出了一种第二算法 OCTM，该算法允许合并非常相似的簇。在每次分配之前，它会检查是否可以基于相似性合并成对的相似簇。如果可以，则允许合并簇及其对应的簇概要。 [48] 中给出了不同聚类算法及其有效性的详细实验结果。文本聚类算法的全面综述可在 [15] 中关于数据聚类和流算法的章节中找到。

## 10.8 流聚类的其他场景

数据流聚类是一个基本问题，其他领域也出现，其中数据自然以流式上下文出现。本节中，我们对这些不同的数据域进行了简要介绍，并提供了指向相关文献的指针。

# 流聚类算法综述

### 10.8.1 聚类不确定数据流

不确定数据通常出现在传感器数据或 RFID 等其他硬件技术的上下文中，当数据收集过程中存在显著错误时。在许多情况下，数据中的错误可以用统计参数（如标准差）或概率密度函数（pdf）来近似。统计信息增加了噪声数据的丰富性，并提供了关于数据中哪些部分不太可靠的信息，因此应在挖掘过程中予以强调。

在此上下文中，[13] 中提出了一种称为 UMicro 的方法，用于聚类不确定数据流。该方法用关于簇中数据点的不确定性的额外信息增强微簇。这些信息用于提高分配的距离函数的质量。该方法已进一步改进，用于不确定数据流的投影聚类 [4, 60]。我们没有提供这些方法的详细讨论，这些方法将在本章关于不确定数据聚类部分中讨论。

### 10.8.2 聚类图流

图流由众多社交和信息网络中的边中心活动创建。根据应用场景，可能存在许多不同的流式和聚类模型。这些不同的模型如下：

- 流是对象的序列，每个对象都是包含节点和边的子集的小图。我们希望通过节点和边之间的相似性来确定流中相似的对象。例如，DBLP  bibliographic 网络有一个由作者论文对应的图组成的传入流。可能希望确定具有相似结构的对象簇。一种用于此问题的算法，被称为 Gmicro，提出在 [14] 中。微聚类表示被扩展以处理边，并在边上使用草图压缩以减少边巨大密度的影響。

- 流是对象的序列，每个对象都是包含节点和边的子集的小图。我们希望确定在这些对象中频繁共同出现并且彼此紧密连接的节点集。 [8] 中提出了一种方法，使用 minhash 图流汇总。

- 流是对象或边的序列。希望在图中确定密集节点簇。

该问题特别通用，也与动态社区检测问题相关。在此上下文中，提出了一种方法，用于使用边流的结构化 reservoir 采样创建图的动态模式 [16]。 [19] 中的工作旨在检测异常，过程中的关键步骤是从边流动态生成节点簇。 [28] 中的工作进一步完善了 [16] 的结构化 reservoir 采样技术，以便为图流中的节点聚类提供更有效的方法。

在许多情况下，例如社交网络，结构信息与网络中的内容信息相关联。例如，Twitter 流中的推文同时具有结构和内容。这些被称为社交流。此类流的聚类需要同时使用结构信息和文本中的内容。 [9] 中的工作设计了用于聚类社交流的方法。基于草图的方法用于汇总社交流中的内容并将其用于聚类过程。此外，在 [9] 中已展示如何将此方法用于事件检测。

在传统的流式模型中，假设只能对数据进行一次遍历，并且可用于应用程序的内存量是恒定的，与流长度无关。

一种用于确定最密集子图的技术已在 [19] 中提出，采用弱流式模型，其中允许对数据进行有限次数的遍历（多于一次），并且可用内存量在输入大小上是次线性的。这种方法能够在随图大小对数增长的图上确定最密集子图。

### 10.8.3 数据流的分布式聚类

在传感器网络的上下文中，数据流仅在分布式设置中可用，其中大量数据在不同传感器处分别收集。聚类数据的自然方法是传输所有数据到中央服务器。然后可以在中央服务器上执行聚类以确定最终结果。不幸的是，由于必须传输到中央服务器的大量数据，这种方法在通信成本方面极其昂贵。因此，设计一种可以降低不同处理器之间通信成本的方法非常重要。 [27] 中提出了一种方法，在每个节点进行局部聚类并以低通信成本将这些簇合并为单一聚类。该工作中提出了两种方法。第一种方法通过在站点当前数据点集上使用最远点算法来确定簇。在最远点算法之后，簇的中心是离中心集合最近的点。对于任何传入数据，只要距离在最优计算半径的某个因子范围内，就将其分配到其簇。否则，通过在当前点集上应用最远点算法来执行重新聚类。在应用最远点算法之后，中心被传输到中央服务器，然后从不同节点的这些局部中心计算全局聚类。如果需要，全局簇可以传输回本地节点。该方法的一个吸引人的特点是提出了对聚类质量的近似界。第二种分布式聚类方法在 [27] 中提出的是并行猜测算法。

还提出了多种用于数据流分布式聚类的方法。例如，使用 k-means 方法进行分布式数据聚类的技术在 [61] 中提出。另一种分布式流聚类方法通过维护在线离散化来降低维度和通信成本，可在 [57] 中找到。最后，使用 EM 方法进行数据流分布式聚类的方法在 [66] 中提出。

## 10.9 讨论与结论

聚类问题对于各种流式应用是基本的，因为它自然适用于以非常小的空间总结和表示数据。文献中提出了多种流聚类技术，例如划分方法、基于密度的方法和概率方法。流聚类方法还已扩展到其他数据域，例如分类、文本和不确定数据。最后，还提出了用于聚类图流的方法。

该问题很可能还有许多进一步的研究方向。这些如下：

- 异构数据流变得极其常见，因为社交网络等应用中，随着时间的推移发布了大量异构内容。希望确定这些异构对象组之间的簇。

- 希望使用链接和内容的组合来确定簇
