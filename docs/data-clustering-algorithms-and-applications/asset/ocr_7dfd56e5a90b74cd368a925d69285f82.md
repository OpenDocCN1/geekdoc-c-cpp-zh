We believe that these techniques may not achieve the goal of feature selection since the initial clusters may not be the real ones or even close. If those clusters are claimed to be real ones, why doing feature selection at all? Other methods apply the same process in an iterative manner using an EM-like approach. This means we use the feature selection method on the whole dataset and then use the selected features to construct the clusters. If we are not satisfied with the clustering quality, we may use this as an indicator that this set of features is not satisfactory. This is exactly the wrapper approach.

# 2.3.2 Model Selection: K and l

Selecting the clusters K or the number of selected features l is an open problem. In real-worlds, we have limited knowledge about each domain. Consequently, determining optimal K or l is almost impossible. Although this problem seems not to be a big issue with some approaches (such as fixed term-based feature selection methods), we still need to determine other sensitive parameters such as clustering. Choosing different l for the same problem usually results in equally good subsets of features and hence, different clustering results. Similarly, choosing different K leads to merging different clusters into one or splitting into smaller ones. In other cases, this may change the set of selected features which results in losing potential and constructing less important ones. Therefore, picking nearly optimal parameters is desirable for better clustering quality. Some work has done to quantify these parameters. For instance, [10] uses the notion of false neighbor below to find the number of selected features for clustering. On the other hand, [67] uses statistics to estimate the number of clusters in a dataset. However, the effort in building parameters for clustering is still limited. We believe it is necessary to pay more attention to these parameters for better clustering results.

# 2.3.3 Scalability

With the tremendous growth of dataset sizes, the scalability of current algorithms may be in jeopardy, especially with those that require online clustering. For example, streaming data or data that cannot be loaded into the memory require a single data scan the second pass is unavailable or very expensive. Using feature selection methods for clustering may reduce the issue of scalability. However, some of the current methods that feature selection in the clustering process require full dimensionality in memory to observe any evolving in the cluster structure. If a change in data structure is observed, the clustering process should be restarted. Furthermore, other methods require an iterative process where each sample is visited more than once until convergence.

On the other hand, the scalability of feature selection algorithms is a big problem. Usually, they require a sufficient number of samples to obtain, statistically, good results. It is very hard to observe a feature relevance without considering the density around each sample. Some methods try to overcome this issue by memorizing only samples that are important or a summary, the mean of each cluster. In conclusion, we believe that the scalability of clustering and feature selection methods should be given more attention to keep pace with the growth and fast streaming data of the data.
