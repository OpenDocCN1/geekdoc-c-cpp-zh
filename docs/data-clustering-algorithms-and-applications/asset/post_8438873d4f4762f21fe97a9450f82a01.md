## 18.5.2 The LuMicro Algorithm

A variation of the UMicro algorithm has been discussed in [55], which incorporates the concept of tuple uncertainty into the clustering process. The primary idea in this approach is that the instance uncertainty of a cluster is quite important, in addition to the expected distances of assignment. If $T$ is the set of possible probabilistic instances of a tuple, then the instance uncertainty $U(T)$ is defined as:

```
$U(T) = \sum_{x \in T} p(x) \log(p(x)) \quad (18.14)$
```

We note that the value of $U(T)$ is somewhat akin to the concept of entropy, which is at least 0, and takes the value of 0 for deterministic data. This concept can also be generalized to a cluster (rather than a single tuple) by aggregating all possible probabilistic instances into the computation. As more points are added to the cluster, the tuple uncertainty increases, because the data cluster tends to be biased towards a few common tuples. Intuitively, this is also equivalent to a reduction in entropy. The LuMicro algorithm implements a similar approach as the UMicro method of assigning points to their closest clusters (based on expected distance), except that the distance computation is only to narrow down to a smaller set of candidate centroids. The final decision on cluster assignment is performed by determining the cluster to which the addition of the data point would result the greatest reduction in uncertainty (or entropy). Intuitively, this can be considered an algorithm that incorporates distance-and probabilistic entropy concepts into the clustering process. Unlike the UMicro algorithm, the LuMicro works with the full probability distribution functions of the underlying records, rather than only the error values because the computation of the uncertainty requires knowledge of the full probability distribution of the tuples.

## 18.5.3 Enhancements to Stream Clustering

The method for clustering uncertain streams can be further enhanced in several ways:

- In many applications, it is desirable to examine the clusters over a specific time horizon rather than the entire history of the stream. To achieve this, a pyramidal time frame [6] can be used for stream classification. In this time frame, snapshots are stored in different orders depending upon the level of recency. This can be used to retrieve clusters over a particular horizon with very high accuracy.
- In some cases, the behavior of the stream may evolve over time. In such cases, it is useful to apply a decay-weighted approach. In the decay-weighted approach, each point in the stream is weighted by a factor that decays over time. Such an approach can be useful in a number of scenarios in which the behavior of the data stream changes considerably over time. In order to use the decay-weighted approach, the key modification is to define the microclusters with a weighted sum of the data points, as opposed to the explicit sums. It can be shown that such an approach can be achieved with a lazy-update method in order to effectively maintain the microclusters.

## 18.6 Clustering Data in High Dimensionality

Recently, this method has also been extended to the case of projected and subspace clustering of high-dimensional uncertain data [32, 4]. The high-dimensional scenario suffers from data sparsity, which makes it particularly susceptible to noise. The addition of uncertainty typically increases the noise and reduces the differences among dimensions. This magnifies the dimensionality sparsity issue and makes the problem even more challenging.

In the case of the standard clustering problem, the main effect of uncertainty is the impact on the data computations. In the uncertain case, the uncertainty affects the choice of dimensions to be picked. The reason for this is that different dimensions in the data can have very different levels of uncertainty. Clearly, the level of uncertainty in a given dimension is critical information in characterizing the clustering behavior along a particular dimension. This is particularly important for the high dimensional case in which a large number of dimensions may be available with varying clustering behavior and uncertainty. The interplay between the clustering process and the level of uncertainty may affect the subspaces which are most optimal for the clustering process. In some cases, if the data is not used in the mining process, this may result in a clustering that not truly reflect the underlying behavior.

## 18.6.1 Subspace Clustering of Uncertain Data

A subspace clustering algorithm for uncertain data was proposed in [32]. The algorithm uses a grid-based method, which attempts to search on the space of medoids and subspaces for the clustering process. In the grid-based approach, the support is counted with w on the relevant medoid we measure a distance w from the medoid along each of the relevant dimensions. The support of the hypercubes of this grid provide us with the idea of the dense subspaces. For the other dimensions, unlimited width is used by a Monte-Carlo sampling approach is used in order to search on the space of possible medoids. The core unit of the algorithm is a Monte-Carlo sampling approach, which generates a single good cluster from the data.

In order to achieve this, a total of numMedoids are sampled from the underlying data. For each medoid, the best possible local subspace is identified, and the best medoid (associated subspace cluster) among all the numMedoids different possibilities is identified. In order to generate the local subspaces, a larger support parameter minSup is used. For all subspaces (corresponding to grid width w), which support at least minSup, the quality of the corresponding subspace is determined. The quality of a local subspace cluster is related to the support in order to account for the number of dimensions in the different subspaces. If this quality is the best encountered so far, then we update the best medoid (and subspace) encountered so far. The quality function for a medoid m and subspace S is related to the support as follows:

> $quality(m, S) = support(m, S) * 1/\beta^S$

Here $\beta$ (0,1) normalizes for the number of dimensions in the different subspaces. The idea is that a subspace with a larger number of dimensions, but with the same support, is considered to be of better quality. A number different methods can be used in order to compute the support of a subset S of dimensions:

- Expectation-Based Support: In this case, the support is defined as the number of data points, whose centroids lie within a distance w of the medoid along the relevant dimensions. Essentially, this method for support computation is similar to the deterministic case of replacing uncertain objects with their centroids.
- Minimal Probability-Based Support: In this case, the support is defined as the number of data points that have a minimum probability of being within a distance of w from the medoid along each of the relevant dimensions.
- Exact Probability-Based Support: This computes the sum of the probabilities that the different objects lie within a distance of w along each of the relevant dimensions. This value is actually equal to the expected number of objects which lie within a distance of w along of the relevant dimensions.
