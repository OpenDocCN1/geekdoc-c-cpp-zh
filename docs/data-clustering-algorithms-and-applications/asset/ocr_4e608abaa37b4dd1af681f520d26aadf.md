Let $C_1,\dots,C_k$ be the clusters of the database $D$ with respect to $E_{eps}$ and $MinPts$. Then the noise is defined as the set of points in $D$ not belonging to any cluster $C_i$,; $noise = \{p \in D |\, p \notin C_i\forall i\}$. Density-based clustering distinguishes three different types of points (see Figure 5.2):

+   - core points, i.e., points with a dense neighborhood $(|NE_{eps}(p)|\geq MinPts)$,

+   - border points, i.e., points that belong to a cluster, but whose neighborhood is not dense, and

+   - noise points, i.e., points which do not belong to any cluster.

In Figure 5.2, e.g., $p$ and $a$ and $c$ are border points. Density-based clusters have two properties that allow their efficient computation. Let $p$ be a point in $D$. Consider the $O$ of all points drawn from $D$, which are density-reachable from $p$ with respect to $E_{eps}$ and $MinPts$. This set $O$ is a cluster with respect to $E_{eps}$ and $MinPts$. Let $C$ be a cluster in $D$. Each point in $C$ is density-reachable from any of the points of $C$ and,; therefore, a cluster $C$ contains exactly the points which are density-reachable from any arbitrary cluster of point $C$. Thus, a cluster is uniquely determined by any of its core points. The algorithm starts with the DBSCAN.

To find a cluster, DBSCAN starts with an arbitrary database point $p$ and retrieves all points density-reachable from $p$ with respect to $E_{eps}$ and $MinPts$, performing repeat queries for $p$ if $p$ has neighbors. If $p$ is a core point, this procedure yields a cluster with respect to $E_{eps}$ and $MinPts$. If $p$ is not a core point, it is density-reachable from $p$ and the noise applies the same procedure to the next database point. If $p$ is actually a border point of cluster $C$, it will be reached or will be (re-assigned) density-reachable from some core point of $C$ and then; The algorithm terminates when all points are assigned to a cluster or to noise.

Standard DBSCAN implementations are based on a spatial index such as an R-tree [14] or X-tree [4], which provide sufficient support of region queries that retrieve the density-neighborhood of a point. In the worst case, DBSCAN performs one region query per database point. This leads to a runtime complexity of O(nlogn) where n is the number of points in database. Unfortunately, spatial indexes degenerate for high-dimensional data, i.e., the performance of query degenerates from $O(n\log n)$ to $O(n)$, and the runtime complexity of DBSCAN becomes $O(n^2)$ for such data. However, if a grid-based data structure supports O(1) query, the runtime complexity of DBSCAN decreases to O(n). This is considered for large datasets. An incremental version of DBSCAN can improve its efficiency in dynamic databases with insertions and deletions. [10] without having to run the DBSCAN algorithm on the updated database. It examines whether an existing cluster is updated by an update of the database and presents algorithms for incremental updates after insertions and deletions. Due to the local nature of density-based clusters, the portion of affected database objects tends to be small which makes the incremental algorithm very efficient.

The basic idea of density-based clusters can be generalized in several ways [30]. First, any notion of a neighborhood can be employed as a distance-based $E_{eps}$-neighborhood which is symmetric and reflexive. The neighborhood $N$ of $p$ is defined as the set of all points $q$ satisfying $NPred(p,q)$. Second, instead of counting the elements in the neighborhood we can use a more general density $MinWeight(N)$ to determine whether the neighborhood $N$ is dense, if $MinWeight$ is monotone in $N$, i.e., if $MinWeight$ is satisfied for all supersets of sets that satisfy F.
