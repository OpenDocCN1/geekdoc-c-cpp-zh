- For each row (or column), finding the best assignment requires only $r$, $c$, and $G$. It does not require other rows.

Exploiting the above characteristics, $G$, $r$, and $c$ are cast to mappers via parameter passing mechanism of MapReduce. Each row (or column) can be independently processed to be assigned to the best group that minimizes the cost. Each row (or column) iteration requires a map and a reduce stage, and it follows the general framework shown in Section 11.4.1. The mapper reads each row and performs local clustering. The reducer performs global clustering by gathering local information and outputs the updated $G$ matrix and $r$ row-label vector ($c$ column-label vector for the column iteration). DisCo minimizes network traffic by transferring only the label vectors and the $G$ matrix between the mapper and the reducer; the matrix data are not transferred.

Experiments were performed on a 39-node Hadoop cluster on matrix data up to 2.5 million by 1.3 million. The performance, measured by the aggregated throughput, increased linearly with the number of machines. The quality of DisCo is the same as that of the serial algorithm since DisCo is an exact algorithm.

## 11.4.6 BoW: Subspace Clustering with MapReduce

BoW [7] is a distributed subspace clustering algorithm on MapReduce. BoW provides subspace clustering algorithms on MapReduce: Parallel Clustering (ParC) and Sample-Ignore (SnI). ParC has three steps as illustrated in Figure 11.9: (1) partition the input data using mappers so that the data are aggregated to a reducer, (2) reducer finds clusters in their assigned partitions using any subspace clustering algorithm (e.g., [8] as a plug-in), and (3) merge the clusters from the previous step to get final clusters. Steps (1) and (3) are performed in a map and reduce stage, respectively, and step (3) is done serially in a machine.

ParC and SnI also have their own pros and cons. In terms of the number of disk I/Os, ParC is better since it requires only map-and-reduce step while SnI uses two map-and-reduce steps. However, in terms of the network traffic SnI is better in the first phase and the fourth phase in filtering in the second phase.

The question is which algorithm runs faster? There are many parameters to answer the question: e.g., number of reducers used, data size, disk speed, network speed, start-up cost, the plug-in algorithm cost, cost of data transferred in the shuffling stage, and the sampling rate. BoW derives the cost (running time) as a function of the parameters to determine the algorithm that gives the minimum running time.

Experimental results show that BoW correctly chooses the best algorithm for different numbers of reducers. BoW also shows linear scalability on the data size. Finally, we note that ParC and

SnI are not exact algorithms due to the clustering on the divided data. However, the quality of the clustering from either ParC or SnI is comparable to the serial version of the algorithm.

## 11.5 Conclusion

Given that (1) data size grows explosively and (2) the intrinsic complexity of a clustering algorithm is often high (e.g., NP-hard), the scalability seems to be a “never-ending” challenge in clustering. In this chapter, we have briefly reviewed three techniques to speed up/scale a data clustering algorithm, including (a) “one-pass” to reduce the iteration number in clustering procedure, (b) randomized techniques to reduce the complexity of the input data size, and (c) distributed and parallel algorithms to speed up/scale the computation. A future trend is to integrate all these available techniques to achieve better scalability.
