## 10.6.3 Massive-Domain Clustering

Massive-domains are those data domains in which the number of possible values for one or more attributes are very large. Examples of such domains are as follows:

- *Network applications, many attributes such as IP-addresses are drawn over millions of possibilities. In a multidimensional application, this problem is further magnified because of the multiplication of possibilities over different attributes.
- *Typical credit-card transactions are drawn from a universe of millions of different possibilities depending upon the nature of the transactions.
- *Supermarket transactions are often drawn from a universe of millions of possibilities. In such cases, the determination of patterns which indicate different kinds of classification behavior may become infeasible from a space-computational-efficiency perspective.

The massive size of the underlying data restricts the computational approach which may be used for discriminatory analysis. This problem is significantly more difficult than the standard clustering in data streams. Space-efficiency is a special concern in the case of data streams, because it is desirable to hold most of the data structures in memory in order to maximize the processing rate of the underlying data. Smaller space requirements ensure that it may be possible to hold most of the data in caches, which can further improve the efficiency of the approach. Furthermore, it may be desirable to implement clustering algorithms in a wide variety of space-constrained architectures such as mobile devices, sensor hardware, or cell processors. Such architectures present special challenges to the massive-domain case if the underlyings are not space-efficient.

The problem of clustering can be extremely challenging from a space and time perspective in the massive-domain case. This is because one needs to retain the discriminatory characteristics of the most relevant clusters in the data. In the massive-domain case, this may entail storing the frequency statistics of a large number of possible attribute values. While this may be difficult to implement, the problem is further hindered by the large volume of data stream which prevents easy determination of importance of attribute-values. The work in [2] proposes a sketch-based approach in order to keep track of the intermediate statistics of the underlying clusters. These statistics are used to make approximate determinations of the assignment of data to clusters. A number of probabilistic results are provided in [2], which indicate that these approximations are sufficiently accurate to provide similar results to an infinite-space clustering algorithm.

The data stream $\mathcal{D}$ contains $d$-dimensional records denoted by $\mathbf{X}_1, \dots, \mathbf{X}_N$. The attributes of $\mathbf{X}_i$ are denoted by $(x_i^1, \dots, x_i^d)$. It is assumed that the attribute value $x_i^k$ is drawn from the ordered set $J_k = \{v_1^k, \dots, v_{M^k}^k\}$. The value of $M^k$ denotes the domain size for the $k$-th attribute. The value of $M$ can be very large and range in the order of millions or billions. From the perspective of a clustering application, this creates a number of challenges, since it is no longer possible to hold the cluster statistics in a space-limited scenario.

The work in [2] uses the count-min sketch [26] for the problem of clustering massive-domain data streams. In the count-min stream, a hashing approach is utilized in order to keep track of the attribute-value statistics in the underlying data. We use $w = \lfloor\ln(1)/\delta\rceil$ independent hash functions, of which each maps onto the range $h = [0,e/\epsilon]$, where $e$ is the base of the natural logarithm. The data structure consists of a 2-dimensional array with $w-h$ cells with a length of $h$ and width of $w$. Each hash function corresponds to one of $w$ 1-dimensional arrays with $h$ cells. In standard applications of the count-min sketch, hash is used to update the counts of the different cells in this 2-dimensional data structure. For example, consider a l-dimensional data stream with elements drawn from a massive set of domain values. When a new element of the data stream is received, we apply each of the $w$ hash functions to map it onto a number in $[0..h-1]$. The count of each set of $w$ cells is increased by 1. In order to estimate the count of an item, we determine the set of $w$ cells where each of the $w$ hash-functions maps it and compute the minimum value among all cells. Let $c_i$ be the true value of the count being estimated. We estimated that the count is at least $c_i$, since we are dealing with nonnegative counts, and it turns out, a probabilistic upper bound to be the overestimation due to hash collisions. It has been shown in [26], that for a data stream with $T$ arrivals, the estimate is at most $c_i + \epsilon T$ with probability at least $1-\delta$.

Algorithm (10.1) uses number of clusters $k$ and data stream $\mathcal{D}$ as input to the algorithm. The clustering is partitioned based and assigning points to the most similar cluster centroid. The frequency counts for the different attributes in the cluster centroids are initialized with the use of sketch table. These frequency counts can be maintained approximately because of the massive size of the underlying attributes in the data stream. Similarity is measured with the computation of the dot-product function between the incoming point and the centroid of the different clusters. This computation can be performed only approximately in the massive-domain case, since the frequency counts for the values in the different dimensions cannot be maintained exactly. For each cluster, we maintain the frequency sketches of the records which are assigned to it. For each cluster, the algorithm maintains a separate sketch table containing the counts of the values in the incoming records. The same hash function is used for each table. The algorithm starts by initializing the counts in each sketch table to 0.

Subsequently, for each incoming record, we will update the counts of the cluster-specific hash tables. In order to determine the assignments of data points to clusters, the d-dimensional records to the frequency statistics of the values in the different clusters are computed. It is not possible to do it all precisely, since the frequency statistics are not maintained. Let $q_j(x^j)$ be the frequency of the value $x^j$ in the $j$th cluster. Let $m_j$ be the number of data points assigned to the $j$th cluster, the d-dimensional statistics of the record $(x^1, \dots, x^d)$ are used. The dot product $D_j$ between the record $\mathbf{X}$ and the $j$th cluster centroid is:

```
$D_j = \sum_{r=1}^d \frac{q_j(x^r)}{m_j}$
```

The incoming record is assigned to the cluster for which $D_j$ is the largest. There are two key steps which use the sketch table during the clustering process:

- Updating the sketch table and other required statistics for each incoming record.
- Comparing the similarity of the incoming record to the different clusters.
