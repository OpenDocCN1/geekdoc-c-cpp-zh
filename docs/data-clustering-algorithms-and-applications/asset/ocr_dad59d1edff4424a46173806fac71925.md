The data clustering algorithm proposed in [5] can generate approximate clusters in user-specified length of history from the current instance. This is achieved by storing the microclusters at particular moments in the stream which are referred to as *snapshots*. At the same time, the current snapshot of microclusters is maintained by the algorithm. Consider for example, the case when the current time is $t_i$ and the user wishes to find clusters in the stream based on a history of length $h$. the macroclustering algorithm will use some of the additive properties of the microclusters stored at snapshots $t_i$, and $(t_i - h)$ in order to find the higher clusters in a history since it is not possible to choose particular instances of time at every moment, it is important to note that it is possible to store the state of the microclusters so that clusters in any specified time horizon $(t_i - h)$ can be approximated. This has been achieved in [5] with the use of the concept of a pyramidal frame.

# 10.0.2.2 Pyramid Time Frame

In this technique, the snapshots are stored at different levels of granularity depending upon the recency. Snapshots are classified into different orders which can range from 1 to log(T), where T is the clock time elapsed since the beginning of the stream. The order of a particular class of snapshots defines the level of granularity in the time at which the snapshots are maintained. Snapshots of different order are maintained as follows:

+   - Snapshots of the i-th order occur at times of $\alpha'$, where $\alpha$ is an integer and $\alpha \ge 1$. Specifically, each snapshot of the $i$-th order is taken at a moment when the current clock is exactly divisible by $\alpha'$.
- At any given moment, only the last $\alpha' + 1$ snapshots of order $i$ are stored.

The above definition allows for considerable redundancy in storage of snapshots. For example, the clock time of 8 is divisible by $2^0$, $2^1$, $2^2$, and $2^3$ (where $\alpha = 2$). Therefore, the state of the microclusters at a clock time of 8 corresponds to order 0, 1, 2, and 3 snapshots. From an implementation point of view, a snapshot needs to be maintained only once. The following observations are true:

+   - For a data stream, the maximum order of any snapshot at T units since the beginning of the stream mining process is $log_{\alpha}(T)$.
- For a data stream the maximum number of snapshots maintained at $T$ time units since the beginning of the stream mining process is $(\alpha' + 1) \cdot log_{\alpha}(T)$.

+   - For any specified time window of $h$, at least one snapshot can be found within $(1+1/\alpha^{l-1})$ units of the current time.

While the first two results are quite easy to see, the last needs to be formally proven [5]. We summarize this result as:

**Lemma 10.0.2.2** Let $h$ be a user-specified time horizon, $t_c$ be the current time, and $t_s$ be the time of the last stored snapshot of any order just before the time $t_c - t_s \le (1+1/\alpha^{l-1}) \cdot h$.
