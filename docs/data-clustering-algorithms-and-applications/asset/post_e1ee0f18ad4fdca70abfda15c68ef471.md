The dense regions are generated by connecting together the dense microclusters which satisfy a condition on connectivity similar to that in [30].
- The second class of techniques divides the data space into grids and then determines the dense grids. The regions in the data are reconstructed by piecing together the connected dense grids.

### 10.3.1 DenStream: Density-Based Microclustering

The DenStream algorithm [24] approach combines microclustering with a density-estimation approach for effective clustering. The first step is to define a core object, which is defined as an object, in the $\varepsilon$-neighborhood of which the weight of the data points is at least $\mu$. A density area is defined as the union of the $\varepsilon$ neighbors of the core objects. 

In the context of dense stream, it is difficult to define these dense regions naturally. Therefore, dense regions of smaller granularity are defined in the form of microclusters. A microcluster is defined as a set of data points with weight at least $\mu$ and for which the radius of the microcluster about its center is less than $\varepsilon$. We note that the weight of a data point is based on a decayed weighted function of the time that it lasted. Therefore, if $f(\delta t)$ is the time since a data point arrived, its weight is given by:

$$f(\delta t) = 2^{-\delta t}$$

Since the radius of the microcluster is constrained to be less than $\varepsilon$, it implies that the number of microclusters is much larger than the number of natural clusters in the data for small values of $\varepsilon$. At the same time, the number of core clusters contains a weight of at least $\mu$. We note that the key difference from the standard microclustering definition is that the number of microclusters is not constrained, though the radius of each microcluster is constrained. Thus, this approach uses a different parameter to the underlying application. The microcluster is also referred to as a c-microcluster.

One immediate observation is that when microcluster is first formed by any algorithm, it is unlikely to quantify the weight of data points required to be defined as a microcluster. Therefore, the concepts of potential core microcluster and outlier microcluster are defined in [24]. In the former case, the microcluster contains a weight of at least $\beta-\mu$ (for some $\beta \in (0,1)$), and in the latter case, it contains a weight less than $\beta-\mu$. Furthermore, the weights of decay points over time, also change from being a $p$-microcluster to an $o$-microcluster, if sufficient data points are not added to it to compensate for the decay. Thus, during its lifecycle, a microcluster may move from being an outlier microcluster to becoming a potential core microcluster, and finally to the state of being a core microcluster. These two kinds of microclusters are referred to as $p$-microclusters and $o$-microclusters respectively.

When a new data point arrives, the following can be the possibilities in what is done with it:

- If the first step is to insert it into a $p$-microcluster, as long as it is possible to do so, without violating the radius constraint.
- If the first step is not possible, the next step is to insert it into an $o$-microcluster, as long as this can be done without violating the radius constraint.
- If the first and second steps are not possible, then a new $o$-microcluster is created containing this data point.

A challenge of methods this approach is that the number of o-microclusters will increase with time, as new o-microclusters are created, and some of the p-microclusters decay back to o-microclusters. From there to time, we prune some of the o-microclusters, which will allow potential for becoming p-microclusters. The larger the $\delta t$ that has elapsed since the creation of an o microcluster, the larger its weight is expected to be. Therefore, with $T_p$ times, we prune all those microclusters, whose weight is less than the threshold $\psi(\delta t)$, where:

$$\psi(\delta t) = \frac{2-\lambda\cdot(\delta t+T_p)}{2-\lambda\cdot(T_p)-1} \quad (10.4)$$

This process continues in order to maintain the microclusters dynamically. We note that the individual microclusters can be reconstructed into density-connected regions in order to create the final set of clusters by arabic. The overall approach for creating the clusters of arbitrary shape is discussed in it [24].

### 10.32 Grid-Based Streaming Algorithms

### 10.32.1 D-Stream Algorithm

A method called D-Stream for real-time density clustering of data was proposed in [25]. It has many similarities with [30] in terms of trying to define fine-grained regions of high density. The main difference at the conceptual level is that this is done with the use of grids rather than microclusters. In the previous case, a decay function $f(\delta t(\mathbf{X}))$ is used to denote the weight of a point $\mathbf{X}$ since the time of its arrival until the current time $t_i$:

$$f(\delta t(\mathbf{X},t_i)) = \mu^{-\delta t(\mathbf{X},t_i)} \quad (10.5)$$

Here, we assume that $\mu > 1$, which is different from the notations in [25]. We note that this decay function is identical to that proposed in [6, 30], by defining the relationship with respect to the parameter $\lambda$ and assuming that $\mu = 2^{-\lambda}$. Under the assumption of [25] that exactly one record arrives at each timestamp, it can be shown that the sum of the weights of all data points is no longer than $\mu /(\mu-1)$.

The grids are formed by discretizing along each dimension. For the $i$-th dimension, the discretization is performed into $p_i$ ranges along the $i$th dimension. This discretization naturally defines a total of $\eta = \Pi p_i$ d-dimensional cells. For each cell $S$, its weight $W(S,t_i)$ is defined as the current time $t_i$, as follows:

$$W(S,t_i) = \sum_{\mathbf{X}\in S} f(\delta t(\mathbf{X},t_i)) \quad (10.6)$$
