# 10.2.2.3 Online Clustering with ClStream

The microclustering phase is the online data collection portion of the algorithm. The aim is to maintain statistics at a sufficiently high level of (temporal and spatial) granularity so that it can be effectively used by the offline components such as horizon-periodic clustering or algorithm analysis. The algorithm works in an iterative fashion, always maintaining a set of microclusters. It is assumed that a total of $q$ microclusters are stored at any moment by the algorithm. We will denote these microclusters by $\mathcal{M}_1...\mathcal{M}_q$. Associated with each microcluster $i$, we create a unique $id$ if first created. If two microclusters are merged (as well) as one a list of $ids$ is created in order to identify the constituent microclusters. The value of $q$ is determined by the amount of memory available in order to store the microclusters. Therefore, typical values of $q$ are significantly larger than the natural number of clusters in the data but are also significantly smaller than the number of data points arriving in a long period of time for a massive data stream. These microclusters represent the current snapshot of clusters which change over the course of the stream as new points arrive. Their status is stored away on disk whenever the clock is divisible by $\alpha^i$ for any integer $i$. At the time $\alpha^r$ units, any microclusters of order $r$ which were stored at a time in the past more than are deleted by the algorithm.
