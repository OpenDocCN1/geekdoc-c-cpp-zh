# 10.3.1 DenStream: Density-Based Microclustering

The DenStream algorithm [24] approach combines microclustering with a density-estimation approach for effective clustering. The first step is to define a core object, which is defined as an object, in the $\varepsilon$-neighborhood of which the weight of the data points is at least $\mu$. A density area is defined as the union of the $\varepsilon$ neighbors of the core objects.
 the context of dense stream, it is difficult to define these dense regions naturally. Therefore, dense regions of smaller granularity are defined in the form of micro clusters. A microcluster is defined as a set of data points with weight at least $\mu$ and for which the radius of the microcluster about its center is less than $\varepsilon$. We note that the weight of a data point is based on a decayed weighted function of the time that it lasted. Therefore, if $f(\delta t)$ is the time since a data point arrived, its weight is given by

```
$f(\delta t) = 2^{-\delta t}$
```

Since the radius of the microcluster is constrained to be less than $\varepsilon$, it implies that the number of microclusters is much larger than the number of natural clusters in the data for small values of $\varepsilon$. At the same time, the number of core clusters contains a weight of at least $\mu$. We note that the key difference from the standard microclustering definition is that the number of microclusters is not constrained, though the radius of each microcluster is constrained. Thus, this approach uses a different parameter to the underlying application. The microcluster is also referred to as a c-microcluster.

One immediate observation is that when microcluster is first formed by any algorithm, it is unlikely to quantify the weight of data points required to be defined as a microcluster. Therefore, the concepts of potential core microcluster and outlier microcluster are defined in [24]. In the former case, the microcluster contains a weight of at least $eta-\mu$ (for some $eta \in (0,1)$), and in the latter case, it contains a weight less than $eta-\mu$. Furthermore, the weights of decay points over time, also change from being a $p$-microcluster to an $o$-microcluster, if sufficient data points are not added to it to compensate for the decay. Thus, during its lifecycle, a microcluster may move from being an outlier microcluster to becoming a potential core microcluster, and finally to the state of being a core microcluster. These two kinds of microclusters are referred to as $p$-microclusters and $o$-microclusters respectively.

When a new data point arrives, the following can be the possibilities in what is done with it:

+   - If the first step is to insert it into a $p$-microcluster, as long as it is possible to do so, without violating the radius constraint.
- If the first step is not possible, the next step is to insert it into an $o$-microcluster, as long as this can be done without violating the radius constraint.
- If the first and second steps are not possible, then a new $o$-microcluster is created containing this data point.
