

# 数据聚类：算法与应用

- 数字 $k$ 和 $l$ 通常很小，因此 $k \times l$ 矩阵 $G$ 很小。此外，行向量和列向量 $r$ 和 $c$ 都可以放入内存中。

- 对于每一行（或列），寻找最佳分配只需要 $r$、$c$ 和 $G$。它不需要其他行。

利用上述特性，$G$、$r$ 和 $c$ 通过 MapReduce 的参数传递机制被投射到映射器中。每一行（或列）都可以独立处理，以分配到使成本最小化的最佳组。每一行（或列）迭代需要一个 map 和一个 reduce 阶段，并且遵循第 11.4.1 节所示的通用框架。映射器读取每一行并执行局部聚类。归约器通过收集局部信息执行全局聚类，并输出更新后的 $G$ 矩阵和 $r$ 行标签向量（列迭代时为 $c$ 列标签向量）。DisCo 通过仅在映射器和归约器之间传输标签向量和 $G$ 矩阵来最小化网络流量；矩阵数据不会被传输。

实验在 39 节点 Hadoop 集群上对高达 250 万行乘 130 万列的矩阵数据进行了。性能以聚合吞吐量衡量，随着机器数量的增加呈线性增长。DisCo 的质量与串行算法相同，因为 DisCo 是一个精确算法。

## 11.4.6 BoW：基于 MapReduce 的子空间聚类

BoW [7] 是 MapReduce 上的分布式子空间聚类算法。BoW 在 MapReduce 上提供子空间聚类算法：并行聚类（ParC）和采样忽略（SnI）。ParC 有三个步骤，如图 11.9 所示：（1）使用映射器对输入数据进行分区，以便数据聚合到归约器，（2）归约器使用任何子空间聚类算法（例如 [8] 作为插件）在其分配的分区中查找聚类，以及（3）合并上一步的聚类以获得最终聚类。步骤（1）和（3）分别在 map 和 reduce 阶段执行，而步骤（3）在单台机器上串行完成。

ParC 和 SnI 的第二阶段遵循第 11.4.1 节描述的通用框架：数据被分区，局部聚类，局部聚类被聚合以形成全局聚类。SnI 的第一阶段是预处理步骤，用于最小化网络流量

ParC 和 SnI 也有各自的优缺点。就磁盘 I/O 次数而言，ParC 更好，因为它只需要 map-and-reduce 步骤，而 SnI 使用两个 map-and-reduce 步骤。然而，就网络流量而言，SnI 在第一阶段和第二阶段的第四阶段过滤中更好。

问题是哪个算法运行更快？有很多参数可以回答这个问题：例如，使用归约器的数量、数据大小、磁盘速度、网络速度、启动成本、插件算法成本、洗牌阶段传输的数据成本以及采样率。BoW 将成本（运行时间）推导为参数的函数，以确定给出最小运行时间的算法。

实验结果表明，BoW 正确地为不同数量的归约器选择了最佳算法。BoW 还显示出数据大小的线性可扩展性。最后，我们注意到 ParC 和

SnI 不是精确算法，因为聚类是在分割数据上进行的。然而，ParC 或 SnI 的聚类质量与算法的串行版本相当。

## 11.5 结论

鉴于（1）数据规模爆炸式增长以及（2）聚类算法的固有复杂性通常很高（例如 NP-hard），可扩展性似乎是聚类中的“永无止境”挑战。在本章中，我们简要回顾了三种加速/扩展数据聚类算法的技术，包括（a）“一次通过”以减少聚类过程中的迭代次数，（b）随机技术以减少输入数据规模的复杂性，以及（c）分布式和并行算法以加速/扩展计算。未来的趋势是将所有这些可用技术集成起来以实现更好的可扩展性。
