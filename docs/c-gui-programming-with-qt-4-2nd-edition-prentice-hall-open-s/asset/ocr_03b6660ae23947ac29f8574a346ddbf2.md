Implicit sharing works automatically behind the scenes, so we don't have to do anything in our code to make this optimization happen. But since it's nice to know how things work, we will study an example and see what happens under the hood. The example uses QString, one of Qt's many implicitly shared classes.

```
QString str1 = "Humpty";nQString str2 = str1;
```

We set str1 to "Humpty" and str2 to be equal to str1. At this point, QString objects point to the same internal data structure in memory. Along the character data, the data structure holds a reference count that indicates how many QStrings point to the same data structure. Since both str1 and str2 point to the same data, the reference count is 2.

```
str2[0] = 'D';
```

When we modify str2, it first makes a deep copy of the data, to ensure that str1 and str2 point to different data structures, and then it applies the change to its own copy of the data. The reference count of str1's data ("Humpty") becomes 1, and the reference count of str2's data ("Dumpty") is set to 1. A reference count of 1 means that the data isn't shared.

```
str2.truncate(4);
```

If we modify str2 again, no copying takes place because the reference count of str2's data is 1. The truncate() function operates directly on str2's data, resulting in the string "Dumpty". The reference count stays at 1.

```
str1 = str2;
```

When we assign str2 to str1, the reference count for str1's data goes down to 0, which means that no QString is using the "Humpty" data anymore. The data is then freed from memory. Both QString point to "Dumpty", which now has a reference count of 2.
