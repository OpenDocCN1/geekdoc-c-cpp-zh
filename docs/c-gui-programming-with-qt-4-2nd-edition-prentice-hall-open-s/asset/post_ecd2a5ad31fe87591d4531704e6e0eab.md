Now let's implement the server. The server consists of two classes: TripServer and ClientSocket. The TripServer class is derived from TcpServer, a class that allows us to accept TCP connections. ClientSocket reimplements TcpSocket and handles a single connection. At any time, there are many ClientSocket objects in memory as there are clients being served.

```cpp
class TripServer : public TcpServer
{
    Q_OBJECT

public:
    TripServer(QObject *parent = 0);

private:
    void incomingConnection(int socketId);
};
```

The TripServer class implements the incomingConnection() function from TcpServer. This function is called whenever a client attempts to connect to the server it is listening to.

```cpp
TripServer::TripServer(QObject *parent)
    : TcpServer(parent)
{}
```

The TripServer constructor is trivial.

```cpp
void TripServer::incomingConnection(int socketId)
{
    ClientSocket *socket = new ClientSocket(this);
    socket->setSocketDescriptor(socket);
}
```

In incomingConnection(), we create a ClientSocket object as a child of the TripServer, and set its socket descriptor to the number provided to us. The ClientSocket object will delete itself automatically when the connection is terminated.

```cpp
class ClientSocket : public TcpSocket
{
    Q_OBJECT

public:
    ClientSocket(QObject *parent = 0);

private slots:
    void readClient();

private:
    void generateRandomTrip(const QString &from, const QString &to, const QDate &date, const QTime &time);
    uint16 nextBlockSize;
}
```

The ClientSocket class is derived from TcpSocket and encapsulates the state of a single client.

```cpp
ClientSocket::ClientSocket(QObject *parent)
    : TcpSocket(parent)
{
    connect(this, SIGNAL(readyRead()), this, SLOT(readClient()));
    connect(this, SIGNAL(disconnected()), this, SLOT(deleteLater()));

    nextBlockSize = 0;
}
```

In the constructor, we establish the necessary signal-slot connections, and we set the nextBlockSize variable to 0, indicating that we do not yet know the size of the block by the client.

The disconnected() signal is connected to deleteLater(), a QObject-inherited function that deletes the object when control returns to Qt's event loop. This ensures that the ClientSocket object is deleted when the socket connection is closed.

Code View:

```cpp
void ClientSocket::readClient()
{
QDataStream in(this);
    in.setVersion(Qt_4_3);

    if (nextBlockSize == 0) {
        if (bytesAvailable() < sizeof(quint16)) {
            return;
        }
        in >> nextBlockSize;
    }
    if (bytesAvailable() < nextBlockSize) {
        return;
    }
    quint16 requestType;
    QString from;
    QString to;
    QDate date;
    QTime time;
    quint8 flag;

    if (requestType == 'S') {
        in >> from >> to >> date >> time >> flag;
    }

    // ... logic for processing trips ...
    // std::rand(from.length()) * 3600 + to.length() * 60 + time.hour();
    int numTrips = std::rand() % 8;
    for (int i = 0; i < numTrips; ++i) {
        // ... process trips ...
    }
}
```

```cpp
void ClientSocket::generateRandomTrip(const QString &from, const QString &to, const QDate &date, const QTime &time)
{
    QByteArray block;
    QDataStream out(&block, QIODevice::WriteOnly);
    out.setVersion(Qt_4_3);

    quint8 duration = std::rand() % 200;
    out << quint16(block.size()) << date << time << duration;

    write(block);
}
```

The generateRandomTrip() function shows how to send a block of data over a TCP connection. This is very similar to what we did in the client.

In main(), we create a TripServer object and a QPushButton that enables the user to stop the server. We start the server by calling QTcpSocket::listen(), which takes the IP address and port number on which we want to accept connections. The special address 0.0.0.0 QHostAddress::Any signifies any interface present on the local host.

Using a QPushButton to represent the server is convenient for development. However, a deployed server would need to run without a GUI, such as a Windows service or a Unix daemon. Trolltech provides a commercial add-on for this purpose, called QtService.

This completes our client-server example. In this case, we used a block-oriented protocol that allows us to use QDataStream for reading and writing. If we wanted to use a line-oriented protocol, the simplest approach would be to use QTcpSocket::canReadLine() and readLine() functions in a slot connected to the readyRead() signal.

```cpp
QStringList lines;
while (tcpSocket.canReadLine())
    lines.append(tcpSocket.readLine());
```

We would then process each line that has been read. As for sending data, that can be done using a QTextStream on the QTcpSocket.
