The selection behavior specifies how selections should work, in this case by entire rows. This selection is usually shown by using a different background color. We have chosen to hide the ID column because the IDs are not meaningful to the user. We have also set NoEditTriggers the table view read-only.

An alternative for presenting read-only tables is to use QSqlTableModel. This class provides the `setQuery()` function, so it is possible to set complex SQL queries to particular views of one or more tables—for example, using joins.

Unlike the Scooter database, most databases have lots of tables and foreign key relationships. Qt provides QSqlRelationalTableModel, a subclass of QSqlTableModel that can be used to display and edit tables with foreign keys. We can add QSqlRelations to the model, one for each foreign key. In many cases, QSqlRelationalTableModel is very similar to QSqlTableModel, except that we foreign key has an ID field and a name field; by using QSqlRelationalTableModel, we can ensure that users can see and change the name field while behind the scenes the corresponding ID field is the one that is actually used. For this to work correctly, we must set a QSqlRelationalDelegate (or a custom subclass of our own) on the view that is used to present the model.
