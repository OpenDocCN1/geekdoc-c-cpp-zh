When we use QStream, Qt takes care of reading and writing each entry, including containers with an arbitrary number of items. This relieves us from the need to structure what we write and performing any kind of parsing on what we read. Our only obligation is to ensure that we read all the entries in exactly the same order as we wrote them, leaving Qt to handle all the details.

QDataStream is useful for our own custom file formats and standard binary formats. We can read and write standard binary formats using the streamer on objects (such as quint16 and float) or using readRawBytes() and writeRawBytes(). If the QDataStream is being purely to read and write basic C++ data types, we don't even need to call setVersion().

So far, we loaded and saved data with the streamer's version hard-coded as QDataStream::Qt_4_3. This approach is simple and safe, but it has one small flaw: we cannot take advantage of new or updated formats. For example, if a later version of Qt added a new attribute to' and we hard-coded the version number to Qt_4_3, that attribute wouldn't be saved or loaded. There are two solutions. The first approach is to embed the QDataStream version number in the file:

```
QDataStream out(&file);
out << quint32(MagicNumber) << quint16(out.version());
```

(MagicNumber is a constant that uniquely identifies the file type.) This approach ensures we always read the data using the most recent version of QDataStream, whatever happens to be. When we come to read the file, we read the stream:

```
quint32 magic;
quint16 streamVersion;
QDataStream in(&file);
in >> magic >> streamVersion;
```
