When script is called, we begin by finding out which QAction was triggered. Then we extract the action's user data using QVariant::value<T>() to cast it to a QScriptValue, which we use in qScript. Then we invoke qScript's run() function, passing qScript as a parameter; this will make qScript this object inside the run(it) function.[*]

[*] QAction is extended to provide a qScriptConnect() function that will allow us to establish C++-to-script connections. Using this function, we could connect the QAction::triggered() signal to the qScript's run(it) function as follows:

Code View:

```
qScriptConnect(action, SIGNAL(triggered()), qScript, qScript.prop("run")););
```

QAction's "data" item mechanism is based on QVariant. The QScriptValue is not one of the data types that QVariant recognizes. Frequently, Qt provides a mechanism for extending the types that QVariant can handle. At the beginning of htmlwindow.cpp, after the #include, we have the following line:

Q_DECLARE_METATYPE(QScriptValue)


This line should appear after the custom data type it refers to has been declared, and can be done only for data types that have a default constructor and a copy constructor.
