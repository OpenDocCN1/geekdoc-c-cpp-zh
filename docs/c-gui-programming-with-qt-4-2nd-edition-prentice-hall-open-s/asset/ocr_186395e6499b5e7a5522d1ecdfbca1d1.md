(usually an hourglass) and restore the normal cursor once all the data is written. At the end of the function, the file is automatically closed by QFile destructor.

QDataStream supports basic C++ types as well as many of Qt's. The syntax is modeled after the Standard C++ <iostream> classes. For example,

```
out << x << y << z;
```

writes the variables x, y, and z to a stream, and

```
in >> x >> y >> z;
```

reads from a stream. Because the C++ primitive integer types may have different sizes on different platforms, it is safest to cast these values to one of quint8, quint8, quint16, quint16, quint32, quint32, quint64, quint64, which are guaranteed to be the size they identify as (in bits).

The Spreadsheet application's file format is fairly simple. A Spreadsheet file starts with a 32-bit number that identifies the file format (MagicNumber, defined as 0x7F5CC83 in spreadsheet.h, an arbitrary number). Then comes a series of blocks, each containing a single cell's row, column, and formula. To save space, we don't output empty cells. The format is shown in Figure 4.3.

The precise binary representation of the data types is determined by QDataStream. For example, a quint16 is stored as two bytes in big-endian order, and a QString as the string's length followed by the Unicode characters.

The binary representation of Qt types has evolved quite a lot since Qt 1.0. It is likely to continue evolving in future Qt releases to keep pace with the evolution of existing types and to allow for new types. By default, QDataStream uses the most recent version of the binary format (version 4.3), but it can be set to read older versions. To avoid compatibility problems if the application is recompiled using a newer Qt release, we explicitly tell QDataStream to use version 9 interface of the version of Qt we are compiling (QDataStream::Qt_4_3 is a convenience constant that equals 9.).
