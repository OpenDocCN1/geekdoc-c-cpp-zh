The mapper must be given to work on, and in the case of a model that has foreign keys, we must also give it a SqlRelationalDelegate. This delegate ensures that values from the QSqlRelation display column are shown the user rather than row IDs. The delegate also ensures that if the user is editing it, the combobox displays values, but the mapper actively writes the corresponding index value (the foreign key) back to the database.

In cases where foreign keys refer to tables with large numbers of records, it is probably best to create our own delegate and use a "list of values" form with a search capability rather than relying on QRelationalTableModel's default comboboxes.

Once the model and delegate are set, we add mappings between the form's widgets and the corresponding field indices. The combobox is treated just like the other widgets since all the work of dealing with the foreign key is handled by the relation we have already set on it.
