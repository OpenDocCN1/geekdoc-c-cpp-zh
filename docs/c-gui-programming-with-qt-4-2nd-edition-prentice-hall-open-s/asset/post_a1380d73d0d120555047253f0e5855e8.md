This trivial function returns the number of the cursor at which the device file pointer is positioned.

Once the handler is constructed, it is possible for the user to call any of its public functions, in any order. It is a potential problem since we must assume that we can only read serially, we need to read the file header before doing anything else. We solve the problem by calling the readHeaderIfNecessary() function in those functions that depend on the header having been read.

The read() function reads the data for whichever image begins at the current device pointer position. If the file's header is read successfully, or after an image has been read and the device pointer is at the start of another image, we can read the next image.


We create a QDataStream to read the device. We must set the byte order to match that specified by the .cur file specification. There is no need to set a QDataStream version number since the format of integers and floating-point numbers does not vary between data stream versions. Next, we read in various items of cursor header data, and we skip the irrelevant parts of the header and the 8-byte color table using QDataStream::skipRawData().

We must account for all the idiosyncrasies—for example, halving the height because the .cur file gives a height that is twice as high as the image's height. The bitsPerPixel and compression values are always 1 and 0 in a monochrome .cur. If we have any problems, we call enterErrorState() and return false.

```cpp
QByteArray xorBitmap = readbitmap(width, height, in);
QByteArray andBitmap = readbitmap(width, height, in);

if (in.status() != QDataStream::Ok) {
    enterErrorState();
    return false;
}
```

The next items in the file are two bitmaps, one XOR MASK and the other AND mask. We read these into QBitArrays rather than into QBitmaps. A QBitmap is a class designed to be drawn on and painted on-screen, but what we need here is a plain array of bits.

We are done with reading the file, we check the QDataStream's status. In an error state, it stays in that state and can only return zeros. For example, if reading fails on the first bit array, the attempt to read the second will result in an empty QBitArray.


```cpp
for (int i = 0; i < int(height); ++i) {
    for (int j = 0; j < int(width); ++j) {
        QRgb color;
        int bit = (i * width) + j;

        if (andbit.testBit(bit)) {
            if (xorBitmap.testBit(bit)) {
                color = 0x7F7F7F7F;
            } else {
                color = 0x00FFFFFF;
            }
        } else {
            if (xorBitmap.testBit(bit)) {
                color = 0xFFFFFF;
            } else {
                color = 0xFF000000;
            }
        }
        image->setPixel(j, i, color);
    }
}
```

We construct a new QImage of the correct size and assign it to *image. Then we iterate over every pixel in the XOR and AND arrays and convert them into 32-bit ARGB color specifications. The AND and XOR arrays are used as shown in the following table to obtain the color of each cursor pixel:

| AND | XOR | Result |
|---|---|---|
| 1 | 1 | Inverted background pixel |
| 1 | 0 | Transparent pixel |
| 0 | 1 | White pixel |
| 0 | 0 | Black pixel |

black, white, and transparent pixels are no problem, but there is no way to obtain an inverted pixel using an ARGB color specification without knowing the color of the original background pixel. As a substitute, we use a semi-transparent gray color (0x7F7F7F7F).

The jumpNextImage() function is used to skip an image. For simplicity, we simply call read() and ignore the resulting QImage. A more efficient implementation would use the information stored in the .cur file header to skip directly to the appropriate offset in the file.

```cpp
void CursorHandler::readHeaderIfNecessary() const {
    if (state != BeforeHeader) {
        return;
    }

    quint16 reserved;
    quint16 type;
    quint16 count;

    QDataStream in(device);
    in.setOrder(QDataStream::LittleEndian);

    in >> reserved >> type >> count;
    in.skipRawData(1);

    if (in.status() == QDataStream::Ok || reserved != 0
    || type != 2 || count == 0) {
        enterErrorState();
        return;
    }
    state = BeforeImage;
    currentImageNo = 0;
    numImages = int(count);
```

```cpp
QBitArray CursorHandler::readBitmap(int width, int height, QDataStream &in) const
{
  QBitArray bitmap(width * height);
  quint32 word = 0;
  quint8 byte;
  for (int i = 0; i < height; ++i) {
    for (int j = 0; j < width; ++j) {
      if ((j % 32) == 0) {
        word = 0;
        for (int k = 0; k < 4; ++k) {
          in >> byte;
          word = (word << 8) | byte;
        }
      }
      bitmap.setBit((height - i - 1) * width + j,
        word & 0x80000000);
    }
  }
  return bitmap;
}
```

The readmap() function is used to read a cursor's AND and XOR masks. These masks have two unusual features. First, they store the rows from bottom to top, instead of the more common top-to-bottom approach. Second, the endianness of the data appears to be reversed from that used everywhere else in .cur files. In view of this, we must invert the y-coordinate in the setBit() call, and we read in the mask values one byte at a time, bit-shifting and masking to extract their correct values.
