
Preferred Expanding are the same way. When a form contains both Preferred and Expanding is resized, extra space is given to the Expanding widgets, while the Preferred widgets stay at their size hint.

There are two other size policies: MinimumExpanding and Ignored. The former was necessary in a few cases in versions of Qt, but it isn't anymore; the preferred approach is to use Expanding and reimplement minimumSizeHint(). The latter is similar to Expanding, except that it ignores the widget's size hint and minimum size hint.

In addition to the size policy's horizontal and vertical components, the QSizePolicy class stores a horizontal and a vertical stretch factor. These stretch factors can be used to indicate that different child widgets grow at different rates when the form expands. For example, if we have a QTree above a QTextEdit and we want the QTextEdit to be twice as tall as the QTree, we can set the QTextEdit's vertical stretch factor to 2 and the QTree's vertical stretch factor to 1.

Yet another way of influencing a layout is to set a minimum size, a maximum size, or a fixed size on the child widgets. The layout manager will respect these constraints when laying out the widgets. And if this isn't sufficient, we can always derive from the child widget's class and reimplement sizeHint() to obtain the size hint we need.

## StackedLayouts

The QStackedLayout class lays a set of child widgets, or "pages", shows only one at a time, hiding the others from the user. QStackedLayout itself is invisible and provides no intrinsic means for the user to change the page. The small arrows and gray frame in Figure 6.5 are provided by Q Designer to make the layout easy to design. For convenience, Qt also includes QStackedWidget, which provides a QWidget with a built-in QStackedLayout.

## Figure 6.5. QStackedLayout

![](img/5a524abdf0b0d58fa99d30abb4463611_241_0.png)

The pages are numbered from 0. To make a specific child widget visible, we can call setCurrentIndex() with a page number. The page number for a child widget is available using indexOf().

The Preferences dialog shown in Figure 6.6 is an example that uses QStackedLayout. The dialog consists of a QListWidget on the left and a QStackedLayout on the right. Each item in the QListWidget corresponds to a different page in the QStackedLayout. Here's the relevant code to a dialog's constructor:

```

We create a QListWidget and populate it with the page names. Then we create a QStackedLayout and call addWidget() for each page. Forms such as this are also very easy to create using Qt Designer:

1. template.
2. Add a QListWidget and a QStackedWidget to the form.
3. (To create a new page, right-click and choose Insert Page; click the tiny left or right arrow located at the top right of the QStackedWidget.).
4. Lay out the widgets side by side using a horizontal layout.
5. Connect the list widget's currentRowChanged(int) signal to the stacked widget's setCurrentIndex(int) slot.
6. Set the value of the list widget's currentRow property to 0.

## Splitters

QSplitter is a widget that contains other widgets. The widgets in a splitter are separated by splitter handles. Users can change the sizes of child's widgets by dragging the handles. Splitters can often be used as an alternative to layout managers, to give more control to the user.

The child widgets of a QSplitter are automatically placed side by side (one below the other) in the order in which they are created, with splitter bars between adjacent widgets. The code for creating the window depicted in Figure 6.7:

```

QTextEdit editor1 = new QTextEdit;
QTextEdit editor2 = new QTextEdit;
QTextEdit editor3 = new QTextEdit;

QSplitter splitter(Qt::Horizontal);
splitter.addWidget(editor1);
splitter.addWidget(editor2);
splitter.addWidget(editor3);
...
splitter.show();
return app.exec();
}
