Now qmake to create a .pro file and a makefile (qmake -project; qmake gotocoll.pro). qmake tool is smart enough to detect the user interface gui and generate the appropriate makefile rules to invoke uic, Qt's user interface compiler. The uic converts gotocelldialog.ui into C++ and puts the result in ui_gotocelldialog.h

The generated ui_gotocelldialog.h file contains the definition of the Ui::GotoCellDialog class, which is a C++ equivalent of the gotocelldialog.ui file. The class declares member variables that store the form's children widgets and layouts, and a setupUi() function that initializes the form. The generated class looks like this:

```
class Ui::GotoCellDialog
{
public:
    QLabel label;
    QLineEdit lineEdit;
    QSpacerItem spacerItem;
    QQPushButton okButton;
    QQPushButton cancelButton;
    ...

    void setupUi(QWidget widget) {
    ...
}
};
```

The generated class doesn't have any base Class. When we use the form in main.cpp, we create a QDialog and pass it to setupUi().

If you run the program now, the dialog will work, but it doesn't function exactly as we want:

+   * The OK button is always disabled.
* The Cancel button does nothing.
* The line editor accepts any text, instead of accepting only valid cell locations.

We can make the dialog function properly by writing some code. The cleanest approach is to create a new class that is derived from QDialog and Ui::GotoCellDialog that implements the missing functionality (thus proving the adage that any software problem can be solved simply by adding another layer of indirection).
