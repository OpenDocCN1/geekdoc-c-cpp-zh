Earlier we specified the SQL query as an argument to QSqlQuery::exec(), and we can also pass it to the constructor, which executes it immediately.

```cpp
QSqlQuery query("SELECT title, year FROM cd WHERE year >= 1998");
```

We can check for an error by calling isActive() on the query:

```cpp
if (!query.isActive())
    QMessageBox::warning(this, tr("Database Error"), query.lastError().text());
```

If no error occurs, the query will become "active" and we can use next() to navigate through the result set. Doing an INSERT is almost as easy as performing a SELECT:

```cpp
QSqlQuery query("INSERT INTO cd (id, artistid, title, year) VALUES (?, ?, ?, 202)");
```

After this, numRowsAffected() returns the number of rows that were affected by the SQL statement (or -1 on error).

If we need to insert a list of records, or if we want to avoid converting values to strings (escaping correctly), we can use prepare() to specify a query that contains placeholders and then bind the values to insert. Qt supports both the Oracle-style and ODBC-style syntax for placeholders, using native support where available and simulating the other. Here's an example that uses Oracle-style syntax with named placeholders:

```cpp
QSqlQuery query;
query.prepare("INSERT INTO cd (id, artistid, title, year) VALUES (:id, :artistid, :title, :year)");
query.bindValue(":id", 203);
query.bindValue(":artistid", 102);
query.bindValue(":title", "Living in America");
query.bindValue(":year", 2002);
query.exec();
```

Here's the same example using ODBC-style placeholders:

```cpp
QSqlQuery query;
query.prepare("INSERT INTO cd (id, artistid, title, year) VALUES (?, ?, ?, ?)");
query.bindValue(203);
query.bindValue(102);
query.bindValue("Living in America");
query.bindValue(2002);
query.exec();
```

After the call to exec(), we can call bindValue() to bind new values and then call exec() again to execute the query with the new values. Placeholders are often used to specify binary data or strings that contain non-ASCII or non-Latin characters. Behind the scenes, Qt uses Unicode with those databases that support it, and for those that don't, transparently converts strings to the appropriate encoding.

Qt supports SQL transactions on databases where they are available. To start a transaction, we call transaction() the QSqlDatabase object representing the connection. To finish the transaction, we either commit() or rollback(). For example, here's how we would look up a foreign key and execute a statement inside a transaction:

```cpp
QSqlDatabase::database().transaction();
QSqlQuery query;
query.exec("SELECT id FROM artist WHERE name = 'Glucifer'");
if (query.next()) {
  int artistID = query.value(0).toInt();
  query.exec("INSERT INTO cd (id, artistid, title, year) "
             + "VALUES (201, " + QString::number(artistID)
             + ", 'Riding the Tiger, 1997')");
}
QSqlDatabase::database().commit();
```

The QSqlDatabase::database() function returns a QSqlDatabase object representing the connection we created with addConnection(). If a transaction cannot be started, QSqlDatabase::transaction() returns false. Some databases do not support transactions. For those, the transaction(), commit(), and rollback() functions do nothing. We can test whether a database supports transactions by hasFeature() on the QSqlDriver associated with the database:

```cpp
QSqlDriver *driver = QSqlDatabase::database().driver();
if (driver->hasFeature(QSqlDriver::Transactions))
..
```

Several other database features can be tested for, including whether the database supports BLOBs (binary large objects), Unicode, and prepared queries.

It is also possible to access the low-level database driver handle and the low-level handle to a query's result set, using QSqlDriver::handle() and QSqlQuery::handle(). Both functions are dangerous unless you know exactly what you are doing and are very careful. See their documentation for examples and an explanation of the risks.

In the examples so far, we have assumed that the application is using a single database connection. If we want to create multiple connections, we can pass a name as a second argument to addDatabase(). For example:

```cpp
QSqlDatabase db = QSqlDatabase::addDatabase("QSQL", "OTHER");
db.setHostName("saturn.mcmanany.edu");
db.setDatabaseName("starsdb");
db.setUsername("hilbert");
db.setPassword("ixtapa7");
```

We can then retrieve a pointer to the QSqlDatabase object by passing the name to QSqlDatabase::database():

```cpp
QSqlDatabase db = QSqlDatabase::database("OTHER");
```

To execute queries using the other connection, we pass the QSqlDatabase object to the QSqlQuery constructor:

```cpp
QSqlQuery query(db);
query.exec("SELECT id FROM artist WHERE name = 'Mando Diao'");
```

Multiple connections are useful if we want to perform more than one transaction at a time, since each connection can handle only one active transaction. When we use multiple database connections, we can still have one unnamed connection and QSqlQuery will use that connection if none is specified.

In addition to QSqlQuery, Qt provides the QSqlTableModel class as a higher-level interface, allowing us to avoid using raw SQL for performing the most common operations (SELECT, INSERT, UPDATE, DELETE). The class can also be used stand-alone to manage a database without any GUI, or it can be used as a source for QListView or QTableView. Here's an example that uses QSqlTableModel to perform a SELECT:

```cpp
QSqlTableModel model;
model.setTable("cd");
model.setFilter("year >= 1998");
model.select();
```

Navigating the result set is done by retrieving a record using QSqlTableModel::record():

```cpp
for (int i = 0; i < model.rowCount(); ++i) {
    QSqlRecord record = model.record(i);
    QString title = record.value("title").toString();
    int year = record.value("year").toInt();
    std::cerr << title << ": " << year << std::endl;
}
```

An important difference between an SQL model and a standard model is that for an SQL model we must call submitAll() to have any changes written to the database.

The QSqlRecord::value() function takes either field name or index. When operating on large sets, it is recommended that fields are specified by their indexes:

```cpp
int titleIndex = model.record().indexOf("title");
int yearIndex = model.record().indexOf("year");
```

To insert a record into a database table, we call insertRow() to create a new row (record), and we use setData() to set the values of each column (field):

```cpp
QTableModel model;
model.setTable("cd");
int row = 0;
model.insertRows(row, 1);
model.setData(model.index(row, 0), 113);
model.setData(model.index(row, 1), "Shanghai My Heart");
model.setData(model.index(row, 2), 224);
model.setData(model.index(row, 3), 2003);
model.submitAll();
```

After the call to submitAll(), the record might be moved to a different row position, depending on how the table is ordered. submitAll() will return false if the insertion failed.

To update a record, we must first position the QSqlTableModel on the record we want to modify (e.g., using select()). We then extract the record, update the fields we want to change, and write our changes back to the database:

```cpp
QSqlTableModel model;
model.setTable("cd");
model.setFilter("id = 125");
model.select();
if (model.rowCount() == 1) {
    QSqlRecord record = model.record(0);
    record.setValue("title", "Melody A.M.");
    record.setValue("year", record.value("year").toInt() + 1);
    model.setRecord(0, record);
}
model.submitAll();
```
