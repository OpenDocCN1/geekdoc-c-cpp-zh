The purpose of a .pro file is to list the source files that are involved in a project. Since qmake is used for building Qt and its associated tools, Qt very well can generate rules for invoking moc, uic, and rcc. As a result, the syntax is very concise and easy to easy to learn.

The three main types of project files are app (for stand-alone applications), lib (for static and shared libraries), and subdirs (for recursive subdirectory builds). This can be specified using the TEMPLATE variable, as follows:

```
TEMPLATE = lib
```

The subsdirs template can be used for building targets in subdirectories. In that case, we need to specify the SUBDIRS variable in addition to TEMPLATE = subsdirs. In each subdirectory, qmake looks a .pro file named after the directory and will build that project. The examples.pro file supplied with the examples provided for this book uses the subsdirs template to run qmake on the individual examples.

If no TEMPLATE entry is present, the default is app. If app and lib projects, the most commonly used variables are the following:

+   - HEADERS specifies the project's C++ header (.h) files.
- SOURCES specifies the project's C++ implementation (.cpp).
- FORMS specifies the Qt Designer .ui files to be processed by uic.
- RESOURCES specifies the .qrc files to be processed by rcc.
- DEFINES specifies the C++ preprocessor symbols that should be predefined.
- INCLUDPATH specifies the directories that should be searched by the C++ preprocessor for global header files.
- LIBS specifies the libraries to link to the project. The libraries are specified either as absolute paths or using the Unix-inspired -L and -l flags (e.g., -L/usr/local/lib and -ldb_cxx).
- CONFIG specifies various project configuration and compiler options.
- QT specifies the Qt modules that are used by the project. (The default is core gui, corresponding to the QtCore and QtGui modules).
- VERSION specifies the version number of the target library.
