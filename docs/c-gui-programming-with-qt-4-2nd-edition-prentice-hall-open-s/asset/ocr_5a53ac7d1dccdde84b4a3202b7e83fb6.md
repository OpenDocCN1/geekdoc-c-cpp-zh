Every action can have an associated "data" item of type QVariant. The QVariant type can hold values of C++ and Qt types; we cover it in Chapter 11. Here, we store the full name of the file in the action's "data" item so we can easily retrieve it later. We also set the action to be visible.

If there are more file actions than recent files, we hide the extra actions. Finally, if there is at least one recent file, we set the separator to be visible.

```
void MainWindow::openRecentFile() {
  if (okToContinue()) {
    QAction action = qobject_cast<QAction>(sender());
    if (action) {
      loadFile(action->data().toString());
    }
  }
}
```

When the user chooses a recent file, the openRecentFile() slot is called. The okToContinue() function is used in case there are unsaved changes, and provided the user did not cancel, we find out particular action invoked the slot using QObject::sender().

The qobject_cast<T>() performs a dynamic cast based on the meta-information generated by moc. Qt's meta-object compiler. It returns a pointer of the requested QObject subclass, or 0 if the object cannot be cast to. Unlike the Standard C++ dynamic_cast<T>(), Qt's object_cast<T>() works correctly across dynamic library boundaries. In our example, we use object_cast<T>() to cast a QObject pointer to a QAction pointer. If the cast is successful (it should be), we call loadFile() with the full name that we extract from the action's data.
