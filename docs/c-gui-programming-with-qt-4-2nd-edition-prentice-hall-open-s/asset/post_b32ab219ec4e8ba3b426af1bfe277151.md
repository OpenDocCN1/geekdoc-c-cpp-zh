If we want to handle unsupported data types in their parameter list, we can use QABase::queryInterface() to retrieve the COM interface and call the method directly. As usual with COM, we must call Release() when we have finished using the interface. If we often need to call such methods, we subclass QAObject or QAWidget and provide member functions that encapsulate the COM interface calls. Be aware that QAObject and QAWidget subclasses cannot define their own properties, signals, or slots.

We will now review the QAServer module. This module enables us to turn a standard Qt program into an ActiveX server. The server can be either a shared library or a stand-alone application. Servers built as shared libraries are often called in-process servers; stand-alone applications are called out-of-process servers.

Our first QAServer example is an in-process server that provides a widget that shows a ball bouncing left and right. We will also see how to embed the widget in Internet Explorer.

The setColor() function sets the value of the color property. It calls update() to repaint the widget.
The unusual part is the requestPropertyChange() and propertyChanged() calls. These functions are inherited from QAxBindable and should ideally be called whenever we change a property. The requestPropertyChange() asks the client's permission to change a property, and returns true if the client allows the change.
The propertyChanged() notifies the client that the property has been changed.
The setSpeed() and setRadius() setters also follow this pattern, and so do the start() and stop() slots, since they change the value of the running property.

The ObjectSafetyImpl class is derived from both QAggregated and IObjectSafety. The QAggregated class is an abstract base class for implementations of additional COM interfaces. The COM object that the QAggregated extends is accessible through controllingUnknown(). The QAxServer module creates this COM object behind the scenes.

The QAXAGG_IKNOWN macro provides standard implementations of QueryInterface(), AddRef(), and Release(). These implementations simply call the same functions on the COM object.

```
long ObjectSafetyImpl::queryInterface(const QUuid &iid, void **iface)
{
    iface = 0;
    if (iid == IID_IObjectSafety) {
        iface = static_cast<IObjectSafety *>(this);
    } else {
        return E_NOINTERFACE;
    }
    AddRef();
    return S_OK;
}
```

The queryInterface() function is a pure virtual function of QAggregated. It is called by the controlling COM object to give access to the interfaces provided by the QAggregated subclass. We must return E_NOINTERFACE for interfaces that we don't implement and for IUnknown.
