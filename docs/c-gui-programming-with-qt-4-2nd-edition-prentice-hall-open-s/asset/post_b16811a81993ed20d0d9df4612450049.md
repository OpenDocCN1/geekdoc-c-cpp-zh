The need to read from or write to files or other devices is common to almost every application. Qt provides excellent support for I/O through QIODevice, a powerful abstraction that encapsulates "devices" capable of reading and writing blocks of bytes. Qt includes the QIODevice subclasses:

| Class | Description |
| :--- | :--- |
| QFile | Accesses files in the local file system and in embedded resources |
| QTemporaryFile | Creates and accesses temporary files in the local file system |
| QBuffer | Reads from or writes data to a QByteArray |
| QProcess | Runs external processes and handles inter-process communication |
| QTcpSocket | Transfers a stream of data over the network using TCP |
| QUdpSocket | Sends or receives UDP datagrams over the network |
| QssSocket | Transfers an encrypted data stream over the network using SSL/TLS |

QProcess, QTcpSocket, QUdpSocket, QssSocket are sequential devices, meaning that the device can be accessed only once, starting from the first byte and progressively to the last byte. QFile, QTemporaryFile, and QBuffer are random-access devices, so they can be read any number of times from any position; they provide the QIODevice::seek() function for repositioning the file pointer.

In addition to the device classes, Qt also provides two higher-level stream classes that we can use to read from and write to, any I/O device: QDataStream for binary QTextStream for text. These classes take care of issues such as byte ordering and text encodings, which Qt applications running on different platforms or in different countries can read and write each other's files. This makes Qt's I/O classes more convenient than the corresponding Standard C++ classes, which leave these issues to the application programmer.

QFile makes it easy to access individual files, whether they are in the file system or embedded in the application's executable as resources. For applications that need to identify which sets of files to work on, Qt provides the QDir and QFileInfo classes, which handle directories and provide information about the files inside them.

QProcess allows us to launch external programs and communicate with them through their standard input, standard output, and error channels (cin, cout, cerr). We can set the environment variables and working directory that the external application will use. By default, communication with the process is asynchronous (non-blocking), but it is also possible to block on certain operations.

Networking and reading writing XML are such substantial topics that we cover separately in their own dedicated chapters (Chapter 15 and Chapter 16).

## Reading and Writing Binary Data

The simplest way to load and save binary data with Qt is to instantiate a QFile, open the file, and access it through a QDataStream object. QDataStream provides a platform-independent storage format that supports C++ types such as int and double, and many Qt data types, including QByteArray, QFont, QImage, QPixmap, QString, and QVariant, as well as Qt container classes as QList<T> and QMap<K, T>.

Here's how we store an integer, a QImage and a QMap<QString, QColor> in a QImage (phil.png)

```
facts.dat:
Map<QString, QColor> map;
map.insert("red", Qt::red);
map.insert("green", Qt::green);
map.insert("blue", Qt::blue);

QFile file("facts.dat");
if (!file.open(IODevice::WriteOnly)) {
    std::cerr << "Cannot open file for writing: "
              << qPrintable(file.errorString()) << std::endl;
    return;
}
```

```
QDataStream out(&file);
out.setVersion(QDataStream::Qt_4_3);
```

```
out << uint32(0x12345678) << image << map;
```

If we cannot open the file, we inform the user and return. the qPrintable() returns a const char * for a QString. (Another approach would have been to use QString::toStd(), which returns a std::string, for which <iostream> has an overload.)

If the file is opened successfully, we create a QDataStream and set its version number. The version number is an integer that influences the way Qt data types are represented (basic C++ data types are always represented the same way). In Qt 4.3, the most comprehensive format is version 9. We can either hard-code the constant 9 or use the QDataStream::Qt_4_3 symbolic name.

To ensure that the number 012345678 is written as an unsigned 32-bit integer on all platforms, we can cast it to uint32, a data type that is guaranteed to be exactly 32 bytes. To ensure interoperability, QDataStream standardizes on big-endian by default; this can be changed by calling setByteOrder().

We don't need to explicitly close the file, since this is done automatically when the QFile variable goes out of scope. We need to verify that the data has actually been written, we can call flush() and check its return value (true on success).

The code to read back the data mirrors the code we used to write it:

```
uint32 n;
Image image;
QMap<QString, QColor> map;
```

```
QFile file("facts.dat");
if (!file.open(IODevice::ReadOnly)) {
  std::cerr << "Cannot open file for reading: "
            << qPrintable(file.errorString()) << std::endl;
  return;
}
```

```
QDataStream in(&file);
in.setVersion(QDataStream::Qt_4_3);
```

```
in >> n >> image >> map;
```
