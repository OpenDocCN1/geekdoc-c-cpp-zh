in performDrag(), we create an object of type QDrag with this as the parent. QDrag stores the data in a QMimeData object. For this example, we provide the data as a text/plain string in QMimeData::setText(). QMimeData provides several features for handling the most common types of (images, URLs, colors, etc.) and can handle arbitrary MIME types represented as QByteArray. The call to QDrag::setPixmap() sets the icons that follow the cursor while the drag is taking place.

QDrag::exec() starts the dragging operation and blocks until the user drops or cancels the drag. It takes a collection of "drag actions" as argument (Qt::CopyAction, Qt::MoveAction, Qt::LinkAction) and returns the drag action that was executed (Qt::IgnoreAction if none was executed). Which action is executed depends on what source widget allows, the target supports, and which modifier keys are pressed when the drop occurs. After the exec() call, Qt takes ownership of the drag object and deletes it when it is finished.

```
void ProjectListWidget::dragEnterEvent(QDragEnterEvent *event)
{
    ProjectListWidget source =
        object_cast<ProjectListWidget>(event->source());
    if (source && source != this) {
        event->setDropAction(Qt::MoveAction);
        event->accept();
    }
}
```

The ProjectListWidget not only originates drags, but also accepts such drags if they come from another ProjectListWidget in the same application. QDragEnterEvent::source() returns a pointer to the widget that initiated the drag if that is part of the same application; otherwise, returns a null pointer. We use q_cast<T>() to ensure that the drag comes from a ProjectListWidget. If all is correct, we tell Qt that we are ready to accept the action as an action.
