```
QDataStream in(device());
in.setByteOrder(QDataStream::LittleEndian);
in >> size;
if (size != 40) {
    enterErrorState();
    return false;
}
in >> width >> height >> numPlanes >> bitsPerPixel >> compression;
height /= 2;

if (numPlanes != 1 || bitsPerPixel != 1 || compression != 0) {
    enterErrorState();
    return false;
}

in.skipRawData((size - 20) + 8);
```

We create a QDataStream to read the device. We must set the byte order to match that specified by the .cur file specification. There is no need to set a QDataStream version number since the format of integers and floating-point numbers does not vary between data stream versions. Next, we read in various items of cursor header data, and we skip the irrelevant parts of the header and the 8-byte color table using QDataStream::skipRawData().

We must account for all the idiosyncrasies—for example, halving the height because the .cur file gives a height that is twice as high as the image's height. The bitsPerPixel and compression values are always 1 and 0 in a monochrome .cur. If we have any problems, we call enterErrorState() and return false.

The next items in the file are two bitmaps, one XOR MASK and the other AND mask. We read these into QBitArrays rather than into QBitmaps. A QBitmap is a class designed to be drawn on and painted on-screen, but what we need here is a plain array of bits.
