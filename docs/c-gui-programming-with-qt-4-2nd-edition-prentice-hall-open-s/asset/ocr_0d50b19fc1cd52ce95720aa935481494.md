Locking and unlocking a mutex in complex functions, or in functions that throw C++ exceptions, can be error-prone. Qt offers the QLL convenience class to simplify mutex handling. QMutexL's constructor accepts a QMutex as argument and locks it. QMutexL's destructor unlocks the mutex. For example, we could rewrite the earlier run() and stop() functions as follows:

```
void Thread::run()
{
  forever {
    {
      QMutexL locker(&mutex);
      if (stopped) {
        stopped = false;
        break;
      }
    }
    std::cerr << qPrintable(messageStr);
  }
  std::cerr << std::endl;
}
```

```
void Thread::stop()
{
  QMutexL locker(&mutex);
  stopped = true;
}
```

One issue with mutexes is that only one thread can access the same variable at a time. In programs with lots of threads trying to read the same variable simultaneously (without modifying it), the mutex can be a serious performance bottleneck. In these cases, we can use QReadWriteLock, a synchronization class that allows simultaneous read-only access without compromising performance.
