# MailClient::MailClient()

```
{
    rightSplter = new QSplitter(Qt::Vertical);
    rightSplter->addWidget(messagesTreeWidget);
    rightSplter->addWidget(editText);
    rightSplter->setStretchFactor(1, 1);

    mainSplter = new QSplitter(Qt::Horizontal);
    mainSplter->addWidget(foldersTreeWidget);
    mainSplter->addWidget(rightSplter);
    mainSplter->setStretchFactor(1, 1);
    setCentralWidget(mainSplter);

    setWindowTitle(tr("Mail Client"));
    readSettings();
}
```

After creating the three widgets that we want to display, we create a vertical splitter, rightSplter, and add the two widgets we want on the right. Then we create a horizontal splitter, mainSplter, and add the widget we want it to display on the left and rightSplter whose widget we want shown on the right. We make mainSplter the QMainWindow's central widget.

When the user resizes a window, QSplitter normally distributes the space so that the relative sizes of the child widgets stay the same. In the Mail Client example, we do not this behavior; instead, we want the QWidget to keep their sizes and to give any extra space to the QTextEdit. It is achieved by the two setStretchFactor() calls. The first argument is the 0-based index of the splitter's child widget, and the second argument is the stretch factor we want to set; the default is 0.

The first setStretchFactor() call is on rightSplter, and it sets the widget at position 1 (editText) to have a stretch factor of 1. The second StretchFactor() call is on mainSplter, and it sets the widget at position 1 (rightSplter) to have a stretch factor of 1. This ensures that any additional space is available.

When the application is started, QSplitter gives the child appropriate sizes based on their initial sizes (or based on their size hint if no initial size is specified). We can move the splitter handles programmatically by calling QSplitter::setSize(). The QSplitter class also provides a means of saving and restoring its state the next time the application is run.
