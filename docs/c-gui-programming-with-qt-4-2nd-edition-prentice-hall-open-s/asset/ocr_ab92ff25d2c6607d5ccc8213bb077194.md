# Double Buffering

Double buffering is a GUI programming technique that consists of rendering a widget to an off-screen pixmap and copying the pixmap to the display. With earlier versions of Qt, this technique was frequently used to eliminate flicker and to provide a smoother user interface.

In Qt 4, Widget handles this automatically, so we rarely need to worry about widget flickering. Still, explicit double buffering remains beneficial if the widget's rendering is complex and is needed repeatedly. We can then store a pixmap permanently with the widget, always ready for the next paint event, and copy the pixmap to the widget whenever we receive a paint event. It is especially helpful when we want to make small modifications, such as drawing a rubber band, without recomputing the whole widget's rendering over and over.

We will round this chapter by reviewing the Plotter custom widget shown in Figures 5.7 and 5.9. This widget uses double buffering and demonstrates some other aspects of Qt programming, including keyboard event handling, manual layout, and coordinate systems.

For a real application we need a graphing or plotting widget, rather than creating a custom widget as we are doing here, we would most likely use one of the party widgets that are available. For example, we might use GraphPak from http://www.ics.com/, KD Chart from http://www.kdab.net/, or Qwt from http://qwt.sourceforge.net.

The Plotter displays one or more curves specified as vectors of coordinates. The user can draw a rubber band on the image, and the Plotter will zoom in the area enclosed by the rubber band. The user draws the rubber band by clicking a point on the graph, dragging the mouse to another position with the left mouse button held down, and releasing the mouse button. Qt provides the RubberBand class for drawing rubber bands, but here we draw it to have finer control over the look, and to demonstrate double buffering.
