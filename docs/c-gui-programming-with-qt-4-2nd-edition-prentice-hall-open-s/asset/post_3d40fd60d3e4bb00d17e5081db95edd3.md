
We simply append the characters to the currentText variable.

```cpp
bool SaxHandler::endElement(const QString & /* namespaceURI,
                               const QString & localName */,
                               const QString &qName)
{
    if (qName == "entry") {
        currentItem = currentItem->parent();
    } else if (qName == "page") {
        if (currentItem) {
            QString allPages = currentItem->text(1);
            if (!allPages.isEmpty())
                allPages += ",";
            allPages += currentText;
            currentItem->setText(1, allPages);
        }
    }
    return true;
}
```

The endElement() function is called when the reader encounters a closing tag. Just as startElement(), the third parameter is the name of the tag.

If the tag is </entry>, we update the currentItem private variable to point to the current QTreeWidgetItem's parent. (For historical reasons, top-level items return 0 as their parent rather than the root item.) This ensures that the currentItem variable is restored to the value it held before the corresponding <entry> tag was read.

If the tag is </page>, we add the specified page number or page range to the comma-separated list in the current item's text in column 1.

```cpp
bool SaxHandler::fatalError(const XmlParseException &exception)
{
    std::cerr << "Parse error at line " << exception.lineNumber()
               << "," << "column " << exception.columnNumber() << ": "
               << qPrintable(exception.message()) << std::endl;
    return false;
}
```

The fatalError() function is called when the reader fails to parse the XML file. If this occurs, we simply print a message to a console, giving the line number, the column number, and the parser's error text.

This completes the implementation of SaxHandler. The main() function that uses it is almost identical to the one we reviewed in the previous section for DomParser, the difference being that we use a SaxHandler rather than a DomParser.

# Writing XML

Most applications that can read XML files also need to write such files. There are three approaches for generating XML files from Qt applications:

- We can use QXmlStreamWriter.
- We can build a DOM tree and save() on it.
- We can generate XML by hand.

The choice between these approaches is mostly independent of whether we use QXmlStreamReader, DOM, SAX for reading XML documents, although if the data is held in a DOM tree it often makes sense to save the tree directly.

Writing XML using QXmlStreamWriter class is particularly easy since the class takes care of escaping special characters for us. If we wanted to output the index data from a QWidget using QXmlStreamWriter, we could do so using two functions. The first function would take a file name and a QWidget *, and iterate over all the top-level items in the tree:

Code View:

```cpp
bool writeXml(const QString &fileName, QWidget *treeWidget) {
    QFile file(fileName);
    if (!file.open(QFile::WriteOnly | QFile::Text)) {
        std::cerr << "Error: Cannot write file "
                  << qprintable(fileName) << ":"
                  << qprintable(file.errorString()) << std::endl;
        return false;
    }

    QXmlStreamWriter xmlWriter(&file);
    xmlWriter.setAutoFormatting(true);
    xmlWriter.writeStartElement("bookindex");
    for (int i = 0; i < treeWidget->topLevelItemCount(); ++i)
        writeEntry(&xmlWriter, treeWidget->topLevelItem(i));
    xmlWriter.writeEndDocument();
    file.close();
    if (file.error()) {
        std::cerr << "Error: Cannot write file "
                  << qprintable(fileName) << ":"
                  << qprintable(file.errorString()) << std::endl;
        return false;
    }
    return true;
}
```

If we switch on auto-formatting, the XML is output in a more human-friendly style, with indentation used to show the data's recursive structure. The writeStartDocument() function writes the XML header line

```xml
<?xml version="1.0" encoding="UTF-8"?>
```

The writeStartElement() function generates a new start tag with the given tag text. The writeEndDocument() function closes any open start tags. For top-level item, we use writeIndexEntry(), passing it the QXmlStreamWriter, and the item to output. Here is the code for writeIndexEntry():

```cpp

```

The function creates an <entry> element corresponding to the QTreeWidgetItem receives as a parameter. The writeAttribute() adds an attribute to the tag that has been written; for example, it might turn <entry> into <entry term="sidebars">. If there are page numbers, they are split on commas, and for each one, a separate <page>...</page> tag is written, with the page text in between. This is achieved by calling writeTextElement() and passing a tag name and the text to put between the start and end tags. In all cases, QXmlStreamWriter takes care of escaping XML special characters, so we never to worry about this.

If the item has children, we recursively call writeIndexEntry() on each of them. Finally, we call writeEndElement() to output </entry>.

QXmlStreamWriter to write XML is the easiest and safest approach, but if we already have the tree in a DOM, we can simply ask the tree to output the relevant XML by calling save() the QDocument object. By default, save() uses UTF-8 as the encoding for the generated file. We can use another encoding by prepending an <?xml?> declaration such as

```xml
<?xml version="1.0" encoding="ISO-8859-1"?>
```

to the DOM tree. The following code snippet shows how to do this:

```cpp
const int Indent = 4;

QDomDocument doc;
...
TextStream out(&file);
DomNode xmlNode = doc.createProcessingInstruction("xml", "version='1.0' encoding=\"ISO-8859-1\"");
doc.insertBefore(xmlNode, doc.firstChild());
doc.save(out, Indent);
```

Starting with Qt4, an alternative is to set the encoding on the QTextStream using setCodec() and to pass QDomNode::EncodingFromTextStream as third parameter to save().

Generating XML files by hand is not much harder than doing with DOM. We can use QTextStream and write the strings as we do with any other text file. The tricky part is to escape special characters in text and attribute values. The Qt::escape() function escapes the characters '<', '>', and '&'. Here's some code that makes use of it:

```cpp
QTextStream out(&file);
out.setCodec("UTF-8");
out << "<doc\n"
 << "  <quote>" << Qt::escape(quoteText) << "</quote>\n"
 << "  <translation>" << Qt::escape(translationText)
 << "</translation>\n"
 << "</doc>\n";
```

When generating XML files like this, in addition to having to write the <?xml?> declaration and setting the right encoding, we must also remember to escape the text we write, and if we must escape single or double quotes in their values. Using QXmlStreamWriter is much easier since it handles all of this is for us.

# Tooltips, Status Tips, and "What's This?" Help

A tooltip is a small piece of text that appears when the mouse hovers over a widget for a certain period of time. Tooltips are presented with black text on a yellow background. Their primary use is to provide textual descriptions of toolbar buttons.

We can add tooltips to arbitrary widgets in code using QWidget::setToolTip(). For example:

```cpp
findButton->setToolTip(tr("Find next"));
```

To set the tooltip of a QAction that can be added to a menu or a toolbar, we can simply call setToolTip() on the action. For example:

```cpp
newAction = new QAction(tr("&New"), this);
newAction->setToolTip(tr("New document"));
```

If we don't explicitly set a tooltip, QAction will automatically use the action text.
A status tip is also a short piece of descriptive text, usually a longer than a tooltip. When the mouse hovers over a toolbar button or a menu option, a status tip appears in the status bar. Call setStatusTip() to add a status tip to an action or to a widget:

```cpp
newAction->setStatusTip(tr("Create a new document"));
```
