QDataStream is useful for our own custom file formats and standard binary formats. We can read and write standard binary formats using the streamer on objects (such as quint16 and float) or using readRawBytes() and writeRawBytes(). So far, we loaded and saved data with the streamer's version hard-coded as QDataStream::Qt_4_3. This approach is simple and safe, but it has one small flaw: we cannot take advantage of new or updated formats. For example, if a later version of Qt added a new attribute to' and we hard-coded the version number to Qt_4_3, that attribute wouldn't be saved or loaded. There are two solutions. The first approach is to embed the QDataStream version number in the file:

```
QDataStream out(&file);
out << quint32(MagicNumber) << quint16(out.version());
```

quint16 streamVersion;
QDataStream in(&file);
in >> magic >> streamVersion;

If the file format contains a version number of its own, we can use it to deduce the stream version instead of storing it explicitly. For example, let's suppose that the file format is for version 1.3 of our application. We might write this to the data as follows:

```

out.setVersion(QDataStream::Qt_4_3);
out << quint32(MagicNumber) << quint16(0x0103);
```

The need to read from or write to files or other devices is common to almost every application. Qt provides excellent support for I/O through QDevice, a powerful abstraction that encapsulates "devices" capable of reading and writing blocks of bytes. Qt includes the QDevice subclasses:

| Class | Description |
| --- | --- |
| QFile | Accesses files in the local system and embedded resources |
| QTemporaryFile | Creates and accesses temporary files in the local system |
| QBuffer | Reads data from or writes to QByteArray |
| QProcess | Runs external processes and handles inter-process communication |
| QTcpSocket | Transfers a stream of data over the network using TCP |
| QUdpSocket | Sends or receives datagrams over the network |
| QssSocket | Transfers encrypted data over the network using SSL/TLS |

QProcess, QTcpSocket, QUdpSocket, QssSocket are sequential devices, meaning that the data can be accessed only once, starting from the first byte and progressing linearly to the last. QFile, QTemporaryFile, and QBuffer are random-access devices, so bytes can be read any number of times from any position; they provide the QDevice::seek() function for repositioning the file pointer. In addition to the device classes, Qt provides two higher-level stream classes that we can use to read and write to I/O device: QDataStream for binary and QTextStream for text. These classes take care of issues such as byte ordering and Qt running on different platforms or in different countries can read and write each other's files. This makes Qt's I/O classes more convenient than the corresponding Standard++ classes, which leave these issues to the application programmer. QFile makes it easy to access individual files, whether they are in the file system or embedded in the application's executable as resources. For applications that need to identify which sets of files to work on, Qt provides the QDir and QFileInfo, which handle directories and provide information about the files inside them. QProcess allows us to launch external programs and communicate with them through their standard input, standard output, and error channels (cin, cout, cerr). We can set the environment variables and working directory that the external application will use. By default, communication with the process is asynchronous (non-blocking), but it is also possible to block on certain operations. Networking and reading XML are also substantial topics that we cover separately in their own dedicated chapters (Chapter 15 and Chapter 16).

# Reading and Writing Binary Data

The simplest way to load and save binary data with Qt is to instantiate a QFile, to open the file, and access it through a QDataStream object. QDataStream provides a platform-independent storage format that supports C++ types as int and double, and many Qt data types, including ByteArray, QFont, QImage, QPixmap, QString, and QVariant, as well as Qt container classes as List<T> and QMap<K, T>.

Here's how we store an integer, a QImage and a QMap<QString, QColor> in a file facts.dat:

```
QImage image("philip.png");

QMap<QString, QColor> map;
map.insert("red", Qt::red);
map.insert("green", Qt::green);
map.insert("blue", Qt::blue);

QFile file("facts.dat");
if (!file.open(QIODevice::WriteOnly)) {
    std::cerr << "Cannot open file for writing: "
              << qPrintable(file.errorString()) << std::endl;
    return;
}
```

```
QDataStream out(&file);
out.setVersion(QDataStream::Qt_4_3);
out << quint32(0x12345678) << image << map;
```

If we cannot open the file, we inform the user and return. The qPrintable() returns a const char * for a QString (Another approach would have been to use QString::toCString(), which returns a std::string, for which <iostream> has a overload.)

If the file is opened successfully, we create a QDataStream and set its version number. The version number is an integer that influences the way Qt data types are represented (base C++ data types are always represented the same way). In Qt 4.3, the most comprehensive format is version 9. We can either hard-code the constant 9 or use QDataStream::Qt_4_3 symbolic name.

To ensure that the number 0x12345678 is written as an unsigned 32-bit integer on all platforms, we cast it to quint32, a data type that is guaranteed to be exactly 32 bits. To ensure interoperability, QDataStream standardizes on big-endian by default; this can be changed by calling setByteOrder().

We don't need to explicitly close the file, since this is done automatically when the QFile variable goes out of scope. We want to verify that the data has actually been written, we can call flush() and check its return value (true on success).

The code to read back the data mirrors the code we used to write it:

```
quint32 n;
Image image;
QMap<QString, QColor> map;
```

```
QFile file("facts.dat");
if (!file.open(QIODevice::ReadOnly)) {
    std::cerr << "Cannot open file for reading: "
              << qPrintable(file.errorString()) << std::endl;
    return;
}
```

```
QDataStream in(&file);
in.setVersion(QDataStream::Qt_4_3);
in >> n >> image >> map;
```
