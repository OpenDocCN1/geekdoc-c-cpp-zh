If the user chooses a file, a new Editor's text is read in, and if the read is successful, a pointer to the Editor is returned. If the user cancels the file dialog, or if the reading fails, a pointer is returned and the user is notified of the error. It makes more sense to implement the file operations in the Editor class than in the MainWindow class, because each Editor needs to maintain its own independent state.

The addEditor() private function is called from newFile() and open() to complete the initialization of a new Editor widget. It starts by establishing two-slot connections. These connections ensure that EditCut and EditCopy are enabled or disabled depending on whether there is selected text.

Because we are using MCI, it is possible that multiple Editor widgets will be used. This is a concern since we are only interested in responding to the copyAvailable(bool) signal from the active Editor window, not from the others. But these signals can only ever be emitted by the active window, so this isn't a problem in practice.

The QMdiArea::addSubWindow() function creates a new QMdiSubWindow, puts the widget in as a parameter inside the subwindow, and starts building the submenu. Next, we create a QAction representing the Window menu. The action is provided by the Editor class, which we will cover in a moment. We also add the action to a QGroup object. QActionGroup ensures that only one Window menu item is checked at a time. Finally, we call show() on the new QMdiSubWindow to make it visible.
