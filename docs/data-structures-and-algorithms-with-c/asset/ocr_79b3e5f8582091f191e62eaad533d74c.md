# Time complexity of Quick Sort

Best-case time complexity: In Quick sort best case occurs when the partitions are as evenly balanced as possible; their sizes are almost equal, each partition has at most n/2 elements and the tree of subproblem sizes looks like the following figure.

![](bbox=[0.1, 0.16, 0.9, 0.4])

The total number of comparisons can be calculated recursively:

```
T(n) = {
  c, when n=1
  2T(n/2) + cn, Otherwise
}
```

Where c is a constant

Now,

```
T(n) = 2T(n/2) + cn
= 2 . [2.T (n/4) + c.n/2] + cn
= 2^2 T(n/4) + cn+cn
= 2^2 T (n/2^2) + 2cn
:
= 2^x T (n/2^x) + xcn
```

Now, let 2^x = n, therefore x = log2n

```
T(n) = nT (n/n) + cnlog2n
= nT (1) + cnlog.n
= cn + cnlog2n [hence T(1) = c]
= O (nlog n)
```

In the best case of quick sort log n passes and each pass n number of comparisons are required.
