| Key element equals to | A[0] | A[1] | A[2] | A[3] | A[4] | A[5] | A[6] | A[7] | A[8] | A[9] |
|---|---|---|---|---|---|---|---|---|---|---|
| No. of Comparisons | 3 | 2 | 3 | 4 | 1 | 3 | 4 | 2 | 3 | 4 |

Average case = 29/10 = 3 (approx) and worst case = 4

Worst-case time complexity. In worst case, total number of comparisons can be calculated recursively

```
T (n) = {
 c, when n=1
 T (n/2) + c, Otherwise
}
```

Where c is a constant

Now,

```
T (n) = T (n/2) + c
 = [T (n/4) + c] + c
 = T (n/4) + 2c
 :
 = T (n/2^r) + rc
 = T (n/n) + clog;n [when 2^r = n then r = log;n]
 = T (1) + clog;n [hence T (1)=c]
 = c + clog;n
 = c[1 + log;n]
 = O (log n)
```

The number of comparisons in [log2 n + 1] worst case is the depth or height of the binary tree. The number of comparisons in average case is approximately equals to the number of comparisons in worst case. The best case occurs when the key found at first comparison.

| Binary Searching algorithm | Best Case | Average Case | Worst Case |
|---|---|---|---|
| | O(1) | O(log n) | O(log n) |
