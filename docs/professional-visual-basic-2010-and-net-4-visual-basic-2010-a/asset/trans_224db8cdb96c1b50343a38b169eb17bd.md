转换中的代码片段

前述 XML 文档中展示的格式与电影供应商链联盟的格式不匹配。为了被供应商集体接受，你必须按如下方式转换文档：

- 删除元素 <FilmOrderList>。
- 删除元素 <multiFilmOrders>。
- 将元素 <FilmOrder> 重命名为 <DvdOrder>。
- 删除元素 <name>（影片名称不应包含在文档中）。
- 将元素 <quantity> 重命名为 HowMuch 并使 HowMuch 成为 <DvdOrder> 的属性。
- 将元素 <filmId> 重命名为 FilmOrderNumber 并使 FilmOrderNumber 成为 <DvdOrder> 的属性。
- 显示属性 HowMuch 在属性 FilmOrderNumber 之前。

转换中执行的许多步骤本可通过替代技术实现。例如，你本可以使用序列化中的源代码样式属性来生成正确的 XML 属性和 XML 元素名称。如果事先知道供应商联盟将制定标准，你本可以编写类使其基于标准进行序列化。关键在于你当时并不知道，现在一个标准（你的旧标准）必须转换为电影供应商联盟新采用的标准。你能做的最糟糕的事情就是更改正在运行的代码，然后强制所有使用该应用程序的用户升级。添加一个额外的转换步骤来应对新标准要简单得多。

实现转换的 XSLT 文件名为 ConvertLegacyToNewStandard.xslt。该文件的一部分实现如下：

```
<?xml version="1.0" encoding="utf-8"?>
<xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
    <xsl:template match="FilmOrder">
        <!-- rename <FilmOrder> to <DvdOrder> -->
        <xsl:element name="DvdOrder">
            <!-- Make element Quantity attribute HowMuch
            Notice attribute HowMuch comes before attribute FilmOrderNumber -->
            <xsl:attribute name="HowMuch">
```

```
<xsl:value-of select="Quantity"></xsl:value-of>
</xsl:attribute>
<!-- Make element id attribute FilmOrderNumber -->
<xsl:attribute name="FilmOrderNumber">
<xsl:value-of select="@id"></xsl:value-of>
</xsl:attribute>
</xsl:element>
<!-- end of DvdOrder element -->
</xsl:template>
</xsl:stylesheet>
```

在前面的 XSLT 片段中，使用了以下 XSLT 元素来促进转换：

- <xsl:template match="FilmOrder"> — 此模板 XSLT 元素中的所有操作都作用于原始文档的 FilmOrder 节点上。
- <xsl:element name="DvdOrder"> — 源文档中对应的 FilmOrder 元素在目标文档中将称为 DvdOrder。
- <xsl:attribute name="HowMuch"> — 一个名为 HowMuch 的属性将包含在之前指定的元素 <DvdOrder> 中。此 HowMuch 的属性 XSLT 元素位于 FilmOrderNumber 的属性 XSLT 元素之前。此顺序是作为转换的一部分指定的，以遵守新标准。
- <xsl:value-of select='Quantity'> — 检索源文档的 <Quantity> 元素的值并将其放置在目标文档中。此 value-of XSLT 元素的实例提供了与属性 HowMuch 关联的值。

两个新的 XSLT 术语已进入你的词汇表：element 和 attribute。这两个 XSLT 元素都名副其实。在 XSLT 中使用 element 节点会在目标 XML 文档中放置一个元素，而 attribute 节点会在目标 XML 文档中放置一个属性。ConvertLegacyToNewStandard.xsl 中的 XSLT 转换过长，无法在此处完整回顾。当完整阅读此文件时，请记住此 XSLT 文件包含内联文档，以精确指定在 XSLT 文档的哪个位置执行转换的哪个方面。例如，以下 XML 代码注释指出了 XSLT 元素 attribute 即将执行的操作：

```
<!-- Make element 'Quantity' attribute HowMuch
Notice attribute HowMuch comes before attribute FilmOrderNumber -->
<xsl:attribute name="HowMuch">
<xsl:value-of select='Quantity'></xsl:value-of>
</xsl:attribute>
```

前面的示例跨越了数页，但仅包含三行代码。这证明 XML 不仅仅是学习如何在 Visual Basic 和 .NET Framework 中使用它。其他方面，你还需要对 XSLT、XPath 和 XQuery 有良好的理解。有关这些标准的更多详细信息，请参阅 Wrox 出版的 Professional XML。

## System.Xml.Xsl 中的其他类和接口

我们刚刚仔细研究了 XSLT 和 System.Xml.Xsl 命名空间，但它远不止于此。System.Xml.Xsl 命名空间公开的其他类和接口包括以下内容：

- IXsltContextFunction — 此接口在运行时访问 XSLT 样式表中定义的一个给定函数。
- IXsltContextVariable — 此接口在运行时访问 XSLT 样式表中定义的一个给定变量。
- `XslArgumentList` — 此类包含参数列表。这些参数是 XSLT 参数或 XSLT 扩展对象。`XslArgumentList` 对象与 `XsltTransform` 的 `Transform` 方法结合使用。参数使你能够使用单个 XSLT 转换进行多次使用，根据需要更改转换的参数。
- `XslContext` — 此类包含 XSLT 处理器的状态。此上下文信息使 XPath 表达式的各个组件能够得到解析（函数、参数和命名空间）。
- `XslException`，`XslCompileException` — 这些类包含转换数据时引发的异常的相关信息。`XslCompileException` 派生自 `XslException`，并由 `Load` 方法抛出。

## ASP.NET 中的 XML

大多数以 Microsoft 为重点的 Web 开发人员通常只关注 Microsoft SQL Server 或 Microsoft Access 来满足其数据存储需求。然而，今天大量数据以 XML 格式存储，因此在改进 Microsoft 的核心 Web 技术以便轻松使用此格式方面取得了相当大的进展。

## XmlDataSource 服务器控件

ASP.NET 包含一系列数据源控件，旨在弥合你的数据存储（如 XML）与可用的数据绑定控件之间的差距。这些新的数据控件不仅使你能够从各种数据存储中检索数据，还使你能够在数据绑定到 ASP.NET 服务器控件之前轻松操作数据（使用分页、排序、编辑和过滤）。

由于 XML 的重要性，ASP.NET 中提供了一个专门的数据源控件用于检索和处理 XML 数据：`XmlDataSource`。此控件使你能够连接到 XML 数据并使用此数据与任何 ASP.NET 数据绑定控件。就像 `SqlDataSource` 和 `ObjectDataSource` 控件一样，`XmlDataSource` 控件不仅使你能够检索数据，还能够插入、删除和更新数据项。随着越来越多的用户转向 XML 数据格式，例如 Web 服务、RSS 源等，此控件是 Web 应用程序的宝贵资源。
