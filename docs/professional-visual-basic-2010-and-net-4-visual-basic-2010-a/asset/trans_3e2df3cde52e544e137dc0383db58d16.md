

有了这个结构，就可以在根据请求页面的最终用户的语言偏好，获取 LabelText 全局资源的适当值。要实现此功能，请使用关键字 Resources 后跟冒号。接下来，指定资源文件的名称。在本例中，资源文件的名称为 Resource，因为此语句会前往 Resource.resx 和 Resource.es.resx 文件以查找所需内容。在指定要使用的特定资源文件之后，语句中的下一项是键——在本例中为 LabelText。

另一种实现相同结果的方法是使用 Visual Studio 中的内置对话框。从设计视图中突出显示您在 Visual Studio 中想要的服务器控件，以便控件出现在属性窗口中。在我的示例中，我突出显示了一个 Label 服务器控件。从属性窗口中，单击表达式属性内的按钮。这会启动表达式对话框，您可以在其中将 LabelText 值绑定到控件的 Text 属性，如图 27-15 所示。

![](img/d99870e80390742f93963da7be0b2e61_924_0.png)

## RESOURCE FILES IN WINDOWS FORMS

与 ASP.NET 一样，您也可以使用 Visual Studio 为 Windows 应用程序使用资源文件（.resx）。要了解如何本地化 Windows 窗体应用程序，您需要重新打开本章前面介绍的 ProVB_2010Localization 项目。在本例中，您将在 Localization 项目中添加一个名为 UsingResx.vb 的新窗体。

与本章前面描述的 ASP.NET 窗体（并标识为“ASP.NET page code block”）类似，此 Windows 窗体对话框应包含几个 Label 控件、一个 Button 和一个 TextBox 控件。最初，您的窗体（及其控件）应如下图 27-17 所示。

![](img/d99870e80390742f93963da7be0b2e61_925_1.png)

### FIGURE 27-17

在开始之前，为窗体打开本地化功能。请记住，以下步骤也可以用于已存在的窗体，如果您将现有窗体转换为处理多种语言。

在设计器中选择窗体，转到属性窗口并将 Localizable 属性更改为 True。这使您可以将多种语言应用于窗体，并将特定文化的元素存储在资源文件中。

在将 Localizable 属性设置为 True 之后，您可以为窗体上的控件提供替代语言值。您当前分配给控件的属性是针对默认语言设置的。

与 ASP.NET 一样，如果文化未确定或此文化没有可用的资源文件，则使用默认设置。要创建新的语言特定资源集，第一步是将窗体的 Language 属性更改为所需的语言。您可以在窗体的 Language 属性中找到此设置，如图 27-18 所示。

请注意，属性窗口列出的选项不仅包括芬兰语，还包括芬兰语（芬兰）等特定于文化的选项。与 ASP.NET 一样，选择语言可以加快创建应用程序的本地化版本的过程，而无需创建特定于国家的资源。从图 27-18 所示的语言属性窗口中，选择芬兰语作为语言，然后按如下方式更改三个控件的值：

```
Button1.Text    Lähetä Nimi
Label1.Text    Mikä sinun nimi on?
Label2.Text    Hei
```

    End Sub
    Private Sub Button1_Click(ByVal sender As System.Object,
