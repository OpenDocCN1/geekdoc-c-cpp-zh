A common programming mistake in a while condition using a logical operator is to use && when you should use || or vice versa. While the logical && operator may seem the obvious choice in this example, the correct choice in other situations may be less intuitive. If you want to loop a number is not between 1 and 10, the loop would be while (num < 1 || num > 10)? The answer is latter: the condition always would be false using the && operator since a number cannot be less than 1 and greater than 10. If you wanted to use the condition instead would be while (num > 1 && num < 0).

Note

The first condition is if num <= 0. If this expression is false, the data is valid, so the issue of whether the user wants to quit does arise. Accordingly, the second condition, quit is true, is not even evaluated. As discussed in Chapter 7, with a logical && operator, the expression is evaluated only if the rest is true. Therefore, the loop ends with the value of quit being true, its initialized value, and code execution continues with the if / else statement following the loop.

However, if num <= 0 is true, then the data is invalid, and the second condition quit is true, is evaluated.

The value of quit may be true either to enter data or under two possibilities. The first possibility is that this is the user's first attempt to enter data and the data was invalid. In this case, the user has not yet been asked whether they want to quit. It is assumed they don't have the opportunity to answer when they want to retry. Therefore, the quit variable is initialized to the value of false when it is declared.

The second possibility is that this is the user's or later attempt to enter data and the data was invalid. In this case, the user has already been asked whether they want to quit, so the value of quit is based on the user's answer.

If the value of quit is false, the loop continues. If the user wants to quit, then the expression quit == false will be false because the value of quit is true. Therefore, the loop ends with the value of quit being true, and code execution continues with the if / else statement following the loop.

At some point (hopefully) the loop will end, either because the user has entered a valid number or has not decided to quit trying. Code execution then continues with the if / else statement following the loop.

The value of quit being false nearly indicates that the user entered valid data, because if they were still trying to do so, the loop would not have ended. Conversely, the value of quit being nearly indicates that the user entered valid data.

Accordingly, we use the value of quit in the if / else statement after the loop ends because the user entered valid data or decided to quit entering invalid data.

Thus, inside the loop, quit is a flag whose value indicates whether the user wants to try again, and after the loop ends, quit is a flag whose value indicates whether the user entered valid data.
