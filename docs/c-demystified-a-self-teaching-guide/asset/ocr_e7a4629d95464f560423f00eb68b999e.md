```
{
string name;
int age;
cout << "Enter name: ";
cin >> name;
cout << "Enter age: ";
cin >> age;
printMessage(name, age);
return 0;
}
void printMessage(string stringName, int theAge) {
  cout << "Your name is " << theName
  << " and your age is " << theAge << endl;
}
```

There is some sample input and output (fortunately the program has no way to verify
age):

+   - Enter first name: Jeff Kent
- Enter age: 21
- Your name is Jeff Kent and your age is 21

The call and function header here are
printMessage(name, age);
void printMessage(string stringName, int theName)

The first argument of the printMessage function expects a string, it is critical that the
first argument in the function is a string. Similarly, the second of the
printMessage function expects an integer, so it is critical that the second argument in the
function is an integer. If the arguments in the function were reversed, as in:
printMessage(age, name);

then the consequence would not be illogical as in the prior example, but instead a
compiler "cannot convert parameter 'int' to 'string." This is because the
compiler was expecting from the function prototype that the first argument (or parameter)
would be a string, not an int.

# Passing Arguments by Reference

Passing arguments by value is fine when you don't want to change their value in the
called function. The printMessage function did not change the value of its arguments; it
simply outputted them.

However, sometimes the intent of a function is to change the value of the argument
passed to it. Consider the following example, in which the doublet function is supposed to
double the value of the argument passed to it:

```
#include <iostream>
using namespace std;
void doubleIt(int);

int main() {
  int num;
  cout << "Enter number: "; }
```
