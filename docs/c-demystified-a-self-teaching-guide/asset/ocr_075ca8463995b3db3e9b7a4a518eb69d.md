Dynamic memory allocation works, even though using dynamic memory, memory is not being allocated at compile time. Instead, memory is being allocated at runtime, and from a different place (the "heap") rather than it is allocated at compile time (the "stack")

**Note** The terms used are used to identify different areas of memory: the stack for memory allocated at compile time; the heap for memory allocated at runtime

While you dynamically allocate a single variable, normally memory allocation is used with arrays (as in this example), or objects with such structures or classes, which are discussed in Chapter 14.

You need to dynamically allocate memory. The pointer must be the same data type as the array that is to be allocated. An assignment statement is used, in the following statement from the program:

```
int * IPtr = new int[numTests];
```

The pointer is on the left side of the assignment operator. Immediately to the right of it, whose purpose is to dynamically allocate memory. The array that is to be allocated immediately follows the operator, declared by data type and size declar in [], with no name. The size declar be a variable of literal or constant.

Since the array has no name, and its elements are referred to the pointer that created it, in loops used to assign values or output the values of the array elements. Therefore, the scope of the dynamically created array is the same as the scope of the pointer to declare it.

The significance of dynamic memory allocation is not scope, but lifetime. Like a global variable or a static variable, the lifetime of a dynamically created variable is as long as that of the program's execution. However, if before the end of the program that points to a dynamically created variable goes out of scope, you no longer have any way of accessing that memory. The dynamically created variable still takes up memory, but is inaccessible. This is called a memory leak.

Having programs dynamically allocate memory but never release it, like a library where patrons check out books but never return them. Sooner or later the library will run out of books, and the program will run out of memory.

A memory leak is not a particular concern in the preceding program since the pointer that points to the dynamically allocated memory does not go out of scope immediately before the program ends. However, if you dynamically allocate inside a function using a local pointer (as in the program the next section), when the function terminates, the pointer will be destroyed but the memory remains, orphaned since there is no longer a way of accessing it for the remainder of the program.
