The following program modifies the previous by assigning the user input to a variable (so far so good) and attempting to assign variable to the constant (not good):

```
#include <iostream>
using namespace std;
int main () {
    const int numTests = 3;
    int num;
    cout << "Enter the number of test scores:";
    cin >> num;
    numTests = num;
    int testScore[numTests];
    return 0;
}
```

Once again, the result is a compiler error. The compiler will fail to assign a value to the constant (numTests = num); the error message will be different than in the previous example, that "l-values const object." The 1 in "l-value" is a small L, not the number one, and refers to the value to the left of the assignment operator. This is another way of saying you can't assign a value to a constant after you.

While you can use a constant instead of a literal to declare the size of an array, the question remains why not the trouble of doing so? The reason is that in your code you need to often refer to the size of the array, not only when declaring it, but also, when assigning values to, and displaying them, the array. However, the needs of the program may require you to modify the code to change the size of the array, usually to make it larger. For example, if as a teacher I change my policy from giving three tests to five. If I need to change the size of the testScore from three to five, I have to find each time it is referred to in the program and change it to 5. Not only is this time-consuming, but the risk of missing a reference increases to change. By contrast, if I use a constant, as const int numTests = 3, then all I need to change the 3 to 5 in one place, and I'm done.

You, "Wait, you just told me earlier in that you can't resize an array." Yes, you cannot resize an array while the program is running. You can change the size of the array in the code, and then recompile the program.

Constants have many uses in addition to signifying the size of an array, and those uses will be covered in this and further chapters of this book.
