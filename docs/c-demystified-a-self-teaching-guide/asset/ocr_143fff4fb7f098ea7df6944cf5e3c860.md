# Using an IDE to Create and Run the “Hello World!” Project

You can use any plain-text editor such as Notepad to write the source code. You can also download a free compiler, which usually includes a preprocessor and linker. Then you can compile and run your code from the command line. The command line may be, for example, a DOS prompt at which you type a command that specifies the action you want, such as compiling, followed by the name of the file you want to.

While there is nothing wrong with using a plain-text editor and command line tools, programmers, including me, to create, compile, and run their programs in a C++ Integrated Development Environment, known by the acronym IDE. The term "integrated" in IDE means that the editor, preprocessor, compiler, and linker are all together under one (software) root. Thus, the IDE enables you to create, compile, and run your code using one program rather than separate programs. Additionally, most IDEs have a graphical user interface (GUI) that makes them easier to use than a command line. Finally, many IDEs have added features that ease your task of finding and fixing errors in your code.

The primary disadvantage of using IDEs is that you have to purchase them (though there are some free ones). They also require additional drive space and memory. Nevertheless, obtaining an IDE since it enables you to run on C++ programming issues without distractions as figuring out the right commands to use on the command line.

There are several IDEs on the market. Microsoft's, called Visual C++, can be obtained separately or as part of Microsoft's Visual Studio subscription. Roland offers C++ Builder, both in free and commercial version. IBM has a VisualAge C++ IDE. There are a number of others as well.

In this book I will use Microsoft C++ .NET 2003 IDE since I have to to. However, most IDEs essentially work the same way, and your code will compile and run the same no matter which IDE you use as long as you don't use any libraries custom to a particular IDE. The standard library files will be being, such as iostream, the same in all C++ IDEs.

Additionally, I am running the code on a Windows 2000 operating system. The results should be similar on other operating systems, not just Windows operating systems, but additional types of operating systems as well, as UNIX.
