graphically the result of declaring a three-element integer array such as int testScore[3]; The base address of an array is the address where the array begins. Figure 10-1, the base address of the testScore array is 101.

```
int testScore[3];
```

| Index | 0 | 1 | 2 |
|---|---|---||}{
| Offset* | 0*=4 | 1*=4 | 2*=8 |
| Address | 101 | 105 | 109 |

* Assumes integer type is 4 bytes

**Figure 10-1:** Indices of a three-element array

The address of the first element of the array in Figure 10-1, 101, is the same as the base address of array itself. Therefore, the value that would be added to the base address to obtain the address of the first element of the array is 0, which is the index of the first element of the array.

The address of the second element of the array is the base address of the array, 101, plus one times the size of the data type of the array, 4, which is 101 + (1 × 4), or 105. Similarly, the address of the third element of the array is the base address of the array, 101, plus 2 times the size of the data type of the array, 4, which is 101 + (2 × 4), or 109.

Thus, the address of any element of the array is the base address plus the offset, and in turn the offset is determined by the index of the array multiplied by the size of the array's data type.

Note We will revisit addresses and offsets in the next chapter on pointers.

Since the first index in an array must always be 0, the index in an array must be less than the number of elements in the array. If you were counting numbers, starting at 1, the last element would be number 3. However, if you are starting at 0 instead of one, the last number would be 2, not 3.

Caution

A common programming mistake is to assume the index of the last element is equal to the number of elements in the array. As you will learn in this, this can result in (depending on the compiler) run-time errors or unpredictable results, which is not good.

At this point, we have not assigned a value to any of the elements of the array. The value of each element will be some strange number as -858993460. As discussed in Chapter 3, the program does its best to interpret whatever value is at a given memory address, perhaps left over from other memory, but the resulting output makes little sense.
