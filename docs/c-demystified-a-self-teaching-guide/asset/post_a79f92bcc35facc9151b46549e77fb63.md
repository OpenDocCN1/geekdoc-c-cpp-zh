
The CPU can access RAM almost as quickly as cache memory. Additionally, the amount of RAM available to store instructions and data is much larger than the amount of cache memory.

However, RAM, like cache memory, is temporary. Instructions and data contained in memory are lost once the computer is powered down. You may have had the unpleasant experience of losing unsaved data when your computer suffered a power failure, or had to be rebooted.

Additionally, we would want the data to remain intact after the program ended, even if the computer is rebooted or powered off. That is not possible with RAM.

Furthermore, your computer likely has many other programs, for e-mail, Internet, word processing, and so on, that you may not be using right now, but you may want to use in the future. Likewise, your computer may also have other files, such as term papers, letters, tax spreadsheets, e-mail messages, and so on, that you may not be using right now but you may want to use in the future. Accordingly, we need another memory location, unlike cache memory or RAM, persistent—that is, it will persist even though the computer is rebooted or turned off.

# Persistent Storage

That other, persistent type of computer memory is naturally enough, persistent storage. This is usually a hard drive, but also could be, among other devices, a CD-ROM or DVD-ROM, floppy or disk zip, or optical drive. No matter what storage device is used, persistent is lasting; instructions and data remain stored even when the computer is powered down. Thus, your computer can be turned off for months, but when it is turned on, the files you previously saved are there.

Persistent storage, in addition to being lasting, also has a much larger capacity than RAM—about one hundred thousand times larger.

Since persistent storage has the advantage of lasting and having a large capacity, it is used to store programs and data. For example, if you used Microsoft Word on your computer, the files for your program would be stored on your hard drive. If you prepared documents using that program, those likewise would be saved as files on your hard drive.

While persistent storage has the advantages of being lasting and having a large capacity, a computer program cannot execute instructions located in persistent storage. The instructions must be loaded from persistent storage into RAM. Similarly, a computer program cannot manipulate data located in persistent storage. This data must be loaded from persistent storage into RAM.

- **Note** Beyond the scope of this chapter, persistent storage also can serve as a backup to RAM, and when serving this is called virtual memory or swap space.

Generally, computer programs use RAM to store instructions and data, so RAM will be our focus in discussing memory. However, much of the discussion of memory may also apply to persistent storage. CPU cache memory is a different subject, discussed more in connection with programming languages, such as assembly language, that are far closer to machine language than C++.

# Addresses

When someone asks where you live, you may answer 1313 Mockbird Lane. That is your address.

Addresses are used to locate persons or places. Addresses usually follow a logical pattern. For example, the addresses on one block may be from 1300 to 1399, the next from 1400 to 1499, and so on.

Locations in memory also are identified by address. These addresses look quite different than the street addresses we use, since they are expressed as hexadecimal (Base 16) numbers such as 0xfc1. However, regardless of how the number is written, as shown in Figure 2-1, memory addresses follow the same logic, sequential pattern as street address, one number numbering after another.

- **Hexadecimal Numbers**—We use numbers that are decimal, or Base 10, in which each digit is 0 and 9. Since 10, 11, 12, 13, 14, and 15 are not single digits, it is expressed as a, 11 as b, 12 as c, 13 as d, 14 as e, and 15 as f. The number 16 in decimal is expressed as 10 in hexadecimal. Memory addresses can be large values, which may be written more compactly in hexadecimal. For example, 1,000,000 in decimal is F4240 in hexadecimal.

Converting hexadecimal and decimal is explained in the upcoming section, "Converting Between Decimal and Hexadecimal."

# Bits and Bytes

While people live at street addresses, what is stored at each memory address is a byte. As discussed in Chapter 1, early computers were a series of switches, one representing on, zero representing off. In computer terminology, a *bit* is either 0 or 1. However, a computer cannot process information as a single bit. Eight bits, or one *byte*, is the smallest unit of information that a computer can process. Accordingly, each address stores up to one byte of information. Thus, just as a street address may be used to locate people who live there, a memory address can be used to locate a value.

# Binary System

The information stored at a memory address, a series of ones and zeros, has little meaning to most of us. However, to a computer, a sequence of ones and zeroes is quite meaningful. For example, 11110000 is binary, or base 2. Each number in binary is represented by a digit that is 0 or 1. The reason both decimal and binary numbers are involved in programming is because both humans and computers are involved.

# Converting Decimal and Hexadecimal

You can write computer programs without knowing how to convert binary and decimal. However, knowing how to do so is not difficult and may help your understanding of what happens behind the scenes. Converting a number from binary to decimal is simple. Going from right to left, the rightmost binary digit is multiplied by $2^0$, the second binary digit from the right is multiplied by $2^1$, the third binary digit from the right is multiplied by $2^2$, and so on, through all the binary digits. The results of each multiplication are added, and the result is the decimal equivalent of the binary number. Table 2-1 shows this calculation for the binary equivalents of the numbers 1 through 5 in decimal.

# Table 2-1: Binary Equivalents of the Numbers 1 through 5 in Decimal

| Binary | Calculation | Decimal |
|---|---|---|
| 0 | $0 \times 2^0 = 0 \times 1$ | 0 |
| 1 | $1 \times 2^0 = 1 \times 1$ | 1 |
| 10 | $(0 \times 2^1) + (1 \times 2^0) = 0 + 2$ | 2 |
| 11 | $(1 \times 2^1) + (1 \times 2^0) = 2 + 1$ | 3 |
| 100 | $(0 \times 2^2) + (0 \times 2^1) + (1 \times 2^0) = 0 + 0 + 4$ | 4 |
| 101 | $(1 \times 2^2) + (0 \times 2^1) + (1 \times 2^0) = 4 + 0 + 1$ | 5 |

Converting a number from decimal to binary is almost as easy. Let's use 5 in decimal as an example.

1. You find the largest power of 2 that can be divided into 5 with a quotient of 1. The answer is $2^2$, or 4.
2. Remember when converting from binary to decimal, the rightmost binary digit is multiplied by $2^0$, or 1, the second binary digit from the right is multiplied by $2^1$, the third binary digit from the right is multiplied by $2^2$, and so on. Since the exponent is 2, a binary 1 goes into the third binary digit from the right, so the binary number now is 1?? representing each binary digit we still need to calculate.
3. When you divide 5 by 4, the remainder is 1. You next try to divide 1 by the next lowest power of 2, $2^1$, or 2. The quotient is 0, so a binary 0 goes into the second binary digit from the right. The binary number now is 10?.
4. When you divide 1 by 2, the remainder is still 1. You next try to divide 1 by the next lowest power of 2, $2^0$, or 1. The quotient is 1, so a binary 1 goes into the rightmost binary digit. The binary number now is 101, and we're done.
