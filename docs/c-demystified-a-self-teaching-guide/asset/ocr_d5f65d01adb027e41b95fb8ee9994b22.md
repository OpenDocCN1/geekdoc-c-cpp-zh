# Assigning a "Compatible" Data Type

The data types in the cin statement may be different. In this example, the data type of the first variable is a string, whereas the data type of the second and third variables is an integer.

What is important is that the order of the input changes the order of the data types of the variables in the cin statement. The input order "Jeff," 200 is assigned to the variables in the order of their appearance in the cin statement, myName, myWeight, and myHeight. Therefore, "Jeff" is assigned to the string myName, 72 to the integer variable myWeight, and 200 to the integer variable myHeight.

The importance of the order of the input matching the order of the data types in the cin statement is demonstrated by changing the order of the user's input from "Jeff," 200, and 72 to 200, "Jeff," and 72. The program output then would be

```
Enter your name, weight in pounds and height in inches
The three inputs separated by a space
200 Jeff 72
Your name is 200
Your weight in pounds is -858993460
Your height in inches is -858993460
```

While I like to lose weight, -858993460 seems a bit extreme. Also, while it is understandable why "Jeff" cannot be assigned to my 72, nor was 72 assigned to my height.

The one output that is correct is the name. Characters, including digits, can be part of a string. Therefore, 200 may be an unusual name to us, it is perfectly OK for cin, which enforces 200 to the string variable *name*.

Why -858993460 was outputted for myWeight has also been explained earlier in the example where the user entered "Jeff" at the prompt to enter a test score.

However, 72 would be a valid value for cin to assignment to the integer variable *myHeight*. Why wasn't 72 the output for height?

The reason is that the next value for cin is not 72, but instead "Jeff." Since cin was unable to assign "Jeff" to *myWeight*, the value remains in line for assignment, to the variable *myHeight*. Unfortunately, cin was unable to assign "Jeff" to *myHeight* either, so the value of *myHeight*, like *myWeight*, is also outputted as -858993460.
