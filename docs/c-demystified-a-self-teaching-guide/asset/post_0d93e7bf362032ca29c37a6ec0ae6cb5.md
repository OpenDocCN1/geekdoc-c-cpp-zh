
# Data Types

The ones and zeroes that may be stored at a memory address may represent text, such as my name, Jeff Kent. These ones and zeroes instead may represent a number, as my height in inches, 72, or a number with digits to the decimal point, as my GPA in high school, I'll say I was 37.5 (honestly don't remember, it was too long ago). Alternatively, the ones and zeroes may represent either true or false, as I am a U.S. citizen.

Data comes in many forms, and is generally either numeric or textual. Additionally, some numeric data uses these numbers, such as 6, 0, or –7, while other numeric data uses floating-point numbers, such as 6., and -6.1.

There are different data types for each of the many forms of data. The data type you choose will affect not only the form in which the data is stored, but also the amount of memory required to store it. Let's now take a look at these different data types.

# Whole Number Data Types

We deal with numbers all the time. Think of the answers to questions such as how many cars are in the parking lot, how many classes are you taking, or how many brothers and sisters do you have? Each answer involves a number, with no need to express any value to the decimal point. After all, who has 31 brothers and sisters?

Often, you don't need a large number. What unfortunate student would need 754,361 classes at most one? However, the whole number needs to be large. For example, if you are studying astronomy, the moon is approximately 240,000 miles from Earth. Indeed, the whole number may need to be very, very large. Pluto's minimum distance from Earth is about 2.7 billion miles.

Many times, the whole number won't be negative. No matter how badly you do on a test, chances are you won't score below zero points. However, some numbers may be below zero, such as the temperature at the North Pole.

Because of the different needs numbers may have many, there are several different number data types (shown in Table 2-2). The listed sizes and ranges are typical, but may vary depending on the compiler and operating system. In the size/operator section later in this chapter, you will determine through code the different data types on your compiler and operating system.

# Unsigned vs. Signed Data Type

Table 2-2 lists three data types: short, int, and long. Each of these three data types has either the unsigned in front of it or not at all—as in unsigned short and short.

Unsigned means the number is always zero or positive, negative never. Signed means the number may be negative or positive (or zero). If you don't specify signed or unsigned, the data type is presumed to be signed. Thus signed and short are the same.

Since an unsigned data type means its value is 0 or positive, negative never, Table 2-2 shows the smallest value of an unsigned short is therefore; an unsigned short cannot be negative. By contrast, the smallest value of a short is -32,768, since a signed data type may be negative, positive, or zero.

# Size

Each of the whole number data types listed in Table 2-2 has a size. Indeed, all C++ types have a size. However, unlike people, the size of a data type is not expressed in inches or pounds (a subject for most), but in bytes.

Since a byte is the smallest unit of address that a computer can process, no data type can be smaller than one. Most data types are larger than one; the whole data types listed in Table 2-2 are too. However, regardless of the size, the number of bytes is a whole number. You cannot have a data type size of 3.5 bytes because .5 bytes, or 4 bytes, is too small for the computer.

Generally, the number of bytes for a data type is the result of a power of 2 since computers use a binary number system. Thus, typical data sizes are 1 byte (2⁰), 2 bytes (2¹), four bytes (2²), or eight bytes (2³).

The size of a data type matters in two respects: (1) the range of different values that the data type may represent and (2) the amount of memory required to store the data type.

# Range

Range means the highest and lowest value that may be represented by a given data type. For example, the range of the unsigned short data type is 0 to 65,365. These lowest and highest values are not arbitrary, but instead can be calculated.

The number of different values that a data type can represent is 2ⁿ n being the number of bits in the data type. The size of a short data type is 2 bytes, or 16 bits. Therefore, the number of different values that the short data type can represent is 2¹⁶, which is 65,536.

However, the highest value that an unsigned short can represent is 65,535, because the unsigned data type starts at 0, not 1. Therefore, the highest that an unsigned data type may represent is 2ⁿ-1 n being the number of bits in the data type, and the minus 1 being used because we are starting at 0, not 1.

Signed data types involve an addition. Since the range of a signed data type includes negative numbers, there needs to be a way of determining whether a number is positive or negative. We determine if a decimal number is positive or negative by looking to see if the number is preceded by a negative sign (−). However, a bit can only be 0 or 1; there is no option for a negative sign in a binary number.

There are several explanations in science for the representation of negative numbers, such as signed magnitude, complement and two’s complement. We don't need to get into the complexities of these explanations.

For example, a signed data type, like an unsigned data type, can represent 2¹⁶ or 65,536 different numbers. However, with a signed data type, numbers must be split evenly between starting at zero. To do this, the ranges would be 0 to 32,767 and -32,768. This can be confirmed by Table 2-2, which shows the range of a signed data type as −32,768 to 32,767.

Another way of explaining the range of the signed short data type is that one of the bits is used to store the sign, positive or negative. The highest number in the range is 2¹⁵−1, or 32,767; the minus 1 being used because we are starting at 0, not 1. The lowest number in the range is -(2¹⁵), or −32,768; there is no minus 1 because we are starting at -1, not.

# Storage

In binary, 65365 as an unsigned short is represented by sixteen: 1111111111111111. You cannot fit 16 bits into a single memory address. A memory address can hold only 8 bits, or bytes. How can you store this value in memory?

The answer is you need two addresses to store 65365 in decimal. This provides two bytes of storage, sufficient to store this value. This is why the short data type requires 2 bytes of storage. Figure 2-3 shows how this value would be stored as a short data type.
