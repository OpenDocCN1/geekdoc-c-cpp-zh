## Second Argument—File Mode

The second argument of the open function defines the mode in which the file should be opened. One choice is whether the file should be opened for writing, reading, or both. There are other choices, each called a file mode flag. Table 13-1 lists the file flags:

## Table 13-1: File Mode Flags

| File Mode Flag | Description |
| --- | --- |
| ios::app | Append mode. The file's existing contents are preserved and all output is written to the end of the file. |
| ios::ate | If the file already exists, the program goes directly to the end of it. Output may be written anywhere in the file. This flag usually is used with binary mode. |
| ios::binary | Binary mode. Information is written to the file in binary format, rather than in the default text format. |
| ios::in | Input mode. Information will be read from the file. The file will not be created if it does not exist. |
| ios::out | Output mode. Information will be written to the file by default, the existing file contents will be overwritten. |
| ios::trunc | If the file exists, its contents are truncated, another for deleted or overwritten. This is the default mode of ios::out. |

If you use the ofstream object to open a file, you do not need any file mode flags. The examples in the previous section did not use any file mode flags. An ofstream object may only be used to open a file for writing, and cannot be used to open a file for reading. There is no need to specify the ios::out flag; that is implied by use of the

Now you may want to use one or more file mode flags with the open function of ofstream if you do not want the default, which is text rather than binary mode and overwrite append to the existing file. One example of when you want to append is an error log file, which keeps track of errors that may occur in a program. When a new error occurs, you don't want to erase the history of prior errors, but rather you want to add to that history.

You can combine two or more flags when opening a file. For example, the following statements open file in binary mode and append rather than to overwrite. The two file mode flags are combined using the bitwise operator (|):

```cpp
ofstream outfile;
outfile.open("students.dat", ios::binary | ios::app);
```

**Note** The bitwise operator | is not the same as the logical or operator || even though they share the same name or the keystroke |.

While you do not need to specify any file mode flags if you use the *fstream* object to open a file, whereas an *ofstream* object may only be used to open a file for writing and not reading, an *fstream* object may be used for both purposes. Therefore, you should specify whether you are using the open member function of the *fstream* object to open the file for writing, or both.

The following code fragment uses the open member function of the *fstream* object to open the file for writing only:

```cpp
fstream a;
afile.open("students.dat", ios::out);
```

## The fstream or ofstream Constructor

You may also use the *fstream* or *ofstream* constructor to open a file for writing. A *constructor* is a function that is automatically called when you want to create an instance of an object.

An object instance is akin to a variable of a primitive data type, such as an int. For example, the following statement could be characterized as creating an instance, named age, of an integer:

```cpp
int age;
```

Similarly, the following statement creates an *fstream* instance named *afile*:

```cpp
fstream afile;
```

Object constructors can be overloaded, that for the same object there may be a constructor with no arguments, a constructor with one argument, a constructor with two arguments, and so forth. For example, the previous statement, *fstream afile*, is called the no-argument constructor of the *fstream* object.

The following statement calls the no-argument constructor of the *ofstream* object, both creating an *ofstream* instance and opening the file *students.dat* for output:

```cpp
ofstream outFile("students.dat", ios::out);
```

The following statement calls the two-argument constructor of the *fstream* object, both creating an *fstream* instance and opening the file *students.dat* for output:

```cpp
fstream afile("students.dat", ios::out);
```

In essence, an *ofstream* (or *fstream*) variable in one statement and calling the open member function in a second statement is analogous to declaring a primitive variable in one statement and then assigning it a value in a second statement, such as:

```cpp
int age;
age = 39;
```

By contrast, using the one or two argument *ofstream* (or *fstream*) constructor is analogous to initializing primitive variable, such as:
```cpp
int age = 39;
```

One alternative is not inherently better than the other. The specific needs of a particular program will dictate which alternative better fits your needs.

## Opening a File for Reading

The primary difference between opening a file for reading and for writing is that you can write to a file that does not exist—the operating system simply creates it—you cannot read from a file unless it already exists. Therefore, you should check if the file was opened before you attempt to read it.

If the file could not be opened for reading, the value of the istream object that called open is NULL. You may recall from Chapter 11 that NULL is a constant defined in standard library whose value is zero. Alternatively, if the file could not be opened, the istream object's fail function returns true, which is the function's return value if operation was not successful.

The following code illustrates the use of both checking if the istream object used to call the open function is NULL and the istream object's fail function returns true:

```cpp
#include <fstream>
#include <iostream>
using namespace std;

int main ()
{
    ifstream infile;
    infile.open("students.dat");
    cout << "" << infile << " " << endl;
    cout << "" << infile.fail() << " = " << infile.fail() << endl;
    return 0;
}
```

If the students.dat file does not exist, the output would be

```
(infile) = 00000000
(infile.fail()) = 1
```

However, if there was a named students.dat in the same directory as your program, then the output would be

```
(infile) = 0012FE40
(infile.fail()) = 0
```

The value, 0012FE40, is the address of the istream variable, and could be different if you run this program again.
