While the delete operator operates on a pointer, the delete operator does not delete the pointer. Instead, the delete operator deletes the memory at the address pointed to by the pointer.

Otherwise, you no longer have a way of accessing the dynamically created memory. The result would be a memory leak.

## Returning Pointers from Functions

In Chapter 10, you learned several ways to initialize a character array. The following program shows you an additional way:

```cpp
#include <iostream>
using namespace std;
char * setName();

int main (void)
{
    char* str = "Jeff Kent";
    cout << str;
    return 0;
}
```

With some sample input and output:

Enter your name: Jeff Kent
Your name is Jeff Kent

The key statement is

```cpp
char* str = "Jeff Kent"
```

This statement is almost the same as:

```cpp
char str[] = "Jeff Kent"
```

In both statements, str is a character pointer, and implicit sizing is used. The difference is that str in the first statement (char* str) is a variable pointer whereas str in the second statement (char str[]) is a constant pointer.

## Returning a Pointer to a Local Variable (Not a Good Idea)

Now, following the advice in Chapter 9 to make your program more modular, try to write a separate function, setName, to obtain your input. The setName function creates a character array, assigns user input to that array using the getline function of the cin object, and returns a pointer to that character array. The address which is returned by the setName function is then assigned to the character pointer str in main. The following program implements this concept:

```cpp
#include <iostream>
using namespace std;
char * setName();

int main (void)
{
    char* str = setName();
    cout << str;
    return 0;
}
```

```cpp
char* setName (void)
{
    char name[80];
    cout << "Enter your name: ";
    cin.getline(name, 80);
    return name;
}
```

The following is some sample input and output:
Enter your name: Jeff Kent ......................D ..................

While the output name is interesting, it would be difficult to write and in any event, it is not what I input. What went wrong is that the pointer returned by the setName function points to a local array whose lifetime ended when the function finished executing and returning control to main.

Accordingly, the intended solution is to extend the lifetime of that character to the life of the program execution itself. One way to accomplish this is by making the character a global variable, but as you should recall Chapter 9, there are other and better alternatives.

## Returning a Pointer to a Static Local Variable

One superior alternative is to make the character array in setName static, as in the following program:
```cpp
#include <iostream>
using namespace std;
char * setName();

int main (void)
{
    char* str = setName();
    cout << str;
    return 0;
}
```

```cpp
char* setName (void)
{
    static char name[80];
    cout << "Enter your name: ";
    cin.getline(name, 80);
    return name;
}
```

The output from the following sample input now looks much better:
Enterter your name: Jeff Kent
Jeff Kent

This works because while the scope of a static value is limited to the function in which it is declared, its lifetime is not similarly limited, but instead lasts as long as the execution of the program. Therefore, the pointer returned by the setName function points to a local array whose lifetime, if it declared with the static keyword, persisted after the setName function finished executing and returning control to main.

## Returning a Pointer to a Dynamically Created Variable

Another alternative, which you learned in this chapter, is dynamic memory allocation:

```cpp
#include <iostream>
using namespace std;
char * setName();

int main (void)
{
    char* str;
    str = setName();
    cout << str;
    delete [] str;
    return 0;
}
```

```cpp
char* setName (void)
{
    char* name;
    name = new char[80];
    cout << "Enter your name: ";
    cin.getline(name, 80);
    return name;
}
```

This works because the pointer returned by the **setName** function points to a character array whose lifetime, since it declared using dynamic memory allocation, persisted after the **setName** function finished executing and returned control to **main**.

As discussed in the previous section, if you dynamically allocate memory inside a function using a local pointer, when the function terminates, the pointer will be destroyed but the memory will remain, orphaned since there is no longer a way of accessing it for the remainder of the program. This problem is avoided in this program because the pointer's address is returned by the **setName** function and is assigned in **main** to another pointer variable, *str*. The pointer variable *str* is then used at the end of **main** with the delete operator to deallocate the character array which was dynamically allocated in the **setName** function.

This is an example where different pointers point to the same memory address. However, in the case you use one of pointers with the delete operator, do not make the common mistake of using another of the pointers with the dynamically created memory. You should only use the delete operator with a pointer that points to dynamically created memory. If that dynamically allocated memory has already been deallocated using the delete operator, using the delete operator second time will lead to unpredictable results.

## Summary

A pointer is a variable or constant whose value is the address of another variable or constant. Other C++ tasks are performed more easily with pointers, while other C++ tasks, such as dynamic memory allocation, cannot be performed without pointers.

Like any variable or constant, you must declare a pointer before you can work with it. The only difference between declaring a pointer and a variable or constant which stores a value instead of an address is that the pointer declaration includes an asterisk as the data type and name. However, the data type in the declaration of a pointer is not the data type of its value, as is the case with a variable or constant which stores a value instead of an address. The actual data type of all pointers, whether integer, float, character, or otherwise, is the same: a hexadecimal value represents a memory address. The data type in the declaration of a pointer refers to the data type of another variable (or constant) whose address is the value of the pointer. In other words, the value of an integer pointer must be the address of an integer variable or constant, the value of a float pointer must be the address of a float variable or constant, and so forth.

You should explicitly assign a pointer value before you use it; otherwise, you risk a runtime error or worse. When you are ready to assign a pointer to the address of another variable or constant, it is too early in your code to know which address to assign to the pointer, unless you first assign NULL, which is a constant defined in standard libraries, including iostream. The value of NULL, the memory address 0, signals that the pointer is not intended to point to an accessible memory location.

The indirection operator is used on a pointer to obtain the value of the variable or constant to which the pointer points. This operation is said to dereference the pointer.

A pointer may be a variable or a constant. The name of an array is a constant pointer, pointing to the base address of the array. A pointer variable, being a variable, may point to different variables or constants at different times.

A pointer variable may be incremented. Incrementing a pointer is common when looping through consecutive indices of an array. Incrementing a pointer does not necessarily increase its value by 1. Instead, incrementing a pointer increases its value by the number of bytes of its data type.

Pointers may be passed by reference arguments. This is commonly used to note that an argument is a pointer. The difference in syntax between passing by reference and passing by address is that, in the function prototype, you use an ampersand (&) for passing by reference, but an asterisk (*) for passing by reference. Additionally, if the pointer argument is the name of a single variable passed to an array, there are two further differences in syntax between passing by reference and passing by address. When you call the function, you don't need to use the address operator (&) for passing by reference, but you do for passing by address. In the body of the called function, you don't need to dereference the argument when you pass it by reference, but when you pass it by address.
