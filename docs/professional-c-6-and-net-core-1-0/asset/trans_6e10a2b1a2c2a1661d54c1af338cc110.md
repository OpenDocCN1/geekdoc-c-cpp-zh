### 在运行时检查代码与动态编程

本章重点介绍自定义特性、反射和动态编程。自定义特性是一种机制，允许你将自定义元数据与程序元素关联起来。这些元数据在编译时创建并嵌入到程序集中。反射是一个通用术语，描述在运行时检查和操作程序元素的能力。例如，反射允许你执行以下操作：

- 枚举类型的成员
- 实例化新对象
- 执行对象的成员
- 获取有关类型的信息
- 获取有关程序集的信息
- 检查应用于类型的自定义特性
- 创建并编译新程序集

这个列表代表了大量的功能，涵盖了.NET Framework类库所提供的一些最强大、最复杂的能力。由于一章的篇幅无法覆盖反射的所有能力，我将重点介绍你最可能经常使用的那些元素。

为了演示自定义特性和反射，在本章中你将首先开发一个示例，其背景是一家定期发布软件升级版本的公司，希望自动记录这些升级的详细信息。在该示例中，你定义自定义特性来指示程序元素最后修改的日期以及所做的更改。然后你使用反射开发一个应用程序，在程序集中查找这些特性，并自动显示自给定日期以来软件所做升级的所有详细信息。

本章中的另一个示例考虑了一个读写数据库的应用程序，它使用自定义特性来标记哪些类和属性对应于哪些数据库表和列。通过在运行时从程序集读取这些特性，程序可以自动检索数据或将数据写入数据库中的适当位置，而无需为每个表或列编写特定逻辑。

本章的第二个重要方面是动态编程，自C# 4.0版本添加`dynamic`类型以来，它一直是C#语言的一部分。Ruby和Python等语言的发展以及JavaScript的日益普及，加剧了人们对动态编程的兴趣。尽管C#仍然是一种静态类型语言，但动态编程的新增功能为C#语言提供了某些开发人员所期望的能力。使用动态语言功能可以从C#内部调用脚本函数，也使COM互操作更加容易。

在本章中，你将了解`dynamic`类型及其使用规则。你还将看到`DynamicObject`的实现方式以及如何使用它。本章还介绍了`ExpandoObject`，它是框架对`DynamicObject`的实现。

### 自定义特性

你在本书中已经看到了如何在程序中的各种项目上定义特性。这些特性由Microsoft作为.NET Framework类库的一部分定义，其中许多特性受到C#编译器的特殊支持。这意味着对于这些特定特性，编译器可以以特定方式自定义编译过程——例如，根据`StructLayout`特性中的详细信息在内存中布局结构体。

.NET Framework还允许你定义自己的特性。显然，这些特性对编译过程没有任何影响，因为编译器对它们没有内在的感知。然而，当这些特性应用于程序元素时，它们会作为元数据被写入编译后的程序集中。

仅凭这一点，这些元数据可能对文档目的很有用，但真正让特性变得强大的原因是，通过使用反射，你的代码可以读取这些元数据并在运行时利用它做出决策。这意味着你定义的自定义特性可以直接影响代码的运行方式。例如，自定义特性可用于为自定义权限类启用声明式代码访问安全检查，将信息与程序元素关联起来供测试工具使用，或用于开发允许加载插件或模块的可扩展框架。

#### 编写自定义特性

要理解如何编写自己的自定义特性，有必要了解编译器在遇到代码中应用了自定义特性的元素时会做什么。以数据库示例为例，假设你有一个如下所示的C#属性声明：

```csharp
[FieldName("SocialSecurityNumber")]
public string SocialSecurityNumber
{
    get {
        // etc.
```

当C#编译器识别到该属性应用了一个特性（`FieldName`）时，它会首先将字符串`Attribute`附加到这个名称后面，形成组合名称`FieldNameAttribute`。然后编译器在其搜索路径中的所有命名空间（即在`using`语句中提及的那些命名空间）中查找具有指定名称的类。请注意，如果你用一个名称已经以字符串`Attribute`结尾的特性来标记某个项目，编译器不会再次将该字符串添加到名称中；它会保持特性名称不变。因此，前面的代码等同于以下代码：

```csharp
[FieldNameAttribute("SocialSecurityNumber")]
public string SocialSecurityNumber
{
    get {
        // etc.
```

编译器期望找到一个具有此名称的类，并且期望该类直接或间接派生自`System.Attribute`。编译器还期望该类包含管理特性使用的信息。特别是，特性类需要指定以下内容：

- 特性可以应用到的程序元素类型（类、结构体、属性、方法等）
- 该特性多次应用于同一程序元素是否合法
- 当特性应用于类或接口时，是否会被派生类和接口继承
- 特性所需的必需参数和可选参数

如果编译器找不到相应的特性类，或者找到了一个特性类但你使用该特性的方式与特性类中的信息不匹配，编译器会引发编译错误。例如，如果特性类指示该特性只能应用于类，但你将其应用于结构体定义，则会发生编译错误。

继续该示例，假设你已经像这样定义了FieldName特性：

```csharp
[AttributeUsage(AttributeTargets.Property,
AllowMultiple=false,
Inherited=false)]
public class FieldNameAttribute : Attribute
{
private string _name;
public FieldNameAttribute(string name)
{
_name = name;
}
}
```

以下各节将讨论此定义的每个元素。

#### 指定AttributeUsage特性

首先要注意的是，特性类本身也被一个特性标记——System.AttributeUsage特性。这是Microsoft定义的一个特性，C#编译器为其提供了特殊支持。（你可以争辩说AttributeUsage根本不是特性；它更像是一个元特性，因为它只应用于其他特性，而不只是应用于任何类。）AttributeUsage的主要目的是标识你的自定义特性可以应用到的程序元素类型。此信息由AttributeUsage特性的第一个参数提供。该参数是必需的，它是枚举类型AttributeTargets。在前面的示例中，你已经指明FieldName特性只能应用于属性，这没问题，因为在之前的代码片段中你正是将其应用于属性。AttributeTargets枚举的成员如下：

- All
