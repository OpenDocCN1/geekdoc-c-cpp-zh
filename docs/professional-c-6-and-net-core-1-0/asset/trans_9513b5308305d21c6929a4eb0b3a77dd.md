## 底层的内存管理

C#编程的优势之一在于程序员无需担心详细的内存管理；垃圾回收器会代你处理内存清理问题。因此，你可以在不承担像C++那样手动管理内存的复杂性的情况下，获得接近C++等语言的效率。然而，尽管你不需要手动管理内存，但仍然值得了解幕后发生的事情。理解你的程序如何在底层管理内存，将有助于提升应用程序的速度和性能。本节将探讨在分配变量时计算机内存中发生的情况。

> **注意** *本节中许多主题的精确细节此处不予展开。本节仅作为一般流程的简要指南，而非具体实现的说明。*

### 值数据类型

Windows使用一种称为*虚拟寻址*的系统，其中从程序看到的内存地址到硬件内存实际位置的映射完全由Windows管理。因此，32位应用程序的每个进程都能看到4GB的可用内存，无论你的计算机实际拥有多少硬件内存（在64位处理器上的64位应用程序中，这个数字更大）。该内存包含程序的一切组成部分，包括可执行代码、代码加载的任何DLL，以及程序运行时使用的所有变量的内容。这4GB内存被称为*虚拟地址空间*或*虚拟内存*。为方便起见，本章使用简称*内存*。

> **注意** 使用*.NET Core*应用程序时，你可以通过选择Visual Studio项目属性中的“调试”设置里的体系结构来指定调试32位还是64位应用程序（参见图5.1）。当选择x86时，你调试的是可在32位和64位系统上运行的32位应用程序；当选择x64时，你调试的是可在64位系统上运行的64位应用程序。如果你在这里看不到不同选项，则需要安装特定的运行时，如第1章“.NET应用程序架构”所述。

可用4GB中的每个内存位置都从零开始编号。要访问存储在内存中特定位置的值，你需要提供表示该内存位置的编号。在任何编译型高级语言中，编译器会将人类可读的变量名转换为处理器能够理解的内存地址。

在处理器的虚拟内存中，有一个被称为*栈*的区域。*栈*存储不属于对象成员的值数据类型。此外，当你调用方法时，栈用于保存传递给方法的任何参数的副本。要理解栈的工作原理，你需要理解C#中变量*作用域*的重要性。如果变量a先于变量b进入作用域，那么b总是会先离开作用域。考虑以下代码：

```csharp
{
    int a;
    // do something
    {
        int b;
        // do something else
    }
}
```

首先，声明变量a。然后，在内部代码块中声明b。接着，内部代码块结束，b离开作用域，然后a离开作用域。因此，b的生命周期完全包含在a的生命周期内。你总是以与分配变量相反的顺序释放变量，这一思想对于栈的工作方式至关重要。

请注意，b与代码处于不同的块中（由不同嵌套的花括号定义）。因此，它位于不同的作用域内。这称为块作用域或结构作用域。

你并不确切知道栈在地址空间中的位置——对于C#开发来说，你也不需要知道。栈指针（由操作系统维护的一个变量）标识栈上的下一个空闲位置。当程序首次开始运行时，栈指针将指向为栈保留的内存块的末尾之后。栈向下填充，从高内存地址到低地址。随着数据放入栈中，栈指针会相应调整，因此它始终指向下一个空闲位置之后。图5.2展示了这一点，其中栈指针的值为800000（十六进制为0xc3500）；下一个空闲位置是地址799999。

下面的代码告诉编译器，你需要在内存中分配空间来存储一个整数和一个double，这些内存位置分别称为nRacingCars和engineSize。声明每个变量的行标明了你开始需要访问该变量的点。声明这些变量的块结束花括号标识了两个变量离开作用域的点：

```csharp
{
    int nRacingCars = 10;
    double engineSize = 3000.0;
    // do calculations;
}
```

假设你使用图5.2所示的栈，当变量nRacingCars进入作用域并被赋值为10时，值10被放置在位置799996到799999，即栈指针所指向位置下方正好4个字节处（4个字节是因为存储int需要这么多内存）。为了容纳这一点，栈指针的值减去4，因此它现在指向位置799996，即新的第一个空闲位置（799995）之后。

下一行代码声明变量engineSize（一个double）并将其初始化为3000.0。double占用8个字节，因此值3000.0被放置在栈上的位置799988到799995，栈指针减8，使其再次指向栈上下一个空闲位置之后的位置。

当engineSize离开作用域时，运行时知道不再需要它。由于变量生命周期总是嵌套的，你可以保证无论engineSize在作用域内发生了什么，栈指针现在都指向存储engineSize的位置。要将engineSize从栈中移除，栈指针加8，现在它指向engineSize结束之后的位置。在此代码点，你位于结束花括号处，因此nRacingCars也离开作用域。栈指针加4。当另一个变量在engineSize和nRacingCars被从栈中移除后进入作用域时，它会从存储nRacingCars的位置799999开始向下覆盖内存。

如果编译器遇到像int i, j,这样的代码行，变量进入作用域的顺序看起来是不确定的。两个变量同时声明并且同时离开作用域。在这种情况下，两个变量从内存中移除的顺序并不重要。编译器在内部总是确保先放入内存的那个变量最后移除，从而保持禁止变量生命周期交叉的规则。

### 引用数据类型

尽管栈提供了非常高的性能，但它的灵活性不足以用于所有变量。变量生命周期必须嵌套的要求对许多用途而言过于严格。通常，你需要使用一种方法来分配内存以存储数据，并在该方法退出后很长时间内保持这些数据可用。每当使用`new`运算符请求存储空间时——所有引用类型都是如此——这种可能性就存在。这就是托管堆发挥作用的地方。
