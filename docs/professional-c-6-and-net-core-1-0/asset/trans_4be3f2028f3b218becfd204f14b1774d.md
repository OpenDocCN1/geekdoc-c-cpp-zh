
应用程序不需要任何清理代码（例如释放或关闭任何打开的对象），那么就不需要这个块。

以下步骤概述了这些块如何协同工作来捕获错误条件：

- 1. 执行流程首先进入`try`块。
- 2. 如果在`try`块中没有发生错误，执行将正常通过该块，当到达`try`块末尾时，如果存在`finally`块，执行流程将跳转到`finally`块（步骤5）。但是，如果`try`块中确实发生错误，执行将跳转到`catch`块（步骤3）。
- 3. 错误条件在`catch`块中处理。
- 4. 在`catch`块末尾，如果存在`finally`块，执行将自动转移到`finally`块。
- 5. 执行`finally`块（如果存在）。

用于实现这一切的C#语法大致如下：

```
try
{
    // code for normal execution
}
catch
{
    // error handling
}
finally
{
    // clean up
}
```

实际上，这个主题存在一些变体：

- 你可以省略`finally`块，因为它是可选的。
- 你还可以根据需要提供任意数量的`catch`块来处理特定类型的错误。但是，你不要太过火，拥有大量的`catch`块。
- 你可以使用catch块定义筛选器，仅当筛选器匹配时，才用特定块捕获异常。
- 你可以完全省略`catch`块，在这种情况下，该语法并非用于识别异常，而是作为一种保证当执行离开`try`块时`finally`块中的代码一定会被执行的方式。如果`try`块包含多个退出点，这很有用。

到目前为止一切顺利，但尚未回答的问题是：如果代码在`try`块中运行，当发生错误时，它如何知道何时切换到`catch`块？如果检测到错误，代码会执行一种称为*抛出异常*的操作。换句话说，它实例化一个异常对象类并将其抛出：

```
throw new OverflowException();
```

这是因为你可以在try块内部多个方法调用中嵌套throw语句，但即使执行流进入这些其他方法，同一个try块仍然适用。如果应用程序遇到throw语句，它会立即沿着栈上的所有方法调用回溯，寻找包含它的try块的末尾以及相应catch块的开头。在此过程中，中间方法调用中的所有局部变量将正确地超出作用域。这使得try...catch架构非常适合本节开头描述的情况，即错误发生在嵌套在15或20个方法调用内部的方法调用中，并且处理必须立即停止。

正如你可能从这段讨论中得出的结论，try块在控制代码执行流程方面可以发挥非常重要的作用。然而，重要的是要理解异常是为异常情况设计的，因此得名。你不会希望将它们用作控制何时退出do...while循环的方式。

## 实现多个 Catch 块

要了解try...catch...finally块在实践中如何工作，最简单的方法是看几个示例。第一个示例名为SimpleExceptions。它反复要求用户输入一个数字，然后显示该数字。但是，为了这个示例，假设数字必须在0到5之间；否则，程序无法正确处理该数字。因此，如果用户输入任何超出此范围的内容，你将抛出异常。然后程序继续要求输入更多数字进行处理，直到用户仅按Enter键而不输入任何内容。

> 注意 你应该注意，这段代码并没有提供何时使用异常处理的好例子，但它展示了如何使用异常处理的良好实践。正如其名称所示，异常是为非正常情况提供的。用户经常输入愚蠢的内容，所以这种情况实际上不算。通常，你的程序会通过执行即时检查来处理不正确的用户输入，并在输入无效时要求用户重新输入。然而，在一个几分钟内就能读完的小示例中，产生异常情况是困难的，所以我会容忍这个不太理想的示例来演示异常如何工作。接下来的示例会呈现更现实的情况。

SimpleExceptions的代码如下所示（代码文件SimpleExceptions/Program.cs）：

```
using System;
using static System.Console;

namespace Wrox.ProCSharp.ErrorsAndExceptions
{
    public class Program
    {
        public static void Main()
        {
            while (true)
            {
                try
                {
                    string userInput;

                    Write("Input a number between 0 and 5" +
                        " (or just hit return to exit)>");
                    userInput = ReadLine();

                    if (string.IsNullOrEmpty(userInput))
                    {
                        break;
                    }

                    int index = Convert.ToInt32(userInput);

                    if (index < 0 || index > 5)
                    {
                        throw new IndexOutOfRangeException($"You typed in {userInput}");
                    }

                    WriteLine($"Your number was {index}");
                }
                catch (IndexOutOfRangeException ex)
                {
                    WriteLine("Exception:" +
                        $"Number should be between 0 and 5. {ex.Message}");
                }
                catch (Exception ex)
                {
                    WriteLine($"An exception was thrown. Message was: {ex.Message}");
                }
                finally
                {
                    WriteLine("Thank you\n");
                }
            }
        }
    }
}
```

这段代码的核心是一个while循环，它不断使用ReadLine来请求用户输入。ReadLine返回一个字符串，因此你的首要任务是使用System.Convert.ToInt32方法将其转换为int。System.Convert类包含各种有用的方法来执行数据转换，并且它提供了int.Parse方法的替代方案。一般来说，System.Convert包含执行各种类型转换的方法。回想一下，C#编译器将int解析为System.Int32基类的实例。

> 注意 还值得指出的是，传递给catch块的参数的作用域仅限于该catch块——这就是为什么你能在前面的代码中在连续的catch块中使用相同的参数名ex。

在前面的示例中，你还检查了空字符串，因为这是你退出while循环的条件。注意，break语句实际上直接跳出了封闭的try块以及while循环，因为这是有效行为。当然，当执行跳出try块时，finally块中的WriteLine语句会被执行。尽管你在这里只是显示一条问候语，但更常见的任务是关闭文件句柄、调用各种对象的Dispose方法以执行清理工作。在应用程序离开finally块之后，它只是继续执行假如没有finally块时本应执行的下一条语句。不过，在这个示例的情况下，你会迭代回while循环的开始，并再次进入try块（除非finally块是因为执行while循环中的break语句而进入的，在这种情况下，你只是退出while循环）。
