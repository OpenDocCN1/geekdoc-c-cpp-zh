
这些32位值被分为以下几个部分：16位用于源数量，8位用于查询者的查询间隔代码，3位用于查询者的鲁棒性变量，1位抑制标志，以及4位保留位。您还可以定义自己的位含义以节省内存。

下面的示例模拟接收值0x79abcdef，并将该值传递给BitVector32的构造函数，以便相应地设置这些位：

```
int received = 0x79abcdef;
BitVector32 bits2 = new BitVector32(received);
WriteLine(bits2);
```

这些位在控制台上显示为初始化状态：

```
BitVector32{01111001101010111100110111101111}
```

然后创建六个部分。第一部分需要12位，由十六进制值0xfff定义（设置了12位）；B部分需要8位；C部分需要4位；D和E部分各需要3位；F部分需要2位。第一次调用CreateSection仅接收0xfff来分配前12位。在第二次调用CreateSection时，将第一个部分作为参数传递，因此下一个部分从第一个部分结束的地方继续。CreateSection返回一个BitVector32.Section类型的值，其中包含该部分的偏移量和掩码：

```
// sections: FF EEE DDD CCCC BBBBBBBB AAAAAAAAAAAA
BitVector32.Section sectionA = BitVector32.CreateSection(0xfff);
BitVector32.Section sectionB = BitVector32.CreateSection(0xff,
sectionA);
BitVector32.Section sectionC = BitVector32.CreateSection(0xf,
sectionB);
BitVector32.Section sectionD = BitVector32.CreateSection(0x7,
sectionC);
BitVector32.Section sectionE = BitVector32.CreateSection(0x7,
sectionD);
BitVector32.Section sectionF = BitVector32.CreateSection(0x3,
sectionE);
```

将BitVector32.Section传递给BitVector32的索引器会返回一个int，该int正好映射到位向量的该部分。如下所示，辅助方法IntToBinaryString获取该int数字的字符串表示：

```
WriteLine($"Section A: {IntToBinaryString(bits2[sectionA],
true)}");
WriteLine($"Section B: {IntToBinaryString(bits2[sectionB],
true)}");
WriteLine($"Section C: {IntToBinaryString(bits2[sectionC],
true)}");
WriteLine($"Section D: {IntToBinaryString(bits2[sectionD],
true)}");
WriteLine($"Section E: {IntToBinaryString(bits2[sectionE],
true)}");
WriteLine($"Section F: {IntToBinaryString(bits2[sectionF],
true)}");
```

方法IntToBinaryString接收一个整数中的位，并返回包含0和1的字符串表示。在实现中，会遍历整数的32位。在迭代中，如果位被设置，则向StringBuilder追加1；否则追加0。在循环内，会发生一次位移，以检查下一位是否被设置：

```
public static string IntToBinaryString(int bits, bool removeTrailingZero)
{
    var sb = new StringBuilder(32);

    for (int i = 0; i < 32; i++)
    {
        if ((bits & 0x80000000) != 0)
        {
            sb.Append("1");
        }
        else
        {
            sb.Append("0");
        }
        bits = bits << 1;
    }
    string s = sb.ToString();
    if (removeTrailingZero)
    {
        return s.TrimStart('0');
    }
    else
    {
        return s;
    }
}
```

结果显示A到F各部分的位表示，现在您可以使用传递到位向量的值进行验证：

```

Section B: 10111100
Section C: 1010
Section D: 1
Section E: 111
Section F: 1
```

## 可观察集合

当您需要集合中的项被移除或添加时的信息时，可以使用ObservableCollection<T>类。这个类最初是为WPF定义的，以便用户界面能够获知集合的变化。现在它同样用于Windows应用程序。使用.NET Core时，您需要引用NuGet包System.ObjectModel。该类的命名空间是System.Collections.ObjectModel。

ObservableCollection<T>派生自基类Collection<T>，该基类可用于创建自定义集合，并且内部使用List<T>。通过重写基类的虚方法SetItem和RemoveItem来触发CollectionChanged事件。此类的客户端可以通过使用INotifyCollectionChanged接口来注册此事件。

下一个示例演示了使用ObservableCollection<string>，其中Data_CollectionChanged方法注册到CollectionChanged事件。向末尾添加两个项——插入一个项，并移除一个项（代码文件ObservableCollectionSample/Program.cs）：

```
var data = new ObservableCollection<string>();
data.CollectionChanged += Data_CollectionChanged;
data.Add("One");
data.Add("Two");
data.Insert(1,"Three");
data.Remove("One");
```

ObservableCollectionSample 使用了以下依赖项和命名空间：

### 依赖项

- NETStandard.Library
- System.ObjectModel

### 命名空间

- System.Collections.ObjectModel
- System.Collections.Specialized
- static System.Console

方法Data_CollectionChanged接收包含有关集合更改信息的NotifyCollectionChangedEventArgs。Action属性提供有关项是添加还是移除的信息。对于移除的项，会设置OldItems属性并列出移除的项。对于添加的项，会设置NewItems属性并列出新项：

```
public static void Data_CollectionChanged(object sender,
NotifyCollectionChangedEventArgs e)
{
    WriteLine($"action: {e.Action.ToString()}");

    if (e.OldItems != null)
    {
        WriteLine($"starting index for old item(s): {e.OldStartingIndex}");
        WriteLine("old item(s):");
        foreach (var item in e.OldItems)
        {
            WriteLine(item);
        }
    }
    if (e.NewItems != null)
    {
        WriteLine($"starting index for new item(s): {e.NewStartingIndex}");
        WriteLine("new item(s):");
        foreach (var item in e.NewItems)
        {
            WriteLine(item);
        }
    }
    WriteLine();
}
```

**运行应用程序会得到以下输出。** 首先，项One和Two被添加到集合中，因此Add操作显示索引0和1。第三项Three插入到位置1，因此显示Add操作索引1。最后，项One被移除，如Remove操作和索引0所示：

```
action: Add
starting index for new item(s): 0
new item(s):
One

action: Add
starting index for new item(s): 1
new item(s):
Two

action: Add
starting index for new item(s): 1
new item(s):
Three

action: Remove
starting index for old item(s): 0
old item(s):
One
```

## 不可变集合

如果对象可以更改其状态，则难以从多个同时运行的任务中使用它。对于这些集合，同步是必要的。如果对象无法更改状态，则从多个线程使用它会容易得多。无法更改的对象是不可变对象。无法更改的集合是不可变集合。

> **注意** *关于使用多个任务和线程以及使用异步方法进行编程的主题将在第15章“异步编程”和第21章“任务与并行编程”中详细说明。*

要使用不可变集合，您可以添加NuGet包`System.Collections.Immutable`。该库在命名空间`System.Collections.Immutable`中包含集合类。

将上一章讨论的只读集合与不可变集合进行比较，有一个很大的区别：只读集合使用可变集合的接口。使用此接口时，集合无法更改。但是，如果某人仍然持有对可变集合的引用，则它仍然可以被更改。而对于不可变集合，没有人可以更改此集合。

`ImmutableCollectionSample` 使用了以下依赖项和命名空间：

### 依赖项

- NETStandard.Library
- System.Collections.Immutable

### .NET Core 包

- System.Console
- System.Collections
- System.Collections.Immutable

### 命名空间

- System.Collections.Generic
- System.Collections.Immutable
- static System.Console

让我们从一个简单的不可变字符串数组开始。您可以按所示使用静态的`Create`方法创建该数组。`Create`方法被重载，此方法的其他变体允许传递任意数量的元素。请注意，这里使用了两种不同的类型：具有静态`Create`方法的非泛型`ImmutableArray`类，以及由`Create`方法返回的泛型`ImmutableArray`结构体。在以下代码片段中，创建了一个空数组（代码文件`ImmutableCollectionSample/Program.cs`）：

```
ImmutableArray<string> a1 = ImmutableArray.Create<string>();
```

空数组并不是很有用。`ImmutableArray<T>`类型提供了`Add`方法来添加元素。然而，与其他集合类相反，`Add`方法不会更改不可变集合本身。而是返回一个新的不可变集合。因此，在调用`Add`方法后，`a1`仍然是一个空集合，而`a2`是一个包含一个元素的不可变集合。`Add`方法返回新的不可变集合：

```
ImmutableArray<string> a2 = a1.Add("Williams");
```

有了这个，就可以以流畅的方式使用此API，并一个接一个地调用`Add`方法。变量`a3`现在引用一个包含四个元素的不可变集合：

```
ImmutableArray<string> a3 =
    a2.Add("Ferrari").Add("Mercedes").Add("Red Bull Racing");
```
