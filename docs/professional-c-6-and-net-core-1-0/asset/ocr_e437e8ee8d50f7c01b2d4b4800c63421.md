What you can also see with the result is that every end-log of a loop uses the same thread and task as the start-log. Using `Task.Delay` with the `Wait` method blocks the current thread until the delay ends.

Change the previous example to now use the `await` keyword with the `Task.Delay` method:

```
public static void ParallelForWithAsync()
{
    ParallelLoopResult result =
        Parallel.For(0, 10, async i =>
        {
            Log($"S {i}");
            await Task.Delay(10);
            Log($"E {i}");
        });
    WriteLine($"is completed: {result.IsCompleted}");
}
```

For example, loop iteration 8, which had thread ID 7 before the delay, has thread ID 5 after the delay. You can also see that tasks no longer exist—there are only threads—and here previous threads are reused. Another important aspect is that the `For` method of the `Parallel` class is completed without waiting for the delay.
