Such issues don’t occur only on the server; the problem is also in the client application as soon as you’re running multiple tasks, or when you’re using the C# `async` and `await` keywords on calling asynchronous methods. Different tasks come into play.

When you create a class that derives from `TraceSource`, all you have to do to create activity IDs is define methods that are post-fixed with `Start` and `Stop`.

For the sample showing activity IDs in action, a Class Library (Package) supporting .NET 4.6 and .NET Core 1.0 is created. Previous versions of .NET don’t support the new `TraceSource` features for activity IDs. The `ProcessingStart` and `RequestStart` methods are used to start activities; `ProcessingStop` and `RequestStop` stop activities (code file MyApplicationEvents/SampleEventSource):

```
public class SampleEventSource : EventSource
{
    private SampleEventSource()
        : base("Wrox-SampleEventSource")
    {
    }

    public static SampleEventSource Log = new SampleEventSource();

    public void ProcessingStart(int x)
    {
        base.WriteEvent(1, x);
    }
    public void Processing(int x)
    {
        base.WriteEvent(2, x);
    }
    public void ProcessingStop(int x)
    {
        base.WriteEvent(3, x);
    }

    public void RequestStart()
    {
        base.WriteEvent(4);
    }
    public void RequestStop()
    {
        base.WriteEvent(5);
    }
}
```
