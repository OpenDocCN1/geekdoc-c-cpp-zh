## Firing robot missiles

Create a C# script and name it Missile. Drag a copy of each of the RobotMissile[Color] prefabs from the Resources folder onto the Hierarchy. It doesn't matter where they end up on the screen because you'll be removing them soon.

Select each of the RobotMissile[Color] GameObjects that you just dragged into the Hierarchy in turn, and drag the Missile script onto each of them.

Open the Missile script in the code editor to add the following variables:

```csharp
public float speed = 30f;
public int damage = 10;
```

speed is how fast the missile should travel. damage is how much damage this missile will cause when it hits the player.

Now, add the following methods just below the damage variable:

```csharp
// 1
void Start()
{
    StartCoroutine("deathTimer");
}

// 2
void Update()
{
    transform.Translate(Vector3.forward * speed * Time.deltaTime);
}

// 3
IEnumerator deathTimer()
{
    yield return new WaitForSeconds(10);
    Destroy(gameObject);
}
```

In the code above, you used coroutines. In computer jarg, you'll hear the word threading tossed around a bit. This is a way of having the computer multiple things at once. In a game, this would mean calculating your artificial intelligence in one thread while playing in another.

Threads are a gnarly topic, and while you use them in Unity, you can simulate threading without the pain and suffering through the use of coroutines. A coroutine will run code at a certain designated time. They run on the main thread and work pretty much like regular code, except they run in intervals. Because they run in the main thread, you don't get any of the nasty concurrency headaches from regular threading.

Coroutines take that return IEnumerator. These determine the duration of the coroutine. Here's the breakdown of what you wrote:

- 1. When you instantiate a missile, you start a coroutine called deathTimer(). This is name of the method that the coroutine will call.
- 2. Move the missile forward at speed multiplied by the time between frames.
- 3. You'll notice that the method immediately returns a WaitForSeconds, set to 10. Once those 10 seconds have passed, the method will resume after the yield statement. If the missile doesn't hit the player, it should auto-destroy.

See? Coroutines aren't so bad at all! :

Save your work and switch back to Unity. Click each RobotMissile[Color] one at a time and click Apply to set the changes on the prefabs.

## Adding damage

Now is the perfect time to add damage to the player. Create a new C# script, name it Player and add the following variables:

```csharp
public int health;
public int armor;
public GameUI gameUI;
private Gunipper gunipper;
private Ammo ammo;
```

health is the remaining life of the player. Add the following to Start():

```csharp
void Start()
{
  ammo = GetComponent<Ammo>();
  gunipper = GetComponent<Gunipper>();
}
```

gameUI and gunipper are simply references to their script types. Add the following method:

```csharp
public void TakeDamage(int amount)
{
  int healthDamage = amount;

  if (armor > 0)
  {
    int effectiveArmor = armor * 2;
    effectiveArmor -= healthDamage;
  }
  // If there is still armor, don't need to process health damage
  if (effectiveArmor > 0)
  {
    armor = effectiveArmor / 2;
    return;
  }

  armor = 0;
  health -= healthDamage;
  Debug.Log("Health is " + health);
  if (health <= 0)
  {
    Debug.Log("GameOver");
  }
}
```

Next, you need to update the Missile script to actually tell the player to take damage.

When the Missile GameObject collides with the Player Capsule Collider, it will damage the player via OnCollisionEnter(). Open the Missile script in the code editor and add the following method:

```csharp
void OnCollisionEnter(Collision collider)
{
  if (collider.gameObject.GetComponent<Player>() != null
  && collider.gameObject.tag == "Player")
  {
    collider.gameObject.GetComponent<Player>().TakeDamage(damage);
  }

  Destroy(gameObject);
}
```
