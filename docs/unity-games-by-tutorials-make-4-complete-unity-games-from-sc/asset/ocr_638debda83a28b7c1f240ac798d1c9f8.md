+   **OnRenderObject**: Called right after the camera has completed rendering the scene. This is very similar to OnPostRender it will work well with GameObjects.

+   **OnRenderImage**: Called after rendering is complete to create an image. This allows you to add effects in the post-processing pass, such as turning a color image black and white.

# # Pausing, disabling and decommissioning

This final batch of events occur when you pause, disable, and decommission GameObjects.

+   **OnDisable**: Occurs when a component becomes disabled or inactive.

+   **OnApplicationQuit**: Occurs when the app is about to end or if you are exiting Play mode.

+   **OnDestroy**: Called before the MonoBehaviour is going to be destroyed. If you need to do any clean up, this is a good time to do it.

MonoBehaviour contains a list of events; we haven't covered them all here. Check the Unity documentation to see what more events are available to you.

# # ScriptableObjects

When making your games, you might be tempted to put all your game logic in MonoBehaviour derived types. After all, this is how you construct all the games in this book. A ScriptableObject is another type that you can use to build your games.

Whereas MonoBehaviour derived scripts can manage the objects of things that appear onscreen, ScriptableObjects manage the data associated with those objects. The beautiful thing is that these objects can be saved in your project and reused much like a prefab.

For instance, you may have all your level data stored in a text file. Each time the game starts, you need to read that text file, parse the information and store all that data into memory. For a desktop PC, this may not be an issue, but for devices with constrained resources like a phone, you are wasting resources on data being used.

By using a ScriptableObject, all the levels can be broken down into individual levels, values can be changed in the inspector and loading them is blazing fast.
