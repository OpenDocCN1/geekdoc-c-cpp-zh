
Unity creates new scripts based on templates, and those templates are the cause of the line ending issues. To fix the issue, you must change the templates. What is with IDEs, or Integrated Development Environments, and their funky templates?

First, open Visual Studio. Click File > Open File and then head over to the location: C > Program Files > Unity > Editor > Data > Resources > ScriptTemplates.

This directory contains a list of templates that Unity uses to create your scripts. For fixing the C# templates, open 81-C# Script-NewBehaviourScript.cs.txt.

Next, click File > Advanced Save. Here, you'll see a familiar dialog. The line endings are to Windows (CR LF) and click OK.

![](img/fd5c2ca20ea33da76d2b61297cc57f6c_653_0.png)

Now, you'll no longer get that message. When working with a source control program such as git, the Windows line endings will be stripped — don’t be surprised when you encounter the message again.

## Debugging

Being a top-level IDE, Visual Studio also comes with a top-level Debugger. Debuggers allow you to pause your game in motion and inspect the state of the variables.

To get started with debugging, you first need to create a breakpoint. A breakpoint is an indicator to the Debugger that it should pause its execution at your point. You create a breakpoint by clicking on the gutter in the left-hand side of the editor. So doing will produce a red dot and highlight the line in red.

```csharp
void OnDisable() {
    int value = 36;
    int additionalValue = 0;
    if (shouldProceed) {
        additionalValue = 6;
    }
}
```

This won't stop your code — yet. To start the Debugger, press the Play button and make sure the Unity Editor is the current target.

![](img/fd5c2ca20ea33da76d2b61297cc57f6c_655_0.png)

Once you start the Debugger, it will attach itself to the Unity editor. When you play the game, the editor will pause at the breakpoint so that you can inspect any variables in your game. You can do this with the Autos view.
