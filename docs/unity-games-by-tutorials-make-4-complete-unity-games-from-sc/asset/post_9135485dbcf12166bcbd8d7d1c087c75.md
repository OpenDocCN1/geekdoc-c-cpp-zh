## The 2D orthographic camera

By default, 2D projects use an orthographic camera. Generally, you'll want to stick with it instead of using a perspective camera. Remember: orthographic cameras just render the game view so that objects near and far are the same size — perfect for 2D!

These are the properties of the current Camera in the scene.

![](img/fd5c2ca20ea33da76d2b61297cc57f6c_333_2.png)

Notice Projection is set to Orthographic as discussed — you'll learn about the Camera's size property in a bit. The other properties will stay at their defaults.

In the Project browser, select the single-block.png sprite under the Sprites sub-folder, then take a look at the Inspector. You'll see that Pixels Per Unit is 100.

![](img/fd5c2ca20ea33da76d2b61297cc57f6c_334_0.png)

What does 100 really mean?

In units, yours doesn't necessarily correspond to pixels on the screen. On some arbitrary scale, as 1 unit = 1 meter. Unity uses Pixels Per Unit to determine sprites' uncased size in units.

Consider this: An imported sprite is 500 pixels wide. The following table will give you an idea of how the GameObject's width would change on the X-axis with different Pixels Per Unit settings at various X-scales.

| Pixels to Units | X-scale | Width Calculation | Width |
| :--- | :--- | :--- | :--- |
| 100 | 0.5 | 500 / 100 * 0.5 | 2.5 units |
| 100 | 1.0 | 500 / 100 * 1.0 | 5.0 units |
| 100 | 2.0 | 500 / 100 * 2.0 | 10.0 units |
| 50 | 0.5 | 500 / 50 * 0.5 | 5.0 units |
| 50 | 1.0 | 500 / 50 * 1.0 | 10.0 units |
| 50 | 2.0 | 500 / 50 * 2.0 | 20.0 units |

Now consider an example from your game. The single-block sprite is 100 x 100 px with a Pix Per Unit value of 100. At a scale of 1 for X and Y, the single-block GameObject would be 1 unit wide and 1 unit tall.

Remember the Size property on the Orthographic Camera you saw a moment ago? With the Size to 5, you would need to stack ten single-block sprites atop each other to reach from bottom of the camera to the top of the camera's viewport. This is because Unity calculates the Orthographic size from the center of the screen to the top.

## Scripting: Smooth camera follow

Scripting is an important part of working in Unity, and you'll start with a simple script that makes the camera follow the player around smoothly. Part of what makes it smooth is that you'll constrain it to a certain plane with X and Y boundaries.

Open the Scripts folder and double-click CameraLerpTransform to open it in your code editor.

Remove the empty Start() and Update() methods in the script template; this script does not require initialization and will use the FixedUpdate() method instead of Update() to follow the player because the physics engine will move the player.

Place the following code into the now-empty CameraLerpTransform class:

```cs
// 1
public Transform cameraTarget;
public float trackingSpeed;
public float minX;
public float minY;
public float maxX;

// 2
void FixedUpdate()
```

![](img/fd5c2ca20ea33da76d2b61297cc57f6c_335_0.png)

```cs
{
// 3
if (camTarget != null) {
// 4
  var newPos = Vector2.Lerp(transform.position,
    camTarget.position,
    Time.deltaTime * trackingSpeed);
  var camPosition = new Vector3(newPos.x, newPos.y, -10f);
  var v3 = camPosition;
  var clampX = Math.Clamp(v3.x, minX, maxX);
  var clampY = Math.Clamp(v3.y, minY, maxY);
  transform.position = new Vector3(clampX, clampY, -10f);
}
}
```

1. These public variable fields let you set the target the camera will track, tracking speed and the camera's bounds.
2. FixedUpdate() is called with every fixed-rate frame — it's the best method when dealing with a Rigidbody component of any kind. The result is the camera will track the player, who will have a Rigid2D attached to it.
3. This null check ensures that a Transform component was assigned to the camTarget field in the editor.
4. Vector2.Lerp() performs linear interpolation between two vectors by the third parameter's value (a value between 0 and 1). Normally, you'd usually use this to move between positions over time, but here actually tracking as you near the camera's target (Soy Boy). The rest of the Lerp method ensures that the position calculated is clamped (constrained) to the MinX, MinY, MaxX, and MaxY points.

## Adding 2D physics

Right now, your sprites can't interact with the physics engine. They just float in the air. If there were to be a reaction would make you think you've created an alternate universe.

Unity's 2D physics system is similar to the 3D system. The main difference is that you use the 2D versions of each type of component.

- Rigidbody2D: Puts a sprite or object under the control of the physics engine. You generally need one for every item that uses a collider.
- BoxCollider2D: Defines an axis-aligned rectangle collision area around an object.
- CircleCollider2D: Creates a circular collision area around an object.
- PolygonCollider2D: Makes an arbitrary polygon-shaped collision area around an object defined by vertices set in different positions. They usually have more edges than other colliders, so they also come at a higher cost. Be careful with these!
- EdgeCollider2D: Represents an arbitrary set of connected edges defined by vertices.
- CapsuleCollider2D: A smooth continuous circumference-shaped collider. Useful as it doesn't easily catch on other collider shapes.
- CompositeCollider2D: Allows you to merge multiple Box and Polygon Collider shapes to form a single composite collider.

## Setting up colliders

Now its is time to get your sprites to play nice with the 2D physics engine. Select the single-block GameObject in your scene. In the Inspector, click Add Component and choose Rigidbody2D under the Physics 2D menu. Select Kinematic for the Body Type as Super Boy won't need to move any terrain — the blocks will be static.

Click Add Component again, and under Physics 2D, choose Box Collider 2D. Unity will add a BoxCollider2D to the sprite and size it to the bounds of your sprite.

![](img/fd5c2ca20ea33da76d2b61297cc57f6c_338_1.png)

Excellent! Your single-block sprite can now interact with the 2D physics engine.
