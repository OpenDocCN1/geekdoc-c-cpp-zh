# Storing best times with binary serialization

Binary serialization allows you to save and load more complex data structures.

To get familiar with this approach, you'll create a way for players to store their
runtimes. Specifically, you'll make it so that the three best times show beneath the
Current level runtime after a player completes a level.

Even when the player closes the game, the program stores the times and reloads them

```c
public List<PlayerTimeEntry> LoadPreviousTimes()
{
    // 1
    try {
        var scoresFile = Application.persistentDataPath +
            "/" + playerName + "_times.dat";
        using (var stream = File.Open(scoresFile, FileMode.Open)) {
            var bin = new BinaryFormatter();
            var times = (List<PlayerTimeEntry>)bin.Deserialize(stream);
            return times;
        }
    // 2
    } catch (IOException exception)
    {
        Debug.LogWarning("Couldn't load previous times for: " +
            playerName + ". Exception: " + exception.Message);
        return new List<PlayerTimeEntry>();
    }
}

```c
public void SaveTime(decimal time)
{
    // 3
    var times = LoadPreviousTimes();
    // 4
    var newTime = new PlayerTimeEntry();
    newTime.entryDate = DateTime.Now;
    newTime.time = time;
    // 5
    var bFormatter = new BinaryFormatter();
    var filePath = Application.persistentDataPath +
        "/" + playerName + "_times.dat";
    using (var file = File.Open(filePath, FileMode.Create)) {
        times.Add(newTime);
        bFormatter.Serialize(file, times);
    }
}
```

# Chapter 14: Saving Data

That's a lot of new code! Essentially, this code handles saving and loading of times to and from a binary formatted file.

- 1. Use try...catch statement to attempt to load saved time entries. You construct the path to the file using a combination of the player's name (stored in PlayerPrefs) and the Application.persistentDataPath. The using statement opens a file stream to the file to read any existing entries using a binary formatter object. You use the Deserialize() method to unpack — a snap — the data in the file by passing in the opened file stream. If the read is successful, it returns a list of player entries.

- 2. If deserialization is unsuccessful, the catch statement finds the errors. Here, you log an info message and return an empty list to the caller. This is important because the player might not have logged or saved times, e.g., when playing the first time.

- 3. When saving a time, you fetch existing entries first with the LoadPreviousTimes() method.

- 4. You create an instance of the PlayerTimeEntry object. Then, you use the current date, as passed to the method, in the entryDate and time property fields.

- 5. You create a binary formatter object to do the magic serialization — a.k.a. packing — the list of player time entries to a file. You create the file path using a combination of the player's name and the Application.persistentDataPath. Again, the using statement opens the file. However, this time it uses the FileMode.Create option, which lets you create a new or overwrite existing files in the same path. Finally, you add the new time entry to the list of pre-existing times before saving them all into the file.

> Note: The using statement in the code above is a special statement in C# that can utilize to deal with objects that implement the IDisposable interface. Most file and IO-related operations provided by the framework support this.

It's a good idea to wrap these operations in a using statement when supported. Once work on the item inside of the using statement finishes, any objects that were created are destroyed.

In the case above, where you're opening and writing to files, you're properly closing file access when the using statement completes. Hence, you shouldn't have locked file issues when writing to the file at a later point.
