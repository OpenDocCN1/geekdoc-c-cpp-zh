In the code above, you used coroutines. In computer jarg, you'll hear the word threading tossed around a bit. This is a way of having the computer multiple things at once. In a game, this would mean calculating your artificial intelligence in one thread while playing in another.

Threads are a gnarly topic, and while you use them in Unity, you can simulate threading without the pain and suffering through the use of coroutines. A coroutine will run code at a certain designated time. They run on the main thread and work pretty much like regular code, except they run in intervals. Because they run in the main thread, you don't get any of the nasty concurrency headaches from regular threading.

Coroutines take that return IEnumerator. These determine the duration of the coroutine. Here's the breakdown of what you wrote:

+   1. When you instantiate a missile, you start a coroutine called deathTimer(). This is name of the method that the coroutine will call.
2. Move the missile forward at speed multiplied by the time between frames.
3. You'll notice that the method immediately returns a WaitForSeconds, set to 10. Once those 10 seconds have passed, the method will resume after the yield statement. If the missile doesn't hit the player, it should auto-destroy.

See? Coroutines aren't so bad at all! :
