## Chapter 18: Making A Tower Defense Game
By Eric Van de Kerckhofove

In a tower defense game, you build up defenses to protect yourself from advancing waves of enemies. To do this, you build and upgrade towers or other defensive elements that either damage or slow down the enemies as they pass by.

![](img/fd5c2ca20ea33da76d2b61297cc57f6c_498_0.png)

There are early examples of these kinds of games. A 1990 game called Rampart, wherein you placed cannons that would automatically attack incoming enemies, for example. In the Fort Condor minigame from the 1997 classic Final Fantasy VII, the player had to put down units to defend the fort. With the release of the popular custom maps for Warcraft III, the genre became extremely popular with lots of modern titles in all kinds of flavors coming out across all platforms.

In this chapter you'll learn to:

- Use manager classes to build all sorts of stuff such as managing the state of the game, the amount of enemies to produce, and the amount of waves to send at a player.
- Use utility scripts to make your life easier so you can prepackage various types of animations to use in other games.
- Get enemies to spawn and move around on a path while your hero reacts accordingly

At the end of this project, you will have a fully functional tower defense game called Runestripe!

## Getting started

Open the starter project in Unity and take a look at the Project browser. The assets for this project are arranged in several sub-folders. Here's a quick rundown of what each sub-folder contains:

- Materials: Materials needed for the tiles, towers and enemies.
- Models: Meshes.
- Music: Background music.
- Prefabs: Particles, level tiles, enemies, towers and the tower projectiles.
- Scenes: Title and game scenes.
- Scripts: This is where your scripts should go.
- Sound FX: Sound effects, including shoot sounds and enemy hits.
- Textures: Textures for the models and UI elements.

Now the project overview is out of the way, it's time to get down to business!
Before setting up your project, it's best to set the aspect ratio. Use the drop-down at the top of the Game window. Depending on your project type, it may default to Free Aspect. Change it to 16:9 to get consistent results.

## Making a path

To prepare the map for enemies to move about, you'll need to make a simple waypoint system so that they can go from point to point. This is one of the easiest ways of doing primitive pathfinding.

![](img/fd5c2ca20ea33da76d2b61297cc57f6c_501_0.png)

To start, create a new empty GameObject in the root of the Hierarchy and name it EnemyPaths. Select the object. Then reset its Transform by clicking on the Settings in the Inspector panel. In the drop-down, click on Reset.

Now, make another empty GameObject and name it Path 0. In the Hierarchy panel, drag Path 0 onto EnemyPaths to make it a child GameObject.

There will be two paths that the enemies can traverse; this is the first one. It's named Waypoint (1) because you will use it later in a zero-based array.

Create a new Sphere (Create > 3D Object > Sphere), set its scale to (0.3, 0.3, 0.3) and name it Waypoint (1). Set its position to (2, 0, -5) and parent it to Path 0. This is the starting point of the path and also the spawning point of any enemies that will use this path. Now, duplicate Waypoint (1) by right-clicking.

![](img/fd5c2ca20ea33da76d2b61297cc57f6c_501_1.png)

Now that you have a series of waypoints, you can store their positions in an array. The array will form a path used by enemies.

In the Project browser, inside Scripts ▸ Game folder, create a sub-folder named Waypoints. Inside the Waypoints folder, create a new C# Script and name it WayPoint Manager.
