# The Target-Action Mechanism

The target-action mechanism enables a control object—that is, an object such as a button, slider, or text
field—to send a message to another object that can interpret the message and handle it as an
application-specific object. The receiving object, or target, is usually a custom controller object. The
message—named an action message—is determined by a selector, a runtime identifier of method.

In the AppKit framework, the cell that controls uniquely encapsulates the target and action.
When the user clicks or activates the control, the control extracts the information from its cell and
sends the message. (A menu item also encapsulates target and action, and sends an action message when
the user chooses it.) The target-action mechanism can work on the basis of a selector (and not a method
signature) because of the signature of an action method in AppKit by convention is always.

In UIKit, the target-action mechanism does not rely on cells. Instead, a control maps a target and action to
one or more events that the control can trigger.

# Uses and Limitations

When creating a Cocoa application, you can set a control's action and target through the Interface Builder
application. You thereby let the control implement custom behavior without any code for the control
itself. The selector and target connection are achieved in a nib and are restored when the nib is
unarchived. You can change the target and action dynamically by setting the control or its cell
`setTarget:` and `setAction:` messages.

A Cocoa program for Mac X can use the target-action mechanism to instruct a custom controller object
to transfer data from the user interface to a model object, or to display data in a model object. The Cocoa
bind obligates the need to use target-action for purpose. Cocoa Bindings Programming
Topics for more about this technology.

Controls and cells do not retain their targets. "Ownership of Delegates, Observers, and Targets" (page
196) for further information.

# Composite

The composite design pattern composes related objects into tree structures to represent part-whole
hierarchies. The pattern lets individual objects treat compositions of objects uniformly.

The Composite pattern is part of the Model-View-Controller aggregate pattern, which is describe in "The
Model-View-Controller Design Pattern" (page 160).
