If you do not follow this ownership policy, two bad things are likely to happen in the Cocoa program. Because you did not release created, copied, or retained objects, your program is leaking memory. A further event that can happen to an object during its life cycle is archiving. Archiving converts the web of objects that constitute an object-oriented graph—into a persistent form (usually a file) that preserves the identity and relationships of each object in the graph. When the program is unarchiving, your object must be able to encode (decode) its instance variables using the methods of the NSObject class. NSObject adopts the Coding protocol for this purpose. For more information on the archiving of objects, see Archives and Serializations Programming Guide.

# Object Creation

The creation of a Cocoa object always takes place in two stages: allocation and initialization. Without both steps an object creation is generally unusable. Although in almost all cases initialization immediately follows allocation, the two operations play distinct roles in the formation of an object.

# Allocating an Object

When you allocate an object, part of what happens is what you expect, given the term allocate. Cocoa allows enough memory for the object from a region of application virtual memory. To calculate how much memory to allocate, it takes the object's instance variables into account—including their types and order—as specified by the object's class.

To allocate, you send the message alloc or allocZone: to the object's class. In return, you get a "raw" (initialized) instance of the class. The alloc variant of the method uses the application's default zone. A zone is a page-aligned area of memory for holding objects and data by allocation. See Memory Management Programming for more information about objects.

An allocation message does other things besides allocating:

+   - It sets the object's retain count to one (as described in "How Memory Management Works" (page 73)).
- It initializes the object's isa instance variable to point to the object's class, a runtime object in its own right that is compiled from the class definition.
- It initializes all other instance variables to zero (or the equivalent type for zero, such as nil, NULL, and 0.0).

An object's isa instance variable is inherited from NSObject, which is common to Cocoa objects. After allocation sets isa to the object's class, the object is integrated into the runtime's view of the inheritance hierarchy and the current network of objects (class and instance) to constitute a program.
