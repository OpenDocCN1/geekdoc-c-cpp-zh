## What Is Cocoa?

- **File system and URL.** NSFileManager provides a consistent interface for file operations such as creating, deleting, and moving files; NSFileHandle permits file operations at a lower level (for example, seeking within a file); NSBundle finds resources in bundles and dynamically loads some of them (for example, nib files and code). You use NSURL... to represent, access, and manage URL sources of data.

- **Concurrency.** NSThread creates multithreaded programs, and there are various lock classes for controlling access to resources by threads. You use NSOperation and NSOperationQueue to perform multiple operations (concurrent or non-concurrent) in priority and dependence order. With NSTask, your program can fact-off a process to perform and monitor its progress.

- **Interprocess communication.** Most of the classes in this category represent various kinds of system ports, sockets, and servers that are useful for implementing low-level IPC. NSPipe represents a BSD pipe, a unidirectional communication channel between processes.

> Note: The name classes are not in the iOS version.

- **Networking.** The NSSystemService and NSServiceBrowser classes support the zero-configuration networking architecture Bonjour. Bonjour is a powerful system for publishing and browsing for services on IP network.

- **Notifications.** See the summary of the notification classes in "Foundation Paradigms and Policies" (page 31).

- **Archiving and serialization.** The classes in this category make object distribution and persistence possible. NSCoder and its subclasses, using the NSCoding protocol, represent the data object in an architecture-independent way using class information to store with the data. NSKeyedarchiver and NSKeyedunarchiver offer methods for encoding objects and values and decoding them in a way that is not dependent on the order of encoding methods.

- **Objective-C classes.** NSException and NSAssertion provide an object-oriented way of making assertions and handling exceptions in code. NSInvocation is a static representation of an Objective-C message that you can store and later invoke a message in another object; it is used by the undo manager (UndoManager) and by the distributed objects system. NSMethodSignature records the type of information and is used in method forwarding. ClassDescription is an abstract class for decoding and querying the relationships and properties of a class.

- **XML processing.** Foundation on platforms has the XMLParser class, which is an object-oriented implementation of a string parser that enables you to process XML data in an event-driven way.

- **Predicates and expressions.** The predicate classes—NPredicate, NSCompoundPredicate, and NSComparisonPredicate encapsulate the logic conditions to fetch or filter an object. NSPrediction objects represent expressions in a predicate.

## What Is Cocoa?

The Foundation framework for iOS has a subset of the classes for Mac OS X. The following categories of classes are present only in the Mac OS X version of Foundation:

- *Spotlight queries.* NSMetadataItem, NSMetadataQuery and related query classes encapsulate file-system metadata and make it possible to query that metadata.

- *Scripting.* The classes in this category help to make your program responsive to AppleScript scripts and Apple event commands.

- *Distributed objects.* You use the distributed object classes for communication processes between the same computer or on different computers on a network. Two of these classes, NSDistantObject and NSProtocolChecker, have a root class (NSProxy) different from the root class of the rest of Cocoa.

## AppKit (Mac OS X)

AppKit is a framework containing all the objects you need to implement your graphical, event-driven interface in Mac OS X; windows, buttons, menus, scrollers, text fields—AppKit handles all the details for you as it efficiently draws on the screen, communicates with hardware devices and buffers, clears areas of drawing and clips views. The number of classes in AppKit may seem daunting at first. However, most AppKit classes are support classes that you use indirectly. They allow you the choice at which you use AppKit:

- *Use Interface Builder to create connections from user-interface objects to your application's controller objects, which manage the user interface and coordinate the flow of data between the user interface and internal data structures. For this, you might use off-the-shelf controller objects (for Cocoa bindings) or you may need to implement one or more custom controller classes—particularly the action and delegate methods of those classes. You might need to implement a method that is invoked when the user chooses a menu item (unless it has a default implementation that is acceptable).

- *Control the user interface programmatically, which requires more familiarity with AppKit classes and protocols. For example, allowing the user to drag an icon from one window to another requires some programming and familiarity with the NSDragger... protocols.

- *Implement your own objects by subclassing NSObject or other classes. When subclassing, you write your drawing methods using graphics functions. Subclassing requires a deeper understanding of how AppKit works.
