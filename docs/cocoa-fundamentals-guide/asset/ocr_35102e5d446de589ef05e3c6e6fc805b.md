What Is Cocoa?

+   **Toolbars, navigation bars, split views, and view controllers.** The ViewController is a class for managing views. A view controller provides methods for creating and observing views, overlays, handling view rotation, and responding to low-memory warnings. UIKit includes concrete subclasses of ViewController for managing toolbars, navigation bars, and images.

Applications use toolbars and navigation bars to manage behavior relative to the "main" view on screen; toolbars are placed beneath the main view and navigation bars above it. You can use toolbar (UIToolbar) to switch between modes or views of an application; you can also use to display a set of functions that perform some action relative to the current view. You use navigation bars (UINavigationBar) to manage sequences of views or views in an application, and in effect, to "drill down" to navigate a hierarchy of objects defined by the application; the Mail application, for example, uses a navigation bar to navigate from accounts to mail folders and to individual email messages. On iPad, applications can use a UISplitViewController to present a master-detail interface.

# Text

Users can enter text in an iOS application through a text view (UITextView) or a text field (UITextField).These classes adopt the UITextInputTraits to specify the appearance and behavior of the virtual keyboard that is presented when users use the text-entry box; subclasses that enable text entry should also conform to this protocol. Applications can draw text in views using NSStringDrawing, a category on the NSString class. With the UIFont class can specify the font characteristics of text in all objects, including table cells, navigation bars, and labels.

Applications that do their own layout and font management can adopt UITextField and use related classes to communicate with the text system of iOS.

# Comparing AppKit and UIKit Classes

AppKit and UIKit are Cocoa frameworks that are designed for different platforms, one for Mac OS X and the other for iOS. Because of this affinity, it not surprising that many of the classes in each framework have similar names; in most cases, the prefix ("NS" "UI") is the only name difference. The similarly named classes fulfill similar roles, but there are differences. These differences can be a matter of scope, inheritance, or of design. Generally, UIKit classes have fewer methods than their AppKit counterparts.
