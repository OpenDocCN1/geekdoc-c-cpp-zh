# What Is Cocoa?

| Classes | Comparison |
| --- | --- |
| NSResponder Responder | These classes also have nearly identical roles. They are abstract classes that define an interface for responding to events and managing the responder chain. The main difference is that the NSResponder event-handling methods are defined for the mouse and keyboard, whereas the UIResponder methods are defined for the Multi-Touch event. |
| NSWindow Window | The UI class occupies a place in the class hierarchy different from the NSWindow class in AppKit; it is a subclass of UIView, whereas the AppKit class inherits from NSResponder. UI has a much more restricted role in an application that also provides an area for displaying views, dispatches events to these views, and converts between window and view coordinates. |
| NSView View | These classes are very similar in purpose and in their sets of methods. They allow you to manage and resize views, manage view content, and convert view coordinates. The design of UIView, however, makes view objects inherently capable of animation. |
| NSControl Control | Both classes define a mechanism for objects such as buttons and sliders that, when manipulated, the control object sends an action message to a target object. The classes implement the target-action mechanism in different ways, because of the difference between event models. [The Target-Action Mechanism](#) |
| NSViewController Controller | The role of both these classes is, as their names suggest, to manage views. How they accomplish this task is different. The management provided by NSViewController is dependent on bindings, which is a technology supported only on Mac OS X used in the iOS application model for modal and navigation user interfaces (for example, the views controlled by navigation). |
| UITableView Table | UITableView inherits from NSControl, but UITableView does not inherit from UITextView. More importantly, UITableView objects support multiple columns of data; UITableView displays only a single column of data at a time, and thus fewer lists than functions of tabular data.|

Many the classes you find have some differences. For example, UIKit has the UITextField and UILabel, the former for editable text fields and the latter for nonempty text fields as labels; with the UITextField you can create both kinds of text fields by simply setting text-attributes. Similarly, the NSIndicator class creates objects in styles that correspond to instances of the UIProgressIndicator and ProgressBar classes.
