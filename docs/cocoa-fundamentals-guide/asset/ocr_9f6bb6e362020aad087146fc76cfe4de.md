# Using Objective-C

Work gets in an object-oriented program through messages; one object sends a message to another object. Through the message, the object requests something from the receiving object (receiver). It requests that the receiver perform action, return some value, or do both.

Objective-C adopts a unique syntactic for messaging. Take the following statement from the SimpleCocoaTool in [Listing 2-2](page 55):

```
Enumerator *enum = [sorted_args objectEnumerator];
```

The message expression is on the right side of the assignment, enclosed by the square brackets. The left-most item in the message expression is the receiver, a variable or expression representing the object to which the message is sent. In this case, the receiver is sorted_args, an instance of NSArray class. Following the receiver is the message.( For now, the discussion focuses on syntax and does not look deeply into how that messages in SimpleCocoaTool actually do.) The message objectEnumerator invokes a method of the sorted_args object named objectEnumerator, which returns a reference to an object that is held by the variable enum on the left side of the assignment. This variable is statically typed as an instance of NSEEnumerator class. You can diagram this statement as:

```
NSName *variable = [receiver message];
```

However, this is simple and not really accurate. A message consists of a selector and the parameters of the message. The Objective-C runtime uses a selector, such as objectEnumerator above, to look up a selector in a table to find the method to invoke. A selector is a unique identifier that represents a method and has a special type, SEL. Because it's so costly, the selector used to look up a selector is frequently called a selector. The above statement is more correctly shown as:

```
NSName *variable = [receiver selector];
```

Messages often have parameters, which are sometimes called arguments. A message with a single parameter affixes a colon to the selector and names the parameter right after the colon. This is constructed with a keyword; a keyword ends with a colon, and a parameter follows the colon. Thus we could diagram a message expression with a single parameter (and assignment) as follows:

```
NSName *variable = [receiver keywordparameter];
```

If a message has multiple parameters, the selector includes all keywords, including colons, but the selector does not include anything else, such as return or parameter types. A message expression with multiple keywords (plus assignment) could be diagrammed as follows:

```
NSName *variable = [receiver keyword1:param1 keyword2:param2];
```
