Adding Behavior to a Cocoa Appm

+   In UIKit, the application sends application:didFinishLaunchingWithOptions: to the delegate.

In these methods the delegate can restore application state and specify global application logic that needs to happen just once in the application's runtime existence. Just before it terminates, the application object for both frameworks sends willTerminate: to its delegate, which can implement the method to gracefully handle program termination by saving documents (and particularly in iOS) application state.

The Cocoa frameworks gives you numerous hooks for events ranging from viewing to activation and de. Sometimes these are implemented as delegate messages and require you to be the delegate of the framework object and to implement the required method. In iOS, they can be inherited from ViewController that controllers override. (See "Communicating with Objects" (page 175) for more on decoding and notification.)

# Initialize or Decode?

If you want objects of your class to be decoded and archived, the class must conform to the NSCoding protocol; it implements encodeCoder and decode them initWithCoder:. Instead of an initializer method or methods, the initWithCoder: is invoked to initialize an object created from archive.

Because the class's initializer method and initWithCoder: might do much of the same work, it makes sense to centralize common work in a helper method called by both the initializer and initWithCoder:. For example, as part of its set-up routine, an object specifies drag types and dragging source, it might implement something such as in Listing 3-4.

Listing 3-4 Initialization helper method

```
-initWithFrame:(CGRect)frame {
    self = [super initWithFrame:frame];
    if (self) {
        [self setTitle:[NSColor lightGrayColor]];
        [self registerForDragging];
    }
    return self;
}
initWithCoder:(NSCoder *)coder {
    self = [super initWithCoder:coder];
    titleColor = [coder decodeObject: copy];
    [self registerForDragging];
    return self;
}
```
