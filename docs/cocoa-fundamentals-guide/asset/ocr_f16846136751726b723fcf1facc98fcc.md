# Foundation Paradigms and Policies

Foundation introduces several paradigms and policies to Cocoa programming to ensure consistent behavior and expectations among the objects of a project in certain situations:

+   **Object retention and disposal.** The Objective-C runtime and Foundation give Cocoa programs two ways to ensure objects persist when they are needed and free them when they are longer needed. Garbage collection, which was introduced in Objective-C 2.0, automatically tracks and decomposes objects that you no longer needs, freeing up memory. Foundation still offers the traditional approach of memory management. It institutes a policy of object ownership where that are responsible for releasing objects they have created, copied, or explicitly retained. `NSObject` class and methods `NSAutleasepool` implement a delayed release mechanism and Cocoa programs have a consistent convention for retaining objects for the caller responsible. For more about garbage collection and explicit memory management, see [Object Retention and Disposal].

iOS Garbage collection is not available to applications running iOS.

+   **Mutable classes.** Various value and container classes in Foundation have a mutable variant of an immutable class, with the mutable class being a subclass of the immutable one. If you need to dynamically change the value or membership of such an object, you create an instance of the mutable class. Because it inherits from the immutable, you can pass the mutable instance in methods that take the immutable type. For more on object mutability, see "Object Mutability" (page 90).

+   **Class clusters.** A class cluster is an set of private subclasses for which the abstract class acts as an interface. Depending on the context (particularly the method you use to create an object), an instance of the optimized class is returned to you. `NSString` and `NSMutableString`, for example, act as brokers for instances of private subclasses optimized for different kinds of storage. Over the years the set of concrete classes has changed several times without breaking applications. For more on class clusters, see "Class Clusters" (page 95).

+   **Notifications.** Notification is a major design pattern in Cocoa. It is based on a broadcast mechanism that allows objects (called observers) to be informed of what another object is doing or encountering in the world of user or system events. The object notifying can be unaware of the existence or identity of the observers. There are several types of notifications: synchronous, asynchronous, and distributed. The Foundation notification mechanism is implemented by `NSNotificationCenter`, `NSNotificationQueue`, and `NSDistributedNotificationCenter` classes. For more on, see "Notifications" (page 190).
