> **Note:** This specifies the nonatomic attribute for the properties, which is guaranteed to return a default atomic. When a property is atomic, its synthesized getter method is guaranteed to return a valid value, even when other threads are executing simultaneously. See the discussion of Properties in The Objective-C Programming Language for a discussion of versus nonatomic properties, especially with regard to performance. For on thread-safety issues, see *Threading Programming Guide*.

The property declaration in the following example tells the compiler that the preview property is read-only so it will not expect to find a setter. By the @dynamic directive in the @implementation block, it also instructs the compiler not to synthesize the getter method, and provides an implementation of that method.

```
@interface MyClass : NSObject
NSImage *previewImage;
@property (readonly) NSImage *previewImage;
// ...
@end
@implementation MyClass
@dynamic previewImage {
    if (previewImage == nil) {
        // lazy load image and assign to ivar
    }
    return previewImage;
}
// ...
@end
```

# Implementing Accessor Methods

For reasons of convention—and it enables classes to be compliant with key-value coding (see [Key-Value Mechanisms](page 128))—the names of accessor methods must have a specific form. For a method that returns the value of an instance variable (sometimes called the getter), the name of the method is the same as the instance variable. For a method that sets the value of an instance variable (the setter), the name begins with "set" and is immediately followed by the name of the instance variable (with the first letter uppercase). For example, if you have an instance variable named "color," the declarations of the getter and setter accessors would be

+   - (NSColor*)color;
- (void)setColor:(NSColor*)aColor;
