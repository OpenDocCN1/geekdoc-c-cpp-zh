# What Is Cocoa?

+   - **Core Graphics.** The Cocoa drawing and imaging classes are (quite naturally) closely based on the Core Graphics framework, which implements Quartz and the window server.

+   - **Launch Services.** The NSWorkspace class exposes the underlying capabilities of Launch Services. Cocoa also uses the application-registration feature of Launch Services to get the icons with applications and documents.

> Note: The intent of this architectural overview is not to itemize every relationship that Cocoa has to other parts of Mac OS X. It serves the most interesting ones in order to give you a general idea of the architectural context of the framework.

Apple has designed Cocoa so that some of its programmatic interfaces give access to the capabilities of underlying technologies that typically need. But if you require such capability is not exposed by the programmatic interfaces of Cocoa, or if you need some finer control of what happens in your application, you may be able to use any underlying framework directly. (A prime example is Cocoa Graphics: by calling functions or of OpenGL, your code can draw gone more complex and nuanced images than is possible with the Cocoa drawing methods.) Frankly, using these lower-level frameworks is not a problem because the programmatic interfaces of most dependent frameworks are written in standard ANSI C, of Objective-C language is a superset.

**Further Reading:** *Mac OS X Technology Overview* gives an overview of the frameworks, services, technologies, and other components of Mac OS X. *Apple Human Interface Guidelines* specifies how the Aqua human interface should appear and behave.

# How Cocoa Fits into iOS

The application-framework layer of iOS is called Cocoa Touch. Although the IOS infrastructure on which Cocoa Touch depends is similar to for Cocoa in Mac OS X, there are some significant differences. Compare Figure 1-2, which depicts the architectural setting of IOS, to the diagram in Figure 1-1 (page 15). The iOS diagram also shows the supporting software as a series of layers going from a Core Foundation to a set of application frameworks, the most critical (for layers) being the UIKit framework. In the Mac OS X diagram, the diagram has middle layers consisting of core-services frameworks and graphics media frameworks and libraries. Here also, a component at one layer often has dependencies on the layer beneath.
