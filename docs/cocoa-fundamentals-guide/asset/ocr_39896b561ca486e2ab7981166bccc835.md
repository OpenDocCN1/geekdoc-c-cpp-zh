The UIKit framework uses delegation extensively and always implements it using formal protocols. The application delegate is extremely important in an application running in iOS because it must respond to application-launch, application-quit, low-memory, and other messages from the application object. The application delegate must manage the UIApplicationDelegate protocol.

Delegating objects do not (and should) retain their delegates. However, clients of delegating objects (applications) are responsible for ensuring that their delegates are around to receive messages. To do this, they may need to retain the delegate in memory-managed code. This precaution applies to data sources, notification observers, and targets of action. Note that in a garbage-collection environment, the reference to the delegate is strong because the retain-cycle problem does not apply.

Some AppKit classes have a restricted type of delegate called a modal delegate. Objects of these classes (NSOpenPanel, for example) run modal delegates that invoke a handler method in the designated delegate when the user clicks the OK button. Modal delegates are limited in scope to the operation of the modal dialog.

The existence of delegates has other pragmatic uses. For example, with delegates it is easy for two coordinators in the same program to find and communicate with each other. For example, the object controlling the application can easily find the controller of the application's inspector window (assuming it's the current keyWindow) using code to simulate the following:

```
id winWindow = [[NSApp delegate];
```

And you can find the application-controller object—by definition, the delegate of the global application instance—by doing something to the following:

```
id appController = [[NSApp delegate];
```

# Data Sources

A data source is a delegate except that, instead of being delegated control of the user interface, it is delegated control of data. A data source is an outlet held by NSView and UIView objects such as tables and outline views that require a source to populate their rows of visible data. The data source for a view is usually the same object that acts as its delegate, but it can be any object. As the delegate, the data source must implement one or more methods of an informal protocol to supply with the data it needs, and in more advanced implementations, to handle data users directly edit in views.
