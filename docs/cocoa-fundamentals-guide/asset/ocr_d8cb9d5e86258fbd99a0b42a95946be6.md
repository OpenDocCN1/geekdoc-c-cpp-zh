# Cocoa Objects

A root class is so-called because it lies at the root of a class hierarchy—in this case, the Cocoa class hierarchy. The root class inherits from no other class, and all classes in the hierarchy inherently inherit from it. Along with the Objective-C language, the root class is primarily where Cocoa accesses and interacts with the Objective-C runtime. Cocoa objects derive the ability to behave as objects large part from the root class.

Cocoa supplies two root classes: NSObject and NSProxy. Cocoa defines the latter class, an abstract subclass, for objects that act as stand in for others; NSProxy is essential in the distributed objects architecture. Because of this specialized role, NSProxy appears frequently in Cocoa programs. When developers refer to a root or base class, they always mean NSObject.

This section looks at NSObject, how it interacts with the runtime, and the behavior and interface for all Cocoa objects. It especially describes the methods NSObject declares for allocation, initialization, memory management, introspection, and runtime support. These concepts are fundamental to an understanding of Cocoa.

# NSObject

NSObject is the root class of most Objective-C class hierarchies; it has no superclass. From NSObject, other classes inherit a basic interface to the runtime system for the Objective-C language, and instances inherit their ability to behave as objects.

Although it not strictly an abstract class, NSObject is virtually one. By itself, an NSObject instance cannot do anything beyond being a simple object. To add any attributes and logic to specify your program, you must create one or more classes inheriting from NSObject or any other class derived from NSObject.

NSObject adopts the NSObject protocol ("Root Class—and Protocol" (page 67)). The NSObject protocol allows for multiple objects. For example, NSProxy, the root class, does not inherit from NSObject but adopts the protocol so that it shares a common interface with other Objective-C objects.

# Root Class—and Protocol

NSObject is the name of both a class and a protocol. Both are essential to the definition of an object in Cocoa. The NSObject protocol specifies the basic interface required of all root classes in Cocoa. Thus not only the class adopts the identically named root, but the other root class NSProxy, adopts it as well. The NSObject class further specifies the basic programmatic interface for any object that is not a proxy object.

The design of Classes uses a protocol such as NSObject in the overall definition of Cocoa objects (rather than making the methods of the protocol of class interface) make multiple root classes. Each root class shares a common interface, as defined by the protocols adopt.

In another sense, NSObject is not the only root protocol. Although the NSObject class does not formally adopt NSCopy, NSMutableCopying, and NSCoding it declares and implements methods related to those objects. (Moreover, the NSObject.h header file, which contains the definition of the NSObject class, also contains the definitions of the root protocols NSObject, NSCopy, NSMutableCopying, and NSCoding) object copying, and decoding are fundamental aspects of object behavior. Many, if not, subclasses are expected to adopt or follow these protocols.
