# A Composite Object: An Example

To illustrate the use of a composite object, imagine you have a mutable array object that tests changes against some validation criteria before allowing any modification to the array's contents. The example that follows a class called ValidatingArray, which contains a standard mutable array object. ValidatingArray overrides all of the primitive methods declared in its superclasses, NSArray and NSMutableArray. It also delays the array, validatingArray, and init methods, which can be used to create and initialize an instance.

```
#import <foundation/foundation.h>

interface ValidatingArray : NSMutableArray

    NSMutableArray *embeddedArray;

+validatingArray;
-init;
-(unsigned)count;
-(object) objectAtIndex:(unsigned)index;
-(void)addObject:(object)at:(unsigned)index;
-(void)replaceObject:(object)at:(unsigned)index;
-(void)removeLastObject;
-(void)insertObject:(object)at:(unsigned)index;
-(void)removeAtIndex:(unsigned)index;

@end
```

The implementation file shows how in an init method of the ValidatingArrayclass, the embedded object is created and assigned to the embeddedArray variable. Messages that access access the array don't modify its contents are relayed to the embedded object. Messages that could change the contents are scrutinized (in pseudocode) and relayed only if they pass the hypothetical validation test.

```
#import "ValidatingArray.h"

@implementation ValidatingArray

-init {
    self = [super init];
    if (self) {
        embeddedArray = [[NSMutableArray allocWithZone:zone] init];
    }
    return self;
}

+validatingArray {
    return [[self alloc] autorelease];
}

-(unsigned)count {
    return [embeddedArray count];
}

-objectIndex:(unsigned)index
```
