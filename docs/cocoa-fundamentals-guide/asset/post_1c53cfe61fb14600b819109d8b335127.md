## Overview of Root-Class Methods

The NSObject root class, along with the adopted NSObject protocol and other root protocols, specify the following interface and behavioral characteristics for all nonproxy Cocoa objects:

+   **Allocation, initialization, and duplication.** Some methods of NSObject (including some from adopted protocols) deal with the creation, initialization, and duplication of objects:
- The `alloc` and `allocWithZone:` methods allocate memory for an object from a memory zone and set the object to point to its runtime class definition.
- The `init` method is for object initialization, the procedure that sets the variables of an object to a known initial state. The class methods `initialize` and `load` give classes a chance to initialize themselves.
- The `new` method is a convenience method that combines allocation and initialization.
- The `copy` and `copyWithZone:` methods make copies of any object that is a member of a class implementing these methods (using the NSCopying protocol); the `mutableCopy` and `mutableCopyWithZone:` (defined in the NSMutableCopying protocol) are implemented by classes that want to make mutable copies of their objects.

See "Object Creation" (page 77) for more information.

+   **Object retention and disposal.** The methods are particularly important to an object-oriented program that uses the traditional, explicit, form of memory management:
- The `retain` method increments an object's retain count.
- The `release` method decrements an object's retain count.
- The `autorelease` method also decrements an object's retain count, but in a deferred fashion.
- The `retainCount` method returns an object's current retain count.
- The `dealloc` method is implemented by a class to release its objects' instance variables and dynamically allocated memory.

See "How Memory Management" (page 73) for more information about explicit memory management.

+   **Introspection and comparison.** Many methods enable you to make runtime queries about an object. These introspection methods help to discover an object's position in the class hierarchy, determine whether it conforms to a certain protocol, and test whether it is a class of these methods.

+   - The superclass and class methods (class and instance) return the receiver's superclass, respectively, as Class objects.

+   - You can determine the class membership of objects with the methods isKindOfClass: and isMemberOfClass:; the latter method is for testing whether the receiver is an instance of the specified class. The method isSubclassOfClass: tests inheritance.

+   - The respondsToSelector: method tests whether the receiver implements a method by a selector. The class method instancesRespondToSelector: tests whether instances of given class implement the specified method.

+   - The conformsToProtocol: method tests whether the receiver (object or class) conforms to a given protocol.

+   - The isEqual: and hash methods are used in object comparison.

+   - The description method allows an object to return a string describing its contents; this is often used in debugging (the print-object command) and the %@ specifier for objects in formatted strings.

See "Introspection" (page 87) for more information.

**Object encoding and decoding.** The following methods permit object encoding and decoding (as part of the archiving process):

+   - The encodeWithCoder: and initWithCoder: are the sole members of the NSCoding protocol. The first allows an object to encode its variables and the second enables an object to initialize from decoded instance variables.

+   - The NSObject declares other methods related to object encoding: classForCoder, replacementObjectForCoder:; and awakeAfterDecoding:

See Archiving and Serialization Programming Guide for further information.

+   - **Message forwarding.** The forwardInvocation: method permits an object to forward a message to another object.

+   - **Message dispatch.** A set of methods beginning with performSelector allows you to dispatch messages after a specified delay and dispatch messages (synchronously or asynchronously) from a secondary thread to the main thread.

NSObject has several other methods, including class methods for versioning and posting (the latter to present itself to the runtime as another class). It also includes methods that you access runtime structures, such as method selectors and function pointers to method implementations.

## Instance and Class Methods

The runtime system methods defined in the root class are in a special way. Instance methods defined in a root class can be performed by both instances and classes. Therefore, all classes have access to the instance methods defined in the root class. Any object can perform any instance method, provided it doesn't have a class with the same name.

For example, a class could be sent messages to perform the NSObject instance methods respondsToSelector: and performSelector:withObject: as in this example:

```
SEL method = @selector(riskAll:);
if ([MyClass respondsToSelector:method])
[MyClass performSelector:method withObject:self];
```

Note that the only instance methods allowed to a class object are defined in its root class. If MyClass implemented either respondsToSelector: or performSelector:withObject:, these new versions would be only available to instances. If the object for MyClass implemented respondsToSelector: or performSelector:withObject: as class methods rather than instance methods, the class would perform these new versions.

## Object Retention and Disposal

Objective-C gives you two ways to ensure that objects persist when they are needed and when they are no longer needed, the preferred approach is to use the technology of garbage collection: The runtime detects objects that are no longer needed and disposes of them automatically. (The preferred approach is the simpler in most cases.) The second approach, called memory management, is based on reference counting: An object carries a numerical value; when this value reaches zero, the object is deallocated.

The amount of work you do, as a developer writing Objective-C code, to take advantage of garbage collection or memory management varies.

+   - Garbage Collection. To enable garbage collection, turn on the Objective-C Garbage Collection flag building in Xcode. For each of your custom classes, you might also have to implement the finalize method to remove instances as notification observers and to free any resources that are not instance variables. Also, ensure that in your nib the object acting as File's Owner maintains an outlet connection to that top-level object you want to persist.

> iOS Note: Garbage collection is not supported in iOS.
