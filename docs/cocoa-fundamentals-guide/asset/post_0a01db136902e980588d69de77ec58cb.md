# Using Objective-C

Work gets in an object-oriented program through messages; one object sends a message to another object. Through the message, the object requests something from the receiving object (receiver). It requests that the receiver perform action, return some value, or do both.

Objective-C adopts a unique syntax for messaging. Take the following statement from the SimpleCocoaTool in [Listing 2-2](page 55):

```
Enumerator *enum = [sorted_args objectEnumerator];
```

The message expression is on the right side of the assignment, enclosed by the square brackets. The left-most item in the message expression is the receiver, a variable or expression representing the object to which the message is sent. In this case, the receiver is sorted_args, an instance of NSArray class. Following the receiver is the message. (For now, the discussion focuses on syntax and does not look deeply into how those messages in SimpleCocoaTool actually do.) The message objectEnumerator invokes a method of the sorted_args object named objectEnumerator, which returns a reference to an object that is held by the variable enum on the left side of the assignment. This variable is statically typed as an instance of NSEEnumerator class. You can diagram this statement as:

```
NSName *variable = [receiver message];
```

However, this is simple and not really accurate. A message consists of a selector and the parameters of the message. The Objective-C runtime uses a selector, such as objectEnumerator above, to look up a selector in a table to find the method to invoke. A selector is a unique identifier that represents a method and has a special type, SEL. Because it's so costly, the selector used to look up a selector is frequently called a selector. The above statement is more correctly shown as:

```
NSName *variable = [receiver selector];
```

Messages often have parameters, which are sometimes called arguments. A message with a single parameter affixes a colon to the selector and names the parameter right after the colon. This is constructed with a keyword; a keyword ends with a colon, and a parameter follows the colon. Thus we could diagram a message expression with a single parameter (and assignment) as follows:

```
NSName *variable = [receiver keywordparameter];
```

If a message has multiple parameters, the selector includes all keywords, including colons, but the selector does not include anything else, such as return or parameter types. A message expression with multiple keywords (plus assignment) could be diagrammed as follows:

```
NSName *variable = [receiver keyword1:param1 keyword2:param2];
```

As with function parameters, the type of parameter must match the type specified in the method declaration. As an example the following message expression from SimpleCocoaTool:

```objectivec
NSCountedSet *cset = [[NSCountedSet alloc] initWithArray:param];
```

Here `param`, which is also an instance of the NSArray class, is the parameter of the message named initWithArray.

The initWithArray: example cited above is interesting in that it illustrates nesting. With Objective-C, you can nest one message inside another; the object returned by one message expression is sent to the receiver by the message expression it encloses. To interpret nested message expressions, start with the inner expression and work your way out. The interpretation of the statement would be:

1. The alloc message is sent to the NSCountedSet class, which creates (by allocating memory for it) an uninitialized instance of the class.

> Note: Objective-C classes are objects in their own right and can send messages to them as well as their instances. In a message expression, the receiver of a class message is always a class object.

2. The initWithArray message is sent to the uninitialized instance, which initializes it with the array args and returns a reference to it.

Next consider this statement from the main routine of SimpleCocoaTool:

```objectivec
NSArray *sorted_args = [[NSArray alloc]
sortedArrayUsingSelector:selector(compare:)];
```

What's noteworthy about this message expression is the parameter of the sortedArrayUsingSelector message. This parameter requires the use of the @selector compiler to create a selector to be used as a parameter.

Let's pause a moment to review message and method methodology. A message is essentially a function defined and implemented by the class of which the receiver of a message is a member. A message is a selector name (perhaps consisting of one or more keys) along its parameters; a message is sent to a receiver and results in the invocation (or execution) of the method. A message expression encompasses both receiver and message. Figure 2-2 depicts these relationships.

# Cocoa Objects

A root class is so-called because it lies at the root of the hierarchy. In Objective-C, most classes inherit from it. The design of Classes uses a protocol such as NSObject in the overall definition of Cocoa (rather than making the methods of the protocol of class interface) make multiple root classes. Each root class shares a common interface, as defined by the protocols adopt.

Objective-C supplies two root classes: NSObject and NSProxy. Because of this specialized role, NSProxy appears frequently in Cocoa. In another sense, NSObject is not the only root protocol. Although it not strictly abstract, NSObject is virtually one.

The NSObject class further specifies the basic programmatic interface for any object that is not a proxy object. When developers refer to a root class, they always mean NSObject.

This section looks at NSObject, how it interacts with the runtime, and the behavior for all objects. It especially describes the methods NSObject declares for allocation, initialization, memory management, and runtime support.

# NSObject

NSObject is the root class of most-class hierarchies; it has no superclass. By itself, an NSObject instance cannot do anything beyond being a simple object. To add any attributes and logic to specify your program, you must create one or more classes inheriting from NSObject or any other class.

# Root Class—and Protocol

NSObject is the name of both a class and a protocol. Both are essential to the definition of an object in Cocoa. The NSObject protocol specifies the basic interface required of all root classes in Cocoa. Thus not only the class adopts the identically named root, but the other root class NSProxy, adopts it as well. The NSObject class further specifies the basic programmatic interface for any object that is not a proxy object.
