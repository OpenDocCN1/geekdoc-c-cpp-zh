

# 第 2 章
Cocoa 对象

> 注：其他 Cocoa 类可以（并且确实）通过分类向 NSObject 添加方法。这些分类通常在委托中定义非正式协议；它们允许委托选择实现该分类的哪些方法。然而，NSObject 上的这些分类不被视为基本对象接口的一部分。

## 根类方法的概述

NSObject 根类，以及采用的 NSObject 协议和其他根协议，为所有非代理 Cocoa 对象指定了以下接口和行为特征：

+   **分配、初始化和复制。** NSObject 的某些方法（包括来自采用协议的一些方法）处理对象的创建、初始化和复制：
- `alloc` 和 `allocWithZone:` 方法从内存区域分配对象的内存，并将对象设置为指向其运行时类定义。
- `init` 方法用于对象初始化，即将对象的变量设置为已知初始状态的过程。类方法 `initialize` 和 `load` 给类一个自行初始化的机会。
- `new` 方法是一个便捷方法，将分配和初始化结合起来。
- `copy` 和 `copyWithZone:` 方法复制任何属于实现这些方法的类的对象（使用 NSCopying 协议）；`mutableCopy` 和 `mutableCopyWithZone:`（在 NSMutableCopying 协议中定义）由希望制作其对象可变副本的类实现。

请参阅“对象创建”（第 77 页）了解更多信息。

+   **对象保留和释放。** 这些方法对于使用传统显式形式的内存管理的面向对象程序尤其重要：
- `retain` 方法递增对象的保留计数。
- `release` 方法递减对象的保留计数。
- `autorelease` 方法也递减对象的保留计数，但以延迟的方式进行。
- `retainCount` 方法返回对象的当前保留计数。
- `dealloc` 方法由类实现以释放其对象的实例变量和动态分配的内存。

请参阅“内存管理的工作方式”（第 73 页）了解有关显式内存管理的更多信息。

+   **内省和比较。** 许多方法使您能够对对象进行运行时查询。这些内省方法有助于发现对象在类层次结构中的位置，确定它是否符合某个协议，并测试它是否是这些方法的类。

+   - 超类和类方法（类和实例）分别以 Class 对象的形式返回接收者的超类。

+   - 您可以使用 `isKindOfClass:` 和 `isMemberOfClass:` 方法确定对象的类成员资格；后一种方法用于测试接收者是否是指定类的实例。`isSubclassOfClass:` 方法测试继承关系。

+   - `respondsToSelector:` 方法测试接收者是否实现由选择器指定的方法。类方法 `instancesRespondToSelector:` 测试给定类的实例是否实现指定的方法。

+   - `conformsToProtocol:` 方法测试接收者（对象或类）是否符合给定协议。

+   - `isEqual:` 和 `hash` 方法用于对象比较。

+   - `description` 方法允许对象返回描述其内容的字符串；这通常用于调试（print-object 命令）和格式化字符串中对象的 %@ 格式说明符。

请参阅“内省”（第 87 页）了解更多信息。

**对象编码和解码。** 以下方法允许对象编码和解码（作为归档过程的一部分）：

+   - `encodeWithCoder:` 和 `initWithCoder:` 是 NSCoding 协议的唯一成员。前者允许对象对其变量进行编码，后者使对象能够从解码的实例变量进行初始化。

+   - NSObject 声明了其他与对象编码相关的方法：`classForCoder`、`replacementObjectForCoder:`；以及 `awakeAfterDecoding:`。

请参阅归档和序列化编程指南了解进一步信息。

+   - **消息转发。** `forwardInvocation:` 方法允许对象将消息转发给另一个对象。

+   - **消息分发。** 一组以 `performSelector` 开头的方法允许您在指定延迟后分发消息，并从辅助线程向主线程分发消息（同步或异步）。

NSObject 还有其他方法，包括用于版本控制和发布的类方法（后者用于将自身呈现给运行时作为另一个类）。它还包括访问运行时结构的方法，例如方法选择器和指向方法实现的功能指针。

## 实例方法和类方法

根类中定义的运行时系统方法以特殊方式存在。根类中定义的实例方法既可以由实例也可以由类执行。因此，所有类都可以访问根类中定义的实例方法。任何对象都可以执行任何实例方法，前提是它没有同名的类。

例如，可以向类发送消息以执行 NSObject 实例方法 `respondsToSelector:` 和 `performSelector:withObject:`，如下例所示：

```
SEL method = @selector(riskAll:);
if ([MyClass respondsToSelector:method])
[MyClass performSelector:method withObject:self];
```

请注意，唯一允许类对象使用的实例方法是其根类中定义的方法。如果 MyClass 实现了 `respondsToSelector:` 或 `performSelector:withObject:`，这些新版本将仅对实例可用。如果 MyClass 的对象将 `respondsToSelector:` 或 `performSelector:withObject:` 实现为类方法而不是实例方法，则类将执行这些新版本。

## 对象保留和释放

Objective-C 为您提供了两种确保对象在需要时存在、在不再需要时被释放的方法，首选方法是使用垃圾回收技术：运行时检测不再需要的对象并自动处理它们。（在大多数情况下，首选方法更简单。）第二种方法称为内存管理，基于引用计数：对象携带一个数值；当该值达到零时，对象将被释放。

作为编写 Objective-C 代码的开发人员，您为利用垃圾回收或内存管理所做的工作量各不相同。

+   - 垃圾回收。要启用垃圾回收，请在 Xcode 中打开 Objective-C 垃圾回收构建标志。对于每个自定义类，您可能还必须实现 `finalize` 方法以删除作为通知观察者的实例并释放任何不是实例变量的资源。此外，确保在您的 nib 中，充当文件所有者的对象与您希望持久化的顶层对象保持出口连接。

> iOS 注：iOS 不支持垃圾回收。
