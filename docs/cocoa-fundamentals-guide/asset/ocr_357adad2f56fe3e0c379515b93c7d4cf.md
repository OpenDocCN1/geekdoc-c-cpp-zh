# Types of Overridden Methods

You may choose to define several types of methods in a subclass:

+   Some framework methods are fully implemented and are meant to be invoked by other framework methods. In words, even though you might reimplement them, you don't invoke them elsewhere in your code. They provide some service—data or behavior—required by some other code at some point during program execution. These methods exist in the public interface for just one reason—so that you can override them if you want. They give you an opportunity to substitute your own algorithm for the one used by the framework or to modify or extend the framework algorithm.

An example of this type is `trackWithEvent:` in the `NSView` class of the AppKit. `NSView` implements this method to satisfy the requirement—handling method tracking and selection—but you may override it if you want different behavior.

+   Another type of method is one that makes an object-specific decision, such as whether an attribute is turned on or whether a policy is in effect. The framework implements a default version of this method that makes the decision you, and you might implement your own version and then add a different decision. In many cases, implementation is simply a matter of returning `YES` or `NO`, or a value larger than the default.

The `acceptFirstResponder` method of `Responder` is typical of this sort of method. Views accept `acceptFirstResponder` messages, among other things, if they respond to keystrokes or mouse clicks. By default, `view` returns `NO` for this method—most views don't accept input. But some, should override `acceptFirstResponder` to return `YES`. A UIKit view is the `layer` class method of `UIView`: if you dont not the default class for the view, you can override the method and substitute your own.

+   Some methods might be overridden, but to add something, not to replace the framework implementation of the method does. The subclass version of the method augments the behavior of the superclass. When the framework performs one of these methods, it's important to incorporate the very method it overrides. It does this by sending a message to `super` (the superclass), invoking the framework-defined version of the method.

This kind of method is one that every class in inheritance is expected to contribute to. For example, objects that archive themselves must conform to the `NSCoding` protocol and the `initWithCoder:` and `encodeCoder:` methods. Before a class performs the encoding or decoding to set its instance variables, it must invoke the superclass version of the method.

Sometimes a subclass version of a method wants to reuse the superclass and then add something, the final result. In the `UIView` method `drawRect:`, for example, a subclass of a class that performs complicated drawing wants to draw a border around the drawing, so it would invoke `super` first.

+   Some framework methods do not have at all return some default value (such as `self`) to prevent runtime or compile-time errors. These methods are overridden. The framework cannot define these methods in rudimentary form because they carry out tasks that are entirely program-specific. There's no need to incorporate the framework implementation of the method with a message to `super`.

Most methods that a subclass overrides belong in this group. For example, the `NSDocument` method `ofType:dataOfType:error:` (among others) must be overridden when you create a document-based application.
