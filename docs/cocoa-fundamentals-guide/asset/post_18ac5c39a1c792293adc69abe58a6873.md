## Cocoa Design Patterns

A model controller is a controller that concerns itself with the model layer. It "owns the model: its primary responsibilities are to manage the model and communicate with view objects. Action methods that apply to the model are whole typically implemented in a model controller. The document architecture provides a number of these methods for you; for example, the NSDocument object (which is a central part of the document architecture) automatically handles actions related to saving files.

A view controller is a controller that concerns itself mostly with the view. It "owns" the interface (the views); its primary responsibilities are to manage the interface and communicate with the model. Action methods concerned with data in a view are typically implemented in a view controller. NSViewController (also part of the document architecture) is an example of a view controller.

"Design Guidelines for MVC Applications" (page 165) offers some design advice concerning objects with merged MVC roles.

> Further Reading: Document-Based Applications Overview discusses the distinction between a model controller and a view controller from another perspective.

## Types of Cocoa Controller Objects

The section "Controller Objects Tie the Model to the View" (page 161) sketches the abstract outline of a controller, but in practice it is far more complex. In Cocoa there are general kinds of controller objects: mediating controllers and coordinating controllers. Each kind of controller object is associated with a different set of classes and provides a different range of behaviors.

A mediating controller is typically an object that inherits from the NSController class. Mediating controller objects are used in the Cocoa bindings technology. They facilitate—mediate—the flow of data between view and model objects.

> iOS Note: AppKit NSController class and its subclasses. These classes and the bindings are not available in iOS.

Mediating controllers are ready-made objects that you drag from the Interface Builder library. You can configure these objects to establish bindings between properties of view objects and properties of controller, and then between those controllers and specific properties of a model object. As a result, when the user changes a value displayed in a view, the new value is automatically communicated to a model object for storage—via the mediating controller; and when a property of a model changes, that value is communicated to a view for display. The NSController class and its subclasses—NSObjectController, NSArrayController, NSUserDefaultsController, and NST...

A coordinating controller is typically a NSViewController or NSDocumentController (available only in AppKit), or an instance of a subclass of NSObject. Its role in an application is to oversee—coordinate—the functioning of the entire application or part of the application, as the objects unarchived from a nib. A coordinating controller provides services such as:

- Responding to delegation methods and observing notifications
- Responding to action methods
- Managing the life cycle of objects (for example, releasing them at the proper time)
