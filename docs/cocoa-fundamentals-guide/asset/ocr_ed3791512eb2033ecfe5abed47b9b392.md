# CHAPTER 3
Adding Behavior to a Cocoa Program

To make each property of a subclass compliant with the requirements of key-value coding, do one of the following:

+   - For an attribute or a-to-one relationship named key, implement accessor methods named key (getter) and setKey: (setter). For example, if you have a property named salary, you would have accessor methods salary and setSalary: (if the compiler synthesizes a declared property, it follows this pattern, unless otherwise).
- For a to-many relationship, if the property is based on an instance variable that is a collection (for example, an NSArray object) or an instance method that returns a collection, give the getter method the same name as the property (for example, employees). If the property is mutable, the getter method does not return a mutable collection (as as NSMutableArray); you must insertObject:forKeyAtIndex: and removeObjectForKeyIndex:. If the instance is not a collection and the getter method does not return a collection, you must implement other NSObjectCoding methods.

To make your object KVO compliant, ensure your object is KVC compliant if you are satisfied with automatic notification, you may choose to implement manual key-value observing, which requires additional work.

> **Further Reading:** Read Key-Value Programming Guide and Key-Value Observing Guide to learn more about these technologies. For a summary of the Cocoa bindings technology, which use KVC, KVO, and [Bindings (Mac OS X)](page 187) in [Communicating with Objects](page 175).

# Object Infrastructure

If a subclass is well-designed, instances of that class will behave in ways expected of Cocoa objects. Code using the object can compare to other instances of the class, discover its contents (for example, in a debugger), and perform basic operations with the object.

Custom subclasses should implement, if not all, of the following root-class and binding protocol methods:

+   - **isEqualTo:** and **hash:**—Implement these NSObject methods to bring some object-specific logic to their comparison. For example, if you have instances of your class by a serial number, what is the basis for equality. For further information, see [Inspection](page 87).
- **description**—Implement this NSObject method to return a string that concisely describes the properties or contents of the object.
