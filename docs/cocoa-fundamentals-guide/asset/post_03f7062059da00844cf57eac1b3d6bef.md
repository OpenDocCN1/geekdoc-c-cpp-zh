# What Is Cocoa?

Beginning with Mac OS v10.5, the window and class of the AppKit support enhanced animation features.

NSView is the superclass for all objects displayed in a window. All subclasses implement a drawing using graphics functions; drawRect: is the primary method you override when creating a new NSView.

- Controller classes for Cocoa bindings. The abstract NSController class and its subclasses NSObjectController, NSArrayController, NSDictionaryController, and NSTreeController are part of the implementation of Cocoa bindings. This technology automatically synchronizes the application data in objects and the presentation of that in a user interface. "The Model-View-Controller Design Pattern" (page 160) for a description of these types of controller objects.

- Panels (dialog). The NSPanel class is a subclass of NSWindow that you use to display transient, or modal, information. For example, you would use an instance of NSPanel, rather than an instance of NSWindow, to display error messages or query the user for a remarkable or unusual circumstances. The AppKit implements some dialogs for you, such as the Save, Open, and Print dialogs, using these dialogs gives you a consistent look and feel across operations.

- Menus and cursors. The NSMenu, NSMenuItem, and NSCursor classes define the look and behavior of the menus and cursors that your application displays to.

- Grouping and scrolling views. The NSBox, NSScrollView, and NSSplitView classes provide graphic "accessories" to other objects or collections of views. With the NSBox class you can group elements in window and draw a border around the entire group. The NSSplitView class lets you append views vertically or horizontally, partitioning each view some amount of a common territory; a sliding control bar redistributes the territory among the views. NSScrollView class and its helper, NSCClipView, provide a scrolling mechanism as well as the graphic objects that let the user indent and control a scroll. The NSRuler allows you to add a ruler and markers to a scroll view.

- Table and views. The NSTableView displays data in rows and columns. NSTableView is ideal for but not limited to, displaying database records, where rows correspond to each record and columns contain record attributes. The user can edit individual fields and rearrange the views. You control the behavior and content of an NSTableView by setting its delegate and data source objects. Outline views (instances of NSOutlineView, a subclass of NSTableView) offer another approach to tabular data. With the NSBrowser class you can create an object with which users can display and navigate hierarchical data.

# Text and Fonts

The Cocoa text system is based on the Core Text framework, which was introduced in Mac OS v10.5. The Core Text framework provides a modern, low-level, high-performance technology for laying out text. If you use the Cocoa system, you should use Core Text.

The NSText class implements a simple editable text-input field, and the NSTextView class provides more editing features for large text bodies.

NSTextView, a subclass of the NSText class, defines the extended text system. NSTextView supports rich text, attributes (graphics, file, and other), input management and key binding, and marked text attributes. NSTextView works with the Window and Font menu, rulers and paragraph styles, the Services family, and the pasteboard (Clipboard). NSTextView allows customizing through delegation and notifications—you rarely need to subclass NSTView. You rarely create instances of NSTView programmatically either, because objects in the Interface Builder library, contain NSTField, NSForm, and NSSScrollView, all contain NSTView objects.

It is also possible to use more powerful and creative text manipulation (such as displaying text in a circle) using NSTStorage, NSLayoutManager, NSTContainer, and related classes. The Cocoa text system supports lists, tables, and noncontiguous sequences.

The UIFont and NSFont encapsulate and font families, sizes, and variations. The Font class defines a single object for each distinct font; for efficiency, these objects, can represent a lot of data, are shared by all the objects in your application. The NSFont class defines the Fonts window that is presented to the user.

# Graphics and Colors

The classes NSImage and NSImageRep encapsulate graphics data, allowing you to easily and efficiently access images stored on the disk and displayed. NSImageRep subclasses class how to draw an image from a particular kind of source data. The NSImage class provides multiple representations of the same image, and it also provides behaviors such as caching. The imaging and drawing capabilities are integrated with the Core framework.

Color is supported by the classes NSColor, NSColorSpace, NSColorPanel, NSColorList, NSColorPicker, and NSColorWell. NSColor and NSColorSpace provide a rich set of colors and formats, including custom ones. The other classes are mostly interface classes: they define present panels and views that allow the user to select and apply colors. For example, the user can drag colors from the Colors window to any color.

The NSGraphicsContext, NSBezierPath, and NSAffineTransform classes help you with vector drawing and graphical transformations such as scaling, rotation, and translation.

# Printing and Faxing

The NSPrinter, NSPrintPanel, NSPageLayout, and NSPrintInfo work together to provide the means for printing and faxing the information that your application displays in its windows and views. You can also create a PDF representation of an NSView object.

# Document and File-System Support

You can use the NSFileWrapper class to create objects that correspond to files or directories on disk. NSFileWrapper holds the contents of the file in memory so that it can be displayed, changed, or transmitted to another application. It also provides an icon for dragging the file or representing it as an attachment. You can use the NSManager in the Foundation framework to access and enumerate file.

The NSDController, NSDocument, and NSController classes define an architecture for creating document-based applications. The NSOpenPanel and NSavePanel provide a convenient and friendly user interface for saving, reverting, closing, and managing these documents. The WindowController class is shown in Interface Builder.

# Internationalization and Character Input

If an application is to be used in more than one part of the world, its resources may need to be customized, or localized; for language, country, or cultural region. For example, an application may have separate Japanese, English, French, and German versions of character strings, icons, nib files, or context help. Resource files specific to a .l extension are grouped together in a subdirectory of the bundle. You usually set up localization resources using Interface Builder. See Internationalization Programming Topics for more information.

The NSIServer and NSManager classes, along with the NSText protocol, give your application access to the text management system. This system interprets keystrokes generated by various keyboards and delivers the appropriate text characters or Control-key events to view objects. Typically the text classes deal with these and you won't have to.

# Operating-System Services

The AppKit provides operating-system service for your application classes that implement the following features:

- Sharing data with other applications. Theasteboard class defines the pasteboard, a repository for data that's copied from your application, making this data available to any application that cares to use it. NSPasteboard implements the free cut/paste operation.
- Dragging. With very little programming on your part, custom views can be dragged and dropped anywhere. Objects become part of this dragging mechanism by conforming to protocols; draggable objects conform to the NSDgingSource protocol, and destination objects (receivers of a drop) conform to the NSDgingDestination protocol. The AppKit holds all the details of tracking the cursor and displaying the dragged image.
- Spell Checking. The SpellServer defines a spell-checking service and provides it as a service to other applications. To connect your application to a spell-checking service, you use the NSSpellChecker class. The NSIgnoreMiselledWords and NSChangeSpelling protocols support the spell-checking mechanism.

# Interface Builder

The NSibConnection class and its two concrete subclasses, NSibControlConnector and NSIBOutletConnector, represent connections in Interface Builder. NSibControlConnector manages an action connection in Interface Builder and NSIBOutletConnector manages an outlet connection.
