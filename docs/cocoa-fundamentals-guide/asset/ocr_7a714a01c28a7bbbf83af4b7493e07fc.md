# CHAPTER 2
Cocoa Objects

A formal protocol is usually what is designated by the term protocol in Cocoa. It allows a class to formally declare a list of methods that are an interface to a vended service. The Objective-C language and runtime system support formal protocols; the compiler can check for types based on protocols, and objects can introspect at runtime to verify conformance to a protocol. Formal protocols have their own terminology and syntax. The syntax is different for provider and client:

+   - A provider (which is usually a class) declares the formal protocol.
- A client adopts a formal protocol, and by doing so agrees to implement all required methods of the protocol.
- A class is said to conform to a formal protocol if it adopts the protocol or inherits from a class that adopts it. (Protocols are inherited by subclasses.)

Both the declaration and adoption of a protocol have their syntactic forms in Objective-C. To declare a protocol you must use the @protocol compiler directive. The following example shows the declaration of the NSCCoding protocol (in the Foundation framework's header file NSObject.h).

```
@protocol NSCCoding
-(void)encodeWithCoder:(NSCoder *)coder;
-(id)initWithCoder:(NSCoder *)coder;
@
```

Objective-C 2.0 adds a freedom to formal protocols by giving you the option of declaring optional methods as well as required. In Objective-C 1.0, the adopter of a protocol had to implement all methods of the protocol. In Objective-C 2.0, protocol methods are implicitly required and can be specifically marked as using the @required directive. You can also mark blocks of methods for optional implementation using the @optional directive; all methods declared after this directive, unless there is an @intervening, which can be implemented. Consider these declarations:

```
@protocol MyProtocol
// implementation of this method is required implicitly
-(void)requiredMethod;

@optional
// implementation of these methods is optional
-(void)someOptionalMethod;
-(void)anotherOptionalMethod;

@required
// implementation of this method is required
-(void)anotherRequiredMethod;
@
```

The class that declares the protocol typically does not implement these methods; however, it should invoke them in instances of the class that conforms to the protocol. Before invoking optional methods, it should verify that they are implemented using the respondsToSelector method.

A class adopts a protocol by specifying the protocol, enclosed by angle brackets, at the end of its interface declaration. A class can adopt multiple protocols by delimiting them with commas. This is how the Foundation NSData class adopts three protocols:

```
@interface NSData :Object <NSCopying, NSMutableCopying, NSCoding>
```
