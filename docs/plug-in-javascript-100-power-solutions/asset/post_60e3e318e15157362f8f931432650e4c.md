### When an Array Is Passed

The O() function comprises three parts. The first tests the argument id to see if it is an array, which it does by using the instanceof operator, like this:

```
if (id instanceof Array) ...
```

If it is an array more than one object has been passed to the function, the array tmp is declared as a local array (that can only be accessed by this instance of function) using the var keyword, like this:

```
var tmp = []
```

Then a for(j) loop iterates through the array, using the integer variable j as an index pointer to each individual element.

### Making Recursive Calls

Interestingly, the O() function is called again within each iteration, but with just the single element located at the current array indexed to j. This is known as a recursive function call, meaning that the function calls itself. It is a very neat way to reuse code to get a job done once you have broken it down into a more manageable chunk. The loop code looks like this:

```
for (var j = 0; j < id.length; ++j)
  tmp.push(O(id[j]), property, value)
```

To explain how it works in this instance, one element has been extracted from an array and then that element is passed back to the function, which will then process that element and return a value back to itself. So, for example, if an array of items is passed to O(id), it will be iterated through each, each time one element from the array in turn to the function's receiving end, until all elements have been processed.

Looked from the receiving end, it sees that it has received a single (and not an array), control flow drops to the remaining code, where that item is processed and whatever value or object is calculated. Upon return the result of the function call (back to the function) is placed in the next location in the tmp array using the JavaScript push() and is promptly forgotten (about since it has been dealt with), and the next element of the array is processed.

Once all elements are done, the value of j equals the number of items in the array, as indicated by id.length, the array tmp is returned to the calling code.

You will notice that the variables property and value are not treated as arrays, because they aren't. If the variable property has a value it will be the name of an object's property, and value will contain the value to assign to that property. These arguments are optional but can be used to give the same value to the same properties of all objects in an array. Because the function itself calls recursively, it also has to pass property and value (whether or not they have values) along with the object to be processed, otherwise if they have values they will be lost.

### How To Use It

The O() plug-in has two distinct modes. In the first it returns an object referred to as string, while in the second it updates an object's property with a new value. In either case, if the object is passed instead of ID name then the object is accessed directly, there's no need to look up.

Furthermore, in both lookup and setting methods you can pass an array of objects andor ID names. If you are looking up, the plug-in returns an array. If you are setting properties, all the objects have the specified property to the given value, and those values are returned.

However, the value returned by the plug-in is really one of using an object, such as the following, which are just four of the countless ways of using the plug-in:

```
objectname = O('mydiv');
O('copyrightspan').innerHTML = '&copy;2011';
background = O('menu').style.backgroundColor
O('menu').style.color = 'yellow';
```

As you will see throughout this book, the O() plug-in is used in a variety of ways, and you will get to thinking of it as the main way to access individual elements in a webpage.

> NOTE Well known JavaScript frameworks, such as jQuery, Script.ac, Prototype, and others, use a similar function to O($), but they usually call it $(). Add even more functionality to it than there is in the O() plug-in, which makes it even more powerful, but also complicated too. The $ is a sensible choice of character for naming such functions as it's short and instantly recognizable. However I have not used the convention because other frameworks do it. That way the plug-ins in this book should be less likely to conflict with third-party frameworks if you use both on the same pages.
