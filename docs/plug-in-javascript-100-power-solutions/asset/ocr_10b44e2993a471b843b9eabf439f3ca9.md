# Waiting Until the Web Page Has Loaded

Quite often, and particularly on longer pages, you will not want your JavaScript run until all elements in a page have loaded. One reason is that the graphics you'll be using might not be ready, or the contents of objects such as divs and spans may not be available for manipulation.

Also, some browsers will return incorrect values when a page hasn't loaded. For example, if you request the width of the browser too early you may get a value that doesn't include the vertical scroll bar, and if you try to place anything in part of the screen (thinking that it is available to you) it will be hidden by a scroll bar.

Some browsers don't even return a semi-useful value. For instance, when asked for the location of an object prior to page loading, Internet Explorer will always return the coordinates 0,0.

Therefore, you will usually need to place all your JavaScript within the body of the following function:

```
<script>
window.onload = function() {
  // Your code and all its functions goes here...\n}
</script>
```

This makes so that your code will not get executed until the very last item has loaded into the page and has fully rendered. If you get into the habit of enclosing all your code within this function, you'll ensure that all objects you access are available and avoid error messages initially unsightly web pages.

By the way, although you could move the call to Initialize() rather than in the <head> of a page, I don't recommend it. Initialize() doesn't rely on any elements of the web page since it interacts only with the browser to create global variables and attach functions to keyboard and mouse events, so you don't need to move it. Also, placing the call to Initialize() right after the command that loads the plug-ins is sensible, you can't have one without the other.

> **Tip** On busy pages, a long initial delay can be quite annoying because various elements will be simply loaded in and displayed where they lie within the HTML—only reaching their final destinations and dimensions. The first solution to this is to ensure that you use a CSS (Cascading Style Sheet) over that in Chapter 2) that is loaded at the start of the day. This will help your page layout form itself on the fly. Another trick is to set zero values to the width and height of objects that you don't want the user to see until later, using standard HTML width and height=keywords (accepted by tables, images, and other objects). Then, once your code is called after the page has fully loaded, you can give these objects their correct positions. Or you can use an element's style आयु to make it invisible, like style='display:none', and change the property to visible when you are ready to display it.
