# About the Plug-in

This plug-in fetches data from a website in the background. It returns the following arguments:

- *id* An object or object ID—this cannot be an array
- *callback* The function to pass the returned data to once it has been retrieved
- *url* The URL with which to communicate
- *args* Any arguments to pass to the URL

# How It Works

This plug-in starts as AjaxRequest(). It starts by setting the content type of the data in the request to a URL-encoded format. It returns the Ajax object with a call to CreateAjaxObject(), and if the result is not true, returns the value false as it cannot proceed without

```
var content = 'application/x-www-form-encoded'
var ajax = new CreateAjaxObject(id, callback)
if (ajax) return false
```

You call the plug-in exactly the same way as GetAjaxRequest()—it's just that the process used by the plug-in to perform the Ajax is a POST, not a GET request. Therefore, the target of the request also needs to respond to the POST request, as is the case with the following example, which fetches the details at Anchorage, Alaska airport:

function todiv() {
  var rss = this.replace(/</g, '&lt;');
  rss = rss.replace(/>/g, '&gt;');
  rss = rss.replace(/\n/g, '<br />');

This example is a little more interesting than the previous two in an RSS feed fetched. It's no different than a web page as for Ajax is concerned, but displaying after it has retrieved poses a problem, in that it contains several XML tags that won't up under HTML.

# The Plug-in

```
function PostAjaxRequest(id, callback, url, args)
{
    var contentType = 'application/x-www-form-urlencoded'
    var ajax = new XMLHttpRequest(id, callback)
    if (!ajax) return false

    ajax.open('POST', url, true)
    ajax.setRequestHeader('Content-type', contentType)
    ajax.setRequestHeader('Content-length', args.length)
    ajax.setRequestHeader('Connection', 'close')
    ajax.send(args)
    return true
}
```

# 88 FrameBust()

This is a simple but useful plug-in that checks whether it is running inside a frame and, if it is, out of it, placing the current page in its own parent page. This can be useful when you find that other sites link to your pages, but bury them inside frames that they do not display at their best. Figure 11-5 shows one page embedded within another and displaying an optional confirm dialog, offering to bust out of the frame.

# About the Plug-in

This plug-in can close any embedding frame, making a web page the parent web page for the current tab or window. It supports the following optional argument:

- *message* If this has a value, it will be displayed in a confirm dialog window offering the user the option to click OK to close the surrounding frame. If it doesn't have a value, the plug-in will automatically and silently close the embedding frame.

# How It Works

This plug-in makes the current document the top one by setting its URL to the top object's, or it displays a message (if the message has a value) that offers the user the choice of breaking out of frames or leaving them as they are.

# How To Use It

To use this plug-in, either without an argument if you never want your pages to be embedded in frames, or a message for a confirm dialog, which the response to is out of frames or leaving them as they are. Here is an example of passing a message:

```
<script>
FrameBust("This page has been loaded within a surrounding frame.\\n"
"Please click OK if you would like to close the surrounding frame.")
</script>
```

You can use \n or other escaped characters in the message. If you don't wish to provide a message and all pages to bust out of frames, just the call to FrameBust().

function FrameBust(message) {
