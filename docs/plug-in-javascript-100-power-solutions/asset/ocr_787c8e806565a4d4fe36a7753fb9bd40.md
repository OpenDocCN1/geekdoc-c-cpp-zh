This is achieved by using a pair of try() ... catch() functions. The first tries the code and passes execution to the second if there is an error.

You may wish to remove the alert (alert) in a production website so that your users won't see any errors in your code. # How To Use It

This plug-in has two distinct modes. In the first it returns an object referred to an ID string, while in the second it updates an object's property with a new value. In either case, if the object is passed to the plugin (instead of its ID name) then the object is accessed directly, there's no need to look it up.

Furthermore, in both lookup and setting methods you can pass an array of objects and/or ID names. If you are looking up, the plug-in returns an array. If you are setting properties, all the objects have the specified property to the given value, and those values are returned.

However, the value returned by the plug-in is really one of using up an object, such as the following, which are just four of the countless ways of using the plug-in.

```
objectname = 0('mydiv)
O('copyrightspan').innerHTML = '&copy;2011';
background = 0('menu').style.backgroundColor
O('menu').style.color = 'yellow'
```

When you are assigning a value to one or more properties, in the following, the returned value will simply be that of the assigned value, which is not that useful to you, except when you are debugging code:

```
O(object, 'innerHTML', '<h1>Heading Text</h1>')
(Array('first', 'second'), 'mouseover', 'mousehandler')
```

As you will see throughout this book, the O() plug-in is used in a variety of ways, and you will get to thinking of it as the main way to access individual elements in a webpage.

> NOTE Well known JavaScript frameworks, such as jQuery, Script.ac, Prototype, and others, use a similar function to O($), but they usually call it $(). Add even more functionality to it than there is in the O() plug-in, which makes it even more powerful, but also complicated too. The $ is a sensible choice of character for naming such functions as it's short and instantly recognizable. However I have not used the convention because other frameworks do it. That way the plug-ins in this book should be less likely to conflict with third-party frameworks if you use both on the same pages.
