# JavaScript and Semicolons

There are JavaScript programmers who always place a semicolon at the end of every statement, but it's not necessary to do so because JavaScript interpreters accept either a semicolon or a new line as the marker for a statement.

However, if you wish to have more than one statement in a line, you must use a semicolon between them. In this book I try to avoid this to keep the code readable as possible.

On the other hand, using semicolons everywhere makes your JavaScript code more easily convertible to languages such as PHP and C, which require them. But it's up to you whether or not you use them.

> **Tip** Some programs that work with JavaScript directly to help find bugs or reduce your code will not work unless you have placed a semicolon after every single statement. If you will use any of these you'll save a lot of time by getting into the habit of using semicolons right away.

# O()

The O() function is the most functional of the plug-ins provided in this book and is used by almost all the others. In its simplest form it replaces the long-wind JavaScript function getById which takes the string argument to it and returns the HTML DOM (Document Object Model) object that has been assigned that ID. The letter O short for Object since the main purpose of this function is to retrieve an object or modify its properties.

# About the Plug-in

This plug-in takes one required and two optional arguments:

- **id**: This can be a string containing the ID of object, an object, or even an array containing several objects/or IDs. If none of the optional arguments are provided, the function returns the object or objects represented by id.
- **property**: This optional string argument can contain the name of a property belonging to the object (or objects) in id that requires modifying.
- **value**: If this optional argument is set it represents the value to be assigned to the property of the object (or objects) in id. Both the property and value arguments must have values, otherwise O() will simply return the object (or objects) in id.

# How It Works

The plug-in does a lot more than provide a shortened name for an existing function, because you can pass it the string ID of an object, or the object itself. For example, consider the following HTML:

```html
<div id='outerdiv'> ...</div>
```

Using the O() plug-in you can access the div directly with the following command:

```javascript
mydiv = O('outerdiv')
```

This command is equivalent to the following, which sets the variable mydiv to represent the div object that has the ID 'outerdiv':

```javascript
mydiv = document.getElementById('outerdiv')
```

This means you can, for example, use the value returned by this plug-in to change the HTML contents of the div (the text between its opening and closing tags) as follows, modifying its innerHTML property:

```javascript
mydiv.innerHTML = "<h1>A Heading</h1>"
```

Or, you can assign the object to a variable and access the object directly by the O() plug-in, like this:

```javascript
O('outerdiv').innerHTML = '<h1>A Heading</h1>'
```

# Passing Strings or Objects

The O() function is also versatile in that you may have a variable containing a string name, like this:

```javascript
variable = 'outerdiv'
```

On the other hand, it can represent the actual object itself, like this:

```javascript
variable = O('outerdiv')
```

The former contains simply the string of characters comprising 'outerdiv', while the latter is an object. Because the job of O() is to return the object referred to by the string passed, if you happen to pass an object instead of a string it will simply return that object back to you. Therefore whether myvariable contains a string that refers to an object or the object itself, you can just use the statement to access it, like:

```javascript
othervariable = O(myvariable)
```

Or like this:

```javascript
O(myvariable).innerHTML = '<h2>Subheading</h2>'
```

Note that there are no quotation marks around myvariable in this instance because a variable, not a string, is being passed.

I have used single quotation marks in these examples but JavaScript allows you to use either single or double quotation marks. However, for the sake of standardization I usually use single quotes for strings, unless a string includes single quotes in which case I use double quotation marks to enclose the string.

# Additional Arguments

As well as accepting strings and objects, the O() plug-in allows you to pass an optional pair of arguments that are then used to modify object properties. For, the previous examples can be rewritten like this:

```javascript
O('outerdiv', 'innerHTML', '<h1>Heading</h1>')
O(myvariable, 'innerHTML', '<h2>Subheading</h2>')
```

Both of the preceding are acceptable alternative syntax for assigning a value to an object's property.

# Passing Arrays

You may be wondering about the point of this alternative syntax. Well, it comes into its own when you want to access many different objects at once. This is something that you cannot do with standard JavaScript, but you can achieve it with the O() plug-in, which allows you to pass an array of objects, object ID names, or a combination of both.

For example, let's say you want to clear the HTML contents of three objects that have the names 'Fred', 'Mary', and 'Bill'. Regular JavaScript would require three separate commas, but you can easily achieve the same result with the following code:

```javascript
ids = Array('Fred', 'Mary', 'Bill')
O(ids, 'innerHTML', '')
```

You can mix objects and object ID names within an array, as follows:

```javascript
ids = Array('Fred', 'Mary', 'Bill', myobject)
```

Or, you can combine everything into one line of code in the following way, which will clear out the innerHTML contents of all the objects:

```javascript
O(Array('Fred', 'Mary', 'Bill', myobject), 'innerHTML', '')
```
