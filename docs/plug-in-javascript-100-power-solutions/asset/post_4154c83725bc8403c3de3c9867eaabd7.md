## 35 Fade()

This plug-in makes great use of the previous one, Opacity(), by making it possible to smoothly change an object's opacity over time. In Figure 5-7, two images have their IDs attached to mouse events so that they fade in and out.

## About the Plug-In

This plug-in fades an object from one opacity value to another (increasing or decreasing it) over a set of milliseconds. It requires the following arguments:

- id: An object, object ID, or an array of objects and/or object IDs
- start: The beginning level of opacity
- end: The final level of opacity
- msecs: The number of milliseconds the fade should take
- interruptible: If this is set, an object's fade can be interrupted and replaced with a new fade on the same object; otherwise, the fade will continue until it has finished.
- CB: This argument is sometimes by other plug-ins when a second function is to be called once this has finished execution. Its value is a string variable containing the name of the function to call. It is not generally a user passable, I will no longer mention CB in the list of arguments, unless it is being used in a different manner.

## How It Works

This is the first of the really useful plug-ins. At most 50 lines of code it isn't short, but don't put off by it; the coding is straightforward, and you've seen many of its parts before. If you can work through this plug-in, you'll be able to follow them all.

This function works using interrupts to call a function at regular intervals to change the opacity of an object by a small amount each time (which is how all the transition and animation plug-ins in this book work). To do this, the plug-in comes in two parts. The first part prepares all the variables and initiates the interrupts, and the second part receives the interrupt calls and performs the incremental opacity changes.

Let's start with the first if() section of code. There's nothing unusual here; it simply passes back to the same function recursively to deal with an element at a time if it's an array:

```javascript
if (id instanceof Array)
{
  for (var j = 0; j < id.length; ++j)
    Fade(id[j], start, end, msecs, interruptible, CB)
  return
}
```

After that, the local variable stepval is created, like:

```javascript
var stepval = Math.abs(start - end) / (msecs / INTERVAL)
```

Its value is calculated by finding the difference between the start and end opacity values; that is, it subtracts one from the other and then passes the result through the Math.abs() function. which gives a positive integer representing the difference, like this:

```javascript
Math.abs(start - end)
```

The length of time that the fade should take, which has been passed as a value in milliseconds in the variable msecs, is divided by INTERVAL, which is the number of milliseconds between each frame of the transition (3 by default). The code for that is simple division:

```javascript
msecs / INTERVAL
```

The first value (the start and end difference) is then divided by the second (the timing) and then assigned to the variable stepval.

## A Specific Case

Let's see what value calculation comes out by assuming that start has a value of 0, end has a value of 100, and msecs has a value of 1000. This gives us the formula:

```javascript
Math.abs(0 - 100) / (1000 / 30)
```

The calculation comes to 100 / (1000 / 30), and the answer is the value 3. In terms of this code, this means that, if the following three things are true:

1. The interrupt is going to take place every 30 milliseconds,
2. You want the animation to make 1000 milliseconds,
3. There are 100 levels of opacity.

The distance between each level of opacity should be 3.

## If a Fade Is Already in Progress

This plug-in is designed so that you can force it to proceed until it has finished, or allow it to be interrupted (but only by Fade() call on the same object). This is so that you can offer mouseover and mouseout routines that will interrupt if you move your mouse.

Alternatively, you may need to display an uninterrupted animation and maybe. You have the option to choose either by setting the interruptible argument to true if a fade can be interrupted, or if it cannot. You can also use 1 and 0 for these values.

The next section of code checks whether a fade is already in progress by looking at the FA_Flag property of id. This is a new property given to id, which has the value true when fade is in progress.

> Note Assigning new properties to objects is a technique used throughout this book. It's a convenient way of using some object-oriented aspects of JavaScript.

The next section of code checks whether a fade is already in progress. If it is, the code checks whether the FA_Int property of id is set (to see whether an interrupt is allowed). If it isn't, the function immediately exits as it cannot interrupted. Otherwise, the clearInterval() function is called to end the repeating transitions, and the object's new FA_Start property is set to the current value in FA_Level.

This primes the new fade to start where the previous one (which was just cancelled) left off, which means that the new fade will ignore the start value that was passed. The following code performs this:

```javascript
if (O(id).FA_Flag)
{
  if (O(id).FA_Int) return

  clearInterval(O(id).FA_IID)
  O(id).FA_Start = O(id).FA_Level
}
```

## If a Fade Is Not in Progress

If a fade isn't already in progress, the new id property FA_Start is assigned the value in start so that the remaining code can use this to know where the fade started from.
