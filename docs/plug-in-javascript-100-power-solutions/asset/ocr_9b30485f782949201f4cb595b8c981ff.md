# 16 Plug-In JavaScript: 100 Solutions

Remembering these two sections of HTML are part of the same document, bringing them together inside an <html> tag, like this:

```
<html>
<head>
  <meta name="robots" content="index, follow" />
  <title>Hello</title>
</head>
<body>
  <a href="http://google.com">Visit Google</a>
  <form id="login" method="post" action="program.php">
    <input id="name" type="text" name="username" value="fred" />
    <input type="submit" />
  </form>
  <img src="photos/vacations/cancun/photoll.jpg" />
</body>
</html>
```

Of course, a page can look quite different from this, but it should follow the same form. Even though browsers are very forgiving and allow you to omit many things, with the opening and closing tags, I do not recommend you to do this, because one day you might want to convert your page to XHTML, which is a lot stricter. It's always a good idea to close every tag and make sure you do so in the right order. For example, you shouldn't close a document by issuing <html> followed by </body> the proper nesting of tags would be broken.

For the same reason, you should also get into the habit of closing tags that have no closing tag, such as <img src="*" />, which does not have a matching <img> tag, and therefore requires a / character right before the final > in order to properly close it. In the same way <br> becomes <br />, and so on.

You should also remember that again tags must have single or double quotation marks to be XHTML compatible, though nearly all browsers allow you to omit them.

> Note In the early days of the Web, when most users used very slow dial-up modems, it was to see all manner of things such as quotation marks and various tags omitted from web pages. Nowadays, most of your users will have fairly decent bandwidth speeds, and there's no longer any reason to do this.

# Accessing the DOM from JavaScript

You may have wondered why I give the ID of "login," and the first input tag of "name" (and the value "fred"). The reason is to show how JavaScript handles all of this DOM nesting quite easily with the use of the period character. For example, standard properties such the document title can be read like this:

```
title = document.title
```
