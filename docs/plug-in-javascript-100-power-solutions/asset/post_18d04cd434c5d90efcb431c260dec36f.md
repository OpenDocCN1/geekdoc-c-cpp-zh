# Plug-In JavaScript: 100 Solutions

## Variables, Arrays, and Functions

| Variable | Description |
| :--- | :--- |
| e | The event passed to the function by browsers other than Internet Explorer. Either e.charCode or e.keyCode contains the value of the key pressed. |
| window.event | Internet Explorer uses the window.event property instead of an event passed as an argument. The keyCode contains the value of the key pressed. |
| BROWSER | Global variable used to determine the browser. |
| KEY_PRESS | Global variable to be assigned the value of the keypress. |
| fromCharCode() | JavaScript function to convert Unicode to characters. |
| FromKeyCode() | Plugin to return the value of a keypress or if it is one of many special characters such as 'Esc', 'Home', and so on. |

## How It Works

This function works differently on whether you are using Internet Explorer or not. If you are, it looks up the key in window.event.keyCode and passes it through the FromCharCode(), which will assign a sign if the key was a special key such as 'Up', 'Backspace', and so on. Then, if the value is a simple number (that is, it hasn't been substituted for a special key), the JavaScript fromCharCode() function converts it from its Unicode to an actual value, so if, for example, the key is pressed, then the value 'e' is returned.

On Non-Internet browsers, both e.charCode and e.keyCode are checked for a value because the events document.onkeydown and document.onkeypress are captured by this function. One function captures regular keys, while the other handles the special keys already referred to, combining both into the same function makes sense. So, if e.charCode has a value, it is passed through the JavaScript fromCharCode() function to convert it to its Unicode. Or, if a special key was pressed, so value is passed through the FromKeyCode() plug-in to look up the key name.

In either case, the result is that KEY_PRESS will contain a letter, punctuation, symbol, the name of a special key, or simply a number if it is one of the others. There is no keyboard buffering to, for example, create strings of input, as only the last key pressed is saved. However, it is quite possible to create an input function using this if you need one.

Finally, a value of true is returned to allow further processing of the function by the browser.

## How To Use It

Using this plug is as simple as referencing the global variable, KEY_PRESS, that it maintains. The following is a simple example that continuously updates the contents of a div with the value of the key pressed:

```javascript
<div id='output'></div>

<script>
window.onload = function() {
  setInterval(simpleInterrupt, INTERVAL)
}

function simpleInterrupt() {
  document.getElementById('output').innerHTML = ' You pressed: ' + KEY_PRESS
}
</script>
```

Again (and I won't mention this anymore), this assumes you have already included the lines to load in Pljs and Initialize() function.
The interrupt is set up so that the value of the last keypress can be continuously displayed. If you prefer, you can use a command such as the following in the loop instead:

```javascript
alert('You pressed: ' + KEY_PRESS)
```

However, it is intrusive, and you have to click the OK button to close the alert each time it is called. What's more, it locks the browser because the alert () prevents you from doing anything else (even closing the browser) until you have clicked OK, and even then the alert will pop up again, and again, forever.

> **Tip** Because of the problem of alert potentially taking over a browser if placed within a loop, this book includes an alternate function called Alert (with an upper case A) which you may prefer to use. It does not lock the browser and has other benefits too. For further details, please refer to Chapter 13.

## The Plug-in

```javascript
function CaptureKeyboard(e) {
  if (BROWSER == 'IE') {
    KEY_PRESS = FromCode(window.event.keyCode)
  }
  if (KEY_PRESS > 0)
    KEY_PRESS = String.fromCharCode(KEY_PRESS)
  } else {
    if (e.charCode) KEY_PRESS = String.fromCharCode(e.charCode)
    else if (e.keyCode) KEY_PRESS = FromCode(e.keyCode)
  }

  return true;
}
```

## Computer Mode: Off

### About the Plug-in

This plug-in can take a key as an argument and return a string representing the special key that was pressed, or the code if no key was pressed.

## Variables, Arrays, and Functions

| Variable | Description |
| :--- | :--- |
| c | Key code passed to the function and returned if it represents a special key |

## How It Works

This function uses a switch() statement to test the value of c and return various strings if it matches. If none of the values match, then c is returned.

## To Use It

Generally this plug-in will be called for you by CaptureKeyboard() plug-in. However, you may have an application for which you'd rather return the strings, or different names. In these cases, feel free to modify the plug-in to your requirements.

For example, if you don't want the keys created by pressing the SHIFT key, you might prefer to return an empty string instead of 'SHIFT'. That way, when the user presses the SHIFT key followed by the M key, for example, you will only see the value 'M' and not 'M'. The reason I bother trapping these special keys is, although there are already useful input features built into JavaScript, these plug-ins allow you to, for example, set up special keys to move objects around the screen or perform particular functions the moment a key is pressed.

Here’s a combined HTML and JavaScript example to return the translations for codes 1 through 144:

```javascript
<div id='output'></div>

<script>
window.onload = function() {
  for (j = 1; j < 145; ++j) {
    document.getElementById('output').innerHTML += FromKeyCode(j) + ', ';
  }
}
</script>
```

An interesting point to note is here the use of the += operator for keeping the contents of the innerHTML property of the 'output' div.

## GetLastKey()

This-plugin returns the value of whatever the last keypress was and resets the stored value to the empty string to indicate that the key value has been retrieved. Figure 3-7 shows how a simple input function created using this-plugin.

## About the Plug-in

This-plugin doesn't take any arguments and returns the value of the most recently pressed key (if any).

## Variables, Arrays, and Functions

| Variable | Description |
| :--- | :--- |
| k | Local string variable that holds the value of KEY_PRESS before resetting it k |

## How It Works

This-plugin assigns the value in KEY_PRESS, the global variable that contains the last key pressed, to the local variable k. Then it resets KEY_PRESS to the empty string to show that the value has been read. Finally, the contents of k is returned. If there was no keypress, the empty string is returned.

## How Use It

To use this-plugin, call with no arguments and will return either a letter, number, punctuation symbol, or a special key. If the key was none of these, its code is returned.

You can use this to create a simple input function, like this:
