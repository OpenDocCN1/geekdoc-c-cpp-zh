+   - MOUSE_IN In a similar fashion, the document.onmouseout and document .onmouseover events are captured, and this global variable is set to true when the mouse pointer is within the bounds of the browser window; otherwise it is set to false.

+   - MOUSE_X and MOUSE_Y This pair of global variables is constantly updated by the CaptureMouse() plug-in (the plugin following this one), which is attached to the document.onmousemove event. Therefore, you can reference these variables at any time to determine the position of the mouse pointer.

+   - SCROLL_X and SCROLL_Y These variables are also kept updated by the CaptureMouse() plug-in. They are continuously updated with values representing the amount by which the mouse has scrolled in both vertical and horizontal directions.

+   - KEY_PRESS This variable is updated by the Keyboard() plug-in, which captures the document.onkeydown and document.onkeypress events and sets the variable on the key that was pressed.

+   - ZINDEX This global variable starts with a default value of 1,000. It is used to determine the zindex property of objects used. This is the depth at which it will be displayed on the screen, with lower or negative numbers being higher and positive numbers. For example, the ContextMenu() plug-in in Chapter 8, which opens a drop-down element when you right-click, uses this value to ensure that the element appears in front of all other windows. The Browser() plug-in (also in Chapter 8), which creates in-browser, movable pop-up windows, sets windows that are linked to ZINDEX + 1, to ensure they come to the front.

+   - CHAIN_CALLS Some of the plug-ins have the ability to be chained together so that they run consecutively, one starting after the previous has finished. Normally, JavaScript does not allow such behavior, and if you call a function that, for example, sets up an interval to perform an animation, that function will return immediately to the calling code without waiting for the sequence of interrupts to complete. This is exactly normal behavior, as it allows other things to happen at the same time. But some of these plug-ins work better when they are chained, which is achieved by placing a sequence of functions in the CHAIN_CALLS array so that each function completes, the next in the chain can be called. The only reasons you might want to access this array is to determine (and how many) functions are queued up, or possibly to empty the interval to cancel all queued functions.
