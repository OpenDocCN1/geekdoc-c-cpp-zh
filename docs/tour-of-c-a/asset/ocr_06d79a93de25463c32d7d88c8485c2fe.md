+   - unique_ptr represents unique ownership (its destructor destroys its object)

The most basic use of "smart pointers" is to prevent memory leaks by careful programming.
For example:

Click here to view code image

```
void f(int i, int j)    // X* vs. unique_ptr<X>
{
    X* p = new X;               // Allocate a new X
    unique_ptr<X> sp(new X);   // Allocate a new X and gives its pointer to unique_ptr
    // ...
    if (i<99) {                // may throw an exception
        if (j<77) return;         // may return "early"
        // ... use p and sp.
    }
    delete p;
}
```

Here, "forgot" to delete p if i<99 or if j<77. On the other hand, unique_ptr ensures that object is properly destroyed whichever we exit it (by executing an exception, return, or by falling off the end). We could have solved the problem by not using a pointer and not using new:

Click here to view code image

```
void f(int i, int j)    // use a local variable
{
    X;
    // ...
}
```

Unfortunately, overuse of new (and of pointers and references) seems to be an increasing problem.

However, when you really need the semantics of pointers, unique_ptr is a lightweight mechanism with no space or time overhead compared to use of a built-in pointer. Its further uses include passing free-allocated objects out of functions:

Click here to view code image

```
unique_ptr<X> make_X(int i)
    // make an X and immediately gives it to a unique_ptr
{
    // ... check i, etc.,
    return unique_ptr<X>(new X(i));
}
```

A unique_ptr is a handle to an individual object (or an array) in much the same way that a vector has a handle to a sequence of objects. Both control the lifetime of other objects (using RAII) and both rely on elimination of copying or on semantics to make return simple and efficient (§6.2.2).

The shared_ptr is similar to unique_ptr except that shared_ptrs are copied rather than moved.
