```
export module std;
export import std.regex; // <regex>
export import std.filesystem; // <filesystem>
export import std.memory; // <memory>
export import std.threading; // <atomic>, <condition_variable>, <future>, <mutex>,
// <shared_mutex>, <thread>
```

```
export module std;
export import std.regex; // <regex>
export import std.filesystem; // <filesystem>
export import std.memory; // <memory>
export import std.threading; // <atomic>, <condition_variable>, <future>, <mutex>,
// <shared_mutex>, <thread>
export import std.core;
// all the rest
```

For this to work we will have to use a C++20 compiler, and also set options to gain access to the experimental modules. Beware that everything "experimental" will change over time.

# A.3 Use Headers

If an implementation doesn't support modules or doesn't have an export module std or equivalent, we can fall back to using traditional headers. They are standard and universally available. The snag is that to get an example to work, we need to figure out which headers are needed and #include them. Chapter 9 can help here, and we can look up the name of a feature we want to use in [Cpprefence] to see which header it is part of. If that gets tedious, we can gather frequently used headers in a std.h header:

```
// std.h
```

```
#include <iostream>
#include <string>
#include <vector>
#include <list>
#include <memory>
#include <algorithm>
// ...
```

and then

```
#include "std.h"
```

The problem is here that #including so much can can give very slow compiles [Stroustrup,2021b].
