Like all standard-library algorithms, for_each() calls its argument using the traditional function syntax f(x), Shape's draw() uses the conventional object-oriented notation x->f(i). A lambda easily mediates between the two notations.

# 16.3.2 mem_fn()

Given a member function, the adaptor mem_fn(mf) produces a function object that can be called as a nameless function. For example

Click here to view code image

```
void draw_all(vector<Shape>& v)
{
    for_each(v.begin(),v.end(),mem_fn(&Shape::draw));
}
```

Before the introduction of lambdas in C++11, mem_fn() and equivalents were the main way to map from the object-oriented style to the functional one.

# 16.3.3 function

The standard-library function is a type that can hold any object you can invoke using the call operator (()). That is, any object of type function is a function object (7.3.2). For example:

Click here to view code image

```
int f1(double);
function<int(double)> fct1(f1);

int f2(string);
function fct2(f2);

function fct3 = [[Shape* p] { p->draw(); };
```

For fct2, I let the function be deduced from the initializer: int(string). Obviously, functions are useful for callbacks, passing arguments as arguments, function objects, however, introduce some run-time overhead compared to direct calls. In particular, for a function object where the size is not computed at compile-time, a free-store allocation might occur which badly impacts performance-critical applications. A solution is coming for C++23: move_only_function.

Another problem is being an object, does not participate in overloading. If you need to overload function objects (including lambdas), consider overloaded (15.4.1).

# 16.4 Type Functions

A type function is a function that is evaluated at compile time given a type as its argument or returning a type. The standard library provides a variety of type functions to help library implementers (and programmers in general) write code that takes advantage of aspects of the language, the standard library, and code in general.
