There was a C++03, which I didn't list because it was a bug-fix release. Similarly, C17 is not listed as it is a bug-fix release to C11.
Differences between C and C++ are not necessarily the result of changes to C made in C++. In several cases, the incompatibilities arise from features adopted improperly into C long after they were common in C. Examples are the assign a T' to a void and the linkage of consts [Stroustrup,2002]. Sometimes, a feature was implicitly adopted after C if it was part of the C++ standard, as with details of the meaning of inline.

# 19.3.2 Compatibility Problems

There are many incompatibilities between C and C++. All can cause problems for a programmer in the context of C++, all can be coped with. If nothing else, C fragments can be compiled as C and linked using the extern "C" mechanism.
The problems for converting a C program to C++ are likely to be:

+   - Suboptimal design and programming style.
- A void implicitly converted to a T' (that is, converted without a cast).
- C++, keywords, such as class and private, used as identifiers in C.
- Incompatible linkage of code fragments compiled as C and fragments compiled as C++.

# 19.3.2.1 Style Problems

Naturally, a C program is written in a C style, such as the style used in K&R [Kernigh,1988]. This implies widespread use of pointers and arrays, and probably many macros. These facilities are hard to rely in a large program. Resource management and error handling are often ad hoc (rather tool and supported) and often undocumented and adhered to. A simple line-for-line conversion of a C program into C++ program yields a program that is often a bit better checked. In fact, I have never converted a C program into C++ without finding some bugs. However, the fundamental structure is unchanged, so are the sources of errors. If you had included error handling, resource leaks, or overflows in the original C program, then there would be in the C++ version. To obtain many benefits, you must make changes to the fundamental structure of the code:

+   [1] Don't use C with C with a few features added. C++ can be used that way, but only suboptimally. To get really many advantages from C++ compared to C, you need to apply different implementation and designs.

+   [2] Use the C standard library as a teacher of new techniques and programming styles. Note the difference from the C standard library, e., = rather than strcp(for).

+   [3] Macro substitution is almost never necessary in C++.
