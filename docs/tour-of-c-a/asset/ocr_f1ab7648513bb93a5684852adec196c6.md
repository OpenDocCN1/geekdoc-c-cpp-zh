# 19.5 Advice

+   [1] The ISO C++ standard [C++,2020] defines C++.
[2] When choosing a strategy for a new project or modernizing a code base, rely on the C++ Guidelines; §19.1.4.
[3] When learning C++, don't focus on language features in isolation; §19.2.1.
[4] Don't get stuck with decades-old language-feature sets and design techniques; §19.1.4.
[5] Before using a new feature in production C++, try it by writing small programs to test the standards conformance and performance of the implementations you plan to use.
[6] For learning C++, use the most-to-date and complete implementation of C++ that you get access to.
[7] The common subset of C and C++ is not the best initial subset of C++ to learn; §19.3.2.1.
[8] Avoid cases; §19.3.2.1; [CG: ES.48].
[9] Prefer named casts, as static over C-style classes; §5.2.3; [CG: ES.49].
[10] When converting a program to C++, rename variables that are C keywords; §19.3.2.
[11] For portability and safety, if you use C, use the common subset of C and C++; §19.3.2.1; [CG: PPL.2].
[12] When converting a program to C++, catch the result of malloc() to the proper type or change all uses of malloc() to uses of new; §19.3.2.2.
[13] When converting from malloc to free and delete, consider using vector, push_back(), and reserve() instead of realloc(); §19.3.2.1.
[14] In C++, there are no implicit conversions from int to enumerations; use explicit type conversion when necessary.
