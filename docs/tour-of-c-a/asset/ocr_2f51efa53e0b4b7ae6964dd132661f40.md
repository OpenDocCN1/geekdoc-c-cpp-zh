The standard library offers several sub-namespaces to std that can be accessed only through an explicit action:

+   - std::chrono: all facilities from chrono, including std::literals::chrono_literals ($16.2)
- std::literals::chrono_literals: suffixes y for years, d for days, h for minutes, ms for milliseconds, ns for nanoseconds, s for seconds, and us for microseconds ($16.2)
- std::complex_complex: suffixes i for imaginary numbers, if for imaginary floats, and il for imaginary long doubles ($6.6).
- std::literals::string_literals: suffixes s for strings ($6.6, $10.2).
- std::literals::string_view_literals: suffixes sv for string views ($10.3).
- std::numbers: for mathematical constants ($17.9).
- std::pmr: for polymorphic resources ($12.7).

To use a sub-namespace, we have to introduce it into the namespace in which we want to use it. For example:

Click here to view code image

```
using namespace literals::complex_literals;
auto z1 = 2+3i; // error: no suffix

using namespace literals::complex_literals; // will make the complex literals
auto z2 = 2+3i; // error: no suffix <double>
```

There is no coherent policy for what should be in a sub-namespace. However, suffixes cannot be explicitly qualified so we can bring in a single set of suffixes into a scope risking ambiguities. Therefore suffixes for a library meant to work with other libraries (that might define their own suffixes) are placed in sub-namespaces.

#  9.3.2 ranges namespace

The standard library offers algorithms, such as sort() and copy(), in two versions:

+   - A sequence version taking a pair of iterators; e.g., sort(begin(v),v.end())
- A range version taking a single range; e.g., sort(v)

Ideally, these two versions overload perfectly without any special effort. However, they don't. For example:

Click here to view code image

```
using namespace std;
using namespace ranges;

void f(vector<int>&v) {
  sort(v.begin(),v.end()); // error:ambiguous
  sort(v); // error:ambiguous
}
```
