This is a notionally simpler alternative to overloading:

Using default arguments means that there is only one definition of the function. That’s usually
for comprehension and code size. When we need different code to implement the same
semantics for different types, we can use overloading.

#  3.4.2 Value Return

Once we have computed a result, we need to get it out of the function and back to the caller.
Again, the default for return is to copy and for all objects that's ideal. We return “by
"reference” only when we want to grant a caller access to something that is not local to the
function. For example, a Vector can grant a user access to an element by subscribing:

Click here to view code image

```
class Vector {
public:
    ...
    double&operator[](int i) { return elem[i]; }   Il return reference to ith element
private:
    double* elem;                               Elem points to an array of sz
    ...
};
```

The ith element of a Vector exists independently of the call of the subscript operator, so we can
return a reference to it.

On the other hand, a local variable disappears when the function returns, so we should not
return pointer or reference to it:

```
int& bad()
{
    int x;
    ...
    return x; // Il bad: return a reference to the local variable x
}
```

Fortunately, all major C++ compilers will catch the obvious error in bad().
