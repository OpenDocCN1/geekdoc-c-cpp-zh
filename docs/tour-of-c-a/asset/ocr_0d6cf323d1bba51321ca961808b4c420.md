A stringstream can be used for both reading and writing. For example, we can define an operation that can convert any type with a string into another representation that can also be represented as a string:

Click here to view code image

```
template<typename Target=string, typename Source=string>
Target(Source arg) // Convert Source to Target
{
    stringstream buf;
    Target result;

    if (!(buf << arg) // write arg into stream
        || !(buf >> result) // read result from stream
        || (!(buf == std::eof())) // If there is anything left in stream?
            throw runtime_error("to<T>() failed");

    return result;
}
```

A template argument needs be mentioned only if it cannot be deduced or if there is no default (§8.2.4), we can write:

Click here to view code image

```
auto x1 = to<string,double>(1.2); // Il very explicit (and verbose)
auto x2 = to<string>(1.2); // Il Source is deduced to double
auto x3 = to<int>(1.2); // Il Target is defaulted to string; Source is deduced to double
auto x4 = to(1.2); // Il < is redundant;
Il Target is defaulted to string; Source is deduced to double
```

If all function arguments are deduced, the < can be left out.
I consider this a good example of the generality and ease of use that can be achieved by a combination of language features and standard-library facilities.

# 11.7.4 Memory Streams

From the earliest days of C++, there have been streams attached to sections of memory designated by the user, so that we can read/write directly from/to them. The oldest such streams, stringstream, have been deprecated for decades; their replacement, stringstream, istringstream, and ostream, did not become official until C++23.
