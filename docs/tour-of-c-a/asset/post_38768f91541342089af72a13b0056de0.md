
## 10.4.2 Regular Expression Notation

The regex library can recognize several variants of the notation for regular expressions. Here, I use the default notation, a variant of the ECMA standard used for ECMAScript (more commonly as JavaScript). The syntax of regular expressions is based on special characters:

| Regular Expression Special Characters | |
|---|---|
| \. Any single character (a "wildcard") | Next character has a special meaning |
| [^ Begin class | Zero or more (suffix operation) |
| ] End character class | One or more (suffix operation) |
| {n,} Begin count | Optional (zero or one) (suffix operation) |
| {n,} End count | Start of line; negation |
| ( ) Begin grouping | End of line |

For example, we can specify a line starting with zero or more As followed by one or more Bs followed by an optional C like this:

```
^A*B+C?$
```

Examples that match:

```
AAAAAAAAAAAAABBBBBBC
BC
B
```

Examples that do not match:

Click here to view code image

| AAAA // no B |
| AAABC // initial space |
| AABBCC // too many Cs |

A part of a pattern is considered a subpattern (which can be extracted separately from a smatch) if it is enclosed in parentheses. For example:

Click here to view code image

```
\d+|d+ // no subpatterns
\d+(-|d+) // one subpattern
(\d+)(|d+) // two subpatterns
```

A pattern can be optional or repeated (the default is exactly once) by adding a suffix:

| Repetition | |
|---|---|
| {n} | Exactly n times |
| {n,} | n or more times |
| At least n and most m times |
| Zero or more, that is, {0} |
| One or more, that is, {1} |
| Optional (zero or one), that is (0,1) |

For example:

```
A(3)B(2,4)C*
```

Examples that match:

- AAABC
- AAABBB

Examples that do not match:

Click here to view image

- AAABC // It too few As
- AAABC // It too few Bs
- AAABBBCCCC // It too many Bs

A suffix after any repetition of the notations (?, *, +, and {}) makes the pattern matcher "lazy" or "non-greedy". When that, looking for a pattern, it will look for the shortest match rather the longest. By default, the pattern matcher always looks for the longest match; this is known as max match. Consider:

```
abab
```

The pattern (ab)+ matches all of ab. However, (ab)* matches only the first. The most common character classifications have names:

| Character Classes | |
|---|---|
| alnum | Any alphanumeric character |
| alpha | Any alphabetic character |
| blank | Any whitespace character |
| cntrl | Any control character |
| digit | Any decimal digit |
| graph | Any graphical character |
| lower | Any lowercase character |
| print | Any printable character |
| punct | Any punctuation character |
| s | Any whitespace character |
| space | Any whitespace character |
| upper | Any uppercase character |
| w | Any word character (alphanumeric characters plus underscore) |

In a regular expression, a character class must be bracketed by []. For example, [digit] matches a decimal digit. Furthermore, several character classes are supported by shorthand notation:

| | Common Character Class | Abbreviations |
|---|---|---|
| d | A lowercase character | [lower] |
| u | An uppercase character | [upper] |
| l | Not u | [lower] |
| U | Not u | [upper] |

For full portability, use character class names rather than abbreviations. As example, consider writing a pattern that defines identifiers: an underscore or a letter followed by a sequence of letters, or underscores. To illustrate the subtleties involved, include a false attempt:

Click here to view code image

```
[alpha]* // wrong: characters from the set "alpha"
[alnum]* // wrong: underscore is not alpha
[alpha]* // OK, but clumsy
[alnum]* // OK: include the underscore in character classes
[alnum]w* // w is equivalent to [alnum]
```

Finally, there is a function that uses the simplest version of regex_match() (10.4.1) to test whether a string is an identifier:

Click here to view code image

```cpp
bool is_identifier(const string& s)
{
    regexp pat("[alpha]\w*"); // underscore or letter
    // followed by zero or more underscores, letters
    return regex_match(s,pat);
}
```

Note the doubling of the backslash to include a backslash in an ordinary string. Use raw string literals to avoid problems with special characters.

Click here to view code image

```cpp
bool is_identifier(const string& s)
{
    regexp pat(R"([alpha]:\w*)");
    return regex_match(s,pat);
}
```

Click here to view code image

- Ax* - A, Ax, Axxx
- Ax+ - Ax, Axx Not A
- id-d? - 2-12
- w(d2)?id(4.5) - bs-245, xx-54321, 22-5432 Digits are in w

- [bS] - bs, BS Not bs
- [aeiou] - a, o, u An English vowel, not x
- [aeiou] - y, k Not an English vowel, not e
- [aeiou]* - a, o English vowel or

A group (subpattern) can potentially be represented by a submatch delimited by parentheses. If you need parentheses that should not define a subpattern, use (?: rather than plain (. For example:

Click here to view code image

- (is,)?(id*) Optional spaces, colons, and/ commas followed by an optional number

Assuming we were not interested in the characters before the number (presumably separators), we could write:

Click here to view code image

- (?:[:;],*)(id*) Optional spaces, colons, and/ commas followed by an optional number

This would save regular expression engine having to store the first characters: the (?: variant has only one subpattern.

| Regular Expression Grouping Examples | |
|---|---|
| id"\w\* | No groups (subpatterns) |
| (id)(is\w\+) | Two groups |
| (id)(is\w\+)+ | Two groups (groups do not nest) |
| (is"\w\+)* | One group; one or more subpatterns; only the last subpattern is saved as a submatch |

Three groups; the \1 means "same as group 1"

## 10.4.3 Iterators

In addition, languages supporting regular expressions often provide:

```cpp
void count_words() {
    std::string text = "The quick brown fox jumps over the lazy dog";
    std::regex re(R"((\w+))"); 
    std::sregex_iterator it(text.begin(), text.end(), re);
    std::sregex_iterator end;
    for (; it != end; ++it) {
        std::cout << (*it)[0] << "\n";
    }
}
```

We can use `std::sregex_iterator` to find all occurrences of a pattern in a string.

```cpp
std::string text = "The quick brown fox jumps over the lazy dog";
std::regex re(R"((\w+))");
auto it = std::sregex_iterator(text.begin(), text.end(), re);
for (; it != std::sregex_iterator(); ++it) {
    std::cout << (*it)[1] << " ";
}
```

Similarly, we can use `std::creregex_iterator` for C-style strings (character arrays).

```cpp
const char* text = "The quick brown fox jumps over the lazy dog";
std::regex re(R"((\w+))");
std::creregex_iterator it(text, text + strlen(text), re);
for (; it != std::creregex_iterator(); ++it) {
    std::cout << (*it)[1] << " ";
}
```

Finally, there is also `std::wcreregex_iterator` for wide-character strings.

```cpp
std::wstring text = L"The quick brown fox jumps over the lazy dog";
std::regex re(L"((\w+))");
std::wcreregex_iterator it(text.begin(), text.end(), re);
for (; it != std::wcreregex_iterator(); ++it) {
    std::wcout << (*it)[1] << L" ";
}
```

[5] string can grow and shrink
[6] Use at() rather than [] when you want range checking.
[7] Use iterators rather than at() when you want to optimize speed.
[8] Use range-for to minimize range checking.
[9] Use c_str() or data() to produce a C-style representation of a string.
[10] Use stringstream for numeric conversion.
