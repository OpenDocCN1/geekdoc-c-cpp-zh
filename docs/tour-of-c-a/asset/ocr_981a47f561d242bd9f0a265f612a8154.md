+   Logical operators: && ||

+   Unary arithmetic and logical operators: +, -, (bitwise complement) and ! (logical negation)

+   Assignments: =, +=, *=, etc.

+   Increments and decrements: ++ --

+   Pointer operations: ->, unary *, and unary &

+   Shift: >> and <<

Unfortunately, we cannot define operator () to get smart references.
An operator can be defined as a member function:

Click here to view image

```
class Matrix {
// ...
Matrix&operator=(const Matrix& m); // Assign m to *this: return a reference to *this
};
```

This is conventionally done for operators that modify their first operand and is for historical reasons to avoid +=, ->, and .
Alternatively, most operators can be defined as free-standing functions:

Click here to view image

```
Matrix&operator+(const Matrix& m1, const Matrix& m2); // Assign m1 to m2 and return the sum
```

It is conventional to define operators with symmetric assignments as free-standing functions so that both operands are treated identically. To gain good performance from returning a potentially large object, such as a Matrix, we rely on move semantics (§6.2.2).

# 6.5 Conventional Operations

Some operations have conventional meanings defined for a type. These conventional are often assumed by programmers and libraries (notably, the standard library), so it is wise to conform to when designing new types for which the operations makes sense:

+   - Compisons: ==, !=, <, <=, >= <> (§6.5.1)

+   - Container operations: size(), begin(), and end() (§6.5.2)

+   - Iterators and 'smart pointers': ->, *, [], ++, --, +, += = (§13.3, §15.2.1)

+   - Function objects: () (§7.3.2)

+   - Input and output operations: >> and << (§6.5.4)

+   - swap() (§6.5.5)

+   - Hash functions: hash() (§6.5.6)
