[1] Use std::string to own character sequences; §10.2; [CG: SL.str.1].

[2] Prefer string operations over C-style string functions; §10.1.

[3] Use string to declare variables and members not as a class; §10.2.

[4] Return strings by value (rely on move semantics and copy elision); §10.2, §10.2.1; [CG: F.15].

[5] Directly or indirectly, use substr() to read strings and replace() to write strings; §10.2.

[6] A string can grow and shrink, and §10.2.

[7] Use at() rather than at[] or [i] when you want range checking; §10.2, §10.3.

[8] Use iterators rather than at() when you want to optimize speed; §10.2, §10.3.

[9] Use a range-for to minimize range checking; §10.2, §10.3.

[10] string input doesn't overflow; §10.2, §11.3.

[11] Use c_str() or data() to produce a C-style representation of a string (only) when you have to; §10.2.

[12] Use a stringstream or a generic value function (such as to++) for numeric conversion of strings; §11.7.

[13] A basic string can be used to make strings of any type; §10.2.1.

[14] Use the s suffix for string literals meant to be standard-library strings; §10.3 [CG: SL.str.2]

[15] Use string_view as an argument of functions that needs to read character sequences stored in various ways; §10.3 [CG: SL.str.2].

[16] Use span_char as an argument of functions that needs to read character sequences stored in various ways; §10.3; [CG: SL.str.2] [CG: SL.11].

[17] Think of a string_view as a kind of pointer with a size attached; it does not own its characters; §10.3.

[18] Use the sv for string literals meant to be standard-library string_views; §10.3.

[19] Use regex for most conventional uses of regular expressions; §10.4.

[20] Prefer regex_match() to make a complete input; §10.4, §10.4.2.

[21] Use regex_search() to search for a pattern in an input stream; §10.4.1.

[22] The regular expression notation can be adjusted to match various standards; §10.4.2.

[23] The default regular expression notation is that of ECMAScript; §10.4.2.

[24] Be constrained; regular expressions can easily become a write-only language; §10.4.2.

[25] Note that for a digit d allows you to express a subpattern in terms of a previous subpattern; §10.4.2.

[26] Use ? to make patterns "lazy"; §10.4.2.

[27] Use regex_iterators for iterating over a stream looking for a pattern; §10.4.3.
