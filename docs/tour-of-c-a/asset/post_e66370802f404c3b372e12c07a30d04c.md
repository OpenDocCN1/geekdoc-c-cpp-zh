
```cpp
return res;
}
```

This is obviously one of many ways to compute the sum of a sequence of numbers.
Consider what makes this code less general than it needs to be:

- Why just ints?
- Why just vectors?
- Why accumulate in a double?
- Why start at 0?
- Why add?

Answering the first question by making the concrete types into template arguments, we have the simplest form of the standard-library accumulate algorithm:

Click here to view code image

```cpp
template<forward_iterator Iter, Arithmetic<iter_value<Iter>> Val>
Val accumulate(Iter first, Iter last, Val res)
{
  for (auto p = first; p!=last; ++p)
    res += p;
  return res;
}
```

Here, we have:

- The data structure to be traversed has been abstracted into a pair of iterators representing a sequence (§8.2.4, §13.1).
- The type of the accumulator has been made into a parameter.
- The type of the accumulator must work with the iterator's value type (the element type of sequence).
- The initial value is an input; the type of the accumulator is the type of this initial value.

A quick examination — even better — measurement will show that the code generated for calls with a variety of data structures is identical to what you get from hand-coded examples.
Consider:

Click here to view code image

```cpp
void use(const vector<int>& vec, const list<double>& lst)
{
  auto sum = accumulate(begin(vec),end(vec),0.0); // accumulate in double
  auto sum2 = accumulate(begin(lst),end(lst),sum);
  // ...
}
```

The process of generalizing from a concrete piece of code (and preferably from several) while preserving performance is called lifting. Conversely, the best way to develop a template is often to:

- first, write a concrete version
- then, debug, test, and measure
- finally, replace the concrete types with template arguments.

Naturally, the repetition of begin() and end() is tedious, so we can simplify the user interface a bit:
Click to view code image

```cpp
template<forward_range R, Arithmetic<value_type_t<R>>> Val
accumulate(const R& r, Val res = 0)
{
    for (auto x : r) {
        res += x;
    }
    return res;
}
```

A range is a standard-library concept representing a sequence with begin() and end() (§13.1). For full generality, we can enhance the += operation also; see §17.3.
Both the pair-of-iterators and the range version of accumulate are useful: the pair-of-iterators for generality, the range version for common uses.

## 8.4 Variadic Templates

A template can be defined to accept any number of arguments of arbitrary types. Such a template is called a variadic template. Consider a simple function to write out values of any type that has a << operator:

Click here to view code image

```cpp
void user() {
    print("first": 1, 2, 2, "hello"s); // first: 1 2 2 hello
    print("insecond": 0, '0.2', 'c', "yuck"s, 0, 1, 2, "in"); // Second: 0.2 c yuck! 0 1 2
}
```

Traditionally, implementing a variadic template has to separate the first argument from the rest and recursively call the variadic template for the tail of the arguments:

Click here to view code image

```cpp
template<typename T>
concept Printable = requires(T t) { std::cout << t; } // Just one operation!

void print() {
    // Ill what we do for no arguments: nothing
}

template<Printable T, Printable... Tail>
void print(T head, Tail... tail) {
    cout << head << ' <<'; // first, what we do for the head
    print(tail...); // then, what we do for the tail
}
```

The Printable... indicates that Tail is a sequence of types. The Tail... indicates that tail is a sequence of values of types in Tail. A parameter declared with a ... is called a parameter pack. Here, tail is a (function argument) parameter pack where the elements are of the types found in the (template) parameter pack Tail. So, print(t) can take any number of arguments of types.

A call to print(t) expands the arguments into a head (the first) and a tail (the rest). The head is printed and then print() is called for the tail. Eventually, tail will become empty, so we need the no-argument version of print() to deal with it. If we don't want to allow the zero-argument case, we can eliminate that print(t) using a compile-time if.

Click here to view code image

```cpp
template<Printable T, Printable... Tail>
void print(T head, Tail... tail)
{
    cout << head << " ";
    if (constexpr(sizeof(tail) > 0)
        print(tail);
}
```

I used a compile-time if (§7.4.3), rather than a final call if print(t) from being generated. Given that, the "print()" does not need to be defined.
The strength of variadic templates is that they can accept any number of arguments you care to give. Weaknesses include:

- The recursive implementations can be tricky to get.
- The type checking of the interface is possibly elaborate.
- The type checking is ad hoc, rather than defined in the standard.
- The recursive implementations can be surprisingly expensive in compile time and memory requirements.

Because of their flexibility, variadic templates are widely used in the standard library, and occasionally overused.

### 8.4.1 Fold Expressions

To simplify the implementation of simple variadic templates, C++ offers a limited form of iteration over a parameter pack. For example:

Click here to view code image

```cpp
template<typename... T>
int sum(T... v)
{
    return (v + ... + 0); // add all elements starting with 0
}
```

This sum can take any number of arguments of types:

Click here to view code image

```cpp
int x = sum(1, 2, 3, 4, 5); // x becomes 15
int y = sum('a', 2); // y becomes 11 (a is truncated and value of 'a' is 9)
```

The body of sum a fold expression:

Click here to view code image

```cpp
return (v + ... + 0); // add all elements of v with the initial value 0
```

Here, (v + ... + 0) means all elements of v starting with 0. That element to be added is the "rightmost" (the one with the highest index); it starting from the right is called a right fold. Alternatively, we could have used a left fold:

Click here to view code image

```cpp
template<typename... T>
int sum(T... v)
{
    return (0 + ... + v); // add all elements of v to v
}
```

Now, the first element to be added is the "leftmost" (the one with the lowest index): it starting from the left is. Fold is a powerful abstraction, clearly used in the standard-library accumulate(), with a variety of names in different languages and communities. In C++, the expressions are currently restricted. Consider a famous example:

Click here to view code image

```cpp
template<Printable ...T>
void print(T&&... args)
{
    (std::cout << ... << args) << '\n'; // print all arguments
}
```

```cpp
print("Hello", "World"); // ((std::cout << "Hello") << "World") << '\n';
```

Why 2017? Because fold was added to C++17 (19.2.3).

## 8.4.2 Forwarding Arguments

Passing arguments unchanged through an interface is an important use of variadic templates. Consider a notion of network input channel for which the actual moving of values is a parameter. Different transport mechanisms have different sets of parameters:

Click here to view code image

```cpp
template<typename Transport>
class InputChannel {
public:
    //
    InputChannel(Transport&&... transportArgs)
    : _transport(std::forward<decltype(transportArgs)>(transportArgs)...)
    //
    Transport _transport;
};
```

The standard-library function forward() (§16.6) is used to move the arguments from the InputChannel constructor to the Transport constructor.

The point is that the writer of InputChannel can construct an object of type Transport without knowing what arguments are required to construct a particular Transport. The implementer of InputChannel needs only to know the common user interface for all Transport objects.

Forwarding is very common in functional libraries where generality and low run-time overhead are necessary and very general interfaces are common.

## 8.5 Template Compilation Model

At the point of use, the arguments for a template are checked against its concepts. Errors found here will be reported immediately. What cannot be checked at this point, such as arguments for unconstrained template parameters, is postponed until code is generated for the template with a set of arguments: "template instantiation."

An unfortunate side of instantiation-type checking is that a type error can be detected uncomfortably (§8.2.4.1). Also checking results in spectacularly bad error messages because the compiler does not have type information giving the programmer's intent and detects problem only after combining information from several places in the program.

The instantiation-type checking for templates checks the use of arguments in the template definition. This provides a compile-time variant of what is often called duck typing ("If it walks like a duck and it quacks like a duck, it's a duck"). Or – using more technical terminology – operate on values, and the presence and meaning of an operation depend solely on its operand values. This differs from the alternative view that "live" in objects. This is the way we determine the presence and meaning of operations. Values (e.g., variables) work in C++, and only values that meet an object's requirements can be put into it. What is done at compile using templates most not involve objects, only values. The exception is locals in a constexpr function (§1.6) that are used as objects inside the compiler.

To use an unconstrained template, its definition (not just its declaration) must be in scope point of use. When using header files and #include, this means that templates are found in header files, rather than .cpp files. For example, the standard <vector> holds the definition of vector.
