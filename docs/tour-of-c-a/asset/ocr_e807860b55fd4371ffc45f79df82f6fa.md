that can be used in very similar manner to the standards. The range-checked vector, Vector (§4.3, Chapter 5) is an example of that; the uniformity of container interfaces allows us to specify algorithms independently of container types. However, each has strengths and weaknesses. subscribing and traversing a vector is cheap and easy. On the other hand, vector elements are moved to different locations when we insert or remove elements; note that a vector is much more efficient than a list for short sequences of small elements (even for insert()); I recommend the standardlibrary vector as the default type for sequences of elements: unless you need a reason to choose another.

Consider the singly-linked, forward_list, a container optimized for the empty sequence (§12.3). An empty forward_list occupies only one node, whereas an empty vector occupies three. Empty sequences, and sequences with only one element or two, are surprisingly common and useful.

An emplacement operation, such as place_back(), takes arguments and builds the object in a newly allocated space in the container, rather than copying an object inside. For example, by a vector<pair<int,string>> we could:

For simple examples like this, optimizations can result in equivalent performance for both calls.
