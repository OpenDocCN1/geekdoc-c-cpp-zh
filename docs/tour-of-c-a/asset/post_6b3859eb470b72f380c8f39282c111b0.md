## 12.1 Introduction

Most computing involves creating collections of values and then manipulating such collections. Reading characters into a string and printing out the string is a simple example. A class with the main purpose of holding objects is commonly called a container. Providing suitable containers for a given task and supporting them with useful foundational operations are important steps in the construction of any program.

To illustrate the standard-library containers, consider a simple program for keeping names and telephone numbers. This is the kind of program for which different approaches appear “simple and obvious” to people of different backgrounds. The Entry class from §11.5 can be used to hold a simple phone book entry. Here, we deliberately ignore many real-world complexities, such as the fact that phone numbers do not have a simple representation as a 32-bit int.

## 12.2 vector

The most used standard-library container is vector. A vector is a sequence of elements of a given type. The elements are stored continuously in memory. A typical implementation of vector (§5.2.2, §6.2) will consist of a handling pointers to the first, one-past-the-last and one-past-the-last allocated space (§13.1) (or the equivalent information represented as a pointer plus offsets:

![](img/0bd2e25eba2737c3c5daca16fad1b65b_176_0.png)

In addition, it holds an allocator (alloc), from which the vector can acquire memory for its elements. The default allocator uses new and delete to acquire and release memory (§12.7). Using a slightly different implementation technique, we can avoid storing any data for simple allocators in a vector object.

We initialize a vector with a set of values of its element type:

Click here to view code image

```cpp
vector<Entry> phone_book = {
  "David Hume",123456,
  "Karl Popper",234567,
  "Bertrand Arthur Russell",345678
};
```

Elements can be accessed through subscribing. So, assuming that we have defined << Entry, can write:

Click here to view code image

```cpp
void print_book(const vector<Entry>& book)
{
  for (int i = 0; i != book.size(); ++i)
    cout << book[i] << "\n";
}
```

As usual, index starts at 0 so book[0] holds the entry for David Hume. The vector member function size() gives the number of elements.

The elements of a vector constitute a range, so we can use a range-for loop (§1.7):

Click here to view code image

```cpp
void print_book(const vector<Entry>& book)
{
    for (const auto& x : book) // for "auto" see §1.4
    cout << x << "\n";
}
```

When we define a vector, we give it an initial size (initial number of elements):

Click here to view image

| vector<int> v1={1, 2, 3, 4}; | size is 4 |
| vector<string> v2; | size is 0 |
| vector<Shape> v3(23); | size is 23; initial value: nullptr |
| vector<double> v4(32,9); | size is 32; initial value: 9.9 |

An explicit size is used in ordinary parentheses, for example, (23), and by default, the elements are initialized to the element type's default value (e.g., nullptr for pointers and 0 for numbers). If you don't want the default value, you can specify it as a second argument (e.g., 9.9 for the 32 elements of v4).

The initial size can be changed. One of the most useful operations on a vector is push_back(), which adds a new element at the end of a vector, increasing its size by one. For example, assuming that we have defined << for Entry, we can write:

Click here to view image

```cpp
void input()
{
    for (Entry& e; cin>>e);
    book.push_back(e);
}
```

This reads Entries from standard input until the end-of-input (e.g., the end of a file) is reached.

The standard-library vector is implemented so that growing a vector by repeated push_back() is efficient. To grow, consider an implementation of Vector from Chapter 5 and Chapter 7:

Click here to view image

```cpp
template <typename T>
class Vector {
    allocator<T> alloc; // Standard-library allocator of space for elements
    T* elem; // Pointer to first element
    T* space; // Pointer to first unused (uninitialized) slot
    T* last; // Pointer to last slot
public:
    // ...
    int size() const { return space-elem; } // Number of elements
    int capacity() const { return last-elem; } // Number of slots
    // ...
    void reserve(int n); // increase capacity
    // ...
    void push_back(const T& t); // Copy t into Vector
    void push_back(T&& t); // Move t into Vector
};
```

The standard-library vector has capacity(), reserve(), and push_back(). The reserve() is used by users of vector and other to make room for more elements. It may have to allocate new memory and when it does, it moves the elements to the new allocation. When reserve() moves elements to a larger allocation, pointers to those elements will now point to the wrong location; they have been invalidated and should not be used. Given capacity() and reserve(), implementing push_back() is trivial:

Click here to view code image

```cpp
template<typename T>
void Vector<T>::push_back(const T& t)
{
    if (capacity()<=size())                // make sure space for it
        reserve(size()*2);             // double the capacity
    construct(space,t);                   // place t at space
    ++size;
}
```

Now allocation and relocation happens only infrequently. I used reserve() to improve performance, but that turned out to be a waste of effort: the heuristic used by vector is on average much better than, so I now exclusively use reserve() to avoid realloc of elements when I want to put elements. A vector can be copied in assignments and initialization. For example:

Click here to view code image

```cpp
vector<Entry> book2= phone_book;
```

Copying and moving vectors are implemented by constructors and assignment operators as described in §6.2. Copying involves copying its elements. Thus, the initialization of book2 and phone_book hold separate copies of Entry. When a vector has many elements, such realloc assignments and initializations can be expensive. Where copying is undesirable, references or pointers (§1.7) or move operations (§6.2) should be used.

The standard-library vector is very flexible and efficient. It is your default container; use it unless you have a solid reason to use some other container. If you use vector because of vague concerns about "efficiency," measure. Our intuition is often fallible in matters of performance of container users.

## 12.2.1 Elements

Like standard-library containers, vector is a container of elements of type T, that is, vector<T>. Just about any qualifications as element type (such as char, int and double), user-defined types (such as string, Entry, list<int>, and Matrix<double,2>), and pointers (such as const char*, Shape, and double*). When you insert a new element, its value is copied into the container. For an integer with the value 7 into a container, the resulting element really has the value 7. The element is not a reference or a pointer to some object creating makes for nice, compact containers with fast access. For people who care about memory size and run-time performance this is critical.

If you have a class hierarchy (§5.5) that relies on virtual functions to get polymorphic behavior, do not store objects directly in a container. Instead store a pointer (or a smart pointer; §15.2.1). For example:

Click here to view code image

```cpp
vector<Shape> vs;
vector<Shape*> vps;
vector<unique_ptr<Shape>> vps;
```

## 12.2.2 Range Checking

The standard-library vector does not guarantee range checking. For example:

Click here to view code image

```cpp
void silly(vector<Entry>& book) {
    int i = book[book.size()].number;
    // ...
}
```

| book.size() is out of range |That initialization is to place some random value in i rather than giving an error. This is undesirable, and out-of-range errors are common problem. Consequently, I often use a simple range-checking adaptation of vector:

Click here to view code image

```cpp
template<typename T>
struct Vec {
    vector<T> vec;
    using vector<T>::vector;

    T& operator[](int i) { return vec.at(i); }
    const T& operator[](int i) const { return vec.at(i); }

    auto begin() { return checked_iter<vector<T>>(*this).begin(); }
    auto end() { return checked_iter<vector<T>>(*this).end(); }
};
```

| use the constructors from vector (under the name Vec) |
| range check |
| range check const objects; §5.2.1 |
| see §13.1 |

Vec inherits everything from vector except the subscript operations that it redefines to do range checking. The at() is an operation that throws an exception of type out_of_range if argument is one of the vector's range ($4.2). For Vec, an out-of-range access will throw an exception that the user can catch. For example:

```cpp
void checked(Vec<Entry>& book) {
    try {
        book[book.size()] = {"Joe", 999999};
        // ...
    } catch (const out_of_range& e) {
        cerr << "range error";
    }
}
```
