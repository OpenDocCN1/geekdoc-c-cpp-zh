knows only the interface defined by Container. Consequently, use(Container)& needn't be recompiled if the implementation of List_container changes or a brand-class derived from Container is used.

The flip side of this flexibility is that objects must be manipulated through pointers or references (§6.2, §15.2.1).

# # 5.4 Virtual Functions

Consider again the use of Container:

Click here to view code image

```
void use(Container& c) {
    const int sz = c.size();
    for (int i=0; i<sz; ++i)
        cout << c[i] << "\n";
}
```

How is the call of c[i] in use() resolved to the right operator[]? When hi calls use(), List_container's operator[] must be called. When gi calls use(), Vector_container's operator() must be called. To achieve this achievement, a Container object must contain information to allow it to select the right function to call at runtime. The compiler converts the name of a virtual function into an index into a table of pointers to functions. That table is usually called the virtual function table or simply the vtable. Each class with virtual functions has its vtable identifying its virtual functions. Can be represented graphically like this:

| Vector_container: | vtable: |
| --- | --- |
| v | Vector_container::operator[]() |
| | Vector_container::size() |
| | Vector_container::Vector_container() |

| List_container: | vtable: |
| --- | --- |
| Id | List_container::operator[]() |
| | List_container::size() |
| | List_container::List_container() |

The functions in the vtable allow the object to be used correctly even when the size of the object and the layout of its data are unknown to the caller. The implementation of the caller needs only to know the location of the pointer to the vtable in a Container and the index used for each virtual function.
