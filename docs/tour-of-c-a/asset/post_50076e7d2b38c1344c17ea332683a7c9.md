When a `string`'s value changes from a short to a long string (and vice versa) its representation adjusts appropriately. How many characters can a "short" have? That's implementation defined, but "about 14 characters" isn't a bad guess.

The actual performance of `strings` can depend critically on the run time environment. In particular, in multi-threaded implementations, memory allocation can be relatively costly. Also, when strings of different lengths are used, memory fragmentation can result. These are the main reasons that the short-string optimization makes them ubiquitous.

To handle multiple character sets, `string` is really an alias for a general template `basic_string` with the character type `char`.

Click here to view code image

```
template<typename Char>
class basic_string {
    // ... string of Char ...
};

using string = basic_string<char>;
```

A user can define strings of arbitrary character types. For example, assuming we have a Japanese character type `Jchar`, we can write:

Click here to view code image

```
using Jstring = basic_string<Jchar>;
```

Now we can do the usual string operations on `Jstring`, a string of Japanese characters.

## # 10.3 String Views

The most common use of a sequence of characters is to pass it to function to read. This can be achieved by passing a `string` by value, a reference to a string, or a C-style string. In many systems there are alternatives, such as string types not offered by the standard. In all of these cases there are extra complexities when we want to parse a substring. To address this, the standard library offers `string_view`; a `string_view` is basically a `(pointer,length)` pair denoting a sequence of characters:

```
{ string_view:: size() }
```

| characters: | P | i | e | t | H | e | i | n |

A string_view gives access to a contiguous sequence of characters. The characters can be stored in many possible ways, including in a string and a C-style string. A string_view is like a pointer or a reference that it does not own the characters it points to. In that, it resembles an STL pair of iterators (§13.3).

Consider a simple function concatenating strings:

Click here to view code image

```
{
  string res(string_view sv1, string_view sv2);
    // initialize from sv1
    return res += sv2; // append to sv2 and return
}
```

We can call cat():

```
string king = "Harold";
auto s1 = cat(king,"William");
auto s2 = cat(king,king);
auto s3 = cat("Edward","Stephen");
auto s4 = cat("Canute",sv);
auto s5 = cat(&king[0,2],"Henry",sv);
auto s6 = cat(&king[0,3],&king[2,4]);
```

This cat() has three advantages over the compose() that takes const string& and arguments (§10.2):

- It can be used for character sequences managed in many different ways.
- We can easily pass a substring.
- We don't have to create a string to have "string view" suffix. To do that, we need to make it visible:

```
using namespace std::string_view_literals; //sv_6
```

Why without such a effect? The reason is when we pass "Edward" we need to construct a string_view from a const char and that requires the characters. For "Stephen"sv the length is computed at compile

A string_view defines a range, so we can traverse its characters. For example:

Click here to view code image

```
void print_lower(string_view sv1)
{
  for (char c : sv1)
    cout << tolower(c);
}
```

One significant restriction of string_view is that it is a read-only view of its characters. For example, you cannot use a string_view to pass characters to a function that modifies its argument to lowercase. For that, you might consider using a span (§15.2.2).

Think of string_view as a kind of pointer; to be used, it must point to something:

Click here to view code image

```
string_view bad()
{
    string s = "Once upon a time";
    return (&s[5],4);
}
```

Here, the string will be destroyed before we can use its characters.
The behavior of out-of-range access to a string_view is undefined. If you want guaranteed range checking, use std(), which throws out_of_range for attempted out-of-range access, or gsi::span(§15.2.2).

## # 10.4 Regular Expressions

Regular expressions are a powerful tool for text processing. They provide a way to simply and tersely define patterns in text (e.g., a U.S. postal code as TX 77845, or an ISO-style code, such as 2009-06-07) and efficiently find such patterns. The standard library provides support for regular expressions in the form of std::regex and its supporting functions. To give a taste of the style of the regex library, let us define and print a pattern:

Click here to view code image

```
regex pat("\w(2)\s\d(5):-\d(4)?"); // U.S. postal code: XXdddddd-dddd and variants
```

People who have used regular expressions in just any language will find lw(2)\s\d(5):-d(4)? familiar. It specifies a pattern starting with two letters lw(2) optionally followed by space \s followed by five digits and four digits -d(4). If you are not familiar with regular expressions, this might be a good time to learn about them [[Stroustrup,2009], [Maddock,2009], [Friedl,1997]].].

To express this, use a raw string literal starting with R" and terminated by ". Strings are particularly suitable for regular expressions because they often contain a lot of backslashes. Had I used a conventional string, the pattern definition would be:

Click here to view code image

```
regex pat("\w(2)\s\d(5):-\d(4)?"); // U.S. postal code pattern
```

In <regex>, the library provides support for regular expressions:

- regex_match(): Match a regular expression against a string (of known) (§10.2).
- regex_search(): Search for strings that match a regular expression in an (arbitarily long)
- regex_replace(): Search for strings that match a regular expression and replace them.
- regex_iterator(): Iterate over matches (§10.2).
- regex_token_iterator: Iterate over non-matches.

### 10.4.1 Searching

The simplest way of using a pattern is to search for it in a:

Click here to view code image

```
int lineno = 0;
for (string line; getline(cin,line); {
    ++lineno;
    smatch matches;
    if (regex_search(line,matches,pat))
        cout << ":" << matches[0] << "\n";
}
```

The regex_search(line,matches,pat) uses the line for matches that the expression stored in pat and if it finds any, it stores in matches. If no match was found, regex_search(line,matches,pat) returns false. The matches are type match. The "s" stands for "sub" or "string," and an match is a vector of submatches. The first element, matches[0], is the complete match. The result of regex_search() is a collection of matches,

```
int lineno = 0;
for (string line; getline(in,line); {
    ++lineno;
    smatch matches; // matched strings here
    if (regex_search(line,matches,pat)) {
        cout << ":" << matches[0] << "\n"; // the complete match
        if (1 < matches.size() && matches[1]) {
            cout << ":" << matches[1] << "\n"; // if there is a sub-pattern
        }

```

This function reads a file looking for U.S. postal codes, such as TX77845 and DC 20500-001. An match type is a container of regex results. matches[0] is the whole pattern and matches[1] is the optional-digit subpattern (\d(4)).

The newline character, \ln, can be part of a pattern, so we can search for multiline patterns. Obviously, we shouldn't read one line at a time if we want to.

The regular expression syntax and semantics are designed so regular expressions can be compiled into state machines for efficient execution. The regex performs this compilation at run time [Cox,2007].
