The standard-library vector has capacity(), reserve(), and push_back(). The reserve() is used by users of vector and other vector to make room for more elements. It may have to allocate new memory and when it does, it moves the elements to the new allocation. When reserve() moves elements to a new and larger allocation, pointers to those elements will now point to the wrong location; they have been invalidated and should not be used.

Given capacity() and reserve(), implementing push_back() is trivial:

```
template<typename T>
void Vector<T>::push_back(const T& t)
{
    if (capacity()<=size())                // make sure we space for it
        reserve(size()=2*size());             // if do double the capacity
    construct_at(space,t);                   // initialize space to "place t at space"
    ++size;
}
```

Now allocation and relocation happens only infrequently. I used reserve() to improve performance, but that turned out to be a waste of effort: the heuristic used by vector is on average much better than my, so I now exclusively use reserve() to avoid realloc of elements when I want to put elements.

A vector can be copied in assignments and initialization. For example:

vector<Entry> book2= phone_back;

Copying and moving vectors are implemented by constructors and assignment operators as described in §6.2. Copying involves copying its elements. Thus, the initialization of book2, book2 and phone_book hold separate copies of Entry in the phone book. When a vector has many elements, such in-alloc assignments and initializations can be expensive. Where copying is undesirable, references or pointers (§1.7) or move operations (§6.2) should be used.

The standard-library vector is very flexible and efficient. It is your default container; use it unless you have a solid reason to use some other container. If you use vector because of vague concerns about "efficiency," measure. Our intuition is often fallible in matters of performance of container users.

# 12.2.1 Elements

Like standard-library containers, vector is a container of elements of type T, that is, a vector<T>. Just about any qualifications as element type (such as char, int and double), user-defined types (such as string, Entry, list<int>, and Matrix<double,2>), and pointers (such as const char*, Shape, and double*). When you insert a new element, its value is copied into the container. For an integer with the value 7 into a container, the resulting element really has the value 7. The element is not a reference or a pointer to some object creating This makes for nice, compact containers with fast access. For people who care about memory size and run-time performance this is critical.
