
The exception will be thrown, and then caught (§4.2). If the user doesn't catch an exception, the program will terminate in a well-defined manner rather than proceeding or failing in an undefined manner. One to minimize surprises from uncaught exceptions is to use a main() with a try-block as this. For example:

Click here to view code image

```cpp
int main() {
    try {
        // your code
    }
    catch (out_of_range& e) {
        cerr << "range error";
    }
    catch (...) {
        cerr << "unknown exception thrown";
    }
}
```

This default exception handles overhead so that if we fail to catch some exception, an error message is printed on the standard error-diagnostic output stream (§11.2).
Why doesn't the standard guarantee range checking? Many performance-critical applications use vectors and checking all subscribing implies a cost on the order of 10%. Obviously, that cost can vary dramatically depending on overhead, optimizers, and an application's use of subscribing. Experience shows that such overhead can lead people to prefer the more unsafe builtin arrays. Even the fear of such overhead can lead to dismay. At least vector is easily checked at debug time and we can build checked versions on top of the unchecked default.

A range-for avoids errors at no cost by minimally accessing all elements in the range. As long as their arguments are valid, the standard-library algorithms do to ensure the absence of range errors.

If you use vector::at() directly in your code, you don't need my Vec workaround. Furthermore, some standard libraries have range-checked vector implementations that offer more complete checking than Vec.

## 12.3 list

The standard library offers a doubly-linked list called list:

- list:

![](img/0bd2e25eba2737c3c5daca16fad1b65b_180_0.png)

We use a list for sequences where we want to insert and delete elements without moving other elements. Insertion and deletion of phone book entries could be common, so a list could be appropriate for representing a simple book. For example:

Click here to view code image

```cpp
list<Entry> phone_book = {
    {"David Hume", 123456"},
    {"Karl Popper", 234567"},
    {"Bertrand Arthur William Russell", 345678}
};
```

When we use a list, we do not access elements subscribing the way we commonly do for vectors. Instead, we might search the list looking for an element with a given value. To do this, we take advantage of the fact that a list is a sequence as described in Chapter 13:

Click here to view code image

```cpp
int get_number(const string &s) {
    for (const auto &x : phone_book) {
        if (x.name==s)
            return x.number;
    }
    return 0; // else 0 to represent "number not found"
}
```

The search for s starts at the beginning of the list and continues until s is found or the end of phone_book is reached.

Sometimes, we need to identify an element in a list. For example, we want to delete an element or insert a new element before it. To do that we use an iterator; a list iterator identifies an element of a list and can iterate through a list (like we have). Standard-library container provides the functions begin() and end(), which return an iterator to the first and one-past-the-last element, respectively (§13.1). Using iterators, we can — less elegantly — write the get_number() function like this:

Click here to view code image

```cpp
int get_number(const string &s) {
    for (auto p = phone_book.begin(); p!=phone_book.end(); ++p) {
        if (p->name==s)
            return p->number;
    }
    return 0; // else 0 to represent "number not found"
}
```

In fact, this way and less error-prone loop is implemented by the compiler. Using an iterator, p is the element to which it refers, ++p advances to refer to the next element, and p refers to a class with a member m, then p->m is equivalent to (*p).m. Adding elements to a list and removing elements from a list is easy:

Click here to view code image

```cpp
void f(const Entry &e, list<Entry>::iterator p, list<Entry>::iterator q) {
    phone_book.insert(p, e); // add e before the element pointed to p
    phone_book.erase(q); // remove the element pointed to q
}
```

For a list, insert(p, elem) inserts an element with a copy of the value before the element pointed to p. Here, p may be an iterator pointing beyond the end of the list. Conversely, erase(p) removes the element pointed to p and destroys it.

These list examples could be better using vector and (surprisingly) perform better with a vector than a list. When we want a sequence of elements, we have a choice between a vector and a list. Unless we have a reason not to use, a vector performs better for traversal (e.g., find() and count()) and for sorting and searching (e.g., sort() and equal_range()) (§13.5, 13.3).

## 12.4 forward_list

The standard library offers a singly-linked list called forward_list:

![](img/0bd2e25eba2737c3c5daca16fad1b65b_182_0.png)

forward_list: A forward_list differs from a doubly-linked list by only allowing forward iteration. The point of that is to save space. There is no need to keep a predecessor pointer in each link and the size of forward_list is just one pointer. If you need the number of elements, count. If you can't afford to count, you probably shouldn't use forward_list.

## 12.5 map

Writing code to look up a name in a list of (name, number) pairs is quite tedious. In addition, linear search is inefficient for all lists. The standard library offers a balanced binary tree (usually a red-black tree) called map:

![](img/0bd2e25eba2737c3c5daca16fad1b65b_182_1.png)

In other contexts, a map is known as an associative array or a dictionary. The standard-library map is a container of pairs of values optimized for lookup and insertion. We can use the same initializer as vector and list (§12.2, 12.3):

```cpp
map<string,int> phone_book = {
    {"David Hume", 123456},
    {"Karl Popper", 234567},
    {"Bertrand Arthur Russell", 345678}
};
```

When indexed by a value of its first type (called the key), a map returns the corresponding value of its second type (called the value or mapped type). For example:

```cpp
int get_number(const string& s) {
    return phone_book[s];
}
```

In other words, subscript a map is essentially the lookup get_number(). If a key isn't found, it is entered into the map with a default value for its value. The default value for an integer type is 0 and happens to be a reasonable value to represent an invalid number. If we wanted to avoid entering invalid numbers into our phone book, we could use find() and insert(12.8) instead of subscript.

## 12.6 unordered_map

The cost of a map lookup is O(log n) where n is the number of elements in the map. That's pretty good. For example, by a map with 1,000,000 elements, we perform only about 20 comparisons and indirections to find an element. However, in many cases, we can do better by using a hashed lookup rather than a comparison using an ordering function, such as the standard-library hashed containers are referred to as “unordered” because they don't require an ordering function:

![](img/0bd2e25eba2737c3c5daca16fad1b65b_183_0.png)

For example, we can use unordered_map from <unordered_map> for our phone book:

```cpp
unordered_map<string,int> phone_book = {
    {"David Hume", 123456},
    {"Karl Popper", 234567},
    {"Bertrand Arthur Russell", 345678}
};
```

Like for a map, we can subscript an unordered_map:

```cpp
int get_number(const string& s) {
    return phone_book[s];
}
```

The standard library provides a default hash function for strings as well as for other built-in and standard-library types. If necessary, we can provide our own. Possibly, the most common need for a custom hash function comes when we want an unordered container of one of our types. A hash function is often implemented as a function object (§7.3.2). For example:

```cpp
struct Record {
    string name;
    int product_code;
    // ...
};

struct Hash {
    // A hash function for Record
    size_t operator()(const Record& r) const {
        return hash<string>(r.name) ^ hash<int>()(r.product_code);
    }
};

unordered_set<Record,Hash> my_set; // unordered_set of Records using Hash for lookup

Designing good hash function is an art and requires knowledge of the data to which it is built. Creating a new hash function by combining existing hash functions with exclusive-or (^) is simple and very effective. However, be careful to ensure that every value takes part in the hash to distinguish the values. For example, unless you have several names for the same product code (or several product codes for the same name), combining the two hashes provides no benefits.

We can avoid explicitly mentioning the hash operation by defining it as a specialization of the standard-library hash:

```cpp
namespace std {
    // Make a hash function for Record
    template<> struct hash<Record> {
        using argument_type = Record;
        using result_type = size_t;

        result_type operator()(const Record& r) const {
            return hash<string>(r.name) ^ hash<int>()(r.product_code);
        }
    };
};
```
