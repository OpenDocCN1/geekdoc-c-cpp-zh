# 8.2.6 Concepts and Types

A type

+   - Specifies the set of operations that can be applied to an object, implicitly and explicitly
- Relies on function declarations and language rules
- Specifies how an object is laid out in memory

A single-argument concept

+   - Specifies the set of operations that can be applied to an object, implicitly and explicitly
- Relies on use patterns reflecting function declarations and language rules
- Says nothing about the layout of the object
- Enables the use of a set of types

Thus, constraining code concepts gives more flexibility than constraining with types. In addition, concepts can define the relationship between several arguments. My ideal is that eventually functions will be defined as template functions with their arguments constrained by concepts. Unfortunately, the not support for that is not yet perfect: we have to use a concept as an adjective, rather than a noun. For example:
