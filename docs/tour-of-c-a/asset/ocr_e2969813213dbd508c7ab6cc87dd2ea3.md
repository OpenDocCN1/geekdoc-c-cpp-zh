# 11.4 I/O State

An iostream has a state that we can examine to determine whether an operation succeeded. The most common use it is to read a sequence of values:

Click here to view code image

```
vector<int> read_ints(istream& is)
{
    vector<int> res;
    for (int i; is >> i; ) {
        res.push_back(i);
    }
    return res;
}
```

This reads from is until that is not an integer is encountered. That something will typically be the end of input. What happening here is that the operation >> returns a reference to is, and testing an iostream yields true if the stream is ready for another operation.

In general, the I/O state holds all the information needed to read or write, such as formatting information (§11.6.2), error state (e.g., has-of-file reached?), and what kind of buffering is used. By using a set the user can set to retrieve that an error has occurred (§11.5) and clear the state if an error wasn't serious. For example, we could imagine a version of read_ints() that accepts a terminating string:

Click here to view code image

```
vector<int> read_ints(istream& is, const string& terminator)
{
    vector<int> res;
    for (int i; is >> i; ) {
        res.push_back(i);
    }
    if (is.eof()) // If: end of file
        return res;
    if (is.fail()) // If we failed to read an int; was it the terminator?
        is.clear(); // It reset the state to good
        string s;
        if (is>>s && s==terminator)
            return res;
        is.setstate(ios_base::failbit); // It add fail() to is's state
    }
    return res;
}
```
