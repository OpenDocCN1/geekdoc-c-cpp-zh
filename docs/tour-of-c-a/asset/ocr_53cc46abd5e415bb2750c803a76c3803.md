This is a simplified version of the standard-library complex (§17.4). The class definition contains only the operations requiring access to the representation. The representation is simple and conventional. For practical reasons, it has to be compatible with Fortran provided sixty and we need a new set of operators. In addition to the logical demands, complex must be efficient or it will remain unchanged. Thus, simple operations (such as constructors, =, imag()) must be implemented without function calls in the generated machine code. Functions defined in a class are inlined by default. An industrial-standard complex is is carefully implemented to provide appropriate inlining. In addition, the standard-library complex has functions shown here constexpr so that we can do complex arithmetic at compile time.

A constructor that can be invoked without an argument is a default constructor. Thus, complex() is complex's default constructor. By defining a constructor you eliminate the possibility of uninitialized variables of type.

The const prefix on functions returning the real and imaginary parts indicates that the functions do not modify the object for which they are called. A const member function can be invoked for const and non-const objects, but a non-const member function can only be invoked for non-const objects. For example:
