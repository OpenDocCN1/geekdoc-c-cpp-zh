In <type_traits>, the standard library provides many functions for inquiring about properties of types. For example:

Click here to view code image

```
bool b = is_arithmetic<T>::value; // Il true if T is one of the (built-in) arithmetic types
using Res = invoke_result<decltype(f)>; // Il Res if f is a function that returns an int
```

The decltype(f) is a call of built-in decltype returning the declared type of its argument; here f.
Some functions create new types based on inputs. For example:

Click here to view code image

```
template<typename T>
using Store = conditional_t<sizeof(T)<max, On_stack<T>, On_heap<T>>;
```

If the (Bool) conditional is true, the result is the first alternative; otherwise, the second. Assuming On_stack and On_heap offer the same access functions to T, they can allocate T as names indicate. Users of Store<X> can be tuned to the size of objects. The performance tuning enabled by this choice of allocation can be very significant. This is a example of how we can construct our own type functions, either from the standard ones or by using concepts.

Concepts are functions which, when used in expressions, are specially typed predicates. For example:

Click here to view code image

```
template<typename F, typename... Args>
auto call(F f, Args... args, Allocator alloc)
{
	if constexpr (invocable<F, Args...>) // Il needs an allocator?
	return f(std::forward<Args>(args)...);
\else
	return f(std::forward<Args>(args)...);
}
```

In many cases, concepts are the best type functions, but most of the standard library was built pre-concepts and must support pre-concept base codes.

The not conventions use _v for type functions that return values, _t for type functions that return types, is a leftover from the weakly typed days of C and pre-concept C++.
