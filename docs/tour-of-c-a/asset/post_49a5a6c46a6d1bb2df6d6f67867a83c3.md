## 7.4.3 Compile-Time if

Consider writing an operation that can be implemented using one of two functions slow_and_safe(T) or simple_and_fast(T). Such problems in foundational code where generality and optimal performance are essential. If a class hierarchy is involved, a base class can provide the slow_and_safe general operation and a derived class can override with a simple_and_fast implementation.

Alternatively, we can use a compile-time if:

Click here to view code image

```cpp
template<typename T>
void update(T& target)
{
    // ...
    if (constexpr(is_trivially_copyable_v<T>)
        simple_and_fast(target); // for "plain data"
    else
        slow_and_safe(target); // for more complex types
    // ...
}
```

The is_trivially_copyable_v<> is a type predicate ($16.4.1) that tells us if a type is trivially copied.

The selected branch of an if constexpr is checked by the compiler. This solution offers optimal performance and locality of the optimization.

Importantly, if constexpr is not a text-manipulation mechanism and cannot be used to break the usual rules of grammar, type, and scope. For example, here is a naive and failed attempt to conditionally wrap a call in a try-block:

Click here to view code image

```cpp
template<typename T>
void bad(T arg)
{
    if constexpr(is_trivially_copyable_v<T>)
        try {
            // Oops, if it extends beyond this line
            g(arg);
        }
    if constexpr(is_trivially_copyable_v<T>)
        catch(...) { /* ... }
}
```

Allowing such text manipulation could seriously compromise readability of code and create problems for tools relying on modern program representation techniques (such as "abstract syntax trees").

Many attached hacks are also unnecessary; cleaner solutions that do not violate scope rules. For example:

Click here to view code image

```cpp
template<typename T>
void good(T arg)
{
    if constexpr(is_trivially_copyable_v<T>)
        g(arg);
    else
        try {
            g(arg);
        }
    catch (...) { /* ... }
}
```

## 8.1 Introduction

What are templates for? In other words, what programming techniques are made effective by templates? Templates offer:

- The ability to pass types (as well as values and templates) as arguments without loss of information. This implies great flexibility in what can be expressed and excellent opportunities for inlining, of which current implementations take great advantage.
- Opportunities to weave together information from different contexts at instantiation time. This implies optimization opportunities.
- The ability to pass values as template arguments. This implies opportunities for compile-time computation.

In other words, templates provide a mechanism for generic programming. The term "generic programming" was first introduced in C++ to describe the practice of writing code that is independent of the types used, using standard-compliant interfaces. Templates are the primary tool for this.

## 8.2 Concepts

Consider the following:

```cpp
template<typename Seq, typename Value>
Value sum(Seq s, Value v)
{
    for (const auto& x : s)
        v += x;
    return v;
}
```

The function above requires that `Seq` be an iterable of elements that can be added to `Value`, and that `Value` supports the `+=` operator. These requirements are not explicitly stated in the template signature, but are implied by the implementation. This is often called "duck typing": if it walks like a duck and quacks like a duck, it's a duck.

In C++20, we can explicitly state these requirements using concepts:

```cpp
template<typename Seq, typename Value>
concept Addable = requires(Seq s, Value v) {
    for (const auto& x : s)
        v += x;
};

template<typename Seq, typename Value>
requires Addable<Seq, Value>
Value sum(Seq s, Value v)
{
    for (const auto& x : s)
        v += x;
    return v;
}
```

By using concepts, we can provide better error messages when a template is used with types that do not satisfy the requirements. We can also allow the compiler to generate more efficient code.

### 8.2.1 Use of Concepts

Concepts allow us to constrain template arguments based on their capabilities. This is much more powerful than using SFINAE.

```cpp
template<typename T>
concept Numeric = requires(T a) {
    a + a;
    a - a;
    a * a;
    a / a;
};

template<Numeric T>
T multiply(T a, T b) {
    return a * b;
}
```

Concepts also allow us to define new interfaces. For example:

```cpp
template<typename T>
concept Printable = requires(T a) {
    { std::cout << a } -> std::same_as<std::ostream&>;
};

template<Printable T>
void print(T a) {
    std::cout << a << std::endl;
}
```
