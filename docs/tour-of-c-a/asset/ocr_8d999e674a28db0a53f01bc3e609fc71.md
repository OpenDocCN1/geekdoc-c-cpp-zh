The elements were copied before the old elements were deleted so that if something goes wrong the element copy and an exception is thrown the old value of the Vector is preserved.

# 6.2.2 Moving Containers

We can control copying by defining a copy constructor and a copy assignment, but copying can be costly for large containers. We avoid the cost of copying when we pass parameters to a function by using references, but we can't return a reference to a local object as the result (the local object would be destroyed by the time caller gets a chance to look at it). Consider:

Click here to view code image

```
Vector operator+(const Vector& a, const Vector& b)
{
  if (a.size()!=b.size()) {
    throw Vector_size_mismatch();
  }
  Vector res(a.size());
  for (int i=0; i<a.size(); ++i)
    res[i]=a[i]+b[i];
  return res;
}
```

Returning from a + involves copying the result of the local variable res and into some place where the caller can access it. We use it + like this:

Click here to view code image

```
void f(const Vector& x, const Vector& y, const Vector& z)
{
  Vector r;
  ...
  r = x+y+z;
  ...\n}
```

That would be copying a Vector at least twice (one for each of the + operator). If a Vector is large, 10000 doubles, that could be embarrassing. The most embarrassing part is that res in operator+ is used again after the copy. We didn't really want a copy; we just wanted to get the result out of a function: we wanted to move a Vector rather than copy it. Frequently, we can state that intent:
