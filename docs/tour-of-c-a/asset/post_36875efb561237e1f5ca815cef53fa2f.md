## 7.1 Introduction

Someone who wants a vector is unlikely always to want a vector of doubles. A vector is a general concept, independent of the notion of a floating-point number. Consequently, the element type of a vector ought to be represented independently. A template is a class or a function that we parametri with a set of types or values. We use templates to represent ideas that are best understood as something general from which we can generate specific types and by specifying arguments, such as double vector's element type.

This chapter focuses on language mechanisms. Chapter 8 follows up with programming techniques, and the library chapters (Chapters 10–18) offer many examples.

## 7.2 Parameterized Types

We generalize our vector-of-doubles type ($5.2.2) to a vector-of-anything type by making a template and replacing the specific type double with a type parameter. For example:

Click here to view code image

```
template<typename T>
class Vector {
private:
    T* elem; // elem points to an array of sz elements of type T
    int sz;
public:
    explicit Vector(int s); // establish invariant, acquire resources
    ~Vector() { delete elem; } // release resources

    // copy and move operations ...

    T& operator[](int i); // for non-const Vectors
    const T& operator[](int i) const;
    int size() const { return sz; }
};
```

The template<typename T> prefixes a type parameter of the declaration it prefixes. It is C++'s version of the mathematical "for all T," or more precisely "for all types T." If you want the mathematical "for all T, such that P(T)," then use these concepts ($7.2.1, $8.2). Using class to introduce a type parameter is equivalent to using typename, and in old code we often see template<class T> as the prefix.

The member functions can be defined similarly:

Click here to view code image

```
template<typename T>
T& Vector<T>::operator[](int i) {
    if (i < 0 || i >= sz)
        throw out_of_range("Vector::operator[]: negative size");
    return elem[i];
}

template<typename T>
const T& Vector<T>::operator[](int i) const {
    if (i < 0 || i >= sz)
        throw out_of_range("Vector::operator[]: negative size");
    return elem[i];
}
```

Given these definitions, we can define Vectors like this:

Click here to view code image

```
Vector<char> vc(200); // vector of 200 characters
Vector<string> vs(17); // vector of 17 strings
Vector<int> vl(45); // vector of 45 lists
```

The >> in Vector<list> terminates the nested template arguments; it is not a misplaced operator. We can use Vectors like this:

Click here to view code image

```
void write(const Vector<string> &vs) // Vector of some strings
{
    for (int i = 0; i!=vs.size(); ++i)
        cout << vs[i] << "\n";
}
```

To support the range-for loop for Vector, we must define begin() and end() functions:

```
template<typename T>
T begin(Vector<T>& x)
{
    return &x[0]; // pointer to first element or one-past-the-element
}
template<typename T>
T end(Vector<T>& x)
{
    return &x[0]+x.size(); // pointer to one-past-the-element
}
```

Given those, we can write:

Click here to view code image

```
void write(Vector<string>& &vs) // Vector of some strings
{
    for (auto &s : vs)
        cout << s << "\n";
}
```

Similarly, we can define lists, vectors, maps (that is, associative arrays), unordered maps (that is, hash tables), etc., must define size (Chapter 12). Templates are a compile-mechanism, so they incur no run-time overhead compared to hand-crafted code. In fact, the code generated for Vector<double> is identical to the code generated of Vector from Chapter 5. A template plus set of arguments is called an instantiation or specialization. In the compilation process, at instantiation time ($8.5), and the error messages are often atrocious.

Concept checking is a purely compile-time mechanism and the code generated is as good as that from unconstrained templates.

## 7.2.1 Constrained Template Arguments

Most often, a template will make sense only for template arguments that meet certain criteria. For example, a Vector typically offers copy operation, and if it does, must require that its elements are copyable. That is, we must require that Vector's template is not just a typename but an "Element" specifies the requirements of a type that can be:

Click here to view code image

```
template<T>
class Vector {
private:
  T* elem; // elem points to an array of sz elements of type T
  int sz;
  // ...
}
```

template<typename T> predicts C++'s version of mathematical "for all T such that P(T)." Such a predicate is called a concept ($8.2). The requirements for the type of standard-library are complicated (§12.2), but for our simple Vector, Element could be like copyable (§14.5). It is a compile-time error to try use a template that does not meet its requirements. For example:

Click here to view code image

```
Vector<int> v1;// OK: we can copy an int
Vector<thread> v2;// Error: we cannot copy (§18.2)
```

Thus, concepts lets the compiler to do type checking at the point of use, giving better error messages earlier than possible with unconstrained template arguments. C++ did not officially support concepts before C++20, so older code uses unconstrained template arguments and leaves requirements to documentation. However, the code generated from templates is checked so that even unconstrained template code is as safe as handwritten code. For unconstrained parameters, type checking cannot done until the types of all entities are available, so it occurs unfortunately in the compilation process, at instantiation time (§8.5).

## 7.2.2 Value Template Arguments

In addition to type arguments, a template can take value arguments. For example:

Click here to view code image

```
template<typename T, int N>
struct Buffer {
  constexpr int size() { return N; }
  T elem[N];
  // ...
```

Value arguments are useful in many contexts. For example, Buffer allows us to create arbitrarily sized buffers with no use of the free store (dynamic memory):

Click here to view code image

```
Buffer<char,1024> glob; // global buffer of characters (statically allocated)
```

```
void fct() {
  Buffer<int,10> buf; // local buffer of integers (on the stack)
  // ...
}
```

Unfortunately, for obscure technical reasons, a string literal cannot yet be a template value argument. However, in some contexts, the ability to parameterize string values is critically important. Frankly, we can use an array holding the characters of a string:

Click here to view code image

```
template<char> s;
void outs() { cout << s; }
```

```
char arr[] = "Weird workaround!";
```

```
void use() {
  outs<<"straightforward use>(); // error for now
  outs<arr>();                   // writes: Weird workaround!
}
```

In C++, there is usually a workaround; we don't need direct support for every case.
