is primarily aimed at supporting systems-level concurrency rather than directly providing sophisticated higher-level concurrency models; those can be supplied in libraries using the standard-library facilities.

The standard library supports concurrent execution of multiple threads in a address space. To allow, C++ provides a suitable memory model and a set of atomic operations. The atomic operations allow lock-free programming [Devchev,2010]. The memory model ensures that as long a programmer avoids data races (uncontrolled concurrent access to mutable data), everything works as one would naively expect. However, most users will see concurrency in the standard library and libraries built on top of them. This section briefly gives examples of the standard-library concurrency facilities: threads, mutex, lock() operations, packaged_tasks and futures. These features are built directly upon operating systems and do not incur performance penalties compared with that. Neither do they guarantee significant performance improvements compared to the operating system offers.

Do not consider concurrency apiece. If a task can be done sequentially, it is often faster and easier to do so. Passing information from one thread to another can be surprisingly expensive.

As an alternative to using concurrency features, we can use a parallel algorithm to exploit multiple execution engines for performance (§13.6, §17.3.1).

Finally, C++ supports coroutines; that is, functions that keep their state between calls (§18.6).

# 18.2 Tasks and threads

We call a computation that can potentially be executed with other computations a task. A thread is the system-level representation of a task in a program. A task to be executed concurrently with other threads is launched by constructing a thread (in <thread>) with the task as its argument. A task is a function or a function object:

```
void f();
struct F {
    void operator()();
};
void user(void (*f)()) {
    thread t1(f);
    thread t2(F{});

    t1.join();
    t2.join();
}
```

The join() ensures that we don't exit() until the threads have completed. To "join" a thread means to "wait for the thread to terminate."
