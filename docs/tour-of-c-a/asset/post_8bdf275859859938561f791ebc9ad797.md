## 2.1 Introduction

We call the types that can be built from the fundamental types ($1.4), the const modifier ($1.6), and the declarator operators ($1.7) built-in types. C++'s set of built-in types and operations is rich, deliberately low-level. They directly and efficiently reflect the capabilities of conventional hardware. However, they don't provide the programmer with high-level facilities to conveniently write advanced applications. Instead, C++ augments the built-in types and operations with a sophisticated set of abstraction mechanisms out of which programmers build such high-level facilities.

The C++ abstraction mechanisms are primarily designed to let programmers design and implement their types, with suitable representations and operations, and for programmers to simply and easily use such types. Types built out of C++ are called user-defined types. They are referred to as classes and enumerations. User-defined types can be built out of built-in types and other user-defined types. Most of this book is devoted to the design, implementation, and use of user-defined types. User-defined types are often preferred over built-in types because they are easier to use, less error-prone, and typically efficient for what they do as direct use of built-in types, or even more efficient.

The rest of this chapter presents the simplest and most fundamental facilities for defining and using types. Chapters 4–8 present a most description of the abstraction mechanisms and the programming styles they support. User-defined types provide the backbone of the standard library, the standard-library chapters, 9–17, provide examples of what can be built using the language facilities and programming techniques presented as Chapters 1–8.

## 2.2 Structures

The first step in building a new type is to organize the elements it needs into a data struct:

```
struct Vector {
    double* elem; // pointer to elements
    int sz;       // number of elements
}
```

This first version of Vector consists of an int and a double. A variable of type Vector can be defined like this:

```
Vector v;
```

However, by itself is not of much use because v's elem pointer doesn't point to anything. For it to be useful, we must give v some elements to point to. For example:

```
void vector_init(Vector& v, int s) // initialize a Vector
{
    v.elem = new double[s]; // allocate an array of s doubles
    v.sz = s;
}
```

That is, v's elem member gets a pointer to the new operator and v's sz member gets the number of elements. The & in Vector identifies that we pass v by non-const reference (1.7); that way, vector_init() modifies the vector passed to.

The new operator allocates memory from the free area (also known as dynamic memory and heap). Objects allocated on the free store are independent of the scope from which they are created and "live" until they are destroyed by the delete (5.2.2).

A simple use of Vector likes like this:

```cpp
double read_and_sum(int s) // it reads from cin and return their sum; s is assumed to be positive
{
    Vector v;
    vector_init(v, s); // allocate s elements for v
    for (int i=0; i<s; ++i)
        cin >> v.elem[i]; // read into elements
}

double sum = 0;
for (int i=0; i<s; ++i)
    sum+=v.elem[i];
return sum;
```

There is a long way to go before Vector is as elegant and flexible as the standard-library vector. In particular, a user of Vector has to know every detail of Vector's representation. The rest of this chapter and the next introduced Vector as an example of language features and techniques. Chapter 12 presents the standard-library vector, which contains many nice improvements.

I use vector and other standard-library components as examples to illustrate language features and design techniques, and to help you learn and emulate the standard-library components.

## 2.3 Classes

A member with the same name as its class is a constructor, that is, function used to construct objects of a class. So, the constructor, Vector(), replaces vector_init()) from $2.2$. Unlike an ordinary function, a constructor is guaranteed to be used to initialize objects of a class. Thus, a constructor(int) defines how objects of type Vector are constructed. In particular, it states that it needs an integer to do that. That integer is used as the number of elements. The constructor initializes the Vector members using a member initializer list:

```cpp
class Vector {
public:
    Vector(int s) : elem(new double[s]), sz(s) {} // construct Vector
    double& operator[](int i) { return elem[i]; } // Element access
    int size() { return sz; }
private:
    double* elem; // pointer to elements
    int sz; // number of elements
};
```

Given that, we can define a variable of our new type:

```cpp
Vector v(6); // a Vector with 6 elements
```

The representation of a Vector (the members elem and sz) is accessible only through the interface provided by the public members. The read_and_sum() example from $2.2$ simplifies to:

```cpp
double read_and_sum(int s) {
  Vector v(s);
  for (int i=0; i<v.size(); ++i)
    cin >> v[i]; // read into elements

  double sum = 0;
  for (int i=0; i<v.size(); ++i)
    sum+=v[i]; // take the sum of the elements
  return sum;
}
```
