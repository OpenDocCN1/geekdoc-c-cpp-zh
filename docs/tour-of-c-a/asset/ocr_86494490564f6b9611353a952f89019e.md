# 17.3.1 Parallel Numerical Algorithms

In <numeric>, the numerical algorithms (§17.3) have parallel versions that differ slightly from the sequential ones. In particular, the parallel versions allow operations on elements in unspecified order. The parallel numerical algorithms can also take an execution policy argument (§13.6): seq, unseq, par, and par_unseq.

| Parallel Numerical Algorithms |
|---||
| x=reduce(b,e) | x=accumulate(b,e,v), except out of order |
| x=reduce(b,e) | x=reduce(b,e,v), where v is b's value |
| x=reduce(pol,b,e) | x=reduce(b,e,v) with execution policy pol |
| x=reduce(pol,b,e) | p=partial_sum(b,e,v), where v is b's value |
| p=exclusive_scan(pol,b,e,out) | p=partial_sum(b,e,out) which excludes the ith input element from the ith sum |
| p=inclusive_scan(pol,b,e,out) | p=partial_sum(b,e,out) which includes the ith input element in the ith sum |
| p=transform_reduce(pol,b,e,f,v) | f(x) for x in [b:e), then reduce |
| p=transform_exclusive_scan(pol,b,e,out,f,v) | f(x) for x in [b:e], then exclusive_scan |
| p=transform_inclusive_scan(pol,b,e,out,f) | f(x) for x in [b:e], then inclusive_scan |

For simplicity, I left versions of these algorithms that take operations as arguments, rather than just using + and *. Except for reduce(), I also left the versions with default policy (sequential) and default value.

Just as the parallel algorithms in <algorithm> (§13.6), we can specify an execution policy:

```
vector<double> v(1, 2, 3, 4, 5, 99999999);
auto s = reduce(v.begin(),v.end()); // It calculate the sum using a double as an accumulator
vector<double> large;
// fill large with lots of values ...
auto s2 = reduce(par_unseq,large.begin(),large.end()); // It calculate the sum using available parallelism
```

The execution policies, par, sec, unseq, and par_unseq are hidden in namespace std::execution in <execution>.
