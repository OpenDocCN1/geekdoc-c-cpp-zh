precision of constants matters for graphics and AI, while smaller representations of values are increasingly important.

# # 17.10 Advice

+   [1] Numerical problems are often subtle. If you are not 100% certain about the mathematical aspects of a numerical problem, take expert advice, experiment, or both; §17.1.

+   [2] Don't try to do serious numeric computation using only the base language; use libraries; §17.1.

+   [3] Consider accumulate(), inner_product(), partial_sum(), and adjacent_difference() before you write a loop to compute value from a sequence: §17.3.

+   [4] For larger amounts of data, try the parallel and vectorized algorithms; §17.3.1.

+   [5] Use std::complex for complex arithmetic; §17.4.

+   [6] Bind an engine to your random number generator; §17.5.

+   [7] Be careful that your random numbers are sufficiently random for your intended use; §17.5.

+   [8] Don't use the C-library rand(); it isn't sufficiently random for real uses; §17.5.

+   [9] Use varray for numeric computation when run-efficiency is more important than flexibility with respect to operations and element types; §17.6.

+   [10] Properties of numeric types are accessible through numeric_limits; §17.7.

+   [11] Use numeric_limits to check that the numeric types are adequate for their use; §17.7.

+   [12] Use aliases for integer types if you want to be specific about their sizes; §17.8.
