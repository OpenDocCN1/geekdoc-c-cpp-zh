We can use the same initializer as for vector and list (§12.2, §12.3):

```

    ("David Hume",123456),
    ("Karl Popper",234567),

```

When indexed by a value of its first type (called the key), a map returns the corresponding value of the second type (called the value or the mapped type). For example:

Click here to view code image

```
int get_number(const string& s)
(
    return phone_book[s];
)
```

In other words, subscript a map is essentially the lookup we get_number(). If a key isn't found, it is entered into the map with a default value for its value. The default value for an integer type is 0 and that happens to be a reasonable value to represent an invalid phone number.
If we wanted to avoid entering invalid numbers into our phone book, we could use find() and insert(§12.8) instead of [ ].

# 12.6 unordered_map

The cost of a map lookup is O(log n) where n is the number of elements in the map. That's pretty good. For example, by a map with 1,000,000 elements, we perform only about 20 comparisons and indirections to find an element. However, in many cases, we can do better by using a hashed lookup rather than a comparison using an ordering function, such as <: The standard-library hashed containers are referred to as “unordered” because they don't require an ordering function:
