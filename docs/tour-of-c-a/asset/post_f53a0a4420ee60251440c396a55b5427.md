## 18.5.4 Stopping a thread

Sometimes we want to stop a thread because we are no longer interested in its result. "killing" is not acceptable because a thread can consume resources that are released (e.g., locks, sub-threads, and database connections). The standard library provides a mechanism for properly clean up and go away: a stop_token. A thread can be programmed to terminate if a stop_token and is requested to stop.

Consider a parallel algorithm find_any() that spawns threads looking for a result. When a thread returns with an answer, we would like to stop the remaining threads. Each thread spawned by find_any() calls find() to do the real work. The find() is a very simple example of a common style of task where there is a main loop in which we can insert a test of whether to continue or stop:

```cpp
void find(stop_token tok, const string* base, const Range<string> r, const string target)
{
    for (string* p = r.first; p<=r.last && tok.requested(); ++p) {
        if (match(*p, target)) // If it applies matching criteria to the two strings
            result = p - r.first; // The index of the found element
        }
    }
}
```

Here, tok.requested() tests whether some other thread has requested this thread to terminate.
stop_token is a mechanism for safety (no data races) running such a request.

### 18.6.1 Cooperative Multitasking

In the first volume of The Art of Programming, Donald Kn praises the usefulness of coroutines. It is a major reason for C++. The keys to such designs are

- Many different coroutines that maintain their state.
- A polymorphism allows us to keep lists of events containing different kinds of coroutines and invoke them independently of their threads.
- A scheduler that selects the next coroutine(s) from the list(s).

Here, I will use couple of coroutines and execute them alternatively. It is essential for such systems not to use too much space. That's why we don't use processes or threads for each. A thread requires a megabyte or two (mostly for the stack), a coroutine often only a couple of dozens. If you need thousands of tasks, that can make a big difference. Context switching between coroutines is also far faster than threads or processes.

First, we need run-time polymorphism to allow us to call dozens or hundreds of different kinds of coroutines uniformly:

```cpp
struct Event_base {
    virtual void operator() = 0;
    virtual ~Event_base() {};
};

template<class Act>
struct Event : Event_base {
    Event(const string n, Act a) : name{ n }, act{move(a) } {}
    string name;
    Act act;
    void operator() override {};
};
```

Here is a trivial use:

```cpp
void test() {
    vector<Event_base> events = {
        new Event("integers", "sequencer(10)\"),
    };
}
```
