## 15.4 Alternatives

The standard offers three types to express alternatives:

| | |
|---|---|
| union | A built-in type that holds one of a set of alternatives (§2.5) |
| variant<T..> | One of specified set of alternatives (in <variant>) |
| optional<T> | A value of T or no value (in <optional>) |
| any | A value of one of an unbounded set of alternative types (in <any>) |

These types offer related functionality to a user. Unfortunately, they don't offer a unified interface.

## 15.4.1 variant

A variant<A,B,C> is often a safer and more convenient alternative to explicitly using a union (§2.5). Possibly the simplest example is to return either a value or an error code:

Click here to view code image

```cpp
variant<string,Error_code> compose_message(istream& s) {
    string message;
    // ... read from s and compose message ...
    if (no_problems)
        return message; // return a string
    else
        return Error_code(some_problem); // return an Error_code
}
```

When you assign or initialize a variant with a value, it remembers the type of that value. Later, we can inquire what type the variant holds and extract the value. For example:

Click here to view code image

```cpp
auto m = compose_message(cin);

if (holds_alternative<string>(m)) {
    cout << get<string>(m);
}
```

```cpp
    auto err = get<Error_code>(m);
    // ...
}
```

This style appeals to some people who dislike exceptions (§4.4), but there are more interesting uses. For example, a simple compiler may not distinguish between kinds of nodes with different representations:

Click here to view code image

```cpp
using Node = variant<Expression,Statement,Type>;

void check(Node* p) {
    if (holds_alternative<Expression>(p)) {
        Expression& e = get<Expression>(p);
        // ...
    }
    else if (holds_alternative<Statement>(p)) {
        Statement& s = get<Statement>(p);
        // ...
    }
}
```

This pattern of checking alternatives to decide on the appropriate action is so common and relatively inconvenient that it deserves direct support:

Click here to view code image

```cpp
void check(Node* p) {
    visit(overloaded {
        [](Expression& e) { // ... },
        [](Statement& s) { // ... },
        // ...
    }, *p);
}
```

This is basically equivalent to a virtual function call, but potentially faster. With all claims of performance, this "potentially faster" should be verified by measurements when performance is critical. The overloaded class is remarkably strange enough, it's a "piece of magic" that builds overloaded set of arguments (usually lambdas):

Click here to view code image

```cpp
template<class... Ts>
struct overloaded : Ts... {
    using Ts::operator()...;
};

template<class... Ts>
overloaded(Ts...) -> overloaded<Ts...>;
// ... deduction
```

## 15.4.2 optional

An optional<> can be a special kind of variant (like variant<A, Nothing>) or as a generalization of the idea of an A either pointing to an object or nullptr. An optional can be useful for functions that may not return an object:

```cpp
optional<string> compose_message(istream& s) {
  string message;
  // read from s and compose message
  if (no_problems)
    return message;
  return {}; // The empty optional
}
```

Given that, we can write

Click here to view code image

```cpp
if (auto m = compose_message(cin))
  cout << m; // Note the dereference (*)
else
  // ... handle error
```

This appears to some people who dislike exceptions (see §4.4). Not use of optional is treated as a pointer to its object rather than the object itself. The optional equivalent to nullptr is the empty object, {}. For example:

Click here to view code image

```cpp
int x = sum(17,19); // 36
int y = sum(17,0); // 17
int z = sum({}); // 0
```

If we try to access an optional that does not hold a value, the result is undefined; an exception is not thrown. Thus, optional is not guaranteed type safe. Don’t try:

Click here to view code image

// ... for trouble
```

## 15.4.3 any

An any can hold an arbitrary type and know which type (if any) it holds. It is basically an unconstrained version of variant:

Click here to view code image

```cpp
any compose_message(istream& s) {
    string message;
    // ... read from s and compose message ...
    if (no_problems)
        return message;
    else
        return error_number(); // return an int
}
```

When you assign or initialize an any with a value, it remembers the type of that value. Later, we can extract the value held by the any by asserting the value's expected type. For example:

Click here to view code image

```cpp
auto m = compose_message(cin);
string& s = any_cast<string>(m);
cout << s;
```

If we try to access an any holding a different type than the expected one, bad_any_access is thrown.
