The >> in Vector<list> terminates the nested template arguments; it is not a misplaced input operator.

To support the range-for loop for Vector, we must define begin() and end() functions:

```
template<typename T>
T begin(Vector<T>& x)
{
    return &x[0]; // pointer to first element or one-past-the-last-element
}
template<typename T>
T end(Vector<T>& x)
{
    return &x[0]+x.size(); // pointer to one-past-the-last-element
}
```

Given those, we can write:

```
void write(Vector<string>& &vs) // Vector of some strings
{
    for (auto &s : vs)
        cout << s << "\n";
}
```

Similarly, we can define lists, vectors, maps (that is, associative arrays), unordered maps (that is, hash tables), etc., we must define size (Chapter 12).

Templates are a compile-mechanism, so they incur no run-time overhead compared to hand-crafted code. In fact, the code generated for Vector<double> is is identical to the code generated for the version of Vector from Chapter 5. Furthermore, the code generated for the standard-library vector<double> is likely to be better (because more effort has gone into its implementation).

A template plus set of template arguments is called an instantiation or a specialization. In the compilation process, at instantiation time, code is generated for each instantiation used in a program ($8.5).
