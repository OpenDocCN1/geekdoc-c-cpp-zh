## 3.3 Namespaces

In addition to functions (§1.3), classes (§2.3), and enumerations (§2.4), C++ offers namespaces as a mechanism for expressing some declarations belong together and their names shouldn't clash with other names. For example, I might want to experiment with my own complex number type (§5.2.1, §17.4):

Click here to view code image

```cpp
namespace My_code {
  class complex {
    // ...
  };

  complex sqrt(complex);
  // ...

  int main();
}

int My_code::main() {
  complex z (1,2);
  auto z2 = sqrt(z);
  std::cout << ' (' << z2.real() << ', ' << z2.imag() << ')';
  // ...
}
```

By putting my code in the namespace My_code, I make sure that my names do not conflict with the standard-library names in namespace std (§3.3). That precaution is wise, because the standard library does not provide support for arithmetic (§5.2.1, §17.4).
The simplest way to access a name in another namespace is to qualify it with the name (e.g., std::cout and My_code::main). The "real main()" is defined in the global namespace, not local to a defined namespace, class, or function.
If qualifying a name becomes tedious or distracting, we can bring the name into a scope with a using-declaration:

[Click here to view image](vector<int>&x, vector<int>& y)

```cpp
void my_code(vector<int>&x, vector<int>& y) {
  using std::swap;
  // ...
  swap(x,y);
  // std::swap();
  other::swap(x,y);
  // Ill other swap()
  // ...
}
```

A using-declaration makes a name from a namespace usable as if it were declared in the scope which it appears. After using std::swap, it is exactly as swap has been declared in my_code(). To gain access to all names in the standard-library namespace, we can use a using-directive:
  using namespace std;

A using-directive makes unqualified names from the named namespace accessible from the scope in which we placed the directive. So after the using-directive for std, we can simply write cout rather than std::cout. For example, we could avoid the repeated std:: qualifications in our trivial vector_printer module:

Click here to view code image

```cpp
export module vector_printer;

import std;
using namespace std;

export
template<typename T>
void print(vector<T> &v) // This is the (only) function seen by users
{
    cout << "in";
    for (const T &val : v) {
        cout << " << " << val << " in";
    }
}
```

Importantly, using of the namespace directive does not affect users of our modules; it is an implementation detail, local to the module.

By using a using-directive, we lose the ability to select us names from namespace, so such facility should be used carefully, usually for a library that's pervasive in an application (e.g., std) or during a transition for an application that didn't use namespaces.

Namespaces are used to organize larger program components, such as libraries. They simplify the composition of a program out of separately developed parts.

## 3.4 Function Arguments and Return Values

The primary and recommended way of passing information from one part of a program to another is through a function call. Information needed to perform a task is passed as arguments to a function and the results produced are passed back as return values. For example:

Click here to view code <int>& v

```cpp
int sum(vector<int>& v)
{
    int s = 0;
    for (const int i : v) {
        s += i;
    }
    return s;
}
```

vector fib = {1, 2, 3, 5, 8, 13, 21};
int x = sum(fib);    // x becomes 53

There are other paths through which information can be passed between functions, such as global variables (§1.5) and shared state in a class object (Chapter 5). Global variables are discouraged as a known source of errors, and state should typically be shared between functions implementing a well-defined abstraction (e.g., member functions of a class; §2.3).

Given the importance of passing information to and from functions, it is not surprising that there are a variety of ways of doing it. Key concerns are:

- Is an object copied shared?
- If an object is shared, is it mutable?
- Is an object moved, leaving an "empty object" behind (§6.2.2)?

The default behavior for both argument passing and return value is "make a copy" (§1.9), but many copies can implicitly be optimized to moves.

In the sum(m) the result is copied out of sum(i) but it would be inefficient and pointlessly copy the very large vector into sum(i); so the argument is passed by reference (indicated by the &; §1.7).

The sum(m) has no reference to modify its argument. This immutability is indicated by declaring the argument const (§1.6), the vector is const-reference.
