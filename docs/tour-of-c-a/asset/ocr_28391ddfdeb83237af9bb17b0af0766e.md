This range concept allows us what to say is sort(v) rather than sort(v.begin(),v.end()) as we had to using the STL since 1994. We can do similarly for our algorithms:

Click here to view forward_range R

```
template<forward_range R>
    requires sortable<iterator<R>>
void my_sort(R& r) // Ill-mod, concept-constrained version of my_sort
{
    return my_sort(r.begin(),r.end()); // Use the 1994-style sort
}
```

Ranges allows us more direct expression of something like 99% of the common uses of algorithms. In addition to the notable advantage, ranges offers some opportunities for optimization and eliminate a class of "silly errors," as sort(v1.begin(),v2.end()) and sort(v2.end(),v1.begin()). Such errors have been seen in "the world."

Naturally, there are different kinds of ranges corresponding to the different kinds of iterators. In particular, input_range, forward_range, bidirectional_range, random_access_range, and contiguous_range are represented as concepts (§14.5).

# 14.2 Views

A view is a way of looking at a range. For example:

Click here to view forward_range auto& r

```
void user(forward_range auto& r)
{
    filter_view v { r, [](int x) { return x%2; } }; // Ill (only) odd numbers from r
    cout << "odd numbers: "
    for (int x : v)
        cout << x << ' \';
}
```

When reading from a filter_view, we read it from the range. If the value matches the predicate, it is returned; otherwise, the filter_view tries again with the element from the range. Many ranges are infinite. We often find only a few values. Consequently, there are views for taking only a few values from a range:

Click here to view forward_range auto& r

```
void user(forward_range auto& r)
{
    filter_view v(r, [](int x) { return x%2; } }; // Ill (only) odd numbers in r
    take_view tv (v, 100); // Ill view at most 100 element from v
    cout << "odd numbers: "
    for (int x : tv)
        cout << x << ' \';
}
```
