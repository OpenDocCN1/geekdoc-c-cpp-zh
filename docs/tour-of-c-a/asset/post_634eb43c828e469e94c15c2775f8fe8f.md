
```cpp
bool operator()(const pair<string,int&>& r) const { return r.second > val; }
```

Alternatively, and equivalently, we could use a lambda expression (§7.3.2):

Click here to view code image

```cpp
auto p = find_if(m, [](const auto& r) { return r.second > 42; });
```

A predicate should not modify the elements to which it is applied.

## 13.5 Algorithm Overview

A general definition of an algorithm is “a finite set of rules which gives a sequence of operations for solving a specific set of problems [and] has five important features: Finiteness ... Definiteness ... Input ... Output ... Effectiveness” [Knuth,1968§1.1]. In the context of the C++ standard library, an algorithm is a function template operating on sequences of elements.

The standard library provides dozens of algorithms. The algorithms are defined in namespace `<algorithm>` and `<numeric>` headers. These standard-library algorithms all take sequences as input. A half-open sequence from b to e is referred as [b:e). Here are a few examples:

## Standard Algorithms <algorithm>

| f=for_each(b,e,f) | For each element x in [b:e) do f(x) |
| p=find(b,e,x) | p is the first p in [b:e) so that "p==x" |
| p=find_if(b,e,f) | p is the first p in [b:e) so that 'f'(p) |
| n=count(b,e) | n is the number of elements 'q' in [b:e) so that "q==x" |
| n=count_if(b,e,f) | n is the number of elements 'q' in [b:e) so that 'f'(q)' |
| replace(b,e,v) | Replace elements 'q' in [b:e) so that "q==v" with v |
| replace_if(b,e,f) | Replace elements 'q' in [b:e) so that 'f'(q)' with v |
| p=copy(b,out) | Copy [b:e) to [out) |
| p=copy_if(b,out) | Copy elements [b:e) from [b:e) so that 'f'(q) to [out) |
| p=move(b,out) | Move [b:e) to [out) |
| p=unique_copy(b,out) | Copy [b:e) to [out); do not copy adjacent duplicates |
| sort(b,e) | Sort elements of [b:e) using the sorting criterion |
| sort(b,e,f) | Sort elements of [b:e) using f as the sorting criterion |
| (p1,p2)=equal_range(b,e,v) | [p1,p2) is the subsequence of the sorted sequence [b:e) with value v; as binary search for v |
| p=merge(b,e,b2,e2,out) | Merge two sorted sequences [b:e) and [b:e2) into [out) |
| p=merge(b,e,b2,e2,out,f) | Merge two sorted sequences [b:e) and [b:e2) into [out) using f as the comparison |

For each algorithm taking a [b:e) range, <ranges> offers a version that takes a range. Please remember (§9.3.2) to use both a traditional iterator version of a standard-library algorithm and its ranges counterpart, you need to either qualify the call or use a using-declaration.

These algorithms, and many more (e.g., §17.3), can be applied to elements of containers, strings, and built-in arrays.

Some algorithms, such as replace() and sort(), modify value elements, but no algorithm adds or subtracts elements of a container. The reason is that a sequence does not identify the container that holds the elements of the sequence. To add or delete elements, you need something that knows about the container (e.g., a back_inserter(); §13.1) or directly refers to the container itself (e.g., push_back() or erase(); §12.2).

Lambdas are very common operations passed as arguments. For example:

Click here to view code image

```cpp
vector<int> v={0,1,2,3,4,5};
for_each(v.begin(),v.end(),[](int &x){x*=x;});
for_each(v.begin(),v.end(),[](int &x){x=sqrt(x);});
```

The standard-library algorithms need to be more carefully designed, and implemented more than hand-crafted loops. Know them and use in preference to bare language.

## 13.6 Parallel Algorithms

When the same task is to do many data items, we can execute it on each data item provided the communications are independent:

- parallel execution: tasks are done on multiple threads (often running on processor cores)
- vectorized execution: tasks are done on a single thread using vectorization, also known as SIMD ("Single Instruction, Multiple Data").

The standard library offers support for both and we can be specific about wanting sequential execution; in `<execution>` namespace:

- seq: sequential execution (feasible)
- par: parallel execution (feasible)
- unseq: unsequenced (vectorized)
- par_unseq: parallel and/or unsequenced execution (feasible). Consider std::sort():

```cpp
sort(v.begin(),v.end());           // sequential
sort(seq,v.begin(),v.end());      // sequential (same as default)
sort(par,v.begin(),v.end());        // parallel
sort(par_unseq,v.begin(),v.end()); // parallel and/or vectorized
```

Whether it is worth to parallelize/vectorize depends on the algorithm, the number of elements in the sequence, the hardware utilization by programs on it. Consequently, the execution policy indicators are just hints. A compiler/or runtime scheduler will decide how much concurrency to use. This is nontrivial and the rule against making statements about efficiency is very important here.

Unfortunately, the parallel algorithms are not yet in the standard, but if we need them, they are easy to define:

Click here to view code image

```cpp
void sort(auto pol, random_access_range& r)
{
  sort(pol.begin(),r.end());
}
```

Most standard-library algorithms, including all in the table except equal_range, can be requested to be parallelized and vectorized using par and unseq. Why far nobody has come up with a parallel algorithm for that? Many numeric data; see §17.3.

## 13.7 Advice

- An STL algorithm operates on one or more sequences; §13.1.
- An input sequence is half-open and defined by a pair of iterators; §13.1.
- You can define your own iterators to serve special needs; §13.1.
- Many algorithms can be applied to I/O streams; §13.3.
- When searching, an algorithm usually returns the end of the input sequence to indicate "not found"; §13.2.
- Algorithms do not directly add or subtract elements from their argument; §13.2.
- When writing a loop, consider whether it could be expressed as a general algorithm; §13.2.
- Use type-aliases to clean up messy notation; §13.2.
- Use predicates and other function objects to give standard algorithms a wider range of meanings; §13.4, §13.5.
- A predicate must not modify its argument; §13.4.
- Know your standard-library algorithms and prefer them to hand-crafted loops; §13.5.

## 14.1 Introduction

The standard-library offers both constrained concepts (Chapter 8) and unconstrained (for compatibility) versions in `<ranges>` namespace ranges. Naturally, I prefer using concepts. A range is a generalization of the C++98 sequences defined by {begin(), end()} pairs; it specifies what it takes to be a sequence of elements. A range can be defined by:

- A (begin, end) pair of iterators
- A (begin, n) pair, where begin is an iterator and n is the number of elements
- A (begin, pred) pair, where begin is an iterator and pred is a predicate; if pred(p) is true for the iterator p, we have reached the end of the range. This allows us to have infinite ranges and ranges that are generated “on the fly” (§14.3).

This range concept allows us to say sort(v) rather than sort(v.begin(),v.end()) as we had to use the STL since 1994. We can do similarly for our algorithms:

Click here to view forward_range R

```cpp
template<forward_range R>
    requires sortable<iterator<R>>
void my_sort(R& r) // concept-constrained version of my_sort
{
    return my_sort(r.begin(),r.end()); // Use the 1994-style sort
}
```

Ranges allow us more direct expression of something like 99% of the common uses of algorithms. In addition to the notable advantage, ranges offer some opportunities for optimization and to eliminate a class of "silly errors," as sort(v1.begin(),v2.end()) and sort(v2.end(),v1.begin()). Such errors have been seen in "the world."

Naturally, there are different kinds of ranges corresponding to the different kinds of iterators. In particular, input_range, forward_range, bidirectional_range, random_access_range, and contiguous_range are represented as concepts (§14.5).

## 14.2 Views

A view is a way of looking at a range. For example:

Click here to view forward_range auto& r

```cpp
void user(forward_range auto& r)
{
    filter_view v { r, [](int x) { return x%2; } }; // odd numbers from r
    cout << "odd numbers: "
    for (int x : v)
        cout << x << ' \';
}
```

When reading from a filter_view, we read it from the range. If the value matches the predicate, it is returned; otherwise, the filter_view tries again with the element from the range. Many ranges are infinite. We often find only a few values. Consequently, there are views for taking only a few values from a range:

Click here to view forward_range auto& r

```cpp
void user(forward_range auto& r)
{
    filter_view v(r, [](int x) { return x%2; } }); // odd numbers in r
    take_view tv (v, 100); // view at most 100 element from v
    cout << "odd numbers: "
    for (int x : tv)
        cout << x << ' \';
}
```

We can avoid naming the take_view by using it directly:

for (int x : take_view(v, 3))
