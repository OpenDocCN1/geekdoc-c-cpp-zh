
Why would we use an array when we use a built-in array? An array knows its size, so it is easy to use with standard-library algorithms, and it can be copied using =. For example:
```
array<int,3> a1 = {1, 2, 3};
a2 = a1; // copy
a2[1] = 5;
a1 = a2; // assign
```

However, my main reason to prefer array is that it saves me from surprising and nasty conversions to pointers. Consider an example involving a class hierarchy:

# Click here to view code image

```
void h()
{
    Circle a1[10];
    array<Circle,10> a2;
    Shape* p1 = a1; // OK: disaster waiting to happen
    Shape* p2 = a2; // Error: no conversion from array<Circle,10> to Shape* (Good)
    p1[3].draw(); // Disaster
}
```

The "disaster" comes because sizeof(Shape) < sizeof(Circle), so subscribing a Circle to a Shape gives a wrong offset. All standard containers provide this advantage over built-arrays.

## 15.3.2 bitset

Aspects of a system, such as the state of an input stream, are often represented as a set of flags indicating conditions such as good/bad, true/on/off. C++ supports the notion of small sets of flags efficiently through bitwise operations on integers (§1.4). bitset<N> generalizes this by providing operations on a sequence of N bits [0:N], where N is known at compile time. For sets of bits that don't fit into a long int (64 bits), using bitset is much more convenient than using integers. For smaller sets, bitset is highly optimized. If you want to name the bits, then you can use a set (§12.5) or enumeration (§2.4).

A bitset can be initialized with an integer or a string:

# Click here to view code image

```
bitset<9> b1("110001111"); // Binary literal using digit separators (§1.4)
bitset<9> b2(0b110001111);
```

The usual binary operators (§1.4) and the left- and right-shift operators (<< >>) can be applied:

# Click here to view code image

```
bitset<9> b3=~1; // complement: b3="001111000"
bitset<9> b4=1&b3; // All zeros
bitset<9> b5=1<<2; // Shift left: b5="000000100"
```

The shift operators (here, <<) "shift" in zeros.

The operations to_ullong(), and to_string() provide the inverse operations to the constructors. For example, we could write the binary representation of an int:

Click here to view code image

```
void binary(int i)
{
    bitset<sizeof(int)> b = i; // assume 8-bit byte (see also $17.7)
    cout << b.to_string() << "\n";
}
```

These bits are presented as 1s and 0s from left to right, with the most significant leftmost, so that argument 123 would give the output

Click here to view code image
00000000000000000000000001111011

For this example, it is simpler to directly use the bitset output operator:

Click here to view code image

```
void binary(int i)
{
    bitset<sizeof(int)> b = i; // assume 8-bit byte (see also $17.7)
    cout << b << "\n";
}
```

A bitset offers many functions for using and manipulating bits, such as all(), any(), none(), count(), flip().

## 15.3.3 pair

It is fairly common for a function to return two values. There are many ways of doing that, the simplest and often best is to define a struct for the purpose. For example, we can return a value and a success indicator.

Click here to view code image

```
struct My_res {
    Entry* ptr;
    Error_code err;
}
```

```
My_res complex_search(vector<Entry>& v, const string& s)
{
    Entry* found = nullptr;
    Error_code err = Error_code::found;
    // ... search for s in v ...
    return (found,err);
}
```

```cpp
void user(const string& s) {
    My_res r = complex_search(entry_table, s); // search entry_table
    if (r.err != Error_code::good) {
        // ... handle error ...
    }
    // ... use r.ptr ...
}
```

We could argue that encoding failure as the end iterator or a nullptr is more elegant, but that can express just one kind of failure. Consequently, we would like to return two separate values. Defining a specific named struct for each pair of values works well and is quite readable if the names of the "pair of values" structs and their members are well chosen. However, for large code bases it can lead to a proliferation of names and conventions, and it doesn't work for generic code where consistent naming is essential.
