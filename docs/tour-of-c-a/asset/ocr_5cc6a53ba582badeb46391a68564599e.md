# 4.1 Introduction

Error handling is a large and complex topic with concerns and ramifications that go far beyond language facilities using programming techniques and tools. However, C++ provides a few features to help. The major tool is the type system itself. Instead of painstakingly building up applications from claims and statements (e.g., char, int, and double) if, while, and for), we build types (e.g., string, map, and thread) and algorithms (e.g., sort(), find_it(), and draw_all()) that are appropriate for our applications. Higher-level constructs simplify our programming, limit opportunities for mistakes (e.g., you are unlikely to try a tree traversal to a dialog box), and increase the compiler's chances of catching errors. The majority of C++ language constructs are dedicated to the design and implementation of efficient and elegant abstractions (e.g., user-defined types and algorithms using them). One effect of using such abstractions is that the point where a run-error can be detected is separated from the point where it can be handled.
