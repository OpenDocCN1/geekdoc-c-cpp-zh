
:elem(new double[s]), sz(s)

That is, we initialize elem to s elements of type double obtained from the free store. Then, we initialize sz to s.
Access to elements is provided by a subscript function, called operator[]. It returns a reference to the appropriate element (a double& allowing both reading and writing).
The size(i) function is supplied to give users the number of elements.
Obviously, error handling is missing, but we'll return to that in Chapter 4. Similarly, we did not provide a mechanism to "give back" to the doubles acquired by new; §5.2.2 shows how to destroy a struct to effectively do that.

There is no fundamental difference between a struct and a class; a struct is simply a class with members public. For example, we can define constructors and other member functions for a struct.

## 2. Enumerations

In addition to classes, C++ supports a simple form of user-defined type for which we can enumerate the values:

Click here to view code image

```cpp
enum Color { red, blue, green };
enum class Traffic { green, yellow, red };
```

```
Color col = Color::red;
Traffic_light = Traffic::light; own```

Note that enumerators, like red, are in the scope of their enum class, so that they can be repeated in enum classes without confusion. For example, Color::red is Color's red which is different from Traffic::red.
Enumerations are used to represent small set of integer values. They are used to make code more readable and less error-prone than it would have had the symbolic (and mnemonic) enumerator names not.

The class specifies that an enumeration is strongly typed and that its enumerators are scoped. By separating types, enum classes help prevent accidental demix of constants. In particular, we cannot mix Traffic_light and Color values.

Click here to view code image

```cpp
Color x = red;
Color y = Traffic_light::red;
Color c23 = Color::red;
auto x24 = Color::red;
```

```
Il error: which red?
Il error that red is not a Color
Il OK
Il OK: Color::red is a Color
```

Similarly, we cannot implicitly mix Color and integer values:

Click here to view code image

```cpp
int i = Color::red;
Color c = 2;
Il error: Color::red is not an int
Il initialization error: 2 is not a Color
```

Catching attempted conversions to enum is a good defense against errors, but often we want to

initialize an enum with a value from its underlying type (by default, that's int), so that it's allowed, as is explicit code conversion from the underlying type:

Click here to view image

```cpp
Color x = Color(5); // OK, verbose
Color y (6);      // also OK
```

Similarly, we can explicitly convert enum value to its underlying type:

```cpp
int x = int(Color::red);
```

By default, an enum class assignment, initialization, and comparisons (e.g., == and <; §1.4) are defined, only once. However, enumeration is a user-defined type, so we can define operators for it (§6.4):

Click here to view image

```cpp
Traffic_light& operator++(Traffic_light& t)    // prefix increment: ++
switch (t) {
    case Traffic_light::green: return t=Traffic_light::yellow;
    case Traffic_light::yellow: return t=Traffic_light::red;
    case Traffic_light::red:   return t=Traffic_light::green;
}
```

```cpp
auto signal = Traffic_light::red;
Traffic_light next += ++signal; // Il becomes Traffic_light::green
```

If the repetition of the enumeration name, Traffic_light, becomes too tedious, we can abbreviate it in a scope:

Click here to view code image

```cpp
Traffic_light& operator++(Traffic_light& t) // prefix increment: ++
switch (t) {
    using Traffic_light; // here, we are using Traffic_light
    case green:  return t=yellow;
    case yellow: return t=red;
    case red:    return t=green;
}
```

If you don't ever want to explicitly enumerate name values, you can remove the class from enum class to get ints (without the need for an explicit conversion), a "plain" enum. The enumerators are entered into the same scope as the name of them enum and implicitly convert to their integer values. For example:

Click here to view code image

```cpp
enum Color { red, green, blue };
int col = green;
```

Here col gets the value 1. By default, the integer values of enumerators start with 0 and increase by one for each additional enumerator. The "plain" enums have been in C++ (and C) since the earliest days, even though they are less well behaved, they are common in current code.

## 2.5 Unions

A union struct in which all members are allocated at the same address so that the union occupies only as much space as its largest member. Naturally, a union can hold a value for only one member at a time. For example, consider a symbol table that holds a name and a value. The value can be either a Node or an int:

Click here to view code image

```cpp
enum class Type { ptr, num }; // Il a Type can hold values ptr and num ($2.4)

struct Entry {
  string name; // Il is a standard-library type
  Type t;
  Node* p; // Il use p if t==Type::ptr
  int i; // Il use i if t==Type::num
};

void f(Entry* pe) {
  if (pe->t == Type::num)
    cout << pe->i;
  // ...
};
```

The members p and i are never at the same time, so space is wasted. It can be easily recovered by specifying that both should be members of a union, like this:

```cpp
union Value {
  Node* p;
  int i;
};
```

Now Value::p and Value::i are placed at the same address of memory of each Value object. This kind of space optimization can be important for applications that hold large amounts of memory so that compact representation is critical. The language doesn't keep track of which kind of value is held by a union, so the programmer must do that:

Click here to view code image

```cpp
struct Entry {
  string name;
  Type t;
  Value v; // Il use v.p if t==Type::ptr; use v.i if t==Type::num
};

void f(Entry* pe) {
  if (pe->t == Type::num)
    cout << pe->v.i;
  // ...
};
```
