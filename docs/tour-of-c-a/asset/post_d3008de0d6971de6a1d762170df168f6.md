
To make literals more readable for humans, we can use a single quote ('') as a digit separator. For example, $\pi$ is about 3.14159'26535'89793'23846'26433'83279'50288 or if you prefer hexadecimal 0x3243F'6A88'85A3'08D3.

## 1.4.2 Initialization

Before an object is used, it must be given a value. C++ offers a variety of notations for expressing initialization, such as the = used, and a universal form based on curly-brace-delimited initializer lists:

Click here to view code image

```
double d1 = 2.3;      ll initialize d1 to 2.3
double d2 = (2.3);      ll initialize d2 to 2.3
double d3 = {2};          ll initialize d3 to 2 (the is optional with { ... })
```

```
complex<double> z = 1;  ll a complex number with double-precision floating-point scalars
complex<double> x = (d1, d2);
complex<double> z3 = {d1, d2};  ll the is optional with { ... }
```

```
vector<int> v = {1, 2, 3, 4, 5, 6}; ll a vector of ints
```

The form is formal and back to C, but if in doubt, use the general }-list form. If nothing else, it saves you from conversions that lose information:

Click here to view code image

```
int i = 7.8;          ll i becomes 7 (surprise?)
int i2 = (7);           ll error: floating-integer conversion
```

Unfortunately, conversions that lose information, are allowed and implicitly applied when you use = (but not when you use {}). And and int to char,). The problems caused by implicit narrowing conversions are a price paid for C compatibility (§19.3). A constant (§1.6) cannot be left uninitialized and a variable should only be left uninitialized in extremely circumstances. Don't introduce a name until you have a suitable value for it. User-defined types (such as string, vector, Matrix, Motor_controller, and Orc_warrior) can be defined to be implicitly initialized ($5.2.1).

When defining a variable, you don't need to state its type explicitly when the type can be deduced from the initializer:

Click here to view code image

```
auto b = true;      // a bool
auto ch = x;       // a char
auto i = 123;       // an int
auto d = 1.2;       // a double
auto z = sqrt(x);   // if the type of whatever sqrt(x) returns
auto bb = (true); // a bool
```

With auto, you can use the = because there is no potentially troublesome type conversion involved, but if you prefer to use {} initialization, you can do that instead.

We use auto where we don't have a specific reason to mention the type explicitly. "Specific reasons":

- The definition is in a large scope where we want to make the type clearly visible by reading of our code.
- The type of the isn't obvious.
- We want to be explicit about a variable's range or precision (e.g., double rather float).

Using auto, avoid redundancy and writing long names. This is especially important in generic programming where the exact type of an object can be hard for the programmer to know and the type names can be quite long ($13.2).

## 1.5 Scope and Lifetime

A declaration introduces its name into a scope:

- Local scope: A name declared in a function ($1.3) or lambda ($7.3.2) is called a local name. Its scope extends from point of its declaration to the end of the block in which it occurs. A block is delimited by a {} pair. Function arguments are considered local names.
- Class scope: A name is called a member name (or class member name) if it is defined in a class ($2.2, $2.3, Chapter 5), outside any function ($1.3), lambda ($7.3.2), or enum class ($2.4). Its scope extends from the opening ({ of its enclosing declaration to the matching).
- Namespace scope: A name is called a namespace name if it is defined in a namespace ($3.3) outside any function, lambda ($7.3.2), class ($2.2, $2.3, Chapter 5), or enum class ($2.4). Its scope extends from the point of declaration to the end of its namespace.

A not declared inside any other construct is called a global name and is said to be in the global namespace. In addition, we can have objects without names, such as temporaries and objects created by new ($5.2.2). For example:

Click here to view code image

```
vector<int> vec; // Il is global (a vector of integers)
void fct(int arg) // Il fct is global (a function)
                   // arg is local (an argument)
```

```
{
    string motto("Who does"); // Il motto is local
    auto p = new Record("Hume"); // Il p points to unnamed Record (created by)
}
```

```
struct Record {
    string name; // Il name is a member
}
```

An object must be constructed (initialized) before it is used and will be destroyed at the end of its scope. For a member, the point of destruction is determined by the point of destruction of the object of which it is a member. An object created by new "lives" until destroyed by delete (§1.7).

## 1.6 Constants

C++ supports two notions of immutability (an object with unchangeable state):

- const: meaning roughly "I promise not to change this value." This is used primarily to specify that data can be passed to functions using pointers and references without fear of it being modified. The compiler enforces this policy by const. The value of const may be calculated at runtime.
- constexpr: meaning roughly "to be evaluated at compile time." This is used primarily to specify constants, to allow placement of data in read-only memory (which is unlikely to be corrupted), and for performance. The value of constexpr must be calculated by the compiler.

For example:

Click here to view code image

```
constexpr int dmv = 17; // Il dmv is a named constant
const int var = 17; // Il var is not a constant
const double sq = sqrt(var); // Il sq is a named constant, possibly computed at runtime
```

```
double sum(const vector<double>& d); // Il sum will not modify its argument (§S1.7)
```

```
vector<double> v = {1, 2, 3, 4, 5}; // Il v is not a constant
const double s1 = sum(v); // Il OK: sum(v) is evaluated at runtime
constexpr s2 = sum(v); // Il error: sum(v) is not a constant expression
```

For a function to be a constant expression, that is, in expression that is evaluated by the compiler, it must be defined constexpr or consteval. For example:

Click here to view code image

```
constexpr double square(double x) { return x*x; }
```
