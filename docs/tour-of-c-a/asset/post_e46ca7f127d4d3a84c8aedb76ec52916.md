## 11.7 Streams

The standard library directly supports

- Standard streams: streams attached to system's I/o streams (§11.7.1)
- File streams: streams attached to files (§11.7.2)
- String streams: streams attached to strings (§11.7.3)
- Memory streams: streams attached to specific areas of memory (§11.7.4)
- Synchronized streams: streams that can be used multiple threads without data races (§11.7.5)

In addition, we can define our own streams, e.g., attached to communication channels. Streams cannot be copied; always pass by reference.

All the standard library templates are templates with their character type as a parameter. The versions with names I use here take chars. For example, ostream<char>. For each stream, the standard library also provides a version for wchar_t. For example, wostream is basic_wostream<wchar_t>. The wide characters can be used for unicode characters.

## 11.7.1 Standard Streams

The standard streams are:

- cout for "ordinary output"
- cerr for unbuffered "error output"
- clog for buffered "logging output"
- cin for standard input.

## 11.7.2 File Streams

In fstream, the standard library provides streams to and from a file:

- ifstreams for reading from a file
- ofstreams for writing to a file
- fstreams for reading from and writing to a file. For example:

Click here to view code image

```cpp
ofstream ofs("target"); // "o" for "output"
if (!ofs)
    error("couldn't open 'target'");
```

Testing that a file has been opened is usually done by checking its state:

Click here to view code image

```cpp
ifstream ifs("source"); // "i" for "input"
if (!ifs)
    error("couldn't open 'source'");
```

Assuming that the tests ofs can be used as an ordinary ostream (just like cout) and ifs can be used as an ordinary istream (just like cin).

File positioning and more detailed control of the way a file is opened is possible, but beyond the scope of this book.

For the composition of file names and file system manipulation, see §11.9.

## 11.7.3 String Streams

In sstream, the standard library provides streams to and from a string:

- stringstreams for reading from a string
- ostringstreams for writing to a string
- stringstreams for reading and writing to a string.

For example:

Click here to view code image

```cpp
void test() {
    ostringstream oss;
    oss << "temperature," << scientific << 123.4567890 << "";
    cout << oss.view() << "in";
}
```

The contents of an ostring can be read using str() (a string copy of the contents) or view() (a string_view of the contents). One common use of an ostring is to format before giving the resulting string to a GUI. Similarly, a string received from GUI can be read using formatted input operations (§11.3) by putting it into an stringstream.

Astringstream can be used for both reading and writing. For example, we can define an operation that can convert any type with a string into another representation that can also be represented as a string:

Click here to view code image

```cpp
template<typename Target=string, typename Source=string>
Target(Source arg) // Convert Source to Target
{
    stringstream buf;
    Target result;

    if (!(buf << arg) // write arg into stream
        || !(buf >> result) // read result from stream
        || (!(buf == std::eof())) // If there is anything left in stream?
            throw runtime_error("to<T>() failed");

    return result;
}
```

A template argument needs be mentioned only if it cannot be deduced or if there is no default (§8.2.4), we can write:

Click here to view code image

```cpp
auto x1 = to<string,double>(1.2); // Il very explicit (and verbose)
auto x2 = to<string>(1.2); // Source is deduced to double
auto x3 = to<int>(1.2); // Target is defaulted to string; Source is deduced to double
auto x4 = to(1.2); // < is redundant;
Target is defaulted to string; Source is deduced to double
```

If all function arguments are deduced, the < can be left out. I consider this a good example of the generality and ease of use that can be achieved by a combination of language features and standard-library facilities.

## 11.7.4 Memory Streams

## 11.9 File System

Most systems have a notion of a file system providing access to permanent information stored as files. Unfortunately, the properties of file systems and the ways of manipulating them vary greatly. To deal with that, the file library in <filesystem> offers a uniform interface. Using <filesystem>, we can partially express file system paths and navigate through file system, examine file types and the permissions associated with this book.

The filesystem library can handle unicode, but explaining how beyond the scope of this book. I recommend using the cppreference [Cppreference] and the Boost filesystem documentation [Boost] for detailed information.

## 11.9.1 Paths

Consider an example:

Click here to view code image

