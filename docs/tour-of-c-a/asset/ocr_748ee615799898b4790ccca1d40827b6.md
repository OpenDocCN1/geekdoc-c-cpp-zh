Many algorithms, most notably sort(), use a swap() function that extends the values of two objects. Such algorithms generally assume that swap() is very fast and doesn't throw an exception. The standard-library provides a std::swap(a,b) implemented as three move operations (§16.6). If you design a type that is efficient to copy and possibly swapped (e.g., by a sort function), then it moves operations or a swap() or both. Note that the standard-library containers (Chapter 12) and string (§10.2.1) have fast operations.

# 6.5.6 hash<>

The standard-library unordered_map<K,V> is a hash table with K as the key type and V as the value type (§12.6). To use a X as a key, we must define hash<X>. For common types, such as std::string, the standard library defines hash<> for us.

# 6.6 User-Defined Literals

One purpose of classes is to enable the programmer to design and implement types to closely mimic built-in types. Constructors provide initialization that or exceeds the flexibility and efficiency of built-in initialization, and for built-in types, we have literals:

+   - 123 is an int.
- 0FF00u is an unsigned int.
- 123.456 is a double.
- "Surprise!" is a const char[10].

It can be useful to provide such literals for a user-defined type also. This is done by defining the meaning of a suitable suffix to a literal, so we can get

+   - "Surprise"s is a std::string.
- 123s is seconds.
- 12.7i is imaginary so 12.7i+47 is a complex number (i.e., (47,12.7)).

In particular, we can get these examples from the standard library by using suitable headers and namespaces:

| Standard-Library Suffixes for Literals |
|---|---|
| <chrono> | std::chrono_literals | h, min, s, ms, us, ns |
| <string> | std::string_literals | s |
| <string_view> | std::string_literals | sv |
| <complex> | std::complex_literals | i, ll, if |

Literals with user-defined suffixes are called user-defined literals or UDLs. Such literals are defined using literal operators.
