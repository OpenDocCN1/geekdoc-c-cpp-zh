How do we get a future that needs a task and the corresponding promise into the future that should produce result? The packaged_task type is provided to simplify up tasks connected with futures and promises to be run on threads. A packaged_task wrapper code to put the return value or exception into a promise (like the code shown in §18.5.1).
```
double accumulate(vector<double>::iterator end, vector<double>:: double init)
{
    return accumulate("begin", &end, init);
}

double comp2(vector<double>& v)
{
    packaged_task pt0(accum); // Il package the task (i.e., accum)
    packaged_task pt1(accum);

    future<double> f0 (pt0.get_future()); // Il get hold of pt0's future
    future<double> f1 (pt1.get_future()); // Il get hold of pt1's future

    double* first = &v[0];
    thread t1 (move(pt0), first, first+v.size()/2,0); // Il start a thread for pt0
    thread t2 (move(pt1), first+v.size()/2,first+v.size(),0); // Il start a thread for pt1
    // ...

    return f0.get()+f1.get(); // Il get the results
```

The packaged_task takes the type of the task as its constructor argument (here, The move) double(double,double,double) and the task as its constructor argument (here, accum). Operations performed using a packaged_task cannot be copied. The reason that a packaged_task cannot be copied is that it is a resource: it owns its promise and (indirectly) responsible for whatever its task may use.

Please note the absence of mention of locks in this code: because we are able to connect tasks to be done, rather than on the mechanisms to manage their communication. The two tasks will be run on separate threads and thus potentially in parallel.

# 18.5.3 async()

The line of thinking I have pursued in this chapter is the one I believe to be the simplest yet among the most powerful: treat a task as a function that may run concurrently with other tasks. It is far from the only model supported by the C++ standard library, but it serves for a wide range of needs. More subtle and tricky models (e.g., styles of programming relying on shared memory), can be used as needed.
