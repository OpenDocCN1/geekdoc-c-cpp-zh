Similarly, istream_iterator is something that allows us to treat an input stream as a read-only container. Again, we must specify the stream to be used and the type of values expected:

Input iterators are used in pairs representing a sequence, we must provide an istream_iterator to indicate the end of the input. This default is istream_iterator:

Typically, istream_iterators and ostream_iterators are not used directly, they are provided as arguments to algorithms. For example, we can write a simple program to read a file, sort the words read, eliminate duplicates, and write the result to another file:

```
int main()
{
    string from, to;
    cin >> from >> to;

    if (ifstream(from)) {
        istream_iterator<string> ii(from);
        istream_iterator<string> eos(cin);
    }

    if (ofstream(to)) {
        ostream_iterator<string> os(to, "\n");


        vector<string> b(ii, eos);
        sort(b);

        unique_copy(b.begin(), b.end(), os);

        returnreturn(b.end()); // os;
    }
}
```

I used the range versions of sort() and unique_copy(). I could have used iterators, e.g., sort(b.begin(),b.end()), which is as common order.

Please remember to use both a traditional iterator version of a standard-algorithm and its counterpart, we need to either qualify the call of the range version or use a using-declaration ($9.3.2):

```
copy(v, oo); // Il potentially ambiguous
ranges::copy(v, oo); // Il OK
using ranges::copy(v, oo); // copy(v, oo) OK from here

```
