# 16.2 Time

In `<chrono>`, the standard library provides facilities for dealing with time:

+   - Clocks, `time_point`, and `duration` for measuring how long some action takes, and as the basis for anything to do with time.
- `day`, `month`, `year`, and `weekday` for mapping `time_points` into our everyday lives.
- `time_zone` and `zoned_time` to deal with differences in time reporting across the globe.
Essentially every system deals with some of these entities.

# 16.2.1 Clocks

Here is the basic way of timing some action:

```
```cpp
using in-namespace std::chrono; see $3.3

auto t0 = system_chrono::now();
do_work();
auto t1 = system_chrono::now();

cout << t1-t0 << ":in";
cout << duration_cast<milliseconds>(t1-t0) << ":ms"; // If unit: 2023[1/1000000]s
cout << duration_cast<nanoseconds>(t1-t0) << ":ns"; // If unit: 2ms2023200ns
```
```

The clock returns a `time_point` (a point in time). Subtracting two points gives a `duration` (a period of time). The various clock types give us measures in various units of time, "clock ticks," (the clock I used measures in hundreds of nanoseconds), so it is often a good idea to convert a `duration` into an appropriate unit. That's what `duration_cost` does.

The clocks are used for quick measurements. Don't make statements about "efficiency" of code without doing measurements. Guesses about performance are unreliable. Simple measurements are better than no measurements, but performance of modern computers is a tricky topic, so we must be careful not to attach too much importance to a few simple examples. Always measure repeatedly to lower the chance of getting blindsided by rare events or cache misses.

Namespace `std::chrono_literals` defines time-suffixes ($6.6). For example:
