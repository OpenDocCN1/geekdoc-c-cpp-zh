
The notation [&int return a<>;] is called lambda expression. It generates a function object similar to Less_than<int>(x). The [&] is a capture list specifying that all names used in the lambda (such as x) will be accessed through references. Had we wanted to "capture" only x, we could have said: [&x]. Had we wanted to give the generated copy of x, we could have said: [x]. Capture nothing is [{}], capture all names used by reference is [&], and capture all names used by value is [=].

For a lambda defined within a member function, [this] captures the current object by reference so that we can access members. If we want a copy of the current object, we can use [*this].

If we want to capture several specific objects, we can list them. The use of [i,this] in the use of expect()(Section 4.5) is an example.

## 7.3.3.1 Lambdas as function arguments

Using lambdas can be convenient and terse, but also obscure. For nontrivial actions (say, more than a simple expression), I prefer to name the operation so more clearly states its purpose and to make it available for use in several places in a program.

In Section 5.5, we noted the advantage of having many functions to perform operations on elements of vectors and unique_ptrs, such as draw_all() and rotate_all(). Function objects (in, lambdas) can help us to separate the traversal of the container from the specification of what is to do with each element.

First, we need a function that performs an operation on the object pointed to by the elements of a container of pointers:

Click here to view code image

```cpp
template<typename C, typename Op>
void for_each(C& c, Op op)
{ // assume that C is a container of pointers (see also 8.2.1)
  for (auto& x : c)
    op(x); // pass op() as a reference to each element pointed to
}
```

This is a simplified version of the standard-library for_each algorithm (Section 13.5).

Now, we can write a version of user(i) from Section 5.5 using a write of _all functions:

Click here to view code image

```cpp
void user()
{
  vector<unique_ptr<Shape>> v;
  while (cin)
    v.push_back(read_shape(cin));
  for_each(v, [](unique_ptr<Shape>& ps) { ps->draw(); }); // draw_all()
  for_each(v, [](unique_ptr<Shape>& ps) { ps->rotate(45); }); // rotate_all(45)
}
```

I pass the unique_ptr<Shape>s to the lambdas by reference. That way for_each() doesn't have to deal with lifetime issues.

Like a function, a lambda can be generic. For example:

Click here to view code image

```cpp
template<class S>
void rotate_and_draw(vector<S>& v, int r)
{
    for_each(v,[](auto& s){ s->rotate(r); s->draw(); });
}
```

Here, in variable declarations, auto means that a value of any type is accepted as an initializer (an argument is considered to initialize the parameter). This makes a lambda with auto parameter template, a generic lambda. When needed, we can constrain the parameter with a concept (Section 8.2). For example, we could define Pointer_to_class rotate * and and write:

Click here to view code image

```cpp
for_each(v,[](Pointer_to_class auto& s){ s->rotate(r); s->draw(); });
```

We can call this generic rotate_and_draw with any container of objects that you can draw and rotate().

Click here to view code image

```cpp
void user()
{
    vector<unique_ptr<Shape>> v1;
    vector<Shape> v2;
    //
    rotate_and_draw(v1,45);
    rotate_and_draw(v2,90);
}
```

For even tighter checking, we define a Pointer_to_Shape concept specifying the properties we want for a type to be usable as a shape. That would allow us to use shapes that aren't derived from class Shape.
