```
constexpr double max1 = 1.4'square(17);
constexpr double max2 = 1.4'square(var);
const double max3 = 1.4'square(var);
```

II OK: 1.4'square(17) is a constant expression
II error: var is not a constant, so square(var) is not a constant
II OK: may be evaluated at run time

A constexpr function can be used for non-constant arguments, but when is the result is not a constant expression. We allow a constexpr function to be called with non-constant-expression arguments in contexts that do not require constant expressions. That, we don't have to define essentially the same function twice: once for constant expressions and once for variables. When we want a function to be used only for evaluation at compile time, we declare it constexpr. For example:

Click here to view code image

```
constexpr double square(double x) { return x*x; }
```

```
constexpr double max1 = 1.4'square(17);
constexpr double max3 = 1.4'square(var);
```

```
II OK: 1.4'square(17) is a constant expression
II error: var is not a constant
```

Functions declared constexpr or const are C++s version of the notion of pure functions. They cannot have side effects and can only use information passed to them as. In particular, they cannot modify non-local variables, but they can have loops and use their own local variables. Example:

Click here to view code image

```
constexpr double nth(double x, int n) // assume <=n
{
    double res = 1;
    int i = 0;
    while (i<n) { // loop: do while the condition is true (§1.7)
        res *= x;
        i++;
    }
    return res;
}
```

In a few places, constant expressions are required by language rules (e.g., array bounds (§1.7), case labels (§1.8), template value arguments (§7.2), and constants declared using constexpr. In other cases, compile-time evaluation is important for performance. Independent of performance issues, the notion of immutability (an object with an unchangeable state) is one of design concern.
