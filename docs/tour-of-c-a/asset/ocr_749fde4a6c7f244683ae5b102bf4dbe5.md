```
R=add_l_reference<T> if T is an lvalue reference, R is T otherwise T&
R=add_r_reference<T> if T is an rvalue reference, R is otherwise T&
R=enable_if_t<b,T,void> if b is false, R is T otherwise R is not defined
R=conditional_t<b,T,U> R if b is true; U other
R=common_type<Ts>... if there is a type that Ts can be implicitly converted to,
R is that type; otherwise R is not defined
R=underlying_type<T> if T is an enumeration, R is its underlying type; otherwise error
R=invoke_result<T,A>... if a T can be called with arguments A..., R is its return type;
therror error
```

These types are properly used in the implementation of utilities, rather than in application code. Of these, enable_if is probably the most common in pre-concepts code. For example, the conditionally enabled -> for a smart pointer is traditionally implemented something like this:

```

// ...
```

# 16.4.4 Associated Types

All standard containers (§12.8) and all containers designed to follow their pattern have some associated types such as value types and iterator types. In <iterator> and <ranges>, the standard library names for those:

| Selected Type Generators |
|---|---|
| range_value_t<R> | The type of range R's elements |
| iter_value_t<T> | The elements pointed to by the iterator T |
| iterator_t<R> | The type of the range R's iterator |
