# Combined pages release

When the system needs to free a virtual address, it first locates the address of the PTE that maps it. The pointed PFN of a combined page has the prototype and combined bits set. The free request for a combined PFN is managed exactly like that for a prototype PFN. The only difference is that the system (if the combined bit is set) calls DecreCombinedPte after processing the prototype PFN.

DecrementCombinedPte is a simple function that decrements the reference count of the combine block of the Prototype PTE. (Keep in mind that at this stage the PTE is transition because the memory manager has already dereferenced the physical page that it maps. The share count of the physical page has already dropped to zero, so we put the PTE in transition.) If the reference count drops to zero, the prototype PTE will be freed, the physical page put in the free list, and the combine block returned to the combine free of the PCS structure of the memory partition.

# Memory enclaves

Threads executing in an enclave have access to process space. Intel has created a technology called Software Guard Extensions (SGX) that allows the creation of enclaves—secure zones in a process where code and data are protected from code outside the enclave. Conversely, code running inside the enclave has full access to process space. A simplified diagram of enclaves is shown in Figure 5-49.

![](img/ff0e6a9d867a3a6e9527eb1d946810fc_483_0.png)

FIGURE 5-49 Memory enclaves.

Intel SGX is supported by sixth generation processors (Skylake) and later, and is available on Windows 7 and later systems (64 bit only). Not all sixth generation Core processors support SGX. Also, an appropriate BIOS update must be installed on the system for SGX to work. Consult the Intel SGX documentation for more information. The Intel SGX website can be found at https://software.intel.com/en-us/sgx.

- Note At the time of this writing, Intel produced two versions of SGX (versions 1.0 and 2.0). Windows currently supports version 1.0. The differences are outside the scope of this book; consult the SGX documentation for more information.
- Note Current SGX versions do not support enclaves in ring 0 (kernel mode). Only ring 3 (user mode) enclaves are supported.

# Programmatic interface

From an developer's perspective, creating and working with an enclave consists of the following steps. (The internal details are described in the following sections.)

- 1. Initially the program should determine whether enclaves are supported by calling IsEnclaveType, passing a value representing the enclave technology, which currently can only be ENCLAVE_TYPE_SGX.
- 2. A new enclave is created by calling the CreateEnclave function, which is similar in its arguments to VirtualAlloc. For example, it is possible to create an enclave in a different process than the caller process. The complication in this function is the need to provide a vendor-specific configuration structure, which for Intel means a 4 KB data structure SGX Enclave Control Structure (SECS), which Microsoft does not define explicitly. Instead, developers are expected to create their own structure based on the particular technology used and defined in its documentation.
- 3. Once an enclave is created, the next step is to populate the enclave with code and data from outside the enclave. This is accomplished by calling LoadEnclaveData where an external memory to the enclave is used to copy data to the enclave. Multiple calls to LoadEnclaveData may be used to populate the enclave.
