# Prioritization strategies

Internally, the five I/O priorities are divided into two I/O prioritization modes, called strategies. These are the hierarchy prioritization and the idle prioritization strategies. Hierarchy prioritization deals with all the I/O priorities except Very Low. It implements the following strategy:

+   - All-critical I/O must be processed before any high-priority I/O.
- All high-priority I/O must be processed before any normal-priority I/O.
- All normal-priority I/O must be processed before any low-priority I/O.
- All low-priority I/O is processed after any higher-priority I/O.

As application generates I/Os, IRPs are put on I/O queues based on their priority, and the hierarchy strategy dictates the ordering of the operations.

The idle prioritization strategy, on the other hand, uses a separate queue for non-idle I/O. Because the system processes all prioritized I/O before idle I/O, it's possible for the I/Os in the queue to be served, as long as there's even a single non-idle I/O on the system in the hierarchy strategy queue.

To avoid this situation, as well as control back-off (the sending rate of I/O transfers), the idle strategy uses a timer to monitor the queue and guarantee that at least one I/O is processed per unit of time (typically, half a second). Data written using non-idle I/O also causes the cache manager to write directly immediately and bypass its read-ahead head read operations that would otherwise preemptively read the file being accessed. The prioritization strategy also waits for 50 milliseconds after the completion of the last non-idle I/O in order to issue the next I/O. Otherwise, idle I/Os would occur in the middle of non-idle streams, causing costly seeks.

User-mode applications can set I/O priority on three different objects. The functions SetPriorityClass (with the PROCESS_MODE_BACKGROUND_BEGIN value) and SetThreadPriority (with the THREAD_MODE_BACKGROUND_BEGIN value), set the priority for all the I/Os generated by either the process or specific threads (the priority is stored in the IRP of request). These functions work on the current process or thread and lower the I/O priority to Very Low. In addition, these also lower the scheduling priority to 4 and the memory priority to 1. The function SetFileInformationHandle can set the priority for a specific file object (the priority is stored in the file object). Drivers can also set I/O priority directly on an IRP by using the IoSetPriority API.
