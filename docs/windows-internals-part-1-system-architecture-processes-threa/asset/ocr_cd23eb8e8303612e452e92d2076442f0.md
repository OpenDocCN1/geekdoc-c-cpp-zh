With the PFN initialized, the system PTE is converted to a global kernel PTE, and its result- ing virtual address is computed. The final step in MiCreateEnclave is to call KeCreateEnclave, which will now do the low-level kernel creation steps, communicating with the actual SGX hardware implementation. One job that KeCreateEnclave is responsible for filling in the base address required by the SECS structure if the caller did not specify one, it must be set in the SECS structure before communicating with the SGX hardware to create an enclave.

# # Loading data into an enclave

Once an enclave has been created, it's time to load information into it. The LoadEnclaveData func- is exposed for that purpose. The function merely forwards the request to the underlying executive function, NtLoadEnclaveData. The function performs a combination of memory copy operation over virtuala11alloc attributes (such as page protection).

If the enclave created with CreateEnclave doesn't have any committed enclave pages, they must first be obtained, which will result in zero memory added to the enclave, which can then be filled with non-zero memory from outside the enclave. Otherwise, if an initial pre-committed initialization size was passed, then the enclave's pages can be directly filled in non-zero memory from outside of the enclave.

Because enclave memory is described by a VAD, may the traditional memory management APIs will function, at least partially, on this memory well. For example, calling Virtuala11alloc using NtAllocateVirtualMemory on an address with the MEM_COMMIT flag will result in MiCommEn-clavePages being called, which will validate that the protection for the new pages is compatible (i.e., a combination of read, write, and/execute, without any special caching or writing flags), and then call MiAddPagesToEnclave, passing a pointer to the enclave VAD associated with the address range, the protection mask that was specified to Virtuala11alloc, and the PTE addresses that correspond to the virtual address range being committed.

MiAddPagesToEnclave checks if the VAD has any EPC pages associated with it, and if there are enough of them to satisfy the commit. If MiReserveEnclavePages is called to obtain a sufficient amount, MiReserveEnclavePages looks at the current enclave page list and counts the total. There aren't enough physical EPC pages provided by the processor (based on the information obtained at boot), the function fails. Otherwise, it calls MiGetEnclavePage in a loop for the required amount of pages.

For each PFN that is retrieved, it is linked to the PFN array in the enclave VAD. Essentially, this means that once an enclave PFN is removed from the enclave page list and into the enclave, into an active state, the enclave VAD acts as the list of active enclave PFNs.

Once the required committed pages have been obtained, MiAddPagesToEnclave translates the page post to LoadEnclaveData into its SGX equities. Next, it reserves the appropri-ate number of system PTEs to hold paging information for each EPC pages that will be required. With this information in hand, it will eventually call AddEnclavePage that calls the SGX hardware to do the actual page adding.
