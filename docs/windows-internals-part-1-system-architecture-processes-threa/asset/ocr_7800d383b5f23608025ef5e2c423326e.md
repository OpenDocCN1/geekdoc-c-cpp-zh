The dispatcher ready queues (Readl isHead in KSHRED_READY_QUEUE) contain the threads that are in the ready state, waiting to be scheduled for execution. There is one queue for each of the 32 priority levels. To speed up the selection of which thread to run or preempt, Windows maintains a 32-bit bitmask called the ready summary (ReadySummary). Each bit sets one or more threads in the ready queue for priority (bit 0 represents priority 0, bit 1 priority 1, and so on).

Instead of scanning each ready list to see whether it is empty or not (on the number of different priorities), a single scan is performed as a native processor to find the highest bit set. Regardless of the number of threads in the ready queue, this operation takes a constant amount of time.

The dispatcher database is synchronized by raising IRQL to DISPATCH_LEVEL(2). (For an explanation of interrupt priority levels, or IRQLs, see Chapter 6). Raising IRQL in this process prevents other threads from interrupting the dispatcher processor because threads run normal at IRQL 0 or 1. However, more is required than just raising IRQL, other processors can simultaneously raise to the same IRQL and attempt to operate on their dispatcher database. How Windows synchronizes the dispatcher database is explained later in this section "Multiprocessor systems."
