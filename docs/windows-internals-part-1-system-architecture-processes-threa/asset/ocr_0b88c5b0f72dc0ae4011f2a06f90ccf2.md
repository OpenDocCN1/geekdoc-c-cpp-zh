# Silo monitors

If kernel drivers have the capacity to add their own silos, how do they know which ones are executing, and what new silos are created as containers? The answer lies in the silo monitor facility, which provides a set of APIs to receive notifications when a silo is created and/ terminated (PsRegisterSiloMonitor, PsStartMonitor, PsUnregisterSiloMonitor), as well as notifications for already-existing silos. Each silo monitor can retrieve its own silo index by calling PsInsertSiloContext, PsRePlaceSiloContext, and PsRemoveSiloContext functions. Additional slots can be allocated with PsAllSiloContextSlot, but this would be only needed if a component wanted to store contexts for some reason.
