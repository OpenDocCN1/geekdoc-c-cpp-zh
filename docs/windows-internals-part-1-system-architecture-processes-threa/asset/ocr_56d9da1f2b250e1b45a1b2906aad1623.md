10. Rt1CloneUserProcess finishes by calling Rt1CreateUserProcess, the user-mode function responsible for general creation, passing flags that indicate the new process should be a clone of the current one. Rt1CreateUserProcess in turn calls ZwCreateUserProcess to request the kernel to create the process.

When creating a cloned process, ZwCreateUserProcess executes most of the code paths as when it creates a new process, with the exception PsAllocateProcess, which it calls to create the process object and initial thread, calls calls MmInitializeAddressSpace with a flag specifying that the address should be a copy-on-write copy of the target process instead of an initial address space. The memory manager uses the same space it provides for the Services for Unix Applications to efficiently clone the address space. Once the target process continues execution, any changes it to its address space are seen only by it, not the clone. This enables the clone's address space to represent a consistent point-in-time view of the target process.

The clone's execution begins at the point after the return from Rt1CreateUserProcess. If the clone's creation is successful, it returns the STATUS_PROCESS_CLONED code, whereas the cloning thread then synchronizes with the target and, at last calls a function optionally passed to Rt1CreateProcessReflection, which performs analysis of the process and reports the results back to the thread that calls Rt1CreateProcessReflection. If no function failed, the thread suspends or terminates, depending on the flags passed to Rt1CreateProcessReflection.

When RAD and WDI process reflection, asking for the function to return a handle to the cloned process and for the clone to suspend itself after it has initialized, they generate a dump of the target process, which suspends the target for the dump generation. Next, they generate a more comprehensive dump of the cloned process. After they generating the dump of the clone, they terminate the clone. The target process can execute during the time window between the minidump's completion and the creation of the clone, but for most scenarios any inconsistencies do not interfere with troubleshooting. The Procdump utility from Sysinternals also follows these steps when you specify the -r switch to create a reflected dump of a target process.

# Conclusion

This chapter examined how the Windows memory manager implements virtual memory management. With as most modern operating systems, each process is given access to a private address space, protecting one's process memory from another by allowing processes to share memory efficiently and securely. Advanced capabilities, such as the inclusion of mapped files and the ability to sparsely allocate memory, are also available. The Windows environment subsystem makes most of the memory manager's capabilities available to applications through the Windows API.
