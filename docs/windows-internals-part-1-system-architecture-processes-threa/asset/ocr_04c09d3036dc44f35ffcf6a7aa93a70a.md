The preceding experiment shows some of the anomalies associated with the idle process and its threads. The debugger indicates an Image name of Idle (which comes from the EPROCESS structure) but Windows utilities report the idle process using different names. Task Manager and Process Explorer call it System Process, while it calls System Process. The process ID and thread IDs (the client IDs, or Cid in the debugger's) are 0, as the PEB and TEB pointers and potentially other fields in the idle process or its threads. Because the idle has no user-mode address space and its threads execute no user-mode code, they have no need of the various data required to manage a user-mode environment. The idle process is an object manager object, and its threads are statically allocated used to bootstrap the system before the process manager and the object manager are initialized. Subsequent idle thread structures are allocated dynamically (simple allocations from a non-paged pool, bypassing the object manager) as Once process management initializes, it uses the special variable PsIdProcess to report the idle process.
