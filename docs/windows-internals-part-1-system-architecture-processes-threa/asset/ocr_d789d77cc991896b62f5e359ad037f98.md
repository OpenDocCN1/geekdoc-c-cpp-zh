The modified page writer writes on two events: the first is an Exit event, and the second in MiSystemPartition.Modifier.ModifiedPageWriterEvent(on Windows 8.x and Server 2012/R2) on a kernel gate stored in MiModifiedPageWriterGate, which can be signaled in the following scenarios:

+   - A request to flush all pages has been received.

+   - The number of available pages—stored in MiSystemPartition.Vp.AvailablePages(MnAvailablePages on Windows 8.x and Server 2012/R2)—drops below 128 pages.

+   - The size of the zeroed and free pages below 20,000, and the number of modified pages destined for the paging file is the smaller of one-sixteenth of the available pages or 64 MB (16,384 pages).

+   - When a working set is being trimmed to accommodate additional pages, if the number of available pages is less than 15,000.

+   - During a list operation (MiInsertPageList). This routine signals event if the number of page-file-destined pages on the modified page list has reached more than 16 pages and the number of available pages has fallen below 1,024.

Additionally, the modified page writer writes on two other events after the preceding event is signaled. One is used to indicate rescanning of the paging file is required (for example, a new page may have been created), stored in MiSystemPartition.Modifier.RescanPageFilesEvent(RescanPageFilesEvent on Windows 8.x and Server 2012/R2). The second event is internal to the paging file header (MiSystemPartition.Modifier.PagingFileHeader[MnPagingFileHeader on Windows 8.x and Server 2012/R2]), which allows the system to manage request flush out of the paging file when needed.

When invoked, the modified page writer writes as many pages as possible to disk with a single I/O request. It accomplishes this by examining the original PTE of the PFN database for pages on the modified page list to locate locations on the disk. Once a list is created, the pages are removed from the modified list, an I/O request is issued, and at successful completion of the I/O request, the pages are placed at the tail of the standby list corresponding to their priority.

Pages that are in the process of being written can be referenced by another thread. When this happens, the reference count and the share count in the entry that represents the physical page are incremented to indicate that another process is using the page. When the I/O operation completes, the modified page writer notices that the reference count is no longer 0 and does not place the page on any standby list.
