

# 第 4 阶段：创建初始线程及其栈和上下文

此时，Windows 内内核进程对象已完全建立。然而，它还没有线程，因此目前还无法执行任何操作。现在是开始这项工作了。通常情况下，`PspThread` 例程负责线程创建的所有方面，并在创建新线程时由 `NtCreateThread` 调用。然而，由于初始线程是由内核通过用户态输入内部创建的，`PspThread` 依赖的两个辅助函数变为：`PspAllocateThread` 和 `PspInsertThread`。`PspAllocateThread` 处理内核对象本身的实际创建和初始化，而 `PspInsertThread` 则处理线程和安全属性的创建，并调用 `KeStartThread` 将内核对象转换为系统中可调度的线程。尽管如此，线程还不会做任何事情。它是以挂起状态创建的，直到进程完全初始化（如第 4 阶段）后才会被恢复。

> 注意：线程参数（在 `CreateProcess` 中无法指定但在 `CreateThread` 中可以指定）是 PEB 的地址。该参数将由在新线程上下文中运行的初始化代码（第 6 阶段描述）使用。

`PspAllocateThread` 执行以下步骤：

- 1. 防止在 Wow64 进程中创建用户态调度（UMS）线程，并防止用户态调用者在系统进程中创建线程。
- 2. 创建并初始化内核线程对象。
- 3. 如果系统启用了能量估计（XBOX 始终禁用），则为内核对象中分配并初始化一个 `Thread_ENERGY_VALUE` 结构。
- 4. 初始化 LPC、I/O 管理和内核使用的各种列表。
- 5. 设置线程创建时间，并创建其线程 ID (TID)。
- 6. 在线程执行之前，它需要一个栈和一个运行所需的上下文，因此会设置这些内容。初始线程的栈大小从镜像中获取；无法指定其他大小。如果是 Wow64 进程，还将初始化 Wow64 线程上下文。
- 7. 为新线程分配线程环境块 (TEB)。
- 8. 将用户态线程起始地址存储在 `THREAD`（在 `StartAddress` 字段）中。这是 `Ntdll.dll` 中系统提供的线程启动函数（`LtlUserStart`）。用户的 Windows 起始地址存储在 `THREAD` 的另一个位置（`Win32StartAddress` 字段），以便像 Process Explorer 这样的调试工具显示这些信息。
- 9. 调用 `KeInitThread` 设置 `KTHREAD` 结构。初始线程的当前优先级设置为进程优先级，其亲和性设置为进程亲和性。`KeInitThread` 随后为线程分配内核栈，并初始化线程的机器硬件上下文，包括上下文、陷阱和异常帧。
- 设置线程上下文，以便线程将在 `KiThreadStartup` 中以内核模式启动。最后，`KeInitThread` 将线程状态设置为 `Initialized`（已初始化）并返回到 `PspAllocateThread`。
- 10. 如果是 Ums 线程，则调用 `PspmsInitThread` 初始化 Ums 状态。

一旦完成这些工作，`NtCreateProcess` 调用 `PspInsertThread` 执行以下步骤：

- 1. 如果使用属性指定了线程理想处理器，则初始化它。
- 2. 如果使用属性指定了线程组亲和性，则初始化组亲和性。
- 3. 如果进程是作业（Job）的一部分，将进行检查以确保线程的组亲和性不违反作业限制（前文描述）。
- 4. 进行检查以确保进程尚未终止、线程尚未终止，或者线程尚未开始运行。如果其中任何一项为真，线程创建将失败。
- 5. 如果线程是安全进程 (IUM) 的一部分，则创建并初始化安全线程对象。
- 6. 通过 `KeStartThread` 初始化线程的 `KTHREAD` 对象。这涉及从所有者进程继承调度设置、设置理想节点和处理器、更新组亲和性、设置基本和动态优先级（通过从进程拷贝）、设置线程量子，并将线程插入到 `KPROCESS` 维护的进程列表中（与 `EPROCESS` 中的列表分开的）。
- 7. 如果进程处于深度冻结状态（这意味着不允许线程运行，包括新线程），则该线程也被冻结。
- 8. 在非 x86 系统上，如果该线程是进程中的第一个（且进程不是空闲进程），则将进程插入到全局变量 `KiProcessListHead` 维护的另一个系统级进程列表中。
- 9. 进程对象中的线程计数，并继承所有者进程的 I/O 优先级和年龄优先级。如果这是该进程拥过的最高线程数，则也会更新线程计数高水位。如果这是进程中的第二个线程，则主令牌（primary token）被冻结（即它不再能更改）。
- 10. 将线程插入进程的线程列表，如果创建者有要求，则挂起该线程。
- 11. 将线程对象插入进程句柄表。
- 12. 如果是进程中创建的第一个线程（即操作是作为 `CreateProcess` 调用的一部分发生的），将调用所有注册的进程创建的回调。然后调用所有注册的线程的回调。如果任何回调否决了创建，则操作将失败并向调用者返回适当的状态。
- 13. 如果提供了作业列表（使用属性）且该线程是进程中的第一个线程，则将进程分配给作业列表中的所有作业。
- 14. 通过调用 `KeReadyThread` 使线程准备好执行。它进入延迟就绪状态。（有关线程状态的更多信息请参见第 4 章。）

# 第 5 阶段：执行 Windows 子系统特定的初始化

一旦 `CreateUserProcess` 返回成功代码，必要的内核进程和线程对象已经创建。`CreateProcessInternal` 执行与 Windows 子系统特定操作相关的各种操作以完成进程初始化。

- 检查 Windows 是否允许运行可执行文件。这些检查包括验证头中的镜像版本，并检查 Windows 是否通过组策略阻止了该进程。在 Windows Server 2012 R2 的特殊版本中（如 Windows Storage Server 2012 R2），还会检查应用程序是否导入了任何不允许的 API。
- 如果适用限制策略，将为新进程创建一个受限令牌。之后，查询应用程序兼容性数据库以查看注册表或系统应用程序数据库中是否存在该进程的项。此时不会应用兼容性 shim；信息将存储在初始线程开始执行的 PEB 中（第 6 阶段）。
- `CreateProcessInternal` 调用某些内部函数（针对非保护进程）获取 SxS 信息（更多信息请参阅本章的“DLL 名称解析和重定向”部分），如清单文件和 DLL 重定向路径，以及其他信息，例如 EXE 所在的媒体是否为可移动设备以及安装程序标志。对于沉浸式进程（immersive processes），它还从包清单中返回版本信息和目标平台。

根据收集的信息构建发送给 Csrss 的 Windows 子系统消息。消息包含以下信息：

- 路径名和 SxS 路径名
- 进程和线程句柄
- 区域句柄
- 访问令牌句柄
- 媒体信息
- AppCompat 和 shim 数据
- 沉浸式进程信息
- PEB 地址
- 表示是否为保护进程或是否需要提升权限运行的各种标志
