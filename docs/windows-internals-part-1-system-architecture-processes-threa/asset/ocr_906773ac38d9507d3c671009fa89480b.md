# Loader interaction with CFG

Although it is the memory manager that builds the CFG bitmap, the user-mode loader (see Chapter 3 for more information) serves two purposes. The first is to dynamically enable CFG support only if the feature is enabled (the caller may have requested CFG for the child process, or the process itself might not have CFG support). This is done by LdpCfgProcessLoadConfig function, which is called to initialize CFG for each loaded module. If the module D11Characteristics flags in the optional header of the PE does not have the CFG flag (DLL_CHARACTERISTICS_CFG), the GuardFlags member of IMAGE_LOAD_CONFIG structure does not have the IMAGE_GUARD_CF_INSTRUMENTED flag, and the kernel has forcibly turned off CFG for this process, then there is nothing to do.

Second, if the module needs, LdpCfgProcessLoadConfig gets the index checking function retrieved from the image (the GuardCFDispatchFunctionPointer member of IMAGE_LOAD_CONFIG_DIRECTORY structure) and sets it to either LdpValidateUserCallTarget in Ntdll, depending on whether export suppression is enabled. Additionally, the function first makes sure the pointer has not been somehow modified to point outside the module.

Furthermore, if improved CFG was used to compile this binary, a second indirect routine is available, called the dispatch CFG route. It is used to implement the enhanced flow flow earlier. If the image includes a function pointer (in the GuardDispatchFunctionPointer member of the aforementioned structure), it is initialized to LdpDispatchUserCallTarget, or LdpDispatchUserCallTarget if export suppression is enabled.

> Note In some cases, the kernel can emulate or perform indirect jumps or calls on behalf of user mode. In situations where there is a possibility, the kernel implements its own MmValidateUserCallTarget routine, which performs the same as LdpValidateUserCallTarget.

The code generated by the compiler when CFG is enabled enables an indirect call that lands in the LdpValidateUserCallTarget(ES) or LdpDispatchUserCallTarget(ES) in Ntdll. This function uses its own target address and checks the best value for the function:

+   * If the state is (0, 0), the dispatch is potentially invalid.
* If the state is (1, 0), and the address is 16-byte aligned, the dispatch is valid. Otherwise, it is potentially invalid.
* If the state is (1, 1), and the address is not 16-byte aligned, the dispatch is valid. Otherwise, it is potentially invalid.
* If the state is (0, 1), the dispatch is potentially invalid.
