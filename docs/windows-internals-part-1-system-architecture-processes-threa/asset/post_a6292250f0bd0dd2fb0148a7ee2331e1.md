
## Examining memory usage

The Memory and performance-counter categories de-facto provide access to most of the details about system and process memory utilization. Throughout this chapter, we'll include references to specific performance counters that contain information related to the component being described. We've included relevant examples and experiments throughout the chapter. One word of caution, however: Different utilities vary and sometimes use inconsistent or confusing names when describing memory information. The following experiment illustrates this. (We'll explain the terms used in subsequent sections).

## EXPERIMENT: Viewing system memory information

The Performance tab in the Windows Task Manager, shown in the following screenshot from Windows 10 1607 system (click the Memory tab on the left in the Performance tab), displays basic system memory information. This is a subset of the detailed memory information available through performance counters. It includes data on both physical and virtual memory. The table that follows shows the meaning of the memory-related values.

### Task Manager Value

The chart's height reflects physical memory in use (not available as performance counter). The area above the line is equal to the Available value in the bottom section. The total height of the graph is equal to the total value at the top right of the graph (9 GB in this example). This represents the total RAM used by the operating system, and does not include shadow pages.

Memory usage details the relation between memory that is actively used, modified, and free (all described in this chapter).

### Memory composition

Total physical memory (top right of graph) shows physical memory usable by Windows.

### Use (Compressed)

This is the physical memory currently used. The amount of compressed memory is in parentheses. Hovering over the value shows the amount of memory saved (Memory compression is discussed later in section "Memory compression").

### Cached

This is the sum of the following performance counters: Cache Bytes, Modified List Bytes, Standby Cache Bytes, and Reserve Cache Bytes.

### Available

This is the amount of memory immediately available for use by processes and drivers. It is equal to the combined size of standby, free and zero list.

### Free

This shows the free and zero list size. To see this information, hover over the rightmost part (assuming you have enough memory to hover over it).

### Committed

The numbers shown here are equal to the values in Committed and Limit counters respectively.

### Paged Pool

This is the total size of paged pool, including both free and allocated regions.

### Non-Paged Pool

This is the total size of non-paged pool, including both free and allocated regions. To see the specific usage of paged and non-paged pool, use Poolmon utility described later in "Pool usage".

## Services provided by the memory manager

| Category | Description |
| :--- | :--- |
| Virtual | The lowest-level API for general memory allocations and deallocations. It always works on page granularity. |
| Heap | Provides functions for small allocations (typically less than a page). It uses the Windows API internally but adds management on top of it. |
| Local/Global | Leftovers from 16-bit Windows; now implemented using the Heap API. |
| Memory-mapped files | Allow mapping files as memory/or sharing memory between cooperating processes. |

The memory manager provides a set of services to allocate and free virtual memory, share memory between processes, map files into memory, flush virtual pages to disk, retrieve information about a range of virtual pages, change the protection of virtual pages, and lock the virtual pages into memory.

Like other executive services, memory-management services allow their caller to supply a process handle indicating the particular memory is to be manipulated. The caller can manipulate either its own memory (with proper permissions) the memory of another process. For example, if a process creates a child process, by default it has right to manipulate the child's virtual memory. Thereafter, the parent process can allocate, deallocate, and write memory on behalf of the child by calling virtual memory and passing a handle to the child process as an argument. This feature is used by subsystems to manage the memory of their client processes. It is also essential for implementing debuggers because debuggers must be able to read and write to the memory of the process being debugged.

## Internal synchronization

The memory manager uses several internal mechanisms to ensure thread safety on multiprocessor systems. Some of the resources requiring synchronization include:

- Working set lock: This is held while changes are made to the working set.
- Address space lock: This is held whenever the address space is changed.

Both these locks are implemented using spinlocks. These are described in Chapter 8.
