# EXPERIMENT: Viewing basic heap information

In this experiment, we'll examine some heaps of a UWP process.

+   1. Using Windows 10, run the Windows calculator. (Click the Start button and type Calculator to find it.)

+   2. The calculator in Windows 10 has been turned into a UWP app (Calculator.Exe). RunDbg and attach to the calculator process.

+   3. Once attached, WinDbg breaks into the process. Issue the !heap command to get a quick summary of heaps in the process:

```
0033> !heap
Heap Address NT/Segment Heap
2531eb9b0000 Segment Heap
2531eb980000 NT Heap
2531eb10000 Segment Heap
25320a4000 Segment Heap
253215a0000 Segment Heap
253214f0000 Segment Heap
2532eb70000 Segment Heap
25326290000 Segment Heap
253215d0000 NT Heap
```

+   4. Notice the various heaps with their handle and type (segment or NT). The first heap is the default process heap. Because it is growable and not using any preexisting memory block, it is created as a segment heap. The second heap is used with a user-defined memory block (described earlier in the "Process heaps" section). Because this feature is currently unsupported by the segment, it's created as an NT heap.

+   5. An NT heap is managed by the Ntdll!HEAP_structure. Let's view the structure for the second heap:
