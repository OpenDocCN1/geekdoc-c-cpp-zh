+   4. The last step that is required to “activate” the enclave is achieved with the InitializeEnclave function. At that point, code that was configured to execute within the enclave can start executing.

+   5. Unfortunately, executing the code in the enclave is not wrapped by the API. Direct use of assembly language is required. The ENTER instruction forces execution to the enclave and the EXIT instruction returns to the calling function. Abnormal termination of the enclave is also possible with Asynchronous Enclave Exit (AEX), such as a fault. The exact details are beyond the scope of this book, as they are not Windows-specific. Consult the SGX document to get the final details.

+   6. Finally, to destroy the enclave, a normal VirtualFree (Ex) function can be used on the pointer to the enclave obtained in CreateEnclave.

# # Memory initializations

During boot, Winload (the Windows Boot Loader) calls Os1EnclavePageRegions, which first checks if SGX is supported by the CPUID. If it is, it issues instructions to enumerate Enclave Page Cache (EPC) descriptors. EPC is the protected memory provided by the processor for paging and enclaves. For each enumerated EPC, Os1EnclavePageRegions calls BMm-AddEnclavePageEnclaveMemory to add the page range to a sorted list of memory descriptors of type Loader_PARAMETER_BLOCK This list is eventually stored in the MemoryDescriptorListHeader of the LOADER_PARAMETER_BLOCK structure used to pass information from the boot loader to the kernel.

During phase 1 initialization, the memory manager CreateEnclaveRegions is called to create an AVL tree for the discovered enclave regions (allowing lookups when needed); the tree is stored in the MiState.Hardware.Enclave data. The kernel obtains a new enclave page list, a special flag to InsertPageFreeOrZeroList enables functionality to utilize this list. However, since the memory manager has no list of identifiers (3 are used for a maximum of 8 values, all taken), the kernel actually identifies these pages as “bad” pages currently suffering an in-page error. The memory manager never to use bad pages, calling enclave pages “bad” from being used by normal memory management operations, and so such pages end up in the bad page list.

# # Enclave construction

The CreateEnclave API ends calling NtCreateEnclave in the kernel. As noted, a SECS structure must be passed in, designed by Intel SGX in Table 5-24.

NtCreateEnclave first checks if memory enclaves are supported by looking at the AVL tree (not by using the CPUID instruction). It creates a copy of the passed-in structure (as is usual for kernel functions obtaining data from user) and attaches to the target process (KeStackAttachProcess) if the enclave is created in a different process than the caller’s. Then it transfers control to MiCreateEnclave to begin the actual work.
