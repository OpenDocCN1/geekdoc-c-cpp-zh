In addition to supporting alternative credential providers, LogonUI can load additional network provider DLLs that need to perform secondary authentication. This capability allows multiple network providers to gather identification and authentication information all at one during normal logon. A user logging on to a Windows system might simultaneously be authenticated on a Linux server. A user would then be able to access resources of the UNIX server from the Windows machine without requiring additional authentication. Such a capability is known as one of single sign-on.

# Winlogon initialization

During system initialization, before any user applications are active, Winlogon performs the following steps to ensure it controls the workstation once the system is ready for user interaction:

+   1. It creates and opens an interactive window station (for example, \Sessions\WindowsStation in the object manager to represent the keyboard, mouse, and monitor. Winlogin creates a security descriptor for the station that has one and only one ACE containing only the system SID. This unique security descriptor ensures that no other process can access the workstation unless explicitly allowed by Winlogon.

+   2. It creates and opens two desktops: an application desktop (\Sessions\WindowsWinSta0\Default, also known as the interactive desktop) and desktop (\Sessions\WindowsWinSta0\Winlogin, also known as the Secure Desktop).
