PsMakeSiloContextPermanent APIs are "permanent" silo contexts, which are not reference counted\and are not tied to the lifetime of the server silo or the number of silo contexts gets. Once inserted,
silo contexts can be retrieved by PsGetSiloContext and/or PsGetPermanentSiloContext.

# EXPERIMENT: Silo monitors and contexts

To understand how silo monitors are used, and how they silo contexts, let's take a look
at the Ancillary Function Driver for Winsock (Afd.sys) and its monitor. First, let's dump the data
structure that represents the monitor. Unfortunately, it is not in the symbol files, so we must do
this as raw data.

```
lkd> dps poi(afdAfdPodMonitor)
ffff387*a97c12f0 ffff387*a7d760c0
ffff387*a97c12f8 ffff387*a7b54b60
ffff387*a97c1390 000000101
ffff387*a97c13c8 ffff387*be4b5b10 afd!AfdPodSiloCreateCallback
ffff387*a97c1440 ffff387*be4e40 afd!AfdPodSiloTerminateCallback
```

Now get the slot (9 in example) from the host silo. Silos store their SLS in a field called
Storage, which contains an array of structures (slot entries), each storing a pointer, and some
flags. We are multiplying the index by 2 to get the offset of the right slot entry, then accessing
tnext field (+1) to get the pointer to the context pointer:

```
lkd> r?@$0 = (nt!ERSVERSILO_GLOBALS*)@masm(nt!PspHostSiloGlobals)
lkd> ?? (void**))@$0->Storage) [9 = 2 + 1]
void == 0xffff888f*ab185941
```

Note that the permission flag (0x2) is ORed into the pointer, mask it out, and then use the
!object extension confirm that this is a silo context.

```
lkd> !object(0xffff888*ab185941 & -2)
Object: fffff88fab185940 Type: (ffff888faac9f20) PsSiloContextNonPaged
```
