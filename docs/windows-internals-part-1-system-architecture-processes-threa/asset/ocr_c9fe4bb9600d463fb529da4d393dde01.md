called LogonUI.exe. When Winelog detects the SAS, it launches this process, which initializes the credentials. When the user enters their credentials (required by the provider) or dismisses the login interface, LogonUI.exe process terminates. Winelog.exe can also load additional network provider DLLs that need to perform secondary authentication. This allows multiple network providers to gather identification and authentication information all at one time during normal login.

After the user name and password (or another information bundle as the credential provider) has been captured, they are sent to the Local Security Authentication Service process (Lass.exe, described in Chapter 7) to be authenticated. Lass.exe calls the appropriate authentication package, implemented as a DLL, performs the actual verification, such as checking whether a password matches is stored in the Active Directory or the SAM (part of the registry that contains the definitions of the local users and groups). Lass.exe will communicate with the Isolated LSA Trustlet (Laiso.exe, described in Chapter 7) to obtain the machine key required to authenticate the legitimacy of the authentication request.

Upon successful authentication, Lass.exe calls a function in the SRM (for example, NtCreateToken) to generate an access token that contains the user's security profile. If User Account Control (UAC) is used and the user logging on is a member of the administrators group his.exe will create a second, restricted version of the token. This access token is then used by Winelog to create the initial process(es) in the user's session. The initial process(es) are stored in the User registry value under the HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Windows registry key. The default is User.exe, but there can be more than one in it.

Userit.exe performs some initialization of the user environment, such as running the login script and reestablishing network connections. It then looks in the registry at the Shell1 value (the same Winelog mentioned previously) and creates a process to run the system-defined shell (by default, Explorer.exe). Then Userit exits. This is why Explorer is shown with no parent. Its parent isn't running. As detailed and explained in Chapter 1. Another way of looking at it is that Explorer is the grandchild of Winelog.

Winelog.exe is not active during user logging in, but also when it intercepts the SAS from the keyboard. When you press Ctrl+Alt+Delete while logged in, the Windows Security screen comes up, providing the options to log off, start the Task Manager, lock the workstation, shut down the system, and so forth. Winelog.exe and LogonUI.exe are the processes that handle this interaction.
