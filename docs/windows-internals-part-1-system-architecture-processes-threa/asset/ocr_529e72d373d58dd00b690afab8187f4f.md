4. Click the **Leak Paged** button. This causes Notfault to begin sending requests to the Myfault device driver to allocate page pool. Myfault will continue sending requests until you click the **Stop Paged** button. Paged pool is not normally released when you close a program that has caused it to occur (interacting with a buggy device driver). The pool is permanently leaked until you reboot the system. However, to make testing easier, the Myfault device driver detects that the process was closed and frees its memory allocations.

5. While the pool is leaking, open Task Manager, click the **Performance** tab, and select the **Memory** label. Notice the **Paged Pool** value climbing. You can also check this with Process Explorer's System Information display (select the **View** menu, choose **System Information**, and click the **Memory** tab).

6. To determine which pool is leaking, run Pool and press the **B** key to sort by the number of bytes.

7. Press **P** twice so that Pool shows only paged pool. Notice the Leak pool tag climbing to the top of the list. (Pool shows changes to pool allocations by highlighting the lines that change.)

8. Click the **Stop Paged** button so that you don't exhausted page pool on your system.

9. Using the technique described in the previous section, run Strings (from Sysinternals) to look for driver binaries that contain the Leak pool tag. This should display a match on the Myfault.sys root, confirming that the driver uses the Leak pool tag.

```
Strings %SystemRoot%\system32\drivers\*.sys | findstr Leak
```
