
## TABLE 7-20 Process mitigation options (continued)

| Mitigation Name | Use Case | Enabling Mechanism |
| :--- | :--- | :--- |
| Disable Extension Points | This prevents a process from loading an input method (IME), a Windows DLL (SetWindowsHook), an initialization DLL (AppInitDll) in the registry, or a Windows layered service provider (LSP). | This is set with SetMitigationPolicy or the PROCESS_CREATION, MITIGATION_POLICY_EXTENSION, POINT_DISABLE_ALWAYS_ON_process-executable flag. |
| Arbitrary Code Guard (CFG) | This prevents a process from executing code or from permission of executing executable code to make writable. It can be configured to allow a parallel thread inside the process to request this capability or to allow a remote process from disabling this mitigation, which are not supported from a security point of view. | This is set with SetMitigationPolicy or the PROCESS_CREATION, MITIGATION_POLICY_PROHIBIT_DYNAMIC_ALWAYS_ON_PROCESS_MITIGATION_PROHIBIT_DYNAMIC_ALWAYS_ON_process-executable flag. |
| Control Flow Guard (CFG) | This helps prevent memory corruption vulnerabilities from using hijacked control flow by validating the CALL or JMP instruction against a list of valid expected target functions. Part of Control Flow Integrity (CFI) mechanisms described in the next section. The image must be compiled with /guard:cf and linked with the Option. The image does not support enforcement for other images loading in the process. It can be set with the PROCESS_CREATION_MITIGATION_POLICY_CONTROL_FLOW_GUARD_ALWAYS_ON flag. |
| CFG Export Suppression | This strengthens by suppressing indirect calls to the exported API table of the image. | The image must be compiled with /guard:exportsuppress, and can also be configured through SetMitigationPolicy or with the PROCESS_CREATION, MITIGATION_POLICY_CONTROL_FLOW_GUARD_EXPORT_SUPPRESSION-process-attribution flag. |
| CFG Strict Mode | This prevents the loading of any image library within the current process that was not linked with the /guard:cf option. | This is set with SetMitigationPolicy or the PROCESS_CREATION, MITIGATION_POLICY_STRICT_CONTROL_FLOW_GUARD_ALWAYS_ON-process-attribution flag. |
| Disable Non System Fonts | This prevents the loading of any font files that have not been registered by Win Logon at user login time, after being installed in the C:\windows\fonts directory. | This is set with SetMitigationPolicy or the PROCESS_CREATION, MITIGATION_POLICY_FONT_DISABLE_ALWAYS_ON-process-attribution flag. |
| Microsoft-Signed Binaries Only | This prevents the loading of any image library within the current process that has not been signed by a Microsoft CA—issued certificate. | This is set with SetMitigationPolicy or the PROCESS_CREATION, MITIGATION_POLICY_BLOCK_NON_MICROSOFT_BINARIES_ALWAYS_ON-process-attribute flag at startup. |
| Store-Signed Binaries Only | This prevents the loading of any library within the current process that has not been signed by the Microsoft Store CA. | This is set through the PROCESS_CREATION_MITIGATION_POLICY_NON_MICROSOFT_BINARIES_ALLOW_STORE_attribute flag at startup time. |
| No Remote Images | This prevents the loading of any image within the current process that is present on a non-local (UNC or WebDAV) path. | This is set through SetProcessMitigationPolicy or the PROCESS_CREATION_MITIGATION_POLICY_LOAD_REMOTE_ALWAYS_ON process-creation attribute. |
| No Low IL Images | This prevents the loading of any library within the current process that has a mandatory label below medium (0x2000). | This is set through SetProcessMitigationPolicy or the PROCESS_CREATION_MITIGATION_POLICY_LOAD_LOW_LABEL_ALWAYS_ON process-creation. It can also be set through a resource claim ACE IMAGED on the file of the process being loaded. |
| Prefer System32 Images | This modifies the search path to always look for the library (through a relative name) in the %SystemRoot%\System32, regardless of the current path. | This is set through SetProcessMitigationPolicy or the PROCESS_CREATION_MITIGATION_POLICY_LOAD_PREFER_SYSTEM32_ALWAYS_ON process-creation attribute. |
| Return Flow Guard (RFG) | This helps prevent classes of memory-corruption vulnerabilities that affect control flow by validating, before the execution of a function called through return-oriented programming (ROP) exploit by hindering its execution or by executing on an invalid stack. This is part of the Control Flow Integrity (CFI) mechanisms. | Currently being implemented in a robust and performant way, this mitigation is not yet available, but is included here for completeness. |
| Restrict Set Thread Context | This restricts the modification of the current thread's context. | Currently disabled preventing the availability of sigma, which makes the mitigation more robust, this mitigation may appear in a future version of Windows. It is included here for completeness. |
| Loader Continuity | This prohibits the loading of any DLLs that do not have the same integrity level as the process, in cases where a signature policy might be enabled at startup time due to compatibility concerns. This specifically targets cases of DLL planting attacks. | This is set through SetProcessMitigationPolicy or the PROCESS_CREATION_MITIGATION_POLICY_2_LOADER_INTEGRITY_CONTINUITY_ALWAYS_ON process-creation attribute flag. |
| Heap Term On Corruption | This disables the Fault Tolerant Heap (FTH) and the raising of a continual exception in the case of heap corruption terminating instead. This prevents the use of heap corruption as a way to force an attacker-controlled exception handler from executing, or in cases the program ignores the heap exception, or cases the exploit only causes heap corruption (limiting its universal effectiveness or reliability). | This is set by using HeapSetInformation or by using the PROCESS_MIGATION_POLICY_HEAP_TERMINATE_ALWAYS_ON process-creation attribute flag. |
| Disable Process Creation | This prohibits the creation of child processes by marking the token with a special restriction, which should stop any other component from creating a process while respecting this (for example, WMI process creation, or a kernel creating the process). | This is set by the PROCESS_CHILD_PROCESS_RESTRICTED attribute flag. It can be overridden to allow packages with the PROCESS_CREATION_DESKTOP_APP_OVERRIDE flag. |
| All Applications Policy | This makes an application running under an AppContainer unable to access resources unless it have an APPLICATION PACKAGES SID present, as explained in section. The presence of an ALL RESTRICTED APPLICATION PACKAGES SID will be required-sometimes referred to as Less Privileged App Container (LPAC). | This is set by the PROCESS_THREAD_ATTRIBUTE_APPLICATION_PACKAGES_POLICY process-creation attribute. |

Note that it is also possible to enable some of these mitigations on a per-application or per-system basis without the cooperation of the application developer. To do so, use the Local Group Policy Editor. Then expand Computer Configuration, then Administrative Templates, then System, and Mitigation Options (see Figure 7-30). In the Process Mitigation Options dialog, enter the appropriate bit value that corresponds to the mitigations being enabled, using 1 to enable a mitigation, 0 to disable it, or 7 to leave it to its default or process-requested value (again, see Figure 7-30). The bit numbers are taken from the PROCESS_MITIGATION_POLICY enumeration found in the Winnt header file. This will result in the appropriate registry value being written in the File Execution Options (IFEO) key for the entered image name. Unfortunately the current version of Windows 10 Creators Update and earlier will strip out many of the newer mitigations. You can avoid this by manually setting the REG_DWORD MitigationOptions registry value.
