With process reflection, the target process is suspended long enough to generate a suspended cloned copy of the target, and the larger dump that captures all of a process's valid user-mode memory can be generated from the clone while the target is allowed to continue execution.

Several Windows Diagnostic Infrastructure (WDI) components use of process reflection to capture memory dumps of processes when their heuristics identify suspicious behavior. For example, the Memory Leak Diagnoser of Windows Resource Exhaustion Detection and Reporting (also known as RADAR), generates a reflected dump of a process that appears to be leaking virtual memory so it can be sent to Microsoft via Windows Error Reporting (WER). WDI's hung process heuristic does the same for processes that appear to be deadlocked on one another. Because these components use heuristics, they can't be certain the processes are faulty and therefore can't suspend them for long periods of time or terminate.

The RtCreateProcessReflection function in Ntdll.dll drives the implementation of process reflection. It works as follows:

+   1. It creates a shared memory section.
2. It populates the shared memory section with parameters.
3. It maps the shared memory section into the current and target processes.
4. It creates two event objects and duplicates them into the target process so that the current process and target process can synchronize their operations.
5. It injects a thread into the target process via a call to RtCreateProcessReflectionUserThreadEx. The thread is directed to begin execution in Ntdll.dll's Rt1ProcessReflectionStartup function. (Because Ntdll.dll is mapped at the same address (randomly generated at boot) into every process's address space, the current process can simply pass the address of the function it obtains from its own Ntdll.dll mapping.
6. If the caller of RtCreateProcessReflection specified that it wants a handle to the cloned process, RtCreateProcessReflection waits for the remote thread to terminate, otherwise it returns to the caller.
7. The injected thread in the target process allocates an additional event object that it will use to synchronize with the cloned process after it's created.
8. The injected thread calls Clone, passing parameters it obtains from the memory mapping it shares with the initiating process.

If the RtCreateProcessReflection option specifies the creation of the clone when the process is not executing in the loader, performing heap operations, modifying the process environment block (PEB), or modifying fiber-local storage is present, then RtCreateProcessReflection acquires the associated locks before continuing. This can be useful for debugging because the memory dump's copy of the data structures will be in a consistent state.
