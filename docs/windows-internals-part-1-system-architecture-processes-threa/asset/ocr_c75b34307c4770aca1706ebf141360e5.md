The driver used for Process Explorer and Process Monitor from Sysinternals are good examples of that as is the console driver (Condrv.sys) mentioned earlier.

+   - Functions that can be called only from kernel mode that are exported and documented in the WDK include various support routines, as the I/O manager (start with Io), general executive functions (Ex) and more, needed for device developers.

+   - Functions that are exported and can be called from kernel mode but are not documented in the WDK include the functions that called by the boot driver, which start with Dmv.

+   - Functions that are defined as global symbols are not exported These include internal support functions within Ntoskrnl.dll, as those that start with Io (internal I/O manager) or Mi (internal memory management functions).

+   - Functions that are internal to a module that are not defined as global symbols These functions are used exclusively by the executive and kernel.

The executive contains the following major components, each of which is covered in detail in a subsequent chapter of this book:

+   - Configuration manager The configuration manager, explained in Chapter 9 in Part 2, is responsible for implementing and managing the system registry.

+   - Process manager The process manager, explained in Chapter 3 and Chapter 4, creates and terminates threads. The underlying support for processes and threads is implemented in the Windows kernel; the executive adds additional semantics and functions to these lower-level objects.

+   - Security Resource Monitor (SRM) The SRM, described in Chapter 7, enforces security policies on the local computer. It guards OS resources, performing runtime-object protection and auditing.

+   - I/O manager The I/O manager, discussed in Chapter 6, implements device-independent I/O and is responsible for dispatching to the appropriate device drivers for further processing.

+   - Plug and Play (PnP) manager The PnP manager, covered in Chapter 6, determines which drivers are required to support a particular device and loads those drivers. It retrieves the hardware resources for each device, the PnP manager assigns the appropriate hardware resources as I/O ports, IRQs, DMAs, and memory locations. It is also responsible for sending proper notification for device changes (the addition or removal of a device) on the system.

+   - Power manager The power manager (explained in Chapter 6), processor power management (PPM), and power management framework (PoFx) coordinate power management I/O notifications to device drivers.
