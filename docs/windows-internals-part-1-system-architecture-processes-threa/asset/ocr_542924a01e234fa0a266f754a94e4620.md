# Fast fail/security assertion codes

Because the __fail intrinsic contains an argument that is bubbled up to the exception record or crash screen, it fails failing to identify which part of the system or process is not working correctly or has encountered a security violation. Table 7-22 shows the various failure conditions and their meaning or significance.

TABLE 7-22 __fastfail failure codes

| Code | Meaning |
| --- | --- |
| Legacy OS Violation (0x0) | An older buffer security check present in a legacy binary has, and has been converted to a security assertion. |
| V-Table Guard Failure (0x1) | The Virtual Table Guard Mitigation in Internet 10 and higher has encountered a corrupted function pointer. |
| Stack Check Cookie Failure (0x2) | The stack check generated with the /GS compiler option (also called a stack canary) has been corrupted. |
| Corrupt List Entry (0x3) | One of the markers for manipulating LIST_ENTRY structures has an inconsistent linked list, where the grandparent or child entry does not point to the parent or child entry of the item being manipulated. |
| Incorrect Stack (0x4) | A user-mode or kernel-mode API that is often potentially called from ROP-based exploits while operating on an attacker-controlled stack has been called, and the stack is not the expected one. |
| Invalid Argument (0x5) | A user-mode CRT API (typically) or other sensitive function has been called with an invalid argument, suggesting potential ROP-based use or another corrupted stack. |
| Stack Cookie Init Failure (0x6) | The initialization of the stack cookie has failed, suggesting image patching or corruption. |
| Fatal App Exit (0x7) | The application has used the FastAppExit user-mode API, which has been converted into a security assertion to guard it advantages. |
| Range Check Failure (0x8) | Additional checks in fixed array buffers to check if the array element is within expected bounds. |
| Unsafe Registry Access (0x9) | A kernel-mode driver is attempting to access registry data from a user-controlled mode (such as an API or user hive) and is not using RTL_REGISTRY_TYPECHECK to protect itself. |
| CFG Indirect Call Failure (0xA) | Control Guard fails an indirect CALL or J instruction to an address that is not a valid dispatch for the CFG bitmap. |
| CFG Write Check Failure (0xB) | Control Guard with write protection has detected an invalid write to protected data. This feature (/guard=cf) is not supported outside of Microsoft. |
| Invalid Fiber Switch (0xxC) | The SwitFiber API is used on an invalid fiber or from a thread which has not been converted to a fiber. |
| Invalid Fiber Set Context (0xD) | An invalid context structure was detected while attempting to restore it (due to an exception or SetThreadContext API), where the stack pointer is not valid. Checked only when CFG is active on the process. |
| Invalid Reference Count (0xE) | A reference counted object (such as the OBJECT_HEADER in kernel-mode or a Win32 sys GDI object) has underflow its reference count below 0 or overflow its maximum capacity back to 0. |
| Invalid Jump Buffer (0x12) | A longjmp is attempted with a jump buffer that contains an invalid stack address or invalid instruction pointer. Checked only when CFG is active on the process.
