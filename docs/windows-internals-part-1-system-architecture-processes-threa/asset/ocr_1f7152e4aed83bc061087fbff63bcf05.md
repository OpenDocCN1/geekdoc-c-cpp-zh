Finally, in the IoT world, certain standard PC hardware such as the Intel controller may not be present and require support for a different controller, even on PC-based systems. Older versions of Windows handled this by forcing each vendor to ship a custom HAL for each possible platform combination. This is not realistic, and results in significant amounts of duplicated code. Windows now supports modules known as HAL extensions, which are additional DLLs on disk that the boot loader may require if hardware requirement is needed during configuration. Your desktop Windows 10 system is likely to include a HalExtPl080.dll and HalExtinctClpDDMA.dll, the latter of which is used in certain low-power IoT platforms, for example.

Creating HAL extensions requires collaboration with Microsoft, and such files must be signed with a special HAL extension available only to hardware vendors. Additionally, they are highly limited in the APIs they can use and interact through limited import/export table mechanism that does not use the traditional PE image mechanism. For example, the following experiment will not show any functions if you try to use it on a HAL extension.
