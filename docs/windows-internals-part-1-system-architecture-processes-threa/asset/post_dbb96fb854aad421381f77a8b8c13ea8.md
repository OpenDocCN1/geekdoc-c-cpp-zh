
Finally, this intermediate Smss.exe process exits, leaving the subsystem processes and Winlogon or Wininit as parent-less processes.

## Windows initialization process

The Wininit.exe process performs the following system initialization functions:

- 1. It marks itself and the main thread critical so that if it exits prematurely and the system is booted in debugging mode, it will break into the debugger. (Otherwise, the system will crash).
- 2. It causes the process to treat errors as critical, such as invalid handle and heap corruption.
- 3. It initializes support for state separation, if the SKU supports it.
- 4. It creates an event Global\First\LogonCheck (this can be observed in Process Explorer or WinObj during the BaseNamedObjects directory) for use by Winlogon processes to detect which Winlogon is first to launch.
- 5. It creates a winlogoff event in the BaseNamedObjects manager directory to be used by Winlogon instances. This event is signaled (set) when a logon operation starts.
- 6. It increases its own process base priority to high (13) and its main thread's priority to 15.
- 7. Unless unconfigured otherwise with the NoDebugThread registry value in the HKLM\Software\Microsoft\Windows\NT\CurrentVersion\Winlogon key, it will break into any user-mode process as specified by the kernel debugger. This enables kernel debuggers to cause Winlogon to attach and break into other user-mode applications.
- 8. It sets the machine name in the environment variable COMPUTERNAME and then updates and creates TCP/IP-related information such as the domain and host name.
- 9. It sets the default profile environment variables USERPROFILE, ALLUSERS, PUBLIC, and ProgramData.
- 10. It creates the temp directory by expanding %SystemRoot%\Temp (for example, C:\Windows\Temp).
- 11. It sets up font loading and DWM if session 0 is an interactive session, which depends on the SKU.
- 12. It creates the initial terminal, which is composed of a window station (always named Win0) and two desktops (Login and Default) for processes to run in session 0.
- 13. It initializes the LSA encryption key, depending on whether it's stored locally or if it must be entered interactively. See Chapter 7 for information on how authentication keys are stored.
- 14. It creates the Service Control Manager (SCM or Services.exe). See the upcoming paragraphs for a brief description and Chapter 9 in Part 2 for more details.
- 15. It starts the Local Security Authentication Subsystem (lsass.exe), and Credential Guard is enabled, the Isolated LSA Trustlet (lsais.exe) requires querying the VBS provisioning from UEFI. See Chapter 7 for more information on Lass.exe and lsais.exe.
- 16. If Setup is currently pending (that, if this is the first boot during a fresh install or an update to a new major OS or Insider Preview), it launches the setup program.
- 17. It waits forever for a request for system shutdown or for one of the aforementioned system processes to terminate (unless the DontWaitSysPros registry value is set in the Winlogon key mentioned in step 7). In either case, it shuts down the system.

## Service control manager

Recall that with Windows, services can refer to either a server process or a device driver. This section deals with services that are user-mode processes. Services like Linux daemon processes in that can be configured to start automatically at system boot without requiring an interactive logon. They can also be started manually, by running the Services administrative tool, using the sc.tool, or calling the WindowsStart function. Typically, services do not interact with the logged-on user, although there are special conditions when this is possible. Additionally, others can run in special service accounts (such as SYSTEM or LOCAL SERVICE), others can run with the same security context as logged-in users. (For more, see Chapter 9 in Part 2.)

The Control Manager (SCM) is a special system process that manages %SystemRoot%\System32\Services responsible for starting, stopping, and interacting with service processes. It is also a protected process, making it difficult to tamper with. Service programs are really just Windows that call special functions to interact with the SCM to perform actions as registering the service's successful startup, responding to status requests, or pausing or shutting down the service. Services are defined in the registry under HKLM\SYSTEM\CurrentControlSet\Services.

Keep in mind that services have three names: the process name you see on the system, the internal name in the registry, and the display name shown in the Services administrative tool. (Not all services have a display name—if a service does not have a display name, the internal name is shown.) Services can also have a description field that details what the service does.

To map a service process to the services contained in that, use the tlist /s (from Debugging Tools for Windows) or tasklist /svc (built-in Windows) command. Note that there isn't always one-to-one mapping between service processes and running services, however, some services share a process with other services. In the registry, the Type value under the service's key indicates whether the service runs in its own process or shares a process with other services in the image.

A number of Windows components are implemented as services, such as the Print Spooler, Event Log, Task Scheduler, and various networking components. For more details on services, see Chapter 9 in Part 2.

## Winlogon, LogonUI, and Userinit

The Windows logon process (%SystemRoot%\System32\Winlogon.exe) handles interactive user logons and logoffs. Winlogon.exe is notified of a user logon request when the user enters the attention sequence (SAS) keyboard combination. The default SAS on Windows is Ctrl+Alt+Delete.

The identification and authentication aspects of the logon process are implemented through DLLs called **credential providers**. The standard credential providers implement the default Windows authentication interfaces: password and smartcard. Windows 10 provides a biometric provider: face recognition, known as **Hello**. However, developers can provide their own credential providers to implement other identification and authentication mechanisms instead of the Windows user name/password method, such as one based on a voice print or biometric device such as a fingerprint reader. Because Winlogon.exe is a critical system process on which the system depends, credential providers and the UI to display the logon dialog box run inside a child process of Winlogon.exe.
