## Dispatcher database

To make scheduling decisions, the kernel maintains a set of data structures known collectively as the dispatcher database. The dispatcher database keeps track of which threads are waiting and which processors are executing.

To improve scalability including thread concurrency, Windows multiprocessor systems have per-processor dispatcher queues and shared processor queues as illustrated in Figure 4-9. In this way, each CPU can check its own shared ready queue for the next thread to run without having to lock the system-wide ready queues.

![](img/ff0e6a9d867a3a6e9527eb1d946810fc_245_0.png)

FIGURE 4-9 Windows multiprocessor dispatcher database (This example shows six processors. P represents processes; T represents threads.)

Windows versions prior to Windows 8 and Windows Server 2012 use per-processor ready queues and a per-processor ready summary which were stored as process control block (PRCB). To see the fields in the PRCB, use !pcb in the kernel debugger. Starting Windows 8 and Windows Server 2012, a shared ready queue and ready summary are used for groups of processors. This enables the system to make better decisions about which processor to use for that group. The per-CPU ready queues are still there for threads with affinity constraints. Because the shared data structure must be protected (by a spinlock), the group should not be too large. In the current implementation, the maximum group size is four processors. If the number of processors is greater than four, more groups would be created and the available processors spread evenly. For example, on a six-processor system, groups of three processors would be created. The ready queues, ready summary (described next), and some other information is stored in kernel structure named KSHARED_READY_QUEUE that is stored in the PRCB. Although it exists for every processor, it's used only on the first processor of each group, sharing it with the rest of the processors in that group.

The dispatcher ready queues (Head in KSHARED_READY_QUEUE) contain the threads that are in the ready state, waiting for execution. There is one queue for each of the 32 priority levels. Windows maintains a 32-bit bitmask called the ready summary. Each bit sets one or more threads in the ready queue (bit 0 represents priority 0, bit 1 priority 1, and so on). Instead of scanning each ready list to see whether it is empty, a single scan is performed as a native processor to find the highest bit set. Regardless of the number of threads in the ready queue, this operation takes a constant amount of time. The dispatcher database is synchronized by raising IRQL to DISPATCH_LEVEL (2). For an explanation of interrupt levels, IRQLs, see Chapter 6. Raising IRQL in this process prevents other threads from interrupting the dispatcher because threads run at normal IRQL (0 or 1). However, more is required than just raising IRQL, other processors can simultaneously raise to the same IRQL and attempt to operate on their dispatcher database. How Windows synchronizes the dispatcher database is explained later in the section "Multiprocessor systems."
