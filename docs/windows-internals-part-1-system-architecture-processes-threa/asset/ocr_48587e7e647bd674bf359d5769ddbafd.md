Shared pages are usually mapped to a view of a section. In this turn is part or all of a file, but may instead represent a portion of page space. All shared pages can potentially be shared with other processes. Sections are exposed in the Windows API as file-mapping objects.

When a shared page is first accessed by any process, it will be read from the associated mapped file unless the section is associated with the paging file, in which case it is created as a zero-initialized page. Later, if it is still resident in physical memory, the second and subsequent processes accessing it simply use the same page contents that are already in memory. Shared pages might have been prefetched by the system.

Two upcoming sections of this chapter, "Shared pages and mapped files" and "Section objects," go into much more detail about shared pages. Pages are written to disk through a mechanism called modified page writing. This occurs as pages are moved from a process's working set to a system-wide list called the modified page list. From there, they are written to disk or remote storage. (Working sets and the modified list are explained later in this chapter.)Mapped pages can also be written back to their original files on disk with an explicit call to FlushViewFile or by the modified page writer as memory demands dictate.

You can decommit pages and/or release address space with the VirtualFree or VirtualFree. The difference between decommitment and release is similar to the difference between reservation and commit. Decommitted memory is still reserved, but released memory has been freed; it is neither committed nor reserved.

Using the two-step process of reserving and committing virtual memory defers committing pages—and, thereby, adds to the system charge described in the next section—until needed, but keeps the convenience of virtual contiguity. Res memory is a relatively inexpensive operation because it consumes very little actual memory. All that needs to be updated or constructed is the relatively small data structures that represent the state of the process address space. We'll explain these structures, called page tables and Virtual Descriptors (VADs), later in this chapter.

One extremely for reserving a large space and committing portions of it as needed is the user-mode stack for each thread. When a thread is created, a stack is created by a contiguous portion of the process address space. (The default size is 1 MB but you can override this size by using the CreateThread and CreateRemoteThread(Ex) function calls or change it on an executable image by using the /STACK linker flag.) By default, the page in the stack is committed and the next page is marked as a guard page (which isn't committed) that traps references before the end of the committed portion of the stack and expands it.
