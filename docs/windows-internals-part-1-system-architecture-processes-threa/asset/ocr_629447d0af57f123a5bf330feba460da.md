# # User-Mode Driver Framework

Windows provides a growing number of drivers that run in user mode, using the User-Mode Driver Framework (UMDF). UMDF version 2 is aligned with KMDF in terms of object, programming model and I/O model. The frameworks are not identical, however, because of the inherent differences between user mode and kernel mode. For example, some KMDF objects listed in Table 6-12 don't exist in UMDF, WDFCHILDLIST, DMA-related objects, WDFLOOKASIDELIST (look-aside lists lists can be allocated only in kernel mode), WDFORESLIST, WDFIOREQLIST, WDFDPC, and WMI objects. Still, most KMDF objects and concepts apply equally to UMDF 2.x.

UMDF provides several advantages over KMDF:

+   - UMDF drivers execute in user mode, so any unhandled exception crashes the UMDF host process, not the entire system.
- The UMDF host process runs with the Local Service account, which has very limited privileges on the local machine and only anonymous access in network connections. This reduces the security attack surface.
- Running in user mode means the IRQL is always 0 (PASSIVE_LEVEL). Thus, the driver can take page faults and use kernel dispatcher objects for synchronization (events, mutes, and so on).
- Debugging UMDF drivers is easier than debugging KMDF drivers because the debugging setup does not require two separate machines (virtual or physical).
