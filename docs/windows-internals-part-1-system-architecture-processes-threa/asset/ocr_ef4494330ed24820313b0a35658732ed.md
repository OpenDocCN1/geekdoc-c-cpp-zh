Each time the kernel virtual address allocator obtains virtual memory ranges for a certain type of virtual address, it updates the MiSystemVaType array, which contains the virtual address type for the newly allocated address. The values that can appear in MiSystemVaType are shown in Table 5-8.

|---|---|--|
| MiVaused (0) | Unused | N/A |
| MiVaSessionSpace (1) | Addresses for session space | Yes |
| MiVaProcessSpace (2) | Addresses for process address space | No |
| MiVaLoaded (3) | Addresses for images loaded by the boot loader | No |
| MiVaPfnDatabase (4) | Addresses for the PFN database | No |
| MiVaNonPagedPool (5) | Addresses for the non-paged pool | Yes |
| MiVaPagedPool (6) | Addresses for the p pool | Yes |
| MiVaSpecialPoolPaged (7) | Addresses for the special pool (paged) | No |
| MiVaSystemCache (8) | Addresses for the system cache | No |
| MiVaPtes (9) | Addresses for system PTEs | Yes |

Although the logic to dynamically reclaim virtual space on demand allows better management of virtual memory, it would be useless without the ability to free this memory. As such, when the paging pool or system cache can be shrunk, or special pool and large page mappings are freed, the associated virtual address is freed. Another case is when the boot registry is released. This dynamic management of memory depending on each component. Additionally, components can reclaim memory through ReclaimSystemVa, which requests virtual addresses associated with the system cache to be freed (through the dereference segment thread) if virtual address space has dropped below 128 MB. Reclaiming can be satisfied if initial non-paged pool has been freed.

In addition to proportioning and better management of virtual addresses dedicated to different kernel memory consumers, the dynamic virtual address allocator has advantages when it comes to memory footprint reduction. Instead of having manually pre-allocate static table entries and page tables, paging-related structures are allocated on demand. On both 32-bit and 64-bit systems, this reduces boot-time memory usage because unused addresses won't have their page tables allocated. It also means that on 64-bit systems, the address space regions that are reserved don't need to have their page tables in memory. This allows them to have arbitrarily large limits, especially on systems that have physical RAM to back the paging structures.
