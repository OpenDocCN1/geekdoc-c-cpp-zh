
在考虑健壮性——以及泛指 SuperFetch 优化时——需要记住的要点是：SuperFetch 会持续监控模式并更新其对系统的理解，以避免获取无用数据。虽然用户日常活动或应用程序启动的变化可能会导致 SuperFetch 用无关数据污染缓存，或者丢弃它可能认为无用的数据，但它能迅速适应任何模式的变化。如果用户的行为是反复无常且随机的，最坏的结果是系统表现得与完全没有 SuperFetch 时的状态相似。如果 SuperFetch 产生疑虑或无法可靠地跟踪，它会保持静默，并且不对给定的进程或页面执行任何操作。

## ReadyBoost

与十年前相比，如今 RAM（内存）非常容易获得且价格廉廉。尽管如此，它的成本仍然无法与硬盘等次级存储相比。遗憾的是，机械硬盘包含许多移动部件，它们很脆弱，更重要的是，与 RAM 相比，它们运行较慢，特别是在寻道期间。因此，在驱动器上存储活跃的 SuperFetch 数据将与页面换出并在内存中发生硬页错误一样糟糕。

固态硬盘和混合硬盘抵消了这些缺点，但它们的价格比 RAM 高且速度更慢。然而，便携式存储媒体如 USB 闪盘（UFD）、CompactFlash 和数字（SD）卡提供了一种实用的折中方案。它们比 RAM 便宜且容量更大，但由于缺少移动部件，它们的响应时间比机械硬盘短。

> 注意：在实践中，CompactFlash 和 SD 卡几乎总是通过 USB 适配器使用，因此它们在系统看来都像是 USB 闪盘。

随机磁盘 I/O 特别昂贵，因为磁盘寻道时间加上典型桌面硬盘的旋转延迟总计约为 10 毫秒——对于当今 3 GHz 或 4 GHz 的处理器来说，这是一个 eternity。然而，闪存内存的读取速度可以比典型硬盘快 10 倍。Windows 包含一项 ReadyBoost 功能，通过在闪存存储设备上创建一个中间缓存层（逻辑上位于内存和磁盘之间）来利用闪存存储设备的优势。

ReadyBoost（不要与另一个 ReadyBoost 混淆）通过位于 `%System-Root%\System32\Drivers\Readyboost.sys` 的程序实现，该程序负责将缓存数据写入非易失性内存（NVRAM）。当你将 USB 闪盘插入系统时，ReadyBoost 会检查该设备以确定其性能特征以及其在 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Endmgmt` 中的插入结果（End 代表外部内存，是 ReadyBoost 在开发期间的开发名称）。

如果新设备的大小在 256 MB 到 32 GB 之间，且随机 4 KB 读取的传输速率达到 2.5 MB/s 或更高，同时随机 512 KB 写入的传输速率达到 1.75 MB/s 或更高，ReadyBoost 将询问你是否愿意分配部分空间用于缓存。如果你同意，ReadyBoost 会在设备根目录下创建一个名为 `ReadyBoost.scache` 的文件，并用它存储缓存页面。

初始化缓存后，ReadyBoost 会拦截对本地硬盘分区区（例如 `C:\`）的所有读写操作，并将任何读取或写入中的数据复制到我们创建的缓存文件中。这其中也有例外——例如，长时间未被读取的数据或属于 2:1 卷快照的数据。存储在缓存驱动器上的数据经过了压缩，通常一个 4 GB 的缓存文件将包含 8 GB 的数据。每个块在写入时都会使用高级加密标准（AES）加密进行加密，并使用每次启动随机生成的密钥，以确保设备从系统移除时缓存中数据的隐私性。

当 ReadyBoost 发现可以从缓存中满足读取请求时，它会从那里提供服务。然而，由于硬盘的顺序读取访问性能优于闪存内存，如果数据在缓存中，它会让属于顺序模式的读取直接进入磁盘。同样，在读取缓存时，如果必须执行 I/O，则会读取磁盘上的缓存。

依赖闪存内存的缺点是用户可以随时将其移除，这意味着系统永远无法在介质上解决关键数据。（正如你所看到的，数据总是先去到次级存储。）在下一节中介绍的关联技术 ReadyDrive 提供了额外的优势，并解决了这个问题。

## ReadyDrive

ReadyDrive 是 Windows 的一项功能，它利用了混合硬盘（H-HDD）。H-HDD 是一种嵌入了 NVRAM 的磁盘。典型的 H-HDD 拥有 50 MB 到 512 MB 不等的缓存。

在 ReadyDrive 模式，驱动器的闪存内存并不像大多数硬盘上常见的 RAM 缓存那样作为自动、透明的缓存。Windows 使用 ATA-8 命令来定义存储在闪存中的磁盘数据。例如，Windows 在系统关闭时会将启动数据保存到缓存中，以便更快重新启动。当系统休眠时，它会将休眠文件数据的部分存在缓存中，以便随后的恢复更快。由于即使在磁盘停止运行时缓存依然有效，Windows 可以将闪存内存作为磁盘写缓存，从而在系统使用电池运行时避免启动磁盘。保持磁盘主轴关闭可以节省硬盘在正常使用下消耗的大部分功率。

ReadyDrive 的另一个使用者是 SuperFetch。它提供了与 ReadyBoost 相同的优势，但功能更强；例如不需要外部闪存设备，并且具有持续工作的能力。由于缓存位于实际硬盘上，用户通常无法在计算机运行时将其移除，硬盘控制器无需担心数据丢失，并且可以使用缓存避免对实际磁盘进行写入操作。

## 进程反射（Process reflection）

在某些情况下，进程表现出问题行为，但由于它仍在提供服务，挂起它以生成内存转储或进行交互是不理想的。挂起进程以生成转储的时间可以通过获取转转储（minidump）来减少，它可以捕捉寄存器和栈，但这种转储类型的信息非常有限，对于诊断崩溃是足够的，但对于故障排除则不然。通过进程反射，目标进程会被挂起足够的时间来生成一个副本，并在目标允许执行时生成其所有用户模式内存。

多个 Windows 诊断基础设施（WDI）组件使用进程反射在启发式方法识别可疑行为时捕捉内存转储。例如，资源耗尽检测与报告（也称为 RADAR）中的内存泄漏诊断会对看似泄漏内存的进程生成反射转储，以便通过 Windows 报告（WER）发送给微软。WDI 的挂起进程启发式方法对死锁的进程执行相同的操作。由于这些组件使用启发式方法，它们无法确定进程是否有故障，因此不能长时间挂起它们。

Ntdll.dll 中的 `RtCreateProcessReflection` 函数驱动进程反射的实现。它的工作原理如下：

- 1. 创建共享内存段。
- 2. 共享内存段填充参数。
- 3. 将共享内存段映射到当前和目标进程中。
- 4. 创建两个事件对象并复制到目标进程中，以便当前进程和目标进程可以同步操作。
- 5. 通过调用 `RtCreateProcessUserThreadEx` 向目标进程注入线程。该线程被定向从 Ntdll.dll 的 `RtProcessReflectionStartup` 函数开始执行。（因为 Ntdll.dll 映射到每个进程地址空间的地址是相同的（启动时随机生成），当前进程可以直接传递从自己的 Ntdll.dll 映射中获取的函数地址。）
- 6. 如果 `RtCreateProcessReflection` 的调用者指定需要副本进程的句柄，`RtCreateProcessReflection` 将等待远程线程终止，否则返回给调用者。
- 7. 目标进程中的注入线程分配一个额外的事件对象，用于在副本创建后与其同步。
- 8. 注入线程调用 `Clone`，传递它从与初始化进程共享内存映射中获取的参数。
