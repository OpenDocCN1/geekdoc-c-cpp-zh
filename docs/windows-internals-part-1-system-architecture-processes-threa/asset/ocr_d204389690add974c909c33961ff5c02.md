Higher-level abstractions such as the GLOBAL have their own APIs for working with files and devices (for example, the System.IO.File class in .NET or .Storage.File class in WinRT), but these eventually call CreateFile() to get the actual handle they hide under the covers.

The GLOBAL?? object manager directory is sometimes called DosDevices, which is an older name. DosDevices still works because it's defined as a symbolic link to GLOBAL?? in the root of the object manager's namespace. In driver code, the ?? is typically used to refer to the GLOBAL?? directory.

The operating system carries all I/O requests as operations on a virtual file because the I/O manager has no knowledge of about files, but therefore making the responsibility of the driver to translate file-oriented commands (open, close, read, write) into device-specific commands. This abstraction thereby generalizes an application's interface to devices. User-mode applications call documented functions, which in turn call internal I/O system functions to read from, write to a file, and perform other operations.
