## Page stages and memory allocations

Pages in a virtual address space are either free, reserved, committed or shareable. Committed and shareable pages are pages that, when accessed, ultimately translate to valid pages in physical memory. Committed pages are also referred to as private pages. This is because committed pages cannot be shared with other processes, whereas shareable pages can (but might be in use by only one process).

Private pages are allocated through the Windows VirtualAlloc, VirtualAllocEx, and VirtualAllocVirtual functions which lead eventually to the execution in the function NtAllocateVirtualMemory inside the memory manager. These functions are capable of committing memory as well as reserving memory. Reserving memory means setting aside a range of contiguous virtual addresses for future use (as an array) while consuming negligible resources and then committing portions of the reserved space as needed. If the size requirements allow, a process can reserve and commit in either case the committed pages can be accessed by any thread. Attempting to access free or reserved memory results in an access violation unless the page isn't mapped to any storage.

If committed (private) pages have never accessed before, they are created at the time of access as zero-initialized pages. Private pages may later be written to the page file by the operating system if required for physical memory. Private refers to the fact that these pages are normally inaccessible to any other process.

> Some functions, as ReadProcessMemory and WriteProcessMemory, appear to permit cross-process memory access but these are implemented by running kernel-mode code in the context of the target process.(This is referred to as attaching to the process.) They also require that the security descriptor of the target process grant the accessor PROCESS_VM_READ or PROCESS_VM_WRITE respectively, or that the accessor holds the SeDebugPrivilege which is by default granted only to members of the administrators group.

Shared pages are usually mapped to a view of a file or part of file, but may instead represent a portion of space. All shared pages can potentially be shared with other processes. Sections are exposed in the Windows API as mapping objects. Pages are written to disk through a mechanism called modified page writing. This occurs as pages are moved from a process's working set to a system-wide list called the modified list. From there, they are written to disk.

When a shared page is first accessed by any process, it will be read from the associated file unless the section is associated with the paging file, in which case it is created as a zero-initialized page. Later, if it is still resident in physical memory, the second and subsequent processes accessing it simply use the same page contents that are already in memory. Shared pages might have been prefetched by the system.

You can decommit pages and release address space with VirtualFree. The difference between decommitment and release is similar to the difference between reservation and commit. Decommitted memory is still reserved, but released memory has been freed; it is neither committed nor reserved. Using the two-step process of reserving and committing virtual memory defers committing pages—and, thereby adds to the system charge—until needed, but keeps the convenience of virtual contiguity. Memory is a relatively inexpensive operation because it consumes little actual memory. All that needs to be constructed is the relatively small data structures that represent the state of the process address space. We'll explain these structures, called page tables and Virtual Descriptors (VADs), later in this chapter.

One extremely reserving a large space and committing portions of it as needed is the user-mode stack for each thread. When a thread is created, a stack is created by a contiguous portion of the process address space. (The default size is 1 MB but you can override this size by using CreateThread and CreateRemoteThread calls or change it on an executable image by using the /STACK flag.) By default, the page in the stack is committed and the next page is marked as a guard page (which isn't committed) that traps references before the end of the committed portion of the stack and expands it.

## Commit charge and commit limit

On the Performance tab in Task Manager, the Memory page, there is a Committed label with two numbers underneath. The memory manager tracks of private committed memory usage on a global basis, termed commitment or commit charge. It is the first of the numbers, which represents the total of committed virtual memory in the system.

There is a system-wide limit, called the system limit or simply the commit limit, on the amount of committed virtual memory that can exist at any one time. Limit corresponds to the current total size of all paging files plus the amount of RAM that is usable by the operating system. This is the second of the numbers displayed under the Committed limit. The memory manager can increase the commit limit by automatically expanding one or more of the paging files if they are not already at their configured maximum size.

Commit charge and the system limit are explained in more detail in the section "Commit charge and the system limit" in this chapter.
