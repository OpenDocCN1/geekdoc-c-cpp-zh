Security descriptors (SDs) can be programmatically retrieved using various functions, such as GetSecurityInfo, KernelGetObjectSecurity, GetFileSecurity, GetNamedSecurityInfo, and other esoteric functions. After retrieval, the SD can be manipulated and the relevant Set function called to make the change. Furthermore, a descriptor can be constructed using a string in a language called Security Descriptor Language (SDDL), which is capable of representing a security descriptor using a compact string. This string can be converted to a true SD by calling ConvertStringToSecurityDescriptor.As you might expect, the convert function exists as well (ConvertSecurityDescriptorToSecurityDescriptor). An access control (ACL) is made up of a header and zero access control entry (ACE) structures. There are two types of ACLs: DACLs and SACLs. In a DACL each ACE contains a SID and an access mask (a set of flags, explained shortly), which typically specifies the access rights (read, write, delete, and so) that are granted or denied to the holder of the SID. There are nine types of ACEs that appear in a DACL: access allowed, access denied, allowed object, denied object, allowed callback, denied callback, allowed object, denied object, and conditional classes. As you would expect, the access-allowed ACE grants access to a user, and the access-denied ACE denies the access rights specified in the access mask. The callback ACEs are used by applications that make use of the AuthZ API (described later) to register a callback that AuthZ will call when it performs an access checking this ACE.

The difference between allowed object and access allowed, between denied object and access denied, is that the object types are used only unique identifier (GUID) field that identifies the ACE applies only to objects or subclasses that have GUID identifiers (GUID is a 128-bit identifier guaranteed to be unique). In addition, another optional GUID indicates what type of child object will inherit the ACE when a child is created in an Active Directory that has the ACE applied to it. The conditional classes ACE is stored in a -callback type ACE structure and is described in the section on the AuthZ APIs.

The accumulation of access rights granted by individual ACEs forms the set of access rights granted by an ACL. If no DACL is present (null DACL in a security descriptor, everyone has full access to the object). If the DACL is empty (it, has zero ACEs), no user has access to the object.
