+   - Windows services These are started by the Windows service control manager. For example, the Task Scheduler service runs in a user-mode process that supports the schtasks command (which is similar to the UNIX commands at cron). (Note that although the registry defines Windows drivers as "services", they are not referred to as in this book.)

+   - Dynamic link libraries (DLLs) These are callable subroutines linked together as a binary file that can be dynamically loaded by applications that use the subroutines. Examples include Msvcrt.dll (the C run-time library) and Kernel32.dll (one of the Windows API subsystem libraries). Windows user-mode components and applications use DLLs extensively. The Advantage provide over static libraries that applications can share DLLs, and Windows ensures that there is only one in-memory copy of a DLL's code among the applications that are referencing it. Note that library .NET assemblies are compiled as DLLs but without any unmanaged exported routines. Instead, the CLR parses metadata to access the corresponding types and members

# Processes

Programs and processes appear similar on the surface, they they are fundamentally different. A program is a static sequence of instructions, whereas a process is a container for a set of resources used when executing the instance of the process. At the highest level of abstraction, a Windows process comprises the following:

+   - A private virtual address space This is a set of virtual memory addresses that the process can use.

+   - An executable program This defines initial code and data and is mapped into the process's virtual address space.

+   - A list of open handles These map to system resources such as semaphores, synchronization objects, and files that are accessible to all threads in the process.

+   - A security context This is an access token that identifies the user, security groups, privileges, attributes, claims, capabilities, User Account Control (UAC) virtualization state, session, and limited user account state associated with the process, as well as the AppContainer identifier and its related sandbox information.

+   - A process ID This is a unique identifier, which is internally part of an identifier called a client ID.

+   - At least one thread of execution Although an "empty" process is possible, it is (mostly) not useful.
