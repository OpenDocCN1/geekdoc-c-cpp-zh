# How SAS is implemented

The SAS is secure because no application can intercept the Ctrl+Alt+Del keystroke combination or prevent Winogalon from receiving it. Win32k.sys reserves the Ctrl+Alt+Del key combination so that whenever the Windows input system (implemented in the raw input thread in Win32k) sees the combination, it sends an RPC message to Logon's message server, which listens for notifications. The keystrokes mapped to a registered key are not sent to any process other than the one it registered, and only the thread that registered a key can unregister it, so a Trojan horse application cannot demrate Logon's ownership of the SAS.

A function, SetWindowsHookEx, enables an application to install a hook procedure every time a keystroke is pressed, even when hot keys are pressed, and allows the hook to squash keystrokes. However, the Windows hot key processing code contains a special case for Ctrl+Alt+Del that disables the keystroke sequence cannot be intercepted. In addition, if the interactive desktop is locked, only keys owned by Winogalon are processed.

Once the Winogalon desktop is created during initialization, it is the active desktop. When the Winogalon desktop is active, it is always locked. Winogalon unlocks the desktop only to switch to the application desktop or the screen-saver desktop. (Only the Winogalon process can lock or unlock a desktop.)
