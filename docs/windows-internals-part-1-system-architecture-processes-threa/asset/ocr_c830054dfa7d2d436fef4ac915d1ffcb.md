The need for fast, efficient, and secure virtualization has driven new models of computing and about software. In today, certain software—such as Docker, which is supported in Windows 10 and Server 2016—runs in containers which provide fully isolated virtual machines designed for running a single application stack or framework, pushing the boundaries of a guest/host even further.

To provide virtualization services, all modern solutions employ the use of a hypervisor, which is a specialized and privileged component that allows for the virtualization and isolation of all resources on the machine, from virtual to physical memory, to device interrupts, and to PCI and USB devices. Hyper-V is an example of such a hypervisor which provides the Hyper-V client functionality exposed in Windows 8.1 and later. Competing products such as Xen, KVM, VMware, and VirtualBox implement all their hypervisors, each with their strengths and weaknesses.

Due to its privileged nature, and because it has even greater than the kernel itself, a hypervisor has a distinct advantage that goes beyond running multiple guest instances of operating systems: It can protect and monitor a single host to offer instances and guarantees beyond the kernel. In Windows 10, Microsoft now leverages the Hyper-V hypervisor to provide a new set of services known as *virtualization-based security* (VBS):

+   **Device Guard** provides Hyper Code Integrity (HVCI) for stronger code-signing guarantees over KMCS alone, and allows for the customization of the signature policy of the Windows OS, for both user-mode and kernel-mode code.
**Hyper Guard** protects this key-related and hypervisor-related data structures and code.
**Credential Guard** this prevents unauthorized access to domain credentials and secrets, combined with secure biometrics.
**Application Guard** provides an even stronger sandbox for the Microsoft Edge browser.
**Host Guardian and Shielded Fabric** these leverage a virtual TPM (v-TPM) to protect a virtual machine from the infrastructure it's running on.

Additionally, the Hyper-V hypervisor enables certain kernel mitigations against exploits and other attackers. The key advantage of all these technologies is that unlike kernel-based security improvements, they are not vulnerable to malicious or badly written drivers, regardless of whether they are signed or not. This makes them highly resilient against today's advanced adversaries. This is possible due to the hypervisor's implementation of Trust Levels (VTLs). Because the normal operating system and its components are in a less privileged mode (VTL 0), but these VTLs run at VTL 1 (a higher privilege), they cannot be affected by kernel mode code. As code, code remains within the realm of the VTL 0 privilege space. In this way, you can find of VTLs as orthogonal to the processor's privilege level within each VTL, and the hypervisor manages privileges across VTLs.
