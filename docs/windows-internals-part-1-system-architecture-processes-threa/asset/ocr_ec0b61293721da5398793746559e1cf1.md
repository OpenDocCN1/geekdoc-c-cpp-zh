Outside the kernel, the executive represents threads and other shareable resources as objects. These objects require some policy overhead, such as object handles to manipulate them, security checks to protect them, and resource quotas to be deducted when they are created. This overhead is eliminated in the kernel, which implements a set of simpler objects, called kernel objects, that help the kernel control processing and the creation of executive objects. Most executive-level objects encapsulate one or more kernel objects, incorporating the kernel-defined attributes.

One set of kernel objects, called control objects, establishes mechanisms for controlling OS functions. These include the Asynchronous Procedure Call (APC) object, the Deferred Procedure Call (DPC) object, and several objects the I/O manager uses, such as the interrupt object.

Another set of kernel objects, known dispatcher objects, incorporates synchronization capabilities that alter or affect thread scheduling. The dispatcher includes the kernel thread, mutex (called mutant in kernel terminology), event, kernel event pair, semaphore, timer, and waiter. The executive uses kernel functions to create instances of kernel objects, to manipulate them, and to construct the complex objects it provides to user mode. Objects are explained in more detail in Chapter 8 in Part 2, and threads are described in Chapter 3 and Chapter 4, respectively.

# Kernel processor control region and control block

The kernel uses a data structure called the kernel processor control region (KPCR) to store processor-specific data. The KPCR contains basic information such as the processor's interrupt dispatch table (IDT), task segment state (TSS), and global descriptor table (GDT). It also includes interrupt controller state, which it shares with other modules, such as the ACPI driver and the HAL. To provide easy access to the KPCR, the kernel stores a pointer to it in the fs on 32-bit Windows and in the gs register on x64 Windows system.

The KPCR also contains an embedded data structure called the kernel processor control block (KPCB). Unlike the KPCR, which is constructed for third-party drivers and other Windows kernel components, the KPCB is a private structure used only by the kernel code in Ntoskrnl.exe. It contains the following:

+   - Scheduling information such as the current, next, and idle threads scheduled for execution on the processor
- The dispatcher database for the processor, which includes the ready queues for each priority level
- The DPC queue
- CPU vendor and identifier information, such as the model, stepping, speed, and feature bits
- CPU and NUMA topology, such as node information, cores per package, logical processors per core, and so on
- Cache sizes
- Time accounting information, such as the DPC and interrupt time.
