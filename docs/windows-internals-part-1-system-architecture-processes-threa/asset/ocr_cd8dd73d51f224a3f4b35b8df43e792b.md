The versions seem to have strayed from a well-defined path starting with Windows 7. Its version number was 6.1 and not 7. Because of the popularity of Windows XP, when Windows Vista bumped the version number to 6.0, some applications failed to detect the correct (OS) as developers checked major numbers greater than or equal to 5 and minor numbers greater than equal to 1, which was not the case with Windows Vista. Having learned the lesson, Microsoft chose to leave the major version number as 6 and the minor version number as 2 (greater than 1) to minimize such incompatibilities. With Windows 10, the version number has been updated to 10.0.

> Starting with Windows 8, the GetVersion Windows API function returns the version number as 6.2 (Windows 8) by default, regardless of the actual OS. (The function is also declared as deprecated). This is to minimize compatibility issues also as an indicator checking for the OS version is not the best approach in most cases. This is because some components can be built out of band, without coinciding with an Windows release. Still, if you need the actual OS version, you can obtain it indirectly by using the VerifyInfo function or the newer version helper APIs, such as IsWindows80Greater, IsWindows8Point10Greater, IsWindows100Greater, IsWindowsServer, and similar. OS compatibility can be indicated in the manifest, which changes the results of this function. (See Chapter 8, “System mechanisms,” in Windows Internals Part 2 for details.)
