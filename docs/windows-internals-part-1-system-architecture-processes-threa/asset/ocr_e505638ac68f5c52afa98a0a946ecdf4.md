AppLocker rules can be defined on the local machine using the Security Policy MMC (secpol.exe, see Figure 7-33) or a Windows PowerShell script, or can be pushed to machines within a domain group Policy. AppLocker rules are stored in multiple locations within the registry:

+   * HKLM\Software\Policies\Windows\Srv2 This key is also mirrored to HKLM\SOFTWARE\Wow6432Node\Policies\Windows\Srv2. The rules are stored in XML format.

+   * HKLM\SYSTEM\CurrentControlSet\Control\AppID\ The rules are stored here and a binary ACE.

+   * HKLKEY_CURRENT_USER\Software\Microsoft\CurrentVersion\Group Objects(GUID)\Machine\Software\Policies\Microsoft\Windows\Srv2 AppLocker policy pushed down from a domain as part of a GPO are stored in XML format.

Certificates for files that have been run are cached in the registry under the key HKLM\SYSTEM\CurrentControlSet\AppID\CertStore. AppLocker also builds a certificate chain (stored in HKLM\SYSTEM\CurrentControlSet\Control\AppID\CertStore) from the certificate found in a file to a trusted root certificate.

There are also AppLocker-specific PowerShell commands (cmdlets) to enable deployment and testing via scripting. Use the Import-Module AppLocker to get AppLocker cmdlets into PowerShell, several cmdlets are available. These include Get-AppLockerFileInfo, Get-AppLockerPolicy, New-AppLockerPolicy, Set-AppLockerPolicy, and Test-AppLockerPolicy.
