## 终止进程

进程是一个容器也是一个边界。这意味着一个进程使用的资源并不一定在其他进程中可见，因此需要使用某些进程间通信机制在进程之间传递信息。因此，进程不能意外地另一个进程的内存上写入任意字节。那需要显式调用如 `WriteProcessMemory` 的函数。然而，为了让其工作，必须显式打开具有适当访问掩码（`PROCESS_VM_WRITE`）的句柄。进程之间的自然隔离可能授予也可能不授予。如果一个进程发生某些异常，它不会对其他进程产生影响。最坏的情况是同一个进程崩溃，但系统的其余部分保持完好。

进程可以通过调用 `ExitProcess` 函数优雅地退出。对于许多进程来说——第一个线程的启动代码在从其主函数返回时会代表该进程调用 `ExitProcess`。*优雅*一词意味着加载到进程中的 DLL有机会执行工作，其方法是通过调用它们的 `DMain` 函数并传递 `DLL_PROCESS_DETACH` 来通知进程正在退出。

`ExitProcess` 只能由进程本身请求退出时被调用。使用 `TerminateProcess` 函数可以对进程进行非优雅终止，该函数可以从进程外部调用（例如，在请求时的 Process Explorer 和任务管理器中）。`TerminateProcess` 需要一个用 `PROCESS_TERMINATE` 访问掩码打开的进程句柄，该掩码可能授予也可能不授予。终止某些进程并不是容易的（或是不可能的）（例如，`Csrss`——请求者无法获取所需的访问掩码的处理器程序）。

这里“非优雅”的含义是 DLL 没有机会执行代码（不会发送 `DLL_PROCESS_DETACH`），并且所有线程都会被突然终止。这在某些情况下可能导致数据丢失——例如，如果文件缓存没有机会将其数据刷新到目标文件。

无论进程以何种方式消失，永远不会有任何泄漏。进程所有的私有内存都由内核释放，地址空间被销毁，指向内核对象的句柄被关闭。如果仍然存在指向该进程的打开句柄（`PROCESS` 结构存在），其他进程可以获取进程管理信息，例如进程退出代码（`GetExitCode`）。一旦这些句柄关闭，`PROCESS` 会被销毁，进程就真的什么都不下了。

尽管如此，如果第三方代表进程在内核内存中进行分配——例如由于 IOCTL 或仅仅由于进程通知——则有责任释放任何池内存。Windows 不跟踪或清理进程拥有的内核内存（进程创建的句柄对应的内存对象除外）。这通常通过 `IRP_MJ_CLOSE` 或 `IRP_MJ_CLEANUP` 通知驱动程序设备对象已关闭，或者通过进程终止通知来实现。（参见第 6 章“I/O 系统”获取更多关于 IOCTL 的信息）。

## 映像加载器

我们刚刚看到，当系统启动启动进程时，内核创建一个对象来表示它并执行各种内核相关的初始化任务。然而，这些任务并没有导致应用程序的执行，仅仅是准备它的上下文和环境。事实上，与内核态代码驱动程序不同，应用程序在用户态下执行。大部分实际初始化工作是在内核之外完成的。这项工作由*映像加载器*（image loader）执行，内部称为 `Ldr`。

映像加载器位于用户态系统库 *Ntdll.dll* 中，而不是内核库中。因此，它的行为就像是作为 DLL 一部分的标准代码，并受到内存访问和安全权限的限制。这使得这段代码变得特殊：它保证自己将始终存在于运行的进程中（*Ntdll.dll* 总是被加载），并且它是第一个运行的代码。

由于加载器在实际应用程序代码之前运行，它对用户和开发者来说通常是不可见的。尽管加载器的初始化任务是隐藏的，但程序在运行时通常会与其接口进行交互——例如，每当加载或卸载 DLL 或查询其基地址时。加载器负责的主要任务之一：

-   为应用程序初始化用户态状态，例如创建初始堆并设置线程本地存储（TLS）和纤线程本地存储（FLS）槽。
-   解析应用程序的导入表（IAT）以加载其所需的所有 DLL（然后递归地解析每个 DLL 的 IAT），随后解析 DLL 的导出表以确保函数确实存在。（特殊的转发器条目可以将导出重定向到另一个 DLL。）
-   在运行时以及按需要时加载和卸载 DLL，并维护所有已加载模块的列表（模块数据库）。
-   处理 Windows 并存运行（SxS）支持所需的程序清单文件，以及多语言用户界面（MUI）文件和资源。
-   读取应用程序兼容性数据库以查找补丁（shims），并在需要时加载 shim 引擎 DLL。
-   启用支持 API Sets 和 API 重定向，这是 One Core 功能的核心部分，允许创建通用 Windows Platform（UWP）应用程序。
-   通过 Switch 启用动态运行时缓解，并与 shim 和验证器（Verifier）机制交互。

正如你所看到的，这些任务大部分对于让应用程序实际运行至关重要。没有它们，调用外部函数或使用堆将立即失败。进程创建后，加载器会调用 `NtContinue` API 在异常帧上继续执行，正如异常处理程序所做的那样。这个异常帧由我们在之前的章节中所示。因此，由于加载器没有使用标准调用跳转到运行的应用程序，你不会在线程的调用树看到加载器的初始化函数。

1. 从安装 WinDbg 的目录启动 Gflags ，然后点击 Image File 选项卡。
2. 在 Image 字段中输入 Notepad.exe，然后按 Tab 键。这应该启用各种选项。选择 Loader Snaps 选项，然后点击 OK 或 Apply。
