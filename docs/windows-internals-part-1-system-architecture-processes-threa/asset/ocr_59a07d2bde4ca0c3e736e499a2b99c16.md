# Look-aside lists

Windows provides a fast-allocation mechanism called look-aside lists. The basic difference between pools and look-aside lists is that while general pool allocations can vary in size, a look-aside list contains only fixed-sized blocks. Although the general pools are more flexible in terms of what they supply, look-aside lists are faster because they don't use spinlocks.

Executive components and device drivers create look-aside lists that match the size of frequently allocated data structures by using the ExInitializePagedList (for non-paged allocations) and ExInitializePagedList (for paged allocations), functions in the WDK. To minimize the overhead of multiprocessor synchronization, several executive subsystems create separate look-aside lists for each processor for their frequently accessed data. The executive also creates a general per-processor and non-paged look-aside list for small allocations (256 bytes or less).

If a look-aside list is empty (as it is when first created), the system must allocate from the pool or non-paged pool. If it contains a free block, the cache can be satisfied very quickly. The list grows as blocks are returned to it. The pool-allocation routines tune the number of free blocks aside how often a device driver or executive subsystem allocates from the list. The more frequent the allocations, the more are stored on a list. Lookaside lists are automatically reduced if they aren't being allocated from. (This check happens once per second when the set manager thread wakes up and calls the ExAdjustListFunction).
