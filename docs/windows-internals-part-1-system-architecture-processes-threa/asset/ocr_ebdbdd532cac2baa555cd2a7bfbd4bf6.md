A section object can be connected to an open file on disk (called a mapped file) or committed memory (sections committed to memory are called page-backed sections because the pages are written to the paging file (as opposed to a mapped file) if demands on physical memory require it. (Because Windows can run with no paging file, page-backed sections might be in "backed" only by physical memory.)As shared committed pages are zero-filled when they are first accessed to ensure that no sensitive data is leaked.

To create a section object, call the CreateFileMapping, CreateFileMappingFrom, or CreateFileMappingNuma(Ex function specifying a previously opened file handle to map to (or INVALID_HANDLE_VALUE for a page-backed section) and a security descriptor. If the section has a name, other processes can use it with OpenFileMapping or the CreateFileMapping* functions. You can access section objects through either handle inheritance (by specifying the handle as inheritable when opening or creating the handle) or handle duplication (using DuplicateHandle). Device drivers can also manipulate section objects with the ZwSection, ZwMapViewSection, and ZwUnmapViewSection functions.

A section object can refer to files that are larger than fit in the address space of a process. (If the paging backs a section object, sufficient space must exist in the file and/or RAM to contain it.) To access a large section object, a process can map only the portion of the object that it requires (a view of the section) by calling the MapViewOf(Ex), MapViewOfFileFromApp, MapViewOfFileNuma and then specifying the range to map. Mapping views permits to conserve address space because only the views of the section object needed at the time will be mapped into memory.

Windows applications can use mapped files to perform I/O by simply making them appear as data in memory within their address space. User applications are not the consumers of section objects; the image loader uses section objects to map executables, DLLs, and device drivers into memory, and the cache manager uses their access to data files. (For information on how the cache manager integrates with the memory manager, see Chapter 14 in Part 2.)
