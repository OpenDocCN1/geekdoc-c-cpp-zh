+   - Page-file-backed mapped memory This is allocated with a MapViewOfFile le that references a section object, which in turn is not associated with a file. The system uses a portion of the page file as the backing store inside. These allocations are not charged to the process file quota.

+   - Copy-on-write regions of mapped memory (even if it is associated with ordinary mapped files) The mapped file provides backing store for its own unmodified content. However, should a page in the copy-on-write region be modified, it can longer use the original mapped file for backing store. It must be kept in RAM or in a paging file. These allocations are not charged to process file quota.

+   - Non-paged and paging pool allocations in system space that are not backed by explicitly associated files Even the free regions of the system memory pools contribute to charge. The non-pagable regions are counted in the commit charge though they will never be written to the page file because they permanently reduce the amount of RAM available for private pageable data. These allocations are not charged to process file quota.

+   - Kernel stacks Threads’ stacks executing in kernel mode.

+   - Page tables Most of these are themselves pagable, and are not backed by mapped files. However, if they are not pagable, they occupy RAM. Therefore, the space required for them contributes to commit charge

+   - Space for page tables that are not yet actually allocated As you will see, large areas of virtual space have been defined but not referenced (example, private virtual space), the system need not actually create page tables to describe it. However, the space for these as-yet-nonexistent page tables is charged to commit charge to ensure that the page tables can be created when they are needed.

+   - Allocations of physical memory via the Address Windowing Extension (AWE) APIs discussed previously, consume physical memory directly.

For many of these items, the commit charge may represent the potential use of storage rather than its actual use. For example, a page of private committed memory does not actually occupy either a physical page of RAM or the equivalent page file space until it’s referenced once. Until then, it is a demand-zero page (described later). But commit charge accounts for pages when the virtual space is first created. This ensures when the page is later referenced, actual physical space will be available for it.

A region of a file backed as copy-on-write has a similar requirement. Until the process to the region, all pages in it are backed by the mapped file. However the process may write to any of the pages in the region at any time. When happens, those pages are thereafter as private to the process. Their backing store is, thereafter, the page file. Charging the system commit for when the page is first created ensures there will be private storage for them later, if and when the we accesses occurs.
