and the SuperFetch component that we'll talk about later. The prefetcher signals %KerneObjects\PrefetchTraces% ready to inform the SuperFetch service that it can now query trace data.

> You can enable or disable prefetching of boot or application starts by editing the DWORD registry value EnablePrefetcher in the HKLM\SYSTEM\CurrentControl\Control\Session Manager\Memory Management\PrefetchParameters key. Set it to 0 to disable prefetching, 1 to enable prefetching of only applications, 2 for prefetching of boot, and 3 for both boot and applications.

The SuperFetch service (which hosts the local prefetcher, although it a completely separate component from the actual SuperFetch functionality) performs a call to the internal NtQuerySystemInformation call requesting the trace data. The local prefetcher post-processes the data, combining it with previously collected data, and writes it to a %SystemRoot%\Prefetch folder (Figure 5-3). The file name is the name of the application to which the trace applies followed by a hash and a hexadecimal representation of the file's path. The file has a .pf extension. An example would be Notepad.EXE-9FB27COE.PF.
