## Kernel debugging

Kernel debugging means examining data structures and/or stepping through functions in the kernel. It is a useful way to investigate Windows internals because you can get clearer image of code flows. Before describing the various ways in which you can debug the kernel, let's examine a set of files you'll need.

### Symbols for kernel debugging

Symbols files contain the names of functions and variables and the layout and format of data structures. They are generated by the linker and used by debuggers to reference these names during a session. This information is not usually stored in the binary because it is not needed to execute the code. These binaries are smaller and faster. However, it also means that when debugging, you must make sure the debugger can access the symbol files.

To use of the kernel-debugging tools to examine Internal kernel data structures such as the process list, loaded driver memory, memory usage, and so on, you must have the correct symbol files for at least the kernel image. For example, if you install a Windows service pack or hot fix that updates the kernel, you must obtain the updated symbol files.

While it is possible to download and install symbols for various versions of Windows, updated symbols for hot fixes are not always available. The easiest way to obtain the correct version of symbols for debugging is to employ the Microsoft on-demand symbol server using a special syntax for the symbol path you specify in the debugger. For example, the following symbol path causes the debugging tools to load required symbols from the Internet symbol server and keep a local copy in the C:\symbols folder:

```
srvc=*:http://msdn.microsoft.com/download/symbols
```
