Some key columns are as follows:

+   **Threads** The Threads column shows the number of threads in each process. This number should normally be at least one, as there's no direct way of creating a process with no threads (and such a process is pretty useless anyway). If a process shows zero threads, it usually means the process can't be deleted for some reason—probably because of some driver code.

+   **Handles** The Handles column shows the number of handles to kernel objects opened by threads running within the process. (This is described later in this chapter and in detail Chapter 8 in Part 2.)

+   **Status** The Status column is a little tricky. For processes that don't have any user interface, Running should the normal case, as other threads may be waiting for something, like a kernel object being signaled or some I/O operation to complete. The other option for processes is Suspended, and if all the threads in process are in a suspended state. This is unlikely to occur by the process itself, but can be achieved programmatically by calling the NtSuspendProcess API which has an option). On the process, typically through a tool (for example, Process Explorer, described later,). For processes that create a user interface, the Running status value will be UI input (technically, the message queue associated with the thread). The suspended state is possible just like in the non-UI case, but for Windows Apps (those holding the Windows Runtime), Suspended normally occurs when the process loses its foreground status by being minimized by the user. Processes are suspended after 5 seconds so that they don't consume any CPU or networking resources, thus allowing the foreground app to get all machine resources. This is especially important for battery-powered devices, such as tablets and phones. And those related mechanisms are described more fully in Chapter 9 in Part 2. The third possible value for Status is Not Responding. This can happen if a thread within the process that created the user interface has not checked its message queue for UI-related activity for at least 5 seconds. The process may be busy doing some CPU-intensive work or waiting on something else entirely (such as an I/O operation to complete). Either way, the UI freezes, and Windows indicates by fading the window(s) in question and appending (“Not Responding”) to its title.

Each process also points to its parent or creator process (which may be, but is not always, its creator process). If the parent no longer exists, this information is not updated. Therefore, it is possible for a process to refer to a nonexistent parent. This is not a problem, because relies on information being kept current. In the case of the Process Explorer tool, the start time of the parent process is taken into account avoid attaching a child process based on a reused process ID.
