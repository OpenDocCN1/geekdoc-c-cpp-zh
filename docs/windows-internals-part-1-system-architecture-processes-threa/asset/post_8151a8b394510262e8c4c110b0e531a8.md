The recommended size is based on a factor that the Process Lifecycle Manager (PLM) uses to determine when to terminate an app. Current factor is 2.3 * RAM, which was considered the size (based on the factor) if RAM = 1 GB (rough minimum for mobile devices). The maximum page file size for a system-managed size is set at three times the size of RAM or 4 GB, whichever is larger. The minimum (initial) page file size is determined as follows:

- If it's the first-managed page file:

  - If the (new) base size is smaller than the computed size for crash dumps (SmpDesiredSizeForCrashDump), then set the base size to the computed size for crash dumps.

# The swap file

In the UWP apps world, when an app goes to the background—for example, it is minimized—the threads are suspended so that the process does not consume any CPU. The physical memory used by the process can potentially be reused for other processes. If memory pressure is high, the private working set (physical memory used by the process) may be swapped out to disk to allow the physical memory to be used for other processes.

Windows 8 added another page file called a swap file. It is essentially the same as a normal page file but is used only for UWP apps. It's created on SKUs if at least one normal page file was created (the normal method). Its name is SwapFile.sys and it resides in the system root partition—for example, C:\SwapFile.sys.

After the normal page files are created, the HKLM\System\CurrentControlSet\SessionManager\Memory management key is consulted. If a value named SwapFile exists, it's then read as a string with the same format as a normal page file, with a filename, an initial size, and a maximum size. The difference is that a value of zero for the sizes is interpreted as no swap creation. These two registry values do not exist by default, which results in the creation of a Swapfile on the system partition with a minimum size of 16 MB on (small disks) (for example, SSD) or 256 MB on (large SSD) disks. The maximum size of the swap file is 1.5 * RAM or 10 percent of the system root partition size, whichever is smaller. See Chapter 7 in this book and Chapter 8, "System mechanisms," and Chapter 9, "Management mechanisms," in Part 2 for more on UWP apps.

Note: The swap file is not counted against the maximum page files supported.

# The virtual page file

The vm debugger hints at another page file called "No Name for Paging File." This is a virtual page file. As the name suggests, it has no actual file but is used indirectly as the backing store for memory compression (described later in this chapter in the section "Memory compression"). It is large, but its size is set arbitrarily to not run out of free space. Invalid PTEs for pages that have been compressed to this virtual page file allow the memory compression store to get to the compressed data when needed by interpreting the bits in the invalid PTE leading to the correct store, region, and index.
