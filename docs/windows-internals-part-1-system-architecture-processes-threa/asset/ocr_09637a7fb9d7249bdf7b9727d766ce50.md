# # Terminating a process

A process is a container and a boundary. This means resources used by one process are not necessarily visible in other processes, so some inter-process communication mechanism needs be used to pass information between processes. Therefore, a process cannot accidentally write arbitrary bytes on another process's memory. That would require explicit call to a function as writeProcessMemory. However, to get that to work, a handle with the proper access mask (PROCESS_VM_WRITE) must be opened explicitly. Natural isolation between processes may or not be granted. If some exception happens in one process, it will have no effect on other processes. The worst that can happen is that the same process would crash, but the rest of the system remains intact.

A process can exit gracefully by calling the ExitProcess function. For many processes—the startup code for the first thread calls ExitProcess on the process's behalf when returns from its main function. The term *gracefully* means that DLLs loaded into the process get a chance to do work by getting notified of the process exit using a call to their DMain function with DLL_PROCESS_DETACH.

ExitProcess can be called only by the process itself asking to exit. An ungraceful termination of a process is possible using the TerminateProcess function, which can be called from outside the process.(For example, Process Explorer and Task Manager when requested.) TerminateProcess requires a handle to the process that is opened with the PROCESS_TERMINATE access mask, which may or not be granted. It's not easy (or it's impossible) to terminate some processes (for example, Csrss—the handler with the required access mask cannot be obtained by the requester.)
