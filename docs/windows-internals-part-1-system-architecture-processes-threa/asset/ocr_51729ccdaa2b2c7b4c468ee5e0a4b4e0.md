# TABLE 7-20 Process mitigation options (continued)

| Mitigation Name | Use Case | Enabling Mechanism |
| --- | --- | --- |
| Heap Term On Corruption | This disables the Fault Tolerant Heap (FTH) and the raising of a continual exception in the case of heap corruption terminating instead. This prevents the use of heap corruption as a way to force an attacker-controlled exception handler from executing, or in cases the program ignores the heap exception, or cases the exploit only causes heap corruption (limiting its universal effectiveness or reliability). | This is set by using HeapSetInformation or by using the PROCESS_MIGATION_POLICY_HEAP_TERMINATE_ALWAYS_ON process-creation attribute flag. |
| Disable Process Creation | This prohibits the creation of child processes by marking the token with a special restriction, which should stop any other component from creating a process while respecting this (for example, WMI process creation, or a kernel creating the process). | This is set by the PROCESS_CHILD_PROCESS_RESTRICTED attribute flag. It can be overridden to allow packages with the PROCESS_CREATION_DESKTOP_APP_OVERRIDE flag. |
| All Applications Policy | This makes an application running under an AppContainer unable to access resources unless it have an APPLICATION PACKAGES SID present, as explained in section. The presence of an ALL RESTRICTED APPLICATION PACKAGES SID will be required-sometimes referred to as Less Privileged App Container (LPAC). | This is set by the PROCESS_THREAD_ATTRIBUTE_APPLICATION_PACKAGES_POLICY process-creation attribute. |

Note that it is also possible to enable some of these mitigations on a per-application or per-system basis without the cooperation of the application developer. To do so, use the Local Group Policy Editor. Then expand Computer Configuration, then Administrative Templates, then System, and Mitigation Options (see Figure 7-30). In the Process Mitigation Options dialog, enter the appropriate bit value that corresponds to the mitigations being enabled, using 1 to enable a mitigation, 0 to disable it, or 7 to leave it to its default or process-requested value (again, see Figure 7-30). The bit numbers are taken from the PROCESS_MITIGATION_POLICY enumeration found in the Winnt header file. This will result in the appropriate registry value being written in the File Execution Options (IFEO) key for the entered image name. Unfortunately the current version of Windows 10 Creators Update and earlier will strip out many of the newer mitigations. You can avoid this by manually setting the REG_DWORD MitigationOptions registry value.
