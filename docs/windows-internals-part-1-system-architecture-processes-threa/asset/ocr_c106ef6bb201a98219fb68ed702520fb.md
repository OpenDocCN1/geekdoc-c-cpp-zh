# Segment heap-specific security features

The segment heap implementation uses security mechanisms to make it harder to corrupt memory or allow code injection by an attacker. Here are a of them:

+   **Fail fast on linked node corruption** The segment heap uses linked lists to track segments and sub-segments. As the NT heap, chunks are added to the list insertion and removal to prevent arbitrary memory writes due to corrupted nodes. If a corrupted node is detected, the process is terminated at `tlFailFast`

+   **Fail fast on red-black (RB) tree node corruption** The segment heap uses RB trees to track back-end and VS allocations. Node insertion and deletion functions validate nodes involved or, if corrupted, invalidate the fail-fast mechanism.

+   **Function pointer decoding** Some of the segment heap allow for callbacks (in VsContext and LfhContext structures, part of the _SEGMENT_HEAP structure). An attacker can override these callbacks to point to his own code. However, the function pointers are encoded by using a XOR function with an random heap key and the context address, both of which cannot be guessed in advance.

+   **Guard pages** When LFH and VS sub-segments and large blocks are allocated, a guard page is added at the end. This helps to detect overflows and corruption of adjacent data. See the section "Stacks" later in this chapter for more information on guard pages.

# Heap debugging features

The heap manager includes several features to help detect bugs by the following heap settings:

+   **Enable tail checking** The end of each block carries a signature that is checked when the block is released. If a buffer overflow destroys the signature entirely or partially, the heap will report this error.
