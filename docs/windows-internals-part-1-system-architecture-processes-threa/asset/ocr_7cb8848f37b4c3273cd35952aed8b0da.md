# Portability

Windows was designed on a variety of hardware architectures. The initial release of Windows NT supported the x86 and MIPS architectures. Support for the Digital Equipment Corporation (which was bought by Compaq, which later merged with Hewlett-Packard) Alpha XP was added shortly thereafter. (After Alpha XXP was a 64-bit processor, Windows NT ran in 32-bit mode. During the development of Windows 2000, a native 64-bit version was running on Alpha XP, but this was never released.) Support for another processor market demands, the Motorola PowerPC, was added in Windows NT 3.51. Because of changing market demands, however, support for the MIPS and PowerPC architectures dropped before Windows 2000. Later, Compaq withdrew support for the Alpha XP architecture, resulting in Windows 2000 being supported only on the x86 architecture. Windows XP and Windows Server 2003 added support for two 64-bit processors: the Intel Itanium IA-64 family and the AMD64 family with their equivalent Intel64-bit Extension Technology (EM64). Latter two implementations are called 64-bit extended systems and they are referred to as x64.(How Windows runs 32-bit applications on 64-bit is explained in Chapter 8 of Part 2.) Additionally, as of Server 2002, IA-64 are no longer supported by Windows.

Newer editions of Windows support the ARM processor. For example, Windows RT was a version of Windows 8 that ran on ARM architecture, although that has been discontinued. Windows 10 Mobile—the successor to Windows 8.x operating systems—runs on ARM based processors, such as Qualcomm Snapdragon models. Windows 10 lot runs on both x86 and ARM devices such as Raspberry Pi 2 (which use an ARM Cortex-A7 processor) and Raspberry Pi 3 (which use the ARM Cortex-A53). As ARM hardware has advanced to 64-bit, a new processor called AArch64, or ARM64, may also be at some point, as an increasing number of devices run on.

Windows achieves portability across hardware architectures and platforms in two primary ways:

+   **By using a layered design** Windows has a layered design, with low-level layers of the system that are architecture-specific or platform-specific isolated into separate modules so that upper layers of the system can be shielded from the differences between architectures and hardware platforms. The two key components that provide OS portability are the kernel (contained in ntoskrnl.exe) and the HAL (contained in Hal.dll). Both components are described in more detail later in this chapter. Functions that are architecture-specific, as thread context switching and trap dispatching, are implemented in the kernel. Functions that differ among within the same architecture (for example, motherboards) are implemented in the HAL. The only other component with a significant amount of architecture-specific code is the memory manager, which is even a small compared to the system. Assembly language is used only for those parts of the OS that need to communicate directly with system hardware (such as the interrupt handler) or that are extremely performance-sensitive (such as context switching).
