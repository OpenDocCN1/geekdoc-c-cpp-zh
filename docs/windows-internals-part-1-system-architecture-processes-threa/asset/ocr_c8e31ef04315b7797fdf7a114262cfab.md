# TABLE 5-19 Physical page states (continued)

| Status | Description |
| --- | --- |
| Modified | The page previously belonged to a working set but was removed. However, the page was modified while it was in use and its contents haven't been written to disk or remote storage. The PTE still refers to the physical page but is marked invalid and in transition. It was worth writing to the store buffer before the physical page can be reused. |
| Modified no-write | This is the same as a modified except that the page has been marked so that the memory manager's modified page would not write to disk. The cache manager marks pages as modified no-write at the request of file writers. For example, NTFS uses this state for pages containing file metadata so that it can first ensure that transaction log entries are flushed to disk before the pages are written to disk. (NTFS transaction logging is explained in Chapter 13, "File systems," in Part 2.) |
| Free | The page is free without unspecified dirty data in it. For security reasons, these pages can be given as a user to a process without being initialized with zeros, or can be overwritten with new data (from example, from a file) before being given to a user process. |
| Zeroed | The page is free and has been initialized with zeros by the zero page thread or was determined to already contain zeros. |
| Rom | The page represents read-only memory. |
| Bad | The page has generated parity or other hardware errors and cannot be used (or as part of an enclave).

The PFN database contains an array of structures that represent each physical page of memory on the system. The PFN database and its relationship to page tables are shown in Figure 5-35. This figure shows, valid PTEs point to entries in the PFN database (and the PFN index points to the page in physical memory), and the PFN database for non-prototype PFNs point back to the page table that is using them (if it is being used by a page table). For prototype PFNs, they point back to the prototype PTE.
