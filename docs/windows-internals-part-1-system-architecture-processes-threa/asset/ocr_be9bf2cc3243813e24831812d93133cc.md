# EXPERIMENT: Viewing a security descriptor

Most executive subsystems rely on the object manager's default security functionality to manage security descriptors for their objects. The object manager's default security functions use the security descriptor pointer to store security descriptors for such objects. For example, the process manager uses default security, the object manager processes and thread descriptors in the object headers of process and thread, respectively. The security descriptor pointer of events, mutexes, and semaphores also store their security descriptors. You can use kernel debugging to verify the security descriptors of these objects once you locate their object header, as outlined in the following steps. (Note that both Explorer and AccessChk can show security descriptors for processes.).

+   1. Start local kernel debugging.

+   2. Type process 0 explorer.exe to obtain information about Explorer:

```
1kd>!process 0 explorer.exe
ffffffff8b13004fd780
SessionId: 1 Cid: 23e4
DirBase: 2aa0ff6000 ObjectTable: ffff82c72fcd80 HandleCount:
<Data Accessible>
Image: explorer.exe

PROCESS fffff813067a080
SessionId: 1 Cid: 27b8
DirBase: 2ca9a7000 ObjectTable: ffff82c72ccc500 HandleCount:
<Data Accessible>
Image: explorer.exe
```

+   3. If more than one instance of explorer is listed, choose one. (It doesn't matter.) Type object with the address of the EPROCESS in the output of the previous command as the argument to show the object data structure:

```
1kd>!object fffff813004fd750 Type: (ffff81f27496950) Process
Objectheader: fffff813004fd750 (new version)
HandleCount: 15 PointerCount: 504639
```

+   4. Type dt_ntl_object_header address of the object header field from your command to show the object header data structure, including the security descriptor pointer value:

```
1kd> dt_ntl_object_header fffff813004fd750
+0000 PointerCount : 05044448
+0008 HandleCount : 015
+0008 NextToFree : 000000000000000f
+0010 Lock : _EX_PUSH_LOCK
+0018 TypeIndex : 0E5
+0019 TraceFlags : 0
+0019 DbgRefTrace : 0y0
+0019 DbgTracePermanent : 0y0
```
