After the normal page files are created, the HKLM\System\CurrentControlSet\SessionManager\Memory management key is consulted. If a DWORD value named SwapFile exists, it's then read as a string with the same format as a normal page file, with a filename, an initial size, and a maximum size. The difference is that a value of zero for the sizes is interpreted as no swap creation. These two registry values do not exist by default, which results in the creation of a Swapfile on the system partition with a minimum size of 16 MB on (small disks) (for example, SSD) or 256 MB on (large SSD) disks. The maximum size of the swap file is to 1.5 * RAM or 10 percent of the system root partition size, whichever is smaller. See Chapter 7 in this book and Chapter 8, "System mechanisms," and Chapter 9, "Management mechanisms," in Part 2 for more on UWP apps.

+   Note The swap file is not counted against the maximum page files supported.

# The virtual page file

The vm debugger hints at another page file called "No Name for Paging File." This is a virtual page file. As the name suggests, it has no actual file, but is used indirectly as the backing store for memory compression (described later in this chapter in the section "Memory compression"). It is large, but its size is set arbitrarily to not run out of free space. Invalid PTEs for pages that have been compressed to this virtual page file and allow the memory compression store to get to the compressed data when needed by interpreting the bits in the invalid PTE leading to the correct store, region, and index.
