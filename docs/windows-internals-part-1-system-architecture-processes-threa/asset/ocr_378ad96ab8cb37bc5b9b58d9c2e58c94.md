Starting with Windows 8.1 and Server 2012 R2, page table hierarchies for reserved regions are not charged immediately; this means huge memory regions can be allocated without exhausting pages. This becomes important in some security features, such as Control Guard (CFG, see Chapter 7 for more details). If the region or a part of it is later committed, system memory is charged to account for the size of the region (and page tables), as the process file quota.

To it another, when the system successfully completes, for example, a VirtualAlloc call or MapView, it makes a commitment that the necessary storage will be available when needed, if it wasn't needed at that moment. Thus, a later memory reference to the allocated region can never fail for lack of storage space. (Of course, it could still fail for other reasons, as page protection, the region being deallocated, and so on.) The commit charge mechanism allows the system to keep this commitment.

The commit charge appears in the Performance Monitor counters as Memory: Committed Bytes. It is also the first of the two numbers displayed on the Task Manager’s Performance tab with the Commit (second being the commit limit), and it is displayed by Process Explorer’s System Information tab as Commit Charge — Current.

The process file quota appears in the performance counters as Process: Page File Bytes. The same data appears in Process: Private bytes counter. (Neither exactly describes the true meaning of the counter)

If the commit charge reaches the commit limit, the memory manager will attempt to increase the commit limit by expanding one or more page files. If that is not possible, subsequent attempts to allocate virtual memory that commit charge will fail until some committed memory is freed. The free counters are listed in Table 5-13 allow you to examine private committed memory usage on a system-wide, per-process, or per-page-file, basis.

**TABLE 5-13** Committed charge and page file performance counters

| Performance Counter | Description |
| :--- | :--- |
| Memory: Committed Bytes | This is the number of bytes of virtual (not reserved) memory that has been committed. This memory doesn't necessarily represent page file usage because it includes committed pages in physical memory that have never been paged out. Rather, it represents the charge that must be paid by page file space and/or RAM. |
| Memory: Commit Limit | This is the number of bytes of virtual memory that can be committed without having to extend the paging files. If the paging files can be extended, this limit is soft. |
| Process: Page File Quota | This is the process's contribution to Memory: Committed Bytes. |
| Process: Private Bytes | This is the same as Process: Page File Quota. |
| Process: Working Set — Private | This is the subset of Process that is currently in RAM and can be referenced without a page fault. |
| Process: Working Set | This is the subset of Virtual Bytes that are currently in RAM and can be referenced without a page fault. |
| Process: Virtual Bytes | This is the total virtual memory allocation of the process, including mapped regions, private committed regions, and reserved regions. |
| Paging File: % Usage | This is the percentage of the page file space that is currently in use. |
| Paging File: % Usage Peak | This is the highest observed value of Paging File: % Usage. |
