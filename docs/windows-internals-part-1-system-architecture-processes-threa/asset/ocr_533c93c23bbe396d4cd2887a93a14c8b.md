Rank always trumps priority. This means given two threads with different ranks, the lower value rank is preferred, regardless of priority. Equal-rank threads are compared based on priority. The rank is adjusted periodically as cycle usage increases.

Rank 0 is the highest (it wins out) against a higher number rank, and is implicit for some threads. This can indicate one of the following:

+   - The thread is not in any scheduling group ('normal') threads
- Under-quota threads
- Real-time priority threads (16–31)
- Threads executing at IRQL APC_LEVEL (1) within a kernel context or guarded region (see Chapter 8 in Part 2 for on APCs and regions)

At various scheduling groups (for example, KQuantum), the decision of which thread scheduled next to the scheduling group (if any) of the current and ready threads. If a scheduling group exists, the lowest value wins out, followed by priority (if ranks are equal), followed by the first arriving thread (if priorities are equal); round-robin at quantum end.

# # Dynamic fair share scheduling

Dynamic fair share scheduling (DFSS) is a mechanism that can be used to distribute CPU time among sessions running on a machine. It prevents one session from potentially monopolizing the CPU if some threads running under that session have a relatively high priority and a run lot. It is enabled by default on a Windows Server system that has the Remote Desktop role. However, it can be configured on any system, client or server. Its implementation is based on group scheduling described in the following section.

During the very last parts of system initialization, the registry SOFTWARE is initialized by Smss, the process manager initializes the final post-boot initialization in BootPhaseComplete, calls PspDFSSEnabled. Here, the system decides which of the two quota mechanisms (DFSS or legacy) will use. For DFSS to be enabled, EnabledQuota registry value must be set to a non-zero value in both of the quotas. The first of these is HKLM\SOFTWARE\Policies\Microsoft\Windows\SessionManager\Quota, System\ControlSet\Control\SessionManager\Quota determines whether the system supports the functionality (which, by default, is set to TRUE on Windows Server with the Remote Desktop role).

If DFSS is enabled, the PspEnabled global variable is set to TRUE, which makes all threads belonging to scheduling groups (except session  Processes). DFSS configuration parameters are read from the aforementioned groups by a call to PspReadDfssConfigurationValues and stored in global variables. These keys are monitored by the system. If modified, the notification callback calls PspReadDfssConfigurationValues again to update the configuration values.
