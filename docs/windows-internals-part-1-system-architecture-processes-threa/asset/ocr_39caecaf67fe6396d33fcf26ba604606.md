# Device enumeration

Device enumeration occurs when the system boots, resumes from hibernation, or is explicitly instructed to do so (for example, clicking Scan for Hardware Changes in the Device Manager UI). The PnP manager builds a device tree (described momentarily) and compares it to its known tree from previous enumeration, if any. For a boot or resume from hibernation, the stored device tree is empty. Newly discovered and removed devices require special treatment, such as loading appropriate drivers (for a newly discovered device) and notifying drivers of a removed device.

The PnP manager begins device enumeration with a virtual bus driver Root, which acts as the bus driver for non-Plug and Play drivers and the HAL. The HAL acts as a bus driver that enumerates devices directly attached to the motherboard as well as system components as batteries. By actually enumerating, however, the HAL relies on the hardware description recorded in the registry to detect the primary bus (in most cases, PCI bus) and devices such as batteries and fans.

The primary bus enumerates the devices on its bus, finding other buses, for which the PnP manager initializes drivers. Those drivers in turn can detect other devices, including other subsidiary buses. This recursive process of enumeration, driver loading (if the driver isn't already loaded), and further enumeration proceeds until all the devices on the system have been detected and configured.

As the buses report detected devices to the PnP manager, the PnP manager creates an internal tree called a device tree that represents the relationships between devices. In the tree all device nodes, or devnodes. A devnode contains information about the objects that represent the device as well as other Plug and Play-related information stored in the devnode by the PnP manager.
