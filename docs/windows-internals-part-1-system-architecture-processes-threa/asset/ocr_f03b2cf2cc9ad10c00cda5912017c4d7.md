# # Windows containers (server silos)

The rise of cheap, ubiquitous cloud computing has led to another major Internet revolution, in which building online services/or back-end servers for mobile applications is as easy as clicking a button on one of the many cloud providers. As the need to migrate from one to another, or from a cloud provider to a datacenter, from a datacenter to a high-end personal server, has grown, it has become increasingly important to have portable back ends, which can be deployed and moved around without costs associated with running them in a virtual machine.

It is to satisfy that technologies like Docker were created. These technologies allow the deployment of an "application in a box" from Linux to another without worrying about the complicated deployment of a local installation or the resource consumption of a virtual machine. Originally a Linux-only technology, Microsoft has helped bring Docker to Windows 10 as part of the Anniversary Update. It can work in two modes:

+   - By deploying an application in a heavyweight, fully isolated, Hyper-V container, which is supported on both client and server scenarios
- By deploying an application in a lightweight, OS-isolated, server silo container, which is currently supported only in server scenarios due to licensing reasons

This latter technology, which we will investigate in this section, has resulted in deep changes in the operating system to support this capacity. Note that, mentioned, the ability for clients to create server silos exists, but is currently disabled. Unlike a Hyper-V container, which leverages a true virtualized environment, a server silo provides a second "instance" of all-mode components while running on top of the same kernel and drivers. At the cost of some security, this provides a more lightweight container environment.

# # Job objects and silos

The ability to create a silo is associated with a number of undocumented subclasses as part of the SetJobObjectInform API. In other words, a silo is essentially a super-job, with capabilities beyond those we've seen so far. In fact, a job object can be used for the isolation and resource management capabilities we've looked at as well as used to create a silo. Such jobs are called hybrid jobs by the system.
