# TABLE 6-8 Important values in driver's registry key

| Value Name | Description |
| --- | --- |
| ImagePath | This is the path to the driver's image file (SYS). |
| Type | This indicates whether this key represents a service or a driver. Value of 1 means a driver and a value of 2 means a system (filter) driver. Values of 16 (0x10) and 32 (0x20) mean a service. See Chapter 9 Part 2 for more information. |

Chapter 11, "Startup and shutdown, in Part 2 describes the phases of the boot process and explains that a Start value of 0 means that the operating system loader loads the driver. A Start value of 1 means that the I/O manager calls driver initialization routines in the order that the driver within a boot phase after the subsystems have initial initialization. Like Windows services, drivers use the Group value in their registry key to specify which group they belong to; the registry value HKLM\SYSTEM\CurrentControlSet\ServiceGroupOrder determines the order that drivers are loaded within a boot phase.

A driver can refine its load order by using a Tag value to control its order within a group. The I/O manager sorts the drivers without a tag to the end of their group according to Tag values defined in the registry keys. You might assume that the I/O manager initializes drivers with lower-number tags before it initializes drivers with higher-number tags, but such isn't necessarily the case. The registry key HKLM\SYSTEM\CurrentControlSet\ServiceGroupList defines tag precedence within a group; with this key, Microsoft and device-driver developers can take liberties with redefining the integer number system.

> The use of Group and Tag is reminiscent of the early Windows NT days. These tags are rarely used in practice. Most drivers should have no dependencies on other drivers (only on kernel libraries linked to the driver, such as NDIS.sys).

Here are the guidelines by which drivers set their Start value:

+   - Non–Plug and Play drivers set their Start value to reflect the boot phase they want to load in.
- Drivers, both Plug and Play and non–Plug drivers, that must be loaded by the boot loader during the system boot specifies a Start value of boot-start (0). Examples include system drivers and the boot file-system driver.
- A driver that isn't required for booting the system and detects that a system driver can't enumerate specifies a Start value of system-start (1). An example is the serial port driver, which informs the PnP manager of the presence of standard PC serial ports that were recorded in the registry.
