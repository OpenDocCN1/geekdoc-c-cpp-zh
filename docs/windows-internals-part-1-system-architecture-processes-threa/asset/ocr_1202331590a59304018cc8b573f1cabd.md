**3-7** Smss certificate.

On Windows 10 and Windows Server 2016, the following processes are PPL signed with WinTcb-Lite: smss.exe, csrss.exe, and wininit.exe. Lass.exe is running as PPL on ARM-based Windows (such as Windows mobile 10) and can run as PPL on x86/x64 if configured as such by a registry setting or by policy (see Chapter 7 for more information). Additionally, certain services are configured to run as Windows PPL or protected processes, such as sppsvc.exe (Software Protection Platform). You may also notice certain service-hosting processes (svchost.exe) running with this protection level, since many services, such as the AppX Deployment Service and the Windows Subsystem for Linux, also protected. More information on protected services will be described in Chapter 9 in Part 2.

The fact that these core system binaries are TCB is critical to the security of the system. For example, Csrss.exe has access to certain APIs implemented by the Windows Manager (Win32k.sys), which could give an attacker Administrator rights access to sensitive parts of the kernel. Similarly, Smss.exe and Wininit.exe implement system startup and management logic is critical to perform without possible interference from an administrator. Windows guarantees that these binaries will run as WinTcb-Lite so that, for example, it is not possible for someone to launch them without specifying the correct process level in the process attributes when calling CreateProcess. This guarantee is known as the minimum TCB list and forces any processes with the names in Table 3-3 that are in a System path to have a minimum protection level and/or signing level regardless of the caller's input.
