# Driver and application control of device power

In addition to responding to power manager commands related to system power-state transitions, a driver can unilaterally control the power state of its device. In some cases, a driver might to reduce the power consumption of a device if the device is inactive for a period of time. Examples include monitors that support dimmed mode and docks that support spin-down. A driver can either detect an idle device or use facilities provided by the power manager. If the device uses the power manager, it registers the device with the power manager by calling the PoRegisterForIdleDetection.

This function informs the power manager of the timeout values to detect whether a device is idle and, so, the device power state that the power manager should apply. The driver specifies two timeouts: one when the user has configured the computer to conserve energy and the other when the user has configured the computer for optimum performance. After calling PoRegisterForIdleDetection, the driver calls PoSetDeviceBusyEx or PoSetDeviceBusy functions, whenever the device is active, and then, register for idle detection by enabling and re-enable it as needed. The PoStartDeviceBusy and PoEndDeviceBusy APIs are available well, which simplify the programming logic required to achieve the behavior described.

Although a driver has control over its own power state, it does not have the ability to manipulate the system power state or to prevent system transitions from occurring. For example, if a badly designed driver does not support any low-power states, it can choose to remain on or turn itself off without hindering the system's overall ability to enter a low-power state—this is because power manager only notifies the driver of a transition and doesn't ask for consent. Drivers receive a power query IRP (IRP_MN_QUERY_POWER) when the system is about to transition to a lower power state.
