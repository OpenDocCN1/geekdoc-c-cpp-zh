+   - Variable vs. Fixed A value of 1 means to enable the variable quantum based on the algorithm shown in the "Variable quanta" section. A setting of 0 or 3 means the default appropriate for the system will be used (variable for client systems, fixed for server systems).

+   - Priority Separation This field (stored in the kernel variable PsPrioritySeparation) defines the priority separation (up to 2), as explained in the "Variable quanta" section.

When you use the Performance Options dialog box (refer to Figure 4-10), you can choose from only two combinations: short quanta for foreground quantums, or long quanta with no quantum changes for foreground threads. However, you can choose other combinations by modifying the Win32PrioritySeparation registry value directly.

Threads that are part of a process running in the idle process class always receive a single quantum thread, ignoring any sort of quantum configuration settings, whether by default or through the registry.

On Windows servers configured as application servers, the initial value of the Win32PrioritySeparation registry value will be hex 26, which is identical to the value set by the Optimize Performance for Programs option in the Performance Options dialog box. This selects quantum and priority-boost behavior that is on Windows client systems, which is appropriate for a server used primarily to host users' applications.

On Windows clients and servers not configured as application servers, the initial value of the Win32PrioritySeparation registry setting will be 2. This provides values of 0 for the Short vs. Long and Variable vs. Fixed bits, relying on the default behavior of the system (depending on whether it is a client system or server system) for these options. However, it provides a value of 2 for the Priority Separation field. After the registry value has been changed by the Performance Options dialog box, it cannot be restored to this original value without modifying the registry directly.
