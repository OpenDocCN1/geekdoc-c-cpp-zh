

10. Rt1CloneUserProcess 通过调用 Rt1CreateUserProcess 完成操作，该用户态函数负责通用的创建工作，并传递标志位以指示新进程应该是当前进程的克隆。`Rt1CreateUserProcess` 接着调用 `ZwCreateUserProcess` 请求内核创建进程。

在创建克隆进程时，`ZwCreateUserProcess` 执行大部分代码路径与创建新进程时相同，但 `PsAllocateProcess` 除外——它调用该函数创建进程对象和初始线程，并调用 `MmInitializeAddressSpace` 传递一个标志，指定地址空间应该是目标进程的写复制（copy-on-write）副本，而不是初始地址空间。内存管理器使用提供为 Unix 应用服务（Services for Unix Applications）的相同空间高效地克隆地址空间。一旦目标进程继续执行，对其地址空间的任何更改只有它自己可见，克隆进程不可见。这使得克隆的地址空间能够代表目标进程某一时间点的视图。

克隆进程的执行从 `Rt1CreateUserProcess` 返回后的点开始。如果克隆创建成功，它将返回 `STATUS_PROCESS_CLONED` 代码；而克隆线程随后会与目标进程进行同步，最后调用一个可选传递给 `Rt1CreateProcessReflection` 的函数，该函数对进程进行分析并将结果报告给调用 `Rt1CreateProcessReflection` 的线程。如果没有函数执行失败，线程将根据传递给 `Rt1CreateProcessReflection` 的标志位进行挂起或终止。

当 RAD 和 WDI 处理进程反射时（请求函数返回克隆进程的句柄并让克隆在初始化后自挂起），它们会生成目标进程的转储（dump），这将挂起目标进程以便生成转储。接下来，它们会为克隆进程生成更全面的转储。在生成克隆转储后，它们会终止克隆进程。在最小转储（minidump）完成与克隆创建的时间窗口，目标进程可以执行，但对于大多数场景，任何不一致之处都不会影响故障排除。Sysinternals 的 `Procdump` 工具在指定 `-r` 交换创建目标进程的反射转储（reflected dump）时也遵循这些步骤。

# 结论

本章研究了 Windows 内存管理器如何实现虚拟内存管理。与大多数现代操作系统一样，每个进程都被赋予了私有地址空间的访问权限，通过允许进程高效且安全地共享内存，保护一个进程的内存免受另一个进程的影响。此外还有可用功能，例如包含映射文件以及稀疏分配内存的能力。Windows 环境子系统通过 Windows API 为应用程序提供了内存器的大部分功能。

# I/O 系统

Windows I/O 系统由几个内核组件组成，这些组件共同管理硬件设备，并为应用程序和系统提供硬件设备的接口。本章列出了 I/O 系统的设计目标，这些目标影响了它的实现。随后涵盖了构成 I/O 系统的组件，包括 I/O 管理器、即插用（PnP）管理器和电源管理器。然后，它检查了 I/O 系统的结构、组件以及各种类型的设备驱动程序。它讨论了描述设备、设备驱动程序和 I/O 请求的关键数据结构，之后描述了 I/O 请求在系统中移动时完成这些请求所需的步骤。最后，它介绍了设备检测、驱动程序安装和电源管理工作。

# I/O 系统组件

Windows I/O 设计的设计目标是为应用程序提供设备（物理）和软件（虚拟或逻辑）的抽象，并具有以下特性：

- 跨设备的统一安全性和命名，以提供可共享资源。（请参见第 7 章“安全性”中对 Windows 安全模型的描述。）

- 高性能异步基于包的 I/O，允许实现可扩展的应用程序。

- 允许使用高级语言编写驱动程序并能轻松地在不同机器架构之间迁移的服务。

- 分层和可扩展性，允许添加驱动程序以透明地修改其他驱动程序或设备的行为，而无需更改其行为或设备。

- 设备驱动程序的动态加载和卸载，使得驱动程序可以按需要加载，并在不需要时不消耗系统资源。

- 支持即插即用（Plug and Play），系统定位并安装新检测到硬件的驱动程序，分配其所需的硬件资源，并允许应用程序发现并激活设备接口。

- 支持电源管理，使系统或单个设备进入低功耗状态。

- 支持多个可安装的系统，包括 FAT（及其变体 FAT32 和 exFAT）、CD-ROM 文件系统（CDFS）、通用磁盘格式（UDF）文件系统、弹性文件系统（ReFS）以及 Windows 文件系统（NTFS）。（请参见本书第二部分的第 13 章关于文件类型和架构的更具体信息）。

- Windows 计时（WMI）支持和诊断，可以通过 WMI 和脚本对驱动程序进行管理和监控。（WMI 在书第二部分的第 9 章“管理机制”中描述。）

# I/O 管理器

I/O 管理器是 I/O 系统的核心。它定义了有序框架或模型，I/O 请求在该框架内传递给设备驱动程序。I/O 系统是基于包的。大多数 I/O 请求由 I/O 请求包（IRP）表示，IRP 是包含完整描述 I/O 请求信息的数据结构。IRP 在 I/O 系统组件之间移动（正如你在“快速 I/O”节中发现的，快速 I/O 是例外；它不使用 IRP）。该设计允许单个应用程序线程并发管理多个 I/O 请求。（有关 IRP 的更多信息，请参见本章后面的“I/O 请求包”部分。）

I/O 管理器在内存中创建一个 IRP 来表示 I/O 操作，将指针传递给正确的驱动程序并在 I/O 操作完成后销毁它。相反，驱动程序接收 IRP，执行指定的操作或 IRP，并将 IRP 回传给 I/O 管理器，要么是因为请求的 I/O 操作已完成，要么必须传递给其他驱动程序进行进一步处理。
