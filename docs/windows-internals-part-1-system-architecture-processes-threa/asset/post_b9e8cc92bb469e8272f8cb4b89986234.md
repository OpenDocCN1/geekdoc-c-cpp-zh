# x86 session space

For systems with multiple sessions (which is almost always the case, as session 0 is used by system processes and services, while session 1 is used for the first logged on user), the code and data unique to each session are mapped into system address space but shared by the processes in that session. # System page entries

System page entries (PTEs) are used to dynamically map system pages such as I/O space, kernel stacks, and memory descriptor lists (MDLs, discussed in extent in Chapter 6). On 32-bit Windows, PTEs are not an infinite resource. The number of available PTEs is such that the system can theoretically describe 2 GB of contiguous virtual space. On Windows 64-bit and Server, PTEs can describe up to 16 TB of contiguous virtual space.

> EXPERIMENT: Viewing PTE information
You can see how many PTEs are available by examining the value of the Free System Page Entries counter in Performance Monitor or by using the !syspte or !vm command in the debugger; you can also dump the _MI_SYSTEM_PTE structure as part of the memory state (MiState) or the MiSystem global variable on Windows 8. This will show how many PTE allocations occur on the system. A high count indicates a possibly PTE leak.

```
kd> !syspte Information
```

# 64-bit address space layout

The theoretical 64-bit virtual address space is 16 exabytes (EB), or 18,446,744,073,709,551 bytes. Current processor limitations allow for 48 address lines only, limiting the possible address space to 256 TB (to the 48th power). The address space is divided in half, where 128 TB is per process and the other 128 TB is used for system space. Windows 8 and Server 2012 are limited to 16 TB. This is because of Windows implementation limits, described in Chapter 10 of the sixth edition of Windows Internals Part 2.
