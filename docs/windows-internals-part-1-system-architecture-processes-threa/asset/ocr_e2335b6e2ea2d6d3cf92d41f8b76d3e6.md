If you select Process Explorer at the lower part when configured to view DLLs, you'll see nothing. That is because Process Explorer uses user-mode APIs to query the loaded modules and requires access that is not granted for accessing protected processes. The notable exception is the System process, which is protected, but Process Explorer shows the list of kernel modules (drivers) since there are DLLs in system processes. This is done using EnumDevDrivers API, which is a system API that does not require a process handle.

If you switch to Handle view, you'll see complete handle information. The reason is similar: Process Explorer has an undocumented API that returns all handles on the system, which does not require a specific process handle. Process Explorer can identify the process simply because this information returns the PID associated with each handle.

# Third-party PPL support

The PPL mechanism extends the protection possibilities for processes beyond executables created solely by Microsoft. A common example is anti-malware software. A typical AM product consists of three main components:

+   - A kernel driver intercepts I/O requests to the file system and/or the network, and implements blocking capabilities using object, process, and thread callbacks
- A user-mode service (typically running under a privileged account) that configures the drivers policies, receives notifications from the driver regarding "interesting" events (for example, infected file), and may communicate with a local server or the Internet
- A user-mode GUI process that communicates information to the user and optionally allows the user to make decisions where applicable.

One possible malware can attack a system is by managing to inject code into a process running with elevated privileges, or inject code specifically inside an anti-malware service and thus tamper with it or disable its operation. However, if the AM service could run as a PPL, code injection would be possible, and no process termination would be allowed, meaning that the AM software would be better protected from malware that does not employ kernel-level exploits.
