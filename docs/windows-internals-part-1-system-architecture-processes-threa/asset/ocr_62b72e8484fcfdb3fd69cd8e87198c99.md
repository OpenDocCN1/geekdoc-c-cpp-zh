# # Heap manager

Most applications allocate smaller blocks than the 64-KB minimum allocation granularity possible using page-granularity functions such as VirtualAlloc. Allocating such a large area for relatively small allocations is not optimal from a memory usage and performance standpoint. To address this, Windows provides a component called the heap manager, which manages allocations inside memory areas reserved using the page-memory-allocation functions. The granularity in the heap manager is relatively small: 8 bytes on 32-bit systems, and 16 bytes on 64-bit systems. The heap manager has been designed to optimize memory usage and performance in the case of these smaller allocations.

The heap manager exists in two places: Ntdll.dll and Ntosnl.exe. The subsystem APIs (such as the Windows heap APIs) call the functions in Ntdll.dll, and various executive components and device drivers call the functions in Ntosnl.exe. Its native interfaces (prefixed with Rt) are available only for use within Windows components or kernel-mode drivers. The Windows API interfaces to the heap (prefixed with Heap) are forwards to the native functions in Ntdll.dll. In addition, legacy APIs (prefixed with either Local or Global) are provided to support older Windows applications. These also call the heap manager, using some of its specialized interfaces to support legacy behavior. The most common Windows heap functions are:

+   - HeapCreate or HeapDestroy These create or delete, respectively, a initial request and size can be specified at creation.
- HeapAlloc This allocates this block. It is forwarded to Rt1AllocateHeap in Ntdll.dll.
- HeapFree This frees a block previously allocated with HeapAlloc.
- HeapReAlloc This changes the size of an existing allocation, growing or shrinking an existing block. It is forwarded to Rt1ReAllocHeap in Ntdll.dll.
- HeapLock and HeapUnlock These control mutual exclusion to heap operations.
- HeapWalk enumerates the entries and regions in a heap.
