Windows keeps track of threads that become inactive because they block on something other than the completion port or the completion port by relying on the queue pointer in a thread's control block. The scheduler that possibly result in a thread blocking (as the WaitForSingleObject, KeDelayExecutionThread, and so on) checks the thread's queue pointer. If the pointer isn't NULL, it calls KIActivateWaitQueue, a queue-related function that decrements the count of active threads associated with the queue. If the resulting number is less than the maximum and at least one completion is in the queue, the thread at the front of the queue thread list is awakened and the oldest packet. Conversely, a thread that is associated with a queue wakes up after blocking, the scheduler executes the KIWaitThread function, which increments the queue's active count.

The PostQueuedCompletionStatus Windows API function returns in execution of the NtSetIoCompletion system service. This function simply inserts the specified packet onto the completion port's queue by using KeInsertQueue.
