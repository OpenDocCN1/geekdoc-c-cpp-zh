# 驱动程序的结构

I/O 系统驱动设备驱动程序的执行。设备驱动程序由一组例组成，这些例被调用以处理 I/O 请求的不同阶段。图 6-9 展示了关键的驱动函数例，将在下文中进行描述。

![](img/ff0e6a9d867a3a6e9527eb1d946810fc_514_0.png)

图 6-9 主要设备驱动程序例。

- 初始化例 WDK：I/O 管理器执行驱动程序初始化例，该例由 WDK 在驱动程序加载到操作系统时通过 DriverEntry 设置。DriverEntry 初始化编译器对栈溢出错误的保护（称为 cookie），然后调用 DriverEntry（此处原文或指代实现逻辑），这是驱动程序编写人员必须实现的。该例填充数据结构以向 I/O 管理器注册驱动程序例，并执行任何必要的全局初始化。

- 添加设备例：支持即插即用的驱动程序会实现添加设备例。每当检测到该驱动程序负责的设备时，PnP 管理器都会向驱动程序发送通知。在此例中，驱动程序通常会创建一个设备对象（在本章稍后部分描述）来表示该设备。

- 一组分发例 Dispatch：分发例是主入口点。包括 open（打开）、close（关闭）、read（读取）和 write（写入）等分发例。当 I/O 管理器调用这些例以执行操作时，会生成 IRP。

- 启动例：驱动程序可以使用启动例来从设备或向设备传输数据。I/O 管理器通过确保驱动程序一次处理一个 IRP 来实现序列化，驱动程序可以并发处理多个 IRP。

- 中断服务例 ISR：当设备中断时，I/O 管理器调用 ISR。在 I/O 模型中，ISR 在 IRQL 级别运行以尽可能减少工作。

- 中断处理 DPC：DPC 在 IRQL 级别执行。I/O 管理器通过调用 DPC 来处理 IRP 的剩余工作。

- 完成完成例：I/O 管理器在完成 IRP 后通知文件驱动程序操作的成功、失败或取消。只有依赖中断的驱动程序才具有完成例。

- 取消 I/O 例：如果 I/O 操作可以取消，I/O 管理器会分配取消例。如果线程在操作完成前取消 IRP（例如通过 CancelIo 函数），I/O 管理器执行取消例。

- 快速分发例：使用缓存管理器的驱动程序通常为内核提供这些例，以绕过典型的 I/O 路径直接访问数据。快速分发例也是内存管理器和缓存管理器对文件驱动程序的回调机制。例如，在创建节时，内存管理器调用文件驱动程序来独占文件。

- 卸载例：卸载例释放使用的系统资源，以便 I/O 管理器从内存中移除驱动程序。在初始化例（DriverEntry）中获取的资源通常在卸载例中释放。如果驱动程序支持，可以在系统运行时进行加载和卸载，但只有在所有设备文件关闭后才会调用卸载例。

- 系统关机通知例：该例允许在系统关机时进行驱动清理。

- 错误日志例：当发生意外错误时（例如磁盘块损坏），驱动程序的错误日志例会记录发生并通知 I/O 管理器。I/O 管理器会将这些信息写入错误日志。

# 驱动程序对象和设备对象

当线程打开文件对象（在本章后的“I/O 处理”部分描述）时，I/O 管理器必须确定调用哪个驱动程序来处理请求。此外，当 I/O 管理器下次使用相同的文件句柄时必须定位这些信息。以下对象填充了这一需求：

- 驱动程序对象：代表系统中的单个驱动程序（DRIVER_OBJECT 结构）。I/O 管理器从驱动程序对象获取驱动程序每个分发例的地址。

- 设备对象：代表系统上的物理或逻辑设备（DEVICE_OBJECT 结构），并描述其特征，例如缓冲区对齐要求和用于存储传入 IRP 的设备队列位置。它是所有 I/O 操作的目标，因为硬件与此对象进行通信。
