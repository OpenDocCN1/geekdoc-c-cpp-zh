# Address Windows Extensions

Although the 32-bit version of Windows can support up to 6 GB of physical memory (refer to Table
2-2), each 32-bit user process has only 2 GB virtual address space by default. (You can configure this
to up to 3 GB using the increaseuser GBC option, described in the section "Virtual
address space layouts.") An application that needs to make more than 2 GB (or 3 GB) of data easily
available in a single process could do so via file mapping, remapping a part of its address space into
portions of a large file. Significant paging will be invoked upon each remap.

For higher performance (and more finer-grained control), Windows provides a set of functions
Address Windows Extensions (AWE). These functions allow to allocate more physical memory
than can be represented in its virtual address space. It can then access the physical memory by mapping
port of its virtual address space into selected portions of the physical memory at various times.

You allocate and use memory via the AWE functions in three steps:

+   1. You allocate the physical memory to use. The application uses the Windows functions
AllocateUserPages or AllocateUserPagesNum. (These require the
SeLockMemoryPrivilege.)

+   2. You create one or more regions of virtual address space to as to map views of the
physical memory. The application uses the Win32 VirtualA1AllocAlloc, VirtualA1AllocEx, or Virtual-
A1AllocExnum with the MEM_PHYSICAL flag.

+   3. Steps 1 and 2 are, generally speaking, initialization steps. To actually use the memory, the applic-
 uses MapUserPhysicalPages or MapUserPhysicalPagesScatter to map a portion of the
physical region allocated in step 1 into one of the regions, or allocated in step 2.
