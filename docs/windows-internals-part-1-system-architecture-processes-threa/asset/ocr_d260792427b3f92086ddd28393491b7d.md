A process to grow beyond 2 GB of address space, the image file must have the IMAGE_FILE_LARGE_ADDRESS_AWARE flag set in the image header (in addition to the global increaseusersva setting). Windows reserves the additional address space for process the application won't see virtual addresses greater than 0xFFFFFFFF. Access to the additional virtual memory is opt-in because some applications assume they'll be at most 2 GB of the address space. Because the high bit of a pointer referencing an address below 2 GB is always zero (31 bits are needed to refer to a 2 GB address space), applications would use the high bit in their pointers as a flag for their other data—clearing it, of course, before referencing the data. If they run with a 3 GB address space, would inadvertently truncate pointers that have values greater than 2 GB, causing program errors, including possible data corruption. You set this flag by specifying the /LARGEADDRESSAWARE linker flag when building the executable. Alternatively, use the property in Visual Studio (choose Linker, select System, and click Enable Large Addresses). You can add the flag to an executable image even without building (no source code required) by using a tool as Edin.exe (part of the Windows SDK toolkit), assuming the file is not signed. This flag has no effect when running the application on a system with 2 GB user address space.

Several systems are marked as large address space so that they can take advantage of systems running with large process address spaces. These include the following:

+   - LSass.exe The Security Authority Subsystem
- Ininet.exe Internet Information Server
- Chkdsk.exe The Check Disk utility
