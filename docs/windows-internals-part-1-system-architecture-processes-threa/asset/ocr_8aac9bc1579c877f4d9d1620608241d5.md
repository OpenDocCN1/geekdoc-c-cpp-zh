To control who can manipulate an object, the security system must be sure of each user's identity. This need to guarantee the user's identity that Windows requires authenticated login before accessing any system resources. When a process requests a handle to an object, the object manager and the security system use the caller's security identification and the object's security descriptor to determine whether the caller should be assigned a handle that grants the process access to the object.

As discussed later in this chapter, a thread can assume a different security context than that of its process. This mechanism is called impersonation. When a thread is impersonating, security validation mechanisms use the thread's security context instead of that of the thread back. When a thread isn't impersonating, security validation fails back using the security context of the thread's owner. It's important to keep in mind that all the threads in a process share the same handle table, so when a thread opens an object—even if it's impersonating—all of the process have access to the object.

Sometimes, the identity of a user isn't enough for the system to grant access to a resource that should be accessible by the account. Logically, one can think of a clear distinction between a service running under the Alice account and an unknown application that Alice downloaded browsing the Internet. Windows achieves this kind of intra-user isolation with the integrity mechanism, which Windows integrity mechanism is managed by User Account Control (UAC) elevations, User Interface Privilege Isolation (UIPI) and AppContainers, all described later in this chapter.

# Access checks

The Windows security model requires that a thread specify up front, at the time it opens an object, what types of actions it wants to perform on the object. The object manager calls the SRM to perform access checks based on the thread's desired access. If the access is granted, a handle is assigned to the thread's process with which the thread (or other threads in the process) can perform further operations on the object.
