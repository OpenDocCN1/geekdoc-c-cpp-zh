# TABLE 5-2 Memory-protection options defined in the Windows API

| Attribute | Description |
| --- | --- |
| PAGE_NOACCESS | Any attempt to read from, write to, or execute code in this region causes an access violation. |
| PAGE_READONLY | Any attempt to write to (on processes with no execute support, execute code in) memory causes an access violation, but reads are permitted. |
| PAGE_READWRITE | The page is readable and not executable. |
| PAGE_EXECUTE | Any attempt to write to memory in this region causes an access violation, but execution (read operations on all executing processes) is permitted. |
| PAGE_EXECUTE_READ* | Any attempt to write to memory in this region causes an access violation, but executes and reads are permitted. |
| PAGE_EXECUTE_READWRITE* | The page is readable, writable, and executable. Any attempted access will succeed. |
| PAGE_WRITECOPY | Any attempt to write to memory in this region causes the system to give a private copy of the page. On processes with no execute support, attempts to execute code in this region cause an access violation. |
| PAGE_EXECUTE_WRITECOPY | Any attempt to write to memory in this region causes the system to give a private copy of the page. Reading and executing code in this region is permitted. (No copy is made in this case.) |
| PAGE_GUARD | Any attempt to read from or write to a guard page raises an EXCEPTION_PAGE exception and turns the guard status. Guard pages can then be specified with any of the page protections listed in this table example PAGE_NOACCESS. |
| PAGE_NOCACHE | This uses physical memory that is not cached. This is not recommended for general usage. it is useful for device drivers—for example, mapping a video buffer with no caching |
| PAGE_WRITECOMBINE | This enables combined memory accesses. When the processor does not cache writes (possibly significantly more memory traffic than if memory writes were cached), but it tries to aggregate write requests to optimize performance. For example, if multiple writes are made to the same address, only collapsed into a single line. Separate writes to different addresses may be delayed—this is not typical for general applications, but it is useful for device drivers—for example, mapping a video buffer as written |

PAGE_TARGETS_INVALID and PAGE_TARGETS_NO_UPDATE (Windows 10 and Windows Server 2016) These values control Control Flow Guard (CFG) for executable code in these pages. These constants have the same value but are used in different calls, essentially acting as a proxy. PAGE_TARGETS_NO_UPDATE indicates that direct calls should fail but allows Protect to change the page range to exclusion without updating CFG state. See "Chapter 7, Security", for more information on CFG.
