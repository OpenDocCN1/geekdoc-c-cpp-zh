# Power availability requests

Applications and drivers cannot veto sleep transitions that are already initiated. However, certain scenarios demand a mechanism for disabling the ability to initiate sleep transitions when a user is interacting with the system in certain ways. For example, if the user is currently watching a movie and the machine would normally go idle (based on a lack of mouse or keyboard input after 15 minutes), the media player application should have the capability to temporarily disable idle transitions as long as the movie is playing. You can probably imagine other power-saving measures that the system would normally undertake, such as turning off or even diminishing the screen, which would also limit your enjoyment of visual media. In legacy versions of Windows, SetThreadState was a user-mode API capable of controlling system and display idle transitions by informing the power manager that a user is still present on the machine. However, this API did not provide any sort of diagnostic granularity for defining the availability request. Also, drivers could not issue their own requests, and even user applications to correctly manage their threading model, because these requests were at the thread level, not at the process or system level.

Windows now supports power requests, which are implemented by the kernel and bona-defined objects. You can use the WinObj utility from Sysinternals (more details on this tool are in Chapter 8 of Part 2) and see the PowerRequest type in the ObjectTypes directory, or use the _object kernel debugger command the ObjectTypes\PowerRequest object type, to validate this.

Power availability requests are generated by user-mode applications through the PowerCreate-Request API and then enabled with the PowerRequest and PowerClearRequest APIs, respectively. In the kernel, drivers use PoCreatePowerRequest, PoSetPowerRequest, and PoClear-PowerRequest. Because handles are used, PoDeletePowerRequest is needed to remove the reference on the object (while user mode can simply use CloseHandle).

There are four kinds of requests that can be called through the Power Request API:

+   **System request** This request asks the system not automatically go to sleep during the idle timer (although the user can still close the lid to enter sleep, for example).
**Display request** This type of request does the same as a system request, but for the display.
**Away-mode request** This is a modification to the normal sleep (S3 state) of Windows, which is used to keep the computer in full power-on mode with the display and sound turned off, making it appear to the user as though the machine is really sleeping. This behavior is normally used only by specialized set-box readers or media center devices whose memory delivery must continue even though the user has pressed a physical sleep button, for example.
**Execution request** This type of request (starting with Windows 8 and Server 2012) is a UWP app process continue execution if normally the Power Lifecycle Manager (PLM) has terminated it (whatever reason); the extended length of time depends on factors such as the power policy settings. This request type is only supported for systems that support Modern Standby, otherwise this request is interpreted as a system request.
