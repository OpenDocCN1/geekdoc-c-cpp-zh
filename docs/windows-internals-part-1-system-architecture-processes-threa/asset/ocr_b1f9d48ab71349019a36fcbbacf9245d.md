+   Active Directory This is a directory service that contains a database stores information about objects in a domain. A Domain is a collection of computers and their associated security groups that are managed as a single entity. Active Directory stores information about the objects in the domain, including users, groups, and computers. Password information and privileges for domain users and groups are stored in domain controllers of the domain. The Active Directory server, implemented as Ntdsa.dll, runs in the LSass process and replicated across the computers. For more information on Active Directory, see Chapter 10, "Networking," in Part 2.

+   Authentication packages These include dynamic link libraries (DLLs) that run in the context of both Lsass process and client processes implement Windows authentication. An authentication DLL is responsible for authenticating a user by checking whether a given user and password match (or whatever mechanism was used to provide credentials), and if so, returning to Lsass information detailing the user's identity, which Lsass uses to generate a token.

+   Interactive logon manager (Winlogon) This is a user-mode process Winlogon. which is responsible for responding to the SAS and managing interactive logon sessions. Winlogon creates a user's first process when the user logs on, for example.

+   Logon user interface (LogonUI) This is a user-mode process running the LogonUI. which presents to the user interface they can authenticate themselves on the system. LogonUI uses credentials to obtain user credentials through various methods.

+   Credential providers (CPs) These are in-process COM objects that run in the Logon process (started by Winlogon when the SAS is performed) and to obtain a user's name and password, smart PIN, biometric data (such as a fingerprint), or other identification mechanism. The standard CPs are authui.dll, SmartCredentialProvider.dll, BioCredProv.dll, and FaceCredentialProvider.dll, a face-detection provider added in Windows 10.

+   Network logon service (Netlogon) This is a Windows service Netlogon, hosted in a standard SvchHost that sets the secure channel to a domain controller, over which requests—as an interactive logon (if the domain controller is running Windows NT 4) or LAN Manager and NT LAN Manager (v1 and v2) authentication validation—are. Netlogon is also used for Active Directory logins.

+   Kernel Security Driver (KSecDD) This is a kernel-mode library (%SystemRoot%\System32\Drivers\KSecdd.sys) of functions that implement the advanced local procedure call (ALPC) interfaces that handle other kernel security components, including the Encrypting File System (EFS), to communicate with Lsass in user mode.

+   AppL This mechanism allows administrators to specify which executable files, DLLs, and scripts can be used by specified users and groups. AppLocker consists of a driver (%SystemRoot%\System32\Drivers\Appid.sys) and a service (AppidSvc.dll) running in a standard SvchHost process.
