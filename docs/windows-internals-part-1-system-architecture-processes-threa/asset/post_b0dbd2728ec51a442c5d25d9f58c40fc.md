
One reason zero-initialized pages are needed to meet security-mode requirements such as the Common Criteria (CC). Most CC profiles specify that user-mode processes be initialized page frames to prevent them from reading a previous process's memory contents. Thus, the memory manager uses user-mode processes zeroed page frames unless the page is read from a backing store. In that case, the memory manager prefers to use non-zeroed page frames, initializing them with the data off the disk or remote storage. The zero page is populated from the free list by the zero page thread (in the System process). The zero page thread waits on a gate object to signal it to go to work. When the free list has eight or more pages, this gate is signaled. However, the zero page thread runs only if at least one processor has no other threads running, because the zero page thread runs at priority 0 and the lowest priority that a user can set is 1.

> Note: When memory needs to be zeroed as a result of a page allocation by a driver that calls MmAllocatePages(Ex), by a Windows application that allocates pages, the memory manager zeros the memory by using a higher-performing function MiZeroInPara which maps regions over the zero page thread, which only zeros a page at a time. In addition, multiprocessor systems, the memory manager creates additional system threads to perform the zeroing in parallel (and in a NUMA-optimized fashion over NUMA platforms).

- When the memory manager doesn't require a zero-initialized page, it goes to the free list. If it's empty, it goes to the zero list. If the zero list is empty, it goes to the standby lists. Before the memory manager can use a page frame from the standby lists, it must first backtrack and remove the reference from the invalid PTE (or prototype PTE) that still points to the page frame. Because entries in the PFN database count back to the previous user's page table (or a page of prototype PTE pool for shared pages), the memory manager can quickly find the PTE and make the appropriate change.
- When a process must give up a page of its working set if its set was full or the memory manager trimmed its set, the page goes to the standby lists if the page was clean (not modified) or to the modified list if the page was modified while it was resident.
- When a process exits, all the private pages go to the free list. Also, when the last reference to a page-file-backed section is closed, and the section has no remaining mapped views, these pages also go to the free list.

## EXPERIMENT: The free and zero page lists

You can observe the release of private pages at process exit with Process Explorer's System Information display. Begin by creating a process with numerous private pages in its working set. We did this in an earlier experiment with the TestLimit utility:

```
C:\Tools\Sysinternals\Testlimit.exe -d 1 -c 1500
```

The -d option causes Testlimit not only to allocate the memory as private committed, but to touch—that is, to access. It causes physical memory to be allocated and assigned to the process to realize the area of private virtual memory. If there is sufficient available RAM on the system, the entire 1500 MB should be in RAM for the process. The process will wait until you choose to exit or terminate (by perhaps pressing Ctrl+C in the command window). After you, follow these steps:

1. Open Process Explorer.
2. Open the View menu, choose System Information, and click the Memory tab.
3. Observe the size of the Free and Zeroed lists.
4. Terminate or exit the TestLimit process.

You may see the free list briefly increase in size. We say "may" because the zero page thread is awakened as soon as there are only eight pages on the free, and it acts very quickly. Process Explorer updates this display only once per second, and it is likely that most of the pages were already zeroed and moved to the zeroed page list before it happened to "catch" this state. If you can see the temporary increase in the free list, you will then see it drop to zero, and a corresponding increase will occur in the zeroed page list. If not, you will simply see the increase in the zeroed list.
