# Priority boosts for multimedia applications and games

Although Windows' CPU-starvation priority boosts might be enough to get a thread out of abnormally long wait state or priority deadlock, they simply cannot deal with the resource requirements imposed by a CPU-intensive application such as Windows Media Player or a 3D game.

Skipping and other audio glitches have long been a common source of irritation among Windows users. The Windows user-mode audio stack exacerbates this because it offers even more chances for preemption. To address this, this client version of Windows uses the MMCSS driver (described earlier in this chapter), implemented in %SystemRoot%\System32\Drivers\MMCSS.sys. Its purpose is to glitch-free multimedia playback for all applications that register with it.

> Note Windows 7 implements MMCSS as a service (rather than a driver). This posed a potential risk, however. If the MMCSS managing thread blocked for any reason, the threads managed by it would retain their time-priority, potentially causing system-wide starvation. The solution was to move the code to the kernel where managing the thread (and other resources used by MMCSS) could not be touched. There are other benefits to being a kernel driver, such as holding a direct pointer to process and thread objects rather than IDs or handles. This bypasses searches based on IDs and handles faster communication with the scheduler and Power Manager.

Client applications can register with MMCSS by calling AvSetThreadCharacteristics with a task name that must match one of the subkeys under HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Multimedia\SystemProfile\Tasks. (The list can be modified by OEMs specific tasks as appropriate.) Out of the box, the following tasks exist:

+   * Audio
* Capture
* Distribution
* Games
* Low Latency
* Playback
* Pro Audio
* Window Manager
