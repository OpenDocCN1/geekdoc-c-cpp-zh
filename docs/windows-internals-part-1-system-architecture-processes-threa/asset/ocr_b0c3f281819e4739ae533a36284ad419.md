With this technology, a "base" system called MinWin is defined (and, at the source level, built), with a minimum set of services that includes the kernel, core drivers (including file systems), system processes such as CSRSS and the Service Control Manager, and a handful of Windows services. Windows Embedded, with its Platform Builder, provides what might be a similar technology, as system builders are able to remove "Windows components," such as the shell, or the network stack. However, removing components from Windows leaves dangling-code paths that, if exercised, would fail because they depend on the removed components. MinWin's dependencies, on the other hand, are entirely self-contained.

When the process manager initializes, it calls the PspInitializeApiSetMap function, which is responsible for creating a section object of the API redirection table, which is stored in %SystemRoot%\System32\ApiSchema.dll. The DLL contains no executable code, but it has a section .api that contains API setting data that maps virtual API sets to DLLs that implement the APIs. Whenever a new process starts, the process manager maps the section object into the process's address space and sets the ApiSetMap field in the PEB to the base address where the section was mapped.

In the loader, LdrLoadFileNameirection function, which is normally responsible for local and Sx/Fusion redirection that was mentioned earlier, also checks for API redirection whenever a new import library has a name starting with API- (either dynamically or statically). The API table is organized by library with each entry describing in which DLL the function can, and that DLL gets loaded.
