
Additionally, because lookups in linked lists are algorithmically expensive (being done in linear time), the loader maintains two red-black trees, which are efficient lookup trees. The first is sorted by base address, while the second is sorted by the hash of the module's name. With these, the searching algorithm can run in logarithmic time, which is significantly more efficient and greatly speeds up process-creation performance in Windows 8 and later. Additionally, as a security precaution the root of these two trees, unlike the linked lists, is not in the PE. This makes them harder to locate by shell code, which is operating in an environment where space layout randomization (ASLR) is enabled. (See Chapter 5 for more on ASLR.)

Table 3-9 lists the various pieces of information the loader maintains in an entry.

## TABLE 3-9 Fields in a loader data table

| Field | Meaning |
|---|--|
| BaseAddressIndexNode | Links this entry in a Red-Black Tree sorted by base address. |
| DllName/BaseNameHashValue | The name of the module itself, without the full path. The second field stores its hash using RtlHashUniCodeString. |
| DdagNode/NodeModuleLink | A pointer to the data structure tracking the dependency graph (DDAG), which parallelizes loading through the worker thread pool. The second field links the structure with the LDR_DATA_TABLE_ENTRIES (part of the same graph) |
| DllBase | Holds the base address at which the module was loaded. |
| EntryPoint | Contains the initial routine of the module (as DllMain). |
| EntryPointActivationContext | Contains the Sx/Fusion activation context when calling initializers. |
| Flags | Loader state flags for this module (see Table 3-10 for a description of the flags). |
| ForwarderLinks | A list of modules that were loaded as a result of export forwards from the module. |
| FullDllName | The fully qualified path name of the module. |
| HashLinks | A list used during process startup and shutdown for quicker lookups. |
| ImplicitPathOptions | Used to store path flags that can be set by LdrImplicitPathOptions API or are inherited from the DLL path. |
| List Entry Links | Links this entry into each of the three ordered lists of the loader database. |
| LoadContext | Pointer to the current load information for the DLL. Typically NULL unless being loaded. |
| ObsoleteLoadCount | A reference count for the module (that, how many times it has loaded). This is no longer accurate and has been moved to the DDAG node structure instead. |
| LoadReason | Contains an enumeration value that explains why this DLL was loaded (dynamically, statically, as a forwarder; as a load-dependency etc.). |
| LoadTime | Stores the system time when this module was being loaded. |
| MappingInfoIndexNode | Links this entry as a node in the red-black tree sorted by the hash of the name. |
| OriginalBase | Stores the original base address (set by the linker) of this module, before ASLR or relocations, enabling faster processing of relocated imports. |

## TABLE 3-9 Fields in loader data table entry (continued)

| Field | Meaning |
|---|---|
| ParentDllBase | In case of static (or forward, or delay-load) dependencies, stores the address of the DLL that has a dependency on this one. |
| SigningLevel | Stores the signature level of this image (see Chapter 8, Part 2, for more information on the Code infrastructure). |
| SizeOfImage | The size of the module. |
