For DLLs, computing the load offset begins with a pre-boot, system-wide value called the image bias. This is computed by InitializeRelocations and stored in the global memory structure (MI_SYSTEM_INFORMATION) in the MiState.Sections.ImageBias fields (MiImageBias variable in Windows 8.x/2012/R2). This value corresponds to the TSC of the CPU when shifted and masked into an 8-bit value. There are 256 possible values on 32 bit systems; computations are done for 64-bit systems with more possible values as the address space is vast. Unlike executables, this is computed once per boot and shared across the system to allow DLLs to remain in physical memory and relocated only once. If DLLs were remapped at different locations inside processes, the code could not be shared. The loader would have to fix up addresses differently for each process, turning what had been shared-read-only code into process-private data. Each process using a DLL would have to have its own private copy of the DLL in physical memory.

Once the offset is computed, the memory manager initializes a bitmap named ImageBasetMap (MiImageBitmap variable in Windows 8.x/2012/R2), This bitmap is used to represent ranges from 0x50000000 to 0x78000000 for 32-bit systems (the numbers for 64-bit systems below), and each bit represents unit of allocation (64 KB, as mentioned). Whenever the memory manager loads a DLL, the appropriate bit is set to mark its location in the system. When the same DLL is loaded again, the memory manager shares its object with the already relocated information.

As each DLL is loaded, the system scans the bitmap from top to bottom for free bits. The ImageBias value earlier is used as a start index from the top to randomize the load across different boots. Because the bitmap will be entirely empty until the first DLL (which is always Ntdll.dll), its load address can be easily calculated (Sixty-four systems have their own bias.)

+   - 32 bit 0x78000000–(ImageBias+NtdlSize64KChunks) * 0x100000
- 64 bit 0xFFFFFF000–(ImageBias64High+NtdlSize64KChunks) * 0x10000000

Each subsequent DLL will load in a 64 KB chunk. Because of this, if the address of Ntdll.dll is known, the addresses of other DLLs could easily be computed. To mitigate this possibility, the order in which DLLs are mapped by the Session Manager during initialization is also randomized with Smss.exe loads.

Finally, if no free space is available in the bitmap (which would mean most of the region for ASLR is in use), the DLL relocation code defaults to the executable code, loading the DLL at a 64 KB chunk within 16 MB of its preferred address.
