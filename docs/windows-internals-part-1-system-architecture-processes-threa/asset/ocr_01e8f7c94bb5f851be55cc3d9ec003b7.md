# Peering into undocumented interfaces

Examining the names of the exported or global interfaces in system kernel (such as Nkrnl, Hal, or Ntdll.dll) can be enlightening—you get into the idea of things Windows can do what happens to be documented and supported today. Of course, just because you know the names of these functions means that you can or call them—the interfaces are undocumented and are subject to change. We suggest that you look at these functions purely to gain more insight into the kind of internal functions Windows performs, not to bypass unsupported interfaces.

For example, looking at the list of functions in Ntdll.dll gives you the list of all the services that Windows provides to user-mode subsystem DLLs verify the subset that each exposes. Many of these functions map clearly to documented and supported Windows functions, several are not exposed via the Windows API.

Conversely, it is also interesting to compare the imports of Windows subsystem DLLs (such as Kernel32.dll or Advapi32.dll) and which functions they call in Ntdll.dll.

Another interesting is to dump Nkrnl.exe—many of the exported functions that kernel-mode device drivers are exposed in the WDK, quite few are not.
