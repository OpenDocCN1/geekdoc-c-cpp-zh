# # Tracing and logging

SuperFetch makes most of its decisions based on information that has been integrated, parsed, and post-processed from raw traces and logs, making these two components the most critical. Tracing is like ETW in some places it uses certain triggers in code throughout the system to generate events, but it also works in conjunction with facilities provided by the system, such as power-manager notification, process callbacks, and file-system driver. The tracer also uses traditional page-aging mechanisms which are in the memory manager, as well as newer-setting aging and access tracking implemented for SuperFetch.

SuperFetch always keeps a trace running and continuously queries data from the system, which tracks page usage and access through the memory manager's access tracking and working-set aging. Trace file-related identification is critical as page usage because it allows prioritization of file data in the cache, SuperFetch leverages filtering functionality with the addition of the Fileinfo driver.(See Chapter 6 for more information on filter drivers). This driver sits on the file-system device stack and monitors access and changes to files at the stream level, which provides with fine-grained understanding of file access.(For more information on NTFS data streams, Chapter 13 in Part 2). The main job of Fileinfo is to associate streams—identified by a unique key, currently implemented as the FContext field of file object—with file names that the user-mode SuperFetch service can identify the specific file stream and offset that a page in the standby list belonging to a memory-mapped section is associated with. It also provides the interface for prefetching data transparently, without interfering with locked files and other file-system state.
