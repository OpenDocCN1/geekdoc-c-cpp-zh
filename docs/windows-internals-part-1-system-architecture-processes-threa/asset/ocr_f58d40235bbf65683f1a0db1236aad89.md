+   The small-IRP look-aside list stores these IRPs with one stack location. (IRP stack locations are described shortly.)

+   The medium-IRP look-aside list contains these IRPs with four stack locations (which can be used for IRPs that require only two or three stack locations).

+   The large-IRP look-aside list contains IRPs with more than four stack locations. By default, the system stores IRPs with 14 stack locations on the large-IRP look-aside list, but once per minute, the system adjusts the number of stack locations allocated and can increase up to a maximum of 20, based on how many stack locations have been recently required.

These lists are also backed by global look-aside lists as well, allowing efficient cross-CPU flow. If an IRP requires more stack locations than are contained in the IRPs on the large-IRP look-aside list, the I/O manager allocates IRPs from non-paged pool. The I/O manager allocates IRPs with the IoAllocateIrp function which is also available for device-driver developers, because in some cases a driver may want to initialize an I/O request directly by creating and initializing its own IRPs. After allocating and initializing an IRP, the I/O manager stores a pointer to the caller's file object in the IRP.

> Note If defined, the DWORD registry value LargeIrpStackLocations in the HKLM\System\ControlSet\SessionManager\O System key specifies how many stack locations are contained in IRPs stored on the large-IRP look-aside list. Similarly, the MediumIrpStackLocations in the same key can be used to change the size of IRP stack locations on the medium-IRP look-aside list.
