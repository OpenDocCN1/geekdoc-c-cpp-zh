The system commit total is displayed under the Committed label as two numbers. The first number represents potential page usage, not actual page usage. It is how much page file space would be used if all the private virtual memory in the system had to be backed up at once. The second number that the system can support before running out of virtual memory is the commit limit, which is the maximum memory usage (This includes virtual memory backed in physical memory as well as the paging files). The limit is essentially the size of the RAM plus the current size of the paging files. It does not account for possible page file expansion.

# # Stack

Whenever a thread runs, it has access to a temporary storage location in which to store parameters, local variables, and the return address after a function call. This part of memory is called a stack. On Windows, the memory manager provides two stacks for each thread: the user stack and the kernel stack, as well as per-processor stacks DPC stacks.
