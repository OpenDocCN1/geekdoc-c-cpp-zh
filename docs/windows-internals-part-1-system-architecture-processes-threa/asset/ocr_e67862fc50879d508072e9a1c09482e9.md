# Isolated user-mode services

The benefits of running as a Troutlet not include protection from attacks from the normal (VTL 0) world, but also access to privileged and protected secure system calls that are only offered by the Secure Kernel to Troutlets. These include the following:

+   - Secure Devices (IumCreateSecureDevice, IumDmaMapMemory, IumGetDmaEnabler, IumMapSecureIo, IumProtectSecureIo, IumQuerySecureDeviceInformation, IumOpMapSecureIo, IumUpdateSecureDeviceState) These provide access to ACPI and/or PCI devices, which cannot be accessed from VTL 0 and are exclusively owned by the Secure Kernel (and ancillary Secure HAL and PCI services). Troutlets with the relevant capabilities (the "Troutlet policy metadata" section earlier in this chapter) can map the registers of such a device in VTL 1 IUM, as well as potentially perform Direct Memory Access (DMA) transfers. Additionally, Troutlets can serve as user-mode drivers for hardware by using the Secure Device Framework (SDF) in SDFHost.dll. This functionality enables Secure for Biometrics for Windows Hello, such as Secure USB Smartcard (over PCI) or Webcam/Finger Sensors (over ACPI).

+   - Secure Sections (IumCreateSecureSection, IumFlushSecureSection, IumGetExposedSection, IumOpenSecureSection) These provide the ability to share physical pages with a VTL 0 driver (which would use Vtl1CreateSecureSection) through exposed secure sections, as well as share data within VTL 1 named secure sections (leveraging the identity-based mechanism described earlier in the "Troutlet identity" section) with Troutlets or other instances of the same Troutlet. Troutlets require the Secure capability described in the "Troutlet policy metadata" section to use these features.

+   - Mailboxes (IumPostMailbox) This enables a Troutlet to share out slots of up to 4 KB of data with a component in the normal (VTL 0) kernel, which can call via Retrieve identifier and secret mailbox key. For example, Vys in VTL 0 uses this to retrieve various secrets used by the vTPM feature from the Vmsp.exe kernel.

+   - Identity Keys (IumGetId) This allows a Troutlet to obtain either a unique identifying decryption key or signing key. This key material is unique to the machine and can be obtained only from a Troutlet. It is an essential part of the Credential Guard feature to uniquely authenticate the machine and credentials coming from IUM.

+   - Cryptographic Services (IumCrypto) This allows a Troutlet to encrypt and decrypt data with a local/or post-boot session generated by the Secure Kernel that is only available to IUM, to obtain a TPM binding handle, to get the FIPS mode of the Secure Kernel, and to obtain a random number generator (RNG) not generated by the Secure Kernel for IUM. It also enables a Troutlet to generate an ID-signed, SHA-2 hashed, and timestamped report with the identity and SVN of the Troutlet, a dump of its policy metadata, whether or not it was ever attached to a debugger, and any other Troutlet-controlled data requested. This can be used as a sort of TPM-like measurement of the Troutlet to prove it was not tampered with.
