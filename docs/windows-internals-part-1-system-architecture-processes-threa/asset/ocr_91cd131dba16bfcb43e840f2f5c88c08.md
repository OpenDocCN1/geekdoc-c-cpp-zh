# Stack randomization

The next step in ASLR is to randomize the location of the initial thread stack and, subsequently, of each new thread. This randomization is enabled unless the StackRandomizationFlag was enabled for the process, and consists of first selecting one of 32 possible stacks separated by either 64 KB or 256 KB. You select this base address by finding the first appropriate memory region and then choosing the xth value where x is once generated based on the current processor's TSC shifted and masked into a 5-bit value (This allows for 32 possible locations.)

When this base address has selected, a new TSC-derived value is calculated—this one by bits long. The value is multiplied by 4 to maintain alignment, which means it can be as large as 2,048 bytes (half a page). It is added to the base address to obtain the final stack base.

# Heap randomization

ASLR randomizes the location of the initial process heap and subsequent heaps when created in user mode. The RtlHeap function uses another pseudo-random TSC-derived value to determine the base address of the heap. This value, 5 bits, is multiplied by 64 KB to generate the final base address, starting at 0, giving a possible range of 0x00000000 for the initial heap. Additionally, the range heap base address is manually deallocated to force an access violation if an attack is a brute-force sweep of the entire heap address range.

# ASLR in kernel address space

ASLR is also active in kernel address space. There are 64 possible load addresses for 32-bit drivers and 256 for 64-bit drivers. Relocating user-space images requires a significant amount of work in kernel space, but if kernel space is tight, ASLR can use the user-mode address space of the System process for this. On Windows 10 (1607) and Server 2016, ASLR is implemented for system memory regions, such as page and non-paged pools, system cache, page tables, and the PFN database (initialized by MiAssignTopLevelRanges).
