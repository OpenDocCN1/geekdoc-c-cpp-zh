# AppContainer and object namespace

Desktop applications can share kernel objects by name. For example, suppose process A creates an event by calling CreateEvent(Ex) with the name MyEvent. It gets back a handle to it later to manipulate it. Process B running in the same session can call CreateEvent(Ex) or OpenEvent with the same name, MyEvent, and assuming it has appropriate permissions which is usually the case if running under the same session gets another handle to the underlying object. Now if process A calls SetEvent on the event while process B was blocked in a call to WaitForSingleObject on its event, process B's waiting would be released because it is the same object. This sharing works because objects are created in the object manager directory Sessions\BaseNamedObjects, as shown in Figure 7-18 with the WinObj prefixed with Global\.

Furthermore, desktop apps can share objects between sessions by using a name in Global\. This creates the object in the session 0 object directory located in BaseNamedObjects (refer to Figure 7-18).
