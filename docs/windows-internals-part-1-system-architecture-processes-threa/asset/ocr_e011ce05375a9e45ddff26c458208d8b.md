# I/O completion parts

Writing a high-performance server application requires implementing an efficient threading model. Having either too few or too many threads to process client requests can lead to problems. For example, if a server creates a thread to handle all requests, clients can become starved because the server will be tied up processing one request at a time. A single thread could simultaneously process multiple requests, switching from one to another as I/O operations are started. However, this architecture introduces complexity and can't take advantage of systems with more than one logical processor. At the other extreme, a server could create a pool of threads that virtually every client request is processed by a dedicated thread. This scenario usually leads to thread-threading, in which lots of threads wake up, perform some CPU processing, block waiting for I/O, and then, after request processing is completed, block again for a new request.
