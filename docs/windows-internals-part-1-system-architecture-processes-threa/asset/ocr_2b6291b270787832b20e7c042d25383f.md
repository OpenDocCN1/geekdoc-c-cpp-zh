15. It starts the Local Security Authentication Subsystem (lsass.exe), and Credential Guard is enabled, the Isolated LSA Trustlet (lsais.exe) requires querying the VBS provisioning from UEFI. See Chapter 7 for more information on Lass.exe and lsais.exe.

16. If Setup is currently pending (that, if this is the first boot during a fresh install or an update to a new major OS or Insider Preview), it launches the setup program.

17. It waits forever for a request for system shutdown or for one of the aforementioned system processes to terminate (unless the DontWaitSysPros registry value is set in the Winlogon key mentioned in step 7). In either case, it shuts down the system.

# Service control manager

Recall that with Windows, services can refer to either a server process or a device driver. This section deals with services that are user-mode processes. Services like Linux daemon processes in that can be configured to start automatically at system boot without requiring an interactive logon. They can also be started manually, by running the Services administrative tool, using the sc.tool, or calling the WindowsStart function. Typically, services do not interact with the logged-on user, although there are special conditions when this is possible. Additionally, others can run in special service accounts (such as SYSTEM or LOCAL SERVICE), others can run with the same security context as logged-in users. (For more, see Chapter 9 in Part 2.)

The Control Manager (SCM) is a special system process that manages %SystemRoot%System32Services responsible for starting, stopping, and interacting with service processes. It is also a protected process, making it difficult to tamper with. Service programs are really just Windows that call special functions to interact with the SCM to perform actions as registering the service's successful startup, responding to status requests, or pausing or shutting down the service. Services are defined in the registry under HKLM\SYSTEM\CurrentControlSet\Services.

Keep in mind that services have three names: the process name you see on the system, the internal name in the registry, and the display name shown in the Services administrative tool. (Not all services have a display name—if a service does not have a display name, the internal name is shown.) Services can also have a description field that details what the service does.

To map a service process to the services contained in that, use the tlist /s (from Debugging Tools for Windows) or tasklist /svc (built-in Windows) command. Note that there isn't always one-to-one mapping between service processes and running services, however, some services share a process with other services. In the registry, the Type value under the service's key indicates whether the service runs in its own process or shares a process with other services in the image.

A number of Windows components are implemented as services, such as the Print Spooler, Event Log, Task Scheduler, and various networking components. For more details on services, see Chapter 9 in Part 2.
