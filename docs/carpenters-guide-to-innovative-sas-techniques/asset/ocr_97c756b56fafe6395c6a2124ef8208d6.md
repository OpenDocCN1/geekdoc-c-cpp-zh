Generally we want the step to terminate on our conditions, and not necessarily just because a last observation is read from one of the data sets.

Like in a MERGE, if there are variables in common, the values that are read in from the last data set replace those read in from earlier ones. As always any variable that is read from an incoming data set is automatically retained.

As seen in Sections 3.1.5, 3.1.6, and 3.8.1, it is possible and sometimes even very advantageous to be able to use multiple SET statements. Just be sure that you understand what is happening when you do so, and be sure that you exercise caution as you take control of the read process.

While it may have been first proposed by Don Henderson, the DOW loop, which is also known as the DO-W loop, was named for Ian Whitlock who popularized the technique and was one of the first to demonstrate its efficiencies. The DOW loop can often be used to improve DATA step performance, and in its simplest form the DOW loop takes control of the DATA step’s implied loop.

Consider the DATA step’s implied loop. During the execution phase each executable statement in the DATA step will execute once for each observation in the incoming data set (WORK.BIG).
