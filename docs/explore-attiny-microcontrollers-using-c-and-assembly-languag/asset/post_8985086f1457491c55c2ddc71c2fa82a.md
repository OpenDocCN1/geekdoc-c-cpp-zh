
### ICALL (Indirect Call to Subroutine)

ICALL works the same way as IJMP, using the Z register as a pointer, except that ICALL pushes the next program memory address onto the stack. ICALL is used to call a subroutine at the address that the Z register is holding.

## 11.2.2.3 Return from Subroutine and Interrupt Instructions

### RET (Return from Subroutine)

RET must be used to return from a subroutine that was called using RCALL or ICALL. The return address is loaded from the stack when RET is executed at the end of a subroutine.

### RETI (Return from Interrupt)

RETI must be the last instruction run in an interrupt service routine so that program execution continues where the main code was interrupted and so that the global interrupt enable bit in the status register is automatically set again. The use of the RETI instruction is explained in Chapter 10, starting from section 10.5.1.

## 11.2.2.4 Compare Instructions

Of the four compare instructions that follow, only CPSE branches. The other compare instructions don't branch, but are typically used in combination with branch instructions.

### CPSE (Compare Skip if Equal)

CPSE compares two registers and skips the next instruction if the values in the registers are equal. It has the format CPSE Rd,Rr where Rd and Rr can be any registers from R0 to R31. This instruction does not alter the status register.

### CP (Compare)

CP compares two registers in the range R0 to R31, which means that it affects flags in the status register. It has the form CP Rd,Rr where Rd and Rr can be any of the registers R0 to R31. The following example demonstrates the use of CP.

```
ldi   R16, 0x05
ldi   R17, 0x05
cp    R16, R17
breq  equal
nop   ; Values are not equal
equal:
nop   ; Values are equal
```

In the code example, values in register R16 and R17 are compared using CP. The BREQ (Branch if Equal) instruction is used after CP to determine if the compared values were equal or not. If the values are equal, then program execution branches to the next NOP instruction at the equal label. If the values are not equal, program execution continues at the first NOP instruction below BREQ. Other conditional branch instructions can be used after CP to determine the outcome of the comparison. Conditional branch instructions are found in section 11.2.2.6 that follows after the next section.

### CPC (Compare with Carry)

CPC is like the CP instruction, but also takes into consideration the carry flag in the status register. As with CP, CPC is usually followed by a conditional branch instruction.

### CPI (Compare with Immediate)

CPI is like the CP instruction, but instead of comparing two registers, it compares one register with an immediate value. It has the form CPI Rd,K where K is an 8-bit immediate value.

## 11.2.2.5 Skip Instructions

### SBRC (Skip if Bit in Register is Cleared)

SBRC tests a bit (0 to 7) in a register (R0 to R31) to see if it is clear. If the bit is clear, it skips the next instruction. It has the form SBRC Rr,b where Rr is the register to test, and b is the bit in the register to test. SBRC was used in section 8.2.3 of Chapter 8 to limit a count value. Any I/O register read into a general purpose register can have its bits tested using SBRC.

### SBRS (Skip if Bit in Register is Set)

SBRS works the same way as SBRC, but tests if a bit is set in a register rather than cleared. If the bit is set, the next instruction is skipped. SBRS was used in the timer polling code from section 10.4.2 of Chapter 10 to test the OCF0A bit in the TIFR register. The TIFR register was first read into a general purpose register before testing the OCF0A bit.

### SBIC (Skip if Bit in I/O Register is Cleared)

### SBIS (Skip if Bit in I/O Register is Set)

SBIC and SBIS work in the same way as SBRC and SBRS, but operate on I/O registers 0 to 31, rather than the general purpose registers. Both instructions have the form SBIC A,b where A is the address of the I/O register, and b is the bit to test. SBIC and SBIS were both used in section 8.2.5 of Chapter 8 to test the state of a switch connected to a pin. To test the bit in an I/O register that has an address greater than 31, it is necessary to first read the value into the I/O register into a general purpose register, and then use SBRC or SBRS to test the bit in the general purpose register.

## 11.2.2.6 Branch Instructions

Branch instructions branch depending on if a bit is set or clear in the status register or SREG. BRBS and BRBC that immediately follow check for a specified bit in the status register. All other branch instructions are synonyms for BRBS and BRBC that check specific status register bits. BRBS and BRBC take two operands – the bit number in the status register to check and the address to branch to. All other branch instructions take only one operand – the address to branch to, because the bit to check in the status register is fixed with these instructions. All of the branch instructions are limited to branching to a relative address that can be between -64 and +63 relative to the PC.

After BRBS and BRBC, there are 9 pairs of branch instructions that test the 8 flags in the status register to see whether they are set or clear. The reason that there are 9 pairs of instructions instead of 8 is because two of the pairs check the status of the C flag.

### Branch if Bit in SREG Set or Cleared

- BRBS (Branch if Bit in SREG is Set)
- BRBC (Branch if Bit in SREG is Cleared)

Of the two instructions BRBS and BRBC, BRBC was used to check the status of the Z flag in the status register for the basic delay subroutine, starting in the code of section 2.3.2 of Chapter 2. BRBC was used to check if the Z bit was cleared, in other words if the contents of a register was not zero. BRBC branched to a DEC instruction that decremented the register. So long as the register did not contain zero, BRBC branched to DEC. When DEC finally decrements the register to zero, then the Z flag is automatically set to indicate that the last arithmetic operation resulted in zero. BRBC then does not branch, but rather runs the instruction directly below it. This part of the delay subroutine code is as follows.

```
...
delloop2:
    dec r17
    brbc SREG_Z, delloop2
...
```

Bits that are found in the status register or SREG are defined in the header file for the AVR being used. These names can be used with the BRBS and BRBC instructions, and are shown as they appear in the header file below.

```
; SREG - Status Register
.equ SREG_C = 0 ; Carry Flag
.equ SREG_Z = 1 ; Zero Flag
.equ SREG_N = 2 ; Negative Flag
.equ SREG_V = 3 ; Two's Complement Overflow Flag
.equ SREG_S = 4 ; Sign Bit
.equ SREG_H = 5 ; Half Carry Flag
.equ SREG_T = 6 ; Bit Copy Storage
.equ SREG_I = 7 ; Global Interrupt Enable
```

BRBS is the counterpart to BRBC. While BRBC checks if a status register bit is clear, BRBS checks if a status register bit is set. The other branch instructions that follow are synonyms for BRBS and BRBC, and are typically used after one of the compare instructions.

### Branch if Equal or Not Equal – SREG Z Flag

- **BREQ (Branch if Equal)**
  Equivalent to BRBS SREG_Z,k where k is the constant relative address to branch to.

- **BRNE (Branch If Not Equal)**
  Equivalent to BRBC SREG_Z,k where k is the constant relative address to branch to.
