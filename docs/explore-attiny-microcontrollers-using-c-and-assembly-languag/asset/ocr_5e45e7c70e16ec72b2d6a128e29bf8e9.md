# 10.2.3.2 How the wait_ms Subroutine Works

The new wait_ms millisecond delay subroutine is based on the previous wait_1s fixed 1s delay subroutine code. The only difference between these two subroutines is the number fed into registers R16 to R19 at the start of these subroutines. Code from the start of the wait_1s subroutine is shown below.

```
wait_1s:
 ldi   R16, low  ((F_CPU - 10) / 10)
 ldi   R17, byte2((F_CPU - 10) / 10)
 ldi   R18, byte3((F_CPU - 10) / 10)
 ldi   R19, byte4((F_CPU - 10) / 10)
```

Because the wait_1s subroutine is fixed to delay for 1s, the number of clock cycles that the subroutine must use up is equal to the frequency that the AVR CPU is clocked at. Some mathematics compensates for the clock cycles used up before and after the loop in the subroutine ( - 10 above), as well as for the cycles used in the loop ( / 10 above).

How the above code is modified for the wait_ms subroutine explains how wait_ms works, and is described in the following paragraphs. In order to modify the above code to be able to use different millisecond delay values, we can start by asking how to generate a 1ms delay using this code. The code simply uses up a certain number of clock cycles, and we must just work out how many clock cycles are needed for 1ms. We know that the time period of one clock cycle is 1 / frequency, written mathematically as shown below, where f is the frequency of the AVR CPU.
