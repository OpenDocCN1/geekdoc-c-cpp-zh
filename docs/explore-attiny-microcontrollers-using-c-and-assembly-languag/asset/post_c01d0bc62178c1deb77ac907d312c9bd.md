
In the main.c listing, change the value of F_CPU to the frequency that your AVR ATtiny device is operating at. As can be seen in the listing, F_CPU is set up for a default ATtiny13(A) clock frequency. After the F_CPU definition the io.h file is included to be able to use I/O port names in the code. The wait_ms.h file included after this is a file that we will create shortly. Once again the code blinks an LED on pin PB4, but this time our wait_ms subroutine is called to provide a delay in the code. The WAIT_MS_TIME() macro passed to wait_ms is used to convert the millisecond value to the correct value so that wait_ms uses up the correct number of clock cycles for the selected millisecond value.

In Microchip Studio, right-click wait_ms.c at the top right of the Solution Explorer pane and then select Add ▶ New Item... on the menu that pops up. Select Preprocessing Assembler File (.S) in the Add New Item dialog box that opens. In the bottom Name: field of the dialog box, enter wait_ms.S with a capital S file extension. Click the Add button at the bottom right of the dialog box to add this new assembly language file to the project.

After adding the new assembly language file to the C project, it opens in Microchip Studio automatically. Replace the comments in this file with the following code.

```
wait_ms.c: wait_ms.S

#include <avr/io.h>

.global wait_ms

wait_ms:
    push R26

wait_ms_loop:
    subi R22, 1
    sbci R23, 0
    sbci R24, 0
    sbci R25, 0
    mov R20, R22
    or R20, R23
    or R20, R24
    or R20, R25
    brbc SREG_Z, wait_ms_loop
    pop R20 ; Restore saved register
    push R20 ; Extra clock cycles for balance
    pop R20 ; Extra clock cycles for balance
    nop ; Extra clock cycle for balance
    nop ; Extra clock cycle for balance
    ret ; Extra clock cycle for balance
```

As can be seen in the wait_ms.S code listing, the same i/o.h file is included as was included in the C code from main.c. In order for the wait_ms subroutine to be visible to the rest of the code, the .global directive is used in front of the wait_ms subroutine name. The code for the wait_ms subroutine follows the global declaration.

In order to make it easy to use the wait_ms subroutine in C code, a header file called wait_ms.h is added to the project. When the header file is included in a C code file, the wait_ms subroutine can be called as if it were a C function.

Right-click wait_ms.c at the top of the Solution Explorer pane in Microchip Studio again. Select Add ▶ New Item... on the menu that pops up. Click the Include File item in the middle pane of the Add New Item dialog box that opens. In the bottom Name: field of the dialog box, enter wait_ms.h and then click the Add button. This adds a new header file to the project. Enter the following code into the wait_ms.h file that automatically opens after adding it.

```
wait_ms.c : wait_ms.h

#ifndef WAIT_MS_H
#define WAIT_MS_H

#define WAIT_MS_TIME(MS_TIME)((((F_CPU * MS_TIME) / 1000) - 20) / 10)

extern void wait_ms(uint32_t);

#endif /* WAIT_MS_H */
```

After adding the files and code to the project as described above, the project can be built and run on hardware or tested in the simulator. At the first breakpoint, use F10 to step over the first PORTB line. Now reset the Cycle Counter to 1 to compensate for the bug. ### 10.3.1.2 How the wait_ms_c Project Code Works

Code in main.c should be self explanatory and the description already given should suffice. Most important is the inclusion of wait_ms.h in main.c. This file allows the wait_ms subroutine to be called and the WAIT_MS_TIME macro to be used.

In wait_ms.h is the WAIT_MS_TIME macro definition. This macro is used to calculate the number used by the wait_ms subroutine to generate the correct number of delay cycles for the given millisecond delay. This macro is passed the number of milliseconds and uses this value together with F_CPU to calculate the number for wait_ms to use. This is the same calculation as we have used before, but it now subtracts 20 because the number of clock cycles used before and after the loop in wait_ms has changed.

The wait_ms subroutine is declared external by using the extern C keyword placed before the wait_ms subroutine function prototype in wait_ms.h. This declaration together with the .global directive in the wait_ms.S file makes the wait_ms subroutine available and visible to any C file that includes the wait_ms.h header file.

The wait_ms.S file contains the code for the wait_ms subroutine. This code is basically the same code that we have been using to generate software time delays in the previous few projects, but does have some modifications. It is still decrementing a 32-bit number in the loop, but this time uses different registers to hold the 32-bit number. The reason for this is that these registers are the registers that the C code automatically uses to pass the 32-bit number to the subroutine. The uint32_t value that can be seen in the function prototype in wait_ms.h is passed to the wait_ms subroutine using a certain register convention. This value is the value that is passed to wait_ms() in the code in main.c using the macro WAIT_MS_TIME(). Section 6 of the Atmel AT1886: Mixing Assembly and C with AVRGCC document is called Parameter passing and contains the information about which registers are used to pass parameters to a function. The following is stated in this section:

> " Arguments in a fixed argument list are assigned, from left to right, to registers r25 through r8. "

This means that when a 32-bit number is passed to a function or subroutine, the left-most byte of the number, or byte 3, is assigned to R25. Byte 2, or the byte to the right of byte 3 is assigned to R24. Byte 1 is assigned to R23. Finally Byte 0, or the right-most byte of the 32-bit number is assigned to R22. These registers therefore replace R19 down to R16 that were used in previous versions of the delay loop in the wait_ms subroutine. The only register still used by the subroutine is R20, which holds the result of the OR operations.

At the start of the wait_ms subroutine, R20 is pushed onto the stack to preserve its value. After the BRBC instruction at the bottom of the loop, R20 is popped from the stack to restore its original value. In order to balance the number of clock cycles that are used up outside the loop in wait_ms, the value in R20 is pushed back onto the stack and then popped from the stack again. This uses up four clock cycles, which could have been done using four NOP instructions.

To get the total number of clock cycles used outside the loop to 20, two NOP instructions are run before the RET instruction. The PUSH instruction at the start of wait_ms, together with the instructions below BRBC add up to 13 clock cycles, if we subtract 1 to compensate for BRBC being 1 clock cycle instead of 2 the last time that it is run. Add to this the 4 clock cycles from the four LDI instruction added by the C code to pass the 32-bit value to the subroutine, and the 4 clock cycles added by the C code to call the subroutine, and we have a total of 20 clock cycles outside the loop of the wait_ms subroutine. Take a look at the disassembled code in the Disassembly window of the project when run in the simulator to see the code that was added to pass the 32-bit value to the subroutine and to call the subroutine.
