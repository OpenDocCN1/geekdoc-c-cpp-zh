
For an ATtiny45, stack initialization could be written as follows for a stack starting at the end of RAM at address 0x015F. In the code below, the lower byte of the address of the top of the stack, which is 0x5F is used instead of low(RAMEND). The high byte of the address of the top of the stack, which is 0x01 is used instead of high(RAMEND).

```asm
ldi   r16, 0x5F
out   spl, r16
ldi   r16, 0x01
out   sph, r16
```

After the stack is initialized in the program a value of 0x5A is loaded to R16. This is simply so that we have a value in R16 to push onto the stack for this example:

```asm
ldi   r16, 0x5A ; Load a value to R16
```

In Microchip Studio, build the program and start the debugger with the simulator selected. Step over the stack initialization code and over the above line. In the memory window at the bottom right of Microchip Studio, select data IRAM in the Memory drop-down box so that the contents of the data Memory is displayed. The last byte of this memory is the top of the stack, scroll down to find it. It is easier to read the memory window if it is changed to display a single column. To do this, select 1 in the Columns field of the Memory window. If the Columns field is not visible, click the small double arrow at the right of the area where data IRAM was selected, as shown in Figure 6.10. This pops out a box that allows 1 to be selected in the Columns drop-down list. If the memory window or pane is wide enough, the Columns field will already be in view and it will not be necessary to click the double arrow, just expand the drop-down Columns box.

Figure 6.10: Change RAM Display to Single Column

After selecting 1 in the Columns list, as can be seen in Figure 6.10, scroll down in the memory window so that the address 0x015F can be seen in this window, as shown in Figure 6.10. This assumes that an ATtiny45 is selected in Microchip Studio, which has the last byte of its SRAM at 0x015F. Also note that at the top of the Processor Status window, the Stack Pointer is set to 0x015F, pointing to the last byte of ATtiny45 SRAM.

Step over the next instruction which is a PUSH instruction that pushes R16 onto the stack:

```asm
push R16    ; Save R16 to the stack
```

Note that 0x5A (5a) now appears in the last byte in the memory window, at address 0x015F for an ATtiny45. In other words R16, or the value in R16, was pushed onto the top of the stack. In the Processor Status window in Microchip Studio, observe that the Stack Pointer is decremented by one, changing from 0x015F to 0x015E. In this program the value of R16 is now temporarily stored on the stack to free up R16 for other use. R16 is cleared in the program to simulate it being used for another purpose and its value changed, as the next line of code shows. Step over this line of code now.

```asm
clr r16     ; R16 gets modified
```

Finally the value that was in R16 is restored to R16 by popping it from the stack with the POP instruction. Step over the POP instruction.

```asm
pop r16     ; Restore R16 from the stack
```

After stepping over the POP instruction, the stack pointer register is incremented by one and can be seen in the Processor Status window to be 0x015F again. R16 now contains 0x5A, which was popped from the stack. The last byte in RAM is still 0x5A (displayed as 5a), but because the stack pointer is pointing to this byte, it will be overwritten when a new value is pushed onto the stack.

## 6.6.3 Calling a Subroutine

Stop the debugger in Microchip Studio and modify the test_asm project by replacing the previous code with the following code that shows how to call a subroutine.

```asm
test.asm : main.asm - subroutine call

ldi r16, 0x55 ; Load a value to R16
rcall delay ; Call the delay subroutine

loop:
rjmp loop

; Delay subroutine
delay:
push r16 ; Preserve R16
ldi r16, 0x03 ; Delay value to decrement
delloop:
dec r16 ; Decrement delay value
brbc SREG_Z, delloop ; Loop until delay value = 0
pop r16 ; Restore R16
ret
```

Build the project, then start debugging and break in the simulator as usual. This program demonstrates two uses of the stack. The first is that the stack is used to store the return address when a subroutine is called. The second is that a register can be preserved on the stack so that code in a subroutine can use the register and then restore it to its original value before returning.

In the above code listing the stack is not explicitly initialized because we are taking advantage of the fact that the default value of the stack pointer is RAMEND, which suits our purposes for this example. Remember that by default the stack pointer points to the last byte in data RAM, which is 0x015F for the ATtiny45.

Don't start stepping through the program in Microchip Studio yet, an explanation of the code is necessary first. The first line of code in the program puts an initial value of 0x55 into R16. As with the previous program this is so that we have a value to push onto the stack for demonstration purposes.

```asm
ldi r16, 0x55 ; Load a value to R16
```

The second line of the program calls a subroutine named "delay":

```asm
rcall delay ; Call the delay subroutine
```

As with the LED blink program led_blink.asm from section 2.3.2 in Chapter 2, the delay subroutine is found below the main code and starts with the label delay:. This delay subroutine is much simpler than the delay subroutine from the LED blink program. The code should look familiar as it is the same code used to demonstrate the use of the zero flag in the status register, only it has been packaged into a subroutine in this example with a few extra lines of code.

A subroutine starts with a label which is a name followed by a colon. A subroutine ends with the RET (Return from Subroutine) instruction. RCALL (Relative Call to Subroutine) is used to call or execute a subroutine from anywhere in the main program, or from another subroutine. A subroutine is a block of functional code that can be called any number of times. The code of a subroutine only has to be written once in a program, but can be called and executed multiple times. This saves program memory and is also convenient because certain tasks or functions that need to be repeated can be put into a subroutine, and called when needed. Program instructions that occur after a subroutine call in a program need to be executed when the subroutine returns. For this reason the address of the instruction that follows a subroutine call is pushed onto the stack automatically. This return address is automatically popped from the stack when the subroutine returns. The subroutine itself can be anywhere in program memory.

Calling the subroutine with the RCALL instruction loads the address of the subroutine to the program counter so that the code of the subroutine starts to run after the RCALL instruction has executed. When stepping through the example project in the debugger and simulator in Microchip Studio, we will see the pushing and popping of the return address during the subroutine happening automatically.

Before continuing, bring the end of the stack into view using the Memory window at the bottom right of Microchip Studio, so that we can see the stack being used. To do this, select data IRAM in the Memory: box of the Memory window. Use the small double arrow at the right of the memory window to pop out the selection box if necessary, and change the Columns: item to 1. Refer back to Figure 6.10 if needed. Scroll down so that address 0x015F is in view in the memory window for the ATtiny45.

In Microchip Studio, step over the first line of code in the program. Note that the Program Counter value in the Processor Status window is now 1, which is the address that the RCALL instruction is at – the first instruction, LDI, is at address 0. This means that the address that the RJMP instruction is at address 2 – RJMP is the third instruction. Program execution will therefore need to continue at address 2 after the subroutine is called and returns. If we were to step over the second line of the program which calls the delay subroutine, the debugger will not step through the code in the subroutine, but will execute this code at full speed and arrive at the RJMP instruction. Use the Step Into icon on the second from top toolbar, or the F11 key to step into the delay subroutine, rather than stepping over it.

After stepping into the delay subroutine, the Stack Pointer in the Processor Status window will have decremented twice, from 0x015F to 0x015D on an ATtiny45. This is because the 16-bit return address of the line of code after the subroutine call was automatically pushed onto the stack. The full 16-bit return address 0x0002 was pushed onto the stack – LSB first with 0x02 at address 0x015F, then MSB with 0x00 at address 0x015E. In the Memory window, 0x02 can be seen at address 0x015F and 0x00 at address 0x015E.

The first line of code in the subroutine pushes R16 onto the stack:

```asm
push r16 ; Preserve R16
```

Registers that are used in a subroutine are typically pushed onto the stack to preserve them and popped from the stack before the subroutine returns so that these registers remain unaltered for the main program. It can get very difficult to keep track of the usage of every register in a big program, so preserving the registers used in a subroutine can prevent unexpected behavior of the main program that may rely on a value in a register being unaltered after a subroutine call. Step over the PUSH instruction at the beginning of the subroutine and note that the value in R16 (0x55) now appears at address 0x015D in the memory window. The Stack Pointer decrements to 0x015C and the stack is now storing a 16-bit subroutine return address and an 8-bit register value.

Step through the subroutine code which loads 0x03 to R16, then decrements R16 until it contains zero. When R16 contains 0x00, the POP instruction is executed followed by the RET instruction, as the following code shows.

```asm
pop r16 ; Restore R16
ret
```
