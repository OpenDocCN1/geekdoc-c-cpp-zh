
Now that the Cycle Counter value is reset, click the Start Debugging icon again, or hit the F5 keyboard key. The program runs in the simulator and execution stops on the second breakpoint which is on the RET instruction. The Cycle Counter now contains a value of 195840, which is the number of cycles that the body of the delay subroutine took to execute, excluding the clock cycles that would be used by the RET instruction. The time delays generated by the delay subroutine are therefore as follows.

- 195.84ms at 1MHz for a default ATtiny25/45/85 (195840 × 1µs = 195840µs or 195.84ms)
- 163.2ms at 1.2MHz for a default ATtiny13(A) (195840 × 0.833µs = 163200µs or 163.2ms)

## 10.2.1.2 Delay Subroutine Mathematical Formula

A mathematical formula can be derived for the delay subroutine in order to calculate the number of clock cycles that it uses up. The formula can then be used to calculate the new time delay when the values loaded to the two count registers in the delay subroutine are changed. What follows describes how to go about deriving a formula for the delay subroutine. Those readers who are not interested in the mathematics can skip ahead to see what the derived formula looks like, although I would encourage everyone to follow along, as it shows how useful mathematics can be.

In order to derive a formula from the delay subroutine and make it easier to comprehend, the count values loaded to registers R16 and R17 can be reduced from 0xff to 3, as follows. This also makes it easier to test in Microchip Studio later.

```asm
; Delay subroutine
delay:
ldi r16, 3 ; 1 clock cycle
delloop1:
ldi r17, 3 ; 1 clock cycle
delloop2:
dec r17 ; 1 clock cycle
brbc SREG_Z, delloop2 ; 1 or 2 clock cycles, if false (1), if true (2)
dec r16 ; 1 clock cycle
brbc SREG_Z, delloop1 ; 1 or 2 clock cycles, if false (1), if true (2)
ret ; 4 clock cycles
```

We can then strip away the operands from each line of code to make it easier to see how many clock cycles are used in the code as the next listing shows.

```
ldi     1+      ; Clock cycle used up once upon entry
delloop1:
ldi     1+      ; Clock cycle used every pass through outer loop
delloop2:
dec     1+      ; Clock cycle used by inner loop
brbc    (2 x 2) or 1+ ; 2 clock cycles on inner loop, except for last pass
dec     1+      ; Clock cycle used by outer loop
brbc    (2 x 2) or 1+ ; 2 clock cycles on outer loop, except for last pass
ret     ; Not counted in this example
```

It is easiest to start with the inner loop that consists of only two instructions as follows.

```
delloop2:
dec     1+      ; Clock cycle used by inner loop
brbc    (2 x 2) or 1+ ; 2 clock cycles on inner loop, except for last pass
```

In this code, the BRBC instruction jumps back to the delloop2 label, which is effectively the address of the DEC instruction. Because we loaded 3 to R17, and are decrementing R17 with the DEC instruction, the first two passes through the loop cause BRBC to use up two clock cycles. Two clock cycles are used because BRBC evaluates to true and branches to the DEC instruction. BRBC tests the Z or zero flag in the status register and branches if the Z flag is clear. The Z flag is always clear until R17 is decremented to 0. When R17 finally contains 0, the Z flag is set to mark that the last mathematical operation resulted in a value of 0. At this final pass through the loop BRBC uses only one clock cycle because it evaluates to false, that is, it does not branch, but executes the instruction below it. When starting with a value of 3 in R17, we therefore have the following number of clock cycles used by the inner loop. The explanation of this calculation follows.

((1 + 2) x 2) + 1 + 1 = 8 clock cycles

This is easier to visualize if we write it as follows.

| Passes through loop, except last ((1 + 2) x 2) | Last pass through loop + 1 + 1 | Result = 8 |
|---|---|---|
| (1 + 2) x (3 - 1) | + 1 + 1 | |
| ((dec + brbc) x num_passes) | + dec + brbc | |

At the top of the above listing we can see that the number of cycles used by the code has been split into three parts – the passes through the loop except the last pass, the last pass through the loop, and the resultant number of clock cycles. The first line below these sections shows the parts of the calculation that were previously derived. At the bottom of the listing are the instructions from the inner loop with the number of clock cycles that they used above them.

Starting at the bottom of the listing, we have num_passes, which is the number of passes through the loop. In our example, register R17 was loaded with 3, so this is the number of passes through the loop. Because the last pass through the loop generates a different number of clock cycles from all other passes, we must subtract 1 from the number of passes, thus num_passes becomes 3 – 1, which is 2. We are therefore left with 1 clock cycle for DEC plus 2 clock cycles for BRBC, which totals 3 clock cycles for every pass through the loop. For all passes through the loop, except the last we therefore have 3 × num_passes, which is 3 × 2 = 6 clock cycles for this example.

Treating the last pass through the loop separately from the preceding passes, we have 1 clock cycle used by DEC and 1 clock cycle used by BRBC, which is 1 + 1 = 2. Add these two clock cycles to the 6 clock cycles used by the previous passes through the loop and we get 8 clock cycles. From this understanding of how the inner loop works in terms of clock cycles used, we can now derive a formula.

In the calculation ((1 + 2) × 2) + 1 + 1 = 8, we have one variable, and one unknown value that we are trying to calculate. The unknown value, which is the number of clock cycles used by the inner loop worked out to 8 in this example. We can call this value CIL which stands for the number of clock cycles (C) of the inner loop (IL), which is mathematically written with the last two letters as subscript:

### C_IL – total clock cycles of inner loop

The variable in the calculation is the number loaded to R17 minus 1 because we need to separate the last pass through the loop as already explained. This value already has 1 subtracted from it in our calculation, shown below.

```
((1 + 2) × 2) + 1 + 1 = 8
```

This should actually be written as follows.

```
((1 + 2) × (3 – 1)) + 1 + 1 = 8
```

This variable can be called VIL which stands for value or variable (V) of the inner loop (IL), which is mathematically written with the last two letters as subscript:

### V_IL = value or variable of inner loop

Substituting the new names for the unknown value and the variable into the calculation, we get the following.

```
((1 + 2) × (3 – 1)) + 1 + 1 = 8
```

becomes

```
((1 + 2) × (V_IL – 1)) + 1 + 1 = C_IL
```

Writing that the normal way for a mathematical equation with the unknown on the left, we get:

```
C_IL = ((1 + 2) × (V_IL – 1)) + 1 + 1
```

Simplifying the equation by doing the addition of known values we get:

```
C_IL = (3 × (V_IL – 1)) + 2
```

Further simplification by doing the multiplication gives us:

```
C_IL = (3V_IL – 3) + 2
```

Which is the same as:

```
C_IL = 3V_IL – 1
```

We can now work out the clock cycles for the outer loop, which includes the inner loop.

The code with the operands removed is repeated below for convenience.

```
ldi     1 +     ; Clock cycle used up once upon entry
delloop1: 1 +     ; Clock cycle used every pass through outer loop
ldi     1 +     ; CIL - Clock cycles used by inner loop
inner_loop 1 +  ; Clock cycle used by outer loop
dec     1 +     ; Clock cycles on outer loop, except for last pass
brbc    (2 x 2) or 1 + ; Not counted in this example
ret
```

With a value of 3 loaded to R16, which is the outer loop count, and calling the inner loop calculation inner_loop we get the following calculation.

```
1 + ((1 + inner_loop + 1 + 2) x 2) + (1 + inner_loop + 1 + 1)
```

Here the inner loop, marked in bold in the code listing, is simplified away to inner_loop, which is where the result of our inner loop calculation will be substituted. The above calculation is easier to visualize if we write it as follows. Note that inner_loop is shortened to CIL in this listing.

| Once off | Passes through loop, except last | Last pass through loop |
|---|---|---|
| 1 + | ((( CIL + 1 + 2 ) x 2)) | + (1 + CIL + 1 + 1) |
| 1 + | (((1 + CIL + 1 + 2 ) x (3 - 1) )) | + (1 + CIL + 1 + 1 ) |
| LDI | (((LDI + CIL + dec + brbc) x num_passes)) | + (LDI + CIL + dec + brbc) |

The above calculation works in a very similar way to the inner loop, except that there are a few extra clock cycles to include in the calculation. When the delay subroutine starts to execute, it runs the first LDI instruction only once, to load the count for the outer loop. This is marked in the once off section of the above listing. The other two sections in the listing result because of the same reason that the inner loop was divided. This is because the BRBC instruction executes in 2 clock cycles for all iterations through the loop, except for the last one. In the above listing, the middle section includes all iterations or passes through the loop, except for the last one. The last section in the listing takes care of the last pass through the loop.

It can be seen that for the middle section of the above listing, the number of cycles through the loop is the sum of the clock cycle from the second LDI instruction, plus the clock cycles from the inner loop, plus one clock cycle for the DEC instruction, plus two clock cycles for the BRBC instruction. The result of this sum is then multiplied by the number of times through the loop. This is 3 – 1 for this example because the last pass through the loop is treated differently to all other passes through the loop. The last pass through the loop is therefore subtracted from the total passes through the loop, the same as for the inner loop. In this example, 3 was loaded to R16, which is the count for the outer loop, so we must do this calculation 2 times instead of 3.

In the last pass through the loop, we have one clock cycle used by the second LDI instruction, plus the clock cycles used by the inner loop, plus the clock cycles used by the DEC instruction, plus one clock cycle used by BRBC instead of the usual two clock cycles. We can now derive a formula for the outer loop as follows.
