With the Toolchain item selected, click General under AVR Assembler to display the options for the AVRASM2 assembly language program, as shown in Figure 12.1.

## 12.1.1.4 List File Options

The list file generated by AVRASM2 can be useful during software development as it shows the final instructions and machine code in hexadecimal format that the input assembly language files were converted to, as well as resource usage. When the list file is generated it includes the entire contents of the .inc file that is automatically included in a Microchip Studio assembly language project, placed at the top of the list file. This makes it necessary to scroll through the first long section of the list file to find the main program code. The normal solution to stop the contents of the .inc file being placed in the list file is to use the .nolist assembler directive before the file is included, and then use the .list assembler directive to enable listing again after the line that includes the .inc file. Because the .inc file is included automatically in a Microchip Studio project, the .nolist and .list directives can't be used without making a change to the project settings first.

In order to be able to use the .list and .nolist directives with the automatically included file in a Microchip Studio assembly language project, first go to the Toolchain General page, as shown in Figure 12.1 on the previous page. Cut (keys Ctrl + X) the file name out of the Include File box at the bottom of this page so that this box is empty, but the text that was in it is on the Windows clipboard. Add the .include directive to the top of the main.asm file of the project and paste the .inc file name next to it between angle brackets. Place a .nolist directive above the .include directive and a .list directive after it, as shown in the following code listing. The .inc file is tn85def.inc for an ATtiny85 selected for the project.

```
.nolist
.include <tn85def.inc>
.list

start:
    sbi   DDRB, DDB4        ; Set pin PB4 as output
    sbi   PORTB, PORTB4     ; Set LED pin high
loop:
    rjmp  loop
```

After saving the changes and building the project, the contents of the .inc file are no longer found in the list file. Take note that if the AVR part is changed in the project, then the new .inc file for the new part is automatically placed in the Include File field of the Toolchain General page. It must be cut from this field again and used to replace the previous .inc file next to the .include directive at the top of the main.asm file.

## 12.1.2 The AVR-AS Assembler

Back in section 10.3 of Chapter 10 an assembly language subroutine was called from a C language program. What wasn't mentioned there is that the assembler program used to assemble the assembly language code file was not the AVRASM2 assembler program that is used with Microchip Studio assembly language projects. The GNU avr-as assembler program is used when including assembly language files in a C program that is built using the AVR GNU toolchain used with Microchip Studio C projects.

Although the avr-as program is the GNU AVR assembler program, assembly language code files ending with a .S extension are passed to the avr-gcc.exe program, along with other options. This avr-gcc program automatically invokes avr-as when it is passed an assembly language file. The avr-as program and AVRASM2 have some differences between them and it is necessary to refer to the avr-as documentation when mixing C and assembly language using the AVR GNU toolchain. The code examples in Chapter 10 were simple enough that it was not necessary to refer to the avr-as documentation.

## 12.1.3 The AVRA Assembler

An open-source assembler program called AVRA that is almost compatible with the Microchip assembler for AVR microcontrollers is available. This assembler is most useful for users wanting to use an AVR assembler program on other operating systems such as Linux. Linux distributions such as Linux Mint include AVRA in their repositories, making it easy to install. The source code for the AVRA project is available on GitHub at: github.com/Ro5bert/avra

## 12.2 The GNU C Toolchain

The open-source GNU C toolchain is the default C toolchain used with Microchip Studio, and the various versions of Atmel Studio that came before it. As with a Microchip Studio assembly language project, a GCC C project has toolchain settings that can be found by selecting Project ▶ <project name> Settings... from the top menu, or by using the Alt + F7 keyboard shortcut, and then clicking the Toolchain item at the left of the page that opens. On this page, settings are found for the AVR GNU C compiler, linker and assembler. One of the main settings that changes the generated machine code is the Optimization setting found under AVR/GNU C Compiler. The Optimization Level field on this page is used to change the optimization of C code, and therefore the generated assembly and machine code. Optimization can be set to one of several levels, or switched completely off. After following this book you now have the skills to examine the code generated by the C compiler by examining the disassembled code in the Disassembly window of a C code project being debugged. By default, a Microchip Studio GNU C project also generates a listing file that shows the assembly language code that was generated from the C code. This file is found in the Solution Explorer pane by expanding the Output Files item, and has a .lss file extension. Double-click this file to open it in Microchip Studio.

The GNU C toolchain for AVR microcontrollers is available for various operating systems, which means that code written in AVR GNU C projects using Microchip Studio can be built on other operating systems, such as Linux. Many Linux distributions have the GNU C tools for AVR microcontrollers available in their repositories. Microchip also supply the same version of the GNU C toolchain for AVR microcontrollers used in Microchip Studio for various operating systems. These toolchains can be downloaded from: www.microchip.com/en-us/development-tools-tools-and-software/gcc-compilers-avr-and-arm

In the introduction chapter a number of reasons were given for learning assembly language. With an understanding of the architecture of AVR microcontrollers and assembly language to program them, two other objectives have been achieved.
