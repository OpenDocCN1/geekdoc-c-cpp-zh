
```
led_count_limit.asm : main.asm

; Set up pins PB0 to PB4 as output pins
ldi r16, 0b0001_1111
out DDRB, r16
clr r0 ; Count register

loop:
out PORTB, r0 ; Display count on LEDs
rcall delay
inc r0 ; Increment count
sbrc r0, 5 ; Reset count if R0 = 0x20
clr r0
rjmp loop

; Delay subroutine
delay:
ldi r16, 0xff
delloop1:
ldi r17, 0xff
delloop2:
dec r17
brbc SREG_Z, delloop2
dec r16
brbc SREG_Z, delloop1
ret
```

The entire program in the above listing works the same way as the led_count.asm program, except for use of the SBRC instruction and the CLR instruction that follows it, as shown below.

```
sbrc r0, 5
clr r0 ; Reset count if R0 = 0x20
```

These instructions limit the value that is written to the LEDs to 0x1F or 0b0001_1111.
SBRC means Skip if Bit in Register is Cleared. In the above code, SBRC checks if bit 5 in register R0 is skipped, and if it is, skips over the next instruction (the CLR instruction that follows it). Bit 5 is always clear up to and including when the count value in R0 reaches 0b0001_1111. When R0 contains this value and the next increment occurs, the value becomes 0b0010_0000, or 0x20, which means that bit 5 in this value is now set for the first time. Remember that bit numbering starts at 0 at the right most bit, so bit number 5 is the 6th bit from the right of the number. Now that bit 5 is set in R0, when the SBRC instruction is next run, the CLR instruction below it is no longer skipped over, but is run. This instruction clears R0 before it is written to the LEDs, or PORTB register, so 0b0010_0000 is never written to PORTB, but rather 0b0000_0000 instead.

As can be seen from this example, the SBRC instruction has two operands, the first being the register to test, which can be R0 to R31. The second operand is the bit in this register to test, which can be 0 to 7.

## 8.2.4 Three Ways to Toggle an LED with an AVR

Three ways of toggling an LED attached to an AVR pin are, 1) to change the pin logic level by value by directly writing a logic level to the PORT register, 2) using exclusive OR, and 3) by using the PINB register. These three methods are explained in the subsections that follow. Toggling an LED of course means changing its logic state either from 0 to 1, or from 1 to 0.

### 8.2.4.1 Toggling an LED by Value

SBI and CBI were used to toggle an LED by value in the led_blink_asm project from section 2.3.2 of Chapter 2. Bitwise OR and AND instructions were used in the same way in the led_blink_c project from section 2.4.2.

As we saw in the led_count_asm project of section 8.2.1.4 of this chapter, the OUT instruction can also be used to change the value of a pin or pins by writing to the PORT register, and could be used in this way to toggle an LED. The same can be said for the led_count_c project, where a value was written directly to the PORTB register to change the values of LEDs. Alternately writing a 1 and then 0 to a bit in a PORT register will toggle an LED, if the corresponding pin is set as an output. As we have already covered how to toggle an LED by value in previous chapters, we will not look at any further code in this section.

### 8.2.4.2 Toggling an LED by Exclusive OR

An LED can be toggled by using the exclusive OR operator that was covered in section 7.4.3 of Chapter 7. If a single bit is always exclusive ORed with a logic level of 1, then if the bit starts out with a value of 1, 1 EOR 1 = 0, the bit ends up toggling from 1 to 0. This means that the next time the bit is exclusive ORed with 1, we have 0 EOR 1 = 1, so the bit now toggles from 0 to 1. If we continue to exclusive OR the bit with 1, it will keep toggling from 1 to 0 and back to 1. We saw this in the EOR example code snippet from section 7.4.3. An LED can be toggled in the same way, as shown in the led_eor_toggle_asm project that follows. Because EOR can’t directly toggle a pin, the pin value is first put into a register by reading the whole port using IN. After toggling the bit in the register using EOR, the new value is written back to the port using OUT.

```
led_eor_toggle.asm : main.asm

; Set pin PB0 as an output
ldi   r18, 0x01
out   DDRB, r18

loop:
in    r19, PORTB    ; Get the PORTB register
eor   r19, r18      ; Exclusive OR with 0x01 to toggle
out   PORTB, r19    ; Write back to PORTB
rcall delay         ; LED on/off delay
rjmp  loop

; Delay subroutine
delay:
ldi   r16, 0xff
delloop1:
ldi   r17, 0xff
delloop2:
dec   r17
brbc  SREG_Z, delloop2
dec   r16
brbc  SREG_Z, delloop1
ret
```

In the above code listing, 0x01 is loaded to R18, which means that the LSB of this register is set and all other bits cleared. R18 is then written to the DDRB register using the OUT instruction, which enables pin PB0 as an output pin.

In the main loop, the value of PORTB is put into R19 using the IN instruction. The value of 0x01 that was originally assigned to R18 is now reused when R18 is exclusive ORed with R19. R19 now contains the toggled bit in its LSB, which was toggled by the EOR instruction. R19 is written back to PORTB using the OUT instruction, which causes the toggled bit to be applied to the LED on pin PB0.

It was necessary to first read the value of PORTB into a general purpose working register, then perform the exclusive OR on it, and finally write the new value back to PORTB because there is no exclusive OR instruction that operates directly on PORTB. EOR can only operate on two registers at a time that are in the range R0 to R31.

It is possible to toggle all of the LEDs in the circuit from Figure 8.2 in section 8.2.1.1, using the previous code, by simply changing the value written to R18 to 0x1F. This then sets up pins PB0 to PB4 as output pins. When this value in R18 is reused in the main loop, all 5 bits of PORTB, from bit 0 to bit 4, are toggled at the same time by the EOR instruction. Exclusive OR can also be used in the C programming language to toggle an LED, as is shown in the led_eor_toggle_c code listing that follows.

```c
//#define F_CPU 1000000UL // 1MHz default clock for ATtiny25/45/85
#define F_CPU 1200000UL // 1.2MHz default clock for ATtiny13(A)
#include <avr/io.h>
#include <util/delay.h>

int main(void)
{
    DDRB = (1 << DDB0); // Set pin PB0 as an output

    while (1) {
        PORTB ^= (1 << PORTB0); // Exclusive OR to toggle LED
        _delay_ms(1000); // LED on/off delay
    }
}
```

In the above listing, bit DDB0 is set in the DDRB register, configuring pin PB0 as an output. (1 << PORTB0) evaluates to 0x01, therefore a bitwise exclusive OR is performed between PORTB and 0x01, which causes pin PB0 and attached LED to toggle. In C it looks like PORTB is directly exclusive ORed with a value, but the disassembly shows that PORTB is read, then the PORTB value exclusive ORed, then the new value written back to PORTB. Take a look at the disassembly in Microchip Studio to see for yourself.

### 8.2.4.3 Toggling an LED with the PINB Register

The PINB register, shown at the bottom of Figure 8.4 in section 8.2.1.8, can be used to toggle the state of pins when these pins are set as outputs. Writing a logic 1 to the corresponding bit in the PINB register toggles the state of the corresponding pin.

Code to toggle 5 LEDs in parallel can be seen in the led_pinb_toggle_asm project code listing that follows. Use the circuit from Figure 8.2 again to run this program. As with the led_eor_toggle_asm project, the value written to R18 at the start of the code can be changed to select which LEDs to toggle in the program.

By now you should know that the binary value 0b0000_1111 written to R18 is the same as 0x1F. To toggle the LED on PB0 alone, this value can be changed to 0x01, or the decimal value 1, or 0b0000_0001. As with the previous code listings, the same delay subroutine is called in the main loop to leave the LEDs on for a time that is visible to the eye.

```
led_pin_toggle_asm : main.asm

; Set up pins PB0 to PB4 as output pins
ldi   r18, 0b0001_1111
out   DDRB, r18

loop:
rcall delay
out   PINB, r18      ; Toggle LEDs
rjmp  loop

; Delay subroutine
delay:
ldi   r16, 0xff
delloop1:
ldi   r17, 0xff
delloop2:
dec   r17
brbc  SREG_Z, delloop2
dec   r16
brbc  SREG_Z, delloop1
ret
```

After writing 0b0001_1111 to R18, R18 is written to DDRB to set up pins PB0 to PB4 as outputs, as we have done before. R18 is then used in the main loop to send the same value to the PINB register in order to toggle all 5 LEDs at the same time. Every time through the loop, the same value is written to PINB, toggling the LEDs each time. This program uses only three lines of code in the loop and is therefore the most efficient way to toggle LEDs of the three methods shown.

Note that writing 0 to any bit in the PINB register that corresponds to an output pin will not affect the state of the output pin. In the above program, if we set pins PB0 to PB4 as output pins as before, and wrote 0b0001_1110 to PINB in the main loop so that the LSB was written 0 every time, then only pins PB1 to PB4 would toggle. Pin PB0 would not be affected at all because it would be written with 0 each time through the loop.

A program equivalent to led_pin_toggle_asm can easily be written in C. This is shown in the led_pin_toggle_c project code listing that follows. In the same way that we have done many times before, DDRB is used to set up pins PB0 to PB4 as outputs, to be used with the circuit of Figure 8.2. In the while(1) loop, the delay function is called. It does not matter whether this function is called at the top or bottom of the loop. PINB is written with 0x1F to toggle all of the LEDs on pins PB0 to PB4 at the same time.
