```
ldi     1+      ; Clock cycle used up once upon entry
delloop1:
ldi     1+      ; Clock cycle used every pass through outer loop
delloop2:
dec     1+      ; Clock cycle used by inner loop
brbc    (2 x 2) or 1+ ; 2 clock cycles on inner loop, except for last pass
dec     1+      ; Clock cycle used by outer loop
brbc    (2 x 2) or 1+ ; 2 clock cycles on outer loop, except for last pass
ret     ; Not counted in this example
```

It is easiest to start with the inner loop that consists of only two instructions as follows.

```
delloop2:
dec     1+      ; Clock cycle used by inner loop
brbc    (2 x 2) or 1+ ; 2 clock cycles on inner loop, except for last pass
```

In this code, the BRBC instruction jumps back to the delloop2 label, which is effectively the address of the DEC instruction. Because we loaded 3 to R17, and are decrementing R17 with the DEC instruction, the first two passes through the loop cause BRBC to use up two clock cycles. Two clock cycles are used because BRBC evaluates to true and branches to the DEC instruction. BRBC tests the Z or zero flag in the status register and branches if the Z flag is clear. The Z flag is always clear until R17 is decremented to 0. When R17 finally contains 0, the Z flag is set to mark that the last mathematical operation resulted in a value of 0. At this final pass through the loop BRBC uses only one clock cycle because it evaluates to false, that is, it does not branch, but executes the instruction below it. When starting with a value of 3 in R17, we therefore have the following number of clock cycles used by the inner loop. The explanation of this calculation follows.

((1 + 2) x 2) + 1 + 1 = 8 clock cycles

This is easier to visualize if we write it as follows.

|---|---|---|
| (1 + 2) x (3 - 1) | + 1 + 1 | |
| ((dec + brbc) x num_passes) | + dec + brbc | |
