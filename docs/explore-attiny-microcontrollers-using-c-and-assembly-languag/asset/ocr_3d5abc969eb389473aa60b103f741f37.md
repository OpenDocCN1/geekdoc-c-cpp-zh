After following this book you now have the skills to examine the code generated by the C compiler by examining the disassembled code in the Disassembly window of a C code project being debugged. By default, a Microchip Studio GNU C project also generates a listing file that shows the assembly language code that was generated from the C code. This file is found in the Solution Explorer pane by expanding the Output Files item, and has a .lss file extension. Double-click this file to open it in Microchip Studio.

The GNU C toolchain for AVR microcontrollers is available for various operating systems, which means that code written in AVR GNU C projects using Microchip Studio can be built on other operating systems, such as Linux. Many Linux distributions have the GNU C tools for AVR microcontrollers available in their repositories. Microchip also supply the same version of the GNU C toolchain for AVR microcontrollers used in Microchip Studio for various operating systems. These toolchains can be downloaded from: www.microchip.com/en-us/development-tools-tools-and-software/gcc-compilers-avr-and-arm

# 12.3 Where to from Here?

I hope that you have enjoyed this adventure exploring the inner workings of 8-bit AVR microcontrollers using ATtiny devices from Microchip. In this section we look at what we have achieved, and look at some ideas of where to proceed from here.

# 12.3.1 Objectives Achieved

In the introduction chapter a number of reasons were given for learning assembly language. The primary reason of properly understanding the architecture of a microcontroller has been achieved in this book. We have covered the internal working registers, memory map, instruction set, and special registers such as the status register, as well as the program counter, stack and stack pointer. Other parts of the AVR architecture such as instruction encoding, how to control on-chip peripherals, and the interrupt system were also covered.

With an understanding of the architecture of AVR microcontrollers and assembly language to program them, two other objectives have been achieved. It is now possible to write smaller more efficient code than a compiler can generate (and to mix optimized assembly language code with C code), as well as to target small AVRs with limited resources.
