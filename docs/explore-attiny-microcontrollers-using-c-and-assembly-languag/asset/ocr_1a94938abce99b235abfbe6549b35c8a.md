In the dummy ISR code, a breakpoint could be put on the NOP instruction during program testing to see if execution ever arrived at the dummy ISR. As can be seen in the dummy ISR, the code simply loops and never returns. If the watchdog timer were enabled on the microcontroller, then this would cause the watchdog timer to time out and reset the microcontroller, which may be desirable if program execution ever arrived at an unused interrupt vector.

While the full interrupt vector table has been implemented in this project, this was done for learning purposes and is actually not necessary. The address of each interrupt vector is defined at the end of the include file for the selected microcontroller. For example, at the bottom of the automatically included tn13def.inc file are the following definitions for the ATtiny13 interrupt vectors.

```
; ********* INTERRUPT VECTORS ************************************************
.equ INT0addr = 0x0001 ; External Interrupt 0
.equ PCINT0addr = 0x0002 ; Timer/Counter Overflow 0
.equ OVF0addr = 0x0003 ; EEPRom Ready
.equ ADCCaddr = 0x0004 ; Analog Comparator
.equ ERDYaddr = 0x0005 ; Timer/Counter Compare Match A
.equ OC0Aaddr = 0x0006 ; Timer/Counter Compare Match B
.equ OC0Baddr = 0x0007 ; Watchdog Time-out
.equ WDTaddr = 0x0008 ; ADC Conversion Complete
.equ ADCaddr = 0x0009
.equ INT_VECTORS_SIZE = 10 ; size in words
```

Instead of using the full interrupt vector table in this project, we could use the above definition for the timer 0 interrupt match A vector location as follows.

```
.org 0
.rjmp main ; Reset vector
.org OC0Aaddr
.rjmp ISR_tim0_compA ; Timer 0 compare match A
main:
sbi DDRB, DDB4 ; Pin PB4 as output pin
...
```

The above code starts as before, with an RJMP to main, as this is the reset vector where program execution starts. The first RJMP instruction is necessary to jump over the vector table to the main program code after powering up the microcontroller or after a reset.
