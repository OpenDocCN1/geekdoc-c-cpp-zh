
The way that microcontrollers and microprocessors generally work when fetching a machine code instruction from memory, is that the address in the program counter is placed on the address bus. A chip select line that is part of the control bus is then asserted to select the correct memory chip. The control bus read line is asserted to ensure that the instruction is read from memory. At this stage the correct instruction from memory is placed on the data bus from the memory location that is addressed. The data that is fetched from memory is a machine code instruction that will be decoded and executed by the microcontroller core or CPU (Central Processing Unit).

## 6.3 Harvard and von Neumann Architectures

Figure 6.4 shows a von Neumann architecture where the program memory, data memory and I/O address space share common address, data and control buses. AVR microcontrollers use a Harvard architecture which has separate buses for program memory and data memory as shown in Figure 6.5.

The AVR with its Harvard architecture increases performance with its parallel data and program buses. While an instruction is being fetched from program memory, data can be transferred between I/O or data memory space on the separate bus. On a von Neumann architecture, an instruction would first be fetched and executed. If the instruction was an instruction that accesses data memory, the address of the data memory would then be placed on the common address bus and the memory accessed via the data bus. The next instruction would only be fetched after the transfer from the data memory.

A Harvard architecture allows program memory and data memory spaces to both start at address 0 as they are separate address spaces. Although the EEPROM on AVR microcontrollers shares the data bus of the data memory or SRAM, it also starts at address 0 because it is accessed as a separate address space using its own set of registers and access protocol.

![](img/83ef13a6c66cc7882b2f357e97f451dc_106_0.png)

## 6.4 Fetching and Executing Instructions

All microcontrollers fetch program instructions from memory and execute them. Figure 6.6 shows a simplified block diagram of an AVR microcontroller. Machine language instructions are fetched from Flash program memory into an instruction register and decoded by an instruction decoder. An Arithmetic and Logic Unit (ALU) does mathematical and logic calculations on values in the general purpose registers. All events that occur on a microcontroller are driven by the clock pulse of the microcontroller. If the clock is stopped, the microcontroller no longer fetches and executes instructions.

AVR microcontrollers have an enhancement that improves performance when compared to general microcontrollers discussed so far. A single level pipeline allows the next instruction to be pre-fetched while the current instruction is being executed. By pre-fetching the next instruction while the current instruction is executing, an instruction can be executed in one clock cycle. Figure 6.7 shows how the pipeline improves AVR performance. In a microcontroller without an instruction pipeline the first instruction would be fetched in the first clock cycle and then executed in the second clock cycle. The second instruction would be fetched in the third clock cycle and executed in the fourth clock cycle.

![](img/83ef13a6c66cc7882b2f357e97f451dc_107_0.png)

Figure 6.6: Simplified Block Diagram of an AVR

| Clock Cycle 1 | Clock Cycle 2 | Clock Cycle 3 | Clock Cycle 4 |
| :--- | :--- | :--- | :--- |
| 1st Instruction Fetch | 2nd Instruction Fetch | 3rd Instruction Fetch | 4th Instruction Fetch |
| 1st Instruction Execute | 2nd Instruction Execute | 3rd Instruction Execute | |

Figure 6.7: AVR Instruction Fetch and Execute Pipeline

Older microcontrollers would in fact typically fetch and execute an instruction in four clock cycles, or more if the address bus is multiplexed. Four steps in executing a machine code instruction are 1) fetch the instruction from memory, 2) decode the instruction, 3) execute the instruction in the ALU and 4) store the result of the operation back in a register.

In AVR microcontrollers the instruction has already been pre-fetched in the previous clock cycle. Instruction decoding, execution and storing of the result are done in a single clock cycle – shown in the instruction execute blocks of Figure 6.7. In a single clock cycle, the AVR fetches the register operands, performs an ALU operation on the operands and stores the result in the destination register.

## 6.5 Status Register

The Status Register is updated with information about the result of the most recently executed arithmetic instruction. It also contains a global interrupt enable bit. Figure 6.8 shows the 8-bit status register and the meaning of each bit. In this section we look at how some of the bits in the status register are used in an assembly language program. Other bits in the status register are explained as they are used in programs throughout the book.

![](img/83ef13a6c66cc7882b2f357e97f451dc_108_0.png)

### 6.5.1 Zero Flag

Bit 1 in the status register is called the zero flag. A flag is a bit that signals when a certain state occurs. The zero flag signals when the result of an arithmetic operation is zero. A branch instruction can be used to test the state of the zero flag and branch if the zero flag indicates that the result of a decrement operation is not zero, as the next example program shows.

Open the test_asm project in Microchip Studio that we have been using to test small assembly language programs. Be sure to stop the debugger/simulator if it is still running from the previous code example. Replace the code with the following.

```
test_asm : main.asm - zero flag test and branch

ldi    r16, 3
del_loop:
    dec    r16
    brbc   SREG_Z, del_loop
loop:
    rjmp   loop
```

Save the main.asm file and build the project. With the simulator selected as the current tool, start the debugger and break as done previously.

The code continually decrements a value in a register until it is zero. This can be used as a simple time delay which uses up clock cycles as the value is decremented. At the beginning of the program, a value of 3 is loaded into register R16. To make a delay that is long enough for the state of an LED to be visible to the eye in an LED blink program, a much larger value would be loaded to a register. As we are using the simulator and just want to see how the zero flag is used, a small value of 3 is loaded to register R16 – we don't want to spend the whole day stepping through code waiting for a value to be decremented to zero.

In Microchip Studio, make sure that the Processor Status window is open. Find the Status Register near the top of the Processor Status window. The Status Register has all of its bits labeled with letters as Figure 6.8 shows. Step over the first and second instructions in the debugger in Microchip Studio. A value of 3 is loaded into R16 and then decremented by one. The BRBC (Branch if Bit in SREG is Cleared) instruction will be executed next. One of the operands of the BRBC instruction is SREG_Z which is the Z or zero bit of the status register (SREG). This instruction tests the Z bit of the status register and branches if this flag is clear or 0, which indicates that the result of the decrement is not zero. Because the result of the DEC instruction is 2 in R16, the result is not zero, which means that the value of the Z flag in the Status Register is 0, so the BRBC instruction causes the program to branch to the del_loop label and run the DEC instruction that follows it.

Step over the BRBC instruction and note that the next instruction to be executed is the DEC instruction again. Step through the program until R16 contains 0 and note at this point that the Z bit in the Status Register turns solid red indicating that it has changed (by changing to red) and is set (indicated by a solid color). Now that the Z flag is set rather than cleared, when the BRBC instruction is executed, it no longer branches to the del_loop label. This is because the branch only occurs if the Z bit is clear or 0. Instructions below BRBC are now executed. Step over the BRBC instruction and note that the program now continues at the RJMP instruction which is part of an infinite loop. The Z flag in the Status Register is now solid blue indicating that it is still set (solid) but did not change (indicated by blue) when the last instruction executed. A flag or bit will be red in the debugger if it changed state during the execution of the previous instruction stepped over. If the next instruction does not change the state of the flag, it will change to blue and remain blue until it is changed again.

From this exercise we can see that the state of the zero flag in the status register was set or changed to logic 1 when the result of an arithmetic operation (DEC or decrement in this example) was zero. A branch instruction was used to test the state of the flag and branch when the zero flag was clear or logic 0. As soon as the flag was set, the BRBC instruction did not cause a branch, but rather caused the instruction below BRBC to be executed.
