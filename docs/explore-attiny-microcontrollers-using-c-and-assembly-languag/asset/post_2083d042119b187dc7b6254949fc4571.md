
Again we have an unknown result of the calculation, and a variable which is the number of passes through the loop. The unknown result will be called C_T for total clock cycles.

Written with the second letter as a subscript, we have:

### C_T – total clock cycles

For the outer loop count variable, which is placed in register R16 in this code, it will be called V_OL for value or variable (V) of the outer loop (OL). Written with the second two letters as subscript, we have:

### V_OL – value or variable of outer loop

Taking our calculation, we can say the following:

```
C_T = 1 + ((1 + inner_loop + 1 + 2) x 2) + (1 + inner_loop + 1 + 1)
```

The 2 in bold in the above formula is actually 3 – 1, or V_OL – 1, which changes the formula to the following when substituted in:

```
C_T = 1 + ((1 + inner_loop + 1 + 2) x (V_OL – 1)) + (1 + inner_loop + 1 + 1)
```

Substituting in the number of clock cycles for the inner loop, represented by C_IL, we get:

```
C_T = 1 + ((1 + C_IL + 1 + 2) x (V_OL – 1)) + (1 + C_IL + 1 + 1)
```

Simplification by adding known values, we now get:

```
C_T = 1 + ((C_IL + 4) x (V_OL – 1)) + (C_IL + 3)
```

Further simplification results in:

```
C_T = ((C_IL + 4) x (V_OL – 1)) + C_IL + 4
```

Working out the multiplication results in:

```
C_T = C_IL V_OL – C_IL + 4V_OL – 4 + C_IL + 4
```

Which simplifies to:

```
C_T = C_IL V_OL + 4V_OL
```

Summarizing our formulas, we have:

### Inner loop:

C_IL = 3V_IL + 1

where:

C_IL – total clock cycles of inner loop

V_IL – value or variable of inner loop

### Outer loop:

C_T = C_IL V_OL + 4V_OL

where:

C_T – total clock cycles

V_OL – value or variable of outer loop

C_IL – total clock cycles of inner loop

The above formulas can be further simplified into one formula by substituting the inner loop formula into the outer loop formula:

C_T = (3V_IL + 1)V_OL + 4V_OL

Which multiplies out to:

C_T = 3V_IL V_OL + V_OL + 4V_OL

This can be simplified to:

C_T = 3V_IL V_OL + 3V_OL

Which can be written:

C_T = 3(V_IL V_OL + V_OL)

It can also be written with the register names instead of the symbols that we have been using, which will make the formula a bit easier to use when looking at the code:

C_T = 3 × (R17 × R16 + R16)

We can now test our new formula in Microchip Studio by changing the values written to R16 and R17, and then use the cycle counter to verify the result from the formula. Open Microchip Studio with the led_blink.asm code in a project, for example pasted into the test_asm project, so that the simulator can easily be used. Insert two breakpoints, as shown in the comments in the led_blink.asm code that follows.

```
start:    sbi    DDRB, DDB4

loop:     sbi    PORTB, PORTB4
          rcall  delay
          cbi    PORTB, PORTB4
          rcall  delay
          rjmp   loop

; Delay subroutine
delay:
ldi     r16, 3      ; Insert first breakpoint, reset cycle counter
delloop1:
ldi     r17, 3
delloop2:
          dec     r17
          brbc    SREG_Z, delloop2
          dec     r16
          brbc    SREG_Z, delloop1
ret                 ; Insert second breakpoint
```

To test the formula, different values are loaded to R16 and R17 in the code in the paragraphs that follow by changing the values at the LDI instructions, as indicated above where the values are both 3. After each change, the project must be built and then the code run in the simulator. The code must be run using the F5 key, or the Start Debugging toolbar button, so that execution stops at the first breakpoint.

At the first breakpoint, reset the Cycle Counter to 1 instead of 0 because of the bug in the simulator. After resetting the cycle counter, run the code again using F5 or the Start Debugging toolbar button, so that execution stops at the second breakpoint on the RET instruction. The cycle counter now contains the total number of clock cycles used by the delay subroutine, excluding the clock cycles used by the RET instruction. This should match the value calculated using the formula with the same values for R16 and R17.

A number of test cases follow that test the formula and show the results from the Microchip Studio simulator cycle counter. These test are done to verify that the formula works correctly and to find the limits of the values that can be used with the formula.

As we derived our formula from an example that uses a value of 3 for both R16 and R17, we start with these values in the first test case that follows.

```
R16 = R17 = 3

C_T: = 3 x (R17 x R16 + R16)
   = 3 x (3 x 3 + 3)
   = 36
```

Testing with the Microchip Studio simulator gives the same result of 36.

Now test the formula with the original values for R16 and R17 used in the code examples from previous chapters. This value is 0xFF (can also be written 0xff), which is 255 in decimal, and is also the upper extreme of any value that can be used with R16 and R17.

```
R16 = R17 = 255

C_T: = 3 x (R17 x R16 + R16)
   = 3 x (255 x 255 + 255)
   = 195840
```

When testing with the simulator in Microchip Studio, don't forget to change the values for R16 and R17, then save the changes and build the project before running the code in the simulator. Remember also to reset the Cycle Counter at the first breakpoint. The value of 195840 calculated above matches the value from the Cycle Counter in Microchip Studio.

Examining the delay subroutine code, we can see that it decrements the two count registers before testing the result of the decrement. From this we can see that loading 0 to either R16 or R17 will cause 1 to be subtracted from 0 when either of these registers is decremented. This results in -1 in two's complement format which is 0xFF in an 8-bit register. Because of this, we will leave the test case for 0 in either of the count registers for the end of our testing.

For now we test the formula with R16 and R17 equal to 1.

```
R16 = R17 = 1

C_T: = 3 x (R17 x R16 + R16)
   = 3 x (1 x 1 + 1)
   = 6
```

Testing the code with R16 and R17 both containing 1 in the Microchip Studio simulator, we get 6 cycles, the same as the result from the formula.

The next test loads R16 and R17 with values at opposite extremes between 1 and 255. Although 0 is the actual lowest extreme, it is tested last in this series of tests.

```
R16 = 1, R17 = 255
C_T: = 3 x (R17 x R16 + R16)
   = 3 x (255 x 1 + 1)
   = 768
```

The result from the Microchip Studio simulator is also 768 clock cycles, the formula is doing well in the tests so far.

R16 and R17 extreme values from the previous test are reversed in this test with R16 now loaded with 255 and R17 loaded with 1.

```
R16 = 255, R17 = 1
C_T: = 3 x (R17 x R16 + R16)
   = 3 x (1 x 255 + 255)
   = 1530
```

The calculated value of 1530 matches the measured value of 1530 in the simulator.

A couple of random values for R16 and R17 are now tested.

```
R16 = 73, R17 = 123
C_T: = 3 x (R17 x R16 + R16)
   = 3 x (123 x 73 + 73)
   = 27156
```

Once again, the calculated value matches the measured value in the simulator.

Reversing the values from the previous example, we get the following.

```
R16 = 123, R17 = 73
C_T: = 3 x (R17 x R16 + R16)
   = 3 x (73 x 123 + 123)
   = 27396
```

This result again matches the simulator measured result.

As already mentioned, we don't expect the formula to work with a value of zero loaded to either R16 or R17. Three tests follow that load zero to both R16 and R17, then to R16 only, and finally to R17 only. After completing these test cases, we have tested all values in R16 and R17 from the upper and lower extremes.

```
R16 = R17 = 0

C_T: = 3 x (R17 x R16 + R16)
    = 3 x (0 x 0 + 0)
    = 0 -- FAIL, measured result is 197376
```

```
R16 = 0, R17 = 255

C_T: = 3 x (R17 x R16 + R16)
    = 3 x (255 x 0 + 0)
    = 0 -- FAIL, measured result is 196608
```

```
R16 = 255, R17 = 0

C_T: = 3 x (R17 x R16 + R16)
    = 3 x (0 x 255 + 255)
    = 765 -- FAIL, measured result is 196605
```

The above test cases show that it is not possible to use 0 for either R16 or R17 in our formula, because the formula does not take into consideration these extreme cases that are the result of decrementing 0 before testing. After considering the previous test cases, we can finally summarize our formula in full as follows:

For: V_IL > 0 and V_OL > 0 (These values must also be ≤ 255 because of 8-bit register size)
C_T = 3(V_IL V_OL + V_OL)
Where:
C_T – total clock cycles
V_IL – value or variable of inner loop
V_OL – value or variable of outer loop

Whereas the previous summary uses a general formula, a more specific formula for the particular code using R16 for the outer loop and R17 for the inner loop, we get:

For: R17 > 0 and R16 > 0
C_T = 3 × (R17 × R16 + R16)
Where:
C_T – total clock cycles
R17 – value in register R17 used for inner loop
R16 – value in register R16 used for outer loop
