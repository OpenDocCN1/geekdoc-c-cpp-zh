
## 10.2.3.2 How the wait_ms Subroutine Works

The new wait_ms millisecond delay subroutine is based on the previous wait_1s fixed 1s delay subroutine code. The only difference between these two subroutines is the number fed into registers R16 to R19 at the start of these subroutines. Code from the start of the wait_1s subroutine is shown below.

```
wait_1s:
 ldi   R16, low  ((F_CPU - 10) / 10)
 ldi   R17, byte2((F_CPU - 10) / 10)
 ldi   R18, byte3((F_CPU - 10) / 10)
 ldi   R19, byte4((F_CPU - 10) / 10)
```

Because the wait_1s subroutine is fixed to delay for 1s, the number of clock cycles that the subroutine must use up is equal to the frequency that the AVR CPU is clocked at. Some mathematics compensates for the clock cycles used up before and after the loop in the subroutine ( - 10 above), as well as for the cycles used in the loop ( / 10 above).

How the above code is modified for the wait_ms subroutine explains how wait_ms works, and is described in the following paragraphs. In order to modify the above code to be able to use different millisecond delay values, we can start by asking how to generate a 1ms delay using this code. The code simply uses up a certain number of clock cycles, and we must just work out how many clock cycles are needed for 1ms. We know that the time period of one clock cycle is 1 / frequency, written mathematically as shown below, where f is the frequency of the AVR CPU.

![](img/83ef13a6c66cc7882b2f357e97f451dc_234_0.png)

Once we know how long one clock cycle takes, we can ask how many of these time periods are needed to make up 1ms. The answer to this question is to divide 1ms by the time period of one clock cycle to find out how many of these clock cycle periods make up 1ms. Mathematically this is written as follows, where C_T is total clock cycles.

![](img/83ef13a6c66cc7882b2f357e97f451dc_234_1.png)

Substituting the formula for the time period of one clock cycle (1/f) into the previous formula in place of t, and using the rules of mathematics, we can invert and multiply 1/f, giving us the following.

$C_T = 1 ms \times \frac{f}{1}$

One millisecond, or 1ms, is one-one-thousandth of a second, or 1/1000, which we can substitute into the above formula to get the following.

$C_T = \frac{1}{1000} \times \frac{f}{1} = \frac{f}{1000}$

From the above calculation, we see that in order for our subroutine to delay for 1ms, we must divide the CPU frequency by 1000. Thus the formula in the following line of code is modified as shown in the line of code after it.

```
ldi R16, low ((F_CPU - 10) / 10)
```

The above becomes the following for a 1ms delay.

```
ldi R16, low ((((F_CPU / 1000) - 10) / 10)
```

Of course, as the number generated by this formula is to be a 32-bit number loaded to four registers, the formula must be applied to each register as before, but it is pointless repeating the code for the other registers here.

Now that we know how to calculate the number of clock cycles to generate a 1ms delay, we can work out how to generate a delay for a specific number of milliseconds. This is done by simply multiplying the number of clock cycles for 1ms by the number of milliseconds which will be called tms. Our formula thus becomes the following.

$C_T = \frac{f}{1000} \times t_{ms} = \frac{f \times t_{ms}}{1000}$

In the code, the number of milliseconds (t_ms in the formula) is called MS_TIME_DEL. Thus with the formula applied to the code, the code now becomes the following.

```
ldi R16, low (((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
```

F_CPU sets the AVR CPU frequency in use, and MS_TIME_DEL sets the time delay to generate in milliseconds. These values are set at the start of the code as follows, using a 1MHz CPU frequency and 500ms delay as an example.

```
.equ F_CPU = 1000000 ; Frequency of CPU
.equ MS_TIME_DEL = 500 ; Time delay in milliseconds
```

The fully modified part of code from the wait_1s subroutine now becomes the following when the new calculation is applied to it for the wait_ms subroutine.

```
wait_ms:
ldi R16, low (((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
ldi R17, byte2(((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
ldi R18, byte3(((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
ldi R19, byte4(((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
```

Remember that the mathematical operators in the above expressions are performed by the AVRASM2 assembler program when it finds them in the source code file during the build process. The result is that the assembler program generates a number based on the values of F_CPU, MS_TIME_DEL and the mathematical expressions. This calculated number is then split into four parts using the functions low(), byte2(), byte3() and byte4(). These functions are also run by the assembler program during the build process, which finally results in four numbers that are loaded into R16 to R19 in the generated machine code. In effect these numbers are “hard coded” into the final machine code, and the wait_ms subroutine always generates the same time delay set by F_CPU and MS_TIME_DEL. This value can’t be changed at run time when the code is executing on the target AVR. It can only be changed at build time in the source code and set to a new value. The mathematical operators and functions used in the above code are found in the Expressions section of the AVR Assembler document from Microchip.

## 10.2.3.3 Limits of the wait_ms Subroutine

The wait_ms subroutine has certain upper and lower limits to the CPU frequency and millisecond time delay that it can be supplied with. If the number of cycles that the calculation generates and places in the 32-bit number stored in R16 to R19, is too high or too low, then the generated time delay will be incorrect. It is best to calculate these limits so that anyone using this wait_ms subroutine will supply it with in-bounds parameters.

### Simplifying the Formula

The formula in the code from the wait_ms subroutine, shown in the following code snippet, can be simplified. It is easy to see the 10 cycles that are used in the loop and the ten cycles used before and after the loop as it appears unsimplified in this code snippet. For the purposes of calculating the upper and lower limits of the wait_ms subroutine it is better to first simplify the formula. Start by taking the formula from the code shown below and write it in normal mathematical notation.

```
ldi R16, low ((((f_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
```

In normal mathematical notation the formula becomes:

\(C_T = \left( \frac{f_{CPU} \times t_{ms}}{1000} - 10 \right) \div 10\)

Instead of dividing by 10 at the end of the formula, we can invert and multiply, which gives us:

\(C_T = \left( \frac{f_{CPU} \times t_{ms}}{1000} - 10 \right) \times \frac{1}{10}\)

Doing the multiplication, we get:

\(C_T = \frac{f_{CPU} \times t_{ms}}{1000 \times 10} - \frac{10}{10} = \frac{f_{CPU} \times t_{ms}}{10000} - 1\)

In the above simplified formula, we can see that the f_CPU t_ms Combination must have a maximum value that causes C_T to be too big to fit into a 32-bit number, which is ultimately stored in R16 to R19 in the code.

### Calculating the Maximum Delay Time of the Subroutine

Because the f_CPU t_ms combination consists of two unknown values, it is reasonable to set one of these values to a known quantity so that we are left with only one unknown value. Setting f_CPU to the maximum clock frequency of the ATtiny devices that we are using leaves t_ms as the only unknown value that we want to calculate. This maximum frequency is 20MHz. The maximum value for C_T is calculated using 2^32 - 1 because C_T is a 32-bit number and this calculation gives the biggest value that a 32-bit number can hold. We can manipulate the C_T formula so that it calculates t_ms and then substitute values for f_CPU and C_T into the manipulated formula. The result of the calculation allows us to work out the f_CPU t_ms Combination that gives us the biggest possible C_T value. This value can then be used to test the upper limit of the value used in the wait_ms subroutine code. We start by writing out the simplified formula from the previous section and then manipulate it.

```
C_T = \frac{f_{CPU} \times t_{ms}}{10000} - 1
```

First get rid of the -1 by adding 1 to both sides of the equation.

```
C_T + 1 = \frac{f_{CPU} \times t_{ms}}{10000}
```

Now get rid of the 10000 from under the right side of the equation by multiplying both sides by 10000 and swap the left and right sides around because we want t_ms to be on the left.

```
f_{CPU} \times t_{ms} = 10000(C_T + 1)
```

To get rid of f_CPU on the left, divide both sides by f_CPU.

```
t_{ms} = \frac{10000(C_T + 1)}{f_{CPU}}
```

We decided to use the value 2^32 - 1 for C_T and 20MHz for f_CPU, so we can substitute these values into the formula and calculate the maximum value of t_ms.

```
t_{ms} = \frac{10000(2^{32} - 1 + 1)}{20 \times 10^6}
= 2,147,483.648
```

The final result has a fractional part, which must be removed because our 32-bit number must be an integer or whole number. 2,147,483 is therefore the biggest millisecond value that can be used with a CPU frequency of 20MHz. If we substitute these values back into the formula that calculates total clock cycles C_T, we get 4,294,965,999 which is 1296 less than 2^32 - 1.
