Remember that you can right-click a register in the Processor Status window and change the number format to decimal on the menu that pops up if you desired.

When the SUB instruction is executed, the N or Negative Flag in the Status Register is set to logic 1 indicating that the result of the arithmetic subtraction operation was negative. A branch instruction could now be used to test the state of the N flag, and run different code depending on if the result of the subtraction was positive or negative.

The result of the subtraction found in R16 is 0xF5 or 245 and is a number in two's complement format which is explained later in this book – in short it is a negative representation of a number. 0xF5 is the hexadecimal two's complement form of the decimal number -11, which is the result of 9 – 20. Converting 0xF5 to decimal in R16 of the Processor Status window does not display a negative number, because the debugger does not interpret the number as negative. The C and S flags were also set in the Status Register after the subtraction. For now, we are only looking at the N or negative flag from the status register, and will look at the other flags later in the book.

## 6.6 Stack and Stack Pointer

A stack is an area of data memory, internal SRAM in an AVR, that is used for storing temporary data and local variables. The stack is also used during interrupts and subroutine calls, where the return address is stored on the stack. For a better understanding of how the stack works, some examples of using the stack follow in a later part of this section.

The stack pointer register (SP) is loaded with an initial address of a memory location in data memory. After the address has been loaded to the stack pointer, the stack pointer is said to point to the memory location at that address. The address that the stack pointer points to is known as the top of the stack. Typically an AVR program will initialize the stack pointer register to point to the highest address location in data RAM. For an ATtiny13(A), this is 0x9F, for an ATtiny25 this is 0xDF, 0x015F for an ATtiny45 and 0x025F for an ATtiny85. We did not need to initialize the stack pointer in the led_blink_asm project from section 2.3.2 in Chapter 2 because the stack pointer defaults to the highest SRAM address in the ATtiny13(A) and ATtiny25/45/85.

### 6.6.1 How the Stack Works

A register that is to be saved to the stack is "pushed" onto the stack. This copies the value from the register to a SRAM memory location currently pointed to by the stack pointer. A value that is to be retrieved from the stack is "popped" from the stack to a particular register. A stack can be thought of like a stack of boxes. A box is put down (pushed). Another box is put on top of the first box (a second push), a third and fourth box can be added to the stack of boxes. When a box is taken from the stack (popped) the top box is removed first. This is a "last in first out" (LIFO) arrangement. Boxes can only be popped in the reverse order in which they were pushed. Figure 6.9 shows the values from registers being pushed onto the stack and popped from the stack.

![](img/83ef13a6c66cc7882b2f357e97f451dc_112_0.png)

- 1) At the top left of Figure 6.9, the stack pointer register is initialized to point to the top location of data memory which is 0x015F for an ATtiny45.
- 2) When a register is pushed onto the stack, the value that the register contains is stored at the memory location that the stack pointer is pointing to. In the figure, the value from the register that is pushed onto the stack is 0x5A. After the value has been pushed onto the stack, the stack pointer is automatically decremented to point to the next available location in data memory, 0x015E.
- 3) In the figure, a second register is pushed onto the stack that contains a value of 0x12. The stack pointer is automatically decremented again to point to the next memory address of 0x015D. The stack now contains two values.
- 4) Finally a value is popped from the stack. When a value is popped from the stack, the stack pointer is automatically incremented, then the value is copied from the memory location that the stack pointer is pointing to, to the destination register. The value that was popped from the stack is still unchanged in memory, but the stack pointer now points to it. Any new value pushed onto the stack will overwrite this value on the stack.

In AVR microcontrollers, the stack pointer register is implemented as two 8-bit registers that enable it to point to 16-bit addresses. SPL (Stack Pointer Low) is the low byte, or least significant byte of the stack pointer. SPH (Stack Pointer High) is the high byte, or most significant byte of the stack pointer. The number of actual bits implemented in the stack pointer depends on the specific AVR microcontroller. The ATtiny13(A) and ATtiny25 do not have a SPH register as it is not necessary because the SPL can address all 64 bytes of data memory in the ATtiny13(A) and 128 bytes of data memory in the ATtiny25.

### 6.6.2 Accessing the Stack with PUSH and POP

Open the test_asm project in Microchip Studio that we have been using to test various code snippets. If the debugger is still running from the previous debugging session, stop it before continuing. Replace the code in the project with the following code that demonstrates stack pointer initialization and the PUSH and POP instructions.

```
test_asm : main.asm - push pop
; Initialize the stack pointer
ldi r16, low(RAMEND)
out spl, r16
ldi r16, high(RAMEND) ; Remove for ATtiny13(A) and ATtiny25
out sph, r16 ; Remove for ATtiny13(A) and ATtiny25
ldi r16, 0x5A ; Load a value to R16
push R16 ; Save R16 to the stack
clr r16 ; R16 gets modified
pop r16 ; Restore R16 from the stack
loop:
rjmp loop
```

The code that initializes the stack at the top of the listing is not necessary because the default value of the stack pointer causes it to point to the last address in SRAM. This code was included just to show how to set up the stack in a program if ever needed. The stack pointer could be set to point to a different location in SRAM, but this is not likely to ever be done, especially in very small microcontrollers that have such small SRAM sizes. In the stack initialization code, a predefined value called RAMEND is used in the code which is the address of the last byte in data RAM. The value of RAMEND will be different for the ATtiny13(A), ATtiny25, ATtiny45 and ATtiny85 because they each have different RAM sizes. A predefined value like RAMEND is convenient because the same code can be used on different microcontrollers without the need to change it. If a different microcontroller is selected in a Microchip Studio project, the value of RAMEND will automatically change to suit the selected AVR microcontroller.

Two functions, low() and high(), are used to load the 16-bit RAMEND address to the two 8-bit registers that make up the stack pointer. In the first line of code, the low byte of RAMEND, low(RAMEND), is moved into R16. This value is then moved from register R16 to the SPL register in the next line of code using the OUT instruction. The OUT instruction means “Store Register to I/O Location”. The stack pointer is found in the I/O register file, so the OUT instruction can be used to copy a register to it. After the SPL is initialized, the high byte, SPH, is initialized with the high byte of RAMEND. This is done in the same way as the SPL, first copying the byte to R16, then using the OUT instruction to copy it to the SPH. The high() function ensures the high byte of RAMEND is copied to R16. Note that low() and high() are helper functions that the assembler program runs. These are not instructions that run on the AVR. These functions each output a number.

Code that initializes the SPH must be removed from the program, as indicated in the comments, if the ATtiny13(A) or ATtiny25 is used. This is because the SPH register does not exist in these microcontrollers. An error will be flagged in Microchip Studio if the SPH initialization code is left in for the ATtiny13(A) or ATtiny25, because SPH is undefined when these devices are selected.

For the ATtiny25, the stack initialization could be written as follows for a stack starting at SRAM address 0xDF. Here the actual address 0xDF is used instead of low(RAMEND),

```
ldi   r16, 0xDF
out   spl, r16
```
