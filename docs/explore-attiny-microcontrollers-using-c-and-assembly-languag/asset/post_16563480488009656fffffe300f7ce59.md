
Table 4.4: Counting in Hexadecimal

| Decimal | Binary | Hexadecimal |
|---|---|---|
| 0 | 0000 | 0 |
| 1 | 0001 | 1 |
| 2 | 0010 | 2 |
| 3 | 0011 | 3 |
| 4 | 0100 | 4 |
| 5 | 0101 | 5 |
| 6 | 0110 | 6 |
| 7 | 0111 | 7 |
| 8 | 1000 | 8 |
| 9 | 1001 | 9 |
| 10 | 1010 | A |
| 11 | 1011 | B |
| 12 | 1100 | C |
| 13 | 1101 | D |
| 14 | 1110 | E |
| 15 | 1111 | F |

No matter how long a binary number is, it can be converted to hexadecimal easily using Table 4.4. Simply divide the binary number up into groups of four binary digits from the right of the number, then use the table to look up each binary number and find its hexadecimal equivalent. For example, a 16-bit binary number 0b1100100111111010 can be grouped as follows:

```
1100 1001 1111 1010
```

Each group of four bit binary numbers is substituted by its hexadecimal equivalent, making the hexadecimal number:

```
C9FA
```

Another way to convert the number to hexadecimal is to place the weight value of each binary digit above each group of four binary digits, but always use 8, 4, 2 and 1 for each group as follows:

```
8421 8421 8421 8421
1100 1001 1111 1010
```

Now add the weight of each 4-bit set that appears above a 1. Ignore the weight if it appears above a 0. We therefore have the following.

| 8421 | 8421 | 8421 | 8421 |
| :--- | :--- | :--- | :--- |
| 1100 | 1001 | 1111 | 1010 |
| 8 + 4 | 8 + 1 | 8 + 4 + 2 + 1 | 8 + 2 |
| = 12 | = 9 | = 15 | = 10 |

The sum of each set of weights is shown below each 4-bit binary digit, but in decimal. This decimal number can be looked up in Table 4.4 to find the hexadecimal value. As can be seen in the table, 12 decimal is C hexadecimal, 9 decimal is 9 hexadecimal, 15 decimal is F hexadecimal and 10 decimal is A hexadecimal, giving us the hexadecimal number C9FA again.

To convert the binary number to hexadecimal without using the table, we need to count in hexadecimal. Using the above numbers that were converted to groups of decimal numbers, from the left, the first digit or MSD is 12 decimal. To convert it to hexadecimal we need to count from 0 to 9, then from 10 to 12 in hexadecimal. 10 is A, 11 is B, 12 is C, so the first digit is C. The next digit is 9 decimal which is the same value in hexadecimal, so we have C9 so far. The next digit to the right is 15 in decimal, so we need to count in hexadecimal again. Count 0 to 9, then A (10), B (11), C (12), D (13), E (14), F (15). We now have C9F. The final digit is the LSD and has a decimal value of 10. Again we count 0 to 9 and then A which is 10 decimal. We have now converted the number from binary to hexadecimal and have 0xC9FA.

The trick to getting good at converting numbers between binary and hexadecimal, and hexadecimal to binary without using Table 4.4 is to use the 8, 4, 2, 1 weighting system. It is easy to convert the numbers 0b0000 to 0b1001 (0 to 9) to their hexadecimal equivalents. For example, 0b0111 is 4 + 2 + 1 or 7 when we place 8421 above the binary number. 8 appears above a zero, so is ignored. All the other weights appear above a one, so we add them together. 0b1001 is 8 + 1, or 9. When we get above 9, from 0b1010 to 0b1111, either count the sum of the weights in hexadecimal, or start to recognize the bit patterns and get to know the equivalent hexadecimal digits A to F. When you are experienced enough you will recognize that 0b1010 is A and 0b1011 is B, etc. It is easy to remember that 0b1111 is F because it is the highest number that can be counted in a 4-bit binary number. Remember that you can also use a calculator to convert between different number systems using binary and hexadecimal when starting out.

## 4.4 Calculating Number Sizes

While on the subject of numbers and number systems, a very useful skill to learn is how to calculate the maximum value that a binary number can hold depending on how many digits it consists of. The maximum size of a number can be calculated mathematically and is useful for determining memory sizes and the maximum value that a certain storage location can hold.

### 4.4.1 Calculating the Maximum Value of a Binary Number

The formula to calculate the maximum value of a binary number is as follows.

```
2^X - 1
```

Where X is the size of the binary number in bits. The maximum size of a four bit binary number is calculated as follows.

```
2^4 - 1
= 16 - 1
= 15
```

The above calculation can be done on the Windows calculator by first putting it into Scientific mode. Click the top left menu icon on the calculator and then click the Scientific menu item. Press 2, x^, 4, = to raise 2 to the power of 4 (2^4), now press –, 1, = to calculate the result of 15. Table 4.1 and Table 4.4 confirm that 15 is the biggest number that can be represented by a 4-bit binary number.

An eight bit number can have a maximum value of 255 as shown by the following formula used to calculate the binary number maximum value.

```
2^8 - 1
= 256 - 1
= 255
```

This calculation can be done on the Windows calculator in Scientific mode again, as follows. Click 2, x^, 8, –, 1, = to get a result of 255.

### 4.4.2 Calculating Memory Size

Memory on a microcontroller consists of storage elements that are arranged as groups of cells, as we saw at the beginning of this chapter. Memory is usually arranged in groups of 8 cells that are able to store an 8-bit number or 1 byte. Each byte of memory has an address. Bytes of memory are arranged sequentially and therefore each byte of memory is followed by another byte of memory with an address that is one higher than the previous address as shown in Figure 4.4.

In the Figure 4.4 example, memory starts with the first byte at address 0 or 0x0000. The next byte is at address 1 or 0x0001, followed by a byte at address 2, and so on. Two lines in the middle of Figure 4.4 are place holders for memory that continues in the same way with consecutive bytes that each have consecutive addresses. This is followed by the last three memory locations in this particular memory. If we know what the address of the last byte in memory is, and if we know the start address of the memory, we can calculate the size of the memory in bytes.

| Address | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|---|
| 0x0000 | | | | | | | | |
| 0x0001 | | | | | | | | |
| 0x0002 | | | | | | | | |
| 0x0003 | | | | | | | | |
| ... | | | | | | | | |
| 0x025D | | | | | | | | |
| 0x025E | | | | | | | | |
| 0x025F | | | | | | | | |

Figure 4.4: Sequential Bytes and Memory Addresses

For memory that starts at address 0 and ends at address 0x25F, a calculator can be used to calculate the memory size. Simply convert the end hexadecimal memory address to decimal and then add one to perform the memory size calculation. 0x25F converts to decimal 607. Add 1 to 607 and we have a memory size of 608 bytes. 1 must be added to the result of the conversion because memory addressing starts at 0 and not 1.

If the memory of Figure 4.4 started at 0x60 instead of 0, and ended at address 0x25F, then to calculate the memory size, we need to first subtract 0x60 from 0x25F, convert the result to decimal and add one. The result of the subtraction is 0x1FF or 511 decimal. Adding 1 gives us a memory size of 512 bytes.

Also note that in Figure 4.4, the bits of each byte are numbered 0 to 7, right to left. These are 8 bits and not 7, because bit numbering starts at 0 and not 1. 0 to 7 are eight numbers, because 0 is included in the number count.

### 4.4.3 Converting Between Bytes and Kilobytes

One kilobyte of memory is 1024 bytes of memory and not 1000 bytes of memory. The reason for this is that the number closest to 1000 is represented by a 10 digit binary number or 2^10 = 1024. To calculate memory size in kilobytes we must therefore divide the memory size in bytes by 1024. For example, 2048 bytes divided by 1024 is 2, or 2 kilobytes, written as 2K bytes, or 2KB. Converting from kilobytes to bytes, we multiply by 1024, so 16K bytes is 16 times 1024 which equals 16384 bytes.

A block of memory that is 16K bytes big and starts at address 0 has its last byte of memory at the address that is one less than the size of the memory. Again, this is because addressing starts at 0 and not at 1. 16K of memory is 16384 bytes long and has its last byte of memory at address 16383 or 0x3FFF.

The reason that the maximum value that a byte can hold is one less than 2^8 or 256 is also because numbering starts at 0 and not 1. 0 to 255 are 256 numbers if we include 0 as a number. 1 to 255 are 255 numbers.

## 4.5 Numbers in Assembly Programs

When entering numbers in an AVR assembly language program, they can be in decimal, binary or hexadecimal format. Some examples follow that are used with the LDI instruction to show the usage of different numbers in an assembly language program. Usage of the LDI instruction is demonstrated in the next chapter. In each of the examples that follow, the number appears at the end of the line of assembly language code. It does not matter whether decimal, hexadecimal or binary is used in the code, the number ultimately ends up as a binary number in the microcontroller, stored as voltage levels. The number 42 decimal.

```
ldi r16, 42
```

The number 0x2A in hexadecimal.

```
ldi r16, 0x2A
```

The same hexadecimal number can be written with lowercase letters.

```
ldi r16, 0x2a
```
