The code from the previous listing can be entered into main.asm from the test_asm project in order to verify how the IFDEF directive works. If you have been following along with this book, the test_asm project is set up to use the simulator and is set up to assemble code for the ATtiny45. After building the project for the ATtiny45, start debugging and break as we have been doing. Open the disassembly window and note that code is found in this window that initializes SPH, as follows.

```
ldi     r16, low(RAMEND)      Load immediate
00000000 LDI R16,0x5F
out     SPL, r16              Out to I/O location
00000001 OUT 0x3D,R16
ldi     r16, high(RAMEND)     ; Remove for ATtiny13(A) and ATtiny25
00000002 LDI R16,0x01         Load immediate
out     SPH, r16              ; Remove for ATtiny13(A) and ATtiny25
00000003 OUT 0x3E,R16         Out to I/O location
ldi     r16, 0x5A             ; Load a value to R16
00000004 LDI R16,0x5A         Load immediate
```

The listing, as shown above from the Disassembly window, has one line from the original assembly language code, followed by what it disassembled to. The disassembled line starts with the address location of the 16-bit instruction in program memory. We can see that the first LDI instruction and OUT instruction are present that initialize SPL, as expected. Because this program was assembled for the ATtiny45, which does have an SPH register, we expect the code that initializes SPH to be present. These two lines are present at addresses 2 and 3. The program continues with the LDI instruction that loads 0x5A to R16. Code below this has not been included in the above listing.
