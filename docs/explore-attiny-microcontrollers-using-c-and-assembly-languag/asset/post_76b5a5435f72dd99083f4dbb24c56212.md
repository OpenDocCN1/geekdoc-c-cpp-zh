## 2.4.2 LED Blink C Code

Replace the skeleton C code in the main.c file with the code in the led_blink_c : main.c code listing that follows. If using an alternate circuit from Appendix B that has the LED attached to pin PB0, then use the alternate C program from section B.5.2 of Appendix B. Be sure to type in all of the code as it is shown in the listing. As with the assembler project, use the Tab key to indent the code as shown. In C programs, a semicolon (;) is not the start of a comment, but is used to terminate C statements. It is therefore important not to leave off any semicolons, or the C compiler will report errors when it is run during the build process.

```
led_blink_c : main.c

//#define F_CPU 1000000UL // 1MHz default clock for ATtiny25/45/85
#define F_CPU 1200000UL // 1.2MHz default clock for ATtiny13(A)
#include <avr/io.h>
#include <util/delay.h>

int main(void)
{
    DDRB = (1 << DDB4); // Set up pin PB4 as an output

    while (1) {
    PORTB |= (1 << PORTB4); // Set pin high (LED on)
    _delay_ms(1000); // 1 second delay
    PORTB &= ~(1 << PORTB4); // Set pin low (LED off)
    _delay_ms(1000); // 1 second delay
    }
}
```

As can be seen in the code listing, there are two definitions for F_CPU at the top of the file. F_CPU is used to tell the code what the initial clock speed of the microcontroller is set to. This is used by the _delay_ms() function to accurately set the time delay that it produces. The reason that there are two functions for F_CPU is because ATtiny13 devices have a different default clock frequency to ATtiny25/45/85 microcontrollers. The first definition is commented out using two forward slashes (//) which means that the second definition takes effect and is set up for ATtiny13 devices. If using one of the ATtiny25/45/85 devices, uncomment the top definition and comment out the second definition as shown in the following code snippet.

```
#define F_CPU 1000000UL // 1MHz default clock for ATtiny25/45/85
//#define F_CPU 1200000UL // 1.2MHz default clock for ATtiny13(A)
```

These two default clock frequencies are close enough so that the program will still work on any of the devices if the changes described above are not made, but to create more accurate timing, the changes can be made.

### 3.1 Mnemonics

The word "mnemonic" (pronounced with the first 'm' silent) means a device or technique used to assist remembering something. A simple example of a mnemonic is "Never Eat Silk Worms" used to remember the points of a compass in a clockwise direction starting with north at the top as follows: North East South West or NESW.

Assembly language instructions consist of mnemonics that are meant to be easy to remember acronyms or abbreviations, for example the mnemonic SBI stands for "Set Bit in I/O Register". Another example is LD which is short for "Load".

Mnemonics in an assembly language program are converted to their binary machine code equivalents by an assembler program. For example the mnemonic SBI is converted to the binary code 10011010 by the assembler. This binary machine code instruction can then be run by the AVR microcontroller, while its mnemonic equivalent is human readable and understandable. Technically, the SBI mnemonic is part of a machine code instruction that consists of an operational code (opcode for short) and two operands. The machine code instruction is actually 16 bits wide when the operands are included, despite ATtiny and ATmega devices having an 8-bit architecture. The opcode SBI converts to an 8-bit number as already explained, and the two operands convert to a second 8-bit number making up 16-bits. Instructions are stored 16-bits wide. This may be a bit difficult to understand at this stage, but it is properly explained as we become more familiar with the AVR architecture in the next few chapters.

The AVR assembler program used by Microchip Studio is not case sensitive, so the mnemonic instructions can be written in upper or lower case, for example SBI or sbi. This book uses uppercase when referring to mnemonics in the text and lowercase in code listings. The reason for this convention is that this is the convention used in the Microchip / Atmel datasheets and other documentation for AVR microcontrollers.
