## 8.2.5 Configuring I/O Pins as Inputs

When a switch is attached to a microcontroller pin and the pin is set up as an input, the state of the switch can be read to determine if it is open or closed. The circuit of Figure 8.6 on the next page is used to demonstrate how to read the state of a switch. Build the circuit on breadboard if you have the hardware. Although the figure shows debugWIRE being used in the circuit, readers who have a hobby programmer can connect it in ISP/SPI mode. Using pins PB3 and PB4 for the switch and LED leaves the other pins free for an ISP/SPI programmer. If using an Atmel-ICE then continue using it in debugWIRE mode.

Switch SW1 in the circuit of Figure 8.6 connects directly from PB3 to GND. With this configuration a pull-up resistor would normally be needed that connects from PB3 to +5V, as shown by the grayed out resistor R2 in the figure, so that the logic level on the pin would be logic 1 when the switch is open. When the switch is closed, the pin is connected to GND, putting a logic 0 on the pin. The pull-up resistor prevents +5V being shorted to GND when the switch is closed, but at the same time allows the two logic levels to appear on the pin when the switch is opened and when closed.

Because AVR microcontrollers have internal pull-up resistors on each pin that can be individually enabled or disabled, we do not need to put an external resistor on pin PB3. The only reason to use an external pull-up resistor would be if a stronger pull-up resistor is desired, meaning a lower pull-up resistor value, say 4k7 or 10k for example. The ATtiny13(A) and ATtiny25/45/85 datasheets shows that the internal pull-up resistors are fairly weak with a wide tolerance, specified at 20KΩ to 50KΩ. These internal pull-up resistor values are found in the Electrical Characteristics part of the datasheets.

Create the read_switch_asm assembler project in Microchip Studio and enter the code into main.asm from the listing that follows. All this program does is switch the LED on if the switch is closed, and switch the LED off if the switch is open. Because a pull-up resistor is used in the circuit, the logic is reversed. 0 is read when the switch is closed, and 1 when open.

```
read_switch.asm : main.asm

sbi   DDRB, DDB4        ; LED connected to PB4
cbi   DDRB, DDB3        ; Switch connected to PB3
sbi   PORTB, PORTB3     ; Enable pull-up on PB3

loop:
sbic  PINB, PINB3       ; Skip if switch closed
cbi   PORTB, PORTB4     ; Switch LED off
sbis  PINB, PINB3       ; Skip if switch open
sbi   PORTB, PORTB4     ; Switch LED on
rjmp  loop
```

At the beginning of the program, the SBI instruction is used to set pin PB4 up as an output pin as was done in the LED blink program. CBI is used to clear a bit in the DDRB register which sets pin PB3 up as an input pin, as can be seen in the second instruction from the code listing. Although pins default to being inputs, this instruction shows that we explicitly want to use this pin as an input, we could however leave this instruction out and the code would still work. Because PB3 is set up as an input pin, setting bit PORTB3 in the PORTB register using the SBI instruction enables the internal pull-up resistor on pin PB3. Refer back to Figure 8.4 in section 8.2.1.8 of this chapter to see the registers and bits that control the I/O port, or refer to the AVR datasheet for the ATtiny part being used.

In the main loop of the program, two instructions are used to test the state of the switch on pin PB3, namely SBIC and SBIS. Both of these instructions test the logic state of bit PINB3 in the PINB register as can be seen in the code. Bit PINB3 contains the logic state of pin PB3 because PB3 was set up as an input pin. The flowchart of Figure 8.7 shows what the code does. An explanation of the use of SBIC and SBIS follows.

SBIC (Skip if Bit in I/O Register is Cleared) skips over the next instruction if pin PB3, that the switch is connected to, is at logic level 0 (the switch is closed). When the switch is open, PB3 is at logic level 1 because of the internal pull-up resistor that is enabled. In this case, the next instruction is a CBI instruction, which switches the LED off, and is therefore not skipped. This means that when the switch is open, the CBI instruction that follows SBIC is executed and the LED is switched off.

SBIS (Skip if Bit in I/O Register is Set) skips the next instruction if PB3 has a logic 1 level applied to it (the switch is open). When the switch is open, a logic 1 is applied to PB3 because of the pull-up resistor, causing the next instruction to be skipped. If the switch is closed, a logic 0 level is applied to PB3, and now the SBIS instruction does not skip the next instruction. The next instruction (SBI) switches the LED on.

Leaving the SBIC instruction out of the program won't seem to make a difference when running the program on physical hardware at full speed. The LED will always be switched off at the top of the loop, whether the switch is open or closed. When the switch is open, the LED will never be switched on. When the switch is closed, the LED will be switched off at the top of the loop and be switched on at the bottom of the loop. Because the LED is switched off for such a short time when the switch is closed, and then switched on, it appears to be solidly on to the eye.

Start the program and break using either a hardware debugger and physical hardware, or the simulator in Microchip Studio. Step through the program with the debugger to make sure that you understand how the SBIC and SBIS instructions are being used to make decisions depending on the state of the switch. Close and open the switch as you are stepping through the code. When testing the code with the switch closed, remember to hold the switch closed and keep it closed while stepping through the code.

If you are using the simulator, you will need to simulate closing and opening of the switch by changing the state of the corresponding bit in the PINB register. To do this, start the debugger, open the I/O window using Debug ▶ Windows ▶ I/O from the top menu, and then click I/O PORT (PORTB) in the I/O window to display the I/O port registers. At the bottom of the I/O window, single-click bit 3 in the PINB register to change its state which simulates the switch changing state. Remember that bit numbering starts at 0 and not 1, so bit 3 is the fourth bit from the right. The state of the LED can be seen in the PORTB register at bit 4 (fifth bit from the right). Take note that in register PINB, when bit 3 is high, the switch is open, when low the switch is closed. This reversed logic can be a bit confusing. Be sure to think carefully about what is happening while stepping through the code.

A C program that is functionally equivalent to the read_switch_asm project is shown in the read_switch_c project code listing that follows. This program is pretty much self explanatory. The first three instructions set up the LED pin, switch pin and internal pull-up, just like the assembly language program. In the if() statement, bit PINB3 in the PINB register is tested to see if the switch is closed or open. Bitwise AND and OR operators are then used to switch the LED off or on.

```
read_switch.c : main.c

#include <avr/io.h>

int main(void)
{
    DDRB  |= (1 << DDB4);    // Set PB4 pin as output for LED
    DDRB  &=~(1 << DDB3);    // Set PB3 pin as input for switch
    PORTB |= (1 << PORTB3);  // Enable pull-up on PB3 pin

    while (1) {
        if (PINB & (1 << PINB3)) {   // If pin is high, switch is open
            PORTB &=~(1 << PORTB4);  // Switch LED off
        } else {
            PORTB |= (1 << PORTB4);  // Switch LED on
        }
    }
}
```

The original read_switch_asm code is placed alongside the disassembled read_switch_c code in the listing that follows. Register addresses have been replaced by register names, and instruction addresses have been replaced by labels in the disassembled code to make it easier to read.

It is interesting to note that the disassembled code is one instruction longer than the hand written assembly language program. Rather than use two bit test and skip instructions, the disassembled code uses a single SBIS instruction and places a RJMP instruction below it. Thus if the switch is closed, a jump occurs to the led_on label where the LED is switched
