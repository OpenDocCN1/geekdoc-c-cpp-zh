## 10.4.1.2 Using Counter/Timer0 as a Timer

In order to use Counter/Timer0 as a simple timer, it can be put into CTC mode, which stands for Clear Timer on Compare. Counter/Timer0 is referred to as Timer0 in the remainder of this text, as it is used as a timer and this simplifies its name. WGM bits are used to put Timer0 into CTC mode and are spread across the TCCR0A and TCCR0B registers. WGM stands for Waveform Generation Mode. Bits WGM[2:0], which means WGM bits 2, 1 and 0, must be set to a binary value of 010 to put the timer into CTC mode. This is indicated near the top of Figure 10.6, below the horizontal dotted line. The same information can also be found in the datasheet for the microcontroller being used. In CTC mode, a value must initially be written to the OCR0A register. After the timer is started, the actual incrementing count value is found in the TCNT0 register. This register is not shown in Figure 10.6, as it is simply an 8-bit register that holds the count value. It is found at address 0x32 on both the ATtiny25/45/85 and ATtiny13(A) ranges. When TCNT0 reaches the same value that was written to OCR0A, a compare match occurs. In CTC mode, TCNT0 is automatically cleared and the timer starts counting from 0 again. At the same time, the OCF0A bit in the TIFR or TIFR0 register is set to flag the timer compare match. Continually reading or polling this bit allows us to check if the timer has timed out.

To initially start Timer0, a value is written to the CS (Clock Select) bits in TCCR0B. This value selects the clock source that clocks Timer0, which can be either the system clock, or the system clock divided down by a prescaler division factor, or an external clock source. These options can be found in the datasheet for the microcontroller being used. The system clock divided by 1024 through the prescaler is chosen for the projects that follow, so this is the value shown in Figure 10.6 below the horizontal dotted line, to the right. As can be seen in the figure, a binary value of 101 is written to the CS[2:0] bits found in the TCCR0B register.

## 10.4.2 Polled Timer Assembly Program

An assembly language program that generates a time delay using Timer0 by polling it follows. This program blinks the LED attached to pin PB4 again, but generates the time delay between blinks from Timer0. Create the timer0_poll_asm assembly project in Microchip Studio and enter the code from the following listing into main.asm.

```
timer0_poll_asm : main.asm

.ifndef TIFR
.equ TIFR = TIFR0
.endif

ldi r17, (1 << DDB4) ; Pin PB4 as output pin
out DDRB, r17
ldi r16, (1 << WGM01) ; CTC mode for timer
out TCCR0A, r16
ldi r16, 0x7F ; Output compare value
out OCR0A, r16
ldi r16, (1 << CS02) | (1 << CS00) ; Prescaler CLK/1024 and start timer
out TCCR0B, r16
ldi r18, (1 << OCF0A) ; For clearing OCF0A flag

loop:
in r16, TIFR ; Read the TIFR register
sbrs r16, OCF0A ; Skip next instruction if timeout
rjmp loop ; Loop if not timed out
out PINB, r17 ; Toggle LED
out TIFR, r18 ; Clear OCF0A flag
rjmp loop
```

### 10.4.2.1 The IFNDEF Directive

In order to compensate for the different names of the TIFR register, which is named TIFR on the ATtiny25/45/85 and TIFR0 on the ATtiny13(A), the .ifndef directive is used at the top of the above code listing. The .ifndef directive means “if not defined”, which means that the code .ifndef TIFR only executes the code between the .ifndef and .endif directives if TIFR is not defined. If the ATtiny13(A) is selected in a Microchip Studio project, then TIFR is not defined. This means that the name TIFR is then assigned the value of TIFR0. TIFR0 is defined for the ATtiny13(A), so TIFR takes on the value of TIFR0, effectively allowing us to use the same code for the ATtiny13(A) and ATtiny25/45/85 that only references the TIFR register. If an ATtiny25/45/85 is selected in Microchip Studio, then TIFR is defined, so the code between the .ifndef and .endif directives is never executed and TIFR is not equated to TIFR0. Note that this type of checking and assignment only works up to a point. For example, the TIFR register has some bits not found in TIFR0. Code that accesses these bits can't work on ATtiny13(A) microcontrollers because they don't exist on these devices.

### 10.4.2.2 Left Shift Operator

At the start of the code of the timer0_poll_asm project, the DDB4 bit is set in the DDRB register to set up pin PB4 as an output pin, as is shown below.

```
ldi r17, (1 << DDB4) ; Pin PB4 as output pin
out DDRB, r17
```

In this code, the value to write to DDRB is first written to R17 and then R17 is written to DDRB. The value written to R17 is (1 << DDB4) which works the same way as it does in C code, as explained next. DDB4 is defined in the .inc include file of the project as follows.

```
.equ DDB4 = 4 ;
```

What the code (1 << DDB4) means is "left shift 1 DDB4 times". Because DDB4 is equated to 4, it means left shift 1 four times. 1 in binary can be written as 0b0000_0001. When this number is left shifted by 4, it means that the 1 is moved to the left four bit places. This gives a value of 0b0001_0000, which means that bit number 4 is set. Bit number 4 is bit DDB4 in the DDRB register. It is bit number 4 when counting bits from the right starting with 0. This left shift allows the name of the bit being set to be used in the code, making it easier for anyone reading the code to see which bit is being set.

We could have directly set bit DDB4 using the SBI instruction as we have done in previous projects, shown below.

```
sbi DDRB, DDB4 ; Set pin PB4 as output
```

This code is useful when setting a single bit. If more than one bit must be set in the DDRB register, then multiple SBI instruction would be needed – one for each bit to set. Using a combination of the LDI instruction and OUT instruction becomes more efficient when setting more than one bit in a register, or to write to registers that are out of range of the SBI instruction, that is registers with addresses above 0x1F. We did use the LDI and OUT combination when setting up the DDRB register to drive more than one LED in Chapter 8. In these projects we did not use the left shift operator, but wrote a value instead. When registers have many differently named bits, it is often better to use the left shift operators. When bits are similar, such as in DDRB, either use the left shift, or write a value. The main reason for not using SBI in this project is because the value in R17 is reused later.

### 10.4.2.3 Register Write or Read-Modify-Write

One difference between using SBI and the LDI/OUT combination is that SBI sets only one bit, while the LDI/OUT combination overwrites everything in the DDRB register. This may be what is required, but in some instances it may not be. In cases where a bit or bits must be set in a register, without changing other bits in the register, a read-modify-write operation must be performed. In the timer0_poll_asm project the first two lines of code, repeated again below, effectively write 0b0001_0000, or 0x10 to R17. This value is then written from R17 to DDRB using the OUT instruction which sets bit 4, but also clears all other bits. In this project, it makes no difference that the other bits are cleared.

```
ldi   r17, (1 << DDB4)  ; Write 0b0001_0000 to R17
out   DDRB, r17         ; Set bit DDB4 and clear all other bits
```

In the case where we don't want to change the other bits, the DDRB register must first be read using the IN instruction, then modified by using the OR operator to set the desired bit, or bits, and then written back to DDRB. This is done the following way.

```
in    r17, DDRB         ; Read -- read DDRB register
ori   r17, (1 << DDB4)  ; Modify -- set desired bit or bits
out   DDRB, r17         ; Write -- write value back to DDRB
```

In the above code, the value in DDRB is read and placed into R17 using the IN instruction, which is the READ part of the read-modify-write operation. ORI is used to set DDRB in R17 without changing any of the other bits, which is the MODIFY part of the read-modify-write operation. Finally the modified value in R17 is written back to DDRB, this is the WRITE part of the read-modify-write operation.

### 10.4.2.4 Initializing Timer 0

After setting up pin PB4 as an output pin, the initialization of Timer0 starts with the following code.

```
ldi   r16, (1 << WGM01)  ; CTC mode for timer
out   TCCR0A, r16
```

Firstly, R16 is used in this code because the value already written to R17 is used later in the code to toggle the LED on pin PB4. The above code sets bit WGM01 in the TCCR0A register. In this code we don't have the option to use the SBI instruction to set WGM01, because the timer registers are out of address range of the SBI instruction, as already mentioned. To put Timer0 into CTC mode bit WGM01 must be set, while WGM00 and WGM02 must be cleared. WGM02 is found in the TCCR0B register and has a default value of 0.
