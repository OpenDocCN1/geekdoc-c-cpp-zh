## 8.3 Summary

- AVR on-chip peripherals are controlled through I/O registers that are mapped in data memory space.

- Information on AVR on-chip peripherals and their registers can be found in the datasheet for the particular AVR part.

- The IN and OUT instructions can be used to copy data between the I/O registers and registers in the register file (R0 to R31). These instructions can only operate on I/O registers in the address range 0 to 63 (0x00 to 0x3F).

- SBI, CBI, SBIS and SBIC are instructions that can be used to directly write and read bits in the I/O registers.

- SBI and CBI can only set and clear bits in I/O registers from address 0 to 31 (0x00 to 0x1F).

- SBIS and SBIC can only test if a bit is set or clear in an I/O register between address 0 and 31 (0x00 to 0x1F).

- Load and store instructions are available for copying data between the register file working registers and any address location in data memory which includes the I/O registers.

### 9.1 Instructions and Labels

A line of assembly language code has the following basic format:

```
[label:] instruction [operands] [comment]
```

At a minimum, a line of assembly language consists of a single instruction. An instruction may require one or more operands, depending on which instruction it is. A label and comment are optional.

A label represents the address of an instruction or the address of the data that follows it. Labels can be written to the left of instructions or above them as shown in the following example code.

```
loop: rjmp loop ; Infinite loop
```

The following code does exactly the same thing as the above code, the position of the label makes no difference.

```
loop:
    rjmp loop ; Infinite loop
```

Each line of assembly language is divided into columns separated by tab characters or spaces. Labels appear at the very left, followed by an instruction mnemonic. If there are operands, they appear in the next column, followed by an optional comment.

There is a limit of 120 characters per line of code for the AVRASM2 assembler program. We have already seen that comments start with a semicolon, but C and C++ style comments can also be used – refer back to section 3.4 of Chapter 3 for a reminder.

Labels can consist of any alphanumeric characters, that is A to Z, a to z and 0 to 9. The underscore can also be used in label names (_). Labels may not start with a number (0 to 9), but must start with an alphabetic letter or an underscore.

### 9.2 The Preprocessor and Include Files

A preprocessor can be a separate program, or a process performed by a software tool such as a compiler or assembler before the main compilation or assembly. The preprocessor performs tasks such as including code and data from other files, substituting values in place of text, and macro expansion.

The AVRASM2 AVR assembler program supports C-like preprocessor directives that start with the hash (#) symbol, as well as assembler directives that start with a period or dot (.). For example, to include an external file in an assembly language program, the following can be used.

```
#include <tn25def.inc>
```

With the above line of code, the preprocessor does not search for the file to include in the current directory but expects the file to be in the path, indicated by angle brackets. The variation below using "" causes a search for the file in the current directory first. Both of these include preprocessor directives work in the same way as they do in a C program.

```
#include "tn25def.inc"
```

In assembly notation, there are also two forms of the include directive. With the first, shown below, the assembler program does not search the current directory for the file to include, but expects it to be in the path.

```
.include <tn25def.inc>
```

With the following directive the assembler program does search the current directory for the file to include.

```
.include "tn25def.inc"
```

When including a file with the include directive, the contents of the included file are effectively substituted into the file that contains the include directive.

In Microchip Studio, the include file for the particular AVR part selected does not have to be explicitly included because this is done in the project settings when the part is chosen during new project creation. For example tn25def.inc, which contains register definitions for the ATtiny25, is included in the project when an ATtiny25 microcontroller is chosen. This file is passed to the assembler program on the command line by Microchip Studio when the project is built – more details on this are found in Chapter 12.

### 9.3 Assembler Directives

Several directives are available for use in assembly language programs. Preprocessor directives start with #, and assembler directives start with a dot (.), as we saw with the example of the include directive in the previous section. This section looks at the most useful of these assembler directives. Preprocessor directives (starting with #) and macros are case sensitive. Assembler directives (starting with .) are not case sensitive.

Assembler directives have the following basic format:

```
[label:] directive [operands] [comment]
```

At a minimum, an assembler directive can consist of a single directive, as the following example illustrates with the CSEG directive.

```
.CSEG
```

Optionally an assembler directive can have a label and an operand or operands, followed by a comment. An example of an assembler directive with one operand is the ORG directive shown in the line of code that follows, that we cover in the next section.
