- 0 + 0 = 0

If we take another example and convert -40 to 2's complement format, first +40 is 0b0010_1000. 1's complement is then 0b1101_0111. We must now add 1 to make it 2's complement. The addition can be done on a calculator in binary mode, or using the binary addition rules mentioned above as follows. Write the 1's complement number down and place the 1 to add to it directly under the LSB as follows.

```
11010111

1
```

Add the LSB of the top number to the digit below it, which is 1 + 1. We get a result of 0 and a carry of 1. The 0 result is placed below the second number, and aligned with the LSB, as can be seen in the next box. The carry is placed above the digit to the left of the LSB as shown below. It is placed here in preparation for the next step, where it is added to the digit below it.

```
  1

+    1
=    0
```

Add the carry from the previous addition to the digit at the left of the LSB, which is the digit below the carry. This results in 1 + 1 = 0, with a carry of 1 again, which is placed above the third digit from the right, as shown in the next box. Strictly speaking, we are adding the carry, plus the digit from the first number, plus an invisible zero from the second number. In the next box the invisible zeros from the second number have been filled in with 0 digit place holders, making it 00000001. This number still has a value of 1, but it is easier to see that we are adding the remaining digits of the first number to 0 in the second number, and to the carry number.


Negative numbers in the AVR are in two's complement format. Although we won't need to convert them manually as we have just done, the above exercise of converting a number to two's complement was included to show what these numbers consist of.

## 7.2 Addition

We look at two basic addition instructions in the AVR in the subsections that follow. These are the ADD (Add without Carry) and ADC (ADD with Carry) instructions. There is a third add instruction (ADIW) that we won't look at here.

### 7.2.1 ADD – Add without Carry

We have already seen the basic ADD (Add without Carry) instruction being used to add two register values. We now look at how the ADD instruction changes the flags in the status register. Open Microchip Studio and use the test project with the simulator again. Enter the following code into main.asm of the test project, replacing the previous code.

```
test_asm : main.asm – ADD with no carry generated
ldi r16, 5
ldi r17, 9
add r16, r17
```

Step over the above code in the simulator and notice that there is no change in the flags of the status register. Change the second operand of the first instruction from 5 to 15, so the program looks as follows. Don't forget to stop the debugger first and to save and build the project again after making the change.

```
test_asm : main.asm – ADD with half carry generated
ldi r16, 15
ldi r17, 9
add r16, r17
```

Step over the above code in the debugger and notice that the H (half carry) flag is set in the status register. The half carry flag is set if there is an overflow or carry from bit 3 to bit 4 of the result of the numbers being added. In the example code, adding 15 or 0b0000_1111 to 9 or 0b0000_1001 results in a number that is bigger than four bits, in other words the number overflows or generates a carry that is put into bit 4 of the number. The result of the addition is 0b0001_1000. Starting at the right of the number and counting from 0, bits 0 to 3 are a four bit number or the lower nibble of the 8-bit number. The addition resulted in bit four being set which is a half carry from the addition of the lower two nibbles. The half carry flag is mainly used with a number format called Binary Coded Decimal (BCD) and is needed for BCD arithmetic operations. For those who are interested in how the half carry flag is used, refer to the article: en.wikipedia.org/wiki/Half-carry_flag

Modify the previous code example to add 100 to 200 as follows.

```
test_asm : main.asm - ADD with carry generated
ldi r16, 100
ldi r17, 200
add r16, r17
```

When the result of an addition is greater than 255, which is the highest value that an 8-bit number can hold, the carry flag (C flag) is set as can be seen when the above code is stepped over in the debugger.

Use the debugger and simulator to experiment with adding of numbers to get a better understanding of what the status register flags are doing. Some examples are 255 + 1 which sets the H (half carry) flag, the C (carry) flag and the Z (zero) flag. The carry flag represents a ninth bit which has a value of 256, which is the result of 255 + 1. The destination register therefore contains zero, and so the zero flag is set in this example.

If the result of an addition operation is a number that has the MSB set, the N (negative) flag will be set in the status register. The programmer can choose to treat the number as negative, if needed, or ignore the negative flag if working with positive numbers only. As an example, try 128 + 1.

### 7.2.2 ADC – Add with Carry

ADC (ADD with Carry) adds the values in two registers and the carry bit where the carry bit is added as the least significant bit of an 8-bit number. This instruction can be used when adding two 16-bit numbers that are split across four registers – two 8-bit registers per 16-bit number. The procedure to add two 16-bit numbers together would be to first add the least significant bytes using the ADD instruction, then add the most significant bytes using the ADC instruction so that the carry from the previous addition is included. An example of adding 9045 (0x2355) to 511 (0x01FF) works as seen in the paragraphs that follow using four registers R16 to R19. The addition looks as follows.

```
0x2355
+ 0x01FF
```

Load the LSB of the first number to R16. Load the MSB of the first number to R17. Load the LSB of the second number to R18. Load the MSB of the second number to R19. We now have:

| Register | Value | Description |
| --- | --- | --- |
| R16 | 0x55 | LSB 1 |
| R17 | 0x23 | MSB 1 |
| R18 | 0xFF | LSB 2 |
| R19 | 0x01 | MSB 2 |

Add the two registers containing the LSBs of each number using the ADD instruction. This is R16 + R18, or 0x55 + 0xFF = 0x54 and a carry of 1. Next, add the MSBs and the carry using the ADC instruction: R17 + R19 + carry, or 0x23 + 0x01 + 0x01 = 0x25. The result of these additions is the two 8-bit addition results put side by side: 0x2554 (9556). This example in code looks as follows. Remember to place an infinite loop below this code.

# test.asm : main.asm – Addition of two 16-bit numbers in 8-bit registers

```
; Add 9045 (0x2355) to 511 (0x01FF)
ldi r16, low(9045) ; Load first number LSB (0x55)
ldi r17, high(9045) ; Load first number MSB (0x23)
ldi r18, low(511) ; Load second number LSB (0xFF)
ldi r19, high(511) ; Load second number MSB (0x01)
add r16, r18 ; Add LSBs
adc r17, r19 ; Add MSBs with carry
```

To make it easier to use decimal notation in the program, the low() and high() functions are used to load the appropriate parts of the numbers to the desired register in byte sizes. The low() function gets the low byte of a 16-bit number and the high() function gets the high byte of a 16-bit number.

Load the above code in the Microchip Studio debugger using the simulator, and step through the program instructions while watching the results in the Processor Status window. R16 and R18 are added with the result stored in R16 and a carry generated, as can be seen by the carry flag in the Status Register. ADC is used to add R17 to R19 (the MSBs) and the carry flag from the LSB addition. The result is stored in R17. We now have the 16-bit addition result in R16 (LSB) of 0x54 and R17 (MSB) containing 0x25. Putting the two register values together we get a result of 0x2554, or 9556.
