
### CBR (Clear Bits in Register)

CBR clears bits in a register by performing a logical AND between the register and the complement of immediate data. This means that all bits in the immediate data that are set, result in the same bits in the destination register being cleared, as the first two lines of the following code show.

```
ldi    R16, 0xA5
cbr    R16, 0xF0    ; Mask is 0x0F

ldi    R16, 0xA5
andi   R16, 0xF0    ; Complement the mask value: 0xF0
```

In the first line of code above, 0xA5 is loaded to R16. In the second line of code, CBR is used on R16 with a mask value of 0x0F. This is not the equivalent of ANDI R16, 0x0F because the complement of the mask value is used, meaning that all bits in the mask value of 0x0F are inverted, causing the mask value to become 0xF0 before performing the ANDI. The result is that the value left in R16 after the CBR instruction has executed in the above example is 0xA0.

The second two lines of code above show the equivalent code using ANDI. 0xF0 is used with ANDI, which is the complement of 0x0F. Both CBR and ANDI in the above code disassemble to ANDI R16, 0xF0 which means that the assembler program must be inverting the mask value when it comes across the CBR instruction and then changes CBR to ANDI.

## 11.2.1.6 Register Set, Clear and Test Instructions

### TST (Test for Zero or Minus)

TST tests if a register contains zero or a negative value by performing a logical AND on the register and itself. This causes the status register flags S, V, N and Z to update according to what the register contains. In the code that demonstrates the use of constant data in Flash memory in section 9.3.2.2 of Chapter 9, we used a trick to update the status register Z flag by subtracting 0 from R16 to find out if R16 contained zero. In this code we could have used the TST instruction instead, as follows.

```
check_0:
lpm    r16, Z+    ; Load byte from program memory
tst    r16        ; Loop if result not zero
brbc   SREG_Z, check_0
```

This code was taken from the example code in section 9.3.2.2, near the bottom of the listing. TST causes the Z flag to update, just as subi r16, 0 did in the original code.

TST is another example of an instruction that is a synonym of another instruction, as are CLR and SER that follow. The encoding below shows that TST is the equivalent of doing an AND operation using the same register as source and destination. This operation does not modify the contents of the target register.

```
TST 0b 0010 000d dddd dddd TST Rd
AND 0b 0010 00rd dddd dddd AND Rd, Rr
```

In the following code it can be seen that an AND instruction with the same source and destination register disassembled to a TST instruction, while a TST instruction disassembled to the same TST instruction.

```
tst r16
0000 0000 TST R16 Test for Zero or Minus
and r16, r16 Test for Zero or Minus
0000 000E TST R16
```

### CLR (Clear Register)

CLR clears a register by doing an exclusive OR between the register and itself. CLR Rd is the same as EOR Rd,Rd.

### SER (Set all Bits in Register)

SER sets all bits in a register. SER Rd is the same as LDI Rd,0xFF.

## 11.2.2 Branch Instructions

Included in the branch instructions section are jump instructions, subroutine call instructions, return from subroutine, return from interrupt, compare instructions, skip instructions and finally instructions that are named starting with the word branch. Each of these types of branch instructions follow in their own subsections.

## 11.2.2.1 Jump Instructions

### RJMP (Relative Jump)

RJMP can jump in the address range PC - 2K + 1 and PC + 2K words. Note that this address range is in 16-bit words. In Table 1.1 from section 1.3 in Chapter 1, the biggest Flash memory size of the microcontrollers listed there is 8KB. Remember that these values are in bytes, so must be divided by 2 to get the number of words. An 8K byte memory is 4K words. Even with a 4K word memory, it looks like the RJMP instruction can only jump to the start and end of memory if the PC is pointing to the middle of memory. How can RJMP jump to the end of a 4K word memory if it can only jump to PC + 2K words and the PC is at 0? Jumping to PC + 2K words is easy enough to understand. If the PC contains the address 0 and an RJMP instruction jumps to address 2048, which is 2K words ahead, there is no problem – the instruction has the following format: RJMP PC+0x8800.

What happens if the PC contains zero and the instruction at address 0 jumps to 2K + 1, or 2049 (0x801)? In this case the instruction ends up as: RJMP PC-0x87FF When this instruction is executed, the PC is loaded with 0x801, or 2049. The reason that the PC is loaded with 0x801 is because -0x07FF ends up as a negative 2's complement number. To convert minus 0x07FF to its 2's complement representation, first invert all bits making the number 0xF800, which is the 1's complement of the number. Add 1 to make it the 2's complement and we get 0xF801. Because an ATtiny with 4K words of memory has a 12-bit PC, the number gets truncated to 0x801 which is the address that we want to jump to.

Take note that PC - 2K + 1 and PC + 2K words describes the range of memory that RJMP can operate on. The actual operation of RJMP is PC <- PC + k + 1, which means that the instruction jumps to the address that is the sum of the current value in the PC and the constant address k encoded into the instruction plus 1.

The following code demonstrates how to jump from address 0 to 2049, and back to 0 again.

```
.org 0
main:
    rjmp  loop

.org 2049

loop:
    rjmp  main
```

The above code disassembles to the following.

```
rjmp  loop
00000000 RJMP PC-0x87FF             Relative jump
00000001 NOP     Undefined
...
000007FF NOP     Undefined
00000800 NOP     Undefined
rjmp  main
00000801 RJMP PC+0x87FF             Relative jump
```

The actual encoding of the two RJMP instructions is as follows.

```
RJMP PC-0x07FF is encoded as 0xC800
RJMP PC+0x07FF is encoded as 0xC7FE
```

The first four bits of an RJMP instruction are always 1100 binary, or C hexadecimal. Thus the first address to jump to is encoded as 0x800, but is shown as -0x07FF in the disassembly. The first RJMP instruction therefore jumps to PC + k + 1 which is 0 + 0x800 + 1 = 0x801.

When the second RJMP instruction jumps back to 0 from address 0x801, it uses the address 0x7FE encoded in the instruction. PC + k + 1 is now 0x801 + 0x7FE + 1 = 0x1000. Again, because ATtiny microcontrollers with 8K bytes of Flash memory (4K words) have a 12-bit PC, the result is truncated to 0x000, and the second RJMP instruction jumps back to address 0.

To jump from address 0 to the last word in a 4K word memory, RJMP PC-0x0801 is used. This is encoded as 0xCFFE, so ends up as 0 + 0xFFE + 1 = 0xFFF. 0xFFF or 4095 is the last address in a 4K memory. To jump back from the last address in a 4K word memory to address 0, RJMP PC+0x0801 is used. This is encoded as 0xC000, so ends up as 0xFFF + 0 + 1 = 0x1000, truncated to 0x000.

### IJMP (Indirect Jump)

The Z register is used as a pointer register when using the IJMP instruction. IJMP jumps to the address that the Z register contains or points to. This means that the address to jump to must be loaded to the Z register before calling IJMP, and IJMP has no operands.

## 11.2.2.2 Subroutine Call Instructions

### RCALL (Relative Call to Subroutine)

RCALL has the same address range and operation on the PC as the RJMP instruction, except that it pushes the address of the next instruction onto the stack before jumping to or calling the subroutine. RCALL has been used many times in code examples in this book, so no further examples are included here. It was first used to call the delay subroutine in section 2.3.2 of Chapter 2 in the LED blink program. Calling a subroutine using RCALL is demonstrated in section 6.6.3 of Chapter 6 where it is shown how RCALL pushes the return address onto the stack. The stack and stack pointer are explained in section 6.6.
