Remember that you can right-click a register in the Processor Status window and change the number format to decimal on the menu that pops up if you desired.

When the SUB instruction is executed, the N or Negative Flag in the Status Register is set to logic 1 indicating that the result of the arithmetic subtraction operation was negative. A branch instruction could now be used to test the state of the N flag, and run different code depending on if the result of the subtraction was positive or negative.

The result of the subtraction found in R16 is 0xF5 or 245 and is a number in two's compliment format which is explained later in this book – in short it is a negative representation of a number. 0xF5 is the hexadecimal two's compliment form of the decimal number -11, which is the result of 9 – 20. Converting 0xF5 to decimal in R16 of the Processor Status window does not display a negative number, because the debugger does not interpret the number as negative. The C and S flags were also set in the Status Register after the subtraction. For now, we are only looking at the N or negative flag from the status register, and will look at the other flags later in the book.

# 6.6 Stack and Stack Pointer

A stack is an area of data memory, internal SRAM in an AVR, that is used for storing temporary data and local variables. The stack is also used during interrupts and subroutine calls, where the return address is stored on the stack. For a better understanding of how the stack works, some examples of using the stack follow in a later part of this section.

The stack pointer register (SP) is loaded with an initial address of a memory location in data memory. After the address has been loaded to the stack pointer, the stack pointer is said to point to the memory location at that address. The address that the stack pointer points to is known as the top of the stack. Typically an AVR program will initialize the stack pointer register to point to the highest address location in data RAM. For an ATtiny13(A), this is 0x9F, for an ATtiny25 this is 0xDF, 0x015F for an ATtiny45 and 0x025F for an ATtiny85. We did not need to initialize the stack pointer in the led_blink_asm project from section 2.3.2 in Chapter 2 because the stack pointer defaults to the highest SRAM address in the ATtiny13(A) and ATtiny25/45/85.
