
WGM01 and clearing all other bits. This also clears WGM00, which in any case also defaulted to 0. In fact all of the other bits in this register have a default value of 0, so in this case we don't need to do a read-modify-write. Because WGM01 is set and WGM00 is cleared, and WGM02 is already cleared or 0 in TCCR0B, Timer0 is now in CTC mode, but has not yet been started.

```
ldi   r16, 0x7F
out   OCR0A, r16    ; Output compare value
```

The value written to OCR0A plus 1 is the number of timer clock cycles that will elapse before the timer flags a compare match. 1 must be added because the timer takes an extra clock cycles to transition from the number that it counts up to, back to 0 when it is automatically reset.

In the next two lines of code, bits CS00 and CS02 are set, while bit CS01 is cleared. This selects the clock for the timer as the system clock divided by 1024. Selecting this clock also starts the timer.

```
ldi   r16, (1 << CS02) | (1 << CS00) ; Prescaler CLK/1024 and start timer
out   TCCR0B, r16
```

A value is written to TCCR0B, overwriting all bits in the register again. In this case, the two bits that are set using the left shift operator are effectively joined together using the bitwise OR operator. (1 << CS02) evaluates to (1 << 2) which results in a binary value of 0b0000_0100 because CS02 is equated to 2 in the header file. This causes 1 to be left shifted by 2. In the case of (1 << CS00), CS00 is equated to 0. The result is that we have (1 << 0) which means 'left shift 1 by 0 bit positions', resulting in 0b0000_0001. When these two values are ORed together using the bitwise OR operator |, the following results:

```
0b0000_0100
OR  0b0000_0001
=   0b0000_0101
```

When the resulting value of 0b0000_0101 is written to TCCR0B, it sets CS00 (bit 0) and CS02 (bit 2), while clearing all other bits, selecting the clock source of Timer0 as the system clock divided by 1024 through the prescaler.

Before entering the infinite loop of the program, a value is written to R18, as shown below.

```
ldi r18, (1 << OCF0A) ; For clearing OCF0A flag
```

This value sets bit OCF0A in R18, which is later written to the TIFR register to clear this flag after each timer compare match. The reason that this works on both ATtiny25/45/85 and ATtiny13(A) microcontrollers despite the fact that this bit is found at different locations in the TIFR register is because the name OCF0A is used in the above code. This name is defined correctly for the chosen microcontroller in the .inc include file of the Microchip Studio project. In the ATtiny13 include file called tn13def.inc, OCF0A is defined as follows.

```
.equ OCF0A = 2 ; Timer/Counter0 Output Compare Flag 0A
```

In the ATtiny45 include file called tn45def.inc, OCF0A is defined as follows.

```
.equ OCF0A = 4 ; Timer/Counter0 Output Compare Flag 0A
```

## 10.4.2.5 Polling Timer 0

Finally we get to the main loop of the program, shown below.

```
loop:
in r16, TIFR ; Read the TIFR register
sbrs r16, OCF0A ; Skip next instruction if timeout
rjmp loop ; Loop if not timed out
out PINB, r17 ; Toggle LED
out TIFR, r18 ; Clear OCF0A flag
rjmp loop
```

At the start of the main loop, the value from the TIFR register is read into R16 for the purpose of checking the OCF0A flag in this register. SBRS (Skip if Bit in Register is Set) checks to see if the OCF0A bit is set. This bit is only set if the timer has timed out, in other words there was a compare match between the TCNT0 register and the OCR0A register. If the timer has not timed out, then OCF0A is not set and SBRS does not skip the next instruction. The next instruction is an RJMP instruction that jumps back to the top of the main loop. This means that the TIFR register is read again and the OCF0A bit checked again.

When the timer does time out, it sets OCF0A. SBRS now detects that OCF0A is set and it skips the next instruction which is the RJMP instruction. The next instruction that is executed is therefore the OUT instruction below the RJMP instruction. This instruction writes R17 to the PINB register, which causes the LED on pin PB4 to toggle. This is because the value in R17 has the bit corresponding to pin PB4 set, which was done by leaving the value of (1 << DDB4) in R17 at the start of the code. Although the bit name corresponding to pin PB4 in PINB is called PINB4, DDB4 and PINB4 are both equated to a value of 4 in the header file, so (1 << DDB4) and (1 << PINB4) both result in the same value that sets the fourth bit in a register.

The second OUT instruction writes the value in R18 to the TIFR register. The value in R18 is (1 << OCF0A) which was written to R18 before entering the main loop. This writes a value of 1 to bit OCF0A which is necessary to clear this bit, as specified in the datasheet.

Finally the RJMP instruction at the bottom of the loop executes, causing program execution to start at the top of the loop again. This causes the code to poll the OCF0A flag in the TIFR register again to test for the next timer timeout. Note that the SBRS instruction that tests if the OCF0A flag is set is the counterpart to the SBRC instruction that we used before. The difference is that the SBRC instruction tests if a bit in a register is clear rather than set.

## 10.4.2.6 Running the Code in the Simulator

Timer0 works in the simulator in Microchip Studio. Put a breakpoint on the RJMP instruction at the bottom of the loop if using the simulator. Run the code using the F5 key. Open the I/O window and click the I/O Port (PORTB) item in the I/O window to display the PORTB registers. Execution will stop on the breakpoint after pin PB4 has been toggled. Continue using the F5 key and observe bit 4 in both the PINB and PORTB registers toggling after each stop on the breakpoint.

## 10.4.3 Polled Timer C Program

An equivalent C project to the previous timer0_poll_asm program follows. Create a new GCC C executable project in Microchip Studio called timer0_poll_c and add the code from the listing that follows to main.c of the project.

The C code project uses the same Timer0 registers as the assembly language project and operates the timer and LED in the exact same way. This code is self explanatory and any C programmer who understands the code from the timer0_poll_asm project should have no problem understanding the C code. Equivalent preprocessor directives are found at the top of the code that take care of the different names used for the TIFR register on ATtiny25/45/85 and ATtiny13(A) microcontrollers so the code can be used on all devices.

```
timer0_poll_c : main.c

#include <avr/io.h>

#ifndef TIFR
#define TIFR TIFR0
#endif

int main(void)
{
  DDRB = (1 << DDB4);       // Pin PB4 as output pin
  TCCR0A = (1 << WGM01);    // CTC mode
  OCR0A = 0xFF;             // Output compare value
  TCCR0B = ((1 << CS02) | (1 << CS00)); // Prescaler CLK/1024 and start timer

  while(1) {
    if (TIFR & (1 << OCF0A)) { // Check for timer compare match
      PINB = (1 << PORTB4);   // Toggle pin PB4
      TIFR = (1 << OCF0A);    // Clear OCF0A flag
    }
  }
}
```

Although the above code works in the same way as the assembly language code did in the previous section, the value written for OCR0A is a bigger value. This is done so that the LED will blink at a slower rate for the assembly language program. In this way, when the code is loaded to hardware that is already running the assembly language version of the code, it can be seen that the new program did indeed load because the LED is blinking more slowly.

## 10.5 Timer Interrupt Delay

The interrupt system of a microcontroller is implemented in the hardware of the microcontroller by the designer and manufacturer of the microcontroller. Interrupts are configured and enabled using software by the end user programmer.

An interrupt system allows an event, such as a timer timeout, to interrupt the current flow of a program. When an interrupt is triggered, program flow automatically jumps to a special subroutine called an Interrupt Service Routine, or ISR. The code in the ISR can be anything that the programmer wants. To use the timer example that follows, the main program sets up the timer and an interrupt, and then enters an infinite loop that does nothing. When the timer times out, it interrupts the infinite loop and calls the ISR. In this project, the ISR toggles the LED. It then returns and the main loop continues running.
