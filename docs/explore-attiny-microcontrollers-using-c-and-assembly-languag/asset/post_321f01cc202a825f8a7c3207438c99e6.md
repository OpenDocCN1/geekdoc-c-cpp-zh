
Now step over the first instruction, using the F10 keyboard key, which moves 34 into R16 and note that this value is now displayed in R16 in the Processor Status window. If you did not change the value to display in decimal, the value will be displayed as 0x22. The number system that the value is displayed in can be changed any time by right-clicking the register and choosing the desired number system from the pop-up menu. The LDI instruction has the format LDI <destination>, <source>. This results in the value on the right being moved into the register on the left, and is similar to writing R16 = 34.

The second instruction is the same as the first, but this time 12 decimal is loaded to register R17, as shown below. Step over this instruction in Microchip Studio and note that the value changes in the Processor Status window next to the R17 item.

```
ldi r17, 12
```

The third instruction, shown below, is ADD (Add without Carry), which adds the value in R16 to the value in R17 and stores the result back in R16.

```
add r16, r17
```

Step over the ADD instruction and the result of adding 34 to 12 is seen in R16, that is 46 appears in register R16. The format of the ADD instruction is similar to the shorthand C notation R16 += R17, where R17 is added to R16 and the result saved back into R16. This can be written out in full as R16 = R16 + R17. We will never use C in this way to directly access these registers by name. C notation is used here just to explain what the assembly language instruction is doing.

The last instruction in the code listing creates an infinite loop to stop the microcontroller from trying to run instructions beyond the end of the program. This code is shown below.

```
loop:
    rjmp loop
```

RJMP (Relative Jump) is used to jump to the loop label, which causes the RJMP instruction to run again infinitely. Without the infinite loop at the end of the program, the microcontroller will automatically fetch and execute the next instruction in memory after our program. The next instruction is undefined and will be whatever happens to be in memory after our program. This can result in undefined and unwanted behavior of the microcontroller. For this reason, a program that does not have a main loop, should always end with an infinite loop.

As indicated in Figure 5.1, the LDI instruction can only be used to load a data value to registers R16 to R31. This is indicated by a line dividing the general purpose register file in half in the figure. For this reason registers R16 and R17 were used in the add registers code example instead of registers R0 and R1. If you try to use the LDI instruction with R0 to R15, an error will be flagged when building the project in Microchip Studio. The same applies to the SER instruction which is used to set all bits to logic 1 in a register. SER can only be used on registers R16 to R31. This also applies to the ANDI and ORI instructions seen in the figure, which are covered in a later chapter. These are just four examples of instructions that can only operate on R16 to R31, there are others. Also shown in the figure is the bit numbering of a register at the top right of the figure. Bits in a byte are numbered from 0 to 7, right to left whether they occur in registers or memory.

### 5.2.2 Incrementing a Register

In this example of register usage, we clear a register and then increment it. Incrementing a register means adding one to the register. Use the same test project from the previous example – replace the code with the following, but leave the infinite loop at the bottom which is not shown in the code below. Before replacing the code, stop the debugger if it is still running from the previous example.

```
test_asm : main.asm - increment register

clr   r0
inc   r0
inc   r0
inc   r0
```

Build the project and then start the debugger as before (start debugging and break). The Processor Status window should automatically open in Microchip Studio when debugging is started, as it was used in the previous example. Scroll up in the Processor Status window so that register R0 (R00) is visible.

The first instruction, CLR (Clear Register), clears register R0, which sets its value to zero. By default the register already has a value of zero when using the simulator. No change will be seen if the instruction is executed when R0 already contains 0x00. The value in this register can be changed in the debugger by double-clicking the value next to R00 in the Processor Status window before stepping over the CLR instruction, so that it is possible to see what this instruction does. For example, double click 0x00 next to R00 in the Processor Status window, type 45 and then press the Enter key. This number will change to hexadecimal and display as 0x2D after hitting the Enter key. It may be easier to see this number by clicking one of the other registers to move the focus off this register. Now step over the CLR instruction and the value in R0 will be cleared to zero (R0 and R00 are the same register. R0 is labeled R00 in the Processor Status window).

The INC (Increment) instruction is repeated three times after the CLR instruction, and is used to increment register R0. Step over the INC instructions and note that R0 increments by one after each INC instruction is executed. When the RJMP instruction is reached at the end of the program, R0 contains 0x03 as expected after three increments. Unlike the LDI instruction, the CLR and INC instructions can be used on any of the general purpose registers from R0 to R31. As already mentioned the counterpart to the CLR instruction, SER, sets all bits in a register, but only works on R16 to R31 and not on R0 to R15 – refer back to Figure 5.1. Experiment with these instructions in Microchip Studio. Try building a project that uses LDI or SER on registers R0 to R15 to see the error displayed in Microchip Studio. Remember to save and build the program each time after making changes to the code. Quick Tip: After building the project, hit the F10 key immediately to start the debugger and break instead of having to click the toolbar button. Continue pressing the F10 key to step over each line of code after this.

The previous two examples show some of the ways that the general purpose working registers are used in assembly language programs. Registers can be used to store values to be used in mathematical calculations and to store the results of calculations. The same applies to Boolean, or logical operations which are still to be covered. Usage of registers will become clearer as you progress through this book and see more code examples, and how other assembly language instructions operate on registers.
