
### 6.1.2.3 RC Oscillator Accuracy

Because the default clock for the AVR is derived from an RC oscillator it is not as accurate as a clock from a quartz crystal oscillator. An accuracy of ±10% is given in the datasheet for the RC oscillator. This accuracy is specified when operating the AVR from 3V at a temperature of 25°C.

### 6.1.2.4 Clock Sources and Improving Accuracy

An external quartz crystal can be used on the ATtiny25/45/85 to produce a more accurate clock source, but this uses up two pins of the microcontroller. This is one of the ways where ATtiny25/45/85 devices differ from ATtiny13(A) devices – ATtiny13(A) devices only have three clock sources to choose from, namely, an external clock input, internal RC oscillator, and internal 128kHz oscillator. This means that ATtiny13(A) devices do not have a crystal oscillator circuit, so can't use an external crystal or ceramic resonator directly on two pins. ATtiny25/45/85 devices on the other hand, have all of the clock sources that ATtiny13(A) devices have as well as a high frequency PLL clock, an additional internal RC oscillator source, a low-frequency crystal oscillator (uses an external 32.768kHz watch crystal), and a crystal oscillator / ceramic resonator derived clock (uses an external quartz crystal or ceramic resonator).

Another way of improving the accuracy of the oscillator is to follow a calibration procedure for the RC oscillator that uses a calibration register in the AVR. Alternatively an external clock source can be used that will use only one extra pin of the microcontroller.

### 6.1.2.5 Calculating Clock Period from Frequency

If an AVR is operating at 1MHz, then the period of its clock or clock pulse is 1µs (one microsecond). This means that an instruction that takes one clock cycle to run will be executed in 1µs. To convert from frequency to period, use the formula:

$t = \frac{1}{f}$ Where t is the time period and f is the frequency.

It is easy to convert between clock frequency and period using a calculator as follows. For a 1MHz frequency we divide one by one million and get 0.000001 or 1µs. To do this on the Windows calculator, first put the calculator into scientific mode using the top left menu icon. Click 1, +, 1, exp, 6, and then = which displays a result of 0.000001. Click the F-E button on the calculator and the result now displays as 1.e-6.

When entering this calculation, we are using exponential notation where the key presses 1, exp, 6 (one exponent six) is a way of writing one million which is 1 followed by 6 zeros. The result of the calculation is 0.000001 which is easier to read after pressing the F-E button which changes the number to 1.e-6 or one exponent minus six. Minus six lets us know that this is microseconds. Click the F-E button again to change back to normal notation.

### 6.1.2.6 Calculating Clock Frequency from Period

To convert from period to frequency, use the formula:

f = 1/t Where t is the time period and f is the frequency.

To find the frequency of a clock source with a 1µs period on the Windows 10 calculator in scientific mode, enter 1, +, 1, exp, 6, ±, then click = followed by the F-E key. The key presses 1, exp, 6, ± is the same as one exponent minus six which is 0.000001 where -6 represents size in decimal places to the right of the decimal point. The ± key simply changes the sign of 6 from + (positive) to - (negative). The result of the calculation is 1.e+6 which is 1,000,000 or one million (1MHz). Pressing the F-E key converts the number to exponential notation which is easier to read as we can see that it is one with six zeros and know that it is therefore 1MHz or one megahertz.

To summarize, on the calculator, 1.e+6 is 1 exponent 6, or 1 x 10^6 or 1,000,000. Ten to the power of 6, or 1 followed by six zeros is mega, or megahertz if we are dealing with frequency. 1.e-6 is 1 Exponent -6, or 1 x 10^-6, or 0.000001 and is micro, or microseconds when dealing with period.

### 6.1.3 The Program Counter

A program counter (PC) is a register in a microcontroller that contains the address of an instruction to execute. When an AVR microcontroller is powered on or reset, the program counter is reset to zero so that it addresses the first instruction in Flash memory at address 0x0000. This allows microcontroller to fetch the instruction at address 0, and execute it. The program counter is then incremented by one so that it points to the next instruction in Flash program memory at address 0x0001. The microcontroller then fetches the instruction at 0x0001 and executes it. Again the program counter is incremented so that it points to the instruction at 0x0002, which is fetched and executed.

The program counter or PC continues to be incremented by one and the instruction that it points to is fetched and executed each time. Instructions are fetched and executed sequentially until a branch or jump instruction is executed that causes a non-sequential address to be loaded to the program counter. Once the jump has occurred, the instruction at the new address is fetched and executed, then the program counter continues to increment by one causing the microcontroller to fetch and execute sequential instructions after the new address that it jumped to. Calling a subroutine and returning from a subroutine also causes the address in the program counter to be altered so that the subroutine can be run. The above explanation assumes 16-bit wide instructions.

When a 32-bit wide instruction is executed, the program counter will be seen to increment by two in the debugger. Opening the led_blink.asm project from Chapter 2 and running it in the debugger shows that the instructions in the main program are all single cycle instructions. After stepping over each instruction, the program counter increments by one. When the RJMP instruction is executed at the bottom of the main loop, the program counter is loaded with the address of the SBI instruction under the loop label and execution starts at the top of the loop again.

The program counter can be thought of as a binary counter that is driven by the main clock of the microcontroller and continues to count up with each clock pulse. A new count value is loaded to the PC when a jump or branch instruction is executed or a subroutine is called or returned from. The count value, of course, is used to address memory which causes the microcontroller to fetch an instruction from that memory address and execute it.

The ATtiny13(A) program counter is 9 bits wide so that it can address 2^9 or 512 16-bit wide instructions, which of course is 1024 bytes, or 1K. In the ATtiny25, the program counter is 10 bits wide because it only needs to address 2^10 instructions (1K or 1024 instructions) which is 2^10 x 2 bytes (2K or 2048 bytes because the program memory is 16-bits wide). In the ATtiny45, the program counter is 11 bits wide so that it can address its 2^11 or 2K 16-bit wide instruction memory (4K bytes). The ATtiny85 has a 12 bit wide PC for its 2^12 or 4K 16-bit wide instructions (8K bytes).

## 6.2 Microcontroller Buses

A bus on a microcontroller or microprocessor is a group of wires. An 8-bit bus is a group of 8 wires. Figure 6.4 shows a block diagram of a general microcontroller that has an address bus, data bus and control bus represented by wide lines. The address bus could be 16 bits wide, depending on the microcontroller, and would then consist of 16 wires. An 8-bit microcontroller would have an 8-bit wide data bus consisting of 8 wires. The number of wires on the control bus varies between architectures, but usually has some chip select lines as well as read and write control lines. Microcontroller buses are used to get data from, and send data to memory and I/O devices. Depending on the microcontroller, the buses may be internal only, or extend to pins on the microcontroller allowing external memory and peripherals to be interfaced to the microcontroller buses.
