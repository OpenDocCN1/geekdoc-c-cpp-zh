
## 10.2.2 A Better Software Delay Subroutine

An improved software delay subroutine is included in the listing below as part of the led_blink_asm code. This new program is now called wait_1s_asm and includes a subroutine called wait_1s that delays for exactly one second. At the top of the listing, the frequency of the AVR that the code is to run on must be assigned to F_CPU. As can be seen, two frequencies have been provided, with one commented out. These are of course for the ATtiny25/45/85 and ATtiny13(A) default frequencies of 1MHz and 1.2MHz respectively. When the frequency is correctly set at the top of the code, the LED attached to pin PB4 stays on for 1 second as the code in the main loop runs.

```
wait_1s.asm : main.asm

; .equ F_CPU = 1000000
.equ F_CPU = 1200000

start:
    sbi DDRB, DDB4    ; Set pin PB4 as output

loop:
    sbi PORTB, PORTB4 ; Set LED pin high
    rcall wait_1s     ; LED on delay
    cbi PORTB, PORTB4 ; Clear LED pin low
    rcall wait_1s     ; LED off delay
    rjmp loop

; 1 second delay subroutine
wait_1s:
    ldi R16, low ((F_CPU - 10) / 10) ; Load number of loop cycles
    ldi R17, byte2((F_CPU - 10) / 10) ; to registers R16 to R19
    ldi R18, byte3((F_CPU - 10) / 10)
    ldi R19, byte4((F_CPU - 10) / 10)

wait_1s_loop:
    subi R16, 1    ; Perform decrement on 32-bit
    sbci R17, 0    ; number in R16 to R19
    sbci R18, 0
    sbci R19, 0
    mov R20, R16   ; Determine if 32-bit number is
    or R20, R17    ; zero using OR and BRBC
    or R20, R18
    or R20, R19
    brbc SREG_Z, wait_1s_loop ; Balance BRBC to 2 clock cycles
    nop            ; Balance instructions outside of
    nop            ; loop to 10 clock cycles
    ret
```

### 10.2.2.1 Principle of Operation

The principle of operation of the wait_1s subroutine is to decrement a 32-bit number until it is zero in order to waste enough time to cause the desired delay of 1 second. If the frequency that the microcontroller is running at is 1MHz, then the subroutine must use up one million clock cycles to create a 1s time delay. This is because 1MHz is 1 million cycles per second, meaning that at this frequency, 1 million cycles take one second to complete.

Some of the ATtiny microcontrollers used in this book can operate up to a maximum clock frequency of 20MHz. Because frequency is measured in Hertz (Hz), which is clock cycles per second, and the wait_1s subroutine is to delay for 1 second, the number of clock cycles to use up for a 1s delay equals the frequency that the microcontroller is operating at. For the maximum frequency of 20MHz, 20 million clock cycles must complete to use up 1s. If the microcontroller is operating at 1.2MHz, then 1.2 million cycles must complete to use up one second, and so on for whichever frequency is being used. F_CPU at the top of the code must be changed to the frequency that the microcontroller is operating at in order for the wait_1s subroutine to correctly delay for 1s.

### 10.2.2.2 32-bit Subtraction with 8-bit Registers

In order to perform subtraction from a 32-bit number on an 8-bit processor, four 8-bit registers are needed to hold the 32-bit number. In the wait_1s subroutine, registers R16, R17, R18 and R19 are used to hold the 32-bit number to subtract from. If the subtraction process took only one clock cycle, then we would only need to load the value of the frequency that the microcontroller is operating at to these registers, as follows.

```
ldi   R16, low (F_CPU)
ldi   R17, byte2(F_CPU)
ldi   R18, byte3(F_CPU)
ldi   R19, byte4(F_CPU)
```

In the above code, we have the familiar low() assembler function that gets the lower byte of the F_CPU value. New in this code is byte2(), byte3() and byte4() which operate in the same way as low(), but get the second, third and fourth bytes of a 32-bit number. These functions are found in the AVR Assembler document. What the above code therefore does is load the value of F_CPU to R16, R17, R18 and R19, byte by byte in order, starting from the least significant byte up to the most significant byte. As it turns out, the subtraction process takes more than one clock cycle. The code in the wait_1s.asm listing therefore does not directly load the value of F_CPU to the registers, but does some mathematical compensation, that is explained in the next section.

The actual subtraction is performed by one SUBI (Subtract Immediate) instruction and three SBCI (Subtract Immediate with Carry) instructions as shown in the following code.

```
subi R16, 1    ; Perform decrement on 32-bit
sbci R17, 0    ; number in R16 to R19
sbci R18, 0
sbci R19, 0
```

The above code is the counterpart to the addition from section 7.2.2 in Chapter 7, where one ADD (Add without Carry) instruction and one ADC (Add with Carry) instruction are used to add two 16-bit numbers and take into consideration the carry. In the negative version of this code as shown above, the subtraction is simply expanded to operate on four registers. In this code, the SUBI instruction subtracts 1 from R16, the LSB. The SBCI instruction is then used to subtract 0 from R17, R18 and R19. Because this instruction takes into consideration any carry that is generated by the subtraction, R17, R18 and R19 are decremented only when a carry occurs. This effectively allows a 32-bit number spread over four registers to be decremented by one each pass through the loop.

The final part of the code in a loop determines whether the 32-bit number in R16 to R19 is zero. This is done by using a logic OR operation that ORs R16, R17, R18 and R19 together, as shown in the following listing. If any of these registers contains a number other than zero, then the result of the OR operations is not zero, which causes the BRBC instruction to jump back to the top of the loop and do another decrement.

```
mov R20, R16    ; Determine if 32-bit number is
or R20, R17     ; zero using OR and BRBC
or R20, R18
or R20, R19
brbc SREG_Z, wait_1s_loop
```

Because the AVR OR instruction is destructive, in that it puts the result of the OR operation into the first register overwriting its contents, an additional register is needed to hold the result of the OR operations. R20 is the register used in the above code to store the result of the OR operations. Firstly, the value in R16 is copied to R20 using the MOV (Copy Register) instruction. After this, R17, R18 and R19 are consecutively ORed with R20, which holds the running result of the OR operations. As R20 is used to store each result, the values in R16 to R19 are never modified or overwritten. After the series of OR operations have completed, the Zero bit in the status register is set only if R16 to R19 all contain zero. This causes program execution to continue below the BRBC instruction. If any of these registers does not contain zero, BRBC jumps to the top of the loop.

### 10.2.2.3 Timing of the Code

Now that we understand the basic working of the wait_1s subroutine, we can examine the timing of the instructions used in this subroutine. The code is repeated below, showing the number of clock cycles used by each instruction

```
wait_1s:
ldi    R16, low  ((F_CPU - 10) / 10)   ; 1 clock cycle
ldi    R17, byte2((F_CPU - 10) / 10)   ; 1 clock cycle
ldi    R18, byte3((F_CPU - 10) / 10)   ; 1 clock cycle
ldi    R19, byte4((F_CPU - 10) / 10)   ; 1 clock cycle

wait_1s_loop:
subi   R16, 1                          ; 1 clock cycle
sbci   R17, 0                          ; 1 clock cycle
sbci   R18, 0                          ; 1 clock cycle
sbci   R19, 0                          ; 1 clock cycle
mov    R20, R16                        ; 1 clock cycle
or     R20, R17                        ; 1 clock cycle
or     R20, R18                        ; 1 clock cycle
or     R20, R19                        ; 1 clock cycle
brbc   SREG_Z, wait_1s_loop            ; 1 clock cycle
nop                                  ; 1 clock cycle
nop                                  ; 1 clock cycle
nop                                  ; 1 clock cycle
ret                                  ; 4 clock cycles
```

As can be seen in the code, every instruction takes only one clock cycle, except for the BRBC instruction and the RET instruction. As we know, the BRBC instruction takes two clock cycles when it branches to the top of the loop, and one clock cycle when it does not branch. In order to effectively make this instruction always use up two clock cycles, a single NOP instruction is placed below it. This means that when BRBC does not branch, it executes the NOP instruction below it effectively using up two clock cycles instead of one.

Instructions in the loop, shown in bold in the above listing, add up to 10 clock cycles. The NOP instruction directly below BRBC is included in this total, as it effectively causes the final execution of BRBC to still use up two clock cycles. F_CPU must be divided by these 10 clock cycles before being loaded into R16 to R19 at the top of the subroutine. This is because the subtraction process in the loop uses up these 10 clock cycles and the subroutine would therefore take 10 times longer if we did not compensate for these 10 clock cycles.
