Figure 6.14 shows how the two LDI instructions are encoded. The first four bits of an LDI instruction are always be 1110 binary, as shown in Figure 6.14 and Figure 6.12. LDI has a constant operand value that gets loaded to the selected register – in the example code this value is 5 for the first LDI instruction and 12 for the second. This constant value is split into two four bit parts as shown by KKKK in the figure when it is encoded into binary. When the two four bit parts are put together they form the 8-bit constant number that is loaded to the register. The constant number can be a value between 0 and 255, or 0b00000000 and 0b11111111. This value range appears in the instruction set manual in the LDI description section shown in Figure 6.12 as 0 ≤ K ≤ 255, which means that the constant value can be greater than or equal to 0, and less than or equal to 255.

The destination register is a four bit value dddd in Figure 6.14 and Figure 6.12. This value can be between 0b0000 and 0b1111, but because the instruction operates only on R16 to R31, it is offset by a value of 16. This means that 16 must be added to the binary encoded register value to get the actual register that is encoded in the instruction. 0b0000 therefore references R16 (0 + 16) and 0b0001 references R17 (1 + 16). Register R31 is encoded as 0b1111 (15) + 16 = 31. It should now make sense why some instructions are limited in the number of registers that they can operate on as follows. LDI instructions are 16 bits wide. The first four bits are always 0b1110. Eight bits are used to encode the constant data value in the instruction. This leaves only four bits to address the destination register. The maximum number of address values that a four bit number can have is 2^4 = 16 (with addresses 0 to 15). The instruction is only capable of addressing 16 registers which have been chosen as R16 to R31 by using an internal offset of 16 on the encoded address.

The ADD (Add without Carry) instruction always starts with 00001, followed by the MSB of the source register address, then the MSB of the destination register address. Four bits of the destination register follow and then four bits of the source register. As shown at the top of Figure 6.15, each 5-bit register address is made up of an initial bit and then the four bits that follow. In the example in the figure, the source address is 17 (0b10001) which addresses R17 and the destination address is 16 (0b10000) which addresses R16. A five bit address is capable of addressing 2^5 = 32 address locations from 0 to 31 which correspond to registers R0 to R31 from the register file. Refer to the ADD instruction in the instruction set manual to see which status register flags are changed after the ADD instruction is executed.

Finally the RJMP (Relative Jump) instruction appears at the end of the example code and can be found at the bottom of Figure 6.15. An RJMP instruction always starts with the binary digits 1100, followed by a 12-bit address. The address encoded in the RJMP instruction is an address that is relative to the current address in the program counter (PC). The jump can occur to a higher address if the address is positive or to a lower address if the address is negative. In the instruction set manual, the range of the relative jump instruction is given as PC – 2K + 1 to PC + 2K (words). This means that a jump can occur to a lower address, at the current PC address minus 2048 + 1, or to a higher address up to PC + 2048 where each address is the address of a 16-bit wide instruction.

In the example program the RJMP instruction is used to jump to the top of the program which means that the jump is jumping to a lower address. The address that is encoded in the instruction in Figure 6.15 is a negative number in two's complement format – 0b111111111100 which has a decimal value of –4. In the code we can see that the RJMP instruction jumps to the first instruction of the program at address 0, where the loop label is. This address is obtained from the formula PC – address + 1, where address is the address encoded in the RJMP instruction. There are four 16-bit instructions in the program starting at address 0 with the RJMP instruction at address 3. The PC will therefore contain 3 when the RJMP instruction is executed. We can calculate the address that will be jumped to as follows: 3 – 4 + 1 which is 0, so the program will jump to address 0 as expected. This just shows how the RJMP instruction is encoded. Fortunately we don’t need to do a calculation like this while programming because we can use labels as destinations to jump to, and let the assembler program calculate the relative address.

## 6.9 Addressing Modes

Addressing modes are part of any microcontroller or microprocessor instruction set architecture. Addressing modes specify the different ways that instructions access source and destination data, which is how the instructions address memory locations and registers or constant data values. In AVR microcontrollers, the addressing modes allow instructions to access program memory and data memory. Data memory includes SRAM and the registers that are mapped to data memory space, which includes the register file and I/O registers. AVR addressing modes can be found in section or Chapter 3 of the AVR instruction set manual. We will not go into great detail on all of the addressing modes yet, but rather look at examples of different addressing modes for a better understanding of what they are.
