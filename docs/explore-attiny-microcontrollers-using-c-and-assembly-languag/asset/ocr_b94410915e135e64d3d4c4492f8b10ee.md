# 10.3 Calling an Assembly Subroutine from C Code

It is easy to call an assembly language subroutine from a C code program. The most important information to have when calling a subroutine from C code is the registers used to pass values to a subroutine and registers used to return values from a subroutine. Register usage by C compilers may be different for different compilers, even for the same microcontroller. This information is available for the avr-gcc compiler in an application note called Atmel AT1886: Mixing Assembly and C with AVRGCC available from: ww1.microchip.com/downloads/en/Appnotes/doc4255.pdf

In the example that follows in the next section, an assembly language subroutine is called from C code and passed a 32-bit value. In the section after the next section, an assembly language subroutine called from C code returns a value.

# 10.3.1 Passing a Value to an Assembly Subroutine from C

The following subroutine code is taken from the wait_ms_macro_asm project in section 10.2.4.2 of this chapter. Some modifications have been done to the code to make a C program able to call the assembly language subroutine. The subroutine is the code that we put into a macro and generates a variable millisecond time delay. In the modified code the subroutine is called wait_ms because this name is short and descriptive. Don’t confuse this subroutine with an earlier subroutine that had the same name. The project consists of three files. Create a new GCC C Executable Project in Microchip Studio called wait_ms.c. Replace the code in main.c of the project with the following code.

```
wait_ms_c : main.c

#define F_CPU 12000000

#include <avr/io.h>
#include "wait_ms.h"

int main(void)
{
    DDRB |= (1 << DDB4);    // Set up pin PB4 as an output

    while (1)
    {
        PORTB |= (1 << PORTB4);    // Set pin high (LED on)
        wait_ms(WAIT_MS_TIME(200));    // LED on delay
        PORTB &= ~(1 << PORTB4);    // Set pin low (LED off)
        wait_ms(WAIT_MS_TIME(1000));    // LED off delay
    }
}
```
