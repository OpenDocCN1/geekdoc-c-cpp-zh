# ## 3.6.3 Putting an AVR Back into ISP mode

In order to put the target ATtiny back into ISP mode from debugWIRE mode, all of the wires for ISP mode must first be connected between the programmer and the ATtiny device on the breadboard. In other words, the MOSI, MISO and SCK wires from Figure 2.1 in section 2.2 of Chapter 2 must be connected back as per the circuit in that figure.

After connecting all of the ISP/SPI wires between the programmer and the target ATtiny, plug the programmer/debugger into a USB port of the host computer, start Microchip Studio and then power up the circuit. In order to take the ATtiny out of debugWIRE mode, a debugging session must be started using any project that uses physical hardware, for example open the led_blink_asm project in Microchip Studio. Make sure that the correct ATtiny device and programmer/debugger are selected on the toolbar. Now click the Start Debugging and Break toolbar icon, or use the Alt + F5 keyboard shortcut. After the debugging session starts, select Debug ▶ Disable debugWIRE and Close from the top menu. This action takes the ATtiny out of debugWIRE mode and stops the debugging session. Cycle the power to the target ATtiny AVR microcontroller.

# ## 3.7 Summary

+   - An assembly instruction consists of an opcode in mnemonic form, and in some cases includes an operand or operands.
+   - A mnemonic in assembly programming is an abbreviated form of a full opcode name, which can be found in the AVR Instruction Set Manual for AVR microcontrollers.
+   - An opcode or operational code is that part of an assembly instruction that specifies the operation that the microcontroller is to perform.
+   - Operands are the part of an assembly language instruction that an opcode operates on such as registers and data.
+   - An assembly language program is written using mnemonic opcodes, operands and labels. A line of code or statement in an assembly language program can be directly translated to its equivalent machine code instruction.
