Now add the weight of each 4-bit set that appears above a 1. Ignore the weight if it appears above a 0. We therefore have the following.

| 8421 | 8421 | 8421 | 8421 |
| :--- | :--- | :--- | :--- |
| 1100 | 1001 | 1111 | 1010 |
| 8 + 4 | 8 + 1 | 8 + 4 + 2 + 1 | 8 + 2 |
| = 12 | = 9 | = 15 | = 10 |

The sum of each set of weights is shown below each 4-bit binary digit, but in decimal. This decimal number can be looked up in Table 4.4 to find the hexadecimal value. As can be seen in the table, 12 decimal is C hexadecimal, 9 decimal is 9 hexadecimal, 15 decimal is F hexadecimal and 10 decimal is A hexadecimal, giving us the hexadecimal number C9FA again.

To convert the binary number to hexadecimal without using the table, we need to count in hexadecimal. Using the above numbers that were converted to groups of decimal numbers, from the left, the first digit or MSD is 12 decimal. To convert it to hexadecimal we need to count from 0 to 9, then from 10 to 12 in hexadecimal. 10 is A, 11 is B, 12 is C, so the first digit is C. The next digit is 9 decimal which is the same value in hexadecimal, so we have C9 so far. The next digit to the right is 15 in decimal, so we need to count in hexadecimal again. Count 0 to 9, then A (10), B (11), C (12), D (13), E (14), F (15). We now have C9F. The final digit is the LSD and has a decimal value of 10. Again we count 0 to 9 and then A which is 10 decimal. We have now converted the number from binary to hexadecimal and have 0xC9FA.

The trick to getting good at converting numbers between binary and hexadecimal, and hexadecimal to binary without using Table 4.4 is to use the 8, 4, 2, 1 weighting system. It is easy to convert the numbers 0b0000 to 0b1001 (0 to 9) to their hexadecimal equivalents. For example, 0b0111 is 4 + 2 + 1 or 7 when we place 8421 above the binary number. 8 appears above a zero, so is ignored. All the other weights appear above a one, so we add them together. Ob1001 is 8 + 1, or 9. When we get above 9, from 0b1010 to 0b1111, either count the sum of the weights in hexadecimal, or start to recognize the bit patterns and get to know the equivalent hexadecimal digits A to F. When you are experienced enough you will recognize that 0b1010 is A and 0b1011 is B, etc. It is easy to remember that 0b1111 is F because it is the highest number that can be counted in a 4-bit binary number. Remember that you can also use a calculator to convert between different number systems using binary and hexadecimal when starting out.
