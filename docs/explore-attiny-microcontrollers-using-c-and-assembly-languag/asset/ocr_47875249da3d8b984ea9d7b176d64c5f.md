0? Jumping to PC + 2K words is easy enough to understand. If the PC contains the address 0 and an RJMP instruction jumps to address 2048, which is 2K words ahead, there is no problem – the instruction has the following format: RJMP PC+0x8800.

What happens if the PC contains zero and the instruction at address 0 jumps to 2K + 1, or 2049 (0x801)? In this case the instruction ends up as: RJMP PC-0x87FF When this instruction is executed, the PC is loaded with 0x801, or 2049. The reason that the PC is loaded with 0x801 is because -0x07FF ends up as a negative 2’s compliment number. To convert minus 0x07FF to its 2’s compliment representation, first invert all bits making the number 0xF800, which is the 1’s compliment of the number. Add 1 to make it the 2’s complement and we get 0xF801. Because an ATtiny with 4K words of memory has a 12-bit PC, the number gets truncated to 0x801 which is the address that we want to jump to.

Take note that PC - 2K + 1 and PC + 2K words describes the range of memory that RJMP can operate on. The actual operation of RJMP is PC <- PC + k + 1, which means that the instruction jumps to the address that is the sum of the current value in the PC and the constant address k encoded into the instruction plus 1.

The following code demonstrates how to jump from address 0 to 2049, and back to 0 again.

```
.org 0
main:
    rjmp  loop

.org 2049

loop:
    rjmp  main
```

The above code disassembles to the following.

```
rjmp  loop
00000000 RJMP PC-0x87FF             Relative jump
00000001 NOP     Undefined
...
000007FF NOP     Undefined
00000800 NOP     Undefined
rjmp  main
00000801 RJMP PC+0x87FF             Relative jump
```
