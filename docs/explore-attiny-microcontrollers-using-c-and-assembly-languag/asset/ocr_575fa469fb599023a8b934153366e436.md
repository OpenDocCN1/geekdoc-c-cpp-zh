The actual subtraction is performed by one SUBI (Subtract Immediate) instruction and three SBCI (Subtract Immediate with Carry) instructions as shown in the following code.

```
subi R16, 1    ; Perform decrement on 32-bit
sbci R17, 0    ; number in R16 to R19
sbci R18, 0
sbci R19, 0
```

The above code is the counterpart to the addition from section 7.2.2 in Chapter 7, where one ADD (Add without Carry) instruction and one ADC (Add with Carry) instruction are used to add two 16-bit numbers and take into consideration the carry. In the negative version of this code as shown above, the subtraction is simply expanded to operate on four registers. In this code, the SUBI instruction subtracts 1 from R16, the LSB. The SBCI instruction is then used to subtract 0 from R17, R18 and R19. Because this instruction takes into consideration any carry that is generated by the subtraction, R17, R18 and R19 are decremented only when a carry occurs. This effectively allows a 32-bit number spread over four registers to be decremented by one each pass through the loop.

The final part of the code in a loop determines whether the 32-bit number in R16 to R19 is zero. This is done by using a logic OR operation that ORs R16, R17, R18 and R19 together, as shown in the following listing. If any of these registers contains a number other than zero, then the result of the OR operations is not zero, which causes the BRBC instruction to jump back to the top of the loop and do another decrement.

```
mov R20, R16    ; Determine if 32-bit number is
or R20, R17     ; zero using OR and BRBC
or R20, R18
or R20, R19
brbc SREG_Z, wait_is_loop
```

Because the AVR OR instruction is destructive, in that it puts the result of the OR operation into the first register overwriting its contents, an additional register is needed to hold the result of the OR operations. R20 is the register used in the above code to store the result of the OR operations. Firstly, the value in R16 is copied to R20 using the MOV (Copy Register) instruction. After this, R17, R18 and R19 are consecutively ORed with R20, which holds the running result of the OR operations. As R20 is used to store each result, the values in R16 to R19 are never modified or overwritten. After the series of OR operations have completed, the Zero bit in the status register is set only if R16 to R19 all contain zero. This causes program execution to continue below the BRBC instruction. If any of these registers does not contains zero, BRBC jumps to the top of the loop.
