# 4.4.3 Converting Between Bytes and Kilobytes

One kilobyte of memory is 1024 bytes of memory and not 1000 bytes of memory. The reason for this is that the number closest to 1000 is represented by a 10 digit binary number or 2^10 = 1024. To calculate memory size in kilobytes we must therefore divide the memory size in bytes by 1024. For example, 2048 bytes divided by 1024 is 2, or 2 kilobytes, written as 2K bytes, or 2KB. Converting from kilobytes to bytes, we multiply by 1024, so 16K bytes is 16 times 1024 which equals 16384 bytes.

A block of memory that is 16K bytes big and starts at address 0 has its last byte of memory at the address that is one less than the size of the memory. Again, this is because addressing starts at 0 and not at 1. 16K of memory is 16384 bytes long and has its last byte of memory at address 16383 or 0x3FFF.

The reason that the maximum value that a byte can hold is one less than 2^8 or 256 is also because numbering starts at 0 and not 1. 0 to 255 are 256 numbers if we include 0 as a number. 1 to 255 are 255 numbers.

# 4.5 Numbers in Assembly Programs

When entering numbers in an AVR assembly language program, they can be in decimal, binary or hexadecimal format. Some examples follow that are used with the LDI instruction to show the usage of different numbers in an assembly language program. Usage of the LDI instruction is demonstrated in the next chapter. In each of the examples that follow, the number appears at the end of the line of assembly language code. It does not matter whether decimal, hexadecimal or binary is used in the code, the number ultimately ends up as a binary number in the microcontroller, stored as voltage levels. The number 42 decimal.

```
ldi r16, 42
```

The number 0x2A in hexadecimal.

```
ldi r16, 0x2A
```

The same hexadecimal number can be written with lowercase letters.

```
ldi r16, 0x2a
```
