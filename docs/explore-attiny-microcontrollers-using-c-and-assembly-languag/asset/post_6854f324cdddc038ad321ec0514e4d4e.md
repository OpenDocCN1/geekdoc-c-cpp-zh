
### MOVW (Copy Register Word)

MOVW copies one register pair to another register pair. Register pairs are not just the named registers X, Y and Z. All registers from R0 to R31 can be used as pairs. The following code demonstrates the use of register pairs, and the notation used.

```
ldi    r17, 0x12
ldi    r16, 0x34
movw   r1:r0, r17:r16  ; Copy register pair r17:r16 to r1:r0
movw   r3:r2, r17:r16  ; Copy register pair r17:r16 to r3:r2
...
...
movw   r29:r28, r17:r16 ; Copy register pair r17:r16 to r29:r28
movw   r31:r30, r17:r16 ; Copy register pair r17:r16 to r31:r30
```

## 11.2.4.2 Load Immediate Instruction

### LDI (Load Immediate)

LDI is an instruction that has been used many times throughout the book so requires no further explanation. Remember that LDI only operates on registers R16 to R31. The reason why this is so is explained in section 6.8 of Chapter 6 where the encoding of the LDI instruction is shown.

## 11.2.4.3 Load Indirect Instructions

Load indirect (LD) instructions load a value from data space to a register R0 to R31, using either register X, Y or Z as an address pointer into the data space. This means that LD instructions have three different variants because of the three different named register pairs X, Y and Z. Within each of these three variants are three possibilities: 1) the named register pair simply points to the address in data space, 2) the named register pair points to the address in data space and is incremented after the load operation (post-increment), and 3) the address in the named register pair is decremented before executing the load operation (pre-decrement). Each of the three LD instruction variants for each of the three named register pairs X, Y and Z are listed below.

### LD (Load Indirect from Data Space to Register using X)

- LD Rd, X     X points to the address in data space to load from
- LD Rd, X+    X points to data space address and is post-incremented
- LD Rd, -X    X points to data space address and is pre-decremented

### LD (Load Indirect from Data Space to Register using Y)

- LD Rd, Y   Y points to the address in data space to load from
- LD Rd, Y+   Y points to data space address and is post-incremented
- LD Rd, -Y   Y points to data space address and is pre-decremented

The LDD instruction that uses the Y register is included with the above LD instructions in the AVR Instruction Set Manual. LDD is treated separately in this chapter and follows the ST instructions from the next subsection.

### LD (Load Indirect from Data Space to Register using Z)

- LD Rd, Z   Z points to the address in data space to load from
- LD Rd, Z+   Z points to data space address and is post-incremented
- LD Rd, -Z   Z points to data space address and is pre-decremented

The LDD instruction that uses the Z register is included with the above LD instructions in the AVR Instruction Set Manual. LDD is treated separately in this chapter and follows the ST instructions from the next subsection.

## 11.2.4.4 Store Indirect Instructions

Store indirect (ST) instructions are the counterparts to the LD instructions. Whereas LD instructions load or copy data pointed to by a named register pair to register R0 to R31, ST instructions store or copy data from a register to data space using a named register pair as a pointer to the address in data space. These instructions have the same variants as the LD versions and are listed below.

### ST (Store Indirect from Register to Data Space using Index X)

- ST X, Rr   X points to the address in data space to store to
- ST X+, Rr   X points to data space address and is post-incremented
- ST -X, Rr   X points to data space address and is pre-decremented

### ST (Store Indirect from Register to Data Space using Index Y)

- ST Y, Rr   Y points to the address in data space to store to
- ST Y+, Rr   Y points to data space address and is post-incremented
- ST -Y, Rr   Y points to data space address and is pre-decremented

The STD instruction that uses the Y register is included with the above ST instructions in the AVR Instruction Set Manual. STD is treated separately in this chapter and follows the LDD instructions from the next subsection.

### ST (Store Indirect from Register to Data Space using Index Z)

- ST Z, Rr    Z points to the address in data space to store to
- ST Z+, Rr   Z points to data space address and is post-incremented
- ST -Z, Rr   Z points to data space address and is pre-decremented

The STD instruction that uses the Z register is included with the above ST instructions in the AVR Instruction Set Manual. STD is treated separately in this chapter and follows the LDD instructions from the next subsection.

## 11.2.4.5 Load Indirect with Displacement

The two variants of the LDD instruction load data from data space to a register R0 to R31 by using the address in either the Y register or the Z register plus a displacement value that can be between 0 and 63. The two variants are listed below, where q is the displacement value that gets added to the address in either the Y or Z register.

- LDD
- LDD Rd,Y+q
- LDD Rd,Z+q

## 11.2.4.6 Store Indirect with Displacement

STD instructions are the counterparts to the LDD instructions that store data to a location in data space from a register R0 to R31. The register value is stored to the address that either the Y or Z register is pointing to plus the q displacement value. As with the LDD instruction, q can be in the range 0 to 63.

- STD
- STD Y+q, Rr
- STD Z+q, Rr

## 11.2.4.7 Load Direct from SRAM

### LDS (Load Direct from Data Space)

LDS has the form LDS Rd,k and loads the contents of data space at address k to the destination register Rd. k can be between 0 and 65535, while Rd can be R0 to R31. LDS is demonstrated in section 5.4.1 of Chapter 5.

## 11.2.4.8 Store Direct to SRAM

### STS (Store Direct to Data Space)

STS has the form STS k, Rr and stores a value from a register to data space address k. k can be between 0 and 65535, while Rr can be R0 to R31. STS is demonstrated in section 5.4.1 in Chapter 5 along with LDS.

## 11.2.5 MCU Control Instructions

### NOP (No Operation)

NOP does nothing except use up one clock cycle. NOP is explained and demonstrated in section 10.1.2.1 of Chapter 10.

### SLEEP (Sleep)

AVR microcontrollers can be put into one of several sleep modes in order to save power. Sleep modes are selected in the MCUCR register and then initiated by running the SLEEP instruction. See the Power Management and Sleep Modes section of the datasheet for the AVR being used for more information on the sleep modes.

### WDR (Watchdog Reset)

If the watchdog timer is enabled on an AVR microcontroller, then it must be periodically reset. WDR must be run before the watchdog timer times out in order to prevent it from resetting the microcontroller. The idea of using the watchdog timer is to start it and then periodically reset it so that it does not reset the microcontroller. If the software running on the microcontroller should hang or lock up the microcontroller, then it can no longer reset the watchdog timer. This causes the watchdog timer to time out and reset the microcontroller, bringing it out of its hung up or locked up state. For more information on the watchdog timer, refer to the System Control and Reset section of the datasheet for the AVR being used.

### BREAK (Breakpoint)

When a breakpoint is inserted into a program using Microchip Studio and a debugger, such as the Atmel-ICE, the instruction that the breakpoint is placed on is replaced by the BREAK instruction. The instruction replaced by the breakpoint is stored. BREAK is used by the debugging system only and is not intended for use by the application software.
