```
start:    sbi    DDRB, DDB4

loop:     sbi    PORTB, PORTB4
          rcall  delay
          cbi    PORTB, PORTB4
          rcall  delay
          rjmp   loop

; Delay subroutine
delay:
• ldi     r16, 3      ; Insert first breakpoint, reset cycle counter
delloop1:
• ldi     r17, 3
delloop2:
          dec     r17
          brbc    SREG_Z, delloop2
          dec     r16
          brbc    SREG_Z, delloop1
• ret                 ; Insert second breakpoint
```

To test the formula, different values are loaded to R16 and R17 in the code in the paragraphs that follow by changing the values at the LDI instructions, as indicated above where the values are both 3. After each change, the project must be built and then the code run in the simulator. The code must be run using the F5 key, or the Start Debugging toolbar button, so that execution stops at the first breakpoint.

At the first breakpoint, reset the Cycle Counter to 1 instead of 0 because of the bug in the simulator. After resetting the cycle counter, run the code again using F5 or the Start Debugging toolbar button, so that execution stops at the second breakpoint on the RET instruction. The cycle counter now contains the total number of clock cycles used by the delay subroutine, excluding the clock cycles used by the RET instruction. This should match the value calculated using the formula with the same values for R16 and R17.
