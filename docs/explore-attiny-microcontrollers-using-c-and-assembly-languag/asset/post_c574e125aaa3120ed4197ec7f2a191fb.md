
C programmers can now debug optimized C programs by looking at and understanding the disassembly of the code when debugging in Microchip Studio. Lines of code that previously mysteriously disappeared when C compiler optimization was enabled can now be understood by looking at the generated assembly code in the list file, and disassembly code during debugging. Readers also have the skills to evaluate different C tools for AVR microcontrollers by looking at the assembly language code that they generate.

Those readers who end up studying microcontroller architecture in schools or universities will already benefit from reading this book, even if a different microcontroller architecture is studied. By studying one microcontroller architecture, many fundamentals are learned that apply to other microcontrollers as well. It takes much less effort learning a second or third architecture after one has been learned.

Anyone interested in the more specialized field of developing programming tools or simulators for AVR microcontrollers have to understand the architecture of the AVR, and have all of the understanding needed, such as instruction operation and encoding covered in this book, to start to develop software tools for AVR microcontrollers.

The final reason for learning assembly language was for understanding application notes and other documentation for AVR microcontrollers that contain assembly language. A number of Microchip/Atmel application notes, as well as datasheets for AVRs have assembly language examples. Take a look at these documents and you will be amazed at how much you now understand. It should now be easy to understand the assembly language code used in these documents and also any AVR assembly language code found on the internet. Any instruction found in code that you can't remember can easily be looked up in the AVR instruction set manual.

In addition to all of the advantages of learning assembly language for AVR microcontrollers you now have a better understanding of Microchip Studio. Using the Disassembly window when debugging is one example of a feature of Microchip Studio that makes no sense to anyone who has not studied the AVR architecture and instruction set.

Finally, C programmers can further study assembly language by writing C programs and looking at the assembly language code that they generate. If you are curious about how certain C code works, or what assembly language it converts to, look at it in the disassembly window when debugging, or in the list file generated when the project is built.

## 12.3.2 What was Not Covered

This book concentrated on the AVR architecture mainly from a programmer's perspective. One aspect of the architecture that was not covered was the implementation of the AVR in hardware. This information is actually proprietary to Microchip. Although they give a programmer's view of the architecture, they do not give away how the AVR core is implemented in hardware. Even if they did, studying the actual hardware implementation would take another whole book.

This book did not cover all of the on-chip peripherals and features of the ATtiny microcontrollers used. It was considered sufficient to cover how some of the peripherals are accessed using assembly instructions. A detailed study of AVR on-chip peripherals and other features is the subject for another book.

## 12.3.3 Other AVR Microcontrollers

Although we studied ATtiny AVR microcontrollers in this book, the core of other AVR microcontrollers is the same. It is easy to transition onto other ATtiny parts, as well as parts from the ATmega range, now that the fundamentals of the AVR architecture have been covered. As we saw, other AVR devices may implement additional, or fewer instructions. On devices with more on-chip peripherals with control registers that fall outside the address range of instructions such as IN and OUT, alternate instructions must be used. You now have the skills to study these other microcontrollers on your own. Refer to the datasheets of other AVR microcontrollers and use the debugger and simulator to analyze any additional features, such as memory and on-chip peripherals.

### A.1.1 Differences Between Hobby Programmers and the Atmel-ICE

An Atmel-ICE is the official USB programmer/debugger from Microchip for 8-bit AVR microcontrollers. It also supports 32-bit ARM microcontrollers from the Microchip Cortex-M SAM range, that were originally from Atmel, as well as 32-bit AVR microcontrollers. The Atmel-ICE can not only be used to program in-circuit programmable ATtiny AVR microcontrollers, but can also be used for debugging these devices (and other supported microcontrollers from the Cortex-M, AVR 32-bit, XMEGA and megaAVR ranges).

Hobby programmers are all "program only" devices, that do not support debugging, and mostly only support 8-bit AVR microcontrollers through the ISP/SPI interface. The main differences between the Atmel-ICE and hobby programmers are:
- the Atmel-ICE supports many more programming interfaces than hobby programmers (discussed in the next section)
- the Atmel-ICE supports debugging
- the Atmel-ICE does not supply voltage to a circuit, whereas hobby programmers usually do or can.

To elaborate on hobby programmers supplying power to a circuit – most hobby programmers supply power through the ISP header. This is usually 5V, but in some cases 3.3V can be selected by changing a jumper on the programmer. The ISP interface on an Atmel-ICE has a VTG pin which is used to sense what voltage the circuit is powered from, instead of supplying voltage to the circuit from this pin.
