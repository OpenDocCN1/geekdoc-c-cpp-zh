# 5.1 AVR Registers

Registers in 8-bit AVR microcontrollers are 8-bit wide storage locations used for the temporary storage of data, or used to control peripheral devices in the case of control registers.

# 5.1.1 General Purpose Working Registers

Registers can be used to store data that is used in mathematical or logical operations, and to store the results of these operations. 8-bit AVR microcontrollers have 32 8-bit wide general purpose working registers grouped together in a general purpose register file as shown in Figure 5.1. An exception to this is the ATtiny4/5/9/10 range that have only 16 general purpose registers – R16 to R31.

# 5.1.2 I/O Registers

In addition to the general purpose working registers, ATtiny AVR microcontrollers have a set of 64 8-bit wide I/O registers which can be found in the datasheet under the Register Summary section. This set of registers includes control registers for controlling the on-chip peripherals such as timers, ADC, SPI, etc. as well as registers such as the status register and stack pointer which are discussed in the next chapter. Some of the bigger ATtiny devices and ATmega devices have an extended I/O register file, but in the interests of keeping things simple at the start, we will not look at this yet.

# 5.2 Using General Purpose Registers

Some program examples will help to show how the general purpose registers are used. Start a new AVR Assembler Project in Microchip Studio called test_asm which will be used to run various short code snippets.

Select the ATtiny45 as the device when creating the project. We will be using the simulator, so it is fine to choose this part even if you do not have a physical chip available. The reason for choosing this part is that the debugger/simulator has some bugs when using the ATtiny13 or ATtiny25. Refer back to section 2.3.1 of Chapter 2 if you need a reminder on how to start a new AVR Assembler Project. Delete the skeleton code from the main.asm file in the new test_asm project. This project and file will be used and reused to test short programs and code snippets, avoiding the necessity to have to create a new project for each and every small program.
