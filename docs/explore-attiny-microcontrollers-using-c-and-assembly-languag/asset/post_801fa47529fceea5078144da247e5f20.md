
The POP instruction restores the original value of 0x55 to R16 by popping it from the stack. After stepping over the POP instruction R16 contains 0x55 and the stack pointer contains the address 0x015D. Step over the RET instruction which returns from the subroutine and automatically pops the return address 0x0002 from the stack and loads it to the program counter so that program execution continues after the subroutine call at the RJMP instruction. The stack pointer is incremented and back at 0x015F because the stack is now empty, as both the register value and return address were popped off of it. Once again, the values pushed to the stack have not been removed from the SRAM, and can be seen in the Memory window. The stack is considered empty because the stack pointer is pointing to the top of the stack. This means that when the stack is used again, these old values will be overwritten.

Unless the default stack pointer value of RAMEND is to be used, all user programs must initialize the SP before subroutines or interrupts are executed. This is usually done at the very beginning of a program in the initialization part of the code. Also bear this in mind when using other microcontrollers that may not necessarily initialize the stack to the desired value by default.

## 6.7 LED Blink Program Fully Explained

The LED blink program from Chapter 2 has only partly been explained so far. The LED blink code follows for your convenience so that you don't have to turn back to Chapter 2, and is accompanied by an explanation. For a refresher, look at Figure 3.1 from Chapter 3 – the flowchart that explains the main functionality of the LED blink program.

At the start of the program, the SBI instruction is used to set bit DDB4 in the DDRB register which configures pin PB4 as an output. Once pin PB4 is set up as an output using the DDRB register, it can be controlled by code to switch its state to high and low using the PORTB register. In the circuit the LED is connected to pin PB4 via a series resistor, allowing the LED to be switched on and off. Typically a program will have an initialization section that sets up the desired state of the AVR before code starts executing in a main loop. Stack initialization and setting up I/O pins of the microcontroller are initialization tasks that fall into the initialization part of the LED blink program. Of course stack initialization is not needed as the ATtiny microcontrollers that we are using initialize the stack pointer to the end of SRAM. If other hardware devices such as the on-chip timer are used in a program, they would also be initialized here.

```
led_blink.asm : main.asm

start:
    sbi    DDRB, DDB4    ; Set pin PB4 as output

loop:
    sbi    PORTB, PORTB4    ; Set LED pin high
    rcall  delay        ; Leave LED on for a while
    cbi    PORTB, PORTB4    ; Clear LED pin low
    rcall  delay        ; Leave LED off for a while
    rjmp   loop

; Delay subroutine
delay:
    ldi    r16, 0xff
delloop1:
    ldi    r17, 0xff
delloop2:
    dec    r17        ; Delay by decrementing
    brbc   SRGE_Z, delloop2
    dec    r16        ; Delay by decrementing
    brbc   SRGE_Z, delloop1
    ret
```

In the main loop, which starts at the loop: label, the SBI and CBI instructions are used to set a bit to switch the LED on, and clear a bit to switch the LED off. These instructions are used to set and clear a bit in the PORTB register that corresponds to the pin that the LED is connected to. In the code, this bit is called PORTB4 and corresponds to pin PB4. The actual registers used to set up and control an LED are shown in Chapter 8. The function of the main loop is easiest to see in the flowchart of Figure 3.1 from Chapter 3 and should be easy to understand at this stage.

Only the delay subroutine requires further explanation, and at this stage we have covered all of the instructions that are used in it. Figure 6.11 shows a flowchart of the delay subroutine. To avoid confusion, it is worth mentioning that the first block in the flowchart called start does not represent the start label of the code, but rather the start of the delay subroutine. This corresponds to the delay: label.

The delay subroutine works by decrementing register R17 containing 0xFF (255) to zero, 0xFF (255) number of times, controlled by R16. Decrementing these registers uses up microcontroller clock cycles, and therefore time, which causes the time delay. This time delay has not been carefully calculated, but was found to be adequate for this program because it allows the LED state to be seen with the eye. At the start of the subroutine, R16 is loaded with 0xFF and decremented only at the end of the outer loop, as can be seen in the flowchart of Figure 6.11, where it is then checked to see if it is zero. R16 never gets reloaded with a new value, it is only ever decremented after the initial value gets loaded to it. The outer loop consists of all of the code between the delloop1: label and the last BRBC instruction that is found just before the RET instruction.

![](img/83ef13a6c66cc7882b2f357e97f451dc_122_0.png)

### Figure 6.11: Delay Subroutine Flowchart

R17 is loaded with 0xFF and then decremented until it is zero in the inner loop. After R17 contains zero, R16 is decremented and tested to see if it contains zero. If R16 does not contain zero, R17 is reloaded with 0xFF and decremented in the inner loop to zero again. The cycle continues until R16 contains zero. When R16 does contain zero, the subroutine returns. Thus we have an inner loop decrementing R17 255 times for every one decrement of R16 causing a time delay in the microcontroller.
