```
#include <avr/io.h>

#ifndef TIFR
#define TIFR TIFR0
#endif

int main(void)
{
  DDRB = (1 << DDB4);       // Pin PB4 as output pin
  TCCR0A = (1 << WGM01);    // CTC mode
  OCR0A = 0xFF;             // Output compare value
  TCCR0B = ((1 << CS02) | (1 << CS00)); // Prescaler CLK/1024 and start timer

  while(1) {
    if (TIFR & (1 << OCF0A)) { // Check for timer compare match
      PINB = (1 << PORTB4);   // Toggle pin PB4
      TIFR = (1 << OCF0A);    // Clear OCF0A flag
    }
  }
}
```

Although the above code works in the same way as the assembly language code did in the previous section, the value written for OCR0A is a bigger value. This is done so that the LED will blink at a slower rate for the assembly language program. In this way, when the code is loaded to hardware that is already running the assembly language version of the code, it can be seen that the new program did indeed load because the LED is blinking more slowly.

# 10.5 Timer Interrupt Delay

The interrupt system of a microcontroller is implemented in the hardware of the microcontroller by the designer and manufacturer of the microcontroller. Interrupts are configured and enabled using software by the end user programmer.

An interrupt system allows an event, such as a timer timeout, to interrupt the current flow of a program. When an interrupt is triggered, program flow automatically jumps to a special subroutine called an Interrupt Service Routine, or ISR. The code in the ISR can be anything that the programmer wants. To use the timer example that follows, the main program sets up the timer and an interrupt, and then enters an infinite loop that does nothing. When the timer times out, it interrupts the infinite loop and calls the ISR. In this project, the ISR toggles the LED. It then returns and the main loop continues running.
