### 3.7 Summary

- An assembly instruction consists of an opcode in mnemonic form, and in some cases includes an operand or operands.
- A mnemonic in assembly programming is an abbreviated form of a full opcode name, which can be found in the AVR Instruction Set Manual for AVR microcontrollers.
- An opcode or operational code is that part of an assembly instruction that specifies the operation that the microcontroller is to perform.
- Operands are the part of an assembly language instruction that an opcode operates on such as registers and data.
- An assembly language program is written using mnemonic opcodes, operands and labels. A line of code or statement in an assembly language program can be directly translated to its equivalent machine code instruction.
- An instruction set for a particular microcontroller architecture is the set of all of the instructions that the architecture can execute and that a program can consist of.
- An assembler program converts assembly instructions written in text using mnemonics, to their binary machine language form.
- Comments are used to add notes to an assembly language program and start with a semicolon. C and C++ style comments can also be used in AVR assembler programs.
- A loop in programming is used to repeatedly run certain parts of code.
- The AVR simulator is useful to quickly see how certain assembly language instructions work and is a great tool when learning assembly language.

This chapter has been a brief introduction to assembly language and the tools used to write, build, simulate and debug AVR assembly language programs. ### 4.1 Bits and Bytes

Because a microcontroller is an electrical machine, it stores numbers as voltage levels. Two voltage levels are used – a high voltage level and a low voltage level. The actual voltage used depends on the voltage that the microcontroller is powered from. If an AVR microcontroller is powered from 5V, then 5V is the high voltage and 0V is the low voltage. If the AVR microcontroller is powered from 3.3V, then 3.3V is the high voltage and 0V the low voltage. A high voltage represents the number 1 and a low voltage represents the number 0. A single binary digit can therefore have a value of either 1 or 0. The word “bit” is an abbreviation of “binary digit”.

A binary value of zero can be referred to as zero, logic zero, low or logic low, and can also be referred to as false. A binary value of one can be referred to as one, logic one, high, logic high and also as true.

In a microcontroller a single binary digit, or bit, is stored in a memory cell which is the smallest building block that memory is made up of. Figure 4.1 shows single cells of memory storage and how a bit with a value of 0 or 1 in a single memory cell is represented by voltage.

| | A single cell in memory can have a value of 0 or 1 | |
|---|---|---|
| 0 | A single cell containing a logic zero level is stored as 0 volts | 0V |
| 1 | A single cell containing a logic one level is stored as 5 volts | 5V |

#### 4.1.1 Counting in Binary

With a single binary digit it is possible to count from 0 up to 1 in the same way that a single decimal digit can be used to count from 0 to 9. When we want to count higher than 9 in decimal, we use another digit and can count from 00 to 99. In the same way using a second binary digit, we can count higher – from 00 to 11 (zero zero to one one), where 11 binary has a decimal value of 3. In this book binary numbers start with 0b (zero bee) to indicate that they are binary numbers and not decimal. The decimal value 3 is therefore written 0b11 in binary, unless the context that the number is used in leaves no doubt that it is a binary number.

Counting in binary works the same way as decimal, except that only two values are available per digit instead of the ten values of decimal. In decimal we would count from 0 to 9 and then increment the next significant digit (the digit to the left) by one, then start counting from 0 to 9 again. In binary the same thing happens — we start at 0 and count to 1, now we have run out of digits, so we increment the next significant digit and have the number 0b10. The first digit is then incremented again, so we have 0b11. Now we have run out of digits again so need to add another digit and increment the number to 0b100. Table 4.1 shows how to count from 0 to 15 or 0b0000 to 0b1111 in binary.

| Decimal | Binary |
| :--- | :--- |
| 0 | 0000 |
| 1 | 0001 |
| 2 | 0010 |
| 3 | 0011 |
| 4 | 0100 |
| 5 | 0101 |
| 6 | 0110 |
| 7 | 0111 |
| 8 | 1000 |
| 9 | 1001 |
| 10 | 1010 |
| 11 | 1011 |
| 12 | 1100 |
| 13 | 1101 |
| 14 | 1110 |
