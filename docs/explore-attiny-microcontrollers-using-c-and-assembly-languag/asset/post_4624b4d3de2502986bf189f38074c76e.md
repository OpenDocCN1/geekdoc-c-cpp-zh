### A.1.2 Programming Interfaces

Most of the hobby programmers support the ISP/SPI programming interface, but usually not many of the other interfaces found on newer AVRs. ISP/SPI programming covers all of the ATtiny microcontrollers shown in Table 1.1 of section 1.3 in Chapter 1. Supported interfaces depend on the firmware in these programmers as well as the programming software that runs on the host computer. Firmware and programming software updates may be available, or become available in the future, that allow programming through other interfaces. This appendix covers three hobby programmers that are widely available. There may be different programmers available that do support other AVR programming interfaces. At the time of writing there were none that were widely available.

USBasp programmers can have their firmware updated to support the TPI interface for programming ATtiny4/5/9/10 microcontrollers, but this update stops the ISP/SPI interface from working on the USBasp shown in Figure A.1. The USBasp must then be programmed with an older version of firmware to get ISP/SPI programming working again. A second programmer is needed to load different versions of firmware to a USBasp. At the time of writing there were no widely available hobby programmers that support the TPI interface, and the UPDI interface found on more modern AVR microcontrollers. This is not a problem when using this book as none of these other interfaces are used.

### A.1.3 Using Hobby USB Programmers with this Book

This book has been designed to use ATtiny microcontrollers that have the ISP/SPI interface and are available in DIP packages. In this way, readers can build all of the circuits in this book and use a cheap hobby programmer to load the software. Readers who want to experiment with the ATtiny4/5/9/10 range that use the TPI interface will probably need to get an additional hobby programmer that supports TPI, or use an Atmel-ICE. ATtiny4/5/9/10 microcontrollers are surface mount devices that need to be soldered to breakout boards in order to be used in breadboard circuits. Modern ATtiny microcontrollers that use the UPDI interface are also all surface mount devices and are not covered in this book, so a UPDI programmer is not needed.

## A.2 Overview of External Programmer Setup

The following list contains all the basic steps needed to set up an external USB hobby programmer in Microchip Studio. Setup details for each step can be found in the section that follows.

- 1) Install a driver for the programmer.
- 2) Download the programming software (a program called avrdude).
- 3) Build an AVR circuit and attach the programmer for testing purposes.
- 4) Work out the arguments that must be passed to avrdude for the particular programmer and AVR microcontroller.
- 5) Open Microchip Studio and set up the external tool and a button for it.
- 6) Test the setup by programming the target AVR microcontroller.
- 7) Fix any programming problems.

## A.3 External Programmer Setup

Steps in the subsections that follow cover all of the steps from the list in the previous section for setting up a USB hobby programmer in Microchip Studio.

### A.3.1 Install a Driver

A driver must be installed for each programmer for it to work on a Windows computer. An Arduino Uno does not need to have a driver installed, but does need the ArduinoISP sketch to be loaded to it to turn it into an ISP programmer. Follow the driver installation procedure under the correct heading that follows for the programmer that you are using – either the USBasp, USBtinyISP, or Arduino Uno.

#### A.3.1.1 USBasp Driver

Links to firmware, drivers, and other information on the USBasp can be found on the web page of the designer of this device, Thomas Fischl, at www.fischl.de/usbasp/

A driver installation tool called Zadig is used to install a driver for the USBasp on a Windows computer. Go to zadig.akeo.ie and download the Zadig executable file by clicking the link under the Download heading on the web page. At the time of writing, the newest version of Zadig was version 2.5, and the file name was zadig-2.5.exe

Plug the USBasp into a spare USB port on the Windows computer. Windows will try to install a driver for the USBasp, but fail, even though it reports that the device is ready. To verify that Windows has found the USBasp, but automatic driver installation failed, right-click the Windows Start button, and then select Device Manager on the menu that pops up. USBasp should be visible under Other devices in the Device Manager window. It will have a triangle icon on it, indicating that a driver was not installed, as shown in Figure A.2.

Windows will pop up a dialog box asking Do you want to allow this app to make changes to your device? Click Yes in this dialog box. In the Zadig update policy dialog box, you can optionally click No to stop Zadig from checking for application updates online, as this is not necessary if the newest version of the software was downloaded. Click the Install Driver button to install the selected driver. Zadig now pops up a dialog box to show that the driver is busy installing. After the driver has finished installing, a dialog box pops up to show that the driver was installed successfully. Click the Close button in this dialog box. Close the Zadig application window.

It was found that after installing the driver, the USBasp appears under Atmel USB Devices or under Microchip Tools in the Device Manager dialog box on computers that already had Microchip Studio installed. On computers that did not have Microchip Studio installed, the USBasp appeared under libusb-win32 devices in the Device Manager dialog box. Note that the USBasp must be plugged into a USB port for it to be seen in the Device Manager dialog box. As soon as it is unplugged, it will disappear from Device Manager. Unplug the USBasp from the USB port before connecting it to a circuit.

At this stage, if the USBasp can be found in Device Manager without any warning icons, the driver is successfully installed, and the USBasp is ready to use. Go to section A.3.2 to download and install the avrdude programming software.

#### A.3.1.2 USBtinyISP Driver

The USBtinyISP is based on the USBtiny software implementation of the USB low-speed protocol. The USBtinyISP was developed by Adafruit where the documentation and more information on the programmer can be found at learn.adafruit.com/usbtinyisp Adafruit provide all the information for anyone to build their own USBtinyISP programmer, and also supply a kit of parts to make building the programmer easier. There are variations of the USBtinyISP available, like the one shown at the left of Figure A.1 at the beginning of this chapter.

A link to the Adafruit driver for the USBtinyISP can be found on the USBtinyISP drivers page at learn.adafruit.com/usbtinyisp/drivers Clicking the Download Adafruit Driver Installer button on this page opens up a page on GitHub. A link to the executable driver installer can be found on the GitHub page. At the time of writing the installer was version 2.5.0.0 and the executable file was named adafruit_drivers_2.5.0.0.exe Click the link to download this file.
