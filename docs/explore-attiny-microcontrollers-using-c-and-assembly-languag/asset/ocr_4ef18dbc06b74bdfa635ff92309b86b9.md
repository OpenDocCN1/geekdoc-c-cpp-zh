value of this number is therefore calculated as 2^31 – 1 which is 2,147,483,647 or 0x7FFFFFFF. In the code, the warning message is not triggered because this positive value is bigger than the value of NUM2, which is 1. If a value of 0x80000000 is used for NUM1, by commenting out the first line of code and uncommenting the second line of code, then the warning message is triggered. Adding 1 to 0x7FFFFFFF gives us a value of 0x80000000. This 32-bit number has its most significant bit set, so is a negative number if it is treated as a 32-bit 2’s compliment signed number. It has a decimal value of –2,147,483,648, and is therefore a negative number with a value less than 1, which is the value of NUM2 in the code. This is the reason why the warning message is triggered with this value.

# Solution to Flagging Out of Range Upper Values

Now that we understand the integer size limitations of the assembler program, we can devise a solution for flagging out of range values used with the time delay subroutine. One way to do this is to test the value of MS_TIME_DEL to make sure that it is less than the maximum value of 2,147,483 that we calculated. This value is much less than the maximum positive value that a 32-bit signed integer can hold, so it will never be treated as a negative number. Even values much bigger than 2,147,483 will not be treated as negative numbers, so if the user tries to use a MS_TIME_DEL of even 1000 times this value, it can be tested with no side effects. The only problem with this solution is the maximum value of MS_TIME_DEL was calculated using a 20MHz F_CPU. This means that if used with say a 1MHz F_CPU, the value of MS_TIME_DEL will also be limited to 2,147,483, whereas in reality MS_TIME_DEL would be able to be much higher when using a 1MHz F_CPU.

Another solution is to take advantage of the fact that the assembler program does not treat values that are not assigned a name using .equ or #define as 32-bit signed integers. The following code, from the top of the wait_ms.asm file, shows that directly placing the calculation into the comparison, circumvents the result of the calculation becoming a 32- bit signed integer. The value that is 2^32 – 1, or 0xFFFFFFFF is also used directly in the comparison.

```
; Millisecond delay subroutine - time set by MS_TIME_DEL
.if ((((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10) > 0xFFFFFFFF)
.error "F_CPU MS_TIME_DEL combination out of range in wait_ms subroutine."
.endif
.equ WAIT_MS_CYCLES = (((F_CPU * MS_TIME_DEL / 1000) - 10) / 10)
```
