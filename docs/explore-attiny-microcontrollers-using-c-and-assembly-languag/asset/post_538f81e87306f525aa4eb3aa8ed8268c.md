Each memory location of program memory is 16-bits wide and cannot be accessed as two 8-bit bytes, each at their own address, as there is no need for byte access of program instructions (an exception to this is that data can be stored in program memory and accessed as bytes, but program instructions are never accessed as bytes). The implications of this is that the first memory location is found at address 0x0000 and contains a 16-bit wide instruction. The second memory location is at 0x0001 and contains a 16-bit wide instruction. This is different from what would normally be expected on byte addressable systems that would address each 8-bit wide byte and thus have the first instruction at addresses 0x0000 and 0x0001, and the second instruction at 0x0002 and 0x0003 if the instructions were 16 bits wide.

With this in mind, refer to the program memory block at the left of Figure 5.3, and let us look at the ATtiny25 as an example. Program memory of the ATtiny25 starts at address 0x0000 and ends at 0x03FF. To calculate the size of the memory that this address range covers, we take the end address 0x03FF and add one (because addresses start at 0) to get 0x0400 and then convert it to decimal which is 1024 or 1K of memory. This can look confusing because now we know from the datasheet that the ATtiny25 has 2K of Flash memory. The reason is that this is 1K × 16-bit wide memory or 1K × 2 bytes which is 2K bytes of memory.

Program memory in the memory map shows that the ATtiny13(A) has memory from 0 to 0x01FF and the ATtiny25 has memory from address 0 to 0x03FF. The ATtiny45 has the same memory as the ATtiny25 and some additional memory from address 0 to 0x07FF. The ATtiny85 has the same memory that the ATtiny25 and ATtiny45 have as well as additional memory. This makes the program memory address range of the ATtiny85 from 0 to 0x0FFF.

### 5.3.2 Data Memory

Data memory on ATtiny13(A) and ATtiny25/45/85 microcontrollers consists of SRAM (Static Random Access Memory). SRAM memory is known as volatile memory as it loses the data stored in it when power to the microcontroller is switched off. Data memory starts at address 0x60 and not 0 because the general purpose working registers and I/O registers are mapped at the beginning of the data space. Having registers mapped into data memory space allows them to be accessed as data memory by instructions, which can be convenient.

Data memory space starts at address 0, the same as program memory space. This is possible because of the architecture of the microcontroller and is explained in the next chapter.

It can be seen from the memory map of Figure 5.3, in the data memory block at the right of the figure, that ATtiny13(A) data memory is 64 bytes in size from address 0x60 to 0x9F, and ATtiny25 data memory is 128 bytes in size from address 0x60 to 0xDF. Data memory of the ATtiny45 is 256 bytes in size from address 0x60 to 0x15F. Data memory of the ATtiny85 is 512 bytes in size from address 0x60 to 0x25F.

The data memory is one byte, or 8-bits, wide and each byte has a unique address. The 14-pin and 20-pin ATtiny AVRs from Table 1.1 in section 1.3 of Chapter 1 follow these SRAM addresses, where devices with 2K of Flash correspond to the ATtiny25, devices with 4K correspond to the ATtiny45 and devices with 8K correspond to the ATtiny85 memories. The memory map of ATtiny48/88 devices differ because they have an extended I/O register file pushing the SRAM start address to 0x0100, and 64 bytes of EEPROM.

### 5.3.3 EEPROM

EEPROM (Electrically Erasable Programmable Read Only Memory) can be used for storing any data values that must be available when the microcontroller is powered on. Unlike SRAM which loses its contents when the microcontroller is powered off, data stored in EEPROM will not be lost. EEPROM is called non-volatile memory because, like Flash program memory, it does not lose its contents when powered off. EEPROM memory is 8-bits wide and byte addressable.

EEPROM memory is programmed by using specific registers found in the I/O register space. As with Flash memory and SRAM, EEPROM starts at address 0 because it has its own address space. EEPROM size for the ATtiny13(A), ATtiny25, ATtiny45 and ATtiny85 can be seen at the bottom right of Figure 5.3.

## 5.4 Accessing SRAM in Assembler Programs

An example program that stores a value in SRAM and loads a value from SRAM introduces two new assembler instructions, namely STS (Store Direct to Data Space) and LDS (Load Direct from Data Space). The AVR simulator will be used again to see the result of running the program.

### 5.4.1 SRAM Store and Load Example

Use the same test_asm project that we created earlier in this chapter, and replace the code with the following program. Remember to leave the infinite loop at the bottom of the new code, which is not shown in the code listing that follows.

```
test.asm : main.asm - SRAM direct store and load
ldi r16, 0xAA ; Data to store to SRAM
sts 0x60, r16 ; Store data from register to SRAM
lds r1, 0x60 ; Load data from SRAM to register
```

If a byte of data is to be stored in SRAM, it must first be loaded to a register. Whenever data is to be manipulated in the microcontroller it must first be loaded to a general purpose working register in order for the internal core of the microcontroller to have access to it. In the above program the LDI instruction is used to load a value of 0xAA to register R16. This value is the value to be stored in SRAM. The STS instruction is then used to store the value in the first SRAM location at address 0x60. As can be seen in the code listing, the STS instruction uses the format STS <destination address>, <source register> to move the data from a source register (R16 in this example) to the destination address 0x60. The address used in this instruction is 16 bits wide and could be written 0x0060, but 0x60 is accepted by the assembler program and implies that the higher byte (or most significant byte) of the address is 0x00. Because the address is 16 bits wide it is able to be used on AVR microcontrollers that have memory up to address 0xFFFF. On the ATtiny13(A), ATtiny25, ATtiny45 and ATtiny85 memory is not available beyond address 0x009F, 0x00DF, 0x015F and 0x025F respectively, so it is up to the programmer not to try to access memory that does not exist.

LDS is the equivalent of STS, but rather than copying a value to SRAM from a register, it copies a value from SRAM to a register. In our example program, LDS is used to get the value 0xAA that was previously stored in SRAM at address 0x60 and put it into register R1. The LDS instruction has the format LDS <destination register>, <source address> where the source address is a 16-bit wide address.

Both the STS and LDS instructions can be used to store and load data to and from the register file and I/O registers because these registers are mapped to the data memory space as can be seen in the memory map. STS and LDS are both 2 × 16-bit words long or 4 byte long instructions, which adds up to 32-bits long.
