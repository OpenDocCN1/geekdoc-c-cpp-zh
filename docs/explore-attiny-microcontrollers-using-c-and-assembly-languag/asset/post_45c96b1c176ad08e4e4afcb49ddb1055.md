
### 3.6.1 Using the AVR Simulator and Debugger

Using the debugger in Microchip Studio with the simulator does not require any physical hardware, or any programmer/debugger such as the Atmel-ICE. Start by opening the led_blink_asm project from Chapter 2 in Microchip Studio. Build the project if you have not already done so. To use the simulator, the simulator option must be selected as the tool that is used with the project – select the simulator instead of the Atmel-ICE or other programming tool. Click the hammer icon labeled None on the second horizontal toolbar, or click the name of the currently selected tool in the same place if you previously selected a programming tool. Alternatively select Project ▶ led_blink_asm Properties... from the top menu or the Alt + F7 keyboard shortcut, then click Tool in the left column. From the drop-down box under the heading Selected debugger/programmer, select Simulator and then save the changes. Tool settings are shown in Figure 3.2.

![](img/83ef13a6c66cc7882b2f357e97f451dc_61_0.png)

Figure 3.2: Selecting the Simulator in Microchip Studio

Start the simulator by clicking the Start Debugging and Break icon on the second top toolbar at the left as indicated in Figure 3.2, alternatively use the keyboard shortcut Alt + F5, or Debug ▶ Start Debugging and Break from the top menu.

When the simulator starts, it highlights the first assembly language instruction in yellow because “Start Debugging and Break” was selected. This means that the debugger was started, the program loaded, but execution of the program was stopped at the first instruction. We now use the debugger in combination with the simulator to step over each instruction in the led_blink_asm assembly language program code. The simulator simulates the currently selected ATtiny AVR microcontroller that was selected when the project was created. Internal registers and memory of the simulated AVR microcontroller can be examined in Microchip Studio when the debugger is running.

By default the I/O window should open as a small floating window, but if it does not, select Debug ▶ Windows ▶ I/O from the top menu to open it. Move this window to a suitable position so that it is easy to see and does not cover the code. Select I/O Port (PORTB) by clicking it in the I/O window. Some additional items are now displayed at the bottom of the I/O window as shown in Figure 3.3. We are interested in the items labeled DDRB and PORTB for this exercise and will see them change when certain assembly language instructions are executed.

![](img/83ef13a6c66cc7882b2f357e97f451dc_62_0.png)

Use the Step Over icon on the second top toolbar or the keyboard key F10 to step through the program instructions. Each time that an instruction is stepped over, it is executed and the next instruction highlighted in yellow. When the following first line of code is stepped over, a change in DDRB is seen in the I/O window.

```
sbi DDRB, DDRB4 ; Set pin PB4 as output
```

DDRB is an 8-bit register that is used to set up the pin that the LED is connected to as an output pin in the LED blink example. The SBI instruction shown in the above code snippet sets the correct bit in the DDRB register so that the LED can be driven on and off by the pin. Bits and registers are fully explained in the next two chapters.

After the loop label in the code, a SBI instruction and then a CBI instruction cause a change in the I/O window. This time the changes appears in the PORTB register. Continue to step through the program using the F10 key or Step Over icon. When the first SBI instruction after the loop label is executed, a change is seen in the PORTB register in the I/O window. This change represents the LED switching on. Step over the call to the delay subroutine and then over the CBI instruction. The CBI instruction switches the LED off, which is seen in the PORTB register of the I/O window.

When the RJMP (relative jump) instruction is executed, program execution starts at the top of the loop again, at the first instruction after the loop label. This completes the loop and the instructions in the loop execute again until the bottom of the loop is reached and the RJMP instruction is executed again.

This was just a basic introduction to using the simulator and was intended to show how instructions are executed from top to bottom unless a jump instruction is executed which changes the flow of a program. Stop the simulator and debugger by clicking the Stop Debugging icon on the second top toolbar (the red square ■), or by selecting Debug ▶ Stop Debugging from the top menu, or the keyboard shortcut Ctrl + Shift + F5.

### 3.6.2 Using a Physical AVR Microcontroller and Debugger

Using the debugger with a physical AVR microcontroller circuit is basically the same as using it with the simulator, but the correct debugging tool must be selected instead of the simulator, and the AVR must be put into a state that enables its debug capabilities. A USB debugger/programmer, such as the Atmel-ICE or AVR Dragon must be used. USB devices that are programmers only will not be able to be used for debugging. This means that those readers who are using a hobby programmer or the AVRISP mkii will not be able to debug physical hardware, but can just read through this section.

In ATtiny13(A) and ATtiny25/45/85, and in fact all of the PDIP packaged microcontrollers from Table 1.1 in section 1.3 of Chapter 1 except the ATtiny26, debugging is done by first enabling debugWIRE on the microcontroller chip itself. For this exercise we use the same LED circuit from Figure 2.1 in Chapter 2 and the same led_blink_asm project.

Plug your debugging device, such as the Atmel-ICE, into a USB port of the host PC. Select the debugger/programmer in Microchip Studio by clicking the hammer icon on the second toolbar where it should now say Simulator if you followed the previous simulator instructions. On the page that opens, use the drop-down box under Selected debugger/programmer to select the debugging tool that you are using to program and debug the AVR. For Interface, select ISP. Save the changes.

We need to change the AVR from its default ISP mode to debugWIRE mode in order to use it with the Microchip Studio debugger. With the debugger/programmer device already plugged into the USB port of the PC and the 6-pin header connected to the AVR microcontroller circuit, power up the AVR circuit. In Microchip Studio select Tools ▶ Device Programming or keyboard shortcut Ctrl + Shift + P. A Device Programming icon can also be found on the top toolbar to the right. The Device Programming dialog box opens and should have the current tool and device already selected. Make sure that the selected interface at the top of the dialog box is ISP and then click the Apply button. To test if the selected tool can correctly connect to the selected device, click the Read button under Device signature at the top of the dialog box. The device signature and target voltage boxes will be filled if the connection was successful. If there is any error when attempting to connect, make sure that the tool, device and interface are correct. Also check that the circuit is correctly wired to the programming tool and that it is powered by 5V. The target AVR must be in its default factory setting state with the ISP interface enabled.

Do not set the DWEN fuse with a program-only USB programmer because it will not be able to take the AVR back out of debugWIRE mode. Click the Fuses item in the left column of the Device Programming dialog box. Under Fuse Name find the DWEN (debugWIRE Enable) fuse which is labeled HIGH.DWEN. If this item is not visible, either use the scroll bar to the right to bring it into view, or resize the dialog box until it shows. Click the checkbox next to this fuse to check it as shown in Figure 3.4. Finally click the Program button in the dialog box. A Fuse Warnings dialog box pops up. Click the Continue button in this box. If it fails, simply click the Program button again. Close the Device Programming dialog box. After the DWEN fuse has been programmed, the AVR is still in ISP mode. The power to the AVR must be switched off and on again (called “cycling the power”) for it to change to debugWIRE mode. Cycle the power to the AVR now.

Now that the AVR is in debugWIRE mode, the tool interface must be changed in Microchip Studio. Once again, click the hammer icon on the second top toolbar. In the page that opens, the correct programming device should still be selected, but the interface must change. Click the Interface drop-down box and select debugWIRE. Save the changes.
