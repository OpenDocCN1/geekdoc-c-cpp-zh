Notice in the memory window at the bottom right of Microchip Studio, with prog FLASH selected in the Memory drop-down list, at that the very right column of this window, the text from the DB constant data lines can be seen (the words "Hello", "Hi", and the letters ABC). This is because this column contains the ASCII representation of the numbers in flash program memory. Computers and microcontrollers only work with numbers, so everything stored in memory is a number. ASCII is a standard way that assigns various numbers to characters, such as letters of the alphabet, punctuation marks and numbers 0 to 9. In this way, if a computer receives the number 0x48, it knows to display the letter 'H'. See the ASCII table in Appendix C of this book. Because the strings defined with DB are mixed with null terminators (zeros), numbers from next to the numbers: label, and program instructions, readable text in the memory window is mixed in with unreadable or meaningless characters. The right column in the memory window tries to convert every number in memory to an ASCII character. Some characters are unprintable (numbers 0 to 31 and 127, or 0x00 to 0x1F and 0x7F), and represented by a dot. Others are from the extended ASCII table, and include numbers above 127, or 0x7F. What extended ASCII characters appear as depends on which character or font set is used to display them.

Open the Processor Status window and step over the instructions that load the address to the Z register (the ZL instructions under the main label). The address of the "Hello" string at the message label is at a very low address, so ZH, or R31 does not change in the simulator, but stays at 0x00. After stepping over the instruction that loads the low address byte to ZL, or R30, it can be seen that both R30 at the bottom of the Processor Status window, as well as the Z Register at the top of the Processor Status window contain 0x02. This is of course because part of the Z register is R30. The first 16-bit instruction at memory location 0x0000 contains the first RJMP instruction of the program. The second 16-bit instruction location in program memory contains the start of the message data, at 16-bit address 0x0001. Because we are byte addressing program memory using the Z register, and left shifted this address of 0x0001 when loading the Z register, the byte address of the start of the message string is 0x0002, as seen in the Z register.

It may be easier to view the Flash program memory as a single column of bytes by changing the Columns field in the memory window. Click the double arrow at the right of the window if needed to change the number of columns using the Columns drop-down list.
