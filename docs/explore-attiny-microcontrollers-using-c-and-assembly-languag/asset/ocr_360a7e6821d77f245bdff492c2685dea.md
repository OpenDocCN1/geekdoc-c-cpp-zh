In the code, the number of milliseconds (t_ms in the formula) is called MS_TIME_DEL. Thus with the formula applied to the code, the code now becomes the following.

```
ldi R16, low (((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
```

F_CPU sets the AVR CPU frequency in use, and MS_TIME_DEL sets the time delay to generate in milliseconds. These values are set at the start of the code as follows, using a 1MHz CPU frequency and 500ms delay as an example.

```
.equ F_CPU = 1000000 ; Frequency of CPU
.equ MS_TIME_DEL = 500 ; Time delay in milliseconds
```

The fully modified part of code from the wait_1s subroutine now becomes the following when the new calculation is applied to it for the wait_ms subroutine.

```
wait_ms:
ldi R16, low (((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
ldi R17, byte2(((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
ldi R18, byte3(((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
ldi R19, byte4(((F_CPU * MS_TIME_DEL) / 1000) - 10) / 10)
```

Remember that the mathematical operators in the above expressions are performed by the AVRASM2 assembler program when it finds them in the source code file during the build process. The result is that the assembler program generates a number based on the values of F_CPU, MS_TIME_DELAY and the mathematical expressions. This calculated number is then split into four parts using the functions low(), byte2() byte3() and byte4(). These functions are also run by the assembler program during the build process, which finally results in four numbers that are loaded into R16 to R19 in the generated machine code. In effect these numbers are “hard coded” into the final machine code, and the wait_ms subroutine always generates the same time delay set by F_CPU and MS_TIME_DEL. This value can’t be changed at run time when the code is executing on the target AVR. It can only be changed at build time in the source code and set to a new value. The mathematical operators and functions used in the above code are found in the Expressions section of the AVR Assembler document from Microchip.

# 10.2.3.3 Limits of the wait_ms Subroutine

The wait_ms subroutine has certain upper and lower limits to the CPU frequency and millisecond time delay that it can be supplied with. If the number of cycles that the calculation generates and places in the 32-bit number stored in R16 to R19, is too high or too low, then the generated time delay will be incorrect. It is best to calculate these limits so that anyone using this wait_ms subroutine will supply it with in-bounds parameters.
