Hexadecimal numbers can also be started with the dollar sign ($) instead of 0x.

```
ldi r16, $2A
```

A binary number 0b0101010.

```
ldi r16, 0b00101010
```

The same binary number with an underscore in the number makes it easier to read and is accepted by the AVR assembler program.

```
ldi r16, 0b0010_1010
```

# 4.6 Numbers in C Programs

Those readers who are C programmers will know that decimal numbers are written just as numbers without any prefix, for example 16 is decimal 16 in a C program. Hexadecimal numbers in C start with the 0x prefix, for example 0x2A.

In standard C, there is no way to directly write a binary number, at least not in the C99 or earlier standards. Hexadecimal numbers are used instead. The GNU C programming tools used with Microchip Studio have an extension that is non-standard that allows binary numbers to be written in C programs. Binary numbers are started with the 0b prefix, the same as for assembly language discussed in the previous section, but does not support the underscore version of a binary number. For example, using the binary number 0b00010000 in a GCC C AVR project started in Microchip Studio will compile and build properly.

The following code snippet shows part of a C program with decimal, hexadecimal and binary numbers.

```
DDRB |= 16;    // DDB4 as decimal
while (1) {
    PORTB |= 0b00010000;    // PB4 as binary (non-standard)
    _delay_ms(1000);
    PORTB &= ~0x10;    // PB4 as hexadecimal
    _delay_ms(1000);
}
```
