In the polled timer projects, TIFR was directly used and is defined with a different name for the ATtiny13(A) and ATtiny25/45/85. We used the .ifndef directive to make the code work for both ATtiny device ranges. In the timer0_unit_int.asm project, TIFR is not directly used, but TISK is. This register is named TIMSK0 for an ATtiny13(A), but TISK for an ATtiny25/45/85, so the same .ifndef code is used, but this time for the TIMSK register rather than for the TIFR register, as can be seen at the top of the code listing. When the OCIE0A bit is set in the TIMSK register in the code, it works for both ATtiny13(A) and ATtiny25/35/85 devices even though this bit is at different positions in the registers of the two ATtiny ranges, as can be seen in the datasheets. Again, this works because it is correctly defined in the header file for the chosen device in Microchip Studio.

Unused vector table entries have been removed from the code. Timer 0 compare match A interrupt vector is included in the code using the name OCOAaddr defined for this address in the ATtiny include files. As already explained, this name is used with the .org directive to set the correct address for the timer 0 compare match A interrupt vector. OCOAaddr is defined as 0x0006 in ATtiny13(A) include files, but as 0x000A in ATtiny25/45/85 files, causing the vector to be placed at the correct address for the chosen device. Because the unused vector table entries were removed, there is no need for the dummy ISR code, which has also been removed from the bottom of the file.
