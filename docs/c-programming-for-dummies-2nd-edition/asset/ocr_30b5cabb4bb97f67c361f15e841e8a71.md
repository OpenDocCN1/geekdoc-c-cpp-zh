Line 18 in Listing 19-9 contains the dreaded, feared, avoided, and cursed ** notation, or double-pointer notation. To use my preferred nomenclature, it's a double-peeker. Before I commence the discussion, do Exercise 19-18.

# Exercise 19-18: Carefully type the source code from Listing 19-9 into your editor. Compile and run.

To understand the **(fruit+x) construct, you must work from the inside out:

```
fruit+x
```

Variable fruit contains a memory address. It's a pointer! The x is a value incrementing by one unit. In this case, the unit is the size of a pointer; all elements of the fruit array are pointers.

```
*(fruit+x)
```

You've seen the preceding construction already. It's the contents of the address fruit+x. From the code, fruit is an array of pointers. So the result of the preceding operation is . . . a pointer!

```
** (fruit+x)
```

Finally, you get a pointer to a pointer or — put better — a peeker to a peeker. If the inside peeker is a memory address, the outside peeker (the first asterisk) is the content of that memory address. Figure 19-2 attempts to clear up this concept.
