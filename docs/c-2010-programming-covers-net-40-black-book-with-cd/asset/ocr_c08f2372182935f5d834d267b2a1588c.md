# Using the Strong Name Utility

The Strong Name utility (sn.exe) helps create unique public--private key pair files that are called strong name files and sign assemblies with them. The Strong Name utility also provides options for key management, signature verification, and signature generation. Type the following code snippet in the command prompt to use the sn utility:

```
sn [-quiet][option [parameter(s)]]
```

Table 33.7 lists some of the important sn utility switches:

# Table 33.7: Showing the Important sn.exe Switches

| Switch | Description |
|---|---|
| -h | Displays the command syntax and options for the Strong Name utility. |
| -e assembly outfile | Extracts the public key from an assembly and stores it in an outfile. |
| -k outfile | Generates a new key pair and writes it to the specified file. |
| -o infile [outfile] | Extracts the public key from the infile and stores it in a .csv file. A comma separates each byte of the public key. If you do not specify an outfile, this option places the output on the Clipboard. |
| -p infile outfile | Extracts the public key from the key pair in the infile and stores it in the outfile. This public key can be used to Delay Sign an assembly using the /delaysign and /keyfile options of the Assembly Linker (AL.exe). When an assembly is Delay Signed, only the public key is set at the compile time and space is reserved in the file for the signature to be added later when the private key is known. |
| -q[quiet] | Specifies the quiet mode, and suppresses the display of success messages. |
| -R assembly infile | Re-signs a Delay Signed or previously signed assembly with the key pair in the infile. |
| -t[p] infile | Displays the token for the public key stored in the infile. The content of the infile must be previously generated by using -p. The Sn.exe utility computes the token using a hash function from the public key. To save space, the CLR stores public key tokens in the manifest as part of a reference to another assembly when it records a dependency to an assembly that has a strong name. The -tp option displays the public key in addition to the token. |
| -T[p] assembly | Displays the public key token for an assembly. The Sn.exe utility computes the token using a hash function from the public key. To save space, the runtime stores public key tokens in the manifest as part of a reference to another assembly when it records a dependency on an assembly that has a strong name. The -Tp option displays the public key in addition to the token. |
| -v assembly | Verifies the strong name of an assembly, where assembly is the name of a file that contains an assembly manifest. |
| -vf assembly | Verifies the strong name of an assembly. Unlike the -v option, -vf forces verification, even if it has been disabled using the -Vr option. |
| -Vl | Lists the current settings for strong name verification. |
| -Vr assembly [userlist] [infile] | Registers an assembly to skip its verification. You can specify a comma-separated list of user names and infiles. |
| -Vu assembly | Unregisters an assembly so that its verification can be skipped. |
| -Vx | Removes all verification-skipping entries. |
| -? | Displays the command syntax and options for the tool. |

# NOTE

All Sn.exe options are case-sensitive and must be typed exactly as specified, to be recognized by the tool.
