# # In Depth

When a Windows operating system starts, various services related to the operating system are also started automatically. These services are known as Windows services, which perform specific functions and do not require user intervention. Windows services do not have user interfaces or produce any visual output. In addition, these services run automatically in the background when you start your system. These services do not require you to log on to the system. Some examples of Windows services are server products, such as Microsoft Exchange, SQL Server, and other applications; for instance Windows date and time that sets the computer clock. When a Windows service starts, it creates a log entry in the event log indicating that it has started. The service also creates a log entry on a specified interval during the time in which it is running and finally when it is stopped.

Visual Studio 2010 enables you to create Windows services as applications and allows you to define the code that controls the actions to be taken when commands, such as start, pause, resume, and stop are sent to the service. You can create Windows service applications by using the ServiceBase, ServiceInstaller, ServiceProcessInstaller, and EventLog classes. In a Windows service application, you can also configure a service to start automatically when the operating system starts or configure it as manual to start the service manually. Since a Windows service does not have any interface, so it cannot be debugged as any regular application, but debugged as a process. Moreover, you can install or uninstall a Windows service application from a target Windows by using the Installutil.exe utility or the Windows installer.

In this chapter, you learn about various classes to create Windows services in Visual Studio 2010 using the ServiceBase, ServiceInstaller, ServiceProcessInstaller, and EventLog classes. The ServiceBase class allows you to define the behavior of the Windows service and the commands, such as Start, Pause, and Stop. The ServiceInstaller and ServiceProcessInstaller classes are used to install Windows services and specific processes to the services, respectively. Next, the EventLog class is explained that enables you to access the Windows event logs from Windows services. Finally, you learn to install and uninstall a Windows service by using Installutil.exe and Windows Installer.

Let’s start with the ServiceBase class.

# ## The ServiceBase Class

The ServiceBase class is the base class to create a Windows service. It is inherited from the Component class. The inheritance hierarchy of the ServiceBase class is as follows:

```
System.Object
    System.MarshalByRefObject
        System.ComponentModel.Component
            System.ServiceProcess.ServiceBase
```

The ServiceBase class provides various properties, methods, and commands to control the behavior of a Windows service. The commands that are given to a Windows includes Start, Pause, and Stop. These commands are handled by Service Control Manager (SCM) that acts as the central organizer of the Windows services.

Some important public properties of the ServiceBase class are listed in Table 20.1:

**Table 20.1: Noteworthy Public Properties of the ServiceBase Class**

| Property | Description |
|---|---|
| AutoLog | Specifies whether or not to record the Start, Stop, Pause, and Continue commands in the event log |
| CanHandlePowerEvent | Determines whether or not a Windows service can handle notifications of computer power status changes |
