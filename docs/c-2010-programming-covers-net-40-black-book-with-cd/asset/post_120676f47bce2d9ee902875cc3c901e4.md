The Designer window allows you to make changes in the XAML file of your application. In other words, the changes made in the Designer window are automatically reflected in the XAML file.

The WPF Designer window provides the following features:

- Zoom Control – Controls the size of the design surface. You can zoom from 10% to 20%.
- Fit In View – Specifies the size of the design surface of an available screen in the Design view.
- Grid Rails – Manage rows and columns in a Grid control. This feature allows you to create and delete the columns and rows as well as adjusting their relative widths and heights.
- Gridlines – Control the height and width of the Grid’s columns and rows by using gridlines.
- Gridline Indicators: Indicates the heights or widths of the nearby columns or rows.
- Move Handle – Helps in dragging the controls to the desired place on the designer.
- Resize Handles – Resize the selected control by clicking and dragging a resize handle.
- Margin Lines – Specify the space between the edge of the control and the edge of its container. You can set the margins of the control by clicking its margin lines.
- Margin Stubs – Set the margin distance of the selected control to the corresponding edge of the container by clicking the margin stub.
- Snaplines – Helps in the alignment of controls relatively.

## The Web Forms Designer

The Web Forms designer is a designer that enables you to make changes in the controls, markup, and script of the Web Forms. This designer helps in creating ASP.NET Web applications with different views of your pages and provides tools, such as the Toolbox and the Properties window for creating and editing the page elements.

Visual Studio 2010 has three views: Design, Split, and Source views in the Web Forms Designer. These views are described as follows:

- Design view – Displays Web pages, master pages, HTML pages, and user controls using the What You See Is What You Get – WYSIWYG view. This view allows you to add controls in the Web Form and set their properties.
- Source view — Displays the markup view of your page, which includes HTML elements, ASP.NET controls and client script. In case, you are working with a single-file page, the source view also displays the server-side code for the page.
- Split view — Enables you to view both the Source view and Design view at the same time. Figure shows the Web Forms designer in the Split view:

![](img/e073a4882197be4ab61103cbe0bcb394_95_0.png)

You can easily switch between the three views of the Web Forms designer using the Design, Split, and Source tabs at the bottom of the currently selected page. You can also open the code-behind page of any selected page in Solution Explorer by right-clicking on the page and selecting the View Code option from the context menu.

By default, when you open a Web page, it is always displayed in the Source view. If you want your pages open in a different view other than the Source view, select Tools → Options. Then, select the HTML Design category, and on the General tab, set your preferred view.

## Server Explorer

There are various services available on a particular server. These services include event logging, message queues, crystal report services, performance counters, other system services, and Database services, such as SQL Server. Server Explorer allows you to view the services available on a particular server. This window is powerful tool that helps you to work with databases in an easy way to use graphical environment. You can drag a service from the window onto a design surface, so that you can interact with this element programmatically in your application. Now let’s suppose that you drag and drop a database table onto a form. In such a case, .NET automatically creates the connection and command objects that are needed to access that table. You can also drag a performance counter onto a Windows Form and use that component to increment or decrement that counter.

Server Explorer can be opened in either of the following ways:

- By selecting View→Server Explorer from the main menu
- By pressing Ctrl+Alt+S keys

## Figure 1.68: Displaying Server Explorer

In Server Explorer, you can view and retrieve information from all the databases you are connected to. For example, you can view the information about all the database tables, views, stored procedures, and functions in this window. Server Explorer provides access to a number of resources. Using Server Explorer, you can view and manipulate data links, database connections, and system resources on any server, which is connected to the network. Some of the tasks that you can perform in Server Explorer are opening the data connections and commands, logging on to servers and displaying their databases and system services, viewing information about the available Web services, creating data connections to SQL Servers and other databases, storing database projects and references, and interacting with data resources by creating data components in your Visual Studio projects.

A node can be defined as a group of various subnodes that are used to perform specific functions in an application. There are three primary nodes in the Server Explorer, which are described as follows:

- Data Connections — Specifies a top-level node that lists the data connections added by a user to the server. You can make data connections of different databases, including Oracle databases running on UNIX or Microsoft Windows Operating Systems.
- Servers — Specifies a top-level node that contains a list of the currently connected servers. You can create new components by dragging the nodes from the Servers node onto Visual Studio Designer. The various child node types available in Servers node are described as follows:
  - Crystal Reports Services — Lists the available Crystal Reporting options
  - Event Logs — Lists the available event logs on the Microsoft Windows 2003 server, Microsoft Windows 2000 server, or Windows NT version 4.0
  - Management Classes – Enables the developers to browse and modify Windows Management Instrumentation (WMI) data and call methods
  - Management Events – Enables the developers to register for WMI events
  - Message Queues – Lists the message queues along with the messages that each queue contains on the selected server.
  - Performance Counters – Lists the performance counters on the Microsoft Windows 2003 server, Microsoft Windows 2000 server, or Windows NT version 4.0
  - Services – Lists the services that exists on the selected Windows 2000 or Windows NT 4.0 server
  - SharePoint Connections – Enables you to connect local SharePoint sites from the computer where applications are developed

The toolbar of Server Explorer contains the following buttons:

- Refresh – Refreshes Server Explorer and shows a list of the recently connected servers. If a particular server or its services have stopped, then its name is not reflected in Server Explorer.
- Stop Refresh – Allows you to stop the refresh process.
- Connect to Database – Enables developers to establish a connection to a database listed in Server Explorer through code.
- Connect to Server – Enables developers to connect to a running server process listed in Server Explorer.
- Add to SharePoint Connections – Adds a SharePoint connection from the computer where applications are developed.
