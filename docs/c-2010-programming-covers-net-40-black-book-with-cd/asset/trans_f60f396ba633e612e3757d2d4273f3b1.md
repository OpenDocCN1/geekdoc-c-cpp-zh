# 手动配置探测设置

如果您已有 Displayer.exe 的配置文件，即 Displayer.exe.config，只需将突出显示的信息放在 assemblyBinding 标签下以设置探测配置，如清单 33.15 所示：

# 清单 33.15：设置探测属性

```
<?xml version="1.0"?>
<configuration>
  <runtime>
    <gcConcurrent enabled="true" />
    <assemblyBinding xmlns="urn:schemas-microsoft-com:asm.v1">
      <publisherPolicy apply="yes"/>
      <probing privatePath="SubDir" />
    </assemblyBinding>
  </runtime>
</configuration>
```

TIP
您可以添加多个用分号分隔的搜索路径，例如 SubDir; NewBin; MySub: 用于探测。

再次尝试运行 Displayer 应用程序，并单击 Call Display 按钮。你可以看到探测设置现在已生效。

# 为签名程序集配置 Codebase 设置

在本节中，我们使用 SharedObject.dll 程序集来添加 codebase 设置。现在，在任意硬盘上创建一个名为 AnotherGAC 的文件夹，例如 E。将 SharedObject.dll 版本 1.0.0.0 移动到此文件夹。在 E 驱动器中创建另一个文件夹 NewGAC 并将 SharedObject.dll 版本 1.1.0.0 移动到此文件夹。从 GAC 中删除 SharedObject.dll 的两个版本。

现在，如果你运行 ASimpleClient，会显示关于缺少配置文件的错误，这意味着应用程序需要程序集查找配置来找到文件。现在让我们看看 codebase 设置如何处理类似这种情况。我们再次通过使用配置工具以及手动方式来探索。

# 使用配置工具配置 Codebase 设置

与配置探测设置类似，您也可以使用配置工具在应用程序中配置 codebase 设置。要配置应用程序，您需要将应用程序以及程序集添加到配置工具。现在，执行以下步骤将应用程序和程序集添加到工具中：

- 1. 打开 .NET Framework 2.0 配置工具并右键单击 Applications 节点。
- 2. 从上下文菜单中选择 Add 选项以显示配置应用程序对话框。
- 3. 单击 Other 按钮并浏览 ASimpleClient.exe，然后单击 Open 按钮。这将在 .NET Framework Configuration 2.0 工具中添加 ASimpleClient 节点。
- 4. 右键单击 ASimpleClient 下的 Configured Assemblies 节点并选择 Add 选项。
- 5. 在 Configure an Assembly 对话框上，选择 Choose an assembly from the list of assemblies this application uses 单选按钮，然后单击 Choose Assembly 按钮。
- 6. 从列表中选择 SharedObject，然后单击 Select 按钮。
- 7. 单击 Finish 按钮。这会将程序集添加到我们客户端应用程序的 Configured Assemblies 文件夹中并打开 SharedObject Properties 对话框。

现在需要配置的应用程序和程序集已添加到工具中，我们可以通过执行以下步骤为它们配置 codebase 设置：

- 1. 右键单击 ASimpleClient 的 Configured Assemblies 文件夹中你拥有的 SharedObject 程序集并选择 Properties 选项以显示 SharedObject Properties 对话框，如果它尚未打开。
- 2. 选择 Codebases 选项卡。

3. 在 Requested Version 字段中输入 1.1.0.0，因为这是应用程序当前绑定到的版本并且会请求该版本。

4. 在 URI 字段中输入 file:///E:/NewGAC/SharedObject.dll，如图 33.20 所示：

6. 运行 ASimpleClient 应用程序，现在应该可以正常运行。

# 手动配置 Codebase 设置

您可以通过添加突出显示的代码将 codebase 设置应用于应用程序的配置文件（ASimpleClient.exe.config），如清单 33.16 所示：

清单 33.16：设置 ASimpleClient.exe.config 文件的代码

```
<?xml version="1.0"?>
<configuration>
<runtime>
<assemblyBinding xmlns="urn:schemas-microsoft-com:asm.v1">
<dependentAssembly>
<assemblyIdentity name="SharedObject" publicKeyToken="001fe4f7b2c7f625" />
<publisherPolicy apply="yes" />
<bindingRedirect oldversion="1.0.0.0" newversion="1.1.0.0" />
<codeBase version="1.1.0.0" href="file:///E:/NewGAC/SharedObject.dll" />
</dependentAssembly>
</assemblyBinding>
</runtime>
</configuration>
```

您会注意到 assemblyIdentity 节点指定了 public token 以标识程序集。然而，请注意 public token 包含各种数字和字母，在手动输入时可能会输入错误。

您还可以通过在配置文件中添加第二个突出显示的行，为应用程序添加 codebase 设置以查找 E:\AnotherGAC 中的旧版本程序集，如清单 33.17 所示：

清单 33.17：设置 Codebase 设置以查找程序集的旧版本

```
<?xml version="1.0"?>
<configuration>
<runtime>
<assemblyBinding xmlns="urn:schemas-microsoft-com:asm.v1">
<dependentAssembly>
```

```
<assemblyIdentity name="sharedobject" publicKeyToken="001fe4f7b2c7f625" />
<publisherPolicy apply="yes" />
<bindingRedirect oldVersion="1.0.0.0" newVersion="1.0.0.0" />
<codeBase version="1.1.0.0" href="file:///E:/NewGAC/sharedobject.dll" />
<codeBase version="1.0.0.0" href="file:///E:/AnotherGAC/sharedobject.dll" />
</dependentAssembly>
</assemblyBinding>
</runtime>
</configuration>
```

# 创建发布者策略

如 In Depth 部分所述，发布者策略用于将程序集的客户端重定向到配置文件的较新版本，而无需重新编译程序集。发布者策略文件指定程序集重定向和代码库设置，并使用与应用程序配置文件相同的格式。然后将发布者策略文件编译成程序集并放置在 GAC 中。

让我们使用 SharedObject 和 ASimpleClient 应用程序来学习如何创建发布者策略文件。执行以下步骤创建发布者策略文件：

- 1. 将 ASimpleClient.exe.config 文件复制到 SharedObject 应用程序的文件夹中。
- 2. 将 ASimpleClient.exe.config 文件重命名为 PubPol.config。
- 3. 打开 Visual Studio 命令提示符（2010）导航到 SharedObject 应用程序的文件夹并输入以下命令：
- al /link:PubPol.config /out:policy.1.0.sharedobject.dll /keyfile:Akey.snk
- 4. 将 ASimpleClient.exe 文件复制到应用程序的 bin\Debug 目录以外的某个位置。

在前面的命令中，al 是程序集链接实用程序，它使用 PubPol.config 文件的配置设置并创建名为 policy.1.0.sharedobject.dll 的发布者策略程序集。

现在，您可以使用 .NET Framework 2.0 配置工具将策略程序集安装到 GAC 中。

现在，当你运行 ASimpleClient.exe 文件时，你会注意到该文件使用了 SharedObject 的新版本。
