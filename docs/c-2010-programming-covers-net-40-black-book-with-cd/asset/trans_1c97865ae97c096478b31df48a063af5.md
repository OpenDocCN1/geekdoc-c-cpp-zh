## MSIL 源代码

在编译程序集时，编译器将源代码翻译成 MSIL。这是因为 MSIL 是一组与平台和 CPU 无关的指令，可以在支持 .NET Framework 的任何环境中执行。MSIL 包含加载、存储、初始化对象以及调用方法的信息，以及执行各种操作（如算术和逻辑操作、控制流、直接内存访问和异常处理）的指令。一旦源代码被执行，实时（JIT）编译器就会将 MSIL 转换为 CPU 特定的代码。

## 类型元数据

类型元数据描述了存储在程序集中的类型的格式。它还包含有关程序集引用的外部类型的信息。执行代码后，CLR 将此元数据加载到内存中并引用它以检索有关源代码的类、成员和继承的信息。

## 资源

.NET Framework 本地化模型由一个包含大量嵌入式资源的主程序集组成，例如应用程序图标、图像文件、声音剪辑和字符串表。由于主程序集包含嵌入式资源，如果在本地化卫星程序集中找不到资源，ResourceManager 类将以分层方式回退到主程序集中的资源。.Net Framework 还支持仅包含本地化资源的卫星程序集。卫星程序集在您希望根据特定文化为国际软件开发分区资源时很有用。

## 程序集类型

根据其位置和对客户端的可访问性，程序集可以大致分为共享或私有。存储在单台机器上的共享程序集的单个副本可以被多个应用程序使用。共享程序集不会部署在正在使用它的应用程序的目录中；相反，它部署在全局程序集缓存（GAC）中，GAC 是程序集的存储库。您也可以使程序集为私有。这意味着复制到应用程序目录中的程序集只能被指定的应用程序访问，而其他应用程序无法使用同一程序集。换句话说，如果只有少数应用程序需要使用您的库程序集，您可以将它们放在相关应用程序的目录中，而不是放在 GAC 中。由于私有程序集独立工作，因此与共享程序集相比，它们更容易管理和维护。私有程序集不需要强名称，并且可以在不担心影响其他应用程序的情况下安装和卸载。

## 程序集签名

在 .NET Framework 3.5 中，有两种方法可以签署程序集——使用强名称和使用 SignTool.exe 文件，也称为 Sign Tool。当您使用强名称签署程序集时，会将公钥加密添加到包含程序集清单的文件中。使用强名称签署程序集可为程序集提供身份，并验证程序集名称是否唯一。另一方面，使用 Sign Tool 签署程序集可为程序集提供强名称和数字签名。Sign Tool 要求发布者向第三方机构展示其身份并获取证书。然后将此证书嵌入到管理员用来确定是否信任代码真实性的文件中。使用 Sign Tool 签署的程序集通过数字签名和证书保证真实性和完整性。此外，Sign Tool 还执行各种功能，例如哈希验证、强名称和签名，以确保程序集未被篡改。

Sign Tool 提供了一个命令行工具，用于对文件进行数字签名并验证文件中的签名。您可以在命令提示符下使用以下命令签署程序集：

```
signtool [command] [options] [file_name]
```
