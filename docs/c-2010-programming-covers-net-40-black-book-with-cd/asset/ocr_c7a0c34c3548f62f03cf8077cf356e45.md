# Multicasting with Delegates

Each delegate object that we have created so far holds a reference of a single method. However, it is possible for a delegate object to hold references of and invoke multiple methods. Such delegate objects are called multicast delegates or combinable delegates. You can encapsulate more than one method into a single delegate object using the overloaded += operator. Each delegate object that you create, by default, maintains an invocation list, which is the list of methods encapsulated into the delegate object. The invocation list of a multicast delegate consists of multiple methods that are invoked in the order they were added to the multicast delegate. Objects of only those delegates that satisfy the following two conditions can be made as multicast delegates:

+   - The return type of the delegate is void
+   - None of the parameters of the delegate is an output parameter (a parameter declared using the out keyword)

You learn how to create a multicast delegate in the Creating Multicast Delegates section of the Immediate Solutions.

# Exploring Covariance and Contravariance

Covariance allows you to create delegate methods, which are used by classes and derived classes. Contravariance allows you to create more general delegate methods that can be used with a larger number of classes. These features are introduced in C# to increase the flexibility while matching delegate methods with delegate signatures. Flexibility means the ability of a delegate to cope up with different classes or events of a program. Normally, the method passed to a delegate must have the same return type and signature as the delegate. However, covariance allows you to use a method that has a derived return type as a delegate. Consider the following code snippet, which defines a delegate:

```
delegate object GetData(TextBox control);    //defining a delegate
```

The preceding statement defines a delegate, GetData. Covariance allows the GetData delegate to point to any method that takes a TextBox argument irrespective of its return type, as all types of .NET classes inherit from the System.Object class. Therefore, the GetData delegate can point to the method, GetcontrolText, as the String type of .NET Framework inherits from the System.String class, as shown in the following code snippet:

```
string GetControlText(TextBox control)    // GetControlText is the method to
{                                        //which the GetData delegate points.
    return control.Text;
}
```

Similar to covariance, contravariance allows you to use a method with derived parameters as a delegate. This means that contravariance enables a delegate to point to a method whose argument is the base type of argument appearing in the delegate's signature. In the preceding code snippets, we have created the GetData delegate. The following code snippet shows that the GetData delegate is pointing to the GetTag() method:

```
object GetTag(Control ctr)
{
    return ctr.Tag;
}
```

In the preceding code snippet, contravariance enables the GetData delegate to point to the GetTag() method, which accepts a Control or Object value, as these types are the base types for the TextBox class specified in the delegate signature.
