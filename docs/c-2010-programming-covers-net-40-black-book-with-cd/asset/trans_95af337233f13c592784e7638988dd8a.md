## 从程序集中的类动态调用方法

如果你正在为 C# 或其他任何 .NET 语言创建新的编译器或解释器，你需要使用反射来查找编译器或解释器中加载的对象的相关信息。你不仅可以查找有关不同对象的信息，还可以动态地在它们上调用方法，如果你知道要调用的方法的名称以及要传递给该方法的参数。

除了将信息传输到方法中之外，C# 还允许你将信息从方法返回给调用函数。这意味着如果一个被调用的方法返回一个值，那么它也会将该信息提供回你的调用应用程序的方法中。在本节中，我们创建 DynamicInvoke.cs 文件，它提供了一组简单的类。首先，我们创建一个实现特定接口的类，通过定义接口的方法。接下来，你直接调用其中一些方法以显示函数的输出。最后，你动态调用其中一些方法以显示该特定过程是如何进行的。

## 验证类是否包含方法

如果你正在编写一种允许使用 C# 对象的脚本语言，你需要在允许脚本编写者使用该方法创建脚本之前验证给定的类是否包含该方法。毕竟，如果方法不存在，调用它就没有意义。这使你能够在运行应用程序之前验证方法。

使用 C# 的反射功能，你可以轻松确定给定的类是否包含给定名称的方法。事实上，你可以更进一步，检查脚本传递给方法的参数的数量和类型是否正确。检查包含特定期望方法的类（类）很有趣。

假设脚本编写者创建了一个包含未定义变量的脚本，该变量调用名为 Foo 的方法。你可以在脚本解析器遇到它时将该变量标记为未定义，因为在脚本中使用该变量时尚未声明该名称的变量。然而，如果你向他们展示变量的可能值，对用户来说更有用更有价值。如果所有可用程序集中只有一个类包含特定方法，你可以合理地假设它是用户想要的。发出警告然后继续创建脚本要比简单地以 Unknown Variable <x> 这样的错误终止要合适得多。

在本示例中，你通过创建一个可以搜索给定程序集中给定方法名的应用程序来探索 C# 反射的功能。包含此名称的任何方法所在的类都会打印到控制台屏幕供用户查看。在此应用程序中搜索全文比在程序集的源代码中搜索要方便得多。在许多情况下，你无法访问程序集的源代码。CLR 就是一个只有二进制访问权限的程序集的良好示例。CD 上的 VerifyClassMethod.cs 示例显示了应用程序源代码。
