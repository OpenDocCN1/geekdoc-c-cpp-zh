# Listing 18.4: Adding the HttpPost and HttpGet Names within the Local web.config File

```
<configuration>
  <system.web>
    <webServices>
      <protocols>
        <add name="HttpPost" />
        <add name="HttpGet" />
      </protocols>
    </webServices>
  </system.web>
</configuration>
```

When you use the HTTP-GET and HTTP-POST protocols, you cannot build Web methods that take complex types as parameters or return values, such as ADO.NET DataSet or structure type. For simple Web services, this limitation may be acceptable. However, if you want to build much more elaborate Web services, you can use SOAP bindings.

# Simple Object Access Protocol

SOAP, one of the key elements in a Web service, is a protocol used for messaging. It is completely XML-based.

SOAP specifications are standardized by W3C and are used by most companies that develop Web services.

SOAP provides a complete set of rules for messages, called SOAP envelopes, as well as the rules for issues, such as data encoding, message handling, and message binding, to other protocols, such as HTTP. One of the great advantages of using a SOAP message is that it is not restricted to any particular protocol. However, the HTTP protocol is most commonly used since it is not restricted to any one operating system.

A SOAP message is a simple XML document, which always contains the mandatory envelope and body elements and can contain a few optional elements, such as <Header> and <Fault>. Listing 18.5 shows the syntax of a SOAP message:

# Listing 18.5: Syntax of a SOAP Message

```
<?xml version="1.0"?>
<soap:Envelope
xmlns:soap="http://www.w3.org/2001/12/soap-envelope"
soap:encodingStyle="http://www.w3.org/2001/12/soap-encoding">
  <soap:Header>
    ...
  </soap:Header>
  <soap:Body>
    ...
    <soap:Fault>
      ...
    </soap:Fault>
  </soap:Body>
</soap:Envelope>
```

As already mentioned, the envelope and body elements are always required in any SOAP message. The following is the syntax of both these elements:

```
<?xml version="1.0"?>
<soap:Envelope
xmlns:soap="http://www.w3.org/2001/12/soap-envelope"
soap:encodingStyle="http://www.w3.org/2001/12/soap-encoding">
...
```
