The collection-based aggregates operate on collections and produce the aggregated result. We can write it anywhere in the query and do not require a GROUP BY clause to obtain a result. The syntax of the collection-based aggregates is as follows:

```
select z.x as x, count({1,2,3}) as y from T as z
```

No support for * — Specifies that Entity SQL does not support the * construct. The syntax * has been supported by Transact-SQL as an alias for the entire row. It also allows a special count (*) aggregate that includes nulls, and such constructs are able to handle inheritance. The following code is valid in Transact-SQL, but invalid in Entity SQL:

```
select * from E and select E1.* from E1, E2...
```

Equivalent expressions can be written in Entity SQL as follows:

```
select value e from E as e and select value e1 from E1 as e1, E2 as e2...
```

Entity SQL does not support the count (*) aggregate but the same result can be obtained by using the count (0) method instead.

Changes to Group By — Specifies that Entity SQL supports aliasing of the GROUP BY clause. Expressions in the SELECT clause and HAVING clause must refer to the GROUP BY keys through the aliases as shown here. The following code is valid in Transact-SQL, but invalid in Entity SQL:

```
select b + c, count(*), sum(a)
from Z
group by b + c
```

In Entity SQL, the same expression can be expressed as follows:

```
select k1, count(z.a), sum(z.a)
from Z as z
group by z.b + z.c as k1
```

ORDER BY clause usage — Specifies that Entity SQL provides the capability of using a nested ORDER BY expression. It can be placed anywhere in the query. According to the need of the application, the developer can use the Order BY clause in any order.

In Transact-SQL, we use the ORDER BY clause in the topmost block as follows:

```
SELECT e1.FirstName, e1.LastName
FROM Company_details.employees as e1
ORDER BY e1.LastName
```

The order of nested queries can be ignored in Entity SQL, as shown in the following syntax:

```
SELECT e2.FirstName, e2.LastName
FROM (SELECT e1.FirstName, e1.LastName
FROM Company_details.employees as e1
ORDER BY e1.LastName) as e2
```

Transact-SQL functionality not available in Entity SQL — Specifies that the transact functionalities are not supported in Entity SQL. The functionalities of SQL that are not supported in Entity SQL are as follows:

+   - Data Manipulation Language (DML) — Entity SQL does not provide support for DML statements such as INSERT, UPDATE, and DELETE
+   - Data Definition Language (DDL) — Entity SQL does not provide support for DDL statements such as CREATE, GRANT, and REVOKE
+   - Imperative programming — Entity SQL supports functional programming languages rather than supporting imperative programming.
+   - Grouping functions — Entity SQL does not provide support for grouping functions such as CUBE, ROLLUP, and GROUPING_SET.
+   - Analytic functions — Entity SQL does not provide support for analytic functions.

Built-in functions and operators — Specifies that Entity SQL provides support for subsets of Transact-SQL built-in functions and operators that are supported by database providers. Entity Framework also provides the capability of declaring built-in and user-defined existing database functions.
