## Split View Bar

In Visual Studio 2010, you can simultaneously work with the Design view as well as the XAML view. This is possible because of the split view bar (Figure 9.22) that presents the split view of the WPF Designer. The split view bar has two tabs that correspond to two panes on its left and three buttons on its right. The first tab corresponds to the Design pane and allows you to see the Design view, while the second tab corresponds to the XAML pane and allows you to see the XAML view. There is a button, Swap Panes, between the Design and XAML panes on the split view bar. When you click the Swap Panes button, the Design view and XAML view are swapped with each other, that is, the Design view appears at the bottom and the XAML view appears at the top, as shown in Figure 9.23:

![](img/e073a4882197be4ab61103cbe0bcb394_364_1.png)

Figure 9.23: Swapping the Design View and XAML View

As stated earlier, there are three buttons on the right side of the split view bar. The first button, Vertical Split, allows you to vertically split the XAML view and Design view, as shown in Figure 9.24:

![](img/e073a4882197be4ab61103cbe0bcb394_365_0.png)

### Figure 9.24: Vertical Splitting Between the XAML View and Design View

The second button, Horizontal Split, allows you to see both the Design view and XAML view horizontally. The button is selected by default. The third button, Collapse Pane, allows you to collapse or hide one of the panes. This implies that you can see only one of the panes. For example, in Figure 9.24, if you click the Collapse Pane button, then the Design pane collapses and you get more space for the XAML view, as shown in Figure 9.25:

## Tag Navigator

In the XAML view, the tag navigator allows you to navigate the parent XAML tag or element of the current tag. The tag navigator appears at the bottom of the XAML view. It displays the currently selected tag (in bold) and the hierarchy up to that tag, as shown in Figure 9.26:

![](img/e073a4882197be4ab61103cbe0bcb394_366_0.png)

### Figure 9.26: Using the Tag Navigator

As you can see in Figure 9.26, the Button tag is the currently selected tag in the XAML view. Its name is displayed in bold in the tag navigator. The name of the Button tag is followed by hyperlinks that are separated from each other by a forward slash, that is, Window/Grid/Button, where Window, Grid, and Button are hyperlinks. The hyperlinks represent the parent tags or hierarchy up to the currently selected tag. If you place the mouse over any of the hyperlinks, a thumbnail image is displayed (Figure 9.26). You can click any of the hyperlinks to select that tag. For example, in Figure 9.26, if you click the Grid hyperlink, then the Grid tag is selected. Figure 9.27 shows the selected Grid tag:

![](img/e073a4882197be4ab61103cbe0bcb394_366_1.png)

### Figure 9.27: Displaying Child Tags for the Selected Grid Tag in the Tag Navigator

Note that if the currently selected tag has any child tags, then the Select Child arrow is enabled and when you click the arrow, a list of the child tags appear, as shown in Figure 9.27. You can click a child tag in the list to navigate that tag.

## Properties Window

The Properties window in the WPF 4.0 Designer allows you to view and work with the properties of controls that are present in the Design view. In the Properties window, the names of the properties are listed on the left side, while the values of the properties are listed on the right side. At the very top of the Properties window in WPF Designer, you can see the class name, control name, and thumbnail image of the selected control. For example, you can see the class name (Button), control name (button1), and the image of the Button control in Figure 9.29:

![](img/e073a4882197be4ab61103cbe0bcb394_367_1.png)

### Figure 9.29: Displaying the Properties Window in WPF 4.0 Designer

The Properties window in the WPF Designer also allows you to search for properties that match a sequence of letters. You can do this by typing the initial characters of the property in the Search box of the Properties window and the search results are displayed to you. You can see in Figure 9.30 that as you type tra in the Search box, properties that contain tra in their names are immediately displayed:

## Toolbox

The Toolbox offers several controls that you can use to design the UI of the WPF applications. You can drag the controls from the Toolbox and drop them onto the Design view. You can also drag and drop the controls onto the XAML view. The controls in the Toolbox of WPF Designer have three tabs:

- Common — Contains the controls that are more commonly used in WPF applications.
- Controls — Contains all the WPF controls.
- General — Contains some general controls, such as the Pointer and TreeView controls. Any custom controls that you create are placed under this tab.

> NOTE
> If the Toolbox is not visible, then you can select View→Toolbox from the menu bar or press CTRL+ALT+X from the keyboard.

Let’s now learn about the Document Outline window.

## Document Outline Window

The Document Outline window presents a hierarchical view of the UI of current WPF application. You can use it to select, remove, and navigate through the UI elements of the WPF application. The Document Outline window is not visible in the WPF Designer, by default. You can view the Document Outline window by selecting View→Other Windows→Document Outline from the menu bar or pressing CTRL+ALT+T from the keyboard. In addition, you can view the Document Outline window (shown in Figure 9.31) by right-clicking anywhere in the Design view and selecting Document Outline. Figure 9.31 shows the structure of a WPF application in the Document Outline window:

![](img/e073a4882197be4ab61103cbe0bcb394_368_0.png)

Figure 9.31: Displaying the Structure of a Standalone WPF Application in the Document Outline Window

In Figure 9.31, the Document Outline window displays the outline or structure of the UI of the WPF application in a top-down hierarchy. At the very top of the hierarchy, the root node or element, the Window element, is displayed. The Grid element exists under the Window element under which its child elements appear. The child elements of the Grid element in this case include the RowDefinitions, ColumnDefinitions, Button, and RadioButton elements.
