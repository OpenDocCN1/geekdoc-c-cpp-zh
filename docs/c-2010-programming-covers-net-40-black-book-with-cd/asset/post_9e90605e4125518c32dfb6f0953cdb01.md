
Define a common set of styles for controls and apply them in your application. A WPF style can set any Dependency property and use it to apply non-formatting characteristics, such as the behavior of a control. WPF styles also use templates to define the appearance of a control.

In this section, you learn about:

- Styles used in WPF
- Different types of templates used in WPF

## Styles in WPF 4.0

Styles in WPF allow you to apply a set of properties to more than one element. For example, you can change the style of the TextBlock control by changing its FontSize and FontFamily properties. However, if you want your TextBlock control to share some properties, you can create a common style for them.

You can bind a style to a control by using the Style property. Styles set the initial appearance of an element; however, you can override the characteristics you set in a style. Styles have some advantages over resources. A style allows you to create groups of related settings. It also streamlines your markup by making it easier to apply these settings. The inheritance hierarchy of the Style class is:

```
System.Object
System.Windows.Threading.DispatcherObject
System.Windows.Style
```

You can add the Style class to your WPF application by using the following code snippet:

```
<Style>
    <!-- Setters -->
</Style>
```

Table 10.52 describes the noteworthy properties of the Style class:

**Table 10.52: Showing the Noteworthy Properties of the Style Class**

| Property | Description |
| --- | --- |
| Setters | Sets the property values and attaches event handlers |
| Triggers | Allows you to change a style setting |
| Resources | Gets or sets a collection of resources you can use with your style |
| BasedOn | Creates a specialized style that inherits the settings of another style |
| TargetType | Gets or sets the type for which the style is intended |

If you want to create more specific styles, you can define them using the resources collection of a container control, for example a Grid control or a StackPanel control. If you want to reuse the style across an application, you can define it using the Resources collection of your application. You can set a style on any element that derives from the FrameworkElement or FrameworkContentElement class. A style is most commonly declared as a resource. Style declaration consists of a Style object that contains a collection of one or more Setter objects. Each Setter object consists of the Property and Value properties. You learn to use styles in the Immediate Solutions section of this chapter.

## Templates

Templates in WPF allow you to customize the look and feel of controls. The templates in WPF derive from the FrameworkTemplate base class. There are two types of templates in WPF: ControlTemplate and DataTemplate. The ControlTemplate template is responsible for specifying the visual structure of a control; whereas, the DataTemplate template is responsible for the graphical representation of objects.

## Triggers

The Triggers class defines the kind of style that you want to apply to your controls. They are set conditionally. For example, you can change the background color of a button when you move the mouse over it. Triggers can also inherit properties through derived styles with the BasedOn property. Triggers are linked to styles through the Style.Triggers collection. Every style can have unlimited number of triggers, and each trigger is an instance of a class that derives from the System.Windows.TriggerBase namespace.

You can also apply triggers directly to elements, without needing to create a style, by using the FrameworkElement.Triggers collection. This trigger collection only supports event triggers. The different types of triggers used in WPF are:

- Property triggers
- Event triggers

Let’s look at these in detail in the following sections.

### Property Triggers

The PropertyTrigger trigger reacts when a property value changes. You can attach actions to a PropertyTrigger trigger in two ways. First, you can use the Trigger.EnterActions property to set actions that are performed when the property changes to the value you specify. Secondly, you can use the Trigger.ExitActions property to set actions that are performed when the property changes back to its original value. You learn more about the practical application of the PropertyTrigger trigger in the Immediate Solutions section of this chapter.

### Event Triggers

The major difference between a PropertyTrigger trigger and an EventTrigger trigger is that while a PropertyTrigger trigger waits for a property change to occur, an EventTrigger trigger waits for a specific event to be fired. An EventTrigger trigger requires a series of actions that modify the control with which it is attached. These actions are used to apply an animation. An EventTrigger trigger specifically starts a set of actions based on the occurrence of an event. When you use an EventTrigger trigger, you need to select events that do not interfere with the inherent behavior of a control.

The inheritance hierarchy of the EventTrigger class is as follows:

```
System.Object
  System.Windows.Threading.DispatcherObject
    System.Windows.DependencyObject
      System.Windows.TriggerBase
        System.Windows.EventTrigger
```

You can add an EventTrigger class to a WPF application by using the following code snippet:

```
<EventTrigger>
  <!--Actions-->
</EventTrigger>
```

You learn more about the practical application of the EventTrigger trigger in the Immediate Solutions section of this chapter.

> **NOTE**
> In addition to property and event triggers, there are other types of triggers. The MultiTrigger trigger allows you to set property values based on multiple conditions. You can use the DataTrigger or MultiDataTrigger trigger when the property of a control is data-bound.

## WPF Commands

Commands are an input mechanism in WPF that provides a way for handling input data. Some of the common examples of commands are Cut, Copy, and Paste. The commands in WPF are based on the RoutedCommand and RoutedEvent classes. The major difference between a command and a simple event handler is that commands separate the action from its logic. The simplest way to use a command in WPF is to use the predefined RoutedCommand class from one of the command library classes.

### Command Sources

A command source triggers a command. For example, a Button or a MenuItem control can be a command source. Command sources in WPF implement the ICommandSource interface.

Table 10.55 describes the properties of the ICommandSource interface:

**Table 10.55: Properties of the ICommandSource Interface**

| Property | Description |
| --- | --- |
| Command | Executes when a command source is invoked |
| CommandTarget | Retrieves the Command object on which the command is executed |
| CommandParameter | Passes information to the handlers implementing a command |

The CommandTarget property of an ICommandSource interface is only applicable when the ICommand interface is a RoutedCommand class. For example, if the CommandTarget property is set on an ICommandSource interface and the corresponding command is not a RoutedCommand class, then the command target is ignored.

The WPF classes that implement the ICommandSource interface are ButtonBase, MenuItem, and Hyperlink. These classes invoke a command when they are clicked. The CanExecuteChanged event informs the command source about the ability of a command to execute the current command. The command source queries the current status of the RoutedCommand class by using the CanExecute() method and disables itself, if the command does not execute. Command sources are automatically enabled when the command is available and disabled when the command is not available.

### Command Targets

A command target is an element on which the command is performed. The command source can set the command target. If the command target is not defined, the current control is used for a command target. For example, if the MenuItem control invokes the Paste command in an application that has a TextBox control and a PasswordBox control, the target can be either of the two controls depending on the current control.

### Command Binding

Command binding links a command to the related application logic for a particular area of the UI. Command binding in WPF is represented by the CommandBinding class, which contains the Command properties, such as PreviewExecuted, Executed, and PreviewCanExecute. The CommandBinding class is important because a single command might be used in several places in an application and has a different significance in each place. Therefore, you can use different command bindings for using the commands at different places in the application.

## Interoperability between Windows Forms and a WPF 4.0 Application

Instead of rewriting the design view for WPF, you can use the existing Windows Forms controls within a WPF application, and create new WPF controls to use within a Windows Forms application. To integrate Windows Forms and WPF, you need classes from the System.Windows.Forms.Integration namespace. This namespace contains classes that support interoperation of Windows Forms and WPF controls. When you use the classes of this namespace, you can host Windows Forms controls on WPF pages and WPF elements in Windows Forms based applications.

Table 10.56 describes the classes of the System.Windows.Forms.Integration namespace:

**Table 10.56: Classes of the System.Windows.Forms.Integration Namespace**

| Class | Description |
| --- | --- |
| ChildChangedEventArgs | Provides data for the WindowsFormsHost.ChildChanged and ElementHost.ChildChanged events |
| ElementHost | Hosts a WPF control, which is a Windows Forms control |
