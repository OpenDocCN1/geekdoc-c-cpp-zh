While working in WPF, you can use numerous properties. Most of these properties are dependency properties, although you can access and use them in the same way as the conventional CLR properties. As stated earlier, the dependency properties are implemented as objects of the DependencyProperty class but they are wrapped as a CLR property to facilitate easy and convenient access. You can use the dependency properties in XAML through attributes or property element syntax, as shown in the following code snippet:

```
<Button Height="25" Width="150" Name="button1" Background="Orange">Dependency Property</Button>
```

In the preceding code snippet, the Height, Width, Name, and Background attributes are dependency properties of the Button class. You can also set these properties in the code-behind file, as shown in the following code snippet:

```
Button button1 = new Button();
button1.Height = 25;
button1.Width = 150;
button1.Background = Brushes.Orange;
```

# Precedence of Dependency Property Values

As you know that the value of a dependency property is affected by various factors or inputs. For example, the value of a dependency property can be set through a reference to a style resource, data binding, or from the parent element. This is why it becomes essential to determine which value is actually set for the dependency property. In such a case, the precedence of the dependency properties becomes imperative. Table 9.11 lists the precedence (highest to lowest) for assignment of dependency properties depending on the kind of input:

| Table 9.11: Highest to Lowest Precedence for Dependency Properties |
| Input | Description |
| Property Coercion | Applies the value that is set through the property coercion. |
| Animations | Applies the value that is set through running animations. |
| Local Values | Applies the value that is set directly in XAML or code-behind file. |
| TemplatedParent Element | Applies the value that is set through the Setter property of control or data templates. |
| Styles | Applies the value that is implicitly set through the Style property. |
| Style Triggers | Applies the value that is set through non-default style triggers. |
| Template Triggers | Applies the value that is set through the template triggers. |
| Style Setters | Applies the value that is set through the Setter property of styles. |
