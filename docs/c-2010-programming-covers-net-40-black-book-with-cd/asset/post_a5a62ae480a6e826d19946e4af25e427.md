
# Listing 7.1: Showing the Use of Dynamic Data Type

```
class Program
{
    static dynamic dyn = 1;
    public void Method1(string str)
    {
        Console.WriteLine(str);
    }
    static void Main(string[] args)
    {
        Program p = new Program();
        //This method compiles and runs successfully.
        p.Method1("Hello");
        //This compiles successfully but, shows an error at run time.
        //The value type of dynamic dyn variable is int.
        p.Method1(dyn);
    }
}
```

In Listing 7.1, you can see that the Method1 method does not identify the value type of the dynamic data type at the compile time. The data type of the dyn parameter is int, which is identified at the run time.

## Exploring Dynamic Language Runtime

The DLR adds a set of services, such as expression trees, call site catching, and dynamic object interoperability for integrating dynamic languages, such as Python and Ruby to the CLR. The main advantage of a dynamic language is that it can identify the data type of an object at run time. However, in case of statically-typed languages, such as C# or Visual Basic, data type of an object must be specified at design time; otherwise, the compiler will raise an error.

In Visual Studio 2010, apart from enabling the dynamic languages to run on the .NET Framework, the DLR also provides dynamic features to statically-typed languages to enable their interoperation with dynamic languages. The libraries that support dynamic interoperation can also be created using DLR. This enables the user of these libraries to write simple code for operating with objects and accessing object members. For example, the following code snippet can be used to increment a counter in XML in C#:
obj.SetProperty("Count", ((int)GetProperty("Count")) + 1);

Following code snippet shows an alternative to perform the same operation using DLR:
obj.Count += 1;

Similar to CLR, the DLR is also a part of the .NET Framework whose installation package is provided with Visual Studio 2010. The System.Dynamic and System.Runtime.CompilerServices namespaces hold the classes for DLR.

Let’s briefly discuss the various advantages provided by the DLR.

## Advantages of DLR

You have already learned that DLR allows you to integrate dynamic languages with the CLR. The DLR allows you to develop the dynamic languages by adding the dynamic features to these languages. For example, Microsoft has developed IronRuby and IronPython languages, which are based on the dynamic languages Ruby and Python. The various advantages provided by the DLR are:

- Allows you to easily implement the dynamic languages to the .NET Framework. To use DLR, the language requires to create expression trees, which contain language-level code in a tree-shaped structure, runtime helper routines, and optional dynamic objects that implements the IDynamicMetaObjectProvider interface. The DLR and the .NET Framework together automate huge code analysis and generate code, which helps you to concentrate only on exclusive language features.

- Provides dynamic features to statically-typed languages. The statically-typed .NET Framework languages, such as C# and Visual Basic can create dynamic objects and use them together with statically-typed objects.

For example, C# and Visual Basic can use dynamic objects for .NET reflection HTML and Document Object Model (DOM).

- Improves future aspects of the DLR and the .NET Framework. The languages in which DLR is implemented can be beneficial for the future improvements of the DLR and the .NET Framework. For example, if Microsoft releases a new version of the .NET Framework that has various improved features, such as improved garbage collector or quicker assembly loading time, the DLR using languages immediately get the benefits of these features. Even if the DLR improves compilation or any other optimization, the performance of languages implemented by using the DLR also improves.

- Implements sharing of libraries and objects, which means that the objects and libraries implemented in one language can be used by other languages using DLR. Moreover, the DLR enables interoperability between statically-typed and dynamic languages. For example, C# can create a dynamic object that uses a library which is written in a dynamic language. At the same time, libraries of the .NET Framework can be used by dynamic languages.

- Enables fast execution of dynamic operations by supporting advance caching. The DLR creates rules for accessing operations that use objects at runtime implementations and then caches these rules to restrict resource-exhausting binding computations during successive executions of the same code on the same types of objects.

## Architecture of DLR

The dynamic language compilers are implemented on the top of the DLR and generate the abstract syntax tree, which is used by the DLR library. The DLR provides some services to the CLR such as expression trees, call site caching, and dynamic object interoperability. The DLR represents the language semantics using expression trees, which helps binders to encapsulate a language’s semantics and specify operations performed in a call site. Call sites refer to the area in the code where logical and mathematical operations, such as a + b or a.b() are performed on dynamic objects.

The services provided by DLR to CLR are used for supporting dynamic languages. These services include the following:

- Expression trees—Enables DLR to extend the functionalities of Language Integrated Query (LINQ) expression trees, such as control flow, assignment, and other language-modeling nodes to a dynamic language. These expression trees define the semantics of a language in form of an abstract syntax tree (AST). AST enables the DLR to dynamically generate code, which the CLR executes at runtime.

- **Call site caching**—Enables the DLR to store the information of the operations and characteristics of the variables, such as their data type. The call site caching also checks whether such operations have been performed previously and retrieve all the information about the variable.

- **Dynamic object interoperability**—Enables the DLR to provide a set of classes and interfaces that represent dynamic objects and operations. These classes and interfaces can be used by language developers and authors of dynamic libraries to create classes, which can be used in static and dynamic type languages.

Let’s learn about the ExpandoObject and DynamicObject classes.

## Understanding the ExpandoObject and DynamicObject Classes

DLR is created using the classes and interfaces of the System.Dynamic namespace. This namespace contains classes, such as ExpandoObject and DynamicObject. These classes are used to implement runtime features in C#. The ExpandoObject class is a class whose members can be explicitly added and removed at run time. The object of this class can be initialized dynamically at runtime. In other words, the ExpandoObject class allows dynamic binding of the objects, which enables you to use standard syntax, similar to the dynobj.Method method instead of using more complex syntax, such as dynobj.getAttribute("Method").

The DynamicObject class allows you to define the specific operations that can be performed on dynamic objects as well the methods to perform those operations. For example, you can define the consequence of getting or setting an object property, calling a method, or performing standard mathematical operations, such as addition and multiplication. The DynamicObject class provides a parent class that specifies the dynamic behavior at run time. This parent class cannot be instantiated directly; therefore, to implement the dynamic behavior, it must be inherited from the DynamicObject class and override the necessary methods.
