In some situations, a programmer needs to make sure that certain values remain constant during the lifecycle of an application. For example, for computing any chemical formula, the atomic values of elements should remain constant. C# has two types of fields – Constant and Read-Only – that address this situation. The Constants and Read-Only fields have some similarities, but are different in some aspects.

Constants are associated with classes that are accessible at the compile time. This means that the value of the variable that you define as a constant is calculated at the compile time. The value of a constant, once declared, cannot be changed. You can declare a variable as constant with the const keyword.

The following code snippet shows the use of constants:

```
struct Atomicweight
{
    public const double Gold = 196.9;
    public const double Silver = 107.8;
}
```

In the preceding code snippet, the atomic weights of Gold (196.9) and Silver (107.8) are compile-time constants, as their values always remain the same and do not change at the runtime.

As already discussed, constants are usually declared at the compile time; however, if you want to make a variable constant at the runtime, you can specify the readonly keyword, as shown in the following code snippet:

```
class MyClass
{
    public readonly int Number1=10;
    public readonly int Number2=20;
}
```

In the preceding code snippet, the values of the Number1 and Number2 variables are set to 10 and 20, respectively in the readonly mode.

The read-only fields are also associated with classes or instances of classes. Their values can be set during class declaration. You can declare a variable as read-only with the readonly keyword. Read-only variables are preferred over constants in situations where you want a field to have different values for different objects of the same class with condition that the value of the field should remain the same for the complete life span of a particular object.
