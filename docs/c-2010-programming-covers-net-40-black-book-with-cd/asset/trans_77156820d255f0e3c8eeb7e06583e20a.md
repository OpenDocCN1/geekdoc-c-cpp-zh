## Channels

在 .NET Remoting 中，通道是传输远程对象之间消息的对象。你可以通过调用 ChannelServices 类的方法在程序中实现通道。

ChannelServices 类的类层次结构如下所示：

```
System.Object
System.Runtime.Remoting.Channels.ChannelServices
```

你可以在表 35.7 中找到 ChannelServices 类值得注意的公共属性：

Table 35.7: ChannelServices 类值得注意的公共属性

| Property | Description |
|---|---|
| RegisteredChannels | 获取当前已注册通道的列表 |

表 35.8 描述了 ChannelServices 类的公共方法：

Table 35.8: ChannelServices 类值得注意的公共方法

| Method | Description |
|---|---|
| AsyncDispatchMessage() | 异步将给定的消息分派到服务器 |
| CreateServerChannelSinkChain() | 为指定的通道生成通道 sink 链 |
| DispatchMessage() | 分派传入的远程调用 |
| GetChannel | 返回具有指定名称的已注册通道 |
| GetChannelSinkProperties() | 返回给定代理的属性的 IDictionary 对象 |
| GetUrlsForObject() | 返回可用于访问指定对象的所有 URL 的数组 |
| RegisterChannel() | 将通道向通道服务注册 |
| SyncDispatchMessage() | 同步将传入消息分派到服务器端链 |
| UnregisterChannel() | 从已注册通道列表中注销特定通道 |

.NET Remoting 架构确保在远程系统上注册对象之前至少应注册一个通道。此外，客户端对象必须指定一个通道以与远程对象通信。然后，已注册的通道会自动开始在远程系统上的指定端口监听客户端请求。

通道在远程对象的意义上是独立的，因为它们充当客户端 AppDomain 与服务器 AppDomain 之间的隧道。例如，如果服务器的 AppDomain 注册一个通道来发布远程对象，并注册另一个通道来发布另一个远程对象；那么客户端可以使用任何一个通道访问这些对象中的任何一个。然而，这些对象无法从另一个 AppDomain 注册的通道访问。

即使通道在不同机器上注册，它们也特定于它们被注册的应用域。因此，如果通道已注册到一台机器，但未注册到该机器上的客户端 AppDomain，则该通道无法公开对象。由于通道是 AppDomain 指定的，因此一旦 AppDomain 被销毁，通道就会被销毁。此外，只能注册一个特定类型的通道在计算机上监听特定地址和端口，尽管两个或多个不同通道可以注册以监听同一地址和端口。通道有以下类型：

- TCP
- HTTP
- IPC

让我们逐一详细讨论这些。

## The TCP Channel

TCP 通道是一个基于套接字的传输通道，使用 TCP 协议在边界之间传输序列化消息流。它使用 TcpChannel 类来设置 Remoting 服务器及其客户端。TcpChannel 类在 System.Runtime.Remoting.Channels.Tcp 命名空间中定义，并实现了 IChannel、IChannelSender 和 IChannelReceiver 接口，这意味着 TcpChannel 类支持在 .NET Remoting 边界之间发送和接收数据。默认情况下，TcpChannel 类使用二进制格式化程序序列化消息；然而，它也可以使用 SOAP 格式化程序。

TcpChannel 类的类层次结构如下所示：

```
System.Object
  System.Runtime.Remoting.Channels.Tcp.TcpChannel
```

## The HTTP Channel

HTTP 通道使用 HTTP 协议在 Internet 上传输消息。你可以使用 HttpChannel 类为对客户端的远程调用指定 HTTP 通道。由于防火墙通常不会阻止 HTTP 通信，因此该类可以在 Internet 上使用。HttpChannel 类在 System.Runtime.Remoting.Channels.Http 命名空间中定义并实现了 HTTP 传输功能。与 TcpChannel 类类似，HttpChannel 类也可以在边界之间发送和接收消息。默认情况下，HttpChannel 类使用 SOAP 格式化程序序列化消息；然而，它也可以使用二进制格式化程序。HttpChannel 类的类层次结构如下所示：

## The IPC Channel

进程间通信（IPC）通道使用 IpcChannel 类实现一个使用 IPC 协议传输消息的通道。IpcChannel 类比 HttpChannel 和 TcpChannel 类快得多，因为它绕过了传统的网络通信来跨越 AppDomain。因此，IpcChannel 只能用于同一台计算机上应用域之间的通信。此外，你不能使用 IpcChannel 类构建跨多个物理计算机的分布式应用程序。IpcChannel 类在 System.Runtime.Remoting.Channels.Ipc 命名空间中定义并实现了 IpcClientChannel 和 IpcServerChannel 类的功能。它也可以在边界之间发送和接收消息。
