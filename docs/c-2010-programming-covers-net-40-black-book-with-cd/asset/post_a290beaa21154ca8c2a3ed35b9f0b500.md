# Configuring Codebase Settings Manually

You can apply the codebase setting to the configuration file (ASimpleClient.exe.config) of your application by adding the highlighted code, as shown in Listing 33.16:

Listing 33.16: Setting the Code of the ASimpleClient.exe.config File

```
<?xml version="1.0"?>
<configuration>
<runtime>
<assemblyBinding xmlns="urn:schemas-microsoft-com:asm.v1">
<dependentAssembly>
<assemblyIdentity name="SharedObject" publicKeyToken="001fe4f7b2c7f625" />
<publisherPolicy apply="yes" />
<bindingRedirect oldversion="1.0.0.0" newversion="1.1.0.0" />
<codeBase version="1.1.0.0" href="file:///E:/NewGAC/SharedObject.dll" />
</dependentAssembly>
</assemblyBinding>
</runtime>
</configuration>
```

You can notice that the assemblyIdentity node specifies the public token to identify the assembly. However, note that the public token contains various numbers and alphabets, which can be entered incorrectly while entering it manually.

You can also add the codebase settings in your application to look up the older version of the assembly in E:\AnotherGAC by adding the second highlighted line in the configuration file, as shown in Listing 33.17:

```

<runtime>
<assemblyBinding xmlns="urn:schemas-microsoft-com:asm.v1">
<dependentAssembly>
```


# Configuring CodeBase Settings for Unsigned Assemblies

The codebase settings for unsigned assemblies can be configured in exactly the way as you configure them for signed assemblies. The only difference is that they do not require assembly’s public key token (as it does not have one because it is not signed); while the version of the assembly is mentioned in the settings.

# Creating Publisher Policies

As discussed in the In Depth section, publisher policies are used to redirect the clients of an assembly to the newer version of the configuration file without recompiling the assembly. The publisher policy file specifies assembly redirection and code base settings, and uses the same format as an application configuration file. The publisher policy file is then compiled into an assembly and placed in the GAC.

Let’s use the SharedObject and ASimpleClient applications to learn about creating the publisher policy files. Perform the following steps to create the publisher policy files:

- 1. Copy the ASimpleClient.exe.config file in the forlder of the SharedObject application.
- 2. Rename the ASimpleClient.exe.config file to PubPol.config.
- 3. Open Visual Studio Command Prompt (2010) navigates to the folder of the SharedObject application and type the following command:
- al /link:PubPol.config /out:policy.1.0.sharedobject.dll /keyfile:Akey.snk
- 4. Copy the ASimpleClient.exe file to a location other than the bin\Debug directory of the application.

In the preceding command, al is the assembly linker utility that uses configuration settings of the PubPol.config file and creates a publisher policy assembly named policy.1.0.sharedobject.dll.

Now, you can install the policy assembly in the GAC using the .NET Framework 2.0 Configuration tool.

Now, when you run the ASimpleClient.exe file, you notice that the file uses the new version of the SharedObject.
