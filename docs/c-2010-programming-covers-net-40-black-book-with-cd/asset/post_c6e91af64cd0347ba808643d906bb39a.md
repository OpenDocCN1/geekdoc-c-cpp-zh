## The Core Presentation Framework

The core presentation framework is a component in Silverlight that offers the features and services for designing the UI of Silverlight applications through controls, styles, templates, 2-D vector graphics, animations, and multimedia. This component also allows you to incorporate user input and interactivity through various input devices, such as mouse and keyboard. It also allows you to bind data with various controls, and specify the UI layout of the Silverlight applications. Moreover, you can also manage the digital rights of the multimedia content used in your Silverlight applications through this component. The XAML parser for processing the XAML content in Silverlight applications is also provided by the core presentation framework.

Now, you are aware of what Silverlight is and that it is a robust and cohesive platform for developing interactive and rich Internet applications. Next, let's move ahead to learn about developing Silverlight applications with Visual Studio 2010.

## Silverlight Applications in Visual Studio 2010

You can create Silverlight applications by using a text editor, such as Notepad. However, various tools, such as Visual Studio 2010, Expression Studio, and ComponentOne Studio, provide an efficient and quick means of creating Silverlight applications as these tools include the essential files and functionality by default. Among these tools, Visual Studio 2010 is an ideal choice for both designers and developers of Silverlight based applications. Note that Silverlight facilitates .NET designers and developers to effortlessly coordinate with each other to build strikingly attractive and compelling Web applications.

Using the Visual Studio 2010 IDE, you can easily create Silverlight 3.0 applications. In Visual Studio 2010, when you select File→New→Project from the menu bar, notice that the templates to create Silverlight 3.0 applications are already available. However, if you try to create a Silverlight application, you get an error saying that the Silverlight developer runtime is not installed on your system. To create Silverlight 3.0 applications, you need to install the Silverlight 3 SDK and the Silverlight 3 developer runtime. You can get the Silverlight 3 SDK from http://www.microsoft.com/downloads/details.aspx?displaylang=en&FamilyID=d09b6ecf-9a45-4d99-b752-2a330a937bc4 and the Silverlight 3 developer runtime from http://go.microsoft.com/fwlink/?LinkID=143433.

> NOTE
> If you use Visual Studio 2010 to develop Silverlight 3.0 applications then you can just drag and drop the Silverlight controls from Toolbox to the Silverlight application interface as you do while creating Windows, WPF, or ASP.NET Web applications.

After you have installed the Silverlight 3 SDK and Silverlight 3 developer runtime, open Visual Studio and select File→New→Project from the menu bar. The New Project dialog box will appear. ## Assemblies and Files in Silverlight Applications

When you use Visual Studio 2010 to create Silverlight 3.0 applications, some essential assembly references and files automatically become a part of the application. The assemblies that are referenced in a Silverlight 3.0 application are as follows:

- mscorlib.dll
- System.dll
- System.Core.dll
- System.Windows.dll
- System.Windows.Browser.dll
- System.Windows.Controls.dll
- System.Net.dll
- System.Xml.dll

Among these assemblies, mscorlib.dll, System.dll, and System.Windows.dll are essential assemblies for Silverlight 3.0 applications. The rest of the assemblies are added to handle certain common functionalities, such as working with the Web browser and XML content. You can add references to other assemblies from the Add Reference dialog box that appears when you right-click the name of a Silverlight application in Solution Explorer and select the Add Reference option from the context menu that appears.

The Visual Studio 2010 integrated development environment (IDE) automatically includes a few files, such as the App.xaml and MainPage.xaml, in a newly created Silverlight 3.0 application, as shown in Figure 17.5:

![](img/e073a4882197be4ab61103cbe0bcb394_873_0.png)

## Figure 17.5: Showing the Files that Constitute a Silverlight 3.0 Application

As shown in Figure 17.5, the files which are automatically included in a Silverlight application are as follows:

- App.xaml — Refers to the XAML file in which you can define application-level resources, such as brush and style objects, which apply to an entire application.
- App.xaml.cs — Refers to the code-behind class for the App.xaml file. The App.xaml.cs file can be used to handle application level events, such as Application_Startup, Application_Exit, and Application_UnhandledException.
- MainPage.xaml — Refers to the XAML file, which is used to define a page, similar to a page in a Web site. The MainPage.xaml file is by default the initial UI control, which is loaded when an application activates. You can use UI controls, such as Button, Label, and TextBox controls, inside the MainPage.xaml file to define the UI of a Silverlight application.
- MainPage.xaml.cs — Refers to the code-behind class for the MainPage.xaml file in which you can write the managed code for a Silverlight application.

An ASP.NET Web application project that you select to host a Silverlight application is automatically created by Visual Studio 2010. This Web application contains HTML and ASP.NET test host pages and a JavaScript helper file that are automatically added to it. You can run and test your Silverlight applications using either the HTML or the ASP.NET test page. You can view the references to some of those files in Solution Explorer, as shown in Figure 17.6.
