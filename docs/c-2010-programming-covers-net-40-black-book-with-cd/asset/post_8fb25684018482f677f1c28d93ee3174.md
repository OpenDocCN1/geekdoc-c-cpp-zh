```
public static int tele_no;
```

In the preceding code snippet, employee is the static class and id and tele_no are its members. A class that is static indicates that its members are also static. You cannot instantiate a static class using the new keyword. .NET Framework's CLR loads the static classes automatically when the program or namespace, which contains the static classes, is loaded.

Static class does not contain instance constructors, which are used to create and initialize instances. Static classes are sealed, which means that you cannot inherit these classes. You can declare a static class member using the static keyword, as shown in the following code snippet:

```
public static class student
{
    public static int roll_no = 4;
    public static int rank;
}
```

The preceding code snippet shows a student class, which is not static. However, the members of this class, roll_no and rank, are static. These static class members are initialized before they are accessed for the first time or before the static constructor is called.

## Properties

In C#, a property is a member that provides a flexible mechanism to read, write, or compute the value of a private field. C# is one of the first languages to offer direct support for properties. C++ Builder and Delphi languages offered this feature as an extension to the languages they supported (C++ and Object Pascal).

To the users of a class, a property looks similar to a public variable on which they can perform the get or set operations. The following code snippet shows how to use a property:

```
// Set the color property
Foo.Color = Color.white;
// Get the color property
Color c = Foo.Color;
```

However, you can implement properties with the type-safe get and set methods. You can create a property by defining an externally available name and then writing the set and get methods. Depending upon the input of the caller of the property, you can decide whether to allow the user to modify the property or not.

The following code snippet shows you the general syntax used for writing a property:

```
// Define the property accessors
public <type> <PropertyName> {
    get
    {
        return <var>;
    }
    set
    {
        // validate the input, found in value
        if ( Isvalid(value) )
```
```
<var> = value;
}
```

In the preceding code snippet, the important thing to note is the value keyword. The value type is of the same type as that of the property itself and you can find it in the public <type> <PropertyName> line. In this line, you are defining the name of the property and the type of the property. Note that you need not have the same type of property as the internal member variable (denoted in the preceding listing by <var>). You can make any conversions in the set and get functions to pass the value into the accessors in a particular format.

A property allows the accessibility of the accessors and also allows you to create a read-only property using Anonymous types.

Let’s first discuss about the accessibility of accessors in detail.

### Accessibility of Accessors

In C#, accessors are the get and set sections of a property. The accessibility of an accessor represents its ability to access the members of a property. The following code snippet shows how to declare an accessor in a property in a class:

```
class MyProperty
{
private string name="Sumit";
public string Name
{
get{return name;}
set{name=value;}
}
}
```

In the preceding code snippet, the get and set accessors have the same accessibility level. This means that both these accessors are public because the property itself is public. In C# 1.1, you cannot change the accessibility level of the get and set accessors separately. However, in C# 2.0 and higher versions, you can specify the accessibility levels of these accessors in a property separately, as shown in the following code snippet:

```
class MyProperty
{
private string name="Sumit";
public string Name
{
get{return name;}
protected set{name=value;}
}
}
```

In the preceding code snippet, as the property named Name itself is public, the get accessor is also public because it is not explicitly marked with any accessor modifier. However, the set accessor is explicitly marked with the protected access modifier. Hence, you can use the get method throughout the program, whereas you can use the set method only inside the same class or a sub-class of the source class. This approach is known as assymetric accessor accessibility.

Now, let’s discuss about the Anonymous types.

### Anonymous Types

Anonymous types provide a way to encapsulate the read-only properties of an object without having to first explicitly define a type. The compiler generates the type name as required but this type name is not available at the source code level. The compiler derives the properties type to generate the type name. In other words anonymous types create unnamed structure types that you can add to the collections and access those structures types using the var keyword.

Anonymous types are the class types that consist of one or more public read-only properties. No other kinds of class members, such as methods or events are allowed. You can use the new keyword with an object initializer to create an anonymous type.

Anonymous types are reference types that are derived directly from the object. If two or more anonymous types have the same number and type of properties in the same order, the compiler treats them as the same type and they share the same compiler-generated type information.

## Indexers

Indexer is a new concept introduced by C#. Indexers allow you to use a class as an array and enable an object to access the members of a class using an index notation. In other words, they provide an index to obtain the values that are stored in an object. The following code snippet shows the syntax for declaring an indexer:

```
<access modifier> <Return Type> this [argument list]
{
    get
    { // code for get }
    set
    { //code for set }
}
```

In the syntax shown in the preceding code snippet:

- The access modifier can be Private, Public, Protected, or Internal.
- Return type can be any valid C# data type, such as a string or integer.
- The this keyword shows that the object is of the current class.
- The argument list specifies the parameters of the indexer. C# indexers must have at least one parameter; otherwise, the compiler gives an error. Indexers in C# allow you to have multiple parameters and each parameter can be of a different type. You can separate these parameters by putting commas between them. Parameter types for indexers can be int, enum, or string. Such a parameter list defines the signature of an indexer. Signatures comprise the number, type, and order of parameter of formal parameters in an indexer and, hence, they help to identify an indexer uniquely. All indexers in the same class should have different signatures.
- The get and set portions of the syntax are known as accessors. The visibility or access level for these accessors is the same as that of the indexer to which they belong. However, you can restrict the visibility of the set accessor by setting its access modifier to either: protected, public, private, or internal protected. The get and set accessor's body is similar to the method body.

The following code snippet shows an example of an indexer:

```
class Employee
{
    private string[] names;
    public Employee()
    {
        this.names = new string[8];
    }
    public string this[int i]
    {
        get
        {
            return this.names[i];
        }
        set
        {
            this.names[i] = value;
        }
    }
}
```

In the preceding code snippet, the [] operator is used to access an indexer. Indexers are implemented in the same way as properties.

Indexers have the following additional features:

- Inheritance — Allows inheritance, which means a derived class can inherit a base class indexer. However, modifiers such as virtual and override are used at the property level, not at the accessor level.
