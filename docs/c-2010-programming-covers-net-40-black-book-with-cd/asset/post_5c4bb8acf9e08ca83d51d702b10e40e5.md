
## Section I – Introduction to .NET

.NET Framework is an internal Windows component that supports the execution of applications created by using various programming languages, such as Visual C#, Visual Basic, Visual F#, and Visual C++. These programming languages are a part of Visual Studio .NET. The .NET Framework consists of a virtual execution system called the common language runtime (CLR) and a set of class libraries. CLR is a Microsoft product of the common language infrastructure (CLI), which is an international standard and a basis for creating execution and development environments in which languages and libraries work together.

Microsoft introduced .NET to bridge the gap and ensure interoperability between applications created in different languages. .NET Framework is used to integrate the business logic of an application implemented in various programming languages and services. Consequently, it induces significant improvements in code reusability, code specialization, resource management, development of applications in multiple programming languages, security, deployment, and administration of programs developed in multiple programming languages.

Since this book is on the C# language, let’s explore the relationship between C# and .NET Framework. C#, as we know, is a programming language designed to build a variety of applications (such as Windows Forms and Web) that run on .NET Framework. It is a simple, type-safe, and object-oriented language. You can use C# to create traditional Windows client applications, distributed components, client-server Web applications, and database applications. In addition, C# 2010 provides an advanced code editor, user interface designers, integrated debugger, and many other tools to make it easier to develop applications based on latest versions of the .NET Framework.

This chapter is divided into four sections, discussing .NET Framework, installation of Visual Studio 2010, features of Visual Studio 2010 integrated development environment (IDE), and C# 2010 related technologies. The chapter also provides the snapshots of .NET-related technologies discussed in various chapters of this book. Now, let’s start with discussing the evolution of .NET.

## Evolution of .NET

Around 1995, Java was gaining popularity because of its platform-independent approach and Sun Microsystems’s open source policy. Later in 2002, Sun Microsystems released the enterprise edition of Java, i.e. Java 2 Enterprise Edition (J2EE), which is a Java Platform to develop and execute distributed Java applications based on the N-tier architecture. The advent of J2EE eventually led to the decline of Microsoft’s market share. Consequently, Microsoft started a project called Next Generation Windows Services (NGWS) to regain the market share. It took more than three years to develop the product, which is now known as .NET.

The first version of .NET is released with the name of .NET Framework 1.0 on February 13, 2002 along with the Visual Studio .NET 2002 IDE. .NET’s second revised version took nearly a year to release and was known as .NET Framework 1.1. Microsoft Visual Studio .NET, better known as Visual Studio .NET 2003, was also a part of the second release. The next version of .NET Framework, .NET Framework 2.0, was released with Visual Studio .NET 2005 on November 07, 2005. After that, .NET Framework 3.0 was released on November 06, 2006 and .NET Framework 3.5 was released on November 19, 2007. Finally, the latest version of .NET Framework, known as .NET Framework 4.0, was released with Visual Studio .NET 2010 on April 12, 2010.

The following are some of the benefits of .NET Framework:

- Consistent programming model – Provides a consistent object-oriented programming model for different languages to perform various tasks, such as connecting to and retrieving data from databases, and reading from and writing to files.
- Cross-platform support – Enables interoperability between multiple Windows operating systems.
- Language interoperability – Enables codes written in different languages to interact with each other. For example, you can inherit a class developed in C# in the Visual Basic environment and vice versa.
- Automatic management of resource – Automates the management of the application resources, such as files, memory, or network and database connections.
- Ease of deployment – Provides easy deployment of applications. In most cases, to install an application, you need to copy the application, along with its components, on the target computer. .NET Framework provides the deployment of .NET applications in the form of assemblies, so that registry entries are not required to store information about components and applications.

## CLR

One of the most important components of .NET Framework is the CLR, better known as the runtime. It provides functionalities, such as memory management, exception handling, debugging, security, thread execution, code execution, code safety, verification, and compilation. CLR can host a variety of languages and ensures interoperability between their code. CLR also supports services that the application uses to access various resources, such as collections, arrays, and operating system folders. The runtime automatically releases the resources when they are no longer in use. This automatic memory management resolves the issue of memory leaks and invalid memory references.

The runtime imposes code access security (CAS) on the code of an application. CAS is the security system of CLR that prevents unauthorized access to use resources and operations. CAS also helps in making the code robust, i.e. it makes the code extensible and reusable.

Let’s now explore managed code, unmanaged code, and memory management in CLR.

## Managed and Unmanaged Code

Managed code is the code that is executed directly by the CLR. Therefore, the applications that are created using managed code automatically have CLR services, such as type checking, security, and automatic garbage collection. These services help to provide platform and language independence for managed code applications. The CLR compiles the applications to Intermediate Language (IL) code and not the machine code. This IL code along with the metadata that describes the attributes, classes, and methods of the code resides in an assembly.

CLR performs the following steps to execute a piece of managed code:

- 1. **Selecting a language compiler** — Refers to the process of selecting a compiler on the basis of the programming language in which the application is created.
- 2. **Compiling the code to IL code** — Refers to the process of converting the source code into IL code, which is CPU-independent. When you compile your source code into the IL code, the required metadata is generated. The metadata contains the definition of types, member signature, the members in the code, and other details that the code uses at the time of execution. The runtime locates and extracts the metadata from the file, during the execution of an application’s code.
- 3. **Compiling IL code to native code** — Refers to the process of converting the IL code into the native or the machine code by the Just-in-time (JIT) compiler. After compiling, the code is passed through a verification process that examines the IL code and metadata to check whether the code is type safe or not, i.e. the code should be able to access only those memory locations which it is authorized to access.
- 4. **Executing the code** — Refers to the process of executing the machine code.

### NOTE

> The CLR also supports another method of compilation named install-time code generation. This method is used to convert the IL code into native code in a single shot by taking larger units of code at a time.

The CLR provides a safe environment for the compilation and execution of the code. This process of compilation and execution of the code is repeated by the JIT compiler also, until the execution is complete. Throughout the execution of the code, the managed code receives services, such as garbage collection, security, interoperability with unmanaged code, cross-language debugging support, and enhanced deployment and versioning support.
