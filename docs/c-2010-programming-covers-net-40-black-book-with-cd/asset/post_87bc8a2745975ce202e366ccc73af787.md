While working in WPF, you can use numerous properties. Most of these properties are dependency properties, although you can access and use them in the same way as the conventional CLR properties. As stated earlier, the dependency properties are implemented as objects of the DependencyProperty class but they are wrapped as a CLR property to facilitate easy and convenient access. You can use the dependency properties in XAML through attributes or property element syntax, as shown in the following code snippet:

```xml
<Button Height="25" Width="150" Name="button1" Background="Orange">Dependency Property</Button>
```

In the preceding code snippet, the Height, Width, Name, and Background attributes are dependency properties of the Button class. You can also set these properties in the code-behind file, as shown in the following code snippet:

```csharp
Button button1 = new Button();
button1.Height = 25;
button1.Width = 150;
button1.Background = Brushes.Orange;
```

## Precedence of Dependency Property Values

As you know that the value of a dependency property is affected by various factors or inputs. For example, the value of a dependency property can be set through a reference to a style resource, data binding, or from the parent element. This is why it becomes essential to determine which value is actually set for the dependency property. In such a case, the precedence of the dependency properties becomes imperative. Table 9.11 lists the precedence (highest to lowest) for assignment of dependency properties depending on the kind of input:

**Table 9.11: Highest to Lowest Precedence for Dependency Properties**

| Input | Description |
| --- | --- |
| Property Coercion | Applies the value that is set through the property coercion. |
| Animations | Applies the value that is set through running animations. |
| Local Values | Applies the value that is set directly in XAML or code-behind file. |
| TemplatedParent Element | Applies the value that is set through the Setter property of control or data templates. |
| Styles | Applies the value that is implicitly set through the Style property. |
| Style Triggers | Applies the value that is set through non-default style triggers. |
| Template Triggers | Applies the value that is set through the template triggers. |
| Style Setters | Applies the value that is set through the Setter property of styles. |
| Theme Styles | Applies the value that is set through the default theme styles. In the default styles, values set through triggers have higher precedence than those set through the Setter property of the default style. |
| Inherited Values | Applies the value that is set through the property value inheritance, that is, the value is inherited from the parent element. |
| Values from Metadata | Applies the value that is set through the property metadata of the dependency property. |

Let’s take an example to demonstrate how the precedence of values of a dependency property works. Consider the code given in Listing 9.5:

## Listing 9.5: Demonstrating the Precedence of Dependency Property Values

```xml
<Window x:Class="PrecedenceDependencyProperty.MainWindow"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    Title="MainWindow" Height="300" Width="300">
    <Window.Resources>
        <Style TargetType="Button">
            <Setter Property="Background" Value="Green"/>
            <Style.Triggers>
                <Trigger Property="IsMouseOver" Value="True">
                    <Setter Property="Background" Value="Red"/>
                </Trigger>
            </Style.Triggers>
        </Style>
    </Window.Resources>
    <Grid>
        <Button Name="button1" Height="25" Margin="50" Content="Button1" Background="Orange" VerticalAlignment="Top"/>
        <Button Name="button2" Height="50" Margin="20" Content="Button2" VerticalAlignment="Center"/>
    </Grid>
</Window>
```

In Listing 9.5, you can see the XAML code for a standalone WPF application named PrecedenceDependencyProperty. The window of the application has a style resource that applies on all the buttons in the application. In the style resource, the dependency property Background of the buttons is set to Green. The style resource also has a trigger that causes the Background property to be set to Red whenever you place the mouse over a button.

As you can see from Listing 9.5, the grid has two buttons named button1 and button2. The Background property of button1 is set to Orange. Since a locally set value has higher precedence than style resources; therefore, the Background property of button1 is Orange and not Green. However, button2 does not have the Background property directly set as a local value; therefore, it takes Green as its effective value. In addition, when you place the mouse over button2, the Background property of button2 is set to Red. This is because the style trigger that is defined in the style resource has higher precedence than the style setter (to set Background=Green).

## Property Value Inheritance

As you know, the elements in WPF applications are treated as nodes in a hierarchical tree with one element nested inside another. In most cases, properties of an element are available to its child elements also. Now, suppose you have to set the value of a dependency property on an element and want this value to be applicable to the child elements too. In such a case, you need to enable property value inheritance that refers to the process where an element inherits the value of a dependency property registered on its parent element. Property value inheritance is not enabled in WPF, by default. However, to enable property value inheritance, you need to change the property metadata. You learn about property metadata later in the chapter.

## Dependency Property Validation and Coercion Callbacks

WPF also offers validation callbacks that validate the value of the dependency properties. The validation callback can be called when the value of the dependency property is programmatically changed and the property metadata is overridden. Validation callbacks are suitable for checking if a particular value is within a particular range.

Validation callbacks are static methods that take a single object as its argument and return a Boolean value, which indicates the validity of the value. If the value is valid and acceptable to the dependency property, then true is returned; else false is returned. In case false is returned by the validation callback, an exception occurs. The ValidateValueCallback delegate takes the parameter of the validation callback, which denotes a validation callback for a dependency property. This delegate is, itself, provided as an argument when the dependency property is registered. The syntax of the validation callback method is as follows:

```csharp
public static type validationCallbackMethod(object value)
{
    //validation logic
}
```

In the preceding syntax:

- `public`, `static`, `object`—Represents C# keywords
- `type`—Represents the type of the dependency property
- `validationCallbackMethod`—Represents the name of the validation callback method that is passed as an argument to the ValidateValueCallback delegate
- `value`—Represents the value that is to be validated

You can also coerce the values of the dependency properties to a particular value or a range of values through the coerce callbacks. You may also want that the value of a dependency property changes depending on the changes in some other properties. In such a case, you can use a property change callback along with the coercion callback. The coercion and changes in the dependency properties are implemented as static methods that are passed as arguments to the CoerceValueCallback and PropertyChangedCallback delegates, respectively, at the time of specifying the property metadata. Note that if the proposed value for coercion is not acceptable by the dependency property, then the callback method returns a special value called UnsetValue. In such a case, the proposed value is discarded and the property is set back to the original value.

The syntax of the coerce value callback method is as follows:

```csharp
private static object coerceCallbackMethod(DependencyObject dObject, object value)
{
    //coercion logic
}
```

In the preceding syntax:

- `private`, `static`, `object`, `DependencyObject`—Represents the C# keywords
- `coerceCallbackMethod`—Represents the name of the coercion callback method that is passed as an argument to the CoerceValueCallback delegate
- `dObject`—Represents the owner of the dependency property
- `value`—Represents the value that is to be validated and then coerced

The syntax of the property changed callback method is as follows:

```csharp
private static void propertyChangedMethod(DependencyObject dObject,
    DependencyPropertyChangedEventArgs eArgs)
{
    //property changed logic
}
```
