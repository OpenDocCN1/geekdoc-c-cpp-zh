
In the preceding syntax:

- private, static, void, DependencyObject, DependencyPropertyChangedEventArgs – Represents the C# keywords
- propertyChangedMethod – Represents the name of the method that is passed as an argument to the PropertyChangedCallback delegate
- dObject – Represents the owner of the dependency property

> NOTE
> The coerce value and property changed callbacks belong to the property metadata; however, the validation callback is not contained in the property metadata.

Now, let’s discuss about dependency property metadata.

# Dependency Property Metadata

Every dependency property has a metadata that refers to an object containing a lot of information about the dependency property. The dependency property metadata can include the default value of the dependency property and reference to coerce and property changed callbacks. You can access the metadata to retrieve or change the information about the dependency property. The dependency property metadata is useful when you want to change the value of an existing dependency property without re-implementing the dependency property or creating a new dependency property. You can change or override the metadata of a dependency property in the derived classes of the owner of the dependency property.

The dependency property metadata is implemented through the PropertyMetadata class. The PropertyMetadata class has a derived class called UIPropertyMetadata, which itself is inherited by the FrameworkPropertyMetadata class. The FrameworkPropertyMetadata class is the class that is mainly used to work with the property metadata for the dependency properties. The FrameworkPropertyMetadata class has several Boolean properties that influence various metadata options of dependency properties. Table 9.12 lists some of the noteworthy properties of the FrameworkPropertyMetadata class:

| Table 9.12: Noteworthy Properties of the FrameworkPropertyMetadata Class |
| Property | Description |
| AffectsArrange | Allows you to specify if the dependency property influences the arrange pass of the element. The arrange pass of an element means how much space is provided to the element and ask it to fall into line. This property is of Boolean type and can be set to true or false. |
| AffectsMeasure | Allows you to specify if the dependency property influences the measure pass of the element. The measure pass of an element means to determine the space that the element needs to use for displaying purpose. This property is of Boolean type and can be set to true or false. |
| AffectsParentArrange | Allows you to specify if the dependency property influences the arrange pass of its parent element. This property is of Boolean type and can be set to true or false. |

| BindsTwoWaysByDefault | Allows you to specify whether two-way data binding is the default binding for a dependency property. This property is of Boolean type and can be set to true or false. |
| CoerceValueCallback | Sets or retrieves the coerce value callback method that is used to coerce values on a dependency property. |

# Custom Dependency Properties

Even though WPF has a whole gamut of dependency properties that is exposed through different WPF classes, you may need to create your own dependency properties, known as custom dependency properties. You can implement any kind of WPF functionality to create custom dependency properties. For example, you can create dependency properties if you want to use animations, styles, and data binding on the property.

Note that you can create a dependency property only for a class that directly or indirectly inherits the DependencyObject class. The DependencyProperty class is then instantiated to create a dependency property identifier (name of the dependency property). The dependency property then needs to be registered with the WPF property system using the Register() method of the DependencyProperty class. While registering the dependency property with the WPF property system, you can specify its property metadata and the validation, coerce value, and property changed callbacks.

After registering the dependency property, it is wrapped with a CLR property that uses the GetValue() and SetValue() public methods. Note that although the dependency properties are accessed as traditional CLR properties in both XAML and code-behind file, you can also directly access the GetValue() and SetValue() methods in the code-behind file.

Now, let’s create a standalone WPF application named SquareBoxDependencyProperty (also available in CD) to demonstrate a custom dependency property. In the code-behind file (MainWindow.xaml.cs), add the following code snippet in the SquareBoxDependencyProperty namespace:

```
public partial class Box : UIElement
{
    public static readonly DependencyProperty BoxHeightProperty;
    public static readonly DependencyProperty BoxWidthProperty;
    public static readonly DependencyProperty IsSquareProperty;
}
```

In the preceding code snippet, a partial class named Box is derived from the UIElement, which inherits the DependencyObject class. In the Box class, three static read-only fields named BoxHeightProperty, BoxWidthProperty, and IsSquareProperty of DependencyProperty type are declared. Note that all three fields are suffixed with the word Property. It is essential to suffix the DependencyProperty fields with the Property word.

If you want to provide validation and coercion on the values of the dependency properties of the Box class, then you need to include the validation and coercion callbacks. The following code snippet shows how to use the validation and coercion in the Box class:

```
public static void IsSquareBoxTrue(DependencyObject myObject, DependencyPropertyChangedEventArgs myObjectArgs)
{
    myObject.CoerceValue(BoxHeightProperty);
    myObject.CoerceValue(BoxWidthProperty);
}
public static object myBoxHeightWidthSquare(DependencyObject myObject, object myValue)
{
    Box box1 = (Box)myObject;
    Boolean square = (Boolean)myValue;
    if (square == true)
        if (box1.BoxHeight > box1.BoxWidth)
            box1.BoxHeight = box1.BoxWidth;
        else
            box1.BoxWidth = box1.BoxHeight;
        return true;
}
public static Boolean IsValidHeight(object height)
{
    if ((int)height <= 0)
        return false;
    else
        return true;
}
public static Boolean IsValidWidth(object width)
{
    if ((int)width <= 0)
        return false;
    else
        return true;
}
```

In the preceding code snippet, the IsSquareBoxTrue() method is the property change callback that has two parameters. The first parameter is of DependencyObject type that refers to an object of the class containing the dependency properties. The second parameter is of DependencyPropertyChangedEventArgs. In the IsSquareBoxTrue method, there are two calls to the CoerceValue() method for BoxHeightProperty and BoxWidthProperty. The CoerceValue() method calls the myBoxHeightWidthSquare() method. The myBoxHeightWidthSquare() method has two parameters of the DependencyObject and object types, respectively. The DependencyObject parameter refers to an object of the Box, while the object parameter refers to the value that is used to coerce the value of other dependency properties. In myBoxHeightWidthSquare() method, if the square variable is true and the BoxHeight property is greater than the BoxWidth property, then the BoxHeight property becomes equal to the BoxWidth property. If the BoxHeight is not greater than the BoxWidth property, then the BoxWidth property is assigned the value of BoxHeight property.
