## Exploring the Features of Entity Framework

为了开发 Entity Framework 应用程序，我们需要在 Visual Studio 2010 中创建概念模型、逻辑模型和可编程对象模型。概念模型定义应用程序中的实体和关系。可编程对象模型随后从概念模型生成。逻辑模型表示关系模型以及概念模型与关系模型之间的映射。Entity Framework 的一些功能提高了数据编程的抽象级别并帮助开发人员提高生产力，如下所示：

- 通过提高对象查询执行的速度并使 SQL 查询的生成更简单来增强性能。
- 使用断开连接的组件操作，该组件在本地缓存数据集和实体集，以便在偶尔连接的环境中使用 Entity Framework。
- 通过在代码生成中使用部分方法来增强可扩展性和业务逻辑，以实现属性和属性更改事件的更改。
- 构成许多查询改进，例如为 LINQ to Entities 添加规范函数以及添加更多与数据库一起使用的操作。
- 扩展在开发过程中描述数据的模型。EDM 提供两种数据模型，即概念数据模型和存储模型，以及在这两个模型之间进行转换的映射。

除此之外，在 .NET Framework 的新版本中引入了一些 Entity Framework 的新功能，如下所示：

引入外键，以便简化在实体类型之间创建和修改关系的过程。开发人员对在概念和对象模型中包含外键有两种观点。一些人认为包含外键非常有利，而另一些人则认为外键污染了他们的概念和对象模型。因此，在 .NET Framework 4.0 中，添加了对一种新型关联的支持，即 FK 关联。此关联简化了在外键作为实体属性公开时生成概念模型的过程。

当您从现有数据库生成模型时，Entity Designer 工具的默认行为是为实体类型创建标量属性，这些属性对应于数据库中相应的外键列。

- 引入 Plain-Old Common Language Runtime Objects (POCO)，允许开发人员创建不仅简单而且可以包含在 Entity Framework 中的类。在 .NET Framework 的早期版本中，从模型派生的类继承自 EntityObject 类。如果开发人员想要创建不绑定到框架的简单类，这会阻碍开发人员。POCO 帮助 Entity Framework 在不更改数据类的情况下使用自定义数据类以及数据模型。简单来说，如果你有一个名为 Employee 的类，其中包含姓名、地址和电话号码，那么 Entity Framework 在实现它时不会更改该类。这意味着该类不会包含 EntityKey 或任何其他属性，这要求你在创建应用程序时实现 Entity Framework 特定的接口。
- 在此版本的 .NET Framework 中引入了 Entity Framework 中的延迟加载。延迟加载功能是许多对象关系映射 (ORM) 工具（如 LINQ to SQL）的常见功能。延迟加载功能简单来说是一种设计模式，有助于将对象的初始化重新安排到需要时为止。此功能有助于提高程序操作的效率。在 Entity Framework 中，延迟加载功能将在通过导航属性访问时加载相关对象。此新功能可以通过将 LazyLoadingEnabled 属性设置为 true 来在 Entity Framework 中实现（默认设置为 false）。LazyLoadingEnabled 属性是 ObjectContext 类的一个实例，该类是 Entity Framework 中以对象形式与数据交互的主要类。
- 引入对 QueryExtender 控件和 POCO 的支持，以用于 EntityDataSource 控件。EntityDataSource 控件是 ASP.NET 数据源控件，是早期版本 Entity Framework 的一部分。然而，随着新版本，EntityDataSource 控件已改进以支持 ASP.NET 中引入的新功能，即 QueryExtender 控件，该控件有助于更好地控制从数据源检索数据。QueryExtender 控件是在开发快速应用程序开发 (RAD) 网站时非常有用的控件。

除了对 QueryExtender 控件的支持外，EntityDataSource 控件现在还支持 POCO 实体，这有助于 EntityDataSource 控件使用生成的类进行其功能。

- 引入对二进制键的支持。Entity Framework 的新版本现在提供对映射为实体/外键的二进制属性类型的支持（通常称为二进制键）。
- 引入 ObjectMaterialized 事件。在此版本的 Entity Framework 中，可以编写在对象被物化后立即执行的逻辑。
