# Converters

You can use converters in Silverlight to apply custom logic to data binding. By custom logic, we mean formatting the data displayed in the UI. The converters were first used with WPF and have been completely migrated to Silverlight to make the data-binding process in Silverlight easy. Data binding in Silverlight supports converters, which allow you to map between the properties used in binding. Unlike with WPF, the data templates in Silverlight do not have triggers to bind the data. The converters in Silverlight work in the same way as data triggers do in WPF.

# DataTemplate and ObservableCollection

The data with which you work in .NET Framework is a collection of objects. You can provide a customized display of data-bound items in Silverlight using a DataTemplate object, which is responsible for displaying each item in the list. For example, the ListBox control in Silverlight is an ItemsControl object. This means that you can establish a DataTemplate object for each item it contains by setting the ItemTemplate property to DataTemplate.

The ObservableCollection object in .NET Framework represents a dynamic data collection that provides notification when you add items, remove items, or refresh the whole list. You can term the ObservableCollection object as a good choice for data binding as it implements the INotifyPropertyChanged and INotifyCollectionChanged interfaces. These interfaces are responsible for providing the change notification to the bound target when an item in the list changes or the property itself changes. You should add the System.Collections.ObjectModel namespace to your Silverlight application to use the ObservableCollection class.

# Data Binding Using Networking API

Silverlight 3.0 supports cross-domain networking support. The networking in Silverlight supports both Hypertext Transfer Protocol (HTTP) and Sockets. This implies that your application can call sites other than the one you have initially specified. Silverlight will check for the existence of the XML policy file on the target servers that indicate whether cross domain network access is allowed for using networking in Silverlight. In addition, Silverlight 3.0 has built-in networking Application Programming Interface (API) that enables the Silverlight client to call the remote XML HTTP services. Furthermore, Silverlight 3.0 also includes a built-in sockets API (System.Net.Sockets) that enables Silverlight clients to communicate over non-HTTP protocols.

New network monitoring APIs have also been introduced with Silverlight 3.0 that help you to check whether you are connected to the network or not. You can determine the status of the network, that is, connected or disconnected, by using the following syntax:

```
bool connectionStatus = NetworkInterface.GetIsNetworkAvailable();
```
