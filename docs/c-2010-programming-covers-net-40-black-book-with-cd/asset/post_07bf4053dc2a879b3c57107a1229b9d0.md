## XCopy Deployment

XCopy is a term used to deploy an application by copying a set of assemblies to a folder on a target computer and then executing the application on the target computer. The application starts executing on the target computer by using its assembly file, which is a self-description file that contains all the information about the application. The XCopy deployment does not make any impact on the target system by way of configuring the components and registering entries, and therefore known as zero-impact installation. In the similar manner, uninstallation is also performed without making any impact on the system. The only thing required at the time of uninstallation is to remove the specific files from the specific directories.

In the XCopy deployment, files are copied to a virtual directory that you have set up for your Web application. The XCopy command can take a number of arguments. Some noteworthy arguments are listed in Table 21.1:

| Table 21.1: Noteworthy Arguments of XCopy |
| Argument | Description |
| /E | Copies directories, subdirectories, and files including empty ones |
| /S | Copies directories, subdirectories, and files excluding empty ones |
| /K | Copies attributes and resets the read-only attributes |
| /R | Overwrites read-only files |
| /O | Copies security-related information, such as file ownership and Access Control List (ACL) information |
| /H | Copies directories and subdirectories, including hidden and system files |
| /I | Assumes that the destination is a directory or creates one if it does not exist |
| /C | Continues copying the files even if errors occurs |

Note that you can find all the arguments of the XCopy command by using the following command on the command prompt:

```
xcopy /?
```

## Deploying Web Applications and Web Sites

To deploy an ASP.NET Web Application or ASP.NET Web site, you need to host the application or Web site on a Web server. To deploy a Web application or Web site, you need to copy the files of the application from a source server to the target server or Web server. In addition, you need to perform some additional tasks on the target server that are given as follows:

- To perform changes, such as settings for debugging or database connection strings in the Web.config file
- To configure Internet Information Services (IIS) settings on the destination computer
- To install security certificates
- To set the values in the registry of the destination computer
- To install application assemblies in the GAC on the destination computer

Visual Studio 2010 enables you deploy a Web application or Web site on a target server by performing the following tasks:

- Creating Web deployment packages
- Using the one-click publishing feature
- Transforming the Web.config file
- Deploying a SQL Server database
- Using the Copy Web Site tool

### Creating Web Deployment Packages

A Web Application project can be deployed by creating a Web deployment package and installing that package on a target server. A Web deployment package is a compressed .zip file that stores the following information:

- **IIS settings** – Include the application pool, the authentication method, and error handling
- **Database scripts** – Perform the changes in the database and its structure
- **Debugging and connection string parameters** – Contain values that might need to be changed when the package is installed

In addition to the preceding information, the .zip file may include security certificates, Windows registry settings, and assemblies installed on the GAC of the target computer.

### Using the One-Click Publishing Feature

You can deploy a Web application remotely by using the one-click publish feature. For this, you need to open the Publish Web dialog box, by right-clicking a project in Solution Explorer and selecting the Publish option from the context menu. Figure 21.9 shows the Publish Web dialog box:

### Transforming the Web.config File

Web.config is an XML document that contains settings for an ASP.NET Web application. It contains the information of control module loading, security configuration, session state configuration, application language, and compilation settings. A Web.config file can also include application specific items, for instance database connection strings. When you deploy a Web application on a different computer, you might need to change the following settings:

- Change a database connection string that points a production database
- Disable debugging
- Remove sensitive information, for instance the connection code when you have to provide a package to a community site

One of the solutions to set the preceding settings is to manually manage the changes in a Web.config file, by performing the following tasks:

- Modifying the Web.config file on a target server each time the project is deployed
- Creating and maintaining multiple versions of the Web.config file for each environment settings (in separate folders or with distinct names) and use the most appropriate on the basis of conditions
- Creating XSLT files to transform the Web.config files and apply them when the project is deployed.

Now in Visual Studio 2010, ASP.NET provides tools that automate the process of transforming a Web.config file when you deploy a Web project. For each environment, in which you want to deploy your Web application, you need to create a transform file that specifies the settings for the Web.config file on the basis of each environment.

A transform file includes the name of the destination environment with a prefix node, Web, and suffix node, Config. For example, the transform file for the Debug build configuration is Web.Debug.Config. A transform file is an XML file that uses XML attributes to specify how the Web.config file should be changed. Consider the following code snippet:

```
<connectionStrings>
  <add name="WebApplicationServices"
       connectionString="[ProductionDatabase]" />
</connectionStrings>
```

In the preceding code snippet, the transform file specifies that the connection string, named WebApplicationServices, would be converted to a production database when the Web application is deployed on the target server. Now, consider the following code snippet:

```
<?xml version="1.0"?>
<configuration xmlns:xdt="http://schemas.microsoft.com/XML-Document-Transform">
  <connectionStrings>
    <add name="WebApplicationServices"
         connectionString="[ProductionDatabase]"
         xdt:Transform="Replace" xdt:Locator="Match(name)"/>
  </connectionStrings>
</configuration>
```

In the preceding code snippet, the Locator attribute specifies that only the add element having the same name as WebApplicationServices should be changed. While, the Transform attribute specifies that the deployment process should replace the entire add element.

### Deploying an SQL Server Database

In Visual Studio 2010, you can also deploy a Web application that use SQL Server database to store and maintain the data related to the application by creating script files (.sql files). You can create a custom .sql script file and specify the order in which the script should run on the target server, and then add this script file to a Web package. When a Web package is installed on a target server, it runs the script file and create the same database on the server.

You specify SQL Server database scripting options in the Package/Publish SQL tab of the project properties window. You can access the project properties window by right-clicking the project name in Solution Explorer
