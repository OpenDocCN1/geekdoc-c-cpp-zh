
The preceding code snippet also includes two other methods, IsValidHeight() and IsValidWidth(). These two methods are the validation methods that are called when the BoxHeight and BoxWidth properties need to be validated. Generally, the validation methods are called after the values are coerced.

Now, you need to register the dependency properties of the Box class. In this case, the dependency properties are registered in the static constructor of the Box class, as given in the following code snippet:

```
static Box() {
    FrameworkPropertyMetadata myBoxHeightMetadata = new FrameworkPropertyMetadata(5);
    FrameworkPropertyMetadata myBoxWidthMetadata = new FrameworkPropertyMetadata(5);
    FrameworkPropertyMetadata squareBoxMetadata = new FrameworkPropertyMetadata
        (false, FrameworkPropertyMetadataOptions.None, new
        PropertyChangedCallback(IsSquareBoxTrue), new
        CoerceValueCallback(myBoxHeightSquare));
    BoxHeightProperty = DependencyProperty.Register("BoxHeight", typeof(int), typeof(Box),
        myBoxHeightMetadata, new ValidateValueCallback(IsValidHeight));
    BoxWidthProperty = DependencyProperty.Register("BoxWidth", typeof(int), typeof(Box),
        myBoxWidthMetadata, new ValidateValueCallback(IsValidWidth));
    IsSquareProperty = DependencyProperty.Register("IsSquare", typeof(Boolean),
        typeof(Box), squareBoxMetadata);
}
```

In the preceding code snippet, the static constructor of the Box class contains three objects of the FrameworkPropertyMetadata class to configure the metadata for the three dependency properties. The myBoxHeightMetadata and myBoxWidthMetadata objects are instantiated with 5 as the default values for the BoxHeight and BoxWidth properties. The squareBoxMetadata object specifies false as the default value and the property changed and the coerce value callback methods for the IsSquare property.

The last three statements in Listing 9.5 registers the BoxHeight, BoxWidth, and IsSquare dependency properties using the Register() method of the DependencyProperty class. The first parameter of the Register() method is the actual name of the dependency property (without the Property suffix). The second parameter is the type of the property value; the third parameter is the owner type (the class that contains the dependency property); the fourth parameter is the property metadata object; and the fifth parameter is the validate value callback() method.

The only thing that remains now is to wrap the dependency properties in CLR wrappers and implement the get and set accessors. You can do this by adding the following code snippet in the Box class:

```
public int BoxHeight
{
    get { return (int)GetValue(BoxHeightProperty); }
    set { SetValue(BoxHeightProperty, value); }
}
public int BoxWidth
{
    get { return (int)GetValue(BoxWidthProperty); }
    set { SetValue(BoxWidthProperty, value); }
}
public Boolean IsSquare
{
    get { return (Boolean)GetValue(IsSquareProperty); }
    set { SetValue(IsSquareProperty, value); }
}
```

In the preceding code snippet, the BoxHeight, BoxWidth and IsSquare dependency properties are implemented as CLR properties and their get and set accessors call the GetValue() and SetValue() methods.

You can now access these dependency properties as CLR properties in the XAML or the code-behind file.

> NOTE
> If you want to reset the value of a dependency property, then you can use the ClearValue() method. With this method, it is not necessary that the dependency property changes back to the default value specified in the property metadata. In fact, the value to which the dependency property reverts is dependent on the inputs available at that time.

Let’s move on to learn about a particular kind of dependency property known as attached properties.

## Attached Properties

An attached property refers to a dependency property that you can access and set to any of the child objects or elements. The attached properties help the child elements to provide information about their appearance and presentation to the parent element. The attached properties of an element are available to all its child elements and each child element can set different values for the same attached property.

Note that attached properties are implemented as dependency properties in the parent or owning element and accessible in both XAML and code-behind file. However, except for certain situations in style triggers, you cannot retrieve the value of attached properties in XAML. Unlike rest of the dependency properties, attached properties are not wrapped within a CLR property as they have to be accessible to all the elements (the parent as well as the child elements). Such elements should be able to assign different values. Some examples of the attached properties include the Row and Column properties of the Grid element.

You can also create user-defined attached properties. To do so, the parent or owning element needs to inherit the DependencyObject class unless the attached property is available only for other elements and not the parent element. A field of the DependencyProperty type is declared to create the attached property, which is then registered using the RegisterAttached() method. You also need to implement the get and set accessors for the property through two static methods. The syntax for the get accessor method of attached properties is as follows:

```
public static type GetPropertyName (type target) {
    //return statement
}
```

In the preceding syntax:
- public, static—Represents the C# keywords.
- type—Represents a valid type.
- GetPropertyName—Represents the name of the method that implements the get accessor method of the attached property. Note that PropertyName in GetPropertyName signifies the actual name of the attached property; therefore, the method name varies on the basis of properties name. For example, if the name an attached property is, Center; then the static method implementing its get accessor is named as GetCenter.
- target—Represents the object or element that gets the value of the attached property.

Note that the get accessor of attached properties needs to have a return statement.

The syntax for the set accessor of attached properties is as follows:

```
public static type SetPropertyName( type target, type value) {
    //statements
}
```

In the preceding syntax:
- public, static—Represents the C# keywords
- type—Represents a valid type
- SetPropertyName—Represents the name of the method that implements the set accessor of the attached property. Note that PropertyName in SetPropertyName signifies the actual name of the attached property; therefore, the method name varies on the basis of properties name. For example, if the attached property is named Center, then the static method implementing its set accessor is named SetCenter.
- target—Represents the object or element on which the attached property is to be set.
- value—Represents the value that is to be set on the attached property.

You can access attached properties as attributes of the child elements. When you access an attached property, it needs to be qualified with the name of the parent or owning element. Consider an example that a Grid element has a Button element as its child element. Then, the Row and Column properties of the Grid element are attached properties, and available to the Grid as well as the Button elements. Now, the Button element can access the Row and Column properties, as shown in the following code snippet:

```
<Button Height="25" Width="150" Name="button1" Grid.Row="1" Grid.Column="1">Attached Property</Button>
```

In the preceding code snippet, you can notice that the Row and Column properties are qualified or preceded with the name of the owning element, that is, Grid.Row and Grid.Column, respectively. The values of the attached properties are specified within the double quotes just as other properties are set in XAML.

You can also access the attached properties through the property element syntax. For instance, the Row and Column attached properties of the Grid element are accessible in the Button element, as shown in the following code snippet:

```
<Button>
<Button.Height>25</Button.Height>
<Button.Width>150</Button.Width>
<Button.Name>button1</Button.Name>
<Button.Content>Attached Property</Button.Content>
<Grid.Row>1</Grid.Row>
<Grid.Column>1</Grid.Column>
</Button>
```

In the preceding code snippet, unlike other properties (for example, Height and Width) of the Button element, the Row and Column properties are not qualified with the Button element. However, these two properties are qualified with the Grid element, which is the owner type of the attached properties.

Similar to custom dependency properties, you can also have custom attached properties. The process of creating a custom attached property is same as that of a dependency property. However, there are certain differences, first, you use the RegisterAttached() method instead of the Register() method to register the custom attached property and, secondly, you do not need to wrap the custom attached property in a CLR property. Let's learn how to create a custom attached property. For this, first create a standalone WPF application named CustomGridAttachedProperty (also available in CD). Now, in the code-behind file of the application, add the following code snippet in the CustomGridAttachedProperty namespace:

```
public class myGrid : UIElement {
public static readonly DependencyProperty CellHeightProperty;
static myGrid() {
CellHeightProperty = DependencyProperty.RegisterAttached("CellHeight",
typeof(int), typeof(myGrid));
}
public static void SetCellHeight(FrameworkElement element, int value) {
element.SetValue(CellHeightProperty, value);
}
public static int GetCellHeight(FrameworkElement element) {
return (int)element.GetValue(CellHeightProperty);
}
}
```

In the preceding code snippet, you can see that a new class named myGrid is added to the CustomGridAttachedProperty namespace. In the myGrid class, a static read-only DependencyProperty field named CellHeightProperty is declared. The myGrid class also has a static constructor in which the CellHeightProperty dependency property field is registered as an attached property. To return and set values of the CellHeight property, two methods, GetCellHeight() and SetCellHeight(), are defined. You can now use the CellHeight attached property by qualifying it with the name of the owner, that is, myGrid.
