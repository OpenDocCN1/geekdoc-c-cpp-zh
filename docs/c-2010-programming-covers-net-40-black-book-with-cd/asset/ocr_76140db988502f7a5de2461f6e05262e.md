# In Depth

A Web service may be defined as an independent and self-sustained unit of a software application hosted on the Internet. A Web service implements specific functionalities to execute the business logic of the application. A Web service can be used to implement various functionalities, such as preparing the pay slips for the employees of a company, calculating the income tax, broadcasting weather reports, and providing updated news. In .NET Framework 4.0, you can create Web services. A Web service created in ASP.NET 4.0 is known as ASP.NET 4.0 Web service and consists of an infrastructure that contains various components used to implement basic functionalities to a Web service, such as locating a Web service, calling a Web service, and so on. You can also use the code model and properties of an ASP.NET Web service while creating Web services. You can also create Web services that use the ASP.NET AJAX functionality. In addition, security measures to check unauthorized access to Web services also need to be incorporated in the Web services created.

In this chapter, you learn about Web services, infrastructure of ASP.NET Web services, code model of ASP.Net Web services, Web service properties, securing Web services, and the use of ASP.NET AJAX with Web services. You also learn how to create an ASP.NET Web service, how to use an ASP.NET Web service, how to share data across Web services, how to do communication between Web services asynchronously, how to work with ASP.NET AJAX-enabled Web services, and how to use an UpdatePanel control with a Web service.

# Introducing Web Services

A Web service is an entity that you can program to provide a particular functionality to applications over the Internet. Suppose you want to host a website on the Internet that calculates the simple interest, compound interest, and income tax of an individual. To do this, you can use a Web service to calculate the simple interest, compound interest, and another Web service to calculate the income tax. In this scenario, a Web service is advantageous in the sense that you do not need to write the code in the Web site for calculating the simple interest, compound interest, and income tax. Instead, all you have to do is to use the Web services that provide these functionalities. You need to subscribe to the Web service before using a Web service in your website.

A Web service allows a website to communicate with other websites irrespective of the programming languages in which they are created. In addition, a Web service can be accessed by any application, regardless of the software and hardware platforms on which the application is running, because the Web service complies with common industry standards, such as Simple Object Access Protocol (SOAP) and Web Services Description Language (WSDL). A Web service does not have any user interface; it only contains the logic for providing specific services to its consumers. A Web service provides an abstraction between the consumer (client) and the provider of the Web service. The Web service only need information about input, output, and location of the client and Web service provider. Before the introduction of Web services, developers employed technologies, such as Component Object Model (COM) and Distributed Component Object Model (DCOM), to use the functionality of one application in another application. These technologies allowed a developer to create code components once and bundle the components so that they could be shared across multiple applications by multiple developers. However, there were some fundamental difficulties in using these components. One such difficulty was that these components needed to be physically distributed and explicitly registered on each client machine. Web services overcome these difficulties as they can be shared among multiple websites without the need to install them on each individual client machines.

Web services have become popular because of the added functionalities they provide over component-based technologies. The advantages of Web services over COM and DCOM are as follows:

+   - Web services are simple to use; and consequently, they can be implemented on varied platforms
+   - Web services are loosely coupled; as a result, their interfaces and methods can be extended
+   - Web services do not carry any state information with them so that multiple requests can be processed simultaneously
