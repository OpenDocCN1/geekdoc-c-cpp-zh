

## 第一节 – .NET 简介

.NET Framework 是 Windows 的内部组件，支持使用各种编程语言（如 Visual C#、Visual Basic、Visual F# 和 Visual C++）创建的应用程序的执行。这些编程语言是 Visual Studio .NET 的一部分。.NET Framework 由一个名为通用语言运行库（CLR）的虚拟执行系统和一组类库组成。CLR 是通用语言基础结构（CLI）的 Microsoft 产品，CLI 是一项国际标准，也是创建语言和库协同工作的执行和开发环境的基础。

Microsoft 推出 .NET 的目的是弥合差距并确保不同语言创建的应用程序之间的互操作性。.NET Framework 用于集成以各种编程语言和服务实现的应用业务逻辑。因此，它在代码重用性、代码专业化、资源管理、以多种编程语言开发应用程序、安全性、部署以及以多种编程语言开发的程序的<|message|> 管理方面带来了显著改进。

由于本书是关于 C# 语言的，让我们探讨 C# 与 .NET Framework 之间的关系。C#，我们所知，是设计用于构建在 .NET Framework 上运行的各种应用程序（如 Windows Forms 和 Web）的编程语言。它是一种简单、类型安全且面向对象的语言。你可以使用 C# 创建传统的 Windows 客户端应用程序、分布式组件、客户端-服务器 Web 应用程序和数据库应用程序。此外，C# 2010 提供了高级代码编辑器、用户界面设计器、集成调试器以及许多其他工具，使基于最新版本的 .NET Framework 开发应用程序变得更容易。

本章分为四个部分，讨论 .NET Framework、Visual Studio 2010 的安装、Visual Studio 2010 集成开发环境（IDE）的功能以及 C# 2010 相关技术。本章还提供了本书各章中讨论的 .NET 相关技术的快照。现在，让我们开始讨论 .NET 的演进。

## .NET 的演进

大约在 1995 年，由于其平台无关的方法和 Sun Microsystems 的开源政策，Java 开始流行。后来在 2002 年，Sun Microsystems 发布了 Java 的企业版，即 Java 2 企业版（J2EE），这是一个基于 N 层架构开发和执行分布式 Java 应用程序的 Java 平台。J2EE 的出现最终导致了 Microsoft 市场份额的下降。因此，Microsoft 启动了一个名为下一代 Windows 服务（NGWS）的项目以重新夺回市场份额。开发该产品花了三年多时间，现在它被称为 .NET。

.NET 的第一个版本于 2002 年 2 月 13 日以 .NET Framework 1.0 的名称发布，同时发布了 Visual Studio .NET 2002 IDE。.NET 的第二个修订版几乎花了一年时间发布，被称为 .NET Framework 1.1。Microsoft Visual Studio .NET，更为人所知的 Visual Studio .NET 2003，也是第二版的一部分。.NET Framework 的下一个版本 .NET Framework 2.0 于 2005 年 11 月 07 日与 Visual Studio .NET 2005 一起发布。之后，.NET Framework 3.0 于 2006 年 11 月 06 日发布，.NET Framework 3.5 于 2007 年 11 月 19 日发布。最后，已知的最新版本的 .NET Framework，即 .NET Framework 4.0，于 2010 年 4 月 12 日与 Visual Studio .NET 2010 一起发布。

以下是 .NET Framework 的一些好处：

- 一致的编程模型 – 为不同语言提供一致的面向对象编程模型，以执行各种任务，例如连接到数据库并从数据库检索数据，以及从文件读取和写入文件。
- 跨平台支持 – 能够在多个 Windows 操作系统之间实现互操作性。
- 语言互操作性 – 使不同语言编写的代码能够相互交互。例如，你可以在 Visual Basic 环境中继承 C# 开发的类，反之亦然。
- 自动资源管理 – 自动管理应用程序资源，例如文件、内存或网络和数据库连接。
- 部署简便 – 提供应用程序的轻松部署。在大多数情况下，要安装应用程序，只需将应用程序及其组件复制到目标计算机即可。.NET Framework 以程序集的形式提供 .NET 应用程序的部署，因此无需在注册表条目中存储有关组件和应用程序的信息。

## CLR

.NET Framework 的最重要组件之一是 CLR，更为人所知的运行时。它提供诸如内存管理、异常处理、调试、安全、线程执行、代码执行、代码安全、验证和编译等功能。CLR 可以托管多种语言并确保其代码之间的互操作性。CLR 还支持应用程序用于访问各种资源（如集合、数组和操作系统文件夹）的服务。运行时在资源不再使用时会自动释放资源。这种自动内存管理解决了内存泄漏和无效内存引用的问题。

运行时对应用程序的代码施加代码访问安全（CAS）。CAS 是 CLR 的安全系统，可防止未经授权访问资源和操作。CAS 还有助于使代码健壮，即它使代码具有可扩展性和可重用性。

现在让我们探索 CLR 中的托管代码、非托管代码和内存管理。

## 托管代码和非托管代码

托管代码是直接由 CLR 执行的代码。因此，使用托管代码创建的应用程序会自动具有 CLR 服务，例如类型检查、安全性和自动垃圾回收。这些服务有助于为托管代码应用程序提供平台和语言独立性。CLR 将应用程序编译为中间语言（IL）代码而不是机器代码。此 IL 代码连同描述代码的属性、类和方法元数据一起驻留在程序集中。

CLR 执行以下步骤来执行一段托管代码：

- 1. **选择语言编译器** — 指根据应用程序创建的编程语言选择编译器的过程。
- 2. **将代码编译为 IL 代码** — 指将源代码转换为与 CPU 无关的 IL 代码的过程。当你将源代码编译为 IL 代码时，会生成所需的元数据。元数据包含类型定义、成员签名、代码中的成员以及代码在执行时使用的其他详细信息。运行时在执行应用程序代码期间从文件中定位并提取元数据。
- 3. **将 IL 代码编译为本地代码** — 指由即时（JIT）编译器将 IL 代码转换为本地或机器代码的过程。编译后，代码会经过验证过程，该过程检查 IL 代码和元数据以检查代码是否类型安全，即代码只能访问其有权访问的内存位置。
- 4. **执行代码** — 指执行机器代码的过程。

### 注意

> CLR 还支持另一种名为安装时代码生成的编译方法。此方法用于一次性将 IL 代码转换为本地代码，一次取较大的代码单元。

CLR 为代码的编译和执行提供了一个安全的环境。JIT 编译器也会重复此代码编译和执行过程，直到执行完成。在整个代码执行过程中，托管代码会接收诸如垃圾回收、安全、与非托管代码的互操作性、跨语言调试支持以及增强的部署和版本控制支持等服务。
