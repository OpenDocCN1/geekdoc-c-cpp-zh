# ## Data Binding in Silverlight

Data binding in simple terms is termed as the connection between the data providers and a UI, which contains data bound controls, such as DataGrid. The UI is termed as the target and the data provider is termed as source. This division in data binding helps in maintaining the application and increasing the performance of your application. The performance increases as this division of data binding makes fewer round trips to the server. Silverlight is a part of the .NET Framework 4.0 where you can implement data binding. Let's learn about the various aspects of data binding in Silverlight.

# ## Types of Data Binding in Silverlight

The various types in which you can bind your data in a Silverlight application are as follows:

+   - **OneTime** – Sets the target and then the binding is completed. You can use OneTime binding when you are displaying data that rarely or never changes.
+   - **OneWay** – Sets the target and keeps this target up to date as the source changes. You can use OneWay binding when you are displaying data that you are not permitted to change.
+   - **TwoWay** – Sets the target and keeps the target up to date as the source changes. It also keeps the source up to date as you change the target or there are some other changes in the application that will cause the source to change.

You can understand the types of data binding in Silverlight using a simple example. Consider a situation in which you are responsible for building an on-line bookstore. If you are displaying information about a book, you might use OneTime binding for the book title and author, as they would never change. You would use OneWay binding for the price of a book, as the user will not be able to change it. You would choose the TwoWay binding for the quantity of the book in hand, as it is subject to change.

# ## Binding Object

The binding object in Silverlight is the universal connector between the target and the source. This binding object is responsible for retrieving the data needed by the target from the source. The binding object in Silverlight represents a binding between the property value of an object and the property value of the control. For example, you can bind the Text property of a TextBox control to the FirstName column of the Customers table. Similarly, you can bind the Text property of another TextBox control to the LastName column of the Customers table. When you run the application, the binding object will ensure that correct data is retrieved in the respective TextBox control. This feature of data binding is very useful in Silverlight applications. In the example explained in the previous section, you are actually binding the Text property of the TextBox control using the binding object.

# ## Data Context

The data context is the process of selecting the right data from the source and sending it to the target at runtime. For example, when you bind the target with the source, you just specify the kind of data the target will display. You specify that the particular text box will display the name of the customer. You do not specify which customer name to display. You just bind the TextBox with the Customers table. This is where the data context comes in role. The data context is the specific customer, displayed at runtime. In simple terms, you can refer data context to a source of data that can be bound to a target. The data context is useful when there are several controls within a container control and all use the same binding source. Each FrameworkElement object has a data context.

When you are creating binding, the dependency property of the FrameworkElement object must be assigned to the binding. This is the basic target of the binding operation. You can set the source of the binding through the DataContext property of the element. The data context also allows its elements to inherit information about the data source from the parent container.
