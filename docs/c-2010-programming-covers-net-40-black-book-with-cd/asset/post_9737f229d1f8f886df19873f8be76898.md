
## Different Editors for Deployment of the Applications

When you create an installer file for your application, you might need to specify where the files of the application should be installed on a target computer, specify what registry keys should be added, or add custom dialog boxes for installation. It is also possible that you need to customize the user interface that is shown during the installation of your application, or run the application to perform some specific actions on a target computer. You can specify and customize the settings related to the deployment of an application by using the deployment editors that are available in Visual Studio 2010. Note that these editors are available only when you add a setup and deployment project in your application. Visual Studio 2010 provides the following deployment editors:

- File System editor
- Registry editor
- File types editor
- User interface editor
- Custom actions editor
- Launch conditions editor

## File System Editor

The File System editor allows you to add the project outputs, files, assemblies, and other items to a deployment project and specify the target location where these files will be deployed. It displays a standard set of deployment folders by default. You can add your own folders and special folders with the editor. In addition, you can specify the desktop and Start menu shortcuts for the application within the File System editor. The files that are part of the deployment must be referenced from within the File System editor. To view the File System editor, click View→Editor→File System menu item. The Registry editor specifies registry keys and data values that you want to add to the registry of the target computer. When you open the Registry editor for the first time, it displays a standard set of registry keys. To view the Registry editor, click View→Editor→Registry. The Registry editor is divided into two panes—the left pane is referred to as the Navigation pane containing hierarchical list of registry hives and the right pane is referred to as the Detail pane displaying the description of the registry hives. A registry hive is a collection of keys, sub keys, and values. You can add custom keys and values and set some properties for the sub keys and values in the Registry editor.

## File Types Editor

The File Types editor establishes association between files and applications. For example, when you double-click the file having the .doc extension, it opens in MS Word. To view the File System editor, click View→Editor→File Types. The File Types editor appears, as shown in Figure 21.3:

![](img/e073a4882197be4ab61103cbe0bcb394_1069_1.png)

To establish the association, all you need to do is just associate file extensions with your application and specify the actions allowed for each file type.

## User Interface Editor

The User Interface editor specifies properties for a set of predefined dialog boxes. It is helpful when you want to add extra information that is displayed during the installation process. The User Interface editor is divided into two sections, Install and Administrative Install. The Install section contains the dialog boxes that are displayed when the user runs the installer; whereas the Administrative Install section contains the dialog boxes that are displayed when the system administrator uploads the installer to a network location. To view the User Interface editor, click View→Editor→User Interface. The User Interface editor appears as shown in Figure 21.4:

![](img/e073a4882197be4ab61103cbe0bcb394_1070_0.png)

In Figure 21.4, you see that the User Interface editor contains a set of predefined dialog boxes. These predefined dialog boxes fall into three categories—Start, Progress, and End. The Start dialog boxes are displayed before the installation starts; the Progress dialog boxes are displayed when the installation is in progress; and the End dialog boxes are displayed when the installation completes successfully.

## Custom Actions Editor

The Custom Actions editor allows you to define custom actions that take place at the end of the installation process on the target computer. Custom actions are created in advance and must be compiled as a .dll or exe file, or added to the project as a script or assembly. You can view the Custom Actions editor by clicking View→Editor→Custom Actions, as shown in Figure 21.5:

![](img/e073a4882197be4ab61103cbe0bcb394_1070_1.png)

### Figure 21.5: Displaying the Custom Actions Editor

In Figure 21.5, you see the Custom Actions editor with four specific phases of custom actions. The description of the phases of custom actions are given as follows:

- Install — Executes actions at the end of the installation phase
- Commit — Executes actions when the installation completes successfully
- Rollback — Executes actions when the rollback phase has completed
- Uninstall — Executes actions when uninstall has completed

Custom actions are run in the same order as they appear in the Custom Actions editor. However, you can also reorder them by dragging or using the Cut/Paste command.

## Launch Conditions Editor

The Launch Conditions editor allows you to specify certain conditions that must be met to continue the installation. For example, if you want to install an application on a specific version of the Windows operating system, the installation first checks the presence of specific conditions and runs the process only when the conditions are met. Otherwise, the installation is terminated at that point. You can view the Launch Conditions editor by selecting View→Editor→Launch Conditions in the Visual Studio 2010 IDE, as shown in Figure 21.6:

![](img/e073a4882197be4ab61103cbe0bcb394_1071_0.png)

Figure 21.6: Displaying the Launch Conditions Editor

The Launch Conditions editor (Figure 21.6) displays the following requirements on a target computer:

- Search Target Machine — Specifies search conditions to determine if a particular file, registry key, or Microsoft Windows Installer component exists on the target computer. Some examples of search conditions are: File Search, Registry Search, and Windows Installer Search.
- Launch Conditions — Specifies predefined launch conditions for an application

## Including Prerequisites for an Application Deployment

To install and run an application on a target computer, you should ensure that the target computer has the prerequisites of running the application. A prerequisite is a component that must be installed on a target computer, as it is required to run your application. For instance, the target computer must be having a particular version of Common Language Runtime (CLR) on the computer. The prerequisites of your applications are selected in the Prerequisites dialog box. These prerequisites install the .NET Framework and other dependencies for your applications on the target computer, as a part of your installer application. You can access the Prerequisites dialog box by first right-clicking a project node in Solution Explorer and selecting the Properties option from the context menu. As a result of this, project properties dialog box appears. Now, select the Publish tab in project properties dialog box, as shown in Figure 21.7:

In Visual Studio 2010, the deployment tools have the capability to automatically detect the existence of components that are required for the execution of an application during installation and install a set of prerequisites for the successful execution of the application. This process is known as bootstrapping and performed by the bootstrapper component that installs the prerequisite components on a target computer by using the bootstrapper package. In addition, a bootstrapper package consists of a group of files and directories of manifest files that describe how the prerequisites are installed on a target computer.
