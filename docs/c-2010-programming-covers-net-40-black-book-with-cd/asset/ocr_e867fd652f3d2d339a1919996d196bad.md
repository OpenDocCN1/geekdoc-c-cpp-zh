# Impersonation and Delegation

We have already discussed that all the ASP.NET applications run by default under the NETWORK SERVICE user account. This built-in Windows account provides the identity for the default application pool in which the ASP.NET applications exist. The NETWORK SERVICE account has limited rights and privileges on the Windows computer. This implies that the ASP.NET application can access only some files and perform specific operations on the computer. For example, the ASP.NET applications can read and write from databases on the computer but cannot delete database logs. In addition, with this low permission access to ASP.NET applications, the security and reliability of applications are preserved in case of any intrusion of the Web server.

There may be situations where you want your ASP.NET application to access a file, database, or any other local resource on the Web server but the NETWORK SERVICE account does not have the required permissions. In such situations, you can make your ASP.NET application to impersonate as a Windows user that has required privileges. For example, your ASP.NET application can impersonate as a user with administrative privileges to access a local resource.

In ASP.NET, impersonation refers to the process of acquiring the identity of an anonymous or authenticated user (Windows authentication) of an ASP.NET application and executing the application as that user. In this way, the ASP.NET application gets access to all the resources on the Web server to which the user has the permissions. You can implement impersonation in an ASP.NET application only when you are using Windows authentication in the application. You may recall that when Windows authentication is enabled in the ASP.NET application, authentication is only required at the IIS level; the application does not perform any authentication and uses the identity provided by IIS. In IIS, you can enable Anonymous, Windows, Basic, or Digest authentication mode to work with Windows users at the ASP.NET application level. This implies that based on the identity passed by IIS, ASP.NET applications can impersonate a Windows user. You can implement impersonation in the following three ways:

+   - Impersonating an anonymous user whose identity is provided by IIS — Occurs when you implement impersonation in an ASP.NET application and enable Anonymous authentication in IIS. In this case, the ASP.NET application runs as an anonymous user, which by default is IUSR.

+   - Impersonating the currently logged-in Windows user who is authenticated by IIS — Occurs when you implement impersonation in an ASP.NET application and enable any of Windows, Basic, or Digest authentication in IIS (with Anonymous authentication in IIS disabled). In this case, the ASP.NET application impersonates the Windows user whose credentials are used to log in to the application.

+   - Impersonating a specific Windows user for all the anonymous and authenticated users — Occurs when you implement impersonation in an ASP.NET application and provide the credentials of a particular Windows user. In this case, irrespective of the authentication enabled in IIS and the ASP.NET application, the application always runs as the impersonated user. Note that for this case, you need to use Access Control List (ACL) to ensure that the impersonated Windows user has permissions to write to the Temporary ASP.NET Files folder at the location C:\Windows\Microsoft.NET\Framework\v4.0.30319. The Temporary ASP.NET Files folder is the location where the compiled files of all the ASP.NET applications are stored.

To effectively implement impersonation in ASP.NET applications, you need to enable impersonation in IIS as well as in the application. To enable impersonation in IIS, double-click the Authentication feature option, which opens the Authentication pane. Right-click the ASP.NET Impersonation option and select Enable.

You need to also enable ASP.NET impersonation as it is disabled by default. You can do this by using the <identity> element in the web.config file in the ASP.NET application. The <identity> element allows you to specify whether to enable or disable impersonation in the ASP.NET application. For example, to enable impersonation in an ASP.NET application, you can use the <identity> element as given in the following code:

```
<identity impersonate="true"/>
```

In case if you want an ASP.NET application to impersonate a particular user at all times, then you can use the <identity> element as given in the following code:

```
<identity impersonate="true" userName="testuser" password="testuser"/>
```

In this code, the ASP.NET application impersonates the Windows user that has the same user name as well as password, which in this case is testuser.
