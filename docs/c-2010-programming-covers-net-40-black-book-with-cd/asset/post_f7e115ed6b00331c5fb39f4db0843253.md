
+   - **JSON Serialization** – Performs customizable serialization and deserialization from the common .NET Framework type to the JSON format and vice versa.
+   - HTTP Handler – Used for the execution of .aspx, .asmx, and .soap files. It is also used by ASP.NET to handle the requests. The HTTP handler can be created by using the IHTTPHandler interface.

Now, let’s learn how to secure a Web service.

## Securing Web Services

If you want to create a Web service and host it over the Internet, you need to be able to control and regulate access to the Web service. Web service requests and responses are sent as XML documents, which are in text format. Therefore, you need to secure the Web service from unauthorized access during such transmission.

You can prevent a Web service from being accessed by unauthorized access in the following two ways:

+   - Using encryption and message-based security
+   - Using authentication and access controls for the Web service

Now, let’s learn about these methods in detail.

## Encryption and Message-Based Security

Encryption is the process of scrambling the text that your Web service contains so that only the intended user is able to decrypt (convert encrypted data back into its original form) it with the help of a key.

Message-based security allows you to send encrypted messages to anyone, without worrying about the decryption of the messages by a malicious user. You can detect any modification made by someone in the message straightaway because the signature (private key) attached to the message becomes invalid, and you can then safely throw the message. This type of security works by encrypting the message at both the request and the response levels.

## Authentication and Access Controls for the Web Service

Authentication is a process of validating a user against the user credentials provided by the user. One way to secure a Web service is to make it mandatory for the users, who want to use the Web service, to provide their credentials in the form of a user ID and password. If they fail to do that, they are refused access to the Web service.

## Creating a Web Service

Before looking at the tasks that we need to perform to create a Web service, let's look at the points to be considered while creating a Web service. The following list enumerates a few noteworthy points:

+   - Ensure that the communication between a Web application that requests a Web service and a Web server that provides the Web service is asynchronous. In asynchronous communication, the Web application does not need to stop its processes until the Web server responds to its request.

+   - Minimize the number of requests that a Web application needs to send to a Web server to obtain a Web service. You can do this by combining similar tasks of the Web service in a single method. For example, suppose you want to create a Web service that provides information about sports items. Instead of creating separate methods for providing information about the name, price, and manufacturer of each item, you can create a method that provides complete information about the items in a single request. The efficiency of the network over which the information is transmitted increases with the decrease in the number of requests required to obtain the Web service. This is because large amount of information, instead of small chunks, is transmitted at once.

+   - Ensure that the Web service is created by using the concepts of object-oriented programming. You can ensure this by abstracting the implementation details of the Web service from the Web application accessing the Web service and by using inheritance and polymorphism to create the Web service. Object-oriented programming concepts allow you to reuse code to create a Web service and simplify the design of the Web service.

+   - Minimize the time a Web server takes to respond to the request of a Web application. You can minimize the response time of the Web server by creating a cache to store the output of the request sent by a Web application to a Web server, for a specific period of time. Now, when a Web application requests a Web service, its request can be fulfilled from the cache. This reduces the time and amount of processing required to obtain the result of the request from the Web server.

## Declaring the Web Service

The next step after creating the Web service project is to declare the Web service in a WebService.asmx file.

A Web service is declared using the @ WebService directive that provides information required by the compilers and parsers of ASP.NET to compile and run the Web service. This includes information on the following attributes of Web services:

+   - Class—Specifies the name of the class that implements the Web service.
+   - CodeBehind—Specifies the file name that contains the implementation of the Web service. This attribute is used when neither the file containing the @ WebService directive nor the file in the Bin folder contains the class that implements the Web service.
+   - Debug—Specifies whether to debug the Web service during compilation. The Web service is debugged during compilation if the value of the Debug attribute is set to True.
+   - Language—Specifies the language in which the Web service is compiled. You can set the Language attribute to any language supported by .NET, such as VB, C#, or jscript.

The syntax of the @ WebService directive is:

```
<%@ webservice attribute="value" ... %>
```

Before declaring a Web service using these attributes, you need to determine whether the class containing the implementation of the Web service is present in the same assembly that contains the @WebService directive or in a separate assembly in the Bin folder. You need to determine this because the declaration of the Web service differs in both the cases.

If the class resides in the same assembly as the @WebService directive, you just need to specify the name of the class in the Class attribute. However, if the class resides in a separate assembly, you need to specify the name of the assembly in which the class resides, in addition to the class name, in the Class attribute. Now, let's consider an example to understand this concept better.

Suppose the name of the class that implements your Web service is Webserv and it resides in the same assembly that contains the @WebService directive.

You can declare this Web service in Visual Studio 2010 by writing the following single-line code in the Service.aspx page:

```
<%@ webservice Language="C#" Class="webserv" %>
```

However, if the Webserv Web service resides in a separate assembly, Webserv_assembly, then you need to write the following single-line code in the Service.aspx page to declare the Web service in Visual Studio 2010:

```
<%@ webservice Language="C#" Class=" WebServ,WebServ_assembly" %>
```

Till now, we have learned how to use the @ WebService directive to declare a Web service. Now, we look at one more directive, @Assembly. We need to understand this directive because in some situations we need to use it as well while declaring a Web service. We first look at such situations and then explore the attributes of this directive.

Suppose you want your Web service to use some assemblies that contain pre-defined interfaces and classes. These interfaces and classes can be user-defined as well as system-defined. If these assemblies reside in the same assembly as the @ WebService directive or in the Bin folder of the Web application containing your website, then they are linked to your Web service automatically. However, this may not always be the case. Therefore, in such situations, you need to use the @ Assembly directive to explicitly link these assemblies to the Web service.

The @ Assembly directive associates an assembly with a Web service when the Web service is compiled. This allows the Web service to use the classes and interfaces defined in that assembly. You need to specify the name of the assembly in its Name attribute to use the @ Assembly directive to associate an assembly with a Web service. You do not need to specify the extension of the assembly while setting the Name attribute. The syntax for setting the Name attribute is:

```
<%@ Assembly Name="assemblyname" %>
```

The @ Assembly directive also allows you to include a code file other than the assembly in a Web service. For example, you can include a C# code file in a Web service by using the @ Assembly directive. You can do so by specifying the path of the file in the Src attribute of the @ Assembly directive. The syntax for using the Src attribute is:

```
<%@ Assembly Src="pathname" %>
```

## Setting the WebService Attribute

The WebService attribute is used to provide additional information about a Web service, such as the functionality of the Web service. However, it is not mandatory to use the WebService attribute in a Web service.

You can also use the WebService attribute to set a default namespace, http://tempuri.org, for a Web service. However, to differentiate your Web service from other Web services available on the Internet, you should change the default namespace, while publishing the Web service. This allows users to uniquely identify their Web service. You need to apply it to the class that implements the Web service to set the WebService attribute. The syntax for using the WebService attribute is:

```
[webservice(Namespace="http://tempuri.org/")]
public class classname
```

## Declaring Methods for a Web Service

You need to declare the methods that define the functionality of the Web service to implement a Web service. The methods of a Web service should be able to send and receive data to and from the Web applications over the Internet, so that the Web service can be accessed by the Web applications. You can enable Web service methods to communicate with the Web applications by declaring the methods Public and by applying the WebMethod attribute to the methods.
