# In Depth

Common Language Runtime (CLR) provides the execution environment to the .NET Framework code. In Visual Studio, the code that runs on CLR is called as managed code. The CLR provides various functions and services that are required to execute a program. Some examples of these services are Just-In-Time (JIT) compilation, memory management, thread management, type safety, and exception handling. This CLR runtime feature is also integrated in SQL Server 2008, which gives developers more flexibility to develop the code. The integrated CLR feature in SQL Server 2008 allows you to create CLR objects, such as stored procedures and triggers, in .NET Framework by using managed languages, such as C#, and to use these objects externally with the help of creating assemblies in SQL Server 2008. You can create CLR objects in .NET Framework by importing the Microsoft.SqlServer.Server namespace.

In this chapter, you learn about the integration of CLR in SQL Server 2008. The chapter begins with hosting of CLR in SQL Server 2008. Next, you learn about the Microsoft.SqlServer.Server namespace and available classes, interfaces, and enumerations in the namespace. You also learn about various CLR objects, such as stored procedures, triggers, aggregate functions, User-Defined Functions (UDF), and User-Defined Types (UDT). Then, you learn how to handle Extensible Markup Language (XML) data in SQL Server 2008. In the Immediate Solutions section of the chapter, you learn how to create and use different CLR objects in .NET Framework and their use in Structured Query Language (SQL).

Let’s start with the hosting of .NET runtime in SQL.

# Hosting of .NET Runtime

SQL Server 2008 provides a CLR integration feature, according to which it can hosts the CLR of .NET Framework 4.0. The CLR integration feature enables you to create stored procedures, triggers, UDF, UDT, and user-defined aggregates in managed code, which provides the benefits of memory management, thread synchronization and management, exception handling, type safety, and debugging services.

By default, the CLR integration feature is disabled in SQL Server 2008, which you can enable by using the clr enabled option of the sp_configure stored procedure. Use the following query in SQL Server Management Studio to enable the CLR integration feature:

```
sp_configure 'clr enabled', 1
GO
RECONFIGURE
GO
```

# NOTE

To disable CLR integration feature, set the clr enabled option to 0.

SQL Server 2008, as a host of CLR, defines some permission levels for executing the code. These permission levels are given as follows:

+   - SAFE – Allows local data access and internal computation only. The SAFE permission is the most restrictive permission that does not allow to access external system resources, such as files, network, environment variables, or registry. An assembly that executes a code with SAFE permissions cannot access these external system resources.
+   - EXTERNAL_ACCESS – Allows to access external system resources, such as files, network, environment variables, or registry.
+   - UNSAFE – Allows unrestricted access to internal and external resources from SQL Server. Code executing by an assembly with UNSAFE permissions can also be an unmanaged code.

You can use assemblies from SQL Server 2008, by creating the assemblies in the server. Use the following command in Management SQL Server Studio to create an assembly:

```
CREATE ASSEMBLY myassem FROM 'D:\black Books\C# 2010\Chapter 23'
WITH PERMISSION SET=SAFE
```
