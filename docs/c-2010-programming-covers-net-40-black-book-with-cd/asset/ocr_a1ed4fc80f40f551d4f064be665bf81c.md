# In Depth

Till now we have learned how to access data from databases in our applications through the concepts of ADO.NET and Language Integrated Query (LINQ). We also know that to develop any database for a project, first, a conceptual schema has to be designed based on which the logical schema or model is designed. Earlier, to develop a project, you first had to design a conceptual model on a paper or a whiteboard. This was a time-consuming and error-prone process, where the developer had to remember every detail of data on which the conceptual model was based. We could not even work with entities in our application in the executable form.

To overcome all these problems, ADO.NET introduced the concept of Entity Framework. ADO.NET Entity Framework enables users to visually design models and map databases, tables, and views by using Visual Studio 2010 and .NET Framework 4.0. ADO.NET Entity Framework also provides the users with the capability of programming a conceptual model. The ultimate goal of introducing Entity Framework in programming is to raise the level of abstraction for data programming and help developers to increase productivity.

ADO.NET Entity Framework enables a developer to show essential features of a logical schema of the data and presents its conceptual schema to the application. In a logical schema, the data is stored in the form of tables in a database. For example, details for a product can be stored in the Products table, orders corresponding to products can be stored in the Orders table, and contact details can be stored in the Contacts table. While creating an application that implements these tables, a developer should know about the database in which these tables reside. The disadvantage of using a logical schema is that very often an application has to use the JOIN clause to retrieve data from tables because it is not always necessary that a logical database always represents the required view of the data for an application. In such a case, if the logical schema is changed, the application is also affected and needs modification according to the changed schema.

Let’s explain this with the help of an example. Suppose we need to create a query in an application that returns the names and results of all the students of batch 2008 in a school. For this, we can use the following query:

```
SELECT c.FirstName, s.RollNumber
FROM Students s
INNER JOIN Contact c on s.StudentID = c.ContactID
Where admission date >= '2008-01-01'
```

In the preceding query, the JOIN clause has been used for all the related tables to obtain the result. Based on the preceding syntax, the following are the problems that a developer faces while implementing such a query:

+   - The syntax is complicated, which unnecessarily consumes more effort and time. In this example, to retrieve the required information, the application has to deal with both the tables, that is, Students and Contacts tables.
+   - Sometimes, a logical schema of a database is not capable of using certain part of an application according to the requirement of a developer. In such scenario, the application has to deal with the entire logical schema, which unnecessarily puts additional load on the server.
+   - A logical schema is unable to understand business entities and their relationships among each other because models, such as a relational model, cannot render the conceptual domain knowledge of the application.
+   - If an application deals with a subset of data, the developers should be able to indicate the appropriate subset that is required in the application.

These problems are very common across data-centric applications. To solve such issues, ADO.NET has introduced the concept of Entity Framework, which is designed to solve the mismatch between the formats of data. The data is stored in a database in the form of tables and consumed through object-oriented programming languages. ADO.NET Entity Framework consists of data models and provides design-time and run-time services that allow the developers to describe the application data.

When we use a logical schema, the queries return certain values, which are not related to the source of data. It implies that there is no common relationship among the elements of a database throughout the application about the core application concepts. Entity Framework allows the developers to describe the application data and isolates the application from the underlying logical database schemas.
