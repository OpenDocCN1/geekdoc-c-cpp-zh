## Code-Behind Page Model

In the code-behind page model, there are two separate files, Default.aspx and Default.aspx.cs. The Default.aspx file is used for ASP.NET presentation tags and the Default.aspx.cs file is used as the programming logic to implement the functionality of a Web application. These two files are then linked together to run the Web application. All the different versions of ASP.NET support this model, by default.

The code-behind file uses the partial class rather than the main class and it does not inherit the .aspx file, whereas both the files are combined together during compilation to implement the complete application.

Now, let’s understand the code-behind model through an application named as CodeBehindExampleCS. You can find the code for the Default.aspx page for the code-behind page model in Listing 13.2:

### Listing 13.2: Showing the Code for the Default.aspx Page

```aspx
<%@ Page Language="C#" AutoEventWireup="true" CodeFile="Default.aspx.cs" Inherits="_Default" %>
<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
<html xmlns="http://www.w3.org/1999/xhtml">
<head runat="server">
<title>Code Behind Page Model</title>
</head>
<body>
<form id="form1" runat="server">
<div>
<asp:Label ID="Label1" runat="server"></asp:Label>
<asp:Button ID="Button1" runat="server" OnClick="Button1_Click" Text="Click Me!" >
</asp:Button>
</div>
</form>
</body>
</html>
```

Now, add the code in the code-behind file of the Default.aspx page for the code-behind page model, as shown in Listing 13.3:

using System.Linq;

		Label1.Text = "Clicked at " + DateTime.Now.ToString();
	}
}

## The System.Web.UI.Page Class

Any Web page requested from a server hosting .NET Framework, whether it contains .NET code or HTML text, is actually based on the System.Web.UI.Page class. All Web pages are inherited from the System.Web.UI.Page class. Here is the class hierarchy for the Page class (note that the Control class here is the ASP.NET Control class, not the Windows application’s Control class):

- System.Object
  - System.Web.UI.Control
    - System.Web.UI.TemplateControl
      - System.Web.UI.Page

## ASP.NET Web Page Syntax

ASP.NET Web pages define the markup syntax that you can use to declaratively create ASP.NET Web pages or user controls. The ASP.NET Web page syntax includes the following components:

- Web page directives
- Form elements
- Web server controls

### Web Page Directives

ASP.NET page directives are instructions to specify optional settings, such as registering a custom control and page language. These settings are used to describe how ASP.NET Web form pages (.aspx) or User control (.ascx) pages are processed by .NET Framework.

Page directives can be placed anywhere in a .aspx or .ascx file; although the standard practice is to include them at the top of the file.

The syntax to use a page directive is as follows:

```
<%@ directive {attribute=value}* %>
```

ASP.NET treats any directive block (<%@ %>), which does not contain an explicit directive name, as a @ Page directive (for a page) or as a @ Control directive (for a user control). ASP.NET 4.0 pages consist of the following directives:

- @ Page
- @ Control
- @ Import
- @ Implements
- @ Register
- @ Assembly
- @ Master
- @ PreviousPageType
- @ MasterType
- @ OutputCache
- @ Reference

### The @ Page Directive

The @ Page directive defines page-specific attributes used by the ASP.NET page parser and compiler. It can be included only in .aspx files.

The syntax for the @ Page directive is as follows:

```
<%@ Page attribute="value" [attribute="value"...] %>
```

The @ Page directive is the most important directive in an ASP.NET page. In ASP.NET 4.0, six new attributes for the @ Page directive are included, which are shown in Table 13.8:

**Table 13.8: New Attributes Included in ASP.NET 4.0 in the @ Page Directive**

| Attribute | Description |
|-----------|-------------|
| ClientIDMode | Sets the method used by the ASP.NET page while generating ClientID values for the server controls on that page. The values that can be assigned to this attribute are: AutoID, Predictable, Static, and Inherit. The AutoID value is the default value for this attribute. |
| ClientTarget | Specifies the browser capabilities that the ASP.NET engine should target while rendering the page. |
| MetaDescription | Specifies the page description in the meta tag for the purpose of Search Engine Optimization (SEO). |
| MetaKeywords | Specifies a page keyword in the meta tag for the purpose of SEO. |
| TargetSchema | Specifies the name of the schema that validates the content of the page. |
| ViewStateMode | Specifies whether the ViewState property of the page is the default mode or not. |

> **NOTE**
> Among the preceding six new attributes introduced in the @ Page directive, the MetaDescription and MetaKeywords attributes are included mainly to improve the optimization of ASP.NET site for SEO. This is done because numerous users visit a site through search engines.

### The @ Control Directive

The @ Control directive defines control-specific attributes used by the ASP.NET page parser and compiler. It can only be used in .ascx files (user controls).
