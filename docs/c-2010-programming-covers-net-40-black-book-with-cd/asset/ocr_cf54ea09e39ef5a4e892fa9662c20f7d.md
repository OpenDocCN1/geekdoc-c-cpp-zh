To create an application that access AD objects in C# 2010, you need to perform the following tasks:

+   - Specify a binding path to establish a connection between an application and AD
+   - Create new objects, for instance users
+   - Modify active data objects
+   - Search AD for objects

# Specifying a Binding Path

The process of connecting an application with AD is called binding. You need to provide a binding string to bind an application with AD. An example of binding string is given as follows:

```
LDAP://192.168.1.95/CN=Users, DC=sq1, DC=local
```

A binding string must contain the following items:

+   - Protocol – Identifies the details of an ADSI provider to provide interface to access directory service
+   - Server name – Identifies the name of the domain controller
+   - Port number – Identifies the name of the server process
+   - Distinguished name of the object – Identifies the name of the object that you want to access
+   - Username and password – Identifies the user who is allowed to access AD
+   - Authentication type – Identifies the need for encryption

# Creating New Objects

You can create AD objects for users, computers, printers, and contacts. The DirectoryEntry and DirectoryEntries classes are used to create a new object. An object of DirectoryEntries can be accessed by using the Children property of a DirectoryEntry, as shown in the following code snippet:

```
DirectoryEntry de = new DirectoryEntry("LDAP://192.168.1.95");
DirectoryEntries users=de.Children;
```

Objects can be added, removed, and searched in a collection by using methods provided by the DirectoryEntries class, as shown in the following code snippet:

```
DirectoryEntry user= users.Add("CN=John Doe", "user");
```

You can add properties to AD objects by using the Add() method of the Properties property, as shown in the following code snippet:

```
user.Properties["company"].Add("Any company");
user.Properties["department"].Add("Sales");
```

The properties added should exist in the schema for the user object. If the property does not exist in the schema, you get the COMException exception that displays the The specified directory service attribute or value does not exist message.
