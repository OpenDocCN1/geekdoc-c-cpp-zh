# Lambda Expressions

In .NET Framework 3.5, a new syntax, named Lambda expressions, was introduced for anonymous methods. A Lambda expression is an anonymous function that can contain expressions and statements to create delegates or expression tree types. The Lambda expressions use the Lambda operator =>. The left-hand side of the Lambda operator specifies the input parameter, and the right-hand side specifies the expression or the statement, shown as follows:

```
(input parameter) => expression
```

The parentheses are optional if the Lambda expression has only one parameter. If there is more than one parameter, parentheses become necessary and comma (,) separates the parameters. With Lambda expressions, there is no need to add the variable to the declaration; the compiler does it for you.

The Lambda expression allows you to declare your method code inline instead of with the delegate function. It has a more concise syntax to achieve the same goal.

The Lambda expressions are very helpful in writing LINQ query expressions, as they provide a very compact and safe way to write functions that passes as argument for further evaluation.

# Comparing Lambda Expressions with Anonymous Methods

The Lambda expressions are almost similar to anonymous method, which was introduced with .NET 2.0. The advantage of the Lambda expression over anonymous method is that it provides a more concise and functional syntax for writing anonymous methods. In the anonymous methods, the curly brackets and the return statements are required. The advantage with the Lambda expressions is that the syntax elements are not required, which is automatically managed by the compiler.

There is no basic difference between the two. This is because Lambda expressions are just an extension of the anonymous method to provide a more concise and functional syntax for writing the anonymous methods. In other words, a Lambda expression is an anonymous function that contains expressions and statements and it is used to create delegates or expression tree types.

# Introducing PLINQ

Parallel LINQ (PLINQ) is the parallel implementation of LINQ, in which a query can be executed by using multiple processors. PLINQ ensures the scalability of software on parallel processors in the execution environment. It is used where data grows rapidly, such as in telecom industry or where data is heterogeneous. PLINQ also supports all the operators of LINQ. In addition, you can query collections by using PLINQ. It can also run several LINQ queries simultaneously and makes use of the processors on the system. Apart from this, PLINQ uses parallel execution, by which the queries run quickly.

PLINQ in ASP.NET 4.0 is equipped with the cancellation types that are used to cancel PLINQ queries, by using the WithCancellation() operator. As PLINQ runs on multiple processors, exceptions from multiple threads are common. PLINQ in ASP.NET 4.0 uses the AggregateException type to collect all the exceptions thrown by the threads. The PLINQ’s functionality inherits the System.Linq.ParallelEnumerable class.
