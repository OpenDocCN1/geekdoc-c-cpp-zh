-   名为 Gacutil.exe 的 GAC 工具
-   使用 Windows 资源管理器将程序集拖入缓存

## 强命名程序集

强名称是一个哈希令牌，包含程序集的标识，即关于程序集名称、版本号、区域性、公钥和数字签名的信息。使用私钥，包含清单的程序集文件会生成强名称。你可以使用 Microsoft Visual Studio .NET 和其他开发工具为程序集提供强名称。为程序集使用强名称具有以下好处：

-   通过生成私钥确保名称的唯一性
-   确保你使用的程序集版本与构建应用程序时所用的版本来自同一发布者
-   便于进行完整性检查，确保程序集内容自上次构建以来未被更改

## 私有程序集和共享程序集

如果程序集仅由单个应用程序使用，则称为私有程序集。例如，如果你创建了一个包含业务逻辑信息的 DLL，则该 DLL 只能由你的客户端应用程序使用。为了运行应用程序，DLL 必须放置在与客户端应用程序安装目录相同的文件夹中。这使该程序集成为你的应用程序的私有程序集。

共享程序集是放置在 GAC 中以便多个应用程序使用的程序集。设想一个场景：DLL 需要在不同应用程序中重用。在这种情况下，无需在每个客户端应用程序中复制一份 DLL，而可以使用 Gacutil.exe 工具将 DLL 直接放置在 GAC 中，任何客户端应用程序都可以从 GAC 访问该 DLL。

## 并行执行

在同一台计算机上执行多个版本的应用程序或组件的过程称为并行执行。.NET Framework 支持多个版本的 CLR、应用程序、组件、编译器和运行时并行执行。它允许在同一台计算机上同时安装多个版本的程序集或应用程序。

## .NET Framework 类库

.NET Framework 由类、接口和值类型组成，这些有助于加快开发过程并提供对系统功能的访问。.NET Framework 提供语言之间的互操作性，因为数据类型符合 CLS（公共语言规范），并且可以从任何编译器符合 CLS 的编程语言中使用。

.NET 应用程序、组件和控件基于 .NET Framework 类型构建。这些实体执行以下功能：

-   表示基本数据类型和异常
-   封装数据结构
-   执行输入/输出操作
-   访问有关已加载类型的信息
-   调用 .NET Framework 安全检查
-   促进数据访问、丰富的客户端图形用户界面（GUI）以及服务器控制的客户端 GUI

框架类库（FCL）是一个庞大的可重用类型库，供托管代码使用。它是一个面向对象的库，用于基于组件的应用程序。FCL 由命名空间层次结构组成，这些命名空间公开了类、结构、接口、枚举和委托。命名空间按其功能进行逻辑定义。例如，System.Data 命名空间包含用于访问数据库的功能。该命名空间进一步分为两个命名空间：System.Data.SqlClient 和 System.Data.OleDb。System.Data.SqlClient 命名空间公开了特定于 SQL Server 的功能；而 System.Data.OleDb 命名空间公开了用于访问对象链接和嵌入数据库（OLEDB）数据源的功能。

使用 FCL 时需要记住以下几点：

-   类、接口、结构和枚举值统称为类型。框架中的不同类型按命名空间层次结构排列。这解决了名称冲突的问题。命名空间按层次结构排列，由句点分隔词语。你可以编写使用 Stream 类或 Form 类的代码；然而，在 IL 中，这些类分别表示为 System.IO.Stream 和 System.Windows.Forms.Form。
-   System 命名空间是 .NET Framework 中基础类型的根命名空间。该命名空间包含表示所有应用程序使用的基本数据类型的类，例如 Object、Byte、Char、Array、Int32 和 String。其中许多类型对应于编程语言使用的原始数据类型。
-   所有数据类型都派生自它们的基类型，而这些基类型派生自 System.Object 类。例如，int 数据类型派生自 System.Int32 类，而 System.Int32 类又派生自 System.Object 类。这是因为 System.Object 类是 .NET Framework 中所有类型的基类型。如果你创建的类没有显式声明基类，则编译器会将其基类显式声明为 Object 类。

## Windows 窗体

Windows 窗体是应用程序中显示的任何窗口的图形表示。它是 Microsoft .NET Framework 的一部分。你可以使用任何 CLR 支持的语言创建 Windows 窗体应用程序。Windows 窗体用于接受用户输入或向用户显示信息。在 Windows 窗体中，你向窗体添加控件并引发事件（例如鼠标单击），这些事件由应用程序中的事件处理程序处理。

## ASP.NET 和 ASP.NET AJAX

ASP.NET 是一种 Web 开发模型，用于通过 Internet 提供交互式、数据驱动的 Web 应用程序。它还包含大量控件，如文本框、按钮和标签，用于组装、配置和操作代码以创建超文本标记语言（HTML）页面。你可以使用任何符合 CLR 的语言（如 Visual Basic 和 C#）创建 ASP.NET 应用程序。ASP.NET 的主要功能如下：

-   **更好的性能**——为对同一网页的任何后续调用提供代码输出的缓存副本。当你第一次请求网页时，CLR 会编译网页代码并存储结果的缓存副本。现在，对于同一页面的任何后续调用，都会检索结果的缓存副本，而不是返回服务器。
-   **更高的安全性**——提供以下四种身份验证方法：
    -   **表单身份验证**——将未经身份验证的请求重定向到 HTML 表单。在表单身份验证中，用户提供凭据并提交表单。如果请求由应用程序进行身份验证，系统会颁发包含凭据的 Cookie，用于重新获取身份。
    -   **护照身份验证**——指定一种集中式身份验证服务，为成员站点提供登录和核心配置文件服务。
    -   **Windows 身份验证**——与 Microsoft Internet 信息服务（IIS）身份验证结合使用。IIS 使用基本、摘要或集成 Windows 身份验证中的一种方式。
-   **更高的可伸缩性**——支持多个 Web 服务器之间的跨服务器会话。这是因为 ASP.NET 中的会话状态在另一台机器或数据库上的单独进程中维护。
-   **无 Cookie 会话**——即使 Web 浏览器中的 Cookie 被禁用，也能存储会话状态。

异步 JavaScript 和 XML（AJAX），以前代号为 Atlas，是 ASP.NET 的扩展，用于开发和实现 AJAX 功能。ASP.NET AJAX 同时启用客户端和服务器端组件，使开发人员能够创建无需完全重新加载页面即可更新网站数据的 Web 应用程序。以下是使用 AJAX 的优点：

-   **异步**——支持对 Web 服务器进行异步调用，无需用户等待数据。
-   **最少的数据传输**——仅向 Web 服务器发送部分修改后的数据，从而最大限度地减少网络流量，并更快地执行操作。此功能在允许受限管道进行数据传输的站点中非常有用，从而提高网络性能。
-   **Web 服务器上的处理最少**——由于只需发送必要的数据，因此最大限度地减少了 Web 服务器上的处理。
-   **上下文**——通过客户端脚本将请求发送回服务器，从而减轻服务器负担。基于 AJAX 的应用程序实现部分页面回发而不是整页回发，从而减少了客户端和服务器之间的数据流量。

## ADO.NET

ADO.NET 是一种用于处理数据和数据库的技术。你可以使用 ADO.NET 连接数据源，以检索、操作和更新数据。

ADO.NET 技术的一些功能如下：

-   **断开式数据架构**——意味着应用程序仅在需要检索或修改数据时才连接到数据库。执行完数据库操作后，与数据库的连接将关闭。要再次执行任何数据库操作，需要重新建立与数据库的连接。不遵循断开式数据架构的应用程序会浪费大量宝贵的系统资源和时间，因为这些应用程序即使在没有必要时也需要保持与数据库的连接。
-   **数据集中的缓存数据**——遵循断开式架构来访问或修改数据。因此，数据集中的缓存数据使应用程序无需连接数据库即可处理每条记录。数据被访问后存储在数据集中。数据集是数据库记录的缓存集，即数据集不依赖于数据源。即使你与正在处理的数据库断开连接，你仍然可以在其中进行修改。
