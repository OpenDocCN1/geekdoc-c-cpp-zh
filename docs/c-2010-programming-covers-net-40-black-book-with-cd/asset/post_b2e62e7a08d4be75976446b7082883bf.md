## In Depth

A Web service may be defined as an independent and self-sustained unit of a software application hosted on the Internet. A Web service implements specific functionalities to execute the business logic of the application. A Web service can be used to implement various functionalities, such as preparing the pay slips for the employees of a company, calculating the income tax, broadcasting weather reports, and providing updated news. In .NET Framework 4.0, you can create Web services. A Web service created in ASP.NET 4.0 is known as ASP.NET 4.0 Web service and consists of an infrastructure that contains various components used to implement basic functionalities to a Web service, such as locating a Web service, calling a Web service, and so on. You can also use the code model and properties of an ASP.NET Web service while creating Web services. You can also create Web services that use the ASP.NET AJAX functionality. In addition, security measures to check unauthorized access to Web services also need to be incorporated in the Web services created.

In this chapter, you learn about Web services, infrastructure of ASP.NET Web services, code model of ASP.Net Web services, Web service properties, securing Web services, and the use of ASP.NET AJAX with Web services. You also learn how to create an ASP.NET Web service, how to use an ASP.NET Web service, how to share data across Web services, how to do communication between Web services asynchronously, how to work with ASP.NET AJAX-enabled Web services, and how to use an UpdatePanel control with a Web service.

## Introducing Web Services

A Web service is an entity that you can program to provide a particular functionality to applications over the Internet. Suppose you want to host a website on the Internet that calculates the simple interest, compound interest, and income tax of an individual. To do this, you can use a Web service to calculate the simple interest, compound interest, and another Web service to calculate the income tax. In this scenario, a Web service is advantageous in the sense that you do not need to write the code in the Web site for calculating the simple interest, compound interest, and income tax. Instead, all you have to do is to use the Web services that provide these functionalities. You need to subscribe to the Web service before using a Web service in your website.

A Web service allows a website to communicate with other websites irrespective of the programming languages in which they are created. In addition, a Web service can be accessed by any application, regardless of the software and hardware platforms on which the application is running, because the Web service complies with common industry standards, such as Simple Object Access Protocol (SOAP) and Web Services Description Language (WSDL). A Web service does not have any user interface; it only contains the logic for providing specific services to its consumers. A Web service provides an abstraction between the consumer (client) and the provider of the Web service. The Web service only need information about input, output, and location of the client and Web service provider. Before the introduction of Web services, developers employed technologies, such as Component Object Model (COM) and Distributed Component Object Model (DCOM), to use the functionality of one application in another application. These technologies allowed a developer to create code components once and bundle the components so that they could be shared across multiple applications by multiple developers. However, there were some fundamental difficulties in using these components. One such difficulty was that these components needed to be physically distributed and explicitly registered on each client machine. Web services overcome these difficulties as they can be shared among multiple websites without the need to install them on each individual client machines.

Web services have become popular because of the added functionalities they provide over component-based technologies. The advantages of Web services over COM and DCOM are as follows:

- Web services are simple to use; and consequently, they can be implemented on varied platforms
- Web services are loosely coupled; as a result, their interfaces and methods can be extended
- Web services do not carry any state information with them so that multiple requests can be processed simultaneously

Web services are most appropriate while communicating across platforms or enforcing trusted connections between the server and the client. In addition, it is a good practice to use Web services under the following circumstances:

- Using caching features of ASP.NET
- Using Secure Socket Layer (SSL) security or Windows authentication
- Integrating ASP.NET Web applications with third-party systems

## Infrastructure of ASP.NET Web Services

The infrastructure of ASP.NET Web services provides a simple Application Programming Interface(API) for Web services to create and understand SOAP messages that in turn help to invoke remote methods. Web services must not be dependent on the selection of the operating system, object model, and programming language. As with other Web-based technologies, Web services should be loosely coupled, should be able to communicate when needed, and have a universal data format to transfer data between the services and its users. The mechanisms included in the infrastructure of a Web service are as follows:

- Consists of a directory that provides a central location for Web service providers
- Consists of a discovery mechanism to locate Web services
- Consists of a service description to know how to use those Web services
- Consists of standard wire formats (protocols) to transmit data between Web services and its users

### Web Services Directory

The Web service directory provides a central location for Web service providers. In other words, it is a place where Web service users (consumers) can easily locate services offered by other companies and organizations. It is difficult to search a Web service without using any resource. Web service directories provide those centralized locations where you can publish information about your Web service. A Web service can be a directory for other Web services and can provide the result of the query to the Web service client. You need Web service directories to know about Web services provided by either multiple organizations or a particular organization. The Web service can be published and discovered by using the specification called Universal Description, Discovery, and Integration (UDDI). The schema associated with UDDI defines four types of information for Web services: business, Web service, binding, and specifications. These information types enable a developer to use a published Web service.

### Web Services Discovery

The Web service discovery provides the capability to locate Web services. This component locates documents that describe a particular Web service, through WSDL. If you want to use a Web service in your website, you first need to know where the Web service is located. On the other hand, if you want other people to use your Web service, they also need to know where your Web service is located. In such a case, there must be a searching (discovery) mechanism, which can locate the required Web service. The following two methods are used to search the Uniform Resource Locator (URL) of a Web service:

- The Web services discovery tool (Disco.exe) – Used for publishing and discovering Web services. This tool discovers URLs of all the Web services located on a Web server and creates a list of them in a file called the DISCO file (a file with the .disco extension). An organization can publish its own DISCO files on its Web server. This file can be accessed by clients to know about the kind of Web services an organization provides.
- UDDI – Centralized directory where Web services offered by different organizations are published. It is a platform-independent method that is built into the .NET platform. A UDDI directory has an advantage over a DISCO file in that the directory provides a single location where clients can search the Web services offered by different organizations.

The following are some of the important features of UDDI:

- Acts as a directory and stores information about Web services
- Uses the World Wide Web Consortium (W3C) and Internet Engineering Task Force (IETF) Internet standards, such as eXtensible Markup Language (XML), Hypertext Transfer Protocol (HTTP), and Domain Name Server (DNS) protocols
- Uses WSDL to describe interfaces to Web services
- Communicates through SOAP

Some benefits of using UDDI are:

- Helps to search for the right business organization from the millions of business organizations that are currently online
- Enables commerce, once the preferred business is discovered
- Helps to reach new customers and increase access to current customers
- Helps to expand offerings and market reach
- Allows rapid participation in the global Internet economy
- Describes Web services and business processes programmatically in a single, open, and secure environment

### Web Services Description

The Web service description provides the description of a Web service in the XML format, known as WSDL. A WSDL document defines message formats, such as HTTP-GET and HTTP-POST, to facilitate communication between a Web service and a client. A message pattern determines how the messages can be exchanged between a client and a service. A Web service defines and supports some message patterns, such as request/reply, one-way, or duplex. The behavior of a Web service depends on these message patterns, which theoretically state the requirements of a Web service user when a message is submitted to it. Now, Let’s discuss WSDL in more detail. WSDL is an XML-based language that defines Web services. Every Web service consists of a corresponding WSDL document that specifies the location of the Web service and lists all the services that the Web service can perform.
