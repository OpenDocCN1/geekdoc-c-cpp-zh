Now, let’s look at static and dynamic resources in detail.

# Static Resources

Static resources are resources that you do not intend to change after they are referenced the first time. These resources are always loaded on the creation of a window. You can reference a static resource by using the StaticResource Markup Extension, which processes the key whose value is looked up in the entire resource dictionary. This whole processing happens during the load process.

A static resource references resources from within a resource dictionary. You should define the resource dictionary in your application before you reference the static resource. A new static resource provides a value by looking up a reference to an already defined resource.

There are certain restrictions on using static resources. For example, it is not recommended to use static resources during run time. This is because static resources are not assessed at run time and using them during this time will throw an exception. The behavior of an exception varies if the reference to a static resource is not found. For example, if the resource is deferred, then the exception occurs at run time and if it is not deferred, the exception occurs at load time.

Static resources follow a lookup process for their implementation, the first step of which involves checking for the requested key within the resource dictionary. The key is defined by the element that sets the static resource. The process then moves to the logical tree upwards to the parent element and then to its resource dictionary. This process continues till the root element is reached. Finally, the application resources are checked.

# Dynamic Resources

Dynamic resources are those resources that can be changed after they are referenced for the first time. A dynamic resource is applied using the DynamicResource Markup Extension, which processes a key by creating an expression. This expression remains unchecked until the application is actually run.

The value of dynamic resources depends on the conditions that are not known until run time. For example, the system colors and system fonts are truly dynamic because they come from the runtime environment of the user and the operating system.

Dynamic resources are referenced for a custom control. You need to adjust the content of the ResourceDictionary class during an application lifetime for using dynamic resources. You can use dynamic resources when you are creating a style where setter values might come from values that are influenced by the user settings.

The lookup process of the dynamic resource is also a bit different from the static resource. The lookup process for dynamic resources checks for the requested key. This key is located within the resource dictionary that sets the property of the element. For example, if the element defines a Style property, then the Resources dictionary within the Style property is checked. The lookup process then tracks the logical tree to the parent element and its resource dictionary. The process continues until the root element is reached. Next, the application resources and the theme resource dictionary are checked. The theme resource dictionary is checked for the theme that is currently active. If the theme changes at run time, then the value is re-evaluated. Finally, the system resources are checked.

During the lookup process, the exception behavior varies. For example, if the resource is requested by a FindResource call, and not found, an exception is raised.

Dynamic resources also have some restrictions from which at least one must be true for the proper implementation of the resources. The first restriction is that the reference of the dynamic resource should be a value within the Style class. The second restriction is that the property being set must be a property of the Freezable class.
