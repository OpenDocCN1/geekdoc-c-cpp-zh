# Creating a New Version of the Shared Assembly

Let’s now create a new version of the SharedObject class library and configure the client application to use this new version without recompiling it. To do so, you first need to modify the Greeting function. Listing 33.8 shows the code to modify the Greeting function of the SharedObject class library:

# Listing 33.8: Showing the Code to Modify the Greeting Function

```
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;
namespace SharedObject
{
    public class SharedObject
    {
        public string Greeting(string name)
        {
            return ("New SharedObject says Hi: " + name);
        }
    }
}
```

To reflect the new version information in the CLR, you need to update the AssemblyInfo.cs file. The version information in the AssemblyInfo.cs file can be updated by using the following line of code:

```
[assembly: AssemblyVersion("1.1.0.0")]
```

# Using the New Version of Shared Assembly

As you know, the .NET compiler connects the client application to the requested version of the shared assembly. However, if you want to configure a specific client application to use only a specific new version of a shared assembly instead of the old versions, you need to write an application configuration file. This application configuration file must be placed in the client application directory. The name of the configuration file is the same as the name of the client application, with the .config extension appended to it. The application configuration file contains blocks of Extensible Markup Language (XML) that customize the binding process between a client application and a shared assembly.
