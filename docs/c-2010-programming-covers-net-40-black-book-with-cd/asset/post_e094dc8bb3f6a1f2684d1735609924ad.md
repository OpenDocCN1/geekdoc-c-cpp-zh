## Enumeration Type

Enumerations are the user-defined integer data types that are declared using the enum keyword. Using enumeration, you can define a set of named integral constants that can be assigned to a variable. For example, you might have a program that models a traffic light. Traffic lights have three possible states—the green light indicating go, the yellow light indicating get prepared to stop, and the red light indicating stop. A traffic light can have only one of these states at a time, implying that the traffic light can be only red, yellow, or green at a time. In such a case, you can define enumeration type variable and assign 3 values to it. The following code snippet shows how to create enumeration type:

```
enum TrafficLight
{Red, Green, Yellow}
```

To use the enumerated type, you need to declare a variable of the new enumeration type, as shown in the following code snippet:

```
TrafficLight t1;
```

The TrafficLight enumeration can take any of the three values, Red, Green, and Yellow; i.e. enumeration can take only those values that are defined while creating the enumeration type, as shown in the following code snippet:

```
t1 = TrafficLight.Red;
t1 = TrafficLight.Green;
t1 = TrafficLight.Yellow;
```

Enumerations, by default, begin with the value of 0 for the first entry. However, you can modify this value by entering a different value for the first entry, as shown in the following code snippet:

```
enum TrafficLight
{
Red=1, Green, Yellow
}
```

## Reference Types

C# also provides types that are passed by references to calling functions, known as reference types. Variables that refer to the objects store the reference of the actual data. In reference types, any changes made in the new copy modify the old copy to which the object is referenced. The reference types use heap to store the references instead of the actual data. In C#, heap is called managed heap, as it manages and maintains a pointer to the address where the next object is to be allocated. Initially, the pointer is addressed to the heap’s base address, and when the first reference is created, the memory is allocated at the base address. When the next object is created in an application, the garbage collector allocates memory for it in the address space just next to the first object and continues to allocate memory for all the newly created objects. C# provides some built-in reference types, which are as follows:

- dynamic type — Performs the type checking of the dynamic type variable at run time instead of compile time. You can add any type of value in the dynamic type variable. This type is similar to the object type; the difference is that the type checking of the variable of object type is performed at compile time. The following code snippet shows how to declare a dynamic type variable:

  ```
  dynamic dyn = 10;
  ```

- object Type — Enables you to assign values of any type to the variables of object type. Object is an alias for the predefined System.Object class. The object type is the ultimate base class for the other types in Common Type System (CTS), such as value types, reference types, predefined types, and user-defined types. All these types are derived directly or indirectly from the object type. The object type can be assigned a value of any other types, but before assigning a value it requires the type conversion. When a value type is converted to the object type, the process is known as boxing and on the contrary, when an object type is converted to the value type, the process is known as unboxing. The following code snippet shows the use of object type:

  ```
  object x;
  x=15; //boxing
  ```

  The first line of the preceding code snippet creates a variable x of object type and the second line assigns value 15 to the x variable. The process of assigning the converted value to the object type is called boxing

- string Type – Enables you to assign string values to the variables of string type. The string type is an alias for the System.String class. It is the unchangeable sequence of Unicode characters contained within double quotes. The string type is a sealed class type that is directly derived from the object type. After creating an object of string type, you cannot change its value. The value for a string type can be assigned using the string literals in two forms – quoted and @-quoted.

  The following code snippet shows how to assign values to string types:

  ```
  string sname="C# 2010";
  ```

  In the preceding code snippet, sname is a string variable having a value C# 2010.

  The @-quoted string literals are written within the double quotes prefixed by the @ character. This is illustrated in the following code snippet:

  ```
  @"Kogent Learning Solutions Inc"
  ```

The reference types can be declared using any of the keywords – class, interface, or delegate. In addition, the reference types also use built-in reference types – dynamic, object, and string. Let’s discuss about these keywords starting with class.

## Classes

In C#, all classes are user-defined data types and are considered as objects. All objects are derived from a single base class, called System.Object. It defines all the objects to the system and treats them in the same way. When you pass an object to a function, you can find out what kind of object you are dealing with by using them as keywords.

All applications in C# are based on a class. Unlike C++ or C, you cannot have a simple function that acts on its own. All C# Console applications contain a single static method, called Main. Listing 2.4 shows the code of a class in a basic C# application:

### Listing 2.4: Showing a Class in a Basic C# Application

```
class Greetings
{
    static void Main()
    {
        System.Console.WriteLine("Hello world from C#");
    }
}
```

In Listing 2.4, we have defined a simple class, called Greetings that normally resides in a file named Greetings.cs. When compiled, it forms an executable file named Greetings.exe that runs from the command-line. This executable file fetches the Console object from the System namespace and invokes the static WriteLine() method of that object. This method returns the string, Hello world from C#, as output to the console device.

## Interfaces

Interfaces define a set of functionalities that can be related to any class or struct. Interfaces in C# are similar to interfaces in Java, but are more flexible in their implementation. If you are accustomed to C++, an interface in C# is the equivalent to an abstract base class in C++. It is important to note that you cannot instantiate an object through an interface. When you create an interface, you define a set of functionalities that implements a specific task.

You can declare an interface in a similar manner as any other class. However, it makes use of the interface keyword to differentiate it from other classes. Interfaces behave similar to templates that have method declarations in them. These methods are abstract in nature, i.e. they do not have implementation of methods in the method body. A class that implements a particular interface needs to use all the methods of that interface; otherwise, the compiler does not compile the code and raises an error.

You can declare an interface in C# by using the following syntax:

```
interface Interface_name
{
    //abstract method declarations in interface body
}
```

In the preceding syntax, the interface keyword declares the interface named Interface_name. Interfaces are discussed in detail in Chapter 5, Object-Oriented Programming in C# 2010.

## Delegates

A delegate is almost equivalent to function pointer in C++ or C. C# contains two kinds of objects—those that create a change and those that respond to the change. A delegate acts as the tunnel between the two kinds of objects—moving information from one side to another. C# delegates are class methods and can be either static or instance class methods. A delegate can keep a track of its own state by maintaining information in the object to which it belongs.

You can create a delegate by using the delegate keyword, as shown in the following code snippet:

```
public delegate int IntDelegate(int a);
```

A simple delegate type is not a method or a function. In fact, it is a definition of a function pointer. You cannot directly use a delegate; you need to associate a function with it.

Now, let’s create a class that uses a delegate to accomplish an internal task from an external source, as shown in Listing 2.5:

### Listing 2.5: Showing the Code of a Class Using a Delegate

```
public delegate int IntDelegate(int a); //creating a delegate
class Calculator
{
    public static int SquareNum(int num)
    {
        return num * num;
    }
}
class DelegateUser
{
    static void Main(string[] args)
    {
        Console.WriteLine("Demonstrating a Simple Delegate");
        IntDelegate delObj = new IntDelegate(Calculator.SquareNum); /*initializing and calling a delegate */
        Console.WriteLine("The square of 5 is {0}", delObj(5));
        Console.ReadLine();
    }
}
```

In Listing 2.5, we have created a delegate named IntDelegate. Next, we have declared a variable, delObj, of type IntDelegate, assigned new object to it, and invoked the delegate by passing the SquareNum() method of Calculator class.

## Pointer Types

A variable that holds the memory address of another type is known as a pointer. Pointer types are used as the data type of variables declared as pointers. In C#, pointer types offer the same capabilities as offered by C and C++ languages. Both, pointers and references represent memory address but the difference is that references are tracked by the garbage collector and pointers are not. While maintaining type safety and security in the context of references, C# uses delegates instead of pointers. However, you can use the unsafe keyword to define an unsafe context where you are free to use the pointers. A pointer type can be declared using the following syntax:

```
type* identifier;
```

The following code snippet shows how to create a pointer variable:

```
char* c;
int*[] x;
```
