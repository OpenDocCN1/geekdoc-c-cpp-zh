## The BitmapSource Class

In WPF, you use the codecs to decode or encode a specific image format. WPF includes codecs for the following types of images, such as BMP, JPEG, TIFF, PNG, Windows Media Photo, GIF, and Icon. The BitmapSource class is an abstract class and it is used to decode and encode images. It can perform either of the two functions; either it can be an individual frame of multiple-frame images or it can be the result of a transform performed on it. It is not used to represent a multi-frame image or an animation. The BitmapSource class represents the single, constant set of pixels at a certain size and resolution. The inheritance hierarchy of the BitmapSource class is as follows:

```
System.Object
  System.Windows.Threading.DispatcherObject
    System.Windows.DependencyObject
      System.Windows.Freezable
        System.Windows.Media.Animation.Animatable
          System.Windows.Media.ImageSource

```

The BitmapFrame class is used to store the actual bitmap data of the image format. The formats, such as GIF and TIFF, support multiple frames per image, but some image formats support only a single BitmapFrame object.

## Image Metadata

Metadata describes the content or characteristic of the file. There is different metadata associated with each image, but WPF imaging provides a uniform way of storing and retrieving metadata for each image. You can access the metadata of the image through the Metadata property of the BitmapSource object. The Metadata property returns a BitmapMetadata object that includes all the metadata information contained by the image. The BitmapMetadata object can be a single schema or a collection of schemas. The image metadata schemas supported by WPF imaging are Exchangeable Image File (Exif), tEXt (PNG Textual Data), image file directory (IFD), International Press Telecommunications Council (IPTC), and Extensible Metadata Platform (XMP).

If the BitmapMetadata object is exposed by a BitmapFrame object that is obtained by using the BitmapDecoder class, it is read-only by default. The mutable operations throw an exception. If the BitmapMetadata object is exposed by a BitmapFrame object that wraps another BitmapSource object, it is mutable on construction. You can use the GetQuery() and SetQuery() methods to read and construct metadata queries, respectively.

## Audio and Video

In this section, you learn two more areas of WPF, audio and video. WPF gives you the ability to play a wide variety of sound formats, which includes anything supported by the Windows Media Player. Similarly, WPF also supports video formats that include the Moving Picture Experts Group (MPEG) and Windows Media Video (WMV) files. You can also integrate the audio and video into the rest of the WPF application. For example, you can use video and combine it with 3-D objects and animation. You can integrate the audio and video content in your application. WPF uses the MediaElement control for playing both video and audio.

### MediaElement and MediaPlayer Classes

The MediaElement and MediaPlayer classes are used in WPF to present audio, video, and video with audio content. The MediaElement class is a UIElement and can be consumed as the content of many controls. It can be used in XAML as well as in code. The MediaPlayer class is designed for Drawing objects. The MediaPlayer class cannot be used in XAML. You cannot declare an instance of the MediaPlayer class in XAML; you cannot load and play the media without using the code. To play media in XAML, you need to use the MediaElement control.

The MediaPlayer class is found in the System.Windows.Media namespace. You need to create a MediaPlayer object, and then call the Open method to load the audio file, and call the Play() method to begin it playing. The audio played using the MediaPlayer class is played asynchronously; there is no option of synchronous playback. The inheritance hierarchy of the MediaPlayer class is as follows:

```
System.Object
```
