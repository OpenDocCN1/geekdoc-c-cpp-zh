In the preceding syntax, access-modifier is the modifier that determines the accessibility of the event; event is a C# keyword; type is the type of the event, which should necessarily be a delegate type; and the event-name is any valid C# identifier.

You need to define a method to listen to an event (that represents the event listener, which is called by the corresponding delegate) to handle the event and then bind this method to the event using the overloaded += operator, as follows:

```
class-object.event-name += new class-object.delegate-name(method-name);
```

Similarly, when you wish to detach from a source of events, you can use the overloaded -= operator, as follows:

```
class-object.event-name -= new class-object.delegate-name(method-name);
```

Let’s consider a scenario where a system object tracks the state of a database and its records. When the database manager object adds, deletes, or even modifies a row, it directly notifies this system object that the database has been changed. This process is time consuming because the database manager needs to know all the internals of the system object. If the system object is changed, or the additional system objects are added, the program needs major modifications to reflect changes.

C# provides event sources and event handlers that help in solving the problem of object notifications, without requiring detailed information about external objects within the event-generating system.

Let’s now learn about event sources, event handlers, events and delegates, and multiple event handlers.

# Event Sources

An event source is an object that notifies other objects or tasks that something has happened. Event notification in C# takes the form of callbacks. The event source sends out a general message when it wants to notify other objects about a change, and then any object interested in the message can read and interpret it. The event handling is in the form of publish-and-subscribe, which requires a generalized broadcast mechanism and that all objects receive all messages.

In C#, each event source maintains all the events published by it. Events in C# are considered to be asynchronous from the perspective of the caller. The occurrence of a callback depends upon the event-firing object rather than its caller.

# Event Handlers

Event handlers receive event notifications. When an event source notifies that an event is called, all the event handlers that have registered for the notification of that event start executing. An event handler may be either a static or a non-static method of a class. In case of a static method, event handlers simply respond to a given event source and take a course of action based on the information passed to the handler. The entire state of the object can be considered allowing an object to make decisions for a given event for non-static event handlers.

Let’s consider an event handler that deals with the problem of account underflows. The event of account underflows occurs when the owner of an account withdraws an amount that would make the account negative. In such a situation, you might want to send the user an email message to notify him that unless the account is brought to balance that day, the user is charged a fee. To do this, the event handler needs to be notified of the fact that a debit had driven the balance negative.

# Events and Delegates
