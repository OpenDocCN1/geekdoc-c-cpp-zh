When you enable Windows authentication in IIS, by default, the Negotiate authentication protocol is used. The Negotiate protocol negotiates with the Web browser to determine whether NTLM or Kerberos authentication is used. If both the Web server and browser support Kerberos, then the Kerberos authentication is used; else, NTLM authentication is used. The Kerberos authentication uses the Windows domain controller on the client, therefore, if the user has a Windows user account, then IIS may use Kerberos authentication. However, if the user is a non-Windows user or if there are no server proxies between the Web server and the client, then IIS may use NTLM authentication.

NTLM authentication is the default authentication for the Negotiate authentication protocol. You can see this default setting in the applicationHost.config file that is located in the C:\Windows\System30\inetsrv\config folder. In the applicationHost.config file, there is a <windowsAuthentication> element, as shown in the following code:

```
```xml
<configuration>
.
<system.webServer>
.
<security>
.
<authentication>
.
<windowsAuthentication enabled="false">
<providers>
<add value="Negotiate" />
<add value="NTLM" />
</providers>
</windowsAuthentication>
</authentication>
</configuration>
```
