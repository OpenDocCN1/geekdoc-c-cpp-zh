# In Depth

Microsoft ActiveX Data Objects.NET (ADO.NET), a part of Microsoft .NET Framework, allows your application to easily communicate with file-based and server-based data sources. ADO.NET libraries appear under the System.Data namespace in the .NET Framework. The most important use of ADO.NET is to communicate with the data and provide data access services to the .NET Framework. It provides access to various kinds of data, such as XML, relational, and application data. In addition to data access, it supports creation of front-end database clients and middle-tier business objects.

ADO.NET provides consistent access to data sources, such as SQL, XML, and data sources accessed through Object Linking and Embedding Database (OLE DB), and Open Database Connectivity (ODBC). It also separates data access from data manipulation and includes separate data providers for connecting to a database, executing commands, and retrieving results.

In this chapter, you learn about data access with ADO.NET. You also get acquainted with database and its various components. In addition, you learn about the basic SQL statements. You also learn about the ADO.NET architecture and its various components. Finally, you learn about the ADO.NET Entity Framework.

# Understanding Databases

Database in simple terms means a collection of structured information. It stores information in an organized and structured manner to facilitate the retrieval as and when required. Databases have become more complex over the years; however, the fundamental concept is still a simple one. For example, suppose you are a teacher, who requires to allot the grades for each student. You might make a table on a paper and enter the grades of the students in that table and name it, the studentstable table. In this example, you have already created a database—or more specifically, a database table on paper. Now, you can make the similar table on the computer that allows you to sort, index, update, and organize any size of tables in an easy way.

A collection of records, that is, rows of records, where each column is a field, becomes a table. In its most common form, a database is merely a collection of one or more tables. However, there is another type of database as well—relational database. It is called so because the relational databases are set up such that the data in multiple tables can be related to one another. To make a table relational, you select certain fields to be primary keys and foreign keys.

The primary key in a table is usually the most important one—you can differentiate between records containing duplicate values on the basis of primary key, as the primary does not contains duplicate value. The foreign key usually represents the primary key in another table, which gives you access to that table in an organized way. For example, you might add a field called studentsid to the studentstable table. The same field, studentsid, may be the primary key in the school registrar’s database table that lists all students. In our table, the studentsid field is then a foreign key, allowing us to specify individual records in the registrar’s table.

You can work with the data present in a database by using Structured Query Language (SQL), which has been elaborately defined later in this chapter. You use SQL to set up a query, which, when applied to a database, typically returns a DataSet of records that matches your SQL query. For example, you may set up a query to get information about all the students who got B grade or better. You can do several things, such as inserting new records, creating new tables, and getting DataSets by using SQL.

Therefore, you can use SQL to filter out the records you do not want and then work on them. Visual C# has a built-in tool (the Query Builder) that allows you to create SQL statements visually.
