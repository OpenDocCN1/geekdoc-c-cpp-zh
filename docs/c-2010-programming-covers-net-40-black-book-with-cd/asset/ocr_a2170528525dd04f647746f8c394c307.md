# Listing 7.1: Showing the Use of Dynamic Data Type

```
class Program
{
    static dynamic dyn = 1;
    public void Method1(string str)
    {
        Console.WriteLine(str);
    }
    static void Main(string[] args)
    {
        Program p = new Program();
        //This method compiles and runs successfully.
        p.Method1("Hello");
        //This compiles successfully but, shows an error at run time.
        //The value type of dynamic dyn variable is int.
        p.Method1(dyn);
    }
}
```

In Listing 7.1, you can see that the Method1 method does not identify the value type of the dynamic data type at the compile time. The data type of the dyn parameter is int, which is identified at the run time.

# Exploring Dynamic Language Runtime

The DLR adds a set of services, such as expression trees, call site catching, and dynamic object interoperability for integrating dynamic languages, such as Python and Ruby to the CLR. The main advantage of a dynamic language is that it can identify the data type of an object at run time. However, in case of statically-typed languages, such as C# or Visual Basic, data type of an object must be specified at design time; otherwise, the compiler will raise an error.

In Visual Studio 2010, apart from enabling the dynamic languages to run on the .NET Framework, the DLR also provides dynamic features to statically-typed languages to enable their interoperation with dynamic languages. The libraries that support dynamic interoperation can also be created using DLR. This enables the user of these libraries to write simple code for operating with objects and accessing object members. For example, the following code snippet can be used to increment a counter in XML in C#:
obj.SetProperty("Count", ((int)GetProperty("Count")) + 1);

Following code snippet shows an alternative to perform the same operation using DLR:
obj.Count += 1;

Similar to CLR, the DLR is also a part of the .NET Framework whose installation package is provided with Visual Studio 2010. The System.Dynamic and System.Runtime.CompilerServices namespaces hold the classes for DLR.

Let’s briefly discuss the various advantages provided by the DLR.

# Advantages of DLR

You have already learned that DLR allows you to integrate dynamic languages with the CLR. The DLR allows you to develop the dynamic languages by adding the dynamic features to these languages. For example, Microsoft has developed IronRuby and IronPython languages, which are based on the dynamic languages Ruby and Python. The various advantages provided by the DLR are:

+   - Allows you to easily implement the dynamic languages to the .NET Framework. To use DLR, the language requires to create expression trees, which contain language-level code in a tree-shaped structure, runtime helper routines, and optional dynamic objects that implements the IDynamicMetaObjectProvider interface. The DLR and the .NET Framework together automate huge code analysis and generate code, which helps you to concentrate only on exclusive language features.

+   - Provides dynamic features to statically-typed languages. The statically-typed .NET Framework languages, such as C# and Visual Basic can create dynamic objects and use them together with statically-typed objects.
