```
// Data contract is not required since both the parameter
// and return types are primitive types.
[OperationContract]
double Area(int area);
// Data Contract is not required because both the parameter and return
// types are marked with the SerializableAttribute attribute.
[OperationContract]
System.Drawing.Bitmap GetImage(System.Uri pictureUri);
// The MyComplexTypes.ReservationForm is a complex type,
//So, a Data Contract is required.
[OperationContract]
bool ApproveReservationForm(MyComplexTypes.ReservationForm rf);
}
```

# Data Contracts

A data contract is an agreement between a client and service that conceptually depicts the data to be exchanged. The communication between the client and the service does not require the same types; however, requires the same data contract. Unlike service contracts, which can handle only simple types, a data contract can handle complex types. It means that a data contract can handle a complex service call; calls which have complex type arguments and return complex type values.

In WCF, service contracts are defined through interfaces, but data contracts are defined through classes. These classes are prefixed with the DataContractAttribute attribute, and their members are prefixed with the DataMemberAttribute attribute.

Listing 19.3 shows how to apply the DataContractAttribute and DataMemberAttribute attributes in an application to create the MyComplexTypes.ReservationForm type:

# Listing 19.3: Showing the Code for Applying the DataContractAttribute and DataMemberAttribute Attributes

```
namespace MyComplexTypes
{
    [DataContract]
    public class ReservationForm
    {
        private int rfid_value;
        // Apply the [DataMember] attribute to the property.
        [DataMember]
        public int ReservationFormId
        {
            get { return rfid_value; }
            set { rfid_value = value; }
        }
    }
}
```

# Behaviors

Behaviors are used to customize the runtime behavior of the service endpoint. They also allow you to add custom extensions to services to inspect and validate service configuration or modify runtime behavior of the applications. You can apply behaviors to your WCF service either through the configuration file or through the attributes provided for it. Following is a list of behaviors used by the WCF services:

+   - Service Behaviors — Identifies service-wide implementation behavior at the service implementation (class) level. You cannot apply this attribute at the contract (interface) level.

+   - Contract Behaviors — Implements the IContractBehavior interface to extend the runtime of the client and service.

+   - Endpoint Behaviors — Implements the IEndpointBehavior interface to modify the runtime of a service or client for a specific endpoint.
