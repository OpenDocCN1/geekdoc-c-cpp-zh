The per-call instantiating service is the default instantiation service that you can activate only in progress. In per-call instantiating service, every client request gets a new committed service instance, even if the client calls a service for the second time. Figure 19.1 shows how you can work with a per-call instantiating service:

![](img/e073a4882197be4ab61103cbe0bcb394_997_0.png)

In Figure 19.1, you can see that a client calls the proxy server, which further forwards the call to a WCF service. After receiving the call, WCF creates a service instance and calls the IDispose.Dispose method on it. After the method call returns, WCF calls the IDispose interface.

To configure a per-call instantiating service as a service type, you can apply the ServiceBehaviorAttribute attribute in an application with the InstanceContextMode property set to InstanceContextMode.PerCall. The following code snippet shows how to configure a per-call instantiating service:

```
[ServiceBehavior(InstanceContextMode=InstanceContextMode.PerCall)]
class MyWCFService : IMyServiceMode
{
    ...
}
```

After configuring the per-call instancing service, you can implement it in your application. Listing 19.1 shows how to implement the per-call instancing service:

In Listing 19.1, you can see that the MyWCFMethod() method accepts a parameter of type MyWCFClass, which identifies the instance of the MyWCFMethod() method, as shown in the highlighted line (Line 1). We have used the GetState() and SaveState() methods to retrieve the state of the instance and save the retrieved state at the end of the method call.

The per-call instancing service is most suited in situations when a small amount of work is to be done in each method call, and there are no more activities to complete in the background once a method is returned.

### Per-session Instancing Service

The per-session instancing service instructs the runtime environment to create a specific instance per client. WCF maintains a private session between a client and a specific service instance. When the client creates a new proxy for a service, which is configured as session-aware, the client obtains a new dedicated service instance that does not depend on any other instance of that service. The obtained instance remains in the service till the client needs it. Each private session creates a unique binding between a proxy and a particular service instance.

**NOTE**

The client session has one service instance per proxy. If the client creates another proxy to the same or different endpoint, the second proxy is associated with a new instance and session.

The service instance can maintain its state because it remains in the memory throughout a session. The following code snippet shows how to configure a per-session instancing service:

```
```csharp
[AttributeUsage(AttributeTargets.Interface|AttributeTargets.Class, Inherited=false)]
public sealed class ServiceContractAttribute : Attribute
{
    public bool Session
    {
        get;
        set;
    }
    // More members
}
```
```

While configuring a per-session instancing service, you can use the Session property to support sessions in your services. By default, the value of the Session property is set to false. If you want the service to support sessions, set the value of Session property to true, as shown in the following code snippet:

```
```csharp
[ServiceContract(Session=true)]
Interface IMyServiceMode
{
    ...
    ...
}
```
```

You can keep a service instance alive throughout the session by setting the InstanceContextMode property of the ServiceBehaviorAttribute attribute to InstanceContextMode.PerSession, as shown in the following code snippet:

```
```csharp
[ServiceBehavior(InstanceContextMode=InstanceContextMode.PerSession)]
class MYWCFService: IMyServiceMode
{
    ...
    ...
}
```
```

### Sharable Instancing Service

When you work with WCF, you may want to pass the current state of your session to another client. You can achieve this by using a sharable instancing service. Unlike a per-session instancing service, a sharable instancing service consists of one addition aspect, unique ID. When the first client creates a session with a sharable instancing service, it passes an ID of the instance to the second client. The second client creates an independent session but shares the same instance.

To configure a sharable instancing service, set the InstanceContextMode property of the ServiceBehaviorAttribute attribute to InstanceContextMode.Sharable, as shown in the following code snippet:

```
```csharp
[ServiceBehavior(InstanceContextMode=InstanceContextMode.Sharable)]
class MyWCFService: IMyServiceMode
{
    ...
    ...
}
```
```

If you configure a service as sharable, you can share an instance of your service across service boundaries. This implies that you can pass a reference of a shared instance from one client to another. The client that receives the instance is required to represent a contract that takes the endpoint address as a parameter Figure 19.2 shows how the session of the instance of the sharable instancing service, Service A, can be shared across service boundaries:

In Figure 19.2, you can see that a client retrieves the endpoint address from Service A and passes this endpoint address to the instance of Service B. With the help of this endpoint address, Service B creates a proxy and calls the instance of Service A.

### Singleton Instancing Service

A singleton instancing service is a service where all the clients are connected to one instance of the WCF service independently, without considering the endpoint of the service to which they are connected. Therefore, these services are considered as ultimate sharable instancing services. The life of a singleton instancing service starts when a host is created, and ends when the host is shut down. Using a singleton instancing service does not require maintenance of a session.

To configure a service as singleton, set the InstanceContextMode property of the ServiceBehaviorAttribute attribute to InstanceContextMode.Single, as shown in the following code snippet:

```
[ServiceBehavior(InstanceContextMode=InstanceContextMode.Single)]
class MySingletonService: ...
{
  ...
  ...
}
```

### The WCF Architecture

WCF supports multiple protocols, such as SOAP and binary. It also provides interoperable communication, which is compulsory for communication between different technologies, such as Java 2 Platform Enterprise Edition (J2EE) and .NET. WCF uses Service Oriented Architecture (SOA) to resolve the interoperability issues that arise at the time of communication.

> NOTE
> SOA is a software design pattern that defines how loosely-coupled software application components interact to implement the business logic of the entire application.
