# In Depth

Consider a situation where some engineers are given specialized tools and are told to make a luxurious car. However, they are not able to do so due to non-availability of any proper model or design. Similar to any other industry, in software development also, a model and a proper design are needed to develop an application. There are mainly two types of programming models followed while developing a software application: Procedure Oriented Programming (POP) and Object Oriented Programming (OOP).

POP is based on the concept of breaking a problem into modules, solving each module separately, and later combining all the solved modules to solve the entire problem. A module can be a method that consists of a block of code. In the POP model, you can call one method from another. This implies that these methods are dependent on each other; thereby, making the reusability of code difficult. The languages that use POP model are COBOL, FORTRAN, and C.

The model of OOP has been introduced to overcome the difficulty of limited or no reusability of code. OOP uses the concept of classes and objects to reuse the existing code. A class acts as a blueprint or template to create instances or objects. This blueprint or template describes the state and behavior for all the objects of the class. The behaviors and properties of objects are represented by methods and variables, respectively. In OOPs, you can also create interfaces that provide the ways of interactions between objects with the outside world. An interface is a collection of methods that have empty bodies. Amongst these two (POP and OOP) models, OOP is considered as the best one to follow since it follows an approach, which is related to real world objects.

You also learn about interfaces, sealed classes, sealed methods, and extension methods. In the Immediate Solutions section of this chapter, you learn how to implement these concepts in C# programs.

# Encapsulation

Encapsulation is the process of hiding the irrelevant information and showing only the relevant information of a specific object to a user. Let’s try to understand the concept of encapsulation with an example. When a customer goes to purchase a refrigerator, the customer looks for the factors, such as color of the refrigerator, its functionalities, and storage capacity; whereas, its internal working and wiring system are hidden from the customer. The company does not want the customer to tamper with the wiring system; as a result, it keeps the details of internal wiring system hidden from the customer. This process of hiding the internal facts is known as encapsulation.

In terms of OOP, encapsulation is the process of wrapping up data and members of a class. It is an approach of hiding the internal state and behavior of a class or an object from unauthorized access. Encapsulation restricts users from sharing and manipulating data; thereby, minimizing the chances of data corruption. The advantages of encapsulation are as follows:

+   - Provides a way to protect our data from unauthorized access. For this, instead of defining our data as public, we can declare those fields (such as data members, member functions, properties, or indexers) as private. The private data can indirectly be operated in two ways, firstly through the accessors and mutators methods and secondly, through the named property.
+   - Increases the maintainability of the code by showing only the relevant information to a user.
+   - Prevents data corruption by enabling private member variables of a class to be accessed through specific methods or properties.
+   - Binds member variables and functions of a class into a single unit: This is also called wrapping up of data members and member functions in a class.

In C# 2010, encapsulation is implemented by using the private access specifier in a class.
