+   - System.Core.dll
+   - System.Windows.dll
+   - System.Windows.Browser.dll
+   - System.Windows.Controls.dll
+   - System.Net.dll

Among these assemblies, mscorlib.dll, System.dll, and System.Windows.dll are essential assemblies for Silverlight 3.0 applications. The rest of the assemblies are added to handle certain common functionalities, such as working with the Web browser and XML content. You can add references to other assemblies from the Add Reference dialog box that appears when you right-click the name of a Silverlight application in Solution Explorer and select the Add Reference option from the context menu that appears.

# Figure 17.5: Showing the Files that Constitute a Silverlight 3.0 Application

As shown in Figure 17.5, the files which are automatically included in a Silverlight application are as follows:

+   - App.xaml — Refers to the XAML file in which you can define application-level resources, such as brush and style objects, which apply to an entire application.
+   - App.xaml.cs — Refers to the code-behind class for the App.xaml file. The App.xaml.cs file can be used to handle application level events, such as Application_Startup, Application_Exit, and Application_UnhandledException.
+   - MainPage.xaml — Refers to the XAML file, which is used to define a page, similar to a page in a Web site. The MainPage.xaml file is by default the initial UI control, which is loaded when an application activates. You can use UI controls, such as Button, Label, and TextBox controls, inside the MainPage.xaml file to define the UI of a Silverlight application.
+   - MainPage.xaml.cs — Refers to the code-behind class for the MainPage.xaml file in which you can write the managed code for a Silverlight application.
