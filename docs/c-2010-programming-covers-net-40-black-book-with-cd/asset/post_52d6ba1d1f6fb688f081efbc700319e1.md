The compilation architecture of ASP.NET 4.0 includes numerous features, which are as follows:

- Multiple language support – Specifies that you can use different languages in a single ASP.NET application. In an ASP.NET 4.0 application, multiple assemblies are created and each assembly supports each language used in the application. Therefore, for the code stored in the App_Code folder, you can specify a subfolder for each language.

- Automatic compilation – Compiles an ASP.NET application and any dependent resource, at the first instance when a user requests a resource from the website. As a rule, an ASP.NET application creates an assembly for each application directory and one for the main directory.

- Flexible deployment – Specifies that in case of deploying your ASP.NET application, you can just copy the source code of the application to the Web server. There are two precompilation options provided by ASP.NET. First, you can compile the website before deploying it, or second you can compile it after it has been deployed, but before a user sends a request to the website. The ASP.NET Merge tool (Aspnet_merge.exe) enables you to combine and manage assemblies that are created by the ASP.NET Compilation tool (Aspnet_compiler.exe). This tool enables you to compile an ASP.NET Web application for deployment to a target location, such as a production server. The ASP.NET Merge tool works on assemblies that have been created by using ASP.NET version 2.0 or advanced versions. It creates one assembly for either each content folder in the target website or content file. It also gives you additional flexibility for deployment. The Merge tool enables you to do the following tasks:

- Creates one assembly for the whole website
- Creates an assembly for each website folder and adds a prefix to the assembly name
- Creates a single assembly for just the website UI elements, such as pages and controls

The syntax for using the Merge tool is as follows:

```
aspnet_merge [-?]
              applicationPath
              [-keyfile filename [-delaysign]]
              [-o assemblyname | -w assemblyname | -prefix prefix]
              [-copyattrs [assemblyfile]]
              [-debug]
              [-nologo]
              [-errorstack]
              [-r]
              [-xmldocs]
              [-a]
              [-logfile logfile]
              [-allowattrs textfile]
```

- Extensible build system – Refers to the customization of ASP.NET build system to compile custom resources. The BuildProvider class is used by ASP.NET applications to build .aspx pages (ASP.NET Web pages), .ascx files (Web User Control file), and global resources.

## Dynamic Compilation in ASP.NET 4.0

When you create an ASP.NET page, the entire content of the page is compiled into a class, which is an instance of the System.Web.UI.Page class. When a user requests for the page, the ASP.NET Framework first searches for the .NET class to execute it. If the class is not located, then it can be compiled into a new .NET class, which is stored in a temporary ASP.NET folder.

If a request is send to the same page again, then the page is not compiled again. The .NET class, which has already been compiled, is executed. This process of not compiling the same page again is called ASP.NET dynamic compilation. If any modification is done in the ASP.NET page, the .NET class is delegated automatically. In other words, dynamic compilation helps in modifying the source code and recompiling the files, without compiling the code, before deploying a Web application.

## Optimizing Dynamic Compilation

As you know, if you make any changes to a dynamically compiled ASP.NET file, it automatically invalidates the file’s cached compiled assembly and triggers recompilation of all the affected resources, such as .dll files. However, in case of large applications, this process of recompilation may make the application unavailable for a long duration, even if the change is a small one.

You can avoid such a situation by setting the optimizeCompilations attribute to True in the web.config file. This implies that after setting this attribute to True, when you implement any change, only the files in which changes are made are recompiled.

## Disadvantages of Dynamic Compilation

The disadvantages of dynamic compilation in an ASP.NET application are as follows:

- Slow response time for the users as the ASP.NET pages and codes must be compiled the first time they are requested
- No means to identify any compile-time bugs, before a user accesses the site
- No provision of creating a compiled version of the site that can be deployed on the production server, without the source code

## ASP.NET 4.0 Coding Models

Generally, a Web form consists of controls, such as Label, Button, Hyperlinks, and business logic. You can use ASP.NET coding techniques to manage these controls and business logic. ASP.NET 4.0 coding techniques refer to the methodologies used for writing code in a Web application. ASP.NET 4.0 provides two types of coding techniques, Single-File page model and Code-Behind page model. In the single-file coding approach, developers write code directly in the .aspx page of the application. A major drawback of the single-file code model is that writing code in a single file results in difficult-to-read Web pages that mix presentation (HTML) with functionality (code). This drawback is specifically evident while developing complex applications. To deal with the drawback of the single-file page model, ASP.NET has introduced the code-behind page model. In this model, you need to maintain separate code files for each Web page. One file stores the code to implement the functionality of a Web page written in some programming languages, such as VB and C#; and the other file stores the HTML markup of the Web application.

## Single-File Page Model

In the single-file page model, the functionality of a Web application and the HTML markup are implemented in the same file. The programming code is in a script block that contains the attribute runat="server" to mark it as code that ASP.NET should execute. Now, let’s understand the single-file page model through an application named as SingleFileModelExampleCS.
