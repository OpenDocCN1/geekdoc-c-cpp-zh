# In Depth

Assemblies can be defined as partially compiled code libraries that consist of all the information or metadata about an application, such as its name, version number, modules, resource files, and code files. The metadata stored in assemblies is required to deploy an application; therefore, assemblies are also known as the fundamental unit of deployment. In .NET, the metadata about an application in an assembly is represented by one or more executables (EXE) or dynamic link libraries (DLL) files. An assembly can store more information compared to the Microsoft Intermediate Language (MSIL) code, which is compiled and run by the Common Language Runtime (CLR). In fact, an assembly can be perceived as a set of one or more modules and classes compiled in MSIL, the metadata that describes the assembly itself, as well as the functionalities of the assembly classes. Depending upon the type of application that you are creating, the .NET Framework allows you to create static or dynamic assemblies. Static assemblies are stored permanently on the disk in the form of portable executable (PE) files; whereas, dynamic assemblies can be run directly from the memory and are not saved to the disk before execution. You can save dynamic assemblies to the disk after they have been executed.

In this chapter, we first discuss about the concept and components of an assembly. In the later section, we discuss about the different assembly types, assembly attributes, assembly signing, assembly storage, assembly information files, and assembly configuration files. Let’s start by exploring the concept of .NET assemblies.

# .NET Assemblies

You have already learned in the previous chapters that the applications in .NET run on a layer of hardware and software abstraction, called CLR. To execute an application, the CLR must be provided with some basic information about the application that it has to execute. This information is provided to it by the .NET assemblies in the form of metadata. The concept of assemblies is often confused with that of namespaces; however, assemblies are entirely different from namespaces. A namespace is imported in the source code; whereas, an assembly is referenced by a compiler switch while deploying the application. An assembly can contain several namespaces.

The following are the basic components of an assembly:

+   - Assembly manifest
+   - MSIL source code
+   - Type metadata
+   - Resources

Let’s now discuss these components in detail.

# Assembly Manifest

Assemblies are self-describing programming units, which maintain all their information in a special unit called the manifest. In other words, the manifest of an assembly contains a collection of data, called metadata, which describes the relations between all the elements in that assembly. The assembly manifest can be stored in a PE file, such as .exe or .dll, with Microsoft Intermediate language (MSIL) code; or in a standalone PE file that contains only assembly manifest information.
