
## CLR Objects

In a WPF application, you can bind a control to data using the public properties or the sub-properties of a CLR object. While using the CLR object for data binding in WPF, you need to implement the INotifyPropertyChanged interface, which helps in updating the target and source property values. You can also use the UpdateTarget() method to update the target property in case any changes are made in the source of the data.

## ADO.NET

To bind a WPF application to an ADO.NET object, you first need to create a connection between a database and an application. After establishing the connection, an adapter is created that executes the Structured Query Language (SQL) statements to retrieve the record from the database. The result is stored in the DataTable object of the DataSet object by calling the Fill() method of the adapter. This result is then displayed in the control of the WPF application. You can also implement the IBindingList interface in the WPF application to provide change notifications. The IBindingList interface provides features to support both complex and simple data binding to a data source.

## XML

To bind the XML data to your application, you need to use the XmlDataProvider class in your WPF application. The XmlDataProvider class serves as the binding source in the markup. When you use the XmlDataProvider class, the data in the application appears in the form of a tree of XML nodes. You can access the data from either an existing XML file in your application or can create a new XML file by using the <x:XData> tag.

## The DependencyObject Class

You can also bind a WPF application with the DependencyObject class. The primary function of the DependencyObject class in a WPF application is to compute the values of properties and provide notifications regarding any change that may have occurred in these values. You can register the dependency property in a WPF application by calling the Register() method of the DependencyProperty class.

## Different Ways of Data Binding in WPF

In WPF, you can bind a control with either a single or a collection of data objects. Depending upon the source from where data is to be retrieved in the application, you can bind a control to a WPF application in various ways: XAML-based data binding and code-based data binding. Now, let’s discuss each of these ways in detail.

## XAML-Based Data Binding

When the data source is an XAML file, then you need to bind the WPF application to it by specifying the Binding property. The Binding property declares a series of clauses, which are in the form of the Name = Value pair, where Name is the name of the Binding property and Value is the value you are setting for the property. The Binding property must be attached to the specific dependency property of the target object. The following code snippet shows the basic syntax of using the Binding property in the XAML format:

```
<TextBox Text="{Binding Source={StaticResource myDataSource}, Path=Name}"/>
```

In the preceding code snippet, the Text property of the TextBox is using the Binding property.

## Data Binding in WPF Using WCF Data Services

WCF Data Services allow you to create and consume the OData services for the Web applications. OData services are based on the Open Data protocol, which is a new data-sharing standard. WCF Data Services provide client libraries that are supported by various technologies, such as .NET, Silverlight, Asynchronous JavaScript and XML (AJAX), Hypertext Preprocessor (PHP), and Java. In addition, these services support OData in SQL Server 2008, Windows Azure Storage, Excel 2010, and SharePoint 2010. The Data Services framework enables you to create flexible WCF Data Services that can be easily integrated with the Web applications. These WCF Data Services use Uniform Service Identifiers (URIs) to display data in various formats, such as JavaScript Object Notation (JSON) and Representational State Transfer (REST).
