Table 18.2 lists the common protocols that Web services use to transmit data:

| Table 18.2: Web Service Protocols Used for Data Transmission |
| Protocol Name | Description |
| HTTP-GET | Creates a query string of the name/value pair, such as name=joe, city=Chicago, and appends it to the Uniform Resource Locator (URL) of the requesting script on the server |
| HTTP-POST | Passes the name/value pair in the body of the HTTP request message |
| SOAP | Exchanges information in a decentralized, distributed environment |
| Multipurpose Internet Mail Extensions (MIME) | Defines the standard representation for complex message bodies, such as messages with embedded graphics or audio clips |

The protocols listed in Table 18.2 are used to invoke Web methods of the Web service. The selection of a Web service protocol determines the types of parameters for a method and its return type.

Let's now explore some important protocols in detail.

# HTTP-GET and HTTP-POST

Although you may know about HTTP-GET and HTTP-POST protocols used by the Web services to transmit data over the network, you must be aware of the fact that these methods of transportation of data are not rich enough to represent complex structures or classes. When you work with Web methods, you can use the HTTP-GET and HTTP-POST methods only with the data types listed in Table 18.3:

| Table 18.3: Data Types Supported by HTTP-GET and HTTP-POST Protocols |
| Data Types | Description |
| Enumerations | Supports the transmission of .NET System.Enum types, provided they are represented as a static constant string. |
| Arrays | Creates arrays as a primitive type. |
| Strings | Refers to the string representation of Common Language Runtime (CLR) primitives, such as Int16, Int32, Int64, Boolean, Single, Double, and Decimal. HTTP-Get and HTTP-POST transmit all numerical data as a string token. |

By default, HTTP-GET and HTTP-POST bindings are not enabled for remote Web service invocation. However, HTTP-POST is enabled to allow a machine to invoke a local Web service. These settings are established in the machine.config file using the <protocol> element. Listing 18.3 shows the partial code of the machine.config file:

# Listing 18.3: Partial Code for the machine.config File

```
<!-- In the machine.config file! -->
<webServices>
<protocols>
<add name="HttpSoap1.2"/>
<add name="HttpSoap"/>
<add name="Documentation"/>
<!-- Http GET and POST are disabled! -->
<!--<add name="HttpPost"/>-->
<!--<add name="HttpGet"/>-->
<!--Used by the web service test page-->
<add name="HttpPostLocalhost"/>
</protocols>
</webServices>
```
