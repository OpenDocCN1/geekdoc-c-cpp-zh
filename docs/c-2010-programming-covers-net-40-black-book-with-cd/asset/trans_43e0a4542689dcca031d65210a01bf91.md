

## 深入探讨

在包含大量对象（如服务器、打印机和数据库）的分布式计算网络中，用户很难在特定时间定位并使用这些对象。为此，引入了目录服务的概念。目录服务用于将所有管理这些对象使用所需的信息集中存储，从而简化定位和管理这些对象的过程。目录服务与目录的区别在于：目录服务既是信息的来源，也是将这些信息提供给用户的技术；而目录仅存储所需的信息。此外，目录服务在维护组织网络基础设施、管理系统以及控制对公司信息系统的访问方面也发挥着重要作用。从 Windows 2000 Server 开始，目录服务以一个新名称引入，即 Active Directory（AD）。

AD 存储基于 Windows 的计算机和服务器上有关网络和域的信息与数据。它以层次结构包含三个基本类别：资源、服务和对象。资源包括硬件资源，如打印机和扫描仪；服务包括 Web 和电子邮件服务器的服务；对象包括域和网络中以计算机节点形式存在的用户。

在本章中，你将了解 AD、其结构、重要性以及如何对其进行管理。你还将了解 AD 中的用户账户和组。接下来，你将了解 System.DirectoryServices 命名空间，它提供了从 .NET Framework 4.0 中创建的应用程序访问 AD 的类。在“直接解决方案”部分，你将学习如何在 AD 中创建用户和组，并创建一个 Windows 窗体应用程序来访问这些用户或组。

让我们从了解 AD 的结构开始。

### Active Directory 的结构

AD 以层次结构包含林和域，其中林是域的集合，而域是组织单位（OU）的集合。OU 是用户、组和计算机的集合，其中用户是单个个人，组是用户账户的组，计算机是特定的工作站。图 37.1 展示了 AD 的结构：

在 AD 的结构中，林代表其安全边界。所有 AD 对象（包括用户、组和资源）都存储在平面数据库文件中。每个对象既存储自己的名称，也存储其所在容器的名称。每个容器自身既存储自己的名称，也存储其上级容器的名称，依此类推，直到根容器。因此，AD 的结构也可以看作一个容器树。

现在，让我们了解 AD 的以下组件：

- **林** —— 表示包含一个或多个域的单个目录。
- **域** —— 指按层次顺序排列的 OU 集合。
- **OU** —— 指用户、组和计算机的集合。
- **域控制器** —— 指运行 Windows Server 2008、Windows Server 2003 或 Windows 2000 Server 操作系统并安装了 AD 的服务器。
- **架构** —— 提供用于在目录中存储信息的对象定义。它是一个自身驻留在目录中的单一组件。
- **数据存储** —— 管理域控制器数据的存储和检索。它包含三层，其中第一层提供访问目录的接口，第二层提供执行读写数据操作的服务，第三层由数据库本身组成。
- **数据库** —— 以文件格式存储数据，位于域控制器的硬盘上。

让我们了解 AD 的重要性。

### Active Directory 的重要性

AD 提供了一个安全且集中化的网络，其范围可能覆盖一栋建筑、一座城市或全国多个地点。它是 Windows Server 2008、Windows Server 2003 和 Microsoft Windows 2000 Server 操作系统中的分布式目录服务。AD 使你可以访问各种对象，包括所有网络用户、设备和资源。它还使你可以将这些对象组成组以便于管理。

AD 的一些优点如下：

- **可伸缩性** —— 使你可以通过包含一个或多个域及一个或多个域控制器来扩展目录，以满足任何网络需求。
- **灵活搜索** —— 允许你在网络上搜索用户和资源，如打印机或文件。
- **数据存储** —— 允许你将应用程序的数据集中存储在一个位置，并在 Windows 网络中的应用程序之间共享。
- **系统化目录更新** —— 通过以同步方式在域控制器之间复制数据，在网络上以安全方式更新目录数据。
- **远程访问** —— 允许你通过网络远程访问或管理连接到基于 Windows 的计算机的任何域控制器。
- **域名系统（DNS）支持** —— 允许你使用提供名称解析服务的 DNS 系统，以在域控制器上反映组织结构。
- **单一且可扩展的架构** —— 指为 AD 对象提供结构要求的对象和规则架构。你可以通过添加新类型的对象或对象属性来扩展此架构。
- **轻量目录访问协议（LDAP）支持** —— 允许你使用 LDAP 协议（一种行业标准的目录访问协议）从管理和查询应用程序访问 AD 对象。AD 支持 LDAPv3 和 LDAPv2 协议。

### 探索用户账户和组

AD 中的用户账户包含定义 AD 中用户所需的所有信息，例如用户名、密码、登录时间和配置文件位置。用户账户在验证用户身份后帮助用户登录网络以访问资源。验证用户身份意味着识别并允许用户登录并访问资源。

用户账户是 AD 网络允许用户访问资源的主要方式。Windows Server 2008 中有以下三种类型的用户账户：

- **内置用户账户** —— 指定在安装 Windows Server 2008 和 AD 作为独立服务器时自动创建的账户类型。它用于执行管理任务，例如管理打印机和备份文件。Administrator 和 Guest 账户是内置用户账户的示例。
- **本地用户账户** —— 指定仅用于访问本地计算机的账户类型。它在本地对用户进行身份验证，以获得该计算机上的资源访问权限。它在计算机的本地安全账户管理（SAM）数据库中创建，而不是在 AD 域中创建。这些类型的账户没有域访问权限。这意味着在一台服务器上配置的本地账户不能用于访问另一台服务器上的资源。
- **域用户账户** —— 指定用于获得 AD 资源（如文件夹和打印机）访问权限的账户类型。账户信息存储在 AD 数据库中。

创建新用户账户时，应记住以下几点：

- 仅在存在数据损坏风险时才重命名管理员账户。
- 确保设置强密码。密码长度应为七个字符。密码应包含大写字母、小写字母、数字和非字母数字字符的组合。
- 不要分发管理员密码，并只让少数人知道该密码。
- 不要将管理员账户用于非管理任务。你可以使用 Guest 账户进行非管理任务。
- 在启用 Guest 账户后重命名它。
- 不允许 Guest 账户使用空白密码，这是 Guest 账户的默认行为。
- 避免使用字典单词、姓名和出生日期作为密码。

组是作为单个对象管理的用户账户或计算机的集合。属于组的用户和计算机称为组成员。组很有用，因为你可以将权利和权限集体分配给组，而不是为每个用户单独分配权限。因此，管理员创建组以使任务（如分配权限和权利）更加容易。你将在“直接解决方案”部分了解如何在 AD 中创建用户账户和组。

### 管理 Active Directory

系统管理员有责任和特权输入新数据、更新和配置目录。有一些用于数据管理的管理工具。这些工具如下：

- **Microsoft 管理控制台（MMC）** —— 帮助你执行管理任务，包括添加和管理多个域、服务器和用户。MMC 控制台承载工具并以控制台形式显示这些工具。这些工具是使用一个或多个管理单元构建的应用程序。MMC 控制台保存为 .msc 文件，可以通过电子邮件发送、在网络文件夹中共享或发布在 Web 上。这些控制台还可以通过系统策略设置分配给用户、组或计算机。
- **管理单元** —— 处理网络管理任务。一些与 AD 相关的常用管理单元如下：
  - **Active Directory 用户和计算机管理单元** —— 管理资源，如用户、组、计算机、共享文件夹和打印机。AD 管理员使用此管理单元执行大部分管理任务。
  - **Active Directory 站点和服务管理单元** —— 管理管理活动，如站点复制、网络拓扑和相关服务。
  - **Active Directory 域和信任管理单元** —— 配置和维护信任关系，并配置林和域功能级别。
