# Routed Events

As you learned earlier, a WPF application has numerous elements. These elements are represented in the form of a tree with one root element (Window or Page) and other elements nested inside the root element. There is no limit for the number of levels of nesting. Except for the root element, all other elements can have more than one nested elements. Most of these elements have certain basic events, for example, the mouse and keyboard events. These events are defined as routed events in WPF. As the name suggests, routed events route or traverse through the element tree of a WPF application. Routed events differ from the traditional CLR events because routed events allow you to raise and handle an event on multiple elements. A routed event originates at one element but can traverse either up or down the element tree from the source element. As the routed event traverses, it is raised on the elements between the root element and the source element and can be handled on each of those elements. You also have the option of handling the routed event at only element and stop the traversal of the routed event at that element.

Routed events belong to the WPF event system and are backed by the RoutedEvent class. Table 9.13 lists some of the noteworthy properties of the RoutedEvent class.

| Table 9.13: Noteworthy Properties of the RoutedEvent Class |
| Property | Description |
| Name | Retrieves the name of the routed event |
| HandlerType | Retrieves the type of handler of the routed event |
| OwnerType | Retrieves the owner with which the routed event is originally registered |
| RoutingStrategy | Retrieves the routing strategy of the routed event |

Since routed events are raised at the elements on the path between the root element and the source element, you can use routed events to pass event information between those elements. The direction in which the routed events (and the event information) traverse depends on the routing strategy employed by the routed event. Now, let's take a look at the routing strategies available for WPF routed events.

# Routing Strategies

In WPF, routed events are used to navigate the elements, up or down, in the elements tree on the basis of their routing strategy. A routing strategy is a way in which an event is raised and traversed in between the elements of the elements tree. These routing strategies are specified with the help of the values of the RoutingStrategy enumeration. These values are given as follows:

+   - Direct – Represents the events that are raised by the source element. These events have the same behavior as of normal .NET events, but can participate in mechanisms that are specific to routed events, for instance event triggers
+   - Tunneling – Represents the events that are raised by the root element first. Then, by each element down the elements tree until the source element is reached.
+   - Bubbling – Represents the events that are raised by the source element first. Then, by each element up the elements tree until the root element is reached.

# Direct Events

Direct events refer to those events that directly apply on the element on which they originated or raised. These events are similar to CLR events that you worked with in Windows Forms applications. This implies that direct events can be raised and handled only on the source element and not routed through other elements in the element tree.
