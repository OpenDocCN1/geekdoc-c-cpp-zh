# In Depth

In programming languages, we mostly use arrays to store and manage data. However, arrays can store a particular type of data, such as int and char. To resolve this issue, the .NET Framework introduces the concept of collections for data storage and retrieval; where collection means a group of different types of data. Collection allows you to store different types of data as well as add, remove, or modify the individual elements of these data types. It also provides automatic memory management and capacity expansion. Built-in collection classes had been introduced in .NET Framework 1.1, which have been retained in the latest version as well. The System.Collections namespace provides various classes, such as ArrayList and Stack, to easily manipulate the data. Some collections classes also provide the search and sort capabilities on the basis of index values or associated key values of the elements.

However, collections are not free from limitations. For example, a significant limitation of collection is that it can store only object types, but not primitive types. The concept of generics has been introduced in .NET Framework 2.0 to overcome this limitation of collections. Generics are a type of fixed data structure, which can be reused by passing different types of parameters to it. They permit classes, structs, interfaces, delegates, primitive types, and methods to be passed as parameters to store and modify data. In other words, generics are used to provide the reusability of code in software components. In .NET, you can create generic collection, which can handle collections of items of any data type in type safe manner by using various generic classes, such as List<T> and Dictionary<TKey>.

In this chapter, you learn about collections and generics in C#. The chapter starts by exploring the concept of collections and various collection classes, such as ArrayList, Hashtable, Stack, and Queue. Next, you learn about generics and its classes, such as List<T> and Dictionary<TKey>. In addition, you learn about the covariance and contravariance mechanisms in generics. In the Immediate Solutions section, you learn to create applications that use different collection and generic classes of .NET Framework 4.0.

# Understanding Collections

As a programmer, you often come across a situation where you need to store lots of values under the same name. In such a situation, arrays are helpful to store the objects of same type. You can declare an array of any type and assign it a value, which can later be retrieved using indexes.

The following code snippet shows how to define arrays of different types:

```
int[] ArrInt;
string[] ArrStr;
MyUDT[] ArrMyUDT;
object[] ArrObj;
```

If you do not know the number of elements to hold in an array beforehand, arrays can always be redefined later to hold more or fewer elements. In the following code snippet, we are redefining the ArrInt array to hold as many values as the value of the ItemCount variable:

```
if (ItemCount > 2000) ReDimPresvInt(ref ArrInt,ItemCount);
for (int i = ItemCount - 2000; i < ItemCount; i++)
    ArrInt[i] = i;
```

Now, there is one limitation of using arrays, i.e., an array declared with some specified size does not resize automatically. .NET provides a solution to this problem in the form of collections. Collections are better optimized to handle size changes dynamically. The difference between arrays and collections is that in collections, you do not need to specify the size of a collection in advance. As you add new elements to the collection, it automatically gets resized to accommodate additional elements.
