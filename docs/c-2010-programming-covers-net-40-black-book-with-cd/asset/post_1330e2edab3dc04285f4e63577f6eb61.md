## The NavigationWindow Control

The NavigationWindow control derives itself from the Window class, and is designed to support content navigation. You can navigate the content by setting the Source property of the NavigationWindow control with the Universal Resource Identifier (URI) of the desired content. You can also track the events raised during the process of navigation as long as the page is in navigation mode. Some of the events that are raised during navigation are Navigating, Navigated, NavigationProgress, NavigationFailed, NavigationStopped, LoadCompleted, and FragmentNavigation. The type of event that is raised depends on the type of navigation performed by the user. The navigation history can be deleted by calling the RemoveBackEntry property.

The inheritance hierarchy of the NavigationWindow class is as follows:

```
System.Object
  System.Windows.Threading.DispatcherObject
    System.Windows.DependencyObject
      System.Windows.Media.Visual
        System.Windows.UIElement
          System.Windows.FrameworkElement
            System.Windows.Controls.Control
              System.Windows.Controls.ContentControl
                System.Windows.Window
                  System.Windows.Navigation.NavigationWindow
```

You can add the NavigationWindow to a WPF application by using the following code snippet:

```
<NavigationWindow>
    <!--Content -->
</NavigationWindow>
```

Table 10.26 describes the noteworthy properties of the NavigationWindow class:

| Property | Description |
|---|---|
| BackStack | Retrieves an IEnumerable property to enumerate the entries in back navigation history for a NavigationWindow control |
| CanGoBack | Retrieves a value that indicates whether there is at least one entry in the back navigation history |

## The UserControl Control

In WPF, the UserControl control provides an empty control, which can be used to create other controls. The use of the UserControl class as the base class provides a simple way to create custom controls. The UserControl control helps you to create controls, which can be used in multiple places within an application. For example, you can preload a ComboBox control with static items that you commonly use in every application. You cannot add a UserControl control to a WPF application with XAML code. Instead, you need to create a UserControl control in the code-behind file. The inheritance hierarchy of the UserControl control is as follows:

```
System.Object
    System.Windows.Controls.Control
        System.Windows.Controls.TemplateControl
            System.Windows.Controls.UserControl
```

You can add the UserControl to a WPF application by using the following code snippet:

```
<UserControl>
    <!--Content -->
</UserControl>
```

There are no noteworthy properties of the UserControl control.

## Headered Content Controls

Headered Content controls are the controls that contain Header and Content properties. The Header property consists of a text value, and the Content property consists of a single content item. Headered Content controls inherit the Content property from the ContentControl control and define the Header property, which is used to provide a heading for the control. The Headered Content controls include the following controls: Expander, GroupBox, and TabItem.

Table 10.27 describes a brief description of all the Headered Content controls:

## Table 10.27: Headered Content Controls

| Control | Description |
|---|---|
| Expander | Represents a control that displays a header with a collapsible window containing content. |
| GroupBox | Represents a control that displays a frame. This control can group together some controls and display them inside a frame. |
| TabItem | Represents a selectable item inside a TabControl control. |

## The TabItem Control
