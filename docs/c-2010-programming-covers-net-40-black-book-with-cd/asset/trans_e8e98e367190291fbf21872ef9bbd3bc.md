## 内存管理

CLR 在托管执行期间提供的最重要的服务之一是自动内存管理。CLR 使用垃圾回收器来管理应用程序的内存分配和释放。CLR 的这一特性对开发人员有益，因为它减少了在开发托管应用程序时编写管理内存代码的负担。自动内存管理消除了许多常见问题，例如忘记释放对象导致内存泄漏，或尝试访问已释放对象的内存。

## CTS

CTS 是运行时不可或缺的一部分，有助于支持跨语言通信。它为在运行时声明、使用和管理类型制定了某些准则。CTS 执行的功能如下：

- 通过建立框架，有助于跨语言通信、类型安全以及代码的高性能执行
- 支持不同编程语言实现的对象模型
- 为不同语言制定准则，确保其对象之间正确交互的范围
- 支持在应用程序开发过程中使用的原始数据类型，例如 Boolean、Byte、Char 和 Int32

CTS 可分为两种数据类型，值类型和引用类型。值类型变量由 CLR 管理，可以将其值存储在堆栈或堆内存中。垃圾回收器通过在变量不再使用时释放其内存空间来管理分配给这些类型的内存。值类型的实例，例如 string，其值分配在堆栈上，而引用类型的实例，例如数组，仅将其实际值的引用分配在堆栈上。

声明为值类型的变量拥有各自独立的数据副本；因此，对一个变量的任何操作都不会影响其他变量。另一方面，声明为引用类型的变量始终共享同一份数据副本或指向同一对象；因此，在一个变量上执行的任何操作都会直接影响引用同一实例的另一个变量。

## 元数据和程序集

元数据是程序在二进制格式中的自我描述。换句话说，元数据包含程序中使用的类、方法和其他元素的 信息。此信息存储在 CLR 可移植可执行文件（PE）文件中或内存中。当你编译 PE 文件中的代码时，元数据被插入到文件的一个部分，而代码被转换为 IL 并插入到文件的另一部分。元数据描述了程序中的每个数据类型和成员。当代码处于运行模式时，CLR 将元数据加载到内存中并查找有关类和成员的信息。程序的元数据包括：

- 程序集信息，例如其标识，可以是名称、版本、区域性、公钥、程序集类型、其他引用的程序集和安全权限
- 有关类型的信息，例如名称、可见性、基类、使用的接口以及成员（方法、字段、属性、事件和嵌套类型）
- 修改类类型和成员的属性信息

提供上述信息后，CLR 能够创建对象、访问数据并调用成员函数。程序集被打包成包含程序和库的单元。程序集包含一个自描述的二进制文件，可以是动态链接库（DLL）或可执行文件（EXE）文件。它还包含一组类型，例如类、接口和结构。单个程序集可以包含多个代码文件，或单个代码文件可以有多个程序集。

程序集可以分为两种类型，静态或动态。静态程序集包括接口、类和资源。这些程序集存储在磁盘上的 PE 文件中。使用 .NET Framework，你可以创建动态程序集，它们可以直接从内存运行，而无需在执行前保存到磁盘。但是，执行后你可以将它们保存到磁盘。

## 程序集内容

通常，程序集是一个逻辑单元，由四个元素组成——清单、类型元数据、实现类型的 IL 代码，以及一组资源，例如位图和联合图像专家组（JPEG）文件。这些元素可以以单个文件或多个文件的集合形式分组。

## 程序集清单

每个程序集都包含描述程序集中元素之间关系的数据。程序集清单是一个文件，其中包含程序集的元数据，即程序集的版本要求和安全标识信息。清单可以存储在包含 IL 代码的 PE 文件中，也可以存储在仅包含清单信息的独立 PE 文件中。

表 1.1 列出了存储在程序集清单中的信息：

| 信息 | 描述 |
|---|---|
| 程序集名称 | 指定程序集的名称。 |
| 版本号 | 指示主版本号、次版本号以及修订号和内部版本号。CLR 使用这些数字来强制执行版本策略。 |
| 区域性 | 提供有关程序集支持的区域性或语言的信息。 |
| 强名称信息 | 指示公钥，当程序集包含强名称时，强名称是用于加密程序集中名称和内容以及公钥的哈希令牌。 |
| 程序集中所有文件列表 | 包含程序集中包含的每个文件的哈希令牌和名称。哈希令牌是根据文件内容生成的字母数字字符串。请注意，程序集的所有文件必须存储在包含程序集清单文件的同一目录中。 |
| 类型引用信息 | 包含将类型引用映射到包含此类型引用声明和实现的文件所需的信息。从程序集导出的类型使用类型引用信息。 |
| 引用程序集信息 | 包含由程序集静态引用的程序集列表。程序集引用包含有关程序集的信息，例如依赖程序集的名称、程序集元数据（版本、操作系统等）和公钥。 |

程序集清单中的信息可以通过使用程序集属性进行修改。你还可以更改程序集的版本、信息和属性，例如商标、产品、公司和版权。

## 全局程序集缓存

全局程序集缓存（GAC）是计算机中机器范围的代码缓存，是注册程序集的中心位置。你应该注意，只有在需要时，程序集才必须通过在全局程序集缓存中注册使其可共享；否则，它们必须保持私有。此外，将程序集安装到 GAC 中并不是使其可供组件对象模型（COM）互操作或非托管代码访问的强制性条件。COM 互操作是一项服务，使 .NET Framework 对象能够与 COM 对象通信。
