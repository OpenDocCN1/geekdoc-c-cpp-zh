## Side-by-Side Execution of Shared Assemblies

Side-by-side execution is a feature that allows developers and users to install different versions of an assembly in GAC and use them without any conflict among different versions. To avoid any conflict, strong names are used, which are already discussed in this chapter in combination with version numbers.

To elaborate the concept of side-by-side execution, let’s assume that you have two applications—App1 and App2—that are using different versions of the SharedObject assembly. App1 and App2 send requests to the CLR when they need to load the corresponding versions of the assembly. App1’s request contains reference for accessing version 1.0.0.0 and App2’s request contains reference for accessing the version 1.1.0.0. CLR uses the assembly’s manifest and the application configuration file to identify the requested version. After identifying the version, CLR searches for the requested version and loads it to the corresponding application. CLR searches GAC, codebase, and probing to search for the requested SharedObject assembly, which we have already explained earlier in this chapter.

The new version of the SharedObject assembly (which we have created earlier) is bound to the client using a file named ASimpleClient.exe.config, which has been created by the configuration tool to perform the binding action. You can find this file in the application's bin\Debug directory. To see how a shared assembly performs side-by-side execution, move the config file to a different folder temporarily and run the ASimpleClient.exe file from the bin\Debug directory. Now, click the Call Greetings button of the Form1 form. Notice that the client is now using the older version of the library. This indicates that the config file is required to bind the client with the new library.

Now, you have two clients running simultaneously, using two different versions of the same library.

Restore the config file in the bin\Debug directory, as we will need it later in this chapter.

## Creating a Private Assembly

We will discuss about creating a private Assembly in this topic. With this assembly, we will expose two simple classes intuitively, such as Class1 and Class2.

These classes are just for demonstration; both of them will have a method named Display, which displays a message box. You pass the text for the message box to the Display method of Class1, and the text and a message box icon to the Display method of Class2. To create a private assembly, perform the following steps:

- 1. Create a Class Library application named PrivateAssembly (also available in CD-ROM).
- 2. Create two classes Class1 and Class2, each with a Display method, as shown in Listing 33.9:

# Listing 33.9: Showing the Code for the Class1.cs File

```
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;
using System.Windows.Forms;

namespace PrivateAssembly
{
    public class Class1
    {
        public void Display(string Message)
        {
            MessageBox.Show(Message);
        }
    }
    public class Class2
    {
        public void Display(string Message)
        {
            MessageBox.Show(Message, "", MessageBoxButtons.OK, MessageBoxIcon.Exclamation);
        }
    }
}
```

> NOTE
> You need to add the reference of the System.Windows.Forms component and add the namespace in the Class1.cs file.

- 6. Add the PrivateAssembly.dll reference file in the Displayer project by right-clicking it in the Solution Explorer and selecting Project→Add Reference.

Now, you can use the classes in the PrivateAssembly.dll class library; for example, to use Class1, you refer to it as PrivateAssembly.Class1.
