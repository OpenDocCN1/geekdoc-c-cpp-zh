```
// Allow a handler for the event
public delegate void valueChangedEventHandler();
```

After creating an event and declaring a delegate that is called when the event is fired, the next task is to use a method that fires the event. This method is used to make the connection between the object event source and the method that might be assigned to handle the event, as shown in the following code snippet:

```
// This method is used to fire the event
protected virtual void OnChanged()
{
    if (Changed != null)
        Changed();
    else
        Console.WriteLine("Event fired. No handler!");
}
```

In the preceding code snippet, you can see that the event-firing mechanism is simple and it looks exactly like a function call. Similar to a function or a method call, the event handler can accept arguments. For example, the value of the nValue variable, in a class has been changed. If you want to inform the listeners about this change, you have to fire an event. The following code snippet shows how to fire an event:

```
public void SetValue( int nv )
{
    if ( nValue != nv )
    {
        nValue = nv;
        // Fire the event
        OnChanged();
    }
}
```

The event mechanism is by no means automatic. If a method in a class modifies the internal member variable directly, without calling a method, the event is not fired. Consider the following code snippet, which declares a method named BadMethod():

```
public void BadMethod()
{
    nValue ++;
}
```

In this case, the event denoting that the variable has changed is not fired because the CLR does not recognize that the event is tied to the value of the variable. While working with events, which check these types of values, you need to ensure that you are always calling the event-firing mechanism when appropriate. The best way to fire an event is to embed that event to the accessor. The following code snippet shows how to define an event handler in another class:

```
public static void HandleChange()
{
    Console.WriteLine("Handler Called");
}
public static void Main()
{
    TestClass tc = new TestClass(3);
    // Create a handler for this class
    tc.Changed += new EventTestClass.ValueChangedEventHandler(
        HandleChange);
}
```

In the preceding code snippet, you can see that we have selected a static method as the event handler. The signature of the event handler method must match with the signature of the event itself. In this case, the delegate method signature specifies a method that contains no arguments and returns no value (a void return). Notice that the event handler method contains the same signature. If you try to use a method that accepts any arguments or returns any sort of value for this event handler, the compiler flags it as an error. Suppose you want to pass the current value of a variable to a method and you want the event handler to test whether or not this value is acceptable, you can modify the delegate to read the code, as follows:

```
public delegate Boolean ValueChangedEventHandler(int nValue);
```
