## 理解实体数据模型

数据模型通常在项目的分析或规划阶段设计。这是因为数据类型之间的关系、它们的属性以及数据中的约束必须在概念上组织好，然后才能在应用程序代码中实现。EDM 用于扩展应用程序设计者在开发过程中用来描述数据的模型。这些模型提供规范来定义应用程序使用的数据。基于 EDM 的应用程序在设计模式中定义应用程序域中的实体和关系，该设计模式用于生成可编程类，然后应用程序代码使用这些类。

在 EDM 中，映射规范连接设计模式和存储模式。包含应用程序数据的存储结构在存储模式中表示。存储模式映射到设计模式，以便映射规范有效地将可编程类连接到存储结构。现在，让我们了解与 EDM 设计相关的以下概念：

- 数据建模
- CSDL
- SSDL
- MSL
- EDM 类型
- 类型约束
- 数据模型工具

让我们现在逐一详细了解这些概念。

## 数据建模

数据建模是一种结构化和组织应用程序所需数据的技术。例如，应用程序中的一个实体必须由数据表示，例如客户、订单和产品，而关系则指定实体之间的逻辑连接。定义实体和关系可能是一个非常复杂的过程。它可能需要意想不到的细节量，例如，订单可能是电话订单、目录订单或互联网订单，这很令人困惑。为了解决这个问题，EDM 定义实体并使用数据读取器以序列化形式或作为具体化对象读取实体。

对象模型表示可以在通用语言运行时（CLR）中编程的类，可以从设计模式中定义的概念模型构建。EDM 概念模型是对应用程序域中实体和关系的规范。对象模型和存储元数据，由数据库结构的逻辑描述组成，被映射到概念层。

现在，让我们讨论 EDM 的设计和实现及其映射到不同平台。

## 设计和实现

EDM 类型在模式中设计，以保持数据的逻辑完整性以及业务和技术应用程序的约束。根据 EDM 规范，实现数据模型需要以下三个开发阶段：

- 应用程序域中的实体和关系在 XML 文件中指定
- 描述数据库结构的元数据也在 XML 文件中指定
- 实体和关系到相应数据库的映射在存储元数据文件中指定

## EDM 映射到 CLR 和数据库管理系统

EDM 支持跨各种存储模型的应用程序场景，并映射到 CLR 和数据库管理系统，例如 SQL Server。随着 EDM 的引入，ADO.NET 提供了一个全面的平台，将应用程序代码连接到存储结构。它使用存储无关的视图机制，利用关系数据库管理系统（RDBMS）的概念来实现模式、编程语言和数据库表之间的映射。EDM 数据服务不依赖于任何特定存储模式。需要多个数据源的应用程序可以为每个数据源维护单独的映射。

使用 Entity Framework 开发应用程序需要创建和映射概念 EDM 和存储实体模型。Entity Framework 已通过 XML 文件的组合使实体关系建模可执行，例如概念模式定义语言（.csdl）、存储模式定义语言（.ssdl）和映射规范语言（.msl）。

## 概念模式定义语言

CSDL 包含一个设计模式，为对象模型提供设计模板。应用程序使用基于 CSDL 的对象模型。模式是一个 XML 文本文件，描述实体和关系类型。它还定义一个容器，以逻辑组织的形式包含这些类型的实例。CSDL 是一种 XML 语法，用于描述 EDM 类型，即安装 Entity Framework 时提供的类型和由开发者设计的那些类型。以下代码片段显示了 CSDL 文件的整体结构：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Schema xmlns:cg="http://schemas.microsoft.com/ado/2006/04/codegeneration" xmlns="http://schemas.microsoft.com/ado/2006/04/edm" Namespace="Humanresource.Salaryschema" Alias="Self">
<Documentation>
<Summary>Shows general Syntax of Conceptual schema (csdl) </Summary>
</Documentation>
<EntityType Name="Employee">
<Key>
<PropertyRef Name="EmployeeId" />
</Key>
<Property Name=" EmployeeId " Type="Guid" Nullable="false" />
<!-- Other properties-->
</EntityType>
<Association Name="Monthly_Salary">
<End Role="Employee" Type="Self.Employee" Multiplicity="0..1" />
</Association>
<EntityContainer Name=" Humanresource.SalarySchema ">
<EntitySet Name="Employee" EntityType="Self. Employee" />
<AssociationSet Name="Monthly_Salary" Association="Self.Monthly_Salary">
<End Role="Employee" EntitySet="Employees" />
<!-- Other roles -->
</AssociationSet>
</EntityContainer>
</Schema>
```

前述代码片段中使用的一些元素和属性如下：

- **Schema** — 指每个 XML 模式的根元素。它表示模式中使用的元素已从 `http://schemas.microsoft.com/ado/2006/04/edm` 提取。该元素包含以下两个属性：
  - **Namespace** — 指模式中的顶级节点，分配应唯一的命名空间。模式中定义的类型在 `Humanresource.SalarySchema` 命名空间下逻辑组织。
  - **Alias** — 指可用于缩短模式其余部分中命名空间名称的属性，例如 `Humanresource.SalarySchema`。例如，Employee 表可以使用别名 `Self` 缩短，该别名已为命名空间声明，例如 `Self.Employee`。

- **Using** — 指用于缩短引用在单独命名空间中定义的类型时的语法的元素。它包含以下两个属性：
  - **Namespace** — 指定外部命名空间
  - **Alias** — 为命名空间提供别名

- **Documentation** — 指 EDM CSDL 文件中的元素，提供有关在模式中声明的实体和关联的使用信息。它具有以下两个子元素：
  - **Summary** — 提供类型的简要描述。此属性是可选的。
  - **LongDescription** — 包含广泛的文本信息。此属性也是可选的。

> **NOTE**
>
> *CSDL 文件的语法中空的 Documentation 元素也是有效的。*

- **EntityType** — 指 EDM 在 CSDL 模式中用于指定应用程序设计域中对象的元素。它包含以下属性：
  - **Key** — 指定实体的一个或多个属性作为键。它唯一标识实体的实例以进行所有操作，可以由一个以上属性组成。
  - **Name** — 标识设计的对象模型中的类型。
  - **NavigationProperty** — 声明用于在由 Association 类型关联的实体之间导航的快捷方式。
  - **Property element** — 包含应用程序中使用的实体的大部分信息。
  - **Type** — 指属性元素的属性，设置为 `Guid` 以指定键的唯一值。

- **Association** — 指指定 EDM 中实体之间逻辑关系的元素。

- **EntityContainer** — 指与 Schema 元素不同的元素，即使 EntityContainer 元素在模式中定义。概念模式中的 EntityContainer 元素映射到存储元数据中相应的 EntityContainer 元素。它还控制从中定义的对象模型中实体和关联的范围。

- **AssociationSet** — 指指定从概念模式构建的类中的关联的元素。从概念模式构建的对象模型需要可编程类和存储结构来包含基于它的应用程序的数据。AssociationSet 元素的属性如下：
  - **AssociationSetMapping** — 将 CSDL 中定义的 AssociationSet 元素连接到 SSDL 中描述存储结构的 AssociationSet 元素
  - **Name** — 指定从 EDM 构建的对象模型中类的名称
  - **Extends** — 提供向现有模式添加实体和关联的手段
