## 深入

在当今的计算机程序世界中，反射被认为是编程中的重要技术，因为它用于在运行时提取程序的每个细节。在 .NET Framework 4.0 中，当程序从其程序集中提取元数据（自信息）并使用此元数据在运行时查找程序集、模块和类型信息时，程序被称为自我反射。

在开发大型应用程序时，反射由于其能够收集和操作程序集和应用程序元数据中的数据而具有重要意义。它对于充分的版本控制、类的动态加载以及应用程序的适当安全处理也是必要的。此外，反射帮助您获取存在于动态链接库（DLL）文件中的类、函数和类型的信息。此外，在 C# 2010 中，您可以使用 System.Reflection 命名空间中包含的类来实现反射。这些类的示例包括 Assembly、Module、MethodInfo 和 ConstructorInfo。

在本章中，您将了解 C# 2010 中反射过程的重要性。本章从探索反射过程开始，在其中您将了解反射过程的必要性和使用方法。接下来，您将了解使用反射动态加载程序集。在“即时解决方案”部分，您将学习如何使用反射从程序集中获取类和类型信息，以及如何从类中获取成员信息。最后，本章将解释如何使用反射来验证和转储类的方法和参数。

让我们开始探索反射过程。

## 探索反射过程

反射被定义为在不访问源代码的情况下找出应用程序内部元素的过程，例如元数据、程序集、模块和类型。您还可以使用反射来查找程序集中所有的类，以及这些类可能支持的所有方法、属性和事件。反射还允许您搜索关于类的所有种类信息，例如它派生的基类以及它支持的接口，并以编程方式探索公共语言运行时（CLR）。

使用反射对 C# 程序进行检查和根据所需目标进行操作。您可以检查类的所有信息，并使用反射技术在运行时动态调用类的方法。可以在运行时直接在应用程序中执行类中方法的生成代码。

借助反射，可以在运行时查看程序集元数据段中的信息。简而言之，反射使您能够以编译器在将应用程序构建为可执行文件（EXE 文件）时识别数据的方式来查看数据。然后，您可以灵活地创建可以在运行时通过利用用户系统上的其他功能来扩展的应用程序。例如，反射还可以用于调查您的主目录中是否存在某些类，如果存在，则在您自己的应用程序中加载和使用它们。

在没有反射的编程语言中，您需要在开始使用 DLL 之前知道哪些类、函数和类型存在于 DLL 中。正如名称所暗示的，DLL 可以动态加载，但不能动态使用。例如，您无法在一组 DLL 中搜索给定名称的函数。即使您能够找到该函数并加载它，也没有办法询问系统可以向其传递哪些参数。C# 反射为您提供了这种能力。

接下来，您将了解反射的必要性。

## 反射的必要性

反射是 .NET Framework 的重要特性，因为它用于提取 .NET Framework 中类的每个细节。反射在开发大型应用程序时由于其能够收集和操作程序集和应用程序元数据中的数据而具有重要意义。它也是必要的，因为

它具有在运行时获取正在加载的内容以及已加载类的成员如何被调用的信息的能力。换句话说，反射对于充分的版本控制、类的动态加载以及应用程序的适当安全处理是必要的。

接下来，您将了解如何使用反射。

## 使用反射

为了理解反射的工作原理，您首先需要了解两个主要概念——应用程序的程序集和清单。我们已经在第 33 章，即 .NET 程序集中详细讨论了程序集和清单。然而，为了回顾它们，让我们简要回顾主要组件。

已经定义，程序集是 .NET 应用程序中的基本部署单元。程序集包含代码、元数据以及在运行时环境中实现和运行应用程序的规则（版本控制和安全）。程序集文件是一个自描述文件，其中包含在应用程序加载到内存中时由运行时环境加载的中间语言（IL）代码。IL 代码包含描述该程序集中类型和方法的信息，这些信息可以使用与经典组件对象模型（COM）的查询接口功能类似的方式使用。

从前面的章节中，您知道清单包含关于程序集整体的信息。清单包含可由运行时环境用于确保在需要时加载应用程序中的正确版本文件的命名和版本信息。此外，由于清单包含对其他程序集的引用，整个包可以一次加载到内存中，运行时可以在程序开始之前验证应用程序的所有元素是否存在。这种技术解决了 Windows 编程早期版本中普遍存在的缺失 DLL 问题。

除上述内容外，清单还包含安全信息，详细说明运行应用程序时允许访问的边界。由于您可以在 C# 中创建的各种类型的应用程序，这种概念非常重要。例如，具有与基于 Web 的应用程序相同访问级别的系统服务必须具有强烈的安全措施以避免黑客入侵您的系统，但不推荐。另一方面，系统服务需要自由地执行其所需的操作，而无需人们参与运行。

清单的最终组件是程序集中找到的所有类型的列表。类型重要，不仅因为它们是应用程序的基本构建块，而且因为您无法在没有它们的情况下使用安装在程序集中的功能。反射主要处理 C# 运行时环境中的清单信息。

现在您已经回顾了程序集和清单，让我们继续看看如何在应用程序中使用反射。C# 反射需要 System.Reflection 命名空间，其中包含所有反射相关类，如 Type、MemberInfo 等。这些类用于从 .NET Framework 下的任何其他类中检索信息。System.Type 类是 System.Reflection 的基类，是访问元数据的主要方式。System.Type 类是一个抽象类，表示公共类型系统（CLS）中的一种类型。

我们之前提到，反射可以动态创建任何类型的实例，将类型绑定到现有对象，或从现有对象获取类型。类型包括构造函数、方法、字段、属性、事件、类和程序集。创建实例后，可以调用适当的方法，并访问字段和属性。这可以通过仅指定对象类型或同时指定需要创建的对象的程序集和类型来完成。此外，反射还使您能够找出与新创建的对象关联的各种方法以及在 C# 中使用这些对象的方式。您可以使用 MemberInfo 抽象类来找出与对象关联的属性和方法。
