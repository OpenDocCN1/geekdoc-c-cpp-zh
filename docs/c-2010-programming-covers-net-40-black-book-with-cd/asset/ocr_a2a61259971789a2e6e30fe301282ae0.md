# Improved Performance

The improvement in the performance of Silverlight 3.0 applications is attributed to the following features:

+   - Assembly caching – Enables the caching of assemblies locally on the client’s machine. In other words, it means that you need not include all the Silverlight assemblies to create an application package by compiling your Silverlight 3.0 applications, as you can use the Silverlight assemblies from the client’s machine.

+   - Binary XML – Helps in increasing the speed at which data can be exchanged between the client and the server by allowing the compression of communication with the server.

+   - Local connection – Enables two Silverlight applications being hosted within the same ASP.NET or HTML test pages to communicate with each other on the client-side itself so that the messages need not be sent back and forth between the client and the server. The Silverlight 3.0 applications are able to communicate with each other because of a new API called LocalConnection that has been introduced in Silverlight 3.0. For instance, a DataGrid control in a Silverlight application can communicate with a ListBox control in another Silverlight application.
