**NOTE**
*.NET compiler automatically creates the generated files (.g.cs files) and you should not manipulate the content of these files if not required.*

After compiling the XAML code, the generated files (.g.cs files) and .NET language code are compiled by the language compiler (csc.exe) into an assembly. The assembly can be an executable (.exe) or dynamic link library (.dll) and contains the .baml file as a resource. When the compilation of the WPF application is complete, you can run it. You can do this by selecting the Debug→Start Debugging option or pressing F5 from the keyboard. This would start the debugging of the WPF application, which implies that the application is compiled and then executed. With the debugging option, you can control many of the aspects of the execution of the WPF application, for example, setting breakpoints, step into and step over the statements, and much more. The debugger allows you to fix compile-time and run-time errors (exceptions).

**NOTE**
*There is one .baml file and a .g.cs file for every window (standalone WPF applications) and page (XBAPs) in a WPF application.*
