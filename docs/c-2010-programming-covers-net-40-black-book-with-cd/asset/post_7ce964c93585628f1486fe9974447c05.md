In .NET remoting, channels are objects that transport messages between the remote objects. You can implement channels in programs by calling the methods of the ChannelServices class.

Table 35.8: Noteworthy Public Methods of the ChannelServices Class

| Method | Description |
|---|---|

The .NET remoting architecture ensures that at least one channel should be registered before registering an object on the remote system. In addition, a client object must specify a channel to communicate with the remote object. Then, a registered channel automatically starts listening the client requests at the specified port on the remote system.

Channels are independent of remote objects in the sense that they act as tunnel between the client's AppDomain and the server's AppDomain. For example, if the server's AppDomain registers one channel to publish a remote object and another channel to publish another remote object; then the client can access any of the objects using any of the channels. However, these objects are not accessible from a channel registered by another AppDomain.

Even though channels are registered on different machines, they are specific to their application domains in which they have been registered. Therefore, if the channel is registered to a machine but is not registered to the client's AppDomain on that machine, the channel cannot expose objects. As channels are AppDomain specified, they get destroyed as soon as the AppDomain is destroyed. Moreover, only one channel of a particular kind can be registered on a computer to listen on the particular address and port, though two or more different channels can be registered to listen on a same address and port. There are the following types of channels:

- TCP
- HTTP
- IPC

Let’s discuss these in detail, one by one.

## The TCP Channel

The TCP channel is a socket-based transport channel that uses the TCP protocol to transport the serialized message stream across boundaries. It uses the TcpChannel class to setup a remoting server and its client. The TcpChannel class is defined in the System.Runtime.Remoting.Channels.Tcp namespace and implements the IChannel, IChannelSender, and IChannelReceiver interfaces, which means the TcpChannel class supports both sending and receiving data across .NET remoting boundaries. By default, the TcpChannel class uses the binary formatter to serialize messages; however, it can also use the SOAP formatter.

The class hierarchy of the TcpChannel class is shown as follows:

## The HTTP Channel

The HTTP channel uses the HTTP protocol to transfer messages over the Internet. You can specify an HTTP channel for remote calls to a client by using the HttpChannel class. This class can be used over the Internet because firewalls generally do not block HTTP communication. The HttpChannel class is defined in the System.Runtime.Remoting.Channels.Http namespace and implements the HTTP transport functionality. Similar to the TcpChannel class, the HttpChannel class can also send and receive messages across boundaries. ## The IPC Channel

The Inter Process Communication (IPC) channel uses the IpcChannel class to implement a channel that uses the IPC protocol to transmit messages. The IpcChannel class is much faster than the HttpChannel and TcpChannel classes as it bypasses the traditional network communication to cross AppDomains. Therefore, the IpcChannel can be used only for communication between application domains on the same computer. Moreover, you cannot use the IpcChannel class to build a distributed application that spans multiple physical computers. The IpcChannel class is defined in the System.Runtime.Remoting.Channels.Ipc namespace and implements the functionalities of the IpcClientChannel and IpcServerChannel classes. It can also send and receive messages across boundaries.
