
<authentication mode="windows|Forms|Passport|None">
  [<forms>
    name="cookieName"
    loginUrl="loginURL"
    defaultUrl="defaultUrl"
    protection="All|None|Encryption|validation"
    timeout="30"
    path="path"
    requireSSL="true|false"
    slidingExpiration="true|false"
    enableCrossAppRedirects="true|false"
    cookieless="UseUri|UseCookie|AutoDetect|UseDeviceProfile"
    domain="domainName">
      <credentials passwordFormat="Clear|SHA1|MD5">
        <user name="userName" password="password"/>
      </credentials>
  </forms>]
  [<passport redirectUrl="loginURL" />]
</authentication>

In the preceding code, you can see that the <authentication> element has an attribute named mode. The mode attribute refers to the authentication mode specified for the ASP.NET application. There is a set of predefined values that can be set for the mode attribute. These values are given as follows:

- Windows – Refers to the Windows authentication for accessing the Web resource. It allows you to use any of the Windows authentication available in IIS, that is, with Basic, Digest, or Integrated Windows authentication. This is the default value for any Web resource.
- Forms – Refers to the Forms authentication for accessing the Web resource.
- Passport – Refers to the Microsoft Passport authentication for accessing the Web resource.
- None – Refers to the authentication when the user credentials (user name and password) are not required to access a Web resource. This value is useful for anonymous or custom authentication.

You can also notice from the syntax that the <authentication> element can have two child elements, <forms> and <passport>. The <forms> element is used when you use the Forms authentication, that is, when the mode attribute of the <authentication> element is set to Forms. The <forms> element has several attributes, which are listed in Table 36.16:

## Table 36.16: Attributes of the <forms> Element

| Attribute | Description |
|---|---|
| Name | Refers to the HTTP authentication cookie used for authentication of a user. The default value for this attribute is .ASPXAUTH. |
| loginUrl | Refers to the URL of the page where the user needs to provide the credentials for authentication. The default value for this attribute is login.aspx. |
| defaultUrl | Refers to the URL of the page to which users are redirected after they are authenticated. The default value for this attribute is default.aspx. |
| Protection | Refers to the type of protection to be used for the authentication cookie. This attribute can have any of the following values: |
|  | All | Indicates that the cookie is protected by using both encryption and validation. This is the default value. |
|  | None | Indicates that the application does not use encryption and validation to protect the cookie. |
|  | Encryption | Indicates that the application uses the DES or 3DES to encrypt the cookie. No validation is performed on the cookie. |
|  | Validation | Indicates that the application uses a validation mechanism to protect the cookie. |
| Timeout | Refers to the time (in minutes) for which the authentication cookie exists. The cookie expires after the time specified by this attribute elapses. The default value for this attribute is 30 (minutes). |
| Path | Refers to the path for storing the authentication cookie. The default value for this attribute is /, which refers to the root folder of the application. |
| requireSSL | Specifies whether a Secure Sockets Layer (SSL) connection is essential to pass the authentication cookie. The default value for this attribute is false. |
| slidingExpiration | Specifies whether the expiration time for the authentication cookie resets on every request in the same session. The default value for this attribute is false. |
| enableCrossAppRedirects | Specifies whether authenticated users can be redirected to Web pages in other Web applications. The default value for this attribute is false. |
| cookieless | Refers to when and how the authentication cookie is generated. This attribute can have either of the following values: |
| UseUri | Indicates that cookies are not used at all. |
| UseCookies | Indicates that cookies are always used. |
| AutoDetect | Indicates that cookies are used only if the Web browsers support them. An attempt to use a cookie is through a probing mechanism. |
| UseDeviceProfile | Indicates that cookies are used only for Web browsers that support cookies. There is no probing mechanism for Web browsers that support cookies. This is the default value. |
| domain | Refers to an optional domain for the outgoing authentication cookie. The default value for this attribute is an empty string. |

The <forms> element can have a <credentials> element that allows you to specify the credentials of users when they are authenticated using Forms authentication. The <credentials> element has an attribute named passwordFormat. This attribute refers to the format for storing the passwords in an encrypted state. This attribute can take the following values:

- Clear – Indicates that the passwords are not encrypted; instead, they are stored as plain text
- SHA1 – Indicates that the passwords are encrypted using the SHA1 hash algorithm, which is the default value
- MD5 – Indicates that the passwords are encrypted using the MD5 hash algorithm

The <credentials> element can have three child elements: <clear>, <remove>, and <user>. Table 36.17 lists these three child elements along with their syntax:

## Table 36.17: Child Elements of the <credentials> Element

| Child Element | Description | Syntax |
|---|---|---|
| <clear> | Allows you to clear all the references of any inherited connection strings. These elements allow you to use only those connection strings created by the current user. | <clear/> |
| <remove> | Allows you to remove a reference of a particular user from the available credentials. | <remove name="userName"/> |
| <user> | Allows you to define the users for the Web application. | <user name="userName" password="password"/> |

Note that there can be several <user> elements in the <credentials> element. If a user requesting for the Web application has any of the user name and password combination, then that user becomes an authenticated user. If you have specified Passport as the value for the mode attribute of the <authentication> element, then you need to define the <passport> element as the child of the <authentication> element. The <passport> element has only one attribute named redirectUrl. This attribute refers to the URL to which users are redirected for authentication with Microsoft Passport. The default value of this attribute is internal.

## The <authorization> Element

As you know, after authentication, a user needs to be authorized to access and use an ASP.NET application. You can use the <authorization> element in the web.config file to specify the kind of authorization you want to implement for the Web application. In the <authorization> element, you can specify the user names and/or roles that an authenticated user must have to perform an action in the Web application. Similar to the <authentication> element, you can define the <authorization> element in the machine.config or web.config file of the Web application, website, Web page, or any subdirectory.

The <authorization> element also appears in the <system.web> element. The syntax of the <authorization> element is as follows:

```
<authorization>
  <allow users="comma-separated list of users"
        roles="comma-separated list of roles"
        verbs="comma-separated list of verbs"/>
  <deny users="comma-separated list of users"
        roles="comma-separated list of roles"
        verbs="comma-separated list of verbs"/>
</authorization>
```

In the preceding syntax, you can see that the <authorization> element does not have any attributes but can have two child elements, <allow> and <deny>. The <allow> element enable you to specify the users, roles, and HTTP transmission methods that have the permission to access the Web application. On the other hand, the <deny> element enable you to specify the users, roles, and HTTP transmission methods that are denied access to the Web application. Both these elements can have three attributes, as listed in Table 36.18:

## Table 36.18: Attributes of the <allow> and <deny> Elements

| Attribute | Description |
|---|---|
| Users | Allows you to specify a comma-separated list of user names that are granted/denied access to the Web application. The default value for this attribute is an asterisk (*) indicating that all authenticated users have/do not have access to the Web application. You can also use a question mark (?) to allow/deny access only to anonymous users. |
| Roles | Allows you to specify a comma-separated list of roles that are granted/denied access to the Web application. An empty string ("") indicates that users that have no roles are granted/denied access. |
| Verbs | Allows you to specify a comma-separated list of HTTP transmission methods that have/do not have access to the Web application. The HTTP transmission methods that you can specify include GET, POST, DEBUG, and HEAD. |

### NOTE

If you want to refer to the users or roles on the computer, then you can use the dot (.) to represent the current computer. This is only applicable for Windows user accounts.

### TIP

It is advisable not to use the <deny> element prior to the <allow> element as the access is allowed or denied depending on the order in which elements are specified in the <authorization> element. For example, if you specify the <deny> element as follows:

```
<authorization>
  <deny users=""/>
  <allow users="TestUser"/>
</authorization>
```
