# In Depth

There have been some technical enhancements in C# 2010 that are over and above the previous versions of C# These enhancements include dynamic data type and Dynamic Language Runtime (DLR). In the previous versions of C#, you could only check the accuracy of code after the application was compiled. If there was some error in the code, then the entire application was required to be rebuilt. Dynamic data type is introduced to overcome this problem. This is a reference type data type, which is checked at the run time instead of compile time; thereby, allowing you to detect the errors at run time only. You can easily convert a dynamic data type into a non-dynamic data type and vice-versa. The DLR feature of C# makes it possible to integrate dynamic programming languages, such as Python and Ruby with the Common Language Runtime (CLR). These languages can identify the data type of an object at run time. DLR provides an environment that enables statically-typed languages to behave similar to dynamic languages without losing their own properties.

In this chapter, you are first introduced to dynamic data types and how they can be used in C# applications. You also learn to convert dynamic data types into non-dynamic data types and vice versa. Next, the chapter discusses about the DLR, its advantages, and architecture. Finally, you learn about the ExpandoObject and DynamicObject classes.

Let’s start by discussing dynamic data type.

# Understanding the Dynamic Data Type

The dynamic data type is a new data type introduced in C# 2010 that supports the late binding. This implies that all the member functions and member variables such as fields, methods, and properties that are associated with dynamic keyword are ignored at compile time. The compiler preserves all the information about the expression, such as data type, which is used later to evaluate the expression at runtime. The dynamic data type is similar to the var data type. The difference between the var and dynamic data types is that var is strongly type checked at compile time; whereas, the dynamic data type is type checked by the compiler only at run time. After declaring a var data type, you cannot explicitly change its type throughout the execution of the program. Following code snippet shows the declaration of a dynamic data type:

```
// In this case, intDyn, floatDyn and stringDyn
// are the name of variables whose data type is dynamic
dynamic intDyn = 4;
Console.WriteLine(intDyn);

dynamic floatDyn = 4.46;
Console.WriteLine (floatDyn);

dynamic stringDyn = "EnhancedType";
Console.WriteLine (stringDyn);
```

In the preceding code snippet, even if you replace the dynamic keyword with the var keyword, the result would be the same. Following code snippet shows the working of the var keyword:

```
class Program
{
    static void Main(string[] args)
    {
        string a = "EnhancedType";
        var str = a;
        Console.WriteLine(str.NonExistingFunction());
    }
}
```

In the preceding code snippet, the NonExistingFunction() method is not declared or defined anywhere in the class, although, in the Main(string[] args) function, the str variable, which is of the var data type calls this method.
