6. Add the following highlighted line to the AssemblyInfo.cs file of the DistAssembly project:
...
[assembly: AssemblyDelaySign(true)]
[assembly: AssemblyKeyFile("../../ThePublickey.snk")]...

Now, build the assembly using Build→Build DistAssembly. You can then turn off the verification process for the assembly by using the following command:
sn /Vr DistAssembly.dll

The receding command also creates enough free space in the assembly for the signature information so that the assembly can be signed again at a later stage.

Now, you may provide the assembly to another developer, with the public key file. Moreover, after the developer completes his work on the assembly, you can sign the assembly with a private key using the following command:
sn /R DistAssembly.dll ../../TheKey.snk

> Tip
> Delayed Signing can also be performed from the project property's Signing tab.

# Configuring Assembly Lookup

As already learned, private assemblies reside in an application folder; whereas, shared assemblies reside in the system's GAC. However, there are situations when you might need to place your assemblies at some other specific locations. .NET Framework 4.0 allows you to decide a location for your assembly so that you can configure your applications to look up the assemblies at the specified locations. As discussed in the In Depth section, all configurations take place in the assembly configuration files. There are two ways to work with the configuration files. One is through the configuration tools and the other way is doing it manually. Let's explore these methods next.

# Configuring Probing

In this section, we configure the assembly lookup for private assembly (PrivateAssembly) and its client (Displayer), which we have created earlier in this chapter. Create a new copy of the Displayer application and add a subfolder in its bin\Debug directory, named SubDir. Now, move PrivateAssembly.dll to the SubDir folder. At this stage, if you try to run the Displayer application, a System.IO.FileNotFoundException exception occurs. This exception occurs because the Displayer application searches the PrivateAssembly.dll file in the same folder where it itself resides.

You can configure the probing setting in your client application, which allows the application to search the assembly in the specified location. As mentioned earlier, you can do it by using the configuration tools as well as manually. Let's learn about these two methods next.
