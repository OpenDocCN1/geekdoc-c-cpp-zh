## 深入探讨

到目前为止，我们已经学习了如何通过 ADO.NET 和语言集成查询（LINQ）的概念在应用程序中访问数据库中的数据。我们还知道，要为项目开发任何数据库，首先必须设计一个概念模式，然后基于该概念模式设计逻辑模式或模型。以前，要开发一个项目，您必须首先在纸上或白板上设计概念模型。这是一个耗时且容易出错的过程，开发人员必须记住概念模型所依据的每一个数据细节。我们甚至无法在应用程序中以可执行的形式处理实体。

为了克服所有这些问题，ADO.NET 引入了实体框架的概念。ADO.NET Entity Framework 使用户能够通过 Visual Studio 2010 和 .NET Framework 4.0 以可视化方式设计模型并映射数据库、表和视图。ADO.NET Entity Framework 还为用户提供了对概念模型进行编程的能力。在编程中引入实体框架的最终目标是提高数据编程的抽象级别，并帮助开发人员提高生产力。

ADO.NET Entity Framework 使开发人员能够展示数据逻辑模式的基本特征，并将其概念模式呈现给应用程序。在逻辑模式中，数据以数据库中的表的形式存储。例如，产品的详细信息可以存储在 Products 表中，与产品对应的订单可以存储在 Orders 表中，联系人的详细信息可以存储在 Contacts 表中。在创建实现这些表的应用程序时，开发人员应该了解这些表所在的数据库。使用逻辑模式的缺点是，应用程序通常必须使用 JOIN 子句从表中检索数据，因为逻辑数据库并不总是能表示应用程序所需的数据视图。在这种情况下，如果逻辑模式发生更改，应用程序也会受到影响，需要根据更改后的模式进行修改。

让我们借助一个例子来说明这一点。假设我们需要在应用程序中创建一个查询，返回学校中 2008 届所有学生的姓名和成绩。为此，我们可以使用以下查询：

```
SELECT c.FirstName, s.RollNumber
FROM Students s
INNER JOIN Contact c on s.StudentID = c.ContactID
Where admission date >= '2008-01-01'
```

在上述查询中，对所有相关表使用了 JOIN 子句来获取结果。基于上述语法，开发人员在实现此类查询时会遇到以下问题：

- 语法复杂，不必要地耗费更多精力和时间。在此示例中，为了检索所需信息，应用程序必须处理两个表，即 Students 和 Contacts 表。
- 有时，数据库的逻辑模式无法根据开发人员的需求使用应用程序的某些部分。在这种情况下，应用程序必须处理整个逻辑模式，这会不必要地增加服务器的额外负载。
- 逻辑模式无法理解业务实体及其相互关系，因为关系模型等模型无法呈现应用程序的概念领域知识。
- 如果应用程序处理的是数据子集，开发人员应该能够指出应用程序所需的适当子集。

这些问题在面向数据的应用程序中非常常见。为了解决这些问题，ADO.NET 引入了实体框架的概念，其设计目的是解决数据格式之间的不匹配问题。数据以表的形式存储在数据库中，并通过面向对象的编程语言来使用。ADO.NET Entity Framework 由数据模型组成，并提供设计时和运行时服务，使开发人员能够描述应用程序数据。

当我们使用逻辑模式时，查询会返回某些值与数据源无关的值。这意味着在整个应用程序中，关于核心应用程序概念，数据库元素之间没有共同的关系。Entity Framework 允许开发人员描述应用程序数据，并将应用程序与底层逻辑数据库模式隔离开来。

在本章中，您将了解 ADO.NET Entity Framework 及其功能。接下来，您将学习实体数据模型（EDM），其中包括数据建模、概念模式定义语言、存储模式定义语言、映射规范语言、EDM 类型、类型约束和数据模型工具。除此之外，您还将学习对象服务、实体结构化查询语言（SQL）及其运算符、EntityClient 提供程序、ADO.NET 元数据和 EDM 生成器工具。
让我们更详细地探讨实体框架的概念。

## 探索 ADO.NET Entity Framework

ADO.NET Entity Framework 不支持将面向对象的类和属性直接映射到关系表和列。它将关系表、列和外键约束映射到概念模型中的实体和关系。现在，让我们了解实体框架的架构。

ADO.NET Entity Framework 旨在支持面向数据的应用程序和服务，并提供一个编程平台，将抽象级别从逻辑关系级别提高到概念级别。ADO.NET Entity Framework 通过使开发人员能够在更高的抽象级别上处理数据，来支持独立于任何特定数据存储（如 SQL Server 引擎或逻辑模式）的代码。概念模型通常用作捕获数据知识和解释应用程序需求的工具，这些需求通常在项目的早期阶段讨论。Entity Framework 提供了将实体和关系规范化为带外键约束的表的能力。因此，它使应用程序能够避免对特定数据引擎甚至特定逻辑模型的硬编码依赖。图 22.1 显示了实体框架的架构：
