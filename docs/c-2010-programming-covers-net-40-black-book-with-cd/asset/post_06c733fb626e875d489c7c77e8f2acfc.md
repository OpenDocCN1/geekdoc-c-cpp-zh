## Exploring the Features of Entity Framework

For developing an Entity Framework application, we need to create a conceptual model, a logical model, and a programmable object model in Visual Studio 2010. A conceptual model defines the entities and relationships in an application. A programmable object model is then generated from the conceptual model. A logical model represents a relational model and a mapping between the conceptual and relational models. Some of the features of Entity Framework that elevate the level of abstraction for data programming and help the developers to increase productivity are as follows:

- Enhances performance by improving the speed of object query execution and makes generation of SQL query simpler.
- Performs operations with disconnected components, which locally caches datasets and entity sets for using Entity Framework in an occasionally connected environment.
- Enhances extensibility and business logics by using partial methods in code generation for changes in property and property changed events.
- Constitutes many query improvements such as addition of canonical functions for LINQ to Entities and addition of more operations to work with a database.
- Expands the data model that describes data during the development process. EDM provides two data models, that is, conceptual data model and storage model, and a mapping that performs translation between these two models.

Along with these, there are some new features introduced in Entity Framework in the new release of .NET Framework, which are as follows:

Introduction of foreign keys so that the process of creating and modifying relationships between entity types is simplified. The developers had two views regarding the inclusion of foreign keys in conceptual and object models. Some felt that the inclusion of foreign keys is very advantageous, while some felt that the foreign keys pollutes their conceptual and object models. Therefore, in .NET Framework 4.0, a support for new type of association called FK association has been added. This association simplifies the process of generation of a conceptual model when the foreign keys are exposed as entity properties.

When you generate a model from an existing database, the default nature of the Entity Designer tool is to create scalar properties on entity types that are corresponding to the respective foreign keys columns in the database.

- Introduction of Plain-Old Common Language Runtime Objects (POCO), which allows the developers to create classes that are not only simple, but also can be included in the Entity Framework. In the previous versions of .NET Framework, the classes that derived from a model are inherited from the EntityObject class. This was a hindrance for the developers if they wanted to create simple classes that are not bound to a Framework. POCO helps the Entity Framework to use custom data classes along with the data model without making any changes to the data classes. In simpler language, if you have a class called Employee with name, address, and phone number, then the Entity Framework will not change the class while implementing it. This implies that the class will not include EntityKey or any other property, which requires you to implement any interface specific to Entity Framework while creating an application.
- Introduction of lazy loading in Entity Framework in this version of .NET Framework. The lazy loading feature is a common feature of many Object Relational Mapping (ORM) tools such as LINQ to SQL. The lazy loading feature, in simple terms, is a design pattern that helps in rescheduling the initialization of an object till the point in it is needed. This feature helps in improving the efficiency of the operation of a program. In Entity Framework, the lazy loading feature will load the related objects when they are accessed through a navigation property. This new feature can be implemented in Entity Framework by setting the LazyLoadingEnabled property to true (which by default is set to false). The LazyLoadingEnabled property is an instance of the ObjectContext class, which is the primary class for interacting with data as objects in Entity Framework.
- Introduction of support for the QueryExtender control and POCO for the EntityDataSource control. The EntityDataSource control is an ASP.NET data source control, which was a part of the earlier version of Entity Framework. However, with the new version, the EntityDataSource control has been improved to support the new feature introduced in ASP.NET, that is, the QueryExtender control, which helps in having more control over data retrieval from a data source. The QueryExtender control is a very helpful control in developing Rapid Application Development (RAD) websites.

Along with the support for the QueryExtender control, the EntityDataSource control now supports the POCO entities also, which helps the EntityDataSource control to use the generated classes for its functioning.

- Introduction of support for binary keys. The new version of Entity Framework now provides support to binary property types that are mapped as entity/foreign key (commonly known as binary keys).
- Introduction of ObjectMaterialized event. In this version of Entity Framework, it is possible to write logic that can be executed immediately after the object has been materialized.
