- Operation contract
- Data contract

## Operation Contract

The operation contract defines the methods that should be exposed to the external client. It provides the OperationContractAttribute attribute, which is used to tag every method that is a component of a service contract. Table 19.4 describes the properties of the OperationContractAttribute attribute:

| `IsInitiating` | Initiates an operation from a sequence of operations. The initiating operation starts a new session; whereas. |

| `Name` | Defines the name of an operation. |

## Data Contracts

A data contract is an agreement between a client and service that conceptually depicts the data to be exchanged. The communication between the client and the service does not require the same types; however, requires the same data contract. Unlike service contracts, which can handle only simple types, a data contract can handle complex types. It means that a data contract can handle a complex service call; calls which have complex type arguments and return complex type values.

In WCF, service contracts are defined through interfaces, but data contracts are defined through classes. These classes are prefixed with the DataContractAttribute attribute, and their members are prefixed with the DataMemberAttribute attribute.

Listing 19.3 shows how to apply the DataContractAttribute and DataMemberAttribute attributes in an application to create the MyComplexTypes.ReservationForm type:

## Behaviors

Behaviors are used to customize the runtime behavior of the service endpoint. They also allow you to add custom extensions to services to inspect and validate service configuration or modify runtime behavior of the applications. You can apply behaviors to your WCF service either through the configuration file or through the attributes provided for it. Following is a list of behaviors used by the WCF services:

- Service Behaviors — Identifies service-wide implementation behavior at the service implementation (class) level. You cannot apply this attribute at the contract (interface) level.
- Contract Behaviors — Implements the IContractBehavior interface to extend the runtime of the client and service.
- Endpoint Behaviors — Implements the IEndpointBehavior interface to modify the runtime of a service or client for a specific endpoint.
- Operation Behaviors – Implements the IOperationBehavior interface to extend the runtime of client and service for an operation.

## Configuration of WCF Services

You can configure a WCF service by using the configuration files, which contain the configuration information of WCF services in the XML format. The XML elements inside these files allow you to modify the configuration details, such as the endpoint address of the WCF service, on machine-by-machine basis. WCF also includes some system-defined elements that allow you to rapidly select the most fundamental features for a WCF service. When you deploy your WCF service, the configuration files provide you the flexibility of presenting the endpoint and service behavior data. You can change the configuration of the WCF service using the web.config file or the WCF Editor Configuration tool.

## Using the web.config File

You can use either the web.config or app.config file to configure WCF services. The choice of the configuration file (web.config or app.config) to configure WCF services depends on the hosting environment that you select for your WCF service. If your hosting environment is IIS, you can use the web.config file, and if your hosting environment is other than IIS, use the app.config file. The web.config file of WCF contains the following elements:

- <Service>
- <endpoints>
- <binding>
- <behaviors>

Let’s discuss these elements in detail.

## The <service> element

The <service> element contains the specifications of all the services that are hosted by applications. It consists of the following two attributes:

- name – Indicates the type that provides the implementation of a service contract. It is the combination of namespace and type name.
- behaviorConfiguration – Indicates the name of one of the <behavior> elements that is found in the <behaviors> element.

## The <endpoint> element

The <endpoint> element contains the following attributes:

- address – Indicates the URI of a service, which can be an absolute address or a relative address.
- Binding – Indicates a system-provided binding, such as WSDualHttpBinding, but can also specify a user-defined binding. The specified binding decides the transport protocol, security, and the encoding format used.
- bindingConfiguration – Contains a string that signifies the binding name of a binding, which is used when the instance of an endpoint is created.
- Contract – Signifies the interface that describes the contract by the name attribute of the <service> element.

## The <bindings> element

The <bindings> element consists of the specifications for all the bindings that an endpoint defined in any service can use. It contains one or more <binding> elements that have a name attribute. This attribute associates the binding with the endpoint specified in the bindingConfiguration attribute of the <endpoint> element.

## The <behaviors> element

The <behaviors> element acts as a container element for one or more <behavior> elements, which describe the behavior of the services. Each <behavior> element consists of a name attribute, which defines either a system-provided behavior or a custom behavior.
