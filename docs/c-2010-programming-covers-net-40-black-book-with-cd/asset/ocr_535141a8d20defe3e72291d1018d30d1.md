# Table 22.1: Noteworthy Entity Framework Terminologies

| Term | Definition |
|------|------------|
| query path | Represents a string of a path that specifies which related objects to return when a typed object query is executed. A query path is defined by calling the Include method on the ObjectQuery class. |
| object context | Represents the entity container defined in the conceptual schema. It contains a connection to the underlying data store and provides services such as change tracking. |
| object query | Represents a query executed against an EDM within an object context that returns data as objects. |
| Object Services | Refers to a service provided by Entity Framework that enables application code to operate on entities in terms of .NET Framework objects. |
| referential constraint | Defines an EDM, which indicates that an entity has a dependent relationship to another entity. This constraint means that an instance of a dependent entity cannot exist without a corresponding instance of the principal entity. |
| relationship | Represents a logical connection between entities. |
| role | Represents the name given to each End of an association. It helps to clarify the semantics of relationships. |
| scalar property | Represents a property of an entity that maps to a single field in the storage schema. |
| simple type | Defines a primitive type that is used for defining properties in the conceptual schema. The storage schema uses data types of the storage model. |
| store schema definition language (SSDL) | Refers to an XML-based language that is used to define the entity types, associations, entity containers, entity sets, and association sets of a storage model often corresponding to a database schema. |
| table-per-hierarchy (TPH) | Refers to a method of modeling a type hierarchy in a database that includes the attributes of all the types in the hierarchy in one table. |
| table-per-type (TPT) | Refers to a method of modeling a type hierarchy in a database. The database consists of multiple tables with one-to-one relationships to model various types. |
| XML (simple type) | Contains well-formed XML or valid XML data. The different facets of this type specify the kind of XML data that can be contained in it. |
| complex type | Represents a complex property as defined in the conceptual model. |

# Exploring the Features of Entity Framework

For developing an Entity Framework application, we need to create a conceptual model, a logical model, and a programmable object model in Visual Studio 2010. A conceptual model defines the entities and relationships in an application. A programmable object model is then generated from the conceptual model. A logical model represents a relational model and a mapping between the conceptual and relational models. Some of the features of Entity Framework that elevate the level of abstraction for data programming and help the developers to increase productivity are as follows:

+   - Enhances performance by improving the speed of object query execution and makes generation of SQL query simpler.
+   - Performs operations with disconnected components, which locally caches datasets and entity sets for using Entity Framework in an occasionally connected environment.
