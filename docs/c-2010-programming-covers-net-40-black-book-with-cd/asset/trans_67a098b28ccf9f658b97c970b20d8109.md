## Roles 类

基于角色的安全在保护 ASP.NET 应用程序方面起着重要作用。借助主体、标识和角色，你可以轻松有效地保护应用程序及其他特定于应用程序的资源。角色是一组类型相似的用户。例如，你可以将所有具有管理权限的用户分组到管理角色下。现在，让我们继续了解 Roles 类，它允许你创建角色、将用户分配到角色以及管理角色。角色管理是指为访问 ASP.NET 应用程序的不同角色分配不同的权限。例如，你可能需要限制那些不是 Administrator 角色成员的用户访问成员资格数据存储区。

Roles 类的层次结构如下：

```
System.Object
System.Web.Security.Roles
```

一个用户可以是多个角色的成员，并享有多个角色的特权。例如，如果你在 ASP.NET 中创建了一个在线讨论论坛，你可能需要将同一个用户同时分配到成员角色和版主角色。该用户将同时享有成员角色和版主角色的特权。

Roles 类位于 System.Web.Security 命名空间中，该命名空间位于 System.Web 程序集中。Roles 类不能被继承。

由于 Roles 类是静态类，你可以直接使用其成员，而无需使用 Roles 类的实例来限定它们。

### 注意

> Roles 仅适用于经过身份验证的用户。

## ASP.NET 安全体系结构

保护 ASP.NET 应用程序涉及 Internet Information Services (IIS)、.NET Framework 和底层操作系统之间的集成同步。如你所知，IIS 是 Windows 操作系统（如 Windows 7）的一部分，作为管理和组织计算机上 Web 应用程序的基础。IIS 提供强大的安全系统来保护 Web 应用程序及其资源。IIS 还可以利用 Windows 操作系统的安全功能。

客户端（Web 浏览器）对 ASP.NET Web 应用程序发出的请求首先由 IIS 处理。如果客户端已通过 IIS 的身份验证，则请求被转发到 ASP.NET 应用程序；否则，拒绝该请求。ASP.NET 应用程序可以使用 .NET Framework 的安全系统对客户端进行身份验证和授权。

ASP.NET 应用程序的安全性在很大程度上依赖于 IIS 和 .NET Framework 提供的安全机制。在 IIS 6.0、7.0 和 7.5（随 Windows 7 提供）中，ASP.NET 工作进程 (aspnet_wp.exe) 在 NetworkService 帐户下运行，IIS 工作进程 (w3wp.exe) 也在此帐户下运行。IIS 工作进程承载 IIS Web 服务器，而 ASP.NET 工作进程承载 ASP.NET 应用程序。NetworkService 帐户是一个具有某些有限权限的内置帐户。此帐户可以保护 Web 服务器免受黑客和意图破坏 Web 服务器的用户的恶意攻击。NetworkService 帐户用于运行 ASP.NET 工作进程，而不是像以前版本的 IIS 和 Windows (Windows XP) 那样使用 ASPNET 用户帐户。

在某些情况下，你可能希望以比 NetworkService 帐户更少的权限运行 ASP.NET 工作进程。在这种情况下，你可以通过更改 machine.config 文件中的某些相关属性来更改运行 ASP.NET 工作进程的用户帐户。machine.config 文件位于计算机上的 C:\Windows\Microsoft.NET\Framework\v4.0.30319\Config 文件夹中。machine.config 文件是一个 XML 文件，包含定义 .NET 应用程序机器级配置设置的各种标记或元素。你可以在记事本或 Visual Studio 2010 中打开 machine.config 文件，并在 <system.web> 元素中找到 <processModel> 元素。在 <processModel> 元素中，你可以设置 userName 和 password 属性。若要让 ASP.NET 工作进程在 TestUser 用户帐户下运行，请按如下方式设置 userName 和 password 属性：

```
<processModel autoConfig="true" userName="TestUser" password="@kogent30"/>
```

password 属性的值是你为 TestUser 帐户指定的密码。

### 注意

> 除了 NetworkService 帐户之外，还有 LocalSystem 和 LocalService 内置帐户。LocalSystem 帐户属于 Administrators 组，在三个帐户中拥有最大权限。因此，LocalSystem 帐户对于 Web 服务器和 Web 应用程序可能不安全。LocalService 帐户的权限最少，在应用程序不使用任何远程资源时非常有用。
