## In Depth

In today’s world of computer programs, reflection is considered as an important technique of programming, as it is used to extract every detail of a program at runtime. In .NET Framework 4.0, a program is said to be reflected on itself when it extracts metadata (self information) from its assembly and uses this metadata for finding assemblies, modules, and type information at runtime.

Reflection is of great significance while developing large applications due to its capability to collect and manipulate the data present in the assemblies and metadata of the applications. It is also necessary for adequate versioning, dynamic loading of classes, and proper security handling of applications. In addition, reflection helps you to get the information of the classes, functions, and types existed in the Dynamically Linked Libraries (DLLs) files. Moreover, in C# 2010, you can implement reflection by using the classes contained in the System.Reflection namespace. Some examples of these classes are Assembly, Module, MethodInfo, and ConstructorInfo.

In this chapter, you learn about the importance of reflection process in C# 2010. This chapter starts with exploring the reflection process, wherein you learn the need and use of the reflection process. Next, you learn about dynamic loading of assemblies using reflection. In the Immediate Solutions section, you learn to use reflection to obtain class and type information from an assembly, and how to obtain member information from a class. Finally, this chapter explains how to use reflection for verifying and dumping the methods and parameters of a class.

Let’s start with exploring the reflection process.

## Exploring the Reflection Process

Reflection is defined as the process of finding out the internal elements, such as metadata, assemblies, modules and types, of an application without accessing the source code. You can also use reflection to find all classes in an assembly, and all the methods, properties, and events that might be supported by each of these classes. Reflection also allows you to search for all kinds of information about a class, such as the base class from which it is derived and the interfaces it supports, and to explore the Common Language Runtime (CLR) programmatically.

The inspection and manipulation of a C# program according to a desired goal is done with the help of reflection. You can inspect all the information about a class and also use reflection techniques to dynamically invoke methods of the class at runtime. The generated code of the methods in the class can be executed directly in the application at runtime.

With the help of reflection, the information in the metadata segment of your assemblies at runtime can be viewed. In a nutshell, reflection enables you to see the data the way the compiler recognizes it when it is building your application into an Executable file (EXE file). You then have the flexibility to create applications that can be extended at runtime by taking advantage of other functionalities on a user’s system. Reflection can also be used, for example, to investigate whether certain classes exist in your home directory and, if so, to load and use them in your own application.

In a programming language without reflection, you are required to know which classes, functions, and types existed in the DLLs before you start using them. As the name suggests, DLLs can be dynamically loaded, but cannot be used dynamically. You cannot, for example, search through a set of DLLs for a function of a given name. Even if you are able to find the function and load it, you have no means to ask the system what parameters can be passed to it. C# reflection provides you this capability.

## Need of Reflection

Reflection is an important feature of .NET Framework because it is used to extract every detail of class in .NET Framework. Reflection is of great significance while developing large applications due to its capability to collect and manipulate the data present in the assemblies and metadata of the applications. It is also necessary because

it has the ability to obtain information at runtime about what is being loaded and how the members of the classes that are loaded to be called. In other words, reflection is necessary for adequate versioning, dynamic loading of classes, and proper security handling of applications.

## Using Reflection

To understand how reflection works, you first need to understand two major concepts—assemblies and manifests of an application. We already had a detailed discussion on assemblies and manifests in Chapter 33, that is, .NET Assemblies. However, to recall them, let’s have a recap of the major components.

It has been already defined that an assembly is the basic unit of deployment in a .NET application. An assembly contains the code, the metadata, and the rules (versioning and security) for implementing and running an application within the runtime environment. An assembly file is a self-describing file that contains the Intermediate Language (IL) code loaded by the runtime environment when the application is loaded into the memory. The IL code contains information that describes the types and methods in that assembly, which can be used in a much similar way as you might use the query interface functionality of classic Component Object Model (COM).

From the earlier chapter, you are aware that a manifest contains information about the assembly as a whole. Manifests contain naming and version information that can be used by the runtime environment to ensure that you are loading the proper version of a file when you want it in your application. In addition, because the manifest contains references to other assemblies, the entire package can be loaded into the memory at one time and the runtime can verify that all elements of the application are present before it starts the program. This technique resolves the missing DLL problem so prevalent in the previous versions of Windows programming.

Besides the above mentioned, manifests also contain security information, which details the boundaries that an application is permitted to access when it is run. This concept is incredibly important because of the varied types of applications you can create in C#. For example, a system service having the same level of access as a Web-based application, which must have intense security to avoid people to hack into your system, is not preferred. A system service, on the other hand, needs the freedom to do what it needs to do without the involvement of people in running it.

The final component of the manifest is the list of all the types found in the assembly. Types are important not only because they are the fundamental building blocks of the application, but also because, you cannot use the functionality installed in an assembly without them. Reflection deals primarily with manifest information in the C# runtime environment.

Now that you have recalled about assemblies and manifests, let’s move on and see how to use reflection in an application. C# reflection requires System.Reflection namespace that contains all the reflection-related classes, such as Type, MemberInfo, and so on. These classes are used to retrieve information from any other class under .NET Framework. The System.Type class is the base class for System.Reflection and is the primary way to access metadata. The System.Type class is an abstract class and represents a type in the Common Type System(CLS).

We have mentioned earlier that reflection dynamically creates an instance of any type, binds the type to an existing object, or gets the type from an existing object. The types include the constructors, methods, fields, properties, events, classes, and assemblies. Once an instance is created, appropriate method can be invoked, and the fields and properties can be accessed. This can be done by specifying only the type of object or specifying both assembly and type of the object that needs to be created. In addition, reflection also enables you to find out the various methods associated with newly created object and the way to use these objects in C#. You can use the MemberInfo abstract class to find out the attributes and methods associated with an object.

- Assembly class – Retrieves and manipulates information about an assembly. This class allows you to perform various functions, such as defining and loading assemblies, loading modules that are listed in the assembly manifest, and locating a type from this assembly to create an instance of it.
