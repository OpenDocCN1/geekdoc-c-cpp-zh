在 .NET 框架中，MSIL 代码可被视为四种代码类型之一——有效、无效、类型安全和可验证类型安全代码。表 36.1 列出了不同类型的 MSIL 代码：

## 表 36.1：运行时 MSIL 代码类型

| MSIL 代码 | 描述 |
|---|---|
| 有效 | 指遵循 .NET 语法和约定的 MSIL 代码，因此可以转换为本机代码。有效的 MSIL 代码可能会使用非类型安全的指针运算。 |
| 无效 | 指无法转换为本机代码的 MSIL 代码。 |
| 类型安全 | 指类型仅通过其公共契约或方法相互访问和交互的 MSIL 代码。 |
| 可验证类型安全 | 指通过验证过程的类型安全 MSIL 代码。 |

现在，让我们详细了解类型安全和可验证类型安全代码。

## 类型安全代码

一种 MSIL 代码，其中一种类型仅通过明确定义且授权的方式访问代码中的其他类型，被视为类型安全代码。明确定义且授权的访问方式是通过使用公共方法和字段。如果一种或多种类型访问另一种类型的私有字段或方法，则 MSIL 代码不被视为类型安全。这意味着在类型安全的 MSIL 代码中，类型不能访问另一种类型的内存位置，除非它具有执行此操作的权限。这种内存隔离和 MSIL 代码的类型安全性可防止类型的侵犯，进而确保一种类型不会被另一种类型进行非预期和恶意的操纵。这最终增强了应用程序的安全性和可靠性。

## 可验证类型安全 MSIL 代码

可验证类型安全代码始终是有效且类型安全的；然而，类型安全代码可能不可验证类型安全。这可能是由于验证过程或语言编译器的不足造成的。CLR 使用内置的验证算法来验证 MSIL 代码的类型安全性。您也可以使用 PEVerify 工具 `peverify.exe` 检查 MSIL 代码是否可验证类型安全，该工具是 .NET Framework 实用程序，可让您确保 MSIL 代码可验证类型安全。您可以在 Visual Studio 2010 命令提示符下使用 PEVerify 工具，并传递包含预期元数据和 MSIL 代码的程序集。使用 PEVerify 工具在命令提示符下的语法为：

```
peverify assemblyname [switches]
```

在上述语法中：

- `peverify` — PEVerify 工具
- `assemblyname` — 您想要执行验证过程的程序集名称
- `[switches]` — 可选的开关集合

PEVerify 工具具有许多开关，其中一些列在表 36.2 中：

**表 36.2：PEVerify 工具的开关**

| 开关 | 描述 |
|---|---|
| `/help` 或 `/?` | 显示 PEVerify 工具的语法和开关 |
| `/md` | 验证程序集中的元数据 |
| `/il` | 验证程序集中的 MSIL 代码 |
| `/clock` | 显示验证所花费的时间（以毫秒为单位） |
| `/hresult` | 以十六进制格式显示错误代码 |
| `/unique` | 隐藏任何重复的错误代码 |
| `/quiet` | 仅显示验证状态，不显示错误代码 |
| `/verbose` | 显示有关验证过程的附加信息 |
| `/ignore=<errorhexcode>[, errorhexcode, errorhexcode…]` | 忽略指定的错误代码（十六进制格式） |
| `/ignore=@filename` | 忽略指定响应文件中的错误代码 |
| `/nologo` | 隐藏产品版本和版权信息 |

请注意，PEVerify 工具在没有表 36.2 中列出的任何或所有开关的情况下执行验证。PEVerify 工具首先验证元数据，如果没有错误，则验证 MSIL 代码。如果元数据验证出现任何错误，则不会验证 MSIL 代码。但是，如果您指定 `/md` 和 `/il` 开关，则无论元数据是否存在错误，MSIL 代码都将被验证。

如果 MSIL 代码经过验证过程但未通过验证，则会发生异常并且应用程序的执行将被停止。如果您确定自己的代码完全受信任且类型安全，则可以绕过验证。您也可以绕过验证以运行非类型安全代码。但是，不建议运行非类型安全代码，因为它可能导致不可预测的结果。要绕过验证，您需要在程序集级别将 SecurityPermission 属性的 SkipVerification 属性设置为 false。

> **NOTE**
> 
> 验证过程仅由 CLR 对托管代码执行；非托管代码不经过验证过程，因此在完全信任环境中运行。

通过这种方式，您可以使用 PEVerify 工具确保 .NET 应用程序的类型安全性，使其在用户计算机上运行安全可靠。通过此，您学习了保护应用程序的第一步。现在，让我们讨论 .NET Framework 4 中的安全更改。
