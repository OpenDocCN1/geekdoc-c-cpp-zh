
The WCF programming model combines Web services, .NET remoting, distributed transactions, and message queues into a single service-oriented programming model for distributed computing. WCF runs in a sandbox (a security mechanism for running programs safely) and provides the enhanced security model to all the WCF applications. To support distributed computing, WCF is designed in accordance with Service-oriented architecture principles where services are used by clients. Services typically have a Web Services Description Language (WSDL) interface, which is used by the clients to utilize the services. WCF implements many advanced Web service standards, such as WS-Addressing, WS-ReliableMessaging, and WS-Security.

## Windows CardSpace

Windows CardSpace (WCS) is a client software that helps in sharing personal information on the Internet. It helps programmers in developing websites and software that are less prone to identity related attacks, such as phishing. WCS helps in reducing the problems of traditional online security mechanisms, as it employs a separate desktop and cryptographically strong authentication, instead using user name and password, for authentication purposes. It facilitates secure online transactions, such as online shopping, banking, and bill payment.

WCS only works with websites that accept the CardSpace logins. When you try to access the resources on the website, which accepts CardSpace, a CardSpace selection window appears. You can select the required card and access the resources on the website. You can create a card using the WCS utility that comes with .NET 4.0. You need to remember only the card instead of multiple usernames and passwords. A provider is required to convert an identity into a card. Some organizations provide their own identity providers to create a card for this conversion. Even WCS comes with its own self-issued identity providers, which are accepted by websites for validating the user. WCS is based on the identity metasystem. This system allows you to use different digital identities across different platforms. There are two types of cards available:

- Personal Cards – Based on the self-issued identity providers
- Managed Cards – Based on identity providers provided by vendors other than Microsoft

Suppose a CardSpace-enabled site wants to retrieve the personal information of a user and for that demands a particular type of token. The CardSpace then represents the stored identities as virtual information cards. The user selects the card to use and the CardSpace software contacts the identity provider to get the digitally signed token that contains the required information. WCS is built with an open set of XML-based protocols, which includes WS-Security, WS-Trust, WS-MetadataExchange, and WS-SecurityPolicy. With these features, any technology or platform can integrate with the CardSpace.

The overall process of the CardSpace contains issuing, acquiring, and using digital identities, and can be defined by the following three distinct roles:

- User – Represents an entity containing a digital identity.
- Identity Provider – Represents a provider that provides a digital identity to the user. The digital identity is used to provide information about the username and password of the user. Digital identities created by the identity providers may contain different information and provide different levels of assurance to identify the actual user.
- Relying Party – Represents an application that relies on a digital identity. It can use an identity to authenticate a user and then make authorization decision, such as allowing or disallowing the user to access information.

## LINQ

LINQ is one of the components of Microsoft .NET Framework 4.0 that adds native data querying capabilities to .NET languages using a syntax similar to SQL.

The following code snippet is a simple LINQ example in C#:

```
var query = from s in Students where s.Gender = "M";
select s.Name;
```

When you execute the given query, it returns the names of all the male students. You can print this list using the code given in the following code snippet:

```
foreach(var name in query)
{
    Response.Write(name);
}
```

The syntax of the query given in the preceding code snippet is similar to that of an SQL query. It is important to note that even if it looks similar to SQL, the LINQ query displayed is not an SQL statement. Instead, it is a purely C# language. Though LINQ queries resemble SQL, they are not restricted to accessing only relational databases.

LINQ enabled data access components are as follows:

- LINQ to ADO.NET – Includes two options, LINQ to SQL and LINQ to DataSet. The LINQ to SQL option is used to translate a query into a SQL query, and then issues it against tables in a SQL Server database. The LINQ to DataSet option is used to execute a query on the contents of a DataSet.
- LINQ to Object – Allows querying objects in a collection.
- LINQ to XML – Allows querying of XML data, including creating and manipulating XML data.

> NOTE
> LINQ also provides other operators for queries, such as OrderBy, GroupBy, and Sum.

## New Features of .NET Framework 4.0

The .NET Framework 4.0 helps in providing a consistent object-oriented programming environment. This version is more secured as it includes an improved security model. Some new features of .NET Framework 4.0 are as follows:

- Improved application compatibility and deployment support
- Dynamic Language Runtime (DLR)

- Parallel computing

Let’s learn about each of them in detail.

### Improved Application Compatibility and Deployment Support

The applications that are developed in the earlier versions of .NET Framework are supported in this version. This implies that the new version of .NET Framework is compatible even with the applications developed in the earlier version of .NET Framework. You can run an application developed in the older version of .NET Framework by specifying the target version of .NET Framework at the time of compilation. You can also run an application created in the older version of .NET Framework by specifying the supported runtime in the application configuration file by using the <supportedRuntime> element.

The following features introduced in the .NET Framework 4.0 provide an improved deployment support:

- .NET Framework Client Profile — Improves the deployment process by providing a fast deployment of Windows forms, console, or WPF applications.
- In-Process Side-by-Side Execution — Helps in loading and starting multiple versions of .NET Framework. The Component Object Model (COM) components run with the .NET Framework, they were developed in.

### Dynamic Language Runtime

The DLR feature is introduced in .NET Framework 4.0 to implement dynamic languages, such as Python and Ruby. This implies that the DLR is a runtime environment that adds services to the CLR to implement dynamic languages.

The purpose of DLR is not only to enable the dynamic languages to run on the .NET Framework but also to provide them with the advantage of .NET interoperability. A new System.Dynamic namespace has been added in.NET Framework to support the DLR functionality. The advantages of DLR are as follows:

- Implements dynamic features in the statically-typed languages, such as C# and Visual Basic (VB), so that these languages can also create dynamic objects
- Enables interoperation between statically-typed languages and dynamic languages, so that the objects that are implemented in one language can easily be used by other languages
- Helps the developers to concentrate on the specific language features as the developers do not have to create code generators
