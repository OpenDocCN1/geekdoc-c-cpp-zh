可用于 ASP.NET 应用程序的身份验证模式有：

- 匿名身份验证
- Windows 身份验证
- 表单身份验证
- Passport 身份验证

请注意，除了 Passport 身份验证外，其他所有身份验证模式都同时受 IIS 7.5 和 ASP.NET 支持。要允许在 IIS 级别进行身份验证，您需要使用 IIS 管理器并指定所需的身份验证。如果您想在 ASP.NET 应用程序中允许身份验证，则需要使用身份验证提供程序。身份验证提供程序是指包含执行所需身份验证的基本代码的代码模块。ASP.NET 为 Windows、表单和 Passport 身份验证提供身份验证提供程序；匿名身份验证没有身份验证提供程序。

现在，让我们一个一个地学习这些身份验证模式。

### 匿名身份验证

请求 ASP.NET Web 资源（例如 Web 页面）的用户默认情况下被验证为匿名用户，即具有任意随机身份的用户。当用户被验证为匿名用户时，该过程称为匿名身份验证。在这种类型的身份验证中，不需要凭据（用户名和密码）来验证用户。这意味着任何尝试访问 Web 资源的用户都会自动通过身份验证，这就是为什么当您希望 ASP.NET 应用程序对所有用户可用或希望获得更好性能时，匿名身份验证很有用。匿名身份验证提供最少的<|message|> 安全，因此，您需要谨慎地对 ASP.NET 应用程序的匿名用户进行身份验证。

### Windows 身份验证

考虑这样一种情况：您的 ASP.NET 应用程序位于 Intranet 或本地计算机上，您希望通过网络或计算机上的不同用户来控制对应用程序的访问。因此，授予应用程序匿名访问可能不是可行的解决方案。在这种情况下，您可以使用 Windows 身份验证来控制对 ASP.NET 应用程序的访问。通过 Windows 身份验证，将用户的身份与存储在 Web 服务器上的 Windows 用户帐户进行检查。如果用户的凭据与 Windows 用户帐户的凭据匹配，则用户通过身份验证。您可以在 IIS 以及 ASP.NET 应用程序中使用 Windows 身份验证。默认情况下，所有 ASP.NET 应用程序都使用 Windows 身份验证。您可以在以下代码中看到 <authentication> 元素的默认设置：

```
<authentication mode="Windows" />
```

当您在 ASP.NET 应用程序中实现 Windows 身份验证时，应用程序使用 IIS 执行的身份验证。如果未经身份验证的用户请求 ASP.NET 应用程序的 Web 页面，则 IIS 会显示对话框以获取用户的凭据。用户提供 Windows 凭据后，IIS 会将凭据与现有 Windows 用户帐户进行验证。如果 IIS 找到匹配项，则用户通过身份验证；否则，拒绝访问 Web 页面。如果 IIS 对用户进行身份验证，则已验证用户的身份将传递给 ASP.NET 应用程序。

在 ASP.NET 中，Windows 身份验证提供程序负责在应用程序中实现 Windows 身份验证。Windows 身份验证提供程序是存在于 System.Web.Security 命名空间中的 WindowsAuthenticationModule 类的实例。WindowsAuthenticationModule 对象引用 ASP.NET 应用程序中已验证的 Windows 用户的身份。当您在 ASP.NET 应用程序中启用 Windows 身份验证时，WindowsAuthenticationModule 对象会创建一个 WindowsIdentity 对象来表示已验证的用户，并将其分配给 HttpContext 对象的 User 属性。

> 注意
> 如果您在 IIS 中选择了匿名身份验证并在 ASP.NET 应用程序中启用了 Windows 身份验证，则应用程序将从 WindowsIdentity 类的 GetAnonymous() 方法的返回值中获取用户的身份。

要在 ASP.NET 中使用 Windows 身份验证，您需要在 IIS 中首先适当地设置身份验证模式。您可以在 IIS 中启用以下任何身份验证模式以在 ASP.NET 应用程序中使用 Windows 身份验证：

- 匿名身份验证
- Windows 身份验证（集成）
- 基本身份验证
- 摘要身份验证

您已经了解到匿名身份验证是 IIS 的默认身份验证模式。现在，让我们学习 IIS 中的 Windows、基本和摘要身份验证模式：

- Windows 身份验证（集成） – 在 IIS 中，Windows 身份验证也称为集成 Windows 身份验证，根据用户 Windows 凭据的真实性对用户进行身份验证。IIS 使用客户端上当前登录用户的 Windows 凭据来验证用户。根据客户端的操作系统和 Web 浏览器，此第一次身份验证尝试可能成功也可能失败。如果第一次尝试不成功，客户端上的 Web 浏览器会显示对话框提示用户输入凭据。对话框中提供的凭据将发送到 Web 服务器进行身份验证。用户最多可以提供三次凭据发送到 Web 服务器。如果用户在第三次尝试时仍无法提供有效凭据，则 Web 浏览器中会出现错误。图 36.10 显示了集成 Windows 身份验证的过程：
