## ProxyWebPartManager 控件

如你所知，Web Parts 应用程序（使用 Web Parts 控件的应用程序）可以为每个 Web 页面包含一个 WebPartManager 控件，用于管理该页面上的所有 Web Parts 控件。你也知道，如果 Web Parts 应用程序包含一个母版页并且 WebPartManager 控件放置在母版页中，那么所有内容页（继承自母版页的 Web 页面）都使用母版页的 WebPartManager 控件来管理它们的 Web Parts 控件。为此，每个内容页声明一个静态链接以连接到母版页的 WebPartManager 控件。要在内容页中声明静态链接，你需要在 ASP.NET 应用程序中添加 ProxyWebPartManager 控件和 `<asp:WebPartConnection>` 元素。

`<asp:WebPartConnection>` 元素派生自 `<staticconnections>` 元素，而后者进一步派生自 `<asp:WebPartManager>` 元素。这样，ProxyWebPartManager 控件在内容页中表现类似于母版页的 WebPartManager 控件。然而，请记住，因为 WebPartManager 控件已在母版页中声明一次，你不能在内容页中声明额外的 WebPartManager 控件。如果你确实想声明更多 WebPartManager 控件，你必须使用 ProxyWebPartManager 控件。这就是 ProxyWebPartManager 控件如何模仿位于母版页中的 WebPartManager 控件。

尽管 ProxyWebPartManager 控件用于替换 WebPartManager 控件以声明静态连接，但 ProxyWebPartManager 类并非派生自 WebPartManager 类。相反，它派生自 Control 类。

> **注意：**  
> 静态连接是始终对所有用户可用的连接。

ProxyWebPartManager 控件是 ProxyWebPartManager 类的对象。你也可以使用属于 System.Web.dll 程序集的 ProxyWebPartManager 类来创建 ProxyWebPartManager 控件。ProxyWebPartManager 类的命名空间层次结构如下：

```
System.Object
    System.Web.UI.Control
        System.Web.UI.WebControls.WebParts.ProxyWebPartManager
```

ProxyWebPartManager 类从 Control 类继承了各种属性，例如 EnableTheming 和 Visible。此类通过重写它们来使用这些属性。除了各种继承的属性之外，ProxyWebPartManager 类还包含一个非继承属性，称为 StaticConnections。StaticConnections 属性获取在内容页上的 <asp:ProxyWebPartManager> 元素内声明的静态连接的集合。与属性类似，ProxyWebPartManager 类还从 Control 类继承了各种事件和方法。

使用 ProxyWebPartManager 类声明 ProxyWebPartManager 控件的语法如下所示：

```
ProxyWebPartManager <object name>;
```

ProxyWebPartManager 类的声明如下：

```
public class ProxyWebPartManager : Control
```

## WebPartZone 控件

从技术上讲，WebPartZone 控件用于在 Web 页面上创建区域，在该区域中 Web Parts 或服务器控件可以根据用户指定的要求进行重新定位、最大化或最小化。

WebPartZone 控件是 WebPartZone 类的对象，允许你在 Web 页面上创建区域。区域创建后，你可以在区域中放置任何服务器控件。

WebPartZone 控件用于设计 Web Parts 应用程序的用户界面（UI）。这些控件使你能够在 Web 页面上托管基于 ASP.NET 的服务器端控件。在运行时，这些服务器端控件作为 Web Parts 控件运行。
