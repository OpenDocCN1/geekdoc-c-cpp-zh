
```
number1 = 127;
number2 = 127;

try
{
    result = unchecked((byte)(number1 * number2));
    Console.WriteLine("Unchecked result: " + result);

    result = checked((byte)(number1 * number2));
    Console.WriteLine("Checked result: " + result);
}
catch (OverflowException exc)
{
    Console.WriteLine(exc);
}
finally
{
    Console.Write("\nPress ENTER to quit...");
    Console.ReadLine();
}
}
```

In Listing 3.16, you can see that we have taken two byte type variables number1 and number2 and assign the value 127 to both of them. In the try block, the result of multiplication of both the variables is stored in another byte type variable, result. As the multiplication of values stored in number1 and number2 variables exceeds the limit of the value that can be stored in the result variable; therefore, an exception occurs. In this case, the checked statement causes the overflow exception and displays the exception message; however, the unchecked statement does not cause any exception and displays the result.

## Exploring Namespaces

The concept of namespaces is not new to C#, as it has been extensively used in C++ and Java. A namespace is a wrapper that is wrapped around one or more structural elements to make them unique and differentiated from other elements. An example of a namespace is shown in the following code snippet:

```
namespace XYZcorporation
{
    public class Corp1 { }
    enum CorpEnum { }
}
```

In the preceding code snippet, XYZCorporation is a namespace containing a class, Corp1, and an enumeration, CorpEnum. If the company buys a third party software from another software vendor, which implements the same class name in their program, the namespace allows the developer to refer the existing class of the code. This can be done by using the complete naming conventions, such as namespace.classname.

All the code that you write remains within an implied namespace that exists for the current context of your code. Another thing worth mentioning about namespaces is that they replace the C++ #include notation with the using keyword (similar to the import statement in Java). This implies that with the use of the using keyword, you can tell the compiler which namespaces and libraries of the code you want to use in the system. The most common use of the using keyword is to include the System namespace in your program, so that you can use most of the common functionalities of the System namespace. To use the System namespace, you can write the following code snippet:

```
using System;
// Call the console class in the System namespace
Console.WriteLine("Hello world");
```

Alternatively, you can write the following code snippet:

```
System.Console.WriteLine("Hello world");
```

The statements shown in both the preceding code snippets are equivalent and can be used to call the WriteLine method of the Console class. Generally, you need to add a namespace every time you want to use its containing classes in the program. However, if the namespace is specified with the using keyword at the top of the code, you do not need to specify it at every instance in the code.

In case of nested namespaces or namespaces that have some common method, you can create aliases for the namespaces. Suppose that your corporation insists on having three levels of namespaces — Corporation, Dept, and Project—wrapped around each class you create. The following code snippet shows the levels at which these namespaces are used:

```
namespace Corporation {
    namespace Dept {
        namespace Project
        {
            class InternalClass { }
        }
    }
}
```

In the preceding code snippet, you can see that we have also created the InternalClass class. You need to use the syntax shown in the following code snippet to refer the InternalClass class in your program:

```
Corporation.Dept.Project.InternalClass
```

Typing the preceding code snippet at all places where you are using the InternalClass class is complex and time-consuming as well. C# provides an alternative option that allows you to specify the alias name for the Corporation.Dept.Project namespace, as shown in the following code snippet:

```
using DCN=Corporation.Dept.Project;
```

Now, after specifying the alias, you can access the members of a specified namespaces for which alias is created in your program by using the following code snippet:

```
DCN.InternalClass
```

In the preceding code snippet, DCN is an alias name for the Corporation.Dept.Project namespace. The following code snippet shows how to use the alias name, DCN, in place of the Corporation.Dept.Project namespace in the program:

```
using System;
using DCN = Corporation.Dept.Project;
namespace Corporation
{
    namespace Dept
    {
        namespace Project
        {
            class InternalClass
            {
                public static void Display()
                {
                    Console.WriteLine("Hello world");
                }
            }
        }
    }
}
public class MainClass
{
    public static void Main()
    {
        DCN.InternalClass.Display();
    }
}
```

The technique of defining the alias name in the preceding code snippet reduces the complexity of code and also minimizes the time spent in typing the full namespace.

The following are some of the common namespaces provided by the .NET Framework class library:

- System—Includes essential classes and base classes that define commonly-used data types, events, event handlers, interfaces, attributes, and exceptions.
- System.Collections—Includes interfaces and classes that define various collections of objects, including lists, queues, arrays, hash tables, and dictionaries.
- System.Data—Includes classes that make up ADO.NET, which allows you to build data-handling components that manage data from multiple distributed data sources.
