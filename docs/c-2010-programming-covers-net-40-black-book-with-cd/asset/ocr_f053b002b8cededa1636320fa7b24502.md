# Web Services Discovery

The Web service discovery provides the capability to locate Web services. This component locates documents that describe a particular Web service, through WSDL. If you want to use a Web service in your website, you first need to know where the Web service is located. On the other hand, if you want other people to use your Web service, they also need to know where your Web service is located. In such a case, there must be a searching (discovery) mechanism, which can locate the required Web service. The following two methods are used to search the Uniform Resource Locator (URL) of a Web service:

+   - The Web services discovery tool (Disco.exe) – Used for publishing and discovering Web services. This tool discovers URLs of all the Web services located on a Web server and creates a list of them in a file called the DISCO file (a file with the .disco extension). An organization can publish its own DISCO files on its Web server. This file can be accessed by clients to know about the kind of Web services an organization provides.
+   - UDDI – Centralized directory where Web services offered by different organizations are published. It is a platform-independent method that is built into the .NET platform. A UDDI directory has an advantage over a DISCO file in that the directory provides a single location where clients can search the Web services offered by different organizations.

The following are some of the important features of UDDI:

+   - Acts as a directory and stores information about Web services
+   - Uses the World Wide Web Consortium (W3C) and Internet Engineering Task Force (IETF) Internet standards, such as eXtensible Markup Language (XML), Hypertext Transfer Protocol (HTTP), and Domain Name Server (DNS) protocols
+   - Uses WSDL to describe interfaces to Web services
+   - Communicates through SOAP

Some benefits of using UDDI are:

+   - Helps to search for the right business organization from the millions of business organizations that are currently online
+   - Enables commerce, once the preferred business is discovered
+   - Helps to reach new customers and increase access to current customers
+   - Helps to expand offerings and market reach
+   - Allows rapid participation in the global Internet economy
+   - Describes Web services and business processes programmatically in a single, open, and secure environment

# Web Services Description

The Web service description provides the description of a Web service in the XML format, known as WSDL. A WSDL document defines message formats, such as HTTP-GET and HTTP-POST, to facilitate communication between a Web service and a client. A message pattern determines how the messages can be exchanged between a client and a service. A Web service defines and supports some message patterns, such as request/reply, one-way, or duplex. The behavior of a Web service depends on these message patterns, which theoretically state the requirements of a Web service user when a message is submitted to it. Now, Let’s discuss WSDL in more detail. WSDL is an XML-based language that defines Web services. Every Web service consists of a corresponding WSDL document that specifies the location of the Web service and lists all the services that the Web service can perform.
