# The ASP.NET Life Cycle

The ASP.NET life cycle shows you how ASP.NET processes Web pages to produce dynamic output. It also shows you how the application and individual pages are instantiated and processed, and how ASP.NET compiles the pages dynamically. We look at these aspects in detail in the following heads:

# ASP.NET Application Life Cycle on IIS 7.5

In this section, we take a look at the complete application life cycle of ASP.NET applications running on integrated mode of IIS 7.5. IIS 7.5 also supports Classic mode, which works similar to any ASP.NET application running in IIS 6.0.

In an integrated mode of IIS 7.5, the application resource request process is similar to IIS 6.0. However, in IIS 7.5, three new events such as MapRequestHandler, LogRequest, and PostLogRequest were raised during request process in addition to events in IIS 6.0. Additionally, IIS 7.5 uses a unified request-processing pipeline for the entire application resource request that was not there in IIS 6.0.

> NOTE
> IIS 6.0 uses two separate pipelines for processing an application resource request. One pipeline is for unmanaged code filters and extensions; other is for managed code components.

The following are the benefits of using the integrated pipeline in IIS 7.5:

+   - Raises all the events of the HttpApplication class, to enable ASP.NET modules in IIS 7.5.
+   - Enables configuration of both managed code and unmanaged code modules. In addition, using the integrated pipeline, we can enable or disable the managed code modules for all requests, even if the user requests for an ASP.NET Web page.
+   - Enables the Web site in calling of the managed code modules at any stage in the pipeline, such as prior to the processing of a user request, or after the request is processed, or in the middle of processing a user request.
+   - Enables the Web site in registering and then either enabling or disabling modules by using the Web.config file.
