## 可远程和不可远程对象

.NET 远程处理架构将对象分为两类——不可远程和可远程。只有当对象的实例可以跨越 .NET 远程处理边界，或者可以被其他对象跨越 .NET 远程处理边界访问时，对象才属于可远程类别。如果对象不满足这两个条件中的任何一个，则该对象属于不可远程对象类别。换句话说，不可远程对象是那些无法在其自己的应用程序域之外访问的对象。不可远程对象设计用于在其创建的同一 AppDomain 内使用，并且始终从该 AppDomain 直接访问。此外，不可远程对象不能被复制或在另一个 AppDomain 中表示。

与不可远程对象不同，可远程对象可通过代理在自己的 AppDomain 之外访问。.NET 远程处理架构将可远程对象大致分为两类——按值封送（MBV）和按引用封送（MBR）。让我们在以下章节中讨论这两类。

## 按值封送

封送是将方法调用在对象之间以及跨应用程序边界打包和发送的过程，使用序列化和反序列化机制。MBV 对象通过实现 ISerializable 接口或被标记为 SerializableAttribute 属性来声明其可序列化性，这反过来会自动序列化对象。ISerializable 接口属于 System.Runtime.Serialization 命名空间。它提供 GetObjectData() 方法，用要序列化在远程对象中的数据填充 SerializationInfo 对象。MBV 对象被复制并从服务器的 AppDomain 传递到客户端的 AppDomain。

## 按引用封送

MBR 对象在客户端使用代理访问。客户端只需持有对象的引用。当客户端在其自己的应用程序域中创建 MBR 对象的实例时，.NET 远程处理框架会创建一个代理来表示 MBR 对象并将该代理的引用发送给客户端。客户端然后在代理上进行调用。.NET 远程处理将这些调用封送到远程对象的应用程序域并调用该调用。要定义 MBR 对象，您需要使用 System.MarshalByRefObject 类。

> NOTE
> 如果客户端和 MBR 对象在同一应用程序域中，.NET 远程处理框架会向客户端返回 MBR 对象的直接引用，而不进行封送。

MarshalByRefObject 类使对象能够在支持远程处理的应用程序中跨应用程序域边界访问。MarshalByRefObject 类的类层次结构如下所示：

在实例化可远程对象之前，您需要通过一个称为激活的过程创建并初始化它。MBR 支持两种类型的激活，服务器激活和客户端激活。

> NOTE
> MBV 对象不需要任何激活过程，因为它们使用序列化过程复制并使用反序列化激活。

两种 MBR 激活类型的描述如下：

- 服务器激活 – 激活存在于服务器上的远程对象。这些远程对象也称为服务器激活对象（SAO）。您不能使用 new 关键字创建 SAO 对象。SAO 对象在客户端在代理对象上调用方法时被激活。SAO 对象使用以下两种模式激活：
  - Singleton – 使用单个对象为所有客户端提供服务。Singleton 对象的实例在第一个客户端尝试访问它时创建。此后，后续客户端调用被引导到同一个 Singleton 对象。Singleton 对象在请求或方法调用之间维护会话状态。
  - SingleCall – 创建一个对象来为单个客户端请求提供服务。当您将对象配置为 SingleCall 时，.NET Framework 为客户端的每次方法调用激活该对象的新实例，之后它将被垃圾回收以进行回收。SingleCall 模式一次只处理一个请求，并且不维护请求之间的会话状态；因此，它被称为无状态。

- 客户端激活 – 激活存在于客户端上的远程对象。这些远程对象也称为客户端激活对象（CAO）。为了处理 CAO 对象，.NET Framework 为每个 CAO 对象的实例分配一个统一资源标识符（URI）。CAO 对象根据客户端请求在服务器上创建。它们为正在服务的每个客户端维护一个状态，但它们不能共享一个公共状态。

> NOTE
> 在应用程序域之外发布在统一资源定位符（URL）上的 SAO 对象称为众所周知对象。
