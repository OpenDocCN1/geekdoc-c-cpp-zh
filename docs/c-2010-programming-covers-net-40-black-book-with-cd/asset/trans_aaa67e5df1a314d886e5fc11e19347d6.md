
Setup.exe 可以在其 Debug 文件夹中找到。你需要将 .msi 文件从构建位置复制到可分发媒体（如软盘和 CD）上以部署应用程序。类似地，要将应用程序部署到网络位置，你需要将 .msi 文件复制到服务器计算机，网络用户可以从该服务器下载它。

## Web 安装项目

在传统的媒体分发系统中，你通过将应用程序的可执行文件复制到媒体设备（例如 CD）然后再复制到 Web 服务器来部署应用程序。然而，Visual Studio 2010 支持直接将应用程序部署到 Web 服务器，因为它包含了用于此目的的部署工具。将 Web 应用程序直接部署到 Web 服务器有其自身优势，因为它自动处理注册和配置引发的问题。此外，Web 应用程序部署到 Web 服务器后，用户可以直接从 Web 服务器下载并运行它。

你可以通过首先创建和构建一个 Web 安装项目并将其复制到 Web 服务器来将 Web 应用程序部署到 Web 服务器。然后，你需要运行安装程序，以使用 Web 安装项目的指定设置将应用程序安装到 Web 服务器上。安装项目与 Web 安装项目之间的主要区别在于：Web 安装项目将应用程序部署到 Web 服务器上的虚拟目录，而安装项目将应用程序部署到目标计算机上的文件夹中。

## Cab 文件项目

Cab 文件项目用于创建 cabinet 文件（.cab），这些文件可以将组件（如 ActiveX 控件）下载到 Web 浏览器。Cab 文件项目通过解决方案资源管理器添加文件和项目输出，并在属性窗口或项目属性页中设置属性。

Cab 文件的属性允许你指定压缩级别、实现身份验证、设置显示名称和版本信息，并指定依赖文件在 Web 上的位置。当你希望在客户端计算机而不是服务器上运行代码时，可以使用 Cab 文件项目。

## ClickOnce 部署技术

ClickOnce 是一种部署技术，允许你将基于 Windows 的应用程序发布到 Web 服务器或网络文件共享位置。Visual Studio 2010 为 ClickOnce 部署技术发布和更新应用程序提供完全支持。ClickOnce 部署技术允许你部署自更新的基于 Windows 的应用程序。它还支持部署 WPF XAML 浏览器应用程序（XBAP）。XBAP 是一种 Windows 技术，用于创建类似于 WPF 应用程序的富 Internet 应用程序。请注意，WPF 是一种不支持 Web 浏览器的 Windows 应用程序；而 XBAP 应用程序可以轻松地托管在 Web 浏览器中。

在 Visual Studio 2010 中，ClickOnce 部署技术增强了以下功能：

- **支持 .NET Framework 4.0 版本** — 通过使用 Visual Studio 2010 创建可面向 .NET Framework 4.0 及其新功能的应用程序。
- **支持多个版本的 .NET Framework** — 创建与多个版本的 .NET Framework 兼容的应用程序。例如，你可以将应用程序的目标框架指定为 .NET Framework 3.5 或 .NET Framework 4。
- **增强的日志记录功能** — 存储日志信息，包括传递给 ClickOnce 运行时的各种参数、浏览器设置和 ClickOnce 安全选项。
- **自定义安装程序和用户界面** — 允许你为安装和更新 .exe 应用程序创建自定义图形用户界面。此外，自定义安装程序可以具有用于安全和维护操作的自定义对话框。

要使用 ClickOnce 部署技术部署基于 Windows 的应用程序，你需要通过向最终用户提供应用程序来发布该应用程序。要发布应用程序，你需要使用发布向导或项目属性对话框中的“发布”页面来设置应用程序的发布属性。发布向导允许你指定要发布应用程序的位置，例如 Web 服务器、网络或文件共享，或可移动媒体。

ClickOnce 部署技术允许你通过选择以下选项之一来部署应用程序：

- **从 Web 或网络共享安装** — 将应用程序部署到 Web 或共享网络上。对于面向高速 Internet 连接或局域网（LAN）用户的应用程序，你应使用此设置。最终用户只需单击 Web 页面上的图标或双击文件共享上的图标即可安装应用程序。使用此设置部署的应用程序会自动添加到“开始”菜单和“添加/删除程序”菜单中。

- **从 CD 或 DVD 安装** — 将应用程序部署到可移动磁盘（如 CD 或 DVD）上。此设置最适合网络连接不稳定或带宽较低的用户使用的应用程序。请注意，在这种情况下，你不需要任何网络连接即可执行应用程序，但需要连接才能更新应用程序。

- **从 Web 或网络共享启动** — 将 Windows 应用程序部署为 Web 应用程序。它适用于那些不经常使用、因此不需要永久安装在最终用户计算机上的应用程序。在这种情况下，当你单击 Web 页面或文件共享上的应用程序图标时，应用程序将开始执行。由于应用程序未安装在最终用户计算机上，你无法在“开始”菜单或“添加/删除程序”菜单中查看它。

接下来，让我们了解 ClickOnce 应用程序缓存。

## 应用程序缓存

当 ClickOnce 应用程序在本地安装或在线托管时，它会存储在客户端计算机的 ClickOnce 应用程序缓存中。ClickOnce 应用程序缓存是一组隐藏目录，位于当前用户的 Documents and Settings 文件夹下的 Local Settings 目录中。应用程序缓存包含所有应用程序文件、程序集、配置文件、应用程序和用户设置以及数据目录。如果应用程序是早期版本创建的，应用程序缓存负责将应用程序的数据目录迁移到最新版本。如果 ClickOnce 应用程序在线托管，ClickOnce 应用程序缓存的大小将限制为指定数量；而安装的应用程序则不受缓存大小限制的约束。缓存存储配额负责确定应用程序缓存的大小。

现在，让我们了解 ClickOnce 部署中的安全性。

## 安全性

当你打算在众多用户之间分发应用程序时，安全性是一个主要关注点。ClickOnce 部署以一组有限的权限部署应用程序，这些权限默认基于应用程序原始版本的部署位置。但是，当应用程序更新时，权限也会相应地更新。

ClickOnce 部署技术是智能客户端应用程序的可靠部署技术。这意味着部署的应用程序不会以任何方式损害客户端计算机。ClickOnce 安全性在安装和运行时为客户端计算机提供保护。使用 ClickOnce 可以向用户确保应用程序的安全性。

此外，ClickOnce 应用程序在运行时基于应用程序的标识受到保护。这使低特权用户无需管理员干预即可部署应用程序。但是，这并不意味着你的应用程序在用户角度上没有受到保护。使用 .NET 基于角色的安全性，如果不允许用户使用应用程序中的某些功能，你可以阻止他们使用这些功能。

ClickOnce 安全性在应用程序部署到客户端计算机后立即提供。所有文件都分别放置在应用程序缓存下的不同目录中。或者，要为应用程序提供运行时保护，ClickOnce 依赖于 .NET Framework 的代码访问安全性（CAS）基础结构。CAS 通过使用 Windows 访问控制和 .NET 基于角色的安全性提供安全机制。
