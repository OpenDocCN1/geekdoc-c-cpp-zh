After creating the Command object, create a DataReader by calling the Command.ExecuteReader to retrieve the rows from a data source. You should use the Read() method of the DataReader object to obtain a row from the results of the query. The DataReader is a good choice when you are retrieving large amounts of data because data does not store in the cache memory. Call the Close() method every time you finish using the DataReader object. This is necessary, because if your Command contains return values, they will not be available until you close the DataReader object.

The question which might arise in your mind is that if both DataReader and DataSet are used to retrieve data, then what is the difference between the two? The answer lies in the functionality of the two. When you decide whether your application should use a DataReader or DataSet, you should consider the type of functionality that your application requires. You can use the DataSet in the following circumstances:

+   - Using DataSet for manipulating the data.
+   - Using DataSet for remoting the data between tiers.
+   - Using DataSet for interacting the data dynamically. By interaction it implies binding data to a Window Form or combining data from multiple sources.
+   - Using DataSet to perform extensive processing without requiring an open connection to the data source.
+   - Using DataReader for returning your data in a forward only and read only manner.

# ADO.NET Entity Framework

The Entity Framework of ADO.NET allows you to focus on data through an object model instead of a relational model. The Entity Framework allows you to write less data access code, reduce maintenance, make the structure of data user friendly, and facilitate the persistence of data. You can use the Entity Framework in your application with directly using a new data provider called EntityClient and a new language called Entity SQL. The EntityClient uses the EntityConnection and EntityCommand objects to return a DbDataReader.
