# Windows Authentication

Consider a situation where your ASP.NET application is on the Intranet or local computer and you want to control the access to your application by different users on the network or computer. Therefore, granting anonymous access to the application may not be a feasible solution. In such a case, you can use Windows authentication to regulate access to your ASP.NET application. With Windows authentication, the identity of a user is checked against the Windows user accounts that are stored on the Web server. If the credentials of a user match with that of a Windows user account, then the user is authenticated. You can use Windows authentication in IIS as well as in the ASP.NET application. By default, all ASP.NET applications use Windows authentication. You can see the default setting of the <authentication> element in the following code:

```
<authentication mode="Windows" />
```

When you implement Windows authentication in an ASP.NET application, the application uses the authentication performed by IIS. If an unauthenticated user requests for a Web page of the ASP.NET application, then the IIS displays a dialog box to obtain the credentials of the user. After the user provides the Windows credentials, IIS validates the credentials against the existing Windows user accounts. If IIS finds a match, then the user is authenticated; otherwise, access to the Web page is denied. In case, IIS authenticates the user, identity of the authenticated user is passed on to the ASP.NET application.

In ASP.NET, the Windows authentication provider is responsible for implementing Windows authentication in the applications. The Windows authentication provider is an instance of the WindowsAuthenticationModule class that exists in the System.Web.Security namespace. A WindowsAuthenticationModule object refers to the identity of the authenticated Windows user in an ASP.NET application. When you enable Windows authentication in the ASP.NET application, the WindowsAuthenticationModule object creates a WindowsIdentity object to represent the authenticated user and assigns it to the User property of the HttpContext object.

> NOTE
> If you have selected anonymous authentication in IIS and enabled Windows authentication in the ASP.NET application, then the application obtains the identity of the user from the return value of the GetAnonymous() method of the WindowsIdentity class.

To use Windows authentication in ASP.NET, you need to first appropriately set the authentication mode at IIS. You can enable any of the following authentication modes in IIS to use Windows authentication in ASP.NET applications:

+   - Anonymous authentication
+   - Windows authentication (Integrated)
+   - Basic authentication
+   - Digest authentication

You have already learned that anonymous authentication is the default authentication mode of IIS. Now, let’s learn about the Windows, Basic, and Digest authentication modes in IIS:

+   - Windows Authentication (Integrated) – In IIS, Windows authentication, also known as integrated Windows authentication, authenticates users based on the authenticity of their Windows credentials. IIS uses the Windows credentials of the currently logged-in user on the client to authenticate the user. Depending on the operating system and Web browser on the client, this first attempt of authentication may succeed or fail. In case the first attempt is unsuccessful, the Web browser on the client displays a dialog box prompting for the credentials of the user. The credentials provided in the dialog box are sent to the Web server for authentication. The user can provide the credentials up to three times to be sent to the Web server.
