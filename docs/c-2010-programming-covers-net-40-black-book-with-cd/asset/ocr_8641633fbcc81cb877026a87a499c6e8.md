In Figure 9.32, the Window element contains the Grid element, which in turn contains three Button elements named button1, button2, and button3. The button3 element itself contains a Label element named label1. This way as and when you add more controls or elements in the WPF application, this element tree grows.

You may also notice in Listing 9.4 that the Window, Button, and Label elements have several attributes. For instance, the Window element has the xmlns, Title, Height, and Width attributes and the Button and Label elements have the Name and Margin attributes. Note that the Window, Grid, Button, and Label XAML elements correspond to the instances of the Window, Grid, Button, and Label classes, respectively. However, the attributes of the XAML elements correspond to the properties of the respective classes. This implies that whenever you add an XAML element in a WPF application, an instance of the respective class is automatically created and the specified properties are set.

# Namespaces and XAML

Similar to XML, XAML requires certain predefined namespaces to allow you to use the elements and attributes. These namespaces convey about the location of the classes and the structural rules or schemas of the WPF applications to the XAML parser. When you create WPF applications, references to the necessary namespaces are automatically added in the Window element (in standalone WPF applications) and the Page element (in XBAPs). The Application element also contains references to the necessary namespaces.

By default, there are two namespaces that are included in WPF applications. The namespaces are added by using the xmlns declarations, which are provided through the xmlns attribute of the Window or Page element.
