### In Depth

Microsoft ActiveX Data Objects .NET (ADO.NET), a part of Microsoft .NET Framework, allows your application to easily communicate with file-based and server-based data sources. ADO.NET libraries appear under the System.Data namespace in the .NET Framework. The most important use of ADO.NET is to communicate with the data and provide data access services to the .NET Framework. It provides access to various kinds of data, such as XML, relational, and application data. In addition to data access, it supports creation of front-end database clients and middle-tier business objects.

ADO.NET provides consistent access to data sources, such as SQL, XML, and data sources accessed through Object Linking and Embedding Database (OLE DB), and Open Database Connectivity (ODBC). It also separates data access from data manipulation and includes separate data providers for connecting to a database, executing commands, and retrieving results.

In this chapter, you learn about data access with ADO.NET. You also get acquainted with database and its various components. In addition, you learn about the basic SQL statements. You also learn about the ADO.NET architecture and its various components. Finally, you learn about the ADO.NET Entity Framework.

### Understanding Databases

Database in simple terms means a collection of structured information. It stores information in an organized and structured manner to facilitate the retrieval as and when required. Databases have become more complex over the years; however, the fundamental concept is still a simple one. For example, suppose you are a teacher, who requires to allot the grades for each student. You might make a table on a paper and enter the grades of the students in that table and name it the students table. In this example, you have already created a database—or more specifically, a database table on paper. Now, you can make the similar table on the computer that allows you to sort, index, update, and organize any size of tables in an easy way.

A collection of records, that is, rows of records, where each column is a field, becomes a table. In its most common form, a database is merely a collection of one or more tables. However, there is another type of database as well—relational database. It is called so because the relational databases are set up such that the data in multiple tables can be related to one another. To make a table relational, you select certain fields to be primary keys and foreign keys.

The primary key in a table is usually the most important one—you can differentiate between records containing duplicate values on the basis of primary key, as the primary key does not contain duplicate values. The foreign key usually represents the primary key in another table, which gives you access to that table in an organized way. For example, you might add a field called StudentID to the students table. The same field, StudentID, may be the primary key in the school registrar’s database table that lists all students. In our table, the StudentID field is then a foreign key, allowing us to specify individual records in the registrar’s table.

You can work with the data present in a database by using Structured Query Language (SQL), which has been elaborately defined later in this chapter. You use SQL to set up a query, which, when applied to a database, typically returns a DataSet of records that matches your SQL query. For example, you may set up a query to get information about all the students who got B grade or better. You can do several things, such as inserting new records, creating new tables, and getting DataSets by using SQL.

Therefore, you can use SQL to filter out the records you do not want and then work on them. Visual C# has a built-in tool (the Query Builder) that allows you to create SQL statements visually.

### Understanding SQL

SQL is a standard interactive and programming language for querying and modifying data and managing databases. It is designed to retrieve and manage data in a Relational Database Management System (RDBMS), create and modify a database schema, and manage a database object control.

We learn to work with a database that contains a table named Customers holding the customer IDs, addresses, and other fields, and a table named Orders holding the fields for the customer orders. These tables are based on the Northwind database.

Let’s learn the basics of SQL in the next section.

### The SELECT Statement

You can use the SELECT statement to get fields from a table. The following is an example to retrieve all the records in the Customers table, by using the wildcard character `*`:

```
SELECT * FROM Customers
```

The preceding example returns a DataSet that holds all the records in the Customers table. You can also use the SELECT statement to select specific fields from a table, as shown in the following example:

```
SELECT CustomerID, Address, City FROM Customers
```

In the preceding example, you can retrieve the CustomerID, Address, and City fields from the Customers table. The preceding example returns a DataSet that holds all the records in the Customers table, and each record has a CustomerID, Address, and City field.

### The WHERE Clause

In SQL, you can use the WHERE clause to specify a criterion that you want all the records to meet. For example, to select all the records in the Customers table, where the City field holds London, you can execute the following statement:

```
SELECT * FROM Customers WHERE City = 'London'
```

The other operators that can be used in the WHERE clauses are as follows:

- `<` (less than)
- `<=` (less than or equal to)
- `>` (greater than)
- `>=` (greater than or equal to)
- `BETWEEN`
- `IN`
- `LIKE`

### The LIKE Clause

In SQL, the LIKE clause allows you to use the partial string that you can specify with wildcards. You can select all the records from the Customers table, where the City field matches the wildcard string `Lo%`. This is shown in the following SQL query statement:

```
SELECT * FROM Customers WHERE City LIKE 'Lo%'
```

The preceding example creates a DataSet which contains only those records whose City field contains names starting with Lo, such as Los Angeles or London. The three possible combinations for using the `%` wildcard character are as follows:

- `Lo%` — Returns all the items starting with Lo, such as London or Los Angeles.
- `%Lo` — Returns all the items ending with Lo, such as São Paulo.
- `%Lo%` — Returns all the items containing Lo anywhere in the field value, such as Barcelona.

### The DISTINCT Clause

Sometimes a database may hold duplicate values in the fields of a table. For example, several customers come from the same cities, so they would have the same value in the City field. You might want to take a look at all the cities represented, without repetition. You can use the DISTINCT clause to avoid repetition, as shown in the following SQL query statement:

```
SELECT DISTINCT City FROM Customers
```

### The Logical Operators

The logical operators are used in a situation when you need to retrieve the records from the database on the basis of some logical conditions. Let’s take an example in which you want to retrieve only those records whose city should neither be Boston or York, and the Fax field should have some value (we use the IS NOT NULL keyword to check if the Fax field contains any value). Following statement can be used to retrieve the required records:

```
SELECT * FROM Customers WHERE City NOT IN ('Boston', 'York') AND Fax IS NOT NULL
```

You can use these logical operators to connect the clauses AND, OR, and NOT. Using AND means that both clauses must be True, using OR means either one can be True, and using NOT flips the value of a clause from True to False or from False to True.

### The ORDER BY Clause

You can order the records in the DataSet by using an SQL statement. You can order the records of the Customers table by CustomerID, as shown in the following example:

```
SELECT * FROM Customers ORDER BY CustomerID
```

You can also sort the records in descending order using the Desc keyword:

```
SELECT * FROM Customers ORDER BY CustomerID Desc
```

> NOTE
> If you are not providing the Desc keyword with the ORDER BY clause, it will, by default, return results in ascending order.

### The GROUP BY Clause

The GROUP BY clause of SQL is used to group some records according to the fields of the table. You can group records in SQL with the GROUP BY clause as shown in the following SQL query statement:

```
SELECT OrderID, SUM(Quantity) FROM OrderDetails GROUP BY OrderID
```

In the preceding example, we are grouping them by OrderID.

### The DELETE Statement

The DELETE statement in SQL is used to delete the records from a table. You can use the WHERE clause with the DELETE statement to delete the records on the basis of some conditions as shown in the following SQL query statement:

```
DELETE FROM Customers WHERE City NOT IN ('Boston', 'York')
```

In the preceding example, we are deleting the records from the Customers table whose City field does not contain the value Boston or York.

### The UPDATE Statement

You can use the UPDATE statement to update a database. Although Visual C# automatically updates databases, it is worth noting that you can also use SQL to update databases. This is shown in the following SQL query statement:

```
UPDATE Customers SET City = 'Boston' WHERE City = 'York'
```

In the preceding example, we are changing the City to Boston in all records where it is York at present.

### Joining Tables

You can join two or more tables in a database with SQL. For example, you can work with relational databases. Now, you want to create a new DataSet with customer contact names from the Customers table and the IDs of the items they have ordered from the Orders table. The field that relates these two tables is CustomerID, so you can set up the SQL query as shown in the following code snippet:

```
SELECT Customers.ContactName, Orders.OrderID FROM Customers, Orders WHERE Customers.CustomerID = Orders.CustomerID
```

The preceding code snippet ensures that the CustomerID field matches in each record you are joining. You can also do inner joins, where records must be in both tables, or outer joins, where records can be in either table.
