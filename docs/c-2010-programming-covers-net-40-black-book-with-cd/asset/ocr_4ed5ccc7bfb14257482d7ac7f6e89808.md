In .NET framework, the MSIL code can be considered as one of the four types of code – valid, invalid, type-safe, and verifiably type-safe code. Table 36.1 lists different types of MSIL code:

# Table 36.1: Types of MSIL Code at Runtime

| MSIL Code | Description |
|---|---|
| Valid | Refers to the MSIL code that follows the .NET syntax and conventions and therefore, can be converted to the native code. Valid MSIL code may use pointer arithmetic that is not type-safe. |
| Invalid | Refers to the MSIL code that cannot be converted to native code. |
| Type-Safe | Refers to the MSIL code in which types access and interact with one another only through their public contracts or methods. |
| Verifiably Type-Safe | Refers to the type-safe MSIL code that has passed the verification process. |

Now, let’s learn about type-safe and verifiably type-safe code in details.

# Type-Safe Code

An MSIL code in which one type accesses the other types in the code only through a well-defined and authorized way is considered as a type-safe code. The well-defined and authorized means of access is by using the public methods and fields. If one or more types access the private fields or methods of another type, the MSIL code is not considered as type-safe. This implies that a type in the type-safe MSIL code cannot access the memory locations of another type unless it has the permission to do so. This memory segregation and type-safety of the MSIL code prevents infringement of types, which in turn ensures that there is no unwanted and malicious manipulation of one type by another. This eventually strengthens the security and reliability of the application.
