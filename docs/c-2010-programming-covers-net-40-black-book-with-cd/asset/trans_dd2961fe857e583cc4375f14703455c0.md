

除了属性系统之外，WPF 还引入了一个增强的事件系统。该事件系统提供了两个新概念，即路由事件和附加事件。

## 路由事件

正如你之前所学，WPF 应用程序包含大量元素。这些元素以树的形式表示，其中有一个根元素（Window 或 Page），其余元素嵌套在根元素内部。嵌套层数没有限制。除根元素外，所有其他元素都可以有多个嵌套元素。这些元素中的大多数都具有某些基本事件，例如鼠标事件和键盘事件。在 WPF 中，这些事件被定义为路由事件。顾名思义，路由事件会在 WPF 应用程序的元素树中路由或遍历。路由事件与传统 CLR 事件不同，因为路由事件允许你在多个元素上引发和处理事件。路由事件起源于一个元素，但可以从源元素沿元素树向上或向下遍历。当路由事件遍历时，它会在根元素和源元素之间的元素上引发，并且可以在这些元素中的每一个上被处理。你也可以选择仅在一个元素上处理该路由事件，并在此元素处停止路由事件的遍历。

路由事件属于 WPF 事件系统，并由 RoutedEvent 类提供支持。表 9.13 列出了 RoutedEvent 类的一些值得注意的属性。

| 表 9.13：RoutedEvent 类的值得注意的属性 |
| 属性 | 描述 |
| Name | 检索路由事件的名称 |
| HandlerType | 检索路由事件的处理程序类型 |
| OwnerType | 检索最初注册路由事件的所有者 |
| RoutingStrategy | 检索路由事件的路由策略 |

由于路由事件是在根元素和源元素之间的路径上的元素处引发的，因此你可以使用路由事件在这些元素之间传递事件信息。路由事件（以及事件信息）遍历的方向取决于路由事件所采用的路由策略。现在，让我们看看可用于 WPF 路由事件的路由策略。

## 路由策略

在 WPF 中，路由事件用于根据其路由策略在元素树中向上或向下导航元素。路由策略是一种在元素树的元素之间引发和遍历事件的方式。这些路由策略借助 RoutingStrategy 枚举的值来指定。这些值如下所示：

- 直接（Direct） – 表示由源元素引发的事件。这些事件的行为与普通 .NET 事件相同，但可以参与特定于路由事件的机制，例如事件触发器。
- 隧道（Tunneling） – 表示首先由根元素引发的事件。然后，由元素树中的每个元素向下传递，直到到达源元素。
- 冒泡（Bubbling） – 表示首先由源元素引发的事件。然后，由元素树中的每个元素向上传递，直到到达根元素。

## 直接事件

直接事件是指那些直接应用于其起源或引发事件的元素上的事件。这些事件类似于在 Windows 窗体应用程序中使用的 CLR 事件。这意味着直接事件只能在源元素上引发和处理，而不能通过元素树中的其他元素进行路由。

## 隧道事件

隧道事件是指那些起源于一个元素，但在根元素或父元素上被引发并可能被处理的事件。换句话说，隧道事件从树中的根元素向下引发到最初引发事件的子元素，即从外部元素到内部元素。隧道事件也称为预览事件，因为事件名称以 Preview 为前缀，如清单 9.6 所示：

## 清单 9.6：演示隧道事件的遍历

```
<Window x:Class="MyWpfApplication.MainWindow"
xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
Title="MainWindow" Height="350" Width="525"
PreviewMouseRightButtonUp="MouseRightHandler">
<Grid Name="grid1" PreviewMouseRightButtonUp="MouseRightHandler">
<Button Name="button1" Height="25" Width="75" Content="button1" Margin="100,10,100,220" PreviewMouseRightButtonUp="MouseRightHandler"/>
<Button Name="button2" Height="150" Width="150" Margin="0" PreviewMouseRightButtonUp="MouseRightHandler">
<Grid Name="grid2" Height="100" Width="100" PreviewMouseRightButtonUp="MouseRightHandler">
<TextBox Name="textBox1" Text="textBox1" Height="25" Margin="0,0,45,60" PreviewMouseRightButtonUp="MouseRightHandler"/>
<TextBox Name="textBox2" Text="textBox2" Height="25" Margin="45,60,0,0" PreviewMouseRightButtonUp="MouseRightHandler"/>
</Grid>
</Button>
<Button Name="button3" Height="25" Content="button3" Margin="100,220,100,10" PreviewMouseRightButtonUp="MouseRightHandler"/>
</Grid>
</Window>
```

在清单 9.6 中，你可以看到 PreviewMouseRightButtonUp 事件在所有元素中都与它的处理程序 MouseRightHandler 关联。PreviewMouseRightButtonUp 事件是一个隧道路由事件，可用于所有从 UIElement 类派生的元素。每当你右键单击任何元素时，PreviewMouseRightButtonUp 事件会发生在根元素上，并向下隧道到源元素。图 9.33 提供了 PreviewMouseRightButtonUp 事件遍历的直观表示：

## 冒泡事件

冒泡事件是指那些起源于一个元素，但在所有父元素（直至根元素）上被引发并可能被处理的事件。换句话说，冒泡事件按照其层次结构顺序从子元素引发到根元素。例如，考虑清单 9.7 中的代码：

## 清单 9.7：演示冒泡事件的遍历

```
<Window x:Class="MyWpfApplication.MainWindow"
xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
Title="MainWindow" Height="350" Width="525"
MouseRightButtonUp="MouseRightHandler">
<Grid Name="grid1" MouseRightButtonUp="MouseRightHandler">
<Button Name="button1" Height="25" Width="75" Content="button1" Margin="100,10,100,220" MouseRightButtonUp="MouseRightHandler"/>
<Button Name="button2" Height="150" Width="150" Margin="0" MouseRightButtonUp="MouseRightHandler">
<Grid Name="grid2" Height="100" Width="100" MouseRightButtonUp="MouseRightHandler">
<TextBox Name="textBox1" Text="textBox1" Height="25" Margin="0,0,45,60" MouseRightButtonUp="MouseRightHandler"/>
<TextBox Name="textBox2" Text="textBox2" Height="25" Margin="45,60,0,0" MouseRightButtonUp="MouseRightHandler"/>
</Grid>
</Button>
<Button Name="button3" Height="25" Content="button3" Margin="100,220,100,10" MouseRightButtonUp="MouseRightHandler"/>
</Grid>
</Window>
```

在清单 9.7 中，你可以看到 MouseRightButtonUp 事件在所有元素中都与它的处理程序 MouseRightHandler 关联。MouseRightButtonUp 事件是一个冒泡路由事件，可用于所有从 UIElement 类派生的元素。每当你右键单击任何元素时，MouseRightButtonUp 事件会在源元素上引发，并遍历到根元素。图 9.34 显示了当 MouseRightButtonUp 事件最初在 textBox1 元素上引发时是如何遍历的：

## 路由事件的处理程序

如你所知，路由事件会遍历元素树。它们从源元素到根元素（或反之）在每个元素的级别上被引发和处理。WPF 提供了全系列的路由事件。你可以轻松方便地在代码隐藏文件中处理这些路由事件。路由事件的事件处理程序的语法如下：

```
public returnType eventHandlerName(object sender, RoutedEventArgs e)
{
    //事件处理逻辑
}
```

在上述语法中：

- public、object、RoutedEventArgs — 表示 C# 关键字。
- returnType — 表示事件处理程序的返回类型。
- eventHandlerName — 表示事件处理程序的名称。建议事件处理程序的名称采用 elementName_eventName 的形式，其中 elementName 是路由事件的所有者，eventName 是事件的名称。
- sender — 表示事件的最新发送者，即最近引发事件的元素。

请注意，RoutedEventArgs 类是提供与所引发路由事件相关信息的基类。例如，引发路由事件的原始源或元素可以通过此类获取。你还可以使用 RoutedEventArgs 类的任何派生类来获取有关路由事件的更具体信息。表 9.14 列出了 RoutedEventArgs 类值得注意的属性：

| 表 9.14：RoutedEventArgs 类的值得注意的属性 |
| 属性 | 描述 |
| Handled | 设置或检索一个值，该值指示路由事件的当前处理状态。如果此属性设置为 true，则事件处理会立即停止。对于成对事件，如果你已将隧道事件的 Handled 属性设置为 true，则冒泡事件不会出现。 |
| OriginalSource | 检索最初引发路由事件的源或元素。原始源是通过命中测试确定的。 |
| Source | 检索引发事件的源。在大多数情况下，OriginalSource 和 Source 指向同一元素；但是，OriginalSource 可能是更具体或嵌套的元素。 |
| RoutedEvent | 设置或检索由事件处理方法处理的路由事件。 |

> 注意
> 你创建的事件处理程序作为参数传递给 RoutedEventHandler 委托。

在代码隐藏文件中添加了路由事件的事件处理程序后，你需要将该处理程序与相应的事件关联。你可以通过使用 XAML 文件中的各种事件属性来做到这一点。你应该注意，属性的名称必须与事件的名称相同。例如，Button 元素的 Click 属性允许你在 XAML 文件中为 Click 事件指定事件处理程序，如以下代码片段所示：

```
<Button Height="25" Width="75" Name="myButton" VerticalAlignment="Center" Click="myButton_Click">Button1</Button>
```

在上述代码片段中，在代码隐藏文件中定义的名称为 myButton_Click() 的方法被指定为 myButton 按钮的 Click 事件的事件处理程序。

或者，你可以在代码隐藏文件中将处理程序与路由事件关联。例如，myButton 按钮的 Click 事件通过使用 += 运算符与 myButton_Click() 方法关联，如以下代码片段所示：

```
myButton.Click += new RoutedEventHandler(myButton_Click);
```
