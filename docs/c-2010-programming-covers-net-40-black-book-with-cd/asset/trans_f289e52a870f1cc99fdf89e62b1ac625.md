## `<location>` Element

你知道如何在 web.config 文件（根级、应用程序级或目录级）中使用 `<authentication>` 和 `<authorization>` 元素来帮助你保护整个 ASP.NET Web 应用程序（们）。现在，考虑一种情况，你只想保护 Web 应用程序中的特定范围的 Web 页面。在这种情况下，而不是使用 `<authentication>` 和 `<authorization>` 元素，你可以使用 `<location>` 元素。`<location>` 元素允许你将某些配置设置应用于特定的 Web 应用程序或页面（或一系列 Web 页面）。你也可以使用 `<location>` 元素来保护特定的 Web 资源，例如虚拟目录或图像。

在 web.config 文件中，`<location>` 元素可以出现在 `<configuration>` 元素内。`<location>` 元素可以包含任何子元素来指定给定 Web 应用程序、页面或资源的设置。`<location>` 元素的语法如下：

```xml
<location allowOverride="true|false" path="Path">
  <!-- child elements -->
</location>
```

在前面的语法中，`<location>` 元素有两个属性：

- **path** – 指你想要保护或应用任何其他配置设置的特定 Web 应用程序、页面或资源。如果省略此属性或将其设置为空字符串，则安全（或配置）设置适用于当前目录及其所有子目录。

- **allowOverride** – 指安全（或配置）设置是否可以在子目录的 web.config 文件中被覆盖。它可以有 `true` 或 `false` 作为其值。如果为 `true`，则设置可以在子目录中被覆盖；如果为 `false`，则设置不能被覆盖。此属性的默认值是 `true`。

## NOTE

你可以在 path 属性中使用 `~/` 来表示当前应用程序根目录。例如，考虑以下代码：

```xml
<location path="~/CustomerLists/Customer.xls">
  <system.web>
    <authorization>
      <deny users="TestUser"/>
    </authorization>
  </system.web>
</location>
```

在前面的代码中，TestUser 用户被拒绝访问位于当前 Web 应用程序根目录的 CustomerList 目录中的 Customer.xls 文件。

## The `<identity>` Element

`<identity>` 元素允许你指定 Web 应用程序的身份。当你想在 Web 应用程序中实现模拟时，它很有帮助。你可以在根级、应用程序级或目录级的 web.config 文件中使用 `<identity>` 元素。`<identity>` 元素可以出现在 web.config 文件的根级、应用程序级或目录级的 `<system.web>` 元素中。`<identity>` 元素的语法如下：

```xml
<identity impersonate="true|false" userName="domain\userName" password="<secure password>"/>
```

在前面的语法中，`<identity>` 元素有三个属性：

- **impersonate** – 指是否使用客户端模拟。此属性可以有 `true` 或 `false` 作为其值。此属性的默认值是 `false`，这意味着不使用模拟。如果你将属性设置为 `true`，则在每次请求上都会使用模拟。

- **userName** – 指在启用模拟时要使用的用户名。

- **password** – 指在启用模拟时要使用的密码。

现在，让我们来看一下在为 ActiveDirectoryMembershipProvider 定义 `<provider>` 元素时你需要设置的一些常见 `<provider>` 元素属性。表 36.19 列出了 `<provider>` 元素的属性：

## Table 36.19: The Attributes of the `<provider>` Element

| Attribute | Description |
|---|---|
| connectionPassword | 指定用于访问 Active Directory 数据存储的密码。此属性确保访问 Active Directory 数据存储的用户是经过身份验证的用户。 |
| connectionStringName | 指定在 web.config 文件的 `<connectionStrings>` 元素中创建的连接字符串的名称。此连接字符串允许你对 Active Directory 数据存储执行创建、更新、获取和验证操作。 |
| connectionUsername | 指定用于访问 Active Directory 数据存储的用户名。此属性确保访问 Active Directory 数据存储的用户是经过身份验证的用户。 |

> **Note**  
> 如果你设置了 `connectionUserName` 属性，请确保也为 `connectionPassword` 属性指定了值。同样，如果你设置了 `connectionPassword` 属性，请确保也为 `connectionUserName` 属性指定了值。

以下代码说明了 ActiveDirectoryMembershipProvider 的配置：

```xml
<membership defaultProvider="ADMembershipProvider">
  <providers>
    <add
      name="ADMembershipProvider"
      type="System.Web.Security.ActiveDirectoryMembershipProvider, System.Web, Version=2.0.0.0, Culture=neutral, PublicKeyToken=b03f5f7f11d50a3a"
      connectionStringName="ActiveDirectoryCS"
      connectionUsername="<domainName>\administrator"
      connectionPassword="pass"/>
  </providers>
</membership>
```

## SqlMembershipProvider

SqlMembershipProvider 用于将用户凭据存储在 SQL Server 数据存储中。你需要先安装 SQL Server 成员资格数据存储，然后配置 SqlMembershipProvider 以在 ASP.NET 应用程序中使用 SqlMembershipProvider。SQL Server 成员资格数据存储是用于存储用户凭据的。我们将在后续主题中查看安装 SQL Server 成员资格数据存储和配置 SqlMembershipProvider 的详细信息。

## Installing the SQL Server Data Store

使用具有管理权限的帐户登录到计算机，例如管理员帐户，以在计算机上安装 SQL Server 成员资格数据存储。登录系统后，从 Visual Studio 2010 命令提示符运行 aspnet_regsql 实用程序并以管理员身份运行。aspnet_regsql 实用程序用于安装 ASP.NET 的各种功能的数据存储，例如配置文件、个性化和成员资格。你需要了解其各种选项，如下所示，以使用 aspnet_regsql 实用程序：

- `-E` — 使用当前登录用户的凭据进行身份验证。
- `-S` — 指定要安装 SQL Server 数据存储的计算机的名称。
- `-A m` — 生成 SqlMembershipProvider 所需的表和存储过程。

例如，你可以使用以下命令在计算机上安装 SQL Server 成员资格数据存储：

```text
aspnet_regsql.exe -E -S server -A m
```

在前一行代码中，计算机的名称是 Server。

## Configuring SqlMembershipProvider

默认情况下，SqlMembershipProvider 的一个实例 AspNet.SqlMembershipProvider 在你的 ASP.NET 应用程序的 Machine.config 文件中定义。此实例将你的 ASP.NET 应用程序连接到在本地计算机上运行的 SQL Server 数据存储实例。因此，如果 SQL Server 成员资格数据存储安装在本地计算机上，你无需显式配置 SqlMembershipProvider。

但是，如果你想将 ASP.NET 应用程序连接到在与 ASP.NET 应用程序运行的计算机不同的计算机上运行的 SQL Server 数据存储，则需要配置 SqlMembershipProvider。你可以通过在 ASP.NET 应用程序的 web.config 文件中定义连接字符串和 SqlMembershipProvider 的实例来配置 SqlMembershipProvider。

与 ActiveDirectoryMembershipProvider 类似，你需要定义 `<provider>` 元素来创建 SqlMembershipProvider 的实例。现在，让我们来看一下在为 SqlMembershipProvider 定义 `<provider>` 元素时你需要设置的一些常见 `<provider>` 元素属性，见表 36.20。

## Table 36.20: Attributes of the `<provider>` Element

| Attribute | Description |
|---|---|
| ApplicationName | 指定单个应用程序的用户的信息。你应该在使用 `applicationName` 属性的值限定用户信息时将其存储在 SQL Server 数据存储中。这可以防止在单个 SQL Server 数据存储中存储多个应用程序的信息时可能出现的相似用户名的冲突。`applicationName` 属性的默认值是 `/`。 |
| EnablePasswordReset | 指定用户是否可以修改其密码。默认情况下，`enablePasswordReset` 属性设置为 `false`。你只能在 `requiresQuestionAndAnswer` 属性设置为 `true` 时将此属性设置为 `true`。 |
| PasswordFormat | 指定在 SQL Server 数据存储中存储密码的格式。此属性可以取以下值：<br><br>- **Clear** – 以明文形式存储密码。以这种格式存储和检索密码很容易；然而，密码安全性受损。<br>- **Encrypted** – 以加密形式存储密码。需要解密才能检索以这种格式存储的密码。然而，以加密格式存储的密码的安全性很高。<br>- **Hashed** – 使用单向哈希算法对密码进行哈希处理后再存储。 这些密码的安全性很高；然而，你无法检索以哈希格式存储的密码。 |
| RequiresQuestionAndAnswer | 指定用户是否需要提供密码问题和答案来修改密码。此属性的默认值是 `false`。 |
| RequiresUniqueEmail | 指示 ASP.NET 应用程序的用户电子邮件地址是否需要唯一。 此属性的默认值是 `false`。 |

以下代码说明了使用上述属性配置 SqlMembershipProvider：

```xml
<configuration>
  <connectionStrings>
    <add name="SqlServices" connectionString="Data Source=localhost;Integrated Security=SSPI;Initial Catalog=aspnetdb;" />
  </connectionStrings>
  <system.web>
    <authentication mode="Forms">
      <forms loginUrl="login.aspx" name=".ASPXFORMSAUTH" />
```
