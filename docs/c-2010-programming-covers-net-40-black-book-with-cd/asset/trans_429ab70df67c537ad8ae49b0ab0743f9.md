

## ASP.NET 网站中的文件类型

Web 应用程序包含众多文件类型，这些文件类型由 ASP.NET 4.0 或 IIS 服务器支持和管理。大多数 ASP.NET 4.0 文件类型都可以使用 Visual Studio 2010 中的“添加新项”对话框自动生成。

文件类型通过应用程序映射映射到 Web 应用程序。例如，如果你在 Windows 资源管理器中双击 .txt 文件，它会打开记事本，因为在 Windows 中 .txt 文件类型默认映射到 Notepad.exe 文件。在 Web 应用程序中，文件类型在 IIS 服务器中映射到应用程序扩展名。表 13.1 列出了由 ASP.NET 管理的文件类型：

| 文件类型 | 位置 | 描述 |
|---|---|---|
| .asax | 应用程序根目录 | 指派生自 HttpApplication 类的代码的 Global.asax 文件。此文件代表 Web 应用程序，并包含在应用程序开始或结束时运行的可选方法。 |
| .ascx | 应用程序根目录或子目录 | 指定义自定义、可重用控件的 Web 用户控件文件。 |
| .ashx | 应用程序根目录或子目录 | 指包含用于实现 IHttpHandler 接口的代码的通用处理程序文件。 |
| .asmx | 应用程序根目录或子目录 | 指包含可通过简单对象访问协议（SOAP）供其他 Web 应用程序使用的类和方法 的 XML Web 服务文件。 |
| .aspx | 应用程序根目录或子目录 | 指包含 Web 控件以及表示和业务逻辑的 ASP.NET Web 窗体。 |
| .axd | 应用程序根目录 | 指用于管理网站管理请求的处理器文件，通常为 Trace.axd。 |
| .browser | App_Browsers 子目录 | 指用于识别客户端浏览器功能的浏览器定义文件。 |
| .cd | 应用程序根目录或子目录 | 指类图文件。 |
| .compile | Bin 子目录 | 指指向代表已编译网站文件的程序集的预编译存根文件。可执行文件类型（.aspx、.ascx、.master、主题文件）会被预编译并放入 Bin 子目录。 |
| .cs, .jsl, .vb | App_Code 子目录，或在 ASP.NET 页面的代码隐藏文件的情况下，与 Web 页面相同目录 | 指源代码文件，可以是 HTTP 模块、HTTP 处理程序、ASP.NET 页面的代码隐藏文件或独立类。换句话说，源代码文件包含在运行时编译的应用程序逻辑。 |
| .csproj, .vbproj, .vjsproj | Visual Studio 项目目录 | 指 Visual Studio 客户端应用程序项目的项目文件。 |
| .disco, .vsdisco | App_WebReferences 子目录 | 指 XML Web 服务发现文件，用于帮助定位可用的 Web 服务。 |
| .dsdgm, .dsprototype | 应用程序根目录或子目录 | 指可添加到任何 Visual Studio 解决方案的分布式服务图文件。它提供或使用 Web 服务，以便分析 Web 服务交互的架构视图，以构建解决方案的副本或改进现有解决方案。 |
| .dll | Bin 子目录 | 指已编译的类库文件（程序集）。除了将编译后的程序集放在 Bin 子目录中之外，还可以将类的源代码放在 App_Code 子目录中。 |
| .licx, .webinfo | 应用程序根目录或子目录 | 指许可证文件。许可有助于作者通过检查用户是否被授权使用该属性来保护知识产权。 |
| .master | 应用程序根目录或子目录 | 指定义 Web 应用程序中其他 Web 页面的布局的主页。 |
| .mdb, .ldb | App_Data 子目录 | 指 Access 数据库文件。 |
| .mdf | App_Data 子目录 | 指与 SQL Server Express 一起使用的 SQL 数据库文件。 |
| .msgx, .svc | 应用程序根目录或子目录 | 指 Indigo 消息框架（MFx）服务文件。MFx 服务文件有助于提供直接访问端口、消息、通道和服务的途径 |
| .rem | 应用程序根目录或子目录 | 指在 Web 应用程序中实现远程处理的处理器文件。 |
| .resources, .resx | App_GlobalResources 或 App_LocalResources 子目录 | 指包含引用图像、可本地化文本或其他数据的资源字符串的资源文件。 |
| .sdm, .sdmDocument | 应用程序根目录或子目录 | 指系统定义模型文件。 |
| .sitemap | 应用程序根目录 | 指包含网站结构的站点地图文件。ASP.NET 附带默认的站点地图提供程序，该提供程序使用站点地图文件轻松在 Web 页面中显示导航控件。 |
| .skin | App_Themes 子目录 | 指包含属性设置以应用于 Web 控件以实现一致格式的皮肤文件。 |
| .sln | Visual Web Developer 项目目录 | 指 Visual Web Developer 项目的解决方案文件。 |
| .soap | 应用程序根目录或子目录 | 指 SOAP 扩展文件。 |

### 注意

由 ASP.NET 管理的文件类型在 IIS 服务器中映射到 aspnet_isapi.dll 处理程序。

## 表 13.2：由 IIS 服务器管理的文件类型

| 文件类型 | 位置 | 描述 |
|---|---|---|
| .asa | 应用程序根目录 | 指包含在 ASP 会话或应用程序生命周期开始或结束时运行的可选方法的 Global.asa 文件 |
| .asp | 应用程序根目录或子目录 | 指包含 @ 指令（如 @Page 指令）和脚本代码的 ASP Web 页面 |

## ASP.NET 生命周期

ASP.NET 生命周期向您展示 ASP.NET 如何处理 Web 页面以生成动态输出。它还向您展示应用程序和单个页面如何实例化和处理，以及 ASP.NET 如何动态编译页面。我们将在以下部分详细讨论这些方面：

- IIS 7.5 上 ASP.NET 应用程序的生命周期
- ASP.NET Web 页面的生命周期

## IIS 7.5 上 ASP.NET 应用程序生命周期

在本节中，我们将了解在 IIS 7.5 集成模式下运行的 ASP.NET 应用程序的完整应用程序生命周期。IIS 7.5 还支持经典模式，其工作原理类似于在 IIS 6.0 中运行的任何 ASP.NET 应用程序。

在 IIS 7.5 的集成模式下，应用程序资源请求过程与 IIS 6.0 类似。然而，在 IIS 7.5 中，除了 IIS 6.0 中的事件外，在请求处理期间还引发了 MapRequestHandler、LogRequest 和 PostLogRequest 等三个新事件。此外，IIS 7.5 使用统一的请求处理管道来处理整个应用程序资源请求，而 IIS 6.0 中则没有此功能。

> 注意
> IIS 6.0 使用两个单独的管道来处理应用程序资源请求。一个管道用于非托管代码过滤器和扩展；另一个用于托管代码组件。

使用 IIS 7.5 集成管道的好处如下：

- 引发 HttpApplication 类的所有事件，以启用 IIS 7.5 中的 ASP.NET 模块。
- 能够配置托管代码和非托管代码模块。此外，使用集成管道，我们可以为所有请求启用或禁用托管代码模块，即使用户请求的是 ASP.NET Web 页面。
- 使网站能够在管道的任何阶段调用托管代码模块，例如在处理用户请求之前、请求处理后或用户请求处理中途。
- 使网站能够通过 Web.config 文件注册然后启用或禁用模块。

## 表 13.3：IIS 7.5 集成模式下 ASP.NET 应用程序生命周期的阶段

|---|---|
