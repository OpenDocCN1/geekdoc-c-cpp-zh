
## In Depth

Extensible Markup Language (XML) is a simple and flexible text format widely used to exchange different type of data on the Web. XML plays a very significant role with respect to .NET Framework, as it provides a namespace, System.Xml, which includes classes required to work with XML. You can import this namespace to use XML in the .NET applications. XML also stores data used in the .NET applications. ActiveX Data Objects (ADO) .NET is a primary tool used for data access and data manipulation in many programming languages supported by .NET Framework 4.0. ADO.NET uses XML as a medium of transferring data between applications and provides some powerful features to read and write XML documents.

Document Object Model (DOM) is a platform and language independent interface, which allows programs and scripts to access and update the content and structure of documents dynamically. You implement DOM with the help of the XmlDocument class. In addition, you can serialize and deserialize objects using the System.Xml.Serialization namespace.

In this chapter, you learn about the support for XML provided by .NET Framework 4.0. You learn about the System.Xml namespace, and how to work with streamed XML. In addition, you learn to implement DOM in .NET. You also learn about working with XPath and XSLT in .NET Framework 4.0. Finally, you learn how to use XML with ADO.NET, and how to work with object serialization in XML.

Now, let’s start our discussion by describing the support for XML provided by .NET Framework 4.0.

## Support for XML in .NET Framework 4.0

XML is a Data Description Language (DDL), which is developed by World Wide Web Consortium (W3C). It is used by ADO.NET as a format to store and transfer data. W3C has developed some standards for XML. The set of W3C standards supported by .NET Framework 4.0 are as follows:

- XML 1.0 (www.w3.org/TR/1998/REC-xml-19980210) with Document Type Definition (DTD) support
- XML Namespaces (www.w3.org/TR/REC-xml-names) for both stream-level and DOM
- XML Schemas (www.w3.org/2001/XMLSchema)
- XPath expressions (www.w3.org/TR/xpath)
- XSLT transformations (www.w3.org/TR/xslt)
- DOM Level 1 Core (www.w3.org/TR/REC-DOM-Level-1/)
- SOAP 1.1 (www.w3.org/TR/SOAP)

After exploring the different standards developed by W3C, let’s now look at the namespace to support XML in .NET Framework 4.0.

## The System.Xml Namespace

.NET Framework provides a namespace known as System.Xml, which contains classes to process XML. Table 30.1 describes some important classes contained in the System.Xml namespace:

Table 30.1: Important Classes in the System.Xml Namespace

| Class Name | Description |
|---|---|
| XmlReader | Specifies an abstract reader class that provides fast and forward-only non-cached XML data. |
| XmlWriter | Specifies an abstract writer class that provides fast non-cached XML data in the form of stream or file format. |
| XmlTextReader | Extends the XmlReader class and provides fast and forward-only stream access to XML data. |

| XmlUrlResolver | Extends the XmlResolver class and resolves resources named by a Uniform Resource Identifier (URI) |

Let’s now proceed to learn about streamed XML.

## Working with Streamed XML

Before the introduction of DOM, Simple Application Programming Interface (API) for XML (SAX) was used to access information stored in XML documents. In the SAX model, you only had the XmlReader and XmlWriter classes to work with XML data. XmlReader-based classes are used to stream XML data for processing in a fast-forward and read-only manner. XmlWriter-based classes are used to generate XML documents. The XmlReader and XmlWriter are abstract classes, so you need to use derived classes of these classes to work with XML in your applications. The classes derived from the XmlReader abstract class are as follows:

- XmlTextReader — Works either with a stream-based object or with TextReader/TextWriter objects
- XmlNodeReader — Uses XmlNode class as a source to read XML data
- XmlValidatingReader — Adds Document Type Definition (DTD) and schema validation; and offers data validation

XmlTextWriter is the class that is derived from the XmlWriter abstract class. Similar to the XmlTextReader class, this class also works with either a stream-based object or the TextReader/TextWriter objects from the System.IO namespace.

Let’s explore the XmlReader and XmlWriter classes in detail.

## The XmlReader Class

The XmlReader class is used to read XML data in a fast, forward-only, and non-cached manner. It is a read-only cursor that works similar to the SAX model. The XmlReader class can read an XML document or a stream. It facilitates a user to pull the data, and can skip the records that are not required in the application. However, the SAX model uses a push model to read XML data, in which a parser pushes events to an application. These events notify the application every time whenever a new record (data or node) has been read.

You need to import the following namespace in your application to work with the XmlReader class:

```
System.Xml;
```

You can use various methods to read data from an XML document, as described in Table 30.2:

Table 30.2: Methods Used by the XmlReader Class for Reading XML Data

| Method Name | Description |
|---|---|
| Read() | Takes the cursor position to the next node. |
| ReadStartElement() | Takes the cursor position to the next node after verifying whether the current node is the first element. An exception of type XmlException is raised if the current node is not the start element. The effect of calling this method is the same as of calling the IsStartElement() method, followed by the Read() method. |
| ReadString() | Reads in the text data from an element. This method returns a string object containing the data. |
| ReadElementString() | Works similar to the ReadString() method. The only difference is that you can optionally pass the name of an element to this method. |

## Validating XML Documents Using the XmlReader Class

You can validate an XML document against an XML Schema Definition (XSD) file, while reading the data, by using an abstract class, called XmlReader. This class validates an XML document against an XSD schema, by creating, first, an object of the XmlReaderSettings class. Then, you add the XSD schema to XmlSchemaSet by setting the Schemas property of the XmlReaderSettings class. You also have to set the XsdValidate property of the XmlReaderSettings class to true, which has the value false, by default.

## The XmlWriter Class

The XmlWriter class is used to write XML to a stream, file, or TextWriter object. In addition, it works in a forward-only, non-cached manner. You can also configure the XmlWriter object, by specifying some parameters, such as whether to indent the content of an XML document or not, and whether the namespaces are supported by an XML document or not.

## Implementing DOM in .NET Framework 4.0

DOM is implemented in .NET Framework by using the XmlNode abstract class. Implementation of DOM in .NET Framework 4.0 supports Core DOM Level 1 and Core DOM Level 2 standards developed by W3C. The XmlNode abstract class represents a node of an XML document. The XmlNodeList class is an ordered list of nodes that supports indexed access of nodes. Any changes to any node are immediately reflected in the list of nodes specified by the XmlNodeList class. Table 30.3 lists the classes derived from the XmlNode abstract class:

| Table 30.3: Classes Derived from the XmlNode Abstract Class |
| Class Name | Description |
| XmlAttribute | Represents an attribute object of an XmlElement object. |
| XmlDocument | Represents the entire XML document that implements the DOM Level 1 and DOM Level 2 specifications. Unlike the XmlReader and XmlWriter classes, this class gives you read and write capabilities and random access to the DOM tree. |
| XmlDocumentFragment | Represents a fragment of the document tree. |
| XmlEntity | Represents an entity node. |
| XmlLinkedNode | Contains the NextSibling and PreviousSibling properties, which are used to retrieve the node immediately after or before the current node. It is an abstract class. |
| XmlNotation | Contains a notation declared in a DTD or schema. |

The XmlLinkedNode class (described in the previous table) is an abstract class that contains derived classes. Table 30.4 lists the classes derived from the XmlLinkedNode class (listed in Table 30.3):

| Table 30.4: Classes Derived from the XmlLinkedNode Class |
| Class Name | Description |
| XmlDeclaration | Represents the declaration node (<?xml version='1.0'...?>) |
| XmlDocumentType | Represents the data related to a document type declaration |
| XmlElement | Represents an XML element object |
| XmlEntityReference | Represents an entity reference node |
| XmlProcessingInstruction | Contains an XML processing instruction |
| XmlCharacterData | Provides text manipulation methods for other classes. It is an abstract class. |
