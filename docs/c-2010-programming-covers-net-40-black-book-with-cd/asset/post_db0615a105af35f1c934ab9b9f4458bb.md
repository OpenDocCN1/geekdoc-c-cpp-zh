## Dynamically Invoking Methods from Classes in an Assembly

If you are creating a new compiler or interpreter for C# or any other .NET language, you need to use reflection to find information about the objects loaded in the compiler or interpreter. You can not only find information about different objects, but also invoke methods on them dynamically, if you know the name of the method you want to call and the arguments you want to pass to the method.

In addition to transferring information into a method, C# allows you to return information from a method to the calling function. This means that if a method, which you call, returns a value, then it will also provide the information back to the method of your calling application. In this section, we are creating the DynamicInvoke.cs file, which gives a simple set of classes. First, we create a class that implements a specific interface by defining the methods of the interface. Next, you call some of these methods directly to show the output of the functions. Finally, you dynamically invoke some of these methods to show how that particular process takes place.

## Verifying that a Class Contains a Method

If you are writing a scripting language that allows the use of C# objects, you need to verify that a given class contains a method before you allow the scriptwriter to create a script by using that method. After all, if the method does not exist, it does not make any sense to call it. This enables you to validate the method without waiting to run the application.

Using the reflection capabilities of C#, you can easily determine whether a given class contains a method by a given name. In fact, you can go further and check to see whether the number and type of arguments the script passes to the method are correct. It is interesting to check for the class(es) that contains a particular desired method.

Suppose that the scriptwriter creates a script containing an undefined variable that calls a method named Foo. You can mark that variable as undefined when your script parser encounters it because a variable of that name has not been declared at the point in the script where it is used. However, it is more useful and valuable to users if you show them the possible values of the variable. If only a single class exists in all the available assemblies for

the application, which contains the particular method, you can reasonably assume that it is the one the user wants. To issue a warning and then continue to create the script is considerably more suitable than simply to terminate with an error, such as Unknown Variable <x>.

In this example, you explore the capabilities of C# reflection by creating an application that can search a given assembly for a given method name. Any class that contains a method of this name is printed on the console screen for the users to view. It is much more convenient to search for full texts in this application than search for the same within the source code for the assembly. In many cases, you do not have access to the source code for the assembly. The CLR is a good example of an assembly in which you have only binary access. The VerifyClassMethod.cs example in the CD shows the application source code.
