
You can create a thread in your C# program by using the Thread class, which is passed in the ThreadStart delegate. The following syntax shows how to define the ThreadStart delegate:

```
public delegate void ThreadStart();
```

Let’s now look at the following code snippet to understand the syntax of the Thread class and the ThreadStart delegate to create and start a thread in a C# program:

```
class MyThreadClass
{
    static void Main()
    {
        //Creating an object of the Thread class
        Thread MyThread = new Thread(new ThreadStart(MyFunction));
        MyThread.Start();
    }
    static void MyFunction() {
        Console.WriteLine("This is my Thread");
        Console.ReadLine();
    }
}
```

In the preceding code snippet, you see that an object of the Thread class is created with the name MyThread and in the Thread class’s constructor the ThreadStart delegate is passed. The ThreadStart delegate indicates that the execution of the C# program should begin with the MyFunction() method. In this example, the MyThread thread executes the MyFunction() method at the same (or nearly same) time the Main() thread calls the MyFunction() method. The Start() method enables the MyThread thread to start.

In C#, you can also create a thread more conveniently by using the shortcut syntax for instantiating delegates, as shown in the following code snippet:

```
static void Main()
{
    Thread MyThread = new Thread (MyFunction);    // No need to explicitly use the
    MyThread.Start();                            //ThreadStart delegate
    ...
}

{
    ...
}
```

In this case, the C# compiler automatically determines the ThreadStart delegate.

Let’s now discuss the concept of multithreading.

## Multithreading

The Multithreading feature enables you to have more than one execution path for your application at a time. You are already aware of Windows multitasking facilities, which allow you to perform more than one task at the same time. In multitasking, you can perform multiple tasks simultaneously, such as writing an article using MS-Word, listening a song in Windows Media Player (WMP), and downloading a movie using the Internet Download Manager. In the same way, you can use multithreading to execute different methods of a program simultaneously. Almost all the Windows applications use the concept of multithreading, such as MS-Word takes user input and displays it on the screen in one thread, while it continues to check spellings and grammatical mistakes in the second thread, and at the same time the third thread saves the document automatically at regular intervals. In the same way, WMP plays music in one thread, displays visualizations in the second thread, and takes user input in the third thread. In C#, multithreading can be achieved by creating multiple threads in a single application. The following code snippet shows the syntax of creating multithreaded applications:

```
static void Main(string[] args)
{
    Thread FirstThread = new Thread(FirstFunction);
    Thread SecondThread = new Thread(SecondFunction);
    Thread ThirdThread = new Thread(ThirdFunction);
    Console.WriteLine("\nThreading Starts...\n");
    FirstThread.Start();
    SecondThread.Start();
    ThirdThread.Start();
}
public static void FirstFunction()
{
....
}
public static void SecondFunction()
{
....
}
public static void ThirdFunction()
{
...
}
```

In the preceding code snippet, you can see that a single application consists of three threads, such as FirstThread, SecondThread, and ThirdThread.

Let’s now learn about the priorities of the thread.

## Thread Priorities

Depending upon the order and importance of the tasks assigned to threads in a multitasking environment, the priority levels of threads is determined. The thread having the higher priority is executed more frequently than one that has a lower priority. Consider a case of an application that is designed to accept user inputs in the first thread and display a message to the user indicating the time that has elapsed after the form has been opened in the second thread. In this case, as the task of accepting the user input needs to be accomplished before any other task, you can define the thread responsible for accepting the user input as the one having the higher priority than the thread controlling the user responsiveness. In C#, the ThreadPriority enumeration defines the set of all possible values for a thread priority. You can get or set the thread’s priority with the Priority property of the Thread class.

Table 31.3: Priorities of a Thread

| Name | Description |
|------|-------------|
| Lowest | Refers to the least important priority level that can be assigned to a thread. A thread with this priority can be scheduled after threads with any other priority. |
| BelowNormal | Refers to the priority level that is just below the Normal level. The thread with this priority can be scheduled after threads having the Normal priority and before those with the Lowest priority. |
| Normal | Refers to the priority level that is neither lowest nor the highest. The thread with this priority can be scheduled after threads with the AboveNormal priority and before those with the BelowNormal priority. All the threads have the Normal priority by default. |
| AboveNormal | Refers to the priority level that is just below the Highest level. The thread with this priority can be scheduled after threads with the Highest priority and before those with the Normal priority. |
| Highest | Refers to the most important priority level that can be assigned to a thread. The thread with this priority can be scheduled before threads with any other priority. |

The following code snippet shows how to set different priority levels to threads:

```
static void Main(string[] args)
{
    Thread FirstThread = new Thread(FirstFunction);
    Thread SecondThread = new Thread(SecondFunction);
    Thread ThirdThread = new Thread(ThirdFunction);
    FirstThread.Priority = ThreadPriority.Lowest;
    SecondThread.Priority = ThreadPriority.Highest;
    ThirdThread.Priority = ThreadPriority.Normal;
    FirstThread.Start();
    SecondThread.Start();
    ThirdThread.Start();
}
```

The preceding code snippet defines three threads—FirstThread, SecondThread, and ThirdThread. The FirstThread thread has been assigned the Lowest priority, the SecondThread thread has been assigned the Highest priority, and the ThirdThread thread has been assigned the Normal priority. It means that when you execute the program, the SecondThread thread is executed first, then the ThirdThread thread is executed, and finally the FirstThread thread is executed.

Let’s now learn about the different states of a thread.

## Thread States

Every object has its state. For example, water is found in three states, such as solid, liquid, and gas and it can be transformed from one state to another. In the same way, threads also have their states and can be transformed from one state to another. The state of a thread determines its actual status at a given point of time. You can determine the state of a thread by the ThreadState property of the Thread class.

Table 31.4: States of a Thread

| Name | Description |
|------|-------------|
| Running | Refers to a state in which the thread is in the execution mode. |
| StopRequested | Refers to a state in which a thread is requested to stop its execution. |
| SuspendRequested | Refers to a state in which a thread is requested to suspend its execution. |
| Background | Refers to a state in which a thread is executed as a background thread, as opposed to a foreground thread. This state is controlled by setting the IsBackground property of the Thread class. |
| Unstarted | Refers to a state in which the Start() method of the Thread class has not yet been invoked. |
| Stopped | Refers to a state in which a thread has already stopped executing. |
| WaitSleepJoin | Refers to a state that occurs when the Wait(), Sleep(), and Join() methods are simultaneously invoked. A thread in this state stops executing and is considered to be blocked. |
| Suspended | Refers to a state in which a thread has been suspended. |
| AbortRequested | Refers to a state in which a thread is requested to stop its functioning permanently. |
| Aborted | Refers to a state in which a thread is considered to be dead forever. |
