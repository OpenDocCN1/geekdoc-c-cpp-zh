As shown in Figure 17.6, there are several files in the Web application, SampleSilverlightApplication.Web. Broadly, a Web application within a Silverlight 3.0 application has three essential files as follows:

- An ASP.NET file – Loads when a Silverlight application runs and hosts the MainPage.xaml XAML file. In our case, the ASP.NET file is the SampleSilverlightApplicationTestPage.aspx (Figure 17.6). An ASP.NET file is the default startup page of a Silverlight 3.0 application.
- An HTML file (a test page) – Hosts the Silverlight application. In our case, the HTML file is SampleSilverlightApplicationTestPage.html (Figure 17.6).
- A JavaScript helper file – Provides methods, such as createObject() and createObjectEx(), to embed a Silverlight application in a Web page. The createObject() and createObjectEx() methods are used to create and initialize the Silverlight content in an ASPX or HTML test page that hosts the Silverlight application. In our case, the JavaScript helper file is Silverlight.js (Figure 17.6).

Depending on the host application that you select, there may be other files that are automatically added to the project. Normally, you use the predefined project templates in Visual Studio 2010. Now, let’s discuss each of the files in detail beginning with the ASP.NET and HTML files that host the Silverlight applications.

## The ASP.NET and HTML Host Pages (Test Pages)

Whenever you create a Silverlight application, you need a page to host that Silverlight application. In Visual Studio 2010, you can opt to host a Silverlight application in either a simple HTML Web page or an ASP.NET Web application. In Visual Studio 2010, when you select an ASP.NET Web application project to host a Silverlight application, an ASP.NET Web application is automatically added to a Silverlight application. The ASP.NET Web application contains two test pages, which are ASP.NET and HTML test pages, created by default for an entire Silverlight application. In other words, it means that the ASP.NET and HTML pages are the test pages that are used to host your Silverlight content. The ASP.NET and HTML test pages can be used to test XAML content of a Silverlight application during the development of the application. In addition, they have the same name as the Silverlight application suffixed with the text TestPage.

The HTML test page (that is, .html test page) largely contains the same code as the TestPage.html file of Silverlight applications that are hosted in a single HTML page. This means that the HTML test page contains the code to create and initialize a Silverlight application. The ASP.NET test page (that is, .aspx test page) contains the equivalent ASP.NET code of the HTML test page. In addition, the ASP.NET test page is the default startup page, as it is the first page that appears when users run a Silverlight application. You can find the ASP.NET and HTML test pages in Solution Explorer, as shown in Figure 17.7:

## The JavaScript Helper File

`Silverlight.js` is a JavaScript helper file that provides programmatic access and logic for the UI elements and objects in a Silverlight application. It is the main file that provides the functionality to create and initialize the Silverlight content, verify that Silverlight is installed on the users’ computers, and check the version of the Silverlight installed on the users’ computers. As the `Silverlight.js` file depends on the browser implementation, details can vary from one Silverlight release to another; therefore, you should periodically check for an updated version of `Silverlight.js` from the MSDN Code Gallery.

The `Silverlight.js` JavaScript helper file defines a new namespace `Sys.Silverlight` that contains the `createObject()` and `createObjectEx()` methods. The `createObject()` and `createObjectEx()` methods create and initialize the Silverlight content in an ASPX or HTML page that hosts the Silverlight application. Both methods have the same functionality and have several parameters, the values of which are fetched from the `<object>` or `<embed>` tag. Note that the `<object>` and `<embed>` tags are also generated by these two methods. The difference between `createObject()` and `createObjectEx()` is that only `createObjectEx()` packs all the parameters in a JSON dictionary.

## The XAML Files

Similar to WPF applications, the design and UI of Silverlight applications are defined through XAML. As stated earlier, every Silverlight application has a few XAML files, such as `App.xaml`, `App.xaml.cs`, `MainPage.xaml`, and `MainPage.xaml.cs`, which define the UI and basic behavior of a Silverlight application. The `App.xaml` and the `App.xaml.cs` files represent the application and the `MainPage.xaml` and `MainPage.xaml.cs` files represent the UI of the application. The `App.xaml` file is an XAML file that contains application-level information and settings. The default content of the `App.xaml` file is shown as follows:

```xml
<Application xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="SampleSilverlightApplication.App">
  <Application.Resources>
  </Application.Resources>
</Application>
```

In the preceding code snippet, you can see that there is only one element named `Application`. The `Application` element has the `xmlns`, `xmlns:x`, and `x:Class` attributes. The `xmlns` attribute refers to the default namespace for working with the Silverlight 3.0 applications. The default namespace for Silverlight 3.0 is http://schemas.microsoft.com/winfx/2006/xaml/presentation, which provides the facility to work with Silverlight controls and types. The `xmlns:x` attribute refers to the namespace that provides the types and classes for XAML as a whole. Note that whenever you use an element that is not defined in the default Silverlight namespace but in the XAML namespace, you need to use `x:` as a prefix for the element. The `x:Class` attribute binds the `Application` element in the `App.xaml` file to the partial class (in the `App.xaml.cs` file) that inherits from the `Application` class. Note that the `x:Class` attribute is bound to the `App` partial class in the `SampleSilverlightApplication` namespace.
