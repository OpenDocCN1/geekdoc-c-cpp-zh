
## The System.Windows.Media.Visual Class

The System.Windows.Media.Visual class is the base class to render elements used in WPF applications. The Visual class provides rendering-related functionalities, such as clipping, transformations, and bounding box calculations. You can clip regions of the elements, apply transformations on the elements, or verify whether or not a point lies within a given boundary.

The Visual class acts as a link between the managed WPF components and the unmanaged milcore component by generating a tree-like structure in the milcore, called composition tree. Every visual element that you use in a WPF application may correspond to zero or more composition nodes in the composition tree. Each composition node has various appearance-related properties and certain rendering instructions that are used to render elements. The composition nodes are traversed one at a time and the rendering instructions on the nodes are executed to composite and display the elements. Note that the composition tree and the nodes are accessible only through a messaging protocol.

WPF uses the retained mode rendering system that is, the complete composition tree is cached by the milcore component. This implies that when there are changes in any composition node, only the changes are conveyed to the milcore component. This ensures faster and optimized repainting of the screen. Note that the composition nodes are rendered using the painter’s algorithm, wherein the distant nodes are rendered first and the nodes that are in the front are rendered next. Using this algorithm, it becomes easier and faster to render complex and intricate visual effects, such as translucent or transparent visuals.

## The System.Windows.UIElement Class

The System.Windows.UIElement class provides APIs to implement the fundamental features in WPF 4.0 applications. For example, layouts and events for WPF elements. You can use the properties and methods of the UIElement class to manipulate the layout of visual elements in WPF applications. The UIElement class introduces an easy-to-use and flexible layout model.

The flexible layout model comprises two phases, namely Measure and Arrange. You can determine the size of an UI element of a WPF application in the Measure phase. The size of an element can be determined multiple times, depending on the size and position of other elements. In the Arrange phase, the optimum position of an element is determined. The flexible layout model in WPF makes it easier for the elements to change their size and positions and provides dynamic layouts for elements. The UIElement class also provides support for events, inputs, and command bindings in WPF applications.

> NOTE
> The Visual and UIElement classes are provided by the PresentationCore assembly.

## The System.Windows.FrameworkElement Class

The System.Windows.FrameworkElement class is the interface between the UIElement class and WPF framework-level implementation elements (elements that you use directly in XAML or code-behind files). The FrameworkElement class not only incorporates the functionalities provided by the UIElement class but also offers additional features to enhance WPF applications. The FrameworkElement class has various properties that help you to uniformly and flexibly apply layout and styles to the WPF framework-level visual elements in WPF applications. It also provides support for specifying different visual elements in the form of a tree, animation and storyboarding, data binding, and events.

The FrameworkElement class has several derived classes that allow you to work with controls, multimedia, and 3-D content. Some of the classes that inherit the FrameworkElement class include the Control, Panel, and Shape classes. Now, let’s first explore these classes one by one.

## The System.Windows.Controls.Control Class

Similar to Windows Forms, WPF also has several predefined UI elements known as controls. Most of the WPF controls are derived from the System.Windows.Controls.Control class. For instance, the Label, Button, RadioButton, and GroupBox controls are derived from the Control class. This class provides several properties to add background and foreground, visual effects, borders, and styles on the controls, as well as change the fonts.

In addition to the exhaustive range of properties to manipulate the look and feel of the controls, the Control class offers a control template for the same tasks. Control templates (instances of the ControlTemplate class) define the look, appearance, and behavior of the respective controls. You can create or modify control templates to suitably change the appearance of the controls.

## The System.Windows.Controls.Panel Class

In WPF 4.0, all the controls that you work with have to be enclosed in a panel, which is a container control that holds other controls as well. A panel allows you to adjust the layout and dimensions of the controls that the panel contains. All the panels are derived from the System.Windows.Controls.Panel class. Some of the panels that inherit the Panel class include Grid, Canvas, and StackPanel.

You can use a particular panel based on your requirements. For example, you can use the Grid panel to arrange the child controls in the form of a grid or the StackPanel panel to position the child controls horizontally or vertically in a straight line. The panels inherit the various properties of the Panel class to allow you to alter the arrangement of the containing or child controls. The properties assist you to change the height and width of the child controls, appropriately align the controls, and position the controls in a layered manner.

## The System.Windows.Shapes.Shape Class

WPF 4.0 offers extensive support for 2-D graphics to develop WPF applications. One of the frequently used 2-D graphics elements in WPF applications is shape. In WPF 4.0, shapes are derived from the System.Windows.Shapes.Shape class. The Shape class has several derived classes, such as Ellipse, Line, Rectangle, and Polygon, to draw and manipulate different shapes in WPF applications. You can use the properties of the Shape class to perform activities, such as filling the shapes with different colors, adding an outline or border to the shapes, and stretching the shapes. You learn more about shapes in Chapter 12, Using Graphics and Multimedia in Windows Forms and WPF.

## The System.Windows.ContentElement Class

The System.Windows.ContentElement class exists in the PresentationCore assembly and offers some of the core-level functionalities to work with the content of WPF applications. It is responsible for the style and presentation of the content. It also offers features, such as input from mouse and keyboard, focusable elements, and events to indicate various changes in the flow content. In addition, it provides several properties, methods, and events to work with animations and textual content.
