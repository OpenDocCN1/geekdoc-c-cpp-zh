# ## Verifiably Type-Safe MSIL Code

A verifiably type-safe code is always valid and type-safe; however, a type-safe code may not be verifiably type-safe. This may happen because of inadequacy of the verification process or the language compiler. The CLR uses an inbuilt verification algorithm to verify the type-safety of the MSIL code. You can also check whether the MSIL code is verifiably type-safe by using the PEVerify tool (peverify.exe), which is a .NET Framework utility that allows you to ensure that your MSIL code is verifiably type-safe. You can use the PEVerify tool at the Visual Studio 2010 Command Prompt and pass the assembly that contains the intended metadata and MSIL code. The syntax for using the PEVerify tool at the command prompt is:

```
peverify assemblyname [switches]
```

In the preceding syntax:

+   - `peverify` — the PEVerify tool
+   - `assemblyname` — name of the assembly for which you want to perform the verification process
+   - `[switches]` — optional set of switches

The PEVerify tool has a number of switches, some of which are listed in Table 36.2:

**Table 36.2: Switches of the PEVerify Tool**

| Switch | Description |
|---|---|
| `/help` or `/?` | Shows the syntax and switches of the PEVerify tool |
| `/md` | Verifies the metadata in the assembly |
| `/il` | Verifies the MSIL code in the assembly |
| `/clock` | Shows the time taken (in milliseconds) for verification |
| `/hresult` | Shows the error codes in hexadecimal format |
| `/unique` | Hides any repeating error codes |
| `/quiet` | Shows only the status of the verification, not the error codes |
| `/verbose` | Shows additional information about the verification process |
| `/ignore=<errorhexcode>[, errorhexcode, errorhexcode…]` | Ignores the specified error codes (in hexadecimal format) |
| `/ignore=@filename` | Ignores the error codes given in the specified response file |
| `/nologo` | Hides the product version and copyright information |

Note that the PEVerify tool performs the verification in the absence of any or all of the switches listed in Table 36.2. The PEVerify tool validates the metadata first and if there are no errors, it verifies the MSIL code. In case of any error in the verification of the metadata, the MSIL code is not verified. However, if you specify the `/md` and `/il` switches, the MSIL code is verified irrespective of whether there are errors in the metadata.

If the MSIL code undergoes the verification process but does not pass the verification, then an exception occurs and the execution of the application is halted. In case you are certain that your code is completely trusted to be type-safe, then you can bypass the verification. You can also bypass the verification if you want to run a non-type-safe code. However, running a non-type-safe code is not recommended as it may lead to unpredictable results. To bypass the verification, you need to set the SkipVerification property of the SecurityPermission attribute to false at the assembly level.

> **NOTE**
> 
> The verification process is performed by the CLR only on managed code; unmanaged code does not undergo the verification process and therefore, is run in a full-trust environment.
