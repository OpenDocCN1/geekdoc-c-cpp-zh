To create an application that accesses AD objects in C# 2010, you need to perform the following tasks:

- Specify a binding path to establish a connection between an application and AD
- Create new objects, for instance users
- Modify Active Directory objects
- Search AD for objects

## Specifying a Binding Path

The process of connecting an application with AD is called binding. You need to provide a binding string to bind an application with AD. An example of binding string is given as follows:

```
LDAP://192.168.1.95/CN=Users, DC=sql, DC=local
```

A binding string must contain the following items:

- Protocol – Identifies the details of an ADSI provider to provide interface to access directory service
- Server name – Identifies the name of the domain controller
- Port number – Identifies the name of the server process
- Distinguished name of the object – Identifies the name of the object that you want to access
- Username and password – Identifies the user who is allowed to access AD
- Authentication type – Identifies the need for encryption

## Creating New Objects

You can create AD objects for users, computers, printers, and contacts. The DirectoryEntry and DirectoryEntries classes are used to create a new object. An object of DirectoryEntries can be accessed by using the Children property of a DirectoryEntry, as shown in the following code snippet:

```
DirectoryEntry de = new DirectoryEntry("LDAP://192.168.1.95");
DirectoryEntries users = de.Children;
```

Objects can be added, removed, and searched in a collection by using methods provided by the DirectoryEntries class, as shown in the following code snippet:

```
DirectoryEntry user = users.Add("CN=John Doe", "user");
```

You can add properties to AD objects by using the Add() method of the Properties property, as shown in the following code snippet:

```
user.Properties["company"].Add("Any company");
user.Properties["department"].Add("Sales");
```

The properties added should exist in the schema for the user object. If the property does not exist in the schema, you get a COMException exception that displays the message: "The specified directory service attribute or value does not exist."

You need to flush the cache to write the data to AD, as shown in the following code snippet:

```
user.CommitChanges();
```

## Modifying the Active Directory Objects

To modify the values of the properties of AD objects, you can use various methods, such as Add(), Remove(), and RemoveAt(). The Add() method is used to add new values to a property, while the Remove() and RemoveAt() methods are used to remove specific values from a property. You can also clear the value of a property by using the PropertyValueCollection.Clear() method.

The following code snippet shows how the properties—company and department—of user Steve can be modified:

```
DirectoryEntry entry = new DirectoryEntry("LDAP://192.168.1.95");

string a = null;
entry.Path = "LDAP://192.168.1.95/CN=" + a + ",CN=Users,DC=sql, DC=local";
entry.Username = "administrator@sql.local";
entry.Password = "kogenta321";
```

## Searching Active Directory for Objects

The DirectorySearcher class is used to search object values in AD. To search object values, you need to define four important parts in the constructor of DirectorySearcher class, which are as follows:

- SearchRoot
- Filter
- PropertiesToLoad
- SearchScope

Let's discuss these parts one by one.

### SearchRoot

The SearchRoot part in the constructor of DirectorySearcher class specifies the base node from where the search should begin. The default node is the root domain. The SearchRoot class starts searching from this domain. The SearchRoot class is used along with the Path property of the DirectoryEntry object.

### Filter

The Filter part defines the criteria for searching objects in AD. The string identifying the filter should be enclosed in parentheses. A search filter contains name, operator, and value. You can also use the `<=`, `=`, `>=`, `&`, and `|` operators while writing the search expressions in a search filter.

### PropertiesToLoad

The PropertiesToLoad part specifies the properties that should be loaded into the cache as well as returned to the caller. By default, the path and the name of the object are returned.

### SearchScope

The SearchScope part defines the depth of a search. In other words, it specifies the start and end of a search. The SearchScope part contains the following attributes:

- `SearchScope.Base` – Starts searching from the base object and returns only one object as the result.
- `SearchScope.OneLevel` – Starts searching from the child collection of the base object. It searches the immediate children of the specified base.
- `SearchScope.Subtree` – Searches the complete tree, implying the entire subtree including the search base is searched.

## Immediate Solutions

To maintain security of network objects, you need to authorize and authenticate user accounts. You need to perform the following steps to create a new user account in AD:

1. Click Start→Administrative Tools→Active Directory Users and Computers. The Active Directory Users and Computers snap-in opens.
2. Right-click the Users node in the forest in which you want to create a new user. In this case, we have right-clicked the dreamtechpress.net forest. The New Object - User wizard opens.
3. Provide the first name, last name, and user logon name in the First name, Last name, and User logon name text boxes.
4. Click the Next button.
5. Provide the password for the user in the Password and Confirm password text boxes, respectively. The User must change password at next logon check box is selected by default.
6. Click the Next button. A new user is created.
7. Click the Finish button to complete the process.

- [ ] You must be a member of the Account Operators group, Domain Admins group, or the Enterprise Admins group in AD, or you must have been given the appropriate authority.
- [ ] You must ensure that the password is a combination of alphabets, numbers, and some special characters.
- [ ] You can also copy any previously created user account.
- [ ] A new user account having the same name as the account that is already deleted does not grant the permissions and group memberships of the deleted account. You need to assign permissions and memberships manually to the user account.

Next, let's learn how to create a group of users in AD.

You can create a group in AD by using the Active Directory Users and Computers snap-in. Perform the following steps to create a group:

1. Open the Active Directory Users and Computers snap-in.
2. Right-click the domain, OU, or container for which you want to create a group, and select New→Group from the context menu. The New Object - Group dialog box opens.
3. Provide a name for the group in the Group name box. The name automatically appears in the Group name (pre-Windows 2000) box.
4. Select a group type from the Group type group. In the Group type group, the following options are available:
   - Security—Provides a secured access to shared resources, such as a file or printer, by a group of users, computers, and other groups
   - Distribution—Refers to a group of users or computers that send e-mails to the other members of the group by using an e-mail application, for instance Microsoft Exchange. You can use Security groups both for resource access and email distribution. If you are creating a group only for email distribution, you should use the Distribution group.
5. Select the scope of the group from the Group scope group. In the Group scope group, the following options are available:
   - Domain local—Refers to groups that are used to grant permissions to resources. A domain local group is defined in the domain naming context. You can include any security principals from a domain.
   - Universal—Refers to groups that are used to grant permissions to resources in the forest. A universal group is defined in the forest naming context. You can include any security principals from a domain or from another domain in the forest.
