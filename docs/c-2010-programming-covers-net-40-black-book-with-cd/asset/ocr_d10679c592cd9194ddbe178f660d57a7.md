# Using XAML in WPF 4.0 Applications

As stated earlier, one of the key ingredients in WPF is its base XAML. The support for XAML (pronounced as zammel) in WPF allows you to declaratively specify the UI or appearance of WPF applications. The XAML loader in WPF 4.0 facilitates you to work with XAML content in WPF applications. With XAML integration in WPF, it is easier and more convenient to draw a line between the design or UI and the logic or functionality of WPF applications. This is because you can use XAML to define the UI of WPF applications, while you can add the logic for the UI in the code-behind file of the application. On the other hand, XAML also eases the sharing of XAML content with the code-behind file as it allows the elements defined in the XAML file to be used in the code-behind file.

Visual Studio 2010 supports the XAML IntelliSense feature and allows the debugging and compilation of XAML content. Moreover, Visual Studio 2010 Software Development Kit (SDK) includes an XAML editing tool called XAMLPad to work with XAML elements in real-time. You can access XAMLPad from C:\Program Files\Microsoft SDKs\Windows\v6.0A\bin\XamlPad.exe.

# XAML Elements

XAML, based on XML, makes use of markup tags, elements, and attributes to define the UI of WPF applications. The XAML elements directly correspond to various managed WPF classes, while the XAML attributes correspond to the properties and events of the classes. In addition, the XAML namespaces in which these XAML elements are defined correspond to the CLR namespaces, so that XAML content can make use of the debugging and compiling provided by .NET Framework 4.0.

In WPF, the XAML elements are represented as a logical tree with several element nodes. Each element corresponds to a tree node while the attributes of the elements become the properties of the nodes. When you add an XAML element within an existing element, it becomes the child element of the existing node. This kind of hierarchical tree-like content model makes WPF applications extensible and easy to render. Note that in any XAML file, there is exactly one topmost or root element. In WPF standalone applications, the root element is the Window element, while in XBAPs the root element is the Page element.
