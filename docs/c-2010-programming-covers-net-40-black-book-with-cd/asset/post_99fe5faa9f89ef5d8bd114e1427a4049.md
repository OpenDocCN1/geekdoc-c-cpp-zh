public delegate void Compute(int x, int y);

Although the syntax of declaring a delegate is similar to that of declaring a method (without method body), the delegate actually represents a class type. As a delegate represents a class type, it can be declared at any place where a class can be defined—outside or inside a class. Delegate types are implicitly sealed; and therefore, deriving a new type from a delegate type is not possible.

## Defining Delegate Methods

A delegate method is any method whose signature (number and type of parameters and return type) matches the delegate signature exactly. It can be either a static method or an instance method. We can define a static method, named Add(), to be encapsulated into the Compute delegate, as follows:

```
public static void Add(int a, int b)
{
    Console.WriteLine("Sum = {0}", a + b);
}
```

Similarly, we can also define an instance method, named Subtract(), to be encapsulated into the Compute delegate, as follows:

```
public void Subtract(int a, int b)
{
    Console.WriteLine("Difference = {0}", a - b);
}
```

## Creating Delegate Objects

You can create an object of a delegate using the following syntax:

```
Delegate-name object-name = new delegate-name(expression);
```

In the preceding syntax, delegate-name is the name of the delegate declared earlier whose object is to be created; object-name is the name of the delegate object; and expression is what you want to encapsulate into the delegate object and it can be the name of a method or an object of a delegate type. If you pass a method or an object of a delegate type to its constructor, its signature should match exactly with the signature of the delegate; otherwise you receive a compile-time error.

Using the preceding syntax, you can create an object of the Compute delegate, named cmp1, to hold the reference of the (static) Add() method, as follows:

```
Compute cmp1 = new Compute(DelegateTest.Add);
```

Similarly, you can create another object of the Compute delegate, named cmp2, to hold the reference of the (instance) Subtract() method, as follows:

```
DelegateTest dt = new DelegateTest();
Compute cmp2 = new Compute(dt.Subtract);
```

## Invoking Delegate Objects

A delegate object is invoked as a method is invoked. The following code snippet shows the syntax to declare a delegate-object:

```
Delegate-object(argument-list)
```

In the preceding syntax, delegate-object is the name of the object being invoked; and argument-list is the list of values that is assigned to the parameters of the method, encapsulated into the delegate object. When a delegate object is invoked, it in turn invokes the method, which is encapsulated into the delegate object.

If the return type of the delegate is void, we add a semicolon after the pair of parentheses in the preceding syntax. On the other hand, if the delegate has a return type other than void, we take the preceding syntax as the right hand side of an assignment statement to invoke the objects of the Compute delegate, cmp1 and cmp2, as follows:

```
cmp1(30, 20);
cmp2(30, 20);
```

## Multicasting with Delegates

Each delegate object that we have created so far holds a reference of a single method. However, it is possible for a delegate object to hold references of and invoke multiple methods. Such delegate objects are called multicast delegates or combinable delegates. You can encapsulate more than one method into a single delegate object using the overloaded += operator. Each delegate object that you create, by default, maintains an invocation list, which is the list of methods encapsulated into the delegate object. The invocation list of a multicast delegate consists of multiple methods that are invoked in the order they were added to the multicast delegate. Objects of only those delegates that satisfy the following two conditions can be made as multicast delegates:

- The return type of the delegate is void
- None of the parameters of the delegate is an output parameter (a parameter declared using the out keyword)

You learn how to create a multicast delegate in the Creating Multicast Delegates section of the Immediate Solutions.

## Exploring Covariance and Contravariance

Covariance allows you to create delegate methods, which are used by classes and derived classes. Contravariance allows you to create more general delegate methods that can be used with a larger number of classes. These features are introduced in C# to increase the flexibility while matching delegate methods with delegate signatures. Flexibility means the ability of a delegate to cope up with different classes or events of a program. Normally, the method passed to a delegate must have the same return type and signature as the delegate. However, covariance allows you to use a method that has a derived return type as a delegate. Consider the following code snippet, which defines a delegate:

```
delegate object GetData(TextBox control);    //defining a delegate
```

The preceding statement defines a delegate, GetData. Covariance allows the GetData delegate to point to any method that takes a TextBox argument irrespective of its return type, as all types of .NET classes inherit from the System.Object class. Therefore, the GetData delegate can point to the method, GetcontrolText, as the String type of .NET Framework inherits from the System.String class, as shown in the following code snippet:

```
string GetControlText(TextBox control)    // GetControlText is the method to
{                                        //which the GetData delegate points.
    return control.Text;
}
```

Similar to covariance, contravariance allows you to use a method with derived parameters as a delegate. This means that contravariance enables a delegate to point to a method whose argument is the base type of argument appearing in the delegate's signature. In the preceding code snippets, we have created the GetData delegate. The following code snippet shows that the GetData delegate is pointing to the GetTag() method:

```
object GetTag(Control ctr)
{
    return ctr.Tag;
}
```

In the preceding code snippet, contravariance enables the GetData delegate to point to the GetTag() method, which accepts a Control or Object value, as these types are the base types for the TextBox class specified in the delegate signature.

## Exploring Anonymous Methods with Delegates

As you know in C# 1.0, a delegate can be declared using named methods. Now, to declare a delegate using the unnamed methods, C# 2.0 introduces the concept of anonymous methods. Anonymous methods allow you to instantiate a delegate and create a code block, which is passed to the delegate as a delegate parameter. This code can be executed by a delegate, when it is called. The following code snippet shows how to define a named method:

```
// Declaring a delegate:
delegate void Delg(int a);

// Defining a named method:
void func(int n)
{
}
// Instantiating the delegate using the named method as a parameter:
Delg d = obj.func;
```

In the preceding code snippet, we have instantiated the delegate, Delg, by using the named method, func, as parameter. Now consider the following code snippet, where we instantiate the delegate using the anonymous method:

```
// Declaring a delegate
delegate void Delg(int a);

// Instantiating the delegate using an anonymous method
Delg d = delegate(int n) { };
```

In the preceding code snippet, we have minimized the coding overhead by eliminating the need for creating a separate method for instantiating a delegate. As a result, the code usability and code maintainability are enhanced.

Anonymous method enables you to pass a code block as a delegate parameter. You need to define an anonymous method in-line and not as a class member, while invoking a delegate. You can pass the anonymous method to only the method that has a delegate type parameter. The following code snippet shows how to pass the anonymous method as a delegate parameter:

```
void function()
{
    System.Threading.Thread th = new System.Threading.Thread
    (delegate()
    {
        System.Console.Write("Hi !");
        System.Console.WriteLine("How are u!");
    });
    th.Start();
}
```

In the preceding code snippet, we have created a thread that executes its code without creating an additional delegate method. The code block for starting the thread is passed as a delegate parameter. This code block acts as the anonymous method, which prevents you from writing a separate delegate method. You need to keep the following points in mind while working with anonymous methods:

- Do not use unsafe code in an anonymous method.
- Do not use statements that transfer the control outside the anonymous block, such as goto, break, or continue. Even if these statements transfer the program control inside the anonymous method, you cannot use these statements outside the anonymous method.
- Do not access the ref or out parameter of an outer scope using the anonymous method. The variables or parameters whose scope contains the anonymous method declaration are said to be in the outer scope of the anonymous method.

## Events

An event is a delegate type class member that is used by an object or a class to provide a notification to other objects that an event has occurred. Event, in itself, is an action that is generated by a user or a computer. In C# you can use events to keep objects notified of the current state of another object or condition. The event keyword can be used to declare an event, as shown in the following syntax:

```
Access-modifier event type event-name;
```
