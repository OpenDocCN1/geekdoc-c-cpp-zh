
## In Depth

In a distributed computing network that contains a number of objects, such as servers, printers, and databases, it becomes difficult for users to locate and use these objects at a specific time. For this purpose, the concept of directory service was introduced. A directory service is used to store all the information required to manage the use of these objects in a centralized location, thereby simplifying the process of locating and managing these objects. A directory service is different from a directory in the sense that a directory service is both the source of the information and the technique that makes the information available to the users, whereas a directory simply stores the required information. In addition, a directory service also plays an important role in maintaining the network infrastructure of an organization, administering a system, and controlling the access to company’s information systems. From Windows 2000 Server onwards, a directory service has been introduced with a new name, Active Directory (AD).

AD stores information and data about networks and domains on Windows-based computers and servers. It contains three basic categories: resources, services, and objects in a hierarchical structure. Resources include hardware resources, such as printers and scanners; services include services of Web and email servers, and objects include users in the form of computer nodes of a domain and network.

In this chapter, you learn about AD, its structure, significance, and how to administer it. You also learn about user accounts and groups in AD. Next, you learn about the System.DirectoryServices namespace, which provides classes to access AD from an application created in .NET Framework 4.0. In the Immediate Solutions section, you learn how to create users and groups in AD and create a Windows Forms application to access these users or groups.

Let’s start by learning about the structure of AD.

### Structure of Active Directory

AD includes forests and domains in a hierarchical structure, where a forest is a collection of domains, which in turn are collections of Organizational Units (OUs). An OU is a collection of users, groups, and computers, where a user is an individual person, a group is a group of user accounts, and a computer is a specific workstation. In the structure of an AD, a forest represents its security boundary. All the AD objects, including users, groups, and resources, are stored in a flat database file. Each object stores its own name as well as the container’s name in which it is contained. Each container itself stores its own name as well as the name of its superior container, and so on, up to the root container. Therefore, the structure of AD can be viewed as a tree of containers also.

Now, let’s learn about the following components of AD:

- **Forest** — Represents a single directory containing one or more domains.
- **Domain** — Refers to a collection of OUs in a hierarchical order.
- **OU** — Refers to a collection of users, groups, and computers.
- **Domain controller** — Refers to a server running a version of Windows Server 2008, Windows Server 2003, or Windows 2000 Server operating systems and has AD installed.
- **Schema** — Provides object definitions that are used to store information in a directory. It is a single component that itself resides in the directory.
- **Data store** — Manages the storage and retrieval of data of a domain controller. It contains three layers, where the first layer provides interfaces to access a directory, the second layer provides the services to perform the operations of reading and writing data, and the third layer consists of the database itself.
- **Database** — Stores the data in a file format and it exists on the hard disk of a domain controller.

Let’s learn the significance of AD.

### Significance of Active Directory

AD provides a secure and centralized network that might span a building, city, or multiple locations across a country. It is a distributed directory service within the Windows Server 2008, Windows Server 2003 and Microsoft Windows 2000 Server operating systems. AD enables you to access various objects, including all network users, devices, and resources. It also enables you to make groups of these objects for ease of management.

Some advantages of AD are given as follows:

- **Scalability** — Enables you to scale a directory to meet any network requirement by including one or more domains with one or more domain controllers.
- **Flexible searching** — Allows you to search users and resources, such as a printer or file, on a network.
- **Data storage** — Allows you to store the data of your applications at a centralized location that is shared among applications across a Windows network.
- **Systematic directory updates** — Updates the directory data in a secure manner over a network by replicating the data between domain controllers in a synchronized way.
- **Remote access** — Allows you to remotely access or administer any domain controller connected to the Windows-based computer over a network.
- **Domain Name System (DNS) support** — Allows you to use the DNS system that provides a name resolution service to reflect organizational structure on a domain controller.
- **Single and extensible schema** — Refers to a schema of objects and rules that provide the structure requirements for AD objects. You can extend this schema by adding new types of objects or object properties.
- **Lightweight Directory Access Protocol (LDAP) support** — Allows you to use the LDAP protocol, which is an industry standard directory access protocol, to access AD objects from management and query applications. AD supports the LDAPv3 and LDAPv2 protocols.

Let’s now learn about the AD objects, users and groups.

### Exploring User Accounts and Groups

A user account in AD consists of all the information, such as the user name, password, logon hours, and the profile location, which is needed to define a user in AD. The user account helps the user to log on to a network to access resources after authenticating the user. Authenticating a user means to identify and allow the user to log in and access resources.

The user account is the primary means by which the AD network allows a user to access resources. There are the following three types of user accounts in Windows Server 2008:

- **Built-in User Accounts** — Specifies a type of account that is automatically created when you install Windows Server 2008 and AD as a standalone server. It is used to perform administrative tasks, such as managing printers and backing up files. The Administrator and the Guest accounts are examples of built-in user accounts.
- **Local User Accounts** — Specifies a type of account that is used to access the local computer only. It authenticates a user locally to gain access to the resources on that computer. It is created in the local Security Account Management (SAM) database of the computer, and not on the AD domain. These types of accounts do not have domain access. This implies that a local account configured on one server cannot be used to access resources on another server.
- **Domain User Accounts** — Specifies a type of account that is used to gain access to the AD resources, such as folders and printers. The account information is stored in the AD database.

While creating a new user account, you should remember the following points:

- Rename the administrator account only if there are chances of data corruption.
- Ensure to set a strong password. The length of the password should be of seven characters. The password should be a combination of uppercase letters, lowercase letters, numbers, and non-alphanumeric characters.
- Do not distribute the administrator password and limit the knowledge of the password to only a few people.
- Do not use the administrator account for the non-administrative tasks. You can use the Guest account for the non-administrative tasks.
- Rename the Guest account after enabling it for use.
- Do not allow a blank password for the Guest account, which is the default behavior of the Guest account.
- Avoid dictionary words, names, and date of birth as passwords.

A group is a collection of user accounts or computers that are managed as a single object. The users and computers that belong to a group are known as group members. Groups are helpful as you can assign rights and permissions collectively to a group rather than assigning permissions to each user individually. Therefore, the administrators create groups to make tasks, such as assigning permissions and rights, easier. ### Administering Active Directory

The system administrator has the responsibility and privilege of entering new data, updating, and configuring a directory. There are some administration tools that are used for data management. These tools are as follows:

- **Microsoft Management Console (MMC)** — Helps you to perform the management tasks, including adding and managing multiple domains, servers, and users. The MMC console hosts tools and displays these tools in the form of consoles. These tools are applications that are built using one or more snap-ins. The MMC consoles are saved as .msc files and can be sent by e-mail, shared in a network folder, or posted on the Web. These consoles can also be assigned to users, groups, or computers with system policy settings.
- **Snap-ins** — Handle network administration tasks. Some commonly used snap-ins related to AD are as follows:
  - **The Active Directory Users and Computers snap-in** — Manages resources, such as users, groups, computers, shared folders, and printers. An AD administrator uses this snap-in to perform most of the administrative tasks.
  - **The Active Directory Sites and Services snap-in** — Manages administrative activities, such as site replication, network topology, and related services.
  - **The Active Directory Domains and Trusts snap-in** — Configures and maintains trust relationships and also configures forest and domain functional levels.
