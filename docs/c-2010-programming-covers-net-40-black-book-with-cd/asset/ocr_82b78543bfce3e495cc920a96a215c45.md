# Exploring ADO.NET Entity Framework

ADO.NET Entity Framework does not support direct mapping of object-oriented classes and properties to relational tables and columns. It maps relational tables, columns, and foreign key constraints to entities and relationships in conceptual models. Now, let’s understand the architecture of Entity Framework.

ADO.NET Entity Framework is designed to support data-centric applications and services, and provides a platform for programming, which raises the level of abstraction from the logical relational level to the conceptual level. ADO.NET Entity Framework supports code that is independent of any particular data storage, such as the SQL Server engine or a logical schema, by enabling the developers to work with data at a greater level of abstraction. Conceptual models are generally used as tools for capturing knowledge of data and explaining the requirements of an application that are usually discussed at early stages of a project. Entity Framework provides the capability to normalize the entities and relationships to tables with foreign key constraints. Therefore, it makes an application capable of avoiding hard-coded dependencies on a particular data engine or even a particular logical model. Figure 22.1 shows the architecture of Entity Framework:
