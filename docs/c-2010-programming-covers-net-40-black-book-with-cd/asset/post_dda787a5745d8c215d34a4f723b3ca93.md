## Working with Custom Routed Events

WPF 4.0 offers numerous routed events that traverse from the source element through the element tree in a WPF application. However, you may need to create custom routed events in certain situations, such as when you want to create custom controls or elements. Creating routed events involves declaring a static read-only field, registering the field as a routed event, and finally wrapping the routed event as a CLR event.

Let's now create a standalone WPF application named FrameRoutedEvent (also available in the CD) by performing the following steps:

+   1. Create a new WPF Application, FrameRoutedEvent.
+   2. Add the following code snippet in the code-behind file of the MainWindow window, that is, the MainWindow.xaml.cs file:

```
public partial class Frame : Border
{
public static readonly RoutedEvent OnMouseHoverEvent; /*declaring the routed event field*/
static Frame() {
    OnMouseHoverEvent = EventManager.RegisterRoutedEvent("OnMouseHover",
    RoutingStrategy.Bubble, typeof(RoutedEventHandler), typeof(Frame)); /*registering the routed event*/
}
public event RoutedEventHandler OnMouseHover /*CLR wrapper for routed event*/
{
    add {
        AddHandler(OnMouseHoverEvent, value);
    }
    remove
    {
        RemoveHandler(OnMouseHoverEvent, value);
    }
}
protected override void OnMouseMove(MouseEventArgs e)
{
    RaiseEvent(new RoutedEventArgs(Frame.OnMouseHoverEvent)); /*Raising the routed event*/
}
}
```

In the preceding code snippet, a partial class named Frame is created by inheriting the Border class. In the Frame class, there is a static read-only field named OnMouseHoverEvent, which is of RoutedEvent type. Note that you need to suffix the actual name of the routed event with the word Event while declaring the field. In the static constructor of the Frame class, the OnMouseHoverEvent field is registered as the OnMouseHover routed event by using the RegisterRoutedEvent() method of the EventManager class. The RegisterRoutedEvent() method takes four parameters in this case. The first parameter is the actual name of the event (that is, without the Event suffix). The second parameter is the routing strategy you want to employ for the routed event, which in this case is the bubbling strategy. The third parameter is the type of handler for the routed event and the fourth parameter is the type of owner of the routed event, which in this case is the Frame class.

After registering the routed event with the WPF event system, you need to wrap the routed event in CLR events. You do this by creating a CLR event that has the same name as the routed event and implement its add and remove event accessors. In the preceding code, the CLR event named OnMouseHover of type RoutedEvent is created in the Frame class. The CLR event contains the add and remove event accessors in which the AddHandler() and RemoveHandler() methods are called, respectively. The AddHandler() and the RemoveHandler() methods take the routed event field identifier as the first argument and a value as the second argument.

In the Frame class, you may also notice that the OnMouseMove() method is available in the Border class and overridden to raise the OnMouseHover routed event. The RaiseEvent() method is called with an object of type RoutedEventArgs.
