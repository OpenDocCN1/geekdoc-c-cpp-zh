Notice that the `Display` object doesn't have to know anything about the `UpOrDown` object, but the `UpOrDown` object needs to know about the `Display` object. Coming up next, we'll turn this on its head when we make the `Display` object an observer.

# ## 20.3 Introducing an Observer

With the traditional target-action approach, the `UpOrDown` object had a handle to the `Display` object and sent the message `updateDisplay:` to that object. With KVO, the observer knows who it is watching. The observed object just sends out a message when the state has changed—all registered observers will get the notification.

In our example, the `Display` object will need to send a message to the `UpOrDown` object to register as an observer. This means that our `Display` object will need a handle to the `UpOrDown` object. At this point, you have a relationship that looks like this:
