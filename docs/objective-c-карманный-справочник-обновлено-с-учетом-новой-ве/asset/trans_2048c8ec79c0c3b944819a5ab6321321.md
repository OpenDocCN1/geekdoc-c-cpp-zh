# 断言期望 (Asserting Expectations)

```objc
@interface IgnoreAsserts : NSAssertionHandler
@end
@implementation IgnoreAsserts
-(void)handleFailureInFunction:(NSString*)functionName
	file:(NSString*)fileName
	line:(NSInteger)line
	description: (NSString *)format, ...
{
  NSLog(\@"Ignoring assert on line %d of %@ in %@", line, functionName, fileName);
}
@end

int main(void)
{
  [[AutoreleasePool new];
  [[NSThread currentThread] threadDictionary
    setObject:[IgnoreAsserts new] autorelease
    forKey:NSAssertionHandlerKey];
  NSAssert(1 == 2, @"This might not be true");
  return 0;
}
```

来自 assert.m

在代码中，标准库提供了 `assert()` 宏，当谓词参数评估为假时，它会记录消息并调用 `abort()`。Objective-C 的版本稍微更有一些。

Foundation 提供了两个宏：`NSAssert()` 和 `NSCAssert()`。如果你在使用 C99（你应该这么做），那么这些是可变的；否则你需要使用像 `NSAssert()` 这样接受固定数量参数的变体。`NSAssert()` 引用了 `self`，因此只能在 Objective-C 方法体内部使用。`NSCAssert()` 可以在 C 函数中使用。与 C 变体不同，当断言为假时它们不会中止程序。相反，它们会向每个线程的断言处理器对象发送消息。该对象默认是 `NSAssertionHandler` 的实例，当在你触发断言时，它会抛出一个 `NSInternalConsistencyException`。你可以捕获它并恢复，但大多数情况下，它会到达栈顶并导致程序中止。

如果你想实现其他行为，可以创建 `NSAssertionHandler` 的子类，并重写一个或两个断言处理方法。这个示例忽略了 C 函数中的断言，仅在遇到它们时记录消息。


想要重写这一点相当是不寻常的，但确实有一些很好的理由。最显而易见的之一是错误报告。当遇到断言时，意味着你的程序发生了严重的错误。你可能想要收集一些关于导致此情况的信息，并将其上传到错误跟踪系统，而不是直接崩溃。

# 记录调试消息

```objc
- (void) log {
  NSLog("%s:%d:%s (%@) Log message", __FILE__, __LINE__, PRETTY_FUNCTION__, self);
}
```

来自 nslog.m
我们已经在很多代码在使用 `NSLog()` 函数。当你在终端中运行应用程序时，传递给 `NSLog()` 的消息将发送到标准错误流。在 OS X 上，图形应用程序中的 `NSLog()` 将消息发送到系统控制台。在带有 GNUstep 的 Microsoft Windows 上，它们发送到系统事件监视器。
`NSLog()` 函数写入一个格式化字符串，前面带有日期、时间、进程名称和进程 ID。当你在格式化字符串中使用 `%@` 格式说明符时，它使用与调试器完全相同的方法来获取对象的字符串表示。

# Objective-C 运行时 (Runtime)

正如我在书开头所说，一个 Objective-C 实现由两部分组成：编译器和运行时库。编译器获取源代码并将动态部分转换为对运行时库的调用。

运行时库是用 C 编写的，这意味着它是用 Objective-C 的子集。运行时库的所有接口（包括由编译器生成的代码调用的接口）对 Objective-C 代码都是可见的。

Objective-C 中所有动态的内容由运行时库实现。最显而见的例子就是消息发送（message sending）。当你发送消息时，运行时负责决定由谁来处理它。

这并不是运行时库的唯一责任。它还处理该语言所有的内省（introspection）功能。它跟踪所有的类元数据并将其暴露给程序员。

当你使用键值编码（key-value coding）时，你是在间接使用运行时查找方法。

# 按名称发送

```objc
id obj = [NSObject new];
sel = NSSelectorFromString("release");
IMP release = [obj methodFor:sel];
release(obj);
```

来自 methodName.m
Objective-C 方法是通过消息发送调用的 C 函数。具体实现方式在运行时之间有所不同。在 NeXT 和 Apple 运行时，简单的消息发送是通过 `objc_msgSend()` 实现的。

遗憾的是，这不是你需要的唯一函数。在 GNU 运行时，这要简单得多。没有 `objc_msgSend()` 函数。相反，你调用 `objc_lookup()` 然后调用返回的结果。

这种跨运行时的最简单的方法是使用 `NSObject` 的 `-methodFor:` 方法。它返回一个指向方法的指针，你可以调用它。它接受两个参数：接收者和选择器。

这几乎足够按名称调用方法了。缺失的部分是将字符串转换为选择器的机制。`NSSelectorFromString()` 函数正是这样做。它接受一个 `NSString` 作为参数并返回一个选择器。你可以将其传递给 `-methodFor:`，作为返回函数的第二个参数。

# 按名称查找类

```objc
Class nsview = NSClassFromCString("NSView");
if (Nil == nsview)
{
    NSLog("未链接 AppKit");
}
else
{
    id view = [nsview new];
    NSLog("View: %@", view);
}
```

来自 weakClass.m
运行时的职责之一是存储所有已加载类的表。你可以遍历此表，逐个查看类，或者可以使用它按名称查找类。

后者对于实现弱类引用（weak class references）特别有用。这些在现代 Apple 运行时中被直接支持，但支持尚未通过语言暴露，因此并没有特别有用。弱类引用的想法是你可以可选地使用某个类。

例如，你可能会在一个框架中编写一些使用 Foundation类的代码，如果链接了 AppKit 的话，就可以使用 AppKit 类。这样该框架就可以任何有 Foundation 实现的地方运行，但只要有 AppKit 特性就会利用它们。你也可以使用这种机制来避免对第三方框架的依赖。
