
此示例使用一个公共类和若干支持该属性的私有子类。你可以交替使用这些类的实例，至少在存储该键时如此。更重要的是，你可以使用类似 `KeyIV` 或 `KeyFallback` 的类进行原型设计，以后切换到其他实现。

回退方法（fallback method）在原型设计时特别有用。当你开始工作时，创建一个私有字典实例变量，并通过 KVC 访问对象上的所有属性。一旦你确定了类真正需要的属性，你就可以将回退实现替换为一组访问器（accessors），并作为一个独立步骤，将 KVC 调用替换为直接的消息发送（direct message sends）。

你可能已经注意到这个示例中的一个点是，KVC 只处理对象，但实例变量是一个 `int`。以某种方式，这仍然可以工作。这是因为 KVC 执行了自动装箱（auto-boxing）。我们通过将 `@"12"` 作为参数传递给 `forKey:` 来设置此属性：KVC 代码在发现属性为整数类型后，向字符串对象发送了 `-intValue` 消息。

在反方向，它构造了一个封装了原始值的 `NSNumber`。如果实例变量或访问器方法使用对象类型，则这段代码会被跳过。注意，KVC 只访问运行时类型信息，并且所有对象类型在类型编码中都被编码为 `"@"`。

这意味着你可以使用 KVC 将 `NSString` 实例设置为声明为 `NSArray` 的实例变量的值。当你尝试这样做时，KVC 不会生成任何错误，编译器也不会产生错误。然而，接收者在下一次向字符串发送诸如 `-objectAtIndex:` 之类的消息时将收到一个异常。

如果你正在为对象类型编写 KVC 访问器，你可能想要添加一个 `assert` 语句来检查该对象是否具有兼容的类。

## 理解键路径 (Understanding Key Paths)

到目前为止，我们查看了获取和设置单个键值的方法。这非常有用，但它并不能完全展示 KVC 的全部灵活性。

我们使用 KVC 完成的大部分操作都可以很容易地完成。如果你想让一个对象访问另一个对象的特定属性，且不想硬编码它，你只需要存储一个选择器（selector）并使用标准的 Objective-C 消息发送机制来调用它。

如果属性存储在那个对象上，这种方法运行良好，但如果你想要一个间接属性（indirect property）会发生什么？你可以存储一个选择器数组，并使用每个选择器来获取中间对象，但这太繁琐了。

通过 KVC，你可以使用键路径（key paths）。这些包含键名的简单字符串，用点隔开。如果你想访问对象的属性的属性，可以使用键路径在单次操作中完成。

**注意：** 访问声明属性的句点表示法（dot notation）看起来与 KVC 表示法非常相似，极很容易混淆两者。这很遗憾，因为它们完全无关。句点表示法会生成指向访问器方法的消息发送，这些方法直接接收键路径。接收键路径的 KVC 方法是更高层次的抽象。这就是为什么句点表示法广不受喜的原因之一。

遗憾的是，这种相似性是故意的。在公开发布之前，Apple 员工使用 KVC 术语来引用声明的属性，两者可能本意联系得更紧密。

例如，如果你有一个显示人物信息的视图，你可以使用 `@"father"` 和 `@"mother"` 键路径连接家族树中的副本。然后你可以在显示祖祖关系的某个中使用同一个视图，并使用 `"father.mother"` 键路径，依此类推。

键路径在 Cocoa 绑定（bindings）中被大量使用。这些是连接模型与视图的通用控制器类。

## 键 (Observing Keys)

```objc
+ (void)observeValueForKeyPath:(NSString*)keyPath
object:(id)object
change:(NSDictionary*)change
context:(void*)context
{
    NSLog("%@.%@ is now %@", object, keyPath,
         [change objectForKey: NSValueChangeNewKey]);
}

+ (void)watchChange {
    MutableDictionary *dict = [NSMutableDictionary new];
    [dict addObserver:self
             forKeyPath:@"akey"
               options:NSKeyValueObservingOptionNew
               context:NULL];

    [dict setObject:@"set as object"
               forKey:@"akey"];

    [dict removeObserver:self
            forKeyPath:@"akey"];
}
```
源自：kvo.m

拥有统一的设置和获取键的机制是有用的，但它并不特别。KVC 的真正力量来自于 KVO，它允许你监控键的变化。

绑定机制在很多情况下使用 KVC 和 KVO 来消除了对控制器的需求。当视图想要修改模型时，它使用 KVC。当模型发生变化时，视图收到来自 KVO 的通知并更新自己以反映变化。这两种密切相关的技术的结合，允许你在对象之间建立紧密的连接，而不会导致设计上的紧密耦合。

注册为 KVO 观察者非常像注册接收通知（参见第 16 章），但有几点不同。最重要的区别之一是，KVO 通知始终发送到同一个方法。本节开头示例代码中的第一个方法展示了它应该是什么样的。

在这个示例中，它是一个类方法。大多数时候，你将使用实例方法，但重要的是要在 Objective-C 中类也是对象，因此你可以在几乎任何通常会使用对象的地方使用它们。这个实现非常简单；它只是记录了该键的新值。第二个方法显示了如何注册通知。通知方法中的 `change` 参数是一个字典，在当前版本中，它包含了键的新值，因为这是我们请求的全部。

该方法中的 `options` 参数是一个位域。你可以请求只需新值、只需旧值，或两者都要。你还可以在更改之前之后请求通知。

这允许你轻松地执行诸如记录对对象的更改的任务，对于实现撤销（undo）很有帮助。如果你的模型对象符合 KVO 规范，你可以保存旧值，以后使用 KVC 将其恢复。这种实现撤销的逻辑可以与模型的实现细节完全解耦。

## 确保符合 KVO 规范 (Ensuring KVO Compliance)

```objc
[self willChangeValueForKey:@"akey"];
aKey = 12;
[self didChangeValueForKey:@"akey"];
```
自：kvo2.m

KVO 作为 Foundation 的一部分并不是魔法。如果你使用 KVC 访问器设置键，向观察者发送通知是非常简单的。如果你直接设置实例变量会发生什么？遗憾的是，答案很简单：什么都不会。

直接设置实例变量只是写入内存。没有方法可以自动检测内存中的值何时被修改。这意味着你必须在本节开头所示的调用来封装对实例变量的直接访问。

这些调用将触发 KVO 通知。注意，如果你调用访问器方法，则不需要发送这些消息。

实现 KVO 的代码相当复杂，并使用了 Objective-C 的一些高级特性。当你为某个键注册观察者时，该键的设置方法将被替换为一个特殊版本，该版本将处理通知。

KVO 可能是 Foundation 框架中看起来像魔法的部分。值得记住，KVO 所做的任何事情你的代码并非做不到。它不依赖于任何未公开的接口、编译器修改或类似的技巧。如果你需要，你可以在自己的代码中实现等的功能。你可以查看 GNUstep 的实现来了解如何这样做。

在 GNUstep 和 OS X 上，KVO 机制都是使用 isa 交换（isa-swizzling）实现的。这是一种技巧，将对象的 isa 指针切换到指向另一个类。
