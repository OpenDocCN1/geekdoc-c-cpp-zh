在 OS X 上，文件系统的布局是非常明确的。你可能会硬编码路径并期望它们正常工作。但如果你将代码移植到其他平台，你会发现事情会发生严重的损坏。

这是 OpenStep 程序员经常遇到的问题之一。例如，在 Solaris、OPENSTEP 和 Windows NT 之间移植代码，需要为每个平台更改许多硬编码路径。

在 Apple 购买 NeXT 后，他们发布了新版本的 OPENSTEP，带有一个 MacOS 兼容层以及一个名为 Rhapsody 的新用户界面。它使用了与 OPENSTEP 相同的 NeXT 文件系统层次结构，并在根目录下包含一个 `/NeXT` 文件夹，该文件夹包含了层次结构中非 UNIX 风格的部分。

随着 Rhapsody DR2，Apple 对目录布局进行了一些重大更改，并引入了现在 OS X 用户熟悉的布局。为了方便使用，并支持 Windows 上的 YellowBox (Cocoa)（该产品在不久后就被停止了），他们引入了 `NSSearchPathForDirectoriesInDomains()` 函数。

此函数返回一个用于特定用途的目录数组。当你调用此函数时，第一个参数描述了你想要的目录类型。这可能是一个应用程序目录、库目录等。第二个参数是文件系统域（domain）。

OS X 像 OPENSTEP 一样将文件系统层次结构划分为若干域，这些域的内容大致相同，但用途不同。这些域是有顺序的，因此你应该优先使用高优先级域中的文件。四个域如下：

- **User (用户)**：该域位于用户主目录内。这里的文件对用户私有，并完全由用户控制。
- **Local (本地)**：包含机器本地文件的域。在 OS X 上，这包括类似 `/Library` 的目录，该目录可以由本地系统管理员修改。
- **Network (网络)**：在该域中看到任何内容是非常稀见的。你将在独立机器或异构网络中的的机器上看不到它。它用于由网络管理员控制的目录。
- **System (系统)**：最后一个域包含系统文件。通常情况下，你永远不应该在该域中的任何位置写入内容，尽管你可以从中读取。你做的任何修改都可能在用户下次更新系统时被撤销。

## 线程

Objective-C 中的线程封装在 `NSThread` 对象中。创建线程有两种方法。第一种类似于标准方法，而第二种旨在类似于 Java。

当你使用 `NSThread` 创建线程时，可以设置它的优先级。最常见的做法是创建一个创建一个释放池。创建线程在 Objective-C 中是一个相对昂贵的操作，就像在 C 中一样。进程必须为线程栈分配内存，创建调度的所有内核数据结构，并为线程本地存储分配额外空间。因此，在创建线程后保持它们运行是一个好主意。

在线程中创建运行循环（run loop）是实现此点的良好方法。你可以注册定时器触发，监控文件描述符的新数据，并在新线程中使用事件驱动的编程风格。POSIX 定义了线程的两种竞争范围。OS X 只实现了系统范围。

`NSThread` 以类方法和实例方法实现了 `threadPriority` 和 `setPriority`。发送给类时，它们控制当前线程的优先级；发送给实例时，它们控制该对象封装的线程的优先级。

线程的优先级决定了它将获得多少 CPU 时间以及在获得访问 CPU 的权限之间等待多久。通过低级 POSIX API 控制线程优先级，你还可以设置调度策略。执行这些操作的函数都是 POSIX 实时扩展的一部分，该扩展还提供了信号队列等。这些尚未被 Objective-C API 暴露（目前）。

使用此 API 设置的优先级是 0 到 1 之间的双精度浮点值。这些值将被缩放到调度器理解的某些整数范围，所以你应该记住微小的差异会被四舍五入。
