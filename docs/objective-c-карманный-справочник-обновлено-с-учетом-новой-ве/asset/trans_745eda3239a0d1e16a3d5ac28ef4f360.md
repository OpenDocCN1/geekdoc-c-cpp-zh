

## 第 9 章：使用属性列表

存储新版格式支持的所有内容。在 OS X 中，Apple 引入了 XML 和二进制属性列表格式。XML 格式极其冗长，但它的优点是它可以被其他兼容 XML 的工具解析，并可以嵌入到其他 XML 文档中。

二进制表示的解析速度非常快且非常密集，但由于是二进制格式，它不是人类可读的。

其他语言的一些库可以处理属性列表。WindowMaker 中的 WINGS 库可以读写属性列表，NetBSD 包含的库也是如此。Apple 的 Core Foundation 框架及其开源的 CFLite 库也可以从 C 代码中使用它们。

## 在属性列表中存储集合

```objectivec
NSArray array = [NSArray arrayWithObjects:
@"array", @"containing", @"string",n@"objects", nil];
[array writeToFile:@"example.plist" atomically:
NO];
MutableArray *cycle = [array mutableCopy]; own[cycle addObject:cycle];
[cycle writeToFile:@"failure.plist" atomically:
NO];
```
源自：writeeplist.m

数组和字典类实现了 -writeToFile:atomically: 方法。这些方法允许你非常方便地使用默认的属性列表格式将集合的内容导出到文件中。这些方法并不是魔法。只有当集合不包含任何无法存储在属性列表中的类型时，它们才会生效。如果你将 YES 作为第二个参数，该方法将确保磁盘上的表示始终保持一致。它会将属性列表写入一个临时文件，并在写入完成后重命名该文件。

运行本节开始的代码将生成一个 example.plist 文件，该文件包含一个数组作为根元素，并在其内部有四个字符串。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList.dtd">
<plist version="1.0">
  <array>
    <string>array</string>
    <string>containing</string>
    <string>string</string>
    <string>objects</string>
  </array>
</plist>
```
源自：example.plist

在当前版本的 OS X 中，这种方法将使用 XML 属性列表格式。如你所见，这非常冗长。旧的 OpenStep 属性列表格式对数组使用括号，对字符串使用双引号，因此体积会小不到的一半。将其转换为二进制格式可以将文件大小从 294 字节减少到 82 字节。

对于如此小小的属性列表，这种的减少是无关紧道的。两种格式都可能放进磁盘上的单个分配单元中，因此它们将占据相同的磁盘空间。两者的解析时间都微乎其微。

然而，对于较大的属性列表，情况并非如此。例如，Safari 将你的历史记录存储在二进制属性列表中。目前，我的记录有 15MB。如果我将其转换为 XML 格式，它会变成 34MB。解析开销也会增加，无论是在 CPU 时间还是内存占用方面。

遗憾的是，集合类不会以默认（XML）格式以外的格式写入自身的属性列表版本。相反，你必须使用 NSSerialization 类，我们将在接下来的节中介绍它。

属性列表格式都是分级结构的。它们不支持写入循环数据结构。此示例中的第二个数组包含一个指向自身的指针。将此内容写入属性列表时的行为是未定义的。在 OS X 上，只有递归指针之前的元素会被存储在文件中。其后出现的任何对象都会被忽略。

## 从属性列表中读取数据

```objectivec
NSArray *array =
[NSArray arrayWithContentsFile:
@"example.plist"];
NSData *data = [NSData dataWithContentsFile:
@"example.plist"];
NSMutableArray *mutable =
[PropertyListSerialization
propertyListFromData:data
mutabilityOption:PropertyListMutableContainers
format:NULL
error:NULL];
[mutable classDescription:@"should have mutable array"];
[[mutable objectAtIndex:0]];
```
源自：readplist.m

读取属性列表有两种方法。第一种是使用集合类的方法，正如我们刚刚查看的写入方法的反向操作。这听起来很容易，但存在一些复杂性。最重要的一点是属性列表并没有存储关于可变性的信息。例如，NSString 和 NSMutableString 以相同的方式存储的。

当你读取属性列表时，你应该得到哪种？如果你向 NSArray 类发送 arrayWithContentsOf: 消息，你会得到一个不可变数组。如果你向 NSMutableArray 发送相同的消息，你会得到一个可变数组。

如果你想读取可变对象，你需要使用 PropertyListSerialization。该类处理读取和写入属性列表，并比各种集合类提供了更细粒度的控制。

> **注意：** 如果你阅读 Apple 最新文档，你会发现我们使用的方法被标记为弃用。这是因为它在引入 serialization 之前就已经存在。

当你使用该类读取属性列表时，可以将可变选项作为参数传递。三种可能的选项。默认情况下对象是不可变的。本节开始使用的选项走向极端，使所有内容可变。第三种选项介于之间：它使容器可变，但其他对象（字符串、数字等）不可变。当你通过这种方式读取属性列表时，属性列表序列化类会告诉你格式是什么。

## 转换属性格式

```objectivec
NSString *file =
[NSString stringWith8String:argv[1]];
NSData *data = [NSData dataWithContentsFile:file];
PropertyListFormat fmt;
id plist = [PropertyListSerialization propertyWithData:data
options:0
format:&fmt
error:NULL];
if (fmt == NSPropertyListListBinaryFormat_v1_0) {
return 0;
}
data = [NSSerialization dataWithPropertyList:plist
format:NSPropertyListListBinaryFormat_v1
options:0
error:NULL];
[data writeToFile:file atomically:NO];
```
源自：makebinaryplist.m

在 OS X 上，你无法以 OpenStep 格式写入属性列表，但仍然可以使用另外两种形式。通常情况下，你应该使用二进制格式存储私有数据，并将 XML 格式用于用户可能用其他工具编辑的内容。

这些不是硬性规定。格式的意义在于你可以在表示之间进行无损转换，因此你可能会随处使用二进制格式——因为它更密集且解析更快——并期望用户在想要修改属性列表时进行转换。

如果你的程序不是每次运行时都修改属性列表，那么在加载它时检查格式是否为二进制是值得的，如果是则按这种格式重新写入。
