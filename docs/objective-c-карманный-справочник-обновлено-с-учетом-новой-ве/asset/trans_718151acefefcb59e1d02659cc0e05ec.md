

## 控制线程优先级

较低优先级的进程运行。如果你将线程优先级设置为大于 0.5，请记住这会对系统的其他部分产生不利影响。这仍然不会导致完全的饥饿。在 OS X 10.6 中，对于纯粹的 CPU 密集型任务，最高线程优先级获得的 CPU 时间略高于最低优先级分配的时间的一倍多。大多数任务都会涉及一些时间等待从磁盘读取数据。处于阻塞状态的线程无论其优先级如何，都不会消耗任何 CPU 时间。

OS X 的调度策略与传统的 UNIX 模型相反，在传统模型中，只有超级用户才能提高进程的优先级。有趣的是，在 OS X 的最新版本中，线程优先级对线程获取 CPU 时间的影响实际上大于拥有该线程的进程优先级。这意味着，虽然你不能提高进程的优先级，但可以通过提高进程中所有线程的优先级来实现相同的效果。

防止普通用户增加进程优先级的原始目的是防止一个用户获取不公平的 CPU 时间。OS X 系统倾向于单用户机器，因此这个问题并不那么严重，但你仍然可以夺取同一用户下更重要任务的处理器时间。例如，实时视频捕获对性能非常敏感，如果你的程序决定将其优先级设置为足够高，导致捕获应用程序丢帧，用户可能会非常恼怒。

设置线程优先级时要体贴。通常，你只应该使用 0 到 0.5 之间的范围。只有在绝对没有其他选择的情况下，才将线程设置为高于默认水平。不要仅仅因为你正在执行某些 CPU 密集型操作并希望它运行得快就这样做。

## 同步线程

```
static NSLock *lock;
static NSMutableArray *messages;
void recordLogMessage(NSString *msg)
{
  [lock lock];
  @try
  {
    [messages addObject:msg];
    NSLog("%@", msg);
  }
  @finally
  {
    [lock unlock];
  }
}
```
来自：lock.m

你可以通过多种方式同步两个线程。执行此类同步的类都遵循 NSLocking 协议。它定义了两个方法：-lock 和 -unlock。

简单的锁类是 NSLock，它实现了互斥锁（mutex）。一次只能有一个线程锁定它，因此向它发送 -lock 消息将导致任何其他向同一对象发送 -lock 消息的线程阻塞，直到你发送了相应的 -unlock 消息。

这对于保护短的临界区域很有用。对于较长的临界区域，NSRecursiveLock 通常更有用。如果你在同一个线程向 NSLock 发送两个 -lock 消息，就会导致死锁。你可以向 NSRecursiveLock 发送任意数量的 -lock 消息，只要发送相同数量的 -unlock 消息即可。这对于从已获取锁的代码以及未获取锁的代码调用的方法非常有用。

传统上讲，这些类的问题在于它们与异常处理结合得并不好。如果你获取了锁然后调用了抛出异常的内容，就会出现问题。锁将永远不会释放。

当 Apple 引入新的异常处理关键字时，它们也引入了 @synchronized。它会在任意对象上锁定，并确保在抛出异常时释放锁。

总的来说，使用这个关键字是一个坏主意。尽管 Java 程序员对其很熟悉，但其实现非常低效。它需要将锁与对象关联，而且即使在不理想的情况下也总是使用递归锁。你可以通过确保在 @finally 块中发送 -unlock 消息来实现相同的效果。

如果你确定所有调用的方法或函数都不会抛出异常，就可以避免使用 @try 和 @finally 块，但在 GNU 和现代 Apple 运行时，它们没有任何运行时开销。

## 存储线程特定数据

```
NSMutableDictionary *threadDict = [[NSThread currentThread] threadDictionary]; [threadDict setObject:@"default" forKey:@"NewKey"];
```
来自：threadDict.m

一旦你有了线程，你通常想为线程私有地存储一些数据。Cocoa 中这方面的例子是当前图形上下文，它必须对任何绘图代码可用，但不能在线程之间共享。

通常，你使用 `pthread_set_specific()` 函数来实现这一点，它存储与当前线程关联的指针。这通常通过将内存区域的地址存储在寄存器中，并使用该区域起始的固定偏移量来处理每个线程特定数据来实现。这意味着你需要为每个线程中的每个线程本地指针留出空间，即使你只将其中一个设置为非 NULL 值。

如果 Cocoa 像这样存储单个图形上下文，那么每个线程都需要一个字大小的空间，尽管大多数程序只需要在一个或可能两个线程中拥有有效的图形上下文。

解决此问题的方案是线程字典（thread dictionary）。这是一个与线程关联的可变字典。你每个线程只需要一个字大小的空间，但你可以在其中存储任意数量的对象。只有与给定键关联了值的线程才需要空间来存储它。

通过向当前线程发送 -threadDictionary 消息访问线程字典。然后你可以像操作其他字典一样操作它。当线程退出时，字典会被销毁。由于字典保留其参数，这意味着从线程引用的任何对象将在析构函数运行后被释放。你可以利用此在线程退出时运行代码，但不建议这样做。线程在退出之前会发布 NSThreadWillExitNotification，所以如果你想运行某些代码，只需观察它即可。

**注意：** 在大多数平台上，你可以使用 `__thread` 关键字，这是一个将变量存储在线程本地存储 GCC 扩展。Darwin 加载器不支持线程局部，因此在 OS X 上是不可能的。这可能会很快改变，因为类似的功能已经在 C 和 C++ 标准的后续版本中了。
