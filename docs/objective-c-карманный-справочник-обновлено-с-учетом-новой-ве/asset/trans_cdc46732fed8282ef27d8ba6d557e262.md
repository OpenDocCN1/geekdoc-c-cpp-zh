
向它发送初始化消息，你将获得两个私有子类的一个实例。

```objc
@implementation IntPair
-( (Pair*)initWithInt:(int)a int:(int)b {
    first = a;
    second = b;
    return self;
}
-(NSString*)description {
    return [NSString stringWithFormat:@"%d, %d",
	first, second];
}
-(float)firstFloat { return (float)first; }
-(float)secondFloat { return (float)second; }
-(int)firstInt { return first; }
-(int)secondInt { return second; }
@end
```

这些具体子类都非常简单。它们都声明了两个实例变量：一个是 int，另一个是 float。它们各自提供一个单一初始化器（该初始化器仅从父类调用），然后它们重写了方法。这个示例没有在父类中提供任何实用的方法。在实际实现中，根据这里显示的四个方法，可能会在父类中实现比较或算术方法。或者，它们可能会在单独的分类（category）中提供。

类簇（class cluster）隐藏了实现的所有细节。你可以更改私有子类的任何方面，而无需修改甚至重新编译使用它们的代码。这就是为什么 Objective-C 中的代码复用比 C++ 等语言更常见的原因之一。在 Objective-C 中，很容易编写出具有公共接口和私有实现的代码，而使用它的代码不需要依赖于实现的任何方面。

子类类簇通常需要实现少数原始方法。其他方法都是基于这些核心功能实现的。我们将在第 7 章的“集合子类”部分详细介绍。

例如，如果你想创建一个 NSString 的子类，必须实现 -length 和 -characterAtIndex::。该类中的所有其他方法只是调用这两个。更高效的实现还会实现 -getCharacters:range::。

## 使用运行循环

```objc
[NSRunLoop currentLoop] run];
```

来自：timer.m

定义大多数非复杂 Objective-C 程序结构的设计模式是运行循环（run loop）。通常，运行循环等待来自一个或多个事件源的数据，然后响应这些数据执行代码，提供了一种事件驱动的编程模型。

Foundation 框架在 NSRLoop 类中提供了运行循环的实现。如果你正在编写应用程序，通常会自动为你创建一个该实例。你也可以在命令行工具中显式地创建一个。

应用程序的主运行循环监听来自窗口服务器的事件，对应于按键、鼠标移动、触摸事件等。其他各种类会隐式地向运行循环添加事件源。例如，我们将在第 8 章介绍的 NSTimer 类会向运行循环添加定时器事件源，从而允许你在特定时间执行某些操作。

第 16 章介绍的通知机制允许你通过运行循环在程序内部传递任意事件的通知，你还可以通过 NSFileHandle 注册文件描述符上的活动通知。

运行循环本身与内存管理有关。每次运行循环迭代都有自己的自动释放池（autorelease pool）。这意味着在运行循环迭代期间发送 -autorelease 消息的对象将在迭代结束时被销（除非在其他地方保留）。由于这一点，加上运行循环用于递送来自用户输入的事件，最好将单个运行循环迭代中执行的工作尽可能减小。在大多数程序中，你不需要直接与运行循环交互。它在后台运行，而其他类提供了更方便的接口。

## 数字

Objective-C 和 Smalltalk 之间的一个大区别是 Objective-C 继承了全范围的原始（非对象）C 类型。这些按 own从小到大排列是 **char, short, int, long 和 long long** 整数，带有有符号和无符号变体，以及两种浮点类型：**float** 和 double。它们的行为与 C 中完全相同，并包含完整的类型提升规则。你还会发现 Objective-C 编译器支持 **long double** 类型，它是取决于架构的。

注意，这与 Java 非常相似，在 Java 中你只有少量的非对象类型可选，但存在一些非常重要的区别。在 Java 中，*固有类型（intrinsic types）*被定义为固定大小。在 C 中，它们被定义为具有最小精度。例如，规范说 **int** 具有“执行环境架构建议的自然大小”，而在 Java 中，它被显式地定义为“32 位有符号补码整数”。

除了原始类型外，C 还支持通过 `typedef` 关键字为现有类型定义新名称。最常见的原因是规范没有要求任何标准类型具有特定大小，只需每种类型至少与前一个一样大。特别是，目前部署的平台中 int 可能是 16 位、32 位或 64 位，因此你不能依赖它们的任何特定大小。

OS X 支持 IL32 和 LP64 模式。这种简写用于描述哪些 C 类型具有什么大小。IL32 意味着 ints 和指针是 32 位。LP64 意味着 longs 和指针是 64 位。将指针转换为整数是一个严重的问题。C99 引入了 `intptr_t` typedef，它是指针的大小。Apple 引入了等效物：NSInteger。它在整个 Cocoa 框架中都被使用，且大小始终与指针相同。还有一个无符号版本 NSUInteger。在 GUI 代码中，你经常会遇到 CGFloat 或 NSFloat。它们相互之间是等价的，且大小与 double 相同。

## 在集合中存储数字

```objc
NSMutableArray *array = [NSMutableArray array];
[array addObject:[NSNumber numberWithInt:12]];
```

来自：numberInArray.m

所有的标准 Objective-C 集合类都允许你存储对象，但你通常也想存储原始类型。解决此问题的方法是装箱（boxing）——将原始类型包装在对象中。

NSValue 类层次结构用于此操作。NSValue 是一个设计用于包装原始值的类。该类非常通用，是类簇的一个示例。当你创建 NSValue 实例时，你会得到某个子类，专门用于存储不同类型的数据。如果你在 NSValue 中存储一个指针，你不希望该实例占用的空间像包含 NSRect（一个包含四个 Float 的 C 结构体）那样大。

NSValue 的一个具体子类特别重要：NSNumber。该类旨在包装单个数值，并可以从任何 C 标准整数类型初始化。

这两个类的指定构造函数（designated constructor）都是 `+writeValueBytes:objcType`。第一个参数是某个值的指针，第二个参数是该类型的 Objective-C 类型编码（type encoding）。类型编码是表示特定类型的字符串。它们在 Objective-C 的内省中被大量使用；你可以作为类型编码字符串获取类中任何方法或实例变量的类型，并解析它以获取相关的编译时类型。

你可以使用 `@encode()` 指令获取任何类型的类型编码。这类似于 C 中的 `sizeof()`，但它不是以整数形式返回大小，而是以 C 字符串的形式返回类型编码。在处理类型编码时，一个非常方便的技巧是使用 `typeof()` GCC 扩展。它返回表达式的类型。你可以将其与 `@encode()` 结合使用，如下所示：

```objc
NSValue *value =
[NSValue valueWithBytes:&aPrimitive
objcType:@encode(typeof(aPrimitive))];
```

这段代码将返回一个包装了 aPrimitive 的 NSValue
