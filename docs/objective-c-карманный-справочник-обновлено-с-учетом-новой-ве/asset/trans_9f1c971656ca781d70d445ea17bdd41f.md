

# 测试一个对象是否理解某个方法

```
$ gcc -framework Foundation -g -std=c99 weakClass.m && ./a.out
a.out[53194:903] Not linked against AppKit
$ gcc -framework Cocoa -g -std=c99 weakClass.m && ./a.out
a.out[53184:903] View: <NSView: 0x1001163b0>
```

输出自：weakClass

注意此示例链接到 Cocoa（它链接了 AppKit 和 Foundation）与仅链接到 Foundation 时输出差异。如果存在 `NSView` 类，它会创建一个实例。如果不存在，它只会记录一条消息。
你也可以将其用于在必须与框架旧版本后兼容的代码中。如果你使用这种机制查找新类，你将得到一个 Nil 值，当这些类不存在时你可以处理该值。

# 测试一个对象是否理解某个方法

```objc
SEL sel = @selector(delegateMethod);
if ([delegate respondsToSelector:sel]) {
    [delegate delegateMethod:self];
}
```

源自：respondsToSelector.m

Objective-C 代码倾向于使用非正式协议（informal protocols）。这些是代理可以选择实现的消息组。
当你编写使用这些代码时，你需要在发送消息之前测试该类是否真的实现了该方法。

**注意：** 这并不完全正确。你可以直接在 `@try` 块中发送消息，并在它不理解方法时捕获抛出的异常。然而，考虑到抛出异常的代价，这并不是推荐的方法。

幸运的是，这样做非常简单。`NSObject` 实现了一个 `-respondsToSelector:` 方法，用于测试接收者是否可以处理带有给定选择器的消息。

此方法不仅由 `NSObject` 实现，也是 `NSObject` 协议的一部分。其他根类也会实现它。这对于转发（forwarding）非常重要。
NSObject 中的此方法方法调用了运行时函数 `class_respondsToSelector()`。在其他类中，实现是不同的。如果你直接使用运行时函数，你的代码将会非常脆弱。

大多数时候，你想知道的是要发送消息的对象是否能处理该消息，而不是它是否有一个处理该消息的方法。在某些语言（如 C++）中，这些是同一个，但在 Objective-C 中，它们是非常不同的概念。

当你向代理发送 `-respondsToSelector:` 消息时，它将测试真实对象是否具有对应该选择器的方法。被代理封装的对象可能是另一个代理，它将再次转发请求。
你也可以通过向类发送 `-conformsToProtocol:` 消息来测试协议的遵循情况。注意，这只测试该类是否被声明为采用该协议。类可以采用协议但不实现它们的所有方法（尽管它们不应该这样做），但更常见的情况是类可以实现协议中的所有方法而不显式地遵循协议。

# 转发消息

```objc
@interface Facade : NSObject{
  id delegate;
}
@implementation Facade
-(id)forwardingTargetForSelector:(SEL)aSel {
  return delegate;
}
-(void)forwardInvocation:(NSInvocation*)anInv {
  [anInv invokeWithTarget:delegate];
}
@end```
```

源自：forward.m

Objective-C 消息旨在类似于 Smalltalk 消息，而不是 C 函数。它们是后期绑定的并且可以被内省。在最底层，它们使用 C 函数实现，但这是一个实现细节。你可以假装消息是对象与其他对象之间传递的、被内省的，然后由方法处理。

当你向一个在该对象上没有对应方法的对象发送消息时，该对象仍然有一些方法可以处理它。这些方法在 Objective-C 的发展过程中已经进化了许多。

在旧的 Objective-C 代码中，会调用对象的 `-forward:::` 方法。这是一个可变方法，并要求接收者知道栈帧的结构。NeXT 用 `-forwardInvocation:` 替换了它。此方法接收一个封装了消息发送的对象。`-forwardInvocation:` 机制非常灵活，但性能并不是特别好。创建对象和解构栈帧的代价比普通消息发送高出几百倍，这意味着你不应该在任何即使有一点点对性能敏感的场合使用这种机制。

如果你使用这种转发机制，那么你必须实现 `-methodSignatureForSelector:` 方法。它返回一个代表与消息关联的调用帧结构的对象。`NSInvocation` 类将在创建封装消息的对象时使用它。

在 10.5 版本中，Apple 引入了一种新的、更快的转发机制。如果你的对象实现了 `-forwardingTargetForSelector:` 方法，它将带有缺失方法的选择器被调用。然后它可以返回一个对象，消息将改为交付给该对象。

这使得像门面模式（façade pattern）这样的设计非常简单。你可以快速地将任何你不理解的方法委托给你的代理。如果你在调用代理方法之前或之后需要一些额外的处理，只需实现该方法并显式地调用代理方法即可。

注意：GNU 运行时使用的两阶段消息发送机制不支持这种新机制，旧版本的 Apple 运行时也不支持。如果你使用它，使用 `--forwardInvocation:` 提供回退代码是一个好主意。如果你使用的是最近的 Apple 运行时，或者带有非脆弱 ABI 的 GNUStep 运行时，你将获得额外速度的好处。

# 查找类

```objc
int classCount = objc_getClassList(NULL, 0);
Class *classList = calloc(classCount, sizeof(Class));
objc_getClassList(classList, classCount);
for (int i=0; i<classCount; i++) {
  [classes addObject:NSStringFromClass(classList[i])];
}
free(classList);
[classes sortUsingSelector:@selector(compare:)];
```

源自：classTree

有两种方法查找 Objective-C 类。如果你知道名称，可以直接使用 `NSStringFromString()` 函数。它接收一个字符串对象作为参数并返回该类，如果没有注册该类，则返回 Nil。

如果你不知道类的名称，那么你需要不同的方法。在某些情况下，你可能想要一个类但不知道它的名称。例如，如果你有一个插件架构，你可能允许用户指定加载 bundle，然后想要收集特定类的子类，或者遵循特定协议的所有类。

**注意：** 当你测试类遵循协议时，最好使用运行时函数，而不是向它们发送 `+conformsToProtocol:` 消息。许多类使用 `+initialize` 进行延迟初始化，向它们发送消息即使你没有真正使用该类，代码也会运行。
