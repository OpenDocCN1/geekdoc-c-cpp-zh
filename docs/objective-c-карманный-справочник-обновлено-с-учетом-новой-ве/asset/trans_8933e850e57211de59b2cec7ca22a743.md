

## 传递错误委托 251

- 此方法返回一个 BOOL，表示操作是否应该继续。如果错误委托没有处理这些条件，你可以通过抛出异常将其与代码中的异常回（unwinding exceptions）相结合。

我在 LanguageKit 框架中使用了这种模式来报告编译器错误和警告。当编译器遇到错误时，它会调用错误委托中的一个方法。默认实现只是将消息打印到控制台，但其他实现可以转换抽象语法树以移除该错误。如果该方法返回 YES，编译器将回溯并尝试重新检查。如果返回 NO，编译器将抛出一个异常，该异常由调用编译器的代码捕获。

总而言之，在操作过程中任何可能遇到可以解决的问题时，你都应该使用这种模式。例如，在加载引用其他文件的文件时可以使用它。如果引用的文件之一缺失，默认选项是终止。然而，错误委托可以提供一条新路径，通过使用某些修复的翻译或提示用户来实现。

## 返回错误值

```
- (BOOL)trySomething;
-(id)trySomethingWithObject:(id)anObject
      error:(NSError**)e;
```

来自：errorReturn.m
在 C 中，一种常见的模式是成功时返回零，返回非零值表示错误条件。这在 Objective-C 中不那么流行，但返回一个表示操作是否成功的 BOOL 值是相对常见的。

大多数时候，这是通过以某种方式变动接收者（receiver）的方法来实现的。当你调用此类方法时，是为了影响对象的某种变化，而不是为了获取一个值，因此返回值没有被用于其他地方。这种模式的一个示例是 NSStream 上的 -setProperty:forKey: 方法。它尝试设置流的属性，如果成功则返回 YES。请注意，这与 C 模式相反，C 模式在失败时返回真值。

## 使用 NSError

```
NSError *error = nil;
NSStringEncoding enc;
NSString *str = [NSString
stringWithContentsFile: @"DoesNotExist"
usedEncoding: &enc
error: &error];
if (nil != error) {
    NSLog("Error: %@",
          [error localizedDescription]);
}
```

来自：nserror.m

Apple 在 OS X 10.2 中引入的几个方法接受一个 NSString* 作为参数。这被用于返回一个报告错误的第二个值。如果调用后指向该变量为 nil，则操作成功。如果不是，它将包含一个描述错误的字符串。

这有一些显而易见的局限性。字符串对于向用户报告是可以的，但对于恢复错误并不特别有用。如果你想在代码中处理错误，你需要以某种方式解析该字符串。

当 Apple 发布 Safari 10.2.7 版本时，增加了一个新类：NSError。它几乎总是通过作为方法最后一个参数传递的指针返回的。错误对象看起来与异常对象非常相似。它有一个名称（称为领域 domain）和一个与之关联的字典。

与异常对象不同，字典包含了本地化的错误描述。你可以无需经过任何额外处理就将其展示给用户。
错误对象有时还包含一种恢复策略。恢复尝试者对象（recovery attempter object）可以尝试从错误中自动恢复。对于某些错误，这是可能的，但当你尝试执行某些可行但不安全的操作时，通常会得到错误。当这种情况发生时，你应该将错误展示给用户，然后调用恢复尝试者。

如果你用过 Common Lisp，这种模式看起来会很熟悉，它是可重启异常（restartable exception）的一种临时形式。

## 访问目录和文件

如果你正在使用 AppKit，对于大多数与文件系统相关的任务，你有两个选择。来自 Foundation 框架的 NSFileManager 类提供了许多操作文件和目录的底层方法。来自 Application Kit 的 NSWorkspace 类提供了更抽象的形式。

NSWorkspace 的许多函数被委托给了工作空间进程（workspace process）。在旧的 NeXT 系统上，这是一个单一程序，而在 OS X 上，其功能的各个部分由窗口服务器和 Finder 实现。

正因如此，当无法保证工作空间进程存在时，考虑使用高级版本是没有意义的——例如，在可能通过服务器代码在远程连接运行的命令行工具中。

UIKit 框架没有 NSWorkspace 的等价物。如果你的目标是 Cocoa Touch，你必须使用更低级的 API。

## 读取文件

```
NSData *copy =
NSData dataWithContentsOfFile: file];
NSData *mapped =
[NSData dataWithContentsOfMappedFile: file];
NSData *read = [[NSFileHandle
HandleForReadingAtPath: file]
DataToEndFile];
```

来自：read.m
UNIX 系统通常提供两种访问的方法：read() 和 mmap() 系统调用。大多数其他系统——至少是运行在带有内存管理单元（MMU）的硬件上的系统——都有这些等效实现。前者将字节流从文件拷贝到缓冲区中。后者将文件数据映射到内存区域。

Foundation 提供了两个大致对应于这些操作的类。NSData 类封装了包含未类型数据的内存区域。你可以通过各种选项从文件创建它的实例。

## 读取文件

对于小文件，你可以直接使用封装了 read()调用的版本，并将文件数据的副本读取到内存中。对于较大的文件，你可能希望使用 +dataWithContentsOfMappedFile:。

后者的优点是它与操作系统的虚拟内存子系统交互得非常好。
