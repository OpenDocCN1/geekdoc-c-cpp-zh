来自：doPublish.m

Objective-C 最强大且最未被利用的部分之一是分布式对象系统。如果你向一个对象发送消息，而该对象不理解如何处理，那么它将接收一个 `-forwardInvocation:` 消息，其中有一个对象将消息作为参数封装。

像 Objective-C 中的其他所有内容一样，你可以对这个对象进行内省。它会告诉你选择器（selector）、参数数量以及所有参数的类型和值。Foundation 框架包含一个类 `NSDistantObject`，它利用了这一点。远端对象是一个代理，将消息转发给远程对象。远程对象可能在不同的进程中，甚至在不同的计算机上。

如果你将对象作为参数传递给发送远端对象的消息，那么它们可能会被复制，或者在远端创建一个远程代理来回传消息。

使用分布式对象非常简单。任何使用它们的程序都包含两个部分：客户端和服务器。服务器向其他进程提供对象，而客户端连接到服务器并访问它们。

默认情况下，对象仅在本地机器上共享。要跨越网络共享它们，你必须在注册对象时使用 `NSSocketPortNameServer`。

## 寻找网络对等

来自：netservice.m

多年来，有很多协议被用于在本地网络上寻找服务。在 90  年代中期之前，NetBIOS 和 AppleTalk 在本地网络中都非常常见，直到它们开始被逐步淘汰并转而 TCP/IP。

TCP/IP 协议栈并不包含任何执行此操作的功能。最接近的方法是广播地址。如果你向广播地址发送数据包，它将发送给本地段上的所有人。这有很多问题；它只在本地物理段上工作，在现代交换机网络上效率低下，而且这是一种非常底层的方法。

IETF 的 ZeroConf 工作组提出的多播 DNS (mDNS) 是此解决方案。DNS 是一种发布映射的可扩展方式。它最常用于从主机名到 IP 地址的映射，但也可以用于电话号码、地理位置信息以及许多其他内容。

通过 mDNS，单个计算机可以在 `.local` 域中发布 DNS 记录。这被用作 DNS 服务发现 (DNS-SD) 的基础，它描述了在 DNS 上上告任意服务的方法。你也可以结合传统的层级 DNS 使用此标准，但它与 mDNS 配合时最有用。

这两个标准的结合通常被称为 Bonjour，并通过 `NSNetService` 类暴露给 Objective-C。这允许应用程序发布 DNS-SD 记录并找到特定服务的所有记录。

许多应用程序都使用了该技术。Safari 使用它共享书签；iChat 使用它查找联系人；iTunes 使用它共享音乐；系统使用它查找共享文件夹和打印机。如果你正在编写任何类型的网络应用程序，你可能会发现使用 `NSNetService` 广告很有帮助。当你发布服务时，必须指定一个唯一的名称。如果你使用分布式对象（我们将在章末尾讨论），那么你可以使用它作为你提供服务的名称，并忽略 Bonjour 系统的底层。使用 `NSServiceBrowser` 类搜索对等实体。正确使用它有点复杂。发布服务是同步的；异步的。当你向浏览器发送搜索消息时，它将传输 DNS 请求。可能需要一段时间才能获得响应，你可能不想停止用户执行任何操作，因此此方法立即返回。

当它接收响应时，该类将向其代理发送一个新的 `NSNetService` 实例来描述发现的每个服务器。它将一直监听，直到你发送停止消息。

在很多情况下，你永远不会发送此消息。你可以让浏览器在进程生命周期内一直运行，并在本地网络出现新对等实体时收到通知。你可以触发用户界面的更新以显示新的对等实体。这就是像 iTunes 这样的程序将网络上出现的新列表添加到库。
