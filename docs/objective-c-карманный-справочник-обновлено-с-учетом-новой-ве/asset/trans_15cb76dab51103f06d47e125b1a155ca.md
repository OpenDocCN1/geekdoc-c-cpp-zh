
注意：Apple 和 GNU 的 Objective-C 实现之间的主要区别之一是 GNU 实现使用了带类型的选择器（typed selectors）。选择器是在消息传递中用于查找方法的名称。在 GNU Objective-C 中，选择器还包含了消息参数类型的编码。这允许函数检查它们被调用时是否使用了正确的参数类型，这对于分布式对象及其他少数情况非常有用。

GNUstep 运行时现在默认使用依赖于类型的分发，这意味着方法查找取决于选择器的类型编码。发送一个与接收者不匹配的带有类型签名的的消息将导致未定义行为，因此，GNUstep 运行时的记录警告或抛出异常的方法，与 Apple 运行时破坏栈的方法同样有效。

参数（arguments）。它们的使用方式与接受函数指针作为参数的 C 函数非常相似，用于延迟执行、回调、集合排序等。

# 声明类

```objc
@interface Integer : NSObject
{
  int integer;
}
  (int)intValue;
  (void)addInteger:(Integer*)other;
@end

@implementation Integer
  (int)intValue { return integer; }
  (void)addInteger:(Integer*)other {
    integer += [other intValue];
  }
@end
```

来自：integer.m

当你创建一个新类时，你需要做两件事：描述它的公共接口并编写它的私有实现。你需要使用三个 Objective-C 关键字：@interface、@implementation 和 @end。

注意，所有新的 Objective-C 关键字都以 @ 符号开头。这是因为该符号在 C 标识符中是不允许使用的。与之对比的是，C++ 引入了如 `class` 之类的标识符，这会破坏任何使用 `class` 作为变量名的 C 代码。

Objective-C 继承了 C 的编译模型，其中编译器期望单个文件，并通过让预处理器组合各种文件来完成分离。按照惯例，Objective-C 类的接口被放在具有 .h 扩展名的头文件中，而实现则存放在 .m 文件中。没有人记得为什么选择 .m。Objective-C 的设计者曾建议过，它可能代表“module（模块）”、“methods（方法）或“messages（消息）”。

由于头文件是由预处理器插入到编译单元中的，在 Objective-C 编译器看到它们之前就已经完成了插入，因此这种分离并不是强制执行的。C++ 和 C 中的不透明数据类型也是如此。

Objective-C 的一个稍微惊讶的方面是，实例变量（Java 和 C++ 称为“字段”）被声明为接口的一部分，而不是实现的一部分。这是早期 Objective-C 版本实现方式的产物。每个对象都被转换为一个 C 结构，其第一个字段是指向类的指针。为了生成这个结构，编译器需要能够看到所有父类的实例变量。这种方法一个不幸的副作用是，修改类的布局意味着你必须重新编译所有的子类。

现在，有了非脆弱性 ABI（non-fragile ABI），你可以向子类隐藏私有实例变量。对它们的每个引用都通过一个间接层。偏移量现在是一个变量，而不是编译时常量。新的编译器允许你在 @implementation 上文中以及 @interface 中定义实例变量。

默认情况下，Objective-C 实例变量是受保护的，这意味着它们只能由类或其子类访问。如果你为它们加上 @private 前缀，它们仅对该类可用；如果加上 @public，则可以在任何地方访问。这并不常见。运行时对访问权限的检查很少，并且有几种机制可以绕过访问控制，因此通常将所有内容保持为受保护状态，仅在私有类中将实例变量设置为公共。

**注意：** Apple 的非脆弱性 ABI 限制了 iv 偏移变量的可见性，如果你尝试从不同的编译单元访问私有实例变量，将产生硬错误。仍然可以通过运行时内省访问私有实例变量，而这种保护在其他运行时中是不提供的。

类接口的基本结构包含三个部分。第一部分是新类在层次结构中的位置：

```objc
@interface ClassName : Superclass <protocols>
```

类名紧跟在 @interface 关键字之后。接着是一个冒号，然后是父类的名称。可以设计新的根类，但要正确做到这一点非常复杂，大多数情况下你将使用 NSObject 或 NSProxy 作为你的父类。

之后，你还可以可选地在角括号中指定一个由逗号分隔的协议列表。Objective-C 中的协议类似于 Java 中的接口。它们定义了对象必须实现的方法列表。

注意：在较新版本的编译器中，你可以在类声明前加上 `__attribute__((weak_import))`。这使得所有引用都变为弱引用（weak）。如果你向该类发送消息而它未被链接，则等同于向 nil 发送消息。以这种方式导入的类的子类在父类加载之前将不会解析。这允许你定义一个继承自可选加载的包（bundle）中类的类。

接下来是相同的实例变量列表。它遵循在 C 中定义结构的语法。一个只包含实例变量而没有方法的简单类定义看起来如下：

```objc
@interface NoMethods : NSObject
{
 int integer;
 NSObject *object;
 float floatingPoint;
}
@end
```

在 C 结构定义中有效的任何内容在在这里都是有效的。如果你使用 Objective-C++，你还可以添加指向 C++ 对象的指针以及具有简易构造函数的 C++ 对象。

最后，你列出类所实现的公共方法。与其为此列表随口编造一些，让我们来看一些真实的方法声明：

+ + (id)new;
- (void)append:(NSString*)aString;

方法声明前的加号表示这是一个附加到类的方法。你可以向类发送 +new 消息，它会返回一个对象指针。id 类型是 Objective-C 引入的一种新类型，类似于 C 中的 void* 类型，但被限于 Objective-C 对象。

注意，返回类型和参数类型使用的语法与类型转换相同。这突显了消息传递和函数调用之间的另一个重要区别。方法被编译为函数，并通过在运行时查找的指针调用。当你发送消息时，编译器隐式地将方法指针转换为这些类型。这种语法还旨在强调参数并不必须是 NSString*；它只需要是你可以转换为 NSString* 的东西。

类的实现部分简单得多。它以 @implementation 指令开头，包含了类所有方法的定义，如下：

```objc
@implementation NewClass
```

```objc
+ (int)classVersion {
    return 2;
}
- (void)log {
    fprintf(stderr, "log message received");
}
```

一个重要的点是你不需要声明类实现的所有方法。未在类接口中声明的方法被视为私有的。调用它们将产生编译时警告，类的未来版本可能会停止响应它们。

# 使用协议

与类一样，Objective-C 中的协议也是对象。协议的行为是 Apple 在现代运行时更改的内容之一。以前，协议是通过名称标识的，如果两个协议名称相同，它们被认为是等价的。这意味着如果你在不同的库中声明了同名的协议，你就无法判断一个对象实现了其中哪一个。更重要的是，你无法查找协议并查看它需要哪些方法。

在 Objective-C 2 中，协议现在是唯一的。
