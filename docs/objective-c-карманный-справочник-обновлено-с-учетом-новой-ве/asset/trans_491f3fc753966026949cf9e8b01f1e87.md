

## 第 10 章：环境

在两种情况下，内核都会收回所有的共享资源，但在突然终止的情况下，这些资源中的某些可能被留在了不一致的状态。一个典型的例子是正在修改中的文件。

这在过去是复杂应用程序（如文字处理器）中的一个大问题。它们会打开文件进行写入，开始修改，然后崩溃，导致文件处于一种非常难以恢复内容的状态。你可以通过使用大多数基础对象（Foundation objects）上的原子写入功能来避免这种情况，这些功能会写入临时文件然后将其重命名，因此写入要么完全成功，要么完全失败——不会部分成功。

在 OS X 10.6 中，Apple 引入了突然终止（sudden termination）机制。其背后的理论是，许多程序在退出时花费大量时间运行对象的析构函数，而这些对象除了释放内存外没有其他影响，操作系统反正会收回这些内存。通过突然终止，进程可以声明它没有未保存的数据。操作系统就可以自由地杀死它，而不是请求它优雅地退出。

这对于长时间空闲的运行后台任务特别有用。这些任务通常会被内核交换出。当你要求它们优雅地退出时，需要将大量的代码和数据调入内存来处理退出。通过突然终止，交换文件中的页面将只需标记为可重用。

### 支持突然终止

在你的应用程序中支持突然终止非常简单。你对 `NSProcessInfo` 调用两个方法，分别在某个不可中断的操作的两侧调用。

注意：如果你在使用 `NSDocument` 基础设施使用 AppKit，则你不需要做任何事情。当任何文档有未保存的数据时，你的应用程序将被标记为不支持突然终止。

这些方法被称为 `-disableSuddenTermination` 和 `-enableSuddenTermination`，但名称略有误导性。它们并没有实际上启用或禁用突然终止，而是修改一个计数器。当计数器达到 0 时，应用程序被标记为可被杀死。

这意味着你可以没有任何问题地在不同线程中使用它们或进行嵌套。计数器初始设置为 1，因此你必须显式向进程信息对象发送 `-enableSuddenTermination` 消息来启用它。如果你正在创建一个应用程序，可以通过在应用程序包（bundle）的属性列表文件（plist）中设置一个键来避免这一点。与命令行工具不同，Cocoa 应用程序通常以包的形式分发。

这些应该被图形界面文件管理器视为文件的目录。NeXT 曾非常有效地利用它们在同一个应用程序中存储针对不同操作系统的二进制文件，允许文件服务器包含一个适用于 OPENSTEP、Solaris 甚至 Windows 的单个应用程序。该包包含的内容之一是一个属性列表，称为 `info.plist`，它描述了关于应用程序的一些属性，例如其主类的名称、启动时加载的资源等。初始的突然终止状态就是这些属性之一。

在 iOS 和 OS X 10.7 中，突然终止非常重要。当这些系统内存不足时，它们将使用突然终止来终止应用程序。预计应用程序能够在不丢失任何用户可见状态的情况下重启。在 OS X 10.7 中，应用程序中的每个窗口都应该能够存储其状态并自动加载。

## 键值编码 (Key-Value Coding)

典型程序中的许多代码都涉及访问和修改对象状态的方面。

键值编码（KVC）机制旨在为设置和获取对象的属性提供一个抽象接口。它与键值观察（KVO）机制结合，KVO 提供了一种观察另一个对象特定属性变化的抽象方式。

KVC 允许你像操作字典一样与每个对象交互。无论属性如何存储，你都使用相同的机制来读取和写入属性。主要优势是它消除了许多为了适应模型视图而编写自定义控制器的需求。

视图类通常需要对模型对象上获取和设置属性。通过 KVC，有一个通用的、参数化的机制来实现此操作。你只需要为视图对象提供一个键或键路径（key path），让它自动从模型中检索数据，而无需了解模型实现的任何细节，甚至无需知道除支持 KVC 之外的任何接口。

## 第 11 章：键值编码

### 通过键访问值

```objc
[object setValue: @"42"
forKey: @"integer"];
int value = [[object valueForKey: @"integer"] intValue];
NSAssert(value == 42, @"Value set and retrieved");
```

> 出自：kvc.m

通过 KVC 操控的对象看起来非常像字典。`NSDictionary` 类本身是符合 KVC 标准的，尽管你在使用它时通常不使用 KVC 方法。

与符合 KVC 标准的对象交互的两种最常用方法是 `-valueForKey` 和 `-setValue:forKey:`。`NSDictionary` 上的 `-objectForKey` 方法在检索值时的行为几乎相同。`NSDictionary` 上的两个设置方法工作方式略有不同。

你首先会注意到，如果你在不可变字典上使用 `-setObject:forKey:`，你会得到一个编译时警告。如果你使用 `-setValue:forKey:`，则不会。此方法由 `NSObject` 实现。当你在不可变字典上调用它时，它会在运行时失败，但在编译时没有任何提示。

另一个大区别是 `nil` 的使用。如果你在 `-setValue:forKey:` 使用 `nil` 作为值，它将删除该键。如果你对 `-setObject:forKey:` 执行相同操作，将得到一个异常。

### 确保符合 KVC 标准

```objc
@interface KeyPublic : NSObject @end
@implementation KeyPublic @end
@interface KeyIVar : KeyPublic
{
    int integer;
}
@end
@implementation KeyIVar @end
```

> 出自：kvc.m

当你使用 KVC 方法时，你几乎是在调用 `NSObject` 中的实现。这些实现会尝试确定应该如何访问属性。

它们首先查找的地方是访问器方法。按照约定，Objective-C 类提供 `-property` 和 `-setProperty:` 方法来读取和设置“属性”。如果你的类提供了这些方法，它们将被调用。KVC 还会查找其他几个方法，包括用于布尔属性的 `-isProperty` 等方法。

```objc
@interface KeyAccessor : KeyVar @end
@implementation KeyAccessor
- (int)integer
{
    return integer;
}
- (void)setInt:(int)aValue
{
    integer = aValue;
}
@end
@interface KeyProperty : KeyPublic
@property int integer;
@end
@implementation KeyProperty
@synthesize integer;
@end
```

> 出自：kvc.m

如果失败了，类将收到一个 `+accessInstanceDirect` 消息。如果返回 `YES`，KVC 方法将查找与属性名称匹配的实例变量并使用它。`NSObject` 中此方法的实现返回 `YES`，所以只有在你想防止 KVC 检查实例变量时才需要重写它。

最后，如果仍然失败，KVC 代码将调用两个备用方法之一，取决于是在设置还是获取属性。这些是 `-valueForUndefinedKey:` 和 `-setKeyValue:forUndefinedKey:`。

```objc
@interface KeyFallback : KeyPublic
{
    NSMutableDictionary *dict;
}
@end
@implementation KeyFallback
-(id)valueForUndefinedKey:(NSString*)akey
{
    return [dict forKey:akey];
}
-(void)setValue:(id)aValue
forUndefinedKey:(NSString*)akey
{
    [dict setValue:aValue forKey:akey];
}
@end
```

> 出自：kvc.m

这些方法是支持 KVC 的最后机会。如果你实现了它们，你应该对所有你不直接支持的键调用父类的实现。如果在根类上调用，它将抛出异常，表明你没有正确处理该键。

如果你使用声明属性来合成访问器方法，你将免费获得 KVC 标准的支持。`kvc.m` 示例展示了实现同一个 KVC 属性的所有不同方式。
