The bindings mechanism uses KVC and KVO to eliminate the need for controllers in a lot of cases. When a view wants to modify a model, it uses KVC. When the model changes, the view gets the notification from KVO and updates itself to reflect the change. The combination of these two—closely related—technologies allows you to have tight connections between objects without tight coupling of their designs.

Registering as a KVO observer is a lot like registering to receive notifications (see Chapter 16), but with a few differences. One of the most important is that KVO notifications are always sent to the same method. The first method in the sample code at the start of this section shows what this should look like.

In this example, it's a class method. Most of the time, you will use instance methods, but it's important to remember that classes are objects in Objective-C, so you can use them in almost any place where you'd normally use an object. This implementation is quite simple; it just logs the new value for the key. The second method shows how to register for the notification.
