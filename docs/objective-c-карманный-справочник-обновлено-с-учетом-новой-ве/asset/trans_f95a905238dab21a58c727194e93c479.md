

# 在 User Defaults 中存储任意对象 211

将 NSColor 对象存储在 defaults 中。

如果属性列表（property lists）以及扩展的 user defaults 支持 NSColor 对象，那就太简单了。遗憾的是，它们不支持。不过，你可以在 defaults 中存储 NSData 实例。如果你有某种将对象转换为数据的机制，就可以将其存储在 defaults 中。

幸运的是，有一种许多常用对象都支持通用方法。任何实现 NSCoding 协议的对象都可以使用 NSCoder 的子类进行序列化和反序列化。

与属性列表不同，NSCoder 机制支持任意对象和循环。遗憾的是，它要求对象实现 NSCoding 协议中的两个方法，因此它并不适用于所有对象。不过，它适用于很多对象，而且复用它存储 defaults 中的对象是非常轻而易举的。如果你经常进行这种操作，可以很容易地为 NSUserDefaults 写一个分类（category），添加 -colorForKey: 和 -setColor:forKey: 方法。这些方法可以接收 NSColor 实例，使用 coder 将其序列化，然后恢复它。

如果你想要一个更通用的解决方案，可以添加一个 -setEncodedObject:forKey: 方法。该方法将接受一个 id<NSCoding> 作为参数，并使用本章开头示例中的代码进行存储。

如果你想在 defaults 中存储某些不支持 NSCoding 协议的对象，你有两个选择。首先，你可以为它添加 NSCoding 支持。这涉及实现 -encodeWithCoder: 和 -initWithCoder: 方法，你可以在分类中实现它们。第二是进行其他类型的转换。许多对象具有 -stringValue 和 -initWithString: 方法。你只需要在存储之前将它们转换为字符串，并在从 defaults 读取时从字符串创建新对象，就可以将它们存储在 defaults 中。

# 与环境交互

Objective-C 通常用于类 UNIX 平台，并从那里继承了“环境”的概念。这包括了工作目录、环境变量等概念。

在传统的 Objective-C 环境中，你被期望以从 C 程序中完全相同的方式获取这些值。通过 OpenStep，Sun 和 NeXT 引入了 NSTProcessInfo 类，它提供了更高层次的抽象。

此部分动机之一是，OpenStep 程序预计将运行在 OPENSTEP、Solaris 和 Windows NT 上。这些系统在环境概念上都有细微差别，因此需要一些抽象来隐藏这些差异。

# 获取环境变量

```
int main(int argc, char **argv, char **envp) {
    // C 语言
    while (*envp) {
        printf("%s\n", envp);
        envp++;
    }
    printf("Working Directory: %s\n", getenv("PWD"));

    // Objective-C 方法
    [NSAutoreleasePool new];
    NSDictionary *env = [[NSProcessInfo processInfo] environment];
    for (NSString *key in env) {
        NSLog("@%@ = %@", key, [env objectForKey:key]);
    }
    NSLog("Working Directory: %@ array of C@\n", [env objectForKey:@"PWD"]]);
    return 0;
}
```
源：env.m

在 OS X 上可以通过三种方式访问环境变量。其中两种方法可以在任何地方工作，而第三种只在某些平台上有效。

OS X 像 Windows 和许多 UNIX 系统一样，将环境作为 main() 函数的第三个参数传递给进程。这是一个 NULL 终止的 C 字符串。C 和 POSIX 标准并不要求这个第三个参数有效，因此在可移植代码中依赖它并不是好主意。

当程序启动时，运行时加载器会加载所有需要的共享库，然后跳转到 C 标准库中的一个特殊函数，通常称为 _start。然后它调用 main()，但在调用之前会存储指向环境变量的指针。

你可以通过调用 getenv() C 标准函数来访问此存储。或者，你也可以向单例 process info 对象发送 -environment 消息来访问环境变量。这会返回一个包含环境的字典。

**注意：** 没有办法使用 Objective-C 代码来设置环境变量。修改环境通常在 C 代码中完成，作为调用 exec() 族函数之一的预备工作。这只在类 UNIX 平台上有效，例如在 Windows 或 Symbian 系统上则无效。因此，不建议这样做。你可以通过向 NSTask 发送 -setEnvironment: 消息来设置一个新的字典，将其作为新子进程的环境。

# 解析命令行参数

```
int main(int argc, char **argv)
{
    [NSAutoreleasePool new];
    NSUserDefaults *d =
        [NSUserDefaults standardUserDefaults];
    NSString *file = [d stringForKey:@"file"];
    if (nil == file) {
        fprintf(stderr,
                "USAGE: %s -file {filename}", argv[0]);
        return 1;
    }
    NSLog("Using file %@", file);
    return 0;
}
```
源：args.m

标准 C 不提供在 main() 函数之外获取程序参数的方法。GNU C 标准库提供了一些扩展以便在程序启动后访问它们，在大多数类 UNIX 平台上，你可以从 /proc 文件系统读取它们，但 C 代码中没有简单的方法可以以可移植的方式获取它们。

在 Objective-C 中，你始终可以通过向 NSProcessInfo 发送 -arguments 消息来获取参数。这会返回一个包含所有选项的 Objective-C 字符串的 NSArray。然后你可以以任何喜欢的方式处理这些参数。

以这种方式访问参数是非常不寻。解析命令行参数最简单的方法（正如我们在上一章中看到的）是使用 NSUserDefaults 中的 NSArgumentDomain。当 Objective-C 程序启动时，所有的命令行参数都会被读取并插入字典中，该字典由默认系统使用。

这使得提供一组命令行参数以及（可配置的）默认值变得非常。当你使用这种方法时，你不需要直接与参数交互。相反，你向默认系统请求某个键的值，它会返回一个可能来自持久化存储位置或命令行的内容。

在 EtoFoundation 框架中，我们提供了一个 GetOptionsDictionary() 函数，它封装了标准的 getopt() 函数。这提供了一种 Objective-C 使用命令行参数的方法。

# 获取用户的本地语言

```
NSLocale *1 =
    [NSLocale autoupdatingLocale];
    NSString *language =
    [1 objectKey: NSIdentifier];
    [1 humanNameForKey: language];
```
**源：locale.m**
如果你的程序以任何方式与用户直接交互，你可能会在某个点想要对其进行本地化。Objective-C 提供了许多实现此点的设施。

NSLocale 对象封装了一个本地语言。获取该类实例有多种方法。如果你向它发送 +systemLocale 消息，你将获得系统语言。然而，这通常不是你应该使用的。它是当用户语言无效时的备用本地语言。

你可以通过两种方式获取用户当前的本地语言。发送 +currentLocale 消息返回一个封装了当前语言的 locale 对象。如果用户选择了新的本地语言，会发布一个 NSCLocaleDidChangeNotification，你可以为新语言获取一个新的 locale 对象。

或者，你可以向该类发送 +autoupdatingCurrentLocale 消息。这返回一个始终代表当前语言的 locale 对象，即使它发生了变化。这可能会稍微令人困惑，因为在该对象上对同一个方法使用相同参数的连续调用可能会返回不同的值。

如果你想在程序运行时支持更改本地语言，避免缓存从 locale 对象返回的数据是非常重要的。如果你在向用户展示保留在屏幕上的内容，你应该确保监控该通知并更新它们，即使你正在使用自动更新的 locale 对象。

# 支持突然终止

```
NSProcessInfo *p =
[NSProcessInfo processInfo];
[p enableSuddenTermination];
// 初始化
[p disableSuddenTermination];
// 执行此处不能被
// 中断的其他操作
modifyFiles();
[p enableSuddenTermination];
```

传统上，进程终止有两种方式。进程可以优雅地退出，通过到达安全停止点然后调用 exit() 或到达 main() 函数的返回语句。或者，它也可以突然退出，通过接收一个未处理的信号，包括段错误等。
