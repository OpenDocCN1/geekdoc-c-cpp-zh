

## 逐个字符处理字符串

```objc
for (NSInteger i=0; i<[aString length]; i++) {
    char c = [aString characterAtIndex:i];
    // Process c.
}
```

来自：stringIterateSlow.m

NSString 类是一个类簇（class cluster）。它是一个抽象类，当你创建一个它的实例时，你得到的是某个私有子类的实例。任何 NSString 子类必须实现两个原始方法：-length 和 -characterAtIndex:。第一个返回长度，第二个返回字符串中特定索引处的字符。

如果你需要对字符串中的每个字符进行某些操作，可以使用一个简单的循环对其进行迭代，并反复调用此方法。这种方法非常低效，因为每个字符都需要发送一次消息（message send）。这比访问 C 字符串中的字符要昂贵得多。这个版本还为每个字符发送一次 -length 消息，只有当长度在迭代过程中可能会变化时，才需要这样做。

另一种方法是获取 C 字符串并对其进行处理。例如，你可以向字符串发送 -UTF8String 消息，然后处理返回的 C 字符串。尽管这听起来合理，但请记住字符串可能非常大，并且可能不是以 UTF-8 存储的，因此对象可能需要将其内部表示转换为 UTF-8，分配内存进行存储，稍后由自动释放池（autorelease pool）或垃圾回收器清理这些内存。

访问字符串字符最高效的方法是 -getCharacters:range:。Objective-C 中以 get 开头的方法通常接收一个指向调用者分配的空间的指针，并返回其中的数据。在这种情况下，第一个参数是一个指向 unichar 缓冲区的指针，该缓冲区必须足够大以存储请求数量的字符。

下一个示例使用了这种机制来统计源文件中分号的数量。首先，它将源代码加载到字符串中，然后每次获取十个字符。注意这种双重循环结构。外层循环获取字符块，然后内层循环遍历该块。当你使用快速枚举（fast enumeration）来遍历集合时，编译器也会生成相同的结构。

这每十个字符需要发送一次消息。你可以通过增加缓冲区的大小，用更多的空间来换取更快的速度。注意，这个缓冲区是分配在栈上的。这种方式很快，但你应该小心确保设置了范围（range）。

```objc
int semicolons = 0;
NSUInteger length = [str length];
NSRange range = { 0, 10 };
while (range.location < length) {
    char buffer[10];
    if (range.location + range.length > length) {
        range.length = length - range.location;
    }
    [str getCharacters: buffer range: range];
    range.location += 10;
    for (unsigned i=0; i<range.length ; i++) {
        char c = buffer[i];
        if (c == ';') {
            semicolons++;
        }
    }
}
printf("Source file contained %d semicolons\n", semicolons);
```

在 OpenStep 中，NSString 上最常用的两个方法是 -cString 和 +stringWithCString::。它们在 C 字符串和 Objective-C 字符串之间进行转换。这些方法的问题在于 C 字符串是不感知编码的。

C 字符串是一个字节数组。你可以在其中存储你喜欢的任何类型的字符数据。对其进行所有操作都是外部定义的，因此对字符编码的知识是字符串之外的（extrinsic）。这与 Objective-C 字符串的工作方式恰相反。

当你将 C 字符串转换为 Objective-C 字符串或反之时，它必须知道 C 字符串的编码是什么。C 标准库函数检查环境变量来确定这应该是什么。遗憾的是，这导致了各种问题。如果你从套接字（socket）或文件读取某些数据，然后用这些函数从其构建 Objective-C 字符串，你得到的是用户选择的文本编码，而不是创建文件的人所选择的编码。

这些方法现在已弃用，取而代之的是带有明确编码参数的方法。需要记住的一点是，任何多字节编码的默认值都是大端（big-endian），这在 Objective-C 流行的 Motorola 68000 系列和 RISC 工作站是有意义的，但在小端 x86 处理器上就不那么合理了。

在使用某些拉丁字母变体的国家，最常见的文本编码是 UTF-8。这允许你用一个字节表示任何 ASCII 字符，用两个字节表示大多数其他常见字符。NSString 提供了用于方便的方法来获取和设置 UTF-8 编码的数据：-UTF8String 和 +stringWithUTF8String:。在大多数代码中，每当你与 C 字符串进行转换时，都可以使用这些方法。

要从其他编码的 C 字符串创建字符串对象，你可以使用 +stringWithCString:encoding: 方法。

该方法的第一个参数是 C 字符串，第二个参数是表示编码的枚举类型成员。如果数据来自旧的 Mac，你可能想使用 NSMacOSRomanStringEncoding，这是在 Mac OS 获得 Unicode 支持之前的默认编码。如果你需要与旧的 Windows 系统相互操作，WindowsCP1252StringEncoding 是你在大多数地区需要的编码。较新的 Windows 系统将使用 UTF-16，但它们更偏于小端版本，UTF16LittleEndianStringEncoding。

如果你在特定的编码中存储字符串数据，通常会使用 NSData 实例而不是指针。这是一个非常简单的类，它封装了一个内存区域：一个指针和一个大小。因为它是一个对象，你可以对它进行内省（introspection），使用引用计数处理销毁，并将其存储在集合中。这使得在许多情况下，它比直接使用指针更方便。

## 修剪字符串

```objc
NSString *str = @" a String with leading spaces";
str = [str stringByimmingCharactersInSet:[CharacterSet whitespaceCharacterSet]];
str = [str substringFromIndex:2];
NSAssertisEqualTo(str, @"String with leading spaces", "Trimming failed");
```

来自：trim.m

通常，当你有一个字符串时，你想修剪两端，移除固定数量的字符或来自特定集合的字符。第二种情况的一个常见例子是移除字符串开头和结尾的空白字符。

Objective-C 字符串对象支持许多方法来实现此。如果你只是想移除字符串末尾或开头的字符，NSString 的 -substringWithRange: 方法是最有用的。它创建一个包含另一个字符串中范围字符的新字符串对象。这对于不可变字符串来说是一个非常廉价的操作；它只是返回一个引用原始字符串数据的字符串对象，不会复制字符串。然而，当你在可变字符串上调用它时，它必须复制字符。移除来自特定集合的字符，你需要了解 NSCharacterSet 对象。正如其名所示，该类封装了一个字符集
