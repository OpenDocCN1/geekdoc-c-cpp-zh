
你现在可以按名称获取协议并对其进行检查。这在旧模型中曾经是可行的，但它取决于编译器是否已经输出了该协议的完整定义。

你可以使用 `@protocol()` 关键字获取协议的引用。此操作的主要目的是测试协议的遵从性。

```
if (![delegate conformsToProtocol: @protocol(DelegateProtocol)]
{
testIndividualMethods = NO;
}
```

你可能会在设置代理（delegate）的方法中使用类似下面的代码段。如果代理符合该协议，则可以保证它已经实现了该协议中的所有方法，因此你不需要测试每一个方法。如果它不符合，你可能需要在发送每条消息之前对每条消息进行测试。

协议为你提供了编译时和运行时的类型检查。你可以通过在类型名后的角括号中放入名称来要求一个对象符合某个协议。以下是一些示例：

```
id <NSCopying> a;
id <NSObject, NSCopying> b;
Object<NSCopying> *c;
```

在这里，你可以将任何实现了 `NSCopying` 协议的对象赋值给 **a**。赋值给 **b** 的对象也必须实现 `NSObject` 协议，任何继承自 NSObject 的对象都会自动实现它。最后，c 必须是 NSObject 的子类并且必须实现 NSCopying 协议。

如果你将一个对象赋值给要求它符合某个协议的变量，但该协议不在声明列表中，编译器将生成警告而不是错误。这不是硬性错误，因为尽管它没有声明协议遵从性，但它仍然实现了该协议所要求的所有方法。

## 向类中添加方法

```
@interface NSObject (Logging)
- (void)log;
@end
@implementation NSObject (Logging)
- (void)log
{
NSLog("@%@@", self);
}
@end
```
来自：logging.m

Objective-C 与 C++ 或 Java 等语言之间的最大区别之一是分类（categories）的概念。这些在 Smalltalk 中就已经存在，但它是作为一种将方法分组以便的方式。在 Objective-C 中，它们允许你向类添加方法，即使你没有该类源代码的权限。

分类定义的结构与类定义相似。分类不能改变类的实例变量，也不能改变其父类，因此 @interface 指令中的这些部分被省略了。在类名后的方括号中会添加分类名称。在前面的代码中，你可以看到一个简单的分类接口和实现，它为 NSObject 添加了一个 -log 方法。然后，你可以向任何对象发送 -log 消息并将其打印到控制台。

注意，分类的接口和实现都是可选的。在下一节中，我们将查看指定了分类接口但没有对应实现会有什么用处。如果你只想替换对象中的方法，那么在不指定接口的情况下指定实现是有用的。

在分类中声明的方法将替换在类中声明的同名方法。这种顺序是有保证的，因此如果存在冲突，分类将始终具有优先级。如果有两个分类定义了相同的方法，则被使用的那一个是未定义的。

分类的一个较少被文档记录的特性是，它们允许你为类添加协议遵从性。在 Foundation 框架中，各种集合（collections）没有共同的父类，也没有实现共同的协议。在 EtoileFoundation 框架中，我们为它们都添加了分类，使它们采用了 Collection 协议。这允许我们在需要某些集合但并不不在乎具体是哪种类型的地方使用该协议。

```
@protocol Collection
- (BOOL)isEmpty;
@end
@interface NSArray (Collection) <Collection> @end
@interface NSSet (Collection) <Collection> @end
@implementation NSArray (Collection)
- (BOOL)isEmpty
{
    return [self count] == 0;
}
@end
@implementation NSSet (Collection)
- (BOOL)isEmpty
{
    return [self count] == 0;
}
@end
```
来自：collection.m

collection.m 的示例展示了这种方法的（非常）简化版本。Collection 协议被添加到了 NSSet 和 NSArray 类中。如果你向这些类的实例发送一个 -conformsToProtocol: 消息，并将 @protocol(Collection) 作为参数，它将返回 YES。

分类有一个特殊情况，即你声明了一个没有名称的分类接口。这被称为“类扩展”（class extension）。与其他应该配有单独指定了分类名称的独立 @implementation 指令的分类不同，在类扩展中声明的方法预计会出现在类的主 @implementation 指令中。你可以用它来前向声明私有方法。

在最现代的 Objective-C 编译器中，你还可以在类扩展内部声明实例变量。你也可以在 @implementation 上下文中声明实例变量，就像在 @interface 上下文中做的那样。这两个机制允许你将实现细节从公共头文件中移出。

如果你正在声明私有实例变量，那么你应该在 @implementation 上下文中声明它们。这确保了不应该访问它们的内容不会意外访问。如果你正在声明公共或受保护的实例变量，且它们应该只在同一个库内访问，那么你应该在私有头文件中的类扩展中声明它们。在新代码中，你应该只在公共头文件中声明预计会被代码用户直接访问的实例变量。

## 使用非正式协议

```
@interface NSObject (InformalProtocol)
- (id)doSomething;
@end
// 仅限 Objective-C 2:
@protocol InformalProtocol
@optional
- (id)doSomething;
@end
```
来自：informalProtocol.m

通常情况下，你想要定义一组希望对象实现的方法，但这些方法是可选的。这在代理中为常见，你需要在发送消息之前使用 -respondsToSelector: 测试对象是否真的实现了该方法。

在 Objective-C 2 之前，通常使用分类来实现非正式协议。如果为 NSObject 创建了接口但没有提供实现，那么编译器将假设每个对象都响应接口中声明的消息，因此当你向对象发送其中任何一个消息时，不会生成警告。

## 使用声明属性合成方法

```
@interface Integer : NSObject
@property (nonatomic,assign) int integer;
@end
@implementation Integer
@synthesize integer;
@end
```
来自：synth.m

Objective-C 2 的大改进之一是声明属性。这些允许你定义某些语义，如果你不需要特殊处理，就可以合成相关方法。

注意：点语法是 Apple 对 Objective-C 所的最具争议的变化之一。它违反了 Objective-C 的核心原则之一——新语义应该始终使用新语法——通过重用结构体字段访问语法来发送消息。点语法对于隐藏糟糕的设计也有用；它鼓励间接引用，这违反了迪米法则。

属性还引入了一些新语法。它们是通过消息实现的。本章开始的示例将创建 -integer 和 -Integer 方法。你可以像调用任何其他方法一样调用它们，也可以使用点语法，如下：

```
obj.integer = 12;
int i = obj.integer;
obj.integer += 42;
```

最后一种情况是最有。将其扩展为传统的 Objective-C 消息语法看起来像这样：

```
[obj setObject:[obj integer] + 42];
```

值得注意的是，这两种生成的代码完全相同。前者看起来更高效，但事实并非。在两种情况下，你都有两次消息发送和一次加法。如果 obj 是 C 结构体，这会昂贵得多。

**注意：** “属性”（property）一词在 Smalltalk 文档中指代任何通过访问器操作的实例变量。它在稍旧的 Objective-C 文档中也以相同的方式使用。指定声明属性（declared properties）而不是属性有助于减少这种歧。

属性声明包含两个部分：接口和实现。接口定义了属性的名称和类型，正如你预期的那样，但它还定义了一些高级语义。
