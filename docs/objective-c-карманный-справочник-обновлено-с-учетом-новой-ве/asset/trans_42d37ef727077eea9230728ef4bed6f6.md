## 理解对象模型

Objective-C 拥有类似于 Smalltalk 的对象模型。如果你来自 Java，你会发现这非常容易理解。如果你来自 Simula 家族语言（如 C++），你可能会觉得稍微困难一点。

艾伦·凯（Alan Kay）将对象的概念描述为一种简单的还原法练习。在解决问题时，你想将其分解为简单的部分。能够运行程序一部分的最简单东西与运行整个程序的东西是同一个：计算机。在艾伦·凯的愿景中，对象是简单的计算机模型，通过交换消息进行通信。

这正是 Objective-C 及其父语言 Smalltalk 中对象的行为方式。它们是程序的孤立部分，它们之间传递消息。通常，这些消息是同步传递的，因此它们的行为有点像函数调用，但重要的是要意识到它们是不同的。

消息是函数调用更高层次的抽象。函数调用非常简单。在许多类类 RISC 的架构上，你将返回地址推入栈中，然后跳转。在所有情况下，目标地址都是固定的。

当你发送消息时，如何处理它完全取决于接收者。最典型的方式是调用与消息同名的方法，但也有其他替代方案。代理对象可能会将消息转发给另一个对象，并且在转发之前可能会对消息参数进行某些替换。

Simula 没有使用“面向对象”这一术语，但许多在 Smalltalk 之后出现的类 Simula 语言都采用了该术语，导致了某些混淆。这一家族的语言（如 C++）使用虚函数表（vtables）来实现某些表面上相似的功能。

Simula 风格的对象包含一个指向其 vtable 的指针（如果有父类，则指向多个 vtables）。当你调用虚函数时，编译器会创建一个指向 vtable 的偏移量，然后调用该偏移量处的函数。

这种差异的副作用之一是，Objective-C 和 C++ 中的指针转换具有非常不同的语义。在 Objective-C 中，当你将指针从一个对象类型转换为另一种类型时，不会生成代码。该转换只是对编译器类型检查器的一个提示。然而，在 C++ 中，指针转换会执行某些指针算术，以便传递转换后指针的代码能够在正确的位置找到 vtable。这意味着在 Objective-C 中，你可以将任何对象类型转换为任何其他对象类型，而在 C++ 中，你需要使用特殊的转换方式。

这种区别非常重要。在 Objective-C 中，影响方法查找的唯一因素是对象的类型。在 C++ 和其他 Simula 家族语言中，查找还受到编译器认为的对象类型的影响。

## 两个类型系统的故事

让接触 Objective-C 的人员感到困惑的问题之一是它有两个类型系统。如果你将原始实现视为一个预处理器，那么这是合理的。Objective-C 预处理器会执行类似 StrongTalk¹ 的类型检查，然后 C 编译器会执行 C 类型检查。

> ¹StrongTalk 是 Smalltalk 的一种方言，增加了可选的静态类型检查。创建该语言的团队后来去开发 Java。StrongTalk 是最快的 Smalltalk 实现，但编译器没有使用静态类型信息进行优化。

C 拥有结构化类型系统。原始数据类型的类型等价取决于两个类型是否具有相同的表示。复杂类型永远不会被视为等价。

Objective-C 增加了代数类型系统。对象的类型由其签名定义：即它声称将响应的消息。你可以隐式地将一个 Objective-C 对象转换为其父类，因为保证会响应父类理解的所有消息。

你可以显式地将对象转换为其他类型。例如，你可以将一个字典对象转换为数组对象。只要你之后只向它发送字典和数组都能理解的消息，这就能正常工作。

## C 就是 Objective-C

Objective-C 最重要的特性之一是它是 C 的纯超集。你可以将 C 视为嵌入在 Objective-C 中用于低级任务的领域特定语言，将 Smalltalk 的子集视为嵌入在 Objective-C 中用于高层任务的领域特定语言。

使用纯 C 解决问题并没有错。许多人在学习 Objective-C 时犯的错误之一是，假设他们必须停止使用 C。对于很多事情，C 的解决方案才是正确的。

**注意：** Objective-C 还有一个姐妹语言 Objective-C++，它与 C++ 的关系就像 Objective-C 与 C 的关系。Objective-C++ 是 C++ 的纯超集，允许你从 Objective-C 对象中调用 C++ 代码，反之亦然。因为它们拥有完全不同的对象模型，你不能用 C++ 派生 Objective-C 类，反之亦然；然而，你可以将 Objective-C 对象的指针作为 C++ 对象的字段。你可以在 Cocoa 框架中看到这一点。并不是所有都是对象。如果你请求字符串中的字符范围，你将使用 `NSRange` 结构体。这是一个 C 结构体——而不是 Objective-C——包含一个位置和一个长度。点、矩形和其他几个东西也以类似的方式表示。如果这些都是对象，你将使用更多的内存，速度更慢，并且不会获得任何灵活性。

Ingalls 测试²认为你应该能够创建一个新的整数类型，并将其用于屏幕窗口定位。Objective-C 没有通过这项测试，但这在现实世界中并不是一个很有用的例子，因为大多数时候设计新的整数类型会破坏许多期望标准行为的东西。

> ^²以丹·英格斯（Dan Ingalls）命名，他是 Smalltalk 的设计者之一，并提出了该测试。

在 Objective-C 中，你不需要在不需要的地方使用动态行为（例如延迟绑定和多态性）。

## 语言与库

对于非常动态的语言，很难在语言和库之间划定界限。在 Smalltalk 中，语言中没有等同于 if 的语句。标准库定义了 True 和 False 单例类，它们响应带有闭包参数的 -ifTrue: 消息。所有复杂的控制结构（如循环或枚举）都是基于此实现的。

Objective-C 从 C 继承了流程控制，但所有的动态行为都由运行时库提供。这与 C 或 C++ 不同。你可以编译一个不调用 libcstdc++ 中任何函数的无限制 C 或 C++ 二进制文件。然而，每一个不是纯 C 程序的 Objective-C 程序必须链接 `libobjc` 才能工作。
