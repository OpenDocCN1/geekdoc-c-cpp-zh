## Overriding the equality

The default implementation of == and != for a class looks at the address. For a struct, the == and != operators examine the fields. This is one of the fundamental differences between reference type and value type.

The default implementation of == and != for a struct uses a generalized technique known as reflection to discover the fields, it can be slow, especially if you are comparing thousands of structs. For this reason, you may want to provide your own implementation of this method for the equality operators to work as expected.

When you use an object as a key in a hash table, for example, the GetHashCode method is called on the object to help calculate a hash value. For more information, see the .NET reference documentation supplied with Visual Studio 2022. All this method needs to return a distinguishing integer. Don't return the same integer from the GetHashCode method of all your objects, however this will nullify the effectiveness of hashing algorithms.

Finally, if you're creating a record type, don't override the default implementations of operator == and !=. Records automatically implement value equality; this is one of the main reasons for using a record. Consider defining a record instead of a struct when your type models data and implement value equality.
