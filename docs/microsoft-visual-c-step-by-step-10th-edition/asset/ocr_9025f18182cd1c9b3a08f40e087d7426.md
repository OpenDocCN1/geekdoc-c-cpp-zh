# Generics and constraints

Occasionally, you'll want to ensure that the type parameter used by a generic class identifies a type that provides certain methods. For example, if you're defining a PrintableCollection class, you might want to ensure that all objects stored in the class have a Print method. You can specify this condition by using a constraint.

By using a constraint, you can limit the type parameters of a generic class to those that implement a particular set of interfaces and therefore provide the methods defined by those interfaces. For example, if the IPrintable interface defined the Print method, you could create the PrintableCollection class like this:

Click here to view code image

```
public class PrintableCollection<T> where T : IPrintable
```

When you build this class with this type parameter, the compiler checks to ensure that the type used for T actually implements the IPrintable interface; if it doesn't, it stops with a compilation error.

You can also force the type parameter to be a struct value type rather than a class by using the struct constraint:

Click here to view code image

```
public class StructCollection<T> where T : struct
```

The class constraint is similar, except that it ensures that the type parameter is a reference type (a class).
