```
private double readDouble(string v)

    Console.Write(v);
    string line = Console.ReadLine();

}
```

This block of code displays the string in variable v on the screen. This variable is the string parameter passed in when the method is called; it contains the message prompting the user to type in the daily rate.

> Note
Console.Write method is similar to the Console.WriteLine statement that you used in earlier exercises, except that it does not output a newline character after the message.

The user types a value, which is read into a string using the ReadLine method and converted to a double using the double.Parse method. The result is passed back as the return value of the method call.

> Note
ReadLine method is the companion method to WriteLine; it reads user input from the keyboard, finishing when the user presses the Enter key. The text typed by the user is passed back as the return value. The text is returned as a string value.

# Using the Visual Studio Debugger to step through methods

Visual Studio provides powerful debugging features that enable you to see how application is executing on a line-by-line basis. This is useful when you need to understand why your program isn't running as expected or if you want to see how application logic flows through the various methods.

In the next exercise, you'll use the debugger to run your program in slow motion. You'll see when each method is called (stepping into the method) and then see each return statement transfers back to the caller (also known as stepping out of the method). While you are stepping into and out of methods, you can use the tools on the Debug toolbar. However, the same commands are also available on the Debug menu when application is running in debug mode.
