For simple properties, you can use expression-bodied members rather than full-blown method syntax for get and set accessors. For example, you can simplify the x and y properties shown in the previous example like this:

```
public int X
{
    get => this._x;
    set => this._x = rangeCheckedX(value);
}

public int Y
{
    get => this._y;
    set => this._y = rangeCheckedY(value);
}
```

Notice that you don't need to specify the return keyword for the get accessor, you simply provide an expression that is evaluated every time the property is read. This syntax is less verbose and arguably more natural, although functionally the properties perform the same task. It's a matter of personal preference as to which you should use, but for simple properties, I recommend adopting the expression-bodied syntax. Of course, you can mix and match; you you could implement a simple get accessor as an expression-bodied member, but a more complex set accessor could still utilize the method syntax.
