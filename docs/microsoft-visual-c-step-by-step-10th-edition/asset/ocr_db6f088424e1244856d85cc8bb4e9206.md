```
Console.WriteLine(i.Value);
}
```

In Chapter 4, "Using decision statements," you saw that the NOT operator (!) prevents a Boolean value. The preceding code fragment tests the nullable variable i, and if it does not have a value (it is null), it assigns the value 99; otherwise, it displays the value of the variable. In this the HasValue property does not provide any benefit over testing for a null value directly. Additionally, reading the Value property is a long-winded way of reading the contents of the variable. However, int is a very simple nullable. You can create more complex value types and use them to declare nullable variables where the advantages of HasValue and Value become more apparent. You'll see some examples in Chapter 9, "Creating value types with enumerations and structures."

> The Value property of a nullable type is read-only. You can use this property to read the value of a variable but not to modify it. To update a nullable variable, use an ordinary assignment statement.
