# Propagating exceptions

Adding a try/catch block to the addValues method has made that method other than robust, but you need to apply the same exception handling to the other methods: subtractValues, multiplyValues, divideValues, and remainderValues. The code for each of these exception handlers will likely be very similar, resulting in you writing the code in each method.

Each of these methods is called by the calculateClick method when the user selects the Calculate button. Therefore, to avoid duplication of the exception-handling code, it makes sense to relocate it to the calculateClick method. If FormatException occurs in the subtractValues, multiplyValues, divideValues, or remainderValues method, it will be propagated to the calculateClick method for handling as described in the section "Unhandled exceptions" earlier in this chapter.

# Using checked and unchecked integer arithmetic

Chapter 2 discussed how to use binary arithmetic operators such as + and on primitive data types such as int and double. You should also recall that the primitive data types have a fixed size. For example, a C# int is 32 bits. Because int has a fixed size, you know exactly the range of values that it can hold: 2147483648 to 2147483647.

> Tip
If you want to refer to the minimum or maximum value of int in code, you can use the int.MinValue or int.MaxValue properties.

The fixed size of the int creates a problem. For example, what happens if you add 1 to an int whose value is currently 2147483647? The answer is that it depends on how the application is compiled. By default, the C# compiler generates code that allows the calculation to overflow silently, and you get the wrong answer. (In fact, the calculation wraps around to the largest negative integer value, and the result generated is -2147483648.) The reason for this behavior is performance: integer arithmetic is a common operation in almost every program, and adding the overhead of overflow checking to each integer expression could lead to very poor performance. In many cases, the risk is acceptable you know (or hope!) that your int values won't reach their limits. If you don't like this approach, you can turn on overflow checking.

> > Tip
You turn overflow checking on and off in Visual Studio 2022 by setting the project properties. In Solution Explorer, select YourProject (where YourProject is the actual name of the project). On the Project menu, select YourProject Properties. In the Project Properties dialog, select the Build tab. Select the Advanced button in the lower-right corner of the page. Finally, select the Advanced Built Settings dialog, select or clear the For Arithmetic Overflow/Underflow checkbox.

Regardless of how you compile an application, you can use the checked and unchecked keywords to turn on and off integer overflow checking in parts of an application that you think need it (or don't). These keywords override the compiler option specified for the project.

# Writing checked statements

A checked statement is a block preceded by the checked keyword. All integer arithmetic in a checked statement always throws an OverflowException if an integer calculation in the block overflows, as shown in this example:

Click here to view image

```
int number = int.MaxValue;
checked{
    int intWillThrow = number++;
    Console.WriteLine("This will not be reached");
}
```

> > Important
Only integer arithmetic directly inside the checked block is subject to overflow checking. For example, if one of the checked statements is a method call, checking does not apply to called method.

You can also use the unchecked keyword to create an unchecked block. All integer arithmetic in an unchecked block never throws OverflowException. For example:

```
int number = int.MaxValue;
unchecked
{
    int intWillThrow = number++;
    Console.WriteLine("This will be reached");
}
```

# Writing checked expressions

You can also use the checked and unchecked keywords to control overflow checking on integer expressions by preceding just the parenthesized expression with the checked or unchecked keyword, as shown in these examples:

Click here to view image

```
int wontThrow = unchecked(int.MaxValue + 1);
int willThrow = checked(int.MaxValue + 1);
```

The compound operators as += and -- and the increment (++) and decrement--) operators are arithmetic operators and can be controlled using checked and unchecked keywords. Remember, x += y is the same as x = x + y.

> Important
You cannot use the checked and unchecked keywords to control floating-point(noninteger) arithmetic. The checked and unchecked keywords apply only to integer arithmetic using data types such as int and long. Floating-point arithmetic never throws Overflow exceptions—not even when you divide by 0.0. (Remember from Chapter 2 that .NET has a special representation for infinity.)
