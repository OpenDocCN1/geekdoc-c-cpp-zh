
```csharp
var anotherAnonymousObject = new Name { Age = 53 };
```

The C# compiler uses the names, number, and order of the fields to determine whether two instances of an anonymous class have the same type. In this case, the variables myAnonymousObject and anotherAnonymousObject have the same number of fields, with the same name and type, in the same order, so both variables are instances of the same anonymous class. This means you can perform assignment statements such as this:

Click here to view code image

```csharp
anotherAnonymousObject = myAnonymousObject;
```

> Note
Be warned that this assignment statement might not accomplish what you expect! You'll learn more about assigning object variables in Chapter 8.

There are quite a few restrictions on the contents of an anonymous class. For example, anonymous classes can contain only public fields, the fields must all be initialized, they cannot be static, and you cannot define any methods for them. You'll use anonymous classes periodically throughout this book and learn more about them as you do.

# Copying type variables and classes

Most of the primitive types built into C#, such as int, float, double, and char (but not string, for reasons that will be covered shortly), are collectively called value types. These types have a fixed size, and when you declare a variable as a value type, the compiler generates code that allocates a block of memory big enough to hold a corresponding value. For example, declaring an int variable causes the compiler to allocate 4 bytes of memory (32 bits) to hold the integer value. A statement that assigns a value (such as 42) to the int causes the value to be copied into this block of memory.

Class types such as Circle (described in Chapter 7) are handled differently. When you declare a Circle, the compiler does not allocate memory for the object itself but instead allocates memory for a reference that holds the address of the object. When you use the `new` keyword, the object is created on the heap and the reference is assigned the address of that object.

When you assign one reference variable to another, you are copying the address, not the object itself. This means that both variables point to the same object in memory. Changes made to the object through one reference will be visible when using the other reference. Here's an example in code:

```csharp
Circle c1 = new Circle(10);
Circle c2 = c1;
c2.Radius = 20;
Console.WriteLine(c1.Radius); // Outputs 20
```

If you set a reference variable to `null`, the variable no longer points to any object. The object it previously pointed to may no longer referenced by any other variables and can be reclaimed by the garbage collector.

If you assign a new object to a reference variable, the variable now points to the new object, and the original object is no longer pointed to by that variable. Changes made to the new object through the variable will not affect the original object. Here's an example in code:

```csharp
Circle c1 = new Circle(10);
Circle c2 = c1;
c2 = new Circle(20);
Console.WriteLine(c1.Radius); // Outputs 10
```

The difference between value types and reference types is fundamental. When you assign one value type to another, the actual data is copied. When you assign one reference type to another, only the address is copied. This means that value type variables are independent of each other, while reference type variables can share the same object.
