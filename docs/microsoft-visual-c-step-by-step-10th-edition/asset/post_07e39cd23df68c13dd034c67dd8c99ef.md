
For example, result, _score, footballTeam, and plan9 are all valid identifiers, whereas result%, footballTeam$, and 9plan are not.

> **Important**

## Using variables

A variable is a storage location that holds a value. You can think of a variable as a box in the computer's memory that holds temporary information. You must give each variable in a program an unambiguous name that uniquely identifies it in the context in which it is used.

You use a variable's name to refer to the value it holds. For example, if you want to store the value of the cost of an item in a store, you might create a variable called cost and store the item's cost in this variable. Later, if you refer to the cost variable, the value retrieved will be the item's cost that you stored.

## Naming variables

You should adopt a naming convention for variables to help avoid confusion concerning the variables you defined. This is especially important if you are part of a project with several developers working on different parts. A consistent naming convention helps to avoid confusion and reduce bugs. The following list contains some recommendations:

- Don't start an identifier with an underscore. Although this is legal in C#, it can limit the interoperability of your code with other languages, such as Visual Basic.
- Don't create identifiers that differ only by case. For example, don't create one variable named myFunction and another named MyVariable because it's too easy to confuse one with the other.
- Start the name with a lowercase letter.
- In a multi-word identifier, start the second and subsequent word with an uppercase letter (This is called camelCase).
- Don't use Hungarian notation (If you are a C++ developer, you're probably familiar with Hungarian notation. If you don't know what it is, don't worry about it!).

For example, score, _score, and FootballTeam are all valid, but only the first is recommended.

## Declaring variables

Variables hold values. C# has many different types of values that it can store and process: integers, floating-point numbers, and strings. When you declare a variable, you must specify the type of data it will hold. Always, you must terminate the statement with a semicolon.

```int age;
```

> Note
If you're a Visual Basic programmer, you should note that C# does not allow implicit declarations. You must explicitly declare all variables before you use them.

After you've declared your variable, you can assign it a value. The statement that follows assigns the value 42 to the variable. The equal sign (=) is the assignment operator, which assigns the value on its right to the variable on its left. After this assignment, you can use the age variable in your code to refer to the value it holds. If you leave the mouse pointer over the variable in the Visual Studio 2022 Code and Text Editor window, a ScreenTip indicates the type of the variable. The next statement writes the value of the age variable (42) to the console:

```csharp
Console.WriteLine(age);
```

## Specifying numeric values

It's important to understand the impact of variable type on the data a variable can hold and how this data is handled. For example, it should be obvious that a numeric variable cannot hold a string value such as "Hello." However, in some cases, the type of value being assigned to a variable is not always clear-cut.

Take the literal value 42 as an example. It is numeric and an integer. But what happens if you try to assign this value to a non-integer type, such as a floating-point variable? The answer is that C# will convert the integer value to a floating-point value. This is relatively harmless, but it's not necessarily good practice. You should specify that you intended to treat the literal value 42 as a floating-point number and haven't mistakenly assigned it to the wrong type of variable. You can do this by appending the f suffix to the numeric literal, like this:

```csharp
// declare a floating-point variable
myVar = 42F; // assign a floating-point value to the variable
```

How about the value 0.42? What is the type of this expression? The answer is that, like numeric literals that include a decimal point, it is actually a double-precision-point variable, referred to as double. In the next section, you'll see that a double has a bigger range and greater precision than a float. If you want to assign the value 0.42 to a float, you must apply the F suffix (the C# compiler insists on this):

```csharp
myVar = 0.42F;
```

C# has other numeric types: long integers, which have a bigger range than integers, and decimals. (Floats and doubles hold exact decimal values but be subject to rounding and other approximations when they are involved in calculations.) You should use the L suffix to assign a numeric literal value to a long integer, and the M suffix to assign a numeric literal value to a decimal.

This might seem like a trivial point, but it is surprising how many subtle errors creep into a program by accidentally assigning a value of the wrong type to a variable. Consider what might happen if you attempt to perform a calculation that involves a large number of significant decimal places and store the results in a float. In the worst case, this could lead to truncating data, causing errors in calculations. For example, if your program was a guidance application for a space-probe, such errors could cause it to completely miss Mars and to head off to the deeper depths of the solar system instead!
