While in many cases this is strictly undefined behaviour, it is such a common practice that many compilers will allow it. Even if the compiler does prevent a direct cast, the C Standard allows any pointer to be cast to a pointer to and a pointer void to be cast to a pointer to any other type.

An alternative method of type punning is to write to a union member of one type and subsequently read the data from a member of another type. This also results in undefined behaviour according to the C Standard but is another example of a widespread practice that most compilers will allow. Type punning is sometimes necessary, but the problem with the available methods is that they rely on multiple implementation defined and unspecified behaviours, so they are far from guaranteed to behave the way you expect them to. Furthermore, using these methods, you can bypass the type system entirely. When you do need to use type punning, there are some steps you can take to make it safer; we will explore these later.

Any function that returns a pointer to void (and almost any function that expects to be passed one when called) exposes a type safety risk, including those included in the C Standard Library. Such functions should be used with care. Notable examples in the C Standard Library are malloc, calloc and realloc – as a consequence of this, dynamic memory allocation is not type safe in C.
