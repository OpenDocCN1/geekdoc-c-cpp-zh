# Endnotes for Chapter 6 - Data Security and Integrity

1 Jewish scholars, as early as the 7th Century, had developed ways of ensuring that copies of the Tanakh (Hebrew Bible) were accurate reproductions of the original — although superficially bearing no resemblance to modern methods (and nothing more than a curious aside in the history to communication), the generally principles are not entirely unrelated to each other.

2 If you feel you must know, start by looking up polynomial arithmetic and particularly polynomial long division.

3 Passwords should never be stored in plaintext; this is one of the most common mistakes in data security and, given that it is well documented and understood, is completely inexcusable. It’s also best to add a “salt” to the password before hashing — this is an arbitrary value, which can be stored alongside the hash, that adds some additional security against comparing the hash against other hashes generated using the same password. The salt can be stored in plaintext, since the hash function is irreversible so the salt alone is useless; however, if multiple password hashes are stored, each should still have its own salt.

4 Specialised hardware often exists to perform error correction for you – if it is available, use it rather than writing code to do the job.
