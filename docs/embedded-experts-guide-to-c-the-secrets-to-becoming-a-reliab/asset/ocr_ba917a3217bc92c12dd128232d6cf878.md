# The compilation stage

The compiler is responsible for translating source code into a format which can be understood by the target platform. This may take place in two stages: a compiler may first translate source code statements into a series of assembly statements and then call an assembler to translate the result into binary opcodes. Since there is generally a very close (often one-to-one) relationship between instructions in assembly and opcodes, the compiler may be able to generate machine code directly without the intervention of an assembler. The programmer is rarely interested in the finer details of the process, so for simplicity, we will assume the latter scenario.

Before translating statements, it is first necessary to convert any literals into a format which can be stored on the target. While this is unlikely to be of much significance for numeric literals, string literals do require some manipulation. Phase 5 of the translation process involves mapping the characters used for writing the source code into the execution character set. This is a distinct step from the character mapping in Phase 1.

Firstly, the character set understood by the compiler need not be the same as the execution character set, although in most cases it is probably safe to assume both support at least the basic ASCII characters.
