Unfortunately, the language used for linker scripts is not standardised and many vendors have developed their own language and syntax to work with their linker. Nonetheless, since all linkers perform the same function, there is some commonality between them and once the principles of one are understood, it should be possible to translate the scripts from one linker to another. Fortunately, many linkers are based on the Unix linker, ‘ld’, which makes this worthwhile considering in a little more detail. If you intend to do any further reading on this subject, you will probably find most readily available information refers to the GNU rather than the Unix version; from the perspective of learning how to use it, this is not a major

There is quite a lot more to writing linker scripts than is described here, and since it is a task which you hopefully won’t find yourself repeating too often, we will introduce some of the more important features and concepts, and allow you to investigate further if you wish.

# Memory regions

The MEMORY command is used to define memory regions. As well as giving each region a name and setting its size and start address, you can set attributes to let the linker know how the region can be used – whether it is a read only or read-write and whether or not it can contain executable instructions.

A linker script may contain only one use of the MEMORY keyword, but multiple regions may be defined at once.
