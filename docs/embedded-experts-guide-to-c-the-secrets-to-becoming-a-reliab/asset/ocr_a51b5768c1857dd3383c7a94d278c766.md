"token pasting" operator, is used to combine two tokens into one. The defined operator is not much use within definitions but may be used elsewhere to check whether a macro has been defined; it is common when performing conditional compilation, i.e. deciding which code to compile based on some criteria which is known at compile-time but not necessarily before.

Object-like macros are often used to define constants with symbolic names. This is generally considered a part of good practice since it avoids the use of "magic numbers" – numbers which appear in source code with no clear origin or meaning. It also allows those constants to be changed without having to search through the entire source for each instance.

These constants do not have a type, nor are they limited to only representing a value. Each instance of the macro in the code is replaced with the text of the macro and the macro may therefore contain anything, including multiple complete statements, provided the result when expanded is valid A macro may even reference another macro, in which case the preprocessor will attempt to iteratively replace the macro instances until all are fully resolved. It is also acceptable to define an empty macro. Although these expand to "0" by default, in practice they are rarely (and should never be) used in this way; instead, it is common to check whether the definition exists as a means of controlling other preprocessor operations. In such instances, the value of the macro is unimportant.
