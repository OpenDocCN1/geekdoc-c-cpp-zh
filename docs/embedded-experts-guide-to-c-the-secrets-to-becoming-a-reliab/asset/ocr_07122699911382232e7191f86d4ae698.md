Common, but non-standard directives include #pragma once and #pragma #pragma once is used as an alternative to include guards to indicate a file which should be included only once; personally I never bother with it, since it is non-standard and as a result the include guards are still required. In theory, it should result in a reduction in compilation times, although I suspect the actual impact is small for most modern compilers. #pragma pack is used to alter the alignment of variables in memory – it accepts an integer argument to determine the amount of padding between variables in memory which do not fill all the space between two memory boundaries. While this can improve memory efficiency to an extent, it almost invariably comes at the cost of increased code size and decreased speed, so this is not really a good reason to use it unless memory is in particularly short supply. You may also come across #pragma which is used to manually exercise control over the amount of loop unrolling the compiler performs. While loop unrolling is a valid optimisation technique, the compiler is often better able to recognise when it will be beneficial, so overriding the default behaviour should be done with care.

Other common uses for #pragma directives include disabling specific compiler warnings or issuing custom errors or warnings.
