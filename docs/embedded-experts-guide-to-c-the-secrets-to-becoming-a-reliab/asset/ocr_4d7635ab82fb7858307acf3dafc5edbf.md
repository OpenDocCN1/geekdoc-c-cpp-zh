If the scheduler forces a task to yield control, then the machine state must be saved – this means all register values, including the program counter and stack pointer, must be moved to non-register memory. If the next task in the queue has not already been started, the scheduler will need to create a new stack frame for the task before calling the entry function for the task (the entry function is the equivalent of the main() function for a task). If the task has previously been started, the scheduler needs to retrieve the machine state from the last time the task yielded from memory and restore it. The process of switching between tasks is commonly known as context

Dealing with a task which ceases execution through a return statement can create problems if not handled with care. Without compiler support, the return statement will be treated as it would in any other function and the stack may not be correctly restored. It is therefore essential to ensure either tasks do not return in the traditional sense and instead use a different method to cease execution, which is difficult to guarantee in practice without compiler support, or for the scheduler to manage stack restoration when tasks do return. The requirement to manipulate the stack pointer and program counter directly makes it impossible to write a pre-emptive scheduler using only the C Standard Library.

The round-robin scheduler is not the only possible scheduler you could use. It generally performs well on one metric – response time. This is the average time between a task arriving in the queue and execution of the task beginning. If we consider a different metric, turnaround time – the average time between a task arriving in the queue and finishing execution – then performance is generally poor. If we wish to improve turnaround time, then an alternative such as a Shortest Time-to-completion First (STCF) scheduler is more appropriate. Unlike a round-robin scheduler, a STCF scheduler does not regularly switch tasks by default (although it must regularly monitor waiting tasks). As the name implies, STCF scheduling works by selecting the task which is expected to take the least time to complete and runs it first.
