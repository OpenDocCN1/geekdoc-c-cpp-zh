IEEE 754, by far the most widely implemented floating point standard, also includes special values to represent infinities and not-a-number (NaN) values; these are included in the standard so that invalid operations, or those that cause an overflow, can be dealt with in a way that does return an undefined result, but does not necessarily cause either a hardware or software exception either. However, in an embedded system there is generally nothing useful you can do with these special values and it is important to check that they are not returned when performing calculations, since they generally indicate an error either in the underlying logic or the data available at run-time.

The technical details of how floating point arithmetic is implemented places restrictions on how it should be used. It is safe to perform greater-than and less-than comparisons on floating point variables, but comparing values for equality should be avoided, since the results cannot be relied upon. Nor should floating point values be used to implement loop counters; if the counter value is required in a floating point calculation, it should be implemented as an integer type and cast to the appropriate floating point type when needed. The C Standard Library header file math.h provides some functions to identify infinite and NaN values, the most obvious being the intuitively named isinf and isnan functions. Whether a compiler implements the IEEE 754 standard can be checked by looking for a definition of the __STDC_IEC_559__ macro (IEEE 754 is also known by the alternative designation IEC 60559, which lends its name to the symbol).
