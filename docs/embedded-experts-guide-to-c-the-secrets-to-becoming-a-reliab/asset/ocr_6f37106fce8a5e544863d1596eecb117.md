# There are no runtime checks in C!

Part of C’s appeal is that it typically compiles to efficient machine code; this is achieved, in part, because of the absence of any significant runtime environment and the associated software overhead. The downside of this is that no runtime checks are performed to prevent problematic code from being executed – even checks for common errors are not performed. Although in a hosted environment some code will trigger operating system intervention, this is generally very limited and, when it does occur; there is often nothing the operating system can do other than terminate the program. For standalone programs, there is no operating system to intervene. In the case of the most serious errors, hardware may behave unpredictably, become unresponsive or, in some cases, force a reset (which is, perhaps, the least problematic of possible responses!). Since the result is not desirable in either case, the programmer clearly has a motivation to include any necessary runtime checks in their code.

No code is generated to prevent null pointer dereferencing or division by zero, for instance. Nor is code produced to protect against integer overflows or a myriad of other potential problems. It may be the case that you wish to exploit integer overflow behaviour, but if you do not, it is your responsibility to prevent it, not the compiler’s.
