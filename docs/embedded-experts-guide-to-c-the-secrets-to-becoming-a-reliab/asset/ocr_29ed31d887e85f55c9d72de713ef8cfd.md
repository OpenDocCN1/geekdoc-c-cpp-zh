# Bootloaders

Another topic which has not so far been addressed is It has been assumed the intended application already resides in program memory and it can be run directly. This is often the case, but it is also possible for a program to be stored externally to program memory and loaded when the system is first activated; this is achieved using a bootloader. A more generally, is any program which loads other programs into memory so they can run; these are usually included as an essential part of most operating systems. Bootloaders are not suitable for all platforms; some microcontrollers are unable to support them and in other cases it may not be appropriate because of the type of memory or because resources are too constrained.

The primary benefit of bootloaders is they offer flexibility; the application code can be loaded from any source the bootloader understands and if multiple possible sources are present it should be possible to choose between them – a feature which could be used, for example, to implement both “normal” and “maintenance” modes. Furthermore, because the loadable code is not launched directly, it becomes possible for programs to be without the need for specialist development tools while also, with a well-designed bootloader, mitigating the risks of self-modifying code.

The most basic bootloaders serve no function other than to identify and copy the bootable program from its source into program memory before branching to the program entry point. Such a bootloader is severely limited; a functional bootloader should at least include a means of verifying the integrity of the code it is loading and determining which code should be loaded if numerous options are available.
