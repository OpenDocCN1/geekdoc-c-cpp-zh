The preprocessor is responsible for completing the first four phases of translation. The input is to the preprocessing stage is a source file and any header and source files referenced using #include directives. The C Standard names this a “preprocessing translation unit” and calls the output simply a “translation unit.”

During Phase 1, the character set used during editing is converted to a character set which the compiler can understand. Every character in the source file is mapped to a supported character in the target set. This may seem a trivial and unimportant step, but it is important to realise this is done in an implementation defined manner. If you have written the source code in an editor which supports the full Unicode codespace but your compiler is expecting ASCII, there is the possibility for information to be lost if any characters not found in ASCII are Although this may not be a major concern, it is worth restricting your editor to use only those characters supported by the rest of the tools you are using. If in doubt, choose ASCII since this is usually supported.

Any trigraphs sequences are also replaced with their single character equivalents during Phase 1. Trigraphs are a feature of the C language, intended to help programmers with keyboards which do not support some of the characters found on a standard US layout, which we have largely ignored since they are prone to cause confusion and make code more difficult to read. Even without these issues, the implementation of trigraphs in C is frankly poor and their use should be strongly discouraged. Nonetheless, it is worth being aware trigraphs are replaced at this point.
