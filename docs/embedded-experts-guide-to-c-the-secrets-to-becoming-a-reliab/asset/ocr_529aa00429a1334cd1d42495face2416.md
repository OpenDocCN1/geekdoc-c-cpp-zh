As a stand-alone statement *p++; makes sense only if the pointer is dereferenced before the increment operation – the value pointed to is neither used nor changed if the increment is performed first, which means the indirection operator is not needed. But the increment operator has a higher precedence than the indirection operator and the statement is equivalent to Any compiler will accept this statement, probably without issuing a warning, since it is perfectly legal C; even the most basic optimising compiler should remove the indirection operator before compiling, since the result is discarded anyway.

The solution is to use parentheses to force statements to be executed in the correct order any time you are in doubt – (*p)++; will always behave as the previous example was expected to. In most cases, the precedence of mathematical operators is as expected, so you can write most formulae out as normal (although parentheses that would usually be omitted can be useful for a completely different reason). Don’t bother trying to memorise the precedence rules for operators – it’s not that useful a piece of knowledge to have and being comfortable removing a few brackets won’t help other people reading your code.

The arithmetic operators may behave as expected, but this is not always true of the logical operators. This is because the logical operators in C use a method known as short-circuit or minimal evaluation: the second operand is only evaluated if necessary – if the first operand to an AND operator evaluates to false, or if the first operand to an OR operator evaluates to true, the second operand will not be evaluated.
