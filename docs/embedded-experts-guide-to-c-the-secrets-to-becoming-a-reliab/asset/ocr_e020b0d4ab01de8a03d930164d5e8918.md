When using it, the programmer needs to be sure the macro being undefined is not being used elsewhere and they are undefining the intended macro; other than in very exceptional circumstances, the macro should be undefined in the same file in which it is defined.

The global scope of macros also means they must be named with care to avoid redefining existing symbols. Names should be chosen so they are unlikely to clash with other names; one common means of achieving this is to use only uppercase characters for macro names, while using lowercase characters for other symbol names. The names must still be chosen so they do not clash with any reserved names; you should not define your own NULL macro, for instance.

Another common convention is to append an underscore to the macro name since this further reduces the likelihood of clashes. It is, however, bad practice to put an underscore in front of the macro name: all names beginning with an underscore followed by an uppercase character are reserved.
