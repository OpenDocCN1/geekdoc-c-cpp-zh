Symmetric key ciphers may further be split into two types of algorithm: block ciphers and stream As the names suggest, block ciphers work on blocks of data, whereas stream ciphers work with an arbitrary-length sequence of individual bits or bytes. Stream ciphers are typically faster than block ciphers but must constantly update their state in order to secure data (the key to a stream cipher is essentially a seed value to a function that generates a much longer key), which requires storing state information relating to the cipher. The state information of the cipher is then combined with the plaintext using a simple XOR to generate the In contrast, block ciphers are stateless. The fixed sized blocks used in block ciphers makes them inherently resistant to the malicious insertion or deletion of data and have high diffusion – meaning that each byte of ciphertext depends on the entire plaintext block rather than only one byte, as is the case with a stream cipher.

A block cipher should not be used to encrypt more than one block of data without either changing the key used for each block or adding an additional “mode of operation” to the cipher. The problem is that given the same input, a block cipher will always produce the same output; although the precise data will be concealed, any patterns in the plaintext will be identifiable, potentially compromising the security of the ciphertext. Cipher Block Chaining (CBC) is a simple and common mode of operation: each plaintext block is XORed with the previous ciphertext block prior to encryption. Since there is no previous ciphertext to use, the first block is XORed with an initialisation

Decryption in CBC is the reverse – decrypt the block, then XOR the plaintext with the ciphertext of the previous block, or the initialisation vector when decrypting the first block. The initialisation vector is a – usually random (or more likely, pseudorandom) – value of the same size
