Although it is unrelated to optimisation, most of the time, const can be used with a variable definition as an alternative to using However, because such variables are not considered true constants, there are a few circumstances where this cannot (or should not) be done: when the constant is used to set length of a bit-field or the size of an following a case statement, where a true constant must be used; and when initialising a static variable or another constant.

The volatile keyword is used to indicate to the compiler a variable’s value should be expected to change unexpectedly. This means a volatile variable must be loaded and evaluated whenever it is encountered and essentially prevents any of the optimisations which might apply to other variables from occurring. While this may seem unnecessary, you will find many variables need to be declared as volatile when using even relatively modest levels of compiler optimisation or the compiler may simply assume their value does not change and optimise accordingly, even if the variables are not Occasionally a variable may be, seemingly paradoxically, both const and this signals to the compiler the value of the variable may not be changed by the code, but the value may change unexpectedly anyway and is most widely used when interacting with hardware.
