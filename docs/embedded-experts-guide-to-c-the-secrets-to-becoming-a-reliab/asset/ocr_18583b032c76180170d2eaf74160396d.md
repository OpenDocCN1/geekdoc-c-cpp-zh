Some variables may also be stored and shared by the operating system.
These are referred to as environment are always stored as a string and
cannot be accessed directly, although the C Standard Library provides the
getenv function for reading them (but no function to create or modify
them). This function accepts a pointer to a string as argument and returns a
char * pointing to the relevant environment variable, or a NULL pointer if
the variable cannot be found. Do not attempt to modify the array pointed
to by the result of a call to getenv – this is undefined behaviour.

An operating system may also provide a command processor which is
capable of interpreting and executing high-level instructions; if this is the
case, a program may request the operating system executes another
program or system function and returns the result using the system
function. The system function accepts a pointer to a string as argument; if
a NULL pointer is provided, then the return value will be non-zero only if
a command processor is available. If a pointer is provided, then the
function passes the contents of the pointed-to string to the command
processor in an implementation-defined manner and returns an
implementation-defined value – the actual behaviour will be determined
by both the compiler and the command processor which is present and the
C Standard imposes no requirement on either other than the compiler
should document its behaviour. The C Standard also warns any program
calling may “behave in a non-conforming manner or ... terminate”.
