Simply put, an interrupt does exactly what its name implies – it interrupts the program; the processor will store its internal state to be retrieved later and transfer control from the current procedure to an Interrupt Service Routine (ISR). When the ISR is finished, the processor restores its previous state and returns control to the procedure which was interrupted.

Interrupts and callbacks may be used together. For instance, a piece of software wishing to communicate with some external piece of hardware may store a reference to a callback when sending a transmission to establish a connection; when a response is received, the ISR used to handle this can transfer control to the callback rather than attempting to handle the data itself. While this might seem a somewhat convoluted arrangement, it is useful when one of several different actions needs to be taken following an interrupt and can be efficiently implemented.

There is no way to declare an interrupt service routine in the C Standard, nor is there a way to assign a particular ISR to an interrupt source. Interrupts are therefore always handled in an implementation defined manner. Compilers designed for embedded targets try to make this relatively easy for the programmer, but the results are not portable; you will need to check the documentation for your compiler to learn how to make a function an ISR.
