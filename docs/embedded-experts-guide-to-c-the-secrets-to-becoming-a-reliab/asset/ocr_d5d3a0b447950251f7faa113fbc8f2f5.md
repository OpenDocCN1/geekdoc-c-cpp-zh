CBC has the advantage that each ciphertext block only directly influences encryption of the next block; thus, if one block is corrupted or lost, decryption will only fail on that block and the block immediately following it. This fact can be exploited to avoid having to share the initialisation vector (you will, however, still need to share the key) – simply fill the first plaintext block with arbitrary values; when decrypting, the initialisation vector is only required for the first block, so everything from the second block onwards will decrypt correctly and since the first block contains no actual data, you can discard it.

Other modes of operation exist, the most common of which are Cipher Feedback (CFB), Output Feedback (OFB) and Counter (CTR). These modes are interesting because they can be used to convert a block cipher to a stream cipher and CTR mode is particularly useful when a high data rate is required. The details of how these modes can be implemented can easily be found online.

# Generating random numbers

Random number generation, or more correctly, pseudorandom number generation, is an important function for many cryptographic protocols; it is crucial to generating keys, initialisation vectors and salts. Unfortunately, it is incredibly difficult to generate a truly random number, so most algorithms for doing so are, in fact, It is easy to generate a sequence of numbers that appear random – Linear Feedback Shift Registers (LFSR) are one of the most common means of doing so, have been extensively analysed and are adequate for many purposes. However, most pseudorandom number generators are not suitable in cryptographic applications since if enough information is known about their state at a given time, it is trivial to determine their past and future states.
