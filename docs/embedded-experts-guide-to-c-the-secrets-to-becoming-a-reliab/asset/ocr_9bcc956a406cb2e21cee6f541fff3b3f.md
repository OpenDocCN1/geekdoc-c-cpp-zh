Before discussing specific type safety issues, it is worth mentioning the typedef keyword. Although typedefs are useful and you should use them when appropriate, don’t be lured into a false sense of security – using typedef creates an alias for an existing type, it does not create a new type. When evaluating the type of a variable, C treats the alias as being interchangeable with the underlying type and with any other alias for that type. Using a typedef may make understanding and debugging code easier, but it will not help the compiler detect mistakes on your behalf.

Some type safety issues are quite subtle, such as the rules for mixing different integer types. When performing operations on integer types, the C Standard (since C99) states: “if an int can represent all values of the original type, the value is converter to an int; otherwise it is converted to an unsigned int.” This is known as integer promotion and can cause some unexpected behaviour. For instance, it is not possible to directly compare an int to an unsigned int; if asked to perform an operation of this sort, the compiler will first perform a type cast on the int so that it is comparing two unsigned values. If both values are positive, this should not cause any issues. But what if the signed value was initially negative?
