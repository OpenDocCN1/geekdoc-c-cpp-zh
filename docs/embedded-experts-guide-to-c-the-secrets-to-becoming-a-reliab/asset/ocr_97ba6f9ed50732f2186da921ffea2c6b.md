But it is precisely that combination of unrestricted low-level functionality, portability and, above all else, the philosophy of “trust the programmer” that makes C such a potentially dangerous language to Like those responsible for mixing nitroglycerin for Alfred Nobel, the C programmer’s work is probably best done sat upon a one-legged stool to ensure they remain alert. Mistakes are easy to make and often remain undetected by the default tools available to the programmer, inviting disaster at some arbitrary point in the future.

No treatment of the C programming language would be complete without a discussion of its shortcomings. It is impossible to become a good C programmer without first developing an acute awareness of the dangers inherent in the language. That is precisely what this chapter aims to do.

# Undefined and unspecified behaviours

One of the C’s most celebrated qualities is that it can be compiled into efficient machine code on a wide range of platforms. The compiler does not typically generate more code than is required to achieve what the programmer has asked for. If the programmer asks the compiler to generate code to divide two integers, the compiler will generate that code and aim to make it efficient – that is, the generated machine code should run as fast as possible. What the compiler will not do is generate any code to check if the operation can be performed or if the result makes any sense.
