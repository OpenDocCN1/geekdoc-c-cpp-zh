The main purpose of a linker is to fulfill each contract – it resolves the references between different source files. It is able to do this because all necessary information is available at link time. By this point, all source files will have been compiled and all functions will be available. The linker can therefore replace each call instruction generated by the compiler – which call an arbitrary address – with a call instruction to the correct address. If for some reason the required information is not available, the linker will fail and generate an error.

The linker is also responsible for deciding where in memory functions and variables should reside. This can only be done at link-time, since, as we have already discussed, much of the required information is not available at compile time. To achieve this, the linker must first group symbolic references to functions and variables into groups. Each group can then be allocated to a segment in memory. The number of segments and their names will depend on which linker you are using, but in general there are at least three memory segments:

+   - The code segment, which contains executable instructions,

+   - The data segment, where global and static variables are stored,

+   - The call stack, where local variables are stored.
