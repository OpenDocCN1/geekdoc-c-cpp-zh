# Author's Note

In this book, I appear to have made two major omissions (and almost certainly many minor ones).

First, there is no mention of C23. When I began this book in 2020, C18 was the most recent version of the C Standard. As I write this, it still is – C23 is currently still being drafted. It may not be known as C23 when it is finalised. It could, in theory, be scrapped entirely (I think this unlikely). The C18 version is not particularly noteworthy – it addressed some issues with C11, but did little else to change the language. C11 wasn’t particularly noteworthy either – it did make some well-intentioned changes, but in practice has not had much of an impact and few, if any, compilers can truly claim to be “C11 compilers.”

Despite C99 being officially withdrawn, I remain convinced it is the most recent version of the standard worth paying much attention to. Many of the proposed changes for C23 are likely to be welcome. Many programmers assume two’s complement representation for signed integers, for instance, and there is a proposal to make this mandatory. Similarly, removal of old-style function declarations and trigraphs may force the rewriting of some older software but will also eliminate common causes of confusion and unexpected behaviour. Other proposals seek to standardise common compiler extensions, such as the #warning directive. So I do think C23 – or whatever it is finally called – could change things, but until it is finalised and there has been an opportunity to see the response from compiler vendors, we will not know.
