# Chapter 1:
“Trust the Programmer”
– Issues with C

It is, perhaps, surprising that it seems nobody has ever published a book of the “Greatest C Programming Mistakes.” It may be that the subject matter is somewhat niche; but there is certainly a market for other books on C Programming. Perhaps it is that the language is seen as somewhat esoteric, even in professional programming circles: it has essentially been replaced by Java and C# in general applications programming and it has never had much of a role to play in web applications. In the Internet Age, you could be forgiven for thinking that C was more or less extinct – an anachronism, curious for its undeniable influence rather than its usefulness; little more than a plaything for overly keen hobbyists.

But there are two areas where C programming continues to dominate: operating systems and embedded programming. C compiles to efficient machine code and it provides many flexible, low-level features that modern programming languages lack. Although it would be entirely possible to develop a new language capable of competing with C on a technical level, it would not be so easy to convince programmers to switch allegiances following their 50 year alliance with “portable assembly For embedded systems, having low-level functionality while avoiding the need to write tediously verbose assembly is precisely what makes C so attractive. The same is true for operating systems.
