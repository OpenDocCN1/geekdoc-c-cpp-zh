# Endnotes for Chapter 4 - Interrupts and Callbacks

1 As a consequence of being invoked through hardware, an interrupt cannot accept any parameters, nor can it return a value, although the compiler may implement them in such a way they appear to be called with arguments to assist the programmer in understanding why the interrupt was invoked. Callbacks, however, may be passed parameters when called and may return a value.

2 Generally, a function is considered reentrant if multiple instances of it can be run concurrently without interfering with each other. When instances only modify variables on within their own stack space this is not a problem; however, if the function modifies a variable not on its own stack, there can be no guarantee the value written to the variable will not change again before it is read. In fact, because C makes no guarantee variable writes are atomic operations (operations that cannot be interrupted before completion) in most cases, there is not even a guarantee the value will not be changed during the write unless additional steps are taken to ensure this.

3 Rather than being a non-existent (invalid) instruction, an illegal instruction is a valid instruction which the current program does not have permission to use.
