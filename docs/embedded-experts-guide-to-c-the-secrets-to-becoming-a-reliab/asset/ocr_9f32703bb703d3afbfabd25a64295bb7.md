When first added to the list, the next task should be set to either NULL or to point to the first task in the list, p_reentry should point to the entry function of the task, p_stack to the task's stack space. The values stored in the cpu_register array need not be explicitly set, although setting them to zero does guarantee that they will have defined values when the task is first run. When switching to another task, the contents of CPU registers (other than the program counter) are copied into the appropriate structure members. The scheduler then retrieves the next task (or the first task, if the entry is the last task in the list) and loads the contents of structure members into the appropriate registers. On returning from the scheduler, the CPU will jump to the address in the link register – because this value has been set to the re-entry address of the next task, control can be passed to a different function to the one which had been executing before the scheduler was invoked.

# Priority task scheduling

Both the coroutine and round-robin scheduling examples we have discussed so far are adapted from a basic first-in, first-out - the tasks in the queue is serviced in the order in which they arrive. Indeed, if tasks complete before their allotted processing time has passed in the round-robin case or do not yield in the cooperative case, both are equivalent to a FIFO based scheduler. The disadvantage of this approach is it is desirable for a task to “jump the queue,” yet the scheduling algorithms we have discussed have no mechanism for allowing this.
