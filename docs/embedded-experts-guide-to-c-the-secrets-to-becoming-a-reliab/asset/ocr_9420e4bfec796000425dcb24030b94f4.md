There may also be one or more dedicated interrupt instructions available; where available these can be used in a similar way to a trap or exception or to make calls to an operating system or kernel routine. The focus of this chapter will be on interrupts which are generated as a result of hardware events; other than for making system calls (which will not be covered here), other types of interrupt are primarily of interest in developing low-level libraries or operating systems.

Timer interrupts are used for periodic events; reasons for using them may include ADC sampling, output updating, task schedulers and hardware polling. Consider a set of traffic lights; obviously, it would be useless to continuously cycle through the possible light states without some delay between them. In a simple application, a delay could be implemented with a simple loop with a fixed number of iterations or by continuously polling a counter until the correct amount of time has passed. However, a more reliable approach would be to use an interrupt to determine when the state needs to change.

One other common use of timer interrupts is to implement a watchdog timer – in this case, the ISR is not intended to be invoked during normal operation; instead, the timer is supposed to be regularly reset before the (almost always non-maskable) interrupt is generated. If the timer is not reset on time, the interrupt will occur and the ISR will be invoked. Such timers are used to detect hardware or software errors which prevent time-critical operations from being performed and force a response from the processor.
