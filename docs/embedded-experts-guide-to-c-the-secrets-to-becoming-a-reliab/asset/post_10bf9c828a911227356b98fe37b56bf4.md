A doubly-linked list adds a link to the previous element to each entry. In a circular linked list, the list eventually loops back on itself – rather than linking to the last element, it links back to the first, although “first” and “last” essentially become meaningless in this case. Lists are typically intended only to contain one type, although type-generic implementations are possible.

Although linked lists are useful structures in their own right, they are also an important building block for implementing queues and pools, which are among the most useful structures for managing memory. It is also possible to use linked lists to implement a stack, however, this may also be achieved using only an array.

## Stacks

A stack, occasionally known as a LIFO (last-in, first-out) is a simple data structure which allows variables to be read and removed in the reverse order to which they are written. The read and write operations are often referred to as “pop” and “push” respectively. Since the pop operation also removes the variable from the stack, there is often also a “peek” operation for reading a value without removing it.

Most software already includes a stack, often referred to simply as the stack, although this is not directly managed by the programmer. Instead, because it is used for local variable allocations and handling function calls and returns, the code for managing it is generated by the compiler. Much of the work in these cases is performed using hardware.

When required, stacks are easy and efficient to implement. This can be done using an array to store the data and a pointer to the next free element. The pop and push functions need only copy data to or from the stack and increment or decrement the pointer as required. It is also recommended additional logic is included to prevent the stack from over- or underflowing. If the stack is only required to store one data type, then an integer may be used to track the next free location instead of a pointer; if the stack is intended to store multiple data types, it should be implemented as an array of

/* Create a generic stack. */
static char stack_array[STACK_SIZE];
static char *p_stack_end = stack_array;
static int stack_free_space = STACK_SIZE;
/* Push data on to the stack. Returns 'true' if
 * the data is successfully added to the
 * stack. */
bool stack_push(char *p_data, int size)
{
    bool success = false;
    int bytes_to_copy = size;
    /* If the stack has space, copy the data on
     * to it. */
    if (stack_free_space >= size)
    {
        while (0 < bytes_to_copy)
        {
            *p_stack_end++ = *p_data++;
            --bytes_to_copy;
        }
    }
    stack_free_space -= size;
    success = true;
    return success;
}
/* Pop data from the stack. Returns true if the
 * data is successfully copied from the
 * stack. */
bool stack_pop(char *p_data, int size)
{
    bool success = false;
    int bytes_to_copy = size;
    /* Get a pointer to the end of p_data. */
    char * p_data_end = &(p_data[size - 1]);
    /* If there is enough data on the stack, copy
    * it. */
    if (STACK_SIZE >= (size + stack_free_space))
    {
        while (0 < bytes_to_copy)
        {
            *p_data_end-- = *p_stack_end--;
            --bytes_to_copy;
        }
        stack_free_space += size;
        success = true;
    }
    return success;
}

## Queues

In contrast to stacks, queues are First-in, First-out (FIFO) data structures (or First-come, First-served, FCFS, in the context of scheduling algorithms); the most recently written element can only be read from the queue once all previously written elements have been read. As with a stack, reading an element from a queue also removes it from the queue. Write and read operations are often known as enqueue and dequeue. Queues are a commonly used buffer implementation, particularly when data needs to be shared between asynchronous tasks; for instance, an interrupt service routine managing a UART may write data to a queue as it is received, to be read by the main application when it is required rather than handled immediately. Queues are also useful for implementing certain types of task scheduler.

Queues can be efficiently implemented in various ways; doubly linked lists are naturally suited to implementing queues (as well as double ended queues), although probably the simplest implementation is to use a circular buffer and to store read and write indices to keep track of elements. A circular buffer can be implemented using a standard array; causing the elements to wrap-around, so the last element appears adjacent to the first, is achieved by calculating the array index modulo the length of the array (the modulo operator is the % symbol; therefore, the calculation can be expressed as index % QUEUE_SIZE. If the length of the buffer is a power-of-two, the modulo calculation can be replaced with a single bitwise-and operation, making this implementation even more efficient. Accessing the queue through specialised enqueue and dequeue functions ensures the indices are maintained, and the accesses are always valid.
