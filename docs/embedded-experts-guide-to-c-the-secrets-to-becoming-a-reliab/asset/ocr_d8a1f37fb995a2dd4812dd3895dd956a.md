Like the logical operators, the comma operator also inserts a sequence point between operands; indeed, this is the only purpose of this operator. This may at first seem useful, since it allows you a degree of control over the order in which subexpressions are evaluated, but that additional control is minimal and probably not worth the trouble: the comma is probably the most poorly understood of all the operators and has the lowest precedence, which can lead it to behave in unexpected ways. The most fitting description I have come across (from an anonymous author) is it’s “mostly useful for obfuscation.” It makes code difficult to read, is rarely used and is never necessary. It should be avoided entirely.

Although not strictly counter-intuitive, the behaviour of an else statement when nesting if statements is not necessarily obvious, and a problem known as a “dangling else” can arise – how should an if statement followed by a nested if statement followed by an else statement be interpreted? Should the else statement be associated with the first or the second if statement?

```
/* Will the ‘else’ path run? */
bool has_apples = false;
bool has_pears = true;
if (has_apples)
if (has_pears)
...
else
...;
```
