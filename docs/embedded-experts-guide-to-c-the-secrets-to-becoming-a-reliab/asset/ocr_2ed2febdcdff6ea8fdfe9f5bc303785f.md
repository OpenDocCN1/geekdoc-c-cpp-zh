It may not be immediately clear how this is useful; but when the symbol is defined externally, either in another included file or using a compiler option (check your compiler documentation), it can aid in porting software from one platform to another or in simplifying the migration from one version of an included library to another.

Unlike C statements, macros need not be (nor should they be) terminated using a semicolon, although a macro consisting of several statements will require all but the last of those statements to be terminated. The preprocessor will treat the definition as complete once it encounters a newline character. If it is desirable for your macro to span multiple lines, then this can be achieved by ending all but the final line with a backslash.

It is particularly important to remember the preprocessor is primarily a text substitution tool when using Object-like macros are not objects and function-like macros are not functions. Occurrences of both cease to exist once the preprocessor's task has been completed, their contents having been expanded and substituted in their place. Function-like macros cause particular confusion, since once defined their usage appears identical to normal functions although there are important differences in how they behave. While it may be tempting to think a macro can be used to create a type-agnostic function, the “function” itself is not defined, can never be called and arguments are not passed to it; rather, the macro text is expanded and substituted in place of the function “call” within the code. This can cause unexpected behaviour if the arguments used are not limited to individual variables and can be particularly problematic if an expression with side-effects is used as an argument, since the expression will be evaluated each time it appears in the macro rather than only once
