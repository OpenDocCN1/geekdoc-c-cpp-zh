Other restructurings of loops can also have a significant impact. A do ... while loop requires fewer jumps than an equivalent while loop; this may even be true if the do ... while loop must be wrapped in an if block to achieve the same Merging two loops which always iterate the same number of times but are otherwise independent of each other (or where any dependencies will not be affected by merging the loops), immediately halves the number of evaluations and jumps which must be performed. If a greater number of loops can be merged, then the number of evaluations and jumps will decrease proportionally. It may also occasionally be possible to improve performance of nested loops by swapping the inner and outer loops; such gains, however, are usually platform dependent and difficult to Where possible, it can be useful to reduce the overhead associated with function calls within loops by moving the loop inside the function; this can significantly improve performance, since each function call adds at least two additional instructions (a call and return) and, usually, some manipulation of memory; alternatively, using inline functions within loops can avoid this additional overhead.

# Other worthwhile optimisations

Replace chains of if ... else if statements with an equivalent switch statement wherever possible. In the worst case, the performance will be the same. However, a chain of if ... else if statements may require multiple evaluations of the same expression followed by conditional branches.
