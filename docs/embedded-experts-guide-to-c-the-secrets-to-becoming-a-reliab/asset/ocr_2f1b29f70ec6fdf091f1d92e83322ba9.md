The integer divide-by-zero example is a clear instance of undefined behaviour – it is a mathematically meaningless Division can be implemented in a number of different ways; the C Standard does not specify any preference as to which should be used and the choice will determine the behaviour when attempting to divide by zero. If the platform you are compiling for has a native divide instruction, a hardware exception may occur; a naïve algorithm performing repeated subtractions could become caught in an infinite loop. Other methods will produce other behaviours, but none will give a meaningful result to the calculation it was asked to solve.

Dividing by zero is an example which, in any useful program, could only occur at run-time – in general, it is not possible to detect a problem either when writing or compiling the code. This is fairly common for undefined behaviours – they do not usually occur as a result of a single, unambiguous line of code. Despite this, many modern compilers are quite good at detecting the potential for undefined behaviours to occur. Although this might seem to be a good thing, they are also very good at creatively, and silently, “resolving” the problem in their own way: through optimisation.
