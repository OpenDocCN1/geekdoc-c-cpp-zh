Pre-emptive multitasking is a much more flexible alternative. A pre-emptive scheduler can interrupt tasks in order to allow other tasks to run. This immediately frees the programmer from determining the best point in the code at which to yield control, immediately solving the problem of one task taking a disproportionate amount of processor time in comparison to others. In addition, more advanced pre-emptive schedulers can schedule tasks based on their importance.

One of the better known and easiest to implement scheduling methods is the round-robin algorithm. Tasks are allowed to run for a fixed amount of time before execution is handed to the next one. Once all tasks have used their allocated time, execution returns to the first task – this is known as cyclic processing. The cycle continues until all tasks in the queue are complete. If a new task is initiated, it joins the back of the task queue. In its simplest form, a round robin scheduler does not allow tasks to be ordered by priority, but there are variants which do factor in the relative importance of tasks.

Correctly implemented, a round robin scheduler has the advantage of being starvation free: no task is denied access to resources because they are always in use by another task. The algorithm is also deterministic – if a task is in the queue, it is guaranteed to be allocated some time to run. The major disadvantage of the round robin approach is, in its basic form, it does not take account of either priority or size of a task – the scheduler always steps through the task queue in the same order and allocates the same time for each task regardless of how long the task needs to run.

Considering the round-robin scheduler allows each task to run for a fixed amount of time before handing execution to the next task in the list, it seems sensible the scheduler should be implemented using a timer interrupt (this is true of many other scheduling algorithms as well).
