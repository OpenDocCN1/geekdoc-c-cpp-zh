Several algorithms have therefore been developed to address this – these are known as, cryptographically secure pseudorandom number These can most easily be implemented by using the key stream generated by a stream cipher or encrypting a free-running counter output using a block cipher, in both cases using the key as the seed value. Other methods are based on hard mathematical problems, often the same as those used in asymmetrical encryption, but these tend to be slow to compute. Alternatively, a true random number generator can be created by measuring some external variable that varies unpredictably, such as thermal noise; these are easy to compute, but slow because it is necessary to accumulate the measurements over a long period. Some algorithms combine both approaches to provide a degree of true randomness by periodically reseeding the generator while also benefiting from the speed advantages of performing encryption compared to accumulating random data.

For purely algorithmic approaches, regardless of the method used to generate a random number, there will always be the problem of choosing an initial seed value to initialise the algorithm. If the same value is used repeatedly, the sequence of random numbers will always be the same. The seed value itself, therefore, needs to be sufficiently random. At the very least, it must be sourced from somewhere independent of the code that uses it; some suggested sources are timers with a period derived from a source other than the CPU clock, unused ADC inputs that have been made deliberately noisy or specialised random number generators.
