The problem is worse when multiple interrupt sources share a single interrupt signal to the CPU, since there will be additional overhead incurred when determining which ISR to transfer control to. If an interrupt is triggered too frequently or if too many interrupts are used then the time spent switching between normal code and ISRs becomes significant – although it can be tempting to use interrupts to respond to every event, this does not always result in the performance benefits you might hope for.

Limiting the number of interrupts you use is a relatively straightforward way to reduce the overhead associated with them. Slow hardware can be periodically polled using a single timer interrupt rather than interrupting on each change of state.
