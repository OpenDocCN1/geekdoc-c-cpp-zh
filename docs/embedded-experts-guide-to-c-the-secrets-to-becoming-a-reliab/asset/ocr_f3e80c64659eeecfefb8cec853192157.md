C has no built-in mechanism to ensure memory safety and violations are probably the most common source of serious programming errors. Countless bugs and security vulnerabilities have been caused by memory safety violations. The infamous “Heartbleed” vulnerability in the OpenSSL library, fist publicly disclosed in 2014, was caused by a buffer over-read error. A buffer overflow vulnerability was discovered in the kernel of multiple Apple operating systems in 2018. In May 2019 it was reported that Facebook’s popular messaging application, WhatsApp, had a memory safety vulnerability. Sir Tony who was the first person to propose using null references as a means of protecting memory in 1965, later described his invention as “my billion-dollar mistake.”

In C, pointers are the cause of many memory safety violations. As C’s only native reference type, programmers have little option but to use them, despite the well-documented risks associated with them. It is entirely possible to assign an arbitrary address to a pointer in C – indeed, when a pointer is declared, this is what happens in most cases (the declaration only allocates space for the pointer – not what it points to). Such pointers are described as “wild.” Alternatively, a pointer may reference a variable which has since fallen out of scope (i.e. should no longer be accessible). In this case, the pointer is said to be “dangling.” Dereferencing either a wild or dangling pointer is undefined behaviour, as is dereferencing the null pointer.
