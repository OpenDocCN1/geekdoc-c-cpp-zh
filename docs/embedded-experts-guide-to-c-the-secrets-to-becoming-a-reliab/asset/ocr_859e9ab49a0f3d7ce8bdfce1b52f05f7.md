The most common and most important type of whitespace is the humble space character. This is the character most likely to change the behaviour of a program. The main reason for using spaces is to make code more readable, however, there are a few instances where a lack of spacing will result in an unintended tokenisation of the code. C's tokenisation rules stipulate that when tokenisation is ambiguous, the compiler should build the tokens, starting from the left, using the largest number of characters possible, regardless of the context – this is often referred to as the “maximal munch” rule. The statement a=-b; could also cause strange behaviour – in early implementations of C, rather than being treated as two separate tokens, =- and += were each treated as a single token with the same purpose as the more common and unambiguous -= and += compound assignment operators; although this was changed early on, some compilers continued to interpret them this way for some time (it’s relatively unlikely that you’re using one of them, but if you are you could spend a very long time trying to solve the problems it causes). The solution is to use whitespace to make the tokens unambiguous. Not only does this prevent the compiler from misinterpreting the code, but also makes it more readable.
