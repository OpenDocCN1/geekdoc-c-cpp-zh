Undefined behaviours are the result of code that is syntactically correct but semantically meaningless, either inherently or because of the data you give it to work with. According to the C Standard, undefined behaviour is caused when you attempt to execute “a non-portable or erroneous program construct” or by providing a valid program with “erroneous data.” There are almost 200 undefined behaviours listed in Annex J of the standard. The name “undefined behaviour” is fitting: if a behaviour is undefined, then the C Standard “imposes no requirements” – in other words, you are entirely at the mercy of the compiler, which is entitled to assume that undefined behaviour will not occur and may, or may not, generate meaningful machine code when it is encountered. Indeed, compilers may even produce code that behaves exactly as the programmer intended.
