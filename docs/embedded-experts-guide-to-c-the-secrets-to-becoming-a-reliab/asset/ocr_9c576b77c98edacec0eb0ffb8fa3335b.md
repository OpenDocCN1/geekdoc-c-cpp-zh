In addition to requiring some thought be given to correctly assigning priorities to tasks, priority-based scheduling introduces a new risk to be wary of: priority inversion. This occurs when a high-priority requires a resource currently being used by a low-priority task, which is subsequently pre-empted by a medium-priority task. The initial blocking of the high-priority task is not the problem: in this case, the scheduler has worked as intended. The problem occurs when the low-priority task is pre-empted by the medium priority task; at this point, the high-priority task has also been pre-empted, albeit indirectly, in a way which does not respect task priorities.

More generally, multitasking either creates new potential issues or increases existing risks. For instance, stack overflow – where the call stack extends beyond its intended end and begins to read or write data never intended to be part of the stack – is always a potential problem; however, without multitasking this is rare and invariably indicates that the platform lacked the necessary memory to support the software; with multitasking, there can be plenty of memory available but a stack overflow may still occur if insufficient memory has been allocated to one (or more) of the individual task stacks. Conversely, deadlock – where two or more tasks are mutually dependent on the completion of each other and therefore prevented from progressing – is a problem which can only arise where multitasking is used.

In relatively simple multitasking environments such problems can be dealt with manually. Priority inversion can be avoided by using only one priority level for all tasks, allocated stack sizes can be increased providing sufficient total memory is available and best practice for preventing deadlocks is to only ever allow a task to hold a single mutex at a time, releasing the held mutex before attempting to acquire another (alternatively, if this is not possible, mutexes should only be acquired in a pre-defined order, and released if any of the acquisitions fail).
