## Pointers

Pointers are variables which store the address of another location in memory. They are often referred to as a reference type and are the only such type available natively in C – many of the reference types found in other programming languages are much more comprehensive than pointers. Because the value of a pointer is an address, the type of object it points to does not affect its size – all pointers occupy the same amount of space in memory. In addition, the address pointed to can be arbitrary, which is the primary reason why pointers are one of the most common sources of serious defects in C programs.

To be useful, pointers must point to something, and although a definition such as uint32_t * const p_cpu_reg = (int *) 0x1000; is valid (and occasionally required), that something is usually another variable, although it can also be a function. Pointers to void are, to some extent, generic pointers – they can point to any type, but cannot be dereferenced without first being cast to a pointer to another type since there is no way of knowing what to do with the data. The C Standard guarantees that a pointer to any type can be cast to a pointer to void and back again without loss of information; however, casting to a pointer to a type other than the original type or char is undefined behaviour. There is also the null pointer (named NULL and typically defined as something like (void *) 0) which is intended to help identify invalid pointers; dereferencing the null pointer is undefined behaviour, but this does not mean it cannot be done – it may in fact be a valid address, even if it is not one you should

One common use of pointers is to implement pass-by-reference behaviour with function calls; this is where a reference to a variable is passed to a function, rather than the value of the variable being passed (which necessarily involves making a copy of the variable). By default, arrays are passed to functions in this way, but other types are not. Pass-by-reference is most useful when working with compound variables, since it can significantly reduce the overhead associated with passing the entire variable. It is not actually necessary for the caller to know anything about the referenced variable beyond its address, a fact that can be exploited to create an additional level of abstraction between the underlying implementation of code modules and the interfaces used to integrate them with other code.

Pointers to functions can be used to implement callback functions and simplify the code required to select a function to call based on data available at runtime. They are, for most purposes, no different to any other type of pointer. The syntax can appear intimidating when first encountered: int (* p_func)(int); declares a pointer to a function returning an int and accepting an int as argument; char (* p_func)(char *); declares a pointer to a function accepting an argument of type char * and returning a char. A typedef is often used to simplify the declaration of function pointers. The statement typedef void (* callback)(arg_t); defines a type (named callback) which can be used to simplify future variable definitions for pointers to functions that accept an argument of type arg_t and do not return a value. Calling a function from a function pointer follows the same syntax as other function calls; there is no need to explicitly dereference the pointer before calling the function it references.

## Integer types

In C, the basic integer types are short, int, long, and (since C99) long long. The int part of the name is optional for the long and long long. All may be preceded by the signed or unsigned modifiers – by default all integer types are signed, with the exception of char which may be either signed or unsigned depending on the implementation. The unmodified char type is referred to as the plain char type and should only be used for storing characters.

The C Standard does not specify an actual bit width for any of the integer types. Rather, a minimum range of values is specified and implementations are free to allow a greater range if desired. Nor does the standard specify the representation of signed values – although two's complement representation is now almost universal, other representations are allowed. To address the need for integers of a known size, C99 introduced fixed-width integer types, which can be found in the stdint.h header file. This significantly reduces the complexity of writing portable code and using these types is encouraged for any type where the size is important. There is no need to use the long or long long types when using fixed-width integers – int may still be useful for variables where the precise width does not matter.

## Floating point considerations

Floating point variables extend the range of numeric values that can be used but require some special treatment. It is important to remember that these values behave differently to integer or fixed-point numbers. First, the absolute precision of floating point values varies with their magnitude, so although 1.0 has an exact floating point representation, adding or subtracting it from other floating point numbers may not produce the expected result. Furthermore, because floating point numbers are often written using decimal notation, it is easy to forget that they are still binary numbers when stored in memory – although you can write code that appears to assign 0.1 to a floating point variable, the actual number stored will be different (0.1 cannot be exactly represented as a floating point number) and seemingly trivial calculations will not necessarily produce the expected result.

IEEE 754, by far the most widely implemented floating point standard, also includes special values to represent infinities and not-a-number (NaN) values; these are included in the standard so that invalid operations, or those that cause an overflow, can be dealt with in a way that does not return an undefined result, but does not necessarily cause either a hardware or software exception either. However, in an embedded system there is generally nothing useful you can do with these special values and it is important to check that they are not returned when performing calculations, since they generally indicate an error either in the underlying logic or the data available at run-time.

The technical details of how floating point arithmetic is implemented places restrictions on how it should be used. It is safe to perform greater-than and less-than comparisons on floating point variables, but comparing values for equality should be avoided, since the results cannot be relied upon. Nor should floating point values be used to implement loop counters; if the counter value is required in a floating point calculation, it should be implemented as an integer type and cast to the appropriate floating point type when needed. The C Standard Library header file math.h provides some functions to identify infinite and NaN values, the most obvious being the intuitively named isinf and isnan functions. Whether a compiler implements the IEEE 754 standard can be checked by looking for a definition of the __STDC_IEC_559__ macro (IEEE 754 is also known by the alternative designation IEC 60559, which lends its name to the symbol).
