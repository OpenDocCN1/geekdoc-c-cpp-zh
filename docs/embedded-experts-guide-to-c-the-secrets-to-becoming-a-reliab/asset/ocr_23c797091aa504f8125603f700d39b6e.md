but it is at least possible to check for a null pointer). Although not entirely reliable, most dangling pointers can be eliminated by avoiding dynamic memory allocation. Finally, if it cannot be guaranteed that a pointer cannot be a null pointer, check before dereferencing.

```
/* Get a reference to an apple. */
char * get_fruit(void)
{
char fruit[] = "apple";
return &fruit[0];
}
```

Dynamic (heap) memory allocation is generally considered bad practice in embedded systems. This was hinted at in the previous section, where the lack of type safety was mentioned, and above, with reference to the issue of dangling pointers. One other major issue with dynamic allocation is memory fragmentation – that is, as portions of memory are allocated and freed, there may be a significant amount of free space that is unsuitable for further allocations because it is non-contiguous. When space is relatively limited, as is the case with most embedded systems, it can quickly become exhausted by repeated dynamic allocations, even if the space appears to be available. Later, we will explore some alternatives that can be used to provide heap-like allocation in a more reliable manner. For now, it is best to accept that functions such as malloc should not be used, no matter how useful you may have found them in the past.
