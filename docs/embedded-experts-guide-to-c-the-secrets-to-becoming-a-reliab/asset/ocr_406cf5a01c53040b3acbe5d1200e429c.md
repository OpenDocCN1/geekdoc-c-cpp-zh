restrict signals that it can be assumed the restricted pointer will never be aliased by another pointer. The problem is the compiler is not required to enforce the restriction in any way: it is entirely the programmer's responsibility to ensure the pointer is not aliased and failing to do so results in undefined behaviour. Several functions in the C Standard Library are defined using pointers, but the use of restrict is discouraged in user code because of the risks associated with it.

# Loops

The repetitive nature of loops makes them a good candidate for optimisation. Even a short loop run many times can slow a program down; in fact, short loops can often benefit the most from relatively simple optimisations. One of the most common optimisations is known as loop Every loop iteration ends with a conditionally executed branch instruction back to the start of the loop (except for infinite loops, where the branch is unconditional); the idea of loop unrolling is to reduce the number of condition evaluations and jumps by combining multiple iterations into one. To do this, it is obviously necessary to know the total number of iterations which will be performed, or at least to know a factor of the number of Compilers can often be relied upon to perform loop unrolling; however, the programmer may have some knowledge about the number of iterations to be performed which is not necessarily available to the compiler, in which case, manual unrolling may be necessary. There may also be redundancy in the results of calculations performed during the iterations which can be exploited; these are unlikely to be known to the compiler, but the programmer should exploit them wherever possible.
