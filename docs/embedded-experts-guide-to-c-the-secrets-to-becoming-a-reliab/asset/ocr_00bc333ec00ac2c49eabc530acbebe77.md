As with variables, there are some functions which should have names that make them quickly identifiable; interrupt service routines and callbacks being the most likely examples you will come The easiest way to highlight these is to use an appropriate suffix with the name: _isr for interrupt service routines or _cb for callbacks, for instance. Similarly, a suffix such as _thread or _task can be used for the entry functions of threads in multitasking software to highlight these functions as having a role similar to the main function used in most C programs.

It is almost universal for C variable and function names to be lowercase, with words separated by underscores – a style which is sometimes referred to as snake There is no actual requirement for this in the C Standard, although I recommend that you follow it simply because it is so widely used. To differentiate macros (both function-like and object-like) from variables and functions, these are generally written in uppercase, again using underscores as a separator You will occasionally see type names capitalised as well – the FILE type in the C Standard Library is one

Symbol names should be chosen so that they are not the same as either a keyword, C Standard Library symbol name or any reserved symbol names – any name beginning with two underscores, or a single underscore followed by a capital letter, is reserved; the safest way to avoid falling foul of this rule is to never begin a name with an underscore. To be safe and prevent confusion, it is best to also avoid any symbol names or keywords found within C++ but not C, even though this may not strictly be necessary. It is best to also avoid names that are very similar to keywords or built-in symbol names; for instance, a register_t or REGISTER macro defined by the programmer could easily be confused with (or mistyped as) the register keyword.
