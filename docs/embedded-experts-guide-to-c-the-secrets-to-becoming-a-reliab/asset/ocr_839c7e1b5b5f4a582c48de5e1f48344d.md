One common cause of errors is confusion between the equality and assignment operators This is particularly common in the controlling expressions for conditionals and loops. It is perfectly legal to perform an assignment in these statements and the behaviour is well-defined, although it is much more common to intend to perform a check for equality in these situations. Given the visual similarity between the operators and the ease of missing an sign, it is not surprising that this causes problems. This is such a common mistake that many compilers will issue a warning message even though there is no requirement for them to do so. Don’t be tempted to make use this ‘feature’ in an attempt to reduce the number of lines of code you have to write – you will soon run into problems and even if you don’t, your code could quickly become unreadable and it won’t make any significant difference to the performance.

When comparing a variable to a constant value, it is helpful to write the constant on the left-hand-side of the operator; doing so ensures that a syntax error will occur if you mistakenly use the assignment rather than equality operator, since assigning a value to a constant is not allowed. I do this with all comparisons, even those that are not so easily mistyped. It can take a while to form a habit like that, but it can save hours of tedious debugging later.
