Cooperative multitasking is easier to implement and typically requires less memory to keep track of processes but can cause issues if poorly coded processes refuse to yield control for an unnecessarily long length of time. Pre-emptive multitasking overcomes this issue at the expense of a more complex scheduler and increased memory usage; greater care is also required when writing processes to work with a pre-emptive scheduler. Like an interrupt, a pre-emptive scheduler disrupts the normal control flow of the program. There may be times when this disruption is problematic; for instance, if we extend the example from earlier to include two processes using the UART, we would not want one of these processes to pre-empt the other mid-transmission. To prevent such a situation from arising, we need to protect certain shared resources from being accessed by different tasks simultaneously.

Most modern general-purpose operating systems adopt a pre-emptive approach to multitasking, although the cooperative model is still used in many embedded systems and some specialist applications. Although operating systems will typically include a scheduler, therefore making implementation easier, an operating system is not strictly required for multitasking. Likewise, some hardware has features designed to aid multitasking, but hardware support is not essential.

If the compiler you are using does not support C11 or later, there is no in-built support for multithreading unless it is provided as a compiler specific extension. C11 introduced two optional additions to the C Standard Library: threads.h and stdatomic.h which provide new functions to aid in developing multitasking software. Third-party libraries are often available, one of the better known is the pthreads (or threads) library. Most multithreading libraries require operating system support.
