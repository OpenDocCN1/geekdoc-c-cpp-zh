From the programmer’s perspective, this step is of little significance since it should have no impact on the functionality of the software.

Actual translation from source code (in the form of tokens) to machine code takes place during Phase 7. This includes another round of tokenisation (according to the C Standard, preprocessing tokens are translated to tokens – it probably isn’t worth worrying about the difference between a preprocessing token and a plain token), followed by syntactic and semantic analysis so machine code may be produced.

At this point, the output is machine code, or a “translated translation unit” to use the C Standard terminology. Further steps are still required in order for the code to run, but these do not have to be completed now. For instance, translation may be halted at this point if the code is to be used as a precompiled library – since there is no intention for the library to run in a stand-alone fashion, no further steps need be taken; indeed, in such a scenario it makes little sense to attempt any further steps, since there would be no way to properly call any of the functions within the library without additional software anyway.

For software which is intended to be loaded to the target and to run immediately, the final stage in the process is linkage. Despite being presented as only a single phase in the C Standard, this is a crucial, and potentially complex, step.
