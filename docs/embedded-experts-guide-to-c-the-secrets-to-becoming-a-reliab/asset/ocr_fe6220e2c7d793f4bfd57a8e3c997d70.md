# Sharing keys

Key sharing has long been a significant hurdle to secure cryptography and was one of the main motivations for developing asymmetric ciphers. You may be tempted to ship your embedded products with a hard-coded key. Although simple, this approach has a number of weaknesses. First, every device produced should have its own key, otherwise compromising one device will compromise every other device as well. Second, if a device is compromised it becomes useless, since it is not trivial to change the key. Finally, a database of every device and its key must be maintained and copied to every other device that may wish to communicate with the device.

An alternative might be to generate a symmetric cipher key with a limited lifetime (often called a session key) and to send this to the device you wish to communicate with, first encrypting it using an asymmetric cipher with the public key for that device. This eliminates the need to have a hard-coded secret key stored on every device since a public key can be freely distributed. Frequently changing the key improves security and since it can be discarded once it is no longer required the risk of it being compromised is reduced. However, such a scheme lacks a property known as perfect forward secrecy – if the private key used to decrypt the short-term key is ever compromised, all past and future keys can be recovered from a record of the communications between devices.
