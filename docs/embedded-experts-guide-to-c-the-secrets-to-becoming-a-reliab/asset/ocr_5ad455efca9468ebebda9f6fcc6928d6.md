Although it is not recommended for most types, there are occasions when you may wish to be able to tell the type of variable from its name. This is most common with floating point types, since these need to be treated differently to integers. A simple way to this is to use _f as a suffix to the name (or _d for a double if you need to differentiate them). Similarly, you may use _b to identify a Boolean type. Related to this is the naming of custom types themselves; it is common to see _t used to identify a type and occasionally you may also see _u used to identify structures and unions, respectively. This is useful for two reasons: first, it makes it clear that the unfamiliar symbol is a type, not a variable, name; second, it allows the instance to have a similar name to the type if desired, e.g., declarations such as adc_register_t adc_register; are relatively common.

Like variables, functions should have meaningful names. It is useful for a function name to give some indication of what the function does and what it does it to – many functions will necessarily have similar names; you may have functions to read analogue and digital inputs, for instance; since the names cannot be identical, identifying the type of input being read is a good way to distinguish them from each other.
