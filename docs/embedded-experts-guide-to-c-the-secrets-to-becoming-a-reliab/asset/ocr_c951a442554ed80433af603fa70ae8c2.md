5 A 1968 paper by Robert Miller (“Response time in man-computer conversational transactions”) suggests a human will perceive a response time of 100 ms as instantaneous, although more recent research suggests this is too slow for many applications. However, where the primary concern is user experience, a delay of 50 ms will usually be acceptable and a delay of 10 ms is too short to be perceived at all. Thus, a sampling rate of 20 to 100 samples per second is adequate for almost all user input requirements.

6 Any shared variable may be read from anywhere in the code without restriction, but modification (writing) of the variable should be restricted to only one ISR or other function (but not both). If two-way communication is required, two variables should be used, even if one of them appears redundant. Later in this book, alternative approaches will be explored.

7 In many higher-level languages, callbacks are often used in a way similar to interrupts – they are invoked automatically when the necessary conditions are met. However, this is only because of the level of abstraction involved; the programmer is isolated from the part of the program responsible for checking conditions and invoking callbacks, which is part of the language’s runtime environment. There is no such runtime environment associated with C programs, so the programmer is responsible for implementing the code required to invoke callbacks.
