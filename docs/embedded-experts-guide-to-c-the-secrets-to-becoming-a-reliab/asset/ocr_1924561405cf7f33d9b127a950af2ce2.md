It is almost impossible to write software that does not include some implementation-defined behaviour. For example, the size of integer types is implementation-defined, but it would be unrealistic to expect programmers not to use them. Other examples are best avoided: performing a right-shift on a negative integer is implementation defined; in this instance it is better to write code to do what you intend, rather than relying on a particular compiler In some cases, there are ways to assure yourself that the result of an implementation-defined behaviour is what you intend; some compilers will also allow you to manually determine some behaviours based on your needs – it is always worth checking the documentation for your compiler.

# Counter-intuitive syntax

C is a programming language; it is neither a form of mathematical notation nor a natural language. It has its own syntax, which at times is counter-intuitive; indeed, there are examples of C syntax which almost seems intended to cause mistakes. Many operators and keywords are overloaded in ways that are easily misunderstood; others are easily mistyped. The precedence of some operators is inconsistent with their mathematical equivalents. It is possible to write statements in C that, although perfectly legal as far as the language is concerned, behave very differently to what would naturally be expected; because these statements are perfectly legal, the compiler may not even issue a warning when they are encountered and they can be difficult to track down, or even detect at all, once the code has been compiled. One common piece of advice commonly given to novice programmers is to make their intentions clear. The problem with this is that the compiler simply doesn’t care about the programmer’s intentions – it cares about how to interpret the lines of code
