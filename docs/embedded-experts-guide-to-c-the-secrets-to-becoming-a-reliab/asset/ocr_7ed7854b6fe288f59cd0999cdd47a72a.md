# Working with operating systems: what the C Standard says

Many (but not all) embedded operating systems differ from their more familiar relatives in one very significant way – they are not intended to be act as a stand-alone piece of software for managing a system; instead, they provide a base upon which specific applications can be built and those applications are often fully integrated into a single executable piece of code with the operating system – from the target system’s point of view, both operating system and application are a single program. As a result, many such operating systems consist of relatively little or no code beyond the kernel – the portion of the operating system responsible for providing crucial functions, but not those such as user interfaces. Some newer embedded operating systems, however, appear more like slimmed-down versions of their desktop equivalents than the specialised programs they have historically been; this is a change which is being at least partially driven by an increase in the number of small but flexible consumer devices, the expansion of the “Internet of Things” and the wider availability of devices and development kits aimed at educational and hobbyist, rather than professional, markets.

Operating systems can simplify writing programs which require multitasking or have complex IO requirements, such as an Ethernet stack, a file system or graphical user interface. They may also provide protection against some (but by no means all) software defects, such as stack overflows, memory access violations and illegal operations.
