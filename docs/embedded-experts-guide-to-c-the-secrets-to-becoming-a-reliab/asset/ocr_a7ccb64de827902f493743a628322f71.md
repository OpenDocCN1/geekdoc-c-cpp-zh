Beyond this, there are a few steps you can take to write code that can be considered good and many of these have little to do with the actual statements and expressions that make up the code. The first, and most important, of these is to work to a coding standard.

# Coding standards

A coding standard, in its most basic form, is a document that sets out a series of rules to be followed when programming. These rules should cover both stylistic and technical usage of the language. In terms of style, although it generally does not matter too much which style you use, consistency is important. For instance, repeatedly changing the bracing style you use will impair the readability of your code. Technical rules are used to outline requirements on how the language is used. These may include restriction on the standard library functions, types and keywords that can be used (using the goto keyword, for instance, is often strongly discouraged). In most cases, which coding standard you use is not overly important; pick one, learn the rules and stick to them. Take the time to understand the rules as well – blind compliance to any standard, however thorough, is not going to help you write good code.

Following a good coding standard will help you to reduce the number of defects in your code and to write code that is easily understood and maintained. Some coding standards are considerably better than others – many are nothing more than a statement of rules based solely on the personal preferences of the authors. If a coding standard does not include at least some objective justification for the rules it contains, you should probably look for another one.
