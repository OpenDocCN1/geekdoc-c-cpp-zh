Alternatively, the callback need not be invoked during the ISR; the direction of communication can be reversed and the ISR can either store a reference to the desired callback in an appropriate global variable, or store the information required for the callback to be selected by other code. The callback can then be invoked when necessary, without causing additional, potentially unpredictable, time servicing the interrupt. This is achieved using an event loop somewhere within a function which runs within the context of the main program control flow – a loop which waits for and responds to new events being registered, essentially another example of busy-waiting.

# Software interrupts

Software interrupts are interrupts which are intentionally triggered through software by executing an interrupt They have so far not been discussed in this chapter. There are two reasons for this: first, they are of relatively limited use outside of a hosted environment (one which includes an operating system), and second, the concept can be a difficult one to grasp at first because they initially appear to be little more than a means of calling a function indirectly, which can lead them to be confused with callbacks.
