Inline functions may be declared by qualifying the function definition with the keyword An inline function is one which eliminates a function call by replacing the call with the body of the function. Qualifying a function with the inline keyword does not guarantee the replacement will take place; rather it serves as a hint to the compiler the programmer would like the replacement to take place if possible and the compiler may choose not to inline the function at all or to inline only in some instances. Inline functions are a good alternative to function-like macros and do not require the special precautions needed when writing macros. One disadvantage of inline functions is they can be difficult to resolve across translation units and this can lead to linker errors or unreachable code being To avoid such problems, it may be best to limit the scope of every inline function to the translation unit in which it is defined by making it static. Furthermore, inlining, while potentially beneficial for code speed, can increase the size of the compiled code. Inlining is most beneficial for small helper functions which are called relatively frequently, where the overhead of a function call is comparable to the code of the function itself.

/* Square a number. Make the function inline so
 * the compiler knows it can omit the function
 * call. */
static inline square(int value)
{
return value * value;
}
