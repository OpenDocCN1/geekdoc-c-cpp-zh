# All operations on atomic_ref

| Member functions | Description |
|---|---|
| `is_lock_free`<br>`atomic_ref<T>::is_always_lock_free` | Checks if the atomic_ref object is lock-free.<br>Checks at compile time if the atomic type is always lock-free. |
| `load`<br>`operator T` | Atomically returns the value of the referenced object.<br>Atomically returns the value of the referenced object. Equivalent to `atomic::load()`. |
| `store` | Atomically replaces the value of the referenced object with a non-atomic. |
| `exchange` | Atomically replaces the value of the referenced object with the new value. |
| `compare_exchange_strong`<br>`compare_exchange_weak` | Atomically compares and eventually exchanges the value of the referenced object. Details are here. |
| `fetch_add`, `+=`<br>`fetch_sub`, `-=` | Atomically adds(subtracts) the value to(from) the referenced object. |
| `fetch_or`, `\|=`<br>`fetch_and`, `&=`<br>`fetch_xor`, `^=` | Atomically performs bitwise OR, AND, and XOR) operation on the referenced object. |
| `++`, `--` | Increments or decrements (pre- and post-increment) the referenced object. |
| `notify_one`<br>`notify_all` | Notifies one atomic wait operation.<br>Notifies all atomic wait operations. |
| `wait` | Blocks until it is notified.<br>Compares itself with the old value to protect against spurious wakeups and lost wakeups.<br>If the old value compares to unequal, returns. |

The composite assignment operators return the new value; the fetch variations return the old value.

Each member functions supports an additional memory-ordering argument. The default for the memory-ordering argument is `std::memory_order_seq_cst` but you can also use `std::memory_order_relaxed`, `std::memory_order_consume`, `std::memory_order_acquire`, `std::memory_order_release`, or `std::memory_order_acq_rel`. The `compare_exchange_strong` and `compare_exchange_weak` member functions can be parametrized with two memory-orderings. One for the success and one for the failure case. If you only explicitly provide one memory-ordering, it is used for the success and the failure case. Here are the details of memory-ordering.
