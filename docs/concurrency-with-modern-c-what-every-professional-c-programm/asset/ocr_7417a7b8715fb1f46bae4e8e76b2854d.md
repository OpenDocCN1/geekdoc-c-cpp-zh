# 14.2.2.1.4 `std::atomic<std::shared_ptr>` is not Lock-Free on Windows

Honestly, I cheated in the previous programs using a atomic operations on a `std::shared_ptr`, and using a `std::atomic<std::shared_ptr>`. You have to assume, that atomics operations on a `std::shared_ptr` are not lock-free. Additionally, an implementation of `std::atomic<std::shared_ptr>` can use a locking mechanism to support all partial and full specializations of `std::atomic`. This happened in the case of the used Visual Studio C++ compiler. The call `atom.load()` on a `std::atomic<std::shared_ptr<Node>>` returns false.
