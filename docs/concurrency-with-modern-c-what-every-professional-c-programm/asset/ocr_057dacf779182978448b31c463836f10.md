# ## 7.4 Task Blocks

Task blocks use the well-known fork-join paradigm for the parallel execution of tasks. They are already part of the [Technical Specification for C++ Extension Parallelism Version 2](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2018/n4742.html), therefore, it’s pretty probable that we get them with C++20.

Who invented it in C++? Both Microsoft with its [Parallel Patterns Library (PPL)](https://en.wikipedia.org/wiki/Parallel_Patterns_Library) and Intel with its [Threading Building Blocks (TBB)](https://en.wikipedia.org/wiki/Threading_Building_Blocks) were involved in the proposal N4441. Additionally, Intel used its experience with their [Cilk Plus library](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2015/n4441.pdf).

The name fork-join is quite easy to explain.

# How does it work?

The creator invokes `define_task_block` or `define_task_block_restore_thread`. This call creates a task block that can create tasks, or it can wait for their completion. The synchronization is at the end of the task block. The creation of a new task is the fork phase; the task block’s synchronization is the join phase of the workflow.
