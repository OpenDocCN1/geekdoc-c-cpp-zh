Read-modify-write operations have an additional guarantee: they always provide the newest value. This means a sequence of `atomicVar.fetch_sub(1)` operations on different threads counts down one after the other without any gaps or duplicates.

If you use an atomic operation `atomicVar.load()` with a memory model that is designed for a write or read-modify-write operation, the write part has no effect. The result is that operation `atomicVar.load(std::memory_order_acquire)` is equivalent to operation `atomicVar.load(std::memory_order_acquire)`. Accordingly, operation `atomicVar.load(std::memory_order_release)` is equivalent to `atomicVar.load(std::memory_order_relaxed)`.
