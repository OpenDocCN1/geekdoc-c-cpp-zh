## 12.3 Given an input file with four billion integers, provide an algorithm to generate integer which is not contained in the file. Assume you have 1 GB of memory.

### FOLLOW UP
What if you have only 10 MB of memory?

### SOLUTION

There are a total of 2^32 or 4 billion distinct integers possible. We have 1 GB of memory, or 8 billion bits.

Thus, with 8 billion bits, we can map all possible integers to a distinct bit with the available memory. The logic is as follows:

1. Create a bit vector (BV) of size 4 billion.
2. Initialize BV with all 0s
3. Scan all numbers (num) from the file and write BV[num] = 1;
4. Now scan again BV from 0th index.
5. Return the first index which has 0 value.

```java
byte[] bitfield = new byte[0xFFFFFFFF];
void findOpenNumber(int number) throws FileNotFoundException {
    Scanner in = new Scanner(new FileReader("input_file_q1_4.txt"));
    while (in.hasNextInt()) {
        int n = in.nextInt();
        /** finds the corresponding number in the bitfield by using the
        * OR operator to set the nth bit of a byte (e.g. 10 would
        * correspond to the 2nd bit of index 2 in the byte array). */
        bitfield[n / 8] |= 1 << (n % 8);
    }
    for (int i = 0; i < bitfield.length; i++) {
        for (int j = 0; j < 8; j++) {
            /** Retrieves the individual bits of each byte. When 0 bit
            * is found, finds the corresponding value. */
            if ((bitfield[i] & (1 << j)) == 0) {
                System.out.println(i * 8 + j);
                return;
            }
        }
    }
}
```

## Follow Up: What if we have only 10 MB?

It's possible to find a missing integer with just two passes of the data. We can divide the integers into blocks of some size (we'll discuss how to decide on size later). Let's assume that we divide the integers into blocks of 1000. So, block 0 represents the numbers 0 through 999, block 1 represents 1000-1999, etc. Since the range of ints is finite, we know that the number of blocks needed is finite.

In the first pass, we count how many ints are in each block. That is, if we see 52, we know that is in block 0, we increment counter[0]. If we see 1425, we know that is in block 1, we increment counter[1]. At the end of the first pass, we'll be able to quickly spot which block is missing. If our block size is 1000, any block which has fewer than 1000 numbers must be missing a number. Pick any one of those.

In the second pass, we'll actually look for which number is missing. We can do this by creating a simple bit vector of size 1000. We iterate through the file, and for each number that should be in our block, we set the appropriate bit in the bit vector. By the end, we'll know which number is missing. 

Now we just have to decide what the block size is. At 2^20 values per block, we will need an array with 2^12 counters and a bit vector in 2^17 bytes. Both of these can comfortably fit in 10MB. What's the smallest footprint? Let N = 2^32:

- counters (bytes): blocks * 4
- bit vector (bytes): N / 8
- blocks * 4 = (N / 8)
- blocks = N / 32
- It's possible to find a missing integer with just under 65KB (or more, sqrt(N)/2)/4 bytes).

```java
int bitSize = 1048576; // 2^20 bits (2^17 bytes)
int blockNum = 4096; // 2^12
byte[] bitfield = new byte[bitSize/8];
int[] blocks = new int[blockNum];

void findNumber() throws FileNotFoundException {
    int starting = -1;
    Scanner in = new Scanner(new FileReader("input_file_q1_4.txt"));
    while (in.hasNextInt()) {
        int n = in.nextInt();
        blocks[n / (bitfield.length * 8)]++;
    }
    for (int i = 0; i < blocks.length; i++) {
        if (blocks[i] < bitfield.length * 8) {
            /* if value < 1000, then at least 1 number is missing
            * that section. */
            starting = i * bitfield.length * 8;
            break;
        }
    }
    in = new Scanner(new FileReader("input_file_q1_4.txt"));
    while (in.hasNextInt()) {
        int n = in.nextInt();
        /* if the number is inside the block that's missing numbers
        * we record it */
        if (n >= starting && n < starting + bitfield.length * 8) {
            bitfield[(n-starting) / 8] |= 1 << ((n - starting) % 8);
        }
    }
    for (int i = 0; i < bitfield.length; i++) {
        for (int j = 0; j < 8; j++) {
            /** Retrieves the individual bits of each byte. When 0 bit
            * is found, the corresponding value. */
            if ((bitfield[i] & (1 << j)) == 0) {
                System.out.println(i * 8 + j + starting);
                return;
            }
        }
    }
}
```

## 12.4 You have an array with all the numbers from 1 to N, where N is at most 32,000. The array may have duplicate entries and you do not know what N is. With only 4KB of memory available, how would you print all duplicate elements in the array?

### SOLUTION

We have 4KB of memory which means we can address up to 8 * 4 = 32,768 bits. Note that 32768 is greater than 32000. We can create a bit vector with 32000 bits, where each bit represents one integer.

NOTE: This isn't an es difficult problem, it's important to implement this cleanly. We will define our own bitset class to hold a large bit vector.

```java
public static void checkDuplicates(int[] array) {
    BitSet bs = new BitSet(32000);
    for (int i = 0; i < array.length; i++) {
        int num = array[i] - 1; // bitset starts at 0, numbers start at 1
        if (bs.get(num)) {
            System.out.println(num);
        } else {
            bs.set(num);
        }
    }
}
```

class BitSet {
    int[] bitset;
    public BitSet(int size) {
        bitset = new int[size >> 5]; // divide by 32
    }

    boolean get(int pos) {
        int wordNumber = (pos >> 5); // divide by 32
        int bitNumber = (pos & 0x1F); // mod 32
        return (bitset[wordNumber] & (1 << bitNumber)) != 0;
    }

    void set(int pos) {
        int wordNumber = (pos >> 5); // divide by 32
        int bitNumber = (pos & 0x1F); // mod 32
        bitset[wordNumber] |= 1 << bitNumber;
    }
}
```
