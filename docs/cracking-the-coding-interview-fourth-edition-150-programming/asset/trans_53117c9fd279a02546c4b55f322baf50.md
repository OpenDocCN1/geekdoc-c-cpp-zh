# 面试中 | 五种算法方法

```
merge(c, ab) --> cab, acb, abc
merge(c, ba) --> cba, bca, bac
```

算法：使用递归算法。通过“切掉”最后一个字符并生成 s[1...n-1]的所有排列来生成字符串的所有排列。然后，将 s[n] 插入字符串的每一个位置。

注意：基础情况（Base Case）和构建算法（Build Algorithms）通常会引出自然的递归算法。

## 方法 V：数据结构脑风暴

描述：这种方法很取巧，但通常有效。只需遍历数据结构列表并尝试应用每种结构。

示例：随机生成数字并存储在一个（可扩展的）数组中。你如何跟踪中位数？

数据结构脑风暴：

- 链表？可能不行 - 链表在访问和排序数字时表现通常不好。
- 数组？也许可以，但你已经有一个数组了。你能以某种方式保持元素排序吗？那可能代价很大。我们先放放这个，如果需要的话再回来。
- 二叉树？这是可能的，因为二叉树在排序方面表现良好。事实上，如果二叉搜索树是完美平衡的，顶端可能是中位数。但要注意 - 如果元素个数是偶数，中位数实际上是中间两个元素的平均值。中间两个元素不能都位于顶端。这可能是一个可行的算法，但我们稍后再。
- 堆？堆非常擅长基础排序以及跟踪最大值和最小值。这很有趣 - 如果有两个堆，你可以跟踪元素中较大部分和较小部分。较大部分存储在最小堆中，使得较大部分中最小的元素位于根节点。较小部分存储在最大堆中，使得较小部分中最大的元素位于根节点。通过这些数据结构，你潜在的中位数元素位于根节点。如果堆的大小不再相同，你可以通过从一个堆中弹出一个元素并推入另一个堆来快速“重新平衡”堆。

注意，你做的题越多，对应该应用哪种数据结构的直觉就会越发达。

# 面试中 | Offer 及以后

## 恭喜！你拿到 Offer 了！

如果你足够幸运拿到了 Offer（我相信你一定会拿到的！），恭喜你！你现在可能在为接受哪个 Offer 以及所有这些趣事感到压力，所以请记住，很可能，你所有的选择都是棒的，你在任何一个地方都会快乐的。

至于选择哪个 Offer，额吧，我们可以告诉你金钱并不重要，诸此类的……但我们会跳过这些，让你自己对金钱重要性做出决定。我们对你还有其他建议。

## 谈判

总是可以商议的！好吧，也许不是总是，但即使招聘官告诉你不是如此，Offer 通常也是可以商量的。如果你有一个有竞争力的 Offer 会有帮助。但是，不要撒谎 - 微软知道 Google 提供了什么，如果你编造数字将是不现实的。此外，技术圈很小，人与人之间会传话。保持诚实。

## 薪水到底如何？

考虑整个 Offer 包。很多公司会有令人印象深刻的薪水，但年终奖很少。其他公司会有巨额年终奖，但工资较低。这非常令人困惑，通常不清楚哪家提供的更多。确保你查看整个包（薪水、入职奖、医疗福利、加薪、年终奖、搬迁费、股票、晋升等）。

## 你的职业选择如何？

即使金钱是唯一的标准，也要考虑长远职业。如果你幸运地有几个 Offer 可以选择，考虑每一个从长远来看会对你的职业产生什么影响。薪水最低但你能学到最多的公司可能就是最好的，即使在财务上也是如此。

我无法给你任何决定最佳 Offer 的魔法公式，但以下是我建议你考虑的（按特定顺序排序）：

- 职业路径：为你的职业制定计划。你希望在 5 年、10 年和 15 年后做什么什么？你需要开发哪些技能？哪家公司或职位将帮助你达到那里？
- 晋升机会：你最终渴望进入管理层，还是更倾向于成为一名日益资深的开发者？
- 金钱和福利：当然，金钱仍然很重要（但如果你处于职业生涯早期，它可能并不重要）。如上所示，确保你查看整个包。

# 面试中 | Offer 及以后

快乐感：你喜欢那里的人吗？产品吗？地点吗？当然，在开始工作之前很难判断。如果你不开心，更换团队的机会有哪些？

品牌：公司品牌名称对你未来的职业意义重大。有些公司名称会为你开启大门，而另一些则没那么容易。

公司稳定性如何？我觉得个性的影响比大多数人认为的要小。市上有如此多的软件公司。如果你被裁了并需要找新工作，找新工作困难吗？只有你才能回答这个问题。

## 在工作中，以及之后……

在入职公司之前，制定一个职业计划。你希望你的职业看起来是什么样？达到那里需要什么？确保你定期检查职业计划，以确保你处于正轨上。

这很容易，特别是在大公司，很容易陷入留待一段时间的状态中。它们是很棒的公司，有很多福利，大多数人在那里都很开心。如果你想一一辈子当工程师，那完全没有问题。

然而，如果你有一天想经营公司，或者进入管理层，你应该停止并检查你的职业计划。
