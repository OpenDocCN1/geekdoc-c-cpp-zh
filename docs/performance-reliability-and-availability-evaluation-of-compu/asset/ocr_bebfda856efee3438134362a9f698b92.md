# Performance Reliability, and Availability Evaluation of Computational Systems

An error is a state of a component of a system (a system substrate) that may cause a subsequent failure (Figure 16.2). A failure occurs when an error is not contained, reaches the system interface, and alters the system. A fault is an event that causes an erroneous substrate [31]. A system with faults that delivers its specified functionality is fault-tolerant; the system does not fail even when there are faulty components.

Summarizing, a fault causes an erroneous substrate. The error can spread through the system because the output of one component may be an input of other components. If the erroneous substrate is not contained, it propagates to the system interface and causes a failure.

For instance, consider an air conditioner switch contact that is stuck open; that is, it is always independently on the switch position. Thus, we already failed the beginning of operations (switch position in open) but there is not yet an error. however, if we change the switch position to closed, the fault causes an error (if not contained), which, in turn, causes a malfunctioning (failure) since the switch contact does not close, and the air conditioner does not start.

Hardware faults can be classified by several aspects. A fault may be active or dormant; otherwise, it is dormant. Concerning durations, faults can be permanent, transient, or intermittent. A permanent fault is a component that is out of service. One example is a burnt-out incandescent lamp. A transient fault causes a component to malfunction for some time, but the component is fully restored after that. Intermittent faults, on the other hand, never go away. They oscillate between dormant and active. A loose electrical connection is an example of an intermittent fault. Fault can also be classified as benign and malicious. A fault that only causes a component to go out of service is called benign. Malicious faults produce plausible but incorrect output. As an example, assume an altitude sensor in an airplane that reports 2000 m altitude to one component and 1200 m altitude to another component [218].

A programming bug (fault) causes erroneous states. For instance, assume a function is presumed to calculate the value of three-dimensional space, but it calculates twothirds of the respective space due to a programming bug. This bug (fault) will run in an erroneous state (error) only when the particular function is executed, and if the erroneous state is not contained, it will propagate to generate a failure.
