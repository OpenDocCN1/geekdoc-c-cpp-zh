# 24 Workload Characterization

This chapter introduces some essential concepts related to workload generation and methods that support workload modeling. Workload may be defined as the amount of work carried out by a system in a specified period. Such a concept has been used in many areas of science and engineering. After some basic definitions, the types of workloads are introduced, and the issues involved in selecting, and analyzing workloads for computer systems [139] are discussed. After, we examine workload generation methods, benchmarks, and synthetic workload generation techniques. Later, we examine workload modeling.

In this context, the workload refers to all inputs that affect the computer system's behavior, such as application programs, services, transactions, and data submitted to a system [66]. When a computer executes a specific workload, it uses the particular system resources such as processor, cache, bus, memory, storage, and network that compose the computer system [53]. Therefore, evaluating computer system performance is only meaningful when the workload context is defined [400]. Here, for meaningful performance measurement, the workload should be carefully selected to achieve the aims by the performance analysis [188].

Defining a suitable workload depends on the type of system being considered, such as a personal computer, a database server, a web-server, an application server accessible on the internet, a mainframe, and a supercomputer; and type of application carried out by the system. Workloads are used, in general, for their primary purposes:

- 1. Evaluation of an existing system for diagnosis and improvements via configuration and upgrade,
- 2. Selection of alternative systems, and
- 3. Analysis of new design proposals.

The level of detail required for workload characterization depends on the evaluation's aims. For instance, when evaluating an operating system scheduling strategy (scheduling workload), it may be required only to represent when processes are “running”, “waiting” for some I/O response, and “blocked”. However, when studying a processor's instruction set ((instruction set workload)), a more elaborated depiction is needed, where the instruction mix is an essential aspect for discerning the effect of adding functional units. Instruction dependencies are vital for exploiting Performance, Reliability, and Availability Evaluation of Computational Systems the advantages of adopting pipelining, branch prediction, and out-of-order instruction execution. Workloads that exploit loop sizes are critical for evaluating the cost-benefit relation of instruction caching. Attributes as I/O sizes (I/O workload), methods of file access, and read-write operations are of paramount importance when evaluating I/O devices. Virtual memory mechanisms support paging and segmentation; thus affecting the use of the main memory. Here, when the number of executed programs uses many portions of scattered data, memory resource becomes a bottleneck for performance. **Memory workload** aims at exercising the memory of the system for supporting memory management policies. A **database workload** bounds resources consumed within a database to high-level search-query-language commands, users, applications, and servers [434]. **Application-level workloads** may specify the sequences of transactions handled by a database to exploit the distinct behavior between a large database, and a database that provides data to a webserver. Such workloads are created on application-specific transactions that depend on the application's functionality, and may include, for instance, entering and delivering orders, recording payments, checking the status of orders, and monitoring the level of resource usages [297, 298].

The interest is increasing in terms of the workload due to the temporal variation of the altered patterns. Internet workloads typically exhibit temporal temporal changes when distinct patterns are observed at different hours of the day and different days of the week. Therefore, if we analyze the average workload throughout a period of great variability, the analysis will undoubtedly reflect the “average” behavior, but it will not describe the users' workload perception. Besides, internet applications and services are continually evolving. Assume, for instance, social networking, live-video, and video-on-demand applications. Such applications are inherently dynamic due to the content popularity of generation service or content [13].

Moreover, the workloads at two end nodes might be different. Clients usually interact with a limited number of servers, and servers typically interact with many clients at a time. Bases caching also modify the data streams between clients and servers [136]. In this context, a **web-server workload** may be characterized by the number of transaction requests (intensity) per unit time and the types of transactions since all transaction requests are not identical, and some servers perform well when dealing with objects, and not properly for requests that require database access [55].

## 24.1 TYPES OF WORKLOADS

This section discusses some important concepts related to computer systems' workloads. Classifying workloads is not easy due to many perspectives that may be considered [66, 136, 148, 188]. The classification discussed in this section also not intend to cover all such perspectives. Instead, we aim to classify the several types of workloads we intend to discuss in this chapter.

In this chapter, we classify the computer workloads into three main classes, here the second is subdivided into two sub-classes:

- Real Workload
- Synthetic Workload
  - Benchmarks
  - Operational Workload
- Performance Work Model

A real workload is a timely ordered set of requests, transactions, program executions, and tasks carried out by a computer system during a production period of interest. By production period, we mean the time interval computer system executes its ordinary, common tasks. This workload indeed represents the computer system load demand that occurred in that specific time. The load changes from hour-hour, weekday to weekday, and season to season; however, a fundamental task for gathering-representative data is the definition of the measuring period and the sampling frequency. The sampling frequency is a key concern when a sampling strategy is adopted instead of a complete record of activities during the production period.
