The failed server may be repaired; thus taking the system back to state $S_0$ with a rate of $\mu$. Thus, the second server may fail; thus reaching state $S_7$ with a rate of $\lambda$. The third event is the successful manual switchover, which takes the system to state $S_2$ with a rate of $m \times \alpha$. The last event is the unsuccessful switchover, which transitions the system to state $S_3$ with a rate of $(1 - m) \times \alpha$. In state $S_5$, the system only handles 50% of the HTTP requests. In state $S_0$, two events are possible: first, the failed server may be repaired. This events the system back to state $S_0$ with a rate of $\mu$. The other possible event is the second server failure, which turns the system unavailable by reaching state $S_7$ with a rate of $\lambda$. It is assumed there is only one repair facility. Therefore, a repair takes the system from state $S_7$ to state $S_2$.

The system availability is estimated from

$$A = 1 - \pi_{S_7},$$

which leads to

$$A = \frac{\mu(\mu((3-2c)\lambda + \delta) + 2\lambda(\delta + \lambda))}{\mu^2((3-2c)\lambda + \delta) + 2\lambda\mu((c-2)\lambda) + 2\lambda^2(\delta + \lambda)} \quad (21.7.7)$$

The capacity ordered is calculated using

$$COA = \frac{2 \times \pi_{S_0} + \pi_{S_2} + 0.5 \times \sum_{i \in \{1,3,4,5,6\}} \pi_{S_i}}{2}, \quad (21.7.8)$$

## 21.8 SIMILAR MACHINES WITH INDEPENDENT REPAIR FACILITIES

A system composed of $M$ servers installed in racks as shown in Figure 21.42. Assume these servers are repaired as part of a cloud data center that provides IaaS [65, 271, 332]. Consider the time to failure of each server is independent and exponentially distributed with a rate of $\lambda$. Moreover, each server has an independent repair facility and the time to repair of each server is independent and exponentially distributed with a rate of $\mu$.

The system availability and reliability may be calculated using RBD or FT but may also be computed using CTMC. The CTMC shown in Figure 21.43 is an availability model of such a system. State $M$ denotes a system with $M$ servers available. If one server fails, the system transitions to $M-1$ with rate $M\lambda$. In state $M-1$, the failed server may be repaired with a rate of $\mu$, or a second server may fail, which transitions to the state $M-2$ with a rate of $(M-2)\lambda$. Similar behavior is seen in the following states. In state 0, however, there is no available server; hence the only possible event is repairing a server, which transitions to state 1 with a rate of $M\mu$ since each server has its repair facility. Solving $Q=0, \sum\pi_i=1$, we get the probability of each state $i$ by

```
$$\pi_i = \frac{M!}{i!(M-i)!} \times \frac{\lambda^{M-i}\mu^i}{(\lambda+\mu)^M} \quad (21.8.1)$$
```

As a comment on the worth of the availability model shown in Figure 21.33 is required to supporting a simpler model by removing some rare occurrence events. For instance, the likelihoods of repair events when states $S_1$ and $S_4$ are rare since the rate $\beta$ is much higher than $\mu$. Hence, the availability model's analytics metrics be significantly improved at the expense of a slight loss of accuracy. This type of practical simplification would be fundamental to the process of reaching a closed-form solution.
