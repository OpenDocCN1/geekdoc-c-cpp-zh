### Table 23.1 TCP Flags

| Value | Flag Type | Description |
| :--- | :--- | :--- |
| S | SYN | Connection Start |
| F | FIN | Connection Finish |

where 50394 is the port number. After the source and destination addresses, the TCP flags are provided; in this specific case, it is Flags (Table 23.1 shows some typical flags). This field can also be a combination of flags, such as [S], for a SYN-ACK packet.

Next is the sequence number of the data contained in the packet. For the first packet captured, this is an absolute number. Subsequent packets use a relative number to make it easier to follow. In this example, the sequence is seq 2921:4381, which means this packet contains 2921 to 4381 of this flow. This is followed by the acknowledge number ack. In this specific case, the packet was received; hence, this flow represents the next expected date (ack 430). When sending a packet, the ack value is ack 1. The window size (win 62440) specifies the number of bytes available in the receiving buffer by TCP options. Finally, the packet length is the length (in bytes) of the payload, which is the difference between the last (4381) and first (2921) bytes, which is 4381 - 2921 = 1460.

The tcpdump allows filtering of the captured packets by a variety of parameters, such as source and destination IP addresses, protocols, ports. Consider, for instance, we want to capture ICMP packets. The command line "tcpdump -i any icmp > tcpdump_test" sniffers ICMP packets looking at every interface and writes the traffic headers in the flow tcpdump_test. A typical chunk of data contained is shown below.

```
18:10:44.754016 IP ubuntu > ec2-54-204-39-132.compute-1.amazonaws.com: ICMP
echo request,
id12648, seq 1, length 64
18:10:44.953102 IP ubuntu > ec2-54-204-39-132.compute-1.amazonaws.com : ubuntu: ICMP
echo reply,
id12648, seq 1, length 64
18:10:45.396782 IP ubuntu > ec2-54-204-39-132.compute-1.amazonaws.com: ICMP
```

The header's content may vary depending on the type of packet. However, the TCP header has its first field, which represents the timestamp of the received or sent packet. The field denotes the network layer protocol (IP for IPv4 and IP6 for IPv6). In this particular case, we have IP. The next field is the source IP and port (80). Port 80 is adopted for HTTP traffic. The next field is the destination IP address and port 192.168.61.128.50394.

The command tcpdump is capable of monitoring many different protocols, such as IP, UDP, ICMP, and other. The aim here is not to support the reader getting started. Details and formats of different protocols may be found in tcpdump's manual. Assume the packet captured by tcpdump below:

```
16:14:06.396782 192.168.61.128.50394 > 192.168.61.128.50394: Flags [], seq 2921:4381, ack 430, win 62440, length 1460
```

Likewise, we can sniff packets based on the source or destination hostname. The command line "sudo tcpdump -i any -c 4 -n src 54.204.39.132 > tcpdump_test" sniffers packets coming from 54.204.39.132 and writes the traffic headers in the file tcpdump_test. A typical chunk of data contained is shown below.

```
18:10:02.273334 192.168.61.128.50394 > 192.168.61.128.50394: Flags [], seq 2921:4381, ack 430, win 62440, length 1460
```

Similarly, the command line "sudo tcpdump -i any -c 4 -n dst 54.204.39.132 > tcpdump_test" sniffers packets sent to 54.204.39.132 and writes the traffic headers in the file tcpdump_test. A typical chunk of data contained is shown below.
