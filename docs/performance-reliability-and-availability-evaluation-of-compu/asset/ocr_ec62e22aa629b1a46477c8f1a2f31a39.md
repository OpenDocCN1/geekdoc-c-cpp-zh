# 22.11 COMMON CAUSE FAILURE

This section shows how to represent a CCF using SPN. The system is composed of two classes of servers, server-class 1 (SC1) and server-class 2 (SC2). The number of servers of type SC1 is NS1, and the number of servers of type SC2 is NS2. The time to failure of each server class is exponentially distributed with MTTF1=10000h and MTTF2=15000h. Two repair teams are available - so the servers of RS1 and RS2 are ass and the time to repair is also exponentially distributed with MTTR=20h. The common mean time to failure is assumed to be exponentially distributed with MTTccf=100000h.

An availability of such a system is depicted by the SPN shown in Figure 22.37. The number of tokens in S1U denotes the number of servers of class SC1 in the operational state, whereas the number of tokens in S1D represents the number of servers of class SC1 in failure. Likewise, the number of tokens in S2U represents the number of servers of class SC2 in the operational state, and the number of tokens in S2D represents the number of servers of class SC2 in failure. The server semantics of transitions FS1 and FS2 are sss, and the transitions' server semantics are sss. Transition CCF represents the common cause of failure. MTTF1 is assigned to FS1, MTTF2 is assigned to FS2, and MTTCF is associated with transition CC. RS1 and RS2 have MTTR as their delays. The arcs connecting S1U to CCF are marking dependent, and the weight is equal to #S1U. Similarly, the arcs connecting S2U to CCF are marking dependent, and the weight is #S2U.
