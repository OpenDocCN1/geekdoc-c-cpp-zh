## 22.2 MODELING TTF AND TTR WITH PHASE-TYPE DISTRIBUTION

This section presents a single-component system whose time to failure and to repair are not exponentially distributed. Here, phase-type distributions were adopted to represent the TTF and TTR (see Section 13.3.8). In this specific case, the TTF is modeled by an Erlang distribution with $K$ phases and with phase rate $\lambda = 1/ttfph$, where $ttfph$ is the mean value of each exponential phase of the distribution. A Cox-1 distribution represents the TTR. The Cox-1 distribution has three parameters: $\omega_0, \omega_1, KC$ and $\mu = 1/ttprph$, where $KC$ is the number of phases, $ttprph$ is the mean value of each exponential phase of the Cox-1 distribution (see Section 13.3.8). A token in place $P_0$ represents an operational component, whereas a token in $P_1$ represents a failure. ## 22.3 HOT-STANDBY REDUNDANCY

This section presents an SPN model for hot-standby redundancies. As done with CTMCs in Section 21.2, we consider a case in which one repair facility is available and a case when the number of repair facilities equals the number of system components (also see Section 18.5 and 19.2). This system is composed of two equivalent servers configured in hot-standby redundancy (see Figure 22.7a). The TTF and TTR of those servers are exponentially distributed with rates $\lambda$ and $\mu$, respectively. Hence, MTTF = $1/\lambda$ and MTTR = $1/\mu$.

First, consider a case in which one repair facility is available. The SPN availability model is shown in Figure 22.7b. This model comprises two places, $COK$ and $CF$, which transition to $F$ and $R$, and the respective arcs. The initial marking of place $COK = 2$ (#COK = 2 in Mercury notation) stating that both servers are available at time $t=0$. The number of tokens in $COK$ denotes the number of servers available, whereas the number of tokens in $CF$ represents faulty servers. Transition $F$ firing represents a server failure, and the transition $R$ firing denotes repairing. The server semantics of $F$ is $iss$ since both servers are concurrently operating and the server semantics of $R$ is $sss$; in this case, we adopt only one repair facility. The arcs' weights are one.

As the system is properly working as long as at least one server is available, the steady-state availability is calculated through the expression

$A = P\{#COK > 0\}$

that is the probability of place *COK* having at least one token. The unavailability be computed through

$UA = P\{#CF > 1\}$

and the downtime in a period $T$ is calculated through

$DT = P\{#CF = 1\} \times T$.

The instantaneous availability is calculated through the expression

$A = P\{#COK > 0\}(t)$,

in Mercury-like notation. A reliability SPN model is proposed in Figure 22.7c. This model is somewhat similar to the SPN (availability model) shown in Figure 22.7b, but the arc that connects the place $CF$ to transition $R$ is marking dependent and has this expression:

$IF(\#CF > 1) : (3)ELSE(1)$;

that is when both servers fail $\#CF > 1$ the arc weight is three; otherwise it is one; thus, the repairing is impossible. In other words, the marking $M = (m_{COK}, m_{CF}) = (0,2)$ is an absorbing marking. Therefore, the value of the metrics

$R(t) = P\{#COK > 0\}(t)$,

when analyzing this SPN (transient analysis - see Section 10.5) is the reliability at $t$.
