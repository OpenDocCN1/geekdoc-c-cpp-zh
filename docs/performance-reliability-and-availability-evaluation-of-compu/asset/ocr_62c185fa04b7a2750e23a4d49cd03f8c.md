i denotes the transaction instance, that is a first transaction, second, third..., tr, as we are already aware, represents the transaction type (tr=1 and tr=2), gt denotes the global time registered in the trace generation. It is a cumulative time that starts at gt=0 and is incremented by the winning event (short delay) assigned to $ta=F_{\alpha}^{-1}$ and $tl=F_{eta}^{-1}$ or $tm=F_{\mu}^{-1}$. The variable $bg$ is the number of bytes transferred in each transaction. When states $s_0$ and $s_1$ are reached, a value is generated and assigned to $bt_1$, which is then assigned to $bt_2$. Likewise, when states $s_2$ and $s_3$ are reached, a number is generated and assigned to $bt_2$, and then to $bt_3$. Finally, $tbt$ is a variable that records the time between each transaction. Such values are obtained from those values generated and assigned to $tl=F_{eta}^{-1}$ and $tm=F_{\mu}^{-1}$. In this particular case, the time units adopted are seconds (s), and the simulator finishes its execution when a one-thousand-length trace (nt=1000 transactions) is generated.

As a specific case, let us define $\alpha=5ps, \beta=10ps, \lambda=350ps,$ and $\mu=700tps$. Besides, let us specify $\omega_1=400 \times 10^{-6}bytes^{-1}$ and $\omega_2=200 \times 10^{-6}bytes^{-1}$.
