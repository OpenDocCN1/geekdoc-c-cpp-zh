## httpperf

This software is a tool implemented in the C programming language at HP Research Labs for generating HTTP workloads and measuring server performance. The initial focus of httpperf providing facilities to build benchmarks. The httpperf is logically divided into three parts: the core HTTP engine, workload generation, and statistics analyzer [182, 292].

The HTTP engine handles the communication with the server and takes care of connection management and HTTP requests and replies handling. The workload generation initiates the HTTP calls at the appropriate times, so a particular workload is induced into the server. The statistics analyzer estimates various performance statistics.

Let us show some performance generated by HTTP by looking at some examples. Executing the command

```
> httpperf --server www.google.com
```

The field Connection Rate tells the input rate in connections per second format. The First Connection is the time between the connection initiation and closure. The Connection Time depicts the average connection time if multiple connections were initiated. The field Length tells us the average number of replies each connection has received. The Request Rate shows the rate at which the HTTP requests were issued. The Request Size depicts the request size in bytes. The field Reply rate informs the rate at which the server replies to the requests. Reply Time shows the time taken by the web-server to respond to the request and the time taken to receive this reply. The Reply Size is similar to the request size; Finally, the Reply Status shows the status code of the reply that httpperf received from the server. The rest of the two sections are for CPU and resources the client spends in carrying out the tests and errors encountered during the test.

The following command is similar to the previous one, but instead of providing the URL, the IP address is specified.

```
> httpperf --server 172.217.03.36
```

The following command, besides the IP address, the connection rate (-rate 600 requests per second) and the number of sessions is specified (-num-conns 20 -20 sessions). The default number of calls per session is one; each connection (session) executes one HTTP call and, if it succeeds, gets the reply.

```
> httpperf --hog --server 172.217.03.36
      --rate 600 --num-conns 20
```

The -hog uses as many TCP ports as required. Without this option, httpperf is typically limited to using ports in the range of 1024 to 5000, which can become a bottleneck. This option must also be specified when measuring NT servers since it avoids TCP incompatibility between NT and UNIX machines.

The command below, besides the information provided in the previous command, also defines the port which is 80. The -port defines the number of ports (N) on which web-server is listening for HTTP requests. Its default value is 80.

```
> httpperf --server 172.217.03.36 --port 80
      --rate 600 --num-conns 20
```

The command line below creates calls to the server specified by http://www.google.com/index.html. The request rates specify two hundred requests per second, and the timeout of each call is five seconds. The default port is used.

```
> httpperf --server www.google.com --uri /index.html
--num-conns 50
--num-call 10 --rate 200 --timeout 5
```

The command line below generates a total of five sessions at a rate of 600 sessions per second. Each session consists of twenty calls spaced out by two seconds, and a timeout of 5s for each call.

```
> httpperf --server www.google.com --uri /index.html
  --wsess=5,20,2 --rate 600 --timeout 5
```

The option -period=[D][T1][T2] specifying "interarrival time" can alternatively be specified by the option "u". However, more alternatives are available with period. The D parameter specifies the interval distribution. If omitted or set to "d", a deterministic period is specified by parameter T1. If D is set to "e", the exponential distribution is used with a mean interarrival time of T1. If D "d", "e" or "u" are omitted, it is equivalent to "d", and the period is specified by parameter T1 in units of seconds. The default value for the period is 0. In such a case, sessions are generated sequentially without any delay. Hence, it is worth noting that specifying, -rate=5 is equivalent to specifying -period=d0.2 or -period=0.2. The following command lines show adopting these possible ("d", "e" or "u”).

```
> httpperf --server www.google.com --uri /index.html
  --wsess=5,20,2 --period=d0.0017 --timeout 5
```

```
> httpperf --server www.google.com --uri /index.html
  --wsess=5,20,2 --period=e0.0017 --timeout 5
```

```
> httpperf --server www.google.com --uri /index.html
  --wsess=5,20,2 --period=u0.0017,0.0024 --timeout 5
```
