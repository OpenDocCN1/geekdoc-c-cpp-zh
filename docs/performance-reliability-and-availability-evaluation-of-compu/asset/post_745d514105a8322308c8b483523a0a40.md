Information Technology Consulting Corporation (ITIC) has provided reliability data of mainstream server manufacturers, operating systems, and virtualization platforms. The ITIC 2020 Global Server Hardware, Server OS Reliability Report evaluates the systems’ reliability by weighing metrics and policies such as (1) automated and manual patch management, (2) Tier 1, Tier 2, and Tier 3 help calls, (3) inherent OS reliability, (4) inherent server availability, (5) unavailability due to planned outages and upgrades, (6) security issues, (7) human error, (8) server virtualization reliability, (10) vendor technical services, (11) understaff information technology departments, (12) servers’ hardware aging, (13) integration and interoperability features [186, 457].

Electronic Parts Reliability Data (ERPD) document presents failure rates on electronic components from historically observed empirical on the field. Data comprised in this document presents average failure rates and the respective confidence intervals. The failure rate was obtained by combining varying failure rates on similar parts from various sources [127]. Likewise, the Non-electronic Parts Reliability Data (NPRD) document provides failure rates on diverse electrical, mechanical, electromechanical, and microwave parts based on observed failed fields [314].

Backblade is a cloud storage and data backup company. Backblade has providing reliability data of its storage systems and devices [33]. The approach adopted by Backblade is to take a daily snapshot of each operational storage device of its datacenters. This snapshot includes basic information along with statistics relating to that drive. All of the drive snapshots for a given day are collected into a “CSV” format file. The initial row of each column names, and the additional rows are the actual data. The columns record the data collection date, serial numbers, manufacturer-assigned serial numbers of the drives, capacities, and if the device is functional or in failure. Backblade makes these datasets freely available, and they can be accessed on the Internet.

A final warning is needed when using reliability data from sources mentioned above and others. Failure rate combines many inherent parameters that may drastically modify the most basic figures over which predictions are to be assessed. Therefore, failure rates as primary parameters should be adopted from those sources with caution. Here, it is prudent to state that in many circumstances, reliability estimates from models that data should be assessed:

- * as approximations of the reliability, the design is qualified in the field,
- to produce relative comparisons to support decisions, and
- * as a basis for contractual requirements.

Hence, a relevant recommendation is to adopt a conservative view of data provided by manufacturers, companies-consortia, general data sources.

## 25.1.2 CENSORING

This section provides more details about the censoring process. Censoring arises when the data are incomplete units were withdrawn from consideration prior to failure or units functioning when the observation period started, but we do not know how long these units have been operating. In addition, units may be removed, for instance, when they fail of other failure modes than the one being estimated.

The data is set to be Left-Censored when we do not know all the units were placed into operation. In this case, we know that a unit is operating when the observation period starts, but not how long the unit has been functioning. The data is said to be Right-Censored when observation of a lifetime may be terminated before the item fails. For example, a set of n similar servers are under a lifetime test. The time required to observe the lifetime (time to failure) of all servers in the study may be large enough that, due to practical constraints, it may prevent the failure observation of all servers. Thus, these servers that do not fail during the observation are said to be right-censored.

A lifetime data set is singly censored when censoring times are the same. The other hand, in multiply censored data, the censoring times occur at many different times. For example, figure 25.1 depicts three data sets (a), singly censored data set (b), and multiply censored data set (c).

Now assume a specific case where five servers ($S_1, S_2, S_3, S_4$, and $S_5$) are under a reliability test that lasts $T$ hours (see Figure 25.2a). During the test, $S_2, S_4$, and $S_5$ failed, the servers $S_1$ and $S_3$ did not fail. Hence, this class of censoring is Right-Censoring Type 1.

Consider that now the reliability test is finished when $k$ servers out of $n$ ($k \le n$) servers fail. For instance, as in the previous case, that five servers ($S_1, S_2, S_3, S_4$, and $S_5$) are allocated to a reliability test. Now, however, assume the test is finished when three out of the five servers fail. As an example, Figure 25.2b shows the first server to fail was $S_1$, the second server that was $S_5$, and the third server that failed was $S_3$. As the test finishes, three out of five servers $S_2$ and $S_4$ are censored. This type of censoring is named Right Censoring Type 2.

Interval Censoring occurs when a failure is known to have occurred between the times of readout $i$ and readout $i+1$ (grouped data). For example, in Figure 25.3, servers $S_5, S_1$ and $S_6$, and $S_3$ were censored in the second, third, and fourth readout since they failed between the respective readout and the previous, but the exact failure time is unknown.

Figure 25.3 shows a reliability experiment in which the failure time are grouped. The reliability experiment lasted T. One server ($S_4$) has already failed in the first readout. This is left censorship since it occurred considering the first readout (first interval). When the experiment finished, the server $S_2$ was still working; however, $S_3$ is considered a right censoring type 1. As already mentioned, in the second readout, one failure was observed ($S_5$). We know that it failed between the first and second readouts, but we did not know the precise time it failed. At the third readout, two servers were considered in failure ($S_1$ and $S_6$). $S_3$'s failure was observed in the fourth readout. In these last three cases ($S_5$, $S_1$ and $S_6$), we have interval censoring.

In the general case, each unit in a test may have a specified interval during which it is known to have failed or a past censorship time is known to have survived. These intervals and censorship times may differ from each other. In the testing, each unit rarely has a different censorship time. However, when considering field data, it is likely to occur. For instance, a data center where servers are operational. These would have different times.

## 25.2 NONparametric METHODS

Nonparametric lifetime data analysis is based on empirical time to failure (and repair), the empirical reliability (and maintainability), and the empirical hazard function. This section presents nonparametric methods for reliability data.

### 25.2.1 UNGROUPED DATA

The first method presented may be applied to complete ungrouped data; that is, it can be adopted when the times to failure of all devices are exact. Assume n servers were observed, Consider the set of $t_i$ sorted in ascending order; $t_i < t_{i+1}$ and so forth.

The reliability at $t_i$ may be estimated by

$$\hat{R}(t_i) = \frac{n-i}{n}, \quad (25.2.1)$$

where $n-i$ is the number of surviving servers at $t_i$ and $n$ is the total number of servers at the beginning of the observation period. Therefore, as $F(t) = 1-R(t)$ (see Equation 16.2.2), then

$$\hat{F}(t_i) = 1 - \frac{n-i}{n}, \quad (25.2.2)$$

As $f(t_i) = dF(t_i)/dt$ (see Equation 16.2.1), we estimate of the probability density function

$$\hat{f}(t_i) = \frac{1}{n(t_i-t_{i-1})}, \quad (25.2.3)$$

Since $\lambda(t) = f(t)/R(t)$ (see Equation 16.2.6), then

$$\hat{\lambda}(t_i) = \frac{1}{(n-i)(t_i-t_{i-1})}, \quad (25.2.4)$$

It is worth observing that for $t_n$, $\hat{F}(t_n) = 1$; $\hat{R}(t_n) = 0$, which denotes that the probability of surviving $t_n$ is null. Since it is unlikely any sample has the longest time to fail (time to repair), the Equation 25.2.1 tends to underestimate the reliability.
