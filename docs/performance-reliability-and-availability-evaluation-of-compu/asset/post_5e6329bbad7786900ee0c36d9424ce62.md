
## 244 Performance, Reliability, and Availability Evaluation of Computational Systems

If we are interested in quantifying not whether the probability of the system is available but to provide a figure of processing capacity that is available, the capacity-oriented availability (COA) could be an interesting metric [95, 437]. The capacity-oriented availability is represented by the mean number of available resources, $mn_{ar}=\sum_{i=1}^n \pi_i$, (in this case, servers) normalized by the total number of resources (in this case servers). Therefore, consider a system with $n$ equivalent servers; the capacity oriented availability can be formalized by

```
COA = \frac{\sum_{i=1}^n \pi_i}{n}
```

where $\pi_i$ is the probability of $i$ servers being up, and the constant $n$ is the total number of servers. For the case shown in Figure 21.29, we have

```
COA = \frac{2 \times \pi_2 + \pi_1}{2}
```

which leads to

```
COA = \frac{\mu(\lambda + \mu)}{2\lambda^2 + 2\lambda\mu + \mu^2}
```

when considering only one repair facility. The COA, when considering two or more repair facilities,

```
COA = \frac{\mu}{\lambda + \mu}
```

COA is a performability (performance + dependability) metric since it combines the system processing capacity with availability.

Assume each server $i$ (resource) sustains a throughput $tp_i$. Such a throughput may have been obtained through measurement, a performance model, or a specification. The average throughput - ATP (another performance metric) is the weighted sum of throughputs in the system. Consider a system with $n$ resources (servers). Each server is able to sustain a throughput $tp_i$. The throughput could be in transactions per time units, MIPS, FLOPS, Qph et al. More formally:

```
ATP = \sum_{i=1}^n i \times tp_i \times \pi_i.
```

**Example 21.7.1.** Consider the system depicted in Figure 21.29. The constant failure rate of each server is $\lambda = 10^{-7}h^{-1}$, and the constant repair rate is $\mu = 10^{-1}h^{-1}$. If only one repair facility is available, we have $A=0.99999$ and $COA=0.999$. If throughput delivered by the server is $tp = 1.2 \times 10^6$ $tph$, $tp^8 = 2.3976 \times 10^6$ $tph$, the mean throughput provided by the system is $2 \times tp \times \pi_2 + tp \times \pi_1 = 2.3976 \times 10^6$ $tph$.

$^8$Transaction per hour - tph.

## Modeling Availability, Reliability, and Capacity with CTMC

The reliability mode is equal to the CTMC depicted in Figure 21.7.a. Hence, the reliability at $t$ is obtained

```
$R(t) = 1 - \pi_0(t),$
```

and the mean time to failure can be calculated from

```
$MTTF = \int_0^{\infty} R(t)dt = \int_0^{\infty}(1 - \pi_0(t))dt$
```

or using the method based on moments described in Section 10.6.1, which leads to

```
$MTTF = \frac{(\lambda + \mu)(4\lambda + \mu)}{2\lambda^2(2\lambda + \mu)}$
```

### Two Servers Available and Processing 100% of the Workload.

**Figure 21.31** Active-Active Servers - Processing 100%. When the server is unavailable, it does not reply (see Figure 21.32). The load balancer waits for a reply during a specified period, keeps forwarding requests to the server. If the server is unavailable, these requests are lost. Assuming the load balancer evenly distributes the requests among both servers, 50% of the requests are lost. After a specified delay, the load balancer understands the server is not available and stops forwarding requests to that (see Figure 21.33). Now 100% of the HTTP requests are handled by the only available server. It is worth stressing that although 100% of the requests are covered, the processing capacity is reduced to only one server. The load balancer resumes requests to the unavailable when it replies. In this state, the system is again coping with the HTTP request, and has two servers processing the requests (see Figure 21.31). Figure 21.34 presents a CTMC that is an availability model of the system depicted in Figure 21.30. In state $S_0$ both servers are available and processing HTTP requests. A failure may occur with a rate of $2\lambda$, and such a failure may be covered with probability $c$ or stay hidden with probability $(1-c)$. It is worth noting that the probability $c$ represents the failure detection mechanism's capacity to sense a failure incident. If the failure is detected, the system transitions to state $S_1$ and otherwise to state $S_3$. In both states, $S_1$ and $S_3$, only one server is available.
