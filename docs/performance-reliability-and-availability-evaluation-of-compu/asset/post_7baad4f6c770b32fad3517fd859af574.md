The MTTF may also be obtained using the method based on methods described in Section 10.6.1 (see Equation 10.6.4).

```
$MTTF = \frac{(\lambda+\mu)(4\lambda+\mu)}{2\lambda^2(2\lambda+\mu)} \quad (21.2.5)$
```

The reliability calculated using this CTMC is higher than calculated from the RBD as well as the mean time to failure. The reason for this is that the combinatorial models (RBD and FT) do not consider the repair of the first component that fails. It is worth noting that the system continues to provide the specified service in the presence of one failure fault. The equivalent CTMC reliability model to the RBD is shown in Figure 21.7.b. The reliability for the RBD equivalent CTMC is

```
$R(t) = 2e^{-\lambda t} - e^{-2\lambda t}$
```

and the mean time to failure is

```
$MTTF = \frac{3}{2\lambda}$
```

### 21.3 HOT-STANDBY WITH NON-ZERO DELAY SWITCHING

Consider again the system depicted in Figure 21.4. This system is composed of two servers in a hot-standby configuration. The time to failure of each server is assumed to be identically distributed with a constant rate equal to $\lambda$. The time to repair a server is exponentially distributed with a rate of $\mu$. Only one repair facility is considered available. Now, assume that when the primary server fails, the standby server takes some time to take over the workload. The CTMC shown in Figure 21.11 is an availability model of such a system. The CTMC is composed of five states:

![](img/2d1450514bb14a0cdfeb504861afab_240.png)

1U, 1D, 1, and 0. In state 2, the two servers are available. In-state 0, no server is available. In-state 1U, 1D, and 1, only one server is operational.

In state 2, either the main server or the standby server may fail. If the standby server fails, the system transitions to state 1U. It is worth noting that in state 1U, the service is not interrupted by the failed server. If this happens, the standby server may be repaired, which takes the system back to state 2. In state 1U, the primary server may fail. If this happens, the system transitions to state 0. As already mentioned, the main server may fail in state 2. If it fails, the system requirement agreement states that short interruptions are allowed. The interruption occurs because the failed server is the main server (the server performing the workload). In state 1D, three events may occur. First, the primary server may fail. Second, the standby server may fail. If it fails, the system transitions to state 0. Third event is the server recovering after a delay of $1/\delta$. In state 1D, two events are possible. First, the main server may repaired, which takes the system back to state 2. Second, the standby server may fail. If this occurs, the system transitions to state 0.

### Modeling Availability, Reliability, and Capacity with CTMC

The system availability is specified by

$A = \pi_2 + \pi_1 + \pi_{1U}. \quad (21.3.1)$

Therefore, using Equation 21.2.7, Equation 21.2.8, and assuming each server's MTTR = $20h$ ($\mu = 5 \times 10^{-2} h^{-1}$), calculate the steady-state availability and the respective downtime:

$A = \frac{\mu(2\lambda_{Server} + \mu)}{2\lambda_{Server}^2 + 2\lambda_{Server}\mu + \mu^2}, \quad (21.3.2)$

For $\lambda = 1.24 \times 10^{-3} h^{-1}, \mu = 2.5 \times 10^{-1} h^{-1}$ and $\delta = 240 h^{-1}$, we obtain $A = 0.999946, DT = (1-A) \times 525600$ minutes = 28.29. Figure 21.12 presents the availability in number of nines $(-\log(1-A))$ against the switching rate, $\delta$, depicted as log $\delta$ in the interval $(10h^{-1},240h^{-1})$ (see Equation 16.2.26). Figure 21.13 shows the yearly downtime in minutes as a function of the switching rate.

![](img/2d1450514bb14a0cdfeb504861afab_241.png)

Figure 21.14 is a reliability model of the hot-standby redundancy with non-zero switching delay. In state 2, both servers may fail. However, if the standby server fails, since it is not processing the workload, the service is not immediately interrupted. Transitions to state $1U$, is still an operational state. In such a state, the spare server may be repaired, or the main server may fail. If it fails, the system becomes unavailable. If the primary server fails in state 2, the system immediately transitions to state 0. It is worth observing that in both states, 2 and $1U$, there is a transition with rate $\lambda$ to state 0. The rate matrix is

```
$Q = \begin{pmatrix} -2\lambda & \lambda & \lambda \ \mu & -\lambda-\mu & \lambda \ 0 & 0 & 0 \end{pmatrix}$
```

From $Q$, we obtain (see the Matrix Structure 10.6.3).

```
$R = \begin{pmatrix} -2\lambda & \lambda \ \mu & -\lambda-\mu \end{pmatrix}$
```
