## Command mpstat

The mpstat command provides measures for each available processor as well as global average measures among all processors. The basic syntax of this command is mpstat [options] [delay] [count], where [delay] and [count] are specified as we have defined for vmstat and the main options are.

- -V - Print version number then exit.
- -I keyword [...] — ALL - Possible keywords are CPU, SCPU, SUM. CPU reports the number of each individual interruption received per second by the processor or processors (sec/interrupts). SCPU reports the number of each individual software interrupt received per second by the processor or processors. SUM reports the total number of interrupts per processor. ALL keyword is equivalent to specifying all the keywords above.
- -P cpu [...] — ON - cpu is the processor number for which statistics are to be reported. Report 0 is the first report. ON indicates the report is for online processors. ALL indicates the report is for all processors.
- -A - This option is equivalent to specifying -u I - ALL

Executing the command "mpstat -P cpu dbs ns > output" generates the processor report log file (output) with ns samples with intervals between each sample of dbs seconds. For an example, consider "mpstat -P 0 5 > output". In this case, a report of processor 0 is generated. This report comprises four (4) samples, and the delay between samples was specified as five seconds (5 s). Below a data set is provided in file output. The averages of the samples are depicted in the last row.

## Network Time Protocol

The Network Time Protocol (NTP) is a protocol used to synchronize the system clock automatically over a network. Let us now configure a client computer to be time-synchronized with NTP servers. For first, open `/etc/ntp.conf` with the command `sudo nano ntp.conf` and include your list of NTP servers; for instance, add these lines in `ntp.conf`

```
NTP time.nist.gov iburst
TP time.nist.gov iburst
server time.nist.gov iburst
server time.nist.gov iburst
```

Configuring with option iburst, the client sends eight packets to the NTP server for calibrating a system clock, but there are other options [315]. Save ntp.conf and restart the NTP service by executing `sudo service ntp restart`. Executing `ntpq -p` or `ntpq -pn` you should be able to see the NTP servers. For instance,

```
remote refid st t when poll delay offset jitter
=====================================================
time-e-www.nist .NIST. u 49 64 1 213.551 -1406.2 631.967
time-a-g.nist.g .NIST. u 54 64 1 223.910 -1426.1 634.623.
```

Check if the computer is synchronized by executing `timedatectl status`. If the output is

Network time on: yes
NTP synchronized: no,

execute `sudo service ntp stop`, then restart the NTP service by executing `sudo service ntp restart`. After that, the command `ntpstat` may be executed. The output should look like

synchronized to NTP server (52.67.171.238) at stratum 4
time correct to within 1283 ms
poll server every 64 s

## Entry /proc/net/ and netstat

The entry `/proc/net/` provides an instant summary of various networking parameters and statistics. Its files describe aspects and status of parts of the system working sockets, and communications between devices. These files can be read by cat command. Besides the files, it contains subdirectories related to protocols. One may also use the command netstat to obtain the content of these files. The netstat most common options are:

- -t, which shows only TCP connections,
- -u, which shows only UDP connections,
- -a, which depicts listening (waiting) sockets;
- -n, which displays IP addresses, port numbers and user ids;
- -p, which lists processes involved. It is valid only netstat is executed as root,
- -c, which continuously refreshes the list of connections.

Executing the command `sudo netstat -t > netstat_dump`, the first options are activated. Typical results contained in file `netstat_dump` look like the following:
