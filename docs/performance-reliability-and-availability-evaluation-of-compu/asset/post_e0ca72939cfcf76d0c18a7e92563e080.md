## 22.4 IMPERFECT COVERAGE

Consider the system depicted in Figure 22.7.a. Now, however, assume the failure coverage is imperfect; that is, the system is configured in hot-standby, and one server may fail, and this failure may not be detected (a hidden failure). Such a failure may be later detected, or the second server available may also fail, and the service becomes unavailable. This aspect was already discussed in Section 21.4, and a CTMC model presented.

This section provides an availability and reliability models specified in SPN (see Figure 22.10). The availability model is shown in Figure 22.10a. It is composed of sets of places $P = \{COK, CF, CF, HF\}$, a set of transitions $T = \{F, R, C, U, D\}$, and their arcs (see $G(UC) := \#COK > 0 \rightarrow \{T, F\}$). The server semantics of $F$ and $R$ are $iss$ and $sss$, respectively since only repair facility is considered in this. The weights assigned to $C$ and $UC$ are $1-c$, respectively. Their priorities are equal to 1. The initial marking states that both servers are available, that is $M_{0} = (m_{COK}, m_{CF}, m_{CF}, m_{HF}) = (2,0,0,0)$.

As servers available, the only possible event is a server failure. It is worth mentioning that the server semantics of $F$ is $iss$. One server failure is depicted by firing $F$, removing one token from $COK$, and storing one token in $CF$. The new marking is $M_1 = (1,1,0,0)$, which is a vanishing marking. In this marking, $C$ fires with probability $c$ and $UC$ fires with probability $1-c$. If $C$ fires, one token is removed from $CF$, and one token is stored in $CFS$. In this new marking, the system is aware of the server failure and demands its repair. The repair is represented by the firing of transition $R$.

If, on the other hand, when marking $M_1$, $UC$ fires, the server failure is not detected by the system and becomes hidden. The hidden failure may be detected later on, after a detection time $(DT)$ represented in transition $D$, and then be repaired, or the second server may fail before the detection of the first server failure. In such a case, the service becomes unavailable. Observe that the $UC$ becomes disabled ($G(COK > 0) \rightarrow F$) once a server is in failure because a second server failure is detected since the service is no longer provided. In this example, the time to fail, repair, and detection time are exponentially distributed with rates of $\lambda$, $\mu$, and $\beta$, respectively. Hence, $MTTF = 1/\lambda$, $MTTR = 1/\mu$, and $MDT = 1/\beta$ (mean detection time).

The instantaneous system availability may be calculated through

$A = P(\{\#COK > 0\}(t))$.

The steady-state system availability may be calculated through

$A = P(\{\#COK > 0\})$.

The steady-state availability expressed in the number of nines may be calculated through

$9s = -\log_{10}P(\{\#COK = 0\})$.

The probability of having a hidden failure is

$PHF = P(\{\#COK > 0) \text{ AND } (\#HF = 0\})$.

The probability that the system is available and safe (hidden failure) is

$AS = P(\{\#COK > 0) \text{ AND } (\#HF = 0)\}$.

The downtime in a period $T$ is

$DT = P(\{\COK = 0\} \times T)$,

and the time the system stays in an unsafe state (hidden failure) in a period $T$ is

$UST = P(\{\#HF = 1\} \times T)$.

The reliability model is depicted in Figure 22.10b. It is somewhat similar to the availability model but with adjustments. This SPN must have an absorbing marking, which creates a state when both servers are available. Two changes were made in the SPN of Figure 22.10a in order to obtain an SPN that allows calculating the reliability. First, when both servers are available, system repair is not allowed. This condition denotes the service stopped; the system ceased to provide its feature was obtained by including a dependent arc between $CFS$ and $R$. The expression is $IF(\#COK = 0) : (3) ELSE(1)$. Thus, when $COK = 0$ (both servers fail), the arc weight is set to 3. Since $CFS$ will never reach 3, this marking is absorbing. The second change was the assignment of a guard expression to transition $D$, $G(D) = \#COK = 0 \rightarrow F$; thus, when no is in place $COK$, transition $D$ becomes disabled. The system reliability is calculated using

$R(t) = P(\{\#COK > 0\})$, and the probability of it being reliable and safe (hidden failure) is

$RS(t) = P(\{\#COK > 0) \text{ AND } (\#HF = 0)\}$.

## 22.5 COLD-STANDBY REDUNDANCY

This section depicts an SPN model for cold-standby redundancy. CMC models for availability and reliability were already presented in Section 21.5. The system considered in this section is depicted in Figure 22.14.a. In the initial configuration, the server $S_1$ is operational, where $S_2$ is the cold spare. This system is considered operational if one web-server ($W_i$) and one database-server ($DB_i$) are available. For these pieces of software, the server's hardware ($HW$) and its operating system ($OS$) should be (Failed), where $i$ represents each server. If one of the components ($W_i, DB_i, OS_i, HW_i$) of the server $S_i$ fails, the system fails, and the spare-server is switched on as soon as possible to resume the service being delivered. The spare server is normally switched off; hence, when a failure occurs in the main server, loaded, the web-server and database-server should be initiated in order to restore the system service (Figure 22.14.c). In the time arrival requests are lost (see Figure 22.14.b). In this model, only one repair facility is adopted, and when both servers are in failure, maintenance priority is given to S$_1$.
