# #26 Fault Injection and Failure Monitoring

Dependable systems are designed to cope with faults through mechanisms that constrain errors propagation and avoid system failures. Therefore, obtaining statistical data from the operational environment after implementing the system or from an equivalent system already operating on the field may not be a suitable alternative to the time required to obtain such data.

Indeed, fault injection has two aims: system validation and system evaluation. The first objective concerns comparing the specified behavior with the implemented system’s behavior and gaining confidence if the system behaves as expected in the presence of faults [32, 70]. The second objective aims to check the implemented system copes with faults appropriate as specified. In other words, fault methods provide means for measuring the impact of faults in the systems’ functions and performance for evaluating effective fault-tolerant mechanisms on models, working prototypes, and systems in the field. Hence, fault injection tools provide means to improve the confidence in the systems’ ability to deliver the proper service [20, 109].

Already by 1972 fault injection was adopted to test the Self-Testing And Repair computer (JPL-STAR) [28]. A major concern when adopting fault injection for a system is to ensure the generated faults represent actual faults to obtain meaningful results [251]. Fault injection methods range, from voltage glitches to electromagnetic interference, impacting light attack, heavy-ion radiation, and injected faults [60, 70, 82, 135, 217, 231, 262, 266, 300, 399, 408].

This chapter aims to characterize some important fault injection procedures and then introduce the concept of fault acceleration and fault acceleration models. Later, some noteworthy fault injection tools are briefly described, and finally, we examine a generic architecture of a software-based fault injection tool.

The faults may be applied in an existing system or functional prototype or in a model [85, 181]. This classification takes into account two perspectives: 1) the target to which faults are injected or 2) the implementation mechanism. The aim target could be: a) specifications (models) or b) systems (actual systems or system-functional prototypes). The implementation mechanism may be divided as a) hardware-based, b) software-based, and c) hardware-based fault injection mechanisms. Hardware-implemented fault injection is accomplished by disturbing the hardware with fluctuations in the environment parameters’ values.
