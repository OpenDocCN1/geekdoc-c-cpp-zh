Upon the main component's failure, the system instantaneously switches over to the spare server if the switching mechanism is considered fault-free. This is usually called perfect switchover. Manual failover may also be adopted if the requirements are not too strict. It is important to stress that the error detection mechanism may also be implemented directly by servers (without the interface of a manager). In such a case, the heartbeat messages are sent directly from each server to each.

This strategy is named cold-standby. The switching delay is much longer than the one considered in the hot-standby mechanism.

Assume a computational system composed of two servers. One of the servers is operatively active ($S_1$) and the other is standby composed of a host operating system ($OS_1$), a hypervisor ($HV_1$), and two virtual machines ($VM_1$ and $VM_2$), each running applications, respectively. The applications running on $VM_1$ are $A_1$ and $A_2$, whereas the applications running on $VM_2$ are $A_1$, $A_2$, and $A_3$. The second server ($S_2$) is executed in standby mode (which is described by Figure 17.8.a). However, different from the standby server of the hot-standby and cold-standby mechanisms, $S_2$ is not completely ready to process transactions when a failure occurs in the active server ($S_1$), nor is it turned off. The software stack executing on $S_2$ when $S_2$ is in the standby mode is composed of the host operating system ($OS_2$) and the hypervisor ($HV_2$). Assume a failure occurs in the $S_1$ hardware; thus taking the active server to failed. The standby server is not yet ready to process transactions (see Figure 17.7b), but it already has a significant part of the software stack in an operational state, what is required to mount the virtual machines ($VM_1$ and $VM_2$) and to start the respective application on each $VM$. This process is shorter than if $S_2$ started from an off state. After mounting the virtual machines and starting the applications, $S_2$ begins the transactions (see Figure 17.8.c). This mechanism is called warm-standby sparing.

Data errors occur when the data are transferred or stored. Information redundancy is a mechanism that aims at tolerating such errors. Many information redundancy strategies are based on coding. Codes allow data correctness, and even correction [218]. The most common codes used in data storage are parity codes, Hamming codes, checksum, and cyclic codes. Coding is a well-established research area, and many textbooks on this topic are available.
