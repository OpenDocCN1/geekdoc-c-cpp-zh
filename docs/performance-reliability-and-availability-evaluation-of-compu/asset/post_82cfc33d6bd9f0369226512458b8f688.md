# 21.4 IMPERFECT COVERAGE

Coverage factor ($c$) was initially defined as the conditional probability that, given the existence of a failure in the operational system, the system can recover [56]. Since then, many authors have proposed refined notions of this concept. A conceptual strategy divides this into three phases: detection, location, and recovery. Each of these phases is associated with a probability of success. Therefore, the overall coverage probability, $c$, is obtained from the product of the success probabilities of the individuals $c = c_dc_c$. A component or subsystem failure may be covered, so the system continues to operate safely or uncovered which may lead to system failure. Assume the servers depicted in Figure 21.8. These servers are configured in hot-standby redundancy. The primary server processes all workload. If it fails, assuming the switching delay is zero, the standby server promptly takes over (see CTMC shown in Figure 21.11); however, the transaction was being processed is lost. If the primary server fails, the detection mechanism may successfully perceive Performance, Reliability, and Availability Evaluation of Computational Systems the spare server failure (the failure is covered) and start recovering. Nevertheless, the spare server failure may not detected. In such a case, the spare server is hidden (the failure is uncovered) and will only be perceived (1) when the primary server fails, since the spare server will not able to take over processing or (2) by later inspection. In this specific case, the failure is represented by the probability of detecting a failure, $c = c_d$. The CTMC depicted in Figure 21.15 is an availability model of such a system. The CTMC is composed of five states, $\{2, 1, U\}$. State 2 represents the two servers that are available; the primary server is operational and processing the workload, whereas the standby is ready to take over. If the main server fails, the system transitions to state 1 with rate $\lambda$. The standby server fails, may not detected. In such a case, it transitions to 1U (Unsafe) with a rate of $\lambda(1-c)$. However, if the standby server fails, the system transitions from state 2 to state 1 with rate $\lambda$. Therefore, the total rate from state 2 to 1 is $\lambda + \lambda c$. The other server may fail. We are considering the switching delay to zero so that there is no interruption in case of primary server failure. When in unsafe state, 1U, two events are probable: First, the main server may fail, and in a case, the system may perceive the failure in the standby server. The perception is delayed by exponentially distributed average of $1/\beta$. After perceiving the uncovered failure, the system transitions to state 1, and in this state, the standby server may be repaired, which takes the system back to state 0. The CTMC infinitesimal generator is

```
$Q = \begin{pmatrix} -\mu & \mu & 0 \\ \lambda & -\lambda-\mu & \mu \\ 0 & 2c\lambda & -2(1-c)\lambda \\ \beta & 0 & -\beta \end{pmatrix}$
```

Solving $Q=0$, $\sum\pi_i=1$, we obtain $\pi_2, \pi_1, \pi_{IU}$, and $\pi_0$. The steady-availability is calculated by $A = \pi_2 + \pi_1 + \pi_{IU}$. Thus

$A = \frac{\mu(\beta+\lambda)+\mu(\beta+(3-2c)\lambda)}{2\lambda^2(\beta+\lambda)+\mu^2(\beta+(3-2c)\lambda)+2\lambda\mu(\beta-(c-2)\lambda)}$ (21.4.1)

The probability of the system being in the unsafe state, $1U$,

$\pi_{IU} = \frac{2(c-1)\lambda\mu}{\lambda(2(c-2)\lambda\mu+(2c-3)\mu^2)-\beta(2\lambda^2+2\lambda\mu+\mu^2)}$ (21.4.2)
