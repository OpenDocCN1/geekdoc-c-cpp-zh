# 23.6.2 STATISTICAL PROFILING

The classical profiling (also called sampling profiling) does not use hooks to probe events of a program as the deterministic profilers do. Instead, the program under analysis is compiled with the profiling option on, and the executable code is generated with a memory map of variables and labels defined on the program (the top of Figure 23.9). Beside, a profiling module is attached to the program to check the addresses on the stack (the bottom center of Figure 23.9). After compiling the source code (the program under analysis) and generating the executable code with the memory map, the executable may be executed. During the execution, the timer interruption interrupts the process related to the program under analysis periodically to the time-frequency ($f_s$) defined for the interruption. When the executable code's next instruction is interrupted by the timer interruption, the address is stored on the stack (see the top of Figure 23.9) addressed by the stack pointer (SP)), and the time interruption service is executed (see right of Figure 23.9).
