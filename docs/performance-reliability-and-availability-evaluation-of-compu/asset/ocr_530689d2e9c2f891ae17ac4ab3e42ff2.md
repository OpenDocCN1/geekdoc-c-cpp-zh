The adopted modeling process considers first the evaluation of lower-level submodels, and the individual results are adopted to higher-level submodels. Finally, the basic SPN submodels are configured and combined to create the SPN final model. The generic component (Figure 22.1) is adopted to represent components that have no redundancy and be in two states, either functioning or failing. In order to compute availability, mean time to failure (MTTF) and mean time to repair (MTTR) are the parameters needed.

The VM performance represents VM requests on a single physical machine containing failures and repairs on the underlying infrastructure. Whenever a user request is performed, a new VM is started (considering that the infrastructure is operational) and becomes available for some time. This component interacts with three generic components: (i) one representing the occurrence of disasters (DC); (ii) the network infrastructure (NAS_NET); and (iii) the physical machine (OSP).

If the external infrastructure or the VM fails during virtual machine execution, the VM should be migrated to another physical machine. If there is no available physical machine in the system, the task is rejected, and any new request must be performed. Figure 22.42 represents the performance model, which is composed of three parts: (i) VM_PART represents the VM behavior running on a single machine; (ii) DC_PART represents the incoming requests to the data center; and (iii) CL_PART models the requests generation.

A VM should migrate to another data center whenever the current data center is full or the underlying infrastructure has failed. Moreover, the backup server is responsible for transmitting the VM image in case of a disaster or network error. The transmission component represents the data transfer from one data center to another and from backup server to a data center.
