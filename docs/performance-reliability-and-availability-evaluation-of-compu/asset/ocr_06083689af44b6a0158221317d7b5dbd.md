It is worth mentioning that the spare server is functional and that its hardware, operating system, hypervisor, and virtual machines are operating. Therefore, its failures rate is $\lambda_{op}$. In state 1, two events occur. The primary server may be repaired, represented by a transition to 2 with a rate of $\mu$. In such a case, the primary server reclaims the workload processing, and the spare server returns to standby. The other possible event in state 1 is the failure of the only operational server, with a rate of $\lambda_{op}$, in which the system is unavailable. In state 0, both servers are out of order. Only one repair facility is available. Therefore, a priority order should be assigned to which server should be repaired first. In this example, differently from the case shown in the CTMC of Figure 21.20, the spare server is repaired first. This event takes the system back to state 1 with a rate of $\mu$.
