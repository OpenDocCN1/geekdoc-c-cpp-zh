# Sieve

Jim Gilbreath been examining the possibility of writing a small benchmarking program wanting small enough to fit on a code page, and not dependent on specific features like multiplication or hardware division. The algorithm mainly emphasizes search performance and basic logic and branching capabilities. It does not require any advanced language features, such as recursion or collection types. The algorithm's implementation calculates only the odd primes that array of elements 8191 remained less than 16385. The benchmark was first named sieve, and the first results were introduced in the September 1981 issue of BYTE in an article titled "A High-Level Benchmark.”[157]. The paper presented recommendations for implementations in ten languages, using BASIC, C, Pascal, COBOL, and FORTRAN, and some lesser-known examples.

In the 1983 edition of BYTE, Jim Gilbreath and his brother, Gary, wrote the code and removed most of the popular languages, leaving Pascal, C, FORTRAN, COBOL, and added Ada and Modula-2. Newer versions of the benchmark keep on being implemented in new languages [319].

# PassMark

PassMark Software Pty. Ltd. is a company focused on developing benchmarks for the Windows operating system. The first benchmark was delivered in 1998 [471]. Since then, the initial benchmark evolved into a family of benchmark suites. One benchmark suite of this is the PerformanceTest suite. The PerformanceTest conducts 32 standard benchmark tests across five tests and calculates the PassMark rating system. The standard test are composed of CPU suite, Memory suite, 2D suite, 3D suite, and Disk suite.

The CPU consists of mathematical operations, compression, encryption, and physics-related functions. The Memory suite is composed of database operations, uncached memory reading, cached memory reading, memory write latency (the time it takes for a single byte of memory to be transferred to the CPU for processing.), and memory threaded. The memory tested test is nearly identical to the uncached memory reading, but separate threads perform them simultaneously to check how well memory copies with concurrent accesses. The 2D suite contains several tests that exercise the Windows graphics functions, dependent on how fast the video card can carry out 2D graphics operations and the color depth.
