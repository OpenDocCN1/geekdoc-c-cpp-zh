A load balancer (LB) distributes the user requests evenly among the active application servers, avoiding a single VM overloaded while the others are idle.

The disaster recovery cloud system has replicas of the web application and databaseserver that are identical to those running in the primary data center. The storage volumes used by both the primary and secondary database-servers are kept synchronized. Both web and database-servers are active in the disaster recovery cloud but not process any user requests while the primary data center is idle. Nevertheless, the auto-scaling mechanism is not considered for the web-servers in the disaster recovery cloud since only the minimum resources are used for this infrastructure. A disaster monitor located outside both sites is responsible for detecting when the primary data center failed due to a disaster. When a disaster occurs, the disaster monitor notifies the servers hosted in the cloud to assume the virtual IPs to which the load balancer directs the users. Using this mechanism makes the transition from the primary data center to the disaster recovery cloud seamless, avoiding users noticing the change of servers for the application.

The SPN model that represents the disaster recovery solution is composed of SPN models that represent web-servers, database-servers, data center, load balancers, cloud servers, and hot-standby redundancies. Note that the primary infrastructure automatically scales up or down the instances of web-servers according to predefined conditions. This work assumed that the primary infrastructure automatically scales up every time an active component fails and down whenever the number of active components increases. This model uses the auto-scaling mechanism GWEbDown and GWEbUp.

To represent the dependency between VMs and data centers, we include immediate transitions and guard functions for each component representing the virtual machines. As an example, if the data center goes down, the web-servers also become unavailable. Such behavior is modeled by two immediate transitions (TWEbDownDC and TWEbDownHot) and guard functions (GWEbDownDC, GWEbDownHot and GWEbIrep), respectively, the transitions TWEbUpDC and TWEbUpHot, which models the unavailability of the web servers.
