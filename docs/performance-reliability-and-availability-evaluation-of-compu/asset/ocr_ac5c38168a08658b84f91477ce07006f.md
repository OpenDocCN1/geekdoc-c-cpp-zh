# Figure 23.5 A Software-Based Interval Timer.

Overhead - The system under measurement determines how an interval timer should be used to measure the duration of an event. For instance, a portion of code depicted in Program 1 named Piece of code being measured is the event. We can think of this as a method, procedure, block of instructions, or basic block. The current time is captured by reading the software timer through Start_count = read_timer(). Executing this primitive function read_timer() reads the software instant and stores the respective value stored in Start_count. After executing this primitive function, the event of interest (Piece of code being measured) starts its execution. After finishing the execution of the event, the software timer is read again, and its current instant is stored in Stop_count. The elapsed time of such an event (Te) is estimated by subtracting the value in Stop_count. This difference specifies the number of clock cycles elapsed during the execution of the event. Multiplying such difference by the duration of a clock cycle provides an estimation of the event duration. It is worth mentioning that the clock cycle is considered a timing reference of the timer.

In Program 2, we have an example of how to measure the execution of pieces of code (events) in Python programs. In this particular example, the execution times of three functions (three events) (tri, factorial, and matrixops) are measured by applying the time.time() function of Python time library. The functions for recording the time stamp, the difference of time stamps, and the library that supports the time.time() function are written in red code.
