Consider a hash size to 4 bits. Figure 17.11 depicts the data block stored in the data disk and the respective parity block. The parity block is obtained by just performing the exclusive or (XOR) operation of the $i$ bits of respective blocks $A_j=a_j^0a_j^1$, $A_{j+1}=a_{j+1}^0a_{j+1}^1$, and $A_{j+2}=a_{j+2}^0a_{j+2}^2$; that is the parity block $A_p=pb_j^0pb_j^1pb_j^2$ is obtained by computing each of its parity bits using

```
$pb_j^i = a_j^i \oplus a_{j+1}^i \oplus a_{j+2}^i$ (17.1.2)
```

where $j=\{1, 4, 7, 10, \dots\}$ and $i=\{1, 2, 3, 4\}$.

If Disk 0, 1, or 2 breaks, the parity disk (Disk 3) is used to regenerate the missing data. Let us look at how this works. Assume Disk 2 failed, so we have lost all read and access to this data. Nevertheless, the parity disk is used to calculate the missing data. The parity data is calculated by performing the same XOR operation over the remaining data and the parity information on the parity disk, assuming a failure in Disk 2, the words $A_3, A_6, A_9$ are lost. However, the word $A_3$ (see Figure 17.11) can be regenerated by executing

```
$a_3^i=a_3^i \oplus a_6^i \oplus a_9^i, \ i=\{1, 2, 3, 4\}$.
```

thus $A_3=0 \oplus 1 \oplus 1 \oplus 0, 1 \oplus 0 \oplus 0 \oplus 0 \oplus 1=0101$. Therefore, RAID 4 structure allows the storage system to tolerate and recover from one disk failure. Considering the infrastructure shown in Figure 17.10, which is composed of three data disks and one parity disk, as long as three out of four disks are functioning the storage system will properly work. The storage capacity efficiency is specified by

```
$$SCE = \frac{ESC}{TDC}$$
```

where $ESC = (n - 1) \times DC$, and $TDC = n \times DC$. Hence

```
$$SCE = \frac{n-1}{n} \quad (17.1.3)$$
```

For an infrastructure with eight disks, $SCE = 0.875$, which is much better than the storage capacity efficiency of RAID 1.

It is worth mentioning that if two disks are used to implement RAID 4, the structure is equivalent to RAID 1 since the exclusive-or operations would result in parity blocks identical content to the data blocks.

**RAID 5** is similar to RAID 4 that the parity data blocks are striped across all disks, instead of being written on a dedicated disk (see Figure 17.12). In RAID 4, each write operation generates a write operation on the parity disk, leading to bottlenecks. In RAID 5, as the block of parity is distributed across the disks, avoids the single disk bottleneck. In RAID 4, it requires at least three disks. **RAID 6 extends** RAID 5 by adopting two parity blocks and storing them in different disks. There are several possibilities for implementing independent parity checks. One of such approaches is a horizontal-vertical strategy. However, this is only one of many approaches to Level 6. Indeed, any method that independently calculates parity bits is classified as RAID 6. The storage capacity efficiency is specified by

```
$$SCE = \frac{(n-2) \times DC}{n \times DC} = \frac{n-2}{n} \quad (17.1.4)$$
```

where $ESC = (n - 2) \times DC$.

The RAID architectures are best to generate hybrid RAIDs (nested raids). Hybrid RAID combines two or more of the standard RAID levels to improve performance, reliability, or cost. Nested RAIDs are named using numbers that denote the standard RAID levels adopted to implement the hybrid RAID. In the numeric designation, the left numbers denote the lower RAID level, whereas the numbers to the right denote the highest RAID level. The most common nested RAIDs are a combination of two standards; the names are represented by two numbers only, where the first digits denote the lowest RAID level and the second digits the highest RAID level. RAID 10 combines RAID 1 (mirroring) and RAID 0 (striping) in one single system (see Figure 17.13.a). RAID 01 combines (RAID 0) and mirroring (RAID 1) (see Figure 17.13.b). Both require at least four disks. Their storage capacity efficiency is 0.5.

However, for RAID, the fault tolerance is different. Consider, for an instance RAID 10 with four disks. This system is composed of two groups of disks, $G_1$ and $G_2$. $G_1$ is composed of Disk 1 and Disk 2, whereas $G_2$ is composed of Disk 3 and Disk 4. Two blocks of data, $A_1$ and $A_2$, are stored in them. In RAID 10, when writing these blocks of data, first $A_1$ is written in Disk 1; then it is mirrored in Disk 2. After, the other ($A_2$) is written (striping) in Disk 3 and mirrored in Disk 4. $A_1$ is stored in Disk 1 AND Disk 2, and $A_2$ is stored in Disk 3 AND Disk 4. If, for instance, Disk 2 fails, the system suffers a failure in Disk 3 or 4, $A_1$ is in Disk 1. However, if Disk 1 fails, let us assume a RAID 01 system composed of two groups of disks known as $G_1$ and $G_2$. When the data $A_1$ and $A_2$, are stored in this system, we have the following: $A_1$ and $A_2$ are written to Disk 1 AND Disk 2 (striping); respectively; then $A_1$ and $A_2$ are mirrored in Disk 3 AND Disk 4. If Disk 2 fails, the system neither allows a failure in Disk 3 nor 4. Chapter 18 discusses these aspects in detail.

## Redundancy

In mirrored parity RAIDs, every write operation causes input-output (I/O) operation overhead. This overhead is usually called a write penalty. In RAID 1, the write penalty is two because each block is written twice due to the mirror disk. RAID 5 has a significant penalty. For each change to the disk, the RAID controller should read the data (first I/O operation) and the respective parity (second I/O operation), the new parity should be calculated (third I/O operation), and the new parity should also be written (fourth I/O operation) before the operation is complete. RAID 6 works similarly to RAID 5, apart from the fact that the parity reading and writing take two I/O operations, due to the two parity blocks for each stripe. To summarize, the writing penalty is expressed in the number of I/O operations for each write operation. For instance, the number of I/O operations for one write operation in RAID 0 is also one. However, the number of I/O operations for one write operation in RAID 5 is four because four I/O operations are required.
