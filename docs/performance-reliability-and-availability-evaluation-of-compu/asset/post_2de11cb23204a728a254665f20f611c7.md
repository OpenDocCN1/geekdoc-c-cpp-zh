The execution of the command "ss -lf" displays listening sockets. We may collect more scientific statistics, for instance by also specifying -t for TCP, -u for UDP, -d for DCC, and -x for Unix domain sockets. By combining the options, we define a command that collects listening sockets of each type of connection, such as "ss -lt", "ss -lu", "ss -ld", "ss -wd", and "ss -lx". The first command ("ss -lt") may also be specified as "ss -tf" or "ss -l". Likewise, others combinations may be represented using these alternative names. If the options -t, -u, -d, -w, and -x are adopted, the respective commands display established or connected. We also have to collect information of connections that are listening, using the option -a. As example, the execution of "ss -a -f" displays a portion of data similar to the following.

## tcpdump

`tcpdump` is a powerful command-line tool for network traffic monitoring and analysis. The `tcpdump` command is used to create "dumps" or "traces" of network traffic and can also be launched in the background by other tools. Monitoring network traffic through `tcpdump` requires high privileges, so most commands are prefixed with `sudo`. As already mentioned at the beginning of this section, our aim is not to reference tools but rather introduce few examples and point out a specific reference. The `tcpdump` has many options that allow configuring and filtering types of network traffic. This section discusses the basic options that can be used as well as some useful examples of `tcpdump`. Hence let us start the command `tcpdump -D` to find out interfaces are available. As a result, information depicted below shows all the active interfaces:

- ens33 (Up)
- any (Up)
- lo (Up, Loopback)
- bluetooth0 (0)
- nfilter (Linux log)
- nfqueue (Linux queue)
- usb1 (1)
- usb0 (2)

A specific interface can be sniffed using the -i option, followed by the interface name. The command `sudo tcpdump -i ens3` captures all packets in interface ens3 until an interrupt signal is sent and presents the output as the source and destination IP addresses instead of hostnames. It is worth mentioning that -in is a combination of -i and -n. Below, a chunk of data packets is shown as an example.

```
tcpdump: verbose output suppressed, use -v or -vv for full protocol decode listening on ens3, link-type Ethernet, capture size 262144 bytes
```

The command `sudo tcpdump -i any` may be adopted to listen on all interfaces. Now, use one of the lines shown above. For instance, consider the line

```
16:28:07.471548 ubuntu.ntp > a.stl.ntp.br.ntp: NTPv4, client length 48
```

This first field (16:28:07.471548) depicts that the packets were traveling, in this format: hh:mm:ss. The second field shows the source hostname, by the destination hostname, ubuntu.ntp > a.stl.ntp.br.ntp. The third field is Network Time Protocol (NTP4). The fourth field shows whether a host is a client or server. In this case, it is a client (Client), and the last field represents the TCP packet length in Bytes (48).
