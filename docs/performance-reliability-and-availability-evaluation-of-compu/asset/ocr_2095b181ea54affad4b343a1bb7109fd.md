# 24.2.2 SYNTHETIC WORKLOAD GENERATION

One difficulty when using benchmarks for evaluating computer system performance is that benchmark designers envision in advance. Specifically, there is no guarantee that the benchmarks cover in all scenarios the planner may need. Therefore, another approach consists of creating a software (tool) that automatically creates or injects workloads to the system under evaluation or an emulator or simulator.

Indeed, many authors use the terms traffic injector, trace generator, traffic generators, and workload generators indistinguishably. On the other hand, some authors use the term traffic injector for tools that only replay trace (traces) on the computer system. Others adopt the term trace generator for tools that generate synthetic workloads recorded into a trace file. Many users use the terms traffic injector, trace generator, traffic generators, and workload generators indistinguishably. Some authors use traffic injectors for tools that only replay trace (traces) on the computer system. However, some author uses the terms traffic generators or workload generator to refer to software systems that generate synthetic workloads based on traces or a mathematical model to drive a load into a system, benchmark, system-emulator or simulator. Therefore, we will use the term Workload Automation Software (WAS) or Workload Automation Tool (WAT) as a generic term. However, a more specific term may be adopted with specific explanation.

In general terms, implementing a workload automation software requires gathering data from real workloads, generating traces, and analyzing the collected data, generating statistics, creating patterns or models, and storing them for later use or injecting the traffic into the system or its emulator or simulator. Hence, the traffic to be injected or stored may express both the original workload or variants that may express other engaging scenarios.
