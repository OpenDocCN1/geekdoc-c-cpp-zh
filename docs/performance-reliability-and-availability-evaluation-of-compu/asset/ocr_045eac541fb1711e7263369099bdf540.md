As already mentioned, the system's model may be coded as part of FIK or may be a data structure handled by a model's interpreter. In this specific case, the system model is represented by the SPN shown in Figure 26.9 and Table 26.3. Therefore, FIK has an SPN interpreter that evaluates each (faults and repairs) can occur depending on the structural and data dependencies and the stochastic-time structure.

The SUT's initial state depicts two virtual machines and external storage systems as functionally operational. This state is depicted in SPN by the following marking:

$M_0^I = (m_{vm1}, m_{vm1d}, m_{vm2}, m_{vm2d}, m_{osu}, m_{osd}, m_{hwku}, m_{stu}, m_{stdd}).

$M_0^I = (1, 0, 1, 0, 1, 0, 1, 0, 0).

The FI evaluates each can possibly occur at this state. The possible events are F1, F2, OSF, HWF, and STF. None of these transitions are immediate; then the stochastic delay related to each enabled transition is generated. The transition with the smallest delay is chosen to be frozen. Let us assume F2 is the transition with the smallest delay. This transition represents the failure event of the VM2. The FI waits until the delay el. After that, F2 is fired. A firing removes one token from place $VM1U$ and stores one token in place $VM1D$. Besides, F2 firing also calls a function to emulate the virtual machine failure. Here, we denote such a function by $killVM(i)$, which kills the virtual machine process $i$. The marking is

$M_1^I = (1, 0, 0, 1, 1, 0, 1, 0, 0).
