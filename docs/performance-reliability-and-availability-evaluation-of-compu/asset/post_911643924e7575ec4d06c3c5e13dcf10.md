The time measured for carrying out the eighty-one Linpack executions was estimated by subtracting the instant of the last measured (3h 14min 50s) from the time instant when the first detected execution (3h 12min 58s). This measured delay $T = 112s$. This information is obtained from Table 24.9. Therefore, the system throughput$^3$ (see Chapter 8) for this workload

```
$X0 = \frac{C0}{T} = \frac{81 executions}{112s} = 0.7232eps.$
```

Using the demand law (see Section 8.3), we may estimate the time demanded from the processor for one execution of the Linpack benchmark by

```
$D_{CPU} = \frac{U_{CPU}}{X0} = \frac{0.44965}{0.7232eps} = 686.51ms.$
```

It is worth noting that representing the impact of a workload on computer resources, the respective utilization must also be evaluated, adopting a similar approach considered in the study for processor resources. We stress I/O devices such as data storage, memory, and network among critical resources. Characterizing the distribution of workload attribute in isolation may not be enough for efficient and thorough representation of the workload. Therefore, an important aspect that should be looked at is possible between distinct workload attributes and samples. Hence, analyzing the correlation between workload parameters (see Section 4.6) and samples (see Autocorrelation in Section 14.4) are aspects that should not be overlooked.

Example 24.3.2. We executed the stress program with the following options:

```
stress --cpu 1 --hdd 1 --timeout 180s
```
which spawn one threads (worker) spinning (1) and writing one. The stress program was configured to be executed for 180 s. After starting the execution of stress, we executed iostat (see Section 23.7) to monitor the system resources. The stress consists of measures collected every five seconds. Hence, the collecting process was 120s. It is worth mentioning that the execution of iostat finished before the stress process. The command line for executing iostat
```
iostat -t 5 > cpostat.txt
```
