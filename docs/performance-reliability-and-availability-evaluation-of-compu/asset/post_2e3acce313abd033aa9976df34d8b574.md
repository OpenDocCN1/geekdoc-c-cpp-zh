## 21.5 COLD-STANDBY REDUNDANCY

Let us assume the system depicted in Figure 21.20. This system is composed of two routers configured in cold-standby. Router1 ($R_1$) is the primary device, whereas Router2 ($R_2$) is a spare unit. In normal operation, the arrival and departure traffic is routed by $R_1$, and Router$_2$ is offline. If $R_1$ fails, $R_2$ is switched on and assumes the traffic routing. Consider $R_1$ and $R_2$ are devices of the same brand, and assume the particular times for failure to be exponentially distributed with a rate of $\lambda$. The delay required after switching one of the spare device until it gets operational is also assumed to be exponentially distributed with a rate of $\delta$. The second failure is exponentially distributed with a rate of $\mu$. The time to repair the routers is exponentially distributed with a rate of $\mu$. Consider only one repair facility. It is also assumed that the router does not fail when switched off.

![](img/2d1450514bb14a0cdf0eb5048614afab_249_0.png)

**Figure 21.20** Two Routers Configured in Cold-Standby.

The CTMC presented in Figure 21.21 is an availability model of the system shown in Figure 21.21. This model is composed of four states, 2, 1D, 1', and 0. $R_1$ is operational and $R_2$ is turned off. The only event possible is a failure of the router $R_1$. It is worth mentioning that if the switched-off device does not fail. If $R_1$ fails, the system transitions to state 1D with a rate of $\lambda$. In state 1D, the system becomes unavailable unless the spare router, $R_2$, requires time to become operational. Additionally mentioned, this delay is exponentially distributed with a rate of $\delta$. From state 1D, two events are possible: $R_2$ can be switched on, and if it occurs, the system transitions from 1D to 1, which is an operational state, with a rate of $\delta$. The second possible event is the repair of $R_1$. If this happens, the system transitions back to state 2 with a rate of $\mu$. In state 1, $R_1$ may be repaired, and so, doing. It may also fail. When this occurs, the system transitions from state 1 to state 0 with a rate of $\lambda$. In state 0, the system is out of service; that is, both routers are out of order. It should be stressed that only one repair facility is available; hence, a repairing priority should be considered. In this example, $R_1$ is repaired first. When this occurs,

Solving $\Pi \cdot Q = 0$, $\sum_{i} \pi_i = 1$, we obtain $\pi_2, \pi_1, \pi_{1D}, \pi_{1'}$. The steady-state availability is calculated by

$A = \pi_2 + \pi_1 + \pi_{1'} \quad (21.5.1)$

$A = \frac{\mu(\delta + \mu) + \mu^2}{\delta(\lambda^2 + \lambda\mu) + \mu^2} \quad (21.5.2)$

The availability expressed in a number of nines is

$nines = -\log\left( \frac{\mu(\delta + \mu) + \mu^2}{\delta(\lambda^2 + \lambda\mu) + \mu^2} \right) \quad (21.5.3)$

The yearly downtime in hours is

$DT = (\pi_{1D} + \pi_0) \times T \quad (21.5.4)$

where $T = 8760h$. The CMC representing the reliability model is composed of two states. When $R_1$ fails, the system transitions to state 1D with a rate of $\lambda$. In state 1D, the system is unavailable; however, 1D is an absorbing state in the reliability model. Therefore, the system reliability is $R(t) = e^{-\lambda t}$ and $MTTF = 1/\lambda$.

## 21.6 WARM-STANDBY REDUNDANCY

The system in Figure 21.24 is composed of two servers, server 1 ($S_1$) and server 2 ($S_2$), in warm-standby redundancy. This system hosts virtual machines for processing the workload demanded from users on the internet. The primary server, $S_1$, is readily available and provides two virtual machines, $VM_1$ and $VM_2$. server 1 infrastructure is composed of its hardware (HW), the operating system (OS), a hypervisor (HP), the virtual machines. In normal operation, server 2 is in standby mode. It is not off. In standby mode, $S_2$ is turned on, and its operating system and hypervisor are functional. The virtual machines, however, are not deployed. When $S_1$ fails, two virtual machines are mounted in $S_2$, and the workload is assigned to them. Therefore, it is clear that the standby takes a time to start processing (switching time) the workload that was being in $S_1$ is required to Consider that the switching time is exponentially distributed with a rate of $\delta$. Assuming that when processing the workload, $S_2$'s components are equivalent to $S_1$'s components, and both MTTFs are equivalent. However, $S_2$'s MTTF, in standby mode, is higher than when it is operating due to its smaller number of components. It is worth mentioning that $S_2$ in standby mode has no virtual machine deployed.

A server in standby mode may be decomposed into hardware (HW), an operating system (OS), and a hypervisor (HP). A server in operational mode, besides operating system, and hypervisor, has two virtual machines, $VM_1$ and $VM_2$.
