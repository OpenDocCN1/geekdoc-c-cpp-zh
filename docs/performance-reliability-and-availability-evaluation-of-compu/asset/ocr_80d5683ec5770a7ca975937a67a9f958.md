Next is the sequence number of the data contained in the packet. For the first packet captured, this is an absolute number. Subsequent packets use a relative number to make it easier to follow. In this example, the sequence is seq 2921:4381, which means this packet contains 2921 to 4381 of this flow. This is followed by the acknowledge number ack. In this specific case, the packet was received; hence, this flow represents the next expected by date (ack 430). When sending a packet, the ack value is ack 1. The window size (win 62440) specifies the number of bytes available in the receiving buffer by TCP options15. Finally, the packet length is the length (in bytes) of the payload, which is the difference between the last (4381) and first (2921) bytes, which is 4381 - 2921 = 1460.

The tcmpdump allows filtering of the captured packets by a variety of parameters, such as source and destination IP addresses, protocols, ports. Consider, for instance, we want to capture ICMP packets. The command line "tcmpdump -i any icmp > tcmpdump_test" sniffers ICMP packets looking at every interface and writes the traffic headers in the flow tcmpdump_test. A typical chunk of data contained is shown below.

```
18:10:44.754016 IP ubuntu > ec2-54-204-39-132.compute-1.amazonaws.com: ICMP
echo request,
id12648, seq 1, length 64
18:10:44.953102 IP ubuntu > ec2-54-204-39-132.compute-1.amazonaws.com : ubuntu: ICMP
echo reply,
id12648, seq 1, length 64
18:10:45.739922 IP ubuntu > ec2-54-204-39-132.compute-1.amazonaws.com: ICMP

```
