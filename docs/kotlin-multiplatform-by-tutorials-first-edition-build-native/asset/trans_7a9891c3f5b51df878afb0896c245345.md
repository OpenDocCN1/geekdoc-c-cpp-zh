## Kotlin Multiplatform 教程

### 第 2 章：开始入门

### iOS

iOS 使用了多种不同的依赖管理系统。其中较为常见的一种是 CocoaPods。如果你打开 `iOSApp/Podfile` 文件，会发现它其实非常简单：

```
target 'iosApp' do
  use_frameworks!
  platform :ios, '14.1'
  pod 'shared', :path => '..//shared'
end
```

其中最重要的部分是 `pod 'shared', :path => '..//shared'` 这一段。它定义了 KMP 将要创建的共享框架，你可以在 iOS 应用中使用该框架。

### BuildSrc

新版 Gradle 的一个优秀特性是 `buildSrc` 模块的概念。在这个模块中，你可以定义版本变量，也可以定义自己的插件。要创建此模块，首先在项目视图中右键单击根文件夹，然后选择 新建 ▶ 目录。输入 `buildSrc`。由于这将是一个模块，你需要一个构建文件。右键单击 `buildSrc`，选择 新建 ▶ 文件。将文件命名为 `build.gradle.kts`，并向其中添加以下代码：

```
repositories {
  mavenCentral()
}

plugins {
  'kotlin-dsl'
}
```

上述代码包含 Kotlin DSL 插件。现在，通过点击窗口右上角的 Sync Now 来同步 Gradle 文件。然后，右键单击 `buildSrc`，选择 新建 ▶ 目录，并选择 `src/main/kotlin`。右键单击 `kotlin` 目录，选择 新建 ▶ Kotlin 类/文件。将文件命名为 `Dependencies`，并选择 文件。此文件将包含定义所有插件和依赖项所需的全部变量。创建此文件是为了避免在多个不同的文件中维护插件和依赖项的所有版本。在一个地方定义版本，日后修改起来会很容易。

通过将以下代码添加到文件中，来定义所有插件名称：

```kotlin
const val androidPlugin = "android"
const val androidApp = "com.android.application"
const val androidLib = "com.android.library"
const val multiplatform = "multiplatform"
const val composePlugin = "org.jetbrains.compose"
const val cocoapods = "native.cocoapods"
```

上述代码定义了常规的 Kotlin 变量，你可以在整个 Gradle 脚本中使用它们。这些变量并不是必需的，但它们让添加过程更简单。接下来，通过添加以下代码来定义版本号：

```kotlin
object Versions {
    // 1
    const val min_sdk = 24
    const val target_sdk = 31
    const val compile_sdk = 31

    // 2
    // Plugins
    const val kotlin = "1.6.10"
    const val kotlin_gradle_plugin = "1.6.10"
    const val android_gradle_plugin = "7.0.4"
    const val desktop_compose_plugin = "1.0.1"
    const val compose_compiler_version= "1.1.0-rc02"
    const val compose_version= "1.1.0-rc01"
                         // TODO: Add Other versions
}
// TODO: Add Deps
```

- 这些变量定义了 Android 的 SDK 版本。某些库需要最低 SDK 版本为 24。你会注意到这些版本与你之前看到的 **build.gradle.kts** 文件中的版本一致。
- 这些变量定义了插件的版本。

注意其中两个含有 `compose` 字样的插件。你将使用 Jetpack Compose 编写 Android UI，并使用 Desktop Compose 编写桌面应用。现在，为你的库定义版本号。将 `// TODO: Add Other versions` 替换为：

```kotlin
const val coroutines = "1.5.0-native-mt"
const val junit = "4.13.2"
const val material = "1.4.0"
const val kotlinXDateTime = "0.3.1"
const val activity_compose = "1.4.0"
const val napier = "2.1.0"
const val junit5 = "1.5.10"
const val frameworkName = "shared"
```

这将为你将使用的一些库定义版本号。接下来，替换 `// TODO: Add Deps`：

```kotlin
object Deps {
    const val android_gradle_plugin =
    "com.android.tools.build:gradle:${Versions.android_gradle_plugin}"
    const val kotlin_gradle_plugin = "org.jetbrains.kotlin:kotlin-gradle-plugin:${Versions.kotlin_gradle_plugin}"

    const val junit = "junit:junit:${Versions.junit}"
    const val material =
    "com.google.android.material:material:${Versions.material}"
    const val napier = "io.github.aakira:napier:${Versions.napier}"

    // TODO: Add Compose
}
```

这里定义了插件和一些常用库的变量。请注意，你是如何使用替换来插入版本号的。这确保了所有模块引用的依赖项及版本都是一致的。

接下来，添加 Compose 库。这些库用于在 Android 中构建新的 Jetpack Compose UI。将 `// TODO: Add Compose` 替换为：

```kotlin
object Compose {
    const val ui =
    "androidx.compose.ui:ui:${Versions.compose_version}"
    const val uiUtil = "androidx.compose.ui:ui-util:${Versions.compose_version}"
    const val tooling = "androidx.compose.ui:ui-tooling:${Versions.compose_version}"
    const val foundation =
    "androidx.compose.foundation:foundation:${Versions.compose_version}"

    const val material =
    "androidx.compose.material:material:${Versions.compose_version}"
    const val material_icons = "androidx.compose.material:material-icons-extended:${Versions.compose_version}"
    const val runtime =
    "androidx.compose.runtime:runtime:${Versions.compose_version}"
    const val compiler =
    "androidx.compose.compiler:compiler:${Versions.compose_version}"
    const val runtime_livedata = "androidx.compose.runtime:runtime-livedata:${Versions.compose_version}"
    const val foundationLayout =
    "androidx.compose.foundation:foundation-layout:${Versions.compose_version}"
    const val activity =
    "androidx.activity:activity-compose:${Versions.activity_compose}"
}
```

你可能并不需要所有这些库，但它们对其他项目会很有用。你将在后面的章节中学习相当多的库。

接下来，将 `// TODO: Add Coroutines` 替换为：

```kotlin
object Coroutines {
    const val common = "org.jetbrains.kotlinx:kotlinx-coroutines-core:${Versions.coroutines}"
    const val android = "org.jetbrains.kotlinx:kotlinx-coroutines-android:${Versions.coroutines}"
    const val test = "org.jetbrains.kotlinx:kotlinx-coroutines-test:${Versions.coroutines}"
}
// TODO: Add JetBrains
```

这提供了对 Kotlin 协程库的访问——对于异步编程非常有用。

接下来，将 `// TODO: Add JetBrains` 替换为：

```kotlin
object JetBrains {
    const val datetime = "org.jetbrains.kotlinx:kotlinx-datetime:${Versions.kotlinxDateTime}"
    const val uiDesktop = "org.jetbrains.compose.ui:ui-desktop:${Versions.desktop_compose_plugin}"
    const val uitkit = "org.jetbrains.compose.ui:ui-util:${Versions.desktop_compose_plugin}"
}
```

这些是来自 JetBrains（KMP 的开发者）的几个库，用于处理多平台的日期时间，还有稍后将会介绍的 Desktop Compose。

现在你已经定义了所有变量，接下来你将使用这些新变量来整理你的构建文件。

#### 共享构建文件

打开共享的 **build.gradle.kts**，并将 plugins 部分替换为：

```
kotlin(multiplatform)
id(androidLib)
kotlin(cocoapods)
```

注意，你无需包含任何文件就能使用这些变量。这是因为 Gradle 可以自动读取在 **buildSrc** 中定义的常量。

通过将 `android` 部分替换为以下代码来清理它：

```kotlin
android {
    compileSdk = Versions.compile_sdk

    sourceSets["main"].manifest.srcFile("src/androidMain/AndroidManifest.xml")
    defaultConfig {
        minSdk = Versions.min_sdk
        targetSdk = Versions.target_sdk
    }
}
```

上述代码将 SDK 版本替换为在 `buildSrc` 中定义的版本。

接下来，打开根目录的 **build.gradle.kts**，并将 classpath 字符串替换为：

```kotlin
classpath(Deps.android_gradle_plugin)
classpath(Deps.kotlin_gradle_plugin)
```

执行一次 Gradle 同步，以确保它能正常工作。

#### Android 构建文件

打开 **androidApp** 的 **build.gradle.kts**，并将 `plugins` 部分替换为：

```kotlin
plugins {
    id(androidApp)
    kotlin(androidPlugin)
}
```

这仅仅是将字符串替换为变量。将 `dependencies` 部分替换为：

```kotlin
dependencies {
    // 1
    implementation(project(":shared"))
    // 2
    with(Deps) {
        implementation(napier)
        implementation(material)
    }

    // 3
    // Compose
    with(Deps.Compose) {
        implementation(compiler)
        implementation(runtime)
        implementation(runtime_livedata)
        implementation(ui)
        implementation(tooling)
        implementation(foundation)
        implementation(foundationLayout)
        implementation(material)
    }
}
```
