实际上，即便是这样的描述也未能完全覆盖C和Pascal中的所有情况。例如，考虑图7.17中给出的C语言中的struct声明（或Pascal中的record声明）。显然，这段代码中的两个struct声明（图7.17的第1-5行和第7-11行）必须各自包含其内部数据字段的进一步声明，并且只要结构体变量本身（x和y）在作用域内，这些声明就必须可以通过成员选择的“点”表示法访问。这意味着两点：(1) 一个struct声明实际上自身包含一个局部符号表作为属性（其中包含成员声明），并且(2) 这个局部符号表在结构体变量本身从程序的“全局”符号表中删除之前，不能被删除。

(2)      int a;
(3)      char b;
(4)      double c;
(5)  } x = {1, 'a',2.5};

任何在语言中可以直接引用的作用域结构也必须拥有自己的符号表。例如包括Ada中的所有命名作用域；C++中的类、结构体和命名空间；以及Java中的类和包。因此，对于这些语言中的任一程序，其符号表更典型的结构是为每个作用域各建立一个表。在解析源程序的过程中，每当进入一个新的作用域时，就为该作用域创建一个新的符号表，并将其压入符号表栈。在此作用域中声明的名字随后被填入该表。如果此时遇到重复的名字，则说明该名字已在同一作用域内声明过，返回错误。当遇到对某个名字的引用时，从栈顶的表开始搜索。如果在该表中未找到该名字的条目，则继续在其下的下一个表中搜索，依此类推，直到找到条目或到达栈底为止。如果到达栈底，则该名字未声明，返回错误。

关于符号表和作用域的最后一个问题是，在同一作用域内，同一个名字可以在多大程度上复用于不同的函数、变量和其他实体。这种复用称为重载，将在下一节连同相关问题一起讨论。

## 7.4 名称解析与重载

关于声明和编程语言中符号表操作的一个重要问题是：同一个名字在多大程度上可以被用来指代程序中不同的事物。人们起初可能会认为这不应该被允许，因为它可能导致严重的混乱和不可读性。然而，考虑一下，例如，用+号表示的加法运算，它在大多数语言中通常是内置的二元中缀⁹运算符，其结果是两个操作数之和。在几乎所有语言中，这个简单的+号至少指代两种（通常更多）完全不同的运算：整数加法和浮点加法（通常在汇编语言中用两个不同的符号ADDI和ADDF或类似名称表示）。这时，+运算符就被称为重载。显然，这种对同一符号的复用不会引起混淆，因为这些操作紧密相关（甚至在某种数学意义上“相同”）。同样显而易见的是，如果编程语言要求程序员为这些操作使用两个不同的符号（比如用+%表示整数加法，用++#表示浮点加法），那将是极大的麻烦。

翻译器如何消解（区分）“+”符号的这两种用途呢？它通过查看操作数的数据类型来实现。例如，在C中，如果我们写2+3，我们指的是整数加法；如果我们写2.1+3.2，我们指的是浮点加法。当然，2+3.2仍然可能存在歧义，语言的规则必须以某种方式处理这种情况（大多数语言自动将2转换为2.0，但Ada认为这是错误）。

因此，允许基于数据类型以某种方式重载运算符和函数名，是语言的一大优势。C++和Ada允许对函数名和运算符进行广泛的重载。Java也允许重载，但仅限于函数名，不包括运算符。¹⁰ 函数式语言Haskell同样允许对函数和运算符进行重载，甚至允许定义新的运算符（这在C++或Ada中是不允许的）。FORTRAN的多个版本（Fortran90/95及更高版本）也允许有限形式的重载。我们这里使用C++、Ada和Java来讨论重载（它们有相似但不完全相同的机制）。Haskell中的重载已在第3章简要描述。关于Fortran 90/95中重载的内容，参见注释和参考文献。

允许重载函数的基本方法是扩展符号表中查找操作的功能，使其不仅基于函数名进行查找，还基于其参数个数和数据类型进行查找。这种在众多同名函数中选择唯一函数的过程，代表了符号表能力的扩展，称为重载解析。
