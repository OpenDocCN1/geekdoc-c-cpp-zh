

通过引用非局部变量来定义块。它无法直接访问其调用环境中的变量。在示例C代码中，过程B不能直接访问过程A的局部变量x。然而，它可能需要A中x的值来执行其计算。

过程与其调用环境通信的方式是通过参数。参数列表在过程定义时一并声明，如上一节中的max过程：

```
int max (int x, int y){
  return x > y ? x : y;
}
```

这里，x和y是max函数的参数。在max被调用之前，它们不取任何值；当max被调用时，它们被调用环境中的实参替换，如下所示：

```
z = max(a+b,10);
```

在这次调用max中，参数x被实参a+b替换，参数y被实参10替换。为了强调参数在被实参替换之前没有值这一事实，参数有时被称为形式参数（formal parameters），而实参被称为实际参数（actual parameters）。

可以有力地论证，过程应该仅使用参数与程序的其余部分通信——也就是说，过程或函数绝不应使用或更改非局部变量。毕竟，这种使用或更改代表了依赖（在使用的情况下）或副作用（在更改的情况下），这种依赖或副作用从过程规范的阅读中是看不出来的——只能通过检查过程体来确定（过程体可能很长，对于库过程甚至可能缺失）。虽然这条规则对于变量来说通常是好的（例如，如果一个全局变量被更改，它仍应作为参数传入），但对于函数和常量来说，期望这一点就太过分了。一般来说，过程体需要调用程序中的其他过程和库过程，也可能需要使用常量（如PI）。这些都是非局部引用，但我们不会希望用所有这些引用把参数列表弄得杂乱无章（尤其是因为它们本质上都是常量）。因此，非局部使用是不可避免的。

然而，有些过程可能只依赖于参数和固定的语言特性。这些过程被称为封闭形式（closed form），因为它们不包含非局部依赖。一个例子是上面的max函数，它不依赖于非局部定义——它完全依赖于固定的语言特性和其参数。

另一方面，同一个函数在C++中的多态定义（使用模板）：

```
template <typename T>
T max (T x, T y)
{ return x > y ? x : y ; }
```

不是封闭形式，因为“>”运算符可以为非内建类型重载。因此，要以封闭形式编写这个函数，我们必须将“>”操作包含在参数列表中：

```
template <typename T>
T max (T x, T y, bool (*gt)(T,T))
{ return gt(x,y) ? x : y ; }
```

（这些例子已在第8.9节中详细讨论。）

这种按值传递形式通常是函数式语言中唯一的参数传递机制。按值传递也是C++和Pascal中的默认机制，并且基本上是C和Java中唯一的参数传递机制。然而，在这些语言中，对按值传递的解释略有不同：参数被视为过程的局部变量，其初始值由调用中实参的值提供。因此，在C、Java和Pascal中，值参数可以被赋值，就像局部变量一样（但不会在过程外部引起任何更改），而Ada的in参数不能作为赋值语句的目标（参见第10.3.5节关于Ada参数的讨论）。

注意，按值传递并不意味着过程外部不会通过参数发生更改。如果参数具有指针或引用类型，那么该值是一个地址，可用于更改过程外部的内存。例如，下面的C函数肯定改变了参数p所指向的整数的值：

```
void init_p (int* p)
{ *p = 0; }
```

另一方面，直接对p赋值不会更改过程外部的实参：

```
void init_ptr (int* p)
{ p = (int*) malloc(sizeof(int)); /* error - has no effect! */
}
```

此外，在某些语言中，某些值隐式地是指针或引用。例如，在C中，数组隐式地是指针（指向数组的第一个位置）；这意味着数组值参数始终可用于更改存储在数组中的值：

```
void init_p_0 (int p[])
{ p[0] = 0; }
```

同样，在Java中，对象隐式地是指针，因此任何对象参数都可以用来更改其数据：

```
void append_1 (Vector v)
// adds an element to Vector v
{ v.addElement( new Integer(1)); }
```

然而，与C一样，直接赋值给参数也是不行的：

```
void make_new (Vector v)
{ v = new Vector(); /* error - has no effect! */ }
```

### 10.3.2 按引用传递

在按引用传递中，实参必须是某种具有已分配地址的变量。按引用传递不是传递变量的值，而是传递变量的位置，因此参数成为实参的别名，对参数所做的任何更改同样作用于实参。在FORTRAN中，按引用传递是唯一的参数传递机制。在C++和Pascal中，可以通过在C++的数据类型后使用与号（&）、在Pascal的变量名前使用var关键字来指定按引用传递（而不是默认的按值传递）：

```
void inc(int& x) // C++
{ x++ ; }

procedure inc(var x: integer); (* Pascal *)
begin
    x :=  x + 1;
end;
```

在调用inc(a)之后，a的值增加了1，因此发生了副作用。多个别名也是可能的，例如下面的例子：

```
int a;

void yuck (int& x, int& y)
{ x = 2;
    y = 3;
    a = 4;
}

yuck (a, a);
```

在调用之后，过程yuck内部的标识符x、y和a都引用同一个变量，即变量a。

如前所述，C可以通过显式地把引用或位置作为指针传递来实现按引用传递。C使用运算符&表示变量的位置，使用运算符*解引用指针。例如：

```
void inc (int* x) /*C imitation of pass by reference */
{ (*x)++; /* adds 1 to *x */ }

int a;

inc(&a); /* pass the address of a to the inc function */
```

这段代码与前面inc过程的C++或Pascal代码具有相同的效果。当然，这里有一个恼人的必要之处：必须显式地获取变量a的地址，然后在inc过程体中再次显式地解引用它。

在ML中，可以通过使用引用类型模拟按引用传递来达到类似效果。（在ML中，与C一样，只有按值传递可用。）例如：

```
fun inc (x: int ref) = x := !x + 1;
```

在支持按引用传递的语言中，必须解决另一个问题：语言如何响应那些不是变量、因而在运行时环境中没有已知地址的引用实参。例如，给定C++代码

```
void inc(int& x)
{ x++; }
...
inc(2); // ??
```

编译器应如何响应inc(2);这一调用？在FORTRAN中，按引用传递是唯一可用的参数机制，因此这是语法正确的代码。编译器的响应是创建一个临时整数位置，用值2初始化它，然后调用inc函数。这实际上模拟了按值传递，因为对临时位置的更改不会影响程序的其余部分。然而，在C++和Pascal中，这是一个错误。在这些语言中，按引用传递的实参必须是左值——也就是说，它们必须具有已知的地址。

### 10.3.3 按值-结果传递

按值-结果传递实现了与按引用传递类似的结果，只是没有建立真正的别名。相反，在按值-结果传递中，实参的值被复制并在过程内使用，然后在过程退出时将参数的最终值复制回实参的位置。因此，这种方法有时被称为复制入（copy-in）、复制出（copy-out）或复制恢复（copy-restore）。

只有在存在别名的情况下，按值-结果传递才能与按引用传递区分开来。因此，在下面的代码中（为方便起见用C语法编写）：

```
void p(int x, int y)
{ x++;
  y++;
}

main()
{ int a = 1;
  p(a,a);
  ...
}
```

如果使用按引用传递，则在调用p后a的值为3；而如果使用按值-结果传递，则a的值为2。

该机制未作规定、且在不同语言或实现中可能有所不同的问题是：结果复制回实参的顺序，以及实参的位置是仅在过程入口处计算并存储，还是在过程出口处重新计算。

另一种可选方式是，语言也可以提供一种按结果传递（pass by result）机制，其中没有传入值，只有传出值。
