

## 13.7.5 Erlang中的消息传递并行性

Erlang是一种函数式语言，由电信公司爱立信（Ericsson）的乔·阿姆斯特朗（Joe Armstrong）于1986年开发。阿姆斯特朗被指派为电信行业所需的分布式、容错、实时应用开发软件。与Lisp一样，Erlang使用严格求值和动态类型。该语言的语法与Haskell（第3章）相似，具有强大的模式匹配能力。然而，Erlang通过单赋值扩展了这种能力，并区分原子和变量，就像Prolog区分常量项和逻辑变量一样。最后，Erlang支持基于消息传递的并发和并行。无副作用和消息传递的存在在Erlang中结合，产生了一种非常简单的并行编程模型。以下Erlang代码示例改编自Armstrong [2007]，该书对该语言提供了极好的介绍。

```
1> Rectangle = {rectangle, 8, 4}
{rectangle, 8, 4}
2> Circle = {circle, 3.5}
{circle, 3.5}
3> {rectangle, Width, Height} = Rectangle.
{rectangle, 8, 4}
4> Width.
8
5> {circle, Radius} = Circle.
{circle, 3.5}
6> Radius.
3.5
```

在这段代码中，矩形和圆形被表示为包含数值信息和作为类型标签的常量项的元组。使用=运算符进行单赋值，允许变量只绑定一次值，但此后可以多次引用该变量。提示符3和5处的赋值说明了模式匹配。=运算符左侧元组中嵌套的变量与运算符右侧变量所引用的结构中的相应值进行匹配和绑定。

模式匹配和变量绑定也构成了Erlang中函数应用的基础。下一个代码段展示了一个geometry模块，其中包含针对前面描述的矩形和圆形表示的area函数定义。这段代码保存在文件geometry.erl中。

```
-module(geometry).
-export([area/1]).

area({rectangle, Width, Height}) -> Width * Height;
area({circle, Radius}) -> 3.14159 * Radius * Radius.
```

请注意，**area**函数由两个子句组成，一个用于矩形，另一个用于圆形。当程序员将**area**函数应用于某个值时，解释器会将该值与**geometry**模块中定义的**area**函数的相应子句头部进行匹配。请注意，函数参数的形式必须与模块中指定的两个子句之一的头部匹配，否则会引发错误。当参数与函数子句匹配时，该子句头部中的变量会绑定到参数中包含的相应值。然后，在绑定的上下文中执行子句中→符号后的代码。下面是一个编译和测试**geometry**模块的示例会话：

```
1> c(geometry).
{ok, geometry}
2> geometry:area({rectangle, 8, 4}).
32
3> geometry:area({circle, 3.5}).
38.4844775
```

在我们研究Erlang如何与其他代码并行执行这段代码之前，我们需要了解函数如何作为参数传递给其他函数。我们之前在其他函数式语言中见过的映射（Mapping）说明了函数参数的用法。Erlang的标准**lists**模块包含一个map函数，用于将其他函数映射到参数列表上。**lists:map**（或其他任何函数）的函数参数必须是称为fun的特殊类型的Erlang函数。以下会话展示了fun在**lists:map**的三种应用中的用法：

```
1> lists:map(fun(N) -> 2 * N end, [2, 4, 6]).
[4, 8, 12]
2> Double = fun(N) -> 2 * N end.
#Fun<erl_eval.6.57006448>
3> lists:map(Double, [2, 4, 6]).
[4, 8, 12]
4> lists:map(fun math:sqrt/0, [4, 9, 16]).
[2, 3, 4]
```

在提示符1处，fun被用于构造一个匿名函数，类似于Lisp中的lambda，以作为参数传递给**lists:map**。在提示符2处，变量Double绑定到一个fun。然后该变量在提示符3处作为参数传递给**lists:map**。在提示符4处，标准数学函数sqrt被包装在fun中，然后在提示符4处作为参数传递给**lists:map**。

有了这些基本概念，我们就可以了解Erlang如何支持并行编程了。Erlang进程是一种非常轻量级的软件对象，它独立于任何其他进程运行，并通过发送和接收消息与其他进程通信。进程的基本操作包括**spawn**（创建新进程）、**send**（向其他进程发送消息）和**receive**（接收消息）。表13.1描述了这些操作在Erlang中的语法和语义。

| 操作 | 作用 |
|---|---|
| Pid = spawn(Fun) | 创建一个新进程，与调用者并行执行函数Fun，并返回该进程的进程标识符。然后可以使用Pid向新进程发送消息。 |
| Pid ! message | 将消息（一个模式）发送给由Pid标识的进程。发送者不等待，而是继续执行。 |
| receive<br>  Pattern1 [ when Guard1 ] -><br>    Expressions1<br>  Pattern2 [ when Guard2 ] -><br>    Expressions2<br>  - - -<br>end | 接收消息（一个模式）。如果消息与给定模式之一匹配，则执行相应的代码。否则，保存该消息以供后续处理。 |

让我们回到之前在geometry模块中定义的area函数示例。在并行计算的上下文中，我们可以将此函数视为在其自己的进程中执行的服务器。另一个称为客户端的进程向该服务器请求给定几何形状的面积。服务器通过计算面积并将其返回给客户端来处理此请求。

在我们的新示例中，客户端进程就是交互式解释器的进程，它首先派生一个服务器进程。当服务器进程被派生时，它运行一个执行无限循环的函数。此循环接收来自客户端的消息，计算面积，并将结果发送回该客户端。在新的实现中，area函数被更新以处理客户端和服务器之间的事务。此函数现在期望服务器进程标识符和形状模式作为参数。下一个会话演示了用户/客户端与面积服务器之间的交互。

```
1> c(area_server).
{ok, area_server}
2> Pid = spawn(fun area_server:loop/0).
<0.35.0>
3> area_server:area(Pid, {rectangle, 8, 4}).
32
4> area_server:area(Pid, {circle, 3.5}).
38.4844775
```

在提示符1处，函数定义模块area_server被编译。在提示符2处，派生了一个服务器进程。它被传递area_server模块的loop函数，并适当包装在fun中。loop函数已准备好接收和处理消息，并立即在新进程中开始并发执行，变量Pid被绑定到服务器的进程标识符。在提示符3和4处，调用新的area函数，以服务器进程标识符和某些形状模式作为参数。在幕后，服务器进程接收来自此函数的消息，该函数返回服务器计算的结果。

下面是服务器函数模块的代码，随后进行解释。

```erlang
-module(area_server).
-export([area/2, loop/0]).

area(Pid, Shape) ->
    Pid ! {self(), Shape},
    receive
        {Pid, Result} ->
            Result
    end.

loop() ->
    receive
        {From, {rectangle, Width, Height}} ->
            From ! {self(), Width * Height},
            loop();
        {From, {circle, Radius}} ->
            From ! {self(), 3.14159 * Radius * Radius},
            loop();
        {From, Other} ->
            From ! {self(), {error, Other}},
            loop()
    end.
```

如前所述，area函数现在期望服务器进程标识符和形状模式作为参数。此函数创建一个包含形状和客户端自身进程标识符（通过调用self()获得）的新模式。服务器将使用客户端进程标识符将其结果发送回客户端。然后将此模式作为消息发送到服务器（Pid）。然后area函数接收服务器的结果。注意，此结果从模式{Pid, Result}中提取。这种表示法保证了客户端通过成功匹配，只收到这个特定服务器发送的消息，而不是此时可能由其他进程发送的其他消息。

loop函数处理来自客户端的请求。此函数作为参数传递给spawn函数以启动服务器进程（本质上告诉进程执行此函数）。注意，loop函数包含一个receive表单，该表单又包含三个守卫，用于匹配从客户端作为消息发送的模式。每个模式中的变量From被绑定到客户端的进程标识符，并用于将结果发送回该客户端。第一个守卫处理矩形的情况，第二个守卫处理圆形的情况，最后一个守卫从不被识别的形状模式中恢复。在每种情况下，发送回客户端（From）的消息都包含服务器的进程标识符（self()），以便客户端只收到由此服务器发送的消息。最后，请注意，在每种情况下，在结果发送回客户端之后，loop函数作为其最后一个逻辑步骤执行递归调用。这样做的效果是继续无限循环，同时释放服务器以接收其他消息。由于尾递归的loop函数编译成真正的循环，它可以永远运行而不会出现栈溢出。

进程之间的交互通常不像面积服务器示例中那样紧密耦合。一方面，进程可能将工作移交给其他进程，然后继续愉快地执行，而不等待响应。另一方面，进程等待接收消息的时间可能超过预期，因为
