If you want to delete a record from the Faculty table, you must first delete the related records from the Login, Course, StudentCourse and Student tables, and then you can delete the desired record from the Faculty table. The reason for that is because some definite relationships exist among five tables.

For example, if one wants to delete a record from the Faculty table, one must perform the following deletions:

- The Faculty_id is a primary key in the Faculty table, a foreign key in the Login and the Course table. Therefore, the Faculty table is a parent table and the Login and Course are children. Before one can delete a record from the Faculty table, one must first delete records that have the faculty_id as the foreign key from the child tables. In other words, one must first delete those records that use the faculty_id as a foreign key from the Login and Course tables.
- When deleting records that use the faculty_id as a foreign key from the Course table, the related course_id, which is a primary key in the Course table, will also be deleted. Course right is now a parent table since the course_id is a primary key for that table. As mentioned, however, to delete any record from a parent table, one must first delete the related records from the child tables. Now the StudentCourse table is a child table for the Course table; the records that use the course_id as a foreign key in the StudentCourse table should be deleted first.
- After those related records in the child tables are deleted, finally the faculty member may be deleted from the parent table, Faculty table.

## 8.6.2.2 Data Deleting Order Sequence

In summary, to delete a record from the Faculty table, one needs to perform the following deletions jobs in the order shown below:

1) Delete all records that use the course_id as the foreign key from the StudentCourse table.
2) Delete all records that use the faculty_id as the foreign key from the Login table.
3) Delete all records that use the faculty_id as the foreign key from the Course table.
4) Delete the desired faculty member from the Faculty table.

You can see how complicated it is in the operational process to delete one record from relational database based on this example.

## 8.6.2.3 Use the Cascade Deleting Option to Simplify the Data Deleting Actions

To simplify the data operations, we can use the Cascade Deleting option provided by the Microsoft SQL Server Management Studio 18.

Recall that we created and built the relationship among our five tables, the five relationships are built among those tables:

1) A relationship between the Login and the Faculty table is setup using the faculty_id as a foreign key FK_Login_Faculty in the Login table.
2) A relationship between the Login and the Student tables is setup using the student_id as a foreign key FK_Student_Login in the Login table.
3) A relationship between the Course and the Faculty table is setup using the faculty_id as a foreign key FK_Course_Faculty in the Course table.
4) A relationship between the StudentCourse and the Course table is setup using the course_id as a foreign key FK_StudentCourse_Course in the Course table.
5) A relationship between the StudentCourse and the Student table is setup using the student_id as a foreign key FK_StudentCourse_Student in the StudentCourse table.

Based on the data deleting sequence (1–4) listed in the last section, in order to delete a record from the Faculty table, one needs to perform four deleting operations in that sequence. Compared with those four deleting operations, the first one is the most difficult and for the reason for that:

To perform the first deleting operation, one must first find course_id that use the faculty_id as the foreign key from the Course table, and based on those course_id, one needs to delete all records that use those course_ids as the foreign keys of the StudentCourse table. To delete operations in sequences 3 and 4, they are very easy and each deleting operation needs only one querying. The conclusion for this discussion is: how can we find an easy way to complete the operation in sequence?

A odd solution to this is to use the Cascade option, as we did in Chapter 2, to perform the data deleting in a cascaded mode. This Cascade option allows the SQL Server database to perform deleting in sequence 1 as a Cascade is selected for relationships 4 and 5 listed above.

Now let's use a real example to illustrate how to use this Cascade option to simplify the data deleting operations, especially for the first deleting in sequence.

1) Go to Start | All Programs | Microsoft SQL Server Tools 18 | SQL Server Management Studio 18.
