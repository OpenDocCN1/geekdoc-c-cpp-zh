Let's have a closer look at this piece of codes to see how it works.

+   A. The namespace **System.Linq** is automatically added into this code section and we need to use all data related to LINQ to SQL and this namespaces all of them.
B. A new instance of our derived class **CSE_DEPTDataContext** is created with the first constructor. This entity class is generated under our current project, this namespace **WebLINQSQL_Project** must be prefixed for that class. Otherwise a compiling error would be encountered.

A trick here is that no connection string is included in this connection object. Yes, where is the connection string? How can we connect to our database without connection string? While, the connection string is in there. Where? Ok, let's have a closer look at it this issue now.

Open our web configuration **Web.config** which is located at the Solution Explorer by double-clicking on it. A sample file is shown in Figure 8.57.

It can be found from this XML file that our connection string is in there under the `<ConnectionString>` tag, which includes the Data Source and the database Provider. In this application, it is a full name for our Data Source, including the database server, database name and authentication mode. Here a **Windows Authentication Mode** is used.

When you create new instance of our derived **DataContext** class to connect to our database, the system can automatically load this connection string from this configuration file and it to connect even when we did not clearly indicate this string. The instance **cse_dept** has finished the database connection when we created it and this has been saved during the creation process. Now we can use this connection object to perform our data actions against our sample database.
