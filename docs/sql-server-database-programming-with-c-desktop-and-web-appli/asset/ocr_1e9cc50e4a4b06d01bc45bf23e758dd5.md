# Introduction to Language Integrated Query (LINQ)

DataContext is a class used to establish a connection between your project and your database. In addition to this connection role, the DataContext also provides the connection function to convert or interpret operations of the Standard Query Operators for SQL statements that can run in relational databases.

Two tools provided by LINQ to SQL are SQL and the Object Relational Designer (O/R Designer). With the help of these tools, users can easily build all entity classes, set the mapping between the relational database and the objects model used in LINQ to SQL and create a DataContext.

The difference between the SQLModel and the Object Relational Designer is that the former is a console-based application, but the latter is a window-based application. This means the SQLModel provides a DOS-like template and the operations are performed by entering single command into a black-and-white window. The Object Relational Designer provides a graphic interface (GUI) and allows users to drag-drop tables represented by graphical icons into the GUI. Obviously, the second method, or tool, is more convenient and easier with the first one.

Due to the discontinuing in support for SQLModel in Visual Studio 2022, we only concentrate on how to use the Object Relational Designer to build LINQ to SQL queries in Chapter 5.

# 4.7 LINQ TO ENTITIES

As mentioned in the Introduction to LINQ section, LINQ to Entities belongs to LINQ to ADO.NET and is a sub-component of ADO.NET 3.5 Entity Framework.

LINQ to Entities queries are performed under the control of the ADO.NET 3.5 Entity Framework (ADO.NET 3.5 EF) and ADO.NET 3.5 Entity Framework Tools (ADO.NET 3.5 EF). ADO.NET 3.5 EF enables developers to work with data in the form of domain-specific objects and properties, such as customers and customer addresses, without thinking about the underlying database tables and columns where this data is stored.

To access and implement ADO.NET 3.5 EF, developers need to understand the Entity Data Model, which is a core of ADO.NET 3.5 EF. LINQ allows developers to develop-set-based queries in their application code, without having to use a separate query language. Through the Object Services infrastructure of the Entity Framework, ADO.NET exposes a common conceptual view of data, including relational data, as objects in the .NET environment. This makes the object layer ideal target for LINQ support.

This LINQ technology, LINQ to Entities, allows developers to create flexible, typed queries against the Entity Framework object context using LINQ expressions and the LINQ standard query operators directly from the development environment. The queries are expressed in the programming language itself and not as literals embedded in the application code, as is the case in applications written on the Microsoft .NET Framework 2.0.
