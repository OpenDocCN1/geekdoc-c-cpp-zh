## 4.8.1 LINQ to XML Class HIERARCHY

First let's have a global picture about the LINQ to XML Class Hierarchy that is shown in Figure 4.45. The following important points should be noticed when watching this class hierarchy:

- 1. XElement is low in the class hierarchy, it is the fundamental class in LINQ to XML. XML trees are generally made up of a tree of XElements. XAttributes are name/value pairs associated with an XElement. XDocuments are created only if necessary, such to hold a DFT or top-level XML processing instruction (ProcessingInstruction). All other XNodes can be leaf nodes under an XElement, or possibly an XDocument (if they exist at the root).
- 2. XAttribute and XNode are derived from a common base class XObject. XAttributes are not XNodes because XML attributes are really name value pairs associated with an XML element not nodes in the XML tree. This contrast with W3C DOM.
- 3. Text and XData are exposed in this version of LINQ to XML, but as discussed above, it is best to think of them as a semi-hidden implementation except when exposing text is necessary. As a user, you can get back the value of the text within an element or attribute as a string or other simple value.
- 4. The only Node that can have children is XContainer, meaning either an XDocument or XElement. An XDocument can contain an XElement (the root element), an XDeclaration, or a ProcessingInstruction. An XElement can contain another XElement, an Attribute, and text (which can be passed in a variety of formats, but will be represented in the XML tree as text)

In addition to this class hierarchy, other important components aligned in XML also play key roles in LINQ to XML. One of them is the XML names.

XML names, often a complex subject in XML programming APIs, are represented simply in LINQ to XML. An XML name is represented by an XNamespace object (which encapsulates the XML namespace URI) and a local name. An XML namespace serves the same purpose that a namespace does in your .NET Framework-based programs, allowing you to uniquely qualify the names of your classes. This ensures that you don't run into a name conflict with other users or built-in names. When you have identified an XML namespace, you can choose a local name that needs to be unique only within your identified namespace.

## 4.8.2 MANIPULATE XML ELEMENTS

LINQ to XML provides a set of methods for manipulating XML. You can insert, delete, copy, and update XML. Before we can continue to discuss these actions, first we need to show you how to create a sample XElement file using LINQ to XML.

### 4.8.2.1 Creating XElement from Scratch

LINQ to XML provides a powerful approach to creating XML elements. This is referred to as functional construction. Functional construction lets you create all or part of your XML tree in a single statement. For example, to create a facultiesElement, you could use the following code that is shown in Figure 4.46.

By indenting, the XElement constructor represents the structure of the underlying XML. Functional construction is enabled by a XElement constructor that takes a params object. An example of the Functional construction is shown below.

```csharp
public XElement(XName faculty_name, params object[] contents)
```

The contents are extremely flexible, supporting any type of object that is a legitimate child of an XElement. Parameters can be any of the following:

- A string, which is added as text. This is the recommended way to add a string as the value of an element; the LINQ to XML implementation will create the internal XText node.
- An XText, which can have either a string or CData value, added as child content. This is mainly useful for CData values; which is simpler for ordinary values.
- An XElement, which is added as a child element.
- An XAttribute, which is added as an attribute.
- An XProcessingInstruction which is added as child content.
- An Enumerable, which is enumerated, and these values are applied recursively.
- Anything else, ToString() is called and the result is added as text content.

The term CDATA, meaning character data, is used for distinct, but related purposes in the markup languages SGML and XML. The term indicates that a certain portion of the document is character data, rather than non-character data or character data with a specific, limited structure.

In the above example showing functional construction, a string ("Patrick Tones") is passed into the faculty_name XElement constructor. This could have been a variable (for example, newElement("faculty_name", facultyName)), it could have been a different type besides string (for example, newElement("quantity", 55)), and it could have been the result of a function call like the one in Figure 4.47.

```csharp
class Person
{
  public string faculty_name;
  public string[] PhoneNumbers;
}

var persons = new[] {
  new Person { faculty_name = "Patrick Tones", PhoneNumbers = new[] { "750-378-0144", "750-055-0145" },
  new Person { faculty_name = "Gretchen Rivas", PhoneNumbers = new[] { "755-055-0163" }
};

XElement faculties = new XElement("faculties",
    from f in persons
    select XElement("faculty", f.faculty,
        from p in f.PhoneNumbers
        select XElement("phone", p)));
Console.WriteLine(faculties);
```
