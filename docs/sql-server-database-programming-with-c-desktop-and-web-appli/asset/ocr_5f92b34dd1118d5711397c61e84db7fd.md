C. Then the SqlCommand object is initialized with a group of related properties. Point one to be noted is the Connection property, which should be assigned as a connection object that is initialized in the Login form. The dynamic parameter, @name, should be SqlDbType.Char since this type is equivalent to a string in C#.

D. The data type of SqlDbType.Char ...

E. If the DataAdapter Method is selected by the users, the SelectCommand property of a DataAdapter is initialized by the above step C, and the Fill() method is called to fill a DataTable, sqlDataTable, to perform a query to the Faculty table and find a match recorded into that DataTable.

F. By checking the Count property of the rows in the filled DataTable, we can confirm whether or not this operation is successful. When Count is greater than 0, which means that at least one data row has been matched and filled, and that query is successful, a user-defined method FillDataTable() is called with the filled DataTable as the argument to display all queried columns in the seen TextBoxes and a faculty in the Faculty form.

G. Otherwise, if the Count property is less than or equal to 0, which means that no row has been matched and retrieved, a warning message is displayed to indicate this case.

H. Some jobs are performed to close some Used DataTable and the DataAdapter to keep our project neat.
