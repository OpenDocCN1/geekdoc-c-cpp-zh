# 4.8.2.1 Creating XElement from Scratch

LINQ to XML provides a powerful approach to creating XML elements. This is referred to as functional construction. Functional construction lets you create all or part of your XML tree in a single statement. For example, to create a facultiesElement, you could use the following code that is shown in Figure 4.46.

By indenting, the XElement constructor represents the structure of the underlying XML. Functional construction is enabled by a XElement constructor that takes a params object. An example of the Functional construction is shown below.

```
public XElement(XName faculty_name, params object[] contents)
```

The contents are extremely flexible, supporting any type of object that is a legitimate child of an XElement. Parameters can be any of the following:

+   * A string, which is added as text. This is the recommended way to add a string as the value of an element; the LINQ to XML implementation will create the internal XText node.
* An XText, which can have either a string or CData value, added as child content. This is mainly useful for CData values; which is simpler for ordinary values.
* An XElement, which is added as a child element.
* An XAttribute, which is added as an attribute.
* An XProcessingInstruction which is added as child content.
* An Enumerable, which is enumerated, and these values are applied recursively.
* Anything else, ToString() is called and the result is added as text content.

The term CDATA, meaning character data, is used for distinct, but related purposes in the markup languages SGML and XML. The term indicates that a certain portion of the document is character data, rather than non-character data or character data with a specific, limited structure.
