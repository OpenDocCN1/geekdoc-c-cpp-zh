The ADO.NET providers for OLE DB, ODBC, SQL Server and Oracle are extended by a suffix .NET, such as OLE DB.NET, ODBC.NET, SQL Server and Oracle.NET. Since most Data Providers used in this book belong to ADO.NET, generally do not need to add that .NET suffix but we will add this if the old Data Providers are used.

The data providers are located at different namespaces and these namespaces hold the various classes you must import into your code in order to use those classes in your project.

Figure 3.3 lists the most popular namespaces used by the different data providers and used by the DataSet and DataTable. Since the Data Provider is located at the different namespace as shown in Figure 3.3, you must first add the appropriate namespace into your C#.NET 2008 project, exactly into the form's code window, whenever you want to use Data Provider. All classes provided by Data Provider must be prefixed by the associated keyword. For example, you may use 'using System.Data.OleDb' to add the name of the OLEDB Data Provider if you want to use this Data in your project, and also all classes belonging to Data Provider must be prefixed by the associated keyword OleDb, such as OleDbConnection, OleDbCommand, OleDbDataAdapter and OleDbDataReader. The same holds true for all other Data Providers.

Although different Data Providers are located at different namespaces and have different prefixes, the classes of these Data Providers have the similar methods or properties with the same name. For example, no what kind of Data Provider you are using such as OleDb, an SQL or an Oracle, they have the methods or properties with the same name, as Connection String property, Open() and Close() method as well as the ExecuteReader() method. This provides flexibility for the programmers and allows them to use different Data Providers access by only modifying the prefix applied before each class.

The following sections provide a more detailed discussion for each specific Data Provider. These discussions will give you a direction or guide to help you select the appropriate Data Provider when you want to them develop the data-driven applications.

# 3.4.1.1 The ODBC Data Provider

The .NET Data Provider for ODBC uses ODBC Driver Manager (DM) through COM interop. The ODBC data provider supports both local and distributed transactions. For distributed transactions, the ODBC data provider, by default, automatically enlist in a transaction and obtains transaction details from Windows 2000 Components Services.

The ODBC .NET data provider provides access to ODBC sources with the help of native OleDb.NET data provider accesses native OLEDB providers. The ODBC.NET supports the following Data Providers:

+   - SQL Server
- Microsoft ODBC for Oracle
- Microsoft Access Driver (*.mdb)
