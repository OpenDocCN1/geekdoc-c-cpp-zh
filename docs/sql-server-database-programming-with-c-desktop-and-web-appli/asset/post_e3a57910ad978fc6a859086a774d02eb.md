# 7.1.1 UPDATING AND DELETING DATA AGAINST RELATED TABLES IN A DataSet

When updating or deleting data against related tables in a DataSet, it is important to update or delete data in the proper sequence in order to reduce the chance of violating referential integrity constraints. The order of command execution will also follow the indices of the DataRowCollection in the DataSet. To prevent data integrity errors from being raised, the best practice is to update or delete data against the database in the following sequence:

- 1) Child table: delete records.
- 2) Parent table: insert, update, and delete records.
- 3) Child table: insert and update records.

For our sample database CSE_DEPT, all five tables are related with different primary keys and foreign keys. For example, among the Login, Faculty and Course tables, the faculty_id acts as a relate these three tables together. The faculty id is a primary key in the Faculty table, a foreign key in both Login and the Course tables. In order to update or delete data from any of those tables, one needs to follow the sequence above. As a case of updating or deleting a record against the database, the following data operation sequence must be performed:

- 1) First, remove or delete record from the child tables, Login and Course tables, respectively.
- 2) Update or delete record in the parent table, Faculty table.
- 3) Finally, updated record can be inserted into the child tables as Login and Course tables for the data updating operation. There is no any data action for the data deleting operations for the child tables.

It would be complicated if we update a full record (including the primary key) for any existing record in our sample database. In practice, it is unnecessary to update a primary key for any record since the primary key has the same lifetime as a database. A better popular way to do this updating is to remove undesired records and insert new records with primary keys. Therefore, in this chapter, we will concentrate on updating existing data in our sample database without touching the primary key. For data deleting, we can delete a full record with the primary key and all related records in the child tables will also be deleted since all tables have set in a Cascade Delete mode when we built these tables for our sample database CSE_DEPT in Section 2.9.4 in Chapter 2.

You can use the TableAdapter.Update() method to update or edit records in a database. The Table TableAdapter.Update() provides several operations that perform depending the parameters passed in.

| TableAdapter DBDIRECT Method | Description |
|---|---|

It is important to understand the results of all these different method signatures. To use this method to update or delete data against the database, one needs to perform the following two steps:

- 1) Change or delete records from the desired DataTable based on the selected data rows from the table in the DataSet.
- 2) After the rows have been modified or deleted from the DataTable, call the TableAdapter.Update to reflect those modifications to the database. You can control the amount of data by passing an entire DataSet, an array of DataRows, or a single DataRow.

Figure 7.2 describes the behavior of the various TableAdapter.Update() methods. parameters or arguments can be passed into these five variations of this method. The parameter DataTable, which is located in a DataSet, is a data mapping to a real table in the database. When a DataTable is passed, any modification to that table will be updated and reflected in the associated table in the database. Similarly, if a DataSet is passed, all DataTables in that DataSet will be updated and reflected to those tables in the database.
The last variation of this method is to preserve the original columns and the new columns of a data table to perform this updating. In fact, this method can be used as a DBDirect method to access the database to manipulate data.
