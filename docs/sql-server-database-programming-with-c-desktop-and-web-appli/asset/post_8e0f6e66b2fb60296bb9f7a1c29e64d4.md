## 2.9.4.1 Create Relationship between the Login and the Faculty Tables

The relationship between the Faculty and the Login table is one-to-many, which means that the faculty_id is a primary key in the Faculty table, and it can be mapped to faculty_id that are foreign keys in the Login table.

To setup this relationship, expand the Login table and the Keys folder that is under the Login table in open Microsoft SQL Server Management Studio 18. Currently, only one primary key, PK_Login, exists under the Keys.

To add a new foreign key, click on the Keys folder and select New Foreign Key item from the popup menu to open the Relationship dialog, which is shown in Figure 2.38.

The default relationship is FK_Login_Login, which is displayed in the Selected Relationship box. Now we want to create the foreign relationship between the Login and the Faculty tables, change the name of this foreign relationship to FK_Login_Faculty by modifying its name in the (Name) box that is under the Identify pane.

Then select two tables by expanding the Tables and Columns Specification item that is under the General pane. Click the expansion button that is located on the right of the Tables and Columns Specification item which is shown in Figure 2.39.

Click the drop-down arrow from the Primary key table combobox and select the Faculty table from this, then click on the row that is just the Primary key table combobox and select the faculty_id column. You can see that the Login table has been automatically selected and displayed in the Foreign key table combobox. Before we close this dialog, we need to do one more thing, which is to setup a cascaded relationship between the Primary key (faculty_id) in the parent table Faculty and the Foreign keys (faculty_id) in the child table Login. The reason we need to do this is because want to simplify the data updating and deleting operations between these tables in a relational database such as CSE DEPT. To do this cascading, scroll down along this Foreign Key Relationships dialog and expand the item **Table Designer**, when you can find the **INSERT And UPDATE Specifications** item. Expand this item and two sub items are displayed, which are:

- **Delete Rule**
- **Update Rule**

The default value for both items is **No Action**. Click on the **No Action** box for the **Delete Rule** item and click on the drop-arrow, and select the **Cascade** item from the list. Perform the same operation for the **Update Rule** item. Your finished Foreign Key Relationships dialog should match one that is shown in Figure 2.41.

In this way, we established the cascaded relationship between the Primary key in the parent table and the Foreign keys in the child table. Later on when you update or delete any Primary key from a parent table, the related foreign keys in the child tables will also be updated or deleted without any additional operations. It is convenient!

Click the **Close** button to close this dialog.

Go to the **File | Save** menu to open the **Save** dialog and click the **Yes** button to save this relationship. When you can select **Yes** or **No** to the **Save Change Script** dialog if it appears.

Now right-click on the **Keys** folder under the **Login** table from the Object Explorer window, and we select the **Refresh** item from the popup menu to refresh this **Keys** folder. Immediately you can find a new foreign key **FK_Login_Faculty** appears under this **Keys**. This is our new created foreign key that sets the relationship between **Login** and **Faculty** tables. You can also confirm and find this new created foreign key by right clicking on the **Keys** folder that is under the **Faculty** table.
