In order to recover deleted faculty, the following points must be kept in mind and the following procedures must be followed:

+   1) Recall that we build our database CSE_DEPT, exactly when we set up the relationships among tables, with the Cascade mode for both Update and Delete Rules for INSERT and UPDATE Specification field between the Faculty and Login, Faculty and Course, and Course and Student tables. This means that for deleted, the Faculty is a parent table for the Login and the Course are child tables to Faculty. Similarly, the Course is a parent table for the StudentCourse table and the StudentCourse is a child table to the Course table. The cascading updating and deleting means when a record in the parent table is updated or deleted, all records in the child tables are also updated or deleted. An example of cascading updating and deleting is shown in Figure 7.20. The faculty member Ying Bai with a faculty_id=B78880 is selected for this updating and deleting example.

+   2) As shown in Figure 7.20, the faculty member with a faculty_id=B78880, which is a primary key in the Faculty table, a foreign key in the Login and the Course tables, are updated or deleted from the Faculty table, the related records in the child tables, Login and Course, with the same faculty_id will also be updated or deleted with the associated columns. Two columns, user_name and pass_word, located in the Login table and four associated columns, course_id, located in the Course table will also be updated or deleted.

+   3) An import issue is to recover these deleted records. You have to recover the records in the parent table (Faculty and Course tables), and then recover the records in the child tables. Following the table order in Figure 7.20 and refer to Sections 2.9.4.1-2.9.4.5 in Chapter 2, as well as Figures 7.21-7.24 to recover these records.
