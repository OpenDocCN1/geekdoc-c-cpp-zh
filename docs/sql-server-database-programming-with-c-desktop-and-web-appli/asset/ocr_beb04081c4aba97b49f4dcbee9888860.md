# PART II QUERY WITH RUNTIME OBJECTS

In contrast to the data-driven application, SelectWizard Project, we developed in Part I, in which a number of the tools and wizards were provided by Visual Studio, such as the DataSet, BindingSource, BindingNavigator and TableAdapter, are utilized to help readers develop professional data-driven applications easily and conveniently, the sample projects developed in this part have nothing to do with those tools and wizards. This means we created ADO.NET objects by directly writing C# codes without the aid of Visual Studio design-time tools and wizards as well as the auto-generated codes. All data-driven objects are created and implemented during the period of runtime. In other words, all objects are created dynamically.

The shortcoming of using Visual Studio tools and wizards to create connections is that the auto-generated connection could are linked to wizards and are embedded into the programs, and those connections are code-dependent. Once connection information in the programs is compiled, it cannot be modified. In other words, your programs cannot be distributed and run in other platforms.

Compared with design tools and wizards, the advantages of using the runtime objects to make the data operations easier: 1) it provides programmers with more flexibility in creating and implementing connection objects and data operation objects related to ADO.NET; and 2) it allows readers to use different methods to access and manipulate data from the data source and the database. But anything has both good and bad, and this is also the case here. The flexibility also brings some complexity. For example, you have to create and use different providers and different commands to access the different databases using the different codes. Unlike the project developed in the last part, which you can use tools and wizards to select any data source you want and proceed the same coding for the different data sources, in this part you must specify the data provider and command type based on your real data source to access the data in your project. The good news is that LINQ technique released by Microsoft in Visual Studio provides an easier way to access different sources. Before we start to develop our projects, a detailed understanding of the connection and data operation classes is very important, and those classes are directly related to the ADO.NET. Although some discussions have been provided in Chapter 3, we will make a more detailed discussion for this topic in this section in order to provide readers with a clear picture of this issue.
