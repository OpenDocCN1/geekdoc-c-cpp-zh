```csharp
private byte[] getFacultyImage()
{
    MemoryStream ms = new MemoryStream();
    OpenDialog dig = new OpenDialog();
    byte[] bimage = null;

    dig.Filter = "JPG Files (*.jpg,*.jpg)|All Files (*.*.*)";
    dig.Title = "Select the Faculty Image";

    if (dig.ShowDialog() == DialogResult.OK)
    {
        PictureBox.Image = Image.FromFile(dig.FileName);
        PictureBox.Image.Save(ms, PictureBox.Image.Format);
        bimage = ms.ToArray();
    }
    return bimage;
}
```

**FIGURE 7.41** The codes for the delete button click method.

Let's have a look at this piece of code to see how it works.

- A. A LogInfo object **logForm** declared first since we need to use a valid database Connection object in its constructor to perform data deleting actions.
- B. A LINQ query is created and and initialized with three clauses, **from**, **where** and **select**. The range variable **fi** is from the **faculty**, which is an instance of our entity class Faculty and the faculty name works as the query criterion for it. All information related to the selected faculty members (**faculty_name**) will be retrieved and stored in the query variable **faculty**. The **Single** method means only a single record is queried.
- C. The system method **DeleteOnSubmit** is executed to execute a deleting action to the faculty instance, **faculty**.
- D. Another system method **SubmitChanges()** is executed to exactly perform this deleting action against the **Faculty** tables in our sample database. Only after this method is executed, the deleting action is performed and the desired record is deleted from our sample database.

Now let's test the data deletion function. In order to avoid a complicated data recovery, we prefer not to delete any original faculty record. The so-called original faculty record is a faculty record that was created when we built our sample database in Chapter 2 those faculty members contained some complicated relationships with other tables, such as **Course**, **Login** and **StudentCourse** tables, by using primary and foreign keys. Refer to Section 7.6 to get more details for these relationships. If an original faculty record was deleted, then not only the selected faculty member from the **Faculty** table, but also 10 records related to deleted faculty member in other tables, such as **Course**, **Login** and **StudentCourse** tables, would be deleted by Cascading Updating and deleting property set in our sample database. The recovering efforts to retrieve deleted records would be time-consuming and very complicated.
To avoid this retrieving, we prefer to delete some inserted faculty record. Recall that in Section 6.2.8 we inserted a new faculty member **Steve Wang** with the following data items:
