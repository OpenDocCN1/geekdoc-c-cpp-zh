
## 3.4.4 TheDataAdapter Class

The DataAdapter serves as a bridge between a DataSet and a data source for retrieving and saving data. The DataAdapter provides this bridge by mapping Fill(), which changes the data in the DataSet and Update, which changes the data in the data source to match the data in the DataSet.

The DataAdapter connects to your database using a Connection object and uses Command objects to retrieve data from the database and populate those to the DataSet and related classes such as DataTables, the DataAdapter uses Command objects to send data from your database to your database.

To perform a query from your database to the DataSet, the DataAdapter uses the suitable Command objects and assign them to the appropriate DataAdapter properties as SelectCommand, and execute Command. To perform other manipulations, the DataAdapter uses the same Command objects but assign with different properties as InsertCommand, DeleteCommand to handle the associated data operations.

As mentioned in the previous section, the DataAdapter is a sub-component of the Data Provider, so it means that the DataAdapter has different versions based on the used Data Provider. For popular Data adapters: OleDataAdapter, SqlDataAdapter and OracleDataAdapter. Different Data adapters are located at the different namespaces.

If you are connecting to a Server database, you can increase overall performance by using SqlDataAdapter along with its associated SqlCommand and SqlConnection objects. For OLE DB-supported data sources, use the OleDataAdapter with its associated OleCommand and OleDbConnection objects. For ODBC-data sources, use the OdbcDataAdapter with its associated OdbcCommand and OdbcConnection objects. For Oracle databases, use the OracleDataAdapter with its associated OracleCommand and OracleConnection.

## 3.4.5 The DataReader Class

The DataReader is a read-only class and can only be used to retrieve and hold the data rows returned from a database executing ExecuteReader() method. This provides a way of reading a forward-only stream of rows from a database. Depending on the Data Provider you are using, four DataReaders are provided by four Providers. These are ODataReader, OleDbDataReader, SqlDataReader and OracleDataReader.

To create a DataReader instance, you must call the ExecuteReader() method of the Command object, instead of using a constructor that the DataReader class does not have any public constructor. The following code to create an instance of the SqlDataReader is incorrect:

```
SqlDataReader sqlDataReader = new SqlDataReader();
```

While the DataReader object is being used, the Connection is busy serving the DataReader, and no other operations can be performed on the Connection other than closing it. This is the case when the Close() method of the Command is called. For instance, you cannot retrieve output parameters until you call the Close() method to close the connected Data.

The Closed property of the DataReader class can be used to check if the DataReader has been closed or not, and it returns a Boolean value. A true means that the DataReader has been closed. It is a good habit to call the Close() method each time you finish that query using DataReader to avoid the troubles caused by the multiple connections to the database.
