# 4.5.3 Operations To DataTable Objects

In addition to the DataRow operators defined in the DataRowExtensions class, there are some other methods that can be used for the DataTable class in the DataTableExtensions class.

Extension methods enable you to "add" methods to existing types without creating a new type, recompiling, or otherwise modifying the original type. Extension methods are a special kind of static method, but they are called as if they were instance methods on the extended type. For code written in C#, there is no difference between calling an extension method and the methods that are actively defined in type.

The most common extension methods are the LINQ standard query operators that add functionality to the existing IEnumerable<T> types. To use the standard query operators, first bring them into scope using System.Linq. Then any type that implements IEnumerable<T> appears to have instances. You can see these additional methods in IntelliSense completion when you type a operator after an instance of Iumerable<T> type such as List<T> or Array.

Two extension methods defined in the DataTable class, AsEnumerable() and CopyToDataTable(), are implemented in data-driven applications. Because of the space limit, we only use the first method in this section.

The functionality of the extension method AsEnumerable() is to convert and return a sequence of type IEnumerable<DataRow> from a DataTable object. You may have already noticed that we used this method in number of the examples in the previous sections. For example, in the example method RowField and DataSetField which are discussed in the last section, you can find this method and its functionality. Refer to Figures 4.40 and 4.41 to get a clear picture in how to use this method to return a DataRow object.

# 4.6 LINQ to SQL

As mentioned in the previous section, LINQ to SQL belongs to LINQ to ADO.NET and it is a sub-component of ADO.NET. LINQ to SQL is absolutely implemented to the SQL Server database. Different databases need to use different LINQ models to perform the associated queries, as LINQ to MySQL, LINQ to DB2 or Oracle.

LINQ to SQL query is performed on classes that implement the IQueryable<T> interface; the interface is inherited from the IEnumerable<T> interface with additional methods, therefore besides the Standard Query Operator (SQO), the LINQ to SQL queries have additional query operators since it uses the IQueryable<T> interface.

LINQ to SQL is an application programming interface (API) that allows users to use and conveniently access the SQL Server database from the Standard Query Operators (SQO) related to the LINQ. To use this API, you first convert your tables in the relational database that is built on a logical model to the entity classes that are built on the objects model. You then setup a mapping relationship between your relational database and a group of objects that are instantiated from entity classes. The LINQ to SQL or the Standard Query Operators will interface with these entities to perform real data operations. After other, each entity class can be mapped or is equivalent to a physical table in the database, and each entity class's property can be mapped or is equivalent to a column in that table. Only after this mapping relationship has been built, one can use the LINQ to SQL to update data against the database.
