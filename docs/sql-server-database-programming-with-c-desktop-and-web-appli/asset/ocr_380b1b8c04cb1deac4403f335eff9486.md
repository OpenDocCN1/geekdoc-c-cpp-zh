# 3.4.2 The Connection Class

As shown in Figures 3.1 and 3.2, the Data Provider contains four sub-classes and the Connection component is one of them. This class provides a connection between your applications and the database you select to connect to your project. To use this class to setup a connection between your application and the desired database, you need first to create an instance or an object based on this class. Depends on your applications, you can create a global instance for your entire project or you can create local connection objects for each of your windows. A global instance is a good choice since you do not need to perform multiple open and close connections for objects. A global connection is used in all sample projects in this book.

The Connection object you want to use depends on the type of data source you select. Data Provider provides four different Connection classes and each is matched to one different data source. Base 3.5 lists these Connection classes used for the different data sources:

The new keyword is used to create a new instance or object of the Connection class. Although different classes provide overloaded constructors, two popular constructors are utilized for Visual C#.NET 2008. One of them does not accept any argument, but the other accepts a connection string as the argument and the constructor is the most used for data connections.

The connection string is a property of the Connection class and it provides all necessary information to connect to your data source. Regularly this connection string contains a few parameters to define a connection, but only five of them are popularly utilized for most data-driven applications:

+   1) Provider
2) Data Source
3) Database
4) User ID
5) Password

The parameters, contained in the connection string may have a little difference. For example, both OLE DB and ODBC databases need all of these five parameters to be included in a connection string to connect to OleDb or ODBC data source. For the SQL Server connection, you may need to use the Server to replace the Provider parameter, and for the Oracle database connection, you do not need the Provider and Database parameters at all for your connection string. You can find these differences in Section 5.15 in Chapter 5.

The parameter name in a connection string are case-insensitive, but some of parameters, such as the Password or PWD, may be case-sensitive.
