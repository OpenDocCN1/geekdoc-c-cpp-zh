The problem is that no faculty name is available in the Course table and we cannot directly get all course_id based on the faculty name. An efficient way to do this is to use a query with joined tables, which we need to perform a single query by two different tables, Faculty, and Course, to pick up all course_id information. To join these two tables, we need to use the primary key and the foreign key, faculty_id, to set up this relationship. In other words, we want to obtain all courses, every course_id, from the Course table based on the faculty name in the Faculty table. But in the Course table, we only have course name and the associated faculty_id information.

Similarly, in the Faculty table, we only have faculty name and the associated faculty_id information. The result is: we cannot set up a direct relationship between the faculty name in the Faculty table and the course_id in the Course table, but we can build an indirect relationship between them via faculty_id which works as a bridge to connect tables together using the primary and foreign key.

A statement with joined tables, Faculty and Course, can be represented as:

```
SELECT course_id, Course.course FROM Course, Faculty
WHERE (course_id = Faculty.faculty_id) AND (faculty_name = @name)
```

The @name is a dynamic parameter and will be replaced by the real faculty name selected by the user as the run projects.

One point to noted is that this syntax of SQL statement is defined in ANSI 89 standard and is relatively out-of-date. Microsoft will not support this out-of-date syntax in the future. So it is highly recommended to use a new syntax for this SQL statement, which is defined in the ANSI 92 standard and looks like:

```
SELECT course_id, Course.course FROM Course JOIN Faculty
ON (course_id = Faculty.faculty_id) AND (faculty_name = @name)
```
