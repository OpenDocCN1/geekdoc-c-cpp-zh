> One important point is to be noted that these new added tools (cSE. DEPTDataSet, facultyTableAdapter, ...) are exactly instances, not the classes, of those design tools. In C#, they are called fields since these instances are class level and they are very similar to the Form variables in Visual Basic.NET and the class variables in Java. This is the reason why the first letter of each instances is lower case. This is a significant difference between Visual Basic.NET and Visual C#.NET. In Visual Basic.NET, all of these added tools are classes, not instances. You must keep this in your mind when you develop data-driven applications in Visual C.

Now you can run your project by clicking the **Start** button. Wait a moment! One more thing before you run your project is to check whether you have selected your **DataGridform** as Visual C#.NET and Visual Basic.NET. In Visual Basic.NET, one can do that by going to the Properties window and selecting the startup form from the Startup object box. But in Visual C#.NET, you cannot do this in that way. As you know, the **Program.cs** in the Solution explorer contains the entry point of each Visual C# project. **Program.cs** contains the `Main()` method, from which the startup object can be defined.

To check the startup for our current project, SelectWizard Project, the **Program.cs** from the Solution window by double-clicking on it. You can find that instruction,

```
Application.Run(new LogInForm());
```

is located inside this **Main()** method. The startup object is defined by calling a method **Run** with the constructor of **LoginForm** as the argument. To change the startup object for our current project, modify this argument from **LoginForm()** to **DataGridViewForm()**, which means that we want to change the constructor of the **DataGridform** class to create a new instance of the **DataGridViewForm** class, and start our project from this.
