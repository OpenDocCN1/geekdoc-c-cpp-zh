## 5.1.1.4 BindingNavigator

The BindingNavigator allows users to select and browse all records stored in the data source (DataSet) by one in a sequence. The BindingNavigator component provides a standard UI with buttons and enables users to navigate to the first and the previous records as well as the next and last records in the data. It also provides textboxes to display how many records existed in the current data table and the current record's index.

As shown in Figure 5.2, the BindingNavigator is also bound to the BindingSource component. When the user clicks either the Previous or the Next button on the BindingNavigator UI, a request is sent to the BindingSource for the previous or the next record, in this turn, request is sent to the data source for picking up that data.

## 5.1.1.5 TableAdapter

From Figure 5.2, one can find that a TableAdapter is equivalent to an adapter and it just works as a connection method between the database and DataSet, and between the BindingSource and the DataSet. This means that the TableAdapter has dual functionalities when it works as different roles for the different purposes. For example, as you develop your data-driven applications using the DataSet using the TableAdapter's Fill method. The TableAdapter also works as an adapter to coordinate the data operations between the BindingSource and the DataSet when the data controls in Visual C# form needs to be filled or updated.

Prior to Visual Studio 2005, the Data Adapter was the only link between the DataSet and the database. If a change is needed in the data, you need to use a different TableAdapter for each table in the DataSet and to call the Update method of each Data Adapter.

The TableAdapter is introduced in Visual Studio 2005 and you cannot find this from the Tool Window. The TableAdapter belongs to designer-generated component that connect your DataSet Objects with their underlying databases, and it will be automatically created when you add and configure data sources such as DataSet Configuration Wizard.

The TableAdapter is similar to Adapter in that both components can handle the data operations between DataSet and database, but the TableAdapter can contain multiple queries to support multiple tables from the database, allowing one TableAdapter to perform multiple queries to your DataSet. Another Data is that each TableAdapter is a unique class that is automatically generated by Visual Studio to work with only the fields you have selected for a specific database.

The TableAdapter class contains queries used to select data from your database. In addition, it contains different methods to allow Fill the DataSet with dynamic parameters in your project from the database. You can also use the TableAdapter to build different SQL statements as Insert, Update and Delete on the different data operations. A more detailed exploration and implementation of TableAdapter with a real example will be provided in the following sections.

## 5.1.2 Data Design Wizards in the Data Source Window

Starting with Visual Studio 2005, two new Integrated Development Environment (IDE) features, the Data Sources Window and the Data Source Configuration Wizard, are added to help set up data access using the new classes, such as DataConnector and DataAdapter.

The Data Sources window is used to display the data sources or available databases in your project. You can use it to create a user interface (consisting of data-bound controls) by dragging items from the Data Sources window into Visual C forms in your project. Each item the Data Sources window has a drop-down control list where you can select the type of control to create by dragging it onto a form. You can also customize the control with additional controls, such as those that you have created.

A more detailed description on how to use the Data Sources window to develop a data-driven project is provided in Section 5.4.

## 5.1.2.2 Data Source Configuration Wizard

The opened **Data Source Configuration Wizard** is shown in Figure 5.4.

By using the Data Source Configuration Wizard, you can select your desired source or database that will be connected to your new project. The Data Source Configuration Wizard supports three types of data sources:

- The first option, **Database**, allows you to select a data source from a database server on your local computer or on a network server. For this kind of data sources are Microsoft SQL 2017, SQL Server 2019, SQL Server 2019 or Oracle Database 18 XE. You also allows you to choose either MDF SQL server database, a Microsoft Access .MDB or .ACCDB file. The difference between a SQL server and a SQL database is that the former is a complete database that integrates the database management system with data tables to form a body or package, but the latter is only a database file.
- The second option, **Service**, enables you to select a source that is located at a Web service.
- The third option, **Object**, allows you to bind your user interface to one of your database classes.

Click the **Next** button after you selected your desired source, and the next step in the Data Source Configuration Wizard allows you select your data model. Currently, only one model is available, which is DataSet. This means that you can set or build a DataSet to connect to your database and fill that DataSet with a data table, a data row, or a data column from the real database. That DataSet is only mapping to your real database and can be updated with any updating in your database. Select that DataSet model and click the **Next** button to continue.
