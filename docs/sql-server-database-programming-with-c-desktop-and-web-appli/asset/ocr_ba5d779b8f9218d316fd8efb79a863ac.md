```
protected SqlConnection SQLConn()
{
    string cmdString = ConfigurationManager.ConnectionString["sql_conn"].ConnectionString;
    SqlConnection conn = new SqlConnection();
    conn.ConnectionString = cmdString;
    conn.Open();
    if (conn.State != System.Data.ConnectionState.Open)
    {
        conn = null;
    }
    return conn;
}

protected void ReportError(SQLBase ErrSource)
{
    ErrSource.SQLOK = false;
}
```

In other words, to delete one record from the parent table, all records that are related to foreign keys and located at different child tables must be deleted. In order to delete a record using the student_id as the primary key from the Student table (parent table), one must first delete these records using the student_id as a foreign key from the Login and the StudentCourse (child tables). Refer to Section 2.5 and Figure 2.12 in Chapter 2 to get a clear relationship description among different tables in our sample database.

From this discussion, it can be found to delete a student record from our sample database, two deleting queries need to be performed: the first query is to delete the records from the child tables, Login and StudentCourse table, and the second query is to delete the record from the parent table Student table. However, because we used the Cascaded Delete function when we added all in our sample database, we do not need to take care of those tables and the database engine handles these deleting actions for automatically.

A point to be noted is that our dynamic input is a student name, but we need a student_id to perform a delete action. Thus two queries are needed for deletion function; first, we need to get a student_id based on the input parameter student name, and then perform a cascaded delete to that student record based on the student_id.

To save the time and space as efficiently, these two queries need to be developed in the following procedure: WebDeleteStudentsSP(). A single input parameter, sName (student name), is passed into this stored procedure. At this moment, we assume that we have already developed that stored procedure, and will use it in this method.

Open our main service page WebServerUpDt.asm and create this method SQLDeleteSP(), which is shown in Figure 9.99.

Let's look at this code of how it works here:

+   A. The name of this method is SQLDeleteSP() and the returned data type is customer class base SQLBase.

+   B. The content of the query string is equal to the name of the stored procedure we will develop soon. The point is that the name used in this query string must be identical with the name used in our stored procedure. Otherwise, a running error may be encountered since the stored procedure is identified by its name as the project name.

+   C. An instance of our returned base class SQLBase, is created. This instance contains the running status of this Web method and will be returned to the calling method when this is done. A local integer variable intDelete is declared and this variable is used to hold the returned value from calling of the system method ExecuteNonQuery() after this method runs.
