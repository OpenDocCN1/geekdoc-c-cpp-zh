```
private void UpdateParameters(ref SqlSqlCommand cmd)
{
    byte[] image;

    image = getFacultyImage(imageID);
    cmd.Parameters.Add("@name", SqlDbType.Char).Value = txtName;
    cmd.Parameters.Add("@title", SqlDbType.Char).Value = txtTitle;
    cmd.Parameters.Add("@office", SqlDbType.Char).Value = txtOffice;
    cmd.Parameters.Add("@phone", SqlDbType.Char).Value = txtPhone;
    cmd.Parameters.Add("@college", SqlDbType.Char).Value = txtCollege;
    cmd.Parameters.Add("@email", SqlDbType.Char).Value = txtEmail;
    cmd.Parameters.Add("@image", SqlDbType.Binary).Value = image;
    cmd.Parameters.Add("@id", SqlDbType.Int).Value = txtID;
}
```

**FIGURE 8.43** the code for the method UpdateParameters().

Then each piece of faculty information is assigned to the associated input parameter by using the Add() method of the Parameters collection of the Command object.

A point to be noted for the argument cmd passed into this method: The parameter is ref, which means that a reference or address of object is passed. When passed this way, modification will be reflected and returned to the calling method. This passing mode is very similar to a pointer in C++.

Another key is the last or dynamic parameter faculty_id, which is a primary key in the Faculty table but a foreign key in the Login and Courses tables. As mentioned above, updating an existing faculty record, this key cannot be modified but all other parameters can be changed without any issue. For the details see the user-defined method getFacultyImage(), refer to Figure 8.40 in Section 8.5 in this chapter.
