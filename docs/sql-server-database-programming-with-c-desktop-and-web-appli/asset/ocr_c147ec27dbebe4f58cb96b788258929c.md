# 4.9 C# 3.0 LANGUAGE ENHANCEMENT FOR LINQ

C# 3.0 introduces several language extensions that build on C# 2.0 to support the creation and use of higher-order, functional-style class libraries. The extensions enable construction of compositional APIs with equal expressive power of query languages in domains as relational databases and XML.

With comparison to C#2.0, significant enhancements have been added to C# 3.0, and these are mainly developed to support the Language-Integrated Query (LINQ). LINQ is a series of language extensions that supports data querying in a type-safe way; it is released with an elder version of Visual Studio, Visual Studio.NET 2008. The data to which we have discussed in the previous sections of this chapter, can take the form of objects (LINQ to Objects), databases (LINQ-enabled ADO.NET, which includes LINQ to SQL, LINQ to DataSet and LINQ to Entities), XML (LINQ to XML) and so on.

In addition to general LINQ topics, special improvements are made for C# 3.0. The main components of these improvements include:

+   * Lambda Expressions
* Extension Methods
* Implicitly Typed Local Variables
* Query Expressions

Let's have a detailed discussion for these topics one by one.

# 4.9.1 Lambda Expressions

Lambda expressions are a feature that is similar in many ways to anonymous methods. If lambda expressions had been developed and implemented into the language first, there would have no need for anonymous methods. The basic idea of using lambda expressions is that you can treat code as data. In the early versions of C#, such as C# 1.0, it is very common to pass strings, reference types, and so to methods that the methods can work on those values. Anonymous methods and lambda expressions extend the range of values to include code blocks. This concept is common in functional programming.

The syntax of lambda expression (=>) followed by an expression. a comma-delimited list of parameters with a statement. For more complicated lambda expressions, a statement block can be followed by the lambda operator. A simple example of lambda expression used in C# looks like:

```
x => y
```

where x on the left side of the lambda operator is the input parameter and y on the right side of the lambda operator is the output parameter. The data type of both input and the output parameters should be explicitly indicated by the delegate. Therefore, the lambda expressions are closely related to the delegate. This lambda expression can be read as input and output. The syntax of this kind simple lambda expressions can be written as:

```
(param1, param2, ... => output
```

A parenthesis should be used to cover all input parameters.
