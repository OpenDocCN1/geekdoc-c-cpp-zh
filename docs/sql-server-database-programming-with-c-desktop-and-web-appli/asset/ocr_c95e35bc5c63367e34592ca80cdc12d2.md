Now we are ready to develop the new project to perform data insertions. The coding process for this data insertion is divided into three steps:

+   1) The data validation after the data insertion.
2) The data validation after the data insertion.
3) The data insertion using the run time object.

The purpose of the first step is to confirm that all inserted data stored in each associated TextBox should be complete and valid. In other words, allTextBox should be non-empty. The second step is used to confirm that the data insertion is successful, in other words, the new inserted data should be in the desired table in the database and can be read and displayed in the Result Form.

> Unlike the returned-data query as SELECT, in a system query Full() is used to try to open a new database connection if any valid connection is existed between the database and the application, all non-returned data queries as INSERT, UPDATE and DELETE do not this functionality to open a new connection between the database and the application if any valid connection is existed. Therefore the user must develop code to provide this kind of functionality to use non-returned data queries.

# 6.5.1 THE CODING PROCESS FOR THE DATA VALIDATION BEFORE THE DATA INSERTION

This validation can be considered as a pre-validation and can be performed by calling two user-defined methods. The first method is InitializeFacultyInfo() and it is used to set up a relationship between each item in the string FacultyInfo[] and each TextBox stored the faculty information. The second method is CheckFacultyInfo() and it is used to scan and check each TextBox to make sure no one of them is empty.
