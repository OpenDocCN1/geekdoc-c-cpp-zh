Data can be loaded into a DataSet using a TableAdapter from different databases such as Microsoft Access, SQL Server, Oracle, Microsoft Exchange, Microsoft Active Directory, or via OLE DB or ODBC-compliant database when your application begins to run the `Form_Load` event procedure is called if one uses a DataGridView object.

Although not tied to any specific database, the DataSet class is designed to contain relational tables as one would in a relational database. Each table included in the DataSet is represented in the DataSet as a DataTable. The DataTable can be considered as a direct mapping to the real table in the database. For example, the LogIn table, LogInData, is a data table component or DataTable that can be mapped to the real table login in the CSE_DEPT database. The relationship between tables is held in the DataSet as a DataRelation object. The DataRelation provides the information that relates a child table to a parent table via a foreign key. From this point of view, a DataSet can be considered a mini database engine, meaning that it can contain all information of tables it holds, such as the column name and data type, all relationships between tables. More importantly, it contains management functionalities of the tables such as browse, select, insert, update and delete data tables.

A DataSet contains and keeps its data in memory as XML files. In Visual Studio NET 203, when one wants to edit the structure of a DataSet, one must do that by editing an XML Schema or XSD. While there is a visual designer, the terminology and user interface are not consistent with a DataSet and its constituent objects.

With the Visual Studio 2022, one can easily edit the structure of a DataSet and make any changes to the structure of that DataSet by using the DataSet Designer in the Data Source window. More importantly, one can graphically manipulate the tables and queries in a more directly tied to the DataSet rather than dealing with an XML Schema (XSD).

Summarily, the DataSet object is a very powerful component that can contain multiple data tables with all information related to those tables. By using this object, one can easily browse, access and manipulate data stored in it. We will explore this component in more detail in the following sections when a real project is built.
