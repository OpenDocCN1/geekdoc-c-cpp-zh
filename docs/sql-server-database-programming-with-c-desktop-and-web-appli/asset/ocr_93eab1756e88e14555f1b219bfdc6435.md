# 8.4.9.1 The AutoPostBack Property of the List Box Control

One important property to add to a list control is the AutoPostBack property. In contrast to the list box used in the Windows-based application, a SelectedChanged event will not be created in the server side if the user clicked and selected an item from the list box. The reason for this is because the default value for the AutoPostBack property of a list control is set to false when you add a new list box to the Web form. This means that if the user clicked an item from the list box, a SelectedChanged event can only be created in the client side and cannot be sent to the server. As you know, the list is running on the server side when the user projects. Therefore, no how many times you clicked and changed the items in the list box at the client side, no event can be created in the server side. Therefore, it is like that clicking on the list box control cannot be reported by your project as the project runs.

In this project we need to use this SelectedChanged event to trigger its event method to perform the course information query. In order to solve this problem, the AutoPostBack property should be set to true. In this way, time you click an item to select from the list box, the AutoPostBack property will be set post to the server to indicate that the user has interacted with that.
