Indexes are created to provide direct access to rows. An index is a tree structure. Indexes are classified on their logic design or their physical implementation. Logical classification is based on an application perspective, whereas physical classification is based on how the indexes are stored. Indexes can be either partitioned or nonpartitioned. Large tables use partitioned indexes, which spreads an index across multiple table spaces, decreasing contention for look up and increasing manageability. An index may consist of a single column or multiple columns; it may be either unique or non-unique. Some of these indexes are outlined below:

Function based indexes compute the value of a function or expression of one or more columns and store it in an index. It can be created as a B-tree or as B-map. It can improve the performance of queries performed on tables that rarely change.

Domain Indexes are application-specific and are created and managed by the user or applications. Single-column indexes are built on text, spatial, scalar, or LOB data types.

B-tree indexes store a list of row IDs for each key. A B-tree index is similar to the ones in the SQL Server described above. The leaf nodes contain index points to rows. The leaf blocks allow scanning of the index in ascending or descending order. Oracle server maintains all indexes when insert, update or delete operations are performed on a table.

Bitmap indexes are useful when columns have low cardinality and a large number of rows. For example, a column may contain few distinct values Y/N for marital, or M/F for gender. A bitmap is organized like a B-tree where the leaf nodes store a bitmap of row IDs. When changes are made to the key columns, bit maps must be updated.

# 2.8.3.4 Initialization Parameter Files

Oracle server must read the initialization parameter file before starting an oracle database instance. There are two types of initialization parameter files: a static parameter file and a persistent parameter file. An initialization parameter file contains a list of instance parameters, the name of the instance is associated with, the name and location of control files and information about the undo segments. Multiple initialization parameter files can exist to optimize performance.

# 2.8.3.4.2 Control Files

A control file is a binary file that contains the current state of the database. Before a database can be opened, the control file is read to determine if the database is in a valid state or not. It maintains the integrity of the database. Oracle uses a single control file per database is maintained continuously by the server. It cannot be edited by a user or database administrator. A control file contains: database identifier; time stamp of database creation; tablespace name; name and location of data files and redo logs; current log file sequence number; archive and backup information.

# 2.8.3.4.3 Redo Log Files

Oracle's redo log provide a way to recover data in the event of a database failure. All transactions are written to a redo log buffer and passed to the redo log files. Redo logs record all changes to the data, provide a recovery mechanism, and can be organized into groups. A set of identical copies of online redo files is called a redo log group.
