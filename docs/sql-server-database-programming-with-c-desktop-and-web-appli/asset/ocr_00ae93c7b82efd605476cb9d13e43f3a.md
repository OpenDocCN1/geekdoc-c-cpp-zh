There is some complexity in creating a data source that accurately represents the file system and handles exceptions gracefully. The examples in this section create a snapshot of FileInfo objects that represent all the files under a specified root folder and all its subfolders. The actual state of each FileInfo may change in the time between you begin and end a query. For example, if you create a list of FileInfo objects to use as a data source, you might try to access the Length property in a query. If the file no longer exists, you will get a FileNotFoundException in your query, even though you are not querying the file directly. Some queries in this use a separate method that consumes these particular exceptions in certain cases. Another option is to keep your data updated dynamically by using the FileSystemWatcher.

Because of the limitation of the search, here we discuss one file operation or query, which is to open, inspect and query the contents of files in a selected folder (the 6th operation).

# 4.4.3.1 Query the Contents of Files in a Folder

This example shows how to query all the files in a directory tree, open each file, and inspect its contents. This type of technique could be used to create index or reverse indexes of the contents of a directory tree. A simple string search is performed in this example. However, more complex types of pattern matching can be performed with a regular expression.
