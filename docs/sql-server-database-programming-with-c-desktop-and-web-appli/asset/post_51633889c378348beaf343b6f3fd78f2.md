# Introduction to Language Integrated Query (LINQ)

Language-Integrated Query (LINQ) is a groundbreaking innovation in Visual Studio 2008 and the .NET Framework version 3.5, which bridges the gap between the world of objects and the world of data.

Traditionally, queries against data are expressed as simple strings without type checking at compile time or IntelliSense support. In addition, you have to learn a different language for each type of data source: Microsoft Access, SQL databases, XML documents, various Web services, and Oracle databases. LINQ makes a query as a first-class language construct in C# and Visual Basic. You write queries against strongly typed collections of objects using keywords and family operators.

In Visual Studio.NET you can LINQ queries in C with SQL Server, XML documents, ADO.NET DataSets, and any collection of objects that supports IEnumerable or the IEnumerable<T> interface. As mentioned in Chapter 3, LINQ support for the ADO.NET 3.5 Entity Framework is also planned, and LINQ providers are being written by third parties for many Web services and database implementations.

You can use LINQ queries in new projects, or alongside non-LINQ queries in existing projects. The only requirement is that the project should be developed under the .NET Framework 3.5 environment.

Before we can dig into LINQ, we had better a general and global picture about the LINQ. Let's start from the basic introduction about the LINQ.

## 4.1 OVERVIEW OF LANGUAGE INTEGRATED QUERY

The LINQ pattern is established on the basis of a group of methods called Standard Query Operators (SQO). Most of these methods operate on sequences, where a sequence is an object whose type implements the IEnumerable<T> interface or the IQuery<T> interface. The standard query operators provide query capabilities, including filtering, projection, aggregation, and sorting and more. All SQO methods are located in the namespace System.Linq. To use these methods, one must declare this namespace with a directive such as: System.Linq in the namespace section of the code windows.

There are potentially confusing signs and terminologies, such as IEnumerable, IEnumerable<T>, IQuery and IQuery<T>. Let's first have a closer look at those terminologies.

### 4.1.1 Some Interfaces Used in LINQ

Four interfaces, IEnumerable, IEnumerable<T>, IQuery and IQuery<T>, are widely used in LINQ queries via SQO. In fact, two interfaces and IQuery are mainly used for the non-generic collections supported by the earlier versions of C#, such as C# 1.0 and the other two, IEnumerable<T> and IQuery<T>, are used to convert the data of types compatible with the System.Collection.Generic in C# 2.0 to either IEnumerable<T> (LINQ to Objects) or IQuery<T> (LINQ to SQL) since LINQ uses a stronger typed query or sequence as the data sources, and any data in those data sources must be converted to this stronger typed collection before the LINQ can be implemented. ### 4.1.1 The Enumerable and IEnumerable<T> Interfaces

The IEnumerable<T> interface is a key part of LINQ to Objects and it allows all of the C# 2 generic collection classes to implement it. This interface permits the enumeration of a collection's elements. All of the collections in the System.Generic namespace support the IEnumerable<T> interface. Here T converts the data type of the sequence or collection. For example, if you have an IEnumerable<int> of int, expressed by IEnumerable<int>, it is a sequence or collection of ints.

In the case of the non-generic collections which existed in the old version of C#, such as C 1.0 or older, they do not support the IEnumerable<T> interface because of the stronger property of the type. Therefore, you cannot directly call those SQO methods whose first argument is an IEnumerable<T> using non-generic collections. However, you can perform LINQ queries using these collections by calling the Cast or OffType SQO to generate a sequence that implements IEnumerable<T>.
