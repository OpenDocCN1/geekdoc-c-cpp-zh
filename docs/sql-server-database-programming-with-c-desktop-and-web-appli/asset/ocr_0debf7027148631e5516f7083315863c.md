# Introduction to Databases

A clustered index sorts the data in a table so that the data can be accessed efficiently. It is akin to a dictionary or a phone book where records are arranged alphabetically. One can go directly to a specific alphabet and then search sequentially for the specific record. The indexes are like an inverted tree. To index a structure is a b-tree for binary-tree. You start with the root at the top and find the location of other pages further down at secondary level, following to tertiary level and until you find the actual data. There can be only one clustered index per table because bottom pages are the leaf pages and physically rearrange the data.

Non-clustered indexes do not physically rearrange the data in the same way as the clustered indexes. They also consist of a binary tree with various levels of pages. The major difference, however, is that the leaves do not contain the actual data as in clustered indexes; they contain pointers that point to the corresponding records in the table. These pointers are called locators.

The indexes be unique where the duplicate keys are not allowed, or not unique, which duplicates keys. Any column that can be used to access data can be used to generate an index. Usually, the primary and the foreign key columns are used to create indexes.

# 2.8.2 Transaction Log Files

A transaction is a logical group of SQL statements which carry out a unit of work. Client server database log file to keep track of transactions that are applied to the database. For example, before an update is applied to a database, the database creates an entry in the transaction log to generate a 'before' picture of the data in a table and then applies a transaction and creates another entry to generate an 'after' picture of the data in that table. This keeps track of all operations performed on a database. Transaction logs can be used to recover data in the case of crashes or disasters. Transaction logs are automatically maintained by SQL Server.

# 2.8.3 Oracle Databases

Oracle was designed to be platform-independent, making it architecturally more complex than the SQL server database. The Oracle database contains more files than SQL Server database. The Enterprise edition is the most powerful and is suitable for large installations using large number of transactions in multi-environments. The Standard edition is also used by multi-user installations. It lacks some of the utilities available in the Enterprise edition. The Personal edition is used in a single-user environment for the development of database applications. The database engine components are virtually the same for all three editions.

Oracle architecture is made up of several components, including an Oracle server, Oracle instance and an Oracle database. The Oracle server contains several files, processes, and memory structures. These are used to improve the performance of the database and ensure database recovery in case of a crash. An Oracle instance contains background processes of an Oracle instance, and an Oracle database. These background processes perform input/output and monitor other Oracle processes to ensure better performance and reliability. The Oracle database consists of files that provide the physical storage for the data.
