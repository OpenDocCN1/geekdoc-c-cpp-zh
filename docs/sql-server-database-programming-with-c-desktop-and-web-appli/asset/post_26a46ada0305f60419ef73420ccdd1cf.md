## 4.5.1 Query TypedDataSet

If the schema of DataSet is known at design time, it is highly recommended that you use a typed DataSet using LINQ to DataSet. A typed DataSet is a class that derives from a DataSet. As such, it inherits all the methods, events, and properties of a DataSet.

Additionally, a typed DataSet provides strongly typed methods, events, and properties. This means you can access tables and columns by name, instead of using collection-based methods. This makes queries simpler and more readable.

LINQ to DataSet allows querying over a DataSet. With a typed DataSet, you do not have to use the generic Field<T> or SetField(T> to access column data. Property names are available to access columns using the correct type, so that the mismatch errors are caught when the code is compiled instead of at runtime.

Before we begin creating a typed DataSet, we must generate a class using the DataSet Designer in Visual Studio 2022.

## 4.5.2 Operations on DataRow Using the Extension Methods

LINQ to DataSet functionality is expressed primarily through the extension methods in DataRowExtensions and DataTableClasses. In C#, you can call either of these methods as an instance method of any object of type. When you use instance method to call this method, omit the first parameter. The DataSet API has been extended with two new methods of the DataRow class, Field() and SetField(). You can use these to form Language-Integrated Query (LINQ) expressions and method queries against DataObjects. They are the recommended methods to use for accessing column values within Language-Integrated Query (LINQ) expressions and method queries.

In this section discuss how to access and manipulate column values using the extension methods provided by the DataRow class, Field() and the SetField() methods. These methods provide easier access to column values for developers, especially regarding null values. The DataSet uses Value to represent null values, whereas LINQ uses the null type supported in .NET Framework 2.0. Using the pre-existing column accessor in DataSet requires us to cast the return object to the appropriate type. If a particular field in a DataRow is null, you must explicitly check for it before returning the value and implicitly casting it to another throws InvalidCastException.

The Field() method allows you to obtain the value of a column from the DataRow object and handles the casting of DBNull. In total, the Field() method has six different prototypes. The SetField() method has three prototypes, allows users to set a new value for a column from the DataRow object, including a nullable data type whose value is null.
