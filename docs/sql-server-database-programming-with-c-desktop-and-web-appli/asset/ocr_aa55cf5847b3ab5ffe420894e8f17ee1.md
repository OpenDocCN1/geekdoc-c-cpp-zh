As discussed in the previous sections, files 2 and 3 are used to provide some default functions to get some system data and operations.
We can add operations or methods to the default service IService1.cs to build our project.
But here we want to build our Web service with our own code-behind page in our custom way, then need to perform the following operations to add a new Web main service into our project:

+   1. Right-click on our new **WebServiceSelect Project** from the Solution Explorer window and select the **Add | Item**.
2. On the **New Item** wizard, select **Web Service (ASMX)** from the Template list.
3. Enter **WebServiceSelect.asmx** in the **Name** box.
4. Click on the **Add** to complete this item addition operation.

The modified Web service project is shown in Figure 9.7.
The Web service file, **WebServiceSelect.asmx**, is a code-behind page and it is where we need to create and develop the codes for our Web service. This page contains a default class that is derived from the base class **WebService**. The class defined a default Web method **HelloWorld** that is a placeholder and we can replace it with our operation or methods based on the requirement of our Web service project. This file is also used to display information about the Web service's methods and access to the Web's WSDL information.
The configuration file **Web.config** is used to set configuration for our new Web service project, as the namespaces for all kinds of Web bodies, connection strings for data components and Web services and Windows authentication. All of these components are automatically created and added into our new project. Importantly, the file **WebServiceSelect.asmx** is designed to automatically create extensible WSDL methods, serialize and de-serialize parameters, and provide hooks for message interception within our applications. But it only contains a compile directive when a new Web service project is created and opened from the File System.
