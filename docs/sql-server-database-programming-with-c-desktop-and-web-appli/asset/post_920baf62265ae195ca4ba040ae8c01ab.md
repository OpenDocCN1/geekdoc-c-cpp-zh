Let's take a look at this piece of codes to see how it works.

A new instances related to our Web service and base class, **wsSQLDelete**, and **wsResult**, are created and those instances are used to access the Web method **wsDeleteStudentSP()** we developed in our Web service **WebServiceUpdt Project**. The key is that our current project's **WebClientSQLUPdt_Project** must be prefixed to our Web reference since this reference is added into our current project, but the Student page file is built in another project or namespace. **WebSelect_Project**. A local string variable **errMsg** is created and is used to resolve the error source that will be displayed as part of an error message.

A Try-Catch block is used to call the method **SQLDeleteSP** with one student's name, **txtName.Text**, that works as an identifier, to run a stored procedure **WebDeleteStudentSP()** to performing this action against sample database.

An error message will be displayed if an error is encountered during data deletion action. One point is to noted that the displaying format of this error message. To display a string in the message box in the client side, one must use the Javascript function **alert("" + input_string + variable as argument that is escaped and represented by "\\"")**.

Besides the system error-checking methods, we also need to check the member data **SQLOK** that is defined in our returned class in the Web service project to make sure that this data deleting is error-free. A returned **false** value of this member data indicates that this deleting encountered some application error and the error source stored in another member **Error** is displayed.

Finally, a cleaning job is performed to empty all pieces of information related to the deleted students from textboxes.
