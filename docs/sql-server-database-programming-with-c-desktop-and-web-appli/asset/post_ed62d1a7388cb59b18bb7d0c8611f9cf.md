## 3.4.1.2 The OLEDB Data Provider

The System.Data.OleDb namespaces hold all classes used by the .NET Framework 2.0 Data Provider for OLE DB. The .NET Framework Data Provider for OLE DB describes a collection of classes to access an OLE DB database source in the managed space. Using OleDbDataAdapter, you can fill a memory-resident DataSet that you can use to query and update the data source. The following Data Providers support:

- Microsoft Access
- SQL Server (7.0 or later)
- Oracle (9 or later)

One advantage of using the OLEDB.NET Data Provider is to allow users to develop a generic data-application. The so-called generic application means you can use the OLEDB.NET Data Provider-you can use the OLEDB.NET Data Provider to access any data source such as Microsoft Access, SQL Server, Oracle and other data source that support the OLEDB.

## 3.4.1.3 The SQL Server Data Provider

This Data Provider access to a SQL Server version 7.0 or later database using its internal protocol. The functionality of the data provider is designed to be similar to that of the .NET Framework data providers for OLE DB, ODBC, and Oracle. All classes related to this Provider are defined in a DLL file and is located at the System.Data.SqlClient namespace. Although Microsoft provides different Data Providers to access the data in SQL Server database, such as the ODBC and OLE DB, for the sake of optimal operations, it is highly recommended to use this Provider to access the data in an SQL Server data source.

As shown in Figure 3.4, this Data Provider is a new version and it can only work for the SQL Server version 7.0 and later. If an older version of SQL is used, you need to use either OLE DB.NET or SQLOLEDB Data Provider.

## 3.4.1.4 The Oracle Data Provider

This Data Provider is an add-on to the .NET Framework that provides access to the Oracle database. All classes related to this Data Provider are located in the System.Data.Oracle namespace. This provider relies upon Oracle Client Interfaces by the Oracle Client Software. You need to install the Oracle client on your computer to use this Data Provider. Microsoft provides multiple ways to access the data stored in an Oracle database, such as Microsoft ODBC for Oracle and OLE DB, you should use this Oracle Data Provider to access the data in an Oracle data source since this one the most efficient way to access the Oracle database.

This Data Provider can only work for the recent versions of the Oracle database such as 8.1.7 and For older versions of the Oracle database, you need to use MSDAORA or an OLE DB.NET.

## 3.4.2 The Connection Class

As shown in Figures 3.1 and 3.2, the Data Provider contains four sub-classes and the Connection component is one of them. This class provides a connection between your applications and the database you select to connect to your project. To use this class to setup a connection between your application and the desired database, you need first to create an instance or an object based on this class. Depends on your applications, you can create a global instance for your entire project or you can create local connection objects for each of your windows. A global instance is a good choice since you do not need to perform multiple open and close connections for objects. A global connection is used in all sample projects in this book.

The Connection object you want to use depends on the type of data source you select. Data Provider provides four different Connection classes and each is matched to one different data source. Base 3.5 lists these Connection classes used for the different data sources:

The new keyword is used to create a new instance or object of the Connection class. Although different classes provide overloaded constructors, two popular constructors are utilized for Visual C#.NET 2008. One of them does not accept any argument, but the other accepts a connection string as the argument and the constructor is the most used for data connections.

The connection string is a property of the Connection class and it provides all necessary information to connect to your data source. Regularly this connection string contains a few parameters to define a connection, but only five of them are popularly utilized for most data-driven applications:

1) Provider
2) Data Source
3) Database
4) User ID
5) Password

The parameters, contained in the connection string may have a little difference. For example, both OLE DB and ODBC databases need all of these five parameters to be included in a connection string to connect to OleDb or ODBC data source. For the SQL Server connection, you may need to use the Server to replace the Provider parameter, and for the Oracle database connection, you do not need the Provider and Database parameters at all for your connection string. You can find these differences in Section 5.15 in Chapter 5.

The parameter name in a connection string are case-insensitive, but some of parameters, such as the Password or PWD, may be case-sensitive. Many of the connection string properties can be read out separately. For example, one of the most properties for your data-driven applications. By checking this property, you can know what is the current connection status between your database and your project, and this checking is necessary for you to make the decision over which your program is supposed to go. You can also avoid the unnecessary errors related to the data source connection by checking this property. For example, you cannot perform any data operation if your database has not been connected to your application. By checking this property, you can get a clearer picture whether your application is connected to your database or not.

A typical data connection instance with a general connection string can be expressed by the following:

```csharp
xxxConnection Connection = new xxxConnection("Provider=MyProvider;" + +
"Data Source=MyServer;" + +
"Database=MyDatabase;" + +
"User ID=MyUserID;" + +
"Password=MyApp;
```

where xxx should be replaced by the selected Data Provider in your real application, as OleDb, Sql or Oracle. You need to use the real values implemented in your applications to replace those nominal values such as MyServer, MyDatabase, MyUserID and MyPassword. Provider indicates the driver you select. If you installed a local SQL server and client such as the SQL Server 2019 Express on your computer, the Provider could be localhost. If you are using a remote SQL Server instance, you need to use your server's network name. If you are using the default instance name SQLX on, you need to use SQLEXPRESS as the value for your Data Provider. For the Oracle database, you do not need to use this parameter.
The Data Source parameter indicates the name of the network computer on which your SQL server or oracle is installed and running.
The Database parameter indicates your database name.
The User ID and Password parameters are used for the security issue for your database. In most cases, the default Windows NT Authentication is utilized.
