# 7.1 UPDATE OR DELETE DATA AGAINST SQL SERVER DATABASES

We have already provided a very detailed discussion about the TableDirect methods in Section 6.1 in Chapter 6. To use these methods to directly access the database to make the desired manipulations to the data that, one needs to use Visual Studio.NET Tools and Wizards to create and configure the associated TableAdapter. There are some limitations when using these Direct methods to update or delete against databases. For example, TableAdapter is associated with a unique data name in the DataSet; therefore, the updating or deleting can only be executed for one data table by the associated TableAdapter. In other words, the specified TableAdapter cannot update or delete data from any other data other than the data that is related to the created TableAdapter.

# 7.1.1 UPDATING AND DELETING DATA AGAINST RELATED TABLES IN A DataSet

When updating or deleting data against related tables in a DataSet, it is important to update or delete data in the proper sequence in order to reduce the chance of violating referential integrity constraints. The order of command execution will also follow the indices of the DataRowCollection in the DataSet. To prevent data integrity errors from being raised, the best practice is to update or delete data against the database in the following sequence:

+   1) Child table: delete records.
2) Parent table: insert, update, and delete records.
3) Child table: insert and update records.
