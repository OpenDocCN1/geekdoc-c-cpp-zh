One need to emphasize that when performing a data insertion, the data can only be inserted into the same item by one time, and does not allow multiple insertions of the same item. To avoid multiples, in this application (exactly in most popular applications) we need to disable the Insert button once record is inserted successfully (refer to step D). If the insertion failed, we need to recover or re-enable the Insert button to allow the user to try another insertion (step E).

From the above explanation, we know that it is a good way to avoid the multiple insertions of the same item into the database by disabling the Insert button after insertion is successfully completed. A question arises: When and how can this be enabled to allow us to insert some other records if we want to do that later? The solution to this question is to develop another method to handle this issue. Try to think about it; the time we want to insert new data item into the database, first must enter each piece of faculty information into each associated TextBox, such as txtFacultyID, txtFacultyName, txtOffice, txtPhone, txtTitle, txtCollegeEmail. In other words, anytime the content of a TextBox is changed, which means that a new record will be inserted, we should enable the Insert button at that moment to allow users to perform this insertion.

Most databases, including the Microsoft Access, SQL Server and Oracle, do not allow multiple insertions of the same data item into the databases. Each data item or record can only be added or inserted into the database by one. In other words, no duplicating record can be added or existed in the database. Each record in the database must be unique. The popular way to avoid this situation is happens to to disable the Insert button after one insertion is done.
