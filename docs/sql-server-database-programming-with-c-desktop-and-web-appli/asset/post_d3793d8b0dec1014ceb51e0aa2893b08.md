### 7.4.2.1 Develop Codes to Delete Data

Open the Delete's Click method by double-clicking the Delete button from the Designer View of the Faculty Form window, and enter the codes that are shown in Figure 7.18 into that method. Let's have a close look at this code to see how it works.

A. The deleting query string is declared at the beginning of this method. The only input parameter is the faculty_name. Although the primary key of the Faculty table is faculty_id, in order to make it convenient to the user, the faculty_name is used as the criterion for this data-deleting query. A potential problem of using the faculty_name column as the deleting-criterion that no duplicated faculty_name should be existed in the Faculty table for application. In other cases, each faculty name must be unique in the Faculty table. A solution to this potential problem is that we use the faculty_id as the criterion for the data-deleting query as an option.

- A. A MessageBox's button is used to display both buttons in the MessageBox, Yes and No, when the project runs.
- B. All components and local variables used in this method are declared here. The data type of the variable is DialogResult. However, one can use an integer variable to return it. We use integer intDelete to hold the returned data from the ExecuteNonQuery() method to delete a record from the Faculty table.
- C. As the delete button is clicked when the project runs, first MessageBox is displayed to confirm that the user wants to delete the selected member from the Faculty table.
- D. If the user's answer is Yes, then the deleting operations begin to proceed. The Command object is initialized and built using the Connection object and the Command string we defined at the beginning of this method.
- E. The dynamic parameter @name is replaced by the real parameter, the faculty name stored in the Faculty Name combobox Combine. A key point to be that you must use the faculty name stored in the combobox control, which is an existing faculty name, you cannot use the faculty name stored in the Faculty Name TextBox since that may be an updating faculty name.
- G. The ExecuteNonQuery() method of the Command class is called to execute the data-deleting query to the Faculty table. The running result of calling that method is stored in the local intDelete.
- H. The Command object is released after the data deleting.
- I. The user-defined method CurrentFaculty() is executed to update all faculty names in the Faculty Name combobox after this deletion query allow users to check and confirm that data deletion.
- J. The returned value from calling of the ExecuteNonQuery() method is equal to the number of rows that have been successfully deleted from the Faculty table. If a zero returns, which means that no row has been deleted from the Faculty table and that data deletion is failed, an error message is displayed if that situation occurred.
- K. After the deleting is completed, all faculty information stored in seven TextBoxes and the faculty image stored in the PhotoBox should be cleaned up by users to confirm this data deletion.

Finally let's take care of the coding process to validate the deleting query.

```csharp
private void cmdDelete_Click(object sender, EventArgs e)
{
    string cmdString = "DELETE FROM Faculty WHERE (faculty_name = @name)";
    MessageBoxButtons vbButton = MessageBoxButtons.YesNo;
    SqlCommand sqlCommand = new SqlCommand();
    DialogResult Answer;
    int intDelete;

    Answer = MessageBox.Show("Do you want to delete this record?", "Delete", vbButton);
    if (Answer == Yes)
    {
        sqlCommand.Connection = loginForm.Connection;
        sqlCommand.CommandType = CommandType.Text;
        sqlCommand.CommandText = cmdString;
        sqlCommand.Parameters.Add("@name", SqlDbType.Char).Value = comboBox.Text;
        intDelete = sqlCommand.ExecuteNonQuery();
        if (intDelete == 0)
        {
            MessageBox.Show("The Deleting failed!");
        }
        else
        {
            ClearFaculty();
            PhotoBox.Image = null;
        }
    }
}
```
