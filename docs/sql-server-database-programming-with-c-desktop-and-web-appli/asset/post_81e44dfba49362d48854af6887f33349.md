| A B | private void CourseList_SelectedIndexChanged(object sender, EventArgs e) {
LogForm logForm = new LogForm();
IQueryable<Course> cinfo = from ci in logForm.dept_Courses
where ci.course_id == (String)CourseList.SelectedItem
select ci;
foreach (Course c in cinfo) {
txtCourseID.Text = c.course_id;
txtCourseName.Text = c.course1;
txtSchedule.Text = c.schedule;
txtClassRoom.Text = c.classroom;
txtCredits.Text = c.credit.ToString();
txtEnroll.Text = c.enroll.ToString();
}
logForm.Close();
} | D |

**FIGURE 5.125** The codes for SelectedIndexChanged method.

Let's have a look at this piece of code to show how it works.

- A. An instance of the LogForm class, **logform**, is created and the purpose of creating this instance is that we can use the global object connection **CSE_DEDataContext** we created in that class.
- B. A standard LINQ to SQL query `IQueryable<Course>` variable and the implicit ci is assigned to the cinfo that is a type Course variable. The iteration ci is used to iterate over the result of this query from the Course table. Then a simple SELECT statement is executed with the **WHERE** clause. The query criteria is that **ci is selected** from the **Course list**.
- C. A foreach loop is utilized to pick up each selected data row c, which is obtained from the cinfo we get from the LINQ query above. Then, assign each column to the associated TextBox in the CourseForm window to display them. Since we are using a typed database, therefore do not have to identify each column by name or we can directly use each column's name as the `field<string>` and the column name as the position for each of them. A trick is that the name of the column on the Course entity class has changed from **course to course1**. Recall that in Chapter 2, the name of this column is **course** in the **Course table** in our sample database. The reason for this is that when we build the object-relational model for our sample database in Section 5.17.2 to create the entity class, there is a duplication between our table's name (**Course**) and the second column's name (course). Note that SQL Server name are not case sensitive, therefore in order to avoid duplicate naming, the second column in the **Course table** has been modified from **course to course1** in the entity automatically by the Object Relational Designer.
- D. Finally the created instance **logform** is closed since we do not need it anymore.

Compared the codes in Figures 5.124 and 5.125 with these codes we developed in Figures 5.82 and 5.83, it can be found that even they have the same functionalities, and this is the evidence of advantage of using LINQ to SQL over the traditional database query methods.
