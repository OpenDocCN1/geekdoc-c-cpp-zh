However, two components in the ADO.NET are Data Provider-independent: DataSet and DataTable. These two components are located at System.Data. You do not need to use any prefix when you use these two components in your applications. Both DataSet and DataTable can be filled using the DataAdapter or the Adapter components.

ADO.NET provides different classes to allow users to develop data-driven applications using different methods. Among these, two popular methods will be discussed in this chapter in detail.

The first method is to use the so-called DataSetDataAdapter method to build a data-driven application. In a real application, DataSet and DataTable classes have different roles when they are embedded into a DataSet and each table can be filled, inserted, updated and deleted using the different query method provided by the DataAdapter as the SelectCommand, InsertCommand, UpdateCommand or DeleteCommand When shown in Figure 5.68, when you use this, the Command and Parameter objects are embedded or attached to the DataAdapter (represented by a shaded block) and the DataTable is embedded into the DataSet (represented by another shaded block). This method is relatively simple since you do not need to call some specific objects, such as the DataReader or ExecuteNonQuery to complete this data query. You just need to call the associated command of the Table to finish this operation. But this simplicity brings some limitations for your applications. For instance, you cannot access data tables separately to perform multiple specific operations using this single specified DataAdapter.

The second method is to use each object individually, which means that you do not have to use the DataAdapter or embed the DataTable into the DataSet. This provides more flexibility. In this method, no DataAdapter or DataSet is needed, and you can create a new Command object with a New connection, then build a query statement and attach some useful parameter to that query for the DataReader object, also you can perform any data manipulation by calling the ExecuteReader() method or any data manipulation by calling the ExecuteNonQuery() to modify the DataTable.

In addition to these two methods, the LINQ method which was introduced by Microsoft in Visual Studio 2008 is also discussed later in this Chapter.
