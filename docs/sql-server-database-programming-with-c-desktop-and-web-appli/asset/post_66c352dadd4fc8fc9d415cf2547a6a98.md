
# Data Updating and Deleting with Visual C#.

Another important point in recovering deleted records is the order in which you performed those recovering jobs. You must first recover the faculty member deleted from the parent table, Faculty table, and then you can recover any other related records in all other child tables. The reason for this is that the Faculty is a parent table with the faculty_id as a primary key, you cannot recover any other record without first recovering the deleted record from the parent table.

To avoid recovering troubles, we prefer to delete some newly inserted faculty record. Recall that in Section 6.2.8 in Chapter 6, we inserted a new faculty member Steve Wang with the following data items:

| Faculty ID: | W56788 |

| Email: | swang@college.edu |
| Faculty Image | Wang.jpg |

The main reason to delete this record is that no record in any other tables is related to this new inserted faculty, and this makes the recovering job much easier and simpler. Prior to performing this deleting action, run our current project to insert record into the Faculty table in our sample database.

Now go to the Faculty Name combo, one can find that new inserted faculty member Steve Wang. Select faculty member and click on the Delete button to delete this record from the Faculty table. Then click on the MessageBox and all faculty information displayed in seven TextBox. Is our data deleting successful? To answer this question, the Faculty Name combo and the deleted faculty member, Steve Wang, cannot be found from box, and this means that the faculty with all information have been successfully deleted from the Faculty table. Yes, our data deleting is successful.

Another way to confirm this deleting action is to open the Faculty table from the Server Explorer window to do that checking.
