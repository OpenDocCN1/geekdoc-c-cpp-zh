# 3 Introduction to ADO.NET

It has been a long story for developers to generate and implement sophisticated data processing techniques to improve and enhance data operations. The evolution of data access has been a long process, focusing predominantly on how to deal with relational data in a more flexible manner. The methodology development has been focused on Microsoft-based APIs, such as ODBC, OLEDB, Microsoft® Jet, Data Access Objects (DAO) and Remote Data Objects (RDO), in addition to many non-Microsoft-based APIs. These APIs did not bridge the gap between object-based and semi-structured (XML) data programming needs. Combining this with the problem of dealing with different data stores, non-relational data such as XML and applications across multiple languages are challenging and have themed opportunities for complete re-architecture. The ADO.NET is a good solution for these challenges.
ADO.NET 2.0 was considered as full solution for the relational database API and object-oriented access API which was introduced with Visual Studio 2.0 and Visual Studio.NET 2005. The latest version of ADO.NET is 4.3, which has released with the .NET Framework 4.0 and Visual Studio.NET 2017. In this chapter, first we will provide a detailed review of the history of ADO.NET, and then a full discussion and description about the components and architectures of ADO.NET 2.0 is given since most components for today's database actions are still covered by the ADO.NET 2.0. Finally we introduce some new features and components in the ADO.NET 3.5.

# 3.1 THE ADO AND ADO.NET

ActiveX Data Object (ADO) is developed on Object Linking and Embedding (OLE) and Component Object Model (COM) technologies. COM is used by developers to create reusable software components, link components to build applications, and take advantage of Windows services. In recent decades, ADO has been the preferred interface for Visual Basic programmers to access various data sources, ADO 2.7 being the latest version of this technology. The development of data access methods can be traced back to the mid-1990s, with Data Access Object (DAO);this was then followed by Remote Data Object (RDO), which is based on Open Database Connectivity (ODBC). The late 1990s saw the development of ADO, which is based on OLEDB.

ADO.NET 4.3 is the latest version of ADO.NET and is based principally on the Microsoft .NET Framework 4.0. The ADO.NET Common Language Runtime provides bi-directional, transparent integration with COM. This means that COM and ADO.NET applications and components can use functionality from each system. However, the ADO.NET 4.3 Framework provides developers with a significant number of benefits, including a more robust, evidence-based security model, automatic memory management native services support and Integrated Query (LINQ). For new developments, the ADO.NET 4.3 is highly recommended as a preferred technology because of its powerful managed runtime environment and services.

This chapter will provide a detailed introduction to ADO.NET 2.0 and ADO.NET 4.3 and its components, and these components will be utilized for the rest of the book.
