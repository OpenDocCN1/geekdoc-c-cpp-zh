
# SQL Server Database Programming with C#

Regularly a Connection String is composed of five parts:

- Provider
- Data Source
- Database
- User ID
- Password

A typical data connection instance with a general connection string can be expressed by the following codes:

```
Connection = new xxxConnection("Provider=MyProvider"; +
    "Data Source=MyServer"; +
    "Database=MyDatabase"; +
    "User ID=MyUserID"; +
    "Password=MyPassword");
```

where xxx should be replaced by the selected data driver in a real application, such as OleDb, Sql or Oracle. You need to use the real parameter values implemented in your applications to replace nominal values as MyServer, MyDatabase, MyUserID and MyPassword in a real application.
The Provider parameter indicates the driver you selected. If you installed a local SQL server and client as the SQL Server 2019 Express on your computer, the computer should be localhost. If you are using a remote SQL server instance, on your computer, you need to use remote server's network name. use \SQLEX as the value for your provider parameter. Similar values can be used for the Oracle server database.

The Data Source parameter indicates the name of connection on which your SQL server instance is installed or running. The Database parameter indicates your database name. The User ID and Password parameters are used for the security for your database. In most cases, the default Windows Security Authentication is utilized.

You can also use the OleDB as SQL Server database driver. A sample connection string to be connected to a SQL Server database using the OleDB driver can be expressed:

```
Connection = new OleDbConnection("Provider=OLEDB"; +
    "Data Source=MyServer"; +
    "Database=CSE_DEPT"; +
    "User ID=MyUserID"; +
    "Password=MyPassword");
```

You need to use the real parameter values implemented in your applications to replace nominal values as MyServer, MyUserID and MyPassword for this connection object.
When you connect to the SQL Server database using SqlClient with the Windows Authentication Mode, the connection string is a little different from those strings above. The Provider parameter should be replaced by the Server parameter and the User ID and Password parameters should be replaced by the Integrated Security parameter. A sample connection string to be used to connect a SQL Server database using the SqlClient is:

```
Connection = new SqlConnection("Server=SMART\SQL2019EXPRESS"; +
    "Database=CSE_DEPT"; +
    "Integrated Security=SSPI");
```

where the value for the Server parameter is: ComputerName\SQL Server 2019 Express name since we installed the Express version of the SQL 2019 Server in our local computer. We also installed the SQL 2019 Client on the same computer to make it work as both a server and client.

However, if a SQL Server Authentication Mode is used for this connection, a completed connection string, including the Server, Database, User and Password, is needed, and it looks like:

```
Connection = new SqlConnection("Server=SMART\SQL2019EXPRESS"; + \
"Initial Catalog=CSE_DEPT"; + \
"User ID=UserID"; + \
"Password=MyPassword");
```

where the database name is replaced by the Initial Catalog and the Integrated Security is replaced by Username and Password.

By default, SQL Server 2019 Express used Windows Authentication to authenticate connections when it is installed in your machine. In most popular database applications, a mixed or a SQL Server Authentication Mode is adopted for most database drivers. To match applications, the default Windows Authentication Mode needs to be changed to the SQL Server Authentication Mode. Two ways can be utilized to change that connection mode:

- 1) Select the SQL Server Authentication Mode when installing SQL Server 2019 Express database in your machine.
- 2) Change the Windows Authentication Mode to the SQL Server Authentication Mode after the SQL Server 2019 Express database has been installed in your machine with the Windows Authentication Mode.

Refer to Appendix C on the CRC ftp site to perform this operation if one wants to use the SQL Authentication Mode to connect to our sample database.
In the sections below we have used the SelectWizard Project, to make things simple, we created and added our DataSet into project using the default Windows Authentication Mode to connect to our sample. If one wants to build a DataSet to connect to the sample database with SQL Server Authentication Mode via design tools and wizards, refer to Appendix D on the CRC ftp site, which provides details to carry out this connection. In the following projects, we will use both authentication methods to connect to our sample database to perform data queries.

In this section, we use an SQL Server 2019 Express database and connect it with our example project using the SQL Server database used in this sample project CSE_DEPT, which was developed in Chapter 2. The advantages of using the Express version of SQL 2019 include, but are not limited to the following:

- The SQL Server 2019 Express is fully compatible with SQL Server 2019 database and has the full functionalities of the latter.
- The SQL Server 2019 can be easily downloaded from the Microsoft site free of charge.
- The Microsoft SQL Management Studio 18 is also downloaded and installed on your local computer free of charge. You can use this tool to build your database easily and conveniently.
- The SQL Client can be downloaded and installed on your local computer free of charge. You can install both SQL Server and Client on your local computer to develop professional data-driven applications to connect to your SQL database easily.

# 5.15.2 Create A New C# Project RTOSelect Project

Now we need to create a Visual C# 2022 project RTOSelect to query data from samples in our database. To make things simple, we only need to use some Windows Forms, such as Login Form, Selection Form, Faculty Form and Course Form, to perform related queries. We only need to build these Forms in this new project. One easy way to build Forms is to use some existing Forms, Login.cs, Selection.cs, Faculty.cs, and Course.cs, which can be found on the CRC Press ftp site, in the folder Students\Windows Forms. One can copy those files and save them to one of your local folders, and add them to the new project later.

Performing the following operations to create a new Visual C# Windows Forms App project RTOSProject:

- 1. Launch Visual Studio 2022 by clicking its icon on the desktop or the task bar.
- 2. Click on the Continue without code link located at the lower-right corner to open the standard Visual Studio window.
- 3. Go to the File | Project item to select the Create new project wizard.
- 4. On the opened wizard, select the template, Windows Forms (.NET Framework) with C#, which is on the left, and click it to select it. Then click on the Next button to continue.
- 5. On the next wizard, Configure your project, enter RTOSProject into the Project name box, and RTOSSelection into the Solution name box, respectively. Select your desired folder as the location from the Location to save this new project.
- 6. Click on the Create to create this new project.

To save the time, we can add and five existing Windows Forms, Login.cs, Selection.cs, Factory.cs, Student.cs and Course, into this new project. Performing the following operations to complete these Forms additions:

- 1. On the newly opened project, go to the Solution Explorer window and right-click on the iconForm1.cs and select the Delete item to remove this file.
- 2. Right-click on the RTOS Project in the Solution Explorer and select the Add | Existing Item to open the Add Existing window.
- 3. Browse to the CRC Press ftp site, in the folder Students\Windows Forms under that site, select the Login.cs by clicking its checkbox on the list.
- 4. Click on the Add button to add this Form into our project.
- 5. Immediately, a new Login.cs is added into the Solution Explorer window. Wait a moment, this file will become a Login.cs folder with two subsidiary files, Login.designer.cs and Login.resx.
- 6. Repeat steps 2-5 to add the other four Forms by one by one. The point is that on each occasion you can add only one file. Otherwise, some exceptions or errors may be encountered.

Now we need to set and use the Login.cs as our starting object, and modify the namespaces in four files to enable our project to recognize them. Performing the following operations to complete this setup and namespaces modifications:

- 1. Right-click on the Login folder from the Solution Explorer window and select the View Code item to open the code for this Login.cs class file.
- 2. Change its namespace from the original SelectWizard_Project to our current namespace, RTOSSelect_Project.
- 3. Open the Login.designer.cs file by double-clicking it from the Solution Explorer window (you need to expand the original namespace SelectWizard_Project to our current namespace).
- 4. Change the top line from the original namespace SelectWizard_Project to our current namespace, RTOSSelect_Project.
- 5. Open the main file, Program.cs, browse to the Main() method that is the entry or starting point for our project. Replace the third coding line using Application.Run(new Form1()); with Application.Run(new LoginForm()).
