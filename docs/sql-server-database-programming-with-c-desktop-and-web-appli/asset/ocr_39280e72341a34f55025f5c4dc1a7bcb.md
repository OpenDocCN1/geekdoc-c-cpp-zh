# 3.4.8 ADO.NET 4.3 ENT FRAMEWORK

Most databases, such as Microsoft Access, SQL Server and Oracle, use the relational model of data. But today almost all programming languages are object-oriented languages and the object-oriented model of data structures are widely implemented in modern programs with those languages. Therefore a potential contradiction exists between the relational model of databases and the object-oriented model of programming in our real world today. Although some new components were added to the ADO.NET 2.0 to solve this contradiction, this does not give a full solution for it.
The latest version of ADO.NET is 4.3, but one of the key issues is closely related to those present in ADO.NET 3.5. A revolutionary solution of this problem was created with the release of ADO.NET 3.5 on the .NET Framework 3. The main contributions include the fact that some new components, ADO.NET 3.5 Entity Framework (ADO.NET 3 EF) and ADO.NET 3 Entity Data Model Tools, were added to ADO.NET 3.5. With these new components, the contradiction between the relational model of data in databases and the object-oriented programming projects can be fully resolved.
A primary goal of the ADO.NET 3.5 EF is to raise the level of abstraction available for data programming, simplifying the development of data-aware applications and enabling developers to write less code.
