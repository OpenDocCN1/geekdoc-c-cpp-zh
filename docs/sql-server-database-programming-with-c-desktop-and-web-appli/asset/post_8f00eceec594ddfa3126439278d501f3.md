You define functions or methods that are exposed by a WCF service by marking them with an OperationContractAttribute. In addition, you can serialize data by marking a composite type with a DataContractAttribute attribute. This enables data binding in a client.

After an interface and its methods are defined, they are encapsulated in a class that implements the interface. A single WCF service class can implement multiple services. A W service is exposed for consumption through what is known as an endpoint. The endpoint provides the only way to communicate with the service; you cannot access the service through a direct reference as you would with other classes.

An endpoint consists of an address, a binding, and a contract. The address defines where the service is located; this could be a URL, an FTP address, or a network path. A binding defines the way that you communicate with the service. WCF bindings provide a versatile mechanism for specifying a protocol such as HTTP or FTP, a security mechanism such as Windows Authentication or user names and passwords, and much more. A contract includes the operations that are exposed by the WCF service.

Multiple endpoints can be exposed for a single WCF service. This enables different clients to communicate with the same service in different ways. For example, a banking service might provide one endpoint for employees and another for external customers, using a different address, binding, and contract.

## 9.2.3.4 WCF Clients

A WCF client consists of a proxy that enables an application to communicate with a WCF service, and an endpoint that matches an endpoint for the service. The proxy is generated on the client by the service. The app.config file includes information about the types and methods that are exposed by the service. For services that expose multiple endpoints, the client can select the one that fits its needs, to communicate over HTTP and use Windows Authentication.

After a WCF client has been created, use the reference in your code just as you could for any other object. For example, call the GetData() method in Figure 9.2, you would write the codes shown in Figure 9.3.

## 9.2.3.6 WCF Visual Studio Templates

Visual Studio provides a set of WCF templates to help developers to build Web services and applications. In fact, WCF Studio templates are predefined and project items you can use in Visual Studio to quickly build WCF services and surrounding applications.
WCF Studio templates provide a basic class structure for service development. Specifically, these templates provide the basic definitions for service contract, data contract, service implementation, and configuration. You can use these templates to create a simple service with minimal code interaction, and well as a building block for more advanced services.
Two of the most popular templates are WCF Service Application template and WCF Service Library template.

When you create new Visual C# project using the WCF Web ServiceApplication template, the project includes the three major features:

- 1) Contract file (IService1.cs): The contract service is an interface that has WCF service attributes. This file provides a definition of a simple service to show you how to define your services, and includes parameter-based operations and a simple data contract sample. The default file is displayed in the code editor after creating a WCF service template.
- 2) Services file (Service1.svc): This file is an implementation for the class IService1 interface, and it implements the contract defined in the service contract.
- 3) Configuration file (Web.config): The configuration file provides the basic elements of a WCF service model with a secure HTTP binding. It also includes an endpoint for the service and metadata exchange.

The template automatically creates a Web Site that will be deployed to a virtual directory and hosts a service in it.

## 9.2.3.6.2 WCF Service Library Project Template

When you create a new C#.NET project using the WCF Service Library template, the new project automatically includes the following three files:

- 1) Service contract file (IService1.cs).
- 2) Service implementation file (Service1.sv).
- 3) Application configuration file (App.config).

## 9.2.5 PROCEDURES TO BUILD AN ASP.NET WEB SERVICE

The advantages of using the WCF templates to build our Web services are obvious; for instance, the protocols of the interface and contract have been predefined. However you must follow up the protocols to your files which could operations and methods. An easy way to do is to directly add our Web service with our operations in our ways. In the following sections, we will not use the protocols provided by WCF and directly create our Web services and place them into an ASP.NET Web services *.asm file.

Web service basically composed of a set of Web methods that can be called by the computer programs in the class. To build those methods, one generally needs to perform the following steps:

- 1) Create a new WCF Service project.
- 2) Add a new ASP.NET Web Service project.
- 3) Create a base class to handle the error checking to protect our real class.
- 4) Create our real Web service class to hold all Web methods and codes to respond to requests.
- 5) Add all Web methods into our Web service class.
- 6) Develop the details code for those Web methods to perform the Web services.
