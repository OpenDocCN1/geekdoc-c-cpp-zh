The first property, ParameterName, contains the name of the selected parameter. The second property, Value, is the value of the selected parameter and it is an object. The third property, DbType, is used to define the type of the selected parameter.

All parameters in the Parameter object must have a data type and you can indicate a data type for a selected parameter by specifying the DbType. ADO.NET and ADO.NET Data Provider have different definitions for the data types they provided. The DbType is the data type used by ADO.NET, but ADO.NET Data Provider has four other popular data types and each is associated with a Data Provider. 3.9 lists these data types as well as the associated Data Providers.

In this book, we will use the data types defined in the ADO.NET Data Provider since all parameters discussed in this section are related to the Data Provider. The default data type for the DbType property is String.

## 3.4.3.3 Parameter Mapping

When you add a Parameter object to the Parameters collection of a Command object by attaching Parameter object to the Parameters property of the Command, the Command object needs to know the relationship between added parameter and the parameters you use in your SQL query string using a SELECT statement. In other words, the Command object needs to identify which parameter used should be mapped to this added parameter. Different parameter mappings are used for different Data Providers. 3.10 lists these mappings.

Both OLE and ODB Data Providers use a so-called Positional Parameter Mapping, which means the relationship between the parameters defined in SQL statement and the added parameters into a Parameters collection is one-to-one in the order. In other words, the order in which the parameters appear in an SQL statement and the order in which the parameters are added to the Parameters collection should be identical. The Positional Parameter Mapping is indicated with a question mark '?'.

For example, the following SQL statement is used for OLE DB Data Provider as a query string:

```
SELECT user_name, pass_word FROM Login WHERE (user_name=?) AND (pass_word=?)
```

The user_name and pass_word are mapped to two columns in the login data table. Two dynamic parameters are represented by two question marks '?' in this SQL statement.

## Introduction to ADO.NET

To add a Parameter to the Parameters collection of a Command object accCommand, you need to use the Add() method as below:

```
accCommand.Parameters.Add("user_name", OleDbType.Char).Value =
txtUserName.Text;
accCommand.Parameters.Add("pass_word", OleDbType.Char, 8).Value =
txtPassWord.Text;
```

You must be careful with the order in which you add these parameters, user_name and pass_word, and make sure that the order is identical to the order in which those two dynamic parameters appear in the above SQL statement.

Both Server and Oracle Data Provider use the Named Parameter Mapping, which means that each parameter, either defined in an SQL statement or added into a Parameters collection, is identified by the name. In other words, the name of the parameter in an SQL statement or a stored procedure must be identical with the name of the parameter you added to a Parameters collection. For example, the following SQL statement is used for a SQL Server Data Provider on a query:

```
SELECT user_name, pass_word FROM LOGIN WHERE user_name LIKE @Param1
AND (pass_word LIKE @Param2)
```

The user_name and pass_word are mapped to two columns in the Log data table. Compared with the above SQL statement, two dynamic parameters are represented by no names of the dynamic parameters @Param1 and @Param2 in the SQL statement. The operator is replaced by the keyword LIKE for these two parameters. This is required by the SQL Server Data Provider.

## 3.4.3.4 Methods of the ParameterCollection Class

Each ParameterClass has more than ten methods, but only two of them are often utilized in the data-driven applications, which are the Add() and AddWithValue() methods. Each Parameter object must be added to the Parameters collection of a Command before you execute that Command to perform any query or data operation.

```
SqlParameter paramUserName = new SqlParameter();
SqlParameter paramPassWord = new SqlParameter();

paramUserName.ParameterName = "@Param1"; paramUserName.Value = txtUserName.Text;
paramPassWord.ParameterName = "@Param2"; paramPassWord.Value = txtPassWord.Text;

As we mentioned in the last, you do not need to worry about the order in which you added the parameter into the Parameter object if you are using a Named Parameter Mapping Data Provider such as an SQL Server or an Oracle. However, you must pay attention to the order in which you added the parameter to the Parameter object if you are using a Positioning Mapping Data Provider such as an DB or ODBC.

To add Parameter objects to a Parameters collection of a Command, two popular ways are generally adopted, Add() method and AddValue().
The Add() method is an overloaded method and it has five protocols, but only two of them are widely used. The protocols of these two methods are shown below:

```
ParameterCollection.Add(SqlParameter value);
ParameterCollection.Add(string parameterName, Object value);
```

The first method needs a Parameter object as the argument, and the Parameter object should have been initialized before you call this Add() to add it into the collection if you
The second method contains two arguments. The first is a String that contains the ParameterName and the second is an object that contains the value of that parameter.
The AddValue() method is similar to the second Add() method with the following protocol:

```
ParameterCollection.AddWithValue(string parameterName, Object value);
```

One example of these used to add Parameter objects into a Parameters collection is shown in Figure 3.12. The top section is used to create and initialize the Parameter objects, which we have discussed in the previous sections.

The second way to do this is to use the AddValue() method to add these two Parameter objects, which is similar to the second protocol of the Add() method.

> The Parameters in the Command class is a collection of a set of Parameter objects. You need to create and initialize a Parameter object, and then you can add Parameter object to the Parameters collection. In this way, you can assign to a Command object.

```
SqlParameter userName = new SqlParameter();

SqlCommand.Parameters.AddWithValue("@Param2", txtPassWord.Text);
