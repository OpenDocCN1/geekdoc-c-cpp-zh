## Part II Query with Runtime Objects

In contrast to the data-driven application, SelectWizard Project, we developed in Part I, in which a number of tools and wizards were provided by Visual Studio, such as DataSet, BindingSource, BindingNavigator and TableAdapter, are utilized to help readers develop data-driven applications easily and conveniently, the sample projects developed in this part have nothing to do with those tools and wizards. This means we created ADO.NET objects by directly writing C# codes. All objects are created during the period of runtime.

The shortcoming of using Visual Studio tools and wizards to create connections is that the auto-generated connections are linked to wizards and are embedded into the programs, and once connection information in the programs is compiled, it cannot be modified. In other words, your programs cannot be distributed and run in other platforms.

Compared with design tools and wizards, the advantages of using the runtime objects to make data operations easier are:
1. It provides programmers with more flexibility in creating and implementing connection objects and data operation objects related to ADO.NET.
2. It allows readers to use different methods to access and manipulate data from the data source and the database.

But anything has both good and bad, and this is also the case here. The flexibility also brings some complexity. For example, you have to create and use different providers and different commands to access the different databases using the different codes. Unlike the project developed in the last part, which you can use tools and wizards to select any data source you want and proceed the same coding for the different data sources, in this part you must specify the data provider and command type based on your real data source to access the data in your project. The good news is that LINQ technique released by Microsoft provides an easier way to access different sources. Before we start to develop our projects, a detailed understanding of the connection and data operation classes is very important, and those classes are directly related to ADO.NET. Although some discussions have been provided in Chapter 3, we will make a more detailed discussion for this topic in this section in order to provide readers with a clear picture of this issue.
