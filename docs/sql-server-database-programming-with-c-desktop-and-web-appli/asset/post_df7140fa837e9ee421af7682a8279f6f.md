## 4.8.4.4 Using XPath with XSLT in LINQ to XML

LINQ to XML supports a set of "bridge classes" to allow it to work with existing capabilities in the System namespace, including XPath and XSLT. A point to be noticed is that System.Xml provides the 1.0 version of these specifications in "Oras."

Extension methods supporting XPath are enabled by referencing the System.Xml.XPath namespace by adding this namespace: using System.Xml.XPath; in the namespace declaration section on the code window of each project.

This brings into scope Navigator overloads to create Navigator objects, XPathEvaluate overloads to evaluate XPath expression, and XPathSelectElement overloads that work like SingleNode and XPathSelectNodes in the System.Xml API. It is necessary to pass in a Resolver object, just with DOM. For example, to display all elements with the name "phone", the following codes can be developed:

```csharp
foreach (var phone in faculties.XPathSelectElements("phone"))
    Console.WriteLine(phone);
```

Likewise, Xsl is enabled by referencing the System.Xml namespace by typing: using System.Xml namespace declaration on the code window of each project. This allows you to create Navigator using the XDocument method and pass it to Transform().

### 4.8.4.5.2 Reading XML and Updating a Database

You can also read XML and put information into a database. For this example, assume that you are getting a set of faculty members in XML format. For simplicity the update records contain only the changes. First let's create a sample XML, which is shown in Figure 4.59. To accomplish this update, you query for each element and call the database to update the corresponding column with the number. A piece of sample code to fulfill this functionality is in Figure 4.60.

```csharp
Element Faculties = new XElement("Elements",
from f in db.Faculties
where f.faculty_id == ""
select new Element("Faculty",
new XAttribute("facultyName", f.name),
new XElement("Office", f.office),
new XElement("Title", f.title),
new XElement("Phone", f.phone),
new XElement("Email", f.email)));
Console.WriteLine(Faculties);
```

**FIGURE 4.58** A sample code to perform the query using XML.

```csharp
foreach (var phone in faculties.Elements("faculty"))
{
  Element faculty = db.Faculties.First(f=>f.faculty_id == (string)f.Element("faculty_id"));
  faculty.Phone = (string)f.Element("phone");
}
db.SubmitChanges();
```

## 4.9 C# 3.0 LANGUAGE ENHANCEMENT FOR LINQ

With comparison to C# 2.0, significant enhancements have been added to C# 3.0, to support data querying in a type-safe way; these are mainly developed to support the Language-Integrated Query (LINQ).

C# 3.0 introduces several language extensions that build on C# 2.0 to support the creation and use of higher-order, functional-style class libraries. The extensions enable construction of compositional APIs with equal expressive power of query languages in relational databases and XML.

In addition to general LINQ topics, special improvements are made for C# 3.0. The main components of these improvements include:

- Lambda Expressions
- Extension Methods
- Implicitly Typed Local Variables
- Query Expressions

Let's have a detailed discussion for these topics one by one.

### 4.9.1 Lambda Expressions

Lambda expressions are a feature that is similar in many ways to anonymous methods. If lambda expressions had been developed and implemented into the language first, there would have no need for anonymous methods. The basic idea of using lambda expressions is that you can treat code as data. In the early versions of C#, such as C# 1.0, it is very common to pass strings, reference types, and so to methods that the methods can work on those values. Anonymous methods and lambda expressions extend the range of values to include code blocks. This concept is common in functional programming.

The syntax of lambda expression (=>) followed by an expression, a comma-delimited list of parameters with a statement. For more complicated lambda expressions, a statement block can be followed by the lambda operator. A simple example of lambda expression used in C# looks like:

```csharp
x => y
```

where x on the left side of the lambda operator is the input parameter and y on the right side of the lambda operator is the output parameter. The data type of both input and the output parameters should be explicitly indicated by the delegate. Therefore, the lambda expressions are closely related to the delegate. This lambda expression can be read as input and output. The syntax of this kind simple lambda expressions can be written as:

```csharp
(param1, param2, ...) => output
```

A parenthesis should be used to cover all input parameters. For more complicated lambda expressions, a statement block should be adopted. An example of this kind of syntax is shown below:

```csharp
(x, y) => { if (x > y) return x; else return y; }
```
