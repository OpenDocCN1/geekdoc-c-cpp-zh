# 5.15.3 Query Data Using the General Runtime Objects for the Login Form

Open the LogLoginForm window from the Solution explorer window by clicking the View Code to begin our coding process.
The first thing we need is to add to the namespace SqlClient that contains all components related to the SQL Server Data Provider since we need to access the SQL Server databases in this project. Type the following code line in the namespace declaration section, which is in the top part, of this code:

```
using System.Data.SqlClient;
```

Since the connection is the first thing we need to do before we can make any data query, therefore need to do the connection join in the constructor of this form object, to allow the connection to be made first as the project runs.
Open the Code window and find the constructor of this form, enter the following codes that are shown in Figure 5.69 into this part.
Let's have a closer look at this piece of code to see how it works.

+   A. The namespace for the SQL Server Data Provider System.Data.SqlClient is added into this for us to use all data components in that namespace.
B. A global SQL connection is declared here. The access mode for this object is Public, which means any object or method defined in this project can use this connection to access the SQL Server database CSE_DEPT.
C. A SqlConnection is created here and it is used to connect our project with the SQL Server database selected. Please note that a Windows Authentication Mode is used for this database connection, the connection string containing the IntegratedSecurity=True parameter is used to indicate that connection mode. This current connection string is commented-out hence we prefer to use the next connection in which a SQL Server Authentication Mode is used.
D. In this connection, a SQL Authentication Mode is adopted and both User ID and Password are added into this string at the end. The advantage of using this connection is that more parameters are included in this connection and make the connection more secured and safe. Refer to Appendix D on the CRC ftp site, exactly as in D.2, to get more details about this connection string.
E A new instance of the SqlConnection is created and initialized with the connection string as the argument.
 A try-catch block is utilized to catch any exception caused by opening this connection. The advantage of using this kind of strategy is to avoid unnecessary system process and simplify this debug procedure. Multiple catch blocks are utilized to track and find any possible exception or error, including SqlException and InvalidOperationException.
G This step is used to confirm whether our database connection is successful or not. If not, an error message is displayed and the project is exited.

After a database connection is successful, we need to use this connection to access the SQL Server database to perform our data query job.
