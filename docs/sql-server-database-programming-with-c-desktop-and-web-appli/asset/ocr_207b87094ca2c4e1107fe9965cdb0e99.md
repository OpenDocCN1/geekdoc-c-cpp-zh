# 9.2.3.1 What is the WCF?

The Windows Communication Foundation (WCF) is a framework for building service-oriented applications. Using WCF, you can send data as asynchronous messages from one service endpoint to another. A service endpoint can be part of a continuously available service hosted by IIS, or be hosted in an application. An endpoint can be a client of a service that requests data from a service endpoint.

WCF is a unified framework for creating secure, reliable, transacted, and interoperable applications. In earlier versions of Visual Studio, several technologies could be used for communicating between applications.

If you wanted to share information in a way that it could be accessed from any platform, you would use a Web service (also known as ASMX Web service). If you wanted to move data between a client and server that are running on the Windows operating system, you would use .NET Remoting. If you wanted transferred communications, you would use Enterprise Services (DCOM), and if you wanted to create a model you would use Message Queuing (also known as MSMQ).

WCF brings together the functionality of all those technologies under a unified programming model. This simplifies the development of distributed applications.
 fact, WCF is implemented as a set of classes on the top of the .NET Framework's Common Language Runtime (CLR). This allows .NET developers to build service-oriented applications easily. In addition, WCF allows the creation of clients that access services in a mutual way, which means that the client and the service can run in the same way as the Windows process. WCF doesn't define a required host. When they run, clients and services can interact via SOAP, or a WCF-specific binary protocol, and in others.

# 9.2.3.2 WCF Data Services

WCF Data Services, formerly known as ADO.NET Data Services, is a component of the .NET Framework that enables you to create services using the Open Data Protocol (OData) to consume data from the Web or internet using the semantics of relational state transfers. OData exposes resources that are addressable by URIs. Data is accessed and changed by using standard HTTP verbs of GET, PUT, POST, and DELETE. OData uses the entity-relationship conventions of the Entity Data Model to expose resources as sets of entities that are related by associations.

WCF Data Services uses the OData protocol for fetching and updating resources. In this way, you can access these services from any client that supports OData. OData enables you to request and write data using non-XML formats: Atom, a set of standards for exchanging and updating data as XML, and JavaScript Object Notation (JSON), a text-based data format used extensively in AJAX.

Data originates from various sources using OData feeds. Visual Studio makes it easier for you to create an OData-based service using an ADO.NET Framework data model. You can also create OData feeds based on common language runtime (CLR) classes and either late-bound or un-typed data.

WCF Data Services also includes a set of client libraries, for general .NET Framework applications and another specifically for Silverlight-based applications.

These client libraries provide an object-based programming model when you access OData from environments such as the .NET Framework and Silverlight.
