Open the RTOUpdateDelete Project and the Course Form, double-click on the Update button to open its Click. Enter the codes shown in Figure 7.25 into this method. Let's have a look at this piece of code to see how it works.

+   A. The query string is defined first at the beginning of this method. All data columns in the Table table, the course_id, are input parameters. The dynamic parameter @cid represents the original course_id, which is a primary key in the Table and will not be updated.
B. All components and local variables are declared here such as the Command object and integer variable intUpdate. The latter is used to hold the returned status of the calling of the ExecuteNonQuery() method.
C. The Command object is initialized and using the Connection object and the Parameter object.
D. A user-defined method UpdateParameters whose codes are shown in H is called to adding all parameters into the Command's properties. The passing mode used for the argument is passing-by-reference, which means a valid starting address of that Command object is passed into the method, and any modification to this Command object is present and it can be returned to the calling method.
E. The ExecuteNonQuery() method of the Command class is executed to update a course in the Table. The running result of this method is returned and stored in the local variable intUpdate.
F. The Command object is released after this data updating action.
G. The returned value of calling the ExecuteNonQuery() method is equal to the number of rows that have been updated in the Table. A zero means that no row has been updated, an error message is displayed to indicate it if this situation is really occured.
