But wait a moment. Before we can continue to develop the Visual# project to call these two stored procedures, is there any way to check whether these two stored procedures work or not? The answer is yes: The Server Explorer in Visual Studio.NET allows us to debug and test custom stored procedures as shown in Figure 5.92a.

Now go to the Server Explorer window, expand our database connection folder and our St Procedures folder. Select one of our stored procedures, and then right-click to select stored procedure. A popup menu will be displayed, which is shown in Figure 5.92a. The functionality for each item is explained below:

+   1 **Add New Stored Procedure**: Create a new stored procedure.
2 **Open**: Open an existing stored procedure to allow it to be edited or modified. The name of the modified stored procedure will be prefixed by **ALTER**.
3 **Execute**: Execute a stored procedure. One can debug and test a developed stored procedure using this in the Server Explorer environment to make sure that the developed stored procedure works fine.
4 **Copy**: Copy a stored procedure.
5 **Delete**: Remove the stored procedure.
6 **Refresh**: Update the content of the stored procedure.
7 **Properties**: Show all properties of the stored procedure.

Now let's run and test our developed stored procedures. Right-click our first stored procedure StudentInfo and select the EXECUTE item from the popup menu.
