By default, all columns in the Login table are selected in the top graphical panel. You can decide which columns you want to query by checking the checkbox in front of each column. In this application, we prefer to select all columns from the top graphical panel. The selected columns will be displayed in the second graphical panel, which is also shown in Figure 5.37.

Since we try to build a dynamic SQL query for the Login table, the login process is as follows: When the project runs, the **username** and **password** are entered by the user, and two items will be embedded into an **SQL SELECT** statement that checks if the username and password entered by the user can find the Login table. If a match is found, the recorded record will be read from the BindingSource to the TableAdapter, and furthermore reflected on the bound textcontrols on the Visual # 2022 Login form.

The problem is that when we build this, we do not know the values of username and password, which will be entered by the user as the project runs. In this order, two parameters are dynamic parameters. To build a dynamic query with two dynamic parameters, we need to use two question marks “?” to temporarily replace those two parameters in the **SELECT statement**.

We do this by typing a query in the **Filter** column for **user_name** and **pass_word** rows in the second graphical pane, which is shown in Figure 5.37. The query marks will become two dynamic parameters after you press the **Enter** key from the keyboard when you finish typing two question marks. This is a typical representation method for the dynamic parameters used in the SQL Server database.

Now let's go to the text pane and you can find that a **WHERE** clause is attached at the end of the SELECT statement, which is shown in Figure 5.37.

```
WHERE (user_name = @Param1) AND (pass_word = @Param2)
```
