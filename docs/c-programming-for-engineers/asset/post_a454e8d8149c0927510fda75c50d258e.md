### 2.2.5 Test and Debug

In testing and debugging a program, several steps are involved:

- **Compilation:** The compiler translates source code into object code, detecting syntax errors during this process.
- **Linking:** The linker combines object files and libraries, identifying linking errors.
- **Execution:** The compiled program is executed with test data to observe its behavior. Logical errors are detected at this stage.
- **Debugging:** Errors encountered during compilation, linking, or execution are analyzed and fixed.

The term "bug" commonly refers to a logical error in code. Resolving logical errors can be a time-consuming process because the problem may not immediately become apparent, if the code appears to be error-free. Debugging means detecting, analyzing, and resolving problems in a computer program. Although a bug may refer to a logical error, debugging includes identifying and correcting any type of error or issue in the code, logical or not. Debugging tools can help developers identify unused variables, unreachable code, or potential memory leaks.

When testing a computer program, specific data inputs are chosen to make the testing process efficient. For example, to test a program that gives kids to 12 or under, we can use age inputs of 11, 12, and 13 instead of using all numbers from 0 to 99. Choosing the best inputs for testing is a complex topic that we won't cover in this semester!

In summary, debugging in an iterative process of identifying, analyzing, and fixing errors. The process might uncover additional errors after fixing initial ones.

### 2.2.6 Document the Program

The final step in completing the program is to create documentation. The documentation consists of technical documentation for programmers and user documentation for non-technical users.

Technical documentation includes:

- **Statement of the problem:** Clearly defining the problem the program aims to solve.
- **Algorithm:** Describing the step-by-step procedure to solve the problem.
- **Program listing:** Providing the code of the program.
- **Test data and results:** Including sample inputs and the corresponding outputs produced by the program.

User documentation includes:

- **Program usage:** Explaining how to load the program onto the computer.
- **Program features:** Describing the various functionalities and how to use them.
- **Handling unusual situations:** Providing instructions on how to handle unexpected scenarios that may occur while using the program.

Both technical and user documentation are essential for different purposes. Technical documentation helps programmers understand and modify the program, while user documentation enables non-technical users to effectively use the program without requiring in-depth knowledge of its internal workings.

### 2.3.1 Hierarchy Charts

Hierarchy charts, also known as structure charts, provide a simplified overview of a software system. They break down complex systems into manageable parts. They are commonly used in structured programming to organize modules in a tree-like structure.

These charts use boxes to represent different modules and lines to depict how these modules connect and interact with each other. This visual representation aids in:

- Understanding the overall structure of the system quickly.
- Identifying dependencies between various modules.
- Improving communication by offering a shared understanding of the system's organization.

While hierarchy charts are not directly utilized during code writing, they serve as valuable tools for programmers to plan and visualize complex software projects.
Moreover, hierarchy charts (shown in Fig. 2.2) find applications beyond software development, including organizational management (depicting hierarchical structures of organizations) and systems engineering (illustrating complex system architectures), among others.

### 2.3.2 Pseudocode

Pseudocode is a simplified, easy-to-understand language that represents a program's logic, without specific programming syntax. Programmers use it to plan, design, and explain how algorithms work, focusing on the ideas and steps without worrying about exact

```text
START
  PRINT "Enter the length: "
  READ length
  PRINT "Enter the width: "

  area = 0.5 * length * width
  PRINT "area of triangle is ", area
```

Pseudocode tips:

- Write only one statement per line
- Capitalize initial keyword: START, END, INPUT, READ, PRINT, OUTPUT, WHILE, IF, ELSE
- Indent to show hierarchy:
  - Sequence: statements one after another
  - Selection: indent statements inside selection
  - Repetition: indent statements inside repetition
- End multi-line structures:
  - IF ELSE structures always end with ENDIF
  - FOR structures always end with ENDFOR
  - WHILE structures always end with ENDWHILE
  - DO structures always end with END

The pseudocode provides a clear and concise representation of logic without being tied to any programming language. It serves as a blueprint for writing actual code.
