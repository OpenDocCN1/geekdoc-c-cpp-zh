The code is **refined** through an iterative process of:

+   - Testing for logic/runtime errors by compiling and running
- Debugging any errors encountered
- Optimizing efficiency and readability

This process continues until the code fully reflects the design accurately and is free of bugs.
Fig. 2.10 shows how the initial or draft version of a C program is generated from the flow chart. The program is still unable to run as it is not complete yet. If this program is compiled, it will have at least two undefined symbol errors:

+   - Undeclared variables: This occurs because the variables, width and area have not been declared yet. Adding the variable declarations resolves this error.
- Unknown symbols: This happens because the compiler does not find to print(). Adding the directive #include <stdio.h> resolves this by providing the compiler with information about this symbol.

Additionally, **prompts** can be added to inform users about the status of the program during execution and guide them when to input values.
