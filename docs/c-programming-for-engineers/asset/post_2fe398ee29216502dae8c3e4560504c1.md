## 7.7 Ternary Operator

The ternary operator, also called the conditional operator, is a concise way to write conditional expressions.
The syntax is:

```c
condition ? value_if_true : value_if_false
```

The condition is evaluated first. If it's true, the expression returns value_if_true; otherwise, it returns value_if_false.
It's often used for simple assignments or expressions where an if statement would be too verbose.

### Snippet: Smaller of Two Numbers

```c
int num1, num2, min;

printf("Enter two numbers: ");
scanf("%d %d", &num1, &num2);

min = (num1 < num2) ? num1 : num2;
printf("Minimum assigns is: %d\n", min);
```

This expression assigns num1 to min if num1 is less than num2; otherwise, the value of num2 is assigned to min.

### Snippet: Even or Odd

```c
int number;

printf("Enter a number: ");
scanf("%d", &number);
```

The selection is generated using a bitwise AND function. Any odd number has its least significant bit equal to 1. ANDing a number with 1 results in either 0 (even) or 1 (odd) result.

### Snippet: Grade Assignment

```c
int marks;

printf("Enter marks: ");
scanf("%d", &marks);

printf("Grade is %c\n", (marks > 79) ? 'A' : 
(marks > 64) ? 'B' : 
(marks > 49) ? 'C' : 
(marks > 34) ? 'D' : 'F');
```

Here, we have an if-else ladder compressed into a nested ternary operated.

The ternary operator in C is handy for compact if/else expressions on a single line. It's used when the condition and both expressions are compatible types. It's great for simplifying code, but don't rely on it too much, especially for complex logic, as it can make the code harder to read.

## 7.8 Writing Efficient Conditionals

Efficient and readable code relies on effective usage of conditional expressions.
However, there are some common pitfalls to be mindful of.

### 7.8.1 Any Non-Zero is True

In C, conditions are evaluated based on zero and non-zero values. Any non-zero value
is considered true. This knowledge can help you write concise code.
Consider the following valid expressions:

```c
if (a > 3) ... // ok, noting special
if (a) ... // execute if a is any non-zero value
if (a != 0) ... // same as above, typical noobb style
if (1) ... // redundant, always execute
if (0) ... // useless, never execute
if (3 | 6) ... // redundant, always execute
if (a = 0) ... // checks if a is 0
if (!a) ... // exactly the same as above
if (a = 0) ... // typo, some compilers convert to a == 0
if (a == 0) ... // a safe way to check if a is 0
```

To prevent unexpected assignments, never put an assignment where a conditional
statement is expected.

### 7.8.2 Testing Bits

In embedded programming, we often have to testing the value of a bit or group bits.

```c
if (a & 1) ... // execute if bit 0 is set
if (a & (1<<10)) ... // execute if bit 4 is set
if (a & (1<<4)) ... // elegant equivalent to above
if (a & 5) == 5 ... // execute if bits 0 and 2 are both set
if (a & 7) == 5 ... // execute if bits 0-2 contains 5
if (-a & 1) ... // execute if bit 0 is cleared
if (-a & (1<<3)) ... // execute if bit 3 is cleared
if (!(a & (3)) ... // execute if a is divisible by 4 (bit 0-1 cleared)
```

### 7.8.3 Lazy Operators

Lazy evaluation – also known as short-circuit evaluation – means that expressions are
only evaluated when absolutely necessary. In logical operations:

- OR: Stops evaluation when any condition is found to be TRUE
- AND: Stops evaluation when any condition is found to be FALSE
