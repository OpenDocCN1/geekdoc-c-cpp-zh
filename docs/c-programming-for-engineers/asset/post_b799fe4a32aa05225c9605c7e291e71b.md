## 13.5 Bit Fields

Bit fields in C allow you to specify the number of bits used by each member of a structure, enabling to pack multiple fields into a single byte or word.

When defining a structure, you declare the size in bits of each member using the unsigned int data type. For example:

```c
struct {
  unsigned int ready:1;
  unsigned int error_code:9;
  unsigned int command:6;
}
```

Here, ready uses 1 bit, error_code uses 9 bits, and command uses 6 bits.
C packs the bit fields as compactly as possible, aligning storage usage with the integer word length of the computer. For instance, on a 32-bit computer, bit fields from 1 to 32 bits use one word, while bit fields from 33 to 64 bits use two words, and so forth.

Using bit fields optimizes memory usage and facilitates working with hardware data layouts, which is crucial for low-memory or hardware interfacing applications.

```c
struct ioreg {
  unsigned int ready:1;
  unsigned int error_code:9;
  unsigned int command:6;
};
```

However, there are drawbacks to using bit fields in C:

- *Portability*: Bit fields are not always portable across different compiler implementations may interpret and lay out bit fields differently.
- *Memory Usage*: Bit fields may not always result in the expected memory usage. Padding may be added between fields, increasing the total size of the structure and potentially losing space-saving benefits.
- *Efficiency*: Bit fields are generally less efficient than regular structures, as individual fields must be extracted and reconstructed, leading to potentially slower performance.

## 13.6 Data Structures

Data structures refers to specialized arrangements used to organize and store data in a computer's memory. The primary purposes of data structures is to optimize the performance of algorithms. Data structures also serve various essential functions, facilitating data organization, enabling efficient storage and retrieval, and supporting effective data manipulation.

Data structures can be broadly categorized into two types: linear and non-linear. Linear data structures organize data elements sequentially, one after the other. Elements in linear data structures are accessed in a sequential order, making traversal straightforward. Examples of linear data structures include arrays, linked lists, stacks, and queues. Non-linear data structures organize data elements in a hierarchical or interconnected manner, where elements may have multiple predecessors and successors. Elements in non-linear data structures can be accessed in various paths, not limited to a single sequence. Examples of non-linear data structures include trees and graphs.

- *Arrays*: Store elements of the same type in a sequence, accessible via indices. They offer a straightforward way to handle data efficiently. Arrays have been covered in an earlier chapter.
- *Stacks*: Linear structures operating on the Last In, First Out (LIFO) principle. They support two main operations: push (adding an element to the top) and pop (removing the top element). Stacks are useful in algorithms like recursion, expression evaluation, and backtracking.

- *Queues*: Linear structures operating on the First In, First Out (FIFO) principle. They have two main operations: enqueue (adding an element to the rear) and dequeue (removing the front element).
- *Trees*: Hierarchical structures where nodes are organized in a tree-like fashion. Nodes have parents and children.
- *Graphs*: Non-linear structures consisting of nodes (vertices) connected by edges representing relationships.
