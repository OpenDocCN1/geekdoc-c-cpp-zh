# 7.9. Pitfalls and Best Practices

```
#include <stdio.h>
void main(void)
{
    int i = 5, j = 2, k;

    if ( i == 3 && j++)
        k = 1;
    else
        k = 2;
    printf("i = %d, j = %d, k = %d\n", i, j, k);
}
```

In the if construct above, the condition i == 3 && j++ is evaluated. Because i == 3 is false, the expression becomes false, and the j++ part is not executed. Therefore, j remains 2. To prevent such issues, avoid using the ++ or -- operators within logical expressions.

# 7.9 Pitfalls and Best Practices

Watch out for these mistakes when using C decision-making:

+   **Equality confusion:** New programmers often mistakenly use the assignment operator (= instead of the equality operator "=\="). This can lead to unexpected outcomes. Consider this code snippet:

if ( a = b )

Accidental assignment can occur in some compilers, where the value of b might be assigned to before the comparison. For comparisons involving constants, this can be prevented by writing the constant first: if (6 == a).
**Wrong Conditions:** Double-check your conditions to ensure they represent the desired logic.
**Boundary conditions:** Test conditions at the edges of expected ranges.
**Misuse of Logical Operators:** Use the right operators (e.g., && for AND, || for OR) and understand their behavior.
**Incomplete Compound Conditions:** Make sure all necessary conditions are combined correctly using logical operators.
**Confusing if-else:** Break down complex logic with multiple conditions and nesting. Add comments to improve clarity.
**Ternary Overuse:** While handy for simple decisions, overuse can make code harder to read. Prioritize readability

By avoiding these pitfalls and being careful during development and testing, you can write more reliable decision-making logic in your C programs.
