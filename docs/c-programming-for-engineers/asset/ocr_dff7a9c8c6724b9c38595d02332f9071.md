# 5.6 Arithmetic Challenges on Microcontrollers

```
printf("int8_t: %u\n", myUint8);
printf("uint16_t: %u\n", myUint16);
printf("uint32_t: %d\n", myUint32);
printf("uint64_t: %llu\n", myUint64);

return 0;

```

In this example, we declare variables of different fixed-size integer types. Then, we assign values to these variables and use the appropriate format specifiers %d, %u, and %lu in printf to correctly display the values. For the variable myUint8 of type uint8_t we assign it the value 255. We then increment its value and check the result. Since uint8_t is an unsigned char type, it can only represent non-negative values from 0 to 255. Adding 1 to 255 will result in overflow, as proven by the output. Fixed-size integers ensure predictable behavior and control over the size and range of integer values in your programs, but you still have to be aware of issues of data loss, division operation quirks, overflow, and other issues. While fixed-size integers are helpful in many cases, they are not always the best choice. If performance is a priority and the size of the integer is not important, standard integer types may be more efficient for the specific target machine.

# 5.6.2 Floating-Point Data Types and Operations

Personal computers typically have built-in hardware support for all floating-point data types, allowing the use of float or double. In fact, using double is recommended on PCs for math operations as it the default data type for the C math library. However, this level of floating-point support is not always available in low-cost microcontrollers. For example, the Cortex-M4F microcontroller has hardware support for float only. Attempting calculations based on double on this chip would require software emulation, resulting in significantly slower performance. In contrast, all 8-bit microcontrollers lack hardware support for floating-point altogether. Therefore, any computations involving floating-point on small microcontrollers must be rewritten to use integer types to prevent a significant slowdown.
