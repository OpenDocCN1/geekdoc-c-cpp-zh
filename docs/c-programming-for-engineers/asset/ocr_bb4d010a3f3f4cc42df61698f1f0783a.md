4. **Linking**: The linker takes one or more object files generated by the assembler and combines them with any necessary library files. It resolves references to external functions and symbols, performs address relocation, and generates an executable file. The executable file may have an extension like .exe on Windows or no extension on Unix/Linux.

On Windows, assembly code may have .ASM extension, object code .OBJ, static libraries .LIB, and dynamic libraries .DLL. Most compilers skip generating .i (preprocessed) and s (assembly) by default unless specifically requested by the programmer, so that you will commonly with source files, object files and executable files on your computer.

For the curious, the compiler itself goes through several steps:

+   **Lexical Analysis**: The compiler reads your code and breaks it down into smaller units tokens. Tokens can be things like keywords (e.g., "if" or "while"), variable names, numbers, or symbols.

+   **Syntax Analysis**: The compiler checks if the tokens from the previous step are arranged correctly according to the language grammar rules. It builds a tree-like structure called the syntax tree to represent the structure of your code.

+   **Semantic Analysis**: The compiler verifies the meaning of your code. It checks if you're using variables and functions correctly, and if the operations you're performing make sense. It also catches errors like a variable before it's defined.

+   **Code Generation**: The compiler translates the syntax tree into instructions that the computer can understand and execute. It generates machine code or a lower-level representation of your code.

+   **Code Optimization**: The compiler tries to improve the efficiency and performance of your code. It applies various techniques to make the generated code faster or use less memory.
