## 1.3.2 Categories of Programming Languages

Computer software is created through a set of instructions called a *program*. To provide precise instructions, *programming languages* are used, as natural languages like English are prone to ambiguity.

Let us begin by explaining the concept "abstraction." Abstraction is the process of simplifying complex things by focusing on the essential parts and hiding the intricate details. It is like driving a car without needing to know how the engine works. Instead, you only need to understand how to use the brakes, accelerator, and steering wheel. Abstraction in programming helps make code easier to read and understand by hiding unnecessary complexities. It allows developers to concentrate on the important aspects of the code without getting caught in the technical details.

Programming languages can be grouped into different levels of abstraction, with each level abstracting certain aspects of the underlying hardware.

- Machine language: The lowest level of programming, machine language directly communicates with the processor using binary code. Each instruction has a unique binary code, and the processor executes these instructions in sequence to perform specific tasks.
- Assembly language: Assembly language uses mnemonic codes instead of binary codes, making programming easier, although hardware knowledge is still required. Programs are translated into machine code by an *assembler*. Assembly language instructions have a one-to-one correspondence with machine code instructions, therefore the code length and execution speed are virtually identical to machine language.

- High-level languages (HLLs): HLLs are the most user-friendly programming languages, using high-level constructs and abstracting away specifics. HLLs are translated into machine code using compilers or interpreters. These languages were developed to abstract hardware complexities, focusing on improving programmer productivity and code readability.

Over time, programming languages continue to evolve to make software development easier and more efficient. New languages and frameworks have been created to address different programming needs and paradigms.

Programming languages can be broadly categorized into four paradigms or styles of programming:

- Procedural Paradigm: This approach breaks down problems into step-by-step procedures, like recipes. Each procedure handles a specific task, promoting code reusability and organization. Think of it organizing a large project into manageable subtasks. Examples include Basic, Fortran, Pascal, and C.
- Object-Oriented Paradigm: This paradigm organizes program as a collection of objects. Each object has its own data and behavior. This approach allows for building modular and adaptive systems. Examples include Smalltalk, Java, and C++.
- Functional Paradigm: This paradigm treats functions as the building blocks of programs. Functions are self-contained units that take inputs and produce outputs, similar to mathematical functions. Examples include Lisp, Scheme, Haskell, ML, and Erlang.
- Logic-Based Paradigm: This approach lets you express problems as facts and rules. The computer then uses logic to solve the problem. It is particularly useful for tasks involving symbolic reasoning and finding solutions that meet certain conditions. Prolog is a prominent example in this category.

Each paradigm offers unique strengths and weaknesses to fit different types of problem and applications.

Programming languages can also be differentiated into compiled and interpreted languages, with their advantages and disadvantages.

**Compiled languages**, such as C, C++, and Rust, go through a compilation process that converts source code into machine code specific to the target processor architecture. This produces a standalone executable file that can run independently. Compiled languages are ideal for high-performance applications given their efficiency, smaller code size, and independence from interpreters. However, they require a separate compilation step and are platform-dependent, which means they need to be recompiled for each target platform.

**Interpreted languages**, such as Python, Ruby, and JavaScript, translate source into machine code by line during runtime. An interpreter program reads, translates, and executes the code. Interpreted languages offer advantages such as portability, ease of use, and rapid development. However, they can be slower and require more resources to operate.

A newer approach is the use of Just-In-Time (JIT) compilation, used by languages such as Java, C#, and some Python and JavaScript implementations. JIT compilation creates a bytecode that is executed by a virtual machine. During execution, the machine analyzes and converts commonly used bytecode sections into machine language, improving performance. This method offers portability, the bytecode does not need to be recompiled on a different platform, and improved performance compared to traditional interpretation.

The choice between compiled and interpreted languages depends on the specific needs of the project, with each approach offering its unique benefits and trade-offs.
