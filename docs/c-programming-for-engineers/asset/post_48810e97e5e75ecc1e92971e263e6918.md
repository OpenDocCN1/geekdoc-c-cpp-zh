# Preprocessor

The C preprocessor is a macro processor that is used before the compilation of a C program. It is used to perform text substitution on the source code before it is compiled. The preprocessor is invoked by the compiler and runs as a separate phase before the compilation process.

# 14.1 Introduction

Preprocessing happens before the actual compilation of C programs. It interprets directives and macros to transform the source code into a modified version that is then passed on to the compiler. See Fig. 14.1.

![](img/33fb6b7acbb6df48a3c9564e97117da6_230_0.png)

Figure 14.1: C preprocessor dataflow

Key features of the C preprocessor include:

- **Macro definitions and substitutions**: Defined using #define, macros allow for code customization without changing the original program.
- **File inclusion**: Managed via #include, this feature includes header files with shared declarations.
- **Conditional compilation**: Enabled by #ifdef and #ifndef, it allows parts of the code to be compiled conditionally based on macro definitions. It is useful for platform-specific customization.
- **Line Control**: Using #line, developers can set line numbers and file attributes for debugging.
- **Error generation**: Triggered by #error, this directive generates error messages during processing.

The C preprocessor provides various directives that allow for code manipulation and optimization during the preprocessing phase. They are grouped as file inclusion, macro substitution, conditional compilation and miscellaneous directives. See Fig. 14.2.

# 14.2 File Inclusion

The #include directive is used to import header files in a C program, allowing for code reuse by incorporating external code files. It inserts the contents of a header file into

![](img/33fb6b7acbb6df48a3c9564e97117da6_231_0.png)

Figure 14.2: Preprocessor directives.

the source code, providing access to necessary declarations and definitions for proper compilation and execution.
Syntax:

```
#include <filename>
```

The <filename> syntax is used for system header files, which are typically located in the standard include directory.
Example:

```
#include <stdio.h>
```

Alternatively, the #include directive can also use quotes to include user-defined header files.
Syntax:

```
#include "filename.h"
```

The "filename.h" syntax is used for user-defined header files, which are typically located in the same directory as the source file.
Example:

```
#include "myheader.h"
```

The order of file inclusion can impact the compilation process as header files may depend on others. Therefore, it is important to include header files in the correct order to ensure proper compilation and avoid errors.
Here is an example of a C program that uses the #include directive:

# 14.3 Macro Substitution

```
#include <stdio.h>
#include "myheader.h"

int main() {
    printf("Hello, world!\n");
    my_function();
    return 0;
}
```

In this example, the stdio.h header file is included to provide access to the print function, and the myheader.h header file is included to provide access to the my_function function. The main function calls these functions to print a message and execute user-defined functionality.

# 14.3 Macro Substitution

Macros in C programming are defined using the #define directive and are used to create shorthand notations or reusable code snippets. They simplify code and improve readability by:

- Replacing repeated code: Define a complex expression or code block once and use its name throughout the program.
- Creating symbolic names: Give meaningful names to constants for better understanding.

Syntax:

```
#define NAME VALUE
```

The preprocessor substitutes the macro NAME with its defined VALUE during the compilation stage, before the actual code is processed.

# 14.3.1 How Macros Work

Macros in C can be defined in two primary forms: simple macros and function-like macros.

- **Simple Macros**: Simple macros are commonly used to give symbolic names to numeric constants. By convention, ALL CAPS are used to identify macro-defined constants.
- **Function-Like Macros**: Function-like macros look like function calls but lack return types and are expanded directly-in-place.

```
#define MAX_VALUE 100 // Defines a macro named MAX_VALUE with value 100
#define SQUARE(x) ((x) * (x)) // Squares the value of x
```

Example:

```
#include <stdio.h>

#define PI 3.14159
#define AREA(r) (PI * (r) * (r))

int main() {
    double radius = 5.0;
    double circle_area = AREA(radius);

    printf("Area of the circle: %.2f\n", circle_area);

    return 0;
}
```

In this example:

- PI is a simple macro for the constant value.
- AREA(r) is a function-like macro calculating the area of a circle.

# 14.3.2 Predefined Macros

C programming provides a set of predefined macros that offer useful information about the current program's context.

| Macro | Value |
| :--- | :--- |
| __FILE__ | A string containing the file name |
| __LINE__ | The line number |
| __DATE__ | The date of the compilation |
| __TIME__ | The time of the compilation |

```c
#include <stdio.h>

int main() {
    printf("File: %s\n", __FILE__);
    printf("Line: %d\n", __LINE__);
    printf("Date: %s\n", __DATE__);
    printf("Time: %s\n", __TIME__);
    return 0;
}
```

# 14.3.3 Side Effects and Pitfalls

Macros can have side effects, especially when arguments are evaluated multiple times. For example:

```c
#define SQUARE(x) (x * x)

int main() {
    int a = 5;
    printf("%d\n", SQUARE(a++)); // Output might be 25 or 36
    return 0;
}
```

To avoid this, use parentheses in the macro definition:

```c
#define SQUARE(x) ((x) * (x))
```

# 14.3.4 Weighing the Use of Macros

While macros offer benefits, they come with potential drawbacks.

Advantages:

- Reuse code: Define and reuse code snippets for common tasks.
- Readability: Simplify complex expressions or create symbolic names for constants.
- Customization: Adapt code for different environments.

Drawbacks:

- Safety Concerns: Lack of type checking can introduce errors.
- Unpredictable Behavior: Undefined evaluation order can lead to unexpected results.
- Debugging Challenges: Errors in macros can be difficult to debug due to the lack of debugging information.
- Not functions: Macros lack features like block structure, variable scope, and return values of functions.

Summary:

- Use macros cautiously due to the potential for errors.
- Consider alternatives like functions for complex logic or where type safety is crucial.

Choose the right tool for the job. While macros offer convenience, prioritize clarity, maintainability, and safety in your code.

# 14.4 Conditional Compilation

Conditional compilation allows you to control which parts of your code are compiled based on specific conditions. This is useful for:

- Including or excluding code based on the target platform or configuration
- Enabling or disabling debugging or testing code
- Customizing your code for different environments

The #ifdef, #ifndef, #else, and #endif directives are used for conditional compilation.

```
#ifdef checks if a macro is defined
#ifndef checks if a macro is not defined
#else provides an alternative code section
#endif marks the end of the conditional block.
```

The syntax for #ifdef and #ifndef is as follows:

```
#ifdef NAME
// Code to be compiled if NAME is defined
#endif
```

```
#ifndef NAME
// Code to be compiled if NAME is not defined
#endif
```
