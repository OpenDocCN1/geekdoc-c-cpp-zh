## 10.8  The proc Filesystem

了解如何查看、评估甚至更改 Linux 内核的 RT 运行特性是有益的。例如，查看正在运行的进程，以及这些进程具有哪些特性，然后基于这些观察采取行动。其中的关键组件是 /proc 文件系统，通常简称为 proc。在这里我们简要概述 proc，并展示了解它如何有助于你评估 Linux 在计算机上管理的任务。那些任务传统上并且非常普遍地被称为进程和线程。

proc 文件系统历史上源自于在 20 世纪 80 年代中期到 2002 年间在贝尔实验室开发的 Plan 9 分布式操作系统。该操作系统基于 UNIX 的大部分原则设计。它通过文件系统将几乎所有计算资源，包括文件、网络接口和外围设备，粘合在一起。proc 使普通用户能够轻松访问内核数据结构、内存分配以及系统上进程的信息。Linux 版本的 ps 命令直接访问 proc 以显示系统上进程的信息。proc 文件系统挂载在 /proc，这使你能够使用 cd 命令在其层次结构中导航。

我们在 Linux Mint 系统上的 /proc 目录结构包括所有正在运行的进程的子目录和其他附属设施。对于系统上的所有进程，都有一个名为 /proc/PID 的目录，其中 PID 是任何特定进程的进程 ID 号。在该目录中，有许多文件和子目录，其中包含有关该进程的信息。例如，目录 1 是 systemd (PID 1)。在以下会话中，我们展示了获取 systemd 进程 (PID 1) 信息的命令。

# Summary

进程是正在执行的程序。作为分时系统，Linux 允许同时执行多个进程。在只有一个 CPU 的计算机系统上，通过调度 CPU 时间并将其分配给每个进程短暂的时间，称为量子，来并发执行进程。每个进程由 Linux 系统分配一个优先级，当 CPU 可用时，它会被分配给优先级最高的进程。

shell 通过使用 fork 和 exec 系统调用创建子进程来执行命令。当进程使用 fork 系统调用时，Linux 内核会创建该进程的主内存的精确映像。shell 本身执行内部命令。外部二进制命令由子 shell 通过 exec 调用用命令的代码覆盖自身来执行。对于由 shell 脚本组成的外部命令，子 shell 会逐一执行脚本文件中的命令。

每个 Linux 进程都有多个属性，包括 PID、PPID、进程名称、进程状态（运行、挂起、交换、僵尸等）、进程执行的终端、进程已运行的时间长度以及进程优先级。ps 命令可用于查看这些属性的静态显示。top 命令可用于查看系统统计信息和运行在系统上的进程的各种属性的动态显示，并允许通过各种按键进行交互命令。

Linux 进程可以在后台或前台运行。前台进程控制终端直到完成，因此在前台进程运行时 shell 不能用于其他用途。当进程在后台运行时，它会返回 shell 提示符，以便用户可以在进程执行时做其他工作。由于后台进程以较低优先级运行，因此耗时长的命令是后台执行的良好候选。提供各种服务的后台系统进程称为守护进程。一组命令可以作为单独的进程或作为一个进程运行。多个命令可以通过使用分号 (;) 作为命令分隔符从一条命令行作为单独的进程运行；用括号括起来，这些命令可以作为一个进程执行。命令可以通过使用与号 (&) 作为命令分隔符并发执行。

挂起进程、将它们从前台移动到后台以及反之亦然、显示其状态、通过信号中断它们以及终止它们统称为作业控制，Linux 拥有一组允许这些操作的命令。前台进程可以通过按下 <Ctrl+Z> 然后执行 bg 命令来挂起并移动到后台。已挂起和后台进程可以通过使用 fg 命令移动到前台。被挂起或在后台运行的命令也称为作业。jobs 命令可用于查看所有作业的状态。你可以按 <Ctrl+C> 来终止前台进程。

kill 命令可以使用其 PID 或作业 ID 终止进程。该命令可用于向进程发送各种类型的信号或软件中断。收到任何信号后，除了一个，
