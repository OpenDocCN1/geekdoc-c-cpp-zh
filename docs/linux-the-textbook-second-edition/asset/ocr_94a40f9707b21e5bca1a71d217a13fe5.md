Table 10.9 shows some examples of the kill command and their meanings.

The hang-up signal is generated when you log out, the interrupt signal is generated when you press <Ctrl+C>, and the quit signal is generated when you press <Ctrl+\>. The kill command sends signal number 15 to the process whose PID is specified as an argument. The default action for this signal is termination of the process that receives it. This signal can be intercepted and ignored by a process, as can most of the other signals. To terminate a process that ignores signal 15 or other signals, signal number 9, known as sure kill, has to be sent to it. The kill command terminates all the processes whose PIDs are given in the proc-list, provided that these processes belong to the user who is using kill. The following session presents some instances of how the kill command can be used. But don’t kill the login shell process because it will log you out.

```
$ jobs -l
[1]  + 14338 Running          sort bigdata > bigdata.sorted
[2]  - 14667 Running          cp biggerdata biggerdata.bak
[3]      14668 Running         grep sh biggerdata > lines.sh
$ kill 14668
$ kill -2 14667
[3]  Terminated               grep sh biggerdata > lines.sh
$ kill -9 14338
[2]  Interrupt                cp biggerdata biggerdata.bak
$ jobs
[1]  Killed                   sort bigdata > bigdata.sorted
$ jobs
$
```
