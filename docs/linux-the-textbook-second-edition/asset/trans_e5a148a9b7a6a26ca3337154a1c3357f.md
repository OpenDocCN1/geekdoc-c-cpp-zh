

- `-n` 不运行任何 makefile 命令；仅显示它们。
- `-s` 以静默模式运行，不显示任何消息。

make 工具基于文件的相互依赖关系、需要构建的目标文件（例如，可执行文件或目标文件[s]）以及用于构建目标文件而需要执行的命令。这些相互依赖关系、目标和命令以 make 规则的形式在 makefile 中指定。以下是 make 规则的语法。

```
target-list: dependency-list
<Tab> command-list

Purpose: The syntax of a make rule
```

这里，target-list 是由一个或多个空格分隔的目标文件列表，dependency-list 是目标文件所依赖的文件（对象、头文件、源代码等）列表，由一个或多个空格分隔，而 command-list 是需要执行以创建目标文件的命令列表，由换行符分隔。command-list 中的每个命令都以 <Tab> 字符开头。注释行以 # 字符开头。target-list 和 dependency-list 中的文件可以使用 shell 通配符 ?, *, [], 和 {}。make 规则的另一种替代语法是 target-list: dependency-list; command-list，其中 "command-list" 是由分号分隔的一系列命令。目标前不应有制表符。

使用 : 操作符时，如果目标的修改时间小于 dependency-list 中的任何文件，则认为目标已过时。如果操作符为 !，则在检查并未重新创建 dependency-list 中的源文件后，目标始终会被重新创建。使用 :: 操作符时，如果在 dependency-list 中未指定源，则目标始终会被重新创建。在 : 和 ! 操作符的情况下，如果 make 被中断，目标将被删除，但在 :: 操作符的情况下则不会。在本书中，我们仅使用最常用的 : 操作符。

makefile 由一组 make 规则组成，这些规则描述了用于创建可执行文件的文件之间的依赖关系。make 工具使用 makefile 中的规则来确定构成程序的文件中哪些文件需要重新编译和重新链接以重新创建可执行文件。因此，例如，如果你修改了一个头文件（.h），make 工具会重新编译所有包含该头文件的文件。包含该头文件的文件必须在相应的 makefile 中指定。包含源文件和 makefile 的目录通常称为构建目录。

以下 makefile 可用于第 14.5.3 节中讨论的 power 程序。

```
$ cat makefile
# Sample makefile for the power program
# Remember: each command line starts with a <TAB>
power: power.c
<Tab>gcc power.c -o power -lm
$
```

如果可执行文件 power 存在，并且源文件 power.c 自可执行文件创建以来未被修改，运行 make 将给出消息，提示可执行文件对 power.c 来说是最新的。因此，make 无需重新编译和重新链接 power.c。有时，你需要强制重新制作可执行文件，因为例如，你的源代码中包含的一个系统头文件已更改。为了强制重新创建可执行文件，你需要更改最后的更新时间。一种常用的方法是用 touch 命令并重新运行 make。以下会话说明了这些要点。

```
$ make
make: 'power' is up to date.
$ touch power.c
$ make
gcc power.c -o power -lm
$
```

当你使用 touch 命令并将其参数设为一个或多个现有文件时，它会将它们的最后更新时间设置为当前时间。当使用不存在的文件作为参数时，它会创建一个零长度（即空）文件，名称与该文件相同。

### Exercise 14.5

创建 C 程序 power.c 文件的可执行代码，并将其放在名为 XpowerY 的文件中。使用前面给出的 makefile，使用 make 工具执行此任务。运行 XpowerY 以确认程序正常工作。

为了展示 make 工具的进阶用法，我们将 power.c 文件中的 C 程序划分为两个文件：power.c 和 compute.c。以下会话显示了这些文件的内容。compute.c 文件包含从 power.c 中的 main 函数调用的 compute 函数。为了生成 power 文件中的可执行文件，我们需要独立编译两个源文件，然后链接它们，如会话末尾的两个 cc 命令行所示。

```
$ cat power.c
#include <stdio.h>
double compute(double x, double y);
int main()
{
    float x,y;
    printf ("The program takes x and y from stdin and displays x^y.\n");
    printf ("Enter integer x: ");
    scanf ("%f", &x);
    printf ("Enter integer y: ");
    scanf ("%f", &y);
    printf ("x^y is: %6.3f\n", compute(x,y));
}

$ cat compute.c
#include <math.h>
double compute (double x, double y)
{
    return (pow ((double) x, (double) y));
}

$ gcc -c compute.c power.c
$ ls
compute.c compute.o power.c power.o
$ gcc compute.o power.o -o power -lm
```

这两个源文件的依赖关系在这个例子中相当简单。要创建可执行文件 power，我们需要两个对象模块：power.o 和 compute.o。如果 power.c 或 compute.c 中的任意一个文件被更新，可执行文件需要重新创建。图 14.4 显示了依赖关系的第一次分析。

![](img/2a18e06cd9c6395e451f26126ecba1fd_434_0.png)

因此，对应于此依赖关系的 make 规则如下。注意，由于 compute.c 文件中的 compute 函数使用了该库中的 pow 函数，必须链接数学库。

```
power: power.o compute.o
    gcc power.o compute.o -o power -lm
```

我们还知道，对象文件 power.o 是由源文件 power.c 构建的，而对象文件 compute.o 是由源文件 compute.c 构建的。图 14.5 显示了依赖关系的第二次分析。

![](img/2a18e06cd9c6395e451f26126ecba1fd_435_0.png)

**FIGURE 14.5** Second cut on the make dependency tree.

因此，创建两个对象文件的 make 规则为

```
power.o: power.c
    gcc -c power.c
compute.o: compute.c
    gcc -c compute.c
```

最终的 makefile 如下所示

```
$ cat makefile
power: power.o compute.o
    gcc power.o compute.o -o power -lm
power.o: power.c
    gcc -c power.c
compute.o: compute.c
    gcc -c compute.c
$
```

然后我们使用前面的 makefile 执行 make 工具：

```
$ make
gcc -c power.c
gcc -c compute.c
gcc power.o compute.o -o power -lm
$
```
