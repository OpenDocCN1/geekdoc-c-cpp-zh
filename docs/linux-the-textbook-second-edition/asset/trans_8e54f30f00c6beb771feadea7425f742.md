

当用户执行 passwd 命令时，该命令会代表运行此命令的用户更改 /etc/passwd 文件中的用户密码。问题在于我们希望用户能够更改自己的密码，同时，他们又不能对 /etc/passwd 文件具有写权限，以防止此文件中其他用户的信息被泄露。在 Linux Mint 中，更改的是不可读的主密码文件 /etc/shadow。

如前所述，当命令执行时，它以运行该命令的用户权限运行。另一种说法是，当命令运行时，它以运行该命令的用户的有效用户 ID 执行。Linux 有一种优雅的机制来解决前一段所述的问题——以及许多其他类似的安全问题——通过允许命令更改其有效用户 ID 并以某种方式获得特权。该机制允许诸如 passwd 之类的命令执行其工作，同时不损害系统的完整性。每个 Linux 文件都有一个额外的保护位与之关联，称为 SUID 位。如果为包含可执行程序的文件设置了此位，则程序在执行时会获得文件所有者的权限。因此，如果文件由 root 拥有并且设置了其 SUID 位，则它将以超级用户权限运行。例如，passwd 命令就设置了此位。因此，当你运行 passwd 命令时，它可以写入 /etc/passwd 文件（用新密码替换现有密码），即使你没有写入该文件的访问权限。

还有其他几个 Linux 命令需要 root 所有权并设置 SUID 位，因为它们访问和更新操作系统资源（文件、数据结构等），而普通用户不得拥有这些资源的权限。其中一些命令是 lp、mail、mkdir、mv 和 ps。开发维护记分文件的计算机游戏软件可以对 SUID 位进行另一种用途。当为此类软件设置 SUID 位时，它可以在用户玩游戏时更新记分文件，尽管同一用户不能通过显式写入来更新记分文件。

如果所有者的执行位显示为 s（或 S），则启用 SUID 位。如果同时启用 SUID 位和执行位，则 ls -l 命令的输出中该位显示为 s。如果启用了 SUID 位但禁用了执行位，则 ls -l 命令会将其显示为 S。以下会话显示了每种情况的示例。

```
$ ls -l cp.new foo
-rwSr--r-- 1 sarwar faculty 14 Aug  4 23:38 cp.new
-r-sr-xr-x 1 sarwar faculty 30 Aug  5 05:27 foo
$
```

可以使用以下语法的 chmod 命令来设置 SUID 位。

Syntax:
chmod 4xxx file-list
chmod u+s file-list
Purpose: Change/set the SUID bit for files in file-list

这里，xxx 是指定用户、组和其他人的读、写和执行权限的八进制数，而八进制数字 4（二进制 100）用于设置 SUID 位。当设置 SUID 位时，如果用户已设置执行权限，则用户执行位将设置为 s（小写）；否则，将设置为 S（大写）。以下会话说明了这些命令语法的用法。首先，ls -l cp.new 命令用于显示 cp.new 文件的执行权限已设置。chmod 4710 cp.new 命令用于设置 SUID 位和其他九个权限位为八进制 710。其次，ls -l cp.new 命令显示 x 位值已更改为 s。随后两个 chmod 命令用于将 SUID 和执行位设置为 0。ls -l cp.new 命令用于显示已从所有者那里收回执行权限。chmod u+s cp.new 命令用于再次设置 SUID 位，最后的 ls -l cp.new 命令显示位值为 S（大写），因为在设置 SUID 位之前未设置执行位。

```
$ ls -l cp.new
-rwx--x--- 1 sarwar faculty 14 Aug  4 23:26 cp.new
$ chmod 4710 cp.new
$ ls -l cp.new
-rwS--x--- 1 sarwar faculty 14 Aug 4 23:26 cp.new
$ chmod u-s cp.new
$ ls -l cp.new
-rw--x--- 1 sarwar faculty 14 Aug 4 23:26 cp.new
$ chmod u+s cp.new
$ ls -l cp.new
-rwS--x--- 1 sarwar faculty 14 Aug 4 23:26 cp.new
```

尽管 SUID 位的想法是合理的，但如果未正确实现，它可能会损害系统的安全性。例如，如果任何 SUID 程序的权限设置为允许其他人写入权限，你可以更改此文件中的程序或用另一个程序覆盖现有程序。这样做会让你以超级用户权限执行你的（新）程序。

## 5.6.2 SGID 位

SGID 位的工作方式与 SUID 位相同，但它会导致进程的访问权限采用文件所有者所属组的组身份。此功能不如 SGID 功能危险，因为大多数特权操作需要超级用户身份，而与当前组 ID 无关。如果 ls -l 命令显示组的执行位为 s（或 S），则启用 SGID 位。如果同时启用 SGID 位和执行位，则 ls -l 命令的输出中该位显示为 s。如果启用了 SGID 位但禁用了执行位，则 ls -l 命令会将其显示为 S。以下会话显示了每种情况的示例。

```
$ ls -l cp.new foo
-rw-r--r-- 1 sarwar faculty 14 Aug 4 23:38 cp.new
-r-xr-sr-x 1 sarwar faculty 30 Aug 5 05:27 foo
```

- Syntax:
- chmod 2xxx file-list
- chmod g+s file-list
- Purpose: Change/set the SGID bit for files in file-list

```
$ chmod 2751 cp.new
$ ls -l cp.new
-rwxr-s--x 1 sarwar faculty 14 Aug 4 23:26 cp.new
```

```
$ chmod g+s cp.new
$ ls -l cp.new
-rwxr-S--x 1 sarwar faculty 14 Aug 4 23:26 cp.new
```

```
$ chmod g-x cp.new
$ ls -l cp.new
-rwxr---x 1 sarwar faculty 14 Aug 4 23:26 cp.new
```

```
$ chmod g+s cp.new
$ ls -l cp.new
-rwxr-S--x 1 sarwar faculty 14 Aug 4 23:26 cp.new
```

你可以使用单个 chmod 命令设置或重置 SUID 和 SGID 位。因此，命令 chmod ug+s cp.new 可用于对 cp.new 文件执行此任务。你还可以通过将访问权限的八进制数字前加上 6 来同时设置 SUID 和 SGID 位以及访问权限位（读、写和执行），因为最左边的八进制数字 6（110）指定同时设置 SUID 和 SGID 位。因此，命令 chmod 6754 cp.new 可用于为 cp.new 文件设置 SUID 和 SGID 位及其访问权限为 754。如果在目录上设置了 SGID，则在该目录中创建的目录将不属于创建该目录的用户的组，而属于父目录的组所有者。

如果你的操作系统和文件系统支持强制文件锁定，则 ls -l 命令会在第七个权限位显示 l。值 l 表示此文件的强制文件锁定已启用。请阅读 fcntl() 系统调用的手册页和第 W21 章，了解建议性（或自主性）和强制性文件锁的详细信息。

## 5.6.3 粘滞位

12 个访问位中的最后一个，粘滞位，如果其他人的执行位为 t（或 T），则处于开启状态，如下所示的 /tmp 情况：

```
$ ls -l / | grep tmp
drwxrwxrwt 14 root root 4096 Jul  1 15:17 tmp
$
```

粘滞位可以为目录设置，以确保无特权用户无法删除或重命名该目录中其他用户的文件。你必须是目录的所有者或具有适当权限才能为其设置粘滞位。某些系统不允许非超级用户设置粘滞位。它通常为包含多个用户拥有的文件的共享目录设置。

之前的命令输出显示，/tmp 目录由 root 拥有，并且粘滞位已打开。它对每个人都有读、写和执行权限。这意味着任何用户都可以在 /tmp 中创建文件或目录。然而，由于粘滞位已打开，没有用户（除超级用户外）可以删除或重命名他/她不拥有的文件或目录。因此，Linux 允许你删除 /tmp 中你拥有的任何文件，但不允许删除其他文件或目录，因为你不是那些文件和目录的所有者。

最初，此位旨在通知内核程序的代码段应因程序的频繁使用而共享或保留在主内存或交换空间中。因此，当为程序设置此位时，系统会在程序执行结束后尝试将程序的可执行代码（仅代码段）保留在内存中——进程在内存中“保留”。如果出于某种原因，系统需要此程序占用的内存空间来加载另一个程序，则设置了粘滞位的程序将被保存到交换空间（用于临时保存进程的磁盘上的特殊区域）。也就是说，如果为程序设置了粘滞位，则程序的代码段在执行结束后要么保留在内存中，要么保留在交换空间中。当再次执行此程序时，如果程序在内存中，则其执行会立即开始。如果程序在交换空间中，则加载所需的时间远短于将其存储为 Linux 文件的情况。因此，如果经常执行设置了粘滞位的程序，则其执行速度会快得多。

此功能对于编译器、汇编器、编辑器以及 ls 和 cat 等命令等程序很有用，这些程序在典型的计算机系统环境中经常使用。然而，必须注意不要让太多程序设置此位。否则，由于缺乏可用空间，系统性能会下降，设置了粘滞位的程序会占用越来越多的空间。新版 Linux 系统中不再需要这种粘滞位的使用，因为虚拟内存系统使用页面置换算法，不会移除最近使用的程序页/段。Linux Mint 允许你在非目录文件上设置粘滞位，如本节末尾的 shell 会话所示。
