

通过 SCI 的 I/O 接口的真正优势在于，open()、read()、write() 和 close() 调用不仅可用于文件，还可用于网络套接字和其他与缓冲区交互不佳的文件型对象。

## 15.7.1 CSL

CSL 实现基于 ISO C 标准规范，该规范已在多个操作系统上实现，包括 UNIX、Linux 和 Microsoft Windows。因此，使用该库编写的代码可在操作系统之间移植。该库由一组预定义且经过充分测试的函数、常量和头文件组成。它为你提供了处理诸如字符 I/O 到文件 I/O、从时间相关函数到复杂数学函数，以及从字符串操作到信号处理的任务的机制。该库中的头文件包含数百种变量类型、函数和宏。一些定义为了完整性而在多个文件中重复。例如，NULL 在多个头文件中定义。表 15.1 列出了构成 CSL 的头文件。

## 15.7.2 使用 CSL 进行文件数据 I/O

标准 I/O 库 API 简单易用，并处理了缓冲区分配以及使用适当大小的块以实现最佳 I/O 的问题（时间上包括 CPU 时间和时钟时间）。该库中的函数使用 SCI 中可用的文件 I/O 调用。使用合适大小的缓冲区和块大小的目的是通过最小化 read() 和 write() 系统调用的次数来最小化磁盘 I/O 操作次数（参见第 15.7.4 节和第 15.7.5 节）。

标准 I/O 库支持三种类型的缓冲 I/O：完全缓冲、行缓冲和无缓冲。ISO C 标准要求标准输入和标准输出对非交互式设备必须是完全缓冲的。另一方面，标准错误从不完全缓冲；它通常是无缓冲的，以便错误消息能尽早显示。

当我们使用标准 I/O 接口打开一个文件时，我们会得到一个指向对象 FILE 的指针，称为文件指针。我们使用该指针和标准 I/O 库函数执行所有后续文件操作。当我们使用 SCI 打开一个文件时，我们会得到一个类型为 int 的对象，称为文件描述符。我们使用该描述符和相关的系统调用执行所有后续文件上的 I/O 操作。这两种对象的另一个术语是文件句柄。在本书中，我们主要处理低级 I/O 接口。

当我们使用标准 I/O 库接口打开一个文件时，会将一个流与该文件关联。根据所使用的字符集，一个字符可能由一个或多个字节表示。因此，流 I/O 取决于字符的“宽度”以字节为单位，并确定流的“方向”。当流创建时它没有方向，其方向由用于对流执行 I/O 的函数类型设置。当我们使用 open() 系统调用打开一个文件时，会将一串字节与该文件关联，并且所有后续 I/O 都是以字节序列形式进行的。

我们假设读者熟悉使用标准 I/O 库进行文件 I/O，并且不再进一步讨论它。

## 15.7.3 通过系统调用在 Linux 中进行低级 I/O

表 15.2 显示了用于文件 I/O 的 Linux 系统调用及其用途。我们将在本章讨论其中大多数系统调用，其余将在第 16 章讨论。如第 15.3.5 节所述，这些实际上是包装函数，最终会将控制权转移给系统调用 syscall()，连同相应的调用号和调用参数，以便执行适当的内核函数来为相关的系统调用服务。要能够使用 open() 和 creat() 系统调用，你需要包含 <fcntl.h> 文件。对于 close() 和 lseek() 系统调用，你需要使用 <unistd.h> 文件。最后，要使用 read() 和 write()，你需要包含 <sys/types.h> 和 <unistd.h> 文件。

在本章中，我们讨论用于对文件执行以下操作的系统调用：创建、打开、关闭、读取、写入、为随机访问做准备、删除文件的硬链接以及获取文件属性。你将在本章末尾的一些编程练习中练习其中的一些剩余调用。

open() 调用原型中的第三个参数 (...) 意味着剩余参数的数量和类型可能变化。creat() 调用中的 mode 参数用于指定新创建文件的访问权限（参见第 5 章）。这两个调用都返回一个非负整数，称为打开文件的文件描述符，可用于使用 read() 和 write() 系统调用（稍后讨论）执行所需 I/O 操作，使用 lseek() 系统调用更改读/写文件指针的位置以进行随机访问，以及使用 close() 系统调用关闭文件。返回的描述符是 PPFDT 中第一个未使用的描述符，从描述符 0 开始。如果文件成功打开，读/写文件指针将被设置为文件的开头。这意味着第一次读或写操作从文件的第一个字节开始。两个调用在失败时都返回 -1。

对 <fcntl.h> 文件中列出的两个或多个常量进行按位或运算形成 flag 参数。表 15.3 显示了一些常用的文件 I/O 标志及其含义。

open() 调用可能因多种原因而失败。表 15.4 给出了针对常规文件调用失败的常见原因，以及保存在 errno 变量中的相应符号值。

由于 creat() 系统调用创建文件并默认以仅写入方式打开它，因此以下调用彼此等效：

```
creat(pathname, mode);
open(pathname, O_WRONLY | O_CREAT | O_TRUNC, mode);
```
