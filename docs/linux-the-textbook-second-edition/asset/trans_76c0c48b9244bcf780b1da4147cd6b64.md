```
sudo systemctl stop name.service
```

## 18.3.1.3 重启和重新加载

要重启正在运行的服务，可以使用 restart 命令，如下所示：

```
sudo systemctl restart name.service
```

如果应用程序能够重新加载其配置文件（无需重启），则可以使用 reload 命令来启动该过程，如下所示：

```
sudo systemctl reload name.service
```

如果不确定服务是否可以重新加载其配置文件，可以使用 reload-or-restart 命令。它会在可用时就地重新加载配置。否则，它将重启服务，以便调用新配置，如下所示：

```
sudo systemctl reload-or-restart name.service
```

## 18.3.1.4 启用和禁用服务

之前的命令对于在当前会话期间启动或停止服务很有用。要让 systemd 在启动时自动启动服务，必须启用它们。

要使服务在启动时启动，请使用 enable 命令，如下所示：

```
sudo systemctl enable name.service
```

这将从系统对服务文件的副本（在我们所有代表性 Linux 系统中位于 /lib/systemd/system 或 /etc/systemd/system）创建一个符号链接到 systemd 查找自动启动文件的位置（传统上为 /etc/systemd/system/some_target.target.wants）。要改变主意并禁用服务自动启动，请使用以下命令：

```
sudo systemctl disable name.service
```

这将删除指示服务应自动启动的符号链接。

请记住，启用服务并不会在当前会话中启动它。

如果希望启动服务并在启动时启用它，则必须同时发出 start 和 enable 命令。

要检查系统上服务的状态，可以使用 systemctl status 命令。以下，我们展示了该命令及其输出，在我们的 Linux 系统上针对已安装的 nginx Web 服务器服务执行：

```
$ sudo systemctl status nginx.service

CGroup: /system.slice/nginx.service

```

之前的命令会显示你服务状态（loaded 和 active）、cgroup 层级，以及 nginx Web 服务器服务的 journald 日志条目的前几行。

它提供了应用程序当前状态的概览，通知你任何问题以及可能需要采取的任何操作。

也有用于检查特定状态的方法。例如，要检查单元当前是否处于活动状态（或正在运行），可以使用 is-active 命令，如下所示：

```
sudo systemctl is-active name.service
```

这将返回当前单元状态，可以是 active 或 inactive。此外，如果单元状态为“enabled”，则表示它在系统启动时启动。

这引出了一个非常实际的可能性：你如何快速知道服务是否已实际安装在你的系统上？即默认安装、由你使用包管理系统的命令安装，或手工构建然后安装？你可以使用 systemctl status 命令，如果输出产生类似以下内容（本例中为 Webmin 服务），你就知道它未被安装，或可能安装不正确！

```
$ sudo systemctl status webmin
• webmin.service
  Loaded: not-found (Reason: No such file or directory)
  Active: inactive (dead)
$
```

要查看单元是否已启用，可以使用 systemctl is-enabled 命令，如下所示：

```
sudo systemctl is-enabled name.service
```

这将显示服务是否已启用或禁用。

第三个状态报告你可以获取的是查看单元是否处于失败状态。这表示启动单元时出现问题：

```
sudo systemctl is-failed name.service
```

这将在运行正常时返回 active，或在发生错误时返回 failed。如果单元是有意停止的，则可能返回 unknown 或 inactive。退出状态“0”表示发生了故障，退出状态“1”表示任何其他状态。

## 18.3.1.6 如何检查系统状态

之前的命令对于有效管理单个服务很有用，但对于探索整个系统及其服务的当前状态帮助不大。有许多 systemctl 子命令及其选项可以提供这类信息。

### 列出当前单元

要查看 systemd 所知的所有活动单元列表，我们可以使用 list-units 命令：

```
$ sudo systemctl list-units
```

这将显示 systemd 当前在系统上处于活动状态的所有单元列表。

输出具有以下列：

- 1. UNIT：systemd 单元名称。
- 2. LOAD：systemd 是否已正确读取单元的配置。已加载单元的配置保存在内存中。
- 3. ACTIVE：关于单元是否处于活动状态的摘要说明。这是判断单元是否成功启动的基本方法。
- 4. SUB：这是一个更低级别的状态，表示有关单元的更详细信息。这通常因单元类型、状态以及单元实际运行方式而异。
- 5. DESCRIPTION：单元是/做什么的简短文本描述。

由于 list-units 命令默认只显示活动单元，因此所有之前的条目在 LOAD 列中都会显示“loaded”，在 ACTIVE 列中都会显示“active”。这是 systemctl 在不带额外子命令调用时的默认行为。它等同于不带参数使用 systemctl。

systemd 具有跟踪每个服务的功能，无论它在系统启动时是否成功启动、是否以非零退出代码退出、是否超时，或是否异常终止（出现段错误），都在启动期间和运行时。键入 shell 提示符下的 systemctl 允许你查看所有服务的状态，例如：

```
$ sudo systemctl
```

ACTIVE 列显示服务的 high-level 状态，服务是否处于活动状态（即正在运行）、非活动状态（即未运行）或任何其他状态，这一点至关重要。列表中标记为 maintenance 并以红色突出显示的项目会告诉你某个服务未能运行或可能遇到问题。
