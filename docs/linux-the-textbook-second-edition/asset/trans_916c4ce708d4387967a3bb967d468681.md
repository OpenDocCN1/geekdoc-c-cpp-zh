## 14.7 动态分析工具

程序的动态分析涉及其在运行时的分析。如前所述，该阶段包括软件的调试、跟踪和性能监控，包括根据产品需求对其进行测试。在本节中，我们讨论两个有用的 Linux 工具：一个用于跟踪程序执行和调试（gdb），另一个用于以实际时间单位测量程序的运行时间（time）。

### 14.7.1 使用 gdb 进行源代码调试

调试软件的任务既耗时又困难。它包括在执行代码时监控其内部工作、检查程序变量的值和函数返回的值，以及使用特定输入参数执行函数。如前所述，许多 C 程序员倾向于在程序中的各个位置使用 printf 调用（C++ 中使用 cout）来定位错误的来源，然后将其移除。这种技术很简单，对于小型程序效果很好。然而，对于大型软件，错误可能隐藏在函数调用层次的深处，这种技术最终会花费大量编辑时间来在源文件中添加和删除 printf（或 cout）调用。在这种情况下，更有效的调试方法是使用符号调试器。典型的符号调试器提供了多种观察程序运行时行为的工具，包括以下内容：

+   - 运行程序
+   - 设置断点
+   - 单步执行
+   - 列出源代码
+   - 编辑源代码
+   - 访问和修改变量
+   - 跟踪程序执行
+   - 搜索函数和变量
+   - 识别程序崩溃时正在做什么

Linux 平台上有多种符号调试器可用，最常见的是免费软件 Gnu 调试器 gdb。Solaris 和 PC-BSD 上的默认源代码调试器分别是 adb 和 gdb。它们提供类似的功能。adb 是 mdb（模块化调试器）的一个链接，它允许你检查进程、用户进程核心转储，以及活动操作系统和操作系统转储。我们主要描述 gdb，因为它是大多数 Linux 系统上的标准调试器。尽管 gdb 也有多个调试 C++ 类的功能，但我们只讨论其调试 C 程序的功能。以下是该实用程序的简要描述。

```
语法：
  gdb [选项] [可执行文件 [核心文件或 PID]]
用途：允许对可执行文件中的程序进行源代码级调试和执行，该可执行文件由 C 或 C++ 源文件生成；或者对因 C/C++ 程序崩溃而创建的核心文件进行调试；或者对正在运行的程序的进程 ID（PID）进行调试
常用选项/功能：
  -c file    将文件 file 作为核心转储进行检查（即 Linux 在程序崩溃时创建的文件）
  -h         列出所有选项及其简要说明
  -n         不要运行任何 .gdbinit 初始化文件中的命令
  -x file    从文件 file 中执行 gdb 命令（如果未指定文件，则从 .gdbinit 初始化文件中执行）
```

在启动期间，gdb 会搜索 .gdbinit。搜索顺序是：当前目录（.），然后是主目录（~）。-x 选项允许你使用任何文件作为启动文件。表 14.1 简要描述了一些常用的 gdb 命令。

### 14.7.1.1 使用 gdb

在使用 gdb（或任何其他调试器）调试程序之前，必须使用 -g 编译器选项编译程序，以在可执行文件中包含符号表以及重定位、调试和剖析信息。这些信息供调试和剖析工具使用。我们使用 bugged.c 文件中的程序来展示 gdb 的各种功能。该程序提示你进行键盘输入，显示输入，然后退出。我们使用几个函数来演示 gdb 的功能：设置断点并显示函数边界的堆栈跟踪、通过逐条执行程序语句来跟踪程序执行、查看变量的类型和值等。以下会话显示了程序代码、在没有 -g 选项的情况下编译以及执行情况。
