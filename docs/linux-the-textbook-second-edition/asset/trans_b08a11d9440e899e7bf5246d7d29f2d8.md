

```
$ gcc -c misc.c
```

你也可以使用 -c 选项编译多个文件。在下面的第一条命令行中，我们使用一条命令将三个源文件全部编译以生成目标文件。编译器在编译时会显示文件名。命令行中列出文件的顺序并不重要。第二条命令行将三个目标文件链接并生成一个可执行文件 polish。

## 14.5.3.3 链接库

Linux 系统上的 C 编译器在编译时会自动为你的程序链接合适的库。然而，有时你必须显式地告诉编译器链接所需的库。你可以通过使用 gcc 命令并加上 -l 选项来实现，后面紧跟库名中在字符串 lib 之后、扩展名之前的字母。大多数库位于 /lib 目录中。你需要为每个需要链接的库使用单独的 -l 选项。在下面的会话中，我们将数学库（根据机器是 32 位还是 64 位，为 /lib/i386-linux-gnu/libm.so.6 或 /lib/x86_64-linux-gnu/libm.so.6）链接到 power.c 文件中程序的目标代码。我们使用第一条 gcc 命令行来展示如果未链接数学库时编译器产生的错误信息。该信息指出在 power.o 文件中使用了符号 pow 但未找到。数学库的名称为 libm.so.6，因此我们在 -l 选项后使用字母 m，该字母位于字符串 lib 之后并在扩展名之前。

```
$ cat power.c
#include <stdio.h>
#include <math.h>

int main()
{
    float x,y;

    printf ("The program takes x and y from stdin and displays x^y.\n");
    printf ("Enter integer x: ");
    scanf ("%f", &x);
    printf ("Enter integer y: ");
    scanf ("%f", &y);
    printf ("x^y is: %6.3f\n", pow((double)x,(double)y));
    return(0);
}
$ gcc power.c
/tmp/cconeTLL.o: In function `main':
power.c:(.text+0x7e): undefined reference to `pow'
collect2: error: ld returned 1 exit status
$ gcc power.c -lm -o power
$ power
The program takes x and y from stdin and displays x^y.
Enter integer x: 9.82
```

## 14.5.4 使用 make 处理基于模块的 C 软件

大多数有用的 C 软件被划分为多个源文件（.c 和 .h）。这种软件结构相比于存储在单个文件中的单体程序有几个优点。首先，它导致更模块化的软件，从而产生更小的程序文件，编辑、编译、测试和调试所需时间更少。它还允许仅重新编译被修改的源文件，而不是整个软件系统。此外，多模块结构支持信息隐藏，这是面向对象设计和编程的关键特性。

然而，多模块实现也有其缺点。首先，你必须知道构成整个系统的文件、这些文件的相互依赖关系，以及自上次创建可执行系统以来被修改过的文件。此外，当处理多模块 C 软件时，将多个文件编译成一个可执行文件有时会变得麻烦，因为需要输入两条很长的命令行：一条为所有 C 源文件创建目标文件，另一条将目标文件链接以创建可执行文件。解决这种不便的一种简单方法是创建一个执行此工作的简单 shell 脚本。这种技术的缺点是，即使只有一个源文件（或头文件）被修改，所有目标文件都会被重新创建，其中大部分是不必要的。

Linux 有一个更强大的工具称为 make，它允许你管理模块的编译为可执行文件。make 实用程序读取一个名为 makefile 的规范文件，该文件描述了软件系统的模块之间的依赖关系。make 实用程序使用 makefile 中的依赖关系规范以及各个组件被修改的时间，来最小化重新编译量。当你的软件系统由数十个文件和多个可执行程序组成时，此实用程序非常有用。在这样的系统中，记住并跟踪所有头文件、源文件、目标文件和可执行文件可能是一场噩梦。以下是 make 实用程序的简要描述。

## Syntax:

```
make [options] [targets] [macro definitions]

Purpose: This utility updates a file based on the dependency relationship in a file called makefile or Makefile; the dependency relationship is specified in makefile in a particular format. “options,” “targets,” and “macro definitions” can be specified in any order

Commonly used options/features:
-d Display debugging information
-f file This option allows you to instruct make to read interdependency specification from "file"; without this option, the file name is treated as makefile or Makefile. The file name “-” implies standard input
-h Display a brief description of all options
```
