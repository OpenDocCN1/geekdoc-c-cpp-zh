

为了生成软件的可执行文件，你需要为三个源文件生成目标文件，并将它们链接成一个可执行文件。完成此任务需要以下命令。注意，和之前一样，在链接 compute.o 文件时需要链接数学库，以便在 power 文件中生成可执行文件。

```
$ gcc -c main.c input.c compute.c
$ gcc main.o input.o compute.o -o power -lm
$
```

与此依赖关系对应的 makefile 如下所示：

```
$ cat makefile
power:          main.o input.o compute.o
        gcc main.o input.o compute.o -o power -lm
main.o:         main.c main.h input.h compute.h
        gcc -c main.c
input.o:        input.c input.h
        gcc -c input.c
compute.o:      compute.c compute.h
        gcc -c compute.c
$
```

执行 make 命令会导致 makefile 中所有目标关联的规则被执行。

```
$ make
gcc main.o input.o compute.o -o power -lm
$
```

如果运行 make 后得到消息 make: 'power' is up to date.，请删除 power 文件并重新运行 make。如果目标文件尚未创建，make 命令将首先为所有模块创建目标文件，然后创建可执行文件，如下所示。

```
$ make
gcc -c main.c
gcc -c input.c
gcc -c compute.c
gcc main.o input.o compute.o -o power -lm
$
```

## 练习 14.7

创建刚才讨论的三个源文件和头文件，然后使用 make 命令在 power 文件中创建可执行文件。使用前面的 makefile 来执行你的任务。

如果 make 规则位于 makefile（或 Makefile）以外的文件中，你需要使用 -f 选项运行 make 命令，例如 make -f my.makefile。

前面的 makefile 中所示的 make 规则包含一些可以删除的多余命令。make 实用程序有一个预定义规则，对于每个规则都会调用 gcc -c xxx.c -o xxx.o 命令，如下所示：

```
xxx.o: xxx.c zzz.h
gcc -c xxx.c
```

此外，make 实用程序会识别出目标文件的名称通常就是源文件的名称。这种能力称为标准依赖关系，因此你可以从目标 xxx.o 对应的依赖列表中省略 xxx.c。因此，下面的 makefile 与前面给出的 makefile 同样有效。

```
$ cat makefile
power:		main.o input.o compute.o
		gcc main.o input.o compute.o -o power -lm
main.o:		main.h input.h compute.h
input.o:	input.h
compute.o:	compute.c compute.h
		gcc -c compute.c
$
```

使用此 makefile 运行 make 命令会产生以下结果：

```
$ make
gcc main.o input.o compute.o -o power -lm
$
```

make 实用程序支持简单的宏，可以进行简单的文本替换。你必须在使用宏之前定义它们；它们通常放在 makefile 的顶部。宏定义的语法如下：

```
Syntax:
  macro_name = text
Purpose: Substitute text for every occurrence of $(macro_name)
```

有了这条规则，文本（text）会替换 makefile 其余部分中每次出现的 $(macro_name)。此外，make 实用程序还有一些内置宏，例如 CFLAGS，它们被设置为默认值，并由内置规则使用，例如如前所述，为预定义规则执行 cc $(CFLAGS) -c xxx.c -o xxx.o 命令。

CFLAGS 宏的默认值通常是 -O（用于优化），但可以将其更改为 cc 编译器的任何其他标志。在我们的系统上，CFLAGS 被设置为 null；也就是说，没有默认选项。make 实用程序为内置规则使用多个内置宏。

下面的 makefile 展示了用户定义宏的使用，以及一些可以在命令行调用的有用的 make 规则。它还表明 make 规则的命令并不总是编译器或链接器命令；它们可以是任何 shell 命令。

```
$ cat makefile
CC = gcc
OPTIONS = -O4 -o
OBJECTS = main.o input.o compute.o
SOURCES = main.c input.c compute.c
HEADERS = main.h input.h compute.h

power:		main.c $(OBJECTS)
		$(CC) $(OPTIONS) power $(OBJECTS) -lm
main.o:		main.c main.h input.h compute.h
input.o:	input.c input.h
compute.o:	compute.c compute.h

all.tar:	$(SOURCES) $(HEADERS) makefile
		tar cvf - $(SOURCES) $(HEADERS) makefile > all.tar

clean:
		rm *.o
$
```

当执行 make 命令时，最后两个目标（all.tar 和 clean）的命令不会执行，因为这些目标不依赖任何东西，也没有任何东西依赖它们。你可以通过将这些目标作为参数传递给 make 来调用与这些目标关联的命令。将这些规则放在 makefile 中的优点是，你不必记住要归档哪些文件（在这种情况下使用 tar 命令），也不必记住在最终可执行文件创建后要删除哪些文件。

### 14.5.5.1 创建归档

你可以使用带 r 键的 ar 命令创建归档。下面的命令行在 mathlib.a 中创建 input.o 和 compute.o 文件的归档。

```
$ ar r mathlib.a input.o compute.o
ar: creating mathlib.a
$
```

注意，如果 mathlib.a 不存在，它会被创建。如果它已经存在并且包含 input.o 和 compute.o 模块，则它们会被命令行中指定的模块替换。一旦归档创建在当前目录中，你就可以使用编译器命令（如 cc）将其链接到 main.c 文件，例如：

```
$ gcc main.c mathlib.a -o power -lm
$
```

你可以使用 q 键将目标模块追加到现有归档的末尾。如果命令中指定的归档不存在，则创建它。在下面的示例中，目标模块 main.o 被追加到现有归档 mathlib.a 的末尾。main.o 追加到 mathlib.a 后，使用 gcc 命令在 power 中创建可执行文件。

```
$ ar q mathlib.a main.o
$ gcc mathlib.a -o power -lm
$
```

创建了一些目标模块的归档后，你可以删除原始模块以节省磁盘空间，如下所示：

```
$ rm compute.o input.o main.o
$
```

### 14.5.5.2 显示目录内容

你可以使用带 t 键的 ar 命令显示归档的目录内容。该命令显示 mathlib.a 归档的目录内容。

```
$ ar t mathlib.a
input.o
compute.o
main.o
$
```

### 14.5.5.3 从归档中删除目标模块

你可以使用带 d 键的 ar 命令从归档中删除一个或多个目标模块。在下面的会话中，第一个 ar 命令从 mathlib.a 归档中删除目标模块 main.o，第二个命令显示新的目录内容，确认 main.o 目标模块已从该归档中移除。

```
$ ar d mathlib.a main.o
$ ar t mathlib.a
input.o
compute.o
$
```

注意，从头创建一个全新的归档比使用 d、q 和 r 键修改现有归档更高效。

### 14.5.5.4 从归档中提取目标模块

你可以使用带 x 键的 ar 命令从归档中提取一个或多个目标模块。提取的模块仍保留在归档中。下面的命令行可用于从 stringlib.a 归档中提取目标模块 cpstr.o 并将其放到当前目录。

```
$ ar x stringlib.a cpstr.o
$
```

你可以运行 ls -l cpstr.o 命令查看 cpstr.o 目标文件已被提取，并使用 ar t mathlib.a 命令查看该目标文件仍是归档的一部分。

虽然我们展示了在命令行中使用 ar 命令的方法，但你也可以将该命令作为 makefile 的一部分运行，以便在可执行文件创建之后，为软件产品的目标文件创建归档。这样做可以让你将来使用在软件中创建的任何通用目标模块（这些模块中的一个或多个函数）。这可以在 makefile 末尾通过显式 make 规则完成，如下所示：

```
mathlib.a:      input.o compute.o
                ar rv mathlib.a input.o compute.o
                rm input.o compute.o
```

下面的 makefile 是对上一节中 makefile 的增强，可用于创建 input.o 和 compute.o 的归档，名为 mathlib.a。然后，在使用 mathlib.a 归档创建可执行文件 power 之前，它会删除 input.o 和 compute.o 文件。

```
$ cat makefile
CC = gcc
OPTIONS = -O4 -o
OBJECTS = main.o input.o compute.o
SOURCES = main.c input.c compute.c
HEADERS = main.h input.h compute.h

power:          main.o mathlib.a
                $(CC) $(OPTIONS) power main.o mathlib.a -lm
main.o:         main.h input.h compute.h

mathlib.a:      input.o compute.o
                ar rv mathlib.a input.o compute.o
                rm input.o compute.o

all.tar:        $(SOURCES) $(HEADERS) makefile
                tar cvf - $(SOURCES) $(HEADERS) makefile > all.tar

clean:
                rm *.o
$
```

对于这些规则中的每一条，make 实用程序都会执行一系列内置命令，这些命令使用 cc 命令生成目标模块，并使用 ar 命令将该目标模块归档。以下是上述 makefile 的示例运行。在运行 make 命令之前，请确保删除当前目录中存在的 compute.o、input.o、main.o 和 mathlib.a 文件。

```
$ make
gcc    -c -o main.o main.c
gcc    -c -o input.o input.c
```
