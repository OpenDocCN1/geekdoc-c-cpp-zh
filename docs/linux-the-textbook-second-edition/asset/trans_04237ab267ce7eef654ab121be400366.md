

被截断为 0，读写文件指针和 EOF 也被设置为 0。你可以使用 truncate() 或 ftruncate() 系统调用来截断文件。下面是对这些命令的简要描述。

```text
#include <unistd.h>
int truncate(const char *path, off_t length);
int ftruncate(int fd, off_t length);

Success: 0

Failure: -1 and kernel variable errno set to indicate the type of error
```

这些函数将现有文件截断为 length 字节。两者的区别在于 truncate() 使用路径名，而 ftruncate() 使用文件描述符。如果 length 小于文件的现有长度，则文件在 length 字节之后的内容将无法再访问。如果 length 大于当前文件大小，则文件大小会增加到 length，之前的 EOF 与新的 EOF 之间的空间会被零填充并成为一个空洞（参见第 15.8.5 节）。

truncate.c 程序接受两个命令行参数：一个文件和一个数字。它使用 lseek() 系统调用显示文件的大小，使用 truncate() 系统调用将文件截断为作为第二个参数指定的大小，并显示截断后文件的大小。示例运行显示了名为 data 的文件在截断前后的大小。请注意，输入文件的大小也通过 ls -l data 命令得到确认。tail 命令用于显示截断前后 data 文件的尾部。


## 15.8.7 Removing a File

你可以使用 unlink() 系统调用从文件系统结构中删除一个文件。下面是对该调用的简要描述：

```text
#include <unistd.h>
int unlink(const char *path);

Success: 0

Failure: -1 and kernel variable errno set to indicate the type of error
```

该系统调用本质上是将文件 inode 中存储的硬链接计数减 1。如果由此产生的链接计数变为 0 且没有进程打开该文件，则文件将被从文件系统中删除。如果链接计数变为 0 但一个或多个进程打开了该文件，则文件的删除将被延迟，直到文件的引用计数变为 0。如果链接计数不为 0，则文件仍保留在文件系统结构中，其目录项将被删除。一旦文件从文件系统中删除，其目录项、inode 以及与该文件关联的所有其他内核资源都将被归还系统以供回收。

成功完成时，unlink() 返回 0。失败时返回 -1，且 errno 被设置为指示失败原因。表 15.10 显示了 unlink() 调用对常规文件失败的一些常见原因。

以下所示的 create_holes_delete.c 程序是第 15.8.5 节中讨论的 create_holes.c 程序的更新版本。该程序保存原始文件的大小，在其中创建空洞，显示原始文件和带空洞文件的大小，然后删除带空洞的文件。程序使用 lseek() 系统调用确定原始文件和带空洞的新文件的大小。示例运行显示了原始文件和带空洞文件的大小。ls -l data 命令显示程序确实删除了带空洞的文件。

**TABLE 15.10**

Some Common Reasons for the `unlink()` System Call to Fail

| Reason for Failure | Value of `errno` |
| --- | --- |
| The named file is a directory | `EISDIR` |
| The file specified in **path** does not exist | `ENOENT` |
| A component in **path** is not a directory | `ENOTDIR` |
| Search permission is denied on a component of **path** | `EACCES` |
| Write permission does not exist on the directory containing the file/link to be removed | `EACCES` |
| A component in **path** exceeds the file name size limit (255 characters) and the entire path exceeds 1,023 characters | `ENAMETOOLONG` |
| An I/O error occurred while deleting the directory entry for the file or deallocating file’s inode | `EIO` |
| The file to be removed resides on a read-only file system or device | `EROFS` |

```text
$ cat create_holes_delete.c
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

#define HSIZE 512L

int main(int argc, char *argv[])
{
        int fd, i, n, nholes, nw, size_o, size_h;
        char *buf="Random data for creating holes.";

        /* Open the given file */
        if (argc != 3) {
                printf("Inappropriate number of command line arguments.\n");
                exit(0);
        }
        nholes = atoi(argv[2]);
        if ((fd = open(argv[1], O_WRONLY)) == -1) {
                perror("File opening");
                exit(1);
        }
        size_o = lseek(fd, 0, SEEK_END); /* Size of original file */
        for (i=0; i<nholes; i++) {
                n = lseek(fd, HSIZE, SEEK_END);
                nw = write(fd, buf, strlen(buf));
        }
        size_h = lseek(fd, 0, SEEK_END); /* Size of file with holes */
        if (close(fd) == -1) {
                perror("File closing");
                exit(1);
        }
        printf("The size of the original file is %d bytes.\n", size_o);
        printf("The size of the file with holes is %d bytes.\n", size_h);
        unlink(argv[1]);
        return(0);
}
$ man cat > data
$ ls -l data
-rw-r--r-- 1 sarwar faculty 1958 Oct 22 21:43 data
$ gcc create_holes_delete.c -w
$ a.out data 3
The size of the original file is 1958 bytes.
The size of the file with holes is 3587 bytes.
$ ls -l data
ls: cannot access 'data': No such file or directory
$
```

remove() 系统调用对于文件而言等同于 unlink() 系统调用。

## 15.9 Getting File Attributes from a File Inode

回想一下，Linux inode 包含文件的 most 属性，包括以下内容：

- Size (in bytes)
- User (Owner) ID
- Group ID (of the owner)
- File mode and access permissions
- Hard link count
- Times for the creation, last access, and last modification
- Pointers to file blocks on secondary storage

请注意，文件的名称和文件读写指针的当前位置并未存储在文件的 inode 中。文件的名称，如第 4 章和第 15.11 节所述，存储在文件的目录项中，而如第 15.5.2 节所述，文件指针存储在 SFT 中。你可以使用 stat()、lstat() 和 fstat() 系统调用获取存储在其 inode 中的文件的属性副本。这些调用会用各种属性的值填充 stat 结构（`struct stat`），该结构定义在 `<sys/stat.h>` 中。我们在第 15.9.1 节和第 15.9.2 节中分别讨论 stat 结构和这三个调用。

### 15.9.1 The stat Structure

文件的 most，但并非全部属性都存储在文件的 inode 中。例如，如第 4 章所述，文件的 inode 号驻留在文件的目录项中，而不驻留在文件的 inode 中。stat 结构描述了 inode 的一部分。以下定义可在 `/usr/include/asm-generic/stat.h` 文件中找到。

```c
struct stat {
    unsigned long st_dev;        /* Device. */
    unsigned long st_ino;        /* File serial number; inode number */
    unsigned int  st_mode;       /* File mode. */
    unsigned int  st_nlink;      /* Link count. */
    unsigned int  st_uid;        /* User ID of the file's owner. */
    unsigned int  st_gid;        /* Group ID of the file's group. */
    unsigned long st_rdev;       /* Device number, if device. */
    unsigned long __pad1;
    long          st_size;       /* Size of file, in bytes. */
    int           st_blksize;    /* Optimal block size for I/O. */
    int           __pad2;
    long          st_blocks;     /* Number 512-byte blocks allocated. */
    long          st_atime;      /* Time of last access. */
    unsigned long st_atime_nsec;
    long          st_mtime;      /* Time of last modification. */
    unsigned long st_mtime_nsec;
```
