## 17.2.2 Linux 的安装

由于我们将四个代表性的 Linux 系统作为本章中展示的各种事物的模型，因此安装其中任何一个系统的最快方法是遵循随软件提供的在线说明，对应你正在安装的版本。我们在附录 A，第 17.2 节中提供了 Linux Mint 版本 18.2 的安装说明。正如第 17.1 节所述，我们建议将安装限制在单磁盘系统上，其中 Linux 是磁盘上唯一的系统。我们还建议使用以下网站上提供的 64 位 ISO 创建的 DVD 介质，对应你想要安装的特定 Linux 版本：

### 17.2.3.1 启动和启动过程

最简单地说，运行 systemd 控制的 Linux 系统的计算机从断电状态到完全正常运行的顺序是先 Booting，然后是 Startup。这详细显示为

Booting

- 主系统板上的固件找到可启动介质。
- 从可启动介质中，引导加载程序将单块内核从启动介质加载到 RAM 中并启动它。

Startup

- 内核使用引导加载程序传递的命令找到主文件系统，在此之后它可以找到并运行 systemd。
- systemd 运行其他程序以找到文件系统并启动网络和所有必要的本地服务进程。

这里使用的术语“booting”是指将操作系统从完全断电状态带到 systemd 可以接管的点。然后在“startup”中，systemd 将计算机带到稳定状态的完全正常运行条件。

但是当由于某种原因无法进行正常的启动和启动，或者无法实现正常关机时，普通用户该怎么办？

对于启动和启动，除非在 POST 期间暴露了电源或硬件相关问题，例如硬盘或内存故障，否则你可以采取几个步骤来检查可能的问题。你实际上可以在图 17.1 所示的任何步骤中干预。

你可以尝试将系统启动到“救援”模式，通过尝试启动到 systemd 紧急或救援目标状态。这在书网站的第 W27 章，第 2.1 节和 5.1.8.8 节中详细显示。这类似于在启动时进入“单用户”模式的传统操作。

你也可以使用引导加载程序 GRUB2 在启动时进入“恢复”模式。在我们的代表性 Linux Mint 系统上，当 POST 成功完成且就在 GRUB2 接管启动过程之前时，你可以按住键盘上的 Shift 键以进入 GRUB2 菜单。在其他 Linux 系统上，该中断可能不同。

请注意，我们在此没有给出 GRUB2 配置和修改的细节。

GRUB2 菜单的高级选项包括启动到替代或之前的“启动环境”的选择，以及进入这些环境的恢复模式。这些环境通常根据内核版本命名。因此，如果你在计算机系统使用过程中升级了操作系统内核，不同内核的不同环境将可供你使用。对于普通用户来说，在启动阶段通过进入这些系统状态来排除系统故障的选择是一个有用的可能性，有助于你恢复数据、日志和其他有价值的信息。

当系统在关机过程中挂起时，诊断问题的一种当代方法是使用 journalctl 命令检查 systemd 日志，如第 W27 章，第 27.2.4 节和 6.2 节所示。这样，如果某个进程或程序阻止系统达到断电状态，日志记录将允许你看到该进程或程序是什么。在关机时，systemd 尝试停止所有服务并卸载所有文件系统。系统最终被断电。我们在下一节中提供了有关使用 systemd 的 Linux 系统如何关机的更多细节。
