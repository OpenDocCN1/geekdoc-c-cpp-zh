
# 9.9 在一条命令中重定向stdin、stdout和stderr

图9.9 输出和错误重定向：（a）cat命令的文件描述符和标准文件；（b）执行cat lab1 lab2 lab3 2>&1后标准文件，stdout和stderr不变；（c）执行cat lab1 lab2 lab3 2>&1 1> cat.output.errors后的标准文件；（d）命令语义。

标准输入、标准输出和标准错误可以在一条命令中按照以下语法进行重定向。

```
Syntax:
command 0< input-file 1> output-file 2> error-file
Purpose: Input to command comes from input-file instead of the keyboard, output of command goes to output-file instead of the display screen, and error messages generated by command are sent to error-file instead of the display screen
```

文件描述符0和1不是必需的，因为它们分别是<和>运算符的默认值。此命令语法的语义如图9.10所示。

命令行内容中文件重定向的求值是从左到右进行的，因此重定向的顺序很重要。考虑以下命令语法。对于第一个命令，如果未找到输入文件，错误消息会发送到显示屏，因为stderr尚未被重定向。对于第二个命令，如果未找到输入文件，错误消息会发送到错误文件，因为stderr已被重定向到该文件。如果错误文件存在，第一个和第二个命令的输出分别发送到stdout和输出文件。

```
command 1> output-file 0< input-file 2> error-file command 2> error-file 1> output-file 0< input-file
```

下面的sort命令对一个名为students的文件中的行进行排序，并将排序后的文件保存到students.sorted中。如果sort命令因为students文件不存在而启动失败，错误消息将按所示发送到显示屏，而不是发送到sort.error文件。原因是，在shell确定students文件不存在时，stderr仍然连接到控制台。

```
$ sort 0< students 1> students.sorted 2> sort.error
cannot open students: No such file or directory
$
```

对于下面的命令，如果sort命令因为students文件不存在而失败，错误消息将发送到sort.error文件。原因是shell先处理错误重定向，然后才确定students文件不存在。

```
$ sort 2> sort.error 0< students 1> students.sorted
$ cat sort.error
cannot open students: No such file or directory
$
```

# 9.10 不覆盖文件内容的重定向（追加）

默认情况下，输出和错误重定向会覆盖目标文件的内容。要将命令产生的输出或错误追加到文件末尾，请将>运算符替换为>>运算符。使用>>时默认文件描述符为1，但可以使用文件描述符2将错误追加到文件。在以下命令中，ls -l的输出追加到output.dat文件中，错误消息追加到error.log文件中。

```
$ ls -l 1>> output.dat 2>> error.log
$
```

下面的命令将memo和letter文件的内容追加到stuff文件的末尾。如果命令产生任何错误消息，它将发送到error.log文件。如果error.log是现有文件，其内容将被错误消息覆盖。

```
$ cat memo letter >> stuff 2> error.log
$
```

如果要保留error.log的现有内容并将新的错误消息追加到其中，请使用以下命令。对于此命令，cat命令产生的任何错误消息都会追加到error.log之前的内容之后。

```
$ cat memo letter >> stuff 2>> error.log
$
```

Bourne shell默认在命令的stdout或stderr被重定向到文件时覆盖该文件，但Korn、TC和Bash shell具有noclobber选项，可防止您意外覆盖重要文件。我们将在9.13节讨论TC shell的此选项，但这里讨论Bash shell。

您可以使用带-o选项的set命令来设置Bash shell中的noclobber选项，如下所示。当然，如果要永久设置此选项，请将该命令放在~/.profile文件中。

```
$ set -o noclobber
$
```

在Bash shell中，还可以使用set -C命令设置该选项。设置noclobber选项后，可以使用>|运算符强制覆盖文件。

# 9.11 Linux管道

Linux系统允许将命令的stdout连接到另一个命令的stdin。可以使用管道字符（|）按以下语法实现。

语法：
command1 | command2 | command3 | ... | command

用途：command1的标准输出连接到command2的stdin，command2的stdout连接到command3的stdin，……，commandN-1的stdout连接到commandN的stdin。

图9.11说明了此命令的语义。

因此，管道允许您将命令的输出作为输入发送给另一个命令。通过管道连接的命令称为过滤器。过滤器属于一类Linux命令，它们从stdin接收输入，以某种特定方式处理，然后发送到stdout。在Linux中，管道和过滤器经常用于完成单个命令无法完成的复杂任务。一些常用的过滤器有cat、compress、crypt、grep、less、lp、more、pr、sort、tr、uniq和wc。如果管道输出端的命令处理输入的速度比连接到其输入端的命令慢，管道会存储多余的数据，并以先进先出的方式将其提供给输出端的命令。因此，如果图9.11中的cmd2处理传入数据的速度慢于cmd1产生数据的速度，则cmd1产生的多余数据会存储在cmd1和cmd2之间的管道中，管道以先进先出的方式将其提供给cmd2。在Linux中，可以不间断（即以原子方式）写入管道的最大数据量由/usr/include/linux/limits.h中的符号常量PIPE_BUF决定。

![](img/2a18e06cd9c6395e451f26126ecba1fd_246_1.png)

图9.12 ls -l | more命令的语义。

例如，在ls -l | more中，more命令将ls -l的输出作为其输入。此命令的净效果是，ls -l的输出每次显示一屏。管道实际上就像一个水管，将ls -l的输出取出并作为输入交给more，如图9.12所示。

此命令不使用磁盘将ls -l的标准输出连接到more的标准输入，因为管道在主内存的内核区域中实现。就I/O重定向运算符而言，该命令等价于以下命令序列。

```
$ ls -l > temp
$ more < temp (or more temp)
[contents of temp]
$ rm temp
$
```

如您所见，不仅需要三个命令来完成同样的任务，而且命令序列也极其缓慢，因为涉及文件读和写操作。回想一下，文件存储在辅助存储设备（通常是磁盘）上。在典型的当代计算机系统中，磁盘操作比主内存（随机存取存储器）操作慢约一百万倍。然而，由于Linux内核高效地缓存文件块以及使用半导体磁盘，管道实际带来的性能提升要小得多。

您可以使用第7章讨论的sort工具对文件中的行进行排序。假设您有一个名为student_records的文件要排序，并且该文件可能有一些重复行，希望在排序后的文件中只出现一次。sort -u student_records命令可以完成此任务。正如第6章所讨论的，如果将带有重复行的student_records的排序版本提供给uniq命令，它也可以完成此任务。执行此任务的一种方法是使用以下命令。more命令用于显示student_records的内容。

```
$ more student_records
John Doe      ECE    3.54
Pam Meyer     CS     3.61
Jim Davis     CS     2.71
John Doe      ECE    3.54
Jason Kim     ECE    3.97
Amy Nash      ECE    2.38
Kim Coleman   CS     3.19
$ sort student_records > student_records_sorted
$ uniq student_records_sorted
Amy Nash      ECE    2.38
Jason Kim     ECE    3.97
Jim Davis     CS     2.71
John Doe      ECE    3.54
Kim Coleman   CS     3.19
Pam Meyer     CS     3.61
$
