Linux不会对这些文件中的任何一个进行区别对待。它不会赋予文件内容结构或含义，因为每个文件只是一系列字节。含义是由使用/处理文件的应用程序附加到文件内容上的。例如，在Linux看来，C程序文件与网页的超文本标记语言（HTML）文件或视频剪辑文件没有区别。然而，C编译器（如cc或gcc）、Web浏览器（如Firefox）和视频播放器（如VLC Media Player）对这些文件的处理方式却不同。

你可以按照自己选择的任何约定来命名文件；Linux不会对任何类型的文件强加命名约定。在大多数Linux系统上，文件名的默认最大长度为255个字符。你可以使用Linux系统中的getconf命令来显示或配置文件名的最大字符数。

尽管你可以使用任何字符作为文件名，但我们强烈建议不要使用不可打印字符、空白字符（空格和制表符）以及shell元字符（如第2章所述），因为它们作为文件名的一部分很难处理。你可以为文件名指定任何自己定义的或应用程序定义的扩展名，但这些扩展名对Linux系统来说毫无意义——它们只是被视为文件名的一部分。例如，你可以给文档加上.exe扩展名，给可执行程序加上.doc扩展名。有些应用程序需要扩展名，而有些则不需要。例如，所有C编译器都要求C源程序文件具有.c扩展名，但并非所有Web浏览器都要求网页文件具有.html扩展名。即便如此，还是应该使用扩展名——这有助于跟踪哪些文件用于什么目的。表4.2中列出了一些常用的扩展名。

### 4.3.2 目录

目录包含其他文件和/或目录的名称（术语“目录”和“子目录”可以互换使用）。在某些系统中，文件夹（folder）、抽屉（drawer）或文件柜（cabinet）等术语也用来指代目录。在任何操作系统中，目录文件都由一组目录项组成，尽管目录项的内容因系统而异。在Linux中，目录项的结构如图4.1所示。

inode编号长四个字节，是磁盘上数组的索引值。该数组的一个元素称为索引节点，通常简称为inode，包含文件的属性，如文件大小（以字节为单位）。当你创建新文件时，Linux内核会为其分配一个inode。因此，Linux中的每个唯一文件都有一个唯一的inode（和inode编号）。正如4.5.7节和第8章所讨论的，文件的硬链接具有相同的inode，并且inode在每个分区内是唯一的。这意味着不同分区上的两个不同文件可以具有相同的inode编号。有关inode的详细信息以及内核如何使用它来访问磁盘上文件内容，将在4.5.7和4.6节中讨论。

### 4.3.3 链接文件

类型为“链接”的文件“指向”一个现有文件。链接文件的内容是现有文件的路径名。因此，链接文件允许你通过文件系统结构中的另一条路径访问现有文件，并在不复制其内容的情况下共享它。Linux中链接的概念将在第8章中详细讨论。但目前，当创建指向现有文件的符号链接时，系统会创建一个类型为链接的文件。符号链接目前在所有Linux版本上都可用。

### 4.3.4 特殊（设备）文件

*特殊文件*，也称为*设备节点*，是访问硬件设备的一种手段，包括键盘、磁盘、磁带驱动器、显卡、网卡和打印机。每个硬件设备至少与一个特殊文件相关联——命令或应用程序通过访问特殊文件来访问相应设备。特殊文件分为两种类型：*字符特殊文件*和*块特殊文件*。字符特殊文件对应于面向字符的设备，如键盘；块特殊文件对应于面向块的设备，如磁盘。特殊文件通常放在**/dev**目录中（更多细节参见4.4节）。

应用程序和命令读写外围设备文件的方式与读写普通文件相同。这种能力是Linux输入输出被称为*设备无关*的主要原因。各种特殊设备模拟物理设备，因此被称为*伪设备*。这些设备允许你在不使用物理连接到Linux系统的设备的情况下与其交互。这些设备变得越来越重要，因为它们允许通过网络连接或通过第W28章中的ssh隧道虚拟终端使用Linux系统。

### 4.3.5 命名管道（FIFO）

Linux有几种工具使进程能够相互通信。这些工具是普遍存在的客户端-服务器软件范例的关键，被称为*进程间通信（IPC）机制*（通常称为*IPC原语*或*IPC通道*）。这些原语称为*管道*、*命名管道*（也称为*FIFO*）和*套接字*（严格符合UNIX System V的系统具有称为*传输层接口*的机制）。这些原语将在第15、16、W20和W21章的“系统编程”下详细讨论。这里，我们简要提及每种原语的目的，以便你理解每种机制的必要性并理解FIFO的需求。

管道是内核内存（内核缓冲区）中的一个区域，允许两个进程相互通信，前提是这两个进程在同一台计算机系统上运行并且彼此相关；通常，这种关系是父子或兄弟关系。FIFO是一种文件（命名管道类型），如果两个进程在同一台计算机上，则允许它们相互通信；但是，这些进程不必通过父子或兄弟关系彼此相关。我们将在第9章的命令级别说明管道和FIFO的用法。

### 4.3.6 套接字

套接字可用于同一台计算机或不同计算机上的进程之间相互通信；这些计算机可以在网络（内联网）上，也可以在Internet上。套接字可以属于不同的地址族，每个地址族指定进程通信时要使用的协议套件。例如，超文本传输协议（HTTP）等应用层协议使用传输控制协议/互联网协议（TCP/IP）协议套件中的**AF_INET**地址族套接字进行通信（有关TCP/IP的详细讨论，参见第11章）。具有**AF_INET**地址族的套接字也称为*Internet域套接字*，这意味着Internet上计算机上运行的进程可以使用此域的套接字相互通信。具有**AF_UNIX**或**AF_LOCAL**地址族的套接字可用于在Linux操作系统下同一台机器上运行的进程之间的通信。这种套接字也称为*UNIX域套接字*。有关UNIX和Internet域套接字的更多详细信息，请参见第W20章。

## 4.4 文件系统结构

操作系统的文件系统结构涉及三个问题。第一个是从用户的角度看系统中的文件是如何组织的。第二个是文件如何存储在辅助存储（通常是硬盘）上。第三个是如何操作文件（读取、写入等）。在本章中，我们将讨论第一个问题，即Linux系统中文件和目录的用户视图。到目前为止，我们的重点一直放在Mint Linux上。

### 4.4.1 文件系统组织

Linux文件系统按层次结构组织，呈树状，但上下颠倒，根在顶部。因此，文件系统结构从一个称为根目录的主目录开始，其下可以有任意数量的文件和子目录，并按任何期望的方式组织。这种结构导致目录与其子目录/文件之间存在父子关系。典型的Linux系统包含数百个文件和目录。对于我们的Linux Mint系统，根目录下的文件和目录（在Linux术语中表示为/）如下所示：
