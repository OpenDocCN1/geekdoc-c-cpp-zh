
a process. Linux 操作系统使用信号来引起进程的注意。你可以向你拥有或有权操作的进程发送 Linux 系统支持的任意一种信号类型。进程在接收到信号后可以采取以下三种操作之一：

- 1. 接受 Linux 内核确定的默认操作
- 2. 忽略该信号
- 3. 拦截信号并执行用户定义的操作

对于大多数信号，默认操作除了其他一些事件外，总是会导致进程终止。忽略信号不会对进程产生任何影响。用户定义操作被指定为程序语句（通常是函数调用），它将控制权转移到进程中的特定代码段。在 shell 脚本中，你可以使用 Bash shell 中的 trap 命令指定这些操作。C shell 通过 onintr 命令提供有限的信号处理。在 C 程序中，你可以使用库调用 signal 指定这些操作。我们将在第 13 章详细介绍 trap 命令。我们将在第 17 章详细介绍 signal(2) 系统调用。欲了解更多详情，请使用 man signal 或 man -S3 signal 命令查看其手册页。

信号可以因各种原因而产生。这些原因中的一些是由进程本身引起的，而另一些则与进程外部有关。由进程内部事件引起的信号被称为内部信号或陷阱（不要与 Bash shell 中的 trap 命令混淆）。例如，进程中执行除零指令会产生陷阱。由进程外部事件或计算机系统中的硬件设备引起的信号称为外部信号。如果外部信号是针对 CPU 或磁盘控制器等硬件设备，则称为硬件中断或中断。旨在引起一个或多个进程注意的外部事件在 Linux 术语中被称为软件中断或信号。例如，当进程尝试执行不存在的指令或访问其无权访问的内存区域时，例如属于其他进程或 Linux 内核的内存，就会为该进程生成内部信号。你可以通过按下 <Ctrl+C>、注销或使用 kill 命令生成外部信号。kill 命令可用于向进程发送任何类型的信号。下面是对 kill 命令的简要描述。

**Syntax:**
`kill [-s signal_name] proc-list`
`kill [-signal_name] proc-list`
`kill [-signal_number] proc-list`
`kill -l [exit_status]`
**Purpose:** Syntaxes 1–3: 向 PID 或 jobID 在以空格分隔的 **proc-list** 中指定的进程发送 **signal_number** 或符号 **signal_name** 的信号；jobID 必须以 % 开头。
Syntax 4: 命令 kill -l 返回所有信号及其编号和名称的列表。操作数 **exit_status** 指定信号编号或终止或完成的进程的退出状态。
**Commonly used options/features:**
1 HUP (Hang-up)
2 INT (Interrupt: <Ctrl+C>)
3 QUIT (Quit: <Ctrl+\>)
6 ABRT (Abort)
9 KILL (Sure kill: Nonignorable, noninterceptable)
14 ALRM (Alarm clock)
15 TERM (Software termination: the default signal number)

挂断信号在你注销时生成，中断信号在你按下 <Ctrl+C> 时生成，退出信号在你按下 <Ctrl+\> 时生成。kill 命令向作为参数指定的 PID 的进程发送信号号 15。此信号的默认操作是终止接收它的进程。此信号可以被进程拦截和忽略，就像大多数其他信号一样。要终止忽略信号 15 或其他信号的进程，必须向其发送信号号 9，即所谓的 sure kill。kill 命令会终止 proc-list 中给出的所有进程的 PID，前提是这些进程属于使用 kill 的用户。以下会话展示了一些使用 kill 命令的实例。但不要杀死登录 shell 进程，因为它会让你注销。

```
$ jobs -l
[1]  + 14338 Running          sort bigdata > bigdata.sorted
[2]  - 14667 Running          cp biggerdata biggerdata.bak
[3]      14668 Running         grep sh biggerdata > lines.sh
$ kill 14668
$ kill -2 14667
[3]  Terminated               grep sh biggerdata > lines.sh
$ kill -9 14338
[2]  Interrupt                cp biggerdata biggerdata.bak
$ jobs
[1]  Killed                   sort bigdata > bigdata.sorted
$ jobs
$
```
