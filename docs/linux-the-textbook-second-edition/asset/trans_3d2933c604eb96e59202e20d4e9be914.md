第一个示例只包含命令。第二个示例包含命令 `ls` 和两个选项 `l` 和 `a`。第三个示例包含命令 `ls`、两个选项 `l` 和 `a`，以及一个命令参数 `m*`。第四个示例包含命令 `lpr`、两个选项 `P` 和 `n`、两个选项参数 `spr` 和 `3`，以及一个命令参数 `proposal.txt`。

你还应该使用以下经验法则：如果命令正确执行，那么你会返回 shell 提示符；如果命令未正确执行，那么命令行上会显示错误消息，然后你会返回 shell 提示符。例如，如果你在命令行上输入 `xy` 然后按下 `<Enter>`，通常你会收到一条错误消息，提示找不到该命令，然后你会返回 shell 提示符，以便输入有效命令。

这一经验法则并不能确保你在命令行上输入语法正确的命令所想达到的目的就一定会实现。也就是说，你可能执行了一条命令并得到了无错误消息的结果，但该命令可能并没有完成你想要它做的事情，仅仅是因为你使用了错误的选项或命令参数！

## 2.3 登录与注销

如何登录 Linux 计算机并优雅地离开？

可以使用以下通用方式之一，或它们的混合组合方式：

- 独立式：使用独立系统，其中 Linux 是硬件上唯一的操作系统。
- 远程：从运行 Linux 或其他操作系统的计算机连接到运行 Linux 的远程计算机。
- 虚拟：在虚拟环境中将 Linux 作为客户操作系统启动，例如 Linux 容器版 C/Linux 容器版 D（LXC/LXD）容器或 VirtualBox，而另一个操作系统作为计算机硬件上的主机系统。

这些通用方式是用户在典型 Linux 会话中采取的第一步，以安全、自主的方式正确访问 Linux 系统。就单个用户而言的自主性，操作系统被看作一个虚拟、并发且持久的环境。它提供“仿佛”她是唯一用户的服务，能够同时执行许多操作，并确保这些操作随时间被安全地保留。

这些方式的更详细描述如下：

1. 独立式：这种方式是最常见的情况，也是我们在本书其余部分采用的方法，即坐在一台可以完全独立运行的计算机前。这并不意味着独立计算机没有连接到局域网（LAN）、内联网或互联网。

   相反，用户与 Linux 的连接在某一时刻专用于单个用户（或可能多个自主用户在不同的时间分别登录到同一系统），即坐在计算机前并登录，独占使用该硬件平台上的 Linux。

2. 远程：使用这种方式有几种变体。这里仅举两个可能的场景：
   - 你坐在一台类似传统终端、连接至大型机的计算机前。这也可能是一台连接到服务器的瘦客户端（一种配置和能力最低限度的设备）。它通过高速通信链路连接到另一台单台计算机或多台通过局域网或互联网互连的计算机。在终端以及其屏幕上出现的控制台或命令窗口中，你与操作系统的界面运行在一台甚至多台其他计算机上。这是一种共享资源方法，多台不同终端上的多个用户可以共享一个 Linux 系统。
   - 你坐在一台独立计算机或设备前，通过 PuTTY、安全外壳（SSH）或 SSH X Windows 转发（传输控制协议（TCP）端口转发的一种变体）等软件，通过高速电信链路连接到另一系统。PuTTY 或 SSH 软件随后成为你的图形连接，允许你登录并使用正在运行 Linux 的远程计算机或系统。这通常是一种共享资源方法，许多不同远程计算机上的多个用户可以共享一个 Linux 系统。这种方式的一种变体是使用虚拟专用网络及其互连软件，从移动设备（如手机或平板电脑）通过互联网远程登录系统。
3. 虚拟：你安装了 Linux 或类 UNIX 操作系统（如 OS X）或其他操作系统，并正在你面前的计算机上运行，并且你在这台计算机上安装了 VirtualBox 等虚拟环境。然后，当你想使用 Linux 系统时，只需切换环境，使虚拟环境中的 Linux 系统成为你与计算机硬件交互的界面。另一种变体是使用基于云的操作系统，它作为“实例”存在于服务器上，你通过 Web 浏览器合法登录到该服务器上。

我们在本章不涉及虚拟连接。但在本书网站的标题为“虚拟化方法论”的第 W23 章中，我们涵盖了 LXC/LXD 和 VirtualBox 等虚拟环境。我们将在那一章中说明连接虚拟机的方式。

### 2.3.1 独立式登录连接到 Linux

本节中显示的登录和注销程序是标准的，在所有 Linux 和类 UNIX 系统之间仅略有差异。这种方式假设在你到达计算机之前，有人已经正常注销或重新启动了计算机，但没有关闭计算机的硬件或操作系统。

在本节中，我们还作出以下基本假设：

1. 你将要登录的是一台已经运行且以 Linux 为操作系统的计算机。
