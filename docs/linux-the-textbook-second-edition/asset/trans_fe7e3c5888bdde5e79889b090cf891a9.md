### 9.5 组合输入和输出重定向

输入和输出重定向可以根据以下命令说明中给出的语法一起使用。

```
Syntax:
    command < input-file > output-file
    command > output-file < input-file
Purpose: Input to command comes from input-file instead of the keyboard and output of command goes to output-file instead of the display screen
```

使用此语法时，command 从 input-file 而不是终端附带的键盘获取输入，并将其输出发送到 output-file 而不是显示屏，如图 9.5 所示。

在 `cat < lab1 > lab2` 命令中，cat 命令从 lab1 文件获取输入并将其输出发送到 lab2 文件。此命令的净效应是 lab1 的副本被创建在 lab2 中。因此，此命令行等同于 `cp lab1 lab2`，前提是 lab2 不存在。如果 lab2 是已存在的文件，则这两个命令的语义不同。`cat < lab1 > lab2` 命令会截断 lab2 将其大小设置为零并将读写指针设置为第一个字节位置 并用 lab1 的内容覆盖它。因为 lab2 没有被重新创建，其属性 例如访问权限和链接计数 未被更改。在 `cp lab1 lab2` 命令的情况下，不仅 lab1 中的数据被复制到 lab2 中，而且其 inode 中的属性也被复制到 lab2 的 inode 中。因此，cp 命令导致 lab1 的真正副本 数据和属性 被复制到 lab2 中。

### 9.6 使用文件描述符进行 I/O 重定向

如第 4.6 节所述，Linux 内核为每个打开的文件关联一个小的整数，称为该文件的 *文件描述符*。标准输入、标准输出和标准错误的文件描述符分别为 0、1 和 2。Bash 和便携式操作系统接口 POSIX shell 允许您打开文件并将文件描述符与之关联；TC shell 不允许使用文件描述符。其他描述符，通常从 3 开始使用，当进程同时打开文件时使用。这些描述符称为用户定义文件描述符。这些描述符的上限 以及因此进程可能同时打开的文件数 因系统而异，可以通过运行 `ulimit -n` 命令来确定。每个描述符用于索引一个内核表，称为 *每个进程的文件描述符表*，如第 4.7 节中简要讨论的那样。对此主题的更详细讨论可在第 15 章和第 16 章以及本书网站上的第 W20 章和第 W21 章中找到。在以下各节中，我们在 Bash 和 POSIX shell 下描述 I/O 和错误重定向。我们在第 9.13 节中讨论 TC shell 语法并给出示例。

通过使用文件描述符，标准输入和标准输出可以在 Bash 和 POSIX shell 中分别使用 0< 和 1> 操作符进行重定向。因此，`cat 1> outfile`，等同于 `cat > outfile`，从标准输入获取输入并将其发送到 outfile；错误消息发送到显示屏。同样，`ls -l foo 1> outfile` 等同于 `ls -l foo > outfile`。此命令的输出 foo 的长列表 进入名为 outfile 的文件，而由此产生的错误消息发送到显示屏。

文件描述符 0 可以与 < 操作符一起用作前缀，以明确指定从文件输入重定向。在以下会话中显示的命令中，grep 命令的输入是当前工作目录中 tempfile 的内容。

```
$ grep "John" 0< tempfile
... command output ...
$
```

### 9.7 重定向标准错误

可以使用 2> 操作符 将命令的标准错误重定向，如下所示：

> Syntax:
>   command 2> error-file
> 
> Purpose: Error messages generated by command and, by default, sent to stderr are redirected to error-file

使用此语法时，command 从键盘获取输入，将其输出发送到监视器屏幕，command 产生的任何错误消息都发送到 error-file。命令语义如图 9.6 所示。命令输入可以来自作为命令行参数传递的文件。

命令 `grep "John" Phones 2> error.log` 从 Phones 文件获取输入，将输出发送到显示屏，grep 产生的任何错误消息都发送到名为 error.log 的文件。如果 error.log 已存在，则会被覆盖；否则会被创建。以下示例显示了如何将 ls -l 的标准错误重定向到文件。

```
$ ls -l foo 2> error.log
... long listing for foo if no errors ...
$
```

`ls -l foo` 的输出发送到显示屏，错误消息发送到 error.log。因此，如果 foo 不存在，错误消息 `ls: foo: No such file or directory` 会进入 error.log 文件，如以下会话所示。消息的实际措辞因系统而异，但基本上会通知您 foo 不存在。

```
$ ls -l foo 2> error.log
$ cat error.log
ls: foo: No such file or directory
$
```

在许多情况下，保持标准错误连接到显示屏而不将其重定向到文件是有用的。例如，当执行 `cat lab1 lab2 lab3 > a11` 命令将文件 lab1、lab2 和 lab3 串联到名为 a11 的文件时，您希望知道三个输入文件中的任何一个是否不存在，或者您是否没有权限读取它们。在这种情况下，将错误消息重定向到文件意义不大，因为您希望立即看到命令执行的结果。

### 9.8 在一个命令中重定向 stdout 和 stderr

标准输出和标准错误可以重定向到同一个文件。一种明显的方法是使用文件描述符与 > 符号将 stdout 和 stderr 重定向到同一个文件，如以下命令所示。

```
$ cat lab1 lab2 lab3 1> cat.output 2> cat.errors
$
```

在这种情况下，cat 命令的输入来自 lab1、lab2 和 lab3 文件，其输出发送到 cat.output 文件，任何错误消息发送到 cat.errors 文件，如图 9.7 所示。

**图 9.8** 错误重定向：(a) 文件描述符和标准文件；(b) cat lab1 lab2 lab3 1> cat.output.errors 2>&1 和 cat lab1 lab2 lab3 2> cat.output.errors 1>&2 命令的语义。

请注意，虽然未在图 9.7b 中显示，但文件 lab1、lab2 和 lab3 在被 cat 命令打开以供读取时已分配了文件描述符。如果三个“lab”文件中的任何一个不存在，或者您没有读取这些文件的权限，命令会产生错误消息。

以下命令将 cat 命令的 stdout 和 stderr 重定向到 cat.output.errors 文件。因此，同一个文件 cat.output.errors 包含 cat 命令的输出，以及命令可能产生的任何错误消息。

```
$ cat lab1 lab2 lab3 1> cat.output.errors 2>&1
$
```

在此命令中，字符串 `2>&1` 告诉命令 shell 使描述符 2 成为描述符 1 的副本，从而使错误消息发送到命令输出发送到的同一位置。同样，字符串 `1>&2` 可用于告诉命令 shell 使描述符 1 成为描述符 2 的副本。因此，以下命令实现了相同的任务。图 9.8 显示了这两个命令的语义。

```
$ cat lab1 lab2 lab3 2> cat.output.errors 1>&2
$
```

文件重定向的命令行内容的求值是从左到右进行的。因此，如果一种记法依赖于另一种记法，重定向必须按从左到右的顺序指定。在前面的命令中，首先，stderr 被更改为文件 cat.output.errors，然后 stdout 成为 stderr 的副本。因此，命令的输出和错误都发送到同一个文件 cat.output.errors。

因此，以下命令不具有前面讨论的两个命令的效果。原因是，在此命令中，stderr 在输出重定向之前被设为 stdout 的副本。因此，stderr 首先成为 stdout 的副本 此时的显示屏 然后 stdout 被更改为文件 cat.output.errors。因此，命令的输出发送到 cat.output.errors，错误发送到显示屏。图 9.9 中显示的序列说明了此命令的语义。

```
$ cat lab1 lab2 lab3 2>&1 1> cat.output.errors
$
```

请注意，图 9.9a 和 b 相同，因为执行 `cat lab1 lab2 lab3 2>&1` 不会对 stdout 和 stderr 做出任何更改 它们在命令执行之前和之后都连接到显示屏。
