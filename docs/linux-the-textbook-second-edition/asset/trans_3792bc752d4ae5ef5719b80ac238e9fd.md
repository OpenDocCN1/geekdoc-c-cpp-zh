## 17.9.4 Linux Security Software

所有较大的 Linux 计算机服务器系统，以及普通用户使用的单个桌面系统，都可以拥有多种基于网络和基于主机的安全软件，以检测恶意活动、保护系统和数据，并支持入侵检测和对其的适当响应。它们可以归纳为以下类别：

- IDS and IPS
- Remote Access Software
- Web Proxies
- Vulnerability Management Software
- Authentication Servers
- Routers
- Firewalls
- Network Quarantine Servers

我们介绍了入侵检测的一些细节，并在下一节中对防火墙进行了更完整的描述。

### 17.9.4.1 System Firewall

防火墙是一种防止对私有网络或计算机进行未经授权的访问或从其访问的设施。防火墙可以在硬件、软件或两者结合中实现。防火墙主要用于防止从互联网对私有网络或内网进行未经授权的访问。进入或离开单个计算机或内网的所有流量都必须经过防火墙，防火墙检查每条消息并阻止不符合指定安全标准或防火墙规则的消息。

除了限制对计算机和网络的访问外，防火墙还可用于通过安全身份验证证书和登录允许远程访问私有网络。常见的做法是让一台独立的计算机充当私有网络的单一硬件防火墙。

硬件防火墙可以作为独立产品购买。它们也可以集成在宽带路由器中，例如 Actiontec PK5000。大多数硬件防火墙至少有四个网络端口来连接其他计算机，但对于更大的网络，可以使用企业网络防火墙解决方案。

在 Linux 中，如果防火墙处于活动状态（已启用或正在运行），通常所有传入流量都会被阻止，直到你指定允许流量进入的 TCP 或 UDP 端口。此外，通常所有端口上的所有传出流量都被允许。在以下各节中，我们描述了 Debian 系列 Linux（包括 Debian、Ubuntu 和 Linux Mint）的 Uncomplicated FireWall（ufw），以及 CentOS 的 firewalld。

要确定防火墙是否处于活动状态，请在我们的代表性 Linux 系统中的任何一个上使用以下 systemd 命令：

```
$ systemctl status firewall_name
```

其中 firewall_name 在 Debian 系列中是 ufw，在 CentOS 中是 firewalld。

### 17.9.4.2 ufw and Netfilter Interface in Debian Linux Family

Debian 系列 Linux 使用 ufw 来保护系统。根据第 17.2 节中的建议安装我们的系统时，默认情况下 ufw 未安装在 Debian 上，但在 Ubuntu 和 Linux Mint 上已安装并处于活动状态。Ubuntu 上阻止了传入流量，但在 Linux Mint 上未阻止。两个系统上的传出流量均已安装且*未*被阻止。其规则的默认配置文件位于 /etc/ufw/ufw.conf。你了解更多关于防火墙规则文本修改的最简单方法是查看 Linux 系统上的 ufw 手册页。我们在书网站的第 W26 章第 9.6.2 节提供了使用命令行方法修改防火墙规则的基本细节的广泛部分，标题为“Linux Uncomplicated Firewall (ufw)”。

除非你的安全模型及其对特定用例的影响需要防火墙规则定制，否则绝对没有必要更改 ufw 防火墙规则。我们在下一节中对 ufw 进行了总体概述。

#### 17.9.4.2.1 Linux ufw

Linux Mint 的默认防火墙配置实用程序是 ufw。与 iptables 防火墙配置实用程序等其他基于规则的防火墙系统不同，ufw 是创建 IPv4 或 IPv6 主机防火墙的更简单方法。“基于规则的系统”意味着你创建语法正确的规则来控制对系统的网络连接访问。ufw 的最基本应用是允许或拒绝端口上的访问，或拒绝来自你已知存在安全风险的特定 IP 地址的访问。

ufw 基于 Linux 内核的 Netfilter 接口，特别是该接口中发现的 filter 表操作和协议。规则格式也类似于 OpenBSD UNIX 中的 Packet Filter 语法。

### 17.9.4.3 firewalld in CentOS

firewalld 是我们 CentOS 系统的默认防火墙管理工具。与 ufw 类似，它通过充当 Linux 内核提供的 iptables 数据包过滤系统的前端来提供广泛的安全功能。firewalld 的代码用 Python 编写。

firewalld 支持 IPv4 和 IPv6 网络，最显著的是能够管理单独的防火墙“区域”。每个区域可以有不同的规则配置。你可以配置 CentOS 上的 Network Manager 以自动切换区域配置。

非常重要的是，鉴于 systemd cgroups 控制，系统服务和应用程序可以使用 D-Bus 接口与 firewalld 交互。D-Bus 接口，或 Desktop Bus，是一种用于进程间通信和远程过程调用的基于软件的总线架构。它允许在同一系统上运行的进程之间进行通信。

firewalld 支持定时规则，这意味着例如可以限制对 Web 服务器的连接（或“命中”）数量。firewalld 不能限制来自已知安全风险 IP 或 URL 的传入命中，类似于 fail2ban 等应用程序。Fail2ban 使用命中计数和按源 IP 地址的服务拒绝来防止暴力破解和分布式拒绝服务攻击。这是在制定安装后软件需求时的一项有效设计约束，正如我们在第 17.2.1 节中所做的那样。

有关 firewalld 的更深入信息，请参阅书网站第 W26 章第 9.7 节。

## 17.9.5 Persistent Media Security

系统管理员可以采取两种基本策略来保护持久性介质，例如旋转式和 SSD 硬盘，包括 USB 挂载介质，并加固这些介质上的文件系统结构。这两种策略的实际技术与本章其他各节中所示的其他系统管理任务有很大重叠。

重叠技术的示例可以在向系统添加硬盘时找到，也许使用 ZFS 为这些磁盘提供冗余，如第 17.4 节中所示的推荐存储模型。这允许系统管理员将用户文件和系统的其他组件隔离开来。这种隔离提供了一种隔离这些资源的方式，因此可以更安全地访问它们。添加额外的磁盘解决了管理员备份重要数据、最重要的用户数据文件的责任。

第一个策略涉及提供额外的物理介质，或现有介质上的额外分区，以容纳用户数据文件，或 Linux 文件系统的其他组件。

第二个策略涉及在这些额外分区或介质上设计和实施文件和目录访问权限，以便通过各种形式的进程凭据进行进程身份验证。

### 17.9.5.1 Persistent Media Allocations for /home

根据第 17.2.1 节中提供的推荐用户数据存储模型，你应该将 /home 子目录，即所有用户目录所在的位置，放在自己的物理介质上。这是一种传统系统管理员设计文件系统结构的技术。当你向此介质上的单个格式化分区添加挂载选项时，可以执行以下操作：

- 设置 nosuid 选项以防止从那里运行具有 SUID 和 SGID 权限启用的可执行程序。出于预防措施，需要 SUID 和 SGID 权限的程序不应存储在 /home 中。
