

当你注销时，你会话中运行的所有进程都会收到挂断信号（信号编号 1）并按默认操作终止。如果你希望进程在你注销后继续运行，你需要以这样的方式执行它们，使其在收到该信号时忽略挂断信号。你可以使用 Linux 命令 nohup 来完成此任务。以下是该命令语法的简要说明。

```
Syntax:
  nohup command [args]
Purpose: Execute command and ignore the hang-up signal
```

你需要对需要很长时间才能完成的进程使用 nohup 命令，例如对包含数十万条客户记录的大型文件进行排序的程序。显然，你会将此类程序在后台运行，以便以较低优先级运行。以下是 nohup 命令使用的简单示例。在此，find 命令在后台运行，在你注销或通过 kill 命令向其发送信号编号 1（挂断）时不会被终止。如果未重定向命令的输出，则默认情况下会将其追加到 nohup.out 文件中。

```
$ nohup find / -name foo -print > foo.paths 2> /dev/null &
[1] 62808
$ kill -1 62808
$ jobs
[1]+ Running        nohup find / -name foo -print > foo.paths 2> /dev/null &
$ kill 62808
$ <Enter>
[1]+ Terminated     nohup find / -name foo -print > foo.paths 2> /dev/null
$ jobs
$
```

如果用分号分隔命令，你可以用 nohup 运行它们。在以下会话中，GenData 生成一些数据并将其放入名为 employees 的文件中，而 sort 命令对文件进行排序并将排序后的版本存储在 employees.sorted 文件中。

```
$ nohup GenData > employees ; sort employees > employees.sorted &
[2] 15931
$
```

## 10.7 Linux 启动、登录和进程层次结构

当你打开 Linux 计算机系统的电源时，基本上会执行两个操作来使你的计算机按你通常期望的方式运行。如第 17 章所述，这两个操作是引导和启动。我们这里关注的是启动操作，特别是用户空间中进程的创建，或用户侧进程。我们还关注 systemd 作为启动阶段的控制进程，以及在计算机通电的整个时间内 systemd 如何以层次结构方式安排和控制进程。

### TABLE 10.10: Some of the Key Linux System Processes

| Process | Purpose |
|---------|---------|
| systemd | 所有用户进程的祖宗；所有用户级服务，包括所有 Internet 服务，以及用户进程都在该进程的子进程下运行 |
| kthread | 内核线程守护进程 |
| agetty | 创建并控制 tty |
| NetworkManager | 管理你的网络设备和连接，尝试在可用时保持活动网络连接 |
| mdm | Mint 显示管理器，控制桌面环境 |
| cupsd | Linux 打印守护进程，管理打印机和打印 |
| systemd-journal | systemd 的日志机制 |

作为启动操作的一部分，Linux 内核从引导介质中提取并配置为工作状态。执行一些检查和其他维护任务后，内核然后从头开始创建第一个内核空间，或内核侧进程。在 Linux 中，该进程称为 swapper 或 scheduler。该进程没有父进程，PID 为 0。该进程的 PPID 也为 0。第一个进程随后生成其他几个内核侧进程，这些进程旨在处理多个重要的内核任务，包括与虚拟内存、文件处理、中断处理相关的任务，以及在持续的引导序列中执行各种任务，例如初始化硬件端口。要查看关键 Linux 进程的简要列表和描述，请参阅表 10.10。

随着启动的继续，在所有主要分支的 Linux 中，只要系统处于运行状态，systemd 就是创建的第一个用户侧进程。systemd 进程的 PID 为 1，并以超级用户权限运行。/etc/systemd/system 目录中的配置指导通过各种“目标”状态进行初始化，这取决于系统是作为服务器还是桌面计算机使用等。要查看 systemd 在将 Linux 系统提升到名义性能时所经历的步骤的说明，请参阅第 18.2 节。

### 10.7.1 Linux 登录和 agetty

就用户空间交互会话而言，在启动过程中至关重要的进程是 agetty，传统上在旧版 UNIX 或 Linux 系统中称为 getty。你可以使用三种方法中的任何一种连接到 Linux 系统：通过 GUI 或字符用户界面 CUI，或通过 ssh（或用于远程登录的类似命令）。无论你使用何种方法连接到 Linux 系统，当你登录到 Linux 系统时，系统会为你创建第一个进程，即你的登录 shell。登录 shell 通过为你执行的每个命令创建进程来解释/执行你的命令（有关命令执行的详细信息，请参阅第 10.3 节）。

如果你通过 GUI 登录，显示管理器会处理 agetty 进程生成的细节。在 Mint Linux 上，这是 mdm。如果你使用 CUI 方法登录，agetty 会执行以下步骤来处理你的登录。在 login: 提示符处，当你输入登录名并按 `<Enter>` 时，agetty 进程会派生一个子进程。子进程执行 exec 系统调用以成为登录进程，其参数为你的登录名。登录进程提示你输入密码并检查你的登录名和密码的有效性。如果它发现两者都正确，登录进程会 exec 成为你的登录 shell。如果登录进程在 /etc/passwd 文件中找不到你的登录名或发现你输入的密码与 /etc/passwd 文件中的密码不匹配，它会显示错误消息并终止。控制权返回到 agetty 进程，后者重新显示 login: 提示符。一旦进入你的登录 shell，你可以进行工作并通过按 `<Ctrl+D>`、输入 logout 然后按 `<Enter>`，或运行 exit 命令来终止 shell。当你这样做时，shell 进程终止，控制权返回到 agetty 进程，后者显示 login: 提示符，生活继续。

当你通过 sshd 守护进程登录到远程服务器时，你在自己的机器上运行 ssh 命令。远程机器上的 sshd 守护进程创建一个子进程，即你的私有 sshd，用于处理与客户端的通信。服务器 sshd 返回去查找来自其他客户端的更多 ssh 连接请求。你的私有 sshd 生成另一个 sshd 进程，该进程用伪终端覆盖自身，提示你输入密码。当你输入正确的密码时，它会为你运行登录 shell 进程。默认情况下，远程 Linux 机器上的默认登录 shell 是 Bash。你在登录 shell 下运行你的命令。当你按 `<Ctrl+D>`、输入 logout 然后按 `<Enter>`，或运行 exit 命令时，你的登录 shell 连同你的私有 sshd 守护进程一起终止。

### 10.7.2 进程生命周期和 pstree

在开机系统的运行时间内始终存在的两个 Linux 进程是 scheduler 和 systemd。agetty 进程监控各种形式的终端线路，必须在终端连接到系统时一直存在。你的登录 shell 进程在你登录期间一直存在。所有其他进程通常寿命很短，或在命令、实用程序或服务必须执行时运行。以下会话中显示的许多服务及其进程对于正常系统操作至关重要。当然，根据你的 Linux 系统设计的使用场景，其中许多其他服务及其进程会持续运行。
