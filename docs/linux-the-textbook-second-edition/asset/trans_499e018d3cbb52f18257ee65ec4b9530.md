### 16.2 进程与线程

在本节中，我们讨论进程和线程的概念。我们的讨论侧重于两者的概念化、它们是如何创建的、它们执行所需的系统资源、它们的地址空间、两者之间的相似之处以及它们之间的不同之处。在讨论了一般性进程之后，我们主要关注 Linux 进程。关于线程的讨论涵盖了用户级和内核级线程库。

对进程的一种简单而高级的看法是：它是正在执行的程序。进程执行从进入进程的入口点（通常是 `main` 函数的第一个语句）开始，并依次连续执行，一次一条程序语句。因此，程序计数器（PC）与进程相关联，它控制程序语句（包括函数调用）的执行顺序。在函数调用时，控制权转移到被调用的函数，执行该函数中的第一条语句，然后逐条语句依次执行函数体的其余代码。从函数返回时，执行调用函数中函数调用之后的语句。进程执行就这样继续下去，直到执行进程中的最后一条语句。

更深入地观察进程，会发现它实际上由以下三个实体组成：

1. 地址空间
2. CPU 状态
3. PCB

正如 10.5.1 节所讨论的，进程的地址空间由进程的主存映像决定。在任何给定时刻 CPU 寄存器的值（包括 PC 的值）构成了进程的 CPU 状态。我们将在下一小节中描述进程主存映像的增强版本、进程的地址空间以及进程的 PCB。

PCB 是一种内核数据结构，用于跟踪进程的运行时属性。在 Linux 中，进程的 PCB 由两部分组成：proc 结构和 u 区。虽然 proc 结构包含进程与调度相关的信息，但 u 区包含有关信号处理、资源分配的信息，以及对 proc 结构的引用。无论进程处于何种状态，进程的 proc 结构始终保留在主存中。然而，只有当进程处于运行状态时，u 区才在主存中。

proc 结构包含 PID 和 PPID、优先级、调度队列和等待队列、关于内存管理（分页和分段）的信息、进程状态以及信号处理掩码。u 区包含指向 proc 结构的指针、阻塞进程的 CPU 状态（即上下文）、用户 ID（UID）和组 ID（GID）、当前目录、进程的 CPU 使用情况、进程所连接的终端、信号处理信息，以及每进程的文件描述符表（PFDT）。

进程不能直接访问其 PCB；内核会根据需要更新进程的 proc 结构字段。例如，当进程优先级发生变化时，内核代码会更新进程 PCB 中的调度优先级字段。虽然 u 区是进程映像的一部分，但进程只能通过代表进程执行的内核代码（例如系统调用的代码）来访问它。

我们在第 10 章中详细讨论了 Linux 进程的内存映像。如前所述，进程内存映像（也称为进程映像）由多个段组成，如图 10.6 所示。

图 16.1 显示了进程映像的完整版本，包括位于映像顶部的 u 区。进程的内存映像描绘了进程可以合法访问的主存区域，称为进程地址空间。

进程映像的某些区域仅在进程存留于系统中（运行或等待某个事件）时才存在；其他区域则是进程映像的组成部分，无论进程是在主存中还是磁盘上的可执行映像。例如，进程的环境、栈、共享（动态链接）库、堆和未初始化数据部分仅在进程存留于系统期间才需要。这些区域在图 16.1 中被标记为“运行时区域”。我们在本章和/或其他章节中已经讨论了进程地址空间的大部分段，但共享库除外。

默认情况下，所有现代 C 编译器（包括 gcc）都在运行时将所有库调用链接到相关的库代码，从而生成可执行代码。当进程调用库函数时，如果相关库的代码尚未因本进程或其他进程先前引用该库而载入内存，则将其载入内存。一旦库代码被载入内存，它就会驻留在内存中，以供任何进程将来引用。这种将库代码链接到可执行代码的方式称为动态链接，以这种方式使用的库称为共享库。因此，动态链接的库总是共享的。

动态链接优于静态链接，主要有以下几个原因：

1. 生成的可执行代码体积更小。这意味着保存它所需的磁盘空间更少，将其加载到主存所需的时间更短，并且执行它所需的主存可能更少（如果执行期间未调用库函数的话）。
2. 库代码只被载入内存一次，并由多个进程共享。
3. 如果库已更新，则无需重新生成（重新链接）新的可执行代码，前提是库调用的原型没有更改。
