## Persistent Cgroups and Setting Their Resources

## Example 17.9 Creating Persistent Cgroups and Modifying Their CPUShare and CPUQuota

目标：通过在 /etc/systemd/system 目录中为其构造服务单元文件来创建持久的或永久的 cgroup。这是 systemd 中用户安装和用户定义服务的标准位置，如第 18 章所示。以下示例的基本目标是创建一个简单的用户定义服务，并使用我们已为 transient 服务在示例 17.8 中展示的相同 systemctl set-property 命令来平衡其 CPU 使用。

前提条件：完成示例 17.8，并在系统上拥有超级用户权限。

要求：按后面呈现的顺序执行以下步骤。

+ 1. 使用你喜欢的文本编辑器以 root 或超级用户身份创建并保存以下文本文件，命名为 test4.service，完全如所示，在 /etc/systemd/system 中：

```
[Unit]
Description=A test service that uses the sha256sum command
After=remote-fs.target nss-lookup.target
[Service]
ExecStart=/usr/bin/sha256sum /dev/zero
ExecStop=/bin/kill -WINCH ${MAINPID}
[Install]
WantedBy=multiuser.target
```

前面文件的结构和组件在第 18 章中完全详细说明。

+ 2. 现在我们可以使用 systemctl 命令及其 unit 子命令启动此服务并使其持久化。我们还可以使用 ps 和 systemctl 命令及其 unit 子命令 status 来监控有关 test4.service 的有价值信息

```

$ sudo systemctl enable test4.service
```

我们从 systemctl status 和 ps 命令中可以看到的有价值信息是，此服务正在消耗我们系统上 99.6% 的 CPU 资源。此外，其 pid 为 2089，它正在运行命令 sha256sum，并且位于 system.slice cgroup “块”中。

+ 3. 我们可以采取两种方法来“限制” test4.service 消耗的 CPU 资源量。首先，我们可以降低 test4.service 的 CPUShare，以将其“限制”回更可接受的值。此更改将在系统重启后保持持久。我们可以将 test4.service 的 CPUShares 值设置为 100（我们在稍后命令中设置的值），这将在该服务下一次重启时生效。其次，我们可以通过将其 CPUQuota 属性更改为更低的百分比值来为 test4.service 设置 CPU 消耗的最大配额。

要对 test4.service 的 CPUShares 或 CPUQuota 进行 transient 或临时（重启或重新启动后不持久）更改，请在以下 systemctl set-property 命令中添加 --runtime 选项。

要使用 CPUShares 限制 test4.service，请使用以下命令

```
$ sudo systemctl set-property test4.service CPUShares=100
```

要使用 CPUQuota 限制 test4.service，请使用以下命令

```
$ sudo systemctl set-property test4.service CPUQuota=20%
```

要使这些更改生效，请使用以下命令：

```
$ sudo systemctl daemon-reload
$ sudo systemctl restart test4.service
```

+ 4. 现在让我们看看 sha256sum 进程的 CPUShares 值是多少。在我们的 Linux Mint 系统上，以下命令显示了这一点：

```
$ cat /sys/fs/cgroup/cpu/system.slice/test4.service/cpu.shares
100
$
```

## 17.8.1.3 Managing Memory

systemd 允许你轻松控制和设置单元的内存使用限制。这在计算机硬件上安装的内存量最少的情况下可能至关重要。要查看单元消耗多少百分比的内存，请使用 top 命令，并检查内存使用变量 %MEM 的列输出。鉴于你的系统设计的使用情况，如果应用程序或服务消耗太多内存，有两种方法可以限制其内存使用。

第一种方法是在 systemctl set-properties 命令中使用属性 MemoryLimit 为特定服务分配值。以下命令将我们在第 17.8.1.2.1 节中创建的单元 test4.service 的 MemoryLimit 设置为 500 MB：

```
$ sudo systemctl set-property test4.service MemoryLimit=500M
```

该限制指定此单元中的任务可以使用的进程和内核内存量。限制是以字节为单位的内存大小。如果数值后跟 K、M、G 或 T，则指定的内存大小分别解析为千字节、兆字节、千兆字节或太字节（以 1024 为基数）。特殊值“infinity”表示不应用内存限制。

之前的 systemctl set-properties 命令将在 /etc/systemd/system/test4.service.d/MemoryLimit.conf 创建一个 MemoryLimit.conf 文件，可以在第二种方法中稍后编辑。

第二种方法是在单元配置文件的 [Service] 部分中放置以下指令：

```
MemoryLimit=value
```

用对在 cgroup 中执行的进程的最大内存使用量的限制替换 value。使用后缀 K、M、G 或 T 来标识千字节、兆字节、千兆字节或太字节作为测量单位。此外，MemoryAccounting 参数必须为该单元启用。

MemoryLimit 参数控制 memory.limit_in_bytes 控制组参数。

要将 500 MB 的内存限制分配给 test4 服务，请修改 /etc/systemd/system/test4.service.d/MemoryLimit.conf 文件中的 MemoryLimit 设置以包含以下内容：

```
[Service]
MemoryLimit=500M
```
