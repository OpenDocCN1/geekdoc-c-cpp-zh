## 18.2 使用 systemd 进行系统启动、初始化和关机

要开始理解 systemd 是什么，以及它作为“超级内核”所实现的部分功能，我们需要考察 systemd 为 Linux 操作系统完成的第一项和最后一项主要任务——启动和关机。其中第一个任务正是 systemd 被引入的目的：更有效、更高效地取代旧式 UNIX 和 Linux init 系统。但是，随着你对本章的深入探索，你会明白 systemd 远不止于此。

### 18.2.1 启动与关机过程概述

使用 systemd 的 Linux 系统如何引导和启动的基本细节见第17章第2.5节。在本节中，我们将进一步详细展开启动阶段的细节，特别是涉及 systemd 特有的步骤。

如第17章所述，在 systemd 作为初始化程序在系统启动期间接管之前，就有多个进程开始起作用。图17.1展示了引导过程：POST、BIOS 或 UEFI、GRUB，然后是启动阶段，内核在此阶段初始化硬件，并准备从根文件系统运行第一个进程。在找到并挂载根文件系统后，systemd 接管，并负责初始化所有剩余硬件、挂载所有必要文件系统、管理系统服务的启动，并允许对所有进程进行细粒度控制。

在关机时，systemd 停止所有服务并卸载所有文件系统（脱离处理它们的存储程序）。然后系统要么重新启动，要么最终关闭电源。

### 18.2.2 systemd 启动：目标、目标状态与目标单元

引导阶段结束后，systemd 成为启动阶段的控制组件，并负责完成启动。它通过初始化系统正常运作所需的文件系统、服务和驱动程序来实现这一点。在 systemd 中，这个过程被拆分为“运行时”步骤（系统实际实时执行时发生的操作），其目标是达到所需或请求的“目标状态”，在 UNIX 和 Linux 术语中以前称为“运行级别”。整个过程尽可能并行完成。这种并行实现了显著更快的启动时间，这是 systemd 控制的 Linux 的一个标志性特点。启动过程也没有固定的路径，因此“目标单元”达到的顺序是在系统实际启动时确定的。在接下来的章节中，我们将给出目标、目标状态和目标单元的完整定义并提供示例。

“依赖关系”是目标单元之间按顺序排列的关系。当 systemd 接管启动阶段时，它首先激活作为默认目标状态 default.target 的上游依赖的目标单元，然后继续激活所有其他下游依赖。default.target 是 graphical.target 或 multi-user.target 的别名，具体取决于系统默认配置为 GUI（例如在桌面系统上）还是仅用于文本控制台（CUI）（例如在服务器系统上）。通常，桌面用户更喜欢 GUI 环境，因为它具有图形化交互操作和窗口系统。服务器通常使用 CUI，因为在该目标状态下运行所涉及的内存和资源开销较低。重要的是要认识到，这两种用例都有非常具体的性能要求，因此也有不同的目标单元激活要求。

图 18.2 显示了根据最终达到的是 GUI 的 graphical.target 还是 CUI 的 multi-user.target 状态，所到达的“里程碑”目标单元描述的顺序。箭头描述了从上到下按什么顺序调用哪些单元。

就目标单元依赖关系而言，图中较上方的目标是较下方目标的依赖。

一些具有代表性的里程碑目标单元，按被调用的顺序如下：local-fs-pre.target、sysinit.target、basic.target 和 graphical.target。其他目标单元，如 timers.target，由 basic.target 调用，并且当它们的“依赖”，即依赖它们的资源和其他目标状态，需要时，会影响系统状态。
