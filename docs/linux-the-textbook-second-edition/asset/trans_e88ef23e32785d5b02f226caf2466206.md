## 16.3.5 覆盖进程映像

一个进程可以用另一个可执行映像覆盖自身。可以使用 execve() 和 fexecve() 系统调用来实现。 这两个调用在参数传递方式上有所不同。以下是这两个调用的简要描述：

```
#include <unistd.h>
int execve(const char *path, char *const argv[], char *const envp[]);
int fexecve(int fd, char *const argv[], char *const envp[]);

Success: Control does not return to the caller process because it has been overwritten with a new executable
Failure: -1 and kernel variable errno set to indicate the type of error
```

在 execve() 调用中，path 是包含新进程可执行映像的普通文件的路径名。在 fexecve() 系统调用的情况下，fd 是包含新进程映像的文件的文件描述符。该文件可能包含二进制可执行代码或由解释器执行、例如 shell 或 Perl 脚本的脚本。脚本文件以以下格式开头的一行：

```
#! interpreter [arg]
```

execve() 系统调用实际上用解释器覆盖调用者进程，并将脚本文件作为参数传递给它。如果在第一行未指定 arg 参数，则脚本文件被指定为传递给解释器的第一个参数；否则，它被指定为第二个参数。argv 参数是指向以空结尾的指针数组的指针，这些指针指向以空结尾的字符串，成为脚本或二进制可执行文件的命令行参数。envp 参数在结构上与 argv 类似，包含不同环境变量的值。

如果要覆盖调用者进程的文件是二进制可执行文件，则像在 C 中使用命令行参数执行 main 程序一样执行它，如以下会话所示：

```
int main(int argc, char **argv, char **envp)
```

其中 argc 是命令行参数的数量，包括程序名，argv 和 envp 如上一段所述。

调用者进程中打开的文件描述符在新进程中保持打开状态，除非为其设置了 close-on-exec 标志。调用者进程中设置为忽略的信号在新进程中仍被忽略，而调用者进程中设置为捕获的信号在新进程中被设置为默认动作。新进程还继承调用者进程的以下标识和属性：PID、PPID、PGID、工作目录、根目录、控制终端、访问组、资源使用情况、计时器、资源限制、信号掩码和 umask。

execve() 和 fexecve() 系统调用可能因多种原因而失败，其中一些列在表 16.6 中。

用于用 execve() 和 fexecve() 调用指定的可执行映像覆盖进程的系统调用接口相当繁琐。Linux 提供了几个具有更易用接口的库函数来执行相同的任务。其中最简单的是 execl() 库调用，它是 execve() 系统调用的前端。我们在本书讨论的示例中使用此调用。以下是该调用的简要描述：

```
#include <unistd.h>
int execl(const char *path, const char *arg, ... /*, (char *)0 */);

Success: Control does not return to the caller process because it has been overwritten with a new executable
Failure: -1 and kernel variable errno set to indicate the type of error
```

execl() 调用可能因与 execve() 系统调用失败相同的理由而失败。

以下会话中所示的 fork_exec_1.c 程序创建一个子进程，该子进程用 /bin/date 文件中的可执行文件覆盖自身，以显示今天的日期和当前时间。因此，子进程成为 date 进程。父进程显示子进程的 PID，等待子进程终止，并显示已终止子进程的 PID。程序的示例运行表明，正如预期的那样，父进程为子进程显示的 PID 与已终止子进程的 PID 相同。

```
$ cat fork_exec_1.c
#include <unistd.h>

extern int errno;

int main(void)
{
    int pid, status;

    pid = fork();
    if (pid == -1) {
        perror("Fork failed");
        exit(1);
    }
    /* Child process */
    if (pid == 0) {
        execl("/bin/date", "date", (char *) NULL);
        perror("execl failed");
        exit(1);
    }
    /* Parent process */
    printf("Child PID = %d.\n", (int) pid);
    pid = wait(&status);
    printf("Child with PID %d has terminated.\n", (int) pid);
    exit(0);
}
$ gcc -w fork_exec_1.c -o forkel
$ forkel
Child PID = 15754.
Sun Oct 22 09:31:34 PKT 2017
Child with PID 15754 has terminated.
$
```

fork_exec_2.c 程序创建一个子进程，该子进程使用 execl() 调用在当前目录中创建一个名为 dir1 的目录。父进程在 dir1 中创建一个名为 foo 的文件，打开此文件，将 Hello, world! 消息写入 foo，将文件指针重置到文件开头，从 foo 中读回 Hello, world! 消息，将此消息显示在标准输出上，从 dir1 中删除 foo，并删除现在为空的 dir1。程序的编译和示例运行如下会话所示。

```
$ cat fork_exec_2.c
#include <fcntl.h>
#include <unistd.h>
#include <errno.h>

#define SIZE 512
#define MODE 0644
#define Message "Hello, world!\n"

extern int errno;

int main(void)
{
    int n, nr, nw, fd, pid, status;
    char buf[SIZE];

    pid = fork();
    if (pid == -1) {
        perror("Fork failed");
        exit(1);
    }
    /* Child process */
    if (pid == 0) {
        execl("/bin/mkdir", "mkdir", "dir1", (char *) NULL);
        perror("execve failed.\n");
        exit(1);
    }
    /* Parent process */
    while (((pid = wait(&status)) == -1) && errno == EINTR)
        ;
    /* Write to foo */
    if (pid == -1) {
        perror("Wait failed");
        exit(1);
    }
    /* Open or create dir1/foo file */
    if ((fd = open("dir1/foo", O_RDWR|O_CREAT, MODE)) == -1) {
        perror("Open failed");
        exit(1);
    }
    /* Write to foo */
    if ((nw = write(fd, Message, strlen(Message))) == -1 ) {
        perror("Write failed");
        exit(1);
    }
    /* Rewind file pointer */
    n = lseek(fd, 0L, SEEK_SET);

    /* Read back from foo */
    if ((nr = read(fd, buf, nw)) == -1) {
        perror("Read failed");
        exit(1);
    }
    /* Throw on standard output */
    write(1, buf, nr);
    if (close(fd) == -1) {
        perror("File closing");
        exit(1);
    }
    /* Remove dir1/foo to make dir1 an empty directory */
    unlink("dir1/foo");
    /* Remove the now empty directory dir1 */
    rmdir("dir1");
    exit(0);
}
```

```
$ gcc -w fork_exec_2.c -o forke2
$ forke2
Hello, world!
$
```

## 16.3.6 创建僵尸进程

当一个进程在父进程未等待时终止，即父进程正在休眠或已完成执行，它无法向父进程报告其终止状态，并被称为僵尸进程。它已完成工作，但分配给它的一些资源可能尚未归还给系统。最终，systemd，即所有用户进程的祖父进程，会接管僵尸进程的父进程身份，接收其状态并释放剩余的系统资源。
