## 17.3.6 账户安全

一旦用户或组账户已添加到系统中，系统管理员接下来关心的就是如何维护安全，即该用户或组账户访问和利用系统服务和文件等一般资源的权限。我们在书网站第 W26.9.3 节“在 Linux 中使用访问控制列表（ACLs）”中展示了一种使用 ACL 实现的方法。我们在第 17.9 节中一般性地讨论系统安全，并在其下的子节中提供详细信息。

如第 17.9.3 节所述，传统的 Linux 权限定义了对文件对象如普通文件或目录的安全访问权限，即读、写和执行权限。第 5 章第 5.4 节展示了文件和目录权限的形式。此外，还有其他高级技术来设置权限，例如设置 setuid、setgid 和粘滞位。除此之外，ACL 模型为用户提供了对文件和目录对象安全更精细的控制。可以认为每个文件对象都关联一个访问 ACL，用于控制对该对象的自主访问。对于目录，此 ACL 称为默认 ACL。Linux 默认使用的是众所周知的 POSIX.1e ACLs 模型。

## 17.4 文件系统、与持久介质的连接以及向系统添加磁盘

问题：什么是计算机文件系统？
答案：一种逻辑上组织数据的方式，以便如果数据是持久的，可以安全且快速地定位，然后以一致的方式访问以供使用。

提供数据持久性，这是 Linux 操作系统本身的第三个主要目标，在很大程度上涉及建立和维护与持久介质（如磁盘驱动器）的连接。这些驱动器及其上的文件系统可以物理直接连接到计算机内部，例如旋转式硬盘、SSD 或 USB 闪存盘。它们也可以是某种远程虚拟驱动，例如网络可用的驱动，或远程卷和驱动组合。

在某些情况下，文件系统可能根本不使用持久存储设备或介质！在这一更高层次的抽象中，文件系统可以访问、使用、组织和表示任何形式的数据，无论其是持久的还是易失的。我们在此使用的易失性一词是指某些进程或服务的瞬时生命周期。当然，systemd 和 Linux 内核控制着计算机上运行的所有进程和服务。伪文件系统和特殊用途文件系统（有时称为合成文件系统），可以被视为虚拟文件系统，具有这种特性。

还有用于连接和访问物理、虚拟或伪文件系统的既定协议，这些文件系统可能位于不同的位置。两个建立和维护对虚拟、网络可用介质和文件系统的连接的访问协议示例是 NFSv4 和 iSCSI。

在本节中，我们首先介绍一种组织方案，可用于思考驱动和文件系统的类型。文件系统可以根据其存在的介质大致分配：直接连接的物理介质（如 SATA 或串行连接小型计算机系统接口（SAS）硬盘）、虚拟介质（如使用 NFSv4 或 iSCSI 的 NAS 或 SAN），或完全不位于持久介质上的专用伪文件系统（如 cgroups 或 proc 文件系统）。

然后我们继续给出一些向 Linux 系统添加直接连接物理磁盘的具体示例。

此外，当使用我们在第 17.2.1 节中给出的推荐存储模型时，我们建议两种向 Linux 系统添加持久介质的方法。它们如下：

- 1. 使用 ZFS 将介质作为虚拟设备集成到新或现有设备池化阵列中，该池可以提供多种不同级别的冗余。这些池称为“zpool”。这是一种简单的方法，在介质上放置主分区后，会自动赋予文件系统并挂载。这在书网站第 W22 章“ZFS 管理与使用”中详细展示。
- 在本书撰写时，可以以简单高效的方式在 Debian 家族的 Linux（Debian、Ubuntu 和 Linux Mint）和 CentOS 7.4 上安装 ZFS。
- 有关在 Debian 家族（Debian 9.1、Ubuntu 16.04 和 Linux Mint 18.2）和 CentOS 7.4 上安装 ZFS 的详细安装说明，请参阅附录 A 第 26.4.7 节。
- 2. 更传统的方法，首先使用电缆将设备正确连接到计算机，对该介质进行分区，手动向其添加文件系统（通常是 ext4 文件系统），然后最终在介质上的分区中创建目录和文件。后续章节详细介绍了这种更传统的方法。

根据我们的组织方案，文件系统可以分为三个按层次排列的层，执行特定功能。这些层从最远离所讨论驱动的实际硬件到最近的硬件排列如下：

逻辑层：该层用于通过 Linux 系统调用与用户应用程序程序及其组成的进程进行交互。它为文件操作提供应用程序编程接口（API），例如打开、关闭、读取等系统调用，并与下面的层连接以进行处理。逻辑层实现高效的文件访问、逻辑组织的目录操作，并提供用户自主性和安全性。在图 17.2 中，该层由图顶部所示的 ISCSI 和进程输入块表示。

虚拟层：该层提供用于在同一台计算机上维护多个同时存在的物理和虚拟文件系统实现的接口机制。例如，它使得在同一系统上同时挂载并透明使用 NFSv4、btrfs、ext3、ext4、fat32 和 ZFS 成为可能，并像它们都是同一类型一样操作来自所有这些实现的文件。

## 图 17.2 Linux 文件系统存储层。

图 17.2 中显示的 Linux IO（LIO）块被称为 iSCSI“目标”，代表虚拟层通过各种网络连接与持久介质的连接。这些连接传统上使用高速光纤通道技术创建存储区域网络（SAN），但最重要的是也可以使用以太网和 TCP/IP 实现。

对虚拟层文件系统的更详细架构分类方案进一步将该层分为基于块的、网络的、可堆叠的、伪的和特殊用途类别。在图 17.2 中，许多不同的文件系统实现，如 NFSv4、ext4、xfs、btrfs、initramfs 和 procfs，都位于该图显示的虚拟文件系统块内。两个非常当代且极其重要的虚拟文件系统是 systemd 使用的 cgroups 文件系统（cgroupfs），以及用户态、基于块的文件系统 ZFS。

物理层：该层关注持久存储设备的物理操作。它处理正在读取或写入的物理块。它处理缓冲和内存管理，并负责将块物理放置在存储介质上的特定位置。物理文件系统与设备驱动程序或物理设备通信的通道交互。在一定程度的简化下，该层可以在图 17.2 中由块层、SCSI 层和物理设备层的集成分组示意性表示。

此外，作为 Linux 内核在我们所定义为瞬时和易失状态下存在时操作不可分割的一部分，伪文件系统和特殊用途文件系统可以被视为系统本身“流动”的管道系列。沿着这一思路思考，当内核在 CPU 和附属 RAM 中时，内核代码本身被组织为一个文件系统。内核（或 systemd 超内核）可以被视为一个易失数据结构的文件系统，它仅使用这些管道来维持硬件和软件的稳定状态；这实现了虚拟化、并发性、用户自主性、安全性和对为此建立的文件系统的必要的归档、长期数据持久性的总体目标。

在 Linux 的历史中，各种文件系统被用来为普通用户提供速度、效率、安全性和实用性。其中最当代和通用的，在 Linux 的三大主要分支中，是 Linux 扩展文件系统（ext）。本书中展示的所有代表性 Linux 发行版都将其用作默认文件系统。
