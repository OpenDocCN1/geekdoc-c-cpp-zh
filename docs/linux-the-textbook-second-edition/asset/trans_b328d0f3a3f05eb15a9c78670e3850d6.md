

## 11.3 使用计算机网络和互联网络的原因

使用计算机网络而不是独立的个人计算机、强大的小型机、大型机或超级计算机的原因有很多。主要原因如下：

- *共享计算资源：* 计算机网络用户可以共享硬件资源，包括计算机、打印机、绘图仪和扫描仪，以及软件资源，如文件（数据和软件）。
- *网络作为通信媒介：* 网络是居住在远方的人们之间廉价、快速且可靠的通信媒介。
- *成本效益：* 在相同价格下，使用工作站网络比使用小型机或大型机可以获得更强的计算能力。
- *性能下降更少：* 使用一台强大的小型机、大型机或超级计算机时，一旦计算机出现任何故障（例如主存中的一位损坏），工作就会戛然而止。而使用计算机网络，如果一台计算机崩溃，网络中的其余计算机仍能继续运行，从而可以继续工作。

## 11.4 网络模型

在网络的设计和实现过程中出现了各种问题，这些问题决定了两个最著名网络模型的设计：

- 1. 用于连接硬件资源的物理通信介质或通信信道的类型：可以是简单的 RS-232 电缆、电话线、同轴电缆、光纤电缆、微波链路或卫星链路。
- 2. 网络的拓扑结构——即主机在网络上的物理排列：一些常用的拓扑结构有总线型、环型、网状和一般图。
- 3. 一组称为协议的规则，用于允许网络上的主机在开始数据传输之前访问物理介质。
- 4. 这些协议用于在局域网中将应用数据（例如网页）从一台主机路由到另一台主机，或在互联网络中将数据从一台网络中的主机路由到另一个网络中的主机。
- 5. 这些协议用于在局域网中将数据从一台主机上的进程传输到另一台主机上的进程，或在互联网络中将数据从一个网络中主机上的进程传输到另一个网络中主机上的进程。
- 6. 这些协议被基于网络的软件用来提供特定的应用程序，如 ftp。

两个最著名的网络模型是国际标准化组织的开放系统互连参考模型（通常称为开放系统互连（OSI）七层参考模型）和 TCP/IP 五层模型。OSI 模型于 1981 年提出，TCP/IP 模型于 20 世纪 70 年代末提出。1982 年 3 月，美国国防部将 TCP/IP 模型作为所有军事网络的标准。TCP/IP 模型起源于 ARPA，是互联网的基础，因此也被称为 IP 模型。该模型由五层组成，每一层都有特定的用途和一组与之相关的协议。图 11.2 中的示意图显示了这两种模型以及两者之间的近似映射。

由于互联网中使用的是 TCP/IP 模型，因此我们将以此为重点。就前面列出的六个问题而言，TCP/IP 模型中的第一层处理前两个问题，第二层处理第三个问题，第三层处理第四个问题，第四层处理第五个问题，第五层处理第六个问题。就实现而言，前四层处理主机之间通信的细节，第五层处理各种应用程序提供的互联网服务的细节。第一层的大部分由硬件处理（所使用的通信介质类型、主机与介质的连接等）。主机中的网络接口卡（NIC）处理第一层的其余部分和第二层。第 2 层由介质访问控制（MAC）地址、网卡、驱动程序和交换机组成。在大多数现有系统上，第 3 层和第 4 层完全在操作系统内核中实现。前两层是特定于网络硬件的，而其余层独立于物理网络工作。在较新的千兆以太网接口上，网络栈的处理开销变得很大，NIC 中使用了 TCP 卸载引擎（TOE）技术，将 TCP/IP 栈的处理工作卸载到网络控制器上。

### 11.5.1 TCP 和 UDP

传输层的目的是将应用数据从你的机器传输到远程机器，反之亦然。这种传送服务可以是一种简单的尽力而为服务，不保证应用数据的可靠传送；也可以是一种保证应用数据可靠且按序传送的服务。用户数据报协议（UDP）提供尽力而为的传送服务，而 TCP 提供完全可靠、按序的传送。UDP 是一种无连接协议；也就是说，它只是将应用数据发送到目的地，在传输数据之前不与目的地建立虚拟连接。因此，发送方主机上的 UDP 软件在发送数据之前不与接收方主机上的 UDP 软件“通信”。TCP 是一种面向连接的协议，在传输应用数据之前，在发送方和接收方主机之间建立虚拟连接，从而实现数据的可靠、无差错、按序传送。当然，建立连接的开销使 TCP 比 UDP 成本更高。许多众所周知的互联网应用程序（如 ftp）使用 TCP。在数据传递效率比无差错、按序传递更重要的应用中（如视频流），使用 UDP。在互联网术语中，由 TCP 传输的数据包称为段，由 UDP 传输的数据包称为数据报。

由于在任何时候可能有多个客户端和服务器进程在使用 TCP 和/或 UDP，这些协议使用称为端口号的 16 位正整数（0–65,535）来标识主机上运行的每个进程。从 0 到 1,023 的端口号称为知名端口，由互联网号码分配局（IANA）控制。像 http 这样的知名服务被分配在知名范围内的端口（不包括 0）。这些服务大多允许使用 TCP 或 UDP，IANA 尽量为同一服务的 TCP 和 UDP 分配相同的端口号。例如，ssh 服务分配端口 22，http（Web）服务器分配端口 80，对于 TCP 和 UDP 都是如此。大多数客户端可以在任何端口上运行，并由操作系统在客户端进程开始执行时分配端口。一些知名客户端（如 ssh）需要使用保留端口作为客户端-服务器认证协议的一部分。这些客户端被分配在 513–1,023 范围内的端口。尽管服务器进程永久运行，但非知名服务的客户端进程在其运行期间被分配端口。这些称为临时端口的端口范围在 1,024–65,535。
