

管道与FIFO之间的另一个区别是：管道是Linux内核维护的主内存缓冲区，没有名称；而FIFO是在磁盘上创建的，并且拥有类似文件名的名称。这意味着，与文件一样，FIFO必须先创建并打开，然后才能用于进程间通信。因此，访问FIFO需要访问其所驻留的辅助存储设备。管道是进程持久的，也就是说，只要创建管道的进程存在，管道就存在。在大多数Linux系统上，FIFO是文件系统持久的，也就是说，它们会一直存在于系统中，直到被显式删除/移除，或者相关文件系统被卸载（即从系统中移除）。

你可以在程序中使用`mknod()`系统调用或`mkfifo()`库调用来创建FIFO，也可以在shell会话中使用`mkfifo`命令来创建FIFO。本节我们将讨论FIFO的命令行用法。关于FIFO、管道以及相关系统调用和库调用的使用，我们将在系统编程相关章节（第15章和第16章，以及本书网站上的W20和W21）中讨论。以下是`mkfifo`命令的简要说明。

```
语法：
  mkfifo [选项] 文件列表
用途： 以文件列表中给出的路径名创建FIFO
输出： 在相关目录中为文件列表中给出的路径名创建FIFO
常用选项/特性：
  -m mode    将新建FIFO的访问权限设置为"mode"；访问权限的指定方式与chmod命令中的"mode"相同，例如666，表示所有人可读写，任何人都没有执行权限
```

在下面的会话中，我们使用第一条命令创建一个名为myfifo1的FIFO，其默认权限基于当前umask值（参见第5章的讨论）。我们使用第二条命令创建一个名为myfifo2的FIFO，所有者具有读写权限，所有其他用户没有任何权限。我们使用`ls -l myfifo1 myfifo2`命令来显示这两个FIFO的访问权限。请注意，两个FIFO长列表中的第一个字符是"p"，表示myfifo1和myfifo2属于FIFO（命名管道）类型。

```
$ mkfifo myfifo1
$ mkfifo -m 600 myfifo2
$ ls -l myfifo1 myfifo2
prw-r--r-- 1 sarwar faculty 0 Aug  9 08:30 myfifo1
prw------ 1 sarwar faculty 0 Aug  9 08:31 myfifo2
$
```

两条命令cmd1和cmd2通过一个名为myfifo1的FIFO进行通信的一般方法，如下面的命令序列所示。

```
cmd1 < myfifo1 &
cmd2 infile | tee myfifo1 | cmd3
```

注意，我们在后台运行第一条命令（后台进程参见第10章），这样才能运行cmd2。当我们执行cmd1时，它会阻塞，因为myfifo1为空。注意，在这种情况下cmd1会阻塞；如果myfifo1是普通文件，它会立即返回。当cmd2的输出通过tee工具发送到myfifo1和cmd3时，cmd1解除阻塞并开始处理myfifo1中的数据。命令cmd1和cmd3的输出被发送到标准输出（即显示器屏幕）。图9.18借助示意图展示了这些语义。

`grep 'd$'`命令从其输入（即`ps -a`命令的输出）中选取守护进程，并通过管道将它们发送给`wc -l`命令。因此，第一条`cat`命令显示系统上运行的所有进程的状态。第二条`cat`命令的输出是系统上运行的进程数量，第三条命令（`ps -a`）的输出是系统上运行的守护进程数量。如输出的最后两行所示，在运行该命令序列时，系统正在运行20个进程，其中两个是守护进程。

此会话中输出的顺序取决于三条命令的调度；前面显示的输出是我们系统产生的最可能输出。一个有趣的练习是设计一个命令序列，确保输出总是按照这里看到的相同顺序产生。

当不再需要使用FIFO时，可以像删除普通文件一样将其移除。这意味着你可以使用`unlink()`系统调用（从进程内部）或命令行下的`rm`命令，从文件系统层次结构中移除FIFO。在下面的会话中，我们使用`rm`命令移除myfifo1和myfifo2这两个FIFO。在`rm`命令前后执行`ls`命令的输出表明，这两个FIFO确实已被移除。

```
$ ls
myfifo1 myfifo2
$ rm myfifo1 myfifo2
$ ls
$
```

## 小结

Linux会自动为每条命令打开三个文件，用于读取输入、发送输出和错误消息。这些文件被称为标准输入（stdin）、标准输出（stdout）和标准错误（stderr）。默认情况下，这些文件连接到命令执行所在的终端。因此，shell使命令输入来自键盘，其输出和错误消息发送到显示器屏幕。通过使用重定向运算符，可以将这些默认文件更改为其他文件：`<`用于输入重定向，`>`用于输出和错误重定向。

这三个标准文件可以使用数字0（stdin）、1（stdout）和2（stderr）来引用，这些数字被称为三个标准文件的文件描述符。Linux中所有打开的文件都以类似的整数来引用，内核使用这些整数对这些文件执行操作。在Bash和POSIX shell中，大于符号（`>`）与描述符1和2结合使用，分别重定向标准输出和标准错误。

命令的标准输出可以通过Linux管道（`|`）连接到另一条命令的标准输入。管道创建在主内存中，用于获取一条命令的输出并将其交给另一条命令，而无需创建磁盘文件，从而有效地使两条命令相互通信。因此，管道被称为IPC通道，它允许同一台机器上相关的命令在shell和应用级别相互通信。通过管道进行通信的进程必须通过一个共同的祖先产生关联；这种关系通常是父子关系或兄弟关系。

I/O和错误重定向功能与管道可以结合使用，以实现强大的命令行。然而，仅靠重定向运算符和管道无法将命令的标准输出同时重定向到文件和另一条命令的标准输入。`tee`工具可用于完成此任务，它将命令的标准输出发送到一个或多个文件以及另一条命令。命令和`tee`通过管道连接。

TC shell不支持带文件描述符的I/O和错误重定向。此外，在TC shell中，将命令的标准输出和标准错误重定向到不同文件的指定方式也与其他shell不同。

FIFO，也称为命名管道，允许系统上相关或不相关的进程进行通信。与作为内存缓冲区的管道不同，FIFO是创建在辅助存储设备上的文件。对于命令行使用，你可以使用`mkfifo`命令创建FIFO。`mknod()`系统调用或`mkfifo()`库调用可用于在进程内创建FIFO。当不再需要FIFO时，你可以从运行中的程序（进程）内部使用`unlink()`系统调用，或在命令行使用`rm`命令将其移除。我们在第15章和第16章以及本书网站的W20和W21中讨论与管道和套接字相关的Linux系统调用和库调用，这些内容属于Linux系统编程。
