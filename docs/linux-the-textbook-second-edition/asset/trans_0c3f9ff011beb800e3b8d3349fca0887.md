## 8.6.4 符号链接的优点和缺点

如前所述，符号链接没有硬链接的问题和限制。因此，可以为目录建立符号链接，也可以在文件系统之间建立符号链接。此外，只要文件路径名不被更改——即原始文件未被移动——指向符号链接的文件就可以由任何类型的编辑器编辑，而不会产生任何不良影响。

符号链接本身也有一个与硬链接无关的问题：如果符号链接指向的文件从一个目录移动到另一个目录，则无法再通过链接访问它。原因是链接文件包含文件结构中文件原始位置的路径名。当文件位置更改时，链接就会变成悬空链接；也就是说，它指向指定（原始）位置不存在的文件。如果删除原始文件，你也会得到一个悬空指针。以下会话说明了这一点。

```
$ mv /dev/shm/Chapter3 .
$ cat temp.soft
cat: temp.soft: No such file or directory
$
```

假设 temp.soft 是指向文件 /dev/shm/Chapter3 的符号链接。mv 命令用于将 /dev/shm/Chapter3 移动到当前工作目录。cat 命令失败，因为软链接仍然指向路径名为 /dev/shm/Chapter3 的文件。这一结果是合乎逻辑的，但仍然是一个缺点；在硬链接中，只要移动的文件仍在同一文件系统内，cat 命令就不会失败。

符号链接的其他一些缺点是 Linux 必须支持额外的文件类型（链接类型），并且必须为每个链接创建一个新文件。链接文件的创建会导致额外的 inode 空间开销、存储链接所指向的文件路径名所需的磁盘空间以及其他内核数据结构。符号链接还会导致文件操作变慢，因为对于对文件的每次引用，都必须打开并读取链接文件，以便到达实际文件。然后对实际文件进行读写处理，如果通过符号链接引用文件，则需要执行额外的磁盘访问。
