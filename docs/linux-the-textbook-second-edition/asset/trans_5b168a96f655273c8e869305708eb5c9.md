
静态分析工具不仅可以让你度量这些参数，还能报告编译器无法捕获的缺陷，例如查找内存泄漏、无效指针和其他内存问题。为此目的，一些常用的 Linux 工具包括 cppcheck、valgrind 和 memcheck。valgrind 的部分工具除了能自动检测与内存相关的缺陷外，还能对程序进行详细的性能分析。gprof 也允许你全面分析程序。所有这些工具都是源代码调试器（将在 14.7 节讨论）的补充。

在接下来的各小节中，我们简要讨论能够执行这些分析的 cppcheck 和 gprof。

## 14.6.1 使用 cppcheck 验证代码的可移植性

大多数 C 编译器在检查类型不匹配方面做得相当好，但很少有编译器能处理可移植性问题。你可以使用 cppcheck，这是一个预装在 Linux Mint 18 中的静态分析工具。它也被集成在许多流行的程序开发环境中，包括 Code::Blocks、Eclipse、git 和 Visual Studio。

你可以用它来识别 C/C++ 软件中编译器通常无法检测到的缺陷。它是 Linux 中开发高质量、整洁且可移植的 C 软件最有用的工具之一。它会检测可能属于缺陷、不可移植或浪费系统资源的程序特性。但它报告的是真实缺陷，不会产生虚假警告。它也不报告结构性问题，例如声明但未使用的变量和不可达代码。cppcheck 可以检测代码中的各种缺陷并相应报告，包括以下类型：

- 越界检查
- 内存泄漏
- 空指针解引用
- 使用过时或不安全的函数

你可以使用 `cppcheck --doc` 命令显示 cppcheck 执行的检查列表。虽然 cppcheck 可以处理各种编译器扩展、内联汇编代码和预处理器文件，但这里的讨论仅限于它在 C 程序文件中的使用。以下是 cppcheck 命令的简要说明。

**语法：** `cppcheck [options] [file(s) or path(s)]`

**用途：** 分析给定的一个或多个源文件（如果是目录，则分析该目录中的文件），查找编译器可能无法捕获的错误

**常用选项/功能：**

| 选项 | 描述 |
|---|---|
| `--doc` | 显示 cppcheck 执行的检查列表 |
| `--inconclusive` | 即使分析结果不确定也报告错误；在这种情况下可能出现误报 |
| `-v` | 报告更详细的错误 |

如果指定路径是目录，cppcheck 会递归检查所有源文件并对其进行分析。我们通过下面会话中展示的简单程序来演示 cppcheck 的用法，以说明它会报告越界问题、空指针解引用和内存泄漏。我们使用了带 `-ba` 选项的 `nl` 命令来为所有源代码行（包括空行）编号，因为 cppcheck 错误消息中报告的行号包含空行。

```bash
$ nl -ba buggy1.c
1  /* Out of bounds check */
2  #define SIZE 10
3
4  int main()
5  {
6      char str[SIZE];
7
8      str[SIZE] = '\0';
9      return 0;
10 }
$ gcc buggy1.c -o buggy1
$ cppcheck buggy1.c
Checking buggy1.c...
[buggy1.c:8]: (error) Array 'str[10]' accessed at index 10, which is out of bounds.
$
```

在下面的 buggy2.c 程序中，我们展示了 cppcheck 如何报告 gcc 无法检测到的空指针解引用错误。

```bash
$ cat buggy2.c
/* Null pointer dereferencing error */
int main()
{
    char *str;

    *str = '\0';
}
$ gcc buggy2.c
$ cppcheck buggy2.c
Checking buggy2.c...
[buggy2.c:6]: (error) Uninitialized variable: str
$
```

下面的示例说明了 gcc 未报告但 cppcheck 捕获到的内存泄漏。

```bash
$ cat buggy3.c
/* Memory leak bug */
#include <stdlib.h>

struct student {
    char name[100];
    int ID;
};

int main()
{
    struct student s;
    char *s1, *s2;
    int size;
    size = sizeof(s);
    s1 = malloc(size);
    s2 = malloc(size);
    free(s1);

    return 0;
}
$ gcc buggy3.c
$ cppcheck buggy3.c
Checking buggy3.c...
[buggy3.c:20]: (error) Memory leak: s2
$
```

```bash

[buggy2.c:6]: (error) Uninitialized variable: str
2/3 files checked 43% done

[buggy3.c:20]: (error) Memory leak: s2
3/3 files checked 100% done
$
```

## 14.6.2 使用 gprof 进行源代码度量

软件性能分析很重要，因为它能让你识别函数调用序列以及软件中耗时的部分。这些信息使你可以更密切地关注软件中导致瓶颈的代码部分或函数。你可以重写这些代码片段，使其更加省时，让程序执行得更快。通过性能分析，你还可以识别程序中被调用频率高于或低于预期的函数。这些信息可能有助于你找出程序中原本可能被忽略的缺陷。

性能分析器基于程序的实际执行来构建数据。因此，在分析复杂或大型程序时，务必使用能够在执行期间调用其所有特性的输入来运行程序。如果程序输入没有调用某组程序功能，则不会为这些功能收集任何分析信息。

要获取程序的分析数据并对其进行分析，需要执行以下步骤：

1. 启用性能分析选项编译并链接你的软件
2. 运行软件，将分析信息收集到文件中
3. 以分析文件作为输入，运行性能分析工具来分析这些信息

启用性能分析选项后，编译器会在目标模块中插入相应代码，以统计每个函数被执行的次数、构建函数调用序列，并收集每个函数所花费的时间。性能分析工具可以生成平面剖析、调用图或带注释的源代码文件形式的输出。

平面剖析输出显示程序执行时每个函数所花费的时间。调用图显示函数调用序列，以及某个函数及其子函数（即被调用的函数）所花费的时间。这使你可以识别可能导致程序瓶颈的函数调用序列。最后，在带注释的源代码文件中，每个函数都标有其调用频率（即被调用的次数）。

Linux 有多个性能分析工具可用，但其中 gprof 和 perf 最为著名。perf 主要用于分析硬件组件、命令和进程的使用情况，而 gprof 则用于源代码性能分析。虽然 gprof 是一个功能强大的工具，拥有大量选项，可以对分析数据文件执行各种类型的分析，但我们仅通过一个小示例简要描述其用法。以下是 gprof 的简要说明：

**语法：** `gprof [options]`

**用途：** 生成用 C 和其他几种语言编写的程序的执行性能分析数据

**常用选项/功能：**

- `-A` — 以带注释的源代码形式显示程序的分析数据
- `-c` — 显示函数名称以及每个函数被调用的次数
- `-p` — 显示平面剖析
- `-q` — 以调用图形式显示分析数据

我们使用 gprof_test.c 文件中的一个小型 C 程序来说明 gprof 的用法。首先，我们使用 `-pg` 选项编译程序，以便在生成的可执行文件中启用性能分析。我们还使用 `-Wall` 选项，以便编译器报告各种警告。其次，运行程序以生成性能分析数据文件 gmon.out。最后，运行 gprof 命令分析 gmon.out 中的数据，并以上文讨论的三种形式之一显示分析信息。要生成带注释的源代码文件，除了 `-pg` 选项外，你还必须使用 `-g` 选项编译源代码。

下面的会话展示了一个示例 C 程序以及生成性能分析信息所需的步骤。在本例中，我们将分析信息保存到名为 prof.out 的文件中。请注意，如果不带选项，gprof 会生成平面剖析，随后是调用图，如会话末尾的 cat 命令所示。输出中使用的术语也在输出中进行了解释（为节省篇幅，我们对输出做了截断）。平面剖析显示，函数 f1、f2 和 f3 分别被调用了 1 次、1025 次和 1074790401 次。它还进一步显示，程序完成所花费的总时间为 0.87 秒，其中 f3 占用了 0.47 秒（即总时间的 54.12%——参见输出中的相应列）。

void f1(int);
void f2(int);
void f3(void);

int main(void)

    f1(COUNT1);
    f2(COUNT2);
