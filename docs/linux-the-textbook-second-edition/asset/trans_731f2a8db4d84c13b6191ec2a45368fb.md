
当用户命令或应用程序需要执行与硬件相关的操作（例如文件读取会转化为一次或多次磁盘读取）时，就会用到 Linux 内核的这些程序。用户无法直接访问这些程序，因此不能将它们作为命令执行。

## 1.7.2 Linux 内核

Linux 内核层包含实际的操作系统。本节将描述 Linux 内核的一些主要功能，如图 1.2 所示。此外，内核还执行多项其他任务，以确保计算机系统公平、有序且安全地使用。这些任务包括管理 CPU、打印机和其他 I/O 设备。内核确保不会有用户进程永久占用 CPU，不会有多份文件同时打印在一台打印机上，并且用户不能终止另一个用户的进程。

### 1.7.2.1 进程管理

内核的这一部分负责管理进程的创建、挂起、恢复和终止，并维护它们的状态。它还提供了多种机制供进程之间相互通信，并在分时系统中调度 CPU 以同时执行多个进程。IPC 是客户端-服务器软件的关键，而这类软件是 Internet 应用的基础，包括网页浏览（HTTP）、文件传输协议（FTP）和远程登录[安全外壳（SSH）]。Linux 系统提供了三种主要的 IPC 机制/通道：

- 管道：同一台计算机上运行的两个或多个相关进程可以使用管道作为 IPC 通道。通常，这些进程具有父子或兄弟关系。管道是一种驻留在主内存中的临时通道，通常由内核代表父进程创建。
- 命名管道：命名管道也称为先入先出（FIFO），是一种驻留在磁盘上的永久通信通道，可供同一台计算机上运行的两个或多个相关或不相关进程用于 IPC。
- 伯克利软件发行版（BSD）套接字：BSD 套接字也是一种临时通道，允许网络（或 Internet）中的两个或多个进程相互通信，同一台计算机上的进程也可以使用它们。套接字最初只是 BSD UNIX 的一部分，但现在每个 Linux 系统都可以使用。Web 浏览器、FTP、SSH 和电子邮件程序等 Internet 软件都是通过套接字实现的。

我们将在本书的主要部分《Linux 系统编程》中详细讨论这些 IPC 机制，特别是本书网站上的第 W20 章。

### 1.7.2.2 文件管理

内核的这一部分管理文件和目录（也称为文件夹）。它执行所有与文件相关的任务，包括创建和删除文件、创建和删除目录、设置文件和目录的访问权限，以及维护文件大小等属性。文件操作通常需要操作磁盘。在多用户系统中，绝不允许用户直接操作磁盘，因为磁盘中包含属于其他用户的文件，而且用户访问磁盘会带来安全威胁。只有内核才能执行所有与文件相关的操作，例如删除文件。此外，只有内核才能决定为文件分配多少空间以及分配在哪里。

### 1.7.2.3 主内存管理

内核的这一部分以有序的方式分配和释放 RAM，以便每个进程都有足够的空间正常执行。它还确保分配给某个进程的部分或全部空间不属于其他进程。分配给进程用于执行的内存空间称为其*地址空间*。内核确保没有进程访问不属于其地址空间的内存区域。内核维护主内存中可供分配给进程的空闲区域。执行此任务的内核代码称为*空闲空间管理器*。当程序要加载到主内存时，空闲空间管理器为其分配足够的空间，*加载器*将程序加载到此空间中。内核还会记录所有进程在内存中的位置，以便当进程尝试访问不属于它的主内存空间时，内核可以终止该进程并向用户提供有意义的提示。当进程终止时，内核会释放分配给该进程的空间，并将其放回空闲空间池中以便重用。

### 1.7.2.4 磁盘管理

内核还负责维护空闲和已使用的磁盘空间，并以有序、公平的方式分配和释放磁盘空间。它决定为新建文件分配多少空间以及分配在哪里。执行此任务的内核代码称为*磁盘存储管理器*。此外，内核还执行*磁盘调度*，当对同一磁盘的多个文件读、写等请求到达时，决定下一步为哪个请求提供服务。

## 1.7.3 系统调用接口

系统调用接口层包含进入内核代码的入口点。由于内核管理所有系统资源，任何涉及访问系统资源的用户或应用程序请求都必须由内核代码处理。然而，出于安全原因，不能允许用户进程开放访问内核代码，而是要让用户进程能够调用内核代码的执行。Linux 提供了多个进入内核的入口或函数调用，称为*系统调用*。有许多系统调用用于处理进程、文件和其他系统资源。这些调用经过充分测试，其中大多数已使用多年，因此与允许任何用户代码执行该任务相比，使用它们带来的安全风险要小得多。

## 1.7.4 语言库

*语言库*是一组用编程语言预编写并预测试的函数，可供程序员在他们开发的软件中使用。库的可用性和使用节省了时间，因为程序员不必从头编写这些函数。这一层包含多种语言的库，包括 C、C++、C#、Java、Perl 和 Python。以 C 语言为例，有多个库，包括字符串库（包含用于处理字符串的函数，例如比较两个字符串的函数）和数学库（包含用于数学运算的函数，例如求一个角的余弦值）。

正如我们在本章前面所述，库和系统调用接口构成了通常所说的 API。换句话说，用 C 等语言编写软件的程序员可以在代码中使用各种 C 库和系统调用中提供的预编写函数。

## 1.7.5 Linux Shell

*Linux shell* 是一个在您登录时开始运行并解释您输入的命令的程序。最常见的 shell 有 Bourne Again shell（bash，所有主要 Linux 发行版中的默认 shell）、Bourne shell（sh）、C shell（csh）、TC shell（tcsh）和 Korn shell（ksh）。我们将在本书的所有核心章节中展示 shell 命令的用法，并在第 12 章和第 13 章中介绍 bash 的 shell 脚本，在第 W29 和 W30 章中介绍 TC shell 的 shell 脚本。

## 操作系统概述

开发者社区和计算机用户社区。它之所以发展、变化和改进，是因为许多不同的、有时甚至是对立的个人和群体的工作和合作。

Linux 随着计算机硬件、软件应用、网络以及“计算机革命”的其他组成部分的发展而不断成长、变化和改进。Linux 项目最初是 Linus Torvalds 的个人主观努力，但由于数千名程序员通过互联网分布式开发，它已发展成为一种通用且大众化的技术工具。因此，它的各类用户群体一定都从这个工具中发现了一些基本优势——尤其是最庞大的普通单机用户群体。要区分不同用户群体在 Linux 发展中的影响是困难的，但有一件事无可争议：Linus Torvalds 统领着这一切。此外，由于该系统从根本上说是一个开放软件系统——即源代码在用户社区中自由分发——其演进在一定程度上受到一种平民主义心态的影响。例如，在 21 世纪，这种开发模式通过 GitHub 等开发资源和源代码仓库得以加速。请参阅本书 GitHub 站点上提供的 Web 资源以获取 GitHub 链接。访问本书 GitHub 站点的说明在前言中给出。而且，由于互联网在社交媒体生活、学术环境以及商业和专业环境中的广泛使用，这种情况在未来还将继续下去。

正是 Linux 底层的核心功能，将其多样化的用户群体聚集到一个社区中，这种聚集与其说是社会学意义上的，不如说是一种独立的“自己动手”（Do-It-Yourself）的智识意义上的社区。当你深入研读本教材的内容时，你可能会想知道自己在 Linux 社区中处于什么位置，以及它的功能如何能适应你的用途。从根本上说，你与计算机交互的方式将是你使用 Linux 操作系统工作时最重要、最令人振奋也最关键的一个方面。

其他当代操作系统的发展是由完全不同的力量和基础（主要是商业化）驱动和塑造的，而促成 Linux 诞生和发展的力量和基础（主要是用户友好的、基于文本的操作系统）则不同。Linux 的历史记录了一个系统应该如何被开发，无论你认为该系统应该如何构建，你认为它应该如何运作（无论你的用户视角是什么），以及你认为应该由谁来控制这一开发过程。
