## 15.2 什么是系统编程？

*应用程序编程* 是编写程序为用户提供服务的技能，包括文字处理、文本和图形编辑、视频处理、语音流，以及互联网服务，如网页浏览。*系统编程* 是编写内核代码以管理系统硬件的能力，包括主内存和磁盘空间管理、磁盘格式化和碎片整理、CPU 调度，以及通过设备驱动程序管理 I/O 设备。它还包括在内核之外开发直接通过系统调用与操作系统接口的实用程序。编写编译器或操作系统代码的任何部分也属于系统编程范畴。虽然应用程序编程要求用户精通语言库，但系统编程要求对计算机硬件、汇编语言以及 C 之类的语言有高度的理解。

在 Linux 术语中，系统编程使用 SCI 来访问硬件资源，如 CPU、磁盘和文件、主内存，以及进程和文件的状态。此类程序包括，例如，一个 shell、一种语言汇编器或编译器、提供计算机硬件资源信息的工具，包括 CPU、磁盘和主内存的使用情况，以及提供软件资源状态的程序，如进程和文件。

## 15.3 进入操作系统内核的入口点

控制从用户进程转移到操作系统内核有几个原因。这些原因总共分为四个类别，被称为四个 *入口点* 进入内核，如图 15.1 所示。由于这些入口点的目的是调用内核中的相关代码片段以提供不同的服务，因此它们也被称为进入内核的 *服务点*。

其中两个入口点，*trap* 和 *interrupt*，是由计算机硬件引起的。*interrupt* 是外围硬件设备向 CPU 发送的“信号”，以引起其注意。例如，在磁盘控制器完成读取磁盘块（或簇）之后，它需要通知 CPU。为此，它会产生一个中断，并且内核接管控制以执行用于为此中断服务的代码，称为该中断的中断服务例程。

软件中断是一种由应用程序通过调用特殊的汇编代码指令（如 x86 CPU 的 int 21h）生成的 trap 形式。

尽管外围设备会产生中断，但 CPU 本身会产生 trap 以处理正在执行的代码中的异常。CPU 这样做的原因有几个，包括执行非法指令（不在 CPU 指令集中的指令）、潜在的运行时错误，如除零情况，以及指令试图访问进程地址空间之外的主内存区域。

在 Linux 术语中，signal 是一种允许中断进程的机制。信号是操作系统提供的高级抽象，允许内核与用户进程之间或两个进程之间进行通信（通常用于进程控制）。在第 13.4 节中，我们详细讨论了这个主题。然而，讨论侧重于 shell 级别的信号处理。表 13.1 显示了一些常用的信号及其用途。请注意，其中一些信号是通过击键生成的，但大多数是软件生成的。我们将在第 16 章中从系统程序员的角度详细讨论信号和信号处理。

## 15.4 系统调用的基础

SCI 是一种机制，允许用户进程在操作系统内核中执行一段代码。进程使用系统调用来调用服务，这些服务允许访问硬件设备和内核资源（代码和数据），而在多用户、分时系统中，进程通常不被允许访问这些资源。这种限制是必要的，以保护属于内核和其他用户的资源（数据和代码）免受用户的意外或恶意访问。SCI 确保这种保护和安全。

### 15.4.1 什么是系统调用？

用户进程不允许直接访问计算机硬件，例如磁盘驱动器和内核数据结构，以确保属于其他用户和内核的资源保持受保护。然而，用户确实需要访问其在系统上拥有的资源，例如文件，以及有关各种系统资源（硬件和软件）的信息，例如 CPU 利用率或系统上运行的任何进程数量。系统调用是一种允许进程执行特权任务的机制，这些任务如果直接访问（读取或写入）I/O 设备或执行一段内核代码，则不允许进程执行。

因此，系统调用是进入 Linux 内核代码的入口点。换句话说，它是进程执行内核中一段代码的方式，确保不属于该进程的资源得到保护。Linux 提供此机制以提供以下几种类型的服务，包括：

- 打开一个文件
- 读写文件数据和属性
- 访问文件属性
- 设置文件属性
- 获取有关系统硬件和操作系统的信息
- 创建一个进程
- 创建进程之间通信的通道
- 获取进程的注意并使其执行特定任务
- 获取有关系统上当前正在运行的进程的信息
- 创建和终止进程
- 停止进程
- 使进程等待不同的事件
- 创建进程之间相互通信的通信通道
- 访问进程属性
- 访问硬件资源的使用情况，如内存和 CPU 利用率

这些服务点是通过 *wrapper*（库）函数提供的，每个系统调用一个。系统程序员使用这些库函数来调用相关服务。

### 15.4.2 系统调用的类型

有几种类型的系统调用处理 Linux 服务的各个方面。我们将它们归类如下：

- 进程控制
- 文件管理/操作
- 设备管理
- 信息维护
- 通信

在本章和本书中关于系统编程的后续章节中，我们将主要介绍与进程控制、文件管理/操作和进程间通信相关的一些常用系统调用。我们在本章讨论与文件管理/操作相关的系统调用。在第 W20 和 W21 章中，我们描述了进程管理和进程间通信的系统调用。

### 15.4.3 系统调用的执行

虽然了解系统调用执行的低级细节对于学习系统编程和精通它不是必要的，但了解操作系统执行系统调用所经历的过程会增强你对该过程的理解。这些步骤依赖于硬件，并且因系统而异。以下是一个步骤序列示例：

1. 用户程序调用充当系统调用包装器的库函数。
2. 库函数：
   i. 将系统调用的参数放在进程栈上。
   ii. 通过寄存器或栈传递一个 *call number*（N），该号码唯一标识系统调用，或作为参数传递给 trap 函数（见第 iii 项）。
   iii. 执行 CPU 指令，称为某些 CPU（如摩托罗拉微处理器）上的 *trap* 指令，以将 CPU 模式从 *user* 切换到 *kernel/system* 并将控制转移到 Linux 内核中的 syscall() 函数。
3. syscall() 函数是系统调用处理程序，并执行以下任务：
   i. 基于调用号识别被调用的系统调用。
   ii. 将适当数量的参数从用户栈复制到内核栈。
   iii. 使用调用号索引 *dispatch table*（包含系统调用服务例程的指针），以执行所请求服务的代码。
