### 18.1 引言：为什么你应该了解并使用 systemd

对于桌面计算机上的普通 Linux 用户而言，由于 systemd 完全自动运行，无需用户做任何操作，那么为什么还要了解并使用它呢？

我们不是在讨论为什么系统管理员、高级 IT 专家、开发人员或系统程序员会想要、会知道或会使用 systemd。

三个初步示例回答了前面的问题。它们是初学者甚至更有经验的 Linux 用户在首次使用 systemd 时可能会遇到的典型场景。

**主要示例 1：** 你想从局域网或互联网上的另一台机器通过 ssh 登录一个新安装的 Linux 系统。当你尝试时，会收到某种晦涩的错误消息，拒绝你通过 ssh 访问该新机器。在你可以用来找出错误原因的众多调试场景中，你只需在该新机器前使用一条 systemd 命令，即可查明 sshd 守护进程是否在运行，甚至是否已安装。然后，从那里快速轻松地解决问题。

**主要示例 2：** 你安装的一个新应用拒绝在你的 Linux 系统上运行。在你可以用来找出该应用行为异常的众多调试场景中，你可以使用一条 systemd 命令来检查最近的系统活动记录，然后从那里快速轻松地解决问题。

**主要示例 3：** 你的 Linux 系统即使对终端中的简单命令也响应非常缓慢，你怀疑某个硬件正在出现故障。你可以使用 systemd 快速轻松地分析系统的整体运行情况，方法是利用可用的“目标”切换到紧急或救援系统状态，从而进入系统操作的调试模式。

我们将在本章后续章节中展示完成这些主要示例的过程。顺便提一下，普通用户需要了解 systemd 的另一个原因是，它已经取代了 Linux 三大分支内核中基于伯克利软件发行版（BSD）风格和 System V 风格的 init 及服务管理机制：Debian（Ubuntu 和 Linux Mint 是其衍生版）、Slackware（openSUSE）和 Red Hat（RHEL、CentOS）。

从表面上看，systemd 是一个集成的 Linux 初始化程序和服务管理器，同时还包含许多额外的重要系统状态控制程序和实用工具。

但实际上，systemd 是一个“超内核”，它使用 Linux 内核本身作为辅助程序来维持 Linux 计算机硬件和软件组件的稳定状态。然后，systemd 监督并管理内核为在该稳定状态下优化运行所做的一切，无论是启动、进程管理和控制、进程间通信（IPC）、硬件服务、网络操作、关机，还是众多其他操作。

如果你已经学过第 17 章和本书网站的 W23 章，你一定会意识到我们在那里介绍的虚拟化技术同样是“超内核”，它们构成了 Linux 内核之上的层。这些虚拟化技术反过来又管理系统启动、磁盘、文件系统以及整个虚拟机。在一定的抽象层次上，操作系统级虚拟化和完全虚拟化只是超内核的实例。

我们已经提出，Linux 内核以及一般而言操作系统最重要的特性是提供虚拟化、并发性和持久性。systemd 提供并高效管理所有这些特性。而且，在这些特性的背景下，systemd 渗透并贯穿于每一个特性之中。

问题：什么是服务管理？

答案：系统服务管理基本上意味着控制哪些服务守护进程运行、它们如何运行以及如何消耗中央处理器（CPU）等系统资源，以及它们何时运行。

systemd 运行并控制我们在本书中演示的所有 Linux 系统——Debian、Ubuntu、Linux Mint 和 CentOS。在本章中，我们将更深入地介绍 systemd，并扩展我们在第 17 章第 2.3.4 节中呈现的内容。
