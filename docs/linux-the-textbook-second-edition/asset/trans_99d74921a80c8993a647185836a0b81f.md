

## 8
## 文件共享
## 目标
- 解释共享文件的方式
- 讨论实现文件共享的 Linux 方案和命令
- 详细描述 Linux 硬链接和软（符号）链接并讨论其优缺点
- 涵盖以下命令和原语：
  `*, ~, df, ln, ln -f, ln -s, ls -i, ls -l`

### 8.1 引言

当一群人共同完成一个项目时，他们需要共享信息。如果要共享的信息位于计算机系统上，团队成员必须共享文件和目录。例如，共同撰写书籍的作者或从事软件项目的软件工程师需要共享与其项目相关的文件和目录。在本章中，我们讨论在计算机系统中实现文件共享的几种方法。本章对文件共享的讨论侧重于在 Linux 系统中文件如何被各种用户从各种目录访问。在第 14 章关于版本控制的主题以及本书网站第 W25 章第 5.7 节中，我们将讨论团队成员如何同时在一个或多个文件上工作而不丢失他们的工作。

可以使用多种方法让一组用户共享文件和目录。在本章中，我们描述了重复共享文件、团队成员的通用登录、设置共享文件的适当访问权限、团队成员的通用组以及通过链接共享。所有这些方法都可用于让 Linux 系统中的用户团队共享文件和目录。虽然我们描述了这些技术中的每一种，但本章主要致力于讨论在基于 Linux 的计算机系统中通过链接共享。

### 8.2 重复共享文件

最简单的方法是复制这些文件并分发给所有团队成员。成员可以将这些副本放在他们自己的账户（目录结构）中的任何位置，并以任何他们想要的方式操作它们。如果团队成员要顺序地工作在共享文件上，该方案效果很好，但如果团队成员要同时工作在这些文件上，则存在明显的问题。在前一种情况下，团队成员一次一个地在共享文件的副本上工作并完成手头的任务。在后一种情况下，由于成员修改了自己的副本，副本变得不一致，没有一份共享文件的副本反映了所有团队成员完成的工作。这种结果违背了共享的目的。

### 8.3 团队成员的通用登录

在此方案中，系统管理员创建一个由团队成员组成的新用户组，并为他们创建一个新的账户，他们都可以访问；也就是说，他们都知道该账户的登录名和密码。团队拥有在此账户下由任何团队成员创建的所有文件和目录，每个人都可以访问它们。

这是一个简单且效果相当好的方案，尤其是在团队数量较少且团队稳定时；也就是说，他们长时间保持在一起。这种情况适用于撰写书籍的作者团队或从事需要数月完成的庞大软件项目的编程团队。然而，该方案也有几个缺点。首先，团队成员必须为当前项目使用单独的账户，并且不能使用他们的常规账户访问共享文件和目录。其次，系统管理员必须为组织中成立的每个新团队创建一个新账户。如果项目的持续时间很短并且每个新项目都成立新团队，则这样做可能会给管理员带来相当多的额外工作。在类似大学的环境中，学生团队为课堂项目而组建，每学期或每季度产生大量团队的情况下，该方案可能会给系统管理员带来真正的麻烦。

### 8.4 设置共享文件的适当访问权限

在此方案中，团队成员决定将所有共享文件放在某位成员的账户下，并且对这些文件的访问权限设置为所有团队成员都可以访问。如果只有该团队的成员构成用户组（请回顾第 5 章中关于所有者、组和其他用户的讨论），该方案效果很好，因为如果组中还有其他用户，他们也将有权访问共享文件。例如，假设两名大学教授 Art Pohm 和 Jim Davis 属于用户组 faculty。他们决定将共享文件放在 Davis 的账户中，但将所有共享文件的组访问权限设置为对所有共享文件可读、可写、可执行。然后用户组 faculty 中的所有教授都将具有相同的访问权限，这将带来安全问题。特别是，如果要共享的信息只是成员账户中总信息的一部分（例如，成员拥有的数十个文件和目录中的两个普通文件），向组中的所有用户敞开大门的风险太高，必须使用更好的技术。

### 8.5 团队成员的通用组

该方案的工作方式与前一种方案类似，只是系统管理员创建一个仅由团队成员组成的新用户组。所有团队成员获得单独的登录并设置其文件的访问权限，以便其他团队成员可以访问。此文件共享方案有效且经常使用，尤其是在与版本控制机制结合使用时（参见第 14 章和本书网站第 W25 章第 5.7 节）。

在第 5.6.3 节中，我们展示了如何为目录设置粘滞位以允许一组用户在其中共享文件和目录，但确保无特权用户无法删除或重命名该目录中其他用户的文件。

### 8.6 通过链接进行文件共享

如第 4 章所述，Linux 文件的属性存储在其磁盘上的 inode 中。当文件被打开时，其 inode 被复制到主内存中，从而可以快速访问其内容。在本节中，我们描述了 inode 的使用如何导致一种机制，使您能够使用多个路径名访问文件。系统管理员通常使用此方案允许通过各种其他目录访问某些文件和目录。因此，例如，系统上所有用户的 home 目录可以通过 /home 或 /usr/home 访问。如第 4 章所述，普通用户的命令、工具和实用程序位于 /bin、/usr/bin 和 /usr/local/bin 目录中，而系统管理员的命令、实用程序、守护进程（参见第 10 章）和工具位于 /sbin、/usr/sbin 和 /usr/local/sbin 目录中。

链接是一种在要共享的文件与希望访问该文件的用户的目录条目之间建立连接的方式。因此，当我们说一个文件有 N 个链接时，我们的意思是该文件在文件系统层次结构中的某个位置有 N 个目录条目。因此，链接通过为要共享的文件提供不同的访问路径来帮助文件共享。然而，对这些文件访问权限的适当设置控制了共享的程度。您可以创建指向您没有任何访问权限的文件的链接，但这毫无用处。因此，通过链接进行文件共享首先是通过建立指向它们的链接来创建对共享文件的访问路径，然后通过设置这些文件的适当访问权限来实现。

Linux 支持两种类型的链接：硬链接和软/符号链接。ln 命令可用于创建这两种类型的链接。本章的其余部分讨论在 Linux 系统中创建这两种类型的链接的方法及其内部实现。

### 8.6.1 硬链接

硬链接是指向文件 inode 的指针。当在 Linux 中创建文件时，系统会为文件分配一个唯一的 inode 并在文件创建的目录中创建一个条目。如第 4 章所述，目录条目包含一个有序对（inode 编号，文件名）。文件的 inode 编号用于访问其属性，包括在磁盘上读取或写入（更改）其内容（参见第 4 章）。假设您在当前工作目录中创建一个名为 Chapter3 的文件，系统为该文件分配 inode 编号 53472；该文件的目录条目将为（52473，Chapter3）。

以下是 ln 命令的简要描述：

```
Syntax:
  ln [options] existing-file new-file
  ln [options] existing-file-list directory
Purpose: First syntax: Create a link to existing-file and name it new-file
Second syntax: Create links to the ordinary files in existing-file-list in directory; links have the same names as the original file
Commonly used options/features:
  -f Force creation of link; don’t prompt if new-file already exists
  -n Don’t create the link if new-file already exists
  -s Create a symbolic link to existing-file and name it new-file
```

不带任何选项的 ln 命令会创建一个文件的硬链接，前提是用户对通向该文件的路径中的所有目录具有执行权限。以下会话说明了如何使用 ln 命令在包含 existing-file 的同一目录中创建硬链接。此示例的唯一目的是说明 ln 命令的使用方式；它并不代表您在实践中建立和使用硬链接的方式。

```
$ ls -il
total 52
16518415 -rw-r--r-- 1 sarwar faculty 1958 Mar  4 09:58 Chapter1
16518416 -rw-r--r-- 1 sarwar faculty 5188 Mar  4 09:58 Chapter2
16518417 -rw-r--r-- 1 sarwar faculty 39573 Mar  4 09:59 Chapter3
$ ln Chapter3 Chapter3.hard
$ ls -il
total 92
```
