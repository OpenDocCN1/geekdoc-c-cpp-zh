## 17.9.6 进程凭证

我们在第 10 章中详细说明的多编程模型要求进程，无论它们是由 shell 内建或外部命令生成，还是由用户编写的程序，或是由使用 fork、exec、execve 系统调用的任何系统程序生成，在它们能够使用诸如系统资源、其他进程、套接字或文件/ inode 等对象之前，必须对其凭证进行身份验证。Linux 系统为进程分配凭证，将进程与特定用户和特定组关联起来。这些凭证在多用户和多编程系统中至关重要，因为它们决定了每个进程在用户空间和内核空间中可以或不可以做什么，维护每个用户个人数据的自主性和系统的稳定性。凭证的使用应用于进程数据结构以及进程试图访问的共享资源中，类似于锁中的钥匙和弹子。文件是系统上的关键资源。因此，在默认的 Linux ext4 文件系统中，每个文件都由特定用户拥有并属于一组用户。文件的拥有者决定了对该文件允许何种操作，区分自己、文件的用户组以及系统上的所有其他用户。当进程试图使用文件时，Linux 虚拟文件系统始终会根据文件所有者建立的权限和进程凭证验证访问是否允许。显然，进程凭证和文件访问权限是集成且不可分割的。这种身份验证耦合基于我们在第 5 章中详细说明的文件权限形式，我们已经展示了 chmod 命令是授予文件和目录这些权限的工具。

### 17.9.7.1 加密的含义

加密使用一种非常成熟的科学，即密码学，来实现数据隐藏。

密码学用于在 Linux 系统上对数据进行编码以隐藏它不被未特权用户看到，然后为特权用户解密或解码数据。在 Linux 系统上，以下是一些可能成为加密目标的对象：

- 单个文件
- 卷或单个分区
- 网页连接
- 网络连接
- 备份文件对象在额外的硬盘或其他媒体上
- 压缩的目录或文件

加密/解密基本上使用多种数学算法来处理上述目标。这些算法称为 *密码学密码*。处理密码学时需要了解的重要术语是 *明文* 和 *密文*。明文是未加密或已解密的格式，而密文是加密的格式。

加密算法的细节、其数学和复杂性，对于普通用户来说不如知道在哪里以及何时应用它们有用。也就是说，在系统、整个磁盘、分区、目录或单个文件级别。并且还知道你为什么要使用它们，并仔细推理和设计你的策略，使用常见的命令行工具来实现这些算法，如书网站上第 W26 章第 9.7.2–9.7.5 节所示。

## 17.10 虚拟化方法

计算机程序和操作系统的虚拟环境可以定义为程序在其中自主运行的外壳。正如我们之前所示，查看操作系统的抽象级别的一部分能力是操作系统呈现虚拟环境幻觉的能力。多任务、多编程操作系统，其中所有用户都呈现出每个单独用户在自己的独立计算机上自主工作的幻觉（事实上许多人也在同一硬件平台上工作），是操作系统虚拟化的一个基本底层方面。在许多方面，在另一个抽象级别上，systemd 可以被视为一个虚拟化程序。它虚拟化 Linux 内核，让你产生直接与之工作的错觉，而事实上你是在 systemd 环境中工作。这种看待 systemd“超级内核”和 Linux 内核本身的方式，最重要的是假设这两个程序的功能是帮助在打开电源、系统运行时或需要关闭电源时维持硬件和软件的稳定状态。在第 18 章中，我们对 systemd 及其操作进行了完整详细的描述。

在书网站上标题为“虚拟化方法”的第 W23 章中，我们展示了在 Linux 主机环境中创建虚拟操作系统环境的两种流行且重要的设施：LXC/LXD 容器和 VirtualBox VMs。这些设施提供了我们在本章中介绍的一些主题的扩展，并扩展了本书前面各章中介绍的许多主题。

这两个设施的区别在于，对于第一个，所有虚拟环境都在同一台主机机器上的同一内核下运行。对于第二个，可以在同一台主机机器上同时运行任意数量的不同内核。这意味着，对于 LXC/LXD 容器，你可以在一台机器上同时运行许多不同的 Linux 发行版。使用 VirtualBox，你可以在一台主机机器上同时运行 Ubuntu、Linux Mint 或 CentOS，或任何数量的其他受支持的操作系统。

Linux 上还有其他类似的虚拟化设施可用。Docker 是另一个容器应用程序套件，允许你“启动”占用磁盘空间大小轻量级的容器实例。一个这些轻量级 Docker 容器实例的典型例子是 Web 服务器软件 nginx。就占用的磁盘空间而言，最轻量级的设施是 Docker 容器，中等重量的是 LXC/LXD 容器，重的是 VirtualBox 客户机。
