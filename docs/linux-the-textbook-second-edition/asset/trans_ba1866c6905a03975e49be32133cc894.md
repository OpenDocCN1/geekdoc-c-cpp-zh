## 14.7.1.5 追踪程序执行

为了找出进程中出现的问题，我们需要识别可能出问题的代码部分。有几种方法可以做到这一点，包括逐行追踪整个程序、追踪某个函数的语句、追踪对特定函数的调用以及追踪变量的变化。我们会使用 gdb 的 where 或 backtrace 命令回溯程序来做到这一点，如下面的会话所示。这两个命令的输出相同：程序发生故障的位置以及到达该位置的方式。其中“如何到达”部分由命令显示的堆栈跟踪（在编程语言术语中也称为堆栈帧或活动记录）中的函数调用序列标识。#0 行显示栈顶，即发生崩溃的 get_input() 函数语句，#1 行显示 get_input() 函数是在 main() 函数的第 20 行被调用的。main() 函数称为调用者（caller），get_input() 函数称为被调用者（callee）。

```
(gdb) where
#0  0x000000000040063b in get_input (prompt=0x400704 "Enter a string: ",
str=0x0) at bugged.c:29
#1 0x00000000004005e3 in main () at bugged.c:20
(gdb) backtrace
#0 0x000000000040063b in get_input (prompt=0x400704 "Enter a string: ", str=0x0) at bugged.c:29
#1 0x00000000004005e3 in main () at bugged.c:20
(gdb)
```

命令的输出显示，当程序收到 SIGSEGV 信号时，它位于 get_input() 函数中第 30 行的位置（内存地址）0x000000000040063b。堆栈帧显示调用序列为 main() => get_input()，并且程序崩溃时正在执行第 29 行的 *str=getchar() 语句（参见上一节的程序清单）。请注意，这一行的代码包含两个赋值语句和一个比较语句。在所有这些语句中，我们都解引用了字符串指针 str。其中两个语句使用了 C 库函数 getchar()。这个库函数经过良好测试，已经使用多年。因此，问题一定出在指针变量 str 上。我们将在后面的一节中继续讨论这个问题。

## 14.7.1.6 设置断点

逐语句查看全部或部分代码的执行情况称为程序/代码追踪。为了追踪代码，你需要在程序中设置断点。你可以使用 break 命令将程序追踪到某个特定语句或函数，如表 14.1 所述。它允许程序不间断地运行，直到控制到达你想更仔细研究的行或函数。以这种方式停止程序的过程称为设置断点。如上一节所示，main 函数从第 14 行开始，但它的第一个可执行语句在第 18 行。我们在 main() 中的第一个可执行语句处设置断点并运行程序。程序在第 18 行停止执行，这是我们设置的唯一断点，该行语句为 null_function1();

```
(gdb) break main
Breakpoint 1 at 0x4005be: file bugged.c, line 18.
(gdb) run
The program being debugged has been started already.
Start it from the beginning? (y or n) y
Starting program: /home/sarwar/linux2e/ch14/bugged

Breakpoint 1, main () at bugged.c:18
18            null_function1();
(gdb)
```

## 14.7.1.7 单步执行程序

始终在程序中设置断点，以便能够逐语句查看全部或部分代码的执行情况。逐语句追踪程序执行的过程称为单步执行程序。单步执行与变量追踪相结合，可以让你仔细研究程序的执行。单步执行可以使用 step 命令完成，该命令执行下一条程序语句，如果该语句是函数调用，则会进入函数内部。你可以使用 next 命令单步执行代码，但它会将一个函数完整执行。如果你正在追踪变量，当变量作用域内的语句执行时，它会显示该变量的值。运行 help scope 命令可获取有关作用域规则的更多信息。

在上一节中，我们在 main 处设置断点并运行程序之后，使用 next 命令逐一运行程序中的每条语句。在第三条 next 语句之后，控制到达 main() 函数中第 20 行的 get_input (PROMPT, temp); 函数调用。然后我们使用 step 命令进入并执行 get_input() 函数中的每条语句。第一条 step 命令将控制带到 get_input() 函数中第一个可执行语句，即 for 循环。第二条 step 语句提示你进行键盘输入。当你输入 Hello World! 后按下 <Enter>，系统会显示错误消息 Program received signal SIGSEGV, Segmentation fault，以及有问题的源代码语句和行号（本例中为 29）以及 str 变量的值。错误消息第二行开头的十六进制数字是导致异常的 getchar() 函数的内存地址。我们可以使用 x 命令显示该内存位置的内容。该命令的输出显示错误发生在 get_input() 函数的第 49 个字节处。我们仍然不知道程序出错的原因。

```
(gdb) next
19 null_function2 ();
(gdb) next
20 get_input(PROMPT, s_val);
(gdb) next
Enter a string: Hello!

Program received signal SIGSEGV, Segmentation fault.
0x00000000004006b3 in get_input (prompt=0x400704 "Enter a string: ", str=0x0)
at bugged.c:29
29 for (*str = getchar(); *str != '\n'; *str = getchar())
(gdb) x 0x00000000004006b3
0x4006b3 <get_input+49>: 0x12eb1088
```
