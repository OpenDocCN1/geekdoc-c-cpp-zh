
```shell
$ ls -l ~/courses/ee446/lab[^5]*.c
...
$
```

类似地，可以使用以下命令来显示当前目录中所有具有四个字符名称且扩展名为 `.html` 的文件的 inode 编号和名称。文件名必须以字母开头，后跟任意两个字符，并以 1 到 5 之间的数字结尾。

```shell
$ ls -i [a-zA-Z]??[1-5].html
...
$
```

在 C shell 下，以下命令显示你主目录中所有不以数字开头且以 `.c` 或 `.C` 结尾的文件的名称。换句话说，该命令显示所有不以数字开头的 C 和 C++ 源程序文件的名称。在 Bourne shell 下，你可以将 `^` 字符替换为 `!` 字符。因此，`ls ~/[^0-9]*.[C,c]` 命令会产生相同的结果。

```shell
$ ls ~/[^0-9]*.[c,C]
...
$
```

## 4.5.6 确定文件内容的类型

由于 Linux 不支持文件扩展名，你可以为任何文件使用任何扩展名。这意味着你可以为可执行程序文件使用 `.jpg` 扩展名。因此，你不能仅通过查看文件名来确定文件内容的类型。由于许多软件工具需要使用扩展名，并且用户可能依赖扩展名，所以扩展名仍然很重要。在 Linux 中，你可以使用 `file` 命令来查找文件内容的类型。该命令主要用于确定文件包含的是文本还是二进制数据。这一点很重要，因为文本文件可以在终端屏幕上显示，而显示二进制文件的内容会在终端屏幕上出现“乱码”，并且还可能冻结你的终端，因为它可能会将某些二进制值解释为控制码。该命令的语法如下。

|  |  |
|---|---|
| **语法：** | `file [option] file-list` |
| **用途：** | 尝试对 file-list 中的文件进行分类 |
| **常用选项/功能：** |  |
| `-f FILE` | 使用 FILE 作为 file-list 中的文件 |

```text
$ file /*
/bin:          directory
/boot:         directory
/cdrom:        directory
/dev:          directory
/etc:          directory
/home:         directory
/initrd.img:   symbolic link to boot/initrd.img-4.4.0-21-generic
/lib:          directory

/media:        directory
```

## 4.5.7 Linux 中文件的表示与存储

如前所述，文件的属性存储在磁盘上称为 inode 的数据结构中。在创建时，每个文件都会从磁盘上的 inode 列表（数组）中分配一个唯一的 inode，该列表称为 i-list。inode 在 i-list 中的索引值称为分配给该文件的 inode 的 inode 编号，即文件的 inode 编号。Linux 内核还在主内存中为所有打开的文件维护一个 inode 表，称为 inode 表。当应用程序打开文件时，会从 inode 表中分配一个 inode，并将磁盘上该文件的 inode 内容复制到其中。

inode 编号用于索引 inode 表，从而可以快速访问打开文件的属性。当文件的属性（例如文件大小）发生变化时，主内存中的 inode 会被更新；磁盘上的 inode 副本会按固定间隔更新。对于未打开的文件，其 inode 驻留在磁盘上。图 4.3 显示了 inode 的部分内容。

“链接计数”字段指定文件在系统内拥有的不同名称的数量。该计数也称为硬链接计数（有关链接的详细信息，请参阅第 8 章）。“文件模式”字段指定文件被打开的目的（读、写等）。“用户 ID”是文件所有者的 ID。“访问权限”字段指定谁可以访问该文件以及执行何种类型的操作（将在第 5 章更详细地讨论）。文件在磁盘上的位置由若干指向包含文件数据的磁盘块的直接和间接指针指定。

典型的计算机系统有多个磁盘驱动器。每个驱动器由许多具有两个表面（顶部和底部）的盘片组成。每个表面在逻辑上划分为称为磁道的同心圆，每个磁道又划分为称为扇区的固定大小部分。所有盘片的两个表面上位于相同位置的磁道构成一个柱面。磁盘 I/O 以扇区（也称为磁盘块）为单位进行。因此，磁盘被称为块设备。传统上，硬盘的扇区大小为 512 字节。较新的硬盘使用 4 K 字节（即 4,096 字节）的扇区大小。CD-ROM 和 DVD-ROM 使用 2 K 字节（即 2,048 字节）的扇区大小。

扇区可以使用由 <磁盘编号、柱面编号、表面编号和扇区编号> 组成的四维地址来寻址。这个四维地址被转换为线性（一维）块编号，而 Linux 中的大多数软件处理的是块地址，因为它们相对容易处理。这些块从最顶层表面上最外层柱面中编号为 0 的扇区开始，该扇区被分配为块编号 0。块编号在该柱面的其余磁道中递增，然后在该磁盘的其余柱面中递增，最后在其余磁盘中递增。图 4.4 所示的示意图是一个磁盘系统的逻辑视图，该系统由磁盘块数组组成。文件空间按两个、四个或八个磁盘块的簇分配。

## 4.7 文件系统

如第 4.2 节所述，并且正如此章所详述的，文件系统通常被认为是在任何现代介质上持久存储数据的一种高度组织且可快速访问的数据集合。这种组织、访问速度、效率和实用性都是任何特定文件系统实现的标志。从这个角度来看，文件系统是一个目录层次结构，其根目录存储在硬盘/固态硬盘（SSD）或磁盘分区上，并挂载（粘合）到某个目录下。文件系统中的文件和目录通过它们挂载所在的目录进行访问。文件系统可以跨多个磁盘，甚至可以跨通过网络连接的计算机。它们的家在任何工作站上都可用，根据需要挂载。本书中所有对文件系统的引用都指向本地文件系统。Linux 网络文件系统（NFSv4）的描述超出了本书的范围，但在第 11 章中会简要提及。

在 Linux 的历史中，使用了各种文件系统来为普通用户提供速度、效率、安全性和实用性。三个当代且极其重要的文件系统是扩展文件系统（ext）、XFS 文件系统和 Zettabyte 文件系统（ZFS）。

这些文件系统中，在所有主要的 Linux 分支中最为普遍的是 ext。大多数 Linux 发行版将其用作默认文件系统。ext 的第四个版本 ext4 是当前版本，具有大规模可扩展性、映射到非常大的磁盘阵列大小的能力以及日志功能等特性。如果文件系统通过将此类更改的意图记录在称为日志的数据结构中，来跟踪尚未提交到文件系统主要部分的更改，则该文件系统被称为使用日志。ext4 支持与 ext3 和 ext2 向后兼容，支持在数据刷新到磁盘之前进行块分配，支持无限数量的子目录，以及以纳秒为单位的时间戳。

ZFS 是一个符合 POSIX 的文件系统，由 Oracle 于 2006 年 6 月首次发布。它是一个事务性文件系统，这意味着文件系统状态在磁盘上始终保持一致。它可靠、灵活、可扩展，具有内置压缩以及用于文件系统备份和恢复的高级功能。然而，ZFS 的标志是它对最大数据完整性的关注，保护用户数据免受各种错误的影响，包括由存储介质老化、电流尖峰、意外磁盘写入等原因引起的错误。它通过使用多种技术来实现这种数据完整性，包括数据复制。基准测试表明，在拥有多个专用磁盘的情况下，ZFS 比 EXT4 快得多。

XFS 是由 Silicon Graphics 创建的高性能 64 位日志文件系统，并于 2001 年移植到 Linux 内核。XFS 的关键特性是执行并行 I/O 操作。它是一个高度可扩展的文件系统，允许 I/O 线程、文件系统带宽、文件大小以及跨多个物理存储设备时文件系统本身的大小具有巨大的可扩展性。
