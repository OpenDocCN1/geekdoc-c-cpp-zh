计算机系统中使用的 CPU 的机器代码。这种翻译通常是一个三步过程，包括编译、汇编和链接。编译过程将源代码（例如 C 程序）翻译为计算机系统中使用的 CPU 的相应汇编代码。然后将汇编代码翻译为相应的机器代码，即对象代码。最后，将对象代码翻译为可执行代码。图 14.2 概述了翻译过程。在大型项目中，你可能有多个源文件。在这种情况下，你将它们编译成单独的对象文件并传递给链接器以生成一个可执行文件。

对象代码由机器指令组成，但它不可执行，因为源程序可能使用了某些库函数，而汇编器无法解析对这些函数的引用，因为这些函数的代码不在源文件(s)中。链接器执行将程序的对象代码与库中的对象代码链接（连接）的任务，并生成可执行二进制代码。

C 程序的翻译在编译之前会经过预处理阶段。C 预处理器翻译以 # 符号开头的程序语句。图 14.3 概述了 C 程序的编译过程。整个翻译过程由单个编译器命令完成。我们将在本章后面讨论各种 Linux 编译器。如前所述，链接器可以被赋予多个对象文件以生成可执行文件。

## 14.4 软件工程生命周期

软件产品是在一系列阶段中开发的，统称为 *软件开发生命周期*。文献中存在并在实践中使用的生命周期模型有多种。用于特定产品的生命周期取决于其规模、要开发的软件的性质（科学、商业等）以及使用的设计方法（面向对象或经典）。一些常用的生命周期

| -bad | 强制在声明后留空行 |
| -bap | 强制在函数体后留空行 |
| -br | 按照更常用的 K&R 风格语法格式化，默认设置 |
| -linux | 按照 Linux 风格编码格式化 |
| -kr | 按照 K&R 风格编码格式化 |
| -orig | 按照原始 Berkeley 风格编码格式化 |
| -st | 将格式化的程序发送到标准输出 |

还有几个其他选项允许你以各种风格格式化代码。你可以在文件名之前或之后指定这些选项。indent 命令确保输入文件和输出文件的名称不同；如果它们相同，它会给出错误消息并退出。默认情况下，备份（即原始）文件保存在在其名称后附加 "~" 的文件中，并且原始文件包含格式化的文件。我们在以下会话中展示了使用名为 second.c 的 C 程序文件对命令的简单使用。indent 命令将源文件 second.c 的原始内容保存在当前目录的 second.c~ 文件中。second.c 文件包含新格式化的代码。

```
$ more second.c
#include <stdio.h>
main()
{
    int i, j;
    for (i=0,j=10; i < j; i++)
    {
        printf("Linux Rules the Networking World!\n");
    }
}
$ indent second.c
$ cat second.c
#include <stdio.h>
main()
{
    int i, j;
    for (i = 0, j = 10; i < j; i++) {
        printf("Linux Rules the Networking World!\n");
    }
}
$
```

如果你没有指定任何输入文件，或指定 "-" 作为输入文件，输入将从标准输入读取。使用 -o 选项，你可以显式指定格式化文件的名称，如 indent first.c -o first_formatted.c。使用 -st 选项，indent 将格式化的代码发送到标准输出。因此 indent -st first.c > first_gnu.c 将保存 Gnu 风格格式化的文件到 first_gnu.c。

## 14.5.3 运行 C、C++、Java、Perl、Python 和 Ruby 程序

Linux 支持大量当代语言的编译器和解释器，包括 C、C++、Java、Perl、Python 和 Ruby。在下面的小节中，我们将展示如何编译和执行 C、C++ 和 Java 程序，以及如何在 Perl、Python 和 Ruby 中运行脚本。我们还将展示如何在 C 中处理多模块程序以及如何将库与你的对象模块链接。

### 14.5.3.1 编译和执行 C 程序

Linux 上有多个 C 编译器可用，包括 cc 和 gcc。Linux 上最常用的 C 编译器是 Gnu C/C++ 编译器 gcc。该编译器是为美国国家标准协会的 C 规范 ANSI C 编写的，ANSI C 是 C 语言的最新标准。所有 C++ 编译器，例如 Gnu C++ 编译器 g++，也可以用于编译 C 程序。g++ 编译器使用必要的选项调用 gcc 使其识别 C++ 源代码。我们在本章中主要讨论 gcc 编译器。

gcc 命令可以带或不带选项使用。我们在此描述一些基本选项，并在本章后面的部分描述一些选项。即使是初学者也常用的一种选项是 -o。你可以使用此选项告知 gcc 将可执行代码存储在特定文件中，而不是默认的 a.out 文件中。在以下会话中，我们展示了使用 -o 选项或不使用 -o 选项编译 first.c 文件中的 C 程序。gcc first.c 命令在 a.out 文件中生成可执行代码，而 gcc -o slogan first.c 命令在 slogan 文件中生成可执行代码。ls 命令用于显示两个 gcc 命令生成的可执行文件的名称。

语法：
**gcc [options] file-list**

用途：此命令可用于调用 C 编译系统。执行时，它会预处理、编译、汇编和链接以生成可执行代码。可执行代码默认放在 a.out 文件中。该命令接受多种类型的文件并根据命令行中指定的选项对其进行处理。文件可以是归档文件（.a 扩展名）、C 源文件（.c 扩展名）、C++ 源文件（.C .cc. 或 .cxx 扩展名）、汇编文件（.s 扩展名）、预处理文件（.i 扩展名）或对象文件（.o 扩展名）。当文件扩展名无法识别时，命令假定该文件为对象或库/归档文件。文件在 file-list 中指定

常用选项/功能：

+   - **-ansi** 强制完全符合 ANSI
+   - **-c** 抑制链接阶段并保留对象文件（扩展名为 .o）
+   - **-g** 为 gdb（Gnu 调试器）创建符号表、分析配置和调试信息
+   - **-llib** 链接到 lib 库
+   - **-mconfig** 为 config CPU 优化代码（config 可以指定各种 CPU，包括 Intel 80386、80486、Motorola 68K 系列、RS6000、AMD 29K 系列和 MIPS 处理器）
+   - **-o file** 在 file 中创建可执行文件，而不是默认文件 a.out
+   - **-O[level]** 优化。你可以指定 0–3 作为 level：通常，level 的数字越高，优化级别越高。如果 level 为 0，则不进行优化
+   - **-pg** 提供用于分析工具 gprof 的分析信息
+   - **-S** 不汇编或链接 .c 文件，并将汇编版本保留在相应的 .s 扩展名文件中
+   - **-v** 详细模式：显示被调用的命令
+   - **-w** 抑制警告
