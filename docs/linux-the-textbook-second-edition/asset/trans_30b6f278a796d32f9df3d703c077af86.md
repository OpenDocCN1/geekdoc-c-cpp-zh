## 10.5.2 Linux进程与线程调度

关于进程和线程调度，你必须先认识到两件初步的事情。首先，Linux 主要是一个通用操作系统，而不是实时（RT）操作系统。这意味着它并不打算用作嵌入式、实时控制系统的基础。但这并不意味着它不能或没有以这种方式非常成功地应用过。实时控制系统的例子出现在任何工业过程应用中的机电嵌入式微处理器引导控制器中。其次，正如 Seymour Cray 所说：“任何人都可以构建更快的处理器。诀窍是构建更快的系统。”这正是调度器所做的；它为你提供了一个吞吐量更高的更快系统。

如第16章16.1节所示，Linux 操作系统及其所运行硬件的稳态维护是通过虚拟化、并发和持久化技术实现的。CPU 调度器提供了操作系统的虚拟化和并发性。

CFS 在 Linux 中实现了虚拟化。这意味着，在系统吞吐量和多进程“同时”执行方面，CPU 看起来比它实际更强大，即使在单核 CPU 上也是如此。CFS 算法及其调度器实现超出了本书的覆盖范围。可以说，CFS 为所有正在执行的进程和线程定制 CPU 使用，以最大化 CPU 利用率和吞吐量。

### 10.5.2.1 Linux调度策略与优先级

进程（或线程）在 CPU 上的调度由调度算法（或策略）决定，该算法从等待使用 CPU 的进程中选择优先级最高的进程，并规定所选进程可以使用 CPU 的时间量。优先级以整数表示。我们简要描述 Linux 调度器使用的各种调度策略以及用于为进程分配优先级值的机制。用于计算优先级的技术使得内核进程能够将其优先级设置得高于任何用户进程。Linux 支持的 CPU 调度策略（或类）及其用途如表10.4所示。

为了全面理解 Linux 中如何分配调度优先级，请浏览 /usr/src/linux-headers-4.4.0-21/include/linux/sched/prio.h。仔细阅读这个头文件将发现，进程的优先级取决于其 nice 值、nice 宽度（NICE_WIDTH）和默认优先级 DEFAULT_PRIO。默认优先级依赖于同一文件中定义的两个符号常量 MAX_RT_PRIO 和 NICE_WIDTH。表10.5显示了这些参数以及计算进程优先级所需的其他一些参数的值。

进程的优先级根据以下公式计算。

$$\text{Priority} = [(\text{nice value}) + \text{DEFAULT\_PRIO}]$$

这意味着较小的 nice 值导致较小的优先级值，反之亦然。因此，如果进程的 nice 值为0，其优先级值将为120。类似地，nice 值为10的进程的优先级值将为130。在 Linux 中，优先级值是反向的，即较小的优先级数字对应较高的 CPU 优先级，反之亦然。因此，优先级值为120的进程将被调度算法优先于优先级值为130的进程。
