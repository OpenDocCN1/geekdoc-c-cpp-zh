正如我们在第 1 章中提到的，进程是正在执行的程序。该程序可能是汇编语言代码、由用 C++ 等高级语言编写的源程序编译后生成的可执行代码、用 LISP、JavaScript、Perl、Python、解释型 C（CINT）或 Linux shell 编写的解释型代码。Linux 系统在每次运行外部命令时都会创建一个进程，并在命令执行完毕后将该进程从系统中移除。我们可以互换使用 *程序* 和 *命令* 这两个术语。

进程的创建和终止是 Linux 系统执行外部命令所使用的唯一机制。在 Linux 这样的典型分时系统中，允许多个用户使用计算机系统并同时运行多个进程，每天会创建和终止数百到数千个进程。请记住，计算机中的中央处理器（CPU）执行进程。问题是，单 CPU 或单核心的系统如何同时执行多个进程？即使对于具有多个 CPU 或 CPU 多核心的系统，进程数也大于 CPU 或核心数。一个进程数大于 CPU 或 CPU 核心数的系统如何同时执行这些进程？对该主题的详细讨论超出了本教材的范围，但我们在第 10.5.2 节以及稍后的第 10.5.1 节中简要涉及了它。你可以在操作系统的概念书籍中获得有关 CPU 调度和相关算法的详细信息。稍后在本章中，我们将讨论查看进程的静态和动态状态、前台和后台进程、守护进程、作业、进程和作业属性以及进程和作业控制。我们将 *分时* 和 *多任务* 同义使用。

你可以使用 nice 或 renice 命令为你的进程分配更高的 nice 值，但非超级用户不能将 nice 值设置为负数。更高的 nice 值意味着更高的优先级值，因此优先级更低。所以，当你增加进程的 nice 值时，你就是在对其他用户进程“友好”。公式清楚地表明，进程最近的 CPU 使用率越高，其优先级值越高，优先级越低。因此，Linux 倾向于最近使用较少 CPU 时间的进程。像 vim 这样的文本编辑器比计算圆周率（π）值的进程获得更高的优先级，因为 vim 大部分时间都在等待 I/O——即读取键盘输入、读写磁盘以及在屏幕上显示文件数据或键盘输入。另一方面，计算 π 的进程大部分时间都在进行计算——即使用 CPU。每秒重新计算所有进程的优先级值会导致进程优先级动态变化（上下波动）。在第 10.5 节中，我们将进一步探讨 Linux 调度概念。我们还在第 10.5.2 节中提供了有关 nice 和 renice 命令使用的更多细节。

### 10.3 Linux 进程状态

Linux 进程可以处于多种状态之一，从一个状态移动到另一个状态，最终完成执行，正常或异常地退出系统。进程在完成工作并优雅地退出系统时正常终止。进程因异常（错误条件）或其所有者或超级用户干预而退出系统时异常终止。进程的所有者可以通过使用命令或特定的按键来终止进程。我们将在本章后面讨论这些命令和按键。进程可能处于的主要状态如图所示 10.1 所示的状态图。

![](img/2a18e06cd9c6395e451f26126ecba1fd_263_0.png)

等待状态涵盖了多个状态；我们在此使用该术语是为了保持图表简洁。属于等待状态的一些状态列在表示该状态的椭圆下方。表 10.1 给出了这些 Linux 进程状态的简要描述。

### 表 10.1
Linux 进程状态的简要描述

| 状态 | 描述 |
|-------|-------------|
| 就绪 | 进程已准备好运行但没有 CPU。根据调度算法，调度程序决定将 CPU 分配给另一个进程。多个进程可以处于此状态，但在单 CPU 机器上，只有其中一个可以执行/运行（即使用 CPU）。 |
| 运行 | 进程实际上正在运行（即使用 CPU）。 |
| 等待 | 进程正在等待某个事件。可能的事件是 I/O 操作完成（例如磁盘/终端读写）、子进程完成（父进程正在等待一个或多个子进程退出），或进程本身正在等待被唤醒，因为它已被置于睡眠状态。 |
| 交换 | 进程已准备好运行，但已被暂时放到磁盘（交换空间）上；也许它需要更多内存，而此时没有足够的可用内存。 |
| 僵尸 | 死亡的进程被称为处于僵尸状态。通常，当进程的父进程在它执行退出调用之前终止时，它会成为僵尸进程。进程已完成并发现父进程没有等待。僵尸进程在实际意义上已完成且不驻留在内存中，但它们仍有一些内核资源分配给它们，无法从系统中移除。所有僵尸及其存活的子进程最终都会被祖父进程 systemd 领养，并从系统中移除。 |

为了简洁起见，并考虑到本书的范围，Linux 进程可能处于的其他状态未包含在此讨论中。

### 10.4 Shell 命令的执行

Shell 命令可以是内部（内置）或外部的。内部/内置命令是指其代码是 shell 进程的一部分的命令。一些常用的内部命令有 .（点命令）、bg、cd、continue、echo、exec、exit、export、fg、jobs、pwd、read、readonly、return、set、shift、test、times、trap、umask、unset 和 wait。外部命令是指其代码位于文件中的命令；文件内容可以是二进制代码或 shell 脚本。一些常用的外部命令有 grep、more、cat、mkdir、rmdir、ls、sort、ftp、telnet、lp 和 ps。Shell 创建一个新进程来执行命令。在命令进程执行期间，shell 会等待其完成。在本节中，我们将描述 shell（或任何进程）如何创建另一个进程并执行外部命令。你可以使用 type 命令来确定你的命令是内置还是外部的，如以下会话所示。在 Bash 下，你还可以使用 `type` 的 `-a` 选项来显示命令的所有位置。请记住，如果你在第 2 章第 2.6 节中为 `type` 命令创建了别名，你将不得不取消别名才能使以下会话正常工作！

在以下会话中，你可以看到 `bg` 命令是内置的。Bash shell 可以通过文件系统结构中可用的可执行文件调用，如下所示。

```
$ type bg
bg is a shell builtin
$ type -a bash
bash is /bin/bash
$
```

Linux 进程可以通过使用 `fork()` 系统调用来创建另一个进程，该调用创建原始进程（即调用 `fork()` 的进程）的精确主内存副本。两个进程都继续执行，从 fork 之后的语句开始。分叉的进程称为父进程，而被创建（分叉）的进程称为子进程，如图 10.2 所示。这里，我们展示了一个创建了子进程（另一个 Bash）的 Bash shell。我们将在第 15–16 章讨论 `fork()` 的使用以及创建进程和进程间通信所需的其他系统调用。
