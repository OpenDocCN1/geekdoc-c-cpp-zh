## 17.8.1.2 systemd Cgroups 对 CPU 调度限制的影响

随着 systemd 被 Linux 内核采纳，并进入所有主要的 Linux 发行版（包括我们所有的代表性系统），许多新特性和更新特性被引入。这些特性彻底改变了系统启动阶段，例如。但最重要的是，它们从根本上改变了系统和应用服务（如 `sshd`）甚至普通用户态进程的管理方式。其中一项被彻底修改和更新的特性，称为控制组（cgroups），在服务与进程/线程管理方面被完全重新组织。进程、线程以及系统服务以统一的方式被分组在一起。这将系统资源管理（例如进程、线程或服务分配到的 CPU 时间百分比）从进程级别提升到了应用级别。这是通过将 cgroup 结构映射到 systemd 的“单元树”来实现的。我们概述了 systemd cgroups 对进程和线程通过 CPU 进行性能调度的影响。在下一节中，我们将重点讨论 cgroups 如何影响内存管理，从而影响系统性能。

在第 18 章中，我们将详细介绍 systemd 的各个方面。关于 cgroups 的更完整论述，请参阅本书网站上的第 W27 章第 6.1 节。我们还在第 10 章第 10.2 节和第 10.5.1 节中阐述了 Linux 内核的 CPU 调度组件及其算法。

cgroups 是一种将服务、进程/线程按照编号组组织在分层树（即“单元树”）中的机制，以便于资源管理。这棵树的结构可以使用 `systemd-cgls` 命令以图形方式展示。我们将展示如何使用 `systemd-cgls` 命令查看和评估 cgroups 结构。然后，对这些编号组施加控制，以影响 CPU 使用率、内存管理、网络带宽以及其他与系统服务相关的活动等资源。这种控制可以是瞬时的或临时的，使用 `systemd-run` 命令即可实现；也可以通过对 systemd 单元文件进行关键修改来实现持久或永久的控制，所有永久性的、开机启动的服务都有这样的单元文件。我们在本节中围绕这两种方式组织内容。

在 Linux 内核引入 cgroups 和 systemd 之前，所有进程获得的系统资源量相似，管理员可以通过进程的 nice 值来修改资源分配以提升性能（根据系统设计时运行的使用场景）。例如，这在第 10 章中有所示范。这种传统方法的缺点是：对于像 Web 服务器或数据库管理程序这样的应用，它们可能同时运行大量子进程或线程，而现有的机制不足以优先处理这些任务组。另一个或一组任务，如果更符合使用场景、属于关键任务，但其子任务数量少得多，却必须与 Web 服务器或数据库管理程序均分资源。

systemd cgroups 相比传统方法具有巨大的优势。例如，使用 systemd cgroups，由 `nginx` Web 服务器启动的所有进程都将拥有自己的 cgroup 编号。这允许您在应用级别使用 systemd 的 `systemctl` 命令控制 `nginx` 及其所有的“子工作进程”。我们将在第 18 章第 5 节中详细介绍 `systemctl` 命令。

关于分层 cgroups 单元树，我们在本书网站的第 W27 章第 6.1 节中提供了更深入的解释。在该节中，我们还展示了 `systemd-cgls` 命令的实用性，以及它如何以一种易于阅读的图形树格式描绘您 Linux 系统上的所有 cgroups 及其分层结构。

这里的关键要点（也是经常被误解的一点）是：如果您运行某个任务，且同时没有其他“优先级”更高（就 cgroup 施加的资源控制而言）的任务在运行，那么该任务将获得 100% 的资源（或接近 100%，因为系统本身需要一小部分资源来维持自身运行！）。

### 17.8.1.2.1 创建临时或持久控制组

正如我们在本书网站第 W27 章第 6.1 节中详细介绍的，cgroup 资源的管理位置是在 systemd 的“单元”文件中。将这种资源管理设施放在单元文件级别，使得其操作可以通过 systemd 的命令行工具进行管理。根据单元文件的类型，您的资源管理设置可以是临时的，也可以是持久的。

要通过单元文件为服务创建临时 cgroup，请使用 `systemd-run` 命令启动该服务。然后，您可以根据系统用例的设计，在应用级别修改资源。值得注意的是，系统编程应用程序可以通过向 systemd 发起 cgroup API 调用来创建临时 cgroup。一旦使用 `systemctl` 命令停止服务，或者系统重新启动（因为使用 `systemd-run` 创建的服务没有永久的单元文件），临时单元就会从系统中移除。

要为服务创建持久 cgroup，请创建/编辑其单元配置文件。该配置在系统重启后仍然保留，因此可用于管理自动启动的服务。

我们在示例 17.8 和 17.9 中，结合相关背景信息，展示了这两种服务创建方法。

### 使用 systemd-run 创建临时 Cgroup 并更改其 CPUShare

要创建临时 cgroup 并在该 cgroup 中运行命令，需要使用 `systemd-run` 命令。`systemd-run` 命令的通用形式（包含一些特定选项）如下：

```
systemd-run --unit=name --slice=slice_name --property prop_name=val command
```

其中

- `name` 是您为该单元指定的名称。如果未指定 `--unit`，系统将自动选择一个无描述性的单元名称。强烈建议始终包含此选项，并选择一个易于识别的描述性名称。
- `slice_name` 是您希望该单元在其下运行的系统中的标准现有 slice 之一。您可以使用 `systemctl -t slice` 命令列出系统上的 slice。或者，您甚至可以通过指定一个新的唯一名称来创建新的 slice。默认情况下，服务和 scope 会在 `system.slice` 中创建。
- `prop_name` 是您希望为该单元初始设置的一个允许的属性，`val` 是您希望为该属性赋予的值。在本节中，我们使用单独的 `systemctl` 命令来更改单元的 `CPUShares`。但也可以使用 `systemd-run` 命令的此选项来完成。
- `command` 是 Linux 命令及其有效选项、选项参数和命令参数，它们将在服务单元启动时于其中执行。该命令应始终放在 `systemd-run` 命令的末尾，以避免将 `systemd-run` 的选项与您希望在单元中运行的命令混淆！

有关选项及其参数的更多信息，请参阅您系统上的 `systemd-run` 手册页。

要设置属性（例如服务获得的 CPU 份额百分比），您可以使用 `systemctl` 命令。使用 `systemctl` 设置服务属性的通用语法是：

```
systemctl set-property service_name property=property_value
```

其中

- `service_name` 是您要修改其属性的服务的名称，
- `property` 是有效的属性名称，并且
- `property_value` 是给定属性的允许值。

更多信息请参阅您 Linux 系统上 `systemctl` 的手册页。
