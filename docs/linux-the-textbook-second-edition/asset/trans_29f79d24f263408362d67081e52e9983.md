

## 18.4 使用 systemctl 查看系统状态

如我们之前所示，可以在逻辑组中操作的 systemd 单元，特别是服务单元，被称为目标单元或简称为目标。本节展示如何使用 systemctl 查看系统状态，以便随后您可以调整服务单元或其他目标单元的各个方面。

### 18.4.1 systemd 服务查看

systemd 允许您分析系统启动过程。您可以列出所有服务及其状态。就效率而言，systemd 还允许您扫描启动过程，以了解每个服务在启动期间花费了多少时间。

要查看自系统上次启动以来已启动的全部活动服务列表，请输入以下命令：

```
$ sudo systemctl
```

要获取特定服务的信息，请使用以下命令：

```
systemctl status name.service
```

要显示启动失败的服务，请在 systemctl 命令中添加 --failed 选项：

```
$ sudo systemctl --failed
```

要调试系统启动时间，您可以使用 systemd-analyze 命令。它显示总启动时间，并且根据您使用的选项，列出按启动时间排序的服务。我们在 Linux Mint 系统上演示此命令的输出，如下所示：

```
$ sudo systemd-analyze critical-chain
```

单元处于活动或已启动后的时间打印在 "@" 字符之后。

单元启动所需的时间打印在 "+" 字符之后。

```

```

该命令还可以生成可缩放矢量图形（SVG）文件，显示服务启动时间与其他服务的相对关系。我们在 Linux Mint 系统上演示此情况如下：

```
$ sudo systemd-analyze plot > /home/bob/mint18-startup.svg
```

前面的命令让您可以查看在图形绘图文件 mint18-startup.svg 中启动的服务及其启动所需的时间，该文件保存在 /home/bob。

## 18.5 创建和添加新的 systemd 控制服务

在本节中，我们首先展示一些创建“新式” systemd 守护进程的简单示例。新式，如我们稍后进一步描述的，意味着守护进程使用 systemd 的功能，而与第 W21 章书网站上说明的“旧式”守护进程相对。

然后我们提供一个完整且实用的 systemd 使用扩展示例：将前面各节所示的一些基本 systemd 设施应用于 C 语言中的一个简单静态页面 Web 服务器守护进程程序。该程序设计为将消息记录到 systemd 日志中，并且可以作为 systemd 服务进行控制。

### 18.5.1 新式守护进程和服务

为了开始本节，重要的是展示一些易于理解的新式 systemd 守护进程示例。

专门编写为仅作为 systemd 服务实现的现代守护进程应遵循一个简单的方案，我们称之为“新式”守护进程。我们留给您将其与在传统 BSD-init 和 System V-init 下运行的“旧式” Linux 守护进程进行对比和比较。我们展示入门级的简单新式守护进程，以及一个更复杂的示例，并对其进行一些观察，以便您了解 systemd 如何简化您与 systemd 的交互，以及它在 Linux 中的服务管理，并增加更多功能。

systemd 中的新式守护进程可以简单到一个 Bash shell 脚本或一个简短的 Python 脚本。它也可以复杂到一个完整的、多模块的 C 程序，其中包含数千行代码。

要使用 systemd 控制它，您可以简单地使用 systemd-run 命令，或者可以通过更复杂的方式将其安装为服务，并附带计时器、套接字或其他单元文件。这些过程在以下各节中进行了解释。

#### 18.5.1.1 一个 systemd-run 命令示例

在本示例中，我们使用 systemd-run 命令执行一个非特权用户 Bash shell 脚本，并说明此守护进程可以作为 systemd 服务进行控制和监控。按以下顺序执行以下步骤，以了解这些要点：

- 1. 在您的主目录中，使用 nano 或您喜欢的文本编辑器创建以下可执行 Bash shell 脚本，命名为 test-daemon.bash：

```
#!/bin/bash
i=0
while sleep 10
do
    echo "<${i}>This message is coming from a new-style daemon"
    i=$(((i+1)%8))
done
```

- 2. 执行以下命令，其中的一些细节我们在第 17 章第 8.1.2.1 节中给出，关于创建临时 cgroups：
  $ systemd-run --user --unit=test-daemon ./test-daemon.sh
  Running as unit test-daemon.service.

- 3. 使用以下命令检查守护进程的状态：
  $ systemctl --user status test-daemon
  • test-daemon.service - /home/bob/./test-daemon.sh

  $ systemctl --user stop test-daemon

#### 18.5.1.2 Bourne-Again 守护进程

以下是我们使用更“永久”且特权用户技术将相同的 Bash shell 脚本制作成服务的示例。按所示顺序执行以下步骤以了解这些要点：

- 1. 在 /usr/local/bin 中创建以下 Bash shell 脚本。将其命名为 new-style.bash，使用您喜欢的文本编辑器。在执行此操作时，请确保拥有 root 权限，以便您可以使用 sudo 命令在第 2 步中保存和执行此文件：

```
#!/bin/bash
i=0
while sleep 10
do
    echo "$i>This message is coming from a new-style daemon" > /dev/pts/0 &
    i=$(((i+1)%8))
done
```

- 2. 当当前工作目录为 /usr/local/bin 时，以 root 身份使用以下命令执行脚本
  $ sudo ./new-style.bash
  注意其在 stdout 上的输出，然后使用 Ctrl-C 终止脚本文件的执行。
