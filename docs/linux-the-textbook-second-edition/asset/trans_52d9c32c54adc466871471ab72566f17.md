### 14.7.2 使用 time 命令衡量运行时性能

程序或任何shell命令的运行时性能可以使用 `time` 命令来测量和显示。该命令报告三个时间：实际时间、系统时间和用户时间。实际时间是程序完成运行所花费的实际时间，系统时间是程序执行期间系统（内核）活动所花费的时间，例如处理时钟中断，用户时间是执行程序代码所花费的时间。由于Linux是一个分时系统，实际时间并不总是等于系统时间和用户时间之和，因为在你的程序执行时可能有许多其他用户进程在运行。下面是该命令的简要说明。

**语法：**
`time [命令]`

**目的：** 报告命令的执行时间，以衡量其运行时性能。它报告三个时间：实际时间（命令执行所花费的实际时间）、系统时间（命令执行期间系统活动所花费的时间）和用户时间（命令代码本身所花费的时间）。

`time` 命令有两个版本：C shell 的内置命令和 `/usr/bin/time` 命令。内置 `time` 命令的输出相当隐晦，而 `/usr/bin/time` 命令的输出则易于阅读。当C shell版本的 `time` 命令在没有任何命令参数的情况下执行时，它会报告当前C shell已经运行的时间长度。报告的时间包括其所有子进程——即在shell下运行的所有命令——所花费的时间。另一个版本的命令没有此功能。`time` 命令将其输出发送到 stderr。因此，如果你希望将 `time` 命令的输出重定向到磁盘文件，则必须将其 stderr（而非 stdout）重定向到该文件。如果你对要计时的程序（或命令）的输出不感兴趣，而只想知道程序完成所需的时间，可以将标准输出重定向到 `/dev/null`。

以下命令报告复制一个10.3 GB文件时 `cp` 命令所花费的时间。请注意输出看起来多么整洁。

```
$ ls -l bigdata
-rw-r--r-- 1 sarwar faculty 10302182842 Oct  3 10:52 bigdata
$ time cp bigdata bigdata.old

real    1m47.155s
user    0m0.040s
sys     0m6.424s
$
```

如前所述，用户时间和系统时间的总和并不总是等于实际时间，尤其是当程序空闲且一段时间内不使用CPU时。在 `time` 命令的输出中，实际时间为1分47.155秒，这显然不等于用户时间和系统时间之和（分别为0.040秒和6.424秒）。

由于 `time` 命令可用于测量任何程序的运行时间，你可以将其用于自己的可执行文件——无论是二进制镜像还是shell脚本。下面的会话展示了 `find` 命令的运行时间。由于我们只想知道 `find` 命令完成需要多长时间，而不是其输出，我们将其输出重定向到 `/dev/null`。

```
$ time find /usr -name socket.h 1> /dev/null

real    0m0.313s
user    0m0.152s
sys     0m0.160s
$
```

还有其他方法可以测量程序的运行时间，并且精度更高。但是，使用 `time` 命令来执行此任务是最简单的方式，我们当然推荐初学者使用。

## 总结

Linux支持所有当代高级语言（包括解释型和编译型），包括C、C++、Java、Javascript、FORTRAN、BASIC和LISP。我们描述了诸如C这样的编译语言程序在执行之前必须经历的翻译过程。我们还简要介绍了典型的软件工程生命周期，并详细讨论了程序开发过程以及Linux中可用于该生命周期阶段的工具。对工具的讨论重点在于如何使用它们开发生产质量的C软件。

程序开发过程包括三个阶段：代码生成、静态分析和动态分析。Linux代码生成工具包括文本编辑器（emacs、pico和vi）、C语言增强器（cb和indent）、编译器（cc、gcc、xlc、CC、cpp和g++）、处理基于模块的软件的工具（make）、创建库的工具（ar、nm和ranlib），以及最常用的版本控制工具git/GitHub及其相关命令。

静态分析阶段的目的是识别软件中可能存在bug或不可移植的特性，并测量诸如LOCs、FPs和函数重复计数等度量。可用于此目的的Linux工具包括cppcheck、memcheck、prof、gprof和valgrind。

动态分析阶段的目的是在程序执行期间对其进行分析。此阶段使用的工具旨在跟踪程序执行，以便调试程序并衡量其执行时间方面的运行时性能。软件生命周期这一阶段常用的Linux工具是调试器（gdb等）和测量程序运行时间的工具（time）。

Linux还有其他一些工具用于软件生命周期的其他阶段，但对此的讨论超出了本书的范围。
