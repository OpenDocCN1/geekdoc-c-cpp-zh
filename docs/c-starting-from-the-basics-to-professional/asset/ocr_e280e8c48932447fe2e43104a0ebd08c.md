The Standard Library offers two generic set containers: `std::set<>` and `std::unordered_set<>`. In essence both provide the exact same functionality. You could replace the `std::set<>` in Ex20_03 with a `std::unordered_set<>`, for instance, and the example will work (nearly) the same. Internally they use very different data structures to organize their data, though, albeit toward the same goal: quickly determining whether and where to insert a new element. We now look at both flavors of sets—ordered and unordered—in a bit more detail.

> **Tip**  Besides `set<>` and `unordered_set<>`, the Standard Library also offers `std::multiset<>` and `std::unordered_multiset<>`. Unlike set containers, multiset containers (also known as bags or msets) may contain the same element more than once (for these containers, `count()` may thus return numbers higher than 1). Their key feature remains that multisets are very fast at determining whether and where a given element is stored in the container.

# Ordered Sets

As the name `unordered_set<>` already gives away, the elements of a regular `set<>` are always ordered. This is also apparent from Ex20_03. Even though you added the elements 1 through 4 in some arbitrary order, the output clearly corroborates that the container somehow organizes its elements in such a way that they become sorted. And for good reason: Ordering your data makes it much easier to quickly find a given element—just imagine how long it would take you to find the definition of *capricious* in a dictionary if all words were scrambled in some arbitrary order!

> **Note**  For those who know their data structures, a `std::set<>` is normally backed by some balanced tree data structure (typically a *red-black tree*). Beyond the fact that this gives you logarithmic `insert()`, `erase()`, `find()`, and `count()` operations, there is normally little need for you to know these implementation details.

By default, a `set<>` orders all elements using the `<` operator. To be stored in a `std::set<T>`, elements of a class `T` should therefore override either operator `<` or operator `>=` (see Chapter 13). We said “by default,” though, because you can override the way a `set<>` orders its elements by specifying which function it should use. For instance, you could replace the definition of `my_set` in Ex20_03 with the following:

```
std::set<int, std::greater<>> my_set;
```

The elements of `my_set` then become sorted from highest to lowest. To print the set you’ll have to update the signature of `printSet()` accordingly as well. To use `std::greater<>`, you may also have to first import the `<functional>` module.

The second type argument of the `std::set<>` class template is optional (it defaults to `std::less<T>`). You can specify any functor type whose binary function call operator compares two `T` elements and returns true if the first element passed to it is first parameter should precede that passed to the second. Typically, a `set<>` default constructs a functor of the corresponding type, but if need be, you could pass one yourself to the constructor of the `set<>` as well.
