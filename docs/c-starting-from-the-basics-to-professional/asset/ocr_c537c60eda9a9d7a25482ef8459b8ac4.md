are not strongly ordered (or totally ordered, as it is more commonly called in mathematics); they are only partially ordered. That is: not all pairs of floating-point numbers are comparable. Concretely, as seen in the previous section, not-a-number values are not ordered with respect to any other number. For that reason, `f1 <> f2` evaluates to `std::partial_ordering::unordered` if `f1` and/or `f2` is not-a-number.

Table 4-2 shows the three types that can be used for three-way comparisons. Comparing two values of most fundamental or Standard Library types results in a `strong_ordering`. When the values are or contain floating-point values, the result becomes a `partial_ordering`. Comparing standard types never results in a `weak_ordering`, but like all comparison category types, you can use it for user-defined `<>` operators (see Chapter 13). An example of a weak ordering would be the ordering of points in an Euclidian space based on their distance to the origin.

**Table 4-2.** Comparison Category Types Defined By `<compare>`

| | less | greater | equal | equivalent | unordered | Usage |
|---|---|---|---|---|---|---|
| `strong_ordering` | ✓ | ✓ | ✓ | ✓ | | Integers and pointers |
| `partial_ordering` | ✓ | ✓ | | ✓ | ✓ | Floating-point numbers |
| `weak_ordering` | ✓ | ✓ | | ✓ | | User-defined operators only |

The three comparison category types are defined by the `<compare>` module. Whenever you use the `<>` operator, even with fundamental types, you have to import the `<compare>` module or you will get a compiler error (you can try it out with Ex4_02).

Notice how only `strong_ordering` uses the term equal, whereas the `partial_` and `weak_ordering` use equivalent. Formally equality implies substitutability, whereas equivalence does not. Substitutability, in turn, more or less means that if `a == b` is true, then `f(a) == f(b)` must be true as well for any function `f`. For floating-point values, for instance, even though `-0.0 == +0.0`, `signbit(-0.0) != signbit(+0.0)` (`signbit()` is a `<cmath>` function that returns—you guessed it—the sign bit of a floating-point number). In other words: `-0.0` and `+0.0` are very nearly equal, but not quite; they are, however, for all intents and purposes, completely equivalent.

**Note** `std::strong_ordering::equivalent` equals `std::strong_ordering::equal`. We recommend you mostly use the latter, as it better expresses the semantics of a strong ordering.

`strong_ordering` values implicitly convert to either `weak_` or `partial_ordering`, and `weak_ordering` values implicitly convert to `partial_ordering`. These conversions have the obvious results. `partial_ordering` values, however, cannot be converted to either of the other types. This makes perfect sense as well: otherwise, what would you do with unordered values?

**Note** The comparison category types of Table 4-2 only act like enumeration types, but they are actually class types. Consequences include that using enum statements will not work for them, and that you cannot use them in the `switch` statement seen later in this chapter either.
