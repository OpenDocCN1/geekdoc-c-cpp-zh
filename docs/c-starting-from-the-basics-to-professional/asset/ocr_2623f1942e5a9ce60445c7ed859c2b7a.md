All algorithms in the `std::ranges` namespace, for instance, are *constrained function templates*. This includes not only the range-based algorithms we discussed in Chapter 20, but also constrained equivalents of the legacy iterator pair-based algorithms in the `std` namespace. When you, for instance, replace the final statement in `Ex21_01.cpp` with `std::ranges::sort(begin(numbers), end(numbers))`, you should get an error message that is much clearer than the one you got with the unconstrained algorithm:

```
error: use of function 'void std::ranges::sort(Iter, Iter) [with Iter = std::_List_iterator<int>]' with unsatisfied constraints
    std::ranges::sort(numbers.begin(), numbers.end());
    [...] 
constraints not satisfied in instantiation of 'void std::ranges::sort(Iter, Iter)':
[...] 
    required for the satisfaction of 'std::random_access_iterator<Iter>'
[...] 
    the required expression '(i - n)' is invalid [...]
    the required expression '(i + n)' is invalid [...]
    the required expression '(i += n)' is invalid [...]
    the required expression '(i -= n)' is invalid [...]
```

**Tip** Always use the algorithms in the `std::ranges` namespace over those in the `std` namespace, even when working with iterator pairs. Thanks to the constraints on their template parameters, these algorithms should result in better error messages when you make a mistake. An added bonus is that many `std::ranges` algorithms accept an optional projection function parameter (see Chapter 20).

Before we can show you how to add constraints to your own templates, we must first introduce the language feature of choice to express their requirements: concepts.

# Concepts

Conceptually, a *concept* is a named set of *requirements*. We distinguish three categories of requirements:

+   - *Syntactic requirements.* For `i` to be a random-access iterator, for instance, expressions such as `i + n`, `i - n`, and `i[n]` should all be valid for integral `n`.

¹Truth be told, we only got an error this clear when using our own constrained version `std::sort()` based on the random-access concept we develop later in this chapter. But at least the potential for more informative error messages is there, and we expect compiler writers and library designers will work hard in the years to come to get better and better diagnostics for constrained templates.
