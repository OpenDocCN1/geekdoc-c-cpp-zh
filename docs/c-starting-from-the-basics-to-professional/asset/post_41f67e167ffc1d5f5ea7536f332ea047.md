### Exercise 17-7.

In Chapter 13 we told you that you can make `std::format()` work with objects of your own class types. As promised, in this exercise you will make it so that, for instance `std::format("My new box, {:.2}, is fabulous!", box)` does the same as

```cpp
std::format("My new box, Box({:.2}, {:.2}, {:.2}), is fabulous!",
             box.getLength(), box.getWidth(), box.getHeight());
```

Like most of the Standard Library, the formatting framework of `<format>` is defined in terms of templates. By default, the templates that underlie `std::format()` can only be instantiated for fundamental types and for the standard string types. But you can add specializations to allow them to be instantiated for your own types as well.

Because function template specialization is flawed (see Chapter 10), the mechanism chosen to allow customization of `std::format()` is of course class template specialization. For every argument of type T that `std::format()` has to format, it creates an object of type `std::formatter<T>` and then invokes two member functions on that object: `parse()` and `format()`. The job of `parse()` is to extract information from the format specification (for instance `:.2`), and to store that information (for instance: the field width 2) in some member variables. These member variables are then used in a subsequent call to `format()` to produce the desired output string.

Creating a full specialization for `std::formatter<Box>` can be quite some work (especially if you have to parse more complex format specifiers), so we propose you take a shortcut here and leverage the existing `std::formatter<double>` type. If `std::formatter<Box>` inherits from that class, you can just have the inherited `parse()` member take care of deciphering the format specifier and use the inherited `format()` member to format the length, width, and height components of your Box.

Your `format()` member must accept two inputs: a Box, obviously, and the so-called format context. The concrete type of this format context is rather long, so we recommend you use auto as a placeholder instead (which effectively reads an extra template type parameter for this member: see Chapter 10). The output of `format()` is to be written to a so-called output iterator (obtained from `context.out()`), and `format()` is to return an output iterator for the remainder of the output. Because this is an exercise on class templates, and you only learn about output iterators in Chapter 20, we will give you an initial outline for the `format()` member (which may or may not compile):

```cpp
auto format(const Box& box, auto& context)
{
    auto iter = format(box.getLength(), context);
    context.advance(iter);
    out = format(box.getWidth(), context);
    context.advance(iter);
    return format(box.getHeight(), context);
}
```

Use this to complete the `std::formatter<Box>` class template specialization and write a short test program that shows that it works. In the solutions online, you can also find an alternate approach for implementing `std::formatter<Box>` that does not rely on inheriting from `std::formatter<double>`.

## Move Semantics

This chapter complements and completes several key topics discussed in the middle parts of the book. In Chapters 12 and 13, for instance, you gained insight from the mechanics behind the copying of objects, that is, copy constructors and assignment operators. And from Chapter 8 you know to prefer pass-by-reference over pass-by-value to avoid undue copying of parameters. For a long time, that was basically all you needed to know. C++ offered facilities to copy objects, and if you wanted to avoid costly copies, then you simply used either references or pointers. Starting with C++11, however, there is a powerful new alternative. You can no longer only copy objects; you can now also move them.

In this chapter, we'll show you how move semantics allows you to efficiently transfer resources from one object into another, without deep copying. We also wrap up our treatment of the special class members—which you already know, the default constructor, destructor, copy constructor, and copy assignment operator.

In this chapter, you’ll learn

- What the difference is between lvalues and rvalues
- That there's another kind of reference: rvalue references
- What it means to move an object
- How to provide so-called move semantics for objects of your own types
- When objects are moved implicitly and how to explicitly move them
- How move semantics leads to code that is both elegant and efficient
- What impact move semantics has on various best practices regarding defining your own functions and types
- The “rule of five” and “rule of zero” guidelines
