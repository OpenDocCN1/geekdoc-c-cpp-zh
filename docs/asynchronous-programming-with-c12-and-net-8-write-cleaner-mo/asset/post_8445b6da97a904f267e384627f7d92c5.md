### 4. Asynchronous API Calls:

Asynchronous programming is crucial when interacting with external APIs, especially when dealing with network latency or long-running operations. Let's consider an example of making asynchronous HTTP requests using the HttpClient class:

```csharp
public async Task<string> GetApiResponseAsync(string apiUrl)
{
    using var httpClient = new HttpClient();
    // Asynchronously send GET request and read response content
    var response = await httpClient.GetAsync(apiUrl);
    // Check if the response is successful
    response.EnsureSuccessStatusCode();
    // Read and return the response content as a string
    return await response.Content.ReadAsStringAsync();
}
```

In this example, the GetApiResponseAsync method asynchronously sends a GET request to an API endpoint specified by the apiUrl parameter using HttpClient. The asynchronous nature of the operation ensures that the application remains responsive while waiting for the API response.

## Chapter 2: Utilizing top-level statements for cleaner and more concise asynchronous code

Utilizing top-level statements in C# 9 and above allows developers to write cleaner and more concise code, especially in asynchronous scenarios. Top-level statements eliminate boilerplate code, making asynchronous programming more straightforward and easier to read. Let's explore how top-level statements can be used effectively in asynchronous code using C# 12 and .NET 8, along with code examples.

### 1. Top-Level Statements Overview:

Top-level statements were introduced in C# 9 as a way to simplify entry points and reduce ceremony in code files. They allow developers to write code without explicit namespaces, class declarations, or Main method signatures, making code files more focused on the actual logic rather than setup.

### 2. Using Top-Level Statements in Asynchronous Code:

Let's dive into an example where we'll create an asynchronous program using top-level statements to fetch data from an API and process it asynchronously.

### Example: Fetching and Processing Data Asynchronously

```csharp
using System;

using System.Net.Http;

using System.Threading.Tasks;

var apiUrl = "https://api.example.com/data";

async Task<string> FetchDataAsync(string url)
{
    using var httpClient = new HttpClient();
    var response = await httpClient.GetAsync(url);
    response.EnsureSuccessStatusCode();
    return await response.Content.ReadAsStringAsync();
}

async Task ProcessDataAsync(string data)
{
    // Simulate data processing asynchronously
    await Task.Delay(1000); // Simulate 1 second delay
    Console.WriteLine($"Processed data: {data}");
}

async Task Main()
{
    var data = await FetchDataAsync(apiUrl);
    await ProcessDataAsync(data);
}
```

In this example:

- We have a top-level async Main method, which is the entry point of the program.
- We define two asynchronous methods:
  - `FetchDataAsync` to fetch data from an API and
  - `ProcessDataAsync` to process the fetched data.
- The `Main` method asynchronously fetches data using `FetchDataAsync` and then processes it using `ProcessDataAsync`.

### 3. Benefits of Using Top-Level Statements for Asynchronous Code:

- **Conciseness:** Top-level statements eliminate the need for explicit class and Main method declarations, resulting in cleaner and more concise code.
- **Focus on Logic:** Developers can focus more on the actual logic of the program rather than boilerplate setup code.
- **Improved Readability:** The reduced ceremony in code makes it easier for developers to understand and maintain asynchronous codebases.

### 4. Handling Exceptions in Top-Level Async Code:

When working with asynchronous code, handling exceptions is crucial. Let's enhance our previous example to include error handling:

```csharp
async Task<string> FetchDataAsync(string url)
{
    try
    {
        using var httpClient = new HttpClient();
        var response = await httpClient.GetAsync(url);
        response.EnsureSuccessStatusCode();
        return await response.Content.ReadAsStringAsync();
    }
    catch (HttpRequestException ex)
    {
        Console.WriteLine($"Error fetching data:\n{ex.Message}");
        throw; // Re-throw the exception
    }
}

async Task ProcessDataAsync(string data)
{
    try
    {
        // Simulate data processing asynchronously
        await Task.Delay(1000); // Simulate 1 second delay
        Console.WriteLine($"Processed data: {data}");
    }
    catch (Exception ex)
    {
        Console.WriteLine($"Error processing data: {ex.Message}");
    }
}
```

In this updated example, we've added try-catch blocks in both `FetchDataAsync` and `ProcessDataAsync` methods to handle potential exceptions gracefully. The `throw` statement re-throws the caught exception to propagate it up the call stack.
