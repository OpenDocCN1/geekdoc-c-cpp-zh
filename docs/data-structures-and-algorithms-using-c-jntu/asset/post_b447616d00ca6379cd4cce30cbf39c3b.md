
### 3.3.7 Back Tracking Algorithms

The backtracking algorithms are completely based on the depth-first recursive search approach. At each step, the algorithm tries to verify whether the solution is found or not. If the solution is found, it exits; otherwise, it moves to the previous step (back) and tries to move to the possible case. If no more choices are found and the solution is not found, then it returns a failure.

Example: 8-Queen Problem.

### 3.3.8 Randomized Algorithms

The randomized algorithms make a random choice at least once to make the decision.

Example: Quick sort uses a random number to select the pivot element.

### 3.3.9 Hill Climbing Algorithms

The complete solution of the problem starts from a poor solution. By repeatedly applying optimizations, an optimal solution will finally be obtained.

## 3.4 Performance Analysis

An algorithm is a step-by-step process of solving a problem. However, a problem can be solved in many ways. Among all the feasible solutions or algorithms, very few algorithms will give a good approach to the solution with minimum amount of time and hardware requirements. These feasible solutions or algorithms are best suited for implementation.

### 3.4.1 Properties of the Best Algorithms

Suppose there are a set of algorithms for a problem. Among all the algorithms, the best algorithm will have the following properties:

- Takes less time for complete execution (time complexity)
- Takes less memory space (space complexity)
- Correctness of the solution
- Modularity
- Maintainability
- Robustness
- Reliability
- Scalability
- Functionality
- Extensibility
- Security
- Simplicity
- User-friendliness
- Programmer time

The algorithms will give a blueprint of software. The algorithms will allow the analysts to find the time it requires to develop the software and it tells the execution time and memory space it requires.

## 3.5 SPACE COMPLEXITY

The number of units of space the algorithm requires is called the space complexity of the algorithm. Each vector variable is allocated one unit of space in the space complexity of the algorithm. But in programs, space complexity depends on the data types used and the number of data items used.

Space complexity of a program is the total memory space required at execution time. Each executable program has the following sections and occupies memory:

- Text section
- Data section
- Bss section
- Rodata section
- Stack section
- Heap section

### 3.5.1 Instruction Space

The total memory space occupied by all instructions at runtime is called instruction space. Instruction space can be calculated based on the static or dynamic libraries the program uses. During execution, dynamic libraries (DLLs) can be loaded into memory based on runtime and conditional requirements. If no dynamic libraries are introduced in the program, then the total space occupied by all instructions is called instruction space.

### 3.5.2 Text Section of a Program

The text section of an executable program contains the processor instructions of the program. Memory size of each instruction depends on word length and is platform dependent (processor and operating system). Total memory space occupied by all instructions is called instruction space.

### 3.5.3 Data Space

Total memory space required by all initialized variables, uninitialized variables, static and constant variables is called data space of a program.

- i. Data section of the executable program
  - Data section contains all initialized global variables and static variables.

- ii. Rodata section
  - Rodata is read-only data. The Rodata section consists of all constants of a program. The user cannot modify data in this section.

- iii. Bss section
  - Bss section contains all uninitialized global variables and static variables.

- iv. Heap section
  - Heap section contains all dynamically created data of the program. This section occupies memory only when the program is executed.

Data space is the total memory space occupied by all data, Bss, rodata, and heap sections.

### 3.5.4 Stack Space

Stack space is the memory space occupied by all uninitialized local variables, formal parameters, frame pointer, and function return pointer. When the main function or a user-defined function calls another sub-function, the function return pointer will be stored in the stack.
