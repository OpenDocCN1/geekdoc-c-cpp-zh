Such an approach may make sense for a general mesh that has been generated by some unknown process, but not in the present context, in which this process is well known. The prolongation operator that transforms a function \(w\) defined on the nodes in the coarse mesh into a fine-grid function \(Pw\) defined on the fine nodes as well can then be designed in a domain-decomposition approach as in Section 17.13 or 21.10, with the sub-domains being, e.g., just coarse finite elements in the coarse mesh. This approach may work not only for the Stokes system but also for the Navier–Stokes and Maxwell systems. Here, however, we introduce a yet more straightforward prolongation operator, which is also suitable for these three systems of PDEs.

This prototype prolongation operator \(P\) indeed uses the property that the coarse mesh in the multigrid hierarchy is the same as the original coarse mesh used in the original adaptive-refinement process. Consider a coarse tetrahedron \(t\), which is split by the refinement process into two fine tetrahedra:

\(t_1 \equiv (\vec{j}, \vec{k}, \vec{n}, \vec{m}),\)
\(t_2 \equiv (\vec{j}, \vec{l}, \vec{n}, \vec{m})\)

by introducing a new fine node \(\vec{n}\) in between \(\vec{k}\) and \(\vec{l}\) (Figure 31.2).

To define the prolongation operator \(P\), let \(w\) be a three-dimensional vector function defined on the corners of \(t\). The fine-grid function \(P w\) is then defined naturally by

\((P w)(\vec{j}) \equiv w(\vec{j})\)
\((P w)(\vec{k}) \equiv w(\vec{k})\)
\((P w)(\vec{l}) \equiv w(\vec{l})\)
\((P w)(\vec{m}) \equiv w(\vec{m})\)
\((P w)(\vec{n}) \equiv \frac{w(\vec{k}) + w(\vec{l})}{2}.\)

Furthermore, let \(q\) be a constant scalar function that has the constant value \(q(t)\) in the entire coarse tetrahedron \(t\). Define \(P q\) as a scalar function that is constant in \(t_1\) and also constant in \(t_2\):

\((P q)(t_1) \equiv q(t),\)
\((P q)(t_2) \equiv q(t).\)

This completes the definition of the fine velocity-type vector function \(P w\) and the fine pressure-type scalar function \(P q\). Thus, the prolongation operator \(P\) is well defined.

As in Section 17.13, the restriction operator is then defined by \(R \equiv P^t\), and the coarse-grid matrix used in the recursion in the multigrid V-cycle is defined by \(Q \equiv R A P\). Alternatively, because the stiffness matrix \(A\) may be highly nonsymmetric, \(R\), \(P\), and \(Q\) can be defined as in Section 17.12. Fortunately, in either case, \(Q\) has the same stencil as the original stiffness matrix that has been assembled in the coarse mesh in the original adaptive-refinement process, so the rest of the multigrid hierarchy can be defined recursively as well.

Clearly, this is just a prototype multigrid version. The prolongation operator designed in Section 21.10 (with each subdomain being, e.g., a coarse tetrahedron) uses much more insight about the original PDE, and thus has a much better chance to produce a good multigrid preconditioner.

Once the Newton iteration is complete and a sufficiently good approximate solution has been found on the current mesh, the next finer prolongation operator can also be used to prolong it to the next finer mesh to serve as an initial guess for the Newton iteration that is about to start there. (See also Section 21.9 above.)

### A.1 Representation of Integers in Any Base

The following code is a more elegant and general version of the code in Section 1.12 in Chapter 1. In fact, it can be used to represent an integer number in any base. In particular, when the chosen base is 2, the code is equivalent to that in Section 1.12 in Chapter 1.

```
int reverse(int n, int base){
    int reversed = n%base;
    while(n /= base)
        reversed = reversed * 10 + n%base;
    return reversed;
} /* reverse an integer number */

int changeBase(int n, int base){
    int even = n%base ? 0 : 1;
    return reverse(reverse(n+even,base),10)-even;
} /* change base from 10 to "base" */
```

### A.2 Prime Factors

In order to have the prime factors of an integer number, we first write a simple function that checks whether a number is prime or not:

```
#include<stdio.h>
int prime(int j){
    for (int i=2; i<j; i++)
        if(j%i==0)return 0;
    return 1;
} /* prime or not */
```

This function is now used in the recursion that prints the prime factors of an integer number. Indeed, given an arbitrarily large integer number n, a loop is used to find its smallest factor i (the smallest number that divides n). (Clearly, i is prime.) Then, both i and n / i are factored recursively, and the loop is terminated. (Clearly, the first recursive call only prints the prime factor i.)

```
void primeFactors(int n) {
    if(prime(n)) printf("%d ",n);
    else
        for(int i=2; i<n; i++)
            if(n%i==0){
                primeFactors(i);
                primeFactors(n/i);
                return;
            }
}  /* prime factors */
```

This is how the above function is actually called in a program:

```
int main(){
    int n;
    scanf("%d",&n);
    printf("%d is the product of ",n);

    primeFactors(n);
    return 0;
}
```

### A.3 Greatest Common Divisor

Here is the code that uses recursion to implement Euclid’s algorithm to find the greatest common divisor of the two positive integer numbers m and n. (Without loss of generality, it is assumed that m > n.)

```
int GCD(int m, int n){
    return m%n ? GCD(n,m%n) : n;
}  /* greatest common divisor */
```

Here is how this function is used:

```
int main(){
    int m,n;
    scanf("%d %d", &m,&n);
    printf("the GCD of %d and %d is %d\n",m,n,GCD(m,n));
    return 0;
}
```
