
Figure 17.9, one must solve a Dirichlet subproblem in the union of finite elements that share this node as their joint vertex.

The Dirichlet boundary conditions for this subproblem are the original values of $u$ at the center node and at the other bullets on the edges across from it. This way, the original value of $u$ at the center node is indeed prolonged implicitly to the rest of the degrees of freedom in Figure 17.9 as well.

Once the above subproblem has been solved, the prolonged values $Pu$ for all the degrees of freedom at the center node in Figure 17.9 are indeed well defined. The definitions of the prolonged values $Pu$ for the degrees of freedom at the edge midpoints in Figure 17.9, on the other hand, are not yet complete: besides the contribution from the center node, there are more contributions from the original $u$ values at the other coarse-grid nodes (the corners in Figure 17.8), which must be added as well to form the final prolonged value $Pu$ at each edge midpoint in Figure 17.9.

In fact, the prolongation procedure at these edge midpoints is in the spirit of the approach used before in the case of linear finite elements. Indeed, if a particular edge midpoint is indexed by $i$ and is assumed to be the only fine point that needs to be prolonged to (a nonrealistic assumption made for the sake of the discussion only), and if the edge endpoints are indexed by $j$ and $k$, then the new prolonged value would be the weighted average

$$(Pu)_i=\frac{A_{i,j}u_j+A_{i,k}u_k}{A_{i,j}+A_{i,k}}.$$

as in algebraic multigrid.

Furthermore, the same applies to the "fine" degrees of freedom at the center in Figure 17.9 as well. Indeed, if such a degree of freedom is indexed by $i$ and is assumed to be the only one that needs to be prolonged to, and if the original $u$-value at the center is indexed by $k$, then the new prolonged value would be obtained by the formula

$$(Pu)_i=\frac{A_{i,k}u_k}{A_{i,k}}=u_k,$$

as in prototype algebraic multigrid.

Thus, we have seen that the present multigrid version for high-order finite elements can be viewed as a geometrically motivated version of algebraic multigrid. In other words, algebraic multigrid can be viewed as a simplified automatic version of prototype multigrid versions not only in linear finite elements but also in high-order finite elements.

## 17.16 Multigrid for Adaptive Meshes

The multigrid method implemented in Section 17.10 assumes nothing about the origin of the linear system of algebraic equations. Indeed, it can be applied equally well to linear systems arising from all sorts of discretization methods, including finite differences, finite volumes, and finite elements. In fact, it provides a "black-box" linear-system solver that takes the coefficient matrix and the right-hand side as inputs and produces the required solution as an output.

resulting multigrid version is no longer a pure "black-box" solver, it might be much more efficient in terms of convergence rate. After all, the more "clever" the solver is in using the specific data available, the more suitable it may be for the specific problem under consideration. Furthermore, with the present object-oriented approach, the extra programming work required to adapt the original implementation can't be too large (see Section 26.1 below).

In Section 17.13, for example, the original domain in which the PDE is defined is decomposed into subdomains to design a prolongation operator that agrees with the original PDE. Although the resulting multigrid version is no longer based on the linear system of algebraic equations alone, it may converge more rapidly and also be more suitable for parallel and cache-oriented implementation. Clearly, a specific version that cleverly uses specific information about the particular problem under consideration must be more efficient than a "stupid" "black-box" algorithm that has to work for many kinds of applications.

The combined domain-decomposition-multigrid solver introduced in Section 17.13 is further extended to two more advanced cases. In Section 17.14, it is extended to systems of PDEs, using extra information from the original PDE about the different unknown functions in it. In Section 17.15, on the other hand, it is extended to high-order finite elements.

The original multigrid algorithm in Section 17.10 is so elementary and pure that it is independent not only of the original PDE but also of the discrete mesh on which it is discretized. In particular, it never uses the history of the mesh or the algorithm by which it has been formed in the first place. Using this information, however, is not necessarily a bad idea—on the contrary, it might be worthwhile in many cases. In fact, it may well enhance the convergence rate, at the cost of some extra programming to read, store, and use the extra information available.

For example, if the mesh has been produced from an adaptive-refinement process, then the improved multigrid version must store all the coarse grids that have been used to form the final fine mesh, and use them as coarse grids in the multigrid linear-system solver as well.

Thus, the additional code required to modify the original multigrid linear-system solver into a more specific version suitable for meshes produced from adaptive refinement is fairly short: it only needs to store the coarse grids used in the adaptive refinement and pass them to the multigrid code to be used there as well. The coarse grids used in the multigrid version are then no longer formed algebraically from the information in the coefficient matrix as in Section 17.8, but are rather the same coarse grids as the ones used in the adaptive-refinement process to form the finest mesh used to assemble the final coefficient matrix.

In Chapters 12 and 13 in [68], the advantage of this version is clearly illustrated. In the applications in this book, however, we prefer to stick to the original multigrid algorithm in Sections 17.8 and 17.9, in which the coarse grids (or levels) are defined purely algebraically in terms of the coefficient matrix only, so no application-dependent data is used.

## 17.17 Adding Rows Efficiently

The set-up phase in the multigrid algorithm requires the calculation of the triple product RAP. Fortunately, R, A, and P are sparse, so this calculation is not too expensive.

To show this, let us consider the calculation of $RA$. The calculation of the $i$th row in $RA$ requires summing a few rows from $A$ multiplied by the corresponding elements from the $i$th row in $R$. Fortunately, the $i$th row in $R$ contains only a few nonzero elements, so this task is not too time consuming.

Still, when the number of nonzero elements in the $i$th row in $R$ is not as small as expected, one may consider another approach, which avoids expensive row operations. In this approach, a dynamic vector is used to store the required $i$th row of $RA$. Initially, this dynamic vector contains zero components only. Then, the relevant rows in $A$ are multiplied by the relevant elements in the $i$th row in $R$ and added one by one to this dynamic vector. Only when it reaches its final form is this dynamic vector converted into the required "row" object and placed in the $i$th row in $RA$.

Similarly, in the ILU factorization, most of the elements in the $i$th row in $L$ are smaller than the prescribed threshold and therefore dropped immediately. As a result, only a few row operations are needed to produce the $i$th row in $U$. Still, if a relatively large threshold is used, so that the $i$th row in $L$ may contain too many nonzero elements, then one should consider the above approach to produce the $i$th row of $U$ in a dynamic vector before it is converted into the required "row" object.

This approach is indeed necessary in the efficient implementation of the approximate-inverse preconditioner below.

## 17.18 Approximate Inverse

The approximate-inverse preconditioner follows from a slight modification of the diagonalization algorithm, Algorithm 2.2, in Section 2.23: once the $i$th column in $W^{t}$ and the $i$th column in $Z^{(i)}$ take their final form in Step 2 of the algorithm in Section 2.23, and once they have been used to calculate the nonzero scalar $D_{ii}$ in Step 3 of that algorithm, they are made sparse by dropping components that are smaller in magnitude than some prescribed threshold $0<\delta<1$ [15]. The diagonal matrix $D$ and the sparse upper-triangular matrices $W$ and $Z$ produced in this modified algorithm are then used to define the preconditioner implicitly by

$$\mathcal{P}^{-1}\equiv ZD^{-1}W^t.$$

Fortunately, the iterative method only requires the application of $\mathcal{P}^{-1}$ to a vector. This can be done efficiently in three steps: first apply $W^t$, then apply $D^{-1}$, and finally apply $Z$.

Since it requires no forward elimination or back substitution in any triangular matrix, the approximate-inverse iterative method is easily implemented on parallel computers. Furthermore, it can serve as a relaxation method within the multigrid V-cycle.

Algorithm 2.2 in Section 2.23 is written in terms of columns rather than rows. To benefit from the present implementation of sparse matrices, which stores rows rather than columns, one should store $W^t$ and $Z^t$ rather than $W$ and $Z$.

The approach discussed in Section 17.17 to sum rows efficiently is particularly valuable here. Indeed, with this approach, $W^{(i)}$ [or $Z^{(i)}$] is embedded and calculated in a dynamic vector, avoiding expensive operations with "row" objects. Only in its final form is $W^{(i)}$ [or $Z^{(i)}$] converted into the required "row" object.
