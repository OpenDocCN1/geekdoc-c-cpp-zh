# # Chapter 26. Adaptive Finite Elements in Three Spatial Dimensions

```
tetrahedron t1(item(i),
itemj,item(k),item(1));
tetrahedron t2(item(i),
t2(item(j),
t1(1),item(k),item(1));
```

Note that, once "itemj" has been used as a corner in "t1", it is referred to as "t1(1)" (a legitimate node in "t1") rather than by its original name "itemj", which stands for a dangling node that belongs to no tetrahedron.

Now, the "refineNeighbors" function is called to refine not only "item" but also its neighbor tetrahedra that share the edge leading from "item[i]" to "item[j]". Clearly, such neighbors can be found only in the "tail" of the linked list, since all the previous ones have already been refined fully:

```
if (next)
( (mesh<tetrahedron*>*)next ) ->
refineNeighbors(item(i),item(j),t1(1));
```

Note that the "next" field is a mere pointer to a linked list of tetrahedra, so it must be converted explicitly into a pointer to an actual mesh before the "refineNeighbors" function can be called.

The two new subtetrahedra, "t1" and "t2", can now be placed in the linked list instead of the original tetrahedron "item":

```
insertNextItem(t2);
insertNextItem(t1);
dropFirstItem();
```

Once "item" has been divided successfully and replaced by its two subtetrahedra "t1" and "t2", the rest of the tetrahedra in the linked list (new as well as old) are also refined by a recursive call to the "refine" function:

```
refine();
return;
}
```

This recursive call actually replaces the original call. Indeed, the "return" command that follows it closes the original call, leaving only the recursive call active. This recursive call continues to refine the up-to-date linked list of tetrahedra, starting from "t1", "t2", etc.

Although "t1" and "t2" have one edge that cannot be divided (because it has just been produced as one half of an original coarse edge, so it has one endpoint whose "getIndex" function returns the trivial value -1), they may still have original coarse edges that may still be divided in the present refinement step. This is why the recursive call must be applied to that tail that starts from "t1" and "t2". Thanks to the "if" question at the beginning of the function, only original coarse edges with endpoints whose "getIndex" function returns a nontrivial nonnegative value to indicate that they indeed belong to the original coarse mesh are divided.
