
```
for(const linkedList<T>* runner = &primes;
    runner; runner = runner->readNext()){
    if(n%(*runner)() == 0)
        return 0;
    if((*runner]() * (*runner]() >= n)
        return 1;
}
return 1;
} // is prime ?
```

Note that this function is implemented as a template function. This gives the user the freedom to call it with 'T' being either "int" or "long int" or even a new class of arbitrarily long integer numbers as in Section 5.24 below. As a matter of fact, 'T' is specified by the arguments with which the function is called. If they are of type "int", then 'T' is interpreted as "int": if, on the other hand, they are of type "long int" (an integer that can be as large as 10^9), then 'T' is interpreted as "long int", and so on.

The above function can now be used in the inductive algorithm to find all the prime numbers between 2 and N. Indeed, once we have the linked list that contains all the prime numbers that are smaller than n, we can call the above "isPrime" function to find out whether n is prime as well or not. If it is, then it is added to the linked list, and the process proceeds to n + 1:

```
template<class T>

    T&largest, T&secondLarge) {
```

The nonconstant arguments "largest" and "secondLarge" that are passed to the function by reference are used to return the two prime numbers that are larger than the first argument "range", which stands for N in the above discussion. The loop below is carried out so long as the Boolean local variable "notComplete" is nonzero:

```
bool notComplete = 1;
largest = 2;

T n=2;

    if(isPrime(++n,primes)){
        secondLarge = largest;
        primes.append(largest = n);
        if(secondLarge>=range)
            notComplete = 0;
    }

```

## 5.17 Lower Bound for the Complexity

Let us calculate a lower bound for the complexity of the above algorithm for a large N. It is well known that the number of prime numbers that are smaller than N is of order N / log N.

(Here the logarithm function is interpreted in, say, base 2: log x ≡ log₂ x.) Furthermore, as we’ll see in Section 5.24 below, the complexity of calculating the modulus operator n%m for two large natural numbers n > m is of order (log n)(log m) bit operations. (The same is true for the division or the multiplication of n by m.) Therefore, each prime number x encountered in the above loop must undergo (in the call to the "isPrime" function) the modulus operator against each of the O(√x / log x) prime numbers that are smaller than √x. Now, at least half of these prime numbers are large enough to have roughly the same logarithm as √x. Therefore, taking the modulus of x against each of them may cost as many as log² √x = (log² x)/4 bit operations.

To estimate (from below) the complexity of the entire algorithm, we must therefore integrate the above costs over all of the x’s between 2 and N, and, in particular, over all the O(N / log N) prime x’s:

∫₂ᴺ 1/log N ∫₂ᴺ √x/(2 log √x) (log √x − 1)(log x) dx ∼ 1/(2 log N) ∫₂ᴺ √x log x dx = 1/(2 log N) · 2/3 x³ᐟ² (log x − 2/3) |₂ᴺ ∼ 1/3 N³ᐟ².

Thus, the above algorithm costs as many as O(N³ᐟ²) bit operations and also sufficient memory to store the O(N / log N) prime numbers. Unfortunately, these requirements are too expensive to afford.

## 5.18 The Elimination Algorithm

Let us now consider another approach, which may be more practical. This is the elimination algorithm, which uses slightly more storage to reduce the time requirement considerably. In this algorithm, all the numbers from 2 to N are stored in a long array. Then, the nonprime numbers are eliminated from the array as described below.

First, we need to calculate the integer part of √N, denoted by ⌊√N⌋ (the largest integer that is smaller than or equal to √N):

```
template<class T>
const T intSqrt(const T& n) {
    T result = 0;
    for(; n >= result*result; ++result)
        ;
    return --result;
} // integer square root
```

Here the empty loop increases the local variable "result" until it gets larger than the required output.

Now, the numbers from 2 to 'N' are placed in a long array of 'N' entries, where 'N' is a constant external integer:

```
const long int N = 10000;
int findAllPrimes(){
    int numbers[N];
    numbers[0] = numbers[1] = 0;
    for(int i=2; i<N; i++)
        numbers[i] = i;
```

Next, the prime numbers (the nonzero entries in the array) are scanned from 2 to ⌊√N⌋:

```
for(int i=2; i<=intSqrt(N); i++)
    if(numbers[i])
```

For each prime number encountered (a nonzero entry in the array), all its multiples, which are clearly nonprime, are eliminated from the array by setting the corresponding entry to zero:

```
for(int j=2*i; j<N; j+=i)
    numbers[j] = 0;
```

Finally, the function also returns the largest prime number found:

```
for(int i=N-1; i>=0; i--)
    if(numbers[i])
        return i;
} // eliminate nonprimes
```

## 5.19 Complexity Estimate

Let us now calculate an upper bound for the complexity of the above elimination algorithm. As follows from Section 5.24 below, the complexity of multiplying the two large integer numbers n and m by each other is of order (log n)(log m) bit operations. Now, each of the O(√N / log N) prime numbers x that lie between 2 and √N has ⌈N / x⌉ multiples that are not larger than N. Each of these multiples is calculated at a cost of at most (log x)(log N) bit operations. Thus, the complexity of the entire algorithm is of order

```
1/log N ∫₂^√N N/x (log x)(log N) dx = N ∫₂^√N log x / x dx
= N/2 log² x |₂^√N
~ N log² N / 8.
```

Thus, the time requirement of the elimination algorithm is only O(N log² N), which is far less than that of the original (inductive) algorithm in Section 5.16. The storage requirement, on the other hand, is slightly larger than in the inductive algorithm: N numbers rather than O(N / log N) numbers.

## 5.20 Finding a Large Prime Number

The above problem is rather difficult: to find all the prime numbers between 2 and N. This is why it has a rather large storage complexity, which keeps N moderate. After all, the resulting prime numbers must be stored somewhere.

Let us now consider the easier problem of finding just one large prime number. For this purpose, one actually only needs an efficient "isPrime" function to check whether a given number n is prime or not.

At first glance, it would seem worthwhile to calculate and store the prime numbers up to ⌊√n⌋, so that n is checked against them only. After all, if n cannot be divided evenly by any of them, then it must be prime as well. However, it turns out that calculating and storing these prime numbers (as in Section 5.16 or 5.18) may increase not only the storage requirement but also the time requirement. As can be seen below, it is better to use a "no-memory" algorithm, in which intermediate results are dropped immediately once they have been used.

Indeed, the following function checks whether a given large number n is prime or not by scanning all the numbers that are smaller than its square root, may they be prime or not, and checking whether either of them divides n evenly:

```
template<class T>
bool isPrime(const T& n){
    for (T i=2; n>=i*i; ++i)
        if(n%i==0)
            return 0;
    return 1;
} // is prime ?
```

The complexity of this function is

∫₂^{√n} (log x)(log n) dx = (log n) x (log x − 1) |₂^{√n} ≈ (√n log² n)/2

Let us now use this efficient function to find a large prime number. Let n be a given large number that is not necessarily prime. To find the largest prime number that is smaller than or equal to n, let us start from n and decrement it by 1 again and again, until the required prime number is reached:

```
template<class T>
const T findPrime(const T& n){
    for (T p=n; ; --p)
        if(isPrime(p))
            return p;
} // find a large prime
```
