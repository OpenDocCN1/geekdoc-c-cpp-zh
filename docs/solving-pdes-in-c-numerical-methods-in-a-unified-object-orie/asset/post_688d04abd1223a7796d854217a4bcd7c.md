
as the polynomial in x

∑ᵢ aᵢ xⁱ

with coefficients that are no longer scalars but rather polynomials in y:

aᵢ = ∑ⱼ aᵢⱼ yʲ

This implementation is slightly more transparent than that in Chapter 5, Section 5.13. Furthermore, the polynomial p(x, y) can still be implemented as a polynomial of polynomials, and the "operator*" can still be used to obtain the product "p*q" of the polynomials p(x, y) and q(x, y). Moreover, the present implementation is particularly useful for integrating over the unit triangle in Figure 5.5. For this purpose, we first define a function that returns the polynomial ∫ˣ p(x)dx, the indefinite integral of p(x):

```
template<class T>
const polynomial<T>
indefiniteIntegral(const polynomial<T>&p) {
    polynomial<T> result(p.size()+1,0);
    for(int i=0; i<p.size(); i++)
        result(i+1) = (1./(i+1)) * p[i];
    return result;
} // indefinite integral
```

This function is now used in conjunction with the functions "operator&" and "operator&&" defined above to integrate over the unit triangle in Figure 5.5:

```
template<class T>
const T
integral(const polynomial<polynomial<T> >&p) {
    polynomial<T> x(2,0);
    x(1) = 1;
    polynomial<T> oneMinusX(2,1);
    oneMinusX(1) = -1;
    polynomial<polynomial<T> >
        integralYp(p.size(),polynomial<T>(1,0));
    for(int i=0; i<p.size(); i++)
        integralYp(i) =
            indefiniteIntegral(p[i]&&oneMinusX);
    return integral(integralYp&x);
} // integral on the triangle
```

## A.9 Sparse Polynomials

Polynomials with only a few nonzero coefficients are called sparse polynomials. It makes no sense to implement such polynomials in a list of coefficients, because there is no point to store the zero coefficients. It makes more sense to use a linked list, in which only the

nonzero coefficients are stored. More precisely, the sparse polynomial is implemented as a linked list of monomials of the form a_i x^i, where a monomial is actually a pair of numbers: a scalar number to store the nonzero coefficient a_i, and an integer number to store the power i.

Later on, we’ll indicate how this object is implemented in the general case. First, however, we implement it in the simple case of a real polynomial of a single variable. In this case, the "monomial" object is already available in Chapter 16, Section 16.2:

```
typedef rowElement<double> monomial;
```

This way, the "monomial" object indeed contains two fields: a "double" field to contain the coefficient a_i, and an integer field to contain the power i. For greater transparency, we also define the member function "power()" that reads this integer field. This function is first declared as a member of the "monomial" class by writing in the body of the "rowElement" class

```
int power() const;
```

Then, it is defined by writing

```
int monomial::power() const{
    return getColumn();
} // power of the monomial
```

Using the code in Chapter 16, Section 16.3, the sparse polynomial is now implemented as a linked list of monomials:

```
typedef row<double> sparsePolynomial;
```

We are now ready to define the operator that multiplies the current sparse polynomial by a monomial. This operator is first declared as a member of the "sparsePolynomial" class by writing in the body of the "row" class

```
const row& operator*=(const rowElement<T>&);
```

Then, it is defined by writing

```
const sparsePolynomial&
sparsePolynomial::operator*=(const monomial&a){
    item = monomial(item.getValue() * a.getValue(),
        item.power() + a.power());
    if(next) *(sparsePolynomial*)next *= a;
    return *this;
} // current sparse polynomial times monomial
```

This member operator is now used to define ordinary operators to multiply "monomial" and "sparsePolynomial" objects:

```
const sparsePolynomial
operator*(const monomial&a,const sparsePolynomial&p){
return sparsePolynomial(p) *= a;
} // monomial times sparse polynomial
```

Furthermore, the "+ =" operator inherited from the base "linkedList" class in Chapter 3, Section 3.5, can be used to add a sparse polynomial to the current sparse polynomial. When the monomials in these polynomials are well-ordered according to increasing power, the sum of polynomials is well-ordered also. This "+ =" operator is now used further to multiply two sparse polynomials:

```
const sparsePolynomial
operator*(const sparsePolynomial&p,
const sparsePolynomial&q){
sparsePolynomial result = q * p;
if(q.readNext()){
sparsePolynomial rest = 
*(const sparsePolynomial*)q.readNext() * p;
result += rest;
}
return result;
} // sparse polynomial times sparse polynomial
```

It is straightforward to extend the above also to polynomials of N independent variables, where N is a fixed integer that may be greater than 1 (see Chapter 25 in [69]). First, monomials of N variables are implemented as a pair whose first field is of type 'T' and second field is of type "vector<int,N>". This way, the "monomial" class is a template class with two unspecified parameters: 'T', the type of coefficient, and 'N', the number of independent variables.

The second field in the above pair contains the indices used in the monomial. For example, when N = 2, the monomial a_i x^i y^j is implemented in the pair (a_i, (i, j)). The sparse polynomial is then implemented as a linked list of monomials, ordered lexicographically: (i1, j1) < (i2, j2) if and only if i1 < i2 or i1 == i2 and j1 < j2. Once the corresponding "operator<" is implemented in the class "vector<int,N>", the "+ =" operator inherited from the base "linkedList" class in Chapter 3, Section 3.5, can be used to add two sparse polynomials while preserving order. The above "operator*" can then be used to multiply two sparse polynomials of N independent variables.

The "difference2" class is derived from "list<dynamicMatrix<T> >". More precisely, a "difference2" object is actually a list of nine "dynamicMatrix" objects. In this list, nine numbers can be stored per grid point. These numbers uniquely define the discrete convection-diffusion terms in two spatial dimensions:

```
template<class T>
class difference2 : public list<dynamicMatrix<T> >{
    public:
        difference2(int,int,const T&,const T&,const T&,const T&,
            const T&,const T&,const T&,const T&,const T&);
```

The above constructor takes two integer arguments to specify the size of the grid and nine "T" arguments to specify the constant coefficients in the constructed "difference2" object. This constructor is only declared above. Here are some more declarations, to be implemented explicitly later on:

```
const difference2<T>&
    operator+=(const difference2<T>&);
const difference2<T>&
    operator-=(const difference2<T>&);
const difference2& operator*=(const T&);
```

The individual elements of the form D_{i,j,k,l} in the difference operator D are accessed (for reading or writing) by the "operator()" with four integer arguments (called as "D(i,j,k,l)"):
```
T& operator()(int i,int j,int k,int l){
    return (*item[(k-i+1)*3+1-j+1])(i,j);
} // access (i,j,k,l)th element
```

The above individual element can also be read by the read-only version, invoked by "D(i,j,k,l,"read")":
```
const T&
operator()(int i,int j,int k,int l, char*) const{
    return (*item[(k-i+1)*3+1-j+1])(i,j,"read");
} // (i,j,k,l)th element (read only)
```

The following member functions return the width and length of the spatial grid:
```
int width() const{ return item[0]->width(); }
int length() const{ return item[0]->length(); }
};
```
