# 5.19 Complexity Estimate

Let us now calculate an upper bound for the complexity of the above elimination algorithm. As follows from Section 5.24 below, the complexity of multiplying the two large integer numbers n and m by each other is of order (log n)(log m) bit operations. Now, each of the O(√N / log N) prime numbers x that lie between 2 and √N has ⌈N / x⌉ multiples that are not larger than N. Each of these multiples is calculated at a cost of at most (log x)(log N) bit operations. Thus, the complexity of the entire algorithm is of order

```
1/log N ∫₂^√N N/x (log x)(log N) dx = N ∫₂^√N log x / x dx
= N/2 log² x |₂^√N
~ N log² N / 8.
```

Thus, the time requirement of the elimination algorithm is only O(N log² N), which is far less than that of the original (inductive) algorithm in Section 5.16. The storage requirement, on the other hand, is slightly larger than in the inductive algorithm: N numbers rather than O(N / log N) numbers.
