
the total time requirement of the algorithm is only

$O(\sqrt{n}\log^3 n).$

Furthermore, this is a completely no-memory algorithm, with a storage requirement as low as $O(1)$ numbers.

As a matter of fact, the above no-memory "isPrime" function can also be used to solve the original problem of finding all the prime numbers between 2 and $N$. This can be done by simply scanning all the numbers from 2 to $N$ and checking which of them is prime. Clearly, this is a completely no-memory algorithm, with storage requirement as low as $O(1)$ numbers. (The prime numbers found throughout the algorithm can be immediately printed onto some external file for safekeeping.) Furthermore, its time requirement is of order

$\frac{1}{2}\int_{2}^{N} \sqrt{x}\log^2 x\,dx = \frac{1}{2}\cdot\frac{2}{3}\left(x^{3/2}\log^2 x - \frac{4}{3}\left(x^{3/2}\log x - \frac{2}{3}x^{3/2}\right)\right)\Bigg|_{2}^{N}$

$\sim \frac{1}{3}N^{3/2}\log^2 N.$

This time requirement is only slightly larger than that in Section 5.16.

## 5.21 Coprime

Let us now introduce an algorithm to find a coprime of a given number $n$, that is, a number that shares no common divisor with $n$. For this purpose, let us first implement Euclid’s algorithm to find the greatest common divisor of two given numbers $m > n$ (see the exercises at the end of Chapter 1):

```
template<class T>
const T GCD(const T& m, const T& n) {
    T mModn = m;
    return (mModn%n) >= 1 ? GCD(n,mModn) : n;
} // greatest common divisor
```

We can now simply iterate in a loop until a coprime of the given number `n` is reached:

```
template<class T>
const T
coprime(const T&n){
    for(T co = 5; ; ++co)
        if(GCD(n,co) == 1)
            return co;
} // coprime
```

The advantage of this implementation is that the resulting coprime is rather small. This turns out to be an advantage in applications in cryptography, as discussed below.

## 5.22 Operations with Modulus

In many practical applications in cryptography, it is required to carry out operations with modulus, such as

$m^e \bmod n,$

where $m, e,$ and $n$ are given positive integer numbers. Unfortunately, $m^e$ may be too large to store in the computer. To avoid too long numbers, it is advisable to take the "mod" operation not only after $m^e$ has already been calculated but also after each multiplication used in the process. For example, the "power" function in Section 5.9 can be rewritten as follows:

```
template<class T>
const T
powerMod(const T&x, const T&n, const T&m) {
    return n!=1 ?
        (n%2 != 0 ?
            x * powerMod(x * x % m, n/2, m) % m
        :
            powerMod(x * x % m, n/2, m))
    :
        x;
// ... x to the n mod m
```

Here, thanks to the fact that the modulus operator is applied to the first argument in the recursive calls, it is kept moderate, as required.

Another important problem is to find the inverse of $q$ modulus $p$

$q^{-1} \bmod p,$

where $p$ and $q$ are given coprime numbers. More specifically, this inverse is defined as the solution $x$ of the equation

$q x \equiv 1 \bmod p.$

Let us show that the inverse of $q$ modulus $p$ indeed exists, and is also unique. Indeed, consider the set of the nonnegative integer numbers that are smaller than $p$:

$S \equiv \{0,1,2,\dots,p-1\}.$

Consider also the mapping

$M : S \to S$

defined by

$M(a) \equiv q a \bmod p, \quad a \in S.$

Let us show that $M$ is a one-to-one mapping. Indeed, if

$M(a) = M(b)$

for some $a,b \in S$ (say, $a \ge b$), then

$q(a - b) \equiv 0 \bmod p.$

In other words, \(p\) divides \(q(a-b)\) evenly. However, since \(p\) shares no prime factor with \(q\), it must divide \(a-b\) evenly as well, that is,

$$a \equiv b \pmod p.$$

This shows that \(M\) is indeed a one-to-one mapping. As a consequence, the number of distinct elements in the image of \(S\) under \(M\) is the same as the number of distinct elements in the original set \(S\):

$$|M(S)|=|S|=p.$$

Thus, \(M\) is a one-to-one mapping from \(S\) onto \(S\). Therefore, \(M\) is also invertible. In other words,

$$M^{-1}: S\to S$$

is well defined. In particular, we can now define

$$q^{-1}\pmod p\equiv M^{-1}1.$$

This completes the proof of our original assertion that the inverse of \(q\) modulus \(p\) indeed exists uniquely.

The following function indeed calculates this inverse. It turns out that, at least for a moderate \(q\), the best way to do this is to scan the sequence

$$1+p,\ 1+2p,\ 1+3p,\ldots$$

until a number that is divisible evenly by \(q\) is reached. This algorithm can be implemented as follows:

```
template<class T>
const T
invertMod(const T&q, const T&p){
  for(T one = p+1; one+=p)
    if(one%q==0)
      return one / q;
} // inverse of q mod p
```

## 5.23 The RSA Algorithm for Coding-Decoding

We are now ready to introduce the RSA algorithm for coding and decoding a message [59]. It is assumed that the message is already in the form of a positive integer number. However, we want the message to be coded in such a way that it can be decoded by the legitimate receiver (decoder) only.

Here is how the RSA algorithm is defined. Let \(p\) and \(q\) (say \(p<q\)) be large prime numbers that are kept secret. Their product

$$n=pq,$$

on the other hand, is available publicly. Define also

$$\phi=(p-1)(q-1).$$

Because \(p\) and \(q\) are kept secret, \(\phi\) is secret as well.

Furthermore, let e ≥ 5 be a small coprime of φ (see Section 5.21). Now, let m be a message, that is, an integer number smaller than p that should be sent secretly to the decoder. Since both n and e are available publicly, the "powerMod" function in Section 5.22 can be used by the sender to calculate the coded message

c = m^e mod n.

To decode the coded message c, the decoder must also have another secret number d, the inverse of e modulus φ:

d ≡ e⁻¹ mod φ.

Thanks to the fact that e and φ are coprime, d indeed exists uniquely and can be calculated using the "invertMod" function in Section 5.22. Fortunately, this can be done by the decoder only, who has φ available.

From Fermat’s little theorem introduced below, it follows that

m^φ = (m^{p-1})^{q-1} = 1 + J q
m^φ = (m^{q-1})^{p-1} = 1 + L p

for some nonnegative integers J and L satisfying J q = L p. Since both p and q are prime, p must divide J as well, implying that J q = J' p q = J' n for some nonnegative integer J'. This means that

m^φ ≡ 1 mod n

as well.

Thus, the decoder is the only one who can use d in the "powerMod" function in Section 5.22 to recover the original message m as follows:

c^d mod n = (m^e)^d mod n = m^{ed} mod n = m m^{K φ} mod n = m.

where K is some nonnegative integer. This completes the definition of the RSA algorithm.

The following program implements the RSA algorithm. This implementation uses variables of type "long int", which may contain integer numbers of order 10^9. In particular, p, q, and m (as well as the external variable N) must be of order 10^4 to make sure that n, φ, d, and the coded message c (including the local temporary variables used in the recursive calls in the "powerMod" function that produces it) do not exceed 10^9.

```
int main(){
    long int p,q,n,phi,e,d,m,c;
    printf("q=%d\n",q = findPrime(N-1));
    printf("p=%d\n",p = findPrime(q-1));
    printf("n=%d\n",n = p * q);
    printf("phi=%d\n",phi = (p - 1) * (q - 1));
    printf("e=%d\n",e = coprime(phi));
    printf("d=%d\n",d = invertMod(e,phi));
    printf("ed mod phi=%d\n",e * d % phi);
    m = p-1;
    printf("m=%d\n",m);
```

```
printf("c=%d\n",c = powerMod(m,e,n));
printf("recovered message=%d\n",powerMod(c,d,n));
return 0;
}
```

Clearly, this program must be kept secret at the hands of the decoder only. Only n and e are made public to let users code their messages. Unfortunately, it would be rather easy to break this code by factorizing n in terms of its prime factors p and q, using, e.g., the "primeFactors" function in Section A.2 in the Appendix.

It is thus necessary to use p and q of a much higher order, for which n is so large that it cannot be factorized in any acceptable time. Fortunately, the improved implementation below is indeed suitable for this purpose: the numbers used in it have no length limit.

## 5.24 Arbitrarily Long Integer Numbers

The "number" class implemented below is derived from a vector of Boolean components to store the binary digits in the binary representation of a number. Since there is no limit on the number of components in the vector, there is also no limit on the number of digits (length) in the number. Furthermore, thanks to the fact that the underlying vector is dynamic, the number of digits can be set properly in run time to allow efficient arithmetic operations.

```
class number : public dynamicVector<bool>{
public:
    int length() const{
        return dim();
    } // length of number
```

The "length()" function above returns the number of binary digits in the current "number" object, or the number of components in the underlying vector. Although this function is exactly the same as the "dim()" function inherited from the base "dynamicVector" class, its name is more relevant and natural in the context of numbers.

In the constructors below, the default constructor of the base "dynamicVector" class is called implicitly first to construct a trivial vector with no components at all. Then, the body of the constructor is executed to allocate memory for the "component" array inherited from the base "dynamicVector" class and initialize it with meaningful values.
