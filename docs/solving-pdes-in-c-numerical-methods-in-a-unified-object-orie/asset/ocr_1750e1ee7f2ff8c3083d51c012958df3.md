# 5.20 Finding a Large Prime Number

The above problem is rather difficult: to find all the prime numbers between 2 and N. This is why it has a rather large storage complexity, which keeps N moderate. After all, the resulting prime numbers must be stored somewhere.

Let us now consider the easier problem of finding just one large prime number. For this purpose, one actually only needs an efficient "isPrime" function to check whether a given number n is prime or not.

At first glance, it would seem worthwhile to calculate and store the prime numbers up to ⌊√n⌋, so that n is checked against them only. After all, if n cannot be divided evenly by any of them, then it must be prime as well. However, it turns out that calculating and storing these prime numbers (as in Section 5.16 or 5.18) may increase not only the storage requirement but also the time requirement. As can be seen below, it is better to use a "no-memory" algorithm, in which intermediate results are dropped immediately once they have been used.

Indeed, the following function checks whether a given large number n is prime or not by scanning all the numbers that are smaller than its square root, may they be prime or not, and checking whether either of them divides n evenly:

```
template<class T>
bool isPrime(const T& n){
    for (T i=2; n>=i*i; ++i)
        if(n%i==0)
            return 0;
    return 1;
} // is prime ?
```

The complexity of this function is

∫₂^{√n} (log x)(log n) dx = (log n) x (log x − 1) |₂^{√n} ≈ (√n log² n)/2

Let us now use this efficient function to find a large prime number. Let n be a given large number that is not necessarily prime. To find the largest prime number that is smaller than or equal to n, let us start from n and decrement it by 1 again and again, until the required prime number is reached:

```
template<class T>
const T findPrime(const T& n){
    for (T p=n; ; --p)
        if(isPrime(p))
            return p;
} // find a large prime
```
