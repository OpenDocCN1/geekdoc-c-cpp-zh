
## 17.19 Naive Implementation of Approximate Inverse

We start with the naive implementation of the approximate inverse, which uses too many row operations. Later on, this implementation will be improved by replacing these expensive row operations with more efficient vector operations. For this, however, we must first implement some preliminary operators and functions.

```cpp
row<T>& operator()(int i) {
return list<row<T> >::operator()(i);
} // read/write ith row
```

This version only invokes the "operator()" of the base "list" class to access the "i"th row in the matrix. With this version, one can write not only A[i][j] to read the "i"th row in the sparse matrix 'A', but also "A(i)" to read or change this row.

```cpp
const T operator*(const row<T>& r) const {
return getColumn() > r.getColumn() ?
r * *this :
r * *this;
}
```

Now, if the current "row" object contains only one row-element, then the required real inner product is just the product of this element with the corresponding one in 'r':

```cpp
!next ?
getColumn() == r.getColumn() ?
getValue() * r.getValue()
0
```

If on the other hand, there are more row-elements in the current "row" object, then a recursive call must be used to calculate and add the contribution from the "tail" of the current "row" object as well:

```cpp
getColumn() == r.getColumn() ?
getValue() * r.getValue()
+ r * *(row<T>*)readNext()
:
r * *(row<T>*)readNext();
} // row times row (real inner product)
```

We now use the above functions to implement a product of the form $A(r^t)$, where $A$ is a sparse matrix and $r$ is a row:

```cpp
template<class T>
const dynamicVector<T>
operator*(const sparseMatrix<T>&M,const row<T>&r){
  dynamicVector<T> result(M.rowNumber(),0.);
  for(int i=0; i<M.rowNumber(); i++)
    result(i) = M[i] * r;
  return result;
}  // matrix times row
```

Finally, we add to the block of the "sparseMatrix" class a member operator that divides each row in the current "sparseMatrix" object by the corresponding component in a dynamic vector:

```cpp
const sparseMatrix&
operator/=(const dynamicVector<T>&D){
  for(int i=0; i<rowNumber(); i++)
    *item[i] /= D[i];
  return *this;
}  // divide each rows by the components of a vector
```




## 17.20 More Efficient Implementation of Approximate Inverse

The following implementation improves on the original one by avoiding expensive row operations and replacing them by more efficient vector operations. For this, however, we must first define some preliminary operators and functions.

The following (ordinary) operator adds a row to a dynamic vector, using a loop over the elements in the row:

```cpp
template<class T>
void operator+=(dynamicVector<T>&v, const row<T>&r) {
    for(const row<T>* runner = &r; runner;
        runner = (const row<T>*)runner->readNext())
        v(runner->getColumn()) += runner->getValue();
} // adding a row to a dynamic vector
```

The following constructor should be added to the block of the "row" class. It constructs a row from a given dynamic vector:

```cpp
row(const dynamicVector<T>&v, double threshold=0.) {
    row<T>* runner = this;
    int first = 1;
```

At the start of the constructor, the default constructor of the base "linkedList" class is invoked implicitly to construct a trivial linked list with only one (trivial) "rowElement" object in it. The local pointer "runner" points to the last item in the underlying linked list, or to the last row-element in the row. The local integer "first" indicates whether it is the first row-element that is about to be defined. The following loop scans the components of the given dynamic vector and detects components that are not too small in magnitude:

```cpp
for(int i=0; i<v.dim(); i++)
    if(fabs(v[i])>threshold) {
```

In order to add a new row-element to the row, we first need to check whether "first" is equal to 1 or not, or whether this is the first row-element in the constructed "row" object or not. If it is, then "runner" already points to it and can be used to define it. If, on the other hand, the first row-element had already been defined and this is another row-element that is about to be defined, then a new memory must first be allocated for it, and "runner" must be advanced to point to this new item:

```cpp
if(!first) {
    runner->next = new row<T>;
    runner = (row<T>*)runner->next;
}
```

Finally, we define an ordinary operator to calculate the real inner product of two dynamic vectors:

```cpp
template<class T>
const T operator&&(const dynamicVector<T>&u,
    const dynamicVector<T>&v){
    T sum = 0;
    for(int i = 0; i < u.dim(); i++)
        sum += u[i] * v[i];
    return sum;
} // real inner product
```

We are now ready to introduce the improved implementation of the approximate inverse.

```cpp
template<class T>
const sparseMatrix<T>
sparseMatrix<T>::factorize(double threshold){
    sparseMatrix<T> At = transpose(*this);
    sparseMatrix<T> Wt(rowNumber());
    sparseMatrix<T> Zt(rowNumber());
```

Unlike in the original implementation, here the sparse matrices "Wt" and "Zt" (that will store W^t and Z^t) are constructed by the constructor that takes only one argument: an integer number to indicate the number of rows in the matrix. The rows themselves, however, are still not constructed and not allocated memory. This will be done later on, when the rows are available in their final form.

```cpp
dynamicVector<T> D(rowNumber(),0.);
for(int i=0; i<rowNumber(); i++){
    row<T> r = *item[i];
```

Unlike in the original implementation, here the i'th column in W is stored in the dynamic vector "wi", and the i'th column in Z is stored in the dynamic vector "zi":

```cpp
dynamicVector<T> wi(rowNumber(),0.);
wi(i) = 1.;
dynamicVector<T> zi(rowNumber(),0.);
zi(i) = 1.;
for(int j=0; j<i; j++){
    row<T> wj = -1. * (Zt[j] * r) / D[j] * Wt[j];
    wi += wj;
}
row<T> c = At[i];
for(int j=0; j<i; j++){
    row<T> zj = -1. * (Wt[j] * c) / D[j] * Zt[j];
    zi += zj;
}
```

This way, an inexpensive matrix-vector product is used to calculate D_i,i, rather than an expensive matrix-row product:

```cpp
D(i) = wi && (*this * zi);
```

Finally, the required 'i'th column in W (or Z) is constructed from those components of "wi" (or "zi") that are not too small in magnitude:

```cpp
Wt.item[i] = new row<T>(wi,threshold);
Zt.item[i] = new row<T>(zi,threshold);
}
*this = transpose(Zt);
return Wt /= D;
} // efficient approximate inverse
```

For the applications in this book, however, it turns out that the approximate inverse (even with this efficient implementation) is much inferior to Gauss–Seidel, both as a preconditioner on its own and as a relaxation method within the multigrid V-cycle. This is why we decline to use it in the applications below. Still, approximate inverse may have its own advantage for other kinds of applications, particularly when parallel implementation is considered. It would be interesting, though, to compare the performance of approximate inverse with that of the parallel ILU version in [66].
