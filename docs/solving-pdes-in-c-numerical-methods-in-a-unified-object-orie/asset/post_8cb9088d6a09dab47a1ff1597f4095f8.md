
## 5.31 Implementation of the Rabin–Miller Test

To implement the Rabin–Miller test, we must first write a function that takes the nonconstant argument "n1" and filters out every power of 2 from it. In other words, the function writes "n1" in the form

n1 = 2^r s,

where s is odd. In the process, "n1" is gradually changed into s, and r is returned by the function:

```cpp
template<class T>
int factor2(T& n1){
    int r = 0;
    while(n1%2==0){
        n1 /= 2;
        r++;
    }
    return r;
} // factorize powers of 2
```

When the function is actually called, the template parameter 'T' can be set to the class "number" defined above, to stand for an arbitrarily long integer number. Furthermore, the input argument "n1" may take the value n − 1, where n is the tested number. This way, the function indeed produces the required factorization

n − 1 = 2^r s,

where s is odd. The numbers r and s are then passed to the function "test()" that implements the Rabin–Miller test as follows:

```cpp
template<class T>
bool test(const T& a, int r, const T& s, const T& n){
    T a2js = powerMod(a,s,n);
    for(int j=0; j<r; j++){
        if(a2js==1)
            return j ? 0 : 1;
```

In this loop, the local variable "a2js" contains the number

a^(2^j s) mod n.

Initially, the index 'j' contains the value j = 0, so "a2js" takes the value

Later on in the loop, on the other hand, when the index 'j' contains the value j ≥ 1, the situation is different. In fact, if "a2js = 1 or a2js ≡ 1 mod n, then a2j+1s = (a2js)^2 ≡ 1^2 ≡ 1 mod n. Furthermore, by repeating this process, we also have a2j+2s ≡ a2j+3s ≡ … ≡ a2js ≡ 1 mod n. This means that the test fails, so the function must return 0, as is indeed done in the above code line.

If, on the other hand, a2js ≡ -1 mod n for some 0 ≤ j < r, then the test is passed, so the function must indeed return 1:

```cpp
if(a2js == n - 1)
    return 1;
a2js = a2js * a2js % n;
return 0;
// Rabin--Miller test
```

Clearly, the length of the above loop is r ≤ log2 n. Furthermore, each step in this loop requires at most one modulus operation, with time complexity of at most log2 n. Thus, the total time complexity of the above function is as small as O(log3 n).

The above functions are now used to apply 'k' consecutive tests. Ideally, the input argument 'a' should be picked randomly between 2 and n - 2. This way, the 'k' tests are indeed independent of each other. In the implementation below, however, we initially pick a = s/2 in the first test, and then increase a gradually in the subsequent tests. Although the tests are then no longer independent of each other, they still give a rather strong indication as to whether n is indeed likely to be prime or not:

```cpp
template<class T>
bool isPrime(int k, const T& n) {
    if ((n==2) || (n==3))
        return 1;
if(n%2==0)
    return 0;
T s = n - 1;
int r = factor2(s);
T a = s / 2;
for(int i=0; i<k; i++){ 
    if(!test(a,r,s,n))
        return 0;
    ++a;
}
return 1;
} // is probably prime ?
```

This completes the implementation of the Rabin–Miller test. The total time complexity is as small as

$O(k \log^3 n)$.

## 5.32 FFT and Its Use in Cryptography

The discrete Fourier transform is used often in applied science and engineering. An efficient way to calculate this transform is by the recursive Fast Fourier Transform (FFT), introduced by Cooley and Tukey.

Below we use recursion and dynamic vectors to come up with a particularly straightforward implementation of FFT. Furthermore, we study the performance of FFT and show that it is indeed better than that of the naive algorithm. Still, we also discuss and estimate the storage overhead in FFT.

FFT is particularly useful in multiplying arbitrarily large natural numbers efficiently. As we’ve seen above, this operation is often required in practical algorithms in cryptography.

As discussed above, natural numbers used in cryptography should be so large that they can never be stored in any standard "int" or even "long int" variable. Fortunately, the object-oriented approach comes to our aid once again: after all, we can define our own "number" class (as in Section 5.24) by derivation from an arbitrarily long array of bits. This way, any mathematical algorithm can preserve its original implementation: all that one needs to do is to use "number" rather than "int" in the original template functions. This way, the original algorithm can use huge natural numbers to produce practically unbreakable coding-decoding methods.

## 5.33 The Discrete Fourier Transform

Let

$f \equiv (f_0, f_1, f_2, \dots, f_{n-1})^t$

be an $n$-dimensional vector with complex components. Let $f()$ also denote the polynomial of degree $n-1$

$f(z) \equiv f_0 + f_1 z + f_2 z^2 + \cdots + f_{n-1} z^{n-1} = \sum_{i=0}^{n-1} f_i z^i.$

As we'll see below, the discrete Fourier transform of the original vector f is obtained by sampling the polynomial f(Z) at n distinct complex points z. Because any polynomial of degree n − 1 is determined uniquely by its value at n distinct points, the Fourier transform is indeed invertible.

More precisely, the inverse Fourier transform can be used to calculate the coefficients of a polynomial from its values at n equidistant points of the form z0, z1, ..., zn−1 on the unit circle in the complex plane. This may be quite practical: for example, to calculate the coefficients of the product of two given polynomials f() and g(). one only needs to sample them at z0, z1, ..., zn−1 and then apply the inverse Fourier transform to the n products f(z0)g(z0), f(z1)g(z1), ..., f(zn−1)g(zn−1).

Let us now define the Fourier transform in some more detail. Let wn be the nth complex root of the unity in the complex plane:

wn ≡ exp(−2π√−1/n).

Define the Fourier matrix of order n by

Wn = (wij)0≤i,j<n .

The Fourier transform transforms the original vector f into the vector Wn f obtained by evaluating the polynomial f() at the powers of w:

Wn f = (f(1), f(wn), f(wn2), ..., f(wn^{n−1}))^t .

## 5.34 The Inverse Transformation

Let us now discuss a few properties of the Fourier transform and its inverse. First, the columns of Wn are orthogonal to each other. Indeed, the inner product of the jth and kth columns (for some distinct 0 ≤ j,k < n) is

∑_{i=0}^{n−1} (w^j)^i (w^k)^i = ∑_{i=0}^{n−1} (w^{j−k})^i = (1 − (w^{j−k})^n ) / (1 − w^{j−k}) = (1 − 1) / (1 − w^{j−k}) = 0.

Furthermore, the squared l2-norm of the jth column of Wn (for some 0 ≤ j < n) is

∑_{i=0}^{n−1} (w^j)^i (w^j)^i = ∑_{i=0}^{n−1} (w^j)^i = ∑_{i=0}^{n−1} 1 = n.

Thus, the inverse Fourier matrix is

Wn^{−1} = 1/n Wn^* = 1/n \bar Wn = 1/n ( (w_n^{-1})^{ij} )_{0≤i,j<n} .

The inverse Fourier transform can thus be applied simply by applying the original Fourier transform with \bar w_n = w_n^{-1}, rather than the original w_n, and then dividing by n.

## 5.35 The Naive Implementation

Let us first implement the Fourier transform and its inverse in the naive way. It is assumed that the original vector **f** has components of type ‘T’, which may be the “complex” type, the “double” type, the “int” type, etc. The returned vector, on the other hand, has components of type ‘S’, which may be different from ‘T’. Usually, ‘S’ is the “complex” type. Still, ‘S’ is not yet specified; this way, it may be a more complicated type in more advanced applications.

The argument "type" is used to specify ‘S’. In the applications below, "type" is going to be a “complex” object, thereby setting ‘S’ to be “complex” as well, as required.

The integer argument "inverse" determines which transform is applied. If it vanishes, then the original Fourier transform is applied. If, on the other hand, "inverse" == 1, then the inverse transform is applied:

```cpp
template<class T, class S>
const dynamicVector<S>
FT(int inverse, const dynamicVector<T>&f,
   const S&type)
{
   dynamicVector<S> result(f.dim(),0.);
   double angle = 8. * atan(1.) / f.dim();
   const complex
      w(cos(angle),(2*inverse-1) * sin(angle));
```

The local complex variable ‘w’ contains wₙ (if "inverse" = 0) or w̄ₙ (if "inverse" = 1). Next, the polynomial f() is formed and stored in the local "polynomial" object "ff":

```cpp
complex wi=1.;
polynomial<T> ff(f.dim());
for(int i=0; i<f.dim(); i++)
   ff(i) = f[i];
```

Horner’s algorithm is then used to sample "ff" at the powers of ‘w’ and place the results in the returned vector "result":

```cpp
for(int i=0; i<f.dim(); i++){
   result(i) = HornerPolynomial(ff,wi);
   wi *= w;
}
return inverse ?
             result / result.dim()
           : result;
}  // naive Fourier transform
```

This completes the naive implementation of the Fourier transform and its inverse.

This naive implementation requires the evaluation of the polynomial f() at 1, wₙ, wₙ², ..., wₙⁿ⁻¹. Because each such evaluation requires O(n) arithmetic operations, the total number of arithmetic operations is O(n²). This amount may be prohibitively large for large n. To avoid this, let us introduce FFT.
