After all, the more "clever" the solver is in using the specific data available, the more suitable it may be for the specific problem under consideration. Furthermore, with the present object-oriented approach, the extra programming work required to adapt the original implementation can't be too large (see Section 26.1 below).

In Section 17.13, for example, the original domain in which the PDE is defined is decomposed into subdomains to design a prolongation operator that agrees with the original PDE. Although the resulting multigrid version is no longer based on the linear system of algebraic equations alone, it may converge more rapidly and also be more suitable for parallel and cache-oriented implementation. Clearly, a specific version that cleverly uses specific information about the particular problem under consideration must be more efficient than a "stupid" "black-box" algorithm that has to work for many kinds of applications.

The combined domain-decomposition-multigrid solver introduced in Section 17.13 is further extended to two more advanced cases. In Section 17.14, it is extended to systems of PDEs, using extra information from the original PDE about the different unknown functions in it. In Section 17.15, on the other hand, it is extended to high-order finite elements.

The original multigrid algorithm in Section 17.10 is so elementary and pure that it is independent not only of the original PDE but also of the discrete mesh on which it is discretized. In particular, it never uses the history of the mesh or the algorithm by which it has been formed in the first place. Using this information, however, is not necessarily a bad idea—on the contrary, it might be worthwhile in many cases. In fact, it may well enhance the convergence rate, at the cost of some extra programming to read, store, and use the extra information available.

For example, if the mesh has been produced from an adaptive-refinement process, then the improved multigrid version must store all the coarse grids that have been used to form the final fine mesh, and use them as coarse grids in the multigrid linear-system solver as well.

Thus, the additional code required to modify the original multigrid linear-system solver into a more specific version suitable for meshes produced from adaptive refinement is fairly short: it only needs to store the coarse grids used in the adaptive refinement and pass them to the multigrid code to be used there as well. The coarse grids used in the multigrid version are then no longer formed algebraically from the information in the coefficient matrix as in Section 17.8, but are rather the same coarse grids as the ones used in the adaptive-refinement process to form the finest mesh used to assemble the final coefficient matrix.

In Chapters 12 and 13 in [68], the advantage of this version is clearly illustrated. In the applications in this book, however, we prefer to stick to the original multigrid algorithm in Sections 17.8 and 17.9, in which the coarse grids (or levels) are defined purely algebraically in terms of the coefficient matrix only, so no application-dependent data is used.
