# Figure 5.1. Schematic representation of inheritance from the base class "list" to the derived class "polynomial".

```
template<class T> class polynomial:public list<T>{
    public:
        polynomial(int n=0){
            number = n;
            item = n ? new T*[n] : 0;
            for(int i=0; i<n; i++)
                item[i] = new T(0);
        } // constructor

        polynomial(int n, const T&a){
            number = n;
            item = n ? new T*[n] : 0;
            for(int i=0; i<n; i++)
                item[i] = new T(a);
        } // constructor with 'T' argument
```

These constructors first implicitly invoke the default constructor of the base "list" class, which constructs a trivial list with no items in it. Thanks to the fact that the "number" and "item" fields in the base "list" class are declared "protected" rather than private, the above constructors can access them and assign meaningful values into them.

Note that some compilers (including GNU versions newer than Version 3.2) may require the prefix "this->" to access the fields "number" and "item" inherited from the base "list" class:

```
this->number = n;
```

(See also the code in Section A.34 in the Appendix and the code on the Web page of the book at http://www.siam.org/books/cs09, which compile with new GNU versions as well.) In the sequel, however, we don’t bother to add this prefix.

The copy constructor and assignment operator don’t have to be defined, because the corresponding operators in the base "list" class do the right thing, that is, copy or assign the items in the argument one by one to the current object.

The following destructor also needs to do nothing, because the destructor of the base "list" class (invoked implicitly at the end of it) destroys first the individual items in the underlying list and then the list itself, as required:

```
~polynomial(){
} // destructor
```
