(Here the logarithm function is interpreted in, say, base 2: log x ≡ log₂ x.) Furthermore, as we’ll see in Section 5.24 below, the complexity of calculating the modulus operator n%m for two large natural numbers n > m is of order (log n)(log m) bit operations. (The same is true for the division or the multiplication of n by m.) Therefore, each prime number x encountered in the above loop must undergo (in the call to the "isPrime" function) the modulus operator against each of the O(√x / log x) prime numbers that are smaller than √x. Now, at least half of these prime numbers are large enough to have roughly the same logarithm as √x. Therefore, taking the modulus of x against each of them may cost as many as log² √x = (log² x)/4 bit operations.

To estimate (from below) the complexity of the entire algorithm, we must therefore integrate the above costs over all of the x’s between 2 and N, and, in particular, over all the O(N / log N) prime x’s:

∫₂ᴺ 1/log N ∫₂ᴺ √x/(2 log √x) (log √x − 1)(log x) dx ∼ 1/(2 log N) ∫₂ᴺ √x log x dx = 1/(2 log N) · 2/3 x³ᐟ² (log x − 2/3) |₂ᴺ ∼ 1/3 N³ᐟ².

Thus, the above algorithm costs as many as O(N³ᐟ²) bit operations and also sufficient memory to store the O(N / log N) prime numbers. Unfortunately, these requirements are too expensive to afford.
