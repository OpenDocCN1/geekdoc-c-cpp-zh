
fails to account for the coarse-scale (global) nature of the solution. A very large number of iterations may therefore be required to resolve this global part as well.

The multigrid iterative method, on the other hand, separates the local features from the global ones. In fact, each level takes care of the features of a particular scale or resolution, which are visible on a particular coarse grid.

The local part of the solution is often relatively easy to solve for in parallel. For example, in the domain-decomposition algorithm in Section 17.13, a well-parallelizable block Jacobi method can be used to relax the individual subdomains concurrently in parallel.

The global part, on the other hand, is much trickier to resolve, particularly in parallel. Indeed, solving the coarse-grid problem in the multigrid algorithm in Section 17.13 requires global communication between the processors available in the parallel computer. As a matter of fact, this communication may be so expensive that it may be worth it to transfer the entire coarse-grid problem to one powerful processor to be solved there sequentially. This way, only two communication steps are required to solve the coarse-grid problem and broadcast the result back to all the processors.

In summary, there is always a trade-off between communication and computation. The local part of the solution process is usually heavy in terms of computation, so it is worth the effort to parallelize. However, there is still a need to solve for the global part. This task is essentially nonparallelizable and may form a bottleneck in the parallel implementation.

## 18.21 Assembling the Stiffness Matrix

In high-order finite-element discretization of three-dimensional (nonlinear) problems, the discretization task that requires integration over the individual finite elements may often be far more time consuming than the numerical solution of the discrete linear system resulting from it. Fortunately, this integration is a completely local process: integrating over a particular finite element requires no data from any other finite element. This is why assembling the stiffness matrix can benefit greatly from a parallel implementation, requiring a very small amount of expensive communication.

There are many more problems that contain completely independent tasks that can be carried out simultaneously in parallel. The independent linear systems in Sections 30.12 and 30.13, for example, can be solved concurrently in parallel. Furthermore, a few large natural numbers can be checked concurrently in parallel to determine whether they are probably prime or not (Chapter 5).
