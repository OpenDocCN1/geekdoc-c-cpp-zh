
Furthermore, the "- =" operator is also used in the following "--" operator, which decrements its argument by 1:

```
const number& operator--(number&n) {
    return n -= number(1);
}  // subtract 1
```

This completes the implementation of the arithmetic operators with "number" objects.

Finally, here is a function that takes a moderate "number" object (of order 10^5) and converts it into a standard integer:

```
const int in(const number&n){
    int result = n[n.length()-1];
    for(int i=n.length()-2; i>=0; i--){
        result *= 2;
        result += n[i];
    }
    return result;
}  // conversion to int
```

It is not recommended to implement this function as an "operator int" member function within the block of the "number" class, because then it would be used by the compiler to convert "number" objects to standard integers not only explicitly but also implicitly (with no notice whatsoever), which might not be what the programmer intended.

## 5.25 The RSA Algorithm with Long Numbers

Here is how the above "number" class can be used to implement the RSA algorithm in Section 5.23 with arbitrarily long numbers. It is assumed here that 'N' is a large external "number" object.

```
int main(){
    number q = findPrime(N-1);
    number p = findPrime(q-1);
    number n = p * q;
    number phi = (p-1) * (q-1);
    number e = coprime(phi);
    number d = invertMod(e,phi);
    number m = 999999;
    printf("m=%d\n",in(m));
    number c = powerMod(m,e,n);
    printf("recovered message=%d\n",in(powerMod(c,d,n)));
    return 0;
}
```

## 5.26 Breaking the Code

As we’ve seen in Section 5.20 above, the time required to find a large prime number p is of order

√p log³ p

bit operations. Similarly, the time required to find a yet larger prime number q is of order

√q log³ q.

Once the required prime numbers p and q have been found, the numbers

n = p q
φ = (p − 1)(q − 1)
e = min { j ≥ 5 | GCD(φ, j) = 1 }
d = e⁻¹ mod φ

can be calculated as in Section 5.25 above. The numbers n and e are placed in the public domain for users to code their messages. The number d, on the other hand, is kept secret at the hands of the legitimate decoder only.

Clearly, the quality of the code is measured in terms of the time required to break it. As the time required to break it gets longer, the code is considered to be better. Fortunately, the time required to break the RSA code is rather long. Indeed, to discover d, the breaker must know φ. Fortunately, φ is kept secret as well. To discover it, the breaker must first decompose n in terms of its prime factors:

n = p q.

Since only n is available, the breaker must scan the numbers from 2 up to ⌊√n⌋ and check which of them divides n evenly. As in Section 5.20 above, this requires as many as

∫₂ᵖ (log x)(log n) dx = log(pq) x (log x − 1) |₂ᵖ
∼ p (log p)(log p + log q) / 2

bit operations. This time requirement is much larger than that required to form the code in the first place (particularly with the probably prime numbers introduced below), which indicates that the code is indeed of high quality. Indeed, for sufficiently large p, the time required to break the code is so large that potential breakers would probably give up in advance and never attempt to break it.

## 5.27 Fermat’s Little Theorem

Fermat’s little theorem is particularly useful in cryptography. This theorem reads as follows. Let p be a prime number. Then, for any natural number a,

aᵖ ≡ a mod p.

Furthermore, assume also that a and p are coprime, or that a is not a multiple of p. Then

a^{p-1} ≡ 1 mod p.

Moreover, let q be the minimal natural number for which

a^{q} ≡ 1 mod p.

[q is called the order of a and is denoted by q = o_p(a).] Then q divides p − 1 with no remainder.

The first part of the theorem is proved by induction on a (Euler’s proof). Indeed, for a = 1, we trivially have

a^{p} = 1^{p} = 1.

For the induction step, we first need to make the following observation. For any integer 0 < i < p, consider the binomial coefficient

binom{p}{i} = p! / (i! (p−i)!).

Because the prime number p appears only in the numerator rather than in the denominator, it must divide the binomial coefficient with no remainder:

p | binom{p}{i}.

We are now ready for the induction step. Assume that a^{p} ≡ a mod p for some a ≥ 1. From Newton’s binomial formula, we then have

(a + 1)^{p} = sum_{i=0}^{p} binom{p}{i} a^{i} ≡ a^{p} + 1 ≡ a + 1 mod p,

as required. This completes the induction step. This proves the first part of the theorem.

So far, we proved that

p | a^{p} − a = (a^{p−1} − 1)a.

Furthermore, because p is prime, it must divide either the first factor, a^{p−1} − 1, or the second factor, a. For this reason, if a and p are coprime, then p cannot divide a, and must divide the first factor in the above product:

p | a^{p−1} − 1.

In other words,

a^{p-1} ≡ 1 mod p.

This proves the second part of the theorem.

To prove the final part, note that the definition of q as the minimal natural number for which a^{q} ≡ 1 mod p implies that

q ≤ p − 1.

Let us show that q indeed divides p − 1. This is proved by contradiction. Indeed, assume that q doesn’t divide p − 1, or that

p − 1 = l q + r,

where l is some natural number and the remainder r satisfies 1 ≤ r < q. Then we’d have

a^r = a^r 1^l ≡ a^r a^{q l} = a^{l q + r} = a^{p − 1} ≡ 1 mod p,

in violation of the original definition of q as minimal. Therefore, our original assumption that q doesn’t divide p − 1 must be wrong. This indeed proves that

q | p − 1,

as required. This concludes the proof of Fermat’s little theorem. This theorem is used below to find a large number n that is almost certainly prime.

## 5.28 Probably Prime Numbers

Unfortunately, the algorithm to find a large prime number n in Section 5.20 is prohibitively expensive due to the large factor √n in the complexity of the "isPrime" function used in it. To avoid this factor, we need to rewrite the "isPrime" function to test whether a given number n is probably prime rather than definitely prime. This would produce an algorithm to find a large probably prime number n, which is good enough for most applications.

In particular, we could safely use probably prime numbers instead of definitely prime numbers in the present RSA coding-decoding algorithm. After all, no hacker would waste time attempting to break a code that probably uses prime numbers and is therefore probably practically unbreakable.

For this purpose, however, the probability that n is prime must be really high. To show how important this is, we first introduce a naive test that is not good enough. Then, we introduce and implement a more reliable test that is indeed used in practical applications.

## 5.29 The Naive Test

Consider the following test to check whether a given number n is likely to be prime or not. Pick some integer number a that satisfies 1 ≤ a < n. If

a^{n − 1} ≡ 1 mod n,

then the test is passed. Otherwise, the test fails.

From Fermat’s little theorem, it follows that if n happens to be prime, then the test is passed for every a. This means that passing the test is indeed a necessary condition for n being prime. Unfortunately, this is not a sufficient condition: there are numbers n that are not prime, yet do pass the test for too many a’s between 1 and n − 1.

The above naive test is too likely to indicate that these n’s are prime, even though they are not. We thus need a stricter test that would be less likely to pass such n’s.

## 5.30 The Rabin–Miller Test

A much more reliable test is indeed the Rabin–Miller test [51], [58]. This test checks whether a given odd number n > 3 is probably prime or not.

The test is defined as follows. First, factorize n − 1 in the form

n − 1 = 2^r s

where s is odd. (Because n is odd, n − 1 is even, so r > 0.) Then, pick some integer number a that satisfies 1 < a < n − 1. We say that the test is passed if either

a^s ≡ 1 mod n

or

a^{2^j s} ≡ −1 mod n

for some 0 ≤ j < r. Otherwise, the test is not passed.

The above test is based on the formula

a^{2^r s} − 1 = (a^{2^{r−1} s} − 1)(a^{2^{r−1} s} + 1) = (a^{2^{r−2} s} − 1)(a^{2^{r−2} s} + 1)(a^{2^{r−1} s} + 1) = (a^{2^{r−3} s} − 1)(a^{2^{r−3} s} + 1)(a^{2^{r−2} s} + 1)(a^{2^{r−1} s} + 1) = ⋯ = (a^s − 1)(a^s + 1)(a^{2 s} + 1)(a^{2^2 s} + 1)⋯(a^{2^{r−1} s} + 1).

The present test is indeed stricter than the original naive test: it requires that n divides not only a^{2^r s} − 1 but also one particular factor of it in the above factorization.

If n is prime, then this is indeed the case. After all, Fermat’s little theorem guarantees that n divides a^{2^r s} − 1. Furthermore, since n is prime, it must also divide one of the factors in the above factorization.

If, on the other hand, n is not prime, then it may still divide a^{2^r s} − 1, so the original naive test may mislead us to think that n is prime. Still, n may fail to pass the present stricter test. For example, n may be written as the product of two factors, each of which divides a different factor in the above factorization of a^{2^r s} − 1. In this case, the Rabin–Miller test is not passed, which indicates that n is not prime, as required.

In summary, passing the test is a necessary condition for n being prime. However, it is not a sufficient condition. In fact, there exists an n that is not prime, yet does pass the test for several a’s between 2 and n − 2. Such an a is called a liar, because it misleads us into thinking that n is prime. Fortunately, at most 25% of the a’s between 2 and n − 2 are liars [58]. Therefore, if a is picked randomly between 2 and n − 2, then the probability that the test would be passed is at most 1/4.

Thus, the probability that k independent tests would all mislead us to think that n is prime is as small as

4^{−k}.

For k = 10, for example, this probability is as small as

4^{−10} = 2^{−20} = 1024^{−2} ≤ 10^{−6}.
