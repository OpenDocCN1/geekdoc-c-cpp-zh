
In order to make sure that the compiler indeed destroys the entire object before going ahead to destroy the next object, one should better invoke the destructor explicitly at the end of the block in which the object is defined. This way, the compiler is forced to complete the destruction of the entire object in one go, including the entire memory it occupies, avoiding the need to locate this memory again and again.

In the present applications in this book, however, we don’t bother to write these extra code lines. They are left as an exercise to the careful reader.

# Part II

# Object-Oriented Programming

The computer program is indeed a good example of a mathematical object that takes no algebraic (arithmetic) operation, yet has a well-defined hierarchical multilevel structure: it may contain subprograms (or functions) that are by themselves programs that do specific tasks. The program can thus be compared to a sentence in any natural human language, which may also contain subsentences, each of which is a sentence in its own right. The only difference is that the basic atoms (or variables) in a computer program are strictly defined (they take the only value 0 or 1), whereas the basic words used in a human language are vague and context dependent and only indicate a subjective meaning by invoking subjective memories in the mind of each individual. Indeed, a particular word can be interpreted only in terms of synonyms that are never exactly the same as the original word. This is why we often interpret a word only implicitly by giving an example of how it can be used in a sentence.

This is also why an object-oriented implementation is so helpful. It may not only implement the original algorithm efficiently, but may also provide a proper interpretation for the original mathematical concepts used in it. This way, the original algorithm becomes much clearer and easier to modify, and the original mathematical theory takes a much more concrete form to help develop yet more advanced algorithms.

Objects are abstract concepts that one can operate on. In C, only numerical objects such as integer or real numbers and characters are available. These objects merely serve as arguments passed to functions. In C++, on the other hand, programmers may construct their own objects, which can be much more complex and have many useful functions. Thus, in C++, objects play a much more active role. They are the center of the implementation, which focuses on them and their properties. They not only wait until some function uses them as arguments, but actively call functions that reflect their potential.

In C++, the programmer implements not only isolated algorithms but also complete mathematical objects (such as vectors and matrices) that can be used in many algorithms and applications. This makes the programming language much more dynamic: the new objects may serve as new types to make the original language richer and more suitable for new applications.

This part introduces the object-oriented approach that is at the very heart of C++. In the first chapter in this part (Chapter 4), a unified approach from graph theory is used to introduce the present object-oriented framework, with potential applications in unstructured meshes and sparse matrices. The second chapter in this part (Chapter 5) introduces algorithms in cryptography and numerical analysis that use mathematical objects in their implementation. Finally, the third chapter in this part (Chapter 6) shows how the object-oriented approach can be used in the mathematical analysis of nonlinear ordinary differential equations (ODEs).

# From Wittgenstein–Lacan’s Theory to the Object-Oriented Implementation of Graphs and Matrices

The human memory can be compared to the memory of the digital computer. In the computer, most of the memory is stored in the secondary memory, which is big enough to contain a lot of data, yet the data in it are not easy to access. When the computer needs some data to compute and solve a particular problem that is given to it by the user, it accesses the required data and transfers them from the secondary memory to the primary memory.

Although the primary memory is much smaller than the secondary memory, the data in it are much easier to access. The processor can therefore use these data to make the required calculations and solve the original problem, using the instructions in the program fed to it by the user.

In the human brain, the subconsciousness plays the role of the secondary memory, whereas the consciousness plays the role of the primary memory. Here, however, data need not be transferred physically to the primary memory to think about or to process. Instead, blood flows to those cells where the data are. The Oxygen fed to these cells gives the required energy to raise the data stored in them to the consciousness to think about, process, and draw the required conclusion, which is then placed in a new cell.

What is then the relationship between my memory and myself? My memory, or to be precise, my secondary memory, contains all my background that I do not always wish to remember. From it, I use or remember only the information required at a certain moment. I then bring this information into my consciousness, use it to draw the required conclusion, and forget it soon after.

The poet Vislava Shimborska wrote about her complex relationship with her own memory in her own brain. It is always after her, seeking her full attention. At sleep, it indeed succeeds. At daytime, on the other hand, she manages to escape and avoid the scenes and images it puts before her eyes. She wants to put an end to this and separate from her memory for good. But then again, this would mean her end as well.

The art of implementing a formal object in a programming language can thus be compared to talking about an abstract concept in a natural human language. While talking, however, sometimes even the best word is not accurate enough to describe the concept fully. In fact, the word can at most realize the concept in part, and inspire or invite more precise words to describe the real nature of the concept.
