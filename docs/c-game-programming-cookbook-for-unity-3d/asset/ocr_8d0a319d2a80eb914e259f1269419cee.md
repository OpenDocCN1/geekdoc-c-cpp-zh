This alternative version of the LoadLevel function shown below uses an index to get a level name earlier to load handling. It uses the original LoadLevel function declared again. Keeping the focus on using a single function for all load-ings rather than duplicating the code or having happen in more than one place:

```
private void LoadLevel( int indexPath )
{
    // load the game level
    LoadLevel(levelNames[indexNum]);
}
```

The final function in the scene manager class is used to reset gameLevelNum-ever we start a new game. It is assumed that the script restarting the game will call this function before calling GoNext() again.

```
public void ResetGame()
{
    // reset the level index counter
    gameLevelNum = 0;
}
```

# 2.2.3 ExtendedCustomMonoBehavior.cs

Extending MonoBehavior is a useful way to avoid repeating common functions or variable declarations. Many classes share functions and/or variables. For example, most of the scripts in this book use a variable myTransform to refer to a cached version of their transforms to save having to look up the transform every time we need to access it. As MonoBehavior provides a host of system functions and calls, making a new class that extends, it can be useful tool to have in the kit. Whereas a new class would use MonoBehavior, we just derive from the new ExtendedCustomMonoBehavior script instead.

For the scripts in this book, the ExtendedCustomMonoBehavior.cs script extends MonoBehavior to include

+   1. myTransform variable to hold a cached reference to a transform
2. myGO variable to hold a cached reference to a gameObject
3. myBody variable for a cached reference to a rigidBody
4. aDidInit Boolean variable to determine whether or not the script has been initialized
5. an integer variable called id to hold an id number
6. a Vector3 type variable called tempV used for temporary vector actions
7. a Transform variable called tempTR used for any temporary references to transforms
8. a function called SetID(integer) so that other classes can set the variable
