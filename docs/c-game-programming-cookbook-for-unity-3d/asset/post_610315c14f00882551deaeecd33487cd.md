With this approach, Apple stores attempted to convey the lifestyle just much as the product, using clear layout and styling to reinforce the key themes of the experience, such as using natural materials to bring a more earthy, organic feel to their casual and clutter-free open plans.

Just like the exterior and layout of a high-end store, your menus and interface can affect how people feel about the game "inside." The unthinkable graphics, or a difficult menu flow can frustrate players before the game starts, leading to a heightened sense of frustration during initial gameplay. An unpolished interface may lower expectations or change the perception of quality of work that has gone into the game. We want to avoid these situations and set the user to feel as good as possible. To encourage a positive start, we should try to make sure that menu systems are tidy and functional, and they attempt to reinforce the main themes of the game world in every aspect.

If you look at most modern videogames, the menus and screens are filled with little touches that developers would notice, like particle effects, transitions, and animations. Most games have dedicated teams for building the menus and interface systems. Artists work hand in hand with developers to build new experiences. All this (sometimes 2D and 3D) comes at a cost, and it may take months of work for just the main menu screen of a commercial title.

Some studios reuse their menu and interface code from game to game, changing the layout and graphics but keeping the underlying code and/or structure. Reuse of menu code makes a lot of sense in an industry where we need to pack in as much gameplay possible and where customers demand a lot more bang for their buck.

The menu system we will be building in this chapter will not be winning awards or enticing players to play. But it will serve as a structural beginning and a functional method for configuring the example games and getting them started. The great thing about this menu is that it's completely open to interpretation. It could be built out for just about any kind of game with the addition of some graphics and sounds. As you develop your games and your style, having an operational menu will help during testing.

The main menu system is used by all of the example games in this book. It is easy to port between games and have submenus for audio and graphics options. The full screen flow for the entire main menu and its submenus is shown in Figure 10.1.

The flow requirements are almost identical for each game, although there are a few that need to be variable. These are:

- 1. Game name.
- 2. Which scene to load when we start the game button.
- 3. The filename of the prefs we save to store options (volume and graphics levels).
- 4. In the case of Interstellar Paranoia, the menu needs to have a Start Co-Op Game button, too.

The menus will be built with Unity GUI, for simplicity, although the basic reusable menu principles could easily be applied to a GUI using custom or third-party solution such as NGUI. Menus should also have the option to play some music in the background as well as a sound effect whenever buttons are clicked, and the background music should continue between menus without restarting or resetting.

The menu is a single class to keep it simple and for easy expansion or porting between projects. It is capable of displaying all different screens that make up the main menu by using a variable to state which menu should be displayed, which is checked by a case statement, and the correct screen composed with the OnGUI function.

To help make customization and stylization easy, the menu system uses a Unity skin named MenuGUIskin, which defines the front to use and any custom layout requirements.

The options uses QualitySettings.names to find how many graphics preferences are available and present them as a slider bar for easy modification by players. Getting all of the QualitySettings.names (rather than hard coding them) allows for greater flexibility when porting between games, as there may not always be the same number of graphics detail. The main menu class is in a script called MenuController.cs. It is derived from MonoBehaviour and looks like this:

```csharp
using UnityEngine;
using System.Collections;

public class MenuController : MonoBehaviour
{
    public int whichMenu = 0;
    public string displayName = "- DEFAULT GAME -";
    public string singleGameStartScene = "DefaultGame";
    public string coopGameStartScene = "";
    public float default_width = 720;
    public float default_height = 480;
    public float audioSFXSlider;
    public float audioMusicSlider;
    public int detailLevels;

    void Start()
    {
        // set up options, if they have already saved to prefs
        if (PlayerPrefs.HasKey("SFXVol"))
        {
            audioSFXSlider = PlayerPrefs.GetFloat("SFXVol");
        }
        else
        {
            audioSFXSlider = 1;
        }

        if (PlayerPrefs.HasKey("MusicVol"))
        {
            audioMusicSlider = PlayerPrefs.GetFloat("MusicVol");
        }
        else
        {
            audioMusicSlider = 1;
        }

        if (PlayerPrefs.HasKey("GraphicsDetail"))
        {
            detailLevels = PlayerPrefs.GetInt("GraphicsDetail");
        }
        else
        {
            string[] names = QualitySettings.names;
            detailLevels = names.Length;
        }
    }

    void OnGUI()
    {
        float resX = Screen.width;
        float resY = Screen.height;
        GUI.matrix = Matrix4x4.TRS(new Vector3(0, 0, 0), Quaternion.identity, new Vector3(resX, resY, 1));

        // set the GUI skin to use our menu skin
        GUI.skin = menuSkin;

        switch (whichMenu)
        {
            case 0:
                GUI.BeginGroup(new Rect(default_width / 2 - 150, default_height / 2 - 250, 500, 500));
                // All rectangles are now adjusted to the group.
                // (0,0) is the top-left corner of the group.
                GUI.Label(new Rect(0, 50, 300, 30), displayName);

                if (GUI.Button(new Rect(0, 200, 300, 40), "START SINGLE"))
                {
                    PlayerPrefs.SetInt("totalPlayers", 1);
                    LoadLevel(singleGameStartScene);
                }
                if (coopGameStartScene != "")
                {
                    if (GUI.Button(new Rect(0, 250, 300, 40), "START CO-OP"))
                    {
                        PlayerPrefs.SetInt("totalPlayers", 2);
                        LoadLevel(coopGameStartScene);
                    }
                    if (GUI.Button(new Rect(0, 300, 300, 40), "OPTIONS"))
                    {
                        ShowOptionsMenu();
                    }
                }
                else
                {
                    if (GUI.Button(new Rect(0, 250, 300, 40), "OPTIONS"))
                    {
                        ShowOptionsMenu();
                    }
                }

                if (GUI.Button(new Rect(0, 400, 300, 40), "EXIT"))
                {
                }
                GUI.EndGroup();
                break;
        }
    }
}
```
