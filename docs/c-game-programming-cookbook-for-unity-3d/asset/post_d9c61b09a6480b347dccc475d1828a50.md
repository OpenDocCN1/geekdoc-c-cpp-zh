## 4.6.1.1 Script Breakdown

All camera scripts used with the framework should implement a SetTarget function. SetTarget takes a single parameter of type Transform to put into the variable named target:

```csharp
public override void SetTarget( Transform aTarget )
  {
    target= aTarget;
  }
```

It may come as a surprise that the main update to the camera happens within LateUpdate() and not within the Update or FixedUpdate function. The reason for this is we prefer physics-wise to have been updated before moving the camera—which should have happened by LateUpdate()—and in doing so, there should be no discrepancies between the positions of our target objects between the end of the camera update and the drawing of the next frame. Drawing at the wrong time could cause a jitter effect as the objects that we are following after the camera positioning.

At the start of LateUpdate(), there are the usual null checks to make sure that we have both a target and a cached version of the camera’s transform:

```csharp
void LateUpdate ()
  {
    if ( target == null )
      return;

    if ( myTransform==null )
      {
        myTransform=transform;
      }
}
```

The script interpolates height and rotation values. Before the interpolation can happen, we need to find out what the target height and rotations are as well as what the current height and rotations are. The wantedHeight variable is a float. We add the value of the public variable height to it, allowing target height adjustment to happen by setting it in the editor:

```csharp
wantedHeight = target.position.y + height;
currentHeight = myTransform.position.y;

wantedRotationAngle = target.eulerAngles.y;
currentRotationAngle = myTransform.eulerAngles.y;
```

currentRotation is a float representing the angle, in degrees, that we need to turn the camera to try and reach the target rotation wantedRotation. It's an interpolation carried out by Math.SmoothDampAngle.

Math.SmoothDampAngle is an interpolation function designed specifically for between two angles. It will automatically catch the return value between 0 and 360 as well as choose the correct way around (if your value is 181°, it interpolate rather than down so that the rotation has a natural flow and doesn't go back on itself).

The Unity documentation tells us that SmoothDampAngle takes the following parameters (in order of how they should be passed in):

| current | The current position. |
| :--- | :--- |
| target | The position we are trying to reach. |
| currentVelocity | The current velocity; this is modified by the function every time you call it. |
| smoothTime | Approximately the time it will take to reach the target. a smaller value will reach the target faster. |
| maxSpeed | Optionally allows you to clamp the maximum speed. |

In this part of the code, currentVelocity variable holds the current velocity of the interpolated move, but it is not actually used anywhere else in the script. It's a required field for SmoothDampAngle, so we provide it for the function to work right and forget about it. Note that one possible could use the velocity may speed limiting the move, with SmoothDampAngle actually take care of this with no extra code by providing a maxSpeed parameter. This is useful for...

The currentRotationAngle is, in fact, the rotation around the y-axis (hence using the name ylabel to describe its speed). The variable rotationSnapTime decides how time it should take for the rotation to happen, which is public and designed to be set in the Unity Editor Inspector on whichever gameObject the script is attached:

```csharp
currentRotationAngle = Math.SmoothDampAngle(currentRotationAngle, wantedRotation, yVelocity, rotationTime);
```

The height movement is interpolated using Math.Lerp, which takes three parameters: the start amount, the target amount, and a time value clamped between 0 and 1. We use the float heightDamping, by Time.deltaTime, to make the transition time based. Are you wondering why do we need to make the time parameter best? How the time parameter of Math.Lerp works has been very popular question on various forums and help pages. The time value represents how much of a portion, of the difference between two values, that should be applied each time line of code is executed. If the time value is 0, the return value will be the start amount. By time is 1, the return value will be the target amount.

By calculating position with Time.deltaTime, the transition from start value to target value is smoothed over a repeatable, fixed amount of time rather than being frame-rate dependent and based on how many times the Mathf.Lerp calculation line is called:

```csharp
currentHeight = Mathf.Lerp(currentHeight, wantedHeight,
damping *= Time.deltaTime);
```

Now that the script has calculated how much to rotate the camera and how high it should be on the y-axis, the script goes to calculate where the camera is going to go position-wise.

wantedPosition is a Vector3 variable that will hold the target position. The first target position is the transform's position and an adjustment for using the currentHeight variable calculated above:

```csharp
wantedPosition = target.position;
wantedPosition.y = currentHeight;
```

The next part of the code calculates how far behind the player need to move the camera. For this, the script uses Mathf.SmoothDampAngle. zVelocity represents speed of movement of the camera along its z-axis, but it is purely a formality to use with SmoothDampAngle and does not:

```csharp
usedDistance = Mathf.SmoothDampAngle(usedDistance, wantedRotation, ref zVelocity, distanceTime);
```

The next part of the code calculates how far behind the player need to move the camera. For this, the script uses Mathf.SmoothDampAngle. zVelocity represents speed of movement of the camera along its z-axis, but it is purely a formality to use with SmoothDampAngle and does not:

```csharp
wantedPosition += Quaternion.Euler(0, currentRotationAngle, 0) * new Vector3(0, 0, -usedDistance);
```

The final part of the function causes the camera to look at the target (player). It does this using Unity's built-in LookAt() function. We pass in the position of the target (as a Vector3) and add an offset where the camera is going to go, via the LookAtVector. You can also add an up vector to the LookAt() function, but in this case we don't need.

Aiming the camera directly at the player from behind the player may obscure the path ahead and make the game difficult to navigate. Instead, we add a small height adjustment to the target position, so that the camera aims above the player as if it were looking, rather than right at it. With a simple target height adjustment, we can help the camera to stay parallel to the ground level and keep good visibility, making the game easier to play.

```cs
myTransform.position = wantedPosition;

myTransform.LookAt( target.position + lookAtAdjustVector );
```

## 4.6.2 Top-Down Camera

The TopDown_Camera.cs script is a basic target-following system for a top-down perspective:

```csharp
public class TopDown_Camera : MonoBehaviour
{
    public Transform followTarget;
    public Vector3 targetOffset;
    public float moveSpeed= 2f;

    private Transform myTransform;

    void Start ()
    {
        myTransform= transform;
    }

    public void SetTarget( Transform aTarget)
    {
        followTarget= aTarget;
    }

    void LateUpdate ()
    {
        if(followTarget!=null)
            myTransform.position= Vector3.Lerp( myTransform.position, followTarget.position + targetOffset, moveSpeed * Time.deltaTime);
    }
}
```
