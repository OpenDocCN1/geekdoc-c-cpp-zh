```

```

If canControl is false, no weapon control is allowed so this function drops out early:

```
// if we are not allowed to control the weapon, we drop out
// if(canControl)
    return;
```

It may seem redundant having a canControl variable that will drop out of this func-along with a variable to decide whether or not to actually execute the firing code, but the reason is consistency; all of the player scripts use canControl, and it is used here too. This script in its current form only deals with weapon control, there is nothing to stop it growing into something more complex later. To make sure that the script remains extensible for future use, the logic to fire is dependent on this-GameObjectShouldFire being set to true:

```
if(thisGameGameObjectShouldFire)
```

Depending on the AIAttackState this enemy is currently set to use, it may be required
to able to have a line of sight to a potential target before firing. doFire is a Boolean vari-able to tell whether or not the conditions to fire (such as line of sight) have been satis-ied and firing is allowed. Before fire condition checking starts, the assumption is made
at firing will not be allowed, and doFire is set to false:

```
// we use doFire to determine whether or not to fire
// right now
dofire=false;
```

There will always be a pause in-between firing. The Boolean variable canFire is used to determine whether or not the script should be allowed to fire at this time.

```
if( canFire )
{
```
