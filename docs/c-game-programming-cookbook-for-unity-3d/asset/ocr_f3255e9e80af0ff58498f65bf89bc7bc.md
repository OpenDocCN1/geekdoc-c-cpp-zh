Private static variable exists within the class it was declared and in any other instances of the same class. Other classes/types of script will not be able to access it.

As a working example, try to imagine a script named player.cs directly controls player objects in your game. They all need to tell a player script when something happens, so we declare the player manager as a static variable in this player.cs script like this:

```
private static Player playerManager;
```

The playerManager object only needs to be set up, by a single instance of the player class, to be ready to use for all the other instances of the same class. player.cs scripts will be able to access the same instance of the PlayerManager.

# 4. The singleton design pattern.

In the previous part of this section, we were looking at a static variable to share a manager across the entire game code. The biggest disadvantage with this method is that it is possible to create multiple instances of the same script. If this happens, you may find that your player code is talking to the wrong instance of the game controller.

A singleton is a commonly used design pattern that allows for only one instance of a particular class to be instantiated at a time. This is ideal for our game scripts that may need to communicate (or be communicated with) across the entire game code. Note that we will be providing a static reference to the script, exactly as we did in the "Static Variables" method earlier in this section, but by implementing a singleton class, we will be adding some extra code to make sure that only one instance of our script is ever created.
