
The next step is to find out the relative position of the waypoint from the (myTransform) transform. transform.InverseTransform converts a position from world space into local space. In this case, we take the position of the waypoint and convert it into the local space of myTransform.

The result of the transform.InverseTransformPoint space conversion is stored in a Vector3 type called RelativeWaypointPosition. This vector now represents the direction that the AI would need to reach the next waypoint.

By dividing the x value of RelativeWaypointPosition by its magnitude, we end up with a number that, in layman's terms, says how much we need to turn left or right to be facing the waypoint, a number that is perfect for use as horizontal input to a steering system. The code below places the calculated steer value into the variable (variable name used for horizontal input throughout this book):

```
RelativeWaypointPosition = myTransform;
myTransform.InverseTransformPoint(currentWaypointPosition);
// by dividing the horz position by the magnitude,
// we get a decimal percentage of the turn angle
// that we can use to drive the wheels
horz = RelativeWaypointPosition.x / RelativeWaypointPosition.magnitude;
```

Now that contains the amount required to turn towards the next waypoint, this value may be used to slow down the bot if it is moving too fast.
The absolute (never negative) value of horz is checked against 0.5 to decide whether or not acceleration should be used. If the turn is more than 0.5, acceleration is set to 0. The acceleration into the vert is calculated by taking the RelativeWaypointPosition z divided by its magnitude, the horizontal turn subtracted from it. The idea is, even though the distance to the waypoint along the AI bot's z-axis is taken into account, the more the turn is, the less the acceleration value will be. In many cases, this should help the AI to get around corners without crashing:

```
// now we do the same for torque, but make sure that
// it doesn't apply any engine torque when going
// around a sharp turn...
if (Math.Abs(horz) < 0.5f) {
  vert = RelativeWaypointPosition.z /
  RelativeWaypointPosition.magnitude -
  Math.Abs(horz);
} else {
  NoMove();
}
```

AIState.steer_to_target works in the same way as the waypoint-steering code above, except that uses FollowTarget to aim instead of the waypoint in the current-WaypointTransform variable:

```
case AIState.steer_to_target:
  // make sure we have been initialized before trying
  // to access waypoints
  if (didInit) {
    return;
  }
  if (followTarget == null) {
    // it may be possible that this function gets
    // called before a target has been set up,
    // we catch any nulls here
    return;
  }

  // now we just find the relative position of the
  // waypoint from the car transform,
  // that way we can determine how far to the left and
  // right the waypoint is.
  transform.InverseTransformPoint(followTarget.position);

  // by dividing the hors position by the magnitude,
  // we get a decimal percentage of the turn angle
  // that we can use to drive the wheels
  horz = (RelativeWaypointPosition.x / RelativeWaypointPosition.magnitude);

  // if we're outside of the minimum chase distance,
  // drive!
  if (Vector3.Distance(followTarget.position, myTransform.position) > minChaseDistance) {
    MoveForward();
  } else {
    NoMove();
  }
```

As this state is following a target around not traveling along a fixed waypoint path, it includes some logic to react to obstacles (in the case the target decides to hide behind a wall or something like that):

```c
if (followTarget == null) {
  LookAroundFor(followTarget);
}
```

It uses the same code as the obstacle detection in AIState.moving_looking_for_target, explained earlier in this section:

```c
// the AvoidWalls function looks to see if there's
// anything in front. If there is, it will
// automatically change the value of moveDirection
// before we do the actual move
if (obstacleFinderResult == 1) { // GO LEFT
  TurnLeft();
}

if (obstacleFinderResult == 2) { // GO RIGHT
  TurnRight();
}
```

When both left and right sides are ahead blocked by an obstacle, the bot will simply back up. This behavior may not be ideal in all situations, but for the Tank Battle example in this book, I saw it as the equivalent of making the AI wait for its target to come out from behind the wall. This code tends to make the bot hang around until it eventually turns to face its target:

```c
if (obstacleFinderResult == 3) { // BACK UP
  MoveBack();
}

break;
```

That's the UpdateAI() function all wrapped up. Next, there is a collection of functions to set inputs for turning left and moving forward and backward. The reason they have their own functions rather than just setting them in the UpdateAI() code is to keep the code clean. The AIState.moving_looking_for_target state uses these functions to navigate the environment.

The AIState.steer_to_target state also uses these to follow the target. All of these states rely on the basic movement logic defined in the previous chapters.
