isFinished is used to tell the player whether or not to act like it is playing the game. When the game ends, isFinished is set to true and the user will no longer have control:

```
isFinished=false;
```

The last part of this function tells the game controller to update the lives display to the health set within the data manager. This needs to happen for the lives display to be populated with the right amount when the game first starts:

```
// tell game control to update the lives UI

The GetInput() function overrides the one from the base class (BaseTopDown) to provide support for respawning and firing. When the game has finished and isFinished is true, or when the player is respawning, all of the inputs are set to zero so that the user cannot move the player:

```
public override void GetInput()
{
    if(isFinished || isRespawning)
    {
        horz=0;
        vert=0;
        return;
    }
```

Before going through to check for input, the function will drop out if canControl is false. canControl means that the user is not supposed to control this player:

```
// drop out if we're not supposed to be controlling
if ((canControl))
return;
```

The actual input values come from the default input controller held in the default_input variable. The variable default_input is declared as type Keyboard_Input. The values returned from a call to default_input.GetHorizontal() and default_GetVertical() are clamped with Mathf.Clamp as a precaution, even though the keyboard controller this example game should never return anything other than a number between -1 and 1:

```
// grab inputs from the default input provider
horz= Mathf.Clamp(default_input.GetHorizontal() , -1, 1);
vert= Mathf.Clamp(default_input.GetVertical() , -1, 1);
```

default_input checks for the fire button, too. Next, the code to see whether the button is pressed and or not firing is actually possible. The Boolean variable canFire is standardized across the example games as a method to be set in the Unity-Inspector window to set whether or not the player should be allowed to fire or not. If the fire is pressed and canFire is set to true, the function Fire() is called on weaponControl object. This should tell the weapon system to fire the currently selected weapon:

```
// fire if we need to
if (default_input.GetFire() && canFire )
{
// tell weapon controller to deal with firing
weaponControl.Fire();
}
```

The game controller has an Invoke statement in its Start() function, which calls Start() and, in turn, calls this GameStart() function: canControl is set to true, meaning that the player now has control:

```
public void GameStart()
{

Respawning the player starts when LostLife() is called by this script's collision. We will look at OnCollisionEnter further in this function. When LostLife() is called, the first thing that happens is the Boolean variable isRespawning is set to true. You may recall this from the input function earlier when the player was respawning. Earlier in this chapter we looked at game controller, PlayerHit() was one of the functions used to display explosion effect. Here, we access the static game controller GameController_LBS.Instance and call PlayerHit(), passing in player's transform:

```
void LostLife() {
    isRespawning=true;

    // blow up!
    GameController_LBS.Instance.PlayerHit( transform );
}
```

The data manager gets a call next to reduce lives by 1:

if(myDataManager.GetHealth()<1) // game over

The weapon system is shut down so firing doesn't happen anymore, followed by a call to the PlayerFinished() function to take care of finalizing the game for this player:

```
// disable and hide weapon
weaponControl.DisableCurrentWeapon();

If the player's health amount is more than 0, the player's model is hidden, the weapon system is disabled and respawn is scheduled 2 seconds from here (via Invoke to call Respawn()):

    MeshGO.SetActive(false);

Respawn() will reposition the player at its starting position and reset all of the variables to put the player back to the state it was at the beginning of the level:

```
void Respawn()
{
    // reset the 'we are respawning' variable
    isRespawning=false;
}
```

When a player spawns, it may often be placed in a position where there is already an enemy or some laser fire. It could be unfair to spawn the player and have it destroyed immediately, so when respawning happens the opportunity for spawn by making the player invulnerable for a short period of time. A call to MakeInvulnerable() starts this, with an Invoke call to activate the Vulnerable function to counter its effect 3 seconds later:

```
// we need to be invulnerable for a little while
MakeInvulnerable();

Invoke("MakeVulnerable",3);
```

The player mesh hidden when the player was destroyed, so SetActive() function is used to show it again:

```
// show ship body again
MeshGO.SetActive(true);
```

As well as the player model being hidden on its destruction, the weapon controller is disabled. To re-enable it, the weapon slot is set to the first one (zero) to reset it, and all to weaponControl.EnableCurrentWeapon() is made to get it going again:

```
// revert to the first weapon
weaponControl.SetWeaponSlot(0);

// show the current weapon (since it was hidden when the ship explosion was shown)
weaponControl.EnableCurrentWeapon();
```

The CollisionEnter function will detect when an object first collides with the player. the layer of the object colliding with it is checked to see whether it is a projectile (on layer 11) and we make sure that the player is not respawning. The simple invulnerability system comes into play in this function; the state of isulnerable decides whether or not it should react to the collision. If all conditions are met, the LostLife() function is called:

```
void OnCollisionEnter (Collision collider)
{
    // MAKE SURE that weapons don't have colliders
    // if you are using primitives, only use a single collider
    // on the same gameObject which has this script on

    // when something collides with our ship, we check its layer
    // to see if it is on 11 which is our projectiles
    // (Note: remember when you add projectiles set the layer
    // correctly!)
    if(collider.gameObject.layer==11 && !isRespawning &&
!isInvulnerable)
{
    LastLife();
}
}
```

MakeInvulnerable() and MakeVulnerable() simply set the Boolean isInvulnerable variable to true or false, respectively:

```
void MakeInvulnerable()
{
    isInvulnerable=true;
}

void MakeVulnerable()
{
    isInvulnerable=false;
}
```
