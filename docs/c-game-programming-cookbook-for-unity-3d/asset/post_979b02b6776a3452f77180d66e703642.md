It is inevitable that a player will need to respawn at some point. This might be due to a player getting stuck, a player falling out of the game area, or perhaps a player choosing to respawn when the car is facing the wrong way along the track. Whatever the reason, there should be a little penalty involved in respawning players from using it as an escape button when trouble hits.

GetRespawnWaypointTransform() is used to return a transform that the respawning code uses for positioning and rotation data. It does not return the current waypoint but instead the last waypoint passed. When this happens, it is also important to change the value of currentWaypointNum too, so that the current waypoint is not too far away from the respawn point.

When the function is called, it first checks if currentWaypointNum is more than 0 so that it can be decremented without breaking the code:

```cs
public Transform GetRespawnWaypointTransform ()
{
    // if we are past the first waypoint, let's go back a
    // waypoint and return that rather than the
    // current one. That way, the car will appear roughly where
    // it despawned rather than ahead of it.
}
```

As long as it is above 0, currentWaypointNum gets decremented by 1 here:

```cs
if (currentWaypointNum>0)
    currentWaypointNum--;
```

The checkpoint checking works by looking at the distance between the player and the waypoint and moving on to the next waypoint when distance gets too low. For this type of waypoint following, steering is employed to turn left or right depending on the direction of the waypoint, the y-axis may be discounted. The first part of this code takes the positions of the player and waypoint and copies them into variables. The copies have the y positions set to 0:

```cs
// now we need to check if we are close enough to the
// waypoint to advance to the next one
myPosition = transform.position;
myPosition.y=0;
```

```cs
// get waypoint position and 'flatten' it
nodePosition = currentWaypointTransform.position;
nodePosition.y=0;
```

The Unity Vector3.Distance takes two Vector3 positions and returns the distance between:

```cs
// check distance from this car to the waypoint
currentWaypointDist = Vector3.Distance(nodePosition,
myPosition);
```

When the distance in currentWaypointDist drops below waypointDistance, increments currentWaypointNum, advancing to the next waypoint:

```cs
if (currentWaypointDist < waypointDistance) {
    // we are close to the current node, so let's move
    // to the next one!
    currentWaypointNum++;
}
```

When currentWaypointNum is greater than or equal to the number in totalWaypoints, we know that the player has been all the way around the track. This is not the place to increase the lap counter, however, as the player needs to cross the start/finish line before the lap may be increased. true when currentWaypointNum goes beyond the total number of waypoints, the variable isLapDone is set to true, and the value of currentWaypointNum is set back to 0 ready to aim for the next waypoint (which is now the first waypoint):

```cs
// now check to see if we have been all the way
// around the track and need to start again
if(currentWaypointNum==totalWaypoints) {
    // completed a lap set the lapDone flag to
    // true, which will be checked when we go over
    // the first waypoint (so that you can't)
    // almost complete a race then go around
    // the other way to confuse it)
    isLapDone=true;
    // reset our current waypoint to the first
    // one again
    currentWaypointNum=0;
}
```

The next part of the code will deal with the updating of currentWaypointTransform variable to reflect any changes to currentWaypointNum. Here the code calls upon waypointManager.GetWaypoint() and stores the return value in the currentWaypointTransform variable:
