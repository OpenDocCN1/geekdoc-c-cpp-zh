## 12.3.2.1 Script Breakdown

The RaceController script is going to be tracking everything we need for a race game
other than players). It derives from MonoBehaviour so that it can tap into the automated
system calls to Update(), Start(), etc.:

```cs
using UnityEngine;
using System.Collections;

public class RaceController : MonoBehaviour
{
    Every racer will be given a unique ID by the global race manager (covered later in this
    chapter). When the script is on its first run, the myID variable is set to -1 so that any other
    scripts trying to access it will instantly know it is not ready. Once the
    script's Init() function has called, ID should no longer be -1, and it should be set
    correctly:

    // default myID to -1 so that we will know if the script hasn't
    // initializing when another script tries to GetID
    private int myID = -1;

RaceController() is automatically called by the engine when the script is
instantiated. To get the player set with an ID as soon as possible before the
actually begins, myID is set up in the constructor (whereas it might be set a little
later on Init() function). To get a unique ID, the global race manager has a function GetUniqueID().
The logic behind this function ensures that each player will be awarded a unique ID
at the start of each game. Its ID may then be used elsewhere. Note that
GlobalRaceManager.Instance is a static variable. The race manager uses some nifty
code to ensure that there is only one instance of the script in action at any time, which will
be looked at later in this section, so don't worry about that just now.myID is an integer, set by call to GlobalRaceManager.Instance.GetUniqueID().
The parameter it takes is instance of the script, so that the race manager will be able to
link ID to the script from here:

```cs
public RaceController()
{
    myID = GlobalRaceManager.Instance.GetUniqueID(this);
    Debug.Log("ID assigned to "+myID);
}
```

Init() grabs a cached reference to myTransform and sets its doneInit to true:

```cs
public void Init()
{
    myTransform= transform;
    doneInit= true;
}
```

There may be occasions where other scripts need to get player's unique number which is why the GetID() function returns the value of myID:

```cs
public int GetID() {
    return myID;
}
```

When the player passes all of the waypoints around the track, the variable lapDone is set to true. This Boolean is used when the player hits the trigger on the start/finish line to see whether the lap should be increased. Increasing laps in this way (rather than just incrementing the current lap counter at the start/finish line) ensures that the player has driven all the way around the track and crosses the finish line:

```cs
public bool IsLapDone() {
    return lapDone;
}
```

RaceFinished() is the function responsible for finding out the player's final race position and telling the player when it is time to stop racing. First, our internal variables are set up for use in other scripts, which is isFinished, raceRunning, and finalPosition:

```cs
public void RaceFinished() {
    isFinished=true;
    raceRunning=true;
}
```

finalPosition gets its value by hitting the GlobalRaceManager for its race position via GetPosition(passing in this player's ID):

```cs
// find out which position we finished in
int finalPosition=GlobalRaceManager.Instance.GetPosition(myID);
```

To tell the player that the race has finished, this script uses Unity's function GameObject.SendMessageUpwards(). What this is a message from this script to the gameObject and every ancestor of it. If there is a component script attached to, containing a function naming the message being sent, in case LapFinished(), then it will be called.

This part of the code could have stored a reference to the player's control script directly, but that would mean hardwiring the player script, which reduces the overall flexibility of this script. For example, the player control script for this game is named PlayerController_MVD. The player control script for the example Tank Battle is named PlayerController_TB. If we wanted to make a reference to the player's script for this game, it would need to be in a variable of type PlayerController_MVD, and for the Tank Battle game, would be in a variable of a different type: PlayerController_TB. To make this work for both games would mean that we need to create either two separate scripts or two different versions of the script. Instead, SendMessageUpwards() will send out the message to everything without caring about what type of script it is talking to, just in case there is no script attached to the same GameObject with the function LapFinished(), the parameter SendMessageOptions.DontRequireReceiver is used, which means that no errors or warnings will occur if there is no script to receive the message:

```cs
gameObject.SendMessage("PlayerFinished", finalRacePosition, SendMessageOptions.DontRequireReceiver);
```

At RaceStart(), our internal state variables are Finished and raceRunning are set to false. Note that raceRunning starts out false because it will be set by another function, a little further on from the initialization of this script:

```cs
public void RaceStart()
{

    raceRunning=false;
}

Other scripts may need to know whether this player has finished racing. The IsFinished() function will return a Boolean to that effect:

```cs
public bool IsFinished()

}

When other scripts need to find out what the player's current lap is, the GetCurrentLap() function gets the latest information by the player's ID as a parameter (so that the global race manager knows who is asking for their lap count) and adds 1 to the return value from GlobalRaceManager.Instance.GetLapsDone() will be how many laps are completed, what the current lap is:

public int GetCurrentLap()

```
