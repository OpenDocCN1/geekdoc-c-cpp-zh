An AudioSource is required on the vehicle to make an engine noise. To set one up, add an AudioSource to the gameObject (Component -> Audio -> AudioSource) and reference an engine audio clip. On the AudioSource, check the boxes for Loop and Play Awake:

The Start() function is called by the engine automatically. It calls the Init() function, which begins by caching references to commonly used objects:

```cs
public virtual void Start() {
    Init();
}
public virtual void Init() {
    // cache the usual suspects
    myBody = rigidbody;
    myGO = gameObject;
    myTransform = transform;
```

GameObject.AddComponent adds the default input controller to the gameObject:

```cs
// add default keyboard
default_input = myGO.AddComponent<Keyboard_Input>();
```

A BasePlayerManager script should already be attached to the gameObject, as per the standard player setup for the framework, but just to be safe, a null check is made before calling the Init():

```cs
// cache a reference to the player controller
myPlayerController= myGO.GetComponent<BasePlayerManager>();
```

```cs
// call base class init
if (myPlayerController!=null)
    myPlayerController.Init();
```

The center of mass may be set on a rigidbody to change the way it behaves in the physics simulation. The farther the center of mass is from the center of the rigidbody, the more it will affect the physics behavior. Setting the center of mass down at -4, for example, help a lot to keep the car stable. This is a method often employed to keep vehicles toppling over in games, but it comes at cost. If the car were to roll and flip over, it will roll in an unrealistic way because of the center of mass will affect its movement. Look to the stabilizer bar simulation for a more realistic solution, but for now, this is as far as we go:

```cs
// with this simple vehicle code, we set the center of the mass
// low to try to keep the car from toppling over
myBody.centerOfMass= new Vector3(0,-4f,0);
```

If no engine sound has been set up in the Vehicle Inspector of the Unity editor, the script tries to find it a call with GameObject.GetComponent(). The sound source will be stored in engineSoundSource and used solely for engine sound effects:

// see if we can find an engine sound source, if we need to

As all of the movement controllers, UserInput sets a flag to decide whether or not inputs should be used to drive the vehicle:

```cs
public void SetUserInput(bool setInput)
{
    canControl= setInput;
}
```

Unlike movement controllers from this book so far, this introduces a lock state. The lock state is for holding the vehicle in place without affecting its y-axis. This differs from disabling user input as it adds physics constraints to the physics object to hold it still (purpose being to hold the vehicle during the counting in the start of a race or other similar scenario):

```cs
public void SetLock(bool lockState)
{
    isLocked = lockState;
}
```

LateUpdate() starts by checking for input via the GetInput() function, when canControl is set to true. Next, UpdateEngineAudio() is called to update the pitch of the engine sound based on the engine speed:

```cs
public virtual void LateUpdate()
{
    // check for input in LateUpdate because Unity recommends
    // this
    if (canControl)
        GetInput();

    // update the audio
        UpdateEngineAudio();
}
```

To keep everything tidy, all of the physics functionality is called from FixedUpdate(), but it actually resides in the Update() function:

```cs
public void FixedUpdate()
{
    UpdatePhysics();
}
```

Changing the pitch of the engine AudioSource object makes a convincing motor sound. As it may be possible for mySpeed to be negative, Mathf.Abs is used, as well as an arbitrary multiplier to bring the number down to something that changes the pitch in a satisfactory manner. There's no science here! The number was decided by trial and error, just adjusting its value until the motor sounded right:

```cs
public virtual void UpdateEngineAudio()
{
    // this is just a 'made up' multiplier value applied to
    // mySpeed.
    engineAudioSource.pitch=0.5f + (Mathf.Abs(mySpeed)*0.005f);
}
```

The real guts of the script may be found in the UpdatePhysics() function. CheckLock() is called first, which takes care of holding the vehicle in place when the lock is on (the variable is Locked set to true):

```cs
public virtual void UpdatePhysics()
{
    CheckLock();
}
```

velo is a variable holding the car's rigidbody:

```cs
// grab the velocity of the rigidbody and convert it into
// flat velocity (remove the Y)
velo=body.angularVelocity;
```

The next task is to find the velocity in the local space:

```cs
// convert the velocity to local space
velo=transform.InverseTransformDirection(body.velocity);
flatVelocity.x=velo.x;
flatVelocity.y=0;
flatVelocity.z=velo.z;
```

mySpeed is then checked to see whether its value is less than 2. When the speed is slow and the brake key is held, brakeTorque is no longer applied to the wheels; instead, a reverse amount of the maximum torque (brakeMax) is applied to make the vehicle reverse:

```cs
// if we're moving slow, we reverse motorTorque
// and remove brakeque
if (mySpeed < 2)
{
    // that is, if we're pressing down the brake
    // brake>0)
    if (brake>0)
        rearWheelLeft.motorTorque = -brakeMax * brake;
        rearWheelRight.motorTorque = -brakeMax * brake;
}
```

In reverse mode, no brakeTorque will be applied to the Wheeliders so that the vehicle is free to move backward:

```cs
rearWheelLeft.brakeTorque = 0;
rearWheelRight.brakeTorque = 0;
```

When the vehicle is reversing, the steering is applied in reverse to switch over when going backward, as a real car:

```cs
frontWheelLeft.steerAngle = steerMax * steer;
frontWheelRight.steerAngle = steerMax * steer;
```

If the reverse conditions have been applied to the WheelColliders, this function drops out before the regular (forward) values are applied:

```cs
// drop out of this function before applying the 'regular'
// non-reversed values to the wheels
return;
}
```

In this script, driving the wheels of WheelColliders is a case of applying motorTorque and brakeTorque and steering the steerAngle:

```cs
// apply regular movement values to the wheels
rearWheelLeft.motorTorque = accelMax * motor;
rearWheelRight.motorTorque = accelMax * motor;
```

```cs
rearWheelLeft.brakeTorque = brakeMax * brake;
rearWheelRight.brakeTorque = brakeMax * brake;
```

```cs
frontWheelLeft.steerAngle = steerMax * steer;
frontWheelRight.steerAngle = steerMax * steer;
```

The CheckLock() function looks to see whether the Boolean variable is set to true; when it freezes, it zeroes all inputs to zero and the x and z velocities of the vehicle's rigidbody. The y velocity is left as is, so that gravity will still apply to the vehicle when it is held in place. This is important at the start of a race when the vehicle is being held until 3, 2, 1 counting in finishes.
