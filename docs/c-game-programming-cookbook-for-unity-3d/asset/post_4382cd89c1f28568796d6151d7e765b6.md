Here, we use the audioSFXSliderValue variable (a float) to return the value that the GUI.HorizontalSlider gives back. A slider may take up to five parameters as follows:

- 1. A rectangle defining the size of the area.
- 2. The current value to render the slider handle. The audioSFXSliderValue variable is used, and it's OK for the GUI.HorizontalSlider to send feedback to itself, as we set the value of handle to the same variable.
- 3. The value at the left end of the slider. Your slider can start anywhere, but in this case, we need it to start at 0.
- 4. The value at the right end of the slider. The maximum volume we would need to set is 1.
- 5. If you wanted to set a GUIStyle, a fifth parameter may be used here too.

PlayerPrefs is used for saving out data we will need later on. In SaveOptionsPrefs(), the values for sound volume, music volume, and graphics detail level are saved to disk. You may have noticed some of these PlayerPrefs names from earlier chapters of this book, where they were used to set volume levels and graphics settings:

```cs
void SavePrefs() {
    PlayerPrefs.SetFloat(gamePrefsName+"_SFXVol", audioSFXSliderValue);
    PlayerPrefs.SetFloat(gamePrefsName+"_MusicVol", audioMusicSliderValue);
    PlayerPrefs.SetFloat(gamePrefsName+"_GraphicsDetail", graphicsSliderValue);

    // set the quality setting
    QualitySettings.SetQualityLevel((int)graphicsSliderValue);
}
```

PlayerPrefs is used to save our settings to disk. The example games in this book use an optional string variable gamePrefsName to attach to the PlayerPrefs key names so that our preferences will be saved individually for each game. This is completely optional—Unity saves preferences on a per-game basis, so your preferences will never be shared across projects. In this case, all of the game examples in this book are saved into a single Unity project, the prefix ensures that each game will save its settings despite them all being lumped into the same preferences files.
