## 2.3.1 Script Breakdown

The script derives from BaseGameController.cs: 


The variable Instance is set to this when the script is first created and the script's constructor gets called:


A call to Init() is made:


The Init() function starts by setting Time.timeScale, in example gameSpeed is set to make the game run faster:

```csharp
void Init ()
{
    // in case we need to change the timescale, it gets here
    Time.timeScale = gameSpeed;
}
```

This game uses a race manager script. As discussed at the beginning of this chapter, the race manager tracks state for both the individual players and the race overall. The game controller needs to tell the race manager, held in the variable GlobalRaceManager, that the race is beginning, and a new race should be initialized:

```csharp
// tell race manager to prepare for the race
GlobalRaceManager.Instance.NewRace( totalLaps );
```

The spawn system requires two arrays to be passed into it for spawning players, for start positions and rotations. In this code, the arrays are initialized and populated with positions and rotations from the startPoints array:

```csharp
// initialize some temporary arrays we can use to set up the players
Vector3 [] playerStarts = new Vector3[numberOfRacers];
Quaternion [] playerRotations = new Quaternion[numberOfRacers];
```

We are going to use the array of start positions that must be in the editor, which means we need to make sure there are enough start positions for the number of players:

```csharp
for ( int i = 0; i < numberOfRacers; i++)
{
    // grab position and rotation values from start transforms
    playerStarts[i] = (Vector3) startPoints[i].position;
    playerRotations[i] = (Quaternion ) startPoints[i].rotation;
}
```

Now that the controller has positions and rotations for the players, SpawnController may be called to add the players to the scene:

```csharp
SpawnController.Instance.SetupPlayers( playerPrefab, playerStarts, playerRotations, numberOfRacers );
```

playerTransforms is filled with all of the transforms. We get to them by calling SpawnController.Instance.GetAllSpawnedPlayers(), which returns all of the player transforms created by the spawn controller:

```csharp
playerTransforms=new ArrayList();
// let's grab references to each player's controller script
playerTransforms = SpawnController.Instance.GetAllSpawnedPlayers();
```

When the game controller communicates with the players, it uses references to them from an array playerList. The next part of the code iterates through the player array (using the value held in numberOfRacers as a total count) and uses GameObject.GetComponent() to find each instance of the CarController_MVD.cs script attached to each player. As the code steps through each player, it also uses GetComponent() to find its AI controller script to tell it which waypoint control script to use and calls its Init() function:

```csharp
playerList=new ArrayList();
for ( int i = 0; i < numberOfRacers; i++)
{
    Transform tempT= (Transform)playerTransforms[i];
    CarController_MVD tempController= tempT.GetComponent<CarController_MVD>();
    playerList.Add(tempController);
    BaseAIController tempAI=tempController.GetComponent<BaseAIController>();
    // tell each player where to find the waypoints
    tempAI.SetWaypointController(WaypointForAI);
    tempController.Init ();
    // tell the car controller script about the waypoint controller so it can pass it onto the racecontroller (!
}
```

The variable WaypointControllerForAI should serve to reference the waypoint controller in the main scene (via the Unity editor inspector):

```csharp

```

playerGO1 will store a reference to the main player's gameObject, which is returned by the spawn controller when we ask for it by index:


Once the main player is established, the game controller adds an AudioListener component to it. By default, Unity adds an audio listener to the main camera of the scene. This is great for a start, but in this case, it makes more sense to have the listener attached to the player; the user is supposed to be in the car, not in the camera:

```csharp
// add an audio listener to the first car so that the audio
// is from the car rather than from the main camera
playerGO1.AddComponent<AudioListener>();
```

Next, the game controller looks to find the default AudioListener component attached to the camera. If it finds one, the next part of the code uses the Destroy() function to remove it. Removing the listener from the camera is important, as Unity allows for single listener per scene, and if there is more than one listener, a warning will be written to the console:

```csharp
// look at the main camera and see if it has an audio listener attached
AudioListener tempListener= Camera.main.GetComponent<AudioListener>();
// if we found a listener, let's destroy it
if(tempListener==null) Destroy(tempListener);
```
