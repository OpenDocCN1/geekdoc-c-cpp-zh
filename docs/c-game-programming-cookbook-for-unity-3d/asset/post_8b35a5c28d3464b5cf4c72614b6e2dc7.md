
```cs
// automatically change the value of moveDirection
// before we do the actual move
if( obstacleFinderResult==-1) { // GO LEFT
    SetAIState(AIState.stopped_running_length );
}
if( obstacleFinderResult==2) { // GO RIGHT
    SetAIState(AIState.stopped_running_right );
}
```

When obstacles are detected on both the left and right sides of the bot, the return result from IsObstacleAhead() is 3. Instead of trying to avoid whatever is blocking the way forward, the bot goes into a reverse state—AIState.backing_looking_for_target:

```cs
if( obstacleFinderResult==3) { // BACK UP
    SetAIState( AIState.backing_looking_for_target );
}
```

Now that the bot has deciding whether or not to turn or back up to avoid obstacles, all that is left for it to move forward. The MoveForward() function is called as break for the next case:

```cs
// all clear! head forward
MoveForward();
break;
```

The next state is AIState.chasing_target:

```cs
case AIState.chasing_target:
// chasing in chase mode, we point toward the target
// and go right at it!
```

As this mode's main objective is to chase the transform in followTarget, we need to make sure that there is an actual transform in there to follow. If followTarget is null, the script changes the state back to AIState.moving_looking_for_target:

```cs
// quick check to make sure that we have a target
// (if not, we drop back to patrol mode)
if( followTarget==null )
    SetAIState( AIState.moving_looking_for_target );
```

TurnTowardTarget() will rotate the transform toward the target passed into the function as a parameter, at the speed by the float variable RotateSpeed. Note that the transform to be rotated will be the transform by the variable rotate-Transform, as described in the Init() function earlier in this section, not specifically the transform to which the script is attached:

```cs
// the TurnTowardTarget function does just that, so
// to chase we just throw it to the current target
TurnTowardTarget(followTarget);
```

Unity.Vector3.Distance function is used to check the position of the transform in followTarget is not too close or too far away:

```cs
// find the distance between us and the chase target
// to see if it is within range
distanceToChaseTarget=Vector3.Distance
    (myTransform.position,followTarget.position);
```

If the target is further than minChase3D units away, the bot will continue to move forward. The MoveForward() function takes keeping of things moving:

```cs
// check the range
if(distanceToChaseTarget>minChaseDistance)
{
    // keep charging forward
    MoveForward();
}
```

When the target transform is too far away, the AIState needs to switch back to the search/patrol state of AIState.moving_looking_for_target:

```cs
// we do a quick check to test the distance
// between AI and target. If it's higher than
// our maxChaseDistance variable, we drop out of
// chase mode and go back to patrolling.
if(distanceToChaseTarget>maxChaseDistance ||
    CanSee(followTarget)==false)
{
    // set our state to 1 - moving_looking_for_
    // target
    SetAIState(AIState.moving_looking_for_target);
}

break;
//
```

The next case is AIState.backing_up_for_target, which calls upon the MoveBack() function to take care of moving the bot backward:

```cs
case AIState.backing_up_for_target:
// look for chase target
if(followTarget!=null)
    LookAroundFor(followTarget);

// backing up
MoveBack();
```

Once IsObstacleAhead() returns a zero (no obstacles) into obstacleFinderResult, we try to avoid hitting the same obstacles by going into turning mode. Which direction to turn is randomized in the hope that if one proves unsuccessful in getting the bot out of the trap status, perhaps the other way will free it. To randomize, we use Random.Range(min,max) to represent a 50/50 percentage split over which direction it will turn:

```cs
if (obstacleFinderResult==0)
{
    // now we've backed up, let's randomize
    // whether to go left or right
    if (Random.Range(0,100)>50)
    {
        SetAIState(AIState.stopped_turning_left);
    } else {
        SetAIState(AIState.stopped_turning_right);
    }
}
break;
```

Functions for turning left and right, TurnLeft() and TurnRight(), respectively, are used by the cases for AIState.stopped_turning_left and AIState.stopped_turning_right. The two cases also check obstacleFinderResult to see whether the path is clear. If the path is clear (when obstacleFinderResult contains zero), the state is changed to AIState.moving_looking_for_target:

```cs
case AIState.stopped_turning_left:
// look for chase target
if(followTarget!=null)
    LookAroundFor(followTarget);

// stopped, turning left
    TurnLeft();

if(obstacleFinderResult==0)
{
    SetAIState(AIState.moving_looking_for_target);
}
break;
```

```cs
case AIState.stopped_turning_right:
// look for chase target
if(followTarget!=null)
    LookAroundFor(followTarget);

// stopped, turning right
    TurnRight();

// check results from looking to see if path ahead
// is clear
if(obstacleFinderResult==0)
{
    SetAIState(AIState.moving_looking_for_target);
}
break;
```

The AIState.paused_looking_for_target does a check to make sure that followTarget is not null and makes a call to LookAroundFor() function to see whether the target is within range to chase. This code contains no movement, and when the bot is in this state, it should stand still and wait for the player to get close, although standing guard:

```cs
case AIState.paused_looking_for_target:
// standing still, while looking for chase target
// look for chase target
if(followTarget!=null)
    LookAroundFor(followTarget);
break;
```

So far, the AI code dealt with patrolling and standing guard, but the script supports waypoint-following and steering behaviors. The first method of waypoint following is AIState.translate_along_waypoint_path, which moves the bot along a path without rotation:

```cs
case AIState.translate_along_waypoint_path:
// following waypoints (moving toward them,
// pointing at them) at the speed of moveSpeed
```

Before trying to follow any sort of path, it is a good idea to check that the initialization (didInit will be true) and the last waypoint has not been reached. If didInit is false or the last waypoint has been reached, the path-following should stop and the function returns:

```cs
// make sure we have initialized before trying
// to access waypoints
if(didInit && reachedLastWaypoint)
    return;
```

The UpdateWaypoints() function is called to check the distance from the bot to the waypoint and update which waypoint to follow, as needed:

```cs
UpdateWaypoints();
```

isStationary is a Boolean variable used to provide a method of keeping the AI stationary, if required. If it is set to true, the bot will not be moved. Note that this state does not have any rotation code or provide input values for its movement; uses Unity's Transform.Translate to directly translate the transform toward each waypoint, instead. It will use the transform held in the variable myTransform:

```cs
// move the ship
if( isStationary)
{
```

A Vector3 called targetMoveVec is a vector for the bot to move along, toward the waypoint. This movement vector is calculated by subtracting the position of the bot from the current waypoint position. The vector is then normalized by Unity's Vector3.Normalize function to strip away the magnitude. Note that the waypoint's transform is held in the current waypointTransform, put there by earlier call to the UpdateWaypoints() function:

```cs
targetMoveVec = Vector3.Normalize(currentWaypointTransform.position - myTransform.position);
```

The actual amount we move is an interpolated somewhere between the current value of moveVec (the current amount being moved) and the vector we calculated in targetMoveVec, pathSmoothing is a float variable used to determine how long the interpolation takes (Time.deltaTime multiplied by pathSmoothing) and therefore how much the rotation along the waypoint path should be smoothed out:

```cs
moveVec = Vector3.Lerp(moveVec, targetMoveVec, Time.deltaTime * pathSmoothing);
```

When the actual translation of the transform happens, the moveVec vector is multiplied by moveSpeed and, in turn, multiplied by Time.deltaTime to keep everything time based:

```cs
myTransform.Translate(moveVec * moveSpeed * Time.deltaTime);
MoveForward();
```

Rotating myTransform toward the target waypoint is optional. The faceWaypoints Boolean variable is intended to be set in the Unity editor window. When faceWaypoints is true, the rotation is carried out by a call to TurnTowardTarget, passing in the current waypoint transform:

```cs
if(faceWaypoints)
{
    TurnTowardTarget(currentWaypointTransform);
}
break;
```

Next in the UpdateAI() function is the steering behaviors, ready for use by the example cases from this book, Metal Vehicle Doom and Tank Battle.

AIState.steer_to_waypoint starts by checking that the initialization occurred (didInit be true) and that the last waypoint has not been reached. If all is well, a call to UpdateWaypoints() will make sure that the current waypoint held by the variable WaypointTransform is the correct:

```cs
case AIState.steer_to_waypoint:
// make sure we have been initialized before trying
// to access waypoints
if(!didInit && !reachedLastWaypoint)
    return;

UpdateWaypoints();
```

It may be possible that currentWaypointTransform does not contain a waypoint. If that is the case, the function drops out:

```cs
if(currentWaypointTransform==null)
{
// it may be possible that this function gets
// called before waypoints have been set up
// so we catch any nulls here
    return;
}
```
