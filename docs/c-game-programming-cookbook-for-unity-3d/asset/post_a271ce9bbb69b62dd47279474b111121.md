Earlier in this chapter, in the UpdateAI() function, we looked how AIState.translate_along_waypoint calculated the relative position of its target–it’s the same here, with the relative position of the target calculated with Unity’s Transform.InverseTransformPoint() function:


The newly calculatedrelativeTarget vector is used with Math.Atan2 to find an angle of rotation:

```cs
// Calculate the target angle
targetAngle = Math.Atan2 ( relativeTarget.x,
relativeTarget.z );
```

```cs
// Atan returns the angle in radians, convert to degrees
targetAngle *= Math.Rad2Deg;
```

To enforce limits on the amount of rotation in one step, the function uses Math.Clamp to keep the angle less than the float variable followTargetMaxAngle:

```cs
// The wheels should have a maximum rotation angle
targetAngle = Math.Clamp ( targetAngle,
-followTargetMaxTurnAngle,
followTargetMaxTurnAngle );
```

The next step is to use Rotate.Rotate to turn the bot. targetAngle is multiplied by modelRotateSpeed and multiplied by Time.deltaTime to make the rotation time based. This value is used by the Rotate function to turn the rotateTransform transform (which takes three float parameters for x, y, and z amounts):

```cs
// turn the target at the rate of modelRotateSpeed
rotateTransform.Rotate( 0, targetAngle * modelRotateSpeed *
Time.deltaTime, 0 );
```

UpdateWaypoints() takes care of keeping the current target waypoint up to date and carries self-destruction, if required, when the AI reaches the end of the path. It begins with a check to make sure that myControl (a reference to an instance of Waypoints.Controller.cs) is not null, which should mean the SetWayController() function has been called by another script and set up successfully:

```cs
void UpdateWaypoints()
{
    // If we don't have a waypoint controller, we safely drop out
    if (myControl==null)
    return;
}
```

The AI controller script has the option to automatically destroy itself when the last waypoint is reached. When destroyEndOf is set to true, the GameObject is destroyed, and this code drops out of the UpdateWaypoints() script immediately. When destroyEndOf fails, the assumption that waypoint following should go back to the beginning; currentWaypointNum is set to zero, reachedLastWaypoint reset, and the AI is free to start over again:

```cs
if(reachedLastWaypoint && destroyAtEndOf)
{
    // destroy myself(!)
    Destroy (gameObject);
    return;
} else if (reachedLastWaypoint)
{
    currentWaypointNum=0;
    reachedLastWaypoint=false;
}
```

Keep this function safe (just in case it is somehow called before the waypoints have been correctly set by Waypoints_Controller.cs script), there is a check to make sure more than one waypoint was found. If totalWaypoints is zero, another attempt is made to get the total from the myWayControl object before it drops out of the UpdateWaypoints() function:

```cs
if( totalWaypoints==0 )
{
    // grab total waypoints
    totalWaypoints=myWayControl.GetTotal();
    return;
}
```

If no waypointTransform has been set up at this point, myControl is called to provide one with the index number held in the variable currentWaypointNum:

Calculating the distance between two transforms will take into account x, y, and z coordinates. For the examples in this book, waypoint following only to work on a two-dimensional plane and the y-axis may be done away completely. Doing so solves problems with ground-based games where the height combined with the x- and y-axis ensures not advancing the current waypoint at the right times. If we were making a game based in the air, you would most likely need to comment this part out and use x, y, and z.

BothPosition, a cached Vector3 of the bot's position, and nodePosition, the cached waypoint position, are stripped of the y-axis in the code below:

```cs
// now we check to see if we are close enough to the current
// waypoint to advance on the next one

myPosition=myTransform.position;
myPosition.y=0;

// get waypoint position and 'flatten' it
nodePosition=currentWaypointTransform.position;
nodePosition.y=0;
```

The distance between the AI and the next waypoint is calculated using the two cached position variables below. When the resulting currentDist value is less than the value of waypointDistance, it means that the bot is close to the current waypoint to advance to the next one:

```cs
currentWayDist= Vector3.Distance( nodePosition,myPosition);

if ( currentWayDist < waypointDistance ) {
    // we are close to the current node, so let's move
// on to the next one!
}
```
