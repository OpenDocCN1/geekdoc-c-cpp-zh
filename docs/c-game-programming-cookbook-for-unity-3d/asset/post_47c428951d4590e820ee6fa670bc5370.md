The raycast starts at the position of the waypoint (from tempVEC) with 300 units added up to it, to ensure that the raycast starts below the ground. The ray direction is -Vector3.up (straight down), but in this call to Physics.Raycast, there is no distance-set, and the ray should detect everything below it no matter how far away:

```csharp
if (Physics.Raycast(tempV + (Vector3.up * 300),
    -Vector3.up, out hit))
{
    tempVEC.y=hit.point.y-15;
}
```

// player rotation to the waypoint's rotation so that we are

myTransform.position=tempVEC;

}

## 12.3.5 User Interface

The user interface for this game is a collection of gameObjects with UI components attached. They are in the game scene (as gameObjects), referenced and managed by the game controller. Here are:

- Final_Position—A gameObject with a UI component on it, displaying a message that will be shown at the end of the game to inform the user of/her final position.
- in_1—A UI component containing a graphic showing the number 1, for the start of the race.
- in_2—A UI component containing a graphic showing the number 2, for the countdown.
- in_3—A UI component containing a graphic showing the number 3, for the countdown.
- Text_Lap—A UI object positioned in the top left of the screen to show how many laps the player has completed.
- Text_Position—A UI object positioned in the top right of the screen to show the current race position of the player.
- WrongWay—A UI object positioned just above the center of the screen. Its gameObject will be made active whenever the user's vehicle is going the wrong way around the track.

## 13 Tank

1974, Kee Games, a subsidiary of Atari, Inc., released an arcade game called Tank!. It was a two-player game where players had to drive around a maze and destroy the other player's tank. Although its graphics were simplistic black and white from a fixed top-down viewpoint, the game was extremely advanced for the time. Its control system was outstanding; it used two-axis (up and down) joysticks to steer each vehicle as each stick were controlling an individual track on each side of the tank. Tank! required two players to play; there was no artificial intelligence. Perhaps this was because of the complexity of AI programming and the technological limitations of the time, or perhaps it was a design decision; it had no apparent impact on its success, and the game was a huge hit. It would be quite a while before a single-player tank game made it into the arcades. I personally recall the privilege of playing a tank game in an arcade in the late 1970s; I played a top-down tank game but it was so long ago that I can't be sure it was the original Tank!. When screenshots, it looks very familiar, at least. Variations on Tank! came on a cartridge called Combat, released in 1977, which included five game types, all tied together by the main theme in the title. Most of my time on the Atari 2600 was spent battling against my brother or my cousin, each of us trying to blast the other out of the games or beat each other's high scores. Tank! was a huge hit with us, and I'm sure that Combat would have ended up being the worst cartridge we owned.

Sometimes in the early 1980s, something arrived at my local arcade that would change my perspective on video games forever. It was the game that finally fired my interest in virtual reality: Battlezone.

Battlezone features vector 3D graphics and one of the most amazing arcade cabinets that any 80s kid could encounter. Instead of having to stand and look at the screen, Battlezone had viewing goggles that looked rather like binoculars. Since it was goggles, the player had to face it with vision taken up entirely by the game.

Battlezone was a single-player game, with enemies controlled by artificial intelligence. Just as with the original game Tank!, its control scheme used two-axis joysticks to simulate control of individual tracks; push both sticks forward and the tank moved forward, pull one back and one forward when the tank turned. The viewpoint was first person, inside the tank. When a projectile hit the player's vehicle, a vector-based glass cracking effect was displayed in front of the view as though the window of the tank had been hit. Battlezone was the closest thing possible to being inside a computer game. In the early 1980s, it was a truly mind-blowing experience; 3D vector graphics were new, and the immersion level offered by the game, its control system, and its goggles-based arcade cabinet second to none.

The design for the example game Tank Battle places itself somewhere between Tank! and Battlezone. The action takes place in a maze, with a number of AI-controlled tanks driving around the game world trying to blast each other into oblivion (see Figure 13.1). The camera view is third person, behind the tank, with a fixed turret projecting forward.

Its overall structure differs a little from other games in this book, as seen in Figure 13.2. This game may be found in the example games project, with its scenes in the Scenes/Tank Battle folder menu_TB and game_TB. Its prefabs are located in the Prefabs/Games/Tank folder.

The most important thing to note about it is that there are several elements extremely close to those from the other example game in this book, Metal Vehicle Doom. The tanks are, in fact, the exact car prefab except for the fact that the tanks have inclusive.
