# CHAPTER 9 PROPERTIES

Unfortunately, WPF inheritance includes many exceptions; thus, you cannot always count on it. For example, the ListBox controls its currently selected item by making the item's background color and its foreground white. If you set the window's Background property to the same blue color. If the ListBox and the items it inherited that property, then all of the items in the ListBox would have backgrounds and the user wouldn't be able to tell which was selected. To prevent this, the ListBox does not inherit its container's Background value.

Of course, you can explicitly set the ListBox's Background property or change the Background properties of the items that it contains, this does not solve the problem. It just makes it less likely that the problem will occur. You can still get into trouble by selecting poor background colors, but it won't happen unless you take extra action.

The InheritedProperties example shown in Figure 9-4 demonstrates some properties that are inherited and some are not.

The program's window sets its font to 18-point bold Comic MS, and you can see in the figure that the program's ComboBox and ListBox items, Label, Button, and GroupBox all inherit this.

The GroupBox sets its Background to a green bright brush. The program's Label, StackPanels, and GroupBox have transparent backgrounds through which, the Button, ComboBoxes, and ListBox display their own backgrounds.

The window sets its Foreground property to yellow. The program's GroupBox inherits this value, but the others do not.

One item in each of the program's ComboBoxes in its ListBox has its Background set to yellow and its Foreground set to red, so you can see that you can explicitly set these colors if you want.

If you download the example program from the book's web site and experiment with it, you'll see that these explicitly set colors do interfere with the ListBox and ComboBox's ability to highlight their selected items.

The moral is that you should be aware that controls inherit property values from their containers — but not always.

# ATTACHED PROPERTIES

Sometimes a control might need a property that contains information for use by another control. For example, a Button inside a Grid control. The Grid needs to determine how to arrange the Button. row and column. Although the Grid needs to know this information, the row and column really belongs to the Button.

So how do you attach this information to the Button control? You could give the Button Row and Column. If you took that approach, you would need to similarly define the same properties for every other kind of control on the off change that instances were placed inside a Grid.
