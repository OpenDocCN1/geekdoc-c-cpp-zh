The first Label displays Time as a StaticResource, so it is not updated every second and displays the resource's initial value, 1:00:00 AM.

The second Label displays TimeNow a DynamicResource, so it shows the current time. It also uses DynamicResource statements to load its colors from its own resources.

Like the second Label, the third Label displays TimeNow a DynamicResource, and thus it shows the current time. It uses DynamicResource statements to load its colors from its system resources. In Figure 12-11, I changed the desktop background color to a dark purple, and the Label's background updated to match.

In summary, dynamic resources place a big load on the system, so you should use StaticResource whenever possible. If you expect a resource value to change while the programming is running, however, use DynamicResource so your program can see the change.

# SUMMARY

XAML resources provide several benefits: giving many controls a consistent appearance, providing a central location for resource definitions, and making it easy to change the appearance of related controls so they remain consistent.

By using resource dictionaries, you can change the entire application's appearance quickly and easily.

One big drawback to resources is that they are fairly verbose and relatively hard to read. For example, the following code defines Rectangles. The first uses hard-coded property values is relatively easy to read. The second uses more flexible values but is harder and to understand-

```
<Rectangle Grid.Row="0" Grid.Column="0" Margin="5"
RadiusX="10" RadiusY="10"
Fill="Yellow" Stroke="Orange" StrokeThickness="1"
/>
<Rectangle Grid.Row="0" Grid.Column="0"
Margin="DynamicResource thkMargin"
RadiusX="DynamicResource dblRadiusX"
RadiusY="DynamicResource dblRadiusY"
Fill="DynamicResource brRectFill"
Stroke="DynamicResource brRectStroke"
StrokeThickness="DynamicResource dblStrokeThickness"
/>
```

If an application has many controls that share the same property values, resources can make the code much harder to read. For example, if a window contains a dozen or so Rectangles with the same Margin, RadiusX, RadiusY, Fill, and Stroke values, then using this kind of resource code would take a huge amount of space.

The next chapter explains one way to practically eliminate this: styles. By using styles, you can package sets of properties for your controls that should have a similar overall appearance. The chapter also explains property triggers, objects that styles can use to change a control's properties when conditions arise.
