CanGoBack — True if the NavigationService can move back to a previous object.

CanGoForward — True if the NavigationService can move forward to a following object.

GoBack — Goes to the previous page if one exists.

GoForward — Goes to the next page if one exists.

Navigate — Displays a Page or URI.

RemoveBackEntry — Removes the most recent navigation history entry.

Source — Gets or sets the URI of the display source. Normally in code-behind, you would use the Navigate method to open a source, but you can set this property in XAML to make the Page open a URI when it is displayed.

# FRAME

The previous example display Page objects. The result is a form containing navigation buttons, the Page object, and nothing else.

Sometimes you may want a Page to appear as only part of a form that also contains other elements. You can achieve this by placing a Page inside a Frame control.

You cannot write XAML code that places a Page inside a Frame, but you can set the Frame's Source property to the name of the Page that it should show when it appears.

The FrameApp program shown in Figure 22-5 uses this to display the Pages used by the PageApp program inside a Frame. In Figure 22-5, the top and bottom labels and the green background are part of a Window. Everything else is inside the Frame.

The following XAML fragment shows how the Frame displays its Labels and Frame. An unnamed style targeted at Label controls the Labels and gives them drop shadows.

```
<StackPanel>
  <Label FontSize="30" FontWeight="Bold" Content="FrameApp"/>
  <Frame Name="main" Source="PageMain.xml" Height="420" Margin="10"/>
  <Label BorderBrush="Black" BorderThickness="1" FontSize="16"
    Content="Use the buttons inside the Page to navigate within the frame."/>
</StackPanel>
```

This code contains two points worth mentioning. First, it sets the Frame's Source attribute to pageMain.xml so the Frame displays a pageMain object when it is loaded.

Second, the code explicitly sets the Frame's height. The Frame only displays its Back and Next buttons when the user can navigate backward or forward. Initially, the Frame has not visited any other pages, so navigation is not possible and these buttons are hidden. Then, when you move to a new Page, the Frame displays its buttons. If you don't set the height explicitly, adding the buttons makes the Frame taller, and that makes the Window rearrange its controls.
