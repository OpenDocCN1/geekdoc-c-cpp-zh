In all of the styles described in the previous, the element introduced with x:Key attribute to give a style name. Controls use the StaticResource keyword to refer to the name.

In contrast, if you omit the attribute and a TargetType, the resulting unnamed style applies to all controls of the TargetType within the style's scope. For example, the following Style applies to every Button within the style's scope, so every Button has a yellow background and a red foreground:

# CLEVER CLASSES

The classes used in the Setters'property attributes must support their properties,
but the style doesn't actually require the controls using them be from that class.

For example, the previous style sets the FrameworkElement.Width and
FrameworkElement.Height properties. The FrameworkElement class has the
Width and Height properties, so WPF can use its definitions to understand how to
set their values. If you changed the Width property to Red, WPF would complain
because FrameworkElement.Width cannot be a color.

While the class defines the properties, the style doesn't require the controls using
it have those classes. In this example, if you were to change FrameworkElement to
Button, the style would still work. The Button class also has Width and Height properties, so it could define them, the Label and Rectangle can still use those property
though they are not descendants of Button.

In fact, if you look back at the style's definition and the result in Figure 13-4, you'll
see the Rectangle uses the same Margin value as the Button and Rectangle
even that property is specified with the Control class and Rectangle isn't a
descendant of Control.

The moral of the story is that it doesn't matter much which classes you use --
as long as they define the properties.

# STYLE WITH SCOPE

An unnamed style applies to all objects of its TargetType but only within its scope. If you want to modify every Label in the entire application, define the style in Application.Resources. If you want to modify the Labels in a window, define the style in Window.Resources. If you want to modify the Labels in a Grid, StackPanel, or other container, define the style in appropriate Resources (Grid.Resources, StackPanel.Resources, etc.).

# PROPERTY VALUE PRECEDENCE

Most of the examples in this book set property values in straightforward, unambiguous ways. For example, the UnnamedStyles sets property values using unnamed styles. It sets a few other properties (e.g., a Button's or Label's Content), but it doesn't set the same property in a Style and element attribute.

In fact, there are many ways in which you set values for the same properties. If you set a property's value in more than one way, WPF uses property precedence to decide which value is actually used. For example, if you set a control's property in a style and also in the control's attributes, then the value in the attribute takes precedence.

The following list shows a partial ordering of how property values might be applied to a control. You can think of the values as being applied in order so that those that are last have a higher precedence and override those that are earlier.

- 1. Container Inheritance — A control may inherit a property from its container. For example, if a Window defines a FontFamily, then Labels inside the Window inherit that FontFamily. (Note that some controls block property inheritance.)
- 2. Default Style — Default styles define the “natural” appearance of control unless you modify it by setting other properties. For example, Buttons have a typical default appearance unless you override it.
- 3. Unnamed Styles — Unnamed styles can have precedence over default styles. If multiple unnamed styles might apply to a control, then the one with the most limited scope has precedence. For example, suppose a Window contains a Grid and both define unnamed Label styles. A Label inside the Grid would use the Grid's version of the Style.

> STYLES NOT DO COMPROMISE
Two styles do not share a control's properties if they set values for different properties. One style or the other will set the control's properties, and the other will have no say in the matter.
If two unnamed styles might apply to a control, then the one with more limited scope has sole control.
- 4. Named Styles — Named styles have precedence over unnamed styles. As is the case with unnamed styles, if more than one name style might apply to a control, then the one with the most limited scope has precedence.
- 5. Local Values — A property value set either with property attribute or property element syntax takes precedence over the previous kinds of values.
- 6. Active Animations — If an animation is running, it may modify current property values. (Chapter 14 describes animation in detail.)
