The Manager class is derived from the Employee class, so it also inherits the Employee class'snFirstName, LastName, and Extension properties.

The View controls that produce these displays include HierarchicalDataTemplate objects in their Resources sections to describe what the control should do at each node. For example, the following code shows how the control handles Region objects:

```
<HierarchicalDataTemplate
DataType="(x:Type local:Region)"
ItemsSource="Binding Path=RegionName">
  <TextBlock Text="(Binding Path=RegionName) Foreground="Red">
    <OuterGlowBitmapEffect />
  </TextBlock>
  <TextBlock.BitmapEffect>
</TextBlock>
</HierarchicalDataTemplate>
```

The HierarchicalDataTemplate has three key keys:

+   First, its DataType attribute tells what this template holds. The preceding template springs into when the TreeView encounters a Region object in its data.
Second, the template's ItemsSource attribute tells the TreeView should look for children of this item. The previous code indicates that a Region object has children that are Departments. You can use the ItemsSource attribute to make the Tree follow paths through the data hierarchy.
Third, the HierarchicalDataTemplate provides the template to display the data at each node. This example displays the Region's RegionName property in a TextBlock.

The TreeView on the left in Figure 18-2 uses the following HierarchicalDataTemplate to display data for a department object:

```
<HierarchicalDataTemplate
DataType="(x:Type local:Department)"
ItemsSource="Binding Path=Managers">
  <TextBlock Text="(Binding Path=Name) Foreground="Blue"/>
</HierarchicalDataTemplate>
```

This template's ItemsSource attribute indicates that the children of a department node are given by the object's Managers property, so the TreeView follows the Managers path of objects.
