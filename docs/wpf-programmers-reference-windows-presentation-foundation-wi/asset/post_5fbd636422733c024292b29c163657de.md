Most of WPF's container controls arrange their children in fairly simple ways. For example, the StackPanel, WrapPanel, Grid, and UniformGrid controls arrange their children in non-overlapping rectangular areas.

These controls are easy to use but sometimes you may not want such simple arrangements. Instead you might want to display text and other objects flowing around sections that contain images, tables, or other items. The next chapter explains how you can use documents to do just that.

# Documents

WPF documents can contain a wide variety of objects such as:

- Paragraphs
- Tables
- Lists
- Floaters
- Figures
- User interface elements as Buttons and TextBoxes
- Three-dimensional objects

WPF has two different kinds of documents: fixed documents and flow documents. This describes these two kinds of documents. It explains the objects that each kind of document can hold and how they must be arranged to produce a valid result.

# FIXED DOCUMENTS

A fixed document displays its contents in exactly the same size and position whenever you view it. If you resize the control that holds the document, parts of the document may not fit, but they won't be moved. In that sense, this kind of document is similar to a PDF (Portable Document Format) file.

The following sections explain how you can build fixed documents and display them in your WPF applications.

# Building XPS Documents

When defined fixed documents, Microsoft also defined XML Paper Specification (XPS) files. XPS file is a fixed document saved in a special format that can be read and displayed by certain programs such as viewers in Internet Explorer.

One of the finest ways you can make an XPS document is to use Microsoft Word. Simply create a Word document containing any text, graphics, lists, or other content that you want, and export it as an XPS document.

Microsoft Word 2007 can export files in XPS (or PDF) format, but you need to install an add-in for that. As of this writing, you can install the add-in by following the instructions in Microsoft’s “2007 Microsoft Office Add-in: Microsoft Save as PDF or XPS” download at r.office.com/rldmsAddinPDFXPS. (If the page you moved can’t find it, go to Microsoft Document Center at http://www.microsoft.com/downloads and search for “Save as PDF or XPS”).

After you install the add-in, simply click on the Windows icon in Word's upper-left corner to expand the main menu. Click on the arrow next to "Save As" command, and select the "PDF or XPS" item.

> WORD OF WARNING
> Although Word can export a file in XPS format, it cannot read an XPS file fully, at least in the version I am using right now (Word 2007 SP1). Be sure to save your document as a Normal document in addition to exporting it so you can reload it later.

Some party products can also convert XPS documents into Word documents. For example, see www.investintech.com/xpscentral/xpsstword.

If you don't have Microsoft Word but are running the Windows 7 operating system, you can still create XPS documents relatively easily. Use Notepad, WordPad, or some other editor to create the document. Next print, selecting Microsoft XPS Document Writer as the printer. The writer will prompt you for the file where you want to save the result.

You can even display a web page in a browser such as Firefox or Internet Explorer, print it, and select XPS Document Writer as the printer.

In addition to printing with the XPS Document Writer, you can use the XPS Viewer as a stand-alone application. You can download and install the writer in the Microsoft Essentials Pack available at www.microsoft.com/whdc/xps/viewxps.mspx.

# Displaying XPS Documents

After you have created an XPS file, you have several options for displaying it.

The Microsoft XPS Viewer, which is installed by default in Windows 7 and integrated into Internet Explorer 6.0 and higher, can display XPS files. By default, XPS files are associated with Internet Explorer, so you can just double-click on the file to view it.

You can also download Microsoft XPS Viewer or Microsoft XPS Essentials Pack (which contains a stand-alone viewer) at www.microsoft.com/whdc/xps/xxps.mspx.

Finally, you can make a WPF application display an XPS file inside a DocumentViewer control. To do that, first add a reference to the ReachFramework library.

In Expression Blend, use the Project menu and select "Add Reference." Browse to the ReachFramework DLL (on your system, it is @\Program Files\Reach Assemblies\Microsoft\Framework\v3.0\ReachFramework.dll) and click OK.

In Visual Studio, open the Project and select "Add Reference." on the Add Reference dialog, select the .NET tab, check the ReachFramework, and click OK.

# Building Fixed Documents in XAML

Building an XPS document is easy with Microsoft Word, WordPad, or some external program, but sometimes it's more convenient to build in XAML or code-behind. For example, you might want a program to generate a report at runtime and display it.

Building a fixed document in XAML is not too complicated, although it is a lot of work because it's a verbose format. Starting by creating a Document to hold the document. Give it any properties and resources it needs (such as a background), and place a FixedDocument inside it.

The FixedDocument object should contain one or more PageContent objects that define its pages.

# PAGES

> If you don't want to build a page within the code, you can set a PageContent object's Source property to the Uniform Resource Identifier (URI) of the page it should display.

You can set each PageContent object's Width and Height properties to determine the size of the page.

Inside the PageContent, you place a FixedDocument to define the page's contents.

Inside the FixedPage, you can control controls such as StackPanel, Grid, TextBlock, and Border to create the page's contents.

# INHERITANCE

> FixedPage objects don't seem to inherit unnamed styles, so, for example, you can't set Label properties in an unnamed style defined in the Window.Resources. You need to either define the style inside the FixedPage or use a named style.
