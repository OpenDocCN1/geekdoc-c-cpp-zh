Unfortunately, the MediaElement control doesn't provide any dependency properties that a XAML file controls its playback. For example, it doesn't provide an IsPlaying or State property that XAML code could set to control the play or pause. That means you have to write code-behind to control the media.

However, XAML does include a SoundPlayerAction command that allows you to play an audio file to the end without pausing or stopping. You can write XAML trigger to invoke this command when an event takes place.

The following XAML code defines a trigger that executes when the btnSoundPlayerAction button fires its Click. When the code executes, the SoundPlayerAction plays the file notify.wav.

```xml
<Window.Triggers>
  <EventTrigger RoutedEvent="Button.Click"
    SourceName="btnSoundPlayerAction">
    <SoundPlayerAction Source="notify.wav"/>
  </EventTrigger>
</Window.Triggers>
```

## DocumentViewer

The FlowDocument object (described later in this chapter) displays information that can rearrange itself as needed at runtime. Just as a web page displayed in a browser can reflow text and controls when the browser resizes, a FlowDocument can rearrange its contents when it is resized.

In contrast, a DocumentViewer displays fixed content that does not reflow at runtime. The content in a DocumentViewer is fixed with every item positioned exactly as it will appear to the user, as the content of a PDF file is fixed.

    <GradientStop Color="#FF06BFF" Offset="1/2"/>
  </LinearGradientBackground>
</DocumentViewer>

  <PageContent>
    <FixedPage Width="500" Height="300"
        Background="#FFFF90" Margin="50">
      <Label Style="(StaticResource headerStyle)">
        FixedDocument Elements
      </Label>
    </FixedPage>
  </PageContent>
</FixedDocument>

## FlowDocumentPageView

FlowDocumentPageView displays a FlowDocument in page viewing mode. In this mode, the user can see a single page at a time, and controls at the bottom of the viewer allow the user to move to other pages.
The size of the page and the amount displayed by the viewer are determined by the FlowDocument's PageHeight and PageWidth properties, and by the viewer's size.
By default, the control scales to the viewer's width. When a page is defined by how much of the document can fit vertically in the viewer at that width. If you set the document's PageHeight and PageWidth properties, the viewer may control the document into more or fewer values.
