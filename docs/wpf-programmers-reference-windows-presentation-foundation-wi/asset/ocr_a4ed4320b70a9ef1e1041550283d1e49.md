attribute syntax to provide simple values, while the Fill setter uses property element syntax
set its value to a RedGradientBrush object.

```
<Style x:Key="RedRectStyle" TargetType="Rectangle">
  <Setter Property="Stroke" Value="5"/>
  <Setter Property="Width" Value="100"/>
  <Setter Property="Height" Value="50"/>
  <Setter Property="Margin" Value="5"/>
  <Setter Property="Fill">
    <Setter.Value>
      <RadialGradientBrush>
        <GradientStop Color="Red" Offset="0"/>
        <GradientStop Color="White" Offset="1"/>
      </RadialGradientBrush>
    </Setter.Value>
  </Setter>
</Style>
```

![](bbox=[0.78, 0.385, 0.875, 0.395])

You can use a style as you use any other resource. Simply set the "Style" to the style's key.

The RedRectangles example program uses the following code to display three reRectangles that
use the RedRectStyle:

```
<StackPanel Orientation="Horizontal">
  <Rectangle Style={StaticResource RedRectStyle}/>
  <Rectangle Style={StaticResource RedRectStyle}/>
  <Rectangle Style={StaticResource RedRectStyle}/>
</StackPanel>
```

![](bbox=[0.78, 0.575, 0.875, 0.585])

Notice how much this style simplifies this. Without the style, each Rectangle would need
to have its own own Stroke, StrokeThickness, Width, Height, Margin, and Fill properties.

# ALL TYPES OF TYPES

The x:Type extension allows you to pass a type into an attribute such as
TargetType. For example, the following two Style tags do the same thing:

```
<Style x:Key="RedRectStyle" TargetType="Rectangle">
<Style x:Key="RedRectStyle" TargetType="(x:Type Rectangle)"
```

Sometimes you might need to use the x:Type syntax to pass a type name into an
attribute that cannot convert the type from a simple string to a type
object, but so far I've been able to use the simpler syntax for styles.

For some reason, possibly early examples were written that way, the more
verbose x:Type format is common in the documentation and on the Web, so you'll
o often see that.
