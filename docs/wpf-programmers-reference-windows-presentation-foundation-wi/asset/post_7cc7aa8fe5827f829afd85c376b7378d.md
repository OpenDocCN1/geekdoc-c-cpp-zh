# Saving XPS Files

Having gone to the trouble of building a fixed document in XAML or code-behind, you might want to save it as an XPS file.

To save a fixed document into an XPS file, save a project in Visual Studio and add references to the ReachFramework and System.Printing libraries. To make using the libraries easier, you can add the following statements to the program:

```csharp
using System.Windows.Xps;
using System.Windows.Xps.Packaging;
```

Next, create an XpsDocument object to write into the file that you want to create. Make an XpsDocumentWriter associated with the document object, and use its Write method to write the FixedDocument into the file.

The SaveFixedDocument example uses the following code to save its FixedDocument object named fdContents into.

```csharp
// Save as an XPS file.
private void SaveAsXps_Click(System.Object sender,System.Windows.RoutedEventArgs args) {
    // Get the file name.
    Microsoft.Win32.SaveFileDialog dlg = new Microsoft.Win32.SaveFileDialog();
    dlg.DefaultExt = "*.xps";
    dlg.Filter = "XPS Documents (*.xps)|All Files (*.*)";
    if (dlg.ShowDialog() == true) {
        // Save the document.
        // Make an XPS document.
        XpsDocument xps_doc = new XpsDocument(dlg.FileName);
        System.IO.FileAccess.Write;
        // Make an XPS document writer.
        XpsDocumentWriter doc_writer = XpsDocumentWriter.CreateXpsDocumentWriter(xps_doc);
        doc_writer.Write(fdContents);
        xps_doc.Close();
    }
}
```

# FLOW DOCUMENTS

A flow document rearranges its contents as necessary to fit the container that is holding it. If you are making the viewing control tall and thin, the document reorganizes its contents to fit. In that sense, this kind of document is similar to a simple web page that rearranges its contents when you resize the browser.

A WPF program displays documents inside one of three kinds of viewers: FlowDocumentPageView, FlowDocumentReader, or FlowDocumentScrollView. The descriptions of these are found in Chapter 5 for more information about them.

A FlowDocument represents the flow document itself. The FlowDocument’s children must be objects that are derived from the Block class. These include BlockUIContainer, List, Paragraph, Section, and Table.

# BlockUIContainer

The BlockUIContainer can hold a single user interface (UI) as a child. For example, it can hold a Button, CheckBox, StackPanel, or Grid. If you want the control to hold more than one element, place container such as a StackPanel or Grid inside the control, and add other controls to the container.

The following XAML code creates a BlockUIContainer holding a GroupBox, which holds a StackPanel, which holds a TextBlock and CheckBoxes:

```xml
<BlockUIContainer>
  <GroupBox Header="BlockUIContainer" Width="250" HorizontalAlignment="Left">
    <StackPanel Margin="30,0,10">
      <TextBlock FlowDocument can hold:</
      <CheckBox Content="BlockUIContainer" Margin="50,0,5" />
      <CheckBox Content="List" Margin="50,0,5" />
      <CheckBox Content="Paragraph" Margin="50,0,5" />
      <CheckBox Content="Section" Margin="50,0,5" />
      <CheckBox Content="Table" Margin="50,0,5" />
    </StackPanel>
  </GroupBox>
</BlockUIContainer>
```

# Paragraph

A Paragraph groups its contents into a paragraph. A Paragraph adds some vertical space between itself and the previous element. A Paragraph typically contains inline elements including:

- Text — Plain text
- Bold — Makes its text bold
- Figure — Embeds an area inside the ParagraphUIContainer where you can place block elements as a Paragraph or BlockContainer. Anchor and offset properties let you determine where in the paragraph the Figure appears.
- Floater — Similar to a Figure except you cannot control exact positioning. Instead, FlowDocument moves the Floater to a position where it fits.

# Flow Documents | 375

- Hyperlink — Displays a hyperlink. NavigateUri property holds the URI to which the object should navigate. The Hyperlink can automatically navigate to that address only if it is contained in a navigation host as NavigationWindow, Frame, or browser.
- InlineUIContainer — Can hold UI elements as Buttons, CheckBoxes, and RadioButtons.
- Italic — Makes its italic
- LineBreak — Makes text start a new line. This does not add extra vertical space between the lines.
- Run — Contains a run of text, with a different appearance from the rest of the paragraph. You can use the Run's properties to change the text's background color, text color, font, size, and so forth.
- Span — Similar to a Run except it can also contain inline elements (e.g., Bold, Italic) and UI elements (e.g., Button, Ellipse, Polygon)
- Underline — Makes its text underlined.
