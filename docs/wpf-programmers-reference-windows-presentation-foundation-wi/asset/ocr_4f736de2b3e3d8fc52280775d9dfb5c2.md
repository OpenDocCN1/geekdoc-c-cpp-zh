```
<Setter Property="Fill" Value="Lime"/>
</Style>
<Style x:Key="isFocused" TargetType="Rectangle">
<Setter Property="Fill" Value="White"/>
</Style>
<Style x:Key="isPressed" TargetType="Rectangle">
<Setter Property="Fill" Value="Yellow"/>
</Style>
</ControlTemplate.Resources>

<!-- The controls that make up the Button. -->
<Grid Name="gradMain" ClipToBounds="True"
Width="TemplateBinding Width"
Height="TemplateBinding Height">
<Rectangle Name="rectMain">\n<ContentPresenter VerticalAlignment="Center" HorizontalAlignment="Center"/>
</Rectangle>
</Grid>

<!-- Behaviors. -->
<ControlTemplate.Triggers>
<Trigger Property="MouseOver" Value="True">
<Setter Target="rectMain" Property="Style"
Value="StaticResource isMouseOver"/>
</Trigger>
<Trigger Property="IsFocused" Value="True">
<Setter Target="rectMain" Property="Style"
Value="StaticResource isFocused"/>
</Trigger>
<Trigger Property="IsDefaulted" Value="True">
<Setter Target="rectMain" Property="Style"
Value="StaticResource isDefaulted"/>
</Trigger>
<Trigger Property="IsPressed" Value="True">
<Setter Target="rectMain" Property="Style"
Value="StaticResource isPressed"/>
</Trigger>
<Trigger Property="IsEnabled" Value="False">
<Setter Target="rectMain" Property="Style"
Value="StaticResource isDisabled"/>
</Trigger>
</ControlTemplate>
</ControlTemplate>
```

The code begins by defining Styles for the Button's different states: normal, defaulted, disabled, mouse, hover, and pressed.

The template creates the Button from a simple Rectangle.

The next, example includes a series of Triggers that handle the Button's different states. Each Trigger simply selects the appropriate Style.

Keeping all of the details in Styles makes the template easier to read than it would be if all of the property settings were contained directly in the Triggers. In this example, the property setting code is quite simple so the difference is small. In a more complex example that uses lots of decorative controls and animations, the difference can be significant.
