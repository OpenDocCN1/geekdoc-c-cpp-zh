The Style then sets the Stroke property to a brush that gives the opposite: It shades from light green to dark green. (This remarkably simple technique gives the Button an easy 3D appearance).

The "default" Style uses the same Fill property but makes the Stroke brush shade from dark green to black. (The difference is fairly subtle. You might want to experiment with larger changes, perhaps adding a completely black outline).

## Glass Button Triggers

The following code shows the Template's Triggers. In response to events and changes in the control-properties, the Triggers set new property values and apply the Styles.

```xml
<!-- MouseOver -->
<Trigger Property="IsMouseOver" Value="True">
  <Setter TargetName="grdMain" Property="Opacity" Value="0.75"/>
</Trigger>

<!-- Focus -->
<Trigger Property="IsFocused" Value="True">
  <Setter TargetName="grdMain" Property="Opacity" Value="0.75"/>
</Trigger>

<!-- Defaulted -->
<Trigger Property="IsDefaulted" Value="True">
  <Setter TargetName="rectMain" Property="Style" Value="StaticResource styDefault"/>
</Trigger>

<!-- Pressed. This comes last after Focus so it gets precedence. -->
<Trigger Property="IsPressed" Value="True">
  <Setter TargetName="grdMain" Property="Opacity" Value="1"/>
</Trigger>

<!-- Disabled. This comes last so it gets ultimate precedence. -->
<Trigger Property="IsEnabled" Value="False">
  <Setter TargetName="rectMain" Property="Style" Value="StaticResource styDisabled"/>
</Trigger>
```

When the control's IsMouseOver property is True, the first trigger sets the Grid's Opacity property to 0.75. This is more than the original value of 0.5, so the control becomes more solid.

When the control receives focus, the second trigger also sets the Grid's Opacity property to 0.75.

When the control's IsDefaulted property is True, the next trigger sets the Rectangle's Style to the "defaulted" Style.

When the IsPressed property is True, the following trigger sets the Grid's Opacity to 1, making fully opaque.

Finally, when the control's IsEnabled property is False, the last trigger sets the Rectangle's Style to the "disabled" Style. The Button control automatically stops interacting with the user, so you don't need to worry about that.

## IMPORTANT ORDER

Notice that the order of the template's triggers is important. Triggers that are defined later are applied later — if two triggers are active at the same time, the second overrides the first.

In this example, the IsPressed trigger must come after the MouseOver trigger. Otherwise, when the user pressed the Button, the IsPressed trigger would occur first. But at that point, since the mouse would be over the Button, the MouseOver trigger would also apply and override the IsPressed trigger so that the user would never see the Button look pressed.

Similarly the IsEnabled trigger comes last so it overrides all other triggers. If the button is disabled, it should never display any of the other appearances.

## ANIMATION ADVICE

Motion is one of the most attention-grabbing effects you can add to a program, but it can also be the most distracting and annoying. A button that flashes bright colors or continually changes size while the mouse is over would really annoy users. The moving highlight that the EllipseButton program displays is subtle so the effect isn't too bad, but careful. Keep animations like this one subtle or make them only once — for example, when the mouse first enters the button, so don't drive your users crazy. In extreme cases, rapidly flashing lights can induce seizures in some people particularly at frequencies between 2 and 55 Hz. Better still, give users a way to disable these sorts of animations. Also note that users with special needs such as color vision deficiency or impairment may not see subtle animations well or at all. Don't rely solely on subtle animations to give the user information.
