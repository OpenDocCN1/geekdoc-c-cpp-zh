Using resources simplifies the code by converting relatively complex property elements into simpler attribute elements. For example, the following code shows how you could define a similar Button without resources. This version is twice as long as the previous one. If the application contains several dozen Buttons, all the extra code would quickly add up and make the code more cluttered and harder to understand.

```
<Button Margin="4" Width="120">
<Button.Background>
<LinearGradientBrush StartPoint="0,0" EndPoint="0,1">
  <GradientStop Color="Red" Offset="0"/>
  <GradientStop Color="White" Offset="0.5"/>
  <GradientStop Color="Blue" Offset="1"/>
</LinearGradientBrush>
</Button.Background>
<DropShadowBitmapEffect/>
<TextBlock TextAlignment="Center" Margin="4">
Traveling-LineBreak/>salesperson/LineBreak/>
</TextBlock>
</Button>
```

The resources also allow you to easily change the appearance of all the buttons at once. For example, the XAML code defines resources with the same keys as before but with different values. When you make these changes to the Resources section of the code, the buttons immediately change their appearance.

```
<Window.Resources>
<RadialGradientBrush x:Key="brButton">
  <GradientStop Color="White" Offset="0"/>
  <GradientStop Color="Blue" Offset="1"/>
</RadialGradientBrush>
<BitmapEffectGroup x:Key="bmeButton">
  <BevelBitmapEffect/>
</BitmapEffectGroup>
</Window.Resources>
```
