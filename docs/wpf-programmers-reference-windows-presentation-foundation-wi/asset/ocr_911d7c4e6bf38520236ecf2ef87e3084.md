# BUILDING COMPLEX SCENES

Throughout this book, I've tried to use XAML code as much as possible. As inconsistent and confusing as XAML is, it hides some of the complexity of WPF programming and makes typical interfaces easier. The designers in Expression Blend and Visual Studio also let you instantly see any changes you make to XAML code so you don't have to run the program to see what you're seeing.

XAML code, however, will get you so far when you are building 3D scenes. XAML is just fine for simple scenes containing a dozen or so triangles that display cubes, tetrahedrons, and other objects with large polygons, but building anything complex in XAML can be difficult.

For example, the spheres shown in Figure 23-9 use 1,140 triangles. In principle you could define all of those triangles in XAML code by hand, in practice that would be extremely difficult and time-consuming. It would also be hard to debug the data if you found one of the triangles wasn't in exactly the right position or if it was randomly oriented. It's much easier to write a little code-behind to generate spheres and other objects that contain a lot of triangles.

The following sections explain how code can generate some particularly useful 3D objects.

# Geometric Shapes

At a low level, it makes sense to build out of triangles because they are simple, it's relatively easy to blend colors across them, and you can easily make complex shapes out of triangles. At a high level, you're more likely to think in terms of rectangles, spheres, cylinders, and other more complex shapes.

Building these out of triangles by hand can be time-consuming and tricky. Building a rectangle out of two triangles without missing the orientation and texture coordinates can be harder than you'd think.

To make complex scenes easier, it's helpful to have a library of code-behind routines that you can use to build these more complex shapes.
