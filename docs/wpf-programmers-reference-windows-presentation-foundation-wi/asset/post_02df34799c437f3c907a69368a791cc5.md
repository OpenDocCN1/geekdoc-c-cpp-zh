# WPF IN NUTSHELL

WPF has been around for a while now, but there are still plenty of people out there who don’t really know what it is. I’ve heard people claim it’s everything from a set of controls to XAML. In fact, a kernel of truth in each of these attitudes. WPF does include a new set of controls replacing the Windows Forms controls. The libraries you need to run WPF applications are installed by Vista and Windows 7, so it is sort of a thing although you can run WPF applications in Windows XP and certainly in future versions of WPF (and even today). WPF applications can use XAML to build interfaces, and XAML is all you really need to write web pages; but there's more to WPF than just XAML.

Again, the truth lies between these two extremes. You can abuse WPF to build completely unusable interfaces full of bouncing buttons, stretched labels, garish colors, and rotating three-dimensional (3D) graphics. You can add animation to the controls like a video game than a business application.

Figure 1-1 shows the Clutter example program displaying a series of rotated images as an invoice spins inside view. This program demonstrates some interesting techniques but goes overboard with gratuitous animation, displaying a spinning invoice area, animated buttons, and sound effects. If you think it's ugly in this book, you should see how annoying it is when you run it!

# ANIMATION OVERLOAD

Before you go overboard with animation, ask yourself, “Does this animation serve a purpose?” If the purpose is to hide a picture while showing it is going so the user can find it again—great. If the purpose is to be cool and make it fly out of a cabinet while growing, spinning, and changing opacity—think again. The first time, the user might think this is cool; by the second or third time, the user will find it annoying; and by the end of the day, the user will be seaisick.

It may not be true that all applications use WPF by the end of the year, but you should consider using WPF for new development. While getting the most out of WPF takes a lot of study and practice, it’s easy enough to use WPF instead of the corresponding Windows Forms controls in most cases. You may not stretch WPF to its limits, but you can take advantage of WPF’s new features without a lot of work.

Of course, some applications will probably never need WPF. Some programs run naturally as automatic services or from the command line and don’t need graphical user interfaces at all.

# What Is WPF?

So, what exactly is WPF? I’ve heard it described as a library, framework, subsystem, set of controls, language, and programming modeling.

Probably the easiest to understand WPF is to think of it as an assortment of objects that make it easier to build cool user interfaces. These objects include a new set of controls, replacing your favorite Windows Forms controls (such as Label, TextBox, Button, Slider) and others providing new features (such as Expander, FlowDocument, and ViewBox).
