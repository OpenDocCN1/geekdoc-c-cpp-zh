
## 408 | CHAPTER 24 SILVERLIGHT

Because Silverlight applications are intended to run in a user's browser

While there are some differences between WPF and Silverlight applications, the majority of what you know about applies to Silverlight. In particular, you can build a user interface with Expression Blend or Visual Studio using familiar controls. Silverlight does not provide all of the controls that WPF does, but it includes the basics such as Button, TextBox, StackPanel, Grid, and so on.

The middle part of Visual Studio shows a designer surface similar to those that you use to make a WPF application. The following code shows the XAML code that Visual Studio created for the new project's MainPage.xaml.

<UserControl x:Class="SelectColor.MainPage"

This code is the code used by a new WPF project except its top-level object is a UserControl instead of a Window. Both kinds of applications start with a Grid control the top-level object to hold any other controls you may add.

You can use the Toolbox to place controls on the design surface and use the Properties window to set properties just as you would in a WPF application. One of the main differences is that the WPF Toolbox holds more controls than the Silver Toolbox.

This example displays the color selection tool shown in Figure 24-4 running inside a Mozilla Firefox browser. When you change the ScrollBars' values, the program displays their new values in the TextBlocks to the right. It also uses those values as the red, green, and blue color components of a color and displays a sample of that in the Grid on the far right.

If you look at the TextBlocks on the right, they are bound to the corresponding ScrollBars so they automatically update to the selected values. The program's only remaining task is to display the color.

To create this event handler, select one of the ScrollBars, click the Properties button, and double-click the Scroll event. This opens the Code Editor for the Scroll event. The following code shows how the event works:

![](img/c9b2d394f4fc2f7e276f6a0a6fa9c2f6_448_0.png)

```csharp
// Update the sample.
private void scr_Scroll(object sender, System.Windows.Controls.EventArgs e)
{
    // Get the new color.
    Color clr = new Color();
    clr.R = (byte)scrRed.Value;
    clr.G = (byte)scrGreen.Value;
    clr.B = (byte)scrBlue.Value;
    clr.A = 255;

    // Apply the color.
    SolidColorBrush br = new SolidColorBrush(clr);
    scrSample.Background = br;
}
```

Available for download on Wix.

This code creates a new Color. It sets the values selected by the ScrollBars, converted into red, green, and blue components into byte values. It uses the Color's alpha component to 255 so the Color is completely opaque. The code finishes by creating a brush to display the color and setting the sample Grid's Background to that brush.

## A BOUNCING Ball

After you build the XAML and write the code-behind, simply press F5 or open the Debug menu and select "Start Debugging" to launch the application in your default browser.

The BouncingBalls example shown in Figure 24-5 uses a timer to display several balls bouncing around in the browser. This example demonstrates code that more closely ties Silver controls with code-behind.

![](img/c9b2d394f4fc2f7e276f6a0a6fa9c2f6_449_0.png)

FIGURE 24-5

The following XAML code shows how the program creates its controls. The program simply displays a Border containing a Canvas.

```
<UserControl x:Class="BouncingBalls.MainPage"
xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
xmlns:d="http://schemas.microsoft.com/expression/blend/2008"
xmlns:mc="http://schemas.microsoft.com/openxmlformats/org/markup-compatibility/2006"
mc:Ignorable="d"
d:DesignHeight="300" d:DesignWidth="400">

  <Grid x:Name="LayoutRoot">
  <Border BorderBrush="Green" BorderThickness="5">
  <Canvas x:Name="canField" Background="LightGreen" SizeChanged="canField_SizeChanged"/>
  </Border>
</Grid>
</UserControl>
```

There are only two interesting points to the XAML code. First, the Canvas has a name that the code-behind can refer to it. Second, the Canvas has a SizeChanged event handler.
