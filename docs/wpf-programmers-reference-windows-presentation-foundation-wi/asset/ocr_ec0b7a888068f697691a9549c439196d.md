> BETTER THAN PRINTING
If you select the Microsoft XPS Document Writer as your printer, the result is different from what you see coming out of a printer. The page is sized to fit the visual, and because the Document Writer can print all the way to the edges of its logical paper, the result isn't chopped off.

The PrintVisual method is extremely simple but doesn't produce a very nice result. It's chopped off at the top and left edges, and cannot rotate, scale, or center it.

The following section describes a much more flexible method of printing.

# Advanced Printing with PrintVisual

The PrintVisual method sends a PrintVisual object to the printer, but it doesn't scale, rotate, or center the object. Frankly, these are things that you program do.

Rather than passing the program into the PrintVisual method, you can make a hierarchy of controls that contains an image of the window. This hierarchy can use Grids, Viewboxes, Images, Rectangles, and any other control that you want to produce the results. It can even include extra controls to produce such items as a page header and footer.

The PrintVisual example program shows this approach to print its window centered at either normal or enlarged scale. Click on the "Print Centered" button to print the window at normal scale. Click on the "Print Stretched" button to print the window as large as possible on the page.

The PrintWindow program requires references to the ReachFramework and System.Printing libraries. In Visual Studio, open the project and select "Add Reference." Select these two libraries and click OK.

To make working with the libraries easier, the program includes the following using statements:

```
using System.Printing;
using System.Windows.Media.Effects;
```
