## XAML EDITOR

The XAML Editor lets you manually edit the window's XAML code. Usually it's easier to use the Window Designer to place controls on the window and let the designer generate the XAML for you, but there are occasions when you'll need to edit the XAML code directly. The Window Designer can't claim to do everything, and it does a poor job of doing others.

For example, the Window Designer will not create or apply styles, templates, storyboards, although if you enter them in the XAML code, it will use its best to honor them.

Sometimes it's easier to edit the XAML than to use the Window Designer. For example, setting exact row and column sizes in a Grid can be tricky in the Window Designer, but it's easy in XAML. Define some row and columns in the Grid, find the RowDefinition and ColumnDefinition elements, and set their Height and Width attributes.

For example, the following code gives a Grid two rows, one of height 30 pixels and one using all the remaining vertical space. It gives the Grid three columns of equal widths.

```
<Grid>
  <Grid.RowDefinitions>
    <RowDefinition Height="30" />
    <RowDefinition Height="*" />
  </Grid.RowDefinitions>
  <Grid.ColumnDefinitions>
    <ColumnDefinition Width="33*" />
    <ColumnDefinition Width="33*" />
    <ColumnDefinition Width="33*" />
  </Grid.ColumnDefinitions>
</Grid>
```

You could finely set the Grid's column widths in the Window Designer, but it would be tricky to make them exactly equal. The Window Designer also can set a row to a fixed value such as 30 pixels.

## COLORIZED CODE

The XAML Editor colorizes code to show its structure. If you don't mess with the default color settings, it displays angle brackets in blue, object names in brown, attribute names in red, and attribute values in blue. The colors make it a bit easier to pick out different parts of an object's definition such as the attribute values.

I recommend that you leave the colors alone as much as possible so your code looks like other developers' code (and the code in this book), but if you really need to change the colors (for example, if you have trouble telling the default colors apart) you can. Open the Tools menu and select Options. Expand the Environment folder and click the Fonts and Colors tab.

## TOOLBOX

The Toolbox holds controls that you can place on the window. Many of the controls, as Label and TextBox, are self-explanatory, and you should have little trouble figuring out how to use them. Many of the controls are also similar to Forms controls, so using them will be easy if you experience with Windows Forms controls. Chapters 5 through 8 describe individual controls in more detail.

To use the Toolbox, click on a control to select. Move to the Window Designer and click-and-drag to place an instance of the control on the window. You can also control the control and use handles to resize it.

If you [Ctrl]-click on a control in the Toolbox, then control remains selected after you click-and-drag to place an instance on the window. This lets you make several controls quickly and be useful, for example, if you need to make a forming of labels and controls.

Click on the Pointer tool to select any previously selected control (including if you [Ctrl]-clicked). One can then click on controls in the Window Designer to select them.

If you double-click on a control on the Toolbox, Visual Studio adds an instance of the control to the window at a default size and location. You can then drag it to position and resize it as needed.

The Toolbox contains tabs that group related controls. In Figure 2-2, the Controls tab is open to display all of the available controls. Figure 2-8 shows the Toolbox with the Common tab expanded. This tab contains only the most frequently used controls, which include (on my system at) Border, Button, CheckBox, ComboBox, Grid, Image, Label, ListBox, RadioButton, Rectangle, StackPanel, TabControl and TextBox.

## PROPERTIES WINDOW

The Properties window lets you view and edit the properties for the currently selected control in the Window Designer. Figure 2-10 shows the Properties window with a Grid control selected.

You can even set these properties to gradient brush but cannot set them to more complex objects as visual brushes.

To set more complex property values in Visual Studio, you need to type the brush's code in the XAML Editor. For example, the code fills a Rectangle with a VisualBrush:

```
<Rectangle>
  <Rectangle.Fill>
```
