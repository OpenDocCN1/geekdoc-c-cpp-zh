Not only does commanding make it easy for the code to handle an operation in a centralized place, the command object also provides a central point for enabling and disabling the controls that trigger it. For example, consider a copy command. If no text is selected that could be copied, then the command object can disable the [Ctrl]+C, context menu, Edit: Copy, and any other actions that trigger a copy.

WPF defines many command objects that you can bind to controls to define actions. Some even have a special relationship with other controls so they can automatically perform actions as you need. Finally, you may need to define new command objects to handle other actions that were not anticipated by WPF.

The following sections describe these three groups of command objects: those predefined by WPF that can take automatic action, those predefined by WPF that cannot take automatic action, and custom commands that you define in your code.

# PREDEFINED COMMANDS WITH ACTIONS

Some controls automatically implement command bindings for you. For example, the TextBox knows how to provide copy, paste, undo, and redo actions. If the program executes the predefined ApplicationCommands.Copy command while a TextBox has focus, then the TextBox copies its selection to the clipboard.

Furthermore, all you need is to tell the item or button that its command is ApplicationCommands.Copy, and the control will automatically trigger the appropriate action as needed. You don't need to write a single line of code-!

The TextBoxCommands example shown in Figure 19-2 demonstrates predefined commands that are supported by the TextBox control. Partly hidden by the program's Edit menu, a toolbar contains Copy, Cut, Paste, and Redo commands similar to those shown in the menu.

The Copy and Cut menu and toolbar buttons are disabled because the TextBox has (you can see the caret just after the word in the upper textbox) has no text selected so those commands don't make sense. The Paste command is enabled because there was text in the clipboard when screenshot was taken so you could paste it into the TextBox. The Undo and Redo commands are always enabled. (It would be better if command objects enabled and disabled themselves appropriately depending on whether the TextBox had changes that could be undo or redo but currently don't.)

The following code shows how your program generates it:

```
<Menu DockPanel.Dock="Top">
<MenuItem Header="Edit">
  <-- Menu items that invoke commands. -->
  <MenuItem Command="ApplicationCommands.Copy"/>
```
