# PROPERTIES, METHODS, AND EVENTS

In case you're not familiar with object-oriented terminology, all objects provide three kinds of features: properties, methods, and events.

A *property* is a value that determines the object's appearance or behavior. For example, a control's *Background* property determines how it is filled, and its *IsEnabled* property determines whether the user can interact with the control. In XAML code, you use attributes and object property syntax to set properties.

A *method* is a routine a control can execute to do something. For example, a *TextBox*'s *Clear* method does erase any text that it contains, and a *Window*'s *Close* method makes the Window itself close. XAML code cannot invoke an object's methods.

An *event* is something that a control raises to let you know something important has happened. Your program can catch and take appropriate action. For example, a *TextBox* raises a *TextChanged* event when it has changed, and a *Button* raises a *Click* event when it is clicked. XAML code can indicate that a particular code-behind routine should handle it. For example, the *Click* attribute at the end of the following XAML statement means the routine btnClear_Click should handle the Button's Click event.

```
<Button Name="btnClear" Content="Button" Click="btnClear_Click" />
```

Note that this book does not cover every control and object provided by WPF. WPF includes a huge number of objects, many of which you will not work with. For example, the ToolTip object to a TextBox control's ToolTip property:

```
<TextBox ToolTip="The customer's ZIP code." />
```

The following code does the same thing with a separate ToolTip object. Which do you think is easier?

```
<TextBox>
  <TextBox.ToolTip>
    <ToolTip>
      The customer's ZIP code.
    </ToolTip>
  </TextBox.ToolTip>
</TextBox>
```

Because the first method is easier, this book only covers objects like ToolTip used by the second method briefly or not at all.
