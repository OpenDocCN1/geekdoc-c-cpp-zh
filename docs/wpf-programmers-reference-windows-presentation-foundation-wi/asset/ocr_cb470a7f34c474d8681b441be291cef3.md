Up to point, this chapter has used only static resources. If WPF encounters a XAML file, it looks up the resource's value and assigns it to whatever property it is currently reading. Once the property value is set, WPF doesn't look again.

This is why the following code described in the section "Resource Hierarchies" earlier in this chapter doesn't work. The attribute Content="StaticResource String4" comes before the Label's resource, the resource isn't ready when the resource is needed.

```
<Label Content="StaticResource String4">
<Label.Resources>
  <sys x:Key="String4">
    String4 in Label.Resources.
  </sys>
</Label.Resources>
</Label>
```

A dynamic resource is similar to a static resource except it is not simply read when it is first encountered. Instead of setting the property's value right away, WPF waits and looks up the property's value when it is actually needed.

For example, the following code (using the DynamicLabelResource example program) works correctly. The code records the fact that the Content uses the resource value String4, but doesn't look up value until it is ready to render the Label. At that the resource exists.

```
<Label Content="DynamicResource String4">
<Label.Resources>
  <sys x:Key="String4">
    String4 in Label.Resources.
  </sys>
</Label.Resources>
```
