# A PROGRAMMING DIGRESSION

When you write a Windows Forms program with C# or Visual Basic, Visual Studio allows you to set control properties at design time, so your code only needs to deal with properties that change at run time.

For example, you can set a Label's font, colors, size, and position in the Form Designer at design time. Then at run time, the program's code might only need to change the Label's text. Visual Studio lets you ignore the other properties by hiding them in a separate designer-generated code module that you need to look for rarely if if ever.

In XAML, you cannot move the unchanging property definitions into the same way. If you need to set a Label's font, color, and position, then those properties are in the same file as the control's declaration. That can make the code cluttered and hard to read.

Styles let you move the unchanging properties out of the control's declaration, making it much easier to read the control's code and understand the program's structure. You can define the styles in a resource dictionary provided by a container, window, or at the application level depending on the scope you want to style.

Simplifying code is an important function of styles, so don't be afraid to use them to make the code simpler. Sometimes it's even worth creating a style that you will only use for a single control if it makes control's declaration easier to read.

# KEYS AND TARGET TYPES

The element's x:Key and TargetType attributes help identify when and where you can use a Style. There are at least three particularly interesting and useful ways in which you can use these attributes: non-specific target types, multiple target types, and unnamed styles.

# Non-Specific Target Types

The TargetType determines the level of control that you can use the Style. While you need to provide this information somehow, you do not necessarily need to be specific.

For example, since the Style's TargetType is set to Button, both buttons can use this Style:

```
<Style Key="OrangeButtonStyle" TargetType="Button">
  <Setter Property="Width" Value="150" />
  <Setter Property="Height" Value="40" />
</Style>
```

OrangeStyle

But if you want to use the style for Labels, you would need to create a second style. If you later change the style's properties, you would need to update both styles.

Another approach is to set the TargetType to a class that is ancestor of both controls. Button and Label both inherit from Control, so if you set the TargetType to Control, the style can apply to both.

The following code shows the new style, which includes the previous Setters plus ones for the Label's properties:

```
<Style Key="OrangeStyle" TargetType="Control">
  <Setter Property="Width" Value="150" />
  <Setter Property="Height" Value="40" />
  <Setter Property="Background" Value="Orange" />
  <Setter Property="Foreground" Value="Yellow" />
  <Setter Property="Margin" Value="5" />
</Style>
```

So far so good, but what if you want to specify values for a control that doesn't have them? For example, Label has BorderBrush and BorderThickness properties. Button doesn't have those properties, so you would need to add them to the style. Fortunately, a control ignores any properties it doesn't understand.

The following code shows the new style:

```
<Style Key="OrangeControlStyle" TargetType="Control">
  <Setter Property="Width" Value="150" />
  <Setter Property="Height" Value="40" />
  <Setter Property="Background" Value="Orange" />
  <Setter Property="Foreground" Value="Yellow" />
  <Setter Property="Margin" Value="5" />
  <Setter Property="BorderBrush" Value="Black" />
  <Setter Property="BorderThickness" Value="2" />
</Style>
```

```
<StackPanel VerticalAlignment="Center">
  <Button Style="{StaticResource OrangeButtonStyle}" Content="Button" />
  <Button Style="{StaticResource OrangeStyle}" Content="Button" />
  <Label Style="{StaticResource OrangeStyle}" Content="Label" />
</StackPanel>
```

# Multiple Target Types

The previous section explains how to build a style that can affect two control types (Button and Label) by setting the Style's TargetType to a class that is ancestor of both. (Button and Label both inherit from Control.)

But if you also want the style to affect rectangles: Button and Label have the Control class as a common ancestor, but Rectangle inherits from the Shape class instead of Control. If you climb a bit higher in the inheritance hierarchy, you'll find that Control and Shape both inherit from FrameworkElement, so you might think you're free. You could simply create a style with TargetType FrameworkElement and buildters as usual.

But, unfortunately, FrameworkElement doesn't support all of them. For example, if you try to change the Style's TargetType to FrameworkElement, Expression Blend flags errors on the Background, Foreground, BorderBrush, and BorderThickness properties.

The problem is that first common ancestor of Button, Label, and Rectangle doesn't support all of the properties you'd like to use. Fortunately, there is another way to specify the objects that provide the style's properties.

Instead of indicating the class with the Style element's TargetType attribute, indicate it in the Setter's Property attribute.
