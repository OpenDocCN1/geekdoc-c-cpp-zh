
# CHAPTER 6 LAYOUT CONTROLS

```xml
<Label.LayoutTransform>
<RotateTransform Angle="90"/>
</Label>
<Border>
<Border DockPanel.Dock="Bottom" Background="Yellow">
<Label Content="4, Bottom"/>
</Border>
<Border DockPanel.Dock="Bottom" Background="#FF80FFF">
<Label Content="5, Bottom"/>
</Border>
<Border Background="White">
<Label Content="6, None"/>
</Border>
</Border></DockPanel>
```

The DockPanel considers its first child. That control has Dock value Top, so the DockPanel attaches it to the top of its area.

Next the DockPanel considers its second child. That has Dock value Left, so the DockPanel attaches it to the left edge of the space that is not occupied by the first child.

The DockPanel continues positioning its children until it reaches the last one. If the control's LastChildFill property is True (which is by default), the control makes its final child fill the remaining space.

# SIZE SPECIFICATIONS

By default, the DockPanel tries to stretch its child controls so they cover the edges to which they are attached. For example, in Figure 6-2, it stretches the Border so it fills the DockPanel's entire width.

At the same time, the DockPanel lets the control try to grow to its natural size in the other dimension. The top Border in Figure 6-2 is about 37 pixels tall because that's how tall it wants to be.

You can override either of a child's dimensions by explicitly setting its Width and Height properties.

# GRID

The Grid arranges its children in rows and columns.

The Grid’s ColumnDefinitions property is a collection of ColumnDefinition objects that determine the widths of the Grid’s columns. Similarly, the Grid’s RowDefinitions property is a collection of RowDefinition objects that determine the heights of the Grid’s rows.

The ColumnDefinition and RowDefinition objects have properties that determine their sizes (Width for columns, Height for rows).

These Width and Height properties take absolute values or proportional values. To use an absolute number of pixels, you can simply use a number. For example, if a column’s Width property is set to 50, then column is 50 pixels wide.

You can include a unit indicator after a number to use a unit other than pixels. The following table lists the unit indicators that you can use:

| INDICATOR | MEANING | EQUIVALENT |
|---|---|---|
| px | pixels | 1 pixel |
| in | inches | 96 pixels |
| cm | centimeters | 96/2.54 * 37 pixels |
| pt | points | 1/72 inch |

To use a proportional width or height, assign the property a number followed by an asterisk (*). (The value * is equivalent to 1*) The Grid calculates the amount of space it has that is not used by absolute values and divides it among the rows or columns with proportional sizing, weighting them according their numeric values.

For example, the following XAML code defines a grid with three columns and two rows.

```xml
<Grid Margin="5">
  <Grid.ColumnDefinitions>
    <ColumnDefinition Width="0.75 in" />
    <ColumnDefinition Width="2*" />
    <ColumnDefinition Width="1*" />
  </Grid.ColumnDefinitions>
  <Grid.RowDefinitions>
    <RowDefinition Height="*30" />
    <RowDefinition Height="*2" />
  </Grid.RowDefinitions>
</Grid>
```

The first column has a width of 0.75 in = 72 pixels, so it takes up the leftmost 72 pixels in the Grid. The second and third columns' are set to 2* and 1*, so the second column is twice as wide as the last. In other words, the second column gets 2/(2+1) = 2/3 of the remaining width in the Grid, and the last column gets 1/(2+1) = 1/3 of the remaining width.

The first row has a height of 30 pixels. The second row has height set to *, so it gets all of the remaining height in the Grid.

By convention, developers set proportional values so that they add up to 100 or 1. That lets you think of these as percentages of the remaining space. For example, in the following XAML code, the first two columns each use 25 percent of the Grid's width and the third column uses the remaining 50 percent of the Grid's width.

```xml
<Grid Margin="5">
  <Grid.ColumnDefinitions>
    <ColumnDefinition Width="25*" />
    <ColumnDefinition Width="25*" />
    <ColumnDefinition Width="50*" />
  </Grid.ColumnDefinitions>
</Grid>
```

To let you place child controls in rows and columns, the Grid control defines Row and Column attached properties. For example, the following XAML code creates a Label and places it in row 0 column 2 of a Grid.

```xml
<Grid Row="0" Grid.Column="2" Content="Hello!"/>
```

The Grid also defines RowSpan and ColumnSpan attached properties, so you can make a child more than one row or column. For example, set RowSpan = 2 to make a child span 2 rows.

# SCROLLVIEWER

The ScrollViewer control displays a child inside a scrollable region. Its most important properties are HorizontalVisibility and VerticalVisibility. These take one of the following values:

- Auto — The scrollbar is displayed when needed and hidden otherwise.
- Visible — The scrollbar is displayed when it isn't.
- Disabled — The scrollbar does not appear even when it is needed. The child's size is set to the available size of the ScrollViewer. For example, a Grid may be resized to fit.
- Hidden — The scrollbar does not appear even when it is needed. The child keeps its original size if it sticks out the bounds of the ScrollViewer (where it is clipped).

Figure 6-5 illustrates the difference between the Disabled and Hidden values. The program contains a StackPanel holding two items. Each ScrollViewer holds a Grid with two equally sized rows and columns. The Grid's ShowGridLines properties are set to True.

![](img/cd394f4fc2f7e276f6a0a6fa9c2f6_144_1.png)

Since the upper ScrollViewer's HorizontalVisibility property is set to Disabled, the horizontal scrollbar isn't shown and the Grid is resized to fit within the ScrollViewer. The large buttons don't fit in the Grid so they are truncated.

The lower ScrollViewer's HorizontalVisibility property is set to Hidden. This time, since the Grid is not resized to fit within the ScrollViewer, it remains large enough to display its buttons. The first buttons fit in the ScrollViewer, but the second doesn't.

The ScrollViewer example program uses the following code to demonstrate the most typical use of the ScrollViewer: to let the user scroll over something too big to fit.

```xml
<ScrollView
  HorizontalScrollBarVisibility="Auto"
  VerticalScrollBarVisibility="Auto">
  <Image Source="ColoradoFlowers.jpg" Stretch="None"/>
</ScrollView>
```

# STACKPANEL

The StackPanel displays its children in a single row or column. If any children don't fit, they are clipped.

The most useful property of the StackPanel is Orientation, which can take the values Vertical (the default) or Horizontal.
