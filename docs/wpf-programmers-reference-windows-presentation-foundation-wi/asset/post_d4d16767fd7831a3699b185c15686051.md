Up to point, this chapter has used only static resources. If WPF encounters a XAML file, it looks up the resource's value and assigns it to whatever property it is currently reading. Once the property value is set, WPF doesn't look again.

This is why the following code described in the section "Resource Hierarchies" earlier in this chapter doesn't work. The attribute Content="StaticResource String4" comes before the Label's resource, the resource isn't ready when the resource is needed.

```xml
<Label Content="StaticResource String4">
<Label.Resources>
  <sys x:Key="String4">
    String4 in Label.Resources.
  </sys>
</Label.Resources>
</Label>
```

A dynamic resource is similar to a static resource except it is not simply read when it is first encountered. Instead of setting the property's value right away, WPF waits and looks up the property's value when it is actually needed.

For example, the following code (using the DynamicLabelResource example program) works correctly. The code records the fact that the Content uses the resource value String4, but doesn't look up value until it is ready to render the Label. At that the resource exists.

```xml
<Label Content="DynamicResource String4">
<Label.Resources>
  <sys x:Key="String4">
    String4 in Label.Resources.
  </sys>
</Label.Resources>
</Label>
```

Dynamic resources are a lot more work for WPF to implement than static resources; in general, therefore, it's better to use static resources when you can. In the previous example, you could probably use the String4 resource in the Label's container instead of the Label. Then you can use a static resource instead of a dynamic resource.

In addition to deferring lookup, WPF prepares dynamic resources so that it can detect changes to their values. For example, if the resource String in the previous example changed while the program was running, WPF would detect the change and update the Label to display the new value.

This ability to detect is most often used with system-defined resources such as system colors. If the user opens the system's configuration applications and changes the system colors, the program automatically reload any modified resources.

The SimpleClock example demonstrates two kinds of changing resources — resources changed by the program and changing system colors.
