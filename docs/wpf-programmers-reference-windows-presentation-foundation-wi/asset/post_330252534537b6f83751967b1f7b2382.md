
# MATERIALS

As previous sections have explained, the effect color given to a triangle in a scene depends on the light and the angle at which the light hits the triangle. The result also depends on the triangle's type of material. WPF provides three kinds of materials: diffuse, specular, and emissive.

A diffuse material's brightness depends on the angle at which light hits it, but the brightness does not depend on the angle at which you view it.

For example, hold a white sheet of paper so that it is perpendicular to the brightest light source nearby. If the light is bright, then when you move your head to look at the paper from different angles, it should appear roughly the same color (unless it's shiny paper, in which case it acts as a specular material—more than that of all). All the examples so far in this chapter have used diffuse materials.

A specular material is somewhat shiny. In that case, an object's brightness depends on how closely the angle between you, and the light sources match the object's mirror angle. The mirror angle is the angle at which most of the light would bounce off the object if it were perfectly shiny.

For example, suppose you have a perfectly shiny steel ball. If you looked closely, you would see a small image of the light reflected in the ball. The place where the reflection is the light's mirror angle points directly at you. On other parts of the ball, you will be off the mirror angle so you won't see the light's reflection.

If the ball is somewhat shiny, for example a billiard ball, then you'll see a bright patch where the mirror angle lines up. Areas near the mirror will be slightly less bright and areas far from the mirror angle will be the least bright.

The final type of material, an emissive material, glows. An emissive material glows only on itself. In other words, it makes its own brightness, but it doesn't contribute to the brightness of other objects as a light would.

Specular and emissive materials are not really intended to be used alone. Most of them are combined with a diffuse material in a MaterialGroup.

The example program shown in Figure 23-9 shows four spheres made of different materials. From left to right, they are diffuse, specular, emissive, and a MaterialGroup combining three types of materials.

Notice that the specular material adds a bright spot to the final and the emissive material makes the sphere brighter overall.

# BUILDING COMPLEX SCENES

Throughout this book, I've tried to use XAML code as much as possible. As inconsistent and confusing as XAML is, it hides some of the complexity of WPF programming and makes typical interfaces easier. The designers in Expression Blend and Visual Studio also let you instantly see any changes you make to XAML code so you don't have to run the program to see what you're seeing.

XAML code, however, will get you so far when you are building 3D scenes. XAML is just fine for simple scenes containing a dozen or so triangles that display cubes, tetrahedrons, and other objects with large polygons, but building anything complex in XAML can be difficult.

For example, the spheres shown in Figure 23-9 use 1,140 triangles. In principle you could define all of those triangles in XAML code by hand, in practice that would be extremely difficult and time-consuming. It would also be hard to debug the data if you found one of the triangles wasn't in exactly the right position or if it was randomly oriented. It's much easier to write a little code-behind to generate spheres and other objects that contain a lot of triangles.

The following sections explain how code can generate some particularly useful 3D objects.

# Geometric Shapes

At a low level, it makes sense to build out of triangles because they are simple, it's relatively easy to blend colors across them, and you can easily make complex shapes out of triangles. At a high level, you're more likely to think in terms of rectangles, spheres, cylinders, and other more complex shapes.

Building these out of triangles by hand can be time-consuming and tricky. Building a rectangle out of two triangles without missing the orientation and texture coordinates can be harder than you'd think.

To make complex scenes easier, it's helpful to have a library of routines you can use to build more complex shapes. The RectanglesAndBoxes program shown in Figure 23-10 demonstrates the routines that build the spheres.

The following code shows the program's MakeRectangle routine, which builds a rectangle:

```csharp
private void MakeRectangle(Model3D model, ref MeshGeometryD mesh, Material material,
    Point3D p1, Point3D p2, Point3D p3, Point3D p4,
    Point u1, Point u2, Point u3, Point u4)
{
    // Make the mesh if null.
    if (mesh == null)
    {
        mesh = new MeshGeometryD();
        Geometry3D new_model = new Geometry3D(mesh, material);
        model.Children.Add(new_model);
    }

    // Make the points.
    mesh.Positions.Add(p1);
    mesh.Positions.Add(p2);
    mesh.Positions.Add(p3);
    mesh.Positions.Add(p4);

    // Set the texture coordinates.
    mesh.TextureCoordinates.Add(u1);
    mesh.TextureCoordinates.Add(u2);
    mesh.TextureCoordinates.Add(u3);
    mesh.TextureCoordinates.Add(u4);

    // Make the triangles.
    int il = mesh.Positions.Count - 4;
    mesh.TriangleIndices.Add(il);
    mesh.TriangleIndices.Add(il + 1);
    mesh.TriangleIndices.Add(il + 2);

    mesh.TriangleIndices.Add(il);
    mesh.TriangleIndices.Add(il + 2);
    mesh.TriangleIndices.Add(il + 3);
}
```
