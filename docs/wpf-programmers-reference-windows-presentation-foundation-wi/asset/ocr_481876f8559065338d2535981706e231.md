# INTRODUCTION

For decades, good developers have separated UI construction from the code behind the user interface. Keeping the two separate makes it easier to distribute work among different developers and makes it easier to build each piece separately. WPF continues this philosophy by making the separation between the user interface and the code behind more distinct than ever.

In fact, Microsoft's original vision, specialized graphic designers built the user interface, and programmers added the code behind completely.

While many development projects cannot afford separate graphic designers and programmers, it's still worthwhile to keep these two tasks separate. This book squares addresses those who perform either of those tasks.

This book provides an introduction to WPF and does not require that you have any experience with it. In fact, it doesn't require you to have any previous programming or UI design experience.

> I dont want to receive a bunch of flaming e-mails complaining that some of the material is too basic, so I'm warning you right now! If you're mortally offended by introductory material, you're welcome to skip the first few chapters and move on the more advanced material.

Although this book does not require previous programming experience, it covers a lot of material and gets into some advanced topics. By the time you finish reading it, you should have learned a lot no matter experienced you are at the start.

# WHAT THIS BOOK COVERS (AND WHAT IT DOESN'T)

This book explains WPF development. It explains how to build user interfaces using Microsoft's Expression Blend tool, Visual Studio, and the XAML programming language. It also explains how to use Visual Studio to attach code to the interface.

WPF is a very flexible tool, and you can use it to make amazing user interfaces. Unfortunately, it is also often complicated, occasionally confusing, and sometimes daunting. You can use it to perform remarkable feats of UI sleek-of-hand, but doing so can be a heroic adventure in experimentation and browsing.

Such deeds of development fly in the face of Microsoft's that specialized graphic designers build user interfaces that programmers then attach to code. I'm having out with the wrong crowd, but the designers I've met did not have the skills or interest to spend time construct elaborate UI interfaces. Instead, they wanted to focus on the interface's appearance and usability.

This book's philosophy is that the user interface is a front end to the application, not the application itself. It should not take years of experience and a PhD in WPF to build a data entry form.
