# CUSTOM COMMANDS

WPF provides around 150 predefined commands, so in many cases, you can find an existing command object to suit your needs. There are classes for copy, cut, paste, zoom in, zoom out, print, help, and many other features that are common to many programs. Appendix K summarizes defined command classes.

Occasionally, you may want to define a command that isn't common in other programs and for which WPF does not define a command class. In that case, you can define your own command objects. You can take two basic approaches to defining new command objects.

First, you can build a class that implements the ICommand interface. This is not hard, but it's harder than the other approach so it isn't discussed here.

Second, you can make an instance of the RoutedCommand or RoutedUI class. These classes are mostly the same except the RoutedUI class has a Text property that the RoutedCommand class lacks. That makes RoutedUI a better choice if you want to display your command's text where as in buttons and menu items.

The basic steps for building a custom RoutedCommand object aren't too complicated, but understanding what's going on it can be tricky.

The command that you define must be shared (shared in Visual Basic) as all instances of the window will share the same instance of the command. Because all instances of the window share the same command object, you might wonder if object enables and disables all of the commands for every window, for example, if a single object determines whether the "Inverse Image" command is enabled or disabled for every window. That would be bad because it would mean different windows could not be in different states at the same time.

Fortunately that is not the case. The object that represents a command is shared between windows, the CanExecute and Executed routines are not. WPF queries each window decide whether it should allow its command to execute.

The ImageColors example program in Figure 1-5 demonstrates custom command objects. Note that the top window's commands are enabled, the bottom window's commands are disabled. Click on the New button to make a new window. Check the Enabled box to enable your commands.

Note that the program buttons and menu items display their accelerator keys (the underlined keys) and the menu items display their shortcut sequences (e.g., [Alt]+I for the Insert command). Also of that is explained shortly.

So what do you need to do to make a custom command object? First, declare the object as static. WPF won't need to set the value of the object, if you like declare it read-only. The following code shows how the ImageColors declares its Invert command object:

```
public readonly static RoutedUICommandImageInvert;
```
