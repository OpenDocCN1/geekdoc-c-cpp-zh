# BINDING COLLECTIONS

Some controls, as Button, TextBox, and Label, are considered content controls. They are intended to display piece of data as some text or a grid containing other controls.

Other controls, as ListBox, ComboBox, TreeView, are considered item controls. These display a repeating sequence of values stored in collections, arrays, trees, or other repetitive structures. The values can be simple things as numbers or strings, or can be more complex objects as instances of the Order or Employee classes.

Binding controls are relatively straightforward. Set the binding, target property, source, and path; and you're done.

# CHAPTER 18 DATA BINDING

Unfortunately, the situation is more complicated if you bind a ListBox to complex objects. To determine what to display for an item, the control calls the item's ToString method. For simple things like numbers and strings, ToString returns the item's textual representation.

For a more complex item like a Person object, ToString returns the name of the class. For example, in the PersonList example, the class's ToString method returns PersonList.Person for every item, a ListBox displays PersonList.Person for every item.

One way around this problem is to make the class override its ToString method to return something more useful.

The PersonList example program in Figure 18-9 displays ListBoxes items from two classes: Person and Person2. The Person class uses its ToString method, while the Person2 class overrides its ToString method.

The Person2 class uses the following to override its ToString method:

```
public override string ToString()
{
    return FirstName + " * " + LastName;
}
```

# CLASSES IN CODE

XAML code can define objects using the classes you have defined in your code-behind. To make this possible, first include a namespace declaration identifying your program's namespace like:

```
xmlns:local="clr-namespace:PersonList"
```

Now the XAML code can use the class as a data type. For example, the PersonList program uses the following code to map its array of Person objects:

```
<x:Array x:Key="people" Type="local:Person">
    <local:Person FirstName="James" LastName="Kirk"/>
    <local:Person FirstName="Spock"/>
</x:Array>
</Window.Resources>
```

Note that the class must have an empty constructor (one that takes no parameters) to be used by XAML code.

The overridden ToString method makes the results shown in a ListBox much more useful. ListBox can do more than display simple strings. It has ItemTemplates that you can use to determine how item is displayed.

The ListBox and ComboBox have an ItemTemplate property that determines how each item is displayed. These templates are described in Chapter 15.

The Planets example shown in Figure 18-10 displays an array of Planet objects in a ListBox on the left and a ComboBox on the right.

Planets

Most of this code uses Styles to define properties for the controls that will display the item's data. The StackPanel at the end contains those controls. The controls that actually display the data are:

- A TextBlock bound to the Planet item's Name
- An image bound to the Planet's Picture property
- A TextBox bound to the Planet's Stats property

In addition to the ItemTemplate property, the ListBox and ComboBox controls provide an ItemsPanel property that defines the panel control to lay out the items. By default, the ListBox and ComboBox use a vertically oriented StackPanel for their ItemsPanel so the items appear in a single column, but you can change this.

The Planets example program uses the following code to make its ListBox arrange items in a WrapPanel instead of a StackPanel:

```
<ListBox.ItemsPanel>
<ItemsPanelTemplate>
<WrapPanel Orientation="Horizontal" HorizontalAlignment="Stretch" />
</ItemsPanelTemplate>
</ListBox.ItemsPanel>
```
