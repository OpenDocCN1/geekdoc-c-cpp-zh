# NO STYLE

Suppose you have defined an unnamed style but don't want the style to apply to a particular control of type. Then you can control the Style to the special value (x:Null) to indicate that it should have no style. For example, the following code creates a Label that has no Style:

```xml
<Label Style="x:Null" Content="Test" />
```

# STYLE INHERITANCE

Resources you apply the same property values to multiple controls. Styles let you group resources into packages to make it even easier to give controls a common appearance.

Style inheritance lets you build one style based on another. That makes it easier still to give controls a common look and even if they don't share the same final styles.

The child inherits all of the Setters and other values defined by the parent style. You can then override some of those values if you like.

To make one style inherit from another, add a BasedOn attribute to its starting element, and set the attribute’s value to the parent Style. Note that the Style is an object defined in a resource dictionary, so you should set it with a StaticResource statement.

For example, the following code defines two brushes for Styles:

```xml
<LinearGradientBrush Key="GreenBrush" StartPoint="0,0" EndPoint="1,0">
  <GradientStop Color="Green" Offset="0"/>
  <GradientStop Color="Lime" Offset="0.3"/>
  <GradientStop Color="Transparent" Offset="0.8"/>
</LinearGradientBrush>
```

```xml
<LinearGradientBrush Key="BlueBrush" StartPoint="0,0" EndPoint="1,0">
  <GradientStop Color="Blue" Offset="0"/>
  <GradientStop Color="White" Offset="1"/>
</LinearGradientBrush>
```

```xml
<Style Key="SizeType" TargetType="FrameworkElement">
  <Setter Property="Width" Value="150"/>
  <Setter Property="Height" Value="30"/>
  <Setter Property="HorizontalAlignment" Value="Left"/>
  <Setter Property="VerticalAlignment" Value="Top"/>
  <Setter Property="Margin" Value="5"/>
</Style>
```

```xml
<Style TargetType="Rectangle" BasedOn="(StaticResource SizeStyle)">
  <Setter Property="Fill" Value="(StaticResource BlueBrush)"/>
  <Setter Property="RadiusX" Value="10"/>
  <Setter Property="RadiusY" Value="10"/>
</Style>

<Style TargetType="Label" BasedOn="(StaticResource SizeStyle)">
  <Setter Property="FontWeight" Value="Bold"/>
</Style>

<Style TargetType="Button" BasedOn="(StaticResource SizeStyle)">
  <Setter Property="Background" Value="(StaticResource GreenBrush)"/>
  <Setter Property="Margin" Value="2,5,5,5"/>
  <Setter Property="FontWeight" Value="Bold"/>
  <Setter Property="Width" Value="100"/>
</Style>
```

The code defines by a LinearGradientBrush named GreenBrush that fades from green to lime to transparent. It also creates a Brush named BlueBrush that fades from blue to white.

The next code defines an unnamed style for Rectangles. It is based on SizeStyle it sets size and alignment properties. The new Style adds values for the Rectangle properties Fill (using the BlueBrush resource), RadiusX, and RadiusY.

The snippet then defines an unnamed style for Labels. This style inherits the SizeStyle's size and alignment properties and adds a new FontWeight Setter.

Finally, the code defines an unnamed style for Buttons. This style sets the Background, Margin, and FontWeight properties. In this example, the unnamed Button overrides the Margin and Width values that it inherits from SizeStyle.

The InheritedStyles example shown in Figure 13-6 uses these styles to display Rectangles and Labels across the top of a Grid and Buttons. The Rectangles are too big to fit in their Grid cells, so their rounded edges are truncated on the top. The Buttons use the GreenBrush Background, so they fade from green to transparent, allowing the window's light green background to show through on their right edges.

# TRIGGERS

The styles described so far always apply their property values to their controls. If a style has a setter when the mouse was over it to provide some visual feedback to the user.

Styles can also define triggers, objects that allow setters only under certain conditions. For example, a trigger might change a Label's color.

WPF provides several kinds of triggers including property triggers, event triggers, and data triggers. This section describes property triggers. Event triggers are closely tied to animation, so they are described in Chapter 14. Data triggers aren't covered here, although they are closely related to data binding which is explained in Chapter 18.

A property trigger performs its action when a specific property has a certain value. For example, a property trigger could invoke one or more Setters if a TextBox's property had the value Test. (They are called property triggers because it's a property value triggers the action.)

When the property no longer has the triggering value, the Trigger deactivates and the original property value returns. For example, when the user moves the mouse off the Label, the Label returns to its original color, font, and size.

This ability to respond to changing properties at runtime gives the controls new behaviors that make an application feel more responsive to the user.

To make a property trigger, create a Style and give it a Style.Triggers property element. Inside the Style.Triggers section, you can add Trigger elements.

Use each Trigger's Property and Value attributes to indicate the property value that should activate the Trigger. Inside the Trigger element, whatever Setters you want the Trigger to execute.

> TRIGGER LOCATIONS

You must place property triggers inside Styles — not in a framework element's Triggers section. For example, you cannot place property triggers in a Window.Triggers or Grid.Triggers section. IntelliSense will pretend that this will work, but in fact, those sections can only hold event triggers (which are described in the next chapter).

Always put property triggers in a Style.
