To provide some separation between the XAML files and the code-behind, the program uses a separate-group of routines to do the real work. Event handlers catch the control events and call the routines

The following code shows how the blue skin defines its red switch skin on the left of the form's top:

```
<Grid
  xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
  xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
  Tag="Blue">

  Lots of code omitted

  <Ellipse Name="Skin" Width="10" Height="10"
           Canvas.Left="70" Canvas.Top="13"
           Cursor="Cross" Tooltip="Change Skin"
           Fill="HotPink" Stroke={StaticResource brRedStroke}
           StrokeThickness="2" Tag="Red.xaml" />

  Lots of code omitted
</Grid>
```

The code fragment starts with a Grid control as the root element. (You can use other controls for the file's root, but Grid is conveniently, because the Visual Studio WPF Window Designer understands how to display the skin if its root is a Grid.) The root element's Tag property is set to the name of it, in this case, Blue.

The code shown omits all of the other controls except its name, ellSkin, and its Tag, Red.xaml. The Tag property used to find which XAML file to load when the circle is clicked.

Ignoring for how this is controlled up to its event handler, the following code shows the event handler that the control executes. Since this event is shared by this control and the red skin's "change skin" polygon (the triangle in the upper-left corner), it's called pSkin.MouseDown.

```
private void MouseDown(object sender, MouseEventArgs e)
{
  FrameworkElement element = (FrameworkElement)sender;
  LoadSkin(element.Tag.ToString());
}
```

This code gets the element that triggered the event (either the blue skin's Ellipse or the red skin's Polygon), reads that element's Tag property to see which XAML file to load, and passes the file-name to the function LoadSkin.
