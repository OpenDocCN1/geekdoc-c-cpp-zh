# ToolTip

The ToolTip displays a tooltip for another object. Figure 5-13 shows a program displaying tooltip for the "First Name" textbox that is sitting under the mouse.

While you can give a control tooltip by building a ToolTip object, it is easier to simply set the control's ToolTip property as shown in the following:

```xml
<TextBox Margin="80,10,12,0" VerticalAlignment="Top"
Text="Prop" Tool="The customer's first name
Name="txtFirstName" Height="21.96" />
```

# SPATIAL CONTROLS

The spatial controls have an important spatial component. Some, such as BulletDecorator and GroupBox, provide spatial arrangement and decoration for other controls. Others, as ListView and ListView, use spatial positioning to show relationships among objects.

# Border

The Border controls a border or background. It's a spatial control in the sense that it creates a space to hold its child. While that may seem like a minor accomplishment, creating separate areas on a window can be very useful for defining groups of controls. For example, if a window contains many radio buttons or checkboxes, grouping them with Borders can make the window easier to read and understand.

The control can have only a small child, but that can be a container such as a Grid StackPanel, so this isn't really much of a restriction.

The following table summarizes the Border's most useful properties:

| PROPERTY | PURPOSE |
| --- | --- |
| Background | The control's background brush |
| BorderBrush | The brush used to draw the Border's edges |
| BorderThickness | Determines the thicknesses of the Border's edges. If this is a single value, all four edges use the same thickness |
| CornerRadius | Determines the radii of curvature for the Border's rounded corners. If this is a single value, then all corners use the same radius. This defaults to 0 for square corners. |

The following XAML code creates the Border shown in Figure 5-14:

```xml
<Border HorizontalAlignment="Center" VerticalAlignment="Center"
  Width="150" Height="100"
  BorderBrush="#FFFF0000" BorderThickness="5">
  <Border.Effect>
    <DropShadowBitmapEffect/>
  </Border.Effect>
  <Border.Background>
    <LinearGradientBrush EndPoint="0.5,0.1" StartPoint="0.5,0.0">
      <GradientStop Color="#FFFF00FF" Offset="0" />
      <GradientStop Color="#FF0000FF" Offset="1" />
    </LinearGradientBrush>
  </Border.Background>
  <TextBlock Width="100" Height="50" FontWeight="Bold"
    TextWrapping="Wrap" TextAlignment="Center"
    Text="This TextBlock is contained inside the Border."/>
</Border>
```

# BulletDecorator

The BulletDecorator displays an item and bullet in bulleted list. The control can have only a single child (other than the bullet), but that can be a container such as a Grid or StackPanel, so this isn't really of a restriction.

The BulletDecorator's most important property is Bullet, which should contain the object to be used as the item's bullet. Normally this should be something that looks like a bullet such as a small image or character, but in theory it can be something else like a label or border.

The following XAML code creates the first item in the bulleted list shown in Figure 5-15. The three BulletDecorator controls are contained in a StackPanel to make the list.

![](img/c9b2d394f4fc2f7e276f6a0a6fa9c2f6_128_0.png)

```xml
<BulletDecorator>
  <BulletDecorator.Bullet>
    <Image Width="20" Height="20"
      Source="Bullet.bmp" Stretch="None"
      HorizontalAlignment="Left" VerticalAlignment="Center">
      <Image.BitmapEffect>
        <GroupShadowBitmapEffect/>
      </Image.BitmapEffect>
    </Image>
  </BulletDecorator.Bullet>
  <Label Content="Choice 1" Foreground="Red"/>
</BulletDecorator>
```

# GroupBox

A GroupBox displays a header and a border around a single child. Like the Border, the GroupBox is useful for creating distinct areas in a window.

The GroupBox's Foreground property determines the brush used to draw the header text, with its BorderBrush property determines the brush used to draw the border. The Background property determines the GroupBox is filled.

| BROKEN BORDERS |
| --- |
| For some reason, the GroupBox's border is partially obscured if the control's BorderThickness property is larger than 2. |
| Note also that you can hide the border by setting BorderThickness = 0. |

# ListView

The ListView displays a set of data items in several layouts. We can define new custom layouts for the control, but perhaps the most common standard layout is the grid-like view shown in Figure 5-17.

![](img/c9b2d394f4fc2f7e276f6a0a6fa9c2f6_129_1.png)

Figure 5-17

Displaying a set of data in a grid with resizable columns may sometimes be useful, the real power of the ListView is its ability to display data from a source such as a database or a list of objects. Data binding is covered in greater detail in Chapter 18; this section covers only a few so you can see how ListView works.

The C# code shows how UseListView defines its BookInfo class. The class's constructor simply initializes the new object's fields: Author, Title, Year, and Price. Since all are implemented in a very similar way, only the code for the Author property is shown here.

```csharp
public class BookInfo
{
    // Initialize a new object's fields.
    public BookInfo(string new_Author, string new_Title,
        string new_Year, string new_Price)
    {
        Author = new_Author;
        Title = new_Title;
        Year = new_Year;
        Price = new_Price;
    }

    private String m_Author;
    public string Author
    {
        get { return m_Author; }
        set { m_Author = value; }
    }
    // Code for the other properties omitted
}
```

![](img/c9b2d394f4fc2f7e276f6a0a6fa9c2f6_130_0.png)

When the program starts, it uses the following code to create an ObservableCollection of BookInfo contains the data that should be displayed. Then the sets the ListView control's DataContext property to the collection so the control has access to all of the data.

```csharp
// Create a list of Books
ObservableCollection<BookInfo> books = new ObservableCollection<BookInfo>();
books.Add(new BookInfo("Daniel Pinkwater", "5 Novels", "3.56"));
books.Add(new BookInfo("Glen Cook", "Garret Files", "2007", "6.99"));
books.Add(new BookInfo("Simon R. Green", "The Man With The Golden Core", "2008", "7.99"));
books.Add(new BookInfo("Tad Williams", "The Name of the Flowers", "2004", "8.99"));
books.Add(new BookInfo("Tom Holt", "You Don't Have to Ever Work Here, but it Helps", "2007", "10.00"));

// Set the ListView's data context to this list
lvbooks.DataContext = books;
```

![](img/c9b2d394f4fc2f7e276f6a0a6fa9c2f6_130_1.png)

In addition to assigning properties such as Name and Background to the ListView, the XAML code must tell what pieces of data to display. The following XAML code creates the ListView shown in Figure 5-7:

```xml
<ListView Name="lvwPeople"
Background="x:Null"
ItemsSource="{Binding}">
    <Grid>
        <GridColumn Header="Author" Width="100"
        DisplayMemberBinding="{Binding Path=Author}"/>
        <GridColumn Header="Title" Width="300">
```
