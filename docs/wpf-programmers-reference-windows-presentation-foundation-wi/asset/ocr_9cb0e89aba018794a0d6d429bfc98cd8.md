# Visual Tree

The second WPF tree is the visual tree. The visual tree represents the structure of visual objects including the components that define them. For example, a scrollbar includes a draggable thumb, two arrows at the ends, and two clickable areas between the thumb and the arrows. Each of those pieces is a separate object that is wrapped inside a scrollbar, and each of the pieces is part of the visual tree.

Why should you care about the logical and visual trees? First, controls need to inherit properties according to their positions in the logical tree. For example, the preceding XAML code the following attributes to set the main FontSize, FontWeight, and FontFamily properties.

```
FontSize="22" FontWeight="Bold" FontFamily="Comic Sans MS"
```

These properties are inherited through the logical tree so the Labels at the bottom of the tree will all use these fonts.

The second reason we care about these trees is that events tend to follow the visual tree. For example, when you click on an arrow in a scrollbar, you don't really want to have to deal with the arrow's events. Instead you let the event propagate up the visual tree to the scrollbar, and you can catch it anywhere.

# Non-Treelike Structure

Because the controls that make a user interface such as this one naturally form a containment hierarchy, they map fairly into XML. Unfortunately some of the things that make up an interface don't fit quite nicely in a tree structure.

For example, Figure 1-5 shows a more complicated version of the previous user interface.

In this version, all of the Image controls have drop shadows. You could give each Image its drop shadow, but that would mean duplicating code, which would make maintaining the program harder. For example, if you later decided to remove the drop shadows or use some other effect (perhaps to put a glow around the images), you would have to update each control separately.

Rather than repeating the drop shadow code, you could define a Style and apply it to each Image. Now to change each Image, you only need to change the Style.

Similarly, this example defines a style for its Label controls that give them drop shadows, makes them yellow, and changes their text.
