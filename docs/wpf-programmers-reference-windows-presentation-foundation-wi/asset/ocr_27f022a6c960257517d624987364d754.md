# A NEW TAKE ON OLD CONTROLS

Some of these controls have been around in other forms for a while. For example, the FlowLayoutPanel does roughly what the new WrapPanel does and the old TableLayoutPanel has a similar purpose to the Grid, although it's not flexible.

Some have claimed that these arranging controls should change the way you design interfaces by allowing you to take best advantage of whatever space is available on the form. Good developers have already been using Windows Forms controls such as FlowLayoutPanel and properties such as Anchor to do this, so it's not a revolutionary new concept, although the new controls do give you some new options.

One new control that deserves special mention is FlowDocument. A FlowDocument is a flexible document object that can hold content like a web page. It can hold text in various styles grouped by paragraphs. It can hold tables, lists, and images. It can hold figures and floaters around the text flows. A FlowDocument can hold WPF controls such as Buttons, TextBoxes, and 3D drawings. It can even run WPF animations in the figures in the document.

WPF comes with three controls for viewing FlowDocuments:

+   * FlowDocumentScrollViewer displays a FlowDocument in a long vertically scrolling page much like a web browser displays pages.
* FlowDocumentPageView displays one page at a time. It provides scrolling and zooming features that the user can see the whole document.
* FlowDocumentReader can display the content in one of three ways: like the FlowDocumentScrollViewer, like a FlowDocumentPageView, or in a two-page mode that shows the document side-by-side pages at a time.

# Declarative Programming

Many developers consider declarative programming as a benefit of using XAML. Intuitively this makes some sense. If the user interface sits there, it is reasonable that the code that implements it should be declarative and sit there, too.

Of course, WPF user interfaces do more than just sitting there. Once you start adding triggers, storyboards, templates, and styles, the interface is doing much more than just sitting. In some cases, an interface built in XAML alone is much harder to understand than one that uses a little code at key points.

Declarative programming is a nice feature of XAML, but it's not clear that it is benefit in itself.
