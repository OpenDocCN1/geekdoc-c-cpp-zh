```
class int_holder {
public:
    void increment() const { ++ *m_i; }

private:
    std::unique_ptr<int> m_i;
};
```

This surprises typical users, because they expect to be unable to change the std::unique_ptr object and what it contains. In fact, const extends only as far as the std::unique_ptr object. Dereferencing the object is a const operation since it makes no change to the std::unique_ptr. This highlights the importance of recognizing the difference between a const pointer and a pointer to const. A pointer to const can be modified but the object it points to cannot. A const pointer cannot be modified but the object it points to can. This is somewhat similar to how references behave: they cannot be reseated, which means they cannot refer to a different object through their lifetime, but the object they refer to can be modified.

> *mutable should not be scattered liberally through your class. It should decorate the data that is used for bookkeeping, rather than for modeling the abstraction.*
