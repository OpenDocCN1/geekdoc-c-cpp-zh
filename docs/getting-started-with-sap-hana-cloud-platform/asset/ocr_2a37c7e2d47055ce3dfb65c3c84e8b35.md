5. Assuming the user decides to provide the client with access, the authorization server will invoke a callback service on the client, providing a temporary authorization code. The client will then exchange this authorization code for a more permanent access token.

6. Finally, with the access token in hand, the client application can begin accessing the target resources on the resource server by simply passing the access token in an HTTP request header. The resource server will use this token to perform the necessary authentication and authorization checks to access the resources.
