# Understanding the JPA's Use of Convention over Configuration

As you can imagine, the mapping process can become quite tedious whenever you're dealing with complex database schemas containing many entities. Fortunately, the JPA has some built-in intelligence that allows you to skip over the mapping step in many cases. For example, if you look closely at the Address entity in Listing 6.2, you'll notice that there are no annotations attached to the street and city attributes. By omitting these details, we're effectively telling the JPA persistence provider that these attributes match up with table columns having the same name and data type. For newly developed database schemas, you can even go so far as to let the JPA persistence provider create the underlying database tables for you in reference to the mapped entities. This is a classic example of how the JPA uses the "convention over configuration" technique to minimize development time.
