You could have the setName and setEmail: methods store the objects directly in their respective instance variables with method definitions like these:

```
- (void) setName: (NSString *) theName
{
    name = theName;
}
```

```
- (void) setEmail: (NSString *) theEmail
{
    email = theEmail;
}
```

The AddressCard object would not own its member objects (it would only contain references to the arguments passed into the methods). We talked about the motivation for an object to take ownership with respect to the Rectangle class owning its origin object in Chapter 8, "Inheritance."
