Several points are worth noting about Program 6.10. The outermost for statement sets up a loop to cycle through integers 2–50. The loop variable p represents the value you are currently testing to see whether it is prime. The first statement in the loop assigns the value 1 to the variable isPrime. The use of this variable will become apparent shortly.

A second loop is set to divide p by the integers 2 through p-1. Inside the loop, a test is performed to see whether the remainder of p divided by d is 0. If it is, you know that p cannot be prime because an integer other than 1 and itself divides it. To signal that p is no longer a candidate as a prime number, the value of the variable isPrime is set equal to 0.

When the innermost loop finishes execution, the value of isPrime is tested. If its value is not equal to zero, no integer was found that evenly divided p; therefore, p must be a prime number, and its value is displayed.

You might have noticed that the variable isPrime takes either 0 or 1, and no other values. Its value is 1 as long as p still qualifies as a prime number. But as a single even divisor is found, its value is set to 0 to indicate that p no longer satisfies the criteria for being prime. Variables used in such a manner are generally referred to as Boolean variables. A flag typically assumes only one of two different values. Furthermore, the value of a flag is usually tested at least once in the program to see whether it is (true or YES) or off (false or NO), and some particular action is taken based on the results of the test.

In Objective-C, the notion of a flag being true or false is most naturally translated into the values 1 and 0, respectively.
