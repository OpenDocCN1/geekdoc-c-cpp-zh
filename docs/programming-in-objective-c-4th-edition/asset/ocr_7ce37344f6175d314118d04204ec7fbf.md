# Note

On your system, your output will differ from that shown.

Let's take a closer look at the following code sequence:

```
dirEnum = [fm enumeratorPath: path];

NSLog (@"Contents of %", path);
while ((path = [dirEnum nextObject]) != nil)
NSLog (@"%@", path);
```

You begin enumeration of a directory by sending an message to a file manager object, in this case fm. An NSDEnumerator object gets returned by the enumeratorPath: method, which is stored inside dirEnum. Now, each time you send a nextObject message to this object, you get returned a path to the next file in the directory you are enumerating. When no more files are left to enumerate, you get nil returned.

You can see the difference between the two enumeration techniques from Program 16.4. The enumeratorPath: method lists the contents of the newdir directory, whereas contentsOfDirectoryAtPath:error: does not. If newdir contained subdirectories, they would have been enumerated by enumeratorPath:.
