autoreleased objects. You do that in your application with a
statement like this:

```
NSAutoreleasePool * pool = [[NSAutoreleasePool
alloc] init];
```

Xcode generates a template with this statement at the start of
main if you create a new project without ARC enabled.

As noted, after the pool is set up, framework methods automatically
add new objects such as arrays, strings, dictionaries, views, buttons,
and other objects to the list maintained by the autorelease pool.

When you're using the pool, you send it a drain message:

```
[pool drain];
```

This has the effect of sending a release message to every object
that was sent an autorelease message and therefore added to
the pool. And as you know, if any of those objects ends up getting
ference counts decremented to zero, those objects will be
sent a dealloc message and their memory released.

Note that the autorelease pool doesn't contain the actual objects
themselves, only a reference to the objects that are to be released
when the pool is drained.

Not all newly objects are added to the autorelease pool.
fact, any object created by a method whose name starts with the
word alloc, copy, mutableCopy, or new is one that is not
autoreleased. In such a case, you are said to own that object. When
y own an object, you become responsible for releasing the
memory taken up by that object when you're doing it. This is
done by sending the object a release message. Or you can add it
to the autorelease pool yourself by sending it an autorelease
message.
