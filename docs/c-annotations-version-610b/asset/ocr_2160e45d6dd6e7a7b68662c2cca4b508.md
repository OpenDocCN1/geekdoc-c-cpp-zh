What about changing fields? Once an unrestricted union has received its value it keeps that variant until used otherwise. That’s in line with the traditional union. But to change the interpretation of an unrestricted union’s class-type field we must make sure that the destructor of that class type field is first called. To do that smoothly we need operator~.

Once again we encounter a complication: unrestricted unions don’t even have a default copy constructor. That’s again understandable: which field should be initialized by the copy constructor?
