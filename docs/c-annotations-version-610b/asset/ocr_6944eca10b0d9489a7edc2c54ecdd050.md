# 23.9.3  Using polymorphic semantic values with Bisonc++

Bisonc++ may use polymorphic semantic values. How this is realized is covered in this section. The described method is a direct result of a suggestion initially brought forward by Dallas A. Clement in September 2007.

One may wonder why unions are still used by Bisonc++, as C++ offers inherently superior constructs to combine multiple types into one type. The support by C++11 for unrestricted unions may result in unions being re-evaluated, but C++ traditionally offers a good alternative for the use of unions: a polymorphic base class and a series of derived classes implementing the alternative data types.

Below, a polymorphic base class (the class Base) is developed. As it is a polymorphic base class it has the following characteristics:

+   - Its destructor is virtual (and has a default implementation);
+   - Objects of the derived classes may be obtained from a pure virtual `ownClone` member implementing a so-called *virtual constructor* (cf. the *virtual constructor* design pattern, *Gamma et al.* (1995));
+   - To obtain a clone of the current (derived class) object, the interface function `clone` must be called. It calls `ownClone` and forms a layer between the derived class implementations of `ownClone` and the user-software. Right now it only calls `ownClone`, but by not defining it as an inline function `clone` can easily be extended once that is required;
+   - Several convenient utility members are defined: a pure virtual `insert` member and an overloaded `operator<<` to allow derived objects to be inserted into `ostream` objects.
