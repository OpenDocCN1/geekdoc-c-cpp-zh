SVseq1 maps the split reads efficiently. Note that BWA can also use local alignment to map one split segment of a split read near the anchor (the other split segment is not mapped and is soft-clipped). Both split segments have to be mapped to call deletions.

The breakpoint of a split read is not clear until ways of splitting the read are examined and a naive way for this purpose is breaking the read into two portions, take each portion as a new read and run a read mapping, such as BWA, $2(n-2m+1)$ times, where $n$ is the length of the read and $m$ is the minimum allowed length of a split segment. The algorithm of SVseq1 only runs the BWA mapping two times for this split read away. We omit the mapping step. Refer to (20) for more details. When the pairs of split segments of a split read are mapped, the breakpoints of one pair correspond to the breakpoint of a potential deletion. Because split read mapping can suffer from noise, repeats and artifacts, FP singleton can be very common. It is not easy to separate many of the TPs even if other information is available. Deletions revealed by split reads become candidate deletions only if they are supported by a set of split reads. When working with population sequence reads, a candidate can be supported by split reads from different individuals. Since singleton split reads may be unreliable, SVseq1 a cutoff of C as the minimum number of split reads need to call deletions. C can be as 2 or 3, even higher values may have higher accuracy but reduce sensitivity when sequence coverage is low.

Since candidate deletions found in the first step are bound to contain many false positives, they have to be further examined before they be put in the final list of candidate deletions. The second step of SVseq1 uses paired-end reads encompassing candidate deletion list got from the first step. A paired-end read encompassing a candidate deletion if its two ends are mapped to different sides of the candidate on the reference genome. The insert size of each encompassing paired-end read is examined to test whether it supports the candidate. When there is a deletion, an read is mapped to the reference genome with insert size extended by the length of the deletion. If discordant insert size and the length of the candidate deletion match with each other, then it is a strong signal that indicates the candidate is a true deletion. Note that the difference between insert size and the length of the candidate deletion is not significantly different from the library insert size. If the insert size of a pair means the length of the candidate deletion is within three standard deviations of library insert size, we say the pair supports the candidate deletion. When a candidate deletion is supported by at least one encompassing paired-end read, a candidate deletion is reported in the final list. Note that the insert size of an encompassing read is not necessarily discordant, especially for deletions that is not very long. In this sense, the signature of read pair used is not exactly the same as the signature introduced in Section 8.2.1, when only one signature is considered. It is the combined signature of split read and pair that is strong enough to call a candidate deletion, while the single signatures may be weak in this purpose.
