## 12.5 COMPARISON

The trimmed simulated RNA-seq data sets were assembled by two reference-based assemblers Tophat2 (10) and SpliceMap (36) and two novo assemblers SOAPdenovo-Trans (37) and Trinity (38). Using Bowtie2, the first 500,000 reads from each data set were mapped onto the hg19 refSeq transcripts that were downloaded from Ensembl.org at ftp://ftp.ensembl.org/pub/release-73 to determine the main pair index reference for each data set. This calculation is in terms of properly tuning reference algorithms and is specific to each analysis as the value generated is dependent on both the cDNA fragments used to prepare the sequencing library and the length of the sequence reads (see Figure 12.1a). The output, an aligned BAM file, was sorted by the SortSam module from SamTools (41). Like the fastq sequence, the SAM/BAM formats have been developed for specifically describing the alignments of fastq reads to reference used using second-generation sequencing (11). SAM (sequence alignment/map) is a text description of an alignment to reference, while BAM is the compressed, version of a SAM file, often more manageable than the sheer size of the data sets that resulted from alignments. Most of the used tools to manipulate and analyze these sequence data recognize one or the other of these formats. The CollectInsertSizeMetrics tool from the picard package (42) was used to find the main pair inner distance and deviation for each data set. For each simulated data set, Tophat2 ran with default settings except for the following parameters (inner pair distance, deviation, GTF file from hg19), which were set as appropriate for each data set. Reads were mapped onto the reference and assembled and possible splits between neighboring regions were determined. The unmapped reads are then fragmented and aligned onto the reference and split junctions. A very good tutorial describing the detailed use of Tophat and Cufflinks for RNA-seq analysis is available (43). For the specific case of detecting novel fusion transcripts, a version of Tophat called Top-fusion has been developed (43).

SpliceMap uses a split-read algorithm. Reads that are less than 50 bp were split into overlapping 25 bp-halves while reads are split into overlapping 50 bp reads. These halves were aligned to the reference gene with either Bowtie or BWA (44). These alignments are combined to determine the exons or split junctions. SpliceMap uses an algorithm somewhat similar to Tophat, but generates its analysis without the use of a GTF file describing the transcripts. Each of the five data sets were assembled by Tophat2 and SpliceMap on a cluster computer with over 18 parallel threads. Thread creates an aligned BAM file, and the SpliceMap creates an aligned SAM file. Cufflinks, which provides quantification of RNA-seq from the assembled or aligned BAM file, was the BAM/SAM files of our both Tophat and SpliceMap outputs to generate FPKM tracking files (Fragments Per Kilo base of exons Per Million reads) value is one of several means developed to normalize relative transcript abundance in RNA-seq analyses, taking into account that transcript size varies considerably in many organisms. We have used Cufflinks

with the following options (-G hg19_ref_canonical.gtf -b hg19canonical.fa -u -compatible-hits-norm) for estimating isoform using the given gtf file (-G option), for improving the estimates of transcript abundance (-b option) and multiple read correction (-u option), and for appropriate compatibility. Identical parameters for Cufflinks were originally designed as a tool for the downstream assembly of the output of the Tophat assembler can be used with the output of other algorithms.

Trinity (38) and SOAPdenovo-Trans (37) were used to generate de novo RNA-seq transcriptomes from our simulated data sets. Both are de Bruijn graph-base, de novo transcript assembly algorithms (45). SOAPdenovo-Trans allows testing of k-mer values, with a fixed value of 25. Each was designed with the goal of the assembly of transcripts and quantitation of their transcript abundance. Both attempt to resolve transcripts by resolving de Bruijn subgraphs that potentially contain multiple isoforms. SOAPdenovo-Trans performs transcript quantification as an option, the output of can be used as an algorithm designed for transcript quantification, such as RSEM (46), edgeR (47), or DESeq (48).

The sets of simulated and trimmed paired-reads were analyzed with programs using default values except the option to calculate FPKM values for the SOAPdenovo-Trans analyses. The Trinity assemblies were then analyzed with RSEM for the determination of FPKM values of the assemblies. Assemblies from both programs were then annotated to hg19 using cmap (49). Trinity is a very memory-intensive program, in this study run over 6 hours or an hour. For speeding up Trinity with large data sets, it is very common to increase the memory allocated to the program (or to one or more of the running programs comprising Trinity, inch, chrysalis, and butterfly) by running analyses using multiple processors, all of which can be controlled using command flags. It is also common with large data sets to do in silico normalization step to reduce the run-time. There is a very active listserv discusses current issues in Trinity assemblies (50) and a very detailed tutorial available (51).

For the transcriptome output of all de novo assemblies, when the aligned length of contig spans through the length of a known transcript, we consider a perfect match; otherwise it will be considered a fractional match. We considered 10%, 50%, and 90% fractional matches in annotating contigs to refSeq transcripts.

## 12.6 RESULTS

Different paired-end RNA-seq data were generated with Flux simulator using refSeq transcripts of the human (hg19) as a guide. The specific details and the summary are provided in the Experiment section. Each data set, after trimming, was assembled with the reference-based Tophat2 and SpliceMap and with the de novo assemblers Trinity and the SOAPdenovo-Trans. For evaluation, true positives are considered to be the transcripts generated with coverage over some specified threshold.
