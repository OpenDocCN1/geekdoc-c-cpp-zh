Although similar in concept with the overlap graph, the de Bruijn graph has several properties that differ in a significant way (20). First, the reads are split across several nodes corresponding to adjacent k-mers. Second, a repeat (i.e., for our purposes, a sequence that occurs a large number of times in the originating sequence, with small variations) will appear as a sequence of adjacent k-mers that occur in a large number of reads. The ends of the repeat region in the graph diverge into the unique portions of the genome or transcript, thus creating a “bubble”. Most importantly, the graph can be constructed in linear time with number of sequences, as compared to the quadratic time required to find all pairwise overlaps among the input.

An Eulerian tour of the graph that visits each node precisely once could, theoretically, represent a solution to genome or transcript assembly problem (19). In practice, however, the graph can contain cycles that are introduced whenever the sequence is repeated in the originating genome or transcript sequences, which introduce ambiguity in deciding the correct path. Most frequently, the solution involves enumerating unambiguous paths (contigs) along with sequences of the repeats, their order and orientation resolved to the extent possible by using information from paired-end reads.

# 11.2.2 Adaptation to Transcriptome Assembly While transcriptome assembly using Bruijn graphs is a natural extension of genome assembly, there are significant differences between the two problems. First, instead of the graph encoding just one genomic sequence, several isoforms share the same path in the graph while the alternatively spliced regions. Second, genes and their isoforms have varying expression, and different sets of parameters may be optimal for each assembly problem.

In Bruijn graphs, the k-mer size significantly affects the balance between sensitivity and accuracy. Lower k values increase sensitivity by allowing low expression isoforms to be asserted, but can introduce artifacts. Larger k values are more accurate in reconstructing transcripts with high read depths, but may miss expression isoforms. Starting from the assumption that a single k value is unlikely to render a universally effective solution, several programs were developed using multiple k values in parallel to produce independent assemblies. The millions of contigs are then merged across assemblies and filtered to remove redundancies and spurious constructs. A simple approach was implemented in the additive Multiple-K method (10). In a more complex merging scheme, Trans-AbySS (13) builds a de Bruijn graph and assembly problem for each k value = 26,...,50. It then merges the results between pairs of assemblies in a hierarchical manner, starting with consecutive (k, k+1) and subsequently merging pairs of intermediate assemblies. In variation, Oases (12) performs an assembly for each k = 19,...,35, then builds a second-stage of de Bruijn graph from the merged set of contigs, which is analyzed to produce the final set of transags. In another variation, Rnotator (11) employs the assembler Velvet (21) with k = 19,...,41 to produce multiple assemblies and then uses a conventional assembler, Minimum (22), to resolve redundancies. The outcome is a nonredundant set of contigs that need to be filtered for artifacts.
