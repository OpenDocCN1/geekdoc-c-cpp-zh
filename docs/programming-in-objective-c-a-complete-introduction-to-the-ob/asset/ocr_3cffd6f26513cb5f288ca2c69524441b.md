To illustrate the use of a compound relational test in an actual program example, let's
 a program that tests whether a year is a leap year. We all know that a year is a leap
y if it is divisible by 4. What you might not realize, however, is that a year that is
divisible by 100 is not a leap year unless it is also divisible by 400.

Try to think how you would go setting up a test for such a condition. First, you
 compute the remainders of the year division by 4, 100, and 400, and assign
tvalues to appropriately named variables, such as rem_4, rem_100, and rem_400,
spectively; then you could test these remainders to determine whether the desired criteria
a leap year were met.

If we rephrase our definition of a leap year, we can say that a year is a leap year
if it is divisible by 4 and not by 100 or if it is divisible by 400. Stop for a mo-
ment to reflect on this last sentence and to verify to yourself that it is equivalent to the pre-
vviously stated. Now that we have reformulated our definition in these terms, it
comes a relatively straightforward task to translate into a program statement, as follows:

```
if (rem_4 == 0 && rem_100 != 0) || rem_400 == 0 )
NSLog("%@s's a leap year.
");"
```

The parentheses around the following subexpression are not required:

```
rem_4 == 0 && rem_100 != 0
```

This is because the expression will be evaluated that anyway: Remember that &&
has higher precedence than ||.

In fact, in this particular example, the following test would work just as well:

```
if ( rem_4 == 0 && ( rem_100 != 0 || rem_400 == 0 )
```

the user to key in the terminal, you end up with a program that determines
