So, in review, why would you want to create a subclass? Here are three reasons:

+   1. You want to extend the functionality of a class, perhaps by adding some new methods/or instance variables.

+   2. You want to make a specialized version of a class (e.g., a particular type of graphic object).

+   3. You need to change the default behavior of a class by overriding one or more of its methods.

# Abstract Classes

What better way to conclude this chapter than a bit of terminology? We introduce it here because it's directly related to the notion of inheritance.

 classes are created just to make it easier for someone to create a subclass. For that reason, these classes are called abstract classes or, equivalently, abstract subclasses. Methods and instance variables are defined in the class, but one is not expected to eventually create an instance from that. For example, the root object NSObject. The Foundation framework, covered in Part II, "The Foundation Framework," has several of these so-called abstract classes. As an example, the Foundation's NSNumber class is an abstract class that was created for working with numbers such as Integers and floatingpoint numbers typically have different storage requirements. Separate subclasses of NSNumber actually exist, they are known as concrete subclasses. Each subclasses. Each concrete subclass falls under the NSNumber class umbrella and is collectively referred to as a cluster.When you send a message to the NSNumber class to create a new object, the appropriate subclass is used to allocate the necessary storage for an integer object and set its value appropriately. These subclasses are actually private. You don't access them directly; they are accessed indirectly through the abstract class. The abstract class gives a common interface for working with all types of objects and relieves you of the burden of having to know which type of number you have stored in your number object and how to retrieve its value.
