# Reference Counting

```
int main (int argc, char *argv[]) {
    NSAutoreleasePool *pool = [NSAutoreleasealloc init];
    NSMutableString *myStr = [NSMutableString stringWithWithString:@"A string"];
    ClassA *myA = [[ClassA alloc init];

    NSLog("%myStr retain count: %lx", [myStr retainCount]);

    myA setStr:myStr;
    NSLog("%myStr retain count: %lx", [myStr retainCount]);

    [myA release];
    [pool drain];
    return 0;
}
```

# Program 17.3 Output

myStr retain count: 1
myStr retain count: 1

The program simply allocates a ClassA object called by myA and then invokes the setter to set it to the NSString object by myStr.The retain count for myStr is 1 both before and after the setStr method is invoked, as you would expect, because the simple method stores the value of its argument in instance variable str. Once again, if the program released myStr after calling the setStr method, the value stored in the instance variable would become invalid because the retain count would be decremented to 0 and the memory space occupied by the object it referenced would be deallocated.

This happens in Program 17.3 when the autorelease pool is released. Even though we didn't add it to that, when we created the string object myStr using the stringWith: method, added it to the autorelease pool. When the pool was drained, myStr was released. Any attempt to access it pool after drained would be invalid.

Program 17.4 makes a change to the setStr: method to retain the value of str.This protects you from someone else later releasing the object str.
