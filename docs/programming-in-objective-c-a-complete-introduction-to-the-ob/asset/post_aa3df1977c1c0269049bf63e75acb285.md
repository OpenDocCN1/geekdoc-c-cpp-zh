## Memory Management

We have focused on the topic of memory management throughout this book. You should understand by now when you are responsible for releasing objects and when you are not. Even though the examples in this book all been small, we have emphasized the importance of paying attention to memory management, to teach good programming practice and to develop leak-free programs.

Depending on the type of application you are writing, judicious use of memory can be critical. For example, if you are writing an interactive drawing application that creates many objects during the execution of the program, you must take care that your program does not continue to consume more resources as it runs. In such cases, it becomes your responsibility to intelligently manage those resources and free them when they are no longer needed. This means freeing resources during the program's execution instead of just waiting until the end.

In this chapter, you will learn about Foundation's memory-allocation strategy in more detail. This involves a more thorough discussion of the autorelease pool and the idea of retaining objects. You will also learn about object's reference or retain count. Finally, we will talk about a mechanism known as garbage collection that alleviates the burden of having to retain and subsequently release your objects when you are done using them. However, as you'll see, garbage collection cannot be used for iOS applications, so you must still understand the techniques for memory management described throughout this book (and in more detail in this chapter).

## The Autorelease Pool

You are familiar with the autorelease pool from previous program examples in this second part of the book. When dealing with Foundation programs, you must set up this pool to use the Foundation objects. This pool is where the system keeps track of your objects for later release. As you've seen, your application can set up the pool with a call like so:

```
NSAutleasePool * pool = [[autoreleasePool alloc] init];
```

## Chapter 17 Memory Management

When the pool is set up, Foundation automatically adds certain arrays, strings, dictionaries, and other objects to this pool. When you're done using the pool, you can release the memory it uses by sending it a drain message:

```
[pool drain];
```

The autorelease pool gets its name from the fact that any objects that have been marked for autorelease, and therefore, recorded in the pool are automatically released when the pool is released. In fact, you can have more than one autorelease pool in your program, and they can be nested as well.

If your program generates a lot of temporary objects (which can easily happen when executing code inside a pool), you might need to create multiple autorelease pools in your program. For example, the following code fragment illustrates how you can set up autorelease pools to release the temporary objects created by each iteration of the loop:

```
autoreleasePool *tempPool;

for (i = 0; i < n; ++i) {
    tempPool = [AutoreleasePool alloc init];
    // lots of work with temporary objects
    [tempPool drain];
}
```

Note that the autorelease pool doesn't contain the actual objects themselves—only a reference to the objects that to be released when the pool is drained.

You can add an object to the current autorelease pool for later release by sending it an autorelease message:

```
[myFraction autorelease];
```

The system adds myFraction to the autorelease pool for automatic release later. As you'll see, the autorelease method is useful for marking objects from inside a method, for later disposal.

## Reference Counting

When we talk about the basic Objective-C class NSObject, we noted that memory is allocated with the alloc method and can subsequently be released with a release message. Unfortunately, it's not always simple. A running application can reference an object that you create in several places; an object can also be stored in an array or referenced by an instance variable else, for example: You can't free up the memory an object uses until you are certain that everyone is using that object.

Luckily, the Foundation framework provides an elegant solution for keeping track of the number of references to an object. It involves a fairly straightforward technique called reference counting. The concept is follows: When an object is created, its reference count is set to 1. Each time you need to, you increment its count by sending a retain message. This is shown in the next line of Program 17.1. As you see, after sending the retain message, its reference count becomes 3. The first reference is the actual object itself, the second is from the array, and the third is from the assignment. Although storing the element in the array creates an automatic increase.

```
[myFraction retain];
```

The output shows that its reference count goes to 2. Next, the object is added to the array using the addObject: method. Note that its reference count goes to 2. The addObject method works automatically; if you check your documentation for the addObject method, you will see this fact described. Adding (or inserting) an object into any type of collection increments its retain count. This means that if you subsequently release the object you've added, it will still have a valid reference from the array and won't be deallocated.

Next, you assign myInt to myInt2. This does not increase the reference count—could mean potential trouble later. For example, if the reference count were decremented to 0 and its released, myInt2 would have an invalid object reference (remember that the assignment of myInt to myInt2 doesn't copy the actual object—only the pointer to where the object is located). Because myNow has another reference (through myInt2), you increment its count by sending a retain message.

```
#import <Foundation/Foundation.h>

// Introduction to reference counting

int main (int argc, char *argv[]) {
    NSAutleasePool *pool = [[autoreleasePool alloc] init];

    NSNumber *myInt = [[NSNumber alloc] initWithValue:100];
    NSLog(@"myInt retain count = %lu", (unsigned long)[myInt retainCount]);

    NSMutableArray *myArr = [[NSMutableArray alloc] init];
    [myArr addObject:myInt];
    NSLog(@"after adding to array = %lu", (unsigned long)[myInt retainCount]);

    NSNumber *myInt2 = myInt;
    NSLog(@"after assignment to myInt2 = %lu", (unsigned long)[myInt retainCount]);

    [myInt retain];
    NSLog(@"myInt retain = %lu", (unsigned long)[myInt retainCount]);

    [myInt release];
    NSLog(@"after release = %lu", (unsigned long)[myInt retainCount]);

    [myArr removeObjectAtIndex:0];
    NSLog(@"after removal from array = %lu", (unsigned long)[myInt retainCount]);

    [pool drain];
    [pool release];
    return 0;
}
```
