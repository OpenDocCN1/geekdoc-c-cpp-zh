# Protocols and Delegation

id currentObject;
...
if ([currentObject conformsToProtocol:protocol (Drawing)] YES)
{
  // Send currentObject paint, erase and/or outline msgs

}

The special @protocol directive used here takes a protocol name and produces a Protocol object, which is what the conformsToProtocol method expects as its argument.
To see if currentObject has implemented the optional outline method, you could write:

```
if ([currentObject respondsToSelector:@selector(outline)] YES)
[currentObject outline];
```

You can enlist the delegate to check for conformance with your variables including the protocol name inside angle brackets after the type name, like this:
<id <Drawing>

This tells the compiler currentObject will reference objects that conform to the Drawing protocol. If you assign a strongly-typed object to currentObject that does not conform to the Drawing protocol (say that you have a Square class that does not conform), the compiler issues a warning message that looks like this:
warning: class 'Square' does not implement the 'Drawing' protocol

This is a compiler check here, so assigning an id variable to currentObject would not generate this message because the compiler has no way of knowing whether the object stored inside an id variable conforms to the Drawing protocol.
You can list more than one protocol if the variable will have an object conforming to more than one protocol, as in this line:

```
id <NSCopying, NSObject> myDocument;
```

When you define a protocol, you can extend the definition of an existing one. This protocol declaration says that the Drawing3D protocol also adopts the Drawing protocol:
@protocol Drawing3D>

Thus, whatever adopts the Drawing3D protocol must implement the methods listed for that protocol, as well as the methods from the Drawing protocol.
Finally, a category can also adopt a protocol, like this:

```
#interface Fraction (Stuff) <NSCopying, NSObject>
```

Here Fraction has a category, Stuff (okay, not the best choice of names!), that adopts the NSObject and NSC protocols.
With class names, protocol names must be unique.
