Assume your viewDidLoad method that you want to allocate your data array and so you insert the following line inside that method:

```
data = [NSMutableArray array];
```

As you know, the array method will create an autoreleased array, which you directly assign to your instance variable data. The problem is that the array will be destroyed as soon as the processing of the current event is completed. Because it's added to the autorelease pool that will be drained at the end of the event loop. In order to ensure the array's survival through event loops, you have a few alternatives. Here are three different lines of code you could use that would work:

```
data = {[NSMutableArray retain]; // survives draining of pool
```

In the last case, since the data has the retain attribute, the autoreleased array will be retained (recall that assigning to self.data will cause the setter to be used). Note that in all three cases you must override dealloc to release your array:

```
(void) dealloc {

```

In many cases, when creating a new object using a framework method you can choose between creating an autoreleased object or an alloced one. If your application will create many objects before the event loop ends and the pool drains, you may want to use the alloc approach. In that way, you can release your objects as soon as you're done using them, without having to wait for the end of event processing. This could mean the difference between your application being terminated by the system because it runs out of memory or running just fine, so it can be an important consideration. In these cases, an analysis of how many objects your application creates when processing an event could prove worthwhile.
