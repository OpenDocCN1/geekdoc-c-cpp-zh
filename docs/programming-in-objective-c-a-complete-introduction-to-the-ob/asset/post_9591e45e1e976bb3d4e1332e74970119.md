
# The #define Statement

The following macro lets you easily create new fractions from your Fraction class on the fly:

```objc
#define MakeFract(x,y) ([[Fraction alloc] initWith:x over y: y])
```

Then you can write expressions such as

```objc
myFract(1, 3); // Make the fraction 1/3
```

The conditional expression operator can be particularly handy when defining macros. The following defines a macro MAX that gives the maximum of two values:

```objc
#define MAX(a,b) ((a) > (b)) ? (a) : (b)
```

This macro enables you to subsequently write statements such as:

```objc
limit MAX(x + y, minValue);
```

This assigns to limit the maximum of x + y and minValue. Parentheses are placed around the MAX definition to ensure that an expression is evaluated properly:

```objc
MAX(x, y) * 100
```

Parentheses are individually placed around each argument to ensure that expressions such as the following are correctly evaluated:

```objc
MAX(x & y, z)
```

The & is the bitwise AND operator, and it has lower precedence than the > operator used in the macro. Without the parentheses in the macro definition, the > operator would be evaluated before the bitwise AND, producing an incorrect result.

The following macro tests whether a character is a lowercase letter:

```objc
#define IS_LOWER_CASE(x) ((x) > 'a') && ((x) < 'z')
```

It thereby permits you to write expressions such as:

```objc
if ( IS_LOWER_CASE(c) )
... 
```

You can use this macro in another macro definition to convert a character from lower to upper case, leaving any non-lowercase character unchanged:

```objc
#define TO_UPPER(x) ( IS_LOWER_CASE(x) ? (x) - 'A' : (x) )
```

Again, you are dealing with a standard ASCII character set here. When you learn string objects in Part II, you'll see how to perform case conversion that will work for international (Unicode) character sets as well.

# The #import Statement

When you have programmed in Objective-C for a while, you will find yourself developing your own set of macros, which you will want to use in each of your programs. But instead of typing these macros into each new program, the preprocessor enables you to collect all your definitions into a separate file and then include them in your program, using the #import statement. These files--similar to the ones you've previously encountered but haven't written yourself--normally with the characters .h and are referred to as header or include files.

Suppose you were to set up some #define statements for the various metric conversions. You might want to define constants that you would need for performing your conversions:

```objc
#define INCHES_PER_CENTIMETER 0.394
#define CENTIMETERS_PER_INCH (1 / INCHES_PER_CENTIMETER)

#define QUARTS_PER_LITER 1.057
#define LITERS_PER_QUART (1 / QUARTS_PER_LITER)

#define OUNCES_PER_GRAM 0.035
#define GRAMS_PER_OUNCE (1 / OUNCES_PER_GRAM)...
```

Suppose you entered the previous definitions into a separate file system called metric.h. Any program that subsequently needed to use any of the definitions contained in the metric.h file could do so by simply including this preprocessor directive:

```objc
#import "metric.h"
```

This statement must appear before any of the #define statements contained in metric.h. The preprocessor looks for the specified file on the system and effectively copies the contents of the file into the program at the precise point at which the #import statement appears. Any statements inside the file are treated just as if they had been directly pasted into the program at that point.

The double quotes around the header filename instruct the preprocessor to look for the specified file in one or more file directories (typically, first in the directory that contains the source file, but the actual places the preprocessor searches can be in Xcode).

Enclosing the filename within the characters < and > instead, as in
```objc
#import <Foundation/Foundation.h>
```

causes the preprocessor to look for the include file only in the special "system" header directory or directories; the current directory will not be searched. Again, with Xcode, you can specify the directories to be searched.

# Conditional Compilation

One of the nicest things about the import file capability is that it enables you to centralize your definitions, ensuring that all programs reference the same value. Furthermore, errors discovered in one of the values contained in the include file are corrected in only one spot, thus eliminating the need to correct every program that uses the value. Any program that referenced the incorrect value would simply have to be recompiled and would not have to be edited.

# Conditional Compilation 

The Objective-C preprocessor offers a feature known as conditional compilation. Conditional compilation is often used to create one program that can be compiled to run on different systems. It is also used to switch on or off statements in the program, such as debugging statements that print the values of variables or trace the flow of execution.

# The #ifdef, #endif, #else, and #ifndef Statements

Unfortunately, a program might rely on system-dependent parameters that need to be specified differently on different devices (for example, an iPhone versus an iPad) or on a particular version of the operating system (for example, Leopard Snow Leopard).

If you have a program that had so many dependencies on the particular hardware or software of the computer system (you should minimize as much as possible), you might end up with many values that would have to be changed to run in other environments. You can help reduce the problem of changing these values for each machine by using the conditional compilation capabilities of the preprocessor. A simple example the following statements have the effect of defining imageFile to "@barnHD.png" if the symbol IPAD has been defined, and to "@barn.png" otherwise:

```objc
#ifdef IPAD
#define imageFile "@barnHD.png"
#else
#define imageFile "@barn.png"
#endif
```

As you can see here, you are allowed to put one or more spaces after the # begins a preprocessor statement. The #ifdef, #else, and #endif statements behave as you would expect. If the symbol specified on the #ifdef line has already been defined—through a #define statement or through the command line—the compiler processes lines up to a #else, #elif, or #endif; otherwise, they are ignored.

To define the symbol IPAD to the preprocessor, the statement
#define IPAD 1

no text has to appear after the defined name to satisfy the #ifdef test. The compiler allows you to define a name to the preprocessor when the program is compiled by a special option to the compiler command. The command line

```bash
gcc --framework Foundation -D IPAD program.m
```

defines the name IPAD to the preprocessor, causing all #ifdef IPAD statements inside program.m to evaluate as TRUE (note that you must type the -D IPAD before the program on the command line). This technique enables you to define names without having to edit the source code.
