object (from the array and through myInt2) remain valid. The system does not deallocate the memory used as long as it has a nonzero reference count.

If you remove the first element from the array myArr using the removeAtIndex: you'll note that the reference count for myInt is automatically decremented to 1. In general, removing an object from any collection has the side effect of decrementing its reference count. This implies that the following code sequence would lead to:

```
myInt = [myArr objectAtIndex: 0];

[myArr removeAtIndex: 0];
```

That's because, in this case, the object referenced by myInt can become invalid after the removeAtIndex: if its reference count is decremented to 0. The solution, here, is to retain myInt after it is retrieved from the array so that it won't matter what happens to the reference from other places.

As noted, in methods that "add" or "insert" objects typically retain objects. To make sure the object stays around and doesn't inadvertently released somewhere else. In a sense when you retain an object, you place your dib on your object to make sure it isn't destroyed by somebody else.

In iOS applications, objects such as views (which are containers that hold graphics, images, that are often drawn on an iOS device's screen) are often added as subviews to existing views (there exists a hierarchy of views that you'll learn about more once you delve into iOS application development). This might be a typical code sequence that you would see in such an application:

```
[view addSubview:anotherView];
[anotherView release];
```

Since the addSubview: method retains the view given as its argument, anotherView can be released without worrying about it being destroyed.
On the flip side, you can later retain that subview you added with a method call like:

```
[anotherView removeFromSuperview];
```

With collections, the view here will be released once it's removed from the hierarchy. A subsequent reference to anotherView may end up crashing your application if it has not been retained by the program.
