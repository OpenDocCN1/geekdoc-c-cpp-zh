# The AddressBook Class

Your AddressCard class seems to be working okay. What if you wanted to work with a lot of AddressCards? It would make sense to collect them, which is exactly what you'll do by defining a new class AddressBook. The AddressBook class will store the name of an address book and a collection of AddressCards, which you'll store in an array object. To start, you'll want the ability to create a new address book, add new cards to it, find out how many entries are in it, and list its contents. Later, you'll want to be able to search the address book, remove entries, possibly edit existing entries, sort it, or even make a copy of its contents.

Let's get started with a simple interface file (see Program 15.10).

# Program 15.10 AddressBook.h Interface File

```objc
#import <Foundation/Foundation.h>
#import "AddressCard.h"

@interface AddressBook : NSObject
{
    NSString *name;
    NSMutableArray *entries;
}

-(id)initWithName:(NSString *)name;
- (void)addCard:(AddressCard *)card;
- (int)entries;
- (void)list;
- (void)dealloc;

@end
```

The initWithName: method sets up the array to hold the address cards and store the name of the book, whereas the addCard: method adds an AddressCard to the book. The entries method reports the number of addresses in your book, and the list method gets a concise list of its entries contents. Program 15.10 shows the implementation file for your AddressBook.

The initWithName: method first calls the init method for the superclass to perform its initialization. Next, it creates a string object (using alloc so it owns it) and sets it to the name of the book passed in as name. This is followed by the allocation and initialization of an empty mutable array that is stored in the instance variable.

You define initWithName: to return an id object, instead of an AddressBook one. If AddressBook is subclassed, the receiver to the initWithName: message (and therefore the return value) isn't an AddressBook object; its type is that of the subclass. For reason, you define the return type as a generic object type.

Notice also in initWithName: you take ownership of the bookName and instance variables using alloc. For example, if you created the array for book using NSMutableArray, as in

```objc
book = [NSMutableArray alloc];
```

you would not be the owner of the book array; it would be autoreleased and you would need to retain it to hang onto it (again, discussed in detail in Chapter). We override the init method here to make sure that if someone does alloc by init, they get a default name of "NoName". So here initWith: method is our designated initializer and we want to make sure that uses it. The addCard: method takes the AddressCard object given as argument and adds it to the book. The count method gives the number of elements in an array. The entries method uses this to return the name of addresses stored in the array.

# Fast Enumeration

The list method's for loop shows a construct you haven't seen before:

```objc
for ( AddressCard *theCard in book )
    NSLog("%@-20s %@", [theCard.name UTF8String], [theCard.email UTF8String]);
```

This uses a technique known as enumeration to sequence through each element of the array. The syntax is simple enough: define a variable that will hold each element of the array in turn (AddressCard *theCard). You follow that with the keyword in, and then list the name of the array. When the for loop executes, it assigns the first element of the array to the variable and then executes the body of the loop. It assigns the second element to the variable and again executes the body of the loop. This continues until all elements of the array have been assigned to the variable and the body of the loop executed. Note that if the card had been previously defined as an AddressCard object, the for loop would simply become:

```objc
for ( theCard in book )
    ...
```

# Looking Up Someone in the Address Book

When you have a large address book, you don't want to list its complete contents each time you want to look up someone. Therefore, adding a method to do that for you makes sense. Let's call the method lookup: and take it as its argument the name to locate. The method will search the address book for a match (ignoring case) and return the matching entry, found. If the name does not appear in the phone book, you'll return nil.

Here's our new lookup method:

```objc
// lookup address card by name -- assumes an exact match

-(AddressCard *) lookup: (NSString *)theName
{
for (AddressCard *nextCard in book)
    if ([nextCard.name caseInsensitiveCompare:theName] == NSOrderedSame)
        return nextCard;

return nil;
}
```
