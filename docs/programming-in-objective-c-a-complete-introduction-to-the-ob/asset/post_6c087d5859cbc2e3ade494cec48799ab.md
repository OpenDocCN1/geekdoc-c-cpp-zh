// Working with Numbers

```
#import <Foundation/Foundation.h>

int main (int argc, char *argv[]) {
    NSAutoreleasePool *pool = [[NSAutoreleasePool alloc] init];
    NSNumber *myNumber, *floatNumber, *intNumber;
    NSInteger myInt;

    // integer value
    intNumber = [NSNumber numberWithInteger: 100];
    myInt = [intNumber integerValue];
    NSLog("@%lx", (long) myInt);

    // long value
    myNumber = [NSNumber numberWithLong: 0xabcdef];
    NSLog("@%lx", [myNumber longValue]);

    // char value
    myNumber = [NSNumber numberWithChar: 'X'];
    NSLog("@%c", [myNumber charValue]);

    // float value
    floatNumber = [NSNumber numberWithFloat: 100.00];
    NSLog("@%g", [floatNumber floatValue]);

    // double value
    myNumber = [NSNumber numberWithDouble: 12345e+15];
    NSLog("@%lg", [myNumber doubleValue]);

    // Wrong access here
    NSLog("@%li", (long) [myNumber integerValue]);

    // Test two numbers for equality
    if ([intNumber isEqualToNumber:floatNumber] == YES)
        NSLog("@*Numbers are equal");
    else
        NSLog("@*Numbers are not equal");

    // Test if one number is <, ==, or > second
    if ([intNumber compare:myNumber] == NSOrderedAscending)
        NSLog("@*First number is less than second");

    [pool drain];
    return 0;
}
```

# A Quick Look at the Autorelease Pool

The first line in Program 15.1 has appeared in every program in this book. The following line reserves space in memory for an autorelease pool that you assign to pool:

```
NSAutoreleasePool * pool = [NSAutoreleasePool alloc init];
```

The autorelease pool provides for the automatic release of memory by objects that are added to the pool. An object is added to the pool when it is an autorelease message. When the pool is released or “drained” all the objects that were added to it are released. Therefore, all such objects are destroyed unless they have been specified to exist beyond the scope of the pool (as indicated by its reference counts).

In general, you don't need to worry about releasing an object that a Foundation method returns. The object is created by the method that returns it. Other times, the object is created and added to the autorelease pool by the method. As described in detail in Part I, “Objective-C Language,” you still need to release any objects (including Foundation objects) that you explicitly create using the alloc method when you are using them.

> Note
> You also need to release objects created by a copy or new method, as you’ll learn in Chapter 17.

Chapter 17, “Memory Management,” fully describes reference counts, the autorelease pool, and the concept of automatic garbage collection.

Let’s return to Program 15.1. The Number class contains many methods that allow you to create NSNumber objects with initial values. For example, the line intNumber = [NSNumber numberWithInteger:100];

creates an object from an integer value whose is 100.

The value retrieved from an NSNumber object must be consistent with the type of value that was stored in it. So in the statement that follows in the program,

```
myInt = [intNumber integerValue]
```

retrieves the integer value stored inside intNumber and stores inside the NSInteger variable myInt. Note that NSInteger is not an object, a typedef for a basic data type.

It is typedef either to a long 64-bit or to an int for 32-bit builds. A similar typedef for NSInteger exists for working with unsigned integers in your program.

In the NSLog, we cast the NSInteger myInt to a long and use the format character %li to ensure that the value is passed and displayed correctly even if the program is compiled for a 32-bit architecture.

For each basic data type, a class method exists that allocates an NSNumber object and sets it to a specified value. These methods begin with numberWithLong:; numberWithFloat; and so on. In addition, instance methods can be used to set a value to a previously alloced NSNumber object to a specified value. These all begin with initWithLong:; and initWithFloat:.

# Number Objects

You get this output:

0

Also, you get no error message from the system. In general, it's up to you to ensure that if you store a value in an NSNumber object, you retrieve it in a consistent manner.

Inside the if statement, the message expression

```
[intNumber isEqualTo:floatNumber]
```

uses the isEqualTo: method to numerically compare two NSNumber objects. The program tests the returned BOOL value to see whether the two numbers are equal.

You can use the compare: method to test whether one numeric value is numerically less than or greater than another. The message expression

```
[intNumber compare:myNumber]
```

returns the value NSOrderedAscending if the numeric value stored in intNumber is less than the numeric value contained in myNumber, returns the value NSOrderedSame if the first number is greater than the second. These values are defined in the header file NSObject.h, which is included when you import Foundation.h.

Note that you cannot change the value of a previously created NSNumber object. For example, this doesn't work

```
NSNumber *myNumber = [[NSNumber alloc] initWithInt:50];
```

This statement will cause your program to crash when it is run. All number objects must be created, meaning that you must invoke one of the methods listed in the first column of Table 15.1 on the NSNumber class or one of the methods listed in column 2 using the result from the alloc method, as shown in the first line of the example.

Of course, based on previous discussions, if you create myNumber this using (alloc), you are responsible for subsequently releasing it when you're done it with a statement as follows:

```
[myNumber release];
```

Just to sure you understand the difference in using numberWithInt: versus numberWithInteger:, just follow these rules:

- 1. If you create an integer using numberWithInt: you should retrieve its value using intValue, and can display your value using %i as the format characters.
- 2. If you create an integer using numberWithInteger: you should retrieve its value using integerValue, and you should cast it to a long if it's displayed or used to a string with a method like stringWith:. The format characters to use would be %li in such cases.
