Some explanation is in order here. First, you define two Fractions—aFraction and bFraction and set their values to 1/4 and 1/2, respectively. You also define a Fraction called resultFraction. This variable will store the result of your addition operation as follows.

The following line of code sends the message to aFraction, passing along the Fraction bFraction as its argument:

```objc
resultFraction = [aFraction add: bFraction];
```

Inside the method, a Fraction object is allocated and the resulting addition is performed. The result that is stored in the Fraction object result is returned by the method, where it is stored in the variable resultFraction. You may have noticed that we didn't allocate it (or initialized) a Fraction object inside main for resultFraction; that's because the add method allocated the object for us and then returned the reference to that object. That reference was stored in resultFraction. So resultFraction ends storing the reference to the Fraction object that we allocated in the add method.

Note that you must be careful at the end of the program to release resultFraction, even though you didn't allocate it yourself in main. The add method allocated it, but it's your responsibility to clean it up.

The following message expression might look like, but it actually creates a problem:

```objc
[[aFraction add: bFraction] print];
```

Because the Fraction returns and you send it a message to print, you have no way of subsequently releasing the Fraction object that add: created. This is an example of a memory leak. If you do this type of nested messaging many times in your program, you will be accumulating storage for fractions whose memory will not be released. Each time, you would be allocating, or leaking, just a bit more memory that you could not directly recover.

One solution is that the print method returns its receiver, which you could release. But that seems a little roundabout. A better solution is to divide the nested messages into two separate messages, as was done earlier in the program.

Let's take one look at fractions in this chapter. For our example, let's consider calculation of the following series:

```
\sum_{i=1}^{n} 1/2^i
```

The sigma notation is shorthand for a summation. Its use here means to add the values of 1/2^i, where i varies from 1 to n. That is, add 1/2 + 1/4 + 1/8 .... If you make the value of n large enough, the sum of these series should approach 1. Let's experiment with different values for n to see how close we get. Program 7.6 performs for the value of n to be entered and performs the calculation.

## Program 7.6 FractionTest.m

```objc
#import "Fraction.h"

int main (int argc, char *argv[]) {
    NSAutoreleasePool *pool = [[NSAutoreleasePool alloc] init];

    Fraction *aFraction = [[Fraction alloc] init];
    Fraction *sum = [[Fraction alloc] init];
    int i, n, pow2;

    [sum setTo:0 over 1]; // set 1st fraction to 0

    NSLog(@"Enter your value for n:");
    scanf("%d",&n);
    pow2 = 2;
    for (i = 1; i<=pow2; i++) {
        [aFraction setTo:1 over pow2];
        sum2 = [sum add:aFraction];
        [sum release]; // release previous sum
        sum = sum2;
        pow2 *= 2;
    }

    NSLog(@"After %i iterations, the sum is %g", i, [sum convertNum]);
    [aFraction release];
    [sum release];

    [pool drain];
    return 0;
}
```

The Fraction is set to the value of 0 by setting its numerator to 0 and its denominator to 1 (what would happen if you set both numerator and denominator to 0?). The program prompts the user to enter a value for n using scanf. You then enter a for loop to calculate the sum of the series. First, you initialize the variable pow2 to 2. This variable is used to store the value of 2². Each time the loop, its value is multiplied by 2. The for loop starts at 1 and goes through n. Each time through the loop, Fraction to 1/pow2, or 1/2^i. Let’s look at the three keys in the loop at a time:

- 1. sum2 = [sum add: aFraction]; This calls the method, passing the argument aFraction. Inside the method, Fraction is added with the receiver (sum), and the result is stored inside the variable sum2 by the assignment statement. Make sure you understand this before you go to the next step.

- 2. [sum release]; This releases the memory taken by the sum. Originally, this was the fraction allocated when the program started. However, this variable is modified each time through the loop (by the statement that follows) to point to a different fraction: the one that the add method returns.

- 3. sum = sum2; This takes the reference to the fraction that the add method returned (which was the fraction we called inside the add method) and we assigned to sum2 in #1 above. This is preparation for the next iteration through the loop. At the end of this statement, sum and sum2 both point to the same fraction object, which is the one that the add method allocated and returned.

When the for loop is completed, you display the final result as a decimal value using the convert method. You have two objects to release: aFraction and your final object stored in sum. Program execution is complete. The output shows what happens when we ran the program three times on a MacBook Air. The first time, the sum of the series was calculated and the resulting value of 0.96875 was displayed. The third time, we ran the program with a value of 15 for n, which gives us a result very close to i.

## Extending Class Definitions and the Interface File

You've now developed a small library of methods for working with fractions. In fact, here is the interface file, listed in its entirety, so you can see all you've accomplished with this class:

```objc
#import <Foundation/Foundation.h>

// Define the Fraction class

@interface Fraction : NSObject
{
    int numerator;
    int denominator;
}

@property int numerator, denominator;
-(void) print;
-(void) setTo:(int) n over:(int) d;
-(double) convertToNum;
-(Fraction *) add:(Fraction *) f;
-(void) reduce;
@end
```

You might not need to work with fractions, but these examples have shown how you can continually refine and extend a class by adding new methods. If you handed the interface file to someone else working with fractions, it would be sufficient for the person to be able to write programs to deal with fractions. If that person needed to add a new method, he could do either directly, extending the class definition, or indirectly, by defining his own subclass and adding his new methods. You'll learn how to do that in the next chapter.
