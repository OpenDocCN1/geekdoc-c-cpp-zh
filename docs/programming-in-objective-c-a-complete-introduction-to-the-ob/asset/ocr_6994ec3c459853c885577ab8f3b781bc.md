# How Things Work

One of the inherited members (it comes from the root object) of the structure is a protected member called isa that identifies the class to which it belongs. Because it's part of the structure (and, therefore, part of the object), it is carried around with the object. In that, the runtime system can always identify the class of an object (even if you assign it to a generic id object) by just looking at its isa member.

You can gain direct access to the members of an object's structure by making them @public (see the discussion in Chapter 10). If you did that with the numerator and denominator members of your Fraction class, for example, you could write expressions such as

```
myFract->numerator
```

in your program directly access the numerator member of the Fraction object myFract. But we strongly advise against doing that. As we mentioned in Chapter 10, it goes against the grain of data encapsulation.

# Fact #2: An Object Variable is Really a Pointer

When you define an object variable as a Fraction, as in

```
Fraction *myFract;
```

you're defining a pointer variable called myFract. This variable is defined to point to something of type Fraction, which is the name of your class. When you allocate a new instance of myFract, with

```
myFract = [Fraction alloc];
```

you're allocating space to store a new Fraction object in memory (that is, space for a structure) and then storing the pointer to that structure that is returned inside the pointer myFract.

When you assign one variable to another, as in

```
myFract2 = myFract1;
```

you're simply copying pointers. Both variables end pointing to the same structure somewhere in memory. Making a change to one of the members referenced (that is, pointed to) by myFract2 therefore changes the same instance variable (that is, structure member) that myFract1 references.

# Fact #3: Methods are Functions, and Message Expressions are Function Calls

Methods are really functions. When you invoke a method, you call a function associated with the class of the receiver. The arguments passed to the function are the receiver (self) and the method's arguments. All the rules about passing arguments to functions, return values, and automatic static variables are the same whether you're talking about a function or a method. The Objective-C compiler creates a unique name for function using a combination of the class name and the method name.
