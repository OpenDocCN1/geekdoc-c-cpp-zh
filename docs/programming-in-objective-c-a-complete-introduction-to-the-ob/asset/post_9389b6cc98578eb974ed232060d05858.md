
# Chapter 19 Archiving

Again, since our AddressCard class inherits directly from NSObject, you don't have to worry about decoding inherited instance variables. If you did, you would insert a line like this at the start of your decoder method (assuming the superclass of your class conforms to the NSCoding protocol):

```
self [super initWithCoder];
```

Each instance variable is decoded by invoking decodeObject:forKey: and passing the same key that you used to encode the variable.

Similarly to your AddressCard class, you add encoding and decoding methods to your AddressBook class. The only line you need to change in your interface file is the @interface declaration to declare that the AddressBook class conforms to the NSCoding protocol. The change looks like this:

```
@interface AddressBook NSObject <NSCoding, NSCopying>
```

Here are the methods for inclusion in the implementation file:

```
-(void)encodeEncoder:(Encoder *) encoder
{
    [encoder encodeObject:bookName forKey:@"AddressBookName\];
    [encoder encodeObject:book forKey:@"AddressBook\];
}
```

```
-(id)initWith:(NSCoder *) decoder
{
    bookName [[decodeObjectForKey:@"AddressBookName"] retain];
    book [[decodeObjectForKey:@"AddressBook"] retain];

    return self;
}
```

As noted, the encodeObject:forKey method works for built-in classes and classes for which you write your encoding and decoding methods according to the protocol. If your instance contains basic data types such as integers or floats, you will know how to encode and decode them (see Table 19.1). Here is a simple definition for a class that contains three instance variables—one is an NSString, another is an int, and the third is a float. The class has one setter method, two getter methods, and two encoding/decoding methods used for archiving:

```
@interface Foo: NSObject<Coding>
{
NSString *strVal;
int intVal;
float floatVal;
}

@property (copy, nonatomic) NSString *strVal;
@property int intVal;
@property float floatVal;
@end
```

The implementation follows:

@implementation Foo

```
@synthesize strVal, intVal, floatVal;

-(void)encodeWithCoder:(NSCoder *)encoder
{
    [encoder encodeObject:strVal forKey:@"strVal"];
    [encoder encodeInt:intVal forKey:@"intVal"];
    [encoder encodeFloat:floatVal forKey:@"floatVal"];
}
```

# Writing Encoding and Decoding Methods

```
-(id)initWith:(NSCoder *)decoder {
  strVal [[decodeObjectForKey:@"strVal"] retain];
  intVal [decodeForKey:@"intVal"];
  floatVal [decodeFloatForKey:@"floatVal"];

  return self;
}
```

Some of the basic data types, such as char, short, long, and long long, are not listed in Table 19.1; you must determine the size of your data object and assign it to the appropriate routine. For example, a short int is normal 16 bits, an int and a long can be 32 or 64 bits, and a long is 64 bytes. (Using the sizeof operator, described in Chapter 13, "Underlying C Language Features," to determine the size of your data type.) To archive a short int, store it in an int first and archive it with encodeIntForKey: Reverse the process to get it back: Use decodeIntForKey and assign it to your short int value.
