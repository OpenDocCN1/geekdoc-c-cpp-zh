The setStr: method first takes whatever is currently stored in the str instance variable and autoreleases it. That, it is available for later release. This is important if the method might be called many times throughout the execution of a program to set the same instance variable to different values. Each time a new value is stored, the old value be marked for release. After the old value is autoreleased, the new one is retained and stored in the str field. The message expression

```
str = [s retain];
```

takes advantage of the fact that the retain method returns its receiver.
dealloc call method is not new; you encountered it in Chapter 15, "Numbers, Strings, and Collections," with your AddressBook and AddressCard classes. Overriding dealloc provides a wide way for you to dispose of the last object your str instance variable when its memory is to be released (that is, when its reference count becomes 0). In such a case, the system calls the dealloc method, which is inherited from NSObject. In the case of objects you retain, allocate or copy (with one of the copy methods discussed in the next chapter) include your methods, you might need to override dealloc so that you get a chance to free them up. The statements

```
[str release];
[super dealloc];
```

+   first release the str instance variable and then the parent's dealloc method to finish the job.

The NSLog call was placed inside the dealloc method to display a message when it is called. We did this to verify that the ClassA object is deallocated properly when the autorelease pool is released.
