# Where Are All Those Objects Going?

Programs 15.4 and 15.5 deal with many string objects that NSString methods create and return. As discussed in the beginning of this chapter, you are not responsible for releasing the memory they use; the objects are. Presumably, the creators have added all these objects to the autorelease pool, and the objects will be freed when the pool is drained. However, if you are developing a program that creates lot of temporary objects, the memory these objects use can accumulate. In such cases, you might need to adopt different strategies for memory to be released during your program's execution, not just when the autorelease pool is drained. Chapter 17 describes this concept. For now, realize that these objects take up memory that can expand as your program executes.

The NSString class contains more than 100 methods that can work with string objects. Table 15.2 summarizes some of the more commonly used, and Table 15.3 lists the additional methods that the NSNSString class provides. Other NSString methods (such as working with pathnames and reading the contents of a file into a string) are introduced to you throughout the remainder of this book. You should look at the documentation for the NSString class to just get a better idea of the wide variety of methods that are at your disposal.
