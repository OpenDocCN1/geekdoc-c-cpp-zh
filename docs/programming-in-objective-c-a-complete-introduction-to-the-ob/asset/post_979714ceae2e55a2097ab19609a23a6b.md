# Archiving with NSKeyedArchiver

A flexible approach enables you to save any type of objects to a file, not just strings, arrays, and dictionaries. This is done by creating a keyed archive using the NSKeyedArchiver class.

Mac OS has supported keyed archives since version 10.2. Before that, sequential archives were created with the NSKeyArchiver class. Sequential archives require that the data in the archive be read back in the same order in which it was written.

A keyed archive is used in which each field of the archive has a name. When you archive an object, you give it a name, or key. When you retrieve it from the archive, you retrieve it by the same key. In that, objects can be written to the archive and retrieved in any order. Furthermore, if instance variables are added or removed to a class, your program can account for it.

# Chapter 19 Archiving

Program 19.3 shows that the glossary can be saved to a file on disk using the method archiveRootObject:ToFile from the NSKeyedArchiver class.

# Program 19.3

```objc
#import <Foundation/Foundation.h>

int main (int argc, char *argv[])
{
    NSAutoreleasePool *pool = [[NSAutoreleasePool alloc] init];
    NSDictionary *glossary = [
        [NSDictionary dictionaryWithObjectsAndKeys:
        "@A class defined so other classes can inherit from it",
        "@abstract class",
        "@To implement all the methods defined in a protocol",
        "@adopt",
        "@Storing an object for later use",
        "@archiving",
        nil];

        [NSKeyedArchiver archiveRootObject:glossary toFile:@"glossary.archive"];

    [pool release];
    return 0;
}
```

Program 19.3 does not produce any output at the terminal. However, the statement `[NSKeyedArchiver archiveRootObject:ToFile:@"glossary.archive"]` writes the dictionary to the file glossary.archive. Any pathname can be specified for the file, the file is written to the current directory.

The file created later can be read into your program by using NSKeyedUnarchiver's unarchiveWithFile:method, as is done in Program 19.4.

# Program 19.4

```objc
#import <Foundation/Foundation.h>

int main (int argc, char *argv[])
{
    NSAutoreleasePool *pool = [[NSAutoreleasePool alloc] init];
    NSDictionary *glossary;
    glossary = [[NSKeyedUnarchiver unarchiveWithFile:@"glossary.archive"];

    for (NSString *key in glossary)
        NSLog("%@: %@", key, [glossary objectForKey: key]);

    [pool drain];
    return 0;
}
```

The statement `glossary = [NSKeyedUnarchiver unarchiveObjectWithFile:@"glossary.archive"];` causes the specified file to be opened and its contents to be read. This file must be the result of a previous archive operation. You can specify a full pathname for the file or a relative pathname, in the example.

After the glossary has been restored, the program simply enumerates its contents to verify that the restore was successful.

# Writing Encoding and Decoding Methods

Basic Objective-C objects such as NSString, NSArray, NSDictionary, NSSet, NSDate, NSNumber, NSData can be archived and restored in the manner described. That includes nested objects, such as an array containing a string or even other objects.

This implies that you cannot directly archive your AddressBook using this technique because the Objective-C system doesn't know how to archive an AddressBook object. If you tried to archive it by inserting a line as

```objc
[NSKeyedArchiver archiveObject:myAddressBook toFile:@"archive.arch"];
```

into your program, you'd get the following message displayed if you run the program:
*** [AddressBook encodeCoder:]: selector not recognized
*** Uncaught exception: <NSInvalidArgumentException>
*** [AddressBook encodeCoder:]: selector not recognized
archiveTest: received signal: Trace/BPT trap

From the error messages, you can see that the system was looking for a method called encodeWithCoder in the AddressBook class, but not defined such a method.

To archive objects other than listed, you must tell the system how to archive, or encode, your objects, and also to unarchive, or decode, them. This is done by adding encodeWithCoder and initWithCoder methods to your class definitions, according to the <NSCoding> protocol. For our address book example, you'd have to add these methods to the AddressBook and AddressCard classes.

# Chapter 19 Archiving

The encodeWithCoder: method is invoked each time the archiver wants to encode an object from the specified class, and the method tells it how to do so. In a similar manner, the initWithCoder: method is invoked each time object from the specified class is to be decoded.

In general, the encoder method should specify how each instance of the object you want to save. Luckily, you have been doing this. For the basic Objective-C classes described previously, you can use the encodeObject:forKey: method. For basic underlying C data types (such as integers and floats), use one of the methods listed in Table 19.1. The method, initWithCoder:, works in reverse: decodeObject:forKey: to decode basic Objective-C classes and the appropriate decoder method shown in Table 19.1.

# Table 19.1 Encoding and Decoding Data Types

| :--- | :--- |
| encodeBool:forKey: | decodeBoolForKey: |

| encodeInt64:forKey: | decodeInt64ForKey: |
| encodeFloat:forKey: | decodeFloatForKey: |
| encodeDouble:forKey: | decodeDoubleForKey: |

# Program 19.5 AddressCard.m

```objc
-(void)encodeWithCoder:(NSCoder *)encoder
{
    [encoder encodeObject:name forKey:@"name"];
    [encoder encodeObject:email forKey:@"email"];
}

-(id)initWithCoder:(NSCoder *)decoder
{
    name = [[decoder decodeObjectForKey:@"name"] retain];
    email = [[decoder decodeObjectForKey:@"email"] retain];
    return self;
}
```
