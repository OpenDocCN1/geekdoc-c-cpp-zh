We are overriding an inherited method here, so you'll recall that in such cases you don't need to declare init in the interface section. Also, that init is defined to return an id type. That's the general rule for writing methods for a class that might be subclassed. You don't want to hardcode a class name in such cases, as the subclass will not be an object from the same class as the parent. To be consistent you should go back to the initWith:over: method and change its return type to id.

When program begins execution, it sends the initialize call method to all your classes. If you have a class and associated subclasses, the parent class gets the message first. This message is sent only once for each class, and it is guaranteed to be before any other messages are sent to the class. The purpose is for you to perform any initialization at that point. For example, you might want to initialize some static variables associated with that class at that time.
