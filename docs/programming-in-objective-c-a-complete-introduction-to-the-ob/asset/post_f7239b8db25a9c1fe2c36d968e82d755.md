```
#ifdef DEBUG

#endif
```

You might have many such debugging statements throughout the program. Whenever the program is being debugged, it can be compiled with the DEBUG to have all the debugging statements compiled. When the program is working correctly, it can be recompiled without DEBUG defined. This has the added benefit of reducing the size of the program because all your debugging statements are not compiled.

# The #if and #elif Preprocessor Statements

The #if preprocessor statement offers a more general way of controlling conditional compilation. The #if statement can be used to test whether a constant evaluates to nonzero. If the result of the expression is nonzero, subsequent lines up to a #else, #elif, or #endif are processed; otherwise, they are skipped.

As an example of how this can be used, the following lines appear in the Foundation file NSString.h:

```c
#if MAC_OS_X_VERSION_MIN < MAC_OS_X_VERSION_10_5
#define NSMaximumLength (INT_MAX-1)
#endif
```

This tests the value of the defined variable MAC_OS_X_VERSION_MIN_REQUIRED against the defined variable MAC_OS_X_VERSION_10_5. If the former is less than the latter, the #define that follows is processed; otherwise, it is skipped. Presumably, this sets the maximum length of a string to the maximum size of an integer minus 1 if the program is being compiled on MAC OS X 10.5 or later versions.

The special operator `defined (name)` can also be used in #if statements. This set of preprocessor statements does the same thing:

```c
#if defined (DEBUG)
...
#endif

and
#ifdef DEBUG
...
#endif
```

The following statements appear in the NSObjectRuntime.h header file for the purpose of defining NS_INLINE (if it's not previously defined) based on the particular compiler that is being used:

```c
#if defined(NS_INLINE)
#if defined(__GNUC__)
#define NS_INLINE static __attribute__((always_inline))
#elif defined(__MWER__) || defined(__cplusplus)
#define NS_INLINE static  inline
#elif defined(__MSC_VER)
#define NS_INLINE static  __inline
#elif defined(__WIN32__)
#define NS_INLINE static  __inline_
#endif
#endif
```

Another common use of #if is in code sequences that look like this:

```c
#if defined (DEBUG)
...
#endif
```

This causes the statements after the #if and up to the #endif to be processed only if DEBUG is defined and has a nonzero value.
Since expressions can be used and since 0 is always false, programmers (myself included) will often comment out a block of code by enveloping it inside a #if 0 ... #undef pair preprocessor statements.

# The #undef Statement

Sometimes you need to define a name to be undefined. You do this with the #undef statement. To remove the definition of a particular name, you write the following:

```c
#undef name
```

Thus, this removes the definition of IPAD:
```c
#undef IPAD
```

Subsequent #ifdef IPAD or #if defined (IPAD) statements evaluate to FALSE.
This concludes our discussion on the preprocessor.

# Underlying C Language Features

This chapter describes features of the Objective-C language that you don't necessarily need to write Objective-C programs. In fact, most of these features come from the underlying C programming language. Features such as functions, structures, pointers, unions, and arrays are best learned on a need-to-know basis. Because C is a procedural language, some of these features go against the grain of object-oriented programming. They can also interfere with some of the strategies implemented by the Foundation framework.

# Arrays

The Objective-C language enables the user to define a set of ordered data items known as an array. This section describes how to define and manipulate arrays. Later sections illustrate how arrays work together with functions, structures, character strings, and pointers.

Suppose you want to read a set of grades into the computer and then perform some operations on these, as rank them in ascending order, compute their average, or find their median.

In Objective-C, you can define a variable called grades that represents not a single value of a grade, but an entire set of grades. You can then refer each element of the set using a number called an index number, or subscript. Whereas in mathematics a subscripted variable, $x_i$ refers to the $i$th element $x$ in a set, in Objective-C the equivalent

```
x[i]
```

So the expression

```
grades[5]
```

(read as "grades 5") refers to element number 5 in the array called grades. In Objective-C, array elements begin with the number 0, so

```
grades[0]
```

actually refers to the first element of the array.

This statement assigns the value contained in grades[50] to g. More generally, if i is declared to be an integer variable, the statement

```

```

assigns the value contained in element i of the grades array to g.

A value can be stored in an element of an array simply by specifying the array element on the left side of an equals sign. In the statement

```c
grades[100] = 95;
```

the value 95 is stored in element number 100 of the grades array.
