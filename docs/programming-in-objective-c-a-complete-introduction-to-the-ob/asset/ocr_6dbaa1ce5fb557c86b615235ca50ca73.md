The message in the program releases or frees the memory that was used for the Fraction object:

```
[myFraction release];
```

This is a critical part of good programming style. Whenever you create a new object, you are asking for memory to be allocated for that. Also, when you're done with the object, you are responsible for releasing the memory when your program terminates anyway. Although it's true that the memory will be released when you anyway, if you start developing more sophisticated applications, you can end up with hundreds (or thousands) of objects that consume a lot of memory.Waiting for the program to terminate for the memory to be released is wasteful of memory, can slow your program's execution, and is not good programming style. Get into the habit of releasing memory when you get right now.

The runtime system provides a mechanism known as garbage collection that facilitates automatic cleanup of memory. However, it's best to learn how to manage your memory yourself without relying on this automated mechanism. In fact, you cannot rely on garbage collection when programming for certain platforms on which collection is not supported, such as the iPhone or iPad. For that reason, we don't talk about garbage collection until later in this book.
