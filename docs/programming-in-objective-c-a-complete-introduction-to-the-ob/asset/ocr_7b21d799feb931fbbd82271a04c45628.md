# Writing Encoding and Decoding Methods 435

These are the new methods used for your AddressCard class to be added to the implementation file:

```
-(void) encodeWithCoder:(NSCoder *) encoder
{
  [encoder encodeObject:name forKey:@"AddressName"];
  [encoder encodeObject:email forKey:@"AddressCardEmail"];
}
```

```
-(id) initWithCoder:(NSCoder *) decoder
{
  name = [[decoder decodeObjectForKey:@"AddressName"] retain];
  email = [[decoder decodeObjectForKey:@"AddressCardEmail"] retain];
  return self;
}
```

The encoding method encode is passed an NSCoder object as its argument. Since your AddressCard inherits directly from NSObject, you don't need to worry about encoding inherited variables. If you did, and if you knew the subclass of your class normed to the NSCoding protocol, you should start your encoding method with a statement like the following to make sure your inherited variables are encoded:

```
[super encodeWithCoder:encoder];
```

Your class has two instance variables, called name and email. Because these are NSString objects, you can use the encodeObject:forKey method to encode each of them. These two instance variables are then added to the archive.

The encodeObject:forKey method adds an object and stores it under the specified key for later retrieval using that key. The key names are arbitrary, so long as you use the same name to retrieve (decode) the data when you archived (encoded) it, you can specify any key you like. The only time a conflict might arise is if the same key is used for a subclass of an object instance being encoded. To prevent preventing this, you can insert the key name in front of the instance variable name when composing the key for the archive, as done in Program 19.5.

Note that encodeObject:forKey can be used for any object that has implemented a corresponding encodeWithCoder: method in its class.
The decoding process works in reverse. The argument passed to initWithCoder is again an NSObject object. You don't need to worry about this argument; remember that it's the one that gets the messages for each object you want to extract from the archive.

Note

Note that decoded objects are retained. That's because the NSCKeyedUnarchiver archives the objects. It's important to retain them if you're writing an iOS application, the autorelease pool drained at the end of processing each event. If you have a property that has the retain or copy attribute, you could also use the setter for property to do the assignment.
