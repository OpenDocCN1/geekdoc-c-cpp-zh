# Separate Interface and Implementation Files 127

Note that the interface file is imported into the implementation file with the following-statement:
#import Fraction.h*

This is done because we separated the interface and implementation sections into two separate files. The compiler will compile each file independently. When the compiler is processing the file containing the implementation section (that is, the Fraction.m ) it will need to know information from the class' interface (such as the names and types of its instances). By importing the .h file, the compiler knows about the class and methods you declared for your Fraction class, and can ensure consistency between the two files.

Another thing you should note is that the file is imported in a set of double quotes, not < and > , as was the case with <Foundation/Foundation.h. The double quotes are used for local files (files that you create) instead of system files, and they tell the compiler where to look for the specific file. When you use double quotes, the compiler typically looks for the specific file inside your project and in a list of other files. If necessary, you can specify different places for the compiler to search.

Note that the test program, FractionTest.m (that was shown at the start of this chapter), includes the interface file Fraction.h, and not the implementation Fraction.m. The interface section provides all the information the compiler needs to know about a class when you need to use the class in another file. The implementation section contains the actual code of the methods, and Xcode takes care of including code along with any other code you write when you build your application.

> In fact, the code may actually be stored someplace else, such as a Framework library, and Xcode will automatically extract it from the library when you build your application.

Now you have your program split into three separate files. This might seem like a lot of work for a small example, but the usefulness will become apparent when you start dealing with larger programs and sharing class declarations with other programmers.
You now compile and run your program the same way you did before: Select Run from the Product menu, or simply click the Run button in the toolbar.

If you're compiling your programs from the command line, give the Objective-C compiler both ".m" filenames. Using gcc, the command line looks like this:

```
gcc -framework Foundation Fraction.m FractionTest.m -o FractionTest
```
