This tells the compiler that the AddressBook adopts the NSCopying and NSCCoding protocols. Again, the compiler expects to see all the required methods for those protocols implemented in the AddressBook implementation section.

If you define your own protocol, you don't have to implement it yourself. However, you are alerting other programmers that if they want to adopt the protocol, they do have to implement the required methods. These methods can be inherited from a superclass. Thus, if one conforms to the NSCopying protocol, its subclasses as well (although that doesn't mean the methods are correctly implemented for subclass).

You can use a protocol to define methods that you want other people who subclass your class. Perhaps you could define a Drawing protocol for your GraphicObject class; in it, you could paint, erase, and outline methods:

```
@protocol Drawing
-(void) paint;
-(void) erase;
-optional
-(void) outline;
@end
```

As the creator of the GraphicObject class, you don't necessarily want to implement these painting methods. However, you want to specify the methods that someone subclasses the GraphicObject class needs to implement to conform to a standard for drawing objects he's trying to create.

> Note of the @optional directive. Any methods that are listed following that directive are optional. That is, an adopter of the Drawing protocol does not have to implement the outline method to conform to the protocol. (And you can subsequently switch back to listing required methods by using the @required directive inside the protocol.)

Well that's the intent, anyway. The compiler lets you say that you conform to a protocol and only issues warnings when you don't implement the methods.

If you create a subclass of GraphicObject called Rectangle and advertise (that is, document) that your Rectangle conforms to the Drawing protocol, users of the class will know that they can send paint, erase, and (possibly) outline messages to instances from that class.

Notice that the protocol doesn't reference any classes; it's massless. Any class can conform to the Drawing protocol, not just subclasses of GraphicObject.
