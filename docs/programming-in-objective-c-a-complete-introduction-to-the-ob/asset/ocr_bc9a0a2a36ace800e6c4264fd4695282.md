# Allocating and Returning Objects from Methods

# Program 7.5 Output

```
1/4
+
1/2
=
3/4
3/4
```

Some explanation is in order here. First, you define two Fractions—aFraction and bFraction and set their values to 1/4 and 1/2, respectively.You also define a Fraction called resultFraction. This variable will store the result of your addition operation follows.

The following line of code sends the message to afraction, passing along the Fraction bFraction as its argument:

```
resultFraction = [aFraction add: bFraction];
```

Inside the method, a Fraction object is allocated and the resulting addition is performed. The result that is stored in the Fraction object result is returned by the method, where it is stored in the variable resultFraction. You may have noticed that we didn't allocate it (or initialized) a Fraction object inside main for resultFraction;that's because the add method allocated the object for us and then returned the reference to that object. That reference was stored in resultFraction. SoresultFraction ends storing the reference to the Fraction object that we allocated in the add method.

Note that you must be careful at the end of the program to release resultFraction, even though you didn't allocate it yourself in main.The add method allocated it, but it's your responsibility to clean it up.

The following message expression might look like, but it actually creates a problem:

```
[aFraction add: bFraction] print];
```

Because you the Fraction returns and sends it a message to print, you have no way of subsequently releasing the Fraction object that add: created. This is an example of a memory leak. If you do this type of nested messaging many times in your program, you will be accumulating storage for fractions whose memory will not be released. Each time, you would be allocating, or leaking, just a bit more memory that you could not directly recover.

One solution to the print method returns its receiver, which you could release. But that seems a little roundabout. A better solution is to divide the nested messages into two separate messages, as was done earlier in the program.
