## Working with Files

The Foundation framework enables you to get access to the file system to perform basic operations on files and directories. This is provided by NSFileManager, whose methods include the capability

- Create a new file
- Read from an existing file
- Write data to a file
- Remove (delete) a file
- Test for the existence of a file
- Determine the size of a file as well as other attributes
- Make a copy of a file
- Test files to see whether their contents are equal

Many of these operations can also be performed on directories. For example, you can create a directory, read its contents, or delete it. Another feature is the ability to link files. That is, the ability to have the same file exist under two names, perhaps even in different directories.

To open a file and perform multiple read-write operations on the file, you use the methods provided by NSFileHandle. The methods in this class enable you to

- Open a file for reading, writing, or updating (reading and writing)
- Seek to a specified position within a file
- Read or write a specified number of bytes from and to a file

The methods provided by NSFileHandle can also be applied to devices or sockets. However, we will focus only on dealing with ordinary files in this chapter.

## Managing Files and Directories: NSFileManager

A file or directory is uniquely identified by NSFileManager using a pathname to file. A pathname is an NSString object that can be either a relative or full pathname. A relative pathname is one that is relative to the current directory. So, the filename copy1.m means the file copy1.m in the current directory. Slash characters represent a list of directories in a path. The filename ch6/copy1.m is also a relative pathname, identifying the file copy1.m stored in the directory ch6, which is contained in the current directory.

Full pathnames, also known as absolute, begin with /. root directory. On your Mac, the full pathname to your home directory is /Users/stevekovchan. This pathname specifies three directories: / (the root directory), /Users, and stevekovchan.

The special character (~) is used as an abbreviation for a user's home directory. ~linda would, therefore, be an abbreviation for the user linda's home directory, which might be the path /Users/linda. A solitary tilde indicates the current user's home directory, making the pathname ~/copy1.m reference the file copy1.m stored in the user's home directory. Other UNIX-style pathname characters, such as . for the current directory and .. for the parent directory, should be removed from pathnames before they are used by any of the Foundation methods. Path utilities are available that you can use for this, and they're discussed in this chapter.

You should try to avoid hard-coding pathnames into your programs. You'll see in this chapter, methods and functions are available that enable you to obtain the pathname for the current directory, a user's home directory, and a directory that can be used for temporary files. You should avoid yourself as much as possible. We'll see later in this chapter that Foundation has a function for obtaining a list of special directories, such as a user's directory. This function is useful for developing both Mac OS and iOS applications.
