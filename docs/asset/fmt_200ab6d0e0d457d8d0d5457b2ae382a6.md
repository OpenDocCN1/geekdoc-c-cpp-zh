
## 35.1 用例：自引用结构

我知道一个真实的用例：对自引用或相互依赖结构的体或联合进行向前引用（在这些示例中我将使用 `struct`，但它们同样适用于 `union`）。让我们先看经典的例子。

但在在此之前，记住这一点！当你声明一个结构体时，在遇到右括号之前，该结构体是不完整的！

```c
struct antelope { // 此时 struct antelope 是完整的
    int leg_count; // 仍然不完整
    float stomach_fullness; // 仍然不完整
    float top_speed; // 仍然不完整
    char *nickname; // 仍然不完整
};

// 现在它是完整的。
```

这似乎足够了。但我们在做链表呢？每个链表节点都需要指向另一个节点的引用。但如果我们还没有完成节点的声明，如何创建指向另一个节点的引用呢？

C 对不完整类型的允许使得这成为可能。我们不能声明节点，但我们可以声明指向它的指针，即使它是不完整的！

```c
struct node {
  int val;
  struct node *next; // struct node 是完整的，但没关系！
};
```

即使节点在第 3 行是不完整的，我们仍然可以声明它的指针。

如果我们有两个相互引用的不同结构体，也可以同样操作：

```c
struct a {
  struct b *x; // 指向 `struct b`
};
```

```c
struct b {
  struct a *x; // 指向 `struct a`
};
```

如果没有对不完整类型的宽松规则，我们永远无法创建那对结构体。

## 35.3 其他不完整类型

声明没有实体的结构体或联合会产生不完整类型，例如：`struct foo;`
枚举在遇到右括号之前是不完整的。

`void` 是一个不完整类型。

没有指定大小的外部数组是不完整的，例如：`extern int a[];`

如果是非外部数组没有指定大小且跟着初始化列表，它在遇到初始化列表的右括号之前是不完整的。

## 35.4 用例：在头文件中的数组

在头文件中声明不完整的数组类型可能是很有用的。在这些情况下，实际的存储（声明完整数组的地方）应该在单个 `.c` 文件中。如果你将其放在 `.h` 文件中，那么每当该头文件被包含时，它都会被重复（重复定义）。

因此，你可以创建一个引用该数组的包含不类型的头文件，如下所示：

```c
// File: bar.h
#ifndef BAR_H
#define BAR_H
extern int my_array[]; // 不完整类型
#endif
```

然后在 `.c` 文件中，实际定义该数组：

```c
// File: bar.c
int my_array[1024]; // 完整类型！
```

然后，你可以在任何需要的地方包含该头文件，并且每个地方都会引用同一个底层 `my_array`。

```c
// File: foo.c
#include <stdio.h>
#include "bar.h" // 包含了 my_array 的不完整类型
int main(void) {
    my_array[0] = 10;
    printf("%d\n", my_array[0]);
}
```

编译文件时，记住向编译器指定所有的 `.c` 文件，但不要指定 `.h` 文件，例如：
`gcc -o foo foo.c bar.c`

## 35.5 补全不完整类型

如果你有一个不完整类型，可以通过在同一作用范围内定义完整的结构体、联合体、枚举或数组来补全它。

```c
struct foo // 不完整类型
struct foo *p; // 指针，没问题
struct foo foo; // 错误：不完整类型
struct foo {
    int x, y, z;
}; // 现在 struct foo 是完整的了！
struct foo foo; // 成功！
```

注意，虽然 `void` 是一个不完整类型，但没有办法补全它。并不是说有人曾想过做那种奇怪的事情。但这确实解释了为什么你可以这样做：

```c
void *p; // OK：指向不完整类型的指针
```
但不能执行以下任何操作：

```c
void v; // 错误：声明不完整类型的变量
printf("%d\n", *p); // 错误：解引用不完整类型
```

## 复数

一个直接从维基百科摘取的关于复数的简短介绍¹：

**复数**是一个可以表示为形式 $a + bi$ 的数，其中 $a$ 和 $b$ 是实数[即 C 语言中的浮点类型]，$i$ 代表虚数单位，满足方程 $i^2 = -1$。因为没有实数满足这个方程，所以 $i$ 被称为虚数。对于复数 $a + bi$，$a$ 被称为**实部**，而 $b$ 被称为**虚部**。

但我就只写到此为止。我们假设你正在阅读这一章，你知道复数是什么，以及你想对它们做什么。

而我们只需要涵盖的是 C 语言执行这些操作的能力。

事实，编译器中对复数的支持是一个*可选*的特性。并不是所有符合标准的编译器都能做到。而那些支持的编译器，其实现程度可能在不同程度上上不相同。

你可以通过以下代码测试你的系统是否支持复数：

```c
#ifdef _STDC_NO_COMPLEX_

#endif
```

```c
#if _STDC_IEC_559_COMPLEX != 1

#endif
```

## 36.2 复数的赋值

由于复数有实部和虚部，且两者都使用浮点数来存储值，我们需要告诉 C 语言对复数的这些部分使用什么种精度。

我们通过在复数之前或之后将其固定为 `float`、`double` 或 `long` 来做到。

让我们根据我们使用的分量来定义一个复数：

```c
float complex c; // 规范倾向于这种方式
complex c; // 一样——顺序不重要
```

那么对于声明，我们如何初始化或赋值它们呢？

```c
double complex x = 5 + 2*I;

```

分别对应 $5 + 2i$ 和 $10 + 3i$。

```c
double a = 5;
```

# 37.1 位宽类型

对于有符号和无符号整数，我们都可以指定一个特定位数的类型，当然，也有一些注意事项。

这些类型主要分为三类（在这些示例中，`N` 将替换为特定的位数）：

- 恰好为特定大小的整数 (`int_N_t`)
- 至少为特定大小的整数 (`int_least_N_t`)
- 至少为特定大小且速度尽可能快的整数 (`int_fast_N_t`)¹

“快”到底快多少？可能被定义为某种程度的快。也许吧。规范没有说明具体快多少，只说“它们”在该架构上将是最快的。大多数 C 编译器都非常出色，所以你可能只会在需要保证最快速度的地方使用它（而不是仅仅希望编译器能生成相当get的代码，尽管它确实是能做到的）。

最后，无符号数有一个前缀 `u` 用来区分它们。

例如，这些类型具有以下列出的含义：

```
int32_t w;               // w 恰好是 32 位，有符号
```
