# 第 7 章
## 线性规划与归约

许多我们想要算法的问题都是优化任务：最短路径、代价最小的生成树、最长递增子序列等。在这种情况下，我们寻求一个满足某些约束条件的解（例如，路径必须使用图的边并从 `s` 到到 `t`，树必须接触所有节点，子序列必须是递增的）；并且 (2) 在所有满足这些约束的解中，根据某个定义良好的标准是最好的。

线性规划描述了一类广泛的优化任务，其中约束条件和优化准则都是线性函数。事实证明，海量的问题可以用这种方式表达。

## 7.1 线性规划导论

在线性规划问题中，我们给定一组变量，并希望给它们分配实数值，以：(1) 满足一组涉及这些变量的线性方程和/或不等式，并 (2) 最大化或最小化一个给定的线性目标函数。

### 7.1.1 示例：利润最大化

一家精品巧克力店有两种产品：它的招牌松松巧克力，称为 *Pyramid*（金字塔），以及更奢华豪华的 Pyramid Nut（坚果）。它应该各生产多少以实现利润最大化？假设它每天生产 `x1` 盒 Pyramid，每盒利润 1 美元；生产 `x2` 盒 Nut，每盒利润为 6 美元；`x1` 和 `x2` 是我们希望确定的未知值。但这不是全部；对 `x1` 和 `x2 >= 0` 有一些限制条件。首先，这些限量巧克力的每日需求最多为 200 盒 Pyramid 和 300 盒 Nut。此外，目前的劳动力每天最多可以生产 400 盒巧克力。最优生产水平是多少？

我们用以下*线性规划*来表示这种情况。

```
Objective function max x1 + 6x2

Constraints x1 <= 200

x2 <= 300

x1 + x2 <= 400

x1, x2 >= 0
```

`x1` 和 `x2` 的线性方程定义了二维（2D）平面上的一条直线，而线性不等式指定了一个*半空间*，即直线一侧的区域。该线性规划的所有满足所有约束的点 `(x1, x2)` 的*可行解*集合，是五个半空间的交集。它是一个凸多边形，如图 7.1 所示。

我们想在这个多边形中找到目标函数——利润最大的点。利润为 `c` 美元的点位于直线 `x1 + 6x2 = c` 上，该直线的斜率为 `-1/6`，图 7.1 显示了不同 `c` 值对应的情况。随着 `c` 的增加，这条“利润线”平行于自身移动并向右移动。由于目标是

**图 7.1** (a) 线性规划的可行区域。(b) 目标函数的等值线：对于不同的利润 `c` 值，`x1 + 6x2 = c`。

![](img/3dd1f1364df8f87b80683fc32a15b999_199_0.png)

是最大化 `c`，我们必须让直线尽可能向上移动，同时仍触及可行区域。最优解将是利润线看到的最后一个可行点，并且必须是该多边形的一个顶点，如图所示。如果利润线的斜率不同，它与多边形的最后接触点可能是整条边而不是单个顶点。在这种情况下，最优解不是唯一的，但一定有一个最优顶点。

线性规划的一个一般般规则是，最优解在顶点处取得。唯一的例外是没有最优解的情况；这可以通过两种方式发生：

1. 线性规划是*不可行的*；约束条件太紧，导致无法满足所有条件。
2. 可行区域是*无界的*；约束条件太松，导致可以获得任意大的值。

### 求解线性规划
线性规划（LPs）可以通过 Dantig 在 1947 年发明的*单纯形法*来求解。我们将在 7.6 节中详细解释，但简而言之，该算法从一个顶点开始（在案例中可能是 (0, 0)），并反复寻找具有更好目标值的相邻顶点（通过可行区域的边连接）。通过这种方式，它在顶点上进行*爬山*，从一个邻居走到另一个邻居，从而稳步地增加利润。这是一个可能的轨迹。

`x1, x2 >= 0`。

到达没有更好邻居的顶点后，单纯形法将其宣布为最优并停止。为什么这种*局部*测试意味着*全局*最优性？根据简单的几何原理——考虑利润线通过这个顶点。由于该顶点的所有邻居都在直线下方，可行多边形的其余部分也必须位于此下方。

### 更多产品

受需求激励，巧克力店决定引入第三种更稀有的巧克力系列，称为 Pyramid Luxe。每盒那种将带来 13 美元的利润。让 `x1, x2, x3` 表示每天生产的每种数量，其中 `x3` 指 Luxe。`x1` 和 `x2` 的旧约束仍然有效，尽管劳动力限制现在扩展到了 `x3`：三个变量之和最多为 400。此外，事实证明 Nut 和 Luxe 使用相同的包装机器，只是 Luxe 使用量是三倍，这增加了另一个约束 `x2 + 3x3 <= 600`。最优生产水平是多少？

这里是更新后的线性规划。

```
max x1 + 6x2 + 13x3

x1 <= 200

x2 <= 300

x1 + x2 + x3 <= 400

x2 + 3x3 <= 600

x1, x2, x3 >= 0
```

## 7.1 线性规划简介

解空间现在是三维的。每个线性方程定义了一个 3D 平面，每个不等式定义了该平面一侧的半空间。可行区域是七个半空间的交集，即一个多面体（7.2）。观察该图，你能破译哪一个不等式对应多面体的哪一个面吗？

利润 `c` 对应于平面 `x1 + 6x2 + 13x3 = c`。随着 `c` 的增加，这个利润平面平行于自身移动，向正象限越深处移动，直到它不再接触可行区域。最终的接触点就是最优的：(0, 300, 0)，总利润为 $3100。

单纯形算法在这个修改后的问题上表现会如何？和之前一样，它将沿着多面体的边缘从一个顶点移动到另一个顶点，稳步增加利润。图 7.2 显示了一条条可能的轨迹，对应于以下顶点和利润的序列：

```
0, 0, 0) -> (200, 0, 0) -> (200, 200, 0) -> (0, 300, 100)

$200 $1400 $2800 $3100
```

最后，在到达没有更好邻点的顶点后，它将停止并宣布该点为最优点。再次根据基本几何原理，如果一个顶点的所有邻居都位于利润平面的一侧，那么整个多面体也必须在该在该侧。

### 一个名为对偶性的魔术

这就是为什么你应该相信 (0, 300, 100) 的总利润为 $3100 是最优的：回看这个线性规划。将第二个和第三个相加，再加上第四个。结果是不等式 `x1 + 6x2 + 13x3 <= 3100`。

你看到了吗？这个不等式说明，任何可行解（满足约束的 `x1, x2, x3` 值）的利润都不大于 3100。所以我们确实找到了最优解！唯一的问题是，我们从哪里得到这四个不等式的这些神秘系数 (0, 1, 4) 呢？

在第 7.4 节中，我们将看到通过求解另一个 LP 总是可以得到这样的系数。除了（这更棒了）我们甚至不需要求解另一个 LP，因为实际上它与原始问题联系如此紧密——它被称为*对偶*（dual）——以求解原始 LP 也就解决了对偶问题！但我们跑得比故事太快了。

如果我们增加第四行，或者几百行呢？问题就变成了高维的，且难以可视化。单纯形法在这种通用设定下依然有效，尽管我们不能再依赖简单的几何直觉来对其进行描述和证明。我们将在第 7.6 节学习完整的单纯形算法。

在此期间，我们可以放心，有许多专业的、工业级的软件包实现了单纯形法，并处理了诸如数值精度等所有棘手的细节。在典型的应用中，主要任务是将问题正确地表述为线性规划。然后软件包会处理其余部分。

考虑到这一点，让我们来看一个高维应用。

### 7.1.2 示例：生产计划

这次，我们的公司生产手工织毯，这种产品的需求极具季节性。我们的分析师对明年整个日历年的需求进行了估计：`d1, d2, ..., d12`。正如所担心的，它们非常不均匀，范围从 440 到 920 不等。

这里是公司的简况。我们目前有 30 名员工，其中每月制作 20 张地毯，月薪为 $2,000。我们没有初始的地毯库存。

我们该如何处理需求波动？有三种方法：
- 1. 加班，但这很贵，因为加班费比工资高出 80%。此外，工人最多只能加 30% 的班。
- 2. 招聘和解雇，但每个人的成本分别为 $320 和 $400。
- 3. 储存过剩产量，但每张地毯每月花费 $8。我们目前没有库存地毯，且必须在年底结束时不留存任何地毯。

这个相当复杂的问题可以被建模并作为线性规划来求解！
关键的第一步是定义变量。

```
w_i = 第 i 月的工人人数; w_0 = 30
x_i = 第 i 月制作的地毯数量
o_i = 第 i 月通过加班制作的地毯数量
h_i, f_i = 分别在第 i 月初招聘和解雇的人数
s_i = 第 i 月底储存的地毯数量; s_0 = 0
```

总而言之，有 72 个变量（如果算上 `w0` 和 `s0` 就是 74 个）。
我们写下约束条件。首先，所有变量必须是非负的：

```
w_i, x_i, o_i, h_i, s_i >= 0, i = 1, ..., 12
```

每月的地毯的总量是常规生产加上加班：

```
x_i = 常规生产 + o_i
```

在第 `i` 月底的地毯数量：

```
s_i = s_{i-1} + x_i - d_i
```

加班限制：

```
o_i <= 0.3w_i
```

招聘和解雇限制：

```
w_i = w_{i-1} + h_i - f_i
```

目标函数：

```
min sum (2000w_i + 320h_i + 400f_i + 8s_i)
```

### 7.1.3 示例：整数规划

下一步是线性规划的一个微型版本。假设我们在管理一个 `A, B, C` 的网络，如图 7.3 所示，我们需要在 `A` 和 `B` 之间、`B` 和 `C` 之间以及 `A` 和 `C` 之间建立带宽。每个连接的带宽需求如下，且每个连接的带宽限制如下：

![](img/3dd1f1364df8f7b0683fc2a15b99_205.png)

约束条件如下：

```
x_AB + x'_AB <= 10
x_BC + x'_BC <= 12
x_AC + x'_AC <= 11
```

最小化总成本：

```
min 3x_AB + 3x'_AB + 2x_BC + 2x'_BC + 4x_AC + 4x'_AC
```

由于带宽必须是整数，这是一个整数规划问题：

```
x_AB, x'_AB, x_BC, x'_BC, x_AC, x'_AC in Z
```

如果我们允许带宽为分数，它就变成了线性规划：

```
x_AB + x'_AB >= 2
x_BC + x'_BC >= 2
x_AC + x'_AC >= 2
```

通过单纯形法，我们可以得到最优解：

```
x_AB = 0, x'_AB = 7, x_BC = x'_BC = 1.5, x_AC = 0.5, x'_AC = 4.5
```

这个解不是整数的，但在目前的应用中我们不需要它是整数的，因此不需要进行舍入。回到原始网络，我们看到除了 `a-c` 之外的所有边都处于满载状态。

## 归约 (Reductions)

有时一个计算任务足够通用，使得它的任何子程序都可以解决许多其他任务，而这些任务看起来可能并不相关。例如，我们在第 6 章中看到寻找有向环图（dag）中最长路径的算法意外地也可以用于寻找递增子序列。我们将这种现象描述为最长递增子序列问题归约为 dag 中的最长路径。反之，dag 中的最长路径归约为 dag 中的最短路径；这里后者的子程序可以用于解决：

```
function LONGEST_PATH(G)
negate all edge weights of G
return SHORTEST_PATH(G)
```
