
另一个经常被提到的性能相关话题是：在事件处理器中使用箭头函数的影响。例如，`Dismiss()` 方法的 `onClick` 处理器是将该方法封装在另一个箭头函数中，以传递项目标识符。每当 `render()` 方法运行时，处理器都会实例化该高阶函数。这可能会对你的应用程序性能产生影响，但在大多数情况下你并不会注意到它。想象你有一个包含 1000 个项目的大表格，每行或每列的事件处理器中都有这样一个箭头函数。那么，考虑性能影响就是值得的了，因此你可以实现一个专门的 `Button` 组件，在构造函数中绑定该方法。但在那之前，这属于过早优化。专注于学习 React 更有价值。

## ES6 解构

JavaScript ES6 有一种方法可以更方便地访问对象和数组中的属性。这被称为解构。对比以下 JavaScript ES5 和 ES6 的代码片段。


## 受控组件

你已经学习了 React 中的单向数据流。同样的规则也适用于输入框，它通过 `searchTerm` 更新本地状态以过滤列表。当状态改变时，`render()` 方法会再次运行，并使用本地状态中最新的 `searchTerm` 应用过滤条件。

但我们没有在输入元素中漏掉什么吗？HTML `input` 标签带有一个 `value` 属性。该属性通常具有显示在输入框中的值。在这种情况下，它应该是 `searchTerm` 属性。然而，似乎在 React 中我们不需要它。

这是错误的。在原生 HTML 中，`<input>`、`<textarea>` 和 `<select>` 表单拥有自己的状态。当有人从外部更改它们时，它们会在内部修改值。在 React 中，这被称为不受控组件，因为它处理自己的状态。在 React 中，你应该确保将这些元素变为受控组件。

你应该如何做呢？你只需要设置输入框的 `value` 属性即可。

```
src/App.js

class App extends Component {
  ...
  render() {
    return (
      <div className="App">
        <form>
          <input
            type="text"
            onChange={this.onSearchChange}
            value={this.state.searchTerm}
          />
        </form>
        {this.state.list.filter(isSearched(this.state.searchTerm)).map(item =>
          ...
        )}
      </div>
    );
  }
}
```
