## 在 WPF 4.0 应用程序中使用 XAML

如前所述，WPF 的关键组成部分之一是其基础 XAML。WPF 中对 XAML（读作 zammel）的支持允许你以声明方式指定 WPF 应用程序的 UI 或外观。WPF 4.0 中的 XAML 加载器使你能够在 WPF 应用程序中处理 XAML 内容。通过在 WPF 中集成 XAML，更容易也更方便地在设计或 UI 与 WPF 应用程序的逻辑或功能之间划清界限。这是因为你可以使用 XAML 来定义 WPF 应用程序的 UI，而可以在应用程序的代码隐藏文件中添加 UI 的逻辑。另一方面，XAML 也简化了 XAML 内容与代码隐藏文件之间的共享，因为它允许在 XAML 文件中定义的元素在代码隐藏文件中使用。

Visual Studio 2010 支持 XAML IntelliSense 功能，并允许调试和编译 XAML 内容。此外，Visual Studio 2010 软件开发工具包（SDK）包含一个名为 `XAMLPad` 的 XAML 编辑工具，可实时处理 XAML 元素。你可以从 `C:\Program Files\Microsoft SDKs\Windows\v6.0A\bin\XamlPad.exe` 访问 `XAMLPad`。

> **注意：** XAML 文件具有 `.xaml` 扩展名。XAML 文件也在 Windows Workflow Foundation（WF）和 Microsoft Silverlight 中受支持。

让我们在 XAML 和 WPF 应用程序的上下文中学习以下内容：

- XAML 元素
- 命名空间和 XAML
- XAML 属性语法
- 标记扩展

### XAML 元素

XAML 基于 XML，使用标记标签、元素和属性来定义 WPF 应用程序的 UI。XAML 元素直接对应于各种托管 WPF 类，而 XAML 属性对应于类的属性和事件。此外，这些 XAML 元素所定义的 XAML 命名空间对应于 CLR 命名空间，以便 XAML 内容可以利用 .NET Framework 4.0 提供的调试和编译。

在 WPF 中，XAML 元素表示为具有多个元素节点的逻辑树。每个元素对应一个树节点，而元素的属性成为节点的属性。当你在现有元素内添加 XAML 元素时，它成为现有节点的子元素。这种分层树状内容模型使 WPF 应用程序具有可扩展性且易于渲染。请注意，在任何 XAML 文件中，恰好有一个最顶层或根元素。在 WPF 独立应用程序中，根元素是 `Window` 元素，而在 XBAP 中，根元素是 `Page` 元素。

让我们以一个名为 `SimpleWPFApplication` 的新 WPF 独立应用程序为例。清单 9.4 显示了该应用程序的 XAML 代码：

#### Listing 9.4: Displaying the XAML code of SimpleWPFApplication

```
<Window x:class="SimpleWPFApplication.MainWindow"
xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
Title="MainWindow" Height="300" Width="300">
<Grid>
<Button Margin="100,25,100,200" Name="button1">Welcome</Button>
<Button Margin="100,100,100,125" Name="button2">WPF</Button>
<Button Margin="50,150,50,10" Name="button3" VerticalAlignment="Bottom">
<Label Margin="5,5,5,5" Name="label1">XAML</Label>
</Button>
</Grid>
</Window>
```

在清单 9.4 中，有四个 XAML 元素，即 `Window`、`Grid`、`Button` 和 `Label`。`Window` 和 `Grid` 元素默认存在于 WPF 应用程序中，而 `Button` 和 `Label` 元素是通过从工具箱拖放相应的控件添加的。这些元素可以以分层方式表示为一棵树，如图 9.32 所示：

![](img/e073a4882197be4ab61103cbe0bcb394_370_0.png)

#### Figure 9.32: Representing the XAML Elements as a Tree

在图 9.32 中，`Window` 元素包含 `Grid` 元素，`Grid` 元素又包含三个名为 `button1`、`button2` 和 `button3` 的 `Button` 元素。`button3` 元素本身包含一个名为 `label1` 的 `Label` 元素。这样，随着你在 WPF 应用程序中添加更多控件或元素，此元素树会不断增长。

你可能还注意到在清单 9.4 中，`Window`、`Button` 和 `Label` 元素具有多个属性。例如，`Window` 元素具有 `xmlns`、`Title`、`Height` 和 `Width` 属性，而 `Button` 和 `Label` 元素具有 `Name` 和 `Margin` 属性。请注意，`Window`、`Grid`、`Button` 和 `Label` XAML 元素分别对应于 `Window`、`Grid`、`Button` 和 `Label` 类的实例。然而，XAML 元素的属性对应于相应类的属性。这意味着每当你在 WPF 应用程序中添加一个 XAML 元素时，相应类的一个实例就会自动创建，并且指定的属性会被设置。

### 命名空间和 XAML

与 XML 类似，XAML 需要某些预定义的命名空间来允许你使用元素和属性。这些命名空间向 XAML 解析器传达类的位置以及 WPF 应用程序的结构规则或架构。当你创建 WPF 应用程序时，对必要命名空间的引用会自动添加到 `Window` 元素（在独立 WPF 应用程序中）和 `Page` 元素（在 XBAP 中）。`Application` 元素也包含对必要命名空间的引用。

默认情况下，WPF 应用程序中包含两个命名空间。命名空间是通过 `xmlns` 声明添加的，该声明通过 `Window` 或 `Page` 元素的 `xmlns` 属性提供。在前面给出的清单 9.4 中，你可以看到 `xmlns` 属性用于在 `Window` 元素中包含这两个命名空间。第一个命名空间的 `xmlns` 声明如下：

```
xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
```

前面的 `xmlns` 声明指定了 XAML 文件和 WPF 应用程序的默认命名空间。该命名空间作为统一资源指示符（URI）提供，就像任何其他 XML 命名空间一样。该命名空间包含所有用于处理 WPF 的 XAML 元素和属性。

第二个命名空间的 `xmlns` 声明如下：

```
xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
```

前面的 `xmlns` 声明指定了用于一般处理 XAML 所需的命名空间。该命名空间比默认命名空间更全面，因为它提供了所有基本 XAML 元素和属性，包括不属于 WPF 的元素。例如，WF 和 Silverlight 的元素。请注意，XAML 命名空间的 `xmlns` 声明指定 `x:` 作为命名空间的别名。此别名（`x:`）必须作为前缀加在属于 XAML 命名空间的每个元素或属性之前。例如，`Window` 元素中的 `x:Class` 属性。`x:Class` 属性属于 XAML 命名空间，并指定实现 `Window` XAML 元素的代码隐藏文件中的部分类。以下代码片段显示了 `x:Class` 属性：

```
x:Class="SimpleWPFApplication.MainWindow"
```

你可能会注意到对 XAML 命名空间和 CLR 命名空间的引用的区别，即 XAML 命名空间以 URI 提供，而 CLR 命名空间以点分隔的名称提供（例如，`System.Windows.Controls`）。由于这种差异，你可能会想知道 XAML 和 CLR 命名空间如何映射或对应。答案很简单，使用名为 `XmlnsDefinitionAttribute` 的程序集级属性。`XmlnsDefinitionAttribute` 属性以其参数的形式接收 XAML 和 CLR 命名空间以便将它们映射。可以将多个 CLR 命名空间映射到单个 XAML 命名空间。

> **注意：** XAML 命名空间的 `xmlns` 声明可以添加到任何 XAML 元素中。然而，建议将引用添加到 XAML 文件的根元素中，即 `Window` 或 `Page` 元素。

在 WPF 中，你也可以创建自己的命名空间并在 XAML 文件中使用它，只需在这些文件的根元素中添加 `xmlns` 声明即可。你可以使用 `namespace` 关键字在当前应用程序的同一程序集或不同程序集中创建命名空间。你需要使用以下语法包含 `xmlns` 声明以将自定义命名空间映射到 XAML 代码：

```
xmlns:custom_prefix="clr-namespace:namespace_name; assembly=assembly_name"
```

在前面的代码片段中，使用了以下选项与 `xmlns` 声明一起使用：

- `custom_prefix` — 指自定义命名空间的前缀
- `clr-namespace` — 指允许你指定自定义命名空间的标记
- `assembly` — 指允许你指定程序集名称的标记

请注意，`clr-namespace` 和 `assembly` 标记共同包含在双引号（"）内，并用分号（;）分隔。此外，`clr-namespace` 标记的值在冒号（:）之后指定，而 `assembly` 标记的值在等于号（=）之后指定。如果命名空间存在于与当前应用程序相同的程序集中，则无需指定 `assembly` 标记。

### XAML 属性语法

如前所述，你可以通过设置适当 XAML 属性来设置 WPF 类的属性。你可以从清单 9.4 回忆起，各个属性由空白分隔，并以名称-值对的形式指定。对于每个属性，属性名称后跟等于号运算符，然后是分配给该属性的值。请注意，无论值是字符串还是数字，它都包含在双引号中，如以下代码片段所示：

```
<Button Height="23" Name="button1">Welcome</Button>
```

如前面的代码片段所示，`Button` 类的 `height` 和 `name` 属性分别通过属性 `Height` 和 `Name` 设置。`Height` 属性的值为 23，`Name` 属性为 `button1`。字符串 `Welcome` 是按钮上显示的文本。这相当于 Windows Forms 应用程序中 `Button` 控件的 `Text` 属性。

虽然通过 XAML 特性设置属性简单、简洁且直观，但 WPF 提供了另一种方式，即属性元素语法。在属性元素语法中，可以通过将属性指定为元素而不是特性来设置属性。属性元素语法使用以下语法来设置属性：

```
<element_name.property_name [attribute1_name="value1" attribute2_name="value2"...
attributeN_name="valueN"]>property_value</element_name.property_name>
```

在上述语法中，设置属性时使用了以下选项：

- `element_name` – 指定属性所属元素的名称
- `property_name` – 指定属性的名称
- `attribute1_name`, `attribute2_name`, ... `attributeN_name` – 指定属性可能包含的任何特性的名称
- `value1`, `value2`, ... `valueN` – 指定特性的值
- `property_value` – 指定属性的值

从上述语法可以看出，属性名使用点运算符（.）限定其所属元素的名称。您可能还会注意到，属性被括在尖括号中，并具有开始和结束标签。请注意，如果属性本身具有自己的属性，则这些属性可以进一步在属性元素语法中表示。

以下代码片段显示了 `Button` 类的属性：

```
<Button>
  <Button.Height>23</Button.Height>
  <Button.Name>button1</Button.Name>
  <Button.Content>Welcome</Button.Content>
</Button>
```
