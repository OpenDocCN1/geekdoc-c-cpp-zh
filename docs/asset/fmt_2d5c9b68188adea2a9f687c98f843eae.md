这里我们看到了所谓的“near”指针和“far”指针之间的区别：这是 16 位内存中的另一个产物。

“near”指针是指向当前数据段内部的指针。因此，`string_compare()` 只接受两个参数（`mov, [bx]` 指令从隐式段访问数据）。

“far”指针是指使用 16 位对作为指针，将其高位加载到 `DX` 寄存器并通过它访问数据的指针（`mov, [bx]` 指令实际工作）。这种区别的原因是紧凑的程序可能只使用一个 64KB 段，不需要传递始终相同的高位。较大的程序可能使用多个 64KB 段，因此需要每次指定地址。

代码也是同样的情况。紧凑的程序可能在一个 64KB 段内拥有所有可执行代码，然后其中的所有函数将使用 `CALL NEAR` 调用，代码流使用 `RET` 返回。但如果有多个代码段，则必须用对来指定函数地址，使用指令调用，代码流使用 `RET` 返回。这就是通过指定“内存模型”在编译器中设置的内容。针对 MS-DOS 和 Win16 的编译器针对每种模型都有特定的库：通过代码和数据的指针类型区分。

## Java

### 4.1.1 介绍

有一些广为人知的 Java（或泛指 JVM 字节码）反编译器¹。这是因为 JVM 字节码的结构化解构比低级别的 x86 代码要容易得多：

- JVM 拥有更多关于数据类型的信息。
- JVM 内存模型更加严谨且概述清晰。
- Java 编译器不进行任何优化（JVM JIT² 在运行时进行优化），因此类文件中的字节码通常具有很高的可读性。

JVM 知识什么时候会有用？

- 对类文件进行快速且粗略的补丁任务，无需重新编译反编译的结果。
- 分析混淆代码。
- 分析由较新的 Java 编译器生成的、且尚无更新的代码。
- 构建你自己的混淆器。
- 构建针对 JVM 的编译器代码生成器（后端）（如 Scala）。
