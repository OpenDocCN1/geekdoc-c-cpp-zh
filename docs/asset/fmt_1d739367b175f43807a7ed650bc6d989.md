
<authentication mode="windows|Forms|Passport|None">

  [<forms>

    name="cookieName"

    loginUrl="loginURL"

    defaultUrl="defaultUrl"

    protection="All|None|Encryption|validation"

    timeout="30"

        <user name="userName" password="password"/>

      </credentials>

  </forms>]

  [<passport redirectUrl="loginURL" />]

</authentication>

在上述代码中，您可以看到 `<authentication>` 元素有一个名为 `mode` 的属性。`mode` 属性指的是为 ASP.NET 应用程序指定的身份验证模式。可以为 `mode` 属性设置一组预定义值。这些值如下所示：

- `Windows` – 指用于访问 Web 资源的 Windows 身份验证。它允许您使用 IIS 中可用的任何 Windows 身份验证，即基本、摘要或集成 Windows 身份验证。这是任何 Web 资源的默认值。
- `Forms` – 指用于访问 Web 资源的 Forms 身份验证。
- `Passport` – 指用于访问 Web 资源的 Microsoft Passport 身份验证。
- `None` – 指在无需用户凭据（用户名和密码）即可访问 Web 资源时的身份验证。此值适用于匿名或自定义身份验证。

您还可以从语法中注意到，`<authentication>` 元素可以有两个子元素：`<forms>` 和 `<passport>`。当您使用 Forms 身份验证时，即当 `<authentication>` 元素的 `mode` 属性设置为 `Forms` 时，使用 `<forms>` 元素。`<forms>` 元素有几个属性，如表 36.16 所列：

### 表 36.16：`<forms>` 元素的属性

| Attribute | Description |
|---|---|
| Name | 指用于验证用户身份的 HTTP 身份验证 Cookie。此属性的默认值为 `.ASPXAUTH`。 |
| loginUrl | 指用户需要提供凭据进行身份验证的页面 URL。此属性的默认值为 `login.aspx`。 |
| defaultUrl | 指用户通过身份验证后被重定向到的页面 URL。此属性的默认值为 `default.aspx`。 |
| Protection | 指用于身份验证 Cookie 的保护类型。此属性可以具有以下任何值： |
|  | `All` | 指示通过加密和验证两种方式保护 Cookie。这是默认值。 |
|  | `None` | 指示应用程序不使用加密和验证来保护 Cookie。 |
|  | `Encryption` | 指示应用程序使用 DES 或 3DES 加密 Cookie。不对 Cookie 执行验证。 |
|  | `Validation` | 指示应用程序使用验证机制来保护 Cookie。 |
| Timeout | 指身份验证 Cookie 存在的时间（以分钟为单位）。Cookie 在此属性指定的时间过后过期。此属性的默认值为 `30`（分钟）。 |
| Path | 指用于存储身份验证 Cookie 的路径。此属性的默认值为 `/`，即应用程序的根文件夹。 |
| requireSSL | 指定传递身份验证 Cookie 是否必须使用安全套接字层（SSL）连接。此属性的默认值为 `false`。 |
| slidingExpiration | 指定在同一会话中每次请求时是否重置身份验证 Cookie 的过期时间。此属性的默认值为 `false`。 |
| enableCrossAppRedirects | 指定是否可以将已通过身份验证的用户重定向到其他 Web 应用程序中的网页。此属性的默认值为 `false`。 |
| cookieless | 指何时以及如何生成身份验证 Cookie。此属性可以具有以下任一值： |
| UseUri | 指示完全不使用 Cookie。 |
| UseCookies | 指示始终使用 Cookie。 |
| AutoDetect | 仅当 Web 浏览器支持 Cookie 时才使用 Cookie。尝试使用 Cookie 是通过探测机制进行的。 |
| UseDeviceProfile | 仅对支持 Cookie 的 Web 浏览器使用 Cookie。对于支持 Cookie 的 Web 浏览器，没有探测机制。这是默认值。 |
| domain | 指传出身份验证 Cookie 的可选域。此属性的默认值为空字符串。 |

`<forms>` 元素可以包含一个 `<credentials>` 元素，该元素允许您指定使用 Forms 身份验证时用户的凭据。`<credentials>` 元素有一个名为 `passwordFormat` 的属性。此属性指以加密状态存储密码的格式。此属性可以采用以下值：

- `Clear` – 指示密码未加密；而是以纯文本形式存储
- `SHA1` – 指示密码使用 SHA1 哈希算法加密，这是默认值
- `MD5` – 指示密码使用 MD5 哈希算法加密

`<credentials>` 元素可以有三个子元素：`<clear>`、`<remove>` 和 `<user>`。表 36.17 列出了这三个子元素及其语法：

### 表 36.17：`<credentials>` 元素的子元素

| Child Element | Description | Syntax |
|---|---|---|
| `<clear>` | 允许您清除所有继承的连接字符串的引用。这些元素允许您仅使用当前用户创建的连接字符串。 | `<clear/>` |
| `<remove>` | 允许您从可用凭据中删除特定用户的引用。 | `<remove name="userName"/>` |
| `<user>` | 允许您定义 Web 应用程序的用户。 | `<user name="userName" password="password"/>` |

请注意，`<credentials>` 元素中可以有多个 `<user>` 元素。如果请求访问 Web 应用程序的用户具有其中任何一个用户名和密码组合，则该用户将成为已通过身份验证的用户。如果您已为 `<authentication>` 元素的 `mode` 属性指定了 `Passport` 值，则需要将 `<passport>` 元素定义为 `<authentication>` 元素的子元素。`<passport>` 元素只有一个名为 `redirectUrl` 的属性。此属性指用户被重定向到 Microsoft Passport 进行身份验证的 URL。此属性的默认值为 `internal`。

## `<authorization>` 元素

如您所知，身份验证后，用户需要获得授权才能访问和使用 ASP.NET 应用程序。您可以在 `web.config` 文件中使用 `<authorization>` 元素来指定希望为 Web 应用程序实现的授权类型。在 `<authorization>` 元素中，您可以指定已通过身份验证的用户必须具有的用户名和/或角色，才能在 Web 应用程序中执行操作。与 `<authentication>` 元素类似，您可以在 Web 应用程序、网站、网页或任何子目录的 `machine.config` 或 `web.config` 文件中定义 `<authorization>` 元素。

`<authorization>` 元素也出现在 `<system.web>` 元素中。`<authorization>` 元素的语法如下：

```
<authorization>
  <allow users="comma-separated list of users"
        roles="comma-separated list of roles"
        verbs="comma-separated list of verbs"/>
  <deny users="comma-separated list of users"
        roles="comma-separated list of roles"
        verbs="comma-separated list of verbs"/>
</authorization>
```

在上述语法中，您可以看到 `<authorization>` 元素没有任何属性，但可以有两个子元素：`<allow>` 和 `<deny>`。`<allow>` 元素允许您指定有权访问 Web 应用程序的用户、角色和 HTTP 传输方法。另一方面，`<deny>` 元素允许您指定被拒绝访问 Web 应用程序的用户、角色和 HTTP 传输方法。这两个元素可以具有三个属性，如表 36.18 所列：

### 表 36.18：`<allow>` 和 `<deny>` 元素的属性

| Attribute | Description |
|---|---|
| Users | 允许您指定被授予/拒绝访问 Web 应用程序的用户名的逗号分隔列表。此属性的默认值为星号 (`*`)，表示所有已通过身份验证的用户都有/没有权限访问 Web 应用程序。您还可以使用问号 (`?`) 仅允许/拒绝匿名用户访问。 |
| Roles | 允许您指定被授予/拒绝访问 Web 应用程序的角色的逗号分隔列表。空字符串 (`""`) 表示没有角色的用户被授予/拒绝访问。 |
| Verbs | 允许您指定拥有/没有访问 Web 应用程序权限的 HTTP 传输方法的逗号分隔列表。您可以指定的 HTTP 传输方法包括 `GET`、`POST`、`DEBUG` 和 `HEAD`。 |

#### 注意

如果要引用计算机上的用户或角色，可以使用点 (`.`) 表示当前计算机。这仅适用于 Windows 用户帐户。

### 提示

建议不要将 `<deny>` 元素放在 `<allow>` 元素之前，因为允许或拒绝访问取决于 `<authorization>` 元素中指定元素的顺序。例如，如果您按如下方式指定 `<deny>` 元素：

```
<authorization>
  <deny users=""/>
  <allow users="TestUser"/>
</authorization>
```

The `<allow>` element is rendered ineffective, and no access is given to the TestUser user.

## `<location>` Element

你知道如何在 `web.config` 文件（根级、应用程序级或目录级）中使用 `<authentication>` 和 `<authorization>` 元素来帮助你保护整个 ASP.NET Web 应用程序（们）。现在，考虑一种情况，你只想保护 Web 应用程序中的特定范围的 Web 页面。在这种情况下，而不是使用 `<authentication>` 和 `<authorization>` 元素，你可以使用 `<location>` 元素。`<location>` 元素允许你将某些配置设置应用于特定的 Web 应用程序或页面（或一系列 Web 页面）。你也可以使用 `<location>` 元素来保护特定的 Web 资源，例如虚拟目录或图像。

在 `web.config` 文件中，`<location>` 元素可以出现在 `<configuration>` 元素内。`<location>` 元素可以包含任何子元素来指定给定 Web 应用程序、页面或资源的设置。`<location>` 元素的语法如下：

```xml
<location allowOverride="true|false" path="Path">
  <!-- child elements -->
</location>
```

在前面的语法中，`<location>` 元素有两个属性：

- `path` – 指你想要保护或应用任何其他配置设置的特定 Web 应用程序、页面或资源。如果省略此属性或将其设置为空字符串，则安全（或配置）设置适用于当前目录及其所有子目录。
- `allowOverride` – 指安全（或配置）设置是否可以在子目录的 `web.config` 文件中被覆盖。它可以有 `true` 或 `false` 作为其值。如果为 `true`，则设置可以在子目录中被覆盖；如果为 `false`，则设置不能被覆盖。此属性的默认值是 `true`。

## NOTE

你可以在 `path` 属性中使用 `~/` 来表示当前应用程序根目录。例如，考虑以下代码：

```xml
<location path="~/CustomerLists/Customer.xls">
  <system.web>
    <authorization>
      <deny users="TestUser"/>
    </authorization>
  </system.web>
</location>
```

在前面的代码中，`TestUser` 用户被拒绝访问位于当前 Web 应用程序根目录的 `CustomerList` 目录中的 `Customer.xls` 文件。

## The `<identity>` Element

`<identity>` 元素允许你指定 Web 应用程序的身份。当你想在 Web 应用程序中实现模拟时，它很有帮助。你可以在根级、应用程序级或目录级的 `web.config` 文件中使用 `<identity>` 元素。`<identity>` 元素可以出现在 `web.config` 文件的根级、应用程序级或目录级的 `<system.web>` 元素中。`<identity>` 元素的语法如下：

```xml
<identity impersonate="true|false" userName="domain\userName" password="<secure password>"/>
```

在前面的语法中，`<identity>` 元素有三个属性：

- `impersonate` – 指是否使用客户端模拟。此属性可以有 `true` 或 `false` 作为其值。此属性的默认值是 `false`，这意味着不使用模拟。如果你将属性设置为 `true`，则在每次请求上都会使用模拟。
- `userName` – 指在启用模拟时要使用的用户名。
- `password` – 指在启用模拟时要使用的密码。

现在，让我们来看一下在为 `ActiveDirectoryMembershipProvider` 定义 `<provider>` 元素时你需要设置的一些常见 `<provider>` 元素属性。表 36.19 列出了 `<provider>` 元素的属性：

### Table 36.19: The Attributes of the `<provider>` Element

| Attribute | Description |
|---|---|
| connectionPassword | 指定用于访问 Active Directory 数据存储的密码。此属性确保访问 Active Directory 数据存储的用户是经过身份验证的用户。 |
| connectionStringName | 指定在 `web.config` 文件的 `<connectionStrings>` 元素中创建的连接字符串的名称。此连接字符串允许你对 Active Directory 数据存储执行创建、更新、获取和验证操作。 |
| connectionUsername | 指定用于访问 Active Directory 数据存储的用户名。此属性确保访问 Active Directory 数据存储的用户是经过身份验证的用户。 |

> **Note**  
> 如果你设置了 `connectionUserName` 属性，请确保也为 `connectionPassword` 属性指定了值。同样，如果你设置了 `connectionPassword` 属性，请确保也为 `connectionUserName` 属性指定了值。

以下代码说明了 `ActiveDirectoryMembershipProvider` 的配置：

```xml
<membership defaultProvider="ADMembershipProvider">
  <providers>
    <add
      name="ADMembershipProvider"
      type="System.Web.Security.ActiveDirectoryMembershipProvider, System.Web, Version=2.0.0.0, Culture=neutral, PublicKeyToken=b03f5f7f11d50a3a"
      connectionStringName="ActiveDirectoryCS"
      connectionUsername="<domainName>\administrator"
      connectionPassword="pass"/>
  </providers>
</membership>
```
