连接查询 `JOIN QUERY` 是传统数据库系统中中最昂贵且最复杂的分析工具之一。随着各种数据集合的指数级增长，NoSQL 数据存储已成为大数据的主流解决方案。然而，在缺乏强索引支持的情况下，连接操作符在针对海量数据进行查询时变得更加更具挑战性。正如 Facebook `[1]` 和 Google `[2]` 报告所示，底层数据量达到了数百 TB 甚至 PB 级。在这些场景下，由于扩展性不佳且容错性差，传统分布式或并行数据库的解决方案是不可行的。研究人员已经对分布式数据上的不同类型连接操作进行了了密集研究，例如相似性连接、集合连接、模糊连接，所有这些都侧重于通过探索云平台 `MapReduce` 计算框架的大规模并行性来实现高效的连接查询。在本章中，我们探索了多路广义连接查询的高效处理，即“复杂连接”，它们被广泛应用于各种实际分析场景，例如查询资源描述框架 `RDF`、从生物化学数据中进行特征选择。复杂连接的实质变化在于，在给定处理单元的情况下，将复杂查询映射到多个并行任务，并按照良好的调度顺序执行它们，从而使总处理时间跨度最小化。在本章中，我们关注云平台上复杂连接查询的评估，并结合案例研究详细阐述了高效的简单协议和 RDF 查询语言 `SPARQL` 查询处理以及多路 Theta 连接的评估。

### 9.1 引言

多路连接是包括知识发现和数据挖掘在内的许多应用中重要且频繁使用的操作。由于连接操作开销巨大，特别是在大型数据集和/或多维数据上，多路连接变成了一项更为昂贵的操作。尽管一些研究人员致力于不同类型两对连接的高效评估，但令人惊讶的是，在多路连接方面的努力很少。

在处理极大规模数据时，使用无共享架构的集群，`MapReduce` 的引入是为了提供一种简单且强大的分布式计算范式。`MapReduce` 架构也提供了良好的扩展性和容错性。在过去几年里，工业界和学术界对 `MapReduce` 的支持日益增加。

### 9.2 背景

#### 9.2.1 MapReduce 基础

`MapReduce` 是 Google 引入的一种编程框架，用于在海量数据集例如爬取的文档或 Web 请求日志上进行并行计算。海量数据需要分布在大量的机器节点上。每个参与节点都贡献存储源，并且它们都连接到同一个分布式文件系统。此外，每台机器在相同的本地存储数据上执行相同的计算，从而实现了大规模的分布式和并行处理。`MapReduce` 框架处理了所有关于并行化、数据分布和分区容错的底层细节，而用户只需关注在每台机器上执行的本地计算。这些计算分为两个阶段：Map 阶段和 Reduce 阶段。分配 Map 阶段的节点以本地数据作为输入，并处理产生存储在本地的中间结果。执行 Reduce 计算的节点接收 Map 的中间输出，并进行合并和处理以产生最终结果，然后存储在分布式文件系统中。

### 9.3 案例研究 1：多路 theta 连接处理

实践中的数据分析查询通常涉及多路连接操作，其中连接条件可以定义为属于 `<, <=, >=, <>` 的二元函数 theta，即 theta 连接。与等值连接相比，它在关系描述上更通用、更丰富，并在数据分析查询中异常实用。考虑以下应用场景：

**示例 1：** 假设我们有 `n` 个城市 `{c_1, c_2, ..., c_n}`，以及任意两个城市 `c_i` 和 `c_j` 之间的所有航班信息 `FI_ij`。给定一个城市序列 `c_s, ..., c_p` 以及每个城市 `c_p` 必须落在区间 `L_i = [l_i1, l_i2]` 内的停留时长，找出所有的旅行计划。

这是一个实际查询，我们假设 `FI_ij` 是一个包含航班号、出发时间 `dt` 和到达时间 `at` 的表。例如，上述请求可以通过对 `FI_{s,s+1},...,FI_{p-1,p}` 执行多路 theta 连接操作，通过指定连续航班之间的时间间隔符合特定城市的停留要求来轻松地回答。例如，`FI_{s,s+1}` 和 `FI_{s+1,s+2}` 之间的 `θ` 函数为 `FI_{s+1}at + L_i < FI_{s+2}dt`。

事实上，随着数据库技术的发展，评估多路 theta 连接一直以来是一个具有挑战性的问题。早期的工作如参考文献 20–23 详细阐述了问题的复杂性和评估策略。然而，它们的解决方案无法扩展到海量数据的多路 theta 连接。在本案例研究中，我们展示如何利用 `MapReduce` 解决方案框架在无共享环境中高效地评估多路 theta 连接查询。

#### 9.3.1 解决方案概述

我们关注的问题如下：给定数量的处理单元可以运行 Map 或 Reduce 任务，将多路 theta 连接映射到若干 Reduce 作业，并按照良好的调度顺序执行它们，使得总处理时间最小。解决这个具有挑战性的问题的解决方案包含两个核心技术。第一种技术是，给定一个多路 theta 连接查询，我们检查所有可能的分解计划并估计每个计划的最小执行成本。特别是，我们制定了正确分解原始多路 theta 连接查询的规则，并研究了使用一个 `MapReduce` 评估多个连接条件函数的最优解决方案。第二种技术是，在计算单元有限且存在可能的评估作业池的情况下，我们对作业选择做出决策，以尽可能快速评估查询。

具体而言，我们在 9.4 节中提出了一种资源感知的 `(key,value)` 对分布方法，用于用一个 Reduce 作业评估链型多路 theta 连接查询，这保证了网络数据拷贝量的最小化，以及 Reduce 任务之间负载的均衡。此外，我们还建立了分解多路连接查询的规则。使用我们提出的成本模型，我们可以确定多路连接查询应该用多个 `MapReduce` 作业还是单个 `MapReduce` 作业进行评估。
