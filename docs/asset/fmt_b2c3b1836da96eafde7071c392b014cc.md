
### F.3 运算符和函数

C 运算符和函数提供了下表所示的 IEC 60559 要求的和推荐的功能。

- `+`、`-`、`*` 和 `/` 运算符提供了 IEC 60559 的加、减、乘、除运算。

- `<math.h>` 中的 `sqrt` 函数提供了 IEC 60559 的平方根运算。

- `<math.h>` 中的 `remainder` 函数提供了 IEC 60559 的取余运算。`<math.h>` 中的 `remquo` 函数提供了相同的运算但带有额外信息。

- `<math.h>` 中的 `rint` 函数提供了 IEC 60559 运算，将浮点数舍入为整数值（相同精度）。`<math.h>` 中的 `nearbyint` 函数提供了 ANSI/IEEE 854 附录中推荐的 `nearbyinteger`。

- 浮点类型的转换提供了 IEC 60559 的不同浮点精度的转换。

- 从整数到浮点类型的转换提供了 IEC 60559 的整数到浮点数转换。

- 从浮点到整数类型的转换提供了类似于 IEC 60559 的转换，但始终向零舍入。

- `<math.h>` 中的 `lrint` 和 `llrint` 函数提供了 IEC 60559 转换（遵循定向舍入模式），从浮点到 `long int` 和 `long long integer` 格式。`lrint` 和 `llrint` 函数可用于从浮点到其他整数格式的 IEC 60559 转换。

- 浮点常数的翻译时间转换以及 `<stdlib.h>`、`<stdio.h>` 和 `<char.h>` 中的 `strtod`、`strtol`、`fprintf`、`ff` 和相关库函数提供了 IEC 60559 二进制转换。`<stdlib.h>` 中的 `stdlib` 提供了 ANSI/IEEE 854 附录中推荐的 `conv` 函数。

> 359) 由于 IEC 60559 运算创建的 NaN 总是静性的，因此静性 NaN（同无穷大）对于运算的封闭是足够的。

- 关系和相等运算符提供了 IEC 60559 比较。IEC 60559 指出需要额外的比较谓词，以便编写考虑到 NaN 的代码。`<math.h>` 中的比较宏（`isgreater`、`isgreaterequal`、`isless`、`isequal`、`issgreater` 和 `isunordered`）补充了语言运算符以解决这一需求。`isgreater` 和 `unordered` 宏分别提供了 IEC 60559 附录中推荐的 `< >` 谓词和无序谓词的静默版本。

- `<fenv.h>` 中的 `fegetexcept`、`fesetexcept` 和 `fetestexcept` 提供了管理浮点状态的设施。

将字符序列转换为浮点类型的此类函数会遵循舍入方向。因此，由于舍入方向可能是向上或向下，实现可能无法通过对已转换的无符号序列取反来转换带负符号序列。

## F.6 返回语句

如果返回表达式在与返回类型不同的浮点格式下求值，则该表达式将按照赋值$^{362}$ 的方式转换为函数的返回类型，并将结果值返回给调用者。

## F.7 收缩表达式

- 收缩表达式（Contracted expression）会进行正确的舍入（一次），并且对无穷大、NaN、符号零、非正数和舍入方向的处理与 IEC 60559 涵盖的基础算术运算保持一致。

### F.8 浮点环境

在 `<fenv.h>` 中定义的浮点环境包括 IEC 60559 浮点异常状态标志位和定向舍入控制模式。它还包括 IEC 60559 的动态舍入精度和陷阱启用模式。

### F.8.1 环境管理

60559 要求浮点操作隐式地引发浮点异常状态标志位，并且舍入控制可以显式地影响浮点操作的结果值。当 `FENV_ACCESS` 编译指令（定义在 `<fenv.h>` 中）的状态为“on”时，这些对浮点状态的更改被视为尊重顺序点的副作用。$^{364}$

362 赋值移除了任何额外的范围，且不需要动态舍入精度和陷阱启用模式。

363 本规范不要求动态舍入精度和陷阱启用模式。

364 如果 `FENV_ACCESS` 编译指令的状态为“off”，实现可以自由假设浮点控制模式将是默认值，且浮点状态标志位将不会测试，这允许进行某些优化（参见 F.9）。

### F.8.2 翻译

在翻译期间，IEC 60559 的默认模式生效：

- 舍入方向模式为舍入最近值。

- 舍入精度模式（如果支持）被设置为结果不被截短。

- 在所有浮点异常上都禁用陷阱或停止（如果支持）。

## 建议实践

实现应当为每个翻译期间的浮点异常（除“不精确”外）产生诊断消息；365) 随后实现应继续对程序的翻译。

### F.8.3 执行

在程序启动时，按照 IEC 60559 的规定初始化浮点环境：

- 清除所有浮点异常状态标志位。

- 舍入方向模式为舍入最近值。

- 动态舍入精度模式（如果支持）被设置为结果不被截短。

- 在所有浮点异常上都禁用陷阱或停止（如果支持）。

## F.9.2 表达式变换

`x/2 ↔ x×0.5` 虽然涉及不精确常数的相似变换通常不会产生数值等价的表达式，但如果常量是精确的，则可以在 IEC 60559 和其他能够完美舍入的机器上进行此类变换。

`1×x` 和 `x/1→x` 表达式 `1×x`、`x/1` 和 `x` 是等价的（在 IEC 60559 机器等上）。³⁶⁸

`x/x→1.0` 如果 `x` 可以为零、无穷或 NaN，则表达式 `x/x` 和 `1.0` 不是等价的。

`x−y→x+(-y)` 表达式 `x−y`、`x+(-y)` 和 `(-y)+x` 是等价的（在 IEC 60559 机器等上）。

`x−y→(−y−x)` 表达式 `x−y` 和 `(-y−x)` 不是等价的，因为 `1−1` 是 `+0`，而 `(-1−1)` 是 `-0`（默认舍入下）。³⁶⁹

`x−x→0.0` 如果 `x` 是 NaN 或无穷，则表达式 `x−x` 和 `0.0` 不是等价的。

`0×x→0.0` 如果 `x` 是 NaN、无穷或 `-0`，则表达式 `0×x` 和 `0.0` 不是等价的。

`x+0→x` 如果 `x` 是 `-0`，则表达式 `x+0` 和 `x` 不是等价的，因为 `(-0)+ (+0)` 产生 `+0`（默认舍入方向下），而不是 `-0`。

`x−0→x` 当舍入方向为向下（向 `∞` 方向）时，`(+0)−(+0)` 产生 `-0`；但在其他情况下，`(-0)−(+0)` 总是产生 `-0`；如果 `FENV_ACCESS` 伪指令的状态为“off”（即默认舍入），则实现可以将 `x−0` 替换为 `x`，即使 `x` 可能是零。

`-x ↔0−x` 如果 `x` 是 `+0`，则表达式 `-x` 和 `0−x` 不是等价的，但 `0−(+0)` 产生 `-0`（除非舍入方向为向下）。

368 本规范未要求对带符号 NaN 进行严格支持，这将导致这些其他移除算术运算符的变换失效。

369 IEC 60559 规定了符号零以在某些不连续点处保持数学恒等性。示例包括：

`1/(1±∞)` 是 `±∞`

对于复数 `z`，`conj(sqrt(z))` 等于 `csqrt(conj(z))`。

## F.9 关系运算符

`$x \neq x \rightarrow false$` 如果 `$x$` 是 NaN，则表达式 `$x \neq x$` 为真。

`$x = x \rightarrow true$` 如果 `$x$` 是 NaN，则表达式 `$x = x$` 为假。

`$x < y \rightarrow isless(x,y)$`（对于 `$\le, >, \ge$` 亦如此）。尽管在数值上，这些表达式不是等价的，因为当 `$x$` 或 `$y$` 为 NaN 且 `FENV_ACCESS` 伪指令的状态为“on”时会产生副作用。如果需要额外的代码来为无序情况引起“无效”浮点异常，那么在 `FENV_ACCESS` 伪指令的状态为“off”的情况下，可以执行这种变换。

关系运算符的含义应当保持。这包括处理由源代码表示的无序情况。

示例

```
// 如果 a 和 b 无序关系，则调用 g 并抛出“invalid”异常
if (a < b)
    f();
else
    g();
```

这不等价于：

```
// 如果 a 和 b 无序关系，则调用 f 并抛出“invalid”异常
if (a >= b)
    g();
else
    f();
```

也不等价于：

```
// 如果 a 和 b 无序关系，则调用 f 而不抛出“invalid”异常
if (isgreaterqual(a,b))
    g();
else
    f();
```

同样不等价于（除非 `FENV_ACCESS` 伪指令的状态为“off”），

```
// 如果 a 和 b 无序关系，则调用 g 而不抛出“invalid”异常
if (isless(a,b))
    f();
else
    g();
```

但等价于：

```
if (!a < b))
  g();
else
  f();
```
