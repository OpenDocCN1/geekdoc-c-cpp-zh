
创建 `books` 表的代码拆分如下：

- 第一部分称为 `title_id`，是一个数字/整数。`auto_increment` 关键字是一个特殊值，在插入行期间自动分配给此字段。
- `title` 列包含内容多达 150 个字符的内容。
- `pages` 列是一个整数整数。
- `PRIMARY KEY` 属性告诉 MySQL 哪个字段是键值。

核心键必须是唯一的且不为 `NULL`。所有表都应该有一个主键，因为当你在从多个表中检索信息并再次利用键属性访问特定列时，它允许 MySQL 加速访问。MySQL 通过使用一种名为索引的特殊信息结构来实现这一点。索引的作用就像查找记录的快捷路径，类似于图书馆中的分类索引。要验证你的表列，请使用 `DESCRIBE`：

```
DESCRIBE books;
```

### 向表中添加数据

`INSERT` 命令用于包含信息。其语法为 `INSERT INTO table columns ([columns]) VALUES ([values]);`。此语法显示了应该将哪些表信息添加到哪些列中，以及值的列表。如果没有指定段，则值必须与创建表时定义的顺序相同在同一个请求中（只要你没有跳过任何段的值）。使用 SQL 命令处理信息以填充数据库时有特定的原则：

- 数字不应被引用。
- 字符串值应当可靠地引用。
- 日期和时间值应当可靠地引用。
- 函数不应被引用。
- `NULL` 永远不应被引用。

最后，如果列没有给出值，它被视为 `NULL`，除非该段存在默认值。如果某个段不能为 `NULL`（它是用 `NOT NULL` 创建的）且你没有指定值，则会发生错误。

例如：

```sql
INSERT INTO books VALUES (1,"Linux in a Nutshell",112);
INSERT INTO authors VALUES (NULL,1,"Ellen Siever");
INSERT INTO authors VALUES (NULL,1,"Aaron Weber");
```

如果没有错误，你将得到：

```sql
mysql> INSERT INTO books VALUES (1,"Linux in a Nutshell",112);
Query OK, 1 row affected (0.00 sec)
mysql> INSERT INTO authors VALUES (NULL,1,"Ellen Siever");
Query OK, 1 row affected (0.00 sec)
mysql> INSERT INTO authors VALUES (NULL,1,"Aaron Weber");
Query OK, 1 row affected (0.00 sec)
```

# 第 10 章：数据库最佳实践

既然你已经运行了 MySQL 并创建了数据库，我们应该谈谈数据库设计和保护你的数据库。正如你可能已经意识到的，对数据进行备份是非常关重要的。将 MySQL 加入 PHP 并为你的动态网站整合应用程序是一个极不起的开始。然而，准确地构建你的数据库将非常有帮助。如果你拥有安全性、信息完整性和备份，你就拥有了数据库最重要的部分。我们将在稍后的章节中讨论安全性。

## 10.1 数据库设计

正确地设计数据库对于你应用程序的卓越性能至关重要。就像把打印机放在离办公室很的地方是无效的一样，在糟糕的连接中设置信息会降低工作效率，因为你的数据库服务器将浪费时间搜索信息。在考虑数据库时，请考虑当数据库被使用时会进行哪些类型的查询。例如，某个待购物品的详情是什么？或者，这是否是一个合法的用户名和密码？

### 关系型数据库

MySQL 是一个关系型数据库。关系框架的一个关键元素是信息可以分布在几个表中，而不是像我们的电话目录示例那样。相关信息存储在孤立表中，并允许你通过利用两个表的键将它们组合起来。键就是表之间的连接。选择主键是在设计另一个数据库时你做的最基础选择中最突出的之一。

你必须理解的核心思想是，你必须确保所选的键是唯一的。如果可能两条记录（过去、现在或未来）在某个属性上具有相同的值，请不要使用该属性作为主键。从另一个表中计数键字段以形成表与表之间的连接被称为外键关系，类似于主管与工人，或客户与买家之间的关系。

由于你有了存储相关信息的孤立表，你必须考虑每个表中与不同表中项目相对应的项目数量。

### 关系类型

数据库连接通过以下分类进行量化：

- 一对一连接
- 一对多连接
- 多对多连接

我们将讨论这些每种连接并给出示例。如果你在考虑关系时考虑到家庭结构，那么你就掌握了要领。当你只和一位父母在一起度过时，这是一种特定的关系；当你和父母双方在一起度过时，这是另一种关系。当你获得一个重要的伴侣，你们每一个人——父母、你和你的伴侣——一起做某事时，这就是另一种关系。这与整体的相似性没有区别。所有这些不同类型的连接类似于存放连接流的特定容器。在数据库世界中，这就是你创建的信息。

### 一对一关系

在一对一关系中，每个项目仅与另一个项目相关联。在在线书店的实例中，客户与其送货地址之间存在协调关系。每个客户必须恰有一个收货地址。

### 标准化

思考你的信息如何连接以及安排它们的最有效方法被称为标准化。信息的标准化是根据连贯的关系将其拆分，以尽可能地减少信息的重复。在大多数情况下，复制的信息会浪费空间并使维护成为一个问题。如果你更改了复制的数据，可能会漏掉某部分并导致数据库中出现不一致。然而，拥有很多东西也是件好事；但数据库将每条信息都放在它们自己的表中将花费大量的处理时间，并且查询会变得复杂。目标是在中间找到平衡。虽然电话目录示例非常简单，但你通过网站准备的类型信息可以从智能收集相关信息中极大获益。我们继续使用在线书店网站。网站需要了解客户信息，包括登录、地址和电话号码，以及关于书籍的数据，包括标题、作者、页数和我们获取的时间。从将大部分此类数据放在一个表中开始。虽然将信息合并到一个表中似乎是一个明智的主意，但它会浪费数据库空间并使信息更新变得重复。所有的客户信息在每次购买时都会重复。一本书受限于两个作者。在这种情况下，我们使用的是具有两个作者的书，而不是仅仅一个。此外，如果客户搬家，他的位置就会改变，表中的每个条目都必须重新设计。

### 规范化的类型

要标准化数据库，请从最基本的标准化原则开始并规律地进行。标准化的过程分为三个阶段，称为结构。

第一步称为第一范式（`1NF` 或 `FNF`），必须在第二范结构之前完成。同样，第三种普通结构不能在第二种结构之前完成。标准化过程包括使你的信息与三个动态结构保持一致。

#### 第一范式

为了使你的数据库符合第一范式，它必须满足三个要求。任何表不能有包含相同类型信息的重复段，且所有段必须包含唯一值。必须有一个主键来唯一地标识列。它可以是一个段或几个段，取决于预期用多少个段来唯一地标识列。

#### 第二范式

虽然第一范式处理了扁平列中信息的重复，但第二范式（或 `2NF`）处理的是垂直段中信息的重复。

普通结构是动态的。为了实现第二范式，你的表必须处于第二范结构中，你必须识别任何在多个列中重复其属性的段。这些段应该设置在它们自己的表中，并通过第一个表中的键值进行引用。另一种想法是，如果表中存在不属于主键的属性。

#### 第三范式

如果你遵循了第一范式和第二范式的过程，你就不需要对你的数据库进行任何操作来满足第三范式（或 `3NF`）的原则。在第三范式中，你正在寻找表中不完全依赖于主键但依赖于表中另一个值的信息。这适用于你的表何处并不显而易见。在表 8-8 中，地址的部分可以被认为与客户没有直接关联。街道地址取决于邮政分区，邮政分区最后城市取决于州。第三范式要求将这些拆分到孤立表中。

正如你所看到的，第三范式消除了更多的信息重复，尽管是以牺牲易用性和性能为代价的。在这个示例中，你真的预计城市和街道名称会频繁更改吗？在这种情况下，第三范式仍然防止了城市和街道名称的拼写错误。因为这是你的数据库，你决定标准化之间的平衡水平以及你数据库的速度或易用性。

## 10.2 数据的备份与恢复

数据类型是对特定类型数据的分类。当你阅读时，你已经习惯了某些形式，例如字母和数字。因此，考虑到你利用了图像、数字和字母，识别不同类型的信息是非常简单的。你起初就可以判断一个数字是比率、时期还是现金的度量。帮助你理解比率、时间或现金度量的图像就是该信息的种类。数据库使用代码来保持对其所存储的不同类型信息的知晓。

许多编程语言要求软件设计者声明每个信息对象的数据类型，而大多数数据库框架都要求客户端指定每个信息字段的类型。可用的信息类型在不同的编程语言之间、在不同的数据库应用程序之间会有所变动。尽管如此，三种基本信息类型——数字、日期/时间字符串——仍然以某种结构的形式存在。

数值型 ID 字段结合大量的特殊数字，提供了一种确保键字段是唯一性的方法。在创建表时指定 `auto_increment` 值是为表记录生成唯一 ID 的极佳方法。例如，如果有两个名为 John Smith 的作者，而你使用他们的名字作为键，那么在识别你使用的是哪一个 John Smith 时就会遇到问题。保留其中一个的键是确保你在数据库中拥有正确信息的关键部分。

### 备份与恢复数据

事实上，即使是维护得最好的数据库偶尔也会出现问题。工具故障，特别是工具故障，真的会破坏你的网站页面。由于你正在使用数据库，仅仅下载 Web 服务器上的文档（HTML、PHP 和图片）是不够的。没有比告诉你的 Web 客户端他们需要返回数据（例如他们的记录）或需要重新制作列表项目更糟糕的了。拥有一个完整的备份可以在 60 分钟的停机时间与需要重新整理数据之间产生巨大差异。

### 复制数据库文件

你同样对你的 MySQL 数据库数据文件进行简单的文档备份，就像你下载 HTML 和 PHP 文档一样。如果你下载下载，就可以下载 MySQL 数据库文档。

我们不建议使用这种策略将数据库从一台机器迁移到另一台服务器，因为 MySQL 的不同版本可能预期这些文档具有不同的设计。MySQL 将其数据文件存储在一个特殊的信息注册表中，在 Windows 上通常位于 `C:\Program Files\MySQL\MySQL Server 4.1\data\[database_name]\`，在 Unix 变体（例如 Linux 和 Mac OS X）上位于 `/var/lib/mysql`。在执行复制备份之前关闭 MySQL 服务，以确保在操作时所有文档都来自同一时间点。

要使用你当前的数据文件完全下载并恢复 MySQL 数据库，所有文档必须在下载时的同一个注册表中进行替换。然后必须重启数据库。

### mysqldump 命令

使用 MySQL 命令行创建完整的数据库备份是理想的。你用于下载和恢复的相同工具也用于更改阶段或将数据库从一台服务器迁移到另一台；`mysqldump` 创建包含所需的 SQL 语句的内容文档，用于重建数据库对象并补充信息。`mysqldump` 命令从命令行运行，并接收下载单个表、单个数据库或所有的参数。命令语法为：

```
mysqldump -u client -p objects_to_backup
```

`mysqldump` 命令创建的备份输出到标准输出（默认打印到屏幕）。指定一个对你需要下载的对象具有访问权限的客户端。将被提示该客户端的相关密码。

使用大于符号 `>` 后跟一个文件名将此输出重定向到文档。

### 备份

我们将向你演示如何从命令行备份一个名为 `store` 的数据库。

```
mysqldump -u root -p store > my_backup_of_store.sql
```

这告诉 `mysqldump` 以 root 客户端登录数据库并下载 store 数据库。你将被提示输入设置的 root 密码。命令的输出通过重定向字符（也称为大于符号 `>`）存放在名为 `my_backup_of_store.sql` 的文件中。

### 恢复 MySQL 备份

好消息是，从 `mysqldump` 记录恢复你的数据库并不困难。备份文件的内容实际上是 SQL 语句，因此可以由 MySQL 命令行客户端准备恢复下载的信息。

如果你使用 `mysqldump --all-databases` 将你的数据库备份到名为 `my_backup.sql` 的文件，你可以恢复你的数据库：

```
mysql -u root -p < my_backup.sql
```

如果你对单个数据库进行了特定备份，情况会更复杂一些。要恢复此类备份文件，请使用 `-D` 命令行开关：

```
mysql -u root -p -D store < my_backup.sql
```

既然你已经知道如何恢复默认转储记录，我们可以继续学习关于导出和导入信息的其他应用。

### 与其他格式一起

尽管处理基于 SQL 的记录是有益的，但有时你可能需要以不同的配置保存信息。例如，处理信息列表的一种策略是 CSV（逗号分隔值）格式。`mysqldump` 命令支持这种配置。你只需要指定 `-no-create-info`、`-tab` 以及 `-fields-terminated-by` 参数：

```
mysqldump -u root -p -no-create-info -tab=/home/jon -fields-terminated-by=','
```

这告诉 `mysqldump` 为每个表生成单独的文档。它们都将被放在 `/home/jon`。每个文件的名称将是表名。每个文件包含由命令行指定的逗号字符（`,`）分隔的记录。

### mysqlimport 命令

当你设置数据库时，可能需要从另一个数据库或 CSV 格式的电子表格获取信息。例如，如果你正在为书籍设置数据，你可能获取当前的书籍索引。示例 8-2 显示了书籍。

要导入示例 8-2 中的信息，请使用 `mysqlimport` 命令：

```
mysqlimport -u root -p --fields-terminated-by= books.txt
```
