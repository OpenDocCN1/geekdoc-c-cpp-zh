
Cortex-M3 和 M4 包含单单元写缓冲区。这允许 CPU 将条目写入缓冲区，并在缓冲区完成对实际 RAM 或外设寄存器的写入时继续执行下一指令。这避免了处理器在等待写入完成时停顿。如果写缓冲区满了，CPU 将被迫等待写入完成。尽管这通常对于应用程序代码来说是透明的，但在某些情况下，有必要等待对 RAM 或外设寄存器的写入完成后再继续程序执行。例如，当我们启用微控制器的外部总线时，有必要等待缓冲区完成对外设寄存器的写入后再尝试访问外部总线上的内存。Cortex-M 处理器提供了一些内存屏障指令来处理这些情况。

## 内存屏障指令

内存屏障指令在指令写入阶段完成之前停止应用程序代码的执行。它们用于在继续执行应用程序代码之前确保关键段已完成。

### 表 3.2 内存屏障指令

| 指令 | 描述 |
|---|---|
| `DMB` | 在进行新的内存访问之前确保所有内存访问已完成 |
| `DSB` | 在执行下一条指令之前确保所有内存访问已完成 |
| `ISB` | 确保在执行下一条指令之前所有之前的指令已完成。这还会刷新 CPU 流水线 |

## 内存访问

Cortex-M 指令集包含允许加载和存储 8 位、16 位和 32 位数据的指令。与 ARM7 和 ARM9 不同，16 位和32 位数据不需要对齐在字或半字边界。这为编译器和链接器提供了最大的灵活性，以充分填充 RAM 内存。然而，这种灵活性是有代价的，因为非对齐传输的执行时间更长。非对齐访问有一些限制。Cortex-M 指令集包含加载和存储多字节指令 Load and Store Multiple，它们可以逐个在寄存器和内存之间传输。这需要多个处理器周期，但仅使用 2 位或 4 字节的指令。这允许非常高效的栈操作和块内存拷贝。加载和存储多字节指令仅对字对齐的数据有效。此外，非对齐数据仅用于用户数据，您必须确保栈是字对齐的。`MSP` 值由链接器初始化，但第二个栈指针——进程栈指针 `PSP` 由用户启用并初始化，因此正确设置它取决于您。我们将在第 5 章“高级架构特性”中介绍其用法。

图 3.16 与早期的 ARM7 和 ARM9 CPU 不同，Cortex 处理器可以进行非对齐内存访问。使用编译器和链接器可以充分利用设备 SRAM。

## SysTick 定器

所有的 Cortex-M 处理器都包含一个标准定时器。被称为 SysTick 定器，是一个带有自动重载的 24 位倒计时器。一旦启动，SysTick 定器将从初始值开始倒计时。当它达到零时，会触发中断，并从重载寄存器加载一个新的计数值。该定时器的主要目的是为实时操作系统 RTOS 或其他事件驱动软件产生周期性中断。如果你没有运行 RTOS，也可以作为简单的定时器使用。

SysTick 定器是一个带有自动重载的 24 位倒计时器。它通常用于为 RTOS 调度器提供周期性中断。SysTick 定器的默认时钟源是 Cortex-M CPU 时钟。可能会切换到另一个时钟源，但这取决于你使用的微控制器。虽然 SysTick 定器对于所有 Cortex-M 处理器都是通用的，但它的寄存器在 NVIC 中占据相同的内存位置。

## Cortex-M 架构

### 运行模式

当 Cortex-M CPU 执行背景非中断代码时，CPU 处于名为 Thread 模式线程模式 的运行模式。当触发中断时，NVIC 将导致处理器跳转到适当的中断服务程序。当这种情况发生时，CPU 切换到一个名为 Handler 模式处理程序模式 的新运行模式。在没有 RTOS 的简单应用程序中，这些运行模式之间没有功能区别。你可以从 Thread 模式或 Handler 模式访问微控制器的所有资源。

### 中断处理——进入

当微控制器产生中断线时，NVIC 将导致并行发生两件事。首先，通过总线获取异常向量。这是进入中断服务程序的入口地址。该地址被推入 `R15` 程序计数器，强制 CPU 跳到中断程序的开头。与此同时，CPU 会自动将寄存器 PUSH 推入到栈并在结束时 POP 弹出。此栈帧包含以下寄存器：`xPSR`, `PC`, `LR`, `R12`, `R3`, `R2`, `R1`, `R0`。此栈帧保留了处理器的状态，并为中断服务程序提供 `R0–R3` 使用。如果 ISR 需要更多 CPU 寄存器，它必须将它们 PUSH 到栈并在退出时 POP 出来。

图 3.21 当发生中断或异常时，CPU 会自动压入栈帧。这由 `xPSR`, `PC`, `LR`, `R12` 和寄存器 `R0–R3` 组成。在中断或异常结束时，栈帧会自动弹出。中断进入过程在 Cortex-M3/M4/M7 上需要 12 个周期，在 Cortex-M0 上需要 16 个周期。所有这些动作由 CPU 中的微代码处理。在实践中，你只需将服务程序写成一个“C”函数。

异常向量存储在中断向量表中。中断向量表位于地址空间 `0x00000000` 的开头。前四个字节用于保存 `MSP` 的初始值。栈指针的起始值由编译器和链接器计算。生成的值将在程序构建时被放置在镜像的开头。重位后，该值将自动加载到 `R13` 中以初始化 `MSP`。然后，中断向量表每四个字节具有一个地址位置，并向地址空间向上增长。向量表的前四个字节持有复位处理程序 reset handler 的地址。接之后是处理器异常地址以及每个微控制器中断服务程序的地址。每个微控制器的向量表都是作为启动代码的一部分预定义的。

```asm
AREA_RESET, DATA, READONLY
EXPORT __Vectors
__Vectors
DCD Initial_sp    : 栈顶
DCD Reset_Handler : 复位处理程序
DCD External Interrupts : 窗口看门狗
DCD QG_IRQHandler_Handler : 通过 EXTI 线路检测 PVD
DCD PVD_IRQHandler_Handler : PVD
DCD TAMPER_IRQHandler_Handler : 篡改
DCD RTC_IRQHandler_Handler : 实时时钟
DCD FLASH_IRQHandler_Handler : 闪存
DCD RCC
```

```c
void RTC_IRQHandler(void) {
}
```
