Per-call 实例化服务是默认的实例化服务，只能在进行中激活。在 per-call 实例化服务中，每个客户端请求都会获得一个新的已提交服务实例，即使客户端第二次调用服务也是如此。图 19.1 显示了如何使用 per-call 实例化服务：

![](img/e073a4882197be4ab61103cbe0bcb394_997_0.png)

在图 19.1 中，你可以看到客户端调用代理服务器，后者进一步将调用转发给 WCF 服务。收到调用后，WCF 创建一个服务实例并在其上调用`IDispose.Dispose`方法。方法调用返回后，WCF 调用`IDispose`接口。

要将 per-call 实例化服务配置为服务类型，可以在应用程序中应用`ServiceBehaviorAttribute`属性，并将`InstanceContextMode`属性设置为`InstanceContextMode.PerCall`。下面的代码片段显示了如何配置 per-call 实例化服务：

```csharp
[ServiceBehavior(InstanceContextMode=InstanceContextMode.PerCall)]
class MyWCFService : IMyServiceMode
{
    ...
}
```

在清单 19.1 中，你可以看到`MyWCFMethod()`方法接受`MyWCFClass`类型的参数，用于标识`MyWCFMethod()`方法的实例，如高亮行（Line 1）所示。我们使用了`GetState()`和`SaveState()`方法来检索实例的状态，并在方法调用结束时保存检索到的状态。

Per-call 实例化服务最适合在每个方法调用中需要完成少量工作，并且方法返回后没有更多需要在后台完成的活动的情况下使用。

### Per-session 实例化服务

Per-session 实例化服务指示运行时环境为每个客户端创建一个特定实例。WCF 在客户端和特定服务实例之间维护一个私有会话。当客户端为配置为会话感知的服务创建一个新代理时，客户端获得一个不依赖于该服务任何其他实例的新专用服务实例。获得的实例在客户端需要它时一直保留在服务中。每个私有会话在代理和特定服务实例之间创建唯一的绑定。

**NOTE**

客户端会话每个代理有一个服务实例。如果客户端创建另一个指向相同或不同端点的代理，则第二个代理与新的实例和会话相关联。

服务实例可以维护其状态，因为它在整个会话期间保留在内存中。下面的代码片段显示了如何配置 per-session 实例化服务：

```csharp
[AttributeUsage(AttributeTargets.Interface|AttributeTargets.Class, Inherited=false)]
public sealed class ServiceContractAttribute : Attribute
{
    public bool Session
    {
        get;
        set;
    }
    // More members
}
```

在配置 per-session 实例化服务时，可以使用`Session`属性来支持服务中的会话。默认情况下，`Session`属性的值设置为`false`。如果希望服务支持会话，请将`Session`属性的值设置为`true`，如下面的代码片段所示：

```csharp
[ServiceContract(Session=true)]
Interface IMyServiceMode
{
    ...
    ...
}
```

你可以通过将`ServiceBehaviorAttribute`属性的`InstanceContextMode`属性设置为`InstanceContextMode.PerSession`来使服务实例在整个会话期间保持活动状态，如下面的代码片段所示：

```csharp
[ServiceBehavior(InstanceContextMode=InstanceContextMode.PerSession)]
class MYWCFService: IMyServiceMode
{
    ...
    ...
}
```

### Sharable 实例化服务

在使用 WCF 时，你可能希望将当前会话的状态传递给另一个客户端。你可以通过使用 sharable 实例化服务来实现这一点。与 per-session 实例化服务不同，sharable 实例化服务包含一个额外的方面，即唯一 ID。当第一个客户端使用 sharable 实例化服务创建会话时，它会将实例的 ID 传递给第二个客户端。第二个客户端创建独立的会话但共享同一个实例。

要配置 sharable 实例化服务，请将`ServiceBehaviorAttribute`属性的`InstanceContextMode`属性设置为`InstanceContextMode.Sharable`，如下面的代码片段所示：

```csharp
[ServiceBehavior(InstanceContextMode=InstanceContextMode.Sharable)]
class MyWCFService: IMyServiceMode
{
    ...
    ...
}
```

如果你将服务配置为 sharable，则可以在服务边界之间共享服务实例的实例。这意味着你可以将共享实例的引用从一个客户端传递到另一个客户端。接收实例的客户端需要表示一个以端点地址作为参数的契约。图 19.2 显示了 sharable 实例化服务 Service A 的实例会话如何在服务边界之间共享：

### Singleton 实例化服务

Singleton 实例化服务是一种服务，其中所有客户端都独立连接到 WCF 服务的一个实例，而不考虑它们连接到的服务的端点。因此，这些服务被视为终极 sharable 实例化服务。Singleton 实例化服务的生命周期始于主机创建时，并在主机关闭时结束。使用 singleton 实例化服务不需要维护会话。

要将服务配置为 singleton，请将`ServiceBehaviorAttribute`属性的`InstanceContextMode`属性设置为`InstanceContextMode.Single`，如下面的代码片段所示：

```csharp
[ServiceBehavior(InstanceContextMode=InstanceContextMode.Single)]
class MySingletonService: ...
{
    ...
    ...
}
```
