## 共享程序集的并行执行

并行执行是一种功能，它允许开发人员和用户在 GAC 中安装同一程序集的不同版本，并在不同版本之间不发生任何冲突的情况下使用它们。为了规避冲突，使用了强名称，本章已经结合版本号对强名称进行了讨论。

为了详细说明并行执行的概念，我们假设有两个应用程序——`App1`和`App2`——它们使用了不同版本的`SharedObject`程序集。当`App1`和`App2`需要加载相应版本的程序集时，它们会向 CLR 发送请求。`App1`的请求包含访问 `1.0.0.0` 版本的引用，`App2`的请求包含访问 `1.1.0.0` 版本的引用。CLR 使用程序集清单和应用程序配置文件来标识所请求的版本。标识出版本后，CLR 会搜索请求的版本并将其加载到相应的应用程序中。CLR 会搜索 GAC、代码库和探测路径来查找所需的`SharedObject`程序集，这些内容本章前面已经解释过。

`SharedObject`程序集的新版本（我们之前创建的）通过名为`ASimpleClient.exe.config`的文件绑定到客户端，该文件由配置工具创建以执行绑定操作。你可以在应用程序的`bin\Debug`目录中找到该文件。要了解共享程序集如何执行并行执行，请暂时将配置文件移动到其他文件夹，并从`bin\Debug`目录运行`ASimpleClient.exe`文件。然后，单击`Form1`窗体上的`Call Greetings`按钮。注意，客户端现在使用的是该库的旧版本。这表明，要将客户端绑定到新库，必须使用该配置文件。

现在，你有两个客户端同时运行，使用同一个库的两个不同版本。

请将配置文件恢复到`bin\Debug`目录中，因为在本章后面我们还需要用到它。

## 创建私有程序集

在本主题中，我们将讨论如何创建私有程序集。使用该程序集，我们将直观地公开两个简单的类，如`Class1`和`Class2`。

这些类仅用于演示；两者都有一个名为`Display`的方法，用于显示消息框。你将消息框文本传递给`Class1`的`Display`方法，并将文本和消息框图标传递给`Class2`的`Display`方法。要创建私有程序集，请执行以下步骤：

1. 创建一个名为`PrivateAssembly`的类库应用程序（也可在 CD-ROM 上获得）。

2. 创建两个类`Class1`和`Class2`，每个类都有一个`Display`方法，如清单 33.9 所示：

# 清单 33.9：显示 Class1.cs 文件的代码

```
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;
using System.Windows.Forms;

namespace PrivateAssembly
{
    public class Class1
    {
        public void Display(string Message)
        {
            MessageBox.Show(Message);
        }
    }
    public class Class2
    {
        public void Display(string Message)
        {
            MessageBox.Show(Message, "", MessageBoxButtons.OK, MessageBoxIcon.Exclamation);
        }
    }
}
```

> **注意**

> 你需要在`Class1.cs`文件中添加`System.Windows.Forms`组件的引用，并添加相应的命名空间。

3. 从主菜单中选择“生成”→“生成解决方案”来生成应用程序。

4. 在`PrivateAssembly`解决方案中添加一个新的 Windows 窗体项目，命名为`Displayer`（也可在 CD-ROM 上获得），以使用此 DLL 文件。

5. 在解决方案资源管理器中右键单击`Displayer`项目，从上下文菜单中选择“设为启动项目”选项，使这个新项目成为启动项目。

6. 在`Displayer`项目中添加`PrivateAssembly.dll`引用文件：在解决方案资源管理器中右键单击该项目，然后选择“项目”→“添加引用”。

现在，你可以使用`PrivateAssembly.dll`类库中的类了；例如，要使用`Class1`，请将其引用为`PrivateAssembly.Class1`。

7. 在`Displayer`应用程序的窗体上添加一个`Button`控件，并将其`Text`属性设置为`Call Display`。

8. 双击`Button`控件以生成其`Click`事件处理程序，并添加代码，如清单 33.10 所示：

# 清单 33.10：显示 Form1.cs 文件的代码

```
{
    c1.Display("Hello from Visual C#!");
}
```

接下来，使用“生成”→“生成 Displayer”菜单项生成`Displayer`应用程序并运行它。将出现`Form1`，单击`button1`按钮。当你单击按钮时，`Display`方法会显示一个消息框，如图 33.14 所示：

## 创建多文件程序集

我们已经以`PrivateAssembly.dll`、`Displayer.exe`、`ASimpleClient.exe`和`SharedObject.dll`的形式见识了单文件程序集。现在，通过创建一个应用程序`MultiFileAssembly`（可在 CD-ROM 上获得），来了解分布在多个文件中的程序集是如何工作的。执行以下步骤来创建`MultiFileAssembly`应用程序：

1. 打开记事本，并编写代码，如清单 33.11 所示：

# 清单 33.11：显示 Class1.cs 文件的代码

```
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;

namespace Class1
{
    class Class1
    {
        public void Greeting(string name)
        {
            System.Console.WriteLine("Class One says Hi : " + name);
        }
    }
}
```

2. 将文件保存为`Class1.cs`。同样，创建一个名为`Class2.cs`的新文件，并在文件中添加代码，如清单 33.12 所示：

# 清单 33.12：显示 Class2.cs 文件的代码

```
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;
namespace Class2
{
    class Class2
    {
        public void Greeting(string name)
        {
            System.Console.WriteLine("Class Two says Hi : " + name);
        }
    }
}
```

我们创建了两个类，每个类都有一个名为`Greeting`的简单函数，在控制台窗口中显示一条消息。

3. 创建第三个文件`SimpleClient.cs`，如清单 33.13 所示：

# 清单 33.13：显示 SimpleClient.cs 文件的代码

```
using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;
namespace SimpleClient
{
    class SimpleClient
    {
        public static void Main()
        {
            Class1.Class1 c1 = new Class1.Class1();
            c1.Greeting("SimpleClient");
            Class2.Class2 c2 = new Class2.Class2();
            c2.Greeting("SimpleClient");
        }
    }
}
```

`SimpleClient`类具有执行程序集所需的`Main`函数。现在，我们需要编译这三个文件。

4. 打开 .NET 控制台窗口：点击“开始”→“所有程序”→“Microsoft Visual Studio 2010”→“Visual Studio Tools”→“Visual Studio 命令提示符(2010)”。切换到保存这些类文件的文件夹，然后输入以下命令：

```
csc /t:module Class1.cs
```

上述命令会创建一个名为`Class1.netmodule`的文件，它是`Class1.cs`类的编译版本。无法通过 .NET IDE 直接创建`netmodule`文件。因此，我们必须使用`csc.exe`（Visual C# 应用程序的命令行编译器）来编译这些文件。

如果使用`Ildasm.exe`打开任何`.netmodule`文件，你会看到它们的清单中没有`.assembly`属性（`.assembly extern`属性与`.assembly`属性不同；它们表示外部引用文件）。除了无法向这些模块指定程序集特定属性（如强名称、版权和其他属性）之外，这也意味着这些模块文件本身不是程序集，CLR 无法执行它们。

5. 输入以下命令编译`Class2.cs`文件：

```
csc /t:module Class2.cs
```

上述命令会创建一个名为`Class2.netmodule`的文件。

6. 输入以下命令编译`SimpleClient.cs`文件：

```
csc /t:module SimpleClient.cs /addmodule:class1.netmodule,class2.netmodule
```

上述命令会创建一个名为`SimpleClient.netmodule`的文件，它是我们的类`SimpleClient.cs`的编译版本。

现在，我们需要使用程序集链接器实用工具（`al`）将这三个模块组合起来，以创建一个可执行的程序集。

7. 在 Visual Studio 命令提示符(2010) 中输入以下命令：

```
al Class1.netmodule Class2.netmodule SimpleClient.netmodule /main:SimpleClient.SimpleClient.Main /out:MultiFileAssembly.exe /target:exe
```

上述命令创建`MultiFileAssembly.exe`（也可在 CD-ROM 上获得）。

8. 从命令提示符运行此文件；输出如图 33.15 所示：

![](img/e073a4882197be4ab61103cbe0bcb394_1600_0.png)
