
```
int main() {
    int N = 1024;
    size_t size = N * sizeof(int);
    int *a, *b, *c;
    int *d_a, *d_b, *d_c; 

    // a, b, c 的设备拷贝
    cudaMalloc((void**)d_a, size);
    cudaMalloc((void**)d_b, size);
    cudaMalloc((void**)d_c, size);

    // 设置输入值
    a = (int*)malloc(size);
    b = (int*)malloc(size);
    random_ints(a, N);
    random_ints(b, N);

    // 将输入拷贝到设备
    cudaMemcpy(d_a, a, size, cudaMemHostToDevice);
    cudaMemcpy(d_b, b, size, cudaMemHostToDevice);

    // 在 GPU 上启动带有 N 个线程的内核
    add<<<256, 4>>>(d_a, d_b, d_c, N);

    // 将结果拷贝回主机
    cudaMemcpy(c, d_c, size, cudaMemcpyDeviceToHost);

    // 清理
    cudaFree(d_b);
    cudaFree(d_c);
    cudaFree(d_a);
    free(b);
    free(c);
    return 0;
}
```

此主机代码包含几个重要步骤：

- 使用 `cudaMalloc` 在 GPU 上分配内存。
- 使用一些随机值初始化数组 `a` 和 `b`。
- 将初始化的数组从主机拷贝到设备 `GPU`。
- 使用特定的线程和块配置启动内核。
- 将结果从设备拷贝回主机。
- 释放分配的资源。

执行程序后，数组 `a` 和 `b` 中的每个元素都并行相加，结果存储在数组 `c` 中。这个简单的示例展示了与顺序方法相比，利用 GPU 力量进行并行计算所需代码的大幅减少。

因此，通过一个简单的示例进入 CUDA 世界不仅说明了 CUDA 编程的基本语法和方法，还展示了通过在 GPU 上并行化来显著加速计算的潜力。从这里开始之旅将进入更复杂的领域，探索内存管理、高级内核配置和优化技术，以充分利用 GPU 用于并行计算任务的力量。

## 理解 CUDA 编程模型

`CUDA` 编程模型引入了一种并行计算的独特方法，利用线程、块和网格的层次结构组织来最大化 `GPU` 加速应用程序的性能。本章重点在于析该模型的核心组件，包括线程执行的作用、内存层次结构以及 `warp` 调度的的重要性。重点介绍了并行执行上下文是如何构建的，如何在各种内存空间之间管理数据以实现高效计算。通过对这些概念的全面检查，读者将深入理解如何利用 `CUDA` 编程模型来优化应用程序的性能和扩展性。

### CUDA 编程模型的核心概念

在计算领域，`CUDA` 编程模型作为效率和速度的标杆脱颖而出，重新定义了并行计算所能实现的边界。该模型的核心是几个核心概念和结构，每个结构都经过精心设计，以优化 `GPU` 资源在并行计算中的利用。本节将深入探讨这些核心概念，包括线程、块、网格、内存层次和 `warp` 调度，为掌握 `CUDA C` 提供至关重要的全面理解。

### 线程、块与网格：执行层次结构

`CUDA` 的基础结构构建在线程之上，线程是执行的最小单元。线程被分组为块 `blocks`，块又组织成网格 `grids`。这种层次结构不仅是组织上的安排，还深度集成到任务在 `GPU` 上的调度和执行方式中。

- 线程 `Threads`：执行的基本单元。每个线程都有唯一的 `Thread ID`，并独立执行相同的代码，但可能根据条件语句发生分歧。
- 块 `Blocks`：执行同一段代码的线程集合。块内的所有线程可以同步其执行，并通过共享内存高效地共享数据。每个块都有唯一的 `Block ID`。
- 网格 `Grids`：最高级别的组织，一个网格由多个块组成。整个计算任务分布在网格内的各个块中。

为了直观理解这一点，考虑 `CUDA` 中一个简单的内核启动语法：

```cpp
threadsPerBlock>>>(arguments);
```

在这个示例中，`numBlocks` 指定了网格中块的数量，`threadsPerBlock` 定义了每个块包含多少线程。

### 内存层次结构：高效管理数据

有效的数据管理对于优化 `CUDA` 应用程序至关重要。`CUDA` 模型提供了一个复杂的内存层次结构，旨在平衡不同内存类型之间的速度与空间：

| 类型 | 描述 |
| :--- | :--- |
| 全局 `Global` | 所有块的所有线程均可访问，但延迟较高。 |
| 共享 `Shared` | 比全局内存快得多，同一块内的所有线程可访问。对于块内的线程间通信至关重要。 |
| 本地 `Local` | 每个线程专用，自动为未放置在寄存器的线程特定变量分配。 |
| 寄存器 `Registers` | 最快的内存，每个线程可直接访问，用于频繁访问或修改的变量。 |

### Warp 调度：优化线程执行

`Warp` 是 32 个线程的组，是支持 `CUDA` 的 `GPU` 中执行和调度的基本单元。`warp` 每次执行单条指令，因此当 `warp` 内的所有线程遵循相同的执行路径时，效率最高。当 `warp` 内的线程选择不同的执行路径时，就会发生分歧，导致序列化执行和潜在的性能损失。

`CUDA` 采用复杂的 `warp` 调度机制来最大化 `GPU` 计算资源的利用率。它可以通过交替执行不同的 `warp` 来隐藏内存操作的延迟，从而让 `GPU` 核心尽可能保持忙碌。

总结来说，`CUDA` 编程模型为利用 `GPU` 的巨大并行性提供了一个稳健的框架。理解并利用线程、块和网格的层次化组织，通过内存层次结构进行高效数据管理以及 `warp` 调度的细微差别，是优化 `CUDA` 应用程序的基础。随着我们在后续章节中深入探讨特定的策略和技术，记住这些核心概念将为掌握 `CUDA C` 编程提供坚实的基础。

# 3.2

## 线程、块与网格：层次结构

`CUDA` 编程模型通过将执行单元组织成由线程、块和网格组成的层次化结构，利用了并行计算的力量。这种架构旨在利用现代 `GPU` 的大规模并行能力，允许开发者在其应用程序中实现卓越的性能加速。在本节中，我们将深入探讨该层次结构的细节，探索每个组件的作用和特征，以及它们如何相互关联以促进高效的并行计算。

### 线程：执行的根本单元

在 `CUDA` 中，执行的最小单元是线程。每个线程都有自己的寄存器，寄存器是高高速存储位置，可提供最快的数据访问速度。线程执行内核 `kernel`，内核是用 `CUDA C` 编写的特殊函数，并拥有自己独特的参数集。为了区分这些线程，`CUDA` 提供了内置变量 `threadIdx` 和 `blockIdx`，它们分别代表线程的索引和线程所属的块。

考虑以下简单的内核，它的功能是两个两个数组：

```cpp
__global__ void add(int *a, int *b, int *c, int N) { 
    int index = threadIdx.x + blockIdx.x * blockDim.x; 
    if (index < N) c[index] = a[index] + b[index]; 
}
```

该内核设计用于多个线程同时执行，每个线程负责将数组 `a` 和 `b` 中特定的元素对相加，并将结果存储在数组 `c` 中。索引变量的计算说明了线程如何唯一标识它们正在处理的数据。

### 块：组织线程

块是一组执行相同内核的线程，它们可以通过共享内存和同步相互协作。块为线程提供了共享结果、协调执行和高效利用缓存的方法。`CUDA` 对每个块的线程数施了限制，这取决于硬件，但通常支持最多 1024 个线程。

块被组织成一维、二维或三维的线程网格，这种维度有助于有助于映射到此类几何形状的任务划分。

### 网格：跨块扩展

为了在单个块的限制之外扩展执行，`CUDA` 使用了网格。网格是块的集合，可以跨越多个 `SM`（流式处理器），允许内核在单个块之外进行扩展执行。网格的维度可以是一维、二维或三维，与块类似，为表达各种并行算法提供了灵活的框架。

在启动内核时指定网格内块的数量，使用如下语法：

```cpp
dim3 threadsPerBlock(256); 
dim3 numBlocks((N + threadsPerBlock.x - 1) / threadsPerBlock.x); 
threadsPerBlock>>>(d_a, d_b, d_c, N);
```

在这个示例中，使用 `dim3` 数据类型来指定每个块线程的维度和块的数量。然后使用这些配置执行内核 `add`，从而根据数据规模实现并行计算。

### Warp 调度的重要性

在 `CUDA` 执行模型中，`warp` 起到的着关键作用。`warp` 是 32 个线程的一组，由 `SM` 统一调度。`warp` 调度通过减少管理单个线程的开销，实现了 `GPU` 资源的有效利用。`warp` 内的每个线程每次执行同一条指令，从而最大化了数据并行任务的吞吐量。

设计内核时考虑到 `warp` 执行至关重要，以避免性能陷阱，例如同一 `warp` 内线程之间的分歧性执行路径，这会导致序列化并降低效率。

### 理解线程执行与同步

`CUDA` 编程模型以其能够将问题划分为成千上万甚至百万个可以并发执行的小任务而闻名。这种能力的核心在于该模型对线程执行和同步的处理，这对于充分利用 `GPU` 的性能至关重要。在本节中，我们将深入探讨 `CUDA` 环境下线程执行的复杂性，并探索用于同步线程的机制，以确保程序的正确执行。

线程层级与执行：在 `CUDA` 中，执行的基本单元是线程。每个线程都有其唯一的 `ID`，它利用该 `ID` 来计算内存地址并做出控制决策。线程被组织成块 `blocks`，而块又被组织成网格 `grid`。这种分级结构有助于实现结构化的并行方法，允许同时进行细粒度 `线程级` 和粗粒度 `块级` 的并行化。

当启动 `CUDA` 内核 `kernel` 时，它会在大量线程中同时执行。`CUDA` 将每个线程分配到 `GPU` 上的特定核心，这些线程以大规模并行的方式并发执行。这些线程的执行上下文 `包括程序计数器和寄存器` 是独立维护的，允许根据条件逻辑通过代码的分叉路径。

线程束执行 `Warp Execution`：理解线程束 `warp` 的概念对于掌握线程如何在 `GPU` 上调度至关重要。一个线程束由 32 个线程组成 `在当前的 NVIDIA 架构中`，它们以同步步的方式执行，这意味着它们在同一时间执行相同的指令。如果线程束内的线程由于条件分支发生发散，线程束将串行执行每个分支路径，这可能会由于线程束发散 `warp divergence` 导致性能下降。

### 线程束执行示例：

- 如果一个线程束中的 16 个线程走了 `if` 语句的“真”路径，而 16 个线程走了“假”路径，`GPU` 将顺序执行这两条路径，实际上使线程束的执行效率减半。

线程同步：在内核内部，线程通常需要相互通信或等待对方以确保数据被正确生成和消费。`CUDA` 提供了同步原语来协调块内线程的执行。最常用的机制是 `__syncthreads()` 函数，它充当屏障 `barrier`，块中的所有线程在任何线程继续之前必须到达此处。该函数对于避免竞态条件并确保共享数据的修改对块中的所有线程可见至关重要。

```cpp
__global void example(int* input) { 
    int sharedData[256]; 
    int tid = threadIdx.x; 
    // 示例计算并写入共享数据
    sharedData[tid] = input[tid] * 2; 
    // 同步块中的所有线程
    __syncthreads(); 
    // 现在可以安全地从 sharedData 读取
    if (tid < 128) { 
        input[tid] += sharedData[tid + 128]; 
    } 
}
```
