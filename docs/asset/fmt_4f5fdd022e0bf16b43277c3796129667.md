
在上面的代码中，我们创建了一个名为 `My thread` 的新线程。`Thread` 类用于实例化新线程并将其赋值给变量。在创建线程并赋值给 `th` 变量后，我们将线程名称输出到控制台。这只是为了测试我们的代码并确保线程已实际创建。

上面的代码创建了初始线程变量，但我们还没有为线程分配任何值，因此我们还没有真正创建一个多线程应用程序。

让我们看看你可以用于实际创建多线程应用程序的代码，而不仅仅是创建一个线程。

```csharp
class MultithreadedProgram
{
    public static void SecondThread()
    {
        Console.WriteLine("子线程启动");
    }
    static void Main(string[] args)
    {
        ThreadStart childref = new ThreadStart(SecondThread);
        Console.WriteLine("在 Main 方法中：创建子线程");
        Thread childThread = new Thread(childref);
        childThread.Start();
    }
}
```

在上面的代码中，我们创建一个新线程并将其赋值给辅助线程。辅助线程被命名为 `childref`，因此很容易与主线程区分开来。注意 `childThread.Start()` 开始了执行。

```cs
childThread.Start();
childThread.Abort();
}
```

注意，我们添加了一行调用 `Abort` 方法的新代码。一旦完成对该线程的操作，此方法就会销毁该线程。

多线程并不是所有程序都需要的，但当你需要创建创建更好的性能时，它非常有帮助。特别是当你有大量数据需要处理，而不强制用户等待直到进程完成时，它尤为有用。

# 第 14 章 多态

**目标：** 多态是一种根据用户输入创建不同响应的方法。本章涵盖 C# 中的多态。

多态是程序员创建动态应用程序的强大工具。多态将你的应用程序提升到了新的高度，无论是创建动态应用程序还是提升你的个人代码。多态在 OOP 中也是常见的，当你处理他人的代码时，应该能够识别出多态，因此我们将向你展示如何在自己的程序中使用它。

## 为什么要使用多态？

当程序员初接触 OOP 时，可能很难识别何时该使用多态。我们讨论了 OOP 的一些类方法和属性。我们可以使用相同的 `Animal` 类、`Lion` 类和 `Bird` 类，这些在之前的章节中讨论过。

在我们使用的 `Animal` 类中，所有动物都能以某种方式说话，但它们并不完全相同。不同的动物有不同的特征，这些特征是不同的。你不需要从 `Animal` 类中移除属性，你需要一种方法来描述不同的动物。

你可以通过两种方法创建多态类：函数重载 `function overloading` 和运算符重载 `operator overloading`。这是你在创建 C# 项目时看到的最常见方法。

你也可以通过类方法使用多态。再次使用 `animal` 类示例：每种动物都以某种方式说话，但它们说话的方式不同。鸟叫，狮子吼。你可以使用函数重载来指定从不同动物那里听到什么类型的语音。

每当你有一个定义程序的模糊基类时，你可能都需要多态来重写参数和函数，以更好地描述子类的特征。

## 重写函数

当你从主类继承方法时，可以重载这些函数以创建一个动态程序。重写函数是在派生父类的子类中完成的。

回到 `Animal` 类。我们知道每种动物必须以某种方式说话，因此我们在抽象类中创建了一个 `Speak` 方法。由于所有动物说话的方式并不相同，我们需要重写抽象类的 `Speak` 方法，以为我们自己的子类类进行定制。让我们看下代码示例：

```cs
abstract class Animal
{
    public abstract void Speak()
    {
        Console.WriteLine("Animals say Hello");
    }
}
class Lion: Animal
{
    public Lion ()
    {
    }
    public override void Speak ()
    {
        Console.WriteLine("A lion roars");
    }
}
```

在上面的代码中，你可以看到创建了一个 `Animal` 类。记住，抽象类不能实例化，所以你必须派生一个可以实例化的子类，否则抽象类对你的程序将毫无用。我们创建一个抽象 `Animal` 类，其中包含名为 `Speak` 的方法供所有动物使用。我们没有为抽象 `Animal` 类编写构造函数，因为该类无法实例化。构造函数用于实例化，因此在抽象 `Animal` 类中添加构造函数没有意义。

然后我们创建一个 `Lion` 类。`Lion` 类派自 `Animal` 类，因为所有狮子都是动物。由于 `Lion` 派自 `Animal` 类，我们可以使用 `Animal` 类中定义的方法。我们只有一个 `Speak` 方法，但可以从父类派生它。然而，狮子与其他动物交流的方式独特，因此我们需要用自己的 `Lion Speak` 重写主 `Animal Speak` 方法。我们在 C# 中使用 `override` 关键字来实现这一点。让我们看下代码示例：

```cs
abstract class Animal
{

    }

class Lion: Animal
{

    {
    }
    public override void Speak ()
    {
        Console.WriteLine("A lion roars");
    }
}
```

注意 `Lion` 类有一个构造函数，因为我们想要实例化这个类。当你在程序中从 `Lion` 类调用 `Speak` 方法时，输出如下：

```cs

{

}
```

在上面的 `Main` 方法中，我们实例化了 `Lion` 类并调用了 `Speak` 方法。由于 `Lion` 类重写了父类的 `Speak` 方法，代码向用户返回“A lion roars”。

我们还可以使用 `Bird` 类作为另一个例子。我们知道鸟说话的方式与狮子不同，因此我们可以创建一个重写方法，创建我们自己的 `Bird` 类方法来描述鸟在野外的说话方式。

## 重载类

重载 `Overloading` 与重写 `Overriding` 相似，但有明显的区别。重写是在子类中完成的，且方法代码中带有重写关键字。而在重载方法中，你在你自己的类中创建这些方法，因此它的工作方式与重写不同。让我们看看在上一节中创建的 `Lion` 类的一个重载方法：

```cs
abstract class Animal
{
    public abstract void Speak()
    {
        Console.WriteLine("Animals say Hello");
    }
}
```

```csharp
Console.WriteLine("Animals say Hello");
);
class Lion: Animal
{
    public Lion ()
    {
    }
    public override void Speak()
    {
        Console.WriteLine("A lion roars");
    }
    public override void Speak ( string gender)
    {
        if ( gender == "male")
        {
            Console.WriteLine("The female lion purrs.");
        } else {
            Console.WriteLine("The male lion roars.");
        }
    }
}
```

注意我们现在已经在 `Lion` 类中添加了第二个方法。注意此方法的名字与我们的另一个 `Speak` 方法相同，但新方法接收一个 `gender` 参数。这个参数将不带任何参数的主 `Speak` 方法与这个接收 `gender` 参数的新方法区分开。这被称为**方法重载** `overloading`，它是为你的程序创建动态类的一种完全合法的方法。

对于基础编程，你知道你可以为两个方法命名相同的名称，但你唯一需要更改的是参数的数量或参数所接收的数据类型。这产生了编译器可以理解的区分。因此，当编译器尝试编译你的代码时，不会返回错误。

让我们来看调用你新重载方法的代码以及在你调用它们后返回的结果。

```csharp
static void Main(string[] args)
{
    Lion l1 = new Lion();
    l1.Speak();
    l1.Speak("male");
}
```

上述代码的结果产生了如下输出：

Animals say hello.
Male lions roar.

编译器能够理解并区分这种差异，因为每个方法使用的参数数量不同。第一个没有参数，而第二个有一个 `string` 类型参数。

以 `Animal` 类为例。我们为 `Lion` 和 `Bird` 类准备了一个 `Animal` 类。

## 错误处理

**目标：** 在部署应用程序之前，你需要修复任何 bug。本章侧重于调试以及你在部署给用户和生产环境之前如何测试你的应用程序。

在将应用程序推广到生产服务器或部署给用户之前，测试应用程序始终是首要任务。在实际部署完整版本之前，你仍然可以使用 beta 测试应用程序，但即使如此，你也应该调试你的应用程序。调试的一个部分是通过错误处理。错误处理是一种捕获错误并为用户“处理”它们的方法。这些错误处理事件向用户显示友好的信息，这样你的代码就不会让用户感到沮丧。本章将讨论你如何在代码中管理这种类型的流程。

## 使用 Visual Studio 调试器

如所述，你需要 Visual Studio 代码编辑器来创建和编译 C# 代码。Visual Studio 包含一个调试器，你可以用它来逐行执行代码。与没有良好编程 IDE 的其他语言相比，使用 C# 的优势之一是 C# 允许你逐行执行每一行代码，然后你可以在执行这些行时观察变量的值。

你可以通过 `F5` 键或调试菜单启动调试器。你可以在代码中设置断点 `breakpoints`，这些断点可以让程序停下来以查看正在发生什么。例如，假设你的模块中存在错误，你不确定哪个变量导致了问题。

调试器中的变量监视窗口 `Watch List` 对于这一过程非常重要，因为它让你能够实时查看变量的值。如果没有这个工具，你在执行代码时只能猜测变量的值。监视窗口让你在执行代码时查看变量的值。它是识别变量是否被赋予错误值的绝佳方法由于逻辑错误发生在运行时，这对你的调试过程非常有用。

## C# 中的 Try Catch 语句

对于错误处理，任何 .NET 语言 包括 C# 和 VB.NET 的主要组件都是 `try-catch` 语句。该语句允许你捕获错误并执行一个处理用户错误的友好的函数。你不想为用户创建不友好、混乱的错误。在某些情况下，这些错误会给应用程序带来安全问题。处理不当的错误可能会显示信息，在某些情况下，它们可能会显示用于破解你服务器的密码和用户信息——这些是你不想向互联网公开的。解决此问题的方案是捕获错误并显示友好的信息，告诉用户如何处理错误而不会让他们感到沮丧。

让我们先看看创建 `try-catch` 语句的模板。我们为你创建了一个可以遵循的基础模板。

```csharp
try
{
  // 导致异常的语句
}
catch(ExceptionName e1)
{
  // 错误处理代码
}
catch(ExceptionName e2)
{
  // 错误处理代码
}
catch(ExceptionName eN)
{
  // 错误处理代码
}
finally
{
  // 将执行的语句
}
```

在上面的代码中，我们首先声明 `try` 语句。这表示你正在开始 `try-catch` 语句。

`try-catch` 语句中的每个 `catch` 语句捕获不同类型的错误。如果你不知道应该遇到什么类型的错误，语句的语句可能会很难，但你应该创建捕获任何类型错误的 `catch` 语句。当编译器捕获到这些类型的语句时，它们将进入 `catch` 语句块，这就是你创建处理你遇到的错误的自定义代码的地方。

当你编写代码时，请记住，用户发现的错误可能是你浏览代码时可能无法发现的。你需要考虑任何编码错误的可能性，包括任何逻辑错误，因此请确保在你的 `try catch` 结构中捕获 trap 任何可能的错误。

我们展示的最后一个语句是 `finally` 语句。该语句告诉编译器在退出之前执行什么。这是你在程序结束之前运行任何类型语句的最后机会。例如，你的代码中可能有一个打开文件的语句。在语句或程序结束之前，你需要关闭该文件，以避免它被操作系统中的任何其他进程锁定。你可以使用 `finally` 语句在程序和代码结束之前关闭文件，以避免代码出现任何 bug。

为了进一步研究我们的代码，让我们仔细查看代码中的一个真实世界示例。

```csharp
public void division(int num1, int num2)
{
    try
    {
        result = num1 / num2;
    }
```
