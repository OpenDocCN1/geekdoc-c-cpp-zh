话虽如此，这仍然是表示发生错误的最简单方法之一。

### 使用异常

现在转向错误处理的另一极端，即真正严重的条件，Objective-C 提供了抛出和处理异常的优秀设施。

Objective-C 语言为异常处理提供了几个内置指令。发出异常情况发生的信号被称为抛出或引发异常。本质上，这包括创建一个 `NSException` 的实例，然后使用内置的 Objective-C 指令 `@throw`。

一旦抛出异常，它将继续沿调用栈向上移动，直到被捕获。要捕获异常，你使用 Objective-C 指令 `@catch`。`@catch` 指令可用于捕获 `NSException` 的特定子类，在你可能想要对特定类型的异常进行特殊处理的情况下，或者可以写成捕获所有异常。清单 10.3 再次显示文件包装器示例，但在此情况下如果文件无法打开，`-openFileAtPath:` 方法会抛出异常。

### 清单 10.3

#### 使用异常的 -openFileAtPath: 方法

    contents = [[NSDictionary dictionaryWithContentsOfFile:inPath] retain];

    {

### 警告

这一点我怎么强调都不过分，所以我在这里再重申一下：在这段代码中，如果异常被抛出，而调用栈上层没有人捕获这个异常，那么应用程序就会崩溃。所以显然，只有当你确定这个失败对该应用程序是一个关键问题时，才应该以这种方式使用异常。

由于捕获这些异常非常重要，我们来看看如何做到这一点。清单 10.5 展示了该应用程序更新后的 `main` 函数，其中加入了适当的异常处理代码。

### 清单 10.5

#### 在 main 函数中处理异常

```objective-c
int main (int argc, const char * argv[])
{
    int retCode = 0;
    @try
    {
        NSAutoreleasePool * pool = [[NSAutoreleasePool alloc] init];

        FileWrapper *wrapper = [[FileWrapper alloc] init];
        [wrapper openFileAtPath:@"..."];

        // do stuff with the file here...

    }
    @catch (NSException *e)
    {
        NSString *errorName = [e name];
        NSString *errorMsg = [e reason];
        NSLog(@"An error occurred: %@ - %@", errorName, errorMsg);
        retCode = -255;
    }
    @finally
    {
        [wrapper release];
        [pool drain];
    }
    return retCode;
}
```

异常的工作方式使得它们能够中断应用程序中的任何位置的程序流程，然后在堆栈中向上跳转，直到异常被捕获。

因此，当你调用的方法可能发生异常时，你必须将可能抛出异常的代码包裹在一个所谓的 `try/catch` 块中。在上述代码中，你可以看到程序做的第一件事就是使用 `@try` 指令，这会开启一个 `try/catch` 块。一旦使用 `@try` 指令，后续代码块（用 `{}` 分隔）中的代码就会像平常一样执行，直到到达代码块末尾，或者抛出异常为止。

如果抛出异常，程序流程会立即中断，并跳到由 `@catch` 指令指定的异常处理器。

`@catch` 指令允许你捕获特定类型的异常。当异常发生时，代码会跳到 `@catch` 指令处，寻找与已抛出异常最匹配的处理器，然后开始在 `catch` 块内再次执行代码。

在这个特定例子中，`catch` 块只是打印错误消息，然后将应用程序的返回码设置为错误状态。通过捕获通用的 `NSException`，如清单 10.5 所示，你实际上捕获了所有异常。

你甚至可以用 `id` 数据类型代替 `NSException` 来捕获，这样你就可以捕获任何被抛出的对象。

在先前的例子中，针对不同类型的错误条件抛出了不同种类的异常；在这种情况下，你需要为需要处理的每种异常分别列出独立的 `catch` 块。清单 10.6 展示了这样一个例子。

### 清单 10.6

#### 捕获不同类型的异常

```objective-c
int main (int argc, const char * argv[])
{
    int retCode = 0;
    @try
    {
        NSAutoreleasePool * pool = [[NSAutoreleasePool alloc] init];

        FileWrapper *wrapper = [[FileWrapper alloc] init];
        [wrapper openFileAtPath:@"..."];

        // do stuff with the file here...
    }
    @catch (FilePermissionException *e)
    {
        // ...
    }
    @catch (FileMissingException *e)
    {
        // ...
    }
    @catch (NSException *e)
    {
        // ...
    }
    @finally
    {
        [wrapper release];
        [pool drain];
    }

```

当以这种方式捕获异常时，你应该按照从最具体到最不具体的顺序列出异常，因为运行时只会执行它找到的第一个匹配的 `catch` 块。

由于异常可以随时中断程序流程，当异常发生时，你的应用程序可能难以对已分配的内存和资源进行适当的清理。幸运的是，除了 `try/catch` 结构之外，Objective-C 的异常处理还内置了另一个功能——`@finally` 指令。

`@finally` 块的工作原理与 `@catch` 块类似，但无论是否发生异常，它都会始终执行。这使得它成为清理在 `@try` 块中分配的内存或其他资源的理想场所。无论你的 `try` 或 `catch` 块内部发生什么，你都可以始终依赖 `@finally` 块被执行。

这种错误处理方式的优点是，你可以将代码分组，让它一直运行直到某个坏情况发生，然后处理该错误条件。此外，错误可以非常详细。你可以把各种各样的信息放入 `NSException` 对象中，并根据需要尽量详细。

在具有复杂错误条件的复杂处理需求情况下，`try/catch/finally` 块甚至可以相互嵌套。这允许你在需要时使用多级别的异常处理。

### 注意

与其他一些更广泛使用异常的语言相比，Objective-C 在错误处理方面使用异常的情况相对较少。如果你来自 `Java` 这类语言，并且也想同样广泛地使用异常，我建议你三思，转而使用接下来要介绍的错误处理机制——`NSError`。

### 注意

要在抛出异常时让调试器中断，你可以在 Objective-C 运行时方法 `objc_exception_throw` 中设置断点。这样做后，当异常被抛出时，它就会触发你的断点并停止应用程序。不过你要小心，因为有些方法会抛出并捕获异常，而不允许它继续沿着堆栈向上传递。这很正常，也不会造成任何损害。

### 使用 NSError

在设计 Foundation 框架时，Apple 意识到他们需要一种错误处理机制，既保留简单返回码的简洁性，又能够提供关于发生了什么类型的错误的更多信息。因此，他们开始引入一个名为 `NSError` 的新错误处理系统。清单 10.7 展示了更新后的文件包装器类，它使用了一个 `NSError`。

### 清单 10.7

#### 使用 NSError 的文件包装器类

```objective-c
-(BOOL)openFileAtPath:(NSString *)inPath withError:(NSError **)outError;
{
    contents = [[NSDictionary dictionaryWithContentsOfFile:inPath] retain];
    if(!contents)
    {
        if(![self fileExistsAtPath:inPath])
        {
            NSDictionary *errorInfo =
            [NSDictionary dictionaryWithObject:@"File doesn't exist."
                                        forKey:NSLocalizedDescriptionKey];

            *outError = [NSError errorWithDomain:@"FileWrapper"
                                            code:404
                                        userInfo:errorInfo];
        }
        else if(![self hasPermissionForFileAtPath:inPath])
        {
            NSDictionary *errorInfo =
            [NSDictionary dictionaryWithObject:@"Permission Error."
                                        forKey:NSLocalizedDescriptionKey];

            *outError = [NSError errorWithDomain:@"FileWrapper"
                                            code:500
                                        userInfo:errorInfo];
        }
        else
        {
            NSDictionary *errorInfo =
                [NSDictionary dictionaryWithObject:@"Unknown error."
                         forKey:NSLocalizedDescriptionKey];

            *outError = [NSError errorWithDomain:@"FileWrapper"
                                            code:501
                                        userInfo:errorInfo];
        }
        return NO;
    }
    return YES;
}
```

`NSError` 是一个在 Cocoa 和 Cocoa Touch 框架中广泛实现的正式化设计模式。

要使用它，你需要扩展你的方法签名以接受一个对 `NSError` 对象的间接引用。该对象由调用方提供。间接引用本质上是指向指针的指针。换句话说，它是指向另一个指针的指针；在这种情况下，它是指向调用方栈中分配的变量的指针。当你为该变量赋值时，你解引用间接引用，从而实际上为其指向的变量赋值。
