实现在两个数据处理系统环境中翻译 C 源代码文件并执行 C 程序，在本国际标准中，这两个环境将分别称为翻译环境和执行环境。它们的特性定义并限制了根据符合实现的语法和语义规则构建的符合实现的 C 程序的执行结果。

## 5.1 概念模型

### 5.1.1 翻译环境

#### 5.1.1.1 程序结构

程序不需要同时翻译。程序文本在本国际标准中以源文件（或预处理文件）为单位保留。一个源文件加上通过预处理器指令 `#include` 包含的所有头文件和源文件被称为预处理翻译单元。预处理后，预处理翻译单元被称为*翻译单元*。之前翻译单元可以单独保留或存储在库中。程序的各个翻译单元通过（例如）调用具有外部链接标识符的函数、操作具有外部链接标识符的对象或操作数据文件进行通信。翻译单元可以分别翻译并在稍后链接以生成可执行程序。

前向引用：标识符的链接 (6.2.2)、外部定义 (6.9)、预处理指令 (6.10)。

#### 5.1.1.2 翻译阶段

翻译语法规则之间的优先级由以下阶段指定。⁶

- 如果必要，物理源文件中的多字节字符以实现定义的方式映射到源字符集（为行尾指示符引入换行符）。三连字序列被替换为相应的单字符内部表示。

- 实现的行为应当类似于这些独立阶段的发生过程，尽管在实践中它们通常被折叠在一起。源文件、翻译单元和翻译后的单元不一定需要存储为文件，这些实体与任何外部表示之间也不存在一一对应的对应关系。该描述仅是概念性的，没有指定任何特定的实现。

- 每个紧挨随换行符的反斜杠字符 (`\`) 实例用于拼接源行以形成逻辑源行。任何物理源行上的最后一个反斜杠才有资格参与此类拼接。非空源文件应以换行符结束，且在任何拼接之前，该换行符前不能紧挨着反斜杠字符。

- 源文件被分解为标记^7) 和空白字符序列（包括注释）。源文件不应预处理标记或部分注释结束。每个注释被替换为一个空格字符。保留换行符。除换行符以外的空白字符序列是保留还是被替换为一个空格，由实现定义。

- 执行预处理指令，展开宏调用，并执行 `#Pragma` 一元运算符表达式。如果通过连接 (6.10.3.3) 产生了匹配通用名称语法的字符序列，则行为是未定义的。`#include` 预处理指令导致命名的头文件或源文件从第 1 阶段到第 4 阶段递归处理。所有预处理指令均被删除。

- 字符常量和字符串字面量的每个源字符集成员转义序列都被转换为执行集中对应的成员；如果没有相应的成员，则转换为除空（宽）字符以外的实现定义成员.^8)

- 相邻的字符串字面量被连接。

- 分隔标记的空白字符不再具有重要性。每个预处理标记转换为一个标记。生成的标记在语法和语义上进行分析，并作为翻译单元进行翻译。

- 解析所有的外部对象和函数引用。链接库组件以满足对当前翻译中未定义的函数和对象的外部引用。所有此类输出都被收集到一个程序中，该程序包含了在其执行环境中执行所需的信息。

**前向引用：**通用字符名称 (6.4.3)、词法元素 (6.4)、预处理指令 (6.10)、三连字序列 (5.2.1.1)、外部定义 (6.9)。

> ^7) 如 6.4 所述，将源文件分解为预处理标记的过程取决于上下文。例如 `#include` 预处理指令中对 `<` 的处理。

> ^8) 实现可能将所有不对应的源字符转换为相同的执行字符。

### 5.1.2 执行环境

定义了两执行环境：*独立*（freestanding）和*托管*（hosted）。在在这两种情况下，当执行环境调用指定的 C 函数时会发生*程序启动*。所有具有静态存储期的对象在程序启动前应被*初始化*（设置为它们的初始值）。此类初始化的方式和时机另有规定*程序结束*将控制交回执行环境。

**前向引用：**对象的存储期 (6.2.4)、初始化 (6.7.9)。

### 5.1.2.1 独立环境

在独立环境（其中 C 程序执行可以在没有任何操作系统的情况下进行）中，启动时调用的函数名称和类型由实现定义。除第4 节要求的最小集外，独立程序可用的任何库设施均为实现定义。

独立环境中程序结束的影响由实现定义。

### 5.1.2.2 托管环境

不要求提供托管环境，但如果存在，应符合以下规范。

> ⁹ 意图是实现应当识别每个违规行为的性质，并在可能的范围内位置。当然，只要仍然翻译了有效程序，实现可以产生任意数量的诊断信息。

#### 5.1.2.2.1 程序启动

启动时调用的函数名为 `main`。实现不对此函数声明任何原型。它应被定义为返回类型为 `int` 且无参数：

```
int main(void) { /* */ }
```

或带有两个参数（此处称为 `argc` 和 `argv`，尽管可以使用任何名称）：

```
int main(int argc, char *argv[]) { /* */ }
```

或等效形式:<sup>10</sup> 或以其他某些实现定义的方式。

如果声明了它们，`main` 函数的参数应遵守以下约束：

- `argc` 的值应为非负。

- `argv` 应为空指针。

- 如果 `argc` 的值大于 0，数组成员 `argv[0]` 到 `argv[argc-1]` 应包含指向字符串的指针，这些字符串在程序启动前由托管环境赋予实现定义的值。意图是从托管环境的其他地方提供程序启动前确定的程序信息。如果托管环境无法提供同时包含大写和小写的字符串，实现应确保接收到的字符串是小写的。

- 如果 `argc` 的值大于 0，`argv[0]` 指向的字符串代表*程序名称*；如果托管环境无法提供程序名称，`argv[0][0]` 应为空字符。如果 `argc` 的值大于 1，`argv[1]` 到 `argv[argc-1]` 指向的字符串代表*程序参数*。

- 参数 `argc` 和 `argv` 以及 `argv` 数组指向的字符串应可被程序修改，并在程序启动和程序结束之间保留其最后存储的值。

#### 5.1.2.2.2 程序执行

在托管环境中，程序可以使用库节（第 7 节）中描述的所有函数、宏、类型定义和对象。

> 10) 因此，`int` 可以替换为定义为 `int` 的类型别名，或者 `argv` 的类型可以写为 `char **argv`，等等。

## 5.1.2.2 程序终止

如果 `main` 函数的返回类型与 `int` 兼容的类型，则从 `main` 函数初始调用的返回等同于调用 `exit` 函数，并将 `main` 函数返回的值作为其参数；sup>11</sup>；到达终止 `main` 函数的 } 符号时返回值为 0。如果返回类型与 `int` 不兼容，则返回给主机环境的终止状态是未指定的。
