
成员属性如 `dummy` 已经构造完成。在基类构造之后，`Tuna` 的实例化继续进行，首先是成员 `Tuna::dummy` 的实例化，最后执行 `Tuna::Tuna()` 中的构造函数代码。输出证明了析构顺序恰恰相反。

# 私有继承

私有继承与公有继承的区别在于，在派生类声明其自基类的行中，使用了 `private` 关键字：

```cpp
class Base
{
  // ... 基类成员和方法
};

class Derived: private Base  // 私有继承
{
  // ... 派生类成员和方法
};
```

基类的私有继承意味着基类的所有公共成员和属性对于任何拥有派生类实例的人来说都是私有的，即不可访问的。换句话说，即使是 `Base` 类的公共成员和方法也只能被 `Derived` 类使用，而不能被拥有 `Derived` 实例的其他人使用。

这与从列表 10.1 开始一直的 `Tuna` 和 `Fish` 示例形成鲜明对比。列表 10.1 中的 `main()` 可以调用 `Tuna` 实例上的函数 `Fish::swim()`，因为 `Fish::swim()` 是一个公共方法，且类 `Tuna` 使用公有继承派自 `Fish`。尝试将第 17 行的 `public` 重命名为 `private` 并观察编译失败。

因此，对于继承层次结构之外的世界，私有继承本质上并不意味着一种“是一个” 的关系，想象一条不会游泳的金枪鱼！由于私有继承允许基类属性和方法仅由派生自它的子类使用，这种关系也被称为“有一个” 的关系。在日常生活中你看到的某些事物中，有一些私有继承的例子，见表 10.2。

## 对象切片问题

当程序员执行以下操作时会发生什么？

```cpp
Derived objectDerived;
Base objectBase = objectDerived;
```

或者，如果程序员执行以下操作呢？

```cpp
void FuncUseBase(Base input);

Derived objectDerived;
FuncUseBase(objectDerived);
```

在这两种情况下，一个 `Derived` 类型的对象被复制到另一个类型 `Base` 中，是显式地通过赋值或作为参数传递的。在这种情况下，编译器只复制了 `objectDerived` 的部分，即能够放入 `Base` 的那部分。这通常不是程序员预期的，这种对使 `Derived` 特化 `Base` 的数据部分的非预期拒绝被称为*切片*。

> 注意
> 要避免切片，请不要按值传递参数。请通过基类指针或指向基类的 const 引用传递它们。

### 多态的基础知识

“Poly”是希腊语中“多”的意思，而“morph”意味着“形式”。多态是面向对象语言的一种特性，允许不同类型的对象以相似的方式被对待。本节重点关注可以通过 C++ 继承层次实现的多态行为，也称为子类型多态。

### 多态行为的必要

在第 10 节“实现继承”中，你通过列表 10.1 了解了金枪和鲤鱼如何从鱼类继承了公有的 `Swim()` 方法。然而，金枪和鲤鱼都可能提供自己的 `Tuna::Swim()` 方法以使它们成为不同的游泳者。尽管如此，由于它们也是鱼类，如果一个拥有金枪鱼实例的用户使用基类来调用 `Fish::Swim()`，他最终将只会执行通用的部分 `Fish::Swim()` 而不是 `Tuna::Swim()`，即使该基类实例是金枪鱼的一部分。这个问题在列表 11.1 中得到了演示。

当你编写程序时，你应该编写有意义的类并创建合理的继承层次，同时始终考虑到应用程序的设计和目的。
