
如果你正在声明私有实例变量，那么你应该在 `@implementation` 上下文中声明它们。这确保了不应该访问它们的内容不会意外访问。如果你正在声明公共或受保护的实例变量，且它们应该只在同一个库内访问，那么你应该在私有头文件中的类扩展中声明它们。在新代码中，你应该只在公共头文件中声明预计会被代码用户直接访问的实例变量。

你所创建的大多数属性默认都是 `nonatomic` 的。访问器方法的原子性并不能让对象线程安全，大多数情况下，使用更高级别的锁机制在线程之间共享对象会效果更好。

考虑 `nonatomic.m` 示例。它声明了一个原子（atomic）属性。你随后在代码中使用了一次递增操作。你可能期望这是一个原子递增，但事实并非如此。这条单一语句会展开为两条消息发送，并在它们之间进行一次递增操作。

```objc
@interface NotReallyAtomic : NSObject
@property int a;
@end

int add(NotReallyAtomic *obj)
{
  obj.a += 1;
}
```

来自：`nonatomic.m`

在属性的语境下，原子性意味着在不使用垃圾回收的情况下，`set` 和 `get` 方法都将尝试获取同一个锁，这样当你尝试在一个线程中设置它而在另一个线程中获取它时，对象不会被意外释放。在垃圾回收模式下，对于非对象属性，`nonatomic` 是意义的。属性可以是 `readwrite`（读写）或 `readonly`（只读），这表示是否支持对它们进行赋值。如果你定义了一个 `readwrite` 属性且没有使用垃圾回收，你还需要定义 setter 的语义。

**注意：** 有时，你可能希望有一个读写属性，但仅在公共接口中使其可读。类扩展（Class extensions）提供了实现此点的机制。如果你在主接口中将属性声明为 `readonly`，但在类扩展中重新声明为 `readwrite`，那么主 `@implementation` 中的 `@synthesize` 指令将创建 setter 和 getter。然而，在类扩展不可见的地方尝试使用 setter 都会会导致编译器错误。

setter 的行为有几种选项。最简单（也是非对象类型的唯一选项）是 `assign`。它通过简单的赋值来设置值。对于非对象类型，这仅仅是复制了该值。对于对象，情况要稍微复杂一些。

各种属性访问器的精确语义取决于内存管理模式。在引用计数（手动或自动）下，当你设置值时，`assign` 执行简单赋值。当你访问该值时，对于 `nonatomic` 属性，它将返回指针；对于 `atomic` 属性，它会先 `retain` 然后 `autorelease` 它。

下一个选项 **retain** 仅在引用计数模式下有意义。在设置 **retain** 属性时，新值会被 `retain`，旧值会被 `release`。在垃圾回收模式下，**assign** 和 **retain** 是等价的。

`copy` 属性与 `retain` 属性类似。在设置它时，新值接收的是 `-copy` 消息而不是 `-retain`。你通常应该对具有不可变类型的属性使用它。例如，如果你声明了一个 `NSString*` 属性，那么使用 `copy` 可以确保你拥有一个不可变的字符串，即使有人使用 `NSMutableString*` 实例来设置它。不可变对象会从 `-copy` 返回自身，因此只有在确实需要为了确保属性不被意外修改时，它才会创建一个副本。

如果你使用自动引用计数（ARC）或垃圾回收（我们将在第 3 章“内存管理”中详细介绍），你可以使用 `weak`。`weak` 属性不会阻止其值被删除，并且当所有其他引用都消失时，它将被设置为 `nil`。

现代编译器还支持将 `unsafe_retained` 作为属性类型。这等同于 `assign`，但更显式地表达了缺乏安全性。

仅对对象有意义的属性类型也可以用于用用 `__attribute__((Nonnull))` 声明的 C 指针类型。该属性告诉编译器该 C 类型实际上是一个 Objective-C 对象。Core Foundation 对象和 blocks（参见“使用 blocks”部分）是此类常见例子。它们暴露在可能包含在 C 程序中的头文件中，因此它们没有显式地暴露 Objective-C 类型，但在 Objective-C 中可以作为 Objective-C 对象使用。

一旦你声明了属性接口，就必须提供实现。属性只是定义访问器方法的一种方式。在上一个例子中，属性 `a` 是通过 `-a` 和 `-setA` 方法实现的第一个方法返回属性的值，第二个方法将其设置为新值。

你可以自己实现这些方法。你可能也会从父类继承它们。如果是此类情况，编译器可能无法看到它们并生成警告。你可以通过为该属性提供一条 `@dynamic` 行来抑制这种警告。这告诉编译器这些方法确实存在，将在运行时解析。

或者，你可以使用 `@synthesize` 告诉编译器为你生成访问器方法。合成的属性方法引用与属性同名的实例变量。这些方法调用运行时库函数，并带有实例变量的偏移量以及指示属性类型的某些标志。通常情况下，你应该尝试始终使用 `@synthesize`。编译器随后将为你当前的编译模式生成具有正确语义的方法。这让你能够轻松地在手动引用计数、自动引用计数和垃圾回收之间切换。你不需要修改任何访问器方法；编译器会为你完成。

## 理解 self, __cmd, super

```objc
id method(id self, SEL _cmd, ...);
```

来自：`object.m`

每个 Objective-C 方法都被编译成一个函数。它有两个隐藏参数：`self` 和 `_cmd`。其中第一个非常显而易见：它是消息的接收者。如果是实例消息，`self` 将是该类的实例。如果是类消息，`self` 将是类本身。在 C++ 中，这个关键字几乎等同于 Objective-C 中的 self，但有一个关键区别：self 不是关键字。它是参数的名字。在 C++ 中给它赋值会导致错误。而在 Objective-C 中赋值是允许的。

第二个隐藏参数是消息的选择器（selector）。这对于转发（forwarding）等功能的正常工作是关。当你向一个不知道如何处理的对象发送消息时，它将构造一个封装了消息的 `NSInvocation` 对象并将其传递给 `forwardInvocation:`。

由于这两个隐藏参数都不是关键字，你可以在方法之外使用它们，尽管 C 规范保留了以下划线开头的标识符，因此最好不要使用 `cmd`。标准的作用域规则适用，所以你也可以在方法内部声明一个名为 `self` 的变量来隐藏传入的版本。如果你这样做，编译器会生成一个警告，因为这是愚蠢的行为，但在语义上是有效的。

`super` 伪变量要复杂一些。这仅作为消息的接收者时有效。它将生成一个消息发送，其中接收者是接收者，但方法将在超类中查找而不是当前类。这就是调用重写方法的方法。

向 `super` 发送消息使用不同的方法查找函数，它接受指向 `objc_super` 结构的指针作为参数。该结构包含了目标类和目标对象。

超类在编译时是固定的。当你编译一个 Objective-C 类时，所有向 `super` 发送的消息都将在类接口中定义为超类的类中查找。对于大多数代码，这并不重要，但如果你在使用运行时库函数向类添加方法，你就需要记住这一点。如果你附加到新类的方法向 `super` 发送消息，它将发送到错误的类。值得注意的是，在 GNU 运行时中，向超类发送消息的实现方式不同。类实现上下文与类结构在同一个编译单元中，因为类结构是由编译器从 `@implementation` 上文中包含的代码生成的。可以通过查找并获取超类字段找到超类指针。

在分类中，类结构是不可用的。必须在运行时查找。这使得从分类定义的方法发送的超类消息变慢。Apple 的运行时通过让链接器解析外部类引用来解决这个问题。

## 理解 isa 指针

```c
typedef struct objc_object *id;
struct objc_object
{
    id isa;
};
```

来自：`object.m`

在 C++ 中，类就是结构体。你可以将一个 C 结构体子类的 C++ 类。当你对 C++ 类调用方法时，你实际上是在调用一个带有修饰名（mangled name）的 C 函数，并将结构体指针作为第一个（隐藏）参数。

在 Objective-C 中，结构体和类是非常不同的。在引入非脆弱 ABI 之前，你可以使用结构体定义中的 `@defs` 关键字来创建一个与类布局相同的结构体，但你不能在类和结构体之间互换使用。

对象和结构体之间的区别在于，你可以向类发送消息。这之所以能行，是因为结构体中的第一个实例变量指向类结构体的指针。按照约定，这个实例变量被称为 `isa`，就像“这个对象是一个……”。如果你定义了一个新的根类，必须记住添加这个实例变量。

与 `self` 和 `_cmd` 隐藏参数一样，`isa` 指针只是另一个实例变量；它不是一个关键字。将其与在 C++ 中调用虚方法进行对比。具有虚方法的 C++ 对象包含一个指向虚函数方法表（vtable）的（隐藏）指针。这是一个函数指针的简单数组。当你调用方法时，编译器会解引用 vtable 指针并在正确的偏移处调用函数。

你无法使用 vtable 找到关于该对象的任何信息，而且它的布局是目标 ABI 定义的一部分，而不是语言的一部分。`isa` 指针非常不同。它是一个显式的实例变量，因此它可以像访问任何其他实例变量一样被访问。它指向一个 `Class`，这是由 Objective-C 运行时头文件提供的类型定义²，并根据运行时被定义为不透明类型或指向公共 C 结构体的指针。

² 如果未提供定义，Clang 将其视为内置类型。

在类结构体具体布局为私有的运行时，你仍然可以找到检查它的函数。这些函数可以告诉你实例变量的偏移、方法和属性的名称及类型签名、父类等。

你可以查看其他对象上的 `isa` 指针。`id` 类型定义为 C 结构体（无访问控制），仅包含指向类的指针，因此你可以像读取结构体中的任何其他字段一样读取它。

在 Objective-C 的最新版本中，直接访问 `isa` 指针已被弃用。你应该使用 `object_getClass()` 和 `object_setClass()` 函数。

最新的运行时借鉴了 Smalltalk 的技巧，将非常小的对象隐藏在指针内部。对象总是按字对齐的，因此指针的低位始终为 0。这允许你执行诸如将 31 位整数存储在 32 位指针中的操作，并将最低位设置为 1 以区分于真实对象。将此类值视为指针并尝试直接访问 `isa` 指针会严重破坏程序运行。

Objective-C 对象可能会转发消息，你持有的对象指针可能是一个代理。如果你想获取另一个对象的类，应该向它发送 `-class` 消息。这种方法较慢，但在存在代理的情况下不会崩溃。
