
```c

// 用于存储转换字符串的宽字符数组

// 将 MB 字符串转换为 WC；返回宽字符的数量

// 打印结果——宽字符字符串使用 %ls

printf("multibyte: %s (%zu bytes)\n", mb_string, mb_len);

printf("wide char: %ls (%zu characters)\n", wc_string, wc_len);

}
```

在我的系统上，输出是：
"The cost is €1.23" (19 字节)
wide char: "The cost is €1.23 (17 字符)"

你的系统字节数取决于你的区域设置。

### 27.10 解析状态、可重启动函数

我们将稍微深入多字节转换的内部原理，这在概念上是有帮助理解的。想象你的程序正在跟踪一个多字节字符序列并将其转换为宽字符，或者反之。在某个某一点，即在处理字符的途中，它可能需要等待更多的字节才能确定最终的值。

这种解析状态存储在一个不透明的变量 `mbstate_t` 中，并在每次执行转换时使用它。这就是转换函数如何跟踪其工作中间位置的。如果你需要在流中途更改字符，或者尝试跳转到输入序列中的不同位置，它可能会因此困惑。

现在有一点：我们做了一些转换，但我从未在地方提到过 `mbstate_t`。这是因为像 `mbstowcs()`、`wcstomb()` 等转换函数每个都有它们使用的 `mbstate_t` 变量。不过，如果你正在编写多线程代码，这些函数是不安全的。

幸运的是，标准库定义了这些函数的可重启动版本，如果你需要，可以按线程传递自己的 `mbstate_t`。如果你在处理多线程事务，请使用这些！

关于初始化 `mbstate_t` 变量的说明：只需使用 `memset()` 将其置零即可。没有内置函数可以强制对其初始化。

```c
mbstate_t mbs;

// 将状态设置为初始状态

memset(&mbs, 0, sizeof(mbs));
```

以下是可重启动转换函数的列表——注意其在 "from" 类型后添加 "r" 的命名约定：

- `mbrtowc()` 多字节到宽字符
- `wcrtomb()` 宽字符到多字节
- `mbstowcs()` 多字节字符串到宽字符字符串
- `wcstombs()` 宽字符串到多字节字符串

这些与非重启动版本相似，区别在于它们要求传递自己的 `mbstate_t` 变量。而且它们会修改源指针（在发现无效字节时提供帮助），因此保存原始数据的副本可能是用的。

这里是本章之前的示例重构，以传递自己的 `mbstate_t`：

```c
#include <stdio.h>
#include <stdlib.h>
#include <stddef.h>
#include <wchar.h>
#include <string.h>
#include <locale.h>
int main(void)
{
    // 从 C 区域切换到一个可能包含欧元符号的区域
    setlocale(LC_ALL, "");
    // 带有欧元符号的多字节字符串（Unicode 点 20ac）
    char *mbs_string = "The cost is \u20ac.23"; // €1.23
    size_t mb_len = strlen(mbs_string);
    // 用于存储转换字符串的宽字符数组
    wchar_t wc_string[128]; // 保存最多 128 个宽字符
    // 设置转换状态
    mbstate_t mbs;
    memset(&mbs, 0, sizeof(mbs)); // 初始状态
    // mbsrtowcs() 会修改输入指针
    mbsrtowcs(wc_string, mbs_string, mb_len, &mbs);
    // (m_string 处理逻辑省略)
}
```

### 27.11.2 UTF-16, UTF-32, char16_t 和 char32_t

`char16_t` 和 `char32_t` 是两种潜在的宽字符类型，大小分别为 16 位和 32 位。它们并不一定是宽字符，因为如果它们无法表示当前区域环境中的每一个字符，就会失去宽字符的本质。规范在各处称它们为“宽字符”类型，事实就是如此。

引入这些类型是为了让事情稍微兼容 Unicode 一。

包含头文件：`<cuchar.h>`。（注意是 "u"，不是 "uw"）。

这个头文件在 OS X 上——目前还还没有。如果你只需要这些类型，可以：

```c
#include <stddef.h>
typedef int_least16_char16_t;
typedef int_least32_char32_t;
```

但如果你还想要相应的函数，那么它们得由你自己来实现。

假设你已经准备就绪，可以使用 `u` 和 `u` 前缀来声明这些类型的字符串或字符：

```c
char16_t *s = u"Hello, world!";
char16_t *c = u"B";
char32_t *t = u"Hello, world!";
char32_t d = u"B";
```

现在——这些这些值是存储在 UTF-16 还是 UTF-32 中？取决于实现。
但你可以测试一下它们是否是那样。如果宏 `__STDC_UTF_16__` 或 `__STDC_UTF_32__` 被定义为 (1)，则意味着这些类型分别持有 UTF-16 或 UTF-32。
如果你好奇，并且（根据我了解的情况）UTF-16 或 UTF-32 是以原生字节序存储的，那么你应该可以直接它们与 Unicode 代码点值进行比较：

```c
char16_t pi = u"\u03BC"; // pi 符号
#if __STDC_UTF_16__
pi == 0x03BC; // 始终为真
#else
pi == 0x030; // 可能为假
#endif
```

## 信号处理

在开始之前，我建议你通常忽略整个章，并使用操作系统的（很可能的）信号处理函数。Unix 类有 `sigaction()` 系列函数，而 Windows 有……它自己的方法。

排除这些差异之后，什么是信号？

### 29.1 什么是信号？

信号会在各种外部事件上触发。你的程序可以配置为中断以处理信号，并可选地在处理完毕后从离开的地方继续。

把它想象成当这些事件之一发生时会自动调用的函数。

这些事件是什么？在你的系统上可能有很多，但在 C 规范中只有几个：

| 信号 | 描述 |
|---|---|
| `SIGABRT` | 异常终止——调用 `abort()` 时发生的情况。 |
| `SIGFPE` | 浮点异常。 |
| `SIGILL` | 非法指令。 |
| `SIGINT` | 中断——通常是按下 CTRL-C 的结果。 |
| `SIGSEGV` | “段错误”：无效内存访问。 |
| `SIGTERM` | 终止请求。 |

你可以使用 `signal()` 函数设置程序对每个信号的忽略、处理或允许默认操作。

### 29.2 使用 signal() 处理信号

`signal()` 取两个参数：感兴趣的信号，以及当该信号被触发时采取的动作。

该动作可以是三种之一：

- 指向处理函数的指针。

## 第 29 章 信号处理

- `SIG_IGN` 忽略信号。
- `SIG_DFL` 恢复信号的默认处理程序。

让我们写一个你可以通过 CTRL-C 退出的程序。（别担心——在下面的程序中，你也可以按 RETURN 退出。）

```c
#include <stdio.h>
#include <signal.h>
int main(void)
{
    char s[1024];
    signal(SIGINT, SIG_IGN); // 忽略由 ^C 引起的 SIGINT
    printf("Try hitting ^C... (hit RETURN to exit)\n");
    // 等待一行输入，以免程序直接退出
    fgets(s, sizeof s, stdin);
}
```

查看第 8 行——我们告诉程序忽略 `SIGINT`，这是按下 CTRL-C 时触发的中断信号。无论你按多少次，该信号都保持被忽略。如果你注释掉第 8 行，你会发现可以无顾忌地按下 CTRL-C 并立即退出程序。
