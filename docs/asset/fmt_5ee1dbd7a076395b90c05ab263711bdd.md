## Objective-C 运行时 Runtime

正如我在书开头所说，一个 Objective-C 实现由两部分组成：编译器和运行时库。编译器获取源代码并将动态部分转换为对运行时库的调用。

运行时库是用 C 编写的，这意味着它是用 Objective-C 的子集。运行时库的所有接口（包括由编译器生成的代码调用的接口）对 Objective-C 代码都是可见的。

Objective-C 中所有动态的内容由运行时库实现。最显而见的例子就是消息发送 `message sending`。当你发送消息时，运行时负责决定由谁来处理它。

这并不是运行时库的唯一责任。它还处理该语言所有的内省 `introspection` 功能。它跟踪所有的类元数据并将其暴露给程序员。

当你使用键值编码 `key-value coding` 时，你是在间接使用运行时查找方法。

### 按名称发送

```objc

id obj = [NSObject new];

```

来自 `methodName.m`
Objective-C 方法是通过消息发送调用的 C 函数。具体实现方式在运行时之间有所不同。在 NeXT 和 Apple 运行时，简单的消息发送是通过 `objc_msgSend()` 实现的。

遗憾的是，这不是你需要的唯一函数。在 GNU 运行时，这要简单得多。没有 `objc_msgSend()` 函数。相反，你调用 `objc_lookup()` 然后调用返回的结果。

这种跨运行时的最简单的方法是使用 `NSObject` 的 `-methodFor:` 方法。它返回一个指向方法的指针，你可以调用它。它接受两个参数：接收者和选择器。

源自：`respondsToSelector.m`

Objective-C 代码倾向于使用非正式协议 `informal protocols`。这些是代理可以选择实现的消息组。

大多数时候，你想知道的是要发送消息的对象是否能处理该消息，而不是它是否有一个处理该消息的方法。在某些语言（如 C++）中，这些是同一个，但在 Objective-C 中，它们是非常不同的概念。

当你向代理发送 `-respondsToSelector:` 消息时，它将测试真实对象是否具有对应该选择器的方法。被代理封装的对象可能是另一个代理，它将再次转发请求。
你也可以通过向类发送 `-conformsToProtocol:` 消息来测试协议的遵循情况。注意，这只测试该类是否被声明为采用该协议。类可以采用协议但不实现它们的所有方法（尽管它们不应该这样做），但更常见的情况是类可以实现协议中的所有方法而不显式地遵循协议。

## 转发消息

```objc

@interface Facade : NSObject{

  id delegate;

}

@implementation Facade

-(id)forwardingTargetForSelector:(SEL)aSel {

  return delegate;

}

-(void)forwardInvocation:(NSInvocation*)anInv {

  [anInv invokeWithTarget:delegate];

}

@end
```

源自：`forward.m`

Objective-C 消息旨在类似于 Smalltalk 消息，而不是 C 函数。它们是后期绑定的并且可以被内省。在最底层，它们使用 C 函数实现，但这是一个实现细节。你可以假装消息是对象与其他对象之间传递的、被内省的，然后由方法处理。

当你向一个在该对象上没有对应方法的对象发送消息时，该对象仍然有一些方法可以处理它。这些方法在 Objective-C 的发展过程中已经进化了许多。

在旧的 Objective-C 代码中，会调用对象的 `-forward:::` 方法。这是一个可变方法，并要求接收者知道栈帧的结构。NeXT 用 `-forwardInvocation:` 替换了它。此方法接收一个封装了消息发送的对象。`-forwardInvocation:` 机制非常灵活，但性能并不是特别好。创建对象和解构栈帧的代价比普通消息发送高出几百倍，这意味着你不应该在任何即使有一点点对性能敏感的场合使用这种机制。

如果你使用这种转发机制，那么你必须实现 `-methodSignatureForSelector:` 方法。它返回一个代表与消息关联的调用帧结构的对象。`NSInvocation` 类将在创建封装消息的对象时使用它。

在 10.5 版本中，Apple 引入了一种新的、更快的转发机制。如果你的对象实现了 `-forwardingTargetForSelector:` 方法，它将带有缺失方法的选择器被调用。然后它可以返回一个对象，消息将改为交付给该对象。

这使得像门面模式 `façade pattern` 这样的设计非常简单。你可以快速地将任何你不理解的方法委托给你的代理。如果你在调用代理方法之前或之后需要一些额外的处理，只需实现该方法并显式地调用代理方法即可。

注意：GNU 运行时使用的两阶段消息发送机制不支持这种新机制，旧版本的 Apple 运行时也不支持。如果你使用它，使用 `--forwardInvocation:` 提供回退代码是一个好主意。如果你使用的是最近的 Apple 运行时，或者带有非脆弱 ABI 的 GNUStep 运行时，你将获得额外速度的好处。

在旧版本的运行时，`Class` 是 `struct objc_class` 的类型定义，该结构定义在头文件中。在更现代的系统中，`Class` 是一个不透明类型，你应当通过一组公共函数与之交互。这使得随着时间的推移 ABI 变得更加容易。类结构的布局可以通过修改编译器和运行时更改，而无需修改任何其他代码。

在较新的运行时，为声明的属性也存储了元数据。你对类设置的几乎任何内容都可以通过调用运行时函数进行检查。你唯一无法做到的就是获取单个方法的源代码。

## 创建新类

```objc
#include <objc/runtime.h>

id fakeDealloc(id self, SEL _cmd, ... ) {
    NSLog(\@"%@ sent a -dealloc message", self);
}
void makeIndestructible(id obj) {
    Class new =
        objc_allocateClassPair(obj->isa, "Fake", 0);
    class_addMethod(new, @selector(dealloc),
        (IMP)fakeDealloc, "v@");
    objc_registerClassPair(new);
    obj->isa = new;
}
```

来自：`newClass.m`

在运行时创建新类是很罕见的，但它确实为非常动态的行为或优化提供了许多机会。我们已经看过了执行此操作 Foundation 框架的一部分。键值观察 `KVO` 机制就会创建新类来拦截访问器方法的调用。

在运行时创建类最重要的一点是，它展示了 Objective-C 的核心原理之一：编译器所做的一切都不是魔法。你可以在自己的 C 代码中生成编译器从 Objective-C 代码中生成的所有内容。当然，编译器在优化结果方面可能做得更好，而且 Objective-C 的版本会更简单。如果不是这样，那么 Objective-C 就没什么意义了。创建一个新类涉及三个步骤：第一，你分配类对 `class pair`，然后，你添加方法、实例变量和协议，最后，你向运行时注册该类对。

> **注意：** “类对” `class pair` 这个术语可能看起来很困惑。你源代码中的每个 Objective-C 类在运行时都会编译为两个类。对象是*类* `class` 的实例，而类是*元类* `metaclass` 的实例。实例方法附加在类上，而类方法附加在元类上。当你向类发送消息时，会使用元类来查找对应的方法。
