## 13.3 文件操作

既然你知道一个文件存在，你可能认为你已经完成了，但实际上并非如此。文件存在并不意味着你可以读取、写入或执行它。要检查这些属性，可以使用 `is_readable` 检查读取权限，使用 `is_writable` 检查写入权限，以及使用 `is_executable` 检查执行文件的能力。每个函数都接受文件名作为参数。除非你知道文件与你的脚本在同一个目录，否则必须在文件名中指定文件的完整路径。你可以使用连接符将路径和文件名组合，例如：

```php
$file_name = $path_to_file . $file_name_only;
```

### URL 包装器

PHP 为文件系统函数构建了两种 URL 约定，包括 `file` 和 `copy`。除了这两个包装器，从 PHP 4:3.0 开始，你可以利用 PHP 脚本和 `stream_wrapper_register` 编写自己的包装器。默认包装器是 `file://`，用于 PHP 的本地文件系统。如果你指定一个相对路径（即不以 `/`、`\` 或 Windows 盘符开头的路径，例如 `C://`），该路径将相对于当前工作目录。

通常这是脚本所在的目录，除非它显然被更改了。通过某些函数（例如 `fopen` 和 `file_get_contents`），可以使用 `include_path` 来查找相对路径。

既然你已经学会了使用 PHP 和 MySQL 构建动态页面，那么早晚研究构建你网站页面基础的 HTML 标记的变化。你将了解到 XHTML、它的要求以及为什么它值得投入额外的精力去创建。请记住，为了从你的 PHP 脚本创建高质量的 Web 内容，标记必须符合标准。将 XHTML 输出视为经过 PHP 和数据库函数处理并请求页面后的最终成品。我们还将检查你的脚本生成的 XHTML 输出，以发现任何错误。

XHTML 代表可扩展超文本标记语言（Extensible HyperText Markup Language）。XHTML 是一种类似于 HTML 的标记变体，但根据 XML 的要求具有更严格的语法。HTML 基于 SGML，SGML 虽灵活但处理起来复杂，而 XML 简化了 SGML，使其在保持灵活的同时更容易转换。XHTML 语言结构看起来非常像 HTML 语言结构，使用更明显且没那么多的符号（例如 `<` 和 `>`）来标识标签，但对这些标签的呈现有更严格的要求。符合这些语法要求的 XHTML 文档被称为良好的（well-formed），而符合语言结构以及 DTD 中包含的辅助规则的 HTML 文档被称为有效的（valid）。XHTML 可以使用任何标准 XML 库处理，而 HTML 通常使用专门为 HTML 修改的解析器。你可以将 XHTML 视为 HTML 和 XML 的许多交叉点，因为它是两者的重新构建。展示变化的最简单方法是显示一个 HTML 文档及其对应的 XHTML 文档。首先，这是一个有效的 HTML 4.0 ：

## 14.1 为什么要用 XHTML？

世界维网联盟（W3C）创建 XHTML 有多种原因，包括：

- Web 内容被传输到比传统电脑更多的设备上，例如黑莓手机、手机和其他移动设备。XML 更严格的语言结构为这些设备及其后端框架减少了一层复杂的处理。
- 从事于动态 HTML 和其他脚本技术工作的开发人员发现，HTML 的灵活性有时意味着他们期望控制的文档结构与预期不同，有时在不同浏览器和程序之间甚至不同。XHTML 更严格的结构消除了这些歧义。
- 随着越来越多的文档管理工具包含 XML 支持，XHTML 与 XML 的相似性使得无需调整即可在 XHTML 上使用这些工具。
- 在宏观上，XHTML 使文档之间具有更好的一致性。虽然 XML 更严格的错误检查听起来像是一种负担，但它可以轻松发现并修正错误。
- 尽管得到了大量的程序支持，W3C 认为迁移到 XML 基础将允许设计师创建自定义词汇，与优秀的 HTML 词汇相结合。W3C 自己的建议包含了视觉和音频、设计和结构。
- XHTML 还可以与其他 XML 词汇混合，使得这种广泛理解的词汇在新环境中更易复用。

## 14.2 XHTML 和 XML 命名空间

XML 极具有非排他性。它描述了标点和基本结构，但对查询没有太多规定，例如，元素应该如何命名。这导致了一个问题：一个连接中的 `Title` 含义与另一个连接中的可能完全不同。XML 命名空间规范（可以在 http://www.w3.org/TR/xml-names/ 处找到）提供了一个设计人员可以使用的系统，利用资源标识符（URIs）来识别特定的词汇。URIs 是已知资源定位符（URLs）和资源名称（URNs）的结合。从 XML 命名空间的角度来看，URIs 非常有用，因为它们可以与所有轻松结合。W3C 声称以 `http` 开头的名称非常适合它们作为标识符。在没有混合词汇的纯 XHTML 中，命名空间通过 `XHTML` 属性在 `html` 标签上声明。例如：

```html
<html xmlns="http://www.w3.org/1999/xhtml">
```

命名空间 URI `http://www.w3.org/1999/xhtml` 现在应用于 `html` 组件本身以及任何元素，因为它们没有自己的、以前缀开头的属性或名称。

## 14.3 XHTML 版本

自诞生以来，XHTML 标准直一直在演进。今天有三种关注的形式：

### XHTML 1.0

XHTML 1.0 的内容与 HTML 4.0 相同，但它需要 XML 语法。

### XHTML 1.1

XHTML 1.1 是 1.0 的重新格式版本。它是严格的，因为它使用了更大的元素集合。这是 W3C 的建议，提供了标准属性和需要符合 XHTML 环境的定义。HTML 的任何元素（例如表示性元素和框架）都被移除了。所有的呈现由层叠样式表（CSS）控制。此外，1.1 包含了对 XML 方言的支持。
