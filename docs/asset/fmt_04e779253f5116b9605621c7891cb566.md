## 使用虚函数实现的多态行为

你可以通过指针`Fish*`或引用`Fish`访问类型为`Fish`的对象。该对象可能仅作为`Fish`实例化，也可能是继承自`Fish`的`Tuna`或`Carp`的一部分。你不知道（也不乎）。你使用此指针或引用调用`Swim()`方法，如下：

```
pFish->Swim();
myFish.Swim();
```

你期望的是，如果它是金枪鱼的一部分，它就像金枪鱼一样游泳；如果它是鲤鱼的一部分，就像鲤鱼一样游泳；如果它不是作为`Tuna`或`Carp`等特殊类的一部分实例化的，就像匿名鱼。你可以通过在基类`Fish`中将函数`Swim()`声明为虚函数来确保这一点：

```
class Base
  virtual ReturnType FunctionName (Parameter List);
};
class Derived
  ReturnType FunctionName (Parameter List);
};
```

使用关键字`virtual`意味着编译器确保调用请求的基类的任何重写变体。因此，如果`Swim()`被声明为虚，调用`myFish.Swim()`（`myFish`类型为`Fish&`）将导致执行`Tuna::Swim()`，如列表11.2所示。

# 虚函数是如何工作的？理解虚函数表

### 注意

这一节对于学习使用多态可选。可以跳过，也可以阅读以满足好奇心。

列表11.2中的`MakeFishSwim(Fish&)`尽管程序员在其内部调用了`Fish::Swim()`，但最终调用了`Carp::Swim()`或`Tuna::Swim()`方法。显然，在编译时，编译器对该函数将遇到的对象的性质一无所知，因此无法确保同一个函数在不同时间点执行不同的`Swim()`方法。需要调用的`Swim()`方法显然是在运行时做出的决策，使用了实现多态的隐形逻辑，该逻辑由编译器在编译时提供。

考虑一个带有虚函数的类`Base`：

```
class Base
{
public:
    virtual void Func1()
    {
        // Func1 实现
    }
    virtual void Func2();
```

```cpp
{
  // Func2 实现
}
// ... 等此类推
virtual void FuncN() {
  // FuncN 实现
}
```

派生类`Derived`继承自`Base`并重写了`Base::Func2()`，同时直接暴露了基类`Base`中的其他虚函数：
class Derived: public Base {
  public:
    virtual void Func1() {
      // Func2 重写了 Base::Func2()
    }
    // Func2 没有实现
}
```

（注：由于原始文本后半部分存在重复和乱码干扰，译文已根据核心逻辑进行清理并确保了不重复输出。）

### 分析

这是一个被精简到极致的示例。你看到两个类，`SimpleClass`和`Base`，它们在成员类型和数量上相同，但`Base`将`DoSomething()`函数声明为虚函数（在`SimpleClass`中是非虚的）。添加`virtual`关键字的区别在于，编译器为类`Base`生成了一个虚函数表，并预留了一个指向`Base`指针的位置作为其隐藏成员。这个指针在我的32位系统中占用4个字节，这就是真金白银。
