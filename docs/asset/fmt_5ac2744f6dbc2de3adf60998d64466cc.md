
这是一个关于隐式约束无用处的良好例子。假设我们要解一个涉及 100 个具有相同定义域 `{0, 1, 2, 3, 4}` 的变量的约束网络。约束是：至少有五个变量为 0。与这些每个约束相关的过滤算法都实现了一致性。在这种情况下，该算法对应于思想：“如果 `a` 被分配给 `k < 5` 个变量，且只有 `5 - k` 个变量未实例化，则将 `a` 分配给所有这些变量”。假设变量值排序是选择定义域大小最小的变量和定义域中的第一个值（经典的最小排序）。在检测到不一致之前，将有 95 个变量实例化为 0。当 94 个变量被实例化为 0 时，所有的过滤算法都没有删除任何值。因此，显然最多有 `100 - 4 × 5 = 80` 个变量可以实例化为 0。如果我们添加这个隐式约束，我们将避免 `5^14` 个约束！此外，我们还可以添加一个更复杂的隐含约束，规定未实例化变量的数量必须同时满足第一个初始约束。

在运动赛程中，我们将看到中断次数总是一个偶数。引入这种隐式约束会加速对最小解的搜索。

## 2.3. 全局约束

全局约束 `C` 是一个涉及一组其他约束的约束，使得与 `C` 相关的过滤算法比 `C` 中每个约束单独的并集更强大。

从数学角度来看，如果 `C` 是一个涉及约束 `c_1, ..., c_p` 的全局约束，那么 `R(c_1) ∪ ... ∪ R(c_p) ⊆ R(C)`。如果 `f(C)` 的复杂度与 `f(c_1), ..., f(c_p)` 的复杂度之和相当，那么这种全局约束就特别有趣。

全局约束的一个众知例子是 `alldifferent`，涉及的变量在实例化时必须取与其他变量不同的值。例如，三个变量 `x_1, x_2` 和 `x_3`，使得 `D_1 = {a, b}`，`D_2 = {a, b}` 和 `D_3 = {a, b, c}`，且约束为 `x_1 ≠ x_2, x_1 ≠ x_3` 和 `x_2 ≠ x_3`。如果与这些每个约束相关的过滤算法确保一致性，则没有值会被删除。但如果我们使用涉及 `x_1, x_2` 和 `x_3` 的 `alldifferent` 约束，与 `alldifferent` 约束相关的过滤算法确保了超一致性，那么 `x_3` 将实例化为 `c`。这种过滤算法由 [Reg94] 提出。它的复杂度较低 `∑_i |D(x_i)|`。在论文的其他部分，当我们不特别提到使用此约束时，我们将考虑与 `i` 相关的过滤算法。

全局约束的引入不会改变解集，正如 [CGL93] 所指出的，对于某些问题可能是至关重要的：“高效解决时间表问题需要对最小/最大约束进行全局计算”。

有时，全局约束仅仅是一组约束以及从这组约束同时存在推导出的隐含约束的并集，且与该全局约束相关的过滤算法是所有过滤算法的并集，因此没有定义新算法。这种约束可以从隐含约束段落中给出的示例获得。

通常，全局约束的引入会导致发现某些新的变量排序，从而改进解的搜索，因为全局约束在每次选择变量或值后都会导致更多的定义域缩减。

## 2.4. 相关约束和冗余约束

乍看之下，添加一个消除某些对称性的约束、隐式约束或全局约束似乎改进了当前模型。

事实并非如此。例如，消除某些对称性可能会增加找到解所需的时间。这可能是由于消除某些对称性会增加找到解的时间。同样地，如果我们添加一个隐式约束，求解的回溯次数不会减少，因为从数学角度来看，这种约束的引入，这种行为已经被考虑在模型内。

根据这些说明，我们可以定义相关约束的概念。一个约束相对于模型是*相关的*，如果该约束的引入：

- 允许我们消除某些对称性；
- 或者它是隐含或全局约束，且其引入改进了解的搜索

值得注意的是，约束相对于模型的相关性有时会导致发现更好的排序。如果一个约束不是相关的，它被称为冗余约束。

# 3. 赛程问题中中断次数的最小化

在这类问题中，我们给定 `n` 个球队和 `n-1` 个周期，对于每个周期每个球队都必须进行主场或客赛，使得每个球队都与其他球队只比赛一次。球队的中断被定义为两次连续的主场或客赛。

### 3.1. 第一个模型

根据问题的定义定义了一些变量：

- 每个周期，每个球队都必须与对手比赛。因此，对于球队 `i`，定义了 `n-1` 个变量。`O_{ij}` 是对应于球队 `i` 在周期 `j` 位置的变量。那么 `O_{ij} = k` 表示球队 `i` 在周期 `j` 与球队 `k` 比赛。初始变量 `O_{ij}` 的定义域包含所有球队。这些变量被称为位置变量
- 每个球队，每个球队都必须进行主场或客赛。对于每个球队 `i` 和每个周期 `j`，定义了一个 0-1 变量 `P_{ij}`。根据惯例，0 对应客赛，1 对应主场。`P_{ij} = 0` 表示球队 `i` 在周期 `j` 进行客赛。这些变量被称为位置变量
- 球队的中断被定义为两次连续的主场或客赛。对于每个球队和每个连续周期，定义了一个 0-1 变量 `B_{ij}`。`B_{ij} = 1` 表示球队 `i` 在周期 `j` 和 `j+1` 之间存在中断。这些变量被称为中断变量。对于每个球队有 `n-2` 个中断变量。

目标，即要最小化的变量，是 `#B`。该变量统计赛程中中断的总数。

该问题的约束可以表示如下：

- 每个球队在所有周期内都与其他球队只比赛一次。对于每个球队 `i`，定义一个涉及 `O_{ij}` 变量（`j=1,...,n`）的 `alldiff` 约束。
- 对于每个周期 `j`，队伍 `i` 对阵队伍 `k`，然后队伍 `k` 对阵队伍 `i`，且 `i` 和 `k` 比赛的地点是不同的。
- 对于每个周期 `j` 和每对队伍 `i` 与 `k`，都定义了一个约束条件（`O_{ij} = k ⇔ P_{ij} ≠ P_{kj}`）。对于给定的周期 `j`，这些约束被称为*场地-对手约束*。
- 球队的休息（break）被定义为连续的两场主场比赛或两场客场比赛。

对于队伍 `i` 和每个周期 `j`，`j = 1, ..., n-2`，定义了约束（`B_{ij} = 1 ⇔ P_{ij} = P_{i(j+1)}`）。

为了计算休息次数的数量，模型中引入了约束（`#B = ∑_{j=1}^{n-2} B_{ij}`）。

与上述每个约束相关的过滤算法确保了一致性。对于 `alldiff` 约束，可以在 [Rég94] 中找到此类过滤算法。对于另外两种约束，必须设计此类过滤算法。

这些算法并不复杂，对应于所有可能情况的枚举和检查。例如，与场地-对手（`O_{ij} = k ⇔ O_{kj} = i` 和 `P_{ij} ≠ P_{kj}`）相关的过滤算法将如下实现：

```
(1) 如果 O_{ij} = k，则 O_{kj} ← i。
(2) 如果 P_{ij} 已实例化，则从 O_{ij} 中移除所有满足 P_{kj} 已实例化且值与 P_{ij} 相同的 k。
(3) 如果 k 被移除，则也从 O_{ij} 中将其移除。
```

我们可以很容易地证明该算法将实现一致性。

使用深度优先分支定界算法来寻找最小值并证明其最优性。

在这个简单的模型中，很难找到一种能产生解的变量值排序。然而，如果先实例化休息变量，其次是场地变量，最后是对手变量，可以得到以下结果：

| 队伍数量 | 4 | 6 |
| :--- | :--- | :--- |
| 回溯次数 | 73 | 62,082 |
| 时间(秒) | 0.1 | 17.7 |

### 3.2. 引入相关约束

通过消除某些对称性并对变量值排序进行链接，可以大大改进之前的结果，以考虑到某些对称性已被移除。这需要一些新变量：对于每个队伍 `i`，`#B_i` 是一个计算 `i` 休息次数的变量。那么 `#B` 被重新定义为 `#B = ∑_{i=1}^{n} #B_i`。

初始公式包含几种对称性。可以识别出两种对称性：

- 所有主场比赛可以用客场比赛替换，反之亦然。
- 队伍可以进行排列。

第一种对称性可以通过决定第一支队伍的第一场比赛为主场比赛来消除。第二种对称性可以通过定义第一支队伍的赛程来消除。例如，通过增加顺序选择对手。此外，第一支队伍可以是任何队伍，因为队伍是可交换的。因此，我们决定第一支队伍将拥有最少的休息次数。

因此，为了打破对称性，模型中添加了以下约束：

- `P_{i1} ← 1`
- `∀ j = 1, ..., n-1: O_{ij} ← j+1`
- `∀ i = 2, ..., n: Bt_i ≤ Bt_i`

因此，变量值排序选择如下：

1. 首先实例化 `Bt` 变量，通过动态选择域中具有最小值的变量并选择该值。
2. 通过首先尝试值 1 来实例化休息变量。
3. 实例化场地变量。
4. 实例化对手变量。

## 命题 4.3

令 `j` 为任意周期，`k` 为任意其他周期使得 `k = j+p, p ≥ 0`。令 `Bt_i(k)` 为球队 `i` 在周期 `j` 到周期 `k` 之间的转换次数。那么 `P_{ij} = P_{ki} ⇔ Bt_i(k)` 的奇偶性为 `p`。

证明。该属性对于 `p=0, 1, 2` 成立。令 `P_{ik}` 为 `P_{ki}` 的相反值。

首先假设 `P_{ij} ≠ P_{ki}`。对于 `x = j+1, ..., k-1` 的任何 `P_{iz}` 赋值，存在一个周期 `l` 使得 `j ≤ l ≤ k` 且对于 `z = l+1, ..., k-1`，`P_{iz} = P_{ki}`。此外，`Bt_i(k) = Bt_i(j,l) + Bt_i(l+1, k-1)`，其中 `P_{il} ≠ P_{ki}` 且 `P_{i(l+1)} ≠ P_{ki}`。由于对于所有 `z = l+1, ..., k-2`，`P_{iz} ≠ P_{ki}` 均相等，则 `Bt_i(l+1, k-1) = k-l = j+p-l`。因此 `Bt_i(j,k)` 的奇偶性取决于 `(l-j)` 和 `(j+p-l) = p-2`，其奇偶性为 `p`。

现在假设 `P_{ij} = P_{ki}`。对于任意 `z = j+1, ..., k-1`，存在一个周期 `l` 使得 `j ≤ l ≤ k` 且对于 `z = l+1, ..., k-1`，`P_{iz} = P_{ij}` 且 `P_{iz} = P_{ki}`。此外，`Bt_i(k) = Bt_i(j,l) + Bt_i(l,k)`，因为 `P_{il} ≠ P_{i(l+1)}`。由于 `P_{il} = P_{ij}` 且 `P_{i(l+1)} = P_{ki}`，`l-j` 和 `l-k` 的奇偶性具有 `k-l-1 = j+p-l-1`。因此 `(l-j)` 和 `(j+p-l-1)=p-1` 不具有 `p` 的奇偶性。

正如我们所提到的，该属性对于推导每支队伍比赛的非常有用。可以从该属性中推导出一个过滤算法。

## 定义 4.4

令 `i` 为一支球队，且

- `EvenSeq(j,k)` 为从周期 `j` 到周期 `k` 的周期序列，使得 `k > j+1`，`P_{ij}` 和 `P_{ik}` 已实例化，且对于所有 `z = j+1, ..., k-1`，`P_{iz}` 未实例化，且该序列中的转换次数为奇数。
- `ExtSeq(j,k)` 为：从周期 `1` 到周期 `j` 的周期序列，使得 `k > j+1`，`P_{ij}` 和 `P_{ik}` 已实例化，且对于所有 `z = j+1, ..., k-1`，`P_{iz}` 未实例化且该序列中的转换次数已实例化；或者是从周期 `j` 到周期 `n-1` 的周期序列，使得 `j < n-1`，`P_{ij}` 已实例化且对于所有 `z = j+1, ..., n-1`，`P_{iz}` 未实例化。
- `OddSeq`，`OddSeq(j,k)` 的序列数量。
- `EvenSeq`，`EvenSeq(j,k)` 的序列数量。
- `ExtSeq`，`ExtSeq(j,k)` 的序列数量。
- `Btinst`，球队 `i` 已经实例化的最大转换次数。
- `maxOddSeq`，通过实例化序列 `OddSeq(j,k)` 可以产生的最大转换次数。
- `maxEvenSeq`，通过实例化序列 `EvenSeq(j,k)` 可以产生的最大转换次数。
- `maxExtSeq`，通过实例化序列 `ExtSeq(j,k)` 可以产生的最大转换次数。

## 命题 4.5

令 `i` 为一支球队，则满足以下属性：

- a) `min(#Bt_i) ≥ #Btinst_i + #OddSeq_i`
- b) `max(#Bt_i) ≤ #Btinst_i + maxOddSeq_i + maxEvenSeq_i + maxExtSeq_i`
- c) `ExtSeq_i = 0 ⇒ #Bt_i` 具有数量 `(#Bt_i, #OddSeq_i)`
- d) `Bt_i` 为奇数 `⇒ P_{il} ≠ P_{(n-1)}`
- e) `Bt_i` 为偶数 `⇒ P_{il} = P_{(n-1)}`
- f) `OddSeq_i ≤ #Bt_i - #Btinst_i ⇒` 所有 `EvenSeq(j,k)` 都不产生转换，所有的 `ExtSeq(j,k)` 亦是。
- g) `OddSeq_i + 1 = #Bt_i - #Btinst_i ⇒` 所有 `EvenSeq(j,k)` 都不产生转换。
- h) `maxOddSeq_i + maxEvenSeq_i + maxExtSeq_i ⇒` 所有 `EvenSeq(j,k)` 都不产生转换。

# 一种用于公交车司机调度系统的约束规划预处理器

Barbara M. Smith, Colin J. Layfield, 和 Anthony Wren

摘要。在城市公交运营中，司机调度是在将公交车分配给时刻表中的行程之后的后续阶段，旨在产生一组公交工作人员人员安排。司机调度涉及构建一组班次，使得每辆公交车都分配有一名司机；班次数量减至最低；且每个班次都遵守关于驾驶时间、最短休息等方面的约定规则。司机调度问题可以使用整数线性规划建模为集合覆盖问题。TRACS II 是一项在利兹大学开发的使用该方法的公交车和司机调度系统；其开发的早期系统自 1984 年以来已应用于英国公交行业。该系统会产生大量的可能班次（目前多达100000个），并选择一个覆盖所有工作的子集形成司机调度表。集合覆盖法已被证明易于适应不同的条件，并产生非常良好的结果。

覆盖问题的复杂性在很大程度上取决于公交时刻表的换接机会数量。当公交车被安排在某一点，司机可以将车交给另一名司机时，就产生了一个换接机会。换接机会越多，需要覆盖的工作以及生成的可能班次越多；集合覆盖问题中的约束和变量也越多。

本文的工作目标是为 TRACS II 使用约束规划。选择部分换接机会，TRACS II 生成的班次可以仅使用这些机会更换司机。良好的换接机会选择可以在显著减少子集覆盖问题规模的同时保持其解的质量。
