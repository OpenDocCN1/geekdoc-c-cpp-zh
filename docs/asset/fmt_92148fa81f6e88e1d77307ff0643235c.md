
或者，你可以在代码隐藏文件中将处理程序与路由事件关联。例如，`myButton`按钮的`Click`事件通过使用`+=`运算符与`myButton_Click()`方法关联，如以下代码片段所示：

```
myButton.Click += new RoutedEventHandler(myButton_Click);
```

你也可以为元素创建自己的路由事件并处理它们。路由事件是`RoutedEvent`类的实例；因此，你首先需要声明一个`RoutedEvent`类型的公共、静态、只读字段。路由事件随后需要使用`EventManager`类的`RegisterRoutedEvent()`方法向WPF事件系统注册。注册路由事件后，你需要为其实现`add`和`remove`CLR包装器。`add`和`remove`CLR包装器使用`AddHandler()`和`RemoveHandler()`方法来允许对路由事件进行事件处理。你将在本章的Immediate Solutions部分学习如何创建自定义路由事件。

> NOTE
>
> `AddHandler()`和`RemoveHandler()`方法在`FrameworkElement`类中定义。

## Attached Events

类似于附加属性，附加事件是事件由一个元素或类拥有或创建，然而，它们可以由元素树中的其他元素处理。许多输入事件，例如鼠标和键盘事件，都是为WPF中的每个元素定义的附加事件。

附加事件在你想要向父元素提供有关子元素组合状态的信息时很有用。父元素可以处理由子元素定义的事件。这样如果子元素共享附加事件并且事件在其中任何一个上被引发，则事件处理程序只需在父元素中指定一次。这可以节省你在所有子元素中为同一事件指定事件处理程序的工作。你可以通过使用所有者的名称限定它们，在父元素中指定附加事件的处理程序。例如，`Click`事件是一个附加事件，由`ButtonBase`类拥有，并被其派生类和元素继承，例如`Button`和`ToggleButton`类。考虑以下代码片段：

```
<Grid Name="grid1" ButtonBase.Click="button_click">
<Button Height="25" Name="button1" VerticalAlignment="Top" Margin="90,30,0,0">Button1</Button>
<ToggleButton Height="25" Name="toggleButton1" VerticalAlignment="Center">ToggleButton1</ToggleButton>
<Button Height="25" Name="button2" VerticalAlignment="Bottom" Margin="90,0,90,30">Button2</Button>
</Grid>
```

在前面的代码片段中，`Click`事件与其处理程序关联在`Grid`元素中，该元素是两个`Button`元素`button1`和`button2`以及一个`ToggleButton`元素`toggleButton1`的父元素。

请注意，`Click`事件的处理程序是在`Grid`元素中指定的，通过将事件属性`Click`与拥有该事件的类`ButtonBase`的名称限定。`Grid`元素中所有者与事件名称之间用点运算符分隔。每当网格中的按钮或切换按钮被单击时，事件处理程序就会被调用。事实上，如果从`ButtonBase`类派生的任何元素被添加到网格中，并且其中任何一个元素被单击，则相同的事件处理程序将被调用。这样，你就可以为子元素拥有一个公共事件处理程序。请注意，尽管`Grid`元素本身没有定义`Click`事件，但它处理其派生自`ButtonBase`类的子元素的`Click`事件。

附加事件从根本上说是路由事件，并且是`RoutedEvent`类的实例。此外，这些事件使用`RegisterRoutedEvent()`方法注册。但是，附加事件没有CLR `add`和`remove`事件包装器来分别添加和删除处理程序。相反，附加事件使用两个公共静态方法来添加和删除事件处理程序。添加附加事件处理程序的公共静态方法的语法如下：

```
public static void Add<AttachedEventName>Handler()
{
    //add event handler logic
}
```

在前面的语法中：

- `public`, `static`, `void`—表示C#关键字

## Lifetime Events

你在WPF应用程序中创建或使用的每个元素都有其生命周期。元素的生命周期以特定的阶段或事件为特征，例如元素何时被创建或初始化、加载和销毁。事件可能因实际元素而异。然而，有某些事件是WPF中所有元素的共同点。WPF中表征元素生命周期的常见事件如下：

- `Initialized` — 指元素生命周期中发生的第一个事件。当元素被创建并使用给定的属性适当配置时，会引发此事件（样式、数据绑定和动态资源属性除外）。如果元素包含子元素，则此事件首先发生在子元素上，然后向上移动到父元素。这是因为除非其子元素已初始化，否则父元素不会完全初始化和设置。
- `Loaded` — 指在`Initialized`事件发出信号后发生的第二个生命周期事件，表明应用程序中所有元素（其样式和数据绑定属性）已设置并准备好渲染。请注意，`Loaded`事件首先发生在根元素（`Window`或`Page`）上，然后向下移动到子元素。当在它们上引发`Loaded`事件时，元素被认为已加载并且可以在屏幕上渲染。
- `Unloaded` — 指最后一个生命周期事件。当特定元素或其根元素或父元素从WPF应用程序中移除时，会发生此事件。

> NOTE
>
> 生命周期事件在`FrameworkElement`类中可用。

除了WPF应用程序元素生命周期中发生的常见事件外，还有特定于应用程序的事件，例如窗口（`Window`元素）和页面（`Page`元素）。让我们先从应用程序特定的生命周期事件开始学习这些事件。

## Application Lifetime Events

独立的WPF应用程序和XBAPs在其生命周期中遵循特定的事件序列。独立的WPF应用程序和XBAPs的生命周期事件有所不同。独立WPF应用程序的生命周期事件如下：

- `Startup` — 指在为应用程序调用`Run()`方法后立即发生的第一个事件。`Startup`事件表示应用程序已准备好显示。在`Startup`事件的事件处理程序中，你可以创建`Window`对象并将其指定为应用程序的主窗口。此外，你可以计算或处理应用程序的任何命令行参数。
- `Activated` — 指当独立的WPF应用程序成为活动应用程序时发生的事件。当应用程序的窗口出现在其他应用程序的窗口之上时，应用程序就是活动应用程序。
- `Deactivated` — 指当独立的WPF应用程序不再是活动应用程序或变得不活跃时发生的事件。换句话说，当应用程序的窗口进入后台并且不再是当前窗口时，就称为`deactivated`事件。
- `SessionEnding` — 指当应用程序关闭并且当前用户终止Windows会话时发生的事件。例如，如果用户关闭或重新启动计算机或从会话注销，则会发生此事件。
- `Exit` — 指在应用程序关闭前发生的事件。在`Exit`事件中，你可以指定任何最终化操作，例如保存退出代码。

> NOTE
>
> 你也可以使用`RaiseEvent()`方法来引发WPF应用程序中所需出现的附加事件。

`Add<AttachedEventName>Handler` — 表示添加事件访问器的名称。`<AttachedEventName>`是附加事件的名称。例如，如果你创建了一个名为`Resize`的附加事件，则添加事件访问器为`AddResizeHandler`。

## NOTE

> 在第3章《C# 2010程序中的流程控制和异常处理》中，你学习了某些已知为异常的异常条件会突然中断应用程序的执行。在WPF中，异常也会导致应用程序关闭或停止执行。在这种情况下，如果异常未被处理，则会引发`DispatcherUnhandledException`事件。然后你可以在`DispatcherUnhandledException`事件处理程序中处理异常。

XBAPs主要以`Startup`和`Exit`事件为特征，其余事件，例如`Activated`、`Deactivated`和`SessionEnding`，对XBAPs不会发生。当`Startup`事件发生时，XBAP的主页面出现；而当`Exit`事件发生时，用户导航到XBAP的其他页面或关闭Web浏览器。在任何未处理的异常情况下，`DispatcherUnhandledException`事件也可能发生。

## NOTE

> `Application`类为独立的WPF应用程序和XBAPs定义应用程序生命周期事件。

## Window Lifetime Events

正如你所知，独立WPF应用程序的核心是一个窗口，它是`Window`类的实例。独立的WPF应用程序可以有多个窗口。应用程序中的每个窗口都有自己的生命周期，其本身以一系列事件为特征。

- `SourceInitialized` – 指当窗口初始化时发生的事件，即当独立的WPF应用程序初始化并且其`Startup`事件被引发时。`SourceInitialized`事件表示窗口已准备好显示。
- `Activated` – 指当窗口成为活动窗口时发生的事件，即窗口出现在其他窗口前面。
- `Loaded` – 指当窗口及其属性被加载并且窗口已准备好渲染时发生的事件。
- `ContentRendered` – 指在窗口及其内容（控件）渲染后立即发生的事件。如果窗口没有任何内容，则此事件可能不会发生。
- `Deactivated` – 指当当前窗口变得不活跃时发生的事件，即当另一个窗口成为活动窗口时。
- `Closing` – 指当用户关闭窗口时发生的事件，例如通过关闭应用程序。此事件发生在窗口实际关闭之前。你可以在窗口关闭之前包含某些预防性或最终化操作，例如取消窗口的关闭操作并保存任何数据。请注意，如果用户在窗口打开时关闭计算机或注销，则不会引发`Closing`事件。
- `Closed` – 指在窗口关闭前发生的事件。此事件表示窗口将在一会儿后关闭，并且无法取消关闭操作。

类似于独立WPF应用程序中的窗口，XBAPs中的页面也有自己的生命周期。你可能还记得XBAPs中的页面是`Page`类的实例。此外，页面托管在Web浏览器或某些特定控件中，例如窗口和框架。XBAP的用户可以以任意随机顺序导航到页面。这意味着页面的生命周期取决于其导航状态而发生大量变化或事件；因此，本章中不讨论它。

让我们学习WPF应用程序中的对话框。

## Working with Dialog Boxes in WPF Applications

类似于Windows Forms应用程序，独立的WPF应用程序也可以使用对话框以获得更好的用户交互性。你可以使用对话框在WPF应用程序中合并功能以显示或从用户检索某些信息。在WPF 4.0中，对话框可以是以下两种类型：

- Modal dialog box – 指除非明确关闭否则保持可见的对话框。只要模态对话框打开，你就无法使用应用程序的任何其他窗口。模态对话框适用于你想要从用户检索某些信息并利用该信息的情况
information for further processing. Some common examples of modal dialog boxes include dialog boxes for opening and saving files.
- Modeless dialog box – Refers to a dialog box that does not prevent the users from working with other windows of the application. In other words, modeless dialog boxes do not affect the functioning of the application. Therefore, these dialog boxes are suitable to display information, such as the current page number.

In WPF 4.0, you can use both modal and modeless dialog boxes in standalone WPF applications. WPF provides various classes to create dialog boxes and use them in applications. Some of the classes include the `MessageBox`, `OpenFileDialog`, `SaveFileDialog`, and `PrintDialog` classes. The `MessageBox` class provides the functionality to work with message boxes, while the `OpenFileDialog`, `SaveFileDialog`, and `PrintDialog` classes allow you to perform some common operations, such as opening, saving, and printing files, respectively. Let’s discuss each of these classes one at a time starting with the `MessageBox` class.

## The MessageBox Class

The `MessageBox` class (in the `PresentationFramework` assembly in the `System.Windows` namespace) allows you to create message boxes that are the simplest modal dialog box available. Message boxes are used to display some information that can further be used to confirm a particular action or make decisions. The information appears as textual message along with an OK button. The `MessageBox` class has the `Show()` method that allows you to display a message box. When the message box appears, by default an OK button is also displayed. However, you can also display other buttons, such as the Cancel, Yes, and No buttons. You can use the `MessageBoxButton` enumeration to specify the buttons that you want to display in the message box. If you want to take some action based on the button that a user has clicked, then you can capture the result in an instance of the `MessageBoxResult` class. If you want to convey the readers whether the message is a warning or additional information, then you can display an icon on the message box by using the `MessageBoxImage` enumeration. The `MessageBoxImage` enumeration provides several predefined icons that can be used.

## The OpenFileDialog Class

The `OpenFileDialog` class (available in the `PresentationFramework` assembly in the `Microsoft.Win32` namespace) allows the users to provide the name of one or more files that are to be opened. The inheritance hierarchy of the `OpenFileDialog` class in WPF 4.0 is as follows:

```
System.Object
  Microsoft.Win32.CommonDialog
    Microsoft.Win32.FileDialog
      Microsoft.Win32.OpenFileDialog
```
